# 路径类 ARC 题目实现检查清单

## 1. 先定义通行规则，再计算路径

- 明确背景、墙、门、轨道、节点和特殊通行物。
- 单行道、门宽、端帽、颜色、传送门等规则必须先改写可通行图。
- 不能先按无向图或全部空格求最短路，再补充特殊规则。

## 2. 必须存在多条候选路线

- 如果题目要求“最短”，输入中至少应有两条合法路线。
- 其中一条是唯一最短路线，其他合法路线应严格更长。
- 只有一条可行路线时，“最短”步骤没有实际作用。

## 3. 非法捷径要真正不可通行

- 可以设置几何上更短的诱饵路线。
- 诱饵必须因可见规则失效，例如逆行端帽、错误门宽或墙体阻挡。
- 应验证忽略特殊规则时的最短路短于遵守规则后的最短路。

## 4. 方向规则必须严格落实

- 无帽轨道可双向通行。
- 有帽轨道只能从无帽端走向有帽端。
- 逆向轨道不是代价更高，而是不存在对应的有向边。

## 5. 保证答案唯一

- 不仅要检查最短距离，还要检查最短路径本身是否唯一。
- 若存在两条等长最短路径，而题面要求只保留一条，则答案不唯一。
- 生成器应统计最短路径数量，而不只是找到任意一条路径。

## 6. 起点和终点必须可判定

- 起点、终点应由稳定的颜色或结构线索区分。
- 不能通过“哪个方向恰好可达”反推起点，除非这本身就是题面规则。
- 不应让随机颜色破坏跨样例的一致语义。

## 7. 距离必须使用题面参照系

- 迷宫题使用沿走廊的四连通最短距离。
- 不能替换成曼哈顿距离、欧氏距离或直线距离。
- 生成器应包含至少一个能区分走廊距离与直线距离的反例。

## 8. 等距题要分别限制距离和数量

- 可限制源点到最近等距位置的共同距离，例如 2～6 步。
- 距离过小会退化成局部对称；距离过大则计算和视觉负担过重。
- “等距位置数量”和“到等距位置的距离”是两个不同约束，不能混淆。

## 9. 控制网格规模和视觉复杂度

- 小型路径题优先使用约 9×9～17×17 的网格。
- 避免接近 30×30 的密集随机迷宫。
- 路线、墙体、端帽、传送门和输出标记应清楚可辨。

## 10. 生成器必须做独立语义验证

- 检查起终点可达、存在多条合法路线、最短合法路线唯一。
- 检查非法捷径确实因规则被阻断。
- 检查输出不同于输入，不同输入不会大量产生相同输出。
- 不能只验证 `main(generate_input())` 自洽。

## 11. 关键步骤必须影响答案

- 去掉门宽、方向、颜色或传送规则后，答案应发生变化。
- 去掉“最短”步骤后，也应无法唯一得到答案。
- 否则相关机制只是装饰，没有真正参与推理。
