## 新题 1：菱形包络碰撞图

**组合逻辑**：[envelope_generation](创新：生成填充区域而非仅轮廓) + [logical_AND](创新：作用于几何计算所得区域而非给定位掩码) + [recolor](覆盖计数决定颜色)

**来源原语**：envelope_generation, solid_bar, center_symmetry（c97c0139）；logical_AND, pixel_align, bitmask（0520fde7）；cross_color_overlap_recolor（58e15b12）；recolor（多题）

**依赖链**：每条实心条的菱形包络必须先完整计算，才能逐像素检测覆盖计数；覆盖计数决定最终着色，缺少包络计算则无区域可比较，缺少覆盖计数判定则无法区分单覆盖和多覆盖区域。

从多条实心条分别生成菱形填充区域，根据每个像素被覆盖的次数决定着色——单覆盖取该条颜色，多覆盖统一标记为冲突色。

**输入结构**：黑(0)背景网格，约 20x20。网格中有 2-4 条单像素宽的实心条（可为水平或垂直），每条长 3-9 像素，颜色各不相同，取自 {蓝(1), 红(2), 绿(3)}。各条之间不物理接触，但位置关系使得它们的菱形包络部分重叠。无其他前景元素。

**规则**：
1. 对每条实心条，计算其菱形填充区域：所有背景(0)像素中，到该条最近像素的曼哈顿距离不超过 floor((L-1)/2) 的像素集合（L 为条长度）。条自身的像素也包含在本条的区域中。
2. 根据每个像素被覆盖的区域数量着色：
   - 被恰好一个区域覆盖：涂为该条的颜色。
   - 被两个或更多区域覆盖：涂为黄(4)。
   - 属于某条自身的像素：保持该条原色不变（即使被多个区域覆盖）。
3. 不在任何区域内的像素保持黑(0)。
4. 处理顺序无影响，因为规则基于覆盖计数而非顺序绘制。

**关键洞察**：菱形区域不是外轮廓描边（区别于 c97c0139），而是填充区域；覆盖检测（改编自 0520fde7 的逻辑与）作用于从条几何属性计算出的掩码，而非输入中直接给定的位图。求解者须先从条长度推导区域，再判断重叠。

    top: dest_r0 = 0
    bottom: dest_r0 = H - object_bbox_height
  output_constraints:
    no_overlap: objects must not overlap after placement at top/bottom
    sufficient_gap: grid tall enough that top objects and bottom objects don't collide

generation_strategy:
  approach: output-first, then scatter to get input
  steps:
    1. Pick H, W in [19, 30]
    2. Choose 4-6 objects; create >=1 duplicated shape group and >=1 unique shape
    3. For each template, grow a random 8-connected shape of area 3-12 within a 2-5 x 2-5 bbox
    4. Duplicate-group members are copies of a template under random rotation/flip; singleton shapes must not match any other shape up to rotation/flip
    5. Assign each object a distinct non-bg color (reuse allowed if needed for >9 objects)
    6. Place duplicated-shape objects at row 0 and unique-shape objects at row H-h in the output grid
    7. Ensure no pixel overlap among all placed objects
    8. Build input by moving each object to a random row in the interior, preserving c0
    9. Validate main(input) == output

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
