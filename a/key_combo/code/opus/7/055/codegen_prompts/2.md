## 新题 2：像素并集涌现形状匹配决定滑动方向

**组合逻辑**：[计数/分组](已有，按颜色分组) → [像素并集 pixel_union](创新：从关系判断变为主动构造操作，将两个精灵体合并为一个涌现形状) → [形状匹配 shape_match + 旋转翻转等价 dihedral_equiv](已有) → [滑动 slide + 碰撞停止 collision_stop](已有)

**来源原语**：像素并集、双掩码并集等三（参考题 fea12743）；形状匹配、归一化掩码、旋转翻转等价（参考题 6165ea8f）；滑动、墙壁列、同色物体朝同色墙、近者优先不重叠、碰撞停止（参考题 f0100645）

**依赖链**：颜色分组确定哪两个精灵体配对→配对后计算像素并集产生一个"涌现形状"→涌现形状与墙边参考形状做旋转翻转等价匹配→匹配结果决定该对精灵体向哪面墙滑动。不计算并集则无形状可匹配；不做等价匹配则不知滑动方向；不理解滑动规则则不知最终位置。涌现形状在输入中不以单一对象存在，这是组合产生的新逻辑。

在一个左右各有彩色墙壁的网格中，内部散布着成对的小精灵体；将每对精灵体的像素并集与墙边参考形状做旋转翻转等价匹配，匹配到哪面墙的参考形状就向哪面墙滑动。

**输入结构**：约 16x16 网格。背景为黑(0)。最左列全部为蓝(1)（左墙），最右列全部为红(2)（右墙）。紧邻左墙内侧（第 2 列起）有一个灰(5)参考形状，3~5 像素，4-连通；紧邻右墙内侧（倒数第 2 列起）有另一个灰(5)参考形状，3~5 像素，4-连通，与左侧参考形状在旋转翻转下不等价。网格内部散布若干小精灵体，每个精灵体 2~4 像素、4-连通。这些精灵体使用若干非墙非灰的颜色（如绿(3)、黄(4)、橙(7)等），每种颜色恰好出现两个精灵体，形成配对。同色的两个精灵体在空间上不相邻（边界框间距至少 2 像素），且两者的像素无重叠位置。生成约束：每对精灵体的像素并集（将两个精灵体平移到以其联合边界框左上角为原点后合并）在旋转翻转下恰好匹配左侧或右侧参考形状之一，不存在两者都匹配或都不匹配的情况。

**规则**：
1. 按颜色将内部精灵体分组——每种非墙非灰颜色恰好有 2 个精灵体组成一对。
2. 对每对精灵体，计算联合边界框（包含两者的最小矩形），将两个精灵体的像素坐标平移到以该联合边界框左上角为原点，取像素并集得到一个掩码。
3. 将该掩码与左侧灰(5)参考形状和右侧灰(5)参考形状分别做旋转翻转等价比较（8 种 dihedral 变换）。
4. 若并集掩码匹配左侧参考→该对的两个精灵体各自向左滑动（保持形状，水平平移），按照离左墙近的先处理的顺序，每个精灵体滑到碰触左墙或已定位的同方向精灵体时停止（精灵体边界框的最左像素抵达障碍右侧相邻列即停）。
5. 若匹配右侧参考→该对向右滑动，规则对称。
6. 两个灰(5)参考形状在输出中保持不变。左右墙保持不变。
7. 不同对之间的滑动互不干扰（不同颜色的精灵体可以在最终位置重叠，后处理的覆盖先处理的；处理顺序：按配对颜色在输入中首次出现的行优先、列优先的阅读序）。

**关键洞察**：没有任何单个精灵体能告诉你它的目的地——必须先将两个同色精灵体合成一个从未在输入中以单一对象出现的"涌现形状"，再通过旋转翻转等价识别该形状，才能确定滑动方向。
