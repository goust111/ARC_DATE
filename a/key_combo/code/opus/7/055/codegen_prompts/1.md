## 新题 1：环路弯折分类驱动选择性象限对称

**组合逻辑**：[环路追踪 trace_cycle](已有) → [分类涂色 classify_and_color](创新：分类结果不仅决定颜色，还决定是否参与对称复制) → [对称补全 symmetry_complete](创新：不同类别像素的反射行为不同，凹弯折不参与反射)

**来源原语**：环路追踪、弯折像素、直行像素、分类涂色（参考题 15663ba9）；对称补全、十字轴线、双轴对称（参考题 60d73be6）

**依赖链**：环路追踪的输出（弯折分类）决定对称补全的输入筛选——凸弯折像素参与全象限反射，凹弯折像素被标记但不反射，直行像素参与全象限反射。分类结果直接改变反射操作的作用范围。删除追踪则无法分类；删除分类则所有像素等同反射（输出错误）；删除反射则无象限扩展。

在一个被十字轴线划分为四象限的网格中，追踪单一象限内的闭合正交环路并分类其弯折像素，然后将凸弯折和直行像素反射到其余三个象限，而凹弯折像素仅保留在原始象限并变色。

**输入结构**：约 17x17 网格。背景为黑(0)。一条完整行和一条完整列由蓝(1)像素填满，形成十字轴线，将网格分为四个象限。恰好一个象限（例如左上）内存在一个由绿(3)像素构成的闭合正交环路：该环路是 4-连通的、一像素宽的闭合回路，每个前景像素恰好有 2 个 4-邻域前景邻居。环路包含至少 2 个凸弯折和至少 1 个凹弯折（即环路不是简单矩形）。其余三个象限为纯背景。生成约束：环路的边界框完全在该象限内，不与十字轴线相邻。

**规则**：
1. 追踪占据象限内的闭合正交环路。对每个像素判定类型：若像素的两个邻居在同一条直线上（水平或垂直），该像素为**直行像素**；否则为**弯折像素**。
2. 对环路中的弯折像素统计转向方向（从前一段到后一段的左转或右转）。出现次数较多的转向方向对应**凸弯折**，出现次数较少的方向对应**凹弯折**。
3. 将环路像素按类型分三组处理反射（反射轴为蓝(1)十字轴线的行和列）：
   - **凸弯折像素**：反射到其余三个象限（跨行轴、跨列轴、跨两轴各一份副本），副本颜色为黄(4)。原位保留绿(3)。
   - **直行像素**：反射到其余三个象限，副本颜色保持绿(3)。原位保留绿(3)。
   - **凹弯折像素**：**不反射**，仅将原位颜色从绿(3)改为红(2)。
4. 蓝(1)十字轴线保持不变。反射副本若落在十字轴线上则不绘制（轴线优先）。
5. 若任何反射副本超出网格边界，则裁剪丢弃。

**关键洞察**：对称补全并非全量复制——凹弯折作为结构缺陷被选择性抑制，导致输出在三个反射象限中出现与原始象限不同的"缺口"。求解者必须先理解环路追踪和弯折分类，才能预测哪些像素会出现在哪些象限。

Recolor each closed orthogonal line loop so convex bend pixels are yellow and concave bend pixels are red.

Input structure
- The grid has a dominant background and exactly one foreground color.
- The foreground forms one or more 4-connected one-pixel-wide closed cycles; every foreground pixel has degree 2.
Rule
- Trace each cycle and inspect the turn at each foreground pixel.
- Straight pixels keep the original foreground color.
- Bend pixels whose turn direction is the majority direction for that cycle are convex corners and become yellow.
- Bend pixels whose turn direction is the minority direction for that cycle are concave corners and become red.
Key insight
- A simple rectilinear closed boundary has exactly four more convex bends than concave bends, so convexity can be inferred structurally from the majority turn sign within each traced cycle.
</description>

  background: 7 [observed]
  cross:

  steps:
    1. Pick grid size H in [8,17], W in [8,17].
    2. Pick cross row r in [3, H-4] and cross col c in [3, W-4]. Choose cross_color != bg.
    3. Choose one of the 4 quadrants as the populated quadrant.
    4. Pick 5-7 distinct marker colors (all != bg, != cross_color).

       Allow color repeats but ensure no two markers at the same cell.
    6. Verify no reflection conflicts: for each pair of markers, their 4 reflected positions

    7. Fill the cross row and column with cross_color. Fill the rest with bg. Place markers.
    8. The 3 empty quadrants (plus possibly parts of the populated quadrant's reflections
       that land out of bounds) are left as bg -- this is the input.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
