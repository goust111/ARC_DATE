## 新题 5：压缩后的计数分类面板

**组合逻辑**：[压缩](创新：压缩对象不是棋盘格颜色而是离散精灵体) + [标记定压缩方向] → [计数](创新：计数的是压缩后共列/共行的精灵体数量) + [分类] + [朝向分组](创新：精灵体的朝向决定进入哪个面板列) → [计数映射槽位]

**来源原语**：压缩/边缘标记/标记定压缩方向(5e6bbc0b)，计数/分类/朝向分组/面板/槽位/朝向决定面板/计数映射槽位(d5c634a2)

**依赖链**：边缘标记决定压缩方向；所有精灵体沿该方向压缩堆叠后，统计每行（或每列）堆叠了多少个精灵体。精灵体有两种朝向（如开口朝左或朝右的 C 形），朝向决定计数结果进入输出面板的左列还是右列。压缩改变了精灵体的空间分组，使得计数结果依赖于压缩方向的选择。

将精灵体沿边缘标记方向压缩堆叠，按朝向分类统计每行/列的堆叠数，编码到输出面板。

**输入结构**：约 14x14 的黑(0)背景网格。包含 6~8 个单色小型精灵体（4-连通，3~5 像素），颜色为红(2)。每个精灵体是一个非对称的小图形，具有可辨识的朝向——约一半开口朝左（记为 L 型），另一半开口朝右（记为 R 型）。精灵体散布在网格中，互不接触。网格的某一条边（上/下/左/右）上有一个绿(3)色单像素边缘标记。生成约束：精灵体的行/列分布使得沿不同方向压缩会产生不同的行/列堆叠分组；L 型和 R 型精灵体在各行/列中的分布不均匀。

**规则**：
1. 确定压缩方向：绿(3)标记在左边 = 向左压缩，右边 = 向右，上边 = 向上，下边 = 向下。
2. 将每个精灵体视为刚体，沿压缩方向平移，直到其最外侧像素到达网格边缘或紧贴另一个已到位的精灵体（精灵体之间不重叠），精灵体保持原形状和朝向不变。按离目标边缘从近到远的顺序处理各精灵体（离边缘近的先到位）。
3. 压缩完成后，沿垂直于压缩方向的轴统计：若压缩方向为水平（左/右），则统计每一行中有多少个精灵体的像素出现在该行；若为垂直（上/下），则统计每一列。同一个精灵体跨多行/列时，每行/列各计一次。
4. 对每行/列的精灵体计数，按朝向分为 L 型计数和 R 型计数。
5. 输出一个面板：行数（或列数）等于输入网格中有精灵体像素出现的行数（或列数），宽为 2 列。左列用蓝(1)填充该行 L 型精灵体的计数个槽位（从上往下填），右列用黄(4)填充 R 型计数个槽位。每个槽位为 1 像素。无精灵体的行在面板中对应行全黑。

**关键洞察**：压缩方向改变了"哪些精灵体共享同一行/列"的分组结果。同样的精灵体配置在向左压缩和向上压缩时会产生完全不同的行/列分组，从而导致面板输出截然不同。求解者必须先模拟压缩过程，再进行分组计数，而非直接统计原始位置。
