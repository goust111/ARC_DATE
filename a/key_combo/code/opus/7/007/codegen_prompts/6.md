## 新题 6：方向精灵体编码旋转角度后旋转配对图案

**组合逻辑**：[旋转/rotate](创新：旋转角度不是固定的 90 度，而是由方向精灵体的朝向编码) + [裁剪/crop](已有) ← 关系 [质心偏移定向/centroid_bias_dir](已有) + [颜色编码方向](创新：方向不编码滑动方向而编码旋转角度) ← 对象 [方向精灵体/directional_sprite] + [方形网格/square_grid]

**来源原语**：旋转、方形网格 ← ed36ccf7；射线延伸、方向精灵体、质心偏移定向 ← 13f06aa5；裁剪 ← 83eb0a57

**依赖链**：方向精灵体的体像素质心偏移确定朝向 → 朝向映射到旋转角度 → 该角度施加于与精灵体配对的方形图案块。删除质心分析则旋转角度未知；删除旋转则方向信息无处应用。

每个方向精灵体的体像素质心偏移指示一个方向，将该方向映射为旋转角度，旋转与之配对的方形图案块，拼合输出。

**输入结构**：约 14x14 的黑(0)背景网格，包含 2~4 对"精灵体 + 方形图案块"。每个方向精灵体由灰(5)体像素（约 5~7 像素的 8-连通形状）和一个嵌入其中的彩色标记像素组成（标记颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，每对使用不同颜色）。体像素围绕标记像素分布，但质心偏向标记的某一侧（上/下/左/右）。与每个精灵体配对的是一个同色边框的方形图案块：用该标记颜色画 1 像素宽边框围成 4x4 或 5x5 的正方形，内部由黑(0)和栗(9)像素组成的非对称图案填充。精灵体与其配对图案块在同一行或同一列上，且该行/列上仅有这一对。生成约束：各对之间的图案块尺寸相同；各精灵体的质心偏移方向互不相同。

**规则**：
1. 识别所有方向精灵体：含有灰(5) 8-连通像素群且内部恰嵌入一个非灰(5)非黑(0)标记像素的结构。识别所有方形图案块：由某种非背景非灰颜色的 1 像素宽正方形边框围合的区域。
2. 配对规则：精灵体中标记像素的颜色与图案块边框颜色相同的为一对。
3. 对每个精灵体，计算其灰(5)体像素的质心（行坐标均值, 列坐标均值），以及标记像素的坐标。质心相对于标记的偏移向量 = (质心行 - 标记行, 质心列 - 标记列)。取行分量和列分量中绝对值较大者确定主轴：若 |行分量| > |列分量| 且行分量 > 0 则尾部朝下、朝向为上；行分量 < 0 则尾部朝上、朝向为下；若 |列分量| >= |行分量| 且列分量 > 0 则尾部朝右、朝向为左；列分量 < 0 则尾部朝左、朝向为右。
4. 朝向映射为顺时针旋转角度：朝上 = 0 度、朝右 = 90 度、朝下 = 180 度、朝左 = 270 度。
5. 对每个配对的方形图案块（包含边框），以其几何中心为旋转中心做对应角度的顺时针旋转。
6. 输出：将所有旋转后的方形图案块按其标记颜色对应的精灵体标记像素在输入中的位置（从左到右扫描列坐标，列坐标相同时从上到下扫描行坐标），从左到右水平拼合成一行，块间无间隔。输出高度 = 图案块边长，宽度 = 图案块边长 x 配对数。

**关键洞察**：旋转角度没有被任何像素的颜色直接编码——它隐藏在方向精灵体中灰(5)体像素相对于标记像素的空间分布中，需要计算质心偏移才能推断朝向，再将朝向翻译为旋转角度。
