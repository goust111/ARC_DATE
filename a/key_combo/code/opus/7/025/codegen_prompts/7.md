## 新题 7：模板匹配后按旋转朝向分涂颜色

**组合逻辑**：[模板匹配 + 含旋转反射变换](已有) → [旋转分类](创新：不仅匹配模板，还识别每个匹配实例相对于参考方位的旋转角度) → [重涂色](已有，但颜色由旋转角度决定而非统一涂色)

**来源原语**：模板匹配(template_matching, 来自 50f325b5), 含旋转反射变换(includes_rotation_reflection, 来自 50f325b5), 非重叠放置(non_overlapping_placement, 来自 50f325b5), 旋转(rotate, 来自 46442a0e), 重涂色(recolor, 来自多源)

**依赖链**：提取青色参考图案作为模板 → 生成模板的四个旋转变体 → 在网格中扫描绿色像素找到每个匹配位置 → 确定每个匹配对应哪个旋转变体 → 按旋转角度分涂不同颜色。匹配操作和旋转分类紧耦合：不仅要找到"在哪里"，还要判断"以什么朝向"，两者共同决定输出颜色。

在网格中找出参考图案的所有旋转副本，并根据每个副本相对于参考方位的旋转角度涂不同颜色。

**输入结构**：约 15x15 的黑(0)背景网格。包含一个青(8)的小参考图案（4-6 个像素，8-连通，非对称——即其四个旋转变体两两不同）。网格中另有若干绿(3)像素区域，其中隐藏着参考图案的精确旋转副本（仅允许 0/90/180/270 度旋转，不含反射）。绿色像素中也混有少量不属于任何模板匹配的干扰像素。生成约束：至少有 3 个不重叠的绿色匹配实例，覆盖至少 2 种不同的旋转角度；参考图案必须是旋转不对称的（4 个旋转变体的归一化掩码互不相同）；各匹配实例不重叠。

**规则**：
1. 提取青(8)参考图案的包围框归一化二值掩码，记为 T0（0 度，原始方位）。
2. 生成 T0 的三个旋转变体：T90（顺时针 90 度）、T180（180 度）、T270（顺时针 270 度）。
3. 按行主序扫描网格，对每个位置尝试放置 T0、T90、T180、T270。若某变体 Tk 的所有掩码位置上的像素都是绿(3)，且该放置不与任何已选放置重叠，则选中该放置并记录旋转角度 k。
4. 对每个选中的放置，将其像素重涂为：
   - 0 度匹配 → 红(2)
   - 90 度匹配 → 黄(4)
   - 180 度匹配 → 橙(7)
   - 270 度匹配 → 蓝(1)
5. 青(8)参考图案保持不变。未被选中的绿(3)像素（干扰像素）保持绿(3)不变。黑(0)背景不变。

**关键洞察**：颜色编码了朝向——求解者不能仅仅找到模板的位置然后统一重涂，必须逐一判断每个副本的旋转角度。由于参考图案是旋转不对称的，四个旋转变体形状各异，这使得旋转分类成为一个非平凡的视觉推理步骤。仅看一个示例可能误以为所有匹配都涂同一颜色。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
