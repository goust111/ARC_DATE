## 新题 10：端点编码位移，障碍绕行留下弯曲迁移轨迹

**组合逻辑**：[平移/translate](创新：位移向量不直接作用于精灵体，而是定义一个目标位置，实际路径需绕行) + [生长/grow](创新：生长方向不固定为"向上"，而是朝目标位置的主方向) + [端点编码位移/endpoints_encode_disp] + [遇障碍则绕行/detour_on_obstacle] + [路径端点/path_endpoint]

**来源原语**：平移、端点编码位移、路径端点（2b9ef948）；生长、遇障碍则绕行、障碍像素（d9f24cd1）

**依赖链**：路径端点编码了位移向量（平移目标），但精灵体不能直接跳到目标位置——它必须沿主位移方向逐步移动，遇到障碍则垂直于主方向绕行。位移编码决定"去哪里"，障碍分布决定"怎么去"，两者交织生成最终的迁移轨迹。

灰色路径两端的彩色像素编码一个位移向量；精灵体沿该方向逐步迁移，遇障碍则垂直绕行，留下弯曲轨迹。

**输入结构**：黑(0)背景，约 14x14 网格。一个黄(4)精灵体（约 2x2 或 3x2 的小实心矩形）。一条灰(5)像素构成的路径（3-6 个像素，可弯折），两端分别连接一个红(2)像素和一个蓝(1)像素。橙(7)障碍像素散布在精灵体与目标位置之间的区域。生成约束：位移向量（从红端到蓝端）的主方向（水平或垂直中较大分量方向）上，精灵体与目标位置之间有足够空间；障碍不覆盖精灵体初始位置或目标位置；精灵体经绕行后能到达目标位置。

**规则**：
1. 找到灰(5)路径两端的红(2)像素 R 和蓝(1)像素 B。计算位移向量 D = B - R = (dr, dc)。
2. 将位移 D 应用于精灵体的左上角，得到目标位置 T。
3. 确定主移动方向：若 |dr| >= |dc| 则主方向为垂直（向上或向下取决于 dr 的符号），副方向为水平；否则主方向为水平，副方向为垂直。
4. 从精灵体当前位置开始，逐步将精灵体沿主方向移动一格：
   - 若精灵体在目标位置处沿主方向的下一格无橙(7)障碍像素与精灵体占据的格子重叠，则正常移动。
   - 若有障碍重叠，则改为沿副方向移动一格（方向选择使精灵体更接近目标的副方向坐标；若两者等距则选行号/列号较小的方向）。
5. 精灵体每离开一组格子，将那些格子标记为栗(9)轨迹色（除非该格已有其他非黑内容）。
6. 精灵体到达目标位置后停止。擦除灰路径和红蓝端点（设为黑(0)）。保留橙障碍。

**关键洞察**：灰色路径的弯折走向完全不影响位移——只有两端的彩色像素坐标差才有意义。但精灵体的实际迁移轨迹可能因障碍而高度弯曲，与编码的直线位移截然不同。
