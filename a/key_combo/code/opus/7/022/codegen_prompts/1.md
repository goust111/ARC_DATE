## 新题 1：封闭区域计数驱动瓦片自增殖

**组合逻辑**：[洪泛填充](用于拓扑检测而非着色) + [计数](区域数→平铺维度) + [裁剪](标记区域→瓦片源) + [平铺](由计数结果参数化)

**来源原语**：洪泛填充(#19 00d62c1b), 计数(#4 a59b95c0), 裁剪(#11 995c5fa3), 平铺(#4 a59b95c0), 封闭区域(#19), 边界(#19), 拓扑内外(#19), 种子像素(#6 8a6d367c)

**依赖链**：洪泛填充的拓扑分析同时产出两个信息——区域总数 N 和各区域的形状；种子像素标记哪个区域被裁剪为瓦片源；N 控制瓦片的行列重复次数。删掉洪泛填充则无法得到 N 和区域划分；删掉裁剪则无瓦片可铺；删掉计数则不知铺多少次。

输入中有多个封闭区域，其中一个被种子标记；将标记区域裁剪为瓦片，按区域总数 N 在两个方向各平铺 N 次。

**输入结构**：约 12x12 的黑(0)背景网格。绿(3)像素构成 3~5 条互不相交的闭合边界曲线（每条曲线为 4-连通的环形像素链，围成一个封闭区域；各封闭区域面积在 4~12 像素之间，形状各异——非全为矩形，可包含不规则轮廓）。恰好一个封闭区域的内部含有一个红(2)种子像素。其余封闭区域内部为纯黑(0)。绿边界之间互不相邻（最小间距 >= 2 像素），保证拓扑分区无歧义。

**规则**：
1. 对网格做拓扑分析（等价于从网格外部对黑像素做洪泛填充），识别所有被绿(3)边界完全封闭的内部区域，记区域总数为 N。
2. 找到包含红(2)种子像素的那个封闭区域，取其最小包围盒（含绿边界像素），裁剪为一个小矩形瓦片 T。裁剪时红(2)种子像素替换为黑(0)（种子不出现在输出中）。
3. 输出一个 (N * T_h) x (N * T_w) 的网格（T_h、T_w 为瓦片 T 的高和宽），将 T 在行方向重复 N 次、列方向重复 N 次，紧密排列。
4. 输出仅包含平铺后的内容，不保留原始网格中的其他区域或背景。

**关键洞察**：封闭区域的数量和形状分别承担不同角色——数量控制平铺规模，被标记区域的形状决定瓦片内容。两者都来自同一次拓扑分析，但用途完全不同；需要对比多个示例才能区分"哪个区域做瓦片"与"有多少区域"这两条规则。

    target_cell: apex + 5 * dir

    at least one of {sprite-hit, multi-projectile collision} occurs per grid
    typical mix: 0-3 sprite hits, 0-2 collision points, rest are lone bg markers

  approach: output-first (place sprites + pre-chosen landing events, then erase landings for input)
  steps:

    - pre-sample sprite positions AND their (kind, direction) jointly so that every apex+5*dir lies in-bounds; reject placements that would make two sprites 8-adjacent (Chebyshev < 2)
    - for each "hit" event: pick a target sprite first, then add a shooter whose apex+5*dir lands on one of the target's 3 pixels (try all 8 directions; choose a kind compatible with that direction)
    - for each "collision" event: pick a bg cell, then add 2+ shooters whose apex+5*dir equals that cell
    - for remaining shooters: pick any apex+dir with target cell empty and not coinciding with other shooters' targets
