## 新题 6：对称补全后按补全轴分层排列

**组合逻辑**：[对称补全+轴对称反射+控制标记指示源侧](保留) → [裁剪+紧凑排列](创新：排列布局由补全轴方向决定而非仅由输入位置决定) + [排序+空间位置排序](创新：同一轴方向的精灵体内部按原始位置排序)

**来源原语**：对称补全+轴对称反射+控制标记指示源侧+对称轴+控制标记(5b692c0f), 裁剪+紧凑排列+空间位置排序(1990f7a8), 排序(941d9a10)

**依赖链**：控制标记和对称轴决定补全方向及结果形状 → 补全轴方向（水平/垂直）将精灵体分为两组 → 组别决定精灵体在输出图集中的行位置 → 组内按原始输入位置排序决定列位置。补全操作的副产品（轴方向）直接编码了排列结构，使补全和排列不可分离。

各精灵体经对称补全后裁剪，按其对称轴方向分为两组分层排列：水平轴补全的排上层，垂直轴补全的排下层。

**输入结构**：约 20x20 的网格，黑(0)为背景。散布 4~6 个不完整的前景对象，每个对象使用一种非黑、非黄的前景色（蓝(1)、红(2)、绿(3)、品红(6)、橙(7)中各取一种，各对象颜色互不相同）。每个对象内部包含黄(4)像素，由两部分组成：一条连续的黄(4)线段作为对称轴（水平或垂直，长度等于对象在该方向的跨度），以及至少一个偏离轴的黄(4)像素作为控制标记（位于轴的一侧）。对象的边界框约 4x4 至 6x6，各对象之间至少间隔 3 像素。生成约束：至少有一个水平轴对象和一个垂直轴对象。补全后每个对象的边界框不超过 6x6。

**规则**：
1. **对称补全**：对每个含黄(4)轴的对象，识别轴方向（水平或垂直）和控制标记所在侧。以控制标记所在侧为源侧，将源侧的全部像素（含前景色和黑(0)背景）沿轴镜像复制到对侧，覆盖对侧原有内容。轴本身保持黄(4)。
2. **记录轴方向**：标记每个对象的补全轴方向——"H"（水平轴，即上下对称）或"V"（垂直轴，即左右对称）。
3. **裁剪**：对每个补全后的对象裁剪其边界框内容。将裁剪结果中的黄(4)轴像素替换为该对象的前景色（轴融入对象）。
4. **分组排列**：将所有对象按轴方向分为两组：H 组和 V 组。H 组排列在输出图集的上层，V 组排列在下层。每组内部按原始输入中对象边界框左上角的位置排序（先比较行号，行号相同则比较列号，小的在左）。
5. **图集构建**：每个裁剪结果放入一个 6x6 的槽位（左上角对齐，不足部分保持黑(0)）。同一层的槽位水平排列，槽位间水平间隔 1 列。上下层之间垂直间隔 1 行。若某组为空（所有对象都是同一轴方向），则输出仅一层。图集画布大小恰好容纳所有槽位和间隔。

**关键洞察**：对称轴方向不仅决定补全操作的镜像方式，还同时决定了该精灵体在输出中的层级归属——这是原参考题中不存在的结构关系。求解者必须先正确判断每个对象的轴方向才能同时完成补全和分组两项任务。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
