## 新题 8：图例排序组装 + 交替翻转条带拼接

**组合逻辑**：[排序拼接/sort_and_concatenate + 图例顺序对应插槽/legend_order_to_slot](创新：图例排序确定精灵体的组装顺序) → [平铺/tiling + 镜像/mirror + 奇偶位交替翻转/alternating_flip](创新：组装后的条带作为瓦片进行交替翻转平铺)

**来源原语**：排序拼接(sort_and_concatenate)·多像素模板(multi_pixel_template)·单像素标记(single_pixel_marker)·标记共行或共列(markers_share_row_or_column)·按位置排序标记(sort_markers_by_position) ← 12997ef3；精灵体(sprite)·色条图例(color_bar_legend)·插槽(slot)·图例顺序对应插槽(legend_order_to_slot)·缺失色补入对应位(missing_color_fill_slot) ← 94be5b80；平铺(tiling)·瓦片(tile)·拼接(concatenation)·奇偶位交替翻转(alternating_flip) ← bc4146bd

**依赖链**：色条图例定义颜色顺序 → 颜色顺序决定多个单色精灵体的垂直拼接顺序 → 拼接出的纵向条带成为一个复合瓦片 → 该复合瓦片沿水平方向按奇偶位交替左右翻转，构成最终的壁纸输出。图例顺序同时控制拼接排序和隐含的翻转对称性——调换图例中两种颜色的位置会产生不同的翻转视觉效果。

按色条图例的颜色顺序将精灵体纵向拼接成条带，再将条带作为瓦片沿水平方向交替镜像拼贴。

**输入结构**：约 12x14 的网格，黑(0) 背景。包含以下元素：
- 一个水平色条图例：位于网格顶部，由 3~4 个紧邻的单色 1x1 像素组成一行，颜色各不相同（如红(2)、蓝(1)、绿(3)、黄(4)），代表从左到右的排序键。
- 一个灰(5) 单色模板图案：约 3x3 边界框内的 4-连通图形（3~5 个灰像素），位于网格的某处，与色条图例不相邻。
- 0~2 个已放置的精灵体实例：使用图例中某种颜色绘制的模板副本（与灰模板形状相同但颜色不同），位于网格中各处。

**规则**：
1. 读取色条图例中的颜色从左到右的顺序，例如 [红(2), 蓝(1), 绿(3), 黄(4)]。
2. 裁剪灰(5) 模板到其边界框，得到模板掩膜（设尺寸 Th x Tw）。
3. 按图例颜色顺序，为每种颜色生成一个模板副本（将灰像素重涂为该颜色）。将这些副本从上到下垂直拼接（无间隔），得到一个高 N*Th、宽 Tw 的纵向"组合条带"，其中 N 为图例颜色数。
4. 以该组合条带为瓦片，沿水平方向拼接 5 个瓦片宽度的壁纸：第 1、3、5 个位置放原始条带，第 2、4 个位置放条带的左右镜像。
5. 输出即为该壁纸。已放置的精灵体实例、色条图例和灰模板均不保留——它们仅用于推断规则。

**关键洞察**：已放置的精灵体实例是线索而非输出组件——它们帮助求解者确认模板形状和颜色映射规则（尤其当灰模板不明显时），但最终输出完全由图例排序和交替翻转逻辑决定。图例中颜色的排列顺序影响组合条带的内部结构，进而影响镜像翻转后的视觉对称性。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
