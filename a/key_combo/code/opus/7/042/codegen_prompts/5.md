## 新题 5：十字定义对称轴 + 四象限镜像 + 边邻接多数决涂色

**组合逻辑**：[擦除/erase + 镜像/mirror](创新：十字删除后镜像扩展) ⇄ [重涂色/recolor + 邻接多数决/adjacency_majority_rule](创新：镜像接缝处多色相遇时按边邻接数决定颜色)

**来源原语**：镜像(mirror)·擦除(erase)·十字图案(cross_pattern)·前景遮罩(foreground_mask)·象限(quadrant)·对称轴定义(symmetry_axis_def)·十字色作涂色源(cross_as_palette) ← 47c1f68c；重涂色(recolor)·连通分量(connected_component)·边邻接计数(edge_adjacency_count)·邻接多数决(adjacency_majority_rule) ← 477d2879

**依赖链**：十字定义对称轴并被删除 → 上左象限的多色图案被镜像到四个象限 → 在原十字位置形成接缝带 → 接缝带上的每个格被四个象限的镜像副本包围 → 该格的颜色由其 4-邻居中各色的边邻接数多数决定。镜像产生的边界恰好是多数决的判定场所——两个操作在空间上嵌套。

删除十字后将左上象限图案四向镜像扩展；原十字所在的接缝行/列上每格的颜色由相邻镜像副本的边邻接多数投票决定。

**输入结构**：约 11x11 的奇数尺寸正方形网格，黑(0) 背景。一条绿(3) 像素构成的完整水平中线和完整垂直中线在网格中心交叉形成十字。左上象限（不含十字行列）内有由红(2) 和蓝(1) 两种颜色构成的图案（共 4~8 个前景像素），图案的 4-连通分量可以不止一个。其余三个象限（不含十字行列）均为黑(0) 背景。不同示例中左上象限图案的形状和颜色分布不同，但始终使用红(2) 和蓝(1) 两种颜色，且图案至少有一个像素与十字行或十字列 4-邻接。

**规则**：
1. 记录十字颜色绿(3)，然后删除十字（整条水平中线和垂直中线全部设为黑(0)）。网格缩小为去掉中线行和中线列后的偶数尺寸方阵（每象限尺寸不变，四象限紧贴拼合）。
2. 将左上象限的图案同时水平镜像和垂直镜像，放入其余三个象限的对应位置，保留各像素原色（红或蓝）。
3. 在缩小后的网格中，找到原十字行和原十字列被删除后形成的"接缝"——即四个象限两两相邻的边界。接缝不是独立的行/列，而是象限边缘像素之间的 4-邻接关系。
4. 对接缝处的每个像素（即紧邻另一象限边缘的像素），统计其所有 4-邻居的颜色（仅统计非黑色邻居）。若红(2) 邻居数 > 蓝(1) 邻居数，该像素涂为红(2)；若蓝 > 红，涂为蓝(1)；若相等，涂为绿(3)（十字的原色作为平局色）。此规则仅修改接缝处已有颜色的像素，不修改黑(0) 背景像素。
5. 非接缝位置的像素保持镜像后的颜色不变。

**关键洞察**：十字不仅是空间分隔器和颜色提供者，它的删除在接缝处制造了多色碰撞——而碰撞的解决必须用到镜像产生的对称结构和源自另一道参考题的邻接多数决规则。平局时十字色回归，使擦除的十字信息以另一种形式保留在输出中。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
