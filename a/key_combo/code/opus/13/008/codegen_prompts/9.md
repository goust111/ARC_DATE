## 新题 9：逐行反转结果编码双色条移动方向

**组合逻辑**：[反转(invert)](已有，创新：反转结果不作为最终输出而作为中间编码) → [滑动(shift) + 对齐(align)](已有) ← [主色像素(dominant_pixel)](已有) + [干扰色像素(distractor_pixel)](已有) + [双色条(two_color_bar)](已有) + [参考条(reference_bar)](已有) + [逐行独立(row_independent)](已有) + [同色对齐(same_color_align)](已有) + [主色与背景互换 → 反转区域编码移动参数](创新)

**来源原语**：反转(invert)、主色像素(dominant_pixel)、干扰色像素(distractor_pixel)、逐行独立(row_independent)、主色与背景互换(native_bg_swap) ← 2de01db2；滑动(shift)、对齐(align)、双色条(two_color_bar)、参考条(reference_bar)、同色对齐(same_color_align)、首行为参照(top_row_reference) ← 9968a131

**依赖链**：逐行反转产生的空间图案编码了每行双色条的移动方向和距离。不执行反转就无法获得方向信息（方向并非由颜色顺序直接决定，这与原题 9968a131 不同）。不执行滑动则反转结果无用途。反转从"最终变换"降格为"信息编码器"，滑动从"简单方向判断"升级为"依赖计算结果的参数化操作"。

先对每行执行颜色反转以计算出一个方向编码，再根据编码决定该行双色条的滑动方向，最后对齐到参考条。

**输入结构**：黑(0)背景，约 12x15 网格。第 0 行是参考条：两个相邻像素，颜色为蓝(1)和绿(3)，位于某两列（如第 4、5 列）。下方每一行（第 1 行到最后一行）包含：(A) 一个双色条（蓝(1)和绿(3)各一像素，相邻，位置各行不同，可能与参考条对齐也可能不对齐）；(B) 该行剩余位置中，有一种"主色"像素（从红(2)、黄(4)、橙(7)中选取，每行的主色可不同）占据 2~4 个位置，以及 0~2 个"干扰色"像素（灰(5)），其余为黑(0)。生成约束：每行的主色像素数量严格大于干扰色像素数量（保证主色可明确判定）；双色条不与主色/干扰色像素重叠。

**规则**：
1. 第 0 行为参考条，记录蓝(1)所在列为 col_blue，绿(3)所在列为 col_green。
2. 对第 1 行到最后一行，逐行独立处理：
   a. 识别该行的主色（最频繁的非黑(0)、非蓝(1)、非绿(3)颜色）。
   b. 执行概念反转：将该行中主色像素的位置标记为"空"，将黑(0)和干扰色位置标记为"实"（不实际修改网格，只用于计算）。
   c. 统计反转后"实"像素在双色条左侧和右侧的数量。若左侧"实"像素更多，则该行双色条向左滑动；若右侧更多，则向右滑动。相等时不滑动。
3. 确定滑动方向后，将双色条水平平移，直到蓝(1)像素位于 col_blue 列、绿(3)像素位于 col_green 列（即与参考条对齐）。若双色条中蓝绿顺序与参考条一致，直接平移对齐；若顺序相反（需要穿过另一色才能对齐），则先交换双色条内两像素的颜色再平移。
4. 输出网格中仅保留参考条和各行移动后的双色条，其余位置全部变为黑(0)（主色、干扰色像素不出现在输出中）。

**关键洞察**：主色和干扰色像素在输出中完全消失——它们的唯一作用是通过反转计算为双色条的移动方向提供编码信息，这是一种隐蔽的间接控制关系，需要对比多个示例才能发现。
