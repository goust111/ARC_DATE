## 新题 3：逐色对角检测驱动选择性翻转

**组合逻辑**：[对角线对齐检测/diagonal_alignment](逐色检查是否存在对角对齐的像素对) → [连线/draw_line](对齐则画对角线段) → [镜像/flip_within_bbox](画线后的颜色掩码在包围盒内垂直翻转) — 对角检测结果同时产出新几何（线段）并触发翻转，形成条件分支结构

**来源原语**：对角线对齐/diagonal_alignment(55783887), 连线/draw_line(55783887), 逐色独立变换/per_color_transform(e74e1818), 包围盒内翻转/flip_within_bbox(e74e1818), 单色掩码/mono_mask(e74e1818)

**依赖链**：对每种非背景色独立处理。若该颜色的像素中存在恰好一对主对角线对齐（行差 = 列差、方向为左上-右下）的像素，则在它们之间画一条该颜色的对角线段，画完后对该颜色的完整掩码（含新画的线段）在其包围盒内执行垂直翻转。若不存在这样的对齐对，该颜色的像素保持原样。删除对角检测则无法判断哪些颜色要翻转；删除画线则翻转后的形状错误（缺少线段像素）；删除翻转则画线只是连接。

对每种前景色独立检测对角对齐像素对，对齐则画连接线段并在包围盒内垂直翻转该颜色的全部像素，未对齐的颜色保持不变。

**输入结构**：
- 约 14x14 的网格，黑(0)背景。
- 3~5 种非背景前景色，每种颜色由 3~8 个像素构成一个单色掩码（4-连通或 8-连通均可、形状不规则）。
- 各颜色掩码的包围盒互不重叠（保证逐色操作不产生像素冲突）。
- 其中恰好有部分颜色（至少 1 种、至多比总颜色数少 1）的像素集合中存在恰好一对像素满足主对角线对齐（即 r2-r1 = c2-c1 > 0），其余颜色不存在这样的对。
- 生成约束：对角对齐的像素对之间的主对角线段上的所有中间像素位置在输入中均为黑(0)（以便画线）。

**规则**：
1. 对每种非背景颜色 C 独立执行以下判断与操作：
   a. 在颜色 C 的所有像素中，检查是否存在恰好一对 (r1,c1)、(r2,c2) 满足 r2-r1 = c2-c1 > 0（主对角线对齐）。若存在多于一对，选择行差最大的一对（保证唯一）。
   b. 若存在这样的对：用颜色 C 填充从 (r1,c1) 到 (r2,c2) 的主对角线段上所有中间像素。然后计算颜色 C 当前完整掩码（含原有像素和新画的线段像素）的包围盒 [r_top, r_bot] x [c_left, c_right]。将掩码内每个像素 (r, c) 映射到 (r_top + r_bot - r, c)，即在包围盒内垂直翻转。翻转后的像素若落在黑(0)位置则绘制颜色 C，原位置变为黑(0)。
   c. 若不存在对角对齐的对：颜色 C 的所有像素保持原位不变。
2. 所有颜色独立处理，结果叠加到同一网格上。由于包围盒互不重叠，不会产生冲突。

**关键洞察**：对角对齐检测既是画线的触发条件又是翻转的触发条件——同一个几何事实同时驱动两个操作；而画出的线段改变了掩码形状，导致翻转结果与仅翻转原始像素完全不同，两个操作通过共享几何紧密耦合。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
