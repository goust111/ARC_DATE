## 新题 4：字形解密连线

**组合逻辑**：[编码字形 + 字形映射颜色](已有) → [配对](创新：配对依据从空间邻接变为解码后的颜色身份) → [连线 + 同行列端点间填充](已有，创新：端点不再是裸标记像素而是整个字形块) → [重涂色](已有，创新：字形自身被重涂为其解码颜色)

**来源原语**：编码字形(code_glyph) / 字形映射颜色(glyph_maps_color) / 配对(pairing) ← ed74f2f2；连线(draw_line) / 同行列端点间填充(fill_between_aligned_endpoints) / 标记像素(marker_pixel) / 行列对齐(row_col_align) ← 253bf280；重涂色(recolor) ← ad173014

**依赖链**：字形解密确定每个字形的颜色身份 → 同色身份建立配对关系 → 配对双方的空间位置确定连线方向（同行或同列）→ 连线颜色取自解码结果。解密、配对、连线三步紧密耦合：不解密就无法配对，不配对就不知道连哪两个端点，不知道颜色身份就不知道连线该涂什么色。

解码散布在网格上的加密字形以获取其隐藏颜色身份，将同色字形配对，并用该颜色沿行或列方向连接配对端点。

**输入结构**：
- 黑(0)背景，约 12x12 网格。
- 6~8 个 3x3 的灰(5)/黑(0) 字形图案，散布在网格中，各字形之间互不接触且不重叠。每个字形的灰色像素恰好 5 个，形成以下三种编码图案之一：
  - "顶T形"（顶行三像素 + 中列下延两像素）→ 编码蓝(1)
  - "右下折线"（左上起沿中列下行两像素 + 右转沿底行右行两像素，共 5 像素）→ 编码红(2)
  - "左下折线"（右上起沿中列下行两像素 + 左转沿底行左行两像素，共 5 像素）→ 编码绿(3)
- 每种编码颜色恰好出现偶数次（2 或 4 次），形成配对。
- 编码同一颜色的字形配对中，每对恰好满足：两个字形的 3x3 边界框中心在同一行或同一列上对齐（但不同时满足两者）。同色字形多于 2 个时，配对方式唯一（每个字形恰好与一个同色字形行或列对齐）。
- 生成约束：不同配对的连线路径互不交叉；同一行或同一列上不会出现三个及以上同色字形。

**规则**：
1. 解码每个字形：根据其灰色像素图案确定编码颜色（顶T→蓝(1)，右下折线→红(2)，左下折线→绿(3)）。
2. 将编码相同颜色的字形配对。若同色字形有 4 个，按行/列对齐关系唯一确定两组配对。
3. 对每对字形，确定它们的对齐方向（同行或同列），在两个 3x3 边界框之间的间隙中（严格在两个边界框之间、沿对齐轴的中线），将所有背景像素填充为该对的编码颜色。
4. 将每个字形内的灰(5)像素重涂为其编码颜色（黑色像素保持黑色）。

**关键洞察**：字形本身是"加密的端点标记"——外观上所有字形都是灰色的 5 像素图案，看不出颜色信息。必须先破译编码规则（需对比多个示例才能归纳出完整的字形-颜色映射表），才能建立配对关系并确定连线颜色。空间对齐约束提供了验证解码正确性的辅助信号，但单独依赖对齐无法确定配对（因为不同色字形也可能碰巧对齐）。
