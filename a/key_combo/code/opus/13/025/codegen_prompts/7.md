## 新题 7：块阵列重排与中心解码

**组合逻辑**：[色块条带 + 排序 → 块阵列重排](创新：排序目标从条带移动变为 3x3 块在阵列中的位置交换) → [边界像素编码 + 中心重建](已有，创新：编码的正确性依赖于排序结果，排序错误则解码出错误的中心)

**来源原语**：块阵列(block_array) / 空心中心(hollow_center) / 边界像素编码(border_pixel_encoding) / 中心重建(center_reconstruct) / 对称映射(opposite_slot_mapping) ← db0c5428；排序(sort) / 色块条带(color_stripe) / 整块移动保持内容(block_move_intact) / 标记行指示顺序(marker_row_order) ← f18ec8cc

**依赖链**：周围块的排列顺序决定了哪些像素与中心空洞相邻 → 相邻像素构成中心块的边界编码 → 编码决定中心块的内容。因此必须先将块排列到正确位置（通过排序），才能读取到正确的边界编码。排序和解码通过"边界邻接"这一空间关系紧密耦合。

将 3x3 块阵列中被打乱的周围块按其主色频率排序归位，使中心空洞的边界编码恢复正确，再据此重建中心块。

**输入结构**：
- 青(8)背景，网格大小恰好容纳一个 9x9 前景区域（即网格至少 11x11，前景区域居中或偏置）。
- 9x9 前景区域是一个 3x3 的块阵列，每个块为 3x3 像素。中心块（第 2 行第 2 列）为空（全部青色背景）。
- 周围 8 个 3x3 块各有一个主色（非青色的主导颜色，如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、品红(6)、灰(5)、栗(9)），以及若干辅助像素（颜色不同于主色且不同于青色）。8 个块的主色互不相同。
- 当前的 8 个块处于被打乱的位置（不是最终正确排列）。
- 在 9x9 区域外部，有一行 8 个单像素标记，颜色与 8 个块的主色一一对应，按从左到右的顺序给出正确的排列顺序提示。
- 生成约束：8 个块的正确排列是按主色在整个 9x9 区域中出现的总频率从高到低，沿顺时针方向从左上角开始排列（左上 → 上中 → 右上 → 右中 → 右下 → 下中 → 左下 → 左中）。标记行的左到右顺序与此顺时针顺序一致。

**规则**：
1. 统计每个 3x3 块的主色在整个 9x9 区域（不含中心块位置）中的出现总次数（包括该主色在其他块中作为辅助像素出现的次数）。
2. 按出现频率从高到低排序。频率相同时，按标记行中的左右顺序决定先后。
3. 将 8 个块按排序结果依次放入顺时针位置序列：左上(0,0)、上中(0,1)、右上(0,2)、右中(1,2)、右下(2,2)、下中(2,1)、左下(2,0)、左中(1,0)。移动时保持每个块的 3x3 内部像素完整不变。
4. 所有块归位后，读取与中心空洞（位置(1,1)）相邻的 8 个像素（空洞四边和四角的像素，来自周围四个块）。这 8 个像素构成中心块的边界编码。
5. 将中心块的 3x3 格填充为：四边像素直接填入对应边缘位置，四角像素填入对应角位置，中心像素取整个 9x9 区域中出现频率最高的非青色颜色。
6. 移除外部标记行。

**关键洞察**：中心块的重建完全依赖于周围块的排列——不同的排列会使不同的像素与中心空洞相邻，导致解码出完全不同的中心内容。排序规则（按主色频率）本身需要全局统计，而频率统计又包含了块间的辅助像素交叉引用，因此不可能通过局部分析确定正确排列。
