## 新题 4：形状匹配编码旋转后异色补全

**组合逻辑**：[same_shape + translate_normalize](创新：匹配目标是外部提示精灵体而非同类对象) → [rotate + pixel_count_encodes_rotation](创新：旋转量由匹配到的提示精灵体像素数编码) → [completion + missing_diff_color_fill](创新：补全作用于旋转后的几何形态)

**来源原语**：same_shape / translate_normalize / placeholder_obj (ad38a9d0), rotate / pixel_count_encodes_rotation / cue_sprite / same_color_matching (6ffbe589), completion / missing_diff_color_fill / connected_component / inside_bbox (60b61512)

**依赖链**：形状匹配确定旋转量来源 → 旋转改变对象朝向与包围框内空位分布 → 补全填充取决于旋转后的空位。任一步骤删除都导致输出错误。

将不完整的彩色对象与外部单色提示体做形状匹配以确定旋转角度，旋转后对包围框内缺失像素做异色补全。

**输入结构**：约 14x18 的网格。背景为黑(0)。网格左侧区域有 3 个不同颜色的 4-连通不完整对象（如红(2)、绿(3)、蓝(1)），每个对象 5~8 像素，各自的包围框为 4x4，包围框内有 2~4 个黑(0)空位。三个对象互不相邻（包围框不重叠）。网格右侧区域有 3 个灰(5)小精灵体（提示），每个提示精灵体 3~6 像素，形状各异。每个提示精灵体的平移归一化形状恰好等于某个左侧对象去除空位后的平移归一化形状（可能需要旋转 0/90/180/270 度后匹配）。三个提示精灵体的像素数分别对应旋转角度：像素数 mod 4 = 0 不旋转，= 1 顺时针 90 度，= 2 顺时针 180 度，= 3 顺时针 270 度。生成约束：每个左侧对象恰好匹配一个右侧提示（一一对应）；三个旋转量互不相同。

**规则**：
1. 提取每个左侧彩色对象的非空像素集合，做平移归一化（将最小行列移到原点）。对每个右侧灰色提示精灵体同样做平移归一化。
2. 对每个左侧对象，逐一尝试将其归一化形状旋转 0/90/180/270 度，与每个提示的归一化形状比较。找到匹配的提示。
3. 该对象的旋转角度 = 匹配提示的像素数 mod 4 x 90 度（顺时针）。以对象包围框中心为旋转中心，将对象整体旋转该角度。旋转后的像素位置取整到最近网格格点。
4. 在旋转后对象的新 4x4 包围框内，将所有黑(0)空位涂为黄(4)。对象原色像素保持不变。
5. 右侧灰色提示精灵体在输出中擦除为黑(0)背景。网格其余区域不变。

**关键洞察**：旋转改变了包围框内空位的空间分布——同一个对象旋转 90 度后，需要补全的位置完全不同。求解者必须先通过形状匹配找到正确的提示精灵体，才能知道旋转多少度，才能知道在哪里补全。
