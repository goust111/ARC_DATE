## 新题 10：标记带划分驱动列局部涂色后平铺

**组合逻辑**：[扩展/中点划分归属](标记像素定义横带边界) + [计数/列选择](带内含前景的列被选中涂色) → [平铺](涂色后的结果 2x2 平铺)

**来源原语**：扩展/expand、边框绘制/frame_drawing、单像素标记/single_pixel_marker、横带/horizontal_band、按行排序/sorted_by_row、中点划分归属/midpoint_band_assignment（来自 0f63c0b9）；重涂色/recolor、前景列/foreground_column、列选择/column_selection、含前景列整列涂色/fg_col_full_recolor（来自 f5b8619d）；平铺/tiling（来自 f5b8619d）

**依赖链**：标记像素行位置 → 中点划分产生横带边界 → 每个横带内独立判断哪些列含前景 → 这些列在该带内的黑背景格被涂青 → 带内的涂色决策在不同带之间独立（同一列在上带可能涂色而在下带不涂） → 涂色完成后整体 2x2 平铺。列选择是带局部的，而非全局的——这是与参考题 f5b8619d 的核心区别。

按标记像素的行位置中点划分横带，在每个横带内独立执行列选择涂色，然后将结果 2x2 平铺。

**输入结构**：约 7x7 的黑(0)背景网格（输出为 14x14）。含 2~3 个孤立的单像素标记，每个使用不同颜色（如红(2)、蓝(1)），位于不同行。另有若干绿(3)前景像素稀疏分布。标记像素和绿像素均不在网格边缘行。生成约束：标记行互不相同；至少存在一列在某个横带内含绿像素而在另一横带内不含（确保带局部列选择产生带间差异）。

**规则**：
1. 按行号排序所有标记像素。在相邻标记行之间取中点（向下取整）作为横带分界行。网格顶部到第一个中点为第一带，相邻中点之间为中间带，最后一个中点到网格底部为最后一带。
2. 对每个横带独立执行：扫描该带行范围内的每一列，若该列在此行范围内存在至少一个绿(3)像素，则将该列在此带行范围内的所有黑(0)像素涂为青(8)。绿(3)像素和标记像素本身保持不变。
3. 将步骤 2 完成后的 7x7 网格进行 2x2 平铺：水平重复 2 次、垂直重复 2 次，输出 14x14 网格。

**关键洞察**：列涂色判断是横带局部的——同一列可能在上带因有绿像素而整列涂青，在下带因无绿像素而保持黑色。这使得输出平铺图案中出现「断列」效果（同一列在不同横带区域有不同颜色），而这种效果在原始参考题的全局列选择中不会出现。标记位置同时决定了带边界（哪些行属于哪个带）和带内有哪些前景像素可用。

Overlay the colored contents of same-sized blank panels after removing the dominant separator color.

Input structure
- The most common color is a separator surrounding several rectangular
  panels made from a common blank color plus sparse colored marks.
- The panels are 4-connected regions of non-separator cells, and all panel
  bounding boxes have the same shape.
Rule
- Create one blank panel of that common shape.
- For each input panel, copy every non-blank mark to the same relative
  position in the output panel.
Key insight
- The large separator color is not part of the answer; the answer is the
  transparent overlay of the small drawings inside its panels.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
