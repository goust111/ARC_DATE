## 新题 4：符号双重编码——颜色解码与位移方向

**组合逻辑**：[符号解码](从 3x3 掩码解码出颜色) + [平移](创新：位移方向不由固定颜色-方向映射表决定，而由同一符号掩码中灰像素的重心偏向编码) ← [颜色编码位移](保留"颜色分组移动"的思路，但方向来源从固定映射变为符号几何)

**来源原语**：符号解码(symbol_decoding) ← 17cae0c1；符号映射颜色(symbol_to_color_mapping) ← 17cae0c1；平移(translate) ← 342dd610；颜色编码位移(color_encoded_disp) ← 342dd610；颜色决定偏移(color_determines_offset) ← 342dd610

**依赖链**：符号掩码 → 解码出颜色（确定"移动谁"）+ 掩码几何重心偏向 → 确定位移方向（确定"往哪移"）→ 在下方操作区找到该颜色的像素并平移。符号同时承载颜色身份和运动指令，两个信息从同一输入元素中提取且缺一不可。

3x3 符号掩码同时编码目标颜色（通过二值图案查表）和位移方向（通过灰像素重心偏向），下方操作区中对应颜色的像素按该方向平移。

**输入结构**：约 10x15 的黑(0)背景网格。顶部 3 行为符号区，被分为若干相邻的 3x3 面板（2-4 个），每个面板内为黑(0)/灰(5)二值掩码图案。每个掩码的灰(5)像素数量在 3-5 个之间，形成非对称的 4-连通图形。底部区域（第 5 行起）散布若干单色像素点，颜色来自解码后的调色板（如蓝(1)、红(2)、绿(3)等），每种颜色 1-3 个像素点，点之间互不相邻。符号区与操作区之间有 1 行黑色空行分隔。生成约束：每个符号掩码解码出的颜色互不相同；掩码中灰像素的重心在 3x3 面板内明确偏向四个基本方向之一（上/下/左/右），即重心行坐标或列坐标偏离中心 (1,1) 至少 0.3 格；操作区中的像素平移后不超出网格边界。

**规则**：
1. 对每个 3x3 符号面板，将灰(5)像素视为 1、黑(0)视为 0，形成二值掩码。使用任务内置的符号-颜色码本将该掩码解码为一种颜色（码本需从多个示例中归纳）。
2. 计算该掩码中所有灰(5)像素相对于面板中心 (1,1) 的重心偏移 (dr, dc)。取绝对值较大的维度确定位移方向：若 |dr| > |dc|，dr < 0 为上、dr > 0 为下；若 |dc| >= |dr|，dc < 0 为左、dc > 0 为右。位移步长固定为 2 格。
3. 在底部操作区找到所有与该符号解码颜色相同的像素，将它们沿确定的方向平移 2 格。保留像素原色。
4. 如果平移后某像素落在已有非黑像素上，后移动的覆盖先到的。
5. 符号区和空行保持不变；操作区中被移走的原始位置恢复为黑(0)。

**关键洞察**：同一个 3x3 符号承担双重角色——其二值图案编码颜色身份，其灰像素空间分布编码运动方向——求解者必须同时提取这两层信息，单独理解任一层都无法完成变换。
