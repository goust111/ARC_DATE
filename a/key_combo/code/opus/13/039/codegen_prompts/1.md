## 新题 1：滑动精灵撞击矩形触发位置分类重涂

**组合逻辑**：[方向编码](创新：从着色标记扩展为精灵内部标记像素编码方向) → [滑动] → [碰撞停止] → [局部位置分类 + 重涂色](创新：分类涂色的颜色来自精灵的双色结构而非固定色)

**来源原语**：滑动/sliding、方向编码/direction_encoding（a8c38be5）；碰撞停止/collision_stop（9bbf930d）；重涂色/recolor、局部位置分类/local_position_classification、矩形/rectangle（b6afb2da）；标记像素/marker_pixel（88a10436）

**依赖链**：精灵内部标记像素的相对位置编码滑动方向 → 精灵沿该方向滑动直到碰撞一个矩形停下 → 碰撞确定哪个矩形被选中 → 该矩形按角/边/内部分类重涂，涂色颜色由精灵的标记色和主体色分别提供。删除方向编码则不知往哪滑；删除碰撞则不知选哪个矩形；删除位置分类则不知怎么涂。

将每个携带方向标记的小精灵滑向它编码的方向，碰撞一个灰色矩形后，用精灵的双色结构对该矩形进行角/边/内部重涂。

**输入结构**：
- 背景：黑(0)。网格约 15x15。
- 2~3 个实心灰(5)矩形（每个至少 4x4），散布在网格中部区域，彼此不相邻、不接触网格边缘。
- 2~3 个小型单色精灵（每个 3~6 像素，4-连通，非矩形轮廓，各自颜色不同，选自红(2)、绿(3)、蓝(1)），分布在矩形外围。
- 每个精灵内部恰有 1 个像素颜色与该精灵主体色不同，称为"方向标记像素"（颜色选自黄(4)、橙(7)、栗(9)等与主体色不同的颜色）。
- 方向标记像素位于精灵包围盒中心的上/下/左/右某一侧（不在正中心），其相对位置编码滑动方向：标记在中心上方→向上滑，标记在右侧→向右滑，以此类推。
- 生成约束：每个精灵沿其编码方向直线滑动时，路径上恰好会遇到一个灰矩形（不会遇到其他精灵或第二个矩形）。不同精灵撞击不同矩形（一一对应）。

**规则**：
1. 对每个精灵，确定其方向标记像素相对于精灵包围盒中心的方位（上/下/左/右），该方位即为滑动方向。
2. 将整个精灵（含标记像素）沿该方向逐格平移，直到精灵的任一像素的下一步会与某灰矩形的像素重叠，此时精灵停在重叠前的最后合法位置。
3. 停下后，识别精灵紧邻的那个灰矩形为其"目标矩形"。
4. 对目标矩形执行位置分类重涂：矩形的四个角像素涂为精灵的方向标记色；矩形的非角边缘像素涂为精灵的主体色；矩形的严格内部像素保持灰(5)不变。
5. 精灵本身从网格上擦除（其最终停留位置的像素恢复为背景色）。
6. 未被任何精灵撞击的灰矩形保持原样。
7. 处理顺序：按精灵初始包围盒左上角从左到右排列，左列相同时从上到下。此顺序仅影响叙述清晰性，因为各精灵撞击不同矩形且互不干扰。

**关键洞察**：精灵的双色结构承担双重角色——方向标记像素的位置编码了滑动方向，而标记色和主体色分别成为目标矩形角和边的重涂颜色；同一个标记像素既是运动指令又是涂色素材。
