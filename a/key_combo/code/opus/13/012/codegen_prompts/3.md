## 新题 3：十字中心检测为括号提取注入内容

**组合逻辑**：[四向对齐/four_way_aligned + 缺失中心/missing_center](已有) → 内容生成 → [括号界定提取范围/bracket_delimited_extraction](已有) → [堆叠/stacking](已有)

**来源原语**：recolor、micro_bar、implied_plus、four_way_aligned、missing_center（参考题 4: 9f5f939b）；crop、stacking、control_pixel_pair、row_segment、bracket_delimited_extraction、equal_width_segments_stacked_in_row_order（参考题 5: 505fff84）

**依赖链**：检测隐含十字中心并标黄 → 黄色像素成为网格内容的一部分 → 括号提取收割含黄色的行段 → 堆叠生成输出。跳过十字检测则输出中缺少黄色中心信息；跳过括号提取则不知道输出包含哪些行段。

在散布微型条的网格中检测隐含十字并标记中心，然后用括号界定符提取特定行段并堆叠，输出中既有原始内容又有检测生成的标记。

**输入结构**：约 20x20 网格，黑(0)背景。灰(5)水平和竖直 2 像素微型条（每条恰好 2 像素，宽 1 像素）散布于网格中。部分微型条按四向对齐排列：以某个背景像素为中心，上下左右各有一条同方向的微型条（竖直条在上下，水平条在左右），中心与每条微型条之间隔 1 像素背景，微型条距中心 2~3 格。这样的四元组构成一个隐含十字。还有一些不参与十字的孤立微型条。另外，某些行上存在成对的控制像素：每行至多一个蓝(1)像素在左侧、一个青(8)像素在右侧，所有此类行的蓝青间距相同。生成约束：至少 2 个隐含十字的中心恰好位于被括号界定的行上（即中心所在行同时有蓝青控制对），至少 1 个中心不在任何括号行上（其标黄效果对输出不可见）。括号行有 4~6 行。

**规则**：
1. 扫描整个网格，找到所有满足以下条件的背景像素 P：P 的上方第 2~3 行同列有灰(5)竖直微型条，下方第 2~3 行同列有灰(5)竖直微型条，左方第 2~3 列同行有灰(5)水平微型条，右方第 2~3 列同行有灰(5)水平微型条。P 上下左右紧邻（距离 1）的四个像素必须为背景。将 P 涂为黄(4)。
2. 识别所有带蓝(1)-青(8)控制对的行，从上到下排列。
3. 对每个括号行，复制蓝与青之间（不含蓝和青本身）的所有像素作为一行输出段。该段中可能包含灰(5)微型条片段、黄(4)中心标记、或黑(0)背景。
4. 将所有输出段按行从上到下的顺序堆叠，组成输出网格。输出宽度 = 蓝青间距，输出高度 = 括号行数。

**关键洞察**：十字中心检测是一个纯几何推理步骤，它在网格中"凭空"创造黄色像素；括号提取是一个独立的空间裁剪机制。两者的耦合在于：检测产生的内容能否出现在最终输出中，完全取决于它碰巧落入了哪些括号行——十字的位置和括号的位置共同决定输出。
