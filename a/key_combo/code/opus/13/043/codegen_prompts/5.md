## 新题 5：色配滑动触框后镜像入内

**组合逻辑**：[颜色匹配归属](创新：颜色不再用于配对色映射，而是用于确定滑动目标) → [滑动](创新：滑动终点不由碰撞决定，而由颜色匹配的天线像素所在框决定) → [镜像](创新：镜像轴不固定，由滑动接触的框边动态决定) → [擦除](已有)

**来源原语**：滑动(slide, 05f2a901), 碰撞阻挡(collision_blocking, 05f2a901), 镜像(mirror, 6855a6e4), 跨框中线反射入内(reflect_centerline_in, 6855a6e4), 矩形边框(rectangular_frame, 7ee1c6ea), 最近邻归属(nearest_assign, 6855a6e4), 擦除(erase, 多题)

**依赖链**：颜色匹配确定精灵体的目标框（通过天线像素），滑动方向由精灵体与目标框的相对位置决定，滑动停止时接触的框边决定镜像轴方向，镜像将精灵体"穿过"框壁翻转到框内部。任何一步的输出都是下一步的必要输入：无匹配则不知目标，无滑动则不知接触哪条边，无接触边则无法确定镜像轴。

将外部精灵体通过颜色匹配找到对应的带天线框，滑动至框边后，以接触的框边为镜像轴翻转进入框内部。

**输入结构**：约 18x18 网格，黑(0) 背景。包含 2-3 个灰(5) 色的薄矩形框（1 像素厚边框，内部至少 6x6），彼此不重叠。每个框的某一条外边上恰好有 1 个彩色"天线"像素（紧贴框外壁，4-邻接于该壁的某个像素），天线颜色各不相同，取自 {蓝(1), 绿(3), 黄(4)}。在远离所有框的位置，有等量的 4-连通单色精灵体（每个 3-7 像素），每个精灵体的颜色与某个天线颜色相同（一一对应）。生成约束：每个精灵体与其匹配框之间恰好存在一条无障碍的水平或垂直路径，使得精灵体沿该方向滑动可以到达框的某一条外壁；精灵体镜像入框后不超出框的内部边界。

**规则**：
1. 通过颜色匹配将每个精灵体与其同色天线像素配对，从而确定目标框。
2. 擦除所有天线像素（置为背景色）。
3. 确定滑动方向：精灵体沿与目标框之间行对齐或列对齐的基本方向（上/下/左/右）滑动。若精灵体在框的正左方（精灵体所有像素的列坐标均小于框左壁列坐标，且精灵体的行范围与框的行范围有重叠），则向右滑动；若在正上方，则向下滑动；以此类推。
4. 滑动精灵体（整体平移），每次移动 1 格，直到精灵体的边界框与框的外壁之间恰好相距 0 格（紧贴但不重叠于框壁）。
5. 确定镜像轴：精灵体最终紧贴的那条框壁即为镜像轴。
6. 以该框壁所在的直线为镜像轴，将精灵体的每个像素翻转到框的内部。保持精灵体的原色不变。
7. 擦除精灵体在框外的原始位置（滑动终点处的像素置为背景色），仅保留框内的镜像副本。
8. 框的灰(5) 边框像素始终保留。
9. 处理顺序：按精灵体颜色在 {蓝(1), 绿(3), 黄(4)} 中的编号从小到大依次处理。若两个镜像副本在框内重叠，后处理的覆盖先处理的（但生成时保证不会发生多个精灵体进入同一个框的情况）。

**关键洞察**：精灵体的"旅程"有三个耦合阶段——颜色匹配选择目的地，滑动方向决定接触哪条框壁，接触的框壁决定镜像轴方向。从左侧接近的精灵体被水平翻转入框，从上方接近的被垂直翻转入框，镜像轴不是预设的而是滑动行为的涌现结果。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
