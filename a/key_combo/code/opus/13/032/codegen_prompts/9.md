## 新题 9：碎片补全数量决定边框高亮

**组合逻辑**：[像素放大 + 模板匹配 + 缩放旋转对齐碎片](已有匹配逻辑) → [补全](创新：补全不仅恢复视觉而且产生计数信号) → [计数](创新：计数对象是补全像素数而非独立对象) → [重涂色](创新：由补全量的比较结果驱动，最大者高亮)

**来源原语**：像素放大、模板匹配、缩放旋转对齐碎片、模板、碎片 ← 6aa20dc0；补全、完整图案推断缺失 ← 72322fa7；边框矩形 ← a6f40cea；计数 ← f8b3ba0a；重涂色 ← 多题

**依赖链**：识别模板 → 对每个边框匹配缩放/旋转 → 补全缺失像素 → 统计各边框补全量 → 补全量最大的边框重涂色。补全操作同时产生视觉输出和数值输出，数值输出驱动后续选择。

用一句话概括：将各边框内的残缺碎片与模板的缩放旋转版本对齐并补全，然后将补全像素最多的边框高亮为红色。

**输入结构**：
- 网格约 20x20，灰(5)背景（最常见的非黑色）。
- 一个小型多色模板对象（3x3 或 4x4，使用 2-3 种不同的非灰色前景色），位于一个孤立角落。
- 网格其他位置有 2 到 3 个边框矩形，每个边框用黑(0)绘制 1 像素厚的边框。每个边框内部填充灰(5)背景加上一个部分碎片（一些正确放置的非灰色像素，匹配模板在某个整数倍缩放 2x 或 3x 和某个旋转 0°/90°/180°/270° 下的图案）。各边框内的缩放或旋转各不相同，碎片的存在比例也不同（例如 30%、50%、70% 的期望非灰像素存在）。
- 生成约束：对每个边框，现有碎片像素唯一确定缩放和旋转（无歧义）。各边框的补全数量（需填入的缺失像素数）两两不同。

**规则**：
1. 识别模板：不同颜色种类最多的非灰色对象。
2. 对每个边框矩形：
   a. 提取内部区域（黑(0)边框之内的所有内容）。
   b. 尝试模板的所有整数缩放（2x、3x）与旋转（0°、90°、180°、270°）的组合。
   c. 找到唯一的缩放+旋转组合，使得内部现有的非灰色像素与对应模板像素完全匹配（无颜色冲突）。
   d. 按匹配到的缩放旋转模板填入缺失像素（将内部应为非灰色但当前为灰(5)的单元格涂上模板对应的颜色）。
   e. 记录补全像素数 C（本边框填入的像素数量）。
3. 补全像素数 C 最大的边框：将其黑(0)边框重涂为红(2)。
4. 其余边框保持黑(0)边框不变。
5. 角落的模板保持不变。

**关键洞察**：补全操作既是视觉恢复（填入缺失像素）也是数值信号（补全计数）。"损坏最严重"（需要最多补全）的边框被高亮——求解者不仅需要重建每个碎片，还需要比较重建工作量的大小。

<description>
Decode a block-grid image by swapping each sprite-coded cell with a solid cell and each blank cell with the sprite.

Input structure
The grid is partitioned by black separator rows and columns into equal-size
square blocks. Each block is either a copy of one two-color sprite or a
uniform blank block of the sprite's minority color; grey pixels are erased
cells that act as wildcards.

Rule
Infer the repeated sprite from fully visible mixed-color blocks. Replace a
block matching that sprite, ignoring grey erasures, with a solid block of
the sprite's majority color. Replace a uniform blank block with the sprite.
Separator rows and columns, including grey erasures on them, become black.

Key insight
The small sprite is a block-level code for one macro-cell state, and the
uniform minority-color block is the other state; the output renders the
opposite code in each macro-cell while cleaning erased pixels.

  sprite: a block_size x block_size tile using both payload colors; foreground fills 67-75% of cells; no LR/UD/180 symmetry [observed]; counts of two colors must differ
  block_states: each NxN macro-cell is either sprite (copy of the sprite tile) or blank (solid blank_color); sprite blocks >= blank blocks [observed]

  at_least_one_clean_sprite: >= 1 block has no grey and contains the full two-color sprite (needed to infer sprite)
  output: same grid size; separator lines become all-black; sprite blocks become solid foreground; blank blocks become the sprite tile; no grey remains

generation_strategy:
  approach: output-first
  steps:
    1. Pick N (2-4) and block_size (2-4). Compute grid side = N*block_size + (N-1).
    2. Pick two payload colors (not 0 or 5).
    3. Generate a random block_size x block_size sprite using both colors, foreground filling 67-75% of cells, counts distinct, no all-one-color rows/cols [observed].
    4. Build the NxN block state map (sprite or blank for each macro-cell). Ensure >= 1 sprite and >= 1 blank.
    5. Construct the output grid: sprite blocks -> solid foreground, blank blocks -> sprite tile, separators -> black.
    6. Construct the clean input grid (before grey): sprite blocks -> sprite tile, blank blocks -> solid blank_color, separators -> black.
    7. Generate a grey blob: pick a random seed cell, grow via BFS/random-walk across the grid (crossing separators), replacing cells with grey (5). Ensure each block keeps >= 1 non-grey cell and remains unambiguous. Ensure >= 1 block stays fully clean with 2 colors (a sprite block). Grey covers 5-25% of grid.
