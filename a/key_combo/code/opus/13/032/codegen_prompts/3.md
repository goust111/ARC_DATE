## 新题 3：拉丁方解编码精灵体旋转参数

**组合逻辑**：[补全 + 拉丁方约束](创新：补全结果不是最终输出而是中间指令) → [计数](创新：读取特定颜色在完成列中的行位置作为数值) → [旋转](创新：旋转量由拉丁方单元格值决定而非由标记像素决定)

**来源原语**：补全、色表、空白单元、拉丁方约束、行列唯一约束 ← 4cd1b7b2；旋转 ← 0e206a2e / 6aa20dc0 / ecaa0ec1；精灵体 ← 多题；分隔行 ← dc46ea44

**依赖链**：补全拉丁方（唯一解）→ 读取每列中关键色的行位置 → 行位置作为旋转量应用于对应精灵体。若不补全则旋转量未知；关键色需要对比多个示例才能识别。

用一句话概括：补全一个部分填充的拉丁方色表，以每列中黄色所在行号作为对应精灵体的 90 度旋转次数，输出旋转后的精灵体。

**输入结构**：
- 网格约 14x18，黑(0)背景。
- 一条全宽灰(5)分隔行将网格分为上区和下区。
- 上区：一个 4x4 像素区域表示部分填充的拉丁方。调色板为{蓝(1)、红(2)、绿(3)、黄(4)}。黑(0)像素为空白。已填入的单元格满足行列唯一性约束。部分填充具有唯一补全方案。
- 下区：4 个小型单色精灵体（每个 3x3 至 4x4 像素，各为不同的非对称 4-连通形状），颜色分别为蓝(1)、红(2)、绿(3)、黄(4)。精灵体从左到右排列并有间隔，使得精灵体 j 位于拉丁方第 j 列的正下方（j = 0,1,2,3，从左到右）。
- 生成约束：每个精灵体不具有 90 度旋转对称性（确保每种旋转产生视觉上不同的结果）。

**规则**：
1. 补全拉丁方：将每个黑(0)单元格替换为{蓝(1)、红(2)、绿(3)、黄(4)}中满足行列唯一性的唯一颜色。
2. 对每列 j（0-3，从左到右），在已补全的列中找到黄(4)所在的行索引 r（0-3，从上到下）。
3. 第 j 列下方的精灵体原地旋转 r x 90 度顺时针（0 = 不旋转，1 = 90° CW，2 = 180°，3 = 270° CW）。旋转以精灵体边界框中心为轴心，若中心落在半像素处则向左上取整。
4. 仅输出下区（含旋转后的精灵体）。上区和分隔行被丢弃。

**关键洞察**：黄(4)是"关键色"——它在每列中的行位置控制旋转量。这是一条隐蔽规则：仅凭单个示例，任何颜色都可能是关键色；必须对比多个示例才能确认始终是黄色起决定作用。拉丁方是中间计算过程而非最终答案。
