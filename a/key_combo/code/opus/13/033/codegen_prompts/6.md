## 新题 6：重力激活容器触发精灵印章

**组合逻辑**：[重力下落(gravity_drop) + 列对齐落入(column_fall_in)](已有) → [填充(fill) + 容器(container)](已有) → [印章覆盖(stamp) + 源图案(source_pattern)](创新：容器激活不仅触发填充，还在容器上方印章精灵图案) + [无容器则铺满底行(no_container_floor)](已有，作为对照分支)

**来源原语**：重力下落、列对齐落入、容器、填充、无容器则铺满底行、标记像素(db7260a4)；印章覆盖、源图案、控制色选中则印章(ad7e01d0)

**依赖链**：标记像素的列坐标决定哪个容器被激活 → 激活同时触发两个操作：容器内填充 + 容器开口上方印章 → 印章位置由容器的空间位置决定（非标记像素位置）。印章逻辑依赖容器激活，容器激活依赖重力落入，三层因果不可拆分。

顶行标记像素沿列下落；若落入 U 形容器则填充容器并在其上方印章精灵图案；若未命中任何容器则仅在底行留下痕迹。

**输入结构**：约 18x20 的黑(0)背景网格。第 0 行有 2~4 个黄(4)标记像素（各占不同列，互不相邻）。网格下半区域有 2~3 个红(2)U 形容器：每个容器由两条竖直侧壁（各 3~5 像素高）和一条连接底部的水平底边构成，内部为黑(0)空腔，开口朝上。容器宽度 3~5 列，各容器互不重叠且不在同一行。网格左下角（与容器不重叠的区域）有一个由蓝(1)和绿(3)像素构成的 3x3 精灵图案（源图案），以其边界框定义。生成约束：至少一个标记像素的列落在某容器的水平跨度内，至少一个标记像素的列不落在任何容器内。不同示例中容器位置和标记列不同。

**规则**：
1. 从输出中移除所有黄(4)标记像素（设为黑(0)）。
2. 定位源图案区域：左下角中由蓝(1)/绿(3)像素构成的 3x3 块，裁剪为印章模板 S。源图案在输出中被擦除（设为黑(0)）。
3. 对每个标记像素（按列坐标从左到右处理）：
   a. 确定该标记的列坐标 col。
   b. 检查是否存在某个 U 形容器，使得 col 落在该容器左侧壁列与右侧壁列之间（含端点）。
   c. 若命中容器：
      - 将该容器内部空腔（侧壁之间、底边之上的所有黑像素）填充为黄(4)。
      - 将印章模板 S 以容器开口中心列为水平对称轴、以容器顶行上方第 1 行为 S 底行，印章到网格上。若印章超出网格上边界则裁剪。
      - 若多个标记命中同一容器，填充和印章只执行一次（幂等）。
   d. 若未命中任何容器：
      - 将网格最后一行第 col 列的像素设为黄(4)。不执行印章。
4. 若两个不同容器的印章在空间上重叠（容器开口很近），列坐标较小的容器的印章先绘制，列坐标较大的后绘制并覆盖重叠部分。
5. 红(2)容器结构（侧壁和底边）保持不变。

**关键洞察**：容器激活是一个"一石二鸟"的触发——同一个重力落入事件同时引发填充（在容器内部）和印章（在容器外部上方）两个空间分离的操作。仅看无碰撞的标记像素会以为规则只是"底行标记"，必须对比命中容器的示例才能发现完整的激活-印章机制。
