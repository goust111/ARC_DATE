## 新题 1：掏空即通道——路径穿越实心矩形

**组合逻辑**：[路径生长](创新：遇障碍不偏转而是穿透掏空后的内腔) + [掏空](创新：由路径碰撞动态触发，非预设全部掏空) + [重涂色](创新：穿越事件触发路径后续颜色转变)

**来源原语**：路径生长(path_grow)、控制像素(control_pixel)、底行起始(bottom_row_origin) ← #1 712bf12e；掏空(hollowing)、实心矩形(solid_rectangle)、保留边擦除内部(keep_border_erase_interior) ← #7 4347f46a；重涂色(recolor) ← #4 36fdfd69

**依赖链**：路径生长决定哪些矩形被碰撞 → 碰撞触发掏空，打通矩形内腔形成通道 → 穿越矩形事件使路径后续段变色 → 先处理的路径掏空矩形后，后续路径若碰到同一矩形的边框（已掏空，无法再次穿透）则停止，因此处理顺序产生路径间的竞争依赖

控制像素向上生长的路径穿透并掏空所遇的实心矩形，穿越后路径变色为红(2)；已被掏空的矩形边框会阻断后续路径。

**输入结构**：
- 黑(0)背景网格，约 15x20。
- 底行（最后一行）包含 2~4 个控制像素，颜色各不相同，取自蓝(1)、绿(3)、teal(8)中不重复选取。各控制像素不在同一列。
- 底行上方散布 3~5 个实心灰(5)矩形，每个至少 3 行 x 3 列（确保有严格内部）。矩形之间互不重叠、互不相邻（间距至少 1 个黑像素），且不接触底行。
- 生成约束：每个控制像素的正上方列范围内至少存在一个灰矩形可被碰撞；不同控制像素可能碰撞不同矩形，也可能有两个控制像素的列穿过同一个矩形。

**规则**：
1. 按列坐标从左到右的顺序逐一处理各控制像素。
2. 对当前控制像素 (r_bottom, c)，令当前路径颜色 = 该控制像素的颜色，从 (r_bottom - 1, c) 开始逐步向上生长：
   - 2a. 若上方单元格为黑(0)（背景），将其涂为当前路径颜色，继续向上一步。
   - 2b. 若上方单元格为灰(5)且属于一个**尚未被掏空**的实心矩形：
     - 对该矩形执行掏空：保留其 1 像素厚的灰(5)边框，将严格内部全部设为黑(0)。
     - 路径从该矩形底边框进入，穿过刚清空的内部（沿当前列垂直向上，将内部的每个黑像素涂为当前路径颜色），从顶边框穿出。边框像素本身保持灰(5)不被路径涂色。
     - 穿出顶边框后（即顶边框上方一个单元格起），当前路径颜色切换为红(2)。后续所有步骤使用红(2)。
   - 2c. 若上方单元格为灰(5)且属于一个**已被掏空**的矩形的边框，路径停止（无法二次穿透）。
   - 2d. 若上方单元格超出网格上边界，路径停止。
   - 2e. 若上方单元格为非黑、非灰的其他颜色（即另一条路径已涂过的像素），路径停止。
3. 所有路径处理完毕后的网格即为输出。

**关键洞察**：掏空不是预先对所有矩形执行，而是由路径碰撞按需触发；同一矩形只能被第一条碰到它的路径穿透，之后变为不可穿透的空心边框。因此路径的左右处理顺序直接决定哪条路径能穿越、哪条被阻断。
