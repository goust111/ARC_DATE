## 新题 6：像素面积决定滑动优先级与遮挡裁决

**组合逻辑**：[计数(counting)](统计各精灵面积) → [滑动(slide)](创新：面积排名决定处理顺序) → [遮挡覆盖(occlusion_overwrite)](创新：面积作为遮挡优先级的裁决依据)

**来源原语**：计数(counting) ← 9565186b；滑动(slide/sliding) ← 3906de3d/f3e62deb；碰撞阻挡(collision_blocking) ← 3906de3d；遮挡覆盖(occlusion_overwrite) ← 13713586；边缘实心条(solid_edge_bar) ← 13713586；按距离排序绘制(draw_ordered_by_distance) ← 13713586；频率排序(frequency_ranking) ← 9565186b

**依赖链**：像素面积统计 → 决定滑动处理顺序（大优先） → 先到者成为后续精灵的物理障碍 → 若最终 bounding box 重叠，面积大者覆盖面积小者的重叠像素。同一个属性（面积）贯穿三个决策层级，不做面积排序就无法确定任何后续步骤。

精灵按面积从大到小依次向边缘滑动并堆叠，体积大的先定位且在重叠时享有遮挡优先权。

**输入结构**：约 16x16 黑(0)背景网格。第 0 行为栗(9)实心满行条。网格中有 4-5 个单色精灵体，颜色互不相同（可为红(2)、绿(3)、蓝(1)、黄(4)、品红(6)），每个精灵是 4-连通形状，像素数在 3-8 之间且互不相同。精灵分布在第 4-14 行之间。生成约束：至少有两个精灵的 bounding box 在列方向有 1-2 列重叠（保证滑动后可能产生遮挡冲突）。

**规则**：
1. 统计每个精灵的像素数量（面积），按面积从大到小排序。面积相同时（由生成约束保证不会出现），按 bounding box 左上角行号从小到大排序。
2. 按排序顺序依次处理每个精灵：将精灵整体向上滑动，保持形状不变。精灵停止条件为：其 bounding box 顶行到达第 1 行（紧贴栗色条下方），或者其任一像素的目标位置已被先前停止的精灵占据。
3. 所有精灵停止后，检查遮挡冲突：若两个已停止精灵的像素占据了同一个格子（因形状不规则且列方向有重叠导致），面积较大的精灵保留该格子像素，面积较小的精灵在该格子的像素被擦除为黑(0)。
4. 栗(9)实心条保持不变。原始位置的精灵像素全部清除（输出中精灵只出现在滑动后的新位置）。

**关键洞察**：面积不仅是一个被动统计量，而是同时扮演"调度器"（决定谁先移动）和"裁判"（决定冲突中谁胜出）两个角色。先移动者占据有利位置，又因面积大而在遮挡时获胜——这两个优势来自同一属性但通过不同机制生效。
