## 新题 1：滑动吞噬标记后按吞噬数重涂色

**组合逻辑**：[滑动(slide)](创新：滑动路径覆盖散布标记) → [计数(counting)](创新：统计被覆盖的标记数) → [重涂色(recolor)](按吞噬数映射目标色)

**来源原语**：滑动(slide) ← f3e62deb/3906de3d；计数(counting) ← 1190e5a7/9565186b；重涂色(recolor) ← aabf363d/bb43febb；碰撞阻挡(collision_blocking) ← 3906de3d；边缘实心条(solid_edge_bar) ← 13713586

**依赖链**：滑动改变精灵的空间位置 → 新位置决定精灵覆盖了哪些标记像素 → 被覆盖的标记数量决定精灵的最终颜色。计数结果只有在滑动完成后才能确定，重涂色规则只有在计数完成后才能执行。

将散布的标记像素视为"资源"，每个精灵滑向边缘时吞噬路径上的标记，吞噬数量决定最终颜色。

**输入结构**：约 15x15 黑(0)背景网格。顶部第 0 行为灰(5)实心条（满行）。网格中散布 3-5 个单色精灵体（每个精灵为 4-连通单色形状，3-6 像素，颜色各不相同，可为红(2)、绿(3)、蓝(1)、橙(7)等）。精灵体分布在第 3-12 行之间。网格中另有 8-15 个孤立的黄(4)标记像素，散布在各行各列，不与任何精灵相邻。生成约束：每个精灵所在列的正上方（从精灵顶部到灰条之间）至少有 1 个黄标记像素；不同精灵的列范围（bounding box 水平投影）互不重叠。

**规则**：
1. 识别顶部灰(5)满行为边缘实心条，确定滑动方向为向上。
2. 每个精灵整体向上平移，直到其 bounding box 顶边紧贴灰条下方（即 bounding box 顶行 = 第 1 行）。
3. 精灵在滑动过程中，其 bounding box 扫过的矩形区域（从原始位置到最终位置的竖直条带）内所有黄(4)标记像素被"吞噬"——在输出中这些黄像素消失（变为黑(0)）。
4. 统计每个精灵吞噬的黄标记像素数量 N。
5. 根据 N 重涂精灵颜色：N=1 → 红(2)；N=2 → 蓝(1)；N=3 → 绿(3)；N>=4 → 品红(6)。精灵形状不变，仅颜色改变。
6. 不在任何精灵列范围内的黄标记像素保持不变。灰条保持不变。

**关键洞察**：精灵的最终颜色不取决于它的初始颜色或位置，而取决于它滑动路径上恰好有多少标记像素——这是一种"空间采样"决定属性的规则，只有理解了滑动路径的几何范围后才能确定计数。

        * Ensure sprite body and marker do not touch (8-neighbor) any anchor, any other sprite, or the border (leave >=1 bg gap except where slide clips allowed).
    - Optional (10-20% of grids): add 1-4 distractor singleton pixels of one anchor color scattered in interior (each isolated 8-neighbor), same color as a left/right anchor (they also slide vertically).
    - Invert: for each sprite (and distractor), pick a scatter displacement along the OPPOSITE axis of its slide (horizontal anchors => move sprite vertically away; vertical anchors => move horizontally away) by some random nonzero offset, keeping sprite inside grid and non-overlapping. Remove original aligned sprite pixels (set to bg), paste at scattered location. This yields the input.
