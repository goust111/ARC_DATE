## 新题 6：引导边旋转后压缩为象限色图

**组合逻辑**：[旋转/镜像](已有) → [象限映射压缩](已有，创新：被压缩对象需先经过旋转对齐)

**来源原语**：旋转、镜像、引导边、边框控制、颜色匹配朝向、裁剪(fc7cae8d)；象限映射、压缩、实心矩形面板、彩色标记、标记在面板象限内、标记半区定输出(19bb5feb)

**依赖链**：引导边颜色与边框控制匹配确定旋转方式 → 旋转改变面板内 2x2 标记的象限归属 → 裁剪掉引导边后做象限压缩。旋转方向判断错误则标记落入错误象限，输出完全不同。删去旋转则标记象限归属不正确；删去压缩则无法得到 2x2 输出。

**输入结构**：约 12x12 的黑(0)背景网格。网格的两条不同边界（如上边和右边）各有一条纯色边（边框控制），颜色各不相同（如上边为橙(7)、右边为栗(9)）。网格中央有一个灰(5)填充的矩形面板（约 7x7），面板的两条边各有 1 像素宽的引导边，颜色分别为橙(7)和栗(9)，与两条边框控制颜色对应。面板内部（不含引导边的区域）含有 1-3 个 2x2 的单色标记块，颜色各不相同（如红(2)、蓝(1)、绿(3)），散布在不同象限。生成约束：引导边的初始位置与对应边框控制所在的边不同（需要非恒等的旋转/镜像才能对齐）。面板内 2x2 标记的分布使得旋转前后至少有一个标记的象限归属发生变化。

**规则**：
1. 确定旋转/镜像变换：找到唯一的二面体群变换（旋转 0/90/180/270 度和/或水平/垂直镜像的组合），使面板的橙(7)引导边朝向网格的橙(7)边框控制所在边，同时栗(9)引导边朝向栗(9)边框控制所在边。
2. 对面板整体（含引导边和内部标记）应用该变换。
3. 裁剪掉旋转后面板的两条引导边，剩余灰色面板内部作为压缩对象。
4. 将裁剪后的面板中线水平和垂直各分为上下左右两半，生成 2x2 输出网格，初始为黑(0)。
5. 每个 2x2 标记块的中心落入哪个半区，其颜色就填入输出的对应单元格。无标记的象限保持黑(0)。

**关键洞察**：不做旋转直接压缩会得到错误的象限映射。引导边颜色编码了"面板的正确朝向"，但引导边本身在压缩前必须被裁剪，因此它们的信息是一次性的——读取后即丢弃。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
