## 新题 2：去重压缩后自相似印章展开

**组合逻辑**：[压缩/去重](移除重复相邻行列恢复种子) → [印章覆盖](种子自身作为掩码和模板进行自相似展开)

**来源原语**：压缩、去重、相邻重复、合并相同行列（e1baa8a4）；印章覆盖、种子精灵、像素到块映射、前景位放自身副本（5b6cbef5）

**依赖链**：印章覆盖的模板和掩码都是压缩的输出——在压缩完成前，既不知道要印什么图案，也不知道在哪些位置印——两步不可拆分。压缩的正确性直接决定展开结果。

将一个被行列拉伸的网格先压缩回种子，再用种子在自身前景位置递归印章展开。

**输入结构**：约 12x12 至 20x20 的网格，无黑(0)背景（所有像素均为非零色）。网格是某个小尺寸种子（3x3 至 5x5）经行列各自重复若干次拉伸而成：每一行被复制了 k_r 次（k_r 在 2~4 之间，不同示例可不同），每一列被复制了 k_c 次（k_c 在 2~4 之间，k_c 可以不等于 k_r）。种子使用黑(0)作为背景和一种非零前景色（如红(2)）。种子中前景像素数量在 3~7 之间。

**规则**：
1. 识别所有相邻且完全相同的行组，保留每组的第一行；对结果再识别所有相邻且完全相同的列组，保留每组的第一列。得到的矩阵即为种子。
2. 以种子为单位构建输出网格：输出尺寸为（种子行数 x 种子行数）行 x（种子列数 x 种子列数）列，划分为种子行数 x 种子列数个块，每块大小等于种子。
3. 遍历种子的每个像素位置 (r, c)：若该位置为前景色，则将种子的完整副本写入输出中对应的第 (r, c) 块；若该位置为黑(0)背景，则对应块全部填黑(0)。
4. 副本中的颜色与种子完全一致（前景色不变，背景保持黑(0)）。

**关键洞察**：行与列的拉伸倍数可能不同（如行重复 3 次但列重复 2 次），仅看单个示例无法确定是先去行重复还是先去列重复——需要对比多个示例确认"先行后列"的去重顺序和各自的倍数独立性。

<description>
Move each marked cross object away from its marker to the grid edge while rotating the colored cross 180 degrees.

Input structure:
- The background is the dominant color.
- Each 8-connected foreground object has nine pixels: a 4-pixel marker-color
  sprite attached to a 5-pixel non-marker colored cross.
- Each object bbox is either 3x6 or 6x3, so the marker sprite is on exactly
  one side of the cross.

Rule:
- Move the whole object straight away from its marker side until the object
  bbox touches the corresponding grid edge.
- Keep the marker sprite unchanged within the object.
- Rotate the 3x3 colored cross block by 180 degrees before placing it.

Key insight:
The marker sprite is a directional tail; the cross is the leading payload,
and only that payload turns around during the slide to the edge.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
