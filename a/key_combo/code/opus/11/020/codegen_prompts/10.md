## 新题 10：递增色段长度编码旋转角度

**组合逻辑**：[逐行递增 + 色段](读取递增色段序列提取长度信息) → [编码映射](长度值映射为旋转角度) → [旋转 + 拼接](对目标精灵体施加对应旋转后拼接输出)

**来源原语**：逐行递增/色段(bbc9ae5d)、编码映射/固定编码表/长度映射颜色(e048c9ed)、旋转(7fe24cdd/291dc1e1)、拼接/阵列排布(7fe24cdd)、精灵体/裁剪/紧凑包围盒提取(1cf80156)

**依赖链**：色段长度编码了旋转指令；旋转指令作用于精灵体产生变换后的版本；多个版本按色段的空间排列顺序拼接。色段序列既是数据（长度=角度编码）又是布局指令（排列顺序=输出排列），双重身份使得推理链不可分割。

一句话总结：输入中递增色段的长度编码旋转角度指令，据此旋转精灵体并按色段顺序拼成一行。

**输入结构**：约 10x14 的网格，分为上下两个区域（由一行灰(5)像素水平分隔）。上半区：黑(0)背景上有一个由红(2)像素组成的不对称小型 4-连通精灵体（约 3x3 边界框，4-6 像素）。下半区：黑(0)背景上有 2-4 行水平色段指令，每行一条色段——色段由黄(4)像素组成，从该行最左列开始向右延伸，长度为 1-4 格。不同行的色段长度可以相同也可以不同。各指令行之间间隔一行黑色空行。生成约束：色段长度仅取 1、2、3、4 四种值。

**规则**：
1. 识别灰(5)分隔行，将网格分为上半区（精灵体）和下半区（指令序列）。
2. 从上半区提取红(2)精灵体并裁剪到紧凑边界框。
3. 从下半区逐行（从上到下）读取每条黄(4)色段的长度 L。
4. 长度映射为旋转角度：L=1 → 0度（不旋转），L=2 → 90度顺时针，L=3 → 180度，L=4 → 270度顺时针。
5. 对精灵体依次施加每条指令对应的旋转，得到一组旋转后的副本。
6. 将所有副本从左到右水平拼接（各副本之间间隔 1 列黑色），形成输出。输出高度 = 精灵体边界框的较大边长（旋转后可能宽高互换，取所有副本中最大高度），各副本顶部对齐，不足高度的部分用黑(0)填充。

**关键洞察**：色段不是装饰性的递增图案，而是对旋转角度的编码指令——求解者需要对比多个示例发现"长度=旋转角度"这一非显然映射关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
