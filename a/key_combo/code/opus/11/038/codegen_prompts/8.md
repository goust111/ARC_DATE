## 新题 8：障碍绕行水平迁移与地面轨迹记录

**组合逻辑**：[pathfinding/detour_on_obstacle](精灵水平移动时遇到障碍向上绕行一行再前进一步，原为垂直生长时水平绕行，此处将运动主方向旋转 90 度并作用于多像素精灵而非单像素路径) + [mirrored_position](精灵的目标位置是其水平镜像位置，原为直接平移到镜像点，此处镜像位置仅为目标，实际到达位置受绕行偏移影响) -> [fill/floor_row](在地面行上用精灵颜色绘制从起点列到终点列的水平轨迹，原为铺满底行或填充容器，此处记录实际水平行程)

**来源原语**：pathfinding/stepwise_advance/detour_on_obstacle/blocker_pixel(参考题10 d9f24cd1), mirrored_position/orientation_preserved(参考题8 8ee62060), translate(参考题8), floor_row/move_to_wall(参考题5 9f41bd9c), fill(参考题5, 13)

**依赖链**：镜像位置定义目标列 -> 精灵向目标水平移动 -> 障碍触发垂直绕行，改变精灵的最终行位置 -> 地面行记录精灵的水平起止范围。镜像提供方向目标，障碍改变实际轨迹，地面轨迹仅反映水平投影——三者在"目标 vs 实际路径 vs 记录"的三角关系中紧密耦合。删除镜像则无目标方向；删除绕行则精灵直达镜像位置（地面轨迹可直接计算）；删除地面轨迹则丢失水平行程信息。

精灵向水平镜像位置移动，遇灰色障碍时上移一行绕行，到达后在地面行绘制起止列之间的水平轨迹。

**输入结构**：约 14x10 的网格。黑(0)背景。最底行为实心栗(9)地面行。2~3 个小型彩色精灵（各 3~5 像素，4-连通，颜色各不相同，如蓝(1)、红(2)、绿(3)），每个精灵紧贴网格的左边缘或右边缘，位于地面行正上方（精灵的最底行像素在地面行上方一行）。灰(5)障碍像素散布在网格中部区域（不紧贴左右边缘），每个障碍为单个像素。生成约束：同一列中不会有两个障碍上下相邻；每个精灵的镜像列范围不与另一个精灵的镜像列范围重叠；所有路径可完成（不存在某列被障碍完全封锁导致精灵无法通过的情况）；精灵边界框高度不超过 2 行。

**规则**：
1. 对每个精灵，计算其水平镜像目标位置：若精灵边界框的左列为 c0、宽度为 w，则目标左列为 grid_width - w - c0。
2. 将精灵视为刚体，从当前位置向目标位置逐列水平移动（每步移动一列，方向为从当前列指向目标列）。每步检查：
   a. 若精灵在下一列的所有像素位置均为黑(0)或栗(9)地面（即无灰(5)障碍阻挡）：精灵水平平移一列。
   b. 若精灵在下一列的任一像素位置被灰(5)障碍占据：精灵先整体上移一行（所有像素行号 -1），然后水平平移一列。若上移后精灵的任一像素超出网格顶部，该像素被裁剪（丢弃）。
3. 精灵到达目标列后，在最终位置绘制精灵（保持原色和内部布局）。将精灵从原位置擦除（置为黑(0)）。
4. 在栗(9)地面行上，从精灵原始左列到最终左列之间（含两端）的所有像素，重涂为精灵的颜色。若最终左列在原始左列的左边，则范围为 [最终左列, 原始左列]；否则为 [原始左列, 最终左列]。
5. 精灵按其最底行像素的行号从大到小处理（更靠近地面的先处理）。行号相同时按列号从左到右处理。不同精灵的地面轨迹若重叠，后处理的精灵的颜色覆盖先处理的。

**关键洞察**：镜像位置只决定目标列，不决定目标行——障碍绕行会将精灵向上推移，因此精灵的最终行位置可能高于其初始行位置。地面轨迹仅记录水平投影（起止列），隐藏了垂直偏移信息。求解者必须逐步模拟路径才能确定精灵的真实最终位置和轨迹长度。
