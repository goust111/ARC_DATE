## 新题 5：框架交叉条纹网格

**组合逻辑**：[颜色匹配配对→标记交叉定位](已有) → [条纹传播](创新：条纹不从边界线段出发，而从框架内部的交叉点出发) + [颜色循环](已有) + [重叠区域重涂](创新：重叠的判断依据从模板副本重叠变为条纹交叉，重涂色由交叉点的标记数量决定)

**来源原语**：标记交叉定位、颜色匹配配对、框架标记(247ef758)；条纹传播、颜色循环、条纹范围差异(221dfab4)；重叠区域重涂(a395ee82)；计数(27a77e38)

**依赖链**：框架边缘标记的颜色配对确定交叉点位置→从交叉点向四个方向传播条纹→条纹使用颜色循环→两条或多条条纹在同一像素相交时，取拥有更多交叉点的那个颜色的条纹。标记配对、条纹传播、交叉冲突解决三步环环相扣。

在矩形框架上通过同色标记的行列交叉定位种子点，从种子点向四方传播颜色循环条纹，条纹交叉处取标记数量更多的颜色。

**输入结构**：黑(0)背景约 16x16 网格。灰(5)单像素线围成一个矩形框架（边距约 2~3 像素到网格边缘）。框架的上/下水平边和左/右垂直边上各有若干单像素标记，标记颜色取自红(2)和蓝(1)。同色标记在行（水平边上的标记对应行号）和列（垂直边上的标记对应列号）上的笛卡尔积定义框架内部的交叉点。框架内部初始为黑(0)。生成约束：红(2)标记在水平边和垂直边上各至少 1 个、至多 3 个；蓝(1)同理；两色标记产生的交叉点集互不重叠。

**规则**：
1. 对每种标记颜色 C（红(2)或蓝(1)），收集水平边上颜色为 C 的标记行号集合 R_C 和垂直边上颜色为 C 的标记列号集合 Col_C。交叉点集 = R_C x Col_C。
2. 从每个交叉点出发，沿上、下、左、右四个方向每隔 1 像素（即步长 2）画一个条纹像素，颜色为该交叉点的颜色 C，直到遇到框架边或已有的同色条纹。条纹像素之间的间隔像素保持黑(0)。
3. 若某像素同时被红(2)和蓝(1)的条纹覆盖（交叉冲突），取交叉点数量更多的颜色（即 |R_C x Col_C| 更大的颜色）。若两色交叉点数量相等，取红(2)。
4. 框架边和标记像素保持不变。框架外部保持黑(0)。

**关键洞察**：条纹的冲突解决不取决于哪条条纹先画或像素的空间位置，而取决于产生该条纹的颜色在全局拥有多少个交叉点——这是一个需要全局计数才能确定的隐蔽规则，仅看局部条纹无法推断。
