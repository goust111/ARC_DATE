## 新题 1：形状配对对角桥

**组合逻辑**：[形状匹配](创新：配对判据从颜色改为归一化形状) + [连线/对角连接](创新：连接对象由同色矩形改为异色同形精灵体) → 桥色由上方精灵体颜色决定

**来源原语**：形状匹配、归一化形状匹配(2a5f8217)；连线、对角线段、对角偏移、对角补全连接(342ae2ed)

**依赖链**：形状匹配的结果决定了哪些对象成对 → 配对关系决定了对角连线的两端点 → 端点的空间位置决定了连线方向。删除形状匹配则无法确定配对；删除连线则无输出变换。

将不同颜色但形状相同的精灵体配对，在配对的两者之间绘制对角桥线段。

**输入结构**：黑(0)背景网格，约 15x15。网格中散布 6~8 个小型 4-连通单色精灵体（每个 3~7 像素，形状各异——可以是不规则小块、带弯折的条状等），每个精灵体使用一种独立颜色，颜色取自 {红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、青(8)}。形状成对出现：每种归一化形状恰好有两个精灵体实例，但这两个实例颜色不同。任意两个精灵体的包围盒互不重叠且至少间隔 2 个像素。同一形状的两个实例在空间上呈对角偏移关系（一个在另一个的左上方或右上方）。生成约束：保证每对形状匹配精灵体的包围盒对角面的最近角点之间存在不被其他精灵体遮挡的 45 度直线路径。

**规则**：
1. 对每个精灵体提取其包围盒内的像素掩码，作为归一化形状（仅平移归一化，不旋转、不翻转）。
2. 将归一化形状相同的两个精灵体配为一对。每个精灵体恰属一对。
3. 对每一对，确定"上方精灵体"（包围盒顶行行号较小者）和"下方精灵体"。
4. 找到上方精灵体包围盒底边与下方精灵体包围盒顶边之间最近的一对角点（上方取底侧角点，下方取顶侧角点；若上方在左上方则取上方的右下角和下方的左上角，反之取上方的左下角和下方的右上角）。
5. 在这两个角点之间沿 45 度方向逐像素绘制对角线段，不含两端点本身（端点已被精灵体占据）。线段颜色为上方精灵体的颜色。
6. 原有精灵体像素保持不变。

**关键洞察**：配对依据是归一化形状而非颜色——两个颜色完全不同的精灵体可能被配对，求解者必须跨颜色对比形状才能发现配对规则。

- Every foreground color appears as exactly two separated solid rectangular 4-connected objects.

Rule:

- For each foreground color, connect the lower facing corner of the upper rectangle to the upper facing corner of the lower rectangle.
- Paint only the intervening background pixels on that diagonal, excluding the two endpoint pixels already in the rectangles.

Key insight:
- Same-color rectangles define the endpoints; the output completes the open diagonal between their nearest facing corners.

Push the central solid rectangle to the grid edge, splitting the perpendicular target rectangle around its path.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
