## 新题 2：对称性分流重力与计数对角线编码

**组合逻辑**：[对称检测](分类) → [滑动/重力沉降](方向由对称性决定) + [计数](统计对称类) → [对角线编码](编码计数结果到输出子区域)

**来源原语**：对称检测(73ccf9c2)、唯一非轴对称/异常值选择(73ccf9c2)、滑动(3618c87e)、重力沉降(3618c87e)、计数(3b4c2228)、对角线编码(3b4c2228)、分隔行(bd4472b8)

**依赖链**：对称检测将对象分为两类 → 对称类型决定重力方向（左右对称→下沉，上下对称→右移） → 计数各类型对象数量 → 对角线编码将计数写入分隔行划出的计数区

一句话总结：小型前景对象按其对称轴方向被分流沉降到不同边，然后各类型的数量被编码为分隔线旁计数区域对角线上的着色单元。

**输入结构**：约 15x15 的网格，黑(0)为背景。网格中央有一条完整的灰(5)水平分隔行，将网格分为上半区（活动区）和下半区（编码区，初始全黑）。上半区散布 5~8 个互不相邻的单色 4-连通小对象（每个 3~6 像素），颜色为红(2)或蓝(1)。每个对象恰好具备以下对称性之一：仅左右镜像对称（竖轴）、仅上下镜像对称（横轴），不存在同时具备两种或无对称性的对象。生成约束：上下对称的对象数量与左右对称的对象数量不相等且各自在 2~4 之间；对象的具体形状（像素布局）各不相同，但对称类型可通过边界框内的前景掩码反射比对确定。

**规则**：
1. 识别上半区所有 4-连通前景对象，对每个对象检测其边界框内掩码的对称类型。
2. 左右对称（竖轴镜像 = 自身）的对象：整体向下平移直至碰到灰(5)分隔行上方或碰到已沉降的对象，保持原色不变。
3. 上下对称（横轴镜像 = 自身）的对象：整体向右平移直至碰到网格右边界或碰到已移动的对象，保持原色不变。处理顺序：按对象边界框左上角从右到左（避免右侧对象阻塞左侧对象路径）。
4. 统计左右对称对象总数 N_v，上下对称对象总数 N_h。
5. 下半区视为编码区。编码区的左半部分（列 0 至 列 floor(W/2)-1）用于编码 N_v：从编码区左上角沿主对角线填 N_v 个红(2)单元。编码区的右半部分（列 floor(W/2) 至 列 W-1）用于编码 N_h：从该子区域左上角沿主对角线填 N_h 个蓝(1)单元。
6. 灰(5)分隔行保持不变。

**关键洞察**：对称类型既决定了对象的物理运动方向（分流机制），又被计数后编码为输出的结构特征；如果不先正确检测对称性，既无法确定移动方向，也无法得到正确的编码数字。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
