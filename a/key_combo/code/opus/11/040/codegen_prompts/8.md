## 新题 8：棋盘格奇偶过滤双面板叠加

**组合逻辑**：[透明叠加(transparent_overlay) + 双面板对齐(dual_panel_alignment)] → [棋盘格(checkerboard)]（创新：棋盘格不是被追踪的对象，而是叠加结果的空间过滤器） → [重涂色(recolor) + 擦除(erase)]

**来源原语**：透明叠加(transparent_overlay, 506d28a5)、双面板对齐(dual_panel_alignment, 506d28a5)、分隔行(divider_row, 506d28a5)、二值掩码(binary_mask, 506d28a5)、棋盘格(checkerboard, 9ba4a9aa)、重涂色(recolor, 506d28a5)、任一前景即输出(either_foreground_yields_output, 506d28a5)

**依赖链**：两个面板的前景掩码叠加 → 叠加产生三类像素：仅上面板有、仅下面板有、两面板都有 → 棋盘格奇偶性进一步过滤：坐标和为偶数的位置保留叠加结果，为奇数的位置擦除 → 最终保留的像素按来源着色

将双面板叠加后的结果经棋盘格奇偶过滤，再按像素来源分别着色。

**输入结构**：黑(0)背景，约 11x13 网格（奇数行数，保证有中间行）。网格正中一行为灰(5)分隔行，将网格分为上下两个大小相同的面板（各 5x13 或类似尺寸）。上面板包含若干蓝(1)前景像素组成的图形（8~15 像素），其余为黑(0)。下面板包含若干红(2)前景像素组成的图形（8~15 像素），其余为黑(0)。两面板的前景图形有部分位置重叠（按面板内相对坐标对齐时，约 3~6 个位置两面板都有前景像素）。网格右下角有一个 2x2 的棋盘格提示块（由黄(4)和黑(0)交替组成，左上角为黄(4)），表示"偶数保留"的过滤规则。生成约束：叠加后经棋盘格过滤仍有至少 5 个像素保留。

**规则**：
1. 移除灰(5)分隔行。将上面板和下面板按位置对齐（同一行列坐标），分别记录各面板中的前景像素位置。输出网格大小等于单个面板。
2. 对输出网格的每个位置 (r, c)，检查上面板和下面板在 (r, c) 处的前景情况。
3. 计算 (r + c) 的奇偶性。若 (r + c) 为奇数，则该位置输出黑(0)，无论两面板是否有前景。
4. 若 (r + c) 为偶数：
   - 两面板都有前景 → 输出绿(3)。
   - 仅上面板有前景 → 输出黄(4)。
   - 仅下面板有前景 → 输出橙(7)。
   - 两面板都无前景 → 输出黑(0)。
5. 棋盘格提示块不出现在输出中（它仅作为规则提示存在于输入中）。

**关键洞察**：叠加结果不是最终输出——棋盘格的坐标奇偶性像一张镂空面具一样遮盖了一半的叠加结果；求解者需要同时理解叠加来源分类和空间过滤两层逻辑，且两者无法分开推理（过滤后才能确认最终颜色）。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
