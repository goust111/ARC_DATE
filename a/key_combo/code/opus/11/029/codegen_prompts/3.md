## 新题 3：对角线段配对围合区域的条纹方向填充

**组合逻辑**：[平行配对/parallel_pairing](识别平行对角线段对) → [填充/fill](创新：填充围合区域) → [条纹决定填充轴/stripe_determines_fill_axis](创新：对角线段的方向决定填充条纹的走向) → [交替填色/alternating_fill]

**来源原语**：平行配对(7666fa5d), 对角线段(7666fa5d, aa300dc3), 填充(7666fa5d, d4f3cd78), 交替填色(db3e9e38), 条纹(8e1813be), 顺序对应(8e1813be)

**依赖链**：平行对角线段的识别与配对决定了填充区域的边界；线段所在的对角线方向（主对角线或反对角线）决定了填充条纹的走向；线段的颜色决定了交替填色的两种颜色。三者耦合——区域由段对定义、条纹走向由段方向定义、条纹颜色由段色定义。

找出平行对角线段对围成的区域，用由段方向和段颜色决定的交替条纹填充。

**输入结构**：约 14x14 的黑(0)背景网格。包含 2~3 对平行对角线段，每段长 3~5 像素。同一对中的两段颜色相同（可选蓝(1)、红(2)、绿(3)中的一种），不同对颜色不同。每段沿主对角线方向（左上→右下）或反对角线方向（右上→左下）排列。同一对的两段平行且沿垂直于段方向的轴相距 2~4 格，形成一个平行四边形区域。不同对的围合区域互不重叠。生成约束：每对的围合区域内只有背景像素；各对之间间距至少 2 格。

**规则**：
1. 将所有非黑像素按颜色分组，每组内识别共线的对角线段（同一对角线 r+c=const 或 r-c=const 上连续排列的同色像素构成一段）。
2. 对每种颜色，将该色的段按平行关系配对（两段所在对角线的截距差最小且方向相同的配为一对）。
3. 确定每对线段的方向：若段沿反对角线(r+c=const)排列，则填充条纹走向为按行（水平条纹）；若段沿主对角线(r-c=const)排列，则填充条纹走向为按列（垂直条纹）。
4. 对每对围合的平行四边形区域内的背景像素进行交替填色：沿步骤 3 确定的走向（行或列），奇数行/列填该对的颜色，偶数行/列填黄(4)。行/列的奇偶性以围合区域内第一行/列为奇数起始。
5. 保留所有原始对角线段像素不变。

**关键洞察**：线段的对角线方向不仅界定了区域形状，还隐式编码了填充条纹的走向——这一对应关系需要对比多个示例（含不同方向的段对）才能归纳出来。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
