## 新题 6：去遮挡镜像补全后按控制像素数进行像素放大

**组合逻辑**：[擦除 + 去遮挡后镜像还原](已有：去遮挡并镜像补全) → [对称补全](已有) → [计数](创新：统计控制行像素数量) → [像素放大 + 数量决定倍率](创新：控制像素数而非前景像素数作为放大系数)

**来源原语**：擦除、对称补全、镜像、填充矩形、遮挡、去遮挡后镜像还原（3345333e）；像素放大、数量决定倍率、前景数为放大系数（ac0a08a4）；控制像素（c9f8e694）；计数（37d3e8b2）

**依赖链**：去除遮挡矩形暴露缺失部分；检测对称轴并补全形状；统计底行控制像素数 K；将补全结果按 K 倍像素放大。遮挡决定需补全的部分，补全决定放大的形状，控制像素数决定放大倍率——三步严格有序。

去除遮挡矩形并镜像补全对称对象，然后按底行彩色控制像素数做像素级放大。

**输入结构**：约 9x8 的主体区域加底部 1 行控制行，总网格约 10x8。背景黑(0)。主体区域包含一个蓝(1) 单色 4-连通对象（面积约 8-16 像素，形状不规则但具有左右镜像对称性），被一个红(2) 实心矩形部分遮挡（矩形约 2x2 到 3x3，覆盖蓝色对象的一侧使该侧像素不可见）。最底行（第 9 行或最后一行）为控制行：黑(0) 背景上散布 K 个彩色像素（颜色互不相同，如绿(3)、黄(4)、橙(7) 等），K 在 2-3 之间。不同示例中 K 不同，蓝色对象形状不同，遮挡矩形位置不同。生成约束：遮挡矩形恰好覆盖蓝色对象的一个侧翼，使得去除遮挡后可用镜像对称唯一确定缺失像素；控制行像素与主体区域无空间重叠。

**规则**：
1. 在主体区域中，检测红(2) 实心矩形 4-连通分量，将其所有像素设为黑(0)（擦除遮挡物）。
2. 对剩余的蓝(1) 像素，检测左右镜像对称轴（在忽略缺失区域的前提下寻找使已有像素最对称的垂直轴线）。沿该轴将已有蓝(1) 像素镜像反射，在缺失位置填入蓝(1) 像素，完成对称补全。
3. 统计最底行（控制行）中非黑(0) 像素的数量 K。
4. 将补全后的蓝(1) 对象裁剪至其最小边界框（边界框内非对象像素保留为黑(0)）。
5. 对裁剪结果执行像素级放大：每个像素（包括黑(0) 背景）替换为 K x K 的同色像素块。输出网格尺寸为原边界框宽度乘以 K、高度乘以 K。
6. 控制行不包含在输出中。

**关键洞察**：控制行像素的颜色是干扰——它们的数量才编码了放大倍率。求解者容易误以为控制像素的颜色与蓝色对象有映射关系（如重涂色），但实际上只有"有几个控制像素"这一信息被使用。需要对比多个示例（不同 K 值对应不同放大倍率）才能排除颜色映射假说。

<description>
Decode a block-grid image by swapping each sprite-coded cell with a solid cell and each blank cell with the sprite.

Input structure
The grid is partitioned by black separator rows and columns into equal-size
square blocks. Each block is either a copy of one two-color sprite or a
uniform blank block of the sprite's minority color; grey pixels are erased
cells that act as wildcards.

Rule
Infer the repeated sprite from fully visible mixed-color blocks. Replace a
block matching that sprite, ignoring grey erasures, with a solid block of
the sprite's majority color. Replace a uniform blank block with the sprite.
Separator rows and columns, including grey erasures on them, become black.

Key insight
The small sprite is a block-level code for one macro-cell state, and the
uniform minority-color block is the other state; the output renders the
opposite code in each macro-cell while cleaning erased pixels.

  at_least_one_clean_sprite: >= 1 block has no grey and contains the full two-color sprite (needed to infer sprite)

generation_strategy:
  approach: output-first
  steps:

    3. Generate a random block_size x block_size sprite using both colors, foreground filling 67-75% of cells, counts distinct, no all-one-color rows/cols [observed].

    6. Construct the clean input grid (before grey): sprite blocks -> sprite tile, blank blocks -> solid blank_color, separators -> black.
    7. Generate a grey blob: pick a random seed cell, grow via BFS/random-walk across the grid (crossing separators), replacing cells with grey (5).
