## 新题 3：双面板逐格比较驱动的条件操作路由

**组合逻辑**：[逐格比较/cell_comparison](已有) → { 双前景 → [重涂色/recolor], 单前景 → [平移/shift](创新：移向分隔行), 双背景 → [背景替换/background_replace] }（分支结构，非线性流水线）

**来源原语**：逐格比较、双面板对齐、分隔行、二值掩码、任一前景即输出（来自 506d28a5）；压缩、堆叠掩码、双背景标记输出（来自 fafffa47）；平移、背景替换、固定步长平移（来自 32e9702f）；重涂色（来自多题）

**依赖链**：逐格比较是决策节点，其结果将每个像素位置路由到三条不同操作分支之一。三条分支的输出共同拼成最终结果——任何一条分支的规则缺失都会留下未确定的像素。比较结果本身依赖分隔行的位置（确定哪些行互相对齐），所以分隔行的识别是整个推理的前提。

用分隔行将网格分为上下两个等大掩码，逐格比较后按三种结果分别执行不同操作：双前景格涂红(2)，单前景格向分隔行方向平移一格，双背景格涂灰(5)，三条分支的结果合成为最终单面板输出。

**输入结构**：约 11x9（奇数行数）的网格，背景为黑(0)。正中间一行为品红(6)全宽分隔行。上半部分（分隔行之上）包含一个蓝(1)前景掩码（4-连通，约 8~15 像素的不规则形状）。下半部分（分隔行之下）包含一个绿(3)前景掩码（同样 4-连通，约 8~15 像素的不规则形状，与上半掩码部分重叠、部分不重叠）。上下两半尺寸相同。生成约束：两个掩码至少有 2 个位置双前景、至少有 2 个位置仅上半前景、至少有 2 个位置仅下半前景、至少有 2 个位置双背景，保证四种情况均出现。

**规则**：
1. 识别品红(6)全宽分隔行，将网格分为上半掩码和下半掩码（各含 (H-1)/2 行，H 为网格总行数）。
2. 将上半掩码与下半掩码按位置逐格比较（上半第 r 行第 c 列对应下半第 r 行第 c 列）。
3. 对每个位置 (r, c) 执行以下操作之一：
   - **双前景**（上半和下半该位置均为非背景色）：输出该位置为红(2)。
   - **仅上半前景**（上半非背景、下半为背景）：将上半该像素向下平移一格（即输出在 (r+1, c) 处为蓝(1)，原位 (r, c) 变为黑(0)背景）。若 r+1 超出输出网格范围则丢弃。
   - **仅下半前景**（下半非背景、上半为背景）：将下半该像素向上平移一格（即输出在 (r-1, c) 处为绿(3)，原位 (r, c) 变为黑(0)背景）。若 r-1 < 0 则丢弃。
   - **双背景**（上下均为背景色）：输出该位置为灰(5)。
4. 冲突解决：若一个平移操作的目标格恰好也是某个"双前景"格，则双前景的红(2)优先保留；若两个平移操作指向同一格（一个从上方下移、一个从下方上移），则输出黄(4)表示交汇。
5. 输出为单个面板（与半幅尺寸相同），不含分隔行。

**关键洞察**：比较结果不是简单的集合运算（并集/交集），而是路由到三条空间变换各异的操作分支；且平移操作可能产生新的冲突（目标格已被占用），需要二级冲突规则来裁决——这是比较结果与空间变换交互产生的涌现效应。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
