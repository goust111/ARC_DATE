## 新题 8：碎片主色查图例定方向，异常碎片原地固定

**组合逻辑**：[切割(cutting) + 射线分割区域(ray_partition)](已有) + [颜色关联区域(color_links_to_region) + 编码映射(encoding_map)](创新：颜色关联从"区域边界色"改为"碎片主色") + [异常值选择(outlier_selection)](创新：异常值从"单色单元"改为"无匹配图例的碎片") + [滑动(sliding)](已有)

**来源原语**：切割、滑动、控制像素、射线分割区域、边界归属决定保留 ← 4a21e3da；编码映射、边界图例、颜色关联区域 ← 88e364bc；异常值选择、忽略干扰项 ← c3202e5a；标记颜色对应 ← 94133066

**依赖链**：控制像素射线切割前景对象为碎片 → 统计每个碎片的主色（占多数的颜色）→ 主色在边界图例中查找匹配 → 图例编码该碎片的滑动方向 → 无匹配图例的碎片（异常值）原地保持 → 三级依赖：切割几何 × 碎片颜色构成 × 图例解码

将多色前景对象沿控制射线切割成碎片，每个碎片的主色在边界图例中查找对应的滑动方向并执行滑动，唯一没有匹配图例的碎片作为异常值固定不动。

**输入结构**：
- 网格约 16x16，黑(0)背景
- 一个多色前景对象居中偏左，约 8x10，由 3~4 种非黑颜色（如蓝(1)、绿(3)、橙(7)、品红(6)）的像素混合构成，4-连通，整体是一个连通块但内部颜色分布不均匀——不同区域以不同颜色为主
- 网格边缘有 2 个红(2)控制像素（分别在不同边上），它们的射线将前景对象切为 3 个碎片
- 网格边缘（非控制像素所在边）有 2 个 3x3 图例矩形。每个图例的填充色与某种前景颜色相同（如一个填蓝(1)、一个填橙(7)），图例中央为灰(5)圆心、另有一个灰(5)指示点，指示点相对圆心的位置编码滑动方向（上/下/左/右）
- 生成约束：3 个碎片的主色（该碎片中像素数最多的颜色）两两不同；恰好 2 个碎片的主色在图例中有匹配，1 个碎片的主色无匹配图例（此碎片为异常值）；图例中指示点只出现在中心的正上/正下/正左/正右四个位置之一（即 dr=0 或 dc=0）

**规则**：
1. 从每个红(2)控制像素出发沿行/列向网格内部画射线（规则同新题 4 的步骤 1），射线穿过前景像素时跳过，只涂黑(0)背景格子为红(2)。
2. 射线将前景对象分割为碎片（分割规则同新题 4 的步骤 2）。
3. 对每个碎片，统计各非黑颜色的像素数量，像素数最多的颜色为该碎片的"主色" D。若有并列，取在碎片包围盒中最先出现（按从上到下、从左到右扫描序）的颜色。
4. 对每个碎片的主色 D，在边界图例中查找填充色为 D 的图例。若找到：
   - 读取该图例的中心灰(5)点和指示灰(5)点，计算方向向量 (dr, dc)（指示点坐标 - 中心点坐标）。
   - 将整个碎片沿方向 (dr, dc) 平移，每步移动 1 格，直到碎片中任何像素的下一步位置超出网格边界或与另一个已固定碎片的像素重叠。碎片停在最后一个合法位置。
5. 无匹配图例的碎片（异常值）：原地保留，不移动，不变色。
6. 碎片处理顺序：先固定异常值碎片，然后按图例在网格边缘上的出现位置（从上到下、从左到右）顺序处理有匹配的碎片。
7. 红(2)射线像素和红(2)控制像素在输出中移除（替换为黑(0)）。图例在输出中移除。

**关键洞察**：切割、颜色统计、图例解码三个机制形成不可跳过的三级依赖——切割位置决定碎片边界，边界决定每个碎片内的颜色构成，颜色构成决定主色，主色决定查哪个图例，图例决定移动方向。异常值机制增加了一层筛选：求解者必须发现"没有图例对应的碎片不动"这条隐含规则，这需要对比多个示例中哪个碎片不动并追溯其主色在图例中缺席。
