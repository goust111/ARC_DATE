## 新题 4：弹射轨迹与图例色序着色

**组合逻辑**：[描边/反射弹回](对角线弹射绘制路径) → [边缘图例串](创新：图例不用于展开，而作为弹射路径的颜色循环序列) → [颜色位置匹配](弹射点的颜色由图例中的位置循环决定)

**来源原语**：描边/trace_path + 反射弹回/reflection_bounce + 画布边界/canvas_boundary(参考题 a3df8b1e)、边缘图例串/edge_legend_string + 颜色位置匹配/color_position_matching(参考题 5af49b42)

**依赖链**：弹射路径决定经过哪些像素和发生几次弹射；图例串的长度决定颜色循环周期；每段弹射路径（两次反弹之间的对角线段）用图例中下一个颜色绘制。路径几何和图例序列共同决定输出的颜色分布。

一个像素沿对角线弹射前进，每次撞壁反弹后切换到图例串中的下一种颜色来绘制下一段轨迹，颜色在图例末尾时循环回到图例开头。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格顶行（第 0 行）有一段水平连续的多色像素串（3~5 个像素，颜色各不相同，取自红(2)、绿(3)、黄(4)、蓝(1)、橙(7)等），这是图例串，其余顶行像素为黑(0)。网格中有一个孤立的灰(5) 像素，不在顶行，位于非边缘位置。生成约束：灰(5) 像素不在顶行或底行；图例串至少 3 个像素。

**规则**：
1. 识别顶行的图例串（连续非黑像素），记录其颜色序列为 C1, C2, ..., Ck（从左到右）。
2. 从灰(5) 像素位置出发，方向为右上（行减 1，列加 1）。
3. 沿对角线移动，每经过一个像素就涂上当前段的颜色。初始段颜色为 C1。
4. 当到达左右边界时，水平方向反转（垂直方向不变，始终向上）；当到达顶行时停止。
5. 每次发生水平方向反弹时，切换到图例中的下一个颜色（C1→C2→C3→...→Ck→C1 循环）。起始点本身用 C1 着色。
6. 图例串保持不变。灰(5) 起始像素被第一段颜色 C1 覆盖。

**关键洞察**：弹射段数由网格几何和起始位置共同决定，而每段颜色由图例串的循环序列决定。求解者需要同时追踪弹射路径的几何变化和颜色序列的循环状态。仅看单个示例可能无法确定颜色是按弹射段切换还是按像素切换。

```yaml
    control pixel also gets reflected, creating a symmetric yellow marker on the other side

generation_strategy:
  approach: output-first
  steps:
    1. Choose grid size and number of objects (1-4)
    2. For each object, build the OUTPUT (symmetric) version first
       a. Pick orientation (H or V), foreground color, bbox size (3-9 x 6-10)
       b. Pick axis position within bbox (source_half >= target_half, diff 0-1)
       c. Draw an irregular connected blob on the source half (~65-80% fill)
       d. Place yellow axis spanning 60-100% of cross-dimension
       e. Place 1 yellow control pixel at perpendicular distance 2, within axis span
       f. Mirror source half across axis (writes fg, bg, and yellow control pixel)
    3. Place objects on grid with >=2-cell gaps, ensuring reflections stay in bounds
    4. Derive INPUT by damaging the target half of each object
       a. For ~30-45% of pixels in the target half region, randomize (swap fg/bg, shift positions)
       b. Optionally detach 1-2 stray pixels from the damaged half (disconnected by 4-connectivity)
```
</generation_spec>
</reference_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
