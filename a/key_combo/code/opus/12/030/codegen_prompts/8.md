## 新题 8：射线擦除后的对称性修复

**组合逻辑**：[射线延伸/命中即整体擦除](从标记条发射射线，擦除被命中的目标对象) → [对称补全](创新：擦除后破坏了网格原有的反射对称性，需利用对称性恢复被擦除区域) → [重涂色](恢复的像素标记为不同于原色的新颜色)

**来源原语**：射线延伸/ray_extend + 标记条/marker_bar + 控制像素/control_pixel + 命中即整体擦除/hit_erases_whole(参考题 2f767503)、对称补全/symmetry_completion + 双轴镜像轨道/two_axis_orbit + 缺失部分标记新色/missing_marked_new_color(参考题 af22c60d, 1b60fb0c)

**依赖链**：射线确定擦除哪些对象；擦除后产生的"缺口"恰好是对称补全需要修复的区域；修复用新颜色标记，使得射线的"破坏"和对称性的"修复"在输出中同时可见。没有射线擦除就没有缺口，没有对称补全就不知道缺口该填什么。

一个具有水平反射对称性的图案中，射线擦除了部分对象。擦除后的缺口通过对称轴另一侧的镜像信息推断出来，并用新颜色填充，标记出"被射线破坏又被对称性恢复"的区域。

**输入结构**：约 18x18 的网格，背景为黑(0)。网格中有一个由蓝(1) 像素组成的大型图案（约占网格面积的 30%~50%），该图案具有关于网格水平中轴线的镜像对称性。图案中还嵌入了若干用红(2) 像素组成的小型 4-连通对象（每个 3~6 像素），这些红(2) 对象也对称分布（每个红对象在对称轴另一侧有镜像对应物）。网格某一边缘有一个 3 像素的灰(5) 水平标记条，其中心像素旁有一个品红(6) 控制像素（在标记条中心的上方或下方）。生成约束：射线方向为垂直（向上或向下）；射线恰好命中 1~2 个红(2) 对象（但不命中它们的镜像对应物）；蓝(1) 图案像素不在射线路径上（射线不影响蓝像素）。

**规则**：
1. 从标记条中心像素出发，沿控制像素反方向发射垂直射线（若控制像素在上方，射线向下；若在下方，射线向上）。
2. 找到射线路径上命中的所有红(2) 的 4-连通对象，将其所有像素擦除为黑(0)。射线本身不留痕迹。
3. 识别网格的水平反射对称轴（中间行）。
4. 对擦除后的每个黑(0) 像素位置，检查其在对称轴另一侧的镜像位置：若镜像位置为红(2)，则该位置是被射线擦除的像素，将其填充为绿(3)。
5. 蓝(1) 图案、未被命中的红(2) 对象、标记条和控制像素保持不变。

**关键洞察**：射线擦除与对称修复是因果关系——擦除制造了对称性破缺，而求解者需要利用幸存的镜像对象来推断缺失内容。输出中绿(3) 像素同时编码了两个信息：射线的破坏范围和对称性的修复能力。

Decode a block-grid image by swapping each sprite-coded cell with a solid cell and each blank cell with the sprite.

Input structure
The grid is partitioned by black separator rows and columns into equal-size
square blocks. Each block is either a copy of one two-color sprite or a
uniform blank block of the sprite's minority color; grey pixels are erased
cells that act as wildcards.

Rule
Infer the repeated sprite from fully visible mixed-color blocks. Replace a
block matching that sprite, ignoring grey erasures, with a solid block of
the sprite's majority color. Replace a uniform blank block with the sprite.
Separator rows and columns, including grey erasures on them, become black.

Key insight
The small sprite is a block-level code for one macro-cell state, and the
uniform minority-color block is the other state; the output renders the
opposite code in each macro-cell while cleaning erased pixels.

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
