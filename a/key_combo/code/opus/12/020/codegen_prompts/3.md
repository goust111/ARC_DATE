## 新题 3：帧侧颜色编码的旋转印章

**组合逻辑**：[crop](创新：从参考框内提取模板图案) + [color_to_side](创新：框四边颜色建立颜色-旋转映射表) → [stamp_overlay + rotate](创新：按散落像素颜色查表旋转后印章) → [only_fill_background](已有：印章仅填充背景格)

**来源原语**：crop（参考题 5daaa586）；color_to_side（参考题 5daaa586）；stamp_overlay、only_fill_background（参考题 dc1df850）；rotate（参考题 2b83f449）；scattered_pixel（参考题 5daaa586）；erase（参考题 abc82100）

**依赖链**：矩形框的四边颜色隐式定义了一张颜色→旋转角度的映射表 → 提取框内灰色模板图案 → 每个散落像素的颜色在映射表中查找对应旋转角度 → 将模板按该角度旋转后印章到散落像素位置。映射表、模板、和散落像素三者缺一不可。

从四色矩形框中提取模板和旋转映射表，在每个散落像素处按其颜色对应的旋转角度印章模板。

**输入结构**：约 18x18 的网格，背景为黑(0)。左上角区域有一个 7x7 的矩形框，框的四边各为一种颜色：上边红(2)、右边绿(3)、下边蓝(1)、左边黄(4)（四角像素归属按顺时针优先：右上角归上边颜色，右下角归右边颜色，左下角归下边颜色，左上角归左边颜色）。框内部（5x5 区域）有一个灰(5)的不对称小图案（约 4-8 像素的 4-连通块，无旋转对称性）。网格其余区域散布 4-8 个孤立像素，颜色为红(2)、绿(3)、蓝(1)或黄(4)之一。生成约束：散落像素之间至少间隔 6 个像素（曼哈顿距离），以确保 5x5 印章不会超出网格边界且各印章之间有足够空间。

**规则**：
1. 提取矩形框内部的 5x5 灰色图案作为模板。
2. 建立颜色→旋转映射：框上边颜色→0度（不旋转）、框右边颜色→逆时针 90度、框下边颜色→180度、框左边颜色→顺时针 90度。即"该颜色对应的框边旋转到朝上位置"。
3. 对每个散落像素，读取其颜色，查映射表得到旋转角度，将模板旋转该角度后以散落像素为中心放置 5x5 印章。
4. 印章仅填充背景(0)格；若印章范围内已有非背景像素则保留原像素。印章颜色使用灰(5)。
5. 所有印章放置完毕后，将原矩形框区域（含框线和内部图案）擦除为黑(0)。

**关键洞察**：矩形框不只是容器——其四边颜色构成一张隐式旋转查找表，求解者必须发现"边颜色 = 旋转角度"这一编码关系。框的四角归属规则需对比多个示例确认。

    if a ray cell is 4-adjacent to another ray start of same color with path len > 1, truncate there
    blocks themselves are unchanged
  ray_lengths: 1-8 observed; at least some rays per example have length >= 2

generation_strategy:
  approach: direct construction (input is simple enough)
  steps:
    1. Pick grid size N in [8..12].
    2. Pick block count K in [1..3]. Place K non-overlapping 2x2 blocks such that each block's 4x4 corner-inclusive bbox is in bounds and no two 4x4 bboxes overlap. Ensure at least one block has margin >= 2 on some diagonal so rays are non-trivial.
    3. For each block, assign a random permutation of {3,6,7,8} to its 4 corners.
    4. Fill everything else with bg=0.
    5. Validate by running solver — reject if solver raises (conflicting rays) or all rays have length 1.
