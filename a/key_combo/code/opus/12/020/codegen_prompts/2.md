## 新题 2：嵌套矩形框的角落引导循环换色

**组合逻辑**：[draw_frame + bounding](已有：识别嵌套矩形框及深度) → [corner_positioning](创新：角落引导像素编码旋转偏移量) → [cyclic_shift](创新：按嵌套深度序列循环轮换颜色)

**来源原语**：draw_frame、bounding、frame_inset_from_extrema（参考题 928ad970）；corner_positioning、corner_color_transfer_vanish（参考题 aabf363d）；cyclic_shift、angular_order_around_center（参考题 880c1354）

**依赖链**：嵌套深度排序建立帧的有序序列 → 角落引导像素的颜色匹配某一帧，将帧深度转化为旋转偏移量 → 循环轮换以该偏移量移动所有帧的颜色。引导像素是解码旋转量的关键。

读取角落引导像素的颜色，找到对应深度的嵌套矩形框，以该深度为偏移量循环轮换所有框的颜色，然后擦除引导像素。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格内有 3-4 个同心嵌套的单像素宽矩形框（相邻框之间间隔 1 像素），每个框使用不同的非黑颜色（如从外到内：红(2)、蓝(1)、绿(3)、黄(4)）。网格左上角 (0,0) 位置有一个引导像素，其颜色与某个框的颜色相同。生成约束：引导像素的颜色必须恰好匹配某一个框的颜色；框的嵌套关系明确（每个框严格包围下一个框）。

**规则**：
1. 识别所有矩形框，按嵌套深度排序：最外层深度为 0，向内依次递增。
2. 读取 (0,0) 处引导像素的颜色 C，找到颜色为 C 的框，记其深度为 D。
3. 将所有框的颜色向内循环轮换 D 个位置：深度 i 的框接收深度 (i - D) mod N 的框的原始颜色（N 为框的总数）。
4. 将 (0,0) 处的引导像素设为黑(0)（擦除）。

**关键洞察**：引导像素并非直接指定某个框的目标颜色，而是通过"匹配颜色 → 定位深度 → 转化为旋转偏移量"这一间接编码链来决定所有框的颜色变换。旋转方向（向内）需对比多个示例归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
