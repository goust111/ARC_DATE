## 新题 8：种子条纹的奇偶镜像拼接

**组合逻辑**：[平铺/种子像素→条纹生成]（半幅填充） + [镜像/拼接/画布加倍]（另半幅生成） + [种子间距奇偶→镜像是否反色（创新隐蔽规则）]

**来源原语**：平铺/种子像素/条纹/阵列排布/种子定条纹周期（0a938d79），镜像/拼接/整幅画布/轴对称/画布加倍（c9e6f938），奇偶决定颜色（db3e9e38）

**依赖链**：两个种子像素在网格左半区定义一个竖直条纹图案（源自 0a938d79），条纹仅填充左半区。右半区通过水平镜像生成（源自 c9e6f938 的画布加倍）。但镜像是否反转两种条纹颜色取决于种子间水平距离的奇偶性（创新：将 db3e9e38 的奇偶决定颜色概念应用于镜像行为）。这一隐蔽规则只有对比种子间距为偶数和奇数的多个示例才能发现。

左半区根据种子像素生成竖直条纹，右半区为左半区的水平镜像，但种子水平间距的奇偶性决定镜像时是否交换两种条纹颜色。

**输入结构**：黑(0)背景，网格行数约 10~14，列数为偶数（约 16~22）。网格中恰好有两个非黑像素（种子像素），颜色互不相同且互不为黑（如红(2)和蓝(1)）。两个种子均位于网格左半区（列索引 < W/2，W 为列数）。两个种子在不同行、不同列。两个种子均不位于网格的左右侧边缘（即列索引不为 0 也不为 W/2-1），因此按 0a938d79 的规则生成竖直全高条纹。生成约束：不同示例中种子的水平距离有时为偶数、有时为奇数，以便求解者归纳奇偶规则。

**规则**：
1. 计算两个种子的水平间距 d = |col_A - col_B|。
2. 在网格左半区（列 0 至 W/2-1）生成竖直条纹：分别在种子 A 和种子 B 所在列绘制全高的竖直色条（种子 A 的颜色填满 A 所在列，种子 B 的颜色填满 B 所在列）。以步幅 2d 沿水平方向重复这两列色条（即在 col_A + 2d, col_A + 4d... 和 col_B + 2d, col_B + 4d... 处复制），向左同理（col_A - 2d... 和 col_B - 2d...）。超出左半区范围（列 < 0 或列 >= W/2）的条不绘制。
3. 生成右半区：
   - 若 d 为偶数：右半区是左半区的简单水平镜像（每行的列 W/2 到 W-1 对应左半区列 W/2-1 到 0 的像素，颜色不变）。
   - 若 d 为奇数：右半区是左半区的水平镜像，但同时交换两种种子颜色（左半区中种子 A 颜色的像素在右半区变为种子 B 的颜色，反之亦然；黑(0)保持不变）。
4. 种子像素本身作为条纹的一部分被正常处理（不额外保留或标记）。

**关键洞察**：种子间距同时控制两个层面——条纹的空间周期（2d）和镜像的色彩行为（是否反色）。同一个几何参数的不同属性（数值大小 vs 奇偶性）分别影响不同的操作环节。这一耦合是隐蔽的：仅看一个示例无法区分"总是保色镜像"和"总是反色镜像"，必须对比奇偶不同的多个示例。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
