## 新题 1：形状识别门控的选择性路径偏转

**组合逻辑**：[形状匹配](创新：匹配结果不用于重涂色，而用于门控偏转条件) → [流动绘制](已有) → [重涂色](创新：偏转器变色为它实际偏转的源流颜色)

**来源原语**：形状匹配/shape_matching (2a5f8217), 归一化形状匹配/normalized_shape_matching (2a5f8217), 流动绘制/flow_draw (f15e1fac), 逐步偏移/step_deflection (f15e1fac), 对齐时偏移/deflect_when_aligned (f15e1fac), 重涂色/recolor (d511f180)

**依赖链**：形状匹配决定哪些偏转器对哪条流生效（选择性偏转），偏转改变路径轨迹，最终只有实际参与偏转的偏转器才被重涂色——三步之间存在信息流依赖：匹配结果→偏转发生与否→重涂色与否。

从边缘出发的彩色流沿直线前进，途中仅被与自身模板形状匹配的偏转器推偏；实际发生偏转的偏转器变为对应流的颜色。

**输入结构**：约 15x15 的黑(0)背景网格。左边缘有 2-3 个不同颜色的源像素（如红(2)、蓝(1)、绿(3)），每个源像素正右方紧贴一个由同色像素构成的小型 4-连通图形（3-5 像素，充当该源的"模板签名"，不同示例中模板的具体形状不同但像素数范围一致）。网格内部散布 3-5 个灰(5)色的小型 4-连通图形（"偏转器"，3-5 像素），它们彼此不相邻且不触碰网格边缘。每个偏转器的归一化形状（将其像素平移到边界框左上角后的掩码）恰好与某一个源模板的归一化形状相同。生成约束：每个源模板至少有一个匹配偏转器；不同源模板的归一化形状互不相同。

**规则**：
1. 每个源像素向右发射一条水平流路径，逐列前进，路径颜色与源像素相同。
2. 当流路径的当前行与某个偏转器的边界框行范围有交集时，检查该偏转器的归一化形状是否与当前流的源模板的归一化形状相同。若相同，流路径在该列向下偏移一个像素（行号+1）后继续水平前进；若不同，流路径不受影响，直线穿过。
3. 若同一流路径依次经过多个匹配偏转器，偏移效果累加（每次+1行）。
4. 流路径遇到网格右边缘时停止。流路径上的像素用源颜色绘制，覆盖背景。
5. 每个偏转器检查是否有至少一条流路径因它而发生了偏移：若是，将该偏转器所有像素重涂为使它偏转的那条流的源颜色；若否，偏转器保持灰(5)不变。
6. 源模板图形在输出中保持原样不变。

**关键洞察**：偏转器是否生效取决于它与流源模板的形状匹配结果——相同外形的灰色小图形对不同颜色的流有选择性响应，形状识别充当了偏转的门控条件。

Recolor each blue placeholder object with the color of the non-blue object that has the same shape.

Input structure
- A black-background grid contains several 4-connected foreground objects.
- Blue objects are uncolored placeholders.
- Every non-blue foreground object is a colored shape template.

Rule
- Compare objects by their normalized 4-connected pixel mask inside their bounding box.
- For each blue object, find the unique non-blue template object with the same normalized mask.
- Recolor all pixels of the blue object to that matched template color; leave templates and background unchanged.

Key insight
- Position is irrelevant: each placeholder is identified by shape equality with a colored template elsewhere in the grid.

- The non-target end object acts as a pusher; the central rectangle travels
  away from it through the perpendicular target, opening a matching gap.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
