## 新题 3：朝向过滤式推移与擦除

**组合逻辑**：[推移](原有) + [擦除](原有，创新：擦除条件由几何朝向与推移方向的匹配性决定) + [朝向编码方向](原有，创新：朝向不再决定射线方向，而是作为推移资格的过滤器) + [碰撞停止](原有，创新：被擦除的精灵体不参与碰撞，改变幸存者的推移路径)

**来源原语**：推移/push、擦除/erase、接触侧决定方向/contact_side_dir、推至边界停止/stop_at_boundary（参考题11 5623160b）；朝向编码方向/orientation_encodes_direction（参考题13 409aa875）；碰撞停止/collision_stop（参考题17 6ad5bdfd）

**依赖链**：几何朝向解码 → 与推移方向比较 → 分流（匹配者推移 / 不匹配者擦除）→ 擦除后更新碰撞环境 → 推移在更新后的环境中执行

朝向编码从射线发射的方向指示器变为一个布尔过滤器，决定精灵体的命运（推移或消亡），而消亡者的缺席又改变了幸存者的物理空间。

**输入结构**：约 12x15 网格，黑(0)背景。网格中散布若干栗(9)色标记像素（单像素，不构成连通体）。有 5-7 个单色 4-连通精灵体，每个精灵体恰好 4 像素，具有沿恰好一个轴的双边对称性（例如：3 像素排成一条直线 + 1 像素从直线中央向垂直方向延伸；不同示例中具体形态不同，但都满足"恰好一个对称轴"的结构约束）。每个精灵体的颜色互不相同，可选自红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、青(8)等。每个精灵体恰好有一个像素与一个栗(9)标记像素四邻接相邻，该相邻面确定接触侧。精灵体的"朝向"定义为：从 3 像素直线的中央像素指向第 4 个（延伸）像素的方向，即上、下、左或右。生成约束：每个栗(9)标记像素最多与一个精灵体相邻；精灵体互不四邻接。

**规则**：
1. 对每个精灵体，确定接触侧（精灵体与栗(9)标记相邻的那一面）和推移方向（远离接触侧的方向，即接触侧的反方向）。
2. 解码精灵体的几何朝向（从 3 像素直线中央指向延伸像素的方向）。
3. 比较推移方向与几何朝向：
   - 若两者相同：该精灵体被保留，等待推移。
   - 若两者不同：该精灵体被擦除——从网格中移除（位置变为黑(0)），但其关联的栗(9)标记像素保留。
4. 擦除所有不匹配精灵体后，对保留的精灵体执行推移：
   - 按精灵体到其推移方向上网格边界的距离从小到大排序（距离最近者先推移）；距离相同时按精灵体最左列像素从左到右排序。
   - 每个保留精灵体沿推移方向刚性平移，直到碰到网格边界、栗(9)标记像素或已结算的其他推移精灵体而停止。
   - 精灵体的原始位置清除为黑(0)。
5. 栗(9)标记像素始终保持不动。

**关键洞察**：精灵体的几何形状同时承载两个功能——它既是被操作的对象，又通过自身的朝向编码决定自己是否有资格被推移。被擦除的精灵体腾出了原本被占据的空间，使得幸存者的推移路径可能更长或到达不同的终点。求解者必须对比多个示例才能归纳出朝向与推移方向的匹配规则，因为单个示例中无法区分"被擦除是因为朝向不匹配"还是"被擦除是因为其他未知条件"。
