## 新题 7：隐含十字计数压缩为颜色编码网格

**组合逻辑**：[压缩/分区采样](创新：采样内容不是单个前景像素而是模式计数结果) + [重涂色](创新：颜色不表示原有属性而编码计数值) + [四向对齐/缺失中心检测](已有原语)

**来源原语**：压缩/分区网格/分区采样(5783df64)、重涂色/微型条/隐含十字/四向对齐/缺失中心(9f5f939b)、计数(de1cd16c)

**依赖链**：分区将网格切为块 -> 每块内检测隐含十字模式需要四向对齐判断 -> 十字计数编码为输出颜色。删去分区则无法界定检测范围（块边界限制了跨块十字的形成）；删去十字检测则无计数来源；删去颜色编码则计数结果无表达方式。

在分区网格的每个块内检测由微型条构成的隐含十字图案的数量，将计数编码为对应颜色输出到压缩网格中。

**输入结构**：一个 18x18 或 21x21 的网格（边长为 6 或 7 的 3 倍），黑(0)背景。网格在概念上被均分为 3x3 共 9 个正方形块（每块 6x6 或 7x7）。每个块内散布若干蓝(1)微型条（每个微型条为水平或垂直方向的 2 像素连续段）。部分微型条的排列会形成隐含十字：某个黑(0)背景像素的上方距离 2~3 格处有一个垂直微型条、下方距离 2~3 格处有一个垂直微型条、左方距离 2~3 格处有一个水平微型条、右方距离 2~3 格处有一个水平微型条（四向齐备）。一个块内可能有 0、1、2 或 3 个这样的隐含十字中心。生成约束：隐含十字中心之间的四向微型条不共享（每个微型条最多属于一个十字）；微型条不跨越块边界；各块的十字中心数量至少出现两种不同值。

**规则**：
1. 将输入网格均分为 3x3 的块阵列，每块尺寸 = 网格边长 / 3。
2. 对每个块，在块内部检测隐含十字：遍历块内每个黑(0)背景像素 (r, c)，检查其四个方向是否都有匹配的微型条——上方：(r-2, c) 和 (r-3, c) 都是蓝(1)；下方：(r+2, c) 和 (r+3, c) 都是蓝(1)；左方：(r, c-2) 和 (r, c-3) 都是蓝(1)；右方：(r, c+2) 和 (r, c+3) 都是蓝(1)。所有 8 个位置都在块内部且满足条件时，(r, c) 是一个隐含十字中心。
3. 统计每个块中的隐含十字中心数量 k。
4. 输出一个 3x3 的网格，每个单元格的颜色编码为：k=0 -> 黑(0)，k=1 -> 蓝(1)，k=2 -> 红(2)，k=3 -> 绿(3)。

**关键洞察**：块边界是隐含的（输入中没有可见的分割线），但它严格限制了哪些微型条可以组合成十字——同样的微型条布局在不同的分区方案下会产生不同的十字计数，求解者必须先推断出正确的分区尺寸。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
