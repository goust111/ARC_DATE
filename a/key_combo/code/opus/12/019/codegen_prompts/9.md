## 新题 9：印章填槽后支撑签名连线

**组合逻辑**：[印章覆盖](已有原语) + [连线](创新：不再连接两个预设标记，而是连接新产生的印章副本) + [支撑签名匹配](已有原语) + [按原色区分涂色](已有原语)

**来源原语**：印章覆盖/精灵体/空槽位/支撑签名匹配/空位接受印章(e5062a87)、连线/标记像素/两点直线路径/按原色区分涂色(bcb3040b)

**依赖链**：支撑签名匹配确定哪些空槽位接受印章 -> 印章覆盖产生新的红色图案 -> 新印章的中心与原始印章中心之间的连线才能绘制。删去匹配则不知道哪些槽位有效；删去连线则只是重复参考题的印章逻辑；删去印章则连线端点不存在。

先将红色精灵体印入所有匹配的灰色支撑空槽中，然后从原始精灵体中心向每个新印章中心画直线，线上经过灰色支撑像素的部分变为绿色、经过黑色背景的部分为红色。

**输入结构**：约 18x18 的网格，黑(0)背景。网格中有一个由红(2)像素和灰(5)支撑像素组成的精灵体（原始精灵体，红色部分为 3~5 像素的 4-连通不规则形状，灰色部分是边界框内的支撑像素）。网格中还有 2~4 个与原始精灵体支撑签名完全匹配的空槽位：这些位置的灰(5)像素排列与原始精灵体边界框内的灰(5)像素一致，但红色位置为黑(0)空白。空槽位之间互不重叠，且不与原始精灵体重叠。此外可能有 0~2 个干扰性的灰(5)像素团（支撑签名不匹配的），不应被填充。生成约束：原始精灵体和每个有效空槽位的边界框中心连线为水平、垂直或 45 度对角线方向之一；各连线路径互不交叉。

**规则**：
1. 提取原始精灵体的边界框，记录红(2)像素的相对位置作为印章掩码，记录灰(5)像素的相对位置作为支撑签名。
2. 从左上到右下逐像素扫描候选位置，在每个位置放置边界框大小的窗口：若窗口内所有印章掩码位置为黑(0)且所有支撑签名位置为灰(5)，则该位置匹配。
3. 对每个匹配位置，将印章掩码对应的黑(0)像素涂为红(2)。
4. 计算原始精灵体的边界框中心 (r0, c0)（行中心取 floor((top+bottom)/2)，列中心取 floor((left+right)/2)）。对每个新印章，计算其边界框中心 (ri, ci)。
5. 从 (r0, c0) 到每个 (ri, ci) 画直线（水平、垂直或 45 度对角线，由两点相对位置决定），包含两个端点。
6. 直线上每个像素的着色：若该像素在步骤 3 完成后为灰(5)（原始支撑像素或槽位支撑像素），则着绿(3)；否则着红(2)。
7. 连线的处理顺序：按新印章中心到原始中心的曼哈顿距离从小到大逐条画线，后画的线覆盖先画的。

**关键洞察**：印章覆盖创造了连线的端点（新印章不存在于输入中），而连线路径上的灰色支撑像素——本来是印章匹配的条件——又成为了连线变色的触发器，同一组灰色像素在"匹配判断"和"路径着色"中扮演了完全不同的角色。
