## 新题 3：精灵体像素数编码旋转后沿视线滑动对接

**组合逻辑**：[旋转(rotate)](创新：旋转量由精灵体自身像素数编码) + [滑动(slide)](已有) — 旋转必须先于滑动执行，因为旋转后的形状决定了对接姿态

**来源原语**：滑动(slide) ← e1d2900e；旋转(rotate) ← 6ffbe589；标记像素(marker_pixel) ← e1d2900e；实心方块(solid_block) ← e1d2900e；提示精灵体(cue_sprite) ← 6ffbe589；视线对齐(sightline_align) ← e1d2900e；同色匹配(same_color_matching) ← 6ffbe589；像素数编码旋转(pixel_count_encodes_rotation) ← 6ffbe589；沿视线移至近块旁(slide_to_nearest_block) ← e1d2900e

**依赖链**：精灵体像素数 → 旋转量 → 旋转后精灵体形状 → 沿视线滑动并贴靠方块。旋转改变了精灵体的空间形态，进而影响滑动后的对接位置和朝向。

将散落的小精灵体先按自身像素数旋转，再沿视线滑动贴靠到同色的 2x2 方块旁。

**输入结构**：约 15x15 的网格，黑(0)背景。包含 3~4 个不同颜色的 2x2 实心方块（颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，每色最多一个方块）。另有 3~4 个小型单色精灵体（4-连通，3~6 像素，形状为非对称的不规则连通体，如 L 形变体、Z 形变体等），每个精灵体的颜色与恰好一个方块相同。每个精灵体与其同色方块之间存在唯一的无遮挡水平或垂直视线（视线路径上无其他非黑像素）。生成约束：不同精灵体的像素数至少有两个不同（以便推断旋转规则）；旋转后精灵体贴靠方块时不会与其他已对接精灵体冲突；至少有一个精灵体像素数为非 4 的倍数（使旋转效果可观察）。

**规则**：
1. 对每个精灵体，统计其像素数 P。
2. 将精灵体以其边界框中心为旋转中心，顺时针旋转 (P mod 4) x 90 度。旋转后像素坐标四舍五入到最近网格位置。若 P mod 4 = 0，不旋转。
3. 找到该精灵体的同色 2x2 方块，确认两者之间的无遮挡视线方向（水平或垂直）。
4. 将旋转后的精灵体沿该视线方向滑动，直到精灵体最近像素紧邻方块边缘（相距 1 像素）。
5. 若某精灵体不存在无遮挡视线（被其他已对接物体阻挡），则该精灵体保持原位不旋转、不移动。
6. 处理顺序：按精灵体与同色方块的曼哈顿距离从小到大处理；距离相同时先处理行号更小的精灵体。

**关键洞察**：精灵体的像素数不只是一个属性——它编码了旋转参数，而旋转必须发生在滑动之前，因为旋转改变了精灵体的形状轮廓，从而影响对接后的最终姿态。需对比不同像素数的精灵体才能发现"像素数 mod 4"的旋转规则。
