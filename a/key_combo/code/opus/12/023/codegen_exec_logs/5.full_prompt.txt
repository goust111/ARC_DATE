## 新题 5：孤立像素射线坐标定位印章

**组合逻辑**：[射线延伸](创新：孤立像素的射线不画在网格上，而是标记格子单元的行列为"活跃") + [行列交叉](活跃行与活跃列的交叉确定目标格元) + [印章覆盖](将模板精灵体复制到目标格元，且行方向和列方向的非交叉格元获得镜像副本)

**来源原语**：射线延伸(ray_extend) + 孤立像素(isolated_pixel) + 行列交叉(row_col_intersection) 来自参考题 23581191；印章覆盖(stamp_overlay) + 分隔线网格(separator_lattice) 来自参考题 e734a0e8/48f8583b；精灵体(sprite) 来自参考题 7d18a6fb/681b3aeb

**依赖链**：两个孤立像素的格元坐标 → 确定活跃格元行和格元列 → 行列交叉格元 = 主目标（放置原版精灵）→ 仅在活跃行的其他格元放水平翻转副本 → 仅在活跃列的其他格元放垂直翻转副本。翻转轴由格元属于活跃行还是活跃列决定，这一规则需对比多个示例归纳。

两个孤立像素在格子阵列中充当行列坐标选择器；行列交叉的格元获得原版精灵，同行或同列的其他格元获得对应方向的镜像副本。

**输入结构**：约 17x17 的网格。红(2)分隔线将网格分为 4x4 的等大方形格元阵列（每个格元约 3x3，格元之间由单像素宽红线分隔）。所有格元内部为黑(0)，除以下三种例外：(a) 一个格元包含一个绿(3)的小型不规则 4-连通精灵体（3~5 像素，不对称，无旋转对称性），即模板；(b) 另一个格元的中心有一个蓝(1)孤立像素；(c) 又一个格元的中心有一个黄(4)孤立像素。蓝像素和黄像素不在同一格元行，也不在同一格元列。生成约束：蓝像素、黄像素、模板精灵体分别在三个不同的格元中；活跃行与活跃列的交叉格元不是模板所在格元、蓝像素格元或黄像素格元；精灵体在任一方向镜像后仍能容纳在单个格元内。

**规则**：
1. 确定蓝(1)孤立像素所在的格元行号（称为活跃行 R），以及黄(4)孤立像素所在的格元列号（称为活跃列 C）。格元行列号从左上角 (0,0) 开始。
2. 在活跃行 R 与活跃列 C 交叉处的格元（即格元 (R, C)），以该格元左上角为锚点，放置模板精灵体的原版副本（保持精灵在模板格元中的相对位置不变）。
3. 活跃行 R 中的其他空白格元（不含蓝像素格元、不含模板格元、不含格元 (R,C)），各放一个精灵的水平翻转副本（沿格元垂直中轴左右镜像）。
4. 活跃列 C 中的其他空白格元（不含黄像素格元、不含模板格元、不含格元 (R,C)），各放一个精灵的垂直翻转副本（沿格元水平中轴上下镜像）。
5. 蓝像素格元和黄像素格元保持原样（仅含各自的孤立像素）。模板格元保持原样。所有非活跃行列的格元保持黑(0)。红(2)分隔线保持不变。

**关键洞察**：两个孤立像素建立了一个格元坐标系统（类似参考题 23581191 中十字射线的行列选择逻辑），但选中格元的内容不是着色而是印章放置。更隐蔽的规则是翻转方向的选择——活跃行格元做水平翻转、活跃列格元做垂直翻转——这一规则不能从单个示例中推断（需要至少两个示例验证翻转轴与行/列的对应关系）。

Input structure
- The input has a dominant background with scattered clutter colors.
- The meaningful objects are monochromatic 4-connected foreground rectangles, each at least 3x3 and exactly filling its bbox.
- These rectangles form a complete lattice whose same-row and same-column bbox intervals overlap.

Rule
- Keep only the filled rectangular objects.
- Group their vertical bbox intervals into output rows and their horizontal bbox intervals into output columns.
- Fill each compact output cell with the color of the rectangle at the corresponding lattice position.

Key insight
- The clutter is not a filled 3x3-or-larger rectangle; the rectangles' overlapping bbox bands define the small table axes.
</description>

  grid: 30x30, background 0
  lattice:
    shape: 2-4 rows x 3 cols [observed cols=3]
    cells: rows*cols filled rectangular monochromatic objects (6-12 total)
  rectangles:
    size: 3-8 height x 3-8 width, each >= 3x3 and area = h*w (perfectly filled)
    colors: 5-6 distinct non-bg non-clutter colors; colors may repeat across lattice cells
    spacing: min gap >= 2 cells between any two rectangles
    band_overlap: rects in the same lattice row share overlapping row-intervals; same for columns
    no_overlap: no two rectangle bboxes overlap spatially
  clutter:
    colors: exactly 2 colors disjoint from bg and rectangle colors
    scatter: ~170-200 small 4-connected components (area 1-8 each, mostly singletons) totaling 260-370 pixels
    large_blobs: 1-3 irregular connected components per clutter color with area 9-14 that are NOT filled rectangles (non-rectangular shape, or h<3 or w<3)
    placement: clutter never overlaps rectangle bboxes; only in bg areas
  output: rows x cols grid where cell (r,c) = color of the rectangle at lattice position (r,c)

generation_strategy:
  approach: output-first
  steps:
    1. Pick lattice shape R x 3 with R in [2,4]; pick R*3 colors (with repeats allowed) from non-zero palette for the output grid
    2. Choose 2 additional clutter-only colors disjoint from rectangle colors and bg
    3. On 30x30 grid assign each lattice cell a rectangle size (h,w) in [3,8]x[3,8]; place them so same-row rects share overlapping row-intervals, same-col rects share overlapping col-intervals, no bbox overlaps, and min gap >= 2
    4. Fill each rectangle solidly with its assigned color
    5. Scatter ~300 pixels of clutter (2 colors) as single pixels and small blobs (area 1-8) across bg-only areas; include 1-3 irregular blobs with area 9-14 that fail the filled-3x3-rect test
    6. Output is simply the R x 3 color grid from step 1

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
