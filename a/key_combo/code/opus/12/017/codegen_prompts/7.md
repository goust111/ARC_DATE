## 新题 7：原始像素计数定缩放倍率 + 图例链式重涂后缩放

**组合逻辑**：[计数/counting + 像素数定尺寸数/pixel_count_sets_size_copies](创新：计数发生在重涂之前，但缩放应用于重涂之后的结果) + [逐行顺序链式替换/chain_replace](图例可能将某些前景色映射为背景色，减少可见像素) + [像素放大/pixel_scale](将重涂后的精灵按预先冻结的倍率放大) + [双列图例/two_col_legend](提供颜色替换规则)

**来源原语**：counting, pixel_count_sets_size_copies (91413438); pixel_scale (8a6d367c); chain_replace, two_col_legend, legend_row_order (e4888269); recolor (多源)

**依赖链**：缩放倍率取决于原始精灵的非背景像素总数（重涂前），但被缩放的内容是重涂后的精灵（可能有像素变成了背景色而"消失"）。如果在重涂后再计数，得到的倍率更小，输出尺寸就会错误。这种时序约束使计数和重涂紧耦合：计数必须先于重涂，但缩放的输入是重涂后的结果。

先数原始精灵的前景像素得缩放倍率，再按图例链式重涂精灵（部分像素可能变为背景色），最后将重涂后的精灵按先前冻结的倍率像素放大输出。

**输入结构**：
- 黑(0)背景，约 12x12 网格
- 左侧：一个 3x3 的多色精灵，包含 2~3 种非黑前景色（如蓝(1)、红(2)、绿(3)），其中非黑像素共 S 个（4 <= S <= 7）
- 右侧：一个 2 列 x K 行的图例块（K = 1~3），每行左列为源色、右列为目标色
- 图例中至少有一行将某前景色映射为黑(0)（背景色），使重涂后精灵的可见前景像素数小于 S
- 图例行从上到下顺序应用（链式替换：前一行的替换结果可能被后一行再次替换）
- 精灵与图例之间间隔至少 2 列背景，互不接触

**规则**：
1. 计算原始精灵中所有非黑(0)像素的总数 S（这是缩放倍率）
2. 按图例从上到下逐行应用链式颜色替换：对精灵中每个非背景像素，若其当前颜色等于该行左列颜色，则替换为右列颜色；替换后继续检查下方行
3. 将重涂后的 3x3 精灵进行 S 倍像素放大：每个像素扩展为 S x S 的同色方块，输出尺寸为 (3S) x (3S)
4. 输出仅包含放大后的精灵，原始精灵和图例均不保留

**关键洞察**：缩放倍率 S 是在重涂前的精灵上计算的"冻结值"，而缩放内容是重涂后的精灵。如果错误地在重涂后计数，由于图例将部分前景色变为背景色(0)，S 会变小，输出尺寸就会出错。必须对比多个示例（图例将不同数量的像素变为背景）才能发现"先数后涂"的时序约束。
