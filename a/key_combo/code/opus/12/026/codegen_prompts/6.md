## 新题 6：原型匹配门控描边与擦除

**组合逻辑**：[形状匹配(shape_match)](已有) + [压缩(compress)](已有) + [描边(outline)](创新：仅对匹配成功的对象描边) + [擦除(erase)](创新：仅对匹配失败的对象擦除) → 组合创新：匹配结果分叉为两种对立操作

**来源原语**：形状匹配(shape_match)←bd14c3bf, 压缩(compress)←bd14c3bf, 描边(outline)←b27ca6d3, 擦除(erase)←a680ac02, 原型对象(prototype_object)←bd14c3bf, 候选对象(candidate_object)←bd14c3bf, 旋转反射等价(rotation_reflection_eq)←bd14c3bf, 游程压缩后比较(run_length_compare)←bd14c3bf, 连通分量(connected_component)←b27ca6d3, 边框(border_frame)←b27ca6d3

**依赖链**：压缩→匹配判定→二元分支（匹配→重涂+描边，不匹配→擦除）。压缩是匹配的前提，匹配结果决定分支走向，两条分支执行完全对立的操作。

用游程压缩后的形状比对将候选对象分为匹配组和不匹配组：匹配的重涂并描边，不匹配的擦除。

**输入结构**：约 18×18 的黑(0)背景网格。网格中有一个红(2)的原型对象（3~6 像素的 4-连通图形）和 4~6 个蓝(1)的候选对象。候选对象的像素数各不相同（3~12 像素），有些是原型的拉伸版本（沿行或列方向将某些行/列重复，使整体变大但压缩后恢复原型形状），有些是完全不同的形状。拉伸版本可能同时经过旋转或翻转。候选对象之间互不相邻（边界框不重叠），且不与原型相邻。生成约束：至少有 2 个候选匹配原型，至少有 1 个不匹配。

**规则**：
1. 裁剪原型对象到其边界框，得到原型掩码 P。
2. 对每个候选对象，裁剪到边界框，然后执行游程压缩：如果相邻两行完全相同，合并为一行；如果相邻两列完全相同，合并为一列。反复执行直到不可再压缩，得到压缩掩码 C。
3. 对原型掩码 P 同样执行游程压缩，得到 P'。
4. 检查 C 是否与 P' 在旋转（0°、90°、180°、270°）或翻转（水平、垂直）的任一变体下相同。
5. 匹配成功的候选对象：将其所有蓝(1)像素重涂为红(2)，然后在其原始（未压缩）边界框外扩 1 格的矩形周边绘制绿(3)边框（仅在黑(0)位置绘制）。
6. 匹配失败的候选对象：将其所有蓝(1)像素擦除为黑(0)。
7. 原型对象本身保持不变。

**关键洞察**：同一个判定条件（压缩后形状匹配）驱动两种对立的操作——匹配者被"接纳"（重涂+描边使其在视觉上与原型统一并高亮），不匹配者被"清除"。这种二元门控在源题中不存在：bd14c3bf 只做重涂不做擦除，b27ca6d3 只做描边不做分类。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
