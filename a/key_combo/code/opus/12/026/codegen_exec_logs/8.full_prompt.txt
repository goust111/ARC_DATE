## 新题 8：边界投射与触发点分束标记

**组合逻辑**：[投射(project)](已有) + [连线(connect)](创新：投射路径替代对角连线) + [射线延伸(ray_extend)](已有) → 组合创新：投射路径上的触发像素使射线分裂为垂直分支

**来源原语**：投射(project)←1f642eb9, 连线(connect)←db695cfb, 射线延伸(ray_extend)←db695cfb, 目标对象(target_object)←1f642eb9, 触发像素(trigger_pixel)←db695cfb, 画布边界(canvas_boundary)←1f642eb9, 碰撞阻挡(collision_blocking)←1f642eb9, 边界像素投射目标(border_projected_to_target)←1f642eb9, 触发点分束(trigger_splits_beam)←db695cfb

**依赖链**：边界像素沿行/列投射→投射路径遇到触发像素时分束为垂直方向的射线→分束射线延伸直到碰到目标对象或网格边界→触发像素位置同时影响原始投射路径的终止和分束射线的起点。投射路径生成分束机会，分束方向由投射方向的垂直旋转决定。

边界标记像素向中心目标投射，途中遇到品红触发点时分裂出垂直方向的射线，原射线被截断。

**输入结构**：约 15×15 的黑(0)背景网格。网格中央偏内有一个由青(8)像素构成的不规则紧凑对象（4-连通，5~10 像素，非矩形）。网格的四条边（第 0 行、最后一行、第 0 列、最后一列）上散布 3~5 个单像素彩色标记，颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取，每个标记颜色不同。在网格内部（非边界、非青色对象上）散布 1~3 个品红(6)的单像素触发点。每个边界标记沿其可投射方向（位于上边则向下投射，位于左边则向右投射，以此类推）的路径上至多经过一个触发点，且该路径最终指向青色对象。生成约束：每个边界标记的投射路径上恰好有 0 或 1 个触发点；触发点不在青色对象的正交邻居上。

**规则**：
1. 识别青(8)目标对象、边界标记像素、品红(6)触发点。
2. 对每个边界标记，确定其投射方向（朝网格内部的唯一正交方向：上边标记向下，下边标记向上，左边标记向右，右边标记向左；角落标记按行优先即向内水平方向投射）。
3. 沿投射方向逐像素前进，在路径上绘制该标记的颜色：
   a. 若路径上未遇到触发点，一直绘制到碰到青色目标对象为止（终点即目标对象表面像素被涂为标记颜色）。
   b. 若路径上遇到品红(6)触发点：在触发点前一个像素处截断原投射路径（触发点本身不被覆盖）。从触发点位置出发，向投射方向的两个垂直方向各发射一条以该标记颜色绘制的射线，射线延伸到碰到任何非黑(0)像素或网格边界时停止（不覆盖终点）。
4. 所有投射按边界标记从左上角开始顺时针的顺序依次处理。后处理的射线遇到先前绘制的射线颜色时视为非黑像素，停止延伸。

**关键洞察**：触发点将一维投射路径转化为二维分支结构——同一个标记的颜色从直线转为丁字形展开。触发点的位置决定了颜色信息在网格上的传播范围和几何形态，这在投射（1f642eb9）和分束（db695cfb）的源题中都不存在。

<description>
Slide each inner colored object horizontally into the same-colored vertical wall until it touches an obstacle.

Input structure
- The background is the dominant color.
- The only foreground colors are two non-background colors.
- One foreground color fills the left column and the other fills the right column.
- Extra 8-connected objects of each wall color appear away from that color's wall.

Rule
- Clear the extra objects from their original positions.
- For each wall color, process its 8-connected extra objects from nearest to farthest from the matching wall.
- Slide each object horizontally toward its matching wall as far as possible without overlapping the wall or an already settled object of the same color.
- Keep the two vertical wall columns fixed.

Key insight
- The side columns act like color-specific gravity walls: same-colored objects compact sideways against their own wall while preserving each object's shape.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
