## 新题 1：旋转条生成禁区后寻找唯一安全路径

**组合逻辑**：[旋转](创新：旋转结果不直接输出，而是生成寻路禁区) + [寻路] + [重涂色]（旋转、寻路均为已有原语，"旋转输出定义禁区"是创新结构关系）

**来源原语**：旋转/中心点不变/朝向交换长度保持(f0f8a26d), 寻路/邻域禁区/唯一安全路径(cc9053aa), 重涂色(67385a82)

**依赖链**：旋转操作的输出改变了空间禁区分布 -> 禁区决定了哪些轨道像素可通行 -> 寻路在可通行子图上找唯一路径 -> 路径像素被重涂色。删除旋转步骤则禁区位置错误（用原始条位置会得到不同路径或无唯一路径）；删除寻路步骤则无法确定哪些像素需要重涂色。

根据输入中条的位置先做心算旋转确定真实障碍，再在轨道上寻找避开这些障碍的唯一路径，将路径涂为端点颜色。

**输入结构**：约 18x18 的黑(0)背景网格。青(8)像素构成一条 4-连通的弯曲轨道路径，轨道两端各有一个栗(9)端点像素。轨道上嵌有 2~3 个橙(7)障碍像素（与参考题 cc9053aa 类似）。此外，网格中散布 3~4 根灰(5)的单像素宽条（奇数长度，水平或竖直，长度 3~7 像素），它们不与轨道重叠，但位于轨道附近。生成约束：每根灰条旋转 90 度后，其旋转像素的 8-邻域至少覆盖到一段轨道像素；所有灰条旋转后产生的禁区加上橙障碍的禁区恰好使两端点之间仅存一条简单 4-连通路径。

**规则**：
1. 将每根灰(5)条绕其中心点旋转 90 度（水平变竖直、竖直变水平，长度和中心不变）。旋转后的灰像素覆盖到的位置成为新的障碍位置（原始灰条像素清除为背景）。
2. 将每个橙(7)障碍像素及其 8-邻域内的所有轨道像素标记为禁行（与参考题 cc9053aa 相同）。
3. 将每个旋转后灰障碍像素及其 8-邻域内的所有轨道像素也标记为禁行（规则与橙障碍相同）。
4. 在剩余可通行的青(8)/栗(9)像素构成的 4-连通子图中，找到两个栗(9)端点之间的唯一简单路径。
5. 将该路径上的所有青(8)像素重涂为栗(9)；端点、橙障碍及所有其他像素保持不变。灰条在输出中不出现（已被清除）。

**关键洞察**：灰条的当前朝向是误导——必须先心算旋转才能知道真正的禁区位置；原始位置的条可能完全不阻挡轨道，旋转后才产生关键阻断，使路径唯一。

<description>
Collapse a separator grid into one color per region, then mirror the compact grid left-to-right.

Input structure:
- The input is divided into uniformly colored cells by horizontal and vertical separator bars.
- Each region between separators has a single color.
- The separator color forms a connected partition spanning the full canvas.

Rule:
- Identify the separator color and extract all separator-delimited regions.
- Replace each region with one pixel of its region color, preserving row and column order.
- Mirror the compact region-color grid horizontally.

Key insight:
- The large chessboard-like image is an enlarged region map; the final step is a left-right
  reflection of that compressed map.
</description>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
