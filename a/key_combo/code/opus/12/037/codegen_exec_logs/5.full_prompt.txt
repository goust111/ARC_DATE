## 新题 5：角落标记编码旋转方向的凹槽拼接

**组合逻辑**：[形状匹配](已有) + [角落标记 → 标记色定朝向](创新组合：原题 fd02da9e 中标记色选模板形状，原题 6e4f6532 中标记色定旋转方向，本题中标记在精灵体上的角落位置编码旋转量) → [旋转](已有) → [拼接入凹槽 + 擦除](已有)

**来源原语**：角落标记/corner_marker、标记色传递给模板/marker_color_pass（来自 fd02da9e）；旋转/rotate、标记色定朝向/marker_color_sets_orientation、标记像素/marker_pixel（来自 6e4f6532）；拼接/assemble、凹槽/notch、中心条/central_bar、形状匹配/shape_matching（来自 16b78196）；擦除/erase（来自 fd02da9e, 6e4f6532）

**依赖链**：凹槽形状 → 限定能匹配的精灵体（形状匹配筛选候选者）→ 但对称精灵体可能以多种旋转角度匹配同一凹槽 → 角落标记位置打破旋转歧义（标记必须面向条内部）→ 精灵体以唯一正确的旋转角度嵌入凹槽。形状匹配和标记解码缺一不可：没有形状匹配无法确定目标凹槽，没有标记解码无法确定旋转角度。

将散落的精灵体旋转至其角落标记朝向中心条内侧的方向，然后嵌入形状匹配的凹槽中。

**输入结构**：约 20x20 的黑(0)背景网格。中央有一个灰(5)实心矩形条（约 4x14 或 14x4 像素），条的边界上有 2-4 个矩形凹槽——凹槽是灰色条边界上向内凹陷的黑(0)缺口，每个凹槽宽 2-4 像素、深 1-3 像素，形状各异。条周围散布与凹槽数量相同的小型单色精灵体（每个精灵体一种颜色，从蓝(1)、红(2)、绿(3)、黄(4)中选取，各不相同），每个精灵体的形状在某个 90 度旋转下恰好可以填满某个凹槽。每个精灵体的边界框的某一个角上有一个额外的橙(7)像素（角落标记），该像素不属于精灵体的功能形状，仅用于指示旋转方向。不同精灵体的标记分别在不同角（左上、右上、左下、右下）。生成约束：每个精灵体恰好匹配一个凹槽（一一对应）；精灵体的形状在排除角落标记后进行匹配。

**规则**：
1. 识别灰(5)中心条及其凹槽。每个凹槽的位置确定其开口方向（朝上/朝下/朝左/朝右——即凹槽向条的哪个外侧方向开放）。
2. 对每个散落的精灵体，分离其角落标记像素（位于精灵体边界框某角的橙(7)像素）和功能形状（剩余非橙像素）。
3. 将每个精灵体的功能形状与各凹槽进行形状匹配：尝试 0/90/180/270 度旋转，找到能恰好填满某个凹槽的旋转角度。
4. 从匹配的旋转角度中选择正确的那一个：对功能形状和角落标记同步施加该旋转后，角落标记像素必须位于旋转后精灵体朝向条内部的那一侧（即与凹槽开口方向相反的一侧）。这唯一确定了旋转角度。
5. 将旋转后的功能形状（不含角落标记）嵌入凹槽，像素涂为该精灵体的颜色。
6. 擦除精灵体原始位置的所有像素（包括角落标记），涂为背景色黑(0)。
7. 灰(5)中心条的其余像素保持不变。

**关键洞察**：形状匹配可能因精灵体的对称性产生多个有效旋转角度（例如一个 2x1 矩形可以 0 度和 180 度都匹配同一个凹槽）。角落标记的位置在旋转后发生变化，只有当标记指向条内部时才是正确旋转——这个约束源于角落标记与凹槽开口方向之间的空间关系，而非直接的颜色或形状属性。
