## 新题 4：频率过滤的印章传递

**组合逻辑**：[计数](已有) → [频率匹配](已有，但用于过滤印章内容而非柱状填充) → [骨架对齐+印章覆盖](已有，但仅传递通过频率过滤的标注像素)

**来源原语**：印章覆盖/stamp、骨架对齐/skeleton_alignment、锚点像素/anchor_pixel、完整标注传递副本/complete_anno_to_copies（参考题17 36d67576）；计数/counting、频率匹配/frequency_matching、频率等于标记数/frequency_equals_marker_count、分隔行/separator_row、编码行/code_row（参考题19 2685904e）

**依赖链**：模板标注像素总数作为频率阈值 → 编码行中符合该频率的颜色构成"激活色集" → 仅激活色的标注像素被印章传递到各副本 → 骨架对齐确定传递时的几何变换 → 缺少频率过滤则传递过多标注，缺少骨架对齐则位置错误

模板中标注像素的数量定义频率阈值；编码行中出现次数恰好等于该阈值的颜色才是"激活色"；仅激活色标注被印章传递到骨架副本上。

**输入结构**：黑(0)背景网格，约18x18。3-4个8-连通小图案（精灵体），共享相同的灰(5)骨架结构（5-8像素，形状为不规则连通片段，不同示例中骨架形状不同）。每个图案中有一个橙(7)锚点像素嵌入骨架内部。其中一个图案（"模板"）除灰骨架和橙锚点外，还包含若干额外标注像素，使用2-3种颜色（如蓝(1)、红(2)、绿(3)），分布在骨架的8-邻域周围。其余图案仅有灰骨架和橙锚点，无标注。网格中有一条黄(4)全宽分隔行（水平贯穿整个网格宽度）。分隔行下方紧接一行编码行，编码行中有若干非黑像素，颜色取自标注色的子集。生成约束：模板中各标注色的像素数互不相等；模板标注像素总数T满足编码行中恰有一种颜色出现T次、至少一种颜色出现次数不等于T；各精灵体互不重叠，距分隔行至少2像素。

**规则**：
1. 找到模板图案（唯一包含非灰、非橙、非黑像素的精灵体），统计其标注像素总数（所有非灰非橙非黑像素之和）为T。
2. 在编码行中，找到出现次数恰好等于T的所有颜色，组成"激活色集"。
3. 在模板中，仅保留颜色属于激活色集的标注像素为"可传递标注"，其余标注色视为被过滤掉（这些像素在输出中变为黑色背景）。
4. 对每个不完整图案（仅有骨架和锚点的副本），找到唯一的旋转/翻转+平移变换，使模板的灰骨架和橙锚点完全映射到该副本的灰骨架和橙锚点上。
5. 通过步骤4的变换，将可传递标注像素映射到副本周围对应位置并绘制（若目标位置超出网格则忽略该像素）。
6. 模板自身的非激活标注像素也被擦除（变为黑色背景）。灰骨架、橙锚点、黄分隔行和编码行保持不变。

**关键洞察**：编码行不仅存在于空间上分离的区域，它通过频率匹配充当了标注内容的过滤器——并非所有标注都被传递，只有"被编码行认证"的颜色才存活。模板的标注数量T是一个自引用参数：它同时描述了模板自身的属性并决定了外部过滤标准。
