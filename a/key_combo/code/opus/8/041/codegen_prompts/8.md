## 新题 8：菱形包络即路径禁区

**组合逻辑**：[连线/draw_path + 避障/obstacle_avoidance](已有) + [包络生成/envelope_generation + 逐步收缩](创新：包络不作为装饰输出，而是计算出路径的禁行区域) + [像素计数编码半径](创新：不再用蓝像素计数编码半径，而是由条的几何长度隐式决定禁区范围)

**来源原语**：连线/draw_path + 避障/obstacle_avoidance（cb2d8a2c）、路径起点/path_start（cb2d8a2c）、障碍条/obstacle_bar + 禁区/exclusion_zone + 像素计数编码半径/pixel_count_encodes_radius（cb2d8a2c）、包络生成/envelope_generation + 逐步收缩/stepwise_shrink + 实心条/solid_bar + 菱形轮廓/diamond_outline + 中心对称/center_symmetry（c97c0139）

**依赖链**：条的长度 → 通过菱形包络公式计算禁区半径和形状 → 禁区约束路径规划 → 路径从起点到对边。删除包络计算则不知道禁区范围（条本身只是一维线段，禁区是二维菱形区域）；删除路径规划则无输出；删除条则无障碍物。

每根红色条的菱形包络区域即为路径禁行区，从边缘绿色起点绕行所有禁区到达对边。

**输入结构**：约 19x19 网格，青(8)背景。网格中有 2-4 根红(2)实心条（水平或垂直，1 像素厚，3-7 像素长）。网格某一条边上有一个绿(3)单像素（路径起点）。不同示例中条的数量、长度、朝向、位置和起点位置均不同。生成约束：从起点到对边存在至少一条绕过所有菱形包络禁区的正交折线路径；各条的菱形包络互不重叠（简化路径规划）。

**规则**：
1. 对每根红(2)条计算菱形包络区域（与源题 c97c0139 相同）：包络半径 R = floor((条长 - 1) / 2)，以条为中轴，逐行/列扩展并两端收缩。包络区域包含条本身和周围的菱形范围内的所有像素。
2. 每根条的整个菱形包络区域（包含条像素）构成禁行区域——路径不得经过这些像素。
3. 从绿(3)起点出发，向对边（与起点所在边平行的另一边）绘制绿(3)路径：
   - 路径默认沿垂直于起点所在边的方向直行。
   - 当直行方向的下一个像素位于禁行区域时，路径做直角转弯（沿平行于起点所在边的方向）绕行，直到可以恢复原方向继续直行。
   - 绕行时选择较短的绕行方向（左绕或右绕，取转弯步数较少的一侧）。若两侧步数相同，选择朝网格中心方向的一侧。
4. 路径到达对边后停止（终点像素涂绿(3)）。
5. 红(2)条像素保持红色。菱形包络区域本身不显示（不涂色），仅作为隐式禁区约束路径。
6. 起点像素保持绿(3)。

**关键洞察**：在源题 cb2d8a2c 中，禁区半径由蓝像素数量显式编码；在源题 c97c0139 中，包络是视觉装饰。此处两个原语产生全新结构关系——条的几何长度通过菱形包络公式隐式定义了禁区的形状和大小，路径必须绕过这些不可见的菱形禁区。求解者必须同时归纳出包络形状规则（从条长推导禁区范围）和路径规划规则（如何绕行），且两者必须配合才能预测输出。
