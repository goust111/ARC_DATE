## 新题 10：框架内镜像展开后轨道冲突多数投票修复

**组合逻辑**：[镜像](跨框架线向外展开) + [对称补全](创新：展开结果中的轨道冲突通过多数投票解决而非简单覆盖) + [重涂色](冲突轨道的修复色)

**来源原语**：镜像(mirror) ← f8a8fe49; 框架线(frame_line) ← f8a8fe49; 内部图案(inner_pattern) ← f8a8fe49; 对称轴关系(symmetry_axis) ← f8a8fe49; 框架为对称轴(frame_as_axis) ← f8a8fe49; 对称补全(symmetry_completion) ← 929ab4e9; 八重对称轨道(eightfold_orbit) ← 929ab4e9; 轨道内唯一可见色(unique_color_in_orbit) ← 929ab4e9; 重涂色(recolor) ← ba97ae07

**依赖链**：内部图案跨两条红框线向外镜像展开为完整图案 → 展开后的图案应具有关于两条框架线的双轴对称性 → 但某些位置因镜像自身的不完美（输入图案本身在框架线附近有微小不一致）导致同一对称轨道内出现多种颜色 → 对每个冲突轨道做多数投票，统一为出现最多的颜色。镜像展开和轨道修复互相依赖：不展开就没有轨道冲突的概念，不修复则输出不满足对称性。

跨框架线镜像展开内部图案，对因输入不一致导致的对称轨道颜色冲突做多数投票统一。

**输入结构**：约 13x13 的网格。红(2)色像素构成两条完整的分隔线（一条水平、一条垂直），将网格分为四个象限。两条红线交于网格内某处（不必在正中心）。四个象限中只有一个象限（如左上）包含由蓝(1)和绿(3)像素在黑(0)背景上绘制的图案。其余三个象限为纯黑(0)背景。该图案象限中有 1~2 个像素是"故意错误的"——它们的颜色与通过双轴对称性应推导出的颜色不一致。生成约束：图案象限中至少有 5 个非背景像素；"故意错误"的像素被替换后（取其对称轨道中的多数色），整个四象限通过双轴镜像可得到完美对称图案；红(2)分隔线上不放置非红像素。

**规则**：
1. 识别红(2)水平线和红(2)垂直线的位置，确定四个象限。找到包含图案的象限（非背景像素最多的象限）。
2. 将图案象限的内容分别关于水平红线镜像翻转至对侧象限、关于垂直红线镜像翻转至对侧象限、关于交叉点做 180 度旋转翻转至对角象限，生成完整四象限图案（红线本身保留不变）。
3. 对完整四象限图案，定义每个非红、非背景像素的"双轴对称轨道"：包括该像素本身、关于水平红线的镜像位置、关于垂直红线的镜像位置、关于交叉点的 180 度旋转位置（最多 4 个位置，可能因位于轴上而退化）。
4. 对每个轨道，统计轨道内各非背景颜色的出现次数。若轨道内所有位置颜色一致，保持不变。若存在颜色冲突（因图案象限的"故意错误"被镜像传播），将轨道内所有位置统一为该轨道中出现次数最多的颜色。若出现次数平局（如 2 蓝 2 绿），选择颜色编号较小的（蓝(1)优先于绿(3)）。
5. 输出网格与输入同尺寸。红(2)线和黑(0)背景保持不变。

**关键洞察**：输入图案象限中的"错误像素"在镜像展开后会传播到最多三个其他位置，形成轨道冲突。修复不是简单地丢弃错误——因为求解者不知道哪个像素是"错的"，只能通过多数投票让轨道自洽。这是镜像展开（f8a8fe49）与对称补全修复（929ab4e9）的结构性耦合：一个产生冗余信息，另一个利用冗余进行纠错。
