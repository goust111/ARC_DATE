## 新题 9：互补自铺展后沿标记方向压缩

**组合逻辑**：[像素放大·自身互补铺展](创新：将小图案按互补规则展开为大网格) + [压缩](创新：沿边缘标记方向将展开结果中的前景像素压缩) + [扫过轨迹](压缩留下的空位着轨迹色)

**来源原语**：像素放大(pixel_scaling) ← 0692e18c; 互补掩码(complement_mask) ← 0692e18c; 自身互补(self_complementary) ← 0692e18c; 前景位置放置瓦片(tile_at_foreground_positions) ← 0692e18c; 压缩(compact) ← 5e6bbc0b; 边缘标记(edge_marker) ← 5e6bbc0b; 标记定压缩方向(marker_sets_dir) ← 5e6bbc0b; 扫过轨迹(swept_trail) ← 5e6bbc0b

**依赖链**：小图案的前景/背景分布决定互补瓦片的内容 → 互补铺展生成大网格（每个前景位置放互补瓦片，每个背景位置放全黑块） → 边缘标记确定压缩方向 → 大网格中所有前景像素沿该方向压缩，空出的位置着轨迹色。互补展开决定了"有什么内容"，压缩方向决定了"内容去哪里"——改变输入图案改变展开结果，改变标记位置改变压缩方向。

将小图案按互补规则展开为大网格，再沿标记方向压缩前景像素。

**输入结构**：网格由两部分组成，以灰(5)色分隔行或分隔列隔开。一侧是一个 3x3 或 4x4 的小图案区域：黑(0)背景上有蓝(1)前景像素（2~5 个前景像素）。另一侧是一个单像素黄(4)色标记，位于分隔线旁的第一行/列的某个边缘位置（靠近上/下/左/右边缘），指示压缩方向。整个网格约 10x5 或 5x10（取决于分隔方向）。生成约束：小图案的包围盒内至少有 2 个背景像素（互补掩码非空）；前景像素不全在同一行或同一列。

**规则**：
1. 读取小图案区域（NxN），确定前景蓝(1)像素位置集合 F 和背景黑(0)位置集合 B（B 即互补掩码）。
2. 构造一个 (N*N) x (N*N) 的展开网格：对小图案中的每个位置 (r,c)，在展开网格的对应 NxN 子块中——若 (r,c) 属于 F，则在该子块中，属于 B 的位置填蓝(1)、属于 F 的位置填黑(0)（即放置互补瓦片）；若 (r,c) 属于 B，则整个子块填黑(0)。
3. 根据黄(4)标记的位置确定压缩方向：标记靠近其所在区域的上边缘→向上压缩；下边缘→向下；左边缘→向左；右边缘→向右。
4. 在展开网格中，将每行（若左/右压缩）或每列（若上/下压缩）的蓝(1)像素向指定方向压缩（消除间隙，紧贴该方向的边缘）。被压缩移走的蓝(1)像素原位置着红(2)色（轨迹），未移动的蓝(1)像素和原本就是黑(0)的位置不变。
5. 输出为展开并压缩后的 (N*N) x (N*N) 网格（不包含分隔线和标记区域）。

**关键洞察**：展开规则是"在前景位置放互补掩码"（与参考题 0692e18c 相同），但展开后还叠加了方向压缩——最终图案既不是简单的互补铺展结果，也不是简单的压缩结果，而是两者的交织。需多个示例才能分离出"先互补展开、再压缩"的两步流程。
