## 新题 4：象限编码旋转角的限数印章

**组合逻辑**：[印章覆盖/分隔网格/标记像素](原有) + [旋转](创新：旋转角度由标记像素在单元格内的象限位置隐式编码，而非显式标注) + [控制条/条长](创新：控制条长度不生成序列而是限制印章总数) + [标记相对方位/方位决定象限分配](原有，但此处"方位"指标记在格内的象限而非相对于外框)

**来源原语**：印章覆盖/模板图块/分隔网格/标记像素/仅标记格被覆盖（e734a0e8）、旋转（fd4b2b02/90347967）、控制条/条长决定序列（5d588b4d）、标记相对方位/方位决定象限分配（94414823）

**依赖链**：分隔网格定义单元格 -> 标记像素的格内象限位置编码旋转角 -> 模板按该旋转角印入标记格 -> 控制条长度限制实际执行的印章总数。三类独立信息（模板内容、旋转角、数量上限）分别由不同元素编码，求解者必须全部解码。

将模板图块按标记像素在单元格内的象限位置决定的旋转角印入标记单元格，总印章数受控制条长度限制。

**输入结构**：
- 黑(0)背景，约 15x15 网格
- 灰(5)完整分隔线（贯穿整行或整列的单像素线）将网格划分为 3x3 或 4x4 的等大矩形单元格，每个单元格内部为 3x3 或 4x4 像素
- 一个单元格内包含一个红(2)非对称精灵图（模板），占据单元格内部分像素（2~5 像素），形状非中心对称使得旋转后可区分方向
- 4~6 个其他单元格各包含一个绿(3)标记像素，分别位于单元格内部的不同象限位置
- 网格第 0 行（分隔线网格上方）有一条蓝(1)控制条，从第 0 列开始，长度为 n（2 <= n < 标记单元格总数）
- 剩余单元格为空

**规则**：
1. 识别包含红(2)精灵图的单元格为模板源，提取精灵图在单元格内的相对像素偏移。
2. 对每个含绿(3)标记的单元格，将单元格内部按行列中线等分为四个象限（若内部边长为奇数，中线像素归入左上象限）。确定标记像素所在象限：
   - 左上象限 -> 旋转 0 度
   - 右上象限 -> 顺时针旋转 90 度
   - 右下象限 -> 旋转 180 度
   - 左下象限 -> 顺时针旋转 270 度
3. 按阅读顺序（从左到右、从上到下扫描单元格）排列所有标记单元格，编号 1, 2, ..., k。
4. 仅对编号 1 到 n 的标记单元格执行印章：将模板按该格对应的旋转角度旋转后，以红(2)色印入该单元格（覆盖该格内的绿(3)标记像素，保持单元格内其余背景不变）。旋转以单元格中心为旋转锚点。
5. 编号 n+1 到 k 的标记单元格：清除其绿(3)标记像素为背景(0)。
6. 模板源单元格、灰(5)分隔线、蓝(1)控制条保持不变。

**关键洞察**：标记像素的颜色统一（全为绿色），不携带信息；真正的编码在其位于单元格内哪个象限——这决定了旋转角度。控制条长度是全局约束，限制了总印章数而非影响每个印章的内容。仅看一个示例可能无法分辨"是象限编码旋转还是某种固定旋转"。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
