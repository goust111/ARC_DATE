## 新题 4：线段长度排序推断平铺周期修复遮挡

**组合逻辑**：[sorting](已有：按长度排序) -> [tiling](创新：排序结果不是用于堆叠，而是定义水平重复瓦片的颜色序列) -> [completion + infer_from_visible](创新：瓦片不是从可见像素推断，而是从独立的线段排序结果构建，用于修复遮挡区域)

**来源原语**：sorting + segment(beb8660c)、tiling + repeating_tile + completion + infer_from_visible(ca8f78db)、occluded_region(ca8f78db)

**依赖链**：线段按长度排序产生颜色序列 -> 该序列定义水平重复瓦片 -> 瓦片修复下方面板的遮挡区域。去掉排序，瓦片颜色顺序不确定；去掉瓦片构建，遮挡区域无法修复；单独看下方面板，因大面积连续遮挡无法从可见像素唯一推断瓦片。

将散布线段按长度排序得到颜色序列，以此为水平重复瓦片修复被黑色遮挡的周期图案。

**输入结构**：
- 网格约 12x18（12 行 18 列），背景黑(0)。
- 上半区（约前 5 行）：3~5 条水平单色线段散布在不同行。每条线段颜色互不相同（取自红(2)、绿(3)、黄(4)、橙(7)、品红(6)等非黑非灰颜色），长度互不相同（范围 1~5 像素）。线段的列位置任意，各线段之间不重叠。
- 一条灰(5)水平分隔行（1 像素高，跨越整个网格宽度），位于上下半区之间。
- 下半区（分隔行以下，约 6 行）：一个水平重复颜色图案，使用与上半区线段相同的颜色集合。该图案的水平周期 = 上半区线段数量。部分单元被替换为黑(0)（遮挡）。
- 生成约束：下半区中每行至少有一个完整周期长度的连续遮挡（确保无法仅从可见像素唯一推断颜色顺序）；下半区的重复图案颜色顺序恰好等于上半区线段按长度升序排列后的颜色顺序。

**规则**：
1. 提取上半区的所有水平线段，记录每条线段的颜色和长度（像素数）。
2. 按长度升序排列线段，得到颜色序列 [c1, c2, ..., cN]（c1 为最短线段的颜色，cN 为最长线段的颜色）。
3. 此颜色序列构成水平重复瓦片 T，周期为 N。
4. 在下半区中，对每个被遮挡的黑(0)单元 (r, c)，用 T[c mod N] 替换其颜色（c 为该单元在网格中的列索引，mod 运算使用 0-基索引）。
5. 下半区中原本可见的（非黑）单元保持不变。
6. 上半区和分隔行保持不变。
7. 输出为整个网格（包含上半区、分隔行和修复后的下半区）。

**关键洞察**：下半区的遮挡面积足够大，使得仅看可见像素无法唯一确定颜色排列顺序。必须利用上半区线段的长度排序来获取正确的颜色序列——线段的空间位置和颜色是干扰项，只有长度决定排列顺序。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/8/018/4.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
