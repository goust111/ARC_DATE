## 新题 3：镜像噪声度编码滑动距离

**组合逻辑**：[镜像](已有) + [逐像素比较/异或差异判定](已有) + [计数](已有) + [滑动](创新：差异格数直接编码滑动步数) —— 非线性依赖：镜像产生参考基准，比较产生差异量，差异量反馈为几何操作参数

**来源原语**：镜像/跨轴反射（#6 88207623）、逐像素比较/差异标记/异或差异判定/分隔列/面板对齐（#19 34b99a2b）、计数（#5 b91ae062, #18 ff28f65a）、滑动/擦除（#12 d255d7a7, #20 7d7772cc）

**依赖链**：左面板镜像 → 与实际右面板逐像素比较 → 计数差异格数 D → D 作为左面板所有对象的水平滑动距离 → 输出仅含滑动后的左面板

将左面板水平镜像后与实际右面板比较，差异像素数即为左面板对象的整体滑动距离。

**输入结构**：
- 约 12x10 网格（偶数宽度，如 12 列），中央有一条全高灰(5)分隔列（第 6 列，0-indexed 第 5 列），将网格分为等宽的左面板（5 列）和右面板（5 列）
- 左面板：黑(0)背景上有 2-3 个小型单色前景对象（4-连通，3-6 像素），颜色各不相同（如蓝(1)、红(2)、绿(3)），对象互不相邻，且每个对象的所有像素距分隔列至少 3 格
- 右面板：黑(0)背景上有与左面板数量相同的前景对象，颜色与左面板一一对应。每个右面板对象近似为对应左面板对象的水平镜像（以分隔列为轴），但有 1-3 个像素位置存在偏差（某些像素缺失或多出）
- 生成约束：(a) 差异格数 D（镜像后的比较不一致格数）在 1-4 范围内；(b) 左面板对象距分隔列的最小距离 > D，保证滑动后不越过分隔列也不与分隔列重叠；(c) 滑动后各对象互不重叠

**规则**：
1. 将左面板以分隔列为轴做水平镜像，生成"理想右面板"（左面板第 i 列映射为右面板第 (面板宽度-1-i) 列）
2. 将理想右面板与实际右面板逐格比较：统计所有"至少一侧为非背景色且两侧颜色不同"的格子数量，记为 D
3. 在左面板中，将每个前景对象整体向右（朝分隔列方向）平移 D 格。对象原位置擦除为黑(0)背景
4. 输出：仅保留左面板（宽度 = 左面板宽度），移除分隔列和右面板。输出网格高度不变，宽度为原左面板宽度

**关键洞察**：右面板不是答案的组成部分，而是一个带有可控噪声的参考镜像。噪声的精确程度（差异格数 D）编码了左面板对象的滑动距离——求解者必须先做镜像比较才能知道该滑多远。

<description>
Move each marked cross object away from its marker to the grid edge while rotating the colored cross 180 degrees.

Input structure:
- The background is the dominant color.
- Each 8-connected foreground object has nine pixels: a 4-pixel marker-color
  sprite attached to a 5-pixel non-marker colored cross.
- Each object bbox is either 3x6 or 6x3, so the marker sprite is on exactly
  one side of the cross.

Rule:
- Move the whole object straight away from its marker side until the object
  bbox touches the corresponding grid edge.
- Keep the marker sprite unchanged within the object.
- Rotate the 3x3 colored cross block by 180 degrees before placing it.

Key insight:
The marker sprite is a directional tail; the cross is the leading payload,
and only that payload turns around during the slide to the edge.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
