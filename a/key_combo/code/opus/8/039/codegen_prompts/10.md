## 新题 10：模板匹配补全工作区精灵后，按精灵颜色数绘制邻接标记条

**组合逻辑**：[模板匹配/template_matching] + [印章覆盖/stamp_overlay] + [部分匹配识别/partial_match_id]（创新：补全不是终点，补全后精灵的颜色多样性成为下一步的输入） → [计数/counting] + [颜色数决定高度/color_count_height] + [邻接放置/adjacent_placement]（创新：计数作用于补全后的精灵而非输入中的原始对象）

**来源原语**：模板匹配/template_matching、印章覆盖/stamp_overlay、部分匹配识别/partial_match_id、忽略干扰项/ignore_distractors、目录模板/catalog_template、工作区精灵/workspace_sprite、子精灵对齐/sub_sprite_align（3ed85e70）；计数/counting、颜色数决定高度/color_count_height、邻接放置/adjacent_placement、多色方块/multicolor_square、标记矩形/marker_rect、绘制/drawing（fcc82909）

**依赖链**：工作区精灵在补全之前是不完整的——其颜色数可能少于补全后的颜色数。颜色数决定标记条高度的规则必须作用于补全后的精灵，因此模板匹配/补全是标记条绘制的前提。反过来，如果已经知道标记条高度，也无法反推需要哪个模板——补全步骤依赖模板匹配结果，标记步骤依赖补全结果，形成严格的依赖链。

将工作区中的残缺精灵匹配到目录模板并补全，然后对每个补全后的精灵计算其不同颜色数，在其正下方绘制对应高度的绿色标记条。

**输入结构**：约 15x15 的网格。背景黑(0)。网格上部有一个非黑色连通区域作为目录背景（约占网格上方 4-5 行，使用灰(5)），目录背景上放置 2-3 个完整的多色模板精灵（每个约 3x3 至 4x4，使用 2-4 种不同的非黑、非灰颜色）。模板精灵之间互不接触，且每个模板的非灰像素颜色组合互不完全相同（至少有一种颜色不同）。网格下部的黑色工作区中有 2-3 个残缺精灵，每个是某个模板的部分可见版本——可能只露出模板的一部分行或列，或者用单一颜色的矩形遮盖了部分区域（保留了足以唯一识别来源模板的子精灵）。工作区还可能有 1 个干扰物体（不匹配任何模板部分）。每个残缺精灵的正下方有足够的空白行（至少 4 行黑色空间）用于绘制标记条。生成约束：每个残缺精灵唯一匹配一个模板；不同的残缺精灵可以匹配同一模板或不同模板。

**规则**：
1. 识别目录区域（灰(5)连通背景）和其上的完整模板精灵。
2. 对工作区中每个非黑对象，尝试将其与每个模板精灵匹配：将对象的可见像素与模板在各种平移对齐下比较，找到唯一一个模板使对象的可见部分完全吻合。无法与任何模板匹配的对象为干扰项，保持不变。
3. 对每个成功匹配的对象，在其原始位置印章覆盖完整的模板精灵（对齐方式由匹配步骤确定；模板中对应目录背景灰(5)的位置视为透明，不覆盖工作区的黑色以外的内容）。
4. 对每个补全后的精灵，统计其中不同的非黑颜色数量 C。
5. 在该精灵的边界框正下方紧邻放置一个绿(3)实心矩形，宽度等于精灵边界框的宽度，高度等于 C。
6. 干扰物体不绘制标记条。目录区域在输出中保持不变。

**关键洞察**：残缺精灵在补全前可能只展示 1-2 种颜色，补全后可能增加到 3-4 种；标记条的高度基于补全后的颜色数——求解者必须先完成模板匹配和补全，才能确定每个标记条应该多高。

<description>
Sort objects to top or bottom edge by whether their shape (up to rotation/flip) is shared.

Input structure:
- bg = most common color.
- Several multicolor connected components (8-connected) scattered across the grid.

Rule:
- Compute each object's canonical shape (binary mask, invariant to rotation and flip).
- Objects whose shape appears in two or more components → translate to TOP edge (row 0).
- Objects whose shape is unique → translate to BOTTOM edge (row H−h).
- Horizontal position (left column) is preserved; only vertical translation changes.

Key insight: The sorting criterion is shape frequency (rotation-invariant), not area — duplicated shapes go up, unique shapes go down.

  bg: most common color (varies across examples)

    area: 3-12 pixels per object

    shape: irregular (L, T, cross, etc.), single 8-connected component

    duplicated: shape occurring >=2 times → objects move to TOP (row 0)
    unique: shape occurring exactly 1 time → objects move to BOTTOM (row H-h)
    note: equal area alone does not matter; only shape equivalence matters
    constraint: must have >=1 duplicated shape group AND >=1 unique shape
  transformation:
    vertical_only: each object translated vertically; c0 preserved
    top: dest_r0 = 0
    bottom: dest_r0 = H - object_bbox_height
  output_constraints:
    no_overlap: objects must not overlap after placement at top/bottom
    sufficient_gap: grid tall enough that top objects and bottom objects don't collide

generation_strategy:
  approach: output-first, then scatter to get input
  steps:
    1. Pick H, W in [19, 30]
    2. Choose 4-6 objects; create >=1 duplicated shape group and >=1 unique shape
    3. For each template, grow a random 8-connected shape of area 3-12 within a 2-5 x 2-5 bbox
    4. Duplicate-group members are copies of a template under random rotation/flip; singleton shapes must not match any other shape up to rotation/flip
    5. Assign each object a distinct non-bg color (reuse allowed if needed for >9 objects)
    6. Place duplicated-shape objects at row 0 and unique-shape objects at row H-h in the output grid
    7. Ensure no pixel overlap among all placed objects
    8. Build input by moving each object to a random row in the interior, preserving c0
    9. Validate main(input) == output
