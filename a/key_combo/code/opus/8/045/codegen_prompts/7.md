## 新题 7：精灵体方向编码加频率定长射线

**组合逻辑**：[质心偏移定向/centroid_bias_dir + 方向精灵体/directional_sprite](已有局部方向解码) + [频率匹配/frequency_matching + 计数/counting](创新：频率不用于筛选颜色，而用于决定射线长度) + [射线延伸/ray_extend](创新：射线长度不由边界或障碍决定，而由同色标记的全局出现频率决定) + [遮挡覆盖/occlusion_overwrite](新增冲突解决层)

**来源原语**：方向精灵体(directional_sprite)/质心偏移定向(centroid_bias_dir)/标记像素(marker_pixel) ← 参考题 13f06aa5；射线延伸(ray_extend)/绘制(drawing) ← 参考题 13f06aa5/13713586；频率匹配(frequency_matching)/计数(counting) ← 参考题 2685904e；遮挡覆盖(occlusion_overwrite)/按距离排序绘制(draw_ordered_by_distance) ← 参考题 13713586

**依赖链**：精灵体几何 → 解码射线方向（局部操作） → 统计各标记颜色的全局出现次数 → 出现次数决定射线长度（全局参数驱动局部操作） → 多条射线可能交叉 → 高频颜色的射线覆盖低频颜色的射线（全局频率同时决定长度和优先级）。方向和长度来自完全不同的信息源（局部几何 vs 全局统计），且冲突解决规则也耦合到频率上。

每个方向精灵体的几何形状编码了射线方向，而射线的长度由同色标记在全网格中的出现频率决定；射线交叉时，高频颜色覆盖低频颜色。

**输入结构**：约 15x15 的网格。黑(0)背景。灰(5)像素形成 4~6 个小型 8-连通方向精灵体（每个约 7 像素），散布在网格中。每个精灵体内嵌入一个单像素标记，标记颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取。同一颜色的标记可以出现在多个精灵体中（例如 2 个精灵体含红标记、3 个含蓝标记等）。每个精灵体的灰像素相对于标记的分布不对称：灰像素的质心偏向标记的某一侧，该偏向方向的反方向即为射线的发射方向（上、下、左或右四个正方向之一）。生成约束：不同颜色的标记出现次数互不相同（例如红出现 2 次、蓝 3 次），且至少存在两条射线在延伸后路径有交叉。

**规则**：
1. 对每个精灵体，计算其灰(5)像素相对于标记像素的质心偏移方向。射线方向为质心偏移的反方向（即灰像素集中在标记的左侧 → 射线向右发射；集中在上方 → 射线向下发射；等等）。取四个正方向中与质心偏移反方向最接近的那个。
2. 统计每种标记颜色在所有精灵体中出现的总次数 → 频率 F(颜色)。
3. 从每个标记像素出发，沿其射线方向绘制一条射线。射线长度（不含标记本身）= F(该标记颜色) 个像素。射线使用标记的颜色绘制。若射线延伸过程中超出网格边界，则超出部分不绘制。
4. 若两条不同颜色的射线经过同一像素，则该像素颜色取频率更高的那个标记颜色（F 值大者覆盖 F 值小者）。若频率相同（生成约束已排除此情况），则取标记在网格中位置靠上（行号小）的那条。
5. 灰(5)精灵体本身保持不变。标记像素保持原色。射线不覆盖灰像素（射线像素若落在灰像素上则跳过该位置，继续向前计数直到画满 F 个非灰像素或超出边界）。

**关键洞察**：射线方向是每个精灵体的局部几何属性（质心偏移），而射线长度是一个全局统计属性（同色标记的总出现次数）。单看一个精灵体无法确定射线长度——必须扫描全网格统计同色标记的数量。同时，频率不仅决定长度还决定冲突优先级，使得出现次数多的颜色既画得更长又在交叉处胜出。
