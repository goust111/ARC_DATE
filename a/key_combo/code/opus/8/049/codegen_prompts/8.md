## 新题 8：边界图例编码重力方向与空心框沉积

**组合逻辑**：[编码映射](边界图例的方向编码) → [重力下落 + 碰撞停止](可移动像素按编码方向滑入对应框) → [填充 + 计数](框内沉积像素数决定内部填充色)

**来源原语**：边界图例(border_legend, #8 88e364bc), 编码映射(encoding_map, #8), 颜色关联区域(color_links_to_region, #8), 重力下落(gravity_drop, #8), 碰撞停止(collision_stop, #8), 空心矩形(hollow_rectangle, #10 d5d6de2d), 填充(fill, #10), 计数(counting, #3 b7999b51), 空心内部变色(interior_recolor, #10)

**依赖链**：边界图例编码每个框的重力方向（将方向信息从输入的空间结构中解码出来），重力方向决定像素如何进入框内并堆积，堆积的像素数量再触发一个颜色映射决策。三步形成信息解码→物理模拟→统计决策的紧耦合链。

边界小方块编码每个空心框的重力方向，散落的像素按对应方向滑入框内堆积，框内像素沉积数量决定框的内部背景填充颜色。

**输入结构**：黑(0)背景网格，约 14x14 至 18x18。网格中有 2~4 个空心矩形框（边框颜色各不相同，从蓝(1)、绿(3)、橙(7)、栗(9)中选取，边框单像素宽，内部为黑(0)），每个框尺寸约 4x4 至 6x6。框的四条边中有一条边有一个单像素宽缺口（"入口"）。网格边缘（紧贴上/下/左/右边界）有与框同数量的 3x3 小方块图例，每个图例的填充色与某个框的边框色相同。每个图例的中心像素为灰(5)，另有一个相邻像素也是灰(5)（上/下/左/右之一），其余为图例填充色。中心到该相邻灰像素的方向编码了重力方向。网格中还散布若干黄(4)可移动像素（共 4~10 个），分布在各框外部。

**规则**：
1. 对每个空心框，找到边框色相同的边界图例。读取图例中灰(5)中心像素到灰(5)相邻像素的方向（上/下/左/右），该方向即为此框的"重力方向"。
2. 所有黄(4)像素沿各自最近框的重力方向滑动。"最近框"由黄像素到各框边框的曼哈顿距离最小值确定（距离相等时选边框色编号较小的框）。
3. 黄像素滑入所属框的缺口后，继续沿重力方向滑动直到碰到框的对面内壁或已堆积的黄像素，然后停止。不对准缺口的黄像素无法进入框内，直接删除。
4. 滑动完成后，统计每个框内部的黄(4)像素数量 n：
   - n = 0 → 框内部保持黑(0)。
   - n = 1~2 → 框内部未被黄像素占据的格子填充绿(3)。
   - n = 3~4 → 填充红(2)。
   - n >= 5 → 填充品红(6)。
5. 黄(4)像素保留在其最终堆积位置（不被填充色覆盖）。
6. 框边框、图例和其余背景保持不变。

**关键洞察**：重力方向不是全局统一的——每个框有自己的方向，由其对应图例编码。需要对比多个示例才能发现框内填充色与沉积像素数量的映射关系（而非与框的颜色或大小有关）。
