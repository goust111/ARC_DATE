## 新题 2：滑动投票决定最短路径终端

**组合逻辑**：[滑动 + 同色配对](孤立像素滑向同色方块) → [无匹配色则删除](清除无目标像素) → [最短路径](以接收到像素的方块为终端求最短路径) → [重涂色](路径着色)

**来源原语**：滑动(sliding, #7 1a07d186), 同色配对(same_color_pairing, #7), 无匹配色则删除(unmatched_deleted, #7), 最短路径(shortest_path, #5 7b0280bc), 图结构(graph_structure, #5), 节点方块(node_square, #5), 轨道段(track_segment, #5), 重涂色(recolor, #5)

**依赖链**：滑动操作将孤立像素移入图节点，决定了哪两个节点成为终端；终端身份是最短路径操作的前提。删除滑动步骤则终端未知，删除路径步骤则滑动结果无用途。

散落的彩色像素沿直线滑向同色方块节点，恰好有两个方块接收到像素成为终端，在方块-轨道构成的图中求这两个终端之间的最短路径并着色。

**输入结构**：黑(0)背景网格，约 15x15 至 20x20。网格中有 4~6 个单色实心方块（每个方块为 2x2 或 3x3，颜色各不相同，从红(2)、蓝(1)、黄(4)、品红(6)、橙(7)中选取）。方块之间有灰(5)的单像素宽轨道段相连，形成一个连通图（每条轨道沿水平或垂直直线连接两个方块的最近边缘）。在方块和轨道之外，散布 2~5 个孤立像素，其中恰好 2 个像素的颜色分别与某个方块匹配，其余像素颜色不与任何方块匹配。每个有匹配的像素与其目标方块在同一行或同一列上，且该方向上无障碍。

**规则**：
1. 对每个孤立像素，检查是否存在颜色相同的方块。若存在，该像素沿与目标方块共享的行或列方向滑动，直到与目标方块的边缘相邻（4-邻接），然后停止并消失（被方块"吸收"）。
2. 颜色不与任何方块匹配的孤立像素直接删除（变为黑(0)）。
3. 恰好有两个方块各吸收了一个像素，这两个方块成为终端节点。
4. 在方块-轨道图中，用广度优先搜索找到两个终端之间的最短路径（经过最少的轨道段）。
5. 路径上的非终端方块重涂为绿(3)，路径上的轨道段重涂为青(8)。终端方块保持原色。
6. 不在路径上的方块和轨道保持原色/原灰色不变。

**关键洞察**：终端节点不是预先标记的，而是由滑动结果动态决定——需要对比多个示例才能发现"吸收了像素的方块"才是终端，而非其他空间属性（如边缘位置或方块大小）。
