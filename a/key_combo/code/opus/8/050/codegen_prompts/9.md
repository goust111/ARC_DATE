## 新题 9：锚点复制受标签面积筛选并裁剪

**组合逻辑**：[面积比较/area_comparison → 多像素涂色留单/multi_recolor_single](已有，创新用法：面积判断用于筛选哪些目标接受复制) → [平移复制/translate_and_copy + 锚点对齐/anchor_alignment](已有) → [重涂色/recolor](已有，创新用法：标签颜色决定副本色) → [裁剪/crop + 背景替换/background_within_crop_replaced](已有)

**来源原语**：平移复制/translate_and_copy、锚点对齐/anchor_alignment、多色精灵体/multicolor_sprite、源锚点/source_anchor_marker、目标锚点/target_anchor_marker、锚点偏移对应/anchor_offset_correspondence（来自 2c737e39）；重涂色/recolor、连通分量/connected_component、孤立像素/isolated_pixel、面积比较/area_comparison、多像素涂色留单/multi_recolor_single（来自 67385a82）；裁剪/crop、前景掩模/foreground_mask、边界框包围/bounding_box_enclosure、裁剪区背景替换/background_within_crop_replaced（来自 a740d043）

**依赖链**：标签面积 → 筛选哪些目标锚点激活（面积>1 才激活） → 激活的目标接受精灵体副本 → 标签颜色决定副本重涂色 → 所有副本和原始精灵体的总包围框 → 裁剪输出。删除面积筛选则所有目标都激活（输出错误）；删除锚点对齐则副本位置不确定；删除裁剪则输出尺寸不确定。

将多色精灵体复制到每个通过面积筛选的目标锚点处，副本颜色取自该目标旁的标签对象颜色，最后裁剪到所有前景的紧致包围框。

**输入结构**：一个约 15x15 的网格，黑(0)背景。网格中有一个多色 4-连通源精灵体（5~8 像素），其中恰好一个灰(5)像素为源锚点，其余像素为 2~3 种非黑非灰颜色。网格中散布 3~5 个孤立灰(5)像素作为目标锚点，互不相邻。每个目标锚点的 8-邻域内有一个"标签"对象：一个单色 4-连通小图形（1~4 像素，颜色取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)），标签对象与目标锚点 8-连通相邻但不包含锚点本身。不同目标的标签颜色可以相同也可以不同，面积可以相同也可以不同。生成约束：至少一个标签面积为 1（即单像素，不会触发复制）、至少两个标签面积大于 1；精灵体副本在各激活目标处互不重叠且不超出网格边界。

**规则**：
1. 对每个目标灰(5)锚点像素，检查其 8-邻域中的标签对象面积。若标签面积 > 1，该目标为"激活"状态；若标签面积 = 1（孤立单像素），该目标为"未激活"状态。
2. 对每个未激活目标：擦除其灰(5)锚点像素（恢复为背景），保留其单像素标签不变。
3. 对每个激活目标：将源精灵体平移复制到此处，使源锚点对齐到目标锚点位置。副本中所有非灰像素统一重涂为该目标的标签对象颜色。灰(5)锚点像素在副本中也涂为标签色。擦除目标锚点和标签对象原始位置（标签位置可能被副本覆盖，若未覆盖则恢复为背景）。
4. 原始源精灵体保留在原位不变。
5. 裁剪输出到所有非黑像素的最小包围矩形。包围矩形内部的黑(0)像素保留为黑(0)。

**关键洞察**：标签对象身兼两职——其面积决定目标是否被激活（筛选），其颜色决定副本的涂色（着色）。单像素标签既"面积不足以激活复制"又"保留在输出中作为残留标记"。需要对比含有不同标签面积配置的示例才能发现面积阈值（>1 才激活）和颜色传递规则。

<description>
Slide multi-color sprites to align their marker pixels with matching isolated border anchors.

Input structure:
- bg = most common color.
- Multi-color sprites in the interior; each has a minority-color "marker" pixel.
- Isolated border pixels (non-bg with all 4-neighbors bg) act as anchors.

Rule:
- Match each sprite to the border anchor sharing its marker color.
- Top/bottom-edge anchor (non-corner): slide sprite horizontally so marker column = anchor column.
- Left/right-edge anchor (or corner): slide sprite vertically so marker row = anchor row.

Key insight: The anchor's edge position determines the slide axis — top/bottom means horizontal, left/right (or corner) means vertical.
</description>
