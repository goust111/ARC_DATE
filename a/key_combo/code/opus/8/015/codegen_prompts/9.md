## 新题 9：引导掩码裁剪后用作印章模板

**组合逻辑**：[裁剪/crop](已有) + [唯一被框选对象/uniquely_enclosed](已有) → [印章覆盖/stamp](创新：裁剪出的精灵体同时充当印章内容和位置掩码) + [高频色位定印章/frequent_positions_set_stamps](已有)

**来源原语**：裁剪(crop)、空心精灵体(hollow_sprite)、引导掩码(guide_mask)、包围框包含(bbox_containment)、唯一被框选对象(uniquely_enclosed) ← 参考题 bf699163；印章覆盖(stamp)、高频色位定印章(frequent_positions_set_stamps)、阵列排布(array_layout) ← 参考题 c3e719e8

**依赖链**：引导掩码选择裁剪哪个精灵体（从多个候选中选一个）；裁剪结果是一个 3x3 图案；该图案的颜色频率分布决定最高频色，从而决定印章放置位置；同一图案又作为印章内容被复制。选择不同的精灵体会导致不同的颜色频率→不同的印章布局→完全不同的输出。

用引导掩码从多个精灵体中选出一个裁剪为 3x3 模板，然后按该模板中最高频色的位置在 9x9 网格中重复印章。

**输入结构**：约 14x14 黑(0)背景网格。3~4 个多色 3x3 精灵体（每个精灵体的 9 个格全为非黑色，使用 2~3 种前景色），分散在网格中，彼此间距至少 2 格。另有一组灰(5)散布像素构成引导掩码，这些灰像素不属于任何精灵体。引导掩码的包围框恰好完全包含其中一个精灵体，且不完全包含其他任何精灵体。生成约束：每个精灵体中恰好一种颜色出现次数严格最多；不同精灵体的最高频色位置分布互不相同（保证选择不同精灵体会产生不同印章布局）；引导掩码像素不与被选精灵体的像素重叠。

**规则**：
1. 识别所有 3x3 精灵体：在网格中找到所有 3x3 区域且其 9 个格全为非黑色的前景对象。
2. 构建引导掩码：收集所有不属于任何精灵体的灰(5)像素。
3. 计算引导掩码的包围框，找到该包围框内唯一完全被包含的精灵体。裁剪该精灵体得到 3x3 图案。
4. 在裁剪出的 3x3 图案中找出出现次数严格最多的颜色 C。
5. 输出为 9x9 黑(0)网格，划分为 3x3 的块槽。图案中颜色 C 所在的每个位置（在 3x3 中的行列坐标），对应的块槽填入裁剪出的完整 3x3 图案副本；其余块槽保持黑色。

**关键洞察**：引导掩码不选择颜色或印章位置——它只选择哪个精灵体成为模板；而被选模板自身的颜色频率分布同时决定了印章内容和印章布局。一次选择产生两个后果（内容 + 布局），且两个后果来自同一个对象的不同属性（几何形状 vs 颜色分布），这使得问题不可分解为独立子问题。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/8/015/9.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
