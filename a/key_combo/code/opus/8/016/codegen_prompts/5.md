## 新题 5：模板旋转诊断转化为滑动方向指令

**组合逻辑**：[旋转/rotate + 模板匹配/template_match](分析每个碎片相对模板的旋转角度) → [滑动/sliding](将旋转角度重新诠释为滑动方向) + [印章覆盖/stamp](在终点位置印上碎片) — 几何分析的结果被重新语义化为运动指令

**来源原语**：旋转/rotate(6aa20dc0), 模板匹配/template_match(6aa20dc0), 印章覆盖/stamp(6aa20dc0), 滑动/sliding(05f2a901), 模板/template(6aa20dc0), 碎片/fragment(6aa20dc0), 锚点方块/anchor_square(05f2a901), 碰撞阻挡/collision_blocking(05f2a901), 缩放旋转对齐碎片/scale_rotate_align_frag(6aa20dc0), 最短接触平移/minimal_contact_shift(05f2a901)

**依赖链**：模板形状 → 碎片旋转角度诊断 → 角度映射为方向 → 碎片沿该方向滑动 → 碰撞检测决定终点。旋转分析和滑动方向之间的映射是隐蔽规则：角度本身不被"执行"为旋转，而被"翻译"为平移方向。

识别每个散落碎片相对于模板的旋转角度，将该角度转化为滑动方向（0度向右、90度向下、180度向左、270度向上），碎片沿该方向滑动至接触锚点或已停靠碎片。

**输入结构**：约 20x20 的网格，黑(0)背景。网格中有一个多色模板对象（3x3 至 4x4 像素，使用最多种颜色的对象，至少 3 种非背景色）。3-4 个散落碎片，每个是模板形状经某个旋转（0/90/180/270 度顺时针）后的单色副本（保留模板的像素连通结构但不保留配色，仅用 1 种非背景色着色，各碎片颜色不同）。一个青(8) 2x2 锚点方块位于网格中部偏某方向。生成约束：每个碎片的旋转角度各不相同（4 个碎片则恰好覆盖 0/90/180/270）；每个碎片沿其映射方向滑动时路径上无障碍（不会穿过其他碎片的初始位置或模板）；各碎片的滑动路径互不冲突。

**规则**：
1. 识别模板：网格中使用最多种不同颜色的对象即为模板。
2. 对每个非模板、非锚点的碎片，确定需要将模板顺时针旋转多少度（0/90/180/270）才能使模板的像素形状与该碎片的像素形状完全重合。此角度记为 R。
3. 将 R 映射为滑动方向：R=0 向右，R=90 向下，R=180 向左，R=270 向上。
4. 按滑动距离从短到长的顺序处理碎片（滑动距离 = 碎片沿该方向移动到首次与锚点或已停靠碎片产生 4-邻接接触时的像素数）。若距离相同，按碎片边界框左上角从左到右、从上到下的顺序。
5. 将碎片平移到终点位置（保持原形状和颜色不变，不执行旋转），擦除其原始位置的像素。模板保持原位不变。

**关键洞察**：旋转角度不是用来"纠正"碎片朝向的——碎片在输出中保持其旋转后的形状不变。角度被重新诠释为运动方向：一个"倒置"的碎片（180度）不会被翻正，而是被推向左方。这种分析结果到运动指令的语义跳跃是最难归纳的规则，需对比多个方向的示例才能确认映射关系。
