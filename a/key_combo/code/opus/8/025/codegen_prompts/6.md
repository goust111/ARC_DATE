## 新题 6：旋转匹配驱动的方向性模板印章

**组合逻辑**：[印章覆盖/stamp_overlay](原有) + [旋转/rotate](作为匹配键而非直接变换，创新后) + [重涂色/recolor](行调色板着色，原有)。创新点在于**每个单元格中的小标记形状本身就是模板的某个旋转/镜像版本的部分投影，识别出变换类型后以该变换盖印完整模板**

**来源原语**：
- 印章覆盖(stamp_overlay), 分隔网格(divider_grid), 模板掩码(template_mask), 行标记(row_marker), 行调色板(row_palette) ← 5a5a2103
- 旋转(rotate), 查表替换(lookup_replace), 形状标记(shape_marker), 颜色与形状对应(color_shape_match), 旋转镜像等价匹配(rotation_reflection_match) ← b20f7c8b

**依赖链**：模板定义基准形状→每个单元格的灰色标记与模板的某个变换匹配→匹配确定该单元格的印章朝向→行调色板确定颜色→按对应朝向和颜色盖印。删除旋转匹配则不知道朝向；删除行调色板则不知道颜色；删除模板则无法识别标记含义

在分隔网格的每个单元格中，将灰色方向标记替换为完整模板的对应旋转/镜像版本，颜色取自该行调色板。

**输入结构**：
- 约 19x19 的网格，栗(9)分隔条将网格分为 3x3 共 9 个等大单元格（每个单元格内部约 5x5），分隔条宽 1 像素
- 左上角单元格（第 0 行第 0 列）包含红(2)模板图案：5x5 范围内的 4-连通不对称形状（5~8 像素），该形状在 8 种刚性变换（4 种旋转 x 2 种镜像）下互不相同
- 第 0 列其余单元格（第 1 行第 0 列、第 2 行第 0 列）各包含一个单色标记像素（位于单元格中心），颜色互不相同且不为红(2)、栗(9)、黑(0)、灰(5)（如蓝(1)和绿(3)），标记该行的输出颜色；第 0 行的输出颜色为红(2)（来自模板自身颜色）
- 其余 6 个单元格（第 0~2 行的第 1~2 列）各包含一组灰(5)微型标记像素（2~3 个像素），这些像素的相对位置是模板图案在某个刚性变换下的关键像素子集（足以在 8 种变换中唯一确定是哪一种）
- 所有单元格背景为黑(0)
- 生成约束：6 个灰色标记对应的 6 种变换互不相同（从 8 种中选 6 种）

**规则**：
1. 从左上角单元格读取红(2)模板图案，记录其像素的相对坐标集合 S
2. 枚举模板的 8 种刚性变换（0/90/180/270 度旋转，各搭配是否水平镜像），得到 8 个变换后坐标集合 {T_i(S)}
3. 对每个非左列单元格，提取其内部灰(5)像素的相对坐标集合 M，在 {T_i(S)} 中找到唯一的 T_k 使得 M 是 T_k(S) 的子集且此子集在 8 种变换中唯一对应 T_k
4. 读取该单元格所在行的输出颜色 C：第 0 行为红(2)，第 1、2 行从对应左列标记读取
5. 清空该单元格内部为黑(0)，以变换 T_k 将完整模板图案盖印到该单元格中心对齐位置，颜色为 C
6. 左上角单元格保持原样（红色模板不变）；左列标记单元格保持原样
7. 栗(9)分隔条保持不变

**关键洞察**：灰色像素看起来像随机散点，但实际是模板在不同刚性变换下的关键像素投影——必须先从左上角学习模板形状、穷举变换、再逐一子集匹配，才能确定每个单元格应印制的朝向；行调色板确定颜色是另一个独立维度
