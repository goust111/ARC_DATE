## 新题 2：半幅同心方阵的对称补全与轴向定向生长

**组合逻辑**：[对称补全](创新：作用于半截同心方阵，而非带遮挡的场景) + [生长](创新：生长方向由对称轴决定，而非固定四向) + [重涂色](创新：生长使用中心标记像素的颜色，而非最外层颜色)

**来源原语**：对称补全/symmetry_completion、镜像对称/mirror_symmetry、反射恢复遮挡/reflection_recovers（参考题 dc0a314f、8e5c0c38）；生长/grow、同心正方形层/concentric_layer、内外层交换/inner_outer_swap（参考题 3befdf3e）；标记像素/marker_pixel（参考题 760b3cac）

**依赖链**：对称轴的检测决定补全方向（左右镜像或上下镜像），同时该轴还决定生长方向（垂直于对称轴）。补全必须先于生长（否则外层边界不完整无法确定生长起点）。生长颜色由中心标记像素提供，而非由外层颜色推断——三者环环相扣。

将半截同心方阵沿其对称轴镜像补全，再沿垂直于该轴的方向以中心标记色向外生长一层。

**输入结构**：约 15x15 黑(0) 背景网格。包含 2~3 个互不接触的半截同心方阵。每个方阵仅显示左半部分或上半部分（沿一条垂直或水平对称轴精确切开），可见部分包含 2~3 层同心正方形环（最外层为某色的单像素宽边框，内层为另一色的实心块，例如外层红(2)、内层蓝(1)）。每个方阵的几何中心处有一个独特颜色的单像素标记（如绿(3)），该颜色不出现在任何环层中。不同方阵的中心标记颜色可以相同也可以不同。不同方阵的对称轴方向可以不同（有的是垂直轴切割露出左半，有的是水平轴切割露出上半）。生成约束：每个半截方阵周围至少有 2 像素的空黑区域用于生长；各方阵的边界框互不重叠。

**规则**：
1. 对每个半截同心方阵，检测其对称轴方向：尝试沿垂直轴和水平轴分别镜像，选择能生成合法同心方阵结构（所有层均为完整闭合矩形环）的那个轴。
2. 沿确定的对称轴镜像可见半部分，补全为完整的同心方阵。
3. 补全后，沿**垂直于对称轴**的方向向外生长一层像素：若对称轴为垂直方向，则在方阵的左侧和右侧各扩展一列像素；若为水平方向，则在上侧和下侧各扩展一行像素。
4. 生长的新像素使用中心标记像素的颜色（不是最外层环的颜色）。生长仅填充黑(0) 背景像素，不覆盖任何已有颜色。
5. 中心标记像素在输出中保持不变。

**关键洞察**：对称轴不仅决定"怎么补"，还决定"往哪里长"——一个几何属性同时控制两步操作的行为，使得对称轴的正确识别成为整道题的关键瓶颈。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
