## 新题 8：框架内模板定义外部精灵归属与点数表示

**组合逻辑**：[模板匹配/template_matching + 含旋转反射/includes_rotation_reflection](创新：模板不是独立给出的参考图案，而是嵌入在框架内部，同时充当视觉元素和分类键) → [计数/counting + 同色匹配/same_color_matching](双重匹配条件：颜色一致且形状一致) → [绘点/draw_dots](计数结果可视化) → [擦除/erase]

**来源原语**：模板匹配 template_matching + 含旋转反射变换 includes_rotation_reflection + 形状匹配 shape_matching + 非重叠放置 non_overlapping_placement (50f325b5), 空心框架 hollow_frame + 计数 counting + 绘点 draw_dots + 同色匹配 same_color_matching + 计数映射点数 count_maps_to_dots + 擦除 erase + 图案精灵体 pattern_sprite (8f215267)

**依赖链**：框架内部的灰色模板是分类键——它决定哪些外部精灵"属于"该框架（必须同时满足颜色匹配和形状匹配）；匹配数量决定框架内绘制的点数；绘点前必须擦除模板和外部精灵。三者缺一不可：没有模板则无法分类，没有计数则无法确定点数，没有擦除则模板干扰点的放置。

框架内嵌的小型灰色模板作为"钥匙"，匹配外部同色且同形的精灵体，匹配数以点的形式显示在框架内。

**输入结构**：
- 约 18x18 网格，黑(0) 背景。
- 2-4 个空心矩形框架，每个框架由单一颜色的 1 像素宽边框构成，内部为黑(0)。框架颜色各不相同，从 {红(2), 蓝(1), 绿(3), 橙(7)} 中选取。每个框架外部尺寸至少 5x5。
- 每个框架的内部左上角区域放置一个小型灰(5) 模板图案（2-3 个 4-连通像素，形状因框架而异，如 L 形、直线、对角线等结构性描述——不同示例中具体形状不同）。
- 框架外部散布着若干小型单色 4-连通精灵体（每个 2-4 像素）。每个精灵体的颜色等于某个框架的颜色。
- 生成约束：每个外部精灵的形状（归一化到包围框的二值掩码）在所有旋转和反射变体下，恰好匹配且仅匹配一个框架的内部灰色模板。每个模板至少被 1 个同色外部精灵匹配。

**规则**：
1. 提取每个框架内部的灰(5) 模板：裁剪为包围框内的二值掩码。
2. 对每个外部精灵体，检查其是否与某框架关联：
   a. 颜色条件：精灵体颜色必须等于框架边框颜色。
   b. 形状条件：将精灵体裁剪至包围框的二值掩码，与该框架内部模板的掩码进行比较，允许 8 种变体（0/90/180/270 度旋转 x 是否水平翻转）。任一变体匹配即通过。
   c. 颜色和形状均满足时，该精灵体归属于该框架。
3. 对每个框架，统计归属于它的外部精灵体数量 N。
4. 擦除所有外部精灵体（设为黑(0)）。
5. 擦除每个框架内部的灰(5) 模板（设为黑(0)）。
6. 在每个框架的内部，沿水平中心行（内部区域行数的中间行，若为偶数取上方的一行）绘制 N 个点：使用该框架的边框颜色，从内部最右列开始向左放置，相邻点之间间隔 1 个黑(0) 像素（即每隔一列放一个点）。若 N = 0，内部保持全黑。
7. 框架边框保持不变。

**关键洞察**：仅凭颜色匹配会产生错误计数——每个框架内隐藏的灰色模板才是真正的分类依据。精灵体必须同时满足颜色和旋转/反射形状匹配才被归类，单独检查任一条件都不充分。模板在框架内部的位置使其看起来像装饰元素，但它实际上编码了匹配规则。
