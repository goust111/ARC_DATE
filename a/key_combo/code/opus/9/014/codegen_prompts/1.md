## 新题 1：分区迷宫转弯计数压缩

**组合逻辑**：[路径追踪 + 碰撞转向](从块内局部路径追踪) → [计数](统计每块内路径转弯次数) → [压缩 + 重涂色](转弯数映射为颜色，压缩为小网格)

**来源原语**：路径追踪/碰撞转向(2dd70a9a, 6bcdb01e)、压缩/分区采样(5783df64)、计数(42a15761)、重涂色(e509e548)

**依赖链**：路径追踪产出每个分区内的路径形态 → 转弯计数从路径形态中提取几何复杂度 → 复杂度映射为颜色并压缩为输出。删除路径追踪则无法得到转弯数；删除计数则无法确定颜色；删除压缩则输出形式不成立。

根据分区内障碍像素追踪局部路径，以路径转弯次数为颜色编码，将整个分区网格压缩为一幅小色块图。

**输入结构**：约 21x21 的网格，被灰(5)单像素宽的水平线和垂直线均匀分割为 3x3 共 9 个 6x6 的块（灰线占去中间行列）。每个块内部：黑(0)为通道背景，散布若干青(8)障碍像素（每块 2~5 个），块的左侧边缘某行有一个绿(3)像素作为入口，块的右侧边缘某行有一个红(2)像素作为出口。生成约束：每个块内从绿入口到红出口存在唯一的无回头路径（障碍的摆放保证路径唯一且不分叉）；不同块的转弯次数互不相同，范围在 0~4 之间。

**规则**：
1. 对每个 6x6 块，从绿(3)入口出发向右行进。遇到青(8)障碍时，转向唯一可通行的垂直方向继续前进；再次遇到障碍时转回水平方向，以此类推。到达红(2)出口时路径结束。
2. 记录每个块内路径的转弯次数（方向改变的次数，0 表示直线通过）。
3. 将 3x3 分区压缩为 3x3 输出网格。每个输出像素的颜色由对应块的转弯次数决定：0 次 → 蓝(1)，1 次 → 黄(4)，2 次 → 橙(7)，3 次 → 栗(9)，4 次 → 品红(6)。
4. 灰分隔线不出现在输出中。

**关键洞察**：障碍像素的空间分布隐式编码了一个数字（转弯次数），必须完整追踪路径才能解码；仅看单个示例无法确定转弯次数与颜色的映射关系，需要对比多个示例中的不同块才能归纳映射表。

    macro_grid: 2-3 rows x 3-6 cols; teal cells 25-50% of total
    role: coarse stencil selecting which output blocks get the stamp
  canvas:
    shape: (macro_h * stamp_h) x (macro_w * stamp_w) -- solid main_color rectangle
    role: defines output dimensions; must tile exactly by control size
  layout: |
    control and pattern share same top row, separated by 1 col of bg
    canvas is below both, separated by 1 row of bg
    all three embedded in the grid with bg border (>=1 cell on each side)
  output: canvas-sized grid; main_color everywhere except teal stamp pasted at each teal macro-cell position (RED pixels in stamp become main_color)

generation_strategy:
  approach: output-first
  steps:
    1. Pick main_color from non-reserved palette; pick stamp_size in {3, 4}
    2. Create stamp (stamp_size x stamp_size) of RED and TEAL pixels; ensure teal fraction 40-60%
    3. Pick macro_grid dims macro_h in [2,3], macro_w in [3,6]
    4. Build selector (macro_h x macro_w boolean); set 25-50% cells to teal
    5. Build output: (macro_h*stamp_size) x (macro_w*stamp_size) filled with main_color; paste teal-masked stamp at each teal selector position
    6. Pick cell_size in {1, 2}; build pattern (macro_h*cell_size x macro_w*cell_size) where each cell block is uniform TEAL or main_color per selector
    7. Build canvas as solid main_color rectangle matching output dims
    8. Assemble input grid: place control at ~(1,1), pattern 1 col to its right (same top row), canvas below both with 1-row gap, pad with BLACK border

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
