## 新题 2：图例串编程螺旋着色

**组合逻辑**：[边缘图例串/edge_legend_string](创新：从位置模板改为颜色程序序列) + [螺旋绘制/spiral_draw](已有) + [颜色位置匹配/color_position_matching](创新：匹配从"锚定"改为"循环索引") + [遇障碍停止/stop_at_blocker](已有)

**来源原语**：边缘图例串、颜色位置匹配 ← 5af49b42；螺旋绘制、遇障碍停止 ← e5c44e8f；种子像素 ← e5c44e8f

**依赖链**：图例串的颜色顺序决定了螺旋每一步的着色 → 螺旋的几何路径决定哪些位置被涂上图例中的哪种颜色 → 障碍像素截断螺旋，决定着色终止点。图例内容、螺旋轨迹、障碍位置三者共同决定输出图案，缺一不可。

用边缘图例串作为颜色程序，沿螺旋路径循环涂色，遇障碍停止。

**输入结构**：约 13×13 的黑(0)背景网格。顶行（第 0 行）从最左列开始有一段水平图例串，由 3~5 个紧邻的不同颜色像素组成（如 红(2)-蓝(1)-绿(3)-黄(4)），图例串右侧至行末为黑(0)。网格内部（非顶行）有一个品红(6)种子像素。另有 1~2 个灰(5)障碍像素。种子像素与图例串颜色均不同，障碍像素与图例串颜色均不同。生成约束：种子像素距最近障碍至少 4 步螺旋距离（保证至少绘制一圈以上的有效螺旋）；图例串长度在不同示例中可不同（用以验证求解者能归纳循环规则而非记忆固定序列）。

**规则**：
1. 识别顶行的水平图例串：从第 0 行最左列起，连续读取非黑(0)像素，直到遇到黑(0)或行末。记录颜色序列 C = [c_0, c_1, ..., c_{k-1}]，共 k 种颜色。
2. 从品红(6)种子像素出发，按方向序列"上→右→下→左"循环，步长序列 2, 2, 4, 4, 6, 6, ...，逐步追踪螺旋路径。维护一个全局步数计数器 i（从 0 开始）。
3. 对螺旋路径上的每一步：
   - 若该位置超出网格边界，跳过该步但 i 仍递增。
   - 若该位置是灰(5)障碍像素，在涂色前停止，螺旋终止。
   - 若该位置在网格内且不是障碍，将其涂为 C[i mod k]（图例序列的第 i mod k 个颜色），i 递增。
4. 种子像素本身保留品红(6)不变（不被螺旋覆盖）。图例串和障碍像素在输出中保持不变。
5. 所有未被螺旋涂色的黑(0)位置保持黑(0)。

**关键洞察**：图例串不是用于空间展开的模板，而是螺旋着色的"程序指令"——其颜色顺序被循环索引为每一步的涂色参数。同一图例串在不同种子位置或不同障碍布局下会产生完全不同的视觉图案，因为步数计数器 i 跟随螺旋的实际绘制进程（含越界跳过），不同示例中的 i 推进节奏不同。求解者必须同时理解螺旋几何和循环颜色映射才能还原规则。

<description>
Sort objects to top or bottom edge by whether their shape (up to rotation/flip) is shared.

Input structure:
- bg = most common color.
- Several multicolor connected components (8-connected) scattered across the grid.

Rule:
- Compute each object's canonical shape (binary mask, invariant to rotation and flip).
- Objects whose shape appears in two or more components → translate to TOP edge (row 0).
- Objects whose shape is unique → translate to BOTTOM edge (row H−h).
- Horizontal position (left column) is preserved; only vertical translation changes.

Key insight: The sorting criterion is shape frequency (rotation-invariant), not area — duplicated shapes go up, unique shapes go down.

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
