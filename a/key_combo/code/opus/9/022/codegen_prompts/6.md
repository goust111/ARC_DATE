## 新题 6：投票恢复精灵体后按颜色锚定展开至标记位置

**组合逻辑**：[投票恢复/majority_vote_recovery](已有) + [展开/expand](创新：展开锚点由颜色匹配决定而非几何对齐) + [颜色位置匹配/color_position_matching](创新：在恢复后的精灵体内匹配而非在图例串中匹配) + [擦除/erase](已有)

**来源原语**：投票恢复、精灵体、插槽阵列、忽略干扰项 ← 0607ce86；展开、颜色位置匹配 ← 5af49b42；孤立标记 ← 5af49b42；擦除 ← 1a07d186

**依赖链**：插槽阵列提供精灵体的多个损坏副本 → 投票恢复得到干净精灵体 → 干净精灵体中每个颜色像素的相对位置成为锚定参数 → 每个孤立标记的颜色在精灵体中定位匹配像素 → 以该像素为锚点将整个精灵体展开到标记位置 → 插槽阵列被擦除。插槽阵列的角色从"需要清理的输出"变为"临时信息源"。

从规律阵列中投票恢复干净精灵体，然后将该精灵体以颜色锚定方式展开到每个孤立标记的位置，最后擦除原始阵列。

**输入结构**：约 18×18 的黑(0)背景网格。网格右半区域有一个 2×3 或 3×3 的规律插槽阵列（行列间距固定），每个插槽包含一个约 3×3 至 4×4 像素的精灵体副本。每个副本使用 2~3 种前景色（如红(2)、蓝(1)、绿(3)），但各副本有 1~2 个像素被随机替换为其他前景色（噪声），不同副本的噪声位置不同。精灵体的每种颜色在其中恰好出现一次或两次（保证颜色→位置映射足够明确）。网格左半区域散布 2~4 个孤立单像素标记，颜色各为精灵体中出现的某种颜色（不重复选取同一颜色两次）。标记之间有足够间距，使得展开后的精灵体互不重叠。黄(4)不在精灵体和标记中使用（保留为区分）。生成约束：每种精灵体颜色至少在一个标记中被使用；精灵体中每种颜色出现的位置是唯一的（若某颜色出现两次，则用于标记时选取该颜色在精灵体中最靠左上角的那个像素作为锚点）。

**规则**：
1. 通过密集行带和列带检测，识别右半区域的插槽阵列及每个插槽的边界。
2. 对精灵体中每个相对位置 (r, c)，统计所有插槽中该位置的颜色出现次数，取众数作为该位置的真实颜色。得到干净精灵体 S。
3. 对网格左半区域的每个孤立标记像素 M（颜色为 color_M）：
   - 在干净精灵体 S 中找到颜色为 color_M 的像素位置 (r_anchor, c_anchor)。若该颜色在 S 中出现多次，取行号最小者；行号相同则取列号最小者。
   - 将整个精灵体 S 放置到输出网格中，使得 S 中 (r_anchor, c_anchor) 位置恰好对齐标记像素 M 的网格坐标。
   - 超出网格边界的部分截断不绘制。
4. 将原始插槽阵列区域的所有像素擦除为黑(0)（包括插槽间间距区域的任何残留噪声像素）。
5. 孤立标记像素本身被精灵体的对应像素覆盖（它们颜色相同，视觉上无变化）。

**关键洞察**：插槽阵列在输入中是最显眼的结构，但在输出中被完全擦除——它是一次性的信息源，而非需要修复的目标。真正的输出由标记像素决定：每个标记的颜色在恢复后的精灵体中定位一个锚点，然后精灵体围绕该锚点展开。这翻转了参考题 0607ce86 中"修复阵列"的直觉——阵列被解码后丢弃。
