## 新题 13：边界锚点驱动精灵体滑动后翻转拼接

**组合逻辑**：[滑动对齐/边缘位置决定轴](已有) + [边界锚点/颜色匹配锚点](已有) + [拼接/翻转副本堆叠拼接](创新：拼接方向由滑动轴决定而非固定方向) + [镜像](创新：翻转的是对齐后的精灵体而非整个画布)

**来源原语**：滑动对齐/边缘位置决定轴/边界锚点/颜色匹配锚点/多色精灵体/标记像素(581f7754), 拼接/翻转副本堆叠拼接(4c4377d9), 镜像(67e8384a, 4c4377d9)

**依赖链**：识别边界锚点和内部精灵体 → 按颜色匹配配对 → 根据锚点边缘位置确定滑动轴 → 精灵体沿轴滑动对齐 → 对齐后的精灵体沿滑动轴做镜像翻转 → 翻转副本拼接在精灵体的对侧

精灵体按颜色匹配滑向边界锚点对齐后，沿滑动轴生成镜像副本并拼接在对侧，形成局部对称结构。

**输入结构**：
- 网格约 14x14，黑(0)背景（最常见颜色）。
- 2~3 个多色精灵体分布在网格内部，每个精灵体为 3x4 至 4x5 像素的四连通多色图形。每个精灵体使用一种主色（如青(8)）和一种标记色。标记色在精灵体中恰好出现 1 个像素。
- 网格边界上有 2~3 个孤立的边界锚点像素（非黑，四邻居中其他非黑邻居均为黑色或网格外），每个锚点颜色与某个精灵体的标记色匹配。
- 上/下边缘的锚点驱动水平滑动，左/右边缘的锚点驱动垂直滑动。
- 生成约束：每个精灵体恰好匹配一个锚点；滑动后精灵体不重叠；精灵体的标记像素与匹配锚点在滑动轴方向上相距至少 3 像素（留出翻转拼接空间）；滑动方向上，精灵体和其翻转副本拼接后不超出网格边界。

**规则**：
1. 识别边界锚点：网格四边上的非黑孤立像素（四连通邻居中非背景像素仅有网格外的边界）。
2. 识别内部多色精灵体（四连通的多色非黑组件）。在每个精灵体中找到出现恰好 1 次的颜色像素作为标记像素。
3. 将每个精灵体与颜色相同的边界锚点配对。
4. 确定滑动轴：锚点在上/下边缘 → 水平滑动（调整精灵体列位置使标记列 = 锚点列）；锚点在左/右边缘 → 垂直滑动（调整精灵体行位置使标记行 = 锚点行）。若锚点在角落，按垂直滑动处理。
5. 执行滑动：将精灵体整体平移使标记像素对齐锚点的对应行或列。清除原位置。
6. 对滑动后的精灵体，沿滑动轴方向做镜像翻转生成副本：
   - 水平滑动的精灵体 → 做左右翻转。
   - 垂直滑动的精灵体 → 做上下翻转。
7. 将翻转副本拼接在精灵体的远离锚点一侧。拼接时副本紧贴精灵体的边界框（间距为 0，共享边界框的一条边）。
8. 若拼接后的像素位置已有其他内容（其他精灵体的像素），后处理的精灵体覆盖先处理的。处理顺序：按锚点的边缘位置，上→右→下→左，同边按行/列号升序。
9. 边界锚点在输出中保持不变。

**关键洞察**：滑动不是最终目标——它确定了精灵体的对齐位置和滑动方向，而这个方向同时决定了镜像翻转的轴向和拼接的方位。单看一个精灵体无法确定是整体翻转还是局部翻转，需要对比多个精灵体的不同滑动方向来归纳翻转-拼接规则。

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
