## 新题 7：障碍条件分支的滑动轨迹与条形复制

**组合逻辑**：[滑动](已有) → [条件分支：障碍 vs 条形接触](创新：同一滑动操作的终止原因触发完全不同的后续处理) → [复制](条件激活) + [重涂色](条件选择)

**来源原语**：滑动(sliding, #56dc2b01), 接触停止(contact_stop, #56dc2b01), 条形障碍(bar_obstacle, #56dc2b01), 碰触后对侧放副本(touch_copy_opposite, #56dc2b01), 复制(copy, #56dc2b01), 重涂色(recolor, #56dc2b01), 路径奇偶交替涂色(alternating_color_by_path_parity, #b782dc8a)

**依赖链**：滑动方向由对象与条形的相对位置决定 → 滑动过程中是否遇到障碍决定分支：遇障碍则擦除障碍 + 对象变色 + 轨迹纯色；未遇障碍则对象保色 + 生成条形副本 + 轨迹交替涂色。分支结果影响输出中的三个独立方面（对象颜色、轨迹图案、是否有副本），且只有理解分支条件才能统一解释所有示例。

将绿色对象沿基本方向向红色条形滑动；若被灰色障碍拦截则擦除障碍、对象变色、轨迹纯色；若无障碍触达条形则保色、放置条形青色副本、轨迹交替着色。

**输入结构**：约 15x15 的黑(0)背景网格。包含以下元素：一个绿(3)小对象（4-连通，3-6 像素），一个红(2)水平或垂直条形（1 像素宽，4-8 像素长），以及 0-2 个灰(5)单像素障碍。绿对象和红条形沿某个基本方向（上/下/左/右）对齐，即沿该方向平移绿对象可以使其到达红条形。灰障碍如果存在，位于绿对象与红条形之间沿滑动方向的路径上（即障碍像素所在行/列与绿对象在滑动方向上的投影有交集）。生成约束：部分示例有障碍，部分示例无障碍，以展示两个分支。

**规则**：
1. 确定滑动方向：从绿(3)对象指向红(2)条形的基本方向（取对象边界框中心到条形边界框中心的主轴方向）。
2. 沿该方向逐像素平移绿对象。若对象的前沿碰到灰(5)障碍像素（即平移后对象的某个像素与障碍像素重合）：
   a. 对象停在碰撞前的最后合法位置。
   b. 擦除所有灰(5)障碍像素（置为黑(0)）。
   c. 将停止位置的对象重涂为青(8)。
   d. 对象从起始位置到停止位置之间经过的空格（对象不再占据的原始位置 + 滑动路径上的空格）全部填黄(4)。
3. 若对象前沿碰到红(2)条形（无障碍阻挡）：
   a. 对象停在紧贴条形的位置，保持绿(3)。
   b. 在对象的另一侧（远离条形的方向），放置一份红条形的副本，颜色改为青(8)，与对象紧贴（副本位置与对象之间无间隙，对称于条形-对象的接触方式）。
   c. 对象从起始位置到停止位置之间经过的空格按步数奇偶交替填色：第一个空格（离起始位置最近）填黄(4)，第二个填橙(7)，第三个填黄(4)，依此类推。
4. 红(2)条形始终保持原位不变。

**关键洞察**：同一个滑动操作因终止条件不同（碰障碍 vs 碰条形）而分裂为两个完全不同的后处理分支。求解者不能把两种情况当作不同的题目——必须识别出"障碍的存在与否"是唯一的分支判据，统一解释所有示例中轨迹颜色模式、对象颜色和副本有无的差异。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
