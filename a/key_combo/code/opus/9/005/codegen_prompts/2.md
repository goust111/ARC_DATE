## 新题 2：图例匹配驱动边缘定向滑动

**组合逻辑**：[形状匹配](已有) → [重涂色](创新：匹配结果同时编码颜色和运动方向) → [平移](创新：颜色决定滑动方向) + [排序](创新：同向冲突时按距离优先排序)

**来源原语**：形状匹配(shape_matching, #845d6e51), 旋转反射等价(rotation_reflection_equivalence, #845d6e51), 图例区域(legend_region, #845d6e51), 分隔线(divider, #845d6e51), 重涂色(recolor, #845d6e51), 平移(translate, #b5ca7ac4), 排序(sort, #b5ca7ac4), 颜色决定目标(color_determines_destination, #b5ca7ac4), 距离优先排序(distance_priority_ordering, #b5ca7ac4), 行重叠内移(row_overlap_shifts_inward, #b5ca7ac4)

**依赖链**：形状匹配确定每个查询精灵体对应的模板 → 模板颜色赋予查询精灵体新身份 → 新颜色（红 vs 蓝）决定滑动方向（左 vs 右）→ 同方向同行的多个精灵体按离目标边缘的距离排序以避免碰撞。四步中任一步被跳过均无法正确生成输出。

将查询精灵体通过形状匹配获得模板颜色，颜色决定滑动方向，同向冲突者按距离排序依次贴靠边缘。

**输入结构**：约 20x25 的橙(7)背景网格。灰(5)水平分隔线（1 像素厚，横跨整个网格宽度）将网格分为上下两半。上半区为图例区：包含 2-4 个小型模板精灵体，每个模板是一个 4-连通的单色图形（3-6 像素），颜色仅使用红(2)和蓝(1)。不同模板的形状在所有旋转和反射下互不等价。下半区为查询区：包含与模板数量相同的青(8)查询精灵体，每个查询精灵体的形状在旋转/反射等价意义下恰好匹配一个模板（一一对应）。查询精灵体之间互不相邻，且不接触网格边缘。生成约束：至少有一对查询精灵体匹配到相同颜色（即至少两个模板同色），且它们位于下半区的相同行范围（边界框在行方向有重叠），以触发碰撞解决机制。

**规则**：
1. 对每个青(8)查询精灵体，在所有旋转和反射下与上半区各模板的形状进行比较，找到唯一匹配的模板。
2. 将匹配的查询精灵体重涂为其对应模板的颜色（红(2)或蓝(1)）。
3. 红(2)精灵体向左滑动至网格左边缘（精灵体边界框的最左列对齐到列 0）；蓝(1)精灵体向右滑动至网格右边缘（精灵体边界框的最右列对齐到最后一列）。精灵体保持其原始行位置不变。
4. 碰撞处理：若两个同色精灵体滑向同一边缘且行范围有重叠（边界框在行方向有交集），则按以下规则处理——离目标边缘更近的精灵体（以边界框到目标边缘的列距离计算）优先贴靠边缘；较远的精灵体紧贴在前者后方（红色方向：较远者的最左列 = 前者的最右列 + 1；蓝色方向：较远者的最右列 = 前者的最左列 - 1）。若列距离相同，则边界框上方（行号较小）的优先。
5. 灰(5)分隔线和上半区模板保持不变。查询精灵体原始位置的像素置为橙(7)背景色。

**关键洞察**：形状匹配的结果不只是一个标签——它同时编码了颜色（视觉输出）和运动方向（空间变换）。仅看单个示例可能以为滑动方向由位置决定，必须对比多个示例中匹配到不同颜色的精灵体的运动方向才能归纳出"颜色决定方向"这一规则。
