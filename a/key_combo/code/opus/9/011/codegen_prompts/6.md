## 新题 6：嵌套深度反转控制标记含义的对称补全

**组合逻辑**：[由外到内嵌套](outer_to_inner) + [包含](containment) → 嵌套深度计算 → 深度奇偶翻转（创新：将"控制标记指示源侧"改造为条件性规则——嵌套深度的奇偶性反转控制标记的语义，偶数深度标记指示源侧、奇数深度标记指示目标侧） → [对称补全/镜像](symmetric_completion, mirror)。源题中控制标记含义固定不变，这里控制标记的含义被嵌套结构动态修改，形成"空间层次 → 语义反转"的涌现效应。

**来源原语**：对称补全(symmetric_completion) ← 5b692c0f/47996f11；对称轴(symmetry_axis) ← 5b692c0f；控制标记(control_marker) ← 5b692c0f；控制标记指示源侧(control_marker_indicates_source) ← 5b692c0f；轴对称反射(axial_mirror_reflection) ← 5b692c0f；嵌套矩形(nested_rectangle) ← 5751f35e；由外到内嵌套(outer_to_inner) ← 5751f35e；包含(containment) ← 8efcae92；大层先画小层覆盖(large_first_small_over) ← 5751f35e；镜像(mirror) ← b10624e5/2dee498d

**依赖链**：检测各对象的空间包含关系 → 计算每个对象的嵌套深度 → 深度奇偶性反转控制标记的语义（偶数深度：标记指向正确侧；奇数深度：标记指向错误侧） → 根据重新解释后的源侧执行镜像对称补全 → 从外到内依次处理，内层覆盖外层。去掉嵌套分析则所有标记按统一语义处理、奇数深度对象被错误补全；去掉控制标记则源侧无法确定；去掉对称补全则无输出变换。

对每个含黄色对称轴和控制标记的彩色对象执行对称补全，但嵌套深度为奇数的对象，其控制标记的含义被反转（指向目标侧而非源侧）。

**输入结构**：约 15x15 的网格。背景为黑(0)。网格上有 2~3 个不同颜色的对象（例如蓝(1)、红(2)、绿(3)），部分对象的边界框嵌套在其他对象的边界框内部（即存在至少一个深度为 1 的对象）。每个对象包含：
- 一组前景色像素构成的不完整图案（左右或上下一半有清晰图案，另一半为空或不同）。
- 一条由黄(4)像素组成的连续直线段穿过该对象，作为对称轴（水平或垂直）。
- 一个偏离对称轴的黄(4)单像素（控制标记），位于对称轴的某一侧。
生成约束：每个对象的前景图案在对称轴一侧完整、另一侧不完整或缺失。外层对象的边界框至少比内层对象的边界框每方向大 2 个像素。不存在深度 >= 3 的嵌套。

**规则**：
1. 对每个对象，计算其嵌套深度：若其边界框不在任何其他对象的边界框内部，则深度为 0；若在恰好一个对象的边界框内部，则深度为 1；以此类推。
2. 对嵌套深度为偶数（0, 2, ...）的对象：控制标记所在的一侧为源侧（正确侧）。将源侧的图案沿对称轴镜像到另一侧，覆盖该侧原有的所有像素（含前景和背景）。
3. 对嵌套深度为奇数（1, 3, ...）的对象：控制标记所在的一侧为目标侧（错误侧）。将对面一侧（非标记侧）的图案沿对称轴镜像到标记侧，覆盖标记侧原有像素。
4. 处理顺序：从嵌套深度最小（最外层）到最大（最内层）依次处理。内层对象补全后的像素覆盖外层对象在同一位置的像素。
5. 黄(4)对称轴和控制标记像素保持不变，不被镜像操作覆盖。

**关键洞察**：控制标记的语义不是全局固定的"标记 = 源侧"，而是被嵌套深度的奇偶性动态反转——外层对象中标记指向正确的一半，内层对象中标记反而指向需要被覆盖的一半；这一反转规则只能通过对比嵌套与非嵌套对象的补全结果才能发现。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
