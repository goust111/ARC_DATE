## 新题 1：枢轴方向编码的印章旋转

**组合逻辑**：[印章覆盖](已有) + [旋转](创新：由枢轴像素相对方向编码旋转角度，而非逐槽位累加) + [枢轴像素](创新：不再定义点对称中心，而是作为方向编码器) → [分块对应](已有)

**来源原语**：印章覆盖/分块对应/模板面板(b190f7f5), 旋转(8e5a5113), 枢轴像素(90347967)

**依赖链**：枢轴像素的方位决定旋转角度 → 旋转角度决定模板朝向 → 朝向后的模板印入对应分块。三者环环相扣：不识别枢轴方位就无法确定旋转；不旋转就印错模板；不做分块映射则无法定位输出。

将每个源像素周围的灰色枢轴像素的相对方位解码为旋转角度，把模板面板的掩码旋转后印入对应的分块位置。

**输入结构**：约 15x15 的网格。由一条灰(5)分隔列将网格分成左右两个大小相同的面板（各约 15x7）。左面板为"源网格"：黑(0)背景上散布 2-4 个不同颜色的前景像素（颜色取自蓝(1)、红(2)、绿(3)、黄(4)中的不同色），每个前景像素恰好有一个灰(5)像素与之 4-邻接（上、下、左、右之一），且不同前景像素的灰色枢轴方位可以不同。右面板为"模板面板"：黑(0)背景上有一个由栗(9)像素构成的 4-连通掩码图形（3-5 像素，非对称形状，以便旋转后可区分朝向）。生成约束：左面板中各前景像素（含其灰色枢轴）互不相邻，保证枢轴归属无歧义；模板掩码在四种 90 度旋转下形状互不相同。

**规则**：
1. 将左面板视为 N x N 的逻辑源格（N 由面板行列数与模板面板尺寸共同确定），每个源格对应输出中一个与右面板等大的分块。
2. 对每个非背景源像素，确定其灰(5)枢轴像素在源像素的哪个 4-邻接方位：上方 → 0 度，右方 → 顺时针 90 度，下方 → 180 度，左方 → 顺时针 270 度。
3. 将右面板的栗(9)掩码按该角度顺时针旋转，然后将掩码中所有栗(9)像素重涂为该源像素的颜色。
4. 将重涂并旋转后的掩码印入输出网格中对应分块的位置，其余分块保持黑(0)背景。
5. 输出网格大小为 N x N 个分块拼成的方阵，每个分块大小等于右面板的行列数。

**关键洞察**：灰色枢轴像素不是对称中心，而是方向指针——它相对于源像素的位置隐式编码了模板的旋转角度，必须跨多个示例才能确认这一编码规则。

Input structure
- A black background contains a small colored foreground mask.
- Exactly one grey pixel sits near the mask and acts as the pivot.

Rule
- For each non-background pixel at (r, c), place the same color at
  (2 * pivot_r - r, 2 * pivot_c - c).

Key insight
- The grey pixel is the center of point symmetry; the output is the same colored mask after a half-turn about that pixel.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
