## 新题 6：重力下落精灵体被尺寸匹配的框架捕获

**组合逻辑**：[滑动sliding + 重力沉降gravity_settle](已有) → [空心框hollow_frame](已有对象，创新用法：框架作为"捕获器"，只有尺寸匹配的精灵体能进入) → [重涂色recolor](创新：框架边框被重涂为捕获到的精灵体颜色，反转了通常"标记涂对象"的方向)

**来源原语**：滑动sliding(d282b262), 重力沉降gravity_settle(d282b262), 碰撞阻挡collision_block(d282b262), 空心框hollow_frame(4c416de3), 矩形框架rect_frame(fcb5c309), 前景对象foreground_object(d282b262), 重涂色recolor(6df30ad6), 面积最大选取largest_area_select(fcb5c309)

**依赖链**：重力下落决定精灵体的运动轨迹；框架的内部尺寸决定哪些精灵体能被捕获（尺寸匹配）；处理顺序（从上到下）决定"谁先占据框架"。三者交织：改变精灵体初始位置会改变到达框架的顺序，改变框架大小会改变匹配关系，改变处理顺序会改变谁被捕获。最终框架的边框颜色反映了捕获结果——这是一个反向信息编码。

小型彩色精灵体从上方下落，被尺寸匹配的灰(5)空心框架捕获并落入框内底部；框架边框变为捕获到的精灵体颜色，未被捕获的精灵体落到网格底部。

**输入结构**：
- 网格约 20x15，背景黑(0)。
- 3-4 个灰(5)空心矩形框架，单像素边框，内部尺寸各不相同（如 3x3、4x3、5x4 内部像素），放置在网格下半部分的不同高度和列位置，框架之间互不重叠、互不相邻。
- 3-4 个小型实心单色精灵体，颜色分别为红(2)、绿(3)、蓝(1)、黄(4)，每个是 4-连通的不规则图形（3-8 像素），放置在网格上半部分。每个精灵体的边界框宽高 <= 某个框架的内部宽高。
- 每个精灵体的列跨度与至少一个框架的内部列跨度有重叠（使精灵体有可能落入该框架）。
- 生成约束：每个框架至多与一个精灵体尺寸匹配（边界框能放入内部），保证无歧义。

**规则**：
1. 按精灵体顶行从小到大排序（高的精灵体先下落）。若顶行相同，左边的先处理。
2. 每个精灵体保持形状和列位置不变，逐行向下移动。
3. 当精灵体的边界框与某个空框架的内部区域在列方向上完全重叠，且精灵体的边界框宽 <= 框架内部宽、边界框高 <= 框架内部高时，该精灵体被"捕获"：精灵体停在框架内部的底边上（边界框底行对齐框架内部底行），列方向居中于框架内部（若无法完美居中，偏左 1 像素）。
4. 若精灵体的下落路径上没有可捕获它的空框架（尺寸不匹配或框架已被占据），精灵体落到网格底行（边界框底行对齐网格最后一行）。
5. 每个捕获了精灵体的框架，其灰(5)边框像素全部被重涂为该精灵体的颜色。
6. 未捕获精灵体的框架保持灰(5)不变。

**关键洞察**：框架是"陷阱"——精灵体能否被捕获取决于边界框与框架内部的尺寸比较，这在视觉上并不直观。再加上从上到下的处理顺序，一个框架可能因为更早到达的精灵体（即使不是最佳匹配）已将其占据而错过"本该属于它的"精灵体。
