## 新题 2：色向滑轨与形状刹车

**组合逻辑**：[颜色匹配边](已有) → [平移](创新：从单步位移改为沿方向持续滑动) → [形状匹配孔洞](创新：从静态嵌入的前提改为滑动的终止条件) → [嵌入填充](已有)

**来源原语**：颜色匹配边/color_match_side(参考题 5034a0b5), 平移/translate(参考题 5034a0b5), 形状匹配孔洞/shape_matches_hole(参考题 67e490f4), 嵌入填充/inlay_fill(参考题 67e490f4), 精灵体/sprite(参考题 228f6490, 67e490f4), 孔洞/hole(参考题 228f6490, 67e490f4), 旋转翻转不变/rotation_flip_invariant(参考题 67e490f4)

**依赖链**：精灵体颜色与边框边颜色匹配决定滑动方向——这是平移的前提；但平移距离不由颜色或边框决定，而由路径上的形状匹配决定：精灵体沿方向持续滑动，首次与某容器孔洞形状匹配时停下并嵌入。方向、距离、嵌入三者各由不同原语控制。

精灵体根据自身颜色与边框边的匹配确定滑动方向，沿该方向持续滑动直至形状匹配路径上某容器的孔洞，嵌入该孔洞并涂上自身颜色。

**输入结构**：黑(0)背景网格，约 18x18。最外一圈为一像素宽矩形边框，四角像素为黑(0)，四边各为一种不同颜色（从蓝(1)、红(2)、绿(3)、黄(4)中各取一种，不同示例中各边颜色可能交换）。边框内部有 2~4 个灰(5)容器（每个容器为 4x4 至 6x6 的实心灰色矩形，内部挖去一个 2~4 像素的 4-连通黑(0)孔洞）。另有 2~4 个小型精灵体（每个为 2~4 像素的 4-连通单色图形，颜色为蓝(1)/红(2)/绿(3)/黄(4)之一，与某条边框边同色）。精灵体初始不与任何容器重叠。生成约束：每个精灵体沿其滑动方向的路径上恰好有一个容器的孔洞在 8 种刚体变换（4 旋转 x 2 翻转）下与该精灵体形状匹配；不同精灵体的滑动路径互不冲突。

**规则**：
1. 识别边框四边颜色，建立颜色→方向映射（上边色→向上，下边色→向下，左边色→向左，右边色→向右）。
2. 对每个精灵体，根据其颜色确定滑动方向。
3. 精灵体从当前位置沿方向逐像素平移。每到一个新位置，检查精灵体形状（在至多 8 种刚体变换下）是否恰好覆盖某个灰色容器内的黑色孔洞。
4. 首次匹配时停止滑动：以匹配的变换姿态将精灵体嵌入孔洞，用精灵体颜色填充孔洞像素，同时将精灵体原位置恢复为黑(0)。
5. 若精灵体滑到边框仍无匹配，则擦除（原位置恢复为黑(0)）。
6. 边框和容器非孔洞部分保持不变。处理顺序：按精灵体边界框左上角从上到下、从左到右依次处理。

**关键洞察**：精灵体颜色同时编码了运动方向（通过边框匹配）和输出颜色（嵌入时的填充色），而停止位置则完全由形状匹配决定——三个独立信息通道编码在不同结构关系中。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
