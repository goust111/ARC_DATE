## 新题 4：计数器编码旋转角度决定宏块图案与填充颜色

**组合逻辑**：[计数/计数器像素](已有) → [旋转/整体旋转](创新：旋转对象是宏块级布尔图案而非像素网格) → [填充/重涂色](创新：旋转后最靠左上的激活块行号索引填充颜色)

**来源原语**：
- 宏块格阵(macro_block_grid)、标记激活块(marker_activates_block)、中心标记触发(center_marker_trigger) -- ce22a75a
- 旋转(rotate)、整体旋转(whole_grid_rotate) -- ed36ccf7
- 计数器像素(counter_pixel)、计数(counting)、计数决定偏移(count_determines_offset)、计数器消失(counter_disappears) -- e48d4e1a
- 擦除(erase) -- 902510d5

**依赖链**：读取右侧计数器列的灰像素数量N → 将宏块激活图案视为4x4布尔矩阵 → 对该矩阵逆时针旋转N x 90度 → 旋转后扫描布尔矩阵找到最靠左上的激活位置 → 该位置的行索引决定填充色 → 按旋转后的图案重新绘制激活宏块

宏块网格中灰色中心标记定义了一个激活图案；右侧计数器的灰像素数量决定逆时针旋转角度；旋转后的激活图案被重新绘制，而填充颜色由旋转结果中最靠左上角的激活块的行位置索引决定。

**输入结构**：
- 黑(0)背景，12x15网格
- 左侧12x12区域是4x4的宏块格阵，每个宏块3x3像素。部分宏块的中心格（即宏块内坐标(1,1)处）为灰(5)表示"激活"，对应宏块其余8格为黑(0)；未激活的宏块全部为黑(0)
- 右侧3列（列12~14）是计数器区域：每列内容相同，从第0行开始连续若干格为灰(5)，其余为黑(0)；灰像素数量N取值1、2或3
- 生成约束：4x4宏块激活图案为非对称图案（90度/180度/270度旋转后至少有一种结果与原图案不同）；激活的宏块数量为3~6个

**规则**：
1. 读取右侧计数器区域中灰(5)像素的行数 N（只需计一列，三列内容相同）
2. 将左侧4x4宏块激活图案抽象为布尔矩阵B（4x4，激活=1，未激活=0）
3. 将B逆时针旋转 N x 90度，得到旋转后矩阵B'
4. 在B'中按行优先、列其次的顺序（从第0行第0列开始，逐行扫描），找到第一个值为1的位置(r, c)
5. 根据r的值确定填充颜色：r=0时蓝(1)、r=1时红(2)、r=2时绿(3)、r=3时黄(4)
6. 输出为12x12网格（右侧计数器区域去除）：对B'中值为1的每个位置，将对应的3x3宏块整体填充为步骤5确定的颜色；其余宏块保持全黑

**关键洞察**：计数器的值通过旋转角度间接影响填充颜色——不同的旋转将不同的激活块推到最靠左上的位置，改变行索引从而改变颜色。求解者不能跳过旋转直接确定颜色，因为颜色依赖于旋转后的空间布局。

<description>
Crop the unique foreground object whose mask is not mirror-symmetric left-to-right.

Input structure
- A dominant background surrounds several same-color 8-connected foreground objects.
- Exactly one foreground color appears.
- All but one foreground object are mirror-symmetric left-to-right inside their tight bboxes.

Rule
- Split the non-background pixels into 8-connected objects.
- Build each object's tight bbox crop over the background.
- Return the single crop whose foreground mask differs from its left-right reflection.

Key insight
- The input is a set of candidate sprites, and vertical-axis asymmetry identifies which one to extract regardless of color or position.
