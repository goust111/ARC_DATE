## 新题 5：种子条纹上的交替擦除与相位编码

**组合逻辑**：[平铺/tiling](种子生成条纹) + [擦除/erase](条纹上打孔) + [种子定条纹周期/seed_sets_stripe_period](周期控制) + [中线交替打孔/alternating_holes_on_center](改造：作用于条纹而非矩形中线)

**来源原语**：平铺(0a938d79), 种子像素(0a938d79), 条纹(0a938d79), 种子定条纹周期(0a938d79), 擦除(3bdb4ada), 中线交替打孔(3bdb4ada)

**依赖链**：种子位置和间距 → 生成条纹图案 → 在每条条纹上从其种子位置开始交替擦除像素 → 两种颜色的擦除起始相位不同（一个从第 1 格开始擦，另一个从第 2 格开始）。条纹周期由种子间距决定，擦除相位由种子颜色决定——周期和相位是两个独立编码维度。

两个种子像素生成周期性条纹，然后在每条条纹上交替擦除像素，两种颜色的擦除相位相反。

**输入结构**：约 12x12 网格，黑(0)背景。恰好两个非黑种子像素，颜色分别为蓝(1)和红(2)。两个种子要么在同一行的不同列（生成列方向的条纹），要么其中一个紧贴网格的上/下边缘（生成行方向的条纹，参照源题 0a938d79 的方向判定规则）。两种子的间距 s 在 2-4 之间。生成约束：网格尺寸能被条纹周期整除或条纹周期足以覆盖大部分网格。

**规则**：
1. 按源题 0a938d79 的方向规则判定条纹方向：若任一种子位于侧边缘，生成行方向条纹（整行涂色）；否则生成列方向条纹（整列涂色）。
2. 以两个种子所在的行/列为起始，沿垂直方向以步长 2s 重复两条条纹（一条蓝、一条红），覆盖整个网格。
3. 在每条蓝(1)条纹上，从条纹起始端（行条纹从最左列，列条纹从最上行）开始，以步长 2 擦除像素（第 1、3、5... 位置变为黑(0)）。
4. 在每条红(2)条纹上，从条纹起始端偏移 1 格开始，以步长 2 擦除像素（第 2、4、6... 位置变为黑(0)）。
5. 种子像素本身遵循与其所在条纹相同的擦除规则，不做特殊保留。

**关键洞察**：蓝和红条纹的擦除相位恰好互补——蓝擦奇数位时红保留奇数位，形成棋盘格般的交错图案。这个相位差在单色条纹中不可见，只有同时观察两种颜色条纹的擦除位置才能发现。需要对比多个不同种子间距的示例才能区分"相位由颜色决定"和"相位由位置决定"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
