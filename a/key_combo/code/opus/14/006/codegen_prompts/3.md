## 新题 3：面积排序驱动的链式精灵对接

**组合逻辑**：[面积分级(area_ranking)](创新：面积决定对接顺序而非颜色) → [对接拼合(docking)](创新：从双体对接扩展为有序链式对接) → [裁剪(crop)]

**来源原语**：对接拼合(docking, 20270e3b)、计数(counting, 多题)、裁剪(crop, 28bf18c6)、精灵体(sprite, 28bf18c6/20270e3b)、连接点(connector_pixel, 20270e3b)、连通分量(connected_component, e8593010)、对接对齐(docking_alignment, 20270e3b)、面积分级(area_ranking, e8593010)、连接点颜色匹配(connector_color_match, 20270e3b)、链式连接(chain_linkage, 84551f4c → 创新为对接链)

**依赖链**：精灵体按像素面积降序排列 → 最大精灵体作为底座 → 依次将下一个精灵体通过共享连接色对接到当前组合体上 → 对接改变组合体的形态，影响后续连接点的可用位置 → 最终裁剪。面积排序决定组装顺序，而组装顺序决定空间布局——调换任何两个精灵体的顺序会得到完全不同的结果。

将多个精灵体按面积从大到小、通过颜色匹配的连接点依次拼装为一个组合体并裁剪。

**输入结构**：约 20x20 的黑(0)背景网格。含 3 个分离的单色精灵体，主体均为蓝(1)，形状各异（4-连通，各 4-8 像素，非矩形，具体形状因示例而异）。三者像素面积互不相同。每个精灵体内嵌 1-2 个连接像素，颜色非蓝(1)非黑(0)。连接像素在精灵体间形成配对：精灵体 A 含一个红(2)连接像素，精灵体 B 含一个红(2)和一个绿(3)连接像素，精灵体 C 含一个绿(3)连接像素。A 的面积 > B 的面积 > C 的面积（不同示例中三者的具体面积和形状都不同，但大小关系一致用于验证排序规则）。生成约束：三个精灵体在输入中互不接触，彼此间距至少 3 像素；对接后组合体不超出 20x20 范围。

**规则**：
1. 计算每个精灵体的像素面积（含连接像素），按面积降序排列。最大者为"底座"。
2. 按面积从大到小依次处理剩余精灵体。对于当前待对接的精灵体 P：
   a. 找到 P 与当前组合体共享的连接颜色 C（恰好一种）。
   b. 平移 P，使 P 中颜色为 C 的连接像素与组合体中颜色为 C 的连接像素在水平方向上相邻（P 的连接像素位于组合体连接像素的正右方，共享同一行）。
   c. 将 P 叠印到组合体上。将两个已匹配的连接像素都重涂为蓝(1)。
3. 全部对接完成后，将组合体裁剪到其非黑(0)像素的最小边界框。
4. 输出裁剪后的组合体。

**关键洞察**：对接顺序由面积排序严格决定，而每次对接改变了组合体的空间形态和剩余连接点的绝对坐标。第二次对接的位置依赖于第一次对接的结果——这是一条不可逆的因果链，不能通过单独观察任何一步来推断全局规则。

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
