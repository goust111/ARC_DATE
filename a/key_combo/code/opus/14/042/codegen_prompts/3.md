## 新题 3：色频驱动轨迹的边缘滑动

**组合逻辑**：[颜色互换/color_swap](创新：互换结果决定目的端外观，少数色决定轨迹颜色) + [滑动/slide](创新：轨迹色由对象内部色频分析决定而非全局固定)

**来源原语**：color_swap, bicolor_pairing_within_object, swap_within_same_object (← 45737921); slide, edge_rectangle, trail_stripe, touching_edge, slide_to_opposite (← b25e450b)

**依赖链**：识别边缘双色矩形 → 统计矩形内两色像素数 → 少数色作为轨迹色 → 矩形滑至对侧边缘 → 到达后矩形内两色互换。对象的内部色构成决定外部轨迹颜色，删除色频分析步骤则轨迹色无法确定。

双色矩形滑至对边，轨迹涂其内部少数色，到达后矩形内两色互换。

**输入结构**：约 18x18 网格，背景黑(0)。2~4 个实心矩形（宽 2~4 列、高 2~4 行），每个矩形恰好包含两种非背景色（取自 1~9），两种颜色的像素数不同（无平局）。每个矩形的颜色分布呈某种几何图案（如一色占上半、另一色占下半，或一色占边框、另一色占中心等），不同矩形的内部分布图案不同。每个矩形仅接触一条网格外边缘（上、下、左或右各最多一个矩形）。不同矩形使用不同的颜色对。生成约束：各矩形的滑动路径（从初始位置到对侧边缘扫过的行/列范围）互不交叉。

**规则**：
1. 对每个矩形，确定其接触的边缘，滑动方向为朝向对侧边缘（接触上边则向下，接触左边则向右，依此类推）。
2. 统计矩形内两种颜色的像素数，像素数较少的记为少数色 m，较多的为多数色 M。
3. 所有矩形同时滑动。每个矩形移至对侧边缘对应位置（保持其原行或原列不变）。
4. 矩形从原始位置到目的位置之间扫过的所有像素（不含目的位置的矩形本身）涂为该矩形的少数色 m。
5. 矩形在目的位置落下后，其内部的颜色 M 和 m 互换：原来是 M 的像素变 m，原来是 m 的像素变 M（内部图案的几何结构保持不变，仅颜色角色互换）。

**关键洞察**：轨迹的颜色不是固定值——它取决于每个矩形内部两种颜色谁是少数。必须先分析每个矩形内的色频比较，才能确定轨迹颜色。同时，到达目的地后的互换使原来的少数色变成多数色，目的端矩形与轨迹在颜色上形成反转关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
