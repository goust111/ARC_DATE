## 新题 1：封闭区域计数驱动精灵旋转

**组合逻辑**：[计数(counting)](已有) + [旋转(rotate)](已有) ← [封闭区域(enclosed_region)](已有, 创新：从分隔框架移入栅格单元内部，成为旋转参数的隐式编码) + [分隔栅格(divider_grid)](已有) + [位置索引(position_index)](已有, 创新：从颜色查找变为旋转量索引)

**来源原语**：计数/封闭区域/忽略干扰项(89565ca0), 旋转/阵列排布(46442a0e), 分隔栅格/位置索引(09629e4f), 精灵体(多题)

**依赖链**：每个单元格的内部墙壁结构 → 计数该单元的封闭背景区域数 → 该数值决定该单元内精灵的旋转角度。计数结果直接参数化旋转操作；不计数则旋转量未知，不旋转则计数无意义。

将网格单元内的墙壁拓扑结构解码为旋转参数，对每个单元的精灵施加不同角度的旋转后输出。

**输入结构**：约 15x21 的网格，灰(5) 色分隔线将网格划分为 2x3 共 6 个等大单元格（每格约 6x6）。每个单元格内包含：(a) 一个由红(2) 色像素组成的 4-连通小图形（3~6 像素，形态各不相同，不具旋转对称性），(b) 若干蓝(1) 色单像素宽的内部墙壁线段，将单元格的剩余黑(0) 色背景分割为 1~4 个封闭区域。内部墙壁从单元边界或其他墙壁延伸，保证每个封闭区域都是 4-连通的。不同单元格的封闭区域数各不相同（生成约束：6 个单元格的区域数为 {1,2,3,4} 的某个子集，保证无歧义映射）。红色精灵不与蓝色墙壁接触。

**规则**：
1. 对每个单元格，计算其中由蓝(1) 色墙壁和灰(5) 色单元边界共同围成的 4-连通黑(0) 色封闭背景区域的数量 N。
2. 将该单元格内的红(2) 色精灵以其边界框中心为旋转中心，顺时针旋转 (N mod 4) x 90 度。N=1 转 90 度，N=2 转 180 度，N=3 转 270 度，N=4（即 0 mod 4）不旋转。
3. 输出时保留灰色分隔线，移除所有蓝色内部墙壁（替换为黑色背景），保留旋转后的红色精灵。

**关键洞察**：蓝色墙壁的拓扑功能（分割出几个封闭区域）是精灵旋转量的隐式编码——视觉上墙壁只是线条杂物，但它们的数量和连接方式决定了各单元格的旋转参数。仅看一个示例无法确定"区域数→旋转角"的映射规则（需对比不同单元格的区域数与精灵朝向变化来归纳）。
