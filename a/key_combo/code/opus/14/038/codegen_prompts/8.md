## 新题 8：条形编码旋转与行提取

**组合逻辑**：[counting + categorical_count](已有) → [rotate + whole_grid_rotate](创新：旋转量由外部编码决定) → [erase + summary_generation](创新：旋转后提取单行作为输出)

**来源原语**：counting/categorical_count/horizontal_bar/row_major_fill（来自 5289ad53）、rotate/whole_grid_rotate/square_grid（来自 ed36ccf7）、summary_generation（来自 5289ad53）、erase（来自 782b5218）

**依赖链**：右区条形的计数编码了两个参数 → 黄条数决定旋转量 → 旋转改变了图案中每行的内容 → 橙条数决定从旋转后图案中提取哪一行。两个计数分别控制不同维度的变换，同时改变一种条的颜色会同时影响旋转和提取，产生双重联动。

右半区的彩色横条编码两个参数：一种颜色的条数决定左半区图案的旋转角度，另一种颜色的条数决定从旋转结果中提取哪一行作为输出。

**输入结构**：约 7x15 的网格，由一条垂直灰(5)分隔线（位于网格中部某列，从顶到底）分为左右两半。左半区：一个 H x H 的方形彩色图案（使用蓝(1)、红(2)、绿(3)等颜色，H 与左半区高度相同且等于网格高度）居中放置，背景黑(0)。右半区：若干单像素厚度的水平横条，颜色为黄(4)或橙(7)，每条横跨右半区全宽，不同条在不同行，不重叠。右半区的非横条像素为黑(0)。生成约束：黄(4)条数不超过 3（确保旋转量 0~3 有意义）；橙(7)条数小于 H（确保行索引有效）；左半区图案关于旋转不对称（不同旋转产生不同结果）。

**规则**：
1. 计数右半区中黄(4)横条的数量 Y 和橙(7)横条的数量 O。
2. 计算旋转量 R = Y mod 4。将左半区的 H x H 图案逆时针旋转 R x 90 度（R=0 不旋转，R=1 旋转 90 度，R=2 旋转 180 度，R=3 旋转 270 度）。
3. 从旋转后的图案中提取第 O 行（0-indexed，从顶部开始计数）。
4. 输出仅为该单行（1 x H 的网格）。丢弃灰分隔线、右半区和图案的其余行。

**关键洞察**：右区的横条不是装饰——它们是编码信号。黄条和橙条各自独立编码一个参数，但它们作用于同一个图案的变换链上：旋转改变了每行的内容，因此提取第 O 行的结果取决于旋转量。将一条黄色横条改为橙色会同时减少旋转量并增加提取行号，对输出产生双重非线性影响。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
