## 新题 4：缺口方位双重编码滑动方向与缩放步长

**组合逻辑**：[slide + notch_determines_dir](缺口决定滑动方向和颜色) <-> [resize + side_length_cycle](缺口方位同时编码缩放循环步数，创新：同一几何特征的两个维度分别驱动位移和形变)

**来源原语**：slide, border_notch, edge_aligned, notch_determines_dir (参考题 320afe60); resize, odd_side_square, side_length_cycle, concentric_position (参考题 522fdd07)

**依赖链**：每个正方形的边框缺口方位是一个二维编码——第一维（左/上 vs 右/下）决定滑动方向和重涂色，第二维（上/右 vs 下/左）决定缩放循环步数。同一个几何特征同时驱动位移（改变位置）和形变（改变尺寸）两个独立变换，删除任一解码层均无法还原完整输出。

每个带边框缺口的奇数边正方形根据缺口方位向左或右滑至边缘并变色，同时按缺口位置编码的步数在尺寸循环中前进。

**输入结构**：黄(4)背景，约 20x25 网格。包含 3~5 个蓝(1)单色实心奇数边正方形（边长取自 {3, 5, 7}），彼此不重叠，各占据不同的行区间（各正方形的行跨度互不交叉，保证滑动后在垂直方向无冲突）。每个正方形的边框上恰好有一个缺口：某条边的正中间像素为背景色黄(4)（例如，边长为 5 的正方形上边缺口即上边第 3 个像素为黄(4)）。缺口可能出现在上、下、左、右四条边之一。不同示例中正方形的大小、位置、缺口方位不同。生成时保证：滑动并缩放后的正方形不超出网格上下边界。

**规则**：
1. 清空画布为黄(4)背景。
2. 对每个正方形，按中心行从上到下的顺序依次处理。检查缺口所在的边：
   - 缺口在左边或上边 -> 该正方形向左滑动，直到左边缘紧贴网格左边界（列 0），重涂为红(2)。
   - 缺口在右边或下边 -> 该正方形向右滑动，直到右边缘紧贴网格右边界（最后一列），重涂为绿(3)。
3. 同时根据缺口方位确定缩放循环步数（循环序列为 ...-> 9 -> 7 -> 5 -> 3 -> 1 -> 9 -> ...）：
   - 缺口在上边或右边 -> 边长在循环中前进 1 步（如 5 -> 3）。
   - 缺口在下边或左边 -> 边长在循环中前进 2 步（如 5 -> 1）。
4. 以正方形滑动后的中心位置（行取原始中心行，列取滑动后的中心列）为中心，按新边长绘制完整实心正方形（无缺口）。若新正方形超出网格上下边界，超出部分裁剪不绘制。
5. 各正方形行区间不交叉，故无重叠冲突。

**关键洞察**：缺口方位是一个二位编码——(左/上 vs 右/下) 对控制方向和颜色，(上/右 vs 下/左) 对控制缩放步数。需要对比多个示例才能分离出这两个编码维度，因为单个示例中方向和步数总是同时变化。

Input structure:
- Yellow is the background and there is one blue foreground color.
- The foreground is split into separated 4-connected objects.

Rule:
- If an object's bbox border contains a background gap flanked by object pixels along that same border, slide it to the right edge and recolor it green.

Key insight:
- The target side is encoded by the object's shape, not by its original position: open notches go right, while closed or solid shapes go left.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
