## 新题 9：平衡点轨道滑动印章

**组合逻辑**：[射线延伸](创新：从轨道点向上下投射测距而非从控制像素出发) → 距离比较寻找平衡点(涌现：轨道点的射线距离形成约束方程) → [滑动](创新：滑动目标由距离平衡决定而非进一步) → [印章覆盖/命中处印标记](保留核心)

**来源原语**：射线延伸/ray_extend(ecdecbb3)、投射/perpendicular_cast(ecdecbb3)、印章覆盖/stamp_overlay(ecdecbb3)、命中处印标记/stamp_at_hit(ecdecbb3)、接触标记/contact_marker(ecdecbb3)、滑动/slide(5168d44c)、轨道点/track_dot(5168d44c)、等距排列/evenly_spaced(5168d44c)、沿轨道进一槽位/advance_one_slot(5168d44c → 创新为advance_to_balance_point)、前景对象/foreground_object(5168d44c)

**依赖链**：每个轨道点向上下投射射线测量到最近水平条段的距离，距离值随轨道位置变化（因为条段不是全宽贯穿条，不同列位置能"看到"不同的条段）→ 寻找唯一的上下距离相等的轨道点作为平衡点 → 精灵体滑动到该平衡点 → 在上下命中的条段位置印章接触标记。射线距离决定了滑动目标，滑动位置决定了印章位置，三者链式依赖。

红色精灵体沿绿色轨道滑动到上下方最近蓝色水平条段等距的唯一平衡位置，并在上下命中的条段处各印一个3x3红色接触标记。

**输入结构**：黑(0)背景，约16x14网格。一行等距绿(3)轨道点水平排列在网格中部某行（间距相等，至少6个点）。一个红(2)小精灵体（3~5像素的4-连通小图形）覆盖在某个轨道点上。若干蓝(1)水平条段（非贯穿行：每段为同一行上连续的蓝(1)像素，宽度至少3像素但不覆盖全行）分布在轨道上方和下方的不同行上。生成约束：条段不与轨道点重叠（不在轨道行上）；条段之间互不重叠；轨道上方至少2个条段，下方至少2个条段；条段在水平方向的覆盖范围不同（不同列位置能看到不同的最近条段）；恰好存在一个轨道点，从该点所在列向上和向下分别到最近蓝(1)像素的行距离相等。

**规则**：
1. 对每个轨道点，从其所在列向上逐行扫描，找到最近的蓝(1)像素所在行，计算行距离d_up。若该列上方无蓝(1)像素，d_up = 无穷大。同理向下扫描得d_down。
2. 找到唯一满足 d_up = d_down（且均为有限值）的轨道点——平衡点。
3. 将红(2)精灵体从当前位置沿轨道水平平移到平衡点轨道位置（保持精灵体形状不变，仅水平平移使精灵体中心对齐平衡点）。精灵体离开的原位置恢复为绿(3)轨道点（如果原本被精灵体覆盖的话）。
4. 在平衡点列上方d_up处命中的蓝(1)像素位置，以该像素为中心印一个3x3红(2)方块标记，标记中心恢复为蓝(1)。同样在下方d_down处命中的蓝(1)像素位置印一个3x3红(2)方块标记，中心恢复蓝(1)。3x3标记中超出网格的像素忽略。
5. 其他所有蓝(1)条段、绿(3)轨道点保持不变。

**关键洞察**：精灵体不是简单地"前进一个槽位"（源题规则），而是在轨道上搜索到两侧条段等距的唯一平衡位置。条段是局部的（非贯穿行），所以不同轨道点"看到"的最近条段可能不同——平衡点的位置取决于条段的水平覆盖范围与轨道点的列对齐关系，这是一个非显然的几何搜索问题。
