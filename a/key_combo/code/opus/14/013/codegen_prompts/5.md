## 新题 5：十字检测定位描边框架与内部擦除

**组合逻辑**：[模式检测](已有：检测 '+' 十字) → [描边](创新：边框不画在画布边界，而是以十字中心为圆心动态确定尺寸) → [擦除](创新：由描边框架的覆盖范围决定擦除目标) + [邻域全匹配](已有) + [画布边界](已有)

**来源原语**：模式检测·十字图案·前景对象·邻域全匹配(1818057f), 描边·画布边界(6f8cd79b), 擦除·仅保留中轴(d23f8c26), 包围框(d56f2372)

**依赖链**：十字检测确定边框的中心位置和数量；每个十字中心到最近网格边缘的距离确定边框的半径；边框围合的区域定义擦除范围——框内非十字的前景像素被清除。去掉十字检测无法确定边框位置；去掉描边则检测结果无法驱动几何变换；去掉擦除则描边仅是叠加，不产生信息变换。三者形成检测→生成→过滤的紧耦合链。

检测前景中的 '+' 十字图案，以每个十字中心为中心绘制正方形边框，框内的非十字前景像素被擦除。

**输入结构**：约 15x15 网格，背景黑(0)。大量蓝(1) 前景像素构成若干 4-连通区域，形态各异（有的紧凑，有的细长，有的带分支，3~12 像素不等）。其中部分位置自然形成 '+' 十字图案：一个蓝(1) 像素的上下左右四个正交邻居也都是蓝(1)。十字图案可能嵌入在更大的前景区域中，也可能恰好是孤立的 5 像素十字。生成约束：十字中心之间的曼哈顿距离 >= 6，保证以下规则产生的边框互不重叠。

**规则**：
1. 扫描所有蓝(1) 像素，找出满足"上下左右四个正交邻居均为蓝(1)"的像素，标记为十字中心。
2. 对每个十字中心 (r, c)，计算其到四条网格边缘的最小距离：d = min(r, c, H-1-r, W-1-c)，其中 H、W 为网格高度和宽度。
3. 以 (r, c) 为中心，绘制边长为 2d+1 的正方形边框（单像素宽），颜色为绿(3)。边框的四条边分别位于 r-d 行、r+d 行、c-d 列、c+d 列，四角共享。若边框像素位置上已有内容（蓝(1) 或其他），覆盖为绿(3)。
4. 对每个十字中心，将其边框**严格内部**（不含边框线本身）所有非十字的蓝(1) 像素擦除为黑(0)。"十字像素"指十字中心本身及其上下左右四个邻居共 5 个像素，这些保留蓝(1) 不擦除。
5. 边框外部的蓝(1) 前景像素保持不变。

**关键洞察**：十字图案在参考题中仅用于重涂色标记，这里十字变成了几何操作的定位锚点——不仅定位边框中心，还通过自身到边界的距离编码了边框的缩放尺寸。框内擦除进一步依赖十字的精确位置来豁免十字自身，形成"检测→定参→保护性擦除"的三层耦合。
