## 新题 6：块网格反转后的环形循环移色

**组合逻辑**：[反转编码/精灵与空白互逆](源自 6350f1f4，反转产生新的环形精灵实例) + [循环移色/角与边中分组](源自 46c35fc7，作用于反转后新出现的环形) + [修复/通配符视为空](源自 6350f1f4，灰色擦除需恢复)

**来源原语**：反转编码/invert_code(6350f1f4), 循环移色/color_cycle(46c35fc7), 修复/repair(6350f1f4), 块网格/block_grid(6350f1f4), 重复精灵体/repeated_sprite(6350f1f4), 均匀空白块/uniform_blank(6350f1f4), 精灵与空白互逆/sprite_blank_inv(6350f1f4), 环形前景/ring_object(46c35fc7), 角位像素/corner_pixel(46c35fc7), 边中像素/side_center_pixel(46c35fc7), 反向循环/opposite_cycle(46c35fc7), 通配符视为空/wildcard_as_blank(6350f1f4)

**依赖链**：识别完整环形精灵 → 反转编码（环形块变实心、空白块变环形）→ 新产生的环形执行循环移色 → 灰色擦除在反转前需忽略、在输出中恢复为正确颜色。反转产生了循环移色的目标对象——不反转就没有需要移色的环；不移色则反转后的环保持原始配色（输出错误）。

将块网格中的环形精灵和空白块互换编码后，对新产生的环形精灵执行一步角-边反向循环移色。

**输入结构**：约 13x13 的网格，由黑(0)单像素宽分隔行和分隔列划分为 3x3 的块阵列（共 9 个块，每个块 3x3 像素）。精灵为一个 3x3 环形（8 个前景像素围绕 1 个黑(0)中心），环形的 8 个像素使用 2~4 种不同前景色（非黑非灰，如蓝(1)、红(2)、绿(3)、黄(4)等），其中角位和边中位颜色各异。空白块为精灵所使用的某一种颜色的 3x3 纯色块。部分块中可能有灰(5)像素替代了原本应有的颜色（擦除/通配符）。生成约束：至少有一个完整无灰色擦除的环形块（用于推断精灵模板）；环形块和空白块各至少 3 个。

**规则**：
1. 从所有无灰色像素的混色块中推断出完整的 3x3 环形精灵模板（包含每个位置的精确颜色）。
2. 反转编码：将每个匹配精灵模板的块（含灰色擦除的块也算匹配，灰色位置视为通配符）替换为该精灵多数色的 3x3 纯色块。将每个纯色空白块替换为精灵模板的完整副本。
3. 对步骤 2 中新放置的每个环形精灵副本，执行一步循环移色：四个角位像素的颜色沿顺时针方向循环移动一位（左上→右上→右下→左下→左上）；四个边中位像素的颜色沿逆时针方向循环移动一位（上中→左中→下中→右中→上中）。
4. 分隔行和分隔列上的所有像素（包括曾被灰色擦除的）恢复为黑(0)。

**关键洞察**：环形精灵在输入中同时是编码符号（标记"开"状态的块）和结构化对象（角位/边中有不同颜色）。反转后空白块变成环形，这些新环形才是循环移色的目标——原始环形块被替换为纯色块，不再参与移色。精灵的双重身份使两个操作深度耦合。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
