## 新题 6：坐标轴约束旋转方向后嵌入框架槽

**组合逻辑**：[嵌入对齐(insert_and_align)](创新：嵌入对象不是凸起条，而是多个独立矩形) + [轴色决定旋转(axis_color_determines_rotation)](创新：旋转不再统一应用于所有对象，而是按对象与轴的相对位置选择性应用) + [列对齐(column_alignment)](已有) + [凸起匹配标记列(projections_match_columns)](创新：匹配的不是凸起与标记列，而是矩形宽度与槽内间隔宽度)

**来源原语**：嵌入对齐/框架槽/凸起条/列对齐/凸起匹配标记列(4c3d4a41), 轴色决定旋转/坐标轴线/矩形/距离排序(291dc1e1)

**依赖链**：坐标轴线颜色决定旋转规则 → 对每个矩形判断是否需要旋转 → 旋转后的矩形尺寸决定它能嵌入哪个框架槽间隔 → 按宽度匹配将矩形插入对应间隔。删掉坐标轴则不知道旋转规则；删掉旋转则矩形尺寸错误、无法匹配框架槽；删掉嵌入对齐则旋转后的矩形无处放置。

根据坐标轴线颜色确定矩形旋转方式，旋转后按宽度匹配嵌入灰色框架的对应间隔中。

**输入结构**：黑(0)背景，约 18x18 网格。网格左边缘有一条完整的垂直彩色线（蓝(1)或红(2)，占满该列所有行），网格上边缘有另一条完整的水平彩色线（与垂直线颜色不同），两线交汇于左上角一个栗(9)色像素。网格下半部分有一个灰(5)色矩形框架（一像素宽边框，内部为黑色，约 3x14），框架内部被 2~3 条垂直灰色隔板分成 3~4 个宽度不等的间隔（每个间隔宽度 2~4 像素，高度均等于框架内部高度）。网格中部散布 3~4 个实心彩色矩形（颜色各不相同，从黄(4)、绿(3)、橙(7)、品红(6)中取），每个矩形宽高均在 1~4 像素范围内。生成约束：蓝(1)线始终为垂直线或水平线之一（不固定）。每个彩色矩形在需要旋转时（见规则），旋转后的宽度恰好等于某个框架间隔的宽度，且这种匹配是一一对应的（无两个旋转后矩形宽度相同、也无两个间隔宽度相同——或者宽度相同时高度可区分）。

**规则**：
1. 识别两条边缘线的颜色。将蓝(1)线所在方向记为"蓝轴方向"。
2. 若蓝轴为垂直方向（左边缘是蓝线），则对每个彩色矩形执行 90 度逆时针旋转（行列互换，原来的列变行、原来的行变列，宽高交换）。若蓝轴为水平方向（上边缘是蓝线），则不旋转。
3. 将旋转后（或未旋转）的每个矩形与框架间隔按宽度匹配：矩形的宽度必须等于间隔的宽度。（生成保证每个矩形恰好匹配一个间隔。）
4. 将匹配的矩形放入对应间隔内：矩形水平居中于间隔（若矩形宽度等于间隔宽度，则左右对齐），矩形底边与间隔底边对齐（重力向下放置）。
5. 保留框架和隔板。擦除矩形的原始位置（恢复为黑色）。保留两条边缘线和栗色角标。

**关键洞察**：坐标轴线不直接参与视觉输出，而是编码了一个全局旋转指令——只有正确解读轴色才能得到正确的矩形尺寸，进而才能完成宽度匹配和嵌入对齐。
