## 新题 4：十字扩展生成引导臂并按臂类型决定接触重涂

**组合逻辑**：[扩展](十字图案的臂色和中心色分别沿正交和对角方向无限延伸至网格边界) + [正交对角分工](创新：扩展后的正交臂和对角臂承担不同的"引导线"角色) → [接触判定](检测延伸线与散布的精灵体是否接触) → [重涂色](创新：被正交臂接触的精灵体涂为一种颜色，被对角臂接触的涂为另一种颜色；同时被两种臂接触的涂为第三种颜色)

**来源原语**：扩展、十字图案、正交对角分工、臂色中心色分延(0962bcdd)；连线/引导线(0d87d2a6)；接触判定、接触则重涂、前景对象(0d87d2a6)；重涂色(12eac192)

**依赖链**：十字的两种颜色分别沿正交和对角方向延伸至边界，形成两类引导线 → 每个散布的精灵体被检测是否与引导线 4-邻接接触 → 接触类型（仅正交 / 仅对角 / 两者都有）决定重涂目标色 → 精灵体的最终颜色编码了它与十字之间的空间角度关系

十字的正交臂和对角臂延伸为两类引导线；散布的小图形按接触的引导线类型被重涂为不同颜色。

**输入结构**：约 20x20 的黑(0)背景网格。网格中央偏左上方有一个 3x3 的十字图案：四个正交臂像素为蓝(1)，中心像素为红(2)。网格中散布 5~7 个小型 4-连通单色图形（精灵体），每个由 3~6 个灰(5)像素组成，形状各异（不规则，非矩形），互不相邻且不与十字相邻。精灵体的位置经过设计：一部分仅在十字的正交方向延长线附近（上下左右），一部分仅在对角方向延长线附近（四个 45 度方向），一部分同时靠近正交和对角延长线的交叉区域。生成约束：每种接触类型（仅正交、仅对角、两者兼有）至少各有 1 个精灵体；精灵体不位于十字的正交或对角延长线正上方（不被延伸线穿过），只在旁边与延伸线 4-邻接接触。

**规则**：
1. 从十字中心出发，沿上、下、左、右四个正交方向，逐像素延伸蓝(1)线直到网格边界（覆盖路径上的黑色像素，但不覆盖已有的非背景像素——若遇到非背景像素则跳过该像素继续延伸）。
2. 从十字中心出发，沿左上、右上、左下、右下四个对角方向，逐像素延伸红(2)线直到网格边界（同样跳过非背景像素继续延伸）。
3. 对每个灰(5)精灵体，检查其所有像素的 4-邻域中是否存在蓝(1)延伸线像素和/或红(2)延伸线像素。
4. 若精灵体仅与蓝(1)正交臂接触（4-邻域中有蓝(1)延伸像素但无红(2)延伸像素），将整个精灵体重涂为绿(3)。
5. 若精灵体仅与红(2)对角臂接触（4-邻域中有红(2)延伸像素但无蓝(1)延伸像素），将整个精灵体重涂为黄(4)。
6. 若精灵体同时与蓝(1)和红(2)延伸线接触，将整个精灵体重涂为橙(7)。
7. 若精灵体与两类延伸线均不接触，保持灰(5)不变。
8. 十字本身（3x3 区域）保持原样不变。

**关键洞察**：十字扩展中的"臂色/中心色角色分工"不再仅仅决定生长方向，而是直接编码了两个语义不同的"引导线系统"——正交系统和对角系统。精灵体的重涂颜色由它处于哪个系统的辐射范围内决定，相当于十字将空间划分为正交区、对角区和交叉区三个语义区域。需要对比多个示例才能区分"接触任一类型即涂同色"和"按接触类型分色"。

import hashlib
import numpy as np

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/4/040/4.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
