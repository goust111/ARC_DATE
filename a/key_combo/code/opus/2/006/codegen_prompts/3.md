## 新题 3：图例串扩展决定腔室填色

**组合逻辑**：[expand/legend_anchored_alignment](已有) → [fill/adjacent_majority_vote](创新：投票对象不是原始标记像素，而是扩展后被腔室墙壁裁剪的图例碎片)

**来源原语**：edge_legend_string、isolated_marker、color_position_matching、legend_anchored_alignment（5af49b42）；connected_chamber、separator_wall、fill、adjacent_majority_vote（7c8af763）

**依赖链**：不扩展图例就无法在腔室内产生足够的颜色分布来做多数投票；不检测腔室边界就不知道在哪裁剪扩展串；裁剪方式直接决定多数颜色，所以标记在腔室中的水平位置实质性影响最终结果。

在墙壁分隔的腔室内，将孤立标记像素扩展为图例串的片段（被墙壁裁剪），然后按各腔室中占多数的颜色填充整个腔室。

**输入结构**：约15x15网格。灰(5)墙壁将网格分隔为4~6个不规则腔室（4-连通的黑(0)区域）。网格最顶行（第0行）是一条水平图例串，由4~5个不同前景色像素排成一行（如蓝(1)、红(2)、绿(3)、黄(4)、橙(7)，从左至右各占一格），图例串紧贴左侧排列，其余顶行格为黑(0)。图例行下方由灰(5)墙分隔的各腔室内，每个腔室含1~2个孤立单像素标记，其颜色取自图例中某个位置的颜色。生成约束：每个腔室的水平跨度至少为3格；每个腔室中若有2个标记则颜色不同。

**规则**：
1. 识别灰(5)墙壁下方各4-连通的黑(0)腔室。
2. 对每个腔室中的每个孤立标记像素：在图例串中定位其颜色所在的列索引k（0起始）。将完整图例串水平复制到该标记所在行，平移使图例的第k格落在标记像素的列位置上。仅保留落在该腔室内部（不包含墙壁格和腔室外格子）的部分，其余裁剪丢弃。
3. 同一腔室内多个标记的扩展若有像素重叠：按标记像素行号升序处理，行号相同按列号升序，后处理的覆盖先处理的。
4. 扩展完成后，对每个腔室统计所有非黑(0)像素的颜色频率。将该腔室的全部黑(0)像素填充为出现次数最多的颜色；若存在平局，选择在图例串中位置靠左的颜色。
5. 灰(5)墙壁和图例行保持不变。扩展产生的非黑像素在填充后被填充色覆盖（即腔室内最终全为同一颜色）。

**关键洞察**：标记像素的扩展不是最终输出——它只是向腔室投射了颜色"选票"。腔室宽度和标记的水平位置共同决定哪些图例颜色被裁剪掉、哪些留下，从而改变多数投票的结果。相同颜色的标记在不同宽度的腔室中可能导致不同的填充色。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
