## 新题 9：缩放锚点决定框架尺寸与遮挡序决定内部分区涂色

**组合逻辑**：[缩放/尺寸比编码缩放](创新：锚点尺寸比决定绘制框架的大小而非缩放已有图案) + [描边/draw_frame](已有) → [遮挡层序/重叠定先后](创新：绘制出的框架之间的重叠产生新的遮挡关系) + [分区涂色/按边界框内外分色](创新：遮挡序决定各框架内部的分区着色方案)

**来源原语**：缩放/尺寸比编码缩放(b10624e5) + 描边/draw_frame/极值内缩定边框(928ad970) + 遮挡层序(68bc2e87) + 分区涂色/按边界框内外分色(137f0df0) + 内部与边框(bb43febb)

**依赖链**：锚点方块的尺寸比 → 决定各框架的绘制大小 → 框架绘制后产生重叠 → 重叠处的可见规则产生遮挡序 → 遮挡序决定每个框架内部用什么颜色填充。删除缩放计算则框架大小不确定，删除框架绘制则无遮挡可分析，删除遮挡序则内部颜色不确定。

根据锚点方块的尺寸比绘制不同大小的同心空心矩形框，再由框架之间的重叠遮挡顺序决定各框架内部的填充颜色。

**输入结构**：黑(0)背景网格，约 18x18。网格中散布 3~4 个实心正方形锚点方块，每个方块使用不同颜色（如红(2)、蓝(1)、绿(3)、黄(4)），边长各不相同（如 1x1、2x2、3x3）。所有锚点方块的几何中心大致位于网格中心附近（距离网格中心不超过 3 格），但互不接触。网格边缘有一个参考方块：一个橙(7)的 1x1 像素，旁边一个灰(5)的空心矩形框（4x4，即外边长为 4 的一像素厚矩形环），表示"1x1 锚点对应 4x4 框架"。生成约束：按尺寸比计算出的各框架都能放入网格内（以各自锚点的中心为框架中心）。各框架至少两两之间存在空间重叠。

**规则**：
1. 识别参考方块（橙(7)）和参考框架（灰(5)空心矩形）。参考方块边长 = 1，参考框架外边长 = 4。基础缩放比 = 4/1 = 4。
2. 对每个彩色锚点方块，计算其框架的外边长 = 锚点边长 x 基础缩放比。以该锚点的几何中心为框架中心，绘制一个该边长的一像素厚空心矩形框，颜色与锚点相同。
3. 绘制顺序按锚点边长从大到小（边长大的先绘制，即框架大的先绘制，作为底层）。后绘制的框架线覆盖先绘制的。
4. 绘制完成后，从框架线的重叠处确认遮挡层序：边长小的锚点对应的框架在上层（后绘制的覆盖先绘制的），即锚点越小，框架层级越高。
5. 对每个框架的内部区域（框架线围成的空间，不含框架线本身）：
   - 如果该框架是最顶层（rank最高）：内部保持黑(0)不变。
   - 如果该框架不是最顶层：内部填充为紧邻其上一层框架的颜色。
6. 内部填充时，已有的框架线像素和锚点方块像素不被覆盖。填充仅涂在当前为黑(0)的内部格子上。
7. 参考方块和参考框架区域保持不变。

**关键洞察**：锚点尺寸比不仅决定了框架大小（大锚点=大框架=底层），还隐式决定了遮挡顺序（小框架覆盖大框架），而遮挡顺序又反向决定了每个框架内部的填充颜色（填充色来自其上层邻居）。尺寸、遮挡、着色三者构成链式因果，在任何单一源题中都不存在。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/2/003/9.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
