## 新题 8：互补矩形填充与交叉图案冲突解决

**组合逻辑**：[互补拼合/complement_fit + 填充/fill](创新：两组碎片各自拼合的矩形存在空间重叠) + [行列交叉/row_col_intersection](创新：重叠区不做简单覆盖，而是画两矩形中心的交叉图案) + [计数/counting → 重涂色/recolor](创新：重叠区的图案颜色由两组碎片的像素数比较结果决定)

**来源原语**：互补拼合(fe45cba4)、碎片(fe45cba4)、填充(56ff96f3)、矩形(56ff96f3)、行列交叉(23581191)、交叉点特殊着色(23581191)、计数(f8ff0b80)、重涂色(多源)

**依赖链**：碎片拼合确定两个矩形的位置和尺寸（拼合→矩形）；两矩形的重叠区域触发冲突解决机制而非简单覆盖（重叠检测→冲突模式切换）；冲突区域绘制以两矩形中心为锚点的十字图案（矩形中心→十字位置）；十字的颜色由两组碎片的总像素数比较决定，像素多的颜色画十字（计数→颜色选择）。这是一个同时约束满足结构：填充和冲突解决必须同时考虑。

两对碎片各自拼成矩形并填充，重叠区绘制以矩形中心为锚的十字图案，十字颜色取像素数更多的碎片组。

**输入结构**：黑(0)背景上约 16x16 的网格。两种前景色（红(2)和绿(3)），每种颜色有 2 个 4-连通碎片。红色的两个碎片互补拼合为一个实心矩形 R_red；绿色的两个碎片互补拼合为一个实心矩形 R_green。每种颜色中，一个碎片触及左边缘，另一个不触边。R_red 和 R_green 的边界框有部分重叠（重叠区域面积 >= 4 个像素），但都不完全包含另一个。红色碎片的总像素数与绿色碎片的总像素数不相等。

**规则**：
1. 对每种颜色，找到触左边缘的碎片（移动件）和不触边的碎片（锚件），计算唯一平移使两者并集为实心矩形。擦除移动件原位，将其绘制到拼合位置。
2. 计算两个矩形的重叠区域 O = R_red 交 R_green。
3. 非重叠区域：R_red 独占区填充红(2)，R_green 独占区填充绿(3)。
4. 重叠区域 O 的处理：
   a. 计算 R_red 的中心坐标 (cr_r, cc_r) 和 R_green 的中心坐标 (cr_g, cc_g)（中心取边界框中心，向下取整）。
   b. 在 O 区域内，将位于 cr_r 行或 cc_r 列的像素，以及位于 cr_g 行或 cc_g 列的像素，涂为"胜出色"——胜出色为两组碎片中总像素数更多的那组的颜色。
   c. O 区域内不在上述行/列上的像素涂为另一组的颜色（"落败色"）。
5. 矩形区域之外保持黑(0)。

**关键洞察**：重叠区域不是简单的颜色覆盖，而是生成了一个新的几何图案（十字）——这个图案的位置由两个矩形各自的中心确定，其颜色由像素数量的全局比较确定。必须对比多个示例中不同的像素数大小关系才能归纳出"多者胜出"规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
