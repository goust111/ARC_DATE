## 新题 5：十字定位旋转印章

**组合逻辑**：[十字图案 → 对称轴定义](提取旋转中心与调色板) + [旋转](根据标记像素所在象限确定旋转角度) + [印章覆盖](将旋转后的图案印在标记位置)（创新：象限位置隐式编码旋转角度，十字同时提供中心参考和着色来源）

**来源原语**：十字图案(cross_pattern) ← 47c1f68c；对称轴定义(symmetry_axis_def) ← 47c1f68c；十字色作涂色源(cross_as_palette) ← 47c1f68c；旋转(rotate) ← 1b60fb0c/6150a2bd；印章覆盖(stamp) ← 88a10436；标记像素(marker_pixel) ← 88a10436/ded97339；中心对齐(center_align) ← 88a10436

**依赖链**：十字提供旋转参考中心和印章颜色 -> 标记像素的象限位置编码旋转角度 -> 旋转后的图案以标记为中心印章。移除十字、判断象限、执行旋转、着色印章四个环节紧密耦合。

移除中心十字后，将左上角的图案按标记像素所在象限对应的旋转角度印章到各标记位置，印章颜色采用十字色。

**输入结构**：奇数边长的正方形网格（约 11x11 至 15x15），背景黑(0)。一条完整的水平线和一条完整的垂直线以橙(7)交叉于网格中心，形成十字。左上象限内有一个蓝(1)小图案（4-连通，3-6 像素，不触及十字线，边界框为奇数行奇数列以确保有明确中心像素）。其他三个象限内各有 0 或 1 个绿(3)标记像素（总共 1-3 个标记），标记不在十字线上。生成约束：每个标记到十字中心的距离足够大，使得以标记为中心印章图案时不会超出网格边界；不同标记的印章区域互不重叠。

**规则**：
1. 记录十字中心坐标，然后擦除整条十字线（橙(7) -> 黑(0)）。
2. 保持左上象限的蓝(1)源图案不变。提取该图案的边界框内容作为印章模板（框内黑(0)像素视为透明）。
3. 对每个绿(3)标记像素，判断其相对于原十字中心所在的象限：
   - 右上象限：将模板顺时针旋转 90 度。
   - 右下象限：将模板旋转 180 度。
   - 左下象限：将模板顺时针旋转 270 度。
4. 将旋转后的模板以绿(3)标记像素为中心印章到网格上。印章中所有非透明像素着色为橙(7)（十字色），覆盖该位置原有内容（包括绿标记本身）。
5. 若多个印章区域有重叠（生成时已保证不重叠，此条为完备性声明），后处理的象限（按右上、右下、左下顺序）覆盖先处理的。

**关键洞察**：每个标记像素的象限位置隐式编码了旋转角度（右上=90、右下=180、左下=270），而十字既提供定位参考又提供着色来源。求解者需要从多个示例中归纳象限-角度的对应关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
