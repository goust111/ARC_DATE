## 新题 6：格子编码门控链式填充

**组合逻辑**：[块解码为掩码](格子指令区解码为二值控制矩阵) + [形状匹配+拼接](精灵体匹配凹槽) + [链式填充](由解码掩码逐行门控链延伸)（创新：格子掩码不直接作用于像素，而是作为链式填充过程的"程序"，控制每条链的延伸步数）

**来源原语**：格子分割(lattice_partition) ← 15113be4；块解码为掩码(decode_block_to_mask) ← 15113be4；指令区域(instruction_region) ← 15113be4；拼接(assemble) ← 16b78196；链式填充(chain_fill) ← 16b78196；凹槽(notch) ← 16b78196；形状匹配(shape_matching) ← 16b78196；固定条带宽度(fixed_strip_width) ← 16b78196

**依赖链**：指令区域解码 -> 二值控制矩阵的列对应凹槽、行对应链步数 -> 精灵体匹配凹槽后启动链式填充 -> 每条链在控制矩阵对应位为 0 时截断。掩码解码结果直接改变链式填充的终止条件。

格子编码的指令区作为"程序"控制链式填充的步数：精灵体拼入横杆凹槽后沿链方向延伸，每走一步查询掩码，遇 0 则停。

**输入结构**：网格约 20x20，背景黑(0)。网格中部有一条灰(5)水平实心横杆（宽度占网格大部分，高 2-3 行）。横杆上边缘有 3 个凹槽（从横杆顶边向上凹入的矩形缺口，每个宽 2-4 列、深 1-2 行），凹槽间至少隔 2 列。横杆上方散布 3 个小精灵体（每个为单色 4-连通区域，3-8 像素，颜色各不相同且非灰(5)非黑(0)非黄(4)），每个精灵体的形状恰好能嵌入一个凹槽（精灵体的底部轮廓与凹槽形状互补）。网格左上角有一个 6x6 的指令区域，内部由黄(4)线分隔为 3x3 的格子，每个格子为 2x2 单元。部分格子内填充红(2)的 2x2 实心块（标记为 1），其余格子为黑(0)（标记为 0）。生成约束：指令区域的第一行（顶行的 3 个格子）至少有 1 个为 1；凹槽从左到右对应指令区域的列 0、1、2。

**规则**：
1. 解码指令区域：将 6x6 区域按黄(4)网格线分割为 3 列 x 3 行的格子。每个格子若包含红(2)的 2x2 块则为 1，否则为 0。得到一个 3x3 的二值控制矩阵 M，其中 M[row][col] 对应行 row（0=顶行）、列 col（0=左列）。
2. 将 3 个凹槽从左到右编号为 0、1、2，对应控制矩阵的列 0、1、2。
3. 对每个凹槽，找到形状匹配的精灵体（精灵体翻转后底部轮廓恰好填满凹槽）。将精灵体移入凹槽位置，这是链的第 0 步（根节点）。第 0 步始终执行（不受掩码控制）。
4. 链式向上延伸：第 s 步（s = 1, 2）时，检查控制矩阵 M[s][col]。若为 1，在前一步精灵体的正上方放置该精灵体的一个副本（形状、颜色不变，边界框底边紧接前一步边界框顶边）。若为 0，该链在此步停止，不再继续。
5. 擦除指令区域（恢复为黑(0)），擦除精灵体原始位置。

**关键洞察**：格子指令区不直接标记输出像素——它编码了一个"执行程序"，控制每条链延伸多远。不同凹槽的链可以有不同长度，取决于其对应列的掩码值分布。
