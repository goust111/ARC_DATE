## 新题 4：外推动画帧后统计频率绘制柱状图

**组合逻辑**：[序列外推(sequence_extrapolation)](已有：从多帧恒定偏移推断下一帧) + [计数(counting)](已有) + [排序(sort)](已有) → 柱状图输出格式(创新：跨越"空间预测"与"统计摘要"两种表征)

**来源原语**：序列外推/面板帧/分隔行/前景精灵/等距堆叠/恒定偏移平移(来自 351d6448)；计数/排序/前景像素/柱状图/频率排序/频率降序柱状图(来自 9af7a82c)

**依赖链**：计数和排序的输入数据不是直接可见的——它来自一个需要先外推出来的第四帧。而且外推过程中，部分像素可能因平移超出面板边界而丢失，这使得第四帧的颜色频率与前三帧不同（不能简单复制）。频率的正确值取决于空间外推中的边界裁切效应。若跳过外推，没有待统计的帧；若跳过统计，无法得到柱状图输出格式。

三帧动画条中，各色像素群按恒定向量逐帧平移；外推出不可见的第四帧后，统计该帧中各颜色的像素数量，按降序绘制为柱状图。

**输入结构**：网格约 8x26。三个等大面板（每个约 8x8）由灰(5)全宽分隔行上下堆叠。每个面板有黑(0)背景，其中散布 3-4 种颜色的像素群（例如红(2)、蓝(1)、绿(3)、黄(4)），每种颜色有 2-5 个像素构成一个 4-连通群组。从第一帧到第二帧、第二帧到第三帧，每种颜色群组均按相同的恒定向量 (dr, dc) 平移（不同颜色的平移向量可以不同）。生成约束：(a) 前三帧中所有像素均在面板边界内；(b) 第四帧外推时，至少有一种颜色的部分像素会超出面板边界（被丢弃），使得第四帧的频率与第三帧不同；(c) 第四帧中至少保留 2 种颜色。

**规则**：
1. 识别灰(5)分隔行，将输入分为三个 8x8 面板。
2. 对每种非黑非灰颜色，比较其在相邻帧中的像素位置，计算恒定平移向量 (dr, dc)。
3. 将第三帧中的每种颜色群组再平移一次 (dr, dc)，生成第四帧。超出 8x8 面板边界的像素丢弃。
4. 统计第四帧中每种颜色占据的像素数。
5. 将颜色按像素数降序排列。若两种颜色像素数相同，将它们的群组在第四帧中的最上最左像素按行优先序比较，靠前者排在左边。
6. 输出一个柱状图网格：宽度 = 存活颜色数，高度 = 最大像素数。黑(0)背景。第 k 列（从左起第 0 列开始）对应排名第 k 的颜色，从顶行起向下填充该颜色，填充行数 = 该颜色的像素数。

**关键洞察**：被统计的那一帧并不直接可见——它是空间外推的产物。关键的非显然之处在于边界裁切：某些颜色的像素在第四帧中被"推出"了面板，导致其频率下降甚至消失。仅观察前三帧的频率趋势（线性不变）无法预测第四帧频率，必须先做空间外推再做统计。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/2/046/4.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
