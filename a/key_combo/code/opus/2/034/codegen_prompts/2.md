## 新题 2：滑动后包围框吞噬

**组合逻辑**：[slide + notch_determines_dir](已有) → [bbox_containment → erase](已有，但作用于滑动后的新位置，创新点在于包含关系是滑动的涌现结果) → [recolor](已有)

**来源原语**：slide、notch_determines_dir、edge_aligned（来自 320afe60）；erase、bbox_containment、delete_if_contained_by_other_color（来自 9720b24f）；recolor（来自多题）

**依赖链**：缺口检测决定滑动方向 → 滑动改变对象位置 → 新位置产生的包围框包含关系决定哪些对象被擦除 → 存活对象按其滑动方向染色。删除滑动步骤则位置不变、无新包含关系；删除包含检测则无法确定哪些对象消失。

带缺口的对象滑向右边缘、无缺口的滑向左边缘，滑动后若一个对象的包围框落入另一个的包围框内则被擦除，存活者按滑动方向染色。

**输入结构**：黄(4)背景网格，约 15x15。网格中有 4~6 个蓝(1)的 4-连通单色对象，每个对象占 4~12 像素，形状各异（不规则连通体，非简单矩形）。部分对象的包围框边界上存在由背景色构成的"缺口"——即该边界行/列上有背景像素位于两个对象像素之间。各对象在输入中互不接触，且包围框互不包含。生成约束：对象的尺寸和初始位置经过选择，使得滑动后恰好产生 1~2 对包围框包含关系；滑动路径上不会有其他对象阻挡。

**规则**：
1. 检查每个蓝(1)对象的包围框四条边界。若任一边界行或列上，存在背景像素位于该行/列上两个对象像素之间（即缺口），则该对象标记为"有缺口"。
2. 有缺口的对象向右滑动，保持行跨度不变，直到其包围框右边缘与网格右边缘齐平。无缺口的对象向左滑动，直到包围框左边缘与网格左边缘齐平。
3. 在所有对象滑动完成后的新位置上，计算每个对象的包围框。若对象 A 的包围框完全落在对象 B 的包围框内部（四条边均严格在 B 的对应边以内或重合），且 A 的像素数少于 B，则擦除 A（所有像素设为黄(4)背景）。
4. 存活的右滑对象重涂为绿(3)；存活的左滑对象重涂为红(2)。
5. 背景保持黄(4)不变。

**关键洞察**：输入中各对象的包围框互不包含，但滑动将它们压缩到网格两侧后产生了新的包含关系——需要推断出包含检测发生在滑动之后而非之前。
