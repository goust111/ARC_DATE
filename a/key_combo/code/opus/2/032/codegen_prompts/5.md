## 新题 5：边缘滑动旋转与标记色轨迹

**组合逻辑**：[滑动/slide + 接触边缘/touching_edge + 滑至对侧边缘/slide_to_opposite](已有) → [旋转/rotate](创新：旋转对象从"十字形载荷"改为"任意图案块的内部像素排列") → [嵌入标记像素/embedded_marker](创新：标记像素从"配对目标"改为"轨迹颜色编码")

**来源原语**：滑动+接触边缘+滑至对侧边缘+边缘矩形+轨迹条纹(b25e450b), 旋转+抵达边界(99caaf76), 嵌入标记像素+颜色配对(54dc2872)

**依赖链**：边缘接触方向决定滑动方向（删除边缘检测则不知道往哪滑）；滑动到对侧后图案块 180 度旋转（删除旋转则目标端图案错误）；嵌入标记像素的颜色决定滑动轨迹的颜色（删除标记则轨迹颜色无法确定）。三个机制分别控制方向、目标形态、路径外观，缺一则输出不完整。

带有嵌入标记像素的小图案块从接触的网格边缘滑向对侧，到达后内部像素旋转 180 度，滑过的路径用标记像素的颜色绘制轨迹。

**输入结构**：
- 网格约 16x16，背景灰(5)。
- 2-4 个小矩形图案块，每块 3x3 或 3x4 像素。每块的大多数像素为同一种非灰颜色（体色，如蓝(1)、绿(3)、黄(4)），另有恰好 1 个像素为不同的非灰颜色（嵌入标记色，如红(2)、橙(7)、栗(9)），标记色在所有图案块中各不相同。
- 每个图案块恰好接触网格的一条边界（上、下、左、右之一），即图案块的一条边与网格边缘重合。
- 不同图案块接触不同的边界（不会有两个块接触同一条边界），且它们的滑动路径互不交叉。滑动路径指：从块的当前位置到对侧边界之间，与块宽度（或高度）相同的矩形条带。
- 生成约束：各图案块的滑动路径（从起点到对侧边界的条带）互不重叠；每个图案块内恰好 1 个标记像素。

**规则**：
1. 对每个图案块，确定它接触的网格边界。接触上边界→向下滑动；接触下边界→向上滑动；接触左边界→向右滑动；接触右边界→向左滑动。
2. 将图案块沿确定方向平移，直到其边界框的对侧边与网格对应边界重合（即滑到底）。
3. 在目标位置放置图案块时，将块内像素排列做 180 度旋转（等价于同时做上下翻转和左右翻转）。标记像素也参与旋转，其在块内的相对位置随之改变。
4. 图案块滑过的区域（起始位置与目标位置之间的所有像素行/列，不含起始位置和目标位置本身）全部涂为该图案块的嵌入标记色。轨迹条带的宽度等于图案块在垂直于滑动方向上的尺寸。
5. 所有图案块同时滑动。由于生成约束保证路径不交叉，无需冲突解决。
6. 起始位置的图案块被移走后恢复为灰(5)背景。

**关键洞察**：嵌入标记像素在源题 54dc2872 中用于配对精灵体与目标控制点，在此处承担全新角色：编码轨迹颜色。旋转机制从源题 99caaf76 的"十字形载荷"泛化为任意矩形图案。标记像素同时存在于旋转后的目标图案中（位置改变）和轨迹中（颜色相同），形成视觉上的连贯线索。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/2/032/5.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
