## 新题 5：对角平移改变行占用后跨面板压缩

**组合逻辑**：[translate](青角指示对角平移) → [compress](跨面板逆序扫描行压缩)

**来源原语**：translate / filled_rectangle / control_pixel / corner_indicates_dir / diagonal_fixed_step（来自 470c91de）；compress / concatenate / panel / divider_column / occupied_row / reverse_scan / empty_rows_discarded（来自 25c199f5）

**依赖链**：对角平移改变了每个面板中哪些行被占用（occupied_row）。行压缩只保留有内容的行，因此平移结果直接决定了压缩的输入。若不先平移就压缩，会保留不同的行集合，得到错误输出。两步操作通过"行占用状态"这一中间量紧密耦合。

在每个面板内将矩形按青色角指示的对角方向平移一格，然后从右到左扫描面板，仅保留有内容的行并压缩到单个面板底部。

**输入结构**：
- 背景为黑(0)，网格约 12x20（较高）
- 栗(9)分隔列（1 像素宽）将网格分为 2-3 个等宽面板，每个面板宽约 4-6 像素
- 每个面板内有 1-3 个小实心矩形（2x2 到 3x4 像素），颜色取自蓝(1)、绿(3)、黄(4)、灰(5)、橙(7)（同一面板内颜色不重复）
- 每个矩形有恰好一个角像素被替换为青(8)，表示对角平移方向（例如青在右上角 = 向右上平移 1 格）
- 面板内有足够空行，使平移后矩形不越出面板边界且不与其他矩形重叠
- 生成约束：平移后所有矩形保持在各自面板内；平移后无重叠；每个面板至少有 1 行在平移后变为全黑（保证压缩有效果）

**规则**：
1. 在每个面板内独立处理：对每个矩形，识别青(8)角像素在矩形四角中的位置，确定对角方向（左上→向左上 1 格、右上→向右上 1 格、左下→向左下 1 格、右下→向右下 1 格）
2. 擦除矩形原始位置（包括青像素），将完整矩形（青像素位置恢复为矩形本色）绘制在平移后的位置
3. 平移后：从右到左扫描面板（最右面板优先）
4. 在每个面板中从上到下逐行检查：若该行在面板范围内包含至少一个非黑像素，则保留该行；全黑行丢弃
5. 将所有保留的行按扫描顺序（右面板行在前，中面板行次之，左面板行在后；同一面板内保持上到下顺序）拼接
6. 在一个单面板宽度的输出网格中，将拼接后的行从底部向上排列，上方用黑行填满
7. 输出中不包含栗(9)分隔列和青(8)像素

**关键洞察**：青色角像素在两个操作中扮演不同的关键角色：在平移阶段，它是方向指令；在压缩阶段，它的消失（被本色替代）意味着平移已完成。平移使某些原本有内容的行变空、某些原本空的行变满，直接重塑了行压缩的结果。仅看平移前的布局无法推断最终压缩输出。
