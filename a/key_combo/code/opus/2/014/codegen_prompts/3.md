## 新题 3：分形蓝图指定列延伸目标

**组合逻辑**：[scale / self_similarity](少数单元位置构成分形蓝图) → [ray_extend](蓝图激活的列向下延伸着色)

**来源原语**：scale / tile / self_similarity / separator_grid / minority_cell / majority_cell / minority_pattern_as_blueprint（来自 b99e7126）；ray_extend / same_column_propagation / fill_column_to_bottom / foreground_source（来自 d037b0a7）

**依赖链**：少数单元在 NxN 单元网格中的位置构成一个小型二值图案 P。将 P 按 N 倍放大覆盖整个单元网格，标记出"活跃单元"。只有活跃单元中的彩色像素才执行向下列延伸。分形蓝图决定了延伸的作用域，列延伸改变了大量单元的内容——两个操作在空间上深度交织。

利用少数单元在网格中的排布作为分形蓝图，放大后确定哪些单元列执行向下颜色延伸。

**输入结构**：
- 背景为黑(0)，网格约 15x15
- 灰(5)分隔线（1 像素宽）将网格划分为 NxN 排列的等大单元格（N = 3 或 4，每个单元格内部为 3x3 像素）
- 大部分单元格内部全黑（多数单元）
- 2-4 个单元格内部包含一个彩色像素（非黑、非灰），位于单元格内部的某个位置——这些是少数单元。不同少数单元的彩色像素可以是不同颜色（取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)），但在单元格内部的相对位置相同（例如都在内部的第 2 行第 1 列）
- 少数单元在 NxN 网格中的行列位置构成一个二值图案 P（少数=1，多数=0）
- 生成约束：P 中至少有 2 个"1"；P 放大 N 倍后叠回网格时，已有的少数单元位置与 P 中的"1"一致；各少数单元彩色像素的颜色互不相同

**规则**：
1. 识别 NxN 单元网格中所有少数单元的位置，构建二值图案 P（N 行 N 列，少数单元处为 1）
2. 将 P 放大到 NxN 单元网格尺度：P 的第 (i,j) 格对应单元网格中以 (i*N, j*N) 为左上角的 N x N 子块中的所有单元。若 P(i,j)=1，则该子块中的所有 N 个单元均为"活跃"单元
3. 已有的少数单元天然为活跃单元。新增的活跃单元（原为多数单元的空单元格）需填入一个彩色像素：颜色取自在单元网格中 Manhattan 距离最近的已有少数单元的颜色（距离相同时取最左的，再取最上的），位置为与已有少数单元相同的单元格内相对位置
4. 对每个活跃单元，将其彩色像素沿所在像素列（不是单元列）向下延伸：从该像素所在行开始，向下填充同色像素，直到遇到灰(5)分隔线时跳过该分隔线继续向下，直到到达网格底部边界
5. 延伸覆盖路径上的黑(0)像素和被跳过的分隔线下方的黑像素，但不覆盖其他彩色像素（遇到已有彩色像素时停止，不包含该像素）
6. 灰分隔线本身保持不变；非活跃单元保持全黑

**关键洞察**：分形蓝图不只是在复制图案（如源题 b99e7126），而是在指定一个完全不同的操作（列延伸）的作用范围。求解者需要先完成分形放大来确定哪些列被激活，然后才能执行延伸——而延伸的结果（垂直彩色条纹穿过多个单元）在视觉上与分形图案截然不同，增加了从输出反推规则的难度。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
