## 新题 2：位置镜像 + 图例形状配色

**组合逻辑**：[平移/镜像位置](将精灵体的边界框位置水平镜像，但不翻转内部像素) → [形状匹配](旋转反射等价下匹配图例) → [重涂色](用匹配到的图例颜色涂色)

**来源原语**：平移(translate)/镜像位置(mirrored_position) ← 8ee62060；形状匹配(shape_matching)/旋转反射等价(rotation_reflection_equivalence) ← 845d6e51；重涂色(recolor) ← c3fa4749/845d6e51；精灵体(sprite) ← 8ee62060/845d6e51；图例区域(legend_region)/分隔线(divider) ← 845d6e51；内部朝向不变(orientation_preserved) ← 8ee62060

**依赖链**：分隔线将画布分为图例区和查询区 → 查询区每个精灵体的边界框位置在查询区内水平镜像（内部形状不翻转）→ 对镜像后的精灵体在所有旋转/反射变换下与图例形状匹配 → 匹配成功的图例颜色决定精灵体的最终颜色

将查询精灵体的位置水平镜像后，按旋转/反射等价匹配图例区的模板形状，用匹配到的模板颜色替换精灵体原色。

**输入结构**：约 16x14 的黑(0)背景网格。一条水平灰(5)分隔线位于网格约中部高度，将网格分为上下两区。上区（图例区）包含 3-4 个小型单色精灵体（4-连通，每个 3-6 像素），颜色各不相同（如红(2)、蓝(1)、绿(3)、黄(4)），形状各异且在所有 8 种旋转/反射变换下互不等价，彼此间隔至少 2 格。下区（查询区）包含同样数量的精灵体，全部为橙(7)色，位于不同位置。每个查询精灵体的形状恰好与某个图例精灵体在旋转/反射等价下匹配。生成约束：查询区宽度为偶数，各精灵体的边界框在水平镜像后不相互重叠。

**规则**：
1. 对查询区中每个橙(7)精灵体，计算其边界框在查询区内的水平镜像位置：new_left_col = 查询区宽度 - 1 - old_right_col。行位置不变。精灵体内部像素排列不翻转——仅搬运整个边界框到新列位置。
2. 将每个精灵体的形状（像素相对位置集合）在全部 8 种旋转/反射变换下与图例区的模板比较，找到唯一匹配的模板。
3. 擦除精灵体的原始位置（设为黑(0)），在镜像后的新位置用匹配模板的颜色绘制精灵体。
4. 上区（图例 + 分隔线）在输出中不变。

**关键洞察**：位置变换（水平镜像）和颜色变换（形状匹配）是两条独立的规则轴——镜像决定"在哪里"，形状匹配决定"涂什么色"。当某个精灵体恰好位于查询区水平中心附近时，镜像后位移很小，有助于求解者先隔离出颜色规则；反之，位于边缘的精灵体位移大，有助于隔离出位置规则。必须结合多个示例同时推断两条规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
