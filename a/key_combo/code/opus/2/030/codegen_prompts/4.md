## 新题 4：方向标记指引滑动、高度排名决定顺序与着色

**组合逻辑**：[方向编码 + 色块决定输出位置](已有) + [高度排名 + 排序](已有) → (创新组合：高度排名不仅决定着色，还决定滑动处理的先后顺序，先处理的竖条占据目标位置后会阻挡后续竖条，使最终布局依赖于高度与方向的联合配置)

**来源原语**：滑动/sliding、方向编码/direction_encoding、色块决定输出位置/color_direction_determines_placement、精灵体/sprite、着色标记/colored_marker（a8c38be5）；排序/sorting、高度排名/height_ranking、竖直线段/vertical_bar、保留极值高度分色/keep_extremes_and_recolor（a61f2674）

**依赖链**：高度排名决定处理顺序 → 先滑动的竖条占位后阻挡后续竖条 → 最终位置由方向+顺序+阻挡三者共同决定 → 高度排名同时决定极值竖条的着色。删除排名则无处理顺序且无法决定着色；删除方向标记则不知道往哪滑。

将多根带方向标记的竖条按高度排名依次向指定方向滑动至边界或被阻挡的位置，最高和最矮竖条分别涂蓝和红。

**输入结构**：约 15x15 网格，背景黑(0)。4-6 根灰(5)竖直线段（1 像素宽、3-8 像素高），各自的底端对齐在网格底部（最后一行）。每根竖条的左侧或右侧紧邻放置一个非灰非黑的标记像素（标记颜色如橙(7)），标记像素在竖条的竖直范围中间行（即 floor((top_row + bottom_row) / 2) 行）。标记在左侧表示该竖条向左滑动，标记在右侧表示向右滑动。各竖条初始位置互不相邻（列间距至少 2）。各竖条高度互不相同。生成约束：至少有两根竖条朝同一方向滑动（使阻挡效果可被观察到）。

**规则**：
1. 按高度从高到矮对竖条排序。高度为竖条像素数。
2. 依排名顺序依次处理每根竖条：读取其标记像素的位置（左侧或右侧），确定滑动方向（左或右）。
3. 将竖条沿水平方向滑动：竖条保持原来的行范围不变，列号沿指定方向逐列移动，直到竖条的任何像素即将超出网格边界或即将与已放置的竖条像素（含先前处理的竖条）在同列重叠时停止。竖条停在最后一个合法列位置。
4. 滑动结束时删除所有标记像素。
5. 将最高的竖条重涂为蓝(1)，最矮的竖条重涂为红(2)。其余竖条保持灰(5)。
6. 若最高和最矮的竖条高度差为 0（不会发生，因生成约束保证互不相同），不做特殊处理。

**关键洞察**：最高的竖条先滑，总能到达边界；较矮的竖条后滑，可能被先到的高竖条阻挡而停在中途。改变任一竖条的高度会同时改变处理顺序、阻挡关系和极值着色，三者紧密耦合。仅凭一个示例无法区分"按高度排序处理"与其他可能的排序规则（如按初始列号）。
