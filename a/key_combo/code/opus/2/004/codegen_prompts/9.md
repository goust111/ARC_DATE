## 新题 9：网格位置隐式编码平铺参数

**组合逻辑**：[平铺 tiling](已有) + [重涂色 recolor](已有) + [压缩 compress](创新：压缩方向反转——从"大格子压成小摘要"变为"小摘要的位置编码大格子的铺设方式") —— 创新点在于：分隔线网格的结构本身编码了变换参数（母题在网格中的行列位置 = 铺设的行列重复数），这是隐式编码结构，非线性流水线

**来源原语**：tiling / tile / side_len_determines_rep（参考题 ccd554ac，此处"边长"被创新为"网格坐标"）；recolor / marker_pixel / filled_gets_marker（参考题 5ad4f10b）；compress / grid_partitioning（参考题 5ad4f10b，此处方向反转）；separator_grid / grid_cell（参考题 e9c9d9a1）

**依赖链**：识别分隔线网格和各单元格内容 → 定位母题所在单元格的行列坐标 (i, j) → 母题铺设 (i+1) 行 x (j+1) 列 → 标记像素的网格坐标通过取模映射到特定铺设副本 → 对应副本重涂色。删除位置编码则不知铺设次数；删除铺设则无输出；删除标记映射则无法确定重涂色副本。

分隔线网格中某个单元格的彩色图案作为母题，其行列坐标编码平铺的重复次数；其他单元格中的标记像素通过坐标取模指定哪些副本被重涂色。

**输入结构**：黑(0)背景，约 15x15。网格被灰(5)单像素宽分隔线均匀分为 K x K 个等大单元格（K 为 3、4 或 5，各示例可能不同）。恰好一个单元格包含一个小型多像素 8-连通彩色图案（"母题"，3-6 像素，单色，非灰非背景色）。0-3 个其他单元格各包含恰好 1 个孤立彩色标记像素（颜色各异，非灰非背景色，与母题色不同）。其余单元格为空（全黑(0)）。生成约束：母题所在单元格的行列索引 (i, j) 均 >= 1（保证至少铺 2x2）；母题图案的边界框严格小于单元格尺寸（保证铺设时不溢出）。

**规则**：
1. 识别灰(5)分隔线，将网格分解为 K x K 单元格。单元格按 0-索引标记：左上角 = (0, 0)。
2. 找到包含多像素图案的单元格，记其行列索引为 (i, j)。提取母题图案（相对于单元格左上角的像素偏移和颜色）。
3. 生成输出画布（无分隔线）：将母题图案平铺 (i+1) 行 x (j+1) 列，各副本之间无间隔，输出画布大小 = (i+1) x 单元格高度 行, (j+1) x 单元格宽度 列。背景为黑(0)。每个副本在其对应的单元格大小区域内以相同偏移放置母题图案。
4. 对输入中每个含标记像素的单元格，记其行列索引为 (r, c) 和标记颜色。在输出中，将位于第 (r mod (i+1)) 行、第 (c mod (j+1)) 列的那个母题副本的所有前景像素重涂为该标记颜色。
5. 若多个标记映射到同一副本（取模后坐标相同），按标记像素在输入中从左到右、从上到下的扫描顺序，后扫描到的颜色覆盖先前的。
6. 未被任何标记映射到的副本保持母题原始颜色。

**关键洞察**：母题在分隔线网格中的位置不是随意放置——行索引编码垂直重复次数、列索引编码水平重复次数。这是一种**隐式编码**：网格结构本身就是变换指令。在源题 5ad4f10b 中，网格分块的作用是"从大到小压缩"；此处完全反转为"从小位置读取参数然后展开"。标记像素的位置通过取模映射到副本的机制也是非显然的——需要对比多个示例才能归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
