## 新题 3：旋转恢复揭示裁剪锚点

**组合逻辑**：[旋转/rotate](已有) → [补全/complete](创新：补全对象从边框变为裁剪区域的定义锚点) → [裁剪/crop](创新：裁剪边界由恢复后的标记点决定，而非由前景掩模边界框决定)

**来源原语**：旋转/rotate + 遮挡块/occluder_block + 旋转对称图案/rotational_pattern + 半周旋转恢复/half_turn_restores(ff805c23), 标记像素/marker_pixel + 补全/complete + 三点定矩形框/three_pts_define_rect(e7639916), 裁剪/crop + 边界框包围/bounding_box_enclosure(a740d043)

**依赖链**：识别遮挡块并旋转 180° 恢复被遮挡像素 → 在恢复后的网格中定位所有标记像素（含原本被遮挡的） → 标记像素的边界框定义裁剪区域 → 执行裁剪。删除旋转恢复则缺失标记点，无法确定裁剪区域；删除标记定位则裁剪无边界；删除裁剪则无输出。

具有 180° 旋转对称的图案中，部分标记像素被遮挡块隐藏；旋转恢复后找到全部标记，由标记的边界框确定裁剪区域，输出裁剪内部并擦除标记。

**输入结构**：约 17x17 网格，黑(0) 背景。网格包含一个由灰(5) 和黄(4) 像素构成的图案，该图案具有精确的 180° 旋转对称性。图案上放置 2-3 个蓝(1) 实心矩形遮挡块（每个 2x2 或 3x3），覆盖住底层图案像素。在图案的未遮挡区域中，散布恰好 2 个红(2) 单像素标记。恰好 1 个遮挡块下方隐藏着第 3 个红(2) 标记（该标记属于原始旋转对称图案的一部分）。3 个标记像素位于其共同边界框的 3 个不同角上（第 4 角无标记）。生成约束：3 个标记的边界框不与任何遮挡块重叠（即裁剪区域内无遮挡块）；仅有一个遮挡块下包含红(2) 像素，使恢复后的标记唯一可辨。

**规则**：
1. 对每个蓝(1) 遮挡块，将整个网格旋转 180°，提取旋转后网格中与该遮挡块相同位置的子块，用该子块替换遮挡块像素（恢复被遮挡内容）。
2. 在恢复后的网格中定位所有红(2) 像素，共 3 个。
3. 计算这 3 个红(2) 像素的轴对齐紧边界框。
4. 裁剪网格至该边界框的严格内部（不包含边界框边缘所在的行列）。
5. 在裁剪结果中，将所有红(2) 像素置为黑(0)（标记是控制点，非输出内容）。

**关键洞察**：3 个标记中有 2 个直接可见，但第 3 个被遮挡块隐藏。裁剪区域的边界依赖于全部 3 个标记的位置——如果不先执行旋转恢复，就无法确定"往哪里裁"。遮挡块隐藏的不是输出内容，而是确定输出范围的结构信息。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
