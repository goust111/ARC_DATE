## 新题 7：内容像素三重功能驱动模板化弹射

**组合逻辑**：[计数/counting](创新：计数结果不直接决定输出几何，而是作为模板查找键) + [颜色到模板映射/color_stencil_map](创新：映射键从颜色变为像素数量) + [弹射/ejection](创新：弹射物从一维尾迹变为二维模板形状) + [擦除/erase](已有)

**来源原语**：杯形框架/cup_frame + 内容像素/content_pixel + 尾刺/tail_spike + 弹射/ejection + 尾部朝向决定射出/tail_determines_emission + 像素数守恒/pixel_count_conservation(3dc255db), 模板遮罩/stencil_mask + 颜色到模板映射/color_stencil_map + 顺序配对/ordered_pairing(42f83767)

**依赖链**：计数杯内内容像素 N → N 匹配恰含 N 个填充像素的模板 → 内容像素颜色按遍历序填入模板各位置 → 擦除杯口内容 → 将着色模板沿尾刺方向弹射放置。删除计数则无法选模板；删除颜色填充则模板为灰色单调形状（与"直接弹射 N 个同色像素"无法区分）；删除弹射则着色模板无安放位置。

杯口内容像素同时承担三重功能：数量选模板、颜色填模板、自身被擦除；选中的模板以二维形状沿尾刺方向弹射而非一维尾迹。

**输入结构**：约 16x16 网格，黑(0) 背景。上方图例区：2-3 个灰(5) 模板（每个约 3x3 大小的二值图案，灰(5) 为填充像素、黑(0) 为空），彼此间隔 1 列黑(0)。不同模板的灰(5) 像素数量互不相同（如分别含 3、5、7 个灰像素），形状各异（十字形、L 形、对角线等结构描述仅作参考，求解者需从像素数量匹配而非形状辨认）。下方操作区：2-3 个杯形框架，每个由独特非黑非灰颜色的一像素厚轮廓构成（如红(2)、蓝(1)），具有收敛的尾刺（指向上/下/左/右之一）和开放的杯口（与尾刺方向相对）。杯口内部含一排内容像素（沿杯口排列），每个内容像素为某种非黑非灰非杯框色的颜色，不同内容像素颜色可以相同也可以不同。生成约束：每个杯的内容像素数 N 恰好等于某个模板的灰(5) 像素数，且不同杯匹配不同模板；每个杯的尾刺弹射方向上有足够空间放置模板。

**规则**：
1. 对每个杯形框架，计数其杯口内部的内容像素数 N。
2. 在图例中查找灰(5) 像素数恰好等于 N 的模板。
3. 将杯口内的内容像素按从左到右（水平杯口）或从上到下（垂直杯口）的顺序读取颜色序列 [c1, c2, ..., cN]。将模板的灰(5) 像素按从左到右、从上到下的顺序排列，第 k 个灰像素着色为 ck。
4. 擦除杯口内所有内容像素（置为黑(0)）。
5. 将着色后的模板放置于尾刺外侧：模板的几何中心对齐尾刺尖端向外偏移一格的位置，沿尾刺方向朝外展开。若模板部分超出网格边界，超出部分舍弃。
6. 杯形框架本身保持不变。

**关键洞察**：内容像素是三重功能体——数量决定选哪个模板、颜色决定模板各像素的着色、自身的存在在弹射后被擦除。弹射结果不再是一维尾迹而是一个二维多色图案。单个示例中可能恰好只有一个杯和一个模板，无法确认是"按数量匹配"还是"按位置匹配"或"按大小匹配"，需多个示例对比。
