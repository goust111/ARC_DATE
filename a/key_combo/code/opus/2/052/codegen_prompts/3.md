## 新题 3：压缩归一化匹配分组与多数表决涂色

**组合逻辑**：[compress/压缩](消除行列拉伸) → [shape_match/形状匹配 + rotation_reflection_eq/旋转反射等价](分组) → [counting + majority_vote/计数与多数投票](组内定色) → [recolor/重涂色 + erase/擦除](统一涂色与孤立擦除)

**来源原语**：compress, adjacent_identical, merge_identical ← ce8d95cc；shape_match, candidate_object, prototype_object, rotation_reflection_eq, run_length_compare ← bd14c3bf；counting, majority_vote ← 27a77e38；recolor ← aabf363d；erase ← e4941b18

**依赖链**：压缩消除尺寸差异是匹配的前提→匹配建立分组是投票的前提→投票定色是重涂的前提→组大小 =1 触发擦除（匹配失败的后果）。四步链中每一步的输出都实质改变下一步的输入空间。

将拉伸变形的对象压缩后按旋转/反射等价分组，每组用多数表决色统一涂色，无法归组的孤立对象被擦除。

**输入结构**：
- 约 20x20 的网格，背景为黑(0)。
- 5~8 个互不相邻的 4-连通单色对象，每个对象 6~20 像素，对象之间至少间隔 2 个背景像素。
- 对象颜色使用 3~4 种（如蓝(1)、红(2)、绿(3)、黄(4)），同色对象可能形状不同，不同色对象可能形状相同。
- 部分对象是同一基础形状的拉伸版本：某些行或列被连续重复了 1~3 次（如一个 3x3 的基础形状可能被拉伸为 3x5 或 5x3）。部分对象在拉伸基础上还做了 90/180/270 度旋转或水平/垂直翻转。
- 恰好有 1~2 个对象的基础形状与所有其他对象都不匹配（孤立对象）。
- 生成约束：每个匹配组至少含 2 个对象；组内至少有一种颜色出现次数严格多于其他颜色（确保多数投票结果唯一）。

**规则**：
1. 裁剪每个对象到其边界框。
2. 对每个裁剪结果执行行列压缩：从上到下逐行扫描，若当前行的像素模式与前一行完全相同则删除当前行；再从左到右逐列扫描，若当前列的像素模式与前一列完全相同则删除当前列。得到每个对象的"压缩掩码"。
3. 对所有对象的压缩掩码进行两两形状匹配：两个掩码在 0/90/180/270 度旋转或水平/垂直翻转后若完全相同，则属于同一组。传递性生效（A 匹配 B、B 匹配 C 则 A、B、C 同组）。
4. 对每个包含 2 个及以上成员的组，统计组内各颜色拥有的对象数量，出现次数最多的颜色为该组的"统一色"。
5. 将组内所有对象的像素重涂为该组的统一色（保持每个对象的形状、位置和拉伸状态不变，仅改变颜色）。
6. 组大小为 1 的孤立对象的所有像素擦除为黑(0)背景。

**关键洞察**：行列压缩消除了拉伸造成的尺寸差异，使得外观完全不同的大小对象实际上是同一基础形状的变体；孤立对象的消失是匹配失败的结果，需要对比多个示例才能确定"不匹配就擦除"这一规则（而非"保持原样"）。
