## 新题 2：桥接连通门控精灵对接

**组合逻辑**：[连通判定/connectivity_test](创新：用作对接操作的门控条件) + [旋转/rotate + 对接拼合/docking] + [擦除/erase]

**来源原语**：connectivity_test(239be575), rotate(2c181942), docking(2c181942), erase(edcc2ff0), hollow_square(2c181942), sprite(2c181942), bridge_path(239be575), color_match_pairing(2c181942), connectivity(239be575), symmetry_disambiguates_rotation(2c181942)

**依赖链**：连通判定筛选出哪些精灵有"对接资格" → 颜色匹配决定精灵对接到hub的哪条边 → 旋转由对称性消歧确定朝向。删除连通判定，所有精灵都会对接（产生多余/错误的结果）；删除颜色匹配，对接位置不确定；删除旋转消歧，朝向不确定。

仅与中心空心方框通过桥接路径相连的精灵才被旋转对接到匹配的边；断连精灵被擦除。

**输入结构**：
- 黑(0)背景网格，约18x18。
- 中央一个空心N x N正方形（hub），N约5-7。四条边各为不同颜色（例如顶边红(2)、底边绿(3)、左边蓝(1)、右边黄(4)），四角像素和内部为黑(0)背景。
- 散布2-4个单色精灵体，每个精灵是4-连通的非矩形小图形（3-8像素，形状各异，不同示例中同颜色的精灵形状不同）。每个精灵的颜色与hub某条边的颜色相同。
- 青(8)色桥接像素形成窄路径（宽度1像素的4-连通链），连接部分精灵到hub的外边界。
- 至少一个精灵没有任何青(8)色路径连接到hub。
- 生成约束：每种hub边颜色最多对应一个精灵；至少有一个精灵通过青(8)桥接与hub连通，至少一个不连通。每个需要对接的精灵恰好有一种旋转使其满足接触边对齐且沿接触轴对称。

**规则**：
1. 构建4-连通图：所有非黑(0)像素（hub边框 + 精灵 + 青(8)桥接）参与，忽略颜色差异。判定每个精灵是否与hub处于同一连通分量。
2. 与hub连通的精灵执行对接：
   a. 颜色匹配：精灵颜色对应hub的哪条边（顶/底/左/右）。
   b. 旋转精灵0/90/180/270度，选择使精灵的接触边恰好有N-2个连续像素可对齐hub该边内侧、且旋转后精灵沿接触边法线方向的轴镜像对称的那个旋转角度（左右边→需上下对称，上下边→需左右对称）。
   c. 将旋转后的精灵平移至紧贴hub对应边的外侧。
3. 与hub不连通的精灵：全部像素擦除为黑(0)。
4. 所有青(8)桥接像素擦除为黑(0)。
5. 输出仅包含hub和成功对接的精灵。

**关键洞察**：青色桥接路径是不可见的"资格认证"——它们在输出中完全消失，但决定了哪些精灵有权参与对接。求解者需要在多个示例中观察到：距离hub很近但没有桥接的精灵被擦除，而距离较远但有桥接的精灵反而被对接，从而归纳出"连通而非距离"才是筛选标准。
