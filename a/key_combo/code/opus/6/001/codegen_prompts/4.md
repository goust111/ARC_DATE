## 新题 4：链式替换后的环色循环

**组合逻辑**：[重涂色/recolor + 链式替换/chain_replace](已有：按图例逐行替换颜色) + [循环移色/color_cycle + 反向循环/opposite_cycle](创新：循环移色作用于替换后的颜色，替换改变了哪些像素"同色"，从而改变循环的实际效果)

**来源原语**：recolor, chain_replace, two_col_legend, legend_row_order (e4888269); color_cycle, ring_object, corner_pixel, side_center_pixel, opposite_cycle, corner_side_group (46c35fc7)

**依赖链**：循环移色需要知道每个位置的当前颜色 → 当前颜色是链式替换后的结果而非输入颜色 → 链式替换改变了颜色分布，可能使原本不同色的位置变为同色，或使原本同色的位置变为不同色 → 这直接影响循环移色时"哪个颜色移到哪里"的最终视觉效果。两个操作的耦合点在于颜色状态的变换：替换改变了循环的操作数。

先按图例对环像素做链式颜色替换，再对替换后的颜色执行角位/边中反向循环。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格中有 2~3 个完整的 3x3 环（8 个前景像素围绕 1 个黑背景中心，每个环的 8 个像素使用 2~4 种颜色，颜色选自红(2)、蓝(1)、绿(3)、黄(4)、灰(5)、品红(6)）。不同环之间至少间隔 2 个像素。网格的左侧或右侧有一个 2 列 N 行（N 为 2~4）的竖直图例块，图例块与环不相邻。图例每行由左列颜色和右列颜色组成，表示"左色 → 右色"的替换规则。生成约束：图例中的替换颜色均出现在至少一个环上；链式替换后，每个环的 8 个位置仍然不全同色（至少包含 2 种不同颜色），以保证循环有可观察效果；图例的替换不产生环外影响（背景和图例本身不被替换）。

**规则**：
1. 读取两列图例，从上到下记录替换规则序列：(c1→c2), (c3→c4), ...
2. 对每个环的每个像素（不包含图例像素和背景像素），按图例行从上到下依次扫描：若当前像素颜色等于该行左列颜色，则替换为右列颜色，然后继续扫描后续行（即同一像素可被多次替换，后续行可以继续作用于已替换的颜色）。
3. 替换完成后，对每个环执行循环移色：将 4 个角位像素（左上、右上、右下、左下）的颜色顺时针循环移动一步（左上→右上→右下→左下→左上）；将 4 个边中像素（上中、右中、下中、左中）的颜色逆时针循环移动一步（上中→左中→下中→右中→上中）。
4. 图例保持不变。背景保持不变。环的中心保持黑色背景。

**关键洞察**：输出颜色既不是单纯替换的结果，也不是单纯循环的结果，而是两步操作按特定顺序复合的结果。仅凭单个示例，求解者可能误以为颜色变化全由替换完成（忽略循环），或误以为是先循环再替换。需要多个示例对比"替换后循环"与"循环后替换"的差异才能确定正确顺序。图例的链式特性（后行可修改前行的输出）进一步增加了辨别难度。
