## 新题 8：擦除对角噪声后按字形模板重建

**组合逻辑**：[擦除/erase + 补线/line_completion](创新：擦除噪声不是最终目的，而是为了暴露被遮盖的锚点标记) + [补全/reconstruct + 颜色对应形状/color_to_shape](创新：字形模板不由示例中的完整字形提供，而由清理后的线段拓扑结构编码)

**来源原语**：erase, line_completion, diagonal_noise, straight_line_segment, gap_length_constraint (7b80bb43); reconstruct, glyph_template, endpoint_marker, frame_bar, color_to_shape, anchor_position (98c475bf)

**依赖链**：字形重建需要锚点位置和字形模板 → 锚点被对角噪声像素遮盖，必须先擦除噪声 → 噪声擦除后露出端点标记像素 → 同时，清理后的直线段的数量和朝向编码了"使用哪个字形模板" → 字形模板库由输入中的边框竖条之间的完整字形提供 → 清理后线段的颜色与字形库中某个字形颜色匹配时，使用该字形。擦除、线段拓扑分析、颜色匹配和字形重建四步紧密耦合。

擦除对角噪声以暴露端点标记，利用清理后直线段的颜色查找对应字形模板，在端点标记位置重建字形。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格左右两侧各有一条灰(5)全高竖直边框条（各 1 像素宽，占满网格高度）。两条边框之间的区域分为上下两部分（无显式分隔，由内容区分）：
- **上半区（模板区）**：包含 1~2 个完整字形，每个字形由单一颜色的像素组成（选自红(2)、蓝(1)、绿(3)），字形为 3~5 像素高、3~5 像素宽的 4-连通图案（如十字、角形等不同结构），不同字形颜色不同。字形之间至少间隔 2 行。
- **下半区（工作区）**：包含若干与模板区字形颜色对应的前景色像素，但这些像素被对角噪声严重干扰——原本的水平或垂直直线段被对角阶梯状噪声像素（45 度链，与直线段同色，8-连通但 4-不连通于直线段）部分替代或遮盖。每条被干扰的线段上有 2 个黄(4)端点标记像素，分别位于该线段应有的起点和终点附近（可能被噪声像素覆盖后仅剩 1 个可见，另 1 个被噪声像素占据了位置——此时噪声擦除后该位置恢复为端点标记）。每种前景颜色在工作区恰好有一条被干扰的线段。

生成约束：对角噪声像素可通过"无正交同色邻居、仅有对角同色邻居"的标准唯一识别；擦除噪声并补全间隙后，每条线段恢复为完整的水平或垂直直线，且两端各有一个黄(4)端点标记；每条线段的颜色恰好匹配模板区中某个字形的颜色。

**规则**：
1. 在工作区中，识别对角噪声像素：与直线段同色、无正交方向的同色邻居、仅有对角方向的同色邻居的像素。将这些像素擦除（变为背景黑(0)）。
2. 补全因噪声擦除而产生的直线段间隙：在水平或垂直方向上，若同色像素之间的间隙长度不超过被擦除的相邻对角噪声的跨度，则用该颜色填补间隙。
3. 擦除和补全后，每条线段恢复为完整直线，两端各有一个黄(4)端点标记。记录每条线段的颜色 C 和其两个端点标记的行坐标。
4. 在模板区找到颜色为 C 的字形模板。
5. 擦除该线段（包括端点标记），在两个端点标记所在的行之间（含端点行），以端点标记的列为水平锚点，绘制字形模板。字形模板垂直居中于两个端点标记的行之间，水平居中于两个端点标记的列之间。
6. 各颜色独立处理。边框竖条和模板区保持不变。

**关键洞察**：对角噪声不仅仅是需要清除的视觉干扰——它遮盖了端点标记的位置，而端点标记决定了字形重建的锚点。擦除操作不是独立的预处理，它的结果直接为后续的字形定位提供必要输入。同时，线段的颜色是字形模板的查找键，但这一对应关系只有在噪声清理后线段完整可见时才能可靠读取。需要多个示例对比才能确认"颜色对应字形"的映射规则而非"位置对应字形"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
