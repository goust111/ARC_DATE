## 新题 5：轨迹编码方向的滑动与路径描绘

**组合逻辑**：[滑动 slide](创新：滑动方向由轨迹反向推断而非行列对齐隐含) + [射线延伸 ray_cast / 轨迹 trail](创新：轨迹从方向编码器变为滑动路径的绘制输出) + [重涂色 recolor](已有) + 碰撞优先级（新关系：路径交叉处由行程距离决定涂色优先）

**来源原语**：滑动 slide / 矩形 rectangle / 标记像素 marker_pixel / 行列对齐 row_col_aligned / 最近者进入内部 nearest_enters（参考题 d6e50e54）、射线延伸 ray_cast / 轨迹 trail / 反向投射 opposite_direction（参考题 9f8de559）、重涂色 recolor（参考题 d6e50e54）

**依赖链**：轨迹方向读取 → 反向确定滑动方向 → 到矩形的距离计算 → 最近者判定 → 滑动执行 → 路径描绘 → 交叉冲突解决。轨迹在输入中是方向编码，在输出中变成路径记录——同一概念的双重角色构成紧耦合。

读取每个标记像素的来向轨迹以确定其滑动方向，将其滑向矩形并沿路径留下颜色轨迹，交叉处由更远的标记覆盖。

**输入结构**：约 16x16 黑(0)背景网格。一个实心蓝(1)矩形（约 4x4 至 5x6）位于网格中央偏某方向。3-5 个栗(9)标记像素分布在矩形外部，每个标记与矩形在行或列上对齐（即与矩形的某行或某列共线）。每个标记像素旁有一条由 2-3 个红(2)像素组成的直线轨迹，轨迹从标记出发向远离矩形的方向延伸（即轨迹指向标记的来处）。生成约束：各标记到矩形最近边的曼哈顿距离互不相同；各标记的滑动路径至多两两交叉一次且不会三条共点。

**规则**：
1. 对每个标记像素，读取其红(2)轨迹的延伸方向。标记的滑动方向为轨迹方向的反方向（即朝向矩形）。
2. 计算每个标记沿滑动方向到矩形最近边的距离。
3. 距离最短的唯一标记为"进入者"——它滑动至矩形边界上与其对齐的像素位置（即进入矩形边界）。其余标记各自滑动至矩形对齐边外侧紧邻的一个像素位置（停在矩形外壁）。
4. 将蓝(1)矩形整体重涂为绿(3)。
5. 对每个标记，沿其从原始位置到最终位置的路径（含起点和终点，不含中间经过的矩形内部像素），将路径上的每个像素涂为栗(9)。
6. 若两条路径在某个像素位置交叉，该像素涂为行程距离更长的标记的颜色（栗(9)，但逻辑上是更远标记的路径覆盖更近标记的路径）。由于所有标记同色，交叉处用黄(4)标识以区分覆盖方——行程更长者的路径在交叉点涂黄(4)，行程更短者的路径在交叉点被覆盖（不可见）。
7. 擦除所有原始红(2)轨迹像素（设为背景色）。

**关键洞察**：输入中的红色轨迹仅用于编码方向信息，输出中被擦除；输出中的新路径记录了实际滑动轨迹，交叉处的黄色标识揭示了距离优先级。同一"轨迹"概念在输入和输出中扮演完全不同的角色。
