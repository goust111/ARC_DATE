## 新题 8：滑向匹配边界后绿标桥接同色邻居

**组合逻辑**：[滑动 + 同色滑向同色边 + 碰撞停止](对象移动到匹配边界) → [连线 + 同色邻接](移动后的空间关系触发连接) + [标记像素](绿色标记的角色在滑动后才显现)

**来源原语**：滑动/同色滑向同色边/碰撞停止/边界色条/单色对象(17829a00), 连线/同色邻接(33067df9), 标记像素(faa9f03d/ff2825db), 擦除(多题)

**依赖链**：边界条颜色决定每个对象的滑动目标方向 → 滑动后对象的新位置改变了全局空间关系 → 绿色标记像素不参与滑动但其位置相对于滑动后的对象产生了新的邻接关系 → 仅当绿标恰好位于两个同色对象之间时才激活桥接 → 桥接的形态（垂直连接条）依赖于滑动后两个对象的精确间距

将对象滑向匹配色的边界条后，检查预置的绿色标记是否落在两个同色对象之间，若是则用绿色垂直连线桥接它们。

**输入结构**：约 14x14 网格，背景黑(0)。第 0 行为蓝(1)全宽条，最末行为红(2)全宽条。网格中间区域散布着若干 4-连通的单色小图形（每个 3-6 像素，形态各异——可以是直线段、拐角、小块等不规则形状），颜色为蓝(1)或红(2)，与边界条之一匹配。同时散布着若干孤立的绿(3)单像素标记。各对象（含绿标记）互不接触、互不重叠。生成约束：滑动后不会有两个同色对象在同一列上重叠（即同列的蓝对象至多一个，同列的红对象至多一个）；至少有 2 个绿标记在滑动后会落在两个同色对象之间，至少有 1 个绿标记在滑动后不在任何两个同色对象之间。

**规则**：
1. 蓝(1)对象向上滑动，直到其包围盒顶边到达第 1 行（紧贴蓝色顶部边界条下方），或碰到同列已停靠的蓝色对象（碰撞停止，停在被碰对象下方相邻行）。红(2)对象向下滑动，直到其包围盒底边到达倒数第 2 行（紧贴红色底部边界条上方），或碰到同列已停靠的红色对象。滑动保持对象形态和列位置不变，仅改变行位置。滑动处理顺序：蓝色对象按包围盒顶行从小到大处理（最靠上的先停靠），红色对象按包围盒底行从大到小处理（最靠下的先停靠）。
2. 绿(3)标记像素不移动，保持原位。
3. 滑动完成后，检查每个绿(3)标记像素：
   a. 在该标记所在列上，向上和向下分别寻找最近的非黑非绿像素。
   b. 若向上最近和向下最近的像素颜色相同（均为蓝(1)或均为红(2)），且它们之间的垂直距离不超过 5 格（含两端的对象像素和中间间隔），则激活该标记：在该列上，从上方对象的最低行到下方对象的最高行之间（含两端）的所有格子均涂为绿(3)，形成一条垂直连接条。已有的对象像素被绿(3)覆盖。
   c. 若不满足上述条件（两侧颜色不同、某侧无对象、或距离超过 5），则擦除该绿标记（置为黑(0)）。
4. 边界条（第 0 行和最末行）保持不变。

**关键洞察**：绿色标记在滑动前看似随机散布的噪声，其真正用途只有在对象滑动到位后才显现——它们是预先放置的桥接锚点，位置是针对滑动后的构型设计的。求解者必须先在脑中完成所有滑动，再判断哪些绿标记会激活，这两步推理紧密耦合且不可跳过。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
