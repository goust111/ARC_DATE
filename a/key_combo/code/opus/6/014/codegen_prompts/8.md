## 新题 8：字形指令编码平移方向、颜色匹配目标、顺序处理形成动态障碍

**组合逻辑**：[解码指令(decode_instructions) + 字形指令(glyph_instruction) + 编码映射(encoding_map)](创新：编码平移方向而非折线段) + [滑动(translate) + 贴墙移动(move_to_wall)](创新：移动终点由动态障碍决定) + [颜色匹配(color_match)](创新：颜色匹配指令到目标对象) + [顺序读取(sequential_reading)](创新：处理顺序产生涌现效应——先移动的对象成为后续对象的障碍)

**来源原语**：解码指令、字形指令、编码映射、顺序读取（136b0064）；滑动、贴墙移动（9f41bd9c）；颜色匹配（981add89）；目标对象（2f767503）

**依赖链**：字形像素数编码平移方向→字形颜色匹配目标对象→按字形从左到右顺序逐一平移对象→先完成平移的对象占据新位置，成为后续对象的阻挡物。每一步的结果改变下一步的空间状态，产生顺序依赖的涌现效应。

顶部字形序列逐一指挥下方同色对象沿编码方向滑动至碰壁停止，先滑动的对象成为后续对象的新障碍。

**输入结构**：约 15x15 网格，黑(0)背景。顶部 3 行为指令区域，包含 3~4 个 3x3 彩色字形，字形之间用 1 列背景分隔，按列排列。每个字形由单一前景色绘制在黑(0)背景上，颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。每个字形的非背景像素数为 3、4、5 或 6 之一（不重复），编码一个方向。指令区域下方（第 4 行起）散布着与字形数量相同的单色 4-连通小对象（每个 3~8 像素），每个对象的颜色恰好匹配一个字形的颜色。对象之间、对象与网格边缘之间有足够空间。生成约束：按字形从左到右的顺序平移对象后，至少有一个对象的最终位置受到了先前已平移对象的阻挡（即它的终点与移动方向上的下一个障碍物是另一个已移动的对象，而非网格边缘）。

**规则**：
1. 读取指令区域中的字形，按从左到右的列顺序排列。每个字形的非背景像素数 A 编码一个平移方向：A=3→上，A=4→右，A=5→下，A=6→左。
2. 每个字形的颜色 C 匹配下方区域中颜色为 C 的唯一目标对象。
3. 按字形从左到右的顺序依次处理：
   a. 确定当前字形对应的目标对象和平移方向。
   b. 将该对象沿指定方向滑动，直到对象的任一像素的下一格遇到网格边缘、另一个对象的像素、或指令区域边界（第 3 行）为止。对象停在最后一个不碰撞的位置。
   c. 对象移动后，其新位置立即生效（成为后续对象的潜在障碍）。
4. 所有对象处理完毕后，将指令区域（顶部 3 行）清除为背景色。

**关键洞察**：指令的处理顺序产生涌现效应——改变字形的左右排列顺序会改变最终布局，因为先移动的对象成为后续对象的障碍。源题(136b0064)中指令顺序编码折线段，各段互不干涉；这里指令顺序引入了动态障碍——每条指令执行后改变了世界状态，使得同一组指令按不同顺序执行会产生完全不同的结果。
