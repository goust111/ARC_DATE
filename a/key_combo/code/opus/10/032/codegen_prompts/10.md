## 新题 10：图例映射颜色确定棋盘格配色后用掩码选择性铺设

**组合逻辑**：[图例映射/legend_mapping]（已有） → [填充/fill + 行列奇偶/parity_fill]（创新：棋盘格的两色由图例指定而非来自输入中已有的两色） + [逐格比较/cell_comparison + 二值掩码/binary_mask]（创新：掩码不做克罗内克积而是选择棋盘格的铺设区域）

**来源原语**：颜色图例/color_legend、图例映射/legend_mapping（5adee1b2）；填充/fill、棋盘格图案/checkerboard、行列奇偶决定填充/parity_fill（ba9d41b8）；逐格比较/cell_comparison、二值掩码/binary_mask（c803e39c、fafffa47）

**依赖链**：图例指定棋盘格的两种颜色（若无图例则不知道用什么颜色画棋盘格）；掩码的前景区域确定棋盘格铺设范围（若无掩码则不知道在哪里画）；两者缺一不可，且图例可能有多条——不同图例条目对应不同掩码区域的不同配色方案，使得图例读取和掩码分区必须联合解码。

图例定义棋盘格配色方案，掩码的不同前景色区域各自按对应图例铺设不同配色的棋盘格。

**输入结构**：约 16x16 黑(0)背景网格。左侧两列为图例区：包含 2 个上下排列的图例条目，每个条目占 2 行 x 2 列。条目格式为左列两像素同色（表示掩码中的区域标识色）、右列上下各一像素分别为两种不同颜色（表示该区域的棋盘格主色和副色）。两个条目之间隔 1 行黑(0)。右侧主区域是一个与图例区不重叠的矩形区域（约 12x12），其中用两种颜色的像素绘制二值掩码：两种颜色分别对应两个图例条目的左列颜色，剩余位置为黑(0)背景。保证每种掩码颜色覆盖至少 4 个像素，两种颜色的区域互不重叠。不同示例中图例颜色组合和掩码形状不同。

**规则**：
1. 读取左侧图例：每个条目的左列颜色为"区域标识色" K，右列上方像素颜色为"主格色" C1，右列下方像素颜色为"副格色" C2。记录映射 K → (C1, C2)。
2. 在右侧主区域中，对每个像素 (r, c)：
   - 若该像素颜色等于某个区域标识色 K：查找映射 K → (C1, C2)，以主区域左上角为锚点计算 (r'+c') 的奇偶性（其中 r', c' 是相对于主区域左上角的偏移），偶数处输出 C1、奇数处输出 C2。
   - 若该像素为黑(0)背景：输出黑(0)。
3. 输出网格仅包含右侧主区域大小的结果（裁去图例列）。
4. 图例本身不出现在输出中。

**关键洞察**：图例不是简单的"旧色→新色"一对一映射，而是"标识色→棋盘格配色方案"的一对二映射。求解者需要发现图例右列的上下两个像素分别对应棋盘格的奇偶相位，这种"图例编码填充模式"的结构在源题中不存在。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
