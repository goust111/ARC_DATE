## 新题 5：双半区掩码逐格比较决定重叠区棋盘格与独占区纯色

**组合逻辑**：[逐格比较/cell_comparison]（已有） → 条件三分支 → 分支A（双前景）：[填充/fill + 行列奇偶/parity_fill]（创新：棋盘格的两种颜色来自两个掩码的前景色） / 分支B（单前景）：纯色填充 / 分支C（双背景）：保持背景

**来源原语**：逐格比较/cell_comparison、堆叠掩码/stacked_mask、背景交集/bg_intersection（fafffa47）；填充/fill、棋盘格图案/checkerboard、行列奇偶决定填充/parity_fill、边框与内部分离/border_interior_split（ba9d41b8）

**依赖链**：逐格比较将每个位置分为三类（双前景、单前景、双背景），分类结果决定该位置的输出规则。棋盘格的两种颜色取决于两个掩码各自的前景色——必须先识别出每个掩码的前景色才能生成棋盘格。单前景区域直接取该侧的前景色。删除比较环节则无法分区；删除棋盘格规则则双前景区域无输出方案。

两个堆叠的半区掩码按格比较：双前景重叠区用两色交替棋盘格填充，单前景独占区纯色填充，双背景区保持背景色。

**输入结构**：约 12x20 黑(0)背景网格，由两个上下堆叠的 6x20（或类似尺寸）半区组成（无显式分隔行，两个半区大小完全相同，上半区占前 H 行、下半区占后 H 行）。上半区有一种前景色（如蓝(1)），前景像素构成一个或多个实心矩形区域，其余为黑(0)背景。下半区有另一种前景色（如红(2)），同样构成一个或多个实心矩形区域，其余为黑(0)背景。两半区的矩形区域在水平位置上部分重叠、部分独占。保证存在至少一个双前景重叠列段和至少各一个单前景独占列段。不同示例中矩形位置和前景颜色不同。

**规则**：
1. 将上下两个半区按行列对齐逐格比较。输出为单个与半区同尺寸的网格。
2. 对每个位置 (r, c)：
   - 若上半区 (r, c) 和下半区 (r, c) 均为前景色（不论颜色是否相同）：输出棋盘格——以输出网格左上角 (0,0) 为锚点，(r+c) 为偶数处涂上半区前景色、(r+c) 为奇数处涂下半区前景色。
   - 若仅上半区 (r, c) 为前景色：输出上半区前景色。
   - 若仅下半区 (r, c) 为前景色：输出下半区前景色。
   - 若两者均为背景色：输出黑(0)。
3. 输出网格尺寸等于单个半区的尺寸。

**关键洞察**：逐格比较产生的不是简单的二值结果（如源题 fafffa47 中的"双背景→标记"），而是三分类，其中最复杂的一类（双前景重叠）触发了全新的棋盘格填充操作，且棋盘格的两种颜色恰好来自引发该分类的两个输入——比较结果和填充参数之间形成闭环依赖。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
