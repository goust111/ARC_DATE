## 新题 10：掩码列范围棋盘填充与竖条中心标记

**组合逻辑**：[掩码映射·列范围提取](创新：掩码的连续前景列段被解读为矩形区域的列跨度) + [填充·棋盘格](创新：棋盘填充的区域由掩码列段动态决定) + [标记竖条·缺口居中](创新：掩码中的背景缺口列成为竖条标记位置)

**来源原语**：掩码映射(mask_mapping) ← 7e4d4f7c；首行掩码(top_row_mask) ← 7e4d4f7c；压缩(compress) ← 7e4d4f7c；填充(fill) ← df8cc377；棋盘格图案(checkerboard) ← df8cc377；空心矩形(hollow_rect) ← df8cc377；标记竖条(marker_bar) ← bae5c565；以缺口为中心(centered_on_gap) ← bae5c565；列标记(column_marker) ← 7e4d4f7c

**依赖链**：首行掩码的前景/背景分布同时编码了两种信息——连续前景列段定义棋盘填充的列范围，背景缺口定义竖条标记的列位置。棋盘填充的行范围由首列的竖条标记高度决定（来自另一个维度的信息）。三种元素（掩码、竖条、棋盘）的几何参数互相引用，形成闭环约束。

读取首行掩码的前景列段和缺口位置，在首列竖条标记指定的行范围内，对每个前景列段区域填充棋盘格图案，在缺口列绘制竖条。

**输入结构**：黑(0)背景，约 12x12 网格。第 0 行（首行）是一个掩码行：部分列为蓝(1)前景，部分列为黑(0)背景。前景像素形成 1~3 个连续列段（每段至少 2 列宽），段之间被单列的背景缺口分隔。第 0 列从第 1 行开始向下有一条绿(3)竖条标记（连续的绿色像素，高度 H 在 3~6 之间）。网格其余像素为背景。(0,0) 位置由首行掩码决定——若第 0 列在掩码中是前景则为蓝(1)，否则为黑(0)。生成约束：掩码中恰好有 1~2 个背景缺口列（每个缺口宽度恰好 1 列），缺口不在首列或末列。

**规则**：
1. 读取第 0 行掩码，识别所有连续蓝(1)前景列段及背景缺口列。
2. 读取第 0 列的绿(3)竖条标记，记录其高度 H（从第 1 行到第 H 行）。
3. 清除整个网格为黑(0)背景。
4. 对每个连续前景列段 [c_start, c_end]：在行范围 [1, H] 和列范围 [c_start, c_end] 定义的矩形区域内填充棋盘格图案——以区域左上角 (1, c_start) 为棋盘起始格（着色格），颜色为蓝(1)，相邻格为背景(0)，交替排列。
5. 对每个背景缺口列 c_gap：在行范围 [1, H] 的所有行上绘制绿(3)竖条（c_gap 列从第 1 行到第 H 行全部涂绿(3)）。
6. 保留第 0 行掩码原样（蓝和黑的原始分布）。第 0 列的绿色竖条保留原样。
7. 棋盘格与竖条若在同一像素重叠（仅当缺口列同时落在某前景段范围内时发生——生成时已通过缺口定义排除此情况，因为缺口是前景段之间的分隔），竖条颜色优先。

**关键洞察**：首行掩码在源题 7e4d4f7c 中仅用于生成一行重涂色掩码，这里被重新解读为空间区域的列跨度定义。掩码中的"前景"和"缺口"编码了两种完全不同的操作目标——前景段触发棋盘填充，缺口触发竖条绘制——同一行的不同像素驱动不同的变换分支，形成隐式的条件分支结构。
