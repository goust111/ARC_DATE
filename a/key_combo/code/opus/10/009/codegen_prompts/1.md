## 新题 1：平行四边形面积排名着色

**组合逻辑**：[对角分解/diag_decompose](已有) → [连线/draw_line](已有，创新：绘制平行四边形四边而非两点直线) → [计数/counting](已有，创新：计算封围面积而非对象个数) → [排序/sort](已有) → [重涂色/recolor](已有，创新：颜色由面积排名决定)

**来源原语**：对角分解(cb227835), 连线(cb227835/29c11459), 计数(2753e76c/a87f7484), 排序(2753e76c), 重涂色(009d5c81/22a4bbc2), 控制序列(3e6067c3), 标记像素(cb227835)

**依赖链**：标记像素对的向量经对角分解生成平行四边形几何 → 几何形状决定封围面积 → 面积排名决定在控制行中的索引 → 索引映射到最终轮廓颜色。面积计算依赖于对角分解产生的具体几何形状，排名依赖面积，颜色依赖排名——删除任一环节均无法确定最终输出。

在黑(0)背景上，多对同色标记像素各自通过对角分解生成平行四边形轮廓；根据每个平行四边形的封围面积排名，从底部控制行读取对应颜色重涂轮廓。

**输入结构**：约 20x20 的黑(0)背景网格。网格中散布 3~5 对标记像素，每对同色（颜色互不相同，使用蓝(1)、绿(3)、黄(4)等），每对中两点的行列偏移既有行分量又有列分量且行列分量大小不等（保证对角分解唯一）。每对标记像素间无其他前景像素遮挡。网格最底行为控制行：从左到右排列 K 个不同颜色的单像素（K = 标记对数），颜色与标记对颜色均不同，使用如红(2)、橙(7)、品红(6)等。不同示例中标记对数量、位置、偏移方向均不同。生成约束：所有平行四边形的封围面积互不相等；不同平行四边形轮廓不重叠；控制行像素数恰好等于标记对数。

**规则**：
1. 识别所有标记像素对：同色且非黑(0)、非控制行颜色的前景像素恰好成对出现，每种颜色恰 2 个像素，作为一对。
2. 对每对标记像素，计算两点间的行列偏移向量 (dr, dc)。将该向量分解为一个 45 度对角分量和一个轴对齐分量（对角分量的行列绝对值相等且等于 min(|dr|, |dc|)，方向与原向量各分量同号；轴对齐分量为原向量减去对角分量）。
3. 以两个标记像素为对角顶点，以对角分量和轴对齐分量为相邻两边，确定平行四边形的四个顶点。沿四边画绿(3)轮廓线（含四个顶点），但保留标记像素原色不变。
4. 计算每个平行四边形内部的像素数（严格位于轮廓线内部的黑色像素数量）作为其封围面积。
5. 将所有平行四边形按封围面积降序排列，得到排名 1, 2, ..., K。
6. 读取控制行的 K 个颜色像素（从左到右对应排名 1, 2, ..., K）。将排名为 i 的平行四边形的全部轮廓像素（不含标记像素）重涂为控制行第 i 个颜色。
7. 擦除控制行（恢复为黑(0)）。擦除所有标记像素（恢复为黑(0)）。

**关键洞察**：轮廓的最终颜色既非标记颜色也非绘制颜色，而是由封围面积在所有平行四边形中的相对排名间接决定的——必须先构造所有几何形状、计算所有面积，才能确定任何一条轮廓的颜色。

      contiguous block on the head-facing side of the interior, filled
      row-by-row (or col-by-col) from head edge inward; 0 to all cells
      may be orange. Grey fills the remainder toward the far side.
      When all cells are orange (grey=0), container does not move.
  head: 1-cell-thick line of 9 (maroon), spans full container border edge,
        adjacent to one side (any of top/bottom/left/right); length 3-7
  dest: identical 9-line further along movement axis (away from container),
        aligned on same row/col; gap >= 0 bg cells between head and dest
        (gap=0 means head and dest touch, forming one connected component)
  movement_rule: |
    steps = min(head_dest_distance, grey_cell_count).
    head_dest_distance = gap + 1 (offset between head_tl and dest_tl).
    Container+head translate toward dest by steps cells.
    Grey cells convert to orange from head-facing side inward, one per step.
  constraints:
    - moved container+head must stay within grid bounds
    - path from container to dest must be clear bg before and after movement
    - minimum 1 bg cell gap between any two non-bg object groups
    - head color always 9, border 0, bg 6 [observed]
    - mix of capping types across examples: some containers capped by grey,
      some by distance, 0-1 fully-orange decoys [observed]

generation_strategy:
  approach: output-first for each container, then undo movement to get input
  steps:
    - choose grid size and number of containers (2-4)
    - for each container, pick inner dims (1-12 x 1-5), head side, gap (0-14)
    - compute h2d = gap + 1; choose initial_orange >= 0 and grey >= 0
      where initial_orange + grey = inner_area; steps = min(grey, h2d)
    - build output position: place container border+interior at final position
      with steps additional cells converted grey->orange from head side inward;
      place head and dest 9-lines at output positions
    - derive input: shift container+head back by steps cells (opposite of
      movement direction); revert the top steps orange conversions to grey
    - include 0-1 fully-orange containers (grey=0, steps=0) as decoys that
      stay in place in both input and output
    - validate: no overlaps, all objects within bounds, >=1 bg cell between
      object groups, path between head and dest is clear bg

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
