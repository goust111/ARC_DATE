## 新题 9：对接拼合方向由走廊检测确定

**组合逻辑**：[对接拼合 docking](拼合方向不由颜色匹配决定，而由走廊方向决定) + [走廊 corridor / 对边连通 opposite_edge_connect](走廊检测结果控制拼合行为) + [旋转 rotate](精灵需旋转到走廊方向) → 走廊驱动的定向拼合

**来源原语**：对接拼合(#18 2c181942)、空心矩形(#18 2c181942)、颜色匹配配对(#18 2c181942)、对称消歧旋转(#18 2c181942)、走廊(#17 2bee17df)、对边连通(#17 2bee17df)、边界像素(#17 2bee17df)、旋转(#18 2c181942)

**依赖链**：边界像素对检测出走廊方向 → 走廊方向指定精灵应拼合到 hub 的哪一侧 → 精灵旋转以适配该侧。走廊检测是空间分析，拼合是几何操作，前者的结果直接参数化后者的方向——颜色匹配被走廊方向替代为配对机制。

通过检测网格边界的无阻挡走廊来确定精灵应拼合到中心空心矩形的哪一侧，并旋转精灵使其接触边适配该侧。

**输入结构**：约 17x17 的网格，背景黑(0)。网格中央有一个 5x5 的空心矩形（hub），四条边各为不同颜色（上:蓝(1)、下:红(2)、左:绿(3)、右:黄(4)），四角为背景色，内部为背景色。网格中散布 2-3 个单色精灵体（每个约 3x4 到 4x5 像素，不规则形状但具有恰好一条对称轴），每个精灵的颜色取自{品红(6)、橙(7)、灰(5)}，与 hub 边颜色均不同。网格的四条边界（最外圈行/列）上有若干标记像素：每个精灵颜色在网格边界上恰好出现两次，分布在相对的两条边上（如上边界和下边界各一个，或左边界和右边界各一个）。两个同色边界标记之间的行或列完全为背景色（构成无阻挡走廊）。不同示例中：精灵数量、形状、颜色不同，走廊方向不同。生成约束：每个精灵颜色的走廊方向（水平或垂直）恰好指向 hub 的某一侧；精灵旋转后能与该侧边缘无缝邻接（接触边像素数等于 hub 边长减 2 即 3 像素）。

**规则**：
1. 检测网格边界上的标记像素，按颜色配对。对每对同色标记，确定其连线方向（水平/垂直）。
2. 走廊方向映射到 hub 侧面：垂直走廊（上下边界标记）→ 走廊穿过 hub 的上方或下方，取标记所在列更接近 hub 中心的一侧；水平走廊（左右边界标记）→ 类似取行更接近 hub 中心的一侧。具体规则：若走廊中线在 hub 中心之上则为上侧，之下为下侧，之左为左侧，之右为右侧。
3. 找到与该走廊颜色相同的精灵，将其旋转（0/90/180/270 度），选择使精灵的对称轴与 hub 该侧边平行、且接触边恰好有 3 个连续像素的旋转态。
4. 将旋转后的精灵平移至紧邻 hub 该侧边外部的位置，接触边与 hub 侧边对齐（居中）。
5. 输出仅包含 hub 和所有已拼合的精灵，其余像素（包括边界标记和原位置精灵）清除为背景色。

**关键洞察**：精灵与 hub 侧面的配对不靠颜色匹配（两者颜色不同），而靠边界走廊的空间指向——走廊是一个隐式的方向指示器，必须先完成走廊检测才能确定拼合方案。
