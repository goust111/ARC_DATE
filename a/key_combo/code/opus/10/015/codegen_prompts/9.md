## 新题 9：重力沉降后的嵌套层次压缩

**组合逻辑**：[滑动(sliding)](创新：重力方向不是水平而是向下，且多个对象互相碰撞阻挡) + [压缩(compress)](创新：压缩的层次顺序不由面积决定，而是由重力沉降后的垂直堆叠顺序决定) → 重力改变对象的空间排列 → 沉降后的垂直分层顺序作为嵌套层次的编码 → 压缩为嵌套方环

**来源原语**：滑动(sliding) + 碰撞阻挡(collision_block) + 重力沉降(gravity_settle) + 前景对象(fg_object) + 画布边界(canvas_boundary) ← d282b262；压缩(compress) + 嵌套形状(nested_shape) + 方环(square_ring) + 嵌套层次(nesting_hierarchy) + 面积序映射环(area_order_to_ring) ← eb5a1d5d；排序(sorting) ← eb5a1d5d

**依赖链**：多个不同色的精灵体散布在网格上 → 向下滑动直到全部沉降（碰撞阻挡） → 沉降后从底部到顶部形成垂直层叠顺序 → 最底层（最先着地）为最外层环，最顶层为最内层 → 压缩为嵌套方环图案

多个彩色精灵体经重力沉降后按垂直堆叠顺序压缩为嵌套方环，底部最先着地的精灵体成为最外层环。

**输入结构**：约 14x14 的黑(0)背景网格。网格中有 4~5 个单色 4-连通精灵体（各 6~15 像素，形状各异，非矩形），每个精灵体颜色不同（如红(2)、蓝(1)、绿(3)、黄(4)、品红(6)）。精灵体散布在网格的不同高度，互不接触。部分精灵体在水平方向上有重叠的列范围（即垂直投影有交集），使得下落时会发生碰撞阻挡。生成约束：(a) 至少有两个精灵体的列范围有重叠，使得沉降时发生非平凡的堆叠；(b) 沉降后每个精灵体的底部行各不相同（不存在两个精灵体在完全相同的行段上着地），从而可以无歧义地确定从底到顶的顺序；(c) 沉降后的垂直顺序与原始的面积大小顺序不同（否则退化为面积排序）。

**规则**：
1. 将每个精灵体视为刚体，同时向下滑动一格。如果某个精灵体的下一格位置被网格底边界或另一个已停止的精灵体占据，则该精灵体停止。重复此过程直到所有精灵体停止。（处理顺序：每一轮中所有可移动的精灵体同时尝试移动；一个精灵体在其正下方没有障碍时才移动。）
2. 沉降完成后，确定垂直层叠顺序：按每个精灵体底部最低行的位置排序。底部最低行最大（最靠近网格底边）的排第一（"最先着地"），底部最低行最小的排最后。
3. 构建嵌套方环输出：精灵体数量为 N，则输出为 (2N-1) x (2N-1) 的网格。排第一的精灵体颜色填充最外层环（第一圈），排第二的填充次外层环，以此类推，排最后的颜色填充中心一个像素。
4. 精灵体的原始形状和大小在输出中不保留——仅保留颜色和沉降后的堆叠顺序。

**关键洞察**：面积排序在本题中完全无用——外环颜色不是由最大精灵体决定，而是由最早着地的精灵体决定。而着地顺序取决于初始高度和碰撞阻挡的交互作用（一个较高的精灵体可能被一个更高的精灵体阻挡而停在高处），必须完整模拟重力过程才能得出正确顺序。
