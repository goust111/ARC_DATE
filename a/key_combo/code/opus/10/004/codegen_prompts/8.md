## 新题 8：链式竖条旋转后按列段分组的调色板重涂

**组合逻辑**：[链式连接/chain_linkage + 高度即宽度/height_equals_width + 旋转/rotate](竖条链式旋转为横条) -> [按列段分组匹配/column_run_group_match](旋转后的横条按水平位置形成列段组) -> [顺序一一对应/order_correspondence + 调色板列/palette_column](列段组按序对应调色板颜色重涂)

**来源原语**：旋转/rotate + 竖条/vertical_bar + 标记条/marker_bar + 链式序列/chained_sequence + 链式连接/chain_linkage + 高度即宽度/height_equals_width (84551f4c), 重涂色/recolor + 调色板列/palette_column + 目标列段/target_column_run + 顺序一一对应/order_correspondence + 按列段分组匹配/column_run_group_match (9b365c51)

**依赖链**：蓝标记条开始链式遍历 -> 链中每根竖条旋转为横条（高度变宽度）-> 旋转后的横条在水平方向上可能首尾相接或有间隔，按水平连续性分组为"列段组" -> 调色板列从左到右依次对应各列段组 -> 每个列段组中的所有横条重涂为对应调色板颜色。链决定了哪些竖条参与旋转；旋转改变了空间布局从而决定了分组方式；分组方式决定了调色板的对应关系。

从蓝色标记条开始沿链式规则收集竖条并旋转为横条，然后将相邻横条分组为列段，按调色板列顺序重涂每个列段组。

**输入结构**：黑(0)背景上，网格底部对齐有若干单像素宽的竖条，全部为红(2)色，高度各不相同（2 至 6 像素）。其中 1 至 2 根竖条为蓝(1)色（链起始标记）。网格左侧有 2 至 4 根全高度的单像素宽调色板列，颜色各异（如绿(3)、黄(4)、橙(7)、品红(6)），从左到右排列。网格约 12x20 至 15x25。生成约束：从每个蓝色标记条出发，按链式规则（下一根竖条的列坐标 = 当前竖条列坐标 + 当前竖条高度）恰好可以到达若干红色竖条，形成不中断的链；不被任何蓝色标记链到达的红色竖条视为"未链接条"；调色板列的数量等于所有链旋转后形成的列段组总数。

**规则**：
1. 识别左侧调色板列，从左到右记录颜色序列 P1, P2, ..., Pk。
2. 对每根蓝(1)标记竖条，按链式规则向右遍历：设当前竖条高度为 h、列坐标为 c，则下一根竖条位于列 c+h，若该列存在底部对齐的红色竖条则纳入链中，否则链终止。
3. 将链中每根竖条（含蓝色起始条）从垂直旋转为水平：以该竖条的底部像素为锚点，向右延伸，长度等于原高度，颜色暂为白(保持原色用于分组)。清除原竖条的垂直像素。
4. 旋转后的横条按列段分组：若两根相邻横条（按锚点列坐标排序）的水平跨度首尾相接（前一根的右端列 + 1 = 后一根的左端列），则归为同一列段组；否则分属不同组。
5. 将所有列段组按其最左列坐标从左到右排序，依次对应调色板颜色 P1, P2, ...。将每个列段组中所有横条像素重涂为对应的调色板颜色。
6. 未被任何链到达的红色竖条保持不变（垂直、红色）。
7. 擦除调色板列（变为黑背景）。

**关键洞察**：源题(84551f4c)中旋转后的横条只是简单地画出来，不存在"分组"概念。源题(9b365c51)中列段分组作用于静态目标图形。这里，链式旋转的结果动态地决定了哪些横条首尾相接——一根较长竖条旋转后占据更多水平空间，可能将原本分开的短横条"桥接"到同一组，或自身占据整组。这种"旋转结果决定分组结构"是两个源题中都不存在的涌现关系。求解者需要先理解链式旋转才能预测分组，而分组错误会导致调色板映射全部偏移。

    colors: 3-4 distinct non-bg colors
    active_edge: the long side (N cells) with strictly higher max-same-color count than the other long side
    active_majority: 5-9 out of N (must exceed non-active side majority)
  sprites:
    count: 3-4, all dihedral transforms of one template
    distinct_orientations: 3 [observed]
    placement: no two sprites' rays of different colors may occupy the same cell
    active_side_faces: toward a grid boundary (left/right/top/bottom)
  markers:
    count: 3, single pixels with unique colors disjoint from template colors
    placement: always on a grid boundary cell (row 0, row H-1, col 0, or col W-1)
    alignment: each marker sits on the edge that its labeling sprite's active side faces
    labeling: each marker labels a unique active-edge cell of the shared template
    distribution: markers spread across 1-3 different sprites [observed]
  output_rule: |
    For each labeled template cell, draw a ray outward from every sprite's
    corresponding active-edge cell through bg cells until hitting non-bg or grid edge.

generation_strategy:
  approach: output-first
  steps:
    1. Choose grid size (H x W) and template dimensions (N x 2, N in 7-9).
    2. Design template with 3-4 colors ensuring active edge has strictly higher majority than non-active edge.
    3. Generate 3-4 dihedral variants of the template and place them on the grid, each facing a grid boundary. Ensure enough clearance between sprites so rays don't conflict (different-color rays never overlap same cell).
    4. Choose 3 active-edge cell indices to label (distinct positions on the template's active edge).
    5. For each labeled cell, assign a unique marker color (not in template colors). Place the marker on the grid boundary that the labeling sprite's active edge faces, aligned with the corresponding active-edge cell. Ensure clear line-of-sight (only bg) between marker and sprite edge.
    6. Verify no ray conflicts by simulating all rays; reject and retry placement if conflicts exist.
