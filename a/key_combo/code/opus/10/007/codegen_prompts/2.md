## 新题 2：面积驱动轨道滑动

**组合逻辑**：[计数/counting](创新：面积不再决定垂直位移而是轨道槽位步数) + [滑动/sliding](创新：从单步推进改为 N 步推进) + [朝近端扩展/toward_nearer_expand](创新：从单像素扩展改为整个对象的滑动方向和重涂色来源) → 碰撞排序（新增）

**来源原语**：计数/counting(b2bc3ffd), 位移等于面积/shift_equals_area(b2bc3ffd), 滑动/sliding(5168d44c), 沿轨道进一槽位/advance_one_slot(5168d44c), 轨道点/track_dot(5168d44c), 等距排列/evenly_spaced(5168d44c), 边缘条/edge_bar(642248e4), 朝近端扩展/toward_nearer_expand(642248e4), 重涂色/recolor(f341894c)

**依赖链**：每个对象的面积 → 确定滑动步数；对象与两侧边缘条的距离 → 确定滑动方向和重涂色颜色；多个对象在同一轨道上碰撞 → 必须按与目标条距离排序依次处理。面积、方向、碰撞三者交织决定最终位置和颜色。

多个不同大小的前景对象沿轨道各自滑动"面积数"个槽位，方向朝向较近的边缘条，滑动后重涂为该条的颜色；若发生碰撞则近者优先，远者停在碰撞前最后空位。

**输入结构**：
- 约 18x10 网格，背景黑(0)。
- 一条竖直轨道：在某一列上等距排列绿(3)单像素点（间距 S，约 2-3 格），贯穿网格中部。
- 2-3 个小型单色前景对象（4-连通，每个 2-5 像素，颜色各不相同，不使用绿(3)/蓝(1)/红(2)/黑(0)），每个对象覆盖恰好一个轨道点位置（该点被对象遮挡）。
- 两条全宽水平边缘条：蓝(1)位于第 0 行（顶部），红(2)位于最后一行（底部）。
- 生成约束：各对象互不重叠；每个对象的像素数不超过总轨道槽位数的一半；滑动后不会超出轨道范围（但可能相互碰撞）。

**规则**：
1. 对每个前景对象，计算其像素数 N。
2. 比较该对象中心行到蓝(1)顶部条和红(2)底部条的行距离，确定较近的条。
3. 沿轨道方向（竖直）将对象滑动 N 个槽位（每个槽位 = 轨道点间距 S），方向朝向较近的边缘条（离顶部条近则上滑，离底部条近则下滑）。若到两条距离相等，则朝上滑动。
4. 滑动后，将对象重涂为较近边缘条的颜色（蓝(1)或红(2)）。
5. 处理顺序：按各对象到其目标边缘条的初始距离排序，近者先处理。若一个对象滑动后会占据已被先处理对象占据的轨道位置，则该对象停在碰撞前的最后一个空槽位上。
6. 被对象离开的轨道点恢复为绿(3)；被对象新覆盖的轨道点被遮挡。

**关键洞察**：面积既是位移量又是碰撞的间接原因——面积大的对象移动远，更容易与其他对象碰撞。处理顺序取决于初始位置与目标条的距离而非面积本身，这意味着一个小对象可能因为离目标近而先处理，从而阻挡后续更大的对象。需要多个示例区分"面积=步数"与"面积=像素距离"。
