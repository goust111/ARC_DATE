## 新题 8：引导边定向旋转后像素放大

**组合逻辑**：[guide_edge/color_match_orientation](引导边颜色与边框控制匹配，确定旋转/镜像方式) → [rotate + reflect](对精灵执行二面体变换) → [crop](裁剪掉引导边) → [pixel_scaling](将裁剪结果放大)

**来源原语**：guide_edge、frame_control、color_match_orientation（fc7cae8d）；rotate、reflect（fc7cae8d, f560132c）；crop（多题）；pixel_scaling、foreground_shape、bounding_box、scale_with_gaps（f25fbde4）

**依赖链**：引导边的颜色匹配决定旋转/镜像方式——不检测引导边就无法确定正确的变换。变换后必须裁剪掉引导边才能得到纯净的精灵内容。裁剪结果再被像素放大——放大尺度取决于裁剪后精灵的尺寸。引导边→变换→裁剪→放大构成严格的信息依赖链，且引导边同时编码了变换方向和裁剪位置（引导边在哪一侧决定从哪一侧裁掉）。

按引导边与边框控制的颜色匹配关系旋转/镜像中央精灵，裁剪引导边后将结果放大两倍。

**输入结构**：一个约 12x12 的网格，黑(0) 背景。网格的四条边中，恰好有两条相邻边（如上边和右边、左边和下边等）由两种不同的纯色填满——例如上边全部为蓝(1)，右边全部为红(2)（角落像素归属于先扫描到的边）。网格中央有一个矩形色块（约 4x5 或 5x4），使用绿(3) 填充内部。该色块的某两条相邻边（各 1 像素宽）分别涂有蓝(1) 和红(2)——这两条是引导边，其颜色与网格边框的两种颜色一一对应。引导边的朝向可能与边框控制不一致（例如蓝色引导边在色块左侧，但蓝色边框控制在网格上方）。生成约束：恰好存在一种二面体变换（旋转 0°/90°/180°/270° 可选配水平/垂直镜像）使得变换后引导边朝向与边框控制朝向一致。

**规则**：
1. 识别网格边框上两种非黑颜色及其所在边（上/下/左/右）。
2. 识别中央矩形色块及其两条引导边（1 像素宽、颜色为边框控制色之一的边）。
3. 找到唯一的二面体变换（旋转+可选镜像），使得色块的蓝(1) 引导边面朝网格的蓝(1) 边框方向，且红(2) 引导边面朝网格的红(2) 边框方向。
4. 对色块（含引导边）执行该变换。
5. 从变换后的色块中裁剪掉两条引导边（各 1 像素宽，分别在匹配方向的那一侧），只保留绿(3) 内部区域。
6. 将裁剪结果进行 2 倍像素放大：每个像素替换为 2x2 同色块。
7. 输出放大后的网格（仅含放大后的绿(3) 区域，背景间隙也一并放大）。

**关键洞察**：引导边是一次性使用的控制信息——它编码了变换方向，用完即裁掉，不出现在最终输出中。像素放大使得裁剪后的小精灵变为更大的输出，如果跳过裁剪直接放大，引导边会被错误地保留并放大。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
