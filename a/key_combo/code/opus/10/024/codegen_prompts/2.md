## 新题 2：旋转条揭示重叠

**组合逻辑**：[rotate/orient_swap_keep](将所有条旋转 90 度) → [logical_AND/pixel_align](检测旋转后两色条的逐像素重叠) + [recolor_by_origin](按来源颜色三分涂色)

**来源原语**：rotate、thin_bar、center_fixed、orient_swap_keep（f0f8a26d）；logical_AND、bitmask、pixel_align、both_mask_overlap（0520fde7）；recolor_by_origin（bcb3040b）

**依赖链**：旋转改变了每种颜色的占据像素集合，重叠检测只对旋转后的状态有意义（原始状态中蓝条全部水平、红条全部垂直，它们的交叉模式完全不同于旋转后的交叉模式）。三分涂色规则又依赖重叠检测的结果。删除旋转步骤，重叠检测的输入错误；删除重叠检测，无法区分三种颜色。

将水平蓝条和垂直红条各自旋转 90 度，然后按旋转后的重叠情况进行三色涂色。

**输入结构**：一个约 13x13 的网格，黑(0) 背景。网格上有若干蓝(1) 色单像素宽条和红(2) 色单像素宽条。所有蓝(1) 条均为水平方向，所有红(2) 条均为垂直方向。每根条长度为奇数（3~9 像素）。条之间互不重叠、互不相邻（任意两条的像素集合在 8-连通意义下不接触）。条的数量：蓝(1) 条 3~5 根，红(2) 条 3~5 根。生成约束：旋转后至少存在一对蓝条与红条在某像素重叠（即某根蓝条的中心行与某根红条的中心列的交点，在两者旋转后的覆盖范围内）。

**规则**：
1. 识别所有蓝(1) 水平条和红(2) 垂直条。对每根条，记录其中心像素坐标和长度。
2. 将每根条绕其中心像素旋转 90 度：水平变垂直，垂直变水平，长度和中心位置不变。
3. 清空网格为全黑(0)。
4. 绘制所有旋转后的条。对每个像素位置：
   - 若仅被旋转后的蓝条覆盖 → 蓝(1)。
   - 若仅被旋转后的红条覆盖 → 红(2)。
   - 若同时被旋转后的蓝条和红条覆盖 → 绿(3)。
   - 若不被任何条覆盖 → 黑(0)。
5. 超出网格边界的部分舍弃。

**关键洞察**：输入中蓝条全部水平、红条全部垂直，看起来互相垂直但几乎不交叉；旋转后蓝条变为垂直、红条变为水平，产生了全新的交叉结构。绿色像素只在旋转后的世界中才能被推导出来。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
