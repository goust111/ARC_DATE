## 新题 3：镜像轴由路径连通性决定

**组合逻辑**：[洪泛填充/路径连通检测](已有) → [连通性决定镜像类型](创新：连通拓扑编码变换类型) → [镜像](已有，但轴选择由拓扑驱动)

**来源原语**：洪泛填充(flood_fill) from b782dc8a; 路径连通(path_connectivity) from b782dc8a; 镜像(mirror) from 963f59bc; 共行列对齐(shared_row_col_align) from 963f59bc; 迷宫走廊(maze_corridor) from b782dc8a

**依赖链**：必须先判断种子像素通过走廊能连通到目标对象的哪一侧（上/下/左/右），连通侧决定该对象的镜像轴方向；若走廊结构不同，同一对象的镜像方式完全不同。

迷宫走廊中的种子像素通过连通路径到达目标精灵体的方向决定该精灵体的镜像轴。

**输入结构**：约 20x20 网格，背景黑(0)。青(8)像素构成迷宫墙壁，形成若干单像素宽的走廊。网格中散布 2~3 个由灰(5)像素构成的小型 4-连通精灵体（3~6 像素，形状不规则且各不相同）。每个精灵体相邻的走廊中恰好有一个红(2)种子像素。种子像素与其对应精灵体之间通过走廊（黑色通路）4-连通可达。生成约束：每个种子与其对应精灵体之间有且仅有一条走廊路径；路径到达精灵体时的最终进入方向唯一确定（从上/下/左/右之一进入精灵体的边界框）。

**规则**：
1. 识别所有灰(5)精灵体和红(2)种子像素。
2. 从每个种子像素出发，沿黑(0)走廊进行 4-连通洪泛搜索，找到与之连通的灰色精灵体。
3. 确定走廊路径最终进入精灵体边界框的方向：从上方进入→水平镜像轴（上下翻转）；从下方进入→水平镜像轴（上下翻转）；从左方进入→垂直镜像轴（左右翻转）；从右方进入→垂直镜像轴（左右翻转）。
4. 对每个精灵体施加对应的镜像变换（以精灵体边界框中心为对称中心）。
5. 保留迷宫墙壁和种子像素不变，仅修改精灵体像素位置。镜像后超出原边界框的像素仍然绘制（覆盖该位置的黑色走廊像素），但不覆盖青色墙壁——若镜像位置与墙壁冲突，该像素不绘制。

**关键洞察**：种子的颜色和位置看似只是简单标记，但真正决定变换类型的是走廊路径的拓扑方向——相同位置的种子若走廊弯曲不同，从不同方向到达精灵体，镜像结果就完全不同。

Reflect the multi-cell foreground mask across each singleton marker so the marker becomes one cell of its colored copy.

Input structure
A background canvas contains one multi-pixel foreground object and one or more singleton marker colors. Each marker
shares exactly one row or exactly one column with a pixel of the source object.

Rule
Keep the source object. For each marker, if it shares a row with exactly one source pixel, reflect the whole source
object horizontally through the vertical midline between that source pixel and the marker. If it shares a column
with exactly one source pixel, reflect the whole source object vertically through the horizontal midline between
them. Paint the reflected mask in the marker color.

Key insight
The singleton marker is one already-reflected cell of the source object, so its aligned source pixel fixes the
mirror axis for the entire copy.
</description>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
