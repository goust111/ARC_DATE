## 新题 9：种子图案四象限镜像展开后填入黑色方孔

**组合逻辑**：[全黑窗口换前景色](创新：填充内容从纯色改为构造图案) + [裁剪] + [翻转形成对称铺展/四象限镜像] + [填充]

**来源原语**：全黑窗口换前景色(6cf79266) + 裁剪(12997ef3) + 翻转形成对称铺展/四象限镜像(62c24649) + 填充(6cf79266)

**依赖链**：种子图案裁剪 → 四象限镜像展开构造填充图案 → 黑色方孔检测 → 用构造图案填充方孔。填充图案不是直接给出的，必须先从种子构造，而方孔尺寸恰好是种子的两倍（四象限展开后匹配），这个尺寸关系是隐式的。

从角落的种子图案做四象限镜像展开，然后将展开结果填入网格中所有全黑方孔。

**输入结构**：约 16x16 的网格。大部分区域是散布的彩色像素（多种颜色混杂，但不含灰(5)），形成一个有噪声的彩色场。网格左上角有一个 2x2 的种子区域，被一圈灰(5)像素（宽 1 像素的 U 形或 L 形边框）标记出来，种子内的 4 个像素为非黑非灰颜色（可能包含 2~3 种颜色）。网格中嵌入 1~3 个完全黑(0)的 4x4 方形空洞，方洞内每个像素均为黑(0)，且方洞不与灰(5)边框接触。生成约束：方洞的 4x4 区域在填充前完全为黑(0)；种子区域的颜色在彩色噪声场中也可能出现（种子不能靠颜色唯一性定位，只能靠灰色边框定位）。

**规则**：
1. 定位灰(5)边框像素，确定其围住的 2x2 种子区域，裁剪出种子图案 S。
2. 将 S 做四象限镜像展开为 4x4 图案 P：S 放左上角，S 的左右镜像放右上角，上半（2x4）的上下镜像放下半，得到 4x4 的 P。
3. 扫描整个网格的所有 4x4 窗口，找到所有 16 个像素均为黑(0)的窗口。
4. 将每个全黑 4x4 窗口的内容替换为图案 P。若多个窗口有重叠（实际上不会，因为全黑窗口之间应间隔），按从左上到右下的顺序处理。
5. 擦除灰(5)边框像素（设为黑(0)），保留种子区域本身不变。其余所有像素保持不变。

**关键洞察**：填充图案不是直接给出的 4x4 块，而是从 2x2 种子经对称展开构造而来。方孔的 4x4 尺寸恰好是种子 2x2 尺寸的四象限展开结果——这个 2 倍关系是隐式的，求解者必须发现种子尺寸与方孔尺寸的对应才能理解构造规则。灰色边框是定位种子的唯一线索，而非装饰。

Stamp recolored copies of the foreground template in the order given by the marker pixels.

Input structure
- A dominant background contains one multi-pixel foreground template color.
- Every other foreground color is a single marker pixel.
- The marker pixels lie on one common row or one common column.

Rule
- Crop the template color to its bounding box and use it as a mask.
- Sort markers left-to-right when they share a row, or top-to-bottom when they share a column.
- For each sorted marker, make one copy of the template mask recolored to that marker color.
- Concatenate the copies horizontally for a marker row, or vertically for a marker column.

Key insight
- The single pixels are an ordered palette; the larger foreground shape is a reusable stencil.

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
