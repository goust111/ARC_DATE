## 新题 9：邻近标记像素计数编码旋转角度

**组合逻辑**：[计数 counting + 角点占用映射标签 corner_occupancy_to_label（创新：从角点占用映射标签改为标记计数映射旋转角度）] → [旋转 rotate]

**来源原语**：counting、corner_occupancy_to_label 来自 27a28665；rotate 来自 67c52801；sprite 来自 845d6e51/20270e3b

**依赖链**：标记像素计数确定旋转角度（计数→分类→编码），旋转操作执行该角度的变换。不计数则角度不可知；不旋转则计数无意义。计数结果与旋转量之间的映射是隐蔽规则，需多个示例归纳。

数清每个精灵体邻域内的标记像素数量，该数量编码了精灵体应旋转的角度。

**输入结构**：约 15x15 网格，黑(0) 背景。3-4 个单色精灵体（4-连通，各自颜色不同，如蓝(1)、红(2)、绿(3)、黄(4)），每个精灵体为不规则连通形状（4-8 像素），具有可辨识的不对称性（使旋转后的结果与旋转前可区分）。每个精灵体的边界框外围 1 像素范围内（即边界框向外扩展 1 像素的环形区域中）散布着若干灰(5) 孤立像素（互不相邻，也不与精灵体相邻）。不同精灵体的灰色标记数量不同（从 1 到 3 不等）。生成约束：精灵体之间的间距至少 4 像素，使得各精灵体的标记邻域不重叠；精灵体旋转后的边界框不超出网格且不与其他精灵体重叠；每个精灵体的形状在 90/180/270 度旋转后两两不同（确保旋转可被验证）。

**规则**：
1. 对每个彩色精灵体，计算其边界框外围 1 像素环形区域内的灰(5) 像素数量 n。
2. 将精灵体绕其边界框中心旋转：
   - n=1 → 顺时针旋转 90 度。
   - n=2 → 旋转 180 度。
   - n=3 → 顺时针旋转 270 度（即逆时针 90 度）。
3. 旋转后的精灵体放置在原边界框中心位置（若边界框尺寸因旋转改变则重新居中）。
4. 擦除所有灰色标记像素（涂黑）。
5. 精灵体按边界框左上角从左上到右下（先行后列）的顺序处理，但由于旋转后互不重叠，处理顺序不影响结果。

**关键洞察**：灰色像素不是精灵体的一部分也不是装饰——它们的数量是旋转角度的密码。求解者必须发现 {1→90, 2→180, 3→270} 这一映射，而这需要对比多个示例（单个示例中可能只看到一种计数值）。

Input structure
- The background is the dominant color.
- One foreground color forms one or more solid 2x2 blocks.

Key insight
- The 2x2 blocks are color rotators and ray blockers; the corner pixels are not independent dots but the four ports of each block.
