## 新题 3：重力落位决定形状匹配填色

**组合逻辑**：[gravity_drop](小对象垂直下落至平台) + [shape_matching](将落点处的对象形状与平台下方密钥图案比较) → [fill](匹配成功则将密钥图案染色) + [erase](匹配成功的对象被吸收移除)

**来源原语**：gravity_drop / collision_stop（来自 36a08778）；shape_matching / support_match（来自 e5062a87）；fill（来自 dbff022c）；erase（来自 1b8318e3）

**依赖链**：对象垂直下落 → 水平位置决定它落在哪个平台上 → 落在平台后，与该平台关联的密钥图案进行形状比较 → 匹配成功触发颜色转移（对象色→密钥图案），不匹配则对象原地保留

彩色小对象从顶部下落至灰色平台，仅当对象形状与平台下方的灰色密钥图案匹配时，密钥图案被染上对象的颜色并吸收该对象。

**输入结构**：约 14x12 网格，黑(0)背景。顶部区域（第 0-2 行）：3-4 个小型 4-连通单色对象（每个 3-5 像素），颜色各不相同（使用红(2)、蓝(1)、绿(3)、黄(4)中的若干种），形状各异。中下部区域：2-4 个灰(5)水平平台段（每段宽 5-7 像素，高 1 像素），分布在不同行高。每个平台正下方一行处有一个灰(5)密钥图案（3-5 像素的 4-连通图形，包围盒不超过平台宽度），密钥图案的形状与某些顶部对象的形状相同或不同。生成约束：每个顶部对象的水平范围恰好与一个平台的水平范围有交叠（确保它能落在该平台上）；不同对象落在不同平台上（水平范围不重叠多个平台）；至少一个对象与其目标平台的密钥不匹配。

**规则**：
1. 每个顶部彩色对象整体向下平移（所有像素同时下移），保持水平位置不变，直到对象最底行像素的正下方一行遇到灰色平台像素时停止（即对象底边紧贴平台顶面）。
2. 对象停稳后，取该对象的像素图案（在其包围盒内的相对坐标集合），与它所停靠的平台正下方的密钥图案的像素图案（在密钥包围盒内的相对坐标集合）进行比较。比较时忽略颜色，仅看相对坐标集合是否完全一致（不允许旋转或翻转）。
3. 若匹配：将密钥图案的所有灰色像素重涂为该对象的颜色。同时将停靠在平台上的该对象的所有像素擦除为黑(0)（对象被"吸收"）。
4. 若不匹配：对象保留在其停靠位置（保持其原色），密钥图案保持灰色不变。
5. 所有平台本身（灰色水平段）在输出中保持不变。

**关键洞察**：重力仅决定空间配对（哪个对象遇到哪个平台），但颜色转移需要形状匹配的二次确认。两个条件缺一不可——即使形状完全匹配，若对象在错误的水平位置（落在别的平台上），也不会发生转移。
