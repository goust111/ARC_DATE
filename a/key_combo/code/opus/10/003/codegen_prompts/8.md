## 新题 8：计数器编码叠加优先级的矩形合并

**组合逻辑**：[透明叠加](创新：叠加时的冲突解决不再要求"标记无冲突"，而是由计数器确定的优先级决定胜出者) + [计数](创新：计数值不再编码空间偏移或半径，而是编码矩形的叠加层级)

**来源原语**：
- 透明叠加(overlay) / 同尺寸对齐(same_size_align) / 标记无冲突合并(markers_merge) ← 25e02866（创新为有冲突的优先级合并）
- 计数(counting) / 计数决定偏移(count_determines_offset) / 计数器消失(counter_disappears) ← e48d4e1a（创新为计数编码优先级）
- 填充矩形(filled_rectangle) / 共享底色(shared_base_color) / 标记像素(marker_pixel) / 计数器像素(counter_pixel) ← 25e02866, e48d4e1a

**依赖链**：识别各同尺寸矩形 → 统计各矩形中灰色像素数量 → 按数量建立优先级排序 → 以优先级解决叠加冲突。计数决定优先级，优先级决定冲突位置的颜色——无法跳过任一步骤。

多个同尺寸填充矩形叠加为一个，标记像素在相同相对位置冲突时由各矩形内灰色计数像素的数量决定优先级。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 3~4个相同尺寸（如5x5）的填充矩形，在网格中分散放置、互不重叠。每个矩形有相同的底色青(8)。
- 每个矩形内含有若干非底色的标记像素（颜色来自蓝(1)、红(2)、绿(3)、黄(4)），标记位于矩形内部不同的相对位置。不同矩形的标记像素可能出现在相同的相对位置但颜色不同（冲突位置）。
- 每个矩形的最底行含有0~3个灰(5)像素，用于编码该矩形的优先级。灰像素数量在各矩形间互不相同。
- 生成约束：至少存在2个相对位置处有标记颜色冲突（即不同矩形在该相对位置有不同颜色的标记）。

**规则**：
1. 识别所有同尺寸填充矩形（以底色青(8)的连通矩形区域识别）。
2. 统计每个矩形最底行中灰(5)像素的数量 G。G 值越大优先级越高。
3. 将每个矩形中的灰(5)像素替换为底色青(8)（灰色仅用于编码优先级，不出现在输出中）。
4. 创建一个与矩形尺寸相同的输出矩形，初始填充为底色青(8)。
5. 按优先级从低到高的顺序，依次将每个矩形的非底色标记像素写入输出矩形的对应相对位置。后写入的（优先级更高的）覆盖先写入的。
6. 输出仅为合并后的单个矩形，置于黑(0)背景上（位置为网格左上角对齐）。

**关键洞察**：各矩形表面上完全对称——大小相同、底色相同。但灰色像素数量编码了隐含的"层级"信息，这决定了标记冲突时谁的颜色胜出。不统计灰色像素就无法确定合并结果。
