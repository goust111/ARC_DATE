## 新题 6：边界标记定平铺维度与棋盘反转

**组合逻辑**：[计数(counting)](创新：按边界方位分别计数，得到两个独立维度) + [平铺(tiling)](创新：平铺倍数不是固定的，而由计数动态决定) + [颜色反转(color_invert)](创新：反转不是全局的，而按棋盘格位选择性施加) + [边界定位(boundary_pos)](创新：边界位置不用于定线方向，而编码平铺参数)

**来源原语**：计数(counting) ← 42a15761/dce56571；平铺(tiling) ← 48131b3c；颜色反转(color_invert) ← 48131b3c；边界定位(boundary_pos) ← 6cdd2623；标记像素(marker_pixel) ← 多题；画布边界(canvas_boundary) ← 6cdd2623；二值图案(binary_pattern) ← 48131b3c

**依赖链**：边界标记的上下/左右分类 → 分别计数得到 V 和 H（不可跳过：无计数则不知平铺维度）→ 平铺 H列xV行 排布（不可跳过：无维度则无法平铺）→ 按 (i+j) 奇偶决定是否反转（不可跳过：反转模式依赖平铺维度，V 和 H 共同决定棋盘格图案）。三步间有信息变换：计数→整数，整数→几何排布，排布位置→布尔选择。

网格边界上的标记像素分上下和左右两组分别计数，得到的两个数决定二值图案的平铺行列数，并以棋盘格方式交替施加颜色反转。

**输入结构**：约 10x10 的网格。中央区域有一个小的二值图案（黑(0) + 一种前景色，如红(2)），尺寸约 3x3 或 3x4，占据网格的中心位置。网格的四条边界（第 0 行、最后一行、第 0 列、最后一列）上散布着若干橙(7)标记像素。标记只出现在边界上，内部无橙色像素。不同示例中标记数量和位置不同，但总在边界上。生成约束：上边界+下边界的标记总数 V 满足 2 <= V <= 4；左边界+右边界的标记总数 H 满足 2 <= H <= 4；输出网格尺寸为 (图案高度 x V) 行 x (图案宽度 x H) 列，不超过 20x20。

**规则**：
1. 统计上边界（第 0 行）和下边界（最后一行）的橙(7)标记像素总数，记为 V。
2. 统计左边界（第 0 列）和右边界（最后一列）的橙(7)标记像素总数，记为 H。
3. 提取中央二值图案（其边界框恰好包含所有前景色像素的最小矩形区域，含内部黑色像素）。
4. 构造输出网格：将图案平铺为 V 行 x H 列的阵列。
5. 对阵列中位置 (i, j)（0-indexed）的图案副本：若 (i+j) 为偶数，放置原始图案；若 (i+j) 为奇数，放置颜色反转图案（前景色与黑(0)互换）。
6. 输出网格中不包含边界标记。

**关键洞察**：边界标记在参考题 6cdd2623 中决定线的方向（上下边→竖线，左右边→横线），本题中则编码平铺维度（上下边→行数，左右边→列数）——同一"边界位置→参数"的结构关系被赋予了全新语义。棋盘反转使得 V 和 H 的具体数值不仅决定输出大小，还决定反转图案的空间分布，两者紧耦合。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
