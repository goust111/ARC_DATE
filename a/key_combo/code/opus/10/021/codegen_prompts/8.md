## 新题 8：格网印章后按邻域密度擦除

**组合逻辑**：[印章覆盖/stamp + 邻域模板/neighborhood_template](创新：印章后的结果不是最终输出，而是中间状态) + [计数/counting + 擦除/erase](创新：计数对象不是孔洞或标记，而是每个格网单元的非背景邻居数，用于决定擦除)

**来源原语**：印章覆盖/stamp、标记单元格/marker_cell、邻域模板/neighborhood_template、格网/lattice、分隔线划分/separator_partition、示例邻域传递同色/exemplar_copied_to_same_color(参考题 39e1d7f9)；计数/counting(参考题 37d3e8b2)；擦除/erase(参考题 54db823b)

**依赖链**：识别装饰标记的邻域模板并印章到所有同色标记 → 印章改变了格网中各单元格的颜色分布 → 在印章后的格网上统计每个非背景单元格的 4-邻域中非背景邻居数 → 邻居数低于阈值的单元格被擦除。印章操作直接改变了后续计数的输入，二者不可独立求解。

在格网中将示例标记的邻域模板印章到所有同色标记后，擦除那些非背景邻居不足的孤立单元格。

**输入结构**：约 13x13 的网格。灰(5)色的水平和竖直分隔线将网格划分为一个 4x4 的格网（每个格网单元约 3x3 含分隔线外的 2x2 可用像素），黑(0)背景。格网中大多数单元格为背景色。有一个蓝(1)色的"装饰标记"单元格，其上、下、左、右四个相邻格网单元中有 2~3 个被涂为不同颜色（红(2)、绿(3)、黄(4)之一），构成邻域模板。另有 2~4 个独立的蓝(1)色标记单元格散布在格网中其他位置（无邻域装饰）。生成约束：装饰标记是唯一一个蓝(1)单元格周围有非背景邻居的蓝单元格；印章时超出格网边界的偏移被丢弃；不同印章之间不会在同一单元格产生冲突（即各独立蓝标记的邻域模板投影不重叠）。

**规则**：
1. 将网格压缩为格网表示（每个分隔线间的单元格取一个值）。
2. 找到唯一的装饰蓝(1)标记——即在格网中蓝(1)单元格中唯一一个至少有一个非背景 4-邻域邻居的。
3. 提取装饰标记的邻域模板：记录其上/下/左/右邻居中非背景单元格的相对偏移和颜色。
4. 对格网中所有其他蓝(1)标记单元格，将邻域模板的每个偏移应用到该标记位置：若偏移后的位置在格网范围内且当前为背景色，则涂上模板中对应的颜色。蓝标记自身保持蓝色不变。
5. 印章完成后，扫描格网中所有非背景单元格，统计每个单元格的 4-邻域（上下左右格网邻居）中非背景单元格的数目。
6. 将非背景邻居数为 0 的非背景单元格擦除（置为背景黑(0)）。装饰标记和其他蓝标记不受此规则豁免——若它们的邻居数也为 0 则同样被擦除。
7. 将格网还原为完整网格输出（恢复分隔线和单元格尺寸）。

**关键洞察**：印章操作本身能"拯救"某些原本孤立的单元格——当两个蓝标记的印章邻域恰好相邻时，印章产物互相成为对方的邻居而存活；而那些印章邻域落在格网边缘、无法获得足够邻居的单元格则被清除。求解者需要先完成印章再做邻居计数，顺序颠倒会导致错误结果。
