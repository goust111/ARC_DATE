## 新题 10：面板旋转后透明叠加

**组合逻辑**：[方向编码 → 旋转](创新：标记位置编码旋转角度) → [透明叠加 + 象限层序](已有)——旋转在叠加之前改变每个面板的内容，使叠加结果不可预测

**来源原语**：透明叠加(transparent_overlay)、裁剪(crop)、面板(panel)、十字分隔线(cross_separator)、图层优先级(layer_priority)、象限位决定层序(quadrant_layer_order) ← e99362f0；方向编码(direction_encoding)、着色标记(colored_marker)、色块决定输出位置(color_direction_determines_placement) ← a8c38be5；旋转(rotate) ← 36d67576

**依赖链**：每个面板中的标记位置编码旋转角度 → 旋转改变面板中图案的朝向 → 旋转后的面板按固定象限层序透明叠加 → 叠加结果由旋转角度和层序共同决定。旋转影响叠加内容，层序影响冲突解决，两者正交耦合。

将十字线分隔的四个面板各自按内部标记编码的角度旋转后，按固定象限层序透明叠加为一个面板。

**输入结构**：黑(0)背景，约 16x16 网格（行列均为偶数+1，使十字线居中）。一条灰(5)色完整行和一条灰(5)色完整列构成十字，将网格分为四个大小相等的矩形面板。每个面板中有一组前景图案（由一种非灰非黑颜色构成，3~8 像素，4-连通，面板间图案颜色各不相同，从蓝(1)、红(2)、绿(3)、黄(4)中取）。每个面板中还有一个品红(6)色单像素标记，位于面板四条边之一的中点附近（距边 0~1 像素）。生成约束：四个面板大小相同（均为 (H-1)/2 x (W-1)/2）。标记位于面板边缘区域的上中、右中、下中或左中位置（一个面板的四种选择之一）。旋转后各面板前景像素不全重叠（确保叠加后能区分图层效果）。

**规则**：
1. 移除灰(5)十字分隔线。
2. 读取每个面板中品红(6)标记的位置，确定旋转角度：
   - 标记在面板上边中部 → 不旋转（0 度）。
   - 标记在面板右边中部 → 顺时针旋转 90 度。
   - 标记在面板下边中部 → 旋转 180 度。
   - 标记在面板左边中部 → 顺时针旋转 270 度。
3. 擦除品红(6)标记像素（设为黑色），然后将每个面板的前景图案按确定的角度绕面板中心旋转。
4. 将四个旋转后的面板对齐到同一画布（大小等于单个面板），按以下层序从底到顶叠加：左下面板（最底层）→ 右上面板 → 左上面板 → 右下面板（最顶层）。
5. 叠加规则：非背景（非黑色）像素覆盖下层。同一位置有多个非背景像素时，层序更高的面板胜出。
6. 输出为叠加后的单面板大小网格。

**关键洞察**：叠加的层序是固定的（由象限位置决定），但每个面板的实际图案朝向由其内部标记编码的旋转决定。两个面板可能有相同的原始图案但不同的旋转角度，导致叠加结果完全不同。求解者必须先分别解码每个面板的旋转，再在脑中执行四层叠加。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
