## 新题 1：反射创建邻接以触发颜色传递

**组合逻辑**：[旋转/点对称](已有) + [邻接传色](已有，但触发条件由反射创造) → [擦除](已有) + [重涂色](已有)

**来源原语**：旋转(rotate)、枢轴像素(pivot_pixel)、点对称(point_symmetry)、绕枢轴半周旋转(half_turn_around_pivot) ← 90347967；重涂色(recolor)、擦除(erase)、标记像素(marker_pixel)、中性遮罩(neutral_mask)、邻接传色(adjacency_transfer)、标记接触即赋色(marker_touch_color) ← b7256dcd

**依赖链**：原始输入中没有任何标记像素与中性遮罩组件 4-邻接——反射通过枢轴创建新的空间邻接关系——邻接传色规则在反射后的布局上生效——传色结果决定最终输出。反射改变了传色的触发条件，传色改变了反射结果的颜色分布，两者交织为一个不可拆分的推理链。

在黑色背景上，将所有前景像素绕灰色枢轴做 180 度点对称反射以创建新邻接，然后利用新邻接关系将标记颜色传递给中性遮罩组件。

**输入结构**：黑(0)背景，约 15x15 网格。包含一个灰(5)枢轴像素。散布着 3~5 个橙(7)色 4-连通组件（每个 3~8 像素，形状各异——可以是不规则斑块、弯曲条带等），作为中性遮罩。另有 2~3 个孤立单像素标记，颜色各不相同（从蓝(1)、红(2)、绿(3)中取），每个标记与所有橙色组件之间至少间隔 2 格（即不存在 4-邻接关系）。生成约束：经过 180 度反射后，至少每个标记的反射像或每个橙色组件的反射像会与某个对方元素产生 4-邻接。所有前景像素（含反射后位置）不超出网格边界。枢轴不与任何其他前景像素重合。

**规则**：
1. 对每个非枢轴、非背景像素 (r, c)，在 (2*pivot_r - r, 2*pivot_c - c) 处放置相同颜色的副本；原始像素保留不动。如果目标位置已有非背景像素，反射像覆盖原有像素。
2. 反射完成后，对每个橙(7)色 4-连通组件（包括原始组件和反射产生的新组件），检查其 4-邻接位置是否有标记像素（包括原始标记和反射产生的标记副本）。
3. 若某橙色组件恰好与一种标记颜色 4-邻接，将该组件整体重涂为该标记颜色。
4. 若某橙色组件与零种或多于一种标记颜色 4-邻接，保持橙(7)不变。
5. 最后擦除所有标记像素（原始和反射副本均设为背景色）。枢轴像素保持灰(5)。

**关键洞察**：原始输入中没有任何标记触碰任何橙色组件——所有颜色传递都是由 180 度反射创造的新邻接关系触发的。求解者必须先在脑中完成点对称反射，才能判断哪些组件会获得哪种颜色。

Input structure
- A black background contains a small colored foreground mask.
- Exactly one grey pixel sits near the mask and acts as the pivot.

Rule
- For each non-background pixel at (r, c), place the same color at
  (2 * pivot_r - r, 2 * pivot_c - c).

Key insight
- The grey pixel is the center of point symmetry; the output is the same colored mask after a half-turn about that pixel.
</description>

  mask:
    description: irregular foreground shape adjacent to pivot (Chebyshev dist 1)
    cell_count: 4-8 non-pivot foreground cells
    distinct_colors: 3-4 (from palette 1-4,6,8; never 5)

    4. Verify all reflected positions (2*pr-r, 2*pc-c) are in-bounds and

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
