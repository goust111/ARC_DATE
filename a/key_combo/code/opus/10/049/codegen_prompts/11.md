## 新题 11：旋转角度由复制次数决定的精灵体印章

**组合逻辑**：[复制放置 + 标记交叉定位](已有) → [旋转](创新：旋转角度不是固定的，由该精灵体的目标位置数量决定) + [计数](创新：计数对象是目标位置而非分量数) → [叠加优先级由目标数排序决定](创新)

**来源原语**：复制放置/replicate_stamp（247ef758）、标记交叉定位/marker_intersection_positioning（247ef758）、精灵体/sprite（247ef758）、框架标记/frame_marker（247ef758）、分隔列/divider_column（247ef758）、颜色匹配配对/color_match_pairing（247ef758）、旋转/rotation（b7cb93ac）、计数/counting（f8b3ba0a）、排序/sorting（f8b3ba0a）

**依赖链**：解析框架标记确定每种颜色的目标行列交叉位置 → 统计每种颜色的目标位置数 → 目标数决定对应精灵体的旋转角度 → 旋转后的精灵体被印章到各目标位置 → 目标数还决定重叠时的绘制优先级（目标多的覆盖目标少的）；计数结果同时控制旋转和优先级两个不同维度

在带框架标记的网格中，每个精灵体被复制到其颜色匹配的所有标记交叉位置，但精灵体的旋转角度由它拥有的目标位置数量决定，重叠时目标位置更多的精灵体绘制在上层。

**输入结构**：约 20x20 的网格，黑(0)背景。右侧有一个矩形框架（由灰(5)像素构成的 1 像素宽边框，内部为黑(0)），框架的上下边和左右边上各有若干彩色标记像素替换灰(5)像素。标记颜色来自 {红(2), 绿(3), 黄(4), 品红(6)} 中的 3~4 种。每种颜色在框架的上边和下边各出现 0~2 次（定义目标列），在左边和右边各出现 0~2 次（定义目标行）。某颜色在上下边均出现的列号与在左右边均出现的行号的笛卡尔积即为该颜色的目标位置集。网格左侧有一个窄条区域（宽 4~5 列），被一列品红(6)... 不对，分隔列颜色不能和标记色冲突。

让我重新设计这个。

实际上让我重新想分隔列的颜色。用栗(9)作为分隔列。

左侧窄条区域（宽约 5 列），被一列栗(9)分隔列与框架区域分开。窄条内从上到下排列 3~4 个精灵体，精灵体之间由至少 1 行黑(0)分隔。每个精灵体是 3x3 的单色 4-连通图形（3~5 像素），颜色与框架标记颜色一一对应。生成约束：每种标记颜色至少有 1 个目标位置；精灵体颜色与标记颜色一一匹配；不同颜色的目标位置数不全相同（至少两种颜色的目标数不同）。

**规则**：
1. 解析框架标记：对每种标记颜色，找出该颜色同时出现在框架上边和下边的列号集合 C，以及同时出现在左边和右边的行号集合 R。该颜色的目标位置集为 R x C（笛卡尔积），即所有 (r, c) 对，其中 r 来自 R，c 来自 C。
2. 统计每种颜色的目标位置数量 N。
3. 根据 N 确定旋转角度：N=1 时不旋转（0 度），N=2 时顺时针旋转 90 度，N=3 时旋转 180 度，N=4 时顺时针旋转 270 度，N>4 时角度 = ((N-1) mod 4) * 90 度。
4. 将旋转后的精灵体以目标位置为中心印章到框架内部。精灵体的中心像素（3x3 边界框的中心）对齐到目标位置。超出框架内部的像素丢弃。
5. 按目标位置数从少到多的顺序印章各颜色（目标少的先画、多的后画覆盖）。同一颜色内按目标位置从上到下、从左到右的顺序印章。目标数相同的颜色，按精灵体在左侧窄条中从上到下出现的顺序排序（上方的先画）。
6. 左侧窄条、分隔列和框架边框不出现在输出中。输出仅为框架内部区域。

**关键洞察**：目标位置的数量不仅决定"在哪里印章"，还决定"印章前怎么旋转"和"重叠时谁在上层"——同一个计数值同时控制了三个不同维度的行为。需要对比多个示例才能同时归纳出旋转规则和优先级规则。
