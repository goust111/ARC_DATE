## 新题 7：色层独立旋转后跨面板叠合与冲突裁决

**组合逻辑**：[旋转](按提示精灵体编码的角度独立旋转各色层) → [透明叠加](分隔面板叠合，创新：旋转后的色层在叠合时产生冲突) → [重涂色](冲突位置由像素数编码规则裁决颜色)

**来源原语**：旋转(rotate)←6ffbe589、色层(color_layer)←6ffbe589、提示精灵体(cue_sprite)←6ffbe589、像素数编码旋转(pixel_count_encodes_rotation)←6ffbe589、透明叠加(transparent_overlay)←e98196ab、分隔行(separator_row)←e98196ab、等高面板(equal_height_panel)←e98196ab、前景不冲突(no_fg_collision→此处创新为有冲突需裁决)

**依赖链**：提示精灵体大小决定各色层旋转角度 → 旋转改变像素位置 → 面板叠合时产生颜色冲突 → 冲突裁决规则依赖于提示精灵体的像素数大小关系。旋转、叠合、裁决三者紧密耦合：旋转角度决定冲突位置，而冲突裁决又引用旋转编码信息。

各色层按提示精灵体大小旋转后移除分隔行并叠合面板，冲突位置保留旋转角度更大的色层颜色。

**输入结构**：约 16×10 的网格，背景为黑(0)。一条横贯全宽的黄(4)实心行将网格分为上下两个等高面板（每个约 7 行）。每个面板使用相同的 2-3 种前景色（取自红(2)、绿(3)、蓝(1)），每种颜色在每个面板中形成一个色层（一组同色像素）。两个面板在分隔行移除前叠合时本身不冲突，但旋转后会产生冲突。网格右侧或底部边缘外围区域有 2-3 个小型单色提示精灵体，每个精灵体的颜色对应面板中使用的一种前景色，精灵体大小为 1-3 像素（像素数互不相同）。生成约束：每个面板的尺寸为正方形或近正方形（行列差不超过 1），使旋转有意义；面板中每种色层的像素在 90° 旋转后不会超出面板边界；至少有一对面板在叠合时存在 2 个以上冲突像素。

**规则**：
1. 识别网格边缘外围的提示精灵体：每个精灵体是一个单色 4-连通区域，颜色匹配面板中的某种前景色。
2. 对每种前景色，计算其对应提示精灵体的像素数 P，旋转角度 = (P mod 4) × 90°顺时针。
3. 在每个面板内，以面板中心为旋转中心，独立旋转每个色层：将该色层的所有像素位置绕面板中心顺时针旋转指定角度。旋转后超出面板边界的像素丢弃。同一面板内不同色层的旋转后像素若重叠，保留旋转角度更大的颜色；角度相同时保留在面板中像素数更少的颜色。
4. 移除黄(4)分隔行。
5. 将上下两面板按局部坐标透明叠合。叠合冲突（两面板的同一局部位置均为非背景）时，保留旋转角度更大的色层颜色；若角度相同，保留上面板的颜色。
6. 输出网格高度 = 单面板高度，宽度 = 原网格宽度。

**关键洞察**：提示精灵体的像素数同时承担两个角色——既编码旋转角度，又隐式定义了冲突裁决的优先级（旋转角度大的优先），这意味着旋转越多的色层在空间竞争中越强势；必须对比多个示例才能发现优先级与旋转角度挂钩而非与颜色本身相关。
