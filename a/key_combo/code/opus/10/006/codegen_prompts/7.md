## 新题 7：图例编码精灵外推印章

**组合逻辑**：[外推/extrapolate + 匀速运动延续/constant_motion](已有) ⊕ [位置对应/positional_mapping + 图例色替换标记/legend_replaces_marker](创新：图例映射的不是标记颜色而是输出精灵的外观) → [印章覆盖/stamp](已有)

**来源原语**：外推/extrapolate + 平移/translate + 帧序列/frame_sequence + 内部精灵/inner_sprite + 等间距排列/equal_spacing + 匀速运动延续/constant_motion（ba1aa698）、印章覆盖/stamp + 裁剪/crop + 图例精灵/legend_sprite + 分隔行/separator_row + 标记像素/marker_pixel + 位置对应/positional_mapping + 图例色替换标记/legend_replaces_marker（20fb2937）

**依赖链**：三条信息线在输出中汇合：(a) 运动外推决定精灵的空间位置，(b) 颜色循环规则决定使用哪个图例条目，(c) 图例映射决定精灵的外观。三者缺一不可：不做外推→位置未知；不识别颜色循环→不知道查询哪个图例条目；不读图例→不知道精灵的外观。任何两者的组合都不能独立产出正确输出。

从帧序列中外推运动位置并推断颜色循环规律，用图例将下一帧的颜色映射为具体精灵外观，在外推位置印章该精灵。

**输入结构**：约 10x28 的宽网格，黑(0)背景。网格中有以下元素：
- 图例区（上部，约 4 行高）：3 个小型填充方块（每个 2x2 像素），颜色各不相同（例如红(2)、蓝(1)、黄(4)），从左到右等距排列。每个方块正下方 1 格处有一个标记像素，颜色与方块不同且各标记颜色互不相同（例如绿(3)、灰(5)、橙(7)）。标记像素的列坐标与方块中心列对齐。
- 一条全宽灰(5)水平分隔行，位于图例区下方。
- 帧序列区（分隔行下方）：3~4 个等宽面板，面板之间共享灰(5)垂直边界列。每个面板内有黑(0)背景和一个单像素标记（颜色为图例标记色之一），位于面板内的某个位置。
- 帧序列中标记的行坐标在连续面板间以固定增量 delta 变化（匀速垂直运动）。列坐标在面板局部坐标系中保持不变。
- 标记颜色在连续面板间按图例从左到右的顺序循环出现（例如：绿、灰、橙、绿、灰、...）。
- 生成约束：面板数 >= 3 以保证运动增量可确认；颜色循环至少走完一轮以保证循环规律可归纳；外推后的标记位置保证印章的方块不超出面板边界。

**规则**：
1. 解析图例：建立标记颜色 → 方块颜色的映射（例如：绿(3) → 红(2), 灰(5) → 蓝(1), 橙(7) → 黄(4)）。同时记录方块的 2x2 形态。
2. 分析帧序列：
   - 识别每个面板中标记像素的局部坐标（行偏移、列偏移）。
   - 计算连续面板间行偏移的差值 delta（应为常数）。
   - 记录连续面板的标记颜色序列。
3. 外推一帧：
   - 位置：在最后一个面板的行偏移基础上加 delta，列偏移不变。
   - 颜色：颜色序列按图例从左到右的顺序循环，取下一个颜色。
4. 构造输出（一个独立面板，与输入面板等宽等高）：
   - 黑(0)背景。
   - 在外推位置处，以标记位置为中心印章图例中对应颜色的 2x2 方块。方块颜色为图例映射的目标颜色（方块本身的颜色），不是标记颜色。
5. 输出仅包含该单个面板，不包含图例和分隔行。

**关键洞察**：标记的颜色不是精灵的颜色——它是一个索引，通过图例间接映射到精灵外观。颜色循环的规律（按图例从左到右的空间顺序）必须从多个示例中归纳，而非从颜色编号的数值顺序推断。
