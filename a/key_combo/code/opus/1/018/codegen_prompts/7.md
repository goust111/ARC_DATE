## 新题 7：对称差异异或掩码循环着色

**组合逻辑**：[镜像](创新：用于空间对齐而非显示) → [异或合成](创新：提取两形状的对称差异作为填色画布) → [循环填充](创新：沿行主序对异或掩码像素循环着色，run-length 由灰色标记高度决定)

**来源原语**：镜像、镜像对应、分隔列（参考题 dd2401ed、c9680e90）；异或合成、半区掩码、恰一为前景、对齐（参考题 31d5ba1a）；循环填充、调色板列、长度标记段、标记高度决定长度、顺序排列（参考题 e7b06bea）

**依赖链**：镜像对齐 → 异或运算确定掩码形状（哪些像素构成画布） → 灰色标记段高度确定 run-length → 调色板确定颜色序列 → 循环填充将颜色按 run-length 铺到掩码像素上。异或结果的形状决定了循环填充的总量和分布；run-length 影响颜色切换频率。

将左右半区的前景形状对齐后取对称差异作为画布，用从灰色标记段读取的 run-length 和调色板颜色对画布像素进行循环着色。

**输入结构**：约 14x25 的网格（宽大于高）。正中有一列灰(5)垂直分隔列。左半区：蓝(1)像素构成一个不规则前景形状（15~30 像素，4-连通），黑(0)背景。右半区：绿(3)像素构成另一个不规则前景形状，黑(0)背景。灰色分隔列的顶部连续 h 个像素为灰(5)（h 取值 1~4，不同示例不同），其下方像素为黑(0)。两个形状水平镜像后部分重叠、部分不重叠（即它们既非完全相同也非完全不相交）。生成约束：对称差异（异或）掩码至少有 8 个像素。

**规则**：
1. 将右半区（不含分隔列）水平翻转，使其与左半区空间对齐。
2. 逐像素分类：若某位置仅在左半区为前景（蓝）且翻转后右半区为背景 → "左独有"；仅在翻转右半区为前景（绿）且左半区为背景 → "右独有"；两者均为前景或均为背景 → 排除。被分类为"左独有"或"右独有"的像素共同构成"异或掩码"。
3. 读取调色板为 [蓝(1), 绿(3)]（即左半区和右半区各自的前景色，按左先右后的顺序）。
4. 读取灰色分隔列顶部连续灰(5)像素的数量 h，作为循环填充的 run-length。
5. 将异或掩码中的像素按行主序排列（第 0 行从左到右，然后第 1 行从左到右，依次类推）。按此顺序，依次为每个掩码像素分配颜色：前 h 个像素着蓝(1)，接下来 h 个着绿(3)，再 h 个着蓝(1)，如此循环直至所有掩码像素着色完毕。
6. 输出一个半区大小的画布，包含着色后的异或掩码像素，其余位置为黑(0)。

**关键洞察**：输出画布的形状由两个前景形状的对称差异决定（既非并集也非交集），而每个像素的颜色由其在掩码中的行主序位置和 run-length 参数共同决定。异或选择规则（而非并集或交集）需对比多个示例才能确认；灰标记段高度编码 run-length 也需对比确认。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
