## 新题 6：字形重建下投影填充

**组合逻辑**：[frame_bar + endpoint_marker + glyph_template + erase + reconstruct + color_to_shape + anchor_position](来自 98c475bf) → [ray_cast + column_coverage + covered_col_to_edge](来自 6d58a25d，创新：射线不是从外部遮挡物下方延伸，而是从重建字形的像素位置向下投射，形成该字形的"列轮廓阴影")

**来源原语**：erase、reconstruct、frame_bar、endpoint_marker、glyph_template、color_to_shape、anchor_position（98c475bf）；ray_cast、foreground_object、column_coverage、covered_col_to_edge（6d58a25d）

**依赖链**：端点标记的颜色关联字形模板 → 字形重建确定像素位置 → 每个字形像素的列位置和行位置决定投影射线的起点和覆盖列 → 不同字形的投影可能在同一列重叠，需按锚行高低优先级解决冲突。字形的具体形状（而非仅边界框）直接决定投影的列轮廓；去掉重建则没有像素位置，去掉列投影则输出不完整，去掉冲突优先级则重叠区颜色不确定。

从端点标记重建字形后，每个字形向下投射列轮廓阴影，高锚行字形的阴影在重叠处优先。

**输入结构**：约 20x15 网格，背景黑(0)。左右各有一条完整高度的灰(5) 竖条（边框）。内部区域包含：一个蓝(1) 完整字形（4-连通，约 8~12 像素，带有非矩形轮廓，如含分支或弯折），以及 2~3 对端点标记（每对在同一行，分别位于第一个和最后一个内部列，颜色各不相同，取自 {红(2), 绿(3), 黄(4)}）。端点标记对的行位于蓝色字形下方。生成约束：蓝色字形的最低像素行与最高端点标记行之间至少隔 2 行；端点标记对之间至少隔 3 行；网格底部到最低端点标记至少留 5 行空间供投影延伸。

**规则**：
1. 记录蓝(1) 字形的模板：以字形最左像素所在行为锚行，记录每个像素相对于锚行的 (行偏移, 列偏移)。
2. 擦除蓝(1) 字形（设为黑(0)）。
3. 对每对端点标记，以其所在行为锚行，用该标记颜色按模板偏移重建字形。
4. 对每个重建字形的每一列，找到该列中属于该字形的最低像素。从该像素下方一格开始，向下填充该字形颜色直到遇到另一个非背景非灰像素或到达网格底部（不含终点像素）。
5. 当两个不同字形的投影在同一格重叠时，锚行更高（行号更小）的字形颜色优先。
6. 灰(5) 边框竖条和端点标记像素保持不变。

**关键洞察**：字形不仅是装饰图案——它的逐列轮廓决定了阴影的宽度和参差形态；不同字形因处于不同高度，其阴影长度和覆盖范围各异，重叠时必须根据锚行高低判断优先级。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
