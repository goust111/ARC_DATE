## 新题 1：象限感知反射印章

**组合逻辑**：[separator_cross + quadrant](来自 2dc579da) → [stamp + sprite + marker_selects_slot](来自 363442ee，创新：槽位变为象限，选择条件变为标记是否存在) → [mirror / axial_symmetry](来自 c9e6f938，创新：反射方向由象限相对位置决定而非全局水平翻转)

**来源原语**：separator_cross、quadrant、marker_quadrant_retained（2dc579da）；stamp、sprite、slot、marker_pixel、partition、marker_selects_slot_for_sprite（363442ee）；mirror、axial_symmetry（c9e6f938）

**依赖链**：分隔十字将网格划分为四个象限 → 标记像素的有无决定哪些象限接收印章（条件判断） → 目标象限相对于源象限的几何位置决定印章的反射类型（空间关系驱动操作变体）。去掉十字则象限不确定，去掉标记则不知道印到哪里，去掉反射规则则印章方向错误。

将一个精灵体按象限相对位置做相应反射后印入每个含标记的目标象限。

**输入结构**：约 15x15 网格，背景黑(0)。灰(5) 构成一条完整行和一条完整列的分隔十字，将网格分为四个大小相等的矩形象限。其中一个象限包含一个蓝(1) 单色 4-连通小图形（3~6 像素，形状不规则，无对称性要求），称为源精灵。其余三个象限中，部分象限包含恰好一个红(2) 标记像素（位置任意但不贴邻分隔线），部分象限为纯背景。生成约束：源精灵的边界框完全落在源象限内部（不触及分隔线）；各示例中源象限位置不固定，精灵形状各异；至少有一个示例中三个目标象限全有标记，至少有一个示例中仅一个目标象限有标记。

**规则**：
1. 识别分隔十字（唯一同时构成一条完整行和一条完整列的颜色）。
2. 确定源象限：包含多像素蓝(1) 图形的那个象限。记录源精灵的形状及其边界框左上角相对于源象限内部区域左上角的偏移 (dr, dc)，以及边界框尺寸 (h, w)。设象限内部区域高 H、宽 W。
3. 对其余三个象限逐一判断：若含红(2) 标记像素则为目标象限，否则跳过。
4. 对每个目标象限，根据其与源象限的相对位置确定反射方式：
   - 同行不同列（水平相邻）：将源精灵左右镜像，放置偏移为 (dr, W - dc - w)。
   - 同列不同行（垂直相邻）：将源精灵上下镜像，放置偏移为 (H - dr - h, dc)。
   - 对角（不同行不同列）：将源精灵上下 + 左右镜像（等效 180 度旋转），放置偏移为 (H - dr - h, W - dc - w)。
5. 印入的精灵使用蓝(1)，标记像素保留红(2)（若精灵像素与标记重叠，标记优先）。
6. 分隔十字、源精灵、无标记象限均保持不变。

**关键洞察**：反射类型没有显式标注——必须从目标象限相对于源象限的行列关系推断出水平镜像、垂直镜像或 180 度旋转，单个示例可能只展示其中一两种，需对比多个示例才能归纳完整规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
