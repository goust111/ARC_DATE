## 新题 3：受损图块定位象限并标记修复

**组合逻辑**：[修复异常/repair](已有，创新为每个象限独立执行多数投票) + [裁剪/crop](已有，创新为由受损检测结果决定裁剪哪个象限) + [重涂色/recolor](已有，创新为将修复像素标记为特殊颜色)

**来源原语**：修复异常/repair(e84fef15)、多数投票共识(e84fef15)、受损副本被标记(e84fef15)、裁剪/crop(88a62173)、象限(88a62173)、分隔十字(88a62173)、异常值选择(88a62173)、重涂色(5a5a2103)

**依赖链**：多数投票在每个象限内部独立执行以识别受损图块 → 受损图块的存在标记出唯一的"异常象限" → 裁剪操作提取该象限 → 修复与标记操作在裁剪结果上完成最终输出；投票结果同时驱动了"选哪个象限"和"修什么像素"两个决策。

在四个象限中找出包含受损图块的那个象限，将其裁剪出来，修复受损图块并用蓝色标记被修复的位置。

**输入结构**：约 21x21 的网格。灰(5)的十字分隔线（中间行和中间列）将网格分成 4 个等大的矩形象限。每个象限内部用橙(7)的细分隔条进一步划分为 2x2 排列的 4 个小图块单元。四个象限各有不同的基础图案（图案使用红(2)、绿(3)、黄(4)、品红(6)中的一种颜色绘制在黑(0)背景上，每个图案为 4-连通的不规则形状，3-8 像素）。在三个象限中，4 个图块完全一致。在恰好一个象限中，某一个图块有 1-3 个像素被擦除为黑(0)。蓝(1)在输入中不出现。生成约束：受损象限中未受损的三个图块足以通过多数投票恢复出完整图案。

**规则**：
1. 对四个象限分别执行：在该象限的 4 个图块之间逐像素多数投票，得到该象限的共识图案。
2. 在每个象限中检查是否存在与共识图案不一致的图块。恰好一个象限包含不一致的图块，称该象限为"受损象限"。
3. 裁剪出受损象限（不含灰色十字分隔线，但保留象限内部的橙色细分隔条）。
4. 将受损图块中与共识不一致的像素位置恢复为共识颜色，并将这些位置改涂为蓝(1)作为标记。其余所有像素保持不变。
5. 输出裁剪后的受损象限（含标记）。

**关键洞察**：多数投票的结果承担双重角色——它既是"哪个象限异常"的检测器（宏观选择），又是"哪些像素需修复"的定位器（微观操作），两个尺度的判断由同一次投票同时得出。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
