## 新题 7：双面板叠加冲突由标记密度裁决

**组合逻辑**：[透明叠加/transparent_overlay](已有，创新为冲突像素的裁决不是取交集而是由标记密度决定) + [计数/counting](已有，创新为计数矩形内标记像素以裁决叠加冲突) + [裁剪/crop](隐含在面板提取中)

**来源原语**：透明叠加(0c9aba6e)、面板/panel(0c9aba6e)、分隔行(0c9aba6e)、位置对齐(0c9aba6e)、计数(8efcae92)、标记像素(8efcae92)、实心矩形(8efcae92)、包含(8efcae92)、标记最多者选取(8efcae92)

**依赖链**：面板分离和位置对齐是叠加的前提 → 叠加产生冲突位置 → 冲突裁决需要计数每个面板中封闭矩形区域内的标记像素 → 计数结果决定该位置由哪个面板的颜色胜出；叠加操作和计数操作互相依赖（需先知道哪里有冲突才知道要比较什么，需要比较结果才能完成叠加）。

将两个面板按位置叠加，在两者都有颜色的冲突位置，取包含更多标记像素的面板一方的颜色。

**输入结构**：约 15x8 的网格，黑(0)背景。一条灰(5)的水平分隔行将网格分为上下两个等大的面板（各约 6x15 或类似比例）。每个面板中有 2-3 个互不重叠的单色实心矩形（矩形使用红(2)、蓝(1)、绿(3)、黄(4)中的颜色，两面板可以使用不同颜色）。部分矩形内部散布着品红(6)的标记像素（替换了矩形原色的若干位置），不同矩形内标记数量不同（0-4 个）。两面板的矩形在位置上有部分重叠区域，也有只出现在一个面板的区域。生成约束：在每个冲突位置，上面板包含该位置的矩形和下面板包含该位置的矩形的标记数量不相等，保证裁决无歧义。

**规则**：
1. 移除灰色分隔行，将上面板和下面板按位置对齐。
2. 逐像素处理：
   - 若该位置两个面板都是黑(0)：输出黑(0)。
   - 若仅一个面板在该位置有非黑像素：输出该非黑颜色（包括品红标记像素原样输出）。
   - 若两个面板在该位置都有非黑像素（冲突）：找到上面板中包含该位置的矩形 R_top 和下面板中包含该位置的矩形 R_bot，分别计数 R_top 和 R_bot 内的品红(6)标记像素数量。标记数量更多的面板胜出，输出该面板在该位置的颜色。
3. 输出与单个面板同大的网格。

**关键洞察**：叠加的冲突裁决规则不是固定的"上优先"或"下优先"，而是由各矩形区域内的标记像素密度动态决定——同一个面板在不同冲突区域可能胜出也可能落败，取决于局部标记计数，这需要对比多个示例中标记分布不同的情况才能归纳。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
