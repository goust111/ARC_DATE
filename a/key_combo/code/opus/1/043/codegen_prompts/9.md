## 新题 9：折叠重叠点触发罗盘射线

**组合逻辑**：[折叠/fold + 透明叠加/transparent_overlay](两面板折叠，检测前景重叠点) → [射线延伸/ray_extend + 罗盘方向/compass_direction](从每个重叠点向四个基本方向延伸射线) + [对称互补/symmetric_complement](非重叠前景像素界定射线终点)

**来源原语**：折叠(fold) ← e3497940；透明叠加(transparent_overlay) ← e3497940；前景优先(foreground_priority) ← e3497940；对称互补(symmetric_complement) ← e3497940；射线延伸(ray_extend) ← 1d398264；罗盘方向(compass_direction) ← 1d398264；中心向外辐射(radiate_from_center) ← 1d398264

**依赖链**：折叠产生两类特殊位置——重叠点（两侧均有前景）和单侧前景点；重叠点是射线发射源，单侧前景点是射线阻挡物——两类位置的角色都依赖折叠结果；射线从重叠点出发，在遇到单侧前景点或网格边缘时停止——射线行为同时依赖发射源和阻挡物的位置。

将网格沿分隔线折叠后，两面板前景像素重叠的位置成为射线发射点，仅单侧有前景的位置成为射线阻挡物；从每个发射点向四个基本方向延伸射线直到遇到阻挡物或边界。

**输入结构**：约 13x(2W+1) 的网格（W 约 6），黑(0)背景，中间有一列品红(6)垂直分隔线贯穿全高。左面板和右面板各有若干红(2)前景像素（每面板 5~10 个像素，形成不规则分布）。两面板的前景像素构成互补图案，但并非完全互补——存在 2~4 个位置两侧都有前景（折叠后重叠），以及若干位置仅一侧有前景。生成约束：重叠点至少 2 个且不在同一行或同一列；从每个重叠点的 4 个基本方向中，至少 2 个方向上存在单侧前景像素作为阻挡。

**规则**：
1. 识别品红(6)分隔列，将网格分为等宽左右面板。
2. 将右面板水平镜像后与左面板对齐。分类每个位置：
   - "重叠点"：左右两侧该位置均有红(2)前景像素。
   - "单侧点"：仅一侧该位置有红(2)前景像素。
   - "空位"：两侧均为背景。
3. 以左面板尺寸创建输出网格，背景为黑(0)。保留所有单侧点，颜色为红(2)。
4. 对每个重叠点，向上、下、左、右四个方向逐格延伸射线，颜色为绿(3)。射线在以下条件停止（不包含停止点）：(a) 到达网格边缘外；(b) 下一格是单侧点（红(2)像素）。
5. 重叠点本身绘制为黄(4)（与射线颜色不同，以标识发射中心）。

**关键洞察**：参考题 e3497940 的折叠是为了将互补的两半合并为完整图案，重叠像素只是验证一致性。这里折叠不产生完整图案，而是产生一种空间分类——同一个折叠操作的结果被解读为两种对立角色（发射器 vs 阻挡器）。求解者必须先理解折叠如何将像素分类，再理解分类结果如何驱动射线行为。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
