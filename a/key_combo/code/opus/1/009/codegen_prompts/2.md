## 新题 2：图元分解驱动的同色滑动归位

**组合逻辑**：[分解](已有) → [重涂色](创新：由分解后的图元形状决定颜色) → [滑动](创新：滑动方向和目标由重涂色结果的颜色决定) + [碰撞阻挡](创新：不同图元间滑动碰撞) + [擦除](创新：无法匹配的残余像素删除)

**来源原语**：分解(decompose, 150deff5), 重涂色(recolor, 150deff5), 基本图元(primitive_shape, 150deff5), 图元形状决定涂色(shape_determines_color, 150deff5), 滑动(slide, 1a07d186), 满行列条(full_span_bar, 1a07d186), 同色配对(same_color_pairing, 1a07d186), 碰撞阻挡(collision_blocking, 1a07d186), 无匹配色则删除(unmatched_deleted, 1a07d186), 擦除(erase, 1a07d186)

**依赖链**：灰色复合体被分解为基本图元 → 图元形状决定重涂颜色（正方形→青、矩形→红）→ 重涂颜色与满行列条颜色配对 → 配对成功的图元朝目标条滑动 → 滑动时图元间碰撞阻挡决定最终停靠位置。分解结果直接改变了滑动操作的目标和路径。

将灰色复合形状分解为正方形和矩形图元，按形状涂色后分别滑向同色满行列条，碰撞时先到者阻挡后到者。

**输入结构**：约 12x12 的黑(0)背景网格。包含一条青(8)全宽水平条（占据某一整行）和一条红(2)全高垂直条（占据某一整列），两条条交叉处为青(8)（水平条优先）。网格其余区域散布 2~3 个灰(5)复合形状，每个复合体由若干紧邻的 2x2 正方形和 1x3 或 3x1 矩形拼接而成（4-连通），总像素数 7~13。生成约束：每个复合体存在唯一的非重叠分解方案；所有图元与两条满行列条之间无遮挡冲突使得至少存在一种合法滑动顺序；灰色复合体不与满行列条重叠。

**规则**：
1. 将每个灰(5)复合形状分解为不重叠的 2x2 正方形和 1x3/3x1 矩形（唯一分解）。
2. 将每个 2x2 正方形重涂为青(8)，每个 1x3/3x1 矩形重涂为红(2)。
3. 青(8)图元沿垂直方向朝青(8)水平条滑动（向上或向下，取决于图元在水平条的哪一侧）。红(2)图元沿水平方向朝红(2)垂直条滑动（向左或向右，取决于图元在垂直条的哪一侧）。
4. 滑动顺序：按图元中心到其目标条的曼哈顿距离从小到大处理（最近者先滑动）。每个图元滑动直至其边缘接触目标条或已停靠的同方向图元为止。
5. 若分解后存在无法归入 2x2 或 1x3/3x1 的残余灰(5)像素，擦除为黑(0)。
6. 满行列条本身保持不变。

**关键洞察**：分解结果不只决定颜色外观——它决定了每个图元的运动方向和目标，进而影响碰撞顺序和停靠位置。不先正确分解就无法确定滑动行为。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
