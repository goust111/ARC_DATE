## 新题 5：面积决定角色的同色滑动对接

**组合逻辑**：[滑动](创新：滑动方向由配对对象的相对位置决定，滑动角色由面积比较决定) + [对接拼合](创新：滑动终止条件为连接点邻接而非固定碰撞) + [重涂色](创新：对接后连接点涂为大精灵体的前景色) + [擦除](已有) ← [面积比较](创新：面积大小决定运动/静止角色) + [同色配对/连接点颜色匹配](创新：连接点颜色用于配对而非对齐) + [碰撞停止](已有)

**来源原语**：滑动(slide, 1a07d186), 对接拼合(docking, 20270e3b), 重涂色(recolor, 67385a82), 擦除(erase, 20270e3b), 精灵体(sprite, 20270e3b), 连接点(connector_pixel, 20270e3b), 面积比较(area_comparison, 67385a82), 同色配对(same_color_pairing, 1a07d186), 连接点颜色匹配(connector_color_match, 20270e3b), 碰撞阻挡(collision_blocking, 1a07d186), 碰撞停止(collision_stop, 332f06d7)

**依赖链**：连接点颜色匹配 → 精灵体配对 → 面积比较确定每对中谁移动谁静止 → 小精灵体沿直线滑向大精灵体 → 滑动终止于连接点 4-邻接（对接）→ 对接后连接点涂为大精灵体前景色，小精灵体原位擦除。面积比较是滑动的前提条件，连接点匹配是配对和对接的双重依据。

通过连接点颜色配对精灵体，面积较小者沿直线滑向面积较大者，直到双方连接点 4-邻接后合并，连接点涂为大精灵体颜色。

**输入结构**：约 14x14 的黑(0)背景网格。散布 4~6 个 4-连通单色精灵体（每个精灵体 3~8 像素，形状不规则），精灵体的前景色各不相同，可选蓝(1)、红(2)、绿(3)、橙(7)等。每个精灵体的边界上有恰好一个连接点像素，颜色与精灵体前景色不同。连接点颜色用于配对：恰好两个精灵体共享同一连接点颜色，形成一对。每对中两个精灵体的面积（不含连接点）不同。配对数为 2~3 对。生成约束：每对中较小精灵体的连接点朝向较大精灵体方向（上/下/左/右之一），且沿该方向到大精灵体的连接点之间无其他精灵体遮挡；不同对的滑动路径互不交叉。

**规则**：
1. 按连接点颜色配对精灵体：共享同一连接点颜色的两个精灵体为一对。
2. 在每对中，比较两个精灵体的面积（不含连接点像素的前景像素数）。面积较大者为"锚"（静止），面积较小者为"活动体"（滑动）。
3. 活动体沿其连接点朝向锚的方向（上/下/左/右，取连接点相对活动体重心最近的基本方向）做直线平移，每步移动 1 像素。
4. 当活动体的连接点与锚的连接点成为 4-邻接时，停止滑动。
5. 将活动体和锚的两个连接点都重涂为锚的前景色。
6. 将活动体滑动前的原始位置（所有像素）擦除为黑(0)。活动体在新位置保留其原始前景色。
7. 各对独立处理，处理顺序不影响结果（由生成约束保证路径无交叉）。

**关键洞察**：面积大小决定了谁移动、谁不动——这不是由空间位置或颜色编号决定的，而是由对象的几何属性（面积）决定的动态角色分配，必须对比多个配对示例才能归纳出此规则。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
