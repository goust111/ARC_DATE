## 新题 1：射线穿透式格点腔室填色

**组合逻辑**：[射线延伸](创新：从标记点出发穿透整个格点骨架，穿过多个腔室) + [填充](创新：由射线穿过与否决定哪些腔室被填色) + [擦除](已有) ← [方向帽](创新：从边框方向帽改为标记像素的方向指示器) + [格点骨架/封闭腔室](已有) + [邻接/距离比较](创新：射线冲突时取距离更近的标记色)

**来源原语**：射线延伸(ray_extend, 4e469f39), 填充(fill, 17b866bd), 擦除(erase, 17b866bd), 格点骨架(lattice_frame, 17b866bd), 封闭腔室(enclosed_cavity, 17b866bd), 标记像素(marker_pixel, 17b866bd), 方向帽(direction_cap, 4e469f39), 邻接(adjacent, 17b866bd)

**依赖链**：方向指示器决定射线方向 → 射线穿过格点确定命中腔室集合 → 命中腔室被填充为射线来源标记的颜色 → 多射线命中同一腔室时，距离更近的标记优先（冲突解决依赖空间距离）。三层操作通过空间交集和距离条件交织。

从标记像素出发沿指定方向射出射线穿透格点骨架，射线经过的每个封闭腔室被填充为该标记的颜色，多射线冲突时近者优先。

**输入结构**：约 15x15 的网格。青(8)像素构成周期性格点骨架，围成若干黑(0)封闭腔室（每个腔室约 12 个像素，参照 5x5 瓷砖结构中骨架围合的矩形空腔）。格点骨架中某些瓷砖的西北角间隙位置放置彩色标记像素（非黑、非青），每个标记像素旁有一个同色的方向指示像素与之 4-邻接，两像素合成一个 2 像素的方向指示器。方向指示器的朝向（指示像素相对标记像素的方位：上/下/左/右）编码射线方向。标记颜色可选红(2)、绿(3)、黄(4)等，每种颜色最多出现一个标记。生成约束：每个腔室最多被两条射线经过；不同标记的方向指示器不冲突（无标记与另一标记重叠）。

**规则**：
1. 对每个标记，读取其方向指示像素的相对方位：上 → 射线向上，下 → 射线向下，左 → 射线向左，右 → 射线向右。
2. 将标记像素及其方向指示像素擦除为黑(0)。
3. 从标记位置沿射线方向逐像素延伸，射线穿过骨架和腔室，直至到达网格边界。记录射线经过的所有腔室（射线至少穿过腔室内一个黑(0)像素即算经过）。
4. 将每个被射线经过的腔室内所有黑(0)像素填充为该标记的颜色。
5. 若同一腔室被两条来自不同标记的射线经过，取标记位置到该腔室中心的曼哈顿距离更小的标记颜色进行填充；若距离相等，取标记位置更靠近网格左上角（先比行号再比列号）的标记颜色。
6. 未被任何射线经过的腔室保持黑(0)不变。青(8)骨架像素全部保留不变。

**关键洞察**：标记不直接填充邻近腔室，而是通过方向指示器编码的射线穿透整个格点，远距离决定多个腔室的颜色——射线的空间路径是填充操作的选择器，冲突解决需要比较距离，三者不可分离。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
