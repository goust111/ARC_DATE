## 新题 2：障碍截断射线与扫描线填充

**组合逻辑**：[射线延伸](从全行/全列延伸 → 遇障碍截断) + [填充](创新：截断端点作为扫描线边界进行行间填充)

**来源原语**：射线延伸/微型标记/朝向决定方向/行覆盖列(9344f635), 碰撞阻挡(3906de3d), 填充/逐行扫描/填充轮廓间区域(aa18de87)

**依赖链**：射线延伸遇到障碍像素被截断，产生截止端点；这些端点在每行上充当扫描线的边界像素；扫描线填充在端点之间注入颜色。删除障碍则射线延伸至网格边缘，不产生行内端点，填充无法触发。删除填充则射线仅改变行/列颜色，不产生端点间的新区域。

彩色多米诺标记向行或列方向发射射线，但射线被灰色障碍截断；截断产生的端点成为扫描线边界，端点之间的空白被填充。

**输入结构**：约 17x17 网格，黑(0)背景。4~6 个彩色多米诺标记（每个为同色的 2 像素 4-连通对象，水平或垂直放置，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，每个多米诺颜色互不相同）。5~8 个灰(5)孤立像素作为障碍，散布于网格中。生成约束：每条射线路径上至少有一个障碍像素；障碍不与多米诺相邻；同一行或列上不超过 2 个多米诺（避免规则歧义）。

**规则**：
1. 对每个垂直多米诺：沿其所在列向上和向下分别发射射线，射线颜色与多米诺颜色相同。射线在碰到灰(5)障碍像素或网格边缘时停止（不覆盖障碍像素本身，射线终止于障碍前一格）。将射线经过的黑色像素涂为多米诺颜色。
2. 对每个水平多米诺：沿其所在行向左和向右分别发射射线，规则同上。
3. 所有列射线先绘制，所有行射线后绘制。行射线在交叉处覆盖列射线颜色。
4. 射线绘制完毕后，在每一行上执行扫描线填充：从左到右扫描，找到所有"射线端点像素"（定义：该像素是某条射线的末端格，即其紧邻的下一格是障碍或网格外）。对每一对相邻的射线端点，若两端点颜色相同，则将它们之间的所有黑(0)像素填充为橙(7)；若颜色不同，填充为栗(9)。
5. 灰(5)障碍像素保持不变。已有颜色的像素（射线像素、多米诺像素）不被填充覆盖。

**关键洞察**：障碍的位置同时决定了射线的长度和扫描线填充的边界位置。移动一个障碍会同时改变射线覆盖范围和填充区域的形状与颜色（因为端点颜色可能因此改变）。需要多个示例才能归纳出"同色端点→橙色填充、异色端点→栗色填充"这一隐蔽规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
