## 新题 9：扫描线填充创建载体区域驱动方向滑动

**组合逻辑**：[填充/逐行扫描](轮廓间填充创建彩色区域) → [滑动](创新：填充产生的区域充当载体，载体颜色编码滑动方向)

**来源原语**：填充/轮廓像素/跨度/逐行扫描/填充轮廓间区域(aa18de87), 滑动/可移动对象/载体区域/嵌入载体内/颜色决定方向(9b4c17c4), 碰撞阻挡(3906de3d)

**依赖链**：扫描线填充在轮廓像素之间创建出彩色区域；这些区域的颜色定义了它们作为载体的滑动方向；嵌入这些区域中的可移动对象根据载体颜色滑动。删除填充则无载体区域，滑动方向无法确定；删除滑动则填充结果只是静态着色。填充步骤的几何输出完全决定了滑动步骤的行为空间。

对角线轮廓像素通过扫描线填充产生交替的蓝色和青色区域，这些区域作为载体决定了嵌入其中的小型对象的滑动方向——蓝色区域内的对象向右滑，青色区域内的对象向左滑。

**输入结构**：约 18x18 网格，黑(0)背景。若干灰(5)像素构成 2~3 条对角线笔画（每条笔画为连续的对角线段，约 5~10 像素长，笔画之间不连通），将网格行内空间分割为多个区间。4~6 个小型可移动对象散布于对角线笔画之间的空白区域中——每个对象为同色的 4-连通图形（2~4 像素，颜色从红(2)、绿(3)、黄(4)、品红(6)中选取，每个对象颜色互不相同）。生成约束：每个可移动对象在至少一行上位于两个轮廓像素之间（确保被填充覆盖）；对象不与轮廓像素相邻；对角线笔画的布局使得同一行上的轮廓像素数量为偶数（确保扫描线配对完整）。

**规则**：
1. 在每一行上从左到右扫描，找到所有灰(5)轮廓像素。将同行中相邻的轮廓像素两两配对（第 1 个与第 2 个配对，第 3 个与第 4 个配对，以此类推）。
2. 对每一对轮廓像素，将它们严格之间的所有黑(0)像素填充为交替颜色：该行中从左数第 1 对填蓝(1)，第 2 对填青(8)，第 3 对填蓝(1)，以此类推。已有颜色的像素（可移动对象的像素）不被覆盖，但它们所在位置的"载体颜色"仍按上述规则确定。
3. 填充完成后，确定每个可移动对象的载体颜色：取该对象所有像素中出现频率最高的载体颜色（即该像素位置按规则应被填充的颜色）。若对象跨越两个不同载体区域，以多数像素所在的载体为准。
4. 蓝(1)载体中的对象整体向右滑动，青(8)载体中的对象整体向左滑动。对象逐格移动直到其任意像素的前方邻格（滑动方向上的下一格）为非黑且非该对象自身颜色的像素，或到达网格边缘。
5. 在滑动后的位置重绘对象（保持原色和形状），擦除原始位置的对象像素（恢复为其载体填充色）。灰(5)轮廓像素保持不变。

**关键洞察**：对角线轮廓的几何形状完全决定了扫描线填充产生的蓝/青交替区域的分布，而这些区域反过来控制对象的滑动方向。修改一个轮廓像素的位置可以改变某个对象所在的载体颜色，从而翻转其滑动方向。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
