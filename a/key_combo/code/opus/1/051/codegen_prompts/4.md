## 新题 4：嵌入计数驱动的印章重复与奇偶重涂色

**组合逻辑**：[计数/counting](创新：计数结果决定印章重复次数而非膨胀距离) → [印章覆盖/stamp_overlay] → [重涂色/recolor + 交替选取/alternating_selection]

**来源原语**：stamp_overlay、sprite、control_pixel、anchor_pixel、relative_coord_copy、strongest_adj_anchor（来自 f5c89df1）；counting、embedded_marker_count、count_determines_expansion（来自 52fd389e）；recolor、alternating_selection、parity_position_recolor（来自 d406998b）

**依赖链**：控制像素的计数决定印章重复次数 N→印章操作在每个目标处生成 N 个副本→副本的序号奇偶性决定其重涂色方案。计数结果既参数化了空间操作（重复次数），又间接参数化了颜色操作（奇偶交替的周期由 N 隐式界定）。

统计精灵体内嵌控制像素数 N，在每个目标位置沿最大空间方向印章 N 次，奇数副本保持原色、偶数副本涂为控制色。

**输入结构**：
- 网格约 20x20，背景黑(0)。
- 网格左上角区域有一个蓝(1)4-连通精灵体（4-7 个蓝(1)像素，不规则形状）。精灵体内部混有 1-3 个绿(3)控制像素（与蓝(1)像素 4-邻接，属于同一连通体的一部分）。
- 精灵体外部紧邻一个红(2)锚点像素：在所有与精灵体 4-邻接的非精灵体像素中，红(2)锚点像素是唯一一个与最多蓝(1)像素 4-相邻的像素。
- 网格其余位置分散有 2-3 个孤立的橙(7)目标标记像素，彼此及与精灵体之间的距离 >= 精灵体包围盒的最大边长 x 3。
- 生成约束：每个目标像素至少在一个基本方向（上/下/左/右）上，到网格边缘的距离 >= 精灵体包围盒对应维度 x N（N 为绿色控制像素数量），以保证有足够空间放置 N 个副本。

**规则**：
1. 统计精灵体内绿(3)控制像素数量，记为 N。
2. 计算精灵体所有蓝(1)和绿(3)像素相对于红(2)锚点的坐标偏移集合 S。
3. 对每个橙(7)目标标记：
   a. 检查目标像素在上/下/左/右四个基本方向上到网格边缘的距离，选距离最大的方向为印章延伸方向。若两个方向距离相同，优先选列方向（上或下），再按上优先于下、左优先于右的顺序决定。
   b. 沿该方向依次放置 N 个精灵体副本。第 k 个副本（k=1,2,...,N）的锚点位置 = 目标像素位置 + (k-1) x 精灵体包围盒在延伸方向上的尺寸 x 延伸方向单位向量。
   c. 第 1、3、5...（奇数序号）副本中，蓝(1)像素保持蓝(1)、绿(3)像素保持绿(3)。
   d. 第 2、4、6...（偶数序号）副本中，蓝(1)像素重涂为绿(3)、绿(3)像素保持绿(3)（即整个副本变为全绿）。
4. 擦除原精灵体（蓝(1)和绿(3)）、红(2)锚点和所有橙(7)目标标记。背景保持黑(0)。
5. 若不同副本发生像素重叠，后放置（序号更大）的副本覆盖先放置的。

**关键洞察**：绿(3)控制像素承担双重角色——其数量决定印章重复次数，其颜色定义偶数副本的重涂色目标。不统计控制像素就无法知道重复次数，不识别其颜色就无法确定偶数副本的涂色方案。印章延伸方向由目标点的空间位置动态决定（非固定方向），需对比多个示例中不同目标的延伸方向才能归纳规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
