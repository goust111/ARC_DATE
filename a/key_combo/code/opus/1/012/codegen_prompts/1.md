## 新题 1：旋转对称门控色对调与象限压缩

**组合逻辑**：[对称检测](从44f52bb0提取，创新为180度旋转对称检测而非镜像对称) → 门控 [颜色互换](从45737921提取，创新为由对称结果有条件触发) → [压缩](从996ec1f3提取，创新为压缩对调后的主色)

**来源原语**：对称检测(symmetry_detection, 44f52bb0), 颜色互换(color_swap, 45737921), 压缩(compress, 996ec1f3), 十字分隔线(cross_separator, 996ec1f3), 四象限(quadrant, 996ec1f3/b10624e5), 对象内双色配对(bicolor_pairing_within_object, 45737921), 对称否决定输出色(symmetric_vs_asym_color, 44f52bb0), 主色代表区域(dominant_per_region, 996ec1f3)

**依赖链**：对称检测的结果作为布尔门控条件决定是否执行颜色互换；颜色互换改变了象限内的主色分布；主色分布的改变直接影响压缩输出的颜色值。三者环环相扣：移除对称检测则不知道哪些象限需要互换，移除互换则压缩结果回退为原始主色，移除压缩则无法生成最终输出格式。

对每个象限内的双色对象检测180度旋转对称性，对称者互换双色，最终将四个象限的后处理主色压缩为3x3网格。

**输入结构**：约20x20网格，黑(0)背景。一条完整的灰(5)行和一条完整的灰(5)列构成十字分隔线，将网格分为四个非空矩形象限。每个象限包含恰好一个由两种非黑非灰颜色组成的4-连通前景对象（5~12像素，形态不限——可以是紧凑块、弯曲条、带分支的连通体等）。每个对象的两种颜色像素数不等（一种多、一种少）。不同象限的对象使用不同的颜色对。生成约束：至少一个象限的对象关于其边界框中心具有180度旋转对称形状，至少一个象限不具有；保证4-连通性和两色不等数条件。

**规则**：
1. 找到唯一的灰(5)整行和灰(5)整列，确定十字分隔线。
2. 对每个象限，提取其中唯一的前景对象，识别该对象使用的两种非背景颜色（记为 A、B）。
3. 将对象的像素模式（仅看形状，忽略颜色）关于其边界框中心做180度旋转，检测旋转后是否与原形状完全重合。
4. 若重合（180度旋转对称）：将该对象中所有 A 色像素改为 B 色、所有 B 色像素改为 A 色。若不重合：保持原样。
5. 对调完成后，统计每个象限中对象像素的主色（像素数较多的颜色）。
6. 输出3x3网格：中间行和中间列填灰(5)（分隔线色），四个角格分别填对应象限的主色。

**关键洞察**：对称检测不是直接决定输出颜色，而是通过门控色对调间接改变哪种颜色成为主色——一个对称的对象互换双色后，原本的少数色变成了多数色，从而翻转了该象限的压缩输出。需要对比多个示例才能发现"对称→互换→主色翻转"这条隐含因果链。
