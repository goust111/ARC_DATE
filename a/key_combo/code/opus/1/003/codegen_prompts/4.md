## 新题 4：虚拟滑动距离选择棋盘格目标

**组合逻辑**：[滑动](创新：不实际移动对象，仅计算假设滑动的距离作为数值) + [计数](已有原语) + [填充·棋盘格](已有原语) + [擦除](已有原语)

**来源原语**：滑动(17829a00) + 同色滑向同色边(17829a00) + 计数(df8cc377) + 像素数匹配格数(df8cc377) + 棋盘格图案(df8cc377) + 空心矩形(df8cc377) + 边界色条(17829a00) + 擦除(df8cc377)

**依赖链**：边界色条确定每个对象的滑动方向 → 计算虚拟滑动距离（不实际移动） → 距离值作为匹配键与空心矩形的棋盘格格数配对 → 匹配成功后用对象颜色填充对应矩形的棋盘格 → 擦除原始对象。滑动操作被重新诠释为"测量工具"而非"运动操作"，其输出是一个数值而非一个位置。

网格顶行和底行分别为两种颜色的边界色条，内部散布同色的小型单色对象和若干灰色空心矩形。每个对象假设向其同色边界滑动，计算出滑动距离，该距离恰好等于某个空心矩形内部棋盘格的格数，以此配对后用对象颜色填充该矩形的棋盘格。

**输入结构**：
- 背景：黑(0)，网格约 15x15
- 第 0 行：全宽红(2)色条
- 最末行：全宽蓝(1)色条
- 内部有 2-3 个小型 4-连通单色对象（每个 3-6 像素），颜色为红(2)或蓝(1)，每种颜色至多出现一个对象
- 内部有 2-3 个灰(5)边框的空心矩形（边框 1 格厚，内部为黑(0)），各矩形内部尺寸不同
- 每个空心矩形内部的"棋盘格格数"定义为：以内部左上角为起点，所有满足 (行偏移 + 列偏移) 为偶数的内部格的数量。各矩形的棋盘格格数互不相同
- 生成约束：对每个彩色对象，其滑动距离（定义见规则）恰好等于某个矩形的棋盘格格数，且不同对象匹配不同矩形

**规则**：
1. 确定每个彩色对象的匹配色条：红(2)对象匹配顶行红色条，蓝(1)对象匹配底行蓝色条。
2. 计算每个对象的滑动距离：
   - 红(2)对象：该对象边界框最上行的行号减去 1（即到顶行色条的行距离）。
   - 蓝(1)对象：(网格高度 - 2) 减去该对象边界框最下行的行号（即到底行色条的行距离）。
3. 计算每个灰色空心矩形内部的棋盘格格数：内部区域中满足 (r - r_interior_top + c - c_interior_left) 为偶数的格的总数，其中 r_interior_top 和 c_interior_left 分别为内部区域的最上行和最左列。
4. 将每个对象与棋盘格格数等于其滑动距离的矩形配对。
5. 在配对矩形的内部，将所有棋盘格位置（步骤 3 中计数的那些格）涂为该对象的颜色，其余内部格保持黑(0)。
6. 擦除所有彩色对象（对象占据的格变为黑(0)）。色条和矩形灰色边框保持不变。

**关键洞察**：边界色条不是物理目的地——它们是计算距离的参照线，滑动距离是一个虚拟测量值而非可见的位移。这个数值被重新诠释为棋盘格选择键，将空间度量转化为组合匹配问题。
