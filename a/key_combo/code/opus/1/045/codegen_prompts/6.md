## 新题 6：标记色选择精灵体拉伸入框

**组合逻辑**：[计数·形状内色频 + 标记色最多者选中](已有，创新：选中的精灵体不是直接裁剪输出，而是作为拉伸模板) → [擦除标记色](创新：标记色仅用于选择，不参与最终形状) → [拉伸 + 线段连接再填充](已有，创新：拉伸源不是预设的外部小精灵体而是选择过程的输出)

**来源原语**：计数/counting、形状内色频/color_frequency_within_shape、标记色像素/marker_color_pixel、标记色最多者选中/max_marker_count_selected、裁剪/crop（来自 ae4f1146）；拉伸/stretch、填充/fill、空心矩形/hollow_rectangle、包围盒映射/bbox_mapping、线段连接再填充/connect_then_fill（来自 465b7d93）；擦除/erase（来自 e41c6fd3）

**依赖链**：计数标记色 → 选中密度最大的精灵体 → 擦除标记色像素得到纯形状 → 将纯形状拉伸映射入框内部。选择结果决定拉伸的源模板；标记色的擦除改变了模板的实际形状（拓扑可能改变），使拉伸结果与任何原始精灵体的直接缩放不同。

统计各精灵体中标记色像素数量选出最密者，擦除标记后将其骨架拉伸填入空心框内。

**输入结构**：约 14x14 的黑(0)背景网格。包含 3 个互不相邻的小精灵体（各占 3x3 边界框），每个精灵体由一种主色（蓝(1)、绿(3)、品红(6)三者之一）和若干橙(7)标记色像素组成。三个精灵体中橙(7)像素数量各不相同（如 1、2、3 个）。网格另一侧有一个较大的灰(5)空心矩形框（内部为黑色，内部区域至少 5x5）。生成约束：选中精灵体（橙色最多者）去除橙色像素后剩余的主色像素至少 3 个且 4-连通，形成可拉伸的线段图案（即相邻像素之间可用水平或垂直线段连接）。

**规则**：
1. 统计每个精灵体中橙(7)像素的数量。选择橙色像素最多的那个精灵体。若平局，选择精灵体边界框左上角更靠上（行号更小）的那个；仍平局则选更靠左（列号更小）的。
2. 在选中精灵体中，擦除所有橙(7)像素为黑(0)，仅保留主色像素。记录剩余像素在精灵体边界框内的相对坐标集合 P。
3. 将精灵体边界框的四个极值（最小行、最大行、最小列、最大列）映射到灰色框内部区域的四个极值（框内最上行、最下行、最左列、最右列）。对 P 中每个像素的相对坐标做相同的线性映射，得到框内映射点集合 Q。
4. 对 Q 中相邻的映射点（原始 P 中 4-连通相邻的像素），在框内用水平或垂直线段连接，线段颜色为该精灵体的主色。
5. 连接完成后，在框内部对所有被线段封闭的背景区域进行洪水填充，填充色为主色。
6. 框的灰(5)边界保留。未选中的精灵体和所有原始精灵体位置擦除为黑(0)。输出网格与输入同尺寸。

**关键洞察**：标记色的功能是双重的——既是选择标准（数量最多的被选中），又是形状干扰（擦除后精灵体的骨架发生变化）；拉伸的源图案不是肉眼直接可见的任何精灵体，而是经过"选择 + 擦除"两步处理后的中间产物。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
