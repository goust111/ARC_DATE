## 新题 1：光晕触碰计数生成框内点阵

**组合逻辑**：[膨胀/光晕](创新：光晕作为空间探测范围) + [同色匹配](已有) + [计数](创新：以物理接触而非纯色匹配为计数条件) + [绘点](已有)

**来源原语**：膨胀/光晕(4258a5f9)、同色匹配(8f215267)、计数/绘点(8f215267)、空心框架(8f215267)、标记保留原色(4258a5f9)

**依赖链**：标记像素膨胀产生光晕 → 光晕是否物理接触框架边界决定该标记是否被该框架计入 → 每个框架的触碰计数决定其内部绘制的点数 → 绘点完成后擦除所有标记和光晕

一句话总结：每个空心框架内绘制的点数等于同色标记像素中光晕能触及该框架的个数。

**输入结构**：黑(0)背景，约 15x15 网格。网格中有 3-4 个空心矩形框架（仅边框像素，内部为背景），每个框架的边框颜色互不相同，可选自蓝(1)、红(2)、绿(3)、黄(4)。框架大小约 4x4 至 6x6，彼此不重叠且不相邻（间距至少 2 格）。网格中另有若干单像素标记点（每个标记点颜色与某个框架颜色相同），散布在框架外部的不同位置。标记点到同色框架的 Chebyshev 距离有些为 1（光晕恰好触碰），有些大于 1（光晕无法触碰）。每种颜色的标记点数量为 1-4 个。生成约束：不同颜色的标记点不会出现在同一位置；同色标记点的光晕（3x3 邻域）互不重叠。

**规则**：
1. 对每个标记像素，生成其 3x3 Chebyshev 邻域（即光晕），颜色与标记相同，超出网格边界的部分舍弃。
2. 对每个颜色为 C 的空心框架 F，扫描所有颜色为 C 的标记像素：若该标记的光晕（含标记自身位置）中至少有一个像素与 F 的边框像素在同一位置（即光晕与框架物理接触），则该标记被 F 计入。
3. 统计 F 的被计入标记数 N。
4. 在 F 的内部区域，沿内部中间行（若内部高度为偶数则取偏上的一行），从最右侧内部列开始，每隔 1 列绘制一个颜色为 C 的点，共绘 N 个点。若内部宽度不够容纳所有点，则从中间行下移一行继续从右往左绘制剩余点。
5. 从输出中移除所有标记像素和光晕像素（恢复为背景色）。框架边框保持不变。

**关键洞察**：不是所有同色标记都被框架计入——只有光晕在空间上触及框架边界的才算。需要对比多个示例来确认是物理接触（Chebyshev 距离 <= 1）而非简单的同色关系决定计数。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
