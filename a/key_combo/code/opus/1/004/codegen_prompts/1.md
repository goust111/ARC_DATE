## 新题 1：对角导轨重力级联

**组合逻辑**：[gravity_drop](已有) + [ray_extend/diagonal](创新：对角线从视觉装饰变为物理偏转导轨) + [recolor](创新：碰撞偏转时触发变色) -- 三者交织为模拟级联，偏转几何决定落水轨迹，导轨色决定水流终色。

**来源原语**：gravity_drop, cascading_branch, collision_stop (36a08778); ray_extend, diagonal_radiation, isolated_pixel (ea786f4a / 623ea044); recolor (78e78cff / aabf363d)

**依赖链**：对角导轨预先确定偏转几何 -> 重力决定水流何时撞上哪条导轨 -> 每次碰撞改变水流行进列并替换水流颜色 -> 最终落点和颜色是所有偏转的叠加结果。删除任一环节（导轨、重力、变色），均无法确定输出。

从顶部水源出发的水流在重力下落过程中被对角导轨逐级偏转并变色，最终落点与颜色由偏转路径的几何叠加决定。

**输入结构**：
- 黑(0)背景，约 15x18
- 顶行有 1-2 个蓝(1)"水源"像素，彼此间隔至少 3 列
- 网格内部有 2-4 条"导轨"线段：每条是一段连续的 45 度对角线，长 3-6 像素，使用同一种非黑、非蓝颜色（如红(2)、绿(3)、黄(4)），从一个起始像素向一个对角方向延伸。每条导轨仅沿一个对角方向（NE、NW、SE、SW 之一）
- 导轨间互不接触，且至少有一条导轨所覆盖的列范围与某个水源的列重合（确保发生碰撞）
- 导轨不接触顶行或底行
- 生成约束：不存在两条导轨在同一列范围内纵向重叠到使同一模拟步出现歧义双碰撞的情况

**规则**：
1. 逐格模拟水流下落。每个水源像素产生一条向下（行号递增）的水流，初始颜色为蓝(1)
2. 水流在当前列垂直下落，每步移动一行，直到遇到导轨像素（原始输入中的非黑、非蓝像素）
3. 碰撞处理：水流停在导轨像素正上方一格并被涂色。水流颜色变为导轨颜色。随后水流沿导轨的对角方向中行号递增的方向滑行（NW-SE 导轨则向 SE 滑，NE-SW 导轨则向 SW 滑）。水流沿导轨每经过一个对角格都涂上导轨颜色，直至滑过导轨末端后再多走一个对角格
4. 滑出导轨后，水流在新列恢复垂直下落，保留当前颜色
5. 水流到达网格底边时停止，该格被涂色
6. 水流遇到已被涂色的非背景像素时，停在其正上方一格（不覆盖已有像素）
7. 原始水源像素保留为蓝(1)；原始导轨像素保留原色
8. 多水源按从左到右处理；同一水源的级联分支按从左到右处理

**关键洞察**：对角线段在源题中仅作为视觉输出（画对角十字），此处被赋予物理斜面的功能角色——其角度改变水流列位、其颜色替换水流颜色，同一水流可经历多次变色。需要多个示例才能确认偏转方向规则（始终沿行号递增的对角分量）和变色规则（取导轨色而非混合色）。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
