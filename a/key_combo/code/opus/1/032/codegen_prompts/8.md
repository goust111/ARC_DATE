## 新题 8：方块计数编码精灵体印章的重涂色映射

**组合逻辑**：[计数/编码](创新：方块计数不再编码到固定图案中，而是生成一个颜色→序号的映射表) + [印章覆盖/周期排布](保留：精灵体按周期网格印章) + [重涂色](创新：印章时精灵体的颜色不按固定规则变色，而是查询计数映射表决定)

**来源原语**：计数/counting(P7-ff28f65a), 编码/encoding(P7-ff28f65a), 前景方块/foreground_square(P7-ff28f65a), 数量映射/count_mapping(P7-ff28f65a), 印章覆盖/stamp(P9-d304284e), 精灵体/sprite(P9-d304284e), 周期排布/periodic_layout(P9-d304284e), 重涂色/recolor(P1-97d7923e)

**依赖链**：方块计数产出颜色→序号映射 → 精灵体的每个像素颜色查询该映射得到序号 → 序号对应固定色表中的输出颜色 → 重涂色后的精灵体按周期网格印章。删除计数则不知道映射关系；删除印章则重涂后的精灵体只出现一次；删除精灵体则无印章内容。三个来源（方块区、精灵体、周期布局）缺一不可。

统计不同颜色的 2x2 方块数量建立颜色映射表，用该映射表重涂精灵体颜色后，将精灵体按周期网格铺满画布。

**输入结构**：约 15x20 的网格，黑(0)背景。分为两个区域：
- 上部区域（约占上方 5-7 行）：散布若干 2x2 的实心彩色方块，颜色包括精灵体中出现的颜色（如红(2)、蓝(1)、绿(3)等）。同一颜色的方块可能出现 1-4 个。方块之间互不相邻（曼哈顿距离 >= 2）。
- 下部区域（约占下方 8-12 行）：包含一个小型多色精灵体（4-连通，4-8 像素，使用 2-3 种颜色，均出现在上部的方块颜色中）。精灵体位于下部区域的左侧。下部区域其余部分为背景。
- 固定色表（不在输入中显示，需从示例推断）：序号 1 → 灰(5), 序号 2 → 品红(6), 序号 3 → 橙(7), 序号 4 → 青(8)。

生成约束：精灵体中出现的每种颜色在上部区域都至少有 1 个 2x2 方块；不同颜色的方块数量互不相同（确保映射无歧义）；方块数量范围在 1-4 之间。

**规则**：
1. 在上部区域识别所有 2x2 实心彩色方块。对每种颜色统计方块数量，得到映射 M：颜色 → 数量。例如 M[红(2)] = 3, M[蓝(1)] = 1。
2. 建立重涂色查询表：对精灵体中的每种颜色 K，其输出颜色为固定色表[M[K]]。例如红(2)有 3 个方块，查固定色表序号 3 → 橙(7)，所以精灵体中的红像素变为橙。
3. 用重涂色后的精灵体作为印章。以精灵体原始包围盒左上角为起始锚点，在下部区域建立周期网格：列间距 = 精灵体宽度 + 1，行间距 = 精灵体高度 + 1。
4. 在每个周期网格位置粘贴重涂色后的精灵体掩码。仅涂背景(0)格点；超出网格边界或进入上部区域的部分裁剪丢弃。
5. 上部区域的方块在输出中被擦除（设为背景(0)）。原始精灵体位置被第一个印章覆盖。

**关键洞察**：2x2 方块不是装饰——它们的数量为精灵体的颜色重映射提供了密钥。精灵体提供形状和初始颜色，方块计数把初始颜色翻译成输出颜色，翻译后的精灵体才能正确印章。仅看一个示例时，印章的颜色似乎"凭空出现"，必须对比方块数量与印章颜色在多个示例间的对应关系才能发现编码规则。固定色表（序号到颜色的映射）本身也是隐蔽规则，需要跨示例归纳。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
