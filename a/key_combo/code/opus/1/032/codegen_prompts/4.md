## 新题 4：模板匹配分类驱动的半区条件重涂色

**组合逻辑**：[模板匹配 + 旋转](创新：匹配结果不再用于印章覆盖，而是作为二元分类器) → [半区变色](创新：不再对所有对象统一涂下半区，而是根据分类结果决定涂上半区还是下半区以及涂什么颜色)

**来源原语**：模板匹配/template_match(P3-6aa20dc0), 旋转/rotate(P3-6aa20dc0), 前景对象/fg_object(P11-e7dd8335), 包围盒/bounding_box(P11-e7dd8335), 半区/half_region(P11-e7dd8335), 半区变色/half_recolored(P11-e7dd8335), 重涂色/recolor(P11-e7dd8335)

**依赖链**：模板的形状掩码（忽略颜色）用于分类每个目标对象 → 分类结果（匹配/不匹配）决定重涂色策略（涂哪半区、涂什么颜色）。删除模板匹配则无法区分对象类别；删除半区重涂色则分类结果无处体现。模板提供分类标准，分类结果驱动空间操作——两者间的依赖不是数据传递而是决策传递。

用模板形状（支持旋转）对散落的前景对象做二元分类：匹配的对象涂下半区为红色，不匹配的涂上半区为蓝色。

**输入结构**：约 15x18 的网格，黑(0)背景。左上角（紧贴第 0 行和第 0 列）有一个小型多色模板对象，占据约 3x3 到 4x4 的包围盒，使用 2-3 种颜色，形状不规则（非矩形，4-连通，3-6 像素）。网格其余位置散布 4-6 个单色前景对象，每个对象是 4-连通的单色形状（3-8 像素），颜色非黑(0)。不同对象的颜色可以相同也可以不同。其中约一半对象的形状（忽略颜色，仅看像素相对位置）与模板在某个旋转（0/90/180/270度）下完全匹配；另一半对象的形状在任何旋转下都不匹配模板。所有对象的包围盒互不重叠，且与模板不重叠。每个对象的包围盒高度至少为 2（确保上下半区各至少占 1 行）。生成约束：匹配与不匹配的对象各至少 2 个。

**规则**：
1. 提取模板的形状掩码：以模板包围盒左上角为原点，记录所有非背景像素的相对 (dr, dc) 坐标集合。忽略模板的颜色信息。
2. 生成模板掩码的 4 个旋转变体（0度、90度顺时针、180度、270度顺时针），每个变体归一化为以 (0,0) 为最小坐标。
3. 对每个非模板的前景对象，提取其形状掩码（同样以包围盒左上角为原点的相对坐标集合）。
4. 将对象的形状掩码与模板的 4 个旋转变体逐一比较。若存在完全匹配的旋转：该对象分类为"匹配"。否则分类为"不匹配"。
5. 对"匹配"类对象：保留包围盒上半区像素的原色不变；将下半区（行索引 >= ceil(bbox_height / 2) 的行，行索引从 0 开始计）所有前景像素重涂为红(2)。
6. 对"不匹配"类对象：将上半区（行索引 < ceil(bbox_height / 2) 的行）所有前景像素重涂为蓝(1)；保留下半区像素的原色不变。
7. 模板对象本身在输出中被擦除（替换为背景(0)）。

**关键洞察**：模板匹配不是为了拼合或覆盖，而是充当一个隐式的"是/否"分类器，其分类结果通过空间位置（上半区/下半区）和颜色（蓝/红）双重编码到输出中。仅看单个示例很难判断为什么有的对象涂上半区蓝色、有的涂下半区红色——必须提取模板形状并测试旋转匹配后才能归纳出分类规则。
