## 新题 4：分区面积奇偶决定循环填充方向

**组合逻辑**：[网格分区/grid_partition](已有) → [计数/counting](已有) → [面积奇偶定填充色/parity_sets_fill](创新：奇偶不决定颜色而决定填充方向) → [循环填充/cyclic_fill](创新：填充方向由外部条件动态决定)

**来源原语**：
- 分隔线、网格分区 ← 6773b310, 7039b2d7
- 计数、面积奇偶定填充色 ← 868de0fa
- 循环填充、循环重复、种子图案 ← 12422b43, 9b30e358
- 封闭区域 ← 868de0fa

**依赖链**：分隔线划定区域 → 计算区域面积 → 奇偶性决定填充方向（向下或向右） → 以区域内已有的种子图案为母题执行循环填充。删除分区则不知道区域边界；删除计数则不知道方向；删除填充则无输出变换。

在由分隔线划定的每个区域中，以区域左上角的小种子图案为母题循环填充该区域，但填充方向由区域面积的奇偶性决定。

**输入结构**：约 17x17 的网格，背景为黑(0)。灰(5) 像素构成完整的水平和垂直分隔线（一像素宽，贯穿整个网格宽度或高度），将网格分为 3x3 共 9 个矩形区域（区域大小不完全相同，宽度范围 3~7 列，高度范围 3~7 行）。每个区域的左上角有一个小种子图案：占据 1~2 行 x 1~2 列，由某种非黑非灰颜色绘制（如蓝(1)、红(2)、绿(3) 等，不同区域颜色可不同）。种子图案所占的行列数不超过区域对应维度的一半。区域其余位置为黑(0)。生成约束：各区域面积（区域内行数 x 列数，不含分隔线像素）有奇有偶，且至少各出现 2 次。

**规则**：
1. 识别灰(5) 分隔线，将网格划分为矩形区域。计算每个区域的面积 = 区域内行数 x 区域内列数。
2. 识别每个区域左上角的种子图案：从区域左上角像素开始，找到连续的非黑像素块，其占据的行数为 H_s、列数为 W_s。
3. 若区域面积为偶数：以种子图案为母题，在区域内沿垂直方向（向下）循环填充。即从种子所在的起始行开始，每隔 H_s 行重复绘制一次种子图案的全部行内容，直到区域底部边缘。每次重复的水平位置与种子相同（仅覆盖种子宽度 W_s 列）。超出区域底部的部分截断。
4. 若区域面积为奇数：以种子图案为母题，在区域内沿水平方向（向右）循环填充。即从种子所在的起始列开始，每隔 W_s 列重复绘制一次种子图案的全部列内容，直到区域右边缘。每次重复的垂直位置与种子相同（仅覆盖种子高度 H_s 行）。超出区域右边的部分截断。
5. 灰(5) 分隔线保持不变。各区域独立处理。

**关键洞察**：同样的种子图案在不同区域中可能呈现完全不同的填充方向——关键在于区域面积的奇偶性，而非种子的形状或颜色；如果单个示例中所有可见区域恰好面积同奇偶，则无法确定方向规则，需要多个示例才能确认方向与面积奇偶的关联。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
