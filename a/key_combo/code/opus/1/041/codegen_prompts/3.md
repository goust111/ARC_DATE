## 新题 3：标记臂方向编码旋转的嵌入填充

**组合逻辑**：[嵌入填充/inlay_fill](已有) + [旋转/rotate](已有) + [擦除/erase](已有)，其中 [最长臂决定镜像侧/longest_arm_mirror_side](创新：臂方向不再编码镜像侧，而编码旋转角度)

**依赖链**：形状匹配确定精灵体属于哪个孔洞 → 十字标记的最长臂方向确定旋转角度 → 旋转精灵体后嵌入对应孔洞 → 擦除所有标记。形状匹配和旋转编码缺一不可：没有形状匹配不知道精灵体填哪个孔洞；没有标记不知道旋转几度（同一形状可能在多种旋转下都能"大致"匹配某个孔洞，但只有标记指定的旋转才精确匹配）。

将框架外的精灵体按形状匹配孔洞，旋转角度由每个精灵体旁的十字标记的最长臂方向编码，旋转后嵌入对应孔洞。

**输入结构**：约 20x20 的网格，背景为黑(0)。一个灰(5) 单色大框架占据网格中央区域（约 12x12），框架宽度为一像素，框架内部有 3~4 个形状各异的孔洞（非灰连通区域，每个孔洞 4~8 像素，4-连通，形状不规则且互不相同）。框架外部散布着与孔洞数量相同的单色小精灵体（每个精灵体颜色不同：蓝(1)、绿(3)、黄(4)、红(2) 等，像素数 4~8，4-连通）。每个精灵体旁（间距 1~2 格）有一个橙(7) 十字标记（一像素宽的十字形，四臂中恰好一臂明显最长，其余三臂等长且较短）。生成约束：每个精灵体的形状恰好匹配一个孔洞（在唯一一种旋转下精确吻合），且该旋转由对应十字标记的最长臂方向编码（最长臂指向上 → 旋转 0 度；指向右 → 顺时针 90 度；指向下 → 180 度；指向左 → 顺时针 270 度）。不同精灵体的颜色互不相同。

**规则**：
1. 裁剪到灰(5) 框架的边界框范围，框架外的区域不出现在输出中。
2. 将框架边界框内全部填充为灰(5)，覆盖所有孔洞。
3. 对每个框架外的精灵体，在框架内找到形状匹配的孔洞（允许旋转匹配，但正确的旋转由标记指定）。
4. 读取该精灵体旁十字标记的最长臂方向，将精灵体顺时针旋转对应角度（上→0°，右→90°，下→180°，左→270°）。
5. 用旋转后精灵体的颜色填充对应孔洞的所有像素。
6. 所有十字标记和框架外精灵体不出现在输出中（输出仅包含框架边界框范围）。

**关键洞察**：标记不指示放置位置或镜像方向，而是编码旋转角度——同一精灵体在多种旋转下可能形状近似匹配某个孔洞，但只有标记指定的旋转才产生精确吻合；需要多个示例才能确认臂方向与旋转角度的映射关系（上=0°、右=90°、下=180°、左=270°）。
