## 新题 6：符号解码驱动的锚点印章

**组合逻辑**：[symbol_decoding](已有：3x3 掩码解码为颜色) → [stamp + color_matching](创新：解码出的颜色作为匹配键而非直接填充，驱动精灵体印章定位)

**来源原语**：symbol_decoding、symbol_mask、panel、symbol_to_color_mapping（17cae0c1）；stamp、sprite、anchor_marker、color_matching、rarest_color_as_anchor（a251c730）；crop（7468f01a）

**依赖链**：符号掩码解码 → 产生颜色键 → 颜色键匹配精灵体锚点 → 印章放置精灵体到解码位置。解码阶段的输出不是最终颜色而是中间匹配信号，这是源题中不存在的结构关系——在 17cae0c1 中解码即终点，在 a251c730 中颜色匹配的键是直接给定的。

解码目标区域中的符号掩码得到颜色，用该颜色匹配源区域中精灵体的锚点色，将匹配的精灵体印章到符号所在位置。

**输入结构**：约 25x10 的网格，黑(0)背景。网格被一条灰(5)竖线（完整高度的单列）分为左右两区。左区（源区域）包含 2-3 个小型多色精灵体（每个为 3x3 至 5x5 的 4-连通图形），精灵体之间互不接触。每个精灵体使用 2-3 种颜色，其中恰好一种颜色在该精灵体内只出现一次，作为锚点色。不同精灵体的锚点色互不相同。右区（目标区域）被黑(0)行分隔为 2-3 个水平面板，每个面板高 3 像素。每个面板内有一个 3x3 的黑(0)/灰(5)二值符号掩码（灰像素构成符号图案）。每个符号掩码对应任务的符号-颜色码本中的一种颜色，且该颜色与某个精灵体的锚点色相同（生成约束：解码颜色与锚点色一一对应）。

**规则**：
1. 识别灰(5)分隔列，将网格分为左区（源）和右区（目标）。
2. 在左区识别各个 4-连通精灵体，对每个精灵体找到出现次数最少的颜色作为锚点色。
3. 在右区识别各个 3x3 面板。对每个面板提取灰(5)像素的二值掩码，用符号-颜色码本（需从示例中归纳）解码为一种颜色。
4. 将每个面板的解码颜色与源区域精灵体的锚点色进行匹配。
5. 将匹配到的精灵体复制到目标区域，使精灵体的锚点像素与该面板的中心像素重合。超出右区边界的部分裁剪丢弃。
6. 输出仅包含右区内容（去掉灰分隔列及左区），尺寸为右区的宽度 x 网格高度。
7. 若多个精灵体的印章区域重叠，按面板从上到下的顺序处理，后印章的覆盖先印章的。

**关键洞察**：目标区域的符号掩码并非直接变成颜色块（与 17cae0c1 不同），而是扮演"地址"角色——解码出的颜色是查找精灵体的索引键。符号码本必须通过对比多个示例中的掩码-精灵体对应关系来归纳。
