## 新题 7：折叠 X 图案作为独立子图的缩放密钥

**组合逻辑**：[折叠/压缩](已有原语) → [计数](创新：计数对象从输入颜色变为折叠后结果的颜色) → [像素放大](已有原语，但作用于独立子图)

**来源原语**：折叠(folding) ← ca8de6ea；压缩(compression) ← ca8de6ea；对角到边映射(diag_to_edge_map) ← ca8de6ea；对角线像素(diag_pixel) ← ca8de6ea；像素放大(pixel_upscale) ← d4b1c2b1；色数决定倍率(color_count_scale) ← d4b1c2b1；色块(color_block) ← d4b1c2b1

**依赖链**：左子图的 X 对角线图案折叠为 3x3 → 折叠过程中不同臂的颜色可能合并到同一位置（取决于颜色是否相同） → 统计折叠后 3x3 中的不同颜色数 → 该数值作为右子图的缩放倍率 → 输出仅包含放大后的右子图。X 图案的颜色多样性在折叠后可能减少（两条臂折叠到同一位置时颜色合并），因此直接数 X 图案中的颜色数会得到错误的倍率。

左侧 5x5 的 X 图案折叠为 3x3 后，其颜色种类数作为右侧 3x3 图案的像素放大倍率。

**输入结构**：约 5x11 的网格。由 1 列灰(5)分隔符将网格分为左右两个 5x5 和 3x3 子区域（左侧 5 列、分隔符 1 列、右侧上部 3x3 居中放置，右侧剩余像素为黑(0)填充。右侧子区域整体为 5x5，3x3 图案居中其中，周围填充黑(0)）。左侧：5x5 网格，黑(0)背景，所有非背景像素严格位于主对角线和副对角线上（共 9 个像素，形成 X 形），使用 2~4 种前景颜色。右侧 3x3 区域内：使用 1~3 种前景颜色的图案，无黑(0)背景像素（所有 9 个像素均为前景色）。生成约束：折叠后的 3x3 中至少有 2 种不同颜色，至多 4 种；倍率确保输出网格不超过 12x12。

**规则**：
1. 提取左侧 5x5 子图。执行 X-到-方形边框折叠：中心像素(2,2)保持在输出(1,1)位置；左上臂像素(0,0)和(1,1)映射到输出的(0,0)和(0,1)——即顶边从左到中心；右上臂像素(1,3)和(0,4)映射到输出的(0,2)和(1,2)——即右边从上到中心；左下臂像素(3,1)和(4,0)映射到输出的(1,0)和(2,0)——即左边从中心到下；右下臂像素(3,3)和(4,4)映射到输出的(2,1)和(2,2)——即底边从中心到右。当两个臂像素映射到同一输出位置时（不会发生，因为 9 个输入位置映射到 9 个不同的输出位置），保留后映射的颜色。
2. 统计折叠后 3x3 网格中的不同颜色种类数 C。
3. 提取右侧 3x3 子图。将其每个像素替换为 CxC 的同色方块，生成 (3C)x(3C) 的输出网格。
4. 输出仅包含放大后的右侧图案，丢弃左侧 X 图案和灰色分隔符。

**关键洞察**：X 图案是一个"密钥"而非输出内容——它的视觉信息永远不直接出现在输出中。折叠操作可能使原本 X 上看到的颜色种类数发生变化（例如 X 上有 4 种颜色，但折叠后两个位置的颜色恰好重复，使得折叠后只有 3 种），因此必须先折叠再计数，而非直接在 X 上计数。需要对比示例中 X 颜色分布和输出缩放倍率的关系才能发现这一点。
