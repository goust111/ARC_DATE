## 新题 6：标记数编码旋转角的精灵印章

**组合逻辑**：[计数](创新：计数结果不用于缩放而是编码旋转角度) + [旋转](已有原语) + [精灵裁剪](已有原语) + [印章覆盖](已有原语)

**来源原语**：计数(counting) ← d4b1c2b1；旋转(rotate) ← 2697da3f；精灵裁剪(sprite_crop) ← 2697da3f；印章覆盖(stamp) ← 8f2ea7aa；标记像素(marker_pixel) ← dc433765；精灵体(sprite) ← 2697da3f；色数决定倍率(color_count_scale) ← d4b1c2b1（创新为"数量决定旋转"）

**依赖链**：裁剪精灵体 → 计算标记像素总数 → (计数 mod 4) × 90° 确定旋转角 → 旋转精灵体 → 在每个标记像素位置印章覆盖旋转后的精灵体 → 擦除原始精灵体位置。标记像素同时承担两个角色：数量编码旋转角度，位置决定印章坐标。改变任何一个标记都同时改变旋转角度和印章布局。

标记像素的总数编码旋转角度，标记像素的位置决定印章放置点，精灵体经旋转后被印章到每个标记位置。

**输入结构**：约 12x12 的黑(0)背景网格。一个由蓝(1)像素构成的紧凑不规则精灵体（4-连通，3~6 像素，边界框约 2x3 或 3x3，非旋转对称——即 0/90/180/270 度旋转后外形不同）。若干红(2)单像素标记散布在网格中（总数 1~7 个），标记之间 8-邻域互不相邻，标记与精灵体的边界框也互不重叠。生成约束：以每个标记为中心放置旋转后精灵体的边界框时，各印章之间互不重叠且不与原始精灵体重叠，不超出网格边界。

**规则**：
1. 裁剪蓝(1)精灵体至其最小边界框，记录精灵体形状。
2. 统计网格中红(2)标记像素的总数 K。
3. 将精灵体顺时针旋转 (K mod 4) x 90 度。当 K mod 4 = 0 时不旋转。
4. 对每个红(2)标记像素：以该标记位置为旋转后精灵体边界框的中心（若边界框边长为偶数，则中心取左上偏移），用蓝(1)覆盖旋转后精灵体的前景位置。超出网格边界的部分丢弃。
5. 擦除原始精灵体位置的所有蓝(1)像素为黑(0)。
6. 所有红(2)标记像素保留不变。

**关键洞察**：标记像素是双重编码体——其数量决定旋转角度（影响精灵体形态），其位置决定印章坐标（影响空间布局）。增减一个标记同时改变精灵体的旋转状态和印章分布，使得两个维度不可分离。需要对比不同标记数量的示例才能归纳出 (K mod 4) x 90 度的旋转规则。

p = Path("/home/lixinyu/snap/a/key_combo/code/opus/3/027/6.py")
mod = SourceFileLoader("new_arc_task", str(p)).load_module()
sigs = set()
for i in range(100):
    inp = mod.generate_input()
    out = mod.main(inp)
    assert isinstance(inp, np.ndarray)
    assert isinstance(out, np.ndarray)
    assert inp.ndim == 2 and max(inp.shape) <= 30, f"input grid exceeds 30x30: {inp.shape}"
    assert out.ndim == 2 and max(out.shape) <= 30, f"output grid exceeds 30x30: {out.shape}"
    sigs.add(hashlib.md5(inp.tobytes() + str(inp.shape).encode()).hexdigest())
print("variants", len(sigs))
assert len(sigs) >= 20
