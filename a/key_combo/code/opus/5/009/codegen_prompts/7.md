## 新题 7：地形坡向编码可移动像素的滑动方向

**组合逻辑**：[重力下落→滑动/slide](创新：滑动方向不是全局固定的"向下"，而是由每个区域的地形坡向局部编码) + [重涂色/recolor](创新：重涂条件由地形高度极值决定，而非直接由颜色属性决定)

**来源原语**：gravity_drop、可移动像素/movable_pixel、碰撞停止/collision_stop、编码映射/encoding_map（参考题 88e364bc）；recolor、地形轮廓/terrain_contour、列高度极值/column_height_extreme、最深与最浅列唯一/unique_deep_shallow（参考题 e45ef808）；分隔墙线/separator_wall、背景区域/background_region（参考题 3bd292e8）

**依赖链**：分隔墙划分区域 → 每个区域的地形轮廓坡向决定该区域的滑动方向 → 可移动像素按该方向滑动至碰撞停止 → 滑动后，地形最高和最低区域的可移动像素被重涂为特殊颜色。地形既是物理障碍又是方向编码器，双重角色不可分离。

红色墙线将网格分为多个区域，每个区域底部有灰色地形轮廓，黄色可移动像素根据所在区域地形的坡向滑动，最终地形最高区域和最低区域的像素被标记为特殊颜色。

**输入结构**：黑(0)背景，网格约 18x18。红(2)墙线（1 像素宽，水平或垂直线段）将网格分为 4-6 个矩形区域。每个区域底部有灰(5)地形轮廓——从区域底行向上、每列有一段连续的灰色像素，各列高度不同，形成一个不规则的地形剖面。每个区域的地形轮廓有明确的单调趋势：要么从左到右递增（左低右高），要么从左到右递减（左高右低）。每个区域中散布 2-4 个黄(4)可移动单像素，位于地形之上的空背景位置。生成约束：所有区域中恰好有一个区域的地形最高列高度是全局最大值（唯一），恰好有一个区域的地形最高列高度是全局最小值（唯一）；每个区域内的可移动像素在滑动后不会超出区域边界。

**规则**：
1. 识别红(2)墙线划分的所有矩形区域。
2. 对每个区域，分析其灰(5)地形轮廓的坡向：比较地形最左列高度和最右列高度。若最左列高度 < 最右列高度（左低右高），则该区域的滑动方向为"向右"；若最左列高度 > 最右列高度，则滑动方向为"向左"。
3. 每个区域内的所有黄(4)像素沿该区域的滑动方向水平移动，遇到以下障碍时停止在障碍前一格：红(2)墙线像素、灰(5)地形像素、区域边界（网格边缘）、另一个已停止的黄像素。同一区域内多个黄像素按滑动方向排序（向右滑则从最右边的像素开始处理，向左滑则从最左边的开始），逐个结算。
4. 滑动完成后，计算每个区域的地形峰值 = 该区域中灰(5)地形轮廓最高列的高度（像素数）。
5. 地形峰值全局最大的区域内所有黄(4)像素重涂为栗(9)。
6. 地形峰值全局最小的区域内所有黄(4)像素重涂为蓝(1)。
7. 其余区域的黄(4)像素保持黄色。墙线和地形不变。

**关键洞察**：地形轮廓扮演双重角色——它既是可移动像素的物理障碍（影响滑动终点），又通过坡向编码了滑动方向（影响滑动起始行为），还通过峰值高度决定了最终的重涂标记。三个功能耦合在同一个几何结构上，无法分离处理。
