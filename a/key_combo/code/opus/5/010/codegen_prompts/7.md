## 新题 7：逐格旋转的模板扩展

**组合逻辑**：[颜色到模板映射/color_stencil_map + 顺序配对/ordered_pairing](已有) + [像素放大/pixel_expand](已有) + [朝向决定方向/orientation_determines_direction](创新：微型 domino 朝向编码旋转角度而非射线方向) → [旋转/rotate](已有，作用于逐个扩展块而非整个图形)

**来源原语**：色卡/color_swatch, 模板遮罩/stencil_mask, 索引网格/index_grid, 颜色到模板映射/color_stencil_map, 顺序配对/ordered_pairing, 像素放大/pixel_expand — 来自参考题 42f83767；微型标记/micro_marker, 朝向决定方向/orientation_determines_direction — 来自参考题 9344f635；旋转/rotate — 来自参考题 1a244afd

**依赖链**：图例区色卡与模板按左到右顺序配对 → 建立颜色→模板映射 → 索引网格每个像素查表获得对应模板 → 同行的微型 domino 标记朝向决定旋转角度（水平=0°，垂直=90°）→ 模板经旋转后扩展为输出块

索引网格的颜色选择模板形状，旁边的微型标记决定该块旋转多少度，两个独立信息源共同决定每个扩展块。

**输入结构**：黑(0)背景，约 20×14 的网格，分上下两个区域，中间隔一行黑(0)空行。上方为图例区（约占 4~5 行）：左侧并排 2~3 个 2×2 色卡方块（颜色各不相同，如红(2)、绿(3)、黄(4)），每个色卡内部全部填充同一颜色；右侧对应位置并排同等数量的 3×3 灰(5)模板遮罩（每个遮罩由灰(5)像素和黑(0)孔洞组成，形状非对称，使得旋转 90° 后图案与原始可区分）。色卡和模板之间间隔 1~2 列。下方为索引区（约占 6~8 行），由两部分水平相邻组成：左侧是一个 3×3 的索引网格（每个像素的颜色取自色卡集合中的某一颜色，不含黑(0)或灰(5)）；紧邻索引网格右侧一列是 3 个橙(7)微型标记，从上到下每个标记占据 1 行，每个标记为 2 个像素的 4-连通 domino——水平排列（同行相邻两像素）或垂直排列（同列相邻两像素）。每行恰好一个 domino 标记，指示该行所有索引像素的旋转方式。生成时保证：图例中色卡数量等于模板数量，按从左到右位置一一配对；所有模板尺寸相同（均为 3×3）。

**规则**：
1. 在图例区，将色卡与模板遮罩按从左到右顺序一一配对，建立颜色→模板映射表。
2. 对索引网格的第 r 行（r = 0, 1, 2），读取该行右侧的橙(7) domino 标记朝向：水平 domino → 旋转角度 0°；垂直 domino → 旋转角度 90°（顺时针）。
3. 对索引网格的每个像素 (r, c)：
   a. 查其颜色在映射表中对应的 3×3 模板遮罩。
   b. 将模板按第 r 行的旋转角度顺时针旋转。
   c. 在输出网格中，以 (r×3, c×3) 为左上角的 3×3 区域绘制旋转后的模板：模板中灰(5)像素替换为索引像素的颜色，黑(0)孔洞保持黑(0)。
4. 输出网格大小为 9×9（3 行×3 列，每格 3×3）。

**关键洞察**：颜色决定"用哪个模板形状"，微型标记朝向决定"旋转几度"——这两个独立信息源分别来自不同位置（颜色来自索引格、旋转来自行标记），必须同时正确解读才能确定每个扩展块的最终形态；单独解读任何一个信息源都无法唯一确定输出。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
