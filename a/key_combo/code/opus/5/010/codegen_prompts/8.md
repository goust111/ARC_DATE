## 新题 8：孔洞计数驱动的限距滑动

**组合逻辑**：[计数/counting + 连通孔洞数为键/connected_hole_count_is_key](创新：孔洞数从匹配键变为滑动距离上限) → [滑动/slide + 同色滑向同色边/slide_to_match](已有) + [碰撞停止/collision_stop](已有) + [冲突优先级/conflict_priority](创新：孔洞数少的优先滑动)

**来源原语**：空心框架/hollow_frame, 孔洞/hole, 连通孔洞数为键/connected_hole_count_is_key, 计数/counting, 嵌套放置/nest_inside — 来自参考题 8698868d；滑动/slide, 边界色条/border_bar, 颜色匹配/color_matching, 同色滑向同色边/slide_to_match, 碰撞停止/collision_stop — 来自参考题 17829a00

**依赖链**：计算每个空心框架内部连通黑(0)孔洞区域的数量 h → h 同时决定两件事：(1) 该框架的最大滑动距离，(2) 滑动执行优先级（h 小的先动）→ 颜色匹配确定滑动方向（朝同色边界条）→ 先动的框架到位后成为障碍阻挡后动者

每个空心框架向同色边界滑动，但最多只能滑动其内部孔洞数步，孔洞少的先动并可能堵路。

**输入结构**：黑(0)背景，约 16×16 的网格。第 0 行（顶行）为红(2)全宽色条（整行全部为红(2)），最后一行（底行）为绿(3)全宽色条（整行全部为绿(3)）。网格内部（第 1 行到倒数第 2 行）散布 4~5 个空心框架，每个框架为一像素宽的矩形边框（外尺寸约 3×3 到 5×5），颜色为红(2)或绿(3)。每个框架内部有 0~3 个灰(5)单像素或双像素障碍物，将框架内部的黑(0)空间分割为若干连通区域（即孔洞）。无内部障碍物的框架孔洞数 h=1（整个内部为一个连通黑(0)区域）；有 1 个障碍物可能 h=1 或 h=2，取决于障碍物是否接触框架边界等。各框架的 h 值互不相同。生成时保证：所有框架初始位置互不接触且不与边界色条接触；各框架与其同色边界条之间的距离均大于等于该框架的 h 值（确保有足够空间滑动）；至少有两个同色框架的滑动路径在同一列上存在交叉可能。

**规则**：
1. 对每个空心框架，计算其内部连通黑(0)区域的数量 h（灰(5)障碍物不计为孔洞的一部分；若框架内部完全为黑(0)则 h=1）。
2. 确定滑动方向：红(2)框架向上滑动（朝顶行红(2)色条），绿(3)框架向下滑动（朝底行绿(3)色条）。
3. 按 h 值从小到大排序所有框架。h 值相同时，距离目标边界色条更近的框架优先。仍然相同时，列号小的优先。
4. 按排序顺序依次执行每个框架的滑动：框架整体（含其内部灰(5)障碍物）沿上或下方向移动，最多移动 h 格。移动过程中，若框架的前进方向边界的下一行（或上一行）存在非黑(0)像素（包括已到位的其他框架、边界色条），则框架在该位置前一格停止（框架边界与障碍物相距 0 格，即紧贴但不重叠）。
5. 所有滑动完成后，框架及其内部在新位置绘制，原位置恢复为黑(0)。

**关键洞察**：框架的内部结构（孔洞数）同时控制两个关键参数——最大移动距离和移动优先级；孔洞少的框架"能力弱"（走得少）但"行动快"（先滑动），可能堵住孔洞多的框架的去路，产生"早到者设障"的涌现效应；必须先正确计算所有框架的孔洞数才能确定全局执行顺序和最终布局。
