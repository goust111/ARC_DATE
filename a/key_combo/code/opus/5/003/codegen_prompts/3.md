## 新题 3：块网格反转后的图例链式重涂

**组合逻辑**：[反转编码](保留精灵/空白互换的核心) + [逐行顺序链式替换](创新：替换目标不是预先存在的像素，而是反转操作产出的像素——反转改变了"哪些空间位置包含精灵颜色"，从而改变了链式替换的作用对象)

**来源原语**：反转编码/块网格/重复精灵体/均匀空白块/精灵与空白互逆/通配符视为空/修复(6350f1f4)，重涂色/双列图例/图例行序决定替换/逐行顺序链式替换/前景像素(e4888269)

**依赖链**：反转编码 → 精灵图案出现在原本为空白的块中 → 这些新位置上的精灵颜色成为图例链式替换的目标 → 替换按行序逐行扫描，同一像素可被连续替换多次 → 输出颜色同时取决于"哪些块被反转"和"图例替换链的顺序"。反转和重涂不可交换执行顺序：先重涂再反转与先反转再重涂产生不同结果，因为反转改变了重涂的空间目标，而重涂改变了反转后的颜色值。

反转块网格的精灵/空白编码，然后用双列图例对反转结果进行逐行链式颜色替换。

**输入结构**：

- 约 18x18 网格，由黑(0)分隔行和分隔列划分为 4x4 阵列共 16 个等大 3x3 块。
- 每个块为下列两种状态之一：(a) 某个固定两色精灵图案的副本（例如红(2)和黄(4)像素以固定 3x3 排列），或 (b) 精灵少数色（例如全黄(4)）填充的均匀空白块。部分块上有灰(5)像素作为擦除/通配符。
- 块网格右侧（不与块重叠）有一个双列竖直图例，包含 2~3 行，每行左列为被替换色、右列为替换色（例如：红(2)→绿(3)，黄(4)→蓝(1)）。
- 生成约束：至少一个块完全无灰(5)擦除，可从中推断完整精灵图案；图例中存在至少一组传递替换（即某行右列颜色等于后续行左列颜色，使得链式替换实际发生多次传递）。

**规则**：

1. 从完全可见的混色块推断出重复精灵图案（忽略灰色擦除像素）。
2. 反转块网格：将匹配精灵的块（灰色像素视为匹配通配符）替换为精灵多数色的均匀填充块；将均匀空白块替换为完整精灵图案。
3. 清理灰色擦除：分隔行/列上的灰(5)恢复为黑(0)；块内的灰色已被反转步骤解决。
4. 对反转后网格中所有非背景(0)、非分隔符(0)的像素，按图例行从上到下逐行扫描执行链式替换：若当前像素颜色等于该行左列颜色，则替换为右列颜色，然后继续扫描后续行（同一像素可在一次扫描中被多次改写）。
5. 图例本身、分隔符和背景不变。

**关键洞察**：反转和重涂不是独立的两步流水线——反转重新分配了精灵颜色的空间位置，图例链式替换再改写这些颜色。不做反转则图例会重涂错误的块（原始精灵位置而非反转后位置）。图例的行序也很关键：链式替换的先后顺序决定了中间颜色是否被二次传递改写，仅看单个示例无法区分"并行替换"与"链式替换"。
