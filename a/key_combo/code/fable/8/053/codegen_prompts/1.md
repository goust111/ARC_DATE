## 1. 孔洞的钥匙

- 参考题目：20 (1f85a75f)、5 (ce602527)、9 (77fdfe62)

### docstring

```text
一句话总述：裁剪最大连通对象，并用散落在外的小碎块作为形状钥匙给它的内部孔洞上色。

输入结构：
- 背景为最常见色。
- 网格上有一个面积最大的单色四连通对象，其内部含若干形状互不相同的背景孔洞。
- 对象之外散落着若干小的单色连通碎块：其中一部分碎块与某个孔洞平移全等，
  其余碎块与任何孔洞都不全等。

规则：
- 找到唯一的最大四连通对象，取其边界框做紧致裁剪作为输出画布。
- 对该对象的每个内部孔洞，在外部碎块中寻找与其平移全等（不旋转不翻转）的
  碎块；找到则把该孔洞整体填成该碎块的颜色。
- 与任何孔洞都不全等的碎块是真噪声，不产生任何效果；没有配对碎块的孔洞
  保持背景色。

关键洞察：
- 散落的小碎块并非应当丢弃的噪声：它们是按形状配键的填色图例，孔洞的
  形状本身就是查找钥匙——"提取大物体、扔掉小碎块"的惯性思路正是诱饵。
```

    rows 7-26: 4x4 table of 5x5 glyph cells (no gaps between cells)
    row 27: full-width separator (color 6)
    rows 28-29: verdict band (2 rows)
    cols: 1 bg gap + 4*5 cells + 1 bg gap = 22
  table:
    size: 4x4 grid of 5x5 cells, each containing a 3x3 monochrome glyph centered in inner 3x3
    colors: 8 available colors (0-9 minus 3 and 8), each used 1-3 times across 16 cells
    shapes: all 16 cells have distinct 3x3 binary patterns; 5-9 filled pixels per glyph
    uniqueness: every (color, shape) pair is unique across all 16 cells
    fixed across examples: yes [observed] -- generator should create a new random table each call
  query:
    count: 3-4 glyphs placed in the same column slots as table columns
    source: each query glyph is an exact copy (same color + shape) of a distinct table cell
    empty_slots: 0-1 trailing slots may be empty (when count < 4)
  outcome:
    success: all 4 query slots filled AND matched table cells form one complete row or one complete column
    fail: matched cells do NOT form a complete row or column, OR fewer than 4 queries
  output_transform:
    always: green-fill (3) the bg pixels inside each matched table cell
    success: also green-fill all bg in query band + fill entire verdict band with green (3)
    fail: query band unchanged + fill entire verdict band with red (2)

generation_strategy:
  approach: output-first
  steps:
    1. Generate a 4x4 table of 16 glyphs with unique (color, 3x3 shape) pairs; use 8 colors from {0,1,2,4,5,6,7,9}, each 5-9 filled pixels in inner 3x3, all shapes distinct
    2. Decide outcome (success ~40%, fail ~60%)
    3. If success, pick a random complete row or column (4 glyphs) as query set
    4. If fail, pick 3-4 glyphs from distinct table cells that do NOT all share a single row or column; if 4, also ensure they don't form a complete row/col
    5. Place query glyphs in column slots 0-3 (leave slot 3 empty if only 3 queries)
    6. Assemble grid: query band (rows 0-4) + separator + gap row + table (rows 7-26) + separator + verdict band (rows 28-29, all bg)
    7. Run solver to produce output (green-fill matched cells, verdict band)

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
