### docstring

```text
每个单色精灵都暗缺一格，框内的孤立像素正是缺失的那一块；平移精灵使缺口套住同色插座，装配后恰好铺满框的内部。

输入结构：
- 网格上有一个一格厚的大空心矩形框，框内部背景上散布若干颜色互不相同的孤立像素（插座）。
- 框外散布同样数量的单色精灵，颜色与插座一一对应；每个精灵的形体上缺了一个
  内部格（相对其完整形状少一格），缺口处显示为背景色。
- 各精灵完整形状互不相同。

规则：
- 每个精灵不旋转、不翻转，仅平移，使其缺失的那一格恰好落在同色插座像素的位置上：
  插座就是补上缺口的那块拼图。
- 擦除精灵的原位置。
- 所有精灵放好后（缺口均被插座补全），其并集恰好无重叠、无缝隙地覆盖框内部的
  全部格子；框本身保持不变。

关键洞察：
- 配准钥匙从未被画出：它是精灵形体里的一格负空间，先要察觉每个精灵"少了一块"，
  再按颜色把负空间对到框内孤立像素上。
- 单看缺口与插座只能定下平移量，装配是否正确还要受"恰好铺满框内部"这一全局
  约束的复核，任何错配都会露出缝隙或重叠。
```

Infer the repeated sprite from fully visible mixed-color blocks. Replace a
block matching that sprite, ignoring grey erasures, with a solid block of

Key insight
The small sprite is a block-level code for one macro-cell state, and the
uniform minority-color block is the other state; the output renders the
opposite code in each macro-cell while cleaning erased pixels.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
