### docstring

```text
按“条高＝同形个数”的图例给灰色形状家族上色，无名家族整族擦除。

输入结构
- 网格底边立着几根互不相邻、高度两两不同的单色实心竖条。
- 其余区域是若干灰色对象；同形（平移等价）的对象构成一族，各族的成员数两两不同。

规则
- 每根竖条声明一条图例：高度为 h 的 c 色条，对应恰有 h 个成员的那一族。
- 把该族所有成员整体涂成 c 色；成员数与任何条高都不符的族，全部擦为背景。
- 竖条本身保持不变。

关键洞察
- 条形图不是要生成的摘要而是输入端的图例，且键既不是位置也不是面积，而是同形对象的出现次数——先归类、再点数、后查表，按左右顺序一一对应只是诱饵。
```

```yaml
    color: non-bg, differs from its diamond's color; two segments of the same diamond may share color
    edge_assignment: each segment sits on exactly one of the 4 diamond edges (TR/TL/BL/BR)
  output_rule: |
    From each endpoint of each outer segment, cast a diagonal ray in the outward direction
    (perpendicular to segment, away from diamond). Paint over bg cells with segment color
    until hitting grid edge. Each segment emits exactly 2 rays.
  ray_length: 0-19 pixels per endpoint; all rays reach grid boundary [observed]

generation_strategy:
  approach: output-first
  steps:
    1. Choose grid dimensions within range. Fill with checkerboard (top-left=1).
    2. Pick 1-3 diamond count and assign distinct non-bg colors (from 2-9).
    3. For each diamond, choose 2-4 edges (TR/TL/BL/BR) to receive outer segments.
    4. Assign a segment color per edge (non-bg, differs from diamond color).
    5. Build output-first -- place each diamond, then for each segment edge, compute the
       full ray pair (from both endpoints outward to grid edge) and paint them.
       Verify no ray collides with existing non-bg pixels; reject or retry placement if so.
    6. Derive input by removing all ray pixels (restoring bg checkerboard values at those cells),
       keeping only diamonds and outer segments.
```
</generation_spec>
</reference_puzzle>
