### docstring

```text
以唯一完整的单元为模板，把其余单元里的残缺像素识别为某个旋转或反射朝向的残迹并补全。

输入结构：
- 整行整列的分隔线把黑底网格分成相等的正方形单元。
- 恰有一个单元画着完整的图案（模板），该图案在旋转和反射下没有任何
  自对称。
- 其余每个单元只画着模板某一个旋转或反射版本的一部分像素；生成保证
  每份残迹恰好与唯一一种朝向相容。

规则：
- 找到像素最完整的那个单元，提取模板。
- 对其余每个单元，在模板的八种朝向中找出与该单元已有像素完全相容的
  唯一朝向。
- 按该朝向把完整图案画满该单元，保留分隔线，输出整个网格。

关键洞察：
- 把完整单元原样复制到所有空槽的直觉是错的：各单元早已各自选定了朝
  向，残缺像素不是噪声而是判定朝向的对齐签名。
```

    output_shape: same as a single frame
  sprite:
    # 4 templates observed in eval (all shown head-UP; each rotatable to U/R/D/L):
    #
    # hollow3 (3px, 2x3):
    #   .#.
    #   #.#
    #
    # filled4 (4px, 2x3):
    #   .#.
    #   ###
    #
    # stem4 (4px, 3x3):
    #   .#.
    #   .#.
    #   #.#
    #
    # midfilled6 (6px, 3x3):
    #   ##.
    #   .##
    #   ##.
    #
    template: one of {hollow3, filled4, stem4, midfilled6}
    size: 3-6 pixels (determined by template)
    same template across all frames (orientation may change); arrow tip encodes facing direction
  markers:
    type: isolated single-pixel dots of the actor color, scattered inside the frame
    count_in_first_frame: 4-12 (equals total consumption steps)
    count_in_last_input_frame: gap (see frame cadence below)
    each marker must NOT overlap any sprite cell; markers and sprite share color but are disjoint regions
  simulation_rule: |
    At each step, exactly one cardinal direction from the head has reachable markers
    (markers sharing the same row or column as the head, on one side — a "half-line").
    The sprite advances to the nearest marker on that half-line.
    On arrival the head lands on the marker (consumed) and re-faces that step's direction;
    the whole sprite body is re-stamped using that direction's template offsets and must fit in-grid.
    CONSTRAINT 1: at each step, markers must exist on at most one direction's half-line.
    Multiple markers on the SAME half-line are allowed (nearest wins).
    CONSTRAINT 2: every marker must be reachable and consumed; the simulation must
    end with zero markers remaining (no stranded markers).
    CONSTRAINT 3: no 180° reversals — the sprite never moves in the exact opposite
    of its current facing direction (only forward or 90° turns).
  frame_cadence:
    frames are snapshots from step 0, step g, step 2g, ... step (F-1)*g where total_steps = F*g = initial_markers
    so gap g = initial_markers / n_frames is an integer; last frame has g markers remaining
    output = state after step F*g (markers=0), showing only the final sprite body
  path_complexity:
    total_steps: 4-12 (= initial_markers)
    turns: >=2; turn_ratio (turns/steps) in 0.4-0.9
    direction_diversity: path uses >= 3 of the 4 cardinal directions {U, D, L, R}
    axis_reversal: on at least one axis, the path moves in BOTH directions
      (i.e. the path is not monotone — not merely R+D, L+D, etc.)
    step_distance: 2-7 (manhattan distance between consecutive markers on path), varied across the path
  layout_constraints:
    every step's landing head + full template body must fit inside the frame (no clipping)
    markers never coincide with any stamped sprite cell at the step they belong to
generation_strategy:
  approach: path-first (simulate forward, then derive snapshots)
  steps:
    - Pick frame_height, frame_width, n_frames (1-4), bg color, actor color, and divider color (distinct; only if n_frames>=2)
    - Pick a template name and an initial direction d0; place initial head so the sprite body fits inside the frame
    - Pick total_steps N (4-12) that is a multiple of n_frames; gap g = N / n_frames
    - Roll out the path greedily: at each step, choose a NEW marker cell that (a) lies on exactly one half-line from the head (same row or col, one side), (b) fits the rotated template fully in-grid, (c) is not already placed, (d) is NOT in the reverse (180°) direction from current facing. CRITICAL: no other remaining marker may lie on a DIFFERENT direction's half-line from the head at that step; if placing a marker would create ambiguity, pick a different position. Vary between forward and 90° turns so turns >= 2 and turn_ratio in 0.4-0.9
    - Record the N chosen markers and the sprite state at steps 0, g, 2g, ..., (F-1)*g
    - Build each input frame: render the sprite at that snapshot's head/direction plus all remaining (un-consumed) markers; output = final sprite only on clean bg
    - Assemble input: concatenate frames horizontally with full-height divider columns (divider color) between them; omit dividers when n_frames=1
    - Verify: run the solver on the assembled input and check its output equals the final-sprite frame
