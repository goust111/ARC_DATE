```text
要画的物体从未在画布上出现，画面只给出它在顶带与左带上的两道计数影子，须用角落的模板对齐影子反求它的位置并画出。

输入结构：
- 网格分为三部分：顶部一条水平条带、左侧一条竖直条带（各用一行/一列分界线与画布隔开）、其余为主画布。
- 主画布的一个角落画有一个红色多格模板形状。
- 顶带中每列立着一根灰色小条，长度等于“隐形物体”在该列占据的格数；左带同理给出每行的占据格数；隐形物体是红色模板的一个平移副本，但在画布上没有画出任何一格。
- 画布中还散布着一个与模板颜色不同的干扰图形，其行、列占据数与两道影子都不吻合。

规则：
- 读出模板每列、每行的占据格数序列。
- 在顶带影子中找到与模板列计数序列完全一致的唯一水平位置，在左带影子中找到与模板行计数序列完全一致的唯一竖直位置，二者交叉确定隐形物体的平移位置。
- 输出仅保留主画布：条带与分界线全部裁除；在求得的位置画出红色模板副本；角落的模板与干扰图形原样保留。

关键洞察：
- 任务的主角从头到尾没有露面：画布上显眼的干扰图形是幌子，真正的物体只活在两道一维影子里。
- 只有把模板分别向两个轴投影成计数序列，再拿去和影子做序列对齐，才能让它在交叉点现形。
```

Compute a grey result bar by adding teal bar heights and subtracting red bar heights.

Input structure
- The grid has a dominant background and several bottom-aligned one-cell-wide vertical bars.
- Teal bars are positive operands; red bars are negative operands.
- The penultimate column is an empty result slot.

Rule
- Keep every input bar unchanged.
- Compute result height = total teal bar height - total red bar height.
- Paint that many bottom cells of the penultimate column grey.

Key insight
- The bars encode arithmetic by height, with color providing the sign.

Stamp recolored copies of the foreground template in the order given by the marker pixels.

Input structure
- A dominant background contains one multi-pixel foreground template color.

Rule
- Crop the template color to its bounding box and use it as a mask.

Key insight
- The single pixels are an ordered palette; the larger foreground shape is a reusable stencil.

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，或从 `arc_utils.py` 摘取少量必要函数；若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
10. 网格尺寸必须符合 ARC 规范：`generate_input()` 产生的输入网格、以及 `main()` 返回的输出网格，行数和列数都必须 ≤ 30（即任何一维都不超过 30，整体不超过 30×30）。随机化网格大小时把上界封顶在 30；若规则会放大网格（如平铺、加边框、整数倍缩放），必须保证放大后的输出仍 ≤ 30×30，必要时收紧输入尺寸或放大倍数的随机范围，确保 100% 的随机样例都不越过 30×30。
