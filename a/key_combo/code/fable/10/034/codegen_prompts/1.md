## 1. 容器倾泻

- 参考题目题号: 20 (551d5bf1)、3 (9473c6fb)、1 (ef135b50)
- 难度评审: 达标
- tags:
  - operation:平移, translate
  - operation:擦除, erase
  - object:空心矩形, rectangular_frame
  - object:边框缺口, border_gap
  - object:孤立像素, isolated_pixel
  - relation:距离排序, distance_ordering
  - condition:缺口即出口, gap_as_exit
  - condition:撞击堆叠, collision_stacking

### docstring

```text
有缺口的蓝框把内部像素按到缺口的距离次序弹出，弹出者沿出口直线飞行、在障碍前依次堆叠，倒空后缺口封闭。

输入结构：
- 黑色背景上有若干蓝色空心矩形框，边框一格厚，互不接触。
- 每个框的边框或者完整，或者恰缺一个非角像素。
- 有缺口的框内部散布若干孤立彩色像素（非蓝非黑），同框内各像素到缺口的曼哈顿距离互不相同。
- 缺口外沿垂直于该边向外的直线上可能有其他框或网格边缘充当阻挡，且该直线上的空位数不少于框内像素数。

规则：
- 边框完整的框连同其内部一切原样保留，并可作为飞行像素的阻挡物。
- 对每个有缺口的框：按到缺口的曼哈顿距离从小到大，内部像素依次从缺口弹出，沿垂直于缺口所在边的方向向外直线飞行，直到撞上网格边缘或任何非黑像素（其他框的边、先前已停下的像素）才停在其前一格。
- 因此先弹出（原来离缺口最近）的像素停得最远，后弹出的像素依次堆叠在更靠近缺口处。
- 全部弹出后框内清空，缺口像素补成蓝色。

关键洞察：
- 缺口不是要修补的缺陷而是出口：像素按离门远近排队飞出并在远端堆叠，输出中的颜色次序恰是框内距离次序的反转。
- 密闭的框既是原样保留的容器，也是别家倾泻物的挡板。
```

    1. Pick grid size ~27-30 x 30, bg=0. Choose 3-4 non-bg colors; designate one as outer_color.
    2. Build exemplar pattern as banded rectangles. For each axis, create 1-7 runs of identical lines with widths 1-5. Ensure exactly one run per axis has strictly more unique colors in its line than all other runs (or is uniquely widest if tied). All four corners must be outer_color.
    3. Compute fixed_rows/fixed_cols (sum of non-stretch run widths per axis).
    4. Generate 1-2 target rectangles with dimensions > (fixed_rows, fixed_cols). Each target is solid outer_color.
    5. Place exemplar and targets on the grid with >=1 bg gap between all pairs and to grid edges. No overlapping.
    6. Input = grid with solid outer_color targets. Output = grid with targets replaced by stretched exemplar.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
