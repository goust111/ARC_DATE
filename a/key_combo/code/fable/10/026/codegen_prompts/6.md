### docstring

```text
角落的小色块是"印章"，主画布是它的"印文"——两者互为左右镜像的槽位蓝图；按此对应补画、抹除并改色横条，使印文与印章完全一致。

输入结构
- 一条灰色直线把网格分成主画布与一个小矩形色块（印章）。
- 主画布可均分为与印章同行列数的等大槽位阵列。
- 印章的每个格子要么是黑色，要么是某种前景色。
- 主画布的部分槽位含有横贯槽位中间一行的整宽横条，其颜色与分布和
  印章不完全一致：有缺失、有多余、也有颜色错误。

规则
- 印章格 (i,j) 为颜色 c 时，槽位 (i, 列数-1-j)（即左右镜像位置）
  必须含一根颜色为 c、位于槽位中间一行、横贯槽位整宽的横条。
- 印章格为黑色时，其镜像位置的槽位必须全空。
- 据此补画缺失的横条、抹去多余的横条、改掉颜色不符的横条。
- 印章与灰色分隔线保持不变。

关键洞察
- 小色块既不是各色横条的计数摘要，也不是同向的位置图——它像实体
  印章盖出印文那样与画布互为镜像；对应关系需要借画布中已经正确的
  横条当密码本来破译，只看单个示例极易误读成计数或同向映射规则。
```

<description>
Extract the largest rectangular foreground frame and recolor its cropped contents to the marker color.

Input structure
- The background is the dominant color.
- There are exactly two foreground colors: one forms complete rectangular
  one-pixel-thick frames, and the other appears as marker pixels/noise.
- The intended frame is the unique largest rectangular frame by bounding-box area.

Rule
- Find the foreground color that forms rectangular frames.
- Crop the bounding box of the unique largest frame of that color.
- In the crop, replace every non-background pixel with the other foreground color.

Key insight
- The marker color supplies the output color; only the largest frame's bbox
  decides which marker pixels are kept and which outside pixels are discarded.

generation_strategy:
  approach: output-first
  steps:

    3. Inside the largest frame interior, place 2-4 marker_color pixels on random bg cells.
    4. Scatter 7-17 additional marker_color pixels (mostly singletons, a few 2px clusters) on bg cells outside all frame bboxes.
    5. Optionally place 0-2 marker pixels inside smaller frame interiors.
    6. Output = crop largest frame bbox, replace all non-bg with marker_color.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
