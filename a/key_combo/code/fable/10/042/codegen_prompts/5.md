### docstring

```text
把四个象限掩码按像素数从多到少的顺序叠到同一画布上，与分隔线同色的那张不是图层而是镂空模板。

输入结构：
- 网格被一条分隔行与一条分隔列（同一种颜色 S）分成四个等大象限。
- 每个象限在黑色背景上有一张单色掩码，四张掩码颜色互不相同，
  其中恰有一张的颜色等于 S。

规则：
- 输出画布为单个象限大小、黑色背景。
- 三张非 S 色掩码折叠到画布同一坐标系后，按像素数从多到少依次盖章：
  像素多的在底层，像素少的在上层，后盖的覆盖先盖的
  （构造保证像素数互不相等）。
- S 色掩码最后应用，但它不涂色：它覆盖到的格子一律擦成黑色，
  无论下面叠了什么。

关键洞察：
- 层叠顺序不由象限位置决定，而由掩码面积决定；
  与分隔线同色是"这张不是内容而是刻刀"的信号，
  把它当普通图层叠上去就全错了。
```

```yaml
  approach: output-first
  steps:
    1. Fix grid 11x11, dest block at rows 4-6 cols 4-6 (green ring + red center).
    2. Decide fill count k in 2-9. Place k maroon in dest row-major; remaining dest cells keep green/red.
    3. Decide if walls exist (yes/no). If yes, pick wall=6 floor=7 (or swap roles).
    4. If walls, build wall barrier around dest with 1-4 floor gaps as corridor openings. Wall forms connected or near-connected frame at ~distance 2 from center, extending outward as corridor arms.
    5. Place k maroon tokens on floor cells reachable from dest openings via BFS, at varied distances. These are the sources that will be erased in output.
    6. Optionally place 0-10 additional maroon tokens in unreachable floor regions (walled off from dest) as distractors.
    7. Derive input: copy output grid, move maroon from dest back to source positions (restore dest to green/red), place erased maroon back on floor.
    8. Validate: run solver on input and confirm output matches.
```

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
