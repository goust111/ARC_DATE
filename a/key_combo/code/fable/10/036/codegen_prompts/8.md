### docstring

```text
以灰框内的双色完整精灵为底版，框外每个只剩顶部若干行的残缺精灵用残存行解出双色替换映射，并原地向下补全成整形。

输入结构：
- 一个灰色空心框内含唯一的完整精灵，由两种角色色构成。
- 框外有若干精灵，各自只保留了模板形状的顶部若干完整行，
  且用与模板不同的颜色绘制。
- 每个残片的残存行至少覆盖模板两种角色色各一格。

规则：
- 将每个残片与模板按顶部行对齐，逐格比对，建立"模板色到残片色"的双色映射。
- 按该映射把模板其余各行逐格翻译，画在残片下方的对应位置。
- 模板与灰框保持不变。

关键洞察：
- 完整精灵只提供角色布局，不提供颜色；每个残片顶部的几行是解码
  双色替换的密码本，补全是按角色翻译而不是复制颜色。
```

```yaml
    block_dims: 2-4 rows x 2-4 cols each; area 6-16 per block
    total_cells: 12-25 (sum of both blocks)
    placement: blocks in different quadrant-regions; never touch grid border [observed]
    solvability: every orbit containing a marker cell has >=1 non-marker cell
  input: output pattern with marker blocks replacing the underlying colors
  transform: for each marker cell, copy color from the non-marker cell in its 4-way orbit

generation_strategy:
  approach: output-first
  steps:
    1. Pick 7-8 colors from {1,2,3,5,6,7,8,9} (exclude 0 and 4).
    2. Fill the top-left 8x8 quadrant randomly using chosen colors.
    3. Reflect quadrant LR, UD, and diagonally to produce the full 16x16 symmetric output.
    4. Choose 2 random non-overlapping rectangles (2-4 rows x 2-4 cols each, total 12-25 cells).
       Place them avoiding row/col 0 and 15, in different quadrant-regions.
    5. Verify solvability -- no orbit has all 4 cells inside the marker rectangles.
       Reject and re-place if violated (low rejection rate since blocks are small).
    6. Replace marker-rectangle cells in the output with color 4 to produce the input.
```

2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
