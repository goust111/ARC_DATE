### docstring

```text
空心矩形框内的多色散点按到门的远近排成一列，从缺口鱼贯而出，在框外形成一条颜色有序的彩条。

输入结构：
- 背景上有若干空心矩形框，每框边界恰缺一个像素（门）。
- 框内散布若干颜色各异的点。
- 同一框内各点到门的框内步行距离（4 邻接、不得穿墙）互不相同。
- 框与框之间留有足够空间，出队彩条不越界、不相撞。

规则：
- 对每个框：计算每个内部点到门的框内最短步行距离。
- 清空框内部。
- 从紧贴门外的一格起，沿垂直于该边向外的方向依次放置各点的颜色：距门最近的点排在队首（紧贴门外），依次向外。
- 框与缺口保持原样。

关键洞察：
- 缺口不是缺陷而是方向指针，点数决定队伍长度。
- 各点的位置并未被完全抛弃——它以"到门的绕墙步行距离序"这一残迹形式决定出队顺序；直线距离与步行距离产生分歧的点正是排序陷阱。
```

```yaml
    1. Pick grid size, 4 distinct colors (bg, sep, src, dist), separator orientation
    2. Place separator at ~35-50% position along the perpendicular axis
    3. Choose source side; place 2-3 solid rects on that side with non-overlapping
       row/col spans, ensuring each mirror fits on the opposite side
    4. Build the output by reflecting each rect and filling corridors with sep color
    5. Derive input by removing the mirrored rects and corridor fills (restore bg)
    6. Scatter distractor pixels (density 3-10%) on both sides, avoiding the
       separator line; some may land inside future corridor regions
```

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
