## 3. 孔洞数即自身缩放倍数

- tags:
  - operation:像素放大, pixel_upscale
  - operation:计数, counting
  - operation:擦除, erase
  - object:闭合轮廓, closed_outline
  - object:封闭孔洞, enclosed_hole
  - relation:拓扑自引用, topology_self_reference
  - condition:孔数定倍数, hole_count_sets_scale
- 参考题目: 8 (447fd412), 18 (e872b94a), 17 (4b6b68e5)

### docstring

```text
每个闭合轮廓对象按自己包围的孔洞个数放大自身，没有孔的对象整体消失。

输入结构：
- 黑背景上散布若干互不相邻的单色 4 连通对象，各自包围 0 个、1 个或多个相互分离的背景孔洞。
- 刻意包含干扰配置：形状相同但孔数不同的对象、孔数相同但形状与颜色都不同的对象、以及实心（0 孔）对象。
- 对象间距与位置保证放大后互不重叠且不越出网格。

规则：
- 对每个对象，数出其内部封闭的背景孔洞数 k（从对象包围盒外沿无法不穿过对象而到达的背景连通块数）。
- k = 0 的对象整体擦除为背景。
- k ≥ 1 的对象以其包围盒左上角为锚点，将自身形状逐像素放大 k 倍重画（k = 1 即原样保留），孔洞在放大结果中仍为背景。

关键洞察：
- 控制缩放的数字没有画在画面上的任何地方——它是对象自身的拓扑性质（孔的个数），对象既是被变换者又是变换参数的载体。
- 实心对象不是标记也不是噪声，而是"0 孔"这一极限情形，因此被抹去而非保留；形状与颜色都是干扰维度，只有孔数起作用。
```

```yaml
    horizontal_separation: column ranges do not overlap (diagonally offset)
    facing_corners: the nearest corners of the two rects lie on an exact 45-degree diagonal
    diagonal_gap: 2-6 pixels between facing corners (exclusive of endpoints)
    direction: mix of upper-left-to-lower-right and upper-right-to-lower-left across pairs
  constraints:
    no_overlap: rectangles and diagonals never overlap each other
    diagonals_on_bg: every diagonal pixel falls on a background cell in the input
    min_bbox_gap: >=2 cells between any two rectangles (any color pair)
  output:
    same_size: grid unchanged except diagonal connectors added
    connector: for each color, paint the open 45-degree diagonal segment between facing corners (endpoints excluded, they are already in the rectangles)

generation_strategy:
  approach: output-first
  steps:
    1. Choose 3-5 foreground colors and assign each a rectangle size (one 3x3, rest 2x2).
    2. For each color, pick a diagonal direction (LR or RL) and a gap length (2-6).
       Compute facing-corner positions, then derive both rectangle bboxes from those corners + sizes.
    3. Place all rectangles and their diagonals on the 16x16 grid.
       Validate no rectangle or diagonal overlaps any other rectangle or diagonal, and all stay in bounds.
       Retry placement on conflict (use random corner offsets within grid).
    4. The output grid is the placed rectangles + diagonals.
    5. Remove the diagonal pixels (set to bg) to produce the input grid.
```
</generation_spec>
</reference_puzzle>
