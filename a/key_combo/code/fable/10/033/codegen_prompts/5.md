### docstring

```text
贴边的发射块把推力沿车道逐块传递，推力在固定转向块处折转90度进入新车道继续传递，每块只前进它与前方最近障碍之间的空隙。

输入结构
- 背景网格上有一个贴住某条外边缘的单色实心矩形发射块，其运动方向为离开该边缘、指向对侧。
- 发射块前方的车道内排着若干颜色互异的自由块；车道中途可有一个固定的墙色转向块，转向块四周恰有一条与来向垂直、排着后续自由块的出路车道。
- 每条车道的尽头是网格边界或另一个墙色块；墙色块永不移动。

规则
- 发射块沿运动方向前进，直到与前方最近的块相贴后停下；被贴上的自由块随即以同方向继续滑动，同样贴上前方最近的块后停下，推力如此逐块传递。
- 推力传到转向块时，转向块不动，推力折转90度沿唯一的出路车道继续：出路车道里最靠近转向块的自由块被推动，规则同前。
- 每条链的最前端块一直滑到贴住网格边界或墙色块为止。
- 输出为所有块停稳后的画面，各块形状与颜色不变。

关键洞察
- 这既不是整体平移也不是各自滑到底：每一块的位移恰好等于它与前方最近障碍之间的原始空隙，整条推力链像牛顿摆一样把间隙逐段吃掉，还会在转向块处拐弯——把两条车道当成独立场景、或以为转向块也会被推走，间隙的重新分配就全部算错。
```

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
