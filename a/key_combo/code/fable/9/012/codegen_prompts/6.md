## 6. 钥匙认孔不认邻居

- 参考题目题号：16, 20, 9
- tags:
  - operation:交换, swap
  - operation:重涂色, recolor
  - object:分隔面板, separated_panel
  - object:图案钥匙, motif_key
  - object:孔洞, hole
  - relation:跨面板形状匹配, cross_panel_shape_matching
  - condition:形状定去向, shape_determines_destination
  - condition:来源底色定颜色, source_base_color_determines_paint

### docstring

```text
每个面板里的图案钥匙按形状找到别的面板中与之全等的孔洞，搬进去并染成钥匙来源面板的底色。

输入结构：
- 分隔色把画面切成若干个同尺寸矩形面板，每个面板有自己的底色。
- 每个面板内含一个背景色（黑）挖出的孔洞和一个由其他颜色拼成的图案（钥匙）。
- 每把钥匙的形状恰与另一个面板的孔洞全等（仅平移、不旋转），配对一一对应；
  任何钥匙都与自己面板内的孔形状不匹配。

规则：
- 为每把钥匙找到孔洞形状与之全等的目标面板。
- 在目标面板中，把该孔洞逐格填上钥匙来源面板的底色。
- 每个面板中原来的钥匙像素清为该面板自己的底色。
- 输出中每个面板呈现为：纯底色，加一块位于原孔处、颜色为某外来面板底色的图形。

关键洞察：
- 钥匙自身的颜色是彻头彻尾的干扰项：真正传递的信息只有两样——
  形状（决定这把钥匙去哪个面板）与来源面板的底色（决定孔被染成什么颜色）；
  配对由形状全等关系跨面板牵线，与面板的相邻位置无关。
```

```yaml
    stretch the frame toward the marker so the marker row/col becomes the new outer border
    expanded frame keeps same border and interior colors; marker is consumed
    expanded frame must be >=3 in both dimensions and fit within grid bounds

generation_strategy:
  approach: output-first
  steps:
    1. Pick grid size H x W in [11,13].
    2. Choose 3 distinct non-zero colors for border, interior, marker (marker=8 preferred).
    3. Pick expanded frame bbox (nr0,nc0,nr1,nc1) with both dims in [5,12], fitting in grid.
    4. Choose expansion direction (up/down/left/right) and shrink amount d in [4,8].
       Shrink the expanded frame on the chosen side by d to get original frame (must remain >=3 in both dims).
    5. Place marker pixel at distance d from the original frame edge, aligned within frame span.
       For up: marker at (nr0, random col in [c0,c1]). For right: marker at (random row in [r0,r1], nc1).
    6. Fill input grid: background, draw original frame (border+interior), place marker.
    7. Fill output grid: background, draw expanded frame (border+interior), no marker.
```

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
