```text
按边框图例"段长即对象大小"的字典，为内部佩错颜色的对象勘误配色。

输入结构
- 画布最外圈边框上嵌有若干互不相邻的单色图例段，颜色互不相同、长度互不相同，边框其余部分为黑色。
- 内部为黑色背景与若干单色 4 连通对象，对象像素数互不相同，且每个对象的像素数恰等于某一条图例段的长度。
- 对象现有的颜色整体上是图例颜色的一个错位排列：有的对象颜色已经正确，有的对象戴着本应属于其他大小对象的颜色；部分示例中错色对象恰好两两互持对方的颜色，构成"对象间交换颜色"的表面规律，但该规律在其他示例中失效。

规则
- 对每个对象数出其像素数，在边框上找到长度与之相等的那条图例段，将对象整体重涂为该段的颜色。
- 完成后擦除边框上的全部图例段，边框恢复为黑色。

关键洞察
- 错色对象之间的互换关系是诱饵；真正的分配字典藏在边框上，键是"段长等于对象像素数"的相等关系，与远近方位、原有颜色都无关。
```

```yaml
    tile_period: 2-4 rows x 3-4 cols when periodic; or non-periodic random
    density: 33-50% of grid cells are pattern color
  marker:
    color: azure(8), count 12-17 pixels (always strictly fewer than pattern pixels)
    bbox: 3-5 rows x 5-8 cols, fully interior to grid (min margin 1 on each side)
    structure: within bbox, every cell is either marker or pattern (no black);
      marker pixels = complement of the pattern within that rectangle
    meaning: marker occupies exactly where black would be if the pattern continued through the bbox
  output_rule:
    same as input except within the marker bbox, pattern(1) pixels become green(3);
    marker(8) pixels and all pixels outside bbox are unchanged
    green(3) never appears in the input

generation_strategy:
  approach: output-first
  steps:
    1. Choose grid 17x17. Pick a pattern style -- either random (~37% density)
       or a small periodic tile (period 2-4 rows x 3-4 cols, density 33-50%).
       Fill the entire grid with the pattern (blue=1 on black=0).
    2. Choose a rectangular bbox (3-5 rows x 5-8 cols) placed fully interior
       to the grid (at least 1 cell margin on all sides). Ensure the bbox
       contains at least one pattern pixel and at least one black pixel.
    3. Within the bbox, replace black(0) pixels with azure(8) marker pixels
       and replace pattern(1) pixels with green(3). This gives the output.
    4. To get the input, copy the output and replace green(3) back to blue(1)
       within the bbox. Verify marker count < pattern count.
```
