## 6. 眼点炮台连锁点火

- tags:
  - operation:连线, line_drawing
  - operation:连锁反应, chain_reaction

  - object:指向眼点, direction_pixel
  - object:点火标记, ignition_marker
  - relation:射线触发下一炮, ray_triggers_next
  - condition:未被击中保持沉默, unhit_stays_silent
- 参考题目题号：2, 15, 18

### docstring

```text
从红色点火标记开始沿直线引燃第一座炮台，此后每座被击中的炮台沿自己眼点指的方向发射主体色射线，未被波及的炮台保持沉默。

输入结构
- 黑底上散布若干“炮台”：一个单色主体块加上紧贴主体某条边中点外侧
  的一个异色眼点，眼点相对主体的方位指示该炮台的发射方向（上下左右）。
- 另有恰好一个孤立的红色点火像素，它与某座炮台的主体在同行或同列
  且中间无遮挡。

规则
- 从红色点火像素向着与它对齐的那座炮台画红色直线段，直到贴上主体。
- 被击中的炮台立即发射：从眼点所在格沿眼点方向画一条主体色射线，
  延伸到碰上另一座炮台（主体或眼点）的前一格为止，碰不到则画到边界。
- 被这条射线击中的炮台按同样方式继续发射；每座炮台至多发射一次。
- 连锁自然终止后输出：所有射线加上原有炮台；从未被击中的炮台
  原样保留但不发射任何射线。

关键洞察
- 画面上并非“每座炮台各自发射”，而是一条由点火点决定起点的因果链；
  哪些炮台开火、火线走向何方，完全由链条的传递次序决定，
  第一眼想到的“全体发射”在多数示例上都会画错。
```

<description>
Expand the colored runs from the left reference panel into the blank right panel.

Input structure:
- A uniform rectangular frame surrounds the grid.
- One full-height divider of the frame color splits a left reference panel
  from a blank right panel.
- Both panels have one background margin column on each side of their active
  columns; the left active columns contain two-column endpoint slots, possibly
  connected by same-color horizontal runs.

Rule:
- Keep the original grid and paint only in the right panel's active columns.
- A source run exactly matching the left endpoint slot is copied to the left
  two columns of the right active span.
- A source run exactly matching the right endpoint slot is copied to the right
  two columns of the right active span.
- A source run connecting the endpoint slots is stretched across the entire
  right active span.

Key insight:
The left panel is a compressed legend for the right panel: endpoint markers
stay two pixels wide, while connectors between endpoints expand to fill the
distance between them.

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。禁止不同的input网格输出相同的output网格。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。注意若描述中存在若干，需实现而不是只有单个，包括object或者对应关系等等。且若涉及到最短路径，则输入网格中必涉及到多条路径，对选择造成干扰。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，并把 `/home/lixinyu/snap/new/solvers/arc_utils.py` 作为公共参考工具箱，优先复用其中已经稳定的 bbox、连通域、裁剪、变换和颜色工具；目标文件必须能被 `SourceFileLoader` 直接加载。
