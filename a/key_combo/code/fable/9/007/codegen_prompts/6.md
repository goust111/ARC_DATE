### docstring

```text
周期花纹中的破缺格不是要修复的噪声，而是一部换色法典的样本；输出是把这部法典施加于整幅"应有花纹"的结果。

输入结构
- 网格由一个未直接给出的小母版无缝周期平铺而成，母版不含黑色。
- 少数格子的颜色与平铺规律在该位置规定的颜色不符。
- 每个异常格的"应有色到实际色"都是同一个颜色置换的一个条目。
- 保证母版可由占绝对多数的守规格唯一推断，且母版的每种颜色都至少作为某个异常格的应有色出现过，使置换可完整读出。

规则
- 由守规格推断出母版与平铺相位，得到每个格子的应有色。
- 汇总全体异常格，读出完整的颜色置换。
- 输出与输入同尺寸：每个格子涂成该格应有色经置换后的颜色。

关键洞察
- 对异常格而言，应有色经置换恰好就是它的输入色，于是输出里"错的格子原封不动、守规矩的格子全部变色"——破缺不是要被修正的对象，而是全网格都要服从的新法律；只想着修复花纹或只想着提取异常，都会南辕北辙。
```

    edge_touching: REQUIRED — every logical polyline endpoint must lie on the grid boundary and extend perpendicular to that edge (e.g., a line reaching the left edge arrives as a horizontal segment pointing inward). No dangling/free endpoints in the grid interior. Lines do not run along grid edges.
    no_junctions: every pixel has degree <=2 within its own color component

  red_markers:
    count: 0 or 2-6 singletons of color 2
    role: each sits at a corner or endpoint of a polyline; removing it creates a gap between two facing line segments
    assignment: nearest line color in axis-aligned line-of-sight, preferring endpoint supported along that axis
  yellow_markers:

    role: adjacent to a line endpoint; erases the arm on the far side of the endpoint and extends the line through the marker to the grid edge
    assignment: same nearest-line-of-sight rule as red
  gaps_in_input: removing red-marker corners + crossing recoloring + yellow-arm erasure splits each output polyline into 2-5 input fragments per color; gap lengths 1-9 cells
  fill_ratio: 23-38% of grid is non-bg in output [observed]

generation_strategy:
  approach: output-first
  steps:
    1. Choose 2-4 line colors (excluding 2 and 4) and grid 12x12.
    2. For each color, build a rectilinear polyline (1-cell-thick, 1-6 turns, 2-20+ px) on the grid; allow different-color lines to cross (at most one crossing per cell). Ensure no same-color junctions (degree<=2). Every polyline endpoint must reach the grid boundary and extend perpendicular to that edge. No dangling interior endpoints. Lines must not run along grid edges.
    3. At each crossing cell, assign the displayed color using the fragmentation rule (more components wins, then lower id).
    4. Decide marker usage -- red only, yellow only, or both. Pick 2-6 corner/endpoint positions on polylines for red markers; pick 0-2 arm endpoints for yellow markers.
    5. For each red marker position, remove the line-color pixel and place color 2; this splits a polyline segment at its corner.
    6. For each yellow marker position, place color 4 adjacent to the endpoint; erase the arm on the far side (set to bg) and verify the new arm would extend to the grid edge.
    7. At crossing cells, show the "wrong" line color (the loser) in the input instead of the winner.
    8. Verify solver recovers the output from the constructed input.
