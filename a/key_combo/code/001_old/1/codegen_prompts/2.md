## 新题 2：列唯一约束下的左滑停靠

**组合逻辑**：[滑动]（已有原语，改造：滑动终点不再由"碰到同伴"决定） → [行列唯一约束](创新：约束不再用于补全空格，而是作为滑动的动态停靠条件) → [擦除原位]（已有原语）

**来源原语**：滑动、擦除（494ef9d7）；行列唯一约束、拉丁方约束（4cd1b7b2）；标记像素（8886d717）

**依赖链**：每个像素向左滑动，但停靠列由"上方已定格像素的颜色分布"决定——先处理的行改变后处理行的合法停靠位置。滑动（操作）与列唯一（条件）不是先后两步，而是每一步滑动都在实时查询约束状态；约束状态又是此前滑动结果累积出来的。

- **摘要**：所有彩色像素向左紧凑排列，但一个像素不能停在"上方行已有同色像素"的列里，遇到这种列就跳过继续找下一列。逐行自上而下结算,输出最终排布。
- **输入**：黑(0)背景方形网格（8x8 至 12x12）。若干行（至少 4 行,不必连续）各含 1~3 个彩色像素（颜色 1~9,同一行内颜色互不相同，不同行之间允许同色重复出现）；其余行全黑。生成约束：按下述规则结算时，每个像素总能在网格宽度内找到合法停靠列。
- **输出**：与输入同尺寸。按行号从小到大处理每个非空行；行内像素按列号从小到大依次结算。每个像素的停靠列是满足以下两个条件的最小列号 c：(a) c 未被本行已结算的像素占用；(b) 在所有已结算完成的行中，列 c 不存在与该像素同色的像素。像素落位到 (本行, c)，原位置置黑。全部像素结算完毕后的网格即为输出；空行保持全黑。
- **key**：单看一例像"向左的重力压缩"，但部分像素会莫名停在更靠右的列——只有对比多例才能归纳出"同色不同列"的隐蔽约束。这不是流水线：不存在"先滑动再检查"的分离阶段，每次滑动的合法性依赖此前所有滑动的结果（状态累积型约束满足），删掉约束退化为平凡重力，删掉滑动则约束无从体现。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
