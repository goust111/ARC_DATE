## 新题 3：标记象限编码旋转与涂色

**组合逻辑**：[旋转](创新：旋转角度不是逐槽位累加，而由标记像素在槽位内的象限位置独立编码) + [重涂色](由标记像素的颜色决定) + [模板·槽位](已有结构)

**来源原语**：旋转(rotate) ← 8e5a5113；重涂色(recolor) ← e9b4f6fc；模板(template)/槽位(slot)/分隔线(divider_line) ← 8e5a5113；标记在面板象限内(marker_in_panel_quadrant) ← 19bb5feb；彩色标记(colored_marker) ← 19bb5feb

**依赖链**：标记像素的象限位置 → 决定旋转角度（位置编码变换参数，源题中无此关系）；标记像素的颜色 → 决定重涂色目标色。同一个标记像素同时编码两个独立参数（旋转 + 颜色），缺少任一参数则输出不确定。

读取每个空槽位中标记像素的象限位置和颜色，将模板旋转至对应角度并涂为对应颜色后填入该槽位。

**输入结构**：约 14×14 黑(0)背景网格。灰(5)分隔线（完整行或完整列）将网格等分为 4~5 个大小相同的矩形槽位。第一个槽位（最左或最上）包含一个由单色非背景像素组成的模板图案（4~8 像素，4-连通，无旋转对称性，颜色为栗(9)）。其余每个槽位内恰好有一个单色彩色标记像素（1 个像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，各槽位颜色可不同），该标记像素位于槽位内部的四个象限之一（以槽位中心为原点划分左上/右上/左下/右下）。生成约束：模板的边界框严格小于槽位尺寸减 2（保证旋转后仍在槽位内）；每个标记像素明确落在某一象限内，不在中心线上。

**规则**：
1. 提取第一个槽位中的模板图案（记录相对于槽位中心的像素偏移）。
2. 对每个后续槽位，找到其中的彩色标记像素，确定其所在象限：
   - 左上象限 → 旋转 0°（不旋转）
   - 右上象限 → 顺时针旋转 90°
   - 右下象限 → 旋转 180°
   - 左下象限 → 顺时针旋转 270°
3. 将模板按确定的角度旋转，将其所有像素的颜色替换为该标记像素的颜色，放置到该槽位中心。
4. 移除标记像素（被旋转后的模板覆盖，或若未被覆盖则设为黑(0)）。
5. 第一个槽位（模板源）保持原样不变。

**关键洞察**：源题中旋转角度沿槽位顺序累加（0°→90°→180°→...）；此题中每个槽位的旋转由其内部标记像素的位置独立编码——同一个标记像素同时承载空间信息（象限→旋转）和颜色信息（→涂色），需对比多个示例才能发现象限-旋转的对应关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
