## 新题 2：边缘线重力堆叠

**组合逻辑**：[滑动](从单像素对扩展到多像素精灵体整体平移) + [擦除](清除原位置) + [边缘线·边缘指示方向](创新：边缘线不再指示射线方向，而编码"重力方向") + [相邻即停止](从像素对扩展到精灵体之间的碰撞停止)

**来源原语**：滑动(slide) ← 494ef9d7；擦除(erase) ← 494ef9d7；边缘线(edge_line) ← 8886d717；边缘指示方向(edge_indicates_direction) ← 8886d717；相邻即停止(adjacent_stop) ← 494ef9d7；精灵体(sprite) ← 8ee62060；内部朝向不变(orientation_preserved) ← 8ee62060

**依赖链**：边缘线位置 → 编码重力方向 → 精灵体沿重力方向整体滑动 → 精灵体之间碰撞检测决定停止位置 → 处理顺序由到边缘的距离决定（近者先落）。边缘线同时决定方向和目标面；碰撞规则将独立的滑动操作耦合为有序堆叠过程。

多个精灵体在边缘线指示的重力方向上整体滑动并堆叠，保持各自形状不变。

**输入结构**：约 15×15 黑(0)背景网格。一条完整的单色实线（橙(7)）占据网格的某一条边（如最下方一整行、最右方一整列等），作为"地面"。网格内散布 3~5 个小型 4-连通单色精灵体（各 3~6 像素，颜色互不相同，从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取）。各精灵体的边界框互不重叠，且在重力方向上互不对齐（即投影到垂直于重力的轴上时，各精灵体的投影区间互不相交），以保证不存在滑动路径冲突。生成约束：每个精灵体与边缘线之间至少有 1 行/列空隙。

**规则**：
1. 识别边缘线所在的边，确定重力方向：边缘线在底边 → 重力向下；在顶边 → 向上；在右边 → 向右；在左边 → 向左。
2. 按各精灵体到边缘线的距离从近到远排序（距离 = 精灵体边界框在重力方向上最靠近边缘线的边到边缘线的像素间隔）。
3. 按此顺序依次处理每个精灵体：将其整体沿重力方向逐像素滑动，保持内部像素布局不变（不翻转、不旋转）。滑动直到精灵体的某个像素与边缘线或已固定的其他精灵体 4-邻接时停止。
4. 将每个精灵体原来位置的像素设为黑(0)。
5. 边缘线本身不变。

**关键洞察**：源题中边缘线指示单像素标记的射线方向；这里边缘线编码整个场景的重力方向，精灵体作为刚体在重力下堆叠——碰撞停止规则将原本独立的滑动操作耦合为全局有序过程。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰，人类必须能从输入输出对中肉眼辨认出规律。具体要求：避免对象粘连、覆盖关系混乱、同一像素多重语义；不同逻辑步骤产生的结果不要大面积层叠在一起导致无法分辨哪个颜色属于哪个步骤；输入中各元素之间保持足够间距，输出中新增的标记/填充/路径等应与背景和已有元素在颜色上有明显区分；若规则涉及多层叠加，生成时控制对象密度和尺寸，确保叠加区域只占少数像素而非铺满整个网格。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。分支概率不必平均——难以发现的隐蔽分支（如少数情况下才触发的特殊规则）应适当提高出现概率，确保在 3 个训练示例中至少出现一次，否则求解者无法归纳该规则。对于颜色映射类规则，确保 2 个左右的示例即可覆盖所有映射关系（每种颜色→颜色的映射至少在某个示例中出现过）。
