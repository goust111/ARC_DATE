# ARC 创新题目设计方法论

> 本文件定义**怎么创新**，不管流程编排（流程见 skill）。
> 输入：一组从参考题中提取的原语池 + 参考题描述。输出：多逻辑组合的创新 ARC 谜题。

---

## 一、角色与原语分类

你是 ARC 谜题设计师。基于当轮参考题提取出的原语池，设计**多逻辑紧耦合**的新题。每道新题至少 2 个原语组合，绝不能是单逻辑题。

参考题的原语分四类，作用不同：
- **操作类（operation）**：真正的逻辑操作（recolor、flood_fill、gravity、tile、scale、rotate、overlay、extrapolate 等）。"多逻辑组合"中的"逻辑"主要来自这一类。不受预定义列表限制，从参考题描述中如实提取。
- **对象类（object）**：描述操作**作用在什么上**（sprite、frame、hole、region、line 等）。不是逻辑本身，是逻辑的操作对象。
- **空间关系类（relation）**：描述对象之间的**空间约束**（adjacent、inside、aligned、symmetric 等）。不是逻辑本身，是逻辑生效的空间条件。
- **条件/判断类（condition）**：描述**什么情况下触发操作、选择哪些对象作为目标**。与空间关系不同——空间关系描述位置，条件描述触发前提。例如：数量条件（"同色邻居恰好 3 个"）、比较条件（"面积最大的对象"）、拓扑条件（"被完全包围的区域"）、模式条件（"与模板匹配"）、颜色条件（"颜色唯一的对象"）。

设计新题时，**操作**是推理链的骨架，但**条件/判断**和**空间关系**不只是操作的参数——它们可以作为推理链中的**决策节点**，改变后续操作的形态或方向。好的多逻辑组合往往是：操作提供"做什么"，条件/关系提供"根据什么决定怎么做"，两者交织成真正的推理图而非线性流水线。

多逻辑耦合最常发生在条件层面——操作 A 的输出改变了操作 B 的触发条件。

### 颜色约束

ARC 谜题只使用 0-9 共 10 种颜色，设计时必须严格遵守：

| 编号 | 颜色 |
|------|------|
| 0 | 黑（通常为背景） |
| 1 | 蓝 |
| 2 | 红 |
| 3 | 绿 |
| 4 | 黄 |
| 5 | 灰 |
| 6 | 品红 |
| 7 | 橙 |
| 8 | 青 |
| 9 | 栗 |

- 不存在"深浅"变体（无深红、亮蓝等），不能用颜色编号做数值大小比较
- 描述颜色时必须使用上表中的名称并标注编号，如"红(2)"
- 涉及颜色映射规则时，必须映射到上表中的具体颜色，不能使用"加深""加亮""互补色"等模糊说法

### 输入形状描述约束

描述输入中的对象形状时，用结构属性（连通性、像素数范围、对称类型、边界框尺寸等）而非具体形状名称（如"T形""L形"）。不同示例中同类对象的具体形状应不同，迫使求解者从结构属性归纳规则而非记忆特定外形。例如写"一个 4-连通的单色小图形（3~6 像素）"而非"一个 T 形图案"。

## 二、设计逻辑组合

从原语池中挑选原语，设计推理链。可以从任意类别的原语出发——以操作类为骨架搭配其他类别，或从其他类别的组合出发再引出操作，方式不限。组合形式不限，任何拓扑都可以（线性、分叉汇合、环形约束、多源汇聚、条件分支等），长度也不限。设计时可以打乱原语顺序、随机抽取组合来打破固定套路，不适合的组合可以舍弃。

如果在组合过程中发现对已有原语做创新改造能产生更好的逻辑效果，可以自由创新。

**创新的核心在于：通过原语的组合产生源题中不存在的新逻辑关系。** 原语在源题中各有其用法，但将不同源题的原语放到一起时，它们之间可以产生全新的结构关系——这种组合涌现出的新逻辑就是创新所在。例如：池中有"矩形"（对象）和"重叠"（关系），可以创新组合为多个空心矩形框相互重叠，根据重叠的遮挡顺序推断颜色优先级，输出一行按优先级排列的颜色序列。

核心要求：
- 删掉任一环节，其余部分无法独立求解
- 不能重复参考题中已有的组合方式
- 生成的题目之间不能相同，每道题的推理骨架必须互不相同
- 新颖性必须落在原语之间的结构关系上，不在某个可命名的部件上
- 如果组合中存在冲突（两个操作修改同一区域、规则矛盾等），需要设计冲突解决规则，且该规则不显而易见
- 组合可能产生涌现效应——A+B 单独都不会产生的效果，组合后出现了。鼓励设计这类题目

**禁止参考题拼装**（最重要的创新底线）：

参考题的 docstring 只用于提取原语和了解已有组合（以便避开）。设计新题时必须在**原语层面**重新组合，不能把两道参考题的完整规则首尾串联。

判断标准——如果新题可以被描述为"先做参考题 A 的完整变换，再做参考题 B 的完整变换"，则属于拼装。拼装的典型特征：
- 新题的前半段保留了参考题 A 的对象结构、空间关系和条件判断不变
- 新题的后半段保留了参考题 B 的对象结构、空间关系和条件判断不变
- 两半之间只有顺序传递（A 的输出直接成为 B 的输入），无新的结构关系

正确做法：每个原语在新题中的**作用方式**（作用于什么对象、由什么条件触发、产生什么中间结果）应至少有一项与其源题不同。好的组合是在原语之间创造**源题中不存在的结构关系**。

自检：写完一道新题后，能否用一句话描述它而不提及任何参考题？如果必须说"像参考题 X 但加了 Y"，说明抽象不够。

**注意逻辑结构多样性**：如果发现已生成的题目超过半数是线性流水线（"先做A→再做B→再做C"），鼓励尝试其他结构，例如：
- 结构解构——输入是多个简单结构的叠加混合，求解者需先分离再推断交互规则
- 同时约束满足——输出需同时满足多条规则，无固定执行顺序
- 隐式编码——输入的几何结构本身编码了变换规则

以上仅为示例，不是穷举。流水线和非流水线都是合法结构，目标是题目间骨架多样。

## 三、验证不可跳步（每道题设计完后）

每道题设计完后检查：

1. **删环节测试**：删除任一逻辑环节，剩余环节是否仍能求解？能→耦合不紧，重新设计
2. **一眼可解测试**：聪明人不经中间推理能否直接写出映射？能→太简单
3. **骨架查重**：推理骨架是否和已生成的新题相同？是→落入套版，重新设计。同时注意避免同一个原语在多道题中反复充当核心机制
4. **颜色编号滥用检查**：规则描述中是否将颜色编号（0-9）用作数值进行大小比较、排序、算术运算或 tie-break？是→违反颜色约束，必须改用空间位置、出现顺序等非编号属性替代
5. **结构多样性检查**（鼓励，非必须）：已生成题目中纯线性流水线结构是否超过半数？是→尝试将部分流水线题调整为非流水线结构，但质量优先，不强制

## 四、质量标准

### 硬性
- 至少 2 个原语组合
- 前一条逻辑的输出实质性改变后一条的输入（有信息变换，不只是传递）
- 至少一个规则需对比多个示例才能归纳
- 逻辑组合不可跳步
- 涉及至少 2 个不同的操作类原语，并搭配对象/空间关系/条件作为约束
- **输入形状多样性**：描述输入中的对象形状时，用结构属性（连通性、像素数范围、对称类型、边界框尺寸等）而非具体形状名称（如"T形""L形"）。不同示例中同类对象的具体形状应不同，迫使求解者从结构属性归纳规则而非记忆特定外形。例如写"一个 4-连通的单色小图形（3~6 像素）"而非"一个 T 形图案"
- **规则描述完备性**：每条规则必须精确到输出唯一确定，不留歧义。具体要求：
  - 涉及多个对象依次处理时，必须写明处理顺序（如"按边界框左上角从左上到右下"或"离该边近的先处理"）
  - 涉及从集合中选取时，必须写明选取策略（如"选与已有颜色都不同的、在输入中出现次数最少的颜色"）
  - 必须说明边界情况的处理（如"超出网格边界的部分舍弃""射线遇到非背景像素时停止，不包含终点"）
  - 多个操作可能修改同一区域时，必须说明冲突解决规则（如"后绘制的覆盖先绘制的"或"面积小的优先"）
  - 必要时给出生成约束以排除歧义（如"生成时保证各对象的移动路径互不冲突"）

- 题目间推理骨架互不相同

### 软性
- 鼓励包含隐蔽规则（仅看单个示例无法确定，必须对比多个示例才能归纳出的非显然映射关系），但不能为了有而有——如果多道题的隐蔽规则套路相同，说明不是真正适合的隐蔽规则，宁可不加
- 对象形态多样——不全是矩形，包含不规则形状(sprite)、封闭区域(closed_region)等
- 尽量覆盖原语池中更多的原语，但质量优先于覆盖率，不要为了凑覆盖率而降低题目质量

### 禁止
- 单逻辑题（人类一眼可解）
- 所有题共享同一推理骨架
- 逻辑之间只是顺序执行无实质依赖
- 骨架退化为"检测属性→直接映射颜色"（中间无信息变换）

## 五、输出格式

每道新题：

```markdown
## 新题 N：[简短标题]

**组合逻辑**：[原语A](创新说明) → [原语B] → [原语C]（标注哪些是已有原语，哪些是创新后的）

**来源原语**：[使用的原语及来自哪些参考题]

**依赖链**：[自然语言描述逻辑之间的耦合关系]

[一句话总结：用一行自然语言概括输入→输出的核心变换]

**输入结构**：[描述输入网格中有哪些元素，精确到另一个模型仅凭此描述就能正确生成代码。必须包含：每种元素的颜色及编号（如"红(2)"）、网格大致尺寸（如"约 15×15"）、元素的具体形态（不能只说"图形"或"线条图"，要说明是什么样的图形——几何结构、像素数范围、连通方式、是否有孔洞等）、对理解题意有影响的布局位置（如某元素固定在左上角、两组元素分别在上半区和下半区、多个对象互不相邻等）、元素间的空间关系、生成约束（保证题目可解的前提条件）]

**规则**：[逐条列出变换规则，每条一行，步骤清晰。每条规则必须无歧义——涉及变换时说明具体算法（如"拉伸"要说明是等比缩放还是线段端点对齐、保持线段数量不变还是插值等）、涉及多对象时的处理顺序、冲突解决方式、边界情况处理。规则必须精确到输出唯一确定，不留任何需要猜测的空间]

**关键洞察**：[一句话点明最非显然的规则或需要对比多个示例才能归纳的地方]
```

文件头：

```markdown
# 第 N 轮 · 创新 ARC 题（多逻辑组合）

> 参考题组：[组文件名，如 001.md]
>
> 参考题（20 道）：[puzzle_id 列表]
>
> 提取的原语：[去重后的原语列表]
>
> 设计原则：每题至少 2 个原语紧耦合；推理骨架互不相同。

---
```

## 六、数量

不限制。能设计多少道符合质量标准的就生成多少道。质量优先于数量。
