## 1. 连锁点火

- tags:
  - operation:射线延伸, ray_cast
  - operation:重涂色, recolor
  - object:实心正方形, solid_square
  - object:对角标记, diag_marker
  - relation:点燃传播网络, ignition_propagation_network
  - condition:仅传播链内点燃, only_reached_ignite

### docstring

```text
从唯一的红色点火方块出发沿对角种子方向发射射线，被击中的灰色方块点燃并接力发射，输出整张点燃传播图。

输入结构：
- 黑色背景上分布若干 2×2 实心方块，每个方块的部分角外侧对角相邻处
  带有单像素种子，标注该方块可发射射线的方向。
- 恰有一个方块连同其种子为红色（点火源），其余方块与种子均为灰色。

规则：
- 红色方块沿其每个种子方向（自方块向外的对角方向）发射射线，
  射线自种子外一格起逐格把背景格涂红。
- 射线遇到任何方块或种子像素即停止；若停止处属于尚未点燃的灰色
  方块单元，该方块连同其种子整体变红，并沿自身种子方向继续发射。
- 射线可以穿过先前射线留下的红色轨迹格（轨迹不阻挡射线），
  已点燃的方块不再重复点燃。
- 过程持续到不再有新方块点燃；未被任何射线击中的方块与其种子
  保持灰色不变。

关键洞察：
- 种子只标注每个方块潜在的发射方向，真正决定输出的是以红色方块
  为源头的点燃传播网络；必须区分"拥有种子"与"被点燃"——
  未接入传播链的方块即使带满种子也保持沉默。
```

## 2. 跨色镜像对

- tags:
  - operation:镜像, mirror
  - operation:重涂色, recolor
  - object:精灵体, sprite
  - object:隐含对称轴, latent_axis
  - relation:形状加位置配对, shape_position_pairing
  - condition:过轴换色, color_swap_across_axis
  - condition:忽略干扰项, ignore_distractors

### docstring

```text
由同形异色物体构成的隐形镜像对各自确定一条竖直镜轴并演示过轴换色规则，为唯一落单的物体补出换色后的镜像伙伴。

输入结构：
- 黑色背景上有若干单色物体；除一个外其余两两成对——每对由两个
  互为镜像（关于某条未画出的竖直轴）的同形状物体组成。
- 同一对的两个成员颜色不同，因此镜像对无法靠颜色识别，
  只能靠形状与位置配对。
- 恰有一个物体没有伙伴：它与恰好一对物体形状相同，颜色等于该对中
  与它同侧成员的颜色。
- 场上存在颜色与落单者相同的其他对（颜色诱饵），也存在离落单者
  更近的别对镜轴（距离诱饵）。

规则：
- 按"形状互为镜像且关于某竖直轴位置对称"找出所有配对，
  求出每对隐含的竖直镜轴。
- 取与落单物体形状一致的那一对及其镜轴。
- 将落单物体关于该轴水平反射，反射像涂成该对中另一侧成员的颜色；
  其余保持不变。

关键洞察：
- 配对关系不由颜色而由形状加位置给出；每一对不仅暗藏一条镜轴，
  还演示了"跨过这条轴颜色如何改变"的换色规则——落单者的补全
  必须同时继承位置反射与侧向换色两条规律，颜色与距离都是诱饵。
```

## 3. 马赛克镂空模板

- tags:
  - operation:压缩, compress
  - operation:裁剪, crop
  - object:瓦片, tile
  - object:彩色方阵, colored_block
  - relation:压缩结果作用于另一物体, compressed_mask_as_stencil
  - condition:尺寸一致选块, size_consistency_selection
  - condition:忽略干扰项, ignore_distractors

### docstring

```text
把大块瓦片马赛克压缩成二值蒙版，再用它对唯一尺寸吻合的彩色方阵做镂空。

输入结构：
- 背景占多数。一处由同色实心 k×k 瓦片构成的马赛克：其外接框可
  均分为 n×n 个单元，每个单元要么被整块填满、要么全空。
- 另有若干实心彩色矩形块（内部逐格上色、颜色多样），其中恰有一个
  的尺寸为 n×n，其余尺寸不同，是干扰项。

规则：
- 将马赛克按单元压缩为 n×n 的二值蒙版（单元被填为满、空为空）。
- 在各彩色块中选出尺寸恰为 n×n 的那一个。
- 输出 n×n 网格：蒙版为满的位置保留该彩色块对应格子的颜色，
  为空的位置置为背景色。

关键洞察：
- 马赛克不是要重涂的图案，而是一张压缩后才显形的镂空模板；
  彩色块的取舍不看颜色与位置，只看它的边长是否等于马赛克的
  单元数——第一级子规则的输出是第二级子规则的操作算子。
```

## 4. 三份残缺证词

- tags:
  - operation:旋转, rotate
  - operation:重涂色, recolor
  - object:观测矩形, observation_rectangle
  - object:方向锚点, orientation_anchor
  - relation:多视角同源, multi_view_same_source
  - condition:对齐后多数表决, majority_vote_after_alignment

### docstring

```text
把三块带蓝色角标的灰色矩形按角标旋回统一朝向后叠加投票，输出获得至少两票的红色图案。

输入结构：
- 黑色背景上散布三个同尺寸灰色矩形，各自被旋转 0°、90°、180°
  或 270° 后放置。
- 每个矩形恰有一个角格为蓝色（方向锚点），内部散布若干红色格。
- 三者是同一幅隐藏图案的三次含噪记录：可能漏画部分真格，
  也可能混入个别多余格。

规则：
- 将每个矩形旋转到使蓝色角标位于左上角的朝向。
- 逐格比对三份记录：在至少两份中为红色的格子判定为真。
- 输出一个该尺寸的灰色矩形，真格涂红，左上角保留蓝色锚点，
  其余为灰色。

关键洞察：
- 三个矩形不是三个独立物体，而是同一幅从未被完整画出的图案的
  三次含噪观测；取交集会丢真格、取并集会收噪声，
  唯有先按锚点对齐、再做多数表决才能还原真相。
```

## 5. 封蜡与灌注

- tags:
  - operation:对接, dock
  - operation:洪泛填充, flood_fill
  - object:围墙回路, wall_loop
  - object:缺口, wall_gap
  - object:彩色碎片, colored_piece
  - relation:形状匹配, shape_matching
  - condition:封堵事件触发灌注, seal_event_triggers_fill

### docstring

```text
把每个碎片嵌入与其形状严丝合缝的围墙缺口，随后只给因封堵而闭合的围墙内部灌注该碎片的颜色。

输入结构：
- 黑色背景上有若干灰色围墙回路，多数各缺一个口：缺口是墙上一段
  缺失格，可能跨过拐角、形状各异。
- 个别围墙天生完整、没有缺口。
- 场上另散布若干彩色碎片（多连格块），每个碎片至多与一个缺口在
  平移意义下形状完全一致。

规则：
- 将每个碎片平移嵌入与其形状完全一致的缺口，嵌入后碎片保持自身
  颜色成为墙的一部分。
- 每当一处围墙因嵌入而变为闭合回路，就把它围出的内部区域整体
  涂成该碎片的颜色。
- 没有匹配碎片的缺口保持开放、内部不涂；天生完整的围墙内部同样
  不涂；无处可嵌的碎片留在原地不动。

关键洞察：
- 灌注不是"闭合就灌"的静态条件，而是"封堵事件"触发的结果——
  输入中本就闭合的围墙恰恰保持空腹；颜色也不是就近取样，
  而是由完成封堵的那枚碎片决定。
```

## 6. 变色弹球

- tags:
  - operation:射线延伸, ray_cast
  - operation:连线, draw_line
  - object:出发角标, start_corner_marker
  - object:障碍块, obstacle_block
  - object:图例条, legend_strip
  - relation:事件驱动换色, event_driven_color_advance
  - condition:仅障碍碰撞推进颜色, only_obstacle_hits_advance

### docstring

```text
弹球从角格出发做四十五度台球反弹，撞到灰色障碍块就按图例条切换到下一种轨迹色，撞到外墙不换色，输出完整彩色轨迹。

输入结构：
- 网格一角有出发标记，场内散布若干灰色实心矩形障碍。
- 以分隔线隔开的一行是彩色图例条，按阅读顺序给出轨迹颜色序列。
- 保证路径最终终止于某个角格。

规则：
- 弹球自出发角沿对角方向前进，轨迹用图例条第一色涂画。
- 撞到网格边界按台球反射规则折返，颜色不变。
- 撞到灰色障碍块面上同样反射，但轨迹自反弹起换为图例条中的
  下一种颜色。
- 到达任一角格停止；输出画出全程轨迹，障碍与图例保持原样。

关键洞察：
- 颜色推进的计数器只挂在障碍碰撞上，外墙反弹是诱饵；
  图例条不是场景装饰，而是按事件顺序被逐一消耗的颜色程序。
```
