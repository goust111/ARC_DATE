## 1. 隐形托板

- 参考题号: 1 (e7639916), 13 (d282b262), 8 (f83cb3f6)
- tags:
  - operation:重力沉降, gravity_settle
  - operation:补全, complete
  - object:标记像素, marker_pixel
  - object:散布像素, scattered_pixel
  - relation:包围盒, bounding_box
  - relation:碰撞阻挡, collision_block
  - condition:三点定矩形框, three_pts_define_rect
  - condition:隐形障碍, invisible_obstacle

### docstring

```text
让散落的沙粒竖直下落，停在由三点标记隐式定义、但从未画出的矩形托板顶面上。

输入结构
- 黑色背景。若干组同色标记像素，每组恰好三枚、组与组颜色互不相同，
  三枚标记都落在其共同包围盒的边界上。
- 另有一种沙色的孤立像素散布在上方区域，沙色不同于任何标记色。
- 部分包围盒所覆盖的列中并没有任何标记像素，部分标记组上方没有沙粒。

规则
- 每组三枚标记定义其包围盒，把整个包围盒视为一块看不见的实心障碍，
  障碍本身不在输出中画出。
- 每粒沙色像素沿所在列竖直下落，停在第一个障碍（隐形包围盒或已落定的
  沙粒）的正上方；该列下方没有任何障碍则落到底行。
- 同列多粒沙粒依次向上堆叠。标记像素保持原样，不参与下落也不被覆盖。

关键洞察
- 三点标记不是等待补全的图形：它们生成的矩形只存在于碰撞层，从不显形。
  沙粒悬停的高度是这块从未画出的托板留下的唯一痕迹，而"把矩形框画出来"
  正是参考套路设下的诱饵。
```

## 2. 凹痕星座

- 参考题号: 3 (de809cff), 5 (8a6d367c), 17 (bf699163)
- tags:
  - operation:缺陷标记, defect_mark
  - operation:重涂色, recolor
  - operation:旋转, rotate
  - object:凹痕, dent
  - object:模板, template
  - object:实心矩形, solid_rectangle
  - relation:形状匹配, shape_match
  - condition:图案索引模板, pattern_indexes_template
  - condition:无匹配则修复, repair_if_unmatched

### docstring

```text
读出每块灰板上凹痕组成的星座，与上方模板旋转比对：匹配则用模板色填坑，
读不出内容的板才按普通破损修复。

输入结构
- 黑色背景上有若干大块灰色实心矩形，每块内部含若干单格黑色凹痕。
- 网格上沿排列几个小模板，每个模板是一种独立颜色的像素星座；
  其中存在像素数相同但形状不同的模板。

规则
- 取每块灰板全部凹痕位置的相对构型，在 0/90/180/270 度旋转下与
  各模板星座逐一比对。
- 若与恰好一个模板匹配，把该板的所有凹痕填成该模板的颜色。
- 若与所有模板都不匹配，视为真实破损，把凹痕填回灰色。
- 模板与灰板轮廓保持不变。

关键洞察
- 凹痕不是待清理的噪声，而是刻在板上的一段可旋转的编码；只有读不出
  内容的破洞才被当作缺陷修补。按像素数配对是走不通的捷径——同数量的
  模板不止一个，必须真正对形状。
```

## 3. 指令带串联

- 参考题号: 8 (f83cb3f6), 7 (c7d4e6ad), 13 (d282b262)
- tags:
  - operation:滑动, sliding
  - object:引导条, guide_bar
  - object:散布像素, scattered_pixel
  - object:行控制色, row_control_color
  - relation:同行对齐, same_row_align
  - relation:碰撞阻挡, collision_block
  - condition:行端口决定去向, row_port_determines_fate
  - condition:指令串联, instruction_composition

### docstring

```text
像素依次穿越多条竖直指令带，每条带在其所在行上的格类型是一条指令，
终点由整串指令复合决定。

输入结构
- 黑色背景。二到三条竖直灰条各自贯穿全高，条上格子分三种：
  灰色实格、红色格、背景色缺口。
- 所有散布的彩色像素位于最左条左侧的区域，每行至多一枚；
  任意一行在全部条上合计至多含一个红色格。

规则
- 每枚像素沿所在行向右滑行，途中每遇到一条竖条，就执行该条在此行的指令：
  灰色实格——停在该条左侧紧邻格；缺口——穿过并继续前进；
  红色格——贴上瞬间反向，改为向左滑行。
- 反向后的像素继续逐条执行指令：缺口照样穿过，灰色实格使其停在该条
  右侧紧邻格；一直无阻挡则停在网格边缘列。
- 各竖条自身保持不变。

关键洞察
- 没有哪一条竖条单独决定终点：实格是墙、缺口是门、红格是弹簧，
  像素的落点是它沿途读到的整串指令的复合结果——被弹回的像素还要
  以相反方向重读先前已经穿过的那些条。
```

## 4. 走廊分水岭

- 参考题号: 16 (b782dc8a), 11 (8d510a79), 3 (de809cff)
- tags:
  - operation:洪泛填充, flood_fill
  - operation:重涂色, recolor
  - object:迷宫走廊, maze_corridor
  - object:种子像素, seed_pixel
  - relation:路径连通, path_connectivity
  - relation:距离排序, distance_ordering
  - condition:近者得色, nearer_seed_claims
  - condition:等距成界, equidistant_frontier

### docstring

```text
两枚种子沿走廊争夺地盘：每个走廊格归最短路更近的种子所有，
两侧等距的格子连成黄色分水岭。

输入结构
- 青色像素构成迷宫墙体，黑色像素为走廊。
- 走廊中有两枚不同颜色的种子像素；黄色不在输入中出现。
- 部分走廊与两枚种子都不连通。

规则
- 对每个可从任一种子沿走廊四连通到达的黑色格，分别计算它到两枚种子的
  最短路径长度（只许走走廊）。
- 距离严格较小的一方获得该格，将其涂成该种子的颜色。
- 到两枚种子距离相等的格子涂成黄色。
- 不可达的黑色格与迷宫墙体保持不变，种子保持原色。

关键洞察
- 画面与"交替涂色"的老题几乎一样，但走廊颜色不来自任何轮流规律，
  而来自一场看不见的最短路竞赛；黄色勾出的分水岭是这场竞赛唯一被
  画出来的等高线。
```

## 5. 杯口接力

- 参考题号: 6 (3dc255db), 13 (d282b262)
- tags:
  - operation:弹射, ejection
  - operation:擦除, erase
  - object:杯形框架, cup_frame
  - object:内容像素, content_pixel
  - object:尾刺, tail_spike
  - relation:尾部朝向决定射出, tail_determines_emission
  - relation:捕获接力, capture_relay
  - condition:像素数守恒, pixel_count_conservation

### docstring

```text
装料的杯子沿尾刺方向射出内容，射流被沿途杯口吞入就换杯接力，
直到最后一次畅通弹射落成直线。

输入结构
- 黑色背景上有若干空心杯形框架，边框颜色互不相同，每只杯有一根汇聚的
  尾刺和与之相对的开口杯口。
- 恰有一只杯的杯口腔内装有 N 枚同色内容像素，其余杯为空；
  其中有的空杯自身弹射路径畅通、却不在任何接力链上。

规则
- 擦除当前杯内的内容像素，从其尾刺尖端起沿尾刺方向逐格前进。
- 若前进路径从某只空杯的开口进入其杯口腔，则 N 枚像素被该杯吞入，
  改由该杯沿它自己的尾刺方向继续弹射，重复本过程。
- 若路径直到出界都未进入任何杯口，则从尾刺尖端外第一格起沿该方向
  画出 N 枚内容色像素，出界部分舍弃。

关键洞察
- 尾刺方向定义的是一张接力网络而非一次发射；从第一只杯直接画线、
  或挑任意一只"射界畅通"的杯画线都是诱饵，最终直线只画在从装料杯
  出发的接力链末端，长度仍守恒于最初的装料数。
```

## 6. 双标记定位

- 参考题号: 18 (291dc1e1), 19 (e6721834), 12 (a834deea)
- tags:
  - operation:平移对齐, translate_and_align
  - operation:擦除, erase
  - object:坐标轴线, coordinate_axis_line
  - object:精灵体, sprite
  - object:标记像素, marker_pixel
  - relation:标记锚定精灵, marker_anchors_sprite
  - relation:位置对应颜色, position_to_color
  - condition:双标记分轴约束, dual_markers_split_axes
  - condition:隐藏刻度, hidden_ticks

### docstring

```text
每个精灵体内嵌两枚异色标记，各自认领网格边缘的一枚同色刻度像素：
一枚只锁定行、一枚只锁定列，两条半约束合成精灵的唯一落点。

输入结构
- 黑色背景，网格无任何画出的轴线；最下行与最左列上散落若干孤立的
  彩色刻度像素，与普通散点没有外观区别。
- 内部有若干单色精灵，每个精灵体内嵌两枚颜色不同的标记像素。
- 每枚标记的颜色恰在最下行或最左列之一上出现恰好一次；同一精灵的
  两枚标记颜色分属两条边。精灵本体色不在边缘出现，另有一对刻度
  不对应任何精灵。

规则
- 对每个精灵：在最左列找到与其中一枚标记同色的刻度，该精灵须平移到
  使这枚标记落在该刻度所在的行；在最下行找到与另一枚标记同色的刻度，
  使那枚标记落在该刻度所在的列。
- 两条约束各锁一维，合成唯一平移量；精灵刚体平移，形状颜色不变。
- 清除精灵原位置，边缘刻度像素保持不变。

关键洞察
- 边缘散点不是待处理的对象，而是一套按颜色寻址的隐形坐标刻度；
  任何一枚标记都不会落在刻度上，也没有哪枚标记单独充当锚点——
  行约束与列约束分别来自不同的标记，只有把两条半约束叠加才能
  解出落点，多出的那对刻度是指向"投影、引力"等歧途的空地址。
```
