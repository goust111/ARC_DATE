## 1. 碰撞传动外推

- 参考题目题号：18（ba1aa698）、17（56dc2b01）
- tags:
  - operation:外推, extrapolate
  - operation:平移, translate
  - object:帧序列, frame_sequence
  - object:内部精灵, inner_sprite
  - object:条形障碍, bar_obstacle
  - relation:等间距排列, equal_spacing
  - relation:接触停止, contact_stop
  - condition:剩余位移传递, residual_motion_transfer

### docstring

```text
在等宽画格序列的下一帧中延续精灵的匀速运动，碰撞时把没走完的位移传递给障碍条。

输入结构：
- 网格是一排共享竖直边框的等宽画格，各画格底色一致。
- 每个画格在相同的局部位置画有一段灰色障碍条。
- 每个画格内有同一个精灵，其位置逐格按固定位移向前推进。
- 训练示例中既有下一帧不发生碰撞的场景，也有发生碰撞的场景。

规则：
- 从相邻画格间精灵的位置差推断每帧位移向量。
- 生成一个独立的下一帧画格，含相同边框与底色；由于输出画格不再共享边框，
  外推时按整格宽度而非共享边框间距换算位移。
- 让精灵沿位移方向逐步前进：若下一步会与障碍条重叠，则精灵停在当前位置。
- 精灵未走完的剩余步数不作废，而是全部传递给障碍条——障碍条沿同一方向
  平移这剩余的步数，至多推到画格内边框处被挡住。

关键洞察：
- 无碰撞示例诱导出纯匀速外推的错误规则；发生碰撞时精灵与障碍构成
  动量传递链，输出中障碍条的新位置由"精灵没走完的步数"决定，
  必须同时追踪两个物体的因果联动。
```

## 2. 隐形嵌套摘要

- 参考题目题号：8（56ff96f3）、12（eb5a1d5d）
- tags:
  - operation:压缩, compress
  - object:锚点像素, anchor_pixel
  - object:方环, square_ring
  - relation:对角配对, diagonal_pairing
  - relation:嵌套层次, nesting_hierarchy
  - condition:隐式矩形, implicit_rectangle
  - condition:剔除非嵌套干扰对, drop_non_nested_pair

### docstring

```text
把仅以角点对给出的嵌套矩形链压缩成同心方环摘要。

输入结构：
- 背景为最常见颜色，其余每种颜色恰好出现两次，构成一对对角角点。
- 每对角点隐含一个从未画出的轴对齐矩形，即两点的包含式包围盒。
- 大部分隐含矩形构成一条严格嵌套链；另有一对角点，其隐含矩形与
  嵌套链交叠但与链中矩形互不包含。

规则：
- 对每种颜色由其两个像素求出隐含矩形。
- 检验矩形之间的包含关系，保留能构成严格嵌套链的矩形，
  剔除与链交叠而不嵌套的干扰对。
- 设嵌套层数为 n，输出 2n×2n 的同心方环图：每层嵌套对应一圈
  一像素厚的方环，最外圈用最外层矩形的颜色，向内依嵌套次序着色，
  最内层为 2×2 实心块。

关键洞察：
- 参与规则的矩形从未被画出，画面上只有它们的生成元角点；
  且并非所有角点对都算数，必须用"是否嵌套"筛掉伪装成同类的干扰对，
  按面积排序会把干扰对错误地排进摘要。
```

## 3. 射线连锁反应

- 参考题目题号：2（23581191）、10（6d58a25d）、7（b782dc8a）
- tags:
  - operation:射线延伸, ray_cast
  - object:种子像素, seed_pixel
  - object:墙体, wall_segment
  - relation:行列交叉, row_col_intersection
  - condition:交点成新源, intersection_spawns_source
  - condition:连锁反应至不动点, chain_reaction_fixpoint

### docstring

```text
让种子像素发射的射线在交叉处点燃新的发射源，连锁至稳定。

输入结构：
- 黑色背景上有若干灰色墙段和两个黄色种子像素。
- 两个种子不同行不同列。
- 墙段会阻断射线。

规则：
- 每个源向四个正方向发射绿色射线，遇灰墙或画布边界停止，
  射线可以穿过已着色的格。
- 若来自不同源的一条水平射线与一条竖直射线交于某个黑色格，
  该格涂红并成为新的发射源。
- 新源同样发射射线、产生新交点，逐代重复，直到不再出现新的交点；
  已有颜色的格不再被覆盖，种子保持黄色。

关键洞察：
- 输出不是一次投影，而是连锁反应的不动点：每个红色交点既是结果又是
  新的原因，墙段的位置决定连锁在何处熄灭。
```

## 4. 漏底局部重力

- 参考题目题号：5（aba27056）、17（56dc2b01）
- tags:
  - operation:滑动, slide
  - object:杯形容器, cup_shape
  - object:封闭区域, enclosed_region
  - object:标记像素, marker_pixel
  - relation:开口朝向, opening_direction
  - condition:逐物体局部重力, per_object_gravity
  - condition:漏孔通道外泄, leak_channel_drain

### docstring

```text
让每个杯子里的散落像素朝各自开口的反方向沉底，漏底杯子对应通道的像素继续外泄坠落。

输入结构：
- 黑色背景上有若干互不相触的单色杯形容器，开口可朝上下左右任意方向。
- 开口是杯壁上宽度不小于二的缺口；部分杯子在开口对侧的杯底
  还有一个一格宽的漏孔。
- 每个杯子的内部空腔中散落若干彩色像素，杯外也可能有零星干扰像素。

规则：
- 对每个杯子，由宽缺口的位置判断朝向，开口的反方向是这只杯子的"下方"。
- 杯内像素沿该方向逐通道下落，堆叠在杯底或先落像素之上，颜色保持不变。
- 若杯底有漏孔，则漏孔所在通道的像素不停留，依次穿过漏孔沿同一方向
  继续下坠，直到碰到画布边缘、其他物体的外壁或先漏出的像素才停下堆叠；
  其余通道正常沉底。
- 杯外的干扰像素不受任何重力影响，原样保留。

关键洞察：
- 不存在全局下落方向，每个容器由自身开口定义局部重力；
  宽缺口与一格漏孔功能完全不同——一个定义方向，一个选择哪条通道的
  内容外泄，只看密底杯的示例会漏掉整条外泄规则。
```

## 5. 象限反射印章

- 参考题目题号：20（007bbfb7）、19（67e8384a）
- tags:
  - operation:像素放大, pixel_upscale
  - operation:印章覆盖, stamp_overlay
  - operation:镜像, mirror
  - object:精灵体, sprite
  - relation:自身为模板, self_as_stencil
  - relation:象限排布, quadrant_layout
  - condition:象限决定副本朝向, quadrant_sets_orientation

### docstring

```text
按分形印章展开精灵，但每个印章副本的朝向由该格相对精灵中心所在象限的镜像规则决定。

输入结构：
- 输入是一个高、宽均为偶数的小精灵，画在黑色背景上。
- 输出尺寸为输入高的平方乘以输入宽的平方。

规则：
- 把输出划分为与输入等尺寸的块，每块对应输入的一个格。
- 输入格为黑色的块保持全黑；非黑格对应的块内印上整幅精灵的一个副本。
- 副本朝向取决于该格相对精灵中心所在的象限：左上为原样，
  右上为左右镜像，左下为上下镜像，右下为两轴镜像。

关键洞察：
- 这不是单纯的自模板印章：印出的整体等价于把"四象限双轴反射平铺"
  规则施加在印章层上，必须逐块比对才能发现各副本朝向的差异。
```

## 6. 路径等距分色

- 参考题目题号：7（b782dc8a）、2（23581191）
- tags:
  - operation:洪泛填充, flood_fill
  - operation:重涂色, recolor
  - object:迷宫走廊, maze_corridor
  - object:种子像素, seed_pixel
  - relation:路径连通, path_connectivity
  - relation:路径距离竞争, path_distance_competition
  - condition:等距标红, equidistant_marked_red

### docstring

```text
按迷宫内的最短路径距离把走廊划分给两个种子，等距处标红。

输入结构：
- 青色像素构成迷宫墙体，黑色像素是走廊。
- 走廊中有一个橙色种子和一个蓝色种子。

规则：
- 对每个黑色走廊格，计算沿走廊四连通到两个种子的最短步数。
- 离橙色种子更近的格涂橙，离蓝色种子更近的格涂蓝。
- 两距离相等的格涂红；从两个种子都无法到达的走廊格保持黑色。

关键洞察：
- 分界线不是两点间的几何中垂线，而是绕墙而行的路径等距脊线；
  空旷区域的示例会诱导出按直线远近划分的错误规则，
  墙体使同一格的直线归属与路径归属可以相反。
```

## 7. 段长认领配色

- 参考题目题号：6（2685904e）、4（f8ff0b80）
- tags:
  - operation:计数, counting
  - operation:频率匹配, frequency_matching
  - operation:重涂色, recolor
  - object:分隔行, separator_row
  - object:编码行, code_row
  - object:前景色掩码, foreground_mask
  - relation:段长尺寸对应, run_length_size_match
  - condition:剩余者互相认领, leftover_mutual_claim

### docstring

```text
用编码行中每种颜色的最长连续段长度为灰色物体配色，两侧各剩的唯一落单者按排除法互相认领。

输入结构：
- 一条实心满宽分隔行把网格分为上下两部分。
- 分隔行下方是一行彩色编码行，同一种颜色可能被拆成多个分离的段，
  各颜色的最长段长互不相同。
- 分隔行上方是若干分离的灰色物体，像素数互不相同，
  物体数与编码行中的颜色数相同。

规则：
- 对编码行中每种颜色求其最长连续段的长度。
- 像素数恰好等于某颜色最长段长的灰色物体，整体涂成该颜色。
- 恰有一个物体的像素数与任何颜色的最长段长都不相等，也恰有一种颜色
  未被任何物体匹配：这一个物体与这一种颜色按"剩余者配对"原则
  互相认领，该物体涂成该剩余颜色。
- 落单物体的像素数与落单颜色的段长在两侧数值排序中的名次错开
  （如物体最大而颜色段长居中），因此按大小名次两两配对的捷径不成立。

关键洞察：
- 编码行是多重诱饵——按左右位置查表、按颜色出现总次数、按大小名次
  排序配对都只在个别示例碰巧成立，唯一贯穿全部示例的键是
  "最长连续段长度"；而落单物体的颜色不来自任何数值相等关系，
  只能靠两侧同时做排除法解释，把它当反例会误以为数值键整体不成立。
```
