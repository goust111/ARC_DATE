## 1. 斜坡级联折转下落

- 参考题目: `3618c87e`, `508bd3b6`, `25ff71a9`
- tags:
  - operation:滑动, sliding
  - operation:路径折转, path_deflection
  - object:下落像素, falling_pixel
  - object:斜坡线段, ramp_segment
  - relation:位移逐段累加, displacement_accumulation
  - condition:重力沉降, gravity_settling

### docstring

```text
让每个下落像素被沿途的灰色斜坡逐段折转，水平落点由所有经过斜坡的位移累加决定。

输入结构：
- 黑色背景，上部散布若干不同颜色的孤立单像素。
- 网格中部有若干段互不相交的灰色45度斜坡线段，输出中原样保留。
- 网格底边即地面，没有基线行。

规则：
- 按初始行从低到高的顺序依次处理每个彩色像素。
- 像素竖直下落；当它落到某个斜坡格的正上方时，改为沿坡面向低端方向斜向滑动
  （每步向低端横移一格、下移一格），越过斜坡低端后恢复竖直下落。
- 一条下落路径可以先后经过多段斜坡，横向位移逐段累加。
- 像素最终停在地面或已落定像素之上，颜色保持不变；斜坡不接收堆叠之外的改动。

关键洞察：
- 斜坡不是挡板而是改向器：竖直下落被折转成斜向滑动，最终列号等于起始列号加上
  沿途每段斜坡贡献的水平投影之和；只看起点正下方会得到错误落点，必须完整追踪
  整条级联路径，并按自低向高的顺序处理堆叠。
```

## 2. 角痕迹重建隐形方块

- 参考题目: `14b8e18c`, `009d5c81`, `e9b4f6fc`
- tags:
  - operation:反演重建, inverse_reconstruction
  - operation:擦除, erase
  - object:角残迹像素, corner_trace_pixel
  - object:色种像素, color_seed_pixel
  - relation:残迹反推母体, trace_implies_object
  - condition:八痕迹一致才重建, consistent_octet_only

### docstring

```text
由每组八个红色角痕迹反推出从未画出的正方形边框，颜色取自组内的色种像素。

输入结构：
- 黑色背景上散布若干红色像素。
- 其中大部分红像素按组分布：每组恰好八个，落在某个隐形正方形四个角点外侧的
  两个正交相邻位置上（每角两个）。
- 每组对应的隐形正方形内部恰有一个非红色的孤立像素（色种）。
- 另有少量与任何一致正方形都无法匹配的散乱红像素作为干扰。

规则：
- 找出所有能被八个红像素唯一确定的隐形正方形。
- 在该正方形的边框位置画出一像素宽的空心框，颜色为组内色种像素的颜色。
- 删除这八个红像素与色种像素；无法配组的干扰红像素保持原样。

关键洞察：
- 红像素不是对象本身，而是某次"角标注"留下的残迹：真正的边框不经过任何红像素，
  角点要从每对红像素的正交相邻关系向斜内侧反推一格；色种只提供颜色不提供位置，
  而判断一堆红点是否成组的依据是它们能否共同指认同一个正方形。
```

## 3. 洋葱缺口驱动的层色循环

- 参考题目: `8fff9e47`, `5b692c0f`, `22806e14`
- tags:
  - operation:层色循环, layer_color_rotation
  - operation:补全, completion
  - object:同心框洋葱, concentric_onion
  - object:缺口, gap
  - relation:缺口边定方向, gap_side_sets_direction
  - relation:缺口层号定步数, gap_depth_sets_steps
  - condition:各洋葱独立, per_onion_independent

### docstring

```text
按缺口所在边决定方向、按缺口所在层的深度决定步数，把洋葱各层颜色整体循环移位并补全缺口。

输入结构：
- 黑色背景上有一到两个"洋葱"：由同心正方形框逐层嵌套构成，层数至少三层，
  各层颜色互不相同，最内层为中心像素或最小框。
- 每个洋葱恰有一层的框上缺失一个像素（缺口），缺口位于该层的上边或下边。

规则：
- 记缺口所在层从最外层向内数的层号为 n（最外层为 1）。
- 缺口在上边：层色向内循环 n 步（每层染成它外侧第 n 层的颜色，越界部分从
  最内侧接续）；缺口在下边：层色向外循环 n 步。
- 输出中所有框完整无缺口；两个洋葱各自独立读取自己的缺口。

关键洞察：
- 缺口不是待修补的破损那么简单，它是双重控制标记：所在边给出循环方向，
  所在深度给出循环步数；层数不少于三且颜色互异，使"循环一步"与"整体反转"
  等貌似成立的读法在对比多个示例后全部破产。
```

## 4. 横梁力矩裁决

- 参考题目: `5207a7b5`, `3b4c2228`, `794b24be`, `332202d5`
- tags:
  - operation:加权求和, weighted_sum
  - operation:比较裁决, comparison_verdict
  - object:灰色横梁, grey_beam
  - object:配重块, weight_block
  - object:支点, pivot
  - relation:距离加权面积, distance_weighted_area
  - condition:平局出灰, tie_outputs_grey

### docstring

```text
比较横梁两侧全部负载对中心支点的力矩，输出较重一侧的颜色。

输入结构：
- 一条灰色横梁占满某一行，长度为奇数；梁正中央下方一格是灰色支点像素。
- 梁的上方和下方都可以附着实心彩色矩形块：上方的块坐在梁面或彼此堆叠，
  下方的块吊挂在梁底或彼此下挂。
- 左半侧所有块同为一种颜色，右半侧同为另一种颜色，任何块不跨越中心列。

规则：
- 每侧力矩 = 该侧所有块像素到中心列的水平距离之和，吊挂块与堆叠块同样计入。
- 输出 1x1 网格：力矩较大一侧的块色；两侧力矩相等时输出灰色。

关键洞察：
- 示例逐一证伪所有捷径读法：块数多的一侧会输，总面积大的一侧会输，
  拥有最远块的一侧也会输；唯一稳定的量是逐像素的"距离x数量"总和。
  堆叠高度与吊挂位置都是视觉诱饵——竖直方向不进入力矩，
  吊在梁下的块也不是负贡献，它同样把自己那一侧压下去。
```

## 5. 虚拟坠落链式染色

- 参考题目: `3618c87e`, `941d9a10`, `332202d5`, `ad38a9d0`
- tags:
  - operation:虚拟下落, virtual_gravity
  - operation:原位重涂色, recolor_in_place
  - object:灰色悬浮对象, grey_floating_object
  - object:彩色基线段, colored_baseline_segment
  - relation:支撑链传导颜色, support_chain_conduction
  - condition:坠落从不显示, fall_never_drawn

### docstring

```text
对每个灰色对象在原位重涂色，颜色由一场从未画出的坠落决定：想象所有对象刚性落下并堆叠，
每个对象染上它整条支撑链最底端触到的那段基线的颜色。

输入结构：
- 底行由若干种颜色的连续段拼成（相邻段颜色不同），是输入中唯一的彩色区域。
- 上方悬浮若干灰色4连通小对象，彼此分离，形状各异。

规则：
- 在想象中按初始位置从低到高的顺序，让每个对象保持形状竖直下落，直到它的
  某个像素停在底行上方一格，或停在先落定的对象之上。
- 直接落在底行上的对象，染其最低最左像素正下方那段基线的颜色；
  落在别的对象上的对象，继承该支撑对象已染上的颜色。
- 输出中所有对象保持输入原位，只替换颜色；底行保持不变。

关键洞察：
- 坠落只发生在推理里，画面上没有任何东西移动，因此逐例看到的只是"原位灰块
  被染成了某些颜色"。诱饵读法"每个对象取其正下方的基线段颜色"能解释所有
  孤立下落的对象，却在会堆叠的对象上失效——那些对象的颜色来自支撑链底端
  对象的落点段，可能与它自己脚下的段色不同；必须还原整场看不见的坠落、
  堆叠次序与颜色沿链上传的因果，才能解释每一个例外。
```

## 6. 指令条程序执行

- 参考题目: `009d5c81`, `cce03e0d`, `5b692c0f`, `25ff71a9`
- tags:
  - operation:旋转, rotation
  - operation:镜像, mirror
  - operation:序列执行, sequential_execution
  - object:指令条, instruction_strip
  - object:主图案, main_motif
  - relation:颜色编码操作, color_encodes_operation
  - condition:顺序不可交换, order_non_commutative

### docstring

```text
把顶部指令条读作一段程序，按颜色对应的几何操作从左到右依次变换主图案。

输入结构：
- 顶行是一条水平指令条：一至三个彩色格子从左到右排列，与主区域之间隔一行黑边。
- 其余部分是正方形主区域，内含一个多色图案。

规则：
- 指令色含义在所有示例间固定：红=顺时针旋转90度，蓝=左右镜像，黄=上下镜像。
- 从左到右依次将每条指令作用于整个主区域。
- 输出只含变换后的主区域，不含指令条与黑边。

关键洞察：
- 指令条不是图案的一部分而是一段程序：单色的含义只能靠跨示例对比破译，
  而真正的关卡是顺序——旋转与镜像不可交换，示例中同一组指令以不同次序出现
  并给出不同结果，逐条按书写顺序执行是唯一能同时满足全部示例的读法。
```

## 7. 变尺度倒转对偶条

- 参考题目: `673ef223`, `b10624e5`, `5b692c0f`
- tags:
  - operation:标记映射, marker_mapping
  - operation:缩放, scaling
  - object:红色边缘竖条, red_edge_bar
  - object:青色标记, teal_marker
  - relation:比例对应, proportional_correspondence
  - relation:反向参数化, reversed_parameterization
  - condition:尺寸比编码倍率, size_ratio_encodes_scale

### docstring

```text
把左条旁的标记按两条竖条的高度比放大、并从相反端起量地映射到右条旁。

输入结构：
- 黑色背景；左边缘贴边一条红色竖条（高 h），右边缘贴边另一条红色竖条
  （高 k*h，k 为 1 至 3 的整数），两条的竖直位置互不相关。
- 左条右侧紧邻列有若干青色标记像素，每个与左条的某一行对齐。

规则：
- 设某标记相对左条顶端的行偏移为 d（从 0 计）。
- 在右条左侧紧邻列涂一段长 k 的青色线段，覆盖右条自底端向上偏移
  k*d 至 k*d+k-1 的行。
- 原有标记与两条红条保持不变。

关键洞察：
- 两条红条是同一把尺的两种刻画：左条从顶端起量，右条从底端起量，且刻度被
  拉伸 k 倍，k 由两条的高度比给出。首个示例里 k=1 且两条恰好等高对齐，
  "同行照抄"的错觉能通过它，却在后续示例中同时败于缩放与倒转——
  对应关系既不是平移也不是简单镜像，而是缩放与反向参数化的复合。
```
