## 1. 孪生密钥晶格

- tags:
  - operation:平移复制, translate_copy
  - operation:图案匹配, pattern_match
  - object:精灵体, sprite
  - object:孪生对, twin_pair
  - relation:隐式位移向量, implicit_translation_vector
  - condition:重复者定周期, twice_pattern_defines_period
  - condition:碰撞终止, collision_stops_chain
- 参考题目题号: f5aa3634, d6542281, 9edfc990

### docstring

```text
找出唯一出现两次的孪生精灵，用它们之间的位移向量把场上每个精灵沿该向量双向链式复制，碰撞即停。

输入结构
- 背景为黑色，前景是若干彼此分离的 4 连通多色精灵。
- 恰有一种精灵图案（按紧致裁剪逐格比色，含内部背景孔）出现两次，且两份朝向相同；
  其余精灵图案互不相同。
- 孪生二者的相对位移在每个用例中固定且非零。

规则
- 找到孪生对，取二者对应像素间的位移向量 v。
- 对场上每一个精灵（包括孪生二者），从其原位出发，分别沿 +v 与 -v 方向逐步生成整体平移副本：
  每前进一步放置一份完整副本；若副本超出网格边界，或与网格中已存在的任何前景像素重叠，
  则该方向的链在此步之前终止，该份副本不画。
- 原有像素全部保留。

关键洞察
- 从未画出任何箭头或标尺：平移向量藏在"哪个图案出现了两次"之中；
  孪生对既是密钥也是普通乘客，整个场景其实是同一平移晶格的部分采样，
  需要在碰撞与出界的约束下把晶格补完。
```

## 2. 管网溢流

- tags:
  - operation:计数, counting
  - operation:填充, fill
  - operation:擦除, erase
  - object:容器矩形, container_rect
  - object:管道, pipe
  - object:源条, source_bar
  - relation:链式连接, chain_link
  - condition:容量溢出传递, capacity_overflow_cascade
  - condition:计数守恒, count_conservation
- 参考题目题号: d93c6891, 7b0280bc, 2685904e

### docstring

```text
灰色源条的像素数化作液体注入相邻容器，装满后经管道溢流到下一容器，逐级传递直到液体用尽。

输入结构
- 背景为黑色。若干实心橙色矩形（容器）由一格宽的橙色直管道首尾相连成一条链，
  管道两端各接触一个容器的边。
- 一根一格宽的灰色条（源条）恰好 4 邻接触链端点处的某个容器的一条边。
- 网格保证：每次注入某容器的液量都是该容器入口边条纹长度的整数倍，且总液量不超过链上容器容量之和。

规则
- 数出灰色源条的像素数 N，并把源条擦除为背景。
- 液体从源条接触的容器开始：以接触边为起点，向对侧逐条把完整的行（或列）条纹涂成蓝色；
  该容器最多容纳其面积那么多液体。
- 若 N 超过当前容器面积，容器涂满后，剩余液量经它连向下一容器的管道继续注入下一容器，
  该段被液体经过的管道整条涂成蓝色；下一容器同样以其管道接触边为起点逐条涂条纹。
- 依链传递，直至液量耗尽；未被液体到达的容器与管道保持橙色不变。

关键洞察
- 灰条不是形状而是守恒的量；容器面积是容量上限，
  真正的规则是"计数 → 容量约束 → 溢流级联"，
  只看第一个容器会误以为是简单的计数转条纹。
```

## 3. 触水落闸

- tags:
  - operation:射线延伸, ray_extension
  - operation:洪泛填充, flood_fill
  - object:墙壁, wall
  - object:门缝, gap
  - object:闸门标记, gate_marker
  - object:种子像素, seed_pixel
  - relation:两遍连通, two_pass_connectivity
  - condition:初始可达者落闸, initially_reachable_drops_gate
  - condition:闸门改变连通, gate_alters_connectivity
- 参考题目题号: 4258a5f9, 9edfc990, e69241bd

### docstring

```text
只有初始水域摸得到的灰色标记才会落下十字闸墙，落下的闸墙又反过来切割水最终能淹到的范围。

输入结构
- 背景为黑色。红色像素构成若干房间的墙，墙上留有一至两格宽的门缝。
- 恰有一个蓝色种子像素位于某个开放区域内。
- 稀疏分布若干灰色标记像素，标记之间互不正交相邻，且不与种子重合。

规则
- 第一遍连通：暂不落闸，从蓝色种子出发沿 4 邻非墙格（黑色格与灰色标记格）洪泛，
  记下哪些灰色标记位于这一初始可达区内。
- 落闸：每个初始可达的灰色标记向上、下、左、右四个方向各延伸一条红色线段，
  直到撞上红墙或网格边缘为止（沿途黑色格涂红），标记自身保持灰色；
  初始不可达的灰色标记不落闸、保持原样。
- 第二遍连通：以原墙加全部新闸线为墙体，重新从蓝色种子出发沿 4 邻黑色格洪泛，
  可达的黑色格涂成蓝色；其余黑色格保持黑色。

关键洞察
- 闸与水互为因果：水的初始范围决定哪些闸落下，落下的闸又重新划分水的最终范围——
  闸线可以封死远处的门缝，甚至把水源所在的大厅劈成两半，使某些"初始摸得到"的
  区域最终反而无水；把所有灰点一视同仁落闸，或只做一遍洪泛，都会得到错误答案。
```

## 4. 奇偶筛镜像

- tags:
  - operation:镜像, mirror
  - operation:抽样过滤, parity_sieve
  - object:分隔线, separator_line
  - object:标记像素, marker_pixel
  - object:实心形状, solid_shape
  - relation:坐标奇偶匹配, coord_parity_match
  - condition:标记定相位, marker_sets_phase
- 参考题目题号: 538b439f, d492a647, 59341089

### docstring

```text
把实心形状镜像到分隔线另一侧，但镜像只在与孤立标记同奇偶的格点上显影，并染成标记的颜色。

输入结构
- 一条贯穿全宽或全高的一格宽黄色分隔线把网格分成两侧。
- 一侧有若干实心红色形状；另一侧除一个孤立的青色标记像素外全为背景。
- 标记不落在任何形状的镜像范围之外的特殊位置约束之内（即标记只提供坐标奇偶）。

规则
- 将每个红色形状沿分隔线做镜面反射，得到另一侧的像素集合。
- 镜像像素中，只有行奇偶与列奇偶都与青色标记相同的格点被涂色，且涂成青色；
  其余镜像像素不画。
- 原侧形状、分隔线与标记保持不变。

关键洞察
- 另一侧出现的不是完整镜像而是"点阵残影"；
  残影落在哪一套格点上，不由形状决定，而由远处那个孤立标记的坐标奇偶定相位——
  标记既是筛网的锚点，也是残影的颜色来源。
```

## 5. 频率定径光环

- tags:
  - operation:膨胀, dilation
  - operation:计数, counting
  - operation:频率匹配, frequency_matching
  - object:编码行, code_row
  - object:分隔行, separator_row
  - object:标记像素, marker_pixel
  - relation:频率定参数, frequency_sets_parameter
  - condition:零频擦除, zero_freq_erased
- 参考题目题号: 2685904e, 4258a5f9

### docstring

```text
底部编码行里每种颜色出现的次数，决定上方同色标记像素长出的实心方形光环的半径；没上榜的颜色被抹除。

输入结构
- 一条灰色实心分隔行横贯全宽，其下方恰有一个非背景编码行，其余为黑色背景。
- 分隔行上方散布若干孤立的彩色单像素标记。
- 网格保证：任意两个光环互不重叠；光环可在网格边缘被裁剪。

规则
- 对每种颜色 c，数它在编码行中出现的次数 k。
- 上方每个颜色为 c 的标记像素，以自身为中心涂一个边长 2k+1 的实心 c 色方块（越界部分裁掉）。
- 上方颜色未在编码行中出现的标记像素被擦除为背景。
- 分隔行与编码行保持不变。

关键洞察
- 编码行不是要匹配的目标而是一张"图例"：颜色的出现频率被读作几何参数（光环半径），
  频率为零则读作"删除"；第一个用例中各色都恰出现一次，看起来像固定的 3x3 光晕，
  这个假象要靠后续用例拆穿。
```

## 6. 珠链最短路

- tags:
  - operation:最短路径, shortest_path
  - operation:重涂色, recolor
  - object:节点方块, node_square
  - object:轨道段, track_segment
  - object:珠子像素, bead_pixel
  - relation:图结构, graph_structure

  - condition:多指标辨析, metric_discrimination
- 参考题目题号: 7b0280bc, 2685904e

### docstring

```text
在方块-轨道图中找两个终端之间总珠数最少的路径并染绿，而不是边数最少或长度最短的路径。

输入结构
- 背景为黑色。两个实心红色方块是终端，若干实心蓝色方块是车站（方块边长不一）。
- 一格宽的灰色轨道段连接方块对，构成图的边；每段轨道上嵌有零到多颗黄色珠子像素
  （珠子占据轨道格）。
- 网格保证：按"路径上珠子总数"衡量的最优路径唯一。

规则
- 把方块视为节点、轨道段视为边，边权为该段轨道上黄色珠子的数目。
- 找出两个红色终端之间边权和最小的路径。
- 把该路径上的车站方块与轨道灰色格全部涂成绿色；珠子保持黄色；
  其余节点、轨道与珠子保持不变。

关键洞察
- 图上同时摆着三种候选度量——经过的边数、轨道的几何长度、珠子的数目——
  只有珠数在所有示例中都与被染绿的路径一致；
  必须识破"更短更直的路"这一诱饵，把珠子读作运费。
```

## 7. 缺角弹球

  - operation:重涂色, recolor

  - relation:对角方向, diagonal_dir
  - condition:标记位定方向, marker_pos_sets_direction
  - condition:命中终止, hit_terminates
- 参考题目题号: 4522001f, 9edfc990

### docstring

```text
2x2 方块的缺角标记发射一颗对角弹球，弹球在网格边缘反弹、留下轨迹，最终击中的障碍物被染成标记色。

输入结构
- 背景为黑色。恰有一个 2x2 方块，其中三格为青色填充色、一格为红色标记，标记位于方块某个角。
- 另有若干实心的彩色矩形障碍物，与方块互不接触。
- 网格保证：弹球在有限步内必定命中某个障碍物。

规则
- 发射方向：由与标记对角相对的那个填充格指向标记格，并沿该对角方向继续向外。

- 当下一步将越出网格边界时，把越界的行分量或列分量取反（撞角则两个分量同时取反），继续前进。
- 当下一步将进入某个障碍物时，弹球终止，整个被命中的障碍物重涂为红色。
- 2x2 方块本体与未被命中的障碍物保持不变。

关键洞察
- 画面上没有任何箭头：发射方向由"哪一角缺了填充色"这一几何残迹给出；
  轨迹要经历若干次镜面反弹，最后一击把命运传递给被命中者——
  第一个示例的直线命中会诱导人忽略反弹规则。
```

## 8. 蓝图水位

- tags:
  - operation:计数, counting
  - operation:填充, fill
  - object:分隔线, separator_line
  - object:标记像素, marker_pixel
  - object:封闭区域, enclosed_region
  - object:门缝, door_gap
  - relation:网格分区, grid_partition
  - relation:跨板对应, cross_board_correspondence
  - condition:计数定液位, count_sets_level
  - condition:门位定涨向, door_sets_direction
- 参考题目题号: 6773b310, e69241bd, d93c6891

### docstring

```text
左侧小蓝图格子的标记数给出每个房间的进水量，而水从该房间自己的门那一侧一层层涨起，水色取标记的颜色。

输入结构
- 网格左部是一个由整行整列灰色分隔线划分成 p×q 格的小蓝图，每格内含零到若干个同色标记像素
  （不同格的标记颜色可以不同）。
- 网格右部是红色墙体围成的 p×q 阵列封闭房间（房间尺寸大于蓝图格），两个阵列按行列位置一一对应。
- 每个房间的墙上恰有一个一格宽的门缝，门可以开在上、下、左、右任意一条墙上；
  不同房间的门朝向不同。
- 网格保证：每个蓝图格内的标记数不超过对应房间沿其门方向的内部层数。

规则
- 对蓝图第 (i,j) 格，数其中标记像素的个数 k 并记下标记颜色 c。
- 在右侧第 (i,j) 号房间内部，从贴着该房间门缝的那面墙的内侧算起，
  向对侧把 k 层完整的内部行（门在上/下墙）或内部列（门在左/右墙）涂成颜色 c；
  k 为零的房间保持空置。门缝本身与墙体不涂。
- 墙体、门缝、分隔线与蓝图本身保持不变。

关键洞察
- 数量与方向来自两个不同的世界：远处的蓝图格用标记个数报出"进多少水"、
  用标记颜色报出"进什么水"，而本地的门缝决定"水从哪边灌"——
  把所有房间一律从底部涨水，或把蓝图格内标记的排布误读为方向，都会在某些示例上失败；
  两块板之间没有任何连线，对应关系只能靠"都是 p×q 阵列"这一结构自觉建立。
```

## 9. 孔位反推分解

- tags:
  - operation:分解, decompose
  - operation:重涂色, recolor
  - operation:填充, fill
  - object:基本图元, primitive_shape
  - object:墙壁, wall
  - object:孔洞, hole
  - relation:数量匹配, count_match
  - condition:需求约束分解, demand_constrained_decomposition
  - condition:图元形状决定涂色, shape_determines_color
- 参考题目题号: 150deff5, 6773b310, fafffa47

### docstring

```text
橙色墙上洞口的形状清单，反过来决定灰色整块该如何切割成 2x2 方件与 1x3 条件，并按件染色补洞。

输入结构
- 背景为黑色。一堵实心橙色矩形墙上凿有若干黑色孔洞，每个孔洞恰为 2x2、水平 1x3 或竖直 3x1。
- 墙外有一个 4 连通的灰色整块。
- 网格保证：灰色块存在多种切成"2x2 方件、1x3 横条、3x1 竖条"的合法分解，
  但其中恰有一种分解的三类件数与墙上三类孔洞的个数完全一致。

规则
- 统计墙上三类孔洞的个数，以此为需求，找出灰色块唯一满足需求的图元分解。
- 按该分解就地重涂灰色块：2x2 方件涂青色，1x3 横条涂红色，3x1 竖条涂蓝色。
- 同时把墙上的孔洞按形状补上同一套颜色：2x2 孔补青色，横孔补红色，竖孔补蓝色。
- 墙体其余部分与背景保持不变。

关键洞察
- 灰色块自身的切法是欠定的：只看块本身可以切出不止一种答案；
  真正的约束在远处的墙上——孔洞是需求清单，切割必须逆着因果去配平三类件数，
  这是"洞决定刀口"的反演，而不是"先切再找洞"。
```

## 10. 错位双掩码

- tags:
  - operation:对齐, align
  - operation:压缩, compress
  - object:堆叠掩码, stacked_mask
  - relation:逐格比较, cell_comparison
  - relation:最大重叠定位, max_overlap_pos
  - condition:先配准后比较, register_before_compare
- 参考题目题号: fafffa47, d6542281

### docstring

```text
上下两张掩码在比较前必须先平移配准到重叠最多的位置，再输出配准后的前景交集。

输入结构
- 网格由一条灰色分隔行分成上下两半，两半等大。
- 上半为黑底加一种前景色，下半为黑底加另一种前景色。
- 网格保证：使两半前景重叠格数最大的平移量唯一（平移后越出半区的部分不参与计数）。

规则
- 遍历所有整数平移量，把下半掩码平移后与上半掩码逐格比较，
  取前景与前景重合格数最大的那个平移量。
- 输出一个与半区等大的网格：在最优平移下两半都是前景的格涂红色，其余格为黑色。

关键洞察
- 直接按原位求交集是精心埋下的诱饵（首个用例的最优平移恰为零）；
  两张掩码其实是同一形状的两次错位曝光，必须先找回错位量完成配准，
  交集才会显影出干净的公共形状。
```
