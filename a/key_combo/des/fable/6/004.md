## 1. 步数预算的轮廓行走

- 参考题目题号: 16 (97c75046)、13 (8f215267)、10 (37ce87bb)
- tags:
  - operation:滑动, slide
  - operation:计数, counting
  - operation:擦除, erase
  - object:标记像素, marker_pixel
  - object:障碍轮廓, obstacle_contour
  - object:散点集, dot_set
  - relation:计数决定步长, count_determines_steps
  - condition:贴边行走, contour_adjacent_walk

### docstring

```text
标记先沿视线贴上障碍，再沿障碍外轮廓行走，行走的步数等于场上散点的数量。

输入结构：
- 背景为最多色；一个连通障碍块（颜色甲）。
- 一个单像素标记（颜色乙），与障碍恰有一条水平或竖直视线。
- 若干颜色丙的散点，分布在远离视线与轮廓的位置。

规则：
- 标记沿视线滑至障碍前最后一格背景格。
- 从该格开始沿障碍外轮廓贴边行走；两个转向中只有一个方向的贴边长度
  不小于散点个数，取该方向。
- 行走的格数等于丙色散点的个数，标记落在终点格。
- 所有丙色散点擦除，障碍保持不变。

关键洞察：
- 散点不是噪声而是步数预算；必须先把"数量"读成"距离"，再把"距离"
  沿障碍轮廓（而非直线）度量，才能找到唯一落点。单看首个示例会误以为
  标记滑到贴边路径的尽头，其余示例的步数会否定这一读法。
```

## 2. 反序端口拼接

- 参考题目题号: 11 (e9fc42f2)、2 (5792cb4d)
- tags:
  - operation:平移, translate
  - operation:拼接, stitch
  - operation:裁剪, crop
  - object:边码序列, edge_code_seq
  - object:前景物体, foreground_object
  - relation:反序匹配, reversed_seq_match
  - condition:面对面逐格同色, facing_cells_equal

### docstring

```text
把每个物体边缘携带的颜色序列当作端口，按"一方序列是另一方反序"的条件
将物体面对面拼接成整体。

输入结构：
- 背景为最多色；若干互不相触的矩形块物体，主体为单一体色。
- 每个物体恰有一条边被替换为一段多色序列码，各序列均非回文。
- 每段序列沿其物体边界按顺时针方向读出后，在全场恰有一段与之互为反序。

规则：
- 互为反序的两段码所在的边即为一对端口；以平移方式将两物体面对面贴合，
  使相对的码格颜色逐格相同。
- 依此把所有物体连成一个整体，物体不旋转、不翻转。
- 输出为拼合结果的紧致裁剪，背景色不变。

关键洞察：
- 端口不是单色标记而是一串颜色；两条边能够贴合当且仅当"面对面读起来
  一致"，而在各自的顺时针读向下这正意味着两段序列互为反序。按原样比对
  序列会以为全场没有任何匹配。
```

## 3. 递进错位的修复与外推

- 参考题目题号: 15 (3cd86f4f)、19 (9b30e358)、12 (38007db0)
- tags:
  - operation:平移, shift
  - operation:检错, detect_anomaly
  - operation:补全, complete
  - object:基元行, motif_row
  - object:空白行, blank_row
  - relation:移位量等差递进, offset_progression
  - condition:唯一异常行, single_bad_row
  - condition:循环回绕, cyclic_wraparound

### docstring

```text
每一行都是同一基元行的循环移位、移位量逐行等差递进；修复唯一破坏递进
的行，并把底部空白行按递进继续补齐。

输入结构：
- 网格上部若干行，每行的像素多重集相同：都是同一条基元行的循环移位，
  首行自身也带非零移位。
- 除一行外，第 r 行的移位量构成等差数列（对行宽取模，会发生回绕）。
- 恰有一行的移位量偏离递进，其像素内容本身没有涂错。
- 网格底部另有若干整行背景的空白行。

规则：
- 由多数行恢复基元行与逐行公差；相邻行直接求差可能恰好用到异常行而
  读错公差，须以全局一致为准。
- 将移位不符的行替换为按等差数列应有的循环移位。
- 按同一递进把底部空白行逐行填为继续回绕的循环移位；其余行保留。

关键洞察：
- 错误藏在"相位"而非像素层面：每一行都是合法的基元行副本，异常的是
  移位量的递进关系。任务不止纠错还要外推——只有真正恢复出基元行与
  公差（而非局部抄邻行），才能同时完成修复与续写；循环回绕使斜向纹理
  在视觉上断裂，直接顺着斜线延伸会画错。
```

## 4. 条形算式指向内腔

- 参考题目题号: 10 (37ce87bb)、3 (7acdf6d3)
- tags:
  - operation:计数, counting
  - operation:填充, fill
  - operation:擦除, erase
  - object:柱状条, vertical_bar
  - object:轮廓对象, outline_object
  - object:行内腔, row_interior
  - relation:算术结果匹配腔面积, result_matches_cavity
  - condition:颜色编码正负, color_encodes_sign

### docstring

```text
底部条形算式的计算结果等于某个空心轮廓的内腔面积，把该内腔填成实心，
并清除算式。

输入结构：
- 背景为最多色；底行上立着若干宽一格、底对齐的竖条，青色条与红色条混排。
- 上方散布若干单色空心轮廓物体，颜色互不相同，各轮廓的内腔面积互不
  相同，轮廓自身的像素数也各不相同。

规则：
- 计算 N = 青条高度之和 − 红条高度之和。
- 对每个轮廓求其行内腔：每个被占行中最左与最右轮廓像素之间的背景格。
- 找到内腔面积恰为 N 的唯一轮廓，把其内腔涂成该轮廓自身的颜色。
- 擦除所有竖条；其他轮廓与背景保持不变。

关键洞察：
- 竖条不是待变换的图形而是一道算式；匹配的对象是"看不见的"内腔面积
  而非轮廓本体的像素数——场上存在本体像素数恰等于 N 的轮廓作为诱饵，
  只有腔体口径才能在所有示例中同时成立。
```

## 5. 调色板相位写入路径

- 参考题目题号: 6 (bae5c565)、2 (5792cb4d)、19 (9b30e358)
- tags:
  - operation:重涂色, recolor
  - operation:擦除, erase
  - object:调色板行, palette_row
  - object:单像素宽路径, one_pixel_path
  - relation:序列循环写入, cyclic_sequence_write
  - condition:缺口定相位, gap_sets_phase

### docstring

```text
把顶行调色板的颜色序列从缺口处开始循环地写到下方单色路径上，再擦除
调色板。

输入结构：
- 顶行是一条多色调色板，恰有一个背景色缺口。
- 其余区域只有一条单色、单像素宽、无分支的 4 连通路径，恰有两个端点。

规则：
- 读取序列：从缺口右侧一格起沿顶行向右读，到行尾回绕到行首，跳过缺口，
  得到循环颜色序列。
- 起点端点为行号更小（更靠近顶行）的那个端点，从它出发沿路径逐格行走。
- 依次用循环序列的颜色重涂路径的每一格；序列用尽后从头继续。
- 顶行整行改为背景色，其余背景不变。

关键洞察：
- 路径是一条待写入的空白磁带；调色板的缺口不是残缺而是读取指针，它
  决定序列的起始相位。忽略缺口、从行首直接读起的涂法只在缺口恰好位于
  行首的示例中侥幸成立。
```

## 6. 穿越交换的归边队列

- 参考题目题号: 17 (b5ca7ac4)、1 (1efba499)、16 (97c75046)
- tags:
  - operation:滑动, slide
  - operation:交换, swap
  - object:彩条, colored_bar
  - object:中立条, neutral_bar
  - relation:穿越即交换, pass_through_swap
  - condition:队列次序反转, queue_order_reversed
  - condition:目标色定方向, target_color_direction

### docstring

```text
青条向左缘、红条向右缘行进，沿途每遇一根灰条便与之交换位置而非推动它，
最终贴边队列里灰条的次序恰好反转。

输入结构：
- 背景为最多色；前景为各自行内互不重叠的水平实心条，分青、红、灰三色，
  灰条长度各不相同。
- 同一行内青条位于红条左侧；灰条散布在有色条与其目标边缘之间或青红之间。

规则：
- 青条向左滑动、红条向右滑动，灰条自身不动但可被交换。
- 有色条每遇到一根灰条，两者交换位置：灰条越到有色条的另一侧紧贴，
  先前收集的灰条被相应挤开并保持贴合；有色条继续前进。
- 运动结束于有色条贴住对应边缘。
- 夹在青红之间、未被任何有色条遇到的灰条原地不动。

关键洞察：
- 机制不是推土机式的保序推挤，而是逐根穿越交换，因而贴边队列中灰条的
  次序与它们在输入中到边缘的远近次序相反。某行只有一根灰条时两种机制
  结果相同——首例正是这样的诱饵，只有多灰条的示例才能区分。
```

## 7. 屏障即镜面的穿越

- 参考题目题号: 1 (1efba499)、5 (5ad8a7c0)
- tags:
  - operation:移动, move
  - operation:擦除, erase
  - object:标记像素, marker_pixel
  - object:屏障线段, barrier_segment
  - relation:关于段中点反射, reflect_about_midpoint
  - condition:出口贴段而生, exit_beside_segment

### docstring

```text
标记穿过竖直屏障段落到另一侧，但出口行不是原行，而是原行关于屏障段
中点行的镜像行。

输入结构：
- 背景为最多色；唯一最多的前景色构成若干条长度为奇数的竖直屏障段。
- 其余前景是单像素标记，每个标记的行处于其屏障段的行跨度内，位于段的
  某一侧。

规则：
- 对每个标记：设其所在行为 r，其屏障段的中点行为 m，则镜像行
  r' = 2m − r。
- 擦除原标记，在屏障段另一侧紧贴屏障的那一格、第 r' 行处画上该标记。
- 屏障保持不变。

关键洞察：
- 屏障不只是被穿越的墙，它自身是一面以段中点为轴的镜子；出口位置由
  屏障段的几何决定，而非标记的直线延伸。示例中恰位于中点行的标记看似
  "直穿"，会诱导出与其余标记矛盾的简单读法。
```

## 8. 实心进空心出的点数结算

- 参考题目题号: 13 (8f215267)、10 (37ce87bb)
- tags:
  - operation:计数, counting
  - operation:擦除, erase
  - operation:绘点, draw_dots
  - object:空心框架, hollow_frame
  - object:图案精灵体, pattern_sprite
  - relation:实空编码正负, solidity_encodes_sign
  - condition:同色归账, same_color_account

### docstring

```text
每个框按颜色结算场上的小图案：实心图案记正、空心图案记负，差值以框内
点数呈现。

输入结构：
- 背景为最多色；若干空心矩形框，颜色互不相同。
- 框外散布若干小图案，每个图案颜色与某个框相同；图案分实心块与空心环
  两类。
- 每个框的同色实心图案数严格大于空心图案数。

规则：
- 擦除所有小图案。
- 对颜色为 C 的框，计 n = C 色实心图案数 − C 色空心图案数。
- 在框内中心行自右向左、每隔一格画一个 C 色点，共 n 个。

关键洞察：
- 正负号不写在颜色里而写在形体里：同样颜色的图案，实心是进账、空心是
  出账。把所有同色图案一并计正的读法在个别框上恰好成立，只有发现
  "实/空"这一符号位，各框的点数才能全部对上。
```

## 9. 补位方向决定归边

- 参考题目题号: 14 (fe45cba4)、17 (b5ca7ac4)
- tags:
  - operation:移动, move
  - operation:补全, complete
  - operation:平移, translate
  - object:缺角矩形, notched_rectangle
  - object:碎片, fragment
  - relation:互补拼合, complement_fit
  - relation:方位决定去向, direction_from_notch
  - condition:贴边停止, stop_at_edge

### docstring

```text
把每块散落碎片装回唯一能补全它的缺角矩形，随后整块矩形朝碎片装入的
方向平移到网格边缘。

输入结构：
- 背景为最多色；若干单色缺角矩形（各缺一块与自身同色的缺口）与同样多
  的散落单色碎片。
- 每块碎片的形状恰好与唯一一个缺口互补，碎片颜色与其目标矩形相同。
- 各矩形补全后的滑动路径互不冲突。

规则：
- 将每块碎片平移进唯一互补的缺口，补成实心矩形。
- 缺口位于矩形的哪一侧（上、下、左、右），补全后的矩形就沿该方向平移，
  直到贴住网格边缘；另一坐标保持不变。
- 先全部补全，再统一移动。

关键洞察：
- 补全不是终点而是读方向的动作：缺口所在的一侧就是整块矩形随后的运动
  方向，碎片既是补丁也是路标。碎片原来散落的位置与移动方向无关，是
  首例中容易误读的诱饵。
```
