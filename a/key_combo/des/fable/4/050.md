## 1. 迷宫出口标签

- tags:
  - operation:射线延伸, ray_extend
  - operation:转弯, turn
  - operation:重涂色, recolor
  - object:控制像素, control_pixel
  - object:障碍像素, blocker_pixel
  - object:灰色矩形, gray_rectangle
  - relation:出口列标签, exit_column_label
  - condition:碰撞转向, collision_turn
- 参考题目: `6bcdb01e`, `ddf7fa4f`, `17b80ad2`

### docstring

```text
顶行每个彩色起点像素沿障碍走廊向下折行前进，命中的灰色矩形被染成该起点的颜色，而路径本身不画出。

输入结构
- 背景为主导色；顶行有若干不同颜色的单像素起点。
- 网格中部散布同一障碍色的像素，构成一格宽的折转走廊。
- 底部有若干灰色实心矩形，各自占据不同列区间。

规则
- 每个起点向正下方发出一条虚拟射线。
- 射线前方一格是障碍时，转向唯一无障碍的垂直方向继续。
- 射线最终命中某个灰色矩形，将该矩形整体染成射线颜色。
- 输出中起点与障碍保持原样，射线路径不落色。

关键洞察
- 起点与它真正标记的矩形通常不同列，正下方的矩形是诱饵；唯一的对应关系藏在需要在脑内模拟的折转路径里。
```

## 2. 转角与障碍互证

- tags:
  - operation:补全, completion
  - operation:因果反演, causal_inversion
  - object:折线路径, bent_path
  - object:障碍像素, blocker_pixel
  - relation:转弯障碍互为因果, turn_blocker_duality
  - condition:缺失侧由另一侧重建, missing_side_reconstruction
- 参考题目: `6bcdb01e`, `981add89`

### docstring

```text
已画出的折线路径与"每个转角直行前方必有障碍"的定律互相印证，补回缺失的障碍并填补路径缺口。

输入结构
- 背景上画有一条一格宽的单色折线路径，从一处边界进入、另一处边界离开。
- 路径中段有一个缺口（若干连续格被抹成背景），缺口两端的走向可由相邻路径格确定。
- 网格上散布障碍色像素；按定律，路径每个直角转角的"直行前方"一格应有障碍，但输入中部分这类障碍缺失；另有一些与路径无关的障碍。

规则
- 对已画出的每个转角，若其直行前方一格没有障碍，补上障碍色。
- 在缺口内重建路径：路径直行，除非直行前方一格有障碍，此时转弯；重建段与缺口两端严格衔接。
- 与路径无关的障碍保持不动。

关键洞察
- 转弯与障碍互为因果：看得见的转角重建看不见的障碍，看得见的障碍重建看不见的路径，两个方向用的是同一条定律。
```

## 3. 铺孔剩件

- tags:
  - operation:拼合填充, packing
  - operation:旋转, rotation
  - operation:镜像, mirror
  - operation:擦除, erase
  - object:空心厚框, thick_hollow_frame
  - object:多连块碎片, polyomino_fragment
  - relation:互补拼合, complement_fit
  - condition:唯一剩件, unique_leftover
- 参考题目: `b7cb93ac`, `54db823b`

### docstring

```text
框外碎片中恰有一块进不了孔洞的拼图，把其余碎片按唯一铺法填进孔洞，并抹除那块剩件。

输入结构
- 网格中央有一个厚壁单色框，框内孔洞是一个不规则的背景色区域。
- 框外散布若干单色多连块碎片，颜色各不相同，其中多块面积相同。
- 去掉恰好一块碎片后，其余碎片可经旋转与镜像无重叠恰好铺满孔洞，且铺法唯一。

规则
- 找出唯一的剩件；其余每块碎片按唯一可行铺法放入孔洞，保持各自颜色。
- 已放入孔洞的碎片从原位置消失，剩件也从网格中抹为背景。
- 框保持不变。

关键洞察
- 多块碎片面积相同，面积核算无法定位剩件；只有孔洞与碎片的几何互补关系能决定谁被排除，而铺满孔洞的过程同时给出输出。
```

## 4. 面板配方展开

- tags:
  - operation:象限映射, quadrant_mapping
  - operation:镜像, mirror
  - operation:重涂色, recolor
  - object:实心面板, solid_panel
  - object:彩色标记, colored_marker
  - object:精灵体, sprite
  - relation:粗位置定块细位置定朝向, coarse_fine_position_coding
  - condition:标记色定拷贝色, marker_color_recolor
- 参考题目: `19bb5feb`, `8d5021e8`, `59341089`

### docstring

```text
实心面板内的 2x2 色块既用象限选出输出块，又用块内偏角决定精灵的翻转朝向，颜色则整体重染每份拷贝。

输入结构
- 输入含一个单色精灵和一个实心矩形面板，二者分离。
- 面板内部有若干 2x2 纯色标记，分属面板的不同象限；每个标记明显偏向其象限的某一个角。
- 精灵的质心偏向其 bbox 的某个角（"重角"）。

规则
- 输出为 2x2 块阵，块尺寸等于精灵 bbox；有标记的象限对应的块放一份精灵拷贝，无标记的块全背景。
- 每份拷贝只能取恒等、左右镜像、上下镜像、180°旋转之一，选取使精灵"重角"与该标记在其象限内偏向的角一致的那一个。
- 每份拷贝整体染成对应标记的颜色。

关键洞察
- 标记编码了三层信息：所在象限选位置、块内偏角定朝向、自身颜色定染色；朝向信息藏在标记的"微位置"里，粗看极易漏掉。
```

## 5. 双轴破缺者当选

- tags:
  - operation:裁剪, crop
  - operation:补全, repair
  - object:颜色掩码, color_mask
  - relation:对称, symmetry
  - relation:双轴公共破缺点, double_axis_defect
  - condition:一步修复双轴者当选, single_move_double_repair
  - condition:两层诱饵, layered_decoys
- 参考题目: `d56f2372`, `8d5021e8`

### docstring

```text
在众多对称与近似对称的掩码中，唯一目标是那颗一次移动能同时修复竖轴与横轴对称的破缺像素所在的掩码，输出修复后的裁剪。

输入结构
- 背景上有若干互不同色的掩码。
- 其中一些裁剪到 bbox 后严格轴对称（竖轴或横轴，甚至双轴）。
- 另有多个掩码各自"差一格"即可修复某一条单轴对称（第二层诱饵，数量不止一个）。
- 恰有一个掩码存在唯一一颗像素，把它移到某个空位后，掩码同时获得竖轴与横轴双重对称。

规则
- 对每个掩码检查：是否存在一次"单像素移动"使其成为双轴对称。
- 严格对称者、只能修复成单轴对称者都不选。
- 选出唯一可修成双轴对称的掩码，执行该移动，输出修复后掩码的 bbox 裁剪。

关键洞察
- 两层诱饵依次排除：先排除"选完美对称者"的惯性，再排除"选任一差一格者"的浅判据；唯一判据是那颗像素同时是两条轴的公共破缺点，一步移动补全两个方向的镜像。
```

## 6. 母版残迹

- tags:
  - operation:补全, completion
  - operation:擦除, erase
  - operation:形状匹配, shape_matching
  - object:空心矩形, hollow_rect
  - object:母版精灵, master_sprite
  - object:残缺拷贝, partial_copy
  - relation:框内参考传形, boxed_reference_shape
  - condition:可嵌入者补全否则删除, embeddable_complete_else_erase
- 参考题目: `776ffc46`, `e5062a87`, `d56f2372`

### docstring

```text
灰框中的母版形状决定框外每个残缺图形的命运——能以某个旋转镜像朝向嵌入母版的补全，嵌不进的整体抹除。

输入结构
- 黑底上有一个灰色空心框，框内是一个完整的单色母版精灵。
- 框外散布若干彩色残缺图形：真残迹是母版经某个旋转或镜像后再抹去若干像素的结果，且残余像素足以唯一确定该朝向。
- 伪残迹在任何朝向下都无法嵌入母版。

规则
- 对每个框外图形，在母版的八个刚体朝向中寻找能覆盖其全部像素的对齐方式。
- 找得到且唯一时，用该图形自身的颜色补全成完整母版形。
- 找不到时，把该图形整体抹为背景。
- 灰框与母版保持不变。

关键洞察
- 补全与删除不是两条规则，而是同一个"能否嵌入母版"测试的两个分支；每个残迹的朝向没有明示，要由残余像素反推。
```

## 7. 隔墙咬合

- tags:
  - operation:平移, translate
  - operation:拼合, packing
  - operation:擦除, erase
  - object:分隔列, separator_column
  - object:连通分量, connected_component
  - relation:边缘对齐, flush_with_separator
  - relation:互补拼合, complement_fit
  - condition:咬合开墙, interlock_opens_wall
- 参考题目: `6e453dd6`, `b7cb93ac`

### docstring

```text
两侧形状分别滑向中央灰墙，隔墙相对的一对形状若能无缝拼成实心矩形，墙在该段消失、两形合体。

输入结构
- 一条一格宽的灰色竖墙把网格分成左右两半。
- 左半与右半各有若干彩色形状，初始都不贴墙。
- 每个左侧形状与至多一个右侧形状行区间相对。

规则
- 左侧形状右滑至贴墙，右侧形状左滑至贴墙。
- 对每对隔墙相对的形状做检验：想象抽掉墙、把右形状再左移一格，若两形状无重叠且并集恰为一个实心矩形，则该对咬合。
- 咬合的对子：墙在其行区间内的格子抹为背景，右形状真正左移一格与左形状拼合，各自颜色保留。
- 不咬合的对子与无配对的形状保持贴墙位置，墙对应段保留。

关键洞察
- 滑动只是把候选者送到墙边；真正的判据是贴墙轮廓的互补性——墙是一扇只为严丝合缝的一对打开的门。
```

## 8. 四向色带与稀有裁决

- tags:
  - operation:传播, propagate
  - operation:射线延伸, ray_extend
  - operation:计数, counting
  - object:边缘控制像素, edge_control_pixel
  - object:障碍块, blocker_block
  - relation:交叉冲突, crossing_conflict
  - condition:稀有色胜出, rarer_color_wins
  - condition:碰撞停止, collision_stop
- 参考题目: `981add89`, `17b80ad2`, `54db823b`

### docstring

```text
四条边上的控制像素向内发射色带，撞障碍而止，纵横色带相交处由全图更稀有的颜色占据。

输入结构
- 背景为主导色；四条边上各有若干彩色控制像素。
- 内部散布若干实心障碍块（单一障碍色）。
- 同方向的色带彼此不同行不同列，不会平行重叠。

规则
- 每个控制像素向对边方向画一条一格宽同色带，遇到障碍块前一格停止，未遇则贯穿到对边。
- 一条横带与一条纵带相交时，相交格取两色中在输入全图中像素总数更少的颜色（设计保证无并列）。
- 控制像素与障碍块保持不变。

关键洞察
- 交叉处的胜负与画带顺序、方向、局部远近都无关，是由全图颜色统计决定的；单看一个示例很容易误结成"竖带压横带"之类的假规则。
```

## 9. 钥匙图例

- tags:
  - operation:提取, extract
  - operation:填充, fill
  - operation:擦除, erase
  - object:单色边框, monochrome_frame
  - object:封闭孔洞, enclosed_hole
  - relation:图例对应, legend_mapping
  - condition:完整框才生效, complete_frame_valid
  - condition:图例用后即焚, legend_consumed
- 参考题目: `d9fac9be`, `aa4ec2a5`, `776ffc46`

### docstring

```text
每个完整的 3x3 钥匙框按"框色找对象、中心色填其孔"生效，随后所有钥匙从画面中焚毁。

输入结构
- 背景上有若干大型单色对象，部分对象含封闭孔洞（对象内部被围住的非对象区域）。
- 画面上散布若干 3x3 钥匙：八个边框格同色、中心一格异色；有的钥匙甚至藏在某个大对象的孔洞里。
- 干扰项包括边框缺格的伪钥匙，以及框色对不上任何有孔对象的死钥匙。

规则
- 只有八格边框完整的钥匙有效；有效钥匙的框色指向同色的大对象，把该对象的全部封闭孔洞区域填成钥匙的中心色。
- 死钥匙不产生填充。
- 输出中所有钥匙（有效、伪、死）所占格子一律抹为背景；若钥匙位于某个孔洞内，该孔按其对象的规则照常填色，覆盖钥匙原位置。

关键洞察
- 3x3 框是图例而非场景对象：读完即毁；藏在孔里的钥匙既是待执行的指令，又占着即将被自己染色的位置。
```

## 10. 尾巴推进与撞击翻转

- tags:
  - operation:滑动, translate
  - operation:旋转, rotate
  - operation:连锁反应, chain_reaction
  - object:标记精灵, marker_sprite
  - object:载荷块, payload_block
  - object:网格边缘, grid_edge
  - relation:标记指示方向, marker_indicates_dir
  - condition:先近后远结算, nearest_first_order
  - condition:撞物才翻转, collision_flip
- 参考题目: `99caaf76`, `6e453dd6`

### docstring

```text
各带尾对象按"离目标边近者先行"依次滑向远离尾巴的方向，撞上先停者的对象其载荷旋转180°，撞墙者保持原样。

输入结构
- 背景上有若干"尾巴+载荷"对象：尾巴是同一标记色的小块，载荷是彩色 3x3 图案，尾巴贴在载荷四边之一。
- 各对象移动方向 = 远离尾巴的方向；多个对象可能共用同一行列通道。

规则
- 按对象初始位置到其目标边的距离从近到远逐个结算。
- 结算时对象沿方向滑动，直到 bbox 贴到网格边，或贴到一个已停下的对象。
- 因撞到网格边停下的对象原样放置；因撞到其他对象停下的，其载荷（不含尾巴）旋转 180° 后放置。
- 尾巴始终保持与载荷的相对位置和自身形状。

关键洞察
- 翻转不是对象的固有属性，而是碰撞事件的记录；必须按距离顺序模拟堆叠连锁，才能知道谁撞墙、谁撞人。
```
