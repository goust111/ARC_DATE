## 1. 缺损即指令

- 参考题目题号: 036-1 (2037f2c7), 036-9 (ecaa0ec1), 036-17 (e84fef15)
- tags:
  - operation:差异提取, difference_extraction
  - operation:计数, counting
  - operation:旋转, rotate
  - operation:擦除, erase
  - object:完整图案, complete_motif
  - object:缺损副本, damaged_copy
  - relation:对齐比较, aligned_comparison
  - condition:缺损连通块数定旋转量, damage_component_count_sets_rotation

### docstring

```text
对每一对"完整图案 + 缺损副本"，数出缺失部分的连通块数 k，把完整图案顺时针旋转 k 个四分之一转后画到缺损副本的位置，并抹去原来的两份。

输入结构：
- 黑色背景上散布若干对单色图案，每对共用一种独有颜色，各对互不接触。
- 每对中两个图案的 bbox 为同尺寸正方形；其一为完整图案，另一为缺损副本
  （按 bbox 左上角对齐后，副本的像素集合是完整图案像素集合的真子集）。

规则：
- 将每对图案按 bbox 左上角对齐比较，得到缺失掩码（完整有而副本无的格）。
- 数出缺失掩码的四连通块数 k（k ≥ 1）。
- 在缺损副本的 bbox 处画出完整图案顺时针旋转 k×90° 后的结果；
  完整图案原位置整体清为背景。

关键洞察：
- 缺损不是待修复的噪声，而是一条指令：差异形状本身无关紧要，只有它的
  连通块数有意义，它规定了搬运到该位置的图案要转多少下。若某对的 k 恰为 4，
  旋转是恒等变换，该对看上去像"单纯修复"——这是诱饵，其余对会推翻它。
```

## 2. 错误显影

- 参考题目题号: 036-17 (e84fef15), 036-8 (5a719d11)
- tags:
  - operation:多数投票, majority_vote
  - operation:差异提取, difference_extraction
  - operation:汇集重绘, collect_redraw
  - object:重复图块, repeated_tile
  - object:分隔网格, separator_grid
  - object:异常像素, anomaly_pixel
  - relation:多数投票共识, majority_vote_consensus
  - relation:因果反演, causal_inversion
  - condition:异常位置互不相同, anomaly_positions_distinct
  - condition:异常色取自底图调色板, anomaly_color_from_palette
  - condition:输出用被覆盖的共识色, output_uses_overwritten_color

### docstring

```text
以全体图块的多数投票求出共识底图，找出每个图块被改写的那一个格，在空白画布
的对应坐标上涂"被抹掉的共识色"（而非现在可见的异常色），输出这张由被擦除
内容拼成的图。

输入结构：
- 输入为等尺寸图块的点阵，由单色分隔线的整行整列隔开。
- 所有图块都是同一底图的副本，但每个图块恰有一个格被改写成底图调色板内的
  另一种颜色；因此任何异常格单看都毫不起眼，只有跨图块比较才能暴露。
- 各图块被改写的块内坐标互不相同。

规则：
- 对每个块内坐标取全体图块的多数颜色，得到共识底图。
- 对每个图块，找出与共识不同的那一格，记录其块内坐标，以及共识底图在该
  坐标上的颜色（即被改写覆盖掉的原色）。
- 输出一张与单个图块同尺寸的黑底画布，仅在每个记录的坐标处涂上对应的
  被覆盖原色；图块中实际可见的异常颜色不进入输出。

关键洞察：
- 多数投票不是为了修复，而且要收集的不是"错误写入了什么"，而是"错误抹掉
  了什么"：答案图形的形状分散在各副本的异常坐标里，颜色则藏在共识底图中，
  两者在画面上都从未直接出现。只抄可见异常色的解法在训练对上即被推翻。
```

## 3. 改道容器

- 参考题目题号: 036-13 (d037b0a7), 036-19 (444801d8), 036-2 (8698868d)
- tags:
  - operation:射线延伸, ray_extend
  - operation:填充, fill
  - operation:连锁传导, chain_conduction
  - object:源像素, source_pixel
  - object:空心容器, hollow_container
  - object:开口, opening
  - relation:列对齐, column_alignment
  - condition:开口门控, opening_gates_entry
  - condition:出口改列, exit_shifts_column

### docstring

```text
顶部的每个彩色源像素向下发出射线；射线只能从容器顶边的单格开口进入，进入即
把容器内部整体染成源色，并从容器底边开口（若有）所在的列继续下落，撞上实心
壁则止步。

输入结构：
- 黑色背景。上方若干彩色单像素源，各占不同列。
- 下方散布若干灰色空心矩形容器；每个容器顶边恰有一个单格开口，底边有零个
  或一个单格开口，顶底开口所在列可以不同。
- 布局保证每个顶部开口至多与一条射线的下落路径对准。

规则：
- 每条射线从源像素沿其所在列向下延伸，途经的背景格染为源色。
- 射线落到某容器顶边开口时穿入，容器内部全部染为源色；若该容器底边有开口，
  射线改从底边开口所在列、容器下方一格起继续向下，重复上述过程；
  若底边无开口，射线终止于容器内。
- 射线撞上容器实心壁（非开口）时，止于壁上方一格，不染该容器。
- 未被拦截的射线一直画到网格底边；未被任何射线进入的容器保持灰色空心。

关键洞察：
- 容器既不是纯障碍也不是待填的杯子，而是改道器：能否进入由开口相对行进
  方向的位置决定，能否穿出、从哪一列穿出由底边开口决定。最终画面是一条条
  经过转接、可以横向改列的传导链，而不是一组彼此独立的竖线。
```

## 4. 旅程条纹

- 参考题目题号: 036-6 (5545f144), 036-10 (0a938d79)
- tags:
  - operation:逐步移动, stepwise_move
  - operation:消除, consume
  - operation:连线, draw_line
  - object:三角精灵体, triangle_sprite
  - object:标记像素, marker_pixel
  - object:条纹, stripe
  - relation:朝向排除身后, facing_excludes_backward
  - condition:行进方向定条纹朝向, travel_direction_sets_stripe_axis
  - condition:吞噬顺序定覆盖, consumption_order_sets_overpaint

### docstring

```text
在脑中重演三角精灵吞掉所有标记的整段旅程，然后只输出条纹：每个标记变成穿过
其位置的整行或整列色条，横竖取决于精灵吞掉它时的行进方向，后吞的条纹覆盖
先吞的。

输入结构：
- 黑色背景上有一只单色三角精灵（尖端指示初始朝向）和若干颜色各异的
  单像素标记。
- 布局保证：每一步中，除精灵正后方外，恰有一个正交方向的半直线上存在
  剩余标记。

规则：
- 精灵每步在前、左、右三个方向（不含正后方）中找到唯一存在剩余标记的方向，
  沿该方向直行到最近的标记，吞掉它并转为面向该方向；重复直到标记吃完。
- 输出同尺寸黑底网格：按吞噬顺序逐个作画——若吞掉某标记时行进方向为水平，
  以该标记颜色画穿过其所在行的整行条纹；若为竖直，画穿过其所在列的整列
  条纹；后画的条纹在交叉格覆盖先画的。
- 精灵与其行走路径不出现在输出中。

关键洞察：
- 条纹的横竖不是标记的固有属性，而是那段从未画出的旅程赋予它的：正后方的
  标记此刻不可达，要等精灵转向后从另一个方向被吃到；交叉格的颜色又泄露了
  吞噬的先后。不完整重演旅程，任何一条条纹都定不了向、排不了序。
```

## 5. 转置对

- 参考题目题号: 036-1 (2037f2c7), 036-11 (d749d46f), 036-14 (8618d23e)
- tags:
  - operation:旋转, rotate
  - operation:差异提取, difference_extraction
  - operation:重涂色, recolor
  - object:矩形区域, rect_region
  - object:干扰区域, distractor_region
  - relation:宽高互换配对, transposed_shape_pairing
  - condition:唯一四分之一转对齐, unique_quarter_turn_aligns
  - condition:残差涂青, residual_teal

### docstring

```text
在栗色画布上找出尺寸互为转置（h×w 与 w×h）的两个图案区域，用唯一能使内容
基本吻合的四分之一转把它们对齐，输出对齐后的图案，并把仍不一致的格涂成青色。

输入结构：
- 画布底色为栗色，其上嵌着若干矩形图案区域，互不接触。
- 恰有两个区域的尺寸互为转置，其余区域的尺寸与这两者既不相同也不互为
  转置，是干扰项。
- 配对的两个区域是同一图案经四分之一转后的两个视角，此外有少数格被改动；
  顺时针与逆时针两种四分之一转中，恰有一种能使两区域绝大多数格一致。

规则：
- 按宽高互换关系挑出配对的两个区域，忽略其余区域。
- 在两种四分之一转中选出使不一致格更少的那一种，把按阅读顺序靠后的区域
  旋转对齐到靠前的区域。
- 输出与靠前区域同尺寸的网格：两者一致的格保留共有颜色，不一致的格涂青色。

关键洞察：
- 把两块图案摆在一起并不能直接找茬：尺寸的转置关系暴露了它们是同一图案的
  两个旋转视角，必须先判定旋转方向再比较，残差才会显形；干扰区域的存在使
  "先按转置尺寸配对"成为不可跳过的第一步。
```

## 6. 长臂锚点

- 参考题目题号: 036-3 (1818057f), 036-18 (7e02026e), 036-20 (a395ee82)
- tags:

  - operation:印章放置, stamp
  - operation:重涂色, recolor
  - operation:擦除, erase
  - object:十字图案, cross_pattern
  - object:模板, template
  - object:长臂, long_arm
  - relation:臂长不对称, arm_length_asymmetry
  - condition:长臂定放置方向, long_arm_sets_direction
  - condition:十字色定印章色, cross_color_sets_stamp_color
  - condition:对称十字不动, symmetric_cross_unchanged

### docstring

```text
把带长臂的十字当作放置指令：抹去它，在其长臂方向、距中心一个模板边长处，
盖上用该十字颜色重涂的模板印章；四臂等长的十字原样保留。

输入结构：
- 网格一角由分隔线隔出模板区，内有一个奇数边长正方形 bbox 的单色模板图案。
- 主区域为黑底，散布若干彩色十字：一部分十字三条臂长 1、一条臂长 2
  （带长臂），另一部分四臂全长 1（对称十字）。
- 布局保证所有印章落在主区域内，且互不重叠、不压住其他对象。

规则：
- 对每个带长臂的十字：记下其中心位置、颜色与长臂方向，然后把十字整体抹为
  背景。
- 以"十字中心沿长臂方向平移一个模板边长"的位置为印章中心，画出模板的
  形状掩码，颜色改用该十字自身的颜色。
- 四臂等长的十字保持不变；模板区原样保留。

关键洞察：
- 十字不是要高亮或重涂的图案（那是参考套路留下的诱饵）：带长臂的十字是
  三合一控制符——中心给基准位置、长臂给偏移方向、自身颜色给印章配色，
  而印章形状由画面另一头的模板提供；四臂等长的十字没有方向信息，只是
  不携带指令的哑元。
```
