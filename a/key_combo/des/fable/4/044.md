## 1. 遮挡时序的重力回放

- 参考题目: `c920a713`、`6ad5bdfd`
- tags:
  - operation:重力下落, gravity_drop
  - operation:排序, sort
  - object:矩形边框, rect_frame
  - object:边墙, edge_wall
  - relation:遮挡顺序, occlusion_order
  - relation:碰撞阻挡, collision_blocking
  - condition:遮挡序即结算序, occlusion_encodes_settle_order

### docstring

```text
把空中互相遮挡的矩形框按遮挡揭示的先后次序，依次落向底部红墙堆叠。

输入结构
- 网格底行是一条完整的红色边墙，红色不再出现在别处。
- 空中悬着若干一格粗、颜色互异的空心矩形框，它们两两交叠；交叠处可见的颜色表明该框盖在另一框之上。
- 每种颜色的可见像素仍足以撑出它完整的外接矩形。

规则
- 先由每种颜色的可见像素恢复其完整矩形框。
- 由所有交叠处的可见性建立"先放置→后放置"的唯一全序（被盖住者先放置）。
- 清空空中区域，按放置顺序逐一处理矩形框：保持其原有列位置，让整框竖直下落，直到再下一步会与红墙或已落定的框发生格子重叠为止。
- 输出为全部框落定后的画面，红墙保持不动。

关键洞察
- 交叠处的遮挡不是要修复的破损，而是时间戳：谁盖住谁给出唯一的放置顺序，而这个顺序正是重力结算顺序——先落的框垫在下面，直接决定最终堆叠的形态。
```

## 2. 并账装箱的计数框

- 参考题目: `8f215267`、`239be575`、`d4c90558`
- tags:
  - operation:计数, counting
  - operation:擦除, erase
  - operation:绘点, draw_dots
  - object:空心框架, hollow_frame
  - object:桥接路径, bridge_path
  - relation:连通性, connectivity
  - relation:容量装箱, capacity_packing
  - condition:连通组共享总账, group_shares_total

### docstring

```text
青色通路把计数框并成一组总账，总账的点按框容量从小到大逐框装箱显示。

输入结构
- 背景为最多色。若干颜色互异、宽度不一的空心矩形框散布网格，每框内部有若干灰色标记像素。
- 框外有青色像素构成的一格粗通路，可能把某些框的边框 4-连通地连接起来；青色与灰色都不是框色。

规则
- 把框边与青色通路一并做 4-连通分量（灰色标记不参与连通），同一分量中的框构成一组。
- 统计每组灰色标记总数 S；擦除所有灰色标记与青色通路。
- 每个框的容量 = 其中心行内侧从右端起每隔一格放点所能容纳的点数（由框内宽决定）。
- 组内各框按容量从小到大排队，把 S 枚灰点先装满最小框，再装下一个，直到点用尽（输入保证组总容量不小于 S）。

关键洞察
- 桥并账之后点数还要装箱重分——任何一个框显示的点数既不是它自己的标记数，也不是组总数，而是"总账在容量序中轮到它的那一份"；孤立框的示例会诱导"数自己"的错误假设。
```

## 3. 指示射线的连锁点火

- 参考题目: `b527c5c6`、`1d398264`、`239be575`
- tags:
  - operation:射线延伸, ray_extension
  - operation:重涂色, recolor
  - object:矩形, rectangle
  - object:指示像素, indicator_pixel
  - object:火种矩形, seed_rectangle
  - relation:方向指示, direction_indication
  - relation:有向可达, directed_reachability
  - condition:仅点燃者发射, only_ignited_fire

### docstring

```text
从唯一的橙色火种矩形出发，红色指示点的射线把火沿有向链传给被击中的矩形。

输入结构
- 黑色背景上散布若干实心矩形，每个矩形边框上恰有一个红色指示像素，标记该矩形的发射方向（红点所在边的外法线方向）。
- 恰有一个矩形是橙色（火种），其余矩形为绿色。

规则
- 已点燃的矩形从其红色指示像素向外发射一条红色射线，射线沿空格直行，直到出界或首次击中另一矩形停下。
- 被射线击中的绿色矩形整体变橙并被点燃，随后从它自己的红点发射自己的射线。
- 反复传播直到没有新的矩形被点燃。
- 输出画出所有已发射的射线；未被点燃的矩形保持绿色且不发射。

关键洞察
- 每个矩形的红点都定义一条潜在的有向边，但真正生效的只有从火种可达的那部分——答案是有向图上的可达闭包，而不是"所有矩形一起发射"。
```

## 4. 隐形菱形场的干涉区

  - object:实心条, solid_bar
  - object:菱形区域, diamond_region
  - relation:场重叠, field_overlap
  - condition:至少两场覆盖, covered_by_two_fields
  - condition:场从未画出, field_never_drawn

### docstring

```text
只把同时落进至少两根条的隐形菱形领域的格子涂成青色。

输入结构
- 单一背景色上有若干一格粗的水平或垂直实心条，颜色互异；条与条互不接触。
- 青色不出现在输入中，专用于输出的干涉区。

规则
- 每根长度为 L 的条定义一个隐形实心菱形领域：以该条为中线、半径 floor((L-1)/2)，每远离中线一步、区间两端各收缩一格所扫出的实心区域（含条自身所在行或列）。
- 保留所有原条。
- 被至少两个隐形领域覆盖的背景格涂青色，其余保持背景；只被一个领域覆盖的部分不画出。

关键洞察
- 每根条都在生成一个从未被画出的菱形场，画面上唯一可见的产物是诸场的交叠区；若不先在心中重建每个隐形场，就无法解释输出中那些看似随意的青色透镜块。
```

## 5. 对角锚点的隐形容器

- 参考题目: `f35d900a`、`6ad5bdfd`、`d4c90558`
- tags:
  - operation:重力下落, gravity_drop
  - operation:擦除, erase
  - object:角标记像素, corner_marker_pixel
  - object:沙粒像素, grain_pixel
  - relation:同色成边, same_color_marks_edge
  - relation:包含, containment
  - condition:容器从未画出, container_never_drawn
  - condition:灰边为地板, grey_edge_is_floor

### docstring

```text
四个角标撑起一个从未画出的矩形容器，内部沙粒落向灰色角标标出的那条边，外部沙粒被清除。

输入结构
- 黑色背景上恰有四个角标像素：灰色两个、另一颜色两个；同色的两个角标各占矩形一条边的两端，两色合起来标出一个轴对齐矩形的四角。矩形的边从未画出。
- 网格上另散布若干彩色沙粒像素，颜色不同于角标色，位置有内有外。

规则
- 由四个角标恢复隐形矩形；灰色角标共享的那条边是容器的地板。
- 矩形内部的沙粒沿垂直于地板的方向坠向地板内侧，逐粒堆积：同一条坠落线上的沙粒依次叠放，保持原有先后次序，不越过地板也不互相穿透。
- 矩形外部的沙粒全部擦除。
- 四个角标保持原位；矩形的边在输出中依然不画。

关键洞察
- 容器只以四个角标的形式存在：一对灰角标既参与撑出容器，又指定重力方向（地板可能是上、下、左、右任意一条边）；沙粒落向的从来不是网格边缘，而是这条看不见的边。
```

```text
先用中心对称补全带洞的模板，再把它按源面板的彩色像素做分形印章展开。

- 输入由两个等大的 N×N 面板并排或上下拼成，共享同一背景色。

关键洞察
- 印章的母版从未完整出现在输入里；若直接拿残缺模板去印，每个印章都会带着同样的洞。必须先由旋转对称还原母版，再做块级展开——补全与印章缺一不可。
```

## 7. 整除配对的比例转运

  - operation:堆叠, stack
  - object:标记条, marker_bar
  - object:精灵体, sprite
  - object:车道, lane
  - relation:整除配对, divisibility_pairing
  - condition:长度比即缩放比, length_ratio_is_scale
  - condition:数量守恒, count_conservation

### docstring

```text
红条车道的精灵搬进"绿条长度恰为红条整数倍"的车道，按长度之商放大后重新堆叠。

输入结构
- 背景为最多色。若干水平细条标记出竖直车道：红条车道内有若干枚相同的单色小精灵，绿条车道为空。
- 各条长度互不相同；每根红条恰有一根绿条的长度是它的整数倍，且这样的绿条唯一。

规则
- 每根红条与长度为其整数倍的那根绿条配对，倍数 k 即缩放系数。
- 红车道中的精灵原位变灰。
- 在配对的绿车道里，把该精灵形状放大 k 倍、重涂为绿色，按原数量自底向上等距堆叠。
- 所有标记条从输出中移除。

关键洞察
- 车道的配对不看远近——就近配对会在部分示例上失效；真正的钥匙是长度的整除关系，而商同时就是精灵的放大倍数：一组比值同时编码了"去哪儿"和"变多大"。
```

## 8. 中轴钥匙带与缺失的钥匙

- 参考题目: `d23f8c26`、`2a28add5`、`8f215267`、`73251a56`
- tags:
  - operation:计数, counting
  - operation:擦除, erase
  - operation:填充, fill
  - object:中轴列, center_column
  - object:钥匙像素, key_pixel
  - object:缺口格, hole_cell
  - relation:同色匹配, same_color_matching
  - condition:钥匙色选计数对象, key_color_filters_count
  - condition:缺失钥匙反推, infer_missing_key

### docstring

```text
正中列的钥匙色决定每行数什么，缺口处的钥匙要先由两侧共现的唯一颜色反推出来。

输入结构
- 网格列数为奇数，背景为非黑的最多色，黑色仅可能出现在正中列。
- 正中列的某些行放着非背景的"钥匙"像素；个别钥匙行的中轴格是黑色缺口（钥匙被抹去）。
- 各行散布多种颜色的像素；没有钥匙的行也可能有散点。

规则
- 输出从全背景画布开始。
- 缺口行的钥匙色 = 该行中轴两侧都出现的那种唯一颜色。
- 对每个钥匙行（含反推出的）：数出该行中轴左侧、右侧与钥匙同色的像素个数 L 和 R，其余颜色一概不计。
- 用钥匙色画横条，从中轴左移 L 格连续画到中轴右移 R 格（含中轴格，缺口格也涂钥匙色）。
- 没有钥匙的行全部清空。

关键洞察
- 中轴是一条钥匙带，钥匙色既是过滤器又是画笔；被抹去的钥匙没有消失——它的身份藏在"两侧共现的唯一性"里，必须先反推生成元，再执行同色计数。
```

## 9. 镜像场中的入侵者

- 参考题目: `67e8384a`、`73251a56`
- tags:
  - operation:镜像, mirror
  - operation:裁剪, clip
  - object:瓦片, tile
  - object:入侵精灵, intruder_sprite
  - relation:双轴反射, biaxial_reflection
  - relation:四重表决, fourfold_voting
  - condition:少数派即残迹, minority_is_trace

### docstring

```text
在一张双轴镜像平铺上找出打破四重对称的少数派格子，裁出入侵者的残迹。

输入结构
- 整张网格本是某个种子瓦片的 2×2 双轴镜像平铺（左右、上下反射）。
- 一个不透明的杂色精灵完整落在某一个象限内，盖掉了该处的平铺内容；精灵可以使用与平铺相同的颜色。

规则
- 对每个格子取它在双轴反射下的四元组，四元组内做多数表决得到平铺的预期值。
- 与预期不符的格子就是入侵者的残迹像素。
- 取残迹像素的最小外接框，按原色输出该裁剪；框内与预期一致的格子输出黑色（黑色不参与平铺与精灵用色）。

关键洞察
- 不能靠颜色把入侵者挑出来——它与平铺共用调色板；唯一的证词来自对称场本身：三个镜像伙伴一致而它独异。输出要的不是修复后的场，而是这份"异议清单"的裁剪，精灵中恰好与预期同色的部分自然隐形。
```
