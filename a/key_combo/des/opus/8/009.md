## 新题 1：指示位定旋转的模板印章

**组合逻辑**：[stamp_overlay](来自 e76a88a6) + [rotate](来自 1b60fb0c，创新：旋转角度由指示像素的方位编码) + [recolor](来自 57aa92db，创新：指示像素颜色替换模板主色)

**来源原语**：stamp_overlay (e76a88a6), rotate (1b60fb0c), recolor (57aa92db), indicator_pixel (b775ac94), size_matching (e76a88a6), solid_rectangle (e76a88a6), adjacency_contact (48d8fb45)

**依赖链**：指示像素的方位决定旋转角度 -> 旋转变换模板 -> 变换后的模板印入目标矩形 -> 指示像素颜色替换模板中的主色。去掉方位检测则旋转角度不确定；去掉旋转则印出的模板方向错误；去掉重涂色则每个目标颜色相同，无法区分。

根据指示像素在目标矩形哪一侧，将多色模板旋转相应角度后印入该矩形，并用指示像素的颜色替换模板中出现最多的颜色。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 一个 4-连通的多色前景对象（模板），使用 2-3 种非黑、非灰颜色，边界框约 3x4 或 4x3 像素，形状不对称（确保旋转后可区分方向）。
- 2-4 个实心灰(5)矩形，每个矩形的内部尺寸（高x宽）与模板的边界框尺寸一致（若模板 3x4，则灰矩形内部恰为 3x4 或 4x3，视旋转需要而定）。
- 每个灰矩形的四条边中恰好有一条边的外侧正中央有一个单像素指示点，指示点颜色为非黑、非灰、且不出现在模板中的颜色，各个指示点颜色互不相同。
- 生成约束：指示点所在方位隐含的旋转后模板边界框尺寸恰好等于该灰矩形的内部尺寸。不同示例中指示点出现在不同的边。

**规则**：
1. 识别模板：唯一的非灰、非单像素的多色前景对象。
2. 对每个灰(5)矩形，找到与其 4-邻接的单像素指示点，并判断指示点贴在矩形的哪一侧：
   - 顶边 -> 顺时针旋转 0 度（不旋转）
   - 右边 -> 顺时针旋转 90 度
   - 底边 -> 顺时针旋转 180 度
   - 左边 -> 顺时针旋转 270 度
3. 将模板按确定的角度顺时针旋转。
4. 在旋转后的模板副本中，将出现像素数最多的那种颜色替换为该指示点的颜色（其余颜色不变）。
5. 将重涂色后的旋转模板覆盖到灰矩形内部，逐像素替换灰色。
6. 移除指示点（设为黑(0)）。模板原件保持不变。

**关键洞察**：指示像素同时编码了两个独立参数——方位编码旋转角度，颜色编码主色替换——使得每个目标矩形需要一次独特的复合变换。仅凭单个示例无法确定"哪一侧对应哪个旋转角度"的完整映射。

## 新题 2：分区频率擦除

**组合逻辑**：[equal_partition](来自 c3202e5a) + [counting](来自 f8b3ba0a，创新：频率统计跨越分区单元而非对象内部) + [erase](来自 54db823b，创新：擦除目标由跨单元比较决定)

**来源原语**：equal_partition (c3202e5a), counting (f8b3ba0a), erase (54db823b), separator_line (c3202e5a), grid_cell (c3202e5a), skip_most_frequent (f8b3ba0a)

**依赖链**：分隔线定义分区边界 -> 统计每个单元的前景像素数 -> 跨所有单元比较频率找出众数 -> 擦除众数对应的单元内容。去掉分区则无统计边界；去掉计数则无法比较；去掉擦除则无输出变换。

将网格等分为若干单元，统计每个单元的前景像素数量，擦除像素数等于众数的所有单元，保留其余单元。

**输入结构**：
- 正方形网格（如 15x15 或 21x21），由单像素宽的黄(4)分隔线（贯穿整行或整列）分为等大的正方形单元（如每个 4x4 或 6x6）。
- 每个单元内含一个小型 4-连通单色前景图形（3-8 像素不等的不规则形状），前景颜色在不同单元中可以不同，但均非黑(0)、非黄(4)。
- 不同单元中的前景像素数量有差异：多个单元共享同一像素数（形成众数），少数单元拥有不同的像素数。
- 背景为黑(0)。
- 生成约束：恰好有一个严格众数（不出现并列最多频次的情况）。

**规则**：
1. 识别黄(4)分隔线，将网格分为等大正方形单元。
2. 对每个单元，统计其中非黑、非黄前景像素的数量。
3. 在所有单元的像素数中找出众数（出现次数最多的那个像素数值）。
4. 将像素数等于众数的所有单元内的前景像素擦除（设为黑(0)）。分隔线保持不变。
5. 像素数不等于众数的单元保留其前景像素不变。

**关键洞察**：擦除判据不基于任何单个单元的内容属性（颜色、形状、位置），而基于跨所有单元的统计比较——必须先计数、再跨分区比较、最后才能确定擦除目标。单个示例中可能无法确认是"擦除最多的"还是"擦除等于某值的"，需要多示例归纳出"众数"这一规则。

## 新题 3：对称补全后按内部标记多数色填充

**组合逻辑**：[mirror/symmetry_completion](来自 bf32578f，创新：补全建立几何边界而非直接产出) + [counting](来自 f8b3ba0a/54db823b，创新：计数范围由补全后的边界决定) + [fill](来自 bf32578f，创新：填充色由标记分布投票决定)

**来源原语**：mirror (bf32578f), counting (f8b3ba0a), fill (bf32578f), half_outline (bf32578f), marker_pixel (48d8fb45), symmetry (bf32578f), interior_marker_count (54db823b)

**依赖链**：半侧轮廓镜像补全 -> 定义闭合内部区域 -> 统计落入内部的各色标记数量 -> 多数色确定填充颜色。去掉补全则内部边界未知；去掉计数则填充色不确定；去掉填充则无输出变换。三者形成几何-统计-渲染的推理链。

将半侧轮廓镜像补全为完整闭合形状，统计落入闭合区域内部的各色标记像素，用数量最多的标记颜色填充内部。

**输入结构**：
- 黑(0)背景，约 14x14 网格。
- 一组绿(3)前景像素形成一个左半轮廓：沿垂直方向上下延伸，最右侧的前景像素紧贴形状的垂直中线。该轮廓呈不规则的半封闭形状（如半个花瓶轮廓，3-5 像素宽，8-12 像素高）。
- 散布在网格各处的 6-10 个单像素标记，分属 2-3 种颜色（如蓝(1)、红(2)、黄(4)），部分标记位于轮廓镜像补全后的内部区域，部分位于外部。
- 生成约束：补全后的内部区域中至少有 2 个标记；内部标记中恰好有一种颜色数量严格最多（无并列）。

**规则**：
1. 找到绿(3)半轮廓最右列的列号 c_max。镜像轴位于 c_max + 0.5 处（即 c_max 与 c_max+1 之间）。
2. 将每个绿(3)像素 (r, c) 关于镜像轴水平翻转，得到镜像像素 (r, 2*c_max + 1 - c)。若镜像位置无前景像素，则绘制绿(3)像素，形成完整的闭合轮廓。
3. 对于每一行，确定该行上最左和最右绿(3)像素的列号，二者之间（不含轮廓像素本身）即为该行的内部区间。所有行的内部区间的并集构成闭合内部区域。
4. 统计所有落在内部区域中的标记像素，按颜色分组计数。
5. 用数量最多的标记颜色填充整个内部区域。
6. 位于内部区域的标记像素保留（绘制在填充色之上）。位于外部的标记像素擦除（设为黑(0)）。轮廓像素（原始和镜像）保持绿(3)。

**关键洞察**：填充颜色并非轮廓本身的属性，而由标记像素与镜像边界的空间交互决定——移动一个标记跨过对称边界就可能改变整个区域的填充色。求解者必须先完成几何补全才能判定哪些标记"算数"。

## 新题 4：周期补全与标记覆写

**组合逻辑**：[completion/translate](来自 53b68214) + [recolor](来自 36fdfd69，创新：重涂色的目标由周期补全位置与标记位置的空间重合决定) + [erase](来自 54db823b，创新：不重合的标记被擦除)

**来源原语**：completion (53b68214), recolor (36fdfd69), erase (54db823b), periodic_translation (53b68214), marker_pixel (48d8fb45), row_pattern (53b68214)

**依赖链**：推断周期和偏移 -> 外推缺失行 -> 检查外推像素与标记像素的空间重合 -> 重合位置用标记色覆写，不重合的标记擦除。去掉周期推断则无法外推；去掉外推则不知哪些位置产生新像素；去掉重合检测则标记无意义。

外推周期行图案以填满画布，当外推像素恰好落在预置标记位置时，用标记颜色覆写该像素；不与外推像素重合的标记被擦除。

**输入结构**：
- 宽 10 的网格，高度为 5-7 行（小于 10），背景黑(0)。
- 上部若干行含有蓝(1)前景像素，形成具有周期性水平偏移的行图案（与 53b68214 类似）：垂直周期 P（2 或 3），每个周期水平偏移 S（1 或 2 像素）。
- 在网格下部的空白区域（第 input_height 行至第 9 行之间），散布 3-6 个单像素标记，颜色为红(2)或绿(3)，位置各异。
- 生成约束：至少有 1 个标记恰好位于外推后某前景像素应出现的位置；至少有 1 个标记不与任何外推位置重合。

**规则**：
1. 将输入行复制到一个 10x10 黑(0)画布的顶部。
2. 从已有行中推断最小垂直周期 P 和对应的水平偏移 S。
3. 对每一行缺失行（行号 >= input_height），从其上方 P 行处复制行内容并水平偏移 S 像素（超出网格边界的像素裁剪丢弃）。
4. 遍历所有标记像素：若该标记位置恰好是某个外推前景像素的位置（即步骤 3 本应在此绘制蓝(1)前景），则将该位置像素设为标记的颜色（红(2)或绿(3)），取代蓝(1)。
5. 若标记位置不与任何外推前景位置重合，则擦除该标记（设为黑(0)）。
6. 原始输入行中的前景像素保持蓝(1)不变（标记仅影响外推部分）。

**关键洞察**：标记像素并非全部有效——只有恰好落在外推图案位置上的标记才产生颜色覆写，其余标记被静默擦除。求解者必须先完成周期外推才能判断每个标记的命运，而标记的存在又改变了外推区域的最终颜色。

## 新题 5：非对称度排序与对称瓦片过滤

**组合逻辑**：[symmetry_detect](来自 662c240a，创新：对称性从二值判断扩展为量化评分) + [counting](来自 f8b3ba0a，创新：计数对象从矩形个数变为不对称像素对数) + [sorting](来自 f8b3ba0a，创新：排序依据从颜色频率变为结构属性) + [crop](来自 662c240a)

**来源原语**：symmetry_detect (662c240a), counting (f8b3ba0a), sorting (f8b3ba0a), crop (662c240a), stacked_layout (662c240a), select_asym_tile (662c240a)

**依赖链**：切分瓦片 -> 检测每块的对角对称性 -> 量化非对称度 -> 丢弃完全对称的瓦片 -> 按非对称度升序排列输出。对称检测既是过滤器（丢弃对称块）又是度量（评分排序），两种功能缺一则输出错误。

将垂直堆叠的瓦片按主对角线对称性过滤和排序：丢弃完全对称的瓦片，将剩余瓦片按非对称程度从低到高重新堆叠输出。

**输入结构**：
- 一个竖长网格（如 5x25 或 4x24），由 5-6 块等大的正方形瓦片（如每块 5x5 或 4x4）垂直堆叠而成，无分隔行。
- 每块瓦片使用两种颜色（一种前景色 + 黑(0)背景），前景色在不同瓦片中可不同。
- 部分瓦片关于主对角线完全对称（cell[r,c] == cell[c,r] 对所有 r,c 成立），部分不对称。
- 生成约束：至少 2 块完全对称、至少 2 块不对称；不对称瓦片的非对称度（不满足 cell[r,c]==cell[c,r] 的 (r,c) 对数，r<c）各不相同。

**规则**：
1. 将输入网格从上到下切分为 N 块等大的正方形瓦片（每块高度 = 网格宽度）。
2. 对每块瓦片，检测是否关于主对角线对称：对所有满足 r < c 的位置对 (r,c)，检查 cell[r,c] 是否等于 cell[c,r]。
3. 丢弃所有完全对称的瓦片（不出现在输出中）。
4. 对每块不对称瓦片，计算其非对称度 = 满足 r < c 且 cell[r,c] != cell[c,r] 的 (r,c) 对数。
5. 将不对称瓦片按非对称度升序排列（非对称度最低的在最上方）。若两块非对称度相同（生成约束下不会发生），保持原始从上到下的顺序。
6. 输出排序后的瓦片垂直堆叠。

**关键洞察**：对称性分析同时充当二值过滤器（对称 vs 不对称）和连续度量（非对称程度），两者作用于同一结构检测但产生不同的后续操作（过滤 vs 排序）。仅凭单个示例难以同时确认"对称块被丢弃"和"剩余块按非对称度排序"两条规则。

## 新题 6：变换编码式像素放大

**组合逻辑**：[pixel_upscale](来自 bf45cf4b，创新：控制网格从二值掩码扩展为多值变换指令) + [mirror/transpose](来自 74dd1130，创新：转置由控制颜色触发而非全局应用)

**来源原语**：pixel_upscale (bf45cf4b), mirror (74dd1130), tile (bf45cf4b), control_sprite (bf45cf4b), polychrome_tile (bf45cf4b), mask_mapping (bf45cf4b), diag_transpose (74dd1130)

**依赖链**：控制网格的每个单元颜色编码一种变换指令 -> 对瓦片施加对应变换 -> 将变换后的瓦片印入输出的对应位置。去掉颜色-变换映射则所有位置贴同一瓦片；去掉变换则控制颜色无意义；去掉放大则无输出结构。控制网格既是空间布局图又是变换参数表。

控制网格的每个非背景单元不仅指示"在此放置瓦片"，还通过自身颜色指定该瓦片应做何种空间变换（原样、主对角线转置、水平翻转）后再放置。

**输入结构**：
- 黑(0)背景，网格约 12x12。
- 一个 3x3 或 4x4 的多色正方形瓦片（使用 2-3 种非黑颜色），刻意设计为无任何对称性（确保各变换结果可区分）。
- 一个矩形控制网格（如 3x4 或 4x3），由蓝(1)、红(2)、黑(0)三种颜色的单元组成。蓝和红单元各至少出现 2 次。
- 瓦片与控制网格在输入中空间分离，不相邻。

**规则**：
1. 识别多色正方形瓦片（唯一的使用 3 种以上颜色的前景对象）和控制网格（唯一的仅含蓝(1)、红(2)、黑(0)的矩形区域）。
2. 对控制网格中的每个单元位置 (i, j)：
   - 黑(0)：输出中对应区域留为瓦片大小的全黑块。
   - 蓝(1)：输出中对应区域放置瓦片的原始副本。
   - 红(2)：输出中对应区域放置瓦片经主对角线转置后的副本（pixel[r,c] -> pixel[c,r]）。
3. 输出网格尺寸为 (控制网格高 x 瓦片高) 行 x (控制网格宽 x 瓦片宽) 列。

**关键洞察**：控制网格并非简单的二值掩码（有/无），而是三值指令图——每种非背景颜色编码一种不同的空间变换。瓦片的刻意不对称使得原样与转置的结果在视觉上可区分，从而令求解者必须从多示例中推断颜色-变换的映射关系。

## 新题 7：射线障碍折线路径

**组合逻辑**：[draw_line/L_path](来自 a2fd1cf0，创新：L 形路径遇障碍变为 Z 形绕行) + [ray_extend](来自 99fa7670/5c0a986e，创新：射线从路径引导变为路径障碍)

**来源原语**：draw_line (a2fd1cf0), ray_extend (99fa7670), L_path_connection (a2fd1cf0), start_marker (a2fd1cf0), end_marker (a2fd1cf0), isolated_pixel (99fa7670), row_column_alignment (99fa7670), canvas_boundary (99fa7670)

**依赖链**：灰色像素发射垂直射线形成障碍壁 -> 同色标记对之间绘制 L 形路径 -> 路径水平段遇障碍壁时截断并绕行形成 Z 形。去掉射线则所有路径为简单 L 形；去掉 L 形路径则射线无交互意义；射线的存在改变了路径的几何形态。

灰色像素发射向下的垂直射线形成障碍壁，同色标记对之间绘制水平优先的 L 形路径，当水平段被障碍壁阻挡时路径绕行为 Z 形。

**输入结构**：
- 黑(0)背景，约 15x15 网格。
- 2-3 对同色标记：每种颜色（如蓝(1)、红(2)、绿(3)）恰好出现两个单像素标记。同色标记对不在同一行也不在同一列。
- 1-2 个灰(5)单像素，位于网格上半部分。
- 生成约束：至少有一对标记的水平连线被灰色射线阻挡（灰色像素的列位于该对标记的列之间，且灰色像素的行不高于该对中上方标记的行）；至少有一对标记的水平连线不被阻挡。

**规则**：
1. 每个灰(5)像素向下发射垂直射线：从该像素所在行向下逐行绘制灰(5)像素，直至网格底边（含底边）。灰色像素本身保留。
2. 对每对同色标记，将行号较小的记为上标记 A (r_a, c_a)，行号较大的记为下标记 B (r_b, c_b)。
3. 绘制路径（路径颜色 = 该对标记的颜色）：
   a. 从 A 出发，沿 A 所在行水平向 B 的列方向逐像素绘制。
   b. 若水平段在到达 c_b 之前遇到灰色射线（即下一个要绘制的像素所在列上存在灰色射线像素），则水平段停止在射线前一列。从停止点向下垂直绘制至 B 所在行 r_b，再从该行水平绘制至 B 所在列 c_b（形成 Z 形三段路径）。
   c. 若水平段未遇到障碍，则一直绘制到 c_b，再从 (r_a, c_b) 向下垂直绘制至 (r_b, c_b)（标准 L 形两段路径）。
4. 路径像素不覆盖灰色射线像素。若不同颜色路径交叉，后绘制的覆盖先绘制的（绘制顺序：按上标记 A 的行号从小到大；行号相同则按列号从小到大）。
5. 标记像素保留原色。

**关键洞察**：灰色射线并非路径的一部分，而是路径的障碍物——射线的存在将本应为 L 形的路径变形为 Z 形绕行。求解者必须先构建射线、再判断每条路径是否被阻挡，两种几何元素（射线 vs 路径）的交互决定了路径的最终形态。

## 新题 8：标记选取控制精灵的像素放大

**组合逻辑**：[crop](来自 48d8fb45，创新：裁剪结果不是输出，而是后续放大操作的控制参数) + [pixel_upscale](来自 bf45cf4b，创新：控制精灵不是预设的，而是从输入场景中通过标记选择得来) + [marker_selects_neighbor](来自 48d8fb45)

**来源原语**：crop (48d8fb45), pixel_upscale (bf45cf4b), marker_pixel (48d8fb45), marker_selects_neighbor (48d8fb45), adjacency_contact (48d8fb45), polychrome_tile (bf45cf4b), mask_mapping (bf45cf4b), control_sprite (bf45cf4b)

**依赖链**：灰色标记选中邻接对象 -> 裁剪选中对象得到二值掩码 -> 掩码作为控制精灵驱动像素放大 -> 瓦片从输入中另一位置获取。去掉标记选择则不知用哪个对象做掩码；去掉裁剪则无法提取掩码；去掉放大则掩码和瓦片无交互。选取操作的输出成为放大操作的输入参数，形成跨操作的信息流。

通过灰色标记像素选出一个前景对象，将其裁剪后的形状作为二值掩码，用于像素放大——掩码中有前景的位置印入从输入中另一处找到的多色瓦片，背景位置留空。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 3-4 个互不相邻的 4-连通单色前景对象（同一种前景颜色，如蓝(1)），每个对象 3-6 像素，形状各异（不规则形状，非简单矩形）。
- 恰好有一个灰(5)单像素与其中一个蓝色对象 4-邻接。
- 在网格的另一区域（与蓝色对象群不相邻），有一个小型多色正方形瓦片（如 3x3），使用 2-3 种非黑、非蓝、非灰的颜色（如红(2)、绿(3)、黄(4)）。
- 生成约束：被选中对象的边界框为正方形或近正方形（确保放大后的输出不会过于细长）。各蓝色对象边界框不重叠。

**规则**：
1. 识别灰(5)标记像素，找到与之 4-邻接的蓝(1)对象。
2. 裁剪该对象的边界框，得到一个二值掩码（蓝色像素 = 填充，黑色像素 = 空）。
3. 识别多色正方形瓦片（唯一一个使用 3 种以上颜色的对象）。
4. 以二值掩码为控制精灵、多色方块为瓦片，执行像素放大：
   - 对掩码中每个位置 (i, j)：若为填充，则在输出中对应区域放置瓦片的完整副本；若为空，则对应区域留为瓦片大小的全黑块。
5. 输出网格尺寸 = (掩码高 x 瓦片高) 行 x (掩码宽 x 瓦片宽) 列。
6. 输出中不包含原始输入的任何内容（原始对象、标记、瓦片均不保留）。

**关键洞察**：灰色标记不是在选择"要输出什么对象"，而是在选择"用什么形状作为放大的控制掩码"——选取操作的产物是另一个操作的参数而非最终答案。求解者若按 48d8fb45 的思路认为选中的对象就是答案，会得到错误结果。
