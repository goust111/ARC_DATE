## 新题 1：射线交织差异图

**组合逻辑**：[射线延伸](每个标记向两个最近边界投射同色射线) → [逐像素比较](两色射线网格逐格比较) → [差异分类着色](创新：交叉点产生第三色)

**来源原语**：射线延伸(ray_extend, #20 705a3229), 逐像素比较(pixel_comparison, #1 d47aa2ff), 差异分类着色(diff_class_color, #1 d47aa2ff), 最近边界方向(nearest_boundary_direction, #20 705a3229)

**依赖链**：射线延伸为两组标记分别生成射线网格，网格的形状由标记位置和边界距离决定；逐像素比较以这两个动态生成的网格为输入（而非静态面板），在交叉处应用差异着色。射线延伸的输出完全决定了比较的空间范围和形状，删除任一步均无法求解。

将两种颜色的标记像素各自向最近边界投射射线，对两组射线网格逐格比较，仅一色占据保留原色，双色交叉的位置涂为第三色。

**输入结构**：黑(0)背景网格，约 12x12 至 16x16。网格中散布两种颜色的孤立像素：红(2)像素 2~4 个，蓝(1)像素 2~4 个。所有孤立像素互不在同一行或同一列上。每个像素到最近水平边界和最近垂直边界的距离均无平局（即不在行或列的正中央）。红像素与蓝像素之间的射线路径保证存在至少 2 处交叉。

**规则**：
1. 对每个红(2)像素，沿其所在列向最近的水平边界（顶/底）延伸一条红(2)射线，同时沿其所在行向最近的垂直边界（左/右）延伸一条红(2)射线，形成一个 L 形。像素本身保留。
2. 对每个蓝(1)像素做相同操作，生成蓝(1)射线。
3. 逐格比较两组射线占据的区域：
   - 仅红射线占据的格子保持红(2)。
   - 仅蓝射线占据的格子保持蓝(1)。
   - 红射线与蓝射线同时占据的格子涂为绿(3)。
4. 原始标记像素保持其原色不变（即使处于交叉位置，标记像素也保持原色）。
5. 所有其他格子保持黑(0)。
6. 处理顺序：先生成所有射线，再统一做逐格比较，不存在先后覆盖问题。

**关键洞察**：被比较的不是预设面板而是动态生成的射线网格——交叉格的颜色（绿(3)）需要对比多个示例才能确认不是来自某种位置规则，而是来自"双色共占"这一比较逻辑。

## 新题 2：滑动投票决定最短路径终端

**组合逻辑**：[滑动 + 同色配对](孤立像素滑向同色方块) → [无匹配色则删除](清除无目标像素) → [最短路径](以接收到像素的方块为终端求最短路径) → [重涂色](路径着色)

**来源原语**：滑动(sliding, #7 1a07d186), 同色配对(same_color_pairing, #7), 无匹配色则删除(unmatched_deleted, #7), 最短路径(shortest_path, #5 7b0280bc), 图结构(graph_structure, #5), 节点方块(node_square, #5), 轨道段(track_segment, #5), 重涂色(recolor, #5)

**依赖链**：滑动操作将孤立像素移入图节点，决定了哪两个节点成为终端；终端身份是最短路径操作的前提。删除滑动步骤则终端未知，删除路径步骤则滑动结果无用途。

散落的彩色像素沿直线滑向同色方块节点，恰好有两个方块接收到像素成为终端，在方块-轨道构成的图中求这两个终端之间的最短路径并着色。

**输入结构**：黑(0)背景网格，约 15x15 至 20x20。网格中有 4~6 个单色实心方块（每个方块为 2x2 或 3x3，颜色各不相同，从红(2)、蓝(1)、黄(4)、品红(6)、橙(7)中选取）。方块之间有灰(5)的单像素宽轨道段相连，形成一个连通图（每条轨道沿水平或垂直直线连接两个方块的最近边缘）。在方块和轨道之外，散布 2~5 个孤立像素，其中恰好 2 个像素的颜色分别与某个方块匹配，其余像素颜色不与任何方块匹配。每个有匹配的像素与其目标方块在同一行或同一列上，且该方向上无障碍。

**规则**：
1. 对每个孤立像素，检查是否存在颜色相同的方块。若存在，该像素沿与目标方块共享的行或列方向滑动，直到与目标方块的边缘相邻（4-邻接），然后停止并消失（被方块"吸收"）。
2. 颜色不与任何方块匹配的孤立像素直接删除（变为黑(0)）。
3. 恰好有两个方块各吸收了一个像素，这两个方块成为终端节点。
4. 在方块-轨道图中，用广度优先搜索找到两个终端之间的最短路径（经过最少的轨道段）。
5. 路径上的非终端方块重涂为绿(3)，路径上的轨道段重涂为青(8)。终端方块保持原色。
6. 不在路径上的方块和轨道保持原色/原灰色不变。

**关键洞察**：终端节点不是预先标记的，而是由滑动结果动态决定——需要对比多个示例才能发现"吸收了像素的方块"才是终端，而非其他空间属性（如边缘位置或方块大小）。

## 新题 3：周期修复揭示隐藏裁剪标记

**组合逻辑**：[补全](利用平移对称修复遮挡) → [异常值选择](修复后识别非周期的异常色) → [裁剪 + 标记对齐指定半区](以异常色像素为标记裁剪半区) → [擦除](清除标记)

**来源原语**：补全(inpaint, #18 0dfd9992), 平移对称(translational_symmetry, #18), 轨道可见色填缺失(orbit_color_restores_missing, #18), 裁剪(crop, #15 fbf15a0b), 标记对齐指定半区(marker_selects_half, #15), 擦除(erase, #15), 异常值选择(outlier_selection, #2 ad3b40cf)

**依赖链**：补全操作恢复被遮挡的像素，其中部分恢复出的像素呈现周期模式中不存在的异常颜色——这些是隐藏的裁剪标记。标记在补全前不可见（被黑色遮挡），补全后才暴露位置信息供裁剪使用。删除补全步骤则标记位置未知，删除裁剪步骤则补全无目的。

修复周期图案的黑色遮挡后，恢复出的像素中出现两个异常颜色像素（不属于周期色板），以它们为标记裁剪出所在半区并擦除标记。

**输入结构**：网格约 10x14 至 14x18。整体为一个具有平移周期性的彩色图案（使用 3~4 种颜色，如蓝(1)、绿(3)、黄(4)、橙(7)），周期为 3x3 至 5x5。图案中有 6~12 个格子被黑(0)遮挡。在这些被遮挡的位置中，恰好有 2 个格子的"真实值"不是周期图案的颜色，而是红(2)——一种在周期图案中完全不出现的颜色。这两个红(2)像素在同一行或同一列上，且都位于网格沿该方向的同一半区内。其余被遮挡位置的真实值均可由周期轨道唯一确定。

**规则**：
1. 检测输入中非黑(0)像素的平移对称性，确定最小平移向量。
2. 对每个黑(0)格子，收集其平移轨道上所有非黑色的可见值。
3. 若轨道上的可见值颜色唯一，用该颜色填充。若轨道上出现的颜色不在周期图案的色板中（即红(2)），同样填入该颜色。
4. 修复完成后，找到恰好 2 个红(2)像素。
5. 若两个红(2)像素共享同一行，检测它们在水平方向上位于左半区还是右半区，裁剪出该半区。若共享同一列，检测上下半区并裁剪。半区边界为网格中线（列数或行数的一半，向下取整）。
6. 在裁剪出的半区中，将两个红(2)像素恢复为黑(0)（擦除标记）。
7. 输出为裁剪后的半区网格。

**关键洞察**：标记在输入中被遮挡为黑色，与普通缺失像素完全无法区分——只有完成周期修复后，红(2)才会作为异常色浮现，而这个异常色恰恰是裁剪指令。需要对比多个示例才能发现红色不是周期图案的一部分而是功能性标记。

## 新题 4：对角印章计数生成柱状图

**组合逻辑**：[印章覆盖 + 尺寸决定步幅](每个矩形沿对角重复直到出界) → [计数](统计每个矩形的有效印章总数) → [排序 + 按高度排列](按印章数降序) → [柱状图输出](每列高度等于对应印章数)

**来源原语**：印章覆盖(stamp, #6 e619ca6e), 尺寸决定步幅(size_determines_stride, #6), 对角偏移重复(diag_offset_repeat, #6), 计数(counting, #3 b7999b51), 排序(sorting, #3), 柱状图(histogram_bar, #3), 按高度排列(height_order, #3)

**依赖链**：对角印章的传播距离取决于矩形自身尺寸和位置（尺寸决定步幅，位置决定到边界的距离），产生的副本数成为排序和柱状图高度的数据来源。印章操作的空间结果被压缩为一个标量（计数），再驱动一个与印章完全不同的可视化操作。删除印章则无计数来源，删除排序则无法确定输出列的顺序。

多个不同尺寸和位置的矩形各自沿对角线方向重复印章直到出界，统计每个矩形产生的印章总数（含原始），按印章数从多到少输出一行顶对齐柱状图。

**输入结构**：黑(0)背景网格，约 15x15 至 20x20。网格中有 3~5 个不重叠的单色实心矩形，颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取）。每个矩形尺寸不同（宽 1~4，高 1~4，不全为正方形）。各矩形的位置保证：以自身尺寸为步幅做对角传播时，不同矩形的印章轨迹互不重叠。每个矩形产生的印章总数（含原始，仅统计至少有 1 个像素仍在网格内的副本）互不相等。

**规则**：
1. 对每个矩形，以其高度 h 为纵向步幅、宽度 w 为横向步幅，沿右下方向 (h, w) 和左下方向 (h, -w) 重复印章。仅保留至少有一个像素落在网格内的副本（部分出界的副本保留界内部分）。
2. 统计每个矩形的有效印章总数 S（包含原始矩形自身，以及两个方向上所有至少部分在界内的副本）。
3. 按 S 从大到小对矩形排序。若 S 相同（生成约束保证不会发生），按矩形左上角列坐标从小到大排列。
4. 输出一个新网格，高度等于所有矩形中最大的 S 值，宽度等于矩形数量。
5. 输出的第 k 列（从左数第 1 列开始）对应排序后第 k 个矩形：该列从顶部开始填充该矩形的颜色，填充行数等于该矩形的 S 值，其余行为黑(0)。

**关键洞察**：同一个矩形的尺寸同时决定了两件事——印章的步幅（小矩形步幅小、副本密集）和印章的面积——但最终计数还取决于起始位置到边界的距离。需要对比多个示例才能确认柱高代表的是印章总数而非矩形面积或包围盒高度。

## 新题 5：压缩色带指令填充空心框

**组合逻辑**：[压缩 + 连续重复折叠](将色带区域的冗余厚度压缩为颜色序列) → [排序](将空心框按空间位置排序) → [填充 + 空心内部变色](按序列顺序逐一填充框内部)

**来源原语**：压缩(compress, #9 746b3537), 连续重复折叠(dup_collapsed, #9), 色带(color_stripe, #9), 条带方向(stripe_orient, #9), 填充(fill, #10 d5d6de2d), 空心矩形(hollow_rectangle, #10), 边框包围内部(frame_encloses_interior, #10), 空心内部变色(interior_recolor, #10), 排序(sorting, #3 b7999b51)

**依赖链**：色带区域是一个编码了颜色指令的"程序"，压缩后产生长度为 N 的颜色序列；空心框区域包含恰好 N 个框，框的空间排序决定了哪个框获得哪个指令颜色。删除压缩则无法从变厚色带中提取指令序列，删除排序则框与颜色的对应关系不确定。

输入左区为变厚色带（编码颜色指令），右区为空心矩形框；压缩色带得到颜色序列后，按框的空间位置排序，依次用序列颜色填充各框内部。

**输入结构**：网格约 10x20 至 14x24，被一条灰(5)纵向分隔列分为左右两区。左区由全宽水平色带组成（每条色带颜色从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中选取），相邻色带颜色不同，每条色带厚度为 1~4 行不等（同色连续行构成一条色带）。右区黑(0)背景上有若干空心矩形框，框边由栗(9)像素构成（单像素宽边框），框内部为黑(0)。框的数量恰好等于左区压缩后色带的条数。各框大小可不同，互不重叠且不接触。

**规则**：
1. 对左区的色带进行压缩：沿垂直方向扫描，将连续相同颜色的行折叠为一个颜色条目，得到一个从上到下的颜色序列 C1, C2, ..., CN。
2. 在右区识别所有栗(9)边框的空心矩形。
3. 将这些矩形按其边界框左上角的位置排序：先按行坐标从小到大，行坐标相同时按列坐标从小到大。
4. 将排序后的第 k 个矩形的内部（边框内的黑色区域）填充为 Ck 颜色。
5. 输出仅保留右区（不含分隔列和左区）：框的栗(9)边框保留，框内部为填充色，框外为黑(0)。

**关键洞察**：色带的厚度是干扰信息——两行红和五行红编码的指令相同。需要对比多个示例才能发现左区不是按面积或行数对应框，而是压缩后的颜色序列与框的空间顺序一一对应。

## 新题 6：障碍转向路径上的图例锚定展开

**组合逻辑**：[寻路 + 障碍触发转向](沿障碍约束路径行进) → [展开 + 图例锚定对齐](在路径上展开图例串，锚定于标记色位置) → [裁剪](路径超出图例长度的部分不涂色)

**来源原语**：寻路(pathfinding, #12 2dd70a9a), 障碍像素(barrier_pixel, #12), 障碍触发转向(barrier_triggers_turn, #12), 展开(expand, #4 5af49b42), 边缘图例串(edge_legend_string, #4), 图例锚定对齐(legend_anchored_alignment, #4), 颜色位置匹配(color_position_matching, #4)

**依赖链**：寻路决定了展开图例串的方向和轨迹（非简单水平线），图例在路径上弯折展开，锚定点由标记颜色在图例中的位置决定。路径的几何形状直接改变了图例串的空间分布形态，两者不可分离。

标记像素沿障碍约束路径行进，路径轨迹上铺设其匹配的边缘图例串，图例以标记颜色的位置为锚点对齐，在转弯处弯折延续。

**输入结构**：黑(0)背景网格，约 12x12 至 16x16。网格顶部边缘有 1~2 条水平图例串（每条图例由 3~5 个不同颜色的像素从左到右排列，颜色从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中选取）。网格内部散布若干青(8)障碍像素。有 1~2 个孤立标记像素（颜色各异），每个标记像素的颜色恰好出现在某一条图例串中（且在该串中位置唯一）。每个标记像素在某个基本方向（上/下/左/右）上有一条可行路径（直行遇障碍转向，路径长度不小于图例串长度）。

**规则**：
1. 对每个标记像素，找到包含该颜色的唯一图例串，记该颜色在图例串中的位置索引为 p（从 0 开始）。
2. 从标记像素出发，沿初始方向（离标记最近的网格边界的反方向，即朝网格内部行进）直行。遇到青(8)障碍时，转向 90 度（优先右转；若右转也被阻挡则左转）继续行进。
3. 沿路径铺设图例串：以标记像素为锚点（路径的第 0 步），图例串的第 p 个元素放在锚点上，第 p-1 个元素放在路径的前一步位置（若存在），第 p+1 个元素放在路径的下一步位置，以此类推。图例串沿路径弯折——在转弯处改变方向继续铺设。
4. 图例串铺设完毕后即停止，路径的剩余部分不着色。
5. 若图例串在锚点的反方向延伸时超出路径起点（即锚点前面的路径长度不足以容纳图例串中锚点之前的元素），超出部分丢弃。
6. 障碍像素和图例串原始位置保持不变。

**关键洞察**：图例串不再沿直线展开而是沿着转弯路径弯折铺设——相同的图例在不同示例中会呈现 L 形或 Z 形，需要对比多个示例才能理解展开方式是"沿路径而非沿行"。

## 新题 7：双序列桥接差异比较图

**组合逻辑**：[连线 + 访问顺序编码](按两条控制序列分别连桥) → [逐像素比较 + 差异分类着色](两组桥网络逐格比较，交叉位置变色)

**来源原语**：连线(bridge_drawing, #19 3e6067c3), 带框方块(framed_square, #19), 控制序列(control_sequence, #19), 访问顺序编码(visitation_order_encoding, #19), 行列对齐(row_column_alignment, #19), 逐像素比较(pixel_comparison, #1 d47aa2ff), 差异分类着色(diff_class_color, #1 d47aa2ff)

**依赖链**：两条控制序列各自独立驱动一组桥的绘制，生成两个"面板层"；逐像素比较将这两个程序性生成的层合并为一个差异图。比较的输入不是静态区域而是由序列规则动态构建的结构，两步不可分离。

同一组带框方块上按两条不同的控制序列分别绘制红色桥和蓝色桥，两组桥网络逐格比较——仅一色占据保留原色，双色重叠的格子涂为第三色。

**输入结构**：黑(0)背景网格，约 14x14 至 18x18。网格中有 4~6 个带框方块，每个方块为 3x3，外框灰(5)，内部填充色各不相同（从绿(3)、黄(4)、品红(6)、橙(7)、栗(9)中选取）。方块之间有足够的行或列对齐关系使桥可以连接（每对相邻方块至少在行带或列带上对齐）。网格底部有两行控制像素：倒数第 2 行为第一条控制序列（从左到右读取颜色），倒数第 1 行为第二条控制序列。每条序列的长度为方块数量（等于方块个数），包含所有方块的内部填充色各一次（即为一个排列）。两条序列不相同。

**规则**：
1. 按第一条控制序列（倒数第 2 行）的颜色顺序从左到右逐对连接方块：第 1 个颜色对应的方块到第 2 个颜色对应的方块之间画红(2)桥，第 2 到第 3 之间画红(2)桥，以此类推。桥沿行或列方向连接（选择与两方块对齐的行带或列带），宽度为 1 像素，填充方块之间的间隙。若两方块在行和列上均对齐，选距离更短的方向。
2. 按第二条控制序列（倒数第 1 行）做同样操作，画蓝(1)桥。
3. 逐格比较两组桥的占据区域：
   - 仅红桥占据 → 红(2)。
   - 仅蓝桥占据 → 蓝(1)。
   - 红桥与蓝桥均占据 → 黄(4)。
4. 方块本身（含外框和内部填充）保持不变。
5. 两行控制序列在输出中擦除为黑(0)。
6. 桥不覆盖方块——桥仅填充两方块之间的空白间隙。

**关键洞察**：重叠格的颜色不是由任何输入元素的颜色决定，而是由两条控制序列引发的程序性绘制碰撞产生——需要对比多个示例才能归纳出"双桥交叉 → 黄(4)"的比较规则，而非某种位置或顺序规则。

## 新题 8：边界图例编码重力方向与空心框沉积

**组合逻辑**：[编码映射](边界图例的方向编码) → [重力下落 + 碰撞停止](可移动像素按编码方向滑入对应框) → [填充 + 计数](框内沉积像素数决定内部填充色)

**来源原语**：边界图例(border_legend, #8 88e364bc), 编码映射(encoding_map, #8), 颜色关联区域(color_links_to_region, #8), 重力下落(gravity_drop, #8), 碰撞停止(collision_stop, #8), 空心矩形(hollow_rectangle, #10 d5d6de2d), 填充(fill, #10), 计数(counting, #3 b7999b51), 空心内部变色(interior_recolor, #10)

**依赖链**：边界图例编码每个框的重力方向（将方向信息从输入的空间结构中解码出来），重力方向决定像素如何进入框内并堆积，堆积的像素数量再触发一个颜色映射决策。三步形成信息解码→物理模拟→统计决策的紧耦合链。

边界小方块编码每个空心框的重力方向，散落的像素按对应方向滑入框内堆积，框内像素沉积数量决定框的内部背景填充颜色。

**输入结构**：黑(0)背景网格，约 14x14 至 18x18。网格中有 2~4 个空心矩形框（边框颜色各不相同，从蓝(1)、绿(3)、橙(7)、栗(9)中选取，边框单像素宽，内部为黑(0)），每个框尺寸约 4x4 至 6x6。框的四条边中有一条边有一个单像素宽缺口（"入口"）。网格边缘（紧贴上/下/左/右边界）有与框同数量的 3x3 小方块图例，每个图例的填充色与某个框的边框色相同。每个图例的中心像素为灰(5)，另有一个相邻像素也是灰(5)（上/下/左/右之一），其余为图例填充色。中心到该相邻灰像素的方向编码了重力方向。网格中还散布若干黄(4)可移动像素（共 4~10 个），分布在各框外部。

**规则**：
1. 对每个空心框，找到边框色相同的边界图例。读取图例中灰(5)中心像素到灰(5)相邻像素的方向（上/下/左/右），该方向即为此框的"重力方向"。
2. 所有黄(4)像素沿各自最近框的重力方向滑动。"最近框"由黄像素到各框边框的曼哈顿距离最小值确定（距离相等时选边框色编号较小的框）。
3. 黄像素滑入所属框的缺口后，继续沿重力方向滑动直到碰到框的对面内壁或已堆积的黄像素，然后停止。不对准缺口的黄像素无法进入框内，直接删除。
4. 滑动完成后，统计每个框内部的黄(4)像素数量 n：
   - n = 0 → 框内部保持黑(0)。
   - n = 1~2 → 框内部未被黄像素占据的格子填充绿(3)。
   - n = 3~4 → 填充红(2)。
   - n >= 5 → 填充品红(6)。
5. 黄(4)像素保留在其最终堆积位置（不被填充色覆盖）。
6. 框边框、图例和其余背景保持不变。

**关键洞察**：重力方向不是全局统一的——每个框有自己的方向，由其对应图例编码。需要对比多个示例才能发现框内填充色与沉积像素数量的映射关系（而非与框的颜色或大小有关）。

## 新题 9：分隔网格角标投票与镜像补全

**组合逻辑**：[四角同色定区域色](角标颜色投票决定区域是否"激活") → [镜像 + 沿轴反射](激活区域的内容沿网格中轴做镜像补全) → [擦除](未激活区域清空)

**来源原语**：分隔网格(divider_grid, #17 7837ac64), 顶点标记(vertex_marker, #17), 角标一致性(corner_consistency, #17), 四角同色定区域色(corners_set_region, #17), 镜像(mirror, #2 ad3b40cf), 沿轴反射(reflect_along_axis, #2), 擦除(erase, #10 d5d6de2d)

**依赖链**：角标投票决定哪些区域被激活（条件判断），激活的区域成为镜像操作的输入素材，镜像轴由网格的对称结构隐式决定。未通过投票的区域被擦除，其内容不参与镜像。删除投票步骤则所有区域等价（无法确定镜像哪些内容），删除镜像则输出仅是过滤结果而非空间变换。

分隔网格中每个区域的四角有颜色标记，四角同色的区域被"激活"；激活区域的内容沿网格中线做左右镜像填入对称位置的区域，未激活区域清空为背景色。

**输入结构**：网格约 11x11 至 15x15。灰(5)分隔条（单像素宽）将网格分割为偶数列的矩形区域网格（例如 2 行 x 4 列或 3 行 x 2 列的区域阵列）。列数为偶数以保证有中轴。每个区域内部包含由 1~4 个彩色像素组成的小图形（4-连通，不接触分隔条）。每个区域的四个角落（分隔条交叉点的对角位置）各有一个单像素标记，颜色为蓝(1)、红(2)或绿(3)之一。部分区域的四角标记颜色完全相同（"激活"），部分不完全相同（"未激活"）。网格区域列数为偶数，形成左右对称的列配对。激活区域全部位于中轴的同一侧（全在左半或全在右半）。

**规则**：
1. 识别灰(5)分隔条，确定区域网格结构。
2. 对每个区域，检查其四个对角角标像素的颜色是否完全一致。一致则该区域"激活"，否则"未激活"。
3. 未激活区域的内部内容（不含分隔条和角标）全部擦除为黑(0)。角标保留原色。
4. 激活区域的内部内容保留不变。
5. 对每个激活区域，找到其关于网格垂直中轴的镜像对称区域。将激活区域的内部图形做左右翻转后复制到对称区域的内部（覆盖该区域已被擦除的黑色）。
6. 分隔条和所有角标保持不变。若对称区域的角标与被复制的图形位置冲突，角标优先保留。

**关键洞察**：角标投票不仅是过滤机制——它同时隐含了"镜像发生的方向"（所有激活区域在同一侧意味着内容从该侧向另一侧反射）。需要对比多个示例才能理解"四角同色"是激活条件而非着色指令。

## 新题 10：满行列锚定滑动后门结构处标记停止

**组合逻辑**：[滑动 + 同色配对](标记像素向同色满行列条滑动) → [门前停止](滑动在门结构处提前停止) → [擦除 + 无匹配色则删除](清理路径残留和无目标标记)

**来源原语**：滑动(sliding, #7 1a07d186), 同色配对(same_color_pairing, #7), 满行列条(full_span_bar, #7), 碰撞阻挡(collision_blocking, #7), 无匹配色则删除(unmatched_deleted, #7), 门结构(gate_motif, #13 182e5d0f), 门前停止(stop_at_gate, #13), 擦除(erase, #13), 四邻接连通(four_neighbor_connect, #13)

**依赖链**：标记像素的目标是同色满行列条（与 #7 相同），但滑动路径上的门结构会拦截标记使其提前停止（门的拦截逻辑来自 #13）。门结构的存在改变了滑动的终点，而门本身在标记到达后被消耗（擦除门的路径色部分）。滑动规则和门停止规则共同约束最终位置，删除任一规则都无法确定标记的终点。

标记像素向同色满行列条滑动，但路径上若存在门结构（由拦截色构成的横截图案），标记在门前一格停止而非到达满行列条，门结构随即被擦除。

**输入结构**：黑(0)背景网格，约 12x12 至 16x16。网格中有 2~3 条满行列条（每条为贯穿整行或整列的单色线，颜色各不相同，从蓝(1)、红(2)、橙(7)中选取）。散布 3~6 个孤立标记像素，部分颜色与某满行列条匹配，部分不匹配。在某些标记与其目标满行列条之间的路径上，存在"门结构"：由 3 个像素组成的直线段（与路径方向垂直），两端为栗(9)、中间为绿(3)，形成栗-绿-栗图案。门结构跨在标记的滑动路径上（门的绿(3)中心像素在标记和目标满行列条之间的直线路径上）。一个标记的滑动路径上最多有一个门。

**规则**：
1. 对每个标记像素，检查是否存在颜色匹配的满行列条。若不存在，删除该标记（变为黑(0)）。
2. 对有匹配的标记，确定滑动方向（从标记出发沿基本方向朝目标满行列条移动——若满行列条为水平线则标记垂直滑动，反之水平滑动）。
3. 沿滑动方向扫描路径：
   - 若路径上无门结构，标记滑到满行列条边缘相邻的位置停止（与 #7 相同）。
   - 若路径上有门结构（栗(9)-绿(3)-栗(9)横截线），标记滑到门的绿(3)中心像素的前一格停止（即标记最终位置与绿(3)中心之间相隔 0 个像素，标记紧邻绿中心但不重叠）。
4. 标记停止后，若是被门拦截的情况，擦除整个门结构（3 个像素均变为黑(0)）。
5. 满行列条和未被涉及的门结构保持不变。
6. 处理顺序：按标记到目标满行列条的距离从近到远依次处理（距离相同时按标记行坐标从小到大）。已处理的标记的最终位置不阻挡后续标记的滑动路径。

**关键洞察**：门结构是一个条件中断器——只有当标记的滑动路径恰好穿过门的绿色中心时，门才会拦截并自毁。门的朝向（水平或垂直）与路径方向垂直这一点需要对比多个示例才能归纳，否则会误以为门只是普通障碍。
