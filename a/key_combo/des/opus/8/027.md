## 新题 1：射线穿越序定义线段链式换色

**组合逻辑**：[连线/line_drawing] → [射线延伸/ray_extend](创新：射线穿越顺序本身生成置换规则) → [重涂色/recolor + 链式替换/chain_replace](创新：置换规则由射线交叉序动态产生，而非来自静态图例)

**来源原语**：连线 line_drawing (070dd51e), 射线延伸 ray_extend (2f767503), 同色配对 same_color_pairing (070dd51e), 标记条 marker_bar + 控制像素 control_pixel (2f767503), 链式替换 chain_replace (e4888269), 纵线覆盖横线 vertical_over_horizontal_priority (070dd51e)

**依赖链**：同色像素对的位置决定线段的走向和交叉结构；射线方向由控制像素确定，射线与线段的交叉顺序随线段拓扑变化；交叉顺序本身构成循环颜色置换规则，再回头作用于所有线段——线段拓扑→交叉序→置换规则→线段颜色，形成闭环依赖。

将同色像素对连成线段后，以标记条发出的射线穿越线段的先后顺序，生成一个循环颜色置换，应用于全部线段。

**输入结构**：
- 约 18x18 网格，黑(0) 背景。
- 4-6 对同色前景像素标记。每种颜色恰好出现 2 个像素，颜色从 {红(2), 蓝(1), 绿(3), 黄(4), 品红(6), 栗(9)} 中选取。每对像素共享同一行或同一列（不会对角放置）。
- 一根 3 像素长的灰(5) 直线标记条（水平或垂直放置）。一个橙(7) 像素 4-邻接于标记条的中心像素，位于标记条的某一端。
- 生成约束：当按规则步骤 1 画出所有线段后，射线（从标记条中心沿远离橙像素方向延伸至网格边界）至少穿越 2 条线段，但不穿越全部线段（即至少有一条线段不被射线穿越）。各对标记像素互不重叠、互不与标记条/控制像素重叠。

**规则**：
1. 对每一对同色像素，画出连接它们的轴对齐线段（含两端点）。若两条线段在某像素重叠，垂直方向的线段覆盖水平方向的线段（即交叉点显示垂直线段的颜色）。
2. 确定射线方向：从标记条中心像素出发，沿远离橙(7) 控制像素的方向延伸一条直线至网格边界。例如橙像素在标记条中心的左侧，则射线向右延伸。
3. 找出射线经过的所有像素位置。若某条线段至少有一个像素落在射线路径上，则该线段被射线"穿越"。
4. 按射线首次接触各线段的距离（距标记条中心的步数），从近到远排列所有被穿越的线段，得到有序序列 [S1, S2, ..., Sk]。
5. 该序列定义一个循环颜色置换：S1 的颜色映射到 S2 的颜色，S2 的颜色映射到 S3 的颜色，...，Sk 的颜色映射到 S1 的颜色。
6. 将此循环置换应用于网格上**所有线段**的像素（包括被穿越和未被穿越的）。若某线段的颜色不在置换映射中（即该线段未被穿越、其颜色也不等于任何被穿越线段的颜色），则该线段颜色不变。
7. 擦除灰(5) 标记条和橙(7) 控制像素（设为黑(0)）。
8. 原始标记像素对保留在原位（已被线段覆盖的情况下，颜色随线段一起变化）。背景像素不变。

**关键洞察**：射线并不擦除或高亮线段，而是用穿越顺序构造出一个循环颜色置换规则，再全局应用。不同的射线方向会产生不同的穿越序列，从而生成完全不同的置换——改变控制像素的位置就会改变所有线段的最终颜色。

## 新题 2：对称性筛选精灵体并按位置配对填入空区域

**组合逻辑**：[裁剪/crop + 筛选/filter](对称性判据) → [排序/sort](位置排序) → [印章覆盖/stamp](配对填入) → [洪泛填充/flood_fill](剩余空区域的兜底处理)

**来源原语**：裁剪 crop + 对称性筛选 symmetry_filter + 忽略干扰项 ignore_distractors (72ca375d), 印章覆盖 stamp (3e980e27), 位置排序 positional_ordering + 洪泛填充 flood_fill + 封闭区域 bounded_region + 分隔线 divider_line (941d9a10)

**依赖链**：对称性筛选决定存活精灵体的数量，数量直接改变位置排序的配对映射（第 k 个精灵体→第 k 个空区域），进而决定哪些区域被填入精灵体、哪些区域被洪泛填充。删除筛选环节则精灵体数量不匹配空区域，删除排序环节则配对关系不确定，删除洪泛填充则剩余区域无处理。

按对称性筛选精灵体后，将存活的精灵体按位置顺序配对填入空白区域，多余空区域洪泛填充标记色。

**输入结构**：
- 约 20x20 网格，黑(0) 背景。
- 灰(5) 分隔线（整行或整列贯穿网格）将网格划分为 4-6 个矩形区域。
- 部分区域内各含一个单色 4-连通精灵体（3-8 像素，具体形状因示例而异），颜色从 {红(2), 蓝(1), 绿(3), 黄(4), 品红(6), 栗(9)} 中选取，每个精灵体颜色不同。
- 其余区域为空（仅含黑(0) 背景）。
- 精灵体总数多于空区域数。其中一部分精灵体具有至少一种对称性（垂直反射、水平反射或 180 度旋转对称），另一部分不具有任何对称性。
- 生成约束：具有对称性的精灵体数量恰好等于空区域数量。每个精灵体的包围框严格小于其所在区域的内部尺寸和所有空区域的内部尺寸（保证能放入任一空区域）。

**规则**：
1. 将每个精灵体裁剪至其包围框，检测其是否具有垂直反射对称、水平反射对称或 180 度旋转对称中的至少一种。通过任一检测的精灵体标记为"存活"，全部未通过的标记为"淘汰"。
2. 擦除所有"淘汰"精灵体（像素设为黑(0)）。
3. 将所有"存活"精灵体按其包围框左上角坐标排序：先按行升序，行相同则按列升序（行主序）。
4. 将所有空区域按其内部左上角坐标排序：先按行升序，行相同则按列升序（行主序）。
5. 将第 k 个存活精灵体配对到第 k 个空区域（k = 1, 2, ...）。
6. 在每个配对的空区域内，将精灵体居中放置（水平和垂直方向均取中心对齐；若无法像素精确居中，向上、向左各偏移半像素，即取 floor）。精灵体保留原色。
7. 擦除所有存活精灵体在原区域中的副本（设为黑(0)）。印章副本保留在目标区域。
8. 灰(5) 分隔线不变。

**关键洞察**：对称性筛选改变的是存活数量而非颜色或位置，而存活数量通过位置排序间接决定了每个精灵体的目的地——增加或减少一个对称精灵体，所有配对关系都会全局重排。

## 新题 3：帧序列外推与包围框包含淘汰

**组合逻辑**：[外推/extrapolate + 匀速运动/constant_motion](多对象独立运动) → [包围框包含/bbox_containment + 擦除/erase](创新：包含关系在输入帧中不存在，仅在外推帧中涌现)

**来源原语**：外推 extrapolate + 帧序列 frame_sequence + 匀速运动延续 constant_motion (ba1aa698), 包围框包含 bbox_containment + 异色包含则删 delete_if_contained_by_other_color + 擦除 erase + 连通分量 connected_component (9720b24f)

**依赖链**：每个对象的独立运动速度决定外推位置，所有对象的外推位置共同决定包围框包含关系，包含关系决定哪些对象被擦除。在输入的三帧中包含关系不成立（生成约束），所以求解者必须先完成外推再检查包含——不能通过观察输入帧直接得出结论。

将帧序列中多个独立运动的对象外推至下一帧，然后淘汰包围框被另一异色对象完全包含的对象。

**输入结构**：
- 网格约 8 行 x 30 列，由 3 个等宽帧面板沿水平方向排列，相邻面板共享 1 列灰(5) 边框。每个面板外围均为灰(5) 边框（1 像素宽），内部填充黑(0)。
- 每个面板内含 2-3 个小型单色 4-连通对象（每个 2-5 像素），颜色从 {红(2), 蓝(1), 绿(3), 黄(4), 橙(7)} 中选取，每种颜色在每帧中恰好出现一个对象，形状在帧间保持不变。
- 同一颜色的对象在相邻帧之间的位置偏移 (delta_row, delta_col) 恒定（即匀速运动）。不同颜色对象的偏移量可以不同。
- 生成约束：在输入的 3 个帧中，任何两个不同颜色对象的包围框之间**不存在**严格包含关系（即不存在 A 的包围框四条边都严格在 B 的包围框内侧的情况）。但在按规则外推的第 4 帧中，至少出现一组严格包含关系。

**规则**：
1. 按颜色识别跨帧对象（每种颜色在每帧出现一次，形状不变）。
2. 对每个对象，计算其包围框左上角在相邻帧间的位移 (delta_row, delta_col)。此位移在帧 1→2 和帧 2→3 之间相同。
3. 构建输出帧：与单个面板相同的尺寸，灰(5) 边框，黑(0) 内部。
4. 对每个对象，将其帧 3 位置加上 (delta_row, delta_col) 得到外推位置。因输出是独立面板（非共享边框），水平方向上以完整面板宽度为基准推进（与 ba1aa698 相同的独立面板偏移规则）。
5. 将所有对象放置到外推位置。
6. 计算所有已放置对象的包围框。若对象 A 的包围框严格包含于对象 B 的包围框内（A.min_row > B.min_row 且 A.max_row < B.max_row 且 A.min_col > B.min_col 且 A.max_col < B.max_col）且 A、B 颜色不同，则擦除对象 A（所有像素设为黑(0)）。
7. 对所有满足包含条件的对象同时执行擦除（一轮判定：不因擦除某对象而改变其他对象的包含关系）。包含其他对象的"容器"对象保留完整。
8. 输出单个面板。

**关键洞察**：运动外推本身是逐对象独立的，但包含判定是全局同时的——求解者必须先预测所有对象的未来位置，再检查它们之间的空间包含关系。包含关系在输入帧中从未出现，仅在外推帧中因速度差异而涌现。

## 新题 4：障碍轮廓环上的竞争生长

**组合逻辑**：[轮廓描边/outline_trace](创新：轮廓不用于描边输出，而用作一维生长轨道) → [生长/grow + 交替变色/alternating_color](创新：沿轮廓环而非二维平面生长) → [面积分级/area_ranking](创新：面积不决定颜色，而决定碰撞优先级)

**来源原语**：轮廓描边 outline_trace + 外侧相邻 outer_adjacent (aa62e3f4), 生长 grow + 交替变色 alternating_color + 相邻间隔 adjacent_gap (af726779), 面积分级 area_ranking + 连通分量 connected_component (e8593010), 轮廓邻接 contour_adjacency + 障碍轮廓 obstacle_contour (97c75046)

**依赖链**：障碍的形状决定轮廓环的拓扑（一维闭合路径）；种子在轮廓环上的位置决定各方向上的可达空间；生长速度相同但碰撞优先级由种子面积排名决定——一个种子的面积排名影响的不只是它自己的边界，还会传递性地改变其他种子对的碰撞结果。

多个种子沿障碍外轮廓环向两个方向生长，碰撞时面积更大的种子吞并争议像素。

**输入结构**：
- 约 15x15 网格，黑(0) 背景。
- 一个大型不规则灰(5) 障碍（8-连通，约 20-40 像素）。障碍无孔洞，外轮廓形成单一闭合环路。
- 2-4 个"种子"分量：小型单色 4-连通分量（每个 1-3 像素），4-邻接于障碍边界。每个种子颜色不同，从 {红(2), 蓝(1), 绿(3), 黄(4)} 中选取。
- 各种子沿轮廓间隔放置，不相邻。
- 生成约束：所有种子的面积（像素数）两两不同。障碍外轮廓上的背景像素数量足够容纳所有种子的双向生长（即轮廓环长度 > 种子数 x 2）。

**规则**：
1. 计算障碍的外轮廓环：所有 4-邻接于至少一个灰(5) 障碍像素的黑(0) 背景像素的集合。按 4-连通顺序将其排列为一条闭合环路（从轮廓上最左上方的像素出发，沿顺时针方向排列）。
2. 每个种子"认领"轮廓环上与自身 4-邻接的所有像素，涂为该种子的颜色。若种子像素本身在轮廓环上，也计入。
3. 生长按离散轮回推进。每轮中，每个种子的领地沿轮廓环的两个方向各扩展一步（即领地边界的相邻未认领轮廓像素被涂为该种子颜色）。
4. 当两个种子的领地同时扩展到同一个轮廓像素时（碰撞），该像素归属于原始输入中 4-连通面积更大的种子。
5. 生长持续到轮廓环上所有像素均被认领。
6. 障碍像素（灰(5)）和不在轮廓环上的背景像素保持不变。种子的原始像素（若不在轮廓环上）保持原色。

**关键洞察**：生长并非在二维平面扩散，而是沿轮廓环的一维闭合路径推进——两个种子在欧氏距离上很近但在轮廓路径上很远时，碰撞位置与直觉相反。面积排名是需要对比多个示例才能归纳的隐蔽规则：单看一个示例，碰撞结果可能恰好与位置顺序一致。

## 新题 5：双掩码按分量面积合并后重新分级涂色

**组合逻辑**：[压缩/compress + 逐格比较/cell_comparison](创新：冲突像素的胜出者不由固定规则决定，而由各自所属分量的面积比较决定) → [连通分量/connected_component + 面积分级/area_ranking + 重涂色/recolor](创新：面积概念被使用两次——先用于合并决策，再用于结果分级涂色，且两次的面积值不同)

**来源原语**：压缩 compress + 逐格比较 cell_comparison + 堆叠掩码 stacked_mask (fafffa47), 连通分量 connected_component + 面积分级 area_ranking + 面积决定颜色 area_determines_color + 重涂色 recolor (e8593010)

**依赖链**：逐格比较时，冲突像素需追溯各自在源半区的母分量面积才能决定胜出者——一个像素的输出不只取决于自身位置的两个值，还取决于该像素所在分量的全局面积。合并后分量拓扑发生变化（可能合并或碎裂），产生新的面积，新面积再决定最终颜色。面积在两个阶段被以不同方式使用，形成不可跳步的双层依赖。

将上下两半网格按面积优先规则逐像素合并为一层，再按合并后新分量的面积重新涂色。

**输入结构**：
- 网格约 11 行 x 7 列。中间第 5 行为灰(5) 水平分隔线。
- 上半区（行 0-4）和下半区（行 6-10）尺寸相同（5x7），均以黄(4) 为背景色。
- 每个半区含 2-4 个前景 4-连通分量，颜色从 {红(2), 蓝(1), 绿(3), 品红(6)} 中选取。每个分量 2-6 像素。
- 至少部分前景像素在上下半区的对应位置（相同行偏移和列）同时存在前景色（即存在冲突位置）。
- 生成约束：同一半区内任意两个分量的面积（像素数）两两不同。

**规则**：
1. 将网格分为上半区和下半区（去除灰(5) 分隔行）。
2. 逐像素比较（相同行偏移、相同列）：
   - 两侧均为黄(4) 背景 → 输出黄(4)。
   - 恰好一侧为前景 → 输出该侧前景色。
   - 两侧均为前景 → 分别找到该像素在各自半区所属的 4-连通分量，比较两个分量的面积（像素总数），输出面积更大的分量的颜色。
3. 合并完成后，在输出网格（尺寸同一个半区）中识别所有 4-连通分量。
4. 按输出分量的面积重新涂色：面积 1-2 → 绿(3)，面积 3-4 → 红(2)，面积 5 及以上 → 蓝(1)。
5. 黄(4) 背景像素不受重涂色影响。

**关键洞察**：单个冲突像素的胜出结果取决于远处像素（母分量的其他像素），而非仅取决于该位置本身——改变一个分量边缘的一个像素就可能改变其面积，进而翻转多个冲突位置的胜负。合并后分量拓扑变化又会产生与输入完全不同的面积分布，使得最终涂色无法从输入直接推断。

## 新题 6：面积排序的重力堆叠

**组合逻辑**：[排序/sort + 面积分级/area_ranking](创新：面积决定处理顺序，而非颜色) → [滑动/slide](创新：滑动方向统一为向下，但终止条件依赖先前已落位的分量) → [障碍轮廓/obstacle_contour](创新：障碍不用于路径引导，而用作承接面)

**来源原语**：排序 sort + 位置排序 positional_ordering (941d9a10), 滑动 slide + 障碍轮廓 obstacle_contour (97c75046), 面积分级 area_ranking + 连通分量 connected_component (e8593010), 轮廓邻接 contour_adjacency (97c75046)

**依赖链**：面积排序决定落下顺序；先落下的分量改变后续分量的障碍环境（变成新的"地面"），使得每个分量的最终位置都依赖于所有更小分量的最终位置。改变任一分量的面积可能改变排序，从而导致全局重新堆叠。

按面积从小到大将分量依次向下滑落，叠放于不规则障碍之上。

**输入结构**：
- 约 15x15 网格，黑(0) 背景。
- 一个大型不规则灰(5) 障碍位于网格下半部，上表面凹凸不平（非水平直线）。障碍 8-连通，约 15-30 像素。
- 3-5 个小型单色 4-连通前景分量（每个 2-5 像素）分布在障碍上方，与障碍之间有若干行黑(0) 间隔。每个分量颜色不同，从 {红(2), 蓝(1), 绿(3), 黄(4), 橙(7)} 中选取。
- 生成约束：每个分量的所有像素都严格位于障碍最高点的上方。所有分量的面积两两不同。每个分量在水平投影上至少部分覆盖障碍的上表面（即向下滑动不会落出网格）。分量之间的水平投影可以重叠也可以不重叠。

**规则**：
1. 找出所有前景 4-连通分量，计算各自的面积。
2. 按面积升序排列（最小先处理）。
3. 按排列顺序逐个处理每个分量：
   a. 将该分量整体逐行向下平移（每次下移 1 行，保持形状和水平位置不变）。
   b. 当下一步平移会导致该分量的任一像素与灰(5) 障碍像素或任何先前已落位分量的像素重叠时，停止平移。分量停留在最后一个不产生重叠的位置。
   c. 若分量向下平移到达网格底部边界（再下移会超出网格），也停止。
4. 所有分量处理完毕后，输出最终网格。障碍和背景像素保持不变。

**关键洞察**：面积最小的分量先落下，占据障碍上表面的凹槽或缝隙，成为后续分量的"地面"延伸。若处理顺序反转（大的先落），堆叠结构完全不同——排序规则是需要对比多个示例才能归纳的隐蔽参数。

## 新题 7：面板叠加与图例链式换色交叉区域

**组合逻辑**：[透明叠加/transparent_overlay + 对齐/alignment](创新：叠加不是取并集或交集标记，而是区分三类像素各有不同处理) → [链式替换/chain_replace + 图例行序/legend_row_order](创新：链式替换仅作用于叠加交叉像素，非交叉像素透传)

**来源原语**：透明叠加 transparent_overlay + 面板 panel + 分隔列 separator_col + 对齐 alignment (e133d23d), 链式替换 chain_replace + 双列图例 two_col_legend + 图例行序决定替换 legend_row_order (e4888269)

**依赖链**：面板叠加决定哪些像素属于"交叉区域"——这些像素成为链式替换的作用目标；链式替换的输入颜色来自左面板的前景色，替换规则来自图例的行序。图例的存在价值仅体现在交叉像素上：若无交叉像素，图例无效；若无图例，交叉像素无法确定输出颜色。

将左右面板叠加，仅交叉位置（双方均有前景）的像素按图例链式替换颜色，非交叉前景直接保留。

**输入结构**：
- 网格约 10 行 x 17 列，黑(0) 背景。
- 第 0 行为图例行：包含 2-3 对水平相邻的彩色像素，每对之间隔 1 个黑(0) 像素。每对的左像素为"源颜色"，右像素为"目标颜色"，从左到右依次排列构成替换链。图例颜色从 {红(2), 蓝(1), 绿(3), 黄(4), 橙(7), 品红(6)} 中选取。链式约束：某一对的右列颜色可以出现在另一对的左列中，形成级联替换。
- 第 1 行为水平灰(5) 分隔线，贯穿整行。
- 第 2 行至末行为主区域，被正中间的一条垂直灰(5) 分隔列分为左面板和右面板，两面板宽度相同。
- 每个面板以黑(0) 为背景，包含若干前景像素/对象，颜色出现在图例的左列中。
- 生成约束：至少存在 3 个对应位置（相同行、相同列偏移），双面板均有前景像素。

**规则**：
1. 移除图例行、灰(5) 分隔行和灰(5) 分隔列。
2. 将左面板和右面板按相对位置逐像素对齐。
3. 对每个对齐位置分类处理：
   a. 两面板均为黑(0) 背景 → 输出黑(0)。
   b. 恰好一个面板有前景像素 → 输出该前景色，不做替换。
   c. 两面板均有前景像素（交叉位置） → 取**左面板**该位置的前景色作为起始色，然后从图例第一对开始依次扫描：若当前色等于该对左列颜色，替换为该对右列颜色，继续扫描后续对（即在同一次处理中，被替换后的新色可以再被后续对替换）。输出最终色。
4. 输出网格尺寸等于单个面板的尺寸。

**关键洞察**：图例的链式替换仅在双面板交叉位置生效——移动任一面板中的一个前景像素，可能使某个位置从"单侧前景"变为"交叉"或反之，从而决定该像素是否经历链式替换。图例行序是隐蔽参数：交换两对的顺序会产生不同的最终颜色。

## 新题 8：框架内模板定义外部精灵归属与点数表示

**组合逻辑**：[模板匹配/template_matching + 含旋转反射/includes_rotation_reflection](创新：模板不是独立给出的参考图案，而是嵌入在框架内部，同时充当视觉元素和分类键) → [计数/counting + 同色匹配/same_color_matching](双重匹配条件：颜色一致且形状一致) → [绘点/draw_dots](计数结果可视化) → [擦除/erase]

**来源原语**：模板匹配 template_matching + 含旋转反射变换 includes_rotation_reflection + 形状匹配 shape_matching + 非重叠放置 non_overlapping_placement (50f325b5), 空心框架 hollow_frame + 计数 counting + 绘点 draw_dots + 同色匹配 same_color_matching + 计数映射点数 count_maps_to_dots + 擦除 erase + 图案精灵体 pattern_sprite (8f215267)

**依赖链**：框架内部的灰色模板是分类键——它决定哪些外部精灵"属于"该框架（必须同时满足颜色匹配和形状匹配）；匹配数量决定框架内绘制的点数；绘点前必须擦除模板和外部精灵。三者缺一不可：没有模板则无法分类，没有计数则无法确定点数，没有擦除则模板干扰点的放置。

框架内嵌的小型灰色模板作为"钥匙"，匹配外部同色且同形的精灵体，匹配数以点的形式显示在框架内。

**输入结构**：
- 约 18x18 网格，黑(0) 背景。
- 2-4 个空心矩形框架，每个框架由单一颜色的 1 像素宽边框构成，内部为黑(0)。框架颜色各不相同，从 {红(2), 蓝(1), 绿(3), 橙(7)} 中选取。每个框架外部尺寸至少 5x5。
- 每个框架的内部左上角区域放置一个小型灰(5) 模板图案（2-3 个 4-连通像素，形状因框架而异，如 L 形、直线、对角线等结构性描述——不同示例中具体形状不同）。
- 框架外部散布着若干小型单色 4-连通精灵体（每个 2-4 像素）。每个精灵体的颜色等于某个框架的颜色。
- 生成约束：每个外部精灵的形状（归一化到包围框的二值掩码）在所有旋转和反射变体下，恰好匹配且仅匹配一个框架的内部灰色模板。每个模板至少被 1 个同色外部精灵匹配。

**规则**：
1. 提取每个框架内部的灰(5) 模板：裁剪为包围框内的二值掩码。
2. 对每个外部精灵体，检查其是否与某框架关联：
   a. 颜色条件：精灵体颜色必须等于框架边框颜色。
   b. 形状条件：将精灵体裁剪至包围框的二值掩码，与该框架内部模板的掩码进行比较，允许 8 种变体（0/90/180/270 度旋转 x 是否水平翻转）。任一变体匹配即通过。
   c. 颜色和形状均满足时，该精灵体归属于该框架。
3. 对每个框架，统计归属于它的外部精灵体数量 N。
4. 擦除所有外部精灵体（设为黑(0)）。
5. 擦除每个框架内部的灰(5) 模板（设为黑(0)）。
6. 在每个框架的内部，沿水平中心行（内部区域行数的中间行，若为偶数取上方的一行）绘制 N 个点：使用该框架的边框颜色，从内部最右列开始向左放置，相邻点之间间隔 1 个黑(0) 像素（即每隔一列放一个点）。若 N = 0，内部保持全黑。
7. 框架边框保持不变。

**关键洞察**：仅凭颜色匹配会产生错误计数——每个框架内隐藏的灰色模板才是真正的分类依据。精灵体必须同时满足颜色和旋转/反射形状匹配才被归类，单独检查任一条件都不充分。模板在框架内部的位置使其看起来像装饰元素，但它实际上编码了匹配规则。
