## 新题 1：弯折点精灵印章

**组合逻辑**：[连线/line_drawing](已有) → [弯折点提取](创新：路由弯折点成为印章目标位) → [锚点对齐/anchor_alignment + 印章覆盖/stamp](已有原语的创新组合：精灵体按锚点对齐到弯折点)

**来源原语**：连线/line_drawing、经由中间点路由/routed_via_waypoint、先横后纵路由/horizontal_then_vertical（来自 0e671a1a）；印章覆盖/stamp、邻域模板/neighborhood_template（来自 39e1d7f9）；锚点对齐/anchor_alignment、多色精灵体/multicolor_sprite、源锚点/source_anchor_marker（来自 2c737e39）

**依赖链**：航点位置决定路由几何形状 → 路由弯折点是中间产物，不存在于输入中 → 弯折点位置成为精灵印章的锚点目标 → 精灵体的锚点像素对齐到每个弯折点。删除路由步骤则无法确定印章位置；删除印章步骤则路由线无法解释输出中出现的精灵体副本。

将多色精灵体沿航点间曼哈顿路由的每个弯折位置印章一份，锚点对齐到弯折点。

**输入结构**：黑(0)背景网格，约 15x15。网格中有一个多色 4-连通小图形（4~6 像素，形状因示例而异），其中恰好有一个灰(5)像素作为锚点，其余像素为 2~3 种非黑非灰颜色。网格中另有 3~4 个单独的彩色标记像素作为航点：一个红(2)、一个黄(4)、一个绿(3)，它们互不相邻且不与精灵体相邻。生成约束：各航点位置保证任意相邻航点不共行且不共列（确保每段路由恰好有一个弯折点）；精灵体印章在各弯折点处不会互相重叠且不超出网格边界。

**规则**：
1. 按红(2)→黄(4)→绿(3)的顺序，对每对相邻航点执行曼哈顿路由：先沿水平方向移动到目标列，再沿垂直方向移动到目标行。路由经过的背景像素绘制为灰(5)；已有非背景像素（航点、精灵体）不被覆盖。
2. 每段路由恰好在水平段与垂直段的转折处产生一个弯折点。提取所有弯折点的坐标。
3. 对每个弯折点，将精灵体以其灰(5)锚点对齐到该弯折点坐标，印章精灵体的所有非灰像素。印章像素覆盖该位置的路由灰线和背景，但不覆盖航点标记像素。
4. 原始精灵体保留在原位不动。航点标记像素保留。

**关键洞察**：弯折点既不是输入中的标记也不是预定义位置——它们是路由算法的几何副产物。改变任何一个航点的位置会改变弯折点坐标，从而改变精灵体出现的位置；需要对比多个示例才能确认路由方向约定（先横后纵）和弯折点作为印章目标的规则。

## 新题 2：连通分量面积索引同心方环

**组合逻辑**：[面积计算/area_comparison](已有) → [面积→切比雪夫距离映射](创新：面积数值转化为空间坐标) → [同心方环填充/concentric_ring + fill](已有) ＋ [多像素涂色留单/multi_recolor_single](已有，创新用法：单像素分量保留原位且涂中心)

**来源原语**：重涂色/recolor、连通分量/connected_component、面积比较/area_comparison、多像素涂色留单/multi_recolor_single（来自 67385a82）；填充/fill、同心方环/concentric_ring、距离映射/distance_mapping、切比雪夫距离/chebyshev_distance、中心对齐/center_aligned（来自 ac0c2ac3）

**依赖链**：连通分量的拓扑结构决定面积 → 面积数值成为环距离索引 → 距离索引决定在输出中涂哪个方环 → 分量颜色决定该环的填充色。单像素分量走特殊路径：保留原位且额外填充中心格。删除面积计算则无法知道涂哪个环；删除环填充则面积信息无处体现。

将散布在奇数方阵上的各色连通分量擦除，按每个分量的面积值填充对应距离的同心方环，单像素分量保留原位并额外填充中心格。

**输入结构**：一个奇数边长的正方形网格（11x11 或 13x13），黑(0)背景。网格上散布 3~5 个单色 4-连通分量，每个分量颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取），面积互不相同（取值范围 1~5 像素）。各分量互不相邻（8-连通意义下不接触）。网格中心格为黑(0)背景。生成约束：所有面积值不超过 (边长-1)/2（保证对应方环完全在网格内）；不同分量面积两两不同。

**规则**：
1. 对每个面积大于 1 的连通分量：擦除其原始位置（恢复为黑(0)背景），然后将中心格的切比雪夫距离等于该分量面积的所有格子填充为该分量的颜色。即面积为 A 的分量填充距离中心恰好 A 的方环。
2. 对每个面积恰好为 1 的单像素分量：保留该像素在原始位置不动，同时将网格正中心格填充为该分量的颜色。
3. 若多个单像素分量存在，中心格取距离网格中心曼哈顿距离最近的那个单像素分量的颜色（生成时保证不出现等距平局）。
4. 各方环独立绘制，不同环之间不重叠（因为面积值互不相同）。环仅覆盖背景像素和已擦除位置，不覆盖保留的单像素分量。

**关键洞察**：分量的面积——一个数量属性——被重新解释为空间坐标（方环距离），而分量的原始空间位置对输出完全无关。单像素分量的特殊待遇（保留且涂中心）需要对比多个示例中有无单像素分量时输出的中心格差异才能归纳。

## 新题 3：象限旋转后前景并集叠加

**组合逻辑**：[标记所在象限选择/marker_quadrant_retained](已有) → [旋转/rotate](已有，创新用法：仅旋转单个象限而非整图) → [透明叠加/transparent_overlay + 并集合并/union_merge](已有，创新用法：叠加对象是旋转后的象限与对角象限)

**来源原语**：旋转/rotate、整体旋转/whole_grid_rotate（来自 ed36ccf7）；透明叠加/transparent_overlay、并集合并/union_merge、分隔行/separator_row、前景掩码/foreground_mask、逐格对齐/cell_aligned（来自 ce4f8723）；裁剪/crop、分隔十字/separator_cross、标记像素/marker_pixel、象限/quadrant、标记所在象限保留/marker_quadrant_retained（来自 2dc579da）

**依赖链**：标记像素位置 → 选定源象限 → 源象限被旋转90度 → 旋转改变了前景像素的空间布局 → 旋转结果与对角象限做前景并集 → 并集中哪些格子是前景取决于旋转后的几何。删除旋转步骤则叠加变为平凡复制；删除叠加步骤则旋转结果没有合并目标。

选出标记所在象限并逆时针旋转 90 度，与对角象限做前景并集叠加，输出单个象限大小的合并结果。

**输入结构**：一个偶数边长的正方形网格（如 12x12 或 14x14），由一种单色（如灰(5)）的十字分隔线（一整行 + 一整列）分成四个等大的矩形象限。每个象限内有若干前景像素（各象限的前景色不同，从蓝(1)、红(2)、绿(3)、黄(4)中选取），背景为黑(0)。恰好一个象限中含有一个品红(6)标记像素，该标记像素位于前景像素之间的背景位置。生成约束：标记所在象限与其对角象限的前景图案不完全相同（保证叠加结果非平凡）；前景像素占每个象限面积的 20%~40%。

**规则**：
1. 找到品红(6)标记像素所在的象限，记为源象限 S。确定其对角象限 D（如 S 在左上则 D 在右下）。
2. 提取 S 的内容（不含分隔线），将品红标记像素视为背景，然后将整个象限内容逆时针旋转 90 度。
3. 提取 D 的内容（不含分隔线）。
4. 将旋转后的 S 与 D 逐格对齐。对于每个格子：若 S 旋转后为前景或 D 为前景，则输出为绿(3)；仅当两者均为背景时，输出为黑(0)。
5. 输出为单个象限大小的网格（去除分隔线），不含其他两个象限。

**关键洞察**：旋转在叠加之前改变了源象限的几何排列，使得并集结果既不等于 S 也不等于 D，而是依赖于旋转方向。需要对比多个示例才能确认旋转方向（逆时针 90 度）以及目标总是对角象限而非相邻象限。

## 新题 4：格子行键色控制填充色与交叉混合

**组合逻辑**：[标记像素共行/列连线填充](已有，来自 e760a62e) ＋ [行首控制像素决定填充色](已有，来自 c9f8e694，创新用法：控制色替代标记色作为填充色) → [双色交叉混合/intersect_blend_color](已有，创新用法：混合的不是标记色而是控制色)

**来源原语**：填充/fill、格子单元/lattice_cell、标记像素/marker_pixel、网格线/lattice_line、共行或共列/shared_row_col、双色交叉混合色/intersect_blend_color（来自 e760a62e）；重涂色/recolor、占位像素/placeholder_pixel、控制像素/control_pixel、同行对应/same_row_mapping、行首色决定填色/row_key_color（来自 c9f8e694）

**依赖链**：标记像素的颜色和位置 → 决定哪些格子行/列需要填充（几何信息）；控制像素的颜色 → 决定填充用什么颜色（色彩信息）；当两组填充区域在同一格子交叉时 → 需要混合规则。三条信息流在每个输出格子汇聚。删除标记则无法确定填充区域；删除控制像素则无法确定填充颜色；删除混合规则则交叉格子颜色不确定。

在格子网格中，标记像素的颜色决定哪些行列需要贯通填充，而每行首列的控制像素决定填充的实际颜色，行列交叉处使用品红混合色。

**输入结构**：一个约 15x18 的网格，由青(8)网格线划分为约 4x5 的矩形格子阵列（每个格子内部约 2x2 或 3x3 像素）。部分格子内含有一个红(2)或绿(3)标记像素（位于格子中心）。对于每个包含标记像素的格子行，该行最左侧格子内有一个"控制像素"，颜色为蓝(1)、黄(4)或橙(7)中的一种（不与标记色相同）。同一格子行内所有标记像素颜色相同（全红或全绿）。生成约束：至少有一个格子行含红标记、至少一个含绿标记；至少有一列同时出现红标记行和绿标记行的格子（保证存在交叉）。控制像素所在的最左格子不含红/绿标记。

**规则**：
1. 对每种标记色（红、绿）分别处理：找出所有含该色标记的格子行，对每行将最左标记所在格子到最右标记所在格子之间的所有格子标记为"行填充区"。同理找出所有含该色标记的格子列，对每列将最上标记到最下标记之间的所有格子标记为"列填充区"。
2. 对每个被标记为填充区的格子：其填充颜色不取标记的红/绿色，而取该格子所在格子行的最左格子中控制像素的颜色。若该格子行无控制像素（该行本身无标记，但因列填充延伸到此行），则取该列中最近的有控制像素的行的控制色（按格子行距离，先上后下）。
3. 若同一个格子同时属于"红标记源"填充区和"绿标记源"填充区（即行列交叉），则该格子填充品红(6)，无论控制像素如何。
4. 填充时整个格子内部全部涂色，保留青(8)网格线不变。原始标记像素和控制像素被填充色覆盖。

**关键洞察**：标记颜色决定的是空间几何（哪些行列贯通），不是输出颜色；输出颜色由一个完全独立的控制像素系统决定。需要对比多个示例才能发现"标记色管几何、控制色管颜色"的分离，以及交叉格子的品红规则独立于控制色。

## 新题 5：射线穿越引导线计数驱动垂直平移

**组合逻辑**：[射线延伸/ray_extend](已有) → [穿越计数](创新：射线穿越引导线的次数替代面积作为位移量) → [平移/translate](已有，创新条件：位移=穿越数而非面积)

**来源原语**：射线延伸/ray_extend、引导线/guide_line、投射到引导线/projection_to_guide（来自 ac3e2b04）；平移/translate、全宽条纹/full_width_stripe、位移等于面积/shift_equals_area（来自 b2bc3ffd，创新为"位移等于穿越数"）

**依赖链**：每个对象内的灰像素位置 → 决定射线路径 → 射线穿越引导线的次数依赖于对象与引导线的空间关系 → 穿越次数成为该对象的垂直位移量 → 对象向上平移。删除射线步骤则无法获得穿越数；删除平移步骤则穿越数无处使用。同一对象在引导线增减后位移量会改变——位移是外部空间关系的函数而非对象自身属性。

从每个对象的灰像素向下发射射线，计算穿越水平引导线的次数，将对象整体向上平移该次数个格子。

**输入结构**：一个约 12x15 的网格，黑(0)背景。网格中有 2~4 条全宽水平红(2)引导线，均匀或不均匀分布。底部有一条全宽黄(4)条纹作为固定基线。在黄条纹上方、引导线之间或之上，散布 3~4 个小型单色 4-连通对象（每个 3~6 像素，颜色互不相同，取自蓝(1)、绿(3)、橙(7)、栗(9)）。每个对象内恰好有一个像素被替换为灰(5)——该像素是射线发射点，其余像素保持对象颜色。生成约束：各对象向上平移后不超出网格顶部、不互相重叠、不与引导线重叠；对象初始位置不与引导线重叠。

**规则**：
1. 对每个对象，从其灰(5)像素的位置向下（行号增大方向）发射一条垂直射线，直到到达黄(4)条纹。
2. 计算该射线穿越的红(2)引导线数量（射线经过的红色像素所在的不同行数），记为 C。
3. 将整个对象（包括其灰像素）向上平移 C 个像素（行号减少 C）。擦除对象原始位置。
4. 红(2)引导线和黄(4)条纹保持不变。
5. 从每个对象平移后的灰(5)像素位置向下绘制一条灰(5)垂直线段，直到碰到红(2)引导线或黄(4)条纹（不含终点），仅绘制在背景像素上。

**关键洞察**：与参考题 b2bc3ffd 中"位移=自身面积"不同，这里位移量由对象与引导线的外部空间关系决定。相同形状和大小的两个对象，若一个在所有引导线之上、另一个在所有引导线之下，位移量截然不同。需要对比示例确认位移来源是穿越数而非面积或其他属性。

## 新题 6：分隔叠加创建拓扑后最大者生长

**组合逻辑**：[透明叠加/transparent_overlay + 并集合并/union_merge](已有) → [连通分量拓扑分析](创新中间步骤：叠加结果的拓扑结构决定后续操作) → [生长/grow + 收缩/shrink + 面积最大者/largest_area](已有)

**来源原语**：透明叠加/transparent_overlay、分隔行/separator_row、前景掩码/foreground_mask、逐格对齐/cell_aligned、并集合并/union_merge（来自 ce4f8723）；生长/grow、收缩/shrink、前景对象/foreground_object、面积最大者/largest_area、最大外扩余内缩/max_grow_rest_shrink（来自 df978a02）

**依赖链**：上下两层掩码各自的前景图案 → 叠加并集创建新的前景分布 → 并集中 4-连通分量的数量和大小由叠加结果决定（两个原本独立的区域可能因叠加而合并为一个大分量） → 最大分量生长、其余分量收缩 → 生长/收缩的对象正是叠加产生的拓扑结构。删除叠加步骤则分量结构不同；删除生长/收缩步骤则叠加结果未经修改。

将被分隔行隔开的上下两层前景掩码做并集叠加，对叠加结果中面积最大的连通分量外扩一层、其余分量内缩一层。

**输入结构**：一个约 11x13 的网格（奇数行数），黑(0)背景。正中间有一行橙(7)分隔行，将网格分为等高的上半区和下半区。上半区有 2~3 个蓝(1)前景区域（4-连通，3~8 像素，形状不规则）。下半区有 2~3 个红(2)前景区域（4-连通，3~8 像素，形状不规则）。生成约束：上下半区对齐后，至少有一对分属上下的区域存在前景像素重叠（确保并集可能合并分量），且至少有一个分量在并集后仍然独立（确保存在大小差异）。并集后各分量面积互不相同（无平局）。最大分量外扩一层后不超出网格边界。

**规则**：
1. 去除橙(7)分隔行，将上半区和下半区逐格对齐。
2. 计算前景并集：对齐后每个格子若上半区为蓝(1)前景或下半区为红(2)前景，则该格子为前景，颜色统一设为绿(3)。仅当两者均为黑(0)背景时该格子为背景。
3. 对并集结果中的绿(3)前景像素做 4-连通分量分析，找出所有连通分量及其面积。
4. 面积最大的分量：其每个前景像素的 4-邻域中若有背景像素，则将该背景像素也涂为绿(3)（即向外扩展一层）。扩展不超出网格边界（输出网格高度 = 原网格高度减 1，即去掉分隔行）。
5. 所有其他分量：移除每个分量中处于分量边界的像素（即该像素在分量内的 4-邻域中至少有一个方向不属于同一分量）。面积为 1 或 2 的分量在此步骤后被完全擦除。

**关键洞察**：叠加并集可能将上下两个原本独立的小区域合并为一个大连通分量，改变"谁是最大者"的判定。仅看输入的上半区或下半区都无法预测输出——必须先完成并集才能确定拓扑结构，再由拓扑结构决定哪个分量生长。

## 新题 7：框内印章后整体镜像与图例逆映射

**组合逻辑**：[图案印章/stamp_glyph + 编码映射/encoding_map](已有) → [镜像/mirror + 邻接/adjacency](已有) → [图例逆映射](创新：镜像副本中颜色按图例反向映射)

**来源原语**：图案印章/stamp_glyph、框架/frame、占位符/placeholder、精灵体/sprite、颜色图例/color_legend、编码映射/encoding_map（来自 edb79dae）；镜像/mirror、前景对象/foreground_object、标记像素/marker_pixel、邻接/adjacency、标记侧翻转且变色/mirror_toward_marker_recolor（来自 2bcee788）

**依赖链**：占位符颜色 → 选择对应精灵体 → 印章到框内 → 图例正向映射决定印章颜色 → 红标记位置决定镜像轴 → 镜像翻转框内几何 → 图例逆向映射改变镜像副本颜色。删除印章步骤则框内无内容可镜像；删除镜像步骤则印章结果不完整；删除逆映射则镜像副本颜色不正确。图例同时提供正向和逆向两个方向的映射。

将精灵体按占位符颜色印章到框内并重涂色，然后按红标记方向镜像整个框内内容，镜像副本中的颜色按图例反向映射。

**输入结构**：一个约 14x14 的网格，黑(0)背景。网格中有一个蓝(1)单色矩形框架（约 6x6 外框，内部约 4x4 可用区域）。框架内部有 2 个不同颜色的占位符像素，位于不同位置，颜色为绿(3)和黄(4)。框架外部有 2 个精灵体（4-连通，3~4 像素，形状不规则）：一个绿(3)精灵体和一个黄(4)精灵体。框架外部另有一个小的颜色图例区域：两对上下相邻的像素，每对上方是占位符色、下方是输出色（如绿(3)上/橙(7)下表示绿→橙，黄(4)上/栗(9)下表示黄→栗）。一个 4-连通的红(2)标记物（2~3 像素）紧贴框架的某一侧（上、下、左或右）。生成约束：精灵体印章到框内后互不重叠；框架加上镜像副本不超出网格边界。

**规则**：
1. 对框架内部的每个占位符像素，找到框外与其颜色相同的精灵体。将精灵体印章到框内，使精灵体的左上角像素与占位符像素的位置对齐。
2. 将每个印章后的精灵体像素重涂为图例中该占位符色对应的输出色（绿(3)→橙(7)，黄(4)→栗(9)）。占位符像素本身也被印章覆盖。
3. 确定红(2)标记物紧贴框架的哪一侧。在框架该侧的外边界设定镜像轴。
4. 将框架内部的全部内容（印章后的结果）关于该轴做镜像翻转，在框架的对侧生成一个等大的镜像副本。
5. 在镜像副本中，将图例映射反转：原本从 A 映射到 B 的，在镜像中将 B 映射回 A（橙(7)→绿(3)，栗(9)→黄(4)）。对镜像副本中所有非背景非蓝(1)像素执行此逆映射。
6. 擦除红(2)标记物（恢复为背景）。蓝(1)框架保留。框外的精灵体和图例保留不变。

**关键洞察**：图例不是单向映射表——它同时定义正向（印章重涂色）和逆向（镜像重涂色），但输入中只显式呈现正向。需要对比多个示例（不同图例配置）才能发现镜像副本使用的是图例的逆映射，而非直接复制颜色或使用其他变换。

## 新题 8：计数定尺寸平铺后模板区域反转

**组合逻辑**：[计数/counting → 像素数决定尺寸/pixel_count_sets_size](已有) → [平铺/tile](已有) → [模板区域反转/invert + 配对色映射/paired_color_mapping](已有原语的创新组合：模板不做遮罩而是标记反转区域)

**来源原语**：计数/counting、四象限/four_quadrants、控制区域/control_region、模板瓦片/stencil_tile、像素数决定尺寸/pixel_count_sets_size、双层图案叠加/two_level_pattern（来自 f931b4a8）；反转/invert、掩码/mask、配对色映射/paired_color_mapping（来自 6ea4a07e）

**依赖链**：上方象限像素计数 → 确定输出尺寸 → 下左图案平铺到该尺寸 → 下右模板同步平铺 → 模板前景位置标记需要反转的格子 → 反转使用颜色配对映射改变平铺图案的颜色。删除计数则尺寸不确定；删除平铺则无基础图案；删除反转则模板无作用。模板不再是可见/不可见的遮罩，而是"正常/反转"的开关。

用上方两象限的前景像素数确定输出尺寸，将下左图案平铺为基底，在下右模板标记的位置对基底颜色做配对色反转。

**输入结构**：一个偶数边长的正方形网格（如 10x10），平均分为四个等大象限。黑(0)为背景。左上象限和右上象限各含若干散布的非背景像素（颜色任意，仅用于计数，通常为灰(5)）。左下象限含一个彩色图案，使用青(8)、绿(3)、灰(5)中的 1~2 种前景色在黑(0)背景上排列（图案占象限面积的 40%~60%）。右下象限含一个模板图案，使用单一前景色（如红(2)）在黑(0)背景上标记位置。生成约束：左上象限前景像素数为 2~5（即输出高度 2~5），右上象限前景像素数为 2~5（即输出宽度 2~5）；左下象限的图案中不包含红(2)色以免与模板色混淆。

**规则**：
1. 计算左上象限中非黑像素数量 H 和右上象限中非黑像素数量 W。输出网格尺寸为 H 行 x W 列。
2. 将左下象限的图案（含背景）平铺到 H x W 的输出网格中：输出格 (r,c) 取左下象限的 (r mod Qh, c mod Qw) 位置的颜色，其中 Qh、Qw 是象限的高和宽。
3. 将右下象限的模板同样按相同方式平铺到 H x W 的虚拟网格中。
4. 对于虚拟模板中前景（红(2)）的位置，将输出网格对应格子的颜色做配对反转：青(8)→红(2)，绿(3)→蓝(1)，灰(5)→黄(4)，黑(0)保持黑(0)。
5. 对于虚拟模板中背景（黑(0)）的位置，输出网格对应格子保持平铺后的原色不变。

**关键洞察**：模板不是遮罩（不控制可见性），而是反转开关——同一个底色在模板前景位置和背景位置产生不同颜色。需要对比多个示例中模板变化导致的输出差异才能发现模板的作用是触发颜色配对映射，而非简单的遮挡或替换。配对映射关系（青→红、绿→蓝、灰→黄）本身也需要从示例中归纳。

**输入结构**：一个约 15x15 的网格，黑(0)背景。网格中有一个多色 4-连通源精灵体（5~8 像素），其中恰好一个灰(5)像素为源锚点，其余像素为 2~3 种非黑非灰颜色。网格中散布 3~5 个孤立灰(5)像素作为目标锚点，互不相邻。每个目标锚点的 8-邻域内有一个"标签"对象：一个单色 4-连通小图形（1~4 像素，颜色取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)），标签对象与目标锚点 8-连通相邻但不包含锚点本身。不同目标的标签颜色可以相同也可以不同，面积可以相同也可以不同。生成约束：至少一个标签面积为 1（即单像素，不会触发复制）、至少两个标签面积大于 1；精灵体副本在各激活目标处互不重叠且不超出网格边界。

**规则**：
1. 对每个目标灰(5)锚点像素，检查其 8-邻域中的标签对象面积。若标签面积 > 1，该目标为"激活"状态；若标签面积 = 1（孤立单像素），该目标为"未激活"状态。
2. 对每个未激活目标：擦除其灰(5)锚点像素（恢复为背景），保留其单像素标签不变。
3. 对每个激活目标：将源精灵体平移复制到此处，使源锚点对齐到目标锚点位置。副本中所有非灰像素统一重涂为该目标的标签对象颜色。灰(5)锚点像素在副本中也涂为标签色。擦除目标锚点和标签对象原始位置（标签位置可能被副本覆盖，若未覆盖则恢复为背景）。
4. 原始源精灵体保留在原位不变。
5. 裁剪输出到所有非黑像素的最小包围矩形。包围矩形内部的黑(0)像素保留为黑(0)。

**关键洞察**：标签对象身兼两职——其面积决定目标是否被激活（筛选），其颜色决定副本的涂色（着色）。单像素标签既"面积不足以激活复制"又"保留在输出中作为残留标记"。需要对比含有不同标签面积配置的示例才能发现面积阈值（>1 才激活）和颜色传递规则。

## 新题 10：少数单元计数定缩放因子后邻域模板印章

**组合逻辑**：[计数少数单元](创新：少数单元的数量成为缩放因子) → [缩放/scale 邻域模板](已有原语的创新用法：模板按少数单元数缩放) → [标记色匹配印章/exemplar_copied_to_same_color](已有) ＋ [分隔线裁切/separator_partition](已有，作为印章边界)

**来源原语**：缩放/scale、平铺/tile、分隔网格/separator_grid、少数单元/minority_cell、多数单元/majority_cell、自相似/self_similarity、少数图案为蓝图/minority_pattern_as_blueprint（来自 b99e7126）；印章覆盖/stamp、标记单元格/marker_cell、邻域模板/neighborhood_template、格网/lattice、分隔线划分/separator_partition、示例邻域传递同色/exemplar_copied_to_same_color（来自 39e1d7f9）

**依赖链**：少数单元的身份识别 → 计数少数单元数量 K → K 成为邻域模板的缩放因子 → 缩放后的模板被印章到所有匹配标记色的单元 → 印章在分隔线处裁切。删除少数单元计数则缩放因子不确定；删除印章则缩放后的模板无处使用；删除分隔线裁切则印章无边界约束。少数单元的内容本身不影响输出（仅数量有意义）。

在分隔网格中，计算少数单元的个数作为邻域模板的缩放因子，将缩放后的模板印章到所有同色标记单元中，在分隔线处裁切。

**输入结构**：一个约 15x15 的网格，由灰(5)分隔线划分为 NxN（N=3~5）的单元阵列，每个单元内部为 3x3 或 4x4 像素。黑(0)为背景。大多数单元内部有相同的简单图案（如全黑或固定的两像素图案），为多数单元。1~3 个单元内部有不同于多数单元的图案，为少数单元（少数单元的图案不需要彼此相同）。恰好一个单元的中心像素为红(2)——这是"示例标记单元"，它的非背景 8-邻域像素构成邻域模板（模板使用蓝(1)和/或绿(3)等颜色）。另有 1~3 个单元的中心像素也是红(2)但没有彩色邻域——这些是"目标标记单元"。少数单元不与任何标记单元重合。生成约束：少数单元数量 K 使得 3x3 模板缩放 K 倍后（即 3K x 3K）不超过单元内部尺寸；目标标记单元数量至少为 1。

**规则**：
1. 识别少数单元（内部图案与多数单元不同的单元），计算其数量 K。
2. 找到示例标记单元（中心为红(2)且 8-邻域有非背景彩色像素的单元）。提取其中心红像素的 8-邻域中所有非背景像素的相对位置和颜色，构成 3x3 邻域模板。
3. 将模板中每个像素扩展为 KxK 的同色块，得到 3Kx3K 的缩放模板。
4. 找到所有目标标记单元（中心为红(2)但 8-邻域均为背景的单元）。对每个目标标记单元，将缩放模板以其中心红像素为中心印章。印章仅绘制在该单元内部的背景像素上；超出该单元边界（即到达灰(5)分隔线或超出）的部分被裁切丢弃。
5. 少数单元的内部图案替换为多数单元的图案（少数标记已被"消费"，其特殊内容不保留）。
6. 示例标记单元保持其邻域模板不变。

**关键洞察**：少数单元在输出中被抹去（替换为多数图案），它们的唯一作用是提供一个计数值作为缩放因子。这个计数值不编码在任何颜色或空间位置中，而是编码在"有多少个单元与众不同"这个全局统计量中。需要对比不同少数单元数量的示例才能发现"少数单元数=缩放因子"的隐蔽规则。
