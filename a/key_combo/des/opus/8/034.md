## 新题 1：射线围合深度着色

**组合逻辑**：[射线延伸](创新：从边界标记发射，遇到已有射线停止) + [填充](创新：区域深度决定填充色) + [计数](创新：计数穿越射线次数作为深度)

**来源原语**：射线延伸(ray_extension) ← 1d398264; 填充(flood_fill) ← 753ea09b; 计数(count) ← aaecdb9a; 边缘标记(edge_marker) ← 5e6bbc0b; 封闭背景区域(enclosed_bg_region) ← 753ea09b; 嵌套层(nested_layer) ← bd5af378

**依赖链**：边缘标记的位置决定射线方向和终点 → 射线网格将画布切分为封闭区域 → 每个区域的"围合深度"（从外边界到达该区域至少需穿越多少条射线）决定其填充颜色 → 深度值通过固定色序映射为具体颜色。删去射线则无分区；删去深度计算则无法选色；删去填充则无输出。

从边界标记发射射线并在射线交汇处截断，按围合深度为分区着色。

**输入结构**：约 15x15 的黑(0)背景网格。网格四条边界上各有 2~4 个单像素标记，使用蓝(1)色。标记不出现在角落。每个边界标记向网格内部发射一条与其所在边垂直的射线（左/右边界标记发射水平射线，上/下边界标记发射垂直射线）。生成约束：标记的位置使得发射的射线两两之间存在交叉（至少形成一个完全封闭的内部矩形区域），但无三线共点。标记像素本身是射线的一部分。

**规则**：
1. 从每个蓝(1)标记出发，沿垂直于其所在边界的方向画一条蓝(1)射线，射线在碰到另一条已存在的射线像素或对侧边界时停止（包含终点像素）。射线绘制顺序不影响最终结果（因为所有射线均为蓝(1)色且交叉点归属无歧义）。
2. 射线将网格划分为若干 4-连通背景区域。计算每个区域的"围合深度"：与网格外边界 4-连通相邻（不穿越任何射线即可到达边界）的区域深度为 0；需至少穿越 k 条射线才能从边界到达的区域深度为 k。
3. 深度为 0 的区域保持黑(0)不变；深度为 1 的区域填充绿(3)；深度为 2 的区域填充黄(4)；深度为 3 的区域填充橙(7)；更高深度依次使用红(2)、品红(6)。蓝(1)射线像素保持不变。
4. 输出网格与输入同尺寸。

**关键洞察**：深度到颜色的映射顺序（黑→绿→黄→橙→红→品红）是隐蔽规则，仅看单个示例可能猜错映射方向或跳色；需对比多个示例中不同深度区域的用色才能确定固定色序。

## 新题 2：棋盘奇偶分流压缩与交叉区冲突合成

**组合逻辑**：[奇偶性选色](创新：奇偶两类分别独立压缩) + [压缩](创新：两个正交方向各压缩一类) + [交叉](创新：交叉区由两类压缩结果叠加决定颜色) + [重涂色]

**来源原语**：奇偶性选色(parity_selects_color) ← 5e6bbc0b; 压缩(compact) ← 5e6bbc0b; 交叉(crossing) ← ba97ae07; 重涂色(recolor) ← ba97ae07; 棋盘格图案(checkerboard_pattern) ← 5e6bbc0b; 横条(h_bar) ← ba97ae07; 竖条(v_bar) ← ba97ae07

**依赖链**：棋盘格的奇偶性将像素分为两类 → 奇类向左压缩、偶类向上压缩（方向由两个边缘标记决定） → 两类压缩后的像素可能在某些单元格重叠 → 重叠区域（"交叉区"）取两类颜色之外的第三种颜色。奇偶分类、压缩方向、冲突规则三者缺一不可。

将棋盘格的两种奇偶类分别沿不同方向压缩，在重叠区域合成第三种颜色。

**输入结构**：约 10x10 的黑(0)背景网格。网格中央有一个矩形区域（约 6x6 至 8x8）填满红(2)/蓝(1)棋盘格图案（(row+col)为偶数的单元格为红(2)，奇数为蓝(1)）。网格左边界或右边界上有一个绿(3)单像素标记，表示水平压缩方向（标记在左边界→向左压缩，在右边界→向右压缩）；网格上边界或下边界上有一个黄(4)单像素标记，表示垂直压缩方向（标记在上边界→向上压缩，在下边界→向下压缩）。两个标记不在同一行或同一列。生成约束：棋盘格区域至少 6x6，保证压缩后两类均有多行多列的像素。

**规则**：
1. 将棋盘格区域的像素按奇偶性分为两组：A 组为红(2)像素（(row+col)为偶数的位置），B 组为蓝(1)像素（(row+col)为奇数的位置）。
2. A 组像素在各自所在行中，向绿(3)标记指示的方向压缩（消除同行内 A 组像素之间的间隙，紧贴棋盘格区域在该方向的边缘）。
3. B 组像素在各自所在列中，向黄(4)标记指示的方向压缩（消除同列内 B 组像素之间的间隙，紧贴棋盘格区域在该方向的边缘）。
4. 压缩后，若某个单元格同时被 A 组和 B 组占据（发生重叠），则该单元格着灰(5)色。仅被 A 组占据的保持红(2)，仅被 B 组占据的保持蓝(1)，均无占据的保持黑(0)。
5. 绿(3)和黄(4)标记像素保留在原位，不参与压缩。输出网格与输入同尺寸。

**关键洞察**：重叠区域的灰(5)色是隐蔽规则——直觉上可能以为重叠区只保留其中一类的颜色，但实际上重叠产生了输入中不存在的第三种颜色。需对比多个示例（不同压缩方向组合导致不同重叠模式）才能发现灰色仅出现在双占区。

## 新题 3：角标记裁剪后的对称检测驱动半区变色

**组合逻辑**：[裁剪](角标记定界) + [对称检测](创新：检测裁剪结果的上下镜像对称性) → 条件分支 → [重涂色](创新：对称与否决定下半区的涂色方案)

**来源原语**：裁剪(crop) ← da6e95e5; 角标记(corner_marker) ← da6e95e5; 包围关系(enclosure) ← da6e95e5; 对称检测(symmetry_detection) ← 44f52bb0; 对称否决定输出色(symmetric_vs_asym_color) ← 44f52bb0; 半区(half_region) ← e7dd8335; 半区变色(half_recolored) ← e7dd8335; 重涂色(recolor) ← e7dd8335

**依赖链**：角标记定位并裁剪出各簇的中心对象 → 对每个裁剪结果做水平镜像对称检测 → 对称性结果决定该对象下半区的着色（对称→下半区涂红(2)，不对称→下半区涂绿(3)） → 输出为各裁剪对象排列在一行中。裁剪结果直接喂入对称检测，对称检测结果直接控制重涂色——三步环环相扣。

裁剪角标记围合的对象，按其上下对称性决定下半区颜色，横向排列输出。

**输入结构**：约 20x20 的黑(0)背景网格。网格中分布 3~4 个互不重叠的簇。每个簇由四个同色角标记像素（位于簇包围盒的四角）和一个位于包围盒中央的单色小图形（4-连通，3~8 像素，不接触包围盒边界）组成。不同簇的角标记颜色互不相同（从蓝(1)、黄(4)、品红(6)、橙(7)中选取）。每个簇内的中心图形颜色为灰(5)。中心图形的包围盒高度为偶数（2 或 4），保证可以精确平分上下半区。生成约束：至少有一个中心图形关于水平中线上下镜像对称，至少有一个不对称。

**规则**：
1. 对每个簇，根据四个同色角标记确定包围盒，裁剪出包围盒内部区域（不含角标记所在行列），得到中心图形及其黑(0)背景。
2. 对每个裁剪结果，检测灰(5)图形是否关于其包围盒的水平中线上下镜像对称（将上半部分翻转后与下半部分逐像素比较，仅比较灰(5)像素位置是否一致）。
3. 若对称，将裁剪结果的下半区所有灰(5)像素重涂为红(2)，上半区保持灰(5)不变。若不对称，将下半区所有灰(5)像素重涂为绿(3)，上半区保持灰(5)不变。
4. 将所有裁剪并着色后的子图按照其对应角标记在原网格中包围盒左上角的列坐标从小到大排序，从左到右水平拼接（子图之间无间隔），形成输出网格。输出网格高度等于最高的子图高度，较矮的子图在顶部补黑(0)行以对齐底边。

**关键洞察**：对称检测的对象不是整个输入而是裁剪后的局部子图，且检测结果不是输出单个指示像素（与参考题 44f52bb0 不同），而是驱动一个空间重涂操作。需对比多个示例才能归纳出"对称→红、不对称→绿"的映射，因为单个示例中可能所有簇恰好都对称或都不对称。

## 新题 4：互补掩码印章经单像素对齐镜像放置

**组合逻辑**：[像素放大·互补掩码提取](创新：提取源图形的互补掩码作为印章模板) + [镜像](创新：由单像素标记的行列对齐确定镜像轴) + [印章覆盖](创新：将互补掩码而非原形状印到镜像位置)

**来源原语**：像素放大(pixel_scaling) ← 0692e18c; 互补掩码(complement_mask) ← 0692e18c; 自身互补(self_complementary) ← 0692e18c; 镜像(mirror) ← 963f59bc; 单像素标记(singleton_marker) ← 963f59bc; 共行列对齐(shared_row_col_align) ← 963f59bc; 对齐决定镜像轴(alignment_mirror_axis) ← 963f59bc; 印章覆盖(stamp_overlay) ← 4c177718

**依赖链**：源图形的形状决定互补掩码的形状（去掉前景、保留包围盒内背景位置） → 单像素标记与源图形某像素的行/列对齐关系确定镜像轴 → 互补掩码沿该轴镜像放置并着标记色。互补提取改变了"印什么"，镜像对齐改变了"印在哪"——两步的输入各自依赖源图形的不同属性。

提取形状的互补掩码，沿单像素标记确定的镜像轴放置互补副本。

**输入结构**：约 15x18 的黑(0)背景网格。网格中有一个由灰(5)像素组成的 4-连通多像素前景图形（5~10 像素，形状不规则，包围盒不超过 5x5）。网格中另有 1~2 个不同颜色的单像素标记（从红(2)、蓝(1)中选取）。每个标记与源图形的恰好一个灰(5)像素共享同一行或同一列（不会同时共享行和列）。标记与源图形之间有足够间距（至少 3 个空像素），保证镜像后的互补掩码不与源图形重叠。生成约束：源图形的包围盒内至少有 2 个背景像素（即互补掩码至少有 2 个像素）。

**规则**：
1. 确定源图形（灰(5)像素构成的 4-连通分量）的包围盒。在包围盒内，所有非灰(5)的位置（即黑(0)背景位置）构成互补掩码。
2. 对每个单像素标记，找到源图形中与该标记共享行或列的那个灰(5)像素（称为"锚点"）。若标记与锚点共享同一行，则镜像轴为标记与锚点列坐标中点处的垂直线；若共享同一列，则镜像轴为标记与锚点行坐标中点处的水平线。
3. 将互补掩码的每个像素位置相对于锚点计算偏移，然后将整组偏移关于镜像轴翻转，得到互补副本的放置位置。互补副本中的每个像素着该标记的颜色。
4. 源图形保持灰(5)不变。标记像素被互补副本覆盖（标记恰好是互补副本的一个像素位置——因为锚点是前景像素，所以锚点的镜像位置落在标记上，而锚点不在互补掩码内；但互补掩码中与锚点相邻的背景位置翻转后可能落在标记上或其附近）。若互补副本的某像素超出网格边界则舍弃。多个标记产生的副本若有重叠，后处理的标记（按标记列坐标从左到右，列相同则行坐标从上到下）覆盖先处理的。
5. 输出网格与输入同尺寸。

**关键洞察**：印章的内容不是源图形自身而是其包围盒内的"空洞"（互补掩码），这与参考题 0692e18c 的自身互补概念同源但用法完全不同——那里互补掩码用于自身放大，这里互补掩码用于外部镜像放置。需要多个示例才能归纳出"印的是空洞而非实体"。

## 新题 5：周期瓦片修复后差异像素射线辐射

**组合逻辑**：[修复噪声](修复周期瓦片中的损坏像素) → [擦除·标记](创新：被修复的像素成为射线源) + [射线延伸](创新：从修复差异点向四方辐射至框架线)

**来源原语**：修复噪声(repair_noise) ← 135a2760; 周期瓦片(periodic_tile) ← 135a2760; 框架分区(frame_partition) ← 135a2760; 周期重复(periodic_repetition) ← 135a2760; 射线延伸(ray_extension) ← 1d398264; 中心向外辐射(radiate_from_center) ← 1d398264; 擦除(erase) ← a2d730bd

**依赖链**：先推断每个框架分区内的最小周期瓦片并修复噪声 → 对比修复前后，标记所有被改变的像素位置 → 每个被改变的像素成为射线源，向四个正交方向发射该像素修复后颜色的射线，射线遇到框架线或网格边界时停止（不穿越框架线）。不完成修复就无法确定哪些像素是"错误的"；不发射射线则修复差异不可见。

修复周期性噪声后，将修复点作为射线源向四方辐射至框架边界。

**输入结构**：约 17x17 的网格。灰(5)色框架线（完整行和完整列）将网格分为 2x2 或 2x3 个矩形分区，每个分区约 5x5 至 7x7。每个分区内部有一个 2x2 或 2x3 的周期瓦片以某种非背景色组合（从红(2)、蓝(1)、绿(3)、黄(4)中选取）铺满分区，瓦片在水平和垂直方向各重复至少 2 次。每个分区恰好有 1~2 个像素被"损坏"——其颜色偏离了周期瓦片的预期值（损坏色为黑(0)或与正确色不同的前景色）。生成约束：每个分区的瓦片周期唯一可推断（最小重复单元在行列方向各至少重复 2 次），损坏像素不在分区角落。

**规则**：
1. 对每个分区，推断最小周期瓦片（对每个余数位置取多数投票确定正确颜色），将分区内所有像素修复为正确的周期铺设值。
2. 对比修复前后的网格，标记所有颜色发生变化的像素位置。这些位置称为"差异点"。
3. 每个差异点以其修复后的颜色（即正确的瓦片颜色）向上、下、左、右四个方向发射射线。射线沿直线延伸，在碰到灰(5)框架线像素或网格边界时停止，不包含框架线像素本身。射线覆盖路径上的所有像素（包括差异点自身），无论原来是什么颜色。
4. 同一分区内多个差异点的射线若在同一像素交叉，以行坐标更小的差异点的颜色优先；行相同则列坐标更小的优先。
5. 框架线像素保持灰(5)不变。输出网格与输入同尺寸。

**关键洞察**：射线的颜色不是固定的，而是取决于该差异点在周期瓦片中的正确颜色——修复步骤的输出直接决定射线步骤的参数。仅看一个示例可能误以为射线颜色是固定的，需对比不同分区中不同颜色损坏点产生的不同颜色射线。

## 新题 6：连通分量计数编码为压缩位移量

**组合逻辑**：[计数](统计每色连通分量数) → [压缩](创新：计数值作为该色所有对象的下移距离) + [扫过轨迹](创新：位移留下的空白填充为指定色)

**来源原语**：计数(count) ← aaecdb9a; 连通分量(connected_component) ← aaecdb9a; 压缩(compact) ← 5e6bbc0b; 扫过轨迹(swept_trail) ← 5e6bbc0b; 重涂色(recolor) ← e7dd8335; 基线对齐(baseline_aligned) ← aaecdb9a

**依赖链**：统计每种前景色的 8-连通分量个数 → 该计数值成为该颜色所有对象整体向下平移的行数 → 平移后空出的原位置填充栗(9)色轨迹 → 平移超出网格底部的像素被截断。计数结果不画成柱状图（与参考题不同），而是隐式编码为空间位移量——不计数就不知道移多远。

统计各色对象数量，以数量为行数将该色所有对象整体下移，原位留栗色轨迹。

**输入结构**：约 15x15 的黑(0)背景网格。网格中散布若干单色 8-连通小对象（每个 2~5 像素，形状不规则）。使用 2~4 种前景色（从红(2)、蓝(1)、绿(3)、黄(4)中选取）。每种颜色有 1~4 个对象。所有对象互不相邻（任意两个不同对象的像素之间至少隔 1 个背景像素）。生成约束：每种颜色的对象数量互不相同；所有对象的最低行坐标加上该色的计数值不全超出网格底部（至少有一种颜色的某个对象下移后仍部分在网格内）。

**规则**：
1. 统计每种前景色的 8-连通分量个数，记为该颜色的"位移量"。
2. 将该颜色的所有像素整体向下平移"位移量"行（每个像素的行坐标增加位移量，列坐标不变）。平移后超出网格底部边界的像素被截断丢弃。
3. 每个被平移走的前景像素，若其原位置现在为空（未被其他颜色平移后的像素占据），则填充栗(9)色。
4. 若两种颜色的像素平移后落在同一位置，位移量较大的颜色覆盖位移量较小的（即移得更远的在上层）。
5. 输出网格与输入同尺寸。黑(0)背景保持不变（除被轨迹或平移像素覆盖的位置外）。

**关键洞察**：每种颜色的移动距离等于该颜色的对象总数——这个"计数→位移"的隐式编码在任何参考题中都不存在。单个示例可能恰好让人误以为位移量是按对象大小或位置决定的，需对比多个示例中各色对象数量与位移量的对应关系。

## 新题 7：类比推断对称补全的变体规则

**组合逻辑**：[类比推理](从训练对推断规则) + [对称补全](创新：补全规则不是标准对称而是训练对示范的变体) + [规则推断](创新：学习的规则是对称补全+额外变换的组合) + [重涂色]

**来源原语**：类比推理(analogy_inference) ← 4c7dc4dd; 训练对映射(training_pair_mapping) ← 4c7dc4dd; 规则推断(rule_inference) ← 4c7dc4dd; 调色板匹配配对(palette_match_pairing) ← 4c7dc4dd; 对称补全(symmetry_completion) ← 929ab4e9; 遮罩像素(mask_pixel) ← 929ab4e9; 八重对称轨道(eightfold_orbit) ← 929ab4e9; 轨道内唯一可见色(unique_color_in_orbit) ← 929ab4e9; 重涂色(recolor) ← ba97ae07

**依赖链**：识别训练对（两个正方形区域，一个有遮罩、一个是"答案"） → 对比训练对中的输入与答案，发现答案并非标准八重对称补全——某些轨道被额外重涂了颜色 → 归纳出"先对称补全、再对特定轨道类型重涂"的组合规则 → 将此组合规则应用于测试区域的遮罩图案。不学习训练对就无法知道额外的重涂规则；不做对称补全就无法处理遮罩。

从训练对中学习一种非标准的对称补全规则（含额外轨道重涂），应用于测试图案。

**输入结构**：约 20x10 的网格（或 10x20）。黄(4)色框架线将网格分为三个相邻的正方形分区（均为 5x5 至 7x7 的奇数边长正方形）。前两个分区构成训练对：第一个分区包含一个部分被栗(9)遮罩的图案（图案用蓝(1)和红(2)两色在黑(0)背景上绘制，栗(9)遮盖了部分位置），第二个分区是该图案的"答案"——遮罩被正确填补且某些轨道被额外重涂。第三个分区是测试输入：另一个部分被栗(9)遮罩的图案（使用相同的两种前景色）。生成约束：答案分区中，"标准对称补全"能解释大部分填补，但有 2~4 个像素与标准补全不同——这些差异构成额外规则（例如：中心像素所在轨道一律重涂为红(2)，或对角线轨道上的蓝(1)全部换为红(2)）。该额外规则在测试分区上也可应用。输出仅为测试分区应用组合规则后的结果（一个无遮罩的正方形网格）。

**规则**：
1. 通过框架线位置识别三个正方形分区。前两个分区为训练对（第一个含遮罩，第二个为答案），第三个为测试输入。
2. 对训练输入分区，执行标准八重对称补全（用每个轨道中唯一的非栗(9)颜色填补栗(9)位置），得到"标准补全结果"。
3. 将标准补全结果与训练答案逐像素对比，记录差异位置。分析差异的共同特征（如：差异像素全部在穿过中心的对角线上，或差异像素全部是某个颜色从 A 变为 B），归纳出额外规则。
4. 对测试输入分区，先执行标准八重对称补全，再应用归纳出的额外规则。
5. 输出为测试分区处理后的正方形网格（不含框架线和其他分区）。

**关键洞察**：这是一道"类比套类比"的题——外层是训练对→测试的类比框架，内层是对称补全的变体学习。若直接对测试区做标准对称补全，会遗漏额外规则；若只看答案分区不对比训练输入，无法分离哪些是补全、哪些是额外变换。

## 新题 8：轮廓围合区域的十字模板匹配选择性填充

**组合逻辑**：[填充](创新：仅填充满足模板条件的围合区域) + [轮廓围合](定义区域边界) + [局部模板匹配](创新：检测区域内是否存在十字图案残留) + [擦除](创新：匹配成功后擦除残留再填充)

**来源原语**：填充(flood_fill) ← 753ea09b; 轮廓围合(contour_enclosure) ← 753ea09b; 封闭背景区域(enclosed_bg_region) ← 753ea09b; 小区域被填充(small_regions_filled) ← 753ea09b; 局部模板匹配(local_template_match) ← 7e02026e; 十字图案(plus_pattern) ← 7e02026e; 正交邻接(orthogonal_adjacency) ← 7e02026e; 擦除(erase) ← a2d730bd; 忽略干扰项(ignore_distractors) ← 753ea09b

**依赖链**：轮廓线将网格分为多个封闭背景区域 → 在每个区域内检测是否存在由特定颜色组成的十字图案（中心+四正交邻居） → 包含十字图案的区域：先擦除十字（变回背景色），再用轮廓色填充整个区域 → 不包含十字图案的区域保持原样不填充。模板匹配是填充的门控条件；擦除保证填充后十字痕迹消失。

仅填充内部含有十字标记的轮廓围合区域，填充前先擦除十字。

**输入结构**：约 18x18 的黑(0)背景网格。绿(3)色像素形成若干 8-连通的长轮廓片段（弧线或折线，每段 8~20 像素），这些片段相互连接或靠近网格边界，将网格内部分割为若干 4-连通的封闭背景区域（每个区域 5~25 个背景像素）和一两个与网格边界相通的大外部区域。部分封闭区域内有一个红(2)色十字图案：一个红(2)像素及其上下左右四个正交邻居也是红(2)（共 5 个红像素组成十字）。十字完全位于该封闭区域内部，不接触轮廓像素。其余封闭区域内部为纯黑(0)背景。网格中还散布少量橙(7)色干扰像素（1~3 个单独像素，可出现在任何位置），干扰像素不参与任何规则。生成约束：至少有 2 个封闭区域含十字，至少有 2 个不含十字；十字的五个像素全部是红(2)且全部位于同一封闭区域内。

**规则**：
1. 将所有非黑(0)像素（绿(3)轮廓、红(2)十字、橙(7)干扰）视为屏障，对黑(0)像素做 4-连通区域分割。
2. 识别所有不与网格边界相邻的封闭背景区域（与边界相通的外部区域排除）。
3. 对每个封闭区域，检查区域内部是否存在红(2)色十字图案（某个红(2)像素的上下左右四邻居均为红(2)且均位于该区域内部或该区域的红(2)像素集内）。
4. 若封闭区域内存在十字图案：先将该十字的 5 个红(2)像素全部改为黑(0)（擦除），然后将该区域的所有黑(0)像素（包括刚擦除变回黑(0)的位置）填充为绿(3)。
5. 若封闭区域内不存在十字图案：该区域保持黑(0)不变。
6. 橙(7)干扰像素保留不变。绿(3)轮廓像素保留不变。输出网格与输入同尺寸。

**关键洞察**：十字图案是"填充许可证"而非输出的一部分——它在触发填充后被擦除，所以输出中看不到任何红色。观察者必须注意到输入中某些区域有红十字而某些没有，且有十字的区域被填充、没有的保持空白。干扰像素是红鲱鱼（herring），需忽略。

## 新题 9：互补自铺展后沿标记方向压缩

**组合逻辑**：[像素放大·自身互补铺展](创新：将小图案按互补规则展开为大网格) + [压缩](创新：沿边缘标记方向将展开结果中的前景像素压缩) + [扫过轨迹](压缩留下的空位着轨迹色)

**来源原语**：像素放大(pixel_scaling) ← 0692e18c; 互补掩码(complement_mask) ← 0692e18c; 自身互补(self_complementary) ← 0692e18c; 前景位置放置瓦片(tile_at_foreground_positions) ← 0692e18c; 压缩(compact) ← 5e6bbc0b; 边缘标记(edge_marker) ← 5e6bbc0b; 标记定压缩方向(marker_sets_dir) ← 5e6bbc0b; 扫过轨迹(swept_trail) ← 5e6bbc0b

**依赖链**：小图案的前景/背景分布决定互补瓦片的内容 → 互补铺展生成大网格（每个前景位置放互补瓦片，每个背景位置放全黑块） → 边缘标记确定压缩方向 → 大网格中所有前景像素沿该方向压缩，空出的位置着轨迹色。互补展开决定了"有什么内容"，压缩方向决定了"内容去哪里"——改变输入图案改变展开结果，改变标记位置改变压缩方向。

将小图案按互补规则展开为大网格，再沿标记方向压缩前景像素。

**输入结构**：网格由两部分组成，以灰(5)色分隔行或分隔列隔开。一侧是一个 3x3 或 4x4 的小图案区域：黑(0)背景上有蓝(1)前景像素（2~5 个前景像素）。另一侧是一个单像素黄(4)色标记，位于分隔线旁的第一行/列的某个边缘位置（靠近上/下/左/右边缘），指示压缩方向。整个网格约 10x5 或 5x10（取决于分隔方向）。生成约束：小图案的包围盒内至少有 2 个背景像素（互补掩码非空）；前景像素不全在同一行或同一列。

**规则**：
1. 读取小图案区域（NxN），确定前景蓝(1)像素位置集合 F 和背景黑(0)位置集合 B（B 即互补掩码）。
2. 构造一个 (N*N) x (N*N) 的展开网格：对小图案中的每个位置 (r,c)，在展开网格的对应 NxN 子块中——若 (r,c) 属于 F，则在该子块中，属于 B 的位置填蓝(1)、属于 F 的位置填黑(0)（即放置互补瓦片）；若 (r,c) 属于 B，则整个子块填黑(0)。
3. 根据黄(4)标记的位置确定压缩方向：标记靠近其所在区域的上边缘→向上压缩；下边缘→向下；左边缘→向左；右边缘→向右。
4. 在展开网格中，将每行（若左/右压缩）或每列（若上/下压缩）的蓝(1)像素向指定方向压缩（消除间隙，紧贴该方向的边缘）。被压缩移走的蓝(1)像素原位置着红(2)色（轨迹），未移动的蓝(1)像素和原本就是黑(0)的位置不变。
5. 输出为展开并压缩后的 (N*N) x (N*N) 网格（不包含分隔线和标记区域）。

**关键洞察**：展开规则是"在前景位置放互补掩码"（与参考题 0692e18c 相同），但展开后还叠加了方向压缩——最终图案既不是简单的互补铺展结果，也不是简单的压缩结果，而是两者的交织。需多个示例才能分离出"先互补展开、再压缩"的两步流程。

## 新题 10：框架内镜像展开后轨道冲突多数投票修复

**组合逻辑**：[镜像](跨框架线向外展开) + [对称补全](创新：展开结果中的轨道冲突通过多数投票解决而非简单覆盖) + [重涂色](冲突轨道的修复色)

**依赖链**：内部图案跨两条红框线向外镜像展开为完整图案 → 展开后的图案应具有关于两条框架线的双轴对称性 → 但某些位置因镜像自身的不完美（输入图案本身在框架线附近有微小不一致）导致同一对称轨道内出现多种颜色 → 对每个冲突轨道做多数投票，统一为出现最多的颜色。镜像展开和轨道修复互相依赖：不展开就没有轨道冲突的概念，不修复则输出不满足对称性。

跨框架线镜像展开内部图案，对因输入不一致导致的对称轨道颜色冲突做多数投票统一。

**输入结构**：约 13x13 的网格。红(2)色像素构成两条完整的分隔线（一条水平、一条垂直），将网格分为四个象限。两条红线交于网格内某处（不必在正中心）。四个象限中只有一个象限（如左上）包含由蓝(1)和绿(3)像素在黑(0)背景上绘制的图案。其余三个象限为纯黑(0)背景。该图案象限中有 1~2 个像素是"故意错误的"——它们的颜色与通过双轴对称性应推导出的颜色不一致。生成约束：图案象限中至少有 5 个非背景像素；"故意错误"的像素被替换后（取其对称轨道中的多数色），整个四象限通过双轴镜像可得到完美对称图案；红(2)分隔线上不放置非红像素。

**规则**：
1. 识别红(2)水平线和红(2)垂直线的位置，确定四个象限。找到包含图案的象限（非背景像素最多的象限）。
2. 将图案象限的内容分别关于水平红线镜像翻转至对侧象限、关于垂直红线镜像翻转至对侧象限、关于交叉点做 180 度旋转翻转至对角象限，生成完整四象限图案（红线本身保留不变）。
3. 对完整四象限图案，定义每个非红、非背景像素的"双轴对称轨道"：包括该像素本身、关于水平红线的镜像位置、关于垂直红线的镜像位置、关于交叉点的 180 度旋转位置（最多 4 个位置，可能因位于轴上而退化）。
4. 对每个轨道，统计轨道内各非背景颜色的出现次数。若轨道内所有位置颜色一致，保持不变。若存在颜色冲突（因图案象限的"故意错误"被镜像传播），将轨道内所有位置统一为该轨道中出现次数最多的颜色。若出现次数平局（如 2 蓝 2 绿），选择颜色编号较小的（蓝(1)优先于绿(3)）。
5. 输出网格与输入同尺寸。红(2)线和黑(0)背景保持不变。

**关键洞察**：输入图案象限中的"错误像素"在镜像展开后会传播到最多三个其他位置，形成轨道冲突。修复不是简单地丢弃错误——因为求解者不知道哪个像素是"错的"，只能通过多数投票让轨道自洽。这是镜像展开（f8a8fe49）与对称补全修复（929ab4e9）的结构性耦合：一个产生冗余信息，另一个利用冗余进行纠错。
