## 新题 1：引导条压缩与单轴重力堆叠

**组合逻辑**：[压缩/compress](已有) + [投射落间隙则擦/erase_if_gap](已有) → [滑动/sliding](创新：在引导条旁做一维重力堆叠) + [碰撞阻挡/collision_block](已有)

**来源原语**：压缩(compress)、引导条(guide_bar)、散布像素(scattered_pixel)、投射到引导条(project_to_guide)、投射落间隙则擦(erase_if_gap) ← 参考题 f83cb3f6；滑动(sliding)、碰撞阻挡(collision_block)、重力沉降(gravity_settle) ← 参考题 d282b262

**依赖链**：压缩步骤决定哪些散布像素存活并将它们重新定位到引导条旁；重力步骤在压缩结果的基础上对存活像素做一维堆叠。引导条的间隙分布同时影响存活集合和堆叠的障碍边界——间隙既是过滤器又是墙壁，删除任一步都无法得到正确输出。

将散布像素正交投射到引导条旁，落在间隙上的擦除，存活像素沿引导条方向滑动堆叠，间隙同时阻断滑动。

**输入结构**：约 15x15 黑(0)背景网格。一条水平或垂直的单像素厚红(2)引导条，位于网格中部，含 1~2 个间隙（间隙处为黑(0)）。引导条两侧散布若干蓝(1)孤立像素，每个像素与引导条之间仅有黑色背景。生成约束：每个蓝像素在引导条方向上的投影位置互不相同（保证压缩后不重叠）；至少有 2 个蓝像素投射到间隙上（会被擦除）；至少有 3 个蓝像素投射到实体段上（会存活）；存活像素分布在至少两个被间隙隔开的引导条段上。

**规则**：
1. 保留引导条不变。
2. 对每个蓝(1)像素，沿垂直于引导条的方向投射到引导条紧邻的一侧（保持其原来在引导条的哪一侧：引导条上方的像素投射到引导条正上方一格，下方的投射到正下方一格；垂直引导条同理取左右）。若该像素投影对应的引导条格为间隙（黑色），则该像素被擦除。
3. 存活的蓝像素停在引导条旁的紧邻格。
4. 所有存活像素同时沿引导条方向滑动：水平引导条上的像素向右滑，垂直引导条上的像素向下滑。像素不能滑过引导条间隙对应的位置（间隙位置的旁侧格视为墙壁），也不能滑过已停止的其他像素或网格边界。反复执行直到所有像素停止。
5. 输出中只保留引导条和最终位置的蓝像素，其余为黑色背景。

**关键洞察**：引导条的间隙同时承担两种功能——在压缩阶段过滤掉投射到间隙的像素，在滑动阶段阻断存活像素的运动。同一结构特征在两个操作中扮演不同角色，必须对比多个示例（有间隙和无间隙的情况）才能归纳出这一双重机制。

## 新题 2：种子选色模板的对角链堆叠

**组合逻辑**：[种子选择模板/seed_selects_template](已有) + [像素放大/pixel_scale](已有) → [堆叠/stacking](创新：不在框内放置，而是沿对角线链式排列) + [冲突优先级/conflict_priority](已有)

**来源原语**：种子选择模板(seed_selects_template)、像素放大(pixel_scale)、模板(template)、种子像素(seed_pixel)、框内匹配(frame_interior_match) ← 参考题 8a6d367c；堆叠(stacking)、对角链排列(diagonal_chain_layout)、角点重叠(corner_overlap)、按左边缘排序(ordered_by_left_edge)、冲突优先级(conflict_priority) ← 参考题 03560426

**依赖链**：种子像素的颜色决定匹配哪个模板（选择）；模板经 2 倍像素放大后尺寸各异（变换）；种子像素在网格中的水平位置决定对角链的放置顺序（排序）；每个放大后模板的实际宽高决定下一个模板的偏移量（几何耦合）。改变种子的水平排列就会改变遮挡关系，改变模板内容就会改变偏移量。

按种子位置顺序将种子选中的放大模板沿对角线依次堆叠，后放的覆盖先放的重叠角。

**输入结构**：约 12x20 黑(0)背景网格，分上下两区。上区：2~4 个小型多色模板（每个为 2x2 或 2x3 或 3x2 或 3x3 的密实色块），彼此间隔至少 2 格，每个模板含一种独特的标识色（如模板 A 含蓝(1)但不含绿(3)，模板 B 含绿(3)但不含蓝(1)），其余像素为灰(5)或其他非标识色。下区：与模板数量相同的孤立种子像素排成一行，颜色分别为各模板的标识色，水平位置各不相同。生成约束：每种标识色恰好出现在一个模板和一个种子中；种子像素之间至少间隔 2 列；不同模板的尺寸至少有一个维度不同（保证对角偏移量不全相同）。

**规则**：
1. 每个种子像素的颜色匹配上方唯一含该标识色的模板。
2. 将每个匹配的模板做 2 倍像素放大（每个原始像素变为 2x2 同色块）。
3. 按种子像素从左到右的列位置排序。按此顺序依次放置放大后的模板：第一个模板的左上角放在输出网格的 (0,0)。设刚放置的模板高 H 宽 W，下一个模板的左上角放在 (H-1, W-1)，使得两个模板恰好共享右下角和左上角的一个格。
4. 后放置的模板像素覆盖先放置的（冲突优先级：后放优先）。
5. 输出网格大小恰好容纳所有放置的模板的并集边界框，多余区域为黑(0)。

**关键洞察**：种子像素的空间顺序不改变模板内容，但决定了对角链中的前后位置，而位置决定了遮挡关系——改变种子顺序会改变哪些模板被部分遮挡，导致完全不同的输出图案。需要对比多个示例才能区分"按种子的列位置排序"与其他可能的排序规则。

## 新题 3：射线开路与迷宫洪泛填充

**组合逻辑**：[射线延伸/ray_cast](创新：射线不绘制线段而是擦除灰色路障) + [擦除/erase](已有) → [洪泛填充/flood_fill](已有) + [路径连通/path_connectivity](已有)

**来源原语**：射线延伸(ray_cast)、颜色决定射线方向(color_determines_ray_direction) ← 参考题 8d510a79；洪泛填充(flood_fill)、迷宫走廊(maze_corridor)、种子像素(seed_pixel)、路径连通(path_connectivity) ← 参考题 b782dc8a；擦除(erase) ← 参考题 3dc255db

**依赖链**：射线擦除步骤改变迷宫的拓扑结构（移除灰色墙段，打通新走廊），洪泛填充在修改后的拓扑上执行。红像素是拓扑操作器而非输出颜色源——它们的位置和朝向决定哪些墙段被移除，从而决定蓝色填充能扩散到多大范围。删除红像素则部分走廊不通，删除蓝像素则无填充源。

红像素沿指定方向发射射线擦除灰色路障打通走廊，然后从蓝像素出发洪泛填充所有可达的走廊格。

**输入结构**：约 15x15 网格，青(8)为迷宫墙体，黑(0)为走廊。走廊网络被若干灰(5)单像素墙段阻断（灰墙段嵌在走廊中，两侧为黑色走廊格，上下或左右为青色墙体，形成一个单像素宽的路障）。1~3 个红(2)像素位于走廊中，每个红像素恰好有一个 4-邻居是灰(5)墙段。1 个蓝(1)像素位于走廊中，作为洪泛填充的种子。生成约束：若不擦除任何灰墙，蓝像素可达的走廊面积严格小于擦除全部灰墙后的可达面积；每个红像素恰好有一个 4-邻居是灰墙段（唯一确定射线方向）；红像素本身在全通后的蓝像素可达区域内；灰墙段总数大于等于红像素总数（可能有部分灰墙未被任何红像素的射线覆盖，保持阻断）。

**规则**：
1. 对每个红(2)像素，找到其唯一的灰(5) 4-邻居，确定从红像素指向该灰邻居的方向。
2. 从红像素出发沿该方向发射射线：射线每步前进一格，将路径上的灰(5)像素变为黑(0)（擦除路障）。射线遇到青(8)迷宫墙或网格边界时停止。射线经过的黑(0)像素不受影响。
3. 所有红像素的射线同时处理完毕后，从蓝(1)像素出发，对所有 4-连通的黑(0)走廊格进行洪泛填充，填充色为蓝(1)。
4. 红(2)像素在输出中保留为红(2)。青(8)墙体保持不变。未被填充覆盖的黑(0)格（不可达的走廊段）和未被射线擦除的灰(5)墙段保持不变。

**关键洞察**：红像素不是输出颜色的来源，而是拓扑操作器——它们的位置和朝向决定哪些灰墙被移除。只有对比多个示例（有些走廊因红像素开路而被填充、有些因无红像素开路而保持黑色）才能归纳出"红射线擦除灰墙"这一非显然规则。

## 新题 4：行控制色重涂与连通融合填孔

**组合逻辑**：[重涂色/recolor](已有) + [每行独立取色/per_row_color](已有) → [连通分量检测/connected_component_detection](创新：在重涂产生的新颜色分布上检测连通分量) → [填充/fill](创新：对因融合而产生的封闭孔洞进行填充)

**来源原语**：重涂色(recolor)、占位像素(placeholder_pixel)、行控制色(row_control_color)、每行独立取色(per_row_color)、同行对齐(same_row_align) ← 参考题 c7d4e6ad；连通分量检测(connected_component_detection) ← 参考题 14754a24；洪泛填充(flood_fill)、路径连通(path_connectivity) ← 参考题 b782dc8a

**依赖链**：行控制色重涂赋予每行灰像素不同颜色；重涂后相邻行若恰好获得相同颜色，原本分离的灰色区块在颜色空间上融合为同一 4-连通分量；融合可能包围出新的黑色孔洞，这些孔洞被同色填充。重涂是融合的前提（不重涂则所有灰色区块已经同色，无法区分哪些该融合），融合是填孔的前提（不融合则无封闭孔洞），填孔依赖融合后的边界（不填则孔洞残留）。

用行控制色替换灰像素后，同色相邻区域融合，被融合区域完全包围的黑色孔洞用该颜色填充。

**输入结构**：约 12x12 黑(0)背景网格。灰(5)像素形成若干 4-连通的不规则形状（每个形状跨越 2~5 行，宽 3~6 像素，形状之间可能仅隔 1 行黑像素）。网格最右列为标记列，每个含灰像素的行在该列有一个非黑非灰的控制色像素（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。生成约束：至少存在两个原本不 4-连通的灰色形状，在重涂后因相邻行获得相同控制色而 4-连通融合；至少一次融合会包围出一个或多个纯黑(0)的封闭孔洞（孔洞的所有 4-连通黑像素均不与网格边界相邻，且其所有 4-邻居要么是同一连通分量的像素要么是孔洞自身的像素）；标记列的控制色不全部相同。

**规则**：
1. 将每个灰(5)像素替换为该行标记列中的控制色。标记列的控制色像素本身保留不变。
2. 在重涂后的网格上，检测所有 4-连通同色前景连通分量。
3. 对每个连通分量，检查其是否完全包围了一个或多个黑(0)孔洞。孔洞定义：一组 4-连通的黑像素，该组中没有任何像素位于网格的第一行、最后一行、第一列或最后一列，且该组的所有 4-邻居要么属于该组自身要么属于同一个前景连通分量。
4. 将每个被完全包围的孔洞用包围它的连通分量的颜色填充。
5. 未被包围的黑像素（与网格边界 4-连通可达的）保持黑色。

**关键洞察**：控制色的分配不仅改变颜色，还改变拓扑——两个形状是否融合取决于它们接触行的控制色是否相同，而融合后的形状边界可能围出原本不存在的封闭区域。求解者需要对比多个示例（有些行颜色相同导致融合和填孔，有些行颜色不同保持分离和无孔）才能发现这一涌现效应。

## 新题 5：弹射后重力沉降

**组合逻辑**：[弹射/ejection](已有) + [尾部朝向决定射出/tail_determines_emission](已有) → [擦除/erase](创新：弹射后擦除杯框架本身) → [滑动/sliding](创新：弹出像素作为独立对象受重力沉降) + [碰撞阻挡/collision_block](已有)

**来源原语**：弹射(ejection)、杯形框架(cup_frame)、内容像素(content_pixel)、尾刺(tail_spike)、尾部朝向决定射出(tail_determines_emission)、像素数守恒(pixel_count_conservation) ← 参考题 3dc255db；滑动(sliding)、碰撞阻挡(collision_block)、重力沉降(gravity_settle)、画布边界(canvas_boundary) ← 参考题 d282b262；擦除(erase) ← 参考题 3dc255db

**依赖链**：弹射方向决定内容像素的初始释放位置（水平坐标）；框架擦除后像素悬空；重力将所有释放像素向下拉至底部堆叠。不同杯的弹射方向不同，使像素散布到不同列，而重力统一将它们拉到底部。弹射决定"从哪里释放"，重力决定"落到哪里"——两者耦合通过列坐标传递。

将每个杯中的内容像素沿尾刺方向弹射出去，擦除所有杯框架，然后所有弹出像素受向下重力沉降至底部堆叠。

**输入结构**：约 18x18 黑(0)背景网格。2~4 个杯形框架，每个由独特的边框色构成（从蓝(1)、绿(3)、黄(4)、品红(6)中选取），杯口朝向与尾刺朝向相反。尾刺为从杯体凸出的 1~2 像素尖端，朝向可为上、下、左、右之一。每个杯内有 2~4 个同色内容像素（颜色为红(2)或橙(7)，每个杯的内容色可以不同）。杯形框架分布在网格的中上部，互不重叠，底部留有足够空间容纳所有弹出像素的堆叠。生成约束：至少两个杯的弹射方向不同；弹射后至少有两个不同杯的内容像素落在同一列（从而在重力沉降时堆叠）；杯的尾刺与网格边界之间有足够空间放置弹出像素。

**规则**：
1. 对每个杯，识别其尾刺方向（尾刺尖端相对于杯体的方向）。
2. 从尾刺尖端出发，沿尾刺朝向的延长线依次放置该杯的内容像素（每个内容像素占一格，紧密排列，第一个紧邻尾刺尖端）。超出网格边界的像素被丢弃。
3. 杯内的原始内容像素被擦除（变为黑色）。
4. 擦除所有杯形框架（边框和尾刺像素全部变为黑色）。
5. 所有弹出的像素同时受向下重力：每个像素独立向下移动，直到碰到网格底边或已停止的其他像素。同一列中位置更低的像素先沉降。像素保持各自的颜色不变。

**关键洞察**：尾刺方向决定弹射轨迹，但不等于最终位置——所有像素最终都被重力拉到底部，尾刺方向只是通过改变像素的列坐标来间接影响最终堆叠结果。需要对比多个示例（不同弹射方向产生不同列分布，进而不同堆叠结果）才能区分"弹射+重力"与"直接重排"的规则。

## 新题 6：引导条投射转对角射线

**组合逻辑**：[压缩/compress](已有) + [投射落间隙则擦/erase_if_gap](已有) → [射线延伸/ray_extend](创新：从引导条位置而非原始位置出发发射对角线射线) + [对角方向/diagonal_dir](创新：方向由像素原来在引导条哪一侧决定) → [擦除/erase](创新：引导条在输出中消失)

**来源原语**：压缩(compress)、引导条(guide_bar)、散布像素(scattered_pixel)、投射到引导条(project_to_guide)、投射落间隙则擦(erase_if_gap) ← 参考题 f83cb3f6；射线延伸(ray_extend)、对角方向(diagonal_dir)、角位控制射线(corner_controls_ray) ← 参考题 1f0c79e5；擦除(erase) ← 参考题 3dc255db

**依赖链**：压缩步骤将散布像素投射到引导条旁，过滤掉间隙处的像素并确定存活像素的引导条坐标；存活像素从引导条位置出发发射对角线射线，方向由原始侧别编码；引导条本身在输出中被擦除。引导条是瞬态结构——输入中存在（用于过滤和定位），输出中消失（只留射线痕迹）。

散布像素投射到引导条过滤存活后，从引导条位置沿对角线射出，方向取决于像素原来在引导条的哪一侧，引导条自身消失。

**输入结构**：约 15x15 黑(0)背景网格。一条垂直的绿(3)引导条（单像素宽），位于网格中部偏左（约第 4~5 列），含 1~2 个间隙（间隙处为黑(0)）。引导条左侧散布若干红(2)孤立像素；引导条右侧散布若干蓝(1)孤立像素。每个散布像素与引导条在同一行（即水平投射必定命中引导条的某一格或间隙）。生成约束：至少一个红像素和一个蓝像素的投射落在间隙上（被擦除）；存活的红和蓝像素至少各有 2 个；不同散布像素不在同一行；存活像素的射线在网格内有足够空间展开（不立即碰到边界）。

**规则**：
1. 对每个散布像素，水平投射到引导条。若该像素所在行的引导条格为间隙（黑色），该像素被擦除，不产生任何输出。
2. 存活像素确定其在引导条旁的发射位置：行号 = 原像素的行号，列号 = 引导条列号 - 1（原来在左侧的）或引导条列号 + 1（原来在右侧的）。
3. 每个存活像素从发射位置出发，沿两个对角方向各发射一条射线：原在引导条左侧的红(2)像素向右上和右下各发一条红色射线；原在引导条右侧的蓝(1)像素向左上和左下各发一条蓝色射线。
4. 射线沿 45 度对角线延伸，每步画一个与发射源同色的像素，直到碰到网格边界停止。
5. 若两条射线交叉在同一格，按发射源在引导条上从上到下的顺序绘制，后绘制的覆盖先绘制的。
6. 输出中引导条被擦除（所有绿(3)像素变为黑(0)），只保留射线像素和发射位置像素。

**关键洞察**：引导条是瞬态结构——它在输入中作为空间滤波器（间隙过滤）和定位锚点（确定射线起点），在输出中完全消失。像素原来在引导条哪一侧的信息通过射线方向被"记忆"在输出中。求解者需要对比输入和输出发现引导条消失、射线出现的对应关系。

## 新题 7：跨面板计数驱动旋转印章

**组合逻辑**：[计数/counting](创新：从九宫格面板中计数精灵体，结果跨面板传递) → [旋转/rotate](已有) + [印章覆盖/stamp](已有) + [高频色位定印章/frequent_positions_set_stamps](已有)

**来源原语**：计数(counting)、印章覆盖(stamp)、精灵体(sprite)、阵列排布(array_layout)、高频色位定印章(frequent_positions_set_stamps) ← 参考题 c3e719e8；旋转(rotate)、旋转关系(rotation_relation) ← 参考题 291dc1e1 / a416fc5b；菱形精灵(diamond_sprite)、九宫格(nine_cell_grid) ← 参考题 a416fc5b

**依赖链**：左面板九宫格中有色精灵体的数量决定旋转角度；右面板的 3x3 彩色图案被旋转该角度后既作为印章内容又作为印章位置掩码（最高频色的位置选择块槽）。旋转同时改变了最高频色在 3x3 中的位置分布，从而改变了哪些块槽被激活。左面板提供计数，右面板提供内容，两者在旋转操作处交汇——删除任一面板都无法确定输出。

用左面板中精灵体的个数决定右面板图案的旋转角度，再用旋转后的图案作为印章模板和位置掩码生成输出。

**输入结构**：左面板：11x11 网格，橙(7)背景，品红(6)分隔条将其划分为 3x3 的九宫格（每个宫格内部 3x3）。其中 1~4 个宫格含有红(2)菱形精灵（4 像素，分别在宫格中心的上下左右各一个），其余宫格为纯橙背景。右面板：3x3 彩色网格，9 个格全为非黑色，使用 2~3 种颜色（如蓝(1)出现 4 次，绿(3)出现 3 次，黄(4)出现 2 次），其中恰好一种颜色出现次数严格最多。两面板水平排列，间隔 1 列黑(0)分隔。生成约束：精灵体数量为 1~4；右面板中最高频色的位置分布在旋转 0/90/180/270 度后至少两种情况下不同（保证旋转角度影响输出布局）。

**规则**：
1. 计数左面板中含有红(2)菱形精灵的宫格数 N。
2. 将右面板的 3x3 图案逆时针旋转 (N-1) x 90 度：N=1 不旋转，N=2 旋转 90 度，N=3 旋转 180 度，N=4 旋转 270 度。
3. 在旋转后的 3x3 图案中找出出现次数严格最多的颜色 C。
4. 输出为 9x9 黑(0)网格，划分为 3x3 的块槽（每个块槽 3x3）。旋转后图案中颜色 C 所在的每个位置（在 3x3 中的行列坐标），对应的块槽填入旋转后的完整 3x3 图案副本；其余块槽保持黑色。
5. 左面板不出现在输出中。

**关键洞察**：旋转不只改变图案的朝向——它还改变了最高频色在 3x3 网格中的位置分布，从而改变了哪些块槽被激活。同一个图案在不同旋转角度下会产生完全不同的印章布局。求解者必须对比多个示例（不同精灵体计数导致不同旋转和不同印章位置）才能归纳出计数-旋转映射和频率驱动印章机制。

## 新题 8：三点构框-边界灌注-凹痕标记

**组合逻辑**：[补全/complete](已有) + [三点定矩形框/three_pts_define_rect](已有) → [洪泛填充/flood_fill](创新：从框边界内侧向内灌注而非从色块向外扩展) → [缺陷标记/defect_mark](创新：将灌注后残留的内部黑色孔洞标记为青色)

**来源原语**：补全(complete)、标记像素(marker_pixel)、空心矩形(hollow_rect)、包围盒(bounding_box)、三点定矩形框(three_pts_define_rect) ← 参考题 e7639916；洪泛填充(flood_fill)、路径连通(path_connectivity) ← 参考题 b782dc8a；缺陷标记(defect_mark)、凹痕(dent)、邻域多数色(neighborhood_majority_color) ← 参考题 de809cff

**依赖链**：三个标记像素定义包围盒并画出矩形框边界（构框）；从框边界内侧出发向内洪泛填充黑色区域为橙色，遇到已有橙色像素停止（灌注）；灌注后框内残留的黑色像素即为被橙色区域完全包围的凹痕，标记为青色（标记）。框不存在则灌注无边界约束，灌注不完成则凹痕与普通黑色像素无法区分。

用三个标记像素构建矩形框，从框边界内侧向内灌注橙色至已有色块边缘，将灌注后框内残留的黑色孔洞标记为青色。

**输入结构**：约 15x15 黑(0)背景网格。1~2 组标记像素，每组 3 个同色像素（如第一组为红(2)，第二组为绿(3)），分布在各自包围盒的边界上。每组标记像素的包围盒内部散布若干橙(7)像素，形成一个 4-连通的不规则色块（5~15 像素），色块内含 1~3 个孤立的黑(0)凹痕（每个凹痕为单个黑像素，被橙色像素 4-连通包围）。包围盒之间不重叠。生成约束：每组恰好 3 个标记像素，分布在包围盒的三条不同边上；橙色色块不接触包围盒的任何边（色块与框边界之间至少有 1 格黑色间距）；凹痕完全被橙色像素 4-连通包围（从框边界无法 4-连通到达凹痕）；色块本身从框边界内侧可以 4-连通到达（即色块与框边界之间的黑色区域是连通的）。

**规则**：
1. 对每组同色标记像素，计算其包围盒，沿包围盒四边画出矩形边框，颜色与标记像素相同。标记像素本身保留在边框上。
2. 在每个矩形框内部（不含边框本身），从紧贴框内壁的所有黑(0)像素出发，洪泛填充所有 4-连通可达的黑(0)像素为橙(7)。填充遇到已有的橙(7)像素时停止（不覆盖），遇到框边框时也停止。
3. 填充完成后，检查框内是否仍有黑(0)像素。这些残留黑像素即为凹痕——它们被橙色区域完全包围，从框边界无法到达。
4. 将每个凹痕像素重涂为青(8)。
5. 框外的所有像素保持原样（黑色背景）。

**关键洞察**：灌注方向是从框边界向内（而非从色块向外），这使得色块内部的孔洞成为不可达的"死角"。框的边界限定了灌注范围，灌注的终止面（已有橙色像素）划分了可达与不可达区域，只有不可达的黑色像素才是需要标记的缺陷。求解者必须对比多个示例才能发现灌注方向是从外向内而非从内向外。

## 新题 9：引导掩码裁剪后用作印章模板

**组合逻辑**：[裁剪/crop](已有) + [唯一被框选对象/uniquely_enclosed](已有) → [印章覆盖/stamp](创新：裁剪出的精灵体同时充当印章内容和位置掩码) + [高频色位定印章/frequent_positions_set_stamps](已有)

**来源原语**：裁剪(crop)、空心精灵体(hollow_sprite)、引导掩码(guide_mask)、包围框包含(bbox_containment)、唯一被框选对象(uniquely_enclosed) ← 参考题 bf699163；印章覆盖(stamp)、高频色位定印章(frequent_positions_set_stamps)、阵列排布(array_layout) ← 参考题 c3e719e8

**依赖链**：引导掩码选择裁剪哪个精灵体（从多个候选中选一个）；裁剪结果是一个 3x3 图案；该图案的颜色频率分布决定最高频色，从而决定印章放置位置；同一图案又作为印章内容被复制。选择不同的精灵体会导致不同的颜色频率→不同的印章布局→完全不同的输出。

用引导掩码从多个精灵体中选出一个裁剪为 3x3 模板，然后按该模板中最高频色的位置在 9x9 网格中重复印章。

**输入结构**：约 14x14 黑(0)背景网格。3~4 个多色 3x3 精灵体（每个精灵体的 9 个格全为非黑色，使用 2~3 种前景色），分散在网格中，彼此间距至少 2 格。另有一组灰(5)散布像素构成引导掩码，这些灰像素不属于任何精灵体。引导掩码的包围框恰好完全包含其中一个精灵体，且不完全包含其他任何精灵体。生成约束：每个精灵体中恰好一种颜色出现次数严格最多；不同精灵体的最高频色位置分布互不相同（保证选择不同精灵体会产生不同印章布局）；引导掩码像素不与被选精灵体的像素重叠。

**规则**：
1. 识别所有 3x3 精灵体：在网格中找到所有 3x3 区域且其 9 个格全为非黑色的前景对象。
2. 构建引导掩码：收集所有不属于任何精灵体的灰(5)像素。
3. 计算引导掩码的包围框，找到该包围框内唯一完全被包含的精灵体。裁剪该精灵体得到 3x3 图案。
4. 在裁剪出的 3x3 图案中找出出现次数严格最多的颜色 C。
5. 输出为 9x9 黑(0)网格，划分为 3x3 的块槽。图案中颜色 C 所在的每个位置（在 3x3 中的行列坐标），对应的块槽填入裁剪出的完整 3x3 图案副本；其余块槽保持黑色。

**关键洞察**：引导掩码不选择颜色或印章位置——它只选择哪个精灵体成为模板；而被选模板自身的颜色频率分布同时决定了印章内容和印章布局。一次选择产生两个后果（内容 + 布局），且两个后果来自同一个对象的不同属性（几何形状 vs 颜色分布），这使得问题不可分解为独立子问题。
