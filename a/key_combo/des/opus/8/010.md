## 新题 1：角对标记区域的对角依赖反射

**组合逻辑**：[填充/fill](创新：不填充矩形实体，而是界定操作区域) + [镜像/reflect](创新：反射方向由标记对的几何关系决定，非固定方向) ← [对角配对/diagonal_pairing](原有) + [同色对定义矩形/pair_defines_rect](原有)

**来源原语**：填充(#56ff96f3)、镜像(#8d5021e8)、对角配对(#56ff96f3)、同色对定义矩形(#56ff96f3)

**依赖链**：同色标记对的空间位置同时决定两件事：(1) 通过边界框确定操作区域；(2) 通过两点的对角线方位（左上-右下 vs 右上-左下）确定区域内图案的反射轴向。内部灰色图案经该反射后以标记色叠入区域——删除标记对的位置关系就无法确定反射方向，删除内部图案就没有反射对象，删除反射操作就无法生成新增像素。

用一行自然语言概括：同色像素对划定矩形区域，其对角方位选择水平或垂直反射，将区域内灰色图案反射后以标记色叠加回去。

**输入结构**：约 14x14 的网格，黑(0)背景。网格中有 2~3 种前景颜色（如红(2)、蓝(1)、黄(4)），每种颜色恰好出现两个孤立像素，分别位于网格的不同位置，它们充当矩形的对角标记。每对标记所定义的轴对齐矩形内部（不含标记像素本身所在行列的边界）散布着若干灰(5)像素，构成一个非对称的小图案（3~6 个灰像素，4-连通或分散均可）。不同颜色对定义的矩形互不重叠。生成约束：每对标记的行坐标不同且列坐标不同（保证矩形面积 > 0）；灰色图案关于水平轴和垂直轴均不对称（否则反射后无变化，规则不可观测）。

**规则**：
1. 对每种前景颜色，取其两个像素的位置，以它们为对角顶点确定一个轴对齐矩形（包含边界）。
2. 判断该颜色对的对角方位：将两像素中行号较小的那个视为"上点"——若上点的列号也较小（即上点在左上），则该对属于"NW-SE 型"；否则上点在右上，属于"NE-SW 型"。
3. 提取该矩形内所有灰(5)像素相对于矩形左上角的局部坐标，形成一个局部图案。
4. NW-SE 型：将局部图案沿垂直轴做左右镜像（列坐标 c 映射为 W-1-c，W 为矩形宽度）。NE-SW 型：将局部图案沿水平轴做上下镜像（行坐标 r 映射为 H-1-r，H 为矩形高度）。
5. 将镜像后的图案以该颜色对的前景色（而非灰色）绘制回矩形的对应位置。若镜像位置已有灰(5)像素，则用前景色覆盖。
6. 原始灰(5)像素保留不变（除非被步骤 5 覆盖）。标记像素本身保留原色不变。矩形外的所有像素不变。

**关键洞察**：标记对不只定义区域——其对角方位隐式编码了反射方向。求解者必须跨示例对比才能发现 NW-SE 型触发水平镜像而 NE-SW 型触发垂直镜像的规则。

## 新题 2：遮挡分布驱动的边框逃逸

**组合逻辑**：[补全/reconstruct](原有) → [计数/count](创新：计数对象从整体像素数变为逐边遮挡像素数) → [推移/push](创新：方向不由固定标记决定，而由遮挡分布推导) + [遮挡层序/occlusion_order](原有) + [接触侧决定方向/contact_side_dir](创新：从标记接触改为遮挡侧推导)

**来源原语**：补全(#68bc2e87)、计数(#d631b094, #bd283c4a)、推移(#5623160b)、遮挡层序(#68bc2e87)、空心矩形(#68bc2e87)、网格边界(#5623160b)

**依赖链**：首先从可见像素重建每个框的完整边界框（补全），然后计算每条边上被遮挡的像素数（遮挡分析 + 计数），遮挡最严重的边决定推移方向（条件判断），最后将框平移到网格边界（推移）。重建是计数的前提，计数是方向判断的前提，方向判断是推移的前提——任一步不可跳过。此外，绘制顺序取决于层序（底层先画），否则推移后的重叠结果不确定。

用一行自然语言概括：重建重叠矩形框的完整形状，每个框朝其被遮挡最严重的边的反方向逃逸至网格边界，按原始层序绘制。

**输入结构**：约 15x15 的网格，黑(0)背景。3~4 个单像素厚的矩形框（空心矩形），每个框使用不同的前景色（如红(2)、蓝(1)、绿(3)、黄(4)）。框的边界框尺寸在 4x4 到 8x8 之间。部分框有区域重叠——重叠处只显示最上层框的颜色，下层框的像素被遮挡。生成约束：每个框至少有一条完整的边可见（保证可重建）；每个框至少有一条边存在被遮挡像素（否则推移方向无法从遮挡信息推导）；推移后不同框的最终位置不重叠（保证输出唯一确定）。

**规则**：
1. 从每种前景色的可见像素推断其完整矩形框的边界框（取可见像素的行列极值即为框的四条边位置）。
2. 重建每个框的完整单像素边框（4 条边各为一行或一列像素）。
3. 确定层序：在任意两个框共享的像素位置上，可见颜色属于上层框。对所有这样的约束取传递闭包，得到唯一的从底到顶的全序。
4. 对每个框，分别统计其四条边（上、右、下、左）上被其他框遮挡的像素数量。
5. 选择遮挡像素数最多的边作为"最受压边"。若有并列，按上→右→下→左的优先级打破。
6. 推移方向为最受压边的反方向：最受压边为上边→向下推，右边→向左推，下边→向上推，左边→向右推。
7. 清除所有框的原始像素。
8. 按层序从底到顶依次绘制：将每个框沿其推移方向平移，直到框的前导边与网格边界重合（即框紧贴该方向的网格边缘），然后绘制该框的完整边框。后绘制的框覆盖先绘制的框。

**关键洞察**：遮挡不仅决定层序（已知用法），还隐含方向信息——每个框被遮挡最严重的那条边指示了"压力来源"，框朝反方向逃逸。求解者必须同时重建几何形状、推断层序、并统计逐边遮挡分布才能确定输出。

## 新题 3：对角射线选择腔室 + 控制矩阵着色

**组合逻辑**：[射线延伸/ray_extend](创新：射线不涂色，仅用于几何选择) + [索引映射/index_mapping](原有) + [填充/fill](原有) ← [对角线激活/diagonal_activation](创新：从涂色通道变为选择通道) + [行列位置对应/row_column_correspondence](原有) + [标记指定腔室/marker_designates_cavity](创新：由射线间接指定而非直接邻接)

**来源原语**：射线延伸(#d07ae81c, #95755ff2)、索引映射(#33b52de3)、填充(#17b866bd)、对角线激活(#d07ae81c)、格点骨架(#17b866bd)、封闭腔室(#17b866bd)、控制矩阵(#33b52de3)、行列位置对应(#33b52de3)

**依赖链**：对角射线从标记出发穿过格点骨架，经过的腔室被"激活"（几何选择）。被激活的腔室需要着色，但颜色不来自射线本身——而是查询控制矩阵中对应(行,列)位置的颜色（索引映射）。射线决定"哪些腔室填色"，控制矩阵决定"填什么色"——两个独立信息源在腔室位置处交汇，缺少任一源则输出不可确定。

用一行自然语言概括：标记像素发射对角射线穿过格点骨架来选中腔室，被选中腔室的填充颜色由角落控制矩阵中的对应位置决定。

**输入结构**：约 17x17 的网格。青(8)格点骨架构成规则网格，围出 M 行 N 列的封闭腔室（M, N 各为 3~5），每个腔室内部为 2x2 或 3x3 的黑(0)区域。网格右上角（格点骨架外部）有一个 M 行 N 列的密集控制矩阵，每个单元格为一种前景色（从红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、品红(6)中选取，同一控制矩阵中颜色可重复）。格点骨架的交叉节点（青色十字交叉处）上有 1~2 个标记像素，颜色为栗(9)，占据原本应为青(8)的格点位置。生成约束：标记像素位于格点交叉节点（而非腔室内部或骨架臂上）；控制矩阵的行列数与腔室网格的行列数一致；每个标记的四条对角射线至少经过一个腔室。

**规则**：
1. 识别格点骨架的周期结构，确定腔室网格的行列编号（从左上角 (0,0) 开始）。
2. 从每个栗(9)标记像素出发，沿 NW、NE、SW、SE 四个对角方向发射射线，射线穿过格点骨架直达网格边缘。
3. 射线经过的每个腔室被标记为"激活"。判断"经过"的标准：射线的 45 度路径与腔室内部的黑(0)区域有至少一个像素相交。
4. 对每个被激活的腔室，查找控制矩阵中同 (行, 列) 位置的颜色。
5. 将该腔室内部所有黑(0)像素填充为查到的颜色。
6. 未被任何射线激活的腔室保持黑(0)不变。
7. 格点骨架（青(8)）、标记像素（栗(9)）和控制矩阵均保持不变。

**关键洞察**：对角射线在此题中不执行涂色（与参考题 d07ae81c 不同），而是充当空间选择器——它画出一条几何路径来"点名"腔室。颜色信息来自完全独立的控制矩阵，两种信息必须在腔室坐标处对齐才能确定输出。

## 新题 4：菱形框射线填充后的图例色换

**组合逻辑**：[射线延伸/ray_extend](原有) → [重涂色/recolor · 颜色互换](创新：互换对象不是输入原色，而是射线填充的中间结果色) ← [遇阻停止/stop_at_blocker](原有) + [图例行内配对/legend_row_pairing](原有) + [同行颜色互换/same_row_bidirectional_swap](创新：作用于中间结果而非输入)

**来源原语**：射线延伸(#95755ff2)、重涂色/颜色互换(#0becf7df)、菱形框(#95755ff2)、侧标记(#95755ff2)、阻挡像素(#95755ff2)、图例(#0becf7df)、框内填充(#95755ff2)、图例行内配对(#0becf7df)、遇阻停止(#95755ff2)、同行颜色互换(#0becf7df)

**依赖链**：侧标记向菱形框内部发射射线并填色（射线延伸），产生中间状态。图例的行配对规则随后将中间状态中的射线色互换为其配对色（重涂色）。输出中可见的颜色既不是侧标记色，也不直接是图例中的某一色，而是由"哪个标记发射了射线"和"图例怎么配对"共同决定。跳过射线步骤则没有填充区域可供互换；跳过互换步骤则输出颜色与实际不符。

用一行自然语言概括：侧标记向菱形框内射线填色后，图例将所有射线填充色互换为配对色，输出是经两层变换后的最终颜色。

**输入结构**：约 15x15 的网格，黑(0)背景。中央有一个灰(5)的单像素厚菱形框（旋转 45 度的正方形，对角线长约 9~11 像素，边沿 45 度方向）。菱形框外部、紧贴菱形边界框的上下左右四个基本方位上各有 0~1 个侧标记像素，共 2~3 个侧标记，使用红(2)、蓝(1)、黄(4)中的颜色（每个标记颜色不同）。菱形内部有 1~2 个绿(3)的阻挡像素。网格的左下角（菱形外部）有一个 2x2 的图例块，定义两行配对：第一行为红(2)和蓝(1)，第二行为黄(4)和橙(7)。生成约束：侧标记颜色均在图例中出现（否则互换无法定义）；菱形内部足够大以容纳有意义的射线路径（内部至少 5x5 像素）；阻挡像素不位于射线的起始行/列的边界（保证射线至少填充 1 个像素）。

**规则**：
1. 每个侧标记沿其所在方位的垂直方向（顶部标记向下，底部向上，左侧向右，右侧向左）向菱形内部发射射线。
2. 射线沿该行或列逐像素推进，仅绘制严格位于菱形内部的黑(0)背景像素，将其涂为该标记的颜色。
3. 射线遇到绿(3)阻挡像素或菱形框边缘（灰(5)）时停止，不覆盖阻挡像素和框边缘。
4. 所有射线填充完成后，对网格中所有严格位于菱形内部且刚被射线涂色的像素执行图例互换：查找该像素颜色在图例中的位置，将其替换为同一行中的另一种颜色。例如：射线填充的红(2)像素 → 替换为蓝(1)；射线填充的蓝(1)像素 → 替换为红(2)；射线填充的黄(4)像素 → 替换为橙(7)。
5. 阻挡像素（绿(3)）不受互换影响。菱形框（灰(5)）不变。图例块本身不变。侧标记像素不变。未被射线覆盖的黑(0)内部像素不变。

**关键洞察**：输出中菱形内部的颜色不是侧标记的颜色——求解者会观察到标记是红色但内部出现的是蓝色，必须发现存在一个两步变换：先射线填色（标记色），再图例互换（配对色）。仅看输出无法反推是哪个标记造成的，必须理解中间步骤。

## 新题 5：像素计数排序堆叠与交替镜像

**组合逻辑**：[计数/count](原有) → [排序/sort](原有) → [堆叠/stacking](原有) + [镜像/reflect](创新：镜像方向不由空间位置决定，而由排序后序号的奇偶性决定) ← [数量决定输出宽/count_determines_width](创新：数量决定排序键而非直接决定尺寸)

**来源原语**：计数(#d631b094, #bd283c4a)、排序(#68bc2e87, #bd283c4a)、堆叠(#4acc7107)、镜像(#8d5021e8)、单色前景对象(#4acc7107)、前景像素(#d631b094)、位置排序(#4acc7107)、对齐紧凑排布(#4acc7107)

**依赖链**：计数每个精灵体的像素总数 → 以此为键排序精灵体 → 排序后的位置编号决定是否施加水平镜像（奇数位原样、偶数位镜像）→ 垂直堆叠输出。计数结果决定排序顺序，排序顺序决定镜像与否，镜像影响最终视觉结果——三步依赖链中任一环节不可跳过。

用一行自然语言概括：将散布的彩色精灵体按像素数升序堆叠，偶数位的精灵体水平翻转。

**输入结构**：约 12x18 的网格，黑(0)背景。网格中散布 4~5 个小型单色 4-连通精灵体，每个使用不同颜色（如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)），像素数各不相同，范围在 3~8 像素之间。每个精灵体的边界框不超过 4x4。精灵体之间互不相邻（8-连通距离至少为 2）。生成约束：所有精灵体的像素数互不相等（保证排序唯一）；每个精灵体关于垂直轴不对称（否则水平镜像无可观测效果）。

**规则**：
1. 识别网格中所有 4-连通的单色前景对象（精灵体）。
2. 统计每个精灵体的像素数量。
3. 按像素数量从小到大排序（最少的排第 1 位）。
4. 将每个精灵体裁剪为其边界框大小。
5. 对排序后位置为偶数的精灵体（第 2、4、...位）执行水平镜像（沿垂直轴左右翻转）。奇数位（第 1、3、5、...位）保持原样。
6. 从上到下依次垂直堆叠所有精灵体（第 1 位在最上方），相邻精灵体之间留 1 行黑(0)间隔。
7. 所有精灵体在输出中水平居中对齐。输出宽度等于最宽精灵体边界框的宽度，高度等于所有边界框高度之和加上间隔行数。若精灵体宽度小于输出宽度，两侧用黑(0)填充；若宽度差为奇数，多余的 1 列黑(0)加在右侧。

**关键洞察**：精灵体的像素数量不仅是一个统计量，更是决定视觉变换（镜像与否）的隐式控制参数——它通过排序位置的奇偶性间接编码了反射指令。求解者需要对比多个示例才能发现"偶数位翻转"的模式。

## 新题 6：边框周期长度驱动内部前缀续写

**组合逻辑**：[平铺/tile · 环形重复](原有) + [外推/extrapolate · 前缀续写](原有) ← [环形周期/cyclic_period](创新：周期值不仅用于边框自身重复，还传递给内部操作作为参数) + [前缀匹配/prefix_matching](原有) + [间隔等长重复/repeat_equal_gap](原有) + [完整模式续写缺失/missing_suffix_continued_from_pattern](创新：续写列数由外部参数决定而非自动补满)

**来源原语**：平铺(#30f42897)、外推(#90f3ed37)、边框段(#30f42897)、行组(#90f3ed37)、列状态序列(#90f3ed37)、矩形边界(#30f42897)、环形周期(#30f42897)、前缀匹配(#90f3ed37)、间隔等长重复(#30f42897)、完整模式续写缺失(#90f3ed37)

**依赖链**：边框上的彩色段通过环形重复补全整个边框（平铺），但同时这个彩色段的长度 L 被提取出来作为参数传递给内部操作——内部的每个不完整行组恰好续写 L 列（外推）。边框操作和内部操作共享同一个数值参数 L，但各自用于不同目的（边框用作重复间隔，内部用作续写长度）。若不从边框提取 L，内部续写列数无法确定；若不完成内部续写，边框的周期信息就是冗余的。

用一行自然语言概括：补全边框的环形彩色段重复模式，同时将边框段长度作为列数参数，续写网格内部每个不完整行组的缺失后缀。

**输入结构**：约 13x13 的网格。网格的矩形边框（最外一圈像素）以灰(5)为底色，其上有一段连续的红(2)像素（长度 L，2~4 像素），位于边框的某条边上。网格内部（边框以内的区域）结构如下：顶部有一个完整的参考行组（1~2 行），横跨整个内部宽度，使用蓝(1)和黄(4)两色交替或形成某种列状态模式。下方有 2~3 个不完整行组，每个行组从左侧开始，只覆盖部分列（是参考行组模式的前缀），颜色与参考行组一致。行组之间用黑(0)行分隔。生成约束：红色边框段的长度 L 满足 2 <= L <= 4；每个不完整行组的前缀长度加上 L 不超过内部宽度（保证续写不越界）；参考行组的列状态模式至少有 2 种不同状态（否则续写无意义）。

**规则**：
1. 识别边框上的红(2)段，记其长度为 L。
2. 将边框展开为顺时针环形路径。从红色段起始位置开始，每隔 2L 个边框位置（即 L 个红色 + L 个间隔）放置一段长度为 L 的红(2)像素，环绕整个边框，仅覆盖原为灰(5)的位置。
3. 识别内部区域的参考行组（最靠近顶部、跨越全部列的那组行），提取其逐列的颜色状态序列。
4. 对每个不完整行组，确定其已有内容匹配参考行组模式的哪个前缀位置。
5. 从匹配位置之后继续参考行组的列状态模式，恰好续写 L 列。续写像素使用绿(3)（与原有颜色区分，标示续写部分）。
6. 若续写过程中参考模式走到末尾，则循环回到参考模式的起始状态继续。
7. 边框内部的参考行组本身不变。黑色分隔行不变。

**关键洞察**：边框图案的几何参数（彩色段长度 L）跨越空间结构传递给完全不同的内部操作，充当隐式的数值指令。求解者必须发现边框和内部之间通过 L 建立的联系——这是两个看似独立的视觉结构之间的隐藏耦合。

## 新题 7：重叠框遮挡像素数编码为色条高度

**组合逻辑**：[补全/reconstruct](原有) → [计数/count](创新：计数对象是每个框被遮挡的像素而非总像素) → [压缩/compress](创新：压缩为柱状色条而非单行) ← [遮挡层序/occlusion_order](原有，同时决定输出列序) + [高度编码数量/height_encodes_count](创新：高度编码遮挡深度而非原始频率)

**来源原语**：补全(#68bc2e87)、计数(#d631b094, #bd283c4a, #a1aa0c1e)、压缩(#d631b094, #a1aa0c1e)、空心矩形(#68bc2e87)、重叠层(#68bc2e87)、色条(#a1aa0c1e)、遮挡层序(#68bc2e87)、高度编码数量(#a1aa0c1e)、重叠定先后(#68bc2e87)

**依赖链**：从可见像素重建完整矩形框（补全）→ 通过重叠位置确定层序（遮挡分析）→ 逐框计算被遮挡的像素数（计数）→ 以遮挡像素数为高度、层序为列序输出柱状图（压缩编码）。补全是计数的前提（不知道完整框就无法算遮挡量），层序同时服务于两个目的（确定谁遮挡谁 + 确定输出列序），计数结果直接编码为几何高度。整条链不可跳步。

用一行自然语言概括：重建重叠矩形框并推断层序，将每个框被上层遮挡的像素数量编码为柱状色条高度，按从底层到顶层排列输出。

**输入结构**：约 14x14 的网格，黑(0)背景。3~4 个单像素厚的空心矩形框，每个框使用不同的前景色（如红(2)、蓝(1)、绿(3)、黄(4)）。框的尺寸在 4x4 到 9x9 之间，彼此部分重叠——重叠区域只显示最上层框的颜色。生成约束：每个框至少有一条完整边可见（保证边界框可重建）；至少有两个不同的框存在被遮挡像素（否则柱状图退化）；不同框的被遮挡像素数互不相等（保证柱状图各列高度不同）；最顶层框的被遮挡像素数为 0。

**规则**：
1. 对每种前景色，从其可见像素推断完整矩形框的边界框（取可见像素的行列极值）。
2. 重建每个框的完整单像素边框。
3. 确定层序：在两个框的重叠像素位置上，可见颜色所属的框在上层。对所有约束取传递闭包得到从底到顶的全序。
4. 对每个框，统计其完整边框中被其他上层框遮挡的像素数量（即：属于该框边框但在输入中显示为其他框颜色的像素总数）。
5. 输出一个紧凑网格：列数 = 框的数量，高度 = 所有框中最大遮挡像素数（若该值为 0 则高度为 1）。
6. 列从左到右对应层序从底层到顶层的框。
7. 每一列从底部向上填充该框颜色的像素，填充行数 = 该框的被遮挡像素数。最顶层框（遮挡数为 0）的列全部为黑(0)。
8. 未填充的单元格为黑(0)。

**关键洞察**：重叠框的遮挡信息同时服务两个用途：层序决定了输出的列排列，而遮挡像素的具体数量——一个不直接可见的几何量，需要同时知道完整框形状和层序才能计算——被编码为色条高度。这是将空间遮挡关系压缩为一维频率图的信息变换。
