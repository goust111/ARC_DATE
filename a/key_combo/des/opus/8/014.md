## 新题 1：对称性门控洪泛填充

**组合逻辑**：[裁剪(crop)] → [对称检测(symmetry)](创新：对称性从选择标准改为触发门控) → [洪泛填充(flood_fill)](创新：填充色由精灵体自身颜色决定而非独立标记像素)

**来源原语**：裁剪/crop、对称/symmetry、对称图案选取/symmetric_selected（来自 d56f2372）；洪泛填充/flood_fill、封闭区域/enclosed_region、墙壁/wall（来自 e69241bd）；精灵体/sprite（来自 c62e2108/845d6e51）

**依赖链**：墙壁将网格分割为封闭腔室，每个腔室内有一个精灵体。精灵体的裁剪结果经对称性检测后决定是否触发洪泛填充——对称性检测的输出是一个布尔门控信号，直接改变了洪泛填充是否执行。同时精灵体自身的颜色提供填充色，使精灵体同时承担"检测对象"和"颜色源"的双重角色。

将每个腔室内精灵体的垂直对称性作为门控条件：对称则洪泛填充整个腔室，不对称则擦除精灵体。

**输入结构**：约 15x15 的网格。背景为黑(0)。灰(5)像素构成一像素宽的连通墙壁路径，将网格分割为 3-5 个互不相通的封闭腔室（每个腔室为 4-连通的黑色背景区域，完全被灰墙或网格边界包围）。每个腔室内恰好有一个单色的 4-连通小精灵体（3-6 像素），各精灵体颜色互不相同，使用红(2)、蓝(1)、绿(3)、黄(4)等颜色。精灵体形状多样：有的裁剪到包围框后左右对称（如竖线、十字、倒T等），有的不对称（如阶梯形、不规则弯折等）。生成约束：每个腔室恰好包含一个精灵体；精灵体不与墙壁相邻（至少间隔一个背景像素）。

**规则**：
1. 识别灰(5)墙壁，找出所有被墙壁或网格边界完全围住的 4-连通黑色背景腔室。
2. 对每个腔室内的精灵体，裁剪到其包围框范围。
3. 判断裁剪结果是否关于垂直中轴左右对称（即与自身的左右镜像完全一致）。
4. 若对称：以该精灵体的颜色对整个腔室执行 4-连通洪泛填充（腔室内所有黑色背景像素变为精灵体颜色，精灵体自身像素不变，结果是整个腔室被该颜色充满）。
5. 若不对称：擦除该精灵体（其像素变为黑色背景），腔室保持为空。
6. 灰色墙壁保持不变。

**关键洞察**：精灵体承担双重角色——其几何属性（对称性）是门控条件，其颜色是填充参数；对称性从"选哪个输出"变成了"是否执行空间操作"的开关。

## 新题 2：裂缝方向决定平铺轴

**组合逻辑**：[裂缝检测(fracture_line)](创新：裂缝方向不再用于分离，而是编码平铺方向指令) → [擦除(erase)] → [平铺(tiling)](创新：平铺轴由裂缝方向参数化而非固定)

**来源原语**：裂缝标记线/fracture_line、沿短轴分裂/split_along_short、擦除/erase（来自 2faf500b）；平铺/tiling、精灵体/sprite（来自 c62e2108/9b30e358）

**依赖链**：裂缝方向的检测结果直接参数化了平铺操作的轴向——水平裂缝使平铺沿垂直方向进行，垂直裂缝使平铺沿水平方向进行。裂缝擦除后的对象形态成为平铺的母体图案，裂缝方向决定母体图案的重复方向。三个环节形成信息流：裂缝→方向参数+母体形态→轴向平铺。

检测每个对象中裂缝线的方向，擦除裂缝后将对象作为母体，沿裂缝的垂直方向周期平铺至网格边界。

**输入结构**：约 18x18 的网格。背景为黑(0)。网格中有 2-3 个互不接触的 8-连通前景对象，每个对象由体色（如红(2)、蓝(1)、绿(3)，各对象体色不同）和标记色橙(7)组成。每个对象的包围框为非正方形矩形。标记色像素在每个对象内形成一条完整的直线，横贯对象包围框的短轴方向：若包围框宽>高，则标记线为垂直线（跨越全部行）；若高>宽，则标记线为水平线（跨越全部列）。对象之间有足够空间使平铺后不会与其他对象的原始位置冲突。生成约束：各对象的平铺方向互不干涉（即沿平铺轴方向上，两个对象不在同一行带或列带内，从而平铺扩展不会相互覆盖）。

**规则**：
1. 找出所有 8-连通前景对象，每个对象包含体色像素和橙(7)标记像素。
2. 对每个对象，检测标记像素的排列方向：若标记像素的列坐标相同（竖直排列），则裂缝方向为垂直；若行坐标相同（水平排列），则裂缝方向为水平。
3. 擦除所有橙(7)标记像素（变为背景色）。
4. 剩余的体色像素构成平铺母体。
5. 若裂缝方向为水平：将母体沿垂直方向周期重复——以母体包围框高度为周期，向上向下重复至网格边界，保持水平位置不变。
6. 若裂缝方向为垂直：将母体沿水平方向周期重复——以母体包围框宽度为周期，向左向右重复至网格边界，保持垂直位置不变。
7. 超出网格边界的部分裁剪丢弃。母体中属于背景色的像素在平铺时不覆盖其他内容（仅复制非背景像素）。

**关键洞察**：裂缝线不是用来把对象掰开的（源题用途），而是一条方向指令——其朝向编码了平铺应沿哪个轴展开，平铺轴始终垂直于裂缝方向。

## 新题 3：象限异常值定位周期修复目标

**组合逻辑**：[相等比较(equality_comparison) + 异常值选择(outlier_selection)](定位操作对象) ↔ [补全(completion) + 周期瓦片推断(periodic_tile)](修复操作) — 两步互相依赖：异常值选择确定修复目标的位置，而多数象限提供修复所需的周期信息

**来源原语**：象限/quadrant、分隔十字/separator_cross、相等比较/equality_comparison、异常值选择/outlier_selection（来自 88a62173）；周期瓦片/periodic_tile、补全/completion、标记为缺失值/markers_missing_val、行列周期/row_col_period（来自 f823c43c）

**依赖链**：四象限比较产生两类输出——异常值象限（操作的目标区域）和多数象限组（修复信息的来源）。多数象限各自含有品红缺损，但同一位置不会在所有三个多数象限中同时缺损，因此交叉比对可还原完整周期瓦片。还原后的瓦片用于覆写异常值象限的内容。异常值检测和周期推断必须协同工作：检测不出异常值就不知道往哪里写，推断不出周期瓦片就不知道写什么。

找到四象限中的异常值，用其余三个象限交叉还原的周期瓦片替换异常值象限的内容。

**输入结构**：奇数行奇数列（如 13x13）的网格。中间行和中间列为黑(0)背景色，形成分隔十字，将网格分为四个大小相同的矩形象限。三个象限包含相同的底层双色周期图案（如红(2)和蓝(1)交替），但每个象限中有若干像素被替换为品红(6)（缺损标记），同一网格位置（相对于象限左上角）至多在两个多数象限中同时缺损（保证可修复）。第四个象限（异常值）包含完全不同的图案（如绿(3)和黄(4)组成的非周期图形）。生成约束：三个多数象限的底层周期图案完全一致；每个缺损位置至少有一个多数象限保留了原始颜色；异常值象限与多数象限的图案明显不同（不只是缺损差异）。

**规则**：
1. 将网格沿分隔十字分为四个象限区域（不含分隔十字本身的行列）。
2. 两两比较四个象限（比较时将品红(6)视为通配符，与任何颜色匹配）。找出三个互相兼容的象限（多数组）和一个与其余三个都不兼容的象限（异常值）。
3. 对多数组的三个象限，逐像素交叉比对：在每个位置，取非品红的颜色值作为该位置的真实值（若三个象限在该位置都非品红且一致，直接取值；若部分为品红，取非品红值）。由此还原出完整的无缺损象限图案。
4. 用还原的完整图案替换异常值象限的全部内容。
5. 输出完整网格（分隔十字、多数象限保持原样不变，仅异常值象限被替换）。

**关键洞察**：异常值检测和周期修复不是先后独立的两步——异常值检测的副产品（多数组的确定）恰好提供了修复所需的冗余信息源，两个操作共享同一次比较的结果。

## 新题 4：中轴提取后种子环形扩展与归属分割

**组合逻辑**：[擦除(erase) + 仅保留中轴(center_axis_only)](滤波产生种子布局) → [同心环扩展(concentric_ring) + 奇偶距离决定填色(parity_distance_fill)](几何生成) + [最近归属(nearest_ownership)](冲突裁决) — 非线性结构：滤波产生的种子布局同时被环扩展和归属计算使用

**来源原语**：中轴列/center_column、仅保留中轴/center_axis_only、擦除/erase（来自 d23f8c26）；同心环/concentric_ring、最近归属/nearest_ownership、奇偶距离决定填色/parity_distance_fill、角标记像素/corner_marker（来自 d22278a0）

**依赖链**：中轴提取是一个空间滤波操作，它决定了哪些像素成为环形扩展的种子点。种子的颜色和位置共同决定输出——颜色成为环的填充色，位置决定环的几何中心和归属边界。滤波步骤从根本上改变了后续几何生成的空间结构。删除滤波步骤意味着种子位置完全不同，环形图案随之改变；删除环扩展则滤波结果仅为一条线段，无二维结构。

提取网格中轴列上的非背景像素作为种子，从每个种子向外扩展偶数Chebyshev距离的同心方环，环之间由最近归属边界切分。

**输入结构**：约 15x15 的网格，列数为奇数。背景为黑(0)。前景像素分布在网格各处，使用 2-4 种颜色（如红(2)、蓝(1)、绿(3)、黄(4)）。中轴列（第 (列数-1)/2 列）上有 2-4 个非背景像素，颜色各不相同，行位置间距至少为 3（使扩展的环有足够空间可见）。中轴列以外的前景像素是干扰项，形状和位置随意。生成约束：中轴列上的种子像素之间至少隔 3 行。

**规则**：
1. 创建与输入同尺寸的全黑(0)画布。
2. 提取输入中轴列（第 (列数-1)/2 列）的所有像素。非背景像素成为种子点，记录其行坐标和颜色。忽略输入中所有其他列的像素。
3. 对输出画布上的每一个像素位置 (r, c)，计算它到每个种子 (r_i, c_mid) 的 Chebyshev 距离 d_i = max(|r - r_i|, |c - c_mid|)。
4. 找出距离最小的种子。若存在两个或以上种子到该位置的 Chebyshev 距离相等（平局），该位置保持黑(0)。
5. 若有唯一最近种子，且该位置到最近种子的 Chebyshev 距离为偶数（包括 0），则涂上该种子的颜色；距离为奇数则保持黑(0)。
6. 输出结果画布。

**关键洞察**：中轴提取不只是裁剪——它是一个将散乱的二维输入降维到一维种子序列的滤波操作，而这个种子序列的具体内容（颜色与间距）决定了二维环形图案的全部特征，构成"降维→重新展开"的信息流。

## 新题 5：形状图例匹配联合包围框宽度平移

**组合逻辑**：[形状匹配(shape_matching) + 旋转反射等价(rotation_reflection_equivalence)](查表获取颜色) ∥ [按自身宽度平移(shift_by_own_width) + 边界框决定偏移(bounding_box_determines_offset)](空间变换) → [重涂色(recolor)](合并应用) — 并行信息流：匹配决定颜色，几何属性决定位移，两者独立计算后合并

**来源原语**：形状匹配/shape_matching、旋转反射等价/rotation_reflection_equivalence、图例区域/legend_region、分隔线/divider、精灵体/sprite（来自 845d6e51）；平移/translate、连通分量/connected_component、边界框决定偏移/bounding_box_determines_offset、按自身宽度平移/shift_by_own_width（来自 64a7c07e）；重涂色/recolor（来自多题）

**依赖链**：形状匹配和包围框宽度计算分别从同一个查询精灵体中提取不同信息——前者提取形状特征用于颜色查表，后者提取几何尺寸用于位移计算。两条信息流在最终的"涂色+放置"步骤中汇合。删除匹配则不知道涂什么色，删除平移则不知道放在哪里，两者缺一不可。

通过图例匹配确定每个查询精灵体的目标颜色，同时将其向右平移自身包围框宽度的距离，在新位置涂上匹配到的颜色。

**输入结构**：约 16x16 的网格。背景为黑(0)。灰(5)一像素宽的 L 形分隔线从上边缘向下延伸再向右延伸至左边缘附近，将左上角围成一个矩形图例区域（约 5x5 到 7x7）。图例区域内有 3-4 个单色模板精灵体，每个由不同颜色绘制（红(2)、蓝(1)、绿(3)、黄(4)），像素数 3-5，形状互不相同（即使考虑全部旋转和反射后仍互不同构）。图例外区域（分隔线右侧和下方）散布若干橙(7)色的查询精灵体，每个查询精灵体的形状恰好与某个模板在某种旋转/反射下同构。各查询精灵体右侧有不少于自身包围框宽度的空白空间。生成约束：查询精灵体互不相邻；每个查询精灵体平移后不与其他查询精灵体的原始或目标位置重叠；图例中每个模板至少被一个查询精灵体匹配。

**规则**：
1. 识别 L 形灰(5)分隔线，确定图例区域和查询区域。
2. 提取图例区域中每个模板精灵体的形状（4-连通像素集裁剪到包围框）和颜色，建立形状→颜色映射表。
3. 对查询区域中每个橙(7)的 4-连通精灵体：
   a. 裁剪到包围框，在所有 8 种旋转/反射变体下与映射表中的每个模板形状比对，找到匹配的模板，记录目标颜色。
   b. 计算该精灵体包围框的宽度 W。
   c. 擦除精灵体原始位置的所有像素（变为黑(0)）。
   d. 将精灵体的每个像素向右平移 W 列（保持行坐标不变），涂上目标颜色。
4. 分隔线和图例区域保持不变。

**关键洞察**：形状匹配提供的是语义信息（颜色身份），包围框宽度提供的是几何信息（位移距离），两者从同一个对象的不同属性中独立提取，在输出时才合并——查询精灵体同时是"查表键"和"位移参数源"。

## 新题 6：空白行双重角色——计数即游程长度，位置即填充目标

**组合逻辑**：[全空行列检测(fully_blank_row_column)](同一结构特征同时产生两种信息) →→ [计数(counting)](空白行数 = 游程长度参数 N) + [位置标记](空白行位置 = 填充目标) → [循环填充(cyclic_fill) + 调色板列(palette_col)](游程长度 N 驱动的循环涂色)

**来源原语**：全空行列/fully_blank_row_column、空行列涂标记色/blank_lines_painted_marker（来自 c1d99e64）；循环填充/cyclic_fill、调色板列/palette_col、标记高度决定长度/marker_height_run_len、擦除/erase（来自 e7b06bea）；计数/counting（来自 e872b94a/d5c634a2）

**依赖链**：空白行集合提供两种本质不同的信息——它们的数量 N 成为循环填充的游程长度参数，它们的行位置标识了填充操作的目标行。这种"同一结构特征同时编码参数和目标"的双重角色是组合的核心，任何一种信息缺失都使问题无法求解。调色板列提供颜色序列，被空白行计数和位置共同消费。

检测网格中全为背景色的行，以其数量为游程长度，从调色板列读取颜色序列，按该游程长度循环涂满这些空白行。

**输入结构**：约 14x10 的网格。背景为黑(0)。网格中有若干行含有非背景的前景像素（红(2)、蓝(1)等组成的图案，具体形状不限），其余行全为黑色（空白行），空白行分散在网格各处（不一定连续），数量为 2-4 行。网格最右侧一列为调色板列：从上到下排列 2-3 个不同颜色的单像素（如第 0 行为绿(3)、第 1 行为黄(4)、第 2 行为橙(7)），调色板列中其余位置为黑(0)。生成约束：空白行判断时包含调色板列（即一行算空白行当且仅当含调色板列在内的所有像素均为黑(0)）；调色板颜色像素所在行不是空白行。

**规则**：
1. 识别所有完全由黑(0)组成的行（包括最右列在内，每一列都为黑色），这些为空白行。
2. 计算空白行总数 N。
3. 读取最右列（调色板列）中的非黑像素，从上到下排列为调色板颜色序列 [C1, C2, ...]。
4. 擦除调色板列（最右列全部变为黑(0)）。
5. 将所有空白行按从上到下的顺序排列。以 N 为游程长度、调色板序列为颜色源进行循环填充：前 N 个空白行整行涂为 C1，接下来 N 个空白行整行涂为 C2，依此类推；调色板颜色用完后从 C1 重新循环。
6. 非空白行的所有像素保持不变（调色板列被擦除除外）。

**关键洞察**：空白行不只是"需要被涂色的目标"——它们的总数同时是游程长度参数 N 的编码载体。同一个结构特征被两种不同方式消费，这种双重角色使得仅看一个示例时难以区分"N 是固定常数"还是"N 由空白行数决定"，必须对比多个示例才能归纳。

## 新题 7：包围框宽度平移入腔后触发洪泛填充

**组合逻辑**：[平移(translate) + 按自身宽度平移(shift_by_own_width)](精确入腔) → [洪泛填充(flood_fill) + 标记色填充区域(marker_color_fills)](级联空间效应) — 级联结构：第一步的空间结果恰好满足第二步的触发前提

**来源原语**：平移/translate、连通分量/connected_component、边界框决定偏移/bounding_box_determines_offset、按自身宽度平移/shift_by_own_width（来自 64a7c07e）；洪泛填充/flood_fill、封闭区域/enclosed_region、墙壁/wall、标记像素/marker_pixel、标记在区域内/marker_inside、标记色填充区域/marker_color_fills（来自 e69241bd）

**依赖链**：小对象的包围框宽度恰好等于它与腔室入口之间的距离，使得"按自身宽度平移"精确地将对象从外部送入腔室内部。对象进入腔室后变为洪泛填充的标记像素，触发整个腔室的颜色填充。平移步骤的输出（对象在腔室内的位置）是填充步骤的前提（腔室内有标记），而平移距离由对象自身属性决定——三者环环相扣。

将腔室外的小对象按自身包围框宽度向右平移，恰好进入相邻腔室，然后以对象颜色洪泛填充整个腔室。

**输入结构**：约 16x16 的网格。背景为黑(0)。灰(5)像素构成墙壁，形成 3-4 个封闭腔室（4-连通黑色背景区域，完全被灰墙或网格边界包围）。每个腔室的左侧墙壁上有一个恰好一像素宽的缺口（开口），缺口所在行与腔室内部连通。在每个缺口的左侧（腔室外部），有一个小的单色 4-连通对象（2-4 像素），各对象颜色不同（红(2)、蓝(1)、绿(3)等）。每个对象的包围框宽度 W 恰好等于对象最右侧像素到缺口位置之间的水平距离，使得向右平移 W 格后，对象整体通过缺口进入腔室内部。生成约束：每个对象平移后完全位于对应腔室内部且不接触墙壁；各对象及其目标腔室一一对应，无歧义。

**规则**：
1. 识别灰(5)墙壁和所有封闭腔室。
2. 找出腔室外的每个非灰非黑的 4-连通小对象。
3. 对每个对象，计算其包围框宽度 W。将对象的每个像素向右平移 W 列（行坐标不变）。擦除原始位置（变为黑(0)）。平移后的对象像素出现在腔室内部。
4. 此时每个腔室内恰好有一个移入的彩色对象。以该对象的颜色对整个腔室执行 4-连通洪泛填充：腔室内所有黑色背景像素变为该对象颜色，对象像素本身保持不变（最终效果为整个腔室被对象颜色充满）。
5. 灰色墙壁保持不变。腔室外部除被擦除的原始对象位置外保持不变。

**关键洞察**：包围框宽度平移在源题中只是一个简单位移操作，这里它的位移距离被精确校准为"刚好穿过墙壁缺口进入腔室"——空间精确性将两个原本无关的操作（自身宽度位移和洪泛填充）串联为因果链。

## 新题 8：控制条跨度对齐双色体的分割-换色-滑移

**组合逻辑**：[跨度对齐(span_alignment)](配对控制条与目标对象) → [分割(split) + 颜色互换(color_swap)](对象内部变换) → [擦除(erase) + 滑动(slide)](控制条位置决定滑移方向) — 控制条同时编码三种信息：对齐选择目标、位置决定方向、擦除腾出空间

**来源原语**：控制条/control_bar、跨度对齐/span_alignment、沿控制条重复/repeat_along_bar、擦除/erase（来自 c62e2108）；分割/split、滑动/slide、双色物体/bicolor_object、颜色互换且偏移/color_swap_offset（来自 fc4aaf52）

**依赖链**：控制条通过列跨度对齐选中目标双色体，控制条相对于双色体的上下位置决定滑移方向（上方→上半部上滑，下方→下半部下滑），控制条被擦除后留出的空间恰好是滑移目标区域。控制条承担三重角色（选择、方向、空间），使其成为不可删除的核心枢纽。

识别与双色对象列跨度对齐的控制条，擦除控制条后将对象水平对半分割、互换双色，并将靠近控制条的半部滑向控制条原位置。

**输入结构**：约 18x14 的网格。背景为黑(0)。网格中有 2-3 个双色 4-连通对象，每个对象由恰好两种非背景色组成（如红(2)+蓝(1)、绿(3)+黄(4)），像素数 6-12，包围框高度为偶数。另有与对象数量相等的一像素厚水平控制条（栗(9)色），每条控制条的列跨度（最左列到最右列的范围）与恰好一个双色体的列跨度完全相同。每条控制条位于其配对双色体的正上方或正下方（同列跨度内），与双色体之间有 1-3 行的黑色间隔。生成约束：控制条与双色体一一配对，无歧义；每个双色体的包围框高度为偶数，使对半分割有确定的中线；滑移后不与其他对象重叠。

**规则**：
1. 找出所有栗(9)色水平控制条（同一行内的连续栗色像素段）。
2. 找出所有非黑非栗的 4-连通双色前景对象。
3. 对每条控制条，找到列跨度完全相同的双色体（配对）。
4. 擦除控制条（像素变为黑(0)）。
5. 对每个配对的双色体，设其包围框垂直中线将对象分为上半部和下半部：
   a. 上半部 = 包围框上半区域（上 H/2 行）内的所有对象像素。
   b. 下半部 = 包围框下半区域（下 H/2 行）内的所有对象像素。
6. 在上半部和下半部中分别互换两种前景色（例如原为红+蓝的像素，红变蓝、蓝变红）。
7. 判断配对的控制条在双色体的上方还是下方：
   a. 若控制条在上方（控制条行 < 双色体最小行）：将上半部整体向上滑动，直到上半部的最下行紧邻控制条原位置的行（即上半部的最下行移动到控制条所在行的下一行）。下半部保持原位。
   b. 若控制条在下方（控制条行 > 双色体最大行）：将下半部整体向下滑动，直到下半部的最上行紧邻控制条原位置的行（即下半部的最上行移动到控制条所在行的上一行）。上半部保持原位。
8. 滑移产生的原位置空缺变为黑(0)背景。

**关键洞察**：控制条不是被复制或平铺的对象（源题用途），而是一个三重信息编码体——其列跨度选择目标、其位置编码方向、其被擦除后的空间成为滑移目的地。

## 新题 9：区域计数编码滑移距离，朝向分类编码滑移轴

**组合逻辑**：[计数(counting) + 连通分量(connected_component) + 背景区域(bg_region)](左区信息提取) ∥ [分类(classify) + 朝向分组(orient_group)](右区精灵体属性判定) → [滑动(slide)](双参数驱动的空间变换) — 同时约束满足结构：滑移距离和滑移方向分别由两个独立信息源决定

**来源原语**：计数/counting、连通分量/connected_component、背景区域/bg_region、前景屏障/fg_barrier、区域数编码像素列/region_count_as_col（来自 e872b94a）；分类/classify、朝向分组/orient_group、朝向决定面板/orient_determines_panel（来自 d5c634a2）；滑动/slide（来自 fc4aaf52/2faf500b）；精灵体/sprite（来自多题）

**依赖链**：左区的屏障结构决定滑移距离（区域数 N），右区每个精灵体的几何朝向决定其滑移方向（宽→右移，高→下移）。两种信息来自完全不同的空间区域，必须同时获取才能确定每个精灵体的最终位置。这不是线性流水线——距离和方向是平行独立计算的，在滑移执行时才合并。

左区屏障分割出的背景区域数决定滑移距离 N，右区每个精灵体按包围框朝向沿对应轴滑移 N 格。

**输入结构**：约 14x18 的网格。背景为黑(0)。网格中间有一列灰(5)垂直分隔线，将网格分为左区和右区。左区包含红(2)前景像素构成的连通屏障路径（不规则折线），将左区的黑色背景分割为 2-5 个 4-连通背景区域。右区散布 3-5 个彩色小精灵体（4-连通，3-6 像素，颜色使用蓝(1)、绿(3)、黄(4)、橙(7)等，各不相同），每个精灵体的包围框为非正方形（要么宽>高，要么高>宽）。生成约束：灰色分隔线为单列；各精灵体互不接触；精灵体滑移 N 格后不超出网格边界且不与其他精灵体（原始位置或滑移后位置）重叠。

**规则**：
1. 识别灰(5)垂直分隔线，将网格分为左区和右区。
2. 在左区中，找出红(2)前景屏障像素。计算黑(0)背景像素构成的 4-连通分量数量，记为 N。
3. 对右区中每个非黑非灰的 4-连通精灵体，判断其包围框的朝向：
   a. 宽型（包围框宽度 > 高度）：该精灵体将沿水平方向滑移。
   b. 高型（包围框高度 > 宽度）：该精灵体将沿垂直方向滑移。
4. 执行滑移：
   a. 宽型精灵体：每个像素向右平移 N 列，行坐标不变。
   b. 高型精灵体：每个像素向下平移 N 行，列坐标不变。
5. 擦除每个精灵体的原始位置（变为黑(0)），在新位置绘制精灵体。
6. 左区（含屏障和分隔线）保持不变。

**关键洞察**：滑移操作的两个参数（距离和方向）由输入的两个不同空间区域分别编码——左区的拓扑结构（区域数）编码"走多远"，每个精灵体自身的几何属性（宽高比）编码"往哪走"。必须对比多个示例才能区分 N 是固定常数还是由左区区域数决定的。

## 新题 10：种子母体平铺遇空心矩形保护窗

**组合逻辑**：[平铺(tile) + 种子图案(seed_motif) + 周期重复(periodic_repeat)](全局图案生成) ⊗ [空心矩形(hollow_rect) + 内部区域(interior_region) + 标记框内保护(marker_bbox_protect)](局部保护区) — 冲突解决结构：两种操作修改同一区域时，保护规则胜出但保护区内部又有透明窗口

**来源原语**：种子图案/seed_motif、周期重复/periodic_repeat、平铺/tile、填满网格/fill_grid（来自 9b30e358）；空心矩形/hollow_rect、标记像素/marker_pixel、内部区域/interior_region、标记框内保护/marker_bbox_protect、填充/fill（来自 d37a1ef5）

**依赖链**：平铺操作试图覆盖全局网格，但空心矩形框定义的保护区阻止了局部覆写。然而保护区内部的标记像素又定义了一个"透明窗口"，窗口内的平铺结果被保留。这形成三层优先级：(1) 矩形框本身永远保持原色，(2) 框内部但窗口外的区域被清为背景（阻挡平铺），(3) 窗口内允许平铺穿透。三层缺任何一层都改变输出。

将底部种子图案向上周期平铺填满网格，但被空心矩形框包围的保护区内，仅在标记像素定义的窗口中显示平铺结果，窗口外的保护区恢复为背景。

**输入结构**：约 15x12 的网格。背景为黑(0)。底部 2-4 行包含一个使用红(2)和蓝(1)的双色种子图案（行内混有背景色像素，这些行整体构成种子母体）。网格中间偏上位置有一个绿(3)一像素宽的空心矩形框（高度和宽度各至少 4），框内部为黑色背景。框内部有若干黄(4)标记像素（2-4 个），这些标记像素的包围框定义一个矩形窗口区域（窗口严格小于框内部区域）。种子图案、矩形框和标记像素在空间上互不重叠。生成约束：种子母体是网格最下方的连续行块（从包含非背景像素的最低行向上取连续行）；标记像素的包围框严格位于矩形框内部区域内。

**规则**：
1. 识别底部种子图案：从网格底部开始，向上找到包含非背景像素的连续行块作为种子母体，行数为 P。
2. 识别绿(3)空心矩形框，记录框本身的像素位置和框的内部区域（严格在框边界之内的所有像素位置）。
3. 识别黄(4)标记像素，计算它们的包围框，定义矩形窗口区域 W。
4. 执行全局平铺：对网格中每个位置 (r, c)，计算对应的种子值 = 种子母体第 (r mod P) 行、第 c 列的颜色。用该值填充位置 (r, c)。
5. 应用保护规则（按以下优先级，后处理的覆盖先处理的）：
   a. 绿(3)矩形框的像素位置：强制设为绿(3)（框不被平铺覆盖）。
   b. 矩形框内部区域中、不在窗口 W 内的位置：强制设为黑(0)背景（保护区屏蔽平铺）。
   c. 窗口 W 内的位置：保留步骤 4 的平铺结果（窗口透传平铺），但黄(4)标记像素本身的位置强制保持黄(4)。
   d. 矩形框外部的位置：保留步骤 4 的平铺结果。
6. 输出最终网格。

**关键洞察**：平铺和保护不是顺序执行的两步——它们是一对覆盖全局的竞争规则，而标记像素在保护区内开了一个"透明窗口"，形成"全局平铺→局部屏蔽→窗口透传"的三级优先级冲突解决，仅看一个示例可能无法区分窗口内的像素是来自平铺还是巧合。

## 新题 11：颜色匹配边框侧面驱动定向半环扩展

**组合逻辑**：[边框(frame) + 颜色匹配边(color_matches_side) + 颜色决定目标边(color_determines_side)](颜色→方向映射) → [同心环(concentric_ring) + 奇偶距离决定填色(parity_distance_fill)](定向环扩展) + [擦除(erase)](清除原始标记) — 隐式编码结构：边框的颜色分布编码了空间展开的方向指令

**来源原语**：边框/frame、标记像素/marker_pixel、颜色匹配边/color_matches_side、颜色决定目标边/color_determines_side、移动/move、擦除/erase（来自 d687bc17）；同心环/concentric_ring、奇偶距离决定填色/parity_distance_fill、角标记像素/corner_marker（来自 d22278a0）

**依赖链**：边框四边各有不同颜色，框内标记像素的颜色匹配某一边。在源题 d687bc17 中，匹配结果是将标记移到对应边旁边；这里匹配结果被重新定义为：从标记位置向匹配边的方向扩展同心半环。颜色匹配提供方向信息，标记位置提供几何中心，奇偶距离规则提供涂色逻辑——三者缺一不可。

框内标记像素的颜色匹配某条边框侧面，从标记位置向该侧面方向扩展奇偶交替的同心半环。

**输入结构**：约 13x13 的网格。背景为黑(0)。一个一像素宽的矩形边框占据网格外围（或靠近外围），四条边分别为四种不同颜色：上边红(2)、下边蓝(1)、左边绿(3)、右边黄(4)。四角像素的颜色归属：左上角=上边色红(2)，右上角=右边色黄(4)，左下角=左边色绿(3)，右下角=下边色蓝(1)。框内部（边框围住的区域）为黑色背景，其中有 2-3 个单像素标记，每个标记的颜色恰好是四种边框颜色之一（如一个红(2)标记表示与上边匹配、一个绿(3)标记表示与左边匹配）。各标记之间至少间隔 3 行 3 列。生成约束：标记不紧贴边框（与边框至少间隔 2 个像素），使环扩展有空间可见；不同标记的半环扩展范围尽量不重叠。

**规则**：
1. 识别矩形边框及其四条边的颜色。记录上、下、左、右四边的颜色。
2. 找出框内部所有非黑标记像素，记录每个标记的颜色和位置 (r_m, c_m)。
3. 擦除所有标记像素（变为黑(0)）。
4. 对每个标记，按从上到下、从左到右的顺序依次处理：
   a. 找到与标记颜色相同的边框侧面，确定扩展方向：匹配上边→向上，匹配下边→向下，匹配左边→向左，匹配右边→向右。
   b. 从标记位置 (r_m, c_m) 开始，对从标记到对应边框之间（不含边框本身）的每个像素位置 (r, c)，计算 Chebyshev 距离 d = max(|r - r_m|, |c - c_m|)。
   c. 若 d 为偶数（含 0）且该位置位于标记到匹配边框方向的半平面内（向上扩展时 r <= r_m，向下时 r >= r_m，向左时 c <= c_m，向右时 c >= c_m），则涂上标记的颜色。
   d. d 为奇数或不在半平面内的位置不涂色。
5. 多个标记的半环扩展若在某位置重叠：后处理的标记（按步骤 4 中的处理顺序）覆盖先处理的。
6. 边框保持不变。

**关键洞察**：边框四边的颜色不只是装饰——它们是方向编码，标记像素通过颜色匹配"读取"这套编码来确定自己的环扩展方向。颜色从身份标识变成了空间指令。

## 新题 12：边缘填充扩展后对称性检测选取输出

**组合逻辑**：[边缘填充(edge_pad) + 复制扩展(outward_copy)](几何预处理) → [裁剪(crop) + 颜色掩码(color_mask)](按色分层) → [对称检测(symmetry) + 对称图案选取(symmetric_selected)](筛选输出) — 预处理改变后续检测结果的结构：同一掩码在扩展前后的对称性可能不同

**来源原语**：边缘填充/edge_pad、边缘行列/border_row_col、复制扩展/outward_copy、角像素双向扩展/corner_extends_both（来自 e633a9e5）；裁剪/crop、颜色掩码/color_mask、包围框/bounding_box、对称/symmetry、镜像/mirror、对称图案选取/symmetric_selected（来自 d56f2372）

**依赖链**：边缘填充改变了网格尺寸和边界像素分布，这可能使某些颜色掩码从不对称变为对称或反之。因此对称性检测的结果依赖于是否先执行了边缘填充——如果跳过扩展直接检测，选出的颜色可能完全不同。扩展操作不只是改变画布大小，它实质性地改变了后续判断的信息基础。

先将输入网格边缘填充扩展一圈，然后在扩展后的网格中按颜色分层裁剪，选出唯一具有垂直对称性的颜色掩码。

**输入结构**：一个较小的网格（如 7x7 或 9x9）。背景为黑(0)。包含 3-4 种非背景色（如红(2)、蓝(1)、绿(3)、黄(4)），每种颜色有若干分散的像素。关键设计：在原始网格中，没有任何颜色掩码的裁剪结果是垂直对称的（或有多个对称的，无法唯一选取）。但在边缘填充（将最外圈像素向外复制一层，角像素向两个方向扩展）之后，恰好有且仅有一种颜色的掩码裁剪结果变为垂直对称。生成约束：边缘填充后恰好一种颜色具有垂直对称裁剪；该颜色在原始网格的边缘行或边缘列上至少有一个像素（否则边缘填充不会改变其掩码形状）。

**规则**：
1. 对输入网格执行一像素边缘填充：创建 (H+2)x(W+2) 的新网格，原始网格放置在中心。上方新增行 = 原始第一行的副本，下方新增行 = 原始最后一行的副本，左方新增列 = 原始第一列的副本，右方新增列 = 原始最后列的副本。四个角落的新增像素 = 对应原始角像素的值。
2. 在扩展后的网格中，对每种非黑颜色，提取该颜色的掩码（所有该色像素的位置），裁剪到其包围框。
3. 判断每个颜色掩码的裁剪结果是否关于垂直中轴左右对称（即裁剪结果矩阵等于其左右翻转）。
4. 选出唯一具有垂直对称性的颜色掩码。
5. 输出该掩码的裁剪结果（包围框大小的子网格，该色像素保留原色，其余位置为黑(0)）。

**关键洞察**：边缘填充不是无意义的画布放大——它通过复制边界像素改变了颜色掩码的几何形状，使原本不对称的掩码变为对称。必须对比多个示例才能发现"先扩展再检测"的顺序依赖关系，而非直接在原图上检测对称性。
