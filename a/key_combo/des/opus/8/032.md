## 新题 1：奇偶门控方位印章

**组合逻辑**：[印章覆盖](方向从固定十字改为奇偶分支的条形) → [方位决定颜色](保留方向-颜色映射但作用于选定轴) ← [行列奇偶](创新：从矩形内部填充改为控制印章朝向)

**来源原语**：印章覆盖stamp_overlay(#19 d364b489)、方位决定颜色direction_color(#19 d364b489)、行列奇偶决定填充parity_fill(#2 ba9d41b8)

**依赖链**：标记像素的网格坐标奇偶性决定印章是水平条还是垂直条（条件门控），条的两端颜色再由相对标记的方位决定（方位-颜色映射）。奇偶判断和方位着色缺一不可：没有奇偶就无法确定条的朝向，没有方位映射就无法确定端点颜色。

将每个蓝色标记根据其坐标奇偶性展开为水平或垂直三像素条，端点颜色由其相对于标记的方位决定。

**输入结构**：约 11x11 的黑(0)背景网格。网格上散布 4~6 个蓝(1)孤立像素作为标记。任意两个标记之间的切比雪夫距离至少为 3（确保印章互不重叠）。输入中不含橙(7)、品红(6)、红(2)、青(8)像素。生成约束：所有标记均不在网格最外一圈边缘行/列上（确保两端均在网格内）。

**规则**：
1. 对每个蓝(1)标记像素，设其位置为 (r, c)。计算 (r + c) mod 2。
2. 若结果为 0（偶数奇偶）：生成水平三像素条——在 (r, c-1) 涂橙(7)，(r, c) 保持蓝(1)，(r, c+1) 涂品红(6)。
3. 若结果为 1（奇数奇偶）：生成垂直三像素条——在 (r-1, c) 涂红(2)，(r, c) 保持蓝(1)，(r+1, c) 涂青(8)。
4. 其余黑(0)背景不变。
5. 冲突处理：由生成约束保证印章不重叠，无需额外冲突规则。

**关键洞察**：标记的网格坐标奇偶性是一个隐藏的二元开关，选择水平还是垂直印章；单看一个示例无法判断开关来源（可能是行号、列号、行列之和等），需要对比多个示例中标记位置与印章朝向的对应关系才能归纳出 (r+c) mod 2 规则。

## 新题 2：拓扑寻色排序印模

**组合逻辑**：[洪泛填充/拓扑内外](创新：不做填充，仅用于读取被包围像素的颜色) → [排序](按边界空间位置排序) → [裁剪+重涂色+拼接](模板裁剪后按拓扑读取的颜色重涂，按排序结果拼接)

**来源原语**：拓扑内外topological_in_out(#8 00d62c1b)、仅填封闭内部fill_enclosed_only(#8 00d62c1b)、排序拼接sort_and_concatenate(#5 12997ef3)、裁剪crop(#1 0bb8deee)、重涂色recolor(#3 913fb3ed)、多像素模板multi_pixel_template(#5 12997ef3)

**依赖链**：拓扑分析确定每个封闭边界包围的像素颜色（这个颜色不是边界色，需要"看穿"边界去读取内部），该颜色作为模板重涂的色源；边界的空间位置提供排序键；排序结果决定拼接顺序。去掉拓扑分析就无法获取正确的重涂颜色（会误用边界色），去掉排序则拼接顺序不确定。

从封闭边界内读取隐藏色源，按边界从上到下排序，将灰色模板依次重涂为读取的颜色并垂直拼接输出。

**输入结构**：约 15x18 的黑(0)背景网格。左侧区域（约占 1/3 宽度）包含一个灰(5)多像素模板——一个 4-连通的单色形状，约 4~7 个像素，边界框约 3x3 或 3x4。右侧区域包含 3 个小的单色封闭环路（每个环路由不同颜色的像素围成，如蓝(1)、红(2)、绿(3)），每个环路内部恰好有 1 个像素，该像素颜色与其所在环路的边界颜色不同（如蓝边界内有黄(4)像素、红边界内有橙(7)像素、绿边界内有品红(6)像素）。三个封闭环路在垂直方向上互不重叠，水平方向也互不重叠。每个环路是一个不规则的 4-连通闭合曲线（非矩形），确保内部区域连通且恰好包含目标像素。生成约束：模板和环路之间无接触；环路内的像素颜色在整个网格中唯一出现于该环路内部（不与其他元素颜色重复）。

**规则**：
1. 将灰(5)模板裁剪至其紧凑边界框，作为印模形状。
2. 对右侧每个封闭环路，通过拓扑分析（4-连通洪泛填充检测）找到被边界完全包围的内部像素，读取该像素的颜色作为"色源"。
3. 按各环路最高行（边界框顶部行号）从小到大排序。
4. 依排序顺序，为每个色源生成一份印模副本，将灰(5)替换为该色源颜色。
5. 将所有副本从上到下垂直拼接（第一个副本的底行与第二个副本的顶行相邻，无间隔），输出拼接结果。左侧模板和右侧环路均不出现在输出中。

**关键洞察**：边界颜色是干扰项——重涂色源不是环路本身的颜色，而是被环路拓扑包围的内部像素颜色。仅看一个示例时，边界色和内部色都可能被当作色源，需要多个示例交叉验证才能排除边界色假设。

## 新题 3：方位吸附变色累积体

**组合逻辑**：[滑动+碰撞停止](保留累积机制) → [方位决定颜色](创新：来源方向决定落点颜色，而非全部统一为灰) ← [最短基方向吸附](选择滑动方向) + [累积影响后续停靠](顺序敏感)

**来源原语**：滑动sliding(#6 a48eeaf7, #17 4093f84a)、碰撞停止collision_stop(#6 a48eeaf7)、最短基方向吸附nearest_cardinal_attract(#17 4093f84a)、累积影响后续停靠mass_affects_stops(#17 4093f84a)、方位决定颜色direction_color(#19 d364b489)、重涂色recolor(#3 913fb3ed)

**依赖链**：每个彩色像素沿最短基数方向滑向灰色块体直至邻接（滑动+碰撞），但落点颜色不统一为灰——而是由滑动来源方向决定（方位映射），且先到达的像素改变块体轮廓，影响后续像素的停靠位置和来源方向判定（累积反馈）。方位映射使得同一像素从不同方向到达会产生不同颜色；累积使得处理顺序影响最终形状和颜色分布。

将散落的彩色像素按距离顺序吸向中央灰色方块，每个像素按其滑入方位变色后并入方块，先到者改变后到者的停靠位置。

**输入结构**：约 13x13 的黑(0)背景网格。中央偏左或偏右位置有一个灰(5)填充的 3x3 方块。方块四周散布 4~6 个彩色像素（颜色各异，可能为蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)等），每个像素与灰色方块在同一行或同一列上（基数方向对齐），距方块边缘 2~5 格不等。生成约束：同一行或同一列上最多一个彩色像素；每个基数方向（上/下/左/右）至少有一个像素；没有两个像素到灰色方块的曼哈顿距离相同（保证处理顺序无歧义）。

**规则**：
1. 计算每个彩色像素到灰(5)方块边缘的曼哈顿距离。按距离从小到大排序确定处理顺序。
2. 依次处理每个像素：将其从原位置擦除（变为黑(0)），沿其所在的基数方向朝灰色块体（含已累积的部分）滑动，直到下一步会与块体重叠时停止。
3. 在停靠位置涂上由来源方位决定的颜色（非像素原色）：
   - 从上方滑入（像素在块体上方，向下滑）→ 涂蓝(1)
   - 从右方滑入（像素在块体右方，向左滑）→ 涂红(2)
   - 从下方滑入（像素在块体下方，向上滑）→ 涂绿(3)
   - 从左方滑入（像素在块体左方，向右滑）→ 涂黄(4)
4. 涂色后该像素成为块体的一部分，影响后续像素的碰撞检测。
5. 原始灰(5)方块保持灰色不变。

**关键洞察**：像素的原始颜色是干扰项，完全被丢弃；输出颜色仅由滑入方位决定。需要多个示例确认这一点（排除"保留原色"和"按距离排序着色"等替代假设）。累积效应使得同一几何布局在不同距离排列下可能产生不同结果。

## 新题 4：标记象限编码全局旋转

**组合逻辑**：[裁剪(象限)](从十字分隔网格中提取四个精灵体) → [旋转](创新：旋转角度不由两个标记的角落关系指定，而由单个标记所在象限编码) → [拼接](重新组装为紧凑蒙太奇)

**来源原语**：裁剪crop(#1 0bb8deee)、十字分隔线cross_divider(#1 0bb8deee)、象限quadrant(#1 0bb8deee)、象限位置对应quadrant_correspondence(#1 0bb8deee)、旋转rotate(#7 ecaa0ec1)、标记像素marker_pixel(#7 ecaa0ec1)

**依赖链**：十字分隔定义四个象限，每个象限内有一个精灵体（裁剪提取）。某个象限中额外的单像素标记编码了一个全局旋转角度（象限位置→角度映射），该角度统一施加于所有四个精灵体。去掉十字分隔无法定义象限；去掉标记无法确定旋转角；去掉旋转则输出与源题#1 的蒙太奇相同。

从十字分隔的四象限中裁剪精灵体，由标记所在象限编码的角度统一旋转后重新拼成蒙太奇。

**输入结构**：约 11x11（奇数行列）的网格。灰(5)像素组成一条完整横行和一条完整纵列（十字分隔线），将网格分为四个大小相等的象限（每象限约 5x5）。每个象限内有一个单色精灵体（4-连通，3~5 像素，边界框 3x3），四个精灵体形状完全相同但颜色各异（如蓝(1)、红(2)、绿(3)、黄(4)）。背景为黑(0)。恰好一个象限内额外有一个品红(6)单像素标记，位于该象限的某个角落单元格（即象限内距离网格角最近的那个单元格），且不与精灵体重叠。生成约束：四个精灵体的形状关于其各自象限中心放置时非旋转对称（即 90 度旋转后形状可区分）。

**规则**：
1. 移除灰(5)十字分隔线。
2. 将每个象限中的精灵体裁剪至其 3x3 紧凑边界框。
3. 找到品红(6)标记所在的象限，根据象限位置确定旋转角度：
   - 左上象限 → 0 度（不旋转）
   - 右上象限 → 顺时针 90 度
   - 右下象限 → 180 度
   - 左下象限 → 顺时针 270 度
4. 将四个裁剪后的精灵体各自绕其 3x3 边界框中心旋转上述角度。
5. 将旋转后的四个 3x3 块按象限顺序（左上、右上、左下、右下）拼成 6x6 的 2x2 蒙太奇。品红标记不出现在输出中。

**关键洞察**：品红标记像素的象限位置是对旋转角度的隐式编码。标记不直接参与几何变换，也不指示源/目标角落（与源题 #7 不同）——它的位置本身就是一个查找键。需要至少两个示例（标记在不同象限）才能确认象限-角度映射规则。

## 新题 5：宽高比门控划线与奇偶蚀刻

**组合逻辑**：[连线](创新：划线方向不直接由短轴决定，而由宽高比通过奇偶门控间接决定) + [行列奇偶决定填充](创新：从独立填充改为与划线结果交互——线保护其所在单元格免受蚀刻) ← [边框与内部分离](区分矩形边框和内部)

**来源原语**：连线draw_line(#15 855e0971)、标记沿短轴展分割marker_short_axis_div(#15 855e0971)、行列奇偶决定填充parity_fill(#2 ba9d41b8)、边框与内部分离border_interior_split(#2 ba9d41b8)、包含containment(#15 855e0971)

**依赖链**：矩形宽高比决定标记划线方向（宽>高则竖线，高>宽则横线）；划线将矩形内部分区；随后奇偶蚀刻对内部非线单元格生效，但线上的单元格被"保护"不受蚀刻。划线和蚀刻共同作用于同一矩形内部，产生了交互效果：线的位置和方向直接影响蚀刻的视觉结果。

在非正方形矩形内部按宽高比确定方向划出标记线，再用奇偶棋盘格蚀刻未被线保护的内部区域。

**输入结构**：约 16x16 的黑(0)背景网格。包含 2~3 个单色实心矩形，颜色各异（如蓝(1)、红(2)、绿(3)），每个矩形至少 5x4 或 4x5（宽高不等，非正方形）。矩形之间互不重叠且不相邻（间隔至少 1 格）。每个矩形内部（不在边框上）有 1 个黑(0)标记像素。生成约束：标记像素不在矩形内部的最外一圈（即标记到矩形每条边至少有 2 格内部距离），保证线两侧都有可蚀刻区域。

**规则**：
1. 对每个矩形，识别其边框（最外一圈像素）和内部（边框以内的区域）。
2. 判断矩形宽高比：若宽度 > 高度（横向矩形），标记扩展为一条贯穿内部全高的竖直线（灰(5)色）；若高度 > 宽度（纵向矩形），标记扩展为一条贯穿内部全宽的水平线（灰(5)色）。
3. 划线完成后，对每个矩形的内部单元格进行奇偶蚀刻：设内部区域左上角为 (r0, c0)，对每个内部单元格 (r, c)，若 (r - r0 + c - c0) mod 2 = 1（奇数奇偶），且该单元格不是灰(5)线，则将其替换为黑(0)背景。
4. 灰(5)线上的单元格、偶数奇偶的内部单元格、边框像素均保持不变。

**关键洞察**：线与棋盘格蚀刻在同一空间中交互——灰色线"遮挡"了奇偶蚀刻，使得线两侧的棋盘格图案可能不连续。需要多个示例来同时确认线方向规则（宽高比）和蚀刻规则（奇偶性及锚点），因为单个示例无法区分"线方向由宽高比决定"和"线方向固定为某方向"。

## 新题 6：L形角编码三角与奇偶填充

**组合逻辑**：[放大画布+补对角线边](保留 L→三角扩展) → [行列奇偶决定填充](创新：从矩形内部填充改为三角形内部填充，锚点从内部左上角改为三角直角顶点)

**来源原语**：放大画布expand_canvas(#18 e3f79277)、补对角线边fill_diagonal_side(#18 e3f79277)、角位边角corner_piece(#18 e3f79277)、行列奇偶决定填充parity_fill(#2 ba9d41b8)

**依赖链**：L 形编码角落位置和边长（确定三角形的几何属性），三角轮廓在扩大画布上绘出后，其围成的内部区域被奇偶棋盘格填充。填充的锚点为三角形的直角顶点（即 L 所触的角落），而直角顶点的位置由 L 编码——因此 L 不仅决定三角的形状和位置，还间接决定了棋盘格的相位。

将角落 L 扩展为三角形轮廓后，以三角直角顶点为锚点对三角形内部做奇偶棋盘格填充。

**输入结构**：约 5x5 的正方形网格（边长 n=5）。背景为黑(0)。前景为一种颜色（如绿(3)）构成的一像素宽 L 形，L 的两条臂分别沿网格的一条水平边缘和一条垂直边缘延伸，两臂在网格的一个角落相交。L 的每条臂长度为 n-1 个像素（即占据了该边缘的一部分，从角落开始但不到对角）。输入中不含黄(4)像素。

**规则**：
1. 确定 L 所触的角落（左上/右上/左下/右下）。
2. 创建 (3n-2) x (3n-2) 的黑(0)背景输出画布（n 为输入边长，此例中输出 13x13）。
3. 在输出画布的同一角落，用 L 的颜色（绿(3)）绘制直角三角形轮廓：两条直角边沿画布边缘延伸，长度为 2(n-1) 个像素（从角落开始）；斜边连接两条直角边的自由端点（用 Bresenham 直线或最近整数近似绘制一像素宽的对角线）。
4. 三角形轮廓围成的内部区域（不含轮廓本身）进行奇偶填充：以三角形直角顶点的坐标 (rv, cv) 为锚点，对每个内部单元格 (r, c)，若 (r - rv + c - cv) mod 2 = 0（偶数奇偶），填充为黄(4)；若为奇数，保持黑(0)。
5. 三角形轮廓保持绿(3)不变。

**关键洞察**：奇偶棋盘格的相位锚定在三角形的直角顶点而非网格原点——由于直角顶点可能在四个角中的任意一个，棋盘格的全局相位随角落位置变化。单个示例无法区分"锚点在直角顶点"和"锚点在网格左上角"，需要看到不同角落的 L 才能确认。

## 新题 7：双重身份标记与对称修复裁剪

**组合逻辑**：[补全(对称恢复)](恢复被遮挡的图案) → [裁剪](由标记定义裁剪窗口) ← [标记像素](创新：标记既是遮挡物的一部分——破坏图案——又是裁剪窗口的定义者，一物两用)

**来源原语**：补全completion(#9 f9012d9b)、对称恢复遮挡symmetry_restores(#9 f9012d9b)、对称轨道symmetry_orbit(#9 f9012d9b)、平移对称图案translational_pattern(#9 f9012d9b)、裁剪crop(#1 0bb8deee)、标记像素marker_pixel(多题)

**依赖链**：红色标记像素标记了裁剪矩形的四个角，同时它们本身覆盖了原始图案（即标记位置处的图案被标记色替换）。对称恢复时必须将标记也视为遮挡物（与黑色遮挡区域一样处理），恢复标记位置下的原始图案色。裁剪窗口由标记位置定义，但输出中标记本身被恢复的图案色替代。标记的双重身份——既破坏又定义——是核心耦合点。

在含平移对称图案的网格上，四个红色标记既遮挡图案又框定裁剪窗口；先修复所有遮挡（含标记处），再按标记位置裁剪输出。

**输入结构**：约 12x12 的网格，被一个多色平移对称图案完全覆盖（无单一背景色，图案由 2~3 种颜色交替构成，平移周期约 3x3 或 4x4）。网格中有一个黑(0)矩形遮挡区域（约 3x4 大小），覆盖了部分图案。此外，恰好 4 个红(2)像素分布在网格上，它们构成一个轴对齐矩形的四个角（此矩形包含黑色遮挡区域，且比遮挡区域大）。红色像素替换了其位置上原本的图案颜色。生成约束：红色标记定义的矩形严格在网格内部（不触边缘）；图案的平移周期和网格尺寸保证每个对称轨道中至少有一个未被遮挡（黑或红均视为遮挡）的代表。

**规则**：
1. 将所有黑(0)单元格和所有红(2)单元格标记为"缺失"。
2. 利用非缺失单元格检测图案的平移对称周期。
3. 对每个缺失单元格，从其对称轨道中找到一个非缺失的同轨道单元格，用该单元格的颜色填充缺失位置，完成图案恢复。
4. 找到四个红(2)标记定义的轴对齐矩形区域（以四角坐标为界，含边界）。
5. 裁剪该矩形区域作为输出。输出中不含红色——标记位置已被恢复为正确的图案颜色。

**关键洞察**：红色标记具有双重身份——它们既是需要被修复的"损坏"（与黑色遮挡一样），又是定义输出范围的"指令"。如果误将红色视为图案的一部分（而非遮挡），恢复和裁剪都会出错。需要多个示例确认红色不属于原始图案且总是构成矩形四角。

## 新题 8：色支路像素放大与间隙偏移投影

**组合逻辑**：[像素放大+图案替换](创新：两种前景色触发不同的内部图案，而非统一替换) → [偏移阴影](创新：阴影仅填入放大后方块内部的黑色间隙，而非全局偏移，产生放大图案与阴影的交织)

**来源原语**：像素放大pixel_upscaling(#14 2072aba6)、图案替换pattern_substitution(#14 2072aba6)、按颜色条件分支color_conditional_branch(#14 2072aba6)、偏移阴影offset_shadow(#12 310f3251)、偏移offset(#12 310f3251)

**依赖链**：每种前景色触发不同的 3x3 放大方块内部图案（色支路分支），不同图案在方块内留下不同位置的黑色间隙；偏移阴影机制在全局层面对每个非黑像素向右下偏移一格投影橙色——但仅当目标位置为黑色时才生效。由于不同图案的间隙布局不同，阴影在不同类型方块中的可见程度和位置也不同。

将两种前景色各自放大为不同内部图案的 3x3 方块，再全局添加右下偏移阴影填充剩余间隙。

**输入结构**：约 5x5 的黑(0)背景网格。包含两种前景色：灰(5)和蓝(1)的像素，共约 4~7 个前景像素。输入中不含红(2)、黄(4)、橙(7)像素。灰和蓝像素的分布使得放大后的 3x3 方块之间至少有一列或一行黑色间隔（即输入中任意两个前景像素不在水平或垂直方向上相邻——对角相邻允许）。

**规则**：
1. 将网格放大 3 倍（每个像素变为 3x3 方块，输出约 15x15）。
2. 黑(0)像素 → 3x3 全黑方块。
3. 灰(5)像素 → 3x3 方块，中心为红(2)，其余 8 格为灰(5)。即：
   ```
   5 5 5
   5 2 5
   5 5 5
   ```
4. 蓝(1)像素 → 3x3 方块，四角为黄(4)，十字位为蓝(1)。即：
   ```
   4 1 4
   1 1 1
   4 1 4
   ```
5. 放大完成后，执行偏移阴影：扫描输出网格中每个非黑像素 (r, c)，若 (r+1, c+1) 为黑(0)，则将 (r+1, c+1) 涂为橙(7)。扫描按从左到右、从上到下顺序进行；已涂为橙(7)的位置视为非黑，可继续向其右下投影。
6. 非黑像素（含已有前景色和新涂阴影）不被覆盖。

**关键洞察**：灰色方块中心有红点、四周满填，因此其右下方向的 (r+1,c+1) 几乎全被灰色像素自身占据，阴影极少渗入方块内部；而蓝色方块四角为黄色、十字为蓝色，四个角的右下方对角位恰好可能落入相邻黑色方块区域或方块间隙，产生更丰富的阴影轨迹。两种方块的阴影"指纹"截然不同，需要对比示例才能同时归纳出图案替换规则和阴影规则。

## 新题 9：旋转面板与三色叠合

**组合逻辑**：[旋转](创新：不旋转精灵体而是旋转整个面板，且旋转角度需从示例中归纳) → [透明叠加](创新：叠加结果不只是并集取单色，而是交叉区域产生第三色) ← [逐像素对齐](面板对齐)

**来源原语**：旋转rotate(#7 ecaa0ec1)、透明叠加transparent_overlay(#10 d19f7514)、逐像素对齐cell_align(#10 d19f7514)、并集取前景union_foreground(#10 d19f7514)、面板panel(#10 d19f7514)

**依赖链**：输入的上下两个面板需先分离，然后对下面板施加 180 度旋转（角度为隐藏规则），再与上面板逐像素叠合。叠合规则区分三种情况产生三种颜色——不是简单的并集取单色。旋转改变了下面板的空间布局，直接影响哪些单元格落入"仅上""仅下""双前景"类别。去掉旋转则叠合结果错误；去掉三色区分则退化为源题 #10 的简单并集。

将上下面板的掩码叠合，其中下面板先旋转 180 度；叠合处为第三种颜色，非叠合处保留各自颜色。

**输入结构**：约 12x6 的网格（高度为宽度的两倍，即 2h x w，其中 h=w=6）。上半面板（前 6 行）：黑(0)背景上有蓝(1)前景像素构成的不规则掩码（4-连通，约 5~10 个像素）。下半面板（后 6 行）：黑(0)背景上有红(2)前景像素构成的另一个不规则掩码（4-连通，约 5~10 个像素）。两个掩码形状不同但有一定的空间互补性（旋转 180 度后有部分重叠、部分独立）。输入中不含黄(4)像素。生成约束：下面板旋转 180 度后与上面板至少有 2 个单元格重叠、至少有 2 个单元格各自独立可见。

**规则**：
1. 将输入网格沿高度中线分为上面板 P_top 和下面板 P_bot，各为 h x w。
2. 将 P_bot 旋转 180 度得到 P_bot'（等同于上下翻转再左右翻转）。
3. 创建 h x w 的黑(0)输出网格。逐像素比较 P_top 和 P_bot'：
   - P_top 为蓝(1)且 P_bot' 为红(2)（双前景）→ 输出黄(4)。
   - P_top 为蓝(1)且 P_bot' 为黑(0)（仅上）→ 输出蓝(1)。
   - P_top 为黑(0)且 P_bot' 为红(2)（仅下）→ 输出红(2)。
   - 双黑 → 输出黑(0)。

**关键洞察**：下面板的 180 度旋转是隐藏规则——单看一个示例时，可能的变换包括不旋转、水平翻转、垂直翻转、90 度旋转等，需要多个示例排除替代假设。三色输出（蓝/红/黄）区分了"仅上""仅下""重叠"三种空间关系，比源题 #10 的单色并集更有信息量。
