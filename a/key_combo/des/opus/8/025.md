## 新题 1：色段对齐与位移条纹编码

**组合逻辑**：[滑动/shift](原有) + [计数/counting](原有) + [填充/fill](原有)，创新点在于**位移量本身成为编码信号**——位移操作的副产物（每行移动距离）直接转化为目标区域的条纹宽度

**来源原语**：
- 滑动(shift), 对齐(align), 色段(color_run), 边界对齐(edge_alignment) ← 984d8a3e
- 计数(counting), 条形段(bar_segment), 矩形容器(rect_container), 像素数转为条纹(pixels_to_stripes) ← d93c6891

**依赖链**：对齐操作的副产物（每行位移距离）成为计数操作的输入；计数结果决定条纹宽度。位移距离既改变了色段的位置（第一个变换），又编码了条纹数量（第二个变换）——同一测量值驱动两个不同视觉特征。删除对齐步骤则无法确定位移距离；删除条纹步骤则容器保持空白

将各行颜色段左移对齐至公共右边界，并在旁侧容器中用每行对应颜色绘制与位移距离等宽的条纹。

**输入结构**：
- 约 12x18 的网格，黑(0)背景
- 左侧约 12x10 区域：每行恰有一段连续的非背景色段（3~7 像素长），各行颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)、品红(6)中选取），色段起始列各行不同，导致各行色段右端列号参差不齐；色段左侧为黑(0)，色段右侧至该区域右边界也为黑(0)
- 右侧约 12x6 区域：以灰(5)单像素厚边框围成的矩形容器，内部全为黑(0)；容器左边框与左侧区域右边界之间隔 1 列黑(0)
- 生成约束：各行色段右端列号互不相同；容器内部宽度 >= 所有色段中最大右端列号与最小右端列号之差

**规则**：
1. 在左侧区域，找出所有色段的右端列号中的最小值 c_min
2. 将每行的色段整体左移，使该行色段的右端对齐到列 c_min；若色段左移后左端超出第 0 列，则从第 0 列开始放置
3. 记录每行的实际位移量 d = 原右端列号 - c_min（非负整数；右端已在 c_min 的行 d=0）
4. 位移后，色段原来占据但现已腾出的空间填为黑(0)
5. 在右侧容器内部（不含灰色边框），每行从容器左内壁起，用该行色段的颜色填充 d 列宽的水平条纹（若 d=0 则该行不填）；剩余位置保持黑(0)
6. 灰(5)容器边框保持不变

**关键洞察**：对齐基准（最小右端列号）需对比多个示例才能确认——单个示例无法区分"对齐到最小右端"与其他对齐策略（如对齐到中位数或最大值）；容器中的条纹宽度编码了位移量，而非色段长度本身

## 新题 2：四向对称补全与象限调色

**组合逻辑**：[对称补全/symmetry_completion](原有) → [重涂色/recolor](依据象限位置，创新后)。创新点在于**对称补全产生的新像素根据其所在象限被赋予不同颜色**，形成结构对称但颜色不对称的输出

**来源原语**：
- 对称补全(symmetry_completion), 标记方块(marker_square), 对称中心(symmetry_center), 标记定义双轴镜像(marker_biaxial_mirror) ← 4938f0c2
- 重涂色(recolor), 边框区域(frame_zone), 相对位置决定颜色(relative_position_determines_color), 象限与边距分层(quadrant_border_layer) ← 639f5a19

**依赖链**：对称补全产生反射像素的位置→象限判定需要这些位置→象限颜色来自角标记→最终每个反射像素的颜色由其象限决定。删除对称补全则无像素可涂色；删除象限规则则反射像素颜色无法确定

以 2x2 标记方块为中心四向镜像补全前景形状，每个象限的反射像素涂上该象限角标指定的颜色。

**输入结构**：
- 约 15x15 的网格，黑(0)背景
- 中心附近有一个绿(3) 2x2 实心方块作为对称标记
- 红(2)像素构成一个 4-连通的不规则前景形状（5~12 像素），全部位于标记方块的某一个象限内（如左上象限）；不同示例中原始形状所在象限可能不同
- 网格四角各有一个单色标记像素（距角 1~2 格）：左上角蓝(1)、右上角黄(4)、左下角橙(7)、右下角品红(6)
- 生成约束：四个角标颜色互不相同，且不与红(2)、绿(3)、黑(0)重复；原始红色形状在其所在象限内完全不超出网格范围；四向反射后所有像素均在网格范围内

**规则**：
1. 以绿(3)方块中心为双轴镜像原点（若方块左上角为 (r,c)，则镜像中心为 (r+1, c+1)，即方块四格的交汇点）
2. 对每个红(2)像素生成三个反射位置：水平镜像（关于垂直轴）、垂直镜像（关于水平轴）、180 度旋转
3. 原始红(2)像素保持红(2)不变
4. 每个新生成的反射像素，根据其相对于镜像中心所在的象限涂色：落入左上象限涂蓝(1)（左上角标颜色）、右上象限涂黄(4)、左下象限涂橙(7)、右下象限涂品红(6)
5. 恰好位于镜像轴线上的反射像素（行 = 镜像中心行 或 列 = 镜像中心列），归入其偏向的象限（行等于中心行时归上方象限，列等于中心列时归左方象限）
6. 绿(3)方块保持不变
7. 若反射像素超出网格边界则舍弃

**关键洞察**：输出形状关于中心四向对称，但四个象限颜色各异；角标与象限的对应关系（同侧角标为该象限提供颜色）需从多个示例归纳——单例中原始红色形状只占一个象限，无法区分"角标为同侧象限着色"还是"角标为对侧象限着色"

## 新题 3：双面板合并构建射线障碍场

**组合逻辑**：[透明叠加/transparent_overlay](原有) → [射线延伸/ray_extend](原有)，创新点在于**叠加操作的输出成为射线操作的障碍地图**——障碍只在合并后才完整存在，单面板中的遮挡结构不完整

**来源原语**：
- 透明叠加(transparent_overlay), 二值掩码(binary_mask), 分隔列(divider_column), 双侧对齐(bilateral_alignment), 并集合并(union_merge) ← 5d2a5c43
- 射线延伸(ray_extend), 微型标记(micro_marker), 朝向决定方向(orientation_determines_direction) ← 9344f635

**依赖链**：两面板各自不完整→叠加合并产生完整障碍地图（青色像素）→射线从标记出发沿指定方向延伸→遇到青色障碍或网格边界时停止。删除叠加步骤则障碍不完整，射线终点错误；删除射线步骤则输出只有合并掩码缺少射线标记

合并蓝色分隔列两侧的黄色掩码为青色，再从橙色多米诺标记沿其朝向发射橙色射线直至遇到青色障碍。

**输入结构**：
- 约 11x23 的网格，黑(0)背景
- 正中央一列为蓝(1)分隔列（全高），将网格分为左右两个等宽面板（各约 11x11）
- 每个面板中散布黄(4)像素（各 8~15 个），构成二值掩码；两个面板在对齐后的同一位置至多有一个面板包含黄色像素（互补放置），但不完全覆盖所有位置
- 每个面板中有 1~2 个橙(7)多米诺标记（同色 2 像素，水平或垂直排列），放置在不与黄色像素正交相邻的位置
- 生成约束：合并后每个橙色多米诺沿其朝向的至少一个方向上存在青色障碍（射线不会无限延伸到网格边界以外的情况也合法）；两面板的橙色多米诺不在同一对齐位置重叠

**规则**：
1. 移除蓝(1)分隔列，将左右面板按行列对齐，输出画布为 11x11
2. 对齐后，任一面板中有黄(4)像素的位置涂为青(8)；两面板均为黑(0)的位置保持黑(0)
3. 合并两面板中的橙(7)多米诺标记，保留其对齐后的位置和朝向
4. 对每个橙色多米诺：水平朝向→向左和向右两个方向各发射一条射线；垂直朝向→向上和向下两个方向各发射一条射线
5. 射线从多米诺端点出发，沿指定方向逐格推进；遇到青(8)像素或网格边界时停止（终止格不涂色）；路径上经过的黑(0)格涂为橙(7)
6. 射线不覆盖已有的青(8)像素或其他橙(7)多米诺/射线；若两条射线路径交叉，交叉点涂为橙(7)

**关键洞察**：某些射线在单面板中看似可以畅通无阻，但合并后对侧面板的黄色像素恰好出现在路径上形成障碍——射线长度只有在两面板合并后才能确定

## 新题 4：多色损伤提取与居中叠合

**组合逻辑**：[差异提取/difference_extraction](多对并行，创新后) → [裁剪/crop](原有) → [透明叠加/transparent_overlay](多色掩码居中合并，创新后)。创新点在于**多组独立的损伤检测结果被空间叠合成一个紧凑输出，各色损伤图案的组合揭示隐藏的空间规律**

**来源原语**：
- 差异提取(difference_extraction), 前景图案(foreground_motif), 缺损副本(damaged_copy), 缺失掩码(missing_cell_mask), 对齐比较(aligned_comparison) ← 2037f2c7
- 裁剪(crop), 透明叠加(transparent_overlay), 前景掩码(foreground_mask), 中心对齐(center_alignment), 多色掩码合并(multi_mask_merge) ← c8cbb738

**依赖链**：每对图案的差异提取→各自产生损伤掩码→裁剪归一化→居中叠合时各色掩码交织成组合图案。跳过差异提取则不知道哪些像素缺失；跳过居中叠合则各掩码分散在输入中无法显示组合结构

对每种颜色的完整/缺损图案对提取缺失像素掩码，裁剪后以各自颜色居中叠合到紧凑画布上。

**输入结构**：
- 约 20x20 的网格，黑(0)背景
- 包含 3~4 种非背景色（从蓝(1)、红(2)、绿(3)、黄(4)中选取），每种颜色出现恰好两个 4-连通图案
- 每对同色图案的边界框形状相同（宽高一致），一个为完整版（所有前景像素均为该颜色），另一个为缺损版（部分前景像素被替换为黑(0)背景）；完整版像素数严格大于缺损版
- 各颜色的图案之间互不重叠（边界框不相交），同色的两个图案也互不重叠
- 每种颜色的损伤掩码（完整版有而缺损版无的像素集合）裁剪后的边界框高度和宽度均为奇数
- 所有颜色的裁剪后掩码的最大边界框高度相同、最大边界框宽度相同（保证居中对齐时中心像素重合）
- 生成约束：各色损伤掩码居中叠合后互不重叠（不同颜色的掩码像素不落在同一位置）

**规则**：
1. 对每种颜色 C，在输入中找到同色的两个 4-连通图案，像素数多的为完整版，少的为缺损版
2. 按边界框左上角对齐两个图案，标记出完整版中为颜色 C 而缺损版中为黑(0)的像素位置，形成颜色 C 的损伤掩码
3. 将每个损伤掩码裁剪到自身最小边界框，保留原色 C
4. 输出画布尺寸 = 所有裁剪后掩码中最大高度 x 最大宽度，背景为黑(0)
5. 将每个裁剪后掩码居中放置到输出画布上（居中 = 掩码边界框中心对齐画布中心）
6. 各色掩码像素保留各自原色

**关键洞察**：单看某一种颜色只能得到孤立的损伤碎片，但所有颜色的损伤掩码居中叠合后形成一个有规律的组合图案——"损伤"本身是编码信号而非随机缺失；需对比多个示例确认是按像素数区分完整版与缺损版（而非按位置）

## 新题 5：降噪补线后在交叉点盖章

**组合逻辑**：[擦除/erase](原有) → [补线/line_completion](原有) → [印章覆盖/stamp_overlay](创新后)。创新点在于**印章位置不是预设的，而是由前两步操作涌现出来的——线段交叉点只在降噪和补线完成后才存在**

**来源原语**：
- 擦除(erase), 直线段(straight_line_segment), 对角噪声(diagonal_noise), 忽略干扰项(ignore_distractors), 间隙长度限制(gap_length_constraint), 补线(line_completion) ← 7b80bb43
- 印章覆盖(stamp_overlay), 模板掩码(template_mask), 矩形精灵体(rect_sprite), 掩码变换匹配则补(transform_match_fill) ← 7df24a62

**依赖链**：擦除对角噪声→暴露断线位置→补线修复断裂→产生完整线段→线段交叉点涌现→在交叉点处盖章。任何一步被跳过，交叉点位置都不正确或不存在

删除对角阶梯噪声、补全断裂直线后，在每个水平线与垂直线交叉点处印上模板图案。

**输入结构**：
- 约 18x18 的网格，黑(0)背景
- 蓝(1)像素构成若干水平和垂直直线段（各 1 像素宽），线段之间有 1~3 像素的断裂间隙
- 同为蓝(1)的对角阶梯像素散布在断裂间隙附近（每个对角像素的上下左右四个正交邻居中无蓝色，但至少一个对角邻居为蓝色）
- 网格右下角 4x4 区域包含一个红(2)的模板图案：3x3 范围内的 4-连通不规则形状（4~6 像素），其余为黑(0)背景；模板区域不与任何蓝色线段或噪声重叠
- 生成约束：补线完成后至少存在 2 个交叉点（水平完整线与垂直完整线的交汇像素）；模板中心像素（第 2 行第 2 列，从 1 开始计数）为红(2)

**规则**：
1. 识别对角噪声像素：蓝(1)像素中，上下左右四个正交方向均无蓝色邻居且至少一个对角方向有蓝色邻居的像素
2. 将所有对角噪声像素擦除为黑(0)
3. 对擦除后的每条水平/垂直方向上的蓝色线段序列：若相邻两段之间的间隙长度 <= 该间隙附近（间隙所在行/列上下/左右 1 格范围内）被擦除的对角像素数量，则用蓝(1)填充该间隙
4. 找出所有交叉点：某像素位置同时属于一条连续水平蓝色线段（长度 >= 3）和一条连续垂直蓝色线段（长度 >= 3）
5. 以每个交叉点为中心，将 3x3 模板图案盖印到网格上：模板中心对齐交叉点，模板中红(2)像素覆盖该位置原有内容（包括蓝色），模板中黑(0)像素不覆盖（透明处理）
6. 若多个交叉点的模板覆盖范围重叠，后处理的覆盖先处理的（处理顺序：按交叉点位置从上到下、从左到右）
7. 模板超出网格边界的部分舍弃

**关键洞察**：交叉点只在擦除噪声并补全线段后才确定——原始输入中线段断裂且噪声遮掩了断裂位置；对角噪声的分布同时编码了间隙长度上限和潜在交叉点的存在暗示

## 新题 6：旋转匹配驱动的方向性模板印章

**组合逻辑**：[印章覆盖/stamp_overlay](原有) + [旋转/rotate](作为匹配键而非直接变换，创新后) + [重涂色/recolor](行调色板着色，原有)。创新点在于**每个单元格中的小标记形状本身就是模板的某个旋转/镜像版本的部分投影，识别出变换类型后以该变换盖印完整模板**

**来源原语**：

- 旋转(rotate), 查表替换(lookup_replace), 形状标记(shape_marker), 颜色与形状对应(color_shape_match), 旋转镜像等价匹配(rotation_reflection_match) ← b20f7c8b

**依赖链**：模板定义基准形状→每个单元格的灰色标记与模板的某个变换匹配→匹配确定该单元格的印章朝向→行调色板确定颜色→按对应朝向和颜色盖印。删除旋转匹配则不知道朝向；删除行调色板则不知道颜色；删除模板则无法识别标记含义

在分隔网格的每个单元格中，将灰色方向标记替换为完整模板的对应旋转/镜像版本，颜色取自该行调色板。

**输入结构**：
- 约 19x19 的网格，栗(9)分隔条将网格分为 3x3 共 9 个等大单元格（每个单元格内部约 5x5），分隔条宽 1 像素

- 第 0 列其余单元格（第 1 行第 0 列、第 2 行第 0 列）各包含一个单色标记像素（位于单元格中心），颜色互不相同且不为红(2)、栗(9)、黑(0)、灰(5)（如蓝(1)和绿(3)），标记该行的输出颜色；第 0 行的输出颜色为红(2)（来自模板自身颜色）
- 其余 6 个单元格（第 0~2 行的第 1~2 列）各包含一组灰(5)微型标记像素（2~3 个像素），这些像素的相对位置是模板图案在某个刚性变换下的关键像素子集（足以在 8 种变换中唯一确定是哪一种）
- 所有单元格背景为黑(0)
- 生成约束：6 个灰色标记对应的 6 种变换互不相同（从 8 种中选 6 种）

**规则**：
1. 从左上角单元格读取红(2)模板图案，记录其像素的相对坐标集合 S
2. 枚举模板的 8 种刚性变换（0/90/180/270 度旋转，各搭配是否水平镜像），得到 8 个变换后坐标集合 {T_i(S)}
3. 对每个非左列单元格，提取其内部灰(5)像素的相对坐标集合 M，在 {T_i(S)} 中找到唯一的 T_k 使得 M 是 T_k(S) 的子集且此子集在 8 种变换中唯一对应 T_k
4. 读取该单元格所在行的输出颜色 C：第 0 行为红(2)，第 1、2 行从对应左列标记读取
5. 清空该单元格内部为黑(0)，以变换 T_k 将完整模板图案盖印到该单元格中心对齐位置，颜色为 C
6. 左上角单元格保持原样（红色模板不变）；左列标记单元格保持原样
7. 栗(9)分隔条保持不变

**关键洞察**：灰色像素看起来像随机散点，但实际是模板在不同刚性变换下的关键像素投影——必须先从左上角学习模板形状、穷举变换、再逐一子集匹配，才能确定每个单元格应印制的朝向；行调色板确定颜色是另一个独立维度

## 新题 7：跨轴镜像与距离编码条纹

**组合逻辑**：[镜像/reflect](原有) + [填充/fill](间隙填充，原有) + [计数/counting](距离测量转条纹数，创新后)。创新点在于**同一个空间度量（对象到分隔线的距离）同时决定两个不同的视觉特征：间隙区域的填充高度和镜像体内部的条纹行数**——分叉-汇合结构而非线性流水线

**来源原语**：
- 镜像(reflect), 分隔线(separator_line), 实心矩形(solid_rectangle), 间隙带(gap_strip), 跨轴对称(cross_axis_symmetry), 分隔色填充间隙(sep_color_fills_gap), 忽略干扰项(ignore_distractors) ← 538b439f
- 计数(counting), 条形段(bar_segment), 像素数转为条纹(pixels_to_stripes), 相邻接触(adjacent_touch) ← d93c6891

**依赖链**：矩形到分隔线的距离 d →（分支1）间隙区域填充分隔色、镜像体放置位置由 d 决定 →（分支2）镜像体内部从接触边起填充 d 行条纹。距离同时驱动两条输出路径，两条分支汇合到同一输出网格上

将分隔线一侧的矩形镜像到另一侧，间隙涂分隔色，镜像体内部从靠近分隔线的边起涂与距离等行数的条纹。

**输入结构**：
- 约 20x15 的网格，黑(0)背景
- 一条水平全宽的品红(6)分隔线（1 像素高），位于网格中部偏上（约第 5~7 行）
- 分隔线上方有 2~3 个不同颜色的实心矩形（如蓝(1) 3x4 即 3 行高 4 列宽、红(2) 2x5），各矩形到分隔线的距离 d（矩形底边到分隔线之间的空行数）各不相同且 d >= 1
- 分隔线下方为空（全黑），且下方空间足够容纳所有镜像体和间隙
- 网格上散布少量孤立干扰像素（单个非背景非品红像素，上下左右四个正交邻居中无同色像素）
- 生成约束：各矩形的列范围互不重叠（水平不交叉），保证间隙填充和镜像体之间不冲突

**规则**：
1. 忽略所有孤立干扰像素（4-连通邻居中无同色像素的单像素），它们不参与任何操作，保持原位不变
2. 对每个实心矩形，计算其底边到分隔线之间的空行数 d
3. 将矩形关于分隔线做垂直镜像，放置在分隔线下方对称位置（镜像体顶边距分隔线 d 行）
4. 原矩形底边与镜像体顶边之间的间隙区域（共 2d+1 行 x 矩形宽度列，包含分隔线所在行）中，非分隔线的行涂为品红(6)；分隔线行本身已是品红(6)
5. 在镜像体内部，从最靠近分隔线的边（镜像体顶边）起，向下涂 d 行该矩形颜色的水平条纹；剩余行保持黑(0)（若 d >= 矩形高度，则整个镜像体涂满该颜色）
6. 原始矩形保持不变（完整保留颜色和位置）

**关键洞察**：间隙填充行数与镜像体内部条纹行数始终相等（均为 d），因为它们由同一个距离值驱动——观察者需要发现"到分隔线的距离"这个隐藏变量同时控制了两种不同的视觉效果；仅凭单个示例无法确认条纹行数的计算规则（可能误以为与矩形高度有关）

## 新题 8：图例查色确定循环调色起点

**组合逻辑**：[查表替换/lookup_replace](原有) + [循环填充/cyclic_filling](原有)，创新点在于**图例查表的结果不直接成为输出颜色，而是作为循环调色板的起始相位偏移**——同一调色板对不同编码块产生不同颜色图案

**来源原语**：
- 查表替换(lookup_replace), 图例面板(legend_panel), 编码块(encoded_block), 形状标记(shape_marker), 颜色与形状对应(color_shape_match), 旋转镜像等价匹配(rotation_reflection_match) ← b20f7c8b
- 循环填充(cyclic_filling), 对角带(diagonal_band), 调色板行(palette_row), 层深度递增(layer_depth_increasing), 层深模色板取色(depth_mod_palette_color) ← b457fec5

**依赖链**：图例面板将形状映射到颜色→颜色在调色板行中的位置索引即为起始偏移→每个编码块的同心层按 (层深 + 偏移) mod 调色板长度取色。删除图例查表则不知道偏移值；删除循环填充则不知道如何着色各层

根据每个编码块内标记形状在图例中对应的颜色确定调色板起始偏移，再以同心层深度循环调色板填充该块。

**输入结构**：
- 约 22x22 的网格，黑(0)背景
- 左上方约 10x6 区域为青(8)底色的图例面板，包含 3~4 个不同颜色的 4-连通小形状（3~5 像素），颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取；每个形状在 8 种刚性变换下互不相同
- 图例面板正下方有一行调色板行：与图例面板中颜色相同的像素按固定顺序排列（如从左到右为蓝(1)、红(2)、绿(3)、黄(4)），各像素间隔 1 格黑(0)，位置索引从 0 开始
- 网格右侧及下方区域包含 3~4 个 7x7 编码块，互不重叠且不与图例面板/调色板行重叠
- 每个编码块内部背景为灰(5)，中央有一个橙(7)小形状（3~5 像素），该形状是图例面板中某个颜色形状的旋转或镜像版本
- 生成约束：每个编码块的橙色形状与图例中恰好一种颜色的形状匹配（在 8 种变换下）；不同编码块可以匹配不同或相同的图例颜色

**规则**：
1. 对每个 7x7 编码块，提取其内部橙(7)像素的相对坐标，与图例面板中各颜色形状的 8 种刚性变换逐一比较，找到唯一匹配的图例颜色 C
2. 在调色板行中查找颜色 C 的位置索引 k（从左到右，从 0 开始）
3. 将编码块内部 7x7 区域按同心层划分：第 0 层 = 最外圈（距块边界 0 像素的环形），第 1 层 = 距块边界 1 像素的环形，以此类推至中心（第 3 层为中心 1x1 像素）
4. 每层的颜色 = 调色板行中第 (层深 + k) mod 调色板长度 位置的颜色
5. 同心层颜色覆盖原有的灰(5)和橙(7)像素
6. 块外区域保持黑(0)；图例面板和调色板行保持不变

**关键洞察**：图例查表的目的不是确定最终颜色（那样每个块只会是单色），而是确定循环调色板的起始相位——两个匹配到调色板中相邻颜色的编码块，其同心环图案将呈现一格相位差；需对比多个示例才能区分"图例决定固定颜色"和"图例决定相位偏移"

## 新题 9：互补面板合并与反对角线结构修复

**组合逻辑**：[透明叠加/transparent_overlay](并集合并，原有) + [填充/infill](反对角线约束填充，原有)。创新点在于**两种修复策略必须协同工作且各自不充分——并集合并恢复大部分缺失值，但双面板共同缺失的稀少位置只能通过反对角线结构规则推断**——同时约束满足结构

**来源原语**：
- 透明叠加(transparent_overlay), 二值掩码(binary_mask), 分隔列(divider_column), 双侧对齐(bilateral_alignment), 并集合并(union_merge) ← 5d2a5c43
- 填充(infill), 边框层(frame_layer), 遮挡空洞(occlusion_hole), 反对角线等值(anti_diagonal_equivalence), 分区结构约束(partitioned_structure_constraint) ← 4aab4007

**依赖链**：（路径 A）两面板并集合并→恢复大部分遮挡空洞；（路径 B）合并后仍有少量双缺失位置→需利用反对角线等值约束从已知值推断→填补剩余空洞。仅用路径 A 有残留空洞无法填补，仅用路径 B 已知值太少（单面板空洞率 30%）无法可靠推断

合并分隔列两侧的互补色彩面板，再利用反对角线同色规则修复两面板共同缺失的像素。

**输入结构**：
- 约 11x23 的网格，黑(0)为缺失标记
- 正中央一列为灰(5)分隔列
- 左右两个 11x11 面板，各自展示同一幅彩色图案的带空洞版本：
  - 完整图案为 11x11，使用 3~4 种非黑非灰颜色（如蓝(1)、红(2)、绿(3)、黄(4)），其中同一条反对角线（row + col = 常数）上的所有像素颜色相同
  - 左面板中约 30% 的像素被替换为黑(0)空洞
  - 右面板中约 30% 的像素被替换为黑(0)空洞
  - 两面板的空洞位置大部分互补（左面板有空洞的位置右面板有值，反之亦然），但有约 5~8 个位置在两面板中均为空洞（双缺失）
- 生成约束：每条反对角线上在合并后（取两面板并集）至少保留一个非黑像素，保证反对角线规则可唯一推断所有双缺失位置的颜色

**规则**：
1. 移除灰(5)分隔列，将左右面板按行列对齐
2. 并集合并：对每个位置 (r,c)，若左面板该位置为非黑色则取左面板值，否则取右面板值（若两面板该位置都非黑则两者一致，取任一即可）
3. 合并后仍为黑(0)的位置为双缺失位置；对每个双缺失位置 (r,c)，计算其反对角线编号 k = r + c，在已有值中找到同一反对角线（r' + c' = k）上的非黑像素，用该颜色填充 (r,c)
4. 输出为 11x11 的无空洞完整图案

**关键洞察**：大部分空洞通过简单的面板合并即可消除，但少数双缺失位置要求发现"同一反对角线上颜色恒定"的结构约束——此规则在单面板中因空洞过多而难以可靠归纳（同一反对角线上可能大半是空洞），只有在合并后的近完整图案中才显现出清晰的反对角线色带
