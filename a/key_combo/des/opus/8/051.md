## 新题 1：标记计数同时决定镜像轴与距离环起始色

**组合逻辑**：[计数(counting)] → 分叉 → [镜像(mirror)](创新：计数奇偶决定轴向，而非凸耳位置) + [填充(fill)](创新：计数值索引循环色板起始位，而非固定起始) → 合流生成镜像副本及其内部色环

**来源原语**：计数(counting) ← ff2825db；镜像(mirror) ← dc2e9a9d；对侧放置(opposite_place) ← dc2e9a9d；填充(fill) + 距离映射(distance_mapping) + 循环色板(cyclic_palette) ← aaef0977；标记像素(marker_pixel) ← 共用

**依赖链**：对每个轮廓形状外侧的标记像素计数 → 计数的奇偶性决定镜像轴（水平或垂直） → 同一计数值的绝对数值决定副本内部距离环的色板起始偏移 → 因此计数被两个下游操作同时消费，删除任一分支都无法独立确定另一分支

根据轮廓外侧标记像素的数量，在对侧放置镜像副本（奇偶定轴），并用距离环填充副本内部（计数值定起始色）。

**输入结构**：约 18x22 的黑(0)背景网格。包含 2-3 个绿(3)空心轮廓形状（4-连通闭合边界，边界像素数 6-12，内部为黑(0)背景，形状各异——不同示例中可为近似矩形、不对称多边形等）。每个轮廓的包围框外侧恰好有一侧排列着 1-4 个红(2)标记像素，紧贴包围框边缘（与包围框间距 0，即相邻），排列方向与该侧边平行。不同轮廓的标记在不同侧。各轮廓包围框之间至少间隔 5 个像素，保证镜像副本有足够空间放置。生成约束：每个轮廓的标记数在 1-4 之间，且同一输入中至少有一个奇数标记轮廓和一个偶数标记轮廓。

**规则**：
1. 对每个绿(3)轮廓，统计其包围框外侧紧贴的红(2)标记像素数量，记为 k。
2. 若 k 为奇数，将该轮廓沿水平轴镜像（上下翻转），副本放在轮廓包围框的对侧（若标记在上方则副本在包围框下方，若标记在下方则副本在包围框上方），副本与原包围框之间间隔 1 行黑(0)背景。若 k 为偶数，将该轮廓沿垂直轴镜像（左右翻转），副本放在包围框的水平对侧（若标记在左侧则副本在右侧，反之亦然），间隔 1 列。
3. 镜像副本的轮廓边界绘制为蓝(1)。
4. 以副本轮廓的内部几何中心像素（内部区域的质心取整到最近像素）为距离零点，对副本内部的每个黑(0)像素计算曼哈顿距离 d，赋色为循环色板 [黄(4), 灰(5), 红(2), 青(8), 栗(9)] 中第 ((d - 1 + k) mod 5) 项的颜色。距离零点本身保持黑(0)。
5. 所有原始绿(3)轮廓像素和红(2)标记像素保持不变。副本像素仅覆盖黑(0)背景。若副本超出网格边界则裁掉超出部分。

**关键洞察**：单一计数值 k 同时控制几何决策（镜像轴向）和色彩决策（色板偏移），求解者必须在多个示例中分离这两层因果才能完整归纳规则——仅看一个示例无法区分"轴向由标记侧决定"还是"由计数奇偶决定"。

## 新题 2：压缩重复行列后在控制像素处印章隐藏精灵体

**组合逻辑**：[压缩(compress) + 去重(deduplicate)] → [印章覆盖(stamp)](创新：印章内容不是预设图案而是压缩后才可见的精灵体) + [以控制点为中心(centered_on_control_pixel)]

**来源原语**：压缩(compress) + 去重(deduplicate) + 相邻重复(adjacent_repeat) + 合并相同行列(merge_identical_row_col) ← e1baa8a4；印章覆盖(stamp) ← ac0c5833；精灵体(sprite) ← ac0c5833；控制像素(control_pixel) ← ecdecbb3/3f23242b；以控制点为中心(centered_on_control_pixel) ← 3f23242b

**依赖链**：输入网格含非均匀行列重复 → 压缩去重后才显现真实精灵体形状和控制像素的真实距离关系 → 精灵体形状决定印章内容 → 控制像素位置（压缩后坐标）决定印章放置点 → 多控制像素时按行主序逐个印章，后印覆盖先印

在一个被行列重复膨胀的网格上，先还原真实布局，再将还原后发现的精灵体图案印章到每个控制像素位置。

**输入结构**：约 20x20 的彩色网格（无纯背景色——所有像素均为非黑色的填充色）。网格是一个较小的"母版"（约 8x10）经行列非均匀拉伸得到：每行被重复 1-3 次（产生若干组相同的相邻行），每列被重复 1-3 次（产生若干组相同的相邻列），不同行/列的重复倍数不必相同。母版中包含：灰(5)为主体填充色（占母版像素的 60% 以上），1 个由蓝(1)像素组成的 4-连通精灵体（3-6 像素，形状各异），以及 2-4 个孤立的红(2)控制像素。精灵体和控制像素在母版中互不相邻（最近曼哈顿距离 >= 2）。生成约束：膨胀后的网格不超过 25x25；母版中精灵体为单个连通分量。

**规则**：
1. 识别所有最大相同相邻行组和最大相同相邻列组，每组保留第一行/列，删除其余，得到压缩后的母版网格。
2. 在母版中，蓝(1)的 4-连通分量即精灵体；红(2)的孤立像素即控制像素。
3. 计算精灵体的包围框及其相对于包围框左上角的掩码。
4. 按行主序（先上后下、同行先左后右）处理每个红(2)控制像素：以该控制像素为中心对齐精灵体包围框的中心（上下左右各偏移半个包围框尺寸，取 floor），将精灵体掩码以蓝(1)覆盖到对应位置。被覆盖的灰(5)像素变为蓝(1)；已有的蓝(1)和红(2)像素不被覆盖。超出母版边界的部分舍弃。
5. 输出为处理后的母版（压缩后的尺寸）。

**关键洞察**：在膨胀网格中，精灵体被行列拉伸成不规则的粗大色块，控制像素之间的距离也被扭曲——必须先正确压缩才能看到精灵体的真实形状和控制像素的真实位置；跳过压缩步骤直接印章会得到错误的图案和错误的放置点。

## 新题 3：多源射线在贯穿条上的汇聚计数决定膨胀大小

**组合逻辑**：[射线延伸(ray_extend)] → [计数(counting)](创新：计数的不是嵌入标记而是同列射线的汇聚数) → [膨胀(dilate)](创新：膨胀量由汇聚计数决定，非预设固定值) → [印章覆盖(stamp_overlay)]

**来源原语**：射线延伸(ray_extend) + 投射(perpendicular_cast) + 命中处印标记(stamp_at_hit) ← ecdecbb3；计数(counting) ← ff2825db；膨胀(dilate) + 计数决定扩展量(count_determines_expansion) ← 52fd389e；贯穿条(full_span_bar) + 控制像素(control_pixel) + 接触标记(contact_marker) ← ecdecbb3

**依赖链**：每个控制像素向贯穿条投射射线 → 多个控制像素的射线可能命中同一条贯穿条的同一列 → 每个命中点的"汇聚计数"=命中该列的不同控制像素数 → 汇聚计数决定该命中点处标记块的膨胀半径 → 不同膨胀半径的标记块可能彼此重叠，后绘制覆盖先绘制

从多个控制像素向平行贯穿条投射垂直射线，按命中点被几条射线共享来决定接触标记的膨胀尺寸。

**输入结构**：约 18x18 的黑(0)背景网格。2-4 条完整灰(5)水平贯穿行（每行所有像素均为灰(5)，行间距 >= 5）。4-6 个红(2)孤立控制像素分布在贯穿行之间和上下两侧的黑(0)区域中，任意两个控制像素不在同一列。生成约束：至少存在一列同时被 2 个不同控制像素的射线命中同一贯穿行（即两个控制像素恰好在同一列的两侧各有一条贯穿行），也至少存在一列仅被 1 个控制像素命中。

**规则**：
1. 对每个红(2)控制像素，沿垂直方向（上下）各投射一条射线，射线在遇到第一条灰(5)贯穿行时停止（命中该行对应列的像素）。若该方向无贯穿行则不产生射线。射线路径上的黑(0)像素（不含命中点）涂为红(2)。
2. 对每个命中点（贯穿行上被射线到达的像素），计算"汇聚数" c = 以该像素所在列为准，有多少条不同控制像素的射线命中了该贯穿行的该列。（注意：同一控制像素的上下两条射线命中不同贯穿行的同列像素不计入同一命中点的汇聚。）
3. 在每个命中点处绘制一个边长为 (2c+1) 的黄(4)实心正方形，以命中点为中心。绘制顺序按命中点从上到下、同行从左到右；后绘制的覆盖先绘制的像素。
4. 每个黄(4)正方形的中心像素恢复为红(2)。
5. 所有灰(5)贯穿行像素若未被黄(4)覆盖则保持灰(5)。

**关键洞察**：命中点的膨胀大小不取决于该控制像素自身的属性，而取决于网格中所有控制像素的全局空间布局——仅凭单个控制像素的位置无法确定其命中标记的大小，必须检查是否有其他控制像素的射线汇聚到同一列。

## 新题 4：象限精灵体的像素并集检测与压缩输出

**组合逻辑**：[象限映射(quadrant_mapping)](创新：象限不再直接映射颜色存在性，而是映射并集角色) ← → [像素并集(pixel_union)](创新：并集检测跨象限在局部坐标系中进行) → [压缩(compress)](创新：将象限级分类结果压缩为 2x2 输出)

**来源原语**：象限映射(quadrant_mapping) + 标记在面板象限内(marker_in_panel_quadrant) + 标记半区定输出(marker_half_determines_output) ← 19bb5feb；像素并集(pixel_union) + 双掩码并集等三(two_union_eq_third) ← fea12743；压缩(compress) ← e1baa8a4；重涂色(recolor) ← fea12743

**依赖链**：四个象限各含一个精灵体掩码 → 将每个精灵体转换到局部坐标（相对于各自象限左上角） → 穷举两两并集检查是否与第三个掩码吻合 → 找到的"操作数"和"结果"角色映射回象限位置 → 输出为 2x2 网格编码各象限角色

将四象限中的精灵体掩码进行局部坐标下的像素并集配对检测，然后将配对角色压缩为 2x2 位置图。

**输入结构**：约 15x15 的黑(0)背景网格，由一条水平灰(5)分隔行和一条垂直灰(5)分隔列划分为四个大小相等的象限（每象限约 7x7）。每个象限内包含恰好一个红(2)精灵体掩码（4-连通前景像素集合，3-7 像素，形状各异）。四个精灵体的掩码在各自象限内的局部坐标（相对象限左上角）下满足：恰好存在唯一的一组 (A, B, C)（A、B 为操作数，C 为结果），使得 A 的掩码像素 OR B 的掩码像素 = C 的掩码像素，且 A 和 B 各自至少贡献一个 C 中没有的"独有像素"（即 A 不是 C 的子集，B 不是 C 的子集）。第四个精灵体 D 不参与任何这样的并集关系。生成约束：四个掩码形状互不全等（含旋转/镜像）；并集关系唯一。

**规则**：
1. 将每个象限的红(2)精灵体掩码提取为局部坐标下的二值掩码（相对于该象限的左上角像素为原点）。
2. 枚举所有 C(4,2)=6 对掩码，对每对计算像素并集（OR），检查该并集是否与剩余两个掩码之一完全匹配。
3. 找到唯一满足条件的三元组 (A, B, C)：A OR B = C。将 A、B 标记为"操作数"，C 标记为"结果"，第四个 D 标记为"无关"。
4. 输出一个 2x2 网格：每个格子对应一个象限（左上→左上，右上→右上，左下→左下，右下→右下）。操作数象限填蓝(1)，结果象限填绿(3)，无关象限填黑(0)。

**关键洞察**：精灵体在输入中各自孤立于不同象限，视觉上看不出关联——求解者必须将它们对齐到同一局部坐标系后做像素级逻辑运算才能发现并集关系；象限位置本身不提供任何线索，它只决定输出格子的颜色分配。

## 新题 5：三角精灵体逐步消除标记并在每站绘制递增边框

**组合逻辑**：[逐步移动(stepwise_move) + 消除(consume)] → [描边(draw_frame)](创新：边框不是由标记极值决定而是由步数决定大小) + [计数(counting)](创新：计数的是累积步数而非嵌入标记)

**来源原语**：逐步移动(stepwise_move) + 消除(consume) + 朝向决定搜索线(facing_sets_search_line) + 最近标记优先(nearest_marker_first) ← 5545f144；描边(draw_frame) ← 928ad970；计数(counting) ← ff2825db；三角精灵体(triangle_sprite) ← 5545f144；标记像素(marker_pixel) ← 共用

**依赖链**：三角精灵体的朝向决定搜索方向 → 最近标记被消除 → 消除后精灵体转向 → 累积步数 n 决定当站绘制的边框边长 (2n+1) → 移动路径（受朝向和标记布局驱动）改变后续可搜索范围 → 边框的空间分布取决于完整移动路径

三角精灵体逐步朝标记移动并消除它们，每消除一个标记就在该位置绘制一个边长随步数递增的空心边框。

**输入结构**：约 17x17 的黑(0)背景网格。1 个绿(3)三角精灵体（由 3-4 个像素组成，呈箭头形，尖端指向一个基本方向：上/下/左/右，尖端像素为"头部"）。4-6 个红(2)标记像素散布于网格中。生成约束：从精灵体初始朝向出发，沿朝向的行或列上必有至少一个标记可达；每步消除后新朝向上也总有标记可达，直至所有标记被消除（即存在一条合法的完整消除路径）。标记之间的行列不重叠（无两个标记在同行或同列），以保证每步只有唯一最近标记。

**规则**：
1. 初始：精灵体的头部像素即当前位置，精灵体的尖端方向即当前朝向。令步数计数 n = 0。
2. 沿当前朝向的半直线（与头部同行或同列，在朝向方向上）搜索最近的红(2)标记。
3. 若找到标记：n += 1。将精灵体整体平移使头部移动到该标记位置，消除该标记。精灵体的新朝向 = 本次移动的方向。在该标记位置绘制一个边长为 (2n+1) 的灰(5)空心矩形边框（1 像素宽边），以标记位置为中心。
4. 重复步骤 2-3 直到当前朝向上无标记可达。
5. 输出：精灵体保留在最终位置（绿(3)），所有绘制的灰(5)边框保留，所有原始标记消失。边框之间若重叠，后绘制的覆盖先绘制的。精灵体像素覆盖边框像素。移动路径不留痕迹。

**关键洞察**：边框大小并非由几何属性决定，而是由到访顺序编号决定——同一组标记如果初始朝向不同，消除顺序改变，每个标记处的边框大小也会完全不同。求解者必须先模拟移动路径才能确定每站的边框尺寸。

**组合逻辑**：[滑动(shift) + 对齐(align)] → [裁剪(crop)] → [镜像(mirror)]（非流水线拼装：对齐改变了裁剪窗口的内容，三者通过空间耦合）

**规则**：
1. 以最顶行的双色条为参考：记其红(2)像素所在列为 col_R，蓝(1)像素所在列为 col_B。
2. 对每条非参考双色条：若其红(2)像素已在 col_R 列，保持不动。否则，整体水平平移该条使其红(2)像素落在 col_R 列（蓝(1)像素自然落在 col_B 列）。移出原位置的像素恢复为黑(0)。

5. 将裁剪区域的列顺序左右反转（水平镜像）。
6. 输出镜像后的裁剪区域。

**关键洞察**：黄(4)标记的位置在对齐过程中不变，但它们框定的内容因对齐而改变——某些条被移入窗口，某些条在窗口内平移。如果跳过对齐直接裁剪，或者先裁剪再对齐，都会得到错误结果。求解者必须识别出正确的操作顺序。

## 新题 7：补全被遮挡矩形框后按距离排名填充内部色彩

**组合逻辑**：[补全(complete)](创新：补全的是互相遮挡的空心矩形框而非实心形状) → [计数(counting) + 距离映射(distance_mapping)](创新：距离用于排名而非环形填充) → [填充(fill) + 重涂色(recolor)](创新：填充色由距离排名从色板中选取)

**来源原语**：补全(complete) + 前景遮挡(foreground_occlusion) + 隐含区域重涂(implied_region_recolor) + 被遮挡形状(occluded_shape) + 矩形足迹(rectangular_footprint) ← 52df9849；填充(fill) + 距离映射(distance_mapping) + 循环色板(cyclic_palette) ← aaef0977；计数(counting) ← ff2825db；空心矩形(rectangular_frame) ← 928ad970

**依赖链**：多个空心矩形框互相遮挡 → 必须先推断每个框的完整矩形边界（补全被遮挡的边框像素） → 补全后确定每个框的内部区域 → 计算每个框内部中心到青(8)标记像素的曼哈顿距离 → 按距离排名为每个框内部赋色 → 框的补全决定了哪些像素属于哪个框的内部，进而影响距离计算和填色范围

先推断被互相遮挡的空心矩形框的完整边界，然后按各框中心到标记的距离排名，用不同颜色填充各框的内部。

**输入结构**：约 16x16 的黑(0)背景网格。3-4 个灰(5)空心矩形框（每个框为 1 像素宽的矩形边框，内部为黑(0)，尺寸各异，边长范围 4-8）。这些框互相部分重叠：在重叠处，只显示一个框的灰(5)像素，另一个框的边框像素被遮挡（显示为遮挡者的灰(5)或遮挡者内部的黑(0)）。重叠的前后关系一致（存在一个全局深度顺序）。网格中另有恰好 1 个青(8)标记像素（不与任何框的边框或内部重叠）。生成约束：每个框至少有 3 条完整边可见（至多 1 条边被部分遮挡），以便可以唯一推断出完整的矩形；所有框的灰(5)颜色相同；框的数量不超过色板长度。

**规则**：
1. 对每个灰(5)矩形框，根据可见的边框像素推断其完整矩形边界（4 条边的行列范围）。具体方法：每个框至少 3 条边完整可见，据此确定 4 条边的行列位置；被遮挡的边框像素位置在另一个框的内部或边框上。
2. 将所有被遮挡的边框像素恢复为灰(5)——即补全每个框为完整的空心矩形。注意：若一个框的补全像素落在另一个框的内部区域，该像素变为灰(5)（补全优先于内部留空）。补全顺序不影响结果，因为所有框颜色相同。
3. 补全后，确定每个框的内部区域（框内不含边框的矩形区域）。若多个框的内部区域重叠，重叠像素归属于深度较前（遮挡他人的）框。
4. 计算每个框内部区域的几何中心（行列坐标各取内部区域的中值，取 floor），再计算该中心到青(8)标记像素的曼哈顿距离。
5. 按距离从小到大排名（最近 = 排名 1），对应色板 [红(2), 蓝(1), 绿(3), 黄(4)]。排名第 i 的框的内部所有黑(0)像素填充为色板第 i 色。距离相同时，框中心行较小的优先；行也相同时列较小的优先。
6. 保持所有灰(5)边框像素和青(8)标记不变。

**关键洞察**：框的补全改变了"哪些像素算内部"——如果不补全就直接用可见边界算内部，被遮挡的框的内部面积会被错误缩小或扩大，导致中心位置和距离排名出错。补全步骤与填充步骤通过框内部的几何定义紧密耦合。

## 新题 8：标记计数编码旋转角度后将碎片嵌入标记边框

**组合逻辑**：[计数(counting)](创新：计数编码的是旋转角度而非膨胀量) → [旋转(rotate)] → [描边(draw_frame)] + [拼合填充(packing)](创新：不是找最小矩形，而是嵌入预定义边框内)

**来源原语**：计数(counting) + 计数决定扩展量(count_determines_expansion) ← 52fd389e（创新改造为"计数决定旋转角度"）；旋转(rotation/rotate) ← b7cb93ac/3c9b0459；描边(draw_frame) + 极值内缩定边框(frame_inset_from_extrema) ← 928ad970；拼合填充(packing) + 多连块碎片(polyomino_fragment) + 按面积降序放置(descending_area_place) ← b7cb93ac；标记像素(marker_pixel) ← 共用；编码映射(encoding_map) ← 52fd389e

**依赖链**：每个碎片内嵌标记像素计数 k → k 编码旋转角度 (k*90°) → 旋转改变碎片的形状轮廓 → 黄(4)角标记确定目标边框 → 旋转后的碎片必须放入边框内 → 放置顺序按碎片在输入中的行主序位置 → 放入失败则说明旋转角度推断有误

**输入结构**：约 18x18 的黑(0)背景网格。3-4 个不同颜色（选自红(2)、蓝(1)、绿(3)、栗(9)）的多连块碎片（4-连通，4-7 像素，形状各异），分散在网格上半区。每个碎片内包含 0-3 个灰(5)标记像素（它们占据碎片体的一部分位置，即碎片总像素 = 碎片色像素 + 灰标记像素）。网格下半区有 4 个黄(4)像素位于矩形的四角位置，界定一个目标矩形区域（内部全为黑(0)）。生成约束：目标矩形的内部面积恰好等于所有碎片旋转后的总像素数（含灰(5)标记）；碎片经正确旋转后可以无重叠地铺满目标矩形内部；灰(5)标记在碎片内的位置保证旋转角度推断无歧义（即不同 k 值产生不同旋转结果）。

**规则**：
1. 对每个碎片，统计其内部灰(5)标记像素数 k。旋转角度 = k * 90° 顺时针。k=0 不旋转，k=1 旋转 90°，k=2 旋转 180°，k=3 旋转 270°。
2. 将每个碎片（包括其灰(5)标记）按对应角度顺时针旋转。
3. 在目标矩形区域内（黄(4)角标记所界定的矩形的内部，不含黄(4)像素所在行列），按碎片在输入中的行主序位置（碎片包围框左上角坐标：先比较行，行小者先；行同则列小者先）依次放入旋转后的碎片。放置策略：在目标区域内从左上到右下逐像素扫描，找到第一个能容纳碎片包围框且所有碎片像素位置均为黑(0)的位置，将碎片放入。
4. 放入的碎片保持各自颜色（碎片色像素保持原色，灰(5)标记像素也保持灰(5)）。
5. 移除网格上半区的原始碎片（恢复为黑(0)）。黄(4)角标记保留。
6. 输出整个处理后的网格。

**关键洞察**：灰(5)标记像素在碎片中承担双重角色——它们的数量编码旋转指令，同时它们作为碎片的一部分参与旋转和拼放。旋转后标记像素的位置改变了碎片的外形轮廓，直接影响拼放的可行性。编码被变换本身所消费。

## 新题 10：骨架格子中标记区域扩展与奇偶格点交叉着色

**组合逻辑**：[扩展填充(expand_fill)](创新：扩展范围由标记跨度决定，但着色不均匀) × [填充(fill)](创新：填充受坐标奇偶性调制) → 同时约束满足（非线性流水线）

**输入结构**：约 17x17 的黑(0)背景网格。灰(5)像素构成骨架格子：重复的 3x3 空心框，框间以 1 像素宽的灰(5)边界行和边界列分隔。每个空心框的中心像素为黑(0)（框内）。网格中有 2-3 种非灰、非黑颜色的标记像素（如红(2)和蓝(1)），每种颜色各 2-4 个标记像素，放置在骨架边界交叉点或边界线段上。生成约束：同颜色标记的跨度矩形互不完全重叠；每种颜色至少有一个标记在偶数行且一个在奇数行（以便推断奇偶规则）。

**规则**：
1. 从灰(5)像素的规律排列推断骨架的边界行集合和边界列集合。
2. 对每种标记颜色，将该颜色的所有标记映射到最近的骨架边界行/列交叉点，确定它们覆盖的边界区间，找到最小的格子对齐矩形（包含所有该颜色标记的最小骨架边界矩形）。
3. 在该矩形内的边界行和边界列上，将黑(0)像素涂为该标记颜色（扩展填充边界）。
4. 对于该矩形内的每个格子单元的中心像素（原为黑(0)），检查该单元在骨架中的格子坐标 (gr, gc)（从左上角格子为 (0,0) 开始计数）。若 (gr + gc) 的奇偶性与该颜色的第一个标记像素的 (row + col) 奇偶性相同，则将该中心像素涂为该标记颜色；否则保持黑(0)。
5. 若两种颜色的矩形重叠区域存在冲突（同一边界像素或中心像素被两种颜色都要求涂色），则后处理的颜色覆盖先处理的。处理顺序：标记颜色中像素总数较少的先处理，相同则颜色编号较小的先处理。
6. 原有灰(5)骨架像素不被覆盖。

**关键洞察**：标记的空间跨度决定了"涂哪些格子的边界"（扩展填充范围），标记自身的坐标奇偶性决定了"格子中心涂不涂"（奇偶过滤）——两者共同作用才能产生最终的棋盘状选择性着色图案。仅知道扩展范围不知道奇偶规则，或仅知道奇偶规则不知道扩展范围，都无法正确填色。
