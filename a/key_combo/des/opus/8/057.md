## 新题 1：封闭区域存活重力

**组合逻辑**：[洪泛填充](创新：不填色，而作为拓扑过滤器决定像素存亡) + [重力下落](已有) + [标记指示方向](已有，指示重力方向)

**来源原语**：洪泛填充/flood_fill、封闭区域/enclosed_region、墙壁线段/wall_segment、孤立背景区域填充/unreachable_background_filled ← a5313dff；重力下落/gravity_drop、标记指示方向/marker_indicates_dir、边缘标记线/edge_marker_line ← afe3afe9

**依赖链**：洪泛填充判定哪些区域被墙壁完全封闭，仅封闭区域内的彩色像素存活；重力方向由边缘灰色标记线给出，存活像素沿该方向滑动至撞墙或堆叠。拓扑判定和物理运动缺一不可——删去封闭检测则无法确定哪些像素保留，删去重力则无法确定保留像素的最终位置。

擦除开放区域中的彩色像素，对封闭区域内的存活像素按灰色边缘标记所示方向施加重力。

**输入结构**：约 12x12 的网格，黑(0)为背景。红(2)单像素厚的墙壁线段形成若干障碍结构，部分结构完全围合出封闭区域，部分结构有缺口通向边界。各区域中散布独立的彩色像素（蓝(1)、绿(3)、黄(4)），每个彩色像素与其他彩色像素不4-邻接。网格的某一条完整边缘（上/下/左/右之一）被灰(5)像素填满，标示重力方向。生成约束：至少有 2 个完全封闭区域和 2 个开放区域，每个封闭区域和至少 1 个开放区域中各含至少 1 个彩色像素。

**规则**：
1. 将红(2)像素视为不可穿越的墙壁。从网格四条边界出发沿4-邻接扩展所有可达的黑(0)像素，标记为"外部"。不可达的黑(0)像素标记为"内部/封闭"。
2. 位于外部区域的彩色像素被擦除（变为黑(0)）。位于封闭区域的彩色像素保留。
3. 确定重力方向：灰(5)标记线在上边缘→重力向上；下边缘→向下；左边缘→向左；右边缘→向右。
4. 对每个封闭区域内的存活彩色像素，沿重力方向逐一滑动，直到碰到红墙、该区域边界或已定位的其他像素。处理顺序：沿重力方向，靠近目标边的像素先处理（如重力向下时，行号最大的像素先处理）。
5. 输出中移除灰(5)标记线（该边恢复为黑(0)）。红墙保持不变。

**关键洞察**：彩色像素的存亡取决于其所在区域的拓扑封闭性（需洪泛填充判定），而存活像素的最终落点取决于全局重力方向——两个独立逻辑交叉决定输出，仅看单个示例难以同时确定封闭判定规则和重力方向。

## 新题 2：缺口方向决定嵌套压缩层序

**组合逻辑**：[压缩/嵌套层次](已有，将嵌套形状压缩为方环摘要) + [缺口决定方向](创新：缺口方向不再决定滑动目标，而决定压缩编码时颜色层序的正逆)

**来源原语**：压缩/compress、嵌套形状/nested_shape、方环/square_ring、嵌套层次/nesting_hierarchy、面积序映射环/area_order_to_ring ← eb5a1d5d；边框缺口/border_notch、缺口决定方向/notch_determines_dir ← 320afe60

**依赖链**：嵌套层次检测给出各层颜色从外到内的排列；缺口方向决定这个排列是正序还是逆序映射到输出方环。删去嵌套检测则无层序可编码，删去缺口分析则不知正逆——同一嵌套结构在不同缺口方向下产生相反的颜色环序。

将每组嵌套形状压缩为小方环摘要，外层形状的缺口方向决定颜色层序是由外到内还是由内到外。

**输入结构**：约 20x20 的网格，黑(0)为背景。网格中有 2-3 组空间互不重叠的嵌套形状组。每组由 3-4 层同心嵌套的单色形状构成（8-连通），每层颜色不同，从{蓝(1), 红(2), 绿(3), 黄(4), 品红(6), 橙(7), 青(8)}中取，外层包围盒面积严格大于内层。每组最外层形状的边界上恰好有一个单像素的黑(0)缺口（该层轮廓上缺失一个像素）。缺口位于上边/下边/左边/右边之一。不同示例中嵌套形状的具体轮廓各异（不规则闭合曲线），但嵌套包围盒层次清晰。生成约束：每组中各层颜色互不相同；至少有一组缺口在上/右，至少有一组缺口在下/左。

**规则**：
1. 识别每组嵌套形状（通过包围盒嵌套关系），按包围盒面积从大到小排序各层，得到层序列 [L_outer, ..., L_inner]。
2. 检查最外层的缺口位置：
   - 缺口在上边或右边→正序编码：输出方环从外到内依次使用 L_outer, ..., L_inner 的颜色。
   - 缺口在下边或左边→逆序编码：输出方环从外到内依次使用 L_inner, ..., L_outer 的颜色。
3. 为每组生成嵌套方环摘要：边长 = 2 * 层数 - 1，从外向内每层缩小一圈（最外环为完整方框，最内层为单像素中心）。
4. 所有摘要方环按其对应组在输入中的包围盒左上角 x 坐标从小到大排列在一行上，相邻方环间隔 1 列黑(0)像素。输出高度等于最大方环的边长，较小方环顶部对齐。

**关键洞察**：缺口方向将嵌套压缩分为两个分支——正序和逆序——使得同一组嵌套形状仅因缺口位置不同就产生完全相反的颜色环序。必须对比多个示例才能归纳出缺口方向与层序正逆的对应规则。

## 新题 3：错切诱发封闭区域

**组合逻辑**：[错切](已有，几何变换改变行间对齐) → [洪泛填充](已有，在变换后的网格中检测因行偏移而新产生的封闭区域)

**来源原语**：错切/shear、行偏移递变/row_offset_progress、行内容保持/row_content_preserved ← 3cd86f4f；洪泛填充/flood_fill、封闭区域/enclosed_region、墙壁线段/wall_segment、孤立背景区域填充/unreachable_background_filled ← a5313dff

**依赖链**：错切改变墙段之间的水平对齐关系，使原本不相邻的墙段在新网格中紧邻从而封合区域。洪泛填充必须在错切后执行，因为原始网格中所有区域均通向边界。几何变换创造了新的拓扑属性——这种因果关系在任一源题中均不存在。

对含红墙线段的网格施加下右错切使断开的墙段偏移接合，然后用蓝色填充所有新形成的封闭区域。

**输入结构**：约 8x8 的网格，黑(0)为背景。红(2)单像素厚的墙壁线段分布在网格中，形成若干近似封闭但有小缺口的结构。在原始网格中，所有黑(0)区域均可4-邻接到达边界（即原始网格无封闭区域）。生成约束：经过下右错切（行 r 右移 r 列）后，至少有 1 个原本开放的区域因墙段偏移接合而变为封闭区域。

**规则**：
1. 创建新网格，宽度 = W + H - 1，高度 = H，初始填满黑(0)。
2. 将原始网格的第 r 行（r 从 0 开始）整行复制到新网格的第 r 行，起始列为 r（即行 0 从列 0 开始，行 1 从列 1 开始，以此类推）。每行内容不变，仅水平位置偏移。
3. 在新网格中执行洪泛填充：从四条边界出发沿4-邻接扩展所有可达的黑(0)像素，标记为外部。
4. 将所有不可达的黑(0)像素（封闭区域）填充为蓝(1)。红(2)墙壁保持不变，外部黑(0)保持不变。

**关键洞察**：错切不改变任何行的内容（行内容保持），但改变了相邻行之间的水平对齐。原始网格中同列但不同行的红墙像素在错切后水平错开，而原本不同列的红墙像素可能因偏移变为水平相邻，封合出原本不存在的闭合区域。求解者必须先在脑中完成错切再分析拓扑。

## 新题 4：格阵位置筛选与面积重排

**组合逻辑**：[筛选/边缘与内部区分](格阵中的位置分类决定精灵体存亡) → [压缩重排/排序](创新：存活精灵体不再原地重涂色，而被提取、重塑为正方形并按面积重新排列)

**来源原语**：筛选/filter、格子结构/lattice、单元格区域/cell_region、行列阵列位置/row_column_position、边缘与内部区分/perimeter_interior_distinction ← 8a371977；压缩重排/repack、排序/sort、色块/color_group、正方形/square、面积递增排列/area_ascending_order、像素数定边长/pixel_count_determines_side ← 8abad3cf

**依赖链**：格阵位置分类（周缘 vs 内部）决定哪些精灵体被保留，而保留精灵体的像素数决定其重塑尺寸和排列顺序。删去位置筛选则不知保留谁，删去面积重排则不知输出形态——空间分类和几何重塑是两个独立维度的信息。

在格阵中丢弃周缘单元格的精灵体，将内部单元格的精灵体按像素数重塑为正方形并按面积从小到大排列。

**输入结构**：约 17x17 的网格。灰(5)像素构成格阵骨架（单像素宽的完整行和完整列），将网格分割为至少 4x4 的矩形单元格阵列。每个单元格内部以黑(0)为底，包含一个单色4-连通精灵体（3-16 像素），颜色从{蓝(1), 红(2), 绿(3), 黄(4), 橙(7), 青(8)}中取。所有内部单元格（非阵列最外行/列）中的精灵体像素数恰好为完全平方数（4 或 9 或 16）。周缘单元格的精灵体像素数可以不是完全平方数。生成约束：内部单元格至少 3 个，且至少 2 个精灵体的像素数不同。不同示例中同类精灵体的具体形状不同。

**规则**：
1. 识别灰(5)格阵将网格分割成的单元格阵列，确定每个单元格的阵列行号和列号（从 0 开始）。
2. 周缘单元格（阵列行号为 0 或最大值，或阵列列号为 0 或最大值）中的精灵体被丢弃。
3. 内部单元格中的精灵体被保留。对每个保留的精灵体，计算其像素数 n，重塑为边长 sqrt(n) 的实心正方形，颜色不变。
4. 将所有重塑后的正方形按边长从小到大排列。边长相同时，按其原始单元格位置从左到右、从上到下排序（先比较列号，列号相同再比较行号）。
5. 输出为单行排列：所有正方形底部对齐，相邻正方形之间间隔 1 列黑(0)像素。输出高度等于最大正方形的边长，输出背景为黑(0)。

**关键洞察**：格阵的空间位置提供了二元分类信号（周缘淘汰、内部保留），这不是装饰而是功能性筛选条件。周缘精灵体的像素数故意不是完全平方数，这是一个隐蔽线索——只有通过对比多个示例发现"内部精灵体总是完全平方数、周缘总是非完全平方数"，才能确认筛选规则与位置的对应关系。

## 新题 5：条形双重编码驱动逐行变换

**组合逻辑**：[计数/条形段](已有，读取条形长度) + [错切/行偏移递变](创新：偏移量不是固定公式 r 而是从条形长度解码) + [重涂色](创新：条形颜色编码该行的色彩替换规则)

**来源原语**：计数/counting、条形段/bar_segment、长度映射颜色/length_maps_color、固定编码表/fixed_encoding ← e048c9ed；错切/shear、行偏移递变/row_offset_progress、行内容保持/row_content_preserved ← 3cd86f4f；重涂色/recolor ← 多题

**依赖链**：每条条形承载两种独立编码——长度是该行的水平偏移量（几何参数），颜色是该行的重涂色规则（色彩参数）。两者同时作用于同一行且互不依赖，必须对比多个示例才能将两种效果分离：仅改变长度的示例暴露偏移规则，仅改变颜色的示例暴露重涂色规则。

左侧彩色条形同时编码右侧图案每行的水平偏移量（条形长度）和重涂色规则（条形颜色），解码后对右侧图案施加逐行变换。

**输入结构**：约 10x16 的网格，黑(0)为背景。一条灰(5)竖直分隔线将网格分为左右两半。左半区：每行至多有一条水平条形段（连续同色像素），颜色为蓝(1)、红(2)或绿(3)之一，长度在 1-4 之间；部分行可能没有条形（空行）。右半区：一个约 6x6 的多色图案（使用黄(4)、橙(7)、青(8)等颜色），嵌在黑背景中。左右两半高度相同，行一一对应。生成约束：三种条形颜色在所有行中至少各出现一次；至少有两行条形长度不同。

**规则**：
1. 对右半区的每一行，找到左半区同行的条形段。若该行无条形，该行偏移量为 0 且不重涂色。
2. 条形长度 L 决定该行的右移偏移量：将右半区该行内容整体右移 L 列。超出右半区右边界的部分截断，左侧空出的位置填黑(0)。
3. 条形颜色决定该行的重涂色规则（仅作用于非黑像素）：
   - 蓝(1)：保持原色不变。
   - 红(2)：将该行所有非黑像素替换为品红(6)。
   - 绿(3)：将该行所有非黑像素替换为栗(9)。
4. 偏移和重涂色同时应用于同一行（先偏移再重涂色，效果等价于同时执行）。
5. 输出仅包含变换后的右半区（去除左半区和灰分隔线），宽度与原右半区相同。

**关键洞察**：每条条形是一个复合编码元素——其长度和颜色是两个正交的信息通道，分别控制几何变换和色彩变换。仅看一个示例时，长度效果和颜色效果混在一起难以区分；必须对比多个示例（特别是条形颜色相同但长度不同、或长度相同但颜色不同的行）才能分离两种编码。

## 新题 6：逐单元调色的克罗内克印章

**组合逻辑**：[克罗内克积/二值掩码](已有，掩码作为形状模板) + [颜色配对映射/标记像素](创新：不再全局统一调色，而是每个单元格的标记独立选择前景/背景色对)

**来源原语**：克罗内克积/kronecker_product、二值掩码/binary_mask、印章覆盖/stamp_overlay ← c803e39c；颜色配对映射/color_pair_mapping、标记像素/marker_pixel、窗口格/window_cell、标记色定窗口填充/marker_sets_window_fill ← 54d9e175

**依赖链**：二值掩码提供所有单元格共享的形状模板（空间结构），但每个单元格的前景/背景色由其中心标记像素通过颜色配对映射独立决定。掩码决定"哪些位置是前景"，标记决定"前景/背景分别涂什么色"——两者在每个单元格中交叉作用。删去掩码则无形状结构，删去标记映射则无法确定各单元格的着色方案。

将同一个二值掩码铺入每个标记单元格，但每个单元格的标记颜色独立选择该单元格中掩码前景和背景的具体着色。

**输入结构**：约 12x20 的网格，黑(0)为背景。一条灰(5)竖直分隔线将网格分为左右两区。左区：一个约 3x3 的二值掩码，前景像素为灰(5)、背景为黑(0)；掩码形状不关于任何轴对称（以便在输出中可辨认朝向）。右区：被灰(5)单像素宽分隔线切分为 2x3 或 3x3 的单元格阵列，每个单元格约 3x3；每个单元格中心位置有一个标记像素，颜色从{蓝(1), 红(2), 绿(3), 品红(6)}中取，其余位置为黑(0)。生成约束：至少使用 3 种不同的标记颜色；掩码中前景和背景像素均至少占 2 个。

**规则**：
1. 从左区提取二值掩码 M（区分前景位置和背景位置）。
2. 对右区的每个单元格，读取其中心标记像素的颜色 c。
3. 根据颜色 c 查找前景/背景色对：
   - 蓝(1) → 前景色=红(2)，背景色=橙(7)。
   - 红(2) → 前景色=黄(4)，背景色=栗(9)。
   - 绿(3) → 前景色=青(8)，背景色=灰(5)。
   - 品红(6) → 前景色=蓝(1)，背景色=绿(3)。
4. 将每个单元格替换为掩码 M 的着色副本：M 中前景位置填该单元格对应的前景色，背景位置填对应的背景色。
5. 输出仅包含右区变换后的结果（去除左区和左侧灰分隔线）。右区内部的灰(5)分隔线保持不变。

**关键洞察**：同一个掩码形状在每个单元格中重复出现（统一空间结构），但每个单元格的标记颜色通过一个隐式配对映射独立选择了前景/背景的着色方案（局部色彩自由度）。必须同时理解掩码形状逻辑和颜色配对映射才能正确生成输出——只看一个单元格无法确定映射表，需对比多个不同标记色的单元格。

## 新题 7：滑动诱发对齐连线

**组合逻辑**：[滑动/缺口决定方向](已有，对象按缺口方向滑向边缘) → [连线/同行列对齐](创新：连线条件基于滑动后的新位置而非原始位置) → [重涂色](创新：是否参与连线决定对象的最终颜色)

**来源原语**：滑动/slide、缺口决定方向/notch_determines_dir、边框缺口/border_notch、靠边对齐/edge_aligned ← 320afe60；连线/connect、同行列对齐/same_row_col_align、标记像素/marker_pixel、局部偏移保持/local_offset_preserved ← cbded52d；重涂色/recolor ← 多题

**依赖链**：缺口决定每个对象的滑动方向 → 滑动改变对象位置 → 新位置决定哪些标记像素同行/列对齐 → 对齐的标记之间画连线 → 是否参与连线决定对象的重涂色。每个环节的输出是下一环节不可替代的输入，形成严格依赖链。

滑动各对象至边缘后，连接新位置下同色同行/列对齐的标记像素，再按是否参与连线对对象重涂色。

**输入结构**：约 14x14 的网格，黄(4)为背景。网格中有 4-6 个蓝(1)单色4-连通小对象（每个 4-8 像素），彼此不4-邻接。每个对象内部恰好有一个位置的像素颜色不是蓝(1)而是标记色（红(2)或绿(3)），该标记像素占据对象的一个像素位置。每个对象的包围盒边界上恰好有一个缺口：在该边的像素行/列中，有一个背景色(黄(4))像素被两侧的对象像素(蓝(1))夹着。缺口位于上/下/左/右边之一。同一标记颜色恰好出现在 2 个不同的对象中（如红(2)标记出现 2 次，绿(3)标记出现 2 次）。生成约束：至少有一对同色标记在滑动后同行或同列对齐，至少有一对不对齐。所有对象的滑动路径互不交叉、滑动后包围盒互不重叠。

**规则**：
1. 确定每个对象的缺口方向：缺口在右边→对象整体向右平移直到包围盒右侧抵达网格右边缘；缺口在左边→向左至左边缘；上→向上至上边缘；下→向下至下边缘。标记像素随对象整体移动，保持其在对象内的局部偏移。
2. 所有对象同时滑动，互不碰撞（生成时已保证路径无冲突）。
3. 滑动完成后，检查每对同色标记像素：若两者位于同一行或同一列，则在它们之间沿该行/列画一条该标记颜色的连线（仅覆盖路径上的背景像素(黄(4))，不覆盖对象像素）。
4. 参与了连线的对象（其标记与另一同色标记成功对齐）的蓝(1)像素全部重涂为绿(3)（标记像素颜色不变）。未参与连线的对象的蓝(1)像素全部重涂为红(2)（标记像素颜色不变）。
5. 背景保持黄(4)。

**关键洞察**：对象的缺口方向决定滑向哪条边缘，但连线关系是滑动的结果而非输入的直接可读属性——两个标记在原始位置可能不对齐，但滑动后恰好同行/列；或者原本对齐但滑向不同边缘后错开。求解者必须先完成所有滑动，再判断对齐关系，最后据此重涂色。

## 新题 8：连线距离的颜色编码

**组合逻辑**：[连线/同行列对齐](已有，连接同色标记) + [计数](已有，测量连线长度) + [重涂色/固定编码表](创新：连线的颜色不继承标记色，而由连线长度通过固定编码表决定)

**来源原语**：连线/connect、同行列对齐/same_row_col_align、标记像素/marker_pixel ← cbded52d；计数/counting、长度映射颜色/length_maps_color、固定编码表/fixed_encoding ← e048c9ed；重涂色/recolor ← 多题

**依赖链**：连线检测确定哪些标记对之间画线（拓扑结构），计数确定每条线的像素长度（度量信息），固定编码表将长度映射为颜色（离散查表）。三者串联且每步不可跳过——删去连线则无线可量，删去计数则不知线长，删去编码表则不知着何色。

连接同色同行/列对齐的标记像素，但连线颜色不是标记色而是由连线长度通过固定编码表决定。

**输入结构**：约 12x12 的网格，黑(0)为背景。网格中散布若干标记像素，颜色从{蓝(1), 红(2), 绿(3), 黄(4)}中取。每种标记颜色恰好出现 2 次，且该对标记必定共享同一行或同一列。不同颜色的标记对之间的连线路径互不交叉。每对标记之间的间距（不含标记本身的像素数）在 2-8 之间。生成约束：至少有两对标记的间距属于不同的编码区间（见下方规则），以便求解者可通过对比确认编码表。

**规则**：
1. 对每种标记颜色，找到该颜色的两个标记像素。两者必共享同一行或同一列。
2. 在两个标记之间沿该行/列画一条连线（覆盖中间的黑(0)像素）。标记像素本身保持原色不变。
3. 计算连线的长度 d（两标记之间不含标记本身的像素数）。
4. 根据长度 d 查固定编码表确定连线颜色：
   - d = 2 或 3 → 连线颜色为橙(7)。
   - d = 4 或 5 → 连线颜色为品红(6)。
   - d = 6 或 7 → 连线颜色为灰(5)。
   - d = 8 → 连线颜色为栗(9)。
5. 连线中的每个像素均涂为该编码颜色。标记像素不变。背景不变。

**关键洞察**：连线的颜色与标记本身的颜色完全无关——标记色仅用于配对（哪两个像素该连），而连线的着色由空间距离通过一个隐式编码表决定。这个编码表必须通过对比多条不同长度的连线才能归纳出来，是本题最隐蔽的规则。
