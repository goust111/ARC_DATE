## 新题 1：不对称标记连线

**组合逻辑**：[对称检测](选出不对称对象作为活跃标记) → [计数](统计活跃标记的像素数，映射连线颜色) → [连线/首尾跨度填充](对同行列的活跃标记做跨度连接)

**来源原语**：对称检测(#73ccf9c2)、计数(#6e02f1e3)、连线/首尾跨度填充(#ded97339)、前景对象(#73ccf9c2)、同行列对齐(#ded97339)

**依赖链**：对称检测筛选出哪些对象参与连线（未通过对称检测的对象被忽略）；活跃标记的像素总数决定连线使用的颜色；连线仅发生在活跃标记之间，非活跃对象既不参与也不阻挡。

将网格中不对称的前景对象视为活跃标记，统计其总像素数以确定连线颜色，然后在同行或同列的活跃标记之间画跨度连线。

**输入结构**：约 15x15 的黑(0)背景网格。网格上散布 5~8 个灰(5)的 4-连通单色小对象（3~7 像素），彼此不相邻、不共享行列上的像素。其中部分对象在其紧包围框内具有左右镜像对称性，其余不具有。生成约束：至少有 2 个不对称对象共享某一行或某一列；不同示例中对称/不对称对象的数量比例不同。

**规则**：
1. 将每个灰(5)的 4-连通前景对象裁剪到其紧包围框，判断其前景掩码是否等于自身的左右镜像。
2. 将所有不对称的对象标记为"活跃标记"，对称对象保持原样不参与后续操作。
3. 统计所有活跃标记的像素总数 N。若 N <= 8，连线颜色为蓝(1)；若 9 <= N <= 14，连线颜色为红(2)；若 N >= 15，连线颜色为绿(3)。
4. 对于每一行，若该行穿过至少两个活跃标记的包围框，则从最左侧活跃标记包围框的最左列到最右侧活跃标记包围框的最右列，将该行上所有黑(0)背景像素填充为连线颜色。活跃标记自身的灰(5)像素保留不变。
5. 对于每一列，执行相同的纵向跨度填充。
6. 对称对象、非活跃区域的背景保持不变。若水平连线和垂直连线在某像素交叉，该像素为连线颜色（无冲突，颜色相同）。

**关键洞察**：对称性检测不是输出的一部分，而是一个隐式门控——它决定哪些对象"存在"于连线逻辑中；像素总数到颜色的映射阈值需要对比多个示例才能归纳出。

## 新题 2：对角朝向分组扩展与图例层叠

**组合逻辑**：[分类/对角朝向](按对角方向分两组) → [扩展](每组的包围框各向外扩一格) → [图例配色](图例决定每组的填充色) → [冲突优先级](像素总数多的组在前层)

**来源原语**：分类/对角朝向(#1d61978c)、扩展(#305b1341)、图例配色(#305b1341)、冲突优先级(#305b1341)、计数(#6e02f1e3)

**依赖链**：对角方向分类决定分组方式；图例将方向组映射到填充色；每组的像素总数决定两个扩展区域重叠时的层叠优先级——像素多的组覆盖像素少的组，这一优先级规则需要在重叠区域才能观察到。

将对角前景条按 NW-SE 与 NE-SW 分为两组，分别扩展包围框并用图例指定的颜色填充，重叠区域由像素数多的组覆盖。

**输入结构**：约 14x14 的黑(0)背景网格。左侧两列（列 0-1）从第 0 行起构成两行图例：第一行左格为橙(7)、右格为黄(4)；第二行左格为橙(7)、右格为绿(3)。图例的含义是"第一种对角朝向用黄(4)填充，第二种用绿(3)填充"——但哪种朝向对应图例的哪一行由下文规则确定。网格其余区域分布着若干橙(7)的前景像素，每个前景像素恰好属于一条 NW-SE 或 NE-SW 方向的一像素宽对角线段（长度 2~5 像素）。两种朝向的线段都存在，且它们的包围框扩展后有重叠区域。生成约束：两种朝向的像素总数不相等。

**规则**：
1. 忽略图例区域（列 0-1）的像素，对网格其余区域的每个橙(7)前景像素判断对角朝向：若该像素与其 NW 或 SE 方向的邻居同为前景，则归入 A 组（NW-SE）；若与 NE 或 SW 方向的邻居同为前景，则归入 B 组（NE-SW）。
2. 统计 A 组与 B 组的前景像素总数。像素总数较多的组为"多数组"，较少的为"少数组"。
3. 图例第一行（行 0）的填充色分配给多数组，第二行（行 1）的填充色分配给少数组。
4. 分别计算 A 组和 B 组所有前景像素的紧包围框，将每个包围框向四个方向各扩展 1 像素（不超出网格边界）。
5. 先绘制少数组：在其扩展包围框内，将所有黑(0)背景像素填充为该组的填充色，保留所有原始橙(7)前景像素不变。
6. 再绘制多数组（覆盖少数组）：在其扩展包围框内，将所有非橙(7)的像素（包括黑色背景和已被少数组填充的像素）替换为该组的填充色。保留橙(7)前景像素。
7. 清除图例区域：将列 0-1 的所有像素设为黑(0)。

**关键洞察**：图例的两行分别对应哪个朝向组不是固定的——它由像素数量的多少决定，必须对比多个示例（其中多数组朝向不同）才能归纳出"多数组取图例第一行"的隐式规则。

## 新题 3：框架内角标记编码缩放因子

**组合逻辑**：[裁剪](提取框架内部) → [计数](统计角标记的不同颜色数) → [像素放大](颜色数作为缩放因子) → [擦除](从缩放结果中移除角标记)

**来源原语**：裁剪(#94133066)、空心矩形/rectangular_frame(#952a094c)、角标记/corner_marker(#952a094c)、像素放大/pixel_scaling(#f25fbde4)、计数(#6e02f1e3)、擦除(#952a094c)

**依赖链**：裁剪依赖框架定位；角标记的颜色多样性决定缩放因子（不知道颜色数就无法确定放大倍率）；缩放后必须擦除角标记——角标记在缩放前是信息编码器，缩放后变成应被移除的残留物。

提取每个框架的内部内容，按框架内角标记的不同颜色数进行像素放大，最后擦除放大后的角标记像素。

**输入结构**：约 20x20 的黑(0)背景网格。网格上有 2~3 个互不重叠的灰(5)一像素宽空心矩形框架（尺寸约 4x4 至 6x6）。每个框架的内部四角各有一个标记像素，标记像素的颜色取自蓝(1)、红(2)、绿(3)、黄(4)，四个角标记的颜色可以相同也可以不同（1~4 种不同颜色）。框架内部除角标记外，还有若干橙(7)的前景像素构成一个小型 4-连通图案（3~6 像素）。不同框架的内部图案形状不同，角标记颜色数也不同。生成约束：每个框架的四角标记颜色数互不相同（如一个框架 1 种，另一个 2 种，第三个 3 种）。

**规则**：
1. 识别每个灰(5)空心矩形框架，提取其内部区域（不含框架像素本身）。
2. 统计该框架内部四个角像素的不同颜色数 K（1 <= K <= 4）。
3. 将内部区域的每个像素替换为 K x K 的同色块，得到放大后的子网格。
4. 在放大后的子网格中，定位四个角区域（每个角是 K x K 的块），将它们全部设为黑(0)背景。
5. 将所有框架的放大结果按从上到下、从左到右的顺序排列输出。第一个放大结果放在输出网格的左上角，后续结果紧邻右侧排列（若一行放不下则换行），间隔 1 列黑色分隔。输出网格大小恰好容纳所有结果。

**关键洞察**：角标记的身份是双重的——它们既是内部图案的一部分（占据内部四角位置），又编码了缩放参数；缩放完成后它们必须被擦除，否则会在输出中留下不属于原始图案的色块。颜色数与缩放因子的映射关系需要对比多个框架的输入输出才能确认。

## 新题 4：交替平移制造对齐后跨度填充

**组合逻辑**：[排序/排列顺序](按纵向位置排序) → [交替平移](奇偶位对象左右移) → [连线/首尾跨度填充](对移位后同列的对象做纵向连接) → [重涂色](连线使用与端点不同的新颜色)

**来源原语**：交替平移(#4364c1c4)、排列顺序(#4364c1c4)、奇偶定方向(#4364c1c4)、连线/首尾跨度填充(#ded97339)、同行列对齐(#ded97339)、重涂色(#0d87d2a6)

**依赖链**：排序确定奇偶分配；交替平移改变对象的列坐标，使原本不同列的对象可能移入同一列；跨度填充仅在移位后的列坐标上检测对齐——不移位就不会有对齐。连线颜色由端点对象无法单独决定，需要额外规则。

先按纵向排序对前景对象做奇左偶右的交替平移，然后对移位后恰好同列的对象之间做纵向跨度连线，连线颜色取决于该列上被连接的对象数量。

**输入结构**：约 15x15 的黑(0)背景网格。网格上有 6~8 个红(2)的 4-连通单色小对象（2~5 像素），每个对象的包围框顶行互不相同（即有唯一的从上到下排序）。所有对象的包围框宽度为 1~2 列。对象的列坐标经过精心安排：原始状态下没有任何两个对象共享同一列范围，但某些相邻排名的对象列坐标恰好相差 2（即一个左移 1、另一个右移 1 后会共享某列）。生成约束：移位后至少有两组不同的列产生对齐，且至少一组有 2 个对象对齐、另一组有 3 个对象对齐。

**规则**：
1. 将所有红(2)前景对象按包围框顶行从小到大排序，排名从 1 开始。
2. 排名为奇数的对象整体向左平移 1 列；排名为偶数的对象整体向右平移 1 列。超出网格左边界的像素丢弃，超出右边界的像素丢弃。
3. 平移后，检查每一列：若该列上有至少两个不同对象的像素，则从该列上最靠上的对象像素所在行到最靠下的对象像素所在行，将该列上所有黑(0)背景像素填充为连线颜色。对象自身的红(2)像素保留不变。
4. 连线颜色由该列上参与连接的不同对象数 M 决定：M = 2 时填蓝(1)，M = 3 时填绿(3)，M >= 4 时填黄(4)。
5. 不参与任何连线的对象仅保留平移后的位置，无额外变化。

**关键洞察**：输入中没有任何两个对象同列——对齐完全是交替平移的涌现结果；求解者必须先推断奇偶平移规则，再在平移后的坐标系中识别对齐关系。连线颜色与对象数量的映射需要在存在不同对齐数量的示例中对比归纳。

## 新题 5：象限异常值精灵平铺全域

**组合逻辑**：[裁剪/象限分割](四象限分离) → [异常值选择](找到与其他三象限精灵不同的那个) → [裁剪](紧包围框裁剪异常精灵) → [平铺](将异常精灵作为瓦片铺满整个网格)

**来源原语**：象限(#0b148d64)、分隔行列(#0b148d64)、异常值选择(#0b148d64)、裁剪(#0b148d64)、平铺(#ea959feb/#0a938d79)、周期重复(#ea959feb)、归一化形状匹配(#2a5f8217)

**依赖链**：象限分割是定位的前提；异常值选择依赖跨象限的形状比较（需要归一化形状匹配来判断"相同"与"不同"）；被选中的异常精灵成为平铺的种子瓦片——选错异常值就会铺错图案。

将网格分为四个象限，找到精灵形状与其他三个不同的象限，裁剪出该异常精灵，然后将其作为周期瓦片从左上角开始铺满整个输出网格。

**输入结构**：约 13x13 的黑(0)背景网格（奇数行列以保证有唯一中心分隔线）。正中间的一整行和一整列为灰(5)分隔线，将网格分为四个大小相等的象限。每个象限内有一个由单一非黑非灰颜色构成的 4-连通小精灵（3~6 像素），四个象限的精灵颜色各不相同，取自蓝(1)、红(2)、绿(3)、黄(4)。其中三个象限的精灵在归一化到包围框左上角后形状完全相同（但颜色不同），第四个象限的精灵形状不同（这是异常值）。精灵在象限内的位置各不相同。生成约束：异常精灵的包围框高度和宽度均不超过象限尺寸的一半（以保证平铺时至少能重复两次）。

**规则**：
1. 识别灰(5)分隔行和分隔列，将网格分为四个象限（不含分隔线）。
2. 提取每个象限中的非黑前景精灵，裁剪到紧包围框，得到归一化掩码（仅看形状，忽略颜色）。
3. 比较四个归一化掩码：三个相同的是"正常"精灵，一个不同的是"异常"精灵。
4. 将异常精灵的紧包围框裁剪保留（保留其原始颜色）。
5. 输出网格的尺寸等于输入网格去掉分隔行列后一个象限的尺寸。以异常精灵裁剪结果为瓦片，从输出网格左上角开始按行优先顺序周期平铺，超出输出网格边界的部分截断。瓦片之间无间隔，未被瓦片覆盖的像素（瓦片内的黑色背景部分）保持黑(0)。

**关键洞察**：异常值不是用颜色判定的（四个颜色都不同），而是用归一化形状判定的——必须对比四个象限的精灵形状才能确定哪个是异常值。异常值从"被排除者"变成唯一的输出种子，这一反转需要多个示例确认。

## 新题 6：互补部分精灵补全后按边界标记旋转

**组合逻辑**：[补全/对齐合并取并集](多个残缺副本合并为完整精灵) → [旋转](按边界标记编码的角度旋转每个完整精灵) → [放置](将旋转后的精灵放回原位)

**来源原语**：补全/对齐合并取并集(#f8cc533f)、各副本互补缺失(#f8cc533f)、部分图案(#f8cc533f)、旋转(#94133066)、外部标记(#94133066)、放置(#a32d8b75)、标记编码位置(#a32d8b75)

**依赖链**：补全操作依赖跨颜色的掩码对齐（不完成补全就不知道精灵的完整形状）；旋转依赖边界标记的位置解读（不知道角度就无法旋转）；旋转的对象又是补全的产物——两步缺一不可。

多种颜色的残缺精灵各自缺失不同部分，通过掩码并集恢复完整形状后，按网格边界上同色标记的位置编码进行旋转。

**输入结构**：约 16x16 的黑(0)背景网格。网格内有 3 种非背景颜色（如蓝(1)、红(2)、绿(3)），每种颜色的前景像素构成同一精灵掩码的一个残缺副本。所有副本左上角对齐到各自的起始位置，但每个副本缺失了精灵掩码中的若干像素（缺失区域为黑色）。三个副本的缺失部分互补：任意一个像素位置，至少有一个副本在该位置保留了前景像素。三个副本在网格上的放置位置互不重叠。另外，网格的四条边界（第 0 行、最后一行、第 0 列、最后一列）上各有至多一个标记像素，标记像素的颜色为蓝(1)、红(2)或绿(3)之一。每种颜色恰好有一个边界标记。生成约束：三个副本的起始位置之间有足够间距，旋转后的精灵不会超出各自副本所在的区域；完整精灵非正方形（以便旋转后可观察到变化）。

**规则**：
1. 对每种颜色，提取其所有前景像素，裁剪到紧包围框，得到该颜色的部分掩码。
2. 将三种颜色的部分掩码按左上角对齐，取像素级"或"并集，得到完整的精灵模板掩码。
3. 对每种颜色，用完整模板掩码替换其部分掩码：在该颜色副本的起始位置，将模板掩码中所有为前景的位置都填充为该颜色。
4. 找到每种颜色的边界标记像素，根据其所在边界确定旋转角度：顶边 = 0 度（不旋转）、右边 = 顺时针 90 度、底边 = 180 度、左边 = 顺时针 270 度。
5. 以每个副本的包围框中心为旋转中心，将补全后的精灵按对应角度旋转。旋转后超出原包围框的像素截断。
6. 移除所有边界标记像素（设为黑(0)）。

**关键洞察**：补全和旋转是串联但紧耦合的——如果不先补全就直接旋转，残缺精灵旋转后的形状是错误的；如果补全后不旋转，输出的精灵朝向是错误的。边界标记的位置编码规则（哪条边对应哪个角度）需要对比多个示例才能归纳。

## 新题 7：引导线接触筛选后按形状匹配重涂色

**组合逻辑**：[连线/引导线绘制](边界标记对生成引导线) → [接触判定](引导线是否接触占位符对象) → [形状匹配](为被接触的占位符找到形状相同的模板) → [重涂色](仅被接触的占位符获得模板颜色)

**来源原语**：连线/引导线(#0d87d2a6)、边界标记对(#0d87d2a6)、接触判定(#0d87d2a6)、接触则重涂(#0d87d2a6)、形状匹配(#2a5f8217)、归一化形状匹配(#2a5f8217)、占位符对象(#2a5f8217)、模板对象(#2a5f8217)、重涂色(#2a5f8217)

**依赖链**：引导线的绘制依赖边界标记对的识别；接触判定依赖引导线是否已画出（引导线未画之前无法判断接触）；形状匹配独立于引导线但只在接触判定为真时才有效——接触是重涂色的门控条件，形状匹配是重涂色的颜色来源。两个独立子系统（引导线 + 形状匹配）必须同时求解才能确定最终输出。

在网格上画出由边界标记对定义的引导线，然后仅将被引导线接触到的蓝色占位符对象重涂为其形状匹配模板的颜色，未被接触的占位符保持蓝色。

**输入结构**：约 18x18 的黑(0)背景网格。网格上有若干蓝(1)的 4-连通占位符对象和若干非蓝非黑的 4-连通模板对象（模板颜色取自红(2)、绿(3)、黄(4)、橙(7)，每个模板颜色唯一）。每个占位符的归一化掩码与恰好一个模板的归一化掩码相同。另外，网格的左右边界上各有 1~2 个品红(6)标记像素，位于同一行的左边界和右边界上成对出现（定义水平引导线）；网格的上下边界上各有 1~2 个品红(6)标记像素，位于同一列的上边界和下边界上成对出现（定义垂直引导线）。引导线总数 2~3 条。生成约束：至少一个占位符被引导线接触，至少一个占位符不被接触；所有模板对象都不被引导线接触。

**规则**：
1. 识别所有品红(6)边界标记对：同一行的左右边界标记定义一条水平引导行，同一列的上下边界标记定义一条垂直引导列。
2. 将每条引导行/列上的所有像素覆盖为品红(6)。已有的前景对象像素被引导线覆盖（但这只影响视觉，不影响对象的原始形状记录——形状匹配基于引导线绘制前的原始形状）。
3. 对每个蓝(1)占位符对象（使用其原始、引导线绘制前的像素集合），判断是否有至少一个像素与引导线像素 4-邻接或重合（接触判定）。
4. 对于被接触的占位符：将其归一化掩码（引导线绘制前）与所有模板对象的归一化掩码比较，找到唯一匹配的模板。将该占位符的所有原始像素位置（若被引导线覆盖则在引导线之上）重涂为模板的颜色。
5. 对于未被接触的占位符：保持其蓝(1)颜色不变（若被引导线覆盖，则覆盖位置显示为品红(6)，未覆盖位置保持蓝(1)）。
6. 模板对象保持原色不变（若被引导线覆盖，则覆盖位置显示为品红(6)）。

**关键洞察**：形状匹配和引导线接触是两个独立的逻辑子系统，但它们必须同时满足才能触发重涂色——光有形状匹配不够（未被接触的占位符不变色），光有接触也不够（接触不决定颜色）。求解者必须发现"接触是门控、形状是映射"的双重结构。

## 新题 8：种子条纹遇障碍偏转绕行

**组合逻辑**：[种子像素定周期](两个种子确定条纹方向和周期) → [平铺/条纹绘制](生成周期性双色条纹) → [障碍偏转绕行](条纹遇障碍块时沿垂直方向偏移一格绕行)

**来源原语**：种子像素(#0a938d79)、种子定条纹周期(#0a938d79)、条纹(#0a938d79)、阵列排布(#0a938d79)、障碍块(#69889d6e)、障碍偏转绕行(#69889d6e)、射线延伸(#69889d6e)、平铺(#ea959feb)

**依赖链**：种子像素的相对位置决定条纹是水平还是垂直以及周期大小——这是条纹绘制的前提；条纹按周期平铺后，每条色带遇到障碍块时必须偏转——偏转规则依赖条纹的延伸方向（由种子决定）；偏转产生的阶梯状弯折在输出中形成独特的几何图案，与简单条纹完全不同。

两个种子像素定义条纹方向和周期，生成的条纹遇灰色障碍块时向垂直方向偏移一格绕行，形成阶梯状弯折。

**输入结构**：约 15x18 的黑(0)背景网格。网格上恰好有两个种子像素，颜色分别为蓝(1)和红(2)。若两个种子位于同一列或其中一个在网格的上/下边缘行，则条纹为水平方向（整行色带）；否则条纹为垂直方向（整列色带）。两个种子的行距（水平条纹时）或列距（垂直条纹时）定义周期间距 D。网格上还有 2~4 个灰(5)障碍块，每个障碍块为 1x1 至 2x2 的实心方块。障碍块不与种子像素重叠。生成约束：障碍块位于条纹将要经过的路径上；不同障碍块不在同一条纹带上（避免同一条纹多次偏转的歧义——每条色带至多遇到一个障碍块）。

**规则**：
1. 判断条纹方向：若任一种子在网格的第 0 行或最后一行，或两种子在同一列，则为水平条纹；否则为垂直条纹。
2. 确定周期：水平条纹时，周期 D = 两种子的行距绝对值；垂直条纹时，D = 两种子的列距绝对值。
3. 生成基础条纹：以两个种子所在的行（或列）为起始，沿垂直于条纹方向以步长 2D 重复两条交替的色带。蓝(1)种子所在行/列为蓝带，红(2)种子所在行/列为红带。每条色带宽度为 1 像素，跨越网格的整个长度。
4. 障碍偏转：沿每条色带的延伸方向逐像素扫描。当色带的下一个像素位置被灰(5)障碍块占据时，色带在遇到障碍的前一个像素处向垂直方向（远离障碍块中心的方向）偏移 1 格，然后继续沿原方向延伸。偏移后色带不再回到原始轨道，而是在新轨道上继续。若偏移方向有歧义（障碍块中心恰好在色带上），则向行号/列号增大的方向偏移。
5. 偏移产生的拐角处，在原轨道和新轨道之间画 1 像素的连接段（与色带同色），确保色带保持 4-连通。
6. 灰(5)障碍块在输出中保持不变。色带覆盖的黑色背景像素变为对应色带颜色。

**关键洞察**：条纹的方向和周期完全由两个种子像素的空间关系隐式编码——不是直接给出的参数；障碍偏转使得原本规则的周期条纹变成局部弯折的图案，求解者必须同时理解"周期如何产生"和"偏转如何发生"才能还原规则。
