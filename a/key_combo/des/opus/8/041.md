## 新题 1：菱形包络的重叠计数着色

**组合逻辑**：[包络生成](已有) + [洪泛填充/区域可达性](已有) + [计数 + 重涂色](创新：从孔洞计数改为重叠区域计数) → 三者通过"包络区域的空间重叠"耦合，重叠数目驱动颜色分配

**来源原语**：包络生成/envelope_generation（c97c0139）、逐步收缩/stepwise_shrink（c97c0139）、洪泛填充/flood_fill（543a7ed5）、计数/counting（37d3e8b2）、重涂色/recolor（37d3e8b2）

**依赖链**：每根条的几何长度决定包络的菱形半径 → 多条的包络在空间上重叠 → 重叠层数决定像素最终颜色。删除包络生成则无区域可叠加；删除重叠计数则无法区分单层与多层；删除重涂色映射则输出不确定。

根据每根前景条生成菱形包络区域，按各像素被覆盖的包络层数分颜色着色。

**输入结构**：约 17x17 网格，黑(0)背景。网格中散布 2-4 根灰(5)实心条，每根条为 1 像素厚、3-7 像素长的水平或垂直线段。各条互不相邻（4-连通不接触），但彼此距离较近，使各自的菱形包络区域会发生空间重叠。不同示例中条的数量、长度、朝向和相对位置均不同。生成约束：任意两条的最近像素距离大于 1 但小于两条包络半径之和，保证至少存在一处重叠区域。

**规则**：
1. 保留所有灰(5)条像素不变。
2. 对每根条计算菱形包络区域：以条为中轴线，沿垂直于条的方向逐行/列扩展，每远离条一行/列则包络段的两端各缩短 1 像素，直到段长缩为 0。包络半径 = floor((条长 - 1) / 2)。包络区域仅包含背景像素位置，不包含条本身。
3. 统计每个背景像素被多少根条的包络覆盖：
   - 恰好 1 层覆盖 → 涂绿(3)
   - 恰好 2 层覆盖 → 涂红(2)
   - 3 层或以上覆盖 → 涂黄(4)
4. 未被任何包络覆盖的背景像素保持黑(0)。
5. 当条像素恰好落在另一根条的包络区域内时，该条像素保持灰(5)不变（条优先于包络着色）。
6. 处理顺序不影响结果——颜色完全由覆盖层数决定，无先后依赖。

**关键洞察**：包络区域在源题中只是装饰性轮廓，这里它们变成了隐式区域，其空间重叠产生了源题中不存在的"层数"信息，驱动全新的颜色编码。求解者必须先从示例归纳出菱形包络的形状规则，再发现重叠层数与颜色的映射关系——仅看单个条无法确定多层颜色。

## 新题 2：孔洞数编码印章方向

**组合逻辑**：[计数（孔洞）](已有) + [印章覆盖](已有，创新：方向由孔洞数决定而非中心颜色匹配) + [颜色匹配](创新：边缘标记教学方向映射)

**来源原语**：计数/counting + 孔洞数映射/hole_count_to_color_mapping（37d3e8b2）、印章覆盖/stamp_repeat（985ae207）、颜色匹配/color_match（985ae207）、封闭背景区域/enclosed_background_region（37d3e8b2）

**依赖链**：孔洞计数 → 查找方向映射 → 确定印章方向和目标颜色 → 执行印章覆盖。删除孔洞计数则方向不确定；删除边缘标记则映射不可学习；删除印章覆盖则无输出动作。

统计每个前景对象内部的封闭孔洞数，以此决定该对象向哪个方向复制印章，印章颜色取自对应边缘的方向标记。

**输入结构**：约 21x21 网格，黑(0)背景。网格中有 3-4 个蓝(1)的 4-连通前景对象，每个约 5-10 像素，形态不规则（非矩形），各自封闭 0-3 个背景孔洞（4-连通封闭区域）。网格四条边的中点各有一个单像素方向标记：顶边中点为红(2)，右边中点为绿(3)，底边中点为黄(4)，左边中点为橙(7)。不同示例中对象形态不同但孔洞数范围不变。生成约束：每个对象的孔洞数互不相同（0、1、2、3 各出现一次，若对象不足 4 个则从中取子集）；对象之间以及对象与网格边缘之间留有足够空间容纳至少 2 个印章副本。

**规则**：
1. 统计每个蓝(1)对象内部的 4-连通封闭背景区域数量（孔洞数 H）。
2. 孔洞数映射到方向标记：H=0 → 顶边标记（红(2)，方向=上），H=1 → 右边标记（绿(3)，方向=右），H=2 → 底边标记（黄(4)，方向=下），H=3 → 左边标记（橙(7)，方向=左）。
3. 将每个对象沿映射方向复制印章：以对象边界框在该方向的尺寸为步长，逐次平移复制，直到下一个副本的边界框会超出网格边界时停止。
4. 每个印章副本的颜色替换为对应方向标记的颜色（例如 H=0 的对象，副本涂红(2)）。原始对象保持蓝(1)。
5. 移除四个边缘方向标记像素。
6. 多个对象的印章副本若发生重叠，按孔洞数从小到大的优先级绘制（孔洞数大的后绘制，覆盖前者）。

**关键洞察**：在源题 37d3e8b2 中，孔洞数映射到颜色；在源题 985ae207 中，中心像素颜色匹配目标矩形决定方向。此处孔洞数不再直接映射颜色，而是编码方向——颜色由方向标记间接提供。求解者必须对比多个示例才能归纳出"孔洞数→方向"的映射关系，因为边缘标记的颜色和位置需要跨示例才能确定。

## 新题 3：条件镜像驱动掩码逻辑合并

**组合逻辑**：[逻辑或合并](已有) + [镜像](创新：不是全图平铺镜像，而是对单侧掩码做条件翻转) + [颜色匹配判断](创新：标记颜色的一致性决定是否翻转)

**来源原语**：逻辑或合并/logical_or_merge（195ba7dc）、分隔列/separator_column（195ba7dc）、掩码/mask（195ba7dc）、镜像/mirror（3af2c5a8）、边色不符则翻转/mismatch_flip（846bdb03）、颜色匹配/color_match（846bdb03）

**依赖链**：标记颜色比较 → 决定是否翻转右半区 → 执行逻辑或合并。翻转改变了像素对齐方式，从而根本性地改变合并结果。删除标记比较则不知何时翻转；删除镜像则所有示例用同一合并方式，与部分示例矛盾；删除逻辑或合并则无输出。

比较两侧掩码的角标记颜色，同色则直接合并，异色则先翻转右侧再合并。

**输入结构**：约 11x21 网格，黑(0)背景。网格正中有一列红(2)全高分隔列，将网格分为左半区（11 行 x 10 列）和右半区（11 行 x 10 列）。每个半区内有橙(7)像素组成的二值图案（掩码）。左半区的左上角像素为一个单像素标记，颜色为绿(3)或蓝(1)之一。右半区的左上角像素也是一个单像素标记，颜色为绿(3)或蓝(1)之一。标记位置固定（各自半区的第 0 行第 0 列），标记不属于掩码图案。不同示例中标记颜色组合不同（同-同或同-异均出现），掩码图案也不同。生成约束：两侧掩码的橙(7)像素分布不完全相同，且非互补关系，以确保翻转与否产生可区分的不同输出。

**规则**：
1. 读取左半区标记颜色 C_L 和右半区标记颜色 C_R。
2. 若 C_L = C_R（标记同色）：直接对两个掩码执行逐像素逻辑或合并——对应位置任一侧有橙(7)则输出蓝(1)，否则输出黑(0)。
3. 若 C_L ≠ C_R（标记异色）：先将右半区水平镜像（左右翻转），再执行逐像素逻辑或合并，同样输出蓝(1)/黑(0)。
4. 输出尺寸等于单个半区尺寸（11 行 x 10 列）。
5. 标记像素位置在输出中视为掩码的一部分参与合并——若标记位置恰好也有橙(7)图案像素，则标记优先，该位置视为无橙像素（标记不是掩码）。
6. 红(2)分隔列不出现在输出中。

**关键洞察**：标记颜色不编码任何视觉内容，仅编码一个布尔指令（翻转/不翻转）。翻转改变了右侧掩码的每个像素对齐位置，导致逻辑或的结果截然不同。求解者必须对比"同色标记"与"异色标记"的示例才能发现翻转规则——单个示例中无法区分"直接合并"和"翻转后合并"。

## 新题 4：引导三角定射线方向，多米诺定射线颜色

**组合逻辑**：[射线延伸 + 引导体](已有) + [擦除](已有) + [双色多米诺 + 四邻接配对](创新：多米诺不再执行配对变色，而是作为颜色选择器为射线提供颜色信息)

**来源原语**：射线延伸/ray_cast + 引导体/guide_object + 引导体定新对角线/guide_tip_seeds_parallel_diagonal（a78176bb）、擦除/erase（a78176bb）、对角线段/diagonal_segment（a78176bb）、双色多米诺/bicolor_domino + 四邻接配对/four_neighbor_pairing（d90796e8）、平行偏移/parallel_offset（a78176bb）

**依赖链**：引导三角的尖端 → 确定新对角线的位置和方向。多米诺中哪个颜色像素更靠近该三角 → 确定该对角线的颜色。两套信息分别回答"在哪画"和"用什么色画"。删除引导三角则不知道画在哪；删除多米诺则不知道用什么颜色；删除擦除则输出保留了辅助标记。

灰色三角标记新对角线的位置，每个三角旁的红绿多米诺中朝向三角的那个颜色决定该对角线的着色。

**输入结构**：约 16x16 网格，黑(0)背景。一条蓝(1)对角线段（从左上到右下或从右上到左下，长度 5-8 像素）。2-3 个灰(5)直角三角形对象（每个 3-6 像素，4-连通），每个三角形的一条直角边紧贴蓝色对角线。每个灰色三角形附近（不接触三角，但 8-邻域距离 ≤ 3）有一个红(2)-绿(3)多米诺（2 像素的 4-连通对，一个红一个绿）。不同示例中三角形数量、位置、多米诺朝向不同。生成约束：每个多米诺与恰好一个三角形最近（不会产生歧义配对）；多米诺的红、绿像素到其配对三角形的最近距离不相等（保证颜色选择无歧义）。

**规则**：
1. 保留原始蓝(1)对角线不变。
2. 对每个灰(5)三角形，找到其远离蓝色对角线的最远端尖端像素（与源题 a78176bb 相同的逻辑）。
3. 过该尖端像素画一条与原对角线平行的对角线，向两端延伸至网格边界。
4. 该新对角线的颜色由配对多米诺决定：找到距离该三角形最近的红绿多米诺，计算多米诺中红(2)像素和绿(3)像素分别到三角形最近像素的切比雪夫距离，取距离更小的那个颜色作为新对角线的颜色。
5. 擦除所有灰(5)像素（三角形移除）。
6. 保留所有多米诺像素不变。
7. 新对角线之间若交叉，交叉像素取后绘制的颜色（按三角形尖端行号从小到大的顺序绘制）。

**关键洞察**：在源题中，引导三角仅提供位置信息，射线颜色继承自原对角线；多米诺则只关心自身配对变色。此处两个原语产生全新的结构关系——三角提供"在哪里"，多米诺提供"用什么颜色"，两者必须配对解读才能确定每条新对角线的完整属性。

## 新题 5：标记向量编码拼接偏移方向

**组合逻辑**：[拼接 + 偏移放置](已有，创新：偏移方向不固定，由标记向量动态决定) + [滑动/趋近目标](创新：绿黄标记不移动，而是编码一个方向向量) + [分隔填充](已有)

**来源原语**：拼接/stitch + 偏移放置/offset_placement + 分隔填充/separator_fill（8618d23e）、对角偏移/diagonal_offset（8618d23e）、滑动/slide + 趋近目标/approach_target + 标记像素/marker_pixel + 目标像素/target_pixel + 共线对齐/collinear_aligned（dc433765）

**依赖链**：绿黄标记的相对位置 → 计算归一化方向向量 → 方向向量决定下半区的偏移方向 → 执行拼接。删除标记分析则偏移方向不确定（不同示例方向不同）；删除拼接则标记无处作用；删除分隔填充则输出中无法区分原始区域和间隙。

读取每个半区中绿黄标记对的方向向量，以此决定上下半区拼接时的错位方向。

**输入结构**：偶数行的网格（约 10x14），黑(0)背景。网格上半区和下半区各包含一个橙(7)图案。每个半区内恰好有一个绿(3)单像素标记和一个黄(4)单像素标记，两者在同一行、同一列或同一 45 度对角线上。不同示例中标记对的方向不同（可能上-下、左-右、对角等）。生成约束：上半区和下半区的绿→黄方向向量相同（归一化后一致），保证规则无歧义。绿、黄标记不与橙图案像素重合。

**规则**：
1. 将网格按行数平分为上半区和下半区。
2. 在任一半区中找到绿(3)标记和黄(4)标记，计算从绿到黄的归一化方向向量 (dr, dc)，其中 dr, dc 各为 -1、0 或 +1。
3. 移除所有绿(3)和黄(4)标记像素（恢复为黑(0)）。
4. 创建输出画布：行数 = 半区行数 + |dr|，列数 = 半区列数 + |dc|，初始填充栗(9)。
5. 将上半区复制到输出画布的起始位置 (0, 0)。
6. 将下半区复制到输出画布的位置 (半区行数 * |dr| 处的偏移行, 半区列数 * |dc| 处的偏移列)。具体地：行偏移 = (dr > 0 ? 1 : 0) + (半区行数 - 1) * 0 ——简化为：下半区左上角放在 (上半区行数 if dr≥0 else 上半区行数-1, max(0, dc)) 处。

更精确地说：
5-6（重新描述）：上半区放置于画布左上角 (r0_top, c0_top)，下半区放置于 (r0_bot, c0_bot)。方向向量 (dr, dc) 决定偏移：
   - r0_top = max(0, -dr), c0_top = max(0, -dc)
   - r0_bot = r0_top + 半区行数 + (1 if dr>0 else (-1 if dr<0 else 0)) 的绝对值方向间隔 ——

（以下为最终精确规则）：
5. 输出画布尺寸：行 = 半区行数 * 2 + (1 if dr != 0 else 0)，列 = 半区列数 + (1 if dc != 0 else 0)。画布初始全部填充栗(9)。
6. 将上半区复制到画布位置 (0, 0 if dc >= 0 else 1)。
7. 将下半区复制到画布位置 (半区行数 + (1 if dr != 0 else 0), 0 if dc <= 0 else 1)。即：下半区相对于上半区，在行方向上间隔 (1 if dr != 0 else 0) 行栗色分隔，在列方向上偏移 (dc 的符号) 列。
8. 当 dr=0 时上下紧贴无行间隔；当 dc=0 时左右不偏移。间隔和偏移位置显示为栗(9)分隔色。

**关键洞察**：在源题 dc433765 中，绿→黄向量驱动的是像素移动；在源题 8618d23e 中，偏移方向是固定的对角偏移。此处两个原语产生全新关系——绿黄标记不再驱动移动，而是作为方向编码器，其向量决定了拼接的错位方式。不同示例中向量不同，迫使求解者从标记方位归纳偏移规则而非记忆固定偏移。

5. 各组的放大块之间若重叠（理论上不会，由生成约束保证），后处理组（按组在网格中的行优先、列次优先顺序）覆盖先处理组。

## 新题 7：四象限镜像平铺后涌现新封闭区域

**组合逻辑**：[镜像 + 平铺/双轴反射四象限](已有) + [洪泛填充 + 区域可达性](已有) + [描边/outline + 孔洞填色轮廓描色](创新：在平铺后的整体上重新分析区域拓扑，利用镜像产生的拓扑变化)

**依赖链**：原始图案 → 四象限镜像平铺 → 平铺改变区域拓扑（原本开放的区域可能因镜像副本的对接而封闭） → 在平铺结果上执行区域可达性分析 → 封闭区域填黄、外部轮廓描绿。删除平铺则无拓扑变化可分析；删除区域分析则不知道哪些区域被封闭；删除着色则无输出标记。三步之间存在涌现效应——单独看平铺或区域分析都不产生新行为，只有平铺改变了拓扑之后区域分析才产生不同于原始图案的结果。

**输入结构**：约 5x6 网格，黑(0)背景，蓝(1)前景像素组成一个图案。图案的关键特征：至少有一条边缘处的前景像素链在该边未完全封闭（即存在从图案内部穿过边缘到达网格边界的背景通路），使得在原始网格中该区域不算封闭孔洞。但镜像拼接后，两个镜像副本在接缝处的前景像素会对接，可能封闭出新的孔洞。不同示例中图案形态不同，导致平铺后产生的新封闭区域数量和形状也不同。生成约束：原始图案中至少有一处"边缘开口"在平铺后被封闭；原始图案中若已有封闭孔洞，平铺后该孔洞应保持封闭（各象限各有一个副本）。

**规则**：
1. 将输入网格做双轴镜像，生成 4 倍大小的平铺网格（与源题 3af2c5a8 完全相同的平铺规则）：
   - 左上象限 = 原始
   - 右上象限 = 水平镜像
   - 左下象限 = 垂直镜像
   - 右下象限 = 180 度旋转
2. 在平铺结果上执行 4-连通洪泛填充，从所有边界背景像素出发标记"可达边界"的区域。
3. 所有不可达边界的背景连通区域即为封闭孔洞 → 全部涂黄(4)。
4. 所有可达边界的背景像素中，与前景像素 8-邻接的 → 涂绿(3)（外轮廓）。
5. 所有蓝(1)前景像素保持不变。
6. 其余背景像素（可达边界但不与前景 8-邻接）保持黑(0)。

**关键洞察**：这道题的核心涌现效应是——原始图案中边缘开口的区域在镜像平铺后可能被封闭。求解者如果先分析原始图案的孔洞再平铺，会遗漏由接缝产生的新孔洞；必须先平铺后分析。这种"操作顺序改变拓扑"的效应在任何一道源题中都不存在。

6. 起点像素保持绿(3)。

**关键洞察**：在源题 cb2d8a2c 中，禁区半径由蓝像素数量显式编码；在源题 c97c0139 中，包络是视觉装饰。此处两个原语产生全新结构关系——条的几何长度通过菱形包络公式隐式定义了禁区的形状和大小，路径必须绕过这些不可见的菱形禁区。求解者必须同时归纳出包络形状规则（从条长推导禁区范围）和路径规划规则（如何绕行），且两者必须配合才能预测输出。

   - 所有与前景像素 8-邻接的外部背景像素 → 涂绿(3)。

不同示例中标记行的间距分布不同，精灵体形态和颜色也不同。生成约束：最小间距值在所有标记行中唯一（无并列最小值）；精灵体放大后不超出合理网格尺寸（最小间距 * 精灵体边界框尺寸 ≤ 20）。

**规则**：
1. 在标记区中找到所有红(2)标记行，每行有且仅有两个红(2)像素。
2. 计算每行两标记之间的水平间距 G（间距 = 两标记列号之差 - 1，即中间背景像素数）。
3. 找到间距最小的行，记其间距为 G_min。
4. 将该最小间距行的两个标记用红(2)连线（填充中间所有像素为红(2)）。其他标记行保持不变。
5. 裁剪精灵体到其最小边界框。
6. 将精灵体等比放大 G_min 倍：每个原始像素变为 G_min x G_min 的同色方块。
7. 输出仅为放大后的精灵体（丢弃标记区和原始背景，输出网格尺寸 = 精灵体边界框尺寸 * G_min）。

**关键洞察**：在源题中，最小间距对触发的是连线填充操作——连线是最终目的。此处连线仅是中间步骤，其真正作用是产出一个数值（间距长度），该数值成为另一个完全不同的操作（像素放大）的参数。求解者必须跨越两个看似无关的区域建立联系：上半部分的标记间距控制下半部分精灵体的放大倍率。单个示例中间距值和放大倍率的对应可能被误解为巧合，需要多个示例才能确认。
