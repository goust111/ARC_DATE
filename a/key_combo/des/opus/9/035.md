## 新题 1：投射碰撞指派轮廓重绘

**组合逻辑**：[投射(project)](创新：从外向内投射至轮廓线而非目标对象) + [碰撞阻挡(collision_blocking)] → 距离竞争指派 → [擦除(erase)] + [轮廓描边(outline_trace)](创新：用指派的标记色而非最小内部色描外轮廓)

**来源原语**：投射、碰撞阻挡（1f642eb9）；擦除、轮廓描边、外侧相邻（aa62e3f4）；标记像素（a04b2602）

**依赖链**：投射确定每个标记到每条轮廓的距离 → 距离竞争决定标记-轮廓指派关系 → 指派结果决定每条轮廓的重绘颜色 → 擦除原轮廓后用指派色描外侧轮廓。投射步骤产生的距离信息直接充当后续竞争指派的判据，删除投射步骤则指派无依据；删除轮廓描边则无可见输出。

从网格边界散布的标记像素向内投射，按碰撞距离竞争"认领"各条闭合轮廓线，然后擦除原轮廓并以认领标记的颜色描绘其外侧轮廓。

**输入结构**：约 15x15 黑(0)背景网格。网格中有 2~3 条闭合轮廓线，每条轮廓由同一颜色的 8-连通像素构成（如绿(3)），形成封闭环形（每条轮廓约 10~18 像素，可为不规则多边形而非仅矩形）。轮廓之间互不接触，内部为黑(0)。另有 3~4 个单像素标记分布在网格中（不在任何轮廓内部或轮廓上），颜色各不相同，取自红(2)、蓝(1)、黄(4)、橙(7)。每个标记至少有一个基本方向（上/下/左/右）的射线能命中某条轮廓。生成约束：不同轮廓的认领结果由距离唯一确定（无平局）。

**规则**：
1. 从每个标记像素出发，沿上、下、左、右四个基本方向各发射一条射线，射线逐格前进直到碰到非黑像素（轮廓单元格）或离开网格边界。记录每条命中射线的距离（经过的黑格数）。
2. 每条命中的射线建立"标记 M 以距离 d 认领轮廓 O"的候选关系。若同一轮廓被多个标记认领，距离最短者胜出。若距离相同（生成时已排除此情况），按标记在网格中从上到下、从左到右的扫描顺序选先出现者。
3. 将所有原始轮廓像素和所有标记像素擦除为黑(0)。
4. 对每条轮廓，找到原轮廓像素的所有 4-邻接黑(0)像素（位于轮廓外侧的一圈），将这些像素涂为该轮廓的认领标记颜色。轮廓内侧的黑像素不涂色。判定"外侧"方法：从网格边缘做黑(0)连通区域泛洪，能被泛洪到达的 4-邻接像素为外侧。
5. 未被任何标记认领的轮廓（无射线命中）保持擦除状态（全黑）。

**关键洞察**：标记与轮廓的配对关系不由欧氏距离决定，而由基本方向投射碰撞距离决定——一个标记可能在欧氏距离上离某轮廓更近，但因不在同行同列而无法投射命中，反而由更远但在同行/列的标记认领。

## 新题 2：分隔网格内碎片合并补全 + 跨区域像素计数决定填充色

**组合逻辑**：[网格分区(grid_partition)] → [合并对齐碎片(merge_aligned_fragments)] → [补全(complete)] → [计数(counting) + 排序(sort)] → [重涂色(recolor)](创新：填充色非本区域固有色，而由跨区域像素计数排名映射)

**来源原语**：网格分区、分隔线（780d0b14）；合并对齐碎片、残缺矩形（8fbca751）；计数、排序、高度排名映射颜色（08ed6ac7）；补全（b7955b3c）

**依赖链**：分隔线定义区域 → 每个区域内的前景碎片需按跨度重叠合并为完整矩形 → 统计各区域前景像素总数并排名 → 排名决定每个区域矩形内缺失格的填充颜色。合并结果影响矩形范围、进而影响像素计数；计数排名影响填充色——三步互为前提。

在分隔线划分的网格中，每个区域含不完整矩形碎片；合并碎片确定矩形范围后，按各区域前景像素总数排名映射颜色来填补缺口。

**输入结构**：约 19x19 网格。灰(5)全行和全列将网格分为 3x3 共 9 个矩形区域。背景黑(0)。每个区域内散布若干青(8)像素，它们是某个矩形轮廓的碎片——同一区域内的碎片可能 4-不连通，但其边界框在行跨度或列跨度上有重叠。不同区域的碎片互不相关。各区域的青像素总数两两不同（如从 3 到 11 各不相同）。每个区域中碎片合并后形成一个唯一矩形的轮廓骨架（边框有缺失格）。

**规则**：
1. 识别所有灰(5)全行和全列，确定 3x3 区域布局。
2. 在每个区域内，找到所有 4-连通的青(8)碎片。
3. 将边界框在行跨度或列跨度上有重叠的碎片传递合并（取并集的边界框），得到该区域的完整矩形范围。
4. 统计每个区域内原始青(8)像素的总数。将 9 个区域按像素总数从多到少排列，排名 1~9。
5. 颜色映射：排名 1~3 → 蓝(1)，排名 4~6 → 红(2)，排名 7~9 → 绿(3)。
6. 对每个区域，将其完整矩形范围内所有黑(0)格（即缺失的矩形边框格和矩形内部格）填充为该区域排名对应的颜色。原有青(8)像素保持不变。

**关键洞察**：填充颜色不由区域自身的前景色决定（所有区域前景色都是青），而由各区域前景像素数量的相对排名决定。求解者必须先合并碎片确定矩形范围（否则无法正确计数与填充范围），再做跨区域比较才能确定填充色。

## 新题 3：对称轨道修复后产生径向射线种子

**组合逻辑**：[对称补全(symmetry_completion)](保留) + [射线延伸(ray_extension)](创新：射线方向由修复像素在对称结构中的位置决定，而非固定对角线方向) + [特定色反射射线(specific_reflects)](保留)

**来源原语**：对称补全、对称轨道、掩码像素（3631a71a）；射线延伸、对角射线种子、反射镜段、边界反射、特定色反射射线（7e2bad24）

**依赖链**：对称修复确定哪些像素被还原 → 被还原像素的位置相对于对称中心决定其射线方向 → 射线在网格中延伸时遇红色反射镜段反射。修复步骤的输出是射线步骤的输入（种子位置和方向同时确定），且射线路径受输入中已有的反射镜段约束。

将对称损坏区修复后，每个修复像素变为射线种子，以其相对对称中心的方位角确定射线的对角方向；射线遇红色镜段反射、遇其他非背景像素停止。

**输入结构**：13x13 正方形网格，背景黑(0)。一组蓝(1)和绿(3)像素构成以网格中心为原点的 4 重旋转对称图案（90 度旋转不变，约 16~24 像素）。其中 3~5 个像素被灰(5)"损坏"替换。另有 2~3 条红(2)线段（水平或垂直，长 3~5 格）放置在网格中，不与对称图案重叠，不覆盖灰(5)位置。

**规则**：
1. 识别灰(5)为掩码色。确定对称群为绕网格中心的 4 重旋转（0/90/180/270 度）。
2. 对每个灰(5)像素，找到其在 90/180/270 度旋转下的轨道伙伴。用轨道伙伴中唯一的非灰颜色替换该灰像素。若多个轨道伙伴均为灰，则通过传递关系（其中某个伙伴的伙伴非灰）确定颜色。
3. 修复完成后，对每个原本为灰（现已修复）的像素，以该像素位置 (r,c) 相对网格中心 (cr,cc) 的方位确定射线方向：
   - 若 r < cr 且 c < cc（左上象限）：射线向左上对角延伸（dr=-1, dc=-1）
   - 若 r < cr 且 c > cc（右上象限）：射线向右上对角延伸（dr=-1, dc=+1）
   - 若 r > cr 且 c > cc（右下象限）：射线向右下对角延伸（dr=+1, dc=+1）
   - 若 r > cr 且 c < cc（左下象限）：射线向左下对角延伸（dr=+1, dc=-1）
   - 若像素恰好在中心行或中心列上，射线方向取该像素偏离中心较大的那个维度所在象限方向（如 r=cr 但 c>cc，则视为右侧，取 dr 为距其最近的非零行偏移方向）。生成时保证不会出现恰好在中心点上的损坏。
4. 每条射线从种子像素的下一格开始，沿对角方向逐格前进，将经过的黑(0)格涂为橙(7)。
5. 若射线下一格是红(2)镜段像素，射线不涂该格，而是反射：水平镜段翻转行方向分量，垂直镜段翻转列方向分量。反射后继续前进。
6. 若射线下一格是非黑、非红的像素（包括对称图案像素或其他射线已涂的橙色），射线停止，不涂该格。
7. 若射线离开网格边界，射线停止。

**关键洞察**：被损坏的像素不仅是需要修复的空白——修复后它们变成射线种子，且种子在对称结构中的位置决定射线方向。因为图案本身 4 重旋转对称，修复像素的轨道伙伴们产生的射线也具有 4 重对称方向；但红色镜段的非对称放置会打破射线路径的对称性，产生非显然的输出。

## 新题 4：精灵裁剪 + 象限旋转印章 + 低频色选位

**组合逻辑**：[精灵裁剪(sprite_crop)] → [计数(counting) + 最低频色定位(least_frequent_color_positioning)](创新：选位颜色非来自瓦片本身而来自独立标记) → [印章覆盖(stamp)](创新：每个印章位的旋转角度由该位所在象限隐式编码) + [旋转(rotate)]

**来源原语**：精灵裁剪、旋转（2697da3f）；印章覆盖、最低频色定位（48f8583b）；计数（bd283c4a）；忽略干扰项（a04b2602）

**依赖链**：精灵裁剪获得印章模板 → 标记像素计数确定最低频色 → 最低频色像素位置确定印章锚点 → 锚点所在象限确定旋转角度 → 旋转后印章粘贴到锚点。裁剪输出喂入印章模板；计数输出决定哪些标记成为锚点；象限位置决定旋转变体。三条信息链汇聚于最终粘贴。

裁剪前景精灵为印章模板，统计散布标记色的像素频率，选最低频色的像素位置为印章锚点，根据锚点所在网格象限旋转印章后粘贴。

**输入结构**：约 17x17 网格，背景黑(0)。左上角区域有一个绿(3)前景精灵（4-连通，8~14 像素，形状非对称使四种旋转可区分，可含背景孔洞）。网格其余区域散布三种颜色的单像素标记：红(2)、蓝(1)、黄(4)。其中一种颜色的像素总数严格少于另外两种（如红 2 个、蓝 5 个、黄 4 个）。生成约束：最低频色的各像素位置使印章粘贴后不超出网格边界且不与原始精灵重叠；最低频各像素分布在不同象限中。

**规则**：
1. 找到绿(3)前景精灵的最小边界框，裁剪出精灵瓦片（bbox 内黑像素视为精灵孔洞保留）。
2. 统计网格中红(2)、蓝(1)、黄(4)三种标记色各自的像素总数，确定像素数最少的颜色为"选位色"。
3. 每个选位色像素的位置成为一个印章锚点（锚点对应印章左上角）。
4. 确定每个锚点所在象限（以网格中心为分界）：
   - 左上象限：印章不旋转（0 度）
   - 右上象限：印章顺时针旋转 90 度
   - 右下象限：印章旋转 180 度
   - 左下象限：印章顺时针旋转 270 度
5. 将旋转后的印章粘贴到对应锚点位置。印章像素覆盖黑(0)背景，但不覆盖原始精灵像素。若多个印章重叠，后处理的印章覆盖先处理的（处理顺序：锚点从上到下、从左到右）。
6. 所有非选位色的标记像素擦除为黑(0)。选位色像素本身被印章覆盖（若印章范围覆盖到）或保留（若未被覆盖）。

**关键洞察**：印章的旋转角度不编码在标记像素本身的任何属性中，而由标记像素在网格中的空间位置（象限）隐式决定。求解者必须对比多个示例才能发现频率选位规则和象限-旋转对应关系——二者缺一不可。

## 新题 5：同色区域按粗粒度块内像素计数排名压缩

**组合逻辑**：[压缩(compress) + 网格分区(grid_partition)](保留) → [计数(counting)](创新：所有区域前景同色，计数非颜色而是像素数) → [排序(sort) + 高度排名映射颜色(height_rank_to_color)](创新：排名分段映射颜色) → [每区域折叠单像素(region_to_pixel)]

**来源原语**：压缩、网格分区、每区域折叠单像素（780d0b14）；计数、排序、高度排名映射颜色（08ed6ac7）；阵列排布、含标记涂标记色（e57337a4）

**依赖链**：分隔线确定区域布局 → 每区域内同色前景像素计数 → 跨区域排名 → 排名段决定输出压缩像素颜色。若不做跨区域比较（仅看单区域颜色），所有区域压缩结果相同，无法区分。

所有分区包含同一前景色的散布像素，用像素数量的跨区域排名替代颜色信息作为压缩输出——同色变异色。

**输入结构**：约 16x16 网格。灰(5)全行和全列将网格分为 4x4 共 16 个矩形区域。每个区域背景黑(0)，内含若干散布的青(8)前景像素（数量从 1 到 16，各区域严格不同）。所有区域的前景色相同（均为青(8)），仅像素数量不同。

**规则**：
1. 找到灰(5)全行和全列，确定 4x4 区域布局。
2. 统计每个区域内的青(8)像素总数。
3. 将 16 个区域按像素数从多到少排列，排名 1~16。
4. 颜色映射：排名 1~4 → 蓝(1)，排名 5~8 → 红(2)，排名 9~12 → 绿(3)，排名 13~16 → 黄(4)。
5. 输出为 4x4 小网格。每个输出格对应一个输入区域，颜色为该区域排名对应的映射色。

**关键洞察**：输入中所有前景像素颜色相同，因此传统的"每区域取其颜色"压缩策略会产生全青的单色输出，完全无信息。求解者必须发现真正的编码信号是像素数量的相对排名，而非颜色本身。

## 新题 6：跨度填充涌现矩形框 + 框内颜色互换

**组合逻辑**：[连线(connect) + 首尾跨度填充(span_fill_between)](保留) → 涌现矩形框结构 → [框内区域(interior_region)](保留) + [颜色互换(color_swap)](保留) + [忽略干扰项(ignore_distractors)](创新：干扰项为框外的同色像素)

**来源原语**：连线、首尾跨度填充（ded97339）；颜色互换、框内区域、框内限定（7ee1c6ea）；忽略干扰项（a04b2602）

**依赖链**：红色标记像素经跨度填充产生连线 → 连线构成闭合矩形框（涌现结构，非显式给定）→ 框内区域识别确定互换边界 → 框内蓝/绿像素互换颜色 → 框外蓝/绿像素不变。跨度填充是框结构的前提条件；若不做跨度填充则无框可言，互换范围无法界定。

散布的红色标记像素经行列跨度填充后涌现出矩形框，框内的蓝/绿像素互换颜色，框外同色像素不受影响。

**输入结构**：约 14x14 网格，背景黑(0)。若干红(2)单像素标记分布在网格中，其布局使得行列跨度填充后恰好形成 1~2 个闭合矩形框（即存在四个红像素分别位于某矩形的四条边的行/列上，填充后形成完整边框）。矩形框内部散布蓝(1)和绿(3)像素。矩形框外部也散布一些蓝(1)和绿(3)像素作为干扰。生成约束：红色标记的行列分布确保跨度填充后恰好形成完整矩形框（每行/列中红色标记的最远对定义了框边）；框内蓝/绿像素各至少 2 个；不同示例中框外干扰像素的数量和位置不同。

**规则**：
1. 找到所有红(2)标记像素。
2. 对每一行中含 >=2 个红像素的行，将最左到最右红像素之间的所有格填充为红(2)。
3. 对每一列中含 >=2 个红像素的列，将最上到最下红像素之间的所有格填充为红(2)。
4. 填充后的红色连通结构形成一或多个闭合矩形框。识别每个矩形框（边界为连续红色的矩形环）。
5. 对每个矩形框，确定严格内部区域（边框内部的格子）。
6. 在每个矩形框的内部区域中，将蓝(1)像素改为绿(3)，绿(3)像素改为蓝(1)。黑(0)内部像素保持不变。
7. 矩形框外部的所有蓝/绿像素保持不变。

**关键洞察**：矩形框在输入中不存在——它们是跨度填充的涌现产物。框外散布的蓝/绿像素是干扰项，测试求解者是否正确识别了涌现框的边界。求解者需要先理解跨度填充如何产生框，再理解框如何界定颜色互换范围。

## 新题 7：粗粒度块内标记边缘方位编码印章旋转

**组合逻辑**：[压缩(compress) + 含标记涂标记色(marker_presence_color)](创新：标记不仅标注"是否有"，其在块内的位置编码旋转信息) → [裁剪(crop)](保留) + [印章覆盖(stamp_overlay)](保留) + [旋转(rotate)](创新：旋转由标记在块内的边缘邻近度决定)

**来源原语**：压缩、粗粒度块、含标记涂标记色、阵列排布（e57337a4）；印章覆盖、瓦片（48f8583b）；旋转（2697da3f）；裁剪（d10ecb37）

**依赖链**：粗粒度块划分确定区域网格 → 识别含多色瓦片模板的块（提取模板）和含标记的块（确定印章位置）→ 标记在块内的边缘方位决定旋转角 → 旋转模板后粘贴到对应位置。单个标记像素同时承载位置信息（哪个块）和方位信息（块内哪条边），信息密度高于普通布尔标记。

将大网格分为粗粒度块阵列，其中一块含多色瓦片模板，其余块中的标记像素靠近块的哪条边就决定模板以何种旋转印入该块。

**输入结构**：15x15 网格（3x3 阵列，每块 5x5），背景黑(0)。中心块包含一个 3x3 的非对称多色瓦片模板（使用蓝(1)和红(2)像素的组合，使 0/90/180/270 度旋转均可区分），模板居中放置（周围一圈黑边距）。其余 8 个块中，2~4 个块各含恰好一个绿(3)单像素标记，其余块为全黑。每个标记像素位于其所在块的某条边附近（距该边 0~1 格，且距其他三条边 >=2 格，使"最近边"唯一确定）。

**规则**：
1. 将网格划分为 3x3 的 5x5 块阵列。
2. 识别中心块中的多色瓦片模板，提取其 3x3 边界框内容。
3. 对每个含绿(3)标记的块，确定标记像素距块四条边的曼哈顿距离，取最近的边：
   - 最近为上边 → 旋转 0 度（原始方向）
   - 最近为右边 → 顺时针旋转 90 度
   - 最近为下边 → 旋转 180 度
   - 最近为左边 → 顺时针旋转 270 度
4. 创建 9x9 输出网格（3x3 阵列，每个子块 3x3）。对每个输入块：
   - 若含绿标记：放置对应旋转的模板瓦片
   - 若为中心块或空块：填充黑(0)
5. 绿色标记像素不出现在输出中（被模板覆盖或被黑色替代）。

**关键洞察**：一个标记像素通过其在粗粒度块内的亚位置（哪条边最近）编码了旋转参数——这不是一个独立的旋转标志位，而是从空间位置中隐式提取的。求解者需对比多个示例发现"块内位置→旋转角"的映射关系。

## 新题 8：碎片合并确定矩形 + 外轮廓描边 + 面积排名定色

**组合逻辑**：[合并对齐碎片(merge_aligned_fragments)](保留) → [轮廓描边(outline_trace) + 外侧相邻(outer_adjacent)](创新：对合并后的完整矩形描外轮廓而非填内部) → [计数(counting) + 排序(sort) + 高度排名映射颜色(height_rank_to_color)](创新：排名对象是矩形面积而非像素数或高度)  + [擦除(erase)]

**来源原语**：合并对齐碎片、残缺矩形、行列跨度重叠（8fbca751）；轮廓描边、外侧相邻、擦除（aa62e3f4）；计数、排序、高度排名映射颜色（08ed6ac7）

**依赖链**：碎片合并确定完整矩形边界 → 矩形面积（高x宽）用于排名 → 排名映射描边颜色 → 擦除原碎片 → 在原矩形边界外侧一圈描边。合并结果同时决定了描边范围和面积排名；排名决定颜色；描边产生输出。三步串联但信息在每步都发生质变。

散布的前景碎片按行列跨度合并为完整矩形后，擦除碎片并在每个矩形外侧一圈描边，颜色由矩形面积排名决定。

**输入结构**：约 18x18 网格，背景黑(0)。散布的青(8)像素形成 3~4 个不完整矩形的碎片。同一矩形的碎片可能 4-不连通，但其边界框在行跨度或列跨度上重叠。不同矩形之间的碎片边界框既不在行跨度重叠、也不在列跨度重叠。各矩形的面积（合并后的完整边界框高 x 宽）两两不同。矩形之间至少间隔 2 格（保证外轮廓不交叠）。

**规则**：
1. 找到所有 4-连通的青(8)碎片。
2. 将边界框在行跨度或列跨度上有重叠的碎片传递合并。
3. 每个合并组的包围边界框定义一个完整矩形。
4. 计算每个矩形的面积 = 边界框高度 x 宽度。按面积降序排名。
5. 颜色映射：排名 1 → 蓝(1)，排名 2 → 红(2)，排名 3 → 绿(3)，排名 4 → 黄(4)。
6. 擦除所有原始青(8)像素为黑(0)。
7. 对每个矩形，找到其边界（矩形四条边上的格子）的所有 4-邻接格中位于矩形外部的格子（外侧邻接格），将这些格涂为该矩形的排名颜色。矩形边界本身和内部不涂色。
8. 若两个矩形的外轮廓在某格重叠（生成约束已保证不会发生），面积更大的矩形优先。

**关键洞察**：输出中可见的矩形轮廓比输入碎片暗示的矩形大一圈（因为是外侧描边），且碎片本身被完全擦除。排名必须在碎片合并后才能计算——单个碎片的面积不等于合并后矩形的面积。

## 新题 9：控制矩阵编码条件互换指令

**组合逻辑**：[索引映射(index_mapping) + 行列位置对应(row_column_correspondence)](保留) + [颜色互换(color_swap)](创新：互换不是全局的，而是由控制矩阵逐格决定是否执行) + [控制矩阵(control_matrix)](创新：矩阵编码二值决策信号而非直接目标色) + [模板格点(template_lattice)](保留)

**来源原语**：控制矩阵、索引映射、模板格点、模板对象、行列位置对应、按控制色重涂（33b52de3）；颜色互换、框内区域、框内限定（7ee1c6ea）

**依赖链**：模板格点提供操作目标（每个模板对象内含蓝/红两色）→ 控制矩阵的行列位置映射到对应模板对象 → 控制格的颜色编码"互换"或"保持"指令 → 对"互换"指令对应的模板执行蓝红互换。控制矩阵的语义不是"涂什么色"而是"做不做操作"，与 33b52de3 的直接重涂完全不同。

格点阵列中每个模板对象含两种颜色，控制矩阵中对应位置的颜色决定该模板是否执行颜色互换——控制矩阵编码操作指令而非目标颜色。

**输入结构**：约 19x19 网格，背景黑(0)。一个 4x3 的模板格点阵列：每个模板对象为 3x3 的灰(5)边框，内含 7 个格（边框像素），内部 2 格中一格蓝(1)一格红(2)（内部两个非黑格的位置在不同模板中可不同）。模板之间间隔 1 格黑背景。在网格的右下角区域，有一个 4x3 的控制矩阵，每格为绿(3)或黄(4)。控制矩阵与模板格点行列数相同。

**规则**：
1. 识别 4x3 模板格点阵列和 4x3 控制矩阵。
2. 将控制矩阵第 i 行第 j 列的格映射到模板格点第 i 行第 j 列的模板对象。
3. 若控制格为绿(3)：将对应模板对象内的蓝(1)像素改为红(2)、红(2)像素改为蓝(1)。
4. 若控制格为黄(4)：对应模板对象保持不变。
5. 将控制矩阵区域全部擦除为黑(0)背景。
6. 其他所有像素（灰边框、背景）保持不变。

**关键洞察**：控制矩阵中的两种颜色不是要涂到模板上的目标颜色，而是一个布尔开关："绿=执行互换"vs"黄=保持原样"。求解者看到控制矩阵中有绿有黄，可能首先猜测它们是直接重涂色——必须对比多个示例才能发现其真正语义是条件开关。

## 新题 10：垂直镜像差异检测 + 差异像素频率堆叠

**组合逻辑**：[镜像(mirror) + 翻转行序(row_reversal)](创新：镜像不是最终输出而是检测工具) → 差异像素提取 → [计数(counting) + 按频率降序(descending_freq)](保留) → [堆叠(stack) + 逐列填充(column_fill)](保留)

**来源原语**：镜像、翻转行序（68b16354）；堆叠、逐列填充、按频率降序、计数（bd283c4a）

**依赖链**：原始网格垂直翻转后与原始逐格比较 → 差异像素（两版本颜色不同的位置）被标记 → 统计差异像素中各颜色的出现频率 → 按频率降序将差异像素堆叠到新网格中。镜像步骤是后续所有步骤的检测前提——不做镜像比较就无法确定哪些像素是"不对称的"。

将网格垂直翻转后与原图逐格比较，提取不一致像素，按颜色频率降序堆叠打包为输出。

**输入结构**：10x8 网格，包含多种颜色的像素（蓝(1)、红(2)、绿(3)、黄(4)、橙(7)），背景黑(0)。网格近似垂直对称（上下半部分大致镜像），但有若干故意的不对称：约 8~15 个像素位置在垂直翻转后颜色不同。不对称像素涉及 3~4 种颜色，每种颜色的不对称像素数互不相同。

**规则**：
1. 将输入网格垂直翻转（行序逆转），得到镜像网格。
2. 逐格比较原始网格与镜像网格。标记所有颜色不同的位置为"差异位置"。
3. 对每个差异位置，取原始网格中该位置的颜色（非翻转版本的颜色）。收集所有差异像素及其颜色。
4. 统计差异像素中各颜色的出现次数。按出现次数从多到少排列颜色。
5. 创建一个与输入同尺寸的全黑(0)输出网格。从最左列开始、每列从底行向上逐格放置，按频率降序排列的颜色依次填入：先放完出现次数最多的颜色的所有像素，再放第二多的，以此类推。若一列填满则转入下一列继续从底部开始。
6. 完全对称的像素（原始与翻转颜色相同）不出现在输出中。

**关键洞察**：网格看似对称，但求解者必须做垂直翻转比较来找出破坏对称的位置。输出丢弃了所有空间信息，仅保留不对称像素的颜色频率统计——从二维空间结构到一维频率编码的降维。
