## 新题 1：奇偶分流的掏空平铺

**组合逻辑**：[掏空(hollowing)] + [计数(counting) → 面积奇偶判断(创新：奇偶决定填充模式而非填充颜色)] + [平铺(tiling) / 洪泛填充(flood_fill)]（掏空与平铺来自不同源题，奇偶判断从"选颜色"创新为"选填充模式"）

**来源原语**：掏空(hollowing) ← 4347f46a；计数(counting) + 面积奇偶(parity_sets_fill) ← 868de0fa；平铺(tiling) + 种子图案(seed_pattern) + 保持种子相位(preserve_seed_phase) ← a57f2f04；洪泛填充(flood_fill) ← 868de0fa

**依赖链**：种子图案嵌在实心矩形内部 → 必须先提取种子再掏空 → 掏空后的内腔面积决定填充模式 → 偶数面积用种子平铺、奇数面积用种子主色洪泛填充。种子提取、掏空、面积计算、填充四步中，任一步缺失都无法得到正确输出。

将实心矩形掏空为边框，根据内腔面积的奇偶性选择两种不同的填充策略：偶数面积用内部原有的种子图案平铺，奇数面积用种子的主色实心填充。

**输入结构**：约 18x18 的黑(0)背景网格。散布 3~5 个不同颜色的实心轴对齐矩形（如蓝(1)、绿(3)、红(2)等），每个矩形至少 5x5（保证内腔至少 3x3）。每个矩形的内腔中包含一个小型种子图案（2x2 或 2x3 的4-连通单色区域，颜色与矩形本体不同，如矩形为蓝(1)则种子为黄(4)），种子位于内腔的某个位置。各矩形互不接触（间距至少 1 像素）。生成约束：每个矩形的内腔面积 (width-2)*(height-2) 在不同示例中既有偶数也有奇数情况；种子图案不触碰矩形边框（与边框间距至少 1 像素）。

**规则**：
1. 对每个实心矩形，定位其内腔中颜色与矩形本体不同的像素集合，取其最小外接矩形作为种子瓦片。记录种子瓦片的内容及其在内腔中的位置（行列偏移）。
2. 计算该矩形的内腔面积：(矩形宽度 - 2) * (矩形高度 - 2)。
3. 掏空该矩形：保留其 1 像素宽的边框，将内腔全部设为黑(0)背景。
4. 根据内腔面积的奇偶性选择填充方式：
   - 偶数面积：以种子瓦片在内腔中进行周期平铺。平铺相位与种子在原始内腔中的位置一致——即内腔坐标 (r, c) 处的颜色为种子瓦片在 ((r - seed_row_offset) mod tile_height, (c - seed_col_offset) mod tile_width) 处的颜色。种子瓦片中为黑(0)的位置在平铺时保持黑(0)。
   - 奇数面积：统计种子瓦片中出现次数最多的非背景颜色（若平局，取在种子中扫描顺序——从左上到右下逐行——最先出现的），用该颜色洪泛填充整个内腔。
5. 各矩形独立处理，互不影响。处理顺序不影响结果（因为矩形互不接触）。

**关键洞察**：种子图案必须在掏空之前提取，否则会被清除；同一个种子在偶数内腔中作为平铺模板使用，在奇数内腔中仅提供一个颜色值——同一输入元素的用途由内腔面积的奇偶性决定。仅看一个示例（若所有矩形碰巧同为偶数或同为奇数面积），无法区分这两种模式。

## 新题 2：折叠生障的路径绕行

**组合逻辑**：[折叠(fold)]（创新：折叠产物从"变形结果"变为"路径障碍"） → [路径绘制(path_drawing) + 绕行(detour)]（创新：绕行方向由障碍的来源属性——固定段/折叠段——决定，而非颜色）

**来源原语**：折叠(fold) + 铰接标记(hinge_marker) + 端点标记(endpoint_marker) + 固定端与活动端(fixed_vs_free) + 空间大侧折入(fold_toward_space) ← 230f2e48；路径绘制(path_drawing) + 绕行(detour) + 边界标记(border_marker) + 阻挡(blocking) ← 96a8c0cd

**依赖链**：折叠改变杆件的空间布局，产生新位置的障碍段 → 路径从边界标记出发直行遇到障碍时绕行 → 绕行方向取决于阻挡段是固定段还是折叠段 → 折叠结果同时决定障碍位置和绕行方向。去掉折叠，障碍布局和方向信号都不存在；去掉路径规则，折叠无目的。

将直线杆在铰接点折叠成 L 形后，从边界标记出发绘制路径，遇到 L 形障碍时根据阻挡部分是原始固定段还是新折叠段来决定绕行方向。

**输入结构**：约 20x20 的黑(0)背景网格。3~5 根直线杆（水平或垂直，1 像素宽），每根杆用绿(3)着色，长度 5~9 像素。每根杆的一个端点为灰(5)像素（端点标记），杆的中间某处有一个橙(7)像素（铰接标记），其余像素为绿(3)。杆件之间互不接触（间距至少 2 像素）。网格某一条边界上有恰好一个红(2)像素（边界标记），位于第一行或最后一行或第一列或最后一列的非角落位置。生成约束：折叠后各 L 形不重叠、不超出网格边界；路径从边界标记到对面边界的行进路线上至少经过 2 根折叠后的杆件；各杆的铰接标记不在端部（保证折叠产生 L 形而非保持直线）。

**规则**：
1. 对每根杆：从灰(5)端点标记到橙(7)铰接标记的这段（含两端）为固定段，保持位置不动。橙(7)铰接标记另一侧的绿(3)像素段为活动尾段。
2. 将活动尾段绕铰接标记旋转 90 度：选择朝向网格边缘空间更大的一侧（以铰接标记到两侧网格边缘的距离判断；若相等，选顺时针方向）。旋转后，活动尾段变为与原方向垂直的一段，起点紧邻铰接标记的对应侧。尾段保持绿(3)色。
3. 折叠完所有杆件后，从红(2)边界标记出发，沿垂直于所在边界向网格内部的方向直行，绘制红(2)路径。
4. 当路径前方下一格为绿(3)或灰(5)或橙(7)像素时（即遇到杆件障碍），判断该像素属于哪根杆的哪个段：
   - 若属于固定段（含灰(5)端点标记和橙(7)铰接标记及其间的绿(3)像素）：路径向左偏转（相对行进方向的左侧）
   - 若属于折叠尾段（铰接标记另一侧折叠后的绿(3)像素）：路径向右偏转
5. 偏转过程：路径先向偏转方向移动一格，然后继续沿原前进方向前行，直到通过障碍段的末端后再多前进一格，再向反方向移动一格回到原始行进车道，继续前进。整个偏转路径上只将黑(0)背景像素涂为红(2)，已有颜色的像素保持不变。
6. 路径到达对面网格边界时停止。若路径遇到网格边界无法偏转，则在边界处停止（生成约束保证此情况不发生）。

**关键洞察**：折叠不仅改变障碍的几何形状，还编码了绕行方向——固定段和折叠段在输出中都是绿(3)色、形态相似，但它们的"来源身份"（折叠前是否移动过）决定了路径绕行方向。求解者必须还原折叠过程才能判断每段障碍的身份。需要对比多个示例才能归纳出"固定段→左、折叠段→右"的方向规则（单个示例中可能只有一种情况）。

## 新题 3：稀疏解码模板补全

**组合逻辑**：[下采样(downsample)]（创新：下采样的产物不是最终输出，而是中间模板） → [模板提取(template_extraction) + 补全(completion)]（创新：模板来自下采样而非直接可见的矩形区域）

**来源原语**：下采样(downsample) + 分隔行列(separator_rows_and_columns) + 奇偶索引分离(even_odd_index_separation) + 保留偶索引交叉(keep_even_crossings) ← 68b67ca3；模板提取(template_extraction) + 补全(completion) + 变换副本(transformed_copy) + 对齐签名匹配(alignment_signature_matching) + 旋转反射等价(rotation_reflection_equivalence) ← 79369cc6

**依赖链**：左区的稀疏格点编码了真实模板 → 下采样解码出紧凑模板 → 模板中的品红像素作为对齐签名 → 在右区找到签名匹配的旋转/反射放置 → 补全每个放置中缺失的非品红像素。去掉下采样，模板形状被分隔行列遮蔽；去掉补全，下采样结果无用武之地。

网格左区用稀疏格点编码了一个隐藏模板，下采样后提取紧凑模板，再用该模板补全右区中由品红签名标记的不完整旋转/反射副本。

**输入结构**：约 15x24 的黑(0)背景网格，沿垂直方向中线分为左区和右区（左区宽度为偶数）。左区：偶数行与偶数列交叉处包含有色像素（黄(4)和品红(6)混合），奇数行和奇数列全为黑(0)，形成稀疏格点图案。左区的有色像素构成的图案在下采样后尺寸约为 3x3 到 5x5。右区：黑(0)背景上散布若干品红(6)像素簇（每簇 2~4 个像素），这些簇是模板的不完整旋转或反射副本的品红部分。生成约束：模板中品红(6)像素的集合在任何旋转/反射变体中互不相同（保证对齐签名唯一确定朝向）；右区中每个品红簇恰好对应模板某一朝向的品红子集且不遗漏任何品红位置；黄(4)位置可被网格边界裁剪但品红(6)位置必须全部在网格内。

**规则**：
1. 对左区执行下采样：仅保留偶数行与偶数列交叉处的像素，去掉所有奇数行和奇数列。产出一个紧凑的矩形模板，包含黄(4)和品红(6)两种颜色的像素。
2. 生成模板的所有 8 种朝向变体（4 种旋转 x 2 种反射状态）。对每种朝向，提取其中品红(6)像素的相对坐标集合作为该朝向的对齐签名。
3. 在右区中，逐像素扫描（从左上到右下）：对每个品红(6)像素作为锚点，尝试所有 8 种朝向：将该朝向的对齐签名对齐到锚点位置，检查签名中的每个品红位置是否都对应右区中的一个品红(6)像素（允许签名的不同位置对齐到同一个锚点）。
4. 若某朝向的对齐签名完全匹配（所有品红签名位置在右区中都是品红像素），则该放置有效。对该放置中模板的黄(4)位置：若该坐标在网格内且当前为黑(0)，则涂为黄(4)；若超出网格边界，忽略。
5. 同一个品红像素可被多个放置共享（当不同朝向的签名重叠时）。品红像素本身不变色。
6. 左区保持原样不修改。

**关键洞察**：模板从未以紧凑形式直接出现在输入中——它被编码在稀疏格点中，求解者必须先识别"偶数行列交叉"规律并心算下采样结果。下采样规律本身需要对比多个示例才能确认（单个示例中，可能误以为是每隔一行一列取样而非严格的偶数索引）。

## 新题 4：中位对齐后的遮蔽循环填充

**组合逻辑**：[对齐(align) + 裁剪(trim)]（创新：对齐改变的不是最终输出的位置，而是后续循环填充的"原料配方"） → [列遮挡(column_coverage) 判断] → [循环填充(cycle_fill)]（创新：循环序列来自对齐后的纵向颜色栈，而非预设序列）

**来源原语**：对齐(align) + 裁剪(trim) + 线段(line_segment) + 平行共向(parallel_codirectional) + 中位线为参考(median_as_reference) ← e376de54；射线延伸(ray_cast) + 列遮挡(column_coverage) + 遮挡列延伸至边(covered_col_to_edge) ← 6d58a25d；循环填充(cycle_fill) + 色彩循环(color_cycle) ← 72207abc

**依赖链**：多根平行线段的位置各不相同 → 以中位线为基准对齐并裁剪到统一长度 → 对齐后各线段在同一列区间纵向叠加形成颜色栈 → 灰色人字形遮蔽物决定哪些列被激活 → 激活列用其颜色栈作循环序列向下填充。对齐步骤改变了每列的颜色组成；遮蔽判断决定了哪些列有填充；循环规则决定了填充内容。三者缺一不可。

多根平行水平线段先对齐到中位线的起止位置，对齐后线段的纵向颜色叠加构成循环序列，再由下方的人字形遮蔽物决定哪些列激活循环填充。

**输入结构**：约 20x20 的黑(0)背景网格。上半区域有 4~6 根水平线段（1 像素厚），各自颜色不同（从红(2)、蓝(1)、绿(3)、黄(4)、栗(9)中选），分布在不同行，起始列和长度各异。下半区域有一个灰(5)人字形（V 形或倒 V 形，开口朝上或朝下，宽度 8~14 像素，由 1 像素厚的对角线段构成）。线段与人字形之间至少隔 2 行空白。生成约束：线段数量为奇数（使中位线唯一）；各线段长度不全相同（使对齐裁剪可见）；人字形跨越的列范围与对齐后线段跨越的列范围有部分重叠但不完全相同。

**规则**：
1. 识别所有水平线段。按行位置排序，取中位线（按行号排序后的中间那根）作为参考线段。
2. 将每根线段水平平移，使其起始列与参考线段的起始列对齐。若线段比参考线段长，从右侧裁剪到参考线段长度；若比参考线段短，从右侧用该线段自身颜色延长到参考线段长度。线段保持在各自的行上，仅水平移动。
3. 对齐后，所有线段覆盖同一列区间 [c_start, c_end]。对该区间内的每一列 c，从上到下读取该列上所有线段的颜色（按行号从小到大），形成该列的颜色序列 S_c。由于所有列的线段集合相同（只是颜色被对齐了），S_c 对所有列相同，记为 S。
4. 对于列区间 [c_start, c_end] 中的每一列 c：从该列最底部的行开始向上搜索灰(5)像素。若在人字形中找到灰(5)像素，则该列被"遮蔽"（激活）；否则不激活。
5. 对每个被激活的列 c：找到该列中灰(5)人字形最下方像素所在的行 r_bottom。从 r_bottom + 1 行开始到网格最后一行，用颜色序列 S 循环填充：第 r_bottom + 1 行涂 S[0]，第 r_bottom + 2 行涂 S[1]，……，序列用完后从头循环。
6. 未被激活的列不做任何修改。人字形本身的灰(5)像素保持不变。线段像素保持对齐后的位置和颜色。

**关键洞察**：对齐步骤不只是几何整理——它将原本散落在不同列区间的线段汇聚到同一列区间，从而改变了每列的颜色"配方"。若不对齐，有些列可能只有 1~2 条线段经过，颜色序列不完整。中位线的选取规则（而非最长或最上的线段）需要对比多个示例才能确认。

## 新题 5：镜像平铺涌现矩形的跨界掏空

**组合逻辑**：[平铺(tiling) + 镜像(mirror)]（创新：平铺后的结果不是最终输出，而是产生新几何特征的中间步骤） → [掏空(hollowing)]（创新：掏空的对象不是输入中的原有矩形，而是平铺涌现的跨界矩形）

**来源原语**：平铺(tiling) + 镜像(mirror) + 瓦片(tile) + 阵列排布(array_layout) + 相邻槽位翻转(adjacent_slot_flip) ← c48954c1；掏空(hollowing) + 实心矩形(solid_rectangle) + 边框(frame) + 保留边擦除内部(keep_border_erase_interior) ← 4347f46a

**依赖链**：小网格经镜像规则铺成 3x3 马赛克 → 相邻瓦片的翻转使得边界处的色块拼合成更大的矩形（这些矩形在单个瓦片中不存在） → 检测所有跨越瓦片边界的实心矩形 → 仅掏空跨界矩形，单瓦片内的矩形保持实心。去掉镜像规则，跨界矩形不会出现；去掉跨界判断，无法区分哪些掏空哪些保留。

将小网格按镜像规则铺成 3x3 马赛克，在瓦片边界处涌现出新的大矩形，仅对跨越瓦片边界的矩形执行掏空操作。

**输入结构**：一个 4x4 或 5x5 的彩色网格，包含黑(0)背景和若干有色像素。有色像素形成 1~3 个小型实心矩形区域（2x2 或 2x3 或 1x3 等），各矩形颜色不同（如蓝(1)、红(2)、黄(4)）。设计时确保：至少一个矩形的某条边紧贴网格边缘，使得镜像平铺后该矩形与相邻瓦片中的镜像副本拼合成更大的矩形；至少一个矩形不贴边，使其镜像后不与邻居拼合。

**规则**：
1. 以输入网格为中心瓦片，构建 3x3 的镜像马赛克，输出尺寸为 (3*H) x (3*W)，其中 H、W 为输入的高和宽。9 个槽位编号如下（行,列从 0 开始）：
   - (0,0) 左上、(0,1) 上、(0,2) 右上
   - (1,0) 左、(1,1) 中心、(1,2) 右
   - (2,0) 左下、(2,1) 下、(2,2) 右下
2. 中心槽 (1,1) 放置原始瓦片。与中心在行方向相邻的槽 (0,1) 和 (2,1) 将瓦片行顺序翻转。与中心在列方向相邻的槽 (1,0) 和 (1,2) 将瓦片列顺序翻转。四个角槽 (0,0)(0,2)(2,0)(2,2) 同时翻转行和列。
3. 在马赛克中检测所有最大单色实心轴对齐矩形（贪心扩展：对每个非背景像素，找到包含它的最大同色矩形；去重后保留不被其他同色矩形严格包含的）。只考虑短边至少 3 像素的矩形（确保有内腔可掏空）。
4. 对每个检测到的矩形，判断其是否"跨越瓦片边界"：矩形的外接框是否跨越任何瓦片槽之间的分界线（行分界线在第 H 行和第 2H 行，列分界线在第 W 列和第 2W 列）。
5. 跨界矩形：掏空，保留 1 像素宽边框，内腔全部设为黑(0)。
6. 未跨界矩形（完全在单个瓦片槽内）：保持实心，不修改。
7. 若掏空操作使某个矩形的内腔像素恰好也是另一个矩形的边框像素，后者的边框保留（掏空不影响其他矩形的边框）。处理顺序：按矩形面积从大到小掏空。

**关键洞察**：镜像平铺在瓦片边界处"制造"了输入中不存在的大矩形——两个贴边的小矩形与它们的镜像副本拼合成更大的整体。是否掏空取决于矩形是否跨界，而跨界与否是由输入小矩形的位置（是否贴边）间接决定的。求解者需要理解镜像规则如何在边界处合并色块，这需要对比多个示例中不同的贴边情况。

## 新题 6：分隔叠加后的凹槽链式填充

**组合逻辑**：[透明叠加(transparent_overlay) + 擦除(erase)]（创新：叠加不是最终合并，而是将分离的元素带入同一坐标系以启用几何匹配） → [形状匹配(shape_matching) → 拼接(assemble)] → [链式填充(chain_fill)]

**来源原语**：透明叠加(transparent_overlay) + 擦除(erase) + 分隔行(separator_row) + 等高面板(equal_height_panel) + 分隔对齐(separator_alignment) + 前景不冲突(no_fg_collision) ← e98196ab；拼接(assemble) + 链式填充(chain_fill) + 精灵体(sprite) + 凹槽(notch) + 中心条(central_bar) + 形状匹配(shape_matching) + 固定条带宽度(fixed_strip_width) ← 16b78196

**依赖链**：分隔行将中心条和精灵体隔离在不同面板 → 删除分隔行并叠加面板，使两者进入同一坐标系 → 精灵体与中心条凹槽的形状匹配只在叠加后才可能 → 匹配的根精灵体定义条带宽度 → 后续精灵体沿条带链式填充。分隔行不仅是分界线，还是信息屏障：不叠加就无法发现匹配关系。

两个面板被分隔行分开，一个面板含有带凹槽的中心条，另一个含有散落精灵体；删除分隔行叠加后，精灵体按形状匹配填入凹槽并沿条带链式延伸。

**输入结构**：约 17x15 的黑(0)背景网格。一条完整的灰(5)水平行横贯全宽，将网格分为上下两个等高面板（各约 8x15）。上面板：一个蓝(1)实心水平长条（宽度 10~13、高度 3~4），位于面板中部。长条的上边缘或下边缘有 2~3 个凹槽（凹槽是黑(0)缺口，从长条外接框边缘向内凹入 1~2 像素，每个凹槽形状不同，如 2x1、1x2、L 形(3像素)等）。下面板：散布 4~7 个小型彩色精灵体（每个 2~5 像素的 4-连通区域，颜色各不相同，如红(2)、绿(3)、黄(4)、橙(7)、栗(9)等）。生成约束：上下面板的前景像素在叠加后不冲突（同一局部坐标不同时有非背景像素）；恰好有与凹槽数量相同的精灵体形状匹配凹槽（允许旋转/反射）；每个凹槽恰好被一个精灵体匹配（无歧义）；剩余精灵体用于链式填充。

**规则**：
1. 删除灰(5)分隔行。
2. 将下面板按局部坐标叠加到上面板上：对于每个局部坐标 (r, c)，若上面板该位置为黑(0)而下面板为非背景色，则输出取下面板的颜色；若上面板为非背景色，则保留上面板的颜色。（因生成约束，不会有冲突。）输出网格高度减少 1 行（删去分隔行）。
3. 对蓝(1)中心条的每个凹槽：从可用精灵体中寻找形状完全匹配凹槽孔洞的精灵体（允许 4 种旋转和 2 种反射共 8 种朝向）。将匹配的精灵体放入凹槽，颜色保持精灵体原色。该精灵体标记为"根件"，从可用池中移除。
4. 每个根件定义一个条带：条带方向为凹槽开口的朝向（若凹槽从上边缘凹入，则条带向上延伸；从下边缘凹入则向下延伸；从左边缘凹入则向左；从右边缘凹入则向右）。条带宽度等于根件在垂直于条带方向上的跨度。
5. 链式填充：从根件的外接框沿条带方向向外看，找到外接框紧邻的下一段背景区域。从剩余精灵体中，找到一个其形状能填入该区域（宽度锁定为条带宽度，高度/长度等于该精灵体的对应维度，允许旋转/反射使其适配）的精灵体。放入后，继续从这个精灵体的外接框向外寻找下一个，直到没有可用精灵体或遇到网格边界。
6. 凹槽处理顺序：从左到右（水平凹槽）或从上到下（垂直凹槽）。链内精灵体选取：从剩余池中按精灵体在原始输入中的位置（按行优先、列次之的扫描序）选取第一个形状适配的。

**关键洞察**：分隔行是一道信息屏障——上面板的凹槽形状和下面板的精灵体形状只有在叠加后才能进行比对。在叠加前，求解者无法直接看出哪个精灵体对应哪个凹槽。条带方向继承自凹槽的开口方向而非任何显式标记，这需要对比多个不同凹槽方向的示例才能归纳。

## 新题 7：折叠制件的拼图组装

**组合逻辑**：[折叠(fold)]（创新：折叠不再是最终变换，而是"制造"拼图碎片的前处理步骤） → [拼合填充(packing)]（创新：拼合的碎片形状由折叠参数动态决定，而非输入中的静态多连块）

**来源原语**：折叠(fold) + 直线杆(straight_rod) + 铰接标记(hinge_marker) + 端点标记(endpoint_marker) + 固定端与活动端(fixed_vs_free) + 空间大侧折入(fold_toward_space) ← 230f2e48；拼合填充(packing) + 多连块碎片(polyomino_fragment) + 紧凑矩形(compact_rectangle) + 无重叠拼合(non_overlap_packing) + 按面积降序放置(descending_area_place) ← b7cb93ac

**依赖链**：每根直线杆的铰接位置和折叠方向决定了 L 形碎片的精确几何形状 → L 形碎片的集合决定了拼图能否填满目标矩形 → 目标矩形的尺寸由输入中的空心灰框指定 → 拼合结果中每块碎片保持其原始颜色。改变任何一根杆的铰接位置，折叠后的形状不同，拼合方案随之改变或变得不可能。

将带铰接标记的直线杆折叠成 L 形碎片，然后将所有碎片无间隙无重叠地拼入一个指定尺寸的目标矩形。

**输入结构**：约 18x18 的黑(0)背景网格。3~5 根直线杆（水平或垂直，1 像素宽），颜色各不相同（红(2)、绿(3)、黄(4)、蓝(1)等），长度 4~8 像素。每根杆的一个端点为灰(5)像素（端点标记），杆的中间某处（非端部）有一个橙(7)像素（铰接标记），其余像素为该杆的主色。杆件之间互不接触。网格的某个角落区域有一个灰(5)空心矩形框（1 像素厚边框，内腔为黑(0)），其内腔尺寸即为拼合目标矩形的尺寸。生成约束：所有杆件折叠成 L 形后的总像素数恰好等于目标矩形的内腔面积；折叠后的 L 形碎片集合恰好能无重叠无间隙地填满目标矩形（存在唯一拼合方案或在旋转/反射等价意义下唯一）。

**规则**：
1. 对每根杆，执行折叠：从灰(5)端点标记到橙(7)铰接标记为固定段（保持不动）。铰接标记另一侧为活动尾段。将活动尾段绕铰接标记旋转 90 度，朝向网格边缘空间更大的一侧（以铰接标记到两侧可选方向的网格边缘距离判断；若距离相等，选顺时针方向）。折叠后每根杆变为 L 形多连块碎片。铰接标记处的像素属于两段共享，折叠后为 L 的拐角。碎片颜色统一为该杆的主色（灰(5)端点标记涂为主色，橙(7)铰接标记也涂为主色）。
2. 读取灰(5)空心矩形框的内腔尺寸作为目标矩形的宽度和高度。
3. 将所有 L 形碎片（和可能未折叠的直线碎片，若铰接点在端部则不折叠）拼入目标矩形，要求：无重叠、无间隙、不超出矩形边界。
4. 拼合规则：按碎片面积（像素数）从大到小排列。面积相同时，按碎片在输入中的位置——以杆的灰(5)端点标记为锚点，按行优先列次之的扫描序排列。
5. 对每个碎片，依次尝试以下朝向：原始形状、顺时针 90 度、180 度、270 度、水平镜像、水平镜像后 90 度、180 度、270 度（共 8 种）。对每种朝向，在目标矩形中从左上到右下逐行扫描放置位置。取第一个不与已放置碎片冲突的位置。
6. 输出为目标矩形大小的网格，每个像素为对应碎片的颜色。灰(5)空心框本身不出现在输出中。

**关键洞察**：拼图碎片不是输入中的现成形状，而是通过折叠"制造"出来的——改变铰接标记的位置会改变 L 形的臂长比，从而影响拼合可行性。求解者必须先还原每根杆的折叠结果（包括确定折叠方向），才能得到碎片集合进行拼合。折叠方向的规则（朝向空间更大的一侧）需要对比不同示例中铰接位置与网格边缘关系才能归纳。

## 新题 8：路径遇障编码的边框循环涂色

**组合逻辑**：[描边(border_draw)]（创新：边框不是最终形态，而是循环涂色的画布） + [路径绘制(path_drawing) + 绕行(detour)]（创新：路径的目的不是路径本身，而是建立障碍的遭遇顺序） → [循环填充(cycle_fill)]（创新：循环序列来自路径遭遇障碍的颜色序列，而非预设）

**来源原语**：描边(border_draw) + 画布边界(canvas_boundary) + 沿边界绘边框(draw_border_frame) ← 6f8cd79b；路径绘制(path_drawing) + 绕行(detour) + 边界标记(border_marker) + 障碍条(obstacle_bar) + 阻挡(blocking) + 障碍色决定绕行(obstacle_color_detour) ← 96a8c0cd；循环填充(cycle_fill) + 色彩循环(color_cycle) + 递增间距序列(increasing_gap_sequence)（创新改造：间距不递增，改为等间距循环） ← 72207abc

**依赖链**：先绘制青色边框 → 从边界标记出发绘制路径，路径遇到蓝/绿障碍条时按颜色绕行 → 路径遭遇障碍的颜色顺序（如"蓝、绿、绿、蓝"）构成一个颜色循环序列 → 用该序列循环涂色替换边框的青色像素。描边提供画布，路径提供序列，循环填充完成涂色——三者形成"画布-读取器-涂料"的三角耦合。

绘制网格边框，路径穿越障碍条时记录遭遇颜色序列，该序列作为循环涂料重新涂色边框。

**输入结构**：约 15x15 的黑(0)背景网格。网格内部（不在边界上）散布 3~6 根 1 像素厚的水平或垂直障碍条，每根为蓝(1)或绿(3)，长度 3~7 像素，垂直于将要通过的路径方向。网格顶部边界的某个非角落位置有一个红(2)像素（边界标记）。生成约束：从红(2)标记向下直行（及绕行后回到的车道）能在到达底部边界前遇到所有障碍条中的至少 3 根；障碍条互不接触；绕行路径不超出网格边界；障碍条的蓝/绿组合在不同示例中不同（以便求解者归纳颜色-方向映射）。

**规则**：
1. 在输出网格上绘制 1 像素宽的青(8)边框：第一行、最后一行、第一列、最后一列全部设为青(8)。网格内部（非边界）保持原状。红(2)边界标记保持红色不被覆盖（它在第一行上，边框绘制时跳过该像素）。
2. 从红(2)标记出发，向下（朝网格内部）绘制红(2)路径。
3. 当路径前方下一格为蓝(1)像素时：路径向左偏转（相对向下方向即向右方向的反向，即向网格左侧移动一格），然后继续向下直行绕过障碍条，在障碍条末端下方一格再向右移回原车道。记录遭遇颜色"蓝(1)"。
4. 当路径前方下一格为绿(3)像素时：路径向右偏转，绕过障碍条后移回原车道。记录遭遇颜色"绿(3)"。
5. 偏转具体过程：(a) 向偏转方向移动 1 格，(b) 继续沿原方向（向下）前行直到超过障碍条末端像素所在行，(c) 向反方向移动 1 格回到原车道，(d) 继续向下。整个偏转路径上只将黑(0)背景像素涂为红(2)，已有颜色不覆盖。
6. 路径到达最后一行边框时停止（不覆盖边框青色）。
7. 将路径遭遇的障碍颜色按遭遇顺序排列，形成颜色循环序列 C（如 [蓝(1), 绿(3), 绿(3), 蓝(1)]）。
8. 用序列 C 循环涂色边框：从网格左上角 (0,0) 开始，沿顺时针方向遍历所有边框像素（先沿第一行从左到右，再沿最后一列从上到下，再沿最后一行从右到左，再沿第一列从下到上，角落像素只在第一次经过时计入），跳过红(2)标记位置，其余每个青(8)边框像素依次替换为 C 中的下一个颜色（序列用完后从头循环）。

**关键洞察**：障碍条同时扮演两个角色——作为路径的物理阻碍决定路径形状，又作为颜色编码器提供边框涂色序列。移动一根障碍条会同时改变路径走向和边框的配色方案。路径是"读取器"，将二维空间中的障碍分布转译为一维的颜色序列。蓝/绿→左/右的方向映射规则需要对比多个示例（含不同蓝绿顺序）才能确认。
