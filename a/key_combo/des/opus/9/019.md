## 新题 1：容器对称性决定内容物补全方式

**组合逻辑**：[墙分隔区域](已有) → [对称补全](创新：对称类型由容器边界决定而非对象自身) + [筛选](已有：不满足对称条件的区域清空)

**来源原语**：墙分隔区域(wall_partitions_regions) ← 62ab2642；对称补全(symmetry_completion) ← 11852cab；分隔墙(partition_wall) ← 62ab2642；连通区域(connected_region) ← 62ab2642；旋转对称(rotational_symmetry) ← 11852cab；筛选(filtering) ← 29623171

**依赖链**：墙的分区形状决定对称类型 → 对称类型决定补全操作的具体方式 → 补全结果反过来必须不越出区域边界（越界则裁剪）。三者形成容器-操作-约束的闭合回路。

将灰墙分隔出的每个区域的边界形状作为对称指令，对区域内的残缺对象施加对应类型的补全。

**输入结构**：约 15x15 的黑(0)背景网格。灰(5)像素构成单像素宽的直线墙，将网格分隔为 4~6 个矩形区域（区域宽高比各异，有的接近正方形，有的明显偏长）。每个区域内有一个由单一非背景、非灰颜色构成的 4-连通前景对象（3~8 像素），该对象是某个对称图形的一部分（缺失了若干像素）。生成约束：每个区域的矩形边界恰好属于以下三类之一——(a) 宽=高（正方形区域），(b) 宽>高 且宽=2*高（横向 2:1），(c) 高>宽 且高=2*宽（纵向 1:2）。每类至少出现一次。区域内对象的完整形态在对应对称操作下可由已有像素唯一确定。

**规则**：
1. 识别灰(5)墙，确定每个矩形分区的宽高比。
2. 对每个分区，根据其宽高比选择补全方式：
   - 正方形区域（宽=高）：对区域内前景对象施加 90 度旋转对称补全（以区域中心为旋转中心，将已有像素旋转 90/180/270 度，在黑(0)位置填入对应颜色）。
   - 横向 2:1 区域（宽=2*高）：对区域内前景对象施加水平镜像补全（以区域的垂直中轴为镜像轴，将已有像素水平翻转，在黑(0)位置填入对应颜色）。
   - 纵向 1:2 区域（高=2*宽）：对区域内前景对象施加垂直镜像补全（以区域的水平中轴为镜像轴，将已有像素垂直翻转，在黑(0)位置填入对应颜色）。
3. 补全产生的像素若落在区域外（理论上不应发生，因生成时保证可解），则裁剪丢弃。
4. 灰(5)墙像素保持不变。

**关键洞察**：对象自身不携带对称类型信息——必须先分析容器（分区矩形）的几何比例才能确定应施加哪种对称操作，这与源题中"对象自身决定自身对称性"完全不同。

## 新题 2：密度竞胜区域发射遮挡射线

**组合逻辑**：[计数](已有) + [筛选](已有) → [射线延伸](创新：射线源由计数胜出决定) → [遮挡覆盖](已有：距墙近者覆盖远者)

**来源原语**：计数(counting) ← 29623171；筛选(filtering) ← 29623171；射线延伸(ray_extend) ← 13713586；遮挡覆盖(occlusion_overwrite) ← 13713586；分隔墙(partition_wall) ← 62ab2642；分区区域(partitioned_region) ← 29623171；按距离排序绘制(draw_ordered_by_distance) ← 13713586

**依赖链**：计数结果决定哪个区域的像素获得发射权 → 射线从胜出像素沿正交方向延伸到墙 → 多条射线重叠时按源像素到目标墙的距离决定遮挡顺序（近者覆盖远者）。计数是门控条件，射线是核心操作，遮挡是冲突解决——三层不可省略。

统计每个墙分区内的前景像素数量，仅让像素最多的区域中的每个前景像素向四方向发射同色射线到墙壁，射线重叠时离目标墙更近的射线覆盖更远的。

**输入结构**：约 17x17 的黑(0)背景网格。灰(5)直线墙（单像素宽）将网格分为 4~6 个矩形区域。每个区域内散布若干单色前景像素（每个区域用同一种非背景、非灰颜色，不同区域颜色不同），数量在 2~7 之间。生成约束：恰好一个区域拥有严格最多的前景像素数量（无并列）。各区域的前景像素互不 4-连通（孤立散布）。

**规则**：
1. 识别灰(5)墙，划分矩形区域。
2. 统计每个区域内非黑(0)、非灰(5)的前景像素数量。
3. 找到像素数量严格最多的唯一区域（生成时保证唯一）。
4. 对该区域内每个前景像素，沿上、下、左、右四个方向发射射线：射线用该像素的颜色逐格绘制，遇到灰(5)墙像素时在墙前一格停止（不覆盖墙本身）。
5. 若两条射线的绘制区域重叠（仅在同一区域内不同像素的正交射线交叉时发生），按源像素到其射线目标墙的曼哈顿距离决定优先级：距离更短（离墙更近）的射线覆盖距离更长的。距离相同时，行号更小的像素优先。
6. 非胜出区域的前景像素保持原样不变。灰(5)墙保持不变。

**关键洞察**：射线延伸操作的前提是密度竞胜——不执行计数就不知道哪些像素有权发射，而遮挡规则只在射线交叉时才需要，两者共同约束最终输出。

## 新题 3：角落对象掩码展开瓦片到对角

**组合逻辑**：[接触两边缘检测](已有) → [像素放大](创新：掩码来自角落对象而非独立精灵) → [平移到对角](创新：展开结果放置在对角线对侧角落)

**来源原语**：复制(copy) ← bc93ec48；角落对象(corner_object) ← bc93ec48；接触两边缘(touching_two_edges) ← bc93ec48；忽略干扰项(ignore_distractors) ← bc93ec48；像素放大(pixel_upscale) ← bf45cf4b；平铺(tile) ← bf45cf4b；控制精灵(control_sprite) ← bf45cf4b；多色瓦片(polychrome_tile) ← bf45cf4b；掩码映射(mask_mapping) ← bf45cf4b

**依赖链**：角落检测筛选出掩码对象（而非源题中直接给定的精灵）→ 每个角落对象作为二值掩码，其每个填充像素展开为瓦片副本 → 展开结果放置到对角线对侧的角落位置。角落身份同时决定了"用什么掩码"和"放到哪里"。

将每个锚定在网格角落的前景对象当作二值掩码，用中央瓦片模板展开放大，并将结果放置到对角线对侧的角落。

**输入结构**：约 20x20 的黑(0)背景网格。在网格中央偏上区域有一个 3x3 的多色瓦片（由 2~3 种非背景色组成，内部有固定图案）。在网格的 2~4 个角落各有一个单色前景对象（3~6 像素，4-连通），其边界框紧贴该角落的两条边缘。不同角落的对象颜色各异。网格边缘和内部可能散布少量孤立干扰像素（不接触任何角落的两条边缘）。生成约束：每个角落对象的边界框不超过 4x4，且展开后的结果（对象边界框高 x 瓦片高, 对象边界框宽 x 瓦片宽）不超过对角角落的可用空间。存在角落对象的角落恰好成对角分布（即若左上有则右下也有，若右上有则左下也有），保证对角放置不冲突。

**规则**：
1. 识别中央区域的 3x3 多色瓦片（唯一的多色 8-连通分量，与任何网格边缘距离 >= 3）。
2. 对每个前景 4-连通分量，判断其边界框是否同时接触网格的两条相邻边缘（即锚定在某个角落）。只有锚定在角落的对象参与后续步骤；其余为干扰项，保留不动。
3. 对每个角落对象，将其边界框内的像素视为二值掩码（非黑 = 1，黑 = 0）。
4. 按掩码展开：掩码中值为 1 的位置放置一份完整的 3x3 瓦片副本，值为 0 的位置放置 3x3 的黑(0)块。展开结果尺寸为（边界框行数 x 3）行 x（边界框列数 x 3）列。
5. 确定对角角落：左上 ↔ 右下，右上 ↔ 左下。将展开结果的边界框对齐到对角角落（例如左上角落对象的展开结果对齐到右下角落，使展开结果的右下像素与网格的右下像素重合）。
6. 展开结果覆盖目标区域的已有像素（包括该角落原有的对象像素）。原角落的对象像素不擦除（保留在原位）。中央瓦片在输出中移除（替换为黑(0)）。

**关键洞察**：角落检测既决定了哪个对象充当掩码（来自源题 bc93ec48 的筛选逻辑），又决定了展开结果的放置位置（对角映射），同一属性驱动两个不同决策——这种一属性双用途的结构在源题中不存在。

## 新题 4：压缩色带序列为瓦片调色板

**组合逻辑**：[压缩](已有) → [编码映射](创新：压缩产生的颜色序列成为像素放大的调色板) ← [像素放大](创新：每个掩码像素的颜色由序列位置决定)

**来源原语**：压缩(compress) ← 4be741c5；色带(color_band) ← 4be741c5；空间排列顺序(spatial_order) ← 4be741c5；行主色压缩单像素(row_majority_to_pixel) ← 4be741c5；像素放大(pixel_upscale) ← bf45cf4b；控制精灵(control_sprite) ← bf45cf4b；掩码映射(mask_mapping) ← bf45cf4b；编码映射(encoding_map) ← dfadab01

**依赖链**：色带压缩生成有序颜色序列 → 序列中第 k 个颜色赋给控制精灵中第 k 个填充像素（按阅读顺序） → 每个填充像素展开为以其赋色填充的方块。压缩结果是放大操作的输入参数（调色板），而非操作的数据对象——这构成参数级耦合。

将输入中色带区域压缩为颜色序列，用该序列依次为控制精灵的填充像素着色，然后将着色后的精灵像素放大为实心方块拼接输出。

**输入结构**：约 12x20 的黑(0)背景网格，被一条灰(5)垂直分隔线分为左右两半。左半部分被 3~5 种非背景色的水平色带完全覆盖（每种颜色占若干连续行，边界参差不齐但行主色明确）。右半部分包含一个灰(5)边框围成的小区域（约 5x5），内部有一个由白(未使用，此处用栗(9))单色绘制的控制精灵（3~5 个像素，4-连通，形状不规则），其余为黑(0)背景。生成约束：左半色带的颜色种类数恰好等于右半控制精灵中栗(9)填充像素的数量。

**规则**：
1. 识别灰(5)垂直分隔线，将网格分为左区（色带区）和右区（精灵区）。
2. 对左区逐行计算行主色（该行出现次数最多的颜色，忽略灰(5)），按从上到下顺序提取连续行主色变化点，得到有序颜色序列 C = [c1, c2, ..., ck]。
3. 在右区中找到栗(9)像素构成的控制精灵。按阅读顺序（从上到下、从左到右）对精灵的填充像素编号 1, 2, ..., k。
4. 将第 i 个填充像素的颜色从栗(9)替换为 C[i]。
5. 以精灵的边界框为掩码进行像素放大：每个填充像素展开为一个 3x3 的实心方块，颜色为该像素在步骤 4 中被赋予的颜色；每个黑(0)像素展开为 3x3 的黑(0)方块。
6. 输出仅包含展开结果（尺寸为精灵边界框行数 x 3, 精灵边界框列数 x 3），丢弃原始网格的其余部分。

**关键洞察**：色带压缩本身不产生视觉输出——它生成的颜色序列作为隐式参数注入像素放大操作，决定了每个展开方块的颜色。不执行压缩就无法确定放大后的配色。

## 新题 5：滑动标记激活门后定义描边边框

**组合逻辑**：[滑动](已有) + [擦除](已有) → [门前停止](已有) → [描边](创新：停止位置成为边框的极值标记) → [遮挡覆盖](创新：边框重叠时按路径长度决定优先级)

**来源原语**：滑动(slide) ← 182e5d0f；擦除(erase) ← 182e5d0f；路径(path) ← 182e5d0f；门结构(gate_motif) ← 182e5d0f；门前停止(stop_at_gate) ← 182e5d0f；描边(draw_frame) ← 928ad970；标记像素(marker_pixel) ← 928ad970；极值内缩定边框(frame_inset_from_extrema) ← 928ad970；遮挡覆盖(occlusion_overwrite) ← 13713586

**依赖链**：标记沿路径滑动到门前停止 → 停止位置成为新的标记点 → 每 4 个同色标记点的极值行列定义一个矩形边框 → 当边框重叠时，标记滑动路径更长的边框被路径更短的覆盖。滑动距离既是操作的副产品又是冲突解决的判据。

多组标记沿绿色路径滑动到各自的门前停止；停止后的位置充当边框描画的极值标记；当多个边框区域重叠时，滑动路径较短（离门较近）的边框覆盖路径较长的。

**输入结构**：约 18x18 的黑(0)背景网格。网格中有多条绿(3)路径（单像素宽，4-连通），每条路径一端连接一个非绿、非黑的彩色标记像素，另一端连接一个门结构（黑(0)-绿(3)-黑(0)的三像素直线段，方向与路径末端方向一致）。标记像素共有 2~3 种颜色，每种颜色恰好出现 4 个，每个标记连接独立的路径和门。路径长度（标记到门的绿色像素数）在 2~8 之间，同色的 4 个标记路径长度各不相同。生成约束：同色 4 个标记滑动到门前后，其停止位置的行列极值能定义一个至少 3x3 的矩形区域。不同颜色组定义的矩形区域至少有部分重叠。

**规则**：
1. 对每个彩色标记像素，沿其连接的绿(3)路径滑动：擦除路径上的绿色像素，标记最终停在与门结构中心相邻的路径像素位置（门前一格），记录该标记的滑动距离（经过的绿色像素数）。
2. 门结构（黑-绿-黑三像素段）保留不变。
3. 按颜色分组，每组 4 个同色标记的停止位置定义一组极值：min_row、max_row、min_col、max_col。
4. 对每组，在 (min_row+1, min_col+1) 到 (max_row-1, max_col-1) 的范围内画一个该颜色的单像素宽矩形边框（即从极值向内缩一格描边），与源题 928ad970 的描边逻辑相同。
5. 若两个不同颜色组的边框区域有像素重叠，按该组 4 个标记的平均滑动距离决定优先级：平均距离更短的组覆盖更长的组。平均距离相同时，标记颜色在输入中首次出现位置（按阅读顺序）更早的组优先。
6. 停止位置的标记像素保留在输出中。

**关键洞察**：滑动操作不仅移动标记，还产生了"滑动距离"这一副产品；该距离在后续边框重叠冲突中充当优先级判据。路径长度的信息在源题中被丢弃，在此题中被复用为遮挡规则的参数。

## 新题 8：形状频次决定字形替换类型

**组合逻辑**：[形状频次分组](已有) → [编码映射](创新：频次值映射到字形字典的键) → [图案印章](已有：用对应字形替换对象)

**依赖链**：先计算每个对象的规范形状（旋转/翻转不变）并统计各形状的出现频次 → 频次值作为键查找字形字典 → 用查到的字形替换该对象所在位置。形状分析不直接产生视觉变换，而是生成一个中间编码（频次数），该编码才是字形选择的决定因素。

**输入结构**：约 18x18 的黑(0)背景网格。网格分为两个区域：上方主区域包含 6~10 个单色小型前景对象（每个 3~6 像素，4-连通，形状不规则），不同对象可能颜色不同。下方用灰(5)水平线隔开的图例区域包含 2~4 个 4x4 字形示例，每个字形旁标注一个数字指示像素（用特定颜色的像素排列成 1~4 的点阵计数标记：1 个点 = 频次 1，2 个点 = 频次 2，以此类推），字形与点阵标记之间间隔 1 列。生成约束：上方主区域中各对象的规范形状（忽略旋转和翻转后的等价形状视为同一类）出现的频次值恰好都能在图例中找到对应字形。每种频次值对应图例中恰好一个字形。

**规则**：
1. 识别灰(5)水平分隔线，分离上方主区域和下方图例区域。
2. 在图例区域中，识别每个 4x4 字形及其右侧的点阵计数标记（标记中非黑像素的数量即为该字形对应的频次键）。建立映射：频次键 → 4x4 字形图案。
3. 在主区域中，对每个 4-连通前景对象计算其规范形状（将对象裁剪到边界框，生成二值掩码，取所有 4 种旋转 x 2 种翻转 = 8 种变换中字典序最小的作为规范形态）。
4. 统计每种规范形状在主区域中出现的次数（频次）。
5. 对每个前景对象，用其频次值查找字形字典，获得对应的 4x4 字形。
6. 将该 4x4 字形印在对象边界框左上角的位置（即以对象边界框的左上角为字形的左上角），超出网格边界的部分裁剪丢弃。若字形覆盖区域与其他对象的字形重叠，按对象边界框左上角的阅读顺序（先上后左）决定优先级，后处理的覆盖先处理的。
7. 原对象的像素被字形完全替换（先清除原对象，再印字形）。图例区域在输出中移除（替换为黑(0)），灰(5)分隔线也移除。

**关键洞察**：形状本身不决定输出——决定输出的是形状的出现频次。两个外观完全不同的对象若碰巧频次相同，会被替换为同一个字形；而外观相同的对象天然频次相同，也映射到同一字形。必须先完成全局形状统计才能执行局部替换。

## 新题 10：贯穿条方向引导色带压缩，压缩结果作为柱状图高度

**依赖链**：贯穿条的方向决定色带的压缩轴（正交于贯穿条）→ 压缩得到颜色序列 → 统计序列中每种颜色出现的段数（而非像素数）→ 以段数为柱高、按段数从多到少排列生成柱状图。贯穿条既是场景元素又是压缩方向的指令。

检测贯穿条方向以确定色带压缩轴，压缩后统计每种颜色的连续出现段数，以段数为高度按降序生成彩色柱状图。

**输入结构**：约 12x15 的网格，无统一背景色。网格大部分被 3~5 种颜色的色带覆盖（色带沿某一轴排列，边界参差不齐）。恰好有 1~2 条贯穿条（某单一颜色的完整行或完整列），贯穿条颜色与色带颜色之一相同。生成约束：色带沿行方向排列（即行主色分析有意义）当且仅当贯穿条为完整列（即贯穿条方向与色带方向正交）。每种色带颜色在压缩序列中至少出现 1 段，最多出现 3 段，且各颜色的段数互不相同。贯穿条颜色在色带中也有出现。

2. 沿贯穿条的正交方向压缩色带：
   - 若贯穿条为垂直列，则色带沿水平方向排列；逐行取行主色（忽略贯穿条所在列），提取从上到下的主色变化序列。
   - 若贯穿条为水平行，则色带沿垂直方向排列；逐列取列主色（忽略贯穿条所在行），提取从左到右的主色变化序列。

4. 生成柱状图输出：
   - 按段数从大到小排列颜色（段数最多的在最左列）。
   - 输出网格宽度 = 颜色种类数，高度 = 最大段数。
   - 每列从顶部开始向下填充该颜色，填充格数 = 该颜色的段数，其余格为黑(0)。

**关键洞察**：柱状图的高度不是简单的像素计数或边界框高度——而是色带在压缩序列中的"碎片化程度"（段数）。一种颜色即使总面积很大，如果连续集中在一起（1 段），柱高也只有 1；反之面积小但分散出现多段的颜色柱高更高。必须先正确压缩才能计算段数。
