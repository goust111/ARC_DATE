## 新题 1：原型匹配驱动的选择性边界内推

**组合逻辑**：[模式匹配pattern_match](创新：匹配结果决定对象存亡) + [平移translate](创新：仅对贴边且匹配的对象执行内推) + [重涂色recolor](已有) + [擦除erase](已有)

**来源原语**：模式匹配、原型 ← d94c3b52；平移、贴边定位、重复色才移动 ← 22208ba4；擦除 ← 多题共有；邻接接触 ← 48d8fb45

**依赖链**：模式匹配将所有精灵体分为"匹配"与"不匹配"两组 → 匹配组内再按是否贴边分流：贴边者执行内推平移并重涂色，非贴边者原地重涂色 → 不匹配组全部擦除。三个判断节点紧密嵌套，缺任一则输出不确定。

在参考题中，22208ba4 用"颜色是否重复"来决定哪些对象移动；d94c3b52 用形状匹配来决定重涂色。本题将两者交织：形状匹配决定存亡，边界位置决定是否移动，两个条件共同决定最终输出——这种"匹配 x 位置"的二维决策在任一参考题中均不存在。

根据精灵体形状和位置的双重条件，保留匹配原型的精灵体（贴边者内推，非贴边者留原位），擦除不匹配者。

**输入结构**：约 14x14 的网格，黑(0)背景。网格中包含：
- 一个青(8)色的"原型"精灵体（4-连通，3~6 像素，形状不规则，无特定对称性），位于网格内部（不接触任何边界）。
- 4~6 个其他颜色（红(2)、绿(3)、黄(4)、蓝(1)等，各不相同）的精灵体，每个也是 4-连通、3~6 像素。其中部分精灵体的形状掩码（忽略颜色后的像素图案）与青色原型完全一致，其余则不一致。
- 匹配与不匹配的精灵体混合分布：部分接触网格边界（至少有一个像素位于第 0 行、最后一行、第 0 列或最后一列），部分完全位于网格内部。
- 生成约束：每个精灵体的边界框互不重叠；至少有一个匹配且贴边的精灵体和一个匹配且非贴边的精灵体；至少有一个不匹配的精灵体。

**规则**：
1. 以青(8)原型精灵体的形状掩码为模板，逐一检查每个非原型精灵体：将其像素图案（忽略颜色，仅看"前景/背景"）与原型掩码比较，完全一致则标记为"匹配"。匹配判断不考虑旋转或翻转——必须在原始朝向下完全一致。
2. 所有"不匹配"的精灵体从网格上擦除为黑(0)。
3. 对于"匹配"的精灵体，检查其是否贴边（至少一个像素触及网格的行边界或列边界）：
   - 贴边者：将其沿垂直于所触边界的方向平移，平移距离等于其边界框在该方向上的尺寸（若同时触及两条边界，则沿两个方向各平移一次）。平移后将其重涂为青(8)。原位置擦除为黑(0)。
   - 非贴边者：原地保留，将颜色重涂为青(8)。
4. 青色原型精灵体本身保持不变。
5. 若平移后的精灵体与其他保留的精灵体（含原型）重叠，平移副本的像素覆盖已有像素。

**关键洞察**：选择标准是"形状匹配"而非"颜色重复"——必须对比多个示例才能排除"颜色相同的存活"这一更显然的假设。贴边状态进一步分流匹配者的处理方式，形成二维决策矩阵。

## 新题 2：邻接标记着色的矩形框填充与面积优先级冲突解决

**组合逻辑**：[填充fill](创新：填充色由外部邻接标记决定) + [计数counting](创新：面积计数用于冲突解决) + [擦除erase](已有)

**来源原语**：填充、空心矩形框、标记像素、标记相对方位 ← 94414823；邻接接触、标记选中邻接体 ← 48d8fb45；计数 ← dc2aa30b / ae58858e

**依赖链**：邻接关系将标记分配给矩形框 → 标记颜色决定该框的填充色 → 当两个框的内部区域在空间上重叠时，各框面积的大小关系决定重叠区域的最终颜色。三步环环相扣：没有邻接分配就不知道填什么颜色；没有面积比较就无法解决重叠冲突。

在 94414823 中，标记的方位决定象限分配，不涉及多框重叠；在 48d8fb45 中，标记选中邻接体后直接裁剪输出。本题将"邻接选择"用于颜色传递，并引入面积比较作为冲突解决规则——标记、填充、面积三者构成源题中不存在的决策链。

根据外部标记的邻接关系确定每个矩形框的填充色，重叠区域按框内面积小者优先的规则着色。

**输入结构**：约 14x14 的网格，灰(5)背景。网格中包含：
- 2~3 个空心矩形框，由蓝(1)像素构成，边框宽度恰好 1 像素，内部为灰(5)背景色。框的尺寸不一（内部面积各不相同，最小 3x3，最大 6x6）。
- 部分矩形框的边框在空间上交叉或重叠（边框像素可以共享，内部区域可以部分重叠）。
- 每个矩形框的外侧恰好有一个单像素标记，标记与该框的某一条边的某个像素 4-邻接。不同框的标记颜色互不相同，取自 {红(2), 绿(3), 黄(4)}。标记不会与两个框同时邻接。
- 生成约束：至少一对矩形框的内部区域存在重叠；每个标记恰好与一个矩形框的边框邻接。

**规则**：
1. 对每个单像素标记，找到与其 4-邻接的蓝(1)矩形框边框，将该标记的颜色指定为该框的"填充色"。
2. 用指定的填充色填满每个矩形框的内部区域（原本为灰(5)的所有像素）。蓝(1)边框像素保持不变。
3. 若两个矩形框的内部区域在空间上重叠（同一像素同时属于两个框的内部），则该像素着内部面积较小的框的填充色。面积定义为该框内部灰(5)像素的总数（未填充前）。生成约束保证不存在面积相同的两个框。
4. 擦除所有标记像素为灰(5)背景色。

**关键洞察**：重叠区域的颜色不是由绘制顺序或位置决定，而是由框内面积的相对大小决定——小框优先。此规则无法从不包含重叠的示例中推断，必须对比有重叠和无重叠的示例才能归纳。

## 新题 3：旋转对称阶数驱动的瓦片重排

**组合逻辑**：[旋转rotate](创新：用于分析对称性而非执行几何变换) + [排序sorting](创新：排序键为旋转对称阶数) + [重排rearrange](已有) + [计数counting](创新：作为同阶瓦片的排序副键)

**来源原语**：排序、重排、瓦片、分隔线、阵列排布、前景数决定排序 ← dc2aa30b；旋转、旋转族成员 ← be03b35f；计数 ← ae58858e

**依赖链**：旋转分析确定每个瓦片的对称阶数（主排序键） → 同阶瓦片之间用前景像素计数作为副键打破平局 → 双键排序结果决定瓦片在网格中的最终位置。旋转分析不产生新图形，但其结果是排序的唯一依据——跳过分析则排序无据；跳过计数则同阶平局无法解决。

dc2aa30b 中排序键是蓝色像素计数（直接可见的属性），本题排序键是旋转对称阶数（需要对每个瓦片执行心理旋转才能判断的导出属性）。计数仅作副键出现，角色完全不同于源题。

按旋转对称阶数从高到低重排所有瓦片，同阶则按前景像素数从少到多排列。

**输入结构**：11x11 的网格。由 2 条单像素黑(0)分隔行和 2 条单像素黑(0)分隔列将网格分为 3x3 共 9 个瓦片，每个瓦片为 3x3。分隔行位于第 3 行和第 7 行，分隔列位于第 3 列和第 7 列。每个 3x3 瓦片在黑(0)背景上有一种前景色（统一使用红(2)）构成的图案，每个瓦片的前景像素数在 1~8 之间。
- 9 个瓦片的图案各不相同。
- 旋转对称阶数分布：至少包含阶数 4（90 度不变）、阶数 2（180 度不变但 90 度会变）、阶数 1（无旋转对称）各至少一个瓦片。
- 生成约束：同一对称阶数内，各瓦片的前景像素数互不相同。

**规则**：
1. 对每个 3x3 瓦片，判断其旋转对称阶数：
   - 阶数 4：图案在顺时针旋转 90 度后与自身完全一致（也意味着 180 度和 270 度均不变）。
   - 阶数 2：图案在旋转 180 度后与自身一致，但旋转 90 度后不一致。
   - 阶数 1：旋转 90 度和 180 度后均与自身不一致。
2. 主排序键：旋转对称阶数从高到低（4 > 2 > 1）。
3. 副排序键（仅在同阶时使用）：前景像素数从少到多。
4. 将排序后的 9 个瓦片按顺序放入 3x3 槽位中：从左上到右下，逐行从左到右。排第 1 名的瓦片进左上槽位，排第 9 名的瓦片进右下槽位。瓦片内部图案不做任何修改。

**关键洞察**：排序键不是任何直接可见的像素属性，而是需要对每个瓦片做旋转变换后比较才能确定的几何不变量。必须对比多个示例（不同瓦片在不同位置）才能排除"按像素数排序"或"按原始位置排序"等更简单的假设。

## 新题 4：交替翻转与换色的循环母题填充

**组合逻辑**：[循环填充cyclic_fill](已有) + [镜像reflect](创新：按奇偶交替执行水平翻转) + [重涂色recolor](创新：与翻转同步的颜色交换)

**来源原语**：循环填充、标记列、母题行、标记界定母题、循环重复 ← 12422b43；镜像、对角对称 ← 9dfd6313；列奇偶交替、奇偶决定交换 ← e9afcf9a；重涂色 ← 多题共有

**依赖链**：标记界定母题高度（行数）→ 母题循环填充空白后缀区 → 每次重复时，奇偶性同时门控两个变换：水平镜像和双色交换。三个操作被奇偶性耦合为一体——若只翻转不换色，或只换色不翻转，输出都不正确。

12422b43 中循环填充是精确重复；9dfd6313 中镜像是对整个网格做一次性转置；e9afcf9a 中奇偶交替作用于列而非重复周期。本题将三者统一到"每个循环周期"这一维度上：每次重复同时受奇偶门控翻转和换色，产生视觉上的"锯齿编织"效果——任一源题中都不存在这种周期性双变换。

将标记界定的双色母题循环向下填充空白区，每个奇数周期同时执行水平翻转和双色交换。

**输入结构**：约 10x15 的网格（10 列、15 行），黑(0)背景。
- 最左列（第 0 列）的前 K 行（K 在 2~4 之间）为灰(5)像素，标记母题行的范围。第 K 行及以下的第 0 列为黑(0)。
- 母题行（第 0 行到第 K-1 行，第 1 列到最右列）包含一个由恰好两种非黑非灰前景色（如红(2)和蓝(1)）构成的图案。图案不具有水平对称性（左右翻转后与原图不同），且两种颜色的像素数量不必相等。
- 从母题行下方开始到网格底部，所有像素（含第 0 列）为黑(0)，即空白后缀区。空白后缀区的行数至少为 3K（可容纳至少 3 次完整的母题重复）。
- 生成约束：母题图案左右翻转后与原图在至少一个像素位置不同；母题中两种颜色的像素位置集合交换后与原图在至少一个位置不同。

**规则**：
1. 提取母题：取第 0 行到第 K-1 行、第 1 列到最右列的子网格作为母题模板。模板中第 0 列的灰(5)标记像素替换为黑(0)。
2. 原始母题行保持不变（灰(5)标记被替换为黑(0)，其余不动），作为"第 1 次重复"（偶数，序号从 1 开始）。
3. 从空白后缀区的起始行开始，逐次将母题模板写入：
   - 偶数次重复（第 2、4、6...次）：将母题模板原样写入（与第 1 次相同）。
   - 奇数次重复（第 3、5、7...次）：先将母题模板水平翻转（每行像素左右镜像），再将模板中的两种前景色互换（所有红(2)变蓝(1)，所有蓝(1)变红(2)），然后写入。
4. 若空白后缀区剩余行数不足一个完整母题高度，则写入能容纳的部分行（从母题顶部开始截取），翻转/换色规则与该次重复的奇偶性一致。
5. 空白后缀区的第 0 列始终为黑(0)。

**关键洞察**：翻转和换色始终同步发生（同为奇数次时触发），缺一不可。仅凭一个周期无法判断是"仅翻转""仅换色"还是"双变换"——需要观察至少两个完整周期来确认二者绑定。

## 新题 5：前景密度排序决定图层优先级的面板叠加

**组合逻辑**：[透明叠加transparent_overlay](创新：图层顺序由计算结果动态决定) + [计数counting](创新：前景计数用于确定图层排序) + [排序sorting](隐式：计数结果排序后映射为图层优先级)

**来源原语**：透明叠加、面板、分隔列、图层优先级 ← 281123b4；排序、计数、前景数决定排序 ← dc2aa30b；逐像素对齐 ← d19f7514

**依赖链**：计数各面板的前景像素数 → 排序产生图层优先级排名 → 优先级决定叠加时每个位置哪个面板的颜色胜出。计数是排序的输入，排序是叠加的参数——三者形成不可跳步的链条。

281123b4 中图层优先级由固定的循环位置序决定（第三面板最前，然后第四、第一、第二），与面板内容无关。本题将优先级改为数据驱动：前景像素最少的面板位于最前层（因为它遮挡最少，效果上等于"最稀疏的在前"）。解题者必须同时计算、排序、叠加，而非套用固定规则。

计算每个面板的前景像素数，按数量从少到多确定图层优先级（最少的在最前），然后将所有面板透明叠加为一个输出。

**输入结构**：4 行 x 19 列的网格。由 3 条单列黑(0)分隔列将网格分为 4 个 4x4 面板。分隔列位于第 4、9、14 列。
- 每个面板在黑(0)背景上有恰好一种前景色（四个面板的前景色互不相同，取自 {红(2), 绿(3), 蓝(1), 黄(4)}）。
- 每个面板的前景像素数互不相同（在 2~10 之间）。
- 四个面板的前景图案在对齐后存在位置重叠（至少有 2 个位置被两个以上面板的前景同时占据）。
- 黑(0)像素视为透明。

**规则**：
1. 统计每个面板中非黑前景像素的总数。
2. 按前景像素数从少到多排列四个面板，得到图层优先级：像素最少的面板为最前层（优先级最高），最多的为最后层。
3. 将四个面板逐像素对齐叠加：对于输出中的每个位置(r, c)，从最前层到最后层依次检查，输出第一个在该位置有非黑前景的面板的颜色；若所有面板在该位置均为黑(0)，则输出黑(0)。
4. 输出为单个 4x4 网格。

**关键洞察**：图层优先级不是按面板在输入中的位置（从左到右或某种循环序）决定的，而是按前景密度决定——最稀疏的面板最"靠前"。这一规则无法从单个示例推断，因为任何固定的位置序都可能碰巧与密度序一致；只有对比多个示例（面板位置不变但密度排名变化时图层结果不同）才能发现。

## 新题 6：标记位置编码的对角线选择性补全

**组合逻辑**：[对称补全symmetry_completion](创新：补全轴和源侧均由标记编码) + [镜像reflect](创新：沿主对角线或反对角线翻转) + [擦除erase](已有) + [逐色处理per_color_processing](已有)

**来源原语**：对称补全、逐色处理 ← 8e5c0c38；镜像、对角对称、沿主对角线转置 ← 9dfd6313；标记像素、标记相对方位 ← 94414823；擦除 ← 多题共有

**依赖链**：标记的位置同时编码两个信息——选用哪条对角线为轴、信任哪一侧为源 → 逐色独立地将源侧图案沿选定对角线反射到另一侧 → 擦除标记。标记位置是对称补全的全部参数来源；没有标记就无法确定轴和源，没有逐色处理则多色图案会混淆。

8e5c0c38 中对称轴是垂直线，且每个色层自己决定轴位置；9dfd6313 中对角线是固定的主对角线，做一次完整转置。本题将对角线选择权交给外部标记——标记所在象限同时编码"主/反对角线"和"源侧"，将原本隐式的轴变为显式编码的参数。这种"标记作为指令"的模式在源题中不存在。

根据灰色标记的位置确定对角线轴和源侧，然后逐色将源侧图案反射补全到另一侧。

**输入结构**：NxN 的方阵网格（N 在 7~11 之间，奇数），黑(0)背景。
- 网格中有一个由 2~3 种非黑非灰颜色（如红(2)、蓝(1)、绿(3)）构成的图案。图案大致分布在网格的某一侧（相对于某条对角线），但在另一侧有少量像素缺失（即图案本应沿某条对角线对称，但对称位置上有些像素是黑(0)）。
- 恰好一个灰(5)单像素标记，位于网格中（不在任何对角线上）。标记的位置决定规则参数：
  - 标记位于主对角线上方（行号 < 列号）→ 使用主对角线（从左上到右下）为对称轴，上方为源。
  - 标记位于主对角线下方（行号 > 列号）→ 使用主对角线为对称轴，下方为源。
  - 标记位于反对角线上方（行号 < N-1-列号）→ 使用反对角线（从右上到左下）为对称轴，上方为源。
  - 标记位于反对角线下方（行号 > N-1-列号）→ 使用反对角线为对称轴，下方为源。
- 生成约束：标记位置明确属于上述四种情况之一（不在任何对角线上，也不在两条对角线的交叉象限边界上）。源侧的图案是完整的（所有应有的像素都存在），另一侧有像素缺失。

**规则**：
1. 读取灰(5)标记的坐标 (r_m, c_m)，判断其所在区域以确定对称轴和源侧（见输入结构中的四种情况）。
2. 对每种非黑非灰前景色独立执行以下操作：
   - 遍历源侧中该颜色的每个像素 (r, c)。
   - 计算其关于选定对角线的对称位置 (r', c')：
     - 主对角线：(r', c') = (c, r)。
     - 反对角线：(r', c') = (N-1-c, N-1-r)。
   - 若 (r', c') 当前为黑(0)，则填入该颜色。若 (r', c') 已有其他非黑颜色，保持不变（源侧数据优先）。
3. 擦除灰(5)标记像素为黑(0)。
4. 源侧的已有像素保持不变。

**关键洞察**：灰色标记不是装饰——它同时编码了两个参数（轴选择 + 源侧选择）。求解者需要对比至少两个示例（标记在不同象限）才能确定标记位置与对称轴的映射关系，排除"总是用主对角线"或"总是以上方为源"等简化假设。

## 新题 7：角落位置参数化旋转的精灵体印章覆盖

**组合逻辑**：[印章覆盖stamp_overlay](创新：印章内容是中心精灵体而非固定模板) + [旋转rotate](创新：旋转角度由角落位置编码) + [裁剪crop](已有) + [重涂色recolor](创新：标记颜色传递给旋转后的印章)

**来源原语**：印章覆盖、角落标记、角落位置选模板、标记色传递给模板 ← fd02da9e；旋转、旋转族成员 ← be03b35f；裁剪、精灵体 ← 28bf18c6；重涂色 ← 多题共有

**依赖链**：裁剪中心精灵体得到印章模板 → 角落位置编码旋转角度 → 旋转后的模板以标记颜色着色 → 放置在角落附近。四步紧密耦合：模板来自裁剪，旋转来自位置编码，颜色来自标记，位置来自角落。

fd02da9e 中每个角落选择不同的固定模板（预设的形状），标记颜色传递给该模板。本题中所有角落使用同一形状（中心精灵体），但每个角落的旋转角度不同——形状不变、变换变。这从"角落选模板"变成了"角落选旋转"，将选择对象从离散模板库改为连续变换空间中的离散采样点。

将中心精灵体按角落位置编码的旋转角度旋转后，以角落标记的颜色印章到各角落附近。

**输入结构**：12x12 的网格，黑(0)背景。
- 网格中心区域（大约第 4~7 行、第 4~7 列）有一个多色精灵体（使用 2 种非黑颜色，如红(2)和蓝(1)），4-连通，占据约 4~8 像素，边界框为 3x3 或 4x4。精灵体的形状在 90 度旋转下与自身不同（不具备 4 阶旋转对称）。

- 其余角落位置为黑(0)（无标记）。
- 生成约束：中心精灵体的边界框在任何旋转下印章到角落后不会超出网格边界，也不会与中心精灵体重叠。

**规则**：
1. 裁剪中心精灵体的边界框，得到一个 HxW 的模板（包含精灵体像素和边界框内的黑色背景像素）。
2. 对每个有标记的角落，根据角落位置确定旋转角度：
   - 左上角 (0,0)：不旋转（0 度）。
   - 右上角 (0,11)：顺时针旋转 90 度。
   - 右下角 (11,11)：旋转 180 度。
   - 左下角 (11,0)：顺时针旋转 270 度。
3. 将裁剪的模板按确定的角度旋转。
4. 将旋转后模板中所有非黑前景像素统一重涂为该角落标记的颜色。
5. 将重涂后的模板放置在角落附近：模板的边界框角与网格角之间留 1 像素间隔。具体地：
   - 左上角：模板左上角放在 (1, 1)。
   - 右上角：模板右上角放在 (1, 10)。
   - 右下角：模板右下角放在 (10, 10)。
   - 左下角：模板左下角放在 (10, 1)。
6. 擦除角落标记像素为黑(0)。中心精灵体保持原样不变。
7. 若印章副本之间不会重叠（由生成约束保证）。

**关键洞察**：所有角落使用同一个精灵体形状——差异仅在旋转角度。角落位置与旋转角度的映射关系（左上=0度，顺时针递增90度）必须通过对比多个示例中不同角落的印章朝向才能归纳。仅看一个角落的示例无法区分"固定模板"和"旋转模板"两种假设。

## 新题 8：精灵体对称性编码矩形框填充图案

**组合逻辑**：[填充fill](创新：填充图案由另一对象的几何属性决定) + [对称补全symmetry_completion 的逆用 → 对称性分析](创新：分析对称性作为分类依据而非执行补全) + [擦除erase](已有) + [裁剪crop](隐式：读取框内精灵体)

**来源原语**：填充、空心矩形框 ← 94414823；对称补全、对称轴 ← 8e5c0c38；棋盘格图案、列奇偶交替 ← e9afcf9a；擦除 ← 多题共有；连通分量 ← ae58858e

**依赖链**：分析框内精灵体的对称类型 → 对称类型映射为特定填充图案 → 用精灵体颜色执行填充并擦除精灵体。对称分析是分类器，填充是执行器——没有分析就不知道填什么图案，没有精灵体颜色就不知道用什么颜色填。

94414823 中填充图案由外部标记的方位决定（象限分配）；8e5c0c38 中对称性分析用于去噪（删除不对称的像素）。本题将对称性分析的输出从"去噪动作"改为"分类信号"，用于选择完全不同的填充模式——对称性不再直接修改图案，而是作为元信息指导另一操作。这种"几何属性作为指令"的间接编码在源题中不存在。

分析矩形框内小型精灵体的对称类型，据此选择框内区域的填充图案（条纹或棋盘），用精灵体的颜色着色。

**输入结构**：约 12x12 的网格，黑(0)背景。包含 2~3 个空心矩形框，每个由蓝(1)像素构成，边框宽 1 像素，内部面积至少 4x4。各框互不重叠且互不相邻。
- 每个框的内部正中央有一个小型单色精灵体（4-连通，3~6 像素），颜色各不相同，取自 {红(2), 绿(3), 黄(4)}。精灵体不接触框的边框。
- 每个精灵体具有以下三种对称类型之一（不同框内的精灵体可以是不同类型）：
  - 仅有垂直对称轴（左右对称，上下不对称）。
  - 仅有水平对称轴（上下对称，左右不对称）。
  - 同时有垂直和水平对称轴。
- 生成约束：不出现无任何对称轴的精灵体；每个示例中至少包含两种不同的对称类型。

**规则**：
1. 对每个矩形框，分析其内部精灵体的对称类型：
   - 仅垂直对称：将框的整个内部区域（含精灵体原本占据的位置）填充为垂直条纹图案——从内部区域的最左列开始，奇数列（第 0、2、4...列，相对于内部区域左边界）填该精灵体的颜色，偶数列（第 1、3、5...列）保持黑(0)。
   - 仅水平对称：将内部区域填充为水平条纹图案——从内部区域的最上行开始，奇数行（第 0、2、4...行，相对于内部区域上边界）填该精灵体的颜色，偶数行保持黑(0)。
   - 垂直+水平对称：将内部区域填充为棋盘格图案——位置 (r, c)（相对于内部区域左上角）满足 (r + c) 为偶数时填该精灵体的颜色，为奇数时保持黑(0)。
2. 填充覆盖精灵体原有像素（精灵体被填充图案取代）。
3. 蓝(1)矩形框边框保持不变。框外的黑(0)背景保持不变。

**关键洞察**：精灵体本身不是输出的一部分——它的几何对称性是一条隐式指令，编码了应当使用哪种填充图案。求解者必须从多个示例中发现"对称类型→填充图案"的映射关系：仅看一个全是垂直对称的示例会误以为所有框都填垂直条纹。
