## 新题 1：尾部长度编码图层优先级的矩形恢复

**组合逻辑**：[occlusion_restore](已有) → [tail_vector → priority_encoder](创新：尾部长度不再编码位移，而是编码图层优先级) → [fill/interior_region](已有) → [conflict_priority](已有，但优先级键来自尾部长度)

**来源原语**：occlusion_restore / tail_vector / tail_displacement (c6e1b8da), fill / interior_region / border / keep_border_fill_in (e88171ec), conflict_priority (9344f635)

**依赖链**：尾部向量的长度决定了图层优先级 → 优先级决定了遮挡恢复后矩形的绘制顺序 → 绘制顺序决定了重叠区域显示哪个矩形的内部填充。删去尾部长度语义，就无法确定图层顺序；删去遮挡恢复，就不知道矩形的完整范围；删去内部填充，就无法区分哪些像素来自哪个矩形。

恢复所有被遮挡的矩形，按尾部长度排出图层顺序后，由短尾（高优先级）矩形覆盖长尾（低优先级）矩形，并将各矩形内部填充为统一颜色。

**输入结构**：约 14x14 的黑(0)背景网格。包含 3-4 个不同颜色的实心矩形（取自蓝(1)、红(2)、绿(3)、黄(4)），每个矩形至少 4x4。部分矩形相互重叠（一个颜色遮住另一个的局部）。每个矩形从其某一条边向外延伸出一条同色的、一像素宽的直线尾部，长度在 1-4 像素之间，各矩形的尾部长度互不相同。生成约束：每个矩形的完整范围（不计遮挡）至少 4x4，使其内部严格内部区域非空；尾部不与其他矩形的主体或尾部接触。

**规则**：
1. 识别每个矩形及其尾部。尾部与矩形某一条边连续，宽度为一像素，沿基数方向延伸。
2. 恢复每个矩形的完整边界框范围——将被其他矩形遮挡的像素恢复为该矩形的颜色。
3. 擦除所有尾部像素（置为背景色黑(0)）。
4. 计算各矩形的图层优先级：尾部越短，优先级越高（越后绘制，在最上层）。
5. 按优先级从低到高（尾部最长者先绘制，最短者最后绘制）逐个绘制矩形。每个矩形的绘制方式为：外围一像素边框保持原色，严格内部像素填充为灰(5)。
6. 后绘制的矩形在重叠区域覆盖先绘制的矩形。

**关键洞察**：尾部看上去是位移向量（如参考题 c6e1b8da），但实际上是图层优先级编码器——长度编码"谁在上面"。必须对比多个示例中不同尾部长度与不同重叠结果的对应关系，才能归纳出"短尾在上"的规则。

## 新题 2：菱形容器中的重力下落

**组合逻辑**：[diamond_frame](已有) → [area_determines_role](已有) → [gravity_drop](已有，但容器从矩形网格改为菱形) → [stop_at_blocker](已有) → [collision_stop](已有)

**来源原语**：diamond_frame / fill_inside_frame / stop_at_blocker (95755ff2), gravity_drop / area_determines_role / stop_at_bottom (6ca952ad), collision_stop (11dc524f)

**依赖链**：菱形框定义了非矩形的重力容器边界 → 面积区分移动者与阻挡者 → 重力驱动移动者下落，但停止条件同时依赖菱形边界（V 形底部）和阻挡像素 → 移动者之间按初始高度排序处理以避免穿越。删去菱形框，重力问题退化为普通矩形下落；删去面积区分，无法判断谁该移动；删去碰撞停止，对象会穿越彼此。

将菱形框内的多像素对象向下做重力下落，单像素阻挡物固定不动；对象遇到菱形斜边、阻挡物或已落定的其他对象时停止。

**输入结构**：约 17x17 的黑(0)背景网格。中央有一个完整的一像素厚菱形框，颜色为红(2)，菱形的四个顶点分别位于网格上下左右边界附近。菱形内部有 2-3 个不同颜色的 4-连通对象（取自蓝(1)、绿(3)、黄(4)），每个对象 3-6 像素，形状不规则（非矩形），初始位于菱形内部的上半区域。菱形内部还有 1-2 个灰(5)单像素作为固定阻挡物。生成约束：初始时所有对象和阻挡物互不接触，且均严格位于菱形内部（不触碰菱形框）。

**规则**：
1. 菱形内部的单像素灰(5)对象为固定阻挡物，永不移动。
2. 菱形内部面积 >= 3 的多像素彩色对象为"下落体"。
3. 将每个下落体逐行向下平移。下落体在以下任一条件满足时停止：(a) 其任一像素的下一行位置落在菱形框上或菱形外部；(b) 其任一像素的下一行位置是阻挡物；(c) 其任一像素的下一行位置已被另一个已落定的下落体占据。
4. 处理顺序：按下落体最低像素的行坐标从大到小（最靠近底部的先处理），保证先落定的不被后处理的穿越。
5. 所有下落体落定后，菱形框、阻挡物和落定对象保持各自颜色；菱形内部未被占据的像素仍为黑(0)。

**关键洞察**：菱形的 V 形底部使"地面"随水平位置变化——中央列可下落最远，侧边列很快就被斜边拦住。同样的重力规则因容器几何而产生非对称的落定格局，需要对比多个示例才能确认容器形状而非对象属性决定最终位置。

## 新题 3：多标记方向编码镜像轴的精灵反射

**组合逻辑**：[micro_marker/domino](已有) → [orientation_determines_direction → orientation_determines_mirror_axis](创新：朝向不再决定行/列涂色方向，而是决定镜像反射轴) → [mirror](已有) → [recolor](已有)

**来源原语**：micro_marker / orientation_determines_direction (9344f635), mirror / contact_edge_align (11dc524f), recolor (604001fa), erase (604001fa)

**依赖链**：多米诺的朝向决定了镜像轴的类型（水平朝向→垂直轴，竖直朝向→水平轴）→ 多米诺的位置决定了轴的坐标 → 镜像操作依赖轴的类型和位置生成反射副本 → 反射副本使用新颜色绘制。删去朝向解读，就不知道做哪种反射；删去镜像操作，就无法生成副本；删去重涂色，就无法在视觉上区分原件与副本。

每个精灵旁的多米诺标记编码了该精灵的反射轴——水平多米诺意味着左右翻转，竖直多米诺意味着上下翻转。

**输入结构**：约 13x13 的黑(0)背景网格。包含 2-3 个不同颜色的 4-连通精灵体（取自蓝(1)、绿(3)、黄(4)），每个精灵 3-7 像素，形状不规则且非对称（使镜像结果可见差异）。每个精灵有且仅有一个与之 4-邻接（共享至少一条边）的红(2)多米诺标记——由两个红(2)像素组成的水平对（同行相邻两列）或竖直对（同列相邻两行）。各多米诺之间互不接触，也不与非对应的精灵接触。生成约束：每个精灵的反射副本（按下述规则生成）完全在网格内且不与其他精灵、副本或多米诺重叠。

**规则**：
1. 为每个精灵找到其唯一的 4-邻接红(2)多米诺。
2. 若多米诺为水平对（两像素同行），则镜像轴为竖直线，通过多米诺两像素列坐标的中点（即两列的算术平均值）。
3. 若多米诺为竖直对（两像素同列），则镜像轴为水平线，通过多米诺两像素行坐标的中点。
4. 将精灵的每个像素关于该轴做反射，生成镜像副本。副本颜色统一为橙(7)。
5. 擦除所有多米诺像素（置为黑(0)）。
6. 原精灵保持其原色不变。

**关键洞察**：水平排列的多米诺触发的是竖直轴反射（左右翻转），这与直觉（水平→水平操作）相反。必须对比包含不同朝向多米诺的多个示例，才能归纳出"朝向与反射轴垂直"的规则。

## 新题 4：形状匹配验证 + 行控制色赋色

**组合逻辑**：[shape_matching / normalized_shape_matching](已有，但作用从"决定颜色"变为"验证合法性") → [per_row_color / row_control_color](已有，但从直接替换灰色变为替换经验证的占位符) → [recolor](已有) + [erase](已有)

**来源原语**：shape_matching / normalized_shape_matching / placeholder_object / template_object (2a5f8217), recolor / per_row_color / row_control_color / placeholder_pixel (c7d4e6ad), erase (604001fa)

**依赖链**：形状匹配判断占位符是否合法 → 仅合法占位符才有资格接受颜色赋值 → 行控制色提供实际输出颜色（而非匹配到的模板颜色） → 不合法占位符被擦除。删去形状匹配，就无法过滤不合法占位符（所有占位符都会被涂色，产生错误输出）；删去行控制色，就只能用模板颜色（参考题 2a5f8217 的做法），但这里模板颜色是干扰项。

占位符通过形状匹配获得合法性确认后，并不继承模板颜色，而是从同行控制列获取真正的输出颜色。

**输入结构**：约 15x15 的黑(0)背景网格。右侧一列为控制列，包含若干单像素控制色（取自绿(3)、黄(4)、红(2)等），在不同行各一个，所在行对应各"颜色区"。网格中部有 2-3 个蓝(1)占位符对象（4-连通，3-8 像素，形状各异）。网格左侧有 2-3 个彩色模板对象（取自绿(3)、黄(4)、橙(7)），每个模板具有唯一的归一化形状掩码。模板数量等于占位符数量；每个占位符的归一化掩码恰好匹配一个模板。每个占位符最高像素所在行恰好有一个控制列像素。生成约束：不同控制像素不在同一行；每个占位符的最高行对应一个控制像素。

**规则**：
1. 对每个对象，提取其边界框内的 4-连通像素掩码作为归一化形状。
2. 对每个蓝(1)占位符，在所有非蓝模板中查找归一化形状相同的唯一模板。
3. 若匹配存在：找到占位符最高像素所在行的控制列像素，将整个占位符重涂为该控制像素的颜色（而非匹配模板的颜色）。
4. 若匹配不存在：擦除该占位符（所有像素置为黑(0)）。
5. 模板对象和控制像素保持不变。

**关键洞察**：形状匹配仅充当"身份验证"——只有通过验证的占位符才能获得颜色，但颜色来源不是匹配的模板（模板颜色是干扰项），而是完全独立的行控制列。需要对比多个示例中模板颜色与实际输出颜色的不一致，才能发现真正的颜色来源。

## 新题 5：射线投票决定矩形框内填充色

**组合逻辑**：[ray_extend](已有) → [counting](已有，但对象从像素集变为射线穿越区域的覆盖面积) → [fill / interior_region](已有) → [stop_at_blocker](已有，但阻挡物在框内部而非射线源端)

**来源原语**：ray_extend / side_marker / blocker_pixel / stop_at_blocker (95755ff2), counting / area_matching (7acdf6d3), fill / interior_region / border / keep_border_fill_in (e88171ec)

**依赖链**：边缘标记发射射线 → 射线穿过框体边框进入框内部（框不阻挡射线）→ 对每个框统计各色射线在其内部的覆盖像素数 → 覆盖最多的颜色填充该框内部 → 阻挡像素同时影响射线传播和填充结果。删去射线，无从确定填充色；删去计数，多色射线穿过同一框时无法选择；删去框的内部概念，无法定义填充区域。

网格边缘的彩色标记发射射线，射线穿透矩形框的边框但被框内阻挡物截断；每个框的内部填充色由穿过其内部的射线颜色投票决定。

**输入结构**：约 15x15 的黑(0)背景网格。包含 2-3 个不重叠的空心矩形框（一像素厚边框为灰(5)），每个框至少 4x4。网格四条边缘（第 0 行、最后一行、第 0 列、最后一列）上分布着若干单像素彩色标记（取自蓝(1)、红(2)、绿(3)），每个标记的所在行或列至少穿过一个框的内部区域。部分框的内部有一个黄(4)阻挡像素。生成约束：至少一个框有且仅有一种颜色的射线穿过，至少一个框有多种颜色的射线穿过（以便出现投票场景）。

**规则**：
1. 每个边缘标记向网格内部发射一条射线，方向垂直于其所在边缘（顶边标记向下，底边标记向上，左边标记向右，右边标记向左），沿其所在行或列直线传播。
2. 射线穿过灰(5)矩形框的边框像素——框对射线透明。射线遇到黄(4)阻挡像素时停止（阻挡像素本身不被射线着色）。射线到达对面边缘时自然终止。
3. 对每个矩形框，统计各颜色的射线在该框的严格内部（不含边框）覆盖的像素数量。
4. 将该框的严格内部全部填充为覆盖像素数最多的颜色。若有计数相同的平局，选择标记距框中心曼哈顿距离更近的那个颜色。
5. 若框内部有黄(4)阻挡像素，填充后该阻挡像素保持黄(4)不变。
6. 矩形框边框保持灰(5)；标记保持原色。

**关键洞察**：矩形框不是射线的障碍物而是射线的"采样窗口"——框将连续射线截取为离散的覆盖区间，通过统计这些区间的长度来投票选出填充色。同一条射线可以同时为多个框贡献投票。

## 新题 6：等差序列定位缺失件 + 锚点定义镜像轴

**组合逻辑**：[arithmetic_progression / completion](已有) → [square_anchor / anchor_as_axis](已有，但锚点位于等差缺口处而非独立放置) → [mirror](已有) → [recolor](已有)

**来源原语**：arithmetic_progression / completion / rect_side_stroke (f8c80d96), mirror / square_anchor / anchor_as_axis / contact_edge_align (11dc524f), recolor (604001fa)

**依赖链**：等差递推发现精灵序列中的缺口位置 → 锚点恰在缺口处，确认位置并提供镜像轴 → 缺口处不是放一个普通副本而是放原件的镜像 → 镜像副本使用新颜色以区分。删去等差递推，就不知道缺口在哪里；删去锚点，就不知道镜像方向；删去镜像，就变成简单的补全题。

沿一条轴线等距排列的同形精灵缺少一个成员，缺口处的锚点方块标记了镜像轴，补全的是原件的反射副本而非直接复制。

**输入结构**：约 18x18 的黑(0)背景网格。包含 3-4 个相同的蓝(1)4-连通精灵体（4-8 像素，形状不规则且非对称），沿水平或竖直方向排列，各精灵边界框的左上角坐标在该轴方向构成等差数列。数列中恰有一个位置缺失（无精灵）。缺失位置处放置一个红(2)的 2x1 或 1x2 实心方块锚点，其长轴垂直于数列排列方向。生成约束：镜像副本在缺口位置不与任何已有精灵重叠；锚点的中心坐标与缺口位置预期的精灵边界框边缘对齐。

**规则**：
1. 识别精灵序列的等差递推模式：所有同色精灵的边界框左上角沿某一轴方向（水平或竖直）等间距排列。
2. 通过等差间距推断缺失成员应在的位置。
3. 红(2)锚点方块标记了缺口位置。锚点的长边定义了镜像轴：长边所在直线即为反射线。
4. 取任一现有精灵的形状模板，关于锚点长边做镜像反射，将反射结果放置在缺口位置。
5. 镜像副本统一涂色为绿(3)。
6. 擦除锚点方块（置为黑(0)）。
7. 原有蓝(1)精灵保持不变。

**关键洞察**：缺口的位置由等差序列决定（"在哪里"），但填入的不是精灵原样而是镜像版本（"长什么样"），这由锚点的朝向编码。两个独立的信息源（序列间距 + 锚点方向）共同约束了一个输出，单独任何一个都不够。

## 新题 7：视线 + 邻接双重验证的噪点清理

**组合逻辑**：[sightline_align](已有) ∧ [adjacency / merge_or_delete](已有) → [recolor](已有，但产生三种结果而非两种) → [erase](已有) → [ignore_distractors](已有)

**来源原语**：sightline_align / sightline / nearest_neighbor (e1d2900e), adjacency / merge_or_delete / noise_pixel / rectangle (7e0986d6), recolor / erase (7e0986d6), ignore_distractors (e88171ec, e1d2900e), solid_block (e1d2900e)

**依赖链**：邻接计数和视线对齐是两个独立的检测维度，共同决定噪点命运 → 两个条件的组合产生三种输出（原色恢复 / 灰化 / 擦除），而非源题中的二元结果 → 红色方块作为干扰项需被正确忽略。删去视线检测，退化为参考题 7e0986d6 的二元规则；删去邻接计数，退化为参考题 e1d2900e 的单向滑动；两者缺一都会产生错误的噪点分类。

同时检测邻接数和视线通达性，将噪点分为三类（强关联→恢复原色、弱关联→标为灰色、无关联→擦除），红色方块是应被忽略的干扰物。

**输入结构**：约 14x14 的黑(0)背景网格。包含 2-3 个大型彩色实心矩形（面积 >= 9，取自蓝(1)、绿(3)），互不重叠。散布着若干小型橙(7)噪点对象（每个 1-3 像素，4-连通），部分位于矩形表面或紧邻矩形，部分远离矩形。另有 1-2 个红(2)的 2x2 实心方块散布于网格中，作为干扰项。生成约束：部分噪点同时满足邻接和视线条件，部分仅满足邻接条件，部分两者都不满足。

**规则**：
1. 识别大型矩形（面积 >= 9）为目标对象，小型橙(7)对象（面积 <= 3）为噪点。红(2)的 2x2 方块为干扰项，完全忽略——不作为目标矩形，也不影响噪点判定。
2. 对每个噪点对象，检查两个条件：
   - 邻接条件：该噪点对象的像素是否共有 >= 2 个 4-邻居像素属于某个大型矩形？
   - 视线条件：该噪点对象的任一像素是否与某个大型矩形在同行或同列上有无遮挡的直线视线（之间全为背景像素）？
3. 若两个条件均满足（强关联）：将该噪点对象重涂为与之 4-邻接最多的矩形的颜色。
4. 若仅邻接条件满足但视线条件不满足（弱关联）：将该噪点对象重涂为灰(5)。
5. 若邻接条件不满足（无关联，无论视线如何）：擦除该噪点对象（置为黑(0)）。
6. 红(2)方块、大型矩形和背景保持不变。

**关键洞察**：参考题 7e0986d6 的噪点清理是二元的（归并或删除），这里通过引入视线检测第二维度，将噪点分为三类。弱关联（有邻接但无视线）是一个仅看单个示例容易误判的边界情况——可能被当作强关联或被误删，必须对比多个示例才能发现灰色输出的存在。

## 新题 8：连线路径激活骨架格子框

**组合逻辑**：[connect / fill_between_markers](已有) → [scaffold_lattice / hollow_cell_frame](已有) → [expand_fill / marker_lattice_align](已有，但激活条件从标记位置变为连线路径经过) → [conflict_priority](已有)

**来源原语**：connect / row_col_aligned / fill_between_markers / marker_pixel / line_segment (dbc1a6ce), scaffold_lattice / hollow_cell_frame / expand_fill / marker_lattice_align / marker_span_extent (97239e3d), conflict_priority / row_overrides_column (9344f635)

**依赖链**：同色标记对之间画连线 → 连线路径穿过骨架的边界行/列 → 路径经过的框被激活并填充连线颜色 → 两条不同颜色的连线穿过同一框时需要冲突解决。删去连线，框无从知道该激活哪些；删去骨架结构，无法定义"框"和"经过"；删去冲突解决，多色交叉处输出不确定。

同色标记对之间的连线在骨架格子上画出路径，路径经过的每个空心框的中心被填充为连线颜色。

**输入结构**：约 17x17 的黑(0)背景网格。一个由灰(5)空心 3x3 小框组成的规则骨架格子，小框之间间隔一行一列的边界带。各小框中心像素为黑(0)（空心）。在骨架的边界交叉点上分布着若干彩色标记像素，颜色取自蓝(1)、红(2)、绿(3)，每种颜色恰好出现两个，构成同色对。每对标记共享同一行或同一列（行列对齐）。生成约束：不同颜色的连线路径至少有一个交叉框（经过同一个小框），以便出现冲突场景；标记不占据小框的中心位置。

**规则**：
1. 对每对同色标记，沿它们共享的行或列画一条连线：将两标记之间（不含标记本身）的所有背景像素涂为该标记颜色。连线经过的灰(5)骨架像素保持灰(5)不变。
2. 识别连线路径经过哪些骨架小框：若连线经过某小框的边界行或列（即连线像素出现在该小框的同一行或同一列的边界区域），则该小框被激活。
3. 将每个被激活的小框的中心像素填充为激活它的连线颜色。
4. 若同一个小框被两条不同颜色的连线激活（交叉），则水平方向的连线优先——中心像素涂为水平连线（同行标记对）的颜色。
5. 未被任何连线激活的小框的中心保持黑(0)。
6. 标记像素保持原色；骨架框体保持灰(5)。

**关键洞察**：标记本身并不直接选择要填充的框（与参考题 97239e3d 不同）——标记通过连线间接激活沿途的框。一对标记可以激活一整串框，形成"路径效应"。冲突解决规则（水平优先）只有在出现交叉路径的示例中才能被归纳出来。
