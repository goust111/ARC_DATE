## 新题 1：跨障碍配对交换后发射配偶色射线

**组合逻辑**：[交换/swap] → [射线延伸/ray_extend](创新：射线颜色取自配对伙伴而非自身) + [重涂色/recolor] + [擦除/erase]

**来源原语**：交换/swap、跨障碍配对/cross_barrier_pair、同行列两侧各一/one_each_side（来自 1efba499）；射线延伸/ray_extend、像素为射线中心/pixel_as_ray_center（来自 140c817e）；擦除/erase（来自 1efba499, d687bc17）；重涂色/recolor（来自 140c817e）；障碍段/barrier_segment（来自 1efba499）；标记像素/marker_pixel（来自 1efba499, 140c817e）

**依赖链**：交换操作决定标记像素的最终位置，而配对关系决定射线使用哪种颜色——位置来自交换结果，颜色来自配对伙伴的原色。两条信息流在射线发射时汇聚，缺少任一条信息都无法正确生成输出。

将散布于障碍段两侧的配对标记像素交换到对侧，再从新位置发射以伙伴原色着色的十字射线，最终输出一张由射线交织成的网格。

**输入结构**：约 18x18 的黑(0)背景网格。灰(5)像素构成 2~4 段水平或垂直的连续障碍段，每段长 3~6 像素，段与段之间互不相邻。若干单像素的彩色标记散布在网格各处（颜色取自蓝(1)、红(2)、绿(3)、黄(4)，每种颜色至多出现 2 次）。部分标记形成"跨障碍配对"：同一行或同一列上，恰好有一段障碍段将该行/列分为两侧，且两侧各恰有一个标记像素。其余标记（不满足配对条件的）为孤立标记。生成约束：每条带有配对标记的行/列只穿过一段连续障碍段；配对标记的颜色互不相同；所有射线的交叉点不与障碍段重合。

**规则**：
1. 扫描每一行和每一列：若该行/列恰好穿过一段连续障碍段，且障碍段两侧各有恰好一个标记像素，则这两个标记构成一个配对。
2. 对每个配对，擦除两个标记的原始位置，将每个标记重新放置到障碍段对侧紧邻障碍段的第一个空单元格中（即交换到对面）。
3. 不满足配对条件的孤立标记全部擦除。
4. 从每个交换后的标记新位置出发，沿该标记所在的行和列双向延伸射线至网格边缘。射线颜色为该标记的配对伙伴在交换前的原始颜色（不是标记自身的颜色）。
5. 将每个交换后标记自身所在的单元格重涂为品红(6)。
6. 障碍段保持灰(5)不变。射线像素不覆盖障碍段像素和品红(6)标记像素。
7. 当两条不同标记发出的射线在同一单元格交叉时，该单元格取列方向（垂直）射线的颜色。

**关键洞察**：射线的颜色不是标记自身的颜色，而是来自它在交换中被配对的那个伙伴的原色——必须同时识别出配对关系和交换后的位置，才能确定射线颜色，仅观察单个示例可能误判为"射线用标记自身颜色"。

## 新题 2：最近边引力堆叠与边色重涂

**组合逻辑**：[最近边归属/nearest_side_assignment](创新：决定引力方向而非仅决定颜色) → [滑动/slide + 碰撞停止/collision_stop + 近墙优先结算/nearest_first_settling] → [重涂色/recolor] + [裁剪/crop]

**来源原语**：最近边归属/nearest_side_assignment、空心矩形/rectangular_frame、重涂色/recolor、裁剪/crop（来自 9aec4887）；滑动/slide、重力下落/gravity_drop、碰撞停止/collision_stop、近墙优先结算/nearest_first_settling（来自 6ad5bdfd）；边框/frame（来自 d687bc17）

**依赖链**：每个物体的最近边归属同时决定两件事——引力方向和最终颜色。引力方向又影响结算顺序（近墙优先），而结算顺序影响碰撞位置，碰撞位置反过来影响后续物体的可落位空间。这形成了一个"归属→方向→结算序→碰撞位→最终布局→重涂色"的紧耦合链。

将框内散布的小图形按各自最近边的方向滑动堆叠，然后用对应边的颜色重涂每个图形，输出裁剪后的紧凑框。

**输入结构**：约 20x20 的黑(0)背景网格。中央区域有一个由四条同长度色条构成的矩形框（无角像素），四条边分别为蓝(1)、红(2)、绿(3)、黄(4)——上、下、左、右各一色。框内部散布 4~7 个灰(5)的 4-连通单色小图形，每个图形 3~5 像素，形状各异（不限于特定几何形状），图形之间互不相邻。生成约束：每个图形的边界框中心到四条边的距离中，最小距离唯一（无并列最近边）；框的内部尺寸至少 10x10 以保证图形有足够散布空间；各图形滑动路径上不存在循环依赖（即不存在 A 需要等 B 先结算但 B 又需要等 A 的情况）。

**规则**：
1. 识别矩形框及其四条边的颜色。
2. 对每个灰(5)图形，计算其边界框中心到框的上、下、左、右内侧边缘的曼哈顿距离，选距离最短的边作为该图形的"吸引边"。
3. 按每个图形到其吸引边的距离从小到大排序（最近的先结算）。按此顺序，将每个图形作为刚体沿吸引边方向滑动，直到图形的前沿碰到框的该边内壁或碰到已结算的其他图形为止。
4. 所有图形结算后，将每个图形重涂为其吸引边的颜色。
5. 输出裁剪为框的边界框（含框边本身）。

**关键洞察**：与单一方向的引力不同，每个物体有独立的引力方向，由其空间位置（最近边）决定——同一网格中的物体可能朝四个不同方向滑动。需要对比多个示例才能确认"吸引方向=最近边方向"而非某种固定方向。

## 新题 3：角位三角轮廓内部的周期分层填色

**组合逻辑**：[角位置对应/corner_correspond + 放大画布/expand_canvas] → [补对角线边/fill_diagonal_side](绘制三角轮廓) + [循环填充/cyclic_filling](创新：填充三角内部而非对角带)

**来源原语**：角位边角/corner_piece、三角轮廓/triangle_outline、放大画布/expand_canvas、角位置对应/corner_correspond、补对角线边/fill_diagonal_side（来自 e3f79277）；循环填充/cyclic_filling、调色板行/palette_row、层深度递增/layer_depth_increasing、层深模色板取色/depth_mod_palette_color（来自 b457fec5）

**依赖链**：L 形角件决定三角形的位置、朝向和尺寸（几何参数），调色板行决定填色序列（色彩参数）。三角轮廓的构建产生了一个需要填充的封闭内部区域，而填色规则依赖从三角顶点向内递增的层深度。两个信息源在"三角内部的像素着色"这一步汇聚——去掉角件无法知道填什么形状，去掉调色板无法知道填什么颜色。

从一个角位 L 形件推断三角形的角落和尺寸，在放大画布上绘制该三角的轮廓，然后用调色板行按层深度循环填充三角内部。

**输入结构**：一个 n x n 的小方格（n 约 5~7），背景为黑(0)。前景色橙(7)构成一个单像素宽的 L 形，L 的两条腿分别贴合方格的一条水平边和一条垂直边（它们共享一个角落的顶点）。L 的两腿等长。另外，在 L 不贴合的那条水平边上，紧贴边缘有一行 2~4 个连续的彩色标记像素（颜色各不相同，取自蓝(1)、红(2)、绿(3)、黄(4)），这是调色板行。调色板行与 L 形件互不接触。

**规则**：
1. 识别 L 形件所在的角落（左上、右上、左下、右下之一），记该角为三角顶点。
2. 构建放大画布：边长为 3n - 2，填充黑(0)。
3. 计算三角边长 s = 2 x (L 腿长度)。在放大画布的对应角落绘制直角三角轮廓：两条直角腿沿该角的两条画布边缘绘制，长度为 s，颜色为橙(7)；两条腿的自由端点用橙(7)对角线段连接（Bresenham 直线）。
4. 填充三角内部（轮廓围成的区域，不含轮廓本身）：对内部每个像素，计算其层深度 d = min(到最近直角腿行的距离, 到最近直角腿列的距离)，层深度从 1 开始。用调色板行中第 ((d - 1) mod 调色板长度) 个颜色涂色。调色板行的读取顺序为从左到右。
5. 轮廓像素保持橙(7)，背景保持黑(0)。

**关键洞察**：三角形的几何构造来自 L 形件（角落、尺寸），但内部的着色图案来自独立的调色板行——仅看三角轮廓无法推断填色规则，仅看调色板无法推断几何形状，两者必须联合解读。

## 新题 4：梳状高度计数驱动逐行递增色段堆叠

**组合逻辑**：[计数/count + 高度编码数量/height_encodes_count] → [排序/sort](创新：按空间位置排序而非按数值) → [填充/fill + 逐行递增/row_by_row_increment + 堆叠/stack]

**来源原语**：计数/count、排序/sort、梳状结构/comb_motif、高度编码数量/height_encodes_count（来自 a1aa0c1e）；填充/fill、堆叠/stack、色段/color_run、逐行递增/row_by_row_increment、每行递增扩展/row_incremental_expand（来自 bbc9ae5d）

**依赖链**：梳状结构的高度编码了计数值，计数值成为色段递增堆叠的初始长度参数。排序决定各梳的色段在输出中的垂直排列顺序。如果计数错误，初始长度就错误，后续逐行递增产生的所有行都错。如果排序错误，输出中各色块的上下位置就错。三个环节串联且每步实质性变换信息。

统计每个梳状结构的高度（行数）得到一组计数值，以各梳对应的颜色为色段色，按计数值为初始长度逐行递增堆叠，最终纵向拼接成输出。

**输入结构**：约 15x20 的黑(0)背景网格。网格中有 3~5 个独立的梳状结构，每个梳由某种前景色构成（各梳颜色不同，取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)）。每个梳是一组垂直排列的三像素宽行，交替出现"实心行"（3 个连续同色像素）和"空齿行"（左右各一个同色像素，中间为黑(0)），底部以一行实心行结束。梳的"高度"定义为其实心行的数目（不计空齿行），范围为 2~6。各梳在网格中水平排列，互不重叠，梳之间至少隔 2 列。生成约束：所有梳的高度互不相同。

**规则**：
1. 识别每个梳状结构，统计其实心行数目作为该梳的计数值 c。
2. 按各梳在输入网格中的水平位置（梳的最左列的列号）从左到右排序。
3. 对排序后的每个梳，生成一个子网格：子网格宽度 W 等于所有梳中的最大计数值，第 1 行从左起填 c 个该梳颜色的像素（其余为黑(0)），此后每行比上一行多填 1 个像素（不超过 W），共生成 W 行。
4. 将所有子网格按排序顺序从上到下纵向拼接，子网格之间无间隔，组成最终输出。

**关键洞察**：梳状结构的高度不是直接成为输出中的行数，而是成为色段的初始长度——这个"高度→初始长度"的间接映射需要对比多个示例才能发现，因为单个示例中很容易将其与其他可能的映射（如高度→行数、高度→总像素数）混淆。

## 新题 5：引力结算后凸耳触发轴向镜像

**组合逻辑**：[墙面确定方向/wall_determines_direction + 滑动/slide + 碰撞停止/collision_stop] → [凸耳决定镜像轴/tab_determines_axis + 镜像/mirror](创新：镜像发生在结算后的位置而非原始位置) + [颜色按方位定/color_by_orient]

**来源原语**：滑动/slide、重力下落/gravity_drop、边墙/edge_wall、墙面确定方向/wall_determines_direction、碰撞停止/collision_stop、近墙优先结算/nearest_first_settling（来自 6ad5bdfd）；镜像/mirror、凸耳/tab、轮廓/outline、对侧放置/opposite_place、凸耳决定镜像轴/tab_determines_axis、颜色按方位定/color_by_orient、擦除/erase（来自 dc2e9a9d）

**依赖链**：引力方向由边墙决定，结算顺序影响各物体最终停靠位置。镜像操作在结算后执行，镜像轴由凸耳决定，镜像副本的放置位置依赖结算后的边界框（不是原始位置的边界框）。因此引力结算的结果实质性地改变了镜像副本的空间位置。

带凸耳的轮廓物体在引力作用下滑向边墙并堆叠，结算完成后每个物体根据凸耳方位在结算位置的对侧生成彩色镜像副本。

**输入结构**：约 18x18 的黑(0)背景网格。一条完整的红(2)单像素厚边墙占据网格的某一条边（上、下、左或右），红(2)不出现在其他位置。网格中散布 2~4 个绿(3)的 4-连通单像素宽轮廓物体，每个物体有一个明确的边界框（约 3x3 到 5x5），边界框的恰好一条边上有一个单像素的绿(3)凸耳（凸耳是边界框某边向外突出的一个像素）。各物体互不相邻，且不与边墙相邻。生成约束：所有物体沿引力方向滑动后不会旋转或变形（纯平移）；各物体的滑动路径互不交叉；结算后的镜像副本不超出网格边界且副本之间互不重叠。

**规则**：
1. 识别边墙所在边，确定引力方向（指向边墙）。
2. 按每个轮廓物体到边墙的距离从小到大排序。依次将每个物体作为刚体沿引力方向滑动，直到前沿接触边墙或已结算物体为止（碰撞停止）。
3. 所有物体结算后，原始位置擦除（变为黑(0)），物体出现在新位置，保持绿(3)。
4. 对每个结算后的物体，找到其凸耳。凸耳在物体边界框的左或右边→水平镜像轴；凸耳在上或下边→垂直镜像轴。
5. 在物体结算后的边界框的凸耳对侧，间隔 1 个像素的位置，放置该物体的镜像副本。副本颜色由镜像轴决定：水平镜像→蓝(1)，垂直镜像→青(8)。
6. 镜像副本仅绘制在黑(0)背景上，不覆盖已有的绿(3)物体、红(2)边墙或其他副本。若两个副本冲突（占据同一单元格），保留结算位置离边墙更近的那个物体的副本。

**关键洞察**：镜像操作的空间参照系不是物体的原始位置而是引力结算后的位置——如果忽略引力步骤直接在原位镜像，副本的位置将完全错误。这个两阶段依赖（先运动、后镜像、镜像位置取决于运动结果）需要对比示例中物体的初始和最终位置才能看出。

## 新题 6：双面板叠加后周期修复缺口

**组合逻辑**：[透明叠加/transparent_overlay + 双面板对齐/dual_panel_alignment] → [补全/complete + 周期对齐/periodic_align + 最小周期修复缺口/min_period_repair_gap](创新：叠加结果本身不是最终输出，而是带缺口的周期图案)

**来源原语**：透明叠加/transparent_overlay、分隔行/divider_row、二值掩码/binary_mask、双面板对齐/dual_panel_alignment、任一前景即输出/either_foreground_yields_output（来自 506d28a5）；补全/complete、周期瓦片/periodic_tile、周期对齐/periodic_align、最小周期修复缺口/min_period_repair_gap、缺失像素/missing_pixel（来自 e95e3d8e）

**依赖链**：叠加操作将两个面板的前景合并成一个带有"空洞"的图案。这些空洞恰好是某个最小周期瓦片的缺失采样点。周期修复需要利用叠加后的非空像素来推断周期瓦片，再用瓦片填补空洞。叠加产生的颜色编码（交集=一种颜色，差集=另一种颜色）直接参与周期瓦片的定义——去掉叠加就无法区分交集和差集像素，去掉周期修复则空洞无法填补。

将分隔线两侧的面板叠加，交集和差集像素分别着不同颜色，剩余黑色空洞通过推断最小周期瓦片来填补。

**输入结构**：约 15x(2m+1) 的黑(0)背景网格（其中 m 约 7~9）。中间有一行完整的灰(5)分隔行，将网格分为等大的上下两个 m 行面板。上面板包含若干蓝(1)前景像素（其余为黑(0)），下面板包含若干红(2)前景像素（其余为黑(0)）。两面板中的前景像素分布不完全相同，但有部分重叠位置。生成约束：叠加后的非黑像素（包含绿(3)交集像素和蓝(1)/红(2)差集像素）构成某个最小矩形周期瓦片的部分采样（至少覆盖 60% 的瓦片位置）；该周期瓦片的尺寸不超过 4x4；至少存在 3 个黑(0)缺口需要修复。

**规则**：
1. 移除灰(5)分隔行，将上下面板逐单元格对齐。
2. 对齐后的每个单元格判定：
   - 上下均为前景→输出绿(3)（交集）
   - 仅上面板为前景→输出蓝(1)
   - 仅下面板为前景→输出红(2)
   - 上下均为黑(0)→暂标为缺失（黑(0)）
3. 在叠加结果中，将绿(3)、蓝(1)、红(2)视为三种不同颜色，寻找面积最小的矩形周期瓦片 T，使得所有非黑像素的颜色都与 T 在其对应行/列余数位置的颜色一致，且 T 的每个余数类至少被一个非黑像素覆盖。
4. 用 T 的对应余数位置颜色填充每个仍为黑(0)的缺失单元格。
5. 输出为 m 行的单面板网格。

**关键洞察**：叠加本身不是最终目标——它产生了一个由三种颜色（绿/蓝/红）组成的图案，这个图案恰好是某个周期瓦片的不完全采样。交集像素（绿色）和差集像素（蓝/红色）在周期瓦片中扮演不同角色，是瓦片的组成部分而非特殊标记。

## 新题 7：线路传输模板图案并在端点重涂色印章

**组合逻辑**：[传输/transmit + 端点配对/endpoint_pairing](创新：传输的对象是模板图案而非令牌形状) + [印章放置/stamp + 颜色替换/color_substitution] + [擦除/erase]

**来源原语**：传输/transmit、线路网络/wire_network、端点配对/endpoint_pairing（来自 a47bf94d）；印章放置/stamp、模板图案/stencil_pattern、规则示例/rule_example、颜色替换/color_substitution、示例定义规则/example_defines_rule、擦除/erase（来自 abc82100）

**依赖链**：线路网络的拓扑决定模板图案的传输路径（哪个端点的图案传到哪里），端点处的本地颜色像素决定重涂色映射（青色图案被替换为什么颜色）。传输目的地由线路决定，印章颜色由目的地的本地上下文决定——两个信息流在"将图案印章到远端"这一步汇聚。

沿线路网络将源端的青色模板图案传输到远端，在远端以远端本地像素的颜色替代青色进行印章，擦除所有源端组件。

**输入结构**：约 20x20 的黑(0)背景网格。包含 2~3 条独立的线路网络，每条线路由灰(5)像素构成单像素宽的 4-连通路径（可弯折），连接两个端点。在每条线路的一个端点（源端）旁，有一个 3x3~4x4 的青(8)模板图案（非对称的连通图形，不占据全部方格，与端点相邻但不重叠线路）。在青(8)图案与线路端点之间有一个单独的彩色像素（取自蓝(1)、红(2)、绿(3)、黄(4)），这是源端的颜色标记。在线路的另一端点（远端）旁，有另一个单独的彩色像素作为远端的颜色标记。生成约束：各线路互不交叉；每条线路恰好一端有青色模板图案；源端与远端的颜色标记颜色不同；青色模板图案在传输到远端后不超出网格边界。

**规则**：
1. 识别每条灰(5)线路网络及其两个端点。
2. 确定线路的源端：有青(8)模板图案相邻的端点为源端，另一端为远端。
3. 将源端的青(8)模板图案沿线路传输到远端：以源端端点为参考锚点，以远端端点为放置锚点，保持图案相对于锚点的偏移不变，将图案印章到远端位置。
4. 印章时，将青(8)替换为远端本地颜色标记像素的颜色（颜色替换）。
5. 擦除所有源端的组件：源端的青(8)模板图案、源端的颜色标记像素。保留远端的颜色标记像素。
6. 灰(5)线路网络保持不变。
7. 若印章后的图案与已有的非黑像素重叠，印章像素覆盖黑(0)背景但不覆盖灰(5)线路和已有的彩色标记像素。

**关键洞察**：线路的作用不是传输颜色信息或变换形状，而是传输空间图案本身——图案从一端被"搬运"到另一端，同时在新位置获得新颜色。这将"路由"和"模板印章"两种原本无关的机制紧耦合：路由决定去哪里，本地颜色决定印什么色，模板决定印什么形状。

## 新题 8：颜色匹配边移动后发射受限内射线

**组合逻辑**：[颜色匹配边/color_matches_side + 移动/move](移动到匹配边) → [射线延伸/ray_extend](创新：仅向框内部发射，方向由到达的边决定) + [重涂色/recolor] + [对角邻居/diagonal_neighbor 装饰]

**来源原语**：移动/move、边框/frame、标记像素/marker_pixel、颜色匹配边/color_matches_side、颜色决定目标边/color_determines_side（来自 d687bc17）；射线延伸/ray_extend、整行整列射线/full_row_column_ray、像素为射线中心/pixel_as_ray_center、对角邻居/diagonal_neighbor、重涂色/recolor（来自 140c817e）

**依赖链**：标记像素的颜色决定它移动到哪条边（颜色→目标边），到达边后它的位置成为射线的发射起点，射线方向固定为从该边朝框内部射入。标记在移动前的正交坐标决定了它在目标边上的精确停靠位置，而该位置又决定了射线在框内的轨迹。最终射线的交叉点产生装饰标记。移动→射线→装饰形成三步不可跳过的变换链。

将框内标记像素移动到颜色匹配的边侧，再从新位置向框内部发射单向射线，射线交叉点绘制红色标记并添加绿色对角装饰。

**输入结构**：约 14x14 的黑(0)背景网格。中央有一个矩形框（约 10x10 内部空间），由四条单像素宽的色条组成，四角为黑(0)背景。上边为蓝(1)，下边为黄(4)，左边为绿(3)，右边为橙(7)。框内部（黑(0)背景）散布 3~6 个单色标记像素，每个标记的颜色为蓝(1)、黄(4)、绿(3)或橙(7)之一（匹配某条边的颜色）。每种边色对应的标记像素至多 2 个。框内不存在与任何边色都不匹配的标记像素。生成约束：移动后的射线至少产生 2 个交叉点；所有标记移动后不会有两个标记占据同一位置。

**规则**：
1. 清空框内部所有标记像素（变为黑(0)）。
2. 对每个标记像素，根据其颜色确定目标边（蓝→上边，黄→下边，绿→左边，橙→右边）。将标记重新放置到目标边的内侧紧邻单元格，保持其原始的正交坐标不变（即匹配上/下边的标记保持原列号，匹配左/右边的标记保持原行号）。
3. 从每个已移动标记的位置出发，向框内部方向发射单方向射线（上边的标记向下射、下边的向上射、左边的向右射、右边的向左射），射线延伸直到碰到对面的框边（不含框边像素）。射线颜色与标记颜色相同。
4. 被移动的标记像素本身保持其原色。
5. 当两条来自不同边的射线在同一单元格交叉时，将该单元格重涂为红(2)。
6. 对每个红(2)交叉点，将其四个对角邻居中位于框内部且当前为黑(0)的单元格涂为品红(6)。
7. 射线像素（非交叉点）不覆盖其他射线——若两条同方向射线经过同一单元格（来自同一边的两个标记），该单元格保持该边的颜色。

**关键洞察**：射线不是从标记的原始位置发射，而是从标记移动到边侧后的新位置发射——这意味着必须先正确执行"颜色匹配→移动"才能知道射线的起点。同时，射线只向内部发射（不是全行全列），方向由标记到达的边决定，这与源题 140c817e 的全向射线本质不同。
