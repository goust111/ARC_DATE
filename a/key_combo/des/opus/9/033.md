## 新题 1：邻接传色决定分量滑动方向

**组合逻辑**：[邻接传色(adjacency_transfer)](创新：传递的颜色不再只是视觉标记，而是编码运动方向) + [滑动(slide)](创新：滑动方向不固定为水平，由传入颜色动态决定) + [碰撞停止(collision_stop)](已有原语，作用于滑动后的分量间互挡)

**来源原语**：邻接传色/标记接触即赋色/中性遮罩/标记像素(b7256dcd), 滑动/靠近障碍停止/固定障碍(9c56f360), 碰撞停止(142ca369)

**依赖链**：标记像素与灰色分量的邻接关系决定每个分量获得的颜色 -> 获得的颜色编码该分量的滑动方向 -> 每个分量沿自身方向滑动时，其他已着色分量和网格边缘充当障碍 -> 最终布局由传色结果与所有分量的相互阻挡共同决定

将灰色连通分量通过相邻标记像素获得颜色，颜色编码滑动方向，各分量沿各自方向滑动直至碰撞停止。

**输入结构**：约 15x15 网格，黑(0)背景。网格中散布 4~6 个灰(5)的 4-连通单色连通分量（每个 3~7 像素，形状各异，包含非矩形不规则形状）。每个灰色分量的 4-邻域边上恰好有一个非灰非黑的标记像素（标记像素彼此不相邻、不与多个分量同时相邻）。标记像素颜色仅限红(2)、蓝(1)、绿(3)、黄(4)四种。各灰色分量之间至少间隔 2 个像素，保证初始时不互相接触。生成约束：沿每个分量的指定滑动方向，不存在两个分量会在同一时刻争夺同一位置的情况（即滑动路径无交叉冲突）。

**规则**：
1. 识别所有灰(5)的 4-连通分量和所有非灰非黑的孤立标记像素。
2. 对每个灰色分量，找到与其 4-邻接的唯一标记像素，将该分量所有像素重涂为标记像素的颜色，然后将该标记像素擦除为黑(0)。
3. 颜色编码滑动方向：红(2)=向下，蓝(1)=向上，绿(3)=向左，黄(4)=向右。
4. 按照"离目标边缘最近的分量优先"的顺序依次处理每个分量的滑动（向下的分量按其最下行从大到小排序，向上的按其最上行从小到大排序，向左的按其最左列从小到大排序，向右的按其最右列从大到小排序；不同方向之间先处理向上、再向下、再向左、再向右）。
5. 每个分量沿其方向整体平移，逐格移动，直到分量中任一像素的下一步位置是网格边缘或已被非黑像素占据的格子，则停止。
6. 所有分量处理完毕后，输出最终网格。

**关键洞察**：颜色在这里不仅是视觉属性，更是运动指令的编码；多个分量的滑动方向各异且互为障碍，因此最终布局是一个多体碰撞问题，无法通过单独考虑任一分量得出。

## 新题 2：稀疏精灵体稠密化后逐像素逻辑合并

**组合逻辑**：[稠密化(densify)](已有原语) + [逻辑运算(logical_op)](创新：不再是简单 NOR，而是对稠密化后的多层结果做分类合并) + [分隔条(separator_bar)](已有原语，划分操作区域)

**来源原语**：稠密化/稀疏精灵体(db615bd4), 逻辑运算/逐像素对应/二值掩模/分隔条(1b2d62fb)

**依赖链**：分隔条将网格分为左右两区 -> 左右两区内的稀疏精灵体各自稠密化（将两步间距的点阵填实） -> 稠密化后的两区按像素位置对齐进行逻辑分类 -> 分类结果决定每个像素的输出颜色

将分隔条两侧的稀疏精灵体分别稠密化，然后逐像素对比两侧结果，用四色编码输出。

**输入结构**：约 11x23 网格（宽大于高），黑(0)背景。正中间有一条贯通全高的蓝(1)垂直分隔条（宽 1 列）。分隔条左侧和右侧各有一个栗(9)色的稀疏单色图形，稀疏图形的像素位于两步间距的晶格上（即相邻像素间在行或列方向相距 2）。左右两区尺寸相同（宽度 = (总宽-1)/2，高度 = 总高）。两个稀疏图形的包围框在对齐到各自区域后尺寸相同。生成约束：两个稀疏图形稠密化后的包围框尺寸一致，保证逐像素对齐有意义。

**规则**：
1. 识别蓝(1)垂直分隔条，将网格分为左区和右区（不含分隔条列）。
2. 对左区和右区各自的栗(9)稀疏图形执行稠密化：将每个稀疏图形的两步间距晶格内所有空缺像素填充为栗(9)，形成实心版本。
3. 将左区的稠密化结果与右区的稠密化结果按像素位置一一对应。对应方式：左区第 r 行第 c 列对应右区第 r 行第 c 列（两区各自以区域左上角为原点）。
4. 输出一个与单区尺寸相同的网格，每个像素按以下规则着色：
   - 左右均为栗(9)（双前景）-> 红(2)
   - 仅左侧为栗(9)（左独有）-> 绿(3)
   - 仅右侧为栗(9)（右独有）-> 黄(4)
   - 左右均为黑(0)（双背景）-> 黑(0)
5. 分隔条不出现在输出中。

**关键洞察**：如果跳过稠密化直接对比稀疏像素，由于两侧原始像素落在不同晶格位上几乎不会重叠，逻辑合并的结果将完全错误；稠密化是使逻辑运算有意义的必要前提。

## 新题 3：射线弹射段长度编码为颜色

**组合逻辑**：[射线延伸(ray_cast) + 反弹(bounce)](已有原语) + [计数(counting)](创新：计数对象从条形段变为射线的每段弹射路径长度) + [长度映射颜色(length_maps_color)](创新：映射对象从水平条形段变为对角射线段)

**来源原语**：射线延伸/反弹/碰撞停止/墙壁像素(142ca369), 计数/长度映射颜色/固定编码表(e048c9ed)

**依赖链**：箭头精灵体的朝向决定射线初始方向 -> 墙壁像素的位置决定弹射点和每段路径的长度 -> 每段长度通过固定编码表映射为一种颜色 -> 每段射线路径被涂为对应颜色

从箭头精灵体发射对角射线，遇墙壁像素反弹，每段弹射路径的像素数通过固定编码映射为该段的颜色。

**输入结构**：约 15x15 网格，黑(0)背景。网格中有一个灰(5)色的 3 像素 L 形箭头精灵体（占据 2x2 包围框中缺一角的形状）。网格中散布 4~7 个孤立的红(2)墙壁像素，彼此不相邻，且不与箭头精灵体相邻。生成约束：射线从箭头出发后，在出网格前至少经历 3 次弹射；每段弹射路径长度在 2~5 之间（含端点处的弹射位置像素）；射线路径不经过任何墙壁像素以外的非背景像素。

**规则**：
1. 确定箭头精灵体的朝向：缺失角所在方向即为射线发射方向（对角方向，如缺右下角则射线向右下发射）。
2. 射线从箭头精灵体的缺失角位置出发，沿对角方向逐格前进，在经过的每个黑(0)背景格子上留下标记。
3. 弹射规则：当射线下一步将到达红(2)墙壁像素时，根据墙壁像素相对于射线当前位置的方位反转对应轴向（正面撞击反转两轴，侧面接触反转单轴），射线改变方向继续前进。墙壁像素本身保持不变。
4. 射线在到达网格边界时终止。
5. 将整条射线路径按弹射点分段（包括起点到第一次弹射、每两次相邻弹射之间、最后一次弹射到出界），计算每段包含的像素数（含该段两端的位置，但弹射点像素归属前一段而非后一段）。
6. 每段长度通过固定编码表映射颜色：2 -> 蓝(1)，3 -> 黄(4)，4 -> 品红(6)，5 -> 绿(3)。
7. 将每段射线路径的所有像素涂为该段映射得到的颜色。箭头精灵体本身擦除为黑(0)。墙壁像素保留红(2)不变。

**关键洞察**：射线几何决定每段长度，长度决定颜色，两者紧密耦合——改变任一墙壁像素的位置会同时改变弹射几何和多段的颜色编码。需要从多个示例中归纳出长度-颜色编码表，因为单个示例中可能不包含所有长度值。

## 新题 4：平铺复原后检测完整边框并提取最稀疏内容

**组合逻辑**：[平铺(tiling) + 补全(completion)](已有原语) + [完整边框检测(complete_border_check)](创新：检测对象从原始输入变为平铺复原后才显现的边框) + [选择(selection) + 最少标记数(minimum_marker_count)](创新：选择标准从标记像素数量变为复原区域中内部异色像素的稀疏程度) + [裁剪(crop)](已有原语)

**来源原语**：平铺/补全/重复瓦片/遮挡区域/可见像素约束推断(ca8f78db), 完整边框检测/最大面积选取/边框包围内容/忽略干扰项(1a6449f1), 选择/最少标记数/标记像素(7bb29440), 裁剪(7bb29440, 1a6449f1)

**依赖链**：黑色遮挡区域破坏了部分边框的完整性 -> 平铺补全恢复被遮挡的像素 -> 复原后才能识别哪些矩形边框是完整的 -> 在所有完整边框中选择内部异色像素最少的那个 -> 裁剪输出该边框的内部区域

先用最小重复瓦片填补遮挡区域，复原后找出所有完整矩形边框，输出内部异色标记最少的边框的内容。

**输入结构**：约 18x18 网格。网格整体是一个由多种颜色构成的二维周期性图案（最小重复瓦片约 4x4 至 6x6），图案中自然嵌入了 3~4 个同色单像素厚矩形边框（边框颜色为橙(7)，与瓦片图案颜色不冲突）。每个边框内部包含若干品红(6)标记像素（数量 0~4 不等），其余内部像素为瓦片图案的自然延续。网格中有 1~2 个黑(0)矩形遮挡区域（约 3x3 至 5x5），覆盖了部分瓦片图案像素，其中至少一个遮挡区域破坏了某个边框的完整性。生成约束：遮挡区域不会完全覆盖任何边框（至少保留边框的三条边），所有完整边框的内部尺寸相同，保证复原后恰好有一个边框的内部品红(6)像素数严格最少。

**规则**：
1. 将所有黑(0)像素视为被遮挡的未知像素。从剩余非黑像素推断最小二维重复瓦片。
2. 用推断出的瓦片周期性地铺满整个网格，替换所有黑(0)遮挡像素，恢复原始图案。
3. 在复原后的网格中，找出所有由橙(7)像素构成的单像素厚完整矩形边框（四条边无断裂）。
4. 对每个完整边框，计算其严格内部区域中品红(6)标记像素的数量。
5. 选择品红(6)标记像素数量最少的那个边框（保证唯一）。
6. 输出该边框的严格内部区域（不含边框本身），保持内部所有像素颜色不变。

**关键洞察**：遮挡区域可能恰好破坏一个边框的某条边，使其在复原前看起来不完整；只有先通过瓦片推断恢复缺失像素，才能正确判断哪些边框是完整的，进而才能在完整边框中做稀疏性选择。

## 新题 5：角落朝向编码翻转方式后印章覆盖

**组合逻辑**：[像素放大/角落标记(corner_marker)](创新：角落标记不再直接放大到外角，而是编码对中心模板的翻转方式) + [翻转(flip)](创新：翻转方式由小标记的几何朝向隐式决定) + [印章覆盖(stamp_overlay)](创新：将翻转后的模板印入标记指定的角落象限) + [重涂色(recolor)](已有原语)

**来源原语**：角落标记/朝向对应角/扩展至外角(b745798f), 翻转/旋转/标记色定朝向(6e4f6532), 印章覆盖/尺寸匹配/有花纹框为模板(f21745ec), 重涂色(多题)

**依赖链**：中心区域的花纹模板提供印章内容 -> 角落 L 标记的朝向同时编码了两条信息：(a) 印章应印入哪个角落象限，(b) 印章在该象限中需要怎样翻转 -> 每个标记的颜色决定印章在该象限中的重涂色 -> 最终四个角落象限可能各有不同翻转和颜色的模板副本

读取中心模板花纹，根据每个角落 L 标记的朝向和颜色，将模板翻转后印入对应角落象限并重涂色。

**输入结构**：约 15x15 奇数尺寸正方形网格，黑(0)背景。网格中心有一个约 5x5 的花纹区域，由灰(5)像素构成不规则但非对称的图案（花纹无旋转或翻转对称性，3~8 个灰色像素）。网格的四个象限角落区域中，有 2~4 个（不一定全部四个角都有）单色 4-连通 3 像素 L 形标记，每个占据 2x2 包围框中缺一角的形状。每个 L 标记颜色各不相同，从红(2)、蓝(1)、绿(3)、黄(4)中取。L 标记位于其所在象限的角落附近（距网格角不超过 3 格）。生成约束：花纹区域严格位于中心，不触及任何象限的角落区域；中心花纹的包围框尺寸不超过象限尺寸，保证印章能完全放入象限。

**规则**：
1. 裁剪中心灰(5)花纹区域的包围框作为模板。
2. 对每个 L 形标记，根据其缺失角方向确定目标象限：缺右下角 -> 印入左上象限，缺左下角 -> 印入右上象限，缺右上角 -> 印入左下象限，缺左上角 -> 印入右下象限（即标记朝向的反方向）。
3. 对模板执行翻转变换：左上象限保持原样，右上象限水平翻转，左下象限垂直翻转，右下象限水平+垂直翻转（等价于 180 度旋转）。
4. 将翻转后的模板印入目标象限，模板对齐到象限的外角（即模板的角与网格的角对齐）。模板中灰(5)像素替换为该 L 标记的颜色，黑(0)像素保持黑(0)。
5. 擦除所有 L 标记和中心花纹区域（设为黑(0)）。没有 L 标记指向的象限保持全黑。

**关键洞察**：L 标记的朝向同时编码了"印到哪里"和"怎么翻转"两条信息，且模板本身无对称性，因此翻转方式的差异会产生可区分的不同输出——必须同时正确推断朝向-象限映射和朝向-翻转映射才能解题。

## 新题 6：包围框包含深度决定同心层配色方案

**组合逻辑**：[包围框包含(bbox_containment)](创新：包含关系不再用于擦除，而是计算嵌套深度) + [循环填充(concentric_fill)](创新：同心层着色方案不再固定，由包含深度动态选择) + [配对色映射(paired_color_mapping)](创新：配对关系从单一映射扩展为深度索引的多套配色方案)

**来源原语**：包围框包含/连通分量/异色包含则删(9720b24f), 循环填充/同心层/边距深度/奇偶交替着色(516b51b7), 配对色映射(6ea4a07e)

**依赖链**：多个矩形的包围框嵌套关系形成层级树 -> 每个矩形在树中的深度（被几层其他矩形包围）决定它使用哪套配色方案 -> 每个矩形内部按边距深度做同心层填充，奇偶层分别使用该矩形配色方案中的两种颜色

计算嵌套矩形的包围框包含深度，每个矩形按其嵌套深度选择配色方案，对内部做奇偶交替同心层填充。

**输入结构**：约 20x20 网格，黑(0)背景。网格中有 4~6 个灰(5)实心矩形（宽高各 4~10 像素），部分矩形的包围框严格嵌套在其他矩形内部（形成 2~3 层嵌套），但矩形之间的像素不重叠（内层矩形完全位于外层矩形的内部空间中，周围有至少 1 像素的间距）。生成约束：嵌套关系构成严格的树结构（无环、无并列包含歧义），最大嵌套深度不超过 3。

**规则**：
1. 找出所有灰(5)的 8-连通实心矩形对象。
2. 计算每个矩形的包围框。若矩形 A 的包围框严格包含在矩形 B 的包围框内部，则 A 被 B 包含。
3. 计算每个矩形的嵌套深度 d：不被任何其他矩形包含的深度为 0，被 1 层包含的深度为 1，以此类推。
4. 根据嵌套深度 d 选择配色方案：
   - d=0（最外层）：外边框保持灰(5)，奇数层涂红(2)，偶数层涂蓝(1)
   - d=1（第二层）：外边框保持灰(5)，奇数层涂绿(3)，偶数层涂黄(4)
   - d=2（第三层）：外边框保持灰(5)，奇数层涂品红(6)，偶数层涂橙(7)
5. 对每个矩形，保持其最外一圈像素为灰(5)，内部像素按到矩形边缘的切比雪夫距离（最小轴向边距）分层：距离为 1 的像素属于第 1 层（奇），距离为 2 的属于第 2 层（偶），以此类推。按该矩形的配色方案着色。
6. 黑色背景和矩形之间的间隔保持不变。

**关键洞察**：同心层填充的几何计算对每个矩形都相同，但颜色选择取决于该矩形在全局嵌套层级中的位置——这是一个全局结构属性（包含深度）驱动局部渲染（配色方案）的耦合，必须同时理解空间嵌套关系和同心层规则才能正确着色。

## 新题 7：十字图案检测触发局部反转并按重叠度着色

**组合逻辑**：[模式检测(pattern_detection)](已有原语，检测十字图案) + [反转(invert)](创新：反转范围从全局掩码缩小为检测到的十字的局部邻域) + [计数(counting)](创新：计数对象从条形段变为每个像素被多少个十字邻域覆盖) + [重涂色(recolor)](创新：重涂色由覆盖计数驱动而非固定映射)

**来源原语**：模式检测/十字图案/邻域全匹配(1818057f), 反转/掩码/配对色映射(6ea4a07e), 计数/固定编码表(e048c9ed), 重涂色(多题)

**依赖链**：检测所有符合条件的十字图案中心 -> 以每个中心为原点定义 5x5 邻域 -> 在每个邻域内执行反转（前景变背景、背景变前景） -> 多个邻域重叠处反转被执行多次（偶数次反转等于不变） -> 反转后的前景像素按被覆盖的邻域数量映射颜色

检测前景中的十字图案，在每个十字周围的 5x5 区域执行反转；重叠区域的奇偶反转次数和覆盖邻域数共同决定最终颜色。

**输入结构**：约 13x13 网格，黑(0)背景。网格中有一种前景色（栗(9)）构成若干连通或不连通的前景区域。前景区域中包含 2~4 个十字图案（中心像素的 4 个正交邻居均为前景色），部分十字的 5x5 邻域可能相互重叠。生成约束：所有十字中心与网格边缘至少间隔 2 行/列（保证 5x5 邻域不出界）；至少有一对十字中心间距在 3~4 之间（使得 5x5 邻域产生部分重叠）。

**规则**：
1. 识别所有十字中心：前景色(栗(9))像素且其上下左右 4 个邻居均为前景色(栗(9))。
2. 对每个十字中心，定义以其为中心的 5x5 区域。
3. 对每个像素，计算它被多少个十字中心的 5x5 区域覆盖，记为覆盖数 k。
4. 对每个被至少一个 5x5 区域覆盖的像素（k >= 1），执行如下变换：
   - 若 k 为奇数：原前景像素变为黑(0)，原黑(0)像素变为前景标记。
   - 若 k 为偶数：像素保持原色不变（偶数次反转互相抵消）。
5. 所有经过奇数次反转后变为前景的像素（即原本为黑(0)且 k 为奇数的像素），按 k 值着色：k=1 -> 红(2)，k=3 -> 绿(3)。
6. 所有经过奇数次反转后变为背景的像素（即原本为前景且 k 为奇数的像素）变为黑(0)。
7. 未被任何 5x5 区域覆盖的像素（k=0）保持原色不变。

**关键洞察**：十字检测的结果不仅标记了位置，更定义了反转区域；当两个十字相邻导致区域重叠时，同一像素被反转偶数次回到原样，产生出乎意料的"抵消孔洞"——这是模式检测与反转运算组合后的涌现效应，单独考虑任一操作都无法预见。
