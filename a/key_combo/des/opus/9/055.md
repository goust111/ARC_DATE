## 新题 1：对角连线生成射线阻挡网

**组合逻辑**：[connect/对角补全连接] → [ray_extend/从臂端发射] → [stop_at_fg/遇前景终止]（connect 创造的新几何体成为 ray_extend 的发射源和阻挡物，两步之间存在双向耦合）

**来源原语**：connect, diagonal_fill（参考题 342ae2ed）; ray_extend, emit_from_arm_end, stop_at_fg（参考题 f8be4b64）; same_color_rect_pair（参考题 342ae2ed）

**依赖链**：对角连线在输入中不存在，是第一步的产物；射线以连线端点为发射源，但连线本身也是射线的阻挡物——即第一步的输出同时充当第二步的"起点"和"约束边界"。删除连线则无发射源；删除射线则连线无意义延展。

将同色矩形对用对角线段连接后，从每条线段的两个端点分别向水平和垂直方向发射该颜色的射线，射线遇到任何非背景像素（包括其他对角线段）即终止。

**输入结构**：约 20x20 的黑(0)背景网格。包含 3-4 对同色实心矩形（每对颜色不同，如红(2)、蓝(1)、绿(3)、黄(4)），每个矩形为 2x2 至 3x3 的 4-连通实心块。每对中两个矩形呈对角偏移排列，面对角在 45 度线上。各对矩形互不相邻，且不同对之间留有足够空隙使射线交互产生可观察的终止行为。生成约束：任意两对矩形的对角连线路径不相交。

**规则**：
1. 对每对同色矩形，找到其面对角（上方矩形的较低面角与下方矩形的较高面角），沿 45 度对角线连接两个面角之间的背景像素，用该颜色填涂（不包含已在矩形内的端点像素）。
2. 所有对角连线绘制完毕后，对每条对角线段的两个端点（即面角像素，已存在于矩形中），分别向上、下、左、右四个方向发射射线。射线颜色与该矩形对的颜色相同。
3. 射线逐像素延伸直到遇到非背景像素（包括其他矩形、其他对角线段、或其他射线先绘制的像素）则停止，不覆盖终止像素本身。
4. 射线绘制顺序：按矩形对的颜色编号从小到大处理每对的射线；同一对内四个端点的射线同时绘制（不互相阻挡），但不同对之间先绘制的射线可阻挡后绘制的。

**关键洞察**：对角连线是中间产物而非最终目标——它既提供射线发射源位置，又作为阻挡物截断其他颜色的射线，使最终图案取决于各对之间的空间拓扑关系。

## 新题 2：嵌套深度决定重力下落距离

**组合逻辑**：[nesting_hierarchy/嵌套层次](创新：嵌套深度编码为运动量) + [gravity_drop/重力下落](创新：非均匀下落) + [compress/面积序映射环](提供嵌套检测逻辑)

**来源原语**：nesting_hierarchy, area_order_to_ring（参考题 eb5a1d5d）; gravity_drop, movable_object, obstacle（参考题 825aa9e9）; counting（参考题 d5c634a2）

**依赖链**：嵌套层次分析确定每个对象的深度值 → 深度值决定该对象在重力下落时可移动的最大行数 → 最终位置取决于深度和障碍物的联合约束。三者缺一不可：无嵌套分析则下落距离不确定；无重力规则则嵌套信息无用；无障碍物则无法产生非线性交互。

嵌套层次越深的对象下落距离越短，最外层对象下落最远，最内层几乎不动。

**输入结构**：约 18x18 的黑(0)背景网格。上半区包含 3-4 个嵌套的单色方环（每层颜色不同，如外到内依次为蓝(1)、红(2)、绿(3)、黄(4)），方环为一像素宽的矩形框，严格嵌套（内层完全被外层包围，各层间有至少 1 像素间隔）。下半区有一行灰(5)色的不连续障碍物像素（3-5 个分散的灰色像素构成"地面"）。上半区嵌套方环与下半区障碍物之间有 4-8 行空白。生成约束：嵌套层数为 3 或 4 层；障碍物横向位置需使不同层的方环下落后至少有一层因被障碍物阻挡而不能落到最远距离。

**规则**：
1. 识别所有嵌套方环并确定嵌套深度（最外层深度为 1，次外层为 2，依此类推，最内层深度为 N）。
2. 每个方环整体向下移动，最大移动行数 = (N - depth + 1)，其中 N 是总层数，depth 是该环的深度。即最外层（depth=1）最多移动 N 行，最内层（depth=N）最多移动 1 行。
3. 实际移动时逐行下移，若方环的任何像素的下一行位置已被障碍物或已停止的其他方环像素占据，则该环在当前位置停止（即使未达到最大移动行数）。
4. 处理顺序：从最外层到最内层依次处理下落，外层先落定后作为内层的额外障碍。
5. 障碍物像素和背景保持不变。

**关键洞察**：嵌套深度不是视觉装饰而是物理参数——它反向编码了下落动能，导致原本严格嵌套的结构在输出中发生层间交错或分离，需对比多个示例才能归纳出"深度=动能"的隐蔽规则。

## 新题 3：压缩色序的循环平铺与象限旋转

**组合逻辑**：[compress/连续重复折叠] → [cyclic_shift/循环移位](创新：对压缩后的色序逐行偏移) → [quadrant_rotation/四象限各不同旋转]（三步结构，但后两步同时约束最终输出，非线性流水线）

**来源原语**：compress, stripe_orient, dup_collapsed（参考题 746b3537）; cyclic_shift, ordered_slots（参考题 2601afb7）; quadrant_rotation, tiling（参考题 cf5fd0ad）; color_count_size（参考题 feca6190）

**依赖链**：压缩产生色序（长度 K）→ 色序决定输出尺寸（KxK）→ 循环平铺填充 KxK 的基础方块（第 i 行将色序循环左移 i 位）→ 基础方块经四种旋转拼成 2Kx2K 输出。压缩结果同时影响尺寸、内容和旋转后图案，是全链的信息源头。

将输入色带压缩为色序，以循环偏移方式铺满一个方块，再将该方块按四象限旋转规则拼合为最终输出。

**输入结构**：输入为一个宽度为 1、高度约 9-15 的列向量（即 Nx1 网格），由 3-5 种不同颜色的连续色带组成（如红(2)占 3 行、蓝(1)占 2 行、绿(3)占 4 行、黄(4)占 2 行）。每种颜色的色带厚度不等（至少 2 行），相邻色带颜色不同。不含黑(0)背景色——所有像素均为非黑前景色。

**规则**：
1. 将输入的连续重复颜色折叠为有序色序（如 [红,蓝,绿,黄]），设长度为 K。
2. 构造一个 KxK 的基础方块：第 i 行（i 从 0 开始）的内容是色序循环左移 i 位后的结果。即第 0 行 = 原序，第 1 行 = 色序左移 1 位，第 2 行 = 色序左移 2 位，依此类推。
3. 构造 2Kx2K 的输出，分为四个 KxK 象限：
   - 左上象限：基础方块旋转 180 度
   - 右上象限：基础方块顺时针旋转 90 度
   - 左下象限：基础方块逆时针旋转 90 度
   - 右下象限：基础方块不旋转（原样）
4. 输出为 2Kx2K 的网格。

**关键洞察**：输入是一维的色带，但压缩后的色序长度 K 同时编码了二维输出的尺寸和内容种子——需对比多个示例发现"色序长度 = 方块边长"这一隐藏的尺寸规则，以及每行的循环偏移模式。

## 新题 4：形状匹配决定旋转角度进而决定填充颜色

**组合逻辑**：[shape_matching/形状对应] → [rotation_matching/旋转匹配](创新：旋转量本身成为信息载体) → [recolor/重涂色](旋转量编码颜色映射)

**来源原语**：shape_matching, shape_correspondence, shape_determines_fill（参考题 93b4f4b3）; rotation_matching, hole_area_determines_role（参考题 3a25b0d8）; recolor, color_swap（参考题 2b01abd0）; template, enclosed_hole（参考题 93b4f4b3）

**依赖链**：模板的孔洞需找到匹配的钥匙对象 → 匹配可能需要旋转（0°/90°/180°/270°）→ 所需的旋转角度决定填充颜色（而非钥匙本身的颜色）。形状匹配确定配对，旋转量确定颜色——两个判断层叠加才能确定最终填色。

孔洞与钥匙的形状匹配需要旋转对齐，所需的旋转角度决定了该孔洞的填充颜色。

**输入结构**：约 15x20 的黑(0)背景网格，分为左右两个区域（中间有一列灰(5)分隔线）。左区：一个灰(5)色实心矩形模板（约 8x8），其中挖有 4 个形状各异的背景色孔洞（每个孔洞为 3-5 像素的 4-连通区域，形状不规则且互不相同，无旋转对称性）。右区：4 个分散的小型单色对象（颜色各不相同，分别为红(2)、蓝(1)、绿(3)、黄(4)），每个对象的形状恰好是某个孔洞旋转 0°、90°、180° 或 270° 后的结果。生成约束：4 个孔洞的旋转量恰好覆盖 0°、90°、180°、270° 各一次；每个钥匙对象与恰好一个孔洞匹配。

**规则**：
1. 对左区模板中的每个孔洞，提取其归一化形状掩码（平移到原点）。
2. 对右区每个钥匙对象，提取其归一化形状掩码。
3. 将每个钥匙尝试旋转 0°、90°、180°、270° 与各孔洞匹配，找到唯一匹配对。
4. 根据匹配所需的旋转角度确定填充颜色：0° → 红(2)，90° → 蓝(1)，180° → 绿(3)，270° → 黄(4)。
5. 输出仅为左区模板部分（紧凑裁剪），每个孔洞填充步骤 4 确定的颜色。钥匙对象自身的颜色不影响输出。

**关键洞察**：钥匙对象的颜色是干扰项——真正决定填色的是匹配所需的旋转量，这只有对比多个示例（观察到钥匙颜色与填充颜色不一致，而旋转量与填充颜色一致）才能归纳。

## 新题 5：轨道滑动后留下互补印记

**组合逻辑**：[sliding/沿轨道进一槽位](创新：滑动多槽) + [stamp_overlay/互补掩码](创新：在经过位置留印) + [counting](创新：像素数决定滑动距离)

**来源原语**：sliding, advance_one_slot, track_dot, evenly_spaced（参考题 5168d44c）; stamp_overlay, complement_mask, self_complementary（参考题 0692e18c）; counting（参考题 d5c634a2）; tight_bbox_extraction（参考题 1cf80156）

**依赖链**：对象的像素数量决定滑动步数 → 每经过一个轨道槽位留下互补掩码印记 → 终点位置放置原始对象。像素计数是运动量的编码；互补掩码依赖对象自身形状；最终输出同时包含"路径痕迹"和"终态位置"。

一个对象沿轨道滑动，滑动距离由其自身像素数决定，经过的每个中间槽位留下其互补掩码的印记。

**输入结构**：约 15x20 的黑(0)背景网格。一条由绿(3)色像素构成的水平轨道（在同一行上等间距排列 6-8 个绿色单像素点，间距为 3 像素）。一个红(2)色的 4-连通小型精灵体（3-6 像素，非矩形，有明确的互补结构），其边界框对齐在轨道的最左侧槽位上（精灵体中心行与轨道行对齐）。生成约束：精灵体像素数不超过轨道剩余槽位数；精灵体边界框宽高不超过轨道间距。

**规则**：
1. 计算红色精灵体的像素数 P。
2. 精灵体沿轨道向右滑动 P 个槽位（从槽位 0 到槽位 P）。
3. 对于经过的每个中间槽位（槽位 1 到槽位 P-1），在该槽位位置放置精灵体边界框的互补掩码：即边界框内原来是背景的位置填红(2)色，原来是红色的位置保持背景。互补印记的颜色为橙(7)。
4. 在最终位置（槽位 P）放置原始红(2)色精灵体。
5. 起始位置（槽位 0）变为背景（精灵体已离开）。
6. 绿色轨道点保持不变（若被印记或精灵体覆盖则精灵体/印记优先）。

**关键洞察**：精灵体的像素数不仅是形态特征还是运动参数——它编码了滑动距离，需对比不同像素数的精灵体在多个示例中的滑动结果才能发现这一对应关系。

## 新题 6：对称轴借用后按距离分级缩放

**组合逻辑**：[axis_borrowed/对称轴借用] + [pixel_scale/倍增缩放序列](创新：缩放因子由到轴距离决定) + [symmetry_completion/借轴复制非对称体]（缩放和对称交织：先缩放再对称，缩放量依赖轴位置）

**来源原语**：axis_borrowed, symmetric_object, asymmetric_object, symmetry_completion（参考题 4c5c2cf0）; pixel_scale, power_of_two_scaling, successive_placement（参考题 762cd429）; distance_preserved（参考题 1a244afd）

**依赖链**：对称体提供对称轴 → 非对称小精灵到轴的距离决定缩放因子 → 缩放后的精灵再沿该轴做镜像补全。轴同时是缩放参数的来源和镜像操作的执行者——两个用途紧耦合于同一几何元素。

非对称精灵按其到对称体轴线的距离进行像素放大，然后沿该轴镜像补全。

**输入结构**：约 20x20 的黑(0)背景网格。中央有一个灰(5)色的、具有垂直对称轴的对称体（如 5x7 的左右对称图形）。在对称体的对称轴一侧（如左侧），散布 2-3 个小型单色精灵体（每个 2-4 像素，颜色各不同，如红(2)、蓝(1)、绿(3)），它们到对称轴的水平距离各不相同（分别为 1、2、3 格距离，从精灵体最近边缘到轴线计算）。生成约束：精灵体足够小使得最大缩放后不超出网格；各精灵体的缩放结果互不重叠；精灵体全部在轴的同一侧。

**规则**：
1. 识别灰色对称体，确定其垂直对称轴（列坐标）。
2. 对轴一侧的每个彩色精灵体，计算其到轴的距离 D（精灵体最近像素到轴的列数差）。
3. 将每个精灵体以 2^(D-1) 为因子进行像素放大（D=1 时不放大，D=2 时每像素变 2x2，D=3 时每像素变 4x4）。放大后的精灵体保持其最近边缘到轴的距离不变（即向远离轴方向膨胀）。
4. 将每个放大后的精灵体沿对称轴做镜像，在轴的另一侧对称位置绘制相同颜色的镜像副本。
5. 灰色对称体保持不变。若镜像副本与对称体重叠，彩色像素覆盖灰色。

**关键洞察**：对称轴不只是镜像工具，还隐式编码了缩放规则——距离越远放大越多，这是一个空间位置到变换强度的隐蔽映射，仅看单个精灵体无法确认是距离而非颜色或面积决定缩放因子。

## 新题 7：格子框架内重力下落后跨框架色序推断

**组合逻辑**：[gravity_drop](创新：在格子槽位内部执行) + [cross_frame_match/跨框架对应] + [infer/槽位位置决定颜色]（重力改变了源信息的布局，推断必须基于重力后的结果——操作 A 的输出改变了操作 B 的触发条件）

**来源原语**：gravity_drop, movable_object（参考题 825aa9e9）; lattice_frame, lattice_slot, cross_frame_match, slot_position_color, infer（参考题 2e65ae53）; fill（参考题 93b4f4b3）

**依赖链**：格子框架内的彩色像素先经重力下落沉到各槽位底部 → 下落后的颜色布局才是"真实源信息"→ 跨框架推断基于下落后的布局确定每个逻辑槽位的颜色 → 用推断结果填充所有框架的空槽位。删除重力则源信息错误；删除推断则无法填充目标。

格子框架内的散落像素先经重力下落到槽位底部，再根据下落后的分布跨框架推断每个槽位应有的颜色。

**输入结构**：约 20x25 的黑(0)背景网格。包含 3 个相同逻辑结构的灰(5)色一像素宽矩形格子框架（每个框架为 2 行 x 3 列的槽位布局，即 2x3=6 个矩形槽位，每个槽位内部约 3x3 像素）。三个框架在网格中水平排列，间隔 2 像素。部分槽位内散布着 1-2 个彩色单像素（颜色为红(2)、蓝(1)、绿(3)、黄(4)之一），像素位于槽位内部的任意行（不一定在底部）。每个逻辑槽位位置（如"第 1 行第 2 列"）在三个框架中至少有一个框架包含彩色像素。生成约束：同一逻辑位置在不同框架中若有颜色像素，重力下落后底部行显示的颜色必须一致（保证可推断性）。

**规则**：
1. 对每个格子框架内部，将所有彩色像素在各自所在槽位内向下做重力下落（落到槽位底部行，或落到同槽位内另一彩色像素上方）。框架线和背景不动。
2. 重力下落完成后，对每个逻辑槽位位置（行号, 列号），观察三个框架中该位置槽位底部行的颜色。取出现的非背景颜色作为该位置的"真实颜色"。
3. 用推断出的真实颜色填充所有三个框架中对应槽位的整个内部区域（整个槽位内部统一填该颜色）。
4. 框架线（灰色）和网格背景保持不变。

**关键洞察**：散落像素的初始位置是干扰——必须先做重力归位才能正确读取颜色信息，直接按像素初始位置推断会得到错误结果。这一"先物理模拟再信息提取"的顺序需要对比示例才能发现。

## 新题 8：朝向分类决定对角轨迹方向与循环配色

**组合逻辑**：[classify/朝向分组] → [diagonal_trace/逐步平移](创新：轨迹方向由朝向决定) + [cyclic_shift/色与高反向轮转](创新：轨迹颜色沿序列循环)

**来源原语**：classify, orient_group, orient_determines_panel（参考题 d5c634a2）; diagonal_trace, stepwise_translation（参考题 feca6190）; cyclic_shift, ordered_slots（参考题 2601afb7）; color_count_size（参考题 feca6190）

**依赖链**：精灵体的朝向分类确定其对角运动方向（上左/上右/下左/下右）→ 精灵体在输出中沿该方向逐步平移留下轨迹 → 轨迹中每一步的颜色从一个有序色序中循环取值。朝向→方向→颜色三层编码，删除分类则方向不确定，删除循环色则轨迹单调无法验证规则。

按精灵体朝向分类确定对角运动方向，运动轨迹的颜色按循环色序逐步变化。

**输入结构**：约 20x20 的黑(0)背景网格。包含 4-6 个灰(5)色小型精灵体（每个 3-5 像素，4-连通），每个精灵体有明确的朝向特征（通过不对称结构判断：如有一个"尖端"像素，尖端方向即朝向——上、下、左、右之一）。网格底部有一行由 3-4 种不同颜色像素构成的色序条（如从左到右依次为：红(2)、蓝(1)、绿(3)、黄(4)各一个像素，紧密相邻），作为颜色参考。生成约束：各精灵体之间留有足够空间使轨迹不重叠；四种朝向至少出现两种。

**规则**：
1. 识别底部色序条，读取从左到右的有序色序（如 [红, 蓝, 绿, 黄]，长度为 C）。
2. 对每个灰色精灵体，识别其朝向（尖端方向）：
   - 尖端朝上 → 对角方向为右上（每步行-1, 列+1）
   - 尖端朝下 → 对角方向为左下（每步行+1, 列-1）
   - 尖端朝左 → 对角方向为左上（每步行-1, 列-1）
   - 尖端朝右 → 对角方向为右下（每步行+1, 列+1）
3. 从每个精灵体的尖端像素出发，沿其对角方向逐步平移绘制轨迹像素。第 k 步（k 从 1 开始）的颜色为色序中第 ((k-1) mod C) 个颜色。
4. 轨迹绘制直到下一步位置超出网格边界或遇到非背景像素为止。
5. 原始灰色精灵体保持不变。色序条保持不变。

**关键洞察**：朝向不仅是分类标签还是运动矢量的编码——"上"映射到"右上对角"而非直线向上，这一非直觉的方向映射需要对比多个不同朝向精灵体的轨迹才能归纳出规则。

## 新题 9：镜像轴上的连线桥接决定颜色互换区域

**组合逻辑**：[mirror/分隔线为对称轴] + [connect/对角补全连接](创新：连线跨越分隔线) + [color_swap/原位颜色互换](创新：互换范围由连线桥接关系决定)

**来源原语**：mirror, separator_line, separator_as_reflection_axis, color_swap, in_place_color_swap, two_color_source_pattern（参考题 2b01abd0）; connect, same_color_rect_pair, diagonal_offset（参考题 342ae2ed）; fill（参考题 2e65ae53）

**依赖链**：分隔线两侧有成对的同色像素 → 同色对跨分隔线做直线连接（线段穿过分隔线）→ 被连线穿过的分隔线区段标记为"激活区段"→ 分隔线的激活区段对应行/列上的所有源图案像素执行颜色互换。连线决定哪些位置被激活，激活决定哪些像素互换——两步判断缺一不可。

跨分隔线的同色对通过连线"激活"分隔线上的区段，被激活区段对应的行内像素执行颜色互换。

**输入结构**：约 15x15 的黑(0)背景网格。中间有一条完整的灰(5)色垂直分隔线（占据一整列）。分隔线左侧有一个由红(2)和蓝(1)两种颜色构成的图案（约 5-8 像素，形状不规则）。分隔线两侧各散布 2-3 个黄(4)色单像素，左侧的每个黄色像素与右侧恰好一个黄色像素在同一行（构成水平对齐的同色对）。生成约束：黄色像素对所在的行不全相同（至少 2 个不同的行）；左侧图案在被激活行和未被激活行都有像素。

**规则**：
1. 找到所有跨分隔线的黄(4)色同行像素对。
2. 对每对黄色像素，画一条水平连线（用黄(4)色填充两像素之间的所有背景像素，包括穿过分隔线的部分——分隔线上该行的像素变为黄色）。
3. 分隔线上变为黄色的行即"激活行"。
4. 对左侧的红蓝双色图案：位于激活行上的像素执行颜色互换（红变蓝，蓝变红）；不在激活行上的像素保持原色。
5. 将颜色互换后的左侧图案整体镜像复制到分隔线右侧的对称位置（右侧对称区域原来应为背景）。
6. 黄色连线、分隔线（未被激活的行仍为灰色）、右侧黄色像素均保持。

**关键洞察**：黄色像素对不是装饰而是"开关"——它们通过连线物理地激活分隔线上的特定行，进而选择性地触发颜色互换。镜像操作作用于互换后的结果，所以右侧图案并非左侧的简单镜像。

## 新题 10：嵌套环面积序排列后按序做象限旋转平铺

**组合逻辑**：[sorting/面积序映射环](创新：排序结果决定平铺顺序) + [tiling/平铺] + [quadrant_rotation/四象限各不同旋转](创新：旋转角度由排列序号决定) + [crop/紧凑包围盒提取]

**来源原语**：sorting, nesting_hierarchy, area_order_to_ring（参考题 eb5a1d5d）; tiling, quadrant_rotation（参考题 cf5fd0ad）; crop, tight_bbox_extraction（参考题 1cf80156）; pixel_scale（参考题 762cd429）

**依赖链**：多个分散对象按面积排序得到序号 → 序号决定该对象在 2x2 象限平铺中的位置 → 每个象限位置有固定旋转角度 → 对象先裁剪到紧凑包围盒再旋转后放入对应象限。排序是位置分配的依据，位置决定旋转——改变任何一个对象的面积都会打乱全局布局。

将多个分散对象按面积从小到大排序，依序放入 2x2 象限网格中，每个象限施加不同旋转。

**输入结构**：约 18x18 的黑(0)背景网格。包含恰好 4 个分散的单色精灵体（颜色各不相同，如红(2)、蓝(1)、绿(3)、黄(4)），每个精灵体为 4-连通不规则形状，像素数互不相同（如分别为 3、5、7、9 像素）。各精灵体互不相邻，位置随机散布。生成约束：4 个精灵体的面积严格不等（无并列）；每个精灵体的紧凑包围盒不超过 4x4。

**规则**：
1. 识别 4 个精灵体，计算每个的像素面积，按面积从小到大排序（面积最小为序号 1，最大为序号 4）。
2. 对每个精灵体做紧凑包围盒裁剪。
3. 确定输出尺寸：设最大包围盒的边长为 M（取宽和高的最大值，所有精灵体中最大者），输出为 2M x 2M 的黑色网格。
4. 将每个裁剪后的精灵体放入 2x2 象限中对应位置（每个象限为 MxM），放置前先施加旋转，精灵体在象限内居左上角对齐：
   - 序号 1（最小面积）→ 右下象限，不旋转
   - 序号 2 → 右上象限，顺时针旋转 90 度
   - 序号 3 → 左上象限，旋转 180 度
   - 序号 4（最大面积）→ 左下象限，逆时针旋转 90 度
5. 输出为 2M x 2M 的网格。

**关键洞察**：对象在输入中的空间位置完全无关——决定输出布局的唯一因素是面积排名，而面积排名又隐式编码了旋转角度和象限位置的对应关系。需对比多个示例才能确认是"面积顺序"而非"颜色"或"位置"决定放置规则。
