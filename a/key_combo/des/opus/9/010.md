## 新题 1：折叠投射定色洪填

**组合逻辑**：[折叠(fold)](创新：折叠不是为了叠加图案，而是建立指示像素到墙壁分区的空间映射) + [洪泛填充(flood_fill)](创新：填充目标区域由折叠后指示像素的落点决定，而非同面板中的固定位置) + [内外分区(inside_outside_partition)](已有原语，作为区域划分基础)

**来源原语**：折叠(fold)←e3497940, 洪泛填充(flood_fill)←7491f3cf, 墙壁边界(wall_boundary)←7491f3cf, 指示像素(indicator_pixel)←7491f3cf, 分隔线(separator_line)←e3497940, 内外分区(inside_outside_partition)←7491f3cf

**依赖链**：折叠操作将右半区的指示像素镜像映射到左半区的坐标系 → 每个指示像素的落点确定它属于哪个墙壁分隔区域 → 洪泛填充以落点为种子、以墙壁为障碍扩散，将整个区域涂为该指示像素的颜色。删除折叠则指示像素与区域失去对应关系；删除墙壁则无法划分区域；删除洪泛填充则无法着色。

将右半区的彩色指示像素通过折叠投射到左半区的墙壁分区中，每个像素为它落入的区域指定填充颜色。

**输入结构**：网格约 13x11（奇数宽度以容纳中央分隔列），黑(0)背景。中央有一整列灰(5)像素从顶到底作为垂直分隔线，将网格分为等宽的左右两半（各 6 列）。左半区：绿(3)像素构成 4-连通的墙壁路径，从左边界或分隔线延伸至另一侧边界或分隔线，将左半区划分为 3-4 个互不相通的封闭区域（仅被墙壁和网格边缘包围的 4-连通黑(0)连通分量）。右半区：3-4 个孤立的单像素指示点，颜色各不相同且均为非黑(0)、非灰(5)、非绿(3)的颜色（例如蓝(1)、红(2)、黄(4)、品红(6)）。生成约束：右半区的每个指示像素经水平镜像后恰好落入左半区的某个封闭区域内部（不落在墙壁像素上），且每个封闭区域恰好接收一个指示像素。

**规则**：
1. 将右半区以分隔列为对称轴做水平镜像，计算每个指示像素在左半区坐标系中的对应位置（列坐标关于分隔列对称翻转）。
2. 移除分隔列和原始右半区，输出仅保留左半区尺寸（高度不变，宽度 = 左半区宽度）。
3. 对每个镜像后的指示像素位置，从该位置出发做 4-连通洪泛填充，以绿(3)墙壁像素和网格边缘为阻挡边界，找到该位置所属的封闭区域。
4. 将该封闭区域内所有黑(0)背景像素涂为该指示像素的颜色。
5. 保持所有绿(3)墙壁像素不变。
6. 处理顺序不影响结果（因为每个区域恰好对应一个指示像素，无冲突）。

**关键洞察**：折叠不是为了叠加两半的图案（如参考题 e3497940 中的互补合并），而是作为空间投射机制——右半区的指示像素必须经过折叠才能确定它对应左半区的哪个分区。求解者需先在脑中完成镜像，再判断每个指示像素"落入"哪个墙壁围成的区域。

## 新题 2：掩码条件分叉的差异化环旋转

**组合逻辑**：[解码(decode) + 掩码匹配(mask_matching)](创新：解码出的掩码不用于重涂色，而是作为条件分叉选择器) → [循环移色(color_cycle)](创新：环的两种子循环不再同时执行，而是由掩码位置选择性地只触发其中一种)

**来源原语**：循环移色(color_cycle)←46c35fc7, 角位像素(corner_pixel)←46c35fc7, 边中像素(side_center_pixel)←46c35fc7, 反向循环(opposite_cycle)←46c35fc7, 角与边中分组(corner_side_group)←46c35fc7, 掩码匹配(mask_matching)←15113be4, 块解码为掩码(decode_block_to_mask)←15113be4, 指令区域(instruction_region)←15113be4, 格子分割(lattice_partition)←15113be4

**依赖链**：指令区域中的 2x2 色块被解码为 3x3 二值掩码 → 掩码的每个位与环阵列中的环一一对应 → 掩码值为 1 的环只执行角位循环、掩码值为 0 的环只执行边中循环。删除掩码则不知道每个环该做哪种旋转；删除环的双子循环结构则掩码无差异化目标。

通过解码指令区域得到 3x3 掩码，控制 3x3 排列的环形对象各自执行角位循环还是边中循环。

**输入结构**：网格约 17x11，黑(0)背景。网格分为上下两区，由一整行灰(5)像素分隔。上区（指令区）：6x6 的区域，内含 2x2 大小的橙(7)色块（0-9 个），排列在 3x3 的位置网格中（每个位置占 2x2 像素），其余位置为黑(0)。下区（环阵列区）：9 个 3x3 环形对象排成 3 行 3 列，相邻环之间隔 1 列和 1 行黑(0)背景。每个环由 8 个非黑前景像素组成（中心位置为黑(0)），分布在 3x3 的八个边界位置。每个环使用 2-4 种不同的非黑颜色（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取），分配到 8 个像素上。生成约束：上区的 3x3 位置网格与下区的 3x3 环阵列一一对应（相同行列索引）；上区至少有 2 个位置有橙(7)块、至少 2 个位置无橙(7)块。

**规则**：
1. 解码上区指令为 3x3 二值掩码 M：位置 (r,c) 的 2x2 区域全部为橙(7)时 M[r][c]=1，否则 M[r][c]=0。
2. 对下区中位置 (r,c) 的环形对象：
   - 若 M[r][c]=1：将四个角位像素（左上、右上、右下、左下）的颜色顺时针轮转一步（左上色→右上，右上色→右下，右下色→左下，左下色→左上）。四个边中像素保持不变。
   - 若 M[r][c]=0：将四个边中像素（上中、右中、下中、左中）的颜色顺时针轮转一步（上中色→右中，右中色→下中，下中色→左中，左中色→上中）。四个角位像素保持不变。
3. 上区的指令区域像素和所有黑(0)背景像素保持不变。

**关键洞察**：掩码不决定"哪些环被变换"（所有环都被变换），而是决定"每个环执行哪种变换"。角位循环和边中循环是同一个环上两条独立的 4-元素轮转通路，掩码在每个环的位置上选择其中一条通路。需要对比多个示例才能确定掩码值 1 和 0 分别对应角位还是边中循环。

## 新题 3：拓扑孔洞驱动的精灵体分级重复

**组合逻辑**：[计数(counting)](创新：计数的对象是连通分量内部的拓扑孔洞，而非独立标记点) → [排序(sorting)](创新：排序键不是长度或位置，而是孔洞数) → [重复(repeat) + 重涂色(recolor)](创新：重复次数由拓扑分析结果驱动，颜色从被分析对象传递到被重复对象)

**来源原语**：计数(counting)←0a2355a6/4852f2fa, 封闭区域(enclosed_region)←0a2355a6, 连通分量(connected_component)←0a2355a6, 按孔洞数映射颜色(hole_count_to_color_mapping)←0a2355a6, 重复(repeat)←4852f2fa, 精灵体(sprite)←4852f2fa, 排序(sorting)←ea32f347, 重涂色(recolor)←ea32f347, 忽略干扰项(ignore_distractors)←0a2355a6

**依赖链**：每个轮廓对象的拓扑孔洞数被计数 → 孔洞数同时充当两个角色：(a) 作为排序键将轮廓按孔洞数升序排列确定输出行序，(b) 作为重复次数确定该行中精灵体副本数 → 每组副本的颜色从对应轮廓对象继承。删除拓扑计数则重复次数和排序键均不可知；删除精灵体则无可重复的模板；删除排序则输出行序不确定。

从每个闭合轮廓的孔洞数推导出精灵体的重复次数和输出排列顺序，轮廓颜色传递给对应的精灵体副本。

**输入结构**：网格约 20x15，黑(0)背景。包含 3-4 个闭合轮廓对象，每个轮廓是单一非黑颜色的 4-连通像素集合，形成一个封闭边界（内部包含 1 到 4 个不等的 4-连通黑(0)孔洞）。轮廓颜色各不相同（例如蓝(1)、红(2)、绿(3)、黄(4)），轮廓之间不相邻不重叠，最小间距 2 像素。各轮廓的孔洞数互不相同。另有一个灰(5)的小型精灵体（3-6 像素的 4-连通小图形，边界框不超过 3x3），位于远离所有轮廓的空旷区域。生成约束：轮廓形状在不同示例中各异（不固定为特定几何形状），仅保证孔洞数一致即可；精灵体形状在同一道题的各示例中保持一致。

**规则**：
1. 识别所有闭合轮廓对象（非灰(5)的 4-连通非黑色区域），计算每个轮廓边界框内被轮廓完全包围的 4-连通黑(0)区域数量（即孔洞数 H）。
2. 提取灰(5)精灵体的最小边界框作为模板（边界框内非灰像素视为黑(0)背景）。设模板尺寸为 W_s x H_s。
3. 将轮廓按孔洞数 H 升序排列。
4. 输出网格宽度 = H_max x W_s（H_max 为最大孔洞数），高度 = 轮廓数量 x H_s。
5. 对排序后第 i 个轮廓（孔洞数为 H_i，颜色为 C_i）：在输出的第 i 行区域（行范围 [i*H_s, (i+1)*H_s)）中，从左侧起水平放置 H_i 个精灵体模板副本，每个副本中灰(5)像素替换为 C_i。剩余位置填黑(0)。
6. 输入中的灰(5)精灵体和所有轮廓对象不出现在输出中——输出完全由重排后的精灵体副本和黑(0)背景构成。

**关键洞察**：轮廓对象的具体形状和大小是干扰项，唯一有意义的属性是其拓扑孔洞数。该数值同时承担双重角色——既是排序键（决定输出中的垂直位置），又是重复次数（决定水平方向的精灵体副本数）。参考题 0a2355a6 中孔洞数映射到固定色表，参考题 4852f2fa 中重复次数由独立标记点计数；本题将拓扑分析的结果直接作为另一个对象的重复参数，两者形成源题中不存在的跨对象参数传递关系。

## 新题 4：图例解析线段交叉的重涂色

**组合逻辑**：[连线(draw_line) + 同色配对(same_color_pairing)](已有原语，作为交叉事件的生成器) → [图例(legend) + 颜色映射(color_mapping)](创新：图例不用于扩展填充或瓦片重涂，而是仅在线段交叉点被激活的查找表) → 交叉检测作为触发事件连接两个子系统

**来源原语**：连线(draw_line)←40853293, 同色配对(same_color_pairing)←40853293, 行列对齐(row_col_align)←40853293, 竖线交叉优先(vertical_priority_at_cross)←40853293, 图例(legend)←305b1341, 图例配色(legend_color_pair)←305b1341, 颜色映射(color_mapping)←b0722778

**依赖链**：同色像素对通过连线形成水平或垂直线段 → 线段在空间中相交产生交叉点 → 交叉点处取竖直线段的颜色作为查找键 → 在图例中查找该颜色对应的映射颜色 → 交叉像素被重涂为映射颜色。删除连线则无交叉事件；删除图例则交叉点颜色无从确定（不再是简单的竖直优先）；删除交叉检测则图例无触发条件。

连接同色像素对形成线段，在线段交叉处查阅图例将竖直线段的颜色替换为图例映射的颜色。

**输入结构**：网格约 15x15，黑(0)背景。左侧两列（第 0、1 列）为图例区：从第 0 行开始，每行的第 0 列是源颜色、第 1 列是映射颜色，连续排列 2-4 行图例条目，其余行为黑(0)。图例区与主区之间第 2 列全为黑(0)作为间隔。主区（第 3 列起）：散布若干同色像素对，每种颜色恰好出现 2 次，同色的两个像素共享行或共享列。颜色使用 3-5 种不同的非黑色（例如蓝(1)、红(2)、绿(3)、黄(4)、品红(6)）。生成约束：至少存在 2 个交叉点（一条水平线段与一条竖直线段在某像素重合）；所有参与竖直线段的颜色均在图例的源颜色列中出现；图例的映射关系至少有一条不是恒等映射（源色和映射色不同）；水平线段的颜色可以不在图例中。

**规则**：
1. 在主区中，对每对同色像素，沿它们共享的行或列填充两者之间（含端点）的所有像素为该颜色，形成线段。
2. 识别所有交叉点：恰好有一条水平线段和一条竖直线段经过同一像素的位置。
3. 在每个交叉点处：取竖直线段的颜色 C_v，在图例中查找 C_v 对应的映射颜色 C_m，将该交叉像素重涂为 C_m。
4. 若竖直线段的颜色 C_v 不在图例源颜色列中，则该交叉点保留 C_v 不变（图例未提供映射时退化为竖直优先）。
5. 非交叉位置的线段像素保持原色不变。
6. 图例区域在输出中保持原样不变。

**关键洞察**：图例不是全局生效的颜色替换表——它仅在交叉事件发生时被查阅，使交叉点成为激活图例的"触发器"。求解者必须先画出所有线段、识别交叉位置，然后才能判断哪些颜色需要被图例映射。参考题 40853293 中交叉点用固定几何规则（竖直优先）解决；参考题 305b1341 中图例驱动全局矩形扩展。本题中交叉检测和图例查找形成事件驱动的耦合关系，两者在源题中互不相关。

## 新题 5：多条排序拼接的彩色换行序列

**组合逻辑**：[排序(sorting) + 长度排名(length_ranking)](创新：排序不用于重涂色而用于确定序列生成顺序) → [生成序列(generate_seq) + 换行平铺(wrap_tile)](创新：序列不由单一控制条驱动，而由多条不同颜色、不同长度的条联合编码——每条贡献一段游程)

**来源原语**：排序(sorting)←ea32f347, 长度排名(length_ranking)←ea32f347, 细条(thin_bar)←ea32f347, 生成序列(generate_seq)←5d588b4d, 换行平铺(wrap_tile)←5d588b4d, 控制条(control_bar)←5d588b4d, 条长决定序列(bar_length_seq)←5d588b4d

**依赖链**：多条不同颜色的细条被测量长度 → 按长度升序排序确定序列中游程的先后顺序 → 每条的长度同时成为对应游程的长度、每条的颜色成为该游程的颜色 → 游程序列以输入网格宽度为行宽换行铺展成二维输出。删除排序则游程顺序不确定；删除任一条则该游程从序列中缺失；删除换行则一维序列无法成为二维输出。

将多条不同颜色、不同长度的细条按长度升序排列，每条贡献一段等长等色的游程，拼接后按输入宽度换行铺成二维网格。

**输入结构**：网格约 12x12，灰(5)背景。包含 3-5 条细条（每条厚度 1 像素，水平或竖直放置），每条颜色各不相同且均非灰(5)、非黑(0)（例如蓝(1)、红(2)、绿(3)、黄(4)、品红(6)），每条长度各不相同（范围 2-7 像素）。条之间互不相邻（最小间距 1 像素背景）。生成约束：所有游程长度之和加上相邻游程间的分隔符像素数（游程数-1）不超过输入网格宽度 x 输入网格高度（保证能铺满或部分铺满）。

**规则**：
1. 识别所有细条，测量每条的像素长度 L 和颜色 C。
2. 按长度 L 升序排列（最短在前）。
3. 构建一维序列：依次拼接每条的游程段，每段为 L 个连续的颜色 C 像素。相邻两段之间插入 1 个灰(5)分隔像素。
4. 将该一维序列按输入网格的宽度 W 进行行主序换行：序列的第 0 至 W-1 个像素填入第 0 行，第 W 至 2W-1 个像素填入第 1 行，依此类推。
5. 若最后一行不足 W 个像素，用灰(5)背景补齐。
6. 输出网格宽度 = W（与输入相同），高度 = 容纳完整序列所需的最少行数。

**关键洞察**：每条细条是一个双属性编码单元——长度编码游程长度，颜色编码游程颜色，两个属性不可分离。参考题 5d588b4d 中单一控制条的长度 n 生成对称的递增递减序列（1,2,...,n,...,2,1），参考题 ea32f347 中条被排序后重涂为固定色表。本题中多条联合编码一个非对称的多色序列，排序决定了拼接顺序，每条同时贡献长度和颜色——这种"多源联合编码"的生成模式在两道源题中均不存在。

## 新题 6：方向-距离-优先级三重编码的印章链

**组合逻辑**：[印章覆盖(stamp_overlay)](创新：印章方向和重复次数不再由单像素指示器给出，而由邻接条的空间位置和长度同时编码) + [邻接触碰(adjacency_touch)](已有原语) + [长度排名(length_ranking) → 冲突优先级(conflict_priority)](创新：条的长度排名不用于重涂色，而用于决定印章副本重叠时的绘制优先级)

**来源原语**：印章覆盖(stamp_overlay)←007bbfb7, 模板(template)←e8dc4411, 邻接触碰(adjacency_touch)←e8dc4411, 指示决定方向色(indicator_dir_color)←e8dc4411, 长度排名(length_ranking)←ea32f347, 冲突优先级(conflict_priority)←305b1341, 重复(repeat)←4852f2fa

**依赖链**：每条邻接条相对模板的位置确定印章方向 → 每条的像素长度确定该方向上的印章副本数 → 副本被涂为该条的颜色 → 当两个方向的副本在空间上重叠时，长度更短的条的副本覆盖长度更长的条的副本（短条→少副本→高优先级）。删除邻接方向则不知道往哪个方向印章；删除条长则不知道印几份；删除优先级则重叠区域颜色不确定。

模板精灵体的邻接彩色条同时编码印章方向、重复次数和重叠优先级：条的位置指方向，条的长度定副本数，短条在重叠时覆盖长条。

**输入结构**：网格约 15x15，黑(0)背景。中央偏中的位置有一个灰(5)模板精灵体：4-连通的单色小图形（4-8 像素，边界框不超过 4x4）。模板的不同侧面各 4-邻接一条彩色细条（厚度 1 像素，水平或竖直），共 2-4 条。每条颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中选取），长度各不相同（范围 2-5 像素）。条的放置方向与其触碰模板的那一侧一致（例如条在模板右侧则条为水平向右延伸，条在模板上方则条为竖直向上延伸）。生成约束：每条触碰模板的不同侧（上、下、左、右各最多一条）；条之间互不接触；模板到网格边缘在每个有条的方向上至少留有 (该条长度 x 模板该方向尺寸 + 1) 像素的空间。

**规则**：
1. 识别灰(5)模板精灵体的边界框（尺寸 W_t x H_t）和形状掩码。
2. 对每条邻接条（颜色 C、长度 L）：
   a. 确定条相对于模板中心的方向 D（上、下、左、右之一）——取条的质心相对于模板质心的方向。
   b. 在方向 D 上，从模板的外侧边缘起，依次放置 L 个模板副本。每个副本的位置相对于前一个副本在方向 D 上平移一个模板边界框尺寸（水平方向平移 W_t，竖直方向平移 H_t）。
   c. 每个副本中灰(5)像素替换为 C。
3. 当两个不同方向的副本在某像素重叠时，取来源条长度更短的那一方的颜色（短条=少副本=高优先级）。若长度相同（生成时已排除此情况），取先处理的方向。
4. 原始灰(5)模板保留不变。条本身的像素在输出中移除（替换为黑(0)背景）。

**关键洞察**：每条邻接条是一个三属性编码信号——空间位置编码方向、像素数编码重复次数、长度排名反向编码重叠优先级（越短越优先）。参考题 e8dc4411 中单像素指示器只编码方向和颜色，无重复次数控制；参考题 ea32f347 中长度排名只用于固定色表重涂。本题中"短条优先"的冲突解决规则需要对比多个示例中不同长度条在重叠区域的表现才能归纳出来。

## 新题 7：标记计数参数化的周期选取重涂

**组合逻辑**：[计数(counting)](创新：计数的对象不是精灵体的重复源，而是成为选取步长的元参数) → [每隔N选取(every_nth_selection) + 按位置排序(sort_by_position)](创新：N 不是固定常数 3，而是由标记像素数动态决定) → [重涂色(recolor)](已有原语)

**来源原语**：计数(counting)←4852f2fa, 单像素标记(singleton_marker)←4852f2fa, 标记计数驱动重复(marker_count_drives_repetition)←4852f2fa, 每隔N选取(every_nth_selection)←22a4bbc2, 按位置排序(sort_by_position)←22a4bbc2, 横条(horizontal_bar)←22a4bbc2, 重涂色(recolor)←22a4bbc2

**依赖链**：散布的标记像素被计数得到 N → 横条按垂直位置排序得到有序序列 → 从序列中每隔 N 个选取一个横条（第 1、第 1+N、第 1+2N...）→ 被选中的横条重涂为红(2)。删除标记则 N 不可知；删除排序则选取序列不确定；删除选取规则则不知道哪些横条被重涂。

计数散布的标记像素得到步长 N，在按位置排序的横条序列中每隔 N 个选取并重涂为红色。

**输入结构**：网格约 14x20，黑(0)背景。包含 6-10 条青(8)水平横条，每条厚度 1 像素，宽度各异（至少 3 像素），分布在不同行（各行最多一条），不与其他元素接触。另有 2-4 个孤立的黄(4)单像素标记，分散在网格中远离横条的位置（与任何横条的最近距离至少 2 像素）。生成约束：标记数量 N 满足 2 <= N <= 4；横条数量至少为 2N+1（保证至少选中 3 条，使周期模式足够明显）；不同示例中标记数量不同（以便求解者对比后发现 N 是变量而非固定值）。

**规则**：
1. 计数所有黄(4)单像素标记的数量，记为 N。
2. 将所有青(8)横条按其所在行号升序排列（行号小的排在前），若行号相同则按最左列号升序排列。给排列后的横条编号 1, 2, 3, ...
3. 选取编号为 1, 1+N, 1+2N, 1+3N, ... 的横条（即从第 1 条开始，每隔 N 条选一条），将它们重涂为红(2)。
4. 未被选中的横条保持青(8)不变。
5. 将所有黄(4)标记像素替换为黑(0)背景（标记在输出中消失）。
6. 其余黑(0)背景像素不变。

**关键洞察**：标记像素不标记空间目标也不驱动重复——它们编码的是一个抽象的数值参数 N，该参数控制选取模式的步长。参考题 22a4bbc2 中步长固定为 3；参考题 4852f2fa 中标记计数驱动精灵体的复制次数。本题中标记计数与周期选取之间形成"元参数传递"——一类对象的数量属性成为另一类对象上的操作参数，这种跨对象的抽象参数编码在两道源题中均不存在。需要对比不同标记数量的示例才能发现 N 是可变的且由标记数决定。
