## 新题 1：视线争夺与奇偶仲裁

**组合逻辑**：[射线投射](创新：从单侧可见性判断改为双源四方向可见性分区) + [重涂色](已有) + [奇偶性选色](创新：从棋盘运动方向选择器改为双源领地争夺的仲裁机制)

**来源原语**：射线投射/ray_cast(参考题 3d588dc9), 重涂色/recolor(参考题 3d588dc9 等), 奇偶性选色/parity_selects_color(参考题 5e6bbc0b), 种子区域/seed_region(参考题 800d221b)

**依赖链**：射线投射从两个种子区域出发，为每个背景像素建立可见性归属——这是重涂色的前提。但当两个种子的可见区域在空间上重叠时，可见性判断无法唯一指定颜色，此时奇偶性规则作为仲裁层介入。奇偶性规则本身不决定哪些像素需要仲裁——这完全由射线投射的空间结果决定。三层逻辑缺一不可。

通过射线投射划分两个种子的可见性领地，将可见区域涂为对应种子颜色；对双方均可见的争夺像素，以棋盘奇偶性仲裁归属。

**输入结构**：黑(0)背景网格，约 15x15。网格中有两个单色种子区域，每个种子为 3~5 像素的 4-连通单色图形，两个种子颜色不同，从红(2)、蓝(1)、黄(4)、橙(7)中选取两种。网格中另有若干灰(5)遮挡体（每个遮挡体为 1~3 像素的 4-连通块，共 3~6 个，散布在网格中）。种子区域与遮挡体互不相邻、互不重叠。生成约束：两个种子的可见区域必须存在非空重叠（至少有一个背景像素同时可被两个种子看到），否则奇偶性规则无法体现。

**规则**：
1. 对每个黑(0)背景像素，分别向上、下、左、右四个方向投射射线。射线沿该方向逐格前进，遇到灰(5)遮挡体像素或网格边界时停止（不含遮挡体本身）。若射线在停止前经过了某个种子区域的任意像素，则该背景像素对该种子"可见"。
2. 若该像素仅对种子 A 可见，重涂为种子 A 的颜色。
3. 若该像素仅对种子 B 可见，重涂为种子 B 的颜色。
4. 若该像素同时对两个种子可见（争夺区），计算棋盘奇偶性：(行号 + 列号) 为偶数时涂为种子 A 的颜色，为奇数时涂为种子 B 的颜色。种子 A 定义为边界框左上角行号较小者；行号相同则列号较小者为 A。
5. 若对两个种子均不可见，保持黑(0)。
6. 种子区域和遮挡体像素保持原色不变。

**关键洞察**：奇偶性仲裁仅在双方视线重叠处生效——只看单个示例容易误判为"可见区域直接涂色"，必须对比含有不同重叠分布的多个示例才能发现棋盘交替规则。

## 新题 2：色向滑轨与形状刹车

**组合逻辑**：[颜色匹配边](已有) → [平移](创新：从单步位移改为沿方向持续滑动) → [形状匹配孔洞](创新：从静态嵌入的前提改为滑动的终止条件) → [嵌入填充](已有)

**来源原语**：颜色匹配边/color_match_side(参考题 5034a0b5), 平移/translate(参考题 5034a0b5), 形状匹配孔洞/shape_matches_hole(参考题 67e490f4), 嵌入填充/inlay_fill(参考题 67e490f4), 精灵体/sprite(参考题 228f6490, 67e490f4), 孔洞/hole(参考题 228f6490, 67e490f4), 旋转翻转不变/rotation_flip_invariant(参考题 67e490f4)

**依赖链**：精灵体颜色与边框边颜色匹配决定滑动方向——这是平移的前提；但平移距离不由颜色或边框决定，而由路径上的形状匹配决定：精灵体沿方向持续滑动，首次与某容器孔洞形状匹配时停下并嵌入。方向、距离、嵌入三者各由不同原语控制。

精灵体根据自身颜色与边框边的匹配确定滑动方向，沿该方向持续滑动直至形状匹配路径上某容器的孔洞，嵌入该孔洞并涂上自身颜色。

**输入结构**：黑(0)背景网格，约 18x18。最外一圈为一像素宽矩形边框，四角像素为黑(0)，四边各为一种不同颜色（从蓝(1)、红(2)、绿(3)、黄(4)中各取一种，不同示例中各边颜色可能交换）。边框内部有 2~4 个灰(5)容器（每个容器为 4x4 至 6x6 的实心灰色矩形，内部挖去一个 2~4 像素的 4-连通黑(0)孔洞）。另有 2~4 个小型精灵体（每个为 2~4 像素的 4-连通单色图形，颜色为蓝(1)/红(2)/绿(3)/黄(4)之一，与某条边框边同色）。精灵体初始不与任何容器重叠。生成约束：每个精灵体沿其滑动方向的路径上恰好有一个容器的孔洞在 8 种刚体变换（4 旋转 x 2 翻转）下与该精灵体形状匹配；不同精灵体的滑动路径互不冲突。

**规则**：
1. 识别边框四边颜色，建立颜色→方向映射（上边色→向上，下边色→向下，左边色→向左，右边色→向右）。
2. 对每个精灵体，根据其颜色确定滑动方向。
3. 精灵体从当前位置沿方向逐像素平移。每到一个新位置，检查精灵体形状（在至多 8 种刚体变换下）是否恰好覆盖某个灰色容器内的黑色孔洞。
4. 首次匹配时停止滑动：以匹配的变换姿态将精灵体嵌入孔洞，用精灵体颜色填充孔洞像素，同时将精灵体原位置恢复为黑(0)。
5. 若精灵体滑到边框仍无匹配，则擦除（原位置恢复为黑(0)）。
6. 边框和容器非孔洞部分保持不变。处理顺序：按精灵体边界框左上角从上到下、从左到右依次处理。

**关键洞察**：精灵体颜色同时编码了运动方向（通过边框匹配）和输出颜色（嵌入时的填充色），而停止位置则完全由形状匹配决定——三个独立信息通道编码在不同结构关系中。

## 新题 3：十字交叉计数决定方块涂色

**组合逻辑**：[射线延伸](已有) + [交叉点重置背景](已有) → [计数](创新：计数对象从连通分量改为十字交叉邻居数) → [像素数映射颜色](创新：映射输入从像素数改为空间拓扑关系数)

**来源原语**：射线延伸/ray_extend(参考题 e9bb6954), 实心方块/solid_block(参考题 e9bb6954), 十字图案/cross_pattern(参考题 e9bb6954), 交叉点重置背景/intersect_reset_bg(参考题 e9bb6954), 计数/count(参考题 aaecdb9a, 6e82a1ae), 像素数映射颜色/count_to_color(参考题 6e82a1ae), 重涂色/recolor(参考题 6e82a1ae)

**依赖链**：十字射线延伸在空间上展开方块的影响范围——交叉点只有在射线延伸后才可检测；交叉邻居计数取决于方块间行列关系的空间拓扑，不可从单个方块推断；计数结果反馈回方块本体的涂色。射线延伸、交叉检测、计数→涂色三环缺一不可。

将灰色方块延伸为十字，交叉处重置为背景，统计每个方块与多少个其他方块产生了交叉，据此将方块本体重涂为对应颜色。

**输入结构**：黑(0)背景网格，约 17x17。网格中有 4~5 个灰(5)实心 3x3 方块。允许部分方块共享中心行或共享中心列（但不会有两个方块同时共享行和列）。方块间间距至少 2 像素（保证交叉点在方块外部）。生成约束：布局使得不同方块的交叉邻居数不全相同——通过安排部分方块共行或共列来创造差异（共行/共列的方块对不产生交叉，仅行列均不同的方块对才产生交叉）。

**规则**：
1. 对每个 3x3 灰(5)方块，将其中心行（整行宽度）和中心列（整列高度）填充为灰(5)，形成十字。
2. 当两个方块中心行不同且中心列不同时，它们的十字在两个像素处交叉（A 的中心行与 B 的中心列交叉，以及 B 的中心行与 A 的中心列交叉），将这些交叉像素重置为黑(0)。
3. 当两个方块共享中心行或共享中心列时，它们的十字在该共享行/列上合并，不产生交叉。
4. 对每个方块，统计其交叉邻居数 K = 与该方块中心行不同且中心列不同的其他方块数量。
5. 根据 K 值将方块 3x3 本体重涂色：K=1 → 绿(3)，K=2 → 红(2)，K=3 → 蓝(1)，K=4 → 黄(4)。十字延伸臂（方块本体外的部分）保持灰(5)不变。

**关键洞察**：共享中心行或中心列的方块对不产生交叉——这一"合并而非交叉"的规则只有在对比包含共行/共列方块对和不包含的多个示例后才能归纳出来。

## 新题 4：封闭框对角晕染与内含物计数定色

**组合逻辑**：[仅对角邻接](已有) + [对角邻接背景着色](已有) + [计数](创新：计数对象从全局连通分量改为特定封闭框内的局部对象) + [像素数映射颜色](创新：决定晕染色的不是封闭框本身的颜色或内层前景色，而是内含物数量的编码映射)

**来源原语**：封闭框/enclosing_frame(参考题 396d80d7), 仅对角邻接/diagonal_only_adj(参考题 396d80d7), 对角邻接背景着色/diagonal_bg_color(参考题 396d80d7), 内层前景/inner_foreground(参考题 396d80d7), 计数/count(参考题 aaecdb9a, 6e82a1ae), 像素数映射颜色/count_to_color(参考题 6e82a1ae), 连通分量/connected_component(参考题 aaecdb9a)

**依赖链**：封闭框的几何形状决定哪些背景像素处于"仅对角邻接"位置——这提供了"在哪里填色"；但填什么颜色不由框的颜色或内层前景色决定，而由框内部 4-连通对象的数量通过编码映射得出。计数结果改变了填色操作的参数。去掉对角邻接判断则不知在哪里填，去掉计数映射则不知填什么色。

统计每个封闭框内的独立对象数量，将数量映射为颜色，填入该框"仅对角邻接"的背景像素位置。

**输入结构**：黑(0)背景网格，约 18x18。网格中有 2~3 个封闭框（每个封闭框为一种颜色的闭合环形边界，颜色从红(2)、蓝(1)、绿(3)中选取，不同框颜色不同）。每个封闭框内部包含若干灰(5)的 4-连通小对象（每个对象 2~4 像素，对象间不相邻），数量 1~4 不等。封闭框之间互不嵌套、互不相邻，各框的"仅对角邻接"位置也互不重叠。生成约束：不同封闭框的内含对象数量不全相同，以体现映射差异。

**规则**：
1. 识别每个封闭框：一种非背景色形成的闭合环形边界，其内部区域严格被边界围住。
2. 统计每个封闭框内部的灰(5) 4-连通对象数量 K。
3. 根据 K 值确定晕染色：K=1 → 黄(4)，K=2 → 橙(7)，K=3 → 品红(6)，K=4 → 栗(9)。
4. 对每个黑(0)背景像素，若它与某封闭框的边界像素存在对角邻接（8-邻域中有该框颜色的像素）但不存在正交邻接（4-邻域中没有该框颜色的像素），则将该像素涂为步骤 3 中该框对应的晕染色。
5. 封闭框边界、内部灰(5)对象、内部背景像素均保持不变。

**关键洞察**：晕染色不是封闭框本身的颜色，也不是其内部对象的颜色，而是由内部对象数量编码映射得出——这一间接关系必须通过对比包含不同数量内部对象的多个示例才能推断。

## 新题 5：路径段的种子近邻着色

**组合逻辑**：[寻路](已有) + [连线/draw_path](创新：从穿越门中心的迷宫路径改为连接散布路标的最短正交路径) → [邻接传色](创新：从网络分支与种子的直接邻接改为路径段与种子的最短距离关系)

**来源原语**：寻路/pathfinding(参考题 7e576d6e), 连线/draw_path(参考题 7e576d6e), 标记像素/marker_pixel(参考题 7e576d6e), 邻接传色/adjacency_color_transfer(参考题 800d221b), 种子区域/seed_region(参考题 800d221b)

**依赖链**：先通过寻路连接路标绘制出路径——路径的形状由路标位置和网格空间决定，此时路径颜色尚未最终确定。然后每段路径根据与各种子区域的空间距离关系获得着色——但种子的"影响范围"取决于路径的实际走向，而路径走向又取决于路标布局。删除寻路则无路径可着色，删除种子着色则路径颜色未定。

连接散布的灰色路标像素绘制最短正交路径，然后将每段路径涂为离该段最近的种子区域的颜色。

**输入结构**：黑(0)背景网格，约 16x16。网格中有 4~6 个灰(5)路标像素（单像素，散布在网格各处）。另有 2~3 个种子区域（每个种子区域为 2~3 像素的 4-连通单色图形，颜色从红(2)、蓝(1)、黄(4)中选取，不同种子颜色不同）。路标像素与种子区域互不相邻。生成约束：任意两个相邻路标之间的曼哈顿最短正交路径不经过种子区域或其他路标；不同路径段的最近种子不全相同。

**规则**：
1. 将所有路标像素按扫描序（从上到下、从左到右）排列为有序序列 W1, W2, ..., Wn。
2. 对每对相邻路标 (Wi, Wi+1)，绘制一条曼哈顿最短正交路径：先沿水平方向移动至目标列，再沿垂直方向移动至目标行（即"先水平后垂直"的 L 形路径）。路径像素初始涂为灰(5)。
3. 路径段定义为连接 Wi 到 Wi+1 的全部像素（含两端路标像素）。对每个路径段，计算该段上每个像素到每个种子区域最近像素的曼哈顿距离，取段内所有像素到该种子的最小距离，再在各种子间取最小者——对应的种子即为该段的"最近种子"。
4. 将该路径段（含两端路标）重涂为最近种子的颜色。若某路标像素同时属于两段路径且两段最近种子不同，则该路标像素取两段中距离更近的那个种子的颜色；距离相同时取扫描序在前的种子。
5. 种子区域保持原色不变。

**关键洞察**：路径的绘制方向（先水平后垂直）是隐蔽规则——它决定了路径的具体走向，从而影响哪个种子离哪段更近。只看路标的起点终点无法唯一确定路径形状，必须从多个示例中归纳出"先水平后垂直"的绘制约定。

## 新题 6：对角复制与箭头射线桥接

**组合逻辑**：[拼接/对角排布](已有) + [对角副本](已有) → [射线延伸](创新：射线从对角副本中的箭头出发，跨越空白象限形成桥接) + [朝向对齐/横杆偏移定方向](已有)

**来源原语**：拼接/concatenate(参考题 fb791726), 对角排布/diag_layout(参考题 fb791726), 对角副本/diag_copy(参考题 fb791726), 射线延伸/ray_extend(参考题 689c358e, e9bb6954), 箭头精灵/arrow_sprite(参考题 689c358e), 朝向对齐/orientation_aligned(参考题 689c358e), 横杆偏移定方向/crossbar_determines(参考题 689c358e)

**依赖链**：对角复制创建了 2x2 画布，其中主对角线放置输入副本，副对角线为空白——这一空间结构是射线延伸的舞台。箭头精灵随输入被复制到两个对角位置，每个副本中的箭头各自向其指向方向延伸射线。射线穿越副对角线空白区域形成"桥接"，在空白象限中留下可见轨迹。对角复制决定了射线的起点分布，箭头方向决定了射线走向，两者共同决定桥接图案。

将输入对角复制到 2x2 画布的主对角线位置，然后从每个副本中的箭头精灵出发沿其指向延伸射线，射线穿越空白象限形成桥接。

**输入结构**：黑(0)背景网格，约 8x8 至 10x10。网格中有 1~3 个箭头精灵（每个箭头为 6 像素的不对称 T 形：一条 4 像素长的主轴和一条 3 像素的横杆，横杆偏向主轴一端，偏向端即为箭头指向端）。每个箭头颜色不同，从红(2)、蓝(1)、绿(3)、黄(4)中选取。箭头指向四个基本方向之一（上/下/左/右）。网格中可能还有少量单像素的装饰前景，不构成箭头形状。生成约束：箭头的指向方向保证射线延伸后能穿入副对角线空白区域（即箭头不全指向同一个主对角线象限）。

**规则**：
1. 构建 2H x 2W 的黑(0)画布。将输入网格粘贴到左上角（行 0~H-1，列 0~W-1）和右下角（行 H~2H-1，列 W~2W-1），形成两个对角副本。副对角线区域（右上和左下）保持黑(0)。
2. 在两个副本中分别识别箭头精灵：通过横杆偏移确定每个箭头的指向方向（横杆距主轴较近的那端为箭头尖端方向）。
3. 从每个副本中每个箭头的尖端出发，沿指向方向逐像素延伸射线。射线颜色为该箭头的颜色。射线在遇到非黑(0)像素或画布边界时停止（不覆盖该非黑像素）。
4. 当两条不同颜色的射线在同一像素交叉时，取来自左上副本箭头的射线颜色（左上副本优先）。若两条射线均来自同一个副本，取箭头边界框左上角扫描序在前者的颜色。
5. 原有的箭头精灵像素、装饰前景像素在两个副本中保持不变，不被射线覆盖。

**关键洞察**：每个箭头因对角复制而产生两条射线（分别从两个副本出发），它们可能在副对角线的空白象限中交汇——这种"分身交汇"效果只有理解了对角复制机制后才能预测。

## 新题 7：表格单元格重力沉降与计数染色表头

**组合逻辑**：[压缩/compact](创新：从全局棋盘压缩改为按表格单元格局部重力沉降) + [分隔线网格](已有) + [计数](创新：统计对象从全局改为跨同列单元格汇总) → [编码映射](创新：将像素总数映射为表头单元格的填充色)

**来源原语**：压缩/compact(参考题 5e6bbc0b), 分隔线网格/separator_grid(参考题 e9c9d9a1), 网格单元格/grid_cell(参考题 e9c9d9a1), 填充/fill(参考题 e9c9d9a1), 计数/count(参考题 aaecdb9a, 6e82a1ae), 编码映射/encoding_map(参考题 77fdfe62, 52fd389e), 表格行列位/table_row_col_pos(参考题 e9c9d9a1)

**依赖链**：分隔线网格将画布划分为表格——压缩操作在每个单元格内部独立进行（像素下沉到单元格底部），而非全局操作。压缩后的像素分布改变了每列的视觉布局但不改变总数。计数操作跨越同一列的所有非表头单元格汇总前景像素总数，该总数通过编码映射决定表头单元格的填充色。压缩和计数相互独立地作用于同一分隔线网格结构，但压缩改变了网格内容的空间分布。

在分隔线网格的每个单元格内将前景像素下沉至底部，然后统计每列的前景像素总数，将总数映射为该列表头单元格的填充色。

**输入结构**：黑(0)背景网格，约 15x19（宽大于高）。绿(3)分隔线将网格分为 3~4 列、3~4 行的表格（分隔线为完整贯通的水平线和垂直线，宽度 1 像素）。最上方一行单元格为表头行，初始全为黑(0)。其余行的单元格内散布着前景像素：同一列的所有单元格使用同一种前景色（从红(2)、蓝(1)、黄(4)、橙(7)中选取，不同列颜色不同）。每个单元格内有 0~4 个前景像素，随机分布在单元格内部（不在分隔线上）。生成约束：不同列的前景像素总数（跨所有非表头行汇总）不全相同且范围在 1~8 之间。

**规则**：
1. 识别绿(3)分隔线网格，确定每个单元格的边界。最上方一行单元格为表头行。
2. 对每个非表头单元格，将其内部的前景像素在该单元格范围内向下压缩：保持像素的列坐标不变，将所有前景像素下移至该单元格最底部的可用行，像素间紧密堆叠（最先处理最下方的像素，逐个上移空出位置给上方的像素）。
3. 对每列，统计所有非表头单元格中的前景像素总数 T。
4. 根据 T 值将该列表头单元格整体填充为指定颜色：T=1~2 → 灰(5)，T=3~4 → 品红(6)，T=5~6 → 青(8)，T=7~8 → 栗(9)。
5. 绿(3)分隔线保持不变。

**关键洞察**：表头颜色不是该列前景色的变体，而是由跨多个单元格汇总的像素计数决定的——这种"局部操作 + 全局统计"的双层结构需要对比不同像素分布的示例才能归纳。

## 新题 8：膨胀环与形状匹配裁定膨胀量

**组合逻辑**：[形状匹配](创新：从嵌入孔洞/印章的前提改为膨胀量的裁定依据) + [膨胀/expansion_fill](创新：膨胀量不由内嵌标记计数决定，而由与外部模板的形状匹配结果决定) + [重涂色](已有)

**来源原语**：形状匹配/shape_matching(参考题 228f6490, 67e490f4), 旋转翻转不变/rotation_flip_invariant(参考题 67e490f4), 膨胀/dilate(参考题 52fd389e), 扩展填充/expansion_fill(参考题 52fd389e), 计数决定扩展量/count_determines_expansion(参考题 52fd389e), 精灵体/sprite(参考题 228f6490, 67e490f4), 矩形块/rectangular_block(参考题 52fd389e), 重涂色/recolor(参考题 6e82a1ae 等)

**依赖链**：外部散布的模板精灵体是膨胀量的"编码器"——每个模板精灵体携带一个像素数量，这个数量将成为某个矩形块的膨胀量。但"哪个模板对应哪个矩形块"不由颜色或位置决定，而由形状匹配决定：每个矩形块内部有一个与某模板形状匹配的"钥匙图案"，匹配成功后该模板的像素数量即为该矩形块的膨胀量。形状匹配提供了模板→矩形块的映射，模板像素数提供了膨胀参数，两者共同决定输出。

外部模板精灵体的形状与矩形块内部钥匙图案匹配，匹配后该模板的像素数即为矩形块的膨胀量，膨胀环涂为模板颜色。

**输入结构**：黑(0)背景网格，约 20x20。网格中有 2~3 个灰(5)实心矩形块（每个约 4x4 至 5x5），每个矩形块内部嵌有一个由黄(4)像素构成的小图案（"钥匙图案"，2~4 像素的 4-连通图形，位于矩形块内部任意位置）。网格中另有 2~3 个散布的单色模板精灵体（每个精灵体 2~5 像素的 4-连通图形，各自颜色不同，从红(2)、蓝(1)、绿(3)、橙(7)中选取）。模板精灵体与矩形块互不相邻。生成约束：每个矩形块的钥匙图案恰好与一个模板精灵体形状匹配（在 8 种刚体变换下）；不同模板精灵体的像素数量不全相同（这样膨胀量不同）；膨胀后的矩形彼此不重叠。

**规则**：
1. 识别灰(5)矩形块及其内部的黄(4)钥匙图案。提取每个钥匙图案的形状掩码（仅关注相对像素位置，忽略绝对坐标）。
2. 识别所有外部模板精灵体，提取每个模板的形状掩码和像素数量 P。
3. 对每个矩形块，将其钥匙图案的形状掩码与所有模板精灵体的形状掩码进行匹配（允许 4 旋转 x 2 翻转 = 至多 8 种刚体变换）。找到匹配的模板后，记录该模板的像素数量 P 和颜色 C。
4. 将该矩形块的边界框向四个方向各膨胀 P 个像素，膨胀区域（原矩形块外、新边界框内的像素）涂为颜色 C。
5. 恢复原矩形块的灰(5)像素和黄(4)钥匙图案像素（膨胀层在矩形块层下方）。
6. 模板精灵体在输出中擦除为黑(0)背景。

**关键洞察**：模板精灵体携带两个独立信息——形状决定"配对哪个矩形块"，像素数量决定"膨胀多远"，颜色决定"膨胀环涂什么色"。三个属性编码在同一个对象中，分别通过不同的结构关系被解读。
