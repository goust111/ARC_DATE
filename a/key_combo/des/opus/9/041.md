## 新题 1：精灵体印章行进中的方位色重写

**组合逻辑**：[颜色匹配/color_match] → [印章覆盖/stamp_repeat](已有) → [重涂色/recolor](创新：中心像素按行进方位重写颜色) + [方位对应/direction_correspondence](创新：从方向标记转为行进方向编码)

**来源原语**：印章覆盖/stamp_repeat(#985ae207), 颜色匹配/color_match(#985ae207), 中心像素/center_pixel(#985ae207), 重叠停止/overlap_stop(#985ae207), 方位对应/direction_correspondence(#d364b489), 方位决定颜色/direction_color(#d364b489), 精灵体/sprite(#985ae207), 实心矩形/solid_rectangle(#985ae207)

**依赖链**：中心像素的颜色决定匹配的目标矩形 → 目标矩形的方位决定印章行进方向 → 行进方向决定每个副本中心像素的重写颜色。中心像素在原件中是"目的地钥匙"，在副本中变为"方向指示器"——同一个像素位置承担了双重语义，这种语义翻转在两道源题中均不存在。

将 3x3 精灵体向匹配矩形方向反复盖章，副本的中心像素按行进的绝对方位重新涂色。

**输入结构**：约 20x20 网格，黑(0)背景。散布 2-4 个 3x3 精灵体，每个精灵体的 8 个边框像素为同一前景色，中心像素为另一颜色（"键色"）。对于每个键色，网格中恰好有一个该颜色的实心矩形（至少 2x2），位于该精灵体的某个基本方位方向上（正上、正下、正左或正右，允许行/列略有偏移但主方向明确）。各精灵体的边框色互不相同；各键色互不相同且与所有边框色不同。精灵体之间、精灵体与非匹配矩形之间间距足够，保证印章路径不冲突。可用颜色示例：精灵体 A 边框蓝(1)、中心红(2)，匹配矩形红(2)；精灵体 B 边框绿(3)、中心黄(4)，匹配矩形黄(4)。

**规则**：
1. 将每个精灵体与颜色等于其中心像素的唯一实心矩形匹配。
2. 确定从精灵体到匹配矩形的基本方位（上/下/左/右）。
3. 沿该方向每隔 3 个像素复制整个 3x3 精灵体，直到某个副本的 3x3 边界框首次与匹配矩形重叠为止。重叠处副本的像素覆盖矩形像素。
4. 对于每个**副本**（不含原件），将其中心像素重涂为行进方向对应的颜色：向上→红(2)，向右→橙(7)，向下→青(8)，向左→品红(6)。
5. 原件的中心像素保持键色不变。
6. 多个精灵体的印章路径保证互不相交（生成约束）。

**关键洞察**：中心像素在原件中是目标匹配键，在副本中变成方向编码器。仅看一个示例中向同一方向行进的多个精灵体，无法区分方向色规则和固定色规则——必须对比不同行进方向的示例才能归纳出方位→颜色的映射。

## 新题 2：对角偏移平铺涌现连通分量分类与射线延伸

**组合逻辑**：[对角线偏移复制/diagonal_offset_copy](已有) → [面积比较/area_comparison](创新：从单色分类改为对平铺涌现的分量分类) → [射线延伸/ray_extend](创新：从锚定方块改为多像素锚定分量)

**来源原语**：平铺/tile(#d13f3404), 对角线偏移复制/diagonal_offset_copy(#d13f3404), 画布加倍/canvas_doubling(#d13f3404), 连通分量/connected_component(#67385a82), 面积比较/area_comparison(#67385a82), 多像素涂色留单/multi_recolor_single(#67385a82), 射线延伸/ray_extend(#d43fd935), 行列对齐/row_col_alignment(#d43fd935), 对齐标记连向锚点/marker_to_anchor(#d43fd935)

**依赖链**：对角平铺使原本分离的像素在加倍画布上产生重叠 → 重叠处像素融合为多像素连通分量（"锚"），未融合的保持孤立（"标记"） → 标记向行列对齐的最近锚发射射线。三者环环相扣：平铺创造连通结构，连通分析分出锚与标记，射线延伸利用这一分类。分量的锚/标记身份完全由平铺重叠几何决定——同一像素在不同输入图案中可能变锚也可能变标记。

将稀疏前景图案沿右下对角线平铺到加倍画布上，因重叠涌现出多像素锚分量与孤立标记像素，然后标记向行列对齐的锚发射射线。

**输入结构**：约 7x7 网格，黑(0)背景。前景像素为绿(3)，共 4-8 个，形成稀疏图案（无两个前景像素 4-连通相邻，保证原图中每个前景像素都是孤立的）。图案经过设计：当在 14x14 加倍画布上沿 (r+k, c+k) 平铺后，部分对角副本的像素恰好 4-连通相邻，形成面积 >= 2 的连通分量；其余像素仍为孤立单像素。生成约束：平铺后至少产生 1 个多像素分量和 2 个孤立像素；至少有 1 个孤立像素与某多像素分量共享行或列。

**规则**：
1. 创建 2 倍高、2 倍宽的画布，填充黑(0)。
2. 对于输入中位于 (r, c) 的每个前景像素，在输出画布的所有 (r+k, c+k)（k=0,1,2,...，只要坐标在画布范围内）位置绘制该颜色。
3. 在结果画布上，计算每个前景像素所属的 4-连通分量的面积：
   - 面积 >= 2 的分量：将其所有像素重涂为蓝(1)，标记为"锚"。
   - 面积 = 1 的像素：保持绿(3)，标记为"标记"。
4. 对于每个绿(3)标记像素，检查它是否与某个蓝(1)锚分量的任一像素共享同一行或同一列。若是，从该标记像素向该锚分量方向（沿共享的行或列）绘制一条绿(3)线段，线段终点为锚分量边界像素的紧邻前一格（不覆盖锚像素）。若标记在同一行/列上与多个锚对齐，仅连向最近的锚。
5. 与任何锚均不共享行或列的标记像素保持原位不变，不发射射线。

**关键洞察**：锚与标记的分类不是输入固有的——输入中所有前景像素都是孤立的。只有对角平铺之后，重叠几何才"涌现"出连通分量。不同输入图案的同一像素可能在平铺后成为锚或标记，因此分类规则无法从单个像素的输入位置静态推断，必须先完成平铺再分析。

## 新题 3：框核互换色后以方块为种子最近扩散填充

**组合逻辑**：[内外层交换/inner_outer_swap](已有) → [最近扩散/nearest_fill](创新：种子不再是条状而是面状方块，扩散色取决于互换后的核色) + [等距异色为分隔/equidist_diff_sep](已有)

**来源原语**：重涂色/recolor(#3befdf3e), 生长/grow(#3befdf3e), 内外层交换/inner_outer_swap(#3befdf3e), 同心正方形层/concentric_layer(#3befdf3e), 填充/fill(#332202d5), 最近扩散/nearest_fill(#332202d5), 最近种子分区/nearest_seed_part(#332202d5), 等距异色为分隔/equidist_diff_sep(#332202d5)

**依赖链**：先对每个带边框的方块执行核-框互换 → 互换后的核色（=原边框色）成为该方块的扩散色 → 以方块中心为种子点，用曼哈顿距离对全背景做最近种子分区 → 等距于两个不同扩散色种子的像素涂为分隔色。互换操作决定了扩散色——不做互换则扩散色全错。

对散布在网格中的带边框方块先做核-框颜色互换，然后以每个方块为种子做最近扩散填充，划分整个背景。

**输入结构**：约 17x17 网格，黑(0)背景。散布 3-4 个小型带边框正方形，每个由 (N-2)x(N-2) 的内核和 1 像素宽的外框组成（N = 3 或 5）。每个方块的内核色和外框色各不相同，形成独特的双色对。不同方块之间至少间隔 3 个黑像素。示例颜色：方块 A 内核红(2)/外框蓝(1)；方块 B 内核黄(4)/外框绿(3)；方块 C 内核橙(7)/外框灰(5)。生成约束：方块数量 >= 3，保证等距分隔线至少出现一次。

**规则**：
1. 对每个带边框方块，交换内核色和外框色：原内核色涂到外框位置，原外框色涂到内核位置。方块几何形状不变。
2. 以每个方块的几何中心像素为种子点。种子的扩散色为该方块交换后的内核色（即原外框色）。
3. 对画布上每个黑(0)像素，计算它到所有种子点的曼哈顿距离，取最近的种子。将该像素涂为最近种子的扩散色。
4. 若某黑像素到两个最近种子的曼哈顿距离相等，且这两个种子的扩散色不同，则该像素涂为栗(9)作为分隔色。若等距种子的扩散色相同，则涂为该共同颜色（无需分隔）。
5. 交换后的方块本身保持不变（不被扩散覆盖）。

**关键洞察**：扩散色不是方块表面最显眼的颜色（内核面积大于外框），而是原外框色——只有识别出核-框互换，才能推断出正确的扩散色。若仅看单个示例，可能将内核色或外框色猜为扩散色；必须对比多个示例中方块颜色与其周围扩散区域的颜色关系，才能发现互换规则。

## 新题 4：角落码对称展开同心环后按环序交替打孔

**组合逻辑**：[对称补全/symmetry_completion](已有) → [擦除/erase](创新：擦除位置由环的嵌套序号决定相位) + [交替/alternating](创新：从单一矩形中心线的固定交替推广为多环间的相位交错)

**来源原语**：对称补全/symmetry_completion(#9d9215db), 镜像/reflect(#9d9215db), 角落编码/corner_code(#9d9215db), 对称展开/symmetric_unfolding(#9d9215db), 同心正方形层/concentric_square_ring(#9d9215db), 擦除/erase(#3bdb4ada), 交替/alternating(#3bdb4ada), 中心线/center_line(#3bdb4ada), 中线交替打孔/alternating_holes_on_center(#3bdb4ada)

**依赖链**：角落码决定有多少层同心环及各环颜色 → 对称展开生成完整环 → 环的嵌套序号（从外到内编号 0,1,2,...）决定打孔相位：偶数环从侧边第 1 个像素（0-indexed）开始打孔，奇数环从第 2 个像素开始 → 相邻环的孔洞互相错开形成视觉棋盘效果。环数和环色只有完成对称展开后才确定；打孔相位只有知道环序号后才确定。

将角落编码的稀疏像素展开为完整同心方环，然后在每层环的各侧边上按环序号的奇偶交替打孔。

**输入结构**：奇数边长（11-15）的正方形网格，黑(0)背景。前景像素仅出现在奇坐标格点上（行、列索引均为奇数），且集中在网格的某一个角落附近（例如左上角）。前景像素编码 3-5 层同心方环的信息：位于对角线上的像素指定该层环四角的颜色；位于水平或垂直轴上的像素指定该层环对应两侧边的颜色。各层环使用不同颜色，如红(2)、绿(3)、蓝(1)、黄(4)、橙(7)。生成约束：至少 3 层环。

**规则**：
1. 找到距所有前景像素最近的角落，将每个前景像素解释为相对于该角落的局部坐标，确定其描述的是哪一层环的哪个部分（对角线像素 → 四角色；轴向像素 → 对侧边色）。
2. 通过双边对称将角落码展开为完整的同心方环。环从外到内编号为 0, 1, 2, ...。
3. 对每层环的每条侧边（上、右、下、左各一条），沿侧边方向对非角落像素执行交替擦除：
   - 偶数环（序号 0, 2, 4, ...）：擦除侧边上偏移量为奇数的像素（偏移量从该侧边的起始角落像素之后开始计数，0-indexed，起始角落本身不计入）。
   - 奇数环（序号 1, 3, 5, ...）：擦除侧边上偏移量为偶数的像素。
4. 环的四个角落像素永远不被擦除。
5. 擦除的像素设为黑(0)。

**关键洞察**：相邻环的打孔相位相反——外环在偏移 1,3,5 处打孔，内环在偏移 0,2,4 处打孔。这形成一种"棋盘嵌套"视觉效果，是两道源题均不存在的涌现结构。仅看单层环无法判断相位规则，必须对比相邻环才能归纳出序号奇偶决定相位的规律。

## 新题 5：引导条定向压缩与紧凑原型拉伸的双轴交互

**组合逻辑**：[拉伸/stretch + 顶点坐标映射/vertex_coord_mapping](已有) → [压缩/compress](创新：压缩轴由引导条朝向决定，而非固定) + [引导条决定朝向/guide_determines_dir](创新：从决定线段方向改为决定压缩方向)

**来源原语**：拉伸/stretch(#b0f4d537), 连线/connect(#b0f4d537), 紧凑原型/compact_prototype(#b0f4d537), 稀疏骨架锚点/sparse_anchor(#b0f4d537), 顶点坐标映射/vertex_coord_mapping(#b0f4d537), 行列独立拉伸/independent_stretch(#b0f4d537), 压缩/compress(#c61be7dc), 引导条/guide_bar(#c61be7dc), 引导条决定朝向/guide_determines_dir(#c61be7dc)

**依赖链**：紧凑原型的顶点映射到骨架锚点 → 拉伸产生带大量空行/空列的线段网络 → 引导条朝向决定压缩轴（水平引导条 → 压缩纵轴即删除全黑行；垂直引导条 → 压缩横轴即删除全黑列） → 同一原型+同一骨架在不同引导条朝向下产生不同纵横比的输出。拉伸和压缩作用于正交的维度，引导条是连接二者的决策节点。

将紧凑原型拉伸到稀疏骨架上，再沿引导条指示的轴压缩掉空行或空列。

**输入结构**：约 20x25 网格，由单列灰(5)像素分为左右两个面板。左面板（约 6x6）包含一个紧凑的彩色线段图：2-4 种非黑非灰非黄颜色的水平和垂直线段，线段在端点、拐角或交叉处形成图的顶点。右面板包含：(a) 若干黄(4)像素作为稀疏骨架锚点，其拓扑结构与原型顶点一一对应但空间拉伸；(b) 两条完整的灰(5)引导条（跨面板全宽或全高），指示压缩方向——两条均为水平则压缩纵轴，两条均为垂直则压缩横轴。生成约束：拉伸后至少产生 2 行或 2 列全黑空隙，保证压缩有可见效果；引导条不穿过锚点。

**规则**：
1. 在左面板中提取紧凑原型的图结构：每个前景线段的端点、拐角、交叉点作为顶点，连接它们的线段作为边，记录每条边的颜色。
2. 将原型顶点的行坐标排序列表映射到右面板黄(4)锚点的行坐标排序列表；列坐标同理。每个原型顶点获得对应的拉伸后坐标。
3. 沿拉伸后的顶点坐标绘制线段：对原型中每条边，在映射后的两个端点之间画水平或垂直直线，使用该边在原型中的颜色。
4. 检查引导条朝向：若两条引导条均为水平（跨面板宽度），则删除拉伸结果中所有不包含任何非黑像素的行（纵轴压缩）；若均为垂直（跨面板高度），则删除所有全黑列（横轴压缩）。
5. 输出为压缩后的图形。不包含引导条、灰分隔列和黄锚点——仅保留彩色线段。

**关键洞察**：拉伸和压缩作用于正交维度——拉伸在两个轴上都可能引入空隙，但只有引导条指定的那个轴的空隙被消除。同一原型和骨架在水平引导条与垂直引导条下会产生不同纵横比的输出，迫使求解者必须同时理解拉伸映射和引导条的压缩语义。

## 新题 6：周期瓦片补全揭示隐藏格行用于逐行异常值提取

**组合逻辑**：[补全/completion + 周期延拓/periodic_extension](已有) → [逐行比较/row_wise_comparison](创新：比较对象从预设格阵变为补全后涌现的格阵) + [异常值选择/outlier_selection](已有，但作用于补全后的完整格阵)

**来源原语**：补全/completion(#50a16a69), 重复瓦片/repeating_tile(#50a16a69), 占位符区域/placeholder_region(#50a16a69), 周期延拓/periodic_extension(#50a16a69), 提取/extraction(#38007db0), 网格单元/lattice_cell(#38007db0), 逐行比较/row_wise_comparison(#38007db0), 异常值选择/outlier_selection(#38007db0)

**依赖链**：可见区域只是完整格阵的一部分 → 周期补全恢复被占位符遮盖的格单元 → 补全后每行格单元才完整可比较 → 逐行找异常值并提取。关键是：某些格行的异常值单元恰好位于占位符区域中，不补全就不可见，该行所有可见单元完全相同，看起来没有异常值。

将占位符区域按周期瓦片补全后，对完整格阵逐行提取异常值单元，拼成单列输出。

**输入结构**：约 15x18 网格。网格左上区域是可见的重复瓦片图案，右侧和/或底部区域被单一占位符色灰(5)填充。可见区域中的瓦片形成一个格阵（用某种格线色分隔的等大方形单元，如格线色为栗(9)），每个单元内部有一个由 2-3 种颜色组成的简单图案（4-8 像素的 4-连通前景）。格阵每行有 4-6 个单元，其中恰好有 1 个单元的内部图案与该行其余单元不同（异常值）。在某些行中，异常值单元位于被占位符遮盖的区域内——此时可见区域中该行的所有单元看起来完全相同。瓦片的最小重复单元包含一个完整格行（含异常值），保证周期延拓能正确恢复所有隐藏单元。生成约束：至少有 1 个格行的异常值在占位符区域中；至少有 1 个格行的异常值在可见区域中。

**规则**：
1. 从可见的左上区域推断最小重复瓦片。
2. 将瓦片沿水平和垂直方向周期延拓，覆盖整个占位符区域，恢复完整格阵。
3. 对每个格行（水平方向的一排格单元），比较所有单元的内部图案。找到内部图案仅出现一次的那个单元（异常值/"odd one out"）。
4. 按格行从上到下的顺序，将所有异常值单元提取出来，排成单列格阵。输出保留原始格线色和单元尺寸。

**关键洞察**：不执行周期补全，部分格行看起来所有单元一致（因为异常值被占位符遮盖），求解者会误以为该行没有异常值或根本不存在该行。补全不仅"填充空白"——它揭示了影响异常值判定的结构信息，使得补全和异常值检测在逻辑上不可分割。

## 新题 7：碎片帧排序重建同心环，紧凑对象像素数编码环间距

**组合逻辑**：[排序/sorting + 按边长降序排列/descending_side_order](已有) → [同心层填充/concentric_fill](创新：环间不再紧邻，间距由另一对象的像素数参数化) + [像素数决定长度/pixel_count_length](创新：从决定线段长度改为决定环间距)

**来源原语**：排序/sorting(#c658a4bd), 同心层填充/concentric_fill(#c658a4bd), 碎片帧/fragmented_frame(#c658a4bd), 嵌套层次/nesting_hierarchy(#c658a4bd), 按边长降序排列/descending_side_order(#c658a4bd), 计数/counting(#e3fe1151), 压缩/compress(#c61be7dc), 像素数决定长度/pixel_count_length(#c61be7dc), 内部对象/inner_object(#c61be7dc)

**依赖链**：碎片帧的边界框最大维度决定各层预期边长 → 按边长降序排列确定嵌套层次 → 独立的紧凑对象的像素计数 G 决定相邻环之间的间隙宽度 → 同心环组装时，第 k 层环的边长 = 最外环边长 - 2kG。两条独立信息源（帧排序 + 像素计数）在组装步骤中合流。

将散乱的碎片帧按预期边长排序后重建同心方环，环与环之间的间隙宽度等于另一个紧凑对象的像素数。

**输入结构**：约 15x15 网格，黑(0)背景。网格中散布 3-5 个不同颜色的碎片方环，每个碎片方环是一个完整方环的部分可见片段（因相互遮挡或边界裁剪而缺失部分像素）。每个碎片方环的所有可见像素为同一颜色，颜色示例：红(2)、绿(3)、蓝(1)、黄(4)。此外，网格中另有一个与所有帧颜色不同的小型紧凑单色对象（如灰(5)，面积 1-4 像素的 4-连通图形），该对象不与任何碎片帧重叠。每个碎片帧的预期完整边长可从其所有可见像素的边界框的较大维度推断。生成约束：各帧预期边长互不相同；紧凑对象的像素数 G 满足最外环边长 - 2(N-1)G >= 1（N 为帧数），保证最内环至少有 1 像素。

**规则**：
1. 对每种碎片帧颜色，计算其所有可见像素的边界框，取较大维度作为该颜色的预期边长 S。
2. 按 S 从大到小排序所有帧颜色，确定嵌套层次：S 最大的在最外层。
3. 计算紧凑灰(5)对象的像素总数 G。
4. 构建输出：正方形画布，边长 = 最大 S。从外到内绘制同心方环：第 0 层（最外）为边长 S_0 的方环，使用排序第一的颜色；第 k 层的边长 = S_0 - 2kG，使用排序第 k 的颜色。每层环是 1 像素宽的方形边框。各层居中。
5. 若计算出的某层边长 <= 0，则该层不绘制（但在生成约束下不会发生）。

**关键洞察**：紧凑灰对象与碎片帧在视觉上毫无关联——一个是小斑点，一个是方环碎片。但小斑点的像素数精确编码了环间距参数。仅靠帧排序无法确定间距（间距不是帧自身属性），仅靠像素计数无法确定哪些颜色放在哪一层。两个独立信息源在组装步骤中交汇，缺一不可。

## 新题 8：反对角线段组内异常值检测与递进位移

**组合逻辑**：[逐行比较/row_wise_comparison → 逐反对角线比较](创新：比较维度从格阵行推广到反对角线) + [异常值选择/outlier_selection](已有) → [平移绘制/translate_draw + 长度递增/length_increment](已有，但仅作用于异常值)

**来源原语**：提取/extraction(#38007db0), 逐行比较/row_wise_comparison(#38007db0), 异常值选择/outlier_selection(#38007db0), 擦除/erase(#50c07299), 平移绘制/translate_draw(#50c07299), 对角线段/diagonal_segment(#50c07299), 同反对角线/same_antidiagonal(#50c07299), 长度递增/length_increment(#50c07299)

**依赖链**：反对角线分组提供比较上下文 → 组内比较识别出异常值线段 → 只有异常值执行擦除+递进位移。异常值检测是递进变换的决策门：多数线段保持不动，只有异常值前进并增长。判断"异常"需要知道同组其他线段的属性——删除分组比较环节则无法区分异常值与多数。

在共享同一反对角线的多组线段中，找出每组中属性独一无二的异常值线段，将其沿反对角线前移并增长一个像素。

**输入结构**：约 15x15 网格，黑(0)背景。网格中分布 3-4 组反对角线段。每组由 3-5 条位于同一反对角线（r+c 值相同）上的不相连线段组成。同组内的线段之间有黑像素间隔（不 4-连通相邻）。同组内，多数线段（2-4 条）具有相同的颜色和长度，恰好 1 条线段在颜色或长度上与多数不同——该线段即为异常值。不同组使用不同的多数颜色（如组 1 多数为红(2)，组 2 多数为绿(3)），异常值颜色也各不相同。生成约束：每条异常值线段的右上端之后在同一反对角线上有足够空间容纳长度+1 的新线段；异常值前移后的新位置不与其他组的线段冲突。

**规则**：
1. 将所有前景线段按其所在反对角线（r+c 值）分组。
2. 在每组内，统计各线段的 (颜色, 长度) 对。出现次数 = 1 的那条线段即为异常值。
3. 对每个异常值线段：
   - 擦除该线段（设为黑）。
   - 在同一反对角线上，从原线段右上端的下一个位置开始，绘制一条长度 = 原长度 + 1 的新线段，颜色保持不变。新线段沿反对角线方向延伸（行递减、列递增）。
4. 所有非异常值（多数）线段保持不变。

**关键洞察**：求解者必须先在视觉上将线段按反对角线分组（非显然，因为不同组的线段在行/列方向上可能交错），然后在每组内做"odd one out"比较。比较维度不是格阵行列而是反对角线——这是对格阵逐行比较原语的几何推广。只有通过对比多个示例才能确认：(a) 分组依据是反对角线而非行/列；(b) 异常值判据同时考虑颜色和长度；(c) 非异常值不动，只有异常值前移增长。
