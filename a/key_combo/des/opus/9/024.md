## 新题 1：竖直条高度排名编码调色板，填充矩形同心色带

**组合逻辑**：[排序/高度排名] → [计数](创新：排名序生成调色板) → [填充/同心色带](创新：外部排名驱动局部填充)

**来源原语**：排序/高度排名/竖直线段/保留极值高度分色(#a61f2674)，填充/同心正方形层/循环色带/距离决定调色板(#13e47133)，计数(#27a77e38, #d631b094)，实心矩形(#e9ac8c9e, #ba9d41b8)

**依赖链**：竖直条的高度差异产生一个全局排名 → 排名顺序赋予每根条的颜色一个调色板位置 → 每个实心矩形按其内部像素到边界的 Chebyshev 距离取调色板颜色，形成同心色带。删掉排名环节，调色板顺序未知；删掉同心填充环节，矩形内部无法着色。

将竖直条的高度排名转化为颜色调色板的顺序，再以该调色板循环填充每个实心矩形的同心层。

**输入结构**：黑(0)背景，约 20x20 网格。网格左侧或顶部排列 3~5 根不同颜色的单像素宽竖直线段（颜色各不相同，从红(2)、绿(3)、蓝(1)、黄(4)、灰(5)中选取），每根高度各不相同（3~10 像素），底部对齐于同一行。网格右侧或下方散布 2~3 个单色灰(5)实心矩形（至少 5x5，保证有多层同心结构），矩形之间互不重叠且不与竖直条重叠。生成约束：竖直条高度严格不同；矩形尺寸保证 Chebyshev 最内层距离 >= 调色板长度。

**规则**：
1. 将所有竖直条按高度从高到低排序，得到颜色序列 palette[0], palette[1], ..., palette[k-1]（高度最高的条的颜色排第一）。若高度相同（生成约束排除此情况），按条在网格中的列位置从左到右 break tie。
2. 擦除所有竖直条（还原为背景色）。
3. 对每个灰(5)实心矩形：计算矩形内每个像素到矩形边界的 Chebyshev 距离 d（边界上 d=0，向内递增）。将该像素重涂为 palette[d mod k]，其中 k 为调色板长度。
4. 矩形以外的区域保持黑(0)背景不变。

**关键洞察**：竖直条不是装饰，它们的高度排名编码了同心带的颜色顺序；调换任意两根条的高度就会改变所有矩形的填充图案。

## 新题 2：重力下落决定扫描序，扫描序决定循环重涂色

**组合逻辑**：[重力下落](已有) + [宽度决定行为](已有) → [排序/扫描序](创新：落点位置产生新扫描序) → [重涂色/颜色循环分配](创新：循环色由落点序决定)

**来源原语**：重力下落/分隔行/穿透与停靠/宽度决定行为/精灵(#84ba50d3)，扫描序/长轴决定扫描/颜色循环分配/重涂色/孤立像素(#9473c6fb)

**依赖链**：精灵体的宽度决定其下落行为（宽精灵停于分隔行上方，窄精灵穿透至底部）→ 落点位置决定扫描序 → 扫描序决定循环重涂色。若跳过重力下落，精灵位置不变，扫描序和颜色完全不同；若跳过重涂色，仅有位置变换无颜色变换。

精灵体按宽度规则下落后，依据落点位置的扫描序循环分配红(2)、青(8)、灰(5)三色。

**输入结构**：黑(0)背景，约 15x18 网格。一条橙(7)满行水平分隔行位于网格中偏下位置（如第 12 行）。分隔行上方分布 4~6 个蓝(1)单色 4-连通精灵体，每个精灵体 3~8 像素，形状各异（有的仅占一列宽度，有的跨 2~3 列）。精灵体之间不重叠，不接触分隔行，各精灵体下方至分隔行之间有足够空间容纳下落。生成约束：至少有 1 个仅一列宽的精灵体和至少 2 个多列宽的精灵体；精灵体的水平位置使得下落后扫描序与原始位置扫描序不同。

**规则**：
1. 清除所有精灵体原始位置的蓝(1)像素（还原为黑(0)）。
2. 对每个精灵体判断宽度（边界框列跨度）：若宽度为 1，该精灵体沿其所在列垂直下落至网格最底行，并擦除它穿越的分隔行像素（该列分隔行变为黑(0)）；若宽度 > 1，该精灵体整体下落直到其最宽水平行段紧邻分隔行上方一行（若移动后精灵体与分隔行重叠，精灵体覆盖分隔行）。
3. 所有精灵体同时下落，互不干扰（生成约束保证落点不冲突）。
4. 下落完成后，计算所有精灵体边界框的左上角坐标。若所有精灵体的边界框在列方向的总跨度 >= 行方向的总跨度，按列主序（列优先、行次之）排列精灵体；否则按行主序（行优先、列次之）排列。
5. 按排列顺序，将第 1 个精灵体所有像素重涂为红(2)，第 2 个为青(8)，第 3 个为灰(5)，第 4 个为红(2)，依此循环。
6. 背景和残留分隔行像素不变。

**关键洞察**：精灵体的原始位置和宽度共同决定落点，落点改变了扫描序，扫描序改变了颜色分配；同一组精灵体换一个起始位置，最终颜色就会完全不同。

## 新题 3：载体色定滑动方向，滑动终点填充边框缺口

**组合逻辑**：[滑动](已有) + [颜色决定方向](已有) → [填充/十字缺口](创新：到达哪侧由滑动决定，填充色来自滑动对象而非边框) + [计数](创新：滑动距离解决多对象冲突)

**来源原语**：滑动/可移动对象/载体区域/嵌入载体内/颜色决定方向(#9b4c17c4)，填充/矩形边框/十字缺口/朝向对应边色/开口朝向决定色(#5b37cb25)

**依赖链**：载体颜色决定滑动方向 → 滑动方向决定对象到达边框的哪一侧 → 到达侧的缺口以对象颜色（非边框侧色）填充 → 多个对象到达同一侧时，滑动距离最远的优先填充缺口。删掉滑动，不知道对象去往哪侧；删掉缺口填充，滑动结果无着落。

彩色小对象沿载体色指定方向滑向矩形边框，用对象自身颜色填充到达侧的缺口。

**输入结构**：黑(0)背景，约 16x16 网格。中央有一个灰(5)单像素厚矩形边框（约 12x12），边框四侧中各有 0~2 个五像素十字形(+)缺口（缺口像素为黑(0)，缺口的开口方向朝向边框外侧，内侧被边框内的前景对象像素封住）。边框内部有 3~5 个不同颜色的单色小对象（每个 2~4 像素，4-连通，颜色从红(2)、绿(3)、黄(4)、品红(6)中选取），每个小对象被一种载体色（蓝(1)或青(8)）的矩形区域包围。蓝(1)载体表示向右滑动，青(8)载体表示向左滑动。生成约束：每个缺口的开口方向恰好对应至少一个对象的滑动目标侧；对象的水平滑动路径上无其他对象阻挡。

**规则**：
1. 对每个小对象，根据其载体颜色确定滑动方向：蓝(1)载体 → 向右，青(8)载体 → 向左。
2. 将每个小对象沿确定方向水平滑动，直到对象边界框的前缘碰到灰(5)边框内侧。记录每个对象的滑动距离（移动的像素列数）。
3. 确定每个对象到达的边框侧（左侧或右侧）。在该侧查找十字缺口。
4. 若某一侧仅有一个对象到达且该侧有缺口：用该对象的颜色填充该侧最近的缺口（5 个缺口像素全部涂为对象颜色）。
5. 若某一侧有多个对象到达且该侧有缺口：选择滑动距离最大的对象的颜色填充缺口。若距离相同，选择在网格中行位置更靠上的对象。该侧若有多个缺口，从上到下依次由滑动距离从大到小的对象填充。
6. 清除所有载体色区域（蓝(1)和青(8)像素还原为黑(0)），清除所有小对象原始位置像素，仅保留边框、已填充的缺口和黑(0)背景。

**关键洞察**：边框缺口的颜色不由边框侧决定，而由滑入该侧的对象决定；载体色同时编码了滑动方向和缺口分配规则。

## 新题 4：旋转标记的双重角色——局部定旋转，全局定缩放

**组合逻辑**：[旋转](已有) + [标记定旋转源目](已有) → [计数/色数决定倍率](创新：标记色的全局多样性决定缩放) → [像素放大](创新：缩放因子来自标记色总数而非输入网格色数)

**来源原语**：旋转/精灵体/单像素标记/缺角方形标记/角落对应/标记定旋转源目(#ecaa0ec1)，像素放大/色块/整体缩放/色数决定倍率(#d4b1c2b1)，计数(#27a77e38)

**依赖链**：每个精灵体的标记局部决定该精灵体的旋转量 → 所有标记像素的颜色全局汇总决定缩放因子 → 每个精灵体先旋转再以全局因子像素放大。删掉旋转，精灵体朝向错误；删掉缩放，输出尺寸错误；删掉计数，缩放因子未知。

标记像素在每个精灵体上指定旋转方向，同时标记颜色的全局多样性决定所有精灵体的统一像素放大倍率。

**输入结构**：黑(0)背景，约 20x20 网格。包含 2~3 个 3x3 的双色精灵体（精灵体内部使用两种前景色构成图案，如红(2)+绿(3)组合）。每个精灵体配有一套旋转标记系统：3 个同色像素构成一个缺角正方形（三个外角位于精灵体某一角的对角方向），1 个同色单像素位于精灵体另一角的对角方向。不同精灵体的标记可以使用不同颜色（如第一个精灵体的标记为黄(4)，第二个为品红(6)，第三个也可能为黄(4)）。精灵体之间间距足够大（至少 6 像素），标记像素不与其他精灵体或标记重叠。生成约束：每个精灵体的旋转标记几何关系明确（缺角方形的缺角恰好触碰精灵体一角，单像素恰好位于精灵体另一角的对角线上）。

**规则**：
1. 对每个精灵体，按旋转标记规则确定旋转量：缺角方形的缺角触碰的精灵体角为目标角，单像素对角相邻的精灵体角为源角；将精灵体原地旋转唯一的四分之一圈倍数使源角映射到目标角。
2. 统计整个网格中所有标记像素（含所有精灵体的缺角方形和单像素标记）使用的不同颜色数 S。
3. 擦除所有标记像素（还原为黑(0)），并在每个缺角方形的几何中心位置放置一个该标记色的像素。
4. 将每个已旋转的精灵体以其边界框中心为锚点进行 S 倍像素放大：精灵体中每个像素替换为 S x S 的同色方块。放大后的精灵体放置于原中心位置，若超出网格边界则裁剪。
5. 背景保持黑(0)。

**关键洞察**：标记像素是双重信号——在每个精灵体的局部语境中编码旋转方向，在全局语境中以颜色多样性编码缩放因子；同一组标记在两个层面上被解读。

## 新题 5：行列奇偶过滤分离信号与噪声，镜像补全信号像素

**组合逻辑**：[行列奇偶决定填充](创新：奇偶不用于棋盘格填充，而用于区分信号/噪声像素) → [对称补全/镜像](创新：仅对过滤后的信号子集执行镜像) → [重涂色](创新：镜像产生的新像素用第二前景色标记)

**来源原语**：行列奇偶决定填充/棋盘格图案/边框与内部分离(#ba9d41b8)，对称补全/镜像/主色前景对象/中轴线/对称/最高频色为目标/忽略干扰项(#c35c1b4c)，重涂色(#a79310a0, #9473c6fb)

**依赖链**：行列奇偶将前景像素分为信号组（偶奇偶）和噪声组（奇奇偶）→ 仅对信号组执行垂直中轴镜像 → 镜像产生的新像素涂为第二色以区分原件与镜像件。删掉奇偶过滤，信号与噪声不分导致镜像结果混乱；删掉镜像，信号像素无法形成对称图案。

利用像素坐标的行列奇偶性区分信号与噪声，对信号像素执行垂直轴镜像补全，补全像素以另一种颜色标记。

**输入结构**：黑(0)背景，约 13x13 网格（行列数均为奇数，保证中轴列存在）。网格上散布约 15~25 个前景像素，分为两种颜色：绿(3)和红(2)。其中绿(3)像素全部位于"行+列为偶数"的坐标位置（即 (r+c) mod 2 == 0），构成一个左半部分的不规则图案（所有绿像素的列坐标 < 网格垂直中轴列）。红(2)像素全部位于"行+列为奇数"的坐标位置（即 (r+c) mod 2 == 1），随机散布在网格各处，充当干扰项。生成约束：绿(3)像素数量 > 红(2)像素数量；绿(3)像素严格在左半区；每个绿像素在中轴镜像位置处为黑(0)背景。

**规则**：
1. 识别所有前景像素的坐标奇偶性：(r+c) mod 2 == 0 的为信号像素，(r+c) mod 2 == 1 的为噪声像素。
2. 保留所有信号像素（绿(3)），擦除所有噪声像素（红(2)还原为黑(0)）。
3. 对每个信号像素，计算其关于网格垂直中轴列 c_mid 的镜像位置：镜像列 = 2 * c_mid - c_original。
4. 在镜像位置放置一个黄(4)像素（若该位置已有信号像素则保持绿(3)不覆盖）。
5. 输出网格包含：原始信号像素（绿(3)）、镜像补全像素（黄(4)）、黑(0)背景。

**关键洞察**：红色像素不是图案的一部分——它们的坐标奇偶性暴露了其干扰本质；真正的信号隐藏在偶奇偶校验的绿色像素中，只有过滤后才能正确执行镜像补全。

## 新题 6：跨面板搬运中最近邻匹配决定锚点颜色配对

**组合逻辑**：[最近邻匹配](创新：匹配不在同一面板内而是跨面板建立颜色链接) + [平移/跨面板搬运](已有) → [锚点对齐](创新：锚点由颜色链接而非固定位置选取) → [重涂色](创新：精灵色来自匹配的标记色)

**来源原语**：最近邻匹配/标记像素/重复精灵体/重涂色/标记主轴方向排列(#50aad11f)，平移/对齐/精灵体/引导标记/分隔行/锚点对齐/跨面板搬运(#dc46ea44)

**依赖链**：下面板中每个精灵体与最近单色标记匹配获得颜色标签 → 上面板中引导锚点各有一种颜色 → 精灵体通过颜色标签找到上面板中颜色匹配的锚点 → 将精灵体搬运至该锚点位置并重涂为锚点颜色。删掉最近邻匹配，精灵体不知道对应哪种颜色；删掉跨面板搬运，精灵体无法到达目标位置。

下面板的精灵体通过最近邻标记获得颜色身份，再搬运至上面板中颜色匹配的锚点处并重涂色。

**输入结构**：黑(0)背景，约 18x12 网格。一条灰(5)满行水平分隔行将网格分为上下两个面板。下面板包含 3 个形状相同的灰(5)单色 4-连通精灵体（每个 4~6 像素），以及 3 个不同颜色的单像素标记（如红(2)、蓝(1)、绿(3)），每个标记紧邻一个精灵体（8-连通距离 <= 2）。上面板包含 3 个与下面板标记颜色一一对应的锚点标记（每个锚点为一个由 3~5 个同色像素组成的小十字或 L 形结构），分布在上面板的不同位置。生成约束：每个下面板标记与恰好一个精灵体最近（无距离相同导致歧义的情况）；上面板三个锚点的颜色与下面板三个标记颜色完全相同且一一对应；精灵体搬运后不超出网格边界。

**规则**：
1. 在下面板中，将每个单像素标记与最近的精灵体配对（欧氏距离，计算标记到精灵体最近像素的距离）。每个精灵体获得其配对标记的颜色标签。
2. 清除下面板所有精灵体和标记像素（还原为黑(0)），保留分隔行。
3. 对每个精灵体，在上面板中找到与其颜色标签相同颜色的锚点标记。
4. 将精灵体搬运至上面板：精灵体边界框的左上角对齐到锚点标记边界框的右下角的右下方一格位置（即锚点右下角的 (row+1, col+1)）。
5. 将搬运后的精灵体重涂为其颜色标签的颜色（替代原来的灰(5)）。
6. 上面板的锚点标记保留不变。

**关键洞察**：下面板的空间邻近关系（最近邻匹配）创建了一张颜色映射表，这张表在跨面板搬运时充当地址解码器——精灵体不是去固定位置，而是去颜色匹配的锚点。

## 新题 8：像素放大后各块内部以邻域颜色构建同心色带

**组合逻辑**：[像素放大/掩码映射](已有) → [填充/同心正方形层](创新：每个放大块的同心带调色板不来自标记像素，而来自原始网格中该像素的四邻域颜色) + [边框与内部分离](创新：每个块的边框保持原色，仅内部填充同心带)

**依赖链**：像素放大创建每个块的空间 → 原始网格中该像素的四邻域提供颜色列表 → 颜色列表按上-右-下-左顺序构成调色板 → 块内部（排除边框一圈）按 Chebyshev 距离循环填充调色板色。删掉像素放大，无内部空间可填充；删掉邻域查询，调色板来源不明。

将小网格像素放大后，每个放大块的内部以该像素在原图中的上-右-下-左邻域颜色为调色板绘制同心色带。

**输入结构**：约 4x4 的小输入网格（无黑(0)背景，所有像素均有颜色），使用 3~4 种颜色（如红(2)、蓝(1)、绿(3)、黄(4)）。每个像素至少有 2 个有效邻居（非边界方向的邻居），即输入不含 1x1 网格。生成约束：输入网格至少 3x3；放大倍率固定为 5（每个像素变为 5x5 块），输出约 20x20。

**规则**：
1. 将输入网格每个像素放大为 5x5 的方块，方块全部先填充为该像素的原色。
2. 对每个 5x5 方块，保留最外一圈（边框）为原色不变。
3. 对方块内部（3x3 区域），构建调色板：依次取原始网格中该像素的上方邻居色、右方邻居色、下方邻居色、左方邻居色。若某方向无邻居（像素在原始网格边缘），跳过该方向。去重后得到调色板 P（保持首次出现顺序）。
4. 对内部 3x3 区域的每个像素，计算其到内部边界的 Chebyshev 距离 d（内部区域的最外圈 d=0，中心 d=1）。将该像素涂为 P[d mod len(P)]。
5. 各方块之间无间隙直接拼接。

**关键洞察**：每个放大块的内部图案不由自身颜色决定，而由其在原始小网格中的邻居决定——局部图案编码了全局拓扑结构。

## 新题 9：角标记颜色多数投票决定内外位移方向

**组合逻辑**：[计数/多数投票](创新：对角标记颜色投票而非对图案区计数) → [平移/标记内角移外角](创新：投票结果决定移动方向是内→外还是外→内) + [擦除](已有)

**来源原语**：计数/多数投票/多数决(#27a77e38)，平移/空心矩形/角标记/内外对角/标记内角移外角/擦除(#952a094c)

**依赖链**：每个空心矩形的 4 个角标记颜色进行多数投票 → 若存在多数色（>= 3 个同色），该矩形的角标记从内角移至外角 → 若无多数色（2-2 平分或四色各异），该矩形的角标记从内角移至边框中点。投票结果决定位移目标类型，而非单纯的方向翻转。

角标记的颜色分布通过多数投票决定标记的目标位置：多数色存在则移至外角，否则移至边中点。

**输入结构**：黑(0)背景，约 18x18 网格。包含 2~3 个单像素厚的灰(5)空心矩形（每个至少 5x5），矩形之间互不重叠且间距 >= 3。每个矩形内部四角各有一个彩色标记像素（位于矩形内框的四个角位置），标记颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取。不同矩形的标记颜色分布不同——有的矩形 4 个标记中 3 个同色（存在多数色），有的矩形 4 个标记两两同色（2-2 平分）。生成约束：至少一个矩形有多数色，至少一个矩形无多数色；外角目标位置和边中点目标位置不与其他矩形重叠。

**规则**：
1. 对每个空心矩形，统计其 4 个内角标记像素的颜色。
2. 判断是否存在多数色（出现次数 >= 3 的颜色）：
   - 若存在多数色：清除 4 个内角标记（还原为黑(0)），将每个标记移至矩形边界框向外扩展 1 格后的对角位置（左上内角 → 左上外角，右上内角 → 右上外角，以此类推），标记保持原色。
   - 若无多数色：清除 4 个内角标记（还原为黑(0)），将每个标记移至其最近的矩形边框中点位置（左上标记和右上标记 → 顶边中点列，取行为边框顶行外一行；左下标记和右下标记 → 底边中点列，取行为边框底行外一行；左上标记和左下标记 → 左边中点行，取列为边框左列外一列；右上标记和右下标记 → 右边中点行，取列为边框右列外一列）。具体地：左上角标记移至顶边中点外一行，右上角标记移至右边中点外一列，左下角标记移至左边中点外一列，右下角标记移至底边中点外一行。每个标记保持原色。
3. 灰(5)矩形边框保持不变，背景保持黑(0)。

**关键洞察**：角标记的颜色不是装饰——它们的多数/少数关系决定了标记被移至外角（径向发射）还是边中点（切向分配）；只看单个示例无法区分这两种模式，必须对比两种情况才能归纳规则。

## 新题 10：棋盘格掩码过滤后各色存活数量决定压缩行的颜色顺序

**组合逻辑**：[行列奇偶决定填充](创新：奇偶不填充而用作空间掩码来淘汰像素) → [计数](创新：计数被掩码改变后的存活量而非原始量) → [排序](创新：存活量排序而非高度排序) → [压缩](创新：输出为排序后的单行色带)

**来源原语**：行列奇偶决定填充/棋盘格图案(#ba9d41b8)，计数/前景像素/数量决定输出宽(#d631b094)，排序(#a61f2674, #9473c6fb)，裁剪/前景矩形(#7468f01a)，压缩(#d631b094)

**依赖链**：棋盘格掩码保留偶校验位置的像素、擦除奇校验位置的像素 → 各颜色的存活像素数量发生变化 → 按存活数量从大到小排序颜色 → 输出一行色带，每种颜色占一格，排列顺序为存活数量降序。删掉棋盘格掩码，计数结果不同导致排序不同；删掉计数/排序，无法确定颜色顺序。

对前景区域施加棋盘格掩码后统计各色存活数量，按数量降序输出单行色带。

**输入结构**：黑(0)背景，约 10x10 网格。网格中央有一个多色前景矩形区域（约 6x8），由 3~4 种颜色（如红(2)、蓝(1)、绿(3)、黄(4)）的像素组成，像素排列不均匀——不同颜色占据不同数量的格子，且各颜色在偶校验位置和奇校验位置上的分布比例不同。生成约束：至少有两种颜色的原始像素总数相同但偶校验位置像素数不同（确保棋盘格掩码改变排名顺序）；前景矩形区域外为黑(0)背景。

**输出结构**：1 行 x k 列的小网格（k = 前景颜色种数），每格一种颜色，按棋盘格掩码后存活数量从多到少排列（最左为最多）。若两种颜色存活数量相同，按该颜色在前景矩形中首次出现的位置（行主序扫描）排列，先出现的排在前。

**规则**：
1. 找到所有非黑(0)前景像素的紧边界框，裁剪出前景矩形区域。
2. 对裁剪后的矩形施加棋盘格掩码：以矩形左上角为原点 (0,0)，保留 (r+c) mod 2 == 0 的像素（偶校验），将 (r+c) mod 2 == 1 的像素设为黑(0)（奇校验淘汰）。
3. 统计掩码后每种非黑颜色的存活像素数。
4. 按存活像素数从大到小排序颜色。平局时，按该颜色在裁剪矩形中按行主序首次出现的位置排序（行主序更早的排前面）。
5. 输出 1 x k 网格，从左到右依次填入排序后的颜色。

**关键洞察**：棋盘格掩码不是视觉效果而是一个空间采样器——它改变了各颜色的"权重"，使得原始数量相同的颜色在掩码后排名不同；颜色在网格中的空间分布直接影响最终顺序。
