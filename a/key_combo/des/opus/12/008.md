## 新题 1：射线触及环形体的计数色循环

**组合逻辑**：[ray_extend](对角射线从孤立像素出发，遇环停止) + [counting](统计每个环被射线触及的次数) + [color_cycle + corner_side_group](触及次数驱动环内角-边中反向循环步数)（三类原语创新耦合：射线几何 → 触及计数 → 循环步数）

**来源原语**：ray_extend, diagonal_dir, isolated_pixel, canvas_boundary (623ea044); color_cycle, ring_object, corner_pixel, side_center_pixel, opposite_cycle, corner_side_group (46c35fc7); counting (a59b95c0)

**依赖链**：射线从孤立像素出发沿对角线延伸，遇到环形对象的外围像素时停止；射线的几何布局决定哪些环被触及以及触及次数 k；k 控制环内角位像素顺时针循环 k 步、边中像素逆时针循环 k 步。三者形成"射线布局 → 触及计数 → 循环步数"的紧耦合链，改变任一孤立像素的位置都会改变所有环的最终颜色。

将孤立像素的对角射线用作环形对象色循环的"驱动信号"：射线触及次数越多，环上颜色旋转越远。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 2-3 个孤立非黑像素（各不同色，如红(2)、蓝(1)、黄(4)），散布于网格内，彼此不在同一行/列/对角线上。
- 2-4 个完整的 3x3 环形前景对象：每个环由 8 个非黑像素围绕 1 个黑(0)中心组成，环的四个角位使用灰(5)，四个边中位使用橙(7)（或其他固定双色组合，各示例中同一类位置使用同一颜色）。环之间互不相邻（边界框不接触）。
- 生成约束：每个孤立像素的四条对角射线至少有一条能到达某个环的外围像素的 4-邻接位置后停止；至少一个环被 2 条以上射线触及。

**规则**：
1. 从每个孤立像素出发，沿四条对角方向（左上、右上、左下、右下）逐格画射线，颜色为该像素的颜色。射线在以下情况停止（不包含停止格）：(a) 到达网格边界；(b) 下一格是任何环形对象的外围像素。
2. 对每个环形对象，统计有多少条射线的终点像素与该环的外围像素 4-邻接（即射线末端紧贴环的外围），记为触及次数 k。同一孤立像素的多条射线可分别触及同一个环（各自计 1 次）。
3. 对每个 k >= 1 的环：将四个角位像素的颜色沿顺时针方向（左上→右上→右下→左下→左上）循环 k 步；将四个边中像素的颜色沿逆时针方向（上→左→下→右→上）循环 k 步。k = 0 的环保持不变。
4. 所有射线像素和孤立源像素保留在输出中，环的黑色中心保持黑(0)。

**关键洞察**：射线是否触及某个环取决于对角线路径上有无其他环阻挡——一个环可能"遮蔽"另一个环使其少收到触及，因此所有环的相对位置共同决定每个环的循环步数，不能独立分析单个环。

## 新题 2：双掩码异或区域中的贪心正方形分级着色

**组合逻辑**：[xor_overlay](双掩码逐像素异或产生活跃区域) → [greedy_selection + largest_first_priority + non_overlapping_constraint](在活跃区域中贪心提取最大不重叠正方形) → [size_to_color_mapping](按正方形边长映射颜色)

**来源原语**：xor_overlay, separator_row, foreground_mask, disagreement_cells_painted (99b1bc43); boolean_op, mask_region, alignment (6430c8c4); greedy_selection, blank_square_region, largest_first_priority, non_overlapping_constraint, minimum_side_length_constraint (31adaf00); size_to_color_mapping (00dbd492)

**依赖链**：分隔行分割上下两层掩码 → 异或运算产生不规则的活跃像素区域 → 区域的几何形状限制可提取的正方形大小 → 贪心选择从大到小提取不重叠正方形 → 正方形边长决定填充颜色。每一步的输出是下一步的必要输入，且异或区域的形状由两层掩码共同决定，无法从任一层单独推断。

两层掩码的对称差产生不规则前景区域，在其中贪心提取最大不重叠正方形，再按边长分级着色。

**输入结构**：
- 网格约 15x20（15 列、20 行），中间有一条全宽红(2)分隔行将网格分为等高的上下两层。
- 上层掩码：黑(0)背景上有蓝(1)前景像素构成 2-4 个不规则 4-连通区域（每个区域 5-15 像素）。
- 下层掩码：黑(0)背景上有黄(4)前景像素构成 2-4 个不规则 4-连通区域，与上层的前景区域有部分空间重叠、部分独立。
- 生成约束：上下两层尺寸相同（去除分隔行后行列数一致）；异或后的活跃区域中至少存在一个边长 >= 3 的全活跃正方形子区域。

**规则**：
1. 移除红(2)分隔行，将上下两层掩码逐像素对齐（第 i 行第 j 列对应）。
2. 对每个像素位置，若恰好一层为前景（蓝或黄）、另一层为背景（黑），标记为活跃；两层都是前景或都是背景则标记为非活跃。初始时活跃像素涂绿(3)。
3. 在活跃像素区域中搜索所有边长 >= 2 的全活跃轴对齐正方形候选区域。
4. 从最大边长到最小边长依次处理候选：若候选正方形不与任何已选中的正方形重叠，则选中。同边长候选按左上角行优先、列次优先排序（即从上到下、从左到右）。
5. 对选中的正方形重涂颜色：边长 2 → 青(8)，边长 3 → 黄(4)，边长 4 → 橙(7)，边长 >= 5 → 品红(6)。未被选中的活跃像素保持绿(3)。非活跃像素为黑(0)。
6. 输出网格的尺寸等于单层掩码的尺寸（分隔行已移除）。

**关键洞察**：两层掩码的前景区域越多重叠，异或后的活跃区域就越小、越碎片化，可提取的正方形也越小——求解者需要同时理解异或语义和贪心提取策略，二者缺一不可。

## 新题 3：边缘匹配链序驱动图例着色

**组合逻辑**：[edge_pixel_matching + chaining_by_edge_contact](块的边缘前景像素匹配确定唯一链式排序) ⊗ [color_bar_legend + legend_order_to_slot](链中位序与图例颜色一一映射) → [recolor](按映射重涂每个块的前景色)

**来源原语**：edge_pixel_matching, chaining_by_edge_contact, sprite, separator_line (78332cb0); color_bar_legend, legend_order_to_slot, stamp_overlay (94be5b80); recolor, ctrl_color_map (cfb2ce5a)

**依赖链**：边缘像素匹配是唯一能确定块排列顺序的信息 → 排列顺序与图例颜色的对应是唯一能确定重涂颜色的信息 → 两步约束共同决定输出，删除任一步都无法确定最终颜色。这是一个约束满足结构而非纯流水线——链序和图例映射必须同时满足。

通过边缘前景像素匹配确定精灵体块的唯一链式排列顺序，链中第 i 个块的前景重涂为图例中第 i 种颜色。

**输入结构**：
- 网格约 22x10，背景黑(0)。
- 网格上部有一条水平图例：N 个相邻单列色条（每条 1 列宽、3 行高），颜色各不相同且均非黑(0)/灰(5)，如蓝(1)、红(2)、绿(3)、黄(4)（N = 4-5）。图例与下方内容之间隔 1 行黑色。
- 图例下方有 N 个 5x5 精灵体块，被灰(5)单列分隔，水平排列。每个块使用灰(5)为前景、黑(0)为背景，各块的灰色图案不同。
- 每个块的左边缘列和右边缘列各有 0-3 个灰(5)像素。两个块"可链接"当且仅当左块右边缘与右块左边缘在至少一个相同行偏移处都有灰(5)像素。
- 生成约束：N 个块恰好存在唯一的链式排列（一条从某块开始、每步唯一后继的完整链），当前输入中块的排列顺序不等于链式顺序。

**规则**：
1. 读取图例从左到右的颜色序列 C_1, C_2, ..., C_N。
2. 检查每对块的边缘匹配关系：块 A 的右边缘第 r 行有灰(5)且块 B 的左边缘第 r 行也有灰(5)（r 为块内行偏移 0-4），若至少一个 r 满足，则 A 可链接到 B（A→B）。
3. 找到唯一的链式全排列 B_1 → B_2 → ... → B_N，其中 B_i → B_{i+1} 均满足边缘匹配。
4. 将链中第 i 个块 B_i 的所有灰(5)前景像素重涂为 C_i。黑(0)背景不变。
5. 输出为按链式顺序水平排列的 N 个重涂后块，块间以灰(5)单列分隔，无图例行（图例在输出中移除）。

**关键洞察**：图例的颜色数等于块数这一对应关系不是偶然——它暗示链序与图例序是同一序关系。求解者必须先发现边缘匹配规则确定链序，再发现链序与图例的对应，两者缺一不可。

## 新题 4：像素对滑动聚合后涌现环形色循环

**组合逻辑**：[slide + adjacent_stop + same_hue_pairing](同色系像素对相向滑动直至相邻) → [ring_object 涌现检测](滑动结果中检测新形成的 3x3 环) → [color_cycle + corner_side_group + opposite_cycle](完整环执行角-边中反向色循环)

**来源原语**：slide, pixel_pair, adjacent_stop, same_hue_pairing, ignore_distractors (494ef9d7); color_cycle, ring_object, corner_pixel, side_center_pixel, opposite_cycle, corner_side_group (46c35fc7)

**依赖链**：滑动改变像素的空间位置 → 新位置决定是否有 8 个像素恰好围成 3x3 环 → 仅对涌现的完整环执行色循环 → 色循环的结果取决于环上各位置的颜色（来自不同滑动对）。环是滑动后的涌现结构——输入中不存在任何环。

散布的同色系像素对水平滑动聚合后，部分像素恰好拼合成完整的 3x3 环形结构，对这些涌现环执行角-边中反向色循环。

**输入结构**：
- 网格约 12x12，背景黑(0)。
- 散布若干单个前景像素，使用 4 种颜色：蓝(1)、青(8)（冷色系对）和红(2)、橙(7)（暖色系对）。
- 每行至多含同一色系的两个像素（构成一个像素对）。蓝与青为一对，红与橙为一对。对内左侧像素列坐标更小。
- 另有若干灰(5)单像素散布于网格中，为干扰项不参与任何操作。
- 生成约束：所有像素对滑动后（右像素移至左像素右侧紧邻位置），恰好有 1-2 组共 8 个前景像素围绕一个黑(0)中心位置构成完整 3x3 环；其余像素对滑动后不参与构成任何环。输入中不存在任何预成的 3x3 环。

**规则**：
1. 识别同色系像素对：蓝(1)与青(8)互为配对色系，红(2)与橙(7)互为配对色系。每行至多一个像素对，对内左像素固定不动。
2. 对每个像素对，将右侧像素向左滑动至左侧像素的紧邻右方（列坐标 = 左像素列坐标 + 1），清除右像素原位置为黑(0)。灰(5)像素不动；非配对的孤立前景像素不动。
3. 滑动完成后，检测所有满足以下条件的 3x3 区域：恰好 8 个外围位置被非黑前景像素占据，中心位置为黑(0)。
4. 对每个检测到的完整环：四个角位（左上、右上、右下、左下）的颜色沿顺时针旋转 1 步（左上色→右上，右上色→右下，右下色→左下，左下色→左上）；四个边中位（上、右、下、左）的颜色沿逆时针旋转 1 步（上色→左，左色→下，下色→右，右色→上）。
5. 未构成完整环的像素保持滑动后的位置和颜色不变。

**关键洞察**：环是滑动操作的涌现产物——求解者无法预知哪些像素会形成环，必须先完成滑动模拟再检测结构，且同一像素对的滑动距离由行内间距决定，间距不同则环的形成与否不同。

## 新题 5：重叠空心矩形的深度分层填充

**组合逻辑**：[hollow_rectangle + center_marker 识别](从标记像素和可见边框碎片还原每个矩形的完整范围) ⊗ [重叠深度计算](逐像素统计被多少个矩形内部覆盖——同时约束满足) → [size_to_color_mapping 变体](深度→颜色映射)

**来源原语**：hollow_rectangle, center_marker, fill, size_to_color_mapping, marker_centered_inside_frame (00dbd492); greedy_selection, non_overlapping_constraint (31adaf00); stamp_overlay (92e50de0)

**依赖链**：标记像素定位矩形中心 → 从中心向外搜索边框确定矩形范围 → 但边框在重叠处被遮挡，需要结合所有矩形的信息交叉推断 → 确定所有矩形后计算每个像素的覆盖深度 → 深度映射到颜色。矩形范围推断和深度计算是同时约束满足问题，而非逐对象独立处理。

多个空心矩形相互重叠，根据标记像素和可见边框碎片还原所有矩形的完整范围，再按每个像素被覆盖的矩形内部数量（深度）分级着色。

**输入结构**：
- 网格约 18x18，背景黑(0)。
- 3-4 个红(2)空心矩形边框，边长为奇数（范围 5-13），矩形中心各不相同。矩形之间有部分重叠——一个矩形的内部区域与另一个矩形的边框或内部交叉。
- 每个矩形的几何中心有一个红(2)标记像素，标记像素始终可见（不被其他矩形的边框覆盖）。
- 当两个矩形的边框在同一像素重叠时，该像素仍显示为红(2)；当一个矩形的边框像素落在另一个矩形的内部区域时，边框像素可见（红色覆盖黑色内部）。
- 生成约束：每个矩形至少有两条完整边可见（未被其他矩形的边框像素部分遮挡到无法推断长度）；至少两个矩形的内部区域有非空交集。

**规则**：
1. 识别所有红(2)标记像素（不在任何矩形边框上、在某矩形几何中心的孤立红像素）。每个标记对应一个矩形。
2. 对每个标记像素，从该位置向四个方向（上下左右）搜索最近的红(2)边框像素，从而确定该矩形的半边长和完整边界。若某方向的边框被另一个矩形的边框遮挡（红像素属于两个矩形），则利用对称性（中心到已知边的距离）推断该方向的边界。
3. 对每个非边框非标记的像素位置 (r, c)，计算它被多少个矩形的内部区域严格包含（位于该矩形边框之内、非边框本身），记为深度 d。
4. 按深度着色：d = 0 → 黑(0)不变；d = 1 → 青(8)；d = 2 → 黄(4)；d = 3 → 绿(3)；d >= 4 → 品红(6)。
5. 所有红(2)边框像素和红(2)标记像素在输出中保持红(2)不变。

**关键洞察**：被遮挡的边框必须从标记位置和矩形的对称性推断——如果标记到上边框的距离为 3 行，那么到下边框也必须是 3 行，即使下边框被另一个矩形的边框穿过。这种交叉推断使得各矩形的范围确定不能独立进行。

## 新题 6：跨分隔行块网格的异或解码与通配符修复

**组合逻辑**：[block_grid + separator_row](识别分隔行上下两个块网格) ⊗ [invert_code 变体 + xor_overlay](块级异或——上下不同类型则输出精灵，相同则输出空白) + [wildcard_as_blank + repair](灰色通配符需从完好块推断精灵后才能判别块类型)

**来源原语**：block_grid, repeated_sprite, uniform_blank, invert_code, wildcard_as_blank, sprite_blank_inv (6350f1f4); xor_overlay, separator_row, foreground_mask, disagreement_cells_painted (99b1bc43); repair (6350f1f4)

**依赖链**：分隔行将网格分为上下两个块网格 → 精灵模板从完好块推断 → 通配符块需与精灵模板对比才能判定类型 → 上下两层同位置块的类型组合通过异或逻辑决定输出块类型 → 三步循环依赖：精灵推断 → 通配符解析 → 异或判定。这是一个结构解构问题——输入是两层编码的叠加，求解者需分层解析。

两个块网格被分隔行隔开，每个块是精灵或空白（可能含灰色通配符擦除），从完好块推断精灵后解析通配符，最终按块级异或输出单层结果。

**输入结构**：
- 网格约 20x10，中间一行为品红(6)全宽分隔行。
- 分隔行上下各为一个块网格，由黑(0)单行/单列分隔线划分为等大方形块的阵列（如 3x3 方块组成 2x4 排列，共 8 个块位置）。上下两层的阵列维度相同。
- 精灵使用两种颜色（如蓝(1)为多数色、红(2)为少数色）组成固定的非对称图案（约 5-7 像素前景）。每个块要么是该精灵的副本（精灵块），要么是精灵少数色红(2)的均匀填充（空白块）。
- 部分块中有灰(5)像素替换了精灵或空白的原始像素（通配符擦除），使得该块的类型不能仅凭自身内容判断。
- 生成约束：至少有一个完整无灰像素的精灵块（跨两层中任一层即可），且精灵为非对称图案以排除翻转歧义。

**规则**：
1. 识别品红(6)分隔行，将网格分为上下两层。在每层中识别黑(0)分隔线，切分出等大方形块。
2. 从所有层中找到完整（无灰像素）且包含两种颜色的块，推断出精灵图案模板（所有完好精灵块应一致）。
3. 对含灰(5)像素的块判定类型：将灰像素视为通配符（匹配任意颜色）。若块的非灰像素与精灵模板对应位置一致，则判定为精灵块；若非灰像素全部为精灵少数色且无矛盾，则判定为空白块。
4. 对上下两层的每个对应位置执行块级异或：若两层块类型不同（一精灵一空白），输出完整精灵块（无灰像素）；若相同（都精灵或都空白），输出空白块（精灵少数色均匀填充）。
5. 输出为单层块网格（与一层尺寸相同），块间分隔线恢复为黑(0)，品红分隔行移除。

**关键洞察**：灰色通配符使得某些块的类型必须借助精灵模板推断，而精灵模板又需要从完好块获取——如果所有完好块恰好都是空白块，就无法直接获得精灵模板，此时必须从含灰的精灵块中交叉推断。这种循环依赖是本题的核心难度。

## 新题 7：对角射线间隙中的贪心正方形邻接着色

**组合逻辑**：[ray_extend + both_diags_through_pixel](多源对角射线划定间隙区域) → [greedy_selection + largest_first_priority](间隙中贪心提取最大不重叠正方形) → [recolor 由邻接射线色决定](正方形颜色取决于与其边界 4-邻接的射线中最多出现的源色)

**来源原语**：ray_extend, isolated_pixel, diagonal_dir, both_diags_through_pixel, canvas_boundary (623ea044); greedy_selection, blank_square_region, largest_first_priority, non_overlapping_constraint, minimum_side_length_constraint (31adaf00); recolor (cfb2ce5a/94be5b80)

**依赖链**：射线的空间布局同时决定两件事——(a) 间隙区域的形状（限制可提取的正方形大小），(b) 邻接颜色信息（决定正方形的填充色）。这不是纯流水线：射线位置对正方形大小和颜色施加同时约束，求解者必须从全局射线网格推断局部正方形属性。

多个孤立像素各发射四条对角射线，射线交织成网格状结构；在射线之间的黑色间隙中贪心提取最大不重叠正方形，每个正方形的颜色由其周围射线的源像素颜色多数决定。

**输入结构**：
- 网格约 16x16，背景黑(0)。
- 2-3 个孤立非黑像素，颜色各不相同（如红(2)、蓝(1)、绿(3)），位置使得其对角射线将网格分割为多个黑色间隙区域。
- 生成约束：孤立像素不在网格边角；射线之间的黑色区域中至少存在 2 个边长 >= 2 的不重叠正方形区域。

**规则**：
1. 按孤立像素在网格中的位置排序（行优先，同行按列），按此顺序依次为每个像素绘制四条对角射线。射线颜色为该像素的颜色，从该像素位置出发沿四个对角方向逐格延伸至网格边界。若射线路径上的某格已被先前绘制的射线占据，则该格保持先前颜色（先绘制优先），当前射线在该处断开但继续向同方向延伸（跳过已占据格继续检查后续格，若后续格为黑则涂色）。
2. 射线绘制完成后，在所有黑(0)像素中搜索边长 >= 2 的全黑轴对齐正方形候选区域。
3. 从最大边长到最小边长贪心选择不重叠的正方形。同边长的候选按左上角行优先、列次优先排序。
4. 对每个选中的正方形，统计其边界（四条边上的像素）向外 4-邻接的所有射线像素的颜色。取出现次数最多的颜色作为该正方形的填充色。若多色出现次数相同，取其中在输入网格中源像素（孤立像素）位置靠左上（行优先、列次优先）的那个颜色。
5. 将选中正方形填充为确定的颜色。未被选中的黑像素保持黑(0)。射线像素保持原色。孤立像素保持原色。

**关键洞察**：射线几何同时扮演"区域划定者"和"颜色提供者"两个角色——改变任一孤立像素的位置不仅改变间隙的大小形状，还改变每个正方形周围的颜色比例，因此射线布局对输出的影响是全局性的。

## 新题 8：路径生长穿越翻转象限

**组合逻辑**：[quadrant + mirror](网格分为四象限，品红标记编码各象限的翻转规则) ⊗ [path_grow + obstacle_deflection](路径从底部控制像素生长，穿越象限边界时行进规则随象限翻转属性而改变)

**来源原语**：quadrant, mirror, flip_correspond, template_block, ctrl_color_map (cfb2ce5a); path_grow, control_pixel, obstacle_deflection, bottom_row_origin, step_by_step_climb, blocker (712bf12e)

**依赖链**：品红标记在左上象限中的子位置编码四象限的翻转方案 → 每个象限的翻转属性决定路径在该象限内的生长方向和偏转方向 → 路径穿越象限边界时规则改变 → 障碍物位置与象限规则交织决定路径轨迹。这是非流水线结构：路径的当前状态（位置+方向）和网格结构（象限+障碍）共同决定下一步。

路径从底行控制像素出发逐步向上生长，遇障碍偏转，穿越象限边界时行进方向和偏转方向由该象限的翻转属性改变。

**输入结构**：
- 网格为 16x16 偶数边长正方形，背景黑(0)。网格被均分为 2x2 的四个 8x8 象限（无显式分隔线，靠网格中心坐标划分：左上象限行 0-7 列 0-7，右上象限行 0-7 列 8-15，左下象限行 8-15 列 0-7，右下象限行 8-15 列 8-15）。
- 左上象限中恰有一个品红(6)标记像素，位于该象限的四个 4x4 子区域之一（左上区、右上区、左下区、右下区），其位置编码翻转方案。
- 每个象限内散布 2-5 个灰(5)障碍像素。
- 最底行（第 15 行，属于下方两个象限）有 1-2 个红(2)控制像素。
- 生成约束：路径至少穿越一个象限边界；品红标记不在灰色障碍的 4-邻接位置。

**规则**：
1. 将网格均分为四象限：左上(UL)、右上(UR)、左下(BL)、右下(BR)。
2. 品红标记在 UL 象限中的相对位置（上半/下半 x 左半/右半）编码翻转方案：
   - 标记在 UL 的左上 4x4 区 → UL=原始, UR=水平翻转, BL=垂直翻转, BR=双翻转
   - 标记在 UL 的右上 4x4 区 → UL=水平翻转, UR=原始, BL=双翻转, BR=垂直翻转
   - 标记在 UL 的左下 4x4 区 → UL=垂直翻转, UR=双翻转, BL=原始, BR=水平翻转
   - 标记在 UL 的右下 4x4 区 → UL=双翻转, UR=垂直翻转, BL=水平翻转, BR=原始
3. 每个象限的翻转属性决定该象限内路径的行为：
   - 原始：生长方向向上（行号减小），遇障碍向右偏转一格
   - 水平翻转：生长方向向上，遇障碍向左偏转一格
   - 垂直翻转：生长方向向下（行号增大），遇障碍向右偏转一格
   - 双翻转：生长方向向下，遇障碍向左偏转一格
4. 从每个红(2)控制像素开始生长。每步操作：确定当前位置所在象限及其规则；尝试沿生长方向移动一格——若目标格为黑(0)，涂红(2)并从新位置继续；若目标格为灰(5)障碍或网格边界，则在当前行向偏转方向移动一格——若该格为黑(0)，涂红(2)并从新位置继续，否则路径终止。
5. 路径越过象限边界线后，自动使用新象限的规则（生长方向和偏转方向可能改变）。
6. 品红(6)标记像素在输出中清除为黑(0)。所有灰(5)障碍保持不变。

**关键洞察**：同一个灰色障碍在不同象限中可能导致路径向左或向右偏转——而求解者无法通过单个示例确定翻转编码规则，必须对比多个示例中品红标记位置和路径偏转方向的对应关系。

## 新题 9：筛除干扰矩形后色数驱动镜像平铺

**组合逻辑**：[filtering + smallest_rect_retained 变体](识别并移除面积最小的实心矩形干扰对象) → [counting + color_count_repetition](移除后的色数 N 决定平铺倍数) → [tiling + mirror + flip_copy_stacked](N x N 镜像平铺而非简单复制)

**来源原语**：crop, filtering, solid_rectangle, distractor_object, smallest_rect_retained (23b5c85d); tiling, counting, tile, palette, color_count_repetition, array_layout (a59b95c0); mirror, concatenate, canvas, flip_copy_stacked (4c4377d9); repetition (a416b8f3)

**依赖链**：干扰矩形是否引入了独有颜色决定移除后 N 的值 → N 决定平铺次数 → 平铺方式为镜像交替而非简单复制 → 三步中任何一步的改变（不同干扰颜色、不同 N、不同翻转规则）都会导致不同输出。干扰对象的筛选和色数计算之间存在隐蔽的耦合——干扰矩形的颜色是否是核心图案的颜色子集直接影响 N。

移除面积最小的实心矩形干扰对象后，统计剩余网格中的不同颜色总数 N，将清理后的网格以镜像交替方式平铺为 N x N 阵列。

**输入结构**：
- 网格约 5x5 至 7x7 的小型网格，背景黑(0)。
- 一个核心图案：使用 2-3 种非背景色（如蓝(1)、红(2)、绿(3)）的 4-连通前景区域，占据网格大部分空间，形状不规则。
- 1-2 个干扰对象：单色实心矩形（像素恰好填满其边界框），面积在所有实心矩形中最小。
- 干扰矩形的颜色可能是核心图案中已有的颜色（此时移除不改变色数），也可能是核心图案中不存在的独有颜色（此时移除后色数减少）。
- 生成约束：核心图案的前景部分不构成任何实心矩形（确保只有干扰对象被识别为实心矩形并移除）。

**规则**：
1. 识别所有单色非背景对象中像素恰好填满其边界框的实心矩形。
2. 找到面积最小的实心矩形（若有多个最小面积的则全部移除），将其像素清除为黑(0)。
3. 统计清理后网格中出现的不同颜色总数 N（包含黑(0)背景）。
4. 将清理后的网格平铺为 N x N 的块阵列，采用镜像交替规则：
   - 列块索引从 0 开始：偶数列块保持原始水平方向，奇数列块水平翻转。
   - 行块索引从 0 开始：偶数行块保持原始垂直方向，奇数行块垂直翻转。
   - 行列翻转独立叠加：偶行偶列 = 原始，偶行奇列 = 水平翻转，奇行偶列 = 垂直翻转，奇行奇列 = 双翻转（水平+垂直）。

**关键洞察**：干扰矩形的颜色选择是一个隐蔽变量——当干扰色在核心图案中也出现时，移除它不改变 N，平铺规模不变；当干扰色是独有的，移除后 N 减小，平铺规模缩小。求解者必须对比多个示例才能发现这一依赖关系。

## 新题 10：种子图案沿单元格对角线传播与逐步色交替

**组合逻辑**：[cell_array + seed_motif](脚手架网格中定位种子) → [diagonal_propagate](种子沿单元格阵列对角线传播) + [row_swap_bicolor](每步传播时双色交换) + [偏心编码方向](种子在单元格中的偏心位置隐式编码传播对角方向)

**来源原语**：separator_line, cell_array, seed_motif, open_cell, same_parity_receive_copy (92e50de0); diagonal_propagate, top_row_band, shrinking_wedge, row_swap_bicolor (b5bb5719); mirror (cfb2ce5a)

**依赖链**：脚手架分隔线定义单元格阵列 → 种子在其单元格内的偏心位置编码传播方向（隐式规则，需对比多个示例归纳） → 沿对角方向逐格传播种子副本 → 每步交替两色，交替规则与传播步数绑定。传播方向不是显式给出的，而是从种子的空间偏心中推断。

脚手架网格中的种子图案沿单元格阵列的对角线逐格传播，每步双色交换，传播方向由种子在其单元格内的偏心位置隐式编码。

**输入结构**：
- 网格约 20x20，由橙(7)全行/全列分隔线构成脚手架，将内部划分为等大方形单元格阵列（如 4x4 的单元格组成 3x3 排列，共 9 个单元格，或 5x5 单元格组成 4x4 排列）。
- 恰好一个单元格包含双色种子图案：使用蓝(1)和红(2)两色，图案为 3-6 像素的非对称 4-连通形状。种子图案在其单元格内不居中，明显偏向某个角落。
- 其余单元格为空（全黑(0)背景）。
- 生成约束：种子不在阵列的角落单元格中（确保至少有两个对角方向可传播）；种子图案的重心偏向的角落方向上至少有 2 个空单元格可接收副本。

**规则**：
1. 识别橙(7)脚手架分隔线，将网格划分为单元格阵列。单元格行索引 i、列索引 j 从 0 开始。
2. 找到包含种子图案的单元格 (i_0, j_0)。记录种子图案中每个像素相对于单元格左上角的偏移。
3. 计算种子图案的像素重心在单元格内的相对位置，确定偏向的角落：
   - 重心在单元格中心偏左上 → 传播方向为右下 (delta_i = +1, delta_j = +1)
   - 重心在单元格中心偏右上 → 传播方向为左下 (delta_i = +1, delta_j = -1)
   - 重心在单元格中心偏左下 → 传播方向为右上 (delta_i = -1, delta_j = +1)
   - 重心在单元格中心偏右下 → 传播方向为左上 (delta_i = -1, delta_j = -1)
4. 从种子位置出发，沿确定的对角方向逐格传播：在单元格 (i_0 + k * delta_i, j_0 + k * delta_j) 处放置种子副本（k = 1, 2, 3, ...），直到超出阵列范围。
5. 第 k 步的副本进行色交换：k 为奇数时蓝(1)和红(2)互换，k 为偶数时保持原色。
6. 原始种子 (k = 0) 保持不变。橙(7)分隔线保持不变。空单元格保持黑(0)。

**关键洞察**：传播方向不是显式标注的，而是由种子图案在单元格内的偏心位置隐式编码——种子偏向哪个角，就向对角方向（远离该角的方向）传播。求解者必须对比多个示例才能发现"偏心方向"和"传播方向"之间的映射关系。
