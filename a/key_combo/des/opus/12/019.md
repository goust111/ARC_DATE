## 新题 1：标记投票决定同心层序

**组合逻辑**：[计数/投票](创新：投票结果不输出单色，而驱动空间排序) + [排序](创新：排序键由投票计数产生，非原始长度) + [同心层填充](已有原语) + [标记归属区域](已有原语)

**来源原语**：计数/投票(de1cd16c)、标记像素/色块区域/标记归属区域/最多标记区胜出(de1cd16c)、排序/按长度降序(3ee1011a)、同心层填充/同心方形层/由外到内嵌套(3ee1011a)

**依赖链**：标记像素的区域归属决定每个区域的票数 -> 票数大小决定排序顺序 -> 排序顺序决定同心层的由外到内赋色。删去投票环节则无法确定层序；删去同心填充则投票结果无处输出；删去归属判断则无法分配票数。

将分布在多个色块区域中的标记像素按归属计数，按得票数从多到少依次填入同心方环的从外到内各层，输出一个紧凑的同心方阵。

**输入结构**：约 15x15 的网格，黑(0)背景。网格中有 3~5 个大的单色矩形区域（每个区域使用不同颜色，如蓝(1)、绿(3)、黄(4)、品红(6)），各区域互不重叠且互不相邻（最小间距 1 像素）。一种稀有颜色——红(2)——仅以单像素形式散布在这些矩形区域内部，总数 5~12 个。每个红(2)标记像素严格位于某个矩形区域的内部（4-邻域全部为该区域颜色）。不同区域中的红(2)标记数量互不相同。生成约束：区域数量 N 满足 3 <= N <= 5；每个区域至少包含 1 个标记像素；各区域的标记数互不相等。

**规则**：
1. 找到全局最稀有的非背景颜色（出现次数最少），这些像素即为标记像素。
2. 对每个标记像素，检查其 4-邻域确定所属区域颜色。统计每种区域颜色包含的标记数。
3. 按标记数从大到小对区域颜色排序。
4. 令 N = 区域颜色种数，创建 (2N-1) x (2N-1) 的输出网格。
5. 最外层方环（第 0 层）填入标记数最多的区域颜色，第 1 层填入第二多的，依此类推，最内层（中心 1x1 像素）填入标记数最少的区域颜色。
6. 处理顺序冲突规则：标记数相等时不会出现（生成约束已保证互不相等）。

**关键洞察**：标记像素本身不出现在输出中——它们通过"投票"间接决定了颜色在几何结构中的空间排列，同一组区域颜色换不同的标记分布会产生完全不同的同心层序。

## 新题 2：形状等价类决定射线朝向

**组合逻辑**：[形状匹配/旋转翻转等价](已有原语) + [射线延伸](已有原语) + [朝向与背离](创新：不再由颜色决定方向，而由同形组内相对距离决定) + [分隔线](已有原语)

**来源原语**：形状匹配/归一化掩码/旋转翻转等价/等价涂指定色(6165ea8f)、射线延伸/分隔线/朝向与背离/颜色决定射线方向(8d510a79)、忽略干扰项(6165ea8f)

**依赖链**：旋转翻转等价检测将精灵体分组 -> 组内距离比较确定哪个精灵体朝向分隔线、哪些背离 -> 射线方向由此确定。删去等价检测则无法分组，无法确定谁朝谁背；删去分隔线则无"朝向/背离"的参照；删去射线延伸则分组结果无输出形式。

在分隔线两侧识别出形状等价的精灵体对，每组中离分隔线最近的精灵体向分隔线发射射线，其余向画布边缘发射射线；无等价伙伴的精灵体不发射。

**输入结构**：约 18x20 的网格，黑(0)背景。一条完整的灰(5)水平直线将网格分为上下两半（灰线占据某一行的全部列）。上下两半各散布 3~5 个小型单色精灵体（4-连通，3~6 像素，各自颜色不同，使用蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中的若干种）。部分精灵体在旋转或翻转（8 种二面体变换）下形状相同，形成 2~3 个等价组，每组恰好 2 个成员。其余精灵体无等价伙伴。精灵体之间互不接触，且不与灰线相邻。生成约束：每个等价组的两个成员分别位于灰线的上下两侧；同一侧不会有两个互相等价的精灵体。

**规则**：
1. 检测灰(5)水平分隔线。
2. 提取每个非背景、非灰色的 4-连通分量作为精灵体。将每个精灵体裁剪到其紧凑边界框，得到归一化掩码。
3. 对所有精灵体两两比较归一化掩码（考虑 8 种二面体变换：4 个旋转 x 2 个翻转），形状相同的归为一组。
4. 对于每个等价组（恰好 2 个成员）：计算每个成员到灰线的最小曼哈顿距离（精灵体任意像素到灰线所在行的最小行距）。距离较小的成员为"近端"，距离较大的为"远端"。
5. 近端精灵体：从其离灰线最近的像素出发，沿垂直方向（朝灰线方向）画一条射线，射线在灰线前一行停止（不覆盖灰线），颜色为该精灵体自身颜色。
6. 远端精灵体：从其离灰线最远的像素出发，沿垂直方向（远离灰线方向）画一条射线，射线延伸到画布边缘，颜色为该精灵体自身颜色。
7. 无等价伙伴的精灵体保持原样，不发射任何射线。
8. 若两条射线经过同一像素，后处理的覆盖先处理的。处理顺序：按精灵体边界框左上角的行优先、列次优先排序。

**关键洞察**：颜色不再直接编码射线方向——求解者必须先通过形状匹配发现哪些精灵体是"同类"，然后在同类内部通过与分隔线的距离比较推断朝向/背离关系，这两个判断层层嵌套，缺一不可。

## 新题 3：指示像素引导周期条纹投射与计数冲突裁决

**组合逻辑**：[射线延伸](已有原语) + [周期掩码](已有原语) + [方向指示](创新：指示像素不再在矩形边框上，而在独立条纹源中，同时携带方向和优先级信息) + [计数](创新：条纹源内部像素数量作为冲突优先级)

**来源原语**：射线延伸/矩形边框/周期条纹/标记条/周期掩码/条纹延伸全行列(6a980be1)、方向指示/指示像素/指示侧扩展至边界(b527c5c6)、计数(de1cd16c)

**依赖链**：指示像素确定每个条纹源的投射方向 -> 周期掩码确定投射的行/列选择 -> 计数解决交叉覆盖冲突。删去指示像素则方向不确定；删去周期提取则不知道投射哪些行列；删去计数则交叉区域无法裁决。

从多个带指示像素的条纹源中提取周期模式，沿指示方向向画布边缘投射，交叉区域由条纹源内前景像素数量多者覆盖。

**输入结构**：约 20x20 的网格，黑(0)背景。网格中有 2~3 个互不重叠的小矩形区域（每个约 4x6 到 6x8 像素），每个矩形区域由一种边框颜色（如蓝(1)、绿(3)、品红(6)）绘制一像素宽的边框。每个矩形内部在水平方向或垂直方向上有周期性条纹：某些行或列填充了另一种颜色（橙(7)），其余内部行/列为黑(0)。条纹周期为 2 或 3（即每隔 1 或 2 行/列出现一行/列橙色）。每个矩形的边框上恰好有一个红(2)指示像素，替换了该位置的边框颜色。指示像素所在的边（上/下/左/右）决定投射方向。生成约束：不同矩形的投射方向允许相同或不同；每个矩形内部的橙(7)条纹像素总数互不相同。

**规则**：
1. 对每个矩形区域，定位其红(2)指示像素。指示像素所在边决定投射方向：上边 -> 向上投射；下边 -> 向下投射；左边 -> 向左投射；右边 -> 向右投射。
2. 提取该矩形内部的周期条纹模式：记录哪些行（若条纹为水平方向）或哪些列（若条纹为垂直方向）包含橙(7)像素，得到一组相对偏移值。
3. 将条纹模式沿投射方向延伸到画布边缘：对于水平条纹向上/下投射的情况，将条纹行模式沿列方向扩展至画布全宽，从矩形边界开始、向投射方向复制周期模式直到画布边缘，使用该矩形的边框颜色绘制；对于垂直条纹向左/右投射的情况，类似地将列模式沿行方向扩展至画布全高。
4. 指示像素自身沿投射方向画一条红(2)直线至画布边缘。
5. 冲突解决：当两个矩形的投射区域重叠时，内部橙(7)条纹像素总数较多的矩形优先（其颜色覆盖对方）。红(2)指示线始终覆盖一切。
6. 原始矩形区域保留不变（边框和内部条纹均保留）。

**关键洞察**：矩形内部的条纹既编码了"投射什么模式"，其像素总数又隐式编码了冲突时的优先级——同一组条纹像素同时承担了内容和权重两个角色，求解者必须同时识别两种功能。

## 新题 4：对称修复驱动自相似块扩展

**组合逻辑**：[补全/对称恢复](已有原语) + [平铺/像素到块映射](创新：种子不是直接给定的，而是修复后的结果) + [前景位放自身副本](已有原语)

**来源原语**：补全/遮挡矩形/平移对称图案/对称轨道/对称恢复遮挡(f9012d9b)、平铺/种子精灵/像素到块映射/前景位放自身副本(5b6cbef5)

**依赖链**：遮挡像素必须通过对称修复才能确定真实颜色 -> 修复后的前景/背景分布决定自相似扩展的布局 -> 布局决定最终输出图案。若跳过修复直接扩展，被遮挡的位置可能是前景也可能是背景，扩展结果完全不同；若只修复不扩展，输出尺寸和结构都不对。

先用平移对称性修复小网格中被遮挡的像素，再将修复后的完整网格作为种子进行自相似块扩展。

**输入结构**：一个 4x4 的网格。使用两种前景颜色（如蓝(1)和绿(3)）以及黑(0)背景，构成一个具有 2x2 平移对称性的图案（即左上 2x2 子块在右上、左下、右下三个位置重复出现，可能有颜色置换但位置结构相同）。其中恰好 2~3 个像素被灰(5)替换，表示遮挡。被遮挡的像素分布在不同的 2x2 子块中，使得每个被遮挡像素至少有一个同轨道的非遮挡像素可供参考。生成约束：修复后的 4x4 网格中至少有 4 个非背景像素；被遮挡像素中至少有 1 个修复后为前景色、至少有 1 个修复后为背景色（确保修复结果实质性影响扩展布局）。

**规则**：
1. 将灰(5)像素视为遮挡标记。
2. 识别 4x4 网格的 2x2 平移对称性：将网格划分为 4 个 2x2 子块，每个子块中相同相对位置的像素属于同一对称轨道。
3. 对每个灰(5)像素，在其对称轨道中找到非灰像素，将灰像素替换为该颜色。若轨道中有多个非灰像素且颜色一致，取该颜色；若不一致（不会出现，生成约束保证）。
4. 修复完成后，得到一个完整的 4x4 种子网格。
5. 创建 16x16 的输出网格，全部初始化为黑(0)。
6. 对种子网格中每个非背景像素（行 r, 列 c），将整个 4x4 种子网格复制到输出网格的对应 4x4 块中（块左上角位于 (4r, 4c)）。种子网格中的背景像素对应的块保持全黑。

**关键洞察**：遮挡像素的真实身份（前景还是背景）直接决定自相似扩展中哪些块被填充、哪些留空——一个灰像素若修复为前景则对应块获得完整种子副本，若修复为背景则留空，导致最终 16x16 图案出现结构性差异。

## 新题 5：横带归属投票选出框架绘制目标

**组合逻辑**：[边框绘制](创新：不再对所有标记都画框，而是由投票筛选) + [计数/投票](创新：投票结果不输出颜色而决定几何处理方式) + [中点划分归属](已有原语) + [按行排序](已有原语)

**来源原语**：扩展/边框绘制/单像素标记/横带/按行排序/中点划分归属(0f63c0b9)、计数/投票/标记像素/标记归属区域/最多标记区胜出(de1cd16c)

**依赖链**：按行排序 + 中点划分将网格分为横带 -> 每条横带内的投票像素计数决定该带的处理方式 -> 得票最多的横带获得全宽边框，其余只获得单行横线。删去分带则无法归属投票；删去投票则所有带获得相同处理（退化为原参考题）；删去绘制则投票无输出。

按标记像素行位置将网格分为横带，统计每条带内的投票像素数量，得票最多的横带获得完整边框，其余仅画标记行横线。

**输入结构**：约 20x14 的网格，黑(0)背景。有 3~5 个孤立的单像素标记，每个标记颜色不同（使用蓝(1)、绿(3)、黄(4)、品红(6)等），分布在不同行（行号互不相同），列位置任意。另外，橙(7)的投票像素以单像素形式散布在网格各处（总数 8~15 个），不与任何标记像素相邻。生成约束：各横带内的橙(7)投票像素数量互不相等（保证唯一胜出）。

**规则**：
1. 找到所有非背景、非橙(7)的单像素（即标记像素），按行号从小到大排序。
2. 在相邻标记行的中点处划分横带边界：第一条带从第 0 行到第一个中点行（含），第二条带从第一个中点行的下一行到第二个中点行（含），依此类推，最后一条带延伸到网格底部。中点行 = floor((r_i + r_{i+1}) / 2)。
3. 统计每条横带内包含的橙(7)投票像素数量。
4. 得票最多的横带为"胜出带"：用该带的标记颜色绘制完整边框——标记所在行全宽填色、横带顶部行全宽填色、横带底部行全宽填色、左边界列（第 0 列）在横带范围内填色、右边界列（最后一列）在横带范围内填色。
5. 其余横带（非胜出）：仅用各自标记颜色将标记所在行全宽填色（一条水平线）。
6. 橙(7)投票像素在输出中全部擦除（还原为黑(0)背景）。
7. 所有绘制操作覆盖背景；若胜出带的边框线与非胜出带的横线重叠（在边界行），胜出带的颜色优先。

**关键洞察**：橙色投票像素在输出中完全消失，但它们的空间分布决定了哪个标记获得"升级"为完整边框的资格——投票是隐式的，求解者需要对比不同示例中投票像素分布的变化来发现这一机制。

## 新题 6：重力落轨后沿周期轨道碰撞滑行

**组合逻辑**：[重力下落](已有原语) + [滑动](创新：滑动不在自由空间而是沿离散轨道) + [周期条纹作为轨道](创新：周期条纹不再是投射模式而是物理运动轨道) + [碰撞阻挡/远近序处理](已有原语)

**来源原语**：重力下落/碰撞停止(28a6681f)、滑动/连通分量/碰撞阻挡/重力远近序处理(5ffb2104)、周期条纹(6a980be1)

**依赖链**：周期条纹定义哪些行是合法轨道 -> 重力下落将对象安置到最近的下方轨道 -> 碰撞滑行按远近序在轨道上排列最终位置。删去轨道则对象落到底部而非离散位置；删去重力则对象不会到达轨道；删去碰撞序则同轨道对象可能重叠。

彩色对象在重力下落时只能停在周期分布的灰色轨道行上，落定后在同一轨道上向右滑行直至碰撞停止，最右侧对象先定位。

**输入结构**：约 18x16 的网格，黑(0)背景。灰(5)水平轨道行以固定周期出现（每隔 3 或 4 行一条，全宽灰线）。在轨道行上方的空间中散布 4~7 个小型彩色对象（每个为单色 4-连通分量，2~4 像素，颜色各异，使用蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)）。这些对象悬浮在轨道之间的黑色区域中。生成约束：每个对象的宽度不超过 2 像素；同一轨道上方区域最多出现 3 个对象（防止过度拥挤）；没有对象直接处于另一个对象正下方（无垂直遮挡）。

**规则**：
1. 识别所有灰(5)水平全宽行作为轨道。
2. 每个彩色对象向下移动，直到其最底部像素的下一行是灰(5)轨道行。对象停在该轨道行的正上方（对象底部像素行 = 轨道行 - 1）。若对象下方没有轨道行（已在最低轨道下方），对象落到网格底部边缘。
3. 落定后，统计每条轨道上（即紧贴其上方的）有哪些对象。对每条轨道，按对象边界框最右列从大到小排序（即最右侧的对象先处理）。
4. 最右侧对象不移动（已就位）。第二右的对象向右平移，直到其右边缘紧贴已就位对象的左边缘（间距 0，相邻）或到达网格右边缘。依次处理更左的对象，每个向右滑行直至碰到已定位对象或右边缘。
5. 对象保持原始形状和颜色，灰(5)轨道行保持不变。对象像素覆盖在背景之上（不覆盖灰线）。

**关键洞察**：周期轨道间距决定了哪些对象会"合流"到同一轨道上（间距不同，分组不同），而同轨道上的碰撞滑行又受分组结果制约——轨道周期是控制最终布局的隐藏参数。

## 新题 7：隐含十字计数压缩为颜色编码网格

**组合逻辑**：[压缩/分区采样](创新：采样内容不是单个前景像素而是模式计数结果) + [重涂色](创新：颜色不表示原有属性而编码计数值) + [四向对齐/缺失中心检测](已有原语)

**来源原语**：压缩/分区网格/分区采样(5783df64)、重涂色/微型条/隐含十字/四向对齐/缺失中心(9f5f939b)、计数(de1cd16c)

**依赖链**：分区将网格切为块 -> 每块内检测隐含十字模式需要四向对齐判断 -> 十字计数编码为输出颜色。删去分区则无法界定检测范围（块边界限制了跨块十字的形成）；删去十字检测则无计数来源；删去颜色编码则计数结果无表达方式。

在分区网格的每个块内检测由微型条构成的隐含十字图案的数量，将计数编码为对应颜色输出到压缩网格中。

**输入结构**：一个 18x18 或 21x21 的网格（边长为 6 或 7 的 3 倍），黑(0)背景。网格在概念上被均分为 3x3 共 9 个正方形块（每块 6x6 或 7x7）。每个块内散布若干蓝(1)微型条（每个微型条为水平或垂直方向的 2 像素连续段）。部分微型条的排列会形成隐含十字：某个黑(0)背景像素的上方距离 2~3 格处有一个垂直微型条、下方距离 2~3 格处有一个垂直微型条、左方距离 2~3 格处有一个水平微型条、右方距离 2~3 格处有一个水平微型条（四向齐备）。一个块内可能有 0、1、2 或 3 个这样的隐含十字中心。生成约束：隐含十字中心之间的四向微型条不共享（每个微型条最多属于一个十字）；微型条不跨越块边界；各块的十字中心数量至少出现两种不同值。

**规则**：
1. 将输入网格均分为 3x3 的块阵列，每块尺寸 = 网格边长 / 3。
2. 对每个块，在块内部检测隐含十字：遍历块内每个黑(0)背景像素 (r, c)，检查其四个方向是否都有匹配的微型条——上方：(r-2, c) 和 (r-3, c) 都是蓝(1)；下方：(r+2, c) 和 (r+3, c) 都是蓝(1)；左方：(r, c-2) 和 (r, c-3) 都是蓝(1)；右方：(r, c+2) 和 (r, c+3) 都是蓝(1)。所有 8 个位置都在块内部且满足条件时，(r, c) 是一个隐含十字中心。
3. 统计每个块中的隐含十字中心数量 k。
4. 输出一个 3x3 的网格，每个单元格的颜色编码为：k=0 -> 黑(0)，k=1 -> 蓝(1)，k=2 -> 红(2)，k=3 -> 绿(3)。

**关键洞察**：块边界是隐含的（输入中没有可见的分割线），但它严格限制了哪些微型条可以组合成十字——同样的微型条布局在不同的分区方案下会产生不同的十字计数，求解者必须先推断出正确的分区尺寸。

## 新题 8：重力定位端点后双角色连线

**组合逻辑**：[重力下落](已有原语) + [连线/两点直线路径](已有原语) + [碰撞停止](已有原语) + [按原色区分涂色](创新：不再只区分蓝/非蓝，而是区分障碍/非障碍)

**来源原语**：重力下落/障碍物/碰撞停止(28a6681f)、连线/标记像素/两点直线路径/按原色区分涂色(bcb3040b)、滑动/碰撞阻挡(5ffb2104)

**依赖链**：重力下落确定同色像素对的最终位置（端点） -> 端点位置决定连线路径 -> 路径上像素的原始颜色（障碍还是背景）决定输出着色。删去重力则端点位置不确定；删去连线则重力后的状态不完整；删去原色区分则线条单调无法表达障碍信息。

同色像素对先在重力下自由下落直到碰撞停止，落定后各对之间画直线，线上穿过灰色障碍的像素变为黄色，穿过黑色背景的像素保持该对颜色。

**输入结构**：约 15x15 的网格，黑(0)背景。网格中有若干灰(5)水平平台（每个平台为一段水平灰线，宽 3~6 像素，分布在不同行，不贴着网格底部）。在网格上半部散布 2~3 对同色标记像素，每对使用不同颜色（如一对红(2)、一对蓝(1)、一对绿(3)），每个标记为单个像素。同一对的两个标记位于不同列。生成约束：每对标记下落后（垂直下落直到碰到灰色平台顶面或网格底部）位于同一行、或同一列、或 45 度对角线上（保证可以画皇后移动直线）；落定后不同对的标记不占据同一像素。

**规则**：
1. 所有标记像素同时向下移动（重力）：每个标记逐行下移，直到其下一行是灰(5)平台或网格底部行的下一行（即停在平台上表面或网格最底行）。标记之间不会互相阻挡（生成约束保证不同标记不会落到同一位置）。
2. 灰(5)平台和原始标记位置的像素清除（标记已移动到新位置）。落定后的标记像素绘制在新位置。
3. 对每一对同色标记，沿它们之间的直线路径（水平、垂直或 45 度对角线）逐步行走，包含两个端点。
4. 路径上的每个像素着色规则：
   - 若该像素在原始输入中是灰(5)（属于障碍平台），则着黄(4)。
   - 若该像素在原始输入中是黑(0)背景或其他颜色，则着该对标记的自身颜色。
5. 若两条不同对的连线经过同一像素，在输入中列号较小的那一对的标记颜色优先。
6. 灰(5)平台中未被任何连线穿过的像素保持灰(5)不变。

**关键洞察**：灰色平台承担双重角色——它们既是阻止标记下落的物理障碍（决定端点位置），又是连线路径上的"染色触发器"（穿过障碍的线段变黄）。同一组平台同时塑造了线的端点和线的颜色模式。

## 新题 9：印章填槽后支撑签名连线

**组合逻辑**：[印章覆盖](已有原语) + [连线](创新：不再连接两个预设标记，而是连接新产生的印章副本) + [支撑签名匹配](已有原语) + [按原色区分涂色](已有原语)

**来源原语**：印章覆盖/精灵体/空槽位/支撑签名匹配/空位接受印章(e5062a87)、连线/标记像素/两点直线路径/按原色区分涂色(bcb3040b)

**依赖链**：支撑签名匹配确定哪些空槽位接受印章 -> 印章覆盖产生新的红色图案 -> 新印章的中心与原始印章中心之间的连线才能绘制。删去匹配则不知道哪些槽位有效；删去连线则只是重复参考题的印章逻辑；删去印章则连线端点不存在。

先将红色精灵体印入所有匹配的灰色支撑空槽中，然后从原始精灵体中心向每个新印章中心画直线，线上经过灰色支撑像素的部分变为绿色、经过黑色背景的部分为红色。

**输入结构**：约 18x18 的网格，黑(0)背景。网格中有一个由红(2)像素和灰(5)支撑像素组成的精灵体（原始精灵体，红色部分为 3~5 像素的 4-连通不规则形状，灰色部分是边界框内的支撑像素）。网格中还有 2~4 个与原始精灵体支撑签名完全匹配的空槽位：这些位置的灰(5)像素排列与原始精灵体边界框内的灰(5)像素一致，但红色位置为黑(0)空白。空槽位之间互不重叠，且不与原始精灵体重叠。此外可能有 0~2 个干扰性的灰(5)像素团（支撑签名不匹配的），不应被填充。生成约束：原始精灵体和每个有效空槽位的边界框中心连线为水平、垂直或 45 度对角线方向之一；各连线路径互不交叉。

**规则**：
1. 提取原始精灵体的边界框，记录红(2)像素的相对位置作为印章掩码，记录灰(5)像素的相对位置作为支撑签名。
2. 从左上到右下逐像素扫描候选位置，在每个位置放置边界框大小的窗口：若窗口内所有印章掩码位置为黑(0)且所有支撑签名位置为灰(5)，则该位置匹配。
3. 对每个匹配位置，将印章掩码对应的黑(0)像素涂为红(2)。
4. 计算原始精灵体的边界框中心 (r0, c0)（行中心取 floor((top+bottom)/2)，列中心取 floor((left+right)/2)）。对每个新印章，计算其边界框中心 (ri, ci)。
5. 从 (r0, c0) 到每个 (ri, ci) 画直线（水平、垂直或 45 度对角线，由两点相对位置决定），包含两个端点。
6. 直线上每个像素的着色：若该像素在步骤 3 完成后为灰(5)（原始支撑像素或槽位支撑像素），则着绿(3)；否则着红(2)。
7. 连线的处理顺序：按新印章中心到原始中心的曼哈顿距离从小到大逐条画线，后画的线覆盖先画的。

**关键洞察**：印章覆盖创造了连线的端点（新印章不存在于输入中），而连线路径上的灰色支撑像素——本来是印章匹配的条件——又成为了连线变色的触发器，同一组灰色像素在"匹配判断"和"路径着色"中扮演了完全不同的角色。
