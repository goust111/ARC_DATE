## 新题 1：重力沉降与形状嵌入

**组合逻辑**：[重力下落](原有) + [形状匹配](原有，创新：匹配结果决定物理状态——嵌入或搁浅) + [嵌入](原有，创新：嵌入后改变碰撞地形，反馈影响后续下落) + [碰撞停止](原有)

**来源原语**：重力下落/gravity_drop、碰撞停止/collision_stop、近墙优先结算/nearest_first_settling（参考题17 6ad5bdfd）；形状匹配/shape_matching、嵌入/embed、孔洞/hole（参考题9 228f6490）

**依赖链**：沉降顺序（最接近平台者先结算）→ 精灵体刚性下落 → 到达平台时进行形状匹配测试 → 匹配成功则嵌入孔洞（孔洞变为实心，改变碰撞地形）→ 匹配失败则搁浅在平台表面 → 地形更新后下一个精灵体开始结算

将形状匹配与重力嵌入为一个带反馈的物理过程：每次嵌入都改变后续精灵体的碰撞环境，使得处理顺序直接影响最终结果。

**输入结构**：约 15x15 网格，黑(0)背景。网格中有 3-4 条灰(5)水平平台，每条平台为 1 像素高、5-8 像素宽的水平连续灰色像素带，分布在不同高度（彼此不在同一行，纵向间距至少 3 行）。每条平台内部有 1-2 个孔洞——即平台像素带中缺失的黑(0)间隙，每个孔洞为 1-3 个连续缺失像素。平台上方的黑色区域中散布 4-6 个单色 4-连通精灵体（每个 2-4 像素），颜色各不相同，可选自红(2)、蓝(1)、绿(3)、黄(4)、橙(7)等。不同示例中精灵体的具体形状不同（不固定为某种命名形状），但每个精灵体的像素数和连通形态保证在所有孔洞中最多只有一个能与之完全匹配。生成约束：每个孔洞的形状在所有精灵体中最多有一个匹配；每个精灵体正下方的下落路径上至少有一条平台。

**规则**：
1. 按精灵体最底行像素到其正下方最近平台表面的距离从小到大排序，距离最小的精灵体先结算（距离相同时按精灵体最左列像素从左到右结算）。
2. 结算一个精灵体时，将其整体刚性地逐行向下平移，直到发生以下情况之一而停止：
   - (a) 精灵体的最底行像素的下一行是灰(5)平台表面或已结算的其他精灵体的顶部 → 进入步骤 3。
   - (b) 精灵体的最底行像素的下一行是网格底边 → 精灵体停在网格底部（不嵌入），保持原色。
3. 当精灵体因条件 (a) 停在某平台上方时，检查该平台是否有孔洞，且精灵体的二值掩膜（忽略颜色）与该孔洞的形状完全一致（像素数相同、连通形态相同、水平对齐时恰好能填满孔洞）。
   - 匹配成功：精灵体嵌入孔洞——精灵体的像素填充到孔洞对应位置，保持精灵体的颜色。该孔洞变为实心（后续精灵体视其为灰(5)平台表面的一部分）。
   - 匹配失败：精灵体搁浅在平台顶部表面，其最底行像素紧贴平台上方一行，保持原色。搁浅的精灵体成为新的碰撞障碍物。
4. 一个精灵体结算完毕后，下一个精灵体基于更新后的碰撞地形重新计算下落。
5. 灰(5)平台本身位置和颜色不变。所有精灵体的原始位置被清除（变为黑(0)）。

**关键洞察**：嵌入操作会修改碰撞地形——一个早期精灵体填满孔洞后，后续精灵体原本可以穿过该孔洞继续下落，现在却被堵住而搁浅在上方。因此，仅凭单个示例中某些精灵体是嵌入还是搁浅的最终状态，无法区分"匹配失败因此搁浅"与"孔洞已被先到者填满因此搁浅"，必须对比多个示例的结算顺序与最终结果才能归纳完整规则。

## 新题 2：面积决定射线长度与交叉着色

**组合逻辑**：[计数](原有，创新：面积不再决定位移距离，而是决定射线长度) + [射线延伸](原有，创新：射线长度由动态属性而非固定值决定) + [重涂色](原有，创新：交叉着色规则区分单源与多源)

**来源原语**：计数/counting、位移等于面积/shift_equals_area（参考题14 b2bc3ffd）；射线延伸/ray_extend、行列交叉/row_column_crossing、异源交叉特殊着色/cross_source_special_color（参考题18 45bbe264）；重涂色/recolor（参考题10 4f537728）

**依赖链**：逐对象像素计数 → 面积值成为该对象的射线长度参数 → 从锚点向四方发射固定长度射线 → 射线交叉检测 → 交叉类型决定着色（单源射线 vs. 多源交叉 vs. 射线覆盖他体）

将面积这一固有属性转化为空间影响力的度量——像素越多的对象"辐射"范围越广——再通过射线的空间交叉产生涌现的着色结果。

**输入结构**：约 15x15 网格，黑(0)背景。网格中有 3-5 个单色 4-连通小对象，每个对象 2-5 像素，颜色互不相同，可选自红(2)、蓝(1)、绿(3)、黄(4)。各对象之间水平和垂直方向至少间隔 2 个空像素。不同示例中对象的具体形状不同，但像素数范围一致。生成约束：任意两个对象的锚点像素（定义见规则）不在同一行或同一列；各对象的面积值保证至少存在一对射线交叉。

**规则**：
1. 对每个对象，计算其像素数（面积 A）。
2. 确定每个对象的锚点像素：对象中行号最小的像素；若有多个行号最小的像素，取其中列号最小者。
3. 从锚点像素出发，沿上、下、左、右四个方向各发射一条单像素宽射线，每条射线恰好 A 个像素长（不含锚点本身）。射线如果超出网格边界则截断（仅绘制在网格内的部分）。射线以对象的颜色绘制。
4. 按对象面积从小到大依次绘制射线。后绘制的射线像素覆盖先绘制的射线像素（后者颜色替换前者），但以下两种特殊情况例外：
   - (a) 若一个格子被来自两个不同对象的射线同时经过（即小面积对象先绘制了该格子，大面积对象又经过该格子），该格子最终着色为橙(7)，不论后续是否还有更多射线经过。
   - (b) 若一条射线经过另一个对象的身体像素（非射线像素），该身体像素改为青(8)。
5. 所有对象的原始身体像素保持原色不变（规则 4b 只改变被他体射线命中的像素；对象自身的射线不影响自身身体像素）。
6. 锚点像素保持对象原色。

**关键洞察**：对象面积同时决定了射线的"势力范围"，使得大面积对象能在更远处形成交叉——但由于射线绘制按面积升序，小面积对象的射线会被大面积对象覆盖，只有在真正的多源交叉点才会保留橙(7)标记。求解者必须先理解面积→长度映射，再推断绘制顺序和交叉着色规则，两者缺一不可。

## 新题 3：朝向过滤式推移与擦除

**组合逻辑**：[推移](原有) + [擦除](原有，创新：擦除条件由几何朝向与推移方向的匹配性决定) + [朝向编码方向](原有，创新：朝向不再决定射线方向，而是作为推移资格的过滤器) + [碰撞停止](原有，创新：被擦除的精灵体不参与碰撞，改变幸存者的推移路径)

**来源原语**：推移/push、擦除/erase、接触侧决定方向/contact_side_dir、推至边界停止/stop_at_boundary（参考题11 5623160b）；朝向编码方向/orientation_encodes_direction（参考题13 409aa875）；碰撞停止/collision_stop（参考题17 6ad5bdfd）

**依赖链**：几何朝向解码 → 与推移方向比较 → 分流（匹配者推移 / 不匹配者擦除）→ 擦除后更新碰撞环境 → 推移在更新后的环境中执行

朝向编码从射线发射的方向指示器变为一个布尔过滤器，决定精灵体的命运（推移或消亡），而消亡者的缺席又改变了幸存者的物理空间。

**输入结构**：约 12x15 网格，黑(0)背景。网格中散布若干栗(9)色标记像素（单像素，不构成连通体）。有 5-7 个单色 4-连通精灵体，每个精灵体恰好 4 像素，具有沿恰好一个轴的双边对称性（例如：3 像素排成一条直线 + 1 像素从直线中央向垂直方向延伸；不同示例中具体形态不同，但都满足"恰好一个对称轴"的结构约束）。每个精灵体的颜色互不相同，可选自红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、青(8)等。每个精灵体恰好有一个像素与一个栗(9)标记像素四邻接相邻，该相邻面确定接触侧。精灵体的"朝向"定义为：从 3 像素直线的中央像素指向第 4 个（延伸）像素的方向，即上、下、左或右。生成约束：每个栗(9)标记像素最多与一个精灵体相邻；精灵体互不四邻接。

**规则**：
1. 对每个精灵体，确定接触侧（精灵体与栗(9)标记相邻的那一面）和推移方向（远离接触侧的方向，即接触侧的反方向）。
2. 解码精灵体的几何朝向（从 3 像素直线中央指向延伸像素的方向）。
3. 比较推移方向与几何朝向：
   - 若两者相同：该精灵体被保留，等待推移。
   - 若两者不同：该精灵体被擦除——从网格中移除（位置变为黑(0)），但其关联的栗(9)标记像素保留。
4. 擦除所有不匹配精灵体后，对保留的精灵体执行推移：
   - 按精灵体到其推移方向上网格边界的距离从小到大排序（距离最近者先推移）；距离相同时按精灵体最左列像素从左到右排序。
   - 每个保留精灵体沿推移方向刚性平移，直到碰到网格边界、栗(9)标记像素或已结算的其他推移精灵体而停止。
   - 精灵体的原始位置清除为黑(0)。
5. 栗(9)标记像素始终保持不动。

**关键洞察**：精灵体的几何形状同时承载两个功能——它既是被操作的对象，又通过自身的朝向编码决定自己是否有资格被推移。被擦除的精灵体腾出了原本被占据的空间，使得幸存者的推移路径可能更长或到达不同的终点。求解者必须对比多个示例才能归纳出朝向与推移方向的匹配规则，因为单个示例中无法区分"被擦除是因为朝向不匹配"还是"被擦除是因为其他未知条件"。

## 新题 4：最短路径构建填充边界

**组合逻辑**：[寻路](原有) + [填充](原有，创新：填充区域的边界不是输入中预设的，而是由寻路结果动态构建的) + [重涂色](原有，创新：填充颜色由相邻路径的端点颜色决定)

**来源原语**：寻路/pathfinding、端点像素/endpoint_pixel、障碍像素/blocker_pixel、最短路径唯一/unique_shortest_path、四邻接连通/four_neighbor_connect（参考题19 b15fca0b）；填充/fill、间隙区域/gap_region、两体之间/between_two_objects、间隙区域涂色/gap_region_recolor（参考题4 d6ad076f）；重涂色/recolor（参考题6 b1948b0a）

**依赖链**：同色端点配对 → 各对端点独立寻路 → 路径像素成为新边界 → 新边界 + 原有墙壁 + 网格边缘围合封闭区域 → 区域着色取决于其边界上路径的端点颜色

路径从"连接手段"变为"拓扑构件"：寻路的输出不是最终答案，而是为填充操作创造出输入中不存在的封闭边界。

**输入结构**：约 15x15 网格，黑(0)背景。蓝(1)像素构成迷宫状的墙壁结构（蓝色像素群形成若干不规则的连续壁段，但不完全封闭任何区域——即黑色区域在仅有蓝色墙壁时全部四邻接连通）。网格中有 2-3 对同色端点像素，每对使用不同颜色（如一对红(2)、一对绿(3)、一对黄(4)）。每个端点为单独一个像素，放置在黑(0)背景上。同色端点之间存在唯一的最短四邻接路径（经过黑色像素，不穿越蓝色墙壁和其他端点）。生成约束：不同颜色对的最短路径互不交叉；所有路径绘制完成后，路径像素 + 蓝色墙壁 + 网格边缘恰好围合出若干封闭区域（即存在黑色连通分量被完全包围）；每个封闭区域的边界上恰好只有一条路径的像素（不会有两条不同颜色的路径同时出现在同一封闭区域的边界上）。

**规则**：
1. 对每对同色端点，找到它们之间经过黑(0)像素的唯一最短四邻接路径（蓝(1)像素和其他颜色的端点像素视为不可通行）。
2. 将每条路径的内部像素（不含端点本身）涂为灰(5)。端点保持原色。
3. 将灰(5)路径像素和蓝(1)墙壁像素共同视为不可通行的边界。
4. 找到所有被边界（灰(5) + 蓝(1)）和网格边缘完全包围的黑(0)四邻接连通分量（封闭区域）。
5. 对每个封闭区域：检查其边界上出现了哪条路径的灰(5)像素。将该区域的所有像素涂为对应路径的端点颜色（例如边界上是红色端点对的路径，则填红(2)）。
6. 未被完全包围的黑(0)区域（与网格边缘连通的区域）保持黑(0)不变。
7. 蓝(1)墙壁、灰(5)路径、端点像素均保持不变。

**关键洞察**：蓝色墙壁本身不围合任何封闭区域——是路径的加入才创造了封闭的拓扑边界。填充颜色不取决于区域自身的任何属性，而取决于哪条路径参与构成了它的边界。求解者必须先理解路径作为边界构件的角色，再理解颜色传递机制，单看最终的填充结果无法跳步反推。

## 新题 5：镜像约束的模板消歧

**组合逻辑**：[模板匹配](原有，创新：单侧匹配故意设计为多义的，必须借助跨面板镜像约束消歧) + [镜像](原有，创新：镜像不是变换操作，而是同时约束条件) + [印章覆盖](原有) + [逐格比较](原有，创新：不在两面板之间做直接逻辑运算，而是用比较来验证模板选择)

**来源原语**：模板匹配/template_matching、印章覆盖/stamp_overlay、部分匹配识别/partial_match_id（参考题3 3ed85e70）；镜像/mirror、拼接镜像副本/append_mirror_copy（参考题5 6d0aefbc）；逐格比较/cell_comparison（参考题15 f2829549）

**依赖链**：这不是线性链，而是同时约束满足——左面板局部匹配产生候选模板集合，右面板局部匹配产生另一个候选集合，镜像一致性条件取两者交集，唯一解确定模板选择

模板匹配与镜像从独立操作变为互锁约束：两个面板各自提供不充分信息，只有通过镜像关系联立才能消歧。

**输入结构**：约 12x25 网格。最上方 2 行为灰(5)背景的目录条，内含 4 个完整的小模板精灵体（每个约 3x3 到 4x4 像素，使用 2-3 种非灰非黑颜色，彼此形状不同）。目录条下方，一条青(8)分隔列将剩余区域纵向分为左面板和右面板（宽度相等）。左面板（黑(0)背景）中有 2 个局部精灵体，每个是某个目录模板的连续子集（保留 40%-60% 的像素，其余像素缺失为黑(0)）。右面板（黑(0)背景）中有 2 个局部精灵体，位于与左面板对应位置的镜像位置（以分隔列为镜像轴），每个是对应完整模板水平镜像后的连续子集（同样保留 40%-60%，但保留的像素区域与左面板的局部不同）。生成约束：每个左面板局部单独考虑时，至少匹配 2 个目录模板；每个右面板局部单独考虑时，也至少匹配 2 个模板；但对于每个位置对（左局部 + 右局部），恰好只有 1 个目录模板同时满足两侧的一致性。

**规则**：
1. 对每个左面板的局部精灵体 P_L：
   a. 遍历 4 个目录模板，尝试将模板对齐到 P_L 的位置，使得 P_L 的所有非黑像素都被模板覆盖且颜色一致（模板可以比 P_L 更大，P_L 是模板的子集）。记录所有匹配的候选模板。
   b. 对每个候选模板 T：将 T 水平镜像得到 T'，将 T' 放置在右面板的镜像对应位置。
   c. 检查右面板在该镜像位置的局部精灵体 P_R：P_R 的所有非黑像素是否都被 T' 覆盖且颜色一致。
   d. 恰好只有一个模板 T 同时通过步骤 a 和步骤 c 的测试。
2. 用确定的模板 T 印章覆盖左面板的 P_L 位置（补全缺失像素）。
3. 用 T 的水平镜像 T' 印章覆盖右面板的 P_R 位置（补全缺失像素）。
4. 从输出中移除目录条（最上方 2 行）和分隔列。
5. 输出为补全后的左面板和右面板并列（不含分隔列），总宽度 = 左面板宽度 + 右面板宽度。

**关键洞察**：这道题的核心推理不是模板匹配本身（那只是手段），而是发现两个面板之间存在镜像约束关系——它们不是独立的补全任务，而是一个联立方程的两个侧面。求解者必须意识到单侧匹配是故意多义的，只有引入跨面板的镜像一致性才能唯一确定答案。

## 新题 6：异或选择孔洞填充

**组合逻辑**：[异或](原有，创新：异或结果不是最终输出，而是中间选择信号) + [填充](原有，创新：填充的对象是另一层结构中的孔洞，而非异或结果本身) + [包含于](原有，创新：包含关系用于检测异或信号是否落入孔洞区域内)

**来源原语**：异或/xor、分隔行/separator_row、掩码/mask、逐像素异或输出/pixelwise_xor_output（参考题7 3428a4f5）；填充/fill（参考题4 d6ad076f）；孔洞/hole、包含于/contained_in（参考题9 228f6490）

**依赖链**：分离上下面板 → 逐像素异或得到差异图 → 差异图中的活跃像素与上面板孔洞做空间包含检测 → 有信号落入的孔洞被填充，无信号的孔洞保持空白

异或不再是变换的终点，而是一种空间选择机制——它产生的"差异信号"筛选出哪些封闭区域需要被激活。

**输入结构**：约 8x17 网格，黑(0)背景。中间一行为黄(4)分隔行，将网格分为高度相等的上下两个面板（每个面板约 8 列宽、8 行高；具体尺寸因示例而异但上下面板维度始终一致）。上面板：红(2)像素构成若干封闭矩形轮廓线（每个矩形 1 像素宽的边框），内部为黑(0)孔洞。矩形之间不重叠、不嵌套、互不相邻（边框间至少 1 像素间距）。上面板中存在 3-5 个这样的矩形框，孔洞大小各不相同。下面板：红(2)和黑(0)像素组成的任意图案（无特定结构约束），作为异或运算的第二掩码。生成约束：异或结果中的活跃像素至少有一个落在某孔洞内部，且至少有一个孔洞内没有任何活跃像素落入。

**规则**：
1. 移除黄(4)分隔行，将上下面板对齐（相同行列坐标对应）。
2. 逐像素异或上下面板：若该位置恰好只有一个面板为红(2)（另一个为黑(0)），则该位置在差异图中标记为"活跃"；若两个面板相同（都红或都黑），则标记为"非活跃"。
3. 在上面板中识别所有封闭矩形框的内部孔洞区域（被红色边框完全包围的黑色连通分量）。
4. 对每个孔洞区域，检查差异图中是否有至少一个"活跃"像素的坐标落在该孔洞区域内。
   - 若有：将该孔洞区域的所有像素填充为绿(3)。
   - 若无：该孔洞保持黑(0)。
5. 输出为修改后的上面板（红色边框不变，被选中的孔洞变为绿色，未选中的孔洞保持黑色）。下面板和分隔行不出现在输出中。
6. 活跃像素本身不直接出现在输出中——它们仅作为选择信号使用。

**关键洞察**：下面板看似是一个独立的图案，实际上它通过与上面板的异或运算产生空间选择信号。求解者需要认识到异或是一个中间计算步骤，其结果不直接显示在输出中，而是决定了上面板哪些孔洞被激活。从输出反推时，绿色填充的孔洞和未填充的孔洞之间的差异无法仅从上面板的几何结构中解释——必须引入下面板信息才能理解选择规则。

## 新题 7：轨迹引导滑动与同色桥接

**组合逻辑**：[沿路径移动](原有，创新：路径作为滑动的导轨而非独立行为) + [滑动](原有，创新：滑动方向由轨迹决定而非由边墙决定) + [填充](原有，创新：填充条件由滑动后的空间关系涌现决定) + [碰撞停止](原有)

**来源原语**：沿路径移动/path_move、轨迹路径/trace_path（参考题16 c9680e90）；滑动/slide、碰撞停止/collision_stop、多米诺骨牌/domino（参考题17 6ad5bdfd）；填充/fill、两体之间/between_two_objects、间隙区域涂色/gap_region_recolor（参考题4 d6ad076f）

**依赖链**：轨迹解析（方向与终点）→ 骨牌沿轨迹滑动 → 短轨迹先结算，碰撞决定最终位置 → 结算完毕后检测同色共线骨牌对 → 对之间的间隙填充

轨迹编码了个体运动指令，但桥接填充是运动完成后的涌现结果——两个骨牌在输入中可能相距甚远，滑动后恰好共线同色，才触发桥接。

**输入结构**：约 15x15 网格，黑(0)背景。网格中有 4-6 个单色 4-连通骨牌（每个恰好 2 像素，水平或垂直排列），颜色可能重复（例如两个红(2)骨牌、两个蓝(1)骨牌、一个绿(3)骨牌）。每个骨牌的一端连接一条同色单像素宽轨迹线，轨迹线为直线段或恰好一个直角转弯的折线（即轨迹只走水平/垂直方向，最多转一次弯）。轨迹线与骨牌同色，且轨迹的起点像素与骨牌的一个端点像素四邻接相邻。不同骨牌的轨迹互不交叉、互不接触。生成约束：所有骨牌沿轨迹滑动后，至少存在一对同色骨牌恰好处于同一行或同一列（共线），且至少存在一对同色骨牌不共线。

**规则**：
1. 对每个骨牌，识别其附着的轨迹线：从骨牌端点出发，沿同色像素逐步追踪（仅四邻接，不走回骨牌本体），直到轨迹末端（度为 1 的像素）。
2. 将骨牌沿轨迹方向平移到轨迹末端——具体地，骨牌的连接端像素移动到轨迹末端像素的位置，骨牌的另一端像素保持与连接端的相对位置不变。
3. 滑动按轨迹长度（轨迹像素数）从小到大排序结算；长度相同时按骨牌最上最左像素的行优先、列次优先排序。先结算的骨牌占据目标位置后成为障碍物。若后续骨牌的目标位置已被占据，该骨牌沿轨迹方向回退到不冲突的最近位置。
4. 滑动完成后，清除所有轨迹像素（变为黑(0)）。骨牌的原始位置也清除（变为黑(0)）。
5. 检查所有同色骨牌对：若两个同色骨牌的全部像素处于完全相同的行（水平共线）或完全相同的列（垂直共线），且它们之间的间隙全部为黑(0)（无其他障碍物），则将间隙像素填充为青(8)。
6. 不共线的同色骨牌对、不同色的骨牌对之间不做任何填充。

**关键洞察**：轨迹是骨牌的"个人剧本"，但桥接是"集体涌现"——输入中没有任何线索直接表明哪些骨牌会被桥接，只有在所有滑动执行完毕后，同色共线的条件才能被检测。求解者需要在理解轨迹驱动的运动机制之外，额外发现桥接规则，而桥接规则只有在对比含不同骨牌数量和颜色分布的多个示例后才能归纳得出。

## 新题 8：推移计数索引查色表

**组合逻辑**：[推移](原有) + [计数](原有，创新：计数对象不是像素面积，而是到达同一边界的精灵体数量) + [重涂色](原有，创新：重涂色的颜色不由精灵体自身属性决定，而由到达计数查表决定) + [稀疏单元色查找表](原有，创新：查找表的索引键从空间位置变为到达计数)

**来源原语**：推移/push、接触侧决定方向/contact_side_dir、推至边界停止/stop_at_boundary（参考题11 5623160b）；计数/counting、位移等于面积/shift_equals_area（参考题14 b2bc3ffd）；重涂色/recolor、稀疏单元色查找表/sparse_cell_color_lookup、位置索引/position_index（参考题2 09629e4f）

**依赖链**：各精灵体按接触侧被推向不同边界 → 统计每条边界的到达数量 → 到达数量作为索引查询查色表 → 用查得颜色重涂对应边界上的所有精灵体

推移的空间结果（各边界的聚集密度）被转化为一个离散索引，反向驱动颜色赋值——物理运动与数据检索通过计数环节链接。

**输入结构**：约 14x14 网格，黑(0)背景。网格一角（如左上角）有一个 4x1 的查色条：4 个水平排列的像素，从左到右分别表示"到达数 = 1 时的颜色""到达数 = 2 时的颜色""到达数 = 3 时的颜色""到达数 = 4 时的颜色"，每个像素颜色互不相同且不为黑(0)或栗(9)（例如依次为蓝(1)、绿(3)、黄(4)、橙(7)）。查色条使用灰(5)背景标识其边界（查色条像素上方或下方有一行灰(5)像素作为底座，以便与其他精灵体区分）。网格其余区域中，散布若干栗(9)标记像素和 6-8 个小型单色 4-连通精灵体（每个 2-3 像素，颜色各异但不含栗(9)和灰(5)）。每个精灵体恰好有一个像素与一个栗(9)标记像素四邻接相邻。生成约束：推移后四条网格边界（上、下、左、右）中至少两条边界有精灵体到达，且各边界到达数量不全相同；最大到达数不超过 4。

**规则**：
1. 对每个精灵体，确定接触侧（与栗(9)标记相邻的面），推移方向为接触侧的反方向。
2. 清除精灵体原始位置（变黑(0)），将精灵体沿推移方向刚性平移，直到碰到网格边界或已结算的其他精灵体而停止。按到边界距离从小到大排序结算（距离相同按行优先列次优先排序）。栗(9)标记像素保持不动，但不阻挡推移（精灵体可以经过标记像素所在位置）。
3. 所有精灵体结算后，统计每条网格边界（上边、下边、左边、右边）上最终停靠的精灵体数量。"停靠在某边界"定义为：精灵体的至少一个像素紧贴该边界边缘（行 0 = 上边，行 max = 下边，列 0 = 左边，列 max = 右边）。
4. 读取查色条：第 1 个像素颜色 = 到达数 1 对应的颜色，第 2 个 = 到达数 2，第 3 个 = 到达数 3，第 4 个 = 到达数 4。
5. 对每条边界：用该边界到达数量对应的查色条颜色，重涂该边界上所有精灵体的全部像素。若某边界到达数量为 0，则无操作。
6. 从输出中移除查色条及其灰(5)底座。栗(9)标记像素保留在原位。

**关键洞察**：精灵体在输入中的颜色与输出中的颜色完全无关——输出颜色完全由"同一边界上有多少精灵体"这一集体属性决定，再通过查色条映射得到。求解者必须先理解推移机制（决定精灵体去向），再理解计数→查表→重涂的三步链条，任何一步的缺失都会导致无法解题。单个示例可能碰巧让求解者误以为颜色由推移方向或原色决定，必须多个示例才能排除这些假设。
