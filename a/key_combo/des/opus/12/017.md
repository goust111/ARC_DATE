## 新题 1：多源射线竞争与轨迹长度优先级

**组合逻辑**：[射线延伸/ray_cast](从单目标擦除改为多源射线绘制) + [计数/counting](创新：计轨迹长度作为优先级度量) + [冲突优先级/conflict_priority](从行/对角优先改为轨迹长度定胜负) + [擦除/erase](已有)

**来源原语**：ray_cast, trail, marker_pixel, opposite_direction (9f8de559); counting (39a8645d); conflict_priority (c92b942c); erase (多源)

**依赖链**：轨迹方向决定射线朝向（反向投射）；轨迹长度决定射线间的优先级；两者共同决定射线绘制的最终结果。删除方向规则则射线无从发射，删除优先级规则则交叉处颜色无法确定。

多条彩色射线从各自标记像素出发向轨迹反方向延伸，在交叉处由轨迹长度裁决归属色，最后擦除所有标记与轨迹。

**输入结构**：
- 黑(0)背景，约 15x15 网格
- 3~4 个标记像素，每个颜色各不相同（使用蓝(1)、红(2)、绿(3)、黄(4)等非黑色）
- 每个标记像素沿某一基本方向（上/下/左/右）紧邻排列 1~4 个同色像素作为轨迹，轨迹呈直线段
- 不同标记的轨迹长度互不相同（保证优先级无并列）
- 各标记及其轨迹之间互不接触，且标记位于轨迹反方向上有足够的背景空间供射线延伸
- 至少两条射线的延伸路径在某些背景格子上交叉（即路径共享同一行或同一列的若干格子）

**规则**：
1. 对每个标记像素，确定其轨迹方向（轨迹像素相对于标记的基本方向），射线方向为轨迹方向的 180 度反向
2. 计算每个标记的轨迹长度 L（仅计轨迹像素数，不含标记本身）
3. 从每个标记像素出发，沿射线方向逐格延伸：遇到背景(0)格则标记为该射线颜色，遇到非背景像素或网格边界则停止（不覆盖非背景像素）
4. 当两条或多条射线标记同一个背景格时，轨迹长度 L 较大的射线获胜（该格着其颜色）
5. 所有射线绘制完毕后，将所有标记像素和轨迹像素擦除为背景(0)

**关键洞察**：轨迹不是装饰——它同时编码了射线方向和优先级权重，两个信息必须从示例中同时发现；仅看单个示例无法区分"某色总是赢"和"轨迹更长者赢"。

## 新题 2：分区内竖线排名压缩

**组合逻辑**：[压缩/compress](从直接读色改为读取排名结果) + [排序/sorting + 高度排名/height_ranking](从保留极值改为全排名) + [重涂色/recolor](排名映射颜色，创新) + [网格分区/grid_partition](双重角色：定义压缩布局 + 定义排名分组)

**来源原语**：compress, divider_line, grid_partition, region_to_pixel (780d0b14); sorting, vertical_bar, height_ranking (a61f2674); recolor (多源)

**依赖链**：分隔线同时定义两件事——压缩后的输出网格布局，以及哪些竖线在同一行内互相竞争排名。排名结果通过颜色映射写入压缩输出。删除分区规则则排名分组和输出布局同时丢失；删除排名规则则输出颜色无法确定。

以黑线分隔的区域内各有一根竖线，同一行区域内按竖线高度排名，排名映射为颜色后压缩为一个像素输出。

**输入结构**：
- 约 20x20 网格
- 贯穿全宽的水平黑(0)线和贯穿全高的垂直黑(0)线将网格分为规则的 M x N 矩形区域（如 3 行 x 4 列）
- 每个区域内背景为青(8)（非黑，与分隔线区分），且恰好包含一根灰(5)竖线（宽 1 格，高度各异）
- 同一行的 N 个区域内，N 根竖线的高度互不相同
- 不同行之间竖线高度可以重复

**规则**：
1. 识别所有水平和垂直黑(0)分隔线，确定 M x N 区域布局
2. 在每一行的 N 个区域中，将区域内竖线按高度从高到低排名：最高 = 排名 1，次高 = 排名 2，依此类推
3. 排名映射颜色：排名 1 -> 红(2)，排名 2 -> 绿(3)，排名 3 -> 黄(4)，排名 4 -> 橙(7)；若 N > 4 则继续：排名 5 -> 品红(6)，排名 6 -> 栗(9)
4. 输出 M x N 网格，每个格子的颜色由该区域竖线在本行中的排名决定

**关键洞察**：输出颜色反映的是行内相对排名而非全局排名——两根等高的竖线若处在不同行，因竞争对手不同，可能获得不同排名和不同颜色。必须对比多个示例才能排除"全局排名"和"按竖线原色输出"等替代假说。

## 新题 3：孔洞双重角色——计数定复制数，种子定内容

**组合逻辑**：[计数/counting](计封闭孔洞数 = 平铺次数) + [封闭孔洞/enclosed_hole](双重角色：被计数 + 容纳种子) + [种子像素/seed_pixel](创新：种子不从候选库选模板，而是自身即为模板) + [平铺/tile](按孔洞数水平重复) + [裁剪/crop](提取种子图案)

**来源原语**：counting, enclosed_hole, enclosed_region (0a2355a6); seed_pixel, seed_selects_template (8a6d367c); tile, pixel_count_sets_size_copies (91413438); crop (b94a9452)

**依赖链**：孔洞同时承担两个不可替代的角色：全部孔洞的数目决定输出的重复次数，唯一含种子的孔洞提供重复的内容。删除计数则不知复制几份，删除种子提取则不知复制什么。两者绑定在同一结构（孔洞）上，无法独立求解。

数封闭孔洞得重复次数，从唯一含种子的孔洞中提取图案，水平平铺该图案相应次数。

**输入结构**：
- 黑(0)背景，约 15x15 网格
- 1~2 个 4-连通单色前景对象（颜色如蓝(1)或红(2)），每个对象封闭 2~4 个 4-连通的黑(0)内部孔洞
- 每个对象中恰好一个孔洞内含有 1~4 个种子像素（颜色与对象色不同，如绿(3)或黄(4)），构成一个小图案（紧凑边界框 2x2 或 3x3 以内）
- 其余孔洞为纯黑(0)，不含任何非背景像素
- 不同对象互不接触，且都不触碰网格边缘
- 若有多个对象，它们的孔洞数互不相同

**规则**：
1. 对每个对象，计数其封闭的黑(0)孔洞总数 N（含有种子的孔洞也计入）
2. 找到含有种子像素的那个孔洞，将种子像素裁剪到其紧凑边界框
3. 将裁剪出的种子图案水平平铺 N 次，相邻副本之间间隔 1 列黑(0)
4. 若有多个对象，按各对象最上端像素的行坐标从小到大排列，依次将其平铺行纵向堆叠，相邻行之间间隔 1 行黑(0)
5. 输出仅包含平铺结果，原对象及其边框均不保留

**关键洞察**：空孔洞没有视觉内容却影响输出的宽度（它们贡献计数）；含种子的孔洞既贡献计数又提供内容——孔洞的双重角色是解题关键，单个示例无法分辨"复制次数 = 孔洞数"和"复制次数 = 种子像素数"等替代假说。

## 新题 4：分隔线对齐比较门控花纹转移

**组合逻辑**：[对齐比较/aligned_comparison](从移动单像素改为门控整体操作) + [颜色匹配定去向/color_match_dest](创新：匹配 -> 转移花纹，不匹配 -> 擦除目标框) + [空心矩形 + 内部花纹/hollow_rect + interior_motif](从无条件转移改为由比较结果条件触发) + [印章覆盖/stamp_overlay + 重涂色/recolor](花纹在转移过程中变色) + [擦除/erase](不匹配时整框擦除)

**来源原语**：aligned_comparison, color_match_dest, separator_line (7d7772cc); hollow_rect, interior_motif, stamp_overlay, patterned_frame_template, size_match (f21745ec); recolor, erase (多源)

**依赖链**：尺寸匹配确定哪些框配对，颜色比较决定配对后是转移花纹还是擦除目标框，转移时花纹还需重涂为目标框色。三个环节缺一不可：没有尺寸匹配则配对错误，没有颜色比较则不知哪些框获得花纹哪些被擦除，没有重涂色则花纹颜色错误。

分隔线两侧各有若干矩形框；左侧框含花纹，右侧框为空。按尺寸配对后，分隔线上的参考像素颜色决定是否将花纹转移到右侧框。

**输入结构**：
- 黑(0)背景，约 20x15 网格
- 一条贯穿全高的灰(5)垂直线位于网格中部，作为分隔线
- 左侧：2~3 个单像素厚的彩色空心矩形框（每个框一种非黑非灰颜色，如蓝(1)、红(2)、绿(3)），每个框内部有同色的花纹像素（不对称图案，约 3~6 个像素）
- 右侧：与左侧数量相同的空心矩形框（每个框一种非黑非灰颜色，如黄(4)、橙(7)、品红(6)），内部无花纹（全为黑(0)背景）
- 左右框通过外部尺寸（高 x 宽）一一配对：每个左框恰好有一个右框与其外部尺寸相同，且不存在两个左框尺寸相同
- 在分隔线列上，每对配对框各有一个参考像素：左框的参考像素颜色为 C_left，右框的参考像素颜色为 C_right，两者位于同一行
- 生成约束：至少一对 C_left == C_right，至少一对 C_left != C_right

**规则**：
1. 通过外部尺寸（高度和宽度）将左右框一一配对
2. 对每一对，检查其在分隔线上的参考像素颜色：
   - 若 C_left == C_right：将左框的内部花纹复制到右框的对应内部位置，花纹像素重涂为右框的边框颜色
   - 若 C_left != C_right：将右框整体擦除为背景(0)（边框和内部全部清除）
3. 左侧所有内容（框、花纹、参考像素）保持不变；分隔线保持不变

**关键洞察**：分隔线上的参考像素不属于任何框的结构——它们是独立的比较通道，门控了完全不同的两种操作（花纹转移 vs. 整框擦除）。必须对比多个示例才能发现颜色匹配/不匹配分别触发哪种操作。

## 新题 5：频率选精灵 + 频率定对角变色周期

**组合逻辑**：[计数/counting + 形状相同/shape_identity + 最高频精灵输出/most_frequent_sprite_output](从输出单份改为输出对角阵列) + [对角偏移重复/diag_offset_repeat + 尺寸决定步幅/size_determines_stride](从矩形改为精灵体) + [周期内指定位变色/cyclic_pos_recolored](创新：周期长度 = 频率计数值而非固定值 3) + [擦除/erase](非选中精灵移除)

**来源原语**：counting, shape_identity, most_frequent_sprite_output (39a8645d); diag_offset_repeat, size_determines_stride (e619ca6e); stamping, cyclic_pos_recolored (d304284e); erase (多源)

**依赖链**：频率计数同时决定两件事——哪种精灵被选中（最高频者），以及对角印章序列中的变色周期（频率值 K）。精灵的边界框尺寸决定步幅。三者缺一不可：不计数则不知选谁也不知周期；不知步幅则排布错误；不知周期则变色位置错误。

从多种重复精灵中选出最高频者，沿两条对角线反复印章；每隔 K 份（K = 频率计数值）将该份变色为红(2)。

**输入结构**：
- 黑(0)背景，约 18x18 网格
- 8~12 个小型单色精灵体（每个 3~6 像素，8-连通），分属 2~3 种形状类型
- 每种形状类型使用各自独有的颜色（如蓝(1)的 L 形散布、绿(3)的 T 形散布等，不同示例中具体形状不同，但同类型内形状一致）
- 恰好一种形状类型的出现次数严格多于其他任何类型（唯一最高频）
- 各精灵体互不接触，且不触碰网格边缘
- 记最高频类型的频率为 K（K >= 2），其边界框尺寸为 H x W

**规则**：
1. 将每个精灵体归一化到其紧凑边界框掩码，以（形状掩码 + 颜色）作为类型标识
2. 统计各类型出现次数，选出唯一最高频类型，记其频率为 K，边界框为 H x W
3. 将所有非最高频精灵擦除为背景(0)
4. 从每个保留的最高频精灵实例的左上角出发，沿右下方向以步幅 (H, W) 反复印章：偏移 (H, W), (2H, 2W), ...；同时沿左下方向以步幅 (H, -W) 反复印章：偏移 (H, -W), (2H, -2W), ...
5. 对每条对角方向的印章序列，从第 1 份印章开始编号（原实例不算，编号 0）：编号为 K 的整数倍的印章（第 K 份、第 2K 份、...）重涂为红(2)，其余保持原色
6. 超出网格边界的部分裁剪丢弃；原精灵实例保持原色不变

**关键洞察**：频率计数 K 同时控制精灵筛选和变色节奏——不计算频率就无法确定对角线上哪些位置变色。仅看单个示例可能将变色位置误读为固定间隔，需要多个示例（K 值不同）才能发现 K = 频率。

## 新题 6：孔洞拓扑解码 + 外部图例映射压缩

**组合逻辑**：[解码/decode](从读取槽位颜色改为读取拓扑特征) + [计数/counting](计封闭孔洞数作为解码键) + [图例映射/legend_mapping](创新：图例将孔洞数映射为颜色，而非位置映射颜色) + [压缩/compress + 每区域折叠单像素/region_to_pixel](将解码后的阵列压缩为小网格)

**来源原语**：decode, repeated_motif, legend_mapping, slot_determines_color (1be83260); counting, enclosed_hole, hole_count_to_color_mapping (0a2355a6); compress, grid_partition, region_to_pixel (780d0b14)

**依赖链**：图例将孔洞数映射为颜色（不是硬编码映射，每个示例的图例可能不同）；孔洞计数将每个花纹的拓扑特征转化为图例查找键；压缩将阵列坍缩为小网格。删除图例则映射关系不确定，删除计数则查找键不确定，删除压缩则输出格式错误。

外观相似的花纹阵列中，每个花纹内部孔洞数不同；外部色条图例将孔洞数映射为颜色；输出为每花纹一像素的压缩网格。

**输入结构**：
- 黑(0)背景，约 20x20 网格
- 一个 R x C 的矩形阵列由相同外形的小花纹组成（每个花纹 5x5，含 1 像素厚的灰(5)外框），花纹之间间隔 1 列/行背景
- 每个花纹的外框形状完全一致，但内部 3x3 区域中，0~4 个格子为黑(0)背景（即封闭孔洞），其余为灰(5)前景
- 不同花纹的孔洞数可能不同（0 到 4 均可出现）
- 阵列外部（如右侧或下方）有一条 5 格长的色条图例，用品红(6)单像素框围住以标识
- 图例的 5 个格子从左到右（或从上到下）分别编号 0~4，每格填有一种颜色（使用蓝(1)、红(2)、绿(3)、黄(4)、橙(7)等），表示孔洞数为该编号时的输出颜色
- 同一输入中图例不含重复颜色

**规则**：
1. 识别花纹阵列的 R x C 布局和外部图例色条
2. 对阵列中每个花纹，计算其内部 3x3 区域中 4-连通的封闭黑(0)孔洞数 H（0 <= H <= 4）
3. 在图例中查找编号 H 对应的颜色 C
4. 输出 R x C 网格，每个格子的颜色为该位置花纹解码后的颜色 C

**关键洞察**：花纹外形完全一样，差异隐藏在内部拓扑（孔洞数）中；图例将拓扑特征翻译为颜色，且图例内容随示例变化，因此不能记忆固定映射。必须同时发现"看的是孔洞数"和"查的是外部图例"这两层间接关系。

## 新题 7：原始像素计数定缩放倍率 + 图例链式重涂后缩放

**组合逻辑**：[计数/counting + 像素数定尺寸数/pixel_count_sets_size_copies](创新：计数发生在重涂之前，但缩放应用于重涂之后的结果) + [逐行顺序链式替换/chain_replace](图例可能将某些前景色映射为背景色，减少可见像素) + [像素放大/pixel_scale](将重涂后的精灵按预先冻结的倍率放大) + [双列图例/two_col_legend](提供颜色替换规则)

**来源原语**：counting, pixel_count_sets_size_copies (91413438); pixel_scale (8a6d367c); chain_replace, two_col_legend, legend_row_order (e4888269); recolor (多源)

**依赖链**：缩放倍率取决于原始精灵的非背景像素总数（重涂前），但被缩放的内容是重涂后的精灵（可能有像素变成了背景色而"消失"）。如果在重涂后再计数，得到的倍率更小，输出尺寸就会错误。这种时序约束使计数和重涂紧耦合：计数必须先于重涂，但缩放的输入是重涂后的结果。

先数原始精灵的前景像素得缩放倍率，再按图例链式重涂精灵（部分像素可能变为背景色），最后将重涂后的精灵按先前冻结的倍率像素放大输出。

**输入结构**：
- 黑(0)背景，约 12x12 网格
- 左侧：一个 3x3 的多色精灵，包含 2~3 种非黑前景色（如蓝(1)、红(2)、绿(3)），其中非黑像素共 S 个（4 <= S <= 7）
- 右侧：一个 2 列 x K 行的图例块（K = 1~3），每行左列为源色、右列为目标色
- 图例中至少有一行将某前景色映射为黑(0)（背景色），使重涂后精灵的可见前景像素数小于 S
- 图例行从上到下顺序应用（链式替换：前一行的替换结果可能被后一行再次替换）
- 精灵与图例之间间隔至少 2 列背景，互不接触

**规则**：
1. 计算原始精灵中所有非黑(0)像素的总数 S（这是缩放倍率）
2. 按图例从上到下逐行应用链式颜色替换：对精灵中每个非背景像素，若其当前颜色等于该行左列颜色，则替换为右列颜色；替换后继续检查下方行
3. 将重涂后的 3x3 精灵进行 S 倍像素放大：每个像素扩展为 S x S 的同色方块，输出尺寸为 (3S) x (3S)
4. 输出仅包含放大后的精灵，原始精灵和图例均不保留

**关键洞察**：缩放倍率 S 是在重涂前的精灵上计算的"冻结值"，而缩放内容是重涂后的精灵。如果错误地在重涂后计数，由于图例将部分前景色变为背景色(0)，S 会变小，输出尺寸就会出错。必须对比多个示例（图例将不同数量的像素变为背景）才能发现"先数后涂"的时序约束。
