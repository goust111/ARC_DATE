## 新题 1：连通性决定射线角色

**组合逻辑**：[连通判定](已有) → [角色分配](创新：连通结果动态划分发射体与障碍体) → [射线延伸](已有，但作用对象由连通判定决定) + [重涂色](已有)

**来源原语**：连通判定/connectivity_test、桥接路径/bridge_path、连通性/connectivity（参考题14 239be575）；射线延伸/ray_extend、障碍对象/blocker_object、射线遇障停止/ray_stops_at_block（参考题2 6ffe8f07）；重涂色/recolor（参考题2/4/13等）

**依赖链**：连通判定将同色对象分为发射体和障碍体两种角色 → 角色分配决定了射线的发射源和终止屏障 → 射线行为完全依赖角色分配结果，无法跳过连通分析直接判断

对同色前景对象做连通分析，被桥接连通的成为射线发射源，孤立的变为障碍阻挡射线。

**输入结构**：黑(0)背景网格，约15x15。3-5个绿(3)前景对象，每个是4-连通的单色小图形（3-6像素，形状各异——不规则团块、短折线、弯曲片段等，不同示例中同类对象形状不同）。部分绿对象之间有青(8)桥接像素连接（单像素宽路径，可弯折，长度至少2像素以确保桥接对象不直接4-邻接）。若干红(2)单像素标记散布在背景上，不与任何绿对象或桥接路径4-邻接。生成约束：每个绿对象的边界框距网格边缘至少2像素；至少存在一个孤立绿对象和一组通过桥接互联的绿对象（2-3个被连在同一分量内）；不同示例中连通拓扑不同（如示例1中左侧两个被桥接而右侧孤立，示例2中上方三个被桥接而下方孤立）。

**规则**：
1. 在所有非黑像素上建立4-连通分量（分量内颜色可不同——绿像素和青桥接像素可在同一分量中）。
2. 对每个绿(3)对象：若其所在连通分量包含至少2个独立的绿对象（即该对象通过桥接与至少一个其他绿对象相连），则该对象为"发射体"；否则为"障碍体"。
3. 将所有障碍体的绿像素重涂为灰(5)。
4. 从每个发射体像素向上、下、左、右四个正方向各发射一条射线。
5. 射线沿途将黑(0)背景像素涂为蓝(1)；遇到灰(5)障碍像素时在该障碍像素前一格停止（不覆盖障碍）；遇到网格边界时停止。
6. 射线穿过其他发射体像素和青桥接像素时不停止，保持它们原色不变。红(2)标记像素被射线覆盖为蓝(1)。
7. 多条射线涂同一像素时无冲突（均为蓝色）。

**关键洞察**：同种颜色、同种形态的前景对象仅因连通性不同而扮演完全相反的角色（射线发射源 vs. 射线屏障）。必须先解决图论连通性问题，才能确定哪些对象发射射线、哪些对象阻挡射线——单看颜色或形状无法区分。

## 新题 2：周期推断约束断线修复阈值

**组合逻辑**：[周期瓦片推断](已有) → [间隙阈值导出](创新：瓦片最小周期维度成为补线的最大允许间隙) → [标记替换](已有) + [补线](已有，但阈值由周期推断结果决定)

**来源原语**：周期瓦片/periodic_tile、行列周期/row_col_period、标记为缺失值/markers_missing_val（参考题12 f823c43c）；补线/line_completion、间隙长度限制/gap_length_constraint（参考题3 7b80bb43）；重涂色/recolor（多道参考题）

**依赖链**：周期推断恢复背景瓦片 → 最小周期维度生成补线阈值 → 补线操作依据该阈值决定填补哪些断口、保留哪些断口 → 跳过周期推断则既无法恢复粉色缺失值，也无法获得正确的间隙阈值

利用背景周期瓦片的最小维度周期作为断线修复的最大允许间隙，同时恢复瓦片中被标记遮蔽的缺失值。

**输入结构**：约14x14网格。背景为一个由蓝(1)和绿(3)两色构成的矩形重复瓦片图案（如交错条纹或格子，行周期P_r和列周期P_c可不相等，范围2-5）。若干红(2)水平或垂直线段叠画在瓦片上方，每条线段至少3像素长。部分红线段存在1-4像素的间隙（间隙处显示的是下层瓦片的蓝或绿色）。另有若干品红(6)像素替换了瓦片中的某些非红色位置（不出现在红线段上）。生成约束：品红像素不超过总非红像素的15%，以保证瓦片周期可推断；每条红线段的间隙不超过2个；至少有一个间隙长度恰好等于min(P_r, P_c)，至少有一个间隙长度恰好等于min(P_r, P_c)+1（确保阈值判断可被观察到）。不同示例中瓦片周期不同，从而产生不同的阈值行为。

**规则**：
1. 将红(2)和品红(6)像素视为"未知"，从剩余蓝/绿像素推断最小矩形瓦片周期（行周期P_r，列周期P_c）。
2. 计算间隙阈值 G = min(P_r, P_c)。
3. 将每个品红(6)像素替换为其网格坐标对应的瓦片颜色（蓝或绿）。
4. 对每条红线段，检测其间隙（连续非红像素段）。若间隙长度 <= G，将间隙填充为红(2)；若间隙长度 > G，保留间隙处的瓦片颜色不变。
5. 处理顺序：先恢复品红缺失值（步骤3），再判断间隙（步骤4），因为间隙像素需要正确的瓦片底色来确认它们不是红线的一部分。

**关键洞察**：瓦片周期承担双重职责——既定义背景图案的恢复规则，又隐式决定了线段修复的严格程度。周期越大允许修复的间隙越长；不同示例中周期变化导致同样长度的间隙在一个示例中被修复、在另一个示例中被保留，迫使求解者发现周期与阈值的关联。

## 新题 3：对角朝向编码外推方向与涂色

**组合逻辑**：[分类/对角朝向](已有) → [外推方向选择](创新：局部对角朝向决定等距标记线的外推方向) + [多数朝向决定色](已有，但从对角线段的分类挪用到外推线的涂色)

**来源原语**：分类/classify、对角线段/diagonal_bar、对角朝向/diagonal_orientation、多数朝向决定色/majority_orient_color（参考题15 1d61978c）；外推/extrapolate、等距标记点/equally_spaced_markers、等距共线/equally_spaced_collinear、边界内延续/continue_within_bounds（参考题11 0b17323b）

**依赖链**：对角线段的局部朝向决定每组标记线从哪端外推 → 对角线段的全局多数/少数分类决定外推像素的颜色 → 同一组对角像素同时提供方向信息和颜色信息，两个角色缺一不可

识别等距标记线旁的对角线段朝向：朝向决定外推方向（从哪端延伸），全局多数朝向决定外推颜色。

**输入结构**：黑(0)背景网格，约15x15。2-3组蓝(1)等距标记，每组恰好3个像素排列在同一条水平、垂直或45度对角线上，相邻标记间距相等（步进向量恒定）。每组标记的中间像素（按行主序排列后的第2个）的8-邻域内有1-3个绿(3)对角线段像素（即这些绿像素仅有对角方向的绿邻居，无正交方向的绿邻居）。所有绿对角像素的朝向为NE/SW或NW/SE之一。生成约束：至少有两组标记线，其中间标记旁的对角朝向不同（一组旁是NE/SW，另一组旁是NW/SE）；两种朝向的绿像素总数不相等（以确保多数/少数可区分）；每组标记线的步进向量保证至少可外推2步而不超出网格。

**规则**：
1. 识别每组3个蓝(1)等距共线标记，按行主序（先按行从小到大，同行按列从小到大）排列，记步进向量为d。
2. 检查该组中间标记的8-邻域内的绿(3)对角像素的朝向：
   - 若为NE/SW朝向（即绿像素的对角邻居在右上/左下方向）：从最后一个标记起沿+d方向外推。
   - 若为NW/SE朝向（即绿像素的对角邻居在左上/右下方向）：从第一个标记起沿-d方向外推。
3. 统计所有绿(3)对角像素的朝向总数：数量多的朝向为"多数朝向"，数量少的为"少数朝向"。
4. 多数朝向对应的外推线涂青(8)；少数朝向对应的外推线涂红(2)。
5. 外推从起点沿步进方向逐步绘制，每步涂一个像素，直到下一步超出网格边界为止。起点像素为距最后（或第一）标记一步之外的第一个位置。
6. 蓝(1)标记和绿(3)对角像素保持不变。

**关键洞察**：对角线段同时承担两种完全不同的语义角色——作为局部标志指示各自标记线的外推方向，又作为全局统计量决定所有外推线的涂色。必须同时解码两个层次才能得到正确输出；仅解码一个层次会在方向或颜色上出错。

## 新题 4：频率过滤的印章传递

**组合逻辑**：[计数](已有) → [频率匹配](已有，但用于过滤印章内容而非柱状填充) → [骨架对齐+印章覆盖](已有，但仅传递通过频率过滤的标注像素)

**来源原语**：印章覆盖/stamp、骨架对齐/skeleton_alignment、锚点像素/anchor_pixel、完整标注传递副本/complete_anno_to_copies（参考题17 36d67576）；计数/counting、频率匹配/frequency_matching、频率等于标记数/frequency_equals_marker_count、分隔行/separator_row、编码行/code_row（参考题19 2685904e）

**依赖链**：模板标注像素总数作为频率阈值 → 编码行中符合该频率的颜色构成"激活色集" → 仅激活色的标注像素被印章传递到各副本 → 骨架对齐确定传递时的几何变换 → 缺少频率过滤则传递过多标注，缺少骨架对齐则位置错误

模板中标注像素的数量定义频率阈值；编码行中出现次数恰好等于该阈值的颜色才是"激活色"；仅激活色标注被印章传递到骨架副本上。

**输入结构**：黑(0)背景网格，约18x18。3-4个8-连通小图案（精灵体），共享相同的灰(5)骨架结构（5-8像素，形状为不规则连通片段，不同示例中骨架形状不同）。每个图案中有一个橙(7)锚点像素嵌入骨架内部。其中一个图案（"模板"）除灰骨架和橙锚点外，还包含若干额外标注像素，使用2-3种颜色（如蓝(1)、红(2)、绿(3)），分布在骨架的8-邻域周围。其余图案仅有灰骨架和橙锚点，无标注。网格中有一条黄(4)全宽分隔行（水平贯穿整个网格宽度）。分隔行下方紧接一行编码行，编码行中有若干非黑像素，颜色取自标注色的子集。生成约束：模板中各标注色的像素数互不相等；模板标注像素总数T满足编码行中恰有一种颜色出现T次、至少一种颜色出现次数不等于T；各精灵体互不重叠，距分隔行至少2像素。

**规则**：
1. 找到模板图案（唯一包含非灰、非橙、非黑像素的精灵体），统计其标注像素总数（所有非灰非橙非黑像素之和）为T。
2. 在编码行中，找到出现次数恰好等于T的所有颜色，组成"激活色集"。
3. 在模板中，仅保留颜色属于激活色集的标注像素为"可传递标注"，其余标注色视为被过滤掉（这些像素在输出中变为黑色背景）。
4. 对每个不完整图案（仅有骨架和锚点的副本），找到唯一的旋转/翻转+平移变换，使模板的灰骨架和橙锚点完全映射到该副本的灰骨架和橙锚点上。
5. 通过步骤4的变换，将可传递标注像素映射到副本周围对应位置并绘制（若目标位置超出网格则忽略该像素）。
6. 模板自身的非激活标注像素也被擦除（变为黑色背景）。灰骨架、橙锚点、黄分隔行和编码行保持不变。

**关键洞察**：编码行不仅存在于空间上分离的区域，它通过频率匹配充当了标注内容的过滤器——并非所有标注都被传递，只有"被编码行认证"的颜色才存活。模板的标注数量T是一个自引用参数：它同时描述了模板自身的属性并决定了外部过滤标准。

## 新题 5：缩略图补全触发计数反馈重涂色

**组合逻辑**：[坐标映射+补全](已有) → [计数](已有，但统计对象为补全操作新增的色块数) → [重涂色](已有，但由新增数量的奇偶性决定重涂目标色组)

**来源原语**：缩略图/minimap、坐标映射/coordinate_mapping、已有块确认对齐/existing_blocks_confirm_alignment、缩放/scale、补全/complete（参考题20 c4d067a0）；计数/counting（参考题6/18/19）；重涂色/recolor（参考题13/15/16等）

**依赖链**：缩略图与现有色块共同确定缩放因子和偏移 → 补全操作放置缺失色块 → 新增色块数量决定后续重涂规则 → 重涂反过来修改包括已有块在内的颜色 → 不执行补全就无法知道新增数量，不知道数量就无法确定重涂目标

先依据缩略图补全缺失的色块，再统计新放置的色块数量，根据数量的奇偶决定对哪个颜色组进行全局重涂。

**输入结构**：黑(0)背景网格，约20x20。左上角有一个小型精灵图（3x4至5x5），其像素使用青(8)、红(2)、蓝(1)三种颜色和黑(0)空位，构成缩略图。主区域中已放置若干NxN单色方块（N需推断，范围3-5），每个方块的颜色和位置对应缩略图中某个像素经缩放+偏移后的结果。部分缩略图像素对应的主区域位置为空（黑色背景），需要补全。生成约束：已有方块至少3个（足以唯一确定N和偏移）；需补全的方块数量在不同示例中奇偶不同；已有方块中青(8)和红(2)都至少出现一次；缩略图不与任何主区域方块的空间重叠。

**规则**：
1. 从已有的NxN单色方块与缩略图像素的颜色对应关系推断缩放因子N和空间偏移（至少3个方块确认对齐）。
2. 对缩略图中每个非黑像素，检查其在主区域对应位置是否已有方块。若该位置为空，放置一个NxN的同色方块——这是"新增方块"。
3. 统计新增方块的总数M。
4. 若M为奇数：将网格中所有青(8)方块（包括已有的和新增的）重涂为黄(4)。
5. 若M为偶数：将网格中所有红(2)方块（包括已有的和新增的）重涂为橙(7)。
6. 蓝(1)方块在任何情况下都不被重涂。缩略图像素保持原色不变。

**关键洞察**：补全操作本身产生的副产品（新增方块数量）反过来决定了对整个布局（包括补全前已有的方块）的颜色修改。这是一个"操作结果反馈修改操作输入"的非线性结构：你必须先完成补全才能知道重涂规则，但重涂的对象包含补全之前就存在的方块。

## 新题 6：颜色编码旋转角度

**组合逻辑**：[同行或同列配对](已有) → [颜色解码旋转角](创新：源像素颜色不是涂色信息而是旋转指令) → [旋转/枢轴](已有，但角度不再固定而由颜色决定) + [重涂色](已有)

**来源原语**：旋转/rotate、枢轴像素/pivot_pixel、源像素/source_pixel、同行或同列/same_row_or_col、距离保持不变/distance_preserved（参考题7 1a244afd）；重涂色/recolor（参考题7等）；图例行内配对/legend_row_pairing（参考题16 0becf7df，此处从颜色互换挪用为颜色-角度映射的隐式编码概念）

**依赖链**：每个源像素的颜色编码了旋转角度 → 枢轴配对确定旋转中心 → 距离保持确定目标位置 → 颜色-角度映射是隐式规则，必须对比多个示例才能归纳 → 缺少颜色解码则角度未知，缺少枢轴配对则中心未知

将每个彩色源像素按其颜色编码的角度绕配对枢轴旋转，旋转后统一涂为橙色。

**输入结构**：黑(0)背景网格，约14x14。3-5个蓝(1)枢轴像素，彼此分散放置（任意两个枢轴之间至少间隔3像素）。若干源像素分布在枢轴的同行或同列上，每个源像素恰好与一个枢轴共行或共列（不存在一个源像素同时与两个枢轴共行/共列的情况）。源像素的颜色为红(2)、绿(3)、黄(4)三种之一。生成约束：每种源色至少出现一次；每个枢轴配对的源像素不超过2个（避免旋转后重叠）；所有旋转目标位置在网格边界内；旋转目标位置不与任何枢轴或其他源像素重叠。

**规则**：
1. 将每个源像素配对到与它在同一行或同一列的唯一蓝(1)枢轴。
2. 根据源像素颜色确定旋转角度：
   - 红(2) → 顺时针90度。
   - 绿(3) → 180度。
   - 黄(4) → 逆时针90度（即顺时针270度）。
3. 以配对枢轴为中心，将源像素按确定的角度旋转，保持源像素到枢轴的曼哈顿轴向距离不变（即旋转的是行列偏移向量，非欧氏旋转）。具体地：若源像素在枢轴的行方向偏移dr、列方向偏移dc，则顺时针90度后偏移变为(dc, -dr)，180度后变为(-dr, -dc)，逆时针90度后变为(-dc, dr)。
4. 删除原始源像素（变为黑色背景）。
5. 在旋转目标位置涂橙(7)。
6. 蓝(1)枢轴像素保持不变。

**关键洞察**：源像素的颜色不是装饰性的，也不会保留到输出——它是一条旋转指令。颜色-角度的映射关系是隐式的，只能通过对比多个示例中不同颜色源像素的旋转结果来归纳（例如，观察到红色源像素总是出现在枢轴的顺时针90度位置，而输出中该位置变为橙色）。

## 新题 7：互补形状选取裁剪并由标记数决定翻转

**组合逻辑**：[互补形状匹配](已有) → [裁剪](已有，但选取标准从标记计数变为形状匹配) → [计数](已有) → [条件镜像](创新：标记计数的奇偶决定是否水平翻转裁剪结果)

**来源原语**：形状匹配/shape_match、互补形状/complementary_shape、缺口形状唯一配对/unique_complement、模板缺口/template_gap（参考题5 18447a8d）；裁剪/crop、计数/counting、标记像素/marker_pixel、包含/containment、标记最多者选取/rectangle_with_most_markers_selected（参考题6 8efcae92）；镜像/mirror（参考题8 de493100）

**依赖链**：模板缺口形状提取 → 与各矩形内部的源形状做互补匹配 → 唯一匹配者被选中裁剪 → 裁剪区域内标记计数决定是否翻转 → 形状匹配和标记计数分别控制"选哪个"和"怎么输出"

从模板缺口形状出发找到唯一互补匹配的矩形，裁剪该矩形，再根据其内部标记数的奇偶决定是否水平翻转输出。

**输入结构**：黑(0)背景网格，约18x18。左上区域有一个青(8)模板矩形（约4x4至6x6），内部缺少若干像素形成一个连通缺口（缺口为黑色，形状为3-5像素的4-连通图形）。网格其余区域散布3-4个绿(3)实心矩形（大小各异，约4x5至6x7），互不重叠，与模板矩形也不重叠。每个绿矩形内部包含一个红(2)的4-连通小图形（3-5像素，各矩形中的红图形形状互不相同），以及0-3个蓝(1)标记像素（单像素，不与红图形4-邻接）。生成约束：恰好一个绿矩形中的红图形归一化后（平移至左上角）与模板缺口形状全等；不同示例中匹配的矩形位置不同；匹配矩形中的蓝标记数在不同示例中奇偶不同。

**规则**：
1. 提取青模板中的缺口形状：模板边界框内黑色像素构成的4-连通区域，归一化为左上角起始。
2. 对每个绿矩形，提取其内部的红(2)图形，归一化为左上角起始。
3. 找到唯一的绿矩形，使其红图形归一化形状与模板缺口归一化形状完全相同——该矩形被选中。
4. 裁剪选中的绿矩形（取其完整边界框内容，包含绿底、红图形、蓝标记）。
5. 统计裁剪结果中蓝(1)标记像素的数量M。
6. 若M为奇数，将裁剪结果沿垂直中轴水平翻转（左右镜像）。若M为偶数（含0），保持裁剪结果不变。
7. 在最终输出中，将红(2)图形像素重涂为青(8)（表示该形状是模板缺口的互补）。

**关键洞察**：选择"裁剪哪个矩形"需要空间形状分析（互补匹配），而决定"输出的朝向"需要计数分析（标记奇偶）——两种完全不同类型的推理同时作用于最终结果。标记像素容易被误认为是选择标准（"选标记最多的"），但实际上它们控制的是输出方向，形成认知陷阱。

## 新题 8：边缘竖条对称性指示镜像重建轴

**组合逻辑**：[边缘竖条几何分析](创新：竖条的对称关系编码了图案的镜像轴方向) → [镜像轴推断](创新) → [遮挡区域重建](已有，但镜像轴不再预设而由竖条推断)

**来源原语**：镜像/mirror、补全/reconstruct、遮挡矩形/occluding_rect、对称图案/symmetric_pattern、双轴对称/two_axis_symmetry、镜像恢复遮挡区/mirror_recover_occluded（参考题8 de493100）；边缘竖条/edge_bar、对称配对/symmetric_pair、行对齐/row_alignment（参考题4 673ef223）

**依赖链**：两条边缘竖条的几何关系编码了镜像轴方向 → 镜像轴确定后才能正确重建遮挡区 → 遮挡区的每个像素通过镜像映射从可见区复制 → 若轴选择错误则重建结果完全不同

分析网格两侧边缘竖条的对称关系，推断出隐含的图案镜像轴（水平或垂直），再沿该轴重建被灰色矩形遮挡的区域。

**输入结构**：约14x14网格，黑(0)背景。网格中有一个由多种颜色（蓝(1)、红(2)、绿(3)、黄(4)中的2-3种）构成的前景图案，该图案关于某一条穿过网格中心的轴具有镜像对称性（可以是垂直轴或水平轴，不同示例中不同）。一个灰(5)实心矩形遮挡了图案的一部分（矩形覆盖的图案像素被灰色替换）。网格的两条相对边缘上各有一条栗(9)竖条（或横条）：若图案是左右对称的（垂直轴），则两条栗条分别在左边缘和右边缘，它们的行范围关于网格水平中心线对称（即一条从第r1行到第r2行，另一条从第(H-1-r2)行到第(H-1-r1)行，H为网格高度）；若图案是上下对称的（水平轴），则两条栗条分别在上边缘和下边缘，它们的列范围关于网格垂直中心线对称。生成约束：灰矩形不覆盖任何栗条像素；灰矩形的每个像素在镜像映射后都有对应的可见（非灰、非栗）像素可供复制（即遮挡区不跨越对称轴）；栗条长度至少3像素，以使对称性可辨认；图案本身不具备另一条轴的对称性（避免歧义）。

**规则**：
1. 找到两条栗(9)边缘条。判断它们的方位：
   - 若两条分别在左右边缘（同列号0和W-1，占据不同行范围）：检查它们的行范围是否关于水平中心线对称。若对称 → 图案的镜像轴为垂直轴（左右对称）。
   - 若两条分别在上下边缘（同行号0和H-1，占据不同列范围）：检查它们的列范围是否关于垂直中心线对称。若对称 → 图案的镜像轴为水平轴（上下对称）。
2. 确定镜像轴后，对灰(5)矩形中的每个像素，计算其关于该轴的镜像坐标。
3. 用镜像坐标处的可见像素颜色替换灰像素。
4. 栗(9)边缘条和原始可见图案像素保持不变。

**关键洞察**：边缘竖条本身不是图案的一部分，而是"元数据"——它们的对称几何关系编码了图案使用的镜像轴方向。求解者必须先从竖条的空间排布推断出对称类型，才能选择正确的重建方向。如果忽略竖条凭直觉猜测轴向，在某些示例中会得到错误的重建。
