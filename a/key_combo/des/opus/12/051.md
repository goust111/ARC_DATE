## 新题 1：引导体路由的同心环色彩置换

**组合逻辑**：[排序/sort] + [射线延伸/ray_cast](创新：射线不用于绘制对角线，而用于建立对象间的颜色路由) + [同心环绘制/concentric_draw](创新：环颜色不来自对象本身，而来自引导体路由的目标对象) + [擦除/erase]

**来源原语**：排序、面积排序（5587a8d0）；射线延伸、引导体（a78176bb）；同心环绘制、嵌套方环（5587a8d0）；擦除（a78176bb）

**依赖链**：面积排序和引导体路由是两条独立分析线，它们在同心环绘制时汇合——面积排序决定每个对象占据哪一层环，引导体路由决定该层环使用什么颜色。两条线缺任一条，输出都无法确定。

根据对象面积确定嵌套环位置，但每层环的颜色不是对象自身的颜色，而是通过灰色引导体射线指向的另一个对象的颜色。

**输入结构**：
- 黑(0)背景网格，约 14x14
- 3~5 个单色 4-连通前景对象，每个对象颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取），像素数各不相同且在 3~12 像素范围内，形状为任意 4-连通单色图形（不限定具体外形，不同示例中同一逻辑角色的对象形状应不同）
- 每个对象恰好有一个灰(5)引导段（2~3 个灰像素组成的直线段），该引导段 4-连通地紧邻该对象的一侧，指向远离该对象的方向
- 每个引导段的延长线方向上（水平或垂直方向，沿引导段指向延伸）恰好存在且仅存在另一个前景对象
- 引导路由构成一个置换：每个对象恰好被另一个对象的引导体指向一次（即引导体网络是对象集合上的一个置换映射，不存在两个引导体指向同一对象）
- 生成约束：引导段的射线路径上不经过第三个对象；所有对象面积互不相同

**规则**：
1. 将所有前景对象按像素数从大到小排序，得到环位序列 [o1, o2, ..., oN]（o1 面积最大，oN 面积最小）。
2. 对每个对象 oi，沿其灰色引导段的指向方向做射线延伸（从引导段末端沿该方向逐像素前进），找到射线首次命中的另一个前景对象 oj。记录映射：oi 的环位 → oj 的颜色。
3. 构造边长为 2N-1 的正方形输出网格，绘制 N 层同心方环：第 1 层（最外环）对应 o1 的环位，使用映射中 o1 路由到的目标对象的颜色填充；第 2 层对应 o2，使用 o2 路由到的颜色；以此类推，第 N 层（中心像素）使用 oN 路由到的颜色。
4. 输入中所有灰色引导段像素和原始前景对象像素均不出现在输出中（输出仅为同心方环图案）。

**关键洞察**：引导体建立了一个颜色置换网络——面积最大的对象决定最外环的"位置"，但该环实际涂上的颜色来自引导体所指向的另一个对象。必须同时完成面积排序和路由追踪才能确定每层环的颜色。

## 新题 2：标记笛卡尔选区内的极值分区涂色

**组合逻辑**：[填充/fill](创新：笛卡尔积不再选择单个像素，而是选择分隔线划分的分区单元格) + [计数/counting] + [重涂色/recolor](创新：极值区域涂色作用于笛卡尔积选中的子集，而非全部分区)

**来源原语**：填充、标记像素、行列交叉、边缘标记笛卡尔积（2281f1f4）；计数、分隔线、封闭区域、面积比较、极值区域分别涂色（6455b5f5）；重涂色（多个参考题）

**依赖链**：边缘标记笛卡尔积筛选出目标单元格子集 → 在该子集内（而非全部单元格内）执行面积极值比较 → 极值涂色仅对子集生效。去掉笛卡尔选区，极值比较的范围错误；去掉极值比较，所有选中单元格颜色相同。

边缘标记的笛卡尔积选中分隔线网格中的特定单元格，仅在被选中的单元格子集内比较面积并对极值单元格分别涂色。

**输入结构**：
- 网格约 13x13，黑(0)为单元格填充色
- 红(2)分隔线（一像素宽的完整水平线和垂直线）将网格分为若干大小不等的矩形黑色单元格（至少 6 个单元格，单元格面积至少有 3 种不同值）
- 蓝(1)标记像素位于第 0 行（顶行），每个标记像素的列坐标落在某个单元格列带内（两条相邻垂直分隔线之间的列范围）；共 2~4 个蓝标记
- 绿(3)标记像素位于最右列，每个标记像素的行坐标落在某个单元格行带内（两条相邻水平分隔线之间的行范围）；共 2~3 个绿标记
- 生成约束：笛卡尔积选中的单元格数量不少于 3 个；选中单元格中面积最小的和面积最大的各自唯一（无并列）

**规则**：
1. 蓝(1)标记像素确定"选中列带"：标记所在列属于哪个列带，该列带即被选中。绿(3)标记像素确定"选中行带"：标记所在行属于哪个行带，该行带即被选中。
2. 取选中列带与选中行带的笛卡尔积 → 得到一组"选中单元格"。
3. 计算每个选中单元格的黑色面积（单元格内黑色像素数）。
4. 面积最小的选中单元格 → 填充为青(8)。面积最大的选中单元格 → 填充为橙(7)。其余选中单元格 → 填充为黄(4)。
5. 未被选中的单元格保持黑(0)。红色分隔线、蓝色标记和绿色标记像素保持不变。

**关键洞察**：标记像素的笛卡尔积不再产生单像素填充（如参考题 2281f1f4），而是选出分区单元格；极值涂色规则不再覆盖全部单元格（如参考题 6455b5f5），而是仅作用于被标记选中的子集。选区范围和涂色规则相互依赖——面积极值的含义取决于哪些单元格被选中。

## 新题 3：跨尺度形状匹配后的配对色角标装饰

**组合逻辑**：[形状匹配/shape_matching] + [筛选/filtering] + [描边/decorate](创新：角标颜色不全部固定，其中一个角标的颜色来自被匹配配对中的另一个对象) + [擦除/erase]

**来源原语**：形状匹配、缩放对象、跨尺度同形、返回较小者（ce602527）；描边、角标记、对角邻接、四角固定配色装饰（95990924）；筛选、干扰对象、忽略干扰项（3194b014/ce602527）；擦除（a78176bb）

**依赖链**：形状匹配确定配对关系和干扰项 → 筛选保留较小者、擦除较大者和干扰项 → 角标装饰中西北角颜色来自被擦除的较大者。去掉形状匹配，不知道保留谁；去掉角标装饰，只是裁剪题；去掉配对色传递（西北角），四角颜色全部固定，信息丢失。

在多个不同颜色和尺度的对象中找出形状相同但尺度不同的配对，保留较小者并在其四角添加角标，其中西北角标的颜色来自被配对的较大对象。

**输入结构**：
- 黑(0)背景网格，约 15x15
- 5~7 个单色 4-连通前景对象，每个对象颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)、青(8)中选取）
- 其中存在 2 组跨尺度配对：每组中较小对象的掩模恰好等于较大对象的掩模按因子 2 缩小（即较大对象的像素坐标全部除以 2 后与较小对象的像素坐标集合一致）。较小对象的边界框为 NxM，较大对象的边界框为 2Nx2M
- 剩余 1~3 个对象是干扰项：它们的形状与任何其他对象均不存在整数倍缩放关系
- 每个较小对象的边界框四角的对角邻接位置（即边界框外扩一圈的四个角像素）均为黑(0)背景（有空间放置角标）
- 生成约束：所有对象互不重叠且边界框互不相邻；两组配对中较小对象的形状不同

**规则**：
1. 对所有对象两两比较，将较小对象的掩模按因子 2 放大后与较大对象的掩模比较，匹配则构成一组配对。
2. 擦除所有干扰对象（替换为黑(0)）。擦除每组配对中的较大对象。
3. 保留每组配对中的较小对象，在其边界框的四个对角邻接位置添加角标：
   - 西北角（边界框左上角的左上对角像素）→ 填充该配对中被擦除的较大对象的颜色
   - 东北角（边界框右上角的右上对角像素）→ 填充红(2)
   - 西南角（边界框左下角的左下对角像素）→ 填充绿(3)
   - 东南角（边界框右下角的右下对角像素）→ 填充黄(4)
4. 若角标固定色（红/绿/黄）与较小对象自身颜色相同，该角标改用灰(5)以避免混淆。

**关键洞察**：三个固定角标颜色（东北红、西南绿、东南黄）是装饰性的，但西北角标的颜色携带了来自配对伙伴的信息——它编码了被擦除的较大对象的身份。求解者必须先完成跨尺度匹配才能知道西北角标应涂什么色。

## 新题 4：平铺合并触发条件膨胀

**组合逻辑**：[平铺/tiling] + [连通检测/connected_component_detection](创新：用于检测平铺后跨边界合并的对象) + [膨胀/dilate](创新：膨胀条件由平铺后的连通分量数决定，而非图例映射) + [筛选/filtering]

**来源原语**：平铺（10fcaaa3）；连通检测、筛选、唯一连通分量、忽略干扰项（3194b014）；膨胀（5adee1b2）

**依赖链**：平铺改变空间拓扑（边缘对象合并）→ 连通检测区分合并与未合并 → 膨胀仅对合并分量执行。去掉平铺，无合并发生；去掉连通检测，无法区分合并与否；去掉条件膨胀，平铺后无变换。

将输入 2x2 平铺后，检测每种颜色的连通分量数——原本触及网格边缘的对象在平铺后跨边界合并，分量数少于 4；仅对发生合并的颜色执行膨胀。

**输入结构**：
- 黑(0)背景网格，约 6x6
- 2~4 个单色 4-连通前景对象，每个颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)中选取），每个对象 2~4 像素
- 至少一个对象的某些像素位于网格的右边缘列或底边缘行（平铺后将与相邻象限的副本合并）
- 至少一个对象完全位于网格内部（距离所有边缘至少 2 像素，平铺后四个副本互不相邻）
- 一个灰(5)单像素干扰点位于网格内部
- 生成约束：对象间互不 4-连通相邻；触边对象仅触及右边缘或底边缘（不同时触及左/上边缘，以确保平铺后至少存在未合并的副本对作为对照）

**规则**：
1. 将输入网格 2x2 平铺，生成宽高各翻倍的输出网格。
2. 擦除输出中所有灰(5)像素（替换为黑(0)）。
3. 对每种非灰前景颜色 c，检测其在输出网格中的 4-连通分量数 K_c。由于原始输入有 4 个副本，若 c 色对象未触边则 K_c = 4；若触及一条边则 K_c = 2（两对副本各合并为一）；若触及右边缘和底边缘两条边则 K_c = 1（四个副本全部合并）。
4. 若 K_c = 4（未合并），该颜色的所有分量保持原样。
5. 若 K_c < 4（发生合并），对该颜色的每个分量执行 1 像素膨胀：将分量边界框向外扩展 1 格（裁剪到网格边界），在扩展区域内的所有黑(0)像素填充为颜色 c。
6. 若两种颜色的膨胀区域冲突（同一像素被两种颜色的膨胀覆盖），分量像素数较少的颜色优先（其颜色写入该像素）。

**关键洞察**：对象在原始网格中的位置（是否触及边缘）通过平铺后的连通分量数间接编码了膨胀条件。内部对象产生 4 个独立副本不膨胀；边缘对象副本合并后数量减少，触发膨胀。同一个平铺操作既改变了空间布局又创造了区分对象的条件。

## 新题 5：边框缺口填色门控内部对象颜色互换

**组合逻辑**：[填充/fill](创新：缺口填色不是最终输出，而是生成门控信号) + [颜色互换/color_swap](创新：互换的执行与否取决于缺口填色结果与对象自身颜色的比较) — 同时约束结构，非线性流水线

**来源原语**：填充、矩形边框、十字缺口、朝向对应边色、开口朝向决定色（5b37cb25）；颜色互换、前景对象、同对象内互换（45737921）

**依赖链**：这是一个同时约束结构——边框侧色决定缺口填色，缺口填色与对象自身颜色的比较决定是否执行互换。两个操作不是顺序独立的：缺口填色的结果改变了互换的触发条件，而互换的目标又取决于对象自身的颜色组成。

矩形边框的缺口被填为对应边框侧的颜色；框内双色对象默认执行颜色互换，但若该对象最近的缺口填色恰好与对象某一颜色相同，则互换被抑制。

**输入结构**：
- 网格约 13x13
- 一个单像素宽矩形边框占据网格边缘附近（边框内边距约 1 像素），四边颜色不同：
  - 顶边：蓝(1)
  - 右边：红(2)
  - 底边：绿(3)
  - 左边：黄(4)
  - 四个角像素为灰(5)（中性，不属于任何边）
- 边框的某些位置存在单像素缺口：缺口是边框线上的一个黑(0)像素，其内侧（朝向框内的方向）是背景或对象像素，外侧朝向网格边界。每个缺口位于某一条边上（顶/右/底/左），共 3~5 个缺口
- 框内黑(0)背景上有 3~5 个 3x3 矩形双色对象，每个对象恰好使用两种颜色（从橙(7)、青(8)、栗(9)、品红(6)以及蓝(1)、红(2)、绿(3)、黄(4)中选取两种），对象内的两种颜色各占若干像素
- 每个 3x3 对象在其边界框的上/下/左/右四个方向中，恰好有一个方向上最近的边框段包含一个缺口（即该对象有且仅有一个"最近缺口"）。"最近缺口"定义：从对象边界框中心出发沿上/下/左/右四个方向扫描，首先遇到的缺口
- 生成约束：每个对象的最近缺口是唯一的（不存在等距的两个缺口）；至少一个对象的最近缺口所在边框侧颜色与该对象的某一颜色相同（将被门控），至少一个对象的最近缺口所在边框侧颜色与该对象的两种颜色均不同（将执行互换）

**规则**：
1. 填充每个缺口像素：用该缺口所在边框边的颜色替换黑(0)像素（顶边缺口填蓝(1)、右边填红(2)、底边填绿(3)、左边填黄(4)），使边框恢复完整。
2. 对每个 3x3 双色对象，确定其最近缺口所在的边框侧颜色 F。
3. 若 F 等于该对象的两种颜色之一：该对象保持原样（颜色互换被门控抑制）。
4. 若 F 与该对象的两种颜色均不同：执行颜色互换——对象内原来为颜色 A 的像素变为颜色 B，原来为颜色 B 的像素变为颜色 A。
5. 边框（含已修复的缺口）和灰色角像素保持不变。

**关键洞察**：边框侧颜色充当"免疫标记"——当缺口填充色与对象的某一组成色匹配时，互换操作被阻止。求解者需同时理解：(a) 缺口属于哪条边决定填充色，(b) 每个对象的最近缺口在哪，(c) 填充色与对象色的匹配关系决定是否互换。三者构成不可拆分的推理闭环。

## 新题 6：分区格内图案补全后按剩余面积涂色

**组合逻辑**：[补全/completion](创新：模板图案从完整单元格推断，应用到其他单元格中的部分副本) + [计数/counting] + [重涂色/recolor](创新：重涂色由单元格的"拥挤度"——剩余背景面积——决定，而非颜色图例)

**来源原语**：补全、对称图案、模板精灵体、形状匹配、完整图案推断缺失（72322fa7）；计数、封闭区域、分隔线、面积比较、极值区域分别涂色（6455b5f5）；重涂色（ddf7fa4f 等）

**依赖链**：补全操作向每个单元格写入图案像素 → 这改变了单元格的剩余背景面积 → 面积极值决定壳层重涂色。若不补全，无法计算正确的剩余面积；若不比较面积，所有图案颜色相同；补全输出实质性改变了后续面积比较的输入。

在分隔线划分的网格中，一个单元格含有完整的对称图案作为模板，其余单元格含有该图案的不完整副本（仅中心或仅壳层）。补全所有不完整副本后，按每个单元格的剩余黑色面积（反映"拥挤度"）对图案壳层执行极值涂色。

**输入结构**：
- 网格约 13x13，黑(0)背景
- 品红(6)分隔线（一像素宽完整直线）将网格分为 3x3 共 9 个矩形单元格，单元格面积不全相同（行高或列宽有差异，至少 3 种不同单元格面积）
- 一个单元格内有一个完整的 3x3 对称图案：中心像素为红(2)，围绕中心的十字位置（上/下/左/右各一像素，共 4 像素）为蓝(1)，构成"十字壳层"图案。此单元格称为模板单元格
- 其余 8 个单元格中有 4~6 个含有不完整副本：某些仅有红(2)中心像素无壳层，某些仅有蓝(1)十字壳层无中心，某些为空（无图案像素）。空单元格不参与补全
- 生成约束：所有含不完整副本的单元格空间足以容纳完整 3x3 图案（单元格宽高均不小于 3）；补全后各含图案单元格的剩余黑色面积互不相同

**规则**：
1. 识别模板单元格中的完整图案：中心色 = 红(2)，壳层色 = 蓝(1)，壳层偏移 = 上下左右各 1 格（十字形）。
2. 对每个含不完整副本的单元格执行补全：
   - 若仅有红(2)中心像素：在其上/下/左/右四个相邻位置补上蓝(1)像素（前提是该位置为黑(0)且在单元格内）。
   - 若仅有蓝(1)十字壳层（4 像素）：在壳层几何中心补上红(2)像素。
3. 补全后，计算每个含图案的单元格的"剩余黑色面积"= 单元格内黑(0)像素总数（即单元格面积减去图案占据的 5 像素和分隔线像素后的值）。
4. 剩余面积最小的单元格（最拥挤）→ 将其图案壳层蓝(1)重涂为青(8)，中心红(2)不变。
5. 剩余面积最大的单元格（最宽敞）→ 将其图案壳层蓝(1)重涂为橙(7)，中心红(2)不变。
6. 其余含图案单元格的壳层保持蓝(1)不变。模板单元格也参与面积比较（它可能是最拥挤或最宽敞的）。
7. 空单元格（无图案像素的单元格）保持全黑。分隔线保持品红(6)。

**关键洞察**：同一个图案模板被复制到大小不同的单元格中，图案本身占据相同的 5 像素，但单元格面积不同导致"拥挤度"不同。拥挤度——一个仅在补全之后才可计算的涌现量——决定了壳层的最终颜色。图案补全和面积比较相互依赖：不补全就无法计算面积差异，不比较面积就无法区分涂色。

## 新题 7：水平镜像复制后列头驱动异色重涂

**组合逻辑**：[平移/translate](创新：镜像位置用于产生对称副本，而非替换原件) + [重涂色/recolor](创新：涂色由控制像素列范围包含关系决定，原件和副本因位于不同列而获得不同颜色) — 汇合结构，镜像定位与列头读取独立进行后在涂色步骤汇合

**来源原语**：平移、精灵体、镜像位置、内部朝向不变（8ee62060）；重涂色、控制像素、单色矩形、列范围包含、控制色决定填色（ddf7fa4f）

**依赖链**：镜像操作决定副本的列位置 → 列头控制像素根据列位置分配颜色 → 原件和副本位于不同列带因此获得不同颜色。镜像不只是复制——它改变了后续涂色的空间语境；列头不只是标签——它们必须在镜像完成后才能正确应用。

将灰色精灵体水平镜像复制到对称位置，保留原件，然后根据顶行控制像素的列覆盖关系分别为原件和副本重涂色——由于二者位于对称的不同列，它们从不同的控制像素获取颜色，产生非对称的彩色输出。

**输入结构**：
- 黑(0)背景网格，约 11x11
- 顶行（第 0 行）有 3~5 个彩色控制像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，各控制像素列坐标不同
- 第 1 行及以下区域有 2~4 个灰(5)精灵体，每个精灵体是 2x2 的 4-连通区块（可含 1 个黑色内部像素，即 2x2 边界框内有 3~4 个灰像素），所有精灵体位于网格左半部分（列坐标 < grid_width/2）
- 网格右半部分对应的镜像位置上无前景像素（全为黑色背景）
- 每个精灵体的列范围内（原始位置的边界框列范围）恰好有一个控制像素；每个精灵体的镜像位置的列范围内也恰好有一个控制像素（可以与原始位置的控制像素不同）
- 生成约束：所有精灵体的原始位置和镜像位置互不重叠；原始位置和镜像位置的列范围各自恰好覆盖一个控制像素

**规则**：
1. 对每个灰(5)精灵体，计算其水平镜像位置：新列起始 = grid_width - sprite_width - 原始列起始（与 8ee62060 相同公式）。在镜像位置绘制该精灵体的副本，保持内部像素布局不变（不翻转精灵体本身）。
2. 原始灰色精灵体保留在原位。
3. 对每个精灵体（原件和副本分别处理）：
   a. 确定其边界框的列范围。
   b. 找到顶行中列坐标落在该列范围内的唯一控制像素，取其颜色 C。
   c. 将该精灵体的所有灰(5)像素替换为颜色 C。
4. 顶行控制像素和黑色背景保持不变。

**关键洞察**：同一个源精灵体产生的原件和副本在结构上完全相同（形状和朝向都保持），但由于它们处于网格的对称两侧，列头控制像素不同，因此获得不同的颜色。镜像操作本身不改变颜色，但它改变了空间位置，而空间位置决定了涂色。这种"位置决定身份"的逻辑需要对比多个示例才能归纳——仅看一个示例可能误以为副本总是某个固定颜色。
