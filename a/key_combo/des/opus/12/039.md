## 新题 1：嵌套深度编码载荷位移量

**组合逻辑**：[计数(counting)](创新：嵌套层数作为位移参数) + [循环位移(cyclic_roll)](已有) + [层序反转(layer_order_reversal)](已有) — 嵌套结构既是参数编码器又是变换目标

**来源原语**：计数(counting) ← 1190e5a7；循环位移(cyclic_roll) ← 79cce52d；层序反转(layer_order_reversal) ← 8dae5dfc；嵌套矩形层(nested_rect_layer) ← 8dae5dfc；控制列(control_column) ← 79cce52d；双轴偏移编码(dual_axis_offset) ← 79cce52d

**依赖链**：嵌套结构的层数 → 水平位移量；控制列中标记的行位置 → 垂直位移量；嵌套结构自身同时经历层序反转。位移量的推断和层序反转共享同一输入结构但产生不同输出，两者必须同时正确才能得到完整解。

将嵌套矩形的颜色层数作为载荷的水平循环位移量，控制列标记位置作为垂直位移量，同时反转嵌套结构自身的颜色层序。

**输入结构**：约 15x15 的网格。左半部分包含一个同心嵌套矩形结构（3~5 层不等，每层颜色不同，使用红(2)、蓝(1)、绿(3)、黄(4)等，层与层之间无间隙，最外层紧贴左半区边界）。左半区与右半区之间有一列宽为 1 的灰(5)色分隔列（即控制列），该列中恰好有一个非灰的标记像素（颜色为橙(7)），其余均为灰(5)。右半区为载荷区域，包含一个由多种颜色（与嵌套结构颜色无重叠）组成的非对称图案，占据整个右半区。生成约束：嵌套层数在 3~5 之间；载荷区域宽高均不小于嵌套层数；不同示例中嵌套层数和标记行位置均不同。

**规则**：
1. 识别灰(5)色控制列，将网格分为左侧嵌套区和右侧载荷区。
2. 对嵌套矩形结构逐层剥离（从最外层开始，每次剥去当前外边界的均匀颜色层），统计总层数 N。
3. 读取控制列中橙(7)标记像素的 0-based 行索引 M（从控制列顶部起算）。
4. 移除控制列。
5. 对载荷区域执行循环位移：向右循环移 N 列，向下循环移 M 行。
6. 对嵌套矩形结构执行层序反转：将第 k 层（从外到内编号 0..N-1）的颜色替换为第 (N-1-k) 层的原颜色，即最外层与最内层互换颜色，以此类推。
7. 输出由反转后的嵌套区和位移后的载荷区水平拼接而成（无控制列）。

**关键洞察**：嵌套矩形结构承担双重角色——它的层数是载荷位移的隐式参数，同时自身也是变换的目标。仅看单个示例无法区分层数计数规则与位移量的关系，需要对比不同嵌套深度的示例才能归纳出"层数 = 水平位移量"。

## 新题 2：尾部三重编码驱动格子填充

**组合逻辑**：[洪泛填充(flood_fill)](创新：填充目标由外部尾部向量选定) + [射线延伸(ray_extend)](创新：尾部方向作为射线投射方向) — 尾部向量同时编码方向、奇偶条件和优先级

**来源原语**：洪泛填充(flood_fill) ← 83302e8f；尾部向量(tail_vector) ← c6e1b8da；格子框架(lattice_frame) ← 83302e8f；封闭背景区域(enclosed_bg) ← 83302e8f；奇偶交替(parity_alternation) ← 97999447；尾部指示位移(tail_displacement) ← c6e1b8da

**依赖链**：尾部方向 → 确定目标格子行/列；尾部长度的奇偶性 → 决定填充颜色（矩形本色 vs 灰色）；尾部绝对长度 → 解决多矩形冲突时的优先级。三个信息从同一几何结构中同时解码，缺一不可。

外部带尾矩形的尾部方向指向格子框架中的一行或一列封闭格子，尾部长度的奇偶性决定填充颜色，绝对长度决定冲突优先级。

**输入结构**：约 18x18 的网格，黑(0)背景。中央区域有一个由品红(6)色线条构成的格子框架（类似井字格但可以是 3x3 或 4x4 的格子，线条宽度 1 像素），框架将中央区分为若干封闭的矩形格子单元（每个单元内部为黑(0)背景）。格子框架外侧散布 3~5 个不同颜色的小实心矩形（2x2 或 2x3 像素，颜色为蓝(1)、红(2)、绿(3)、黄(4)等互不相同），每个矩形有一条一像素宽的同色尾部从矩形某一侧沿基数方向向格子框架延伸（尾部长度 2~6 像素，不触及框架）。生成约束：每个矩形的尾部朝向格子框架；不同矩形的尾部行/列坐标对应框架中不同行/列的格子；至少有一对矩形指向有重叠格子的行/列。

**规则**：
1. 对每个带尾矩形，确定尾部延伸方向（上/下/左/右）。
2. 沿尾部方向做射线投射，确定该射线穿过格子框架时对应的格子行（若尾部水平延伸则对应格子所在行）或格子列（若尾部垂直延伸则对应格子所在列）。具体地：射线从尾部末端沿尾部方向延伸至框架内部，经过的所有完整格子单元即为该矩形的目标单元集合。
3. 判断尾部长度（不含矩形本体，仅计尾部像素数）的奇偶性：奇数 → 用该矩形自身颜色填充目标格子单元；偶数 → 用灰(5)填充目标格子单元。
4. 若两个矩形的目标集合存在重叠格子单元，该单元取尾部更长的矩形所决定的颜色。若长度相同，取矩形在输入中距格子框架更近的那个。
5. 从输出中移除所有矩形及其尾部（仅保留格子框架和已填充的格子单元）。未被任何矩形指定的格子单元保持黑(0)。

**关键洞察**：尾部是一个三重编码器——方向选择目标格子、长度奇偶性决定填充色、绝对长度裁决冲突。仅看单个示例可能看到尾部和填充色的关联，但无法确定奇偶规则还是其他数值规则，需要对比不同尾部长度的示例才能归纳。

## 新题 3：精灵体像素数编码旋转后沿视线滑动对接

**组合逻辑**：[旋转(rotate)](创新：旋转量由精灵体自身像素数编码) + [滑动(slide)](已有) — 旋转必须先于滑动执行，因为旋转后的形状决定了对接姿态

**来源原语**：滑动(slide) ← e1d2900e；旋转(rotate) ← 6ffbe589；标记像素(marker_pixel) ← e1d2900e；实心方块(solid_block) ← e1d2900e；提示精灵体(cue_sprite) ← 6ffbe589；视线对齐(sightline_align) ← e1d2900e；同色匹配(same_color_matching) ← 6ffbe589；像素数编码旋转(pixel_count_encodes_rotation) ← 6ffbe589；沿视线移至近块旁(slide_to_nearest_block) ← e1d2900e

**依赖链**：精灵体像素数 → 旋转量 → 旋转后精灵体形状 → 沿视线滑动并贴靠方块。旋转改变了精灵体的空间形态，进而影响滑动后的对接位置和朝向。

将散落的小精灵体先按自身像素数旋转，再沿视线滑动贴靠到同色的 2x2 方块旁。

**输入结构**：约 15x15 的网格，黑(0)背景。包含 3~4 个不同颜色的 2x2 实心方块（颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，每色最多一个方块）。另有 3~4 个小型单色精灵体（4-连通，3~6 像素，形状为非对称的不规则连通体，如 L 形变体、Z 形变体等），每个精灵体的颜色与恰好一个方块相同。每个精灵体与其同色方块之间存在唯一的无遮挡水平或垂直视线（视线路径上无其他非黑像素）。生成约束：不同精灵体的像素数至少有两个不同（以便推断旋转规则）；旋转后精灵体贴靠方块时不会与其他已对接精灵体冲突；至少有一个精灵体像素数为非 4 的倍数（使旋转效果可观察）。

**规则**：
1. 对每个精灵体，统计其像素数 P。
2. 将精灵体以其边界框中心为旋转中心，顺时针旋转 (P mod 4) x 90 度。旋转后像素坐标四舍五入到最近网格位置。若 P mod 4 = 0，不旋转。
3. 找到该精灵体的同色 2x2 方块，确认两者之间的无遮挡视线方向（水平或垂直）。
4. 将旋转后的精灵体沿该视线方向滑动，直到精灵体最近像素紧邻方块边缘（相距 1 像素）。
5. 若某精灵体不存在无遮挡视线（被其他已对接物体阻挡），则该精灵体保持原位不旋转、不移动。
6. 处理顺序：按精灵体与同色方块的曼哈顿距离从小到大处理；距离相同时先处理行号更小的精灵体。

**关键洞察**：精灵体的像素数不只是一个属性——它编码了旋转参数，而旋转必须发生在滑动之前，因为旋转改变了精灵体的形状轮廓，从而影响对接后的最终姿态。需对比不同像素数的精灵体才能发现"像素数 mod 4"的旋转规则。

## 新题 4：恢复遮挡后按遮损比重涂色

**组合逻辑**：[遮挡恢复(occlusion_restore)](已有) + [计数(counting)](创新：计算遮挡比而非绝对面积) + [重涂色(recolor)](创新：遮挡比排名决定新颜色分配) — 恢复后的面积信息反馈到颜色决策

**来源原语**：遮挡恢复(occlusion_restore) ← c6e1b8da；计数(counting) ← 8597cfd7/1190e5a7；重涂色(recolor) ← 83302e8f/f76d97a5；实心矩形(solid_rectangle) ← c6e1b8da；两区域比较(region_comparison) ← 8597cfd7；图层优先级(layer_priority) ← e99362f0

**依赖链**：遮挡恢复 → 获得每个矩形的真实面积 → 计算遮挡像素数与真实面积之比 → 按遮挡比排序 → 用底部色条中对应位置的颜色重涂 → 以原始图层顺序绘制。遮挡比无法在恢复之前计算，色条位置无法在排序之前映射。

先恢复被遮挡的矩形，统计每个矩形的遮挡比例，再按比例排名从底部色条获取新颜色，最后以原始遮挡层序绘制。

**输入结构**：约 14x14 的网格，黑(0)背景。包含 3~4 个不同颜色的实心矩形（颜色为蓝(1)、红(2)、绿(3)、黄(4)等），彼此部分重叠，形成可辨认的遮挡层次关系（上方矩形覆盖下方矩形的部分区域，被遮挡部分的像素在输入中显示为上方矩形的颜色）。网格最底部一行为色条行：包含与矩形数量相同的单像素色块（颜色互不相同，与矩形颜色不重叠，可使用橙(7)、品红(6)、青(8)等），从左到右排列，其余为黑(0)。生成约束：每个矩形至少有一部分未被遮挡（以便识别其颜色和边界框的至少两个角点）；各矩形的遮挡比例互不相同；色条中的颜色数量等于矩形数量。

**规则**：
1. 识别所有实心矩形。对每个矩形，根据其可见像素推断完整边界框，将被遮挡区域恢复为该矩形的颜色，得到每个矩形的完整面积 A。
2. 统计每个矩形在输入中被其他矩形遮挡的像素数 O（即恢复后新增的像素数）。计算遮挡比 R = O / A。
3. 按遮挡比 R 从大到小对矩形排序。遮挡比最大的矩形排第 1，最小的排最末。
4. 读取底部色条行中从左到右的颜色序列。将排名第 k 的矩形重涂为色条中第 k 个颜色（k 从 1 开始）。
5. 移除底部色条行。
6. 按原始遮挡层序（从底层到顶层）逐层绘制重涂后的矩形：先绘制最底层矩形的完整区域，再绘制上方矩形覆盖其上。
7. 输出的网格行数比输入少 1（去掉色条行）。

**关键洞察**：色条的排列顺序不是直接对应矩形的左右位置或颜色编号，而是对应遮挡比排名——被遮挡越严重的矩形获得色条中越靠左的颜色。必须先恢复遮挡才能计算比例，必须计算比例才能确定颜色映射，仅看单个示例难以确定排序依据。

## 新题 5：标记选象限叠加，非标记象限缩微嵌入

**组合逻辑**：[裁剪(crop)](已有) + [透明叠加(transparent_overlay)](已有) + [缩小复制(shrink_copy)](创新：非选中象限缩小后嵌入叠加结果中心) — 同一分隔结构驱动全尺寸叠加与缩微嵌入两种不同操作

**来源原语**：裁剪(crop) ← 2dc579da；透明叠加(transparent_overlay) ← e99362f0；缩小复制(shrink_copy) ← 11e1fe23；分隔十字(separator_cross) ← 2dc579da/e99362f0；象限(quadrant) ← e99362f0；标记像素(marker_pixel) ← 2dc579da；图层优先级(layer_priority) ← e99362f0；象限位决定层序(quadrant_layer_order) ← e99362f0

**依赖链**：十字分隔 → 四象限提取；标记像素位置 → 区分主象限与副象限；主象限对齐叠加（层序由象限在网格中的位置决定）→ 得到基底画布；副象限 2:1 缩微 → 嵌入基底画布中心（层序同样由原象限位置决定）。标记选择、叠加、缩微三个操作相互约束。

四象限中标记象限全尺寸叠加为基底，非标记象限缩微后嵌入基底中心，所有层序由象限的原始网格位置决定。

**输入结构**：约 17x17 的网格（奇数边长，使十字恰好居中，每个象限为 8x8）。一条全宽行和一条全高列由品红(6)色组成十字分隔，将网格分为四个 8x8 象限。四个象限各有一种前景色（从蓝(1)、红(2)、绿(3)、黄(4)中选取）在黑(0)背景上组成一个 4-连通图案（4~10 像素的不规则形状）。恰好两个象限中各含一个橙(7)色标记像素（位于该象限图案外部的背景位置上）。生成约束：四个象限的图案颜色互不相同；标记像素所在的两个象限不相邻（即一个在左上/右下，一个在右上/左下，或一个在左上/右下对角等）；每个象限的图案边界框不超过 6x6，确保缩微后（4x4 范围内）不会与全尺寸图案严重冲突。

**规则**：
1. 移除品红(6)十字分隔线，提取四个 8x8 象限。
2. 包含橙(7)标记的两个象限为"主象限"，不含标记的两个为"副象限"。移除所有标记像素（还原为黑(0)背景）。
3. 将两个主象限按本地坐标对齐叠加到一个 8x8 画布上。层序规则：按象限在原网格中的位置编号（左上=0，右上=1，左下=2，右下=3），编号小的先绘制（作为底层），编号大的后绘制（作为顶层，覆盖冲突像素）。
4. 对每个副象限，执行 2:1 缩微：将 8x8 图案缩为 4x4（每 2x2 区域取左上像素值；若左上为背景则取该 2x2 区域中任一非背景像素；若全为背景则为背景）。
5. 将两个缩微副象限放置于叠加画布的中心 4x4 区域（行 2~5、列 2~5）。层序同样按原象限位置编号，编号小的先绘制，编号大的覆盖。缩微图案覆盖在主象限叠加结果之上。
6. 输出 8x8 画布。

**关键洞察**：标记像素不属于图案本身，而是象限的选择信号——有标记的象限提供全尺寸的背景层，无标记的象限被压缩后镶嵌在中心。仅看单个示例难以区分层序规则是由颜色还是由位置决定的，需要对比标记在不同象限组合中的示例。

**组合逻辑**：[擦除(erase)](已有) + [平移(translate)](创新：存活物体按颜色滑向对应边界) + [计数(counting)](已有) — 指示条同时是输入（颜色过滤器）和输出（计数条），形成双向依赖

## 新题 10：灰色掩码从反转镜像嵌套中采样颜色

**组合逻辑**：[擦除(erase)](已有) + [层序反转(layer_order_reversal)](已有) + [镜像(mirror)](已有) + [洪泛填充(flood_fill)](创新：掩码像素按距离从变换后结构中采样颜色) — 层序反转和镜像改变了最近邻关系，掩码采样依赖变换后的空间布局

**来源原语**：擦除(erase) ← f76d97a5；层序反转(layer_order_reversal) ← 8dae5dfc；镜像(mirror) ← b20f7c8b；洪泛填充(flood_fill) ← 83302e8f；掩码像素(mask_pixel) ← f76d97a5；嵌套矩形层(nested_rect_layer) ← 8dae5dfc；前景像素(foreground_pixel) ← f76d97a5；嵌套层次(nesting_hierarchy) ← 8dae5dfc；颜色替换(color_replacement) ← f76d97a5；掩码决定保留(mask_determines_keep) ← f76d97a5；颜色序列逆转(color_sequence_reversed) ← 8dae5dfc

**依赖链**：嵌套结构层序反转 → 颜色重排 → 水平镜像 → 改变空间颜色分布；灰色掩码像素保留位置 → 从反转镜像后的嵌套结构中取最近颜色 → 掩码被重涂。层序反转和镜像必须在掩码采样之前完成，因为它们改变了最近颜色的分布。

嵌套矩形的颜色层序反转并水平镜像后，散布的灰色掩码像素从变换后的结构中按曼哈顿距离采样颜色。

**输入结构**：约 14x14 的网格，黑(0)背景。网格中央偏左有一个嵌套矩形结构（3~4 层同心矩形，由外到内颜色分别为如蓝(1)、红(2)、绿(3)、黄(4)，每层厚度 1~2 像素，最外层边界框约 8x8~10x10）。在嵌套结构外部的网格区域中，散布 5~8 个灰(5)色单像素（掩码像素），位置不规则分布于嵌套结构的上方、右侧和下方。另外还散布 2~4 个与嵌套结构同色的干扰像素（如蓝(1)或红(2)的孤立单像素），位于嵌套结构外部。生成约束：灰色掩码像素的位置使得其最近嵌套像素分布在不同层上（以便展示层序反转对采样的影响）；嵌套结构不在网格正中心（偏左），使得水平镜像产生可观察的位置变化；不同示例中嵌套层数和颜色排列不同。

**规则**：
1. 识别嵌套矩形结构，通过逐层剥离确定层序（从外到内）。
2. 将干扰像素（嵌套结构外部的非黑、非灰像素）擦除为黑(0)。
3. 对嵌套结构执行层序反转：最外层颜色 ↔ 最内层颜色，第二层 ↔ 倒数第二层，以此类推。
4. 对反转后的嵌套结构执行水平镜像（以嵌套结构自身的边界框垂直中轴为镜像轴），镜像后结构仍在其原始边界框位置内。
5. 对每个灰(5)掩码像素，计算它到反转镜像后的嵌套结构中每个非黑像素的曼哈顿距离。取距离最小的像素的颜色。若距离相同，取行号更小的像素；行号也相同则取列号更小的像素。
6. 将灰色掩码像素重涂为步骤 5 中确定的颜色。
7. 输出网格：黑色背景 + 反转镜像后的嵌套结构（在原位置）+ 重涂后的掩码像素（在原位置）。

**关键洞察**：灰色掩码像素是"探针"——它们从变换后（而非原始）嵌套结构中采样颜色。水平镜像改变了哪些嵌套像素距某个掩码最近，层序反转改变了那些像素的颜色——两个变换叠加后，掩码获得的颜色与直觉预期不同。仅看原始输入中掩码与嵌套结构的相对位置无法直接推出掩码颜色，必须先推断出层序反转和镜像两步变换。
