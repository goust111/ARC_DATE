## 新题 1：嵌套环缝隙射线穿透与区域染色

**组合逻辑**：[射线投射/ray_cast](已有) + [反弹/bounce](已有) + [填充/fill](创新：从区域填充改为射线路径决定的区间填充) + [嵌套层次/nesting_hierarchy](创新：从排序依据改为射线传播的拓扑结构) + [颜色继承/color_inheritance](已有)

**来源原语**：射线投射、反弹、颜色继承、碰撞停止 ← 142ca369；方环、嵌套层次 ← eb5a1d5d；填充、内部区域 ← e88171ec

**依赖链**：嵌套环的缝隙位置决定了射线能穿透到哪些层级 → 射线在环壁上的反弹决定了其当前颜色（颜色继承） → 射线经过的封闭区间获得射线当前颜色的填充。三个环节缺一不可：无缝隙则射线无法穿越层级；无反弹则无颜色切换；无填充则无可见输出。

将嵌套环内的发射器像素发出的对角射线沿缝隙穿透多层同心环，每次反弹继承环壁颜色，并以当前颜色填充所经过的环间封闭区域。

**输入结构**：约 15x15 网格，黑(0)背景。2-3 层同心方环（每层一像素厚），各层颜色不同（例如外层红(2)、中层蓝(1)、内层绿(3)）。每层环恰好有一个 1 像素宽的缝隙（缺口），缝隙位置各层不同。最内层环的某一段壁上有一个黄(4)发射器像素。生成约束：缝隙不在环的角上；发射器不在缝隙相邻位置；每对相邻环之间的区域至少 2 像素宽。

**规则**：
1. 发射器从其位置向外发射一条 45 度对角射线，初始方向为远离环中心的象限方向。
2. 射线前进时，若碰到环壁像素，则按碰撞面法线反弹（碰到水平壁则翻转纵向分量，碰到竖直壁则翻转横向分量，碰到角点则两个分量都翻转），并且射线颜色变为该壁像素的颜色。
3. 若射线到达某层环的缝隙位置（该位置是背景色），射线直接穿过，不反弹，颜色不变。
4. 射线经过的每个封闭环间区域（两层相邻环之间的空间）被标记为"已访问"。射线离开该区域后，将该区域中所有背景像素填充为射线进入该区域时的颜色（即射线在最近一次反弹后获得的颜色）。
5. 射线到达网格边界时终止。最外层环与网格边界之间的区域，若被射线经过，同样填充。
6. 未被射线经过的环间区域保持黑(0)。
7. 所有环壁像素和发射器像素保持不变。

**关键洞察**：缝隙的位置决定了射线能到达哪些环间区域，而射线在每次反弹时继承的壁色决定了每个被访问区域的填充颜色——同一条射线在不同层级可能携带不同颜色，因此相邻区域可能被填充为不同的颜色。需要对比多个示例才能确认"穿过缝隙不变色、碰壁才变色"这一规则。

## 新题 2：控制矩阵编码滑动方向与障碍接触变色

**组合逻辑**：[索引映射/index_mapping](创新：映射目标从颜色改为运动方向) + [滑动/sliding](已有) + [重涂色/recolor](创新：触发条件从控制矩阵改为障碍接触) + [接触停止/contact_stop](已有)

**来源原语**：索引映射、控制矩阵、行列位置对应、重涂色 ← 33b52de3；滑动、方向 ← 25ff71a9；条形障碍、接触停止 ← 56dc2b01

**依赖链**：控制矩阵的颜色决定每个精灵体的滑动方向 → 滑动路径上的障碍决定精灵体在何处停止 → 是否接触到障碍决定精灵体是否变色以及变为什么颜色。三个环节相互依赖：方向错误则停止位置错误；停止位置错误则接触关系错误；接触关系错误则最终颜色错误。

用控制矩阵为格点上的精灵体分配滑动方向，精灵体沿指定方向滑动直到碰到障碍条或网格边缘，碰到障碍条的精灵体被重涂为障碍条的颜色。

**输入结构**：约 15x15 网格，黑(0)背景。左上角有一个 3x3 控制矩阵，每格填充一种颜色（红(2)、蓝(1)、绿(3)、黄(4)或黑(0)）。网格右下方区域内，9 个单像素精灵体按 3x3 格点排列（等间距，间距约 3-4 格），每个精灵体颜色各不相同（从橙(7)、灰(5)、品红(6)、栗(9)、青(8)中选取）。格点之间散布若干短障碍条（水平或竖直的 2-3 像素线段），障碍条颜色为红(2)、蓝(1)或绿(3)。生成约束：每个精灵体沿其分配方向的路径上最多遇到一个障碍条；控制矩阵中至少有一个黑(0)（不移动）和至少三种不同的方向色。

**规则**：
1. 控制矩阵第 r 行第 c 列的颜色映射到格点中第 r 行第 c 列的精灵体（行列位置对应）。
2. 颜色编码滑动方向：红(2)=向下，蓝(1)=向右，绿(3)=向上，黄(4)=向左，黑(0)=不移动。
3. 每个精灵体沿分配的方向逐像素滑动，直到其下一步将进入一个障碍条像素或超出网格边界时停止。
4. 各精灵体独立处理（互不阻挡，可穿越彼此的起始位置）。
5. 若精灵体停止时与某障碍条相邻（即停止原因是障碍条），则将该精灵体重涂为该障碍条的颜色。
6. 若精灵体停止在网格边缘（未接触任何障碍条），则保持原色不变。
7. 输出时擦除控制矩阵（其所在区域变为黑(0)），障碍条保持不变。

**关键洞察**：控制矩阵在源题中用于重涂颜色，但在本题中它编码的是运动方向——精灵体的最终颜色不由控制矩阵直接决定，而是由运动路径上是否遇到障碍条间接决定。需要对比多个示例才能归纳出颜色→方向的编码规则以及"碰障碍才变色"的条件。

## 新题 3：字形解码射线模式与中心方块辐射

**组合逻辑**：[解码/decode](创新：解码目标从颜色映射改为射线发射模式) + [射线延伸/ray_extension](已有) + [位置映射/positional_mapping](创新：从行序映射改为相对空间位置映射射线起点)

**来源原语**：解码、字形图案、位置映射 ← 995c5fa3；射线延伸、实心正方形、障碍像素、遇障碍截断 ← 212895b5；裁剪 ← 995c5fa3

**依赖链**：字形中灰色像素的数量决定射线发射模式 → 字形相对于中心方块的空间位置决定射线起点和大致方向 → 障碍像素决定每条射线的终止位置。三个环节紧耦合：不解码则不知道发射几条射线；不定位字形则不知道从哪里发射；无障碍则射线长度无约束。

将中心方块四侧的字形图案解码为射线发射模式，从方块对应边缘发射相应模式的射线，射线遇障碍像素截断。

**输入结构**：约 18x18 网格，黑(0)背景。网格中心有一个实心 3x3 方块，单色（例如蓝(1)）。靠近网格四边（上、下、左、右）各有一个 3x3 字形块，由灰(5)和黑(0)像素组成，每个字形块与方块之间至少隔 3 行/列。网格中散布若干橙(7)障碍像素（单像素点）。生成约束：每个字形块的灰像素数在 1-7 之间；四个字形块的灰像素数 mod 4 的结果至少覆盖两种不同值；障碍像素不与方块或字形块相邻。

**规则**：
1. 对每个字形块，计算其灰(5)像素数量 P，令 ray_type = P mod 4。
2. 射线模式解码：ray_type=0 表示不发射任何射线；ray_type=1 表示发射一条沿对应方位的基本方向射线（从方块对应边中心向外的正交方向）；ray_type=2 表示发射两条对角射线（从方块对应边中心向外的两个 45 度方向散开）；ray_type=3 表示发射三条射线（一条正交 + 两条对角）。
3. 每个字形块的位置决定射线起点：上方字形 → 射线从方块顶边中心像素出发向上方区域发射；右方字形 → 从方块右边中心像素出发向右方区域发射；下方字形 → 从方块底边中心像素出发向下方区域发射；左方字形 → 从方块左边中心像素出发向左方区域发射。
4. 所有射线以方块的颜色（蓝(1)）绘制，逐像素延伸直到碰到橙(7)障碍像素或网格边界时停止（不覆盖障碍像素）。
5. 输出时擦除所有字形块（其像素变为黑(0)），方块和障碍像素保持不变。

**关键洞察**：字形在源题中编码颜色序列，但此处编码的是几何发射模式——灰像素数量不是查表索引，而是对射线数量和方向的数值编码。需要对比多个示例才能区分"不发射""单射线""双对角""三射线"四种模式及其与灰像素数的模运算关系。

## 新题 4：缺损像素计数参数化阶梯扩展步长

**组合逻辑**：[差异提取/difference_extraction](已有) + [阶梯扩展/stepped_expansion](创新：步长不由条高决定，而由外部计算结果决定) + [跨色重叠变色/cross_color_overlap_recolor](已有)

**来源原语**：差异提取、前景图案、缺损副本、对齐比较 ← 2037f2c7；阶梯扩展、竖直条对、周期性步长、跨色重叠变色 ← 58e15b12

**依赖链**：两个图案的对齐比较提取出缺损像素集合 → 缺损像素的数量成为阶梯扩展的步长参数 → 步长参数决定了条对扩展的换列周期 → 不同色条对的扩展交叉处触发变色。前半段（差异提取）的数值输出直接驱动后半段（阶梯扩展）的几何行为，删掉差异提取则步长无从得知。

比较两个对齐图案提取缺损像素数，该数值作为下方竖直条对阶梯扩展的周期步长，不同色扩展重叠处变为品红色。

**输入结构**：约 20x25 网格，黑(0)背景。上半区域（约占 7 行）：两个相同大小的多色图案（bbox 约 5x5，使用红(2)和绿(3)等 2-3 种前景色）水平并列，间隔 2-3 列黑色。左侧图案完整；右侧图案是其缺损副本，有 N 个前景像素被替换为黑(0)（N 在 2-5 之间）。下半区域（约占 15 行）：2-3 对竖直条对，每对由同色的两根竖直条组成（每根条高 2-4 像素），各对颜色不同（例如蓝(1)对、黄(4)对、灰(5)对），条对之间水平间距足够，各对的两根条左右对称分布。生成约束：下半区域条对的行区间互不重叠；各对两条之间间隔至少 4 列。

**规则**：
1. 将两个图案的 bbox 左上角对齐，逐像素比较。在完整图案中为前景色而在缺损副本中为黑(0)的像素即为缺损像素。计算缺损像素总数 N。
2. N 成为所有竖直条对阶梯扩展的步长：每对竖直条从其原始行区间向上和向下延伸；在原始行区间内，左条和右条保持原始列位置不变。
3. 超出原始行区间后，每经过 N 行，左条向左偏移一列，右条向右偏移一列。即：距离原始区间边界 1 到 N 行时偏移 1 列，N+1 到 2N 行时偏移 2 列，以此类推。
4. 扩展像素使用其所属条对的颜色绘制。超出网格边界的部分舍弃。
5. 若两个不同色条对的扩展像素落在同一格，则该格重涂为品红(6)。
6. 上半区域的两个图案在输出中被擦除（变为黑(0)）。

**关键洞察**：上半区域的图案比较本身不产生可见输出——它是一个纯计算步骤，其结果（缺损像素数）作为隐藏参数传递给下半区域的几何操作。求解者必须先发现"两个图案有差异"，再发现"差异数量=步长"，这种跨区域的参数传递需要对比多个示例才能归纳。

## 新题 5：对称性筛选印章模板后控制矩阵逐位重涂

**组合逻辑**：[筛选/filter](已有) + [印章覆盖/stamp_overlay](已有) + [索引映射/index_mapping + 重涂色/recolor](已有) + [对称性筛选目标/symmetry_filter](创新：从筛选输出改为筛选印章模板) + [自身为模板/self_as_stencil](已有)

**来源原语**：筛选、精灵体、干扰体、对称性筛选目标 ← 72ca375d；印章覆盖、自身为模板、非背景处印章 ← 007bbfb7；索引映射、控制矩阵、行列位置对应、按控制色重涂 ← 33b52de3

**依赖链**：对称性筛选决定哪个精灵体成为印章模板 → 模板的自身几何决定印章展开后的格点布局 → 控制矩阵按位置对应关系为每个格点副本分配颜色。筛选错误则模板错误，模板错误则格点布局错误，布局错误则控制矩阵无法正确映射。

从多个精灵体中筛选出具有反射对称性的那一个作为印章模板，将其自身展开为格点矩阵，再用控制矩阵按位置对应关系为每个格点副本重涂颜色。

**输入结构**：约 20x20 网格，黑(0)背景。左半区：3-4 个小型单色精灵体（各 3x3 或 4x4 bbox，4-7 像素），颜色各不同（例如红(2)、蓝(1)、绿(3)、黄(4)），彼此间隔至少 2 像素。其中恰好一个具有水平或竖直反射对称性，其余为非对称干扰体。右半区：一个控制矩阵，其行列尺寸与对称精灵体的 bbox 尺寸相同，矩阵中在对称精灵体非背景像素对应位置填充颜色（从橙(7)、灰(5)、品红(6)、栗(9)、青(8)中选取），在对称精灵体背景像素对应位置为黑(0)。生成约束：对称精灵体的非背景像素数 K 在 4-6 之间；控制矩阵中恰好有 K 个非黑色格，颜色至少两种不同。

**规则**：
1. 对每个精灵体裁剪到其 bbox，测试水平反射和竖直反射对称性。保留唯一具有某种反射对称性的精灵体作为印章模板，丢弃其余干扰体。
2. 将印章模板作为自身模板（self_as_stencil）进行展开：创建一个 (H x H) 行 (W x W) 列的输出网格（H、W 为模板 bbox 的高和宽）。将输出划分为 H x W 个大小为 H x W 的块，每个块对应模板中的一个像素位置。
3. 对于模板中每个非背景像素位置 (r, c)，在输出网格对应的块中粘贴整个模板的图案。对于模板中背景像素位置对应的块，保持全黑。
4. 对每个已粘贴的模板副本，将其所有前景像素重涂为控制矩阵中相同位置 (r, c) 的颜色。
5. 左半区的所有精灵体和右半区的控制矩阵在输出中被擦除。输出仅包含展开后的重涂格点矩阵。

**关键洞察**：对称性在源题中用于识别输出目标，但此处它选择的是印章操作的模板——模板的形状进而决定了格点的拓扑结构，而控制矩阵的映射依赖于这个拓扑结构。三个操作形成一条信息链：对称性→模板形状→格点布局→颜色分配。

## 新题 6：括号框内宽排序压缩为嵌套方环

**组合逻辑**：[裁剪/crop](已有) + [排序/sorting](创新：排序依据从面积/嵌套层级改为容器几何属性) + [压缩/compress](已有) + [括号框/bracket_frame](创新：从源/目标通道改为排序度量的容器)

**来源原语**：括号框、可移动对象、通道对齐 ← df9fd884；裁剪 ← df9fd884, 72ca375d；排序、压缩、方环、嵌套层次、面积序映射环 ← eb5a1d5d

**依赖链**：括号框的内宽几何属性提供排序键 → 排序决定精灵体在嵌套环中的层级 → 精灵体的颜色（而非括号框的颜色）填充到对应层级的环。括号框不出现在输出中，但其几何属性决定了输出结构。

测量多个括号框的内部宽度，按宽度排序其中包含的精灵体，将排序后的精灵体颜色序列压缩为同心方环。

**输入结构**：约 15x18 网格，黑(0)背景。水平排列 3-5 个 U 形括号框（开口朝上），每个括号框一像素厚，各括号框颜色相同（例如均为灰(5)）。各括号框的内部宽度互不相同（例如 3、5、7、9 列）。每个括号框内部底边上放置一个小型单色精灵体（4-连通，3-6 像素），精灵体颜色各不相同（例如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)）。括号框之间水平间隔至少 2 列。生成约束：精灵体不接触括号框壁（与壁至少隔 1 像素）；各括号框高度相同。

**规则**：
1. 识别所有 U 形括号框，测量每个括号框的内部宽度（左内壁与右内壁之间的背景列数）。
2. 从每个括号框内部裁剪出精灵体（裁剪到精灵体自身 bbox）。
3. 按括号框内部宽度从大到小排序精灵体。
4. 设排序后共 N 个精灵体，创建 (2N-1) x (2N-1) 的输出网格。
5. 从外到内填充同心方环：最外一圈（整个输出边框）填充排序第一（最宽括号框中）精灵体的颜色；向内缩进一像素的环填充排序第二的颜色；以此类推，直到中心单像素填充排序最后（最窄括号框中）精灵体的颜色。
6. 输出中不包含括号框和原始精灵体的形状信息——仅保留颜色序列。

**关键洞察**：括号框在源题中是定义源/目标通道的结构，但此处它是一个几何量尺——内宽值决定排序位次。精灵体的形状在压缩过程中被完全丢弃，只有颜色被保留到方环中，而颜色的层级由容器的宽度决定。需要对比多个示例才能确认排序键是括号框内宽而非精灵体面积或括号框总宽。

## 新题 7：边框近侧色重涂后包围框包含擦除

**组合逻辑**：[重涂色/recolor](创新：触发条件从缺口朝向改为最近边距离) + [擦除/erase](已有) + [包围框包含/bbox_containment](创新：在重涂之后执行，使颜色成为擦除的判断条件之一)

**来源原语**：矩形边框、朝向对应边色、重涂色 ← 5b37cb25；连通分量、包围框、包围框包含、擦除、异色包含则删 ← 9720b24f；填充、内部区域、保留边框填内部 ← e88171ec

**依赖链**：每个灰色对象到四边的距离决定其重涂颜色 → 重涂后的颜色决定哪些包含对是"异色"的 → 异色包含关系触发小对象擦除。重涂步骤的结果直接改变擦除步骤的判断条件：两个靠近同一边的对象重涂后同色，即使有包含关系也不会被擦除；而靠近不同边的对象可能触发擦除。

将矩形边框内部的灰色对象按最近边距离重涂为对应边色，然后检查重涂后的异色包围框包含关系，被异色大对象包围的小对象被擦除。

**输入结构**：约 18x18 网格，黑(0)背景。外圈是一个一像素厚的矩形边框，四边颜色各异：顶边红(2)、右边蓝(1)、底边绿(3)、左边黄(4)。四个角像素为黑(0)。边框内部有 5-8 个灰(5)的 4-连通对象，每个 3-8 像素，形状各异（非矩形的不规则连通区域）。对象分布在边框内不同位置：有的靠近某一边，有的靠近中心。部分对象之间存在包围框包含关系（一个对象的 bbox 完全在另一个对象的 bbox 内部）。生成约束：至少有一对包含关系中的两个对象分别最近于不同的边（异色包含）；至少有一对包含关系中的两个对象最近于同一边（同色包含，不触发擦除）。

**规则**：
1. 对每个灰(5)对象，计算其所有像素到边框四边的最小切比雪夫距离。确定距离最小的那一边。
2. 将该对象的所有像素重涂为最近边的颜色。平局时按固定优先级打破：顶(红) > 右(蓝) > 底(绿) > 左(黄)。
3. 重涂完成后，检查所有对象对之间的 bbox 包含关系。若较小对象的 bbox 完全在较大对象的 bbox 内部，且两者颜色不同（异色），则擦除较小对象（将其像素恢复为黑(0)）。
4. 若两个具有 bbox 包含关系的对象重涂后颜色相同（同色），则不触发擦除，两者都保留。
5. 边框本身保持不变。

**关键洞察**：重涂和擦除之间存在非线性耦合——对象的空间位置通过"最近边"机制转换为颜色，而颜色又成为擦除决策的输入。两个 bbox 有包含关系的对象，如果恰好都靠近同一边框边（同色），则小对象存活；如果靠近不同边（异色），则小对象被擦除。求解者需要先推断近边重涂规则，再推断重涂后的包含擦除规则，两步的结果不可从单个示例中同时确定。

## 新题 8：最小间距连线兼编码像素放大倍率

**组合逻辑**：[连线/connect + 填充/fill](已有) + [像素放大/pixel_upscale](已有) + [最小间距对触发/min_gap_triggered](创新：间距值不仅触发连线，还编码放大系数)

**来源原语**：连线、填充、对称标记对、间隔段、中轴对称、最小间距对触发 ← 5ad8a7c0；像素放大、整幅网格、均匀整数倍缩放 ← 60c09cac

**依赖链**：最小间距值同时承载两个功能——它触发哪一对标记被连线，并且该数值加一等于像素放大倍率 → 连线修改了网格内容 → 修改后的网格被整体放大。间距值是一个"双用"参数：删掉连线操作则网格图案不对；删掉放大操作则输出尺寸不对；不计算间距则两者都无法执行。

找到间距最小的镜像标记对并连线，然后以该间距值加一为倍率对整个网格进行像素放大。

**输入结构**：约 7x7 或 8x8 网格，黑(0)背景。使用单一前景色（例如红(2)）。4-6 行各含有一对镜像标记像素（两个前景像素关于网格竖直中轴对称），不同行的两标记之间的水平间距不同（间距值范围 1-4，即两标记之间的空背景像素数）。部分行可以没有标记。生成约束：恰好一行具有唯一最小间距；最小间距 G 为 1、2 或 3（保证放大后输出不超过 30x30）；网格宽度为奇数（确保存在唯一中轴）。

**规则**：
1. 对每个含有镜像标记对的行，计算两标记之间的水平间距 G（两标记之间的背景像素数）。
2. 找到间距最小的那一行。将该行两标记之间的所有背景像素填充为前景色（连线）。
3. 其他行的标记对不做连线处理。
4. 计算放大倍率 S = G + 1（其中 G 是步骤 2 中的最小间距值）。
5. 将整个网格（连线后的版本）进行 S 倍像素放大：每个像素替换为 S x S 的同色块。输出尺寸为原始高度 x S 行、原始宽度 x S 列。

**关键洞察**：最小间距 G 同时扮演两个角色——作为连线触发条件（选择哪一行被连线）和作为放大参数（G+1 倍缩放）。这是一种"同一测量值的双重用途"模式，求解者需要对比多个示例才能发现间距值与放大倍率之间的 +1 关系。

## 新题 9：对称补全揭示隐藏图案后按提示精灵体旋转色层

**组合逻辑**：[对称补全/symmetry_completion](已有) + [旋转/rotate](已有) + [同色匹配/same_color_matching](已有) + [像素数编码旋转/pixel_count_encodes_rotation](已有) + [裁剪/crop](已有)——但组合方式全新：补全的输出成为旋转的输入，源题中两套逻辑独立运作

**来源原语**：对称补全、对称图案、标记矩形、双轴反射对称、标记遮挡区域 ← 0934a4d8；旋转、色层、提示精灵体、同色匹配、像素数编码旋转 ← 6ffbe589；裁剪 ← 0934a4d8, 6ffbe589

**依赖链**：对称补全恢复被标记矩形遮挡的像素 → 恢复后的完整图案被分解为色层 → 每个提示精灵体的像素数编码对应色层的旋转角度 → 旋转后的色层重新合成。对称补全和色层旋转之间有实质依赖：被遮挡区域的像素可能属于需要旋转的色层，不先补全就无法正确旋转。

先用双轴对称恢复被标记矩形遮挡的像素，再根据外部提示精灵体的像素数对匹配色层执行旋转，输出合成后的裁剪图案。

**输入结构**：约 15x15 网格，黑(0)背景。网格中央区域有一个多色图案（使用 2-3 种前景色，例如红(2)、蓝(1)、绿(3)），该图案具有双轴反射对称性（水平+竖直）。图案中有一个实心单色矩形块（例如橙(7)，3x4 或 4x3）覆盖了部分图案像素（标记矩形）。在图案 bbox 外部，有 1-2 个小型单色提示精灵体（每个 2-5 像素的 4-连通区域），其颜色与图案中某个前景色相同。生成约束：标记矩形不完全覆盖任何一个色层（每个色层在标记外至少有足够像素体现对称性）；提示精灵体的颜色互不相同且均出现在图案中；至少有一种图案前景色没有对应的提示精灵体（该色层不旋转）。

**规则**：
1. 识别标记矩形：找到唯一一种颜色，其所有像素构成一个实心矩形。该矩形下方覆盖的是被遮挡的图案像素。
2. 利用图案的双轴反射对称性恢复标记矩形下的每个像素：对于标记中的像素 (r, c)，在其水平镜像位置 (r, c') 或竖直镜像位置 (r', c) 寻找非标记色的像素，复制其颜色。若两个镜像位置都被标记覆盖，则使用对角镜像位置 (r', c')。
3. 将补全后的图案裁剪到其 bbox（不含标记色），得到中间结果。
4. 对每个提示精灵体，计算其像素数 P，令旋转角度 = (P mod 4) x 90 度顺时针。
5. 在中间结果中，找到与该提示精灵体同色的色层（所有该颜色的像素集合）。将该色层在裁剪 bbox 范围内旋转指定角度（以 bbox 中心为旋转中心）。旋转到 bbox 外的像素丢弃，旋转后空出的位置保持为黑(0)。
6. 没有对应提示精灵体的色层不旋转，保持原位。
7. 将所有色层（旋转后的和未旋转的）合成到黑(0)背景上。若旋转后两个色层在某像素位置重叠，旋转过的色层优先。
8. 输出合成后的裁剪图案。

**关键洞察**：对称补全和色层旋转分属两道不同的参考题，各自独立可解。但组合后产生了新的结构依赖：标记矩形下被遮挡的像素可能恰好属于需要旋转的色层——如果不先补全就旋转，该色层会缺少关键像素导致旋转结果错误。求解者需要先推断对称补全规则，再推断像素数编码旋转规则，两者必须按正确顺序执行。
