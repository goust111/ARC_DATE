## 新题 1：对称修复解锁载体滑动

**组合逻辑**：[对称补全](局部化为逐形状补全，非全局) + [滑动](补全后形状边界变化影响终点) + [颜色决定方向](已有) + [嵌入载体内](已有)

**来源原语**：对称补全、掩码像素、对称轨道映射（参考题 47996f11）；滑动、可移动对象、载体区域、嵌入载体内、颜色决定方向（参考题 9b4c17c4）

**依赖链**：对称补全改变形状的有效边界框（原先被遮蔽的边缘像素被恢复为实色），扩大后的边界框决定了形状在载体内滑动到端点时的最终位置。不完成补全就无法确定真正的形状轮廓，而无法确定轮廓就无法计算滑动终点。

将载体区域内被掩码破坏的小图形先通过局部对称关系修复完整，再按载体颜色指定的方向将完整图形滑动到载体边界。

**输入结构**：约 15x15 网格，黑(0)背景。包含 2-3 个互不相邻的水平条状载体区域，每个载体为单色实心矩形，颜色为蓝(1)或青(8)，宽约 8-12 像素、高 3-5 像素。每个载体内部嵌入一个 4-连通的小图形（3-6 像素，颜色为绿(3)或橙(7)，非载体色非背景色），该图形具有左右反射对称或 180 度旋转对称，但其中 1-2 个像素被品红(6)遮蔽（品红像素替换了原本的实色像素）。品红像素总是位于图形的对称伙伴能覆盖的位置上。不同示例中小图形的具体形状各不相同，但始终满足某种二阶以上对称性。生成约束：每个载体内恰好一个图形；图形距离载体左右边界均至少留有 1 像素空间；品红像素的对称伙伴位置上是非品红实色。

**规则**：
1. 对每个载体内的小图形，从其非品红像素的排布推断该图形的对称类型（左右反射或 180 度旋转）。
2. 对每个品红(6)像素，找到它在该对称类型下的轨道伙伴像素，将品红替换为伙伴的颜色，完成图形修复。
3. 修复后，计算每个图形的新边界框。若图形位于蓝(1)载体内，将整个图形沿水平方向向右滑动，直到图形边界框的右边缘紧贴载体区域的右边缘。若位于青(8)载体内，向左滑动，直到图形边界框的左边缘紧贴载体区域的左边缘。
4. 滑动过程中保持图形形状与行不变；图形原位置的像素恢复为载体颜色。
5. 所有图形同时执行滑动（不存在互相阻挡）。

**关键洞察**：品红遮蔽的像素可能位于图形的边缘，修复后会扩展图形的边界框，从而使滑动终点比未修复时更靠内。不修复就滑动会产生错误的最终位置——两步操作在空间尺度上紧耦合。对称类型（反射还是旋转）须从多个示例中归纳，不由任何显式标志指示。

## 新题 2：非对称检测定位支架扩展

**组合逻辑**：[对称检测](检测结果不是裁剪输出而是坐标输入) + [扩展填充](扩展目标由检测坐标决定) + [标记对齐格子边界](已有)

**来源原语**：对称检测、前景对象、唯一非轴对称、异常值选择（参考题 73ccf9c2）；扩展填充、骨架格子、空心小框、标记像素、标记对齐格子边界、标记跨度决定范围（参考题 97239e3d）

**依赖链**：对称检测的输出不是被裁剪的对象本身，而是该对象在格子坐标系中的行列位置。这组坐标成为扩展填充操作的输入——决定在哪一行和哪一列的格子边界上涂色、在哪些框心中填色。删除检测步骤则无从知道扩展哪一行列；删除扩展步骤则检测结果无处使用。

在支架格子中找到唯一形状不对称的框心图案，沿其所在格子行和列进行支架边界扩展与框心填充。

**输入结构**：约 19x19 网格，黑(0)背景。灰(5)像素构成一个规则的支架格子，由 4x4 排列的空心 3x3 框组成（框的外边缘为灰(5)，框心 1x1 为黑(0)），相邻框之间共享边界行/列。每个框的中心单元格内放置一个 1-3 像素的小图形（颜色为蓝(1)、红(2)、绿(3)、黄(4)中的任意一种，每个框可不同）。这些小图形中，恰好一个在其所占的 1x1（或周围 3x3）局部区域内不具备左右镜像对称性；其余所有图形都是左右对称的。不同示例中，非对称图形位于不同的格子位置，图形形态各异（但始终是 1-3 像素的 4-连通体）。生成约束：恰好一个非对称图形；格子至少 3x3 排列以保证行列扩展可见。

**规则**：
1. 识别支架格子结构，将其分解为格子行和格子列（由灰(5)框边界定义）。
2. 检查每个框中心图形的左右镜像对称性（将图形在其紧凑边界框内做左右翻转，比较翻转前后的前景掩码是否一致）。
3. 找到唯一不对称的图形，记录其所在的格子行索引 R 和格子列索引 C（从 0 开始）。
4. 将第 R 行所有框的灰(5)边界段重涂为红(2)；将第 C 列所有框的灰(5)边界段重涂为红(2)。
5. 在第 R 行与第 C 列交叉处的框（即非对称图形所在的框），将框心填充为红(2)。在第 R 行其余框和第 C 列其余框中，将框心填充为绿(3)。
6. 不在第 R 行也不在第 C 列的框保持不变。

**关键洞察**：非对称图形本身不出现在输出中（它只是一个定位信号）。它的格子坐标驱动了一个完全不同的视觉操作——十字形支架扩展。检测的产物是位置信息而非对象本身，这使两步操作成为不可分割的推理链。交叉框用红(2)填心、非交叉行列框用绿(3)填心这一区分规则需要对比多个示例才能归纳。

## 新题 3：镜像堆叠创建邻接用于选择性擦除

**组合逻辑**：[镜像](作为中间计算手段而非最终目的) + [拼接](创建新空间拓扑) + [擦除](邻接阈值过滤，创新：在合成网格上执行)

**来源原语**：镜像、拼接、画布、翻转副本堆叠拼接（参考题 4c4377d9）；擦除、孤立像素、矩形、邻接、邻接不足则删除、忽略干扰项（参考题 7f4411dc）

**依赖链**：镜像拼接不是最终输出，而是一步空间构造——它在接合缝处为原本孤立的像素创造新的 4-邻居关系。后续的邻接过滤利用这些新关系决定哪些像素存活。没有镜像就没有新邻接；没有过滤则镜像毫无意义。两步在拓扑层面耦合。

将输入网格垂直翻转后堆叠于原网格上方，在合成网格中按邻接支持度擦除孤立像素，保留矩形结构。

**输入结构**：约 10x8 网格，黑(0)背景。网格中有 2-3 个小矩形（2x3 或 3x2，4-连通），颜色为蓝(1)。另有 4-8 个散落的蓝(1)单像素（噪声），这些噪声像素在颜色上与矩形无法区分。部分噪声像素位于网格的顶部两行或底部两行（靠近将要产生接合缝的边缘）。不同示例中矩形的位置、数量和噪声分布各不相同。生成约束：矩形的每个像素至少有 2 个蓝(1) 4-邻居（在原始网格中即满足）；噪声像素在原始网格中最多有 1 个蓝(1) 4-邻居；至少有一个噪声像素位于第 0 行或最后一行。

**规则**：
1. 将输入网格按上下方向垂直翻转，得到镜像副本。
2. 将镜像副本放在原始网格上方，拼接为高度翻倍、宽度不变的合成网格。
3. 在合成网格中，对每个蓝(1)像素计算其蓝(1) 4-邻居数量。
4. 保留拥有 2 个及以上蓝(1) 4-邻居的像素；将少于 2 个的蓝(1)像素擦除为黑(0)。
5. 输出即为过滤后的合成网格。

**关键洞察**：镜像拼接并非装饰性操作——它在接合缝两侧创造新的邻接关系。原始网格中位于第 0 行的噪声像素在合成网格中获得了来自镜像副本的邻居，可能因此从 1 个邻居增加到 2 个而存活；而远离接合缝的噪声像素不获得新邻居仍被擦除。矩形在原始网格中已有充足邻接，镜像后支持度更高。邻接阈值（恰好 2）须从多个示例中归纳——阈值 1 或 3 会产生不同的存活集合。

## 新题 4：循环位移重定位标记后支架扩展

**组合逻辑**：[循环位移](对支架内容做空间重排) + [扩展填充](在重排后的标记位置上执行) + [标记位定位移量](已有) + [标记对齐格子边界](已有)

**来源原语**：循环位移、控制行、控制列、标记像素、双轴偏移编码、标记位定位移量（参考题 79cce52d）；扩展填充、骨架格子、空心小框、标记对齐格子边界、标记跨度决定范围（参考题 97239e3d）

**依赖链**：控制行列编码的位移量决定支架内容的循环平移，平移改变标记像素在格子坐标系中的位置，位置变化又决定扩展填充的目标区域。位移量、标记原位置、扩展结果三者形成不可跳步的推理链。

读取控制边界中的位移量，循环平移支架载荷区域，然后在平移后的标记位置上执行格子对齐的矩形扩展。

**输入结构**：约 17x17 网格。第 0 行为控制行，用灰(5)填充，其中有一个红(2)单像素标记。第 0 列为控制列，用灰(5)填充，其中有一个红(2)单像素标记（控制行和控制列在 (0,0) 交汇为灰(5)）。剩余 16x16 区域为载荷，包含一个 4x4 排列的支架格子：由黄(4)像素构成的空心 3x3 框（相邻框共享边界），框心为黑(0)。在部分框心中有绿(3)或蓝(1)的单像素标记。不同示例中红(2)控制标记的位置不同，绿/蓝标记的分布也不同。生成约束：载荷区域尺寸可被格子单元尺寸整除（如 16=4x4）；控制行中红标记的列位置和控制列中红标记的行位置均在有效范围内（0 到格子列/行数减 1）；每种标记颜色至少出现 2 个以保证扩展为矩形而非点。

**规则**：
1. 读取控制行中红(2)标记的零基列索引（相对于载荷区域），设为水平位移量 S_h。
2. 读取控制列中红(2)标记的零基行索引（相对于载荷区域），设为垂直位移量 S_v。
3. 移除控制行和控制列，保留 16x16 载荷区域。
4. 将载荷区域向右循环平移 S_h 个格子单元宽度（如每个格子单元宽 4 像素，则平移 S_h x 4 像素），向下循环平移 S_v 个格子单元高度。像素越过边界从对侧重入。
5. 平移后，重新识别各框心中标记像素的格子坐标。
6. 对每种标记颜色，找到包含该颜色所有标记的最小格子对齐矩形。沿该矩形的边界涂上对应标记颜色（覆盖黄(4)格子边界段），并将矩形内所有框心填充为该标记颜色。
7. 若两种颜色的扩展矩形边界重叠，后处理的颜色覆盖先处理的。处理顺序：绿(3)先于蓝(1)。

**关键洞察**：循环位移不改变标记像素的集合，但改变它们在格子坐标系中的位置。同样的三个绿色标记，在位移前可能构成 L 形格子矩形，位移后可能排列为一条横线。扩展填充的形状完全取决于位移量——而位移量编码在控制边界中，与标记布局在空间上分离。必须先解码位移、再平移、再扩展，跳过任何一步都无法得到正确答案。

## 新题 5：印章放置后载体滑动与图例双重编码

**组合逻辑**：[图案印章](精灵体放置到占位符位置) + [滑动](方向由载体颜色决定) + [重涂色](由图例映射) + [颜色图例](创新：同时编码目标颜色和载体归属)

**来源原语**：图案印章、框架、占位符、精灵体、颜色图例、编码映射（参考题 edb79dae）；滑动、载体区域、嵌入载体内、颜色决定方向（参考题 9b4c17c4）；重涂色（多源）

**依赖链**：图例提供占位符颜色到输出颜色的映射，同时占位符在框架内的位置决定其所在载体色带，而载体色带又决定滑动方向。三个操作通过图例和空间位置紧耦合：印章确定初始位置→位置确定载体→载体确定方向→方向确定终点→图例确定最终颜色。删除任何一步均无法求解。

在分色带框架内的占位符位置印章精灵体，沿载体色带滑动到边界，再按图例重涂最终颜色。

**输入结构**：约 20x15 网格，黑(0)背景。网格中央有一个灰(5)单像素宽的矩形框架（约 14x10 内部空间）。框架内部被分为上下两个水平色带：上半为蓝(1)区域，下半为青(8)区域，两色带无间隙无重叠。色带内部散布 2-3 个占位符单像素，颜色为红(2)或绿(3)（每种颜色各 1-2 个）。框架外部：每种占位符颜色对应一个小精灵体（3-5 像素的 4-连通不规则形状，颜色与占位符匹配，如红(2)精灵体对应红(2)占位符）。另有图例区域：2-3 个垂直排列的双像素对，每对由上像素（占位符色）和下像素（输出色）组成，如上红(2)下黄(4)表示红色精灵最终涂为黄(4)。不同示例中精灵体形状、占位符位置和图例映射各不相同。生成约束：每个精灵体印章后不超出框架和色带边界；同一色带内的精灵体滑动后互不重叠；图例中的输出颜色与输入中所有已用颜色均不同。

**规则**：
1. 识别灰(5)框架及其内部的蓝(1)/青(8)色带划分。
2. 对每种占位符颜色，在框架外找到同色精灵体。
3. 在每个占位符位置印章对应精灵体（占位符像素作为精灵体左上角对齐点），印章颜色保持占位符色。
4. 确定每个已印章精灵体所在的色带（以精灵体像素的多数所在色带为准）。
5. 若精灵体位于蓝(1)色带，将其整体向右滑动，直到精灵体边界框右边缘紧贴色带右边缘（即框架内壁）。若位于青(8)色带，向左滑动至色带左边缘。
6. 滑动后，按图例将每个精灵体从占位符色重涂为对应的输出色。精灵体原位置恢复为色带底色。
7. 处理顺序：在同一色带内，距色带目标边（蓝带为右边、青带为左边）更远的精灵体先滑动。

**关键洞察**：图例承担双重职责——它既定义了颜色映射（最终涂什么色），又通过占位符颜色间接选择了精灵体形状；而占位符在框架内的垂直位置决定了色带归属和滑动方向。这三者（形状、方向、颜色）的信息来源在空间上完全分离（精灵体在框架外、占位符在色带内、图例在另一角落），必须交叉引用才能求解。图例的双重编码角色需要对比多个示例才能发现。

## 新题 6：双色分裂后象限对应重涂色

## 新题 7：下采样揭示碎片用于精灵体印章补全

**组合逻辑**：[下采样](几何压缩使离散像素塌缩为可识别图案) + [印章覆盖](在压缩网格上执行精灵体补全) + [颜色重叠匹配](已有) + [最大重叠确定位置](已有)

**来源原语**：下采样、分隔行列、奇偶索引分离、保留偶索引交叉（参考题 68b67ca3）；印章覆盖、多色精灵体、部分掩码、颜色重叠匹配、最大重叠确定位置、冲突优先级（参考题 d6542281）

**依赖链**：原始网格中，分隔行列将有效像素隔开，使得部分掩码的各像素在空间上不连续，无法直接识别为精灵体碎片。下采样移除分隔行列后，像素塌缩为紧凑排列，碎片的空间关系才呈现出与精灵体的匹配。下采样是解锁模式识别的前提，而精灵体补全是下采样的唯一目的。

在含分隔行列的稀疏网格中，下采样去除分隔后在紧凑网格上识别精灵体碎片并补全为完整精灵体。

**输入结构**：约 19x19 网格（奇数尺寸，确保偶索引位置为 10x10）。所有奇数索引行和奇数索引列全为黑(0)（分隔行列）。偶数行与偶数列的交叉位置构成 10x10 的有效载荷。载荷中大部分为黑(0)背景，包含一个多色精灵体（由 2-3 种非黑颜色组成，共 6-12 个有效像素，4-连通），以及 1-2 组散落的同色像素（颜色与精灵体中的某种颜色匹配，每组 2-4 个有效像素）。这些散落像素实际上是精灵体的部分副本，但在 19x19 原始网格中因被分隔行列打断而无法直接看出空间对应关系。不同示例中精灵体形态和散落碎片的位置各不相同。生成约束：每组散落像素对应精灵体在某个平移位置的子集，且该平移位置唯一（最大重叠唯一）；精灵体和散落碎片在 10x10 载荷中不重叠；精灵体在载荷中足够远离边缘以保证碎片补全后不越界。

**规则**：
1. 下采样：移除所有奇数索引行和列，保留偶数行与偶数列交叉处的像素，得到 10x10 紧凑网格。
2. 在紧凑网格中，识别多色精灵体（最大的多色 8-连通前景区域）。
3. 对每组散落的同色像素，测试精灵体在所有可能平移位置下的颜色重叠：将精灵体中与散落像素同色的部分逐一对齐，计算散落像素与精灵体像素的精确颜色匹配数。
4. 选取匹配数最大的平移位置（保证唯一）。
5. 在该平移位置印章完整精灵体。若印章位置的某像素已有非背景前景色（来自已有的散落像素），保留原有像素颜色不覆盖。
6. 输出为补全后的 10x10 紧凑网格。

**关键洞察**：在原始 19x19 网格中，散落像素被分隔行列物理隔断，看起来只是随机噪点。只有下采样让它们塌缩到紧凑空间后，它们之间的相对位置才暴露出与精灵体的匹配关系。下采样不是信息丢失，而是信息显现——它是模式识别的先决条件。冲突优先级规则（已有像素优先还是印章优先）需要对比多个示例才能确定。

**来源原语**：裁剪、标记像素、标记对齐指定半区、保留标记半区（参考题 fbf15a0b）；标记、全空行列、空行列涂标记色（参考题 c1d99e64）；重涂色（多源）；邻接（参考题 7f4411dc）

2. 在保留的半区中，将绿(3)标记像素擦除为黑(0)背景。
3. 找到半区中所有完全由黑(0)组成的行和列。
4. 将这些全空行和全空列中的所有像素涂为黄(4)。
5. 对半区中每个蓝(1)像素，检查其 4-邻居中是否有黄(4)像素（即是否与新涂的标记线相邻）。

7. 红(2)像素不受此规则影响，保持原色。
8. 输出为处理后的半区网格。

**关键洞察**：裁剪决定内容→内容决定空行列→空行列决定标记线→标记线决定哪些蓝色像素变红。这条四步级联意味着同一个输入的左半区和右半区会产生完全不同的标记线和重涂色结果。选择哪半区不是随意的——它由绿色标记的位置决定。邻接重涂色规则（蓝变红而非红变蓝、只检查 4-邻接而非 8-邻接）需要对比多个示例才能归纳。

## 新题 9：象限叠加后按标记距离解决冲突

1. 移除灰(5)分隔十字（水平行和垂直列）。
2. 将四个象限对齐叠加为一个象限大小的输出网格。
3. 对于输出网格的每个像素位置：
   - 若四个对应象限像素中只有一个非背景，输出该颜色。

## 新题 10：颜色图例编码对称类型指导定向补全

**组合逻辑**：[对称补全](对称轴方向由外部编码决定而非从形状内部推断) + [编码映射](创新：图例编码对称类型而非颜色) + [颜色图例](已有，但编码内容创新)

**来源原语**：对称补全、对称图案、掩码像素、对称轨道映射、全对称群轨道约束（参考题 47996f11）；颜色图例、编码映射（参考题 edb79dae）

**依赖链**：图例将每个形状的颜色映射到一个对称类型指示色，该指示色编码了应使用左右反射还是上下反射来补全该形状的被遮蔽像素。没有图例就无法确定对称轴方向（形状本身因部分遮蔽而可能兼容两种解释），而没有形状也无从应用对称操作。两者互为必要条件。

按颜色图例指定的对称轴类型（左右或上下），分别对各个部分遮蔽的图案进行对称补全。

**输入结构**：约 14x14 网格，黑(0)背景。网格中有 3-4 个互不相邻的小图案，每个由单一非黑非品红颜色组成（从蓝(1)、红(2)、绿(3)、橙(7)中选取，颜色各不相同），占 4-8 个像素，4-连通。每个图案中有 1-3 个像素被品红(6)遮蔽（品红像素替换了原本的实色像素）。每个图案本身具有某种反射对称性（左右或上下），但因为品红遮蔽了部分像素，仅从可见像素无法唯一确定是左右对称还是上下对称——两种解释都可能在局部成立。网格的一个角落有图例区域：每种图案颜色与一个指示色配对，形成水平双像素对（左为图案色，右为指示色）。指示色为蓝(1)或红(2)。不同示例中图案形态和图例内容不同。生成约束：每个图案在品红被两种对称轴补全后会得到不同的结果（否则图例无意义）；图例中每种图案颜色恰好出现一次；若图案颜色本身就是蓝(1)或红(2)，则图例中该行的指示色不会与图案色相同（避免混淆）。

**规则**：
1. 在网格角落找到图例区域（水平双像素对，左像素为某图案颜色，右像素为蓝(1)或红(2)）。
2. 读取图例：蓝(1)指示色表示该颜色的图案应按左右反射对称补全；红(2)指示色表示应按上下反射对称补全。
3. 对每个图案，根据图例中对应的对称类型：
   - 左右反射：以图案紧凑边界框的垂直中轴为对称轴。对每个品红(6)像素，找到其关于该轴的镜像位置上的像素；若镜像位置是非品红实色，将品红替换为该颜色。
   - 上下反射：以图案紧凑边界框的水平中轴为对称轴。同理执行品红替换。
4. 品红像素的镜像位置保证是非品红实色（由生成约束保证）。
5. 图例本身不出现在输出中（图例区域的像素全部擦除为黑(0)背景）。

**关键洞察**：图例的创新在于它编码的不是颜色映射（输入色→输出色），而是几何操作的参数（对称轴方向）。同一个被遮蔽的图案在左右补全和上下补全下会产生不同的形状——例如品红像素在左上角，左右补全会从右上角复制颜色，上下补全会从左下角复制颜色。没有图例的指引，补全结果是歧义的。图例的编码约定（蓝=左右、红=上下或反之）需要对比多个示例中的补全结果才能反推确定。
