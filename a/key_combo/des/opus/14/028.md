## 新题 1：十字墙壁引力下落

**组合逻辑**：[射线延伸/ray_extend] → [行列交叉/row_column_crossing](创新：交叉点生成障碍物) → [重力下落/gravity_drop](创新：以动态生成的交叉墙为障碍) → [填充/fill]

**来源原语**：射线延伸(45bbe264), 行列交叉(45bbe264), 重力下落(db7260a4), 填充(db7260a4), 异源交叉特殊着色(45bbe264)

**依赖链**：蓝(1)锚点的十字射线在交叉处生成红(2)墙壁像素 → 顶行标记沿自身列重力下落 → 红(2)墙壁像素成为下落的阻挡障碍 → 下落停止位置向下填充标记色至下一个障碍或底边。射线构造阶段的输出直接决定了重力阶段的障碍拓扑，两步不可分割。

从蓝(1)锚点生成十字射线网格，以交叉点作为墙壁，再让顶行彩色标记沿列下落，遇墙停止并向下填色。

**输入结构**：黑(0)背景，约 15x15 网格。顶行（第 0 行）有 2~4 个互不同列的单像素标记，颜色各不相同，取自绿(3)、黄(4)、品红(6)、橙(7)。网格内部散布 2~3 个蓝(1)单像素锚点，各锚点行列互不相同，且不与任何顶行标记同列。生成约束：每个顶行标记的正下方列中至少存在一个由蓝(1)锚点射线交叉产生的红(2)墙壁像素（即至少有两条来自不同蓝锚点的射线在该列相交），以保证每个标记都能被阻挡。

**规则**：
1. 对每个蓝(1)锚点，沿其所在行向左右延伸至网格边界、沿其所在列向上下延伸至网格边界，将经过的所有黑(0)像素涂为蓝(1)。锚点自身保持蓝(1)。
2. 若某个像素同时被两条或更多来自不同蓝(1)锚点的射线覆盖（即不同锚点的行线与列线交叉），则该像素涂为红(2)而非蓝(1)。同一锚点的行线与列线交叉（即锚点自身）不算。
3. 移除每个顶行标记的原始像素。对每个标记，从其原始列的第 1 行开始向下搜索，找到该列中第一个红(2)像素的行号 r_stop。
4. 从 r_stop 行开始（含 r_stop），沿该列继续向下，将所有像素（无论当前颜色）涂为该标记的颜色，直到遇到下一个红(2)像素（不含该像素）或到达网格底边（含底边）。
5. 若某标记列中不存在任何红(2)像素，则将该列从第 1 行到底行全部涂为标记颜色。

**关键洞察**：蓝(1)锚点的十字射线本身不是障碍——只有不同锚点射线的交叉点（红(2)）才充当墙壁；必须先完成整个射线网格的构造并标记所有交叉点，才能判断每个标记的下落停止位置和填充范围。

## 新题 2：封闭面积配对容器填充

**组合逻辑**：[计数/counting](封闭背景区域面积) → [面积匹配/area_matching](创新：面积值与容器宽度配对) → [填充/fill] + [擦除/erase]

**来源原语**：计数(8ba14f53), 封闭背景区域(8ba14f53), 面积匹配(a25697e4), 容器(db7260a4), 填充(db7260a4), 擦除(b9630600)

**依赖链**：计算每个封闭形状内部的黑(0)像素数 → 将该数值与容器内腔宽度进行配对 → 用形状颜色填充匹配的容器内腔 → 擦除原始形状。不计算封闭面积就无法确定配对关系，不配对就无法决定填充目标。

计算封闭形状内部空腔面积，以面积值匹配同宽容器，用形状颜色填充对应容器后擦除原始形状。

**输入结构**：黑(0)背景，约 18x12 网格。上半区（约前 7 行）有 3 个互不相邻的 4-连通单色封闭形状，每个形状由不同颜色绘制（取自红(2)、绿(3)、蓝(1)），像素数在 8~16 范围内，每个形状完全包围若干黑(0)像素（封闭区域面积各不相同，在 1~5 之间）。形状内部的封闭黑(0)像素是指不能通过 4-连通路径经黑(0)像素到达形状边界框外部的黑(0)像素。下半区（约后 5 行）有 3 个灰(5)像素构成的 U 形容器（两条竖直侧壁 + 一条底部横条），每个容器的内腔宽度（两侧壁之间的水平像素数）各不相同，分别等于上半区三个形状的封闭面积值。容器之间水平间隔至少 2 列。生成约束：三个封闭面积值互不相同，三个容器宽度恰好是这三个面积值的某个排列。

**规则**：
1. 对上半区每个封闭形状，计算其内部封闭的黑(0)像素数量（即该形状边界框内、不能通过 4-连通黑(0)路径到达边界框外部的黑(0)像素总数），记为该形状的"封闭面积"。
2. 对下半区每个 U 形容器，测量其内腔宽度（左侧壁右边缘列号 + 1 到右侧壁左边缘列号 - 1 之间的列数）。
3. 将每个形状与内腔宽度等于其封闭面积的容器配对（一一对应）。
4. 对每个配对，将容器内腔中所有黑(0)像素涂为该形状的颜色。内腔范围为：侧壁之间的列、底部横条上方到容器开口顶部的行。
5. 擦除上半区所有封闭形状的像素（恢复为黑(0)）。

**关键洞察**：形状的外观轮廓是干扰信息——决定配对的是形状内部不可见的封闭空腔面积，而非形状本身的像素数或外形；必须通过洪水填充或连通性分析来计算封闭面积。

## 新题 3：游程压缩匹配决定射线方向

**组合逻辑**：[压缩/compress](游程压缩规范化) → [形状匹配/shape_match](创新：匹配结果不用于重涂色，而是决定后续操作参数) → [射线延伸/ray_extend](创新：方向由匹配到的原型颜色编码)

**来源原语**：压缩(bd14c3bf), 形状匹配(bd14c3bf, 2a5f8217), 游程压缩后比较(bd14c3bf), 旋转反射等价(bd14c3bf), 射线延伸(6ffe8f07), 颜色编码方向(f3e62deb), 颜色决定方向(f3e62deb)

**依赖链**：候选体经行列游程压缩后得到规范形状 → 与原型的规范形状进行旋转/反射匹配 → 匹配到的原型颜色编码一个方向 → 候选体从其质心出发沿该方向发射射线。压缩是匹配的前提，匹配结果是射线方向的决定因素，三步环环相扣。

将拉伸变形的灰(5)候选体压缩后与彩色原型匹配，匹配到的原型颜色编码方向，候选体从质心沿该方向射出射线。

**输入结构**：黑(0)背景，约 20x20 网格。左上角 6x6 区域内有 4 个互不相邻的小型原型对象（每个 2~4 像素的 4-连通图形），颜色分别为绿(3)、黄(4)、品红(6)、青(8)，代表左、下、上、右四个方向。网格其余区域散布 4~6 个灰(5)候选对象，每个是某个原型的"拉伸版"——沿行方向或列方向重复了若干相邻行/列，使得候选体的原始像素布局被放大，但拉伸倍数和方向因候选体而异（像素数在 6~20 范围）。不同候选体可能对应同一个原型。生成约束：每个候选体压缩后的规范形状恰好与某个原型（允许旋转/反射）匹配，且匹配唯一；所有候选体的射线路径（从质心到网格边界）互不经过其他候选体。

**规则**：
1. 对左上角每个原型，裁剪至其边界框并记录颜色和规范形状。
2. 对每个灰(5)候选体，裁剪至边界框，然后折叠所有相邻的全同行和全同列（游程压缩），得到压缩后的二值掩码。
3. 将每个候选体的压缩掩码与所有原型的掩码进行比较（允许 0/90/180/270 度旋转和水平/垂直反射），找到唯一匹配的原型。
4. 根据匹配原型的颜色确定方向：绿(3)=左，黄(4)=下，品红(6)=上，青(8)=右。
5. 计算候选体所有像素坐标的质心（行取平均后四舍五入，列取平均后四舍五入）。从质心位置向匹配方向发射一条射线，将射线经过的所有黑(0)像素涂为红(2)，直到到达网格边界（含边界行/列）。射线不修改非黑(0)像素。
6. 原型和候选体自身的像素保持不变。

**关键洞察**：候选体的视觉外形因拉伸而与原型差异巨大，必须先做游程压缩消除拉伸才能识别其原型归属；而原型的颜色不是用来重涂候选体的，而是编码了一个方向指令——这打破了"形状匹配用于重涂色"的常见模式。

## 新题 4：角落标记定位印章与十字射线交叉

**组合逻辑**：[朝向对应角/facing_corner](角落标记映射印章位置) + [印章放置/stamp] → [射线延伸/ray_extend](创新：从印章位置发射，颜色来自标记而非印章) → [异源交叉特殊着色/cross_source_special_color]

**来源原语**：角落标记(b745798f), 朝向对应角(b745798f), 印章放置(a251c730), 精灵体(a251c730), 射线延伸(45bbe264), 行列交叉(45bbe264), 异源交叉特殊着色(45bbe264)

**依赖链**：L 形角落标记的朝向决定印章放置的目标角落 → 印章位置决定射线的发射原点 → 标记颜色决定射线颜色（而非印章自身颜色） → 不同印章的射线交叉处产生特殊颜色。印章的放置位置和射线的着色来源被拆分到不同元素上，形成三角依赖。

根据 L 形标记朝向将灰色印章图案放置到对应角落，再从各角落印章发射标记色的十字射线，交叉点涂红(2)。

**输入结构**：黑(0)背景，约 15x15 网格。网格正中央有一个灰(5)的小型精灵体图案（3x3 至 4x4，4-连通，非对称，像素数 5~10）。围绕精灵体有 2~4 个 L 形角落标记，每个标记由 3 个像素组成，排列在 2x2 区域内占据其中 3 格形成 L 形。每个标记颜色不同（取自绿(3)、黄(4)、品红(6)、青(8)），每个标记的 L 形朝向不同，分别指向四个角落之一（开口朝右下=指向左上角，开口朝左下=指向右上角，开口朝右上=指向左下角，开口朝左上=指向右下角）。生成约束：至少有 2 个标记；各标记朝向互不相同；精灵体放置到任何角落后其边界框都不超出网格。

**规则**：
1. 裁剪中央灰(5)精灵体的边界框，得到印章模板 S。
2. 对每个 L 形标记，根据其 L 开口方向确定目标角落：开口朝右下 → 左上角，开口朝左下 → 右上角，开口朝右上 → 左下角，开口朝左上 → 右下角。
3. 将印章 S 放置到目标角落（印章边界框与网格对应角落齐平），保持灰(5)颜色不变。
4. 对每个已放置的印章副本，沿其边界框的每一行向左右延伸至网格边界，沿其边界框的每一列向上下延伸至网格边界。延伸像素涂为对应 L 形标记的颜色（不是灰(5)）。延伸射线遇到灰(5)印章像素或其他已放置印章的像素时跳过不覆盖。
5. 若某像素被来自两个不同标记的射线同时覆盖，则涂为红(2)。
6. 擦除原始中央精灵体和所有 L 形标记（恢复为黑(0)）。

**关键洞察**：标记的几何朝向决定空间位置（印章放在哪个角），标记的颜色决定射线着色（射线涂什么色）——这两个信息通道绑定在同一个标记对象上但作用于不同的后续操作，求解者必须同时追踪两条信息流。

## 新题 5：缩略图编码条形旋转指令

**组合逻辑**：[坐标映射/coordinate_mapping](创新：缩略图像素不编码颜色而编码旋转指令) + [旋转/rotate](条形绕中心旋转 90 度) + [已有块确认对齐/existing_blocks_confirm_alignment](创新：通过已正确旋转的条形反推映射关系)

**来源原语**：缩略图(c4d067a0), 坐标映射(c4d067a0), 已有块确认对齐(c4d067a0), 旋转(f0f8a26d), 单像素宽条(f0f8a26d), 中心点不变(f0f8a26d)

**依赖链**：必须先从已正确旋转的条形推断缩略图到主网格的比例因子和偏移量 → 用推断出的映射确定每个缩略图前景像素对应的条形 → 将对应条形旋转 90 度（保持中心和长度不变）。映射推断和旋转判定互相依赖——不知道映射就不知道旋转哪些条形，不识别已旋转的条形就无法推断映射。

根据左上角缩略图的前景/背景模式决定哪些条形需旋转 90 度，映射比例由已处于正确朝向的条形推断。

**输入结构**：黑(0)背景，约 17x17 网格。左上角从 (0,0) 起有一个小型缩略图（3x3 至 4x4），由红(2)前景像素和黑(0)背景像素组成，排列在规则栅格上。主区域有若干蓝(1)单像素宽条形（水平或垂直），每个条形长度为奇数（3~7 像素），各条形互不接触。每个条形的中心点在主网格中的位置可通过固定的比例因子 k 和偏移量 (dr, dc) 映射到缩略图的某个栅格位置：条形中心 (r, c) 对应缩略图位置 ((r-dr)/k, (c-dc)/k)。其中部分条形当前朝向已经是"旋转后"的正确状态（即这些条形在缩略图中对应红(2)像素且已经是旋转后的朝向），可用于确认比例和偏移。生成约束：至少有 2 个条形已处于旋转后状态用于推断映射；缩略图中每个红(2)像素在主网格中恰好有一个对应条形；旋转后所有条形互不重叠。

**规则**：
1. 识别左上角缩略图区域及其栅格布局（每个栅格位置为 1x1 像素）。
2. 识别主区域所有蓝(1)条形及其中心点坐标和当前朝向（水平/垂直）。
3. 利用已知处于旋转后正确朝向的条形（它们在输入中的朝向与"未旋转"的默认朝向不同），建立中心坐标到缩略图栅格位置的线性映射 (r, c) → ((r-dr)/k, (c-dc)/k)，解出比例 k 和偏移 (dr, dc)。判断方法：在所有可能的 k 和 (dr, dc) 组合中，找到使最多条形中心映射到缩略图整数栅格位置的那组参数。
4. 对每个条形，通过映射找到其对应的缩略图栅格位置。若该位置为红(2)，则将该条形绕其中心旋转 90 度（水平变垂直、垂直变水平），保持长度不变。若该位置为黑(0)，条形保持原样。
5. 输出旋转后的完整网格。缩略图区域保持不变。

**关键洞察**：缩略图中的红(2)像素不是要放置的色块，而是"旋转此条形"的布尔指令——这颠覆了缩略图通常编码颜色信息的模式；求解者必须从已旋转的少数条形反推坐标映射关系，才能确定哪些条形需要旋转。

## 新题 6：标记选择后扩展并偏移阴影装饰

**组合逻辑**：[标记选中邻接体/marker_selects_neighbor](灰标记选择目标对象) → [扩展/expand](选中对象边界框扩展) → [偏移复制/offset_copy](创新：阴影像素的相对偏移在扩展边界上复制装饰)

**来源原语**：标记选中邻接体(48d8fb45), 邻接接触(48d8fb45), 扩展(305b1341), 偏移复制(35ab12c3), 阴影像素(35ab12c3), 擦除(b9630600)

**依赖链**：灰(5)标记通过 4-连通邻接选择目标对象 → 被选对象的边界框扩展 1 像素生成填充区域 → 阴影像素相对于对象的偏移向量在扩展边界的每个边缘像素上复制。标记决定"谁被处理"，扩展决定"填充范围"，阴影偏移决定"装饰图案"——三层信息叠加在同一个对象的邻域中，必须全部正确提取。

灰(5)标记选中邻接的彩色对象，被选对象扩展填充，同时将对象旁的阴影像素偏移图案复制到扩展边界上作为装饰。

**输入结构**：黑(0)背景，约 14x14 网格。有 3~5 个 4-连通单色小型对象（每个 3~6 像素），颜色各不相同（取自蓝(1)、红(2)、绿(3)、黄(4)）。其中 2~3 个对象有一个灰(5)单像素与之 4-连通邻接（标记像素）。每个被标记的对象还有恰好 1 个橙(7)单像素（阴影像素）与该对象 4-连通邻接（但不与灰标记邻接）。阴影像素相对于其邻接的对象像素有一个方向偏移（上/下/左/右之一）。未被标记的对象既无灰(5)标记也无橙(7)阴影像素。生成约束：所有对象（含扩展后范围）互不重叠；阴影偏移方向在扩展边界上复制时不超出网格。

**规则**：
1. 识别所有灰(5)单像素标记。对每个标记，找到与之 4-连通邻接的唯一彩色对象，该对象即为"选中对象"。
2. 对每个选中对象，找到与之 4-连通邻接的橙(7)阴影像素。记录阴影像素相对于其邻接的对象像素的偏移向量 (delta_r, delta_c)（例如阴影在对象像素正上方则偏移为 (-1, 0)）。
3. 计算选中对象的边界框，向四个方向各扩展 1 像素。将扩展区域内所有黑(0)像素涂为该对象的颜色（原有对象像素保持不变）。
4. 找到扩展后矩形的所有边缘像素（最外一圈）。对每个边缘像素位置 (r, c)，在位置 (r + delta_r, c + delta_c) 处涂上橙(7)（若该位置在网格内且当前为黑(0)）。
5. 擦除所有灰(5)标记像素和原始橙(7)阴影像素（恢复为黑(0)）。未被标记选中的对象保持原样。

**关键洞察**：灰(5)标记、彩色对象和橙(7)阴影三种元素紧邻共存，求解者必须区分"选择信号"（灰）、"操作主体"（彩色对象）和"装饰模板"（橙）三种角色——阴影像素容易被误认为对象的一部分或噪声，但它实际上是扩展边界装饰图案的种子。

## 新题 7：自相似嵌套与图例层级冲突

**组合逻辑**：[自相似嵌套/self_similar_nesting](前景位置决定印章) + [重涂色/recolor](创新：印章中每种颜色通过图例映射为填充色) → [图例顺序决定层级/legend_order_layer](创新：嵌套重叠区域用图例行序决定优先级)

**来源原语**：自相似嵌套(8f2ea7aa), 前景位置决定印章(8f2ea7aa), 像素放大(8f2ea7aa), 图例配色(305b1341), 图例顺序决定层级(305b1341), 冲突优先级(305b1341)

**依赖链**：多色模体的前景像素位置决定在哪些块中印章模体自身 → 印章后每个块内出现多种颜色 → 每种颜色通过图例映射为对应填充色 → 相邻块的印章可能在边界处视觉冲突 → 图例行序提供优先级来解决重绘冲突。自相似嵌套制造了冲突发生的条件，图例同时承担颜色映射和冲突裁决两个功能。

将多色模体进行自相似嵌套扩展，每个颜色通过图例映射为填充色，嵌套后重叠区域按图例行序优先级决定最终颜色。

**输入结构**：黑(0)背景。网格大小恰好是模体边长的平方（如模体 3x3 则网格 9x9，模体 4x4 则网格 16x16）。网格左上角前两列（列 0 和列 1）从第 0 行起有一个两列图例：每行左列为一种源色，右列为其对应的填充色，共 2~3 行（即 2~3 组映射）。图例区域下方和右方为黑(0)。网格中有一个紧凑的正方形边界框模体（3x3 或 4x4），由 2~3 种非黑前景色组成（颜色恰好是图例中的源色），像素数占边界框的 40%~70%，其余为黑(0)。模体位置不与图例重叠。生成约束：图例源色与模体使用的颜色一一对应；图例填充色互不相同且与源色均不同；模体中相邻前景像素在自相似嵌套后会导致相邻块产生边界重叠。

**规则**：
1. 读取图例：第 i 行（从 0 起）的 (列0色, 列1色) 为第 i 组颜色映射。记录图例行序（行号越小优先级越高）。然后清除图例区域（涂为黑(0)）。
2. 裁剪模体至其边界框，得到 NxN 的模式 M。
3. 自相似嵌套：对 M 中每个前景像素位置 (r, c)（0-indexed），将完整模式 M 复制到输出网格中以 (r*N, c*N) 为左上角的 NxN 块中。M 中黑(0)位置对应的块保持全黑。
4. 颜色映射：对输出网格中每个非黑像素，将其颜色从图例源色替换为对应的图例填充色。
5. 冲突解决：若步骤 3 中多个块的印章范围在边缘像素重叠（当两个被激活的块在模体中相邻时，它们的 NxN 区域不重叠，但此规则处理的是同一像素被多次赋色的情况——具体发生在模体中对角相邻的两个前景像素对应的块在角点共享像素的情况），按图例优先级处理：该像素最终取图例行号最小的那组映射对应的填充色。

**关键洞察**：自相似嵌套将一个紧凑模体展开为大型图案，模体中多颜色共存导致展开后不同颜色区域在块边界处视觉碰撞；图例不仅仅是一张颜色转换表，其行序隐含了图层优先级——求解者必须同时理解嵌套规则和图例的双重功能才能正确还原输出。

## 新题 8：空心矩形走廊网络中的方向滑动

**组合逻辑**：[连线/connect + 最小生成树/min_spanning_tree](创新：走廊网络创建可通行路径) → [颜色编码方向/color_coded_dir](创新：矩形内标记颜色决定内容物滑动方向) → [滑动/slide](创新：沿走廊通道滑动直到碰壁)

**来源原语**：连线(b9630600), 最小生成树(b9630600), 空心矩形(b9630600), 走廊(b9630600), 重叠决定走廊宽度(b9630600), 滑动(f3e62deb), 颜色编码方向(f3e62deb), 颜色决定方向(f3e62deb)

**依赖链**：先构建空心矩形之间的最短走廊网络（MST）→ 走廊连通了各矩形的内部空间 → 矩形内的彩色标记像素决定滑动方向 → 标记沿走廊和矩形内部连通空间滑动直到碰壁。走廊的几何结构决定了哪些方向可以滑动多远，标记的颜色决定了实际滑动方向——两者共同决定终点。

先按 MST 连接空心矩形形成走廊网络，然后矩形内部的彩色标记沿颜色编码的方向在网络内滑动至碰壁停止。

**输入结构**：黑(0)背景，约 20x20 网格。有 3~5 个灰(5)空心矩形框（外壁 1 像素厚，内部为黑(0)，各框大小 4x4 至 7x7 不等），互不接触，之间有黑(0)间隔。部分矩形内部恰好有 1 个彩色标记单像素，颜色取自绿(3)=左、黄(4)=下、品红(6)=上、青(8)=右（同一网格中至少有 2 个标记，颜色可重复）。其余矩形内部无标记。各矩形之间存在水平或垂直的可见间距（两矩形的内部行/列范围有重叠，且间距中全为黑(0)）。生成约束：每对有重叠内部范围的矩形之间的最短间距唯一确定（无并列）；MST 连接后走廊不经过任何第三个矩形；每个标记沿其方向滑动时路径上无其他标记。

**规则**：
1. 识别所有灰(5)空心矩形和所有彩色标记像素。
2. 按参考题 b9630600 的规则构建 MST 走廊网络：计算每对矩形之间的最短可见间距，选择最小生成树，对每条选中的间距绘制走廊——水平间距取两矩形内部行范围重叠的最上和最下行作为走廊边界行，在两行之间穿过间距涂灰(5)，并擦除两侧面对的墙壁像素（严格在两走廊边界行之间的部分）；垂直间距做转置操作。
3. 走廊绘制完成后，网络内部形成一个连通的可通行空间（所有矩形内部 + 走廊内部的黑(0)像素构成的连通区域）。
4. 对每个标记像素，根据其颜色确定滑动方向（绿(3)=左，黄(4)=下，品红(6)=上，青(8)=右）。标记从当前位置沿该方向在可通行空间内逐像素滑动。标记在遇到灰(5)墙壁像素或网格边界时停止（停在墙壁/边界前一格）。若滑动方向上标记当前位置的下一像素就是墙壁，则标记不移动。
5. 擦除标记的原始位置（涂黑(0)），在新位置涂上标记颜色。按标记在输入中从上到下、从左到右的顺序依次处理滑动（先处理的标记的最终位置成为后续标记的障碍）。

**关键洞察**：走廊的几何形状（宽度和长度由矩形内部重叠范围决定）限制了标记的可达空间——标记可以滑出自己所在的矩形、穿过走廊、进入另一个矩形，但只能沿直线移动；必须先完成 MST 走廊构建才能确定可通行空间的拓扑。

## 新题 9：原型锚点定位与空腔嵌套旋转

**规则**：
1. 识别所有框架（灰(5)边框 + 黑(0)空腔）及其标记颜色和标记位置。识别所有可移动工具及其锚点颜色（像素数最少的颜色）。
2. 通过锚点颜色 = 标记颜色将每个工具与唯一框架配对。
3. 对每个配对，尝试所有 8 种旋转/翻转变换（4 种旋转 x 是否水平翻转），找到使工具形状恰好填满框架空腔、且工具锚点像素落在框架标记位置的唯一变换。

5. 将变换后的工具放入框架空腔，覆盖原空腔中的黑(0)像素。擦除工具原始位置（涂黑(0)）。框架边框和标记像素保持不变（工具锚点像素叠在标记位置上，用工具的锚点色覆盖）。

**关键洞察**：求解者不仅要找到正确的旋转/翻转使工具嵌入空腔，还必须判断该变换是否包含反射——这个看似纯几何的判断会触发颜色层面的变化（双色互换），将空间推理和颜色推理耦合在一起。

## 新题 10：图例排位重涂色与射线遮挡填充

**规则**：
1. 识别所有橙(7)精灵体，按边界框左上角坐标排序（先行后列），得到排位序列 S1, S2, ..., Sn。
2. 识别图例区域中的像素序列 L1, L2, ..., Ln（若图例为纵向排列则从上到下，横向则从左到右）。
3. 将 Si 与 Li 配对。Li 的颜色编码方向：绿(3)=左，黄(4)=下，品红(6)=上，青(8)=右。
4. 对每个精灵体 Si，从其边界框的对应边（左=左边缘全列, 右=右边缘全列, 上=上边缘全行, 下=下边缘全行）沿分配方向发射射线：
   - 方向为左：从精灵体边界框每一行的最左列向左逐像素延伸，遇到蓝(1)像素或网格左边界时停止（不含蓝像素本身）。
   - 方向为右：从精灵体边界框每一行的最右列向右延伸，同理。
   - 方向为上：从精灵体边界框每一列的最上行向上延伸，同理。
   - 方向为下：从精灵体边界框每一列的最下行向下延伸，同理。
5. 将射线扫过的所有黑(0)像素涂为橙(7)（精灵体自身颜色）。不覆盖蓝(1)障碍、图例像素或其他精灵体像素。
6. 图例区域保持不变。

**关键洞察**：图例像素的颜色不是精灵体的目标涂色（精灵体保持橙(7)），而是编码精灵体应当发射射线的方向——这反转了图例的常见用途；求解者必须先通过空间排位建立精灵体与图例的对应关系，才能得知每个精灵体的射线方向。
