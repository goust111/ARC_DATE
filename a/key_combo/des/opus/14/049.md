## 新题 1：射线穿框计数染色

**组合逻辑**：[掏空](创新：使实心矩形变为可穿透框架) → [射线延伸](创新：射线穿越框架边界而非停止) → [计数](创新：统计穿越框架边界次数) → [重涂色](创新：穿越数映射为颜色)

**来源原语**：掏空/hollowing(4347f46a)、射线延伸/ray_extend(ecdecbb3)、计数/counting(e50d258f, d0f5fe59)、重涂色/recolor(ea32f347)、实心矩形/solid_rectangle(4347f46a)、控制像素/control_pixel(ecdecbb3)、内部包含/containment(4347f46a)、投射/perpendicular_cast(ecdecbb3)

**依赖链**：掏空将实心矩形变为仅保留边框的空心框架，这使得射线能穿越多层框架而不被第一个实心面挡住；射线穿越边框的次数编码了控制像素在嵌套结构中的几何深度；穿越次数再通过固定映射表决定控制像素的最终颜色。四步环环相扣——不掏空则射线无法穿透，不投射射线则无法得到穿越数，不计数则无法确定目标颜色。

将黑色背景上嵌套的蓝色实心矩形掏空为框架，然后统计每个灰色控制像素的四方向射线穿越框架边界的总次数，按穿越数重涂控制像素颜色。

**输入结构**：黑(0)背景，约15x15网格。若干蓝(1)单色实心矩形（每个至少3像素宽、3像素高），矩形之间存在嵌套关系（小矩形完全在大矩形内部），但任意两个矩形的边框像素互不共享。若干灰(5)控制像素散布在矩形外部或嵌套间隙中（控制像素与任何矩形像素不4-邻接）。生成约束：嵌套层数至少为2（即存在矩形A包含矩形B再包含矩形C的结构）；控制像素至少4个，分布在不同嵌套深度的位置。

**规则**：
1. 对每个蓝(1)实心矩形执行掏空操作：保留其一像素宽边框，将边框严格内部的所有像素设为黑(0)。
2. 从每个灰(5)控制像素出发，向上、下、左、右四个基本方向各发射一条射线，射线沿直线前进直到离开网格边界。
3. 统计每个控制像素的四条射线穿越蓝(1)边框像素的总次数：每条射线每经过一个蓝(1)像素计为一次穿越（进入一个框架的边框算一次，离开同一框架的另一侧边框再算一次）。
4. 按穿越总数对控制像素重涂颜色：0次 → 保持灰(5)，2次 → 红(2)，4次 → 绿(3)，6次 → 黄(4)，8次及以上 → 橙(7)。
5. 蓝(1)边框像素和黑(0)背景保持不变。

**关键洞察**：掏空操作是射线能够穿透多层结构的前提——实心矩形会完全阻挡射线，而空心框架仅在边框处产生可计数的穿越事件。穿越总数直接编码了控制像素在嵌套层次中的几何深度，而这个深度信息只有在掏空之后才能通过射线投射获得。

## 新题 2：连线围区泛洪

**组合逻辑**：[连线](保留核心：同色配对连接) + [竖线交叉优先](保留) → 线段交叉围成封闭区域(涌现结构) → [泛洪填充](创新：填充由线段围成的涌现区域) + 最近线段决定填色(创新)

**来源原语**：连线/draw_line(40853293)、同色配对/same_color_pairing(40853293)、行列对齐/row_col_align(40853293)、竖线交叉优先/vertical_priority_at_cross(40853293)、泛洪填充/flood_fill(b9e38dc0)、填充种子/fill_seed(b9e38dc0)、线段/line_segment(40853293)

**依赖链**：连线操作将分散的标记像素对连成线段，线段在网格上交叉围成封闭区域——这些区域是连线操作的涌现产物，在连线前不存在。泛洪填充利用这些涌现区域作为边界，而填充颜色由种子到最近线段的距离决定。交叉优先规则既影响交叉点处的可见颜色，又隐含地影响了区域的边界判定。

连接同色标记像素对形成交叉线段，线段围成的封闭区域从灰色种子泛洪填充，填充色取距种子最近的线段颜色。

**输入结构**：黑(0)背景，约14x14网格。至少4对前景色标记像素，每种颜色恰好出现两次，两个同色像素共享行或列。使用的颜色包括蓝(1)、红(2)、绿(3)、黄(4)等（每对一种颜色）。若干灰(5)种子像素分别位于连线后将被线段围成的封闭区域内部。生成约束：标记像素对的连线必须产生至少3个交叉点；交叉点与线段共同围成至少2个完全封闭的区域（四面均被线段包围，不接触网格边界）；每个封闭区域内恰好有一个灰(5)种子像素；种子不位于任何线段上；至少存在两个封闭区域，其最近线段颜色不同。

**规则**：
1. 用一像素宽直线连接每对同色标记像素（包含两个端点），线段颜色为该对标记的颜色。
2. 当水平线段和竖直线段在同一像素处交叉时，该像素显示竖直线段的颜色（竖线优先）。
3. 线段在网格上将背景划分为若干区域。找到所有完全被线段像素包围的封闭区域（区域内任何像素的4-连通路径均无法在不经过线段像素的情况下到达网格边界）。
4. 对每个封闭区域内的灰(5)种子像素，计算种子到该区域所有边界线段像素的曼哈顿距离，取最小值对应的线段颜色作为该区域的填充色。若最近距离对应多条不同颜色的线段，取其中竖直线段的颜色（与交叉优先规则一致）。
5. 从种子像素开始，用确定的填充色泛洪填充整个封闭区域（填充在遇到线段像素或网格边界时停止）。种子像素被填充色覆盖。
6. 非封闭区域（可达网格边界的区域）内的灰(5)像素保持不变。线段像素保持不变。

**关键洞察**：封闭区域是连线操作的涌现产物——线段交叉在网格上自然围成了这些区域，它们在输入中不存在任何对应结构。填充色的决定规则与交叉优先规则使用相同的"竖直优先"逻辑，形成统一的非显然偏好，需要对比多个示例才能发现这种一致性。

## 新题 3：透明叠加后掏空重叠区

**组合逻辑**：[透明叠加](保留核心：按面板位置层序合成) + 重叠层数检测(涌现：叠加过程中产生的隐藏信息) → [掏空](创新：仅掏空被多层覆盖的矩形区域)

**来源原语**：透明叠加/transparent_overlay(ea9794b1)、图层优先级/layer_priority(ea9794b1)、面板位决定层序/panel_layer_order(ea9794b1)、面板/panel(ea9794b1)、掏空/hollowing(4347f46a)、实心矩形/solid_rectangle(4347f46a)、边框/frame(4347f46a)、保留边擦除内部/keep_border_erase_interior(4347f46a)

**依赖链**：面板叠加决定每个像素的可见颜色（图层优先级），同时产生一个隐藏维度——每个位置被多少个面板的非背景像素覆盖。可见颜色和覆盖层数来自同一组面板数据但提取了不同维度的信息。覆盖层数 >= 2 的位置所对应的矩形需要被掏空，而掏空后保留的边框颜色由叠加的可见颜色决定。两个操作无法分离：不做叠加就不知道可见颜色和覆盖层数，不根据覆盖层数就不知道掏空哪些矩形。

将四个面板中的实心矩形按位置层序透明叠加为一个画面，然后找到被两个及以上面板同时覆盖的矩形区域，将这些区域掏空为框架（保留叠加后的可见颜色），未重叠的矩形保持实心。

**输入结构**：黑(0)背景，约14x14网格，无分隔线。网格在概念上被均分为2x2共4个等大面板区域（左上、右上、左下、右下）。每个面板内包含1~2个单色实心矩形（至少3x3），不同面板中的矩形颜色互不相同——例如左上面板中的矩形为蓝(1)，右上为红(2)，左下为绿(3)，右下为黄(4)。部分矩形在叠加后会重叠（即四个面板中对应位置有两个或更多面板存在非背景像素）。生成约束：至少存在2对矩形在叠加后发生重叠；至少1个矩形在叠加后完全不与其他矩形重叠；重叠区域的面积至少为3x3（使掏空操作有意义）。

**规则**：
1. 将四个面板按位置层序叠加到一个与单个面板等大的输出网格上：先绘制左上面板的非背景像素，然后依次绘制右下、左下、右上面板的非背景像素。后绘制的覆盖先绘制的。
2. 在叠加过程中，记录每个输出像素被多少个面板的非背景像素覆盖（覆盖层数）。
3. 对于叠加结果中属于某个矩形区域（该区域在叠加结果中形成一个完整矩形轮廓）且区域内存在任何覆盖层数 >= 2 的像素的矩形：执行掏空操作——保留该矩形在叠加结果中的可见颜色边框（一像素宽），将边框严格内部的像素设为黑(0)。
4. 叠加结果中完全没有被多层覆盖的矩形（区域内所有像素覆盖层数均为1）保持实心不变。
5. 输出为单个面板大小的网格。

**关键洞察**：面板叠加产生两个维度的信息——可见颜色（由层序决定）和覆盖层数（由重叠程度决定）。可见颜色决定掏空后框架的颜色，覆盖层数决定是否需要掏空。求解者必须同时追踪两个维度，仅看叠加结果的外观无法判断哪些矩形应被掏空，因为高优先级层可能完全遮盖了低优先级层的存在。

## 新题 4：排序驱动偏移阴影与镜像

**组合逻辑**：[排序/长度排名](创新：排名编码阴影偏移方向而非颜色) → [偏移阴影](创新：偏移方向由排名决定而非固定) + [镜像](创新：指示像素仅决定镜像轴，颜色由固定规则给出)

**来源原语**：排序/sorting(ea32f347)、长度排名/length_ranking(ea32f347)、排名决定颜色/rank_determines_color(ea32f347 → 创新为rank_determines_direction)、偏移阴影/offset_shadow(310f3251)、阴影像素/shadow_pixel(310f3251)、镜像/mirror(b775ac94)、指示像素/indicator_pixel(b775ac94)、邻接/adjacency(b775ac94)、细条/thin_bar(ea32f347)

**依赖链**：长度排名提供排名值 → 排名值编码为阴影偏移方向（排名1向右、排名2向下、排名3向右下），替代了源题中排名→颜色的映射 → 每根条按其排名方向生成蓝色阴影 → 指示像素确定镜像轴 → 条和阴影一起被镜像，镜像副本使用固定的绿色和黄色。排名、阴影方向、镜像轴三条信息链在输出中交汇，缺少任何一条都无法重建完整输出。

将三根不等长灰色细条按长度排名，排名决定其蓝色阴影的偏移方向，再以各条旁的红色指示像素为轴将条及其阴影一起镜像，镜像副本使用绿色条和黄色阴影。

**输入结构**：黑(0)背景，约14x16网格。恰好三根灰(5)单像素宽直条（可以是水平或竖直的），长度互不相同（如3、5、7像素）。每根条的某一侧有一个红(2)指示像素与条4-邻接（三根条的指示像素分别在条的不同侧，如一个在条的上方、一个在左方、一个在下方）。生成约束：三根条互不4-邻接且与网格边界至少间隔2像素；每根条的阴影和镜像副本不超出网格边界。

**规则**：
1. 按像素数量从多到少对三根灰(5)条排序，分别得到排名1（最长）、排名2（中等）、排名3（最短）。
2. 根据排名确定阴影偏移方向：排名1的条 → 阴影向右偏移1像素（即阴影中每个像素比原条对应像素列号+1）；排名2的条 → 阴影向下偏移1像素（行号+1）；排名3的条 → 阴影向右下偏移1像素（行号+1且列号+1）。
3. 在偏移位置绘制该条的阴影副本，颜色为蓝(1)。原条保留灰(5)不变。若阴影像素与原条像素重叠，保持灰(5)。
4. 以每根条旁的红(2)指示像素为镜像中心，将该条及其阴影一起做点对称（180度旋转）镜像：镜像后的条颜色为绿(3)，镜像后的阴影颜色为黄(4)。
5. 若镜像副本的像素与原始条/阴影像素重叠，后绘制的镜像副本覆盖之前的像素。红(2)指示像素保留不变。

**关键洞察**：长度排名在源题中直接映射为条的颜色（一步完成），这里排名映射为阴影偏移方向（改变了后续操作的几何形态）。指示像素在源题中同时决定镜像轴和副本颜色，这里只决定镜像轴（颜色由固定规则给出）。两种"属性→参数"映射相互独立但在空间上交织，构成了非平凡的推理图。

## 新题 5：门结构过滤计数对角线输出

**组合逻辑**：[滑动](保留核心：沿路径移动) + [门前停止](创新：门作为过滤条件而非单纯停止点) → [擦除](保留：消耗路径) → [计数](创新：计数成功到达门的标记数量) → [对角线输出](创新：输出尺寸由过滤后的计数决定)

**来源原语**：滑动/slide(182e5d0f)、门结构/gate_motif(182e5d0f)、门前停止/stop_at_gate(182e5d0f)、路径/path(182e5d0f)、擦除/erase(182e5d0f)、标记像素/marker_pixel(182e5d0f)、四邻接连通/four_neighbor_connect(182e5d0f)、计数/counting(d0f5fe59)、数量决定边长/count_determines_side(d0f5fe59)、对角线标记/diagonal_marker(d0f5fe59)、连通分量/connected_component(d0f5fe59)

**依赖链**：每个组件中灰色标记沿绿色路径滑动，有门结构的组件中标记到达门前并消耗路径，无门的组件保持不变 → 门结构充当过滤器，区分"有效组件"和"无效组件"→ 仅计数有效组件的数量N → 输出N×N对角线网格。门既是滑动的终止条件也是计数的筛选条件，双重角色使其不可删除。

在多个独立路径组件中，灰色标记沿绿色路径滑动至门结构前停止并消耗路径，无门的组件保持原状；计数成功到达门的标记数量N，输出N×N主对角线网格。

**输入结构**：黑(0)背景，约18x18网格。若干互不4-邻接的独立前景组件，每个组件由以下元素构成：一条绿(3)像素组成的单像素宽路径（可包含直角转弯，但不分叉）；路径一端有一个灰(5)标记像素（与路径端点4-邻接）；路径另一端可能有或没有门结构。门结构为三个像素的直线段：两端为栗(9)、中间为绿(3)，方向与路径末端走向垂直。部分组件有门结构，部分没有（路径末端直接终止于背景，无栗(9)像素）。生成约束：有门组件至少3个，无门组件至少1个；所有组件互不4-邻接。

**规则**：
1. 对每个包含门结构的组件：将灰(5)标记像素沿绿(3)路径滑动至门中心绿(3)像素的4-邻接位置（路径上靠近门的那一端）。滑动经过的所有绿(3)路径像素被擦除为黑(0)。门结构（两个栗(9)像素和中心绿(3)像素）保持不变。标记像素在新位置显示灰(5)。
2. 对每个没有门结构的组件：所有像素保持原状不变（灰(5)标记留在原位，绿(3)路径保留）。
3. 计数所有成功到达门前的灰(5)标记数量，记为N。
4. 输出一个N×N的黑(0)网格，主对角线（从左上角到右下角）像素填为绿(3)。

**关键洞察**：门结构在源题中是每个组件都有的停止点，这里变成了区分有效与无效组件的过滤器。无门组件的存在是干扰项——它们占据视觉空间但不影响最终输出的N值。求解者需要先理解滑动-门机制，再发现只有到达门的标记才被计入，最后理解计数值编码了输出网格的尺寸。

## 新题 6：延伸投票选取框架裁剪

**组合逻辑**：[延伸](创新：朝最近框架边延伸而非朝边缘条) → 延伸方向标记框架(涌现：延伸操作变为投票机制) → [计数](创新：计算每个框架的得票数) → [裁剪](创新：选取标准从面积最大变为得票最多) + [重涂色](保留)

**来源原语**：延伸/extend(642248e4)、朝近端扩展/toward_nearer_expand(642248e4)、控制像素/control_pixel(642248e4)、裁剪/crop(fcb5c309)、最大框决定裁切/largest_frame_crops(fcb5c309 → 创新为most_voted_frame_crops)、矩形框架/rect_frame(fcb5c309)、面积最大选取/largest_area_select(fcb5c309)、重涂色/recolor(fcb5c309)、计数/counting(e50d258f)

**依赖链**：每个控制像素向最近的矩形框架边延伸一个像素（投票），不同控制像素可能投票给不同框架 → 汇总每个框架收到的投票数 → 得票最多的框架被选中裁剪（面积仅作为平局打破条件）→ 裁剪结果中框架像素被重涂为控制像素的颜色。延伸操作的方向和投票目标无法独立于框架位置确定，计数结果无法独立于延伸结果确定，裁剪目标无法独立于计数结果确定。

红色控制像素各自朝最近的蓝色矩形框架边延伸一个像素作为"投票"，得票最多的框架被裁剪输出，裁剪结果中框架像素重涂为红色。

**输入结构**：黑(0)背景，约16x16网格。至少3个蓝(1)单像素宽矩形框架（空心矩形，仅有边框），大小各不相同（边框围成的内部面积互不相等）。若干红(2)控制像素散布在框架外部（不在任何框架的边框上或内部）。生成约束：框架互不重叠、互不嵌套；每个控制像素在至少一个基本方向上能看到某个框架的边框像素（即同行或同列存在框架边框像素）；至少存在一个框架得到的投票数严格多于其他所有框架。

**规则**：
1. 对每个红(2)控制像素，在上、下、左、右四个方向上分别寻找最近的蓝(1)框架边框像素。取四个方向中距离最近的那个方向（曼哈顿距离）。若多个方向距离相同，优先选择按顺时针顺序较早的方向（上 > 右 > 下 > 左）。
2. 在该最近方向上，将控制像素旁的一个背景像素填为红(2)（即从控制像素向该方向延伸一个像素）。被延伸像素所指向的框架获得一票。
3. 统计每个框架收到的总票数。选取得票最多的框架。若票数相同，选取边框围成内部面积最大的框架。
4. 裁剪被选中框架的边界框（包含其完整边框）。
5. 在裁剪结果中，将所有蓝(1)框架像素重涂为红(2)，其他像素不变。
6. 输出裁剪后的网格。

**关键洞察**：源题中控制像素朝近端边缘条延伸一个像素（方向由两条边缘条的距离比较决定），这里延伸方向由最近框架的位置决定——延伸操作从一个简单的距离响应变成了聚合投票机制。选取裁剪目标的标准从"面积最大"变为"得票最多"，使得输入中控制像素的分布成为决定输出的关键因素。

## 新题 7：异常值象限驱动印章渲染

**组合逻辑**：[相等比较 + 异常值选择](保留核心) → 异常值图案提取为印章模板(创新：异常值不直接输出而成为中间工具) → [印章渲染](创新：模板来自异常值而非预定义区域) + 标记像素定位印章(保留)

**来源原语**：异常值选择/outlier_selection(88a62173)、相等比较/equality_comparison(88a62173)、象限/quadrant(88a62173)、分隔十字/separator_cross(88a62173)、输出唯一象限/output_unique_quadrant(88a62173 → 创新为outlier_as_template)、印章渲染/stamp_rendering(65b59efc)、模板掩码/template_mask(65b59efc)、标记像素/marker_pixel(65b59efc)、编码映射/encoding_map(65b59efc)

**依赖链**：四个象限比较找到异常值 → 异常值图案成为印章模板（形状和颜色均保留）→ 模板在标记区域的指定位置被反复印章 → 输出仅包含印章结果。异常值识别是获取模板的唯一途径（模板在输入中没有额外标注），印章位置由标记像素决定，两者缺一不可。

将分隔十字分割的四个象限中的异常值图案提取为印章模板，在独立标记区域中按红色标记像素的位置重复印章该模板。

**输入结构**：约15x21网格（或21x15），分为左右两个大区域，由两列黑(0)分隔。左侧区域为约15x15，被黑(0)分隔十字（中间行和中间列全为黑(0)）分为4个等大象限。三个象限包含相同的单色图案（如蓝(1)的4-连通小图形，3~8像素），第四个象限包含不同颜色和形状的图案（如绿(3)的另一4-连通小图形）——这是异常值。右侧区域为标记区域，尺寸为象限尺寸的整数倍（如1x2个象限大小），黑(0)背景上散布若干红(2)标记像素。生成约束：异常值象限的图案完全在象限内部（不触碰分隔十字）；标记区域可被精确划分为若干与象限等大的块；至少2个块包含红(2)标记像素，至少1个块不包含。

**规则**：
1. 比较左侧区域的四个象限图案（忽略黑(0)背景，仅比较非背景像素的位置和颜色）。找到唯一不同的象限——异常值象限。
2. 提取异常值象限的非背景像素图案作为印章模板（记录每个非背景像素相对于象限左上角的行列偏移及其颜色）。
3. 将右侧标记区域划分为与象限等大的块（从左上角开始，按行列顺序切割）。
4. 对每个包含至少一个红(2)标记像素的块：在该块的对应位置上印上模板图案（按模板中记录的偏移和颜色绘制像素）。已有的红(2)标记像素被模板覆盖（若重叠）。不包含红(2)标记像素的块保持全黑(0)。
5. 输出仅为右侧标记区域（去掉左侧象限区域和分隔列）。

**关键洞察**：异常值象限在源题中被直接裁剪输出，这里变为中间产物——它是印章操作的模板来源。求解者需要先通过象限比较发现异常值（非显然步骤），再将异常值的几何结构解码为可复用的印章掩码，最后在标记区域中按激活条件应用。三步紧耦合且任何一步都无法跳过。

## 新题 8：缺角三角形泛洪遮蔽

**组合逻辑**：[缺角定位](保留核心) → [连线](保留：绘制三角形边) → [泛洪填充](创新：填充三角形围成的区域) + [障碍投射阴影](创新：阴影方向由直角顶点位置决定，沿直角边方向传播)

**来源原语**：缺角定位/missing_corner_loc(1478ab18)、缺角为直角顶点/missing_is_vertex(1478ab18)、直角三角形/right_triangle(1478ab18)、连线/draw_line(1478ab18)、包围方块/bounding_square(1478ab18)、标记像素/marker_pixel(1478ab18)、泛洪填充/flood_fill(b9e38dc0)、障碍物/obstacle(b9e38dc0)、障碍投射阴影/obstacle_casts_shadow(b9e38dc0)、填充种子/fill_seed(b9e38dc0)

**依赖链**：缺角定位确定直角顶点 → 直角顶点定义三角形的三条边和两条直角边方向 → 三角形边线围成封闭区域供泛洪填充 → 障碍像素沿直角边方向投射阴影阻挡填充传播。直角顶点位置同时决定了三角形形状和阴影传播方向，改变缺角位置会同时改变这两者，形成不可分离的耦合。

找到标记像素边界正方形的缺角作为直角顶点，绘制青色直角三角形轮廓并从种子泛洪填充三角形内部，蓝色障碍像素沿直角边方向投射阴影阻挡填充。

**输入结构**：橙(7)背景，约15x15网格。恰好4个灰(5)标记像素，其边界框（最小包围矩形）为正方形：3个在正方形的三个角上，1个在正方形内部（用作干扰项）。正方形区域内还有若干蓝(1)障碍像素（不在灰(5)标记像素位置上）。一个红(2)种子像素位于将被三角形边线包围的区域内部。生成约束：缺角位置使三角形区域内至少包含1个蓝(1)障碍像素；红(2)种子像素在三角形内部且不在障碍像素上也不在三角形边线上；三角形内部面积足够大（正方形边长至少6像素）。

**规则**：
1. 找到4个灰(5)标记像素的边界正方形。确定正方形四角中没有灰(5)标记像素的那个角——缺角。缺角即为直角三角形的直角顶点，与缺角相邻的两个正方形角（分别与缺角共享行或列）为三角形的另外两个顶点。正方形对角位置的标记像素（与缺角对角）为干扰项，不影响规则。
2. 用青(8)绘制三角形的三条边：两条直角边（从直角顶点到两个邻角）和一条斜边（连接两个邻角）。边线为一像素宽，包含端点。
3. 从红(2)种子像素开始，用红(2)泛洪填充三角形内部区域。填充在遇到青(8)边线像素、网格边界或蓝(1)障碍像素时停止。
4. 每个蓝(1)障碍像素沿两条直角边的方向各投射一条"阴影射线"：从障碍像素出发，沿直角边的方向（从直角顶点指向该邻角的方向向量）延伸，直到遇到青(8)边线或网格边界。阴影射线经过的所有像素（不含起点障碍像素和终点边线像素）恢复为橙(7)背景——即使这些像素已被步骤3的泛洪填充。
5. 灰(5)标记像素、青(8)边线、蓝(1)障碍像素、红(2)种子像素（如果未被阴影覆盖）保持不变。

**关键洞察**：直角顶点位置（由缺角决定）不仅定义了三角形的形状，还隐式定义了障碍物投射阴影的方向——阴影沿直角边方向传播。如果缺角在左上，直角边方向为向右和向下，阴影就向这两个方向扩散；如果缺角在右下，方向完全相反。同一个几何推断同时约束了填充区域和阴影方向，两者不可分离。

## 新题 9：平衡点轨道滑动印章

**组合逻辑**：[射线延伸](创新：从轨道点向上下投射测距而非从控制像素出发) → 距离比较寻找平衡点(涌现：轨道点的射线距离形成约束方程) → [滑动](创新：滑动目标由距离平衡决定而非进一步) → [印章覆盖/命中处印标记](保留核心)

**来源原语**：射线延伸/ray_extend(ecdecbb3)、投射/perpendicular_cast(ecdecbb3)、印章覆盖/stamp_overlay(ecdecbb3)、命中处印标记/stamp_at_hit(ecdecbb3)、接触标记/contact_marker(ecdecbb3)、滑动/slide(5168d44c)、轨道点/track_dot(5168d44c)、等距排列/evenly_spaced(5168d44c)、沿轨道进一槽位/advance_one_slot(5168d44c → 创新为advance_to_balance_point)、前景对象/foreground_object(5168d44c)

**依赖链**：每个轨道点向上下投射射线测量到最近水平条段的距离，距离值随轨道位置变化（因为条段不是全宽贯穿条，不同列位置能"看到"不同的条段）→ 寻找唯一的上下距离相等的轨道点作为平衡点 → 精灵体滑动到该平衡点 → 在上下命中的条段位置印章接触标记。射线距离决定了滑动目标，滑动位置决定了印章位置，三者链式依赖。

红色精灵体沿绿色轨道滑动到上下方最近蓝色水平条段等距的唯一平衡位置，并在上下命中的条段处各印一个3x3红色接触标记。

**输入结构**：黑(0)背景，约16x14网格。一行等距绿(3)轨道点水平排列在网格中部某行（间距相等，至少6个点）。一个红(2)小精灵体（3~5像素的4-连通小图形）覆盖在某个轨道点上。若干蓝(1)水平条段（非贯穿行：每段为同一行上连续的蓝(1)像素，宽度至少3像素但不覆盖全行）分布在轨道上方和下方的不同行上。生成约束：条段不与轨道点重叠（不在轨道行上）；条段之间互不重叠；轨道上方至少2个条段，下方至少2个条段；条段在水平方向的覆盖范围不同（不同列位置能看到不同的最近条段）；恰好存在一个轨道点，从该点所在列向上和向下分别到最近蓝(1)像素的行距离相等。

**规则**：
1. 对每个轨道点，从其所在列向上逐行扫描，找到最近的蓝(1)像素所在行，计算行距离d_up。若该列上方无蓝(1)像素，d_up = 无穷大。同理向下扫描得d_down。
2. 找到唯一满足 d_up = d_down（且均为有限值）的轨道点——平衡点。
3. 将红(2)精灵体从当前位置沿轨道水平平移到平衡点轨道位置（保持精灵体形状不变，仅水平平移使精灵体中心对齐平衡点）。精灵体离开的原位置恢复为绿(3)轨道点（如果原本被精灵体覆盖的话）。
4. 在平衡点列上方d_up处命中的蓝(1)像素位置，以该像素为中心印一个3x3红(2)方块标记，标记中心恢复为蓝(1)。同样在下方d_down处命中的蓝(1)像素位置印一个3x3红(2)方块标记，中心恢复蓝(1)。3x3标记中超出网格的像素忽略。
5. 其他所有蓝(1)条段、绿(3)轨道点保持不变。

**关键洞察**：精灵体不是简单地"前进一个槽位"（源题规则），而是在轨道上搜索到两侧条段等距的唯一平衡位置。条段是局部的（非贯穿行），所以不同轨道点"看到"的最近条段可能不同——平衡点的位置取决于条段的水平覆盖范围与轨道点的列对齐关系，这是一个非显然的几何搜索问题。

## 新题 10：指示像素计数编码拼接偏移

**组合逻辑**：[邻接 + 计数](创新：指示像素数量编码为数值而非指示轴/色) → 数值编码偏移量(涌现：计数产生的数值成为几何参数) → [拼接/偏移放置](创新：偏移量由计数动态决定而非固定为1)

**来源原语**：指示像素/indicator_pixel(b775ac94)、邻接/adjacency(b775ac94)、指示定镜像与色/indicator_sets_axis_color(b775ac94 → 创新为indicator_count_sets_offset)、拼接/stitch(8618d23e)、偏移放置/offset_placement(8618d23e)、对角偏移/diagonal_offset(8618d23e)、半区域/half_region(8618d23e)、分隔填充/separator_fill(8618d23e)、计数/counting(e50d258f)

**依赖链**：上半区红色指示像素的数量编码行偏移量R，下半区绿色指示像素的数量编码列偏移量G → 偏移量决定了拼接时下半区相对上半区的对角偏移步长 → 输出网格的总尺寸由半区尺寸加上偏移量确定。指示像素的数量（而非位置或颜色属性）是关键信息，且R和G分别独立编码两个维度的偏移，需要对比多个示例才能区分"R控制行偏移、G控制列偏移"的映射方向。

统计上半区红色指示像素数量R和下半区绿色指示像素数量G，以R为行间距、G为列偏移，将上下半区拼接到栗色画布上。

**输入结构**：黑(0)背景，约10x10网格，偶数行（上下半区各占一半行数）。上半区包含一个蓝(1)为主色的图案（4-连通的单色或多色小图形，占据半区的部分像素），图案边缘4-邻接有若干红(2)指示像素（每个红(2)像素至少与一个蓝(1)像素4-邻接）。下半区包含一个黄(4)为主色的图案，图案边缘4-邻接有若干绿(3)指示像素（每个绿(3)像素至少与一个黄(4)像素4-邻接）。生成约束：红(2)指示像素数量为1~3个；绿(3)指示像素数量为1~3个；上下半区的图案形状不同；指示像素不与另一半区的图案4-邻接。

**规则**：
1. 统计上半区中红(2)指示像素的数量，记为R。统计下半区中绿(3)指示像素的数量，记为G。
2. 将上半区中的红(2)指示像素去除（设为黑(0)），将下半区中的绿(3)指示像素去除（设为黑(0)）。
3. 创建输出网格，行数 = 上半区行数 + R + 下半区行数，列数 = max(上半区列数, 下半区列数 + G)。整个输出网格用栗(9)填充。
4. 将处理后的上半区（去除红色指示像素后的所有像素）复制到输出网格的左上角（从第0行、第0列开始），其中黑(0)像素也复制（覆盖栗(9)）。
5. 将处理后的下半区（去除绿色指示像素后的所有像素）复制到输出网格中，起始位置为第(上半区行数 + R)行、第G列，其中黑(0)像素也复制。
6. 上半区与下半区之间的R行栗(9)间隔以及左侧的G列栗(9)偏移形成可见的L形栗色间隙。

**关键洞察**：源题中对角偏移固定为(1行, 1列)，这里偏移量由两组指示像素的数量分别编码——红色数量决定行间距，绿色数量决定列偏移。指示像素在源题(b775ac94)中通过位置和颜色编码镜像轴和副本颜色，这里通过数量编码数值参数，完全不同的信息提取方式。仅看一个示例无法确定R编码行还是列，需要对比多个示例中R、G值与偏移方向的对应关系。
