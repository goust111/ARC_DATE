## 新题 1：借轴射线擦除

**组合逻辑**：[axis_borrowed](已有) + [mirror](创新：将标记像素跨对称轴反射生成虚拟标记) → [ray_extend](创新：从真实和虚拟两个标记同时投射射线) → [erase + hit_erases_whole](已有)

**来源原语**：axis_borrowed / symmetric_object（参考题 4c5c2cf0）、mirror（参考题 c9e6f938 / bc4146bd）、ray_extend / hit_erases_whole（参考题 2f767503）、erase（参考题 2f767503）

**依赖链**：对称体的对称轴被"借用"来反射标记像素，生成一个虚拟标记 → 真实标记与虚拟标记各自沿垂直于对称轴的方向投射射线 → 射线命中的目标对象整体被擦除。删去对称轴检测，则无法确定虚拟标记位置；删去射线投射，则无法选择擦除目标；删去擦除规则，则射线无可见效果。

将对称体的几何属性作为空间操作的参数来源——对称轴不再用于补全对称体自身，而是用于生成另一个对象的镜像副本，这是源题中不存在的结构关系。

**输入结构**：约 15x15 网格，黑(0) 背景。包含以下元素：
- 一个蓝(1) 的多像素对象（约 8~14 像素，4-连通），具有精确的单轴镜像对称性（对称轴为垂直线或水平线，各示例可不同）。该对象形状不固定（可以是十字、菱形、对称的不规则形状等），但保证有且仅有一条对称轴。
- 一个红(2) 标记像素（单像素），位于对称轴的一侧，不与蓝色对象相邻。
- 若干绿(3) 目标对象（各 3~6 像素，4-连通，形状不规则且各不相同），散布在网格中，互不接触，也不与蓝色对象或红色标记接触。
- 生成约束：红色标记关于对称轴的镜像位置必须落在背景上（不与任何对象重叠）；至少有一个绿色对象被射线命中，至少有一个不被命中。

**规则**：
1. 检测蓝(1) 对称体的唯一对称轴（垂直或水平）。
2. 将红(2) 标记像素关于该对称轴做镜像反射，得到虚拟标记位置（该位置在输出中不绘制任何标记，仅用于射线起点计算）。
3. 确定射线方向：垂直于对称轴。若对称轴为垂直线，则射线方向为水平（向左和向右各一条）；若对称轴为水平线，则射线方向为垂直（向上和向下各一条）。
4. 从真实标记位置沿射线方向（两个相反方向）各投射一条射线，直至离开网格边界。从虚拟标记位置同样沿射线方向投射两条射线。共四条射线。
5. 对于每个绿(3) 目标对象：若该对象的任意像素被上述四条射线中的任何一条经过，则将该对象的所有像素重涂为黑(0)（整体擦除）。
6. 所有其他像素（蓝色对称体、红色标记、未被命中的绿色目标、背景）保持不变。

**关键洞察**：对称体不参与变换本身——它的对称轴是一个隐式参数，决定了虚拟标记的位置和射线的方向。求解者必须同时发现"对称轴借用"和"射线命中即整体擦除"两个规则，且需要对比多个示例（对称轴方向不同的情况）才能确认射线方向始终垂直于对称轴。

## 新题 2：配对围墙洪水擦除

**组合逻辑**：[diagonal_pairing + pair_defines_rect](已有) → [fill](创新：填充矩形作为墙壁而非最终输出) → [flood_fill + inside_outside_partition](已有) → [erase + hit_erases_whole](创新：擦除对象基于洪水可达性而非射线)

**来源原语**：diagonal_pairing / pair_defines_rect（参考题 56ff96f3）、fill（参考题 56ff96f3）、flood_fill / inside_outside_partition / indicator_pixel / wall_boundary（参考题 7491f3cf）、erase（参考题 2f767503）

**依赖链**：同色像素对定义矩形的对角 → 填充矩形形成墙壁结构 → 指示像素发起洪水填充，被墙壁阻挡，将空间分为可达区和不可达区 → 位于可达区内的目标对象被整体擦除。配对关系创造了源题中不存在的围墙拓扑；洪水填充不再用于选择源面板，而是用于决定擦除目标。

**输入结构**：约 14x14 网格，黑(0) 背景。包含以下元素：
- 2~3 种前景色（如蓝(1)、红(2)、绿(3)），每种颜色恰好出现两次，各为孤立单像素——这些是角标记。每对同色像素的位置保证：它们定义的轴对齐矩形互不重叠（矩形边界可以共线但内部不交叉）。
- 一个黄(4) 指示像素（单像素），位于所有矩形围成的区域之外（即从黄色像素出发沿网格边界可到达网格边缘，不穿过任何矩形）。
- 若干橙(7) 目标对象（各 2~5 像素，4-连通），散布在网格中。生成约束：每个橙色对象要么完全在某个矩形围成的内部区域内，要么完全在外部区域内（不横跨墙壁）；至少有一个橙色对象在洪水可达区内，至少有一个在不可达区内。
- 角标记与橙色对象互不接触；黄色指示像素与角标记互不接触。

**规则**：
1. 对每种前景色（蓝(1)、红(2)、绿(3)），取其两个像素的坐标，计算轴对齐矩形的边界框，将该边界框内所有像素填充为该颜色。这些填充矩形构成墙壁。
2. 从黄(4) 指示像素出发，做 4-连通洪水填充，将墙壁像素（任何非黑(0)、非黄(4)、非橙(7) 的像素）视为障碍。所有被洪水到达的像素（含指示像素自身）构成"可达区"。
3. 对于每个橙(7) 目标对象（4-连通分量）：若该对象的所有像素均在可达区内，则将其所有像素重涂为黑(0)（擦除）。若对象有任何像素不在可达区内，则整个对象保留不变。
4. 墙壁（填充矩形）、黄色指示像素、以及未被擦除的橙色对象在输出中保持不变。

**关键洞察**：同色像素对看似是简单标记，实际上它们隐式定义了矩形墙壁，这些墙壁将网格空间分区。求解者必须先发现"配对→矩形→墙壁"这一非显然的构建链，才能理解哪些橙色对象会被擦除。需对比多个示例才能排除"按位置""按颜色"等错误假设，确认擦除取决于洪水可达性。

## 新题 3：连线屏障截断列传播

**组合逻辑**：[draw_line + row_col_align](创新：连线不是连向矩形而是连接行对齐的同色像素对) → [fill + same_column_propagation + fill_column_to_bottom](创新：传播不再无阻碍地到达底部，被水平线截断) ← [collision_stop](创新：碰撞不再停止于矩形表面，而是停止于动态生成的线段)

**来源原语**：draw_line / row_col_align / collision_stop（参考题 2c608aff）、fill / same_column_propagation / fill_column_to_bottom（参考题 d037b0a7）

**依赖链**：行对齐的蓝色像素对之间画水平线，生成屏障 → 红色源像素向下传播，遇到屏障则在屏障上方一格停止 → 屏障的存在与位置直接决定传播的长度。线段绘制和列传播共享同一网格空间，两者的交互产生了源题中不存在的"动态屏障截断"效应。

**输入结构**：约 12x15 网格（宽略大于高），黑(0) 背景。包含以下元素：
- 若干红(2) 源像素（各为单像素），分布在网格的上半区（约前 1/3 行），每个占据不同的列。
- 若干蓝(1) 像素，成对出现。每对蓝色像素在同一行，之间隔着若干列的背景。不同对可以在不同行。每对之间的水平距离至少为 2（即连线至少包含 1 个中间像素）。
- 生成约束：红色像素不与任何蓝色像素同行；每列最多有一个红色源像素；蓝色对连线形成的水平线段之间不在同一行重叠；至少有一个红色像素的正下方存在蓝色连线（会被截断），至少有一个红色像素的正下方无蓝色连线（传播到底部）。

**规则**：
1. 对于每对同行的蓝(1) 像素，画一条水平蓝(1) 线段，填充它们之间（含端点）同行的所有像素。蓝色像素本身保持蓝色。
2. 对于每个红(2) 源像素位于 (r, c)：从该像素开始，向下逐行检查列 c 的像素。若下一行的像素为黑(0) 背景，则将其涂为红(2)；若下一行的像素为蓝(1)（水平线段的一部分）或已到达网格底部，则停止。停止时不覆盖蓝色像素——红色传播的最后一个像素是蓝色线段正上方一行（或网格最后一行）。
3. 若同一列有多条蓝色水平线段在不同行，红色传播在遇到第一条（最近的）时即停止。
4. 蓝色线段、红色源像素及其传播、以及未被涉及的黑色背景构成最终输出。红色不覆盖蓝色。

**关键洞察**：蓝色像素对之间的连线不是装饰——它们是阻断红色向下传播的物理屏障。求解者必须先理解蓝色对连线规则（同行配对连线），再理解红色传播规则（向下直至碰撞蓝色线段），两个规则在空间上交互才决定最终输出。仅看单个示例可能误以为红色传播有固定长度。

## 新题 4：标记距离决定嵌套层叠画序

**组合逻辑**：[complete + nested_rectangle + outer_to_inner](已有) + [distance_mapping + manhattan_distance](创新：距离不用于生成同心环，而用于决定矩形的绘制优先级) → [stacking + conflict_priority](创新：冲突解决不按固定的大-小顺序，而按与标记的距离动态排序)

**来源原语**：complete / nested_rectangle / sparse_rect_layer / outer_to_inner / large_first_small_over（参考题 5751f35e）、distance_mapping / manhattan_distance / marker_pixel（参考题 aaef0977）、stacking / conflict_priority（参考题 03560426）

**依赖链**：稀疏的矩形层被补全为实心矩形 → 标记像素的位置决定了每个矩形的优先级（以矩形中心到标记的曼哈顿距离排序）→ 矩形按距离从远到近依次绘制，近者覆盖远者。标记位置改变则叠画顺序改变，最终可见颜色分布随之改变。距离映射从"生成颜色环"被改造为"决定绘制序"，这是全新的结构关系。

**输入结构**：约 15x15 网格，黑(0) 背景。包含以下元素：
- 3~5 种前景色（如蓝(1)、红(2)、绿(3)、黄(4)、灰(5)），每种颜色有若干散落的像素（3~8 个），这些像素都位于同一个轴对齐矩形的边界框上（不一定覆盖整条边）。这些是稀疏矩形层的采样点。
- 各颜色的边界框面积互不相同（保证无面积并列）。边界框之间存在嵌套或部分重叠关系（不全嵌套，允许部分重叠）。
- 一个橙(7) 标记像素（单像素），位于网格中某处（可以在某个矩形内部，也可以在所有矩形外部）。
- 生成约束：移动标记到不同位置时，至少有一对矩形的距离排序会改变（即距离排序不退化为固定的面积排序）；各颜色的稀疏像素足以唯一确定其矩形边界框（至少标记两条不同的边）。

**规则**：
1. 对每种前景色，取其所有像素的轴对齐边界框作为该颜色的完整矩形。
2. 计算橙(7) 标记像素到每个矩形中心（边界框中心，若为非整数则取四舍五入）的曼哈顿距离。
3. 按距离从大到小的顺序依次绘制矩形（距离最大的最先画，距离最小的最后画，后画覆盖先画）。若两个矩形距离相同，则面积较小者后画（小的覆盖大的）。
4. 橙(7) 标记像素在最终输出中保留（画在最顶层）。
5. 所有矩形外部的区域保持黑(0) 背景。

**关键洞察**：叠画顺序不是由矩形的几何嵌套关系决定，而是由标记像素到每个矩形中心的曼哈顿距离决定。同样的一组矩形，标记在不同位置会产生不同的叠画结果。求解者必须对比多个示例（标记位置不同）才能排除"大的先画""外层先画"等错误假设，发现距离才是排序依据。

## 新题 5：射线选择性激活框架填充

**组合逻辑**：[ray_extend + marker_bar + control_pixel](已有) → [ray_intersection](创新：射线命中不触发擦除，而是触发洪水填充) → [flood_fill](创新：填充的目标是框架围成的封闭区域，不是面板分区) + [hit_erases_whole](创新反转：命中即整体"激活"而非擦除)

**来源原语**：ray_extend / marker_bar / control_pixel / ray_intersection（参考题 2f767503）、flood_fill / enclosed_region（参考题 7491f3cf / ac6f9922）、rectangle（参考题 56ff96f3 / b527c5c6）

**依赖链**：标记条和控制像素确定射线方向 → 射线扫过网格，检测哪些矩形框架被穿过 → 被穿过的框架内部做洪水填充（变实心），未被穿过的保持空心轮廓。射线的选择性与填充的激活形成紧耦合——射线决定"哪些"框架变化，填充决定"怎样"变化。

**输入结构**：约 15x17 网格，黑(0) 背景。包含以下元素：
- 4~6 个矩形框架（单像素宽的轮廓），各为不同的前景色（如蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、品红(6)）。框架大小不一（宽和高各在 3~6 之间），在网格中散布，互不重叠，互不接触（框架之间至少间隔 1 像素背景）。
- 每个框架内部全为黑(0) 背景（空心）。
- 一个由三个灰(5) 像素组成的直线标记条（水平或垂直），位于网格边缘附近，不与任何框架重叠。
- 一个灰(5) 控制像素，与标记条中心像素相邻（4-邻接），位于标记条的一侧。标记条和控制像素共同确定射线方向。
- 生成约束：若标记条颜色与某框架颜色相同（均为灰(5)），则通过位置区分（标记条在网格边缘区域，框架在中心区域）。射线路径上至少穿过 2 个框架，至少有 1 个框架不在射线路径上。

**规则**：
1. 从标记条中心像素出发，沿远离控制像素的方向投射一条直线射线（水平或垂直），直至离开网格边界。
2. 遍历所有矩形框架。若射线经过该框架的任何轮廓像素（射线与框架轮廓有交点），则该框架被"激活"。
3. 对每个被激活的框架：将其内部所有黑(0) 像素填充为该框架的轮廓颜色（空心→实心）。
4. 未被射线穿过的框架保持空心轮廓不变。
5. 标记条、控制像素、以及射线路径上的背景像素均不改变（射线本身不可见，不在输出中绘制）。

**关键洞察**：射线是一个隐形的选择器——它不留痕迹，但决定了哪些框架从空心变为实心。求解者需同时发现射线的方向规则（由标记条和控制像素决定）和激活效果（命中→填充），并需多个示例确认射线本身不画线、未命中框架不变。

## 新题 6：洪水分区内逐行局部翻转

**组合逻辑**：[flood_fill + wall_boundary + inside_outside_partition](已有) → [local_reverse + independent_side_reverse](创新：翻转不作用于固定的中心分隔像素两侧，而作用于洪水分区确定的"内部"区域中的每一行)

**来源原语**：flood_fill / wall_boundary / inside_outside_partition / indicator_pixel（参考题 7491f3cf）、local_reverse / center_symmetry / independent_side_reverse / pixel_segment（参考题 833966f4）

**依赖链**：墙壁像素形成封闭边界 → 洪水填充从指示像素出发确定"外部"区域，剩余为"内部"→ 内部区域中每行的非背景像素序列被原地翻转，外部区域不变。洪水分区决定翻转范围，翻转改变内部像素排列。两者共同决定输出，缺一不可。

**输入结构**：约 11x11 网格，黑(0) 背景。包含以下元素：
- 灰(5) 墙壁像素组成一个封闭的不规则环形边界（4-连通环，保证将网格分为内外两个区域）。墙壁不碰触网格边缘（即外部区域与网格边缘相连）。墙壁形状在不同示例中不同（不固定为矩形）。
- 一个黄(4) 指示像素位于墙壁外部（与网格边缘在同一 4-连通分量中）。
- 墙壁内部区域包含若干行的彩色像素图案：各行中有不同颜色的非背景像素（如蓝(1)、红(2)、绿(3) 等），形成在行内有意义的左右排列顺序。内部不同行的非背景像素数量和颜色组合可以不同。
- 墙壁外部区域（除指示像素外）可以有少量装饰性的彩色像素（如橙(7)），用于迷惑。
- 生成约束：内部区域至少有 3 行包含 2 个以上非背景像素（使得翻转有可观测效果）；外部装饰像素（若有）在翻转前后的位置不变（因为它们不在内部区域）。

**规则**：
1. 从黄(4) 指示像素出发，做 4-连通洪水填充，将灰(5) 墙壁像素视为障碍。所有被洪水到达的像素构成"外部区域"。
2. 未被洪水到达、且不是墙壁的像素构成"内部区域"。
3. 对内部区域的每一行独立处理：提取该行中所有属于内部区域的像素位置及其颜色值，将这些颜色值的顺序翻转（左右互换），然后放回原位置。即若该行内部区域像素从左到右的颜色序列为 [A, B, C, D]，则变为 [D, C, B, A]，仍在原来的列位置上。
4. 墙壁像素、指示像素、外部区域的所有像素（含装饰像素）保持不变。

**关键洞察**：外部的装饰像素不受影响——只有墙壁围住的内部像素才被逐行翻转。求解者需先识别墙壁和洪水分区机制（哪些像素算"内部"），再发现内部像素的逐行翻转规则。仅看单个示例可能误以为是全局水平镜像或某种重涂色。

## 新题 7：重叠矩形解码叠画序提取

**组合逻辑**：[stacking + conflict_priority](已有，但方向反转：从叠画结果反推叠画序) → [extract_summary + compress](创新：摘要提取不再从表格槽中读颜色，而是从重叠遮挡关系中推断优先级序列)

**来源原语**：stacking / conflict_priority / solid_rectangle / corner_overlap（参考题 03560426）、extract_summary / compress / contained_in（参考题 ac6f9922）

**依赖链**：多个实心矩形相互重叠，可见颜色反映遮挡关系 → 从每个重叠区域的可见颜色推断两两优先级 → 将所有两两比较汇总为全序 → 输出一行颜色序列表示从底到顶的叠画顺序。这是一个解构型谜题：输入是操作的结果，求解者需反向推理出操作参数。

**输入结构**：约 12x12 网格，黑(0) 背景。包含以下元素：
- 4~5 个不同颜色的实心矩形（如蓝(1)、红(2)、绿(3)、黄(4)、灰(5)），大小不一（宽和高各在 3~6 之间）。
- 矩形之间存在部分重叠：每对相邻优先级的矩形至少有 1 个像素的重叠区域。在重叠区域中，只有优先级最高（最后绘制）的矩形颜色可见。
- 每个矩形至少有部分区域未被其他矩形遮挡（可见其原始颜色和大致形状）。
- 生成约束：叠画顺序是一个全序（不存在环形遮挡）；叠画顺序与矩形面积无单调关系（即不是简单的"大的在下小的在上"），也与颜色编号无关；至少有 3 对矩形存在直接重叠（不靠传递推断）。

**规则**：
1. 识别所有不同颜色的矩形。对于每个颜色，其完整矩形区域由该颜色可见像素的轴对齐边界框确定（被遮挡的像素不可见，但边界框可从可见边缘推断）。
2. 对于每个重叠区域（两个矩形边界框的交集），观察该区域的可见颜色——该颜色对应的矩形优先级高于另一个。
3. 从所有两两比较中推导出完整的从底到顶的叠画顺序。
4. 输出一个 1 行 N 列的网格（N = 矩形数量），从左到右依次为从底层到顶层的矩形颜色。

**关键洞察**：这是一个逆向推理题——输入是叠画的最终结果，输出是叠画的执行顺序。求解者不能简单读取颜色，必须在重叠区域做两两比较来推断全序。需对比多个示例才能确认输出的排列方向（左=底层、右=顶层）以及排除按面积、按颜色编号排序等错误假设。

## 新题 8：边缘填充角点生成对角射线

**组合逻辑**：[edge_pad + border_row_col + corner_extends_both](已有) → [ray_extend + diagonal_dir](创新：对角射线的起点和颜色由填充后的角像素决定，而非输入中预设的正方形) + [outward_copy](创新：边缘复制不只是扩展尺寸，还创造了射线发射源)

**来源原语**：edge_pad / border_row_col / corner_extends_both / outward_copy（参考题 e633a9e5）、ray_extend / diagonal_dir / square / canvas_boundary / color_diag_corner_edge（参考题 5c0a986e）

**依赖链**：3x3 彩色图案先做边缘填充扩展为 5x5 → 5x5 结果的四个角像素成为对角射线的发射源 → 从每个角沿向外对角方向投射射线直至网格边界，射线颜色等于该角像素的颜色。边缘填充决定了角像素的颜色（它们是原 3x3 四角的复制），角像素颜色又决定了射线颜色。

**输入结构**：约 13x13 网格，黑(0) 背景。包含以下元素：
- 网格中心放置一个 3x3 的彩色图案块，9 个像素中包含 2~4 种不同的非黑色颜色（如蓝(1)、红(2)、绿(3)、黄(4) 等的组合）。该图案不要求对称——四个角像素的颜色可以各不相同，也可以部分相同。
- 3x3 图案块周围全为黑(0) 背景。
- 生成约束：3x3 图案的四个角像素至少有 2 种不同颜色（使得四条射线的颜色差异可观察）；网格大小保证每个角的对角射线至少延伸 3 个像素才到达边界。

**规则**：
1. 将 3x3 图案做边缘填充：顶行复制到上方一行，底行复制到下方一行，左列复制到左方一列，右列复制到右方一列。四个角位置由相邻边的交汇确定（如左上角 = 原图案左上角像素）。结果为 5x5 图案，放置在网格中心。
2. 取 5x5 图案的四个角像素：左上角 (r1,c1)、右上角 (r1,c2)、左下角 (r2,c1)、右下角 (r2,c2)。
3. 从左上角沿左上方向（行-1，列-1）投射射线，直至离开网格。射线颜色 = 左上角像素颜色。
4. 从右上角沿右上方向（行-1，列+1）投射射线，直至离开网格。射线颜色 = 右上角像素颜色。
5. 从左下角沿左下方向（行+1，列-1）投射射线，直至离开网格。射线颜色 = 左下角像素颜色。
6. 从右下角沿右下方向（行+1，列+1）投射射线，直至离开网格。射线颜色 = 右下角像素颜色。
7. 5x5 图案本身（含填充的边缘）保留在输出中。射线像素绘制在背景上，不覆盖图案。

**关键洞察**：对角射线的颜色不是直接从输入的 3x3 图案读取的——它们来自边缘填充后 5x5 结果的角像素。虽然 5x5 的角像素颜色等于 3x3 的角像素颜色（因为边缘填充的角 = 原角的复制），但求解者必须理解边缘填充的完整机制才能推断 5x5 的整体形态，特别是非角位置的边缘像素颜色。需对比多个示例（不同的 3x3 图案）才能确认射线颜色由角像素决定，而非由其他位置的像素决定。
