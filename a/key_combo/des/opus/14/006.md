## 新题 1：滑动距离驱动同心方框生长

**组合逻辑**：[滑动(sliding)](创新：滑动距离成为后续生长参数) → [计数(counting)](创新：计量移动路径长度) → [生长(grow)](创新：层数由滑动距离决定而非固定种子间距)

**来源原语**：滑动(sliding, a79310a0)、生长(grow, 5c2c9af4)、计数(counting, d4b1c2b1)、前景对象(foreground_object, a79310a0)、种子像素(seed_pixel, 5c2c9af4)、同心方框层(concentric_layer, 5c2c9af4)、标记像素(marker_pixel, faa9f03d/25d487eb)、方向指示(direction_indication, 25d487eb)

**依赖链**：灰(5)标记像素指定滑动方向 → 对象沿该方向滑到网格边界 → 滑动距离（质心移动的格数）被计量 → 该距离除以 2（向下取整）决定在原始位置生长的同心方框层数。删掉滑动则无法知道层数；删掉计数则不知道生长多少层；删掉生长则原始位置没有输出。

将小型前景对象从其初始位置滑向网格边界，并在其出发位置以滑动距离编码的层数生长同心方框。

**输入结构**：约 15x15 的黑(0)背景网格。含 2-3 个单色 4-连通小图形（各 2-4 像素，颜色互不相同，均非黑(0)、非灰(5)，如蓝(1)、红(2)、绿(3)）。每个图形的某一条基本方向边（上/下/左/右）外侧恰好有一个灰(5)像素作为方向标记，标记与图形边缘曼哈顿距离为 1。不同图形的标记可指向不同方向。各图形及其标记互不接触，且沿各自滑动方向到网格边界之间没有其他前景像素阻挡。生成约束：每个图形的滑动距离（质心到达边界后的质心位移格数）至少为 4，保证至少 2 层同心方框。

**规则**：
1. 对每个前景图形，识别其相邻的灰(5)标记像素。标记所在方向为"来源侧"，图形沿**远离标记的方向**（即来源侧的反方向）滑动。标记像素随后被擦除（变为黑(0)）。
2. 图形沿滑动方向整体平移，直到图形的任一像素到达网格边界行/列为止。记录图形质心（边界框中心，向下取整）移动的格数 D。
3. 在图形**原始位置的质心**处，以该图形的颜色绘制同心方框。最内层为质心处 1 个像素，第 k 层（k=1,2,...）为以该像素为中心、边长 2k+1 的正方形的边框。共绘制 floor(D/2) 层（不含中心像素本身）。超出网格边界的同心方框像素舍弃。
4. 滑动后的图形保持原形状和原颜色绘制在新位置。
5. 若两个图形的同心方框像素重叠，按图形在输入中边界框左上角从左到右、从上到下的顺序，后处理的覆盖先处理的。

**关键洞察**：滑动是一种运动操作，同心生长是一种生成操作；两者通过"滑动距离"这一中间量耦合——距离越大层数越多。观察者需同时推断方向规则和距离-层数映射，两者缺一不可。

## 新题 2：分区结构双重编码——内容与放大倍率

**组合逻辑**：[计数(counting)](创新：统计非空分区数作为放大因子) + [像素放大(pixel_upscale)](创新：倍率来自同一结构的填充统计而非全局色数)

**来源原语**：计数(counting, 1190e5a7/d4b1c2b1)、像素放大(pixel_upscale, d4b1c2b1)、分隔栅格(divider_grid, 1190e5a7)、矩形区域(rectangular_region, 1190e5a7)、网格采样(grid_sampling, 90c28cc7)、分区数定输出尺寸(partition_sets_size, 1190e5a7 → 创新)、色数决定倍率(color_count_scale, d4b1c2b1 → 创新为填充区数决定倍率)

**依赖链**：红(2)分割条将网格切分为 R x C 个区域 → 每个区域内可能有或无一个彩色像素 → 非空区域的总数 K 成为放大因子 → 以 R x C 的"有/无"模式作为低分辨率图案 → 将其放大 K 倍输出。分区结构同时提供图案内容和缩放参数，两个用途不可分割。

将红色条分隔的网格视为低分辨率图案，以其中非空区域的计数作为像素放大倍率输出。

**输入结构**：约 12x12 的黑(0)背景网格。红(2)单像素宽的水平条和垂直条贯穿整个网格宽度/高度，将网格分为 R x C 个矩形区域（R、C 各 2-4）。每个区域内部尺寸相同（至少 2x2）。部分区域正中央放置一个彩色像素（颜色非红(2)、非黑(0)，可为蓝(1)、绿(3)、黄(4)等不同颜色），其余区域内全为黑(0)。生成约束：非空区域数 K 满足 2 <= K <= 4，以保证输出尺寸合理（最大 4R x 4C）。不同示例的 K 值应不同。

**规则**：
1. 识别红(2)分割条，确定 R x C 的分区网格。
2. 构建 R x C 的低分辨率图像：若区域内含彩色像素，该位置取该像素的颜色；若区域为空，该位置取黑(0)。
3. 统计低分辨率图像中非黑(0)像素的总数 K。
4. 将低分辨率图像进行 K 倍像素放大：每个像素替换为 K x K 的同色实心方块。
5. 输出仅包含放大后的图像，不包含红色分割条。

**关键洞察**：同一个分区结构被双重使用——既是内容的载体（哪些位置有什么颜色），又是缩放参数的来源（非空位置的数量）。求解者必须遍历所有分区才能同时获取图案和倍率。

## 新题 3：面积排序驱动的链式精灵对接

**组合逻辑**：[面积分级(area_ranking)](创新：面积决定对接顺序而非颜色) → [对接拼合(docking)](创新：从双体对接扩展为有序链式对接) → [裁剪(crop)]

**来源原语**：对接拼合(docking, 20270e3b)、计数(counting, 多题)、裁剪(crop, 28bf18c6)、精灵体(sprite, 28bf18c6/20270e3b)、连接点(connector_pixel, 20270e3b)、连通分量(connected_component, e8593010)、对接对齐(docking_alignment, 20270e3b)、面积分级(area_ranking, e8593010)、连接点颜色匹配(connector_color_match, 20270e3b)、链式连接(chain_linkage, 84551f4c → 创新为对接链)

**依赖链**：精灵体按像素面积降序排列 → 最大精灵体作为底座 → 依次将下一个精灵体通过共享连接色对接到当前组合体上 → 对接改变组合体的形态，影响后续连接点的可用位置 → 最终裁剪。面积排序决定组装顺序，而组装顺序决定空间布局——调换任何两个精灵体的顺序会得到完全不同的结果。

将多个精灵体按面积从大到小、通过颜色匹配的连接点依次拼装为一个组合体并裁剪。

**输入结构**：约 20x20 的黑(0)背景网格。含 3 个分离的单色精灵体，主体均为蓝(1)，形状各异（4-连通，各 4-8 像素，非矩形，具体形状因示例而异）。三者像素面积互不相同。每个精灵体内嵌 1-2 个连接像素，颜色非蓝(1)非黑(0)。连接像素在精灵体间形成配对：精灵体 A 含一个红(2)连接像素，精灵体 B 含一个红(2)和一个绿(3)连接像素，精灵体 C 含一个绿(3)连接像素。A 的面积 > B 的面积 > C 的面积（不同示例中三者的具体面积和形状都不同，但大小关系一致用于验证排序规则）。生成约束：三个精灵体在输入中互不接触，彼此间距至少 3 像素；对接后组合体不超出 20x20 范围。

**规则**：
1. 计算每个精灵体的像素面积（含连接像素），按面积降序排列。最大者为"底座"。
2. 按面积从大到小依次处理剩余精灵体。对于当前待对接的精灵体 P：
   a. 找到 P 与当前组合体共享的连接颜色 C（恰好一种）。
   b. 平移 P，使 P 中颜色为 C 的连接像素与组合体中颜色为 C 的连接像素在水平方向上相邻（P 的连接像素位于组合体连接像素的正右方，共享同一行）。
   c. 将 P 叠印到组合体上。将两个已匹配的连接像素都重涂为蓝(1)。
3. 全部对接完成后，将组合体裁剪到其非黑(0)像素的最小边界框。
4. 输出裁剪后的组合体。

**关键洞察**：对接顺序由面积排序严格决定，而每次对接改变了组合体的空间形态和剩余连接点的绝对坐标。第二次对接的位置依赖于第一次对接的结果——这是一条不可逆的因果链，不能通过单独观察任何一步来推断全局规则。

## 新题 4：多源射线网络的距离优先交叉着色

**组合逻辑**：[射线延伸(ray_cast)](创新：多源同时发射，而非单一对角线的两端) + [碰撞停止(collision_stop)](创新：障碍物阻断射线) + [计数(counting)](创新：距离比较决定交叉点着色)

**来源原语**：射线延伸(ray_cast, 508bd3b6/25d487eb)、计数(counting, 多题)、种子像素(seed_pixel, 5c2c9af4)、射线路径(ray_path, 508bd3b6)、矩形障碍(rect_obstacle, 508bd3b6 → 创新为小型灰色障碍)、碰撞停止(collision_stop, 332f06d7)、端点朝向(endpoint_facing, faa9f03d → 创新为交叉优先级判定)

**依赖链**：各种子同时向四个基本方向发射射线 → 灰色障碍物阻断特定方向的射线 → 射线路径在某些格子交叉 → 交叉格的颜色取决于到达该格的各射线中哪条路径最短 → 障碍物的位置同时影响哪些射线能到达交叉点以及各射线的路径长度。四个层次（发射、阻断、交叉、着色）通过空间几何紧密耦合。

从多个不同色种子像素同时发射基本方向射线，射线被灰色障碍物阻断，在交叉点处以到达距离最短的射线颜色着色。

**输入结构**：约 13x13 的黑(0)背景网格。含 3 个种子像素，颜色互不相同且非黑(0)非灰(5)（如红(2)、蓝(1)、绿(3)）。另有 2-3 个灰(5)小型障碍物，每个为 1x2 或 2x1 的实心条。种子像素不位于网格边界行/列。障碍物不与种子像素相邻。生成约束：至少存在 2 个射线交叉点；不同示例中种子和障碍物的位置不同，使交叉点的颜色分配发生变化。

**规则**：
1. 从每个种子像素向上、下、左、右四个方向发射射线，射线颜色为该种子的颜色。
2. 每条射线逐格延伸。当下一格是灰(5)障碍物像素或网格边界时，射线停止（不覆盖障碍物，不超出边界）。射线不穿过其他种子像素（遇到其他种子时也停止，不覆盖该种子）。
3. 对每个被射线覆盖的非种子格子，记录到达该格的所有射线及各自的路径长度（从种子像素到该格的曼哈顿距离）。
4. 若该格只有一条射线到达，着该射线颜色。若有多条射线到达，着路径长度最短的射线的颜色。若最短路径长度相同，取种子像素行号较小者的颜色；若行号也相同，取列号较小者的颜色。
5. 种子像素保持原色不变。灰(5)障碍物保持不变。

**关键洞察**：灰色障碍物不仅创造"射线阴影"（某些方向的射线被截断），还改变交叉点处的距离对比——移除一个障碍物可能让原本被阻断的射线重新到达某个交叉点并以更短距离夺取着色权，从而改变多个格子的颜色。

## 新题 5：对角方位编码旋转角度并按标记色排列拼接

**组合逻辑**：[对角配对(diagonal_pairing)](创新：对角方位编码旋转参数而非字形内容) → [旋转(rotate)](创新：旋转角度由空间关系隐式编码) → [排序(sorting)] → [裁剪(crop) + 拼接(concatenate)]

**来源原语**：旋转(rotate, 84551f4c)、裁剪(crop, 28bf18c6)、拼接(concatenate, 28bf18c6)、精灵体(sprite, 28bf18c6)、标记像素(marker_pixel, faa9f03d/25d487eb)、对角配对(diagonal_pairing, f35d900a → 创新为方位编码)、方向指示(direction_indication, 25d487eb → 创新为旋转角编码)、沿轴排列(axis_arrangement, 817e6c09)、排序(sorting, 817e6c09)

**依赖链**：标记像素相对精灵体边界框中心的对角方位（东北/东南/西南/西北）编码旋转角度 → 旋转后的精灵体形状改变 → 标记颜色决定输出中的排列顺序 → 裁剪并拼接。标记像素同时承载两条信息（位置→旋转，颜色→排序），缺任一条均无法还原输出。

根据标记像素相对精灵体的对角方位确定旋转角度，再按标记颜色排列后水平拼接。

**输入结构**：约 18x18 的黑(0)背景网格。含 3 个单色小精灵体，每个由同一颜色（如蓝(1)）的 3-6 个 4-连通像素组成，形状互不相同且无旋转对称性（保证旋转后可区分方向）。每个精灵体的边界框外恰有一个标记像素，位于边界框某个角的对角方向（即边界框角外侧的 45 度方向相邻格）。三个标记像素颜色互不相同，取自 {红(2)、绿(3)、黄(4)}。三个精灵体互不接触，各精灵体的边界框互不重叠，间距至少 2 像素。生成约束：每个精灵体边界框为正方形（宽=高），且边长为奇数（如 3x3 或 5x5），以保证旋转后边界框尺寸不变。不同示例中标记的对角方位组合应不同。

**规则**：
1. 对每个精灵体，找到其边界框外侧对角位置的标记像素。确定标记相对于边界框中心的方位：
   - 东北（标记在中心的右上方）→ 旋转 0 度（不旋转）
   - 东南（标记在中心的右下方）→ 顺时针旋转 90 度
   - 西南（标记在中心的左下方）→ 旋转 180 度
   - 西北（标记在中心的左上方）→ 顺时针旋转 270 度
2. 将每个精灵体围绕其边界框中心旋转相应角度。
3. 裁剪每个旋转后的精灵体到其边界框。
4. 按标记颜色排序：红(2) 排第一、绿(3) 排第二、黄(4) 排第三。
5. 将排序后的裁剪精灵体从左到右水平拼接，相邻精灵体之间插入 1 列黑(0)间隔。
6. 标记像素不出现在输出中。

**关键洞察**：标记像素的空间位置（哪个对角）和颜色身份（红/绿/黄）各自编码了不同的变换参数——位置决定旋转角度，颜色决定输出排列。需要对比多个示例才能分别推断这两条独立编码规则，因为单一示例中方位和颜色是混在一起的。

## 新题 6：连通分量面积分类驱动同心方框色带与层数

**组合逻辑**：[计数(counting) + 面积分级(area_ranking)](创新：面积分类同时决定组件重涂色和同心生长的色带结构) → [重涂色(recolor)] + [生长(grow)](两个操作由同一分类结果平行驱动并在空间上交织)

**来源原语**：重涂色(recolor, e8593010)、生长(grow, 5c2c9af4)、计数(counting, d4b1c2b1/1190e5a7)、连通分量(connected_component, e8593010)、同心方框层(concentric_layer, 5c2c9af4)、种子像素(seed_pixel, 5c2c9af4)、面积分级(area_ranking, e8593010)、面积决定颜色(area_determines_color, e8593010 → 创新为面积同时决定颜色和同心层参数)

**依赖链**：黑色连通分量按面积分为三类 → 每类的计数（A1、A2、A3）同时决定两件事：(a) 对应类别的重涂颜色，(b) 同心方框中该颜色的层数 → 同心方框和重涂组件在空间上交织，组件像素优先于同心方框像素。面积分类是一个决策节点，同时向两个操作分发参数。

统计灰色网格上黑色连通分量的面积分布，同时据此重涂各分量并从种子生长出反映面积分布的彩色同心方框。

**输入结构**：约 15x15 的灰(5)背景网格。散布多个黑(0)的 4-连通分量，每个分量的面积恰好为 1、2 或 3（各面积类别至少出现 1 个分量，总共 4-7 个分量）。另有恰好 1 个红(2)种子像素，位于网格内部（不在边界行/列），不与任何黑色分量相邻。生成约束：三种面积类别的分量数量（A1、A2、A3）互不相同，以确保同心色带宽度不同从而可区分；A1+A2+A3 <= 8，以保证同心方框不过大。不同示例中 A1、A2、A3 的值应不同。

**规则**：
1. 识别所有黑(0)的 4-连通分量，按面积分类：面积 1 的分量有 A1 个，面积 2 的有 A2 个，面积 3 的有 A3 个。
2. 重涂各分量：面积 1 → 绿(3)，面积 2 → 蓝(1)，面积 3 → 黄(4)。
3. 以红(2)种子像素为中心，向外生长同心方框边框。从里到外依次为：
   - 第 0 层：中心像素本身，保持红(2)。
   - 第 1 至第 A1 层：颜色为绿(3)（对应面积 1 类的计数）。
   - 第 A1+1 至第 A1+A2 层：颜色为蓝(1)（对应面积 2 类的计数）。
   - 第 A1+A2+1 至第 A1+A2+A3 层：颜色为黄(4)（对应面积 3 类的计数）。
   每一层是以种子为中心、边长为 2k+1 的正方形边框（k 为层号）。
4. 同心方框像素若与已重涂的分量像素重叠，保留分量的颜色（分量优先于同心方框）。超出网格边界的同心方框像素舍弃。
5. 灰(5)背景和不受影响的区域保持不变。

**关键洞察**：面积分类是一个"一次计算、双重使用"的决策节点——它既决定了分量的目标颜色，又决定了同心方框每段色带的宽度。同心方框本质上是面积分布的"空间直方图"，而分量重涂是同一分类的"就地标注"。两个输出视觉上交织在一起，需要同时理解才能完整推断规则。

## 新题 7：三角形定向射线触发沿途闭合区域的交替色填充

**组合逻辑**：[射线延伸(ray_extend)](创新：射线方向由三角形定向确定，且射线充当填充触发器而非视觉路径) + [填充(fill)](创新：填充色在每次穿越闭合区域时交替) + [方向指示(direction_indication)](创新：三角形-底像素结构提供方向)

**来源原语**：射线延伸(ray_extend, 25d487eb/508bd3b6)、填充(fill, a834deea → 创新为射线触发的洪水填充)、三角形(triangle, 25d487eb)、标记像素(marker_pixel, 25d487eb)、方向指示(direction_indication, 25d487eb)、顶点反基底延伸(tip_away_from_base, 25d487eb → 创新为射线源)、奇偶交替选择(alternating_parity_selection, 817e6c09 → 创新为交替填充色)、边框区域(bordered_region, a834deea)

**依赖链**：三角形的底像素确定射线方向 → 射线从顶点射出 → 射线穿过闭合矩形框时触发填充 → 填充颜色在两色之间交替（第 1 个穿越的用底像素色，第 2 个用三角形体色，第 3 个再用底像素色...）→ 未被射线穿越的矩形框不填充。三角形方向决定射线路径，路径决定穿越顺序，顺序决定颜色分配。

从三角形尖端沿其指向射出一条射线，沿途穿越的闭合矩形框按遇到顺序被交替色填充。

**输入结构**：约 14x16 的黑(0)背景网格。含 1 个实心填充三角形（如红(2)，面积约 6-10 像素，由一种颜色填充，呈直角三角形或等腰三角形，朝基本方向之一开口）。三角形底边中央有 1 个颜色与三角形不同的像素作为底标记（如黄(4)），该像素是三角形内唯一的异色像素。另有 3-4 个灰(5)单像素宽边框的闭合矩形框（每个内部约 3x3 至 4x4，内部全为黑(0)），分散在网格上。生成约束：从三角形尖端沿远离底标记的方向发出的射线至少穿过 2 个矩形框，且至少有 1 个矩形框不在射线路径上。不同示例中三角形朝向不同。

**规则**：
1. 识别三角形中唯一的异色底标记像素，确定底标记在三角形中的位置。找到底标记暴露在三角形外侧的方向（即底标记处三角形的开口方向）。射线方向为该开口方向的反方向（即从底标记穿过三角形体指向尖端并继续延伸）。
2. 从三角形尖端（射线方向上三角形的最远像素位置）的下一格开始，沿射线方向逐格绘制射线，颜色为底标记的颜色。射线在到达网格边界时停止。射线穿过灰(5)矩形框边框时继续延伸，不改变边框颜色。
3. 按射线遇到矩形框的先后顺序（离三角形尖端近的先），对被射线穿越（射线至少穿过其边框进入内部）的矩形框进行编号：第 1、3、5...个（奇数序号）矩形框的内部（边框内黑(0)区域）填充为底标记的颜色；第 2、4、6...个（偶数序号）矩形框的内部填充为三角形体的颜色。
4. 未被射线穿越的矩形框保持不变（内部为黑(0)，边框为灰(5)）。
5. 三角形本身（含底标记）保持不变。灰(5)边框保持不变。

**关键洞察**：射线的路径由三角形的几何定向决定，但射线本身不是目的——它是"选择器"，选中哪些矩形框被填充。而填充颜色的交替规则意味着矩形框的空间排列顺序（沿射线方向）隐式编码了颜色分配。移动一个矩形框可能改变后续所有框的颜色奇偶性。

## 新题 8：内嵌标记计数决定旋转拼贴的副本数与角度序列

**组合逻辑**：[计数(counting)](创新：标记数同时编码副本数量和旋转序列) → [裁剪(crop)] → [旋转(rotate)](创新：每个副本的旋转角度由其在序列中的位置决定) → [拼接(concatenate)](创新：拼接为 K 份而非固定 2 份)

**来源原语**：裁剪(crop, 28bf18c6)、拼接(concatenate, 28bf18c6 → 创新为多副本拼接)、旋转(rotate, 84551f4c)、计数(counting, d4b1c2b1/52fd389e)、精灵体(sprite, 28bf18c6)、内嵌标记计数(embedded_marker_count, 52fd389e)、计数决定扩展量(count_determines_expansion, 52fd389e → 创新为计数决定拼接数和旋转序列)、编码映射(encoding_map, 52fd389e)

**依赖链**：精灵体内嵌标记像素的数量 K 同时决定三件事：(a) 裁剪后制作 K 个副本，(b) 第 i 个副本顺时针旋转 i x 90 度，(c) 标记像素在输出中被擦除。K 是连接计数、旋转和拼接的枢纽参数，且标记在输出中消失，迫使求解者从输入中读取后在输出中验证。

裁剪精灵体后，按内嵌标记数制作多份渐进旋转的副本并水平拼接，同时擦除标记。

**输入结构**：约 10x10 的黑(0)背景网格。含 1 个单色精灵体，主体为蓝(1)（4-连通，5-8 像素），其中嵌有 K 个红(2)标记像素（K 为 2 或 3，因示例而异）。精灵体含标记在内的整体为 4-连通。精灵体边界框为正方形（宽=高），且边长为奇数（如 3x3 或 5x5），保证旋转后尺寸不变。精灵体形状不具有 90 度旋转对称性（即旋转 90 度后与原图不同），以确保旋转效果可观察。生成约束：不同示例中 K 的值应不同（一个示例 K=2，另一个 K=3），以便求解者通过对比推断 K 与副本数/旋转的关系。

**规则**：
1. 裁剪精灵体（含红(2)标记像素）到其最小边界框。
2. 统计边界框内红(2)标记像素的数量 K。
3. 生成 K 个副本。第 i 个副本（i 从 0 开始）围绕边界框中心顺时针旋转 i x 90 度：
   - 第 0 个副本：旋转 0 度（原样）
   - 第 1 个副本：旋转 90 度
   - 第 2 个副本（若 K=3）：旋转 180 度
4. 在所有副本中，将红(2)标记像素重涂为蓝(1)（擦除标记）。
5. 将 K 个副本从左到右水平拼接，相邻副本之间插入 1 列黑(0)间隔。
6. 输出拼接后的结果。

**关键洞察**：红色标记像素是"自毁型信息载体"——它们在输入中编码了副本数量和旋转序列，但在输出中被擦除。求解者在输出中只看到蓝色副本的旋转排列，必须回到输入中数红色像素才能理解为什么是这么多个副本、为什么每个旋转了不同角度。
