## 新题 1：色带压缩长度编码精灵位移

**组合逻辑**：[压缩 compress](已有) → [计数 counting](创新：计数对象从独立像素变为压缩后的条带条目数) → [平移 translate](已有) + [擦除 erase](已有)

**来源原语**：压缩 compress、连续重复折叠 dup_collapsed、色带 color_stripe、条带方向 stripe_orient（参考题 746b3537）；计数 counting、计数决定偏移 count_determines_offset、计数器消失 counter_disappears（参考题 e48d4e1a）；平移 translate（参考题 e48d4e1a）；精灵体 sprite（参考题 9bebae7a / 91413438）

**依赖链**：压缩条带得到去重条目数 N → N 作为平移距离 → 条带方向决定平移轴 → 精灵相对条带的位置决定平移朝向。删除压缩步骤则 N 未知；删除方向判断则轴未知；删除位置关系则朝向未知。

将色带压缩后的去重条目数作为位移量，沿垂直于条带的方向将精灵推向条带侧，然后擦除条带。

**输入结构**：约 12x15 的黑(0)背景网格。网格中包含两个元素：(1) 一个 4-连通的单色小图形（精灵），使用红(2)，由 3~6 个像素组成，形状不规则（不同示例中形状不同）；(2) 一段色带区域，贴靠网格的一条边（上、下、左或右边缘），由 2~5 条满宽水平条带（若贴上/下边）或满高垂直条带（若贴左/右边）组成，每条条带厚度 1~3 格，使用互不相同的非黑颜色（如蓝(1)、绿(3)、黄(4)、灰(5)等）。相邻条带颜色不同。精灵与色带之间有若干行/列的黑色空隙，两者不重叠。生成约束：精灵移动后不会超出网格边界。

**规则**：
1. 识别色带区域：找到贴靠网格边缘的、由连续满宽行或满高列组成的矩形区域。判断条带方向——若由满宽行组成则为水平条带，若由满高列组成则为垂直条带。
2. 压缩色带：沿条带法线方向（水平条带沿列方向，垂直条带沿行方向）逐行/逐列读取颜色，将连续相同颜色的行/列折叠为一个条目。设折叠后的条目数为 N。
3. 确定平移轴：水平条带 → 精灵沿垂直方向（上下）移动；垂直条带 → 精灵沿水平方向（左右）移动。
4. 确定平移朝向：精灵向色带所在的边缘方向移动（即朝向色带一侧）。
5. 将精灵的每个像素沿确定的轴和朝向平移 N 格。平移后精灵占据新位置，原位置设为黑(0)。
6. 擦除整个色带区域（设为黑(0)）。
7. 其余像素不变。

**关键洞察**：色带不是装饰——它是一把被编码的标尺：条带的厚度是干扰信息，只有去重后的条目数才是位移指令。需对比多个示例（不同条带厚度但相同条目数产生相同位移）才能归纳出压缩规则。

## 新题 2：缺口射线索引格子块多数色填充框体

**组合逻辑**：[射线延伸 ray_extend](创新：射线不是填色工具而是空间索引指针) + [多数决 majority_vote](已有) → [洪泛填充 flood_fill](已有) + [修补 repair](创新：修补缺口而非修补主体缺陷)

**来源原语**：洪泛填充 flood_fill、射线延伸 ray_extend、空心矩形 rectangular_frame、边框缺口 border_gap、缺口方向决定射线 gap_direction_determines_ray（参考题 551d5bf1）；多数决 majority_vote、填色块 filled_block、分隔行列 separator_row_col、格子格局 lattice_layout、每块取唯一多数色 majority_color_per_block（参考题 af24b4cc）

**依赖链**：缺口位置 → 射线方向 → 射线命中格子块 → 多数决读取该块颜色 → 用该颜色填充对应框体内部 → 修补缺口恢复完整边框。射线是选择器而非涂色器，多数决是解码器而非压缩器。删除射线则不知选哪块；删除多数决则噪声像素导致歧义；删除填充则无输出变化。

每个蓝色框体的缺口发射射线指向格子区域，射线命中的格子块经多数决得到一个颜色，用该颜色填充框体内部并修补缺口。

**输入结构**：约 18x20 的黑(0)背景网格，分为上下两个区域。上方区域（约前 10 行）包含一个矩形格子：由灰(5)分隔行和分隔列将区域划分为 2~3 行 x 3~4 列的等尺寸格子块（每块约 3x3），每块内有一个占多数的非黑非灰颜色（如红(2)、绿(3)、黄(4)等），并混有 1~2 个不同颜色的噪声像素（保证多数色唯一）。下方区域（约后 8 行）包含 2~3 个蓝(1)空心矩形框（4-连通的 1 像素宽实心边框，内部为黑(0)，边框宽高各 4~6 格）。每个框的顶边有且仅有一个非角落位置的缺失像素（缺口），其他三条边完整。各框水平间距至少 2 格，互不重叠。生成约束：每个缺口的列坐标落在格子的某一列带（两条灰色分隔列之间的区域）内；不同框的缺口对应不同的格子列带。

**规则**：
1. 对每个蓝(1)框体，定位其顶边的缺口像素位置 (r_gap, c_gap)。
2. 从缺口向上发射射线：从 (r_gap - 1, c_gap) 开始，逐行递减行号，跳过黑(0)和灰(5)像素，直至遇到第一个非黑非灰非蓝的像素。该像素属于某个格子块。
3. 确定该格子块的边界：从命中像素出发，找到它所在的、被灰色分隔行/列包围的矩形区域。
4. 对该格子块内所有像素计算多数色（出现次数最多的颜色，保证唯一）。
5. 用多数色填充该框体的内部（所有严格在边框内的黑色像素）。
6. 将缺口像素涂为蓝(1)，修补边框使其完整。
7. 格子区域、灰色分隔线、蓝色边框像素均保持不变。

**关键洞察**：缺口不是向外溢出颜色的出口（与参考题 551d5bf1 的用法相反），而是向内选取颜色来源的瞄准器；格子块中的噪声像素使得直接读取射线首个命中色会出错，必须对整个块做多数决才能确定正确填色。

## 新题 3：碎片跨度合并的宽高比编码对称修复轴

**组合逻辑**：[合并对齐碎片 merge_aligned_fragments](已有) → [宽高比判断](创新：合并后矩形的几何属性编码操作选择) → [镜像 mirror](已有，但轴由碎片几何决定) → [补全 reconstruct](已有)

**来源原语**：合并对齐碎片 merge_aligned_fragments、残缺矩形 fragmented_rectangle、行列跨度重叠 span_overlap、连通分量 connected_component（参考题 8fbca751）；镜像 mirror、补全 reconstruct、双轴对称 two_axis_symmetry、遮挡矩形 occluding_rect、对称图案 symmetric_pattern、镜像恢复遮挡区 mirror_recover_occluded（参考题 de493100）

**依赖链**：找到散布的青色碎片 → 按跨度重叠传递合并 → 得到合并包围框的宽高比 → 宽高比决定对称轴类型 → 用该对称轴镜像恢复被遮挡的图案像素。碎片不是待补全的目标（与 8fbca751 不同），而是编码了修复指令的信号源。

散布的小碎片经跨度合并后的宽高比告诉求解者该用哪条对称轴修复被绿色矩形遮挡的图案。

**输入结构**：约 14x14 的黑(0)背景网格。网格大部分区域被一个近似双轴对称的多色图案占据（使用蓝(1)、红(2)、黄(4)等 2~3 种非黑颜色，图案像素总数约 40~60）。图案的对称中心约在网格中心。一个实心绿(3)矩形（宽 3~5、高 3~5 格）覆盖了图案的一个非中心区域，其下方的图案像素被绿色替换而不可见。绿色矩形不跨越对称中心。在图案外围的黑色边界区域中，散布着 3~5 个青(8)的小碎片（每个碎片为 4-连通的 1~3 像素）。这些碎片的包围框在行跨度或列跨度上存在重叠，使得它们可以传递合并为一个整体。生成约束：(a) 碎片合并后的整体包围框宽高比严格不为 1:1（即宽 != 高）；(b) 图案在合并宽高比指定的对称轴上确实具有对称性，使得绿色矩形下方的像素可通过该轴唯一恢复；(c) 不同示例中碎片的分布位置和数量不同，但合并后的宽高比类别（横宽或纵高）保持与对称轴的对应关系一致。

**规则**：
1. 找到所有青(8)像素的 4-连通分量。
2. 传递合并：若任意两个分量的包围框在行跨度上有交集（存在公共行号）或在列跨度上有交集（存在公共列号），则合并为一组。重复直到无法继续合并。
3. 计算合并组的整体包围框（所有分量包围框的并集）。设宽 W、高 H。
4. 若 W > H（横向扁平）：使用水平轴镜像——对称轴为图案的水平中心行。对绿色矩形覆盖的每个格 (r, c)，取其关于水平中心行的镜像位置 (r', c) 的颜色。
5. 若 H > W（纵向狭长）：使用垂直轴镜像——对称轴为图案的垂直中心列。对绿色矩形覆盖的每个格 (r, c)，取其关于垂直中心列的镜像位置 (r, c') 的颜色。
6. 将绿色矩形的每个像素替换为步骤 4/5 中读取到的镜像颜色。
7. 擦除所有青(8)碎片像素（设为黑(0)）。
8. 其余像素不变。

**关键洞察**：散布的青色碎片不是图案的一部分，也不是待修复的缺陷——它们是一个编码信号，只有先合并再读取几何属性才能解码出修复所需的对称轴。需要对比多个示例（碎片排布不同但合并后宽高比类别相同时使用相同的对称轴）才能归纳出编码规则。

## 新题 4：标记计数与基线方位联合约束部分填充

**组合逻辑**：[计数 counting](已有) + [基线对齐 baseline_aligned](创新：基线不是归一化参考线而是填充方向的决定者) → [填充 fill](创新：部分填充而非全量填充，高度由计数决定、起始侧由基线决定) + [擦除 erase](已有)

**来源原语**：计数 counting、计数器像素 counter_pixel、计数决定偏移 count_determines_offset、计数器消失 counter_disappears（参考题 e48d4e1a）；对齐 align、填充 fill、标记行 marker_row、基线对齐 baseline_aligned、最大高度归一化 max_height_normalize（参考题 41ace6b5）；空心矩形 rectangular_frame（参考题 551d5bf1）；擦除 erase（参考题 1c02dbbe）

**依赖链**：灰色标记计数得到 N → 基线与框体的相对位置决定填充起始侧 → 从该侧起填 N 行。N 和方向缺一不可：无 N 则不知填多少，无基线则不知从哪侧开始。

用每个框体旁灰色标记的数量决定填充行数，用框体相对于基线的位置决定从哪一侧开始填充，然后擦除标记和基线。

**输入结构**：约 14x14 的黑(0)背景网格。一条橙(7)水平基线（满宽、1 像素厚）横贯网格，将其分为上下两半（基线大致在中间，但不必严格居中）。网格中分布有 2~3 个不同颜色的空心矩形框（边框 1 像素宽，实心，使用蓝(1)、红(2)、绿(3)等不同颜色），每个框的内部宽高各 3~5 格（即边框外尺寸 5~7 格）。框之间互不重叠，与基线也不重叠（框完全在基线上方或下方）。每个框的旁边（框的包围框外扩 1~2 格的范围内）散布着 1~4 个灰(5)标记像素，这些灰色像素互不 4-相邻、也不与任何框的边框 4-相邻。生成约束：每个灰色像素到最近框边框像素的曼哈顿距离严格小于到其他任何框边框像素的曼哈顿距离（即关联关系无歧义）；每个框关联的灰色像素数 N 不超过该框的内部高度。

**规则**：
1. 将每个灰(5)像素关联到距其边框像素曼哈顿距离最小的框。统计每个框关联的灰色像素数 N。
2. 判断每个框的中心（包围框中心）相对于橙色基线的位置：
   - 若框中心在基线上方：填充从框内部最底行开始，向上延伸 N 行。
   - 若框中心在基线下方：填充从框内部最顶行开始，向下延伸 N 行。
3. 对步骤 2 确定的行范围内，将框内部的所有黑(0)像素涂为该框的边框颜色。
4. 若 N 等于框内部高度，则整个内部被填满。
5. 擦除所有灰(5)标记像素（设为黑(0)）。
6. 擦除橙(7)基线（设为黑(0)）。
7. 框的边框像素和其余黑色背景不变。

**关键洞察**：基线不是数据分隔线，而是一个方向场——它决定每个框的"重力方向"：上方的框从底部向上填充（仿佛颜色从基线侧涌入），下方的框从顶部向下填充。需对比上下两侧各有框的示例才能归纳出这一方向翻转规则。

## 新题 5：降采样掩码分组驱动跨框图案联合补全

**组合逻辑**：[降采样 downsample](已有) → [分组 grouping](创新：分组依据不是颜色而是外部空间掩码) → [对称补全 pattern_union_completion](已有，但作用于掩码定义的组而非颜色定义的组)

**来源原语**：降采样 downsample、单色图案 mono_pattern、整数缩放对应 int_scale_correspond（参考题 6ecd11f4）；分组 grouping、对称补全 pattern_union_completion、彩色边框 colored_frame、内部图案 internal_motif、同色框共享图案 same_color_frames_share_motif、按边框颜色分组 group_by_frame_color（参考题 42918530）

**依赖链**：大图案降采样 → 得到二值掩码 → 掩码将框体分为"覆盖组"和"未覆盖组" → 组内框体联合补全内部图案。分组标准来自外部空间信号而非框体自身颜色，颠覆了参考题 42918530 的"同色即同组"假设。删除降采样则分组标准消失；删除联合补全则组内信息不共享。

大尺度单色图案降采样后形成二值分组掩码，决定哪些小框共享内部图案并相互补全。

**输入结构**：约 20x20 的黑(0)背景网格，分为上下两个区域。上方区域包含一个大的单色黄(4)图案，占据一个矩形区域（如 9x12 或 12x12 格），该图案是一个小型二值模板（如 3x4 或 4x4 的黄/黑模式）的整数倍放大（倍率 k=3，即每个模板像素对应 kxk 的同色方块）。下方区域包含一个 m 行 x n 列的框体网格（m、n 与降采样后的模板尺寸匹配），框体间以 1 格黑色间距排列。每个框体为 3x3 大小（含 1 像素宽彩色边框），边框颜色使用蓝(1)、红(2)、绿(3)中的某一种。框体内部（1x1 的中心格）可能有一个与边框同色的像素（表示该框有内部图案），也可能为黑(0)。同一颜色的框可能分布在掩码的不同区域。生成约束：(a) 降采样后的模板恰好有 m 行 x n 列；(b) 每个分组（覆盖/未覆盖）内至少有 2 个框；(c) 同一组内的框的内部图案取并集后不与任何已有内部像素矛盾。

**规则**：
1. 裁剪黄(4)图案到其包围框。判断缩放倍率 k：k 为黄色图案的包围框宽度除以框体网格的列数（或高度除以行数，两者应一致）。
2. 将黄色图案降采样为 m x n 的二值掩码 M：每个 k x k 块中只要有一个黄色像素，对应掩码单元为 1（覆盖）；否则为 0（未覆盖）。
3. 将框体网格中第 i 行第 j 列的框映射到 M[i][j]。掩码值为 1 的框归入"覆盖组"，掩码值为 0 的框归入"未覆盖组"。
4. 在每个组内，收集所有框的内部像素位置的并集（位置相对于框的左上角）。将该并集中的所有位置在组内每个框中都涂上该框自身的边框颜色。原本已有内部像素的位置保持不变（颜色一致，无冲突）。
5. 擦除整个黄色图案区域（设为黑(0)）。
6. 输出下方区域的框体网格（含补全后的内部图案），保持框间间距和框边框不变。

**关键洞察**：框的边框颜色不决定分组——相同颜色的框可能因掩码覆盖状态不同而分属不同组，进而拥有不同的补全图案。分组的依据隐藏在一个看似无关的大尺度图案中，只有通过降采样建立空间对应关系才能发现。

## 新题 6：遮挡精灵重建排序后按计数裁选平铺

**组合逻辑**：[补全 reconstruct](已有) → [排序 sorting](已有，按遮挡层序) → [计数 counting](已有) → [平铺 tile](创新：平铺对象是重建后的精灵，数量由独立计数器决定)

**来源原语**：堆叠 stacking、排序 sorting、补全 reconstruct、空心矩形精灵 ring_sprite、遮挡碎片 occluded_fragment、遮挡层序 occlusion_order、可见像素定边框 visible_defines_bbox、忽略干扰项 ignore_distractors（参考题 652646ff）；平铺 tile、计数 counting、像素数定尺寸数 pixel_count_sets_size_copies、精灵体 sprite、阵列排布 array_layout（参考题 91413438）

**依赖链**：可见碎片 → 重建完整环形精灵 → 遮挡关系推断层序 → 排序得到优先级队列 → 独立小精灵的前景像素计数得到 K → 取队列前 K 个 → 水平平铺输出。重建、排序、计数三步缺一不可：不重建则精灵不完整无法输出，不排序则顺序不定，不计数则不知取几个。

从重叠的环形碎片中重建完整精灵并按遮挡顺序排序，再由独立小精灵的前景像素数决定输出前几个。

**输入结构**：约 16x16 的黑(0)背景网格。网格主体区域包含 3~5 个相互重叠的环形精灵（ring sprite）：每个精灵为一种颜色（使用蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中的不同颜色），完整形态是 6x6 包围框内的 12 像素空心环（即 6x6 方框的边界像素去掉 4 个角的结果）。由于重叠，下层精灵的部分像素被上层颜色覆盖，呈现为不完整的碎片。每种颜色可能存在 1~2 个不在任何环模板上的噪声像素（干扰项）。在网格的一个角落（与精灵重叠区不交叉的 3x3 区域），有一个独立的 3x3 小精灵，使用灰(5)和黑(0)两色（灰色像素数为 1~5）。生成约束：遮挡关系可构成全序（即任意两个相邻层的精灵在某处有直接遮挡）。

**规则**：
1. 识别所有环形精灵颜色。对每种颜色，找到其像素中所有落在某个 6x6 环模板平移位置上的像素（忽略不在任何模板上的噪声像素）。确定每个精灵的平移位置（模板左上角坐标）。
2. 对每个精灵，检查其模板中应有但实际缺失的像素位置。这些位置当前被某种其他颜色占据——该颜色的精灵在当前精灵之上。由此建立有向遮挡关系图。
3. 对遮挡关系图做拓扑排序，得到从最顶层到最底层的颜色序列。
4. 为每个颜色重建完整的 6x6 环形精灵（12 像素环，黑色内部和角落）。
5. 读取角落中 3x3 小精灵的灰(5)像素数，设为 K。
6. 从拓扑排序序列中取前 K 个颜色。
7. 输出：将这 K 个完整 6x6 环形精灵按拓扑序从左到右水平排列，精灵之间无间距。输出网格大小为 6 行 x (6 * K) 列。背景为黑(0)。

**关键洞察**：小精灵的前景像素数 K 是一个隐式截断指令——它决定输出多少个重建后的精灵。K 不是精灵的总数（总数可能更多），这一点只有对比不同示例（小精灵不同、输出精灵数不同）才能发现。

## 新题 7：双区增长差选择碎片矩形进行跨度合并补全

**组合逻辑**：[计数 counting](已有) + [选择 selection](已有，基于最大增长差) → [合并对齐碎片 merge_aligned_fragments](已有) → [重涂色 recolor](创新：仅对被选中颜色的碎片执行合并补全)

**来源原语**：计数 counting、选择 selection、横分隔线 divider、标记掩码 marker_mask、两区域比较 region_comparison、最大增长差 maximum_growth_difference（参考题 8597cfd7）；补全 complete、重涂色 recolor、残缺矩形 fragmented_rectangle、连通分量 connected_component、行列跨度重叠 span_overlap、合并对齐碎片 merge_aligned_fragments（参考题 8fbca751）

**依赖链**：分隔线划分上下区域 → 每种颜色分别在两区计数 → 计算增长差选出目标颜色 → 仅对目标颜色的下方碎片执行跨度合并 → 在合并包围框内补全为完整矩形。选择步骤是门控条件：错误的颜色选择会导致错误的合并对象。删除计数比较则无法确定目标；删除合并则碎片不连通、无法补全。

比较两种颜色在分隔线上下的像素数增长，增长最大的颜色获得"碎片合并补全"资格。

**输入结构**：约 14x16 的黑(0)背景网格。一条灰(5)水平分隔行（满宽、1 像素厚）将网格分为上下两区。网格中有两种非黑非灰颜色（如青(8)和红(2)）的前景像素，散布在上下两区中。在下方区域，每种颜色的像素形成若干小的 4-连通碎片（每个碎片 2~5 像素），这些碎片属于同一个未完成矩形的残片——不同碎片的包围框在行跨度或列跨度上有交叠，可传递合并。上方区域也有两种颜色的像素，但数量和分布不受特定约束（可能是散点，不必形成矩形结构）。生成约束：恰好一种颜色在下方的像素数严格多于上方（增长为正），另一种颜色在下方的像素数不多于上方（增长 <= 0）。两种颜色的增长差不相等。

**规则**：
1. 对两种前景颜色分别计数：A_c = 灰色分隔行上方该颜色的像素数，B_c = 下方的像素数。
2. 计算增长值 G_c = B_c - A_c。选择 G_c 更大的颜色作为目标颜色。
3. 在下方区域中，找到目标颜色的所有 4-连通碎片。
4. 传递合并：若任意两个碎片的包围框行跨度有交集或列跨度有交集，则合并为一组。重复直到无法继续。
5. 对每个合并组，计算其整体包围框。将该包围框内所有黑(0)像素涂为绿(3)。目标颜色的原有像素保留不变。
6. 非目标颜色的所有像素（上方和下方）保持不变。
7. 擦除灰色分隔行（设为黑(0)）。
8. 上方区域的目标颜色像素保持不变。

**关键洞察**：分隔线上下的计数比较是一个选择门——只有"生长中"的颜色才值得投入合并补全操作。另一种颜色即使也有碎片结构也被忽略。需要对比多个示例（两种颜色的增长方向互换时，被补全的颜色也随之切换）才能归纳出选择规则。

## 新题 8：嵌入与孤立标记分治驱动框体修补与方向性选择填充

**组合逻辑**：[嵌入与孤立分类 embedded_vs_isolated](已有) → 分支：嵌入 → [修补 repair](已有)；孤立 → [射线延伸 ray_extend](创新：方向由边缘线决定) → [邻接判断](创新：延伸后是否触及框体决定是否填充) → [洪泛填充 flood_fill](已有)

**来源原语**：修补 repair、标记像素 marker_pixel、边缘线 edge_line、嵌入与孤立 embedded_vs_isolated、边缘指示方向 edge_indicates_direction（参考题 8886d717）；洪泛填充 flood_fill、空心矩形 rectangular_frame（参考题 551d5bf1）；擦除 erase（参考题 e4941b18）

**依赖链**：标记分类 → 嵌入标记修补边框缺陷 → 孤立标记沿边缘线方向延伸一格 → 延伸像素若触及框体则触发该框填充。分类、方向判断、填充触发三步紧耦合：不分类则嵌入标记也会被延伸（错误修改）；不延伸则孤立标记无法建立与框体的空间联系；不填充则无输出变化。整体结构为条件分支而非线性流水线。

同种颜色的标记像素在不同空间语境下扮演相反角色：嵌入于框边的标记修补缺陷，孤立在背景上的标记沿边缘线方向延伸后触发邻近框体的内部填充。

**输入结构**：约 14x14 的黑(0)背景网格。网格中包含 2~3 个橙(7)空心矩形框（1 像素宽实心边框，内部为黑(0)，各边框宽高 5~7 格），互不重叠。部分框的边框有 1~2 个单像素缺口（非角落位置），缺口位置被红(2)像素占据（嵌入标记）——这些红色像素的 4 个基数邻居中至少 3 个是橙(7)。此外，在黑色背景区域散布着 1~3 个孤立的红(2)像素，它们的 4 个基数邻居全是黑(0)（不与任何框的边框相邻）。网格的某一完整边界行或边界列被青(8)像素填满（边缘线），形成一条沿网格边缘的实线（如最右列全为青色）。生成约束：每个孤立红色像素沿朝向边缘线的基数方向延伸 1 格后，该新位置恰好与某个框的边框 4-相邻（即距某框边框曼哈顿距离为 1）；不同孤立标记延伸后触及的框互不相同（或未触及任何框则该标记无效果）。

**规则**：
1. 确定边缘线位置和方向：找到被青(8)完全填满的边界行或列。
2. 分类每个红(2)像素：
   - 嵌入标记：4 个基数邻居中有 3 个或以上是橙(7)。
   - 孤立标记：4 个基数邻居中没有橙(7)像素。
3. 修补：将每个嵌入标记涂为橙(7)，修复框边框。
4. 延伸：对每个孤立标记，计算从该标记到青色边缘线的基数方向（上、下、左或右中，使标记沿该方向前进可接近边缘线的那个方向）。在该方向上前进 1 格，在该新位置放置一个临时标记。
5. 触发填充：检查每个临时标记的 4 个基数邻居。若有邻居是橙(7)框边框像素，则确定该框为填充目标。用青(8)（与边缘线同色）洪泛填充该框的内部（所有严格在已修补边框内的黑色像素）。
6. 擦除所有红(2)像素（包括孤立标记的原始位置）和所有临时标记（设为黑(0)）。
7. 未被任何孤立标记触及的框保持空心。边缘线和框边框不变。

**关键洞察**：同一颜色的标记根据空间嵌入程度被分派到截然不同的逻辑分支：嵌入的修补结构，孤立的触发操作。边缘线不参与最终输出的绘制，它仅提供方向信息——告诉孤立标记该向哪边"伸手"去触碰框体。
