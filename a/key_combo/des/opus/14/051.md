## 新题 1：射线分区洪泛着色

**组合逻辑**：[射线延伸](从孤立标记出发向四方延伸) + [洪泛填充](以射线和障碍物为壁垒进行区域填充) + [重涂色](根据区域边界接触的射线颜色决定填充色) — 三者交织为"射线划疆→填充占地→接触定色"的推理图

**来源原语**：射线延伸(ray_extend, 参考题 97999447/a78176bb), 洪泛填充(flood_fill, 参考题 9edfc990), 重涂色+接触判定(recolor+contact_detection, 参考题 0d87d2a6), 障碍物(blocker, 参考题 9edfc990), 孤立像素(isolated_pixel, 参考题 97999447)

**依赖链**：射线延伸创建空间分隔线 → 分隔线与障碍物共同界定洪泛填充的封闭区域 → 每个填充区域的颜色取决于其边界接触了哪些颜色的射线。三个环节相互依赖：删除射线则无分区，删除洪泛则无区域，删除接触判定则无法确定颜色。

从孤立标记像素出发发射射线构建分隔网格，再用种子像素洪泛填充被射线和障碍物围成的区域，最终每个区域的颜色由其边界所接触射线的颜色唯一决定。

**输入结构**：黑(0)背景，约 15x15 网格。网格中散布 3~4 个孤立的非黑非灰单像素标记，每个标记颜色互不相同（如红(2)、蓝(1)、绿(3)、橙(7)）。网格中另有若干灰(5)像素构成短墙段（2~4 像素的水平或垂直直线段），作为障碍物。此外有 2~3 个黄(4)种子像素分布在不同区域。生成约束：每个黄种子必须位于某个由射线和障碍物围成的封闭区域内；每个封闭区域至多包含一个黄种子；每个含种子的封闭区域的边界至少接触一条射线。

**规则**：
1. 从每个彩色标记像素出发，沿上、下、左、右四个方向延伸同色射线，射线遇到灰(5)障碍物像素或网格边界时停止（不包含障碍物像素本身，即射线终止于障碍物前一格）。
2. 射线绘制完成后，从每个黄(4)种子像素出发，沿四邻连通方向对黑(0)背景进行洪泛填充。填充不能穿越射线像素、灰(5)障碍物像素或网格边界。
3. 对每个洪泛填充区域，检查其边界（区域像素的四邻域中属于射线的像素）所接触的射线颜色集合：若集合中只有一种颜色，将该区域全部重涂为该射线颜色；若集合中有多种颜色，将该区域全部重涂为灰(5)。
4. 未被洪泛填充覆盖的黑(0)像素保持不变。所有标记像素、射线像素、障碍物像素和种子像素保留原色。

**关键洞察**：射线同时承担两个角色——它既是可见的线性输出，又是洪泛填充的隐形墙壁；最终区域颜色不由种子决定，而由"围墙"的颜色成分决定，多色围墙产生灰色中和效果。

## 新题 2：面积驱动滑行与奇偶拖尾

**组合逻辑**：[计数](面积) → [排序](面积降序定处理顺序) → [滑动](面积决定下移量) + [奇偶交替](滑行轨迹交替着色) + [碰撞阻挡](先处理的大对象阻挡后续小对象) — 面积同时决定位移、顺序和碰撞格局

**来源原语**：计数+面积决定位移(count+area_determines_displacement, 参考题 8e301a54), 滑动+碰撞阻挡(slide+collision_blocking, 参考题 05f2a901), 奇偶交替(parity_alternation, 参考题 97999447), 排序(sorting, 参考题 d4c90558), 锚点方块(anchor_square, 参考题 05f2a901)

**依赖链**：面积计数同时决定处理顺序（降序排列）和滑动距离 → 大对象先滑动并固定位置成为障碍 → 小对象滑动时遇到已固定的大对象或锚点则提前停止 → 实际停止位置决定拖尾长度和奇偶图案。面积这一单一属性通过排序、位移、碰撞三条路径同时影响最终输出。

将每个前景对象按其像素面积向下滑动相应行数，滑行路径留下颜色与灰色交替的拖尾，大对象优先滑动并成为后续小对象的障碍物。

**输入结构**：黑(0)背景，约 12x18 网格。网格中有 3~5 个小型单色 4-连通前景对象（每个 3~7 像素，形状各异，不同示例中同类对象形状不同），颜色互不相同（如红(2)、蓝(1)、绿(3)、橙(7)），均位于网格上半部。网格下方靠近底边处有一个青(8) 2x2 锚点方块。生成约束：所有对象在同一列范围内不重叠；各对象按面积向下滑动后不会超出网格左右边界；至少有两个对象的滑动路径在纵向上存在潜在交叠。

**规则**：
1. 计算每个前景对象的像素面积。
2. 按面积从大到小排序。面积相同时，按对象边界框左上角的行号升序（靠上的优先）。
3. 按排序顺序依次处理每个对象：将对象整体向下平移，目标位移量等于其面积（单位：行）。若平移过程中对象的任一像素会与已固定的对象（含先前滑动完成的对象和青(8)锚点方块）发生重叠，则对象停在重叠前的最后合法位置。
4. 对象滑动后，在其原始位置到最终位置之间的每一列上留下拖尾：设对象在该列的原始最低行为 r0、最终最高行为 r1，则对 r0 < r < r1 范围内的每个空白像素，若 (r - r0) 为偶数则涂为该对象颜色，若为奇数则涂为灰(5)。
5. 锚点方块保持不变。拖尾不覆盖任何已有非黑像素。

**关键洞察**：面积承担三重职责——决定滑动距离、决定处理优先级、以及通过优先级间接决定碰撞格局；大面积对象滑得远且先滑，可能反而因碰撞提前停下，使其拖尾比小对象更短，形成反直觉的输出。

## 新题 3：对称轨道揭示隐藏方向指令

**组合逻辑**：[对称补全](还原被遮罩的图案) → [条件判断：轨道期望色](对称轨道揭示标记位置的"本应颜色") → [平移/对角偏移](期望色决定偏移方向) — 非线性结构：对称分析的结果不直接进入下一步操作，而是充当条件判断的输入

**来源原语**：对称补全+八重对称轨道+遮罩像素(symmetry_completion+eightfold_orbit+mask_pixel, 参考题 929ab4e9), 平移+对角偏移+源色决定方向(translate+diagonal_offset+source_color_decides, 参考题 1e5d6875), 擦除(erase, 参考题 a78176bb)

**依赖链**：对称补全还原完整图案 → 完整图案揭示每个标记位置的"轨道期望色" → 期望色作为隐式指令决定对角偏移方向 → 偏移产生新像素。对称补全的输出并非直接传递给平移操作，而是经过一层"期望色解码"才变为方向指令。

在具有四重旋转对称的正方形图案中，还原灰色遮罩像素以确定完整对称结构，再利用对称轨道解码橙色标记的"本应颜色"，将该颜色作为方向指令生成对角偏移副本。

**输入结构**：黑(0)背景，约 11x11 正方形网格。中央区域有一个使用红(2)和蓝(1)两色构成的图案，该图案在四重旋转对称下不变（即 90 度旋转后图案与自身重合）。部分图案像素被灰(5)遮罩替换（每个对称轨道中至少保留一个可见像素）。另有 2~4 个橙(7)标记像素，每个橙标记替换了图案中的某个红或蓝像素（标记位置属于图案区域）。生成约束：每个橙标记的对称轨道中至少有一个非橙非灰的可见像素，以便确定该轨道的本应颜色；各标记的对角偏移结果不超出网格边界。

**规则**：
1. 识别图案的四重旋转对称结构。对每个灰(5)遮罩像素，找到其四重旋转轨道中的可见（非灰非橙）像素颜色，将灰像素替换为该颜色。
2. 对每个橙(7)标记像素，通过其四重旋转轨道确定该位置"本应"的颜色（轨道中非橙像素的颜色）。
3. 若本应颜色为红(2)：在距橙标记沿"朝向网格中心"方向偏移一步的对角位置绘制一个绿(3)像素。
4. 若本应颜色为蓝(1)：在距橙标记沿"远离网格中心"方向偏移一步的对角位置绘制一个黄(4)像素。
5. "朝向/远离网格中心"指：计算标记到网格中心的向量，选择行和列分量均朝向（或远离）中心的对角方向。
6. 橙标记像素保留为橙(7)。绿/黄像素若落在已有非黑像素上，则不绘制。

**关键洞察**：橙色标记是被篡改的对称像素，其"真实身份"（红或蓝）被对称结构隐藏起来，只有先完成对称还原才能解码方向指令——方向信息不在标记本身，而在它"本应是什么"中。

## 新题 4：引导线分区计数排序输出

**组合逻辑**：[连线/引导线](边界标记对生成贯穿引导线) → [包含+计数](引导线分区确定标记像素归属并计数) → [排序+重涂色](按区内计数排序输出摘要行) — 多源汇聚结构：引导线、边框、标记像素三类独立输入通过分区操作交汇

**来源原语**：连线+边界标记对+引导线(line_drawing+border_marker_pair+guide_line, 参考题 0d87d2a6/29700607), 包含+计数+标记像素(containment+counting+marker_pixel, 参考题 d4c90558), 排序+标记数决定行长(sorting+marker_count_row_len, 参考题 d4c90558), 空心矩形(hollow_rect, 参考题 d4c90558)

**依赖链**：边界标记对 → 生成贯穿引导线 → 引导线将网格切割为矩形分区 → 每个分区内统计黄标记数 → 每个彩色框的中心所在分区决定该框的"关联标记数" → 按关联标记数排序生成摘要输出。引导线、框、标记三者各自独立存在于输入中，仅通过分区操作产生关联。

用边界标记对画出贯穿全网格的引导线，将空间切割为分区，统计每个分区中的标记像素数量，再将每个彩色矩形框按其所在分区的标记数排序，输出按计数递增的摘要色条。

**输入结构**：黑(0)背景，约 18x18 网格。蓝(1)单像素标记成对出现在网格的对边（左右边或上下边各一个，行号或列号相同），定义 2~3 条引导线。网格内部有 3~4 个不同颜色的空心矩形框（颜色为红(2)、绿(3)、橙(7)、品红(6)等，均非蓝非黑非黄非灰），框的大小不等（边界框 3x3 到 6x6 不等）。网格内另散布若干黄(4)单像素标记。生成约束：引导线不穿过任何矩形框的边框像素；每个矩形框的中心像素落在某个分区内且不在引导线上；每个含框的分区内至少有一个黄标记。

**规则**：
1. 对每对蓝(1)边界标记，画一条蓝色直线贯穿网格（同行标记画水平线，同列标记画竖直线）。
2. 蓝引导线将网格切割为若干矩形分区（含网格边界围成的区域）。
3. 对每个分区，统计其内部黄(4)标记像素的数量（引导线上的像素不属于任何分区）。
4. 对每个彩色矩形框，确定其边界框中心像素所在的分区，将该分区的黄标记数作为该框的"关联计数"。
5. 输出一个新网格：行数等于框的数量，列数等于最大关联计数。按关联计数从小到大排列（计数相同时按框中心行号升序），每行用该框颜色填充前"关联计数"个像素，其余填黑(0)。

**关键洞察**：蓝引导线不是可见对象的一部分，而是创建了一个不可见的坐标分区系统——黄标记和彩色框各自独立分布，只有通过引导线定义的分区才建立起两者之间的对应关系。

## 新题 5：压缩揭示真实距离的最近种子填充

**组合逻辑**：[压缩/去重](消除重复行列还原真实结构) → [最近扩散](在压缩空间中做最近种子填充) → [平铺/展开](按原始重复因子回展) — 三明治结构：压缩和展开夹着核心逻辑，且压缩因子本身携带信息

**来源原语**：压缩+去重+相邻重复+合并相同行列(compress+deduplicate+adjacent_repeat+merge_identical_row_col, 参考题 e1baa8a4), 最近扩散+种子条+最近种子分区+等距异色为分隔(nearest_fill+seed_bar+nearest_seed_part+equidist_diff_sep, 参考题 332202d5), 周期对齐(periodic_align, 参考题 e95e3d8e)

**依赖链**：输入含重复行列 → 压缩找到真实结构（去除膨胀） → 在压缩网格中识别种子条并做最近种子填充（距离基于压缩后的行号） → 等距异色行变为分隔行 → 将填充结果按原始重复因子展开回原始尺寸。若不压缩则距离计算错误；若不展开则输出尺寸错误；压缩本身即揭示了展开所需的因子。

将一个被行列重复膨胀的网格先压缩至本体，在压缩空间中按种子条的真实间距做最近填充，再按原始膨胀因子回展为输出。

**输入结构**：约 16x16 网格，无黑(0)背景——整个网格被颜色填满。网格是一个较小网格（约 6x6 至 8x8）经行列重复膨胀而成：某些行被复制 2~3 次（相邻完全相同的行），某些列被复制 2~3 次（相邻完全相同的列）。原始小网格使用 2~3 种颜色（如红(2)、蓝(1)、绿(3)）构成一个非周期图案。在膨胀后的网格中，有 2~3 整行被替换为单一品红(6)色，作为"种子条"。不同种子条使用不同颜色（品红(6)和橙(7)）。生成约束：种子条在膨胀网格中的位置不落在重复行组的边界上（即每条种子条完全替换了某个重复组中的一行）；压缩后任意两条不同色种子条之间至少间隔 2 行。

**规则**：
1. 识别相邻完全相同的行组和列组，每组仅保留第一行/列，得到压缩网格。记录每个行组和列组的重复次数。
2. 在压缩网格中定位种子条（整行为品红(6)或橙(7)的行）。
3. 对压缩网格中每个非种子行：计算其到最近种子条的行距离（压缩后的行号之差）。将该行所有像素重涂为最近种子条的颜色。
4. 若某行到两条最近种子条的距离相等且两条种子条颜色不同，将该行全部涂为灰(5)作为分隔行。若等距种子条颜色相同，正常涂为该颜色。
5. 每条种子条自身在压缩网格中保留其原色。
6. 按步骤 1 记录的重复次数，将压缩网格的每行/列恢复为对应数量的重复行/列，得到最终输出。

**关键洞察**：肉眼看到的种子条间距是膨胀后的像素距离，但真正的"最近种子"判定基于压缩后的行距——重复行组多的区段在视觉上更宽但逻辑上并不更远，不压缩就会算错最近种子归属。

## 新题 6：图例指导的条件偏移印章

**组合逻辑**：[印章覆盖](图例精灵映射到标记位置) + [列选择](青色前景列标识激活列) → [条件分支：对角偏移 vs 原位](激活列内的标记做对角偏移印章，非激活列原位印章) — 多输入决策结构：图例定内容，列选择定行为模式

**来源原语**：印章覆盖+图例精灵+分隔行+位置对应+图例色替换标记(stamp+legend_sprite+separator_row+positional_mapping+legend_replaces_marker, 参考题 20fb2937), 列选择+前景列+含前景列整列涂色(column_selection+foreground_column+fg_col_full_recolor, 参考题 f5b8619d), 对角偏移(diagonal_offset, 参考题 1e5d6875)

**依赖链**：图例区定义标记色→精灵的映射 → 下方标记区中每个标记按映射获得精灵内容 → 列选择判定每个标记所在列是否为"激活列" → 激活列中的标记进行对角偏移印章，非激活列中的标记原位印章。图例决定"印什么"，列选择决定"怎么印"，两个信息源独立且必须同时使用。

根据顶部图例将下方标记替换为对应精灵，但精灵的放置方式取决于标记所在列是否包含青色前景像素——有则对角偏移放置，无则居中放置。

**输入结构**：黑(0)背景，约 16x20 网格。上部为图例区：3~4 个小型单色实心正方形精灵（3x3 或 4x4，颜色如红(2)、绿(3)、橙(7)），水平排列且间隔均匀。每个精灵正下方一行有一个对应的单像素标记（颜色各异，如蓝(1)、品红(6)、栗(9)），标记与精灵中心列对齐。图例区下方有一整行灰(5)分隔行。分隔行以下为标记区：散布若干标记像素（颜色与图例标记色相同），以及若干青(8)单像素分布在部分列中。生成约束：标记区中每个标记与任何其他标记或青像素至少间隔精灵边长的距离；青像素不与标记同格；每种标记色在标记区中至少出现一次。

**规则**：
1. 建立图例映射：按从左到右顺序，将每个图例标记色与其上方的精灵配对。
2. 识别激活列：标记区中任何包含至少一个青(8)像素的列为激活列。
3. 丢弃图例区和分隔行。输出网格宽度不变，高度为分隔行以下的行数。
4. 对标记区中每个标记像素：
   - 查找其图例映射获得对应精灵。
   - 若标记所在列为激活列：将精灵中心对齐到标记位置后，整体向右下方偏移 1 像素（行+1，列+1），然后绘制精灵。
   - 若标记所在列非激活列：将精灵中心对齐到标记位置，直接绘制精灵。
5. 精灵超出网格边界的部分裁剪丢弃。
6. 多个精灵重叠时，按标记位置从左到右、从上到下的顺序处理，后绘制的覆盖先绘制的。
7. 青(8)像素在输出中移除（被背景或精灵覆盖）。

**关键洞察**：青色像素不出现在最终输出中——它们是隐形的"模式开关"，默默将同列标记的印章行为从居中切换为偏移；只有对比含青列和不含青列的标记输出差异，才能发现这一隐藏规则。

## 新题 7：对称轨道定色的引导体射线

**组合逻辑**：[对称补全](还原中央图案) + [射线延伸](从引导体尖端向外射线) + [擦除](移除引导体和障碍物) — 但射线颜色不由引导体决定，而由对称轨道在中央图案中的映射色决定，形成"对称分析↔射线着色"的交叉依赖

**来源原语**：对称补全+八重对称轨道(symmetry_completion+eightfold_orbit, 参考题 929ab4e9), 射线延伸+引导体+引导体定新对角线(ray_cast+guide_object+guide_tip_seeds_parallel_diagonal, 参考题 a78176bb), 擦除(erase, 参考题 a78176bb), 障碍物(blocker, 参考题 9edfc990)

**依赖链**：中央图案需对称补全才完整 → 引导体的尖端定义射线起点和方向 → 射线颜色不是引导体色，而是尖端位置在四重旋转轨道中对应的中央图案像素色 → 障碍物截断射线长度 → 擦除引导体和障碍物。对称分析和射线着色交叉：不完成对称就不知道射线颜色，不识别引导体就不知道射线起点。

在正方形网格中心还原四重旋转对称图案，从灰色引导体尖端发射射线，射线颜色由尖端在对称轨道中映射到中央图案的颜色决定，射线被橙色障碍物截断后擦除所有辅助元素。

**输入结构**：黑(0)背景，约 13x13 正方形网格。中央区域（约 5x5 至 7x7）有一个使用红(2)和蓝(1)构成的图案，具有四重旋转对称性，但部分像素被灰(5)遮罩。中央图案外围有 2~4 个灰(5)小型三角形引导体（每个由 3~6 像素构成直角三角形），每个引导体有一条边紧邻中央图案边界。网格中另有若干橙(7)单像素障碍物散布在外围区域。生成约束：每个引导体的远端尖端（距中央图案最远的像素）到中央图案边界至少 2 像素；每个遮罩像素的四重旋转轨道中至少有一个可见（非灰非橙）像素；引导体尖端位置的四重旋转轨道中至少有一个像素落在中央图案区域内且为非灰可见像素。

**规则**：
1. 识别中央图案区域及其四重旋转对称性。将灰(5)遮罩像素替换为其旋转轨道中的可见颜色。
2. 对每个灰色引导体，定位其远端尖端像素（距中央图案几何中心最远的像素）。
3. 确定每个尖端的射线方向：从中央图案中心指向尖端的主方向（上、下、左、右中最接近的基方向）。
4. 确定每个尖端的射线颜色：将尖端坐标做四重旋转，找到落在中央图案区域内的对应坐标，取该坐标处的（已补全的）颜色。
5. 从每个尖端沿步骤 3 确定的方向延伸射线，射线颜色为步骤 4 确定的颜色。射线遇到橙(7)障碍物或网格边界时停止（不包含障碍物像素）。
6. 擦除所有灰(5)像素（引导体和遮罩均移除，遮罩位置已在步骤 1 中被替换）和所有橙(7)障碍物像素（替换为黑(0)背景）。

**关键洞察**：射线颜色不来自引导体本身（引导体全是灰色），而来自尖端在对称旋转下的"影子位置"在中央图案中的颜色——引导体同时编码了射线的空间起点和颜色查询坐标。

## 新题 8：格子分类驱动的条件洪泛

**组合逻辑**：[格子结构分析](识别单元格并分类为边缘/内部) + [计数](统计两类单元格中的标记数量) → [条件分支](计数对比决定激活哪类单元格的标记) → [洪泛填充](仅从激活标记出发填充) — 决策节点结构：格子分类和计数共同构成一个非显然的条件判断

**来源原语**：格子结构+单元格区域+行列阵列位置+边缘与内部区分(lattice+cell_region+row_column_position+perimeter_interior_distinction, 参考题 8a371977), 计数(counting, 参考题 d4c90558), 洪泛填充+种子像素+四邻连通(flood_fill+seed_pixel+four_neighbor_connectivity, 参考题 9edfc990), 重涂色(recolor, 参考题 8a371977), 障碍物(blocker, 参考题 9edfc990)

**依赖链**：格子线定义单元格 → 单元格按阵列位置分为边缘/内部两类 → 统计两类中的黄标记总数并比较 → 多数方获得激活权 → 仅从激活方的标记出发洪泛 → 格子线中存在单像素缺口允许填充跨越单元格 → 单元格内的彩色小图形阻挡填充路径。删除格子分析则无法分类；删除计数则无法决定激活方；删除洪泛则无输出变化。

灰色格子将网格划分为单元格阵列，统计边缘单元格和内部单元格中的黄标记数量，数量多的一方激活其标记进行洪泛填充，填充通过格子线缺口蔓延到相邻单元格。

**输入结构**：黑(0)背景，约 15x15 网格。灰(5)格子线将网格分为 4x4 或 5x5 的单元格阵列（每个单元格为 2x2 或 3x3 的黑色区域）。部分格子线交叉点处缺少一个灰像素（形成 1 像素宽的缺口），允许相邻单元格四邻连通。部分单元格内有一个黄(4)单像素标记。部分单元格内有一个小型彩色图形（红(2)或蓝(1)，2~3 像素，4-连通），充当障碍物。生成约束：边缘单元格（阵列的最外一圈）和内部单元格（被边缘完全包围的单元格）中的黄标记数量不相等；格子缺口构成的连通路径确保至少一个激活标记能通过缺口到达相邻单元格；彩色图形不与黄标记同单元格。

**规则**：
1. 识别灰(5)格子线结构，确定单元格阵列的行列布局。
2. 将每个单元格分类为边缘（其阵列行号或列号为第一行/列或最后一行/列）或内部（不在边缘）。
3. 统计边缘单元格中黄(4)标记总数 P 和内部单元格中黄(4)标记总数 I。
4. 若 P > I：激活所有边缘单元格中的黄标记，填充色为红(2)。
5. 若 I > P：激活所有内部单元格中的黄标记，填充色为绿(3)。
6. 从每个激活的黄标记出发，沿四邻连通方向对黑(0)像素进行洪泛填充。填充不能穿越灰(5)格子线像素（但可通过缺口进入相邻单元格）。填充不能穿越彩色图形像素（红/蓝障碍物）。
7. 所有非激活的黄标记保留为黄(4)。激活的黄标记被填充色覆盖。灰格子线、彩色图形均保持不变。

**关键洞察**：格子结构同时承担三个功能——定义单元格边界（几何）、区分边缘/内部（分类）、通过缺口控制连通性（拓扑）；黄标记的两个阵营通过数量博弈决定谁获得填充权，失败方的标记静默地留在原地。

## 新题 9：框内计数定射线的裁剪排序输出

**组合逻辑**：[裁剪](识别唯一完整边框并裁切) → [计数](统计裁切区内各框的标记数) → [排序](按计数排列) → [射线延伸+奇偶交替](从每个框中心向下画长度等于计数的交替射线) — 计数值同时决定排序键、射线长度和覆写优先级的三重角色

**来源原语**：裁剪+唯一完整边框+单色边框(crop+unique_complete_frame+monochrome_frame, 参考题 c909285e), 计数+排序+标记数决定行长+按计数升序排列(counting+sorting+marker_count_row_len+sorted_by_count, 参考题 d4c90558), 空心矩形+标记像素(hollow_rect+marker_pixel, 参考题 d4c90558), 射线延伸+奇偶交替+交替填充至边界(ray_extend+parity_alternation+alternating_fill_to_edge, 参考题 97999447)

**依赖链**：唯一完整边框裁剪定义有效区域 → 区域内各彩色框的标记计数决定排序 → 排序决定处理顺序 → 从每个框中心向下画射线，长度=标记数，颜色奇偶交替 → 后处理（计数更大）的射线覆盖先处理的。计数值的三重角色使得改变任何一个标记都会连锁影响排序、射线长度和覆写结果。

在由唯一完整边框裁切出的区域内，统计每个彩色框中的标记数，按计数排序后从每个框中心向下画出长度等于计数的奇偶交替色射线，后处理的覆盖先处理的。

**输入结构**：黑(0)背景，约 20x20 网格。网格中有一个由栗(9)色像素构成的完整矩形边框（栗色仅出现在此边框上，且构成完整矩形轮廓）。栗色边框内部有 3~4 个不同颜色的空心矩形框（如红(2)、蓝(1)、绿(3)、品红(6)），大小各异（3x3 到 7x7 不等）。每个彩色框内部散布若干黄(4)单像素标记（1~5 个不等）。栗色边框外可能有干扰元素（随机彩色像素），需忽略。生成约束：各彩色框互不重叠且完全位于栗色边框内部；各框的黄标记数互不相同；每个框中心到栗色边框底边的距离大于该框的标记数。

**规则**：
1. 找到栗(9)色完整矩形边框，裁剪输出为该边框的边界框区域（含边框本身）。丢弃边框外的所有内容。
2. 在裁剪区域内，对每个彩色空心矩形框，统计其边界框内部的黄(4)标记像素数量。
3. 按标记数从小到大排序。
4. 按排序顺序依次处理每个框：从该框边界框的中心像素出发，向下画一条射线，长度等于该框的标记数（像素数）。射线着色规则：距起点偏移为偶数（0, 2, 4...）的像素涂为该框颜色，偏移为奇数（1, 3, 5...）的像素涂为灰(5)。
5. 后处理的射线像素覆盖先处理的射线像素（标记数大的框有更长射线且优先级更高）。
6. 射线不覆盖彩色框的边框像素和栗色边框像素。黄标记在输出中保留。

**关键洞察**：标记数承担三重职责——排序键决定处理顺序，射线长度决定空间覆盖范围，而处理顺序又隐含了覆写优先级；由于奇偶交替，长射线覆盖短射线时不是简单替换，而是产生与两者计数差相关的条纹干涉图案。

## 新题 10：膨胀因子编码偏移的压缩嵌套

**组合逻辑**：[压缩/去重](消除重复行列找到真实矩形) → [排序+嵌套](按面积降序嵌套) + [滑动](偏移量由压缩时移除的重复行数编码) — 信息提取结构：压缩不仅是预处理，其副产品（重复因子）直接编码了嵌套布局参数

**来源原语**：压缩+去重+相邻重复+合并相同行列(compress+deduplicate+adjacent_repeat+merge_identical_row_col, 参考题 e1baa8a4), 排序+嵌套+面积递减嵌套+角落对齐嵌套(sorting+nest+area_descend_nest+corner_aligned_nest, 参考题 6cbe9eb8), 前景矩形+壁纸背景+忽略干扰项(foreground_rectangle+wallpaper_bg+ignore_distractors, 参考题 6cbe9eb8), 滑动(slide, 参考题 05f2a901)

**依赖链**：输入含重复行列（膨胀）和壁纸背景 → 压缩去除重复行列并记录每组重复次数 → 在压缩网格中识别前景矩形并按面积排序 → 在黑色画布上做角落对齐嵌套（最大在外，依次套入左下角） → 每个矩形在嵌套时额外向右偏移，偏移量等于该矩形原始行范围内被移除的重复行总数。压缩的副产品（各区段重复次数）变为嵌套布局的水平偏移参数，不压缩则无法排序，不记录重复因子则无法确定偏移。

将含重复行列膨胀的壁纸网格压缩至本体后，识别前景矩形按面积降序嵌套，每个矩形的水平偏移量由其原始行范围的行重复因子之和编码。

**输入结构**：约 18x18 网格，网格被周期壁纸背景填满（使用灰(5)和黑(0)交替的棋盘格或条纹），其上叠加 3~4 个前景色矩形（实心或空心框，颜色如红(2)、蓝(1)、绿(3)、橙(7)）。整个网格经过行列重复膨胀：某些行组被重复 1~3 次，某些列组被重复 1~2 次。生成约束：压缩后前景矩形面积互不相同；压缩后最大矩形足以容纳所有较小矩形的嵌套（含偏移）；各矩形的原始行范围内重复行数总和互不相同且均不超过 3。

**规则**：
1. 识别相邻完全相同的行组和列组，每组保留第一行/列得到压缩网格。记录每个行组的重复次数（即该组中的行数）。
2. 在压缩网格中，忽略壁纸背景，识别所有前景色矩形（颜色与壁纸色不同的连通矩形区域）。
3. 按前景矩形的边界框面积从大到小排序。
4. 创建一个黑(0)画布，尺寸等于最大矩形的边界框。
5. 依次绘制每个矩形：
   - 最大矩形直接绘制在画布上（左上角对齐画布左上角）。
   - 后续每个矩形绘制在前一个矩形内部的左下角，但额外向右偏移 d 像素，其中 d = 该矩形在压缩前所跨行范围内所有行组的（重复次数 - 1）之和。
6. 若偏移后矩形超出父矩形右边界，则裁剪超出部分。
7. 空心框仅绘制边框像素，实心矩形绘制全部像素。后绘制的覆盖先绘制的。

**关键洞察**：行重复不是噪声——每个矩形区段被膨胀的程度编码了该矩形在嵌套中的水平偏移量；压缩是必需步骤（否则矩形面积失真无法正确排序），但压缩过程中丢弃的信息（重复因子）恰恰是嵌套布局的关键参数。
