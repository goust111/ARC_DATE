## 新题 1：突起定向的逐体重力沉降

**组合逻辑**：[叶状突起 + 突起定行列](创新：突起方向不再选取行列做切割，而是为每个对象指定独立的滑动方向) → [滑动 + 碰撞阻挡 + 重力沉降](已有) → [擦除](创新：突起本身在沉降后被移除)

**来源原语**：叶状突起(leaf_protrusion)·突起定行列(leaf_selects_row_col) ← f1cefba8；滑动(sliding)·碰撞阻挡(collision_block)·重力沉降(gravity_settle) ← d282b262；擦除(erase) ← a09f6c25

**依赖链**：突起的朝向决定该对象的滑动方向 → 不同对象沿不同方向运动导致碰撞拓扑与单一重力完全不同 → 沉降完成后删除突起像素使最终形态与输入的关系更隐蔽

每个前景精灵携带一个单像素突起，突起的朝向决定该精灵的独立滑动方向；所有精灵同时沿各自方向滑动直到碰壁或碰撞静止，然后删除突起像素。

**输入结构**：约 15x15 的黑(0)背景网格。散布 3~5 个互不相邻的 4-连通单色前景精灵（每个精灵 3~6 像素，形状不限但连通），每个精灵使用不同的非黑颜色（如红(2)、绿(3)、蓝(1)、黄(4)等）。每个精灵恰好有一个单像素"叶状突起"——该像素与精灵主体仅通过一个正交邻居相连，且该邻居位于精灵主体内部。突起与其唯一邻居的相对方向（突起在邻居的上/下/左/右）即为该精灵的滑动方向。生成约束：各精灵的滑动路径在运动过程中不产生死锁（即不存在两个精灵相向运动且同时到达同一行/列的情况；可通过让相向运动的精灵在正交方向上不重叠来保证）。

**规则**：
1. 对每个精灵，找到其叶状突起像素（与主体仅有一个正交邻居相连的末端像素）。突起像素相对于其唯一邻居的方向即为该精灵的滑动方向（例如突起在邻居的右侧 → 精灵向右滑动）。
2. 所有精灵同时开始沿各自方向逐格滑动。每一步中，若某精灵的下一位置（整体平移一格后占据的所有格子）均在网格内且不与任何已静止的精灵或本步无法移动的精灵重叠，则该精灵移动一格；否则该精灵静止。
3. 重复步骤 2 直到所有精灵静止。
4. 删除每个精灵的突起像素（将其恢复为背景色），保留精灵主体。

**关键洞察**：突起像素既是结构特征（末端单连接像素）又是运动指令（方向编码），而非参考题中的行列选择器；多方向同时运动产生的碰撞图案无法从任何单一重力方向推导。

## 新题 2：对称类型匹配驱动的模板印章

**组合逻辑**：[对称类型决定颜色](创新：对称类型不再映射为颜色，而是作为匹配键关联精灵与槽位) + [掩码匹配](创新：匹配标准从形状一致改为对称类别一致) → [印章覆盖 + 重涂色](已有原语组合使用)

**来源原语**：对称类型决定颜色(symmetry_det_color) ← a09f6c25；掩码匹配(mask_matching) ← 321b1fc6；印章覆盖(stamp_overlay)·重涂色(recolor) ← 321b1fc6 / c64f1187；对称轴(symmetry_axis) ← a09f6c25

**依赖链**：对称分类将精灵和槽位分成对应组 → 分组关系决定哪个精灵印入哪个槽位 → 印章时精灵必须按槽位轮廓色重涂，且需旋转/翻转至与槽位轮廓对齐

将每个图例精灵按其反射对称类型与对应的目标槽位匹配，然后将精灵的内部图案印入槽位并重涂为槽位轮廓色。

**输入结构**：约 18x18 的黑(0)背景网格，分为上下两区（中间隔一行黑(0)空行）。上区（图例区）包含 3 个互不相邻的多色精灵（每个精灵 4~8 像素，4-连通），它们的反射对称类型分别为水平对称、垂直对称、无对称（旋转对称或完全不对称）。每个精灵由两种颜色组成：灰(5)作为"墨水色"绘制内部图案，外加一种独特的"签名色"（如红(2)、蓝(1)、绿(3)）标记 1~2 个像素。下区（工作区）包含 3 个用不同单色绘制的空心轮廓框（每个框由单色像素围成，内部为黑(0)，框的像素数 8~12），每个轮廓框的内部空间恰好可容纳一个精灵的边界框。每个轮廓框也拥有恰好一种反射对称类型（水平、垂直、无），与上区三个精灵的对称类型形成一一对应。生成约束：三种对称类型两两不同；每个轮廓框的内部空间尺寸等于且仅等于一个精灵的边界框尺寸。

**规则**：
1. 对上区每个精灵，计算其 4-连通像素集合的反射对称类型：仅有水平对称轴 → "水平"；仅有垂直对称轴 → "垂直"；两者都没有或都有 → "无"。
2. 对下区每个轮廓框，同样计算其轮廓像素集合的反射对称类型。
3. 将对称类型相同的精灵与轮廓框配对（一一对应）。
4. 对每对配对：将精灵的灰(5)墨水像素印入轮廓框内部对应位置，但将灰(5)替换为该轮廓框的轮廓颜色。精灵的"签名色"像素不印入（保持为黑(0)背景）。
5. 上区的原始精灵全部擦除为背景色。

**关键洞察**：对称类型在参考题中是直接映射为输出颜色的标签，此处它变成了匹配键——求解者必须先分类再配对，且签名色像素的去留规则需要对比多个示例才能归纳。

## 新题 3：交叉色阵提取——从正交条叠加中解码隐式网格

**组合逻辑**：[全幅条 + 正交交叉](已有) → [层序推断 + 交叉可见色为上层](已有) → [提取](创新：不再输出 1x1 单色，而是提取完整的交叉色矩阵作为紧凑网格) + [裁剪](创新：裁剪目标不是面板象限而是交叉点构成的逻辑矩阵)

**来源原语**：全幅条(full_span_bar)·正交交叉(orthogonal_crossing)·层序推断(infer_layer_order)·交叉可见色为上层(visible_at_crossing_is_top) ← 1a2e2828；提取(extract) ← d9fac9be；裁剪(crop) ← 73182012

**依赖链**：条的识别确定交叉点矩阵的维度 → 每个交叉点的可见色需要全局层序推断才能解读 → 推断出的真实横条颜色排列构成输出网格的行，真实纵条颜色排列构成输出网格的列 → 输出网格每格填入该行横条的颜色

在多条水平和垂直全幅色条交叠的画布上，通过交叉点的可见颜色推断全局层序，然后输出一个紧凑网格，每行对应一条横条，每列对应一条纵条，格内颜色为该交叉点处的横条颜色。

**输入结构**：约 15x15 的灰(5)背景网格。有 3~4 条水平全幅条和 3~4 条垂直全幅条，每条宽度为 1 像素，颜色各不相同（从红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、品红(6)中选取）。条之间在画布上正交交叉，每个交叉点显示层序较高的那条的颜色。同方向的条互不重叠。生成约束：层序是一个全序（无并列），且每条的层级可以通过至少一个交叉点的可见色推断出来（即不存在被完全遮盖而无任何可见交叉点的条）。

**规则**：
1. 识别所有水平全幅条和垂直全幅条。水平条是某一行中所有非背景像素颜色相同（或被高层条遮盖的位置除外）的行；垂直条类似。
2. 在每个交叉点(r, c)处，可见色属于层序较高的条。收集所有交叉点的可见色，推断全局层序：若交叉点(r, c)显示横条 H 的颜色，则 H 在层序中高于经过该点的纵条 V；反之亦然。
3. 构建一个 H_count x V_count 的输出网格（H_count = 横条数量，V_count = 纵条数量）。横条按在画布上从上到下的位置排列为输出的行，纵条按从左到右排列为输出的列。
4. 输出网格的第 i 行第 j 列填入第 i 条横条的颜色。

**关键洞察**：交叉点的可见色看似直接给出了输出，但它编码的是层序信息而非横条颜色——在高层纵条遮盖低层横条的交叉点处，可见色是纵条色而非横条色，求解者必须先推断全局层序才能还原每个交叉点处被遮盖的横条颜色。

## 新题 4：边框色定射线方向，中心色定角落装饰

**组合逻辑**：[单色边框 + 边框包围中心](已有) → [忽略干扰项](已有) + [射线延伸](创新：射线方向由边框颜色条件分支决定，而非固定方向) + [描边 + 角标记](创新：角落装饰色由中心像素颜色决定，而非固定配色方案)

**来源原语**：单色边框(monochrome_frame)·边框包围中心(frame_encloses_center)·中心色为输出(center_color_output)·忽略干扰项(ignore_distractors) ← d9fac9be；射线延伸(ray_extend)·延伸至边或标记(extend_to_edge_or_marker) ← 256b0a75 / f1cefba8；描边(decorate)·角标记(corner_marker)·对角邻接(diagonal_adjacency) ← 95990924

**依赖链**：边框识别（区分真实框和干扰项）→ 边框颜色触发条件分支决定射线方向 → 中心像素颜色决定角落装饰色 → 射线延伸时需知道所有边框位置（射线遇到另一个边框时停止），因此所有边框必须先全部识别

在散布干扰像素的画布上识别所有 3x3 单色边框，根据边框颜色发射特定方向的射线、根据中心颜色在四角放置装饰像素，射线遇到另一个边框时终止。

**输入结构**：约 17x17 的黑(0)背景网格。包含 3~5 个 3x3 单色边框（8 个边界像素同色，中心像素为另一种非黑色）。边框颜色从 {红(2), 蓝(1)} 中选取，中心颜色从 {绿(3), 黄(4), 橙(7)} 中选取。画布上还散布若干单独的前景像素（与边框使用相同的颜色集合），这些是干扰项——它们不构成完整的 3x3 边框。各边框之间至少间隔 2 格（确保角落装饰和射线有空间）。生成约束：任意两个边框之间至少存在一条无障碍的水平或垂直通路（使射线可以到达）。

**规则**：
1. 识别所有有效的 3x3 边框：一个 3x3 窗口中 8 个边界像素颜色相同（为边框色）且中心像素为另一种非黑色（为中心色）。不满足此条件的前景像素视为干扰项，擦除为背景色。
2. 射线延伸——按边框颜色分支：
   - 边框色为红(2)：从边框中心向上和向下各发射一条射线，射线颜色为该框的中心色，逐格延伸直到到达网格边缘或遇到另一个边框的任意像素（不覆盖该像素，射线终止于其前一格）。
   - 边框色为蓝(1)：从边框中心向左和向右各发射一条射线，规则同上。
3. 角落装饰——中心色决定配色：在每个边框的四个对角邻接位置（即 3x3 边框外侧的四个角：左上外角、右上外角、左下外角、右下外角）放置装饰像素，颜色为该框的中心色。若该位置已被射线占据，装饰像素覆盖射线。
4. 处理顺序：先绘制所有射线，再绘制所有角落装饰（装饰优先级高于射线）。

**关键洞察**：边框颜色和中心颜色各自控制不同的输出维度（方向 vs. 着色），两者缺一不可；射线的终止条件依赖于全局边框布局，单看一个边框无法确定其射线长度。

## 新题 5：突起朝向的条件分叉——填充与射线的互斥选择

**组合逻辑**：[叶状突起 + 突起定行列](已有) → 条件分叉{水平突起 → [填充 + 内外色互换](创新组合)；垂直突起 → [射线延伸 + 重涂色](创新组合)} → 两条分支的结果在同一画布上叠加

**来源原语**：叶状突起(leaf_protrusion)·突起定行列(leaf_selects_row_col)·双色矩形(bicolor_rectangle)·内外色互换延伸(swap_extend) ← f1cefba8；填充(fill)·空心矩形(hollow_rectangle)·孔洞在框内(hole_inside_frame) ← e73095fd；射线延伸(ray_extend) ← 256b0a75

**依赖链**：突起方向判断 → 触发完全不同的操作分支 → 两个分支修改同一画布的不同区域，但射线可能穿过已填充的矩形内部，需要分支间协调优先级

对每个空心矩形的突起方向做分叉：水平突起触发内部填充并反转内外色，垂直突起触发从突起端射出射线并沿途重涂。

**输入结构**：约 16x16 的黑(0)背景网格。包含 3~4 个互不相邻的空心矩形（每个矩形由单色轮廓围成，内部为黑(0)，轮廓宽度 1 像素，矩形外尺寸 4x4 至 6x6 不等）。每个矩形使用不同的轮廓色（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。每个矩形恰好有一个单像素叶状突起——从轮廓某条边的中点向外延伸一个像素，颜色为橙(7)。突起方向：若突起从矩形的左边或右边伸出则为"水平突起"；若从上边或下边伸出则为"垂直突起"。生成约束：同一行/列上不会有两个矩形的垂直/水平突起同时射线方向相对（避免射线冲突歧义）。

**规则**：
1. 对每个空心矩形，找到其橙(7)突起像素，判断突起方向（突起相对于轮廓的朝向）。
2. **水平突起分支**：将该矩形内部（轮廓围成的黑(0)区域）填充为橙(7)，同时将该矩形的轮廓色改为黑(0)（内外色互换：原来轮廓有色内部黑，变为轮廓黑内部有色）。删除突起像素。
3. **垂直突起分支**：保留矩形不变。从突起像素位置沿突起朝向发射一条射线，射线颜色为该矩形的轮廓色，逐格延伸直到网格边缘或遇到任何非黑(0)像素（不覆盖终点像素）。删除原始突起像素，射线取代之。
4. 冲突处理：若垂直分支的射线穿过已被水平分支填充的矩形内部区域，射线像素覆盖填充色（射线优先）。处理顺序：先执行所有水平分支的填充，再执行所有垂直分支的射线。

**关键洞察**：同一种结构特征（突起）在不同朝向下触发完全不同的操作——这不是参数化的同一操作，而是真正的逻辑分叉；两个分支的结果在空间上可能交互（射线穿过填充区），需要跨分支的优先级规则。

## 新题 6：去噪与补周期的相互约束

**组合逻辑**：[对角噪声 + 擦除](已有) ⇄ [周期瓦片 + 最小周期推断填补](已有)（双向约束：去噪需要周期信息区分噪声与图案，补周期需要去噪后的干净样本）

**来源原语**：对角噪声(diagonal_noise)·擦除(erase)·忽略干扰项(ignore_distractors)·间隙长度限制(gap_length_constraint)·补线(line_completion) ← 7b80bb43；周期瓦片(periodic_tile)·缺失单元(missing_cell)·最小周期推断填补(smallest_period_inferred_fill) ← 29ec7d0e

**依赖链**：画布同时存在对角噪声和周期缺失 → 噪声像素可能恰好位于周期位置上（看似合法）→ 判断某像素是噪声还是周期图案需要同时考虑其连通性（是否仅有对角邻居）和周期一致性（是否符合最小周期）→ 两个约束必须联合求解

在一个既有对角阶梯噪声又有周期性缺失的网格上，同时去除噪声并补全周期图案，两个任务相互依赖。

**输入结构**：约 14x14 的黑(0)背景网格。存在一种前景色（如蓝(1)）构成的周期图案，最小周期为 p（水平和垂直周期相同，p 取 3 或 4）。该周期图案的部分单元被删除（显示为黑(0)），形成"缺失单元"。此外，有若干蓝(1)像素构成 45 度对角阶梯链——每个对角噪声像素与其他蓝(1)像素仅有对角邻接（8-连通但 4-断连）。关键复杂性：某些对角噪声像素恰好位于 (row mod p, col mod p) 与周期图案一致的位置上，表面上看与周期图案兼容。生成约束：真实的周期图案瓦片中，每个非背景位置至少在网格中出现 2 次作为干净样本（无对角邻接的孤立噪声），确保有足够信息进行消歧。

**规则**：
1. 识别所有仅有对角前景邻居、没有任何正交前景邻居的蓝(1)像素，标记为"疑似噪声"。
2. 对剩余的蓝(1)像素（非疑似噪声），推断最小周期 p：找到最小的 p 使得所有剩余蓝(1)像素在 (row mod p, col mod p) 位置上一致。
3. 用推断出的周期 p 反过来验证疑似噪声：若某个疑似噪声像素的 (row mod p, col mod p) 位置在周期瓦片中应为前景色，且该像素至少有一个正交方向上的相邻周期位置也有前景像素（只是因为缺失而暂时不可见），则该像素是被误判的真实图案像素，不应删除。否则确认为噪声，删除。
4. 删除确认的噪声像素后，补全所有缺失单元：对每个黑(0)位置，若 (row mod p, col mod p) 在周期瓦片中应为前景色，则填入蓝(1)。

**关键洞察**：去噪和补周期不是先后两步，而是相互约束的联合推理——仅靠连通性无法区分恰好落在周期位置的噪声，仅靠周期性无法区分落在周期位置的噪声与真正的缺失单元；必须同时使用两个约束才能消歧。

## 新题 7：位移碰撞产生新形状，新形状的对称性决定重涂色

**组合逻辑**：[颜色编码位移 + 平移](已有) → [碰撞阻挡](创新：不是阻挡停止，而是重叠合并) → [对称类型决定颜色 + 重涂色](创新：对称分类的对象不是输入精灵，而是碰撞合并后的涌现形状)

**来源原语**：颜色编码位移(color_encoded_disp)·平移(translate)·颜色决定偏移(color_determines_offset) ← 342dd610；碰撞阻挡(collision_block) ← d282b262；对称类型决定颜色(symmetry_det_color)·对称轴(symmetry_axis)·重涂色(recolor) ← a09f6c25

**依赖链**：颜色决定位移向量 → 位移后某些精灵重叠合并 → 合并后的连通区域形成新的形状 → 新形状的反射对称性决定该区域的最终颜色 → 位移方案不同则合并形状不同、对称性也不同，三步环环相扣

前景精灵按颜色编码的方向平移后，重叠的精灵合并为新的连通区域；每个合并区域按其反射对称类型被统一重涂为特定颜色。

**输入结构**：约 13x13 的灰(5)背景网格。散布 4~6 个单色前景精灵（每个精灵 2~4 像素，4-连通，形状不限）。精灵颜色从 {红(2), 蓝(1), 绿(3), 橙(7)} 中选取，同色精灵可能有多个。颜色与位移的对应关系：红(2) → 向右移 2 格；蓝(1) → 向下移 2 格；绿(3) → 向左移 2 格；橙(7) → 向上移 2 格。生成约束：平移后至少存在两组不同的重叠情况（至少 2 个合并区域），且合并后的区域分别呈现不同的对称类型。所有精灵平移后仍在网格范围内。

**规则**：
1. 清空画布为灰(5)背景。
2. 按颜色编码的位移平移每个精灵的所有像素：红(2)右移 2，蓝(1)下移 2，绿(3)左移 2，橙(7)上移 2。
3. 平移后，将所有前景像素视为一个集合，按 4-连通性划分为若干连通区域。每个连通区域可能由一个或多个原始精灵的像素合并而成。
4. 对每个连通区域，判断其反射对称类型：
   - 仅有水平对称轴 → 重涂为黄(4)
   - 仅有垂直对称轴 → 重涂为品红(6)
   - 同时有水平和垂直对称轴（含中心对称）→ 重涂为青(8)
   - 无任何反射对称轴 → 重涂为栗(9)
5. 未合并的孤立精灵（平移后仍独立的连通区域）同样按上述规则重涂。

**关键洞察**：输出颜色不由输入颜色直接映射，而是由位移导致的碰撞几何涌现决定——同样的输入精灵在不同初始位置会产生不同的合并形状和不同的对称性，从而得到不同的输出颜色。这是操作（平移）→ 涌现结构（合并形状）→ 属性分析（对称性）→ 重涂色的四步耦合链。

## 新题 8：印章填充后重力沉降——源体位置影响终态

**组合逻辑**：[掩码匹配 + 印章覆盖 + 源色覆盖占位副本](已有) → [擦除](已有) → [滑动 + 重力沉降 + 碰撞阻挡](已有，但作用对象是印章产物而非原始精灵) → 源体擦除的位置影响重力路径

**来源原语**：掩码匹配(mask_matching)·印章覆盖(stamp_overlay)·源色覆盖占位副本(source_colors_onto_placeholders)·精灵体(sprite)·占位对象(placeholder) ← 321b1fc6；擦除(erase) ← 321b1fc6；滑动(sliding)·碰撞阻挡(collision_block)·重力沉降(gravity_settle) ← d282b262

**依赖链**：掩码匹配决定哪些占位体被激活 → 印章覆盖赋予占位体多色图案 → 源体擦除在画布上留出空白 → 重力沉降时，空白区域改变了碰撞路径 → 若源体位于占位体下方，擦除它会让占位体下落更多

将源精灵的配色印到所有掩码匹配的占位体上，擦除源精灵，然后对所有印好的精灵施加向下重力使其沉降。

**输入结构**：约 15x18 的黑(0)背景网格。包含 1 个多色源精灵（3~5 像素，4-连通，由 2~3 种非黑颜色组成，如红(2)和蓝(1)）。另有 3~4 个灰(5)单色占位体，每个占位体的形状掩码（归一化后的像素相对位置集合）与源精灵完全一致。占位体分布在网格的不同高度。源精灵位于网格的中下部区域（非最底行）。网格底部可能有若干黄(4)的固定障碍块（1~2 个，各 2~3 像素，4-连通），它们不参与匹配和印章，但会在重力沉降中充当障碍。生成约束：占位体之间水平方向不重叠（列范围不交叉），使重力沉降时各精灵独立下落不互相干扰；源精灵正下方至少有一个占位体（使得擦除源精灵对该占位体的下落距离产生影响）。

**规则**：
1. 找到唯一的多色源精灵（由多于一种非黑色组成的 4-连通区域）。
2. 找到所有灰(5)的 4-连通占位体，验证每个占位体的归一化掩码与源精灵一致。
3. 将源精灵的多色图案印入每个匹配的占位体：占位体的每个像素按其在掩码中的相对位置，替换为源精灵对应位置的颜色。
4. 将源精灵的所有像素擦除为黑(0)背景。
5. 对所有已印色的占位体（现在是多色精灵）施加向下重力：所有精灵同时逐行下移，直到每个精灵的底部像素接触网格底边或接触下方已静止的精灵/障碍块的顶部。黄(4)障碍块不移动。
6. 输出最终画布。

**关键洞察**：源精灵的位置不只是"图案来源"——它在印章完成后被擦除，留出的空白改变了位于其上方的占位精灵的下落距离。若源精灵恰好挡在某个占位体的下落路径上，擦除它会让该占位体多下落若干行。求解者必须理解擦除和重力的顺序依赖。
