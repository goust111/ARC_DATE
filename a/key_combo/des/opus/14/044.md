## 新题 1：对角连线切割区域的面积填色

**组合逻辑**：[连线(connect)](创新：连线不再仅为视觉连接，而是作为区域边界) + [洪泛填充(flood_fill)] + [面积决定填充色(area_determines_fill_color)](创新：面积阈值对应三级颜色) ← [无障碍通路(unobstructed_path)] 与 [封闭区域(enclosed_region)] 同时约束

**来源原语**：连线/中心对角对齐/无障碍通路(55059096), 洪泛填充/封闭区域/面积决定填充色(c0f76784), 十字图案(55059096)

**依赖链**：灰色轮廓线形成半封闭结构 → 十字图案中心之间的对角连线穿过这些结构 → 连线与轮廓线共同构成全封闭边界 → 新形成的封闭区域面积决定填充颜色。删掉连线则区域不封闭、无法填充；删掉面积判断则不知道用什么颜色；删掉轮廓线则连线无法形成封闭区域。

根据十字图案间的对角连线与灰色轮廓线共同围合出的区域面积，分级填充不同颜色。

**输入结构**：黑(0)背景，约 18x18 网格。网格中有 4~6 个绿(3)色五像素十字图案（中心加四个基数方向邻居，3x3 边界框）。灰(5)色像素构成若干不规则的一像素宽轮廓线段（水平或垂直），这些线段形成半封闭的凹形或 U 形结构，单独无法围成完整封闭区域。部分十字图案的中心恰好在同一条 45 度对角线上，且它们之间的对角路径上只有黑色背景像素（无灰色或绿色像素阻挡）。生成约束：每条可画对角线至少与一段灰色轮廓线配合后能围成封闭区域；不同封闭区域的面积分布在 1~3、4~8、9+ 三个区间内。

**规则**：
1. 保留所有输入像素不变。
2. 对每对绿(3)十字图案，若两个中心的行差绝对值等于列差绝对值（即共线于 45 度对角线），检查两中心之间的严格对角线段上每个内部像素是否均为黑(0)背景。若是，将这些内部像素涂为红(2)。
3. 将红色对角连线视为与灰色轮廓线等价的边界。扫描所有 4-连通的黑(0)背景区域：若某区域被灰(5)像素、红(2)像素和/或网格边界完全包围（即该区域内无像素可通过 4-连通路径到达网格边缘而不穿越灰或红像素），则该区域为封闭区域。
4. 统计每个封闭区域的像素数（面积）。面积 1~3 的填品红(6)，面积 4~8 的填橙(7)，面积 9 及以上的填青(8)。
5. 不封闭的黑色区域保持黑色不变。

**关键洞察**：对角连线不是装饰——它们与已有轮廓线协同形成新的封闭边界；求解者必须先画连线，再判断哪些区域因此变得封闭，最后才能按面积分配颜色。

## 新题 2：异或解码坐标瓦片阵列

**组合逻辑**：[异或合成(xor_compositing)](已有) → [补全(completion)](创新：补全的对象不是直接给出的，而是从异或结果中涌现) + [阵列坐标编码(array_coord_encoding)](已有) + [孔洞位置等于坐标(hole_equals_coordinate)](已有)

**来源原语**：异或合成/半区掩码/恰一为前景(31d5ba1a), 补全/瓦片阵列/位置孔洞/阵列坐标编码/孔洞位置等于坐标(9ddd00f0)

**依赖链**：输入的上下半区各自看不出瓦片结构 → 异或合成后才涌现出带分隔行列的部分瓦片阵列 → 识别已有瓦片的孔洞位置编码规则 → 推断并补全缺失瓦片。删掉异或步骤则看不到瓦片阵列；删掉坐标编码规则则不知道如何填补缺失瓦片的孔洞位置。

将上下半区异或后涌现的部分坐标编码瓦片阵列补全为完整阵列。

**输入结构**：黑(0)背景，偶数高度的网格（约 16x8 或 14x7 再乘 2 = 约 16x16 或 14x14）。网格严格分为上半区和下半区，高度相等。上半区包含蓝(1)前景像素散布在黑色背景上；下半区包含红(2)前景像素散布在黑色背景上。两个半区单独看均为无规律的像素散布，不呈现可识别的结构。生成约束：上下半区的像素分布经过精心设计，使得对位异或（同位置恰有一个前景时输出前景，两个都有或都没有时输出背景）后，结果恰好是一个 n*n+n-1 边长的正方形区域内的部分瓦片阵列——n x n 的瓦片被单像素宽的背景分隔行列分开，已出现的瓦片用黄(4)前景填充（异或结果统一用黄(4)呈现），每个已出现瓦片内恰有一个背景像素位于该瓦片在阵列中的坐标位置处。至少出现 n 个瓦片（覆盖每行或每列至少一个），但不填满全部 n x n 个位置。n 的取值为 3 或 4。

**规则**：
1. 将上半区与下半区按位置对齐。对每个坐标 (r, c)，若上半区第 r 行第 c 列与下半区对应位置恰有一个为前景，则输出黄(4)；否则输出黑(0)。
2. 在异或结果中识别瓦片阵列结构：找到由单像素宽黑色行和列分隔的 n x n 格瓦片排列。
3. 对每个已出现的瓦片，验证其内部恰有一个黑色像素（孔洞），且该孔洞的局部坐标 (lr, lc)（在瓦片内的行列偏移，从 0 开始）等于该瓦片在阵列中的位置 (tr, tc)（瓦片行号, 瓦片列号，从 0 开始）。
4. 对每个缺失的瓦片位置 (tr, tc)，填入黄(4)前景并在局部坐标 (tr, tc) 处留一个黑(0)孔洞。
5. 输出为异或结果大小的网格（即上半区或下半区的尺寸），包含完整的 n x n 瓦片阵列。

**关键洞察**：瓦片阵列不存在于任何一个半区中——它是两半区异或运算的涌现产物；求解者必须先发现异或关系，才能进入坐标编码的补全阶段。

## 新题 3：标记像素按距离分配同心环层颜色

**组合逻辑**：[排序(sort)](创新：排序依据从坐标轴距离改为到环层的最小欧氏距离) + [最近邻选择(nearest_neighbor_selection)](创新：不再选择最近标记给对象赋色，而是反过来——标记选择最近环层来决定赋色序) + [重涂色(recolor)](创新：不是循环移位，而是按排序序列赋色) + [擦除(erase)](已有)

**来源原语**：排序/距离排序(291dc1e1), 最近邻选择/欧氏距离最小(6df30ad6), 重涂色/同心正方形层/嵌套层序(bda2d7a6), 擦除/标记像素(6df30ad6/b7256dcd)

**依赖链**：标记像素的空间位置 → 计算每个标记到各环层的最近距离 → 按距离从近到远排序标记颜色 → 排序结果映射为从外到内的环层重涂色方案 → 擦除标记。删掉排序则不知道颜色映射顺序；删掉距离计算则排序无依据；删掉重涂色则排序结果无用。

根据散落标记像素到同心环层的最近距离排序，将排序后的标记颜色依次赋给从外到内的环层。

**输入结构**：黑(0)背景，约 17x17 网格。网格中央有一组同心矩形环，共 4 层（从外到内），每层一像素宽，初始均为灰(5)。环层之间有一像素宽的黑色间隔。在环结构外部（不与任何环层 4-邻接）散布 4 个单像素标记，颜色分别为蓝(1)、红(2)、绿(3)、黄(4)，各出现恰好一次。生成约束：4 个标记到其各自最近环层像素的欧氏距离互不相等（无平局）；标记彼此不相邻，且不在网格边缘行列上。

**规则**：
1. 对每个标记像素，计算该标记到 4 层环中每一层所有像素的欧氏距离，取最小值作为该标记到该层的距离。再取 4 层中距离最小的那一层作为该标记的"最近环层"。
2. 按最近环层从外到内排序标记颜色：最近层为最外环的标记排第一，最近层为次外环的排第二，依此类推。若两个标记的最近环层相同（生成时已排除此情况），则按该层上的最小距离从小到大排。
3. 将排序后的颜色序列依次赋给从外到内的环层：第一个颜色赋给最外环，第二个赋给次外环，第三个赋给次内环，第四个赋给最内环。
4. 用赋得的颜色重涂对应环层的所有灰色像素。
5. 擦除所有标记像素（恢复为黑色背景）。

**关键洞察**：标记像素的空间位置隐式编码了环层的重涂色顺序——不是标记直接"染"最近的环（那只是 1 对 1 传色），而是标记的距离排序决定了全局的颜色排列方案。

## 新题 4：邻接传色触发笛卡尔积补全的颜色传播

**组合逻辑**：[邻接传色(adjacency_transfer)](已有) + [印章覆盖(stamp_overlay)](创新：新印章的颜色不固定，由传播规则从行列已着色精灵体推断) + [笛卡尔积缺位填充(cartesian_product_gap_fill)](创新：填充颜色不再统一，而是依赖行列交叉的颜色传播) + [擦除(erase)](已有)

**来源原语**：邻接传色/中性遮罩/标记像素/标记接触即赋色(b7256dcd), 印章覆盖/同形精灵体/笛卡尔积缺位填充/格点对齐(5b526a93), 擦除(6df30ad6)

**依赖链**：标记像素通过邻接传色给相邻精灵体着色 → 着色的精灵体标定了"活跃行"和"活跃列" → 笛卡尔积补全在空槽位生成新精灵体 → 新精灵体的颜色由其所在行的已着色精灵体颜色决定（若行无着色则用列的）。删掉邻接传色则所有精灵体仍为灰色、无颜色来源；删掉笛卡尔积补全则空槽位不填充；删掉颜色传播规则则不知道新精灵体用什么颜色。

标记像素先把颜色传给相邻的精灵体，再通过行列传播规则将颜色扩散到笛卡尔积补全的新精灵体上。

**输入结构**：黑(0)背景，约 19x19 网格。网格上有若干灰(5)色相同连通小图形（4-连通，4~6 像素，形状不规则但所有实例完全相同），排列在一个行列格点上（各实例的左上角分别在固定行起始和列起始的交叉点上）。格点共有 4 行 4 列共 16 个槽位，但仅有 7~9 个槽位被灰色精灵体占据，其余为空。在部分已占据精灵体的 4-邻接外侧各放置 1 个标记像素，颜色为蓝(1)、红(2)、绿(3)中的一种，共 3 个标记像素（颜色各不相同）。生成约束：每种标记颜色仅邻接一个精灵体；被标记的 3 个精灵体分别在不同的行上；至少存在一个空槽位同时位于某个有标记精灵体的行和另一个有标记精灵体的列上（用于测试行列冲突规则）。

**规则**：
1. 对每个 4-连通灰(5)精灵体组件，检查是否有非背景、非灰的标记像素与之 4-邻接。若有，将该精灵体所有灰色像素重涂为标记颜色（若一个精灵体邻接多个标记颜色——生成时已排除——取最先扫描到的）。
2. 擦除所有标记像素（恢复为黑色背景）。
3. 确定精灵体模板（公共形状掩码）和所有已有精灵体的左上角位置，从中提取行起始集合和列起始集合。
4. 对每个行列交叉点的空槽位 (r, c)，粘贴一个精灵体副本。新精灵体的颜色确定规则：
   - 检查同行（行起始 = r 的行）是否有已被传色的精灵体。若有，使用该行传色精灵体的颜色。
   - 若同行无传色精灵体，检查同列（列起始 = c 的列）是否有已被传色的精灵体。若有，使用该列传色精灵体的颜色。
   - 若行列均无传色精灵体，新精灵体保持灰(5)。
5. 已有的灰色精灵体（未被标记邻接的）保持灰色不变。

**关键洞察**：邻接传色只是颜色注入的起点；真正的难点在于理解笛卡尔积补全时颜色按"行优先、列次之"的传播规则扩散——这是源题中不存在的结构关系，因为 5b526a93 的补全颜色是统一的，b7256dcd 的传色不涉及格点传播。

## 新题 5：图例面板解码形状后按计数排序堆叠

**组合逻辑**：[查表替换(lookup_replace)](创新：查表结果不替换像素，而是获取颜色标签) + [旋转镜像等价匹配(rotation_reflection_match)](已有) + [计数(counting)](创新：计数对象从散落像素变为匹配同一图例的形状数量) + [排序(sort)](创新：排序依据从空间距离变为计数值) + [堆叠(stack)](已有)

**来源原语**：查表替换/图例面板/形状标记/颜色与形状对应/旋转镜像等价匹配(b20f7c8b), 计数(f3cdc58f/8efcae92), 排序/堆叠/距离排序(291dc1e1)

**依赖链**：图例面板定义颜色-形状字典 → 每个散落对象通过旋转/镜像匹配到一个图例形状（获得颜色标签） → 按颜色标签分组并计数 → 按计数从多到少排序各组 → 将每组的所有对象堆叠为一列（列内自上而下排列各对象）。删掉图例匹配则无法分组；删掉计数排序则不知道列的顺序；删掉堆叠则无法生成输出布局。

将散落对象通过图例匹配分组，按组内数量排序后堆叠为多列输出。

**输入结构**：黑(0)背景，约 20x20 网格。左侧有一个青(8)色矩形面板（约 6x8），面板内包含 3 个不同颜色的 8-连通形状（每个形状 3~5 像素，颜色分别为蓝(1)、红(2)、绿(3)），形状之间和面板边缘之间有青色间隔。面板右侧的区域散布着 7~10 个灰(5)色 4-连通小图形（每个 3~5 像素）。每个灰色图形的形状在旋转（0/90/180/270 度）和/或镜像变换下与面板中某一个形状等价。生成约束：3 种图例形状各自匹配到的灰色图形数量互不相等；每种图例形状至少被匹配 1 次；灰色图形之间互不重叠，各自的边界框不相交。

**规则**：
1. 提取图例面板中 3 个形状及其颜色。
2. 对每个灰色图形，尝试所有 8 种旋转/镜像变换，找到与某个图例形状像素结构完全一致的匹配。将该灰色图形标记为对应的图例颜色。（生成时保证每个灰色图形恰好匹配一个图例形状。）
3. 按图例颜色分组，统计每组中灰色图形的数量。
4. 按数量从多到少对各组排序。数量相同时（生成时已排除），按图例形状在面板中从上到下的出现顺序排列。
5. 输出一个紧凑网格：每组占一列，列从左到右按排序结果排列。每列内将该组的所有灰色图形自上而下依次放置（保持原始形状、不做旋转变换、用对应图例颜色绘制），相邻图形之间有 1 行黑色间隔。各列之间有 1 列黑色间隔。输出网格的高度为最高列的高度，较短列底部填黑色。

**关键洞察**：图例面板不直接替换像素（如 b20f7c8b 中那样），而是充当分类字典——匹配结果转化为分组依据，分组的计数值又决定堆叠时的列排布顺序，三层逻辑环环相扣。

## 新题 6：坐标轴约束旋转方向后嵌入框架槽

**组合逻辑**：[嵌入对齐(insert_and_align)](创新：嵌入对象不是凸起条，而是多个独立矩形) + [轴色决定旋转(axis_color_determines_rotation)](创新：旋转不再统一应用于所有对象，而是按对象与轴的相对位置选择性应用) + [列对齐(column_alignment)](已有) + [凸起匹配标记列(projections_match_columns)](创新：匹配的不是凸起与标记列，而是矩形宽度与槽内间隔宽度)

**来源原语**：嵌入对齐/框架槽/凸起条/列对齐/凸起匹配标记列(4c3d4a41), 轴色决定旋转/坐标轴线/矩形/距离排序(291dc1e1)

**依赖链**：坐标轴线颜色决定旋转规则 → 对每个矩形判断是否需要旋转 → 旋转后的矩形尺寸决定它能嵌入哪个框架槽间隔 → 按宽度匹配将矩形插入对应间隔。删掉坐标轴则不知道旋转规则；删掉旋转则矩形尺寸错误、无法匹配框架槽；删掉嵌入对齐则旋转后的矩形无处放置。

根据坐标轴线颜色确定矩形旋转方式，旋转后按宽度匹配嵌入灰色框架的对应间隔中。

**输入结构**：黑(0)背景，约 18x18 网格。网格左边缘有一条完整的垂直彩色线（蓝(1)或红(2)，占满该列所有行），网格上边缘有另一条完整的水平彩色线（与垂直线颜色不同），两线交汇于左上角一个栗(9)色像素。网格下半部分有一个灰(5)色矩形框架（一像素宽边框，内部为黑色，约 3x14），框架内部被 2~3 条垂直灰色隔板分成 3~4 个宽度不等的间隔（每个间隔宽度 2~4 像素，高度均等于框架内部高度）。网格中部散布 3~4 个实心彩色矩形（颜色各不相同，从黄(4)、绿(3)、橙(7)、品红(6)中取），每个矩形宽高均在 1~4 像素范围内。生成约束：蓝(1)线始终为垂直线或水平线之一（不固定）。每个彩色矩形在需要旋转时（见规则），旋转后的宽度恰好等于某个框架间隔的宽度，且这种匹配是一一对应的（无两个旋转后矩形宽度相同、也无两个间隔宽度相同——或者宽度相同时高度可区分）。

**规则**：
1. 识别两条边缘线的颜色。将蓝(1)线所在方向记为"蓝轴方向"。
2. 若蓝轴为垂直方向（左边缘是蓝线），则对每个彩色矩形执行 90 度逆时针旋转（行列互换，原来的列变行、原来的行变列，宽高交换）。若蓝轴为水平方向（上边缘是蓝线），则不旋转。
3. 将旋转后（或未旋转）的每个矩形与框架间隔按宽度匹配：矩形的宽度必须等于间隔的宽度。（生成保证每个矩形恰好匹配一个间隔。）
4. 将匹配的矩形放入对应间隔内：矩形水平居中于间隔（若矩形宽度等于间隔宽度，则左右对齐），矩形底边与间隔底边对齐（重力向下放置）。
5. 保留框架和隔板。擦除矩形的原始位置（恢复为黑色）。保留两条边缘线和栗色角标。

**关键洞察**：坐标轴线不直接参与视觉输出，而是编码了一个全局旋转指令——只有正确解读轴色才能得到正确的矩形尺寸，进而才能完成宽度匹配和嵌入对齐。

## 新题 7：帧内散落像素连接同色框边后按边分段计数渲染柱状图

**组合逻辑**：[裁剪(crop)](已有) + [连线(connect)](创新：连线方向由颜色对应的框边方位决定，非对角线而是正交方向) + [散落连接同色框边(scatter_connect_side)](已有) + [计数(counting)](创新：计数对象从单色像素变为每条框边上连接到的散落像素数) + [计数渲染柱状图(counts_as_histogram)](创新：柱状图的列不按调色板固定顺序，而按框边位置映射——上/右/下/左)

**来源原语**：裁剪/矩形框/散落像素/颜色对应边/散落连接同色框边(5daaa586), 计数/柱状条/调色板顺序/计数渲染柱状图(f3cdc58f)

**依赖链**：识别矩形框和散落像素 → 按颜色将散落像素连接到对应框边 → 统计每条框边被连接的散落像素数量 → 在裁剪后的框内底部区域用框边颜色渲染柱状图。删掉连线则无法确定哪些像素属于哪条边（计数无依据）；删掉计数则柱状图无高度信息；删掉裁剪则输出范围不确定。

裁剪矩形框，将散落像素连接到同色框边，再按每边的连接数在框内绘制柱状图。

**输入结构**：黑(0)背景，约 20x20 网格。网格中有一个由四条完整线段构成的矩形框（约 12x12），四条边颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)中各取一色，上边为一色、右边为一色、下边为一色、左边为一色）。四个角点颜色取该角相邻的两条边中行号或列号更小的那条边的颜色。矩形框外部散布若干单色像素，每个散落像素的颜色恰好与四条框边中的某一条相同。散落像素总数 8~14 个，每种框边颜色至少有 1 个、至多 5 个散落像素。矩形框内部初始全为黑色。生成约束：框的内部高度至少为 6 行（足以容纳柱状图）；框的内部宽度至少为 8 列（足以放下 4 列柱状图加间隔）。

**规则**：
1. 裁剪：输出为矩形框的精确边界框（含框线本身）。
2. 连线：对每个散落像素，沿垂直于其同色框边的方向画一条直线段，从散落像素出发延伸到同色框边上对应的像素为止（即行或列对齐的投影点）。连线颜色与散落像素和框边颜色相同。若散落像素在框外（裁剪前），连线中位于裁剪区域外的部分丢弃，仅保留进入裁剪区域后的部分。
3. 计数：统计四条框边各自有多少个散落像素与之颜色匹配（即被连接到该边的散落像素数）。
4. 柱状图渲染：在裁剪后框内部的底部区域绘制 4 列柱状图。四列从左到右分别对应上边、右边、下边、左边（固定框边方位顺序）。每列宽 1 像素，列与列之间间隔 1 像素黑色，4 列整体水平居中于框内部。每列从框内部底边向上填充该边颜色，高度等于该边的散落像素计数。
5. 连线像素与柱状图像素若重叠，柱状图覆盖连线。框线本身保持不变。

**关键洞察**：散落像素的颜色同时承载两层语义——它既决定连线方向（指向同色框边），又贡献给该框边的柱状图计数；求解者必须先理解颜色-框边对应关系，才能同时完成连线和计数两个操作。
