## 新题 1：嵌套框包含深度螺旋仪表

**组合逻辑**：[counting](创新：计量嵌套包含深度，而非原题中的空行数) + [spiral_fill](保留螺旋填充机制) + [hollow_rect + containment](引入空心矩形嵌套结构替代 U 形框架)

**来源原语**：counting, spiral_fill, gauge_output (参考题 b0c4d837); hollow_rect, containment (参考题 776ffc46)

**依赖链**：空心矩形的空间包含关系 → 计算每层嵌套深度 → 深度值作为螺旋填充量 → 生成仪表阵列。包含关系分析是计数的前提，计数结果是螺旋填充的输入，删除任一环节均无法求解。

将多层嵌套空心矩形的包含深度编码为一排按深度排列的螺旋仪表。

**输入结构**：黑(0)背景，约 18x18 网格。包含 3~5 个不同颜色的空心矩形（单像素宽的闭合矩形边框，颜色从红(2)、蓝(1)、绿(3)、黄(4)、品红(6)中选取），严格嵌套：每个矩形完全位于外一层矩形的内部空间中，最内层矩形的内部为纯黑(0)。各层矩形边框之间至少间隔 1 行/列的背景像素，确保嵌套层级可通过边界框包含关系唯一确定。不同示例中嵌套层数（3~5 层）和各层颜色均不同。

**规则**：
1. 识别所有空心矩形对象（单像素宽的闭合矩形边框），提取每个矩形的边界框。
2. 根据边界框的严格包含关系确定嵌套层级：最外层矩形深度为 1，被一层包含的深度为 2，依此类推直到最内层。
3. 输出为单行 3x3 单元格组成的阵列，单元格之间用 1 列黑(0)间隔。单元格从左到右按深度从小到大排列（最外层在最左）。输出网格高度为 3，宽度为 (矩形数量 x 3 + (矩形数量 - 1) x 1)。
4. 每个 3x3 单元格用该矩形的颜色沿顺时针螺旋从左上角开始填充（填充顺序：左上、上中、右上、右中、右下、下中、左下、左中、中心），恰好填充等于该矩形深度值的单元格数，其余位置为黑(0)。

**关键洞察**：螺旋填充量不来自几何测量（如空行数或面积），而来自拓扑关系（嵌套包含深度）；必须先重建完整的嵌套层级才能确定每个仪表的填充量。

## 新题 2：缺角位置同时编码补全方位与印章旋转角

**组合逻辑**：[completion](保留缺角补全) <-> [stamp_overlay](旋转方向由缺角位置决定，创新：缺角是双重信号——既是待修复缺陷，又是旋转元数据)

**来源原语**：completion, missing_corner_completes_square, inside_bbox (参考题 3aa6fb7a); stamp_overlay, control_sprite, coarse_to_fine_substitution (参考题 5833af48)

**依赖链**：缺角位置同时触发两个操作——(a) 补全该角为标记色，(b) 决定控制精灵体的旋转角度用于印章覆盖。单一几何特征承担修复和编码两种角色：跳过补全则无法标记哪个角缺失；跳过印章则无法利用方位信息。

在补全每个 L 形缺角的同时，用缺角方位决定控制精灵体以何种旋转角度印入对应区块。

**输入结构**：黑(0)背景，约 20x20 网格。灰(5)网格线将画布划分为若干不重叠的 6x6 区块（网格线宽 1 像素）。每个 6x6 区块的左上 2x2 子区域包含一个 3 像素的 L 形前景色对象（橙(7)，4-连通，占据 2x2 中的 3 个位置），缺少一个角像素（为黑(0)）。每个区块的右下 4x4 子区域为纯黑(0)。此外，网格外侧（如最上方或最左侧的独立区域）有一个 4x4 控制精灵体，由红(2)和青(8)像素组成，形成不对称图案（四个旋转态均可区分）。不同示例中各区块的 L 形缺角位置不同，控制精灵体图案不同。生成时保证至少出现 2 种不同的缺角方位。

**规则**：
1. 对每个区块中的 L 形对象，找到其 2x2 边界框中唯一的黑(0)像素（缺角位置）。
2. 将缺角像素涂为蓝(1)，完成 2x2 正方形。
3. 根据缺角在 2x2 中的位置确定旋转角度：左上缺角 -> 0 度；右上缺角 -> 顺时针 90 度；右下缺角 -> 180 度；左下缺角 -> 顺时针 270 度。
4. 将控制精灵体按该旋转角度旋转后，印入该区块的 4x4 子区域（红(2)和青(8)像素保持原色）。
5. 输出保留灰(5)网格线和所有补全后的 2x2 正方形。

**关键洞察**：缺角是"双重信号"——既是需要修复的几何缺陷（补全为蓝(1)），又是编码旋转方向的元数据（决定精灵体旋转角度）。单独的补全或单独的印章覆盖都无法产生完整输出。

## 新题 3：切比雪夫路径兼做对角射线屏障

**组合逻辑**：[connect + chebyshev_shortest](连线生成路径) <-> [ray_extend + diagonal_radiation](路径充当射线障碍物，创新：同一结构同时扮演连接器和屏障两种角色)

**来源原语**：connect, start_marker, end_marker, path, chebyshev_shortest, between_endpoints (参考题 992798f6); ray_extend, diagonal_radiation, extend_to_edge, isolated_pixel (参考题 ea786f4a)

**依赖链**：路径连接两个端点标记 -> 路径像素成为射线的不可穿透屏障 -> 射线从第三个发射点沿四对角方向延伸直到碰到路径或网格边缘。路径的几何形状（由端点位置唯一确定）直接决定每条射线的长度和终止位置。

先用切比雪夫最短路径连接两个端点，再从第三个发射点向四个对角方向发射射线，射线遇路径即停。

**输入结构**：黑(0)背景，约 15x15 网格。包含恰好三个特殊像素：一个蓝(1)像素和一个红(2)像素作为路径端点，以及一个绿(3)像素作为射线发射点。三个像素互不在同一行或同一列上，蓝(1)和红(2)之间在行方向和列方向上均有距离（保证路径包含对角段和直走段）。绿(3)像素位于蓝-红连线的一侧。生成时保证：(a) 绿(3)不在未来路径上；(b) 至少有两条对角射线会被路径截断（即射线在到达网格边界前先碰到路径）；(c) 至少有一条对角射线不被路径截断而到达网格边缘。不同示例中三个像素的位置不同。

**规则**：
1. 保留输入的蓝(1)、红(2)、绿(3)像素不变。
2. 从蓝(1)像素朝红(2)像素绘制切比雪夫最短路径：从蓝(1)的下一像素开始，先沿对角方向（每步行列各变化 1，朝红(2)靠近）行走，对角段走完后沿剩余的较长轴方向直走，到达红(2)的前一像素为止。路径像素（不含蓝(1)和红(2)本身）涂为灰(5)。
3. 从绿(3)像素出发，向四个对角方向（右下、右上、左下、左上）各发射一条射线，射线像素涂为橙(7)。
4. 每条射线逐像素延伸：当下一个目标位置超出网格边界，或该位置已有非黑(0)像素（灰(5)路径、蓝(1)/红(2)端点等），该射线停止。停止时的阻挡像素不被涂色，射线不包含阻挡位置。
5. 若某对角方向的第一步即遇阻挡或越界，则该方向不产生任何射线像素。

**关键洞察**：灰(5)路径同时扮演"连接器"（连接两端点）和"屏障"（截断对角射线）两种角色；路径的弯折几何直接塑造了射线辐射的不对称图案——改变端点位置会改变路径形状，进而改变哪些射线被截断。

## 新题 4：缺口方位双重编码滑动方向与缩放步长

**组合逻辑**：[slide + notch_determines_dir](缺口决定滑动方向和颜色) <-> [resize + side_length_cycle](缺口方位同时编码缩放循环步数，创新：同一几何特征的两个维度分别驱动位移和形变)

**来源原语**：slide, border_notch, edge_aligned, notch_determines_dir (参考题 320afe60); resize, odd_side_square, side_length_cycle, concentric_position (参考题 522fdd07)

**依赖链**：每个正方形的边框缺口方位是一个二维编码——第一维（左/上 vs 右/下）决定滑动方向和重涂色，第二维（上/右 vs 下/左）决定缩放循环步数。同一个几何特征同时驱动位移（改变位置）和形变（改变尺寸）两个独立变换，删除任一解码层均无法还原完整输出。

每个带边框缺口的奇数边正方形根据缺口方位向左或右滑至边缘并变色，同时按缺口位置编码的步数在尺寸循环中前进。

**输入结构**：黄(4)背景，约 20x25 网格。包含 3~5 个蓝(1)单色实心奇数边正方形（边长取自 {3, 5, 7}），彼此不重叠，各占据不同的行区间（各正方形的行跨度互不交叉，保证滑动后在垂直方向无冲突）。每个正方形的边框上恰好有一个缺口：某条边的正中间像素为背景色黄(4)（例如，边长为 5 的正方形上边缺口即上边第 3 个像素为黄(4)）。缺口可能出现在上、下、左、右四条边之一。不同示例中正方形的大小、位置、缺口方位不同。生成时保证：滑动并缩放后的正方形不超出网格上下边界。

**规则**：
1. 清空画布为黄(4)背景。
2. 对每个正方形，按中心行从上到下的顺序依次处理。检查缺口所在的边：
   - 缺口在左边或上边 -> 该正方形向左滑动，直到左边缘紧贴网格左边界（列 0），重涂为红(2)。
   - 缺口在右边或下边 -> 该正方形向右滑动，直到右边缘紧贴网格右边界（最后一列），重涂为绿(3)。
3. 同时根据缺口方位确定缩放循环步数（循环序列为 ...-> 9 -> 7 -> 5 -> 3 -> 1 -> 9 -> ...）：
   - 缺口在上边或右边 -> 边长在循环中前进 1 步（如 5 -> 3）。
   - 缺口在下边或左边 -> 边长在循环中前进 2 步（如 5 -> 1）。
4. 以正方形滑动后的中心位置（行取原始中心行，列取滑动后的中心列）为中心，按新边长绘制完整实心正方形（无缺口）。若新正方形超出网格上下边界，超出部分裁剪不绘制。
5. 各正方形行区间不交叉，故无重叠冲突。

**关键洞察**：缺口方位是一个二位编码——(左/上 vs 右/下) 对控制方向和颜色，(上/右 vs 下/左) 对控制缩放步数。需要对比多个示例才能分离出这两个编码维度，因为单个示例中方向和步数总是同时变化。

## 新题 5：缺口驱动剪切方向后点对称补全

**组合逻辑**：[notch_determines_dir](缺口决定剪切方向) -> [shear_transform + offset_grows_with_distance](执行方向性剪切改变形状) -> [point_symmetry + center_rotational](将变形后的对象点对称到另一侧)（创新：三环节非线性耦合——缺口同时影响剪切结果和最终对称副本的外观）

**来源原语**：shear_transform, bottom_anchor, offset_grows_with_distance (参考题 423a55dc); point_symmetry, center_marker, separator_col, center_rotational (参考题 e729b7be); border_notch, notch_determines_dir (参考题 320afe60)

**依赖链**：缺口方位 -> 决定剪切方向（左倾或右倾）-> 剪切改变对象形状 -> 变形后的对象点对称补全到分隔线另一侧。若跳过剪切，对称副本与原件形状相同，缺失变形效果；若跳过对称，右侧为空；若忽略缺口方位，剪切方向不确定。右侧出现的图形既非原件的简单点对称，也非固定方向的剪切结果。

根据每个图形的边框缺口决定左倾或右倾剪切，然后将剪切后的图形绕中心标记做 180 度旋转对称补全到分隔线另一侧。

**输入结构**：黑(0)背景，奇数行奇数列（约 17x21）网格。中心行的最左像素、正中像素、最右像素为栗(9)中心标记。正中列除中心标记外全部为黄(4)分隔色。分隔线左侧有 2~3 个不同颜色的小型 4-连通前景对象（每个 3~8 像素，形状非对称），颜色从红(2)、蓝(1)、绿(3)、品红(6)中选取。每个对象的边界框左边或右边上恰好有一个缺口（边框边缘上有一个像素为黑(0)而非前景色）。分隔线右侧为纯黑(0)。不同示例中对象的形状、颜色、位置、缺口方位不同。生成时保证：(a) 各对象互不相邻；(b) 剪切后的像素不越过分隔列；(c) 点对称映射后的像素在网格范围内。

**规则**：
1. 保留输入中的黄(4)分隔列和栗(9)中心标记。
2. 对左侧每个前景对象，检查其边界框缺口的方位：
   - 缺口在左边 -> 左倾剪切：以对象最底行为锚点，每向上一行，该行所有该对象的像素向左平移 1 格。
   - 缺口在右边 -> 右倾剪切：以对象最底行为锚点，每向上一行，该行所有该对象的像素向右平移 1 格。
   - 剪切后超出网格左边界的像素丢弃；超出分隔列（进入分隔列或右侧）的像素丢弃。
3. 剪切后的对象像素保留在左侧原位（覆盖剪切前的位置，先清除原对象像素再绘制剪切后的像素）。
4. 设中心标记为 (cr, cc)。对每个剪切后的对象像素 (r, c)，计算 180 度旋转映射点 (2*cr - r, 2*cc - c)。若映射点在网格范围内且不在分隔列上，用该对象的颜色涂该像素。
5. 若多个对象的旋转映射像素冲突（占据同一位置），按对象中心行从上到下的优先级，后处理的覆盖先处理的。

**关键洞察**：缺口不只分类对象，还实质性改变对象的形状（通过剪切方向），而改变后的形状又决定了点对称副本的几何外观。右侧出现的图形与左侧原件形状不同——求解者必须同时理解剪切方向规则和点对称机制才能正确预测输出。

## 新题 6：原型互换后形状匹配驱动参考色传递

**组合逻辑**：[replace + toggle_to_alternate_prototype](形状互换) <-> [recolor + shape_match + boxed_color_to_match](互换后的新形状与灰框参考匹配以确定颜色，创新：互换操作反转了形状-颜色对应关系)

**来源原语**：replace, prototype_sprite, prototype_pairing, toggle_to_alternate_prototype, anchor_region (参考题 c7f57c3e); recolor, shape_match, containment, hollow_rect, boxed_color_to_match (参考题 776ffc46)

**依赖链**：识别原型配对关系 -> 每个自由精灵体切换到交替原型形状 -> 新形状与灰框参考精灵体匹配 -> 用匹配参考的颜色重涂。形状匹配发生在原型互换**之后**，匹配目标是交替原型的形状而非原始形状。跳过互换则形状不匹配；跳过重涂则颜色错误。互换操作反转了直觉上的形状-颜色对应。

将每个自由精灵体切换到交替原型形状，再根据灰框内同形参考的颜色重新涂色。

**输入结构**：黑(0)背景，约 20x20 网格。包含以下元素：
- 2 个灰(5)空心矩形框（单像素宽边框，大小约 5x5~7x7），各自内部包含一个不同颜色的小型精灵体作为参考样本。参考 A 为红(2)，参考 B 为蓝(1)。两个参考精灵体形状不同且均不对称（各 3~5 像素，4-连通），不互为旋转或镜像。
- 4~6 个自由精灵体（不在灰框内），全部为橙(7)色。其中一半的形状与参考 A 完全相同（平移后掩码匹配），另一半与参考 B 完全相同。自由精灵体之间互不重叠，与灰框互不重叠。
- 生成时保证：两种参考形状在像素掩码上不存在旋转/镜像等价性，以便唯一确定匹配关系。

**规则**：
1. 识别灰(5)框和框内参考精灵体，记录参考 A 的形状掩码及颜色（红(2)）、参考 B 的形状掩码及颜色（蓝(1)）。
2. 对每个自由橙(7)精灵体，通过形状掩码匹配（忽略平移）判断其属于原型 A 还是原型 B。
3. 将每个自由精灵体的形状切换到交替原型：原型 A 的实例 -> 替换为原型 B 的形状掩码；原型 B 的实例 -> 替换为原型 A 的形状掩码。新形状以原精灵体边界框的左上角对齐放置，原位置的旧像素清除。
4. 切换形状后，该精灵体的新形状与某个灰框参考精灵体形状匹配。用该匹配参考的颜色替换橙(7)涂色。具体而言：原本是原型 A 的精灵体 -> 切换为 B 形状 -> 与参考 B 匹配 -> 涂为蓝(1)。原本是原型 B 的 -> 切换为 A 形状 -> 与参考 A 匹配 -> 涂为红(2)。
5. 灰(5)框及框内参考精灵体保持不变。

**关键洞察**：最终颜色取决于切换**后**的形状匹配，而非原始形状匹配。因此原本与参考 A 同形的精灵体最终获得参考 B 的颜色——互换操作反转了形状-颜色的对应关系。求解者若直接按原始形状匹配颜色会得到相反结果。

## 新题 7：射线侧翼构建禁区后寻找唯一安全路径

**组合逻辑**：[ray_extend + collision_generates_side_wakes](射线碰撞产生侧翼，构建动态禁区) -> [pathfinding + unique_safe_path + neighbor_exclusion](在禁区裁剪后的轨道中寻找唯一路径)（创新：射线模拟是中间步骤而非最终目标，其输出构建了寻路的约束场）

**来源原语**：ray_extend, branching, seed_pixel, obstacle_pixel, collision_generates_side_wakes, row_propagation (参考题 79fb03f4); pathfinding, track_path, endpoint, neighbor_exclusion, unique_safe_path, ignore_distractors (参考题 cc9053aa)

**依赖链**：种子像素发射水平射线 -> 射线碰撞障碍物产生侧翼扩展 -> 射线和侧翼像素的 8-邻域共同构成禁区 -> 禁区裁剪掉轨道路径的某些分支 -> 在剩余轨道中找到两个端点之间的唯一简单路径并重涂色。射线模拟的结果决定禁区形状，禁区形状决定哪条路径存活。

先模拟水平射线碰撞障碍物产生的侧翼扩展构建禁区场，再在射线未覆盖的轨道区域中找到两个端点间的唯一安全路径并涂色。

**输入结构**：黑(0)背景，约 18x18 网格。包含以下元素：
- 1~2 个黄(4)种子像素位于最左列（列 0），是水平射线发射器。
- 3~5 个灰(5)障碍像素散布在网格中，至少部分位于种子像素所在行上或附近（保证射线会碰到障碍）。
- 一条预设的青(8) 4-连通轨道路径，从网格上方区域延伸到下方区域，路径弯曲穿过网格。轨道路径在某些位置有分叉（存在多条可能路线连接两个端点）。
- 恰好 2 个栗(9)端点像素嵌在青(8)轨道上，分别位于轨道的两个末端。
- 生成时保证：(a) 射线模拟完成后，恰好有一条 4-连通简单路径在禁区外连接两个栗(9)端点；(b) 若不进行射线模拟（无禁区），则存在多条路径（即射线禁区确实裁剪掉了备选路径）；(c) 黄(4)射线和灰(5)障碍不直接覆盖青(8)轨道像素，禁区仅通过 8-邻域间接影响轨道。

**规则**：
1. 射线模拟阶段：
   - 从每个黄(4)种子像素向右逐像素发射射线，将经过的黑(0)背景像素涂为黄(4)。
   - 射线碰到灰(5)障碍像素时停止（障碍保持灰(5)不变）。在障碍正上方和正下方各 1 个像素位置产生侧翼：若该位置为黑(0)，涂为黄(4)；若为其他颜色则不涂。
   - 射线不穿过障碍，到障碍前一个像素即停。
2. 禁区定义：所有黄(4)像素（包括种子、射线、侧翼）及每个黄(4)像素的 8-邻域中的所有位置均为禁区。
3. 寻路阶段：
   - 在由青(8)和栗(9)像素组成的轨道图中，移除所有处于禁区内的青(8)像素（禁区内的栗(9)端点不移除）。
   - 在剩余轨道图中，找到连接两个栗(9)端点的唯一 4-连通简单路径。
   - 将该安全路径上的青(8)像素重涂为栗(9)。
4. 不在安全路径上的青(8)像素保持青(8)不变。黄(4)射线/侧翼像素、灰(5)障碍像素保留在输出中。

**关键洞察**：射线模拟不是最终目标而是中间步骤——它构建了一个动态禁区场，该禁区场通过 8-邻域扩展裁剪掉轨道路径的备选分支，使得两端点之间恰好剩余一条可行路径。必须先完成完整的射线碰撞模拟才能确定哪些轨道分支被封锁、哪条路径是唯一安全的。
