## 新题 1：障碍阻断射线投票

**组合逻辑**：[ray_cast](创新：射线被固定障碍截断而非延伸至网格边缘) + [vote/counting](创新：射线到达区域边界计为一票，多标记汇总投票) + [recolor](已有) + [stop_at_barrier](创新：从滑动阻挡改为射线阻挡)

**来源原语**：ray_cast（673ef223）、vote/marker_in_region（de1cd16c）、fixed_barrier/stop_at_barrier（9c56f360）、recolor（ba97ae07/25094a63）、color_region（de1cd16c）

**依赖链**：障碍的空间分布决定哪些射线能到达哪些区域（stop_at_barrier 约束 ray_cast 的有效覆盖范围），到达区域边界的射线构成投票（ray_cast 的输出成为 vote 的输入），投票汇总结果决定哪个区域被重涂（vote 的输出成为 recolor 的触发条件）。移除障碍阻断则投票退化为距离无关的全连接投票；移除投票统计则射线无聚合用途；移除重涂则投票结果无输出载体。三者缺一均导致输出不可确定。

一句话总结：每个标记像素向四方发射射线，射线遇障碍停止，到达彩色区域边界的射线为该区域投一票，票数最多的区域被重涂为黄色。

**输入结构**：约 18x18 的网格，黑(0)背景。包含以下元素：
- 3 个单色实心矩形区域，颜色分别为红(2)、蓝(1)、绿(3)，大小各约 3x4 像素（不同示例中大小可略有变化），分布在网格不同位置，彼此不相邻，且任意两个区域不共享同一行或同一列
- 若干灰(5)障碍像素，以孤立像素或长度不超过 3 像素的正交短线段形式散布在网格中，分布在标记与区域之间的路径上
- 2~4 个橙(7)标记像素，孤立放置（每个标记与最近的非背景像素至少相距 2 像素），不同示例中标记数量和位置不同
- 网格中不含黄(4)像素
- 生成约束：每个标记至少有一条射线能无阻挡地到达某个彩色区域的边界像素；不同示例中障碍布局不同，确保获胜区域在不同示例间有所变化；不同示例中三个区域获得的票数互不相同（无平票）

**规则**：
1. 每个橙(7)标记像素向上、下、左、右四个方向各发射一条射线。
2. 每条射线从标记像素的相邻格逐像素延伸。射线遇到以下任一情况时停止：灰(5)障碍像素、彩色区域像素（红(2)/蓝(1)/绿(3)）、其他橙(7)标记像素、或网格边缘。射线本身不包含起始标记和终止像素。
3. 若一条射线的终止原因是遇到了某个彩色区域的边界像素（即射线行进方向上第一个非背景非障碍像素属于红/蓝/绿区域之一），则该区域获得来自此标记的一票。同一标记最多投出 4 票（四个方向），可分别投给不同区域或多票投给同一区域。
4. 统计所有标记对所有区域的投票总数。将票数最多的区域的全部像素重涂为黄(4)。
5. 平票处理（仅在生成约束未能完全排除时作为兜底）：选取边界框左上角行号更小的区域胜出；行号相同则列号更小者胜出。
6. 标记像素、障碍像素及未获胜的区域保持原色不变。射线本身不可见，不在输出中绘制。

**关键洞察**：获胜区域不取决于标记与区域的欧氏距离或曼哈顿距离，而取决于障碍拓扑对射线路径的过滤。一个距离远但通道畅通的区域可以从多个标记获得投票，而一个近在咫尺但被障碍遮挡的区域可能一票未得。仅看单个示例可能误以为"最近的区域获胜"或"标记最多的行/列方向决定获胜者"，必须对比多个不同障碍布局的示例才能归纳出射线投票机制。

## 新题 2：滑动对齐后连线编码

**组合逻辑**：[slide/stop_at_barrier](已有) → [connect/row_col_aligned](创新：对齐关系由滑动结果动态产生而非静态存在) → [counting](已有) → [encoding](创新：连线数编码为空间图案而非简单计数)

**来源原语**：slide/stop_at_barrier（9c56f360）、connect/row_col_aligned（dbc1a6ce）、counting/encoding（ff28f65a）、fixed_barrier（9c56f360）、line_segment（dbc1a6ce）

**依赖链**：障碍位置决定滑动终点（barrier → slide），滑动终点决定哪些像素列对齐（slide → column alignment），列对齐触发连线生成（alignment → connect），连线数量决定输出编码（connect → count → encode）。这是一条信息持续变换的链：空间位置 → 运动终态 → 对齐关系 → 连通结构 → 数值 → 图案。删除滑动则无对齐关系可言；删除连线则列对齐无输出意义；删除编码则连线计数无载体。

一句话总结：红色像素在各行中向左滑动至障碍，滑动后同列的红色像素对用青色连线，连线总数编码为 3x3 蓝色图案。

**输入结构**：约 12x12 的网格，黑(0)背景。包含以下元素：
- 3~5 个红(2)像素，每个独占一行（不同行），初始位置在该行的右半部分（列号 >= 网格宽度/2），不同示例中行号和列号不同
- 若干灰(5)障碍像素，以孤立像素形式固定在网格中。每行最多一个障碍像素，位于该行红色像素的左侧某处。部分行没有障碍像素
- 网格中不含蓝(1)、青(8)、黄(4)像素
- 生成约束：滑动完成后，恰好有 1~5 对红色像素处于同一列（即至少 2 个红色像素滑动到同一列），且不同示例中同列对数不同。每列最多有 2 个红色像素滑动到位（不会出现 3 个以上同列），确保"对"的定义无歧义

**规则**：
1. 每个红(2)像素在其所在行内向左滑动：清除原位置，将像素放置在该行灰(5)障碍像素右侧紧邻的列。若该行无障碍像素，则放置在第 0 列。障碍像素本身不被覆盖，保持灰(5)。
2. 滑动完成后，检查所有红(2)像素的列坐标。对于每一对处于同一列的红色像素（该列恰好有 2 个红色像素），在它们之间的所有黑(0)背景格填充青(8)，形成一条竖直连线段（不包含两端的红色像素本身）。
3. 统计形成的青(8)连线段总数，记为 N。
4. 输出一个 3x3 的网格，初始全黑(0)。按以下固定顺序依次填充 N 个蓝(1)像素：(0,0)、(0,2)、(1,1)、(2,0)、(2,2)（行,列，0-索引）。即 N=1 时仅填 (0,0)；N=2 时填 (0,0) 和 (0,2)；N=3 时填 (0,0)、(0,2)、(1,1)；以此类推，最多 N=5。
5. 滑动过程中，若红色像素的目标位置已有另一个红色像素（两个红色像素滑动到完全相同的格），则后到者放置在先到者的右侧紧邻列。处理顺序为按原始行号从小到大。

**关键洞察**：障碍是整条推理链的上游控制变量——移动一个障碍改变对应像素的滑动终点，可能创建或消除一组列对齐，从而改变连线数和最终编码图案。仅看单个示例无法确定编码序列的固定顺序（可能误以为是按行扫描或其他规律），需要至少两个不同 N 值的示例才能推断填充顺序。

## 新题 3：交叉维度匹配填孔

**组合逻辑**：[crossing](创新：交叉区域的几何维度成为匹配键) + [shape_matching](创新：按矩形维度而非像素图案匹配) + [fill](创新：填充色来自交叉处的隐藏条颜色) + [recolor](已有)

**来源原语**：crossing（ba97ae07）、h_bar/v_bar（ba97ae07）、shape_matching（42f14c03）、object_with_holes/hole（42f14c03/8698868d）、fill（3ad05f52）、recolor（ba97ae07）

**依赖链**：横竖条的交叉产生具有特定维度的矩形区域（crossing → 维度集合），灰色对象中的孔洞与交叉矩形按维度配对（维度集合 → shape_matching），配对关系决定每个孔洞应填充的颜色——该颜色来自交叉处被遮挡的那根条的颜色（shape_matching + crossing_layering → fill_color）。移除交叉分析则无维度信息来源；移除维度匹配则无法将孔洞与交叉区关联；移除隐藏色规则则无法确定填充颜色。

一句话总结：横条与竖条的交叉区域产生特定维度的矩形，灰色对象中维度匹配的孔洞被填入交叉处隐藏条的颜色。

**输入结构**：约 18x18 的网格，黑(0)背景。包含以下元素：
- 2 根全宽横条（水平方向从第 0 列延伸至最后一列，各自占据连续若干行），颜色分别为红(2)和绿(3)，高度分别为 2 行和 3 行，位于网格上半部和下半部，彼此不相邻
- 2 根全高竖条（垂直方向从第 0 行延伸至最后一行，各自占据连续若干列），颜色分别为蓝(1)和橙(7)，宽度分别为 3 列和 4 列，位于网格左半部和右半部，彼此不相邻
- 4 个交叉矩形区域（每对横竖条产生一个交叉），维度分别为 2x3、2x4、3x3、3x4（横条高度 x 竖条宽度）。每个交叉区域内所有像素统一显示为两根相交条中某一根的颜色（即"上层"条的颜色），另一根条的颜色在交叉处不可见
- 一个大型灰(5)实心对象，边界框约 10x10，放置在网格中不与任何条重叠的区域。对象内部有恰好 4 个矩形背景孔洞（4-连通黑(0)像素区域），每个孔洞的维度（高度x宽度）与上述 4 个交叉矩形之一的维度匹配（允许 90 度旋转匹配：2x3 的孔洞匹配 3x2 的交叉或 2x3 的交叉）。四个孔洞维度互不相同，四个交叉维度互不相同，形成一一对应
- 网格中不含黄(4)像素
- 生成约束：四个交叉的"上层"条不全相同——部分交叉处横条在上层，部分交叉处竖条在上层（确保隐藏色不是单一规律可猜出的）

**规则**：
1. 识别全宽横条（在整行中无黑色像素间断的连续行带）和全高竖条（在整列中无黑色像素间断的连续列带），记录每根条的颜色和尺寸（高度/宽度）。
2. 计算每对横竖条的交叉矩形维度：(横条高度, 竖条宽度)。
3. 观察每个交叉区域内的实际显示颜色。该颜色对应"上层"条。"隐藏色"为该交叉处另一根条的颜色。例如：红(2)横条与蓝(1)竖条交叉，若交叉处显示红(2)，则隐藏色为蓝(1)。
4. 对灰(5)对象中的每个矩形孔洞，测量其维度（高度x宽度）。在四个交叉矩形中找到维度匹配的那个（维度完全相同，或旋转 90 度后相同：HxW 匹配 WxH）。
5. 将该孔洞填充为匹配交叉处的隐藏色。
6. 横条、竖条、交叉区域、灰色对象的非孔洞像素均保持不变。

**关键洞察**：填充色不是交叉处可见的颜色，而是被遮挡的那根条的颜色。仅看单个示例可能误以为"孔洞填交叉可见色"，必须对比多个示例（其中同维度交叉的可见色/隐藏色互换）才能确认填充规则取的是隐藏色。维度匹配（包含旋转）是将孔洞与交叉区域关联的唯一线索——颜色无法提前知道，位置无直接对应。

## 新题 4：走廊弯折编码旋转嵌套

**组合逻辑**：[pathfinding](创新：路径的几何特征——弯折次数——成为信息载体，而非路径本身) + [rotate](创新：旋转角度由路径拓扑动态决定而非固定) + [nest_inside](已有) + [size_matching](创新：维度匹配用于 sprite-frame 配对)

**来源原语**：pathfinding/corridor（3ad05f52）、rotate（36d67576）、nest_inside/hollow_frame（8698868d）、size_matching（890034e9）、anchor_pixel（36d67576）

**依赖链**：走廊的空间路径是 sprite 与 frame 之间唯一的物理连接（pathfinding 确定关联），路径中的弯折次数决定旋转角度（pathfinding 几何 → rotate 参数），旋转后的 sprite 必须尺寸匹配才能正确嵌入 frame（rotate + size_matching → nest_inside）。移除路径追踪则无法得知旋转量；移除旋转则嵌入后图案方向错误；移除嵌套则旋转和路径都失去输出意义。走廊同时承担"连接器"和"变换编码器"双重角色。

一句话总结：每个不规则小图形沿专属走廊滑向匹配的空心框架，走廊中 90 度弯折的次数决定图形被顺时针旋转的角度，旋转后嵌入框架内部。

**输入结构**：约 20x20 的网格，黑(0)背景。包含以下元素：
- 2~3 个空心框架：每个框架是 1 像素厚的灰(5)正方形边框（外轮廓 5x5，内部 3x3 为黑(0)背景），分布在网格不同区域，彼此间距至少 3 像素。每个框架的边框上恰有一个像素被替换为非灰色（该像素颜色与某个 sprite 的颜色相同），用于标识配对关系
- 2~3 个 sprite：每个是一个 4-连通的单色前景形状（3~6 像素，边界框 3x3），颜色各不相同（如红(2)、蓝(1)、绿(3)），且不具有 90 度旋转对称性（即至少一次 90 度旋转产生不同的像素图案）。sprite 放置在远离框架的位置
- 2~3 条橙(7)走廊：每条走廊由 1 像素宽的正交连续橙(7)像素构成，连接一个 sprite 的边界框外侧到其配对框架的边框外侧。走廊彼此不相交，不穿过任何框架或 sprite。每条走廊包含 0~3 个 90 度弯折（方向改变点），不同走廊的弯折数互不相同
- 网格中不含黄(4)像素
- 生成约束：sprite 与框架数量相等，配对关系由框架边框上的彩色像素唯一确定（颜色与某个 sprite 的颜色匹配）；不同示例中走廊弯折数不同，确保旋转角度在多个示例间有变化

**规则**：
1. 配对：每个 sprite 与框架边框上包含该 sprite 颜色像素的框架配对。
2. 路径追踪：沿橙(7)走廊像素从 sprite 侧追踪到框架侧。在走廊路径上计数 90 度方向改变的次数（从水平转为垂直或从垂直转为水平均计为一次弯折），记为 T。
3. 旋转：将 sprite 在其 3x3 边界框内顺时针旋转 (T mod 4) x 90 度。T=0 不旋转；T=1 旋转 90 度；T=2 旋转 180 度；T=3 旋转 270 度。
4. 嵌套：将旋转后的 sprite 放置在配对框架的 3x3 内部空间中心，sprite 像素覆盖原有的黑(0)背景。sprite 使用其原始颜色。
5. 擦除：将所有橙(7)走廊像素和 sprite 原始位置的像素替换为黑(0)背景。
6. 框架边框（包括其上的彩色配对像素）保持不变。

**关键洞察**：走廊不仅仅是连接 sprite 与框架的通道——其几何弯折次数隐式编码了旋转变换参数。仅看单个示例中一条直通走廊（T=0）和一条单弯走廊（T=1）可能误以为规则是"有弯就旋转 90 度、无弯不旋转"，但无法确定多弯的规律（是每弯加 90 度还是有弯就统一旋转）。必须对比包含不同弯折数的示例才能归纳出 T x 90 度的线性编码规则。

## 新题 5：孔洞检测与信号色压缩

**组合逻辑**：[flood_fill](创新：用于检测区域内部孔洞而非填充通道) + [compress/quadrant_mapping](创新：从面板级压缩推广到任意区域阵列压缩) + [counting](创新：全局颜色稀有度分析而非简单计数) + [recolor](创新：孔洞存在与否作为重涂条件)

**来源原语**：flood_fill（a64e4611）、compress/quadrant_mapping（19bb5feb）、counting/vote（de1cd16c/ff28f65a）、recolor（25094a63）、hole（8698868d）、color_region（de1cd16c）、panel（4e7e0eb9）

**依赖链**：这不是线性流水线，而是两条独立分析路径在最终压缩步骤汇合。路径 A：对每个区域进行孔洞检测（flood_fill 识别区域内部的背景连通分量），判定每个区域是否含孔。路径 B：全局颜色统计，找出仅出现于一个区域中的"信号色"（counting/稀有度分析）。汇合：压缩时根据孔洞状态和信号色身份三方联合决定每个输出格的颜色。移除孔洞检测则无法区分有孔和无孔区域；移除信号色识别则不知道有孔区域应填什么颜色；移除压缩则两项分析无汇合载体。

一句话总结：将 3x3 区域阵列压缩为 3x3 输出，无孔区域保留原色，有孔区域替换为全局唯一的信号色，信号色自身的区域变为背景。

**输入结构**：14x14 的网格。黑(0)像素在第 4 列、第 9 列、第 4 行、第 9 行形成 1 像素宽的十字分隔线，将网格划分为 3x3 共 9 个 4x4 的正方形区域（区域坐标：左上角分别在 (0,0)、(0,5)、(0,10)、(5,0)、... 等位置）。包含以下元素：
- 每个 4x4 区域内大部分像素为同一种前景色（该区域的"主色"），使用红(2)、蓝(1)、绿(3)、橙(7)、灰(5)、品红(6)、栗(9)中的若干种。不同区域可以有相同主色，但恰好有一种颜色仅作为主色出现在唯一一个区域中（称为"信号色"）
- 部分区域内部有 1~3 个黑(0)背景像素作为"孔洞"——这些像素被该区域的主色像素完全包围（4-连通意义下与分隔线和网格边缘不相连）。其余区域内部无孔洞（全部为主色像素）
- 分隔线像素均为黑(0)
- 信号色区域本身可以有孔洞，也可以没有孔洞（不同示例中有不同情况）
- 生成约束：至少 2 个非信号色区域有孔洞；至少 2 个区域无孔洞；信号色在整个网格中仅作为一个区域的主色出现（其他区域的主色均与信号色不同）

**规则**：
1. 识别 9 个 4x4 区域及其分隔线结构。对每个区域统计主色（区域内出现次数最多的非黑色颜色）。
2. 孔洞检测：对每个区域，检查其 4x4 范围内是否存在黑(0)像素被主色像素完全 4-连通包围（即该黑色像素的所有 4-连通邻居要么是主色像素，要么是同一孔洞中的其他黑色像素，且该连通分量不与区域边界上的分隔线相连）。若存在则标记该区域为"有孔"。
3. 信号色识别：统计所有 9 个区域的主色。找到仅出现一次的主色，即信号色。
4. 输出一个 3x3 网格，每格对应一个区域：
   - 若该区域无孔洞：输出格 = 该区域的主色。
   - 若该区域有孔洞且主色不是信号色：输出格 = 信号色。
   - 若该区域是信号色区域（无论有无孔洞）：输出格 = 黑(0)。
5. 分隔线不出现在输出中。

**关键洞察**：信号色在输入中仅标记一个区域，但在输出中却可能出现在多个位置（所有有孔的非信号区域）。信号色区域自身则"消失"为黑色——它是钥匙而非锁。仅看单个示例可能误以为"有孔区域统一变为某固定颜色"或"直接取孔洞数量做映射"，必须对比多个示例中信号色的变化才能发现信号色是由全局稀有度决定的，且它替代的是孔洞区域的颜色而非孔洞本身的位置信息。

## 新题 6：镜像形状识别裁剪填充

**组合逻辑**：[crop](已有) + [mirror](创新：镜像不是输出操作，而是匹配过程中的逆变换——必须将标记形状水平翻转后才能与孔洞匹配) + [shape_matching](创新：匹配需要先执行镜像预处理，直接比较会失败) + [fill](已有) + [ignore_distractors](已有)

**来源原语**：crop（42f14c03/3f7978a0）、mirror（4e7e0eb9）、shape_matching/normalized_match（42f14c03）、fill（42f14c03）、object_with_holes/hole（42f14c03/8698868d）、marker_shape（42f14c03）、ignore_distractors（42f14c03）

**依赖链**：镜像是匹配的前置条件（mirror → shape_matching），匹配结果决定裁剪哪个对象和用什么颜色填孔（shape_matching → crop + fill），干扰项的排除依赖匹配结果（shape_matching → ignore_distractors）。移除镜像则标记形状与孔洞无法匹配（它们是左右相反的）；移除匹配则无法确定裁剪对象和填充颜色；移除裁剪则输出范围不可确定。镜像-匹配是一个不可拆分的融合操作：跳过镜像直接匹配会得到零匹配结果。

一句话总结：将标记形状水平翻转后与各大型对象的孔洞匹配，裁剪孔洞全部匹配成功的对象，用对应标记的颜色填充孔洞。

**输入结构**：约 16x16 的网格，黑(0)背景。包含以下元素：
- 2~3 个大型单色前景对象，各使用不同颜色（如灰(5)约 6x7、栗(9)约 5x6），均为 4-连通形状，每个对象的边界框内含有 1~2 个矩形或不规则形状的背景孔洞（黑(0)像素连通区域，被对象颜色完全包围）。不同对象的孔洞形状（在边界框内的相对位置和像素布局）互不相同
- 2~3 个小型标记形状（marker），各为不同颜色（如红(2)约 3~5 像素、蓝(1)约 3~5 像素），均为 4-连通形状，放置在远离大型对象的位置。每个标记形状是某个大型对象的某个孔洞的水平镜像（左右翻转）版本
- 恰好一个大型对象是"目标对象"：该对象的所有孔洞都能在标记形状中找到镜像匹配（形成双射——每个孔洞匹配一个标记，每个标记匹配一个孔洞）。其余大型对象的孔洞无法与任何标记形状建立完整的镜像匹配（它们是干扰项）
- 标记形状与目标对象的孔洞之间没有颜色对应关系暗示——匹配完全基于几何形状的镜像关系
- 生成约束：标记形状的原始形状（未翻转）与任何对象的孔洞形状均不直接匹配，确保必须执行镜像操作才能找到匹配

**规则**：
1. 提取每个大型对象内部所有孔洞的形状（将孔洞像素在边界框内的相对位置记录为归一化形状，左上角对齐到 (0,0)）。
2. 对每个标记形状，计算其水平镜像（左右翻转）后的归一化形状。
3. 对每个大型对象，检查是否存在其所有孔洞与标记形状的镜像之间的双射匹配（每个孔洞的归一化形状恰好等于某个标记镜像后的归一化形状，且无重复使用标记）。
4. 找到唯一满足完整双射匹配的大型对象（目标对象）。裁剪该对象的边界框作为输出网格的范围。
5. 在裁剪后的输出中，将每个孔洞填充为与其匹配的标记形状的颜色。目标对象的非孔洞像素保持原色。
6. 其余大型对象和未匹配的标记形状不出现在输出中。

**关键洞察**：直觉上会尝试直接用标记形状匹配孔洞，但由于标记是孔洞的水平镜像，直接匹配必然失败。解题者必须发现镜像关系才能建立匹配。这一发现需要对比多个示例：在某个示例中标记恰好是对称的（镜像后不变），可能会误以为是直接匹配；只有在标记不对称的示例中，直接匹配失败才会迫使解题者尝试镜像操作。
