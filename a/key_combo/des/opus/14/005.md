## 新题 1：主干选通虚线补填

**组合逻辑**：[连线/连接到主干](源自 bf89d739，改造为空间选通器) + [填充/单像素间隙补填](源自 a699fb00，触发条件由主干掩码限定) + [擦除](源自 f76d97a5，清除非选通区域)

**来源原语**：连线/connect_to_spine(bf89d739), 填充/single_gap_filled(a699fb00), 掩码决定保留/mask_determines_keep(f76d97a5), 虚线段/dashed_segment(a699fb00), 控制像素/control_pixel(bf89d739), 主干线段/spine_segment(bf89d739)

**依赖链**：主干构建确定绿色(3)线段的空间位置 → 绿色线段充当空间掩码，限定哪些虚线间隙有资格被补填 → 未被掩码覆盖的间隙不补填。删除主干构建则无法确定掩码位置；删除间隙补填则主干无用武之地。

在黑色背景上，红色控制像素通过正交线段连接到主干，所形成的绿色路径网络选通蓝色虚线中哪些间隙被补填为红色。

**输入结构**：约 15x18 的黑(0)背景网格。含 4~6 个红(2)像素，其中恰好两个共享同一行或同一列（构成主干对）。另有 3~5 条水平蓝(1)虚线段，每条由蓝像素与单像素黑间隙交替组成，长度 5~11 像素，分布在网格不同行。虚线段之间不相邻（行间距至少 2）。非主干红像素分布在主干的垂直跨度范围内（若主干水平则在主干列跨度内），保证每个非主干红像素到主干有无阻碍的正交路径。生成约束：绿色连接线段（尚未绘制）会穿过某些虚线间隙所在的行列交叉点，但不会穿过蓝色像素本身。

**规则**：
1. 找到共享同一行或同一列的两个红(2)像素，将它们之间的黑(0)像素涂绿(3)，两端红像素保持红色不变，形成主干线段。
2. 对每个非主干红像素，沿垂直于主干的方向绘制绿(3)线段直到接触主干线段所在的行或列（不覆盖主干线段上的绿像素——那些已经是绿色；也不覆盖端点的红像素）。连接线段只覆盖黑(0)像素。
3. 检查每条蓝(1)虚线段中的每个单像素黑间隙：若该间隙像素恰好位于某条绿(3)线段（主干或连接段）所经过的列（若主干水平）或行（若主干垂直）上，则将该间隙涂红(2)。
4. 不满足上述条件的间隙保持黑(0)不变。
5. 所有绿(3)线段、红(2)像素、蓝(1)像素均保留在输出中。

**关键洞察**：绿色主干网络不是装饰线条，而是空间选通掩码——虚线间隙是否补填取决于它与主干网络的列（或行）对齐关系，必须先完成主干构建才能判定补填位置。

## 新题 2：旋转编码的同心包裹顺序

**组合逻辑**：[旋转检测](源自 7953d61e，改造为编码信号而非视觉变换) + [压缩/每区域折叠单像素](源自 780d0b14，提取颜色) + [嵌套包裹/逐层构建](源自 45a5af55，层序由旋转编码决定)

**来源原语**：旋转/rotation(7953d61e), 压缩/compress(780d0b14), 嵌套包裹/nested_wrapping(45a5af55), 网格分区/grid_partition(780d0b14), 逐层构建/layer_by_layer_build(45a5af55), 逐象限旋转排布/quadrant_rotation_layout(7953d61e), 分隔线/divider_line(780d0b14), 色块区域/colored_region(780d0b14)

**依赖链**：网格分区 → 每个区域内精灵的旋转角度编码一个优先级数字 → 优先级数字决定颜色在同心包裹中的层序 → 区域颜色决定每层颜色。旋转检测、颜色提取、包裹构建三者缺一不可。

将分区网格中每个区域的精灵旋转角度解码为层序编号，按此顺序用区域颜色由内向外构建同心正方形框架。

**输入结构**：约 15x15 的网格，由黑(0)单像素宽分隔线划分为 3x3 或 4x4 等大的正方形区域（每个区域约 3x3 至 4x4 像素）。每个区域内包含一个小型非对称单色精灵（2~4 像素的 4-连通图形，精灵在其区域内的形态是同一模板的 0/90/180/270 度旋转之一）。不同区域的精灵颜色互不相同，均为非黑非灰前景色。参考精灵（0 度）以左上角区域为准。生成约束：区域数量不超过 8 个（保证颜色够用）；每个旋转角度至少出现一次以提供归纳线索。

**规则**：
1. 识别黑(0)分隔线，定位所有矩形区域。
2. 以左上角区域的精灵朝向定义为 0 度参考。对每个区域，判断其精灵相对于参考的旋转角度：0 度=0，逆时针 90 度=1，180 度=2，逆时针 270 度=3。
3. 按行优先顺序读取所有区域，提取每个区域的（颜色, 旋转编码值）对。
4. 按旋转编码值从小到大排列区域；编码值相同时按行优先读取顺序排列。排列结果的第一个区域为最内层，最后一个为最外层。
5. 最内层区域的颜色构成中心实心正方形，边长=1。每个后续区域的颜色在当前形状外包裹一层正方形框架，厚度=1。
6. 输出为构建完成的同心正方形，尺寸为 2N-1 x 2N-1（N 为区域总数）。

**关键洞察**：精灵的旋转角度不产生视觉变换效果，而是作为隐式编码信号决定同心包裹的层序——必须对比多个示例才能发现旋转角度与层序的映射关系。

## 新题 3：禁区屏蔽的印章覆盖

**组合逻辑**：[印章覆盖](源自 a04b2602，印章区域被禁区截断) + [避障/禁区](源自 cb2d8a2c，禁区半径由蓝像素计数编码) + [选择/仅处理区域内标记](源自 a04b2602，忽略区域外干扰项)

**来源原语**：印章覆盖/stamp(a04b2602), 避障/obstacle_avoidance(cb2d8a2c), 像素计数编码半径/pixel_count_encodes_radius(cb2d8a2c), 包含于边界框/in_bounding_box(a04b2602), 标记像素/marker_pixel(a04b2602), 禁区/exclusion_zone(cb2d8a2c), 忽略干扰项/ignore_distractors(a04b2602), 障碍条/obstacle_bar(cb2d8a2c)

**依赖链**：区域判定筛选有效标记 → 障碍蓝像素计数确定禁区半径 → 禁区空间范围屏蔽印章像素 → 每个标记的实际印章形状因周围障碍分布不同而不同。删除禁区计算则印章完整无缺（退化为原始印章题）；删除标记筛选则干扰标记产生错误印章。

在绿色矩形框内，对每个红色标记印上蓝色空心环，但障碍物的蓝色像素数量编码禁区半径，禁区内的印章像素被抑制。

**输入结构**：约 18x18 的黑(0)背景网格。一个绿(3)空心矩形框（单像素宽边框，内部约 12x12）。框内：2~4 个红(2)标记像素散布在黑色区域中；1~3 个障碍小块，每个障碍块由红(2)和蓝(1)像素混合组成（4-连通，3~6 像素），蓝像素数量 1~3 不等。框外：1~2 个红(2)干扰像素（与框内标记颜色相同但不参与计算）。生成约束：框内标记像素与障碍块互不相邻（间距至少 2 像素）；障碍块不接触绿色边框；每个标记的 3x3 邻域至少有一部分落入某障碍的禁区内（保证禁区确实截断印章）。

**规则**：
1. 识别绿(3)矩形框的边界框。仅处理边界框内部的红(2)像素作为有效标记；框外红像素为干扰项，原样保留不处理。
2. 对框内每个障碍块（含蓝(1)像素的 4-连通区域），计数其蓝像素数量 B。该障碍的禁区为：以障碍块每个像素为中心、曼哈顿距离 <= B 的所有像素的并集。
3. 对每个有效红标记，尝试将其 8-邻域（3x3 区域去中心的 8 个位置）涂蓝(1)。但若某个待涂位置落入任何禁区内，则该位置不涂色（保持原色）。
4. 标记像素本身始终保持红(2)。若两个标记的印章区域重叠，重叠位置涂蓝(1)（标记中心仍为红）。
5. 绿框、障碍块、干扰像素均原样保留。

**关键洞察**：每个标记的实际印章形状不是固定的 8-像素环，而是被周围障碍的禁区"啃蚀"后的不规则子集——必须先计算所有禁区的空间范围才能确定每个印章的最终形态。

## 新题 4：十字双功能的对称补全与象限着色

**组合逻辑**：[裁剪/边框](源自 77fdfe62，保留内部) + [对称补全/双轴对称](源自 60d73be6，十字轴线同时担任分区轴) + [重涂色/角标色定象限](源自 77fdfe62，创新为对称后再着色)

**来源原语**：裁剪/crop(77fdfe62), 对称补全/symmetry_complete(60d73be6), 重涂色/recolor(77fdfe62), 边框/frame(77fdfe62), 十字轴线/cross_axis(60d73be6), 角标像素/corner_pixel(77fdfe62), 稀疏标记/sparse_marker(60d73be6), 象限/quadrant(77fdfe62), 双轴对称/biaxial_symmetry(60d73be6), 四象限镜像填充/quadrant_mirror(60d73be6), 角标色定象限涂色/corner_sets_quadrant(77fdfe62)

**依赖链**：裁剪获得内部区域 → 十字轴线既是对称轴又是象限分界 → 对称补全确定所有标记位置 → 象限归属决定每个标记的最终颜色。十字的双重身份（对称轴+分区线）使三步紧耦合：对称补全使用十字的几何位置，着色使用十字划分出的象限归属。

裁剪出框内区域后，以内部十字为对称轴将稀疏标记反射到四个象限，再按角标颜色对每个象限的标记统一着色。

**输入结构**：约 17x17 的网格。一个灰(5)单色边框（两条水平满行线 + 两条垂直满列线构成矩形框）。框的四个对角外角各有一个前景色像素（四种不同颜色，从{蓝(1), 红(2), 绿(3), 黄(4), 品红(6), 橙(7)}中选取），作为象限图例。框内区域约 13x13：包含一个由栗(9)色构成的十字（一整行 + 一整列的栗色像素），将内部分为四个象限。在某一个象限（如左上象限）中散布 2~4 个白色... 不对，ARC 没有白色。在某一个象限中散布 2~4 个青(8)标记像素，其余三个象限无标记。生成约束：标记不接触十字轴线；十字轴线恰好在内部区域的中间行和中间列（保证四象限等大）。

**规则**：
1. 裁剪掉灰(5)边框及其外部，输出仅包含框内矩形区域（含十字轴线）。
2. 识别栗(9)色十字（内部的完整行和完整列）。以该十字为双对称轴，将每个青(8)标记像素反射到另外三个象限的对应位置（跨行反射、跨列反射、跨两轴反射），共得到最多 4 倍的标记。
3. 根据标记所在象限，将其重涂为对应的角标颜色：左上象限 → 框左上外角色，右上象限 → 框右上外角色，左下象限 → 框左下外角色，右下象限 → 框右下外角色。
4. 十字轴线的栗(9)色像素保留不变。背景像素（黑(0)）保留不变。
5. 框外的四个角标像素不出现在输出中（已被裁剪）。

**关键洞察**：栗色十字不是普通装饰——它同时担任对称反射的几何轴和象限划分的逻辑边界。仅凭单个示例无法区分"按角标色直接放置标记"和"先反射再按象限着色"，必须对比多个示例（标记在不同象限、不同位置）才能归纳出双重机制。

## 新题 5：平移后重组的主干连接

**组合逻辑**：[平移/按自身宽度平移](源自 64a7c07e，改变对象间对齐关系) + [连线/连接到主干](源自 bf89d739，作用于平移后的新布局) + [擦除](源自 f76d97a5，清除原始位置)

**来源原语**：平移/translate(64a7c07e), 连线/draw_line(bf89d739), 连通分量/connected_component(64a7c07e), 边界框决定偏移/bounding_box_determines_offset(64a7c07e), 按自身宽度平移/shift_by_own_width(64a7c07e), 连接到主干/connect_to_spine(bf89d739), 主干线段/spine_segment(bf89d739), 共行列定义主干/shared_row_col_spine(bf89d739), 控制像素/control_pixel(bf89d739)

**依赖链**：每个对象按自身宽度右移 → 移动后的新位置改变了哪些对象共享行/列 → 共享行/列的对确定主干 → 其余对象正交连接到主干。平移决定了主干身份，主干身份决定了连接拓扑——跳过平移无法确定正确的主干对。

将多个前景对象各自按边界框宽度右移后，在新位置上识别共行/列的主干对并绘制正交连接线。

**输入结构**：约 16x14 的黑(0)背景网格。含 4~6 个单色小型 4-连通前景对象，每个对象 2~5 像素，颜色均为红(2)。对象宽度（边界框宽度）各不相同（1~4 列宽）。关键约束：在输入原始位置上，没有任何两个对象共享同一行或同一列的边界框中心行/中心列。但在每个对象右移其自身宽度后，恰好有两个对象的边界框中心行或中心列对齐（成为主干对）。右移后所有对象不重叠，且每个非主干对象在主干的垂直跨度范围内（若主干水平）或水平跨度范围内（若主干垂直）。生成约束：右移后对象右端不超出网格边界。

**规则**：
1. 识别所有 4-连通红(2)前景对象，计算每个对象的边界框宽度 W。
2. 将画布清为黑(0)。将每个对象整体右移 W 列（即对象的每个像素列坐标加 W）。
3. 在新位置中，找到恰好两个对象共享同一行区间或同一列区间的对（若多对满足则选共享跨度最长的一对），将它们之间沿共享行或列的黑(0)像素涂绿(3)，两端对象的红色像素保持不变，形成主干线段。
4. 对每个非主干对象，从该对象最靠近主干的像素出发，沿垂直于主干方向绘制绿(3)线段直到接触主干线段所在行或列。连接线段仅覆盖黑(0)像素。
5. 所有红(2)像素保持红色，绿(3)线段覆盖黑色背景。

**关键洞察**：平移前没有任何对象对齐（无法构建主干），平移改变了空间布局，使特定对象对齐成为主干——主干的身份完全由平移后的几何关系决定，必须先完成平移才能识别。

**规则**：
1. 从所有无灰色像素的混色块中推断出完整的 3x3 环形精灵模板（包含每个位置的精确颜色）。

3. 对步骤 2 中新放置的每个环形精灵副本，执行一步循环移色：四个角位像素的颜色沿顺时针方向循环移动一位（左上→右上→右下→左下→左上）；四个边中位像素的颜色沿逆时针方向循环移动一位（上中→左中→下中→右中→上中）。
4. 分隔行和分隔列上的所有像素（包括曾被灰色擦除的）恢复为黑(0)。

**关键洞察**：环形精灵在输入中同时是编码符号（标记"开"状态的块）和结构化对象（角位/边中有不同颜色）。反转后空白块变成环形，这些新环形才是循环移色的目标——原始环形块被替换为纯色块，不再参与移色。精灵的双重身份使两个操作深度耦合。

**输入结构**：约 12x12 的黑(0)背景网格。含一个红(2)像素和一个青(8)像素，二者不在同行也不在同列。另有一个独立的多色正方形瓦片（如 3x3 或 4x4），使用 2~3 种非黑前景色（如绿(3)、蓝(1)、黄(4)），放置在远离两个端点的区域。三个元素（红像素、青像素、瓦片）互不相邻。生成约束：红像素与青像素的行差和列差均至少为 2（保证路径有可见的 L 形转折）；瓦片不与路径区域重叠。

**规则**：
1. 从红(2)像素出发，沿水平方向画黄(4)像素直到到达青(8)像素所在列，然后沿垂直方向画黄(4)像素直到到达青(8)像素所在行。红和青端点像素保持原色。
2. 计算路径（含两个端点）的边界框。在该边界框内构建二值掩码：路径像素（黄、红、青）= 填充，黑色背景 = 空白。
3. 以该掩码为控制精灵，以输入中的多色瓦片为图块，执行像素放大：掩码中每个填充像素替换为瓦片的完整副本，每个空白像素替换为与瓦片同尺寸的黑(0)区域。

**关键洞察**：直角路径不是最终输出的视觉元素，而是中间步骤产生的控制精灵形状。端点的空间位置通过路径几何间接决定了放大后图案的 L 形轮廓——这种"路径即控制精灵"的关系在单个示例中容易被误解为简单缩放。

**规则**：
1. 对左上象限中的每个标记像素：将标记清除为黑(0)，并将该标记正下方-右方的相邻腔室（同一格点周期内的封闭黑色区域）填充为标记的颜色。
2. 识别十字轴线（贯穿整个网格的完整青色行和完整青色列）。

5. 格点骨架青(8)色像素和十字轴线不变。

**关键洞察**：格点骨架同时提供两种约束——它定义了腔室的离散位置（限制了填充目标），又包含一条十字轴线作为对称轴（决定了传播方向）。标记只出现在一个象限，求解者必须发现十字轴线的对称传播功能才能填充其余三个象限。

## 新题 9：多尺度压缩与编码平移

**组合逻辑**：[压缩/每区域折叠单像素](源自 780d0b14，将大区域折叠为像素) + [平移/按自身宽度平移](源自 64a7c07e，创新为在压缩后坐标系中按原始宽度偏移) + [重涂色](源自 f76d97a5，碰撞解决)

**来源原语**：压缩/compress(780d0b14), 平移/translate(64a7c07e), 重涂色/recolor(f76d97a5), 分隔线/divider_line(780d0b14), 色块区域/colored_region(780d0b14), 连通分量/connected_component(64a7c07e), 边界框决定偏移/bounding_box_determines_offset(64a7c07e), 网格分区/grid_partition(780d0b14), 按自身宽度平移/shift_by_own_width(64a7c07e)

**依赖链**：网格分区和区域识别 → 每个区域内对象的边界框宽度记录（原始尺度信息）→ 压缩为单像素网格 → 在压缩网格中按原始宽度执行平移 → 碰撞时根据原始面积决定保留色。压缩销毁了空间细节但保留了颜色，而平移量来自被销毁的细节——两个尺度相互依赖。

将分区网格压缩为每区域一像素后，在压缩网格中将每个像素右移其原始区域内对象的边界框宽度。

**输入结构**：约 19x19 的网格，由黑(0)单像素宽分隔线（完整行和完整列）划分为 3x4 或 4x3 的矩形区域阵列（约 8~12 个区域）。每个区域约 4x4 至 6x5 像素。每个区域内部有一个单色 4-连通前景对象（2~6 像素），颜色各不相同，从 {蓝(1), 红(2), 绿(3), 黄(4), 品红(6), 橙(7), 青(8), 栗(9)} 中选取。对象形态各异，边界框宽度 1~4 列不等。区域内未被对象占据的部分为黑(0)。生成约束：不同区域内对象的边界框宽度至少有两种不同值（保证平移量有差异）；压缩后的网格宽度足以容纳最大平移量（否则使用环绕）。

**规则**：
1. 识别所有黑(0)分隔线（贯穿整个网格的完整行和完整列），定位各矩形区域。
2. 对每个区域，找到其内部非黑前景对象，记录其颜色 C 和边界框宽度 W。
3. 将整个网格压缩为一个小网格：每个区域折叠为一个像素，该像素颜色 = C。压缩后网格的行列数等于区域阵列的行列数。
4. 在压缩后的小网格中，将每个彩色像素向右平移 W 列（W 为该像素对应的原始区域内对象的边界框宽度）。平移后超出右边界的像素环绕到同一行的左侧。
5. 若两个像素平移后落在同一位置：保留对应原始区域内对象面积（像素数）更大者的颜色；面积相同则保留原始区域在行优先顺序中靠前者的颜色。
6. 未被任何像素占据的压缩格位填黑(0)。

**关键洞察**：压缩操作消除了空间细节但保留了颜色信息，而平移量恰恰编码在被消除的空间细节（边界框宽度）中——求解者必须在压缩前提取并记忆每个对象的宽度信息，才能在压缩后正确执行平移。这种跨尺度依赖是两个操作的核心耦合点。

## 新题 10：虚线条纹的同心框架构建

**组合逻辑**：[嵌套包裹/条高决定框厚](源自 45a5af55，框厚来自条纹高度) + [填充/单像素间隙补填](创新：虚线条纹的间隙模式转移到 2D 框架的周长上) + [擦除](源自 f76d97a5，间隙位置在框架上留空)

**来源原语**：嵌套包裹/nested_wrapping(45a5af55), 填充/fill(a699fb00), 色条/color_stripe(45a5af55), 同心正方形层/concentric_square_frame(45a5af55), 逐层构建/layer_by_layer_build(45a5af55), 条高决定框厚/stripe_height_as_thickness(45a5af55), 虚线段/dashed_segment(a699fb00), 单像素间隙补填/single_gap_filled(a699fb00), 邻接/adjacency(a699fb00)

**依赖链**：条纹高度决定框架层厚度 → 条纹是实心还是虚线决定对应框架层的填充模式 → 虚线间隙的位置模式沿框架周长映射为周期性缺口。条纹的几何属性（高度）和内部模式（实心/虚线）分别控制框架的不同特征。

从水平条纹自下而上构建同心正方形框架，实心条纹产生完整框架层，虚线条纹产生带周期性缺口的框架层。

**输入结构**：约 8x15 的网格（宽大于高）。自上而下堆叠 4~6 条横跨全宽的水平条纹，颜色各不相同（从前景色中选取），高度 1~3 行。条纹分两种：实心条纹（整行全为该颜色）和虚线条纹（该颜色像素与黑(0)像素在行内交替排列，间隔恰好 1 像素）。同一条纹内所有行的模式相同（若虚线则每行都是虚线，位相一致）。条纹之间无间距直接堆叠。生成约束：至少有一条实心条纹和一条虚线条纹；条纹颜色互不相同。

**规则**：
1. 从下到上读取条纹。最下方条纹为最内层，最上方为最外层。
2. 最内层条纹构成中心实心正方形，边长 = 该条纹高度（行数）。若该条纹为虚线，中心正方形也按虚线模式局部留空（按行优先顺序遍历正方形像素，虚线条纹第一行的着色/留空交替模式循环应用于正方形所有像素）。
3. 每个后续条纹在当前形状外包裹一层正方形框架，厚度 = 该条纹高度。
4. 实心条纹对应的框架层：所有像素填充为该条纹颜色。
5. 虚线条纹对应的框架层：从框架左上角开始，沿框架周长（上边从左到右、右边从上到下、下边从右到左、左边从下到上）顺序排列像素。按虚线条纹第一行的着色/留空交替模式（着色像素→填充该色，黑像素→留黑(0)）循环映射到周长上的每个径向位置。同一径向位置上框架的所有厚度层像素状态一致（全填或全空）。
6. 输出尺寸由所有条纹高度之和决定：边长 = 2 x (所有高度之和) - 最内层高度。

**关键洞察**：虚线条纹的 1D 交替间隙模式并非直接"缩放"到 2D 框架的每一行/列，而是沿框架周长重新映射——这种 1D 到 2D 的拓扑变换需要理解周长遍历顺序。仅看单个示例无法区分"按行填充"和"沿周长填充"的差异。
