## 新题 1：正交对角扫掠与交叉着色

**组合逻辑**：[滑动/slide](创新：从两条正交边同时扫掠，产生两组方向相反的对角轨迹) + [重涂色/recolor](创新：交叉单元格取第三种固定颜色，而非覆盖)

**来源原语**：滑动/slide、对角轨迹(diagonal_trace)、逐步平移(stepwise_translation) 来自 feca6190；重涂色/recolor 来自 396d80d7 / 2de01db2

**依赖链**：两组扫掠各自独立生成轨迹 → 轨迹的空间交叉生成重叠单元格 → 重叠判定触发第三色着色规则。扫掠方向和交叉判定缺一不可。

将两条分别位于左边缘和底边缘的稀疏线段沿正交对角方向扫掠，非重叠轨迹保持原色，两组轨迹交叉处着第三色。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 左边缘（第 0 列）放置一条与网格同高的稀疏竖线，其中 2~4 个像素为蓝(1)，其余为黑(0)。
- 底边缘（最后一行）放置一条与网格同宽的稀疏横线，其中 2~4 个像素为红(2)，其余为黑(0)。
- 左下角像素（最后一行第 0 列）固定为黑(0)，保证两条线不在起点重合。
- 生成约束：两条线的有色像素在网格内至少产生一个轨迹交叉点。

**规则**：
1. 将左边缘竖线沿右下方向（每步 +1 列、+1 行）逐步平移复制，直至整条线完全移出网格边界，超出边界的像素裁剪丢弃。蓝(1)像素在每步留下足迹，形成一组从左上到右下的平行对角轨迹。
2. 将底边缘横线沿右上方向（每步 +1 列、-1 行）逐步平移复制，直至整条线完全移出网格边界，同样裁剪。红(2)像素形成一组从左下到右上的平行对角轨迹。
3. 对每个网格单元格判定覆盖情况：
   - 仅被蓝轨迹覆盖 → 蓝(1)。
   - 仅被红轨迹覆盖 → 红(2)。
   - 同时被蓝轨迹和红轨迹覆盖 → 黄(4)。
   - 未被任何轨迹覆盖 → 保持黑(0)。

**关键洞察**：交叉色（黄）无法从单个交叉点确定——可能是蓝或红覆盖，也可能是某种混合规则。必须对比多个示例中交叉点的数量和位置，才能排除"后画的覆盖先画的"等替代假设，确认交叉色是固定的第三种颜色。

## 新题 2：面积驱动双向位移与碰撞仲裁

**组合逻辑**：[连通检测/connected_component_detection] + [平移/translate](创新：双向位移，上方对象下移、下方对象上移) + [计数/counting](创新：面积同时决定位移量和碰撞优先级)

**来源原语**：连通检测 来自 2c0b0aff；平移、位移等于面积(shift_equals_area) 来自 b2bc3ffd；裁剪、互补拼合(complement_fit) 来自 681b3aeb

**依赖链**：连通检测确定每个对象及其面积 → 面积决定位移距离 → 双向位移产生碰撞 → 碰撞仲裁再次依赖面积（小面积优先）。面积同时是位移参数和冲突解决参数，构成自指环路。

检测分隔条上下的单色连通对象，每个对象沿纵向朝分隔条方向平移自身面积步，碰撞区域由面积较小的对象覆盖。

**输入结构**：
- 网格约 15x20，背景黑(0)。
- 网格中部有一条全宽灰(5)水平条纹（1 像素高），将网格分为上半区和下半区。
- 上半区有 2~3 个 4-连通单色前景对象（每个 3~7 像素），颜色各不相同（如蓝(1)、红(2)、绿(3)），彼此不相邻。
- 下半区同样有 2~3 个 4-连通单色前景对象（每个 3~7 像素），颜色与上半区不重复（如黄(4)、橙(7)、青(8)）。
- 生成约束：所有对象的像素面积两两不同；经位移后至少一对上下对象的像素存在重叠。

**规则**：
1. 擦除灰(5)分隔条，将其变为黑(0)。
2. 每个原来在分隔条上方的对象，保持形状不变，整体向下平移 n 行，n = 该对象的像素面积。
3. 每个原来在分隔条下方的对象，保持形状不变，整体向上平移 m 行，m = 该对象的像素面积。
4. 平移后超出网格边界的部分裁剪丢弃。
5. 若两个对象平移后某些像素位置重叠，重叠单元格取面积较小的那个对象的颜色（小对象在碰撞中优先）。
6. 无重叠的像素保持平移后的颜色。

**关键洞察**：面积在本题中承担双重角色——既是位移距离的唯一参数，又是碰撞优先级的判定依据。仅看单个示例可能将位移理解为固定常数或行数差，需要多个示例对比不同面积的对象才能归纳出"位移 = 面积"，而碰撞优先级必须在至少一对重叠对象上才能验证。

## 新题 3：分隔压缩网格中的距离奇偶反转

**组合逻辑**：[坐标压缩/coordinate_compression](已有) + [反转/invert](创新：按块距离奇偶条件触发，而非逐行全量反转) + [块距离/block_distance](创新：不用于沙漏谓词，而用于奇偶分类)

**来源原语**：坐标压缩、分隔线(separator_line)、定位标记(anchor_marker)、块距离(block_distance) 来自 7d419a02；反转(invert)、逐行独立(row_independent) 来自 2de01db2

**依赖链**：坐标压缩识别块结构 → 定位标记确定距离原点 → 曼哈顿块距离计算 → 奇偶性决定是否反转该块内容。压缩、锚点、距离、反转四环节任缺一个均无法求解。

移除分隔线后按块坐标计算每块到锚点块的曼哈顿距离，距离为奇数的块做前景/背景反转，偶数块保持不变。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 若干条完整的黑(0)分隔行和分隔列将网格划分为不规则大小的矩形块（分隔线间距不等，约 2~5 像素）。
- 每个块内部包含一种非黑前景色的简单图案（如几个像素组成的小形状），各块前景色可不同。
- 恰好一个块内部包含一个 2x2 品红(6)定位标记，该标记所在块为锚点块。品红(6)不在其他任何块中出现。
- 生成约束：至少存在距离为奇数和距离为偶数的非锚点块各 2 个以上。

**规则**：
1. 识别所有完整的黑(0)分隔行和分隔列（跨越网格全宽或全高的纯黑行/列）。
2. 移除分隔行和分隔列后，得到一个逻辑块网格，每个块占据一个逻辑行列坐标 (br, bc)。
3. 找到包含品红(6) 2x2 标记的锚点块，记其逻辑坐标为 (ar, ac)。
4. 对每个块（包括锚点块），计算曼哈顿块距离 d = |br - ar| + |bc - ac|。
5. d 为偶数（包括 d=0 的锚点块本身）：保持块内所有像素不变。
6. d 为奇数：块内每个像素做前景/背景反转——黑(0)像素变为该块的前景色，该块前景色像素变为黑(0)。块的前景色定义为该块内出现次数最多的非黑非品红颜色。
7. 分隔行和分隔列在输出中保持黑(0)不变。锚点块内的品红(6)标记保持不变。

**关键洞察**：分隔线间距不等导致块的视觉大小不同，容易误以为反转条件与块面积或位置有关。只有压缩到逻辑块坐标后计算到锚点的曼哈顿距离，再判断奇偶性，才能统一解释所有块的变换。需要多个示例验证距离而非位置决定反转。

## 新题 4：标记列传播与计数三角楔形裁剪

**组合逻辑**：[传播/propagate + 逐列填充/column_fill](已有) + [计数/counting](创新：散落控制点的数量决定楔形几何尺寸) + [擦除/erase](创新：三角楔形边界裁剪传播结果)

**来源原语**：传播、逐列填充、底行标记选定列(bottom_marker_selects_column)、纵向色带(vertical_color_band) 来自 17b80ad2；计数、角落控制点(corner_control)、三角区域(triangle_region)、计数决定尺寸(count_determines_size) 来自 902510d5

**依赖链**：底行标记选定列 → 列传播生成纵向色带（中间结果 A）；散落控制点计数 → 确定三角边长（中间结果 B）；A 和 B 独立计算后联合应用：楔形裁剪色带。两条支线并行且最终汇合。

在标记列中向上传播颜色形成纵向色带，同时计算散落控制点的数量作为三角楔形的边长，最终只保留楔形区域内的色带像素。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 底行包含 2~4 个非黑标记像素（颜色各异，如蓝(1)、绿(3)），标记对应的列。
- 在每个标记列中，底行标记之上散布 1~3 个非黑像素（颜色可与底行标记不同），这些像素是色带的端点。
- 网格四角中恰好一个角落有一个非黑像素（栗(9)），指示楔形的顶点角。该颜色不在任何标记列中出现。
- 在网格其余区域（非标记列、非角落）散落 3~8 个同色单像素控制点，颜色为灰(5)。灰(5)不在标记列或角落中出现。
- 生成约束：控制点数量不超过网格边长；楔形区域与至少两个标记列有交集。

**规则**：
1. 识别底行的标记像素，确定标记列。
2. 在每个标记列中，从底行向上扫描，记住最近遇到的非黑颜色。将该列中每个黑(0)像素替换为记住的颜色，形成纵向色带。遇到新的非黑色时更新记忆。非标记列不做任何传播。
3. 计算所有灰(5)控制点的数量 S。
4. 找到栗(9)角落像素所在的角（左上、右上、左下、右下之一），以该角为顶点定义一个直角三角形区域：三角形的两条直角边分别沿该角所在的行边缘和列边缘延伸，直角边长度均为 S。
5. 三角形内部定义为：像素到该角所在行边缘的距离 dr 和到该角所在列边缘的距离 dc 满足 dr + dc < S 的所有单元格。
6. 输出网格中，仅保留三角形区域内的传播结果（色带像素）；三角形区域内的非标记列像素保持黑(0)。
7. 三角形区域外的所有像素设为黑(0)（包括原本的色带、标记、控制点等）。
8. 栗(9)角落像素和灰(5)控制点在输出中均擦除为黑(0)。

**关键洞察**：传播和计数是两个完全独立的分析——传播只关心标记列内部的颜色序列，计数只关心散落的灰点。两者的输出在空间裁剪这一步才汇合。单个示例中可能恰好所有色带都在三角形内，使裁剪不可见，必须对比多个示例才能发现三角形边界的存在及其与控制点数量的关系。

## 新题 5：交替偏移后的隐性对齐连线

**组合逻辑**：[滑动/shift + 逐行交替方向](创新：偏移改变标记像素的行列对齐关系) + [连线/connect + 首尾跨度填充](创新：对偏移后的坐标做跨度填充，而非原始坐标)

**来源原语**：滑动/shift、前景格子体(foreground_lattice)、底行锚定(bottom_row_anchored)、逐行交替方向(alternating_direction_per_row) 来自 1c56ad9f；连线(connect)、标记像素(marker_pixel)、同行列对齐(row_col_aligned)、首尾跨度填充(span_fill_between) 来自 ded97339

**依赖链**：交替偏移改变每行的水平位置 → 原本不对齐的标记像素偏移后落入同一列 → 此时触发跨度填充。偏移规则和连线规则互为前提：不知道偏移就无法判断哪些标记对齐，不知道连线规则就看不出偏移的意义。

对前景格子体做底行锚定的逐行交替偏移后，在新坐标下对标记像素执行同行同列跨度填充连线。

**输入结构**：
- 网格约 12x12，背景黑(0)。
- 一个蓝(1)的 4-连通前景格子体占据网格中部偏大的区域（约占网格面积 40%~60%），每行至少包含一个前景像素。
- 在格子体内部的 3~5 个位置，蓝(1)像素被替换为红(2)标记像素。这些标记像素仍属于格子体的几何位置，但颜色不同。
- 生成约束：在输入的原始坐标下，没有任何两个红(2)标记共享同一行或同一列（即原始状态下无法连线）。经过交替偏移后，至少两对标记像素共享同一列或同一行。

**规则**：
1. 确定格子体（蓝(1)加红(2)像素的并集）的边界框，以边界框的底行为锚定行。
2. 锚定行不偏移。从锚定行向上计数，记与锚定行的行距为 k（k=1 为上方第一行，k=2 为第二行......）：
   - k 为偶数：该行不偏移。
   - k 为奇数：若 k = 1, 5, 9, ...（即 k mod 4 = 1），该行向左偏移 1 像素；若 k = 3, 7, 11, ...（即 k mod 4 = 3），该行向右偏移 1 像素。
3. 每行的所有像素（蓝和红）整体随偏移移动。超出网格边界的像素裁剪丢弃。
4. 在偏移后的坐标中，对红(2)标记像素执行跨度连线：
   - 每一行中若有 2 个或以上红(2)像素，将该行中最左和最右红(2)像素之间的所有像素（含端点）涂为红(2)。
   - 每一列中若有 2 个或以上红(2)像素，将该列中最上和最下红(2)像素之间的所有像素（含端点）涂为红(2)。
5. 红(2)连线覆盖其路径上的蓝(1)像素和黑(0)像素。

**关键洞察**：输入中红标记刻意不对齐——在原始坐标下无法连线。只有先发现交替偏移规则（锚定底行、k mod 4 决定方向），标记才会"意外"落入同行或同列，连线才成为可能。偏移规则本身需要通过格子体边缘的锯齿变化来归纳，而连线规则需要通过红色跨度来验证——二者必须同时正确才能复现输出。

## 新题 6：障碍折线路由驱动的列选择性反转

**组合逻辑**：[射线延伸/ray_extend + 障碍决定转向](创新：路由不绘制彩色路径，而是生成列激活掩码) + [反转/invert + 逐行独立](创新：反转仅作用于路由激活的列，而非整行)

**来源原语**：射线延伸(ray_extend)、边缘标记(edge_marker)、障碍像素(obstacle_pixel)、障碍决定转向(obstacle_turn) 来自 891232d6；反转(invert)、逐行独立(row_independent)、主色与背景互换(native_bg_swap) 来自 2de01db2

**依赖链**：路由生成列激活掩码（空间分析） → 逐行独立的主色检测（颜色分析） → 掩码与主色联合决定每个像素的输出颜色。路由分析和颜色分析完全独立，在最终着色时才汇合。

从底边标记向上射线延伸，遇障碍右移一列后继续上行，路径经过的(行,列)形成激活集合；每行中仅激活列的像素执行主色/背景反转。

**输入结构**：
- 网格约 14x14，背景黑(0)。
- 每行包含若干非黑像素，每行有一种"主色"——该行中出现次数最多的非黑颜色。不同行的主色可以不同（如某行主色蓝(1)、另一行主色绿(3)等）。行内可能有少量其他非黑色的"干扰像素"。
- 底边（最后一行）有 1~2 个红(2)标记像素，它们同时也属于该行内容的一部分。
- 网格中散布 2~5 个橙(7)像素作为障碍。障碍不在底行。
- 生成约束：每条路由从底边标记出发向上至少经过一个障碍；路由右移后不会碰到同一行的第二个障碍；路由不会超出网格右边界。

**规则**：
1. 从每个底边红(2)标记像素出发，沿当前列逐行向上前进，构建一条路径：
   - 检查当前列中上一行的像素：若不是橙(7)障碍，则前进到上一行同列，将该 (行, 列) 加入激活集合。
   - 若上一行同列是橙(7)障碍：不进入障碍单元格，将当前列号 +1（右移一列），然后从障碍所在行开始继续向上前进，将 (障碍所在行, 新列) 加入激活集合。
   - 到达第 0 行时停止（第 0 行对应的列也加入激活集合）。
2. 合并所有路由的激活集合。
3. 对每行独立确定主色：该行中出现次数最多的非黑颜色；若出现次数并列，取在该行中最先（最左）出现的颜色。
4. 对每行的每个像素：
   - 该像素所在列在激活集合中：执行反转——主色像素变为黑(0)，非主色像素（包括黑(0)和干扰色）变为该行主色。
   - 该像素所在列不在激活集合中：保持不变。
5. 橙(7)障碍像素在输出中始终保持橙(7)，不参与反转。

**关键洞察**：路由是一条折线，每遇到障碍就右移一列——但路由本身在输出中不可见，它只充当"哪些列参与反转"的隐性控制。求解者必须同时推断路由规则（向上走、遇障碍右移）和反转规则（主色与背景互换），并理解二者通过列激活关系耦合。单看反转效果无法解释为何某些列被反转而另一些没有，必须发现路由的存在。

## 新题 7：稀疏精灵稠密化后按位序印入放大布局

**组合逻辑**：[稠密化/densify](已有) + [印章覆盖/stamp + 像素放大/pixel_upscale](创新：不再印同一图案，而是将不同稠密化精灵按位置顺序分配到不同灰像素对应的块槽位) + [位置顺序/position_order](创新：跨操作传递——精灵的空间顺序决定其在印章布局中的槽位分配)

**来源原语**：稠密化(densify)、稀疏精灵体(sparse_sprite)、位置顺序(position_order) 来自 db615bd4；印章覆盖(stamp)、像素放大(pixel_upscale)、控制像素(control_pixel)、源图案(source_pattern)、像素到块映射(pixel_block_mapping)、控制色选中则印章(stamp_where_control) 来自 ad7e01d0

**依赖链**：稠密化将稀疏精灵变为实体形状 → 源图案定义块布局和灰像素位置 → 精灵按空间位置排序 → 排序后的精灵依次放入灰像素对应的块槽位。稠密化改变精灵形态，位置排序改变分配对象，源图案的灰像素改变目标位置——三者交织。

**输入结构**：
- 网格约 12x12，背景黑(0)。
- 网格一角有一个小矩形源图案（尺寸 R 行 x C 列，如 3x3 或 3x4），由灰(5)像素和其他像素组成。灰(5)像素 2~4 个，其余位置为某种单一前景色（如蓝(1)）或黑(0)。
- 网格其余区域散布 N 个稀疏精灵体（N 等于灰(5)像素数量），每个精灵由单一颜色的像素组成（各精灵颜色不同，如红(2)、绿(3)、黄(4)），像素间隔 2 步（相邻精灵像素之间隔一个黑像素，构成棋盘式稀疏分布）。每个精灵稠密化后的边界框尺寸不超过 R x C。
- 各精灵之间互不接触，与源图案也不接触。

**规则**：
1. 识别源图案：包含灰(5)像素的最小矩形区域，记其尺寸为 R 行 x C 列。
2. 稠密化每个稀疏精灵：在精灵的边界框内，将 2 步间隔的空位（每隔一个的黑像素）填充为精灵颜色，得到密实版本。
3. 将所有稠密化精灵按其在输入中边界框左上角的位置排序：先按行坐标升序，行相同则按列坐标升序。得到有序序列 S1, S2, ..., SN。
4. 构建输出网格，尺寸为 (R x R) 行 x (C x C) 列。输出划分为 R 行 C 列的块网格，每块尺寸 R x C。源图案的像素 (r, c) 对应输出中第 r 块行、第 c 块列的块。
5. 按行优先顺序扫描源图案中的灰(5)像素，依次取有序序列中的下一个稠密化精灵，将其绘制到对应块的左上角（精灵不足块大小的部分以黑(0)填充）。
6. 源图案中非灰像素对应的块全部填充为黑(0)。

**关键洞察**：与参考题 ad7e01d0 中"灰像素处印同一图案"不同，本题在每个灰位置印入不同的稠密化精灵。精灵到槽位的分配由两个独立排序决定：精灵按空间位置排序，灰像素也按行优先顺序排列，二者一一对应。如果不先稠密化精灵、不确定位置排序，就无法知道哪个精灵放在哪个块中。

## 新题 8：控制点计数三角与顶行色序循环填充

**组合逻辑**：[计数/counting + 三角区域](创新：计数决定三角形状的边界，而非填充色) + [平铺/tiling + 顶行色序](创新：循环色序填充三角内部，而非矩形区域)

**来源原语**：计数、角落控制点(corner_control)、三角区域(triangle_region)、计数决定尺寸(count_determines_size)、最大分量保留(largest_component_kept) 来自 902510d5；填充(fill)、平铺(tile)、顶行色序(top_row_color_sequence)、分隔行(separator_row)、分隔下循环填色(below_separator_cycle_fill) 来自 bd4472b8

**依赖链**：顶行色序提供填充模板（数据源 A）→ 控制点计数决定三角边长（数据源 B）→ 角落像素决定三角方位 → 三角边界裁剪循环填充结果。A 和 B 独立提取，在几何填充时汇合。

计算散落控制点数量作为三角形边长，以角落像素定位三角形，用顶行色序循环填满三角形内部。

**输入结构**：
- 网格约 12x12，背景黑(0)。
- 顶行（第 0 行）包含 2~4 种非黑颜色的像素序列（如蓝(1)、红(2)、绿(3)交替），形成一个色序模板。顶行中无黑(0)像素。
- 第 1 行为全灰(5)分隔行。
- 第 2 行及以下为工作区域，背景黑(0)。
- 工作区域中，恰好一个网格角落（左下、右下之一，因顶行被色序和分隔行占据，仅考虑下方两角）有一个栗(9)像素，指示三角形顶点所在角。
- 工作区域中散落 3~10 个同色单像素控制点，颜色为橙(7)。橙(7)不出现在顶行或分隔行。
- 生成约束：控制点数量不超过工作区域的行数和列数中的较小值。

**规则**：
1. 提取顶行的色序模板 P = [c0, c1, c2, ...]，长度为 L。
2. 计算工作区域中橙(7)控制点的数量 S。
3. 找到栗(9)角落像素所在的角，以该角为直角顶点定义一个边长为 S 的直角等腰三角形。三角形的两条直角边沿网格边缘延伸。三角形内部定义为：像素到角落所在行边缘的距离 dr 和到角落所在列边缘的距离 dc 满足 dr + dc < S 的所有工作区域单元格。
4. 对三角形内部的每个单元格 (r, c)，按行优先顺序编号 i（从 0 开始，i 按照先行后列递增），将其颜色设为 P[i mod L]——即用顶行色序循环填充。
5. 三角形外部的工作区域保持黑(0)。
6. 栗(9)角落像素和橙(7)控制点在输出中均擦除为黑(0)。
7. 顶行色序和灰(5)分隔行在输出中保持不变。

**关键洞察**：三角形的边界和填充内容来自两个完全无关的信息源——边长来自控制点计数，填充色序来自顶行模板。单独看三角形看不出色序从何而来，单独看顶行看不出它被用于填充什么形状。必须跨区域关联才能完整理解规则。

## 新题 9：旋转匹配拼块放置与对角邻接扩展

**组合逻辑**：[形状匹配/shape_match + 旋转/rotate + 翻转/flip](已有) + [重涂色/recolor + 仅对角邻接](创新：匹配放置后的拼块触发对角邻接扩展，产生"光晕"效果)

**来源原语**：形状匹配(shape_match)、旋转(rotate)、翻转(flip)、缩放对应(scale_correspondence)、八方向匹配(all_orientations_matching)、框架(frame)、孔洞槽位(hole_slot)、拼块(piece) 来自 898e7135；重涂色(recolor)、仅对角邻接(diagonal_only_adj)、对角邻接背景着色(diagonal_bg_color)、封闭框(enclosing_frame)、内层前景(inner_foreground) 来自 396d80d7

**依赖链**：孔洞形状提取 → 拼块缩放匹配（含旋转/翻转） → 放置拼块到对应孔洞 → 放置后触发对角邻接扩展 → 扩展区域可能冲突，需面积仲裁。匹配决定了放置位置和朝向，放置决定了哪些像素存在，存在的像素决定了对角扩展的范围——逐层因果。

将外部拼块通过旋转/翻转匹配到框架孔洞后放入，再对每个拼块的框架色边界做对角邻接扩展，扩展色为该拼块的内层色。

**输入结构**：
- 网格约 18x18，背景黑(0)。
- 网格中心有一个绿(3)的单色矩形框架，框架宽度 1 像素，框架内部为黑(0)背景，包含 2~3 个不相邻的连通孔洞区域（形状各异，非矩形，面积 3~8 像素）。
- 框架外部有 2~3 个拼块，每个拼块由 k x k 的小方块（k=2 或 k=3）组成，拼块整体形状在缩小 k 倍后与某个孔洞在某个旋转/翻转下形状一致。每个拼块有两种颜色：外边界像素为绿(3)（与框架同色），内部像素为另一种颜色（每个拼块的内部色不同，如蓝(1)、红(2)、黄(4)）。
- 生成约束：每个孔洞恰好匹配一个拼块（一一对应）；不同孔洞的形状在所有 8 个方向变换下两两不同。

**规则**：
1. 提取框架内的连通孔洞区域，记录每个孔洞的形状（像素相对坐标集合）。
2. 对每个外部拼块，按 k 倍缩小得到单像素级形状，在 8 个方向（4 旋转 x 2 翻转）下与各孔洞比较，找到唯一匹配的孔洞和对应的变换方向。
3. 将拼块按匹配的变换方向旋转/翻转后，放入对应孔洞位置。放置时拼块按 k 倍缩放填入孔洞：孔洞的每个像素位置对应拼块的一个 k x k 块。
4. 放置完成后，对整个框架内部区域执行对角邻接扩展：对每个仍为黑(0)的背景像素，检查其四个对角邻居——若它与某个拼块的绿(3)边界像素仅有对角邻接（四个正交邻居中无绿(3)像素），则将该背景像素涂为与之对角相邻的那个拼块的内部色。
5. 若某个背景像素同时对角邻接两个不同拼块的绿(3)边界，取面积较小的拼块的内部色（面积 = 拼块缩小后的像素数）。
6. 框架像素保持绿(3)不变。框架外部保持黑(0)。

**关键洞察**：形状匹配决定拼块的朝向和位置，但最终输出还取决于放置后产生的对角邻接效果——这是匹配和放置操作的涌现结果。对角扩展的范围由拼块的绿色边界形状决定，而边界形状又取决于匹配时选择的旋转/翻转方向。冲突解决规则（小面积优先）需要在多个拼块的扩展区域重叠时才能观察到。

## 新题 10：稀疏框架加厚与精灵阻断列传播

**组合逻辑**：[加厚/thicken + 稀疏边框](已有) + [填入/insert + 等距排列入框](已有) + [传播/propagate + 逐列填充](创新：插入的精灵体成为列传播的障碍物，精灵的双重角色——内容和屏障——是源题中不存在的结构关系)

**来源原语**：加厚(thicken)、稀疏边框(sparse_frame)、稀疏精灵体(sparse_sprite)、填入(insert)、等距排列入框(equidist_in_frame)、位置顺序(position_order) 来自 db615bd4；传播(propagate)、逐列填充(column_fill)、底行标记选定列(bottom_marker_selects_column)、纵向色带(vertical_color_band) 来自 17b80ad2

**依赖链**：加厚框架确定填充边界 → 精灵稠密化并等距放入框架 → 精灵的放置位置改变了列传播的障碍分布 → 传播在精灵处中断。精灵的最终位置取决于框架尺寸和精灵数量，传播结果取决于精灵位置——形成间接依赖。

将稀疏框架加厚为实心边框、稀疏精灵稠密化后等距填入框内，再在标记列中向上传播颜色，精灵体阻断传播。

**输入结构**：
- 网格约 16x16，背景黑(0)。
- 一个稀疏矩形边框：边框像素颜色为绿(3)，分布在 2 步间隔的格子上（即边框像素之间隔一个黑像素），围成一个矩形轮廓。边框宽度方向为 1 像素（在稀疏尺度上），实际占据约 2 像素宽。
- 边框外部有 2~3 个稀疏精灵体，每个由单一颜色（如蓝(1)、红(2)、黄(4)）的像素在 2 步间隔格子上组成。
- 边框内部（稀疏框架围成的区域）的底行附近有 2~3 个橙(7)标记像素，占据不同列。在这些标记列的上方散布 1~2 个其他非黑色像素（如青(8)、品红(6)）作为色带端点。
- 生成约束：框架宽度大于高度（横向框架），精灵按左到右位置顺序排入；至少一个标记列与某个放入的精灵的列范围重叠。

**规则**：
1. 将稀疏矩形边框加厚为实心 1 像素宽的矩形边框：找到稀疏边框像素的外边界框，在外边界框的四条边上画实心绿(3)线（填补稀疏间隙）。原稀疏边框像素以外的同行同列间隙也填为绿(3)。
2. 稠密化每个外部稀疏精灵（填补 2 步间隔的空位）。
3. 清除原稀疏边框和精灵占据的像素为黑(0)，然后绘制加厚后的实心边框。
4. 将稠密化精灵按在输入中的位置顺序（边界框左上角按列坐标升序）排列，等间距放入框架内部：框架内部宽度均分为 (N+1) 个间隔（N 为精灵数），第 i 个精灵的左边缘放置在第 i 个间隔的起点位置，精灵顶边与框架内部顶边对齐。
5. 在加厚框架的内部区域中，对每个橙(7)标记像素所在的列执行向上传播：从标记像素位置向上逐行扫描，记住最近的非黑颜色，将黑(0)像素替换为记住的颜色。遇到新的非黑色（包括色带端点的颜色）时更新记忆。
6. 传播在以下情况停止或跳过：遇到已放入的精灵体像素时，传播在精灵底边缘的前一行停止（精灵像素不被覆盖）；遇到框架边框像素时，传播在边框前一行停止。
7. 橙(7)标记像素在输出中保持橙(7)。

**关键洞察**：精灵在本题中具有双重角色——它们既是插入框架内的可见内容物，又是列传播的不可见屏障。精灵的等距放置位置由框架宽度和精灵数量决定，而传播路径能走多远取决于精灵恰好占据了哪些列。不同示例中精灵数量不同导致放置位置不同，从而改变传播结果的形态——这种间接耦合需要跨示例对比才能归纳。
