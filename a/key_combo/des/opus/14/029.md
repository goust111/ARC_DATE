## 新题 1：异常瓷砖编码的行级擦除掩模

**组合逻辑**：[逐行比较 + 异常值选择](已有) → [差异提取](创新：异常值不被提取输出，而是与多数派逐像素比较得到差异位置集) → [擦除 + 相对自身定位](创新：差异位置集作为局部坐标掩模，应用于该行所有瓷砖)

**来源原语**：逐行比较/row_wise_comparison（38007db0）、异常值选择/outlier_selection（38007db0）、擦除/erase（52364a65）、相对自身定位/self_relative_pos（52364a65）、瓷砖网格排列/tile_grid_layout（1c0d0a4b）、按对象局部裁切/local_bbox_crop（52364a65）

**依赖链**：异常瓷砖的识别依赖逐行比较 → 异常瓷砖与多数派的像素级差异产生擦除掩模 → 掩模以局部坐标形式应用于整行所有瓷砖（包括异常瓷砖自身）。删除比较步骤则无法获得掩模；删除擦除步骤则比较结果无处施加。异常瓷砖既是被分析对象又是被擦除对象，双重身份不可分离。

在由分隔线划分的瓷砖网格中，每行瓷砖中的异常者不被提取，而是作为"指令源"——它与多数派的像素差异位置定义了一组局部坐标擦除掩模，该掩模被施加于该行的每一个瓷砖。

**输入结构**：约 15x19 的网格，灰(5)分隔线将网格划分为 3 行 4 列共 12 个 3x3 瓷砖区域。背景为黑(0)。每个瓷砖内部用蓝(1)前景像素绘制一个 4-连通的小图形（3~6 像素，形状因瓷砖而异）。在每一行的 4 个瓷砖中，有 3 个瓷砖的内部图形完全相同（多数派），1 个瓷砖的内部图形与多数派在 1~3 个像素位置上不同（异常瓷砖）。生成约束：异常瓷砖的图形与多数派图形的差异仅在于若干像素位置的前景/背景状态互换（即异常瓷砖可能在某些位置多了前景像素，或少了前景像素，或两者兼有）。

**规则**：
1. 对每一行瓷砖，找出多数派图形（出现 3 次的内部图案）和异常瓷砖（出现 1 次的内部图案）。
2. 逐像素比较异常瓷砖与多数派：记录所有值不同的局部坐标位置（行内偏移、列内偏移），形成该行的"擦除掩模"。
3. 对该行的每一个瓷砖（包括异常瓷砖），将擦除掩模对应的局部坐标位置上的像素设为背景色黑(0)，无论该位置原来是前景还是背景。
4. 不在掩模中的位置保持不变。分隔线保持不变。
5. 各行独立处理，不同行的掩模互不影响。

**关键洞察**：异常瓷砖不是答案本身，而是"指令"——它与多数派的差异编码了一组擦除坐标，这组坐标被广播到整行的所有瓷砖上。求解者必须先识别异常、再提取差异、最后全行施加，三步紧耦合。

## 新题 2：面板空集交集派生印章模板

**组合逻辑**：[逻辑运算 + 逐格比较](已有) → [交集结果作为模板](创新：逻辑运算的输出不直接作为答案，而是成为印章覆盖的模板精灵体) → [印章覆盖 + 分块对应 + 源色决定涂色](已有，但模板来源全新)

**来源原语**：逻辑运算/logical_operation（f2829549）、逐格比较/cell_comparison（f2829549）、双空交集涂色/intersect_empty_fill（f2829549）、印章覆盖/stamp（b190f7f5）、分块对应/block_correspondence（b190f7f5）、源色决定模板涂色/source_color_determines_template_recolor（b190f7f5）、分隔列/separator_column（f2829549）、模板面板/template_panel（b190f7f5）

**依赖链**：两个面板的逐格逻辑比较产生交集图案 → 交集图案定义印章模板的形状 → 源网格中的有色像素指定印章位置和颜色 → 模板被重涂色后印章到对应输出块。删除逻辑运算则无模板可用；删除印章覆盖则交集图案无处展开。

两个等宽面板的背景空集交集产生一个精灵体形状，该形状作为模板被按源网格中各有色像素的位置和颜色进行印章覆盖式展开。

**输入结构**：约 11x15 的网格，由三个区域组成。左侧和中间各为一个 5x5 面板，之间由一列红(2)分隔列隔开。右侧紧邻分隔列后为一个 5x5 源网格。左面板和中面板背景均为黑(0)，各自用一种前景色（左面板为蓝(1)，中面板为绿(3)）绘制一个 4-连通图形（4~8 像素）。两面板的前景图形有部分重叠区域、部分各自独有区域。源网格背景为黑(0)，其中散布 2~4 个不同颜色的前景像素（可用黄(4)、品红(6)、橙(7)等），每个像素占 1 格，互不相邻。生成约束：两面板的背景空集交集（两面板对应位置均为背景的像素集合）形成一个 4-连通的非空图形，至少 3 像素。

**规则**：
1. 将左面板和中面板逐格比较：记录两面板对应位置均为背景色黑(0)的所有坐标，形成"交集掩模"——这些位置定义了印章模板的形状。
2. 以源网格为定位参照。输出为 (5K)x(5K) 的网格（K 为源网格的边长 5），初始化为黑(0)。
3. 对源网格中每个非背景像素位于 (r, c) 处：取交集掩模作为精灵体形状，将掩模中所有标记位置重涂为该像素的颜色，然后将此重涂色精灵体印章到输出中以 (r, c) 为块坐标的 5x5 区域。
4. 未被任何印章覆盖的输出位置保持黑(0)。

**关键洞察**：模板不是现成给出的，而是由两个面板的"共同空白"推导而来——求解者必须先做逻辑比较得到模板形状，再用它进行印章展开。模板的派生和使用是两个不可分离的推理步骤。

## 新题 3：射线切割精灵体后按面积-频率映射重涂色

**组合逻辑**：[切割 + 射线分割区域](已有) → [连通分量检测 + 计数](已有，但作用对象从散布像素变为切割碎片) → [重涂色](创新：碎片按面积排名映射到输入中散布标记像素的按频率排名的颜色)

**来源原语**：切割/cutting（4a21e3da）、射线分割区域/ray_partition（4a21e3da）、控制像素/control_pixel（4a21e3da）、连通分量检测/connected_component_detection（12eac192）、计数/count（878187ab）、重涂色/recolor（12eac192）、频率比较/frequency_compare（a6953f00）、标记像素/marker_pixel（878187ab）

**依赖链**：控制像素射线切割精灵体 → 切割产生碎片，各碎片面积不同 → 碎片面积排名与输入中散布标记像素的颜色频率排名建立一一映射 → 每个碎片被重涂为对应排名的标记颜色。删除切割则无碎片；删除频率分析则无颜色映射；删除重涂色则碎片颜色不变。

精灵体被边缘控制像素的射线切割为碎片，碎片按面积从大到小排列，散布在网格其他位置的标记像素按颜色出现频率从高到低排列，两个排列一一对应确定碎片的输出颜色。

**输入结构**：约 14x14 的网格，背景黑(0)。网格中央偏左有一个灰(5)前景精灵体（8~15 像素的 4-连通不规则形状，非凸，使得切割后产生面积不等的碎片）。网格边缘（第 0 行、第 0 列、最后一行、最后一列上）有 2 个红(2)控制像素，分别位于不同边缘。网格中远离精灵体的区域散布着若干单像素标记，使用 3 种颜色（如蓝(1)、绿(3)、黄(4)），每种颜色出现的像素个数互不相同（如蓝 4 个、绿 2 个、黄 1 个）。生成约束：两条控制射线恰好将精灵体切割为 3 个 4-连通碎片，且三个碎片的面积互不相同；标记颜色的种类数等于碎片数（均为 3）。

**规则**：
1. 从每个红(2)控制像素出发，沿其所在行（若控制像素在左/右边缘）或所在列（若控制像素在上/下边缘）向网格内部画射线。射线经过的所有背景色黑(0)像素被标记为切割线（涂红(2)）。射线在到达精灵体最远端像素的同列/同行后停止；射线遇到精灵体前景像素时跳过（不切断精灵体像素本身，但切割线在精灵体两侧的背景上均留下痕迹）。
2. 切割线将精灵体分割为若干 4-连通碎片（精灵体像素中，被切割线所在行或列穿过的像素归属于射线靠近控制像素一侧的碎片；若一个精灵体像素同时被两条切割线穿过，归属于两条射线的控制像素公共角落方向的碎片）。
3. 计算每个碎片的面积（像素数），按面积从大到小排列，记为碎片序列 F1, F2, F3。
4. 统计输入中各标记颜色的出现频率（像素总数），按频率从高到低排列，记为颜色序列 C1, C2, C3。
5. 将 Fi 的所有像素重涂为 Ci（面积最大碎片涂频率最高的标记颜色，次之对应次之，以此类推）。
6. 切割线红(2)像素保留在输出中。所有标记像素从输出中擦除（设为背景）。其余背景不变。

**关键洞察**：碎片的颜色不由精灵体自身决定，而由网格中远处散布的标记像素的统计频率决定——面积排名与频率排名的隐式一一映射是需要对比多个示例才能归纳的非显然规则。

## 新题 4：内部连通分量计数决定边框平铺间距

**组合逻辑**：[连通分量检测 + 计数](已有) → [计数值作为平铺间距参数](创新：计数结果不映射为矩形尺寸，而是映射为边框环形平铺的间隔步长) → [平铺 + 环形周期](已有，但间距来源全新)

**来源原语**：连通分量检测/connected_component_detection（12eac192）、计数/count（878187ab）、平铺/tile（30f42897）、环形周期/cyclic_period（30f42897）、边框段/border_segment（30f42897）、矩形边界/rectangular_border（30f42897）、计数映射尺寸/count_maps_to_size（878187ab）、间隔等长重复/repeat_equal_gap（30f42897）

**依赖链**：内部连通分量计数 → 计数值 K 定义边框平铺间距 → 边框段按间距 K 在环形周期上重复放置。删除分量计数则间距未知；删除平铺则计数无用武之地。内部结构与边框图案通过一个整数参数紧密耦合。

网格内部的前景连通分量个数决定了边框彩色段在矩形周界上重复平铺时相邻副本之间的间隔步长。

**输入结构**：约 12x12 的网格，背景黑(0)。网格的矩形边界（第 0 行、最后一行、第 0 列、最后一列）上有一段连续的蓝(1)前景像素（长度 2~4 像素，位于某一条边上，不跨角），其余边界像素为黑(0)。网格内部（排除边界行列后的 10x10 区域）散布若干红(2)前景像素组成的 4-连通连通分量，分量个数为 2~5 个，每个分量 2~5 像素，分量之间互不 4-连通。生成约束：设蓝色段长度为 n，内部红色分量个数为 K，边界周长为 P = 2*(W-1) + 2*(H-1)。则 (n + K) 能整除 P，确保平铺能精确覆盖整个周界而无截断。

**规则**：
1. 统计网格内部（不含边界行列）的红(2)前景像素的 4-连通连通分量个数，记为 K。
2. 将矩形边界展开为顺时针环形路径（从左上角出发，沿上边→右边→下边→左边，总长度 P）。
3. 在环形路径上定位蓝(1)段的起始位置。从该起始位置开始，每隔 (n + K) 步放置一份蓝色段的副本（副本长度为 n，副本之间的空隙长度为 K）。放置沿顺时针方向循环，直到回到起始位置。
4. 内部红(2)分量保持不变。所有其他像素保持不变。

**关键洞察**：边框图案的周期不由段长本身决定（参考题中间距=段长），而由内部的连通分量计数决定——求解者必须分析内部结构才能推断边框平铺规律，这是跨区域的参数传递。

## 新题 5：跨尺度形状匹配触发条件性占用反转

**组合逻辑**：[形状匹配 + 跨尺度同形](已有) → [匹配结果作为布尔条件](创新：匹配不是为了选取输出对象，而是标记哪些瓷砖需要变换) → [反转填充](已有，但仅对匹配瓷砖执行)

**来源原语**：形状匹配/shape_matching（ce602527）、跨尺度同形/cross_scale_same_shape（ce602527）、反转填充/occupancy_inversion（1c0d0a4b）、重涂色/recolor（1c0d0a4b）、瓷砖/tile（1c0d0a4b）、分隔行列/separator_rows_and_columns（1c0d0a4b）、瓷砖网格排列/tile_grid_layout（1c0d0a4b）

**依赖链**：键瓷砖提供参考形状 → 各瓷砖的图案与键瓷砖在 1x 或 2x 尺度比较 → 匹配的瓷砖执行占用反转（前景变背景、背景变红(2)）→ 不匹配的瓷砖保持不变。删除形状匹配则不知道反转哪些瓷砖；删除反转则匹配结果无下游效果。

网格中的瓷砖若与独立键区域的图案在 1 倍或 2 倍尺度下形状相同，则该瓷砖执行占用反转；不匹配的瓷砖保持原样。

**输入结构**：约 13x17 的网格。灰(5)分隔线将主区域划分为 2 行 3 列共 6 个 4x4 瓷砖。每个瓷砖内部背景为黑(0)，用蓝(1)前景像素绘制一个 4-连通小图形（3~7 像素）。主区域右侧留出一个独立的 4x4 "键区域"，与主区域以双列灰(5)分隔，键区域内部用绿(3)前景像素绘制一个参考图形。生成约束：6 个瓷砖中，有 2~3 个瓷砖的蓝色图形与键区域的绿色图形在形状上匹配（忽略颜色，仅比较占用像素的相对位置集合）。匹配可以是 1 倍（像素位置集合相同）或 2 倍（瓷砖图形是键图形的 2 倍放大版，此时键图形较小，约 2~3 像素，瓷砖图形为对应的 2x2 块放大）。不同瓷砖中的非匹配图形形状各异。

**规则**：
1. 提取键区域的绿(3)图形，记录其前景像素的局部坐标集合 S_key。
2. 对主区域的每个瓷砖，提取其蓝(1)图形的局部坐标集合 S_tile。
3. 尺度 1 匹配：S_tile == S_key（忽略颜色）。尺度 2 匹配：将 S_key 中每个坐标 (r,c) 扩展为 {(2r,2c), (2r,2c+1), (2r+1,2c), (2r+1,2c+1)}，检查扩展后集合是否等于 S_tile。若任一尺度匹配，则标记该瓷砖。
4. 对每个标记瓷砖执行占用反转：瓷砖内部原为蓝(1)前景的位置设为黑(0)背景；原为黑(0)背景的位置设为红(2)。
5. 未标记的瓷砖保持原样。分隔线和键区域保持原样。

**关键洞察**：形状匹配不是为了选出"哪个对象是答案"，而是作为布尔谓词决定哪些瓷砖执行反转变换——匹配本身不产生输出，只决定变换的作用域。键图形可能需要 2 倍缩放才能与某些瓷砖匹配，这增加了匹配判断的难度。

## 新题 6：端点连线被控制射线阻断后死端擦除

**组合逻辑**：[连线 + 同行列对齐 + 同色同子格位置](已有) → [射线延伸作为阻断屏障](创新：控制像素射线不是用于切割对象，而是在瓷砖格子的连线路径上形成阻断墙) → [擦除](创新：被阻断后无法到达对端的连线段被回溯擦除)

**来源原语**：连线/connect（a096bf4d）、同行列对齐/same_row_col_align（a096bf4d）、同色同子格位置/same_color_subcell（a096bf4d）、端点标记/endpoint_marker（a096bf4d）、格子瓦片/lattice_tile（a096bf4d）、分隔线/separator_line（a096bf4d）、射线延伸/ray_extend（4a21e3da）、控制像素/control_pixel（4a21e3da）、擦除/erase（52364a65）

**依赖链**：端点按颜色和子格位置分组 → 同组端点在瓷砖行/列方向连线 → 控制像素从网格边缘射出阻断射线 → 射线穿过的瓷砖行/列上的连线在射线位置被截断 → 截断后仅保留从某端点出发能连通到另一端点的连线段，无法到达任何端点的孤立线段被擦除。删除连线逻辑则无线段；删除射线阻断则所有连线畅通；删除死端擦除则存在虚假线段。三步相互制约。

在瓷砖格子中，同色同子格位置的端点之间画连线，但网格边缘的控制像素射出的阻断射线会截断路径上的连线；被截断后孤立的（两端均不接触端点标记的）线段被擦除。

**输入结构**：约 17x17 的网格。橙(7)分隔线将网格划分为 4 行 4 列共 16 个 3x3 瓷砖。每个瓷砖内部背景为黑(0)，填充色为灰(5)。部分瓷砖内部有一个彩色端点标记像素（可用蓝(1)、红(2)、绿(3)），位于该瓷砖 2x2 内区的某个子格位置（左上、右上、左下、右下之一）。每种端点颜色恰好出现 2~3 次；同色端点的子格位置相同。网格边缘（第 0 行/列或最后行/列）上有 1~2 个黄(4)控制像素。生成约束：至少一条同色端点连线的瓷砖路径被某条控制射线穿过，产生至少一个需要擦除的死端线段。

**规则**：
1. 将端点标记按颜色和 2x2 内区子格位置分组。同组端点在瓷砖行（若共享瓷砖行）或瓷砖列（若共享瓷砖列）方向连线：对路径上每个中间瓷砖的相同子格位置，涂上该组的端点颜色。
2. 从每个黄(4)控制像素出发，沿其所在行（若位于左/右边缘）或所在列（若位于上/下边缘）向内画射线。射线覆盖的所有像素（包括分隔线位置和瓷砖内部位置）均标记为"阻断"。射线从边缘延伸到对侧边缘。
3. 对步骤 1 中画出的每条连线，检查连线路径上是否有像素被阻断射线穿过。若有，则在阻断位置处截断连线。
4. 截断后，检查每段残余线段：若该段的两端都不紧邻（4-连通）一个同色端点标记，则该段为"死端"，将其所有像素擦除（恢复为灰(5)填充色）。
5. 保留所有紧邻端点标记的线段。阻断射线本身不绘制到输出中（仅用于截断判断）。控制像素保留在输出中。

**关键洞察**：连线和阻断是两个独立的空间过程，它们的交叉点产生截断；但关键的第三步——死端擦除——才使整个逻辑不可分解：仅看连线规则或仅看阻断规则都无法预测最终哪些像素存在。

## 新题 7：对角带周期延展后按散布像素频率替换缺席颜色

**组合逻辑**：[射线延伸 + 周期重复 + 画布倍增](已有) → [频率比较](创新：不用于选取角落，而是将散布像素的颜色统计与带中颜色做交叉比对) → [重涂色](创新：带中"无支撑"的颜色被替换为最稀有的未使用散布色)

**来源原语**：射线延伸/ray_extend（cad67732）、周期重复/periodic_repeat（cad67732）、画布倍增/canvas_doubled（cad67732）、对角色带/diag_color_band（cad67732）、频率比较/frequency_compare（a6953f00）、重涂色/recolor（d406998b / 12eac192）、标记像素/marker_pixel（878187ab）

**依赖链**：对角带的周期和偏移被学习后延展到 2 倍画布 → 带中使用的颜色集合 B 与散布像素的颜色集合 M 做交集分析 → B 中不在 M 中的颜色（"无支撑色"）被替换为 M 中不在 B 中的颜色（"候补色"），按稀有度排名一一配对。删除延展则无完整带；删除频率分析则不知替换什么；删除替换则频率分析无效果。

对角周期色带延展到加倍画布后，带中那些在散布标记像素中找不到"支撑"的颜色被替换为散布像素中最稀有的、尚未出现在带中的颜色。

**输入结构**：约 8x8 的网格，背景黑(0)。一条斜向色带从左上向右下延伸（或从右上向左下），宽度 1~2 像素，由 2~3 种前景色组成，具有行周期性（如周期为 2：第 0 行红(2)、第 1 行蓝(1)、第 2 行红(2)...）。网格中远离色带的区域散布若干单像素标记，使用 2~4 种颜色，每种颜色的出现次数互不相同。生成约束：色带颜色集合与标记颜色集合不完全相同——至少有 1 种颜色仅出现在色带中（"无支撑色"），至少有 1 种颜色仅出现在标记中（"候补色"）。无支撑色数量等于候补色数量。

**规则**：
1. 识别对角色带的方向、占用的对角偏移集合、颜色的行周期（含带内的背景间隙），以及带的起始位置（作为 2 倍画布左上象限的裁切）。
2. 生成 2H x 2W 的背景画布，将色带的周期/偏移规则延展到整个画布（若原带为右上-左下方向，先水平翻转为左上-右下方向进行延展，完成后翻转回来），得到完整的延展带。
3. 计算色带颜色集合 B = {带中出现的所有非背景色}。计算标记颜色集合 M = {所有散布标记像素的颜色}。
4. 无支撑色集合 U = B - M（在带中但不在标记中的颜色）。候补色集合 R = M - B（在标记中但不在带中的颜色）。
5. 将 U 中的颜色按它们在色带中的出现频率从低到高排列（出现次数少的排前面）。将 R 中的颜色按它们在散布标记中的出现频率从低到高排列。
6. 按排名一一配对：U 中最稀有的颜色替换为 R 中最稀有的颜色，次稀有对应次稀有，以此类推。
7. 在延展后的 2H x 2W 画布上，将所有被替换颜色的像素涂为对应候补色。带中有支撑的颜色保持不变。散布标记像素不出现在输出中（输出仅为延展后的画布）。

**关键洞察**：散布标记像素不是装饰物——它们的颜色集合与色带颜色集合的差集关系定义了一个颜色替换映射。这个映射只有在延展色带之后才被施加，且替换的配对规则（按稀有度排名对齐）需要对比多个示例才能归纳。

## 新题 8：最近边决定移动方向后邻接触发条溅射

**组合逻辑**：[投射到最近边界 + 最近边界方向](创新：最近边不用于画射线，而是决定像素的移动方向——总是朝向远离最近边的方向移动) → [平移 + 固定步长移动](已有) → [邻接触发对角溅射](已有，但触发来源变为多方向移动后的邻接)

**来源原语**：投射到最近边界/projection_to_nearest_edge（705a3229）、最近边界方向/nearest_boundary_direction（705a3229）、平移/shift（73c3b0d8）、固定步长移动/fixed_step_move（73c3b0d8）、邻接触发对角溅射/adjacency_triggers_diagonal_splash（73c3b0d8）、触发条/trigger_bar（73c3b0d8）、移动像素/moving_pixel（73c3b0d8）、标记像素/marker_pixel（705a3229）

**依赖链**：每个移动像素的最近网格边决定其移动方向（朝远离最近边的方向） → 各像素独立移动一步 → 移动后若邻接触发条，则沿移动方向的反方向发射两条 45 度对角射线。删除最近边判断则移动方向未知；删除移动则无法产生邻接；删除溅射则邻接判断无后续效果。三个环节的信息不可跳步。

散布的移动像素各自朝远离其最近网格边的方向移动一步；若移动后紧邻横向触发条，则沿移动来向（即朝最近边方向）发射两条 45 度对角射线。

**输入结构**：约 13x13 的网格，背景黑(0)。网格中有一条完整的水平蓝(1)触发条（占据某一行的全部列）。触发条上方和下方各散布若干绿(3)移动像素（每个占 1 格，互不相邻，不与触发条 4-连通相邻）。生成约束：每个移动像素到四条网格边（上、下、左、右）的距离中存在唯一最小值（无平局）。部分移动像素在移动一步后恰好与触发条 4-连通相邻（即移动后位于触发条的上一行或下一行），部分移动后仍不相邻。

**规则**：
1. 对每个绿(3)移动像素，计算它到网格四条边的距离：到上边 = r，到下边 = (H-1-r)，到左边 = c，到右边 = (W-1-c)。找到距离最小的边（唯一）。
2. 确定移动方向：朝远离最近边的方向移动。即：最近边为上 → 向下移动；最近边为下 → 向上移动；最近边为左 → 向右移动；最近边为右 → 向左移动。
3. 将每个移动像素从原位置擦除，在移动方向上偏移 1 步的位置重新绘制绿(3)。
4. 检查每个移动后的绿(3)像素：若它与蓝(1)触发条 4-连通相邻（即上下左右相邻的某个像素属于触发条），则从该移动像素位置出发，沿移动来源方向（即指向最近边的方向）的两条 45 度对角线画绿(3)射线，直到射线离开网格。
5. 不与触发条相邻的移动像素仅停留在移动后的位置，不发射射线。
6. 触发条蓝(1)像素保持不变。射线覆盖触发条以外的所有路径上的像素。

**关键洞察**：与参考题（所有像素统一向下移动）不同，每个像素的移动方向由其独特的空间位置（最近边）决定，因此不同像素可能向不同方向移动。溅射的方向也因此不统一——射线沿移动的反方向发射，而非固定向上。求解者必须先推断出"最近边→反向移动"的规则，才能预测哪些像素会触发溅射及溅射方向。
