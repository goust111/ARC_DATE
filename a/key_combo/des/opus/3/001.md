## 新题 1：标记双信号滑动

**组合逻辑**：[计数 counting](创新：计数结果作为滑动距离参数) + [质心偏移定向 centroid_bias_dir](创新：作用于矩形内标记点而非方向精灵体) → [滑动 slide](创新：方向与距离均由标记决定，而非拓扑分类) + [碰撞停止 collision_stop](已有)

**来源原语**：计数 counting / 内部标记计数 interior_marker_count (54db823b)，质心偏移定向 centroid_bias_dir (13f06aa5)，滑动 slide / 碰撞停止 collision_stop (ac2e8ecf)

**依赖链**：标记像素的空间分布决定滑动方向，标记像素的数量决定滑动距离——同一组像素同时编码两个参数。碰撞检测的结果又反过来截断实际滑动距离，使得处理顺序影响最终布局。

将每个前景矩形内部的红色标记像素解读为双信号源：其数量决定滑动步数，其质心偏移方向决定滑动朝向，按面积从小到大依次滑动并在碰撞时停止。

**输入结构**：约 15x15 的网格，黑(0)背景。网格中散布 3~5 个单色 4-连通填充矩形（每个矩形使用不同的非黑非红颜色，如蓝(1)、绿(3)、黄(4)、橙(7)），矩形之间互不相邻，各矩形面积不同（3x2 至 5x4 不等）。每个矩形内部嵌有 1~3 个红(2)标记像素，取代该位置原来的矩形颜色。红像素在矩形内部的分布不居中——例如集中在左半区、或偏向上方。生成约束：各矩形面积互不相同；同一矩形内红像素的质心与矩形中心之间的偏移在四个基本方向（上/下/左/右）之一上最大，且该方向上矩形沿途有足够空间（至少 1 格）容纳滑动。

**规则**：
1. 对每个矩形，统计其内部红(2)像素的数量 D。
2. 计算该矩形内所有红像素的质心坐标 (cr, cc)，以及矩形包围盒的中心坐标 (mr, mc)。取向量 (cr - mr, cc - mc)，将其量化为四个基本方向中偏移绝对值最大的那个方向，即为该矩形的滑动方向。若行偏移与列偏移绝对值相等，优先取行方向（上或下）。
3. 按矩形面积从小到大排序，依次处理。
4. 清除当前矩形在原位置的所有像素（包括红标记），然后将整个矩形（含红标记）沿滑动方向平移 D 格。若平移过程中矩形的任何像素会与已放置的矩形或网格边界重叠，则停在最后一个合法位置（碰撞停止）。
5. 所有矩形放置完成后，将每个矩形内的红(2)标记像素重涂为该矩形自身的颜色（标记消失，矩形恢复为纯色）。

**关键洞察**：红色标记像素是一次性双信号源——其数量与空间分布分别编码了滑动的两个独立参数（距离和方向），且在最终输出中被擦除。仅看单个示例无法区分"标记质心偏左→向左滑"和"标记质心偏左→向右滑"，必须对比多个不同偏向的示例才能归纳方向规则。

## 新题 2：拓扑障碍射线

**组合逻辑**：[滑动 slide](已有：按拓扑分类滑动) + [射线延伸 ray_extend](创新：射线被滑动后的对象阻挡而提前终止) + [碰撞停止 collision_stop](创新：从对象碰撞扩展到射线碰撞) + [重涂色 recolor](创新：被射线命中的对象像素变为射线标记色)

**来源原语**：滑动 slide / 有孔者升无孔者降 hole_up_holeless_down / 碰撞停止 collision_stop (ac2e8ecf)，射线延伸 ray_extend / 间隔涂色至边界 dotted_ray_to_edge / 质心偏移定向 centroid_bias_dir (13f06aa5)，重涂色 recolor (1818057f)，封闭对象 closed_object / 开放对象 open_object / 封闭孔洞 enclosed_hole (ac2e8ecf)，方向精灵体 directional_sprite / 标记像素 marker_pixel (13f06aa5)

**依赖链**：对象先按拓扑分类（有孔/无孔）滑向对边，滑动后的落点决定了网格中的障碍物分布。然后方向精灵体发射射线，射线在途中遇到障碍物时提前终止并将命中像素重涂。若不先完成滑动，射线的终止位置和重涂目标都无法确定。

先将封闭帧对象滑向顶边、开放对象滑向底边以形成障碍布局，再从方向精灵体沿质心偏移反方向发射间隔涂色射线，射线遇到障碍像素或网格边界时停止并将命中像素重涂为射线标记色。

**输入结构**：约 18x18 的网格，灰(5)背景。网格中有 2~3 个单色 4-连通前景对象（使用蓝(1)、绿(3)等颜色），其中至少一个是封闭帧（其包围盒内部有至少一个被完全包围的灰背景孔洞），至少一个是开放线形图案（无封闭孔洞）。对象形状为不规则 4-连通图形（5~12 像素），不全是矩形。另有 2~3 个方向精灵体：每个精灵体由 7 个橙(7)像素组成一个 8-连通的不对称形状（类似箭头，质心偏向一侧），其中嵌入 1 个非灰非橙的标记像素（如红(2)、黄(4)等不同颜色）。精灵体与前景对象互不接触。生成约束：精灵体不位于网格边缘行/列；各前景对象在水平方向上与至少一个精灵体的射线路径共享列区间（确保射线有机会遇到障碍）。

**规则**：
1. 将所有前景对象（非精灵体）按拓扑分类：包围盒内存在被该对象完全包围的灰(5)背景连通域→封闭帧；否则→开放对象。
2. 封闭帧向上滑动至最高合法位置（紧贴网格顶边或已放置对象，保持水平位置和形状不变）。开放对象向下滑动至最低合法位置。同方向内按原始垂直顺序处理，先到者先放。精灵体不移动。
3. 对每个方向精灵体，计算其橙色像素的质心相对于标记像素的方向向量，取反方向（即远离质心的方向），量化为四个基本方向之一，此为射线方向。
4. 从标记像素出发沿射线方向，每隔一格涂一格标记色（间隔涂色：第 1 格涂色，第 2 格跳过，第 3 格涂色......）。
5. 射线在以下情况终止：(a) 遇到非灰背景像素（即碰到滑动后的对象或另一个精灵体），此时将该被命中的像素重涂为射线标记色，射线停止；(b) 到达网格边界，此时将该边界侧的整行或整列全部涂为射线标记色。
6. 多条射线涂色冲突时（两条射线想涂同一像素），按精灵体在网格中从左到右、从上到下的顺序，后处理的覆盖先处理的。

**关键洞察**：射线的终点完全由拓扑滑动的结果决定——同一精灵体在不同示例中可能因障碍物滑动后的不同落位而产生不同长度的射线。仅凭一个示例无法确定射线是"总是到达边界"还是"遇障碍停止"，必须对比有障碍和无障碍的情况。

## 新题 3：距离分级缩放与轴向旋转堆叠

**组合逻辑**：[距离排序 distance_ordering](创新：距离同时决定排列顺序与缩放因子) + [像素放大 pixel_upscale](创新：放大倍数由空间距离参数化) → [旋转 rotate](已有：由轴色决定) → [堆叠 stack](已有)

**来源原语**：距离排序 distance_ordering / 轴色决定旋转 axis_color_determines_rotation / 坐标轴线 coordinate_axis_line / 堆叠 stack (291dc1e1)，像素放大 pixel_upscale (27f8ce4f, 6aa20dc0)，旋转 rotate (291dc1e1, 6aa20dc0)

**依赖链**：每个精灵体到轴角的距离同时决定了它在输出中的排列位置和放大倍数。旋转取决于轴线颜色布局。三个参数（排列顺序、缩放因子、是否旋转）全部由输入的空间几何关系决定，没有任何一个可以跳过。

将散布在坐标轴附近的小精灵体按到轴角的距离排序，距离越近放大倍数越大，根据轴线颜色决定是否旋转 90 度，最后从上到下堆叠输出。

**输入结构**：约 20x20 的网格，黑(0)背景。沿网格的某一条水平边和某一条垂直边各有一条单色线（颜色分别来自 {蓝(1), 红(2)} 的某种分配），两线在角点处相交，交点像素为黄(4)。网格内部（不接触轴线）散布 3 个小单色精灵体，每个精灵体占据 2x2 或 2x3 的包围盒，使用不同颜色（如绿(3)、橙(7)、品红(6)），精灵体形状不全相同（可以是 L 形、方块、线段等不规则 4-连通图形，3~6 像素）。各精灵体到黄(4)交点的曼哈顿距离互不相同。生成约束：精灵体之间互不相邻；各精灵体到轴角的曼哈顿距离（取精灵体包围盒中心到轴角像素的曼哈顿距离）互不相等。

**规则**：
1. 识别两条轴线及黄(4)交点。确定蓝线和红线的朝向。
2. 计算每个精灵体的包围盒中心到黄(4)交点的曼哈顿距离，按距离从近到远排序，记为第 1、第 2、第 3 个精灵体。
3. 分配放大倍数：第 1 个（最近）→ 3 倍放大；第 2 个 → 2 倍放大；第 3 个（最远）→ 1 倍（不放大）。像素放大规则：每个原始像素变为 k x k 的同色方块，其中 k 为放大倍数。
4. 判断旋转：若蓝(1)线为垂直线，则将每个精灵体（放大后的）逆时针旋转 90 度；若蓝线为水平线，则不旋转。
5. 将处理后的 3 个精灵体从上到下堆叠（最近的在最上方，最远的在最下方），各精灵体之间无间隔行。水平方向上各精灵体左对齐。输出网格宽度等于最宽精灵体的宽度，高度等于三者高度之和。

**关键洞察**：距离在参考题 291dc1e1 中仅决定堆叠顺序，而此处距离还额外决定了放大倍数——"近大远小"的透视映射必须通过对比不同距离精灵体的输出大小才能归纳，仅看单个精灵体无法区分"固定 2 倍放大"和"距离决定放大倍数"。

## 新题 4：角位定向剪切与剪后半区变色

**组合逻辑**：[角位指示方向 corner_indicates_dir](创新：控制像素位置同时编码剪切方向和变色分割轴) → [剪切变换 shear_transform](创新：锚定行/列由角位决定，不再固定为底行) + [重涂色 recolor / 半区变色 half_recolored](创新：分割在剪切后的包围盒上计算)

**来源原语**：剪切变换 shear_transform / 偏移随行距增 offset_grows_with_distance / 底行锚点 bottom_anchor (423a55dc)，角位指示方向 corner_indicates_dir / 控制像素 control_pixel (470c91de)，重涂色 recolor / 半区 half_region / 半区变色 half_recolored (e7dd8335)，包围盒 bounding_box (e7dd8335)

**依赖链**：控制像素的角位决定剪切锚定边（上/下/左/右），从而改变剪切方向和形态。剪切改变了包围盒形状，而重涂色的半区分界线在剪切后的包围盒上计算。控制像素同时约束剪切和变色两步，且变色边界依赖剪切结果。

每个前景对象有一个控制像素标记其某个角，该角的位置决定剪切的锚定边和方向；剪切完成后，在新包围盒上按控制像素所在的半区将该半区重涂为红色。

**输入结构**：约 14x14 的网格，黑(0)背景。网格中有 2~3 个单色 4-连通前景对象（各用不同颜色，如蓝(1)、绿(3)、橙(7)），每个对象占据 4~6 行、3~5 列的包围盒，形状不规则（不全是填充矩形，可以有孔洞或凹陷，4-连通，8~20 像素）。每个对象恰好有一个像素被替换为青(8)控制像素，该青像素位于对象包围盒的四个角位之一（左上/右上/左下/右下）。不同对象的控制像素可以在不同角位。生成约束：对象之间水平和垂直方向至少间隔 3 格，确保剪切后不会重叠；每个对象的包围盒行数和列数均为偶数（保证半区分割无歧义）。

**规则**：
1. 对每个对象，找到其青(8)控制像素的角位（左上/右上/左下/右下）。
2. 确定剪切锚定边和方向：
   - 控制像素在上方两角之一（左上或右上）→锚定最上行不动，各行向下偏移随距离增加。偏移方向：左上→各行向左偏移；右上→各行向右偏移。
   - 控制像素在下方两角之一（左下或右下）→锚定最下行不动，各行向上偏移随距离增加。偏移方向：左下→各行向左偏移；右下→各行向右偏移。
   - 偏移量 = 该行到锚定行的行距（绝对值），单位为格。
3. 将青(8)像素视为对象本体颜色执行剪切：清空原位，将对象所有像素（含控制像素位置，使用对象颜色）按上述偏移重新放置。超出网格边界的像素丢弃。
4. 计算剪切后对象的新包围盒。按控制像素原角位将包围盒分为两半：
   - 角位在左侧（左上或左下）→左右分割，左半区为控制半区。
   - 角位在右侧（右上或右下）→左右分割，右半区为控制半区。
   - 分割线为包围盒水平中点（左半含中线列，右半不含）。
5. 将控制半区内的所有对象像素重涂为红(2)，另一半保持原色不变。

**关键洞察**：同一个控制像素的角位编码了三重信息——剪切锚定边、剪切偏移方向、变色半区选择。变色分界线在剪切后的新包围盒上计算，而非原包围盒，因此同一对象在不同角位的控制像素下会产生完全不同的变色区域。必须对比多个角位不同的示例才能同时归纳出剪切规则和半区选择规则。

## 新题 5：前缀编码可变内缩描边

**组合逻辑**：[编码映射 encoding_map](创新：编码内容从颜色映射变为几何参数——内缩深度) + [描边 draw_frame / 极值内缩定边框 frame_inset_from_extrema](创新：内缩深度不再固定为 1，而由编码决定) + [前缀色映射补全行 prefix_map_complete](创新：从行补全变为角标记属性解读)

**来源原语**：描边 draw_frame / 极值内缩定边框 frame_inset_from_extrema / 标记像素 marker_pixel / 空心矩形 rectangular_frame (928ad970)，编码映射 encoding_map / 前缀色映射补全行 prefix_map_complete / 模板行 template_row / 列对齐 col_alignment (82819916)，角标记 corner_marker (a1570a43)

**依赖链**：图例行将角标记颜色映射到内缩深度数值；角标记颜色确定了使用哪个内缩深度；内缩深度决定了矩形框的绘制位置。三层信息串联，跳过任一层都无法正确画框。

网格顶部有一行图例，将角标记颜色映射到内缩深度值；网格内有多组不同颜色的四角标记，每组定义一个矩形区域；按图例解码每组角标记的颜色得到内缩深度，然后在相应深度处用灰色画矩形框。

**输入结构**：约 20x20 的网格，黑(0)背景。最顶行（第 0 行）为图例行：从左起依次排列 2~3 对"颜色-数字"编码单元，每个单元占两列：第一列为某种颜色 C（如红(2)、绿(3)、蓝(1)），第二列为 1~3 个同色像素竖直排列（像素个数即内缩深度 d，用品红(6)表示计数像素）。各单元之间有至少 1 列黑色间隔。图例行下方的网格区域（第 2 行起）包含 2~3 组四角标记：每组由 4 个同色像素组成，分别位于某个矩形的四角（行极值和列极值各有唯一像素）。不同组使用不同颜色（与图例中出现的颜色 C 对应）。矩形区域内部为黑色背景，可能包含一些黄(4)装饰像素（不影响规则）。各组矩形不重叠。生成约束：每组角标记的颜色必须在图例中有对应条目；各组矩形至少 6x6（确保内缩深度 3 仍有空间画框）；图例中品红像素个数范围为 1~3。

**规则**：
1. 解读图例行：扫描第 0 行的非黑像素，每遇到一个非品红颜色 C 后面紧跟若干品红(6)像素（在 C 的右方同一列或下方同列堆叠），品红像素的数量即为颜色 C 对应的内缩深度 d。具体而言，图例的每个编码单元占一列：该列第 0 行为颜色 C，第 1 行起连续的品红像素个数为 d。
2. 在网格中识别每组同色四角标记（排除图例行的像素），每组 4 个像素的行极值和列极值确定外边界矩形。
3. 查图例得到该颜色的内缩深度 d。
4. 在该矩形的外边界向内缩进 d 格处，画灰(5)矩形框（仅边框，不填充内部）。即框的上边 = 角标记最小行 + d，下边 = 最大行 - d，左边 = 最小列 + d，右边 = 最大列 - d。
5. 保留角标记像素和内部黄(4)装饰像素不变。灰(5)框像素覆盖该位置的原始黑色背景，但不覆盖已有的非黑像素。

**关键洞察**：框的位置不是固定的"角标记内缩 1 格"（如参考题 928ad970），而是由图例编码的可变参数决定。仅看单个示例可能误以为所有框都内缩相同深度，必须对比不同角标记颜色对应不同内缩结果的示例才能发现图例映射关系。

## 新题 6：尺寸匹配平移与标记计数排除

**组合逻辑**：[包围框对齐 bounding_box_alignment](创新：从单目标变为多目标尺寸匹配) + [计数 counting / 最少标记者选中 least_marker_selected](创新：选中的对象被排除而非被擦除到原位) → [平移 translate / 对象移入标记矩形 object_moved_into_marker_rectangle](创新：排除一个对象后剩余对象各自平移到匹配目标)

**来源原语**：平移 translate / 包围框对齐 bounding_box_alignment / 对象移入标记矩形 object_moved_into_marker_rectangle / 角标记 corner_marker (a1570a43)，擦除 erase / 计数 counting / 内部标记计数 interior_marker_count / 最少标记者选中 least_marker_selected / 稀疏标记 sparse_marker (54db823b)

**依赖链**：每个对象通过包围盒尺寸与目标矩形匹配，但对象比目标多一个。标记计数最少的对象被排除（连同其匹配的目标），剩余对象才执行平移。排除决策影响平移方案——如果排除了另一个对象，所有剩余对象的目标分配都会改变。

多个前景对象各含不同数量的灰色标记像素，多组角标记定义等量的目标矩形。对象与目标按尺寸一一匹配，但多出一个对象——标记最少的对象连同其匹配的目标一起被删除，剩余对象平移至各自目标内。

**输入结构**：约 20x20 的网格，黑(0)背景。网格中有 4 组绿(3)角标记，每组 4 个绿像素定义一个矩形的四角，4 个矩形的内部尺寸互不相同（如 3x2, 4x3, 3x4, 5x2 等）。另有 4 个前景对象，各用不同颜色（蓝(1), 红(2), 黄(4), 橙(7)），每个对象是 4-连通的不规则图形（5~15 像素），其包围盒尺寸恰好与某一个目标矩形的内部尺寸一致（一一对应）。每个对象内部嵌有 1~4 个灰(5)标记像素（替代对象颜色的位置）。4 个对象中恰好有 1 个的灰像素数量严格最少（无并列）。生成约束：4 个对象的包围盒尺寸与 4 个目标矩形的内部尺寸形成一一映射（没有两个对象匹配同一目标）；目标矩形之间互不重叠且不与对象初始位置重叠；灰标记最少的对象只有 1 个灰标记，其余至少 2 个。

**规则**：
1. 识别 4 组绿(3)角标记，每组 4 个像素确定一个目标矩形（内部 = 角标记行列极值各内缩 1 格）。
2. 计算每个前景对象的包围盒尺寸（行数 x 列数），与目标矩形的内部尺寸匹配。每个对象恰好匹配一个目标。
3. 统计每个对象内部的灰(5)标记像素数量，找到数量最少的那个对象。
4. 将该对象及其匹配的目标矩形（含 4 个绿角标记）全部擦除为黑(0)背景。
5. 对剩余 3 个对象，将每个对象从原位置平移到其匹配目标矩形内，对齐方式为对象包围盒左上角与目标内部左上角重合。灰标记像素随对象一起移动，保持灰色。清除原位置。

**关键洞察**：尺寸匹配建立了对象与目标的映射关系，但标记计数在映射建立后才生效——它排除了一个对象-目标配对。仅看输出（3 个对象各就各位）无法直接得出排除规则；必须对比多个示例中"哪个被排除了"与"哪个标记最少"的对应关系才能归纳。

## 新题 7：十字计数杯体填充

**组合逻辑**：[模式检测 pattern_detection / 邻域全匹配 all_neighbors_match](创新：检测范围约束在杯体内部而非全局) + [计数 counting](创新：检测结果的数量作为颜色映射的键) → [填充 fill / 标记色决定填充 marker_color_sets_fill](创新：填充色由模式计数映射决定，而非由内部标记像素直接指定) + [追加封盖层 cap_layer_added](已有)

**来源原语**：模式检测 pattern_detection / 邻域全匹配 all_neighbors_match / 十字图案 cross_pattern (1818057f)，填充 fill / 杯状轮廓 cup_outline / 标记色决定填充 marker_color_sets_fill / 追加封盖层 cap_layer_added / 内部包含 containment (444801d8)，计数 counting / 内部标记计数 interior_marker_count (54db823b)

**依赖链**：首先在每个杯体内部检测 '+' 十字图案（模式检测依赖杯体边界约束），然后统计每杯的十字数量（计数依赖检测结果），最后由数量映射到填充颜色（填充依赖计数结果）。三步信息逐级派生，删除任一环节都无法确定填充色。

蓝色杯状轮廓内部散布黄色像素，其中部分组成 '+' 十字图案；统计每个杯内的十字数量，按数量映射到不同填充色填满杯体并加盖。

**输入结构**：约 16x16 的网格，黑(0)背景。网格中有 3~4 个蓝(1)杯状轮廓（开口朝上的 U 形或类似容器形状），每个杯宽 5~7 格，高 4~6 格。杯体由蓝像素围成，上方开口（顶行无蓝像素封顶）。每个杯的内部（蓝围墙之间的黑色区域）散布若干黄(4)像素。部分黄像素形成 '+' 十字图案（一个黄中心像素的上下左右 4 个正交邻居均为黄色），其余黄像素不构成十字。不同杯内的十字数量不同：有的杯 0 个十字，有的 1 个，有的 2 个。生成约束：杯体之间水平间隔至少 2 格；杯内部空间至少 3x3（足以容纳 1 个十字）；每个杯内的黄像素除了十字本身外，还有至少 1 个孤立黄像素（不参与任何十字），确保求解者不能简单地数黄像素总数；十字之间不共享像素。训练示例中须覆盖 0、1、2 三种十字数量各至少出现一次。

**规则**：
1. 识别每个蓝(1)杯状轮廓的包围盒和内部区域（包围盒内、蓝像素围成的封闭空间）。
2. 在每个杯的内部区域中检测 '+' 十字：一个黄(4)像素若其上下左右 4 个正交邻居均在杯内部且均为黄(4)，则该像素是十字中心。每个十字由中心及其 4 个邻居共 5 个像素构成。统计每个杯的十字数量。
3. 按十字数量映射填充色：
   - 0 个十字 → 红(2)
   - 1 个十字 → 绿(3)
   - 2 个十字 → 橙(7)
4. 用映射得到的填充色覆盖杯内部所有非蓝像素位置（包括黄像素和黑空白），即填满整个杯体内部。蓝色杯壁保持不变。
5. 在每个杯正上方一行（杯包围盒最上行 - 1），将杯开口对应的列范围全部涂为该杯的填充色，形成封盖层。

**关键洞察**：填充色不是由杯内某个单独标记像素直接指定的（不同于参考题 444801d8），而是由十字图案的检测和计数间接决定的。十字检测规则（来自 1818057f 的邻域匹配）与填充规则（来自 444801d8 的杯体填充）在此通过计数-映射桥梁耦合。仅看一个杯无法区分"按十字数量选色"和"按黄像素总数选色"或"按杯大小选色"，必须对比多个杯的不同情况才能排除干扰假设。
