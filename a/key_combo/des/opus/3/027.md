## 新题 1：区域配对滑动

**组合逻辑**：[洪泛填充](创新：不用于涂色，而是用于建立不可见的分组约束) + [滑动](已有原语) + [趋近目标](已有原语)

**来源原语**：洪泛填充(flood_fill) ← e681b708；滑动(slide) ← dc433765；趋近目标(approach_target) ← dc433765；障碍段(barrier_segment) ← 1efba499；区域邻接(region_adjacency) ← e681b708；标记像素(marker_pixel) ← dc433765；目标像素(target_pixel) ← dc433765

**依赖链**：洪泛填充以墙壁为障碍将空间分区 → 分区结果决定每个绿(3)标记与哪个黄(4)目标配对 → 配对关系决定滑动方向。删除洪泛填充步骤，则无法确定配对关系（近距离的黄色目标可能与绿色标记被墙壁分隔在不同区域）；删除滑动步骤，则分区信息无处使用。

将墙壁分隔出的区域作为不可见的配对约束，在同一区域内将绿色标记沿直线向黄色目标移动一格。

**输入结构**：约 12x12 的黑(0)背景网格。灰(5)像素排列成若干条水平或垂直的单像素宽墙壁线段，将网格分割成多个 4-连通区域。每个区域内至多放置一个绿(3)标记像素和一个黄(4)目标像素；部分区域同时包含绿和黄各一个，部分区域只有其中之一，部分区域两者皆无。在包含两者的区域内，绿与黄保证处于同一行、同一列或 45 度对角线上。生成约束：墙壁不形成封闭环（每个区域均与网格边界相连），不同区域中的绿-黄对距离关系不同（防止近距离匹配巧合等于区域匹配）。

**规则**：
1. 以灰(5)墙壁像素和网格边界为障碍，对所有非墙壁像素进行 4-连通洪泛填充，划分出若干独立区域。
2. 对每个同时包含一个绿(3)标记和一个黄(4)目标的区域：计算从绿到黄的归一化方向向量（行方向和列方向各取 -1/0/+1），将绿标记沿该方向移动一格（即清除绿标记原位置为黑(0)，在相邻一格处涂绿(3)）。
3. 仅包含绿标记而无黄目标的区域、仅包含黄目标而无绿标记的区域、两者皆无的区域：不做任何改变。
4. 所有灰(5)墙壁和黄(4)目标保持不变。

**关键洞察**：配对关系由区域归属决定，而非空间距离——一个绿标记可能在物理距离上更靠近另一个区域中的黄目标，但被墙壁阻隔后必须向本区域内较远的黄目标移动。需要对比多个示例中不同墙壁布局下的配对情况才能归纳出"同区域配对"规则。

## 新题 2：连通分量大小三元门控

**组合逻辑**：[八连通判定 + 计数](已有原语) → 三元分支：{最大 → 模板提取, 单像素 → [印章覆盖](已有原语), 中间尺寸 → [擦除](已有原语)}

**来源原语**：印章覆盖(stamp) ← 8f2ea7aa；擦除(erase) ← 42a50994；连通分量(connected_component) ← 42a50994；八连通判定(eight_connectivity) ← 42a50994；单像素分量移除(single_pixel_removed) ← 42a50994；自相似嵌套(self_similar_nesting) ← 8f2ea7aa

**依赖链**：八连通分量分析 → 最大分量成为印章模板（模板身份取决于全局比较，非局部属性） → 单像素分量位置成为印章目标 → 中间尺寸分量被擦除。删除连通分量分析则无法区分三种角色；删除印章操作则模板无用武之地；删除擦除操作则中间尺寸分量的处理规则缺失。

根据同色前景像素的 8-连通分量大小决定三种不同操作：最大分量作为模板、单像素处获印章覆盖、中间尺寸分量被擦除。

**输入结构**：约 15x15 的黑(0)背景网格。所有前景像素为同一颜色（如红(2)）。前景像素形成若干 8-连通分量：恰好一个最大分量（像素数 >= 6，形态为紧凑的不规则图形，边界框约 3x3 至 4x4，内部可含黑(0)孔洞），若干单像素分量（彼此 8-邻域内无其他前景像素），以及若干中间尺寸分量（像素数 2~4，形态为短线段或小簇，各自 8-连通）。生成约束：单像素分量位置保证以其为中心放置模板的边界框后不与最大分量或其他印章重叠；中间尺寸分量的像素数严格小于最大分量。

**规则**：
1. 对所有前景像素进行 8-连通分量标记。
2. 识别像素数最多的分量为"模板"。将模板裁剪至其最小边界框（保留内部孔洞为黑(0)）。
3. 对每个像素数 = 1 的分量：以该像素位置为中心，将模板边界框居中放置，用模板的前景像素覆盖对应位置（模板中黑(0)位置不改变目标网格）。超出网格边界的部分丢弃。
4. 对每个像素数在 2 至（模板像素数 - 1）之间的分量：将其所有像素擦除为黑(0)。
5. 模板分量本身保持原位不动。

**关键洞察**：分量大小是一个三元开关——最大者定义模板身份，最小者（单像素）触发印章，中间者被清除。仅凭一个示例可能看不到中间尺寸分量被擦除的行为（若该示例恰好没有中间尺寸分量），必须对比多个示例才能归纳出完整的三元规则。

## 新题 3：奇偶过滤同心环

**组合逻辑**：[排序](已有原语) + [奇偶性](创新：从对象属性筛选器变为集合过滤器，过滤后改变环的尺寸和配色) + [同心层填充](已有原语)

**来源原语**：排序(sorting) ← 3ee1011a；同心层填充(concentric_layer_filling) ← 3ee1011a；单色线段(mono_segment) ← 3ee1011a；同心方形层(concentric_square_layer) ← 3ee1011a；由外到内嵌套(outside_in_nesting) ← 3ee1011a；按长度降序(desc_segment_length) ← 3ee1011a；奇偶性(parity) ← 22806e14

**依赖链**：枚举所有线段 → 奇偶过滤（仅保留奇数长度线段） → 过滤后集合决定排序输入 → 排序后的颜色序列和最大长度同时决定环的层数、尺寸和配色。删除奇偶过滤则环的尺寸和配色都会改变（偶数长度线段会参与）；删除排序则无法确定由外到内的颜色顺序。

过滤掉偶数长度的线段后，将剩余奇数长度线段按长度降序排列，构建同心方形环。

**输入结构**：约 10x10 的黑(0)背景网格。散布着若干条单色 4-连通的水平或垂直直线段，每条线段颜色互不相同，长度互不相同（范围 2~7）。线段之间互不接触（8-邻域无重叠）。线段总数约 4~6 条，其中至少 2 条长度为奇数、至少 1 条长度为偶数。生成约束：奇数长度线段数量 >= 2（确保至少两层环）。

**规则**：
1. 识别所有前景线段，计算每条线段的像素长度。
2. 丢弃所有长度为偶数的线段（它们不参与输出）。
3. 将剩余奇数长度线段按长度从大到小排序。
4. 令 N = 排序后第一条（最长）线段的长度。创建 NxN 的输出网格。
5. 从最外层开始，依次用排序后各线段的颜色填充同心方形层（最外层 = 最长线段的颜色，次外层 = 次长线段的颜色，依此类推）。若线段数少于可用层数，内部未覆盖的层保持黑(0)。

**关键洞察**：偶数长度线段是视觉干扰——它们增加了输入的颜色和线段数量，但不参与输出构建。奇偶过滤同时改变了环的边长（由最长的奇数线段决定，而非全局最长线段）和配色方案。需要对比包含不同偶数线段的示例才能发现过滤规则。

## 新题 4：帧补全后按组计数构建同心环

**组合逻辑**：[分组 + 对称补全](已有原语) → [计数](创新：计数对象从线段长度变为颜色组的帧数量) → [同心层填充](创新：层数和颜色由组大小排序决定，而非线段长度)

**来源原语**：对称补全(pattern_union_completion) ← 42918530；分组(grouping) ← 42918530；同心层填充(concentric_layer_filling) ← 3ee1011a；计数(counting) ← d4b1c2b1；彩色边框(colored_frame) ← 42918530；内部图案(internal_motif) ← 42918530；同色框共享图案(same_color_frames_share_motif) ← 42918530；按边框颜色分组(group_by_frame_color) ← 42918530；由外到内嵌套(outside_in_nesting) ← 3ee1011a

**依赖链**：按颜色分组帧 → 组内取并集补全每个帧的内部图案（补全验证分组正确性） → 统计每个颜色组包含的帧数量 → 按帧数量从多到少排列颜色 → 构建同心环：总帧数决定边长，组帧数排序决定由外到内的颜色。删除补全步骤则无法确认分组正确性（外观不同的帧可能是同一组的不完整版本）；删除计数步骤则无法确定环结构。

将同色方形边框按颜色分组并补全内部图案，再用每组的帧数量决定同心环的层颜色排列。

**输入结构**：约 15x15 的黑(0)背景网格。网格中排列着若干等大的方形边框（边长 3 或 4，均为正方形），相邻边框之间间隔 1 列或 1 行的黑(0)背景。每个边框有 1 像素宽的实色边界，内部可能有若干与边界同色的额外像素（内部图案）。边框共使用 2~3 种前景颜色，每种颜色有 2~4 个边框。同色边框的内部图案可能不同——它们是同一完整图案的不同不完整子集（每个边框展示了完整图案的部分像素，但至少保留了边界）。总帧数约 6~10 个。生成约束：同色边框的内部图案取并集后得到的完整图案在每个边框中一致且唯一。

**规则**：
1. 识别所有方形边框，按边界颜色分组。
2. 对每个颜色组，收集组内所有边框的内部像素相对位置（相对于边框左上角），取并集。将该并集图案写入组内每个边框——即补全不完整的边框。
3. 统计每个颜色组包含的边框数量。
4. 按边框数量从多到少排列颜色组。若数量相同，按该颜色组在输入中首次出现的列位置从左到右排列。
5. 令 S = 所有边框的总数。创建 SxS 的输出网格。
6. 从最外层到最内层，依次用排列后各颜色组的颜色填充同心方形层——最外层用数量最多的颜色组的颜色，次外层用数量次多的颜色组的颜色，依此类推。每个颜色组的颜色占据连续若干层，层数等于该组的帧数量。

**关键洞察**：补全步骤本身不改变输出的几何结构（同心环），但它是正确分组的验证手段——外观不同的边框可能因为是同一完整图案的不同残缺版本而属于同一组。组内帧数量同时决定了该颜色在环中占据的层数，使得补全、计数和环构建三者形成不可跳步的链条。

## 新题 5：尾部位移后对角连线

**组合逻辑**：[滑动 + 尾部决定平移](已有原语) + [连线 + 对角补全](创新：连线对象从预设的矩形对变为滑动后新产生的对角偏移矩形对)

**来源原语**：滑动(slide) ← c6e1b8da；尾部向量(tail_vector) ← c6e1b8da；尾部指示位移(tail_displacement) ← c6e1b8da；尾部决定平移(tail_determines_shift) ← c6e1b8da；实心矩形(solid_rectangle) ← c6e1b8da；连线(connect) ← 342ae2ed；同色矩形对(same_color_rect_pair) ← 342ae2ed；对角偏移(diagonal_offset) ← 342ae2ed；对角补全连接(diagonal_fill) ← 342ae2ed

**依赖链**：识别带尾矩形 → 根据尾部方向和长度滑动矩形体 → 滑动改变矩形位置 → 在新位置上重新评估同色矩形对的空间关系 → 对角偏移的同色对之间画对角连线。删除滑动步骤则矩形位置不变，对角关系不同，连线结果完全不同；删除连线步骤则滑动后的新空间关系无处体现。

先根据尾部向量平移带尾矩形，再在新位置下对角连接同色矩形对。

**输入结构**：约 14x14 的黑(0)背景网格。若干实心矩形（每个矩形 2x2 至 3x4 像素），每种前景颜色恰好出现两个矩形（形成同色对）。部分矩形从某一边伸出 1 像素宽的直线尾部（长度 1~3 像素，沿上/下/左/右四个基本方向之一），其余矩形无尾部。同一颜色的两个矩形中，可能一个有尾、一个无尾，也可能两个都有尾或都无尾。颜色数约 3~4 种，即 6~8 个矩形。生成约束：所有滑动后的矩形互不重叠且不超出网格边界；至少一个同色对在滑动前是同行或同列对齐但在滑动后变为对角偏移，至少一个同色对在滑动前是对角偏移但在滑动后变为同行或同列对齐。

**规则**：
1. 识别每个矩形及其可能的尾部。尾部定义：从矩形某一边的某个像素沿该边的法线方向向外延伸的 1 像素宽同色直线段。
2. 对每个带尾矩形：移除尾部像素（设为黑(0)），将矩形体沿尾部方向平移，平移距离等于尾部长度（像素数）。
3. 无尾矩形保持原位。
4. 在所有矩形移动完成后，检查每个同色矩形对：若两个矩形的边界框在行方向和列方向上均有偏移（即非同行也非同列），则它们构成对角偏移对。
5. 对每个对角偏移的同色对，找到两个矩形边界框上距离最近的一对角点，沿 45 度对角线在两角点之间画一条该颜色的连线（仅覆盖黑(0)背景像素，不覆盖已有矩形或其他连线）。同行或同列的同色对不画连线。

**关键洞察**：尾部滑动重新配置了空间拓扑——某些原本同行对齐的矩形对在滑动后变为对角偏移（需要画连线），而某些原本对角偏移的对在滑动后变为同行对齐（不需要连线）。需要对比多个示例才能发现连线依据的是滑动后的位置而非滑动前的位置。

## 新题 7：折叠 X 图案作为独立子图的缩放密钥

**规则**：
1. 提取左侧 5x5 子图。执行 X-到-方形边框折叠：中心像素(2,2)保持在输出(1,1)位置；左上臂像素(0,0)和(1,1)映射到输出的(0,0)和(0,1)——即顶边从左到中心；右上臂像素(1,3)和(0,4)映射到输出的(0,2)和(1,2)——即右边从上到中心；左下臂像素(3,1)和(4,0)映射到输出的(1,0)和(2,0)——即左边从中心到下；右下臂像素(3,3)和(4,4)映射到输出的(2,1)和(2,2)——即底边从中心到右。当两个臂像素映射到同一输出位置时（不会发生，因为 9 个输入位置映射到 9 个不同的输出位置），保留后映射的颜色。
2. 统计折叠后 3x3 网格中的不同颜色种类数 C。
3. 提取右侧 3x3 子图。将其每个像素替换为 CxC 的同色方块，生成 (3C)x(3C) 的输出网格。
4. 输出仅包含放大后的右侧图案，丢弃左侧 X 图案和灰色分隔符。

**关键洞察**：X 图案是一个"密钥"而非输出内容——它的视觉信息永远不直接出现在输出中。折叠操作可能使原本 X 上看到的颜色种类数发生变化（例如 X 上有 4 种颜色，但折叠后两个位置的颜色恰好重复，使得折叠后只有 3 种），因此必须先折叠再计数，而非直接在 X 上计数。需要对比示例中 X 颜色分布和输出缩放倍率的关系才能发现这一点。

## 新题 9：射线探测跨障碍投票重涂色

## 新题 10：周期平铺后条纹相位遮蔽

**组合逻辑**：[平铺/最小周期扩展](已有原语) + [条纹图案](创新：条纹不是从标记生成，而是由已有图案元素的列位置决定相位) + [擦除](创新：擦除条件由条纹相位控制，而非连通分量大小)

**来源原语**：平铺(tile) ← d8c310e9；最小周期扩展(minimal_period_extend) ← d8c310e9；最小周期单元(minimal_period) ← d8c310e9；列周期重复(column_period) ← d8c310e9；条纹图案(stripe_pattern) ← 834ec97d；列对齐(col_alignment) ← 834ec97d；标记移行绘条纹(marker_drop_stripes) ← 834ec97d；擦除(erase) ← 42a50994

**依赖链**：识别输入中的局部图案 → 找到最小列周期 → 按该周期向右平铺填满整个网格 → 识别平铺后图案中某个特定颜色的首次出现列 → 该列的奇偶性定义条纹相位 → 与该相位相同的列保留，不同相位的列全部擦除为背景色。删除平铺步骤则右侧是空白、无内容可擦除；删除条纹擦除则输出只是完整平铺，缺少相位选择；条纹相位取决于平铺后某颜色像素的列位置，而非输入中该颜色的位置（平铺可能改变首次出现列）。

先将局部图案按最小列周期平铺满整个网格，再以特定颜色首次出现的列奇偶性为相位，仅保留同相位列、擦除异相位列。

**输入结构**：约 6x12 的网格。黑(0)背景。前景图案集中在左侧若干列（约占网格宽度的 1/3 到 1/2），使用 2~3 种前景颜色（如蓝(1)、红(2)、黄(4)）。图案按行呈现列周期性结构（最小列周期 P 约为 2~4 列）。右侧列为黑(0)背景（尚未平铺的区域）。其中一种前景颜色被指定为"相位色"——该颜色在输入中出现次数最少（像素数最少的前景颜色）。生成约束：平铺后相位色首次出现的列位置在不同示例中奇偶性不同（以防止求解者将相位硬编码为固定值）。

**规则**：
1. 找到输入图案的最小列周期 P：满足所有前景像素按 (行, 列 mod P) 分组后位置一致的最小正整数 P。
2. 将该周期图案向右重复平铺，填满整个网格宽度。
3. 在平铺后的完整网格中，找到像素总数最少的前景颜色作为"相位色"。记录相位色首次出现（按列从左到右扫描）的列索引 C0。
4. 令相位 = C0 mod 2（0 或 1）。
5. 对于网格中每一列：若该列索引 mod 2 与相位相同，则保留该列内容不变；否则将该列所有像素擦除为黑(0)。
6. 输出擦除后的网格。

**关键洞察**：平铺本身是完整的图案补全，但条纹擦除步骤将一半的列清空，使输出呈现交替列的条纹效果。关键在于相位的确定——它取决于平铺后最少出现的颜色的首列位置，而非输入中该颜色的位置。由于平铺重复会在新列上生成该颜色的副本，首列位置始终等于原始位置，但求解者必须理解平铺先于相位计算才能正确推导。需要对比多个示例中相位色位置和保留列的对应关系来归纳规则。
