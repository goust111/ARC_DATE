## 新题 1：折叠重排后连线

**组合逻辑**：[fold](已有) + [connect/span_fill](已有) + [row_col_aligned](创新：作用于折叠后的端点位置，而非静态标记) + [fold_toward_space](已有)

**来源原语**：fold, hinge_marker, endpoint_marker, fixed_vs_free, fold_toward_space（来自 230f2e48）；connect, span_fill_between, row_col_aligned（来自 ded97339）

**依赖链**：折叠改变杆件自由端的空间位置 -> 折叠后某些端点标记恰好落在同一行或同一列 -> 对齐的端点之间填充连线。删除折叠步骤则无端点对齐，删除连线步骤则折叠后的对齐关系无可见效果。

将多根铰接杆件折叠后，利用折叠产生的新行列对齐关系在端点之间画连线。

**输入结构**：约 12x15 的网格，黑(0)背景。3-4 根水平或垂直的直杆，每根由红(2)像素组成（长 5-7 像素，4-连通）。每根杆有一个灰(5)端点标记位于其一端，一个蓝(1)铰接标记位于杆的某个内部像素位置。杆件之间互不接触，且初始状态下任意两个灰(5)端点标记既不同行也不同列。生成约束：对每根杆按规则折叠后（保持灰端点侧固定，自由尾部向空间更大的一侧折叠90度），至少有两个灰(5)端点标记落在同一行或同一列上；折叠后的杆件不会相互重叠或越出网格。

**规则**：
1. 对每根杆，识别固定段（从灰(5)端点标记到蓝(1)铰接标记之间的像素，含两端）和自由尾部（蓝(1)铰接标记远端的红(2)像素）。
2. 保持固定段不动。将自由尾部在蓝(1)铰接标记处折叠90度，选择到网格边缘距离更大的垂直方向；若两侧距离相等，选顺时针方向。折叠后的尾部像素仍为红(2)。
3. 所有杆件折叠完成后，找出所有共享同一行或同一列的灰(5)端点标记对。
4. 对每一对同行对齐的灰(5)端点，用橙(7)填充它们之间该行上所有黑(0)像素（仅覆盖黑色单元格，保留已有的红、蓝、灰像素不变）。对每一对同列对齐的灰(5)端点，同理填充该列上它们之间的黑(0)像素。
5. 若多对端点共享同一行或列且跨度嵌套，仅对最外层的一对端点画连线（即取该行/列上最远的两个灰端点之间的跨度）。

**关键洞察**：折叠前没有任何端点对齐，连线目标完全由折叠后的几何布局决定——不做折叠就无法判断哪些端点该连线。

## 新题 2：重力沉降后锚点叠加

**组合逻辑**：[sliding/gravity](已有) + [transparent_overlay](已有) + [crop](已有) + [anchor_alignment](创新：锚点位置由重力沉降后的落点决定，而非静态位置)

**来源原语**：sliding, gravity_settling, column_independent, foreground_pixel（来自 1e0a9b12）；transparent_overlay, crop, sprite, anchor_pixel, anchor_alignment, anchor_registration_overlay（来自 137eaa0f）

**依赖链**：重力沉降改变每个精灵体各像素的纵向位置 -> 精灵体的锚点像素随之移动到新位置 -> 以新锚点位置对齐叠加所有精灵体 -> 裁剪合成结果。删除重力步骤则锚点位置不正确，叠加结果不同；删除叠加步骤则重力沉降无后续合成。

让多个带锚点的精灵体先受重力沉降到底部，再以沉降后的锚点位置对齐叠加并裁剪。

**输入结构**：约 14x14 的网格，黑(0)背景。3 个小型多色精灵体（每个 3-5 像素，4-连通），每个精灵体恰好包含一个灰(5)锚点像素和若干同一颜色的像素（三个精灵体分别使用红(2)、蓝(1)、绿(3)）。精灵体分布在网格上半部分，各精灵体的像素所在列互不重叠（即没有任何两个精灵体的像素出现在同一列中），确保重力沉降时互不干扰。生成约束：沉降后三个灰(5)锚点像素恰好落在同一行上（这要求精灵体的初始纵向排列和内部结构经过设计）。

**规则**：
1. 对每一列独立地将所有非黑像素向下滑动至底部，列内保持原有的从上到下顺序。
2. 沉降后，在每个精灵体中定位灰(5)锚点像素。
3. 将每个精灵体裁剪为其沉降后形态的最小边界框。
4. 以某个输出中心点对齐所有精灵体的灰(5)锚点，透明叠加（黑(0)视为透明）。
5. 若两个非黑像素在叠加时重合，沉降后灰(5)锚点所在列号较小（更靠左）的精灵体优先。
6. 将叠加结果裁剪为包含所有非黑像素的最小边界框作为输出。

**关键洞察**：精灵体的初始高度决定了沉降后锚点的行位置，进而决定叠加时各精灵体的相对偏移。同样的精灵体放在不同高度会产生完全不同的合成结果。

## 新题 3：矩形中心十字线生成平铺网格

**组合逻辑**：[draw_line/crosshair](已有) + [tile](已有) + [grid_partition](创新：分隔线不是预设的，而是由矩形中心位置生成) + [object_occludes_overlay](已有)

**来源原语**：draw_line, hollow_rectangle, crosshair, center_alignment, canvas_spanning_cross, object_occludes_overlay（来自 41e4d17e）；tile, separator_line, tile_pattern, grid_partition, filled_tile_to_empty_slots（来自 c444b776）

**依赖链**：空心矩形的中心确定十字线位置 -> 十字线充当分隔线，将网格分成若干单元格 -> 在单元格内平铺图案 -> 矩形遮挡十字线和图案（矩形同时是分隔线生成器和遮挡层）。删除十字线步骤则无分隔网格；删除平铺步骤则十字线无用途。

通过空心矩形的中心画出全长十字线作为分隔网格，再将小图案平铺到每个单元格中。

**输入结构**：约 16x16 的网格，青(8)背景。2-3 个蓝(1)空心矩形（每个 3x3 到 5x5，单像素厚轮廓线）放置在网格中，它们的中心行互不相同、中心列互不相同。在不包含任何矩形的某个区域内有一个小型红(2)前景图案（3-5 个像素的单色4-连通图形），该图案位于青(8)背景上。生成约束：矩形的中心行和中心列将网格（连同网格边缘）分成若干矩形单元格，其中至少有一个单元格完全不包含蓝色矩形且仅含背景色和红色图案；每个单元格的尺寸足以容纳红色图案。

**规则**：
1. 确定每个蓝(1)空心矩形的中心行和中心列。
2. 沿每个中心行画全宽品红(6)水平线，沿每个中心列画全高品红(6)垂直线。蓝(1)矩形像素遮挡品红线（重叠处保留蓝色）。
3. 以品红(6)线和网格边缘为分隔，将网格划分为若干矩形单元格。
4. 找到包含红(2)图案的单元格，提取红(2)图案相对于该单元格左上角的位置偏移。
5. 将该图案以相同的相对偏移复制到所有其他单元格中。复制时仅覆盖青(8)背景像素；已有的蓝(1)矩形像素、品红(6)分隔线像素和其他非背景像素不被覆盖。
6. 品红分隔线和蓝色矩形保持不变。

**关键洞察**：矩形承担双重角色——它们既是需要保留的前景对象，又隐式编码了平铺网格的布局。移动一个矩形就会改变分隔线位置，从而改变整个平铺模式。

## 新题 4：对称补全揭示重涂色目标

**组合逻辑**：[symmetric_complete](已有) + [recolor](已有) + [marker_identifies_window](创新：窗口资格取决于补全操作的结果而非原始输入) + [max_marker_no_overlap](已有)

**来源原语**：symmetric_complete, tab, notch, boundary, opposite_side_complement, cross_span_projection（来自 8dab14c2）；recolor, solid_window, marker_pixel, center_pixel, marker_identifies_window, max_marker_no_overlap（来自 9caba7c3）

**依赖链**：边界缺口补全 -> 填入的前景像素使原本不完整的 3x3 区域变为实心窗口 -> 新窗口中包含红色标记像素 -> 对最大标记集窗口执行重涂色。删除补全步骤则窗口不完整不符合重涂色条件；删除重涂色步骤则补全只是几何修复无进一步意义。

先对前景对象的边界做对称补全（填缺口、补凸起），补全后新出现的实心 3x3 窗口成为重涂色目标。

**输入结构**：约 14x14 的网格，黑(0)背景。一个厚实的直角多边形灰(5)前景对象（约 8x10 像素范围，内部填实）。边界上有 2-3 个单像素凸起（tab：仅有一个前景4-邻居的边界前景像素）和 2-3 个单像素缺口（notch：有三个前景4-邻居的黑色背景像素）。前景内部嵌有若干红(2)标记像素。某些包含红(2)标记像素的 3x3 区域在当前输入中并非全部为前景——因为该区域边界上的缺口使得 3x3 中有一个黑色像素。生成约束：每个缺口被填充后恰好使其所在的某个 3x3 区域变为完全前景（9 个像素全为灰或红），且该 3x3 区域包含至少一个红(2)像素且中心为灰(5)；补全后不会出现新的缺口或凸起导致需要迭代。

**规则**：
1. 对称补全边界：对每个凸起（tab），沿其所在行或列投射到前景跨度的对侧边缘，移除对侧边缘像素（创建对称缺口）。对每个缺口（notch），沿其所在行或列投射到对侧边缘外一格，添加前景像素（创建对称凸起）。
2. 补全完成后，扫描所有 3x3 区域，找出满足以下条件的候选窗口：(a) 9 个像素全为前景色（灰(5)或红(2)），(b) 至少包含一个红(2)像素，(c) 中心像素为灰(5)。
3. 若多个候选窗口重叠，比较它们的红(2)像素集合——选取红像素集不是任何其他候选窗口红像素集严格子集的窗口（最大标记集筛选）。
4. 对每个选中的窗口：将灰(5)中心像素重涂为黄(4)，将窗口内其他灰(5)像素重涂为橙(7)。红(2)像素保持不变。
5. 选中窗口之外的所有像素（包括补全操作产生的新前景像素）保持原色不变。

**关键洞察**：在补全之前，标记像素所在的 3x3 区域因缺口存在而不符合"实心窗口"条件。对称补全填入了关键像素，使窗口"亮起"——重涂色目标完全由边界几何变换决定。

## 新题 5：围墙约束下的非对称同心扩展

**组合逻辑**：[concentric_expansion](已有，但扩展量被围墙截断变为非对称) + [fill](已有) + [partial_enclosure](创新：围墙不再用于泛洪填充，而是作为扩展的物理屏障) + [inner_size_sets_expansion](已有)

**来源原语**：concentric_expansion, rectangular_frame, inner_rectangle, outer_layer, strictly_inside, concentric_nesting, inner_size_sets_expansion（来自 3a301edc）；partial_enclosure, opening_direction（来自 b9e38dc0）；fill, interior_region（来自 d37a1ef5）

**依赖链**：内矩形尺寸决定扩展量 -> 尝试对称扩展 -> 围墙在某些方向截断扩展 -> 开口侧不受限制 -> 最终扩展形状非对称。删除围墙则扩展对称（与源题相同）；删除扩展则围墙无约束功能。

在半封闭围墙内对嵌套矩形做同心扩展，围墙截断某些方向的扩展量，产生非对称外层。

**输入结构**：约 15x15 的网格，黑(0)背景。一个蓝(1)矩形框（单像素厚轮廓，约 5x5），框内有一个红(2)实心矩形（约 3x3），严格嵌套在蓝框内部。一个绿(3)半封闭围墙（U 形或 L 形，单像素厚，约 9x11）包围着蓝色矩形框的 2-3 个方向，留有一个开口方向。开口侧到网格边缘至少有 4 像素的间距。生成约束：内矩形的高度和宽度定义的对称扩展量在至少一个方向上会超过蓝框到绿色围墙的距离，使得该方向被截断。

**规则**：
1. 确定扩展量：内红(2)矩形的高度 H_inner 和宽度 W_inner。
2. 尝试将前景区域（蓝框+红色内部）的边界框向上和向下各扩展 H_inner 像素，向左和向右各扩展 W_inner 像素。
3. 对每个方向独立截断：若扩展区域在某方向遇到绿(3)围墙像素，截断到围墙前一格（扩展填充到紧邻围墙的那一行/列为止，不覆盖围墙）。若扩展区域超出网格边界，截断到网格边缘。
4. 在截断后的扩展区域内，将所有黑(0)像素填充为红(2)。
5. 原有的蓝(1)框、红(2)内部和绿(3)围墙保持不变。

**关键洞察**：同一个内矩形尺寸在不同围墙几何下产生不同的非对称扩展结果——围墙接近的方向被截断而开口方向自由延伸。围墙位置是决定最终形状的隐含变量。

## 新题 6：角落复制构建射线障碍

**组合逻辑**：[copy/translate](已有) + [ray_cast](已有) + [collision_stop](创新：碰撞对象由前一步的复制操作产生) + [clockwise_next](已有) + [emit_from_endpoints](已有)

**来源原语**：copy, translate, corner_object, touching_two_edges, clockwise_next, ignore_distractors（来自 bc93ec48）；ray_cast, diagonal_segment, diamond_outline, emit_from_endpoints, collision_stop（来自 80a900e0）

**依赖链**：角落对象被顺时针复制到空角 -> 所有四角被占据 -> 中心菱形的对角线段向外发射射线 -> 射线在碰到角落对象（含复制品）时停止。删除复制步骤则两个方向的射线不会被阻挡（打到网格边缘）；删除射线步骤则复制只产生静态装饰。

将角落对象顺时针复制到空角后，从中心菱形发射的对角射线被角落对象（含副本）阻挡。

**输入结构**：约 15x15 的网格，黑(0)背景。中心区域有一个小型蓝(1)空心菱形轮廓（约 5x5，由8个像素构成）。菱形每条边外侧各有一段短的红(2)对角线段（每段 2-3 像素），朝外方向排列。在四个网格角中恰好有 2 个角被绿(3)小型4-连通对象占据（每个 3-5 像素），这些对象的边界框触及该角的两条相邻网格边缘。另外 2 个角为空。被占据的两个角不相邻（如左上和右下，或右上和左下）。其余非菱形、非线段、非角落的前景像素（如有）为干扰项。生成约束：顺时针复制后四个角都被绿色对象占据；从红色线段端点沿对角方向发射的射线会在碰到某个角落对象前穿越足够多的像素以产生可见射线（射线长度至少 3 像素）。

**规则**：
1. 识别角落对象：边界框触及两条相邻网格边缘的绿(3) 4-连通组件。
2. 将每个角落对象顺时针复制到下一角（左上->右上，右上->右下，右下->左下，左下->左上），保持朝向不变，将边界框对齐到目标角。源像素不清除。
3. 对每段红(2)对角线段，确定其相对于菱形的外向方向（垂直于该菱形边缘、远离菱形中心的方向）。
4. 从该线段的两个端点，各沿外向的对角方向发射射线，将射线经过的黑(0)像素涂为红(2)。
5. 射线遇到非黑像素（包括绿色角落对象、蓝色菱形像素、其他红色像素或干扰项）或网格边缘时停止，终止像素不被涂色。
6. 干扰项保持不变，且充当射线障碍物。

**关键洞察**：射线的长度取决于角落对象的存在和位置。复制步骤为原本空白的角落填入障碍物，使所有四个方向的射线都有明确终点——射线障碍是构建出来的，不是输入中就有的。

## 新题 7：围墙开口方向决定路径段反转方向

**组合逻辑**：[reverse_color_seq](创新：仅反转围墙内的子段而非整条路径) + [opening_direction](创新：开口方向不用于泛洪填充，而是决定反转参考方向) + [endpoint_traversal](已有)

**来源原语**：reverse_color_seq, one_pixel_path, endpoint_pixel, endpoint_traversal, shape_fixed_reversed（来自 5792cb4d）；partial_enclosure, opening_direction（来自 b9e38dc0）；fold_toward_space（来自 230f2e48，空间方向判断的思路）

**依赖链**：路径穿过多个围墙 -> 确定每个围墙的开口方向 -> 仅反转围墙内的路径子段 -> 反转的"起点端"是子段中更靠近开口的那一端。删除围墙分析则不知哪些段需要反转及反转方向；删除反转操作则围墙只是静态装饰。

一条多色路径穿越多个半封闭围墙，围墙内的路径段颜色序列被反转，反转方向由开口朝向决定。

**输入结构**：约 15x18 的网格，黑(0)背景。一条多色4-连通单像素宽路径横跨网格，恰有两个端点，无分叉。路径使用 4-5 种不同的非黑颜色（如红(2)、绿(3)、黄(4)、蓝(1)、橙(7)），颜色沿路径变化。2-3 个灰(5)半封闭围墙（U 形，单像素厚）放置在网格中，路径从每个围墙的唯一开口处穿入穿出。路径与围墙壁之间至少隔一格黑色像素（路径不接触围墙壁，仅通过开口穿行）。生成约束：每个围墙内的路径子段至少包含 3 个像素；围墙之间互不重叠；路径在围墙内的走向使得可以明确区分"靠近开口端"和"远离开口端"。

**规则**：
1. 从路径的一个端点出发，沿4-连通方向遍历到另一个端点，记录完整颜色序列。
2. 对每个灰(5)半封闭围墙，确定其开口方向（U 形的开放侧朝向）。
3. 确定路径在该围墙内部的子段：从路径进入围墙内部空间的第一个像素到离开围墙内部空间的最后一个像素（围墙内部定义为围墙壁的4-连通封闭区域内的非墙像素）。
4. 在该子段内，以更靠近开口一端的路径像素为"起始"，更远离开口一端的为"结尾"，将子段的颜色序列就地反转。即：起始像素获得原结尾像素的颜色，依此类推。
5. 围墙外的路径像素保持原始颜色不变。
6. 所有围墙壁像素和背景像素保持不变。

**关键洞察**：不同围墙的开口朝向不同，决定了各自内部路径段的"起始端"选取方式。仅观察一个围墙无法确定反转规则是"靠近开口的当起始"还是相反——必须对比多个围墙的示例才能归纳出方向规则。

## 新题 8：字形扩展后跨面板交换

**组合逻辑**：[stamp_glyph](已有) + [swap](已有) + [recolor](创新：重涂色的颜色来源是对侧面板的底色，而非字形自身颜色) + [encoding_map](已有) + [pairwise_exchange](已有)

**来源原语**：stamp_glyph, control_pixel, glyph_dictionary, sample_legend, encoding_map（来自 dfadab01）；swap, separated_panel, motif_mask, pairwise_exchange, base_color_source, ignore_distractors（来自 5a719d11）

**依赖链**：控制像素在各自面板内扩展为字形 -> 扩展后的字形图案成为面板的图案掩码 -> 成对面板间交换图案掩码 -> 交换时用对侧面板底色重涂。删除字形扩展则无图案可交换；删除交换步骤则字形留在原面板内。

在成对面板内先将控制像素扩展为字形，再将扩展后的字形图案作为掩码在面板对之间交换并重涂色。

**输入结构**：约 14x20 的网格。灰(5)全宽空行和至少一条灰(5)全高空列作为分隔线，将非分隔区域划分为 2 个行带，每个行带包含一个左面板和一个右面板（共 4 个面板，2 对）。每个面板有一种主导底色（如左面板为青(8)，右面板为栗(9)）。每个面板内有 1-2 个单像素控制标记，颜色为红(2)或绿(3)。网格左上角的小区域为样本图例区，展示字形字典：红(2)对应一个 3x3 十字形（中心和四个正交邻居），绿(3)对应一个 3x3 菱形（中心和四个对角邻居）。图例区的控制像素标记在样本右下方。生成约束：每个控制像素扩展为 3x3 字形后不超出所在面板边界；同一面板内的多个字形扩展后不重叠；同一行带的左右面板内控制像素的排布方式不同。

**规则**：
1. 在每个面板内，将每个控制像素扩展为其对应的 3x3 字形，控制像素位于字形中心。字形以控制像素的原始颜色绘制。超出面板边界的部分裁剪。
2. 对每个行带（水平面板对）：提取左面板的字形掩码（所有非底色的像素位置和形状）和右面板的字形掩码。
3. 将两个面板各自清空为自身底色。
4. 将右面板的字形掩码粘贴到左面板的对应位置，粘贴时所有字形像素重涂为右面板的底色（栗(9)）。
5. 将左面板的字形掩码粘贴到右面板的对应位置，粘贴时所有字形像素重涂为左面板的底色（青(8)）。
6. 移除样本图例区（填充为黑(0)或所在面板底色）。
7. 灰(5)分隔线保持不变。

**关键洞察**：最终每个面板中的图案形状由对侧面板的控制像素和字形字典共同决定，而图案颜色由对侧面板的底色决定。三个信息源（字形字典、对侧控制像素位置、对侧底色）缺一不可。

## 新题 9：分区计数驱动旋转角度

**组合逻辑**：[count](已有) + [rotate](已有) + [recolor](已有) + [partition_count_determines_size](创新：分区计数不是生成网格尺寸，而是决定旋转的四分之一圈数)

**来源原语**：count, generate_grid, separator_line, partition_count_determines_size（来自 7039b2d7）；rotate, recolor, line_segment, pivot_marker, rotation_around_pivot, clockwise_quarter（来自 c074846d）

**依赖链**：分隔线将网格分区 -> 计数行区域数 R -> R 决定每根线段绕枢轴顺时针旋转的四分之一圈数 -> 线段旋转并重涂原位颜色。删除计数步骤则不知旋转角度；删除旋转步骤则计数无用途。

用分隔线划分的行区域数作为所有线段的顺时针旋转四分之一圈数。

**输入结构**：约 14x14 的网格，黑(0)背景。若干黄(4)全宽水平线和/或全高垂直线作为分隔线。分隔线之间的矩形区域中，每个区域恰好包含一个灰(5)枢轴标记像素和一根红(2)直线段（2-4 像素长，4-连通，水平或垂直），线段的一端与灰(5)标记相邻。生成约束：连续非分隔行的区间数（行区域数）R 满足 2 <= R <= 4；列区域数与行区域数相等（正方形分区）；对每根线段旋转 R 个四分之一圈后，结果线段不超出所在区域且不与其他对象重叠。

**规则**：
1. 计算 R = 连续非分隔行的区间数（即有多少组被分隔线隔开的连续行段）。
2. 旋转量 Q = R（顺时针四分之一圈数）。即 R=2 时旋转 180 度，R=3 时旋转 270 度，R=4 时旋转 360 度。
3. 对每个区域内的线段：(a) 将红(2)线段原来占据的像素重涂为绿(3)。(b) 以灰(5)枢轴为中心，将线段顺时针旋转 Q 个四分之一圈，在新位置绘制红(2)像素。(c) 若 Q=4（360 度），线段回到原位，绿色被红色覆盖（红色优先，即该像素最终为红色）。
4. 灰(5)枢轴标记和黄(4)分隔线保持不变。

**关键洞察**：分隔线的数量不仅是视觉布局，更是编码了一个全局参数（旋转角度），该参数控制每个区域内的局部变换。增减一条分隔线就会改变所有区域内线段的旋转结果——全局结构隐式编码了局部操作的参数。

## 新题 10：标记邻接选择折叠锚点端

**组合逻辑**：[fold](已有) + [crop](已有，但选择功能来自标记邻接) + [marker_selects_neighbor](创新：标记不是选择"哪个对象输出"，而是选择"哪端作为固定端") + [adjacency_contact](已有) + [fixed_vs_free](创新：固定端不由端点标记颜色决定，而由外部灰色标记的邻接位置决定)

**来源原语**：fold, straight_rod, hinge_marker, fixed_vs_free, fold_toward_space（来自 230f2e48）；crop, marker_pixel, foreground_object, adjacency_contact, marker_selects_neighbor（来自 48d8fb45）

**依赖链**：灰色标记像素与杆件某一端邻接 -> 被触及的那一端成为折叠的固定端 -> 另一端为自由端 -> 自由端在铰接处折叠。删除标记则固定端不确定（对称杆件两端等价）；删除折叠则标记只是静态点缀。

灰色标记像素通过邻接关系指定每根杆件的固定端，从而决定折叠方向。

**输入结构**：约 12x12 的网格，黑(0)背景。2-3 根直杆，每根由红(2)像素组成（5-7 像素长，水平或垂直，4-连通）。每根杆有一个蓝(1)铰接标记位于杆的某个内部像素（不在两端）。每根杆的其中一个端点旁有一个灰(5)标记像素与该端点4-连通相邻（灰色像素不在杆上，在杆旁边的空位）。灰色标记仅触及该端点，不触及杆的其他像素或铰接标记。生成约束：每根杆恰好有一个灰色标记触及其一端；灰色标记不触及其他杆件；折叠后的自由尾部不超出网格且不与其他杆件重叠。

**规则**：
1. 对每根杆，找到与灰(5)标记像素4-连通相邻的端点。该端点所在的一侧（从该端点到蓝(1)铰接标记的路径）为固定段。
2. 铰接标记远端的红(2)像素为自由尾部。
3. 保持固定段不动。将自由尾部在蓝(1)铰接标记处折叠 90 度，选择到网格边缘距离更大的垂直方向；若两侧距离相等，选顺时针方向。
4. 折叠完成后，移除所有灰(5)标记像素（设为黑(0)）。
5. 蓝(1)铰接标记保持原位。红(2)像素在固定段不动，在自由尾部移动到折叠后的新位置（原位设为黑(0)）。

**关键洞察**：灰色标记是一次性的方向选择器——它在输出中消失，但它的位置决定了折叠的极性。对于铰接标记不在正中间的杆件，标记触及不同端会导致不同长度的尾部被折叠，产生截然不同的结果。
