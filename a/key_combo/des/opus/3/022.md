## 新题 1：面板重叠检测驱动逐矩形变换选择

**组合逻辑**：[透明叠加/overlap_test](创新：从全局检测改为逐矩形检测) + [重涂色/recolor](已有) + [内部与边框/interior_vs_border](已有) → 重叠结果决定每个矩形接受哪种变换

**来源原语**：透明叠加(bbb1b8b6)、前景掩码(bbb1b8b6)、面板(bbb1b8b6)、分隔列(bbb1b8b6)、重涂色(bb43febb)、内部与边框(bb43febb)、仅内部像素变色(bb43febb)、无重叠时叠加(bbb1b8b6)、实心矩形(bb43febb)

**依赖链**：面板分离 → 右面板掩码与左面板各矩形逐一做重叠检测 → 检测结果决定对该矩形施加"内部重涂"还是"整体重涂"两种不同变换。重叠检测是变换选择的前提，变换类型依赖检测结果，两者缺一不可。

将右侧面板的掩码作为选择器，对左侧面板中每个矩形执行不同的变换：未被掩码覆盖的矩形仅内部变色，被掩码覆盖的矩形整体变色。

**输入结构**：黑(0)背景网格，约 13 列 x 8 行。由一列灰(5)分隔符将网格分为左右两个等宽面板（各 6 列）。左面板包含 2~4 个互不重叠的蓝(1)实心矩形（每个至少 3x3），矩形之间至少间隔 1 个黑像素。右面板包含若干红(2)前景像素构成的散布掩码（不规则形状，4-连通或多个碎片均可）。生成约束：右面板掩码在对应位置上，至少命中一个左面板矩形的区域，同时至少有一个左面板矩形完全不被命中。

**规则**：
1. 移除灰(5)分隔列，以左面板作为输出画布（尺寸等于单个面板）。
2. 对左面板中每个蓝(1)矩形，检查右面板掩码中是否有任何红(2)像素落在该矩形对应的位置范围内。
3. **未被覆盖的矩形**（该矩形占据的所有位置在右面板中均无红像素）：保留蓝(1)边框（矩形最外一圈像素不变），将严格内部的所有像素重涂为绿(3)。
4. **被覆盖的矩形**（该矩形占据的位置中至少有一个在右面板中存在红像素）：将该矩形全部像素（含边框）重涂为红(2)。
5. 背景像素保持黑(0)不变。
6. 多个矩形独立处理，处理顺序不影响结果（矩形互不重叠）。

**关键洞察**：重叠检测不是全局的"是否有任何重叠"二元判断，而是逐矩形进行——即使整体存在重叠，未被触及的矩形仍获得不同的变换。需要对比多个示例才能确认覆盖判定的粒度是单矩形而非全面板。

## 新题 2：标记引导滑动与同步收缩留迹

**组合逻辑**：[滑动/sliding](创新：作用对象从孤立像素改为实心正方形) + [缩放/resize](创新：从原地收缩改为滑动终点处收缩) + [连线/draw_line](创新：从对侧连线改为中心轨迹线)

**来源原语**：滑动(ae3edfdc)、标记像素(ae3edfdc)、行列对齐(ae3edfdc)、压缩到标记旁(ae3edfdc)、缩放(522fdd07)、同心定位(522fdd07)、边长循环变换(522fdd07)、奇数边正方形(522fdd07)、连线(29c11459)

**依赖链**：每个正方形滑向其同色标记 → 到达终点后以新中心位置为基准收缩 → 滑动路径上留下中心轨迹。标记决定滑动方向和距离，滑动终点决定收缩后的位置，轨迹记录了从何处来。三者形成链式依赖。

将每个彩色实心正方形沿行/列滑向其同色标记像素，到达后原地收缩两级，并在滑动路径上留下中心点的灰色轨迹。

**输入结构**：黑(0)背景网格，约 17x17。网格中有 2~3 个单色实心奇数边正方形（边长取自 {5, 7, 9}），颜色各不相同（如蓝(1)、红(2)、绿(3)）。对每个正方形，在与其中心同行或同列的位置上有恰好一个同色的孤立标记像素（1x1），位于正方形外部。正方形之间、正方形与标记之间留有足够间距，使滑动后的正方形互不重叠且不超出网格边界。生成约束：每个正方形的滑动方向上无其他正方形或标记阻挡。

**规则**：
1. 对每个正方形，找到与其颜色相同且与其中心共行或共列的唯一标记像素。
2. 确定滑动方向：正方形中心指向标记的基数方向（上/下/左/右）。
3. 将正方形沿该方向平移，直至正方形最靠近标记的那条边与标记相邻（标记紧贴正方形边缘外侧一格）。
4. 在滑动过程中，正方形中心经过的每个像素位置（从起始中心到终止中心，不含终止中心本身）涂为灰(5)。
5. 滑动完成后，将正方形以新中心为基准收缩两级：边长 n 变为 n-4（如 9→5, 7→3, 5→1）。收缩后的正方形保持原色。
6. 消除标记像素（标记位置变为黑(0)）。
7. 按正方形中心的初始位置从左上到右下的顺序依次处理（先按行再按列）；若轨迹与其他已到位的正方形重叠，轨迹不覆盖正方形像素。

**关键洞察**：灰色轨迹的长度隐式编码了原始正方形的尺寸和位移距离，但收缩量是固定的（始终减 4），与位移无关。需要对比不同尺寸正方形的示例才能确认收缩量是常数而非与位移成比例。

## 新题 3：块网格编码控制环形旋转方向

**组合逻辑**：[反转编码/invert_code](创新：从输出反转变为用作指令读取) + [循环移色/color_cycle](已有) + [位置索引/position_index](创新：从颜色查找变为方向查找)

**来源原语**：反转编码(6350f1f4)、块网格(6350f1f4)、精灵与空白互逆(6350f1f4)、重复精灵体(6350f1f4)、均匀空白块(6350f1f4)、循环移色(46c35fc7)、环形前景(46c35fc7)、角位像素(46c35fc7)、边中像素(46c35fc7)、反向循环(46c35fc7)、角与边中分组(46c35fc7)、位置索引(09629e4f)

**依赖链**：识别块网格中的精灵/空白模式 → 按位置索引映射到对应环形对象 → 精灵块指定正向旋转、空白块指定反向旋转 → 对每个环执行指定方向的颜色循环。块网格是环旋转的指令表，不解读块网格就无法确定任何环的旋转方向。

读取下方块网格中每个格子的精灵/空白状态，以此决定上方对应位置的 3x3 环的角/边颜色旋转方向。

**输入结构**：黑(0)背景网格，约 15x13。网格分上下两个区域，中间间隔 2 行黑像素。上方区域：一个 2x3 排列的 3x3 环阵列（2 行 3 列共 6 个环），每个环之间间隔 1 列/行黑像素。每个环由 8 个前景像素构成（中心为黑(0)），8 个像素颜色各不相同或部分相同，颜色取自 {蓝(1)、红(2)、绿(3)、黄(4)、橙(7)、青(8)}。下方区域：一个 2x3 块网格，由灰(5)分隔行和列划分为 6 个 3x3 方格，位置与上方环阵列一一对应（左上对左上，以此类推）。每个方格要么包含一个可辨识的双色精灵图案（如栗(9)和黄(4)的固定小图案），要么是单色均匀块（全部为精灵图案中的少数色，如全栗(9)）。生成约束：精灵图案在所有精灵格中完全一致；至少有一个精灵格和一个空白格。

**规则**：
1. 识别下方块网格中重复出现的双色图案为"精灵"，单色均匀格为"空白"。
2. 建立位置对应：块网格第 i 行第 j 列的格子对应上方环阵列第 i 行第 j 列的环。
3. 对应格为精灵的环：角位像素（左上、右上、右下、左下）顺时针循环一步，边中像素（上中、右中、下中、左中）逆时针循环一步。
4. 对应格为空白的环：角位像素逆时针循环一步，边中像素顺时针循环一步（方向与精灵格相反）。
5. 输出仅包含上方区域（旋转后的环阵列），去除下方块网格和间隔行。
6. 环的处理顺序不影响结果（各环独立旋转）。

**关键洞察**：块网格不是要被"反转输出"的编码对象（如源题 6350f1f4），而是一张空间指令表——其精灵/空白状态编码了每个环的旋转方向。需要对比多个示例（精灵格对应的环和空白格对应的环旋转方向相反）才能归纳出这一映射规则。

## 新题 4：对角分析驱动射线方向与互补印章

**组合逻辑**：[对角互补/diagonal_complement](创新：从相邻补块改为沿射线远程投射互补图案) + [射线延伸/ray_extend](创新：射线方向由对角朝向决定而非由标记位置决定) + [印章覆盖/stamp](创新：印章内容为源图案的几何互补而非源图案本身)

**来源原语**：对角互补(22233c11)、正方形块(22233c11)、对角空位补块(22233c11)、射线延伸(ac3e2b04)、投射到引导线(ac3e2b04)、引导线(ac3e2b04)、交叉点印章环形(ac3e2b04)、印章覆盖(ac3e2b04)

**依赖链**：分析每个对角图案的填充方向 → 填充方向决定射线投射轴 → 射线与引导线交叉 → 交叉点处印章为源图案的互补对角。对角分析同时产生射线方向和印章内容两个输出，射线提供位置，互补提供内容，三者会聚在交叉点。

分析每个对角色块图案的填充朝向，沿其决定的轴向发射射线，在射线与引导线的交叉点印章该图案的对角互补色块。

**输入结构**：黑(0)背景网格，约 20x15。网格中有 2~4 条贯穿全宽的水平红(2)引导线（每条 1 像素宽，间隔数行）。引导线上分布着 2~3 个绿(3)对角图案，每个图案占据一个 2k x 2k 的正方形区域（k=2 或 3，即 4x4 或 6x6），该区域被等分为 2x2 的 k x k 方块，其中恰好两个对角方块填满绿(3)，另两个为黑(0)。每个图案的中心行落在某条红引导线上。图案之间水平间距足够大（至少 2k+2 列），使射线互不干扰。生成约束：每个图案的射线方向上至少存在一条其他红引导线可供交叉。

**规则**：
1. 对每个绿(3)对角图案，判断其填充对角方向：若填充块为西北-东南对角（左上+右下），记为 NW-SE；若为东北-西南对角（右上+左下），记为 NE-SW。
2. 确定射线方向：NW-SE 填充 → 从图案中心沿垂直方向（上下）各发射一条射线；NE-SW 填充 → 从图案中心沿水平方向（左右）各发射一条射线。
3. 射线以蓝(1)涂色，仅覆盖黑(0)背景像素，遇到非背景像素（红线、绿图案、已有蓝像素）时跳过该像素继续延伸，直至网格边界。
4. 在射线与每条红(2)引导线的交叉位置（射线经过红引导线所在行/列的那个坐标），以该交叉点为中心印章一个与源图案同尺寸的**互补对角图案**：将源图案中绿(3)的方块位置留为黑(0)，将源图案中黑(0)的方块位置涂为青(8)。印章仅覆盖黑(0)像素，不覆盖红线或其他已有前景。
5. 源绿(3)图案保持不变。红引导线保持不变。
6. 若多个图案的射线经过同一条引导线的不同位置，各自独立印章，互不影响。按图案中心从左到右的顺序处理；若印章区域与已有印章重叠，后处理的覆盖先处理的青(8)像素。

**关键洞察**：对角方向不仅决定互补印章的几何形状（翻转填充/空白），还同时决定射线的投射轴——这两个看似独立的输出（方向 + 内容）都由同一个几何分析产生。必须对比 NW-SE 和 NE-SW 两种图案的示例才能同时归纳出方向规则和互补规则。

## 新题 5：L 形投影构建滑动障碍

**组合逻辑**：[射线延伸/ray_extend](已有，投射到最近边界形成L形) + [滑动/sliding](已有，像素向标记压缩) → 投影线构成障碍物改变滑动终点

**来源原语**：射线延伸(705a3229)、投射到最近边界(705a3229)、标记像素(705a3229, ae3edfdc)、滑动(ae3edfdc)、行列对齐(ae3edfdc)、压缩到标记旁(ae3edfdc)、孤立像素(ae3edfdc, 705a3229)

**依赖链**：橙色投影器发射L形射线 → L形射线覆盖部分网格形成屏障 → 蓝色滑动器沿行/列向红色目标移动时遇到屏障则停止。投影步骤的几何输出直接改变滑动步骤的终止条件——不执行投影则滑动结果错误，不执行滑动则投影无功能意义。

先将橙色标记投射为朝最近两条边的 L 形射线墙，再将蓝色像素沿行/列向红色目标滑动，遇射线墙则提前停止。

**输入结构**：黑(0)背景网格，约 14x14。网格中有 2~3 个橙(7)孤立像素（投影器），每个投影器距一条水平边和一条垂直边更近（无中点平局）。另有 2~4 个蓝(1)孤立像素（滑动器），每个滑动器与恰好一个红(2)孤立像素（目标）共享同一行或同一列。滑动器和目标之间的路径上无其他前景像素（在投影前）。生成约束：至少有一个滑动器的滑动路径会被某条 L 形射线横穿；至少有一个滑动器的路径不被任何射线横穿（以便对比）。投影器不与任何滑动器或目标共行/列。

**规则**：
1. **投影阶段**：对每个橙(7)像素，沿其所在列向较近的水平边界（上或下）画橙(7)线，同时沿其所在行向较近的垂直边界（左或右）画橙(7)线。仅覆盖黑(0)像素。若两条边界等距，则选上方/左方（但生成时保证不出现等距）。
2. **滑动阶段**：对每个蓝(1)像素，找到与其共行或共列的唯一红(2)目标。沿蓝→红方向逐格移动：
   - 若下一格为黑(0)或已是蓝(1)，继续移动。
   - 若下一格为橙(7)射线像素，停止在当前格（不进入橙像素）。
   - 若下一格为红(2)目标像素，停止在当前格（紧邻目标，不覆盖目标）。
3. 将蓝像素从原位擦除（变黑(0)），在停止位置涂蓝(1)。
4. 红(2)目标像素和橙(7)投影像素均保留不变。
5. 滑动器按其初始位置从上到下、从左到右的顺序处理。已移动的蓝像素视为前景，阻挡后续蓝像素（后续蓝像素遇到已到位的蓝像素时停在其前一格）。

**关键洞察**：L 形投影必须先于滑动执行，因为投影线构成了影响滑动终点的屏障。被屏障截停的滑动器与未被截停的滑动器在输出中位置差异显著——需要对比两种情况的示例才能发现屏障的截停作用，而非误以为所有滑动器都到达目标旁。

## 新题 6：形状频率决定变换类型

**组合逻辑**：[形状匹配/shape_matching](已有) + [描边/outline](已有) + [填充/fill](创新：从U形框架内部填充改为包围框内部填充) → 形状频率选择施加哪种几何操作

**规则**：
1. 找出所有红(2)4-连通对象，对每个对象计算其归一化形状掩码（裁剪到紧致包围框后的像素模式）。
2. 按归一化掩码分组，统计每种形状的出现次数。
3. **唯一形状**（出现恰好 1 次）：以该对象的紧致包围框为基准，向外扩展 1 格得到扩展框（裁剪到网格边界）。在扩展框的周边像素中，将所有黑(0)像素涂为绿(3)。红像素不被覆盖。

5. 所有原始红(2)像素保持不变。
6. 对象处理顺序：按包围框左上角坐标从左上到右下（先行后列）。

**关键洞察**：变换类型不是基于对象的尺寸或位置选择的，而是基于其形状在全局中是否独一无二——必须扫描并比较所有对象后才能决定任何一个对象的变换方式。仅看单个示例中某个对象被描边或被填充，无法判断选择依据是频率还是尺寸。

## 新题 8：条纹距离排序填充 U 形框架

**组合逻辑**：[排序/sort](创新：排序键从条纹位置改为条纹与目标的距离) + [填充/fill](创新：从螺旋填充改为逐行/逐列带状填充) + [条纹决定填充轴/stripe_determines_fill_axis](已有) → 条纹朝向决定填充轴，条纹到框架的距离决定填充顺序

**依赖链**：检测条纹朝向（水平/垂直）→ 朝向决定填充维度（行/列）→ 计算每条条纹到 U 形框架最近边的距离 → 按距离升序排列 → 依此顺序逐行或逐列填充框架内部。朝向分析和距离排序共同决定输出，缺一则填充结果错误。

1. 判断所有条纹的朝向：水平（沿行延伸）或垂直（沿列延伸）。
2. 计算每条条纹到 U 形框架最近边像素的曼哈顿距离（取条纹上所有像素到框架上所有灰像素的最小距离）。

4. 填充框架内部空腔：
   - 若条纹为水平：从空腔顶行到底行，依次用排序后第 1、第 2、…条条纹的颜色填满整行。
   - 若条纹为垂直：从空腔左列到右列，依次用排序后第 1、第 2、…条条纹的颜色填满整列。
5. 原始条纹和 U 形框架保持不变。

**关键洞察**：排序键是条纹到框架的距离而非条纹本身的行/列坐标——只有在条纹空间顺序与距离顺序不一致的示例中，求解者才能排除"按位置排序"的错误假设，发现真正的排序依据。

**组合逻辑**：[逐步移动/stepwise_move + 消除/consume](已有，消除标记确定路径) + [堆叠/stack](创新：从垂直像素重排改为按消除顺序决定层色) + [居中金字塔/centered_pyramid](已有)

**依赖链**：三角精灵体逐步消除标记 → 消除顺序记录颜色序列 → 该序列决定金字塔从顶到底每层的颜色 → 以精灵最终位置为中心基线对齐构建金字塔。移动路径编码了颜色信息，金字塔结构编码了路径长度；两者通过消除顺序紧密耦合。

**规则**：
1. 从精灵体出发，沿当前朝向方向扫描同行或同列，找到最近的标记像素。
2. 将精灵体移动到该标记位置，消除标记，将该标记的颜色追加到颜色序列末尾。精灵体朝向更新为本次移动方向。
3. 重复步骤 1-2，直到当前朝向的半线上无标记。此时检查所有四个基数方向——若某方向有标记则转向该方向继续（生成保证最多一个方向有剩余标记）。若无标记，停止。
4. 设收集了 n 个颜色（c1, c2, ..., cn），以精灵体最终位置所在列为中心列，在精灵体最终位置下方构建金字塔：
   - 第 1 层（最顶）：宽 1 像素，颜色 c1，位于精灵体正下方 1 格。
   - 第 2 层：宽 3 像素，颜色 c2，居中于中心列，紧接第 1 层下方。
   - 第 k 层：宽 2k-1 像素，颜色 ck，居中对齐。
5. 清除精灵体（最终位置变黑(0)）。金字塔底部与网格底边之间可能有空行。
6. 若金字塔某层超出网格左右边界，超出部分裁剪掉。

**关键洞察**：标记的消除顺序完全由精灵体的移动路径决定（朝向→最近标记→新朝向→下一个最近标记），而这个顺序直接映射为金字塔的层色分配。仅看最终金字塔无法还原路径，仅看标记分布无法确定层色——两者通过消除顺序耦合。

## 新题 10：对侧矩形相向合并后重涂内部

**组合逻辑**：[对侧配对/opposite_pairing](创新：从孤立像素配对改为矩形配对) + [滑动/sliding](创新：从像素滑动改为整体矩形滑动) + [重涂色/recolor + 内部与边框/interior_vs_border](创新：在合并后的新拓扑上执行内部重涂)

**依赖链**：按颜色配对对侧矩形 → 两矩形相向滑动至相邻 → 用桥接列/行连接为一体 → 在合并后的新形状上划分边框与内部 → 内部重涂。合并改变了拓扑，使得新内部严格大于两个原始内部之和，重涂范围依赖合并几何。

将网格两侧同色矩形对向滑动至相邻，用桥接带连为一体，再将合并体的内部像素重涂为新颜色。

**输入结构**：黑(0)背景网格，约 19x9（宽扁形）。网格中有 2 对实心矩形，每对共享一种颜色且位于网格对侧（一个在左侧区域，一个在右侧区域）。颜色如：一对蓝(1)、一对红(2)。每个矩形至少 3x3，同对矩形高度相同，在同一行带内水平对称分布。同对矩形之间间隔至少 4 列（确保滑动距离 >= 2）。不同对矩形位于不同行带，行带之间至少间隔 1 行。

**规则**：
1. 按颜色将矩形配对。每对中，左侧矩形和右侧矩形具有相同高度。
2. 两个矩形同时向对方方向水平滑动，各自滑动距离为两矩形间距的一半减 1（使得滑动后两矩形之间恰好间隔 1 列黑像素）。若间距为奇数，左侧多滑 1 格。
3. 用该对颜色填充两矩形之间的 1 列间隔（桥接列），使两矩形和桥接列形成一个完整的实心矩形。
4. 对合并后的完整矩形，将其严格内部（不含最外一圈像素）的所有像素重涂为黄(4)。最外一圈保持原色。
5. 若合并后的矩形宽度或高度不足 3（无严格内部），则不重涂（整体保持原色）。
6. 两对矩形独立处理，处理顺序不影响结果（不同行带互不干扰）。
7. 滑动路径上无轨迹保留（干净滑动）。

**关键洞察**：合并后的内部区域不等于两个原始矩形内部之和加桥接列——桥接列旁的原边框像素在合并后变为内部像素，使得重涂范围涌现性地大于预期。需要准确理解"合并后再划分内部"而非"分别划分内部再拼接"。
