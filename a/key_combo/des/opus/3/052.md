## 新题 1：方向标记驱动滑动与接触计数染色

**组合逻辑**：[方向编码](原有) → [滑动+接触停止](创新：滑动方向由标记编码而非固定) → [计数+重涂色](创新：同一障碍的接触次序决定颜色)

**来源原语**：方向编码(a8c38be5)、滑动(025d127b/56dc2b01)、接触停止(56dc2b01)、计数(9af7a82c)、重涂色(800d221b)、颜色循环(195c6913)

**依赖链**：标记像素的方位决定精灵体的滑动方向；滑动沿该方向持续直至接触障碍条；每个障碍条独立累计被接触次数，该次序索引一个颜色循环表来决定精灵体的最终颜色。去掉方向编码则滑动方向不确定；去掉接触停止则终点位置不确定；去掉计数染色则输出颜色不确定。

将散布的带标记精灵体按各自标记方向滑动至障碍条，再依据每个障碍条上的接触先后顺序查表重涂精灵体颜色。

**输入结构**：约 18x18 黑(0)背景网格。网格中有 3-5 个单色小精灵体（每个由 3-6 个 4-连通像素组成，形状各异，所有精灵体颜色相同，如蓝(1)）。每个精灵体正好有一个相邻（4-邻接、不属于精灵体本身）的标记像素，颜色为绿(3)，位于精灵体的上/下/左/右某一侧。网格中有 2-3 条红(2)直线障碍条（宽 1 像素、长度 3-8 像素，方向水平或垂直）。网格左下角有一个 1 行 K 列（K >= 精灵体数量）的色带，依次显示颜色循环序列（如黄(4)、灰(5)、品红(6)、橙(7)...），该色带不参与滑动逻辑。生成约束：每个精灵体沿其标记方向的路径上恰好有一条障碍条可达；不同精灵体滑动路径互不交叉。

**规则**：
1. 识别每个精灵体及其唯一相邻的绿(3)标记像素。标记在精灵体上方表示向上滑动，在下方表示向下，在左侧表示向左，在右侧表示向右。
2. 擦除所有绿(3)标记像素。
3. 将每个精灵体沿标记所指方向逐像素平移，直到精灵体的任一像素与某条红(2)障碍条 4-邻接为止（精灵体不覆盖障碍条，停在相邻位置）。
4. 按从上到下、从左到右的顺序处理精灵体（以精灵体包围盒左上角坐标排序，先按行再按列）。为每条障碍条维护一个独立的接触计数器，初始为 0。当一个精灵体停靠到某障碍条时，该障碍条的计数器加 1，当前计数值记为 N。
5. 将该精灵体重涂为左下角色带中第 N 个颜色（1-indexed；色带从左到右依次为第 1、第 2、... 个颜色）。
6. 输出保留障碍条（红色不变）和色带，精灵体在新位置以新颜色绘制，原位置擦除为黑(0)。

**关键洞察**：同一障碍条可被多个精灵体从不同方向接触，接触的先后顺序（由空间处理序决定）索引同一个颜色循环表，使得停靠在同一障碍条上的精灵体获得不同颜色——仅看单个示例可能以为颜色由滑动方向决定，需要对比多个示例才能发现是接触次序决定的。

## 新题 2：封闭面积柱状图按框架高度排序

**组合逻辑**：[裁剪+包围检测](原有) → [计数](创新：计数对象是封闭背景面积而非前景像素) → [排序](创新：排序键与柱高度来自同一对象的不同度量)

**来源原语**：裁剪(b9b7f026)、包围(b9b7f026)、含孔洞者选中(b9b7f026)、计数(9af7a82c/b7999b51)、排序(9af7a82c/b7999b51)、柱状图(9af7a82c/b7999b51)、包围盒高决定柱高(b7999b51)、频率降序柱状图(9af7a82c)

**依赖链**：先检测哪些矩形框封闭了背景孔洞（排除实心矩形）；对每个含孔洞的框计算两个独立度量——封闭背景像素面积（决定柱高）和框自身包围盒高度（决定排列顺序）。去掉封闭检测则不知道哪些框参与统计；去掉面积计数则柱高无定义；去掉包围盒高度排序则列序不确定。

从含孔洞的矩形框中提取封闭面积，按框的包围盒高度降序排列为柱状图——柱高是封闭面积，列序是框高。

**输入结构**：约 20x20 黑(0)背景网格。网格中有 4-6 个单色矩形对象，颜色各不相同（如蓝(1)、红(2)、绿(3)、黄(4)、灰(5)），互不重叠且互不相邻。其中一部分矩形是实心填充，另一部分是空心框（1 像素宽边框，内部为黑(0)背景）。空心框的尺寸各异，确保每个空心框的包围盒高度互不相同，每个空心框封闭的背景像素数量也互不相同。生成约束：至少 2 个空心框、至少 1 个实心矩形；空心框的包围盒高度排名与封闭面积排名不完全一致（至少有一对空心框的两个排名顺序相反），以确保排序键和柱高的分离可被观察到。

**规则**：
1. 找出所有单色 4-连通前景对象。对每个对象，检查其包围盒内部是否存在一个完全被该对象颜色围合的黑(0) 4-连通区域（该背景区域不触及包围盒的任何边）。
2. 排除所有不含封闭孔洞的对象（实心矩形等），仅保留含孔洞的空心框。
3. 对每个空心框测量两个值：(a) 封闭的黑(0)像素总数 A；(b) 框的包围盒高度 H（像素行数）。
4. 将所有空心框按 H 降序排列。H 相同时（生成约束保证不会出现，但作为容错）按包围盒左上角列号升序排列。
5. 构建输出：输出网格高度 = max(A) 行，宽度 = 空心框数量列。每列对应一个空心框（按上述排序从左到右），从顶行开始向下填充该框的颜色共 A 行，其余为黑(0)。

**关键洞察**：排序的键（包围盒高度）和柱的高度（封闭面积）是同一对象的两个不同几何度量。仅看单个示例可能误以为两者成正比或排序键就是柱高本身，需要多个示例才能发现二者解耦。

## 新题 3：补全色表作为路径网络重涂查找表

**组合逻辑**：[间隙填充+周期推断](原有) → [计数+邻接传色](创新：计数结果作为已补全表格的索引) → [重涂色](创新：颜色由表格查找而非直接邻接决定)

**来源原语**：间隙填充(1e97544e)、周期推断(1e97544e)、对角线相位偏移(1e97544e)、路径网络(800d221b)、中心枢纽(800d221b)、种子区域(800d221b)、邻接传色(800d221b)、邻接计数决定色(800d221b)、重涂色(800d221b)、颜色循环(195c6913)

**依赖链**：角落的残缺表格必须先用对角相位周期规则补全，补全后的表格第一行构成颜色查找序列；路径网络中每条分支与枢纽相邻的像素数决定查找索引；索引查表得到分支的新颜色。去掉表格补全则查找序列未知；去掉邻接计数则索引未知；去掉重涂则输出不变。

先补全角落残缺的周期色表，再用路径分支与枢纽的邻接像素数作为索引查表，将每条分支重涂为查到的颜色。

**输入结构**：约 20x20 黑(0)背景网格。主体是一个灰(5)色的细线正交路径网络（1 像素宽），网络中心有一个 3x3 灰(5)实心正方形枢纽。从枢纽向外延伸 3-5 条分支，每条分支长度不同（3-8 像素）。每条分支的末端附近有一个 1-2 像素的种子区域，颜色各不相同（取自蓝(1)、红(2)、绿(3)、黄(4)中的若干种），种子与分支 4-邻接。网格右下角有一个 4x4 的小表格区域，用品红(6)像素标注边框（1 像素宽框线），内部是 2x2 的色格，其中部分色格已填色、部分为黑(0)空白。已填色格遵循一个以列为相位的颜色循环规律，且对角线上下存在相位偏移。生成约束：表格的已填部分足以唯一推断完整的颜色循环及相位偏移规则；补全后表格第一行的颜色序列长度不小于最大邻接数；不同分支与枢纽的邻接像素数互不相同。

**规则**：
1. 识别右下角的品红(6)边框小表格。表格内部为 2x2 色格（部分为黑(0)空白）。
2. 从已填色格推断颜色循环序列 C 及对角线相位偏移规则：主对角线及以上的色格取该列的周期相位 p = col mod len(C)，主对角线以下取相位 p = (col+1) mod len(C)。用此规则将所有黑(0)空白色格补全。
3. 读取补全后表格第一行的颜色序列 S = [S[0], S[1], ...]（从左到右）。
4. 在路径网络中，找到 3x3 灰(5)实心枢纽。对枢纽外围的每条分支，计算该分支中与枢纽 4-邻接的像素数量 k（即分支直接连接枢纽的像素数，通常为 1，但如果分支在枢纽边上有多点连接则更大）。
5. 将每条分支的所有灰(5)像素重涂为 S[(k-1) mod len(S)]（k 从 1 开始，索引从 0 开始）。枢纽本身保持灰(5)不变。
6. 种子区域、表格区域保持不变。

**关键洞察**：残缺表格并非装饰——它是唯一的颜色查找源，必须先补全才能使用。分支的邻接像素数（通常被忽略的微小几何差异）成为查表的关键索引，而非直接使用种子颜色来涂色。

## 新题 4：精灵体对称性编码瓦片镜像阵列

**组合逻辑**：[对称性分析](创新：对称性不用于消歧旋转，而用于编码指令) → [平铺+镜像](创新：镜像位置由外部对称性信号决定而非固定)

**来源原语**：对称消歧旋转(2c181942)→改造为对称性分析编码、平铺(00576224/a416b8f3)、镜像(00576224)、阵列排布(00576224)、中间行翻转(00576224)→改造为条件性翻转、精灵体(2c181942/a8c38be5)、形状匹配(2c181942)

**依赖链**：精灵体的对称性属性（左右/上下/均有/均无）决定瓦片阵列中哪些位置执行镜像翻转；平铺生成基础阵列后根据对称性信号选择性翻转特定行或列的瓦片。去掉对称性分析则翻转模式不确定；去掉平铺则无阵列可操作。精灵体不出现在输出中——它纯粹是指令编码器。

分析散落精灵体的镜像对称性，以此决定瓦片阵列中奇数行/列是否做镜像翻转，然后输出修改后的瓦片阵列。

**输入结构**：约 15x15 黑(0)背景网格。左上角有一个 3x3 的彩色瓦片（4 种颜色填充 9 格，无对称性，以确保翻转可被观察到）。网格右下区域有一个由红(2)像素构成的小精灵体（4-8 个 4-连通像素，占据一个不超过 4x4 的包围盒）。精灵体的形状具有特定对称性：可能仅有左右镜像对称、仅有上下镜像对称、两者兼有、或两者皆无。瓦片和精灵体之间有足够间距（至少 2 像素）。生成约束：不同训练示例中精灵体的对称类型不同，以便求解者通过对比归纳映射规则。

**规则**：
1. 识别左上角的 3x3 瓦片 T 和右下区域的红(2)精灵体。
2. 分析精灵体的镜像对称性：检查是否关于垂直中轴左右对称（记为 sym_LR = true/false），是否关于水平中轴上下对称（记为 sym_UD = true/false）。
3. 构建一个 3x3 的瓦片阵列（输出为 9x9 网格），初始时每个位置放置瓦片 T 的原始副本。
4. 若 sym_LR = true，则将阵列中列索引为奇数（0-indexed，即第 1 列）的所有瓦片替换为 T 的左右镜像。
5. 若 sym_UD = true，则将阵列中行索引为奇数（0-indexed，即第 1 行）的所有瓦片替换为 T 的上下镜像。若该位置已被步骤 4 左右翻转，则在翻转结果上再做上下镜像（等价于 180 度旋转）。
6. 输出仅包含 9x9 瓦片阵列，精灵体和原始瓦片区域不出现在输出中。

**关键洞察**：精灵体是一个与输出内容完全无关的"指令对象"——它的几何对称性属性被解码为瓦片阵列的镜像规则。仅看单个示例无法判断是精灵体的对称性、颜色、面积还是位置在编码指令，必须对比多个示例（对称类型不同但瓦片相同、或瓦片不同但对称类型相同）才能锁定规则。

## 新题 5：面板内滑动后跨面板图层合成

**组合逻辑**：[滑动](创新：滑动发生在面板内部而非全局) + [透明叠加+图层优先级](创新：优先级解决的冲突取决于滑动位移后的像素位置)

**来源原语**：滑动(025d127b)、支撑(025d127b)、有后续像素则移(025d127b)、透明叠加(6a11f6da)、等高面板(6a11f6da)、图层优先级(6a11f6da)、底层最优先(6a11f6da)

**依赖链**：每个面板中的前景对象独立执行东南支撑滑动，改变像素位置；滑动后的三个面板做透明叠加，底层优先。滑动改变了哪些位置有前景像素，从而改变了面板之间的冲突格局——同样的三个面板如果不做滑动，合成结果完全不同。去掉滑动则合成输入错误；去掉合成则三面板未合并。

三个等高面板各自的前景对象先做东南支撑滑动，然后将滑动后的面板按中-上-下的图层优先级透明叠加为单面板输出。

**输入结构**：约 21x7 的网格（3 个面板纵向堆叠，每个面板 7x7）。背景为黑(0)。三个面板由 1 像素宽的灰(5)水平分隔线分开（分隔线位于第 7 行和第 14 行，0-indexed）。顶部面板（行 0-6）含蓝(1)前景像素；中部面板（行 8-14 去掉分隔行后对应行 8-13，6 行）含红(2)前景像素；底部面板（行 15-20）含绿(3)前景像素。每个面板中的前景像素构成一个 4-连通小图形（4-8 像素），形状各异，不触及面板边界。生成约束：三个面板中的前景图形在各自面板内的相对位置存在部分重叠（即如果把三个面板叠放到同一坐标系，至少有 2 个位置上存在多面板的前景像素），且滑动后的重叠位置与滑动前不同（即至少有一个滑动前不冲突但滑动后冲突的位置，或反之）。

**规则**：
1. 识别三个面板的边界（由灰(5)分隔线划分）。分隔线不参与后续操作。
2. 在每个面板内部独立执行滑动：对该面板中的每个前景像素，检查同面板内是否存在另一个前景像素在它的严格右下方（行号更大且列号更大）。若存在，将该像素向右移动 1 列；若不存在（即该像素处于该面板前景图形的东南前沿），保持不动。所有像素的移动判定基于滑动前的位置，同时执行。
3. 将三个面板映射到同一坐标系（每个面板的相对坐标：面板内第 r 行第 c 列对应输出第 r 行第 c 列）。
4. 透明叠加：先铺中部面板的非黑像素；再覆盖顶部面板的非黑像素（覆盖中部）；最后覆盖底部面板的非黑像素（覆盖前两层）。未被任何面板的前景覆盖的位置保持黑(0)。
5. 输出为单个面板大小的网格（与单面板等大），不含分隔线。

**关键洞察**：面板内的东南支撑滑动改变了前景像素的列坐标，而图层合成对同一坐标的冲突按面板层级裁决。滑动位移量因图形形状而异（前沿不动、内部右移），使得冲突格局无法通过简单平移预测——必须先完成逐像素滑动判定，才能确定最终合成结果。

## 新题 6：菱形轮廓半径调整改变射线传播拓扑

**组合逻辑**：[收缩+膨胀](原有，颜色决定操作) → [射线延伸](创新：射线被调整后的菱形轮廓阻挡，而非网格边界) → [连线](创新：连线端点由射线终点定义而非预设像素对)

**来源原语**：收缩(d753a70b)、膨胀(d753a70b)、菱形轮廓(d753a70b)、颜色决定操作(d753a70b)、半径微调(d753a70b)、射线延伸(db695cfb)、触发像素(db695cfb)、触发点分束(db695cfb)、连线(db695cfb)

**依赖链**：菱形轮廓先按颜色执行收缩或膨胀，改变其几何位置；触发像素向四个基方向发射射线，射线被调整后的菱形轮廓阻挡而停止；如果两条不同触发像素发出的射线终止在同一菱形轮廓上，则用该触发像素的颜色连接这两个终止点。去掉半径调整则阻挡位置不同、射线长度不同、连线端点不同；去掉射线则无终止点可连；去掉连线则输出不完整。

菱形轮廓按颜色收缩或膨胀后成为射线障碍，触发像素发射基方向射线至碰到菱形轮廓为止，终止在同一菱形上的射线对之间用触发色连线。

**输入结构**：约 22x22 橙(7)背景网格。网格中有 2-3 个曼哈顿菱形轮廓（1 像素宽的菱形环），其中红(2)菱形 1-2 个（半径 3-5），灰(5)菱形 1 个（半径 2-4）。菱形互不重叠，与网格边界保持至少 3 像素距离。另有 2-4 个孤立的触发像素，颜色为蓝(1)或绿(3)，分布在菱形外部。生成约束：红(2)菱形收缩 1 层后、灰(5)菱形膨胀 1 层后，每个触发像素至少有一个基方向射线能到达某个菱形轮廓；至少存在一对触发像素，它们的射线分别终止在同一个菱形轮廓上（即该菱形被两条射线击中）。

**规则**：
1. 清除所有红(2)和灰(5)菱形轮廓像素。
2. 以相同圆心重绘：红(2)菱形半径减 1，灰(5)菱形半径加 1。若收缩后半径为 0，则仅绘制圆心单像素。膨胀后超出网格边界的部分裁剪。
3. 从每个触发像素（蓝(1)或绿(3)）向上、下、左、右四个方向各发射一条射线。射线逐像素延伸，遇到调整后的菱形轮廓像素时停止（射线包含起点、不包含终点轮廓像素）。遇到网格边界时也停止。射线用该触发像素的颜色绘制。
4. 对每个调整后的菱形轮廓，收集所有终止在它上面的射线（即射线的下一像素属于该菱形轮廓）。若恰好有 2 条这样的射线（来自不同触发像素），在该菱形轮廓的表面上，沿轮廓弧从一个终止点画到另一个终止点（取较短弧），颜色为两个触发像素中编号较小的那个颜色（蓝(1) < 绿(3)则用蓝）。若多于 2 条，按顺时针顺序两两配对（第 1 与第 2 连、第 3 与第 4 连，依此类推），奇数条的最后一条不连。若仅 1 条或 0 条，不做连线。
5. 触发像素本身保留原色。

**关键洞察**：菱形的收缩/膨胀不仅改变视觉外观，更本质地改变了射线的传播距离和终止位置，进而决定哪些射线对会在同一菱形上"会师"并被连线。这是一个"几何变形改变拓扑连接"的涌现效应——收缩可能使原本能到达的菱形变得太小而被射线越过，膨胀则可能拦截原本会飞向远处的射线。

## 新题 7：多目标窗口粘贴与方向标记偏移

**组合逻辑**：[平移粘贴+标记点对齐](原有) → [方向编码](创新：编码的不是布局位置而是粘贴时的局部偏移) → [掩码裁剪](原有，但裁剪多个独立窗口)

**来源原语**：平移粘贴(2f0c5170)、掩码裁剪(2f0c5170)、共享标记点(2f0c5170)、标记点偏移对应(2f0c5170)、精灵窗口(2f0c5170)、空白窗口(2f0c5170)、方向编码(a8c38be5)、色块决定输出位置(a8c38be5)→改造为色块决定偏移方向、着色标记(a8c38be5)

**依赖链**：精灵窗口中的标记点确定粘贴基准位置；每个目标空白窗口的方向标记编码一个额外的 1 像素平移偏移；精灵图案先对齐标记点再按偏移方向移动 1 格后裁剪到窗口边界。去掉标记对齐则基准位置不确定；去掉方向偏移则所有窗口得到相同结果（但实际不同）；去掉掩码裁剪则溢出部分不知如何处理。

将精灵图案粘贴到多个目标窗口中，先按标记点对齐，再按各窗口的方向标记做 1 像素额外偏移，超出窗口的部分裁剪。

**输入结构**：约 20x20 黑(0)背景网格。网格中有 1 个精灵窗口：一个灰(5)填充的矩形区域（约 5x5），内含若干彩色像素构成一个小图案（3-5 像素，颜色为蓝(1)），以及 1 个黄(4)标记像素。另有 2-3 个目标空白窗口：同样大小的灰(5)填充矩形区域，每个内含 1 个黄(4)标记像素和 1 个品红(6)方向标记像素。品红标记位于该窗口标记点的上/下/左/右某一侧且与标记点 4-邻接。所有窗口大小相同。各窗口之间至少间隔 2 像素。生成约束：精灵图案在对齐+偏移后，至少有一个窗口会出现图案部分溢出窗口边界的情况（以测试裁剪规则）；不同目标窗口的品红方向标记位于标记点的不同方向。

**规则**：
1. 识别精灵窗口（含彩色图案像素的灰色矩形）和目标窗口们（无彩色图案、仅有标记的灰色矩形）。
2. 在精灵窗口中，记录蓝(1)图案像素相对于黄(4)标记像素的偏移集合 D = {(dr_i, dc_i)}。
3. 对每个目标窗口：
   a. 找到黄(4)标记点位置 (r_m, c_m) 和品红(6)方向标记位置。
   b. 品红标记相对于黄标记的方位决定额外偏移：品红在上 → 额外偏移 (-1, 0)；品红在下 → (1, 0)；品红在左 → (0, -1)；品红在右 → (0, 1)。记为 (dr_e, dc_e)。
   c. 擦除该窗口中的黄(4)和品红(6)标记像素（变为灰(5)）。
   d. 对于 D 中的每个偏移 (dr_i, dc_i)，计算目标像素位置 (r_m + dr_i + dr_e, c_m + dc_i + dc_e)。若该位置落在目标窗口的灰(5)区域内，则将该位置涂为蓝(1)；若超出窗口范围，则丢弃（不绘制）。
4. 精灵窗口保持原样不变。输出整个网格。

**关键洞察**：品红方向标记不编码目标窗口在布局中的位置（那是 a8c38be5 的用法），而是编码粘贴时的微小局部偏移。因为偏移仅 1 像素，差异非常细微——必须仔细对比多个目标窗口的输出才能发现图案整体偏移了 1 格，而非简单的标记点对齐。

## 新题 8：粒子路径模拟结果的频率柱状图

**组合逻辑**：[路径模拟+交替转向+颜色循环](原有) → [计数](创新：计数对象是模拟产生的轨迹像素而非输入像素) → [排序+柱状图](创新：模拟是中间过程而非最终输出)

**来源原语**：路径模拟(195c6913)、交替转向(195c6913)、碰撞停止(195c6913)、颜色循环(195c6913)、粒子(195c6913)、起始标记(195c6913)、计数(9af7a82c/b7999b51)、排序(9af7a82c)、柱状图(9af7a82c)、频率降序柱状图(9af7a82c)

**依赖链**：粒子从起始标记出发，按交替转向规则在网格中移动并用循环颜色绘制轨迹；轨迹完成后，统计每种循环颜色被绘制的像素数量；按数量降序排列为柱状图输出。去掉路径模拟则无轨迹可统计；去掉计数则无柱高；去掉排序则列序不确定。模拟的具体路径（取决于障碍布局和交替转向规则）完全决定了最终柱状图的形态。

粒子在障碍网格中做交替转向路径模拟，用循环颜色绘制轨迹，然后统计各颜色轨迹长度生成降序柱状图。

**输入结构**：约 15x15 黑(0)背景网格。网格左上角 2x2 区域有两个单色块，从左到右定义颜色循环序列（如左上蓝(1)、右上红(2)，表示循环为蓝→红→蓝→红...）。网格中有若干灰(5)障碍像素，分布在网格内部形成不规则的稀疏障碍场（单个像素或短线段，共 8-15 个灰像素）。有 1 个绿(3)起始标记像素，位于某条障碍物旁（与某个灰像素 4-邻接）。起始标记旁有一个黄(4)单像素表示初始运动方向（黄在绿的上方 → 初始向上；黄在下方 → 初始向下；黄在左 → 初始向左；黄在右 → 初始向右）。生成约束：粒子按规则运动时，轨迹长度至少 6 像素且会发生至少 3 次碰撞转向；各循环颜色被绘制的像素数互不相同。

**规则**：
1. 读取左上角 2x2 区域的颜色循环序列 C：C[0] = (0,0)处颜色，C[1] = (0,1)处颜色（若 2x2 区域有 4 个不同色块则循环长度为 4，按左上→右上→左下→右下的顺序读取；若只有上方一行有非黑色则循环长度为 2）。清除该 2x2 区域为黑(0)。
2. 找到绿(3)起始标记和黄(4)方向指示。粒子的起始位置为绿标记所在格，初始方向由黄像素相对于绿标记的方位确定。清除绿(3)和黄(4)像素。
3. 模拟粒子运动：
   a. 粒子从起始位置沿初始方向移动。维护碰撞计数器 n = 0 和颜色索引 idx = 0。
   b. 每步：将当前位置涂为 C[idx mod len(C)]，然后 idx += 1。尝试沿当前方向移动到下一格。
   c. 若下一格为灰(5)障碍或网格边界：n += 1。将当前位置涂为灰(5)（终止色覆盖循环色）。尝试转向 90 度——若 n 为奇数则向左转（逆时针），若 n 为偶数则向右转（顺时针）。
   d. 转向后检查新方向的下一格：若可行（非障碍、非边界、未被涂过），则沿新方向继续移动。若不可行，粒子停止。
4. 模拟结束后，统计网格中每种循环颜色 C[i] 被绘制的像素总数（不含被灰色覆盖的碰撞点）。
5. 构建输出柱状图：输出网格高度 = 最大像素数，宽度 = 循环颜色种类数。各颜色按像素数降序排列，每列从顶行开始向下填充对应颜色，填充高度等于该颜色的像素数，其余为黑(0)。

**关键洞察**：路径模拟不是最终输出——它是一个产生中间数据的"计算引擎"，其输出（各色轨迹长度）被压缩为柱状图。观察者在训练示例中看到的是输入障碍布局和输出柱状图，必须在脑中重建完整的粒子运动过程才能理解映射关系。交替转向规则使得轨迹路径高度依赖障碍布局的微小变化，仅靠一个示例很难确定转向规则的奇偶性。
