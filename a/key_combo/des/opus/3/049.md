## 新题 1：嵌套深度决定孤立像素的循环涂色

**组合逻辑**：[严格包含/strict_containment](用于计算嵌套深度而非确定颜色继承) + [计数/counting](逐像素计算包围层数) + [循环颜色分配/cyclic_color_assignment](以深度值驱动循环而非扫描序) + [擦除/erase](移除框架仅保留像素)

**来源原语**：严格包含、矩形边框（参考题 7d1f7ee8）；计数（参考题 ff28f65a）；循环颜色分配、孤立像素（参考题 9473c6fb）；擦除（参考题 9b365c51）

**依赖链**：矩形边框的包含关系为每个孤立像素产生一个嵌套深度值；该深度值取代扫描序位置，成为循环涂色的输入索引；框架移除后，仅深度-颜色映射信息保留在输出中，缺少框架则无法反推深度

[将散落在嵌套矩形框之间的孤立像素，按其被框架包围的层数循环涂色，然后移除所有框架]

**输入结构**：约 15x15 的网格，黑(0)为背景。3~5 个单色空心矩形边框（每个边框颜色互不相同，从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)中选取；每个边框是 4-连通单色矩形周长，宽度为 1 像素），部分矩形严格嵌套在其他矩形内部（即一个矩形的所有像素都严格位于另一个矩形边框围成的内部区域），也可能有矩形互不嵌套。橙(7)的孤立像素（每个为单独 1 像素，4-连通不与任何其他橙像素相邻）散布在框架之间的空隙中，总数 5~10 个。生成约束：孤立像素不位于任何矩形边框像素上；任意两个矩形要么严格嵌套要么完全不相交（不存在部分重叠）。

**规则**：
1. 识别所有单色矩形边框对象（每个矩形边框是一组 4-连通的同色像素，形成一个完整的矩形周长）。
2. 对每个橙(7)孤立像素，计算其嵌套深度 d：有多少个矩形边框的内部区域严格包含该像素（d 从 0 开始，不被任何框包围则 d=0，被 1 层包围则 d=1，以此类推）。
3. 按深度值 d 从小到大对所有孤立像素排序；同一深度内，按行优先扫描序（先行号小、再列号小）排序。
4. 按排序后的顺序，依次将每个孤立像素涂为红(2)、青(8)、灰(5) 的循环：第 1 个涂红(2)，第 2 个涂青(8)，第 3 个涂灰(5)，第 4 个涂红(2)，依此循环。
5. 移除所有矩形边框像素（设为黑(0)背景）。输出仅保留重涂色后的孤立像素和黑(0)背景，网格尺寸不变。

**关键洞察**：循环涂色的索引不来自像素的空间位置，而来自几何包含关系产生的深度值；框架在输出中被擦除，因此求解者必须先从输入的框架结构推断每个像素的深度，才能确定颜色。仅看单个示例无法区分"按深度排序"和"按行优先扫描序排序"——必须对比包含不同嵌套配置的多个示例才能归纳出深度优先的规则。

## 新题 2：分隔线方向分支决定平铺方向与倍数

**组合逻辑**：[全空行列检测/detect_empty_row_col](检测分隔线) → 条件分支 → [平铺/tiling](方向和重复数由分隔线方向决定) + [重涂色/recolor](分隔线在输出中变为绿(3))

**来源原语**：全空行列检测、分隔行列、包围框内部（参考题 da2b0fe3）；平铺、边长决定重复数（参考题 ccd554ac）；重涂色（参考题 da2b0fe3）

**依赖链**：分隔线的方向（水平/垂直）是一个隐式条件，它同时决定三件事——取哪个子区域作为平铺源、沿哪个方向平铺、以及重复次数等于子区域在该方向上的像素行/列数。分隔线检测、平铺方向选择、重复次数计算三者共享同一个检测结果

[找到前景包围框内的唯一空白分隔线，将分隔线一侧的子区域沿垂直于分隔线的方向平铺，重复次数等于子区域在平铺方向上的尺寸，分隔线本身涂绿]

**输入结构**：约 10x10 至 14x14 的网格，黑(0)为背景。一个由单色前景像素（蓝(1)或红(2)）组成的连通图案，其包围框内部恰好有一条完整的全背景行或全背景列（即该行/列在包围框范围内全为黑(0)）。该分隔线将包围框内的前景分为两个非空子区域。生成约束：包围框内恰好有一条这样的全空行或全空列，不会同时存在水平和垂直分隔线；两个子区域的前景图案不要求相同。

**规则**：
1. 计算所有非背景像素的包围框（最小包含矩形）。
2. 在包围框内找到唯一一条完全为黑(0)的行或列，记为分隔线 S。
3. 分隔线 S 将包围框内区域分为两个子区域 A 和 B（如果 S 是水平行，则 A 在上、B 在下；如果 S 是垂直列，则 A 在左、B 在右）。
4. 取子区域 A（靠近左上角的那个）作为平铺源瓦片 T。
5. 确定平铺方向：若 S 是水平行，则沿水平方向（向右）平铺；若 S 是垂直列，则沿垂直方向（向下）平铺。
6. 计算重复次数 N：T 在平铺方向上的像素长度（若水平平铺则 N = T 的列数；若垂直平铺则 N = T 的行数）。
7. 构造输出：将 T 沿平铺方向重复 N 次，相邻副本之间插入一列（水平平铺时）或一行（垂直平铺时）绿(3)分隔线。输出仅包含平铺结果和绿色分隔线，背景为黑(0)。

**关键洞察**：分隔线的方向是一个二值条件分支，它同时控制了"取哪块""往哪铺""铺几次"三个参数。仅从一个示例看，无法确定是"总是取上/左子区域"还是"取较小的子区域"——需要对比水平分隔和垂直分隔的不同示例才能归纳出"取靠近左上角的子区域"这一规则。

## 新题 3：碎片帧内标记连通体计数决定同心嵌套顺序

**组合逻辑**：[连通检测/connected_component_detection](识别标记连通体) + [计数/counting](统计每个帧内的标记体数量) + [排序/sorting](按计数而非边长排序) + [同心层填充/concentric_fill](按排序结果构建同心环)

**来源原语**：同心层填充、碎片帧、嵌套层次、按边长降序排列（参考题 c658a4bd）；连通检测、标记色连通体、指定面积筛选（参考题 2c0b0aff）；计数（参考题 ff28f65a）

**依赖链**：连通检测将标记像素聚类为对象 → 计数统计每个帧内的对象数量 → 排序用计数替代边长作为排序键 → 同心填充的层序由排序结果决定。删除计数步骤则排序无依据；删除连通检测则无法区分相邻标记点属于同一对象还是不同对象

[将散乱的碎片方形帧按其内部所含标记连通体数量排序，重建为居中同心方环]

**输入结构**：约 20x20 的网格，黑(0)为背景。4 个单色碎片方形帧（每帧颜色从蓝(1)、红(2)、黄(4)、品红(6)中选取），每帧是一个正方形边框的部分像素（因重叠或遮挡而有缺口，但其包围框的较长边仍反映原始边长）。各帧的原始边长互不相同（如 5、7、9、11）。绿(3)标记像素散布在各帧的包围框内部区域中，形成若干 4-连通连通体（每个连通体 2~5 像素），不同帧内的标记体数量互不相同（如分别有 1、2、3、4 个）。生成约束：绿(3)像素仅出现在某个帧的包围框严格内部区域，不与帧的边框像素重叠；每个绿(3)连通体完全位于一个帧的内部（不跨帧）。

**规则**：
1. 识别每个单色碎片帧，确定其原始边长 L（该颜色所有像素的包围框的较长边）。
2. 对每个帧，找出其包围框严格内部的所有绿(3)像素，用 4-连通连通检测将它们聚类为连通体，记数量为 C。
3. 按 C 从大到小排序各帧。若 C 相同（生成约束保证不会发生），以 L 较大者优先。
4. 创建正方形输出，边长等于所有帧中最大的 L。
5. 按排序顺序从外到内绘制居中同心方环：第一个帧（C 最大）绘制在最外层（边长 = 最大 L），第二个帧绘制在次外层（边长 = 第二大 L），依此类推。每层方环使用对应帧的颜色，仅绘制边框像素（厚度 1 像素）。内层覆盖外层的重叠像素。
6. 绿(3)标记像素不出现在输出中。

**关键洞察**：同心环的嵌套顺序不由帧的空间位置或边长大小决定，而由每个帧内包含的标记连通体数量决定。求解者必须先完成连通检测和计数，才能确定哪个颜色画在哪一层。仅看一个示例无法区分"按边长排序"和"按标记数排序"——需要一个标记数多但边长小的帧出现在外层，才能排除边长假说。

## 新题 4：镜像对称恢复遮挡区后执行宏单元格精灵替换

**组合逻辑**：[对称补全/symmetry_completion](恢复被遮挡的宏单元格) + [压缩/compress](将宏单元格网格压缩为粗模板) + [粗模板精细替换/coarse_to_fine_substitution](用控制精灵体替换填充位)

**来源原语**：对称补全、双轴镜像对称、实心标记矩形、遮挡由镜像恢复（参考题 67b4a34d）；压缩、网格分块、填充位出标记色（参考题 5ad4f10b）；控制精灵体、宏单元格模式、粗模板精细替换（参考题 5833af48）

**依赖链**：镜像对称恢复决定被遮挡区域包含哪些宏单元格 → 恢复后的完整网格才能正确压缩为粗模板 → 粗模板中的填充/空位决定哪些位置被控制精灵体替换。若跳过对称恢复，被遮挡区域的宏单元格状态未知，后续替换位置不确定

[先用双轴镜像对称恢复被灰色标记矩形遮挡的区域，再将恢复后的宏单元格网格中的每个填充位替换为控制精灵体的图案]

**输入结构**：约 18x18 的网格，黑(0)为背景。包含三个分离的前景区域：
- 控制精灵体：位于网格左上角区域，一个 3x3 的小矩形，由红(2)和青(8)像素组成（红(2)标记"空"、青(8)标记"有图案"）。
- 宏单元格网格：位于网格右侧，一个 12x12 的正方形区域（4x4 个 3x3 宏单元格紧密排列），每个宏单元格要么全为蓝(1)（表示"填充"），要么全为黑(0)背景（表示"空"）。整个 4x4 宏单元格模式具有水平和垂直镜像对称性，但其中一个 3x3 或 6x3 的矩形区域被灰(5)实心矩形覆盖。
- 生成约束：灰(5)矩形的位置和大小保证通过水平、垂直或 180 度镜像中至少一种方式，每个被遮挡像素的值可从其未被遮挡的镜像位置唯一确定。控制精灵体与宏单元格网格不重叠且不相邻。

**规则**：
1. 识别灰(5)实心矩形（该颜色仅以实心矩形形式出现）。
2. 对灰(5)矩形覆盖的每个像素，通过宏单元格网格的水平镜像、垂直镜像或 180 度旋转找到其未被遮挡的对应位置，将对应值（蓝(1)或黑(0)）复制回来。若多种镜像都给出值且一致，取任一即可（生成约束保证一致）。
3. 恢复后，将完整的 4x4 宏单元格网格压缩：每个 3x3 块若全为蓝(1)则标记为"填充"，否则标记为"空"。
4. 构造 12x12 输出（与宏单元格网格同尺寸）。对每个"填充"位，将控制精灵体的青(8)像素位置复制到输出对应的 3x3 块中（青(8)保持青(8)，红(2)位置填黑(0)）。对每个"空"位，该 3x3 块全为黑(0)。
5. 输出不包含控制精灵体本身和灰(5)矩形。

**关键洞察**：对称恢复和精灵替换共享同一个宏单元格网格结构——前者在宏单元格级别恢复被遮挡的填充/空状态，后者在像素级别用精灵体图案填充这些状态。跳过对称恢复则无法确定被遮挡宏单元格是"填充"还是"空"，替换结果不确定。

## 新题 5：路径生长轨迹的列段分组驱动调色板重涂色

**组合逻辑**：[路径生长/path_grow](从底行控制像素向上生长) + [障碍偏转/obstacle_deflection](遇障碍物右移) → [按列段分组匹配/column_run_group_match](将路径轨迹按垂直跨度分组为列段) → [顺序一一对应/order_correspondence](列段与调色板一一对应) + [重涂色/recolor](用调色板颜色替换路径颜色)

**来源原语**：路径生长、控制像素、障碍块、底行起始、逐步攀升、障碍偏转（参考题 712bf12e）；调色板列、目标列段、顺序一一对应、按列段分组匹配（参考题 9b365c51）；重涂色（参考题 9b365c51）

**依赖链**：路径在障碍物作用下产生不同的垂直跨度 → 相邻且垂直跨度相同的路径列被归为同一列段 → 列段数量必须与调色板列数量一致 → 每个列段被对应调色板颜色重涂。障碍物布局决定路径形态，路径形态决定列段分组，分组决定颜色分配——三层因果不可跳过

[从底行红色像素向上生长路径（遇灰色障碍则右移），将生长后的路径轨迹按垂直跨度分组为列段，用左侧调色板颜色依序替换各列段颜色]

**输入结构**：约 15x20 的网格（15 列、20 行），黑(0)为背景。
- 左侧调色板区：从第 0 列开始，K 条全高单色列（每列一种颜色，从蓝(1)、黄(4)、品红(6)、橙(7)中选取，K=3 或 4），相邻调色板列之间隔一列黑(0)背景。调色板区总宽度约为 2K-1 列。
- 调色板区右侧隔一列黑(0)背景后为路径区：
  - 底行（第 19 行）有若干红(2)控制像素，散布在路径区的不同列上。
  - 路径区上方散布着灰(5)障碍块（每个障碍块为 1~3 像素的水平连续段，位于不同行）。
- 生成约束：红(2)控制像素互不相邻；每条路径在生长过程中不会与另一条路径交叉或合并；路径生长完成后，路径区中所有路径列恰好可分为 K 个列段（每个列段是最大连续列组，组内各列的红(2)像素垂直跨度——从最低红像素行号到最高红像素行号——完全相同）。

**规则**：
1. 从每个红(2)控制像素出发，向上逐行生长路径：若正上方一格为黑(0)背景，将其涂红(2)并从该格继续向上；若正上方一格为灰(5)障碍，则在当前行向右一格，若该格为黑(0)背景则涂红(2)并从该新位置继续向上；若右移目标格不可用（超出网格、非背景、或已被占用），则该路径停止。
2. 路径生长完毕后，在路径区中逐列统计红(2)像素的垂直跨度（最高行号到最低行号的差值 +1；无红像素的列跨度视为 0）。
3. 将路径区的列从左到右扫描，将相邻且垂直跨度相同（且 >0）的列归为一个列段。跨度为 0 的列视为列段之间的天然分隔（不归入任何列段）。
4. 从左到右读取调色板列的颜色，与从左到右的列段一一对应。将每个列段内所有红(2)像素重涂为对应的调色板颜色。
5. 输出中移除调色板区（设为黑(0)）和灰(5)障碍块（设为黑(0)），仅保留重涂色后的路径轨迹和黑(0)背景。网格尺寸不变。

**关键洞察**：障碍物的空间布局间接控制了颜色分配——改变一个障碍物的位置可能改变某条路径的垂直跨度，导致该列从一个列段移入另一个列段，从而获得不同的调色板颜色。仅从一个示例无法确定分组依据是"垂直跨度"还是"红像素数量"——需要对比不同障碍布局的示例才能排除后者。

## 新题 6：压缩瓦片马赛克后识别循环移位并预测下一行

**组合逻辑**：[压缩/compress](将多像素瓦片压缩为单像素填充/空状态) + [循环移位/cyclic_shift](识别压缩后的行间循环左移模式) + [预测下一周期行/predict_next_cycle](推断下一行) + [填充位出标记色/filled_gets_marker](输出使用标记色)

**来源原语**：压缩、瓦片、网格分块、填充位出标记色（参考题 5ad4f10b）；循环移位、精灵网格、预测下一周期行（参考题 e78887d1）；列固定颜色（参考题 e78887d1，此处不使用——创新点之一）

**依赖链**：未压缩的原始瓦片在像素级别上看不出简单的循环移位模式（因为每个瓦片是多像素且形态各异）→ 压缩后才在粗粒度上暴露出行间循环左移 → 预测在压缩层面进行 → 输出需要将预测结果重新展开为瓦片大小并使用标记色填充。压缩是发现循环的前提，循环是预测的前提

[将大型彩色瓦片马赛克压缩为填充/空的粗网格，识别行间循环左移规律，预测下一行，用标记色输出预测的一行瓦片]

**输入结构**：约 16x12 的网格，黑(0)为背景。包含两种前景色：
- 瓦片色（蓝(1)）：形成 3 行 x 5 列的等大正方形瓦片阵列（每个瓦片 3x3 像素），相邻瓦片行之间隔一行黑(0)背景，相邻瓦片列之间隔一列黑(0)背景。整个阵列占据网格上方区域。每个瓦片位置要么全为蓝(1)（"填充"），要么全为黑(0)（"空"）。
- 标记色（红(2)）：在网格下方散布少量红(2)噪声像素（总共 3~5 个，不构成有意义的图案）。
- 粗网格的 3 行填充/空模式具有循环左移关系：第 2 行是第 1 行循环左移 1 位，第 3 行是第 2 行循环左移 1 位。
- 生成约束：每行至少有一个"填充"位和一个"空"位。

**规则**：
1. 识别瓦片色（占据面积较大的前景色）和标记色（像素数较少的前景色）。
2. 将瓦片阵列压缩为 3x5 的二值粗网格（每个 3x3 块若全为瓦片色则为 1，否则为 0）。
3. 识别行间模式：粗网格第 k+1 行是第 k 行循环左移 1 位。
4. 预测第 4 行：将第 3 行循环左移 1 位得到预测行。
5. 输出为 1 行 x 5 列的瓦片行（3x(5*3+4) = 3x19 的像素网格）：对预测行中的每个"填充"位，输出对应的 3x3 块全为标记色（红(2)）；"空"位输出黑(0)；相邻瓦片之间插入一列黑(0)分隔。

**关键洞察**：原始瓦片的多像素结构掩盖了循环移位规律——在像素级别观察，每行瓦片只是一些散乱的蓝色方块。只有压缩到粗网格才能看到简洁的循环左移。此外，输出使用的是标记色而非瓦片色——散布的红色噪声像素看似无关，实际上暗示了输出应使用的颜色。

## 新题 7：主对角线转置揭示行组前缀模式以进行外推补全

**组合逻辑**：[镜像(沿主对角线转置)/diag_transpose](揭示隐藏的行组结构) → [前缀匹配/prefix_matching](识别下方行组为上方完整模式的前缀) → [外推/extrapolate](用蓝色续写缺失部分) → [镜像(逆转置)/diag_transpose](将结果转回原始方向)

**来源原语**：镜像/沿主对角线转置（参考题 74dd1130）；前缀匹配、外推、行组、列状态序列、完整模式续写缺失（参考题 90f3ed37）；补全（参考题 90f3ed37）

**依赖链**：原始方向上行组看不出前缀关系（模式在列方向上呈现，而非行方向）→ 转置后行列互换，前缀匹配模式才变得可见 → 在转置空间中完成外推 → 逆转置还原。跳过转置则无法发现前缀规律，跳过逆转置则输出方向错误

[输入的行组前缀模式隐藏在列方向中，需先沿主对角线转置使其变为行方向，完成外推补全后再转置回去]

**输入结构**：一个 N x N 的正方形网格（N 约 12~15），黑(0)为背景。
- 网格中有若干由黄(4)像素组成的前景图案。
- 直接观察行（水平方向）：各行的黄(4)像素分布看不出明显的前缀/续写关系。
- 但若将网格沿主对角线转置（行列互换），则转置后的网格呈现出如下结构：
  - 转置后的各列由黑(0)背景行分隔为若干行组。
  - 最上方的行组横跨所有列，形成完整的列状态参考模式（每列或有前景或无前景，构成一个二值序列）。
  - 下方的行组从左列开始，是上方完整模式的逐渐缩短的前缀（即只覆盖前若干列，右侧列缺失）。
- 生成约束：转置后的行组分隔行全为黑(0)；每个下方行组的列状态序列是上方完整行组的一个严格前缀（压缩后的列状态序列一致）。

**规则**：
1. 将整个 N x N 网格沿主对角线转置：像素 (r, c) 移动到 (c, r)。
2. 在转置后的网格中，识别由全黑(0)行分隔的行组。最上方行组为完整参考模式 P。
3. 对每个下方行组，其已有的列状态序列是 P 的前缀。将 P 中剩余的列状态用蓝(1)续写到该行组中：对缺失的每一列，若 P 在该列有前景则填蓝(1)，否则留黑(0)。保留行组中原有的黄(4)像素不变。
4. 将补全后的转置网格再次沿主对角线转置（即逆转置），恢复原始方向。
5. 输出为逆转置后的 N x N 网格。

**关键洞察**：前缀续写模式藏在网格的列方向中——直接读行看到的是无规律的图案。求解者必须先发现转置操作（通过对比多个示例中行读与列读的规律性差异），在转置空间中完成补全，再转置回来。单个示例中无法区分"按行读"和"按列读"两种假说，必须对比多个示例。

## 新题 8：按循环移位一致性筛选并裁剪正确的精灵格区域

**组合逻辑**：[连通检测/connected_component_detection](分离各矩形区域) + [循环移位/cyclic_shift + 预测下一周期行/predict_next_cycle](验证每个区域内的精灵格是否满足循环移位规律) → [裁剪/crop + 最大计数选择 → 一致性筛选](选出唯一满足条件的区域并裁剪输出)

**来源原语**：裁剪、矩形区域、连通检测（参考题 2c0b0aff）；循环移位、精灵网格、预测下一周期行、列固定颜色（参考题 e78887d1）；指定面积筛选→替换为一致性筛选（创新：筛选条件从"面积=5 的连通体最多"变为"循环移位模式一致"）

**依赖链**：必须先分离各个矩形区域 → 对每个区域内部独立检验循环移位一致性 → 只有通过验证的区域被选中裁剪输出。循环模式验证不是输出变换，而是选择判据——它决定"输出什么"而非"怎么变换"

[从多个被边界色分隔的矩形区域中，找出内部精灵格满足循环左移规律的唯一区域，将其原样裁剪输出]

**输入结构**：约 20x25 的网格，灰(5)为边界背景色，填满整个网格底色。网格被灰(5)行列分隔为 3~4 个大小近似的矩形前景区域（每个区域约 6x10 至 8x12）。每个矩形区域内部：
- 有一种主填充色（从蓝(1)、红(2)、黄(4)、绿(3)中选取，各区域不同）作为该区域的背景。
- 区域内部包含一个 3xM 的精灵格（M=3 或 4）：精灵行之间隔一行该区域的主填充色，精灵列之间隔一列该区域的主填充色。每个精灵为 3x3 像素，由该区域的主填充色和橙(7)像素组成（橙(7)构成精灵的前景图案，主填充色为精灵内的背景）。
- 在恰好一个区域中，精灵格满足循环移位规律：忽略颜色只看 3x3 二值掩模时，每一精灵行是上一精灵行循环左移一个精灵位的结果。
- 在其他区域中，精灵格的行间关系不满足循环左移（可能是随机排列、镜像、或其他非循环变换）。
- 生成约束：恰好有一个区域满足循环移位；各区域的精灵数量和尺寸相同，无法通过大小区分。

**规则**：
1. 识别灰(5)边界背景，将网格分离为若干矩形前景区域。
2. 对每个区域，定位其内部的精灵格。将每个 3x3 精灵转化为二值掩模（橙(7)=1，主填充色=0）。
3. 检验循环移位一致性：对每对相邻精灵行（第 k 行和第 k+1 行），忽略颜色，检查第 k+1 行的掩模序列是否是第 k 行的掩模序列循环左移 1 位。所有相邻行对都满足则该区域通过验证。
4. 裁剪通过验证的唯一区域（不含外围灰(5)边界），原样输出（保留该区域的主填充色和橙(7)精灵图案）。

**关键洞察**：选择哪个区域裁剪输出不取决于任何几何属性（面积、位置、颜色数量），而取决于区域内部是否满足一个抽象的组合模式（循环左移）。求解者必须理解循环移位规则本身才能做出正确选择。仅看单个示例可能偶然猜对选择（如"选最左边的区域"），但多个示例中正确区域的位置会变化，迫使求解者发现真正的筛选条件。
