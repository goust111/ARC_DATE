## 新题 1：枢轴旋转后重力沉降

**组合逻辑**：[旋转(rotate)](已有) + [重力下落(gravity_drop)](已有) + [碰撞阻挡(collision_blocking)](已有) → 创新：旋转结果重塑碰撞拓扑，沉降格局完全依赖旋转后的新空间布局

**来源原语**：旋转(rotate)、枢轴像素(pivot_pixel)、同行或同列(same_row_or_col)、距离保持不变(distance_preserved) ← 1a244afd；滑动(slide)、重力下落(gravity_drop)、连通分量(connected_component)、碰撞阻挡(collision_blocking)、重力远近序处理(gravity_far_to_near) ← 5ffb2104

**依赖链**：旋转改变每个对象的空间坐标 → 新坐标重新定义对象之间的垂直遮挡关系 → 最底部对象先沉降形成障碍 → 上方对象依高度序沉降，碰撞格局完全由旋转结果决定

将每个小图形绕其配对枢轴旋转90度后，所有图形在向下重力作用下沉降至互相阻挡或触底。

**输入结构**：
- 黑(0)背景，约12x12网格。
- 蓝(1)像素为枢轴点，共2~3个，散布于网格中部偏上区域，彼此不在同行同列。
- 其他前景色（红(2)、绿(3)、黄(4)等）各形成一个4-连通单色小图形（3~5像素），共2~3个，形态不固定（不规则连通块，非特定几何形状）。
- 每个小图形恰好有一个蓝(1)枢轴在其同行或同列上（一对一配对），配对距离为1~3格。
- 生成约束：各图形互不接触；旋转后所有像素仍在网格范围内；旋转后各图形不重叠。

**规则**：
1. 将每个前景小图形绕其配对的蓝(1)枢轴逆时针旋转90度。旋转保持每个像素到枢轴的距离不变，偏移向量 (dr, dc) 变为 (-dc, dr)。
2. 擦除所有前景小图形在原位置的像素（设为黑(0)）。蓝(1)枢轴保留在原位不动。
3. 在新位置绘制旋转后的图形，保留原色。
4. 对所有旋转后的图形施加向下重力：按各图形边界框底边行号从大到小排序（最低者最先处理），每个图形整体逐行下移，直至其任何像素的正下方一行被已沉降的图形像素或网格底边阻挡，则停止。
5. 蓝(1)枢轴在重力阶段不移动，也不构成障碍。

**关键洞察**：旋转改变了各图形的相对高度和水平投影重叠关系，因此重力阶段的碰撞格局完全取决于旋转结果——跳过旋转直接做重力无法得到正确输出，且不同示例中枢轴位置不同导致碰撞拓扑截然不同。

## 新题 2：包围框检测驱动的上下分色

**组合逻辑**：[包围框包含(bbox_containment)](已有) + [重涂色/等分(recolor/equal_split)](已有) → 创新：包含关系不删除目标而是触发上下分色，且分色的目标颜色取自包含者

**来源原语**：包围框包含(bbox_containment)、异色包含则删(delete_if_contained_by_other_color)、连通分量(connected_component)、包围框(bounding_box) ← 9720b24f；重涂色(recolor)、等分(equal_split)、下半变色(lower_half_recolored) ← ce9e57f2

**依赖链**：计算所有对象的包围框 → 检测包围框包含关系（被谁包含）→ 包含关系决定哪些对象需要变换 → 包含者的颜色决定下半重涂的目标色 → 对被包含对象执行上下等分重涂

找出被更大异色对象包围框包含的小对象，将其上半保留原色、下半重涂为包含者的颜色。

**输入结构**：
- 黑(0)背景，约14x14网格。
- 前景有3~4种颜色（如红(2)、绿(3)、蓝(1)、黄(4)），每种颜色形成1~2个8-连通单色对象。
- 较大对象（约10~20像素）呈开口形态（如U形、C形、弧形等不规则开口结构），在空间上松散环绕较小的异色对象（3~6像素的不规则连通块）。
- 较小对象的最小包围框严格包含在较大对象的最小包围框内。
- 生成约束：不存在多层嵌套（每个小对象至多被一个大对象包含）；未被包含的对象不包围任何其他对象。

**规则**：
1. 找出所有8-连通单色非黑对象，计算每个对象的最小包围框。
2. 若对象A的包围框严格包含在另一异色对象B的包围框内，且B的像素数多于A，则标记A为"被包含对象"，B为A的"包含者"。
3. 对每个被包含对象A：以A的包围框高度 h 为准，上半 ceil(h/2) 行中属于A的像素保留A的原色，下半 floor(h/2) 行中属于A的像素重涂为其包含者B的颜色。
4. 所有未被包含的对象（含包含者自身）保持不变。

**关键洞察**：包围框包含关系同时承担两个角色——它既决定哪些对象被变换（选择功能），又通过包含者的颜色决定变换使用的目标颜色（参数功能）。必须先识别包含关系才能确定重涂颜色，二者不可分离。

## 新题 3：射线寻靶对接

**组合逻辑**：[射线延伸(ray_extend)](已有，改为向下对角) + [对接(dock)](已有，改为射线定靶) + [色彩互换(color_swap)](已有) + [障碍偏转绕行(obstacle_deflection)](已有) → 创新：对接目标由射线空间路径决定而非颜色匹配

**来源原语**：射线延伸(ray_extend)、障碍偏转绕行(obstacle_deflection)、障碍块(blocker)、源像素(source_pixel)、对角方向(diagonal_direction) ← 69889d6e；对接(dock)、色彩互换(color_swap)、双色精灵体(two_tone_sprite)、色条(color_bar)、颜色反转映射(inverted_color_mapping) ← 7c66cb00

**依赖链**：从每个精灵体发射对角射线 → 射线遇障碍偏转（向外平移）→ 射线命中的色条即对接目标 → 将精灵体移至色条上方并执行颜色互换

每个双色精灵体向下发射对角射线，射线绕过障碍后命中的色条即为对接目标，对接时内外色互换。

**输入结构**：
- 黑(0)背景，约16x20网格。
- 上半区（前5行内）：2~3个双色精灵体，每个约3x3大小，由外圈色（占8像素环绕）和内核色（中心1像素）组成。各精灵体外圈色互不相同。
- 中部区域：散布5~8个灰(5)障碍像素，不与精灵体或色条直接相邻。
- 下半区（后4行内）：2~3条水平色条，每条为一整行中的连续色段（约8~12像素长），具有填充色和两端各1像素的边界色。色条数等于精灵体数。各色条填充色互不相同。
- 生成约束：每个精灵体的射线最终恰好命中不同的色条（一对一对接）。

**规则**：
1. 从每个精灵体的底部中心像素向左下方发射2像素宽的对角射线：每下移一行，射线带（水平连续的2个像素）左移一列。
2. 若射线带在某行的两个位置中有任何一个与灰(5)障碍重叠，则该行及后续行的射线带整体右移1列，重复检测直到带内两个像素都不与障碍重叠。
3. 射线到达某条色条所在行时停止，该色条即为此精灵体的对接目标。
4. 擦除射线路径上的所有临时像素和原始精灵体。
5. 将精灵体放置到目标色条的正上方，水平位置以射线停止时的带中心列对齐。放置时执行颜色互换：精灵体外圈色变为目标色条的边界色，内核色变为目标色条的填充色。

**关键洞察**：对接目标不由颜色匹配决定，而由射线的空间路径决定——障碍位置改变射线轨迹，从而改变精灵体与色条的配对关系，同一组精灵体和色条在不同障碍布局下可能产生完全不同的对接结果。

## 新题 4：封闭区域计数驱动角落印章

**组合逻辑**：[洪泛填充(flood_fill)](已有，用于识别封闭区域) + [计数(counting)](已有) + [印章覆盖(stamp_overlay)](已有) → 创新：计数结果选择印章数量，多数色决定印章颜色，三步紧耦合

**来源原语**：洪泛填充(flood_fill)、封闭区域(enclosed_region)、轮廓框(outline_frame)、标记像素(marker_pixel)、标记在封闭区域内(marker_in_enclosed_region)、多数色决定填充(majority_color_fill)、忽略干扰项(ignore_distractors) ← 4b6b68e5；计数(counting) ← c8b7cc0f/27a28665；印章覆盖(stamp_overlay)、角落标记(corner_marker)、角落位置选模板(corner_selects)、标记色传递给模板(marker_color_pass) ← fd02da9e

**依赖链**：洪泛填充识别封闭内部 → 区分有效标记与框外干扰 → 计数有效标记总数N → N决定激活前N个角落 → 多数标记色C决定印章颜色

计数封闭轮廓内的标记像素总数决定激活哪几个角落印章，印章颜色取自区域内的多数标记色。

**输入结构**：
- 黑(0)背景，约10x10网格。
- 灰(5)像素构成一个封闭的单像素宽轮廓框，位于网格中部（形状不固定，可能为矩形或不规则多边形封闭环，4-连通闭合，面积约占网格1/4~1/3）。
- 轮廓框内部散布1~4个标记像素，颜色来自红(2)、绿(3)、蓝(1)中的若干种。生成约束：其中一种颜色的标记数量严格多于其他任何一种。
- 网格的四个角落像素（(0,0)、(0,W-1)、(H-1,0)、(H-1,W-1)）各放置一个橙(7)占位符像素。
- 轮廓框外部、非角落位置可能有1~2个与框内标记同色的干扰标记像素。

**规则**：
1. 通过洪泛填充识别灰(5)轮廓框围成的封闭区域：从轮廓框的包围框边界向内做4-连通背景色洪泛填充，未被填充到的、非灰(5)像素所在的区域即为封闭内部。
2. 计数封闭区域内（不含轮廓框本身）的非黑、非灰标记像素总数 N。框外的同色像素为干扰项，不计入。
3. 确定封闭区域内出现次数最多的标记颜色 C。
4. 按阅读顺序（左上→右上→左下→右下）激活前 min(N, 4) 个角落。
5. 擦除所有橙(7)占位符、所有标记像素（框内和框外的干扰项均擦除）。灰(5)轮廓框保留。
6. 对每个激活的角落，放置一个2x2纯色方块，颜色为 C，方块位于角落向网格内部偏移1格的位置：左上角方块占 (1,1)~(2,2)，右上角占 (1,W-3)~(2,W-2)，左下角占 (H-3,H-1-1)~(H-2,1)即(H-3,1)~(H-2,2)，右下角占 (H-3,W-3)~(H-2,W-2)。
7. 未激活的角落保持为背景色黑(0)。

**关键洞察**：需要三步紧耦合推理——先识别封闭区域才能区分有效标记与干扰项，再计数才能决定激活几个角，最后用多数色涂印章。跳过任一步都无法得到正确输出：不识别区域则干扰项干扰计数，不计数则不知几个角激活，不判多数色则印章颜色不定。

## 新题 5：栅格遮罩下的投影路径

**组合逻辑**：[网格线绘制(grid_line_drawing)](已有) + [投影/连线(project/draw_path)](已有) + [裁剪(crop)](已有) → 创新：栅格线不是最终产物而是路径的可见性遮罩，投影路径被栅格分割为间断点阵

**来源原语**：网格线绘制(grid_line_drawing)、行列索引奇偶性(row_column_index_parity)、方阵(square_grid)、网格线(grid_line) ← 332efdb3；连线(draw_path)、裁剪(crop)、投影(project)、边框矩形(framed_rectangle)、外部色迹(external_color_trace)、接触点映射(touch_point_mapping) ← a6f40cea

**依赖链**：裁剪到边框内部 → 在内部按奇偶规则绘制栅格线 → 将外部色迹触碰点映射到内部坐标 → 画曼哈顿路径 → 路径只在栅格"空白格"上可见，栅格线位置被遮罩

在矩形框内部先画栅格线，再投影外部色迹为曼哈顿路径，路径被栅格线遮罩为间断点阵。

**输入结构**：
- 灰(5)背景，约15x15网格。
- 蓝(1)像素构成一个单像素宽的矩形边框，框内填充灰(5)。内部区域至少7x7（保证栅格有足够空间）。
- 边框外侧有2~3组彩色像素（红(2)、绿(3)、黄(4)等），每组由2~4个同色像素组成，紧贴边框外壁排列。
- 每组色迹的像素触碰边框的不同边（如一组的两个端点分别触碰上边和右边）。各组颜色互不相同。
- 生成约束：各组色迹两两无共享边。

**规则**：
1. 输出为边框内部区域（不含蓝(1)边框本身），尺寸为内部高 x 内部宽。
2. 以内部区域左上角为 (0,0) 原点，将所有行索引或列索引为偶数的像素涂为栗(9)，形成周期-2栅格线。行列索引均为奇数的像素保持灰(5)背景（即"空白格"）。
3. 对每组外部色迹，找出其触碰蓝(1)边框的接触点，将接触点的行/列映射到内部坐标系（接触点在边框第几行就映射到内部第几行，列同理）。
4. 对每组色迹，在其两个映射端点之间画最短曼哈顿路径（先沿水平方向移动至目标列，再沿垂直方向移动至目标行）。
5. 路径仅在"空白格"（行索引和列索引均为奇数的位置）上可见，以该组颜色绘制。路径经过栅格线位置（行或列索引为偶数）的部分不绘制——该位置保持栗(9)。
6. 若多条路径的空白格位置重叠，按颜色编号从小到大依次处理，后处理的覆盖先处理的。

**关键洞察**：栅格线不是装饰而是功能性遮罩——它将连续曼哈顿路径分割为间断点阵。求解者必须同时理解栅格的奇偶规则和路径的投影规则，才能判断哪些格子最终有颜色、哪些被栅格遮蔽。

## 新题 6：平铺补全后滑动压紧

**组合逻辑**：[平铺/补全(tile/complete)](已有) + [滑动(slide)](已有) → 创新：平铺产生的新内容成为滑动的操作对象，障碍将对称图案打散为非对称分布

**来源原语**：平铺(tile)、补全(complete)、平移对称(translational_symmetry)、平移周期图案(translation_pattern)、相位偏移(phase_shift) ← caa06a1f；滑动(slide)、可移动行程(movable_run)、固定障碍(fixed_barrier)、靠近障碍停止(stop_at_barrier)、同行阻挡(same_row_blocking) ← 9c56f360

**依赖链**：检测左半部分图案的平移周期 → 向右补全平铺至覆盖全网格 → 区分原始像素与新增像素 → 每行中新增像素段向左滑动至碰到障碍或原始像素停止

- 黑(0)背景，约12x15网格（12行15列）。

**规则**：
1. 从左半部分的红(2)像素中检测水平平移周期 T（使整个红色图案沿水平方向每 T 列重复一次的最小正整数）。
2. 用该周期将红(2)图案向右补全平铺至覆盖整个网格宽度。若补全的红(2)像素与绿(3)障碍重叠，该位置保留绿(3)（障碍不被覆盖）。
3. 对每行独立处理：将该行中因补全而新增的红(2)像素（即原始输入中不存在、仅因平铺而产生的像素）视为可移动行程。同一行内可能有多段不连续的可移动行程。
4. 对每行的每个可移动行程，整体向左滑动，直到其最左像素的左侧紧邻该行中最近的固定元素（绿(3)障碍像素或原始红(2)像素），或到达第0列。多段行程按从左到右顺序依次处理，先滑动的行程滑动完成后成为后续行程的障碍。
5. 绿(3)障碍和原始左半部分的红(2)像素位置不变。

**关键洞察**：平铺补全决定每行产生多少新像素及其初始位置，而障碍的行内分布决定这些新像素的最终停靠点——两个逻辑在每行交织：不做补全则无内容可滑动，不考虑障碍则无法确定停靠位置。同一周期图案在不同障碍布局下产生截然不同的非对称输出。

补全小网格中的缺失像素，使其经边缘扩展后恰好形成完美的平移对称图案。

2. 对补全后的4x4网格执行边缘扩展：在四周各扩展一层像素，得到6x6网格。上边缘行复制为新的第0行，下边缘行复制为新的第5行，左边缘列复制为新的第0列，右边缘列复制为新的第5列。四个角像素向两个方向扩展形成2x2角块。

## 新题 8：图例种子的计数倍增

**组合逻辑**：[像素放大(pixel_upscale)](已有，改为可变倍率) + [计数(counting)](已有) + [填充图例(populate_legend)](已有，改为放大种子) → 创新：对象计数不产生点序列而是作为放大倍率参数，颠覆"计数→点阵"的固有模式

**输入结构**：
- 黑(0)背景，约18x18网格。
- 右侧有一个灰(5)单像素宽矩形图例框，内部填充黑(0)，约占网格右侧6列、高度覆盖全网格高度。
- 图例框内最左非黑列有2~3个颜色键像素（如红(2)、绿(3)、蓝(1)），垂直间距至少5行（保证放大后有空间）。
- 每个颜色键像素的正右方紧邻一个同色种子图案，种子为1x1或2x1（水平排列的1~2个像素）。
- 网格左侧（图例框外）散布着与颜色键对应的前景对象：每色1~3个独立的4-连通单色图形（每个3~8像素的不规则连通块），各对象互不相邻。
- 生成约束：每色对象数N满足 1 <= N <= 3；放大后的种子（NxN或Nx2N）不超出图例框内部空间。

**规则**：
1. 对每种颜色键，计数图例框外该颜色的独立4-连通对象数量 N。
2. 提取图例框内该颜色键旁的种子图案（键像素正右方紧邻的同色连续像素块）。
3. 将种子图案按 N 倍像素放大：种子中每个像素变为 NxN 的纯色方块。
4. 将放大后的图案写入图例框内部，起始位置为键像素所在行、键像素右侧第2列。放大后的图案向右和向下扩展。

6. 擦除原始种子图案（放大前的1~2像素）。颜色键像素保留。
7. 图例框外的所有对象和图例框本身保持不变。

**关键洞察**：计数不是产生点序列（如1个对象→1个点），而是决定几何变换的倍率参数（1个对象→1倍放大即不变，3个对象→3倍放大即每像素变9像素）。同一种子在不同示例中因对象数量不同而产生截然不同的输出尺寸，必须对比多个示例才能发现"计数=倍率"这一隐蔽规则。

## 新题 9：墙壁门径与滑动锚点

**组合逻辑**：[寻路/连线(pathfinding/draw_path)](已有) + [滑动(slide)](已有) → 创新：滑动后的停靠位置成为路径的强制锚点，滑动结果重塑路径几何

**依赖链**：走廊中的彩色段向下方墙壁滑动 → 停靠位置确定路径的必经锚点列 → 连线穿越门中心并经过锚点列 → 路径在每段走廊中取该走廊色段颜色

- 黑(0)背景，约12x18网格。

- 每道墙壁有一个3像素宽的门段（门段为黑(0)间隙），各墙壁的门段位置不同。
- 最上走廊和最下走廊各有一个橙(7)标记像素（路径的起止点），位于走廊内任意位置。
- 中间走廊各有一个彩色水平行程（红(2)或绿(3)，2~4像素长的连续水平色段），位于走廊中部偏上，不紧贴任何墙壁。
- 生成约束：每条走廊最多一个色段；各色段水平位置与门段中心列不相同。

**规则**：
1. 对每条中间走廊的彩色行程：整体向下滑动（保持水平位置不变），直到行程的底边像素紧贴该走廊下方墙壁（若走廊下方是网格底边则贴底边）。
2. 以最上走廊的橙(7)标记为起点、最下走廊的橙(7)标记为终点，画一条正交路径依次穿越所有门中心，从上向下逐层推进。

**关键洞察**：色段滑动后的停靠列成为路径的强制锚点，改变了路径的水平走向——不同示例中色段的初始位置不同，滑动后锚点不同，路径形状随之改变。跳过滑动则锚点未定，路径无法确定。

## 新题 10：反对角线修复与包含擦除

**组合逻辑**：[填充/infill(infill)](已有) + [擦除(erase)](已有) + [反对角线等值(anti_diagonal_equivalence)](已有) + [包围框包含(bbox_containment)](已有) → 创新：空洞修复改变包围框大小从而改变包含判定结果，两步之间有隐式因果

**来源原语**：填充(infill)、反对角线等值(anti_diagonal_equivalence)、遮挡空洞(occlusion_hole)、边框层(frame_layer)、分区结构约束(partitioned_structure_constraint) ← 4aab4007；擦除(erase)、包围框包含(bbox_containment)、连通分量(connected_component)、包围框(bounding_box)、异色包含则删(delete_if_contained_by_other_color) ← 9720b24f

**依赖链**：黑色空洞使对象断裂、包围框偏小 → 反对角线等值规则修复空洞恢复完整对象 → 修复后重新计算包围框 → 检测包含关系 → 擦除被包含的对象

先用反对角线等值规则填补遮挡空洞恢复完整图案，然后擦除被更大异色对象包围框包含的小对象。

**输入结构**：
- 黑(0)背景，约14x14网格。
- 有2种前景色（如红(2)和蓝(1)），每种颜色形成2~4个8-连通单色对象，大小从3像素到20像素不等。
- 部分对象被黑(0)像素遮挡（1~3个空洞像素散布在对象内部），破坏了对象的完整形态，可能将一个对象断裂为多个碎片。
- 可见的（非遮挡的）前景像素满足反对角线等值性质：同一条反对角线（row+col=常数）上所有可见的非黑像素颜色相同。
- 生成约束：至少一个小对象（完整形态3~5像素）的某些像素被遮挡，使得修复前该对象的包围框不被任何大对象包围框包含，但修复后扩大的包围框被包含。这确保修复步骤对最终结果有实质影响。

**规则**：
1. 对每个黑(0)像素，检查其所在反对角线（row+col=常数）上所有非黑像素的颜色。若该反对角线上有且仅有一种非黑颜色，则该黑像素为遮挡空洞，填充为该颜色。若该反对角线上无非黑像素或有多种非黑颜色，则该黑像素为真实背景，不填充。
2. 在修复后的网格上，找出所有8-连通单色非黑对象，计算每个对象的最小包围框和像素数。
3. 若对象A的包围框严格包含在另一异色对象B的包围框内，且B的像素数大于A，则擦除A（将A的所有像素设为黑(0)）。
4. 所有未被擦除的对象保持修复后的状态。

**关键洞察**：空洞修复和包含擦除之间存在隐式因果——未修复的空洞可能使对象断裂导致包围框缩小，从而逃过包含检测。必须先修复再判断包含，且求解者需要对比多个示例才能发现这一顺序依赖：某些"碎片"修复后合并为一个对象，其扩大的包围框恰好落入另一对象的包围框内。
