## 新题 1：对角朝向投票决定滑动轴

**组合逻辑**：[分类/classify](已有) + [对角朝向/diagonal_orientation](已有) → 全局轴向参数(创新：朝向多数票决定另一组对象的运动轴) → [滑动/sliding](已有) + [同色配对/same_color_pairing](已有) + [擦除/erase](已有) + [重涂色/recolor](已有)

**来源原语**：分类、对角朝向、多数朝向决定色 (参考题 #17 1d61978c)；滑动、孤立像素、满行列条、同色配对、无匹配色则删除 (参考题 #6 1a07d186)；重涂色 (参考题 #17)

**依赖链**：对角线段的朝向分类结果（多数方为何）决定了一个全局参数——孤立像素的滑动轴向；滑动轴向与满行列条的朝向交互决定哪些像素能到达匹配色条、哪些被删除；分类结果同时也触发对角线段本身的重涂色。三个子系统（对角线段、孤立像素、满行列条）通过全局轴向参数耦合为一体。

对角线段的朝向多数票决定孤立像素向哪个轴滑动，从而选择性地与满行列条配对或被删除。

**输入结构**：约 12x12 网格，黑(0)背景。灰(5)前景像素形成若干单像素宽的对角线段（每段 2-5 像素，沿 NW-SE 或 NE-SW 方向排列，各段之间不相邻）。另有 3-6 个孤立单像素，颜色各异（从蓝(1)、红(2)、绿(3)、黄(4)中取），散布在网格内部。还有 2-3 条满行列条（各跨满网格全宽或全高、单像素厚、单色，颜色从上述孤立像素的颜色中取），其中至少一条水平、至少一条垂直。生成约束：两种对角朝向的像素数不相等；每个孤立像素的颜色至少对应一条满行列条。

**规则**：
1. 将所有灰(5)对角线段像素按对角邻居连通方向分类为 NW-SE 组或 NE-SW 组。判断方法：若该像素的左上(NW)或右下(SE)方向存在同色对角邻居，则属于 NW-SE 组；若右上(NE)或左下(SW)方向存在同色对角邻居，则属于 NE-SW 组。
2. 统计两组像素数。将多数组像素重涂为青(8)，少数组像素重涂为红(2)。
3. 确定全局滑动方向：若多数组为 NW-SE，则所有孤立像素向下滑动；若多数组为 NE-SW，则所有孤立像素向右滑动。
4. 每个孤立像素沿确定的方向滑动，直到与同色的满行列条相邻（紧贴条的近侧）时停止。若路径上先遇到另一个已结算的像素，则紧贴该像素停止。滑动过程中跳过对角线段像素（对角线段不阻挡滑动）。
5. 若孤立像素沿滑动方向直到网格边缘都未遇到同色满行列条，则该像素被删除（设为背景）。
6. 所有满行列条保持原样不变。

**关键洞察**：对角线段不是被动的涂色对象——它们的朝向统计结果是一个全局开关，决定了一组完全不同的元素（孤立像素）的运动物理学。不同示例中对角朝向的多数方可能不同，导致滑动轴翻转，从而使同一组孤立像素产生完全不同的结算位置和存活集合。

## 新题 2：极值条高度驱动柱状频率匹配

**组合逻辑**：[排序/sorting](已有) + [保留极值高度分色/keep_extremes_and_recolor](已有) → 高度值提取(创新：极值条高度成为频率目标数) → [频率匹配/frequency_matching](已有) + [柱状填充/histogram_fill](已有)

**来源原语**：排序、竖直线段、高度排名、保留极值高度分色 (参考题 #10 a61f2674)；计数、频率匹配、柱状填充、分隔行、编码行、频率等于标记数 (参考题 #7 2685904e)

**依赖链**：竖直条高度排名筛出最高和最矮两根条，它们的像素高度 H_tall 和 H_short 被提取为数值参数；这两个参数分别作为频率匹配的目标值，在编码行中寻找出现次数恰好等于该值的颜色；命中的列位置和极值条的指定颜色共同决定柱状图的绘制位置和颜色。没有排序步就没有频率目标；没有频率匹配就不知道在哪些列画柱。

竖直条的极值高度成为柱状频率匹配的目标数，将空间排名与统计计数桥接为一体。

**输入结构**：约 14x14 网格，黑(0)背景。上半区：5-7 根灰(5)竖直条，各 1 列宽，高度各不相同（3-10 像素），底端对齐于分隔行上方的同一行，各条之间至少隔 1 列空列。最高和最矮条的高度唯一（无并列）。下半区：一条全宽橙(7)分隔行，紧接分隔行下方一行为编码行，编码行中散布着若干不同颜色的像素（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取，每种颜色出现若干次）。生成约束：编码行中至少有一种颜色出现次数 = H_tall，至少一种颜色出现次数 = H_short；不存在同时满足两个频率的颜色。

**规则**：
1. 在上半区找到所有灰(5)竖直条，按像素高度排序。识别最高条（高度 H_tall）和最矮条（高度 H_short）。
2. 将最高条重涂为蓝(1)，最矮条重涂为红(2)。擦除所有其他灰(5)条（设为背景）。
3. 在编码行中，找出所有恰好出现 H_tall 次的颜色。对于该颜色在编码行中的每个出现位置（列 c），从分隔行上方第 1 行开始向上绘制蓝(1)竖直柱，高度为 H_tall 像素。
4. 在编码行中，找出所有恰好出现 H_short 次的颜色。对于该颜色在编码行中的每个出现位置（列 c），从分隔行上方第 1 行开始向上绘制红(2)竖直柱，高度为 H_short 像素。
5. 柱状图绘制区域与保留的极值条不重叠（生成时保证极值条所在列不出现在编码行的频率匹配列中）。
6. 分隔行和编码行保持不变。

**关键洞察**：条的高度在源题中只用于"选谁存活"的二元判断；此处高度值被二次利用为频率匹配的魔法数字——求解者必须发现"存活条的像素高度"与"编码行中某颜色出现次数"之间的数值等式关系，才能定位柱状图的列位置并确定其高度和颜色。

## 新题 3：模板匹配选定精灵体拉伸入框

**组合逻辑**：[形状匹配/shape_match](已有) + [掩码相同/mask_equality](已有) → 目标选择(创新：匹配结果不是重涂色而是选定拉伸目标) → [拉伸/stretch](已有) + [包围盒映射/bbox_mapping](已有) + [线段连接再填充/connect_then_fill](已有) + [擦除/erase](已有)

**来源原语**：形状匹配、模板、框架、前景对象、掩码相同、模板选同形重涂 (参考题 #16 63613498)；拉伸、精灵体、空心矩形、包围盒映射、线段连接再填充 (参考题 #9 465b7d93)

**依赖链**：L形框架内的模板定义了目标形状掩码；该掩码在多个候选精灵体中筛选出唯一匹配者；被选中的精灵体随即被拉伸映射进空心矩形框架的内部；未匹配的精灵体和L形框架区域被保留。没有模板匹配就无法确定拉伸哪个精灵体；没有拉伸步骤就不知道如何填充空心框。

L形框架是形状选择器，空心矩形是拉伸画布；模板匹配将二者桥接。

**输入结构**：约 15x15 网格，黑(0)背景。组件如下：
- 灰(5) L形框架位于网格一角（竖直臂在右、水平臂在底），L形框架围合区域内有一个单色小模板图形（绿(3)，4-连通，3-6 像素，形状为不规则多连通体而非标准几何形），模板不接触L形框架。
- 一个橙(7)空心矩形框（1 像素厚，约 5x5 至 7x7 外径），位于网格另一区域，内部为背景。
- 3-4 个小型单色精灵体散布在两个框架之外，各有不同颜色（蓝(1)、红(2)、黄(4)、品红(6)），各 3-6 像素，4-连通。其中恰好一个精灵体的归一化掩码（平移无关形状）与模板一致，其余精灵体形状各不相同且与模板不同。
- 生成约束：匹配精灵体与模板的像素数相同且归一化后形状重合；其他精灵体的像素数或归一化形状至少有一项与模板不同。

**规则**：
1. 提取灰(5) L形框架围合区域内的绿(3)模板图形，计算其归一化掩码（将边界框左上角对齐到原点后的二值形状）。
2. 对框架外的每个精灵体计算归一化掩码，找到唯一与模板掩码一致的精灵体（不考虑颜色）。
3. 将匹配精灵体的边界框四角映射到空心矩形框内部区域的四角（左上对左上、右下对右下）。
4. 对于匹配精灵体中每对 4-连通相邻像素，在映射后的坐标之间画水平或垂直直线段，使用该精灵体的原色。
5. 用同一颜色填充由上述线段围合的封闭背景区域。
6. 擦除匹配精灵体在原位置的像素（设为背景）。擦除灰(5) L形框架及绿(3)模板（均设为背景）。
7. 未匹配的精灵体和橙(7)空心矩形框保持不变。

**关键洞察**：源题 #16 中匹配后只做重涂色，源题 #9 中只有唯一精灵体无需选择。此处模板匹配的输出不是颜色变换而是一个选择决策——在多个候选者中挑出拉伸对象。L形框架是"形状查询"，空心矩形是"画布"，两个框架功能完全不同却必须协同。

## 新题 4：标记计数双重控制边框平铺间隔与调色板

**组合逻辑**：[计数/counting](已有) → 数值 N 同时作为(创新：一个数值同时参数化两个不同子系统) → [平铺/tile](已有, gap 由 N 决定而非段长) + [频率匹配/frequency_matching](已有, 目标数 = N) → [重涂色/recolor](已有, 平铺副本用频率匹配筛出的颜色着色)

**来源原语**：计数、频率匹配、分隔行、标记段、编码行、频率等于标记数 (参考题 #7 2685904e)；平铺、边框段、矩形边界、环形周期、间隔等长重复 (参考题 #3 30f42897)

**依赖链**：标记段的像素数 N 同时进入两条路径——一条控制边框平铺的间隔（gap = 2N），另一条作为频率匹配的目标阈值，筛出编码行中出现次数恰好为 N 的颜色集合；这些颜色按首次出现的列位置排序后循环分配给平铺副本作为着色。三个数据源（标记计数、编码行统计、边框段几何）汇聚为一个输出。

标记像素数量同时决定了边框段在周界上的重复间距和内部编码行的颜色筛选阈值，三源信息融合为一体。

**输入结构**：约 14x14 网格，黑(0)背景。
- 网格矩形周界上有一段连续的蓝(1)前景像素（3-5 像素长），位于某一边的部分位置，其余周界像素为背景。
- 网格内部：一条全宽灰(5)水平分隔行将内部分为上下两区。分隔行正上方一行中有一段连续的橙(7)标记像素（marker run，2-4 像素长）。分隔行正下方一行为编码行，其中散布着若干不同颜色的像素（从红(2)、绿(3)、黄(4)、品红(6)中选取），每种颜色出现特定次数。
- 内部其余位置为背景。
- 生成约束：令 N = 标记像素数。网格周长足以容纳至少 3 个间距为 2N 的段副本（含原始段）。编码行中至少有 2 种颜色的出现次数恰好等于 N。

**规则**：
1. 数标记段中橙(7)像素的个数，记为 N。
2. 将网格矩形周界按顺时针展开为一条环形路径（从左上角开始，依次为顶边→右边→底边→左边）。
3. 以原始蓝(1)边框段的起始位置为锚点，沿环形路径每隔 2N 个边界位置放置一个与原始段形状相同的副本（长度不变、贴合边界走向）。
4. 在编码行中找出所有出现次数恰好为 N 的颜色，按其在编码行中首次出现的列位置从左到右排序，得到调色板列表 P。
5. 将平铺产生的副本（不含原始段）依生成顺序用调色板 P 循环着色：第 1 个副本涂 P[0]，第 2 个副本涂 P[1]，……超出 P 长度时从头循环。原始蓝(1)段保持原色不变。
6. 分隔行、标记段和编码行保持不变。

**关键洞察**：数值 N 是整道题的枢纽，它既是空间参数（平铺间隔 = 2N）又是统计阈值（频率目标 = N）。求解者必须发现标记段长度与编码行频率之间的数值桥梁，否则既无法定位副本位置也无法确定副本颜色。源题 #3 中间隔等于段长本身，源题 #7 中标记数驱动柱状高度；此处间隔和调色板都由一个外部计数值参数化，且用途完全不同于两个源题。

## 新题 5：重力穿越同心环与选择性色环旋转

**组合逻辑**：[重力下落/gravity_drop](创新：方向为向心而非单轴) + [同色配对/same_color_pairing](创新：配对对象从满行列条变为同心环) → 结算位置决定激活集 → [重涂色/recolor + 色沿层序循环移/colors_cycle_by_nesting](创新：循环仅在被激活的环子集上执行)

**来源原语**：重力下落、碰撞停止、近墙优先结算 (参考题 #18 6ad5bdfd)；同色配对、孤立像素、滑动、无匹配色则删除 (参考题 #6 1a07d186)；同心正方形层、嵌套层序、重涂色、色沿层序循环移 (参考题 #8 bda2d7a6)

**依赖链**：孤立像素向网格中心滑动，经过多层同心环，在颜色匹配的环外壁停止（同色配对 + 重力）→ 停止位置决定哪些环被"激活"→ 激活环子集内部执行色环旋转，未激活环保持原色。重力结算依赖环色（决定停靠位置），色环旋转依赖重力结算的结果（决定哪些环参与旋转）。

孤立像素向心滑动至同色环边界停止；被命中的环形成激活子集，仅在该子集内执行色序旋转。

**输入结构**：约 13x13 网格，黑(0)背景。网格中央区域由 3-4 层同心矩形环组成，每层 1 像素厚，各层颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)中取）。最内层环围合的中心区域为背景。4-8 个孤立单像素分布在最外层环的外侧（即网格的外围区域），每个像素的颜色等于某一层环的颜色。生成约束：至少 2 层环会被像素命中（激活），至少 1 层环不会被命中（未激活），使选择性旋转可被观察到。每个孤立像素的颜色至少对应一层环。

**规则**：
1. 每个孤立像素从其位置向网格中心方向滑动（沿该像素到网格中心连线的主轴方向——若该像素到中心的水平距离 >= 垂直距离则水平滑动，否则垂直滑动；等距时水平优先）。
2. 像素滑动过程中穿过背景和不同色的环像素（不被阻挡），直到到达与自身同色的环的外边界——停在该环外侧紧邻的那个背景格（若该格已被其他已结算像素占据，则停在紧邻该像素的外侧格）。近中心的像素（距中心曼哈顿距离小的）先结算。
3. 若像素滑动到网格中心仍未遇到同色环（不应发生，由生成约束保证），则删除该像素。
4. 结算完成后，标记所有"被激活的环"——至少有 1 个像素停在其外侧的环。
5. 将被激活环按嵌套层序（从外到内）排列。在这个激活子集内执行颜色循环移位一步：每个激活环取该子集中下一层内侧激活环的颜色；最内层激活环取最外层激活环的颜色。
6. 未激活的环保持原色不变。已结算的孤立像素保持其原色（结算前的颜色）不变。

**关键洞察**：源题 #8 的颜色循环是无条件的全局操作；此处循环变为条件性的——只有"接住了像素"的环才参与旋转，且旋转在激活子集的嵌套子序列上执行。不同的像素配置导致不同的激活集合，进而导致不同的旋转结果。求解者必须先解决重力配对问题才能确定哪些环被激活，再在激活子集上执行（而非全局的）旋转。

## 新题 6：弹射体改造墙壁拓扑后分支射线穿行

**组合逻辑**：[射线发射/projectile_fire](已有) + [朝向编码方向/orientation_encodes_direction](已有) → 环境改造(创新：弹射体落点生成新墙壁像素，改变墙壁拓扑) → [分支/branch](已有) + [从边缘推进/advance_from_edge](已有) + [墙段开口分支/branch_at_opening](已有) + [重涂色/recolor](已有)

**来源原语**：射线发射/projectile_fire、三角精灵体、朝向编码方向、碰撞变色规则 (参考题 #1 409aa875)；分支、射线延伸、边缘标记、墙段、从边缘推进、墙段开口分支 (参考题 #12 f9a67cb5)

**依赖链**：三角精灵体发射弹射体 → 弹射体落在空白格则生成新墙壁像素（改变墙壁拓扑），落在已有对象则标记栗(9) → 精灵体被擦除 → 边缘标记发出分支射线，穿越原始墙段和新生成的墙壁，在开口处分支。弹射体阶段的输出重构了射线阶段的运行环境，使射线路径成为两阶段的耦合结果。

弹射体的落点创造新墙壁，从而改写了后续分支射线的穿行拓扑；射线最终形态是发射与穿行两步耦合的结果。

**输入结构**：约 14x14 网格，黑(0)背景。组件如下：
- 一个蓝(1)单像素边缘标记，位于网格某一边的边缘（如左边缘某行）。
- 2-3 条灰(5)水平墙段，各 4-8 像素长，彼此平行，垂直于边缘标记的推进方向排列。每条墙段有 1-2 个单像素宽的缺口（开口）。
- 2-4 个三角精灵体（3 像素的轴对齐 L 形或对角 V 形），颜色各不相同（从红(2)、绿(3)、黄(4)、橙(7)中取），分布在墙段之间或周围。
- 生成约束：至少一个精灵体的弹射体落点恰好位于某条墙段的缺口位置（从而将该缺口封闭），使分支射线的路径与无弹射体时明显不同。弹射体落点不能超出网格边界。边缘标记的推进方向上至少经过 2 条墙段。

**规则**：
1. 对每个三角精灵体，根据其形状确定发射方向（L 形从缺角对侧的对角方向发射，V 形沿开口对侧的轴向发射，同参考题 #1）。从顶点沿发射方向前进恰好 5 格为落点。
2. 若落点在网格内且为背景格，则将该格涂为灰(5)（新墙壁像素）。
3. 若落点在网格内且为非背景格（已有墙段像素、其他精灵体像素等），则将该格重涂为栗(9)。不产生新墙壁。
4. 若落点超出网格边界，则无效果。
5. 所有弹射体处理完毕后，擦除所有三角精灵体（将其原始像素设为背景），但保留步骤 2-3 中产生的新墙壁和栗(9)标记。
6. 从边缘标记向内推进分支射线（同参考题 #12）：沿推进方向逐格前进，将经过的背景格涂为蓝(1)。当射线下一格为墙段像素（原始灰(5)或新生成的灰(5)），则将该墙段的连续灰(5)像素段的近侧面及其两端相邻开口涂为蓝(1)，然后从每个在网格内的开口位置继续向内推进新的分支射线。
7. 栗(9)像素视为非墙壁、非背景的障碍物：射线遇到栗(9)像素时停止该分支，不涂色、不穿越、不分支。
8. 边缘标记保留蓝(1)。所有墙段（含新墙壁）和栗(9)标记保留在输出中。

**关键洞察**：源题 #1 中弹射体仅标记碰撞点颜色；源题 #12 中墙壁是静态给定的。此处弹射体物理地改造了墙壁拓扑——一个落入缺口的弹射体可以封闭通道，一个击中墙壁的弹射体产生栗色阻挡点。求解者必须先完成全部弹射体结算以确定修改后的墙壁布局，才能正确推演分支射线的路径。同一初始墙壁配置在不同精灵体位置下会产生截然不同的射线图案。
