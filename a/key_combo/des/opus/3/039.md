## 新题 1：对称墙镜像标记洪泛

**组合逻辑**：[对称补全](创新：镜像单像素标记而非补全图案缺口) + [洪泛填充](已有) + [墙壁/封闭区域](已有)；对称补全的输出改变了洪泛填充的触发条件（哪些区域有标记种子）

**来源原语**：对称补全(symmetry_completion) ← 9d9215db/9ecd008a；洪泛填充(flood_fill) ← e69241bd/c0f76784；墙壁(wall) ← e69241bd；封闭区域(enclosed_region) ← 6455b5f5/e69241bd/c0f76784；标记在区域内(marker_inside) ← e69241bd；镜像(mirror) ← 9ecd008a

**依赖链**：墙壁结构的双侧对称性隐式定义了一条镜像轴 → 将单半侧的标记像素沿该轴镜像复制到对侧空腔室 → 每个腔室用其内部标记颜色洪泛填充。若跳过镜像步骤，对侧腔室无标记、无法填充；若跳过洪泛，镜像标记仅为单像素、不产生面积填充。镜像轴本身需要从墙壁对称结构中推断，不可从标记位置直接读取。

将输入中仅存在于一侧的单像素标记通过墙壁对称性镜像到对侧空腔室后，用各腔室内标记的颜色洪泛填充每个被墙壁围成的封闭区域。

**输入结构**：约 15x15 网格。背景黑(0)。灰(5) 像素构成一组连通的墙壁线段，将网格内部分隔为若干不规则但 4-连通的封闭腔室（每个腔室为 4-连通的黑(0) 区域，面积约 4~20 像素）。整体墙壁图案关于网格的一条中轴线（可能是垂直中轴或水平中轴）呈精确的双侧对称。在中轴线的一侧（称"源半侧"），部分腔室各包含恰好一个标记像素，颜色为蓝(1)、红(2)、绿(3)、黄(4) 中的某一种；每个含标记的腔室仅含一个标记。另一侧（称"镜半侧"）的对应腔室内部全为黑(0)，不含任何标记。不含标记的源半侧腔室在镜半侧也没有标记。生成约束：(a) 对称轴为网格正中一列或正中一行（奇数尺寸网格取中心列/行）；(b) 每个标记像素的镜像位置保证落在镜半侧对应腔室内部（非墙壁上）；(c) 不同腔室的标记颜色可重复。

**规则**：
1. 确定对称轴：找到使灰(5) 墙壁图案精确左右对称（或上下对称）的唯一中轴线。
2. 对源半侧每个标记像素 p(r,c)，计算其关于中轴线的镜像坐标 p'(r',c')，在 p' 位置放置与 p 同色的标记像素。
3. 对每个 4-连通的黑(0) 腔室区域执行洪泛填充：若该腔室内恰好包含一个标记像素，将整个腔室填充为该标记的颜色；若腔室内无标记，保持黑(0) 不变。
4. 灰(5) 墙壁像素保持不变。
5. 处理顺序不影响结果（各腔室独立填充，墙壁阻隔保证无跨腔室渗透）。

**关键洞察**：对称轴未被显式标记——必须从墙壁图案的几何对称性中推断；而对称轴是垂直还是水平需对比多个示例才能确定规律（不同示例中对称方向可能与网格宽高比或标记分布方向有关）。

## 新题 2：嵌套深度决定精灵涂色

**组合逻辑**：[包含树/计数](创新：将包含层数用作连续变量驱动重涂色，原题中包含树仅用于规范化布局) → [重涂色](创新：涂色依据是结构深度而非原始颜色或面积)

**来源原语**：包含树(containment_tree) ← 2d0172a1；计数(counting) ← 6455b5f5/42a15761；重涂色(recolor) ← 689c358e/6455b5f5；嵌套框架(nested_frame) ← 2d0172a1；封闭区域(enclosed_region) ← 多题

**依赖链**：嵌套框架的包含树结构决定每个精灵的嵌套深度 → 嵌套深度映射为特定输出颜色 → 精灵被重涂为该颜色。若跳过包含树分析，无法计算深度；若跳过重涂色，深度信息无处体现。精灵的原始颜色在输出中被完全覆盖——它是干扰项，仅结构位置决定输出。

根据小精灵被几层矩形框架嵌套包围的层数，忽略其原始颜色，将其重涂为深度对应的固定颜色。

**输入结构**：约 16x16 网格。背景黑(0)。若干灰(5) 空心矩形框架嵌套排列（框架为 1 像素宽的矩形环，内部为黑(0) 空腔；大框架的空腔内可再包含较小框架）。嵌套最深不超过 3 层。在最内层框架的内部，各有一个小的单色精灵（4-连通、2~5 像素的不规则形状），精灵颜色为蓝(1)、红(2)、绿(3)、橙(7) 中随机一种（颜色与嵌套深度无关）。精灵不接触任何框架边缘（至少间隔 1 像素）。同一层级可有多个并列的框架（兄弟框架互不重叠）。生成约束：(a) 每个精灵完全包含在恰好一组嵌套框架链中；(b) 框架仅由灰(5) 构成，精灵仅由非灰非黑颜色构成；(c) 不同深度的精灵数量至少各有 1 个。

**规则**：
1. 建立框架包含树：框架 A 包含框架 B 当且仅当 B 的所有像素都在 A 的空心内部的 4-连通黑(0) 区域中。
2. 对每个精灵，计算其嵌套深度 d = 包围它的框架层数（直接在最外层框架内 → d=1；在一个框架内、该框架又在另一框架内 → d=2；以此类推）。
3. 将精灵重涂为深度对应的颜色：d=1 → 蓝(1)，d=2 → 红(2)，d=3 → 绿(3)。精灵的形状保持不变，仅颜色改变。
4. 所有灰(5) 框架和黑(0) 背景保持不变。

**关键洞察**：精灵的原始颜色是刻意的干扰——输出颜色完全由嵌套结构位置决定；具体的"深度→颜色"映射表（1→蓝、2→红、3→绿）需要对比多个示例中不同深度精灵的输入输出颜色才能归纳。

## 新题 3：种子射线分割与极值面积涂色

**组合逻辑**：[射线延伸](创新：种子在边框上、射线向内部延伸形成分割线，原题中射线从精灵向边框延伸) → [面积比较 + 极值区域分别涂色](创新：面积比较作用于射线创造的新分区，而非已有的分隔线分区)

**来源原语**：射线延伸(ray_extend) ← 689c358e；面积比较(area_comparison) ← 6455b5f5；极值区域分别涂色(extreme_regions_recolor) ← 6455b5f5；矩形边框(rectangular_frame) ← 689c358e；封闭区域(enclosed_region) ← 6455b5f5/c0f76784

**依赖链**：边框上种子像素的位置决定射线位置 → 射线将边框内部分割成若干矩形区域（分区结构在输入中不存在，是射线操作的涌现结果）→ 各区域面积的极值比较决定涂色。若跳过射线步骤，内部无分区、无法比较面积；若跳过面积比较，射线仅是线段、不产生区域涂色。种子之间的间距协同决定分区面积——移动任一种子会同时改变多个分区的面积，可能翻转极值排序。

从矩形边框顶边和左边上的种子像素向内部延伸射线，将边框内部分割为若干矩形区域，然后将面积最小的区域涂青、面积最大的区域涂蓝。

**输入结构**：约 12x12 网格。背景黑(0)。灰(5) 像素构成一个 1 像素宽的实心矩形边框，占据网格最外一圈。在边框的顶边内侧（第 1 行），有 2~3 个红(2) 种子像素嵌在灰色边框像素之间（替换对应位置的灰色像素）。在边框的左边内侧（第 0 列），有 1~2 个红(2) 种子像素嵌在灰色边框像素之间。边框内部（被边框围住的区域）全为黑(0)。生成约束：(a) 种子像素只出现在顶边和左边；(b) 顶边种子的列坐标互不相同，左边种子的行坐标互不相同；(c) 分割产生的所有矩形区域面积互不相等（无并列极值）。

**规则**：
1. 对顶边的每个红(2) 种子像素，从该像素所在列、边框内部顶行开始，向下绘制一条红(2) 垂直射线，直到碰到底部边框（不含边框像素本身），射线占据该列从内部顶行到内部底行的所有像素。
2. 对左边的每个红(2) 种子像素，从该像素所在行、边框内部左列开始，向右绘制一条红(2) 水平射线，直到碰到右侧边框（不含边框像素本身），射线占据该行从内部左列到内部右列的所有像素。
3. 红色射线将边框内部分割为若干矩形区域。每个区域是一个 4-连通的黑(0) 像素集合（被射线和/或边框围住）。
4. 计算每个矩形区域的面积（黑色像素数）。
5. 将面积最小的区域填充为青(8)，面积最大的区域填充为蓝(1)。其余区域保持黑(0)。
6. 灰(5) 边框和红(2) 射线保持不变。

**关键洞察**：种子位置的不均匀间距导致分割出的矩形面积各异，但面积由水平和垂直间距的乘积决定——仅看一个方向的间距无法判断面积极值，必须联合两个方向的种子位置进行二维推理。

## 新题 4：降噪宏块压缩后重力下落

**组合逻辑**：[降噪](已有) → [压缩](已有，创新：压缩结果作为重力操作的输入而非最终输出) → [重力下落](已有，创新：作用于压缩后的低分辨率像素而非原始对象)

**来源原语**：降噪(denoise) ← 5614dbcf；压缩(compress) ← 5614dbcf/4be741c5；网格分块(grid_partitioning) ← 5614dbcf；噪声像素(noise_pixel) ← 5614dbcf；重力下落(gravity_drop) ← 6ca952ad；触底停止(stop_at_bottom) ← 6ca952ad；忽略标记取主色(ignore_marker_dominant) ← 5614dbcf

**依赖链**：灰噪声像素干扰宏块的真实颜色判断 → 降噪（忽略灰色）确定每个宏块的真实主色 → 压缩将每个宏块映射为一个低分辨率像素 → 低分辨率网格中的彩色像素在各自列内向下坠落直到触底或堆叠。降噪错误会导致空块被误判为彩色块（多出下落物）或彩色块被误判为空块（丢失下落物）；压缩改变了重力作用的空间尺度；重力改变了压缩结果的空间布局。三步中任意一步被跳过，输出都不同。

将含有灰色噪声像素的大网格先降噪、压缩为低分辨率网格，再将低分辨率网格中的彩色像素在各自列内执行重力下落。

**输入结构**：约 15x15 网格（行列数均为 3 的倍数）。背景黑(0)。网格可视为 5x5 的宏块阵列，每个宏块为 3x3 像素。每个宏块要么全为黑(0)（可能含少量灰(5) 噪声像素），要么有一种主色（蓝(1)、红(2)、绿(3)、黄(4) 之一）占据至少 7 个像素、其余 1~2 个像素为灰(5) 噪声。全黑宏块中的灰噪声不超过 2 个像素。彩色宏块在阵列中稀疏分布（约占总宏块数的 30%~50%），且在某些列中，彩色宏块下方存在空的黑色宏块（即彩色宏块"悬浮"）。生成约束：(a) 每列内所有彩色宏块的主色互不相同（避免堆叠后颜色混淆）；(b) 纯黑宏块中的灰噪声不会使该块的灰像素数超过 2（确保不会被误判为彩色块）。

**规则**：
1. 降噪：对每个 3x3 宏块，统计其中各非灰(5) 颜色的像素数。若黑(0) 像素数最多（含灰色后仍为背景主导），则该宏块为"空块"；否则，取像素数最多的非黑非灰颜色为该宏块的主色。
2. 压缩：将每个宏块替换为单个像素——空块 → 黑(0)，有主色的块 → 该主色。得到 5x5 的低分辨率网格。
3. 重力下落：在低分辨率网格的每一列中，所有非黑像素向下移动，堆叠在该列底部。上方空出的位置填黑(0)。同一列内像素的相对上下顺序保持不变。
4. 输出 5x5 的低分辨率网格。

**关键洞察**：灰色噪声是关键干扰——纯黑宏块中散布的灰像素可能诱使求解者将其误认为有内容的宏块，但正确的降噪规则是"灰色永远是噪声、不作为主色候选"，这一规则需从多个示例中归纳确认（例如观察到含灰的黑块在输出中始终不产生下落像素）。

## 新题 5：标记最稀疏矩形跨面板透明叠加

**组合逻辑**：[选择/最少标记数](已有) ⊕ [裁剪](已有) → [透明叠加](创新：叠加的不是固定面板，而是从各面板中按条件选出的子区域)

**来源原语**：选择(selection) ← 7bb29440；最少标记数(minimum_marker_count) ← 7bb29440；裁剪(crop) ← 7bb29440/2d0172a1；透明叠加(transparent_overlay) ← e98196ab；分隔行(separator_row) ← e98196ab；等高面板(equal_height_panel) ← e98196ab；前景矩形(foreground_rectangle) ← 7bb29440；标记像素(marker_pixel) ← 7bb29440；前景不冲突(no_fg_collision) ← e98196ab

**依赖链**：分隔行将网格分为两个面板 → 在每个面板中独立执行"选出标记最少的矩形"并裁剪 → 两个裁剪结果透明叠加为最终输出。选择步骤决定了哪些矩形参与叠加（换一个标记数，输出完全不同）；叠加步骤将两个独立选择的结果合并为一个不可分解的输出。这是一个分叉-汇合结构：两个面板独立执行选择，结果汇合于叠加。

从分隔行划分的两个面板中各选出标记像素最少的矩形，裁剪后透明叠加为一个合成图案。

**输入结构**：约 19x10 网格。背景黑(0)。一行完整的灰(5) 实心行横贯全宽，将网格分为上下两个等高面板（各约 9x10）。每个面板内包含 2~3 个实心矩形（每个矩形由单一填充色构成，颜色为蓝(1)、红(2)、绿(3)、黄(4)、橙(7) 中的某一种；不同矩形颜色不同）。矩形尺寸约 3x3 到 5x5，互不接触（间隔至少 1 像素黑色）。每个矩形内部有 0~4 个标记像素（标记像素颜色与矩形填充色不同，且不为黑(0) 或灰(5)）。上下两个面板中被选中矩形（标记最少者）的裁剪结果尺寸相同。生成约束：(a) 每个面板内，标记数最少的矩形唯一（无并列）；(b) 两个被选中矩形的裁剪尺寸相同（宽高一致）；(c) 两个裁剪结果在同一局部坐标处不会同时存在非黑前景像素（保证叠加无冲突）。

**规则**：
1. 识别灰(5) 分隔行，将网格分为上面板和下面板。
2. 在每个面板中，找出所有实心前景矩形（4-连通的同色非黑区域，形状为矩形）。
3. 对每个矩形，计数其标记像素数（矩形边界框内、颜色与矩形主色不同的像素数量）。
4. 从每个面板中选出标记像素数最少的矩形。
5. 将两个被选中矩形各自裁剪为其边界框大小的子网格。
6. 透明叠加：创建与裁剪尺寸相同的输出网格，初始化为黑(0)。遍历每个局部坐标，若上面板裁剪结果在该位置为非黑色则取该颜色，否则取下面板裁剪结果在该位置的颜色。
7. 输出叠加后的小网格。

**关键洞察**：分隔行既不是输出内容也不是装饰——它指示"分面板独立选择再合并"的操作结构；选择标准（标记最少）必须从多个示例中归纳，因为单看一个示例可能误以为选择依据是面积、颜色或位置。

## 新题 6：边缘射线遇墙变色与分区洪泛

**组合逻辑**：[生长/射线延伸](创新：射线从边缘条出发、被内部墙壁截断) + [重涂色](创新：涂色取决于射线是否被墙壁阻断——结构条件驱动涂色) + [洪泛填充](创新：填充颜色取决于邻接射线的类型而非区域内标记)

**来源原语**：生长(grow) ← 758abdf0；射线延伸(ray_extend) ← 689c358e；墙壁(wall) ← e69241bd；碰撞停止(collision_stop) ← 88e364bc；洪泛填充(flood_fill) ← e69241bd/c0f76784；重涂色(recolor) ← 689c358e/6455b5f5；边缘满条(full_edge_bar) ← 758abdf0；标记条(marker_bar) ← 758abdf0；封闭区域(enclosed_region) ← 多题

**依赖链**：标记像素从边缘条出发向内生长为射线 → 墙壁决定射线是否被截断 → 截断状态决定射线被重涂为什么颜色（被墙阻断 → 保持橙色；到达对边 → 变为绿色）→ 射线 + 墙壁 + 边框共同将内部分割为封闭区域 → 每个封闭区域的填充颜色取决于与它 4-邻接的射线类型（橙色 / 绿色 / 两者都有）。墙壁同时承担三重角色：阻断射线、影响射线涂色、形成分区边界。移除任何一步都无法得到正确输出。

从边缘条向内延伸的标记射线被内部墙壁截断或贯穿全程后变色，形成的分区按邻接射线类型洪泛填充不同颜色。

**输入结构**：约 10x12 网格。背景黑(0)。左边缘整列为绿(3) 满条。在绿满条右侧紧邻的第 1 列中，某些行有橙(7) 标记像素（每行至多一个，约占总行数的 40%~60%）。网格内部（第 2 列至倒数第 2 列）散布灰(5) 垂直墙壁段（每段为 1 像素宽、2~4 像素高的垂直线段），墙壁段数量约 2~4 段，互不相邻。右边缘整列为绿(3) 满条。生成约束：(a) 橙标记像素仅出现在第 1 列（紧靠左边缘条）；(b) 灰墙壁不接触左右两侧的绿边缘条；(c) 每个橙标记所在行至多有一段灰墙壁（避免多段截断的歧义）；(d) 灰墙壁段不跨越有橙标记的所有行（保证至少一条射线能贯穿）。

**规则**：
1. 对每个橙(7) 标记像素，从其位置开始向右延伸水平射线（逐像素填充），直到遇到以下情况之一停止：(a) 碰到灰(5) 墙壁像素 → 射线停止在墙壁左侧一格（不覆盖墙壁），射线保持橙(7)色；(b) 到达右侧绿(3) 边缘条 → 射线延伸到绿条左侧一格，射线整体重涂为绿(3)。
2. 射线绘制完毕后，灰墙壁 + 绿边缘条 + 橙/绿射线共同将网格内部分割为若干 4-连通的黑(0) 封闭区域。
3. 对每个封闭区域，检查与它 4-邻接的所有非黑像素中射线像素的颜色类型：
   - 仅邻接橙(7) 射线（或无射线邻接）→ 填充黄(4)
   - 仅邻接绿(3) 射线 → 填充蓝(1)
   - 同时邻接橙(7) 和绿(3) 射线 → 填充红(2)
4. 灰(5) 墙壁、绿(3) 边缘条、以及射线像素（橙或绿）保持不变。
5. 注意：边缘条本身的绿色不算作"射线颜色"——只有从标记生长出的射线（包括被重涂为绿的贯穿射线）才参与邻接判断。

**关键洞察**：墙壁同时扮演三个结构角色——截断射线、改变射线颜色、划分封闭区域——这意味着移动一段墙壁会连锁改变射线长度、射线颜色和区域填充色。区域填充规则（邻接颜色类型→填充色）需要从多个示例中对比归纳。

## 新题 7：中心像素回文补全后排序

**组合逻辑**：[对称补全](创新：补全对象是宏单元中心像素列的垂直回文结构，而非完整图案的镜像) → [计数](已有) → [列排序](已有，但排序值被补全改变——补全是排序的前置依赖)

**来源原语**：对称补全(symmetry_completion) ← 9d9215db/9ecd008a；计数(counting) ← 42a15761/6455b5f5；列排序(column_sorting) ← 42a15761；宏单元(macro_cell) ← 42a15761；中心像素列(center_pixel_col) ← 42a15761；按填充数降序(desc_filled_count) ← 42a15761；对称展开(symmetric_unfolding) ← 9d9215db；间隔列(gutter_column) ← 42a15761

**依赖链**：宏单元中心像素列应呈垂直回文（上下对称），但部分中心被擦除破坏了回文 → 对称补全恢复缺失的中心像素 → 补全后计数每列的填充中心数 → 按填充数降序排列中心列。补全直接改变计数结果：一列原本看起来只有 2 个填充中心，补全后可能变成 4 个，排名跃升。若跳过补全，排序基于不完整的计数，结果不同。

恢复宏网格中心像素列被擦除的回文对称像素后，按每列填充中心数从多到少重新排列中心列。

**输入结构**：约 13x13 网格（如 5 行 x 4 列的宏阵列，每个宏单元 3x3，列间有 1 像素黑(0) 间隔列）。红(2) 像素填充每个宏单元的 3x3 区域（除中心像素外）。每个宏单元的中心像素要么为黄(4)（"填充"），要么为黑(0)（"空"）。在完整状态下，每个宏列（竖直方向的一组中心像素）呈垂直回文（即从上到下和从下到上读取的填充/空序列相同）。但每列有 0~2 个中心像素被"擦除"（从黄变为黑），破坏了回文对称性。被擦除的像素总是位于回文轴的一侧（确保另一侧的对称位置仍为黄色，可作为恢复依据）。生成约束：(a) 宏行数为奇数（确保回文有唯一中轴行）；(b) 补全后各列的填充中心数互不相同（无并列排名）；(c) 被擦除的中心总能从其回文对称位置恢复（对称位置的中心为黄色）。

**规则**：
1. 识别宏网格结构：红(2) 的 3x3 宏单元被黑(0) 间隔列分隔，每个宏单元的中心像素位于该 3x3 块的正中。
2. 对每个宏列（垂直方向的一组中心像素），检查其垂直回文性：以该列的中间行为对称轴，若位置 i 处为黄(4) 但其对称位置 (n-1-i) 处为黑(0)，则将黑(0) 位置补全为黄(4)。
3. 补全后，计数每个宏列的填充中心数（黄(4) 像素数量）。
4. 按填充中心数从多到少（降序）重新排列各宏列的中心像素列。移动时，整列中心像素的垂直模式作为整体搬移到新位置，红色框架和间隔列保持不变。
5. 输出重排后的完整网格。

**关键洞察**：中心像素列看似随机残缺，但残缺模式遵循回文对称约束——被擦除的都是有对称对应的像素。补全后排序结果可能与直接对残缺列排序截然不同，因为某些看似稀疏的列在补全后变得密集。回文补全规则本身需要对比多个示例（看到被擦除的位置总是能在对称位置找到对应）才能确认。

## 新题 8：参考行对齐后色带压缩

**组合逻辑**：[对齐](创新：对齐目标由一行特殊参考像素定义，参考行位置不固定) + [压缩](创新：压缩粒度为色带→单像素，与对齐结果耦合——对齐改变每行的多数色，从而改变压缩输出)

**来源原语**：对齐(align) ← 9968a131；同色对齐(same_color_align) ← 9968a131；参考条(reference_bar) ← 9968a131；压缩(compress) ← 4be741c5；色带(color_band) ← 4be741c5；空间排列顺序(spatial_order) ← 4be741c5；行主色压缩单像素(row_majority_to_pixel) ← 4be741c5

**依赖链**：参考行标识了每种色带颜色的"正确"列位置 → 各色带按参考行指示的列位置水平对齐 → 对齐后的色带按行取多数色压缩为单列向量。对齐改变了每行的像素分布，直接影响哪个颜色成为多数色。若跳过对齐，每行多数色可能因色带偏移而计算错误；若跳过压缩，对齐后的多行色带不会被简化为序列。参考行的识别规则（"含每种色带颜色恰好一个像素的行"）本身是一个需要归纳的隐蔽条件。

找到网格中唯一的参考行，按其指示的列位置水平对齐各色带，再将对齐后的色带逐行取多数色压缩为单列向量。

**输入结构**：约 10x10 网格。背景黑(0)。网格中有 3~4 条水平色带（每条色带由同一颜色构成，占据连续的 2~3 行，颜色为蓝(1)、红(2)、绿(3)、黄(4) 中不同的一种）。色带的边界参差不齐：同一色带内不同行的彩色像素起止列可能略有差异（偏移 1~2 列），且某些位置被黑(0) 空隙打断。色带之间可能有 0~1 行黑(0) 间隔。网格中有一行特殊的"参考行"，该行恰好包含每种色带颜色各一个像素（分布在不同列），其余位置为黑(0)。参考行的位置不固定——它可能在色带之间、色带之上或色带之下。生成约束：(a) 参考行是唯一满足"含每种色带颜色各恰好一个像素"条件的行；(b) 对齐后，每行的多数色唯一确定（无并列）；(c) 色带从上到下的颜色顺序在不同示例中不同。

**规则**：
1. 识别参考行：找到网格中唯一一行，满足它包含的每种非黑颜色都恰好出现一次、且这些颜色恰好是所有色带的颜色集合。记录参考行中每种颜色所在的列号。将参考行从网格中移除（不参与后续处理）。
2. 对每条色带，计算其"多数列"：统计该色带所有行中、该颜色出现次数最多的列号。
3. 将每条色带整体水平平移，使其多数列与参考行中该颜色的列号对齐。平移后超出网格范围的像素舍弃，空出的位置填黑(0)。
4. 对齐后，对网格中（除已移除的参考行外）每一行，计算其多数色：统计该行非黑像素中出现次数最多的颜色。若该行全为黑色，多数色为黑(0)。
5. 输出一个单列向量（高度 = 原网格行数减 1，宽度 = 1），每个像素为对应行的多数色。

**关键洞察**：参考行的位置不固定且视觉上不显眼（仅含几个散落的彩色像素），必须通过"每种色带颜色恰好出现一次"这一结构特征来识别；色带的参差边界是噪声，对齐操作将其归一化后，行多数色才能正确反映色带的本来排列。
