## 新题 1：同心环分区双瓦片修复

**组合逻辑**：[同心层填充](创新：环不着色，仅作空间分区器) + [修复噪声/平铺](创新：按环奇偶归属推断两套独立瓦片) + [控制像素] + [周期瓦片]

**来源原语**：同心层填充/concentric_fill（b7fb29bc）、奇偶距离决定颜色/parity_distance_color（b7fb29bc）、修复噪声/repair_noise（135a2760）、周期瓦片/periodic_tile（135a2760, ea959feb）、控制像素/control_pixel（b7fb29bc）、矩形边框/rectangular_frame（b7fb29bc）

**依赖链**：控制像素的位置决定了每个单元格的 Chebyshev 距离奇偶性 -> 奇偶性将所有内部单元格分成两个空间交错集合 -> 每个集合内部独立存在一套周期瓦片图案 -> 两套瓦片各自有少量像素被损坏 -> 必须先正确分区才能分别推断各自的周期并修复

从控制像素出发按 Chebyshev 距离奇偶性将矩形框内部分为两组交错区域，每组区域内各有一套独立的周期瓦片图案（含少量噪声），分别推断各自最小重复瓦片并修复损坏像素。

**输入结构**：约 18x18 的网格，黑(0)背景。一个蓝(1)单像素宽矩形边框占据网格大部分面积。框内有一个红(2)控制像素（位置因示例而异）。框内其余单元格被两套交错的彩色周期图案覆盖：一套使用绿(3)和黄(4)两色，另一套使用灰(5)和品红(6)两色。两套图案按如下方式交错排列——以控制像素为中心计算每个单元格的 Chebyshev 距离，奇数距离的单元格属于图案 A（绿/黄），偶数距离的单元格属于图案 B（灰/品红）。每套图案在其所属的单元格集合内呈现周期性重复（周期约 2x2 至 4x4），但各有 2-4 个像素被损坏为黑(0)。生成约束：控制像素不在框的正中心（否则对称性太强），两套瓦片的周期尺寸互不相同，损坏像素不集中在同一区域。

**规则**：
1. 识别蓝(1)矩形边框和框内唯一的红(2)控制像素。
2. 对框内每个非红非蓝的单元格，计算其到控制像素的 Chebyshev 距离（max(|dr|, |dc|)）。
3. 距离为奇数的单元格归入集合 O，距离为偶数的单元格归入集合 E。
4. 在集合 O 内，将各单元格按其在网格中的原始行列坐标取模，用多数投票法推断该集合的最小周期瓦片（每个 (r mod pH, c mod pW) 残差位置取出现次数最多的非黑颜色）。周期瓦片必须在该集合内至少沿每个轴重复 2 次。
5. 对集合 E 执行同样的周期瓦片推断，独立于集合 O。
6. 将集合 O 和集合 E 中所有黑(0)损坏像素替换为其所属集合的周期瓦片在对应残差位置的颜色。
7. 边框、控制像素和框外区域保持不变。

**关键洞察**：控制像素并非装饰——它的位置决定了奇偶环的空间分布，从而将两套视觉上混杂的周期图案分离为可独立推断的子集；仅凭一个示例无法确定分区机制，必须对比不同控制像素位置的示例才能发现 Chebyshev 距离奇偶性是分区依据。

## 新题 2：标签方位编码旋转印章

**组合逻辑**：[镜像位置](创新：镜像位置确定印章目标位) + [印章覆盖](创新：印章内容来自镜像对侧) + [旋转](创新：旋转角度由标签像素方位编码) + [擦除]

**来源原语**：镜像位置/mirrored_position（8ee62060）、印章覆盖/stamp（39e1d7f9）、旋转/rotate（a25697e4）、擦除/erase（1b8318e3, 7d7772cc）、精灵体/sprite（8ee62060）、标记像素/marker_pixel（ce22a75a, 39e1d7f9）

**依赖链**：标签像素标识哪个精灵是模板（而非目标）-> 模板精灵与其镜像位置配对，镜像位置即印章目标 -> 标签像素相对于模板中心的 4-方向位置编码旋转角度 -> 模板按编码角度旋转后印章到镜像位置 -> 原始模板及标签擦除

在关于垂直中轴对称配对的精灵中，带标签像素的一方是模板，标签的相对方位编码旋转角度；模板旋转后印章到其镜像位置，原件擦除。

**输入结构**：约 15x19 的网格，黑(0)背景。2-4 个小型单色精灵体（各 3-6 像素的 4-连通单色图形，颜色各异，取自蓝(1)、绿(3)、黄(4)、品红(6)等），成对关于网格垂直中轴对称放置。每对中恰有一个精灵带有一个橙(7)标签像素，该标签与精灵的边界框 4-邻接（上、右、下、左四个方位之一）。未带标签的一侧在镜像位置处放一个与对应精灵同色的单个锚点像素（标记目标中心）。生成约束：各精灵对互不重叠，标签像素不被其他精灵遮挡，各对的标签方位不全相同（至少出现两种不同方位）。

**规则**：
1. 识别网格的垂直中轴 x = (W-1)/2。
2. 找到所有 4-连通的非黑非橙单色精灵。按垂直中轴配对：每个精灵与其关于中轴的镜像位置处的同色锚点像素（或精灵）配对。
3. 在每对中，带有橙(7)标签像素的一方为模板，镜像侧的锚点像素标记目标中心位置。
4. 确定标签像素相对于模板边界框中心的 4-方向位置：上方 -> 0 度（不旋转），右方 -> 顺时针 90 度，下方 -> 180 度，左方 -> 逆时针 90 度（即顺时针 270 度）。若标签与中心的行列偏移同时涉及两个方向，取绝对偏移量较大的方向。
5. 将模板精灵的像素图案以其边界框中心为旋转中心，按步骤 4 确定的角度顺时针旋转。
6. 将旋转后的图案以目标锚点像素的位置为中心印章到网格上。超出网格边界的部分舍弃。
7. 擦除原始模板精灵和其橙(7)标签像素（置为黑(0)）。目标侧的锚点像素被印章覆盖。
8. 各对独立处理，处理顺序为模板边界框左上角从左到右、从上到下。若印章区域重叠，后处理的覆盖先处理的。

**关键洞察**：标签像素承担双重功能——既标识模板身份（有标签的是源，无标签的是目标），又通过其相对方位编码旋转角度；仅看单个示例可能猜不出旋转规则，需对比多个示例中不同标签方位对应的不同旋转结果才能归纳。

## 新题 3：路径端点位移解码驱动走廊路径铺设

**组合逻辑**：[端点编码位移](创新：位移用于平移门框而非空心框) + [平移] + [路径填充](创新：在平移后的新位置之间铺设走廊) + [最短路径并集]

**来源原语**：端点编码位移/endpoints_encode_disp（2b9ef948）、平移/translate（2b9ef948, 8ee62060）、路径填充/path_fill（692cd3b6）、门框/doorway_frame（692cd3b6）、走廊路径/corridor_path（692cd3b6）、路径端点/path_endpoint（2b9ef948）、最短路径并集/monotone_shortest_path_union（692cd3b6）

**依赖链**：每个门框各关联一条灰色折线路径 -> 路径两端的彩色端点编码一个位移向量 -> 每个门框按各自的位移向量平移到新位置 -> 在两个平移后的门框之间计算并绘制单调最短路径并集走廊 -> 路径的弯折形状无关紧要，只有端点间的净向量决定位移

先从灰色路径的彩色端点解码位移向量，将两个门框分别平移到新位置，然后在新位置间铺设单调最短路径并集走廊。

**输入结构**：约 20x20 的网格，黑(0)背景。两个蓝(1)小型门框结构（每个约 3x3 至 4x4 的单像素厚矩形框，框上恰有一个缺口即门洞，门洞内有一个红(2)标记像素）。每个门框附近有一条灰(5)像素组成的折线路径（3-7 个灰像素，可含转弯），路径一端连接一个绿(3)像素，另一端连接一个黄(4)像素。绿(3)像素和黄(4)像素不与门框相邻。两条路径互不相交，两个门框互不重叠。生成约束：每个门框按其关联路径的位移向量平移后仍在网格内且两者不重叠，平移后两个门框之间存在至少一条背景单元格组成的单调路径。

**规则**：
1. 识别两个蓝(1)门框及其内部红(2)标记像素。
2. 对每个门框，找到其附近的灰(5)折线路径。路径的两个端点分别是一个绿(3)像素和一个黄(4)像素。
3. 计算位移向量：从绿(3)端点指向黄(4)端点的向量 (dr, dc) = (r_yellow - r_green, c_yellow - c_green)。灰色路径的中间弯折不影响位移。
4. 将门框（含其蓝(1)像素和红(2)标记）整体平移 (dr, dc)。擦除原始位置的门框像素和路径（灰、绿、黄）像素，全部置为黑(0)。
5. 在两个平移后的门框之间铺设走廊：找到每个门框的门洞缺口外侧第一个背景单元格（外门口单元格）。
6. 以两个外门口单元格为起止点，仅允许朝向对方的行/列步进（单调步进），收集所有此类最短路径经过的背景单元格的并集，将其涂为黄(4)。同时将两个门洞缺口处的背景单元格也涂为黄(4)。
7. 平移后的门框蓝(1)像素和红(2)标记保持不变。

**关键洞察**：灰色折线路径的几何走势是干扰项——无论路径多么曲折，只有两端彩色像素之间的净向量决定门框位移；求解者必须先正确解码位移、完成平移后才能确定走廊路线，两步之间存在不可跳过的信息依赖。

## 新题 4：吸附计数奇偶控制锚框排列方向

**组合逻辑**：[吸附/snap](创新：吸附后的像素总数成为控制参数) + [计数/counting] + [局部翻转/local_reverse](创新：翻转作用于锚框上的吸附像素序列) + [锚块/anchor_block] + [最近距离/nearest_distance]

**来源原语**：吸附/snap（1b8318e3）、最近距离/nearest_distance（1b8318e3）、最短距离分配/nearest_frame_assign（1b8318e3）、计数/counting（5289ad53）、局部翻转/local_reverse（833966f4）、锚块/anchor_block（1b8318e3）、外框边缘/outer_frame（1b8318e3）、孤立像素/singleton_pixel（1b8318e3）

**依赖链**：各彩色孤立像素按最近距离分配到灰色锚块 -> 统计每个锚块吸引的像素数 -> 吸附像素按顺时针顺序排列到锚块的外框边缘 -> 若该锚块的吸附数为奇数则逆转排列顺序 -> 奇偶判断依赖吸附阶段的结果，无法提前确定

将彩色孤立像素吸附到最近的灰色锚块外框，按顺时针排列；若某锚块吸引的像素总数为奇数，则逆转该锚块上的排列顺序。

**输入结构**：约 15x15 的网格，黑(0)背景。2-3 个灰(5)实心 2x2 锚块，彼此间距至少 5 个单元格。6-10 个彩色孤立像素散布在网格各处，颜色取自蓝(1)、红(2)、绿(3)、黄(4)、品红(6)等，每个像素颜色互不相同。生成约束：每个锚块至少吸引 2 个像素，且各锚块吸引的像素数不全相同（至少一个奇数、一个偶数），不存在距离两个锚块等距的像素（无分配歧义）。

**规则**：
1. 识别所有灰(5)实心 2x2 锚块和所有非黑非灰的孤立像素。
2. 对每个孤立像素，计算它到每个锚块的 King-move 距离（Chebyshev 距离，取到锚块 4 个单元格的最小值）。将像素分配给距离最近的锚块。
3. 清除所有孤立像素的原始位置（置为黑(0)）。
4. 对每个锚块，确定其外框边缘（锚块 2x2 区域向外扩展一圈的 12 个单元格位置，裁剪掉超出网格的部分）。
5. 将分配给该锚块的像素按其原始位置到锚块中心的角度排序（以正上方为 0 度，顺时针增大）。
6. 按排序结果依次将像素放入外框边缘的顺时针序列中：第一个像素放在外框边缘最接近正上方的位置，后续像素依次顺时针放置到下一个可用的外框位置。
7. 统计该锚块吸引的像素总数 k。若 k 为奇数，将已放置的 k 个像素在外框上的位置序列整体逆转（第一个与最后一个交换，第二个与倒数第二个交换，以此类推）——即改为逆时针排列。若 k 为偶数则保持顺时针不变。
8. 灰色锚块本身保持不变。

**关键洞察**：吸附的计数结果是一个涌现属性——它取决于像素与锚块的全局空间分布，而非任何预设参数；该计数的奇偶性决定排列方向的规则仅能通过对比吸引不同数量像素的锚块才能归纳出来。

## 新题 5：腔体嵌套后按派生色连接走廊

**组合逻辑**：[嵌套/dock](保留腔体面积匹配) + [路径填充/path_fill](创新：走廊端点和颜色由嵌套结果决定) + [同色配对](创新：配对基于嵌套派生的活动色而非输入色) + [面积匹配] + [空腔]

**来源原语**：嵌套/dock（a25697e4）、面积匹配/area_matching（a25697e4）、空腔/cavity（a25697e4）、可移动工具/movable_tool（a25697e4）、路径填充/path_fill（692cd3b6）、走廊路径/corridor_path（692cd3b6）、门洞朝向/doorway_orientation（692cd3b6）、同色配对/same_color_pairing（06df4c85）、最短路径并集/monotone_shortest_path_union（692cd3b6）

**依赖链**：可移动工具按腔体面积匹配嵌套到边框 -> 填充腔体的那个颜色成为该框架的"活动色" -> 具有相同活动色的框架对之间铺设走廊 -> 走廊使用该共享活动色绘制 -> 不匹配的框架不连通 -> 活动色在嵌套前无法确定，走廊路线在平移前无法确定

先将双色工具嵌套进匹配腔体的框架，填入腔体的颜色成为框架的活动色；活动色相同的框架对之间用该色铺设单调最短路径走廊。

**输入结构**：约 20x20 的网格，黑(0)背景。3-4 个蓝(1)单像素厚矩形边框贴近网格边缘（至少一条边与网格边界重合），每个框架内部有一个背景色(黑(0))矩形腔体（2-5 个像素面积），每个框架在一条边上有一个单像素宽的缺口（门洞朝向框架外部）。网格中央散布 3-4 个双色可移动工具：每个工具由两种非蓝非黑颜色组成的 4-连通图形（3-8 像素），两色区域的像素数分别等于某个腔体的面积和一个非腔体值。颜色取自红(2)、绿(3)、黄(4)、灰(5)、品红(6)等。生成约束：工具与腔体的面积匹配是一一对应无歧义的；嵌套完成后至少存在一对活动色相同的框架（即至少两个工具有一个相同颜色恰好是各自填充腔体的那个颜色）；活动色不全相同（至少一个框架的活动色独一无二）。

**规则**：
1. 识别所有蓝(1)边框框架及其内部黑(0)腔体，记录每个腔体的像素面积。
2. 识别所有非蓝非黑的双色 4-连通可移动工具，记录每种颜色的像素数。
3. 对每个工具，找到腔体面积等于该工具某一色区域像素数的框架。将工具旋转/翻转使该色区域精确填充腔体（另一色区域位于腔体外的框架边缘或外部）。若嵌套方向涉及反射（翻转），则交换工具的两种颜色。
4. 填入腔体的颜色即为该框架的"活动色"。
5. 清除工具原始位置的像素（置为黑(0)）。
6. 将活动色相同的框架两两配对。对每一对，以各自门洞外侧第一个背景单元格为端点，沿行/列方向仅允许朝向对方的单调步进，收集所有此类最短路径经过的背景单元格的并集，涂为该共享活动色。门洞缺口单元格也涂为同色。
7. 活动色独一无二（无配对）的框架不绘制任何走廊。
8. 若同一对框架之间的走廊经过另一个框架的外壁，走廊视该外壁为阻挡物绕行（仅走背景单元格）。
9. 蓝(1)边框和嵌套后的工具像素保持不变。

**关键洞察**：走廊的颜色和连接对象都不是输入直接给出的——它们是嵌套操作的派生结果；求解者必须先完成所有嵌套才能知道哪些框架应被连接以及用什么颜色，两阶段之间存在不可跳过的信息变换。

## 新题 6：异常象限裁剪模板印章到格网标记

**组合逻辑**：[裁剪/crop + 异常值选择/outlier_selection](创新：裁剪结果不是最终输出，而是后续印章的模板) + [印章覆盖/stamp](创新：印章模板来自异常象限而非专用示例区) + [格网/lattice + 标记单元格/marker_cell](创新：标记色与异常色相同，建立跨区域语义链接)

**来源原语**：裁剪/crop（0b148d64）、颜色异常值选择/outlier_color_selection（0b148d64）、象限/quadrant（0b148d64）、分隔行列/separator_row_col（0b148d64）、印章覆盖/stamp（39e1d7f9）、格网/lattice（39e1d7f9）、标记单元格/marker_cell（39e1d7f9）、示例邻域传递同色/exemplar_copied_to_same_color（39e1d7f9）、分隔线划分/separator_partition（39e1d7f9）

**依赖链**：网格上半区分为四象限 -> 三个象限共享一种前景色，一个象限颜色独特（异常值）-> 裁剪异常象限的内容作为模板 -> 下半区是分隔线划分的格网 -> 格网中部分单元格含有与异常色相同的标记像素 -> 将模板印章到每个标记单元格处 -> 异常色同时充当选择键和目标键

上半区四象限中颜色独特的异常象限被裁剪为印章模板，印章到下半区格网中所有与异常色同色的标记单元格位置。

**输入结构**：约 19x15 的网格，由一条全宽灰(5)水平分隔行分为上下两区。上半区（约 9 行）被一条全高灰(5)垂直分隔列进一步分为四个象限，每个象限约 4x7。三个象限各含若干稀疏像素均为红(2)，一个象限的稀疏像素为绿(3)（异常色）。每个象限内像素形成不规则的小图案（2-5 像素，4-连通）。下半区（约 9 行）是一个 3x3 等分格网，由灰(5)单像素分隔线划分为 9 个单元格（每格约 3x4）。其中 2-4 个单元格各包含一个绿(3)标记像素（位于单元格中心），其余单元格为纯黑(0)。生成约束：异常象限的图案边界框不超过格网单元格尺寸，标记单元格数量至少为 2。

**规则**：
1. 在上半区识别四个象限，比较各象限中非黑非灰像素的颜色。三个象限共享一种颜色（红(2)），一个象限使用独特颜色（绿(3)）——后者为异常象限。
2. 裁剪异常象限的内容：取其中所有非黑非灰像素的最小边界框，提取该区域作为模板。模板中的像素保留其原色（绿(3)），背景为黑(0)。
3. 在下半区格网中找到所有包含绿(3)标记像素的单元格。
4. 对每个标记单元格，将模板以标记像素位置为中心进行印章：模板中心对齐标记像素，将模板的非黑像素覆盖到该单元格对应位置。超出单元格边界的部分裁剪丢弃（不越过分隔线）。
5. 印章完成后，擦除上半区所有象限内容（置为黑(0)），仅保留灰(5)分隔线结构和下半区的印章结果。
6. 下半区无标记的单元格保持纯黑(0)不变。

**关键洞察**：异常色在输入中承担双重语义——在上半区它标记"哪个象限是模板来源"，在下半区它标记"哪些格网单元格是印章目标"；求解者必须先通过颜色对比完成异常值检测，才能知道模板内容和印章位置，两步之间共享同一个颜色作为语义链接。

## 新题 7：包裹铺设序列遇预置触发点发射对角溅射

**组合逻辑**：[生成序列 + 换行平铺/wrap_tile](保留控制条长度驱动升降游程) + [射线延伸/ray_extend](创新：射线从生成图案与预置触发点的对齐处发射，而非从移动像素发射) + [邻接触发对角溅射](创新：触发条件变为"生成像素直接落在预置像素正上方")

**来源原语**：生成序列/generate_seq（5d588b4d）、换行平铺/wrap_tile（5d588b4d）、条长决定序列/bar_length_seq（5d588b4d）、控制条/control_bar（5d588b4d）、递增递减游程/rise_fall_run（5d588b4d）、射线延伸/ray_extend（73c3b0d8）、邻接触发对角溅射/adjacency_triggers_diagonal_splash（73c3b0d8）、触发条/trigger_bar（73c3b0d8）

**依赖链**：顶行控制条长度 n 定义升降序列 1,2,...,n,...,2,1 -> 序列换行铺设到网格中 -> 网格中预置的孤立触发像素保持不动 -> 若某个生成的前景像素恰好落在触发像素的正上方一行 -> 该生成像素发射向上的两条对角射线 -> 射线是否发射取决于生成图案与预置触发点的空间对齐，这一对齐在铺设前无法预测

按控制条长度生成升降游程并换行铺设，当铺设的前景像素恰好落在预置触发像素正上方时，从该位置向上发射两条对角射线。

**输入结构**：约 12x12 的网格，黑(0)背景。顶行（第 0 行）从最左列起有一段连续的蓝(1)水平条（长度 n，3 <= n <= 5），条右侧到行尾为黑(0)。网格中散布 2-4 个红(2)孤立像素（不在第 0 行，不在第 1 行，不相邻，不与控制条同行），它们是预置的触发像素。其余单元格为黑(0)。生成约束：网格行数足以容纳完整的升降序列换行铺设（总前景像素数 = n^2，加上间隔的背景像素后需要的行数不超过网格高度减 1）；至少一个触发像素会被生成图案在其正上方一行产生的前景像素激活，至少一个触发像素不会被激活（其正上方一行不会有生成像素落在那里）。

**规则**：
1. 读取顶行蓝(1)控制条长度 n。
2. 构建一维前景游程序列：长度为 1, 2, ..., n, n-1, ..., 2, 1 的蓝(1)游程，相邻游程之间用一个黑(0)间隔像素分隔。
3. 从第 1 行第 0 列开始，按行主序将该一维序列逐像素铺设到网格中（每行宽度 = 网格宽度），到行尾自动换行到下一行。最后一行不足网格宽度的部分用黑(0)填充。
4. 保留所有红(2)触发像素在原位不变。若铺设的蓝(1)像素与红(2)触发像素位置重合，红(2)保留（红色覆盖蓝色）。
5. 检查每个红(2)触发像素正上方一行同列位置：若该位置为蓝(1)前景像素（来自步骤 3 的铺设结果），则从该蓝(1)像素位置向左上和右上两个对角方向各发射一条蓝(1)射线，射线每步行号减 1、列号分别减 1 和加 1，直到离开网格边界。射线像素覆盖路径上的黑(0)背景像素；若射线遇到已有的非黑像素（含其他射线像素或红色触发像素），该射线在该像素前一格停止（不覆盖已有非黑像素）。
6. 第 0 行的控制条保持不变。

**关键洞察**：对角射线并非从所有前景像素发射，而是仅从恰好位于预置触发像素正上方的那些生成像素发射；哪些位置会触发取决于升降序列的换行铺设结果与触发像素列号的巧合对齐，求解者必须先完成心理铺设才能判断哪些触发点被激活。

## 新题 8：参考比对滑动后距离优先消解冲突

**组合逻辑**：[滑动/slide + 颜色匹配定去向/color_match_dest](保留匹配判断分流机制) + [同心层填充/concentric_fill](创新：Chebyshev 距离不用于着色，而用作冲突优先级) + [以控制点为中心/centered_on_control](创新：控制点提供优先级度量中心) + [擦除/erase]

**来源原语**：滑动/slide（7d7772cc）、颜色匹配定去向/color_match_dest（7d7772cc）、对齐比较/aligned_comparison（7d7772cc）、参考像素/reference_pixel（7d7772cc）、源像素/source_pixel（7d7772cc）、分隔线/separator_line（7d7772cc）、以控制点为中心/centered_on_control（b7fb29bc）、控制像素/control_pixel（b7fb29bc）、擦除/erase（1b8318e3）、冲突优先级/conflict_priority（1b8318e3）

**依赖链**：参考像素与源像素按行对齐比较颜色 -> 匹配的源像素滑向分隔线旁 -> 不匹配的滑向远端边缘 -> 多个源像素可能滑向同一目标位置产生冲突 -> 网格中一个控制像素提供 Chebyshev 距离参考中心 -> 冲突时距离控制像素更近的源像素获胜，其余被擦除 -> 距离优先级规则仅能从有冲突发生的示例中归纳

源像素按颜色匹配与否分流滑动到分隔线旁或远端；当多个像素滑向同一位置时，距离控制像素更近者优先，其余擦除。

**输入结构**：约 14x14 的网格。一条完整的灰(5)水平分隔线横贯网格中部（如第 6 行全为灰(5)）。分隔线上方为"参考侧"：紧邻分隔线的那一行（第 5 行）有 4-6 个彩色参考像素，颜色取自蓝(1)、红(2)、绿(3)、黄(4)，其余位置为黑(0)。分隔线下方为"源侧"：距分隔线 3-4 行处（如第 9 行或第 10 行）有 4-6 个彩色源像素，与参考像素按列对齐（即每个源像素正上方的参考行同列处有一个参考像素），颜色取自同一色集但不一定与对齐的参考像素同色。源侧其余位置为黑(0)。网格内另有一个橙(7)控制像素位于源侧某处（不在源像素行上，不在参考行上，不在分隔线上）。生成约束：至少有两个源像素滑动后目标位置相同（产生冲突），这两个源像素到控制像素的 Chebyshev 距离不相等（无优先级歧义）。

**规则**：
1. 识别灰(5)水平分隔线、分隔线上方的参考像素行、分隔线下方的源像素、以及橙(7)控制像素。
2. 对每个源像素，找到同列的参考像素，比较两者颜色。
3. 若颜色匹配：该源像素的目标位置为分隔线正下方第一个单元格（第 7 行同列）。
4. 若颜色不匹配：该源像素的目标位置为源侧最底行同列（即网格最后一行同列）。
5. 收集所有（目标位置, 源像素）对。若多个源像素的目标位置相同，计算每个源像素原始位置到橙(7)控制像素的 Chebyshev 距离，距离最小的获胜保留，其余被丢弃（擦除）。若距离相等（生成约束下不会出现），取行号较小者。
6. 清除所有源像素的原始位置（置为黑(0)）。将每个获胜的源像素放置到其目标位置。
7. 参考像素、分隔线和控制像素保持不变。

**关键洞察**：在无冲突的示例中，控制像素看起来毫无作用（纯干扰项）；只有当两个源像素的目标位置重合时，控制像素的距离优先级规则才显现——求解者必须对比有冲突和无冲突的示例才能归纳出控制像素的真正用途。
