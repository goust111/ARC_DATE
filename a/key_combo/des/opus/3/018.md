## 新题 1：奇偶格点门控的点对称印章

**组合逻辑**：[坐标奇偶匹配](创新：从填充背景变为二值筛选条件) + [镜像](创新：从轴对称变为点对称/180度旋转) + [印章覆盖](已有) + [擦除](已有)

**来源原语**：坐标奇偶匹配(coord_parity_match) ← d492a647；镜像(mirror) ← 2b01abd0；印章覆盖(stamp) + 锚点标记(anchor_marker) + 同色对应(same_color_match) ← 1b59e163；擦除(erase) ← edcc2ff0

**依赖链**：奇偶种子像素的位置决定活跃格点 → 活跃格点判定每个精灵体的锚点是否"通过" → 通过者执行点对称镜像并印章到同色目标标记位置，未通过者被擦除 → 三层逻辑缺一不可：没有奇偶判定就不知道保留哪些精灵体，没有点对称就不知道印章的形状，没有锚点-标记配对就不知道印章放在哪里。

将网格中散布的精灵体按锚点坐标的奇偶归属进行筛选，通过者以锚点为中心做 180 度旋转后印章到同色目标标记处，未通过者消失。

**输入结构**：
- 背景：黑(0)，网格约 18x18。
- 3~4 个小型 8-连通精灵体（各 3~6 像素），每个精灵体使用一种独有的非背景色（如蓝(1)、红(2)、绿(3)），形状各异（无固定几何形态，由像素连通决定）。
- 每个精灵体内部或紧邻处恰好嵌有一个"锚点像素"，颜色与精灵体不同但在所有精灵体间也各不相同（如黄(4)、橙(7)、栗(9)）。锚点颜色是该精灵体的"配对标识"。
- 网格其他位置散布着若干孤立的"目标标记"像素，每个目标标记的颜色与某个锚点颜色相同。同一锚点颜色可能有 1~2 个目标标记。
- 网格中有唯一一个灰(5)像素，作为"奇偶种子"。它不与任何精灵体相邻。
- 生成约束：每个精灵体的锚点颜色至少有一个对应的目标标记。各精灵体、目标标记、奇偶种子互不相邻。精灵体的锚点中恰好有部分落在种子定义的奇偶格点上、部分不落在。

**规则**：
1. 奇偶种子灰(5)像素的行列坐标 (r_s, c_s) 定义活跃奇偶类：(r_s % 2, c_s % 2)。
2. 对每个精灵体，检查其锚点像素的坐标 (r_a, c_a) 是否满足 r_a % 2 = r_s % 2 且 c_a % 2 = c_s % 2。
3. 若满足（"通过"）：以锚点为中心，对精灵体做 180 度旋转（即每个精灵体像素 (r, c) 映射到 (2*r_a - r, 2*c_a - c)），得到镜像副本。将镜像副本以精灵体的颜色印章到每个同色目标标记位置——目标标记的坐标替代锚点坐标作为旋转中心，精灵体的相对偏移保持不变。原始精灵体保留在原位。
4. 若不满足（"未通过"）：擦除该精灵体的所有像素（包括锚点）为背景色。
5. 所有锚点像素、目标标记像素、奇偶种子像素在输出中均被擦除为背景色，无论是否通过筛选。
6. 多个印章重叠同一像素时，锚点行坐标较小者优先；行坐标相同时列坐标较小者优先。超出网格边界的印章像素被丢弃。

**关键洞察**：奇偶种子看似与精灵体无关，但它定义了一个隐蔽的二值筛选器——只有锚点恰好落在种子同奇偶格点上的精灵体才会被保留和复制，需要对比多个示例才能发现这一筛选规则。

## 新题 2：对角连线穿越容器触发充能

**组合逻辑**：[连线/对角线段连接](已有) + [计数](创新：计数对象从标记数量变为几何交叉数) + [逐步充能](创新：充能驱动力从移动距离变为外部穿越计数)

**来源原语**：连线(line_drawing) + 对角线段连接(diagonal_segment_connect) + 端点对(endpoint_pair) + 同色配对(same_color_pairing) ← 1f876c06；逐步充能(incremental_charge) + 带边框容器(bordered_container) + 能量上限步数(energy_caps_steps) ← 271d71e2；计数(counting) ← edcc2ff0

**依赖链**：同色端点对决定对角线段路径 → 对角线段是否穿过容器内部产生交叉计数 → 交叉计数决定容器灰色单元转橙色的数量（受灰色单元总数上限约束）→ 三者形成"路径创造 → 空间交叉检测 → 数值驱动变换"的因果链，去掉任何一环都无法求解。

在黑色背景上画出所有同色端点对的 45 度对角连线，然后根据穿过每个带边框容器内部的连线条数，将该容器对应数量的灰色内部单元充能为橙色。

**输入结构**：
- 背景：黑(0)，网格约 20x20。
- 2~3 个带边框容器：每个容器是一个矩形，边框用一种独有颜色绘制（如品红(6)、栗(9)），内部全部填充灰(5)。容器内部尺寸约 3x3 到 5x5。容器之间互不重叠，间距至少 2 像素。
- 3~5 对彩色端点像素，每种前景色（如蓝(1)、红(2)、绿(3)、黄(4)）恰好出现两次，分布在网格各处（容器外部）。同色两像素之间形成严格 45 度对角线（|delta_row| = |delta_col|）。
- 生成约束：部分对角线段穿过某些容器的内部区域，部分不穿过。至少一个容器被至少一条对角线穿过，至少一个容器不被任何对角线穿过。端点不落在容器边框或内部。

**规则**：
1. 对每种前景色（不含容器边框色和灰色），将同色两端点之间的所有 45 度对角路径单元（含端点）涂上该颜色。
2. 对每个容器，计算有多少条不同颜色的对角线段至少有一个单元落在该容器的内部区域（边框内侧、不含边框本身）。记该计数为 K。
3. 将该容器内部的灰(5)单元从左上角按阅读序（从左到右、从上到下）依次转换为橙(7)，共转换 min(K, 灰色单元总数) 个。
4. 绘制顺序：先执行步骤 3（充能），再执行步骤 1（画对角线）。因此对角线颜色会覆盖容器内部已充能的橙色单元或未充能的灰色单元。
5. 容器边框永远不被覆盖。没有被任何对角线穿过的容器（K=0）保持灰色内部不变。

**关键洞察**：对角连线本身不是最终目的——它们充当"探针"，穿过容器的条数才是驱动容器内部变化的信号；求解者需要发现充能量等于穿越线段数而非其他量（如线段长度或端点距离）。

## 新题 3：分隔面板异或比较驱动条件棋盘扩展

**组合逻辑**：[异或叠加](已有) + [像素放大](已有) + [图案替换](创新：替换图案随异或来源方向变化，非固定映射) + [按颜色条件分支](创新：分支条件由面板比较结果而非原色决定)

**来源原语**：异或叠加(xor_overlay) + 分隔行(separator_row) + 前景掩码(foreground_mask) + 对齐(alignment) + 前景不一致处涂色(disagreement_cells_painted) ← 99b1bc43；像素放大(pixel_upscaling) + 图案替换(pattern_substitution) + 棋盘格图案(checkerboard_pattern) + 按颜色条件分支(color_conditional_branch) ← 2072aba6

**依赖链**：分隔行定义面板分割 → 上下面板逐像素比较产生异或结果 → 异或结果分三类（上方贡献/下方贡献/一致）→ 每类映射到不同的 2x2 扩展图案（条件分支）→ 比较、分类、扩展三步紧耦合：不做比较不知道哪些单元分歧，不区分来源方向就无法选择正确图案，不做扩展就无法渲染棋盘。

将分隔行分割的上下两块前景掩码做异或比较，每个结果单元扩展为 2x2 块——分歧单元按来源面板方向生成不同颜色的棋盘格，一致单元扩展为纯背景块。

**输入结构**：
- 背景：黑(0)，网格约 14x(2H+1)，其中 H 为面板高度（约 4~6 行）。
- 一条完整宽度的分隔行，颜色为品红(6)，将网格分为等高的上面板和下面板。
- 上面板：在黑(0)背景上，前景像素全部为蓝(1)，形成一个不规则的连通或非连通掩码（约占面板面积的 30%~50%）。
- 下面板：在黑(0)背景上，前景像素全部为黄(4)，形成另一个不规则掩码，与上面板的掩码有部分重合、部分独有区域。
- 生成约束：上下面板尺寸完全相同。至少存在上方独有、下方独有、双方重合三种区域各至少一个像素。

**规则**：
1. 移除品红(6)分隔行，将上下面板逐单元对齐。
2. 对齐后的每个位置 (r, c) 分为三类：
   - **上方分歧**：上面板为蓝(1)前景、下面板为黑(0)背景。
   - **下方分歧**：上面板为黑(0)背景、下面板为黄(4)前景。
   - **一致**：两面板均为背景，或均为前景。
3. 输出网格尺寸为 2H x 2W（H 为面板高度，W 为面板宽度）。每个对齐位置 (r, c) 映射到输出的 2x2 块，左上角为 (2r, 2c)。
4. 一致位置 → 2x2 全黑(0)块。
5. 上方分歧 → 2x2 棋盘 [[蓝(1), 品红(6)], [品红(6), 蓝(1)]]。
6. 下方分歧 → 2x2 棋盘 [[黄(4), 品红(6)], [品红(6), 黄(4)]]。
7. "均为前景"（上蓝下黄同位置）归类为一致，输出黑块——此规则需要对比多个示例才能归纳出（直觉上可能认为应该输出某种混合图案）。

**关键洞察**：分隔行的品红(6)色并未消失——它作为棋盘格的交织色重新出现在输出中，将输入的结构色回收为输出的编码色；同时"双方均前景 → 视为一致"的规则违反直觉，必须对比示例才能确认。

## 新题 4：容器内灰点计数决定透明叠加优先级

**组合逻辑**：[计数](创新：计数结果作为空间优先级排序依据) + [填充](已有) + [透明叠加](创新：图层优先级由动态计数而非固定位置决定)

**来源原语**：计数(counting) ← edcc2ff0, 6773b310；填充(fill) ← 3eda0437；透明叠加(transparent_overlay) + 图层优先级(layer_priority) + 面板位决定层序(panel_layer_order) ← ea9794b1；带边框容器(bordered_container) ← 271d71e2

**依赖链**：统计每个容器内部灰点数量 → 灰点数量排序生成图层优先级（少者在上）→ 容器内部填充为边框色后按优先级透明叠加 → 重叠区域显示优先级更高容器的颜色。三者形成"测量 → 排序 → 合成"的紧耦合链：不计数就不知道优先级；不填充就没有待合成的色块；不叠加就无法处理重叠。

将若干部分重叠的带边框容器各自填充为边框色，重叠区域按"内部灰点越少优先级越高"的规则确定显示颜色。

**输入结构**：
- 背景：黑(0)，网格约 16x16。
- 3~4 个带边框容器，每个容器是一个矩形：边框为一种独有颜色（如蓝(1)、红(2)、绿(3)、黄(4)），边框宽度 1 像素。容器内部在黑(0)背景上散布若干灰(5)像素点，不同容器内灰点数量不同（如分别为 1、3、5 个）。
- 容器之间存在部分重叠——某些容器的矩形区域（含边框）与另一容器有交集。至少有两对容器存在重叠。
- 生成约束：每个容器的灰点数量互不相同，保证优先级排序唯一。容器的重叠区域不超过任一容器面积的一半。

**规则**：
1. 统计每个容器内部区域（边框内侧）的灰(5)像素数量。
2. 按灰点数量从少到多排序，灰点最少的容器优先级最高（最上层）。
3. 将每个容器的内部区域全部填充为该容器的边框颜色（灰点和黑色单元都变为边框色）。
4. 按优先级从低到高（灰点最多者最先绘制）依次绘制填充后的容器（含边框）。后绘制的容器覆盖先绘制的，因此优先级最高的容器（灰点最少）最后绘制，在重叠区域显示其颜色。
5. 容器外部的背景保持黑(0)不变。

**关键洞察**：灰色点在输出中完全消失，但它们的数量编码了容器的"深度"——灰点少的容器离观察者更近，遮挡灰点多的容器；求解者必须发现这一隐蔽的数量-优先级映射。

## 新题 5：滑动至锚点后异或解决碰撞

**组合逻辑**：[滑动](已有) + [异或叠加](创新：从预对齐掩码比较变为滑动产生的动态碰撞解决) + [碰撞停止](已有) + [擦除](已有)

**来源原语**：滑动(slide) + 精灵体(sprite) + 方块锚点(square_anchor) + 接触边对齐(contact_edge_align) + 碰撞停止(collision_stop) ← 11dc524f；异或叠加(xor_overlay) + 前景不一致处涂色(disagreement_cells_painted) ← 99b1bc43；同色配对(same_color_pairing) ← 1f876c06

**依赖链**：精灵体沿基本方向滑向同色锚点 → 滑动后精灵体可能占据重叠位置 → 重叠区域用异或规则解决（同时被两个精灵体覆盖的单元变为背景）→ 滑动是异或的前提条件（不滑动就没有重叠），异或是滑动结果的解释规则（不做异或就不知道重叠处画什么）。两个操作在空间上交织而非顺序独立。

将多个精灵体同时滑向各自同色的方块锚点直到接触，然后对滑动后的精灵体位置做异或处理——重叠单元变为背景色。

**输入结构**：
- 背景：灰(5)，网格约 15x15。
- 2~3 个小型 8-连通精灵体（各 4~7 像素），颜色各异（如蓝(1)、红(2)、黄(4)），形状不规则（非矩形、非对称，由像素连通性定义）。
- 每个精灵体有一个同色的 2x2 实心方块锚点，位于精灵体的某个基本方向上（上/下/左/右），与精灵体之间隔若干背景单元。
- 生成约束：每个精灵体与其锚点之间沿基本轴方向无遮挡（路径上只有背景色）。滑动后至少有一对精灵体存在像素级重叠（即它们的最终位置共享至少一个单元格）。各精灵体-锚点对的滑动轴可以不同。

**规则**：
1. 所有精灵体同时移动：每个精灵体沿连接自身与同色 2x2 锚点的基本方向（上/下/左/右）平移，直到精灵体的前沿像素与锚点的近边相邻（间距 0，紧贴）。
2. 移动完成后，擦除所有 2x2 锚点为背景色。
3. 处理重叠：对于每个输出单元格，统计有多少个移动后的精灵体覆盖该位置。
   - 恰好 1 个精灵体覆盖 → 显示该精灵体的颜色。
   - 恰好 2 个或更多精灵体覆盖 → 显示背景色灰(5)（异或消除）。
4. 未被任何精灵体覆盖的单元保持背景色灰(5)。

**关键洞察**：滑动本身不会产生意外——每个精灵体到锚点的运动是确定的；真正的推理难点在于发现重叠区域的消除规则（异或），需要对比有重叠和无重叠的示例才能归纳出"重叠 → 背景"这一非显然规则。

## 新题 6：标记计数的奇偶性翻转区域填充格点

**组合逻辑**：[计数](已有) + [填充](创新：填充图案由外部计数的奇偶性动态决定) + [坐标奇偶匹配](创新：从全局固定格点变为按区域条件翻转的格点)

**来源原语**：计数(counting) + 双标记区域出前景(dual_marker_foreground) + 网格分区(grid_partition) ← 6773b310；填充(fill) ← 3eda0437；坐标奇偶匹配(coord_parity_match) + 奇偶格点(parity_lattice) + 同奇偶背景涂色(same_parity_colored) ← d492a647；分隔线(separator_line) ← 6773b310

**依赖链**：蓝色种子像素在其所在区域内的局部坐标定义基准奇偶类 → 每个区域内红色标记的计数产生奇偶判定 → 偶数区域使用基准格点、奇数区域使用反转格点 → 按对应格点进行填色。计数的奇偶性动态修改了几何填充图案，而非仅作为数值汇总。

在分隔线划分的网格中，根据每个区域内红色标记数量的奇偶性，交替使用正向或反向奇偶格点进行填色。

**输入结构**：
- 背景：黑(0)，网格约 15x15。
- 灰(5)的完整宽度分隔行和完整高度分隔列将网格划分为 3x3 或 4x3 的矩形区域（每个区域约 3x3 到 4x4 个内部单元）。
- 其中一个区域包含恰好一个蓝(1)像素（"奇偶种子"），该区域内无红色标记。
- 其余区域各包含 0~3 个红(2)标记像素，散布在黑(0)背景上。
- 生成约束：至少有两个区域的红色标记数量为奇数，至少两个为偶数（含 0）。蓝色种子在其区域内的位置不在角落（以避免退化）。

**规则**：
1. 蓝(1)种子在其区域内的局部坐标（相对于区域左上角内部单元）为 (lr, lc)。定义基准奇偶类为 (lr % 2, lc % 2)。
2. 对每个区域（含种子所在区域），统计其中红(2)标记的数量 K。
3. 若 K 为偶数（含 0）：对该区域内局部坐标 (r', c') 满足 r' % 2 = lr % 2 且 c' % 2 = lc % 2 的所有单元，填充绿(3)。
4. 若 K 为奇数：对该区域内局部坐标 (r', c') 满足 r' % 2 != lr % 2 且 c' % 2 != lc % 2 的所有单元，填充黄(4)。（即基准奇偶类的行列都取反）。
5. 填色覆盖该位置的原有内容（包括红色标记和蓝色种子）。不在目标格点上的单元变为黑(0)背景。
6. 灰(5)分隔线保持不变。

**关键洞察**：同一个奇偶种子在不同区域产生不同的填充图案——关键不在种子本身，而在于每个区域的标记数量的奇偶性翻转了格点相位，并且奇数区域和偶数区域使用不同的填充颜色（绿 vs 黄），需要多示例对比才能发现这一双重编码。

## 新题 7：外部标记计数覆盖弹射长度

**组合逻辑**：[弹射](创新：弹射长度由外部标记计数决定而非内部内容像素数) + [计数](创新：计数对象从区域内物体变为散布在全局的同色标记) + [擦除](已有) + [同色对应](已有)

**来源原语**：弹射(ejection) + 杯形框架(cup_frame) + 尾刺(tail_spike) + 内容像素(content_pixel) + 尾部朝向决定射出(tail_determines_emission) + 像素数守恒(pixel_count_conservation) ← 3dc255db；计数(counting) + 标记像素(marker_pixel) ← edcc2ff0, 6773b310；同色对应(same_color_match) ← 1b59e163

**依赖链**：杯形框架的尾刺确定弹射方向（保留原始机制）→ 散布在网格中与杯框同色的独立标记被计数 → 计数值替代内容像素数成为弹射长度 → 内容像素被擦除但不参与长度计算。尾刺决定"往哪射"，外部标记决定"射多远"，内容像素只是被清除的"废料"——三个信息源缺一不可。

杯形框架弹射一条射线，方向由尾刺决定，但射线长度等于网格中与杯框同色的独立标记数量，而非杯内内容像素的数量。

**输入结构**：
- 背景：黑(0)，网格约 18x18。
- 2~3 个杯形框架（U 形或类似凹形结构，各约 5x4 到 6x5 像素），每个框架的边框颜色各不相同（如蓝(1)、红(2)、绿(3)）。
- 每个杯框有一个收敛的尾刺在某一侧，开口（嘴部）在对侧。嘴部内部有 1~4 个橙(7)内容像素。
- 网格空白区域（杯框外部）散布着孤立的标记像素，颜色与某个杯框的边框色相同。例如：蓝(1)杯框对应 3 个散布的蓝(1)标记，红(2)杯框对应 1 个散布的红(2)标记。
- 生成约束：每种杯框颜色的独立标记数量与该杯内容像素数量不同（否则无法区分两种规则）。标记像素不与任何杯框相邻。至少有一个杯框的标记数 > 内容像素数，至少一个杯框的标记数 < 内容像素数。弹射路径上无其他非背景像素（直到网格边界）。

**规则**：
1. 对每个杯形框架，识别其尾刺方向：尾刺的外向方向（远离嘴部的方向）即为弹射方向。
2. 统计网格中与该杯框边框颜色相同的独立标记像素数量（不含杯框自身的边框像素）。记为 M。
3. 擦除杯框嘴部内的所有橙(7)内容像素为背景色。
4. 从尾刺尖端沿弹射方向画一条橙(7)直线段，长度为 M 像素（每个像素紧接前一个，从尾刺尖端的下一个单元开始）。超出网格边界的部分被截断。
5. 擦除所有独立标记像素为背景色。杯框的边框结构保持不变。
6. 各杯框的弹射独立执行。若两条弹射线段交叉，后处理的覆盖先处理的（处理顺序：按杯框尾刺尖端的行坐标从小到大，行相同则按列坐标从小到大）。

**关键洞察**：直觉上会假设弹射长度等于被清除的内容像素数量（源题 3dc255db 的规则），但实际长度由外部同色标记数量决定——这个"长度来源错位"需要对比内容像素数与弹射长度不一致的多个示例才能归纳出。

## 新题 8：区域物体计数分派不同几何操作

**组合逻辑**：[计数](已有) + [按颜色条件分支](创新：分支条件从颜色类别变为数值区间) + [描边](已有) + [填充](已有) + [重涂色](已有)

**来源原语**：计数(counting) + 网格分区(grid_partition) + 四连通物体(four_conn_object) ← edcc2ff0, 6773b310；按颜色条件分支(color_conditional_branch) ← 2072aba6；描边(border_draw) + 沿边界绘边框(draw_border_frame) ← 6f8cd79b；填充(fill) ← 3eda0437；重涂色(recolor) ← edcc2ff0；分隔线(separator_line) ← 6773b310

**依赖链**：分隔线将网格划分为区域 → 统计每个区域内 4-连通前景物体的数量 → 数量落入不同区间触发不同的几何操作（0→不变，1→描边，2→全填充，3+→重涂色+描边）。这不是线性流水线而是条件分派结构：同一个计数结果导致不同输出形态，求解者必须同时学习计数规则和四个分支的映射。

根据分隔线分割出的每个区域内小物体的数量，对该区域施加不同的几何操作——从不变、描边、全填充到重涂色加描边。

**输入结构**：
- 背景：黑(0)，网格约 16x16。
- 灰(5)的完整宽度分隔行和完整高度分隔列将网格划分为 3x3 共 9 个矩形区域（每个区域约 4x4 内部单元）。
- 每个区域内包含 0~4 个小型 4-连通前景物体（每个物体 2~5 像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中取，同一区域内各物体颜色可相同或不同），散布在黑(0)背景上。物体形状各异，非固定几何模式。
- 生成约束：9 个区域中至少各有一个区域分别包含 0、1、2、3 个物体（保证四个分支都出现）。同一区域内的物体互不相邻（4-连通意义上各自独立）。

**规则**：
1. 对每个区域，统计其中 4-连通前景物体的数量 K（忽略物体颜色，仅计数独立连通分量）。
2. 根据 K 的值对该区域执行不同操作：
   - **K = 0**：该区域保持不变（全黑）。
   - **K = 1**：在该区域的内部边界（紧贴分隔线或网格边缘的一圈内侧单元）绘制青(8)边框，宽度 1 像素。区域内原有的单个物体保持不变。
   - **K = 2**：将该区域内部全部填充为蓝(1)，覆盖所有原有物体和背景。
   - **K >= 3**：将该区域内所有前景物体的颜色统一重涂为红(2)（形状保持不变），同时在该区域的内部边界绘制青(8)边框，宽度 1 像素。若边框位置与物体像素重叠，边框覆盖物体。
3. 灰(5)分隔线保持不变。

**关键洞察**：计数不是为了汇总信息，而是作为一个条件分派器——同一种"数数"操作的不同结果导向完全不同的几何变换，四个分支必须全部正确识别才能通过所有测试用例。
