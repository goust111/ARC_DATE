## 新题 1：弯折分类光环叠印

**组合逻辑**：[环路追踪 + 分类涂色](已有) → [印章覆盖 + 邻域扩展](已有，但印章颜色由弯折分类决定——创新耦合) → [重涂色](创新：叠印冲突区产生第三色)

**来源原语**：环路追踪/trace_cycle（15663ba9）、分类涂色/classify_and_color（15663ba9）、印章覆盖/stamp_overlay（dc1df850）、邻域扩展/neighborhood_expand（dc1df850）、仅填背景格/only_fill_background（dc1df850）、重涂色/recolor

**依赖链**：环路追踪得到每个像素的弯折类型 → 弯折类型决定该像素光环的颜色 → 不同颜色光环在空间上重叠时产生第三种颜色。删除追踪步骤则无法分类弯折；删除分类则光环无颜色依据；删除重叠规则则无法确定冲突区颜色。

根据环路上每个像素的弯折类型，在其周围印上不同颜色的光环；当两种光环重叠时，重叠区域变为第三种颜色。

**输入结构**：约 15x15 的黑(0)背景网格。绿(3)前景色形成一条或多条闭合正交环路（每条环路为 1 像素宽、4-连通、每个前景像素恰好有 2 个前景邻居）。不同环路互不接触，且均不触碰网格边界。环路包含凸弯折和凹弯折（即环路形状不是简单矩形，至少有一个凹角）。生成约束：任意两个弯折像素的 Chebyshev 距离至少为 1（即它们的 3x3 光环区域可以重叠，但弯折像素本身不相邻），以保证光环重叠模式可辨识。

**规则**：
1. 对每条闭合环路执行环路追踪。在每个前景像素处判定转向：若该像素的两个邻居共线则为直行像素；否则为弯折像素。
2. 对每条环路统计所有弯折像素的转向方向。出现次数较多的方向为凸弯折，出现次数较少的方向为凹弯折。
3. 对每个凸弯折像素，以其为中心在 3x3 邻域内将所有黑(0)背景格涂为黄(4)。不覆盖任何非黑像素（包括绿(3)环路像素和已涂色的光环像素）。
4. 对每个凹弯折像素，以其为中心在 3x3 邻域内将所有黑(0)背景格涂为红(2)。同样不覆盖非黑像素。
5. 凸光环和凹光环的印章按环路追踪顺序依次执行。若某个背景格同时处于某凸弯折的 3x3 范围和某凹弯折的 3x3 范围内，则无论印章顺序如何，该格最终颜色为蓝(1)。具体实现：所有印章完成后，检查每个已涂色格——若它既在某凸弯折的 3x3 范围内又在某凹弯折的 3x3 范围内，则改涂为蓝(1)。
6. 直行像素和环路像素保持绿(3)不变。

**关键洞察**：蓝(1)像素只出现在凸弯折光环与凹弯折光环的空间交集处。求解者必须先正确分类弯折类型，再理解"双重覆盖→第三色"的冲突解决规则，两者缺一不可。不同环路形状产生不同的重叠图案，需要对比多个示例才能确认冲突规则。

## 新题 2：箭头导向生长与像素计数重排

**组合逻辑**：[朝向推断](已有) → [生长 + 遇障碍则绕行](已有，但生长方向由箭头推断决定——创新耦合) → [计数](已有) → [压缩重排 + 像素数定边长](已有，但排序键由路径像素计数决定——创新耦合)

**来源原语**：射线延伸/ray_extend（6e19193c）、朝向推断/dir_inference（6e19193c）、缺角指示方向/missing_corner_dir（6e19193c）、生长/grow（d9f24cd1）、遇障碍则绕行/detour_on_obstacle（d9f24cd1）、计数/counting（ae58858e）、压缩重排/repack（8abad3cf）、面积递增排列/area_ascending_order（8abad3cf）、像素数定边长/pixel_count_determines_side（8abad3cf）

**依赖链**：箭头缺角推断方向 → 沿该方向生长路径（遇灰障碍则向右侧偏移一格绕行）→ 统计每条路径总像素数 → 以像素数为边长的平方根重排为正方形。删除方向推断则不知往哪生长；删除障碍绕行则路径长度不同；删除计数则无法确定正方形大小。

从每个箭头精灵体出发沿其朝向生长路径并绕过障碍，最终将每条路径的总像素数转化为等面积正方形，按大小排列输出。

**输入结构**：约 18x18 的黑(0)背景网格。3-4 个青(8)箭头精灵体（每个约 2x3 或 3x2 像素，为一个小矩形缺去一个角像素，缺角位置指示朝向）。灰(5)障碍像素若干，散布在网格中部，不与箭头精灵体相邻，不位于网格边缘行/列。生成约束：每个箭头在其朝向上到达网格边界的路径不会与其他箭头的路径交叉；每条路径的总像素数（箭头本身 + 路径延伸像素）为完全平方数。

**规则**：
1. 对每个箭头精灵体，根据缺角位置推断朝向：缺角所在方位即为箭头指向（例如右上角缺失则指向右上，取主方向为"向右"——具体地，缺角在精灵体边界框的哪一侧，朝向就是该侧对应的正交方向：上/下/左/右）。
2. 从箭头精灵体边界框在朝向一侧的中心像素开始，沿朝向逐格生长路径，使用青(8)涂色。若下一格是灰(5)障碍，则改为向朝向的顺时针 90 度方向移动一格（例如朝向为"上"时，顺时针 90 度为"右"），然后恢复原朝向继续生长。若连续遇到障碍（绕行后前方仍是障碍），继续同方向绕行。路径到达网格边界时停止。
3. 统计每条路径的总青(8)像素数，包括箭头精灵体自身的像素。
4. 清空整个网格为黑(0)。将每个箭头+路径组重新绘制为一个实心青(8)正方形，边长 = sqrt(该组总像素数)。
5. 所有正方形沿网格底边从左到右排列，按边长从小到大排序，相邻正方形之间留一列黑(0)间隔。最左侧正方形的左边缘贴网格左边界。

**关键洞察**：障碍的位置会改变每条路径的实际长度（绕行增加像素数），因此正方形的大小和排列顺序无法仅凭箭头位置预测——必须实际模拟路径生长才能计数，再由计数决定重排结果。

## 新题 3：分隔线标记压缩与窗口色彩映射

**组合逻辑**：[填充 + 标记色定窗口填充](已有) ← [坐标压缩](已有，但压缩目标由分隔线上的标记像素指定——创新耦合) → 输出为压缩后的已填充网格（创新：填充在压缩前执行，但输出是压缩后的结果）

**来源原语**：填充/fill（54d9e175）、坐标压缩/coordinate_compression（7d419a02）、分隔线/separator_line（54d9e175, 7d419a02）、标记像素/marker_pixel（54d9e175）、窗口格/window_cell（54d9e175）、颜色配对映射/color_pair_mapping（54d9e175）

**依赖链**：分隔线上的特殊标记指示哪些分隔线将被压缩移除 → 窗口中心标记决定填充颜色 → 填充后再按标记压缩分隔线 → 压缩合并相邻同色窗口。删除标记识别则不知压缩哪些分隔线；删除填充则压缩后窗口内容不确定；两者顺序不可调换（压缩后中心标记位置失效）。

在分隔线划分的窗口中按中心标记颜色填色，随后移除被特殊标记的分隔线，输出压缩后的网格。

**输入结构**：约 15x15 的网格。黑(0)背景。灰(5)完整行和完整列构成分隔线，将网格划分为若干 3x3 窗口。每个窗口中心恰有一个前景标记像素，颜色为蓝(1)、红(2)、绿(3)或黄(4)中的一种。部分灰(5)分隔线（行或列）上恰有一个像素被替换为青(8)，该青像素标记此分隔线将被压缩移除。生成约束：被标记的分隔线不包括网格最外圈的边框分隔线（如果有的话）；被标记分隔线的两侧窗口中心标记颜色相同（确保压缩后合并无冲突）。

**规则**：
1. 颜色配对映射：蓝(1)→品红(6)，红(2)→橙(7)，绿(3)→青(8)，黄(4)→栗(9)。
2. 将每个 3x3 窗口的全部 9 个像素替换为其中心标记的映射色，形成实心色块。
3. 灰(5)分隔线保持不变——除了含青(8)标记的分隔线。
4. 移除每条含青(8)标记的分隔线（整行或整列）：将该行/列删除，两侧内容合并紧贴。若被移除分隔线两侧的窗口填充色相同，它们合并为一个更大的同色矩形区域。
5. 输出为压缩后的网格，尺寸小于输入。

**关键洞察**：填充必须在压缩之前执行，因为中心标记的位置只在未压缩网格中有意义。压缩移除分隔线后，相邻同色窗口无缝合并，形成比单个窗口更大的色块——求解者必须理解"先填后压"的时序，而非"先压后填"。需要对比多个示例才能发现青(8)标记仅出现在两侧同色窗口之间的分隔线上这一生成约束。

## 新题 4：路径穿越区域的周期性洪泛填充

**组合逻辑**：[寻路 + 生长 + 遇障碍则绕行](已有) → [洪泛填充 + 封闭区域](已有，但填充对象由路径穿越顺序决定——创新耦合) → [等间隔采样填充](已有，但采样序列作用于穿越序列而非空间位置——创新耦合)

**来源原语**：寻路/pathfinding（d9f24cd1）、生长/grow（d9f24cd1）、遇障碍则绕行/detour_on_obstacle（d9f24cd1）、洪泛填充/flood_fill（7447852a）、封闭区域/enclosed_region（7447852a）、区域排列顺序/region_order（7447852a）、等间隔采样填充/periodic_fill（7447852a）

**依赖链**：路径从起点生长并绕过障碍 → 路径依次穿越若干封闭区域 → 穿越顺序决定区域编号 → 按周期模式（每隔 3 个）选择区域进行洪泛填充。删除路径生长则无法确定穿越顺序；删除周期采样则不知填充哪些区域；穿越顺序取决于障碍布局，与区域空间位置不完全一致。

从起点出发生长路径穿越由边界线划分的区域，按路径穿越顺序对区域编号，然后对编号为 0、3、6... 的区域洪泛填充特定颜色。

**输入结构**：约 15x20 的黑(0)背景网格。红(2)线条构成不规则边界，将网格分割为 6-10 个封闭区域（每个区域为 4-连通的黑(0)像素块，被红线完全包围）。红线上有若干处宽度为 1 像素的缺口（通道），允许从一个区域进入另一个区域。一个蓝(1)起点像素位于网格底部某个区域内。灰(5)障碍像素散布在部分通道前方（在通道的正前方一格），迫使路径绕行至其他通道。生成约束：从起点出发，每个区域恰好有唯一可达的下一个区域（不会出现路径分叉的情况）；路径最终覆盖所有区域。

**规则**：
1. 从蓝(1)起点像素出发，逐格向上生长路径。路径使用蓝(1)绘制。
2. 当路径前方是红(2)边界线时，沿当前行向右搜索最近的通道（红线缺口）。若通道前方一格有灰(5)障碍，跳过此通道继续向右搜索。找到无障碍通道后，路径水平移动至通道位置，穿过通道进入下一个区域，然后恢复向上生长。
3. 路径依次穿越区域，记录穿越顺序：第一个进入的区域编号为 0，第二个为 1，依此类推。起点所在区域编号为 0。
4. 对编号满足 n mod 3 = 0 的区域（即 0、3、6、...），将区域内所有黑(0)像素洪泛填充为黄(4)。路径像素蓝(1)不被覆盖。
5. 对编号满足 n mod 3 = 1 的区域，洪泛填充为绿(3)。
6. 对编号满足 n mod 3 = 2 的区域，保持黑(0)不变。
7. 红(2)边界线、灰(5)障碍、蓝(1)路径像素均保持原色。

**关键洞察**：区域的填充颜色不由空间位置决定（不是"从左到右第几个"），而由路径的穿越顺序决定。灰障碍堵住某些通道后，路径被迫走另一条路线，改变穿越顺序，进而改变颜色分配。求解者必须模拟路径行为才能确定顺序。

## 新题 5：拉伸线段网络的间隙修复

**组合逻辑**：[拉伸 + 顶点坐标映射 + 行列独立拉伸](已有) → [间隙填充 + 端点朝向](已有，但间隙产生于拉伸过程——创新耦合) → [标记归属最近线](已有，但标记指示哪些间隙需要修复——创新耦合)

**来源原语**：拉伸/stretch（b0f4d537）、连线/connect（b0f4d537）、顶点坐标映射/vertex_coord_mapping（b0f4d537）、行列独立拉伸/independent_stretch（b0f4d537）、间隙填充/gap_fill（faa9f03d）、修复/repair（faa9f03d）、端点朝向/endpoint_facing（faa9f03d）、标记归属最近线/marker_assigned_to_nearest_line（faa9f03d）、标记像素/marker_pixel（faa9f03d）

**依赖链**：紧凑原型通过锚点映射拉伸到大画布 → 拉伸产生间隙（某些线段端点不再对齐）→ 绿标记像素标识需要修复的间隙 → 按端点朝向填充间隙。删除拉伸则无线段网络可修复；删除标记识别则不知哪些间隙需要填充（有些间隙是结构性的，不应填充）；删除端点朝向判断则填充方向不确定。

将紧凑线段原型拉伸到稀疏锚点画布上，然后利用标记像素定位并修复拉伸过程中产生的线段间隙。

**输入结构**：约 20x20 的网格，灰(5)完整列将其分为左右两个面板。左面板（约 6x6）：紧凑彩色线段原型，由蓝(1)和红(2)水平/垂直线段组成，线段在端点、拐角或交叉处形成图论顶点（度数不为 2 的前景像素）。右面板（约 12x12）：黑(0)背景上有若干黄(4)锚点像素，布局与左面板顶点的行列排序一一对应（但间距不均匀）。右面板中还有若干绿(3)单像素标记，散布在锚点之间的空白区域。生成约束：左面板的每条线段在拉伸后，其两端点之间的锚点行或列完全对齐（同行或同列）；绿标记像素恰好落在两个面对面（facing）的拉伸线段端点之间的间隙中。

**规则**：
1. 在左面板中识别所有图论顶点（度数 ≠ 2 的前景像素）。按行坐标排序得到行序列，按列坐标排序得到列序列。
2. 右面板的黄(4)锚点像素按相同方式排序。将左面板的第 k 个行坐标映射到右面板的第 k 个行坐标，列坐标同理。
3. 将左面板的每条线段拉伸到右面板：线段的两个端点通过坐标映射确定新位置，线段在映射后的行/列区间内绘制为连续像素，保持原色（蓝或红）。
4. 拉伸后，右面板某些相邻线段的端点之间可能存在 1-3 像素的间隙。
5. 对每个绿(3)标记像素，沿其所在行和列搜索最近的拉伸线段端点。将标记归属于那条端点正对（facing）该标记方向的线段。
6. 对每个被标记的间隙，用所归属线段的颜色（蓝或红）填充从该线段端点到对面最近同色端点之间的所有空白像素。绿标记像素自身也被替换为该线段颜色。
7. 未被绿标记指示的间隙保持黑(0)不变。
8. 左面板和灰分隔列在输出中移除，输出仅包含右面板。

**关键洞察**：绿标记像素的作用是区分"结构性间隙"（原型中本就不连通的线段之间的空隙）和"拉伸间隙"（同一线段拉伸后端点未对齐产生的裂缝）。只有被标记的间隙会被修复，这需要求解者理解标记的选择性修复语义。

**规则**：
1. 识别完整黑(0)分隔线（贯穿整个网格宽度/高度的纯黑行或列，不含任何前景像素）。移除这些分隔线，将网格坐标压缩。
2. 在压缩后的网格上追踪青(8)环路。对每个像素判定：直行、凸弯折（多数转向方向）或凹弯折（少数转向方向）。

4. 输出着色（在压缩后的网格上）：
   - 沙漏区域内的环路像素：无论弯折类型，一律涂为黄(4)。
   - 沙漏区域外的凸弯折像素：涂为红(2)。
   - 沙漏区域外的凹弯折像素：涂为绿(3)。
   - 沙漏区域外的直行像素：保持青(8)。
5. 品红(6)标记在输出中保持不变。背景保持黑(0)。
6. 输出网格为压缩后的尺寸（小于输入）。

**关键洞察**：沙漏遮罩优先级高于弯折分类——一个凸弯折若在沙漏内则变黄而非变红。求解者必须同时理解两个独立机制（弯折分类和沙漏距离）及其优先级关系，这只能通过对比沙漏边界附近的像素颜色来归纳。

## 新题 7：字形解码驱动的窗口填充与邻接合并重涂

**组合逻辑**：[解码 + 字形映射颜色行](已有，但映射对象从行变为窗口填充色——创新改造) → [填充](已有) → [计数 + 面积超阈值则变色](已有，但"面积"重新定义为同色邻接窗口数——创新耦合)

**来源原语**：解码/decode（995c5fa3）、字形图案/glyph_pattern（995c5fa3）、位置映射/positional_mapping（995c5fa3）、填充/fill（54d9e175）、窗口格/window_cell（54d9e175）、分隔线/separator_line（54d9e175）、计数/counting（ae58858e）、重涂色/recolor（ae58858e）、面积超阈值则变色/recolor_above_threshold（ae58858e）、连通分量/connected_component（ae58858e）

**依赖链**：字形解码确定每个窗口的填充色 → 填充后识别同色邻接窗口群 → 若群组窗口数达到阈值则整体重涂为第二色。删除解码则窗口无颜色；删除邻接分析则无法判断合并；删除阈值则不知哪些群组变色。

**输入结构**：约 17x17 的网格。灰(5)完整行和完整列构成分隔线，将网格划分为 4x4（或 3x3）的窗口阵列，共 9-16 个窗口。每个窗口内为一个 4x4 的灰(5)+黑(0)字形图案（灰像素构成图案，黑像素为该字形的"孔洞"——即字形由灰底上的黑色掩码定义）。共有 4 种不同的字形掩码图案，每种对应一种颜色：第一种→红(2)，第二种→青(8)，第三种→黄(4)，第四种→绿(3)。字形掩码图案在不同示例中保持一致。生成约束：至少存在一个由 3 个以上同色相邻窗口构成的连通群组；窗口之间通过灰分隔线分隔，相邻指共享一条分隔线（上下或左右）。

**规则**：
1. 对每个窗口，提取其 4x4 内容。黑(0)像素在灰(5)底上的位置构成字形掩码图案。
2. 将掩码图案与 4 种已知图案比较（精确匹配，不考虑旋转/反射），确定对应颜色。
3. 将整个窗口（含原有灰和黑像素）替换为对应颜色的实心 4x4 色块。
4. 灰(5)分隔线保持不变。

6. 若某群组包含 3 个或更多窗口，将该群组内所有窗口重涂为品红(6)。
7. 包含 1 或 2 个窗口的群组保持原解码颜色不变。

**关键洞察**：最终颜色不仅取决于单个窗口的字形解码，还取决于解码后相邻窗口是否"碰巧"解码为同一颜色并形成大群组。求解者必须先破解字形-颜色映射（需对比多个示例中同一字形总是产生同一颜色），再理解群组阈值规则（需观察到大群组被统一重涂）。

## 新题 8：压缩匹配筛选下的方向性射线延伸

**组合逻辑**：[形状匹配 + 压缩 + 旋转反射等价](已有) → [射线延伸](已有，但射线方向由匹配时的旋转变换决定——创新耦合：匹配过程的副产物成为后续操作的参数) → [重涂色](已有，区分匹配与不匹配的候选)

**来源原语**：形状匹配/shape_match（bd14c3bf）、压缩/compress（bd14c3bf）、旋转反射等价/rotation_reflection_eq（bd14c3bf）、游程压缩后比较/run_length_compare（bd14c3bf）、射线延伸/ray_extend（6e19193c）、朝向推断/dir_inference（6e19193c）、重涂色/recolor（ae58858e）

**依赖链**：压缩候选形状并与原型比较 → 匹配成功的候选获得一个旋转/反射变换 → 该变换应用于预定义的"原型朝向"得到该候选的实际射线方向 → 沿该方向延伸射线。删除压缩匹配则不知哪些候选参与射线延伸；删除旋转提取则无法确定射线方向；两者不可替换顺序。

用游程压缩后的形状匹配筛选候选对象，匹配时所用的旋转变换同时决定每个候选发射射线的方向。

**输入结构**：约 16x16 的黑(0)背景网格。左上角有一个小的红(2)原型形状（3-5 像素的 4-连通不规则形状，不对称，裁剪后约 2x3 或 3x3，可能有行/列重复）。网格其余区域散布 4-6 个青(8)候选形状，每个约 3-8 像素。部分候选是原型在行/列方向上拉伸后的旋转/反射变体（压缩后与原型匹配）；其余候选与原型无关（压缩后仍不匹配）。候选之间互不接触，且与原型不接触。生成约束：原型定义一个"参考朝向"为"向右"（原型边界框最右列的前景像素数多于最左列——即形状重心偏右）；每个匹配候选的射线路径不穿过其他候选的边界框。

**规则**：
1. 裁剪原型至其边界框。对原型执行游程压缩（按行逐行，连续相同的行合并为一行；按列逐列，连续相同的列合并为一列），得到原型的压缩掩码。
2. 对每个候选形状执行同样的裁剪+压缩，得到候选压缩掩码。
3. 将每个候选压缩掩码与原型压缩掩码在 4 种旋转 x 2 种反射 = 8 种变换下比较。若某变换下完全一致，该候选为"匹配"，记录所用变换 T。若多种变换均匹配，取旋转角度最小的那个（0° > 90° > 180° > 270°），角度相同则取不反射的。
4. 原型的参考朝向为"向右"。对匹配候选，将"向右"经变换 T 的逆变换，得到该候选的射线方向（上/下/左/右之一）。
5. 从匹配候选边界框在射线方向一侧的中心像素出发，沿射线方向绘制青(8)直线至网格边界。射线像素涂为青(8)。
6. 匹配候选自身重涂为黄(4)以区分。
7. 不匹配的候选保持青(8)不变，不发射射线。
8. 原型保持红(2)不变。

**关键洞察**：形状匹配过程产生的旋转变换不仅是"是否匹配"的布尔判断，还携带了方向信息——同一形状的不同旋转变体会发射不同方向的射线。求解者必须从多个示例中归纳出"匹配旋转决定射线方向"这一非显然的耦合关系。

## 新题 9：双约束区域着色

**组合逻辑**：[洪泛填充 + 封闭区域](已有) ← [排序 + 区域排列顺序](已有) + [计数](已有) → [重涂色](创新：颜色由空间位置奇偶性和标记数量的双重约束共同决定——同时约束满足结构，非流水线)

**来源原语**：洪泛填充/flood_fill（7447852a）、封闭区域/enclosed_region（7447852a）、排序/sort（7447852a）、区域排列顺序/region_order（7447852a）、计数/counting（ae58858e）、面积超阈值则变色/recolor_above_threshold（ae58858e）、重涂色/recolor（694f12f3）、面积排名映射色/area_rank_maps_color（694f12f3）

**依赖链**：洪泛填充识别所有封闭区域 → 同时需要：(A) 按空间位置排序判定奇偶性，(B) 统计区域内标记数量判定是否"富标记" → 两个独立判据交叉形成 2x2 决策矩阵 → 矩阵的四个象限对应四种输出颜色。任一判据缺失则颜色退化为二分类，无法确定全部四种颜色。

识别由边界线划分的所有封闭区域，根据每个区域的空间位置奇偶性和内部标记数量的双重组合确定其填充颜色。

**输入结构**：约 16x16 的黑(0)背景网格。红(2)线条形成不规则边界，将网格分割为 6-10 个封闭区域。每个区域内部散布若干蓝(1)标记像素（0-5 个不等）。区域形状各异（非全是矩形），面积不完全相同。生成约束：区域的边界框中心 x 坐标互不相同（保证左右排序无歧义）；四种颜色组合在示例中均至少出现一次。

**规则**：
1. 以红(2)线为边界，对黑(0)背景执行洪泛填充，识别所有封闭区域。触碰网格边界的外部区域不计入。
2. 约束 A——空间排序：按每个区域边界框中心的 x 坐标从左到右排序，编号 0, 1, 2, ...。编号为偶数的区域标记为"偶位"，编号为奇数的标记为"奇位"。
3. 约束 B——标记计数：统计每个区域内蓝(1)标记像素的数量。数量 >= 3 的标记为"富标记"，数量 < 3 的标记为"贫标记"。
4. 颜色决策矩阵：
   - 偶位 + 富标记 → 填充为黄(4)
   - 偶位 + 贫标记 → 填充为绿(3)
   - 奇位 + 富标记 → 填充为橙(7)
   - 奇位 + 贫标记 → 填充为灰(5)
5. 用决定的颜色洪泛填充每个区域内的所有黑(0)像素。蓝(1)标记像素也被替换为该区域的填充色。
6. 红(2)边界线保持不变。

**关键洞察**：四种输出颜色形成 2x2 矩阵，由空间位置和标记数量两个正交维度共同决定。仅凭单个示例无法分离两个维度——例如一个黄(4)区域可能被误认为"所有左侧区域都是黄色"或"所有标记多的区域都是黄色"。至少需要两个示例才能归纳出双约束结构。
