## 新题 1：射线穿透式格点腔室填色

**组合逻辑**：[射线延伸](创新：从标记点出发穿透整个格点骨架，穿过多个腔室) + [填充](创新：由射线穿过与否决定哪些腔室被填色) + [擦除](已有) ← [方向帽](创新：从边框方向帽改为标记像素的方向指示器) + [格点骨架/封闭腔室](已有) + [邻接/距离比较](创新：射线冲突时取距离更近的标记色)

**来源原语**：射线延伸(ray_extend, 4e469f39), 填充(fill, 17b866bd), 擦除(erase, 17b866bd), 格点骨架(lattice_frame, 17b866bd), 封闭腔室(enclosed_cavity, 17b866bd), 标记像素(marker_pixel, 17b866bd), 方向帽(direction_cap, 4e469f39), 邻接(adjacent, 17b866bd)

**依赖链**：方向指示器决定射线方向 → 射线穿过格点确定命中腔室集合 → 命中腔室被填充为射线来源标记的颜色 → 多射线命中同一腔室时，距离更近的标记优先（冲突解决依赖空间距离）。三层操作通过空间交集和距离条件交织。

从标记像素出发沿指定方向射出射线穿透格点骨架，射线经过的每个封闭腔室被填充为该标记的颜色，多射线冲突时近者优先。

**输入结构**：约 15x15 的网格。青(8)像素构成周期性格点骨架，围成若干黑(0)封闭腔室（每个腔室约 12 个像素，参照 5x5 瓷砖结构中骨架围合的矩形空腔）。格点骨架中某些瓷砖的西北角间隙位置放置彩色标记像素（非黑、非青），每个标记像素旁有一个同色的方向指示像素与之 4-邻接，两像素合成一个 2 像素的方向指示器。方向指示器的朝向（指示像素相对标记像素的方位：上/下/左/右）编码射线方向。标记颜色可选红(2)、绿(3)、黄(4)等，每种颜色最多出现一个标记。生成约束：每个腔室最多被两条射线经过；不同标记的方向指示器不冲突（无标记与另一标记重叠）。

**规则**：
1. 对每个标记，读取其方向指示像素的相对方位：上 → 射线向上，下 → 射线向下，左 → 射线向左，右 → 射线向右。
2. 将标记像素及其方向指示像素擦除为黑(0)。
3. 从标记位置沿射线方向逐像素延伸，射线穿过骨架和腔室，直至到达网格边界。记录射线经过的所有腔室（射线至少穿过腔室内一个黑(0)像素即算经过）。
4. 将每个被射线经过的腔室内所有黑(0)像素填充为该标记的颜色。
5. 若同一腔室被两条来自不同标记的射线经过，取标记位置到该腔室中心的曼哈顿距离更小的标记颜色进行填充；若距离相等，取标记位置更靠近网格左上角（先比行号再比列号）的标记颜色。
6. 未被任何射线经过的腔室保持黑(0)不变。青(8)骨架像素全部保留不变。

**关键洞察**：标记不直接填充邻近腔室，而是通过方向指示器编码的射线穿透整个格点，远距离决定多个腔室的颜色——射线的空间路径是填充操作的选择器，冲突解决需要比较距离，三者不可分离。

## 新题 2：图元分解驱动的同色滑动归位

**组合逻辑**：[分解](已有) → [重涂色](创新：由分解后的图元形状决定颜色) → [滑动](创新：滑动方向和目标由重涂色结果的颜色决定) + [碰撞阻挡](创新：不同图元间滑动碰撞) + [擦除](创新：无法匹配的残余像素删除)

**来源原语**：分解(decompose, 150deff5), 重涂色(recolor, 150deff5), 基本图元(primitive_shape, 150deff5), 图元形状决定涂色(shape_determines_color, 150deff5), 滑动(slide, 1a07d186), 满行列条(full_span_bar, 1a07d186), 同色配对(same_color_pairing, 1a07d186), 碰撞阻挡(collision_blocking, 1a07d186), 无匹配色则删除(unmatched_deleted, 1a07d186), 擦除(erase, 1a07d186)

**依赖链**：灰色复合体被分解为基本图元 → 图元形状决定重涂颜色（正方形→青、矩形→红）→ 重涂颜色与满行列条颜色配对 → 配对成功的图元朝目标条滑动 → 滑动时图元间碰撞阻挡决定最终停靠位置。分解结果直接改变了滑动操作的目标和路径。

将灰色复合形状分解为正方形和矩形图元，按形状涂色后分别滑向同色满行列条，碰撞时先到者阻挡后到者。

**输入结构**：约 12x12 的黑(0)背景网格。包含一条青(8)全宽水平条（占据某一整行）和一条红(2)全高垂直条（占据某一整列），两条条交叉处为青(8)（水平条优先）。网格其余区域散布 2~3 个灰(5)复合形状，每个复合体由若干紧邻的 2x2 正方形和 1x3 或 3x1 矩形拼接而成（4-连通），总像素数 7~13。生成约束：每个复合体存在唯一的非重叠分解方案；所有图元与两条满行列条之间无遮挡冲突使得至少存在一种合法滑动顺序；灰色复合体不与满行列条重叠。

**规则**：
1. 将每个灰(5)复合形状分解为不重叠的 2x2 正方形和 1x3/3x1 矩形（唯一分解）。
2. 将每个 2x2 正方形重涂为青(8)，每个 1x3/3x1 矩形重涂为红(2)。
3. 青(8)图元沿垂直方向朝青(8)水平条滑动（向上或向下，取决于图元在水平条的哪一侧）。红(2)图元沿水平方向朝红(2)垂直条滑动（向左或向右，取决于图元在垂直条的哪一侧）。
4. 滑动顺序：按图元中心到其目标条的曼哈顿距离从小到大处理（最近者先滑动）。每个图元滑动直至其边缘接触目标条或已停靠的同方向图元为止。
5. 若分解后存在无法归入 2x2 或 1x3/3x1 的残余灰(5)像素，擦除为黑(0)。
6. 满行列条本身保持不变。

**关键洞察**：分解结果不只决定颜色外观——它决定了每个图元的运动方向和目标，进而影响碰撞顺序和停靠位置。不先正确分解就无法确定滑动行为。

## 新题 3：连接点方向编码的旋转印章

**组合逻辑**：[旋转](创新：旋转角度由连接点的方位编码，而非预设固定值) + [印章覆盖](创新：印章图案旋转后覆盖，中心色由连接点颜色填入) + [擦除](已有) ← [连接点](创新：从对接用途改为编码旋转参数和颜色参数的双通道信息载体) + [孤立像素](已有) + [十字图案](已有) + [中心展开](已有)

**来源原语**：旋转(rotate, 97a05b5b/a416fc5b), 印章覆盖(stamp, b60334d2), 擦除(erase, a416fc5b), 连接点(connector_pixel, 20270e3b), 孤立像素(isolated_pixel, b60334d2/67385a82), 十字图案(cross_pattern, b60334d2), 中心展开(center_expansion, b60334d2), 对接对齐(docking_alignment, 20270e3b)

**依赖链**：连接点的方位编码旋转角度（位置通道）→ 固定模板按该角度旋转 → 旋转后的模板覆盖到孤立像素位置 → 连接点的颜色填入模板中心（颜色通道）→ 连接点自身被擦除。单个像素同时编码几何变换参数和颜色参数，两个通道必须同时正确解码才能得到正确输出。

读取每个孤立灰像素旁连接点的方位来旋转固定 3x3 模板，再用连接点的颜色填充模板中心，最后擦除连接点。

**输入结构**：约 11x11 的黑(0)背景网格。散布 3~4 个孤立的灰(5)像素，每个灰像素周围 3x3 范围内只有一个非黑非灰的彩色像素（连接点），与灰像素 4-邻接（上/右/下/左之一）。各连接点颜色互不相同，可为红(2)、绿(3)、黄(4)、品红(6)等。所有孤立灰像素之间距离足够大（各自的 3x3 印章范围互不重叠）。固定模板定义：中心 = 黑(0)，四对角 = 灰(5)，四正交 = 蓝(1)（与参考题 b60334d2 的模板一致但会被旋转）。生成约束：每个灰像素的 3x3 邻域内恰好有一个连接点；连接点不出现在网格边缘导致印章越界的位置。

**规则**：
1. 定义固定 3x3 模板（未旋转状态）：中心 = 黑(0)；上/下/左/右 = 蓝(1)；四对角 = 灰(5)。
2. 对每个孤立灰(5)像素，读取其连接点的方位：连接点在灰像素的上方 → 旋转 0 度；右方 → 顺时针旋转 90 度；下方 → 旋转 180 度；左方 → 顺时针旋转 270 度。
3. 将模板按步骤 2 确定的角度旋转。
4. 将旋转后的模板以灰像素位置为中心覆盖到网格上（覆盖原有像素）。
5. 将模板中心（原为黑(0)）替换为该连接点的颜色。
6. 擦除连接点像素为黑(0)（若连接点位于模板覆盖区域内，则被模板覆盖后再处理；若在覆盖区域外，直接擦除）。
7. 不同孤立像素的印章互不重叠（由生成约束保证），因此无冲突。

**关键洞察**：连接点是一个双通道编码器——其空间位置（上/右/下/左）编码几何旋转角度，其颜色编码中心填色。求解者必须同时解码两个独立信息通道，缺一不可。

## 新题 4：标记列位置控制反转填充色

**组合逻辑**：[反转填充](创新：填充色不固定，由同行标记的列位置决定) + [重涂色](创新：列位置→颜色映射应用于整行瓷砖的反转结果) + [擦除](创新：标记瓷砖整体清除) ← [瓷砖/分隔行列](已有) + [标记像素](创新：从控制单行颜色扩展为控制同行所有瓷砖的反转色) + [列位置映射](已有) + [瓷砖网格排列](已有)

**来源原语**：反转填充(occupancy_inversion, 1c0d0a4b), 重涂色(recolor, a85d4709), 擦除(erase, a416fc5b), 瓷砖(tile, 1c0d0a4b), 分隔行列(separator_rows_and_columns, 1c0d0a4b), 标记像素(marker_pixel, a85d4709), 列位置映射(column_position_mapping, a85d4709), 标记列决定整行色(marker_column_determines_row_color, a85d4709), 瓷砖网格排列(tile_grid_layout, 1c0d0a4b)

**依赖链**：识别瓷砖网格结构 → 在每行瓷砖中定位含灰标记的特殊瓷砖 → 读取灰标记在特殊瓷砖内的列位置 → 列位置映射为颜色 → 该颜色用于同行所有非标记瓷砖的反转填充 → 标记瓷砖本身清除。标记位置横向控制反转色，反转操作纵向改变每个瓷砖内容，两者在瓷砖网格上形成行列交叉依赖。

在瓷砖网格中，每行有一个含灰标记的特殊瓷砖，其列位置映射为颜色；同行其余瓷砖做占位反转，反转后的前景色即为该映射颜色。

**输入结构**：约 11x11 的网格，被单像素宽的黑(0)分隔行和分隔列划分为 3x3 瓷砖的规则网格（例如 3 行 3 列共 9 个瓷砖）。每个瓷砖为 3x3。大部分瓷砖中包含若干青(8)前景像素和若干黑(0)背景像素（各瓷砖的青色图案不同）。每一行瓷砖（同一瓷砖行）中恰好有一个瓷砖是"标记瓷砖"：该瓷砖内仅含一个灰(5)像素，其余 8 格为黑(0)。灰像素在 3x3 瓷砖内的列位置（左列/中列/右列）在不同行间不同。生成约束：每行恰好一个标记瓷砖；标记瓷砖的灰像素位于 3x3 瓷砖的任意位置但列位置（左/中/右）是有意义的编码。

**规则**：
1. 识别网格中的分隔行列和 3x3 瓷砖。
2. 在每一行瓷砖中，找到标记瓷砖（内含灰(5)像素的瓷砖）。
3. 读取灰(5)像素在其 3x3 瓷砖内的列位置：左列（第 0 列）→ 红(2)，中列（第 1 列）→ 黄(4)，右列（第 2 列）→ 绿(3)。
4. 将标记瓷砖内所有像素擦除为黑(0)（含灰像素本身）。
5. 对同一行中的每个非标记瓷砖执行反转填充：将该瓷砖内的青(8)像素改为黑(0)，将该瓷砖内的黑(0)像素改为步骤 3 确定的颜色。
6. 分隔行列保持黑(0)不变。

**关键洞察**：灰标记不在它所控制的瓷砖内——它位于同行的另一个瓷砖中，且其列位置（而非颜色或形状）编码了整行瓷砖反转后的填色。求解者必须跨瓷砖读取控制信息，这种行级广播关系在单个示例中难以归纳。

## 新题 5：面积决定角色的同色滑动对接

**组合逻辑**：[滑动](创新：滑动方向由配对对象的相对位置决定，滑动角色由面积比较决定) + [对接拼合](创新：滑动终止条件为连接点邻接而非固定碰撞) + [重涂色](创新：对接后连接点涂为大精灵体的前景色) + [擦除](已有) ← [面积比较](创新：面积大小决定运动/静止角色) + [同色配对/连接点颜色匹配](创新：连接点颜色用于配对而非对齐) + [碰撞停止](已有)

**来源原语**：滑动(slide, 1a07d186), 对接拼合(docking, 20270e3b), 重涂色(recolor, 67385a82), 擦除(erase, 20270e3b), 精灵体(sprite, 20270e3b), 连接点(connector_pixel, 20270e3b), 面积比较(area_comparison, 67385a82), 同色配对(same_color_pairing, 1a07d186), 连接点颜色匹配(connector_color_match, 20270e3b), 碰撞阻挡(collision_blocking, 1a07d186), 碰撞停止(collision_stop, 332f06d7)

**依赖链**：连接点颜色匹配 → 精灵体配对 → 面积比较确定每对中谁移动谁静止 → 小精灵体沿直线滑向大精灵体 → 滑动终止于连接点 4-邻接（对接）→ 对接后连接点涂为大精灵体前景色，小精灵体原位擦除。面积比较是滑动的前提条件，连接点匹配是配对和对接的双重依据。

通过连接点颜色配对精灵体，面积较小者沿直线滑向面积较大者，直到双方连接点 4-邻接后合并，连接点涂为大精灵体颜色。

**输入结构**：约 14x14 的黑(0)背景网格。散布 4~6 个 4-连通单色精灵体（每个精灵体 3~8 像素，形状不规则），精灵体的前景色各不相同，可选蓝(1)、红(2)、绿(3)、橙(7)等。每个精灵体的边界上有恰好一个连接点像素，颜色与精灵体前景色不同。连接点颜色用于配对：恰好两个精灵体共享同一连接点颜色，形成一对。每对中两个精灵体的面积（不含连接点）不同。配对数为 2~3 对。生成约束：每对中较小精灵体的连接点朝向较大精灵体方向（上/下/左/右之一），且沿该方向到大精灵体的连接点之间无其他精灵体遮挡；不同对的滑动路径互不交叉。

**规则**：
1. 按连接点颜色配对精灵体：共享同一连接点颜色的两个精灵体为一对。
2. 在每对中，比较两个精灵体的面积（不含连接点像素的前景像素数）。面积较大者为"锚"（静止），面积较小者为"活动体"（滑动）。
3. 活动体沿其连接点朝向锚的方向（上/下/左/右，取连接点相对活动体重心最近的基本方向）做直线平移，每步移动 1 像素。
4. 当活动体的连接点与锚的连接点成为 4-邻接时，停止滑动。
5. 将活动体和锚的两个连接点都重涂为锚的前景色。
6. 将活动体滑动前的原始位置（所有像素）擦除为黑(0)。活动体在新位置保留其原始前景色。
7. 各对独立处理，处理顺序不影响结果（由生成约束保证路径无交叉）。

**关键洞察**：面积大小决定了谁移动、谁不动——这不是由空间位置或颜色编号决定的，而是由对象的几何属性（面积）决定的动态角色分配，必须对比多个配对示例才能归纳出此规则。

**依赖链**：识别瓷砖网格 → 对每个瓷砖执行占位反转（青→黑，黑→青）→ 反转后全为青(8)的瓷砖（原来全为黑的空瓷砖）变为"墙"→ 反转后仍含黑(0)像素的瓷砖变为"通道"→ 在瓷砖级别寻找起点到终点的最短路径 → 路径上的通道瓷砖内的黑(0)像素填为黄(4)。反转操作的结果不是最终输出，而是中间判据——这种"操作为条件服务"的结构与常见"操作为结果服务"截然不同。

先对每个瓷砖做占位反转，全填满的瓷砖成为墙壁、仍有空隙的成为通道，然后在瓷砖级别寻路并填色标记路径。

**输入结构**：约 11x11 的网格，由单像素黑(0)分隔行列划分为 3x3 瓷砖的规则网格（如 3 行 3 列共 9 个瓷砖）。每个瓷砖 3x3，内含若干青(8)前景像素和若干黑(0)背景像素（每个瓷砖的青色图案不同，有的像素多有的像素少）。有两个特殊瓷砖：一个全为红(2)（起点），一个全为绿(3)（终点）。其余瓷砖为青黑混合。生成约束：在反转后的瓷砖网格中，从起点到终点存在通过通道瓷砖（4-邻接）的路径；全黑的原始瓷砖（反转后变全青=墙）的分布使路径唯一；原始全青瓷砖（反转后变全黑=通道）不能太多以保持一定难度。

**规则**：
1. 识别分隔行列和 3x3 瓷砖网格。红(2)瓷砖为起点，绿(3)瓷砖为终点。
2. 对每个青黑混合瓷砖执行占位反转：青(8)像素 → 黑(0)，黑(0)像素 → 青(8)。起点和终点瓷砖不反转。
3. 反转后判定每个瓷砖的通行性：
   - 反转后 9 个像素全为青(8)（即原始瓷砖 9 格全为黑(0)）→ 墙壁，不可通行。
   - 反转后至少有一个黑(0)像素（即原始瓷砖至少有一个青(8)像素）→ 通道，可通行。
   - 起点和终点始终可通行。
4. 在瓷砖级别（将每个瓷砖视为一个节点），从起点出发经 4-邻接的通道瓷砖寻找到终点的最短路径。
5. 路径上的通道瓷砖（不含起点和终点）：将其中的黑(0)像素（反转后的背景）填充为黄(4)。青(8)像素（反转后的前景）保持不变。
6. 非路径上的瓷砖保持反转后的状态。起点保持红(2)，终点保持绿(3)。分隔行列保持黑(0)。

**关键洞察**：原始瓷砖中前景像素越少的瓷砖，反转后越容易被填满成为墙壁——这是反直觉的：看起来"越空"的瓷砖反而成为障碍。求解者必须先做心理反转再判断通行性，否则会错误地把空瓷砖当作通道。
