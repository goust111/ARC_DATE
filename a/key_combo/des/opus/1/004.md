## 新题 1：对角导轨重力级联

**组合逻辑**：[gravity_drop](已有) + [ray_extend/diagonal](创新：对角线从视觉装饰变为物理偏转导轨) + [recolor](创新：碰撞偏转时触发变色) -- 三者交织为模拟级联，偏转几何决定落水轨迹，导轨色决定水流终色。

**来源原语**：gravity_drop, cascading_branch, collision_stop (36a08778); ray_extend, diagonal_radiation, isolated_pixel (ea786f4a / 623ea044); recolor (78e78cff / aabf363d)

**依赖链**：对角导轨预先确定偏转几何 -> 重力决定水流何时撞上哪条导轨 -> 每次碰撞改变水流行进列并替换水流颜色 -> 最终落点和颜色是所有偏转的叠加结果。删除任一环节（导轨、重力、变色），均无法确定输出。

从顶部水源出发的水流在重力下落过程中被对角导轨逐级偏转并变色，最终落点与颜色由偏转路径的几何叠加决定。

**输入结构**：
- 黑(0)背景，约 15x18
- 顶行有 1-2 个蓝(1)"水源"像素，彼此间隔至少 3 列
- 网格内部有 2-4 条"导轨"线段：每条是一段连续的 45 度对角线，长 3-6 像素，使用同一种非黑、非蓝颜色（如红(2)、绿(3)、黄(4)），从一个起始像素向一个对角方向延伸。每条导轨仅沿一个对角方向（NE、NW、SE、SW 之一）
- 导轨间互不接触，且至少有一条导轨所覆盖的列范围与某个水源的列重合（确保发生碰撞）
- 导轨不接触顶行或底行
- 生成约束：不存在两条导轨在同一列范围内纵向重叠到使同一模拟步出现歧义双碰撞的情况

**规则**：
1. 逐格模拟水流下落。每个水源像素产生一条向下（行号递增）的水流，初始颜色为蓝(1)
2. 水流在当前列垂直下落，每步移动一行，直到遇到导轨像素（原始输入中的非黑、非蓝像素）
3. 碰撞处理：水流停在导轨像素正上方一格并被涂色。水流颜色变为导轨颜色。随后水流沿导轨的对角方向中行号递增的方向滑行（NW-SE 导轨则向 SE 滑，NE-SW 导轨则向 SW 滑）。水流沿导轨每经过一个对角格都涂上导轨颜色，直至滑过导轨末端后再多走一个对角格
4. 滑出导轨后，水流在新列恢复垂直下落，保留当前颜色
5. 水流到达网格底边时停止，该格被涂色
6. 水流遇到已被涂色的非背景像素时，停在其正上方一格（不覆盖已有像素）
7. 原始水源像素保留为蓝(1)；原始导轨像素保留原色
8. 多水源按从左到右处理；同一水源的级联分支按从左到右处理

**关键洞察**：对角线段在源题中仅作为视觉输出（画对角十字），此处被赋予物理斜面的功能角色——其角度改变水流列位、其颜色替换水流颜色，同一水流可经历多次变色。需要多个示例才能确认偏转方向规则（始终沿行号递增的对角分量）和变色规则（取导轨色而非混合色）。

## 新题 2：重力沉降-计数门控-柱状填充

**组合逻辑**：[gravity_drop](已有) + [counting/frequency_matching](已有，应用于重力沉降结果) + [histogram_fill](已有，由计数匹配门控激活) -- 重力在墙壁通道内产生沉降计数，计数是否匹配标记段长度决定通道是否获得柱状填充，三步形成信息变换链。

**来源原语**：gravity_drop, collision_stop (36a08778); wall_pixel, wall_bounds_span, scanline_interval (78e78cff); counting, frequency_matching, histogram_fill, marker_run, separator_row, frequency_equals_marker_count (2685904e)

**依赖链**：墙壁将网格划分为垂直通道 -> 散布像素在通道内重力沉降 -> 逐通道统计沉降像素数 -> 与标记段长度匹配的通道获得柱状填充（高度等于标记段长度），不匹配的仅保留沉降结果。删除重力则无法确定通道计数；删除计数则无法判断门控；删除柱状填充则无法产生输出条纹。

散布像素在墙壁通道内下落沉降，只有沉降像素数等于顶部标记段长度的通道才从分隔行向上生长同高度柱状条。

**输入结构**：
- 黑(0)背景，约 12x14
- 灰(5)墙壁像素构成 3-5 条单像素宽的垂直线，从第 0 行延伸至一条灰(5)全宽水平分隔行（约第 10 行），将分隔行以上的网格分为 4-6 个宽 2-4 列的垂直通道
- 通道内散布着各色像素（红(2)、绿(3)、蓝(1)），每通道 1-4 个，高度各异。同一通道内所有散布像素同色，不同通道可用不同颜色
- 顶行有一段连续的橙(7)像素（"标记段"），长度 2-4 像素
- 分隔行以下区域为空（黑(0)）
- 生成约束：至少两个通道的散布像素数等于标记段长度，至少一个通道不等于，确保门控非平凡

**规则**：
1. 分隔行以上的所有散布彩色像素在各自墙壁通道内垂直下落（行号递增），堆叠在分隔行上方或已沉降像素上方。墙壁阻止水平移动，每个像素严格在本通道内下落
2. 统计标记段（顶行橙(7)像素）的像素数，得到目标计数 T
3. 对每个通道，统计重力沉降后的彩色像素总数
4. 若通道沉降计数等于 T：在该通道中，从分隔行正上方（已沉降像素之上）向上绘制 T 格高的柱状条，使用该通道的沉降像素颜色。柱状条在通道内水平居中，宽度为 1 像素
5. 若通道沉降计数不等于 T：该通道仅显示沉降后的像素，不绘制额外柱状条
6. 墙壁像素、分隔行像素、标记段像素保持不变
7. 通道从左到右处理

**关键洞察**：重力沉降不是最终输出，而是一个中间计算步骤——其结果产生逐通道计数，只有计数命中标记段长度的通道才触发二次柱状填充。单个示例无法区分门控条件是"等于标记段长度"还是其他阈值（如"大于 2"），需要多个示例确认。

## 新题 3：角落近邻染色的点对称补全

**组合逻辑**：[point_symmetry](已有) + [recolor](创新：反射像素的颜色由最近角落标记的近邻关系决定) + [erase](已有，角落标记使用后消失) -- 角落标记同时充当空间色源和激活信号，其位置通过近邻距离与反射像素形成源题中不存在的空间-颜色耦合。

**来源原语**：point_symmetry, center_marker, center_rotational (e729b7be); corner_marker, corner_positioning, corner_selects (fd02da9e); recolor, corner_color_transfer_vanish (aabf363d); erase (3bdb4ada)

**依赖链**：中心标记定义旋转中心 -> 源图案绕中心 180 度旋转产生反射位置 -> 每个反射位置的颜色由最近角落标记决定（曼哈顿距离） -> 角落标记消失。四步环环相扣：无中心则无旋转几何，无角落标记则无反射颜色，无近邻规则则颜色分配不确定。

左侧有色图案绕中心标记做 180 度点反射，反射副本中每个像素取距其最近的角落标记的颜色，之后角落标记消失。

**输入结构**：
- 黑(0)背景，奇数尺寸约 13x13
- 网格正中心有一个灰(5)像素——中心标记
- 黄(4)像素填充中心列（除中心标记格外），构成左右分界线
- 左半侧（中心列左侧所有列）有一个由 5-10 个蓝(1)像素组成的 4-连通前景图案，形状不规则（非矩形、非对称）
- 2-3 个角落标记像素分布在网格的不同角落（四角中的 2-3 个），每个角落标记使用不同颜色，取自{红(2), 绿(3), 橙(7)}
- 右半侧（中心列右侧所有列）无前景像素
- 生成约束：源图案反射后不会落在角落标记位置或分界线列上；至少有两个角落标记各"领有"（是最近角落标记的）至少一个反射像素，确保近邻分配非平凡

**规则**：
1. 定位中心标记（网格正中心的灰(5)像素），记其坐标为 (cr, cc)
2. 对左半侧的每个蓝(1)源像素 (r, c)，计算其 180 度旋转像：(2*cr - r, 2*cc - c)
3. 对每个反射位置，计算其到所有角落标记的曼哈顿距离，选择距离最小的角落标记。平局时选择行号更大（更靠近底边）的角落标记；若仍平局，选择列号更大（更靠近右边）的
4. 将反射位置涂上对应最近角落标记的颜色
5. 擦除所有角落标记像素（置为黑(0)）
6. 保持原始蓝(1)源图案、中心标记灰(5)、黄(4)分界线不变

**关键洞察**：角落标记具有双重角色——其位置决定哪些反射像素归属它（近邻领地），其颜色成为被领有像素的涂色。单个示例中角落标记可能全部等距，无法区分近邻规则与"统一涂色"规则，需要多个示例（角落标记数量和位置变化）才能归纳近邻分配机制。

## 新题 4：对角分区面积择优裁剪

**组合逻辑**：[ray_extend/diagonal](创新：对角线从视觉射线变为空间分区边界) + [area_comparison](已有，在对角分区内计算面积) + [crop](已有) + [recolor](已有，分区归属的对角中心提供颜色) -- 对角线射线定义非矩形分区，面积比较在这些分区中选优，裁剪后用分区所属的对角中心色重涂前景。

**来源原语**：ray_extend, diagonal_radiation, isolated_pixel, extend_to_edge (ea786f4a / 623ea044); crop, connected_component, area_comparison, largest_area_selected (be94b721); recolor (78e78cff)

**依赖链**：两个孤立像素各发射四条对角射线 -> 射线将网格分割为多个多边形区域 -> 前景对象被归入其质心所在区域 -> 各区域前景面积汇总 -> 面积最大的区域被选中 -> 该区域的轴对齐边界框被裁剪 -> 裁剪内前景用距该区域质心最近的孤立像素颜色重涂。每一步均依赖前一步的输出。

两个不同色的孤立像素各发对角十字将网格分割为多边形区域，包含最大前景总面积的区域被裁剪输出，前景被重涂为该区域所归属的孤立像素颜色。

**输入结构**：
- 黑(0)背景，约 16x16
- 两个孤立像素，颜色分别为红(2)和绿(3)，位于网格内部不同位置（不在同一行、同一列或同一对角线上），距网格边缘至少 3 格
- 每个孤立像素向 NE、NW、SE、SW 四个方向发射其自身颜色的对角射线，延伸至网格边界。这些射线是输入的一部分（已预先绘制）
- 3-5 个小型单色 4-连通前景对象（每个 3-8 像素），颜色取自不与孤立像素及其射线冲突的颜色（如蓝(1)、黄(4)、灰(5)），散布在网格各处。每个对象完全位于一个分区内部（不跨越对角射线）
- 生成约束：恰好一个分区的前景像素总数严格大于所有其他分区；两个孤立像素的对角十字最多交于一点

**规则**：
1. 识别由两个对角十字线和网格边界共同形成的分区。每个对角十字从其中心向四个方向射出 4 条射线，共 8 条射线将网格划分为若干多边形区域。射线像素本身是区域边界，不属于任何区域
2. 对每个前景对象（非黑、非射线、非孤立像素的 4-连通分量），将其归入包含其最上最左像素的区域
3. 汇总每个区域的前景像素总数
4. 选择前景总面积唯一最大的区域
5. 计算该选中区域内所有像素（不含射线）的轴对齐边界框
6. 裁剪该边界框。裁剪内所有前景对象像素重涂为距选中区域质心（区域内所有非射线像素坐标的算术平均，取整）欧氏距离最近的孤立像素的颜色。裁剪内的背景像素保持黑(0)，射线像素也置为黑(0)
7. 输出裁剪后的网格

**关键洞察**：对角射线在源题中仅为视觉输出（画十字），此处被重新定义为空间分区工具——其几何构型决定哪些前景对象被归为一组，面积比较在这些非矩形分区上进行，最终裁剪的范围和重涂色均由分区归属关系推导。需要多个示例（孤立像素位置变化导致分区拓扑变化）才能归纳分区机制。

## 新题 5：最短路径列深度柱状图

**组合逻辑**：[pathfinding](已有) + [counting](已有，按列统计路径深度) + [histogram_fill](已有，柱高由路径深度决定) -- 最短路径的逐列深度剖面被编码为柱状图高度，路径本身不出现在输出中，仅其几何投影通过柱状图显现。

**来源原语**：pathfinding, shortest_path, endpoint_component, corridor (3ad05f52); histogram_fill, counting, separator_row, code_row, frequency_matching (2685904e); wall_pixel (78e78cff)

**依赖链**：迷宫中求两端点最短路径 -> 路径本身不绘制，而是按列统计路径经过的格数（列深度） -> 分隔行下方的编码行提供每列颜色 -> 仅在路径经过的列中、编码行有色的列中，从分隔行向上绘制高度等于列深度的柱状条。路径几何同时决定"哪些列有柱"和"柱多高"。

迷宫的最短路径不被绘制，而是其逐列深度被转化为分隔行上方的柱状条高度，柱色取自分隔行下方的编码行。

**输入结构**：
- 黑(0)背景，约 14x16
- 灰(5)墙壁像素在上部区域（第 0 行至约第 11 行）构成简单迷宫结构，通道宽 1-2 格
- 两个小型（2-3 像素）4-连通红(2)端点分量，分别位于迷宫左右两侧边缘附近
- 约第 12 行为灰(5)全宽分隔行
- 第 13 行为"编码行"：特定列上有单个彩色像素（蓝(1)、绿(3)、黄(4)、橙(7)等），其余列为黑(0)。编码行有色列中至少部分与最短路径经过的列重合，也至少有一个路径经过的列在编码行中为黑
- 第 14 行及以下为空黑
- 生成约束：两端点间的最短 4-连通路径所经过的列集合唯一（即使存在多条等长最短路径，它们经过的列集合相同）；任意列的路径深度不超过分隔行与网格顶行之间的空行数

**规则**：
1. 将灰(5)墙壁像素视为不可通行。求两个红(2)端点分量之间的最短 4-连通路径（从一个分量的任意格到另一个分量的任意格），仅经过非墙壁格。若存在多条最短路径，选择字典序最小的路径（将路径的坐标序列 (r0,c0),(r1,c1),... 按字典序比较）
2. 对最短路径经过的每一列 c，统计该列中路径格的数量，记为 depth(c)
3. 对每个路径经过的列 c，查看编码行（第 13 行）该列的颜色。若该格为黑(0)，跳过该列（不绘制柱状条）
4. 若编码行该格有颜色，从分隔行正上一行起向上绘制 depth(c) 格高的垂直柱状条，使用编码行颜色，位于列 c
5. 保留所有原始元素：墙壁、端点、分隔行、编码行
6. 不绘制路径本身——路径仅用于中间计算

**关键洞察**：路径从未被画出——它是一个隐藏的测量工具。每列的路径深度成为柱高，编码行提供柱色，因此输出以柱状图形式编码了路径的列剖面但不暴露路径本身。单个示例难以区分柱高来源是"路径深度"还是某个固定值，需要多个示例（不同迷宫结构导致不同深度分布）才能归纳。

## 新题 6：棋盘奇偶分类旋转堆叠

**组合逻辑**：[parity_selects_color](创新：从选色改为将对象分为两个处理组) + [sort/distance_ordering](已有) + [rotate](已有，仅对一组生效) + [stack](已有，两组独立堆叠) -- 棋盘奇偶性创建一个二元分类器，决定每个矩形的处理管线（是否旋转、按哪条轴排序），这种分类角色在源题中不存在。

**来源原语**：checkerboard_pattern, parity_selects_color, edge_marker, marker_sets_dir (5e6bbc0b); sort, stack, rotate, distance_ordering, coordinate_axis_line, axis_color_determines_rotation (291dc1e1); rectangle (3bdb4ada / 291dc1e1); crop (be94b721)

**依赖链**：棋盘背景的奇偶性将矩形分为 A/B 两组 -> A 组按距水平轴距离排序、B 组按距垂直轴距离排序 -> B 组矩形各自旋转 90 度逆时针 -> A 组在输出左半部堆叠、B 组在输出右半部堆叠。删除奇偶分类则无法分组；删除排序则堆叠顺序不确定；删除旋转则 B 组外形错误。

棋盘背景上的矩形按其中心格的棋盘奇偶性分为两组，一组不旋转、另一组旋转 90 度，各组按各自参考轴的距离排序后分左右堆叠输出。

**输入结构**：
- 蓝(1)/黑(0)棋盘图案填充约 20x20 网格的背景（格 (r,c) 在 (r+c) 为偶数时为蓝(1)，奇数时为黑(0)）
- 两条边缘线构成 L 形位于左上角：第 0 行为红(2)水平线，第 0 列为绿(3)垂直线，(0,0)格为橙(7)
- 4-6 个实心单色矩形散布于网格内部（不接触边缘线），每个矩形使用不同颜色，取自{黄(4), 灰(5), 品红(6), 青(8), 栗(9)}。每个矩形宽 2-4 格、高 3-6 格（或反之），但宽高不等（非正方形，以便旋转可见）
- 矩形间互不重叠
- 生成约束：至少两个矩形的中心格为偶校验（蓝），至少两个为奇校验（黑）

**规则**：
1. 确定每个矩形的奇偶组别：取矩形中心格坐标——对于偶数尺寸边，使用靠上靠左的中心格：行 = top + floor((height-1)/2)，列 = left + floor((width-1)/2)。若该格在棋盘中为蓝(1)（偶校验），归入 A 组；若为黑(0)（奇校验），归入 B 组
2. A 组：按每个矩形中心到水平红(2)边缘线（第 0 行）的曼哈顿距离升序排列。距离相同时按中心列号升序排列
3. B 组：按每个矩形中心到垂直绿(3)边缘线（第 0 列）的曼哈顿距离升序排列。距离相同时按中心行号升序排列。然后将 B 组中每个矩形逆时针旋转 90 度
4. 输出网格：背景为黑(0)。宽度 = A 组矩形最大宽度 + 1（间隔列） + B 组旋转后矩形最大宽度。高度 = max(A 组堆叠总高度, B 组堆叠总高度)，其中堆叠总高度 = 各矩形高度之和 +（矩形数 - 1）个间隔行
5. A 组矩形在输出左侧从上到下按排序顺序堆叠，左对齐于第 0 列，相邻矩形间隔 1 行空黑行
6. B 组矩形（旋转后）在输出右侧从上到下按排序顺序堆叠，左对齐于第（A 组最大宽度 + 1）列，相邻矩形间隔 1 行空黑行
7. 较短一侧的堆叠顶对齐（从第 0 行开始）
8. 输出中不含边缘线、棋盘背景或橙(7)角点

**关键洞察**：棋盘背景不是装饰——其在每个矩形中心格的奇偶性决定矩形的处理组别，进而决定排序参考轴和是否旋转。单个示例无法区分分组依据是"棋盘奇偶性"还是"颜色"或"位置区域"，需要多个示例（矩形位置变化导致分组变化）才能归纳分类机制。
