## 新题 1：线段穿框与孔洞几何门控填色

**组合逻辑**：[连线 draw_line] + [孔洞几何决定填充 hole_geometry_sets_fill](创新：孔洞几何作为线段颜色传递的门控条件) + [擦除 erase]（线段和标记像素仅为中间媒介，输出中不可见）

**来源原语**：
- 连线 draw_line、同色配对 same_color_pairing、行列对齐 row_col_align ← 40853293
- 空心矩形 hollow_rectangle、封闭区域 enclosed_region、擦除 erase、边框包围内部 frame_encloses_interior ← d5d6de2d
- 孔洞 hole、仅正方形孔洞填充 only_square_holes_filled、孔洞几何决定填充 hole_geometry_sets_fill ← 44d8ac46

**依赖链**：连线确定哪条线段穿过哪个框（颜色分配） → 框内孔洞的几何形状决定是否接受该颜色（门控判断） → 通过门控的孔洞被填入对应线段的颜色 → 最终擦除所有线段和标记像素，仅保留框与填色结果

通过同色标记像素对之间的连线穿过空心框来传递颜色，但只有内部孔洞为正方形的框才真正接受颜色填充，其余框的孔洞保持空白。

**输入结构**：
- 黑(0)背景，网格约 15x15。
- 3~5 个灰(5)一像素宽空心矩形框（边界框尺寸 3x3 到 6x6 不等），散布在网格上，彼此不重叠且不相邻（任意两框的边界像素之间至少间隔 1 个黑色像素）。每个框内部有一个连通的黑(0)孔洞区域；部分孔洞的边界框为正方形且孔洞像素完全填满该边界框（即孔洞本身是一个实心正方形块），其余孔洞的边界框为非正方形或孔洞像素不完全填满其边界框（即形状不规则）。
- 与灰框数量相同的彩色标记像素对（每种颜色恰好出现两次，颜色从红(2)、绿(3)、黄(4)、蓝(1)、橙(7)中选取），每对共享同一行或同一列。
- 每对标记像素之间的直线段恰好穿过一个灰框（从框的一侧边界进入、从另一侧穿出），且每个灰框恰好被一条线段穿过。不同线段不交叉。
- 所有标记像素均在灰框外部，不在任何框的边界或内部上。

**规则**：
1. 对每对同色标记像素，确定它们之间的水平或垂直直线段（含两端点的所有整数坐标像素）。
2. 确定每条线段穿过的灰框（线段经过该框的至少一个边界像素）。
3. 对每个被线段穿过的灰框，检查其封闭的黑色孔洞区域：计算孔洞区域的边界框，若该边界框为正方形且孔洞像素完全填满该边界框，则将孔洞内所有像素填入穿过此框的线段颜色；否则孔洞保持黑(0)不变。
4. 擦除所有标记像素和线段路径上的所有像素（还原为黑(0)），但不擦除灰框边界。
5. 输出网格保留灰框边界和被填色（或未填色）的孔洞。

**关键洞察**：线段在输出中完全不可见——它们仅作为颜色到框的传递媒介；真正决定输出的是孔洞的几何形状，只有正方形孔洞才能"接收"颜色。求解者需要同时理解线段的路由功能和孔洞的几何过滤功能。

## 新题 2：对称补全同时揭示通路与障碍后寻路

**组合逻辑**：[对称补全 symmetry_completion](创新：补全同时恢复轨道段和障碍物，两类信息对寻路的影响相反) → [寻路 pathfinding + 邻域禁区 neighbor_exclusion + 重涂色 recolor]

**来源原语**：
- 对称补全 symmetry_completion、反射旋转定颜色 reflect_rotate_color、遮挡像素 occluding_pixel、对称图案 symmetric_pattern、对称轨道 symmetry_orbit ← f9d67f8b
- 寻路 pathfinding、唯一安全路径 unique_safe_path、邻域禁区 neighbor_exclusion、障碍物 obstacle、端点 endpoint、轨道路径 track_path、重涂色 recolor ← cc9053aa

**依赖链**：栗色遮挡像素掩盖了部分轨道和障碍 → 利用反射对称性补全所有被遮挡的位置 → 补全同时恢复新的青色轨道段（开辟新通路）和新的橙色障碍（及其 8-邻域禁区，封死某些捷径） → 在补全后的网络中寻找两端点间的唯一安全路径

先用反射对称性修复被遮挡破坏的网格（同时恢复出隐藏的轨道和障碍），再在修复后的轨道网络中找到避开所有障碍邻域的唯一路径并标红。

**输入结构**：
- 黑(0)背景，网格约 15x15，底层图案关于某一列具有完美的左右反射对称性（对称轴不一定在网格正中央，但总是在某个整数列或两列之间的半整数位置）。
- 青(8)像素构成一个 4-连通轨道网络（含分支和环路），网络中恰好嵌有两个红(2)端点像素（红像素也是轨道的一部分，与青像素 4-连通）。
- 橙(7)像素作为障碍物散布在轨道附近（不在轨道上，即不与任何青/红像素重合）。
- 栗(9)像素作为遮挡色覆盖了若干位置——这些位置的真实颜色可能是青(8)、橙(7)或黑(0)中的任意一种。栗色像素的存在打破了表面上的对称性。
- 去除所有栗色像素后，剩余的青 + 橙 + 黑 + 红像素构成关于该对称轴的完美左右反射图案（红端点的位置也是对称的，或位于对称轴上）。
- 生成约束：每个输入至少有一个栗色像素。两个红端点不在任何橙障碍的 8-邻域内（补全前后均是如此）。补全后，橙障碍的 8-邻域禁区恰好使两端点间只存在唯一一条 4-连通安全路径（仅经过青和红像素且不经过任何禁区内的像素）。补全前若将栗色像素视为可通行，则路径不唯一。

**规则**：
1. 识别遮挡色为栗(9)——它是唯一一种移除后使剩余非黑像素（青、橙、红）关于某列呈完美左右反射对称的颜色。
2. 确定反射对称轴。对每个栗(9)像素，计算其关于对称轴的镜像位置，将栗色像素替换为该镜像位置的颜色（青(8)、橙(7)或黑(0)）。
3. 在补全后的网格中，将每个橙(7)像素及其 8-邻域（上下左右和四个对角方向各一步）内的所有像素标记为禁行区。
4. 在剩余的非禁行区青(8)和红(2)像素中，寻找两个红(2)端点之间的唯一 4-连通简单路径。
5. 将该路径上的青(8)像素重涂为红(2)。端点保持红色。所有其他像素（橙障碍、黑背景、非路径青像素、已被恢复的像素）保持不变。

**关键洞察**：遮挡像素同时隐藏了轨道和障碍——对称补全不只是修通路，还会"生出"新的橙色障碍及其 8-邻域禁区，堵死某些看似可行的捷径。求解者必须意识到补全结果中包含两种性质相反的信息才能找到正确路径。

## 新题 3：平铺涌现十字图案与行迹填色竞争

**组合逻辑**：[平铺 tiling](创新：平铺在瓦片边界涌现出原图中不存在的十字构型) → [局部模板匹配 local_template_match + 重涂色 recolor] + [行内背景填色 row_bg_colored](创新：十字重涂色"消耗"前景像素，改变行迹填色的触发条件) + [冲突优先级 conflict_priority]

**来源原语**：
- 平铺 tiling、行内背景填色 row_bg_colored、冲突优先级 conflict_priority、前景像素 fg_pixel ← c92b942c
- 局部模板匹配 local_template_match、十字图案 plus_pattern、正交邻接 orthogonal_adjacency、重涂色 recolor ← 7e02026e

**依赖链**：平铺在瓦片边界创造了原图中不存在的正交邻接关系 → 新邻接使孤立的前景像素形成完整十字构型 → 十字图案被重涂为绿色（"消耗"了部分黄色前景像素） → 行迹填色仅在仍含黄色像素的行生效 → 绿色像素不被蓝色行迹覆盖（绿色优先）

将小网格 3x3 平铺后，在瓦片边界涌现的十字图案被染绿，含剩余前景的行中背景被染蓝，绿色优先于蓝色。

**输入结构**：
- 黑(0)背景，网格为 4x4 或 5x5 的小网格。
- 恰好一种前景色黄(4)，以散布的单像素形式出现（2~4 个像素）。
- 前景像素的位置经过设计：在单个瓦片内，没有任何黄色像素的上下左右 4 个邻居全为黄色（即原图中不存在完整的黄色十字构型）；但在 3x3 平铺后，某些跨瓦片边界的位置会出现中心和 4 个正交邻居全为黄(4)的十字构型。
- 蓝(1)和绿(3)在输入中不出现（保留为输出的标记色）。

**规则**：
1. 将输入网格水平重复 3 次、垂直重复 3 次，生成一个宽和高均为原图 3 倍的平铺画布。
2. 十字检测与重涂：在平铺画布中，检查每个黄(4)像素——若其上、下、左、右 4 个邻居均为黄(4)，则将该中心像素及其 4 个正交邻居全部重涂为绿(3)。若多个十字图案共享像素，共享区域同样为绿(3)（合并处理）。
3. 行迹填色：在完成十字重涂后的画布中，逐行检查——若某行仍包含至少一个黄(4)像素（已被重涂为绿(3)的像素不再算作黄色），则将该行中所有仍为黑(0)的像素填充为蓝(1)。
4. 冲突规则：绿(3)像素不被蓝(1)覆盖；黄(4)像素不被蓝(1)覆盖。蓝(1)仅填入黑(0)位置。
5. 输出即为处理后的平铺画布。

**关键洞察**：单个瓦片内不存在完整十字——十字构型只在平铺后的瓦片边界涌现，求解者必须先完成平铺才能定位需要染绿的区域。同时，绿色重涂"消耗"了部分黄色像素，可能使某些行不再含有黄色从而失去蓝色行迹——求解者需要追踪这一连锁效应来确定最终哪些行有蓝色填充。

## 新题 4：精灵体像素数匹配轮廓内腔面积的归位

**组合逻辑**：[裁剪 crop + 计数 counting] + [面积匹配 area_matching](创新：精灵体像素数与轮廓内腔面积的数值匹配决定空间归位目标) + [紧凑排列 compact_packing](创新：不是排入固定网格而是逐像素嵌入匹配轮廓的内腔) + [擦除 erase]

**来源原语**：
- 裁剪 crop、紧凑排列 compact_packing、精灵体 sprite、空间位置排序 spatial_position_ordering ← 1990f7a8
- 轮廓对象 outline_object、源像素集 source_pixel_set、行内腔 row_interior、面积匹配 area_matching、像素数等于腔面积 count_equals_cavity ← 7acdf6d3
- 计数 counting ← 2a28add5
- 擦除 erase ← d5d6de2d

**依赖链**：裁剪每个精灵体并计算其前景像素数 → 计算每个轮廓对象的行内腔总面积 → 像素数与腔面积数值相等的精灵体-轮廓对一一匹配 → 将精灵体像素按扫描序填入匹配轮廓的内腔像素位置 → 擦除原位精灵体

将散布的彩色精灵体按各自的像素数匹配到内腔面积相等的轮廓对象中，逐像素填入内腔，并擦除原始位置。

**输入结构**：
- 黑(0)背景，网格约 15x20。
- 3~4 个灰(5) 8-连通轮廓对象，每个由一像素宽的灰边界围成。轮廓形状不规则但保证：在该轮廓占据的每一行中，最左灰像素和最右灰像素之间（不含灰像素本身）的所有黑色像素构成该行的内腔段；所有行的内腔段汇总即为该轮廓的行内腔。各轮廓的行内腔总面积互不相同（范围 3~8）。轮廓之间不重叠不相邻。
- 与轮廓数量相同的彩色精灵体（每个是一个 4-连通单色小图形，像素数 3~8，颜色互不相同，从红(2)、绿(3)、黄(4)、蓝(1)、橙(7)中选取），散布在轮廓对象外部，彼此不相邻。
- 每个精灵体的前景像素数恰好等于某一个轮廓对象的行内腔面积，且此匹配是一一对应的（无两个精灵体像素数相同，无两个轮廓内腔面积相同）。
- 生成约束：精灵体的像素可以按从上到下、从左到右的扫描序排列后逐一放入对应轮廓的内腔像素（也按从上到下、从左到右排列），而不会出现冲突。

**规则**：
1. 识别所有灰(5) 8-连通轮廓对象。对每个轮廓，计算行内腔：在轮廓占据的每一行中，最左灰像素列号记为 cL，最右灰像素列号记为 cR，该行内腔为 (cL+1) 到 (cR-1) 列中颜色为黑(0)的所有像素。将所有行的内腔像素汇总，得到该轮廓的内腔面积 A。
2. 识别所有非灰非黑的 4-连通精灵体。对每个精灵体，计算其前景像素数 P。
3. 对每个精灵体，找到内腔面积 A = P 的唯一轮廓对象，建立一一匹配。
4. 对每个匹配对：将精灵体的前景像素按从上到下、从左到右的扫描序排成列表 S；将轮廓内腔的像素按同样的从上到下、从左到右扫描序排成列表 T。将 T 中第 i 个像素涂为精灵体的颜色（对应 S 中第 i 个像素的颜色，由于精灵体单色所以颜色相同）。
5. 擦除每个精灵体在原始位置的所有像素（变为黑(0)）。灰轮廓边界保留不变。

**关键洞察**：精灵体不按颜色、位置或形状匹配到轮廓——唯一的匹配依据是数值相等（像素数 = 内腔面积）。求解者必须同时完成两类计数（精灵体像素和轮廓内腔面积）才能确定对应关系。

## 新题 5：下移触发对角溅射级联穿透空心框

**组合逻辑**：[平移 shift + 触发条 trigger_bar → 射线延伸 ray_extend](创新：对角射线被空心框边界阻挡) + [擦除 erase + 填充 fill](创新：射线击中框时打开该框——擦除边界并填色内部——解除射线阻挡引发向上级联)

**来源原语**：
- 平移 shift、移动像素 moving_pixel、触发条 trigger_bar、邻接触发对角溅射 adjacency_triggers_diagonal_splash、固定步长移动 fixed_step_move ← 73c3b0d8
- 射线延伸 ray_extend ← c92b942c
- 空心矩形 hollow_rectangle、封闭区域 enclosed_region、擦除 erase、填充 fill、边框包围内部 frame_encloses_interior、空心内部变色 interior_recolor ← d5d6de2d

**依赖链**：红色像素下移一行 → 落到触发条正上方的像素向左上和右上发射对角射线 → 射线遇到灰框边界时停止并"打开"该框（擦除边界、内部填绿） → 边界被擦除后射线继续沿原方向延伸 → 可能击中更高处的灰框，再次触发打开 → 逐层级联直到射线离开网格

像素下移到触发条上方后发射对角射线；射线被空心框边界阻挡，但击中即打开该框（边框消失、内部染绿），之后射线继续向上延伸，级联打开所有对角线上的框。

**输入结构**：
- 黑(0)背景，网格约 18x18。
- 一条黄(4)全宽水平触发条位于网格下部（距底部约 2~3 行）。
- 2~3 个红(2)移动像素散布在触发条上方。部分红像素距触发条恰好 2 行（下移 1 行后将与触发条正交相邻），其余红像素距触发条更远（下移 1 行后仍不与触发条相邻）。
- 4~6 个灰(5)一像素宽空心矩形框（边界框尺寸 3x3 到 5x5），分布在触发条上方的区域，彼此不重叠不相邻。某些框在对角线方向上存在上下排列关系——即下方框恰好位于某条对角射线路径上，挡在上方框与射线源之间。
- 红像素不在任何框内部或边界上。
- 生成约束：每个将触发溅射的红像素（下移后与触发条相邻的像素）的至少一条对角射线路径上有一个灰框；其中至少一条路径上有两个纵向排列的灰框（下方框阻挡射线到达上方框），以产生级联效果。

**规则**：
1. 将每个红(2)像素从原位置擦除（变为黑(0)），并在同列、下移一行的位置重新绘制红(2)像素。
2. 对每个下移后与黄(4)触发条正交相邻（正上方一格）的红像素，发射两条上行对角射线：一条向左上方（每步行 -1、列 -1），一条向右上方（每步行 -1、列 +1）。不与触发条相邻的红像素只移动不发射。
3. 每条射线逐像素向上延伸，延伸过程中的处理规则：
   a. 若下一像素为黑(0)，将其涂为红(2)，继续延伸。
   b. 若下一像素为灰(5)（框边界），射线暂停。找到该灰像素所属的空心矩形框，执行打开操作：将该框全部灰(5)边界像素擦除为黑(0)，将该框原先封闭的黑色内部区域全部填充为绿(3)。打开完成后，射线从暂停处继续延伸——该位置现已从灰变为黑(0)，涂为红(2)，并继续检查下一像素。
   c. 若下一像素为绿(3)（已被打开的框内部），将其保持绿(3)不变，射线穿透继续延伸。
   d. 若下一像素为红(2)（另一条射线的痕迹）、黄(4)（触发条）或超出网格边界，射线永久停止。
4. 黄(4)触发条保持不变。

**关键洞察**：灰框既是射线的目标也是射线的障碍——低处的框挡住射线触及高处的框。只有先打开低处的框（擦除其边界），射线才能穿透继续上行并级联打开高处的框。求解者需要沿对角线追踪射线路径、判断框的遮挡层次，才能确定最终哪些框会被打开。

## 新题 6：框内标记计数驱动柱状条重分配

**组合逻辑**：[计数 counting + 框内包含 inside_frame + 忽略干扰项 ignore_distractors](创新：计数结果不渲染为 tally 而是作为排序键) → [排序 sort + 重分配 redistribute + 槽位保持颜色 slot_retains_color]

**来源原语**：
- 计数 counting、矩形框 rectangular_frame、标记像素 marker_pixel、框内包含 inside_frame、标记数映射填充 marker_count_fill、忽略干扰项 ignore_distractors ← c8b7cc0f
- 排序 sort、重分配 redistribute、柱状条 vertical_bar、基线 baseline、高度排序 height_ordering、槽位保持颜色 slot_retains_color ← 31f7f899

**依赖链**：识别框内与框外标记像素 → 仅计数框内标记（框外同色标记为干扰项） → 按框从左到右的排列将计数值对应到柱状条槽位 → 以计数值为排序键对柱状条高度轮廓重新分配 → 每个槽位保留其原始颜色

计算每个矩形框内的标记像素数量，以该数量为键将柱状条按高度从矮到高重新排列到从左到右的槽位中，槽位保留原色。

**输入结构**：
- 黑(0)背景，网格约 15x20。
- 网格下部有一条灰(5)全宽水平基线（占据一行）。
- 从基线向上伸出 4~5 根单列宽柱状条，各条颜色互不相同（从红(2)、绿(3)、蓝(1)、黄(4)、橙(7)中选取），高度互不相同（2~7 像素高）。各条之间间隔至少 2 列。
- 网格上部（不与柱状条区域重叠）有与柱状条数量相同的品红(6)一像素宽矩形框（边界框尺寸 3x3 到 5x5），彼此不重叠不相邻。
- 青(8)标记像素散布在网格各处——既出现在品红框内部，也出现在品红框外部。每个框严格内部（不含边界）的青像素数量互不相同（范围 1~5）。框外的青像素是干扰项。
- 品红框按从左到右的中心 x 坐标排列顺序与柱状条按从左到右的 x 坐标排列顺序一一对应：第 i 个最左的框对应第 i 个最左的柱状条槽位。
- 生成约束：各框内青像素计数互不相同，各柱状条高度互不相同。柱状条按当前高度排列不是升序（否则排序无效果）。

**规则**：
1. 识别所有品红(6)矩形框。对每个框，计数其严格内部（不含边界像素所在行列的边界行/列，仅含被边界完全包围的内部像素）的青(8)标记像素数量。忽略品红框外部和边界上的所有青像素。
2. 将品红框按中心 x 坐标从小到大排列为 F1, F2, ..., Fn，对应的框内青像素计数为 C1, C2, ..., Cn。
3. 将柱状条按 x 坐标从小到大排列为 S1, S2, ..., Sn（S_i 与 F_i 对应）。记录每根柱状条的高度 H_i 和颜色。
4. 以 C_i 为排序键，将 (C_i, H_i) 对按 C_i 从小到大排序。排序后第 j 个 (C, H) 对的高度 H 分配给第 j 个槽位 S_j。
5. 在输出中，每个槽位 S_j 绘制高度为分配到的 H 值的柱状条，颜色保持 S_j 原来的颜色。基线保留。
6. 擦除所有品红框和所有青标记像素（变为黑(0)）。输出仅保留灰基线和重新分配后的彩色柱状条。

**关键洞察**：排序键不是柱状条自身的高度，而是各自对应矩形框内的青色标记像素计数——框外大量散布的同色青像素是干扰项，必须精确地只统计框内的。求解者需要先完成框内计数才能确定柱状条的重新排列方式。

## 新题 7：缺损差异掩码的列像素数隐式编码柱状条高度

**组合逻辑**：[差异提取 difference_extraction + 对齐比较 aligned_comparison](创新：差异掩码不直接使用其形状，而是将其逐列像素数作为数值编码) → [计数 counting] → [填充 fill](创新：计数值驱动柱状条高度生成)

**来源原语**：
- 差异提取 difference_extraction、对齐比较 aligned_comparison、前景图案 foreground_motif、缺损副本 damaged_copy、缺失掩码 missing_cell_mask ← 2037f2c7
- 计数 counting ← 2a28add5, c8b7cc0f
- 填充 fill ← d5d6de2d, 44d8ac46
- 柱状条 vertical_bar、基线 baseline ← 31f7f899

**依赖链**：对齐完好图案与缺损副本，逐像素比较提取差异掩码 → 对差异掩码按列统计缺失像素数 → 每列的计数值映射为输出柱状条的高度 → 在基线上方生成对应高度的柱状条

比较同一图案的完好版与缺损版提取差异，差异掩码中每列的缺失像素数直接编码了输出柱状条的高度。

**输入结构**：
- 黑(0)背景，网格约 12x20（较高）。
- 网格上半区包含两个多色前景图案，水平排列且间隔至少 2 列黑色。左侧图案完好（无缺失），右侧图案是同一图案的缺损副本——仅移除了部分前景像素（将其变为黑(0)），不增加任何新像素。两图案的边界框尺寸相同，均为 R 行 x M 列（R 约 4~6，M 约 4~6）。图案内含 2~3 种前景色（不含黑色），各像素颜色和位置在完好版中已确定。
- 缺损副本中，每列被移除的前景像素数量互不相同（范围 0 到 R，且至少有一列为 0、至少有一列大于 0）。
- 网格下半区有一条灰(5)水平基线（全宽，占一行）。基线上方有 M 个等距的柱状条槽位，每个槽位一列宽，槽位的水平位置与图案的列一一对应（第 j 个槽位对应图案的第 j 列）。输入中柱状条槽位为空（黑色）。
- 生成约束：缺损副本中各列缺失数互不相同。完好图案和缺损副本的边界框左上角在同一行，便于逐列对齐比较。

**规则**：
1. 分别裁剪完好图案和缺损副本到各自的边界框。将两个裁剪结果按左上角对齐，逐像素比较。
2. 提取差异掩码：标记所有在完好图案中为非黑前景色、在缺损副本中为黑(0)的像素位置。
3. 对差异掩码逐列统计：第 j 列（j = 1, 2, ..., M，从左数）中被标记为缺失的像素数记为 H_j。
4. 在网格下半区，从灰(5)基线向上，在第 j 个槽位绘制高度为 H_j 的柱状条（即从基线上方第 1 行到第 H_j 行涂色）。柱状条颜色为青(8)。若 H_j = 0，该槽位不绘制任何像素。
5. 输出保留完整的网格：上半区两个图案保持原样（完好版不变，缺损版保持缺损状态），下半区显示灰基线和新生成的青色柱状条。

**关键洞察**：缺损不是随机的——每列的缺失像素数量经过精心设计以编码柱状条高度。求解者必须先完成差异提取、再按列统计缺失数，才能发现这一从图案空间到柱状图空间的隐式编码关系。单看缺损副本本身无法发现规律，必须与完好版对比。
