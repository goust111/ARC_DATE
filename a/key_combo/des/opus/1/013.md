## 新题 1：对称过滤驱动同心调色

**组合逻辑**：[镜像对称检测](已有) + [擦除](已有) → [同心层填充](已有，创新：填充色板由对称过滤结果动态决定，而非静态对角标记)

**来源原语**：镜像对称/mirror_symmetry (ce039d91), 镜像配对则涂色/recolor_if_mirror_pair (ce039d91), 擦除/erase (9f8de559, 6c434453), 同心层填充/concentric_fill (99306f82), 嵌套层次/nesting_hierarchy (99306f82), 空心矩形框/hollow_rect_frame (99306f82)

**依赖链**：镜像对称检测将像素分为"配对"与"噪声"两类 → 配对像素的颜色按空间顺序构成色板 → 该色板驱动空心矩形框内的同心层填充。删除对称检测步骤则色板未知，无法填充；删除填充步骤则对称检测无输出载体。

输入中散落的彩色像素既是对称测试的对象，又是调色板的候选源；空心矩形框既是填充目标，又隐式定义了对称轴（框的垂直中线即镜像轴），对称检测与填充操作共享同一几何参照。

**输入结构**：黑(0)背景，约 15x16（偶数宽度）网格。网格中央偏下有一个灰(5)单像素厚的空心矩形框（内部约 5x5 至 7x7 的空腔）。框外散布约 8~12 个单像素前景点，使用红(2)、蓝(1)、绿(3)、黄(4)中的 3~4 种颜色。其中部分像素关于网格垂直中线成对出现（同色、同行、列关于中线对称），另一部分不成对（噪声像素）。生成约束：成对像素的颜色去重后恰好有 k 种（k 等于框内空腔能容纳的同心层数，即 min(空腔宽, 空腔高) // 2 向上取整），保证色板长度与层数匹配。成对像素不与框重叠。

**规则**：
1. 确定镜像轴：网格垂直中线（列索引 W/2 - 0.5 处，W 为网格宽度）。
2. 对每个非背景、非框像素 (r, c)，检查其关于镜像轴的对称位置 (r, W-1-c) 是否也是同色非背景非框像素。
3. 若两端都满足，标记该像素为"配对像素"；否则标记为"噪声像素"。
4. 擦除所有噪声像素为背景色黑(0)。
5. 收集所有配对像素的颜色。按像素位置从上到下、同行从左到右的顺序扫描，取每种颜色首次出现的顺序，构成色板序列 P = [c1, c2, ..., ck]（每种颜色仅取一次）。
6. 用色板 P 对框内空腔进行同心层填充：c1 填最外层环，c2 填次外层环，...，最后一种颜色填充剩余中心区域。
7. 框本身和框外的配对像素保持不变。

**关键洞察**：噪声像素是干扰项，必须通过对称检测过滤掉后才能确定正确的色板顺序；仅看单个示例可能无法区分色板的排序规则（按首次出现位置而非颜色编号），需要对比多个示例才能确认排序依据是空间扫描顺序。

## 新题 2：剪切解码隐藏模板

**组合逻辑**：[剪切变换](已有) → [模板匹配](已有，创新：匹配发生在变换后的形状空间，而非原始空间) → [重涂色](已有) + [擦除](已有)

**来源原语**：剪切变换/shear_transform (423a55dc), 底行锚点/bottom_anchor (423a55dc), 偏移随行距增/offset_grows_with_distance (423a55dc), 模板匹配/template_matching (50f325b5), 含旋转反射变换/includes_rotation_reflection (50f325b5), 重涂色/recolor (50f325b5), 擦除/erase (6c434453)

**依赖链**：剪切变换改变每个对象的几何形状 → 变换后的形状与模板比较决定匹配/不匹配 → 匹配者重涂色，不匹配者擦除。剪切步骤不可跳过，因为原始形状均不匹配模板；模板匹配不可跳过，因为无法区分哪些该保留。

剪切变换在源题中是全局唯一对象的视觉效果，在此处变为多个对象的"解码器"——同一变换作用于不同形状产生不同结果，只有特定原始形状经剪切后才恰好吻合模板，形成"编码-解码"结构关系。

**输入结构**：黑(0)背景，约 14x14 网格。左上角有一个青(8)模板图形（4-连通，4~6 像素，具有明确的非对称轮廓以区分旋转/反射变体）。网格中散布 5~7 个绿(3)单色小图形（4-连通，各 4~7 像素），彼此互不相邻，边界框互不重叠。生成约束：其中恰好 2~3 个绿图形经过左剪切变换（底行锚定，每行上移一行则左移一列）后，其归一化形状等价于青模板的某个旋转或反射变体；其余绿图形经剪切后与模板的所有旋转反射变体均不匹配。

**规则**：
1. 识别青(8)模板图形，提取其边界框归一化的二值掩码 T。
2. 对每个绿(3)图形独立执行左剪切变换：令该图形最底行为锚定行；对图形中每个像素 (r, c)，将其移至 (r, c - (bottom - r))，其中 bottom 为该图形最底行行号。若目标列超出网格左边界则丢弃该像素。
3. 对剪切后的每个绿图形，提取其边界框归一化的二值掩码 S。
4. 枚举模板 T 的全部旋转（0/90/180/270度）和反射变体（共至多 8 种）。
5. 若 S 与 T 的任一变体完全匹配，则将该图形（在其**剪切后位置**）重涂为青(8)。
6. 若 S 与 T 的所有变体均不匹配，则擦除该图形的剪切后位置上的所有像素为背景色黑(0)。
7. 原始青模板保持不变。剪切前的绿像素位置清除为背景色。

**关键洞察**：输入中没有任何绿图形的原始形状与模板匹配——匹配只在剪切变换后的形状空间中成立。求解者必须先理解剪切规则，再在心理上对每个图形执行变换，才能判断哪些图形应保留。需对比多个示例才能确认剪切方向（左移而非右移）和锚定行（底行而非顶行）。

## 新题 3：射线偏转汇聚生长

**组合逻辑**：[流动绘制/射线延伸](已有) + [逐步偏移](已有) → [生长](已有，创新：生长种子由射线汇聚位置动态决定，而非预设种子行) + [交替变色](已有)

**来源原语**：流动绘制/flow_draw (f15e1fac), 边缘起点像素/edge_source_pixel (f15e1fac), 偏移控制像素/deflector_pixel (f15e1fac), 逐步偏移/step_deflection (f15e1fac), 对齐时偏移/deflect_when_aligned (f15e1fac), 生长/grow (af726779), 相邻间隔/adjacent_gap (af726779), 交替变色/alternating_color (af726779), 间隔行生成/gap_row_generate (af726779)

**依赖链**：边缘射线受偏移像素偏转，形成弯曲路径 → 两条路径在同一行相邻汇聚的位置成为生长种子 → 种子向下交替变色生长。射线偏转决定了汇聚的行和列位置，生长的起始条件完全由偏转结果决定；若删除偏转则射线平行不汇聚、无种子可生长，若删除生长则偏转路径无后续输出。

源题中射线偏转仅产生视觉轨迹，生长仅从静态种子行展开；此处两者耦合为"偏转→汇聚检测→动态播种→生长"的因果链，汇聚检测是源题中不存在的新结构节点。

**输入结构**：黑(0)背景，约 18x15 网格。顶行有 3~5 个绿(3)源像素，分布在不同列。左侧列（第 0 列除外，约第 1~3 列范围）有 3~6 个红(2)偏移控制像素，分布在不同行。网格其余区域为背景。生成约束：经偏转后，恰好有 2~3 对射线在某些行上占据相邻列（列差为 1），形成汇聚；至少有一条射线不与任何其他射线汇聚。

**规则**：
1. 每个绿(3)顶行源像素向下发射一条射线，初始列为源像素所在列。
2. 射线逐行向下推进。在到达每一行之前，检查该行是否有红(2)偏移控制像素：若有，则射线在该行的列位置比上一行右移一格（列号 +1）；若无，列位置保持不变。若右移后的列超出网格右边界，射线在该行终止。
3. 将每条射线经过的所有背景像素绘为绿(3)。射线遇到非背景像素（包括其他射线已绘制的像素）时穿过但不覆盖（保留先绘制的颜色）。射线绘制顺序：按源像素列号从左到右。
4. 扫描每一行，寻找"汇聚对"：若该行上有两条不同射线的路径占据相邻列（列差恰好为 1），且这两列之间无其他射线路径，则取这两列的中间偏左列（即较小列号）所在的、下方第一个背景行的该列位置作为橙(7)生长种子。
5. 从所有种子开始向下生长：在当前活跃种子行的两行下方，对每对活跃种子（包括同代种子和射线路径上的绿像素均视为"活跃点"），若两个活跃点之间间隔恰好一个背景像素，则在该背景像素位置放置子代种子。
6. 子代种子颜色在橙(7)和品红(6)之间交替：第一代种子为橙(7)，第二代为品红(6)，第三代为橙(7)，依此类推。
7. 生长在无法产生子代或下一行超出网格边界时停止。

**关键洞察**：红色偏移像素不直接参与生长，但它们重塑了射线路径的几何形状，间接决定了哪些射线会汇聚、在何处汇聚。生长的空间分布完全由偏转拓扑决定，需对比多个示例才能确认汇聚的判定条件（相邻列而非同列）。

## 新题 4：分裂掩码的双色克罗内克积

**组合逻辑**：[分裂](已有，创新：分裂对象从实心矩形变为二值掩码) → [克罗内克积](已有) + [颜色互换](已有，创新：两半各自独立做积，颜色由对方决定)

**来源原语**：分裂/split (9f669b64), 穿越并分开/pass_through_split (9f669b64), 实心矩形/solid_rectangle (9f669b64), 克罗内克积/kronecker_product (8e2edd66), 二值掩码/binary_mask (8e2edd66), 颜色互换/color_swap (8e2edd66), 前景背景互换填充/fg_bg_inverted_fill (8e2edd66)

**依赖链**：红色水平条将蓝色掩码分裂为上下两部分 → 上部掩码做克罗内克自积但用下部的前景色（红），下部掩码做克罗内克自积但用上部的前景色（蓝） → 两个积结果纵向拼接，中间以红条分隔。分裂位置决定两个子掩码的形状，子掩码形状决定积的结果；颜色互换建立了两半之间的交叉依赖，不能独立求解任一半。

源题中克罗内克积作用于单一完整掩码，分裂作用于沿轴排列的实心矩形；此处二者结合在同一对象上——分裂创造出两个子掩码，每个子掩码独立执行克罗内克积，但颜色交叉引用对方，形成源题中不存在的"分裂-交叉积"结构。

**输入结构**：黑(0)背景，约 7x7 网格。网格中有蓝(1)像素构成一个非对称的二值图案（4-连通，约 8~14 像素，分布在多行多列）。一条红(2)水平单像素厚横条横穿整个网格宽度，将蓝色图案分为上下两个非空部分（横条所在行的蓝像素被横条覆盖，视为被切断）。生成约束：上部蓝色子图案和下部蓝色子图案的行数和列数均不超过 4，以保证克罗内克积输出不超过约 16x16。上下两部分各自至少包含 2 个蓝像素和 2 个黑背景像素。

**规则**：
1. 找到红(2)水平条所在行 r_split。
2. 提取上部子掩码 M_upper：行 [0, r_split) 中，取包含所有蓝像素的最小边界框，框内蓝像素标记为 1，黑像素标记为 0。
3. 提取下部子掩码 M_lower：行 (r_split, H) 中，同样取最小边界框并提取二值掩码。
4. 对 M_upper 计算克罗内克自积：M_upper 中每个 0 值单元格替换为 M_upper 的一个副本（其中 1 值像素涂为红(2)，0 值像素涂为黑(0)）；每个 1 值单元格替换为全黑(0)块。得到结果 K_upper。
5. 对 M_lower 计算克罗内克自积：M_lower 中每个 0 值单元格替换为 M_lower 的一个副本（其中 1 值像素涂为蓝(1)，0 值像素涂为黑(0)）；每个 1 值单元格替换为全黑(0)块。得到结果 K_lower。
6. 输出网格：K_upper 在上，其下一行为红(2)横条（宽度等于输出网格宽度，即 max(K_upper 宽, K_lower 宽)），再下为 K_lower。若 K_upper 和 K_lower 宽度不同，较窄者左对齐，右侧补黑(0)背景。

**关键洞察**：红色横条的双重身份是解题核心——它既是几何分割线（决定两个子掩码的形状），又是颜色供体（上半部分的积使用红色而非蓝色）。需对比多个示例才能发现颜色交叉规则（上用红、下用蓝）而非同色自积。

## 新题 5：图例配色驱动重力滑动

**组合逻辑**：[相对位置匹配](已有) + [重涂色](已有) → [滑动](已有，创新：滑动方向由重涂色结果决定) + [碰撞停止](已有)

**来源原语**：占位块/placeholder_object (1da012fc), 图例矩形/legend_rectangle (1da012fc), 控制标记点/control_marker (1da012fc), 相对位置对应/relative_position_correspondence (1da012fc), 最小距离匹配/minimum_distance_matching (1da012fc), 重涂色/recolor (1da012fc), 滑动/slide (f0100645), 墙壁列/wall_column (f0100645), 同色物体朝同色墙/same_color_wall (f0100645), 近者优先不重叠/nearest_first (f0100645), 碰撞停止/collision_stop (f0100645)

**依赖链**：图例中标记点的相对位置与占位块匹配 → 匹配确定每个占位块的新颜色 → 新颜色决定每个块朝哪面同色墙壁滑动 → 滑动时按距离排序、碰撞停止。若删除图例匹配则颜色未知、滑动方向不确定；若删除滑动则重涂色无空间效果。

源题中图例仅用于静态着色，重力墙仅用于同色吸引；此处图例的颜色分配直接决定了力学行为的方向——同一个占位块如果被分配不同颜色，会朝完全不同的方向运动，颜色成为运动指令的编码载体。

**输入结构**：黑(0)背景，约 17x17 网格。网格右上角有一个灰(5)实心矩形（约 4x4），内部嵌入 3~4 个单像素彩色标记点（使用红(2)、蓝(1)、绿(3)中的颜色），标记点位于矩形内部的不同相对位置。网格左列为红(2)实心墙壁列（从顶到底），右列为蓝(1)实心墙壁列，底行为绿(3)实心墙壁行。网格中散布 3~4 个灰(5) 4-连通占位块（各 3~6 像素，形状各异但均为连通的不规则小图形），彼此不相邻、不与图例和墙壁重叠。生成约束：占位块数量等于标记点数量；各占位块的边界框中心在网格中的相对位置（归一化到占位块活动区域）与各标记点在图例内的相对位置构成唯一最小距离一一匹配（无平局）。每种墙壁颜色至少被分配到一个占位块。

**规则**：
1. 识别灰(5)图例矩形及其内部的彩色标记点。
2. 识别图例外部的所有灰(5) 4-连通占位块。
3. 计算每个占位块边界框中心相对于所有占位块构成的最小外接矩形的归一化坐标 (rx, ry)。
4. 计算每个标记点相对于图例内部区域的归一化坐标 (mx, my)。
5. 对占位块和标记点进行一一匹配：选择使所有配对的欧几里得距离 sqrt((rx-mx)^2 + (ry-my)^2) 之和最小的匹配方案。
6. 将每个占位块的所有像素重涂为其匹配标记点的颜色。
7. 擦除图例矩形及其内部标记点为背景色。
8. 对每个重涂后的块执行滑动：红(2)块向左朝左墙滑动，蓝(1)块向右朝右墙滑动，绿(3)块向下朝底墙滑动。同色块按离目标墙的距离从近到远排序依次处理。每个块沿滑动方向平移，直到其边缘像素紧邻墙壁或同色已停止的块为止。
9. 滑动后块保持其形状不变，仅位置改变。两面墙壁和底行墙壁保持不变。

**关键洞察**：图例不是静态参考卡片——它编码的颜色直接化为物理运动方向。求解者必须先完成位置匹配和着色，才能推断每个块会朝哪个方向运动。需对比多个示例才能确认匹配依据是相对位置（而非面积、形状或绝对距离）。

## 新题 6：格子瓦片上的转向路径绘制

**组合逻辑**：[射线延伸 + 转向](已有，创新：转向发生在瓦片格子的粗粒度层级而非像素层级) + [同色同子格填充](已有，创新：子格位置由起点编码而非独立标注) + [连线](已有)

**来源原语**：射线延伸/ray_extend (e5790162), 转向/turn (e5790162), 转向控制点/turn_ctrl_pixel (e5790162), 颜色决定转向/color_determines_turn (e5790162), 格子瓦片/lattice_tile (a096bf4d), 端点标记/endpoint_marker (a096bf4d), 同行列对齐/same_row_col_align (a096bf4d), 同色同子格位置/same_color_subcell (a096bf4d), 连线/connect (a096bf4d), 填充/fill (a096bf4d)

**依赖链**：起点像素在瓦片内的子格位置编码了初始运动方向 → 路径在瓦片格子上逐步推进 → 遇到品红/青控制瓦片时在格子层级转向 → 路径经过的每个空瓦片在与起点相同的子格位置填入绿色 → 遇到红色终点瓦片停止。子格位置同时编码方向信息和绘制位置，形成双重语义耦合；转向发生在粗粒度格子而非像素级别，与源题的像素级转向形成尺度转换。

**输入结构**：黑(0)背景，约 17x17 网格。灰(5)分隔线将网格划分为 4x4 的瓦片格子（每个瓦片内部为 3x3，分隔线宽度 1 像素；整体格子约 4 行 4 列共 16 个瓦片）。大多数瓦片内部全为黑(0)背景。以下瓦片包含特殊内容：
- 恰好一个瓦片包含一个绿(3)单像素，位于其 3x3 内部的某个边中点位置（上中、下中、左中、右中之一），表示起点及初始方向（上中 = 向上移动，下中 = 向下，左中 = 向左，右中 = 向右）。
- 2~4 个瓦片各包含一个品红(6)单像素（位于瓦片内部中心），表示"右转控制"。
- 1~3 个瓦片各包含一个青(8)单像素（位于瓦片内部中心），表示"左转控制"。
- 恰好一个瓦片包含一个红(2)单像素（位于瓦片内部中心），表示终点。
- 生成约束：从起点瓦片沿初始方向在瓦片格子上直线前进，必然先遇到一个控制瓦片或终点瓦片（不会先出界）。路径不会回到已访问的瓦片。

**规则**：
1. 找到包含绿(3)像素的起点瓦片。绿像素在瓦片 3x3 内部的位置决定初始方向：行 0 列 1（上中）= 向上，行 2 列 1（下中）= 向下，行 1 列 0（左中）= 向左，行 1 列 2（右中）= 向右。记该子格在 3x3 内部的位置为 (sr, sc)。
2. 从起点瓦片沿初始方向在瓦片格子上移动（每步移动到相邻瓦片）。
3. 进入一个新瓦片时：
   - 若该瓦片为空（全背景），在其内部 (sr, sc) 位置填入绿(3)，继续沿当前方向前进。
   - 若该瓦片含品红(6)像素，不修改该瓦片，将当前方向顺时针旋转 90 度（右转），继续沿新方向前进。
   - 若该瓦片含青(8)像素，不修改该瓦片，将当前方向逆时针旋转 90 度（左转），继续沿新方向前进。
   - 若该瓦片含红(2)像素，停止路径绘制。
4. 若下一步将离开瓦片格子边界，同样停止。
5. 所有分隔线、控制瓦片内容、终点瓦片内容、起点瓦片内容均保持不变。

**关键洞察**：起点像素的子格偏移执行双重职能——它既编码初始运动方向（上/下/左/右），又指定路径在每个空瓦片内的绘制坐标。求解者必须同时推断方向编码规则和子格复制规则，而这两者共享同一几何信息。需对比多个示例确认子格位置与方向的对应关系。

## 新题 7：十字化种子的阻断生长

**组合逻辑**：[方框换为十字掩模](已有) → [生长](已有，创新：十字中心成为生长种子) + [忽略干扰项→阻断点](创新：源题中被忽略的干扰项在新题中变为生长阻断器)

**来源原语**：空心矩形/hollow_rect (6c434453), 十字图案/cross_pattern (6c434453), 方框换为十字掩模/square_to_cross_mask (6c434453), 重涂色/recolor (6c434453), 擦除/erase (6c434453), 生长/grow (af726779), 相邻间隔/adjacent_gap (af726779), 交替变色/alternating_color (af726779), 间隔行生成/gap_row_generate (af726779), 忽略干扰项/ignore_distractors (ce039d91)

**依赖链**：空心方框转换为十字图案确定了种子位置（十字中心） → 种子向下生长时，散布的单像素干扰点充当阻断器（生长不能穿越或占据阻断点所在位置） → 阻断改变了生长树的形态。方框转换不可省略（否则种子位置未知）；阻断点不可忽略（否则生长树形态错误）。

源题中空心方框到十字是局部掩码替换，生长是从种子行展开的三角形扩展，干扰项在源题中被过滤掉；此处三者交织——掩码替换产生种子，"干扰项"反转角色变为功能性阻断器，阻断器改变生长的拓扑结构。

**输入结构**：黑(0)背景，约 16x14 网格。网格上半部分（约前 4~5 行范围）有 2~4 个蓝(1)像素构成的 3x3 空心方框（8 个蓝边缘像素包围 1 个黑中心像素），各方框互不重叠且不相邻。网格中散布 4~8 个黄(4)单像素点（"阻断点"），分布在方框下方的区域（行号大于所有方框的最底行），彼此不相邻。生成约束：各方框的中心列间距至少为 3，以保证生长树有足够空间展开。阻断点的位置应使得至少一个生长树的某一代子代被阻断（即阻断点恰好位于某个潜在子代位置上）。

**规则**：
1. 对每个 3x3 空心蓝(1)方框执行十字化：擦除四角像素为黑(0)背景，将四个边邻像素和中心像素重涂为红(2)，形成红色十字图案。
2. 每个红色十字的中心像素成为一个生长种子，标记为第 0 代，颜色为红(2)。
3. 从所有种子开始执行生长：在当前代活跃点所在行的 2 行下方，扫描所有活跃点对（同代种子或上一轮仍活跃的点均计入）。对每对活跃点 (r, c1) 和 (r, c2)（c2 = c1 + 2，即间隔一个像素），检查中间位置 (r+2, c1+1)：
   - 若 (r+2, c1+1) 是黑(0)背景且不是黄(4)阻断点，则放置一个子代种子。
   - 若 (r+2, c1+1) 是黄(4)阻断点，则不放置子代（该分支被阻断）。阻断点保留不变。
4. 子代颜色在橙(7)和品红(6)之间交替：第 1 代为橙(7)，第 2 代为品红(6)，第 3 代为橙(7)，依此类推。
5. 生长停止条件：某一代无法产生任何子代，或下一目标行超出网格底边。
6. 黄(4)阻断点在输出中保持不变。十字图案的非中心像素保持不变。

**关键洞察**：黄色单像素看似与方框变换无关的"噪声"，实际上它们是生长过程的空间约束——每个阻断点都可能截断一整条生长分支，从而改变最终树的形态。求解者需对比多个示例才能发现阻断点的功能角色（阻断生长而非被忽略或被覆盖）。

## 新题 8：频率分类构建偏转墙

**组合逻辑**：[排序/形状频次分组](已有，创新：分类结果不是简单上下排列，而是构建偏转器的几何分布) → [流动绘制](已有) + [重涂色](已有)

**来源原语**：排序/sorting (62593bfd), 平移/translate (62593bfd), 多色连通分量/multicolor_component (62593bfd), 形状频次分组/shape_frequency_grouping (62593bfd), 旋转翻转不变/rotation_flip_invariant (62593bfd), 共享与唯一形状/shared_vs_unique_shape (62593bfd), 流动绘制/flow_draw (f15e1fac), 边缘起点像素/edge_source_pixel (f15e1fac), 逐步偏移/step_deflection (f15e1fac), 对齐时偏移/deflect_when_aligned (f15e1fac), 重涂色/recolor (50f325b5)

**依赖链**：计算每个对象形状的旋转翻转不变标准形 → 共享形状的对象平移至左墙形成左偏转器，唯一形状的对象平移至右墙形成右偏转器 → 顶行源像素向下发射射线 → 射线遇到左偏转器所在行时左移一格，遇到右偏转器所在行时右移一格 → 射线路径涂为源像素颜色。形状分类不可省略（否则偏转器位置和方向未知），射线绘制不可省略（否则分类无视觉输出）。

源题中形状频率分组仅决定对象的纵向目标位置，射线偏转仅由边缘固定像素驱动；此处分组结果直接构建射线的偏转几何——同一对象在不同示例中可能因频率变化从左偏转器变为右偏转器，颠覆射线路径。分类与偏转通过空间位置紧耦合。

**输入结构**：黑(0)背景，约 18x16 网格。顶行有 3~5 个单像素源点，使用红(2)、蓝(1)、绿(3)等不同颜色（每个源点颜色不同）。网格中央区域散布 4~6 个单色 8-连通小图形（各 3~5 像素，使用灰(5)单色），它们的形状（旋转翻转不变的标准形）中有些重复出现（至少 2 个图形共享同一标准形），有些只出现一次。各图形互不相邻，不与顶行源点重叠。生成约束：共享形状的图形和唯一形状的图形平移至左/右墙后，其所占行的集合应与至少 2 个源像素的列位置产生交互（即射线会经过偏转器所在行），以保证偏转可见。

**规则**：
1. 识别所有灰(5) 8-连通图形，对每个图形计算其边界框归一化的二值掩码，再取所有 4 种旋转 x 2 种翻转（共至多 8 种变体）中字典序最小者作为标准形。
2. 统计每种标准形的出现次数。出现次数 >= 2 的为"共享形状"，出现次数 = 1 的为"唯一形状"。
3. 将共享形状的图形平移至左墙：保持每个图形的行位置（边界框顶行不变），将其列位置平移使边界框左列对齐到第 0 列。将唯一形状的图形平移至右墙：保持行位置不变，将其列位置平移使边界框右列对齐到第 W-1 列（W 为网格宽度）。擦除图形原始位置为黑(0)。
4. 平移后的图形重涂为黄(4)（不再是灰色），以区分偏转器与背景。
5. 从每个顶行源像素向下发射一条射线，初始列为源像素所在列。射线逐行向下推进：
   - 在到达行 r 时，检查第 0 列上是否有黄(4)左墙偏转器像素在行 r：若有，射线在行 r 的列位置比行 r-1 左移一格（列号 -1）。
   - 检查第 W-1 列上是否有黄(4)右墙偏转器像素在行 r：若有，射线在行 r 的列位置比行 r-1 右移一格（列号 +1）。
   - 若同一行左右墙均有偏转器，两个偏移抵消，列位置不变。
   - 若列位置超出 [0, W-1] 范围，射线终止。
6. 将每条射线经过的背景像素涂为该射线源像素的颜色。射线绘制顺序：按源像素列号从左到右，后绘制的不覆盖先绘制的。
7. 黄(4)偏转器像素和顶行源像素在输出中保持不变。

**关键洞察**：灰色图形在输入中看似随意散布的静态对象，实际上它们的形状重复性决定了分类去向（左墙还是右墙），分类去向决定了偏转方向（左偏还是右偏），最终塑造了射线的轨迹。同一图形在不同示例中如果从"唯一"变为"共享"（因其他图形的加入），偏转方向会翻转——需对比多个示例才能发现分类标准是形状频率而非位置或面积。
