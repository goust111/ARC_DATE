## 新题 1：标记偏心定条纹方向

**组合逻辑**：[标记在矩形内](已有) → [射线延伸](创新：不延伸射线本身，而是用标记到最近内壁的方向推断填充轴向) → [奇偶交替 + 填充](创新：在框内沿推断轴做交替条纹填充)

**来源原语**：标记在矩形内(marker_inside_rect, 8cb8642d), 射线延伸(ray_extend, 97999447), 奇偶交替(parity_alternation, 97999447), 填充(fill, 4612dd53), 空心矩形(hollow_rectangle, 8cb8642d)

**依赖链**：标记相对于框的偏心方向决定条纹轴向 → 条纹轴向决定交替填充的铺设方式 → 框边界截断填充范围。删除偏心判断则条纹方向不确定；删除交替填充则无输出内容；删除框边界则填充范围不确定。

在每个空心矩形框内，根据标记像素偏向哪面墙来决定条纹方向，然后用标记色与灰(5)交替填充框的内部。

**输入结构**：约 15x15 的黑(0)背景网格。网格中有 3-4 个不重叠的空心矩形框，每个框由单一前景色绘制（如红(2)、蓝(1)、绿(3)等，各框颜色不同），框壁宽 1 像素，内部为黑(0)。每个框内部恰好有 1 个标记像素，颜色与框色不同且与其他标记颜色也不同（如黄(4)、橙(7)、品红(6)等）。标记像素不在框的正中心——它在水平方向或垂直方向上明显偏向某一面内壁（即标记到最近水平内壁的距离与到最近垂直内壁的距离不相等）。生成约束：每个框的内部宽度和高度均 >= 3，标记到最近水平内壁与最近垂直内壁的距离不相等。

**规则**：
1. 对每个框，计算标记像素到四面内壁的距离。找到距离最近的那面内壁。
2. 如果最近内壁是水平的（顶壁或底壁），则条纹方向为**垂直**（条纹沿列排列）。如果最近内壁是垂直的（左壁或右壁），则条纹方向为**水平**（条纹沿行排列）。
3. 沿条纹方向，以标记所在行（水平条纹时）或列（垂直条纹时）为起始线（偏移量 0），向两侧交替铺设条纹：偏移量为偶数的行/列填充标记色，偏移量为奇数的行/列填充灰(5)。
4. 条纹仅填充框内部的黑(0)像素，不覆盖框壁。
5. 所有框独立处理，输出中框壁和背景保持不变。

**关键洞察**：标记不仅提供条纹颜色，它在框内的偏心位置编码了条纹的铺设方向——离哪面墙更近，条纹就垂直于那面墙展开。

## 新题 2：面积排名驱动颜色轮转

**组合逻辑**：[墙分隔区域](已有) → [计数/排序](创新：按区域面积排名建立全序) → [循环移位 + 重涂色](创新：颜色按面积排名的环形移位重新分配)

**来源原语**：分隔墙(partition_wall, 62ab2642), 墙分隔区域(wall_partitions_regions, 62ab2642), 循环移位(cyclic_shift, e78887d1), 重涂色(recolor, ba97ae07), 排序(sort, aaecdb9a), 连通区域(connected_region, 62ab2642)

**依赖链**：墙结构划分区域 → 区域面积建立全序排名 → 排名决定颜色的环形移位映射 → 移位后重涂每个区域。删除墙结构则无区域可排序；删除面积排序则无移位依据；删除循环移位则重涂无规则。

在灰墙分隔的彩色区域中，按面积从小到大排列所有区域，然后将每个区域的颜色循环移位给下一个更大的区域。

**输入结构**：约 12x12 的网格。灰(5)像素构成 1 像素宽的墙，将网格分隔为 4-6 个不规则的 4-连通区域。每个区域填充单一颜色（从红(2)、蓝(1)、绿(3)、黄(4)、橙(7)中选取，各区域颜色不同）。每个区域的面积（像素数）互不相等。生成约束：任意两个区域面积不同，区域数 >= 4。

**规则**：
1. 识别所有被灰(5)墙分隔的 4-连通非灰区域。
2. 按面积（像素数）从小到大排列这些区域，记为 R_1, R_2, ..., R_k，对应原始颜色 C_1, C_2, ..., C_k。
3. 执行循环移位：R_1 接收 C_2 的颜色，R_2 接收 C_3 的颜色，...，R_{k-1} 接收 C_k 的颜色，R_k 接收 C_1 的颜色。
4. 灰(5)墙像素保持不变。

**关键洞察**：颜色轮转不是按空间邻接关系（如相邻区域交换），而是按面积全序进行循环——位置相距很远的两个区域可能因为面积相邻而交换颜色。

## 新题 3：双面板重叠决定分量命运

**组合逻辑**：[透明叠加](已有) → [颜色位置匹配](创新：叠加后的右面板颜色信息作为左面板分量的重涂依据) → [重涂色/擦除](创新：按重叠颜色数量的三分支条件决定保留、重涂或擦除)

**来源原语**：透明叠加(transparent_overlay, e345f17b), 面板(panel, e345f17b), 前景掩码(fg_mask, e345f17b), 对齐(alignment, e345f17b), 重涂色(recolor, 09629e4f), 擦除(erase, 8cb8642d), 连通分量(connected_component, aaecdb9a)

**依赖链**：双面板逐像素对齐 → 找到每个左面板分量被右面板覆盖的颜色集 → 覆盖颜色数决定三种不同命运（0色擦除、1色重涂、多色保留）。删除对齐则无法确定覆盖关系；删除颜色集判断则三分支坍缩；删除任一分支处理则输出不确定。

将左右面板对齐叠加，根据右面板在每个左分量上覆盖的颜色种类数来决定该分量是被擦除、被重涂还是保持原色。

**输入结构**：约 10x21 的网格。中间第 11 列为灰(5)分隔线，将网格分为左面板（10x10）和右面板（10x10）。左面板在黑(0)背景上有 4-5 个小型 4-连通单色分量（每个 3-8 像素），颜色各不相同（如红(2)、蓝(1)、绿(3)、黄(4)）。右面板在黑(0)背景上也有若干单色分量（如橙(7)、品红(6)、青(8)），形状和位置与左面板不同，但经对齐后会与部分左面板分量产生重叠。生成约束：至少有 1 个左分量与右面板 0 个前景像素重叠，至少有 1 个左分量与右面板恰好 1 种颜色重叠，至少有 1 个左分量与右面板 2 种以上颜色重叠。

**规则**：
1. 将左右面板按像素坐标对齐（忽略灰分隔列）。
2. 对左面板中每个 4-连通分量 L，收集所有与 L 的像素位置重合的右面板前景颜色（去重），记为集合 S_L。
3. 若 |S_L| = 0（右面板在 L 的所有位置都是背景）：在输出中擦除 L（填充为黑(0)）。
4. 若 |S_L| = 1（右面板在 L 上只有一种前景色 c）：在输出中将 L 的所有像素重涂为 c。
5. 若 |S_L| >= 2（右面板在 L 上有多种前景色）：在输出中保留 L 的原始颜色不变。
6. 输出为单个 10x10 网格（不包含分隔线和右面板）。

**关键洞察**：右面板不是简单的二值掩码（有/无），而是一张空间分布的颜色查询表——覆盖颜色的"唯一性"决定了左分量的命运，使得同一个右面板分量如果跨越了多个左分量，可能对不同左分量产生不同效果。

## 新题 4：同色对边连通方能成廊，交叉处变色

**组合逻辑**：[对边连通](创新：增加同色约束，只有两端边界像素颜色相同才构成有效走廊) → [填充](已有) → [交叉 + 标记](创新：水平走廊与垂直走廊的交叉处涂为第三色)

**来源原语**：对边连通(opposite_edge_connect, 2bee17df), 边界像素(border_pixel, 2bee17df), 走廊(corridor, 2bee17df), 填充(fill, 2bee17df), 交叉(crossing, ba97ae07), 标记(mark, 456873bc), 方向分色(direction_based_color_split, 08573cc6)

**依赖链**：边界像素颜色匹配判定有效走廊 → 走廊方向决定填充色 → 交叉处两个方向的走廊同时经过导致颜色冲突 → 冲突解决为第三色。删除颜色匹配则过多走廊被选中（规则退化）；删除方向分色则交叉无法区分；删除冲突解决则交叉处颜色不确定。

在网格边界上放置红和蓝像素，只有同色对边像素之间的无阻挡通道才被填充——红对红的行填红，蓝对蓝的列填蓝——而行列交叉处变为黄色。

**输入结构**：约 13x13 的黑(0)背景网格。网格四边上散布着红(2)和蓝(1)像素（每边 3-6 个，其余边界像素为黑(0)）。网格内部散布少量灰(5)阻挡像素。生成约束：存在至少 2 行，其最左列与最右列的边界像素都是红(2)且该行内部（不含两端）全为黑(0)（无阻挡）；存在至少 2 列，其最上行与最下行的边界像素都是蓝(1)且该列内部至少 1 列全为黑(0)（无阻挡）；存在至少 1 个合法红行与 1 个合法蓝列的交叉点；存在至少 1 行左右端皆为红但内部有灰(5)阻挡（验证阻挡规则）。

**规则**：
1. 对每一行：检查最左列（列 0）和最右列（列 W-1）的像素。若两者都是红(2)，且该行内部（列 1 到列 W-2）所有像素均为黑(0)，则该行为**有效水平走廊**。
2. 对每一列：检查最上行（行 0）和最下行（行 H-1）的像素。若两者都是蓝(1)，且该列内部（行 1 到行 H-2）所有像素均为黑(0)，则该列为**有效垂直走廊**。
3. 将每条有效水平走廊的内部像素填充为红(2)。
4. 将每条有效垂直走廊的内部像素填充为蓝(1)。
5. 若某像素同时位于一条有效水平走廊和一条有效垂直走廊上（交叉处），将其重涂为黄(4)。
6. 所有原始前景像素（边界上的红/蓝和内部的灰阻挡）保持不变。

**关键洞察**：走廊的合法性不仅取决于"无阻挡"，还取决于两端边界像素的颜色是否匹配——一行若左端红右端蓝（或一端为黑），则不构成走廊。颜色本身成为走廊筛选的门控条件，而非仅仅是装饰。

## 新题 5：隐形走廊决定区域生缩

**组合逻辑**：[墙分隔区域](已有) → [对边连通](创新：走廊是穿越墙间隙的不可见背景通道) → [生长/收缩](创新：区域是否毗邻走廊决定其生长或收缩)

**来源原语**：分隔墙(partition_wall, 62ab2642), 连通区域(connected_region, 62ab2642), 对边连通(opposite_edge_connect, 2bee17df), 走廊(corridor, 2bee17df), 生长(grow, df978a02), 收缩(shrink, df978a02)

**依赖链**：墙结构同时产生区域和走廊 → 走廊路径判断需检查从网格一边到对边的无阻挡行/列 → 区域与走廊的相邻关系分类区域 → 分类结果决定生长或收缩方向。删除走廊识别则无法分类区域；删除生长/收缩则无输出变化；删除墙结构则一切不存在。

灰墙将网格分成彩色区域，同时墙的间隙形成贯穿网格的隐形走廊；毗邻走廊的区域向外膨胀一层，不毗邻走廊的区域向内收缩一层。

**输入结构**：约 14x14 的黑(0)背景网格。灰(5)像素构成 1 像素宽的不完整墙网络，将网格分隔为 5-7 个 4-连通区域，每个区域填充单一颜色（红(2)、蓝(1)、绿(3)、黄(4)、橙(7)等）。墙在某些位置有 1 像素宽的缺口。部分行或列从网格左边到右边（或上边到下边）存在仅经过黑(0)背景像素的连续路径（这些即为隐形走廊——它们穿过墙缺口但本身是背景色）。生成约束：至少 2 个区域的边界像素与某条隐形走廊 4-邻接，至少 2 个区域不与任何走廊邻接；每个区域面积 >= 9（保证收缩后仍有像素）。

**规则**：
1. 识别所有**隐形走廊**：一条隐形水平走廊是某一整行像素，从列 0 到列 W-1 全部为黑(0)背景（不是灰墙，不是彩色区域）。一条隐形垂直走廊是某一整列像素，从行 0 到行 H-1 全部为黑(0)背景。
2. 对每个彩色区域，检查其是否有至少一个像素的 4-邻居落在某条隐形走廊上。若是，标记该区域为**走廊毗邻**；否则标记为**走廊隔绝**。
3. 对每个走廊毗邻区域：将其**生长**一层——将该区域所有像素的 4-邻居中为黑(0)背景的像素涂为该区域颜色。生长不跨越灰(5)墙，不覆盖其他彩色区域。
4. 对每个走廊隔绝区域：将其**收缩**一层——将该区域中所有 4-邻居包含黑(0)或灰(5)的边缘像素改为黑(0)。
5. 灰(5)墙和走廊背景像素本身保持不变（走廊不被可见地标记）。
6. 若多个区域生长到同一像素，该像素归属面积较大的区域。

**关键洞察**：走廊本身在输入和输出中都不可见（始终为黑色背景），但它们的存在决定了哪些区域获得生长优势、哪些被惩罚收缩——求解者需要先发现这些隐形的贯穿全行/全列的背景通道。

## 新题 6：交叉条带的奇偶干涉

**组合逻辑**：[横条 + 竖条](已有) → [奇偶交替](创新：从 1D 射线推广到 2D，两条正交方向各自产生奇偶序列) → [交叉 + 重涂色](创新：交叉区域的颜色由两个方向的奇偶性共同决定，形成类棋盘干涉图案)

**来源原语**：横条(h_bar, ba97ae07), 竖条(v_bar, ba97ae07), 交叉(crossing, ba97ae07), 奇偶交替(parity_alternation, 97999447), 重涂色(recolor, ba97ae07)

**依赖链**：横条定义水平奇偶序列 → 竖条定义垂直奇偶序列 → 交叉区域需同时解析两个序列 → 两个奇偶值的组合（同奇偶 vs 异奇偶）决定交叉颜色。删除任一方向的奇偶序列则交叉处颜色退化为单色；删除交叉处理则两条带互不影响（失去耦合）。

一条水平色带和一条垂直色带各自呈现奇偶交替条纹，在它们正交交叉的区域里，颜色由两个方向的奇偶性联合决定，形成棋盘状干涉图案。

**输入结构**：约 15x15 的黑(0)背景网格。一条水平色带占据连续的 2-3 行，横贯整个网格宽度，颜色为红(2)。一条垂直色带占据连续的 2-3 列，纵贯整个网格高度，颜色为蓝(1)。两者在网格中部形成一个矩形交叉区域，该交叉区域在输入中统一为红(2)（即水平带"盖在"垂直带上方）。生成约束：横带宽度（行数）和竖带宽度（列数）均 >= 2，交叉区域面积 >= 4。

**规则**：
1. 对水平带中**非交叉**的部分：从该带的最左列开始，逐列交替填充——偏移量为偶数的列保持红(2)，偏移量为奇数的列涂为灰(5)。偏移量定义为 p_h = c - c_left，其中 c_left 是该带最左列的列坐标（即 0）。
2. 对垂直带中**非交叉**的部分：从该带的最上行开始，逐行交替填充——偏移量为偶数的行保持蓝(1)，偏移量为奇数的行涂为灰(5)。偏移量定义为 p_v = r - r_top，其中 r_top 是该带最上行的行坐标（即 0）。
3. 对**交叉区域**的每个像素 (r, c)：计算其在水平带中的列偏移 p_h = c - 0 = c，以及在垂直带中的行偏移 p_v = r - 0 = r。若 p_h 和 p_v 奇偶性相同（同为偶数或同为奇数），涂为黄(4)。若奇偶性不同（一奇一偶），涂为黑(0)背景。
4. 背景区域保持不变。

**关键洞察**：交叉区域不是简单地取某一条带的颜色或交换颜色——它是两个独立的一维奇偶信号在二维空间中的干涉结果，产生棋盘状图案。只观察水平带或只观察垂直带都无法推断交叉处的模式。

## 新题 7：框内标记计数决定阶梯层数

**组合逻辑**：[包含 + 计数](创新：标记数量作为构造参数而非颜色源) → [擦除](已有) → [逐行递增 + 堆叠](创新：在框内自底向上构建阶梯形，层数由计数决定)

**来源原语**：包含(containment, 855e0971), 计数(count, aaecdb9a), 擦除(erase, 8cb8642d), 逐行递增(row_by_row_increment, bbc9ae5d), 堆叠(stack, bbc9ae5d), 空心矩形(hollow_rectangle, 8cb8642d), 标记像素(marker_pixel, 8cb8642d)

**依赖链**：框包含标记 → 标记计数提供层数 N → 擦除标记后在框内构建 N 层阶梯 → 框的内部尺寸约束阶梯的最大宽度。删除计数则层数不确定；删除框则阶梯无边界；删除擦除则标记与阶梯混杂。

每个空心矩形框内散布着若干标记像素；清除标记后，在框内从底部开始构建阶梯形，阶梯层数等于该框内标记的数量。

**输入结构**：约 16x20 的黑(0)背景网格。网格中有 3-4 个不重叠的空心矩形框，每个框由唯一的前景色绘制（如红(2)、蓝(1)、绿(3)），框壁 1 像素宽。每个框内部散布 1-5 个栗(9)色标记像素，标记位置随机但不在框壁上。各框内标记数量互不相同。生成约束：每个框的内部高度 >= 该框的标记数量，内部宽度 >= 该框的标记数量；各框标记数互不相等。

**规则**：
1. 对每个框，计数其内部栗(9)标记像素的数量 N。
2. 擦除该框内所有栗(9)标记（改为黑(0)）。
3. 在框内部从底部开始，构建左对齐的阶梯形：底部第 1 行（框内最后一行）填充 N 个框色像素（从框内最左列开始），向上第 2 行填充 N-1 个，第 3 行填充 N-2 个，...，第 N 行填充 1 个。
4. 若阶梯的宽度超出框内部宽度，裁剪右侧超出部分。若阶梯的高度超出框内部高度，裁剪顶部多余行。
5. 框壁和背景保持不变。各框独立处理。

**关键洞察**：标记的位置完全不影响输出——它们仅以数量形式编码了一个构造参数。求解者需要意识到标记是一元计数器，然后将计数值转化为阶梯的几何形状。

## 新题 8：四向标尺编码非均匀螺旋

**组合逻辑**：[螺旋绘制](创新：标准螺旋的等差递增改为四方向独立递增率) → [标尺条](创新：标尺从平铺的重复长度转为螺旋各方向的增长步幅) → [方向分色](已有) → [擦除 + 边界截断](已有)

**来源原语**：螺旋绘制(spiral_drawing, 08573cc6), 标尺条(ruler_bar, 9c1e755f), 标尺长度决定重复(ruler_length_repeat, 9c1e755f), 方向分色(direction_based_color_split, 08573cc6), 中心标记(center_marker, 08573cc6), 边界截断(boundary_truncation, 08573cc6), 擦除(erase, 8cb8642d)

**依赖链**：四条标尺各自编码一个方向的增长步幅 → 螺旋的每个方向按各自步幅独立递增 → 四色分别着色四个方向的线段 → 边界截断终止螺旋。删除任一标尺则该方向增长率不确定；删除方向分色则各段不可区分；删除边界截断则终止条件不明。

从中心标记出发画螺旋，每个方向的臂长增长速率由该方向对应的边缘标尺长度决定，四色标尺兼作螺旋该方向段的着色源。

**输入结构**：约 17x17 的黑(0)背景网格。网格中心附近有一个栗(9)色中心标记像素。网格四边各有一条 1 像素宽的彩色标尺条，紧贴边缘：
- 顶边（行 0）：一段红(2)水平条，长度 S_up（1-4 像素），从列 0 开始向右排列。
- 底边（行 H-1）：一段蓝(1)水平条，长度 S_down（1-4 像素），从列 0 开始向右排列。
- 左边（列 0）：一段绿(3)垂直条，长度 S_left（1-4 像素），从行 1 开始向下排列（避免与顶边标尺在 (0,0) 重叠）。
- 右边（列 W-1）：一段黄(4)垂直条，长度 S_right（1-4 像素），从行 1 开始向下排列。
生成约束：S_up、S_down、S_left、S_right 不全相同（至少两个值不同）；中心标记不在网格正中心（略有偏移），以使螺旋非对称。

**规则**：
1. 擦除四条边缘标尺（恢复为黑(0)），保留中心标记栗(9)。
2. 从中心标记开始，按顺序绘制螺旋段：左 → 下 → 右 → 上 → 左 → 下 → 右 → 上 → ...
3. 每个方向有独立的臂长递增序列：
   - 第 k 次向左段（k = 1, 2, 3, ...）的长度 = k x S_left
   - 第 k 次向下段的长度 = k x S_down
   - 第 k 次向右段的长度 = k x S_right
   - 第 k 次向上段的长度 = k x S_up
4. 每段的颜色取自该方向的标尺颜色：向左段为绿(3)，向下段为蓝(1)，向右段为黄(4)，向上段为红(2)。
5. 绘制时逐像素前进；若下一个像素超出网格边界，立即停止该段（已绘制的像素保留），继续绘制下一个方向的段。若连续四段（一整圈）都在第一个像素就越界，终止整个螺旋。
6. 后绘制的像素覆盖先绘制的像素（中心标记栗(9)不被覆盖）。

**关键洞察**：这不是标准的均匀增长螺旋——四个方向各有不同的增长步幅，由边缘标尺的长度编码。标尺被"消费"为构造参数后从输出中擦除，因此求解者必须在输入中读取标尺长度才能推断螺旋的非对称形状。
