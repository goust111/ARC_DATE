## 新题 1：对称分类射线碰撞反馈

**组合逻辑**：[recolor + symmetry_det_color](创新：对称类型不再映射颜色，而是映射射线方向) → [ray_extend](已有) → [trail_intersection](创新：交叉点触发源对象重涂色反馈)

**来源原语**：recolor、symmetry_axis、ray_extend（来自 a09f6c25、ac605cbb、178fcbfb）；trail_intersection（来自 ac605cbb）；connected_component（来自 b27ca6d3）；singleton_noise（来自 a09f6c25）

**依赖链**：对称分类的结果决定射线方向 → 射线方向决定哪些射线相交 → 交叉点的存在反馈决定源对象是否被重涂色。删除对称分类则射线方向不确定；删除射线则无交叉；删除交叉反馈则无重涂色。

输入中的单色小图形按对称类型发射不同方向的射线，射线的交叉事件反过来决定源图形的最终颜色。

**输入结构**：约 18x18 的黑(0)背景网格。散布 4~6 个单色 4-连通前景图形，每个图形由 3~7 个像素组成，各使用不同的非黑颜色（从蓝(1)、红(2)、绿(3)、品红(6)、橙(7)中取）。每个图形恰好具有一种反射对称类型：水平轴对称、垂直轴对称或对角线对称（主对角线或副对角线均归为对角线类）。此外可能有若干孤立的单像素前景点作为噪声。生成约束：任意两个图形的边界框不重叠且间距至少 2 像素；每种对称类型至少出现一个图形；不同示例中同类对称的图形具体形状不同。

**规则**：
1. 忽略所有孤立单像素（面积 = 1 的 4-连通分量），将其擦除为黑(0)。
2. 对每个剩余图形，计算其边界框中心（取边界框行范围和列范围的中点，向下取整）。判定其反射对称类型：
   - 水平轴对称：从中心向右发射一条射线。
   - 垂直轴对称：从中心向下发射一条射线。
   - 对角线对称：从中心向右下发射一条射线。
3. 射线使用灰(5)绘制，从中心的下一个像素开始，沿指定方向逐像素延伸，直到碰到网格边界或碰到另一个图形的非黑像素（不包含终点）为止。射线不覆盖图形自身的像素。
4. 检查所有射线之间的交叉：若两条射线经过同一像素，则该像素重涂为黄(4)。
5. 对每个图形，统计其射线参与的交叉点数量：
   - 0 个交叉点：图形保持原色不变。
   - 1 个或以上交叉点：图形所有像素重涂为青(8)。
6. 绘制顺序：先画所有射线（灰），再标记交叉点（黄覆盖灰），最后处理图形重涂色。

**关键洞察**：对称类型不再直接映射输出颜色（与参考题 a09f6c25 不同），而是映射射线方向；最终颜色由射线的全局交互结果——交叉事件——反向决定，形成"分类→传播→反馈"的闭环。

## 新题 2：门控走廊旋转印章

**组合逻辑**：[pathfinding + door_segment](创新：门不仅是通路，每过一道门累积 90 度旋转) → [stamp + rotate](创新：印章旋转角度由路径上经过的门数决定)

**来源原语**：pathfinding、door_segment、parallel_walls、through_door_center（来自 7e576d6e）；stamp、neighborhood_template（来自 39e1d7f9）；rotate（来自 2c181942）

**依赖链**：门段的位置决定路径走向 → 路径经过的门数决定旋转角度 → 旋转角度决定印章在目标位置的朝向。删除门控则旋转角度不确定；删除路径则无法确定经过几道门；删除旋转印章则无输出。

一个模板图案通过平行墙壁中的门逐层传递，每穿过一道门旋转 90 度，在含有同色标记的走廊中留下旋转后的印章。

**输入结构**：约 20x15 的黑(0)背景网格。3~4 条水平方向的灰(5)完整横墙将网格分为 4~5 条等高走廊（每条走廊高 3~4 行）。每道墙中恰好有一个 3 像素宽的门段（门段处墙色被擦为黑(0)）。最上方走廊包含一个 3x3 的红(2)模板图案（非对称，旋转后可区分朝向）。其余走廊各包含一个红(2)标记像素，位于走廊内任意位置。生成约束：模板图案在四个旋转态下互不相同；各门段的水平位置不同；标记像素不与门段垂直对齐。

**规则**：
1. 识别最上方走廊中的 3x3 红(2)模板图案，记为 T。
2. 从模板所在走廊开始，向下逐层穿过每道墙的门段中心。记录从模板走廊到目标走廊共穿过 k 道门（k = 1, 2, 3, ...）。
3. 对第 k 层走廊中的红(2)标记像素，将模板 T 顺时针旋转 (k x 90) 度得到 T_k。
4. 以标记像素为中心（标记像素对应 T_k 的中心像素），将 T_k 印章到该走廊中。印章仅覆盖黑(0)像素，不覆盖墙壁像素；超出走廊范围的部分裁剪丢弃。
5. 印章完成后，擦除原始标记像素（将其重涂为模板中该中心位置的颜色，即融入印章）。
6. 保持所有墙壁和门段不变。处理顺序：从上到下逐层处理。

**关键洞察**：门段不仅是空间通路，更是旋转计数器——经过的门数编码了印章的旋转角度，这在单个示例中可能被误判为固定旋转，必须对比经过不同门数的走廊才能归纳出累积旋转规则。

## 新题 3：内容像素加权图路径弹射

**组合逻辑**：[pixel_count_conservation](创新：像素数量不再守恒于弹射，而是作为图的边权) → [shortest_path + graph_structure](已有) → [ejection + tail_determines_emission](创新：仅最短路径上的杯弹射，其余杯清空)

**来源原语**：ejection、cup_frame、tail_spike、content_pixel、pixel_count_conservation（来自 3dc255db）；shortest_path、node_square、track_segment、terminal_node、graph_structure（来自 7b0280bc）

**依赖链**：内容像素数量构成边权 → 边权决定最短路径 → 路径选择决定哪些杯弹射、哪些杯清空。删除内容计数则无法定义边权；删除最短路径则不知弹射哪些杯；删除弹射/清空则无输出变化。

杯中内容像素的数量编码了图的边权，最短路径上的杯沿尾部方向弹射内容，其余杯被清空。

**输入结构**：约 25x25 的黑(0)背景网格。5~7 个杯形框架散布其上，每个杯的边框使用同一种颜色——蓝(1)。每个杯是一个 5x5~7x7 的 U 形或 C 形开口框架，开口朝上/下/左/右之一，在开口对侧有一个 1 像素的尾刺突出。杯的内部（开口区域内侧）包含若干红(2)内容像素（1~5 个不等）。其中恰好 2 个杯的边框为橙(7)而非蓝(1)，标记为终端节点。杯与杯之间通过绿(3)的 1 像素宽轨道段相连，形成无向图（无环，但可能有分叉）。生成约束：图是连通的；两个终端之间存在至少两条不同路径；不同路径上的内容像素总数不同（保证最短路径唯一）。

**规则**：
1. 将每个杯视为图的一个节点。两个杯之间若有绿(3)轨道段直接相连，则构成一条边。
2. 每条边的权重 = 该边两端杯中红(2)内容像素数量之和。
3. 计算两个橙(7)终端节点之间的最短路径（权重总和最小的路径）。
4. 对最短路径上的每个非终端杯：识别其尾刺方向，将杯内所有红(2)内容像素擦除为黑(0)，然后从尾刺尖端开始沿尾刺朝外方向逐像素绘制红(2)，绘制的像素数 = 被擦除的内容像素数。若射线超出网格边界则截断。
5. 对终端杯：保持内容像素不变（不弹射）。
6. 对不在最短路径上的杯：擦除其内部所有红(2)内容像素为黑(0)，不弹射。
7. 最短路径上的轨道段重涂为灰(5)；其余轨道段保持绿(3)不变。
8. 所有杯的边框保持不变。

**关键洞察**：内容像素承担双重角色——既是图的边权（用于寻路计算），又是弹射的物理载荷（守恒地转移到尾部外侧）。这种同一数据的双重语义在单个示例中极易被忽略。

## 新题 4：四象限提取驱动配色对接

**组合逻辑**：[crop + four_way_reflective_symmetry](已有：提取象限) → [color_match_pairing](创新：提取出的象限按子区域颜色配对到空心方框的边) → [docking + symmetry_disambiguates_rotation](创新：对接时旋转由对称性消歧)

**来源原语**：crop、quadrant、four_way_reflective_symmetry（来自 73182012）；docking、hollow_square、color_match_pairing、symmetry_disambiguates_rotation（来自 2c181942）；sprite（来自 2c181942）

**依赖链**：四象限提取得到源瓦片 → 源瓦片被分解为子区域 → 子区域颜色与空心框边颜色配对 → 配对确定对接位置 → 对称性消歧确定旋转角度。每一步的输出都是下一步不可替代的输入。

从四向镜像面板中还原源瓦片，将瓦片拆分为四个子区域，按颜色匹配对接到中央空心方框的四条边上。

**输入结构**：约 22x22 的黑(0)背景网格，包含两个不重叠的结构：(A) 一个 8x8 的前景面板，其四个 4x4 象限互为反射对称（左右镜像、上下镜像、180 度旋转），面板由 4 种非黑颜色构成；(B) 一个 6x6 的空心矩形（边框宽 1 像素），四条边各使用不同颜色：上边红(2)、下边绿(3)、左边蓝(1)、右边黄(4)，四个角像素为黑(0)，内部为黑(0)。结构 A 的左上象限（4x4）恰好可被一条水平线和一条垂直线分为四个 2x2 子区域，每个子区域是单色的，四个子区域的颜色恰好与空心框的四条边颜色一一对应。生成约束：源瓦片（左上象限）在四个旋转态下互不相同；每个 2x2 子区域关于其将要对接的边的法线方向具有镜像对称性（用于消歧旋转）。

**规则**：
1. 识别 8x8 前景面板，提取其左上 4x4 象限作为源瓦片 S。
2. 将 S 沿中心十字分为四个 2x2 子区域：左上 P_TL、右上 P_TR、左下 P_BL、右下 P_BR。
3. 对每个子区域 P，找到空心框中颜色与 P 相同的那条边，记为目标边。
4. 旋转子区域 P（0/90/180/270 度），使其在垂直于目标边的轴上具有镜像对称性，且其接触边（朝向框的一侧）有 2 个像素与目标边对齐。若多个旋转角度都满足对称性条件，选择使 P 的非接触边像素与目标边中心最近的那个旋转。
5. 将旋转后的 P 平移到紧贴目标边外侧的位置，居中对齐。
6. 输出 = 空心框 + 四个对接后的子区域，其余一切清为黑(0)（包括原始面板）。

**关键洞察**：提取和对接是两个完全不同的操作，但它们通过颜色配对紧密耦合——必须先正确提取象限才能获得子区域颜色，而子区域颜色又是对接配对的唯一线索。

## 新题 5：尺寸分级多操作调度

**组合逻辑**：[size_classification](创新：尺寸不再只是二分类描边/忽略，而是三级分类调度不同操作) → [outline | fill + ray_extend](各级对应不同操作) → 操作结果之间存在覆盖冲突需按优先级解决

**来源原语**：outline、size_classification、micro_obj_outlined（来自 b27ca6d3）；fill、marker_color_sets_fill、cap_layer_added（来自 444801d8）；ray_extend、seed_color_determines_extend（来自 178fcbfb）；connected_component（来自 b27ca6d3）；containment（来自 444801d8）；marker_pixel（来自 5117e062）

**依赖链**：连通分量面积决定分类 → 分类决定应用哪种操作 → 不同操作的输出在空间上可能重叠 → 冲突解决规则依赖于操作类型。删除分类则不知道对哪些对象做什么；删除任一操作则一类对象无输出；删除冲突解决则重叠区域不确定。

红色连通分量按面积分为三级，每级触发不同操作（忽略/描边/填充延伸），操作结果之间的空间冲突按固定优先级解决。

**输入结构**：约 16x16 的黑(0)背景网格。散布若干红(2) 4-连通前景分量，面积从 1 到约 12 像素不等。面积分三级：1 像素（噪声）、2 像素（微型条/dominoes）、3 像素及以上（大型）。每个大型分量的边界框内部恰好包含一个非红非黑的标记像素（蓝(1)或绿(3)之一）。生成约束：微型条既有水平也有垂直朝向；大型分量至少有 2 个；蓝标记和绿标记各至少出现一次；任意两个大型分量的边界框不重叠；微型条不位于任何大型分量的边界框内。

**规则**：
1. 计算每个红(2) 4-连通分量的面积。
2. 面积 = 1（噪声）：擦除为黑(0)。
3. 面积 = 2（微型条）：保留原像素，并在其边界框外扩 1 像素的矩形周边（裁剪到网格内）绘制绿(3)描边框，仅在当前为黑(0)的像素上绘制。
4. 面积 >= 3（大型分量）：找到其边界框内的标记像素。
   - 标记为蓝(1)：将分量所有像素填充为蓝(1)，然后从分量边界框的垂直中心行向左和向右各延伸一条蓝(1)射线，直到碰到非黑像素或网格边缘（不包含终点）。
   - 标记为绿(3)：将分量所有像素填充为绿(3)，然后从分量边界框的水平中心列向上和向下各延伸一条绿(3)射线，直到碰到非黑像素或网格边缘（不包含终点）。
5. 标记像素本身在填充时被覆盖（融入填充色）。
6. 冲突解决：描边（绿框）的优先级高于射线延伸——若射线经过描边框的像素，描边框保留不被覆盖。处理顺序：先执行所有大型分量的填充和射线延伸，再执行所有微型条的描边。

**关键洞察**：面积阈值创造了三条完全不同的操作分支，但这些分支不是独立的——射线延伸可能穿过微型条的描边区域，描边优先级规则在单个示例中不一定能观察到（需要对比有冲突和无冲突的示例）。

## 新题 6：跨面板质心循环置换

**组合逻辑**：[sorting + centroid_offset_positioning](已有) → [positional_selection](创新：选择策略不再是"第 k 面板取第 k 个"，而是按面板内质心排名选取) → [merge](创新：放置位置不由源面板决定，而由循环右移的邻面板质心位置决定)

**规则**：
1. 对每个面板，按对象质心的行坐标从小到大排序（行坐标小 = 靠上 = 排名第 1）。
2. 从左面板 L 选排名第 1（质心最高）的对象 O_L；从中面板 M 选排名第 2（质心居中）的对象 O_M；从右面板 R 选排名第 3（质心最低）的对象 O_R。
3. 创建一个与单面板同尺寸（10x10）的黑(0)输出画布。
4. 放置规则（循环右移）：
   - O_L 放置到 O_M 在 M 面板中的质心行坐标位置（即 O_L 的质心行对齐到 O_M 原来的质心行，列坐标保持 O_L 在 L 面板中的相对列坐标）。
   - O_M 放置到 O_R 在 R 面板中的质心行坐标位置（列坐标保持 O_M 在 M 面板中的相对列坐标）。
   - O_R 放置到 O_L 在 L 面板中的质心行坐标位置（列坐标保持 O_R 在 R 面板中的相对列坐标）。
5. 若放置后对象超出画布边界，超出部分裁剪。若两个对象在输出中重叠，后放置的覆盖先放置的（放置顺序：O_L → O_M → O_R）。

**关键洞察**：选取规则和放置规则是解耦的两套逻辑，但它们通过质心位置这一共享属性交织在一起——你必须同时理解"面板序号决定选取排名"和"循环右移决定行坐标"，缺一不可。单个示例无法区分循环右移和其他可能的排列方式。

## 新题 7：掩码选通的四向对称补全与涂色

**组合逻辑**：[dominant_color_selects_pos](创新：高频色不再选印章位，而是选择哪些象限参与对称补全) → [symmetry_completion + four_way_reflective_symmetry](创新：补全不是复原已知瓦片，而是从多个残缺象限交叉推断完整图案) → [recolor](创新：被选中象限统一涂为掩码色)

**来源原语**：dominant_color_selects_pos、input_pattern、block_slot（来自 27f8ce4f）；symmetry_completion、tile_fragment、four_way_reflective_symmetry（来自 4e45f183、73182012）；recolor（来自 a09f6c25）

**依赖链**：高频色位置选通象限 → 被选通的象限提供对称信息用于补全 → 补全后所有象限获得完整图案 → 被选通象限统一重涂色。删除选通则不知补全哪些象限；删除对称补全则残缺象限无法恢复；删除重涂色则选通象限不可见。

一个 3x3 颜色掩码选择 2x2 象限阵列中的参与者，被选中的残缺象限通过四向反射对称互相补全，最终被选中象限统一涂为掩码色。

**输入结构**：约 15x15 的黑(0)背景网格，包含两个分离结构：(A) 一个 3x3 的颜色掩码方块，其中恰好有一种颜色出现次数最多（至少 3 次），记为掩码色 C_m，其余位置为其他非黑颜色。(B) 一个 10x10 的区域（偶数边长），被中心十字线分为四个 5x5 象限（十字线本身为灰(5)，宽 1 像素，不算入象限）。每个象限包含同一个源图案的某种反射变体（左右/上下/180 度），但每个象限随机擦除了 1~3 个像素为黑(0)。四个象限合在一起包含源图案的所有像素信息（即没有任何像素在所有四个象限的对应位置都被擦除）。生成约束：源图案不具有任何自身对称性（确保四个旋转/反射态可区分）；掩码方块中 C_m 出现的位置数量恰好为 2 或 3（不是全部 9 个）。

**规则**：
1. 识别 3x3 掩码中出现次数最多的颜色 C_m 及其所在位置集合 S。
2. 将 S 中的位置映射到 2x2 象限选择：掩码的左上 2x2 区域映射到四个象限（掩码(0,0)→左上象限，掩码(0,1)→右上象限，掩码(1,0)→左下象限，掩码(1,1)→右下象限）。掩码中第三行和第三列若含 C_m 则作为冗余确认，不引入新的象限选择。
3. 利用四向反射对称关系，从所有四个象限（无论是否被选中）的未擦除像素交叉推断出完整的源图案 P。具体方法：对于源图案位置 (r,c)，检查四个象限在其对应反射位置的像素值，取第一个非黑值作为 P(r,c)。
4. 用完整源图案 P 及其反射变体填回所有四个象限的被擦除位置（修复）。
5. 将 S 选中的象限中所有非灰非黑像素统一重涂为 C_m。未选中的象限保持修复后的原色。
6. 输出仅包含 10x10 象限区域（含灰色十字线），掩码方块不出现在输出中。

**关键洞察**：掩码的高频色同时承担两个角色——选择哪些象限被重涂，以及提供重涂的目标颜色。而对称补全必须利用包括未选中象限在内的全部信息，形成"全局推断、局部着色"的约束结构。

## 新题 8：隐含十字图节点的块网格路径反转

**组合逻辑**：[missing_center + four_way_aligned](创新：隐含十字的中心标记不再只是重涂色，而是构建图的节点) → [pathfinding + door_segment](创新：块网格分隔线上的门段定义图的边) → [invert_code](创新：路径上的块执行精灵/空白反转)

**来源原语**：missing_center、micro_bar、implied_plus、four_way_aligned（来自 9f5f939b）；block_grid、repeated_sprite、uniform_blank、sprite_blank_inv（来自 6350f1f4）；door_segment（来自 7e576d6e）；pathfinding（来自 7e576d6e）；invert_code（来自 6350f1f4）

**依赖链**：隐含十字检测产生图节点 → 分隔线门段产生图边 → 图的路径搜索确定要反转的块 → 反转操作改变块的精灵/空白状态。每步缺失都导致后续不可执行。

在块网格中，含有隐含十字结构的块为图节点，分隔线上的门段为图边，起点到终点路径上的所有块执行精灵/空白状态反转。

**输入结构**：约 19x19 的网格，由黑(0)分隔行和分隔列划分为 3x3 共 9 个等大方块（每块约 5x5），分隔线宽 1 像素。每个方块要么是蓝(1)前景色的某个固定小精灵（3~5 像素的非对称 4-连通图案，所有精灵块使用同一个图案），要么是红(2)的均匀填充块（"空白"态）。部分方块内部额外存在隐含十字结构：四个绿(3)的 2 像素微型条分布在方块中心的上下左右各偏移 2~3 格处（微型条叠加在精灵或空白图案之上）。分隔线（黑色）的某些位置有 1 像素宽的黄(4)门段，表示相邻两个方块之间存在通路。恰好有 2 个方块标记为终端：这两个方块的四角各有一个橙(7)像素。生成约束：含隐含十字的方块有 3~5 个；门段只出现在两个都含隐含十字的相邻方块之间的分隔线上；两个终端方块都含隐含十字；终端之间通过门段连通（存在至少一条路径）。

**规则**：
1. 识别每个方块中是否存在隐含十字结构（中心周围四个方向各有一个绿(3)微型条）。存在隐含十字的方块标记为图节点。
2. 将每个隐含十字的中心像素涂为黄(4)。
3. 检查每条分隔线上的黄(4)门段：若门段两侧的方块都是图节点，则构成一条图边。
4. 找到两个终端方块（含橙(7)角标记）之间的最短路径（经过最少的边）。若最短路径不唯一，选择路径上方块的行列坐标字典序最小的那条。
5. 对路径上的每个方块（包括终端）执行状态反转：
   - 精灵块 → 将精灵像素擦为红(2)，变成均匀空白块。
   - 空白块 → 将均匀红(2)替换为蓝(1)精灵图案（使用与其他精灵块相同的图案，左上角对齐）。
6. 反转后，保留隐含十字的绿(3)微型条和黄(4)中心点不变（它们叠加在反转后的底图上）。终端的橙(7)角标记也保留。
7. 不在路径上的方块保持不变。门段保持黄(4)不变。

**关键洞察**：隐含十字在源题中只标记一个缺失中心，这里它被重新赋予"图节点"的结构角色；块的精灵/空白状态在源题中是全局反转，这里只对路径上的块局部反转——这两个改造使得三个独立的参考题机制形成了不可分割的推理链。

## 新题 9：精灵朝向驱动的方向弹射与全局反转

**组合逻辑**：[repeated_sprite + sprite_blank_inv](已有：识别精灵/空白态) → [tail_determines_emission](创新：精灵的不对称形状本身定义弹射方向，而非外部尾刺) → [ejection](创新：仅空白态块弹射，精灵态块吸收) → [invert_code](已有：弹射完成后全局反转)

**来源原语**：repeated_sprite、uniform_blank、sprite_blank_inv、invert_code、wildcard_as_blank（来自 6350f1f4）；ejection、tail_spike、tail_determines_emission、pixel_count_conservation（来自 3dc255db）；content_pixel（来自 3dc255db）

**依赖链**：精灵的形状不对称性定义方向 → 方向决定弹射走向 → 块的精灵/空白状态决定弹射还是吸收 → 弹射完成后全局反转改变所有块状态。四步紧密耦合，删除任一步均无法得出正确输出。

块网格中不对称精灵的"尖端"定义方向，空白块沿此方向弹射内容像素，随后所有块执行精灵/空白反转。

**输入结构**：约 15x15 的网格，由黑(0)分隔行和列划分为 3x3 共 9 个等大方块（每块约 4x4），分隔线宽 1 像素。所有精灵块共享同一个蓝(1)小图案（3~4 像素的非对称 4-连通图案，具有唯一的"尖端"方向——像素分布的质心偏离几何中心的方向即为尖端朝向，尖端指向上/下/左/右之一）。空白块为红(2)均匀填充。部分空白块的中心有一个绿(3)像素（内容像素）。灰(5)像素可出现在任何块中，视为通配符（在判断精灵/空白态时忽略）。生成约束：精灵的尖端方向在所有示例中保持一致；含绿(3)内容像素的空白块至少有 2 个；精灵块和空白块各至少有 3 个。

**规则**：
1. 从完整可见的精灵块（不含灰(5)通配符）中推断精灵图案及其尖端方向 D（质心相对于方块几何中心的偏移方向，取四个基本方向中最近的）。
2. 对每个含绿(3)内容像素的空白块：沿方向 D 发射绿(3)射线，从该方块在 D 方向边缘的外侧下一个像素开始，穿过分隔线，绘制 1 个像素（射线长度固定为 1，因为每个空白块只有 1 个内容像素）。射线绘制在分隔线上的像素会覆盖黑(0)。若射线目标位置已超出网格边界则不绘制。绘制后擦除原空白块中的绿(3)内容像素为红(2)。
3. 对每个不含内容像素的空白块和精灵块：不执行弹射操作。
4. 弹射全部完成后，执行全局反转：所有精灵块变为红(2)均匀空白块，所有空白块（包括已弹射过的）变为蓝(1)精灵图案（精灵左上角与方块左上角对齐）。
5. 灰(5)通配符像素在反转后保持灰(5)不变（覆盖在反转后的底图之上）。
6. 分隔线上被射线覆盖的绿(3)像素保留不变（不受反转影响，因为分隔线不属于任何方块）。

**关键洞察**：精灵的几何不对称性在源题中无语义，这里被赋予了"方向编码"的角色——同一个图案既是视觉标识（区分精灵/空白），又是方向指示器（决定弹射走向）。全局反转在弹射之后执行，意味着弹射时的空白块在输出中变成了精灵块，造成视觉上的"反直觉"效果。

## 新题 10：格网杯填充与位置驱动封盖延伸

**组合逻辑**：[lattice + separator_partition](已有) → [fill + marker_color_sets_fill](已有) → [cap_layer_added](创新：封盖方向不再固定朝上，而由杯相对于模板的位置决定) → [ray_extend + axis_aligned](创新：从封盖端沿同方向射线延伸到分隔线)

**来源原语**：lattice、separator_partition（来自 39e1d7f9）；fill、cup_outline、marker_pixel、marker_color_sets_fill、cap_layer_added（来自 444801d8）；ray_extend、axis_aligned（来自 a2d730bd）；same_color_match（来自 a2d730bd）；neighborhood_template（来自 39e1d7f9）

**依赖链**：格网结构划分出杯所在的格子 → 模板杯示范填充+封盖模式 → 其他杯复制该模式但封盖方向由相对位置决定 → 封盖方向进一步驱动射线延伸。删除格网则不知道杯的格子位置；删除模板则不知道填充模式；删除位置判断则封盖方向不确定；删除射线则输出不完整。

格网中散布着杯形轮廓，一个已填充封盖的模板杯示范变换模式，其余杯按位置关系确定封盖方向并沿该方向射线延伸。

**输入结构**：约 21x21 的网格，由灰(5)分隔行和分隔列划分为 4x4 共 16 个格子（每格约 4x4），分隔线宽 1 像素。大部分格子为黑(0)背景。其中 4~6 个格子各含一个蓝(1)杯状轮廓（U 形/C 形/倒 U 形/反 C 形，开口朝上/下/左/右之一，占据格子内约 3x3 区域），杯内有一个标记像素（颜色为红(2)、绿(3)或黄(4)之一，每个杯的标记色可不同）。其中恰好一个杯已被填充并封盖：杯内部全部填为标记色，且在杯开口方向外侧紧邻的一行/列有一条与杯口等宽的标记色封盖条。该杯即为模板杯。生成约束：模板杯位于格网的非边缘格子（确保四个方向都有邻格）；其余杯未填充（内部只有标记像素和黑色）；不同示例中杯的开口方向和标记颜色组合不同。

**规则**：
1. 识别模板杯（已填充且封盖的杯），记录其填充+封盖的模式：内部填充为标记色，开口方向外加一条封盖层。
2. 对每个非模板杯，执行以下操作：
   a. 用杯自身的标记色填充杯内部（将杯内所有黑(0)像素涂为标记色）。
   b. 确定封盖方向：计算该杯所在格子相对于模板杯所在格子的方向向量。若该杯在模板杯的上方（行坐标更小），封盖朝上；下方则朝下；左方则朝左；右方则朝右。若同时有行和列偏移，取偏移绝对值更大的维度（相同则取行方向）。
   c. 在封盖方向上，紧邻杯口外侧绘制一条与杯口等宽的标记色封盖条（宽 1 像素）。
   d. 从封盖条继续沿同方向延伸标记色射线（宽 1 像素，取杯口中心列/行），直到碰到灰(5)分隔线为止（不包含分隔线像素）。
3. 模板杯保持不变（已经是填充+封盖状态，但不需要射线延伸）。
4. 处理顺序：按格子从左上到右下的行优先顺序逐个处理。若射线经过已被其他杯射线涂色的像素，后处理的覆盖先处理的。

**关键洞察**：模板杯只示范了"填充+封盖"这个局部模式，封盖方向和射线延伸是求解者必须从多个示例中归纳出的隐蔽规则——单看模板杯无法得知封盖方向由相对位置决定，也无法得知封盖之后还有射线延伸。
