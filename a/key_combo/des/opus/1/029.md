## 新题 1：重力筛选嵌入

**组合逻辑**：[gravity_drop](已有，创新为"逐层尝试"而非直接落底) + [shape_matching -> embed](已有，创新为沿重力路径逐一检验) + [area_determines_role](已有) + [erase](已有)（创新核心：重力的连续空间搜索与离散形状判别融合为"空间形状滤波链"——碎片沿重力路径逐一穿过容器，仅在形状匹配处停驻）

**来源原语**：gravity_drop, stop_at_bottom, area_determines_role (6ca952ad); shape_matching, piece_fits_hole, embed (228f6490); erase (f21745ec); hole (228f6490)

**依赖链**：面积阈值将对象分为容器和碎片 -> 碎片按重力下落，逐行扫描路径上的容器 -> 每遇容器，检查碎片掩码是否与该容器孔洞全等 -> 首次匹配即嵌入容器孔洞 -> 不匹配则穿透继续下落 -> 到达底部仍无匹配的碎片被擦除。重力的空间顺序决定了哪个容器优先接收碎片，形状判别决定是否真正停驻——两者交织成不可拆分的空间筛选逻辑。

将小碎片从上方沿重力下落，穿过不匹配的容器孔洞，在第一个形状匹配的容器中嵌入，无匹配则消失。

**输入结构**：
- 网格约 20x15，背景黑(0)
- 灰(5)矩形实心块 3 个，面积均 > 12 像素，分布在网格中部和下部的不同行高（相邻容器之间至少隔 2 行空行），每个块内部有一个黑(0)孔洞——孔洞为 4-连通的不规则形状，像素数 3~6，三个孔洞形状两两不同
- 彩色小碎片 3 个，分别为蓝(1)、红(2)、绿(3)，每个碎片 3~6 像素，4-连通不规则形状，位于网格最顶部 3 行内
- 每个碎片的列范围（边界框的左列到右列）与其正下方至少两个容器的列范围有交集
- 生成约束：三个碎片中恰好两个的掩码与某个孔洞形状全等（可平移重合），第三个碎片无匹配孔洞；三个碎片的列范围互不重叠；一个碎片的匹配孔洞在路径上的第一个容器中，另一个碎片的匹配孔洞在路径上的第二个容器中（需穿越第一个不匹配的容器）

**规则**：
1. 角色划分：面积 > 10 的灰(5)连通区域为容器，其余非背景 4-连通区域为碎片
2. 对每个碎片，将其二值掩码（仅看形状占位，忽略颜色）整体沿行方向逐行向下平移
3. 在每个平移位置，检查碎片掩码是否与当前重叠的容器孔洞掩码全等——即碎片掩码平移后恰好覆盖孔洞的所有黑(0)像素且不超出孔洞范围
4. 若全等匹配：将碎片以自身颜色绘入孔洞对应位置，碎片原位置恢复为黑(0)。该孔洞标记为已占用，不再接受其他碎片
5. 若碎片掩码底行到达网格最后一行仍未匹配任何孔洞：碎片原位置恢复为黑(0)（碎片消失）
6. 处理顺序：碎片按边界框顶行从大到小处理（最靠下的碎片先处理），顶行相同则按左列从小到大
7. 容器灰(5)外轮廓及未被嵌入的孔洞保持不变

**关键洞察**：容器的垂直排列构成一条"形状滤波链"——碎片不是落入最近的容器，而是穿透不匹配的容器、落入路径上第一个形状全等的容器；若将容器的上下顺序对调，输出会改变。

## 新题 2：异或种子射线竞争图

**组合逻辑**：[xor_overlay](已有) -> [ray_cast](已有，创新为从异或分歧点发射正交射线) + 射线间互相遮挡（创新：源题中射线沿对角线穿过引导体终端，此处射线从 XOR 种子沿正交方向扩展，且射线之间构成竞争性空间分割）

**来源原语**：xor_overlay, separator_row, foreground_mask, disagreement_cells_painted (99b1bc43); ray_cast, guide_object (a78176bb); erase (f21745ec)

**依赖链**：分隔行将输入分为上下两掩码 -> 逐格异或提取分歧像素作为种子 -> 每颗种子向四个正方向发射射线 -> 射线遇到已有种子或已有射线即停止 -> 处理顺序决定射线长度。异或的空间分布直接控制射线图的拓扑——分歧点密集处射线被截短，稀疏处射线延伸到边界。

将上下两面板的前景差异像素提取为种子，再从每颗种子向四方发射射线直至碰撞，形成竞争性十字星网络。

**输入结构**：
- 网格总高 17 行、宽 9 列，背景黑(0)
- 第 9 行（0-索引第 8 行）为灰(5)分隔行，贯穿整行
- 上半区（行 0~7，共 8 行 x 9 列）：蓝(1)像素组成的前景掩码，5~10 个前景像素散布其中
- 下半区（行 9~16，共 8 行 x 9 列）：红(2)像素组成的前景掩码，5~10 个前景像素
- 两掩码有部分重叠区域和部分独有区域
- 生成约束：异或后分歧像素（恰好一个半区为前景）数量在 4~7 之间；分歧像素两两曼哈顿距离 >= 3（保证射线有足够空间展开）

**规则**：
1. 移除灰(5)分隔行。将上半区与下半区逐格对齐（上半区第 i 行第 j 列对应下半区第 i 行第 j 列），得到 8x9 的工作网格
2. 对齐后，若位置 (i,j) 上恰好一个半区为前景、另一个为背景，则该位置标记为绿(3)种子；若两半区都为前景或都为背景，则该位置为黑(0)
3. 对每颗绿(3)种子，从该格分别向上、下、左、右四个方向逐格延伸绿(3)射线。射线在以下情况停止（停止位置不涂色）：(a) 下一格超出工作网格边界；(b) 下一格已是绿(3)（种子或其他射线）
4. 种子按行优先（行号从小到大）、列次优先（列号从小到大）的顺序依次处理；先处理种子的射线可阻挡后处理种子的射线
5. 工作网格中未被种子或射线覆盖的格保持黑(0)
6. 输出为 8x9 的工作网格

**关键洞察**：种子处理顺序（行优先从左上到右下）使左上方种子的射线倾向于更长、右下方种子的射线被截断——仅看单个示例无法确定处理方向是左上优先还是右下优先，需对比多个示例中相似种子布局下的射线长度不对称性来归纳。

## 新题 3：互补拼合驱动瓦片补全

**组合逻辑**：[complement_fit + non_overlap_pack](已有) <-> [tiling + completion](已有)（创新核心：拼合与补全构成双向约束满足——碎片拼合给出候选瓦片集合，可见格子反向筛选唯一正确拼法，两侧信息缺一不可，不是单向流水线）

**来源原语**：non_overlap_pack, complement_fit, densest_minimal_bbox (681b3aeb); tiling, completion, occluded_region, infer_from_visible (ca8f78db); crop (681b3aeb); separator_row (99b1bc43)

**依赖链**：两块互补碎片可以有多种等面积的平移拼法 -> 每种拼法产生一个候选瓦片 -> 下方可见重复图案只与其中一种拼法像素完全一致 -> 用该唯一瓦片平铺修复遮挡区域。碎片拼合和可见图案同时约束答案，两侧信息互为必要条件。

从两块拼图碎片的最密拼合中重建瓦片单元，再用该瓦片修复下方被遮挡的重复图案。

**输入结构**：
- 网格约 18x12，背景黑(0)
- 顶部 4 行：两块单色碎片。碎片 A 为蓝(1)，碎片 B 为红(2)，各 3~5 像素，4-连通不规则形状，互不接触（水平距离 >= 2 列）
- 第 5 行：灰(5)分隔行，贯穿整行
- 下方 13 行：蓝(1)和红(2)像素交织组成的重复图案平铺区域。图案中有 1~2 个矩形遮挡区域（全为黑(0)，宽高各 2~4 格）
- 重复图案的周期瓦片为碎片 A 和碎片 B 最密拼合后的结果（矩形包围盒，约 3x3 至 4x4）
- 生成约束：两碎片恰好有 2 种不重叠最密拼法（最小包围盒面积相同），但仅有一种与下方可见像素在行列模余上完全一致

**规则**：
1. 从顶部裁剪出碎片 A（蓝(1)）和碎片 B（红(2)）的二值掩码及颜色
2. 枚举所有平移（不旋转不翻转）下的不重叠放置，计算二者并集的最小包围盒面积，保留面积最小的所有拼法
3. 对每种最密拼法，将拼合结果视为候选瓦片（包围盒内：碎片 A 占位填蓝(1)，碎片 B 占位填红(2)，空位填黑(0)）
4. 将每个候选瓦片在下方区域按行列模余对齐，与所有可见（非黑(0)）像素逐格比较。保留与可见像素完全一致的唯一候选
5. 用确定的瓦片按行列模余平铺下方区域，所有遮挡格（原为黑(0)但瓦片对应位置非黑(0)）填入瓦片颜色
6. 输出仅保留下方区域（去除顶部碎片区和灰(5)分隔行），尺寸为 13x12

**关键洞察**：碎片拼合给出"可能的瓦片"（多选一），可见图案给出"必须满足的约束"——两者共同唯一确定答案。仅看碎片无法选出正确拼法，仅看图案无法完整推断瓦片单元。

## 新题 4：重叠矩形框遮挡序解码

**组合逻辑**：[transparent_overlay](已有，创新为 N 层遮挡叠加而非两面板合并) + [sorting](已有，创新为从局部遮挡线索推断偏序后拓扑排序)（创新核心：叠加可见性编码了隐式偏序关系，求解者需从边框交叉处的局部颜色推断全局堆叠排序——这是结构解构型推理，非流水线）

**来源原语**：transparent_overlay, cell_alignment (dae9d2b5); sorting, height_order (b7999b51); hollow_rect (f21745ec); counting (b7999b51)

**依赖链**：多个不同颜色的空心矩形框叠放于同一网格 -> 边框交叉处仅显示上层颜色 -> 从可见交叉格推断两两遮挡偏序 -> 部分框对之间无直接交叉，需经第三框传递推断 -> 拓扑排序得到全局从顶到底的颜色序列 -> 输出为一列颜色。

从多个重叠空心矩形框的边框交叉处可见颜色中推断完整堆叠顺序，输出从顶层到底层的颜色列。

**输入结构**：
- 网格约 15x15，背景黑(0)
- 4 个一格宽的空心矩形框（仅边框像素，内部为黑(0)），每个框使用不同颜色：蓝(1)、红(2)、绿(3)、黄(4)。边框外高各 5~9 格、外宽各 5~9 格，大小不完全相同
- 矩形框的位置使得：每两个相邻层级的框至少有一段边框交叉（存在某格同属两个框的边框路径）
- 交叉格仅显示堆叠层级更高的框的颜色（上层遮挡下层）
- 每个框的四个角像素中至少有两个可见（未被更高层框遮挡），确保可从可见像素重建每个框的完整矩形范围
- 生成约束：遮挡偏序可唯一确定一个全序（4! 排列中仅一种与所有可见交叉一致）；至少有一对框之间无直接边框交叉，其先后关系须通过与第三框的传递推断获得

**规则**：
1. 识别所有空心矩形框：每种前景颜色的可见像素构成某个矩形的边框子集。利用可见角点（至少两个可见角）推断每个框的完整矩形范围（左上角和右下角坐标）
2. 还原每个框的完整边框路径（矩形四边所有格的集合）。在两个框的边框路径交叉位置（同一格属于两框的边框），可见颜色属于堆叠层级更高的框。由此建立有向关系：可见色 -> 被遮挡色（可见色在上层）
3. 若两个框无直接交叉，其相对层级通过传递性推断（A 在 B 上，B 在 C 上 -> A 在 C 上）
4. 对所有有向关系做拓扑排序，得到唯一的从顶层到底层的颜色全序
5. 输出为 4x1 的列网格，从第 0 行到第 3 行依次填入从顶层到底层的框颜色

**关键洞察**：某些框之间无直接边框交叉，其先后关系必须通过与第三个框的传递推断获得——仅从直接遮挡对无法确定全序。需要对比多个示例来确认传递推断规则而非仅读取直接遮挡结果。

## 新题 5：图例双编码驱动同心展开

**组合逻辑**：[rank_correspond + legend_pos_color](已有) + [expand + center_expand](已有) + [counting](已有，创新为"图例像素数编码展开半径")（创新核心：图例同时承载两种信息维度——颜色排列位置编码映射对象，像素数量编码展开规模——单一元素的双重语义是源题中不存在的结构关系）

**来源原语**：rank_correspond, legend_pos_color, color_legend (fafd9572); expand, center_expand, parity_determines_color (db3e9e38); counting, pixel_count (f8ff0b80, 1fad071e)

**依赖链**：识别图例区域中各颜色的像素数 -> 像素数编码该颜色对应标记点的展开半径 -> 图例颜色的排列位置与标记点的空间排位一一对应确定颜色映射 -> 每个标记点以中心向外展开 n 层同心方环，奇偶层交替使用映射颜色与黑色。

图例中每种颜色的像素数量决定对应标记点的同心方环展开半径，图例的位置顺序决定颜色映射。

**输入结构**：
- 网格约 20x20，背景黑(0)
- 左上角区域（行 0，列 0~5 以内）有一个紧凑的水平图例：3 种颜色的像素紧密排成一行（水平相邻），如蓝(1)占 1 格、红(2)占 2 格、绿(3)占 3 格，从左到右排列。图例总宽 = 三种颜色像素数之和（此例为 6），高 1 格
- 网格中分布 3 个灰(5)单像素标记点，位置互不相邻且距网格边界至少 5 格，标记点两两曼哈顿距离 >= 10（保证展开后不重叠）
- 标记点按行优先（行号从小到大）、列次优先（列号从小到大）排列，与图例中颜色从左到右的顺序一一对应
- 生成约束：展开半径最大为 3 层（图例中单色最多 3 像素），展开后的同心方环不超出网格边界且不互相重叠

**规则**：
1. 识别图例：位于网格第 0 行最左端的连续非黑(0)非灰(5)像素段。图例中的颜色按从左到右出现的顺序排列，每种颜色连续占若干格
2. 统计图例中每种颜色的连续像素数量 n_c，该数值为展开半径
3. 将图例颜色按从左到右顺序排列，与灰(5)标记点按行优先、列次优先排序后一一对应：图例第 1 种颜色 -> 排序第 1 的标记点，依此类推
4. 对每个标记点：以该点为中心，绘制 n_c 层同心方形环。方形环的第 k 层（k >= 0）为所有切比雪夫距离恰好等于 k 的格集合。k=0（中心像素）用映射颜色填充。k >= 1 时：k 为奇数填黑(0)，k 为偶数填映射颜色
5. 灰(5)标记点被中心层的映射颜色覆盖
6. 图例区域保留不变
7. 超出网格边界的部分舍弃不绘制

**关键洞察**：图例的每种颜色同时编码两个独立维度——空间排列位置编码映射目标（对应哪个标记点），像素数量编码展开规模（几层环）。单个示例无法区分"像素数编码半径"与"颜色编号编码半径"等替代假说，需多个示例对比排除。

## 新题 6：镜像周期归一化后异或检错

**组合逻辑**：[mirror + period](已有) -> [xor_overlay](已有，创新为"归一化后逐块异或检测损坏")（创新核心：镜像识别不是最终输出而是为异或比较提供前置归一化——不做镜像归一化则异或产生大量假阳性，两步骤以"噪声消除-信号提取"方式紧耦合）

**来源原语**：mirror, period, smallest_period_flipped (2dee498d); crop (2dee498d); xor_overlay, disagreement_cells_painted (99b1bc43); foreground_mask (99b1bc43)

**依赖链**：找到最小列周期使每块为基础块的直接或镜像拷贝 -> 对每块判定镜像变体类型 -> 按逆变换将每块归一化到基础块朝向 -> 将归一化后的块与基础块逐格异或 -> 仅被损坏的块产生非零分歧 -> 输出标记损坏位置。

在含镜像重复的瓦片阵列中定位被篡改的像素，先按镜像类型归一化再异或比较以排除镜像造成的假差异。

**输入结构**：
- 网格约 12x16，背景黑(0)
- 网格水平方向等分为 4 个列块，每块宽 4 列、高 12 行
- 第一块（列 0~3）为基础瓦片，使用蓝(1)和红(2)在黑(0)背景上绘制非对称图案（8~12 个前景像素，非水平对称且非垂直对称）
- 后续 3 块各为基础瓦片的某种变体：直接复制、水平翻转（左右镜像）或垂直翻转（上下镜像），三块中至少出现两种不同变体
- 恰好有 1 个块被"损坏"：在其正确变体基础上有 1~2 个像素被篡改（前景变背景、背景变前景、或蓝红互换）
- 生成约束：基础瓦片足够不对称，使直接复制与任何镜像在至少 4 个像素位置上不同（防止误判）；损坏的像素位置不在基础瓦片的对称轴上（如果存在部分对称）

**规则**：
1. 确定列块宽度 w = 4，将网格分为 4 个列块 B_0, B_1, B_2, B_3
2. 对每块 B_i（i = 1, 2, 3），分别计算其与 B_0 的三种比较：(a) B_i 与 B_0 直接比较的差异像素数 d_direct；(b) B_i 与 B_0 水平翻转版的差异像素数 d_hflip；(c) B_i 与 B_0 垂直翻转版的差异像素数 d_vflip。选差异像素数最小的变体作为 B_i 的镜像类型
3. 按确定的镜像类型对 B_i 做逆变换（直接 -> 不变，水平翻转 -> 再水平翻转，垂直翻转 -> 再垂直翻转），得到归一化块 N_i
4. 将每个 N_i 与 B_0 逐格异或比较：颜色不同的位置为分歧像素
5. 输出一个 12x4 的网格（与单块同尺寸）：所有分歧像素位置涂绿(3)，其余涂黑(0)。若多块有分歧，将所有块的分歧位置取并集

**关键洞察**：不做镜像归一化直接异或，合法镜像块会产生大量假差异——求解者必须先理解"直接/水平翻转/垂直翻转"的镜像重复规律并将每块归一化，才能通过异或准确定位真正的损坏像素。

## 新题 7：锚点边缘编码个体重力方向

**组合逻辑**：[gravity_drop](已有，创新为每个对象有独立的重力方向) + [color_match_anchor + edge_position_determines_axis](已有，创新为边缘位置不再决定滑动轴而是决定重力矢量方向) + [erase](已有)（创新核心：源题中边缘位置决定水平/垂直滑动轴，此处边缘位置决定重力矢量方向——同一网格中不同精灵体因颜色锚点位于不同边缘而沿不同方向"坠落"，形成多方向碰撞动力学）

**来源原语**：gravity_drop, slide, stop_at_bottom (6ca952ad); color_match_anchor, border_anchor, edge_position_determines_axis (581f7754); marker_pixel, multicolor_sprite (581f7754); erase (f21745ec)

**依赖链**：每个精灵体有唯一颜色 -> 同色锚点在网格某条边缘上 -> 锚点所在边缘决定该精灵体的重力方向 -> 精灵体沿各自方向滑动直到撞边或碰撞 -> 距目标边更近的精灵体先处理 -> 先到位的精灵体成为障碍阻挡后续精灵体。

每个精灵体根据其颜色匹配锚点所在的网格边缘获得独立的重力方向，然后沿该方向滑动到边界或碰撞停止。

**输入结构**：
- 网格约 13x13，背景黑(0)
- 3~4 个小型单色精灵体（4-连通，4~7 像素，每个使用不同颜色：如蓝(1)、红(2)、绿(3)、黄(4)），位于网格内部（每个精灵体的边界框距网格边界至少 2 格）
- 对每个精灵体，网格边缘上有一个同色的孤立锚点像素（其 4-邻域全为黑(0)或网格外）。锚点不在角落格（不同时处于两条边上）
- 不同精灵体的锚点分布在不同的边缘上（如蓝的在顶边、红的在底边、绿的在左边、黄的在右边），至少有两个精灵体的重力方向不平行
- 生成约束：所有精灵体沿各自方向滑动后的最终位置互不重叠

**规则**：
1. 通过颜色将每个精灵体与其同色边缘锚点配对
2. 根据锚点所在边缘确定该精灵体的重力方向：
   - 锚点在顶边（第 0 行）：重力向上（行号减小方向）
   - 锚点在底边（最后一行）：重力向下（行号增大方向）
   - 锚点在左边（第 0 列）：重力向左（列号减小方向）
   - 锚点在右边（最后一列）：重力向右（列号增大方向）
3. 计算每个精灵体沿其重力方向到目标边界的距离（边界框在该方向最前沿的像素到目标边的格数）。按此距离从小到大排序（距目标边近的先处理）。距离相同时按边界框左上角行号从小到大、再按列号从小到大排序
4. 按上述顺序依次处理每个精灵体：沿重力方向逐格平移整个精灵体，直到精灵体的任一像素下一步会超出网格边界或与已定位精灵体的像素重叠时停止
5. 锚点像素在输出中被擦除（恢复为黑(0)）
6. 精灵体在最终位置以自身颜色绘制，原位置恢复为黑(0)

**关键洞察**：同一网格中不同精灵体可能沿完全不同的方向移动——一个向上一个向右——运动路径可能交叉，处理顺序决定了谁先占位、谁被挡住。仅从单个示例无法确定处理顺序规则（按距离排序），需多个示例对比归纳。

## 新题 8：模板印章叠加面积优先覆盖

**组合逻辑**：[template_matching + stamp_overlay](已有) + [sorting by area_ordering](已有，创新为面积决定绘制优先级)（创新核心：源题中模板印章不涉及重叠冲突解决，源题中面积排序仅输出颜色列——此处面积排序不输出列表而是决定绘制层序，两个独立机制在重叠区域产生不可拆分的耦合）

**来源原语**：template_matching, stamp_overlay, catalog_template, workspace_sprite, sub_sprite_align, partial_match_id (3ed85e70); sorting, area_ordering, descending_pixel_count (f8ff0b80); ignore_distractors (3ed85e70)

**依赖链**：目录区展示完整模板精灵 -> 工作区有模板的局部视图 -> 通过子区域匹配识别每个局部对应哪个模板 -> 对齐并印章完整模板 -> 多个模板的印章范围重叠 -> 按模板前景像素面积从大到小的顺序绘制（小模板后画覆盖大模板）-> 重叠区显示面积更小模板的颜色。

从目录匹配局部精灵对应的完整模板并印章到工作区，重叠区域由模板面积决定覆盖优先级：面积小的绘制在上层。

**输入结构**：
- 网格约 20x20，背景黑(0)
- 左侧 6 列：灰(5)连通的目录背景区域。目录内有 3 个多色模板精灵（每个边界框约 3x3 到 5x5，使用蓝(1)、红(2)、绿(3)、黄(4)中的 2~3 种颜色组成非对称图案），模板精灵彼此不重叠且均与灰(5)背景相邻。三个模板的前景像素面积（非黑(0)非灰(5)像素数）两两不同
- 右侧 14 列：黑(0)工作区。包含 3 个局部精灵，每个是某个目录模板的连续子区域（至少包含模板前景像素的 40%，且包含该模板中唯一可识别的颜色组合或空间特征）
- 局部精灵的放置位置使得：将它们各自补全为完整模板后，至少有两个模板的边界框互相重叠（重叠面积至少 2x2 格）
- 生成约束：每个局部精灵唯一对应一个目录模板（无歧义匹配）；模板内不使用灰(5)色

**规则**：
1. 识别目录模板：灰(5)区域内，将所有非灰(5)非黑(0)的连通前景像素聚类为独立模板。记录每个模板的完整像素图案（相对坐标+颜色）及前景像素面积
2. 对工作区每个局部精灵（非黑(0)的连通前景组），在所有模板中搜索唯一包含该精灵像素图案（相同颜色、相同相对坐标关系）作为子区域的模板
3. 将匹配模板对齐——使已知子区域（局部精灵）与模板中的对应部分重合——确定模板在工作区的完整放置位置
4. 按模板前景像素面积从大到小的顺序依次绘制（面积最大的模板先画，面积最小的后画）。后画的覆盖先画的。模板边界框内黑(0)像素和灰(5)像素视为透明（不绘制，保留下层内容或黑色背景）
5. 输出仅保留右侧工作区（14 列宽），目录区不出现在输出中
6. 工作区中不属于任何模板覆盖范围的格保持黑(0)

**关键洞察**：模板匹配仅确定"哪个模板放在哪里"，重叠区域的最终像素还取决于模板面积排序——面积小的模板优先显示（后绘制覆盖先绘制），此覆盖规则无法从匹配逻辑中推出，需从示例中重叠区域的实际颜色归纳得出。
