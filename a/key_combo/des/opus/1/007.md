## 新题 1：射线筑墙围区，边界主色灌注

**组合逻辑**：[射线延伸](将算术线延伸重新定义为"筑墙") → [洪泛填充](识别被墙壁封闭的区域) → [重涂色](创新：边界接触的多色墙壁中，出现频率最高的墙色决定填充色)

**来源原语**：射线延伸/外推(0b17323b)、等距共线(0b17323b)、边界内延续(0b17323b)、洪泛填充(a5313dff)、区域封闭(a5313dff)、墙壁线段(a5313dff)、孤立背景区域填充(a5313dff)、重涂色(多题)

**依赖链**：射线延伸在网格上建立完整的墙壁网络 → 只有墙壁网络全部画完后，才能判断哪些背景区域被完全封闭 → 封闭区域的填充色取决于其边界上各色墙段的出现频率，因此延伸方向和颜色都直接影响最终填充结果。

从等距标记点组外推的射线在网格上交织成墙壁网络，被完全包围的背景区域以其边界上出现最多的墙色进行填充。

**输入结构**：
- 约 15x15 的黑(0)背景网格。
- 网格中散布 2~4 组等距共线标记点，每组恰好 3 个像素，同组同色，不同组颜色互不相同（使用蓝(1)、红(2)、绿(3)、橙(7)等）。每组 3 个标记点在同一条直线上（水平、垂直或 45 度对角线），且相邻标记间的行列步长相同。
- 各组标记线的延长线会在网格内相互交叉，形成若干封闭区域和若干开放区域（可达网格边界的区域）。
- 生成约束：保证至少存在 2 个封闭区域；每个封闭区域的边界至少接触 2 种不同颜色的墙壁线段，且其中一种的像素数严格多于其他任何一种（无平局）。

**规则**：
1. 对每组 3 个等距共线标记点，沿其所在直线方向，从首端标记向外和末端标记向外分别逐格延伸，直到下一步超出网格边界为止。延伸像素涂为该组标记的颜色。原始标记像素保留不变。若延伸路径上遇到已有非背景像素（另一条线的标记或延伸），该像素保持原色不被覆盖，但延伸不终止——跳过已占用像素继续向前延伸。
2. 将所有标记像素和延伸像素视为墙壁。用 4-邻接洪泛填充从网格四条边界出发，标记所有能够不穿越墙壁到达边界的背景像素为"外部"。剩余的背景像素（无法到达边界）构成封闭区域。
3. 对每个 4-连通的封闭区域，检查其所有 4-邻接的墙壁像素，统计各墙壁颜色的像素数量。将该封闭区域的所有像素填充为出现次数最多的墙壁颜色。
4. 外部背景像素、墙壁像素均保持不变。输出网格尺寸与输入相同。

**关键洞察**：延伸的方向和长度决定了墙壁交叉位置，从而决定了哪些区域被封闭以及每个区域与哪些颜色的墙壁接触——填充色不是预定义的，而是从墙壁网络的几何结构中涌现的。

## 新题 2：平移碰撞，标记叠合

**组合逻辑**：[平移/按自身宽度平移](保留原语) → [透明叠加/标记无冲突合并](创新：叠加的触发条件不再是预对齐的对象，而是平移后产生的碰撞区)

**来源原语**：平移(64a7c07e)、按自身宽度平移(64a7c07e)、边界框决定偏移(64a7c07e)、透明叠加(25e02866)、填充矩形(25e02866)、标记像素(25e02866)、共享底色(25e02866)、同尺寸对齐(25e02866)、标记无冲突合并(25e02866)

**依赖链**：每个矩形按自身宽度右移 → 移动后某些矩形在空间上重合 → 重合区域内各矩形的标记像素需要合并 → 合并冲突时按原始位置判定优先级。平移幅度依赖几何（宽度），叠加发生在平移之后的新位置，而冲突解决又回溯到原始布局。

将多个同尺寸填充矩形各自向右平移其边界框宽度的距离，在碰撞区域内将各来源矩形的内部标记像素按坐标合并。

**输入结构**：
- 约 18x20 的黑(0)背景网格。
- 3~5 个填充矩形（4-连通、实心），全部具有相同的尺寸（如 4x3 或 5x4），并共享同一种底色（如蓝(1)）。
- 每个矩形内部有 1~3 个非底色标记像素（红(2)、绿(3)、黄(4)、橙(7)等），各标记在矩形内的相对位置互不相同（不同矩形的标记不占据相同的本地坐标）。
- 矩形沿水平方向排列，相邻矩形之间的水平间距恰好等于矩形自身宽度，从而平移后产生精确重叠。部分矩形之间间距可以不等于宽度（移动后不重叠）。
- 生成约束：至少有一对矩形在平移后完全重叠；不同矩形的标记像素在本地坐标上互不冲突（保证合并无歧义）；平移后所有矩形仍完全在网格内。

**规则**：
1. 找到所有 4-连通的底色（蓝(1)）填充矩形对象。
2. 将每个矩形的所有像素（含标记）向右平移其边界框宽度的列数。原位置全部置为黑(0)背景。
3. 若平移后两个或更多矩形的边界框完全重叠，则将它们合并为一个矩形：底色像素保持底色；各来源矩形的标记像素按本地坐标叠加到输出矩形的对应位置。
4. 若两个标记像素在合并时落到同一本地坐标（生成约束保证本轮不会出现此情况，但规则需完备描述）：保留原始位置更靠左（列号更小）的那个矩形的标记色。
5. 未发生重叠的矩形平移后独立保留。输出网格尺寸与输入相同。

**关键洞察**：平移幅度来自对象自身的几何属性（宽度），碰撞是否发生取决于原始间距与宽度的关系——求解者必须先测量宽度和间距才能判断哪些矩形会重叠以及如何合并标记。

## 新题 3：外推定位，色链选模，印章铺陈

**组合逻辑**：[外推/等距共线](保留原语) → [查表映射](创新：标记色 → 精灵体选择) → [印章覆盖](创新：印章位置由外推结果计算得出，而非预置占位符)

**来源原语**：外推(0b17323b)、等距共线(0b17323b)、边界内延续(0b17323b)、算术线(0b17323b)、印章覆盖(321b1fc6)、精灵体(321b1fc6/1cf80156)、擦除(321b1fc6)、查表映射(9110e3c5)、编码映射(9110e3c5)

**依赖链**：等距标记组定义外推方向和步长 → 外推产生一组网格内坐标 → 标记组的颜色通过编码映射关联到某个精灵体 → 在每个外推坐标处印上该精灵体的副本 → 不同标记组的印章可能交叠，需按组内外推点数量决定优先级。三条信息流（位置来自外推、内容来自色链、冲突来自多组交互）在印章操作处汇合。

从等距标记组外推出放置坐标，按标记颜色选定对应精灵体，在每个外推点印章复制该精灵体。

**输入结构**：
- 约 16x16 的黑(0)背景网格。
- 2 个小型多色精灵体（各由 4~6 个像素组成的 4-连通单色或多色图形），分别位于网格的不同角落区域。每个精灵体内有一种出现次数最多的颜色（主色），两个精灵体的主色互不相同（如精灵体 A 主色红(2)，精灵体 B 主色绿(3)）。
- 2 组等距共线标记点，每组 3 个同色像素。一组颜色为红(2)（与精灵体 A 主色相同），另一组颜色为绿(3)（与精灵体 B 主色相同）。两组标记线方向可以不同（一组水平，一组对角线等）。
- 生成约束：每组的外推点（向末端方向延伸、在网格内的后续等距位置）至少有 1 个、至多 4 个；两组外推产生的印章区域之间如有重叠，重叠区域中两组的像素不在同一格（或者在同一格时由优先级规则处理）；各精灵体的紧凑包围盒足够小，印章不超出网格边界。

**规则**：
1. 对每组 3 个等距共线标记点，按行主序排列，计算相邻标记间的步长向量（行差, 列差）。
2. 从该组最后一个标记（行主序最后）开始，向步长方向逐步外推：每一步的坐标 = 上一步坐标 + 步长。只要外推坐标仍在网格内就继续（判据：以外推点为左上角放置精灵体包围盒后，整个包围盒仍在网格内），否则停止。
3. 根据标记组的颜色选取对应精灵体：颜色与精灵体 A 主色相同 → 选精灵体 A；颜色与精灵体 B 主色相同 → 选精灵体 B。
4. 在每个外推坐标处，以该坐标为精灵体紧凑包围盒的左上角，将精灵体的所有非背景像素印到网格上。
5. 若两组的印章区域有像素重叠，外推点数量较少的那组优先（其印章像素最后绘制，覆盖先前的）。若两组外推点数量相同，则标记组行主序首标记行号较小的优先。
6. 擦除两个原始精灵体和所有原始标记点（置为黑(0)背景）。输出网格尺寸与输入相同。

**关键洞察**：印章"在哪"由外推几何决定，印章"印什么"由颜色匹配决定——两条独立推理线在放置操作处汇合，缺少任何一条都无法确定输出。

## 新题 4：绕行轨迹分段染色

**组合逻辑**：[路径绘制/绕行](保留原语) → [重涂色](创新：路径不再统一着色，每段的颜色由触发该段绕行的障碍物颜色决定)

**来源原语**：路径绘制(96a8c0cd)、绕行(96a8c0cd)、障碍色决定绕行(96a8c0cd)、边界标记(96a8c0cd)、障碍条(96a8c0cd)、路径轨迹(96a8c0cd)、阻挡(96a8c0cd)、重涂色(多题)

**依赖链**：路径从边界标记出发沿直线行进 → 遇到障碍条时按其颜色决定绕行方向（蓝左绿右） → 每次绕行在路径中产生一个新的直线段 → 该段的颜色不是统一的红，而是等于触发本次绕行的障碍条颜色 → 第一段（首次绕行前）的颜色保留为标记色。绕行改变的不仅是路径几何，还改变了后续段的着色规则。

从边界标记出发绘制路径，遇障碍物绕行；路径的每个直线段着色为触发该段偏移的障碍物颜色，首段保留标记原色。

**输入结构**：
- 约 15x15 的灰(5)背景网格。
- 网格某一条边界上有一个红(2)标记像素（入口标记），朝向网格内部的方向是唯一确定的（例如标记在顶边 → 向下行进）。
- 沿行进方向的路径上，依次横亘 2~4 条障碍条，每条为 1 像素厚的连续线段，垂直于路径行进方向。障碍条的颜色为蓝(1)或绿(3)，每条可独立选色。
- 障碍条不与网格边界齐平（两端至少各留 1 格空隙），使路径可以从两侧绕行。
- 生成约束：所有障碍条之间至少间隔 2 行/列；路径绕行后不会离开网格；至少存在一条蓝障碍和一条绿障碍。

**规则**：
1. 路径从红(2)标记出发，沿垂直于入口边界的方向（如标记在顶边则向下）直线行进。
2. 当路径即将进入障碍条占据的格子时，根据障碍条颜色在行进方向的参考系下绕行：
   - 蓝(1)障碍 → 路径向行进方向左侧偏移 1 列，绕过障碍条端部后再偏回原方向继续前进。
   - 绿(3)障碍 → 路径向行进方向右侧偏移 1 列。
   - 绕行细节：路径先横移 1 格到障碍条端部外侧，再纵向前进越过障碍所在行/列，再横移 1 格回到原来的纵向车道上。
3. 路径被分割为若干"直线段"（每段是连续的纵向像素序列，两次绕行之间的部分）。各段着色规则：
   - 第一段（从入口标记到第一次绕行前）：着红(2)色。
   - 从第 N 条障碍绕行后到第 N+1 条障碍绕行前的段：着第 N 条障碍的颜色。
   - 绕行过程中的横移和纵移像素也属于触发该绕行的障碍段，着该障碍色。
4. 路径前进直到到达对面边界或网格内再无障碍（最后一段延伸至对面边界）。
5. 障碍条像素保留原色不变。只有背景像素被路径覆盖。输出网格尺寸与输入相同。

**关键洞察**：路径并非单色——每段路径的颜色是前一个绕行障碍的"回声"，求解者必须逐段追踪绕行历史才能确定各段着色，而非仅仅画出路径形状。

## 新题 5：唯体筛色，注入交叉

**组合逻辑**：[连通检测 → 筛选/唯一连通分量 → 最大面积选择](保留原语链) → [射线延伸/交叉/交叉点标记新色](创新：交叉点的标记色不再是固定的黄色，而是由筛选结果动态注入)

**来源原语**：连通检测(3194b014)、筛选(3194b014)、唯一连通分量(3194b014)、最大面积选择(3194b014)、忽略干扰项(3194b014)、单色连通体(3194b014)、射线延伸(bdad9b1f)、横条段(bdad9b1f)、竖条段(bdad9b1f)、交叉(bdad9b1f)、交叉点标记新色(bdad9b1f)、重涂色(多题)

**依赖链**：连通检测分析所有前景色 → 筛选出恰好形成 1 个连通体的颜色 → 从中选面积最大的 → 该颜色被注入到十字交叉点 → 同时该连通体自身被重涂为横条段的颜色。筛选结果同时影响两个下游操作（交叉着色和连通体重涂），形成分叉依赖。

筛选出具有唯一连通分量且面积最大的前景色，将该色注入到横竖条段延伸后的交叉格，并将该连通体本身重涂为横条段的颜色。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 1 条水平条段（1 像素厚的连续水平线段，长度 3~6 像素，颜色如橙(7)）和 1 条垂直条段（1 像素厚的连续垂直线段，长度 3~6 像素，颜色如品红(6)），两者所在行与列的交叉位置当前是背景色。
- 3~5 个散布的单色前景对象（4-连通），颜色各不相同（使用红(2)、蓝(1)、绿(3)、黄(4)等）。其中一部分颜色的像素被分裂成多个不相连的碎片（干扰项），另一部分颜色的像素恰好形成 1 个 4-连通体。
- 生成约束：在恰好形成 1 个连通体的颜色中，面积最大者唯一（无平局）；该颜色与横条段和竖条段的颜色均不同；横条段和竖条段颜色也互不相同。

**规则**：
1. 对每种非背景、非条段的前景色，统计其 4-连通单色连通分量个数。
2. 保留恰好只有 1 个连通分量的颜色，忽略其余（干扰项）。
3. 在保留的颜色中，选出像素面积最大的那个颜色，记为 C。
4. 将横条段沿其所在行延伸至网格全宽（涂横条段的颜色），将竖条段沿其所在列延伸至网格全高（涂竖条段的颜色）。
5. 横条段所在行与竖条段所在列的交叉格涂为颜色 C。
6. 将颜色 C 的那个连通体的所有像素重涂为横条段的颜色。
7. 其余前景对象（含干扰项）保持不变。输出网格尺寸与输入相同。

**关键洞察**：交叉点的颜色不是预设常量，而是由一个独立的筛选推理链动态产出的——求解者必须先完成连通体分析才能知道交叉点该涂什么色。

## 新题 6：角点分类驱动印章旋转

**组合逻辑**：[分类/角点占用映射](保留原语) → [旋转](创新：旋转角度由分类结果参数化) → [印章覆盖](创新：印章位置由独立标记指定，而非占位符掩码)

**来源原语**：分类(27a28665)、角点占用映射标签(27a28665)、掩码图案(27a28665)、角点(27a28665)、旋转(21897d95)、印章覆盖(321b1fc6)、精灵体(321b1fc6/1cf80156)、擦除(321b1fc6)、标记像素(25e02866)

**依赖链**：3x3 分类器图案的角点占用数量 → 映射为旋转角度 → 每个放置标记关联最近的分类器 → 在标记位置印上按对应角度旋转后的精灵体副本。三种独立元素（分类器、标记、精灵体）在印章操作处汇合，缺少任何一种都无法确定输出。

按 3x3 图案的角点占用数量确定旋转角度，在标记位置印上旋转后的精灵体副本。

**输入结构**：
- 约 18x18 的黑(0)背景网格。
- 1 个多色精灵体（4-连通，4~8 像素，非对称形状以使旋转可区分），位于网格某一角落区域。精灵体使用红(2)和蓝(1)等颜色，不使用灰(5)和黄(4)。
- 2~4 个 3x3 的灰(5)分类器图案散布在网格中，每个图案内恰好有 5 个灰(5)像素和 4 个黑(0)像素。各分类器的角点占用数量可能不同（0、1、2 或 4 个角被灰色占据）。分类器之间至少间隔 3 格。
- 与分类器数量相同的黄(4)放置标记，每个标记是单个像素，散布在网格中。
- 生成约束：每个放置标记与恰好一个分类器的曼哈顿距离最近（无平局）；以放置标记为左上角印章后，精灵体包围盒不超出网格边界；不同印章之间不重叠；分类器图案中不出现 3 个角被占据的情况。

**规则**：
1. 将精灵体裁剪到其紧凑包围盒。
2. 对每个 3x3 灰(5)分类器，统计 4 个角点中有多少个是灰(5)：
   - 0 个角 → 旋转 0 度（原始朝向）
   - 1 个角 → 顺时针旋转 90 度
   - 2 个角 → 旋转 180 度
   - 4 个角 → 顺时针旋转 270 度（等价于逆时针 90 度）
3. 每个黄(4)放置标记关联到曼哈顿距离最近的分类器（标记中心到分类器 3x3 区域中心的曼哈顿距离）。
4. 在每个放置标记位置，以该标记像素为左上角，印上按关联分类器对应角度旋转后的精灵体副本。精灵体的非背景像素覆盖网格上的原有内容。
5. 擦除原始精灵体、所有分类器图案和所有放置标记（置为黑(0)）。印章像素不被擦除。输出网格尺寸与输入相同。

**关键洞察**：分类器看似只是一个抽象标签，但它参数化了空间变换的角度——求解者需要发现"角点数→旋转度"的编码映射，并将其应用到与分类器空间上分离的印章操作中。

## 新题 7：围区计数定放大倍率

**组合逻辑**：[洪泛填充/区域封闭](识别封闭区域) → [计数](统计封闭区域数量) → [裁剪/紧凑包围盒提取](提取精灵体) → [像素放大](创新：放大倍率不是固定常量，而是由封闭区域数量动态决定)

**来源原语**：洪泛填充(a5313dff)、区域封闭(a5313dff)、墙壁线段(a5313dff)、孤立背景区域填充(a5313dff)、画布边界(a5313dff)、计数(9110e3c5/27a28665/d5c634a2)、裁剪(1cf80156)、紧凑包围盒提取(1cf80156)、精灵体(1cf80156)、像素放大(33067df9)

**依赖链**：红色墙壁划分出封闭区域 → 封闭区域的数量 N 成为放大倍率 → 精灵体被裁剪提取 → 精灵体的每个像素被放大为 NxN 块。N 来自空间分析而非直接给定，裁剪和放大的对象（精灵体）与墙壁结构完全独立，两条推理线在像素放大处汇合。

统计红色墙壁围成的封闭区域数量 N，将网格中的小型精灵体裁剪并按 N 倍像素放大输出。

**输入结构**：
- 约 20x20 的黑(0)背景网格。
- 若干红(2)像素组成 1 像素厚的墙壁线段（直线段或折线段），在网格中形成封闭和非封闭区域。墙壁线段可以接触网格边界（与边界共同形成封闭区域）。
- 1 个与红色无关的小型多色精灵体（3x3 或 4x4 包围盒内，使用蓝(1)、绿(3)、黄(4)等颜色），位于网格中不被任何墙壁包围的开放区域内。
- 生成约束：封闭区域数量 N 在 2~4 之间；精灵体放大 N 倍后的尺寸不超过 16x16；精灵体不与任何墙壁像素相邻。

**规则**：
1. 将红(2)像素视为墙壁。用 4-邻接洪泛填充从网格四边出发，标记所有能不穿越墙壁到达边界的黑(0)像素为外部。剩余的黑(0)像素为封闭区域。
2. 统计 4-连通的封闭区域数量，记为 N。
3. 找到网格中唯一的非红、非黑前景对象（精灵体），裁剪到其紧凑包围盒。
4. 对裁剪后的精灵体进行 N 倍像素放大：每个像素扩展为 NxN 的同色方块。背景像素（黑(0)）同样放大。
5. 输出仅为放大后的精灵体（尺寸 = 原始包围盒宽 x N 行、原始包围盒高 x N 列）。墙壁和外部区域不出现在输出中。

**关键洞察**：放大倍率不是直接可读的数字，而是隐藏在墙壁拓扑中——求解者必须完成一次完整的封闭区域检测才能得到这个关键参数。

## 新题 8：图例解密揭示隐藏条段，延伸成十字

**组合逻辑**：[重涂色/图例色替换](保留原语) → [射线延伸/交叉](创新：需要延伸的条段不是直接可见的，而是在图例重涂色之后才显现为同色连续段)

**来源原语**：重涂色(e9b4f6fc)、颜色替换映射(e9b4f6fc)、微型图例(e9b4f6fc)、图例色替换(e9b4f6fc)、多色目标对象(e9b4f6fc)、裁剪(e9b4f6fc)、射线延伸(bdad9b1f)、横条段(bdad9b1f)、竖条段(bdad9b1f)、交叉(bdad9b1f)、交叉点标记新色(bdad9b1f)

**依赖链**：图例定义颜色替换映射 → 应用映射后，原本看似杂色的区域中浮现出一条横向同色段和一条纵向同色段 → 识别出这两条段后，分别沿全行和全列延伸 → 标记交叉格为黄(4)。重涂色不只是外观变化——它改变了结构识别的条件，使隐藏的条段变为可检测。

通过图例定义的颜色替换，将中央图案中被伪装的条段统一为同色；随后延伸这两条段并标记交叉点。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 网格中央有一个矩形的多色图案区域（约 6x6 至 8x8），使用 3~5 种非黑前景色。图案内部隐藏着一条水平的 1 像素厚线段和一条垂直的 1 像素厚线段，但它们被不同颜色伪装（例如横段中一部分像素是红(2)、一部分是橙(7)，看起来不连续）。
- 在图案区域之外的网格边缘，有 1~2 个水平排列的 2 像素图例色块（domino），每个色块左像素为替换色、右像素为被替换色。图例定义的替换关系恰好能将隐藏条段中被伪装的像素统一为同一种颜色（例如图例：绿(3)|红(2) 表示红→绿，使得原来"绿+红混合"的横段全部变绿）。
- 图例所定义的被替换色（右像素色）出现在图案中但不出现在隐藏条段之外的位置（即替换只影响条段像素）。
- 生成约束：应用所有图例替换后，图案区域内恰好存在一条水平和一条垂直的 1 像素厚同色连续段（长度至少 3 像素），且它们的行列交叉格当前是其他颜色（非段色）；段色与黄(4)不同。

**规则**：
1. 读取所有图例色块：每个 domino 的左像素为替换色 R，右像素为源色 S。
2. 在中央图案区域内，将所有颜色为 S 的像素替换为 R。若有多个图例，依次应用（各图例的源色互不相同，顺序无影响）。
3. 替换后，在图案区域内寻找恰好一条水平 1 像素厚同色连续段（同一行中连续 3+ 个相同非背景色像素且上下邻格非该色）和恰好一条垂直 1 像素厚同色连续段（同一列中连续 3+ 个相同非背景色像素且左右邻格非该色）。
4. 将水平段沿其所在行延伸至网格全宽（涂水平段的颜色），将垂直段沿其所在列延伸至网格全高（涂垂直段的颜色）。延伸覆盖背景像素和图例像素，但不覆盖图案区域内的非段非背景像素。
5. 水平段所在行与垂直段所在列的交叉格涂为黄(4)。
6. 输出网格尺寸与输入相同。

**关键洞察**：条段在重涂色之前是"隐身"的——求解者必须先理解图例的替换规则并在脑中完成替换，才能"看到"需要延伸的结构。颜色替换在这里不是最终目的，而是解锁下一步结构识别的钥匙。

## 新题 9：反对称补全——交换对旋转轨道的色彩翻转

**组合逻辑**：[对称补全/对称轨道](创新：对称不再是色彩相等，而是沿旋转轨道的色彩交换) + [重涂色/双色互换](创新：交换对不再全局应用，而是定义轨道上的"翻转关系")

**来源原语**：对称补全(3631a71a/af22c60d)、对称轨道(3631a71a)、同轨道色填补损坏(3631a71a)、轨道内已知色唯一(af22c60d)、掩码像素(3631a71a/af22c60d)、重涂色(d511f180)、双色互换(d511f180)、仅交换两色(d511f180)、图例(0becf7df)、图例行内配对(0becf7df)

**依赖链**：图例定义交换对（A↔B） → 该交换对改写了对称轨道的匹配规则：轨道伙伴不再是"同色"，而是"互为交换色"或"同色"（取决于是否属于交换对） → 对每个掩码像素，通过其 180 度旋转轨道伙伴的颜色和交换规则联合推出应填的颜色。图例和对称轴两条信息缺一不可。

图案满足"反对称"——沿 180 度旋转，交换对中的颜色互换而非相等。用图例定义的交换对和反对称约束联合确定掩码像素的颜色。

**输入结构**：
- 约 10x10 的正方形网格（奇数边长，如 9x9 或 11x11），无固定背景色。
- 网格左上角有一个 2x1 的图例块（水平排列的两个像素），定义一对交换色（如左像素红(2)、右像素蓝(1)，表示红↔蓝是交换对）。
- 网格其余位置由红(2)、蓝(1)、绿(3)、黄(4)四种颜色构成一个图案，另外有若干灰(5)像素标记掩码（损坏位置）。
- 隐藏结构：该图案满足关于网格中心点的 180 度旋转"反对称"——对于每个非掩码像素 (r,c) 及其旋转伙伴 (H-1-r, W-1-c)：若像素颜色属于交换对，则伙伴的颜色是其交换色（红的伙伴是蓝，蓝的伙伴是红）；若像素颜色不属于交换对，则伙伴颜色与自身相同（绿的伙伴是绿，黄的伙伴是黄）。
- 生成约束：每个 180 度旋转轨道中至少有一个非掩码像素；图例块本身的位置 (0,0) 和 (0,1) 的旋转伙伴不是掩码（或者图例在输出前被移除）；掩码像素数量占总像素的 10%~25%。

**规则**：
1. 读取图例块 (0,0)|(0,1) 为交换对：左色 = A，右色 = B，A↔B 互为交换色。
2. 对每个灰(5)掩码像素 (r,c)，找到其 180 度旋转伙伴 (H-1-r, W-1-c)。
3. 若伙伴是非掩码像素，颜色为 X：
   - 若 X = A → 掩码填 B
   - 若 X = B → 掩码填 A
   - 若 X 不属于交换对 → 掩码填 X
4. 若伙伴也是掩码像素：由于网格边长为奇数，中心点 ((H-1)/2, (W-1)/2) 是自身的旋转伙伴。此格若为掩码，其颜色必须是非交换对色（因为交换对色的自伙伴要求 X = swap(X)，仅当 A=B 时成立，而交换对双色不同）。通过上下文（相邻已确定像素的模式）推断，但生成约束保证此情况最多出现 1 次且有唯一解。
5. 移除图例块：将 (0,0) 和 (0,1) 填为其旋转伙伴的反对称对应色（按规则 3 的逻辑推出）。
6. 输出完整的无掩码网格，尺寸不变。

**关键洞察**：如果不知道交换对，求解者会尝试普通旋转对称补全，但会发现某些轨道伙伴颜色"矛盾"（红对蓝）——只有引入图例定义的"交换对称"概念，矛盾才能统一消解。这是一种非标准对称：旋转不保持颜色相等，而是保持颜色在交换对中的互换关系。
