## 新题 1：奇偶棋盘过滤的射线投射

**组合逻辑**：[射线延伸](创新：不再从实心方块而是从单个标记像素出发) + [坐标奇偶匹配](创新：不再全局填充奇偶格点，而是仅对射线路径上的格点做奇偶过滤) + [交叉点重置背景](保留：不同来源射线交叉处归零)

**来源原语**：射线延伸/ray_extend(P5-e9bb6954), 坐标奇偶匹配/coord_parity_match(P4-d492a647), 标记像素/marker_pixel(P4-d492a647), 交叉点重置背景/intersect_reset_bg(P5-e9bb6954)

**依赖链**：标记像素的位置同时决定射线起点和奇偶过滤类别；射线路径限定了过滤区域（非全局）；过滤后的像素集合才进入交叉检测环节——三者环环相扣，缺一不可。

从每个彩色标记像素发射四方向射线，但射线仅在与标记同棋盘奇偶的格点上着色；不同标记的射线在同一格点冲突时该格点重置为背景。

**输入结构**：约 15x15 的网格，黑(0)背景。散布若干灰(5)障碍像素（不构成连通形状，仅作为射线终止屏障，每个示例 8-15 个灰像素随机分布）。网格中有 2-4 个彩色标记像素，每个标记是一个独立的单像素，颜色互不相同且非黑(0)非灰(5)——例如红(2)、蓝(1)、绿(3)、橙(7)等。标记之间互不相邻（曼哈顿距离 >= 3）。生成约束：至少存在一对标记的射线在过滤后发生交叉（即存在某个背景格点同时位于两个标记的射线路径上，且该格点的棋盘奇偶同时匹配两个标记）。

**规则**：
1. 每个标记像素位于 (r, c)，其棋盘奇偶类别定义为 P = (r + c) % 2。
2. 从标记像素出发，沿上、下、左、右四个方向逐格延伸射线。射线在遇到灰(5)像素或网格边界时停止（停止格不包含在射线内）。标记像素本身不属于射线。
3. 对射线路径上的每个格点 (r', c')：若 (r' + c') % 2 == P 且该格点当前为背景(0)，则标记该格点为"待涂色"并记录来源标记的颜色。若该格点的棋盘奇偶与 P 不匹配，则跳过。
4. 所有标记的射线处理完毕后，检查冲突：若某个格点被两个或更多不同标记标记为"待涂色"，则该格点保持背景(0)。
5. 无冲突的"待涂色"格点涂上其唯一来源标记的颜色。
6. 标记像素本身保持原色不变。灰(5)像素保持不变。其余背景像素保持不变。

**关键洞察**：射线不是连续着色所有经过的背景格点，而是隔一个涂一个（棋盘过滤），且这个过滤的相位由标记像素自身的位置奇偶决定。仅看单个示例可能误以为是随机跳跃着色，需对比不同位置的标记才能归纳出棋盘奇偶规则。

## 新题 2：轮廓围合区域的图例排名填色

**组合逻辑**：[洪泛填充/轮廓围合](保留：识别轮廓围合的背景区域) → [计数](创新：不再计数前景像素，而是计算围合区域的面积) → [长度排名 + 高度即排名索引](创新：排名对象从竖条变为围合区域，图例的高度不再索引竖条排名而是索引区域面积排名)

**来源原语**：洪泛填充/flood_fill(P17-753ea09b), 轮廓围合/contour_enclosure(P17-753ea09b), 封闭背景区域/enclosed_bg_region(P17-753ea09b), 计数/counting(P7-ff28f65a), 颜色图例/color_legend(P1-97d7923e), 长度排名/length_ranking(P1-97d7923e), 高度即排名索引/legend_height_as_rank_index(P1-97d7923e)

**依赖链**：轮廓围合产出区域集合 → 面积计数产出排名 → 图例高度索引排名选择区域 → 区域被涂上图例颜色。删除围合检测则无区域可排名；删除计数则无法排序；删除图例则不知道哪个排名对应哪个颜色。

识别轮廓线围合的背景区域，按面积排名，再用图例中色块的高度作为排名索引对区域填色。

**输入结构**：约 18x18 的网格，黑(0)背景。灰(5)像素构成若干 8-连通的线段或折线，这些线段围合出 3-5 个大小不等的封闭背景区域（每个区域 4-连通，面积在 3-20 像素之间，互不相同）。灰线段不构成完美矩形——它们是不规则的折线或多边形边界。网格最上方 2-3 行为图例区域，与主绘图区之间至少间隔一行全背景行。图例区域包含 2-4 个紧贴第 0 行的彩色竖条，每个竖条宽 1 像素，高度各不相同（1 到封闭区域总数之间），颜色互不相同且非黑(0)非灰(5)。图例竖条之间至少间隔 1 列。生成约束：封闭区域的面积互不相等；图例竖条的高度值覆盖 1 到竖条数量的连续整数。

**规则**：
1. 识别所有灰(5)像素。以灰像素和网格边界为屏障，找出所有 4-连通的背景(0)区域。
2. 丢弃接触网格边界的背景区域（它们是轮廓的"外部"）以及图例区域所在行的背景区域。保留完全被灰像素包围的内部背景区域。
3. 计算每个内部区域的面积（像素数）。按面积从大到小排名：面积最大的区域排名 1，次大排名 2，依此类推。
4. 读取图例：每个彩色竖条的颜色为 K、高度为 h。高度 h 表示排名索引。
5. 对于每个图例条目 (K, h)，将排名为 h 的内部区域的所有像素涂为颜色 K。
6. 没有对应图例条目的内部区域保持背景(0)不变。灰(5)像素和图例像素在输出中保持不变。

**关键洞察**：图例竖条的高度不是目标区域的面积值，而是面积排名的序号。高度为 2 的竖条指向面积排名第二的区域，无论该区域有多大。需对比多个示例（图例高度相同但目标区域面积不同）才能确认这一索引关系。

## 新题 3：面板差异生成对称损伤图

**组合逻辑**：[逐像素比较](保留：左右面板对齐比较) → [差异分类着色](创新：差异位不再标红/蓝，而是统一标为绿色占位符) → [对称补全](创新：不再以给定的绿色为起点，而是由比较步骤产生绿色，再做双轴对称修复)

**来源原语**：逐像素比较/pixel_comparison(P10-d47aa2ff), 面板/panel(P10-d47aa2ff), 面板对齐/panel_align(P10-d47aa2ff), 分隔列/separator_col(P10-d47aa2ff), 对称补全/symmetry_completion(P13-903d1b4a), 双轴反射轨道/two_axis_orbit(P13-903d1b4a), 占位标记/placeholder_marker(P13-903d1b4a), 轨道内唯一可见色/unique_color_in_orbit(P13-903d1b4a)

**依赖链**：面板比较确定哪些格点"可信"、哪些是"损伤"→ 损伤格点被标记为绿色占位符 → 双轴对称约束从可信格点恢复损伤格点的颜色。跳过比较则不知道哪些格点损伤；跳过对称补全则损伤格点无法恢复。两步产生的信息类型完全不同（比较产出"可信/损伤"二分类，对称产出"具体颜色"），不可互替。

比较两个面板的像素，将一致处保留、差异处标为损伤占位符，再利用底层图案的双轴对称性修复所有损伤格点。

**输入结构**：网格列数为奇数（约 11-17 列），行数约 7-11。正中间有一列宽度为 1 的橙(7)分隔列，将网格分为宽度相等的左面板和右面板。两个面板的背景色均为黑(0)。底层设计是一个具有左右对称和上下对称性的彩色图案（使用 2-3 种非黑非橙非绿的颜色，如红(2)、蓝(1)、黄(4)等）。左面板展示该图案的一个"带噪声"版本：其中 2-4 个像素被随机替换为错误颜色或背景。右面板展示同一图案的另一个"带噪声"版本：在不同的 2-4 个位置有错误。两个面板不在同一位置同时出错——即对于每个设计位置，至少一个面板给出正确颜色。生成约束：底层图案严格满足水平和垂直两轴反射对称；每个对称轨道中至少有一个位置在两个面板中都正确。

**规则**：
1. 移除橙(7)分隔列。将左面板和右面板逐像素对齐比较。
2. 若两面板在位置 (r, c) 处颜色相同且为非背景色：输出该颜色（可信前景）。
3. 若两面板在位置 (r, c) 处均为背景(0)：输出背景(0)。
4. 若两面板在位置 (r, c) 处颜色不同（包括一方为背景另一方为前景，或两方为不同前景色）：输出绿(3)作为损伤占位符。
5. 现在得到一个单面板尺寸的中间网格，包含可信像素和绿(3)占位符。该中间网格在忽略绿色后具有双轴反射对称性。
6. 对每个绿(3)格点，找到它在水平反射和垂直反射下的轨道（最多 4 个位置）。轨道中恰好有一个非绿颜色出现在可信位置上。将该绿格点替换为该颜色。
7. 输出为修复后的单面板图案（无分隔列、无绿色）。

**关键洞察**：面板比较不是最终答案——它产生一个"损伤中间态"，必须再由对称约束修复。两个面板是同一对称设计的两个"有噪观察"；一致处提供可靠数据，不一致处标记损伤，而底层对称性恢复其余部分。单个示例可能让人以为只需取两面板的"或"，但当两面板在同一位置都给出前景（只是颜色不同）时，简单取并集会出错，必须走对称修复路径。

## 新题 4：模板匹配分类驱动的半区条件重涂色

**组合逻辑**：[模板匹配 + 旋转](创新：匹配结果不再用于印章覆盖，而是作为二元分类器) → [半区变色](创新：不再对所有对象统一涂下半区，而是根据分类结果决定涂上半区还是下半区以及涂什么颜色)

**来源原语**：模板匹配/template_match(P3-6aa20dc0), 旋转/rotate(P3-6aa20dc0), 前景对象/fg_object(P11-e7dd8335), 包围盒/bounding_box(P11-e7dd8335), 半区/half_region(P11-e7dd8335), 半区变色/half_recolored(P11-e7dd8335), 重涂色/recolor(P11-e7dd8335)

**依赖链**：模板的形状掩码（忽略颜色）用于分类每个目标对象 → 分类结果（匹配/不匹配）决定重涂色策略（涂哪半区、涂什么颜色）。删除模板匹配则无法区分对象类别；删除半区重涂色则分类结果无处体现。模板提供分类标准，分类结果驱动空间操作——两者间的依赖不是数据传递而是决策传递。

用模板形状（支持旋转）对散落的前景对象做二元分类：匹配的对象涂下半区为红色，不匹配的涂上半区为蓝色。

**输入结构**：约 15x18 的网格，黑(0)背景。左上角（紧贴第 0 行和第 0 列）有一个小型多色模板对象，占据约 3x3 到 4x4 的包围盒，使用 2-3 种颜色，形状不规则（非矩形，4-连通，3-6 像素）。网格其余位置散布 4-6 个单色前景对象，每个对象是 4-连通的单色形状（3-8 像素），颜色非黑(0)。不同对象的颜色可以相同也可以不同。其中约一半对象的形状（忽略颜色，仅看像素相对位置）与模板在某个旋转（0/90/180/270度）下完全匹配；另一半对象的形状在任何旋转下都不匹配模板。所有对象的包围盒互不重叠，且与模板不重叠。每个对象的包围盒高度至少为 2（确保上下半区各至少占 1 行）。生成约束：匹配与不匹配的对象各至少 2 个。

**规则**：
1. 提取模板的形状掩码：以模板包围盒左上角为原点，记录所有非背景像素的相对 (dr, dc) 坐标集合。忽略模板的颜色信息。
2. 生成模板掩码的 4 个旋转变体（0度、90度顺时针、180度、270度顺时针），每个变体归一化为以 (0,0) 为最小坐标。
3. 对每个非模板的前景对象，提取其形状掩码（同样以包围盒左上角为原点的相对坐标集合）。
4. 将对象的形状掩码与模板的 4 个旋转变体逐一比较。若存在完全匹配的旋转：该对象分类为"匹配"。否则分类为"不匹配"。
5. 对"匹配"类对象：保留包围盒上半区像素的原色不变；将下半区（行索引 >= ceil(bbox_height / 2) 的行，行索引从 0 开始计）所有前景像素重涂为红(2)。
6. 对"不匹配"类对象：将上半区（行索引 < ceil(bbox_height / 2) 的行）所有前景像素重涂为蓝(1)；保留下半区像素的原色不变。
7. 模板对象本身在输出中被擦除（替换为背景(0)）。

**关键洞察**：模板匹配不是为了拼合或覆盖，而是充当一个隐式的"是/否"分类器，其分类结果通过空间位置（上半区/下半区）和颜色（蓝/红）双重编码到输出中。仅看单个示例很难判断为什么有的对象涂上半区蓝色、有的涂下半区红色——必须提取模板形状并测试旋转匹配后才能归纳出分类规则。

## 新题 5：递减光晕的循环色带

**组合逻辑**：[递减填充/逐步缩短行程](保留：从圆润对象的边缘行程逐层外扩，每层缩短) + [循环填充/色彩循环](创新：不再在固定间距位置循环填色，而是在每个递减层使用不同的循环色) → 冲突解决依赖层深优先级

**来源原语**：递减填充/shrinking_fill(P8-9772c176), 边缘行程/side_run(P8-9772c176), 圆润对象/rounded_object(P8-9772c176), 四方外扩/four_way_expansion(P8-9772c176), 逐步缩短行程/progressively_shortened(P8-9772c176), 循环填充/cycle_fill(P16-72207abc), 色彩循环/color_cycle(P16-72207abc)

**依赖链**：圆润对象的边缘行程决定外扩的初始宽度和方向 → 递减规则决定每层的几何形状 → 色彩循环为每层分配颜色。删除递减几何则不知道每层涂哪些格点；删除色彩循环则所有层同色（退化为 P8 原题）；删除边缘行程则无法启动外扩。三者交织产生彩虹渐缩光晕效果，这在任何单一参考题中都不存在。

从圆润对象的四个边缘行程向外逐层扩展，每层宽度递减 2，每层颜色按指示行的色彩循环依次变换，形成彩虹渐缩光晕。

**输入结构**：约 20x20 的网格，黑(0)背景。包含 1-2 个青(8)圆润对象——每个对象是一个凸的 4-连通形状，边缘光滑（无单像素突出），上下左右各有一段连续的水平或垂直边缘行程，每段行程至少 3 像素长。两个对象互不相邻（包围盒间距 >= 6）。网格最底一行为颜色指示行：包含 2-4 个相邻的彩色像素（非黑(0)、非青(8)），从左到右读取构成一个色彩循环序列，例如 [红(2), 黄(4), 蓝(1)]。指示行的其余像素为背景(0)。生成约束：对象足够居中，使得至少 2 层外扩不超出网格边界（不含指示行所在行）。

**规则**：
1. 识别所有青(8)圆润对象和底部颜色指示行。读取指示行中从左到右的非背景像素颜色序列作为色彩循环 C = [C_1, C_2, ..., C_m]。
2. 对每个圆润对象，识别其四个边缘行程：
   - 上行程：对象最顶一行中所有属于对象的连续水平像素段。
   - 下行程：对象最底一行中所有属于对象的连续水平像素段。
   - 左行程：对象最左一列中所有属于对象的连续垂直像素段。
   - 右行程：对象最右一列中所有属于对象的连续垂直像素段。
3. 从每个行程向外逐层扩展，层编号从 1 开始：
   - 上行程的第 k 层：在对象顶边上方第 k 行，水平居中，长度 = 上行程长度 - 2k。若长度 < 1 则停止。
   - 下行程的第 k 层：在对象底边下方第 k 行，水平居中，长度 = 下行程长度 - 2k。
   - 左行程的第 k 层：在对象左边左方第 k 列，垂直居中，长度 = 左行程长度 - 2k。
   - 右行程的第 k 层：在对象右边右方第 k 列，垂直居中，长度 = 右行程长度 - 2k。
4. 第 k 层的颜色为 C[((k-1) mod m) + 1]，即按色彩循环依次着色。
5. 仅涂背景(0)格点。若某格点超出网格边界（或位于指示行所在行），跳过。
6. 冲突解决：若来自同一对象不同方向的扩展层重叠在同一格点，层编号（k）较小者优先；层编号相同时，水平方向（上/下行程）优先于垂直方向（左/右行程）。若来自不同对象的扩展层重叠，层编号较小者优先；层编号相同时，包围盒左上角更靠左的对象优先（若左上角同列则更靠上者优先）。
7. 青(8)对象本身保持不变。输出中移除指示行（该行全部设为背景(0)）。

**关键洞察**：递减填充在参考题中是单色的（全为黄色），但这里每一递减层携带循环中的不同颜色，在视觉上形成围绕对象的彩虹渐缩带。色彩循环的读取来源（指示行）与几何结构（对象边缘行程）完全独立，必须同时掌握两者才能生成正确输出。需要多个示例对比才能发现层号与循环索引的对应关系。

## 新题 6：宏列按围合空洞数排序

**组合逻辑**：[列排序](保留：移动宏列的中心像素列) + [围合检测](创新：不再在二维网格上检测封闭背景区域，而是在一维中心像素序列中检测被夹的空洞段) → 排序键从"填充数"变为"空洞数"

**来源原语**：列排序/column_sorting(P6-42a15761), 宏单元/macro_cell(P6-42a15761), 中心像素列/center_pixel_col(P6-42a15761), 间隔列/gutter_column(P6-42a15761), 轮廓围合/contour_enclosure(P17-753ea09b), 封闭背景区域/enclosed_bg_region(P17-753ea09b), 计数/counting(P7-ff28f65a)

**依赖链**：宏网格结构决定中心像素的提取 → 一维空洞检测（围合概念的一维化）产出每列的空洞计数 → 计数作为排序键驱动列重排。删除宏网格结构则无法提取中心像素；删除空洞检测则无排序键；删除列排序则空洞信息无处体现。

在宏网格中提取每个宏列的中心像素序列，计算其中被填充像素两侧夹住的空洞段数，按空洞数从多到少重排宏列。

**输入结构**：一个矩形宏网格，由红(2)的 3x3 宏单元组成，宏单元之间以 1 像素宽的黑(0)间隔列和间隔行分隔。宏网格有 5-6 个宏列和 5-7 个宏行。每个宏单元的中心像素要么是红(2)（填充），要么是黑(0)（空）。整体网格尺寸约为 (宏行数x4-1) x (宏列数x4-1)，例如 6 宏行 x 5 宏列 = 23x19。生成约束：各宏列的空洞数互不相同（确保排序结果唯一）；至少一个宏列有 0 个空洞，至少一个宏列有 2 个以上空洞。

**规则**：
1. 解析宏网格结构。提取每个宏列的中心像素序列（从上到下），形成一维二值序列（填充/空）。
2. 对每个宏列的一维序列，计算"空洞数"：一个空洞定义为一个极大连续空段，且该段的上方和下方都紧邻填充像素。紧贴序列顶端或底端的连续空段不算空洞（它们是开放端，非围合）。例如：[填, 空, 填, 空, 填] 有 2 个空洞；[空, 填, 填, 填, 空] 有 0 个空洞；[填, 空, 空, 填, 空] 有 1 个空洞。
3. 按空洞数从大到小排序宏列。空洞数相同时（由生成约束保证不会发生），按原始从左到右顺序保持不变。
4. 将整个中心像素列移动到排序后的位置。红(2)宏单元边框和黑(0)间隔保持不动——仅中心像素跟随排序移动。

**关键洞察**：排序的键不是填充像素的数量（参考题 P6 的做法），而是填充像素之间"夹住"的空洞段数。一个全满的列（5 个填充、0 个空洞）排名低于一个有很多间断的列。这是"围合"概念从二维到一维的降维应用。仅看单个示例时，排序标准可能被误认为是填充数或某种外观特征，需要对比多个示例才能发现空洞计数规则。

## 新题 7：碎片相位验证修复周期壁纸

**组合逻辑**：[周期推断](保留：从非缺损像素推断瓦片周期) + [互补拼合/移动](创新：碎片不再拼合矩形，而是通过相位颜色验证后填入壁纸缺损处) → 形状匹配与周期相位双重约束

**来源原语**：周期推断/period_inference(P14-c663677b), 重复瓦片/repeating_tile(P14-c663677b), 缺损像素/corrupted_pixel(P14-c663677b), 周期相位对应/periodic_phase_match(P14-c663677b), 非缺损像素一致性/non_corrupted_consistency(P14-c663677b), 移动/move(P19-fe45cba4), 碎片/fragment(P19-fe45cba4), 互补拼合/complement_fit(P19-fe45cba4), 碎片触边锚不触边/frag_edge_anchor(P19-fe45cba4)

**依赖链**：周期推断确定瓦片内容 → 碎片的形状匹配缺损区域的形状（多个候选） → 碎片颜色与候选位置的瓦片相位比对消歧 → 碎片移至唯一匹配位置。删除周期推断则无法验证碎片颜色；删除形状匹配则无法缩小候选；删除碎片则缺损无法修复（因为壁纸自身的冗余不足以在有多个相同相位缺损时确定颜色——此处设计为存在多个形状相同的缺损区域，仅靠周期推断无法区分它们）。

推断壁纸周期，找到形状匹配的缺损区域候选，再用碎片颜色与周期相位比对选出唯一正确位置，将碎片移入缺损处。

**输入结构**：约 16x16 的网格，黑(0)背景。主区域（约占网格中心 12x12）包含一个重复的矩形瓦片图案，瓦片尺寸为 3x3 或 4x4，使用 2-3 种非黑颜色（如红(2)、蓝(1)、黄(4)）。主区域内有 2-3 个缺损区域：每个缺损区域是一块连续的黑(0)像素（4-连通，2-4 像素），破坏了壁纸的局部。网格边缘（触碰边界的位置）有 2-3 个彩色碎片，每个碎片是一个 4-连通的小形状（2-4 像素），触碰网格的至少一条边。碎片数量等于缺损区域数量。生成约束：至少两个缺损区域的形状（相对像素位置集合）完全相同，但它们在壁纸中的绝对位置不同（因此对应的瓦片相位不同，期望的颜色也不同）；每个碎片的形状匹配至少一个缺损区域；每个碎片的颜色仅与其唯一正确的目标缺损位置的瓦片相位一致。

**规则**：
1. 识别主壁纸区域和边缘碎片。壁纸区域中的非黑像素构成重复瓦片的可见部分，黑像素为缺损。
2. 推断瓦片周期 (rp, cp)：找到最小的行周期 rp 和列周期 cp，使得所有非黑像素在相同相位 (r mod rp, c mod cp) 处颜色一致。重建完整瓦片 T[i][j]（i=0..rp-1, j=0..cp-1）。
3. 在壁纸区域内找到所有缺损区域（4-连通的黑像素组）。对每个缺损区域，记录其形状掩码（相对坐标集）和绝对位置。
4. 对每个边缘碎片：
   a. 提取碎片的形状掩码和每个像素的颜色。
   b. 在所有缺损区域中找到形状掩码与碎片匹配的候选（碎片掩码 == 缺损区域掩码）。
   c. 对每个形状匹配的候选缺损区域，检查颜色一致性：将碎片放置在该缺损位置后，碎片每个像素的颜色是否等于 T[pixel_row mod rp][pixel_col mod cp]。
   d. 恰好一个候选通过颜色验证。将碎片移至该位置。
5. 移动碎片：在目标缺损位置写入碎片颜色，将碎片原位置设为背景(0)。
6. 壁纸其余像素和主区域外的背景保持不变。

**关键洞察**：碎片不能仅凭形状放置——多个缺损区域形状相同，只有颜色与瓦片相位一致的那个才是正确目标。这将"形状拼合"（来自 P19）和"相位一致性"（来自 P14）熔合为一个双重约束系统。在参考题 P14 中，缺损可以纯粹由周期推断恢复，不需要外部碎片；在参考题 P19 中，碎片通过形状互补即可定位。这里两条路各自不够，必须同时使用。

## 新题 8：方块计数编码精灵体印章的重涂色映射

**组合逻辑**：[计数/编码](创新：方块计数不再编码到固定图案中，而是生成一个颜色→序号的映射表) + [印章覆盖/周期排布](保留：精灵体按周期网格印章) + [重涂色](创新：印章时精灵体的颜色不按固定规则变色，而是查询计数映射表决定)

**来源原语**：计数/counting(P7-ff28f65a), 编码/encoding(P7-ff28f65a), 前景方块/foreground_square(P7-ff28f65a), 数量映射/count_mapping(P7-ff28f65a), 印章覆盖/stamp(P9-d304284e), 精灵体/sprite(P9-d304284e), 周期排布/periodic_layout(P9-d304284e), 重涂色/recolor(P1-97d7923e)

**依赖链**：方块计数产出颜色→序号映射 → 精灵体的每个像素颜色查询该映射得到序号 → 序号对应固定色表中的输出颜色 → 重涂色后的精灵体按周期网格印章。删除计数则不知道映射关系；删除印章则重涂后的精灵体只出现一次；删除精灵体则无印章内容。三个来源（方块区、精灵体、周期布局）缺一不可。

统计不同颜色的 2x2 方块数量建立颜色映射表，用该映射表重涂精灵体颜色后，将精灵体按周期网格铺满画布。

**输入结构**：约 15x20 的网格，黑(0)背景。分为两个区域：
- 上部区域（约占上方 5-7 行）：散布若干 2x2 的实心彩色方块，颜色包括精灵体中出现的颜色（如红(2)、蓝(1)、绿(3)等）。同一颜色的方块可能出现 1-4 个。方块之间互不相邻（曼哈顿距离 >= 2）。
- 下部区域（约占下方 8-12 行）：包含一个小型多色精灵体（4-连通，4-8 像素，使用 2-3 种颜色，均出现在上部的方块颜色中）。精灵体位于下部区域的左侧。下部区域其余部分为背景。
- 固定色表（不在输入中显示，需从示例推断）：序号 1 → 灰(5), 序号 2 → 品红(6), 序号 3 → 橙(7), 序号 4 → 青(8)。

生成约束：精灵体中出现的每种颜色在上部区域都至少有 1 个 2x2 方块；不同颜色的方块数量互不相同（确保映射无歧义）；方块数量范围在 1-4 之间。

**规则**：
1. 在上部区域识别所有 2x2 实心彩色方块。对每种颜色统计方块数量，得到映射 M：颜色 → 数量。例如 M[红(2)] = 3, M[蓝(1)] = 1。
2. 建立重涂色查询表：对精灵体中的每种颜色 K，其输出颜色为固定色表[M[K]]。例如红(2)有 3 个方块，查固定色表序号 3 → 橙(7)，所以精灵体中的红像素变为橙。
3. 用重涂色后的精灵体作为印章。以精灵体原始包围盒左上角为起始锚点，在下部区域建立周期网格：列间距 = 精灵体宽度 + 1，行间距 = 精灵体高度 + 1。
4. 在每个周期网格位置粘贴重涂色后的精灵体掩码。仅涂背景(0)格点；超出网格边界或进入上部区域的部分裁剪丢弃。
5. 上部区域的方块在输出中被擦除（设为背景(0)）。原始精灵体位置被第一个印章覆盖。

**关键洞察**：2x2 方块不是装饰——它们的数量为精灵体的颜色重映射提供了密钥。精灵体提供形状和初始颜色，方块计数把初始颜色翻译成输出颜色，翻译后的精灵体才能正确印章。仅看一个示例时，印章的颜色似乎"凭空出现"，必须对比方块数量与印章颜色在多个示例间的对应关系才能发现编码规则。固定色表（序号到颜色的映射）本身也是隐蔽规则，需要跨示例归纳。
