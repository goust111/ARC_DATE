## 新题 1：条纹优先级驱动的光环冲突裁决

**组合逻辑**：[排序(sort)](条纹行位置→优先级序) + [印章覆盖(stamp_overlay)](创新：覆盖次序由外部优先级表决定) + [条纹(stripe) × 标记像素(marker_pixel)](创新：条纹不再决定填充轴，而是编码处理优先级) + [仅填背景格(only_fill_background)]

**来源原语**：排序 ← 8e1813be；印章覆盖/光环区域/仅填背景格 ← dc1df850；条纹/顺序对应 ← 8e1813be；标记像素/标记颜色对应 ← dc1df850

**依赖链**：条纹的行排列提供了一个优先级排序表 → 标记像素的颜色匹配到条纹从而获得优先级 → 优先级高的标记先执行光环扩展 → 先扩展的光环占据背景格后，后扩展的光环无法覆盖已占位置 → 最终图案取决于条纹顺序与标记空间分布的交互

根据网格顶部的彩色条纹行顺序，依次为下方同色标记像素扩展 3x3 光环，先扩展者占据背景格、后者不可覆盖。

**输入结构**：约 15x15 的网格，背景黑(0)。顶部 3~5 行为水平条纹，每行一种颜色（如红(2)、蓝(1)、绿(3)等），各行颜色互不相同，宽度等于网格宽度。条纹下方隔 1 行空行后，散布 4~8 个单像素标记，每个标记的颜色与某条条纹相同。标记之间距离不一——部分标记的 3x3 光环区域会彼此重叠。生成约束：每种条纹颜色至少对应 1 个标记，至少存在 2 对标记的光环范围有重叠。

**规则**：
1. 读取顶部条纹区域，按行从上到下确定颜色优先级序列（第 1 行颜色优先级最高，依次递减）。
2. 按优先级从高到低依次处理所有同色标记像素：对每个标记像素，将其 Chebyshev 距离 1 邻域（3x3，含自身）中所有仍为黑(0)背景的格子涂为该标记的颜色。
3. 标记像素自身保持原色不变。已被先前步骤涂色的格子不再改变。
4. 同一优先级内的多个标记按其在网格中从上到下、从左到右的顺序处理。
5. 条纹区域本身在输出中保持不变。

**关键洞察**：条纹不是装饰性边框——它们是优先级排序表，决定了光环重叠区域归属于哪种颜色。仅看单个示例，可能误以为优先级与颜色编号或标记数量有关，需要对比条纹顺序不同的多个示例才能确认优先级来源。

## 新题 2：格子槽频次控制矩形跳跃倍数

**组合逻辑**：[计数(counting)](创新：对格子槽中颜色出现次数计数) + [平移(translate)](创新：位移量为自身高度 × 频次) + [格子框架(lattice_frame) × 实心矩形(solid_rectangle)](创新：格子不再用于跨框架推断填充色，而是作为频次编码表)

**来源原语**：计数 ← fcc82909；平移/移动自身高度 ← 5521c0d9；格子框架/格子槽位/位置对应颜色 ← 2e65ae53；实心矩形 ← 5521c0d9

**依赖链**：格子槽位中各颜色的出现次数决定倍率 → 矩形的颜色匹配格子中的颜色获得倍率 → 矩形位移 = 自身高度 × 该倍率 → 移除原位矩形后在新位置绘制

统计左侧格子中各颜色出现的槽位数，将右侧同色矩形上移"自身高度 x 槽位数"的距离。

**输入结构**：约 18x18 的网格，背景黑(0)。左侧约占 1/3 宽度，包含一个灰(5)线条构成的矩形格子框架，内部被分为 3x3 或 4x3 等均匀槽位，部分槽位内部填有纯色（如红(2)、蓝(1)、绿(3)等），其余槽位为黑(0)背景。右侧约占 2/3 宽度，散布 2~4 个单色实心矩形（无重叠），每个矩形颜色与格子中某种填充色相同，矩形高度各异（1~4 像素），上方有足够空间容纳跳跃。生成约束：每种矩形颜色至少在格子中出现 1 个槽位；矩形跳跃后不超出网格上边界且不彼此重叠。

**规则**：
1. 在左侧格子中，统计每种非背景、非框架颜色占据了多少个槽位，记为该颜色的频次 F。
2. 对右侧每个实心矩形，找到其颜色在格子中的频次 F。
3. 将该矩形从原位清除（填黑(0)），然后在原位正上方偏移 (F x 矩形高度) 个像素处重新绘制。即矩形新的顶边行号 = 原顶边行号 - F x 高度。
4. 格子区域在输出中保持不变。
5. 若多个矩形颜色相同，它们共享同一频次 F，各自独立计算位移。处理顺序不影响结果（生成时保证跳跃后矩形互不重叠且不超出边界）。

**关键洞察**：格子不是用来推断缺失颜色的查阅表——它是频次编码器：同一颜色占据越多槽位，对应矩形跳得越远。位移量是频次与自身高度的乘积，需要同时获取两条信息才能确定输出。

## 新题 3：堆叠掩码交集编码平铺镜像指令

**组合逻辑**：[压缩(compress) / 逐格比较(cell_comparison)](创新：交集结果不直接输出，而是编码逐列镜像指令) + [平铺(tiling) + 镜像(mirror)](创新：镜像不再按固定奇偶交替，而是由掩码交集的列特征动态决定)

**来源原语**：压缩/堆叠掩码/逐格比较/背景交集 ← fafffa47；平铺/镜像/奇偶位交替翻转 ← bc4146bd

**依赖链**：两半掩码逐格比较产生交集图案 → 统计交集图案每列的标记像素数奇偶性 → 奇偶性决定该列在平铺输出中使用原始瓦片列还是镜像瓦片列 → 瓦片在整个输出区域中逐列拼贴，列方向是否翻转由掩码交集动态控制

将上下两半掩码的背景交集逐列统计奇偶，用奇偶结果决定输出中每列采用瓦片原列还是水平镜像列。

**输入结构**：约 14x10 的网格，分为三个垂直区域。上半区（前 5 行）和下半区（第 6~10 行）各为一个 5x10 的二值掩码：共享同一背景色黑(0)，上半区前景色为蓝(1)，下半区前景色为红(2)，两种前景色各自形成不规则图案。网格最右侧 3 列（与掩码区不重叠）的底部放置一个 3x3 的瓦片图案，用橙(7)和黄(4)两色构成。瓦片不是左右对称的。生成约束：掩码区宽度为瓦片宽度的整数倍（如宽度 6 = 3x2）；掩码交集各列的标记像素数不全相同（既有奇数列也有偶数列）。

**规则**：
1. 将上半区与下半区逐格比较：两格均为黑(0)背景的位置标记为品红(6)，其余位置标记为黑(0)。得到一个与半区同尺寸的交集图。
2. 对交集图的每一列，统计品红(6)像素的个数。若个数为奇数，该列标记为"翻转"；若为偶数（含 0），标记为"保持"。
3. 输出网格尺寸等于半区尺寸。用 3x3 瓦片水平平铺填充输出（瓦片在垂直方向上也重复平铺，行数取模循环）。
4. 对于标记为"保持"的列，使用瓦片对应列原样；标记为"翻转"的列，使用瓦片水平镜像后的对应列（即瓦片第 0 列变为第 2 列，第 2 列变为第 0 列）。
5. 输出只包含平铺结果，不包含原始掩码区和瓦片区。

**关键洞察**：两半掩码的交集不直接出现在输出中——它被压缩为一组逐列的奇偶信号，这些信号像开关一样控制每列瓦片是否镜像。必须同时理解掩码比较规则和镜像平铺规则才能求解。

## 新题 4：对称轨道揭色后按颜色选邻域几何扩展

**组合逻辑**：[对称补全(symmetry_completion)](确定隐藏颜色) → [描边(mark_neighbors)](创新：扩展几何不再由固定色决定，而由对称补全后新出现的颜色属性决定) + [双轴镜像(biaxial_mirror) × 标记色选邻域几何(marker_color_selects_neighborhood)](创新：两个原本属于不同题的条件合并——对称轨道提供颜色，颜色又选择邻域类型)

**来源原语**：对称补全/双轴镜像/标记色空洞/标记处填入轨道色 ← b8825c91；描边/标记色选邻域几何/对角邻接/正交邻接 ← 0ca9ddb6

**依赖链**：灰(5)标记格遮挡了对称图案中的若干像素 → 通过双轴镜像轨道推断每个灰格应为红(2)或蓝(1) → 用推断出的颜色替换灰格 → 替换后出现的红像素向对角方向扩展黄(4)标记、蓝像素向正交方向扩展橙(7)标记（仅填背景格）

先用双轴对称补全灰色空洞处的真实颜色，再根据补全后的颜色（红→对角扩展，蓝→正交扩展）执行邻域描边。

**输入结构**：约 11x11（奇数边长以保证中心轴存在）的网格，背景黑(0)。网格中有一个以水平和垂直中心线为轴的双轴对称彩色图案，由红(2)和蓝(1)像素构成。图案中若干位置的像素被替换为灰(5)（标记色），破坏了对称性。在每个四格轨道（原始位置、水平镜像位、垂直镜像位、180度镜像位）中，至多一个格子为灰色，其余至少有一个可见的红或蓝像素。生成约束：灰色替换后，补全出的红像素和蓝像素都至少各 2 个；补全后的某些像素扩展区域会与原有像素相邻（但扩展仅覆盖黑(0)背景格）。

**规则**：
1. 将所有格子按双轴（水平 + 垂直中心线）镜像分组为四格轨道。
2. 对每个包含灰(5)格的轨道，用该轨道中非灰格的颜色（红(2)或蓝(1)）替换灰格。若轨道中灰格与非灰格各半（如 2 灰 2 非灰），仍以非灰格颜色为准（生成时保证每轨道至少有一个非灰格且同轨道非灰格颜色一致）。
3. 对称补全完成后，对每个**原本为灰色、现在被补全的像素**执行邻域扩展：
   - 若补全颜色为红(2)：将其 4 个对角邻居中仍为黑(0)的格子涂为黄(4)。
   - 若补全颜色为蓝(1)：将其 4 个正交邻居中仍为黑(0)的格子涂为橙(7)。
4. 原本就可见的红、蓝像素不触发扩展。扩展只作用于补全后新显现的像素。
5. 扩展产生的黄、橙像素不会覆盖任何非背景像素（红、蓝、其他黄橙均不被覆盖）。超出网格的邻居忽略。

**关键洞察**：灰色格子同时承担两个角色——它是对称补全的空洞（需从轨道推断颜色），也是邻域扩展的触发中心（推断出的颜色决定扩展形状）。不完成对称补全就不知道该向哪个方向扩展，不理解颜色-几何映射就无法确定最终输出。

## 新题 5：噪声擦除后框内图案设定补线预算

**组合逻辑**：[擦除(erase)](清除对角噪声) + [补线(line_completion)](创新：间隙填充的最大长度不再由噪声跨度决定，而由框内图案的宽/高决定) + [矩形框(rectangular_frame) + 直线段(straight_line_segment) + 对角噪声(diagonal_noise)](创新：框从"待填充的目标"变为"提供补线参数的参考尺")

**来源原语**：擦除/补线/直线段/对角噪声/忽略干扰项/间隙长度限制 ← 7b80bb43；矩形框/框内匹配 ← 8a6d367c

**依赖链**：对角噪声必须先擦除才能识别真实间隙 → 矩形框内部的彩色图案提供了一个几何量度 → 水平线段的最大可填间隙等于框内图案的宽度，垂直线段等于框内图案的高度 → 超过预算的间隙保持断开

擦除对角噪声像素后，用矩形框内彩色区域的宽/高作为水平/垂直线段断口的最大填充长度。

**输入结构**：约 18x18 的网格，背景黑(0)。网格中有一个灰(5)像素构成的 1 像素宽矩形框（约 5x4 到 7x6 大小），框内部分区域填有绿(3)像素构成的一个小型连通图案（3~8 像素，4-连通，非矩形），其余框内为黑(0)背景。框外散布若干红(2)像素构成的水平和垂直线段（各 1~3 条，长度 3~10 像素），部分线段有 1~4 像素宽的断口。断口附近散布着红(2)的对角噪声像素（仅与同色像素有对角邻接而无正交邻接的孤立像素或 45 度链）。生成约束：框内绿色图案的边界框宽度和高度不相等（如宽 3 高 2），以便水平/垂直线段的填充预算不同；至少有一条线段的间隙长度 <= 对应预算（可修复），至少一条 > 预算（不可修复）。

**规则**：
1. 擦除所有对角噪声像素：删除每个红(2)像素中没有任何红(2)正交邻居、只有红(2)对角邻居的像素（将其设为黑(0)）。对因擦除而新暴露出的孤立对角像素重复此过程直到稳定。
2. 计算矩形框内绿(3)图案的最小边界框，记其宽度为 W、高度为 H。
3. 扫描所有水平红(2)线段中的间隙（同一行内两段红线之间的黑(0)连续区域）。若间隙长度 <= W，则用红(2)填充该间隙；否则保留断开。
4. 扫描所有垂直红(2)线段中的间隙（同一列内两段红线之间的黑(0)连续区域）。若间隙长度 <= H，则用红(2)填充该间隙；否则保留断开。
5. 矩形框及其内部在输出中保持不变。

**关键洞察**：矩形框内的图案不是待补全的目标——它是一把尺子，其边界框的宽度和高度分别设定了水平和垂直线段断口修复的最大预算。必须先擦除噪声才能测量真实间隙长度，再用框内尺度判断是否修复。

## 新题 6：多色方块颜色数决定精灵体复制份数

**规则**：
1. 统计 2x2 方块中不同非黑颜色的数量 N（范围 2~4）。
2. 裁剪精灵体的最小边界框（保留内部黑色空洞）。
3. 生成宽度为 N 倍精灵体边界框宽度、高度等于边界框高度的输出。
4. 从左到右放置 N 份精灵体副本。第 1、3、... 份（奇数位）使用原始朝向，第 2、4、... 份（偶数位）使用左右镜像。

**关键洞察**：2x2 方块不是装饰——它的颜色多样性编码了精灵体的重复次数。镜像交替规则是固定的（奇偶位），但重复几次需从方块推断。仅一个示例可能误判 N 的来源（如精灵体面积、方块位置等），需对比不同方块颜色数的示例才能确认。

## 新题 7：路径通道宽度索引格子槽位颜色

**组合逻辑**：[膨胀求交(dilate_intersect)](提取两路径间通道) + [推断(infer) + 重涂色(recolor)](创新：通道不再统一涂色，而是逐段用格子槽位颜色重涂) + [路径组件(path_component) × 格子框架(lattice_frame)](创新：通道的局部宽度作为索引查询格子槽位)

**来源原语**：膨胀求交/路径组件/通道/两路径间隙重叠区 ← f1bcbc2c；格子框架/格子槽位/跨框架对应/槽位位置决定颜色 ← 2e65ae53；推断/重涂色 ← 2e65ae53

**依赖链**：两路径 8-邻域膨胀求交得到通道像素 → 通道沿路径方向被分为若干段，每段有局部宽度（1 或 2 像素） → 格子框架底部有一行槽位，槽位编号 1, 2, ...，每个槽位内填有一种颜色 → 通道每段的局部宽度作为索引，查询对应编号的格子槽位颜色 → 该段通道被涂为查询到的颜色

提取两条路径之间的通道，按通道各段的局部宽度查询格子中对应编号槽位的颜色来重涂每段。

**输入结构**：约 16x16 的网格，背景黑(0)。网格上半部有两条橙(7)的 1 像素宽 4-连通路径组件，大致平行地从左向右蜿蜒（路径间距在 1~3 像素间变化，形成宽窄不一的通道）。网格底部有一个灰(5)线条构成的 1 行 N 列格子框架（N >= 3），每个槽位内填有一种不同颜色（如蓝(1)、红(2)、绿(3)等）。通道像素（两路径膨胀交集）初始为黑(0)背景。生成约束：通道各段宽度为 1~N 的整数值，且至少出现两种不同宽度；两路径不直接接触（最小间距 >= 1）。

**规则**：
1. 对两条橙(7)路径各自进行 8-邻域膨胀 1 像素，取两个膨胀结果的交集，排除路径本身的像素，得到通道像素集合。
2. 沿通道的水平方向，将通道切分为连续的垂直切片（每列 1 个切片）。每个切片的"局部宽度"等于该列中通道像素的个数。
3. 读取底部格子框架的槽位：从左到右编号为 1, 2, 3, ...，记录每个槽位的填充颜色。
4. 对通道的每个垂直切片，用其局部宽度 w 作为索引，查询编号为 w 的格子槽位颜色，将该切片中所有通道像素涂为该颜色。
5. 路径像素、格子框架及其他区域保持不变。

**关键洞察**：通道不是整体涂一种颜色——它的每一列切片根据局部宽度获得不同的颜色，而颜色来自底部格子的位置索引映射。通道的几何形状（宽窄变化）与格子的颜色序列共同决定了最终着色。

## 新题 8：外部标记定向裁剪后按图例膨胀围框

**组合逻辑**：[裁剪(crop) + 旋转(rotation)](由外部标记决定朝向) + [膨胀(dilate) + 颜色图例(color_legend)](创新：膨胀围框的颜色不再由固定图例条给出，而是由裁剪后内部颜色的出现次数匹配图例确定) + [外部标记像素(external_marker) × 封闭孔洞(enclosed_hole)](创新：旋转后孔洞的相对位置变化影响膨胀是否保留孔洞)

**来源原语**：裁剪/旋转/外部标记/内部标记/外部标记决定朝向 ← 94133066；膨胀/颜色图例/图例映射/封闭孔洞/孔洞保留不填 ← 5adee1b2

**依赖链**：外部标记确定矩形的旋转方向 → 裁剪并旋转矩形 → 旋转后统计内部非背景、非标记颜色的像素数 → 像素数最多的颜色作为"主色"去匹配图例左列 → 图例右列给出围框颜色 → 对旋转后的裁剪图执行 1 像素膨胀围框，但保留裁剪图中的封闭背景孔洞不填

用外部标记决定矩形裁剪朝向，再用旋转后内部主色查颜色图例获取围框色，膨胀围框时保留孔洞。

**输入结构**：约 16x16 的网格，背景黑(0)。网格中有一个约 5x6 的单色（如蓝(1)）实心矩形，内部嵌有 1~2 个单像素的颜色标记（如红(2)、绿(3)），以及 1 个由背景色(0)形成的 1~2 像素封闭孔洞。矩形外部有与内部标记同色的外部标记像素（每种标记色恰好内外各一个）。网格左边缘有 2~3 个 2x2 颜色图例块：每块左列为一种前景色（如蓝(1)、红(2)等），右列为对应的围框色（如黄(4)、栗(9)等）。生成约束：矩形内部蓝色像素数远多于标记色像素数，使蓝色为主色；外部标记的相对排列经旋转后与内部标记匹配，且旋转角度为 90/180/270 度之一。

**规则**：
1. 识别矩形及其内外标记像素。将外部标记像素的相对坐标（以外部标记群的左上角为原点）与内部标记像素的相对坐标（以内部标记群的左上角为原点）对比，找到唯一的旋转/翻转使两者匹配。
2. 裁剪矩形的最小边界框，对裁剪结果应用步骤 1 确定的旋转/翻转。
3. 在旋转后的裁剪图中，统计非背景(0)、非标记色的像素数量最多的颜色，记为主色 C。
4. 在左边缘图例中查找左列颜色 = C 的图例块，取其右列颜色作为围框色 H。
5. 将旋转后的裁剪图向四周各扩展 1 像素，扩展区域全部填为围框色 H。
6. 裁剪图内部的封闭背景孔洞（4-连通的黑(0)区域且不接触裁剪图边界）保持为黑(0)，不被围框色填充。
7. 输出为带围框的旋转裁剪图（尺寸 = 裁剪图 + 2 行 2 列）。

**关键洞察**：外部标记同时解锁旋转方向和内部结构的重排；旋转后主色可能因裁剪范围微调而变化（不同旋转下边界框可能不同），所以围框颜色依赖于旋转结果。孔洞保留规则进一步约束膨胀操作——不是简单扩边，而是要识别并避开内部封闭区域。

## 新题 9：色段对齐后空出位置由对称轨道填色

**组合逻辑**：[滑动(shift) + 对齐(align)](色段右边界对齐) + [对称补全(symmetry_completion)](创新：对称补全不作用于预先存在的图案，而是作用于对齐操作腾出的空白区域) + [色段(color_run) × 标记色空洞(marker_color_hole)](创新：对齐后左侧空出的像素成为需要通过垂直轴对称推断的空洞)

**来源原语**：滑动/对齐/色段/同行排列/边界对齐 ← 984d8a3e；对称补全/双轴镜像/标记色空洞/标记处填入轨道色 ← b8825c91

**依赖链**：每行的中间色段右移对齐到统一列 → 对齐操作在某些行左侧腾出空白区域 → 将空白视为灰(5)标记空洞 → 以网格垂直中心线为轴，用对称轨道中非空洞格的颜色填充这些空洞

将各行色段右对齐后，左侧腾出的空位用垂直轴对称从右侧对应位置的颜色补全。

**输入结构**：约 9x12 的网格，无背景色（全部填满）。每行由三种颜色构成：左侧区域为灰(5)，中间为一段连续的品红(6)色段（宽度各行不同），右侧为栗(9)。品红色段的右边界列在不同行各不相同。此外，网格整体接近垂直轴对称——如果将品红色段对齐后，左右两侧的灰(5)和栗(9)图案在垂直中心线两侧是镜像的，但对齐前由于色段偏移，左侧部分行被品红侵占，无法看到完整的对称图案。生成约束：网格列数为奇数（确保垂直中心线存在）；品红色段的最小右边界列在 >= 中心列的位置（对齐不越过中心线）；对齐后左侧空出的位置至少有 3 处需要通过对称补全来确定颜色。

**规则**：
1. 找到所有行中品红(6)色段的右边界列的最小值 R_min。
2. 在每行中，将品红色段整体左移使其右边界对齐到 R_min 列。色段左移后，色段原占据的右侧位置空出，填为灰(5)（标记色）。色段左侧原有的灰(5)像素保持不变。
3. 对齐完成后，将所有灰(5)像素视为待填充的对称空洞。以网格垂直中心列为对称轴，对每个灰(5)像素，找到其镜像位置。若镜像位置是非灰(5)像素（品红(6)或栗(9)），则将该灰(5)像素替换为镜像位置的颜色。
4. 若镜像位置也是灰(5)，保持灰(5)不变（生成时保证不会出现两侧同时为灰的情况）。
5. 品红色段像素和已有栗(9)像素在整个过程中不被修改。

**关键洞察**：对齐操作不是最终目标——它制造了空洞。这些空洞的填充不是简单的"用左侧颜色延伸"，而是通过垂直轴对称从网格另一侧复制颜色。必须先完成对齐才能确定空洞位置，再用对称规则才能确定空洞颜色。

## 新题 10：连通分量面积排序决定格子槽位填充顺序

**组合逻辑**：[排序(sort)](创新：按连通分量面积排序，而非按位置) + [填充(fill) + 格子槽位(lattice_slot)](创新：槽位颜色不再通过跨框架推断，而是由排序后的连通分量颜色依次填入) + [连通分量(connected_component) × 顺序对应(ordinal_correspondence)](创新：面积大小建立分量与槽位之间的序对应)

**来源原语**：排序/顺序对应 ← 8e1813be；填充/格子框架/格子槽位 ← 2e65ae53；连通分量 ← 5adee1b2

**依赖链**：识别格子外的各色连通分量并计算面积 → 按面积升序排列分量 → 格子槽位按从左到右、从上到下排序 → 排序后的分量颜色依次填入排序后的槽位 → 槽位数量可能大于分量数量，多余的槽位保持背景色

统计格子外各色连通分量的面积，按面积从小到大将其颜色依次填入格子的槽位（从左到右、从上到下）。

**输入结构**：约 16x16 的网格，背景黑(0)。网格右侧有一个灰(5)线条构成的矩形格子框架，分为 2 行 3 列共 6 个槽位（或类似布局），所有槽位内部初始为黑(0)。网格左侧散布 3~5 个不同颜色的 4-连通单色连通分量（如红(2)、蓝(1)、绿(3)、黄(4)等），每个分量形状不规则（非矩形），面积各不相同（范围 2~10 像素）。生成约束：分量数量 <= 槽位数量；各分量面积互不相等（无需 tie-break）。

**规则**：
1. 识别格子框架外所有非背景、非灰(5)的 4-连通单色连通分量，记录每个分量的颜色和面积（像素数）。
2. 将分量按面积从小到大排序。
3. 将格子槽位按从左到右、从上到下排序（即第一行从左到右，然后第二行从左到右，以此类推）。
4. 将排序后的分量颜色依次填入排序后的槽位：第 1 小的分量颜色填入第 1 个槽位，第 2 小的填入第 2 个，以此类推。每个槽位内部全部填为对应颜色。
5. 若槽位数量多于分量数量，多余槽位保持黑(0)背景。
6. 格子框架线条（灰(5)）保持不变。格子外的连通分量在输出中保持不变。

**关键洞察**：格子不是分量的缩略图也不是颜色查找表——它是一个按面积排序的结果展示板。分量颜色与槽位之间没有空间位置对应关系，完全由面积大小建立序对应。仅看一个示例可能误以为是按位置或按颜色编号排序，需要对比多个示例确认是面积排序。
