## 新题 1：框内标记计数参数化条形循环移位

**组合逻辑**：[计数(counting)](创新：计数结果不用于擦除判定，而作为循环移位量的参数) + [框内限定(frame_interior_only)](已有) + [循环移位(cyclic_shift)](创新：移位量由标记计数动态决定，而非固定为1)

**来源原语**：计数(counting)、标记包含于对象(marker_in_object) ← a934301b；循环移位(cyclic_shift)、竖直条(vertical_bar)、条高度(bar_height)、条颜色(bar_color)、有序槽位(ordered_slots) ← 2601afb7；矩形边框(rectangular_frame)、框内区域(interior_region)、框内限定(frame_interior_only) ← 7ee1c6ea

**依赖链**：矩形边框界定计数范围 → 框内标记像素总数成为循环移位步长 → 步长同时作用于颜色右旋和高度左旋两个独立属性；删除框则计数范围不确定，删除计数则移位量不确定，删除移位则计数无意义

一句话总结：在矩形框内统计标记像素总数，以该数值为步长对框内各竖直条的颜色和高度分别做反向循环移位。

**输入结构**：约 15x15 网格，黑(0)背景。网格中有一个灰(5)一像素厚矩形边框。框内底部对齐着 4-6 根一像素宽的竖直条，每根高度不同（3-8 像素），每根颜色各异（取自蓝(1)、红(2)、绿(3)、黄(4)、品红(6)等，不含灰(5)和橙(7)）。框内还散布着若干橙(7)标记像素，这些标记像素一部分落在竖直条所在列上（与条像素重叠时不遮挡条，仅视为该列存在标记），一部分落在条之间的空列上。框外可能存在干扰性的橙(7)像素，但不参与计数。生成约束：框内各条高度互不相同，框内标记像素总数不超过条数减一（保证移位量在合理范围内），各示例中标记数量不同。

**规则**：
1. 识别灰(5)矩形边框，取其严格内部区域。
2. 统计框内所有橙(7)像素的总数，记为 S。
3. 将框内竖直条按所在列从左到右编为有序槽位 0, 1, ..., N-1（N 为条的数量）。
4. 构建输出：对于槽位 i 的条，其颜色取自槽位 (i - S) mod N 的原始颜色，其高度取自槽位 (i + S) mod N 的原始高度。
5. 条仍底部对齐在原列位置。边框、框外像素和背景不变。所有橙(7)标记像素（框内框外）在输出中保持不变。

**关键洞察**：标记像素的数量不是用来筛选对象的阈值（与参考题 a934301b 不同），而是编码了一个全局参数——循环移位步长。必须对比多个示例中不同的标记数量与对应的移位结果，才能归纳出"总数=步长"这一映射关系。

## 新题 2：字形解码多方向射线擦除

**组合逻辑**：[解码指令(decode_instructions)](创新：字形面积编码射线方向而非折线段) + [射线延伸(ray_extend)](创新：从单起点同时发射多条射线，方向由字形集合决定) + [擦除(erase)](已有：命中即整体擦除)

**来源原语**：字形指令(glyph_instruction)、分隔列(separator_column)、编码映射(encoding_map)、解码指令(decode_instructions)、顺序读取(sequential_reading) ← 136b0064；射线延伸(ray_extend)、控制像素(control_pixel)、标记条(marker_bar)、射线命中(ray_intersection)、命中即整体擦除(hit_erases_whole) ← 2f767503；擦除(erase) ← a934301b

**依赖链**：字形像素面积 → 解码为射线方向集合 → 从起始标记同时发射所有解码方向的射线 → 射线命中的目标对象被整体擦除；删除解码则不知方向，删除射线则解码无用，删除擦除则射线无效果

一句话总结：将分隔区内每个 3x3 字形的像素面积解码为一个射线方向，从起始标记同时发射所有解码方向的射线，擦除被任意射线穿过的目标对象。

**输入结构**：约 18x12 网格，黑(0)背景。一条红(2)全高竖直分隔列将网格分为左右两区。左区（约 6 列宽）包含 2-4 个 3x3 字形，字形由蓝(1)像素构成，字形之间以至少一行黑(0)间隔分开，按列主序排列（从上到下，从左到右）。右区包含一个灰(5)起始标记像素和 3-6 个 4-连通的绿(3)目标对象（每个 3-8 像素，形状各异：非对称连通块）。生成约束：字形像素面积取值范围为 3-6，各字形面积互不相同；起始标记位于右区中部附近；目标对象互不相邻且不接触起始标记；每个解码方向至少命中一个目标对象。

**规则**：
1. 识别红(2)分隔列，左侧为字形区，右侧为目标区。
2. 在字形区按列主序（同列内从上到下，再到右列）读取每个 3x3 字形。
3. 统计每个字形的蓝(1)像素数（面积），按如下映射解码为方向：面积 3 → 上，面积 4 → 下，面积 5 → 右，面积 6 → 左。
4. 在目标区找到灰(5)起始标记。从该点同时向所有解码方向各发射一条无限射线（射线沿行或列延伸直到网格边界）。
5. 对于每个绿(3)目标对象，若其任一像素被任一射线穿过，则将该对象所有像素设为黑(0)。
6. 输出仅保留右区（裁掉分隔列及左区），起始标记保留，未被命中的目标对象保留。

**关键洞察**：字形的具体形状无关紧要，只有像素总数（面积）携带信息——这与参考题 136b0064 中面积编码折线方向/长度类似，但这里面积编码的是独立射线方向而非连续路径段。面积到方向的具体映射表（3→上、4→下等）需要通过对比多个示例归纳。

## 新题 3：精灵体尺寸排序驱动色彩指引查找表赋色

**组合逻辑**：[尺寸排序(size_ordering)](创新：排序结果不用于标记推进，而作为颜色查找表的索引) + [位置对应(pos_correspond) → 指引色映射(guide_maps_quadrant)](创新：指引块的空间位置不再映射到精灵体的空间象限，而映射到尺寸排名) + [平移对齐(translate_align)](已有：精灵体居中到格元中心)

**来源原语**：标记点阵(marker_lattice)、精灵体(sprite)、格元内居中(centered_within_cell)、平移对齐(translate_align) ← 20981f0e；色彩指引块(color_guide)、象限(quadrant)、位置对应(pos_correspond)、重涂色(recolor)、指引色映射象限(guide_maps_quadrant) ← 7c008303；尺寸排序(size_ordering)、标记段(marker_segment) ← 48634b99

**依赖链**：精灵体像素数 → 尺寸排序确定排名 → 排名索引到色彩指引块的光栅位置 → 获得目标颜色并重涂 → 同时平移居中；删除排序则不知颜色对应关系，删除指引块则无目标颜色，删除居中则输出位置错误

一句话总结：按精灵体像素数从小到大排名，用排名在 2x2 色彩指引块中查得对应颜色后重涂精灵体，同时将每个精灵体居中到其所在格元中心。

**输入结构**：约 15x15 网格，黑(0)背景。灰(5)标记像素构成规则的笛卡尔点阵（行间距和列间距相等，均为 d，d 在 4-6 之间），将网格隐式分为若干格元。其中一个格元包含一个 2x2 色彩指引块，使用四种互不相同的非黑(0)非灰(5)颜色（如蓝(1)、红(2)、绿(3)、黄(4)），该格元无其他前景像素。其余 4 个格元各含一个单色精灵体（4-连通，像素数在 2-6 之间，形状各异），颜色均为橙(7)。四个精灵体的像素数互不相同。每个精灵体在其格元内位置偏离中心。其余格元为空。生成约束：恰好 4 个精灵体对应指引块的 4 个位置；精灵体居中后不超出格元边界。

**规则**：
1. 识别灰(5)标记点阵，确定格元划分。
2. 找到包含 2x2 色彩指引块的格元，读取指引块四个颜色，按光栅顺序（左上→右上→左下→右下）编为位置 1、2、3、4。
3. 统计每个橙(7)精灵体的像素数，按像素数从小到大排名为 1、2、3、4。
4. 将排名为 k 的精灵体重涂为指引块位置 k 的颜色。
5. 将每个精灵体平移，使其边界框中心与所在格元的中心对齐（若边界框尺寸为偶数，取偏左上的中心像素）。
6. 标记点阵和指引块在输出中保持不变。

**关键洞察**：色彩指引块的四个位置不再对应精灵体的四个空间象限（与参考题 7c008303 完全不同），而对应尺寸排名——最小的精灵体获得指引块左上角的颜色，最大的获得右下角的颜色。必须对比多个示例中精灵体大小与所得颜色的对应关系才能发现这一排名映射。

## 新题 4：括号提取构造模板图案后逐锚点印章

**组合逻辑**：[括号界定提取(bracket_delimited_extraction) + 堆叠(stacking)](创新：提取结果不作为最终输出，而作为中间模板图案) + [印章放置(stamp) + 颜色替换(color_substitution)](创新：模板非预设，而由提取动态构造) + [颜色重叠匹配(color_overlap_match)](创新：用锚点颜色匹配模板中的对应像素来确定印章对齐位置)

**来源原语**：控制像素对(control_pixel_pair)、行段(row_segment)、括号界定提取范围(bracket_delimited_extraction)、堆叠(stacking) ← 505fff84；印章放置(stamp)、模板图案(stencil_pattern)、颜色替换(color_substitution)、规则示例(rule_example) ← abc82100；颜色重叠匹配(color_overlap_match)、最大重叠确定位置(max_overlap_pos) ← d6542281

**依赖链**：控制像素对括号 → 提取行段 → 堆叠构造多行模板 → 模板中的非黑像素为印章形状 → 锚点颜色与模板像素匹配确定印章平移量 → 印章印出并重涂色；删除提取则无模板，删除印章则模板无用，删除颜色匹配则不知印章位置

一句话总结：用蓝/青控制像素对从上半区提取行段并堆叠为模板图案，在下半区将该模板对齐到每个锚点像素处印出，印章颜色取锚点颜色。

**输入结构**：约 18x14 网格，黑(0)背景。网格水平分为上下两区，由一行黄(4)分隔线隔开。上区有 3-5 行包含蓝(1)/青(8)控制像素对，每行恰有一个蓝(1)在左、一个青(8)在右，所有行中蓝-青之间的间距相同（3-5 个像素）。两控制像素之间的像素为红(2)或黑(0)构成的图案段。其余行无控制像素。下区为一片空白画布（黑(0)），上面散布着若干单独的彩色锚点像素（颜色各异，取自绿(3)、品红(6)、橙(7)等，互不相同）。生成约束：锚点之间距离足够大，保证以锚点为中心放置模板后各模板实例互不重叠；模板尺寸不超过 5x5。

**规则**：
1. 识别黄(4)分隔行，上方为提取区，下方为印章区。
2. 在提取区从上到下扫描，找到所有包含蓝(1)和青(8)控制像素的行。
3. 对每个标记行，提取蓝(1)与青(8)之间（不含控制像素本身）的像素段。
4. 将提取的段按行序从上到下堆叠，形成一个多行模板图案（仅含红(2)和黑(0)）。
5. 模板中红(2)像素位置为印章的"实心"位置，黑(0)为"透明"位置。
6. 对下区每个锚点像素：将模板的几何中心（行数和列数各取中间值，向下向右取整）对齐到锚点位置，将模板中所有红(2)位置印出，颜色替换为该锚点的颜色。
7. 分隔行和上区在输出中被裁掉，仅输出下区（含印章结果）。

**关键洞察**：模板图案不是预先存在的空间实体，而是由括号提取动态构造的中间产物——提取过程的输出成为印章过程的输入工具。这种"提取即构造"的两阶段结构在任何单一参考题中都不存在。

## 新题 5：面板归属与标记奇偶分支决定框内操作类型

**组合逻辑**：[计数(counting)](创新：计数结果的奇偶性决定分支，非阈值判断) + [颜色互换(color_swap) | 重涂色(recolor)](两个操作作为条件分支的两臂) + [所属面板(panel_membership) + 对侧面板色(opposite_panel_color)](创新：面板色不用于修补缺陷条，而在奇数分支中提供重涂目标色) + [框内限定(frame_interior_only)](已有)

**来源原语**：计数(counting)、标记像素(marker_pixel)、标记包含于对象(marker_in_object) ← a934301b；矩形边框(rectangular_frame)、框内区域(interior_region)、颜色互换(color_swap)、框内限定(frame_interior_only) ← 7ee1c6ea；面板(panel)、所属面板(panel_membership)、对侧面板色(opposite_panel_color)、重涂色(recolor) ← 9b5080bb；擦除(erase) ← a934301b

**依赖链**：标记计数 →{偶数: 框内双色互换; 奇数: 框内多数色重涂为对侧面板色} → 标记像素擦除。面板归属仅在奇数分支生效，与计数结果形成条件耦合；删除计数则不知走哪个分支，删除面板信息则奇数分支无目标色，删除框则操作范围不确定

一句话总结：统计每个矩形框内标记像素数，偶数则互换框内两色，奇数则将框内较多的色替换为所在面板的对侧面板色，最后擦除所有标记。

**输入结构**：约 16x16 网格。一条灰(5)水平全宽分隔线将网格分为上面板（背景绿(3)）和下面板（背景蓝(1)）。每个面板内有 2 个灰(5)一像素厚矩形边框（共 4 个框）。每个框的严格内部包含两种非背景、非灰的颜色（如红(2)和黄(4)，或品红(6)和橙(7)）的像素图案，以及若干栗(9)标记像素。不同框内的标记数量不同（范围 1-4）。框外、分隔线上无标记像素。生成约束：每个框内恰好有两种图案色，各框内的标记像素数在各示例间变化，保证同一示例中至少一个框为偶数标记、至少一个框为奇数标记。

**规则**：
1. 识别灰(5)水平分隔线，确定上面板（绿(3)背景）和下面板（蓝(1)背景）。
2. 识别每个灰(5)矩形边框及其严格内部区域，确定该框所属面板。
3. 统计每个框内栗(9)标记像素的数量 M。
4. 若 M 为偶数：将框内的两种图案色互换（色 A 的像素变色 B，色 B 的变色 A）。
5. 若 M 为奇数：统计框内两种图案色的像素数，将较多的那种色的所有像素重涂为该框所属面板的对侧面板色（上面板框用蓝(1)，下面板框用绿(3)）；较少的色保持不变。
6. 所有框内的栗(9)标记像素设为该框所在面板的背景色。
7. 框、分隔线、框外像素均不变。

**关键洞察**：标记计数的奇偶性构成条件分支——同一幅图中不同框走不同变换路径。偶数分支完全不需要面板信息（纯框内互换），奇数分支才需要面板归属来确定重涂目标色。必须对比包含不同奇偶组合的多个示例才能同时归纳出两条分支规则。

## 新题 6：角位 L 形补全三角后按最近归属裁剪并奇偶环纹填色

**组合逻辑**：[补全(complete)](创新：多个 L 形同时补全为三角，而非单个 L 扩展到更大画布) + [最近归属(nearest_ownership)](创新：归属区域由三角顶点定义而非角标记像素) + [奇偶距离决定填色(parity_distance_fill)](创新：环纹仅在三角轮廓内部绘制，而非全网格)

**来源原语**：角位边角(corner_piece)、三角轮廓(triangle_outline)、补全(complete)、补对角线边(fill_diagonal_side)、角位置对应(corner_correspond) ← e3f79277；角标记像素(corner_marker)、同心环(concentric_ring)、最近归属(nearest_ownership)、奇偶距离决定填色(parity_distance_fill) ← d22278a0；填充(fill) ← ce22a75a

**依赖链**：L 形角位 → 补对角线边得到三角轮廓 → 轮廓围成的区域定义该角的所有权范围 → 多个三角区域重叠处用最近归属分配 → 在归属确定的区域内按 Chebyshev 距离奇偶填色；删除补全则无三角区域，删除归属则重叠区无法着色，删除奇偶则区域内为纯色（丢失关键信息）

一句话总结：将各角落的 L 形补全为直角三角形轮廓，对三角内部像素按最近角顶点归属，再以 Chebyshev 距离奇偶交替填色与留空。

**输入结构**：约 15x15 网格，黑(0)背景。2-3 个不同角落各有一个一像素厚的彩色 L 形（每个 L 触碰其所在角的两条网格边缘，颜色互不相同，取自红(2)、蓝(1)、绿(3)等）。各 L 形的臂长不同（范围 4-7 像素）。L 形仅占据角落区域，互不接触。生成约束：各 L 形臂长选取使得补全后的三角形内部区域存在部分重叠（至少两个三角的填充区域有公共像素），但重叠区面积不超过任一三角面积的一半。

**规则**：
1. 对每个 L 形，确定其所在角落（左上/右上/左下/右下）和臂长 n。
2. 补全对角线边：连接 L 的两个自由端点，用该 L 的颜色画一条像素化的直线段（Bresenham 算法），形成完整直角三角形轮廓。
3. 确定每个三角形的内部填充区域：轮廓线围成的所有像素（含轮廓本身）。
4. 对网格中每个属于至少一个三角内部的像素，计算其到每个相关三角顶点（L 所在角落点）的欧氏距离平方。将该像素归属于距离最近的角；若距离相等（平局），该像素设为黑(0)背景。
5. 对已归属的像素，计算其到归属角的 Chebyshev 距离 d。若 d 为偶数，填该角 L 形的颜色；若 d 为奇数，填黑(0)。
6. 不属于任何三角内部的像素保持黑(0)。

**关键洞察**：L 形的补全不是最终目的（与参考题 e3f79277 不同），而是为了创建空间所有权区域。同一网格上多个三角相互竞争像素归属，归属边界不是预设的直线而是由三角顶点距离动态决定的。奇偶环纹填色进一步在每个归属区域内创建非平凡的纹理——整个输出是补全、归属、填色三层逻辑的交织结果。

## 新题 7：竖条高度排序编码循环移位量驱动区域颜色轮换

**组合逻辑**：[尺寸排序(size_ordering)](创新：排序排名不用于标记推进，而编码循环移位步长) + [环绕角度排序(angular_order_around_center) + 循环轮换(cyclic_shift)](已有：区域颜色循环) + [裁剪(crop)](创新：条形编码区在输出中被裁掉，仅保留变换后的主区域)

**依赖链**：标记段所在条的高度排名 → 排名值 = 循环移位步长 S → 区域按角度排序后颜色旋转 S 步 → 裁掉条形编码区；删除排名则 S 未知，删除角度排序则区域顺序不确定，删除裁剪则输出格式错误

**输入结构**：约 14x18 网格，黑(0)背景。网格纵向分为左右两部分：右侧约 4 列为"编码区"，由一条灰(5)全高竖直分隔线与左侧主区域隔开。主区域中央有一个黄(4)/橙(7)构成的十字或 T 形分隔结构，围绕分隔结构有 4-6 个单色 4-连通区域（每个区域颜色互不相同，取自蓝(1)、红(2)、绿(3)、品红(6)、栗(9)等）。编码区内有 3-5 根灰(5)一像素宽竖直条，底部对齐，高度互不相同（范围 3-9 像素）。其中恰好一根条的上半段或下半段被染为红(2)（标记段），其余条全为灰(5)。生成约束：各示例中标记段所在条的高度排名不同（即标记出现在不同高度的条上）。

**规则**：
1. 识别灰(5)竖直分隔线，左侧为主区域，右侧为编码区。
2. 在编码区中找到所有竖直条，按高度升序排列，排名从 1 开始。
3. 找到携带红(2)标记段的条，其排名即为循环移位步长 S。
4. 在主区域中，识别黄(4)/橙(7)分隔结构和围绕它的各色区域。
5. 计算每个区域的质心，以分隔结构质心为原点，按屏幕坐标系顺时针角度排序各区域。
6. 每个区域保持其像素位置不变，但接收角度序列中前 S 个位置的区域颜色：即区域 i 的新颜色 = 区域 (i - S) mod N 的原始颜色（N 为区域总数）。
7. 分隔结构不变。输出仅保留主区域（裁掉分隔线和编码区）。

**关键洞察**：编码区是一个独立的"控制面板"——竖条高度的排序关系编码了一个数值参数，而不是直接参与空间变换。标记段在条上的位置（上半/下半）不影响移位量（与参考题 48634b99 中半段位置保持的作用完全不同）。必须对比多个示例中标记所在条的排名与区域颜色旋转的步数，才能归纳出"排名=步长"这一关系。

## 新题 8：掩码解码筛选格元后叠印多色精灵体

5. 若两个合格格元相邻导致叠印区域在格线处冲突（不同精灵体副本的像素映射到同一位置），则距源格元 Manhattan 距离较大的副本优先（远处覆盖近处）。

**关键洞察**：掩码匹配在参考题 15113be4 中直接触发重涂色，但这里掩码匹配仅起筛选作用——决定哪些格元成为印章目标。印章内容来自网格中另一个格元的精灵体，而非指令区域本身。这构成"筛选器"与"内容源"分离的两阶段架构，两者缺一不可。

**输入结构**：约 16x14 网格，黑(0)背景。网格左侧（约第 1-2 列区域）有一根 3 像素的竖直红(2)标记条和一个相邻的绿(3)控制像素（控制像素在标记条中心的左侧或右侧）。网格主体中有 5-7 行各包含一对蓝(1)/青(8)控制像素（蓝在左、青在右），每对之间间隔相同（3-5 像素）。蓝-青之间的像素由品红(6)和黑(0)构成图案，部分行的图案段中混有 1-2 个橙(7)像素。其余行无控制像素对。标记条纵向位于网格的某处，其所在行范围覆盖部分带控制像素对的行。生成约束：标记条 + 控制像素可确定一个竖直射线方向（上或下）；射线从标记条中心出发沿确定方向能穿过至少 2 行但不超过全部含控制像素对的行；被射线穿过的各行段宽度相同。

**规则**：
1. 找到红(2)三像素竖直标记条和相邻的绿(3)控制像素。
2. 确定射线方向：控制像素在标记条中心的左侧 → 射线向右（但因为是竖直条，实际规则为：控制像素在标记条中心的上方 → 射线向下；控制像素在下方 → 射线向上）。
3. 从标记条中心像素沿射线方向作竖直半射线，直到网格边界。
4. 找到射线穿过的所有行（射线经过的行号集合）。
5. 在这些行中，筛选出包含蓝(1)/青(8)控制像素对的行。
6. 从上到下依次提取每个筛选行中蓝(1)与青(8)之间（不含控制像素）的像素段。
7. 将提取的段按行序堆叠为输出网格。
8. 在堆叠结果中，将所有橙(7)像素设为黑(0)。

**关键洞察**：射线在参考题 2f767503 中直接擦除目标对象，但这里射线的作用是"空间选择器"——决定哪些行的数据被采集。括号提取在参考题 505fff84 中无条件提取所有标记行，这里变为有条件的（仅射线命中行）。橙色像素在提取前看似图案的一部分，在堆叠后才被擦除——擦除时机（先提取后擦除 vs. 先擦除后提取）影响输出内容，需要从示例中推断正确顺序。
