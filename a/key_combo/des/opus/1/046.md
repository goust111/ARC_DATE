## 新题 1：箭头射线交叉点的跨度填充

**组合逻辑**：[朝向推断/dir_inference] → [射线延伸/ray_extend](创新：从箭头顶点向指向方向发射，非从外角发射到网格边缘) → [碰撞变色/collision_recolor](创新：交叉点标记而非弹丸命中) → [首尾跨度填充/span_fill_between](创新：在交叉点之间而非在原始标记之间填充)

**来源原语**：朝向推断、缺角指示方向(6e19193c)；射线延伸(e179c5f4, 6e19193c, 13713586)；碰撞变色规则(409aa875)；连线、同行列对齐、首尾跨度填充(ded97339)

**依赖链**：箭头缺角推断方向 → 方向决定射线路径 → 射线之间的空间交叉产生碰撞标记点 → 碰撞点的行列对齐关系决定跨度填充区域。碰撞点是射线交互的涌现产物，跨度填充作用于这些涌现的点而非输入中的原始对象。

从箭头精灵体发射方向射线，标记射线交叉点为栗(9)，再在同行或同列的交叉点之间填充灰(5)跨度线段。

**输入结构**：约 18x18 的黑(0)背景网格。散布 4~6 个橙(7)箭头精灵体，每个由 3 个像素组成、呈直角 L 形（占据 2x2 边界框中的三个格，缺失的那个角指示箭头朝向）。各箭头的朝向不全相同（上、下、左、右至少出现两种）。箭头之间互不相邻（边界框间距至少 2 格），且摆放位置保证至少存在 2 对射线会在网格内交叉。

**规则**：
1. 对每个箭头精灵体，找到其 2x2 边界框中缺失像素的位置；缺失角所在的方向即为箭头指向（例如右上角缺失则指向右上……但本题只使用四个正交方向：若缺失角在左上，箭头指向左上对角对应的正交分量中较长的一侧——具体地：缺失角行列偏移量为 (-1,-1) 对应上方，(+1,-1) 对应左方——实际规则：缺失角在左列则朝左，在右列则朝右，在上行则朝上，在下行则朝下；若缺失角同时在角落，取行方向）。简化规则：将 2x2 框中三个橙(7)像素的行坐标均值和列坐标均值与框中心比较，颜色重心偏移的反方向即为射线发射方向（即箭头从重心向缺口方向发射）。
2. 从箭头边界框在发射方向一侧的中点格出发，沿发射方向逐格延伸一条橙(7)射线，直到碰到网格边缘或另一条已存在的射线像素时停止（不含终止格）。
3. 所有射线绘制完毕后，检查所有射线像素：如果某个格子被两条不同箭头的射线同时经过（即两条射线路径重叠的像素），将该格重涂为栗(9)，标记为交叉点。
4. 对每一行，如果该行含有至少两个栗(9)交叉点，将最左交叉点到最右交叉点之间的所有非橙(7)、非栗(9)的格子填充为灰(5)。对每一列执行相同操作（最上到最下交叉点之间填充灰(5)）。灰(5)不覆盖已有的橙(7)或栗(9)。

**关键洞察**：跨度填充的锚点不是输入中的箭头，而是射线交叉产生的碰撞标记——这些标记的位置完全由箭头的方向和间距决定，需要先推断方向、再追踪射线、再检测交叉，才能确定填充区域。

## 新题 2：边缘矩形滑动留下面积分级的周期轨迹

**组合逻辑**：[接触边缘/touching_edge] → [滑动/slide + 滑至对侧/slide_to_opposite] → [面积分类/area_classification](创新：面积决定轨迹颜色和周期填充密度，而非决定对象自身颜色) → [循环填充/periodic_fill + 周期相位对齐/periodic_phase_align](创新：填充对象为轨迹条纹而非V形扩展) → [按距离排序绘制/draw_ordered_by_distance](创新：原用于投射到边缘的距离排序，此处用于轨迹重叠时的优先级)

**来源原语**：边缘矩形、接触边缘、滑至对侧边缘、轨迹条纹(b25e450b)；面积分类、面积决定颜色(d2abd087)；循环填充、周期相位对齐、对角线格点(c1990cce)；按距离排序绘制(13713586)

**依赖链**：边缘接触确定滑动方向 → 滑动产生矩形轨迹区域 → 矩形面积同时决定两件事：轨迹基底颜色（面积分类）和对角格点周期（面积映射到周期参数）→ 轨迹重叠时，距离出发边更远的矩形（即滑动距离更长的）优先绘制其轨迹。面积既决定外观又决定优先级之外的周期结构，是多路耦合。

将接触网格边缘的黑色矩形同时滑向对侧边缘，每个矩形留下的轨迹条纹的颜色和内部对角格点密度由矩形面积决定，重叠区域按滑动距离排序覆盖。

**输入结构**：约 16x16 的灰(5)背景网格。3~5 个黑(0)实心矩形，每个恰好接触网格的一条外边缘（上、下、左或右），不同矩形可接触不同边缘。矩形面积各不相同，范围在 2~12 像素之间（宽或高至少为 1，另一维至少为 2）。矩形之间不相邻，保证同方向滑动路径上不存在另一个矩形阻挡。

**规则**：
1. 确定每个黑(0)矩形接触的外边缘，该矩形向对侧边缘方向滑动（接触上边缘→向下，接触左边缘→向右，以此类推）。
2. 计算每个矩形的面积（像素数）。面积 <= 4 的矩形归为"小型"，面积 > 4 的归为"大型"。
3. 所有矩形同时滑动。滑动后，在矩形原位置到新位置之间的整个条纹区域绘制轨迹：小型矩形的轨迹基底色为橙(7)，大型矩形的轨迹基底色为青(8)。
4. 在每条轨迹内部叠加对角格点图案：沿 NW-SE 方向，每隔 K 格绘制一个前景点（颜色为蓝(1)）。K 值由面积决定：小型 K=2（每隔 2 格），大型 K=3（每隔 3 格）。格点相位以轨迹条纹左上角为原点，满足 (row + col) mod K == 0 的格子绘制蓝(1)点。
5. 矩形在对侧边缘的最终位置保持黑(0)。
6. 若两条轨迹区域重叠，以矩形距其出发边更远者（即从出发边到矩形中心的距离更大，等价于滑动路程更长的）的轨迹覆盖在上层。距离相同时，面积更大的覆盖。

**关键洞察**：矩形面积不仅决定轨迹颜色（二分类），还决定内部周期格点的间距，产生视觉上截然不同的条纹纹理；需要对比多个示例才能将面积阈值和周期参数同时归纳出来。

## 新题 3：去遮挡恢复模板后印章补全部分副本

**组合逻辑**：[擦除/erase](识别并移除遮挡矩形) → [对称补全/symmetry_completion + 镜像/mirror](创新：恢复被遮挡破坏的模板，而非恢复最终输出) → [模板与副本匹配/template_copy_match + 补全/completion](创新：模板不是输入直接给出的，而是经对称恢复推断出的) → [印章覆盖/stamp](创新：补全部分副本时使用遮挡矩形的颜色而非模板原色)

**来源原语**：擦除、填充矩形、遮挡、镜像、对称补全、去遮挡后镜像还原(3345333e)；模板精灵体、不完整副本、缺失掩码、模板与副本匹配、非标记精确匹配、补全、印章覆盖(bb52a14b)

**依赖链**：遮挡矩形同时承担两个角色——它破坏了主模板的完整性，它的颜色也是后续补全的渲染色。必须先识别遮挡矩形 → 擦除它以暴露被遮挡的主图案 → 利用左右对称性补全主图案得到完整模板 → 用完整模板在网格其余位置匹配部分副本 → 将部分副本中缺失的像素用遮挡矩形的颜色填入。遮挡矩形的颜色信息必须在擦除前记住，否则后续无法确定补全颜色。

擦除覆盖在主图案上的实心矩形，通过左右镜像对称恢复完整模板，然后用该模板找到网格中的部分副本并以遮挡矩形的颜色补全缺失像素。

**输入结构**：约 15x20 的黑(0)背景网格。网格上半区中央有一个蓝(1)的单色图案（4-连通，约 8~15 像素，具有严格的左右镜像对称性，但被遮挡后对称性被破坏）。一个红(2)实心矩形（约 3x2 到 4x3）部分覆盖在蓝(1)图案上，遮住了图案的一侧若干像素。网格下半区散布 2~3 个蓝(1)的部分副本——每个副本与完整模板的部分像素位置精确匹配（相对于各自边界框左上角），但各缺失了不同的若干像素（缺失位置为黑(0)）。部分副本之间互不重叠，与主图案区域也不重叠。生成约束：遮挡矩形覆盖的蓝(1)像素恰好可以通过左右对称从未被覆盖的一侧推断出来。

**规则**：
1. 在网格中找到唯一的红(2)实心矩形连通分量，记录其颜色为红(2)，然后将其所有像素擦除为黑(0)。
2. 对擦除后残留的蓝(1)图案，检测其左右镜像对称轴（该轴通过图案边界框的水平中心线）。将图案中每个蓝(1)像素关于该对称轴做镜像，若镜像位置为黑(0)则填入蓝(1)。完成后得到完整的对称模板。
3. 提取完整模板的边界框作为匹配窗口（大小为 H x W）。在网格中逐像素滑动该窗口，检查每个位置：窗口内所有蓝(1)像素是否都在网格中对应位置也为蓝(1)（允许网格中该位置为黑(0)，即"缺失"，但不允许为其他非黑非蓝颜色）。若窗口内模板的蓝(1)像素中至少 40% 在网格中匹配为蓝(1)，且没有任何冲突色，则认定为部分副本。排除模板自身所在位置。
4. 对每个匹配到的部分副本，将模板中蓝(1)但副本中为黑(0)的位置填入红(2)（遮挡矩形的颜色）。

**关键洞察**：遮挡矩形扮演双重角色——它既是需要移除的噪声（破坏模板对称性），又是补全部分副本的颜色来源；求解者必须在擦除前记住遮挡矩形的颜色，否则无法确定补全时该用什么颜色。

## 新题 4：图例解码指导跨颜色连线

**组合逻辑**：[解码/decoding + 编码映射/encoding_map](读取图例中的颜色配对关系) → [忽略干扰项/ignore_distractors](创新：过滤工作区中不在图例中的颜色) → [连线/connect + 同行列对齐/row_col_aligned + 首尾跨度填充/span_fill_between](创新：连线颜色不等于端点颜色，而是由图例映射决定)

**来源原语**：图例精灵、分隔行、位置对应、图例色替换标记(20fb2937)；解码、编码映射、颜色索引模板(65b59efc)；忽略干扰项(c35c1b4c, bb52a14b)；连线、同行列对齐、首尾跨度填充(ded97339)

**依赖链**：图例定义了"标记色→连线色"的映射表 → 该映射决定哪些工作区像素是有效标记（过滤干扰项）→ 有效标记按颜色分组后在同行同列间连线 → 连线使用的不是标记自身颜色而是图例映射的目标色。图例解码是后续一切操作的前提，且连线颜色的非直觉映射使得必须对比多个示例才能归纳。

读取顶部图例中的颜色映射，在底部工作区中将同色标记沿共享行或列连线，连线颜色为图例中该标记色对应的映射色。

**输入结构**：约 14x14 的黑(0)背景网格。顶部 3 行为图例区，包含 2~3 组颜色配对：每组由一个 1x1 的标记色像素和紧邻其右的一个 1x1 映射色像素组成，各组之间间隔至少 2 列黑(0)。第 4 行为灰(5)分隔行（整行灰色）。第 5 行起为工作区。工作区中散布若干标记像素，颜色为图例中出现过的标记色（每种标记色出现 2~5 个像素）。工作区中还散布 2~3 个干扰像素，其颜色不在图例的标记色集合中。工作区中同种标记色的像素至少有一对共享同一行或同一列。生成约束：不同颜色标记的连线区域不重叠。

**规则**：
1. 读取图例区（分隔行上方）：每组连续的两个非黑像素中，左边是标记色，右边是映射色。记录映射关系（如：红(2)→绿(3) 表示工作区中红色标记的连线应画为绿色）。
2. 在工作区（分隔行下方）中，忽略所有颜色不属于图例标记色集合的像素（视为黑(0)背景）。
3. 对每种标记色，找出工作区中该色的所有像素。对每一行，若该行有至少两个该色像素，将最左到最右之间的黑(0)格填充为图例中对应的映射色。对每一列，若该列有至少两个该色像素，将最上到最下之间的黑(0)格填充为映射色。填充不覆盖任何已有非黑像素。
4. 图例区和分隔行在输出中移除，输出仅包含工作区部分。

**关键洞察**：连线颜色与端点标记颜色不同——红(2)标记之间的连线可能是绿(3)——这个映射关系编码在图例中，仅凭工作区无法推断，必须先解码图例。

## 新题 5：颜色编码三种反对角线变换

**组合逻辑**：[同反对角线/same_antidiagonal + 对角线段/diagonal_segment] → [颜色决定投影深度/color_det_depth](创新：颜色不再决定投影深度，而是决定变换类型——前进、后退或分裂) → [平移绘制/translate_draw + 擦除/erase + 长度递增/length_increment](创新：三种变换共享同一空间的反对角线，而非单一变换)

**来源原语**：对角线段、同反对角线、平移绘制、擦除、长度递增(50c07299)；颜色决定投影深度(e39e9282)；碰撞变色规则(409aa875)

**依赖链**：颜色分类决定每段对角线段的变换类型（三选一）→ 每种变换有不同的位移和长度变化规则 → 所有线段同时在反对角线上执行各自的变换 → 若两段变换后的新位置重叠，重叠格涂为栗(9)。颜色是变换选择的唯一键，删除颜色分类环节则无法确定任何线段该做什么。

**输入结构**：约 15x15 的黑(0)背景网格。3~5 段一像素宽的对角线段分布在不同的反对角线上（每段占据一条从左下到右上的反对角线的连续若干格）。线段有三种颜色：绿(3)、红(2)、蓝(1)。每种颜色至少出现一段。每段长度在 2~5 像素之间。各段之间不共享反对角线，且各段变换后的目标位置不超出网格（生成约束）。

**规则**：
1. 绿(3)线段执行"前进"：擦除当前位置，将线段沿其反对角线向右上方平移，新线段起点紧接原线段右上端点的下一格，新长度 = 原长度 + 1。新线段画为绿(3)。
2. 红(2)线段执行"后退"：擦除当前位置，将线段沿其反对角线向左下方平移，新线段终点紧接原线段左下端点的前一格，新长度 = 原长度 - 1。若原长度为 1，则整段消失（仅擦除，不绘制）。新线段画为红(2)。
3. 蓝(1)线段执行"分裂"：擦除当前位置。在原线段右上端点的下一格起画一段长度为 floor(原长度/2) 的蓝(1)线段（沿反对角线向右上延伸）；在原线段左下端点的前一格起画一段长度为 ceil(原长度/2) 的蓝(1)线段（沿反对角线向左下延伸）。若原长度为 1，仅向右上画 1 格。
4. 所有变换视为同时发生。若任何两段新线段（含分裂产生的子线段）在同一格重叠，该格涂为栗(9)，覆盖原色。

**关键洞察**：三种颜色编码了三种完全不同的空间变换类型；仅看一种颜色的线段行为不足以推断其他颜色的规则，必须观察不同颜色的示例才能归纳出完整的颜色-变换映射。

## 新题 7：双面板叠加后按来源分类决定镜像

**组合逻辑**：[双面板对齐/dual_panel_alignment + 透明叠加/transparent_overlay](合并两面板) → [连通分量/connected_component + 计数/counting](创新：对叠加后的结果做分量分析，而非直接输出叠加结果) → [面积分类/area_classification](创新：面积分类决定后续操作类型而非颜色) → [镜像/mirror + 对称补全/symmetry_completion](创新：仅对小分量做镜像，且镜像可能与大分量冲突时大分量优先)

**输入结构**：约 11x23 的黑(0)背景网格。第 11 行（0-indexed 第 10 行，即正中行）为品红(6)分隔行（整行品红）。分隔行将网格分为上下各 10x23 的面板。上面板有若干橙(7)前景像素组成 2~4 个 4-连通图形，下面板有若干蓝(1)前景像素组成 2~4 个 4-连通图形。两面板的图形位置经过设计，使得叠加后部分原本分开的图形会因空间邻接而合并为更大的连通分量，部分则保持独立。

**规则**：
1. 移除品红(6)分隔行。将上下两面板逐像素对齐（上面板第 r 行对应下面板第 r 行）。

5. 面积 <= 6 的分量标记为"小型"，对其做左右镜像：将该分量的每个像素关于输出网格垂直中轴线做镜像。镜像位置若为黑(0)则填入红(2)；若该位置已有绿(3)（属于大型分量），则不覆盖——大型分量优先。
6. 小型分量的原始绿(3)像素保留不变。

**关键洞察**：某个面板中一个小图形在叠加后可能因为与另一面板的相邻图形合并而变成大型分量，从而失去被镜像的资格——叠加不仅改变外观，还改变了后续操作的分类判定。

## 新题 8：形状分类决定投射行为与弹丸碰撞

线段向边缘实心条投射彩色条纹（按距离排序覆盖），三角精灵体发射弹丸，弹丸命中的条纹整体被重涂为栗(9)。

**规则**：
1. 识别蓝(1)实心边缘条及其所在边（如左边缘）。所有非背景、非边缘条的前景对象均平行于边缘条。

4. 三角体发射：每个三角体沿其缺失角方向（指向边缘条）发射一颗弹丸，弹丸从三角体顶点出发，沿水平方向前进恰好 5 格（若超出网格则在网格边缘停止）。弹丸落点标记为黑(0)。
5. 碰撞检测：若弹丸落点位于某条线段投射的条纹区域内，则该条纹整体重涂为栗(9)（含该条纹所有像素，不论是否被后续条纹覆盖——即恢复该条纹的完整范围并涂栗(9)，覆盖之上的一切）。
6. 三角体自身像素保持品红(6)不变。边缘条保持蓝(1)不变。

**关键洞察**：线段和三角体在输入中视觉相似（都是小型前景对象），但它们的行为完全不同——线段产生被动的投射条纹，三角体产生主动的弹丸；两者的交互决定了最终哪些条纹被摧毁。

**输入结构**：约 16x16 的网格，大部分为黑(0)，散布若干橙(7)像素构成不规则的墙壁/障碍（4-连通，形成分隔但不完全封闭的结构）。网格中存在一块较大的全黑矩形空间（两侧均 >= 4），是最大的无障碍矩形区域。该矩形内部有 1~3 个单像素标记，颜色各不相同（从红(2)、绿(3)、蓝(1)中选取）。矩形外部也有 1~2 个同色标记（干扰项）。矩形外部的橙(7)墙壁像素和黑(0)像素构成二值图案。

**规则**：
1. 在整个网格中搜索面积最大的、两侧均 >= 4 的全黑(0)轴对齐矩形。若有多个面积相同的候选，选左上角行号最小的；行号也相同时选列号最小的。
2. 画布内操作——对画布（最大矩形）内部的每个非黑标记像素，以该像素为中心画一个 3x3 的十字图案（中心格 + 上下左右各一格），颜色为该标记的颜色。超出画布边界的部分不绘制。十字图案覆盖画布内已有的任何内容。
3. 画布内填充——画布内所有仍为黑(0)的格子接受周期对角格点填充：以画布左上角为原点，满足 (row + col) mod 3 == 0 的格子填充为灰(5)，其余黑(0)格保持不变。灰(5)不覆盖十字图案。
4. 画布外操作——画布外部的所有格子做颜色反转：橙(7)变为黑(0)，黑(0)变为橙(7)。画布外的标记像素也被反转为黑(0)（等同于被忽略）。
5. 画布边界上的像素属于画布内部。

**关键洞察**：最大空矩形既是印章操作的作用域又是周期填充的容器，同时也是画布内外两种截然不同变换（印章+填充 vs 颜色反转）的分界线——矩形外的标记虽然颜色相同但因不在画布内而被完全忽略。
