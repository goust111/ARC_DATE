## 新题 1：障碍绕行路径合并决定直方图排名

**组合逻辑**：[生长/grow + 遇障碍则绕行/detour_on_obstacle](路径生成) → [连通检测/connected_component_detection + 计数/counting](创新：路径合并改变计数) → [柱状填充/histogram_fill + 排序/sort]

**来源原语**：生长/grow、寻路/pathfinding、遇障碍则绕行/detour_on_obstacle、起点像素/start_pixel、障碍像素/blocker_pixel、逐步推进/stepwise_advance（← #10 d9f24cd1）；连通检测/connected_component_detection、计数/counting、排序/sort、柱状填充/histogram_fill、按数量降序/sort_by_count_desc、靠端对齐/end_aligned_layout（← #2 2753e76c）

**依赖链**：路径生长中的障碍绕行使相邻列的同色路径可能合并为一个连通体，这种涌现性合并改变了每种颜色的连通体计数，而计数直接决定直方图排名与行宽。删掉路径生长则无法知道哪些路径合并；删掉连通检测则无法从路径图到直方图；删掉排序则输出顺序不确定。

从底行多色起点向上生长路径（遇灰障碍右绕），统计每色合并后的独立路径数，降序建右对齐直方图。

**输入结构**：
- 黑(0)背景网格，约 15x20（15 列 20 行）
- 底行（第 19 行）分布 3~4 种颜色的起点像素（如红(2)、蓝(1)、绿(3)、橙(7)），每种颜色 2~4 个起点，各起点互不相邻（至少隔 1 列）
- 网格内部（第 1~18 行、第 1~13 列范围内）散布灰(5)障碍像素；障碍不在底行、顶行和最左/最右列
- 生成约束：灰障碍的布局保证至少一种颜色的两条路径因绕行而在某行占据相邻列（从而 4-连通合并为一个连通体），同时另有至少一种颜色的所有路径始终保持独立；各颜色最终的连通体数量两两不同

**规则**：
1. 对底行每个非黑像素，从该位置开始向上逐步生长路径，路径颜色与起点一致
2. 每步优先向上移动一格（行号减 1）；若正上方格子为灰(5)，改为向右移动一格（列号加 1），仍着起点颜色；若右方格子也为灰(5)或超出网格右边界，路径终止
3. 路径到达第 0 行时终止；路径经过的所有格子着起点颜色
4. 所有路径绘制完毕后，对每种起点颜色，用 4-连通性统计该颜色像素组成的独立连通体数量
5. 将各颜色按连通体数量降序排列
6. 输出一个新网格：高度 = 颜色种数，宽度 = 最大连通体数量；第 k 行对应第 k 名颜色，左侧黑(0)填充、右侧用该颜色填充该颜色的连通体数量个像素（右对齐直方图）

**关键洞察**：直方图的排名不由起点数量决定，而由路径合并后的连通体数量决定。灰障碍的绕行效应使"路径数"和"连通体数"产生不可预测的差异——必须完整模拟路径生长才能知道哪些路径合并了。

## 新题 2：双空间推理——压缩网格对齐与原始网格障碍检验

**组合逻辑**：[下采样/downsample + 奇偶索引分离](在压缩空间确定对角对齐) ↔ [连线/connect + 无障碍通路](在原始空间验证通路) → 输出在压缩空间

**来源原语**：下采样/downsample、奇偶索引分离/even_odd_index_separation、保留偶索引交叉/keep_even_crossings、分隔行列/separator_rows_and_columns（← #18 68b67ca3）；连线/connect、中心对角对齐/center_diagonal_alignment、无障碍通路/unobstructed_path（← #1 55059096）

**依赖链**：压缩后的坐标决定哪些同色像素处于同一 45 度对角线上，但连线能否绘制需回到原始网格检查——分隔行列的交叉点中可能藏有灰障碍，这些障碍在压缩后消失却能阻断连线。两个空间的信息互为必要条件：压缩空间提供"谁对齐"，原始空间提供"能否连"。

压缩稀疏网格后找同色对角对齐的像素对，仅当它们在原始网格中对角路径上无灰障碍时才画红连线。

**输入结构**：
- 黑(0)背景网格，偶数行偶数列（如 14x14）
- 偶数行偶数列的交叉格点（如 (0,0), (0,2), (2,0), (2,2) ...）为"数据位"，可放置彩色像素（如绿(3)、蓝(1)），也可为黑(0)空位
- 奇数行和奇数列为分隔行列，大部分为黑(0)
- 部分奇数行与奇数列的交叉点处放置灰(5)障碍像素（即 (1,1), (1,3), (3,1) 等位置）
- 生成约束：至少存在 2 对同色像素在压缩后处于同一 45 度对角线上；其中至少 1 对在原始网格对角路径上存在灰障碍（不应连线），至少 1 对路径畅通（应连线）

**规则**：
1. 压缩网格：仅保留偶数行偶数列交叉处的像素，移除所有奇数行和奇数列，得到 (H/2) x (W/2) 的压缩网格
2. 在压缩网格中，枚举所有同色像素对 (A, B)，其中 A 和 B 满足 |row_A - row_B| = |col_A - col_B|（处于同一 45 度对角线）且 A、B 之间无其他同色像素（只连相邻的对角邻居）
3. 对每个候选对，回到原始网格：将压缩坐标 (r, c) 映射回原始坐标 (2r, 2c)，沿 A 到 B 的 45 度对角线逐格检查每个中间格（步长为 (sign(dr), sign(dc))），包括途经的奇数行奇数列交叉点
4. 若路径上所有中间格（不含端点 A、B 自身）均为黑(0)背景，则在压缩网格上将 A、B 之间对角线上的所有中间格涂红(2)
5. 若路径上存在任何灰(5)像素，不绘制该连线
6. 输出为压缩后的网格，包含原数据像素及红连线；灰障碍和分隔行列均不出现在输出中

**关键洞察**：对角对齐在压缩空间判定，通路畅通性在原始空间验证——灰障碍在压缩后消失，但它们的存在与否决定了连线能否绘制。求解者必须在两个空间之间来回推理。

## 新题 3：等差矩形笔画补全后洪水填充封闭围合区域

**组合逻辑**：[补全/completion + 等差递推/arithmetic_progression](推断缺失笔画的位置与边型) → [flood_fill + 内外分区/inside_outside_partition](创新：笔画的边组合决定封闭性，封闭性决定是否填充)

**来源原语**：补全/completion、等差序列/arithmetic_sequence、矩形边框笔画/rect_side_stroke、等差递推/arithmetic_progression、画布裁切可见/canvas_clips_visible（← #4 f8c80d96）；flood_fill、内外分区/inside_outside_partition、墙壁边界/wall_boundary（← #9 7491f3cf）

**依赖链**：等差递推确定每个缺失笔画的 bbox 位置和尺寸 → 所有笔画共享相同的"边组合"（如只画顶边+右边+底边的三面 U 形），补全后每个笔画的形态固定 → 部分笔画靠近画布边缘、被裁切后残余边恰好与画布边界共同围合出封闭区域，而居中的笔画因缺边保持开口 → 封闭性决定是否被填充。补全与填充通过笔画形态和画布边界的交互深度耦合。

补全等差递增的矩形边框笔画序列，从四角灰色洪水填充，被笔画与画布边界共同围合的区域涂红。

**输入结构**：
- 黑(0)背景网格，约 20x20
- 若干黄(4)矩形边框笔画：每个笔画仅绘制矩形四边中的固定 2~3 条边（如所有笔画都只画顶边+右边+底边，形成右开口的 U 形；或只画左边+底边，形成 L 形），全部笔画的边组合相同
- 各笔画的 bbox 共享同一中心，bbox 宽和高分别按固定步长等差递增（如宽每次 +3，高每次 +3）
- 序列中缺失 1~2 个成员（其位置可从等差模式推断）
- 最外层 1~2 个笔画的部分边被画布边界裁切（仅可见部分出现在网格中）
- 生成约束：笔画的边组合与画布裁切的共同作用使得至少一个笔画（结合画布边界）围合出封闭区域，至少一个笔画有通向网格角落的开口（不封闭）

**规则**：
1. 识别所有已有黄(4)笔画的 bbox（通过分析每个笔画的行列范围），按 bbox 面积排序，推断等差步长（宽步长 dW 和高步长 dH）
2. 确定序列的 bbox 中心（所有笔画共享），向内外两个方向延伸序列，直到新增笔画的裁切可见部分为零像素
3. 每个补全的笔画绘制与已有笔画相同的边组合，颜色黄(4)，超出画布的部分裁切不画
4. 所有笔画绘制完毕后，从网格的四个角点 (0,0)、(0,W-1)、(H-1,0)、(H-1,W-1) 分别开始 4-连通洪水填充灰(5)，黄(4)像素作为墙壁阻挡扩散
5. 填充完成后，仍为黑(0)的区域（未被灰(5)触达）涂红(2)——这些是被黄笔画与画布边界共同围合的封闭内部
6. 黄(4)笔画像素保持不变

**关键洞察**：笔画只画部分边，所以封闭性不由笔画自身决定——靠近画布边缘的笔画可能因画布边界替代了缺失边而意外围合出封闭区域，而居中的小笔画因缺边而始终开口。必须完整补全序列并结合画布边界才能判断哪些区域被封闭。

## 新题 4：重力沉降压缩符号后投射 L 形射线

**组合逻辑**：[压缩/compress + 重力下落/gravity_drop + 标记指示方向](确定沉降后位置) → [射线延伸/ray_extend + 投射到最近边界](依赖沉降后位置确定方向)

**来源原语**：压缩/compress、空心符号/hollow_symbol、边缘标记线/edge_marker_line、栅格对齐/grid_aligned、标记指示方向/marker_indicates_dir、重力下落/gravity_drop（← #11 afe3afe9）；射线延伸/ray_extend、标记像素/marker_pixel、投射到最近边界/projection_to_nearest_edge（← #15 705a3229）

**依赖链**：边缘标记线决定重力方向 → 压缩后的像素沿重力方向沉降堆叠 → 沉降后每个像素到四条网格边的距离全部改变 → 最近边界方向（决定 L 形射线的两个臂朝向）完全依赖沉降后位置。同一组符号更换标记线位置，射线图案完全不同。

将粗格点上的空心 3x3 符号压缩为单像素，按边缘标记线指示的重力方向沉降堆叠，每个像素向最近的水平边和最近的垂直边各投射一条同色射线。

**输入结构**：
- 黑(0)背景网格，约 15x15
- 内含 4~6 个空心 3x3 符号（每个符号由一种独立颜色绘制，如红(2)、绿(3)、蓝(1)、橙(7)等；空心指中心像素为背景色，八个边界位中至少六个有色），分布在步长为 3 的粗格点上（如左上角在 (0,0), (0,3), (3,0) 等），符号之间有空行/列间隔
- 一条满跨的品红(6)线沿网格某一条边绘制（顶边/底边/左边/右边之一），宽度 1 像素
- 生成约束：符号的分布使得压缩+沉降后至少有 2 个像素的"最近水平边"方向或"最近垂直边"方向与仅压缩（不沉降）时不同

**规则**：
1. 将每个 3x3 空心符号替换为其颜色的一个像素，放置在该符号在粗格点中的逻辑坐标上；移除所有不含符号的格点行和格点列，得到紧凑网格（品红标记线不参与压缩，在压缩后移除）
2. 根据品红(6)标记线在原始网格中的位置确定重力方向：顶边 → 向右，右边 → 向下，底边 → 向左，左边 → 向上（顺时针映射）
3. 沿重力方向沉降所有像素：保持每个像素在垂直于重力方向的轴上的坐标不变，沿重力方向移动直到碰到紧凑网格的该方向边界或另一个已沉降的像素。处理顺序：沿重力方向距目标边界最近的像素先处理
4. 对沉降后的每个像素 P 位于 (r, c)，设紧凑网格尺寸为 H x W：
   - 计算到上边距离 d_up = r，到下边距离 d_down = H-1-r，到左边距离 d_left = c，到右边距离 d_right = W-1-c
   - 沿列方向（上或下）向 d_up 和 d_down 中较小者的方向画射线，从 P 到该边界（含边界格），颜色与 P 相同；若 d_up = d_down 则选上方
   - 沿行方向（左或右）向 d_left 和 d_right 中较小者的方向画射线，从 P 到该边界（含边界格），颜色与 P 相同；若 d_left = d_right 则选左方
5. 多条射线交叉时：后绘制的覆盖先绘制的。绘制顺序：按像素在沉降后网格中从左到右、从上到下的顺序
6. 像素本身的颜色保留（不被射线覆盖）

**关键洞察**：重力方向改变每个像素的最终位置，从而改变"最近边界"的判定和射线朝向——同一组符号仅改变标记线位置（换一条边），所有射线的方向和长度都可能完全改变。重力与射线通过位置深度耦合。

## 新题 5：对象中心投影标记驱动折线路径角对选择

**组合逻辑**：[投影/project + 中心对齐/center_alignment](确定路径列) ↔ [draw_line + 中心偏移选角/center_offset_selects_corner](创新：源对象的水平偏侧同时决定角对方向)

**来源原语**：投影/project、前景对象/foreground_object、边行/edge_row、中心对齐/center_alignment、对象中心在边行标/center_marked_edge_row（← #13 54d82841）；draw_line、标记像素/marker_pixel、折线路径/folded_path、列对齐/column_alignment、中心偏移选角/center_offset_selects_corner（← #16 7ec998c9）

**依赖链**：每个对象的 bbox 水平中心确定投影标记列（路径的"脊柱"）→ 同一对象的水平中心相对于网格中心列的偏侧决定折线路径连接哪对角落。同一个空间属性（对象水平位置）同时控制路径的"位于哪列"和"朝向哪对角"，构成单源双用的紧耦合。

将多个前景对象的水平中心投影到底行作为标记，每个标记列画一条蓝色折线路径，路径连接的角对由源对象在网格左半或右半决定。

**输入结构**：
- 黑(0)背景网格，约 12x19（12 行 19 列，宽度为奇数以确保唯一中心列）
- 3~4 个单色 4-连通前景对象（每个 3~8 像素，不规则形状，不同示例中形状不同），各用不同颜色（如红(2)、绿(3)、橙(7)、栗(9)），互不相邻，分布在网格上半区（前 8 行内）
- 底行（第 11 行）初始为全黑(0)
- 生成约束：无两个对象的 bbox 水平中心列相同；所有对象的 bbox 中心列均不等于网格中心列 (W-1)/2 = 9；至少一个对象在网格左半（中心列 < 9），至少一个在右半（中心列 > 9）

**规则**：
1. 对每个前景对象，计算其 bbox 水平中心列：center_col = floor((min_col + max_col) / 2)
2. 在底行（第 11 行）的 center_col 位置放置该对象颜色的标记像素
3. 对每个标记，用蓝(1)绘制该标记列（center_col）从第 0 行到第 11 行的垂直线段
4. 判断该对象的 center_col 与网格中心列 grid_center = 9 的关系：
   - 若 center_col < grid_center（对象在左半）：沿第 0 行从列 0 向右画蓝(1)水平线到 center_col（含），沿第 11 行从 center_col 向右画蓝(1)水平线到列 W-1（含）
   - 若 center_col > grid_center（对象在右半）：沿第 0 行从 center_col 向右画蓝(1)水平线到列 W-1（含），沿第 11 行从列 0 向右画蓝(1)水平线到 center_col（含）
5. 前景对象像素和底行标记像素保持原色不变（蓝线不覆盖它们）
6. 多条蓝色路径重叠的格子仍为蓝(1)

**关键洞察**：对象的水平中心位置既决定折线路径的列位（投影），又决定路径连接哪对角落（偏侧选角）——左半对象的路径从左上角出发经该列达到右下角，右半对象反之。看单个对象可能误以为角对选择与颜色或形状有关，需要对比多个不同偏侧的对象才能归纳出位置决定方向的规则。

## 新题 6：图例印章覆盖后按模板面积全局排名重涂内部

**组合逻辑**：[印章覆盖/stamp_overlay + 控制色查找图例/control_selects_legend](局部：确定每个槽位放什么模板) → [面积比较/area_comparison + 面积排名映射色/area_rank_maps_color + 填充/fill](全局：所有已印模板的面积排名决定内部颜色)

**来源原语**：印章覆盖/stamp_overlay、图例模板/legend_template、插槽阵列/slot_array、控制像素/control_pixel、颜色映射模板/color_template_map、控制色查找图例/control_selects_legend（← #19 c64f1187）；重涂色/recolor、填充/fill、空心矩形/hollow_rect、面积比较/area_comparison、面积排名映射色/area_rank_maps_color（← #3 694f12f3）

**依赖链**：控制像素颜色查找图例确定每个槽位的模板形状（局部决策）→ 印入后需统计所有已印模板的内部面积并全局排名 → 排名结果反过来决定每个模板的内部填充色。局部的"放什么"与全局的"排几名"交织：必须完成所有印章操作才能进行排名，而排名结果又修改了每个印章的内部。

按控制像素颜色查找图例中不同大小的空心矩形模板印入槽位，再按各模板内部面积的全局排名给内部涂色。

**输入结构**：
- 黑(0)背景网格，约 20x16
- 上部图例区（前 6 行）：水平排列 3 组"标记+模板"，组间隔 1 列黑背景
  - 每组包含：一个彩色标记像素（位于模板左上角的上一行、左一列位置）和一个灰(5)绘制的空心矩形模板
  - 三个模板大小不同：3x3 空心矩形（内部面积 1x1=1）、3x5 空心矩形（内部面积 1x3=3）、5x5 空心矩形（内部面积 3x3=9），均用灰(5)画边框
  - 三个标记颜色互不相同（如红(2)、绿(3)、橙(7)）
- 下部插槽区（第 8 行起）：水平排列 3~5 个插槽，每个插槽是 5x5 的灰(5)填充方块，槽间隔 1 列黑背景
  - 部分插槽内含一个彩色控制像素（颜色匹配某个图例标记色，位置在插槽内部任意一格），其余插槽无控制像素（纯灰）
- 生成约束：3 种控制色各至少出现一次；含控制像素的插槽数量 >= 3

**规则**：
1. 读取图例：每个彩色标记色映射到其对应的空心矩形模板形状（3x3、3x5 或 5x5）
2. 对每个含控制像素的插槽：根据控制像素颜色查找对应模板，将模板居中放入插槽区域（模板的 bbox 中心对齐插槽的中心，若不能完美居中则偏左偏上），模板边框颜色改为控制像素的颜色（替代灰(5)）。不含控制像素的插槽在输出中变为黑(0)背景
3. 所有模板印入完毕后，计算每个已印模板的内部面积（边框内部的非边框像素数量）
4. 按内部面积从小到大排名（生成约束保证面积两两不同）。若两个模板大小相同（来自同一图例模板），按插槽从左到右的位置排名
5. 按排名填充内部颜色：排名第 1（最小）→ 内部填蓝(1)；排名第 2 → 内部填红(2)；排名第 3 → 内部填绿(3)；若有更多则排名第 4 → 填黄(4)，依此类推
6. 模板边框保持控制像素的颜色不变

**关键洞察**：每个模板的内部颜色不由其自身的控制像素颜色决定，而由它在所有已印模板中的面积排名决定——同一种控制色在不同题目实例中可能获得不同的内部填色，因为排名取决于当前实例中出现了哪些模板的组合。需要对比多个示例才能发现"面积排名决定内部色"这一隐蔽规则。

## 新题 7：笛卡尔积格点补全后边界凸缺互补适配

**组合逻辑**：[笛卡尔积缺位填充/cartesian_product_gap_fill + 格点对齐](确定新精灵体位置) ↔ [对称补全/symmetric_complete + 对侧互补/opposite_side_complement](创新：新精灵体的边界凸缺必须适配所有相邻精灵体)

**来源原语**：笛卡尔积缺位填充/cartesian_product_gap_fill、同形精灵体/identical_sprite、行列格点/row_column_lattice、格点对齐/lattice_alignment（← #20 5b526a93）；对称补全/symmetric_complete、凸起/tab、缺口/notch、边界/boundary、对侧互补/opposite_side_complement、跨行列投射/cross_span_projection（← #12 8dab14c2）

**依赖链**：笛卡尔积规则确定哪些格点位置需要填充新精灵体 → 每个新精灵体的邻居集合取决于其格点位置 → 每个新精灵体的边界凸缺配置必须与其所有已有邻居的对面边界互补。这是同时约束满足问题：填充位置决定邻居关系，邻居关系决定凸缺修改，且一个新精灵体可能同时被多个方向的邻居约束。

在行列格点上补全缺位精灵体，每个新精灵体的凸缺边界必须与所有相邻精灵体的对面边界互补。

**输入结构**：
- 黑(0)背景网格，约 18x18
- 单一前景色（如绿(3)）形成若干同形 4-连通精灵体，排列在行列格点上（行间距和列间距各固定，如每 5 行、每 5 列一个精灵体起始位置）
- 每个精灵体的基础形状为一个近似矩形的 4-连通区域（约 3x3 至 4x4 bbox），且部分边界像素向外凸出 1 格（凸起/tab）或向内缺少 1 格（缺口/notch）：
  - 凸起：精灵体边界上一个像素向外突出 1 格（该像素只有 1 个同色 4-邻居）
  - 缺口：精灵体边界上一个位置向内凹陷 1 格（该空位有 3 个同色 4-邻居）
- 所有精灵体共享相同的基础形状和凸缺模式
- 格点不完整：已占据的格点位置包含至少一个完整行和至少一个完整列，其余若干位置为空
- 生成约束：每个待填位置至少与一个已有精灵体在格点上水平或垂直相邻；相邻精灵体之间的间距足够大（>= 1 列/行黑背景间隔），使凸起不会触碰到邻居

**规则**：
1. 识别所有已有精灵体的基础形状掩码（含凸缺），确定格点行起始集合和列起始集合
2. 对每个未占据的格点位置（行起始与列起始的笛卡尔积中缺少精灵体的位置），放置一个青(8)底色的精灵体副本（基础形状与原精灵体相同）
3. 对每个新放置的青(8)精灵体，检查其在格点上的每个 4-连通方向（上/下/左/右）是否存在已有的绿(3)精灵体邻居：
   - 对每对相邻的（新青精灵体, 已有绿精灵体），查看它们面对面的边界轮廓（沿共享边平行方向逐像素比较）
   - 在绿精灵体的对面边界上有凸起的位置，青精灵体必须有缺口：移除青精灵体该位置的像素（变为黑(0)背景）
   - 在绿精灵体的对面边界上有缺口的位置，青精灵体必须有凸起：在青精灵体该位置添加一个青(8)像素
   - 在绿精灵体的对面边界上平齐（无凸无缺）的位置，青精灵体保持原状
4. 若一个青精灵体有多个方向的已有邻居，各方向的凸缺修改独立应用（不同方向修改不同边，不会冲突）
5. 若两个相邻的待填位置都是新青精灵体：按从上到下、从左到右的顺序依次确定，先确定的视为"已有"参与后续的互补判定
6. 已有的绿(3)精灵体保持不变

**关键洞察**：笛卡尔积规则决定"在哪填"，但填入后每个新精灵体的具体形状不再是原始模板的简单复制——它的凸缺边界被周围已有精灵体的对面边界反向约束。同一模板在不同格点位置因邻居不同而呈现不同的边界轮廓，使得"复制"和"适配"深度耦合。
