## 新题 1：视线配对矩形的间距调相棋盘填充

**组合逻辑**：[视线匹配](创新：从路径-标记配对改为矩形-矩形配对) + [边框与内部分离](已有) + [行列奇偶决定填充](创新：奇偶相位由间距距离调制) + [擦除](已有，用于移除未配对矩形)

**来源原语**：视线匹配 ← #2(696d4842)；边框与内部分离、行列奇偶决定填充 ← #10(ba9d41b8)；填充矩形 ← #8(36fdfd69)/#13(470c91de)；擦除 ← #11(9b365c51)/#18(6d0160f0)

**依赖链**：视线匹配确定矩形配对关系 → 配对间距测量得到距离 G → G 调制棋盘奇偶相位 → 未配对矩形被擦除。删除视线匹配则无法知道谁和谁配对；删除间距测量则无法确定棋盘相位；删除棋盘填充则无法产生内部图案变化。

用一句话概括：通过行列视线将矩形两两配对，在每个配对矩形的内部填充棋盘格，棋盘的奇偶相位由配对间距的奇偶性决定，未配对矩形则被清除。

**输入结构**：
- 黑(0)背景，约 20x20 网格。
- 4-8 个单色填充矩形，每个至少 4x4，各自颜色互不相同（均为非黑、非红的 ARC 颜色）。矩形互不重叠、互不接触。
- 每个矩形的边框上恰好有 1 个红(2)标记像素（替换了该位置原本的矩形颜色）。
- 矩形两两配对：每对中，两个矩形的红标记像素之间存在唯一的清晰水平或垂直视线（视线上所有中间格均为背景(0)）。
- 生成约束：每个红标记只与恰好一个其他红标记互相可见，形成完美配对（无歧义）。可能存在 0-2 个不参与任何配对的孤立矩形（它们的红标记的视线方向上不可见任何其他红标记）。

**规则**：
1. 配对识别：两个矩形配对当且仅当它们的红边框标记之间有一条仅穿过背景(0)格的水平或垂直直线段（不含两端红标记本身）。
2. 对每一对，测量间距 G = 两个红标记之间沿视线方向的背景格数量（不含两端标记格本身）。
3. 对每个已配对的矩形，保留其 1 像素宽的边框不变。
4. 填充内部（边框严格内侧的所有格）为棋盘图案：对内部格在内部区域内的局部坐标 (r, c)（以内部左上角为 (0,0)），若 (r + c + G) mod 2 == 0，则设为背景(0)；否则保留矩形原色。
5. 移除所有红标记像素（设为该矩形的原色，恢复边框完整性）。
6. 将所有未配对的矩形整体擦除（所有格设为背景(0)）。

**关键洞察**：间距 G 的奇偶性决定棋盘相位翻转——同一对中的两个矩形共享同一个 G 值，因此它们的棋盘图案在全局坐标系下可能同相或反相，取决于各自内部左上角坐标与 G 的联合奇偶。这一规则只有通过对比不同间距的配对才能归纳出来。

## 新题 2：射线命中处的旋转模板印章

**组合逻辑**：[二值掩码](已有) → [射线延伸](创新：射线方向决定模板旋转角度) → [印章覆盖](创新：印章为解码后的旋转二值模板，非固定 3x3 块)

**来源原语**：射线延伸、投射 ← #14(ecdecbb3)；印章覆盖、空位接受印章 ← #5(e5062a87)/#17(f0df5ff0)；二值掩码 ← #12(80af3007)；标记像素 ← 多题

**依赖链**：解码二值模板 → 从标记像素发射四方向射线 → 射线命中障碍物 → 射线方向决定模板旋转角度 → 在命中点以旋转后模板印章填充。删除模板解码则无印章内容；删除射线则无命中点；删除旋转映射则印章形状不确定。

用一句话概括：从标记像素向四个正交方向发射射线，在每个命中障碍物处，以射线方向所对应的旋转角度将二值模板印章到命中点。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 网格左上角区域有一个 3x3 的灰(5)/黑(0)格子簇，编码一个二值模板：灰(5) = 开，黑(0) = 关。模板非旋转对称（旋转 90/180/270 度后与原图不同），有 3-5 个"开"格。
- 2-4 个蓝(1)标记像素分散在网格中，互不相邻，不与模板簇相邻。
- 若干绿(3)障碍像素或短障碍段（2-3 像素的正交连通段）分散在网格中。
- 生成约束：每个标记至少在 2 个正交方向上可见障碍物（中间无其他非背景像素阻挡）；各次印章的 3x3 足迹互不重叠；模板簇与所有印章足迹不重叠。

**规则**：
1. 读取 3x3 模板：以灰(5)格子簇的包围框左上角为模板 (0,0)，灰 = 1，黑 = 0。模板的默认朝向定义为"射线向上"时使用的朝向。
2. 对每个蓝(1)标记像素，依次向上、右、下、左四个方向发射射线。
3. 每条射线沿该方向穿过背景(0)格，遇到首个非背景格（障碍物、模板簇边缘、或其他标记）或网格边界时停止。若射线在标记的相邻格即遇到非背景格或网格边界（距离为 0），则该方向不产生动作。若射线到达网格边界前未遇到非背景格，也不产生动作。
4. 当射线命中一个非背景格（命中格坐标为 (hr, hc)）时，根据射线方向确定模板旋转角度：向上 → 0 度；向右 → 顺时针 90 度；向下 → 180 度；向左 → 顺时针 270 度。
5. 将旋转后的 3x3 模板以命中格 (hr, hc) 为中心放置。对模板中每个"开"位置对应的网格格：若该格为背景(0)，涂为红(2)；若为非背景，保持不变。
6. 绘制射线轨迹：将标记与命中格之间（不含两端点）的所有背景(0)格涂为蓝(1)。
7. 处理顺序：标记按从上到下、从左到右排序；每个标记内按上、右、下、左顺序处理。后处理的射线轨迹和印章可覆盖先前绘制的射线轨迹格，但不覆盖先前印章的红(2)格。
8. 灰(5)模板簇、蓝(1)标记像素、绿(3)障碍像素均保留不变。

**关键洞察**：模板是非旋转对称的，因此不同射线方向在命中点产生不同形状的印章。求解者必须同时掌握模板解码、射线传播和方向-旋转映射三个机制才能确定每个印章的形态。

## 新题 3：装配序号驱动的错切拼合

**组合逻辑**：[连接配对](已有) + [拼接](已有) + [错切](创新：错切幅度由装配序号决定，非由墙壁方向决定) + [序列索引](创新：装配中的时序索引驱动几何变形)

**来源原语**：连接配对、拼接、逐步拼合 ← #6(cbebaa4b)；错切、逐行偏移 ← #7(9f41bd9c)；序列索引 ← #15(a5f85a15)

**依赖链**：识别锚点精灵 → 扫描未配对连接器确定装配顺序 → 装配序号 k 决定错切幅度 → 错切变形后再平移拼合。删除连接配对则无法确定装配顺序；删除序号-错切映射则无法确定变形幅度；删除拼合则碎片无法归位。

用一句话概括：通过红色连接器逐步将精灵体拼合到锚点周围，每个精灵体在拼合前按其装配序号进行递增的水平错切变形。

**输入结构**：
- 黑(0)背景，约 22x22 网格。
- 一个锚点精灵：包含一个 3x3 黄(4)实心块，外围有若干该精灵自身颜色（如蓝(1)）的像素，边缘上有 2-4 个红(2)连接器像素。
- 3-4 个额外精灵体，每个是一个紧凑的单色 4-连通形状（单一非红、非黄颜色，4-8 个非红像素），边缘上有 1-2 个红(2)连接器像素。不同精灵体颜色互不相同。
- 所有精灵体在输入中互不接触，分散在网格各处。
- 生成约束：装配顺序无歧义——在每一步中，恰好只有一个未拼合精灵体能够将其某个红连接器与当前组装体上的某个未配对红连接器重合（通过平移），且平移后不产生非红有色像素的冲突。扫描顺序为：对组装体上的未配对红连接器按从上到下、从左到右排序，对每个依次检查所有未拼合精灵体。

**规则**：
1. 锚点精灵（含黄(4)块的那个）保持原位，初始化组装体。设序号计数器 k = 1。
2. 扫描组装体上所有未配对的红(2)像素（从上到下、从左到右）。对每个未配对红像素，检查是否存在某个未拼合精灵体，使得将该精灵体平移到其某个红连接器与该组装体红像素重合后，不产生非红有色像素重叠。
3. 取扫描中找到的第一个有效配对。在拼合前，对该精灵体施加水平错切：以精灵体包围框的第 0 行为基准，第 i 行向右偏移 (k - 1) * i 个像素（即第 0 行不动，第 1 行右移 k-1 格，第 2 行右移 2*(k-1) 格，依此类推）。错切后超出网格范围的像素被裁掉。
4. 将错切后的精灵体平移放置，使连接器重合。重合的两个红像素合并为一个红像素。k 递增。
5. 重复步骤 2-4，直到所有精灵体均已拼合或无法再拼合。
6. 拼合完成后，移除所有红(2)连接器像素（设为背景(0)）。

**关键洞察**：错切幅度随装配序号递增——后拼合的精灵体变形更严重。由于装配序号取决于连接器的拓扑可达性（哪些连接器先暴露），几何变形实际上由结构连通性间接决定，而非空间位置。需要对比多个示例中不同装配顺序导致的不同错切结果才能发现此规则。

## 新题 4：镜像色带与间距编码尾端重涂

**组合逻辑**：[镜像](已有) + [间距编码尾长](创新：间距不再编码路径尾长，而是编码色带重涂深度) + [重涂色](已有) + [标记像素](已有，但角色从路径端点匹配变为色带修改器)

**来源原语**：镜像、色带行、色带翻转到对侧 ← #3(496994bd)；间距编码尾长、视线匹配 ← #2(696d4842)；重涂色 ← 多题；标记像素 ← 多题

**依赖链**：镜像色带到底部 → 测量标记到最近色带的距离 d → 确定"远色带"（较远的那一条） → 在远色带的内侧 d 行涂标记颜色。删除镜像则无底部色带可操作；删除距离测量则无法确定重涂深度；删除远近判定则不知道涂哪条色带。

用一句话概括：将顶部色带镜像到底部，然后根据间隙中标记像素到最近色带的距离，将该距离行数的远端色带内侧行重涂为标记颜色。

**输入结构**：
- 黑(0)背景，约 15x20 网格（宽大于高更易观察）。
- 顶部 2-4 行为连续的满宽单色色带（如蓝(1)），占据网格最上方的完整行。
- 色带下方为若干行纯背景(0)行（间隙），间隙高度至少 6 行。
- 间隙中散布 1-3 个标记像素，每个标记为不同颜色（如绿(3)、橙(7)、品红(6)），各自是孤立单像素。
- 底部行在输入中全为背景(0)（镜像色带尚未生成）。
- 生成约束：每个标记到最近色带的距离 d 不超过色带行数（保证重涂不会超出色带范围）；不同标记的颜色互不相同；不同标记到最近色带的距离互不相同。

**规则**：
1. 将顶部色带镜像到网格底部：色带的第 1 行映射到网格最后一行，色带的第 2 行映射到倒数第 2 行，依此类推。原顶部色带保持不变，中间间隙保持不变。
2. 对每个标记像素（位于行 r_m），计算 d_top = r_m 到顶部色带底边的行距（r_m 行号减去色带最下一行的行号），d_bot = 底部镜像色带顶边到 r_m 的行距（镜像色带最上一行的行号减去 r_m 行号）。
3. 令 d = min(d_top, d_bot)。"远色带"为距离较大的那条色带。若 d_top == d_bot，则远色带为底部镜像色带。
4. 在远色带中，将最靠近间隙的 d 行重涂为该标记的颜色。具体地：若远色带为顶部色带，则涂其最下方 d 行；若远色带为底部镜像色带，则涂其最上方 d 行。
5. 若两个标记要求重涂同一色带的重叠行区域，则 d 值较小（距最近色带更近）的标记优先。在优先标记已涂的行上，低优先级标记的重涂不生效。
6. 所有标记像素在最终输出中被移除（设为背景(0)）。

**关键洞察**：标记的位置同时编码了两个信息：（1）距离最近色带的距离决定重涂深度；（2）距离远近的比较决定重涂发生在哪条色带上。将标记上移一行可能同时改变目标色带和重涂深度，形成非直觉的双重编码。此规则仅凭单个示例无法确定——需要对比标记在不同位置时输出的变化才能归纳。

## 新题 5：对角线交替位的图例链式替换

**组合逻辑**：[奇偶交替涂色](创新：交替位不再涂固定色，而是经图例链处理) + [逐行顺序链式替换](创新：链式替换仅作用于交替位，非全局) + [对角线段](已有) + [双列图例](已有)

**来源原语**：奇偶交替涂色、对角线段、序列索引 ← #15(a5f85a15)；逐行顺序链式替换、双列图例、图例行序决定替换 ← #19(e4888269)

**依赖链**：识别对角线段并标记奇偶位 → 读取图例链 → 仅对奇数位像素执行链式替换 → 偶数位像素不变。删除奇偶识别则不知对哪些像素施加替换；删除图例链则不知替换成什么颜色；删除对角线段识别则不知交替从哪里重新开始。

用一句话概括：在每条右下对角线段中，仅对奇数索引位置的像素执行图例定义的链式颜色替换，偶数索引位置的像素保持原色。

**输入结构**：
- 黑(0)背景，约 14x14 网格。
- 左上角有一个双列图例块：2-4 行，每行左列一个颜色、右列一个颜色，图例块内部全部填满（无背景格）。图例与主场景之间至少有 2 行和 2 列的背景间隔。图例中使用的颜色均来自 ARC 调色板。
- 主场景中，2-3 种不同颜色的前景像素组成若干右下对角线段（每段是沿 (r+1, c+1) 方向连续的同色非背景像素的极大序列）。每段至少 3 个像素。对角线段可以有不同颜色。
- 生成约束：图例链非平凡——至少一种出现在对角线段中的颜色也出现在图例的左列中；至少存在一个级联替换（某行的右列颜色是更下方某行的左列颜色），使得单次链式处理会引发多步替换。

**规则**：
1. 识别主场景（不含图例区域）中所有极大右下对角线段。一个段是满足以下条件的极大像素序列：每个像素与前一个像素的位置关系为行+1、列+1，且颜色相同、非背景。
2. 在每个段内，从左上端点开始对像素编号，索引从 0 起。
3. 对每个奇数索引的像素（索引 1、3、5、...），执行图例链式替换：从图例第一行到最后一行逐行扫描，若该像素当前颜色等于该行左列颜色，则替换为右列颜色，然后继续向下扫描剩余行（颜色可能被多次改写）。
4. 偶数索引的像素（索引 0、2、4、...）保持原色不变。
5. 图例块本身保持不变。背景像素不变。

**关键洞察**：链式替换是顺序敏感的（同一颜色可能被连续的图例行多次改写），且仅作用于交替位置。这意味着一段对角线中相邻两个像素——一个偶数位、一个奇数位——即使初始颜色相同，最终颜色也可能不同。求解者必须同时掌握交替选择规则和级联替换机制才能确定输出。

## 新题 6：射线测距的不等臂十字补全

**组合逻辑**：[补全](创新：十字臂长不再由最大红跨度推断，而是逐方向射线测距) + [射线延伸](创新：射线用于测量而非连接) + [碰撞停止](创新：碰撞点同时定义臂端和接触标记) + [贯穿条](已有，作为障碍物)

**依赖链**：识别十字中心（红标记） → 从中心向四个正交方向射线 → 每条射线到达贯穿条或网格边缘时停止，距离定义该方向的臂长 → 用臂色填充各臂 → 在臂端放置接触标记。删除射线测距则无法确定各臂长度；删除贯穿条则所有臂等长（退化为简单十字）；删除接触标记则输出不完整。

用一句话概括：在红标记位置补全十字图案，每条臂的长度由该方向射线到最近灰色贯穿条或网格边缘的距离独立决定，臂端放置橙色接触标记。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 2-4 条贯穿条：全宽水平灰(5)条或全高垂直灰(5)条（1 像素厚），将网格分为若干区域。可以有水平和垂直混合。
- 2-4 个红(2)标记像素分布在不同区域中（不在灰条上）。
- 若干蓝(1)像素散布在标记附近，作为基底/噪声像素需保留。
- 生成约束：任意两个标记不共享行或列；每个标记在至少 3 个正交方向上可见灰条（第四个方向可以是网格边缘）；不同标记的十字臂互不交叉。

**规则**：
1. 对每个红(2)标记像素位于 (r, c)，向上、下、左、右四个方向发射射线。
2. 每条射线穿过背景(0)格和蓝(1)格。射线遇到灰(5)格或到达网格边界（最后一个有效行/列）时停止。
3. 该方向的臂长 = 从标记（不含）到停止点（不含灰条格或网格边界外）的格数。若射线在标记的紧邻格即为灰条或网格边界（臂长为 0），则该方向不画臂。
4. 绘制臂：从标记向外沿该方向的每个格，若该格为背景(0)，涂为绿(3)；若为蓝(1)，保持蓝(1)不变。
5. 在每条臂的最末格（距标记最远的臂格）放置橙(7)接触标记，覆盖该格原有颜色。若臂长为 0 则不放。
6. 红(2)标记像素本身涂为绿(3)。
7. 灰(5)贯穿条、不在臂路径上的蓝(1)像素、背景(0)均保持不变。
8. 处理顺序：标记按从上到下、从左到右排序。若两个标记的臂在某格交叉（理论上不应发生因为生成约束保证不交叉，但作为安全规则），后处理的臂覆盖先处理的臂格，但橙(7)接触标记不被非接触标记格覆盖。

**关键洞察**：与标准固定半径十字不同，每条臂的长度由最近障碍物的距离独立决定。一个靠近某侧灰条但远离其他灰条的标记会产生高度不对称的十字。求解者必须意识到臂长是逐方向测量的，而非全局统一。

## 新题 7：克罗内克展开后的角位编码对角平移

**组合逻辑**：[克罗内克自积](已有) + [像素放大](已有) + [角位指示方向](创新：从矩形角控制像素改为掩码角活跃格) + [对角固定步移](创新：平移向量由掩码自身的结构属性编码，非外部控制像素)

**来源原语**：克罗内克自积、像素放大、二值掩码、编码映射 ← #12(80af3007)；对角固定步移、角位指示方向、控制像素 ← #13(470c91de)

**依赖链**：解码 3x3 掩码 → 识别唯一活跃角格确定对角方向 → 执行克罗内克自积展开为 9x9 → 将整个 9x9 图案沿该对角方向平移 1 格。删除掩码解码则无法得到展开内容和方向信息；删除克罗内克展开则仅有 3x3 无法体现自相似结构；删除角位方向判定则不知往哪个方向移。

用一句话概括：将 9x9 块编码的 3x3 二值掩码进行克罗内克自积展开，然后将结果沿掩码中唯一活跃角格指示的对角方向平移一格。

**输入结构**：
- 黑(0)背景，约 15x15 网格。
- 网格中偏中心位置有一个 9x9 区域，由前景色（如蓝(1)）和背景(0)格组成。该区域按 3x3 块瓦片划分为 9 个 3x3 子块，每个子块要么全部前景色（"开"），要么全部背景色（"关"），编码一个 3x3 二值掩码 M。
- 掩码 M 恰好有 1 个角位格为活跃（即 M 的 (0,0)、(0,2)、(2,0)、(2,2) 四个格中恰好有一个值为 1），总活跃格数为 3-5 个。掩码不具有旋转对称性。
- 生成约束：9x9 区域的位置使得克罗内克展开结果加上 1 格对角平移后仍完全在网格范围内。

**规则**：
1. 定位 9x9 前景包围框，将其解码为 3x3 二值掩码 M：M[i][j] = 1 当且仅当第 (i,j) 个 3x3 子块全部为前景色，否则 M[i][j] = 0。
2. 识别 M 中唯一的活跃角格位置，确定对角方向：(0,0) → 左上；(0,2) → 右上；(2,0) → 左下；(2,2) → 右下。
3. 构建 9x9 克罗内克积 K = M 张量积 M：K[3i+a][3j+b] = M[i][j] AND M[a][b]。
4. 清除原 9x9 区域为背景(0)。
5. 将 K 放置到网格上，相对于原 9x9 区域左上角沿步骤 2 确定的对角方向偏移 1 格。K 中值为 1 的格涂前景色，值为 0 的格保持背景(0)。
6. 超出网格边界的部分裁掉（不环绕）。

**关键洞察**：掩码同时编码了两种信息——自相似展开的内容和平移方向向量。求解者必须从同一输入中做出两种不同的解读：一次作为展开模板，一次作为方向编码器。

## 新题 8：装配序号对应调色板重涂

**组合逻辑**：[拼接](已有) + [连接配对](已有) + [顺序一一对应](创新：对应关系从空间排列改为时序装配顺序) + [调色板列](创新：调色板给出的颜色按装配序号而非空间位置分配)

**来源原语**：拼接、连接配对、逐步拼合 ← #6(cbebaa4b)；顺序一一对应、调色板列、按列段分组匹配 ← #11(9b365c51)；重涂色 ← 多题

**依赖链**：读取调色板颜色序列 → 通过连接器配对确定装配顺序 → 第 k 个拼合的精灵体涂第 k 个调色板颜色 → 连接器和调色板最终被清除。删除调色板则不知涂什么颜色；删除连接器配对则无法确定装配顺序（也就无法确定颜色对应）；删除重涂则精灵体保持原色（失去调色板的意义）。

用一句话概括：通过连接器逐步将精灵体拼合到锚点上，每个精灵体被重涂为调色板中与其装配序号对应的颜色。

**输入结构**：
- 黑(0)背景，约 20x22 网格。
- 顶部 1-2 行为调色板带：3-5 个单像素宽的满高彩色列（每列单色，各列颜色互不相同，均为非黑、非红、非灰的 ARC 颜色），相邻调色板列之间间隔 1 列背景(0)。
- 调色板带下方（间隔至少 2 行背景）：一个锚点精灵，包含一个 2x2 黄(4)实心块及其他灰(5)像素，边缘有红(2)连接器像素。
- 3-5 个额外精灵体，每个为紧凑的单色灰(5)形状（4-8 个非红像素，4-连通），边缘有 1-2 个红(2)连接器像素。所有非锚点精灵体的非红像素均为灰(5)。
- 精灵体在输入中互不接触，分散在调色板带下方。
- 生成约束：装配顺序无歧义——每一步恰好只有一个未拼合精灵体可与组装体上的某个未配对红连接器成功配对（扫描组装体未配对连接器从上到下、从左到右；对每个依次检查未拼合精灵体）。调色板列数 = 额外精灵体数。

**规则**：
1. 读取调色板：扫描顶部调色板带从左到右，记录每个非背景色列的颜色，得到有序序列 P[1], P[2], ..., P[n]。
2. 初始化组装体为锚点精灵（黄(4)块和灰(5)像素保持原色）。设序号 k = 1。
3. 扫描组装体上未配对的红(2)连接器（从上到下、从左到右）。对每个未配对连接器，检查是否存在某个未拼合精灵体，使得平移该精灵体令其某个红连接器与该组装体连接器重合后，不产生非红有色像素的位置冲突。
4. 取第一个有效配对。将该精灵体的所有灰(5)像素重涂为 P[k]，然后平移放置使连接器重合。重合的红像素合并为一个。k 递增。
5. 重复步骤 3-4，直到所有精灵体拼合完毕。
6. 擦除所有红(2)连接器像素（设为背景(0)）。
7. 擦除调色板带（所有调色板列像素设为背景(0)）。

**关键洞察**：调色板的从左到右顺序对应的不是精灵体的空间位置，而是装配时序——一种时间到颜色的映射。由于装配顺序取决于连接器的拓扑可达性，求解者必须模拟完整的拼合过程才能知道每个精灵体最终被涂成什么颜色。

- 在除标记瓦片和模板瓦片之外的非空瓦片中，恰好有一个瓦片的二值掩码（前景/背景的开关模式）与模板瓦片相同。这是"目标瓦片"。目标瓦片的颜色与模板瓦片不同。
- 生成约束：掩码匹配唯一（仅有一个其他瓦片匹配模板掩码）。模板瓦片不是标记瓦片本身。

7. 其余瓦片（包括模板瓦片）保持不变。分隔线保持不变。

**关键洞察**：标记像素是一个指针（其局部坐标选择模板），模板的形状是一个地址（掩码匹配确定目的地）。两种编码机制缺一不可——坐标编码告诉你"哪个是模板"，形状匹配告诉你"模板去哪里"。

- 左上角有一个双列图例块（2-3 行），与主场景之间用背景隔开。图例颜色来自 ARC 调色板。至少存在一个级联替换（某行的右列颜色等于更下方某行的左列颜色）。
- 1-2 个孤立的彩色单像素（起始标记），其颜色出现在图例的左列中。每个起始标记恰好与一个灰(5)路径格正交相邻。
- 灰(5)路径结构：一个连通的、1 像素宽的正交路径（无分支），沿路径有非背景/非灰边界格或网格边缘作为墙壁。
- 生成约束：对起始色反复应用图例链至少能产生 3 种不同颜色后才到达不动点或循环；路径长度至少 10 格，足以展示颜色模式和至少 2 次碰撞转向。

**规则**：
1. 读取图例：从上到下记录每行的 (左列颜色, 右列颜色) 对，得到有序替换列表。
2. 对每个起始标记（位于 (r, c)，颜色为 C_0），确定初始方向：起始标记恰好与一个灰(5)路径格正交相邻，粒子从标记向该路径格方向移动。
3. 定义颜色序列：C_0 为第 0 步颜色。从 C_k 得到 C_{k+1} 的方法：对 C_k 执行图例链式替换——从图例第一行到最后一行逐行扫描，若 C_k 等于该行左列颜色，则替换为右列颜色，继续向下扫描（颜色可能被多次改写）。最终结果为 C_{k+1}。若整个链没有任何匹配（C_k 不等于任何行的左列颜色），则颜色序列终止。
4. 粒子进入路径。在第 k 步（从 k=0 开始），将当前格涂为 C_k（覆盖灰(5)）。然后沿当前方向移动到下一格。
5. 碰撞处理：若下一格为非背景、非灰格（墙壁）或为网格边界外，则发生碰撞。碰撞时，先将当前格涂为 C_k，然后转向 90 度。转向方向交替：第 1 次碰撞 → 左转（逆时针），第 2 次 → 右转（顺时针），第 3 次 → 左转，依此类推。
6. 若计划转向的方向也被阻挡（该方向的格为非背景、非灰，或超出网格），粒子停止。
7. 若颜色序列终止（步骤 3 中链式替换无匹配），粒子立即停止，不再涂色。
8. 图例块保持不变。起始标记像素被消耗（设为背景(0)）。未被粒子涂色的灰(5)路径格保持灰色。
9. 若有多个起始标记，按从上到下、从左到右的顺序依次处理各粒子。后处理的粒子涂色可覆盖先前粒子的涂色。

**关键洞察**：颜色循环不是从输入中直接读取的——它是通过对起始色反复应用图例链计算出来的。一个包含级联替换的图例（如第 1 行 A→B，第 2 行 B→C）在单次链式处理中会产生 A→C 的效果，使得颜色序列 A, C, ... 并非从任何单行图例直接可见。求解者必须同时模拟路径行为和颜色生成过程。
