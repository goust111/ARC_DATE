## 新题 1：象限感知反射印章

**组合逻辑**：[separator_cross + quadrant](来自 2dc579da) → [stamp + sprite + marker_selects_slot](来自 363442ee，创新：槽位变为象限，选择条件变为标记是否存在) → [mirror / axial_symmetry](来自 c9e6f938，创新：反射方向由象限相对位置决定而非全局水平翻转)

**来源原语**：separator_cross、quadrant、marker_quadrant_retained（2dc579da）；stamp、sprite、slot、marker_pixel、partition、marker_selects_slot_for_sprite（363442ee）；mirror、axial_symmetry（c9e6f938）

**依赖链**：分隔十字将网格划分为四个象限 → 标记像素的有无决定哪些象限接收印章（条件判断） → 目标象限相对于源象限的几何位置决定印章的反射类型（空间关系驱动操作变体）。去掉十字则象限不确定，去掉标记则不知道印到哪里，去掉反射规则则印章方向错误。

将一个精灵体按象限相对位置做相应反射后印入每个含标记的目标象限。

**输入结构**：约 15x15 网格，背景黑(0)。灰(5) 构成一条完整行和一条完整列的分隔十字，将网格分为四个大小相等的矩形象限。其中一个象限包含一个蓝(1) 单色 4-连通小图形（3~6 像素，形状不规则，无对称性要求），称为源精灵。其余三个象限中，部分象限包含恰好一个红(2) 标记像素（位置任意但不贴邻分隔线），部分象限为纯背景。生成约束：源精灵的边界框完全落在源象限内部（不触及分隔线）；各示例中源象限位置不固定，精灵形状各异；至少有一个示例中三个目标象限全有标记，至少有一个示例中仅一个目标象限有标记。

**规则**：
1. 识别分隔十字（唯一同时构成一条完整行和一条完整列的颜色）。
2. 确定源象限：包含多像素蓝(1) 图形的那个象限。记录源精灵的形状及其边界框左上角相对于源象限内部区域左上角的偏移 (dr, dc)，以及边界框尺寸 (h, w)。设象限内部区域高 H、宽 W。
3. 对其余三个象限逐一判断：若含红(2) 标记像素则为目标象限，否则跳过。
4. 对每个目标象限，根据其与源象限的相对位置确定反射方式：
   - 同行不同列（水平相邻）：将源精灵左右镜像，放置偏移为 (dr, W - dc - w)。
   - 同列不同行（垂直相邻）：将源精灵上下镜像，放置偏移为 (H - dr - h, dc)。
   - 对角（不同行不同列）：将源精灵上下 + 左右镜像（等效 180 度旋转），放置偏移为 (H - dr - h, W - dc - w)。
5. 印入的精灵使用蓝(1)，标记像素保留红(2)（若精灵像素与标记重叠，标记优先）。
6. 分隔十字、源精灵、无标记象限均保持不变。

**关键洞察**：反射类型没有显式标注——必须从目标象限相对于源象限的行列关系推断出水平镜像、垂直镜像或 180 度旋转，单个示例可能只展示其中一两种，需对比多个示例才能归纳完整规则。

## 新题 2：格子完整性门控面积重涂

**组合逻辑**：[lattice_frame + enclosed_bg + flood_fill + intact_broken_differ](来自 83302e8f) → [connected_component + area_ranking + area_determines_color + recolor](来自 e8593010，创新：面积分级的对象不是前景分量而是格子单元内的嵌入图形，且仅在通过完整性测试的单元中生效) → [erase](来自 3391f8c0，创新：擦除条件由格子结构完整性决定)

**来源原语**：lattice_frame、enclosed_bg、flood_fill、intact_broken_differ、containment（83302e8f）；connected_component、area_ranking、area_determines_color、recolor（e8593010）；counting（b0c4d837）；erase（3391f8c0）

**依赖链**：格子完整性分类将每个单元标记为完整或缺损 → 完整单元中的图形进入面积分级重涂流程 → 缺损单元中的图形被擦除。完整性测试是面积重涂的前置门控：去掉完整性判断则不知道对哪些图形做面积分析，去掉面积分级则完整单元内的图形颜色不确定，去掉擦除则缺损单元的输出不正确。

根据格子单元的结构完整性决定内部图形的命运：完整单元中的图形按面积重涂，缺损单元中的图形被清除。

**输入结构**：约 14x14 网格，背景黑(0)。灰(5) 形成近似规则的矩形格子框架（水平和垂直条各 1 像素宽，间距约 3~4 像素），但部分条上有单像素缺口（缺口处为黑(0)）。每个格子单元内部可能放置一个单色 4-连通小图形（2~5 像素，颜色取自 {蓝(1), 红(2), 绿(3), 黄(4)} 中的一种，不同单元可用不同颜色），也可能为空。生成约束：至少 3 个完整单元含图形，至少 2 个缺损单元含图形，至少 1 个完整单元为空；不同示例中缺口位置和图形面积分布不同。

**规则**：
1. 识别灰(5) 格子框架。对网格中所有黑(0) 4-连通区域做洪泛标记。
2. 对每个黑色区域判断完整性：若区域面积等于其含边界框面积（即区域恰好是一个实心矩形），则该区域所在单元为"完整"；否则（缺口导致多个单元的背景连通）该区域覆盖的所有单元为"缺损"。
3. 对完整单元内的每个非灰非黑 4-连通图形，按面积重涂：面积 = 2 → 红(2)，面积 = 3 → 蓝(1)，面积 = 4 → 绿(3)，面积 = 5 → 黄(4)。图形原色被替换。
4. 对缺损单元内的所有非灰非黑像素，设为黑(0)（擦除）。
5. 空的完整单元保持黑(0)。灰(5) 格子框架像素保持不变。

**关键洞察**：格子的结构完整性不仅分类区域（如参考题 83302e8f），还充当后续操作的门控条件——同样面积的图形，在完整单元中被重涂为特定颜色，在缺损单元中则直接消失；必须对比多个示例才能同时归纳出完整性门控规则和面积-颜色映射表。

## 新题 3：内部像素计数柱状图

**组合逻辑**：[connected_component + solid_interior + full_neighborhood_inside_component + recolor](来自 09c534e7) → [counting + histogram_bar + counts_as_histogram](来自 f3cdc58f，创新：柱高不是简单的像素计数而是经内部检测筛选后的计数) → [marker_inside_component + row_alignment](创新组合：标记像素的行坐标决定柱状图的列顺序，而非调色板顺序)

**来源原语**：connected_component、singleton_marker、solid_interior、marker_inside_component、full_neighborhood_inside_component、recolor（09c534e7）；counting、sorting、fg_pixel、histogram_bar、palette_order、counts_as_histogram（f3cdc58f）；row_alignment（673ef223）

**依赖链**：3x3 邻域检测识别各分量的内部像素 → 内部像素数成为柱状图的柱高 → 标记像素的行位置决定柱的左右排列。三步之间存在信息变换：邻域检测将空间形态转化为计数，计数转化为柱高，行位置转化为列序。去掉邻域检测则柱高不确定，去掉行位置排序则列序不确定。

将每个前景分量的"厚实内部"像素数统计为柱状图柱高，按标记行位置从上到下排列为从左到右的柱。

**输入结构**：约 15x20 网格，背景黑(0)。包含 3~5 个单色 4-连通前景分量，每个分量使用不同颜色（取自 {蓝(1), 红(2), 绿(3), 黄(4), 品红(6)}），面积均 >= 6 像素，含有宽度 >= 3 的"厚实"区域（至少部分像素的 3x3 邻域全在分量内）和宽度 = 1 的"通道"部分。每个分量内部恰有一个单点标记像素，颜色为灰(5)，位于分量内部（标记的 4 个邻居中至少 2 个属于该分量）。生成约束：各分量互不接触（8-连通距离 >= 2）；各标记像素的行坐标互不相同；不同示例中分量形状不同。

**规则**：
1. 对每个前景分量，找出所有"内部像素"：该像素的完整 3x3 邻域（8 个邻居 + 自身共 9 格）全部属于同一分量。
2. 统计每个分量的内部像素数量，记为该分量的"内部计数"。
3. 清空输出为黑(0)，输出网格高度与输入相同，宽度等于分量个数。
4. 按各分量灰(5) 标记像素的行坐标从小到大排列分量（行坐标最小的排在最左列，依次向右）。
5. 对每个分量，在其对应列从底部向上填充该分量主体颜色的像素，填充数量等于该分量的内部计数。

**关键洞察**：柱状图的列顺序既不是按颜色编号也不是按面积排序，而是由各分量内部标记像素的行坐标决定——这是一个隐蔽的空间属性映射，需要对比多个示例才能发现排序依据不在分量本身而在标记位置。

## 新题 4：前缀外推后布尔交集

**组合逻辑**：[prefix_matching + column_state_sequence + extrapolate + missing_suffix_continued_from_pattern](来自 90f3ed37，创新：外推应用于两个并列掩码而非行组) → [boolean_op + mask_region + divider_line + alignment + bg_intersection_out](来自 6430c8c4，创新：参与布尔运算的掩码是外推补全后的结果而非直接给出)

**来源原语**：complete、extrapolate、row_group、column_state_sequence、prefix_matching、missing_suffix_continued_from_pattern（90f3ed37）；boolean_op、mask_region、divider_line、alignment、bg_intersection_out（6430c8c4）

**依赖链**：上半区提供完整参考模式 → 下半区两个掩码各自只有参考模式的前缀 → 用参考模式外推补全两个掩码 → 对补全后的两个掩码做按位布尔运算输出交集背景。外推步骤依赖参考模式（无参考则前缀无法补全），布尔运算依赖补全结果（未补全的前缀做布尔运算会得到错误答案）。两步之间的信息变换：外推把不完整的空间模式转化为完整掩码，布尔运算把两个掩码的叠加关系转化为单一输出。

用共享参考模式分别外推补全两个不完整掩码，然后输出二者均为背景的位置。

**输入结构**：约 13x22 网格。一条完整宽度的橙(7) 水平分隔行将网格分为上下两半。上半区包含一个完整的列状态参考模式：每列要么为黑(0) 背景，要么在特定行偏移处有灰(5) 前景像素，形成一个可识别的列状态序列（如交替出现"空列-单像素列-双像素列"的循环）。下半区由一条完整高度的灰(5) 垂直分隔列分为左右两个等宽面板。左面板包含蓝(1) 前景像素构成的模式前缀（从最左列开始，覆盖若干列后中断，其余列为纯背景）。右面板包含红(2) 前景像素构成的另一段模式前缀（同样从最左列开始，长度与左面板不同）。生成约束：两个前缀的列状态序列与上半区参考模式的列状态序列前缀匹配；两个前缀长度不同且均短于参考模式；面板宽度等于参考模式列数。

**规则**：
1. 移除橙(7) 水平分隔行和灰(5) 垂直分隔列（它们是结构标记，不参与输出）。
2. 从上半区提取完整的列状态参考序列：逐列记录前景像素的行偏移模式。
3. 对左面板：识别其蓝(1) 像素构成的列状态前缀，与参考序列比对。从前缀终止处开始，按参考序列的后续列状态用蓝(1) 补全至面板右端。
4. 对右面板：同理用红(2) 补全。
5. 将补全后的左面板和右面板逐格对齐。输出一个与单面板同尺寸的网格：凡两个面板该格均为黑(0) 背景的位置，输出绿(3)；其余位置输出黑(0)。

**关键洞察**：两个掩码故意不完整——直接对不完整的前缀做布尔运算会因缺失区域全为背景而产生虚假的"双空"结果；必须先识别共享参考模式并补全两个前缀，才能得到正确的交集。

## 新题 5：遮挡序驱动的循环色印章

**组合逻辑**：[hollow_rectangle + overlap_layer + occlusion_order + overlap_determines](来自 68bc2e87) + [stamp + sprite_template + same_color_match + anchor_marker](来自 1b59e163 和 363442ee，创新：印章颜色不由模板自身颜色决定而由遮挡序的循环移位决定) + [erase + simultaneous_replacement](来自 3391f8c0，创新：擦除和重绘的时序由遮挡序约束)

**来源原语**：sorting、reconstruct、hollow_rectangle、overlap_layer、occlusion_order、overlap_determines（68bc2e87）；stamp、sprite、sprite_template、same_color_match、anchor_marker、anchor_positions_copy（1b59e163 / 363442ee）；erase、simultaneous_replacement、color_identifies_template（3391f8c0）

**依赖链**：遮挡关系分析得出层叠顺序 → 层叠顺序产生循环颜色映射（第 k 层的印章用第 k+1 层的颜色，最顶层用最底层颜色） → 颜色匹配关联矩形框与精灵模板 → 同步擦除后按新颜色重绘。去掉遮挡分析则循环映射无从建立，去掉颜色匹配则不知道哪个模板放哪个框，去掉同步擦除则重叠区域的绘制顺序出错。

根据重叠矩形框的遮挡层序，将每个框内的精灵模板用循环后移一位的层序颜色重新绘制。

**输入结构**：约 18x18 网格，背景黑(0)。包含 3~4 个单像素厚的空心矩形框，颜色各不相同（取自 {蓝(1), 红(2), 绿(3), 黄(4)}），矩形互有重叠（重叠处只显示最上层颜色）。网格底部 3 行是模板区：包含与每个矩形框同色的小型 4-连通精灵模板（每个 3~5 像素，形状不规则，各模板间互不相邻，边界框不超过 3x3）。生成约束：每对矩形至少有一个重叠像素可用于判断层序；模板区与矩形框区不重叠；所有矩形框大小相同（边界框尺寸一致，约 6x6 至 8x8）。

**规则**：
1. 将每个矩形框重建为其可见像素边界框的完整单像素边框。
2. 在每个重叠像素处，可见颜色所属的框在被遮挡颜色所属的框之上。综合所有重叠约束，推断唯一的从底到顶层叠顺序，记为排名 1（底）到 N（顶）。
3. 建立循环颜色映射：排名 k 的框映射到排名 (k mod N) + 1 的框的颜色。即排名 1 → 排名 2 的颜色，排名 2 → 排名 3 的颜色，...，排名 N → 排名 1 的颜色。
4. 在模板区中，通过颜色匹配找到每个框对应的精灵模板。
5. 同步擦除所有矩形框的内部区域（框线保留，内部设为黑(0)），同时擦除模板区（全部设为黑(0)）。
6. 对每个矩形框，将其对应的精灵模板居中印入框内部，但使用该框循环映射后的新颜色绘制。居中规则：模板边界框中心对齐框内部区域中心，四舍五入偏左偏上。
7. 框线保持原色不变。若印章像素与框线像素重叠，框线优先。

**关键洞察**：每个印章的颜色不是其模板的原色，而是由遮挡层序循环后移一位决定的——必须先完整解出层叠顺序才能确定颜色映射，且循环性质意味着最顶层的印章反而使用最底层的颜色，这是仅看单个示例难以确定的规则。

## 新题 6：字形重建下投影填充

**组合逻辑**：[frame_bar + endpoint_marker + glyph_template + erase + reconstruct + color_to_shape + anchor_position](来自 98c475bf) → [ray_cast + column_coverage + covered_col_to_edge](来自 6d58a25d，创新：射线不是从外部遮挡物下方延伸，而是从重建字形的像素位置向下投射，形成该字形的"列轮廓阴影")

**来源原语**：erase、reconstruct、frame_bar、endpoint_marker、glyph_template、color_to_shape、anchor_position（98c475bf）；ray_cast、foreground_object、column_coverage、covered_col_to_edge（6d58a25d）

**依赖链**：端点标记的颜色关联字形模板 → 字形重建确定像素位置 → 每个字形像素的列位置和行位置决定投影射线的起点和覆盖列 → 不同字形的投影可能在同一列重叠，需按锚行高低优先级解决冲突。字形的具体形状（而非仅边界框）直接决定投影的列轮廓；去掉重建则没有像素位置，去掉列投影则输出不完整，去掉冲突优先级则重叠区颜色不确定。

**规则**：

2. 擦除蓝(1) 字形（设为黑(0)）。
3. 对每对端点标记，以其所在行为锚行，用该标记颜色按模板偏移重建字形。
4. 对每个重建字形的每一列，找到该列中属于该字形的最低像素。从该像素下方一格开始，向下填充该字形颜色直到遇到另一个非背景非灰像素或到达网格底部（不含终点像素）。
5. 当两个不同字形的投影在同一格重叠时，锚行更高（行号更小）的字形颜色优先。
6. 灰(5) 边框竖条和端点标记像素保持不变。

**关键洞察**：字形不仅是装饰图案——它的逐列轮廓决定了阴影的宽度和参差形态；不同字形因处于不同高度，其阴影长度和覆盖范围各异，重叠时必须根据锚行高低判断优先级。

**关键洞察**：空隙区域的形状完全是涌现的——红色像素图案决定了哪些块包含自身副本（从而可能阻隔或连通空隙），灰色实心块则充当额外的隔断；同一输入图案既是展开规则又是展开后被复制的内容，这种自引用结构使得空隙形态难以直觉预判。

## 新题 8：多源射线碰撞涌现重涂

**组合逻辑**：[ray_cast + foreground_object + column_coverage + covered_col_to_edge](来自 6d58a25d，创新：多个不同色标记在同一列下方独立投射射线，射线从标记位置而非遮挡物底部开始) + [fill + adjacency + single_gap_filled](来自 a699fb00，创新：间隙填充应用于碰撞区与非碰撞区交界处) + [connected_component + area_ranking + area_determines_color + recolor](来自 e8593010，创新：被分级的不是输入分量而是射线碰撞涌现出的连通区域)

**来源原语**：ray_cast、foreground_object、marker_pixel、column_coverage、covered_col_to_edge（6d58a25d）；fill、dashed_segment、adjacency、single_gap_filled（a699fb00）；connected_component、area_ranking、area_determines_color、recolor（e8593010）

**依赖链**：遮挡物（屋顶）的列覆盖筛选出有效标记 → 有效标记各自投射下行射线 → 同列异色射线在重叠行产生碰撞标记 → 碰撞标记形成连通区域 → 区域面积决定最终颜色。碰撞区域的形状和面积是涌现的：取决于标记的列共享关系和行间距，无法从单个标记推断。去掉遮挡筛选则无效标记也参与（答案不同），去掉碰撞检测则没有碰撞区域，去掉面积分级则碰撞区颜色不确定。

遮挡物下方的多色标记各自向下投射射线，同列异色射线碰撞产生的连通区域按面积重涂。

**输入结构**：约 16x16 网格，背景黑(0)。上部有一个灰(5) 大型遮挡物（类似倒 V 形或不规则屋顶形状，约占网格上方 1/3 区域，底边参差不齐）。遮挡物下方散布单像素标记，颜色取自 {蓝(1), 红(2), 绿(3)}，共 5~8 个。部分列包含多个不同色标记（在不同行），部分列仅有一个标记或无标记。另有若干标记的列不在遮挡物正下方（这些是干扰项）。生成约束：至少 2 列包含 2 个不同色标记且这些列在遮挡物覆盖范围内；遮挡物外的干扰标记至少 1 个；不同示例中遮挡物形状和标记分布不同。

**规则**：
1. 识别灰(5) 遮挡物。对每个标记像素，向上搜索同列是否存在灰(5) 遮挡物像素。若存在，该标记为"有效"；否则为"无效"（干扰项，忽略）。
2. 对每个有效标记，从其所在位置向下投射射线：从标记行 +1 开始逐行向下填充该标记颜色，直到到达网格底部。标记自身保持原色。
3. 逐格检查射线叠加：若某格只有一条射线经过，该格取该射线颜色；若某格有两条或以上不同色射线经过，该格标记为黄(4)（碰撞色）。
4. 找出所有黄(4) 4-连通区域。按面积重涂：面积 = 1 → 橙(7)，面积 = 2~3 → 品红(6)，面积 >= 4 → 栗(9)。
5. 灰(5) 遮挡物、有效标记的原始像素、无效标记的原始像素均保持不变。无射线经过的背景格保持黑(0)。

**关键洞察**：碰撞区域的形状和面积是多个独立射线空间叠加后的涌现结果——两个标记在相邻列的不同行产生的碰撞区域形状与它们的行间距和列间距同时相关，仅从标记位置无法直觉推断碰撞区域的连通结构。

## 新题 9：隐式格子编码自相似印章

**组合逻辑**：[divider_grid + vertex_marker + corner_consistency + corners_set_region + compress](来自 7837ac64，创新：压缩结果不直接作为输出而是作为自相似展开的种子) → [seed_sprite + pixel_to_block_mapping + fg_position_copy + stamp](来自 5b6cbef5 和 363442ee，创新：展开中一种特殊颜色的块不是实心填充而是印入格子中找到的精灵模板)

从标记格子中压缩出种子掩码，再用种子掩码指导自相似展开，其中特殊单元展开为格子中提取的精灵。

**输入结构**：约 17x17 网格，背景黑(0)。灰(5) 形成规则的分隔网格，将内部划分为 4x4 = 16 个大小相同的矩形单元（每单元约 3x3 像素）。部分网格交叉点处有彩色标记像素，颜色取自 {蓝(1), 红(2), 绿(3)}。其中恰好一个单元内部包含一个橙(7) 单色 4-连通小图形（2~4 像素，称为精灵），该单元的四角标记颜色为橙(7)。其余激活单元（四角同色且非橙色）仅含背景。生成约束：至少 4 个单元四角同色（含精灵单元），至少 3 个单元无标记或标记颜色不一致（非激活）；不同示例中激活单元的位置分布和精灵形状不同。

**规则**：
1. 识别灰(5) 分隔网格和所有矩形单元。
2. 对每个单元，检查其四个角顶点：若四角均有同色非灰标记，该单元为"激活"单元，激活颜色为该角标颜色；否则为"非激活"单元。
3. 找到激活颜色为橙(7) 的单元，提取其内部精灵模板（记录像素相对于单元左上角的偏移和颜色橙(7)）。

   - 橙(7) 像素 → 将精灵模板印入该块（精灵像素为橙(7)，其余为黑(0)）。
   - 其他非黑颜色像素 → 该块全部填充该颜色。
   - 黑(0) 像素 → 该块全部黑(0)。
6. 输出不包含灰(5) 分隔线。

**关键洞察**：输入格子是一种视觉编码——顶点标记编码了一个 4x4 的布尔/颜色掩码，而精灵藏在其中一个单元里提供展开的精细模板；解题者必须先"解码"格子得到压缩种子，再用种子驱动展开，两层抽象缺一不可。

## 新题 10：控制点矩形框与对称边栏投影

**组合逻辑**：[control_pixel + extreme_row_col + ctrl_extremes_rect + draw_frame + pivot_pixel + pivot_to_sides + draw_line](来自 e4075551) + [edge_bar + symmetric_pair + row_alignment + marker_maps_opposite + ray_cast](来自 673ef223，创新：射线不是从标记直接到边栏，而是从枢轴十字线延伸到边栏后通过对称映射激活对侧) + [recolor](来自 e8593010，创新：重涂对象是边栏的行段而非连通分量)

**来源原语**：draw_frame、draw_line、control_pixel、pivot_pixel、extreme_row_col、ctrl_extremes_rect、pivot_to_sides（e4075551）；ray_cast、edge_bar、symmetric_pair、row_alignment、marker_maps_opposite、recolor（673ef223）；connected_component（e8593010）

**依赖链**：四个控制像素的极值位置定义矩形框 → 枢轴位置决定框内十字线走向 → 十字线水平段延伸为射线触达边栏 → 射线触达行通过对称映射激活对侧边栏的对应行 → 被激活行重涂色。控制像素的空间分布 → 矩形几何 → 枢轴的框内偏移 → 射线方向 → 边栏激活行。整条链中，每一步的输出都实质性改变下一步的输入：矩形大小和位置影响十字线端点，十字线端点决定射线方向，射线行决定边栏哪些行变色。

四个控制像素构建矩形框，框内枢轴的十字连线向外延伸为射线触达两侧边栏，并通过对称映射激活对侧边栏的对应行。

**输入结构**：约 15x15 网格，背景黑(0)。左右各有一条等高的完整高度红(2) 实心竖条（各 1 列宽，位于最左列和最右列），竖条高度等于网格高度。网格内部有四个单像素控制点，颜色各不相同（取自 {蓝(1), 绿(3), 黄(4), 品红(6)}），它们的行列极值定义一个矩形：最上方的控制点定义矩形顶边行，最下方的定义底边行，最左方的定义左边列，最右方的定义右边列。一个灰(5) 枢轴像素位于该矩形严格内部。生成约束：矩形的左右边列均不与边栏竖条相邻（至少隔 2 列）；枢轴不在矩形的行/列中心（使得向左和向右的射线长度不同）；两侧红色边栏高度相同（均为网格全高）。

**规则**：
1. 找出四个控制像素。以最上方控制点的行为顶边、最下方的行为底边、最左方的列为左边、最右方的列为右边，构建矩形框。用各控制点的颜色绘制对应边：顶边行从左边列到右边列用最上方控制点颜色，底边行同理用最下方颜色，左边列从顶边行+1 到底边行-1 用最左方颜色，右边列同理用最右方颜色。
2. 从灰(5) 枢轴像素出发，沿其所在行向左和向右各画灰(5) 直线直到触及矩形框边（不含框边像素），沿其所在列向上和向下同理。形成框内灰色十字。
3. 枢轴向左的灰色线继续向左延伸为青(8) 射线，从矩形左边列 -1 开始向左画青(8) 像素直到遇到左侧红色边栏（不含边栏像素）。记录射线到达的行号 R_left。
4. 枢轴向右的灰色线同理向右延伸为青(8) 射线，直到遇到右侧红色边栏。记录射线到达的行号 R_right。
5. 对称映射：左侧边栏总高度为 H_bar。R_left 在左侧边栏内的偏移为 offset_L = R_left - 边栏顶部行。在右侧边栏中找到相同偏移的行 R_mirror_right = 右侧边栏顶部行 + offset_L，将右侧边栏该行像素从红(2) 重涂为青(8)。
6. 同理：R_right 在右侧边栏内的偏移为 offset_R，在左侧边栏中找到相同偏移的行，将左侧边栏该行像素从红(2) 重涂为青(8)。
7. 控制像素、枢轴像素保留原色。

**关键洞察**：枢轴在矩形框中的位置同时决定了向左和向右射线的行号——由于枢轴不在框中心，左右射线可能在不同行，导致两侧边栏各有一行被对称激活且行号不同；必须追踪从控制点→矩形→枢轴→射线→边栏→对称映射的完整几何链才能确定最终哪些边栏像素变色。
