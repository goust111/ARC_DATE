## 新题 1：对角射线锚定平铺相位

**组合逻辑**：[ray_extend](创新：射线不作为视觉输出，而是确定空间锚点) + [tiling](创新：平铺相位由外部射线入射点决定，而非种子自身位置) + [erase]（辅助：清除射线痕迹）

**来源原语**：ray_extend / diagonal_dir / both_diags_through_pixel（623ea044），tiling / seed_pattern / rectangular_cavity / wall / preserve_seed_phase（a57f2f04），isolated_pixel（623ea044）

**依赖链**：射线的几何轨迹决定了它进入每个空腔的入射点坐标；该入射点坐标成为平铺网格的锚点，从而决定种子图案在空腔内的相位偏移。没有射线就无法确定相位，没有空腔和种子图案射线就无意义。

对角射线穿过空腔壁进入空腔的位置决定了空腔内平铺图案的对齐锚点，同一种子在不同锚点下产生不同的平铺相位。

**输入结构**：约 16x16 的黑(0)背景网格。灰(5)像素构成墙壁，围出 2-3 个矩形空腔（内部为黑(0)，各空腔大小不同，约 4x4 到 6x8）。每个空腔内有一组彩色像素构成种子图案：一个小矩形区域（2x2 或 2x3），使用各空腔独有的非黑非灰颜色（如红(2)、蓝(1)、绿(3)等）。空腔外的黑色区域中有 1-2 个孤立彩色像素（使用橙(7)或品红(6)等与种子颜色不同的颜色），各孤立像素之间和与空腔之间至少间隔 2 个像素。生成约束：每个空腔的至少一条对角射线必须穿过该空腔的墙壁（即孤立像素的对角线延伸路径与空腔有交集）。

**规则**：
1. 从每个孤立彩色像素出发，沿四个对角方向（左上、右上、左下、右下）画射线，延伸至网格边界，颜色为该像素的颜色。射线经过灰(5)墙壁时不停止，继续穿透。
2. 对每个空腔，找到所有穿入该空腔的射线。取这些射线中最先进入空腔内部的那个像素位置作为"锚点"（即射线从空腔外穿越墙壁后在空腔内部的第一个像素）。若多条射线进入同一空腔，取行坐标最小的入射点；若行坐标相同，取列坐标最小的。
3. 以锚点为平铺网格的对齐参考点（锚点对应种子图案的左上角位置），将种子图案周期性地平铺填满整个空腔内部。超出空腔边界的部分裁剪。
4. 清除所有射线像素（将射线经过的非墙壁、非空腔内容的位置恢复为黑(0)；空腔内的射线像素被平铺内容覆盖）。
5. 墙壁像素保持不变。孤立像素本身也被清除。

**关键洞察**：种子图案的内容决定"铺什么"，但铺出来的空间对齐完全由外部孤立像素的对角射线入射位置决定。同一个空腔在不同孤立像素位置下会产生不同的平铺偏移，必须对比多个示例才能确认锚点选取规则（最小行再最小列的入射点）。

## 新题 2：模板匹配确定排位后图例重涂色

**组合逻辑**：[rotate + template_match](已有：旋转匹配碎片) → [rank_correspond](创新：匹配后的碎片按空间位置排位) → [recolor](创新：排位映射到图例颜色，碎片整体重涂为单色)

**来源原语**：rotate / template / fragment / template_match / scale_rotate_align_frag（6aa20dc0），rank_correspond / color_legend / legend_pos_color（fafd9572），recolor（6e82a1ae, fafd9572）

**依赖链**：模板匹配确定每个碎片是模板的哪个旋转副本，验证碎片身份。碎片的空间排位（边界框位置排序）决定它对应图例中的第几个颜色。图例颜色直接覆盖碎片的所有像素。三个环节缺一不可：没有模板匹配无法验证碎片有效性，没有排位无法建立碎片与图例的对应，没有图例没有目标颜色。

通过模板旋转匹配识别散落碎片的身份，按碎片空间位置排序后用紧凑图例逐一分配新颜色，每个碎片整体重涂为对应的图例色。

**输入结构**：约 18x18 的灰(5)背景网格。左上角区域有一个多色模板对象（使用 3-4 种非灰颜色，如红(2)、蓝(1)、绿(3)、黄(4)，是场景中颜色种类最多的连通体，约 3x3 到 4x4 像素）。网格中散布 3-5 个单色碎片（各自使用不同的非灰颜色，每个碎片是模板某个旋转版本的部分像素子集，至少包含模板像素的 60%，为 4-连通）。网格右边缘有一列紧凑的图例像素（每行一个像素，连续排列，使用橙(7)、品红(6)、青(8)等与碎片颜色不同的颜色，图例像素数 = 碎片数）。生成约束：每个碎片对应模板的一个旋转（0/90/180/270度），碎片的颜色和位置互不相同，碎片之间不重叠。

**规则**：
1. 识别颜色种类最多的连通体为模板。
2. 对每个非模板、非图例的前景连通体（碎片），尝试将模板的四种旋转版本与碎片对齐：找到一个旋转使得碎片的所有像素位置都是旋转后模板像素位置的子集。
3. 将所有成功匹配的碎片按边界框位置排序：先按边界框顶行升序，顶行相同则按边界框左列升序，得到排位 1, 2, 3, ...
4. 图例像素同样从上到下编号 1, 2, 3, ...
5. 将排位为 k 的碎片的所有像素重涂为图例中第 k 个像素的颜色。
6. 模板和图例在输出中保持不变。背景保持灰(5)。

**关键洞察**：图例不是要复制的图案，而是按空间排位分配颜色的"调色盘"。碎片的原始颜色与最终颜色无关——最终颜色完全由碎片在网格中的空间排列顺序和图例的对应位置决定。需要多个示例才能区分排位规则（空间位置 vs. 碎片面积 vs. 匹配旋转角度等备选方案）。

## 新题 3：对称补全创造新孔洞后形状匹配填充

**组合逻辑**：[symmetry_completion](创新：对称补全不是恢复已有像素，而是在框架中挖出新孔洞) + [inlay_fill](已有：形状匹配后填色) + [erase]（辅助：移除外部精灵体）

**来源原语**：symmetry_completion / mirror（3345333e），inlay_fill / template_frame / sprite / hole / shape_matches_hole / rotation_flip_invariant（67e490f4），erase（3345333e）

**依赖链**：框架具有近似左右对称但一侧缺少某些孔洞。对称补全在缺失侧创建新孔洞（通过移除框架像素）。新旧孔洞共同构成完整的孔洞集合后，才能与外部精灵体进行形状匹配和填色。补全步骤改变了后续填充的目标集合——不补全则一侧孔洞不存在，无法填充。

对一个近似对称但有缺口的框架进行镜像补全以产生成对的孔洞，然后用外部形状匹配的精灵体颜色填充所有孔洞。

**输入结构**：约 16x16 的黑(0)背景网格。中央有一个大型单色框架（蓝(1)，约 12x12，像素组成一个厚度为 1-2 像素的封闭边界，内部有若干不规则孔洞）。框架整体近似左右对称（存在一条垂直对称轴），但对称性不完美：某些孔洞仅出现在对称轴的一侧，对侧的对应位置仍被框架像素填充。框架外部散布 3-5 个小型单色精灵体（各 3-6 像素，4-连通，使用红(2)、绿(3)、黄(4)、橙(7)等不同颜色），每个精灵体的形状在允许旋转和翻转后能与某一类孔洞形状匹配。生成约束：补全后每种孔洞形状至少对应一个外部精灵体；每个精灵体最多匹配一种孔洞形状；对称轴两侧的成对孔洞形状相同（互为镜像，但因为是不规则形状，旋转翻转后等价）。

**规则**：
1. 检测框架的垂直镜像对称轴（忽略不对称的部分，以大多数像素确定轴位置）。
2. 对于仅出现在对称轴一侧的每个孔洞，在对侧的镜像位置移除框架像素，创建对称的新孔洞。
3. 清点所有孔洞（包括原始孔洞和新创建的孔洞），提取每个孔洞的形状（4-连通区域的像素集合）。
4. 对每个孔洞形状，在外部精灵体中寻找形状匹配者（允许 0/90/180/270 度旋转和水平/垂直翻转）。
5. 将每个孔洞的所有像素填充为匹配精灵体的颜色。对称成对的孔洞形状相同，因此填充相同颜色。
6. 移除框架外部的所有精灵体像素（设为黑(0)）。框架像素和背景不变。

**关键洞察**：框架的不完美对称是设计意图——缺失的对称孔洞是隐含指令"先补全再填充"。仅凭单个示例，无法确定是"先补全对称再匹配"还是"仅填充已有孔洞"——需要看到示例中补全侧的孔洞确实被填充了，才能归纳出补全先于填充的顺序。

## 新题 4：跨框架推断完整图案后用作平铺种子

**组合逻辑**：[infer + cross_frame_match](已有：跨框架推断颜色) → [tiling](创新：推断结果不是填回框架，而是作为种子图案平铺到另一个区域)

**来源原语**：infer / lattice_frame / lattice_slot / cross_frame_match / slot_position_color（2e65ae53），tiling / seed_pattern / rectangular_cavity / wall / preserve_seed_phase / pattern_fills_cavity（a57f2f04）

**依赖链**：多个格子框架各自只展示了完整颜色图案的一部分。跨框架推断才能还原完整图案。该图案随后成为平铺种子，用于填充一个独立的大空腔。推断环节产出种子内容，平铺环节消费种子——前者的输出是后者的唯一输入来源。

从多个部分填充的格子框架中推断出完整颜色矩阵，再将该矩阵作为种子图案周期性地平铺填满独立的大空腔。

**输入结构**：约 20x16 的黑(0)背景网格。橙(7)的水平分隔行将网格分为上下两部分。上半部分包含 2-3 个小型格子框架（绿(3)像素构成 1 像素宽的网格线，将每个框架分为相同布局的槽位，如 2x3 或 3x3 个槽位，每个槽位内部约 2x2 像素）。各框架的部分槽位已填充颜色（红(2)、蓝(1)、黄(4)、品红(6)等），其余槽位为黑(0)。跨所有框架，每个逻辑槽位位置至少在一个框架中已被填充。下半部分包含一个由绿(3)墙壁围成的大矩形空腔（内部约 8x10，当前为黑(0)）。生成约束：所有框架的槽位布局相同（行列数相同）；同一个逻辑位置在不同框架中若被填充则颜色一致；大空腔的宽和高均为种子图案宽高的整数倍或更大。

**规则**：
1. 识别上半部分的所有格子框架，解析其槽位布局（R行 x C列）。
2. 对每个逻辑槽位位置 (r, c)，在所有框架中找到该位置已填充的颜色，记为该位置的颜色。
3. 将推断出的 RxC 颜色矩阵组装为一个矩形种子图案（每个逻辑位置对应种子中一个像素）。
4. 在下半部分的大空腔中，以空腔内部左上角为锚点，将种子图案周期性平铺，直到填满整个空腔。种子图案的每个像素对应空腔中一个像素（不做缩放）。
5. 输出仅保留下半部分（大空腔及其墙壁）。移除分隔行和上半部分的所有内容。

**关键洞察**：格子框架不是需要"修复"的目标，而是编码了平铺种子的分布式存储器。推断操作从多个不完整副本中恢复一份完整信息，该信息的用途（平铺填充）与其存储形式（格子框架）截然不同。需要多个示例来确认：推断结果不是填回框架本身，而是用于平铺另一个区域。

## 新题 5：像素计数决定同心环层数，颜色交替生长

**组合逻辑**：[counting](创新：计数结果不映射为颜色，而是映射为空间生长层数) + [grow](创新：不依赖已有边框，而是从对象中心向外生成全新的同心结构) + [recolor]（辅助：交替颜色层）

**来源原语**：counting / count_to_color（6e82a1ae），grow / concentric_layer / outward_rect（3befdf3e），recolor（6e82a1ae），foreground_object（6e82a1ae）

**依赖链**：像素计数决定同心环的层数，层数直接控制生长操作的空间范围。生长操作的颜色交替规则使用对象原色，因此原色信息必须在计数步骤之后传递到生长步骤。当不同对象的同心环重叠时，像素计数同时充当优先级判据——计数、生长、冲突解决三者形成闭环依赖。

统计每个前景对象的像素数量，以此决定在其边界框中心生成多少层同心方环，对象原始形状被完全替换为以原色和黑色交替的同心方环结构。

**输入结构**：约 15x15 的黑(0)背景网格。散布 3-5 个小型 4-连通单色前景对象（每个对象 2-5 个像素，形状不规则——可以是直线段、弯折条、小块等，不限定具体外形）。每个对象使用不同的非黑颜色（如红(2)、蓝(1)、绿(3)、黄(4)、品红(6)）。对象之间有足够间距（边界框之间至少间隔 3 个像素），以容纳生长后的同心环结构。生成约束：最大像素数对象的同心环（半径 = 像素数 - 1）不超出网格边界；不同对象的同心环可以有少量重叠（用于测试优先级规则）。

**规则**：
1. 对每个前景对象，计算其像素数量 N。
2. 计算该对象边界框的中心坐标（行中心 = (顶行 + 底行) / 2 向下取整，列中心 = (左列 + 右列) / 2 向下取整）。
3. 擦除该对象的所有原始像素（设为黑(0)）。
4. 以中心坐标为原点，绘制 N 层同心方环：
   - 第 1 层（最内层）：仅中心像素，涂对象原色。
   - 第 2 层：中心外扩 1 格的方环边框（即 3x3 方框的边界像素），涂黑(0)。
   - 第 3 层：外扩 2 格的方环边框（5x5 方框的边界像素），涂对象原色。
   - 以此类推，奇数层涂对象原色，偶数层涂黑(0)。
5. 若不同对象的同心环像素重叠，像素数 N 更大的对象优先（其环覆盖另一方）。若 N 相同，边界框顶行更小（更靠上）的对象优先；若仍相同，边界框左列更小（更靠左）的优先。
6. 超出网格边界的环像素直接裁剪（不绘制）。

**关键洞察**：对象的不规则形状完全消失，被同心方环取代——对象的唯一遗产是中心坐标、颜色和像素计数。像素计数同时决定了环的层数（空间范围）和重叠冲突的优先级，形成双重用途。需要多个示例才能确认层数与像素数的关系（N 个像素 = N 层，非 N-1 或 2N 等），以及偶数层涂黑的交替规则。

## 新题 6：奇数正方形循环缩放后双面板叠加取优先

**组合逻辑**：[resize / side_length_cycle](已有：边长循环变换) + [overlay / per_pixel_comparison](创新：叠加规则不是取背景交集，而是按原始尺寸决定优先级)

**来源原语**：resize / odd_side_square / center_point / concentric_position / side_length_cycle（522fdd07），overlay / mask / per_pixel_comparison / both_background_marked_foreground（94f9d214），panel / separator_row（0c9aba6e）

**依赖链**：缩放改变了每个正方形的覆盖区域，从而改变了双面板叠加时的重叠结构。但叠加的优先级规则依赖于缩放前的原始边长——必须记住变换前的状态来裁决变换后的冲突。缩放决定"哪些像素存在"，原始尺寸决定"冲突时谁赢"，两者分别来自变换后和变换前的状态，紧密耦合。

将两个面板中的奇数边正方形各自循环缩放一级，然后叠加两个面板，重叠区域按原始（缩放前）边长较大者的颜色着色。

**输入结构**：约 10x22 的黑(0)背景网格（宽大于高）。黄(4)的垂直分隔列将网格分为左右两个等大面板（各约 10x10）。每个面板包含 2-3 个实心奇数边正方形（边长属于集合 {1, 3, 5, 7, 9}），各正方形使用不同的非黑非黄颜色（如红(2)、蓝(1)、绿(3)、品红(6)、灰(5)等），正方形之间不重叠（在各自面板内）。左右面板中的正方形颜色、大小、位置可以不同。生成约束：缩放后的正方形不超出面板边界；至少存在一对左右面板正方形在缩放后有空间重叠（用于测试优先级规则）。

**规则**：
1. 记录每个正方形的原始边长。
2. 对两个面板中的每个正方形，执行边长循环变换：1->9, 3->1, 5->3, 7->5, 9->7。保持中心坐标不变，颜色不变。
3. 移除分隔列。将左右面板按位置对齐（左面板的第 j 列对应右面板的第 j 列）。
4. 生成一个面板大小的输出网格。对每个像素位置：
   - 若两个面板在该位置均有非黑颜色：取原始边长更大的那个面板中对应正方形的颜色。若原始边长相同，取左面板的颜色。
   - 若仅一个面板在该位置有非黑颜色：使用该颜色。
   - 若两个面板均为黑(0)：输出黑(0)。
5. 输出仅为合并后的单个面板。

**关键洞察**：一个边长为 1 的点会膨胀为 9x9 的大方块，覆盖面积剧增，但它的优先级最低（原始边长仅为 1）。反之，一个 9x9 的方块缩小为 7x7，失去了边缘区域，但在剩余区域内仍拥有最高优先级。观察者必须区分"当前可见大小"和"原始大小"这两个不同的量，才能正确解题。

## 新题 7：竖条滑动至灰线后在停靠点印章模板

**组合逻辑**：[sliding / collision_blocking](已有：条状物滑动直到碰撞) → [stamp](创新：印章位置不由规则示例定义，而是由滑动后的停靠位置决定) + [erase]（辅助：清除引导结构）

**来源原语**：sliding / bar / same_col_align / collision_blocking / slide_until_near_target（3906de3d），stamp / stencil_pattern / recolor（abc82100），erase（3345333e, a78176bb）

**依赖链**：滑动操作决定每个竖条的最终位置，该位置成为印章操作的放置坐标。竖条的颜色决定印章副本的颜色。滑动距离（从起点到终点的行数差）决定重叠时的优先级。三个信息（位置、颜色、优先级）全部来源于滑动过程，驱动后续的印章操作。

彩色竖条沿各自列滑向灰色水平线直到紧邻，在每个停靠点以竖条颜色印章一份模板图案，滑动距离长者优先覆盖。

**输入结构**：约 15x15 的黑(0)背景网格。网格中部有一条水平灰(5)线（占据一整行，1 像素高）。灰线上方和下方各散布若干竖条（每个竖条宽 1 像素，高 2-3 像素，4-连通垂直线段），使用不同的非黑非灰非青颜色（如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)等），每列最多一个竖条。网格的一个角落区域（如左下角）有一个青(8)色的小型连通图案（模板，3-5 像素，不规则形状），不与灰线和竖条重叠。生成约束：灰线上方的竖条与灰线之间至少有 1 行空隙；灰线下方的竖条与灰线之间至少有 1 行空隙；竖条滑动到灰线旁后，相邻竖条的印章图案可能部分重叠。

**规则**：
1. 识别灰(5)水平线为碰撞边界，青(8)连通体为模板图案。
2. 灰线上方的每个竖条向下滑动，直到竖条的底部像素紧邻灰线上方（即底部像素位于灰线行 - 1）。灰线下方的每个竖条向上滑动，直到竖条的顶部像素紧邻灰线下方（即顶部像素位于灰线行 + 1）。
3. 计算每个竖条的滑动距离（移动的行数，即终位置与起位置的差的绝对值）。
4. 在每个竖条滑动后的中心像素位置（竖条高度的中间行，若偶数高度取偏上的行；列为竖条所在列），放置一份模板图案的副本。放置方式：模板图案的边界框中心对齐到该位置。模板副本的颜色为该竖条的颜色（替换青色）。
5. 若不同竖条的模板副本有像素重叠，滑动距离更长的竖条优先（其副本覆盖另一方）。若距离相同，灰线上方滑来的竖条优先于下方滑来的。若方向也相同，列坐标更小（更靠左）的优先。
6. 擦除灰线、原始青(8)模板图案、以及竖条的起始位置残影（若有）。输出仅包含印章副本和黑色背景。

**关键洞察**：灰线是"集合点"，将分散的竖条吸引到中部。但竖条到达后并非简单停留——它们各自触发一次模板印章，且滑动距离（路途远近）决定了重叠冲突的裁决。来自远处的竖条拥有更高优先级，这条规则需要对比多个示例中的重叠情况才能归纳。

## 新题 8：双面板去遮挡对称补全后叠加取交集，按行控制色着色

**组合逻辑**：[erase + symmetry_completion](已有原语，创新组合：两个面板各自独立去遮挡并补全) → [overlay / per_pixel_comparison](创新：取两个补全后面板的交集而非各自输出) → [recolor / per_row_color](创新：交集像素不统一着色，而是按行从控制列取色)

**来源原语**：erase / occlusion / mirror_after_occluder_removal / symmetry_completion（3345333e），overlay / per_pixel_comparison / both_background_marked_foreground（94f9d214），recolor / per_row_color / row_control_color / same_row_align（c7d4e6ad），filled_rectangle（3345333e），panel / separator_row（0c9aba6e）

**依赖链**：(1) 遮挡物移除揭示了被隐藏的区域，但留下空洞。(2) 对称补全利用各面板自身的镜像对称修复空洞。(3) 两个面板补全后可能各自"过度生成"（将遮挡区域的对称位置也补全了），取交集过滤掉过度生成的像素，保留两个面板共同认可的前景。(4) 行控制色逐行为交集像素赋予不同颜色。四步依赖链中，每一步的输出实质性改变下一步的输入：遮挡物位置影响补全范围，补全范围影响交集结果，交集确定着色目标，控制色确定最终外观。

两个各自被不同矩形遮挡的对称面板分别去遮挡并镜像补全，叠加取交集得到可靠前景，再按行控制色逐行着色。

**输入结构**：约 14x14 的黑(0)背景网格。橙(7)的水平分隔行将网格分为上下两个等高面板（各约 6x14）。
- 上面板：一个蓝(1)单色图案在黑背景上，具有左右镜像对称性。一个红(2)实心矩形（约 2x3 到 3x4）覆盖了图案的一部分，遮挡了该区域的蓝色像素。
- 下面板：一个绿(3)单色图案在黑背景上，具有左右镜像对称性，与上面板的蓝色图案形状不同。一个红(2)实心矩形覆盖了该图案的另一部分。
- 网格最右列为控制色列：从上到下每行一个彩色像素（使用黄(4)、灰(5)、品红(6)、青(8)中的若干种），像素数等于单个面板的行数。控制色列不被分隔行中断（分隔行位置的控制色像素也存在，但不用于输出）。

生成约束：每个面板的对称图案在去除遮挡物并补全后为完整的对称图形；两个面板的完整图案有部分空间重叠（按位置对齐后至少有若干行列同时为前景）；红色不出现在图案或控制色中（红色仅用于遮挡物）。

**规则**：
1. 在每个面板中，识别红(2)实心矩形为遮挡物并擦除（将其像素设为黑(0)）。
2. 对每个面板，检测其前景图案的垂直镜像对称轴。将被遮挡区域中缺失的前景像素通过镜像反射补全（若对称轴一侧有前景像素而另一侧的镜像位置被遮挡物覆盖过，则在该镜像位置恢复前景像素）。补全后的前景色与原图案相同（上面板用蓝(1)，下面板用绿(3)）。
3. 移除分隔行，将两个补全后的面板按位置对齐。
4. 生成一个面板大小的输出网格。对每个像素位置：
   - 若上面板补全后该位置为前景（蓝(1)）**且**下面板补全后该位置也为前景（绿(3)）：标记为输出前景。
   - 否则：标记为黑(0)背景。
5. 对每个输出前景像素，根据其所在行在控制色列中的对应颜色进行着色（第 r 行的前景像素涂为控制色列第 r 个像素的颜色）。
6. 移除控制色列本身（不出现在输出中）。输出网格宽度 = 原面板宽度 - 1（去掉控制色列占用的列）。

**关键洞察**：单独看任一面板，去遮挡后补全可能"猜错"——遮挡区域的对称位置可能本来就没有前景像素，但补全操作会错误地添加。两个面板使用不同的遮挡位置，它们补全后的交集过滤掉了各自的过度生成，仅保留两个独立信息源共同支持的前景。这种"双源校验"机制是多示例才能归纳的核心——观察者需要理解交集的作用不是合并两个图案，而是互相验证。
