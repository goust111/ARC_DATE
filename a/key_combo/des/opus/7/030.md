## 新题 1：字形编程的精灵导航

**组合逻辑**：[解码/decode](创新：将方向解码结果用作导航指令而非绘制路径) + [逐步移动/stepwise_move](创新：移动方向由外部指令序列决定而非由精灵朝向决定) + [消除/consume](已有)

**来源原语**：解码/字形/弯头决定偏移(e6de6e8f)、逐步移动/消除/三角精灵体/最近标记优先(5545f144)、顺序排列(e6de6e8f)

**依赖链**：字形条的解码产生一个有序方向序列；该序列逐条控制精灵的移动方向，替代了精灵自身朝向的决策作用；每步移动后消除到达的标记像素，标记的消失改变后续步骤的可达性。三者形成"解码→导航→消除→影响后续导航"的循环依赖。

根据字形指令条编码的方向序列，驱动精灵逐步移动并消除路径上最近的标记像素，输出精灵的最终位置。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格顶部两行是一段字形指令条，由红(2)像素组成的若干字形从左到右排列，每个字形跨两行、宽 1~2 列（与 e6de6e8f 结构一致）。顶部两行与下方区域之间有一行黑(0)分隔。下方区域包含一个由蓝(1)像素组成的 3~5 像素箭头形精灵体（4-连通、具有可辨识的尖端朝向，但初始朝向不影响规则）和 4~8 个散布的绿(3)单像素标记。精灵体和标记之间有足够距离，保证每步指令在指定方向上至多只有一个标记可达。生成约束：字形数量等于标记数量；每一步在解码方向上恰好存在一个可达标记（即沿该方向的半行或半列上有且仅有一个尚未消除的标记）。

**规则**：
1. 解码顶部字形条：从左到右逐个读取字形。仅占一列且两行均为红(2)的字形解码为"沿当前列方向前进"（即向下）；占两列的 L 形弯头字形中，缺失红像素的角在左上则解码为"向右"，缺失角在右上则解码为"向左"，缺失角在左下则解码为"向上偏右"（向上），缺失角在右下则解码为"向上偏左"（向上）。简化规则：竖直字形→向下，弯头顶部缺口在左侧→向右，弯头顶部缺口在右侧→向左，弯头底部缺口→向上。
2. 获得方向序列 D1, D2, ..., Dn。从精灵体的尖端像素出发，执行第一条指令 D1：沿 D1 方向搜索最近的未消除绿(3)标记，将精灵体平移至该标记位置（精灵尖端移动到标记所在格），消除该标记。
3. 依次执行 D2, D3, ... Dn，每步同理。若某步方向上无可达标记，跳过该指令（生成约束保证此情况不出现）。
4. 输出仅保留精灵体在最终位置的蓝(1)像素和所有未被消除的绿(3)标记（生成约束下所有标记均被消除），背景为黑(0)。字形指令条不出现在输出中。

**关键洞察**：字形条不是绘制路径的模板（与 e6de6e8f 的用法完全不同），而是一段控制精灵移动方向的"程序"；求解者必须同时掌握字形解码规则和精灵导航规则，任一环节缺失都无法确定最终位置。

## 新题 2：遮挡层序决定扩展冲突

**组合逻辑**：[层序推断/layer_infer](已有) + [拉伸/extrude](创新：扩展后的冲突区域由层序决定归属而非简单覆盖) + [边缘延伸角落留黑/edge_extrude_corner_black](已有，作为扩展的局部约束)

**来源原语**：层序推断/遮挡层次/交叉可见色为上层(22425bda, 1a2e2828)、拉伸/扩展/边缘延伸角落留黑(49d1d64f)、交叠区域(1a2e2828)

**依赖链**：重叠区域的可见颜色决定层序；层序决定扩展冲突的归属；扩展操作本身又在原始重叠区域之外创建新的接触区域，但这些新接触不改变已推断的层序（层序仅由输入中的重叠决定）。层序推断和扩展操作通过冲突解决规则紧密耦合。

从部分重叠的彩色矩形块中推断遮挡层序，然后将每个矩形向外扩展一圈，扩展冲突区域归属于层序更高的矩形。

**输入结构**：约 18x18 的网格，背景为黑(0)。包含 3~5 个不同颜色的实心矩形块（每个约 3x4 至 5x6 像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)中选取），彼此部分重叠。在重叠区域中，高层矩形的颜色覆盖低层矩形的颜色（与 22425bda/1a2e2828 类似的遮挡可见性）。每对相邻层的矩形之间至少有一个重叠像素，使层序可以从可见颜色中完整推断。生成约束：所有矩形的层序构成唯一的全序（无循环遮挡）；任何两个矩形扩展后的一像素外框至少在一个非角落位置接触，以确保冲突解决可观测。

**规则**：
1. 还原每个矩形的完整范围：被遮挡的像素仍属于该矩形，其颜色在输出中可能被恢复或继续被遮挡。
2. 从重叠区域推断层序：若位置 (r,c) 属于矩形 A 和矩形 B 的重叠区域，且该位置显示 A 的颜色，则 A 在 B 之上。传递闭包得到完整的从低到高的层序。
3. 对每个矩形执行一像素外扩：在其边界框四周各扩展一行/列，扩展像素颜色与矩形相同，但扩展框的四个角落像素保持黑(0)（与 49d1d64f 一致）。
4. 冲突解决：若两个矩形的扩展区域（或扩展区域与另一矩形的原始区域）重叠于同一像素，该像素归属层序更高的矩形，显示该矩形的颜色。原始矩形体的遮挡关系同样延续（高层覆盖低层）。
5. 输出保留背景黑(0)以及所有经扩展和冲突解决后的矩形像素。

**关键洞察**：扩展操作本身不改变层序，但创造了新的冲突区域；求解者必须先从输入的原始重叠推断层序，再将同一层序应用于扩展后产生的全新冲突——两步使用同一推断结果但作用于不同几何范围。

## 新题 3：旋转匹配决定边框处理

**组合逻辑**：[形状匹配/shape_matching](创新：匹配时需尝试旋转，匹配所需的旋转量编码了额外规则) + [旋转/rotate](创新：旋转不是目的而是匹配的手段，旋转量本身成为信息载体) + [重涂色/recolor](创新：重涂范围由旋转量决定)

**来源原语**：形状匹配/形状对应/匹配形状决定填色(93b4f4b3)、旋转/整图半周旋转(6150a2bd)、重涂色(396d80d7, c9f8e694)、模板/封闭孔洞(93b4f4b3)、单色对象(93b4f4b3)

**依赖链**：形状匹配需要旋转才能成功→旋转量决定孔洞边框的重涂规则→重涂结果反过来验证匹配的正确性（对称形状可能有多种旋转匹配，但只有一种旋转量产生跨示例一致的边框效果）。

将右侧面板中可能经旋转的单色对象与左侧模板的孔洞进行旋转匹配，用对象颜色填充对应孔洞，同时根据匹配所需的旋转量决定孔洞周围边框像素的处理方式。

**输入结构**：约 12x24 的网格，由一条灰(5)竖线在中间分为左右两个等宽面板，各约 12x11。左侧面板：一个由品红(6)像素组成的单连通模板，内部有 3~4 个互不相连的背景色(黑(0))孔洞区域，每个孔洞为 3~5 像素的不规则 4-连通形状，且至少有一个孔洞不具备旋转对称性。右侧面板：3~4 个单色对象（颜色分别从蓝(1)、红(2)、绿(3)、黄(4)中选取），每个对象是某个孔洞经 0/90/180/270 度旋转后的形状副本，放置在黑(0)背景上，对象之间互不接触。生成约束：每个孔洞恰好有一个右侧对象与之匹配（旋转后形状完全一致），且匹配唯一（不存在两个不同旋转量都能匹配的情况，必要时通过设计非对称孔洞形状来保证）。

**规则**：
1. 提取左侧模板中每个孔洞的形状掩码（归一化到边界框左上角）。
2. 提取右侧每个单色对象的形状掩码（同样归一化）。
3. 对每个孔洞，在右侧对象中寻找唯一匹配：将对象掩码分别旋转 0、90、180、270 度，与孔洞掩码比对，找到完全吻合的旋转量 R。
4. 用匹配对象的颜色填充该孔洞的所有像素。
5. 根据旋转量 R 处理该孔洞的**边框像素**（孔洞 4-邻域中属于品红(6)模板的像素）：
   - R = 0 度：边框像素保持品红(6)不变。
   - R = 90 度：边框像素重涂为该对象颜色。
   - R = 180 度：边框像素重涂为黑(0)（擦除）。
   - R = 270 度：边框像素重涂为灰(5)。
6. 输出仅包含左侧面板（不含分隔线和右侧面板），分隔线列及右侧区域全部裁去。

**关键洞察**：旋转不只是匹配工具——匹配所需的旋转量本身编码了一条隐蔽的边框处理规则，求解者必须对比多个示例才能归纳出"旋转量→边框效果"的映射关系。

## 新题 4：行键控色的奇偶印章

**组合逻辑**：[印章覆盖/stamp_overlay](已有) + [重涂色/recolor · 行首色决定填色](创新：印章副本的颜色不继承种子色，而由目标单元格所在行带的控制像素决定) + [同奇偶格接收副本/same_parity_receive_copy](已有，作为印章目标选择)

**来源原语**：印章覆盖/种子图案/开放单元格/同奇偶格接收副本/单元格阵列(92e50de0)、重涂色/行首色决定填色/控制像素/同行对应(c9f8e694)、分隔线(92e50de0)

**依赖链**：种子图案决定印章形状→奇偶判定决定哪些单元格接收印章→但每个副本的颜色不来自种子而来自该单元格所在行带的控制像素。三条规则同时约束每个输出像素：位置由奇偶决定、形状由种子决定、颜色由行键决定。缺少任一条都无法确定输出。

在脚手架网格的同奇偶单元格中印章种子图案，但每个副本的颜色由该行带左侧的控制像素决定而非继承种子色。

**输入结构**：约 19x19 的网格。灰(5)像素组成完整的水平和竖直分隔线，将网格分割为 4x4（或 3x3）的开放单元格阵列，每个单元格约 4x4 像素。网格最左列（列 0）在每条水平分隔线所界定的行带内各有一个控制像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，位于该行带的第一个非分隔行。恰好一个开放单元格内包含一个由橙(7)像素组成的 2~3 像素小图案（种子图案），其余单元格为纯黑(0)背景。生成约束：每个行带有且仅有一个控制像素；控制像素不与分隔线重叠；种子图案完全位于一个单元格内部。

**规则**：
1. 识别灰(5)分隔线，将网格划分为开放单元格阵列。记录每个单元格的行索引 (ri) 和列索引 (ci)。
2. 找到包含橙(7)种子图案的单元格，记录其行索引 ri0 和列索引 ci0，并提取图案相对于该单元格左上角的偏移掩码。
3. 对每个开放单元格 (ri, ci)：若 ri 与 ri0 的奇偶性相同，且 ci 与 ci0 的奇偶性相同，则该单元格为"接收单元格"。
4. 对每个接收单元格，将种子图案的偏移掩码印章到该单元格中。印章像素的颜色不是橙(7)，而是该单元格所在行带在列 0 的控制像素颜色。若单元格在边缘被截断，印章超出部分舍弃。
5. 种子单元格自身也执行印章（视为接收单元格），其颜色同样由所在行带的控制像素决定——因此种子的橙(7)在输出中被替换。
6. 输出保留灰(5)分隔线、列 0 的控制像素、所有非接收单元格的黑(0)背景，以及接收单元格中的印章像素。

**关键洞察**：种子图案提供形状但不提供颜色——颜色来自行带控制像素，这一规则在单个示例中可能被误解为"所有副本同色"（若该示例的接收单元格恰好都在同一行带），必须对比多个示例才能归纳。

## 新题 5：地形过滤的锚点射线

**组合逻辑**：[射线延伸/ray_extend](已有) + [地形轮廓/terrain_contour](创新：地形不再用于找极值列，而是作为标记像素的可见性过滤器) + [重涂色/recolor](创新：射线穿过地形表面时为表面着色)

**来源原语**：射线延伸/锚定方块/标记像素/行列对齐/对齐标记连向锚点(d43fd935)、地形轮廓/列高度极值(e45ef808)、重涂色(多题)

**依赖链**：地形表面的高度决定哪些标记"露出"（可见）→可见标记向锚点发射射线→射线经过的列若有地形表面则为该表面像素着色。地形既是过滤器（决定标记可见性）又是画布（接收射线着色），双重角色形成紧耦合。

仅地形表面之上的标记像素向锚定方块发射射线，射线经过地形表面时为表面像素染上射线颜色。

**输入结构**：约 16x16 的网格，背景为黑(0)。底部若干行为栗(9)像素组成的地形轮廓：每列从底部向上有一段连续的栗(9)像素，高度在 2~8 行之间不等，形成不规则的地形剖面。地形之上（即每列的最上方栗(9)像素之上）为黑(0)空域。空域中放置一个红(2)的 2x2 锚定方块，位于网格中上部。空域中还散布 4~6 个单像素标记，颜色从蓝(1)、绿(3)、黄(4)中选取。部分标记位于地形表面之下（被地形"掩埋"——其行号大于等于该列地形表面行号）。生成约束：至少 2 个标记在地形之上且与锚定方块行对齐或列对齐；至少 1 个标记被掩埋；被掩埋的标记中至少 1 个与锚定方块对齐（以制造干扰）；每条射线路径上至多经过一个地形表面像素。

**规则**：
1. 确定每列的地形表面行（该列最上方的栗(9)像素所在行）。
2. 判断每个标记像素是否"可见"：若标记所在行严格位于其所在列的地形表面行之上（行号更小），则可见；否则被掩埋，在输出中擦除（设为黑(0)）。
3. 对每个可见标记，检查其是否与锚定方块的某行或某列对齐（即标记的行号等于锚定方块占据的两行之一，或标记的列号等于锚定方块占据的两列之一）。
4. 对每个对齐的可见标记，从标记位置沿行或列方向向锚定方块绘制射线，填充标记颜色，直到到达锚定方块相邻的像素为止。射线不覆盖锚定方块本身。
5. 若射线路径经过某个地形表面像素（该列最顶部的栗(9)像素），将该地形表面像素重涂为射线颜色（其下方的栗(9)像素不受影响）。
6. 未对齐的可见标记保留原位不变。锚定方块保留红(2)不变。

**关键洞察**：地形同时扮演两个角色——滤除不可见的标记（即使它们与锚点对齐），以及接收射线的着色。求解者容易忽略地形的过滤作用而错误地让被掩埋的标记也发射射线。

## 新题 6：遮挡层序驱动的精灵拼接

**组合逻辑**：[层序推断/layer_infer](创新：层序不用于确定可见颜色，而用于确定拼接顺序) + [裁剪/crop](已有) + [拼接/concatenate · 接缝对齐](已有) + [重涂色/recolor](已有，灰控制像素统一重涂)

**来源原语**：层序推断/遮挡层次(22425bda)、裁剪/拼接/精灵体/接缝对齐/控制像素对齐拼接(234bbc79)、交叠区域(1a2e2828)、重涂色(c9f8e694)

**依赖链**：精灵体的空间重叠→推断遮挡层序→层序决定拼接的左右顺序（而非精灵在输入中的空间位置）→灰色接缝标记决定垂直对齐偏移→重涂灰像素为精灵主色。拼接顺序和垂直对齐分别依赖两个独立的推断结果，缺一不可。

从部分重叠的彩色精灵体中推断遮挡层序，按层序（底层在左、顶层在右）裁剪并紧凑拼接，垂直对齐由灰色接缝标记决定。

**输入结构**：约 15x20 的网格，背景为黑(0)。包含 3~4 个 8-连通的彩色精灵体，每个精灵体有一个主色（从蓝(1)、红(2)、绿(3)、黄(4)中选取）和若干灰(5)控制像素位于其左右边缘。精灵体的边界框高度约 4~6 行、宽度约 3~5 列。精灵体之间部分重叠（边界框有交集），在重叠区域中，高层精灵的颜色覆盖低层。每个精灵的左边缘和右边缘各有至少一个灰(5)控制像素。生成约束：任意两个相邻层的精灵之间至少有一个重叠像素以确定相对层次；全部精灵的层序构成唯一全序；灰(5)控制像素不出现在重叠区域内。

**规则**：
1. 还原每个精灵的完整形状：被遮挡区域的像素属于被遮挡的精灵，颜色为该精灵的主色（非灰(5)的前景色）。
2. 从重叠可见颜色推断层序：在重叠位置显示的颜色对应更高层的精灵。传递闭包得到完整层序。
3. 将每个精灵裁剪到其完整边界框（包含被遮挡区域还原后的像素）。
4. 将裁剪后的精灵替换灰(5)控制像素为该精灵的主色。
5. 按层序从底到顶排列为从左到右拼接。拼接时去除精灵之间的间距，边界框紧邻。
6. 垂直对齐：第一个精灵（最底层）的顶部行与输出顶部对齐。后续每个精灵的垂直位置由接缝标记决定——前一精灵右边缘最低的灰标记行与后一精灵左边缘最高的灰标记行对齐到输出的同一行。输出高度为容纳所有精灵所需的最小行数。
7. 拼接后的空白区域（无精灵覆盖）填充黑(0)。

**关键洞察**：拼接顺序不由精灵在输入中的左右位置决定——输入中最左边的精灵可能是最高层，在输出中出现在最右边。求解者必须抵抗"输入位置=输出位置"的直觉。

## 新题 7：扩展角隙的对角邻接填充

**组合逻辑**：[拉伸/extrude · 边缘延伸角落留黑](已有) + [重涂色/recolor · 对角邻接背景着色](创新：对角邻接检测作用于扩展后的几何而非原始几何) → 涌现效应：扩展操作故意留出的角隙恰好是对角邻接规则的作用目标

**来源原语**：拉伸/扩展/边框绘制/边缘延伸角落留黑(49d1d64f, 0f63c0b9)、重涂色/仅对角邻接/对角邻接背景着色/封闭框/内层前景(396d80d7)

**依赖链**：每个封闭框先执行外扩（角隙留黑）→外扩后的框几何改变了哪些背景像素满足"仅对角邻接"条件→满足条件的像素被涂为内层前景色。扩展和对角填充两步操作的几何互相啮合：角隙是扩展规则刻意创建的，而对角填充规则恰好选中这些角隙。

将每个带有内层前景色的封闭框向外扩展一圈（角落留黑），然后用内层前景色填充所有仅与扩展后框体对角邻接的背景像素。

**输入结构**：约 18x18 的网格，背景为黑(0)。包含 2~3 个不重叠的封闭框结构，每个结构由两种颜色组成：一种颜色形成矩形环（框），宽度为一像素；另一种颜色（内层前景色）为框内部的 1~3 个像素。不同封闭框使用不同的颜色对，例如第一个框为红(2)框+蓝(1)内层，第二个框为绿(3)框+黄(4)内层。框的边界框严格包含内层前景像素的边界框。封闭框之间至少间隔 3 个像素，确保扩展后不会互相接触。

**规则**：
1. 对每个封闭框执行一像素外扩：在框的边界框四周各扩展一行/列，扩展像素颜色与框色相同，但扩展矩形的四个角落像素保持黑(0)。
2. 框内部的内层前景像素和原始框像素保持不变。
3. 扩展完成后，扫描整个网格。对每个黑(0)背景像素，检查其 8 邻域：若该像素与某个扩展后框色存在对角邻接（至少一个对角方向有该框色像素），但与该框色不存在正交邻接（上下左右均无该框色像素），则将该像素重涂为该封闭框的内层前景色。
4. 若一个背景像素同时满足多个封闭框的对角邻接条件（不会发生，因为框间距足够大），则按框的边界框面积从小到大优先（面积小的优先）。
5. 输出包含所有扩展后的框、内层前景、以及新涂色的对角邻接像素。

**关键洞察**：扩展操作刻意留出的四个角隙像素恰好满足"仅对角邻接于框"的条件，因此内层前景色总是精确地出现在扩展后的四个角——这一涌现效果不是任一规则单独能产生的，而是两条规则的几何契合。

## 新题 8：孔洞计数驱动的中点带框

**组合逻辑**：[计数/counting · 孔洞数映射颜色](创新：计数结果不直接重涂对象，而决定对象所属横带框的颜色) + [边框绘制/frame_drawing · 中点划分归属](创新：带的划分依据对象行位置，但带的颜色来自孔洞计数而非对象原色)

**来源原语**：计数/孔洞数映射颜色/前景对象/封闭背景区域(37d3e8b2)、边框绘制/中点划分归属/单像素标记/横带(0f63c0b9)、按行排序(0f63c0b9)

**依赖链**：每个前景对象的封闭孔洞数→映射为颜色→该颜色用于绘制该对象所属横带的边框。对象的行位置→中点划分→确定横带范围→横带范围+孔洞映射颜色共同确定输出。颜色来自计数，几何来自位置，二者在带框绘制时汇合。

统计每个前景对象中封闭孔洞的数量以确定颜色，再根据对象行位置通过中点划分确定横带范围，用该颜色绘制横带的边框。

**输入结构**：约 20x14 的网格，背景为黑(0)。包含 3~4 个灰(5)色的 4-连通前景对象，每个对象为不规则实心形状（约 3x4 至 5x6 像素），内部含有 1~3 个封闭的黑(0)背景孔洞（每个孔洞为 1~2 像素的 4-连通区域）。不同对象的孔洞数量各不相同。对象分布在不同行高度，任意两个对象的行范围不重叠（边界框行范围无交集）。生成约束：每个对象的孔洞数唯一（如一个 1 孔、一个 2 孔、一个 3 孔）。

**规则**：
1. 对每个灰(5)前景对象，计算其内部封闭的 4-连通黑(0)背景区域的数量。
2. 孔洞数映射颜色：1 个孔洞→蓝(1)、2 个孔洞→红(2)、3 个孔洞→绿(3)。
3. 确定每个对象的"锚行"——该对象边界框的垂直中心行（若边界框高度为偶数，取靠上的那行）。
4. 按锚行从上到下排序所有对象。相邻两个对象的锚行中点作为横带的分界行。最顶部的带从第 0 行开始，最底部的带到最后一行结束。
5. 对每个对象的横带，用该对象的孔洞映射颜色绘制全宽边框：
   - 绘制锚行为该颜色的全宽横线（覆盖该行全部像素）。
   - 绘制该横带内最左列（列 0）和最右列（最后一列）为该颜色的竖线。
   - 若横带包含网格顶行（第 0 行），则该顶行也绘制为全宽横线。
   - 若横带包含网格底行（最后一行），则该底行也绘制为全宽横线。
6. 原前景对象的灰(5)像素在输出中被擦除（设为黑(0)），仅保留边框。
7. 绘制顺序按对象从上到下；若边框像素重叠（仅在列 0 和最后一列的分界行可能发生），后绘制的覆盖先绘制的。

**关键洞察**：输出中完全看不到原始对象的形状——对象被擦除，只留下由孔洞数决定颜色的横带框。求解者必须意识到对象本身是"一次性"的信息源，其形状仅用于计数，其位置仅用于划分带域。

**组合逻辑**：[解码/decode](创新：解码结果不用于绘制路径，而作为投影参数) + [投影/project · 接触边决定投影](创新：投影深度/方式由字形指令而非颜色决定) + [擦除/erase](已有，灰方块擦除)

**来源原语**：解码/字形/弯头决定偏移/顺序排列(e6de6e8f)、投影/擦除/小方块/标记像素/接触边决定投影/颜色决定投影深度(e39e9282)

**依赖链**：字形条解码为指令序列→指令按从左到右顺序一一对应各标记-方块对→每条指令决定该对的投影方式（近边/中线/偏移）。解码环节缺失则投影规则不确定；投影对象缺失则解码无处施加。

**输入结构**：约 18x18 的网格，背景为黑(0)。网格底部两行为红(2)像素组成的字形指令条（与 e6de6e8f 格式一致），包含 3~4 个字形，从左到右排列。网格上方区域包含 3~4 对"标记-方块"组合：每对由一个栗(9)单像素标记和一个 3x3 的实心方块组成，标记紧邻方块的某一条边（上/下/左/右）。方块颜色从灰(5)和品红(6)中选取，但在本题中方块颜色不决定投影方式。标记-方块对按照其中心列从左到右排序后，与字形序列一一对应。生成约束：字形数量等于标记-方块对数量；各对之间互不接触。

**规则**：
1. 解码底部字形条：竖直字形（单列两行红(2)）解码为"近边投影"；弯头字形中缺口在左侧解码为"中线投影"；缺口在右侧解码为"偏移投影"。
2. 按中心列从左到右排序所有标记-方块对，获得有序列表 P1, P2, ..., Pn。
3. 字形指令序列 I1, I2, ..., In 与标记-方块对一一对应。
4. 对每对 Pk，确定标记接触方块的边（上/下/左/右），然后执行对应指令 Ik：
   - 近边投影：将标记颜色栗(9)印在方块内距接触边最近的一行/列的对应位置（与标记在接触边上的坐标对齐）。

5. 投影完成后，灰(5)方块被擦除（所有灰(5)像素设为黑(0)），品红(6)方块保留。但两种方块内的栗(9)投影像素均保留。
6. 原标记像素：若对应方块被擦除（灰(5)），标记保留；若方块保留（品红(6)），标记擦除。
7. 输出不包含底部字形指令条（裁去底部两行）。

**关键洞察**：投影方式不再由方块颜色编码（与 e39e9282 不同），而由一组空间分离的字形指令控制；求解者必须发现字形条与标记-方块对之间隐含的从左到右配对关系。

## 新题 10：奇偶过滤的层序提取

**组合逻辑**：[最高层提取/extract_top_layer · 交叉可见色为上层](已有) + [填充/fill · 坐标奇偶匹配](创新：奇偶格点不用于填充背景，而作为空间过滤器筛选参与层序竞争的条) + [层序推断/infer_layer_order](已有)

**来源原语**：最高层提取/全幅条/正交交叉/交叉可见色为上层(1a2e2828)、填充/奇偶格点/坐标奇偶匹配/同奇偶背景涂色(d492a647)、标记像素(d492a647)

**依赖链**：标记像素的坐标奇偶定义一个格点→仅通过该格点的全幅条参与层序竞争→在通过格点的条中推断层序→提取最高层颜色。奇偶过滤和层序推断互相依赖：不知道哪些条参与就不能推断层序，不知道标记奇偶就不能确定参与者。

用标记像素的坐标奇偶过滤全幅条，在通过同奇偶格点的条中推断遮挡层序并输出最高层颜色。

**输入结构**：约 15x15 的网格，背景为黑(0)。包含 4~6 条全幅条：每条或为全宽水平条（高度 1 像素，跨整个网格宽度）或为全高垂直条（宽度 1 像素，跨整个网格高度）。每条颜色不同，从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中选取。水平条与垂直条正交交叉时，交叉像素显示较高层条的颜色。在网格中任一不与条重叠的黑(0)背景像素位置，放置一个灰(5)单像素标记。生成约束：至少 2 条水平条和 2 条垂直条；通过标记行/列奇偶格点的条不少于 3 条（保证过滤后层序仍可推断）；标记不位于任何条上；过滤后的条集合中存在唯一的最高层。

**规则**：
1. 记录灰(5)标记像素的位置 (rm, cm)，确定行奇偶 (rm mod 2) 和列奇偶 (cm mod 2)。
2. 对每条水平条，其所在行为 rh。若 rh mod 2 等于 rm mod 2，则该水平条"通过"行奇偶格点，被选入候选集。
3. 对每条垂直条，其所在列为 cv。若 cv mod 2 等于 cm mod 2，则该垂直条"通过"列奇偶格点，被选入候选集。
4. 在候选集的条中推断层序：对候选集中每对水平条与垂直条的交叉位置，检查可见颜色。可见颜色对应的条在另一条之上。传递闭包得到候选集内的完整层序。
5. 输出为 1x1 网格，内容为候选集中层序最高的条的颜色。

**关键洞察**：全局最高层条可能不通过标记的奇偶格点——因此答案不是全局最高层，而是奇偶过滤后子集的局部最高层。求解者必须先理解奇偶过滤再做层序推断，两步的顺序不可逆转。

## 新题 11：角点占用分类驱动的选择性旋转

**组合逻辑**：[分类/classification · 角点占用映射标签](创新：分类结果不直接输出为 1x1 标签，而作为每个对象的旋转量参数) + [旋转/rotate](创新：旋转量由对象的角点占用分类决定) + [印章覆盖/stamp_overlay](已有，将旋转后的对象印回原位)

**来源原语**：分类/计数/角点占用映射标签/掩码图案/角点(27a28665)、旋转/整图半周旋转(6150a2bd)、印章覆盖(92e50de0)、重涂色(多题)

**依赖链**：每个对象的边界框角点占用情况→分类为旋转量（0/90/180/270）→按该旋转量旋转对象的内容→将旋转结果印回原位。分类和旋转紧耦合：分类结果直接参数化旋转操作，而非产生一个颜色标签。

检查每个前景对象边界框四角的占用情况进行分类，分类结果决定该对象需旋转的角度，将旋转后的对象印回原位。

**输入结构**：约 16x16 的网格，背景为黑(0)。包含 3~5 个不重叠的单色前景对象（颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取），每个对象为 4-连通的不规则形状，像素数在 4~8 之间，边界框为 3x3。每个对象占据其 3x3 边界框中的恰好 5 个像素（与 27a28665 的五像素掩码一致），其中有 0~4 个像素位于边界框的四个角。不同对象的角点占用数量不全相同。对象之间间隔至少 2 个像素，确保旋转后不互相重叠。生成约束：每个 3x3 边界框在旋转后仍位于网格内部；至少出现两种不同的角点占用数量。

**规则**：
1. 对每个前景对象，提取其 3x3 边界框内的掩码（5 个像素）。
2. 计算掩码占据边界框四个角（左上、右上、左下、右下）的数量 n。
3. 角点数映射旋转量：n=0→不旋转(0 度)、n=1→顺时针 90 度、n=2→180 度、n=3→顺时针 270 度、n=4→不旋转(0 度)。
4. 将该对象的 3x3 掩码绕其中心按映射的角度旋转。
5. 将旋转后的掩码用对象原色印回原边界框位置（旋转不改变边界框位置，仅改变内部像素分布）。
6. 背景保持黑(0)不变。

**关键洞察**：角点占用数量不直接输出为颜色标签（与 27a28665 的直接映射不同），而是隐蔽地编码了旋转参数——求解者必须在多个示例中对比同一角点数的对象旋转前后的变化，才能归纳出角点数→旋转量的映射表。

## 新题 12：对角标记定矩形与地形轮廓的交集填充

**组合逻辑**：[连线/draw_line · 对角标记定矩形](已有) + [地形轮廓/terrain_contour](创新：地形不用于找极值列，而作为填充区域的遮罩) + [填充/fill](创新：仅填充矩形内部与地形空域的交集)

**来源原语**：连线/填充/标记像素/矩形/行列分割线/对角标记定矩形(21f83797)、地形轮廓/列高度极值(e45ef808)、分隔行(e45ef808)

**依赖链**：两个标记像素定义矩形的对角→延伸标记行列为分割线→矩形内部应被填充→但地形轮廓遮罩限制了实际填充范围（仅填充地形表面之上的部分）。矩形定义和地形遮罩共同约束填充区域，缺一不可。

用两个标记像素定义矩形并绘制行列分割线，但矩形内部仅在地形轮廓之上的空域部分填充颜色。

**输入结构**：约 16x16 的网格，背景为黑(0)。底部若干行为栗(9)像素组成的地形轮廓（每列从底部向上有连续的栗(9)像素，高度 2~10 行不等）。地形之上的空域中有恰好两个红(2)单像素标记，位于不同行不同列，且两个标记均严格在地形表面之上。生成约束：两个标记定义的矩形内部（严格内部，不含标记所在行列）至少部分位于地形表面之上、至少部分位于地形表面之下或之上，以使遮罩效果可观测。

**规则**：
1. 两个红(2)标记像素确定对角矩形的两个对角顶点。
2. 将两个标记所在的行绘制为全宽红(2)横线，两个标记所在的列绘制为全高红(2)竖线。这四条线构成行列分割线。
3. 确定矩形的严格内部区域（两标记行之间、两标记列之间，不含边界行列）。
4. 对矩形严格内部的每个像素 (r, c)：若该像素严格位于该列地形表面之上（r 小于该列最上方栗(9)像素的行号），则填充为蓝(1)；若该像素位于地形表面或之下，则保持该像素的原色（栗(9)或黑(0)）不变。
5. 行列分割线覆盖一切：无论位置在地形之上还是之下，分割线像素均为红(2)。
6. 地形轮廓中未被分割线覆盖的像素保持栗(9)不变。

**关键洞察**：蓝色填充不是简单的矩形——它被地形轮廓"切割"成不规则形状。求解者必须同时理解矩形定义规则和地形遮罩规则，任一规则单独都不能解释输出中蓝色区域的形状。
