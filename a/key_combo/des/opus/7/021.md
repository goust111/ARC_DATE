## 新题 1：色带压缩对角编码

**组合逻辑**：[压缩(compress)](已有) + [计数(counting)](已有) + [对角线输出(diagonal_output)](创新：对角线不再只填单色，而是按压缩色序逐格赋色) → 压缩提供有序色序和长度，长度决定网格边长，色序填入对角线

**来源原语**：压缩(compress)、条带方向(stripe_orient)、连续重复折叠(dup_collapsed) ← 746b3537；计数(counting)、数量决定边长(count_determines_side)、对角线标记(diagonal_marker)、对角线输出(diagonal_output) ← d0f5fe59

**依赖链**：压缩操作同时产出两个结果——有序色序列和序列长度 N；N 决定输出网格的尺寸（N×N），色序列决定对角线上每格的颜色。删除压缩则无法得知 N 和色序；删除对角编码则无法生成输出布局。

将全宽色带压缩为去重色序，以序列长度为边长构建方阵，将色序逐格写入主对角线。

**输入结构**：
- 网格约 12×6 至 20×6，背景无特定颜色——整个网格被全宽水平色带（每条色带颜色均匀、宽度 1-4 行不等）完全覆盖，无背景暴露。
- 色带颜色从上到下依次排列，相邻色带颜色不同，共使用 3-6 种不同颜色，如蓝(1)、红(2)、绿(3)、黄(4)、灰(5)。
- 同一颜色可在不同位置多次出现（即色带序列可能为 A-B-A-C 形式）。
- 生成约束：色带总数（折叠后去重计数）不超过 8，确保输出方阵尺寸合理。

**规则**：
1. 检测色带方向（此处为水平全宽色带）。
2. 从上到下遍历行，将连续相同颜色的行折叠为一个条目，得到压缩色序列（如厚度为 3 的红色带仍只算一个红色条目）。
3. 记压缩后的色带数量为 N。
4. 输出一个 N×N 的方阵，背景填充黑(0)。
5. 主对角线（从左上到右下，即位置 (0,0)、(1,1)、...、(N-1,N-1)）上第 i 格填入压缩色序列的第 i 个颜色。

**关键洞察**：色带的厚度是完全冗余的信息——不同示例中同一色带可能有不同厚度但产出相同的压缩序列。必须对比多个示例才能确认厚度不影响结果，且色序是逐格映射到对角线而非单一颜色填充。

## 新题 2：重叠空心框遮挡深度提取

**组合逻辑**：[分类(classify)](已有) + [排序(sorting)](创新：排序键不是空间位置，而是从像素遮挡关系中推断的深度序) → 分类区分框体，遮挡分析确定深度，深度序驱动输出

**来源原语**：空心矩形(hollow_rectangle)、仅保留空心对象(hollow_only_retained) ← a680ac02；分类(classify)、内部判定类型(interior_determines_type) ← 2ba387bc；排序(sorting)、拼接(concatenate) ← a680ac02 / 67636eac；接触判定(contact_detection) ← 0d87d2a6

**依赖链**：首先必须识别各框的完整边界（包括被遮挡部分），然后从重叠区域的可见颜色推断深度顺序——哪个框在最上层。深度推断依赖于框的识别，而输出排列依赖于深度推断。三步紧密耦合：框识别 → 遮挡分析 → 深度序输出。

从多个相互重叠的单色空心矩形框中推断前后遮挡顺序，输出一行按从前到后深度排列的颜色序列。

**输入结构**：
- 网格约 12×12 至 16×16，背景黑(0)。
- 3-5 个单色空心矩形框（边框宽度 1 像素，内部为黑(0)）散布在网格上，每个框颜色不同，如红(2)、绿(3)、蓝(1)、黄(4)、橙(7)。
- 框的尺寸不同（边界框约 4×4 至 8×8），彼此部分重叠。在重叠区域，只有最上层（最前方）框的像素可见，被遮挡框的对应像素不显示。
- 每个框至少有一段边框完全可见（未被任何其他框遮挡），确保每个框的颜色可识别。
- 生成约束：遮挡关系构成全序（不存在循环遮挡，如 A 盖 B、B 盖 C、C 盖 A），确保深度序唯一确定。

**规则**：
1. 识别所有不同颜色的空心矩形框。每个框由其边框颜色标识。
2. 对任意两个重叠的框 X 和 Y，检查重叠区域中可见的像素颜色：若重叠区域显示 X 的颜色，则 X 在 Y 之上。
3. 根据所有两两比较的结果，构建从最前（最上层）到最后（最底层）的完整深度序。
4. 输出为单行网格（1×K，K 为框的数量），从左到右依次填入各框颜色，按照从最前到最后的深度顺序排列。

**关键洞察**：框的空间位置（上下左右）与深度顺序无关——一个位于网格底部的框可能遮挡位于网格顶部的框。必须从重叠处的像素可见性推断遮挡关系，而非从框的坐标推断。这一规则需对比多个示例才能排除"位置决定深度"的错误假设。

## 新题 3：边界标记选择性镜像打包

**组合逻辑**：[连线/边界定位(boundary_pos)](已有) → [裁剪(crop)](已有) + [镜像(mirror)](创新：镜像与否由标记所在边决定) → [拼接(concatenate)](已有)

**来源原语**：标记像素(marker_pixel)、画布边界(canvas_boundary)、边界定位(boundary_pos)、边界标记定贯穿线(boundary_marker_span) ← 6cdd2623；裁剪(crop)、拼接(concatenate)、布局轴方向(layout_axis_direction)、按位置紧密排列(tight_packing_by_position) ← 67636eac；镜像(mirror)、翻转后粘贴(flipped_before_paste) ← 9f27f097

**依赖链**：边界标记通过列对齐选中精灵（选择依赖），标记在顶边还是底边决定该精灵是否镜像（条件分支依赖），最终按标记的列顺序拼接裁剪结果（排列依赖）。三重依赖缺一不可。

根据网格顶/底边界上的标记像素选中对应列下方的精灵，按标记所在边决定是否垂直镜像，最后按标记列顺序水平拼接。

**输入结构**：
- 网格约 15×15，背景黑(0)。
- 网格内部散布 4-6 个单色 8-连通精灵，每个精灵颜色不同，边界框约 3×3 至 4×4，精灵之间互不重叠且互不相邻。
- 网格的第一行（顶边）和最后一行（底边）上分别有若干灰(5)标记像素。每个标记像素的列坐标恰好落在某个精灵的边界框列范围内。每个精灵最多被一个标记选中，每个标记恰好选中一个精灵。
- 未被任何标记列覆盖的精灵是干扰项。
- 生成约束：标记总数等于需要输出的精灵数（3-5 个），且每个标记的列范围不会同时覆盖两个精灵。

**规则**：
1. 找到顶边和底边上所有灰(5)标记像素。
2. 对每个标记，找到其列坐标与之重叠的精灵（标记列落在精灵边界框的列范围内）。
3. 若标记在顶边：裁剪该精灵的边界框，保持原样（不镜像）。
4. 若标记在底边：裁剪该精灵的边界框，将裁剪结果上下镜像（垂直翻转）。
5. 按标记像素的列坐标从左到右排序。
6. 将所有裁剪结果（经过或未经过镜像的）按此顺序水平拼接，相邻裁剪之间无间隔。若裁剪高度不同，顶部对齐，短的一侧用黑(0)填充。
7. 未被选中的精灵在输出中不出现。

**关键洞察**：边界标记的作用不是定义贯穿线（源题用法），而是同时承担两个功能——选择目标精灵和编码变换类型（顶边=保持，底边=镜像）。需对比多个示例才能区分"选择"和"镜像条件"这两层语义。

## 新题 4：控制色分组投票模板恢复

**组合逻辑**：[分类(classify)](创新：按控制像素颜色分组，而非按形状类型) + [投票恢复(majority_vote_recovery)](创新：分组投票而非全局投票) → [印章覆盖(stamp)](已有)

**来源原语**：投票恢复(majority_vote_recovery)、插槽阵列(slot_array)、密集带检测(dense_band_detection) ← 0607ce86；控制像素(control_pixel)、颜色映射模板(color_template_map) ← c64f1187；印章覆盖(stamp) ← 9f27f097 / c64f1187

**依赖链**：控制像素颜色将插槽分成若干组（分类依赖），每组内部独立进行多数投票以恢复该组的干净模板（投票依赖于分类），恢复后的模板替换原有噪声副本（印章依赖于投票结果）。分类错误导致投票混入异类样本，投票失败导致印章内容错误。

将插槽阵列中的噪声模式按控制像素颜色分组，每组通过多数投票恢复各自的干净模板，再用恢复的模板替换所有噪声副本。

**输入结构**：
- 网格约 18×18，背景黑(0)。
- 前景像素构成一个规则的矩形插槽阵列（如 3×4 的阵列），插槽间由 1 像素宽的黑(0)间隔分隔。每个插槽为 3×3 或 4×4 的小矩形。
- 每个插槽内包含一个由灰(5)像素组成的噪声图案——这是某个模板的损坏副本（个别像素可能被随机翻转为黑(0)或灰(5)）。
- 每个插槽的左上角有一个控制像素，颜色为红(2)、蓝(1)或绿(3)。同一控制颜色的所有插槽实际上共享同一个底层模板，但每个副本有独立的随机噪声。
- 不同控制颜色对应不同的底层模板（灰色像素的占据位置不同）。
- 生成约束：每种控制颜色至少对应 3 个插槽，且噪声比例不超过 25%（确保多数投票能正确恢复）。

**规则**：
1. 定位插槽阵列：找到规则排列的矩形插槽集合。
2. 读取每个插槽左上角的控制像素颜色。
3. 将插槽按控制颜色分组。
4. 对每组，在插槽内的每个相对位置（排除左上角控制像素位置），统计该位置在组内所有插槽中的多数颜色（黑(0)或灰(5)）。以多数颜色作为该位置的恢复值。
5. 用组内恢复的干净模板替换该组每个插槽的内容（左上角控制像素保留不变）。

**关键洞察**：与源题（全局单模板投票）不同，这里存在多种底层模板，必须先正确分组才能投票。分组的依据是控制像素颜色——这个信息必须通过对比多个示例来确认，因为从单个示例中无法排除"按位置分组"或"按灰色像素数量分组"等替代假设。

## 新题 5：计数器门控对角约束拼合

**组合逻辑**：[计数(counting)](已有) → [对角线输出(diagonal_output)](创新：对角线不是最终输出，而是拼合的禁止区) + [拼合填充(packing)](创新：必须绕开对角线约束)

**来源原语**：计数(counting)、计数器像素(counter_pixel)、计数器消失(counter_disappears)、计数决定偏移(count_determines_offset) ← e48d4e1a；对角线标记(diagonal_marker)、数量决定边长(count_determines_side)、对角线输出(diagonal_output) ← d0f5fe59；多连块碎片(polyomino_fragment)、拼合填充(packing)、无重叠拼合(non_overlap_packing)、按面积降序放置(descending_area_place) ← b7cb93ac

**依赖链**：计数器决定输出方阵边长 N（尺寸依赖），N 决定对角线位置（约束依赖），对角线作为禁止区约束拼合操作的可用空间（拼合依赖于前两步）。删除计数则无法确定网格大小；删除对角约束则拼合退化为源题的无约束版本。

统计灰色计数器像素得 N，构建 N×N 方阵，将主对角线标记为禁区（填灰色），再将散落的多连块碎片无重叠地拼入非对角线区域。

**输入结构**：
- 网格约 14×14，背景黑(0)。
- 网格最右列包含若干灰(5)像素（从顶部开始连续排列），数量为 N（4-6）。其余最右列位置为黑(0)。
- 网格其余区域散布若干单色 4-连通多连块碎片（每块 2-5 像素），每块颜色不同，如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)。碎片互不重叠、互不相邻。
- 生成约束：所有碎片的总面积恰好等于 N×N - N（即方阵面积减去对角线格数），确保拼合恰好填满。

**规则**：
1. 统计最右列中灰(5)像素的数量，记为 N。
2. 构建一个 N×N 的输出方阵，初始全黑(0)。
3. 将主对角线位置（(0,0)、(1,1)、...、(N-1,N-1)）填入灰(5)，这些位置不可放置碎片。
4. 将碎片按面积从大到小排序；面积相同时，按碎片在输入中的边界框左上角位置从左到右、从上到下排序。
5. 按排序顺序，对每个碎片尝试其原始方向以及 90°/180°/270° 旋转和水平镜像的所有朝向（共最多 8 种），在输出方阵的非对角线空位中从上到下、从左到右扫描第一个可放置位置，放入碎片。
6. 最右列的灰色计数器像素在输出中消失（不出现在输出网格中）。

**关键洞察**：对角线在源题中是最终输出内容，但这里它是拼合过程中的几何障碍。计数器的数值同时决定了两个相互依赖的约束——棋盘大小和障碍物位置。需要对比多个示例确认对角线是固定禁区（而非某种动态障碍）以及计数器与棋盘边长的等量关系。

## 新题 6：类型分支对齐重涂色

**组合逻辑**：[分类(classify)](已有) + [行列对齐(row_col_align)](已有) + [重涂色(recolor)](创新：重涂色方式由对象类型决定——同一颜色信号在不同类型对象上产生不同视觉效果)

**来源原语**：分类(classify)、空心矩形(hollow_rectangle)、实心方块(solid_square)、内部判定类型(interior_determines_type) ← 2ba387bc；重涂色(recolor)、分隔线网格(separator_grid)、行列对齐(row_col_align)、对齐标记定颜色(aligned_marker_color)、单像素标记(singleton_marker) ← ef26cbf6

在分隔线网格中，按行/列对齐找到颜色标记，将标记色应用于同行/列的对象——但空心框只重涂边框像素，实心块整体重涂。

**输入结构**：
- 网格约 15×15，背景黑(0)。
- 灰(5)像素构成完整的水平和垂直分隔线，将网格划分为 3×3 或 4×4 的规则单元格阵列。每个单元格内部约 3×3。
- 部分单元格内包含一个居中的 3×3 对象：要么是空心矩形框（外圈一种颜色、内部 1×1 为黑(0)），要么是 3×3 的实心方块（全部填充同一种颜色）。这些对象初始颜色统一为白/栗(9)。
- 每行（或每列）的单元格中恰好有一个"标记单元格"，其中只包含一个单像素标记点，颜色为红(2)、蓝(1)、绿(3)或黄(4)中的某一种。
- 其余单元格为空（全黑(0)）。
- 生成约束：每个包含对象的单元格所在行或列中恰好有一个标记单元格（不会同时在行和列中各有一个标记），确保颜色指定唯一。

**规则**：
1. 找到灰(5)分隔线划分的单元格阵列。
2. 识别每个单元格的内容类型：空心框、实心块、单像素标记或空。
3. 对每个包含空心框或实心块的单元格，找到与之同行或同列的那个标记单元格，读取标记颜色 C。
4. 若该对象是空心框：将边框像素（外圈）重涂为颜色 C，内部保持黑(0)。
5. 若该对象是实心块：将全部 3×3 像素重涂为颜色 C。
6. 分隔线和标记像素在输出中保持不变。

**关键洞察**：同一套对齐机制（行/列对齐找标记色）对不同类型的对象产生不同的涂色效果。从单个示例中，如果所有对象恰好都是同一类型，则无法发现类型分支规则。必须看到两种类型并存的示例才能归纳出完整规则。

## 新题 7：路径长度排序精灵压缩堆叠

**组合逻辑**：[端到端遍历(endpoint_traversal)](创新：遍历目的不是反转颜色，而是测量路径长度) → [排序(sorting)](创新：排序键是路径长度而非空间位置) → [压缩(compress)](创新：压缩对象是二维精灵而非一维色带) + [堆叠(stack)](已有)

**来源原语**：单像素宽路径(one_pixel_path)、端点像素(endpoint_pixel)、端到端遍历(endpoint_traversal) ← 5792cb4d；排序(sorting)、沿主轴排列(along_main_axis) ← a680ac02；压缩(compress)、连续重复折叠(dup_collapsed) ← 746b3537；堆叠(stack) ← 2ba387bc；连通精灵(connected_sprite)、裁剪(crop) ← 67636eac

**依赖链**：路径遍历测量每条路径的长度（信息提取），路径长度作为排序键对各精灵排序（长度→排序的跨域映射），排序后的精灵被逐行压缩并堆叠为输出（压缩+堆叠依赖于排序顺序）。删除路径遍历则无排序依据，删除排序则输出顺序不确定，删除压缩则输出维度不匹配。

每个精灵通过一条单像素路径连接到网格边界；测量各路径长度，按长度升序对精灵排序，将每个精灵水平压缩为单列后垂直堆叠。

**输入结构**：
- 网格约 20×20，背景黑(0)。
- 3-5 个单色 4-连通精灵（每个 4-8 像素，颜色各不相同，如红(2)、蓝(1)、绿(3)、黄(4)），散布在网格中部。每个精灵的边界框约 2×3 至 3×4，形状不规则（非矩形，具体形状因示例而异）。
- 每个精灵恰好有一个像素与一条灰(5)的单像素宽 4-连通路径相邻。该路径无分叉，从精灵旁延伸到网格边界的某个边缘像素。不同路径长度不同（2-8 像素）且互不接触。
- 生成约束：所有精灵边界框的行数相同（如都是 3 行高），列数可不同。各路径长度两两不同，确保排序无歧义。

**规则**：
1. 识别所有灰(5)路径。每条路径的一端连接某个精灵（与精灵 4-相邻），另一端在网格边界。
2. 对每条路径，从边界端点沿路径走到精灵端，统计路径像素数量即为路径长度。
3. 按路径长度从小到大排序对应的精灵。
4. 对每个精灵，裁剪其边界框。将裁剪结果按列压缩：对每一行，取该行中出现的非黑颜色（精灵颜色）和黑(0)，保留精灵颜色的像素个数作为该行的"密度值"——实际操作为将每行折叠为单个像素，颜色为该行中精灵颜色出现次数 >= 1 则为精灵色，否则为黑(0)。
5. 将所有压缩后的单列结果（每列高度相同）按排序顺序从左到右水平拼接为输出。
6. 灰(5)路径在输出中消失。

**关键洞察**：路径在源题中承载颜色序列信息，但这里路径仅作为度量工具——其长度编码了排序优先级。排序键不在精灵自身的可见属性中，而在精灵外部的连接结构中。单个示例可能偶然吻合多种排序假设（如按精灵面积、按颜色），需要多个示例排除干扰。

## 新题 8：缩放因子驱动旋转与锚点校准

**组合逻辑**：[缩放(scale)](创新：缩放因子不用于缩放操作本身，而是作为旋转次数的参数) + [旋转(rotation)](已有) + [对齐(align)/锚点区域(anchor_region)](创新：锚点校准从原型替换场景迁移到旋转场景)

**来源原语**：缩放(scale)、原型精灵(prototype_sprite)、锚点区域(anchor_region)、原型配对(prototype_pairing) ← c7f57c3e；旋转(rotation) ← b7cb93ac；对齐(align)、锚点像素(anchor_pixel)、对齐到锚点(aligned_to_anchor) ← e41c6fd3

**依赖链**：必须先识别每个精灵是原型的几倍缩放（缩放因子提取），缩放因子 mod 4 决定顺时针旋转次数（跨域参数映射），旋转后锚点区域必须对齐回原位（旋转与对齐耦合）。缩放因子同时承担"分类标签"（哪些是同因子组）和"旋转参数"两个角色。

识别每个精灵相对于原型的缩放因子，将精灵顺时针旋转（缩放因子 mod 4）× 90 度，旋转后将精灵重新定位使其内部锚点区域回到原始坐标。

**输入结构**：
- 网格约 20×20，背景黑(0)。
- 一个 2×2 或 3×3 的原型图案由多种前景色组成（如红(2)和蓝(1)像素的组合），其中恰好有一个像素是特殊的锚点色黄(4)。
- 网格上分布 3-5 个该原型的缩放副本，缩放因子为 1、2、3 或 4（即 1 倍大小的副本尺寸等于原型，2 倍副本每个像素扩展为 2×2 块，以此类推）。各副本互不重叠。
- 原型本身也作为一个 1 倍副本出现在网格中。
- 每个副本内部的黄(4)锚点区域（1 倍时为单像素，2 倍时为 2×2 块，以此类推）标记了对齐参考点。
- 生成约束：所有副本旋转后不会超出网格边界；不同副本的锚点区域在旋转后不会重叠。

**规则**：
1. 找到最小的前景精灵副本，确认其为 1 倍原型（或从只出现一次的最小重复模式推断原型）。
2. 对每个精灵副本，将其与原型比对，确定缩放因子 S。
3. 计算旋转次数 R = S mod 4（S=1 → 旋转 1 次即 90°，S=2 → 旋转 2 次即 180°，S=3 → 旋转 3 次即 270°，S=4 → 旋转 0 次即不旋转）。
4. 记录该副本内黄(4)锚点区域的左上角原始坐标 (ar, ac)。
5. 将该副本以其中心为旋转中心，顺时针旋转 R × 90°。
6. 旋转后，平移整个副本使其黄(4)锚点区域的左上角回到 (ar, ac)。
7. 所有副本处理完毕后，在黑(0)背景的同尺寸画布上绘制全部旋转并重定位后的副本。

**关键洞察**：缩放因子在源题中是被保留的几何属性（缩放多少就保持多少），但这里它被"挪用"为另一种变换（旋转）的控制参数。锚点机制从"替换时保位"变成了"旋转后归位"。必须对比多个不同缩放因子的副本才能发现 S mod 4 = 旋转次数这个隐蔽映射。

## 新题 9：密集带检测逐槽镜像展开

**组合逻辑**：[密集带检测(dense_band_detection)](已有) → [镜像(mirror)](创新：不是整体镜像拼接，而是对每个独立槽内容做四方向镜像) + [阵列排布(array_layout)](创新：原始阵列结构保留但每个单元膨胀)

通过行列密集带检测定位噪声网格中的插槽阵列，提取每个槽的内容图案，将每个图案做 2×2 对称镜像展开后按原始阵列布局拼回。

**输入结构**：
- 网格约 16×16，背景黑(0)。
- 前景像素构成一个规则的行列插槽阵列（如 3×3 阵列），但存在稀疏的随机噪声像素散布在阵列之外。
- 每个插槽为 3×3 的小区域，内含 2-5 个非黑像素构成的小图案（颜色为蓝(1)或红(2)等，同一插槽内只用一种颜色）。
- 不同插槽的图案互不相同（与源题中所有槽包含同一模板的损坏副本不同）。
- 密集行带和密集列带定义了插槽的行列位置（与 0607ce86 的检测方法相同）。
- 生成约束：噪声像素密度远低于插槽区域密度，确保密集带检测不被干扰。

**规则**：
1. 通过行密度和列密度检测找到密集行带和密集列带。它们的笛卡尔积定义了插槽位置。
2. 忽略所有不在插槽位置内的噪声像素。
3. 提取每个插槽的 3×3 内容图案 P。
4. 对每个 P，构建 6×6 的镜像展开块：左上 = P 原样，右上 = P 水平镜像，左下 = P 垂直镜像，右下 = P 水平+垂直镜像（即 180° 旋转）。
5. 将所有展开块按原始阵列布局排列（保持行列顺序），相邻块之间有 1 像素宽的黑(0)分隔。
6. 输出即为该重排后的网格。

**关键洞察**：密集带检测在源题中服务于"投票恢复同一模板"，但这里每个槽内容各不相同，检测的目的从"去噪恢复"变为"定位提取"。镜像展开的 2×2 对称模式需要对比多个示例才能确认：单个示例中可能看似是简单的 2 倍缩放，但多个示例证明是四方向镜像拼合。

## 新题 10：位置镜像与逆缩放耦合

**组合逻辑**：[镜像位置(mirrored_position)](已有) + [缩放(scale)](创新：缩放因子不是保持而是取逆——小变大、大变小) → 位置镜像和尺寸反转同时作用于每个精灵

**来源原语**：镜像位置(mirrored_position)、平移(translate)、内部朝向不变(orientation_preserved) ← 8ee62060；缩放(scale)、原型精灵(prototype_sprite) ← c7f57c3e；形状匹配(shape_match) ← 9f27f097

**依赖链**：必须先识别所有精灵共享同一原型的不同缩放版本（形状匹配+缩放因子提取），再将位置水平镜像（位置变换），同时将缩放因子取逆（尺寸变换）。位置镜像和逆缩放必须同时完成——只做位置镜像会导致大精灵放在原来小精灵的位置却放不下，只做逆缩放不改变位置则布局不变。两个变换互为对方的空间前提。

将同一原型的多个缩放副本水平镜像到画布对称位置，同时将每个副本的缩放因子取逆（最大倍率变最小、最小变最大），保持精灵内部朝向不变。

**输入结构**：
- 网格约 18×18，背景黑(0)。
- 存在一个小型原型图案（2×2），由 2-3 种非黑颜色组成（如红(2)和蓝(1)的组合）。
- 网格上分布 3-4 个该原型的缩放副本，缩放因子两两不同，取自 {1, 2, 3}（1 倍 = 2×2, 2 倍 = 4×4, 3 倍 = 6×6）。每个副本颜色与原型一致（缩放时每个像素扩展为 S×S 的同色块）。
- 各副本沿水平方向散布，互不重叠，各副本的垂直中心大致对齐（在同一行带内）。
- 生成约束：设网格宽度为 W，任何副本水平镜像并逆缩放后不会超出网格边界，也不会与其他镜像后的副本重叠。输入中缩放因子的最大值 S_max 已知（等于副本数量，如 3 个副本则 S_max=3），逆缩放因子 = S_max + 1 - S。

**规则**：
1. 识别所有前景精灵并确认它们共享同一原型图案（通过归一化到最小尺寸比对）。
2. 对每个副本，确定其缩放因子 S（边界框边长 / 原型边长）。
3. 找到所有副本中的最大缩放因子 S_max。
4. 对每个副本，计算逆缩放因子 S' = S_max + 1 - S。
5. 构建空白黑(0)画布，尺寸与输入相同。
6. 对每个副本，将其边界框的水平位置镜像到画布对称位置：new_col = W - old_col - old_width（W 为网格宽度），垂直位置保持不变（保持同一行）。
7. 在镜像后的位置，以逆缩放因子 S' 重新缩放原型并绘制（S' 倍缩放版本的左上角放在镜像后计算的新位置，垂直居中于原副本所在的行带中心）。
8. 精灵内部颜色分布（原型图案）保持不变，不做旋转或翻转。

**关键洞察**：源题中位置镜像保持精灵不变地搬到对称位置，源题中缩放因子在原型替换时被保持。这里两者反向耦合——大精灵镜像后变小，小精灵镜像后变大，构成一种"空间守恒"效应。需要多个示例才能确认逆缩放关系 S' = S_max + 1 - S，因为单个示例可能被解读为简单的固定缩放。
