## 新题 1：对称性角色分配与对角辐射着色

**组合逻辑**：[symmetry_filter](创新：从筛选/裁剪变为角色分配机制) + [diagonal_radiation](创新：从单像素发射变为从精灵体包围盒四角发射) + [nearest_distance + recolor](创新：距离计算在精灵体中心之间而非像素与边缘线之间) + [truncate_at_blocker](保留：射线遇到障碍停止)

**来源原语**：symmetry_filter（72ca375d）、diagonal_radiation（ea786f4a）、nearest_distance + recolor（2204b7a8）、truncate_at_blocker（212895b5）

**依赖链**：对称性检测将精灵体分为"辐射源"和"接收目标"两类角色——辐射源的包围盒四角发出对角射线——射线命中接收目标后，目标被重涂为距离最近的辐射源颜色。角色分配决定了谁发射、谁被涂色；射线路径决定了哪些目标被命中；距离比较解决了多源冲突。三者环环相扣，缺一不可。

对称性检测将精灵体分为射线源和涂色目标，射线源从包围盒四角发出对角射线命中目标后将其重涂为最近源的颜色。

**输入结构**：约 15x15 的黑(0)背景网格。网格上散布 5-6 个小型单色 4-连通精灵体（每个 3-6 像素，形态各异——无固定形状名，由连通性和像素数定义），每个精灵体颜色互不相同（使用蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)等非黑色）。其中恰好 2 个精灵体在其包围盒内具有对称性（垂直镜像、水平镜像或 180 度旋转对称中的至少一种），其余精灵体不具有任何此类对称性。所有精灵体互不相邻（包围盒之间至少间隔 2 个像素），且均不接触网格边缘。生成约束：每个非对称精灵体至少被一条来自对称精灵体的对角射线命中。

**规则**：
1. 对每个精灵体在其包围盒内进行对称性检测（测试垂直镜像、水平镜像和 180 度旋转对称三种），满足任意一种即为"辐射源"，否则为"接收目标"。
2. 对每个辐射源，从其包围盒的四个角各发出一条对角射线，方向为远离包围盒中心的方向（左上角 → 向左上延伸、右上角 → 向右上、左下角 → 向左下、右下角 → 向右下）。射线逐像素延伸，遇到网格边缘或任何其他精灵体的像素时停止（不包含终止位置的像素）。
3. 若某"接收目标"精灵体的任一像素恰好位于某条射线路径上，则该目标被该射线的辐射源"命中"。
4. 被命中的目标精灵体整体重涂为命中它的辐射源的颜色。若被两个不同辐射源的射线同时命中，取包围盒中心之间 Manhattan 距离更近的辐射源颜色；若距离相同，取包围盒左上角行号更小的源；行号也相同时取列号更小的源。
5. 辐射源精灵体保持不变。射线本身不绘制在输出中。未被任何射线命中的接收目标保持原色不变。

**关键洞察**：对称性不是筛选输出的标准——它是一个角色分类器。必须先判定对称性才能知道谁是射线发射者、谁是被着色者；这一角色分配在任何单个源题中都不存在。

## 新题 2：缺陷缺口编码方向的面积排名射线

**组合逻辑**：[defect_bar](创新：结构缺陷从"需要修补的瑕疵"变为方向编码器和射线起点) + [marker_indicates_dir](创新：方向信息嵌入在结构缺陷中而非独立标记精灵体中) + [ray_extension + truncate_at_blocker](保留) + [area_comparison → area_rank_maps_color](创新：排名映射射线颜色而非矩形内部填充色)

**来源原语**：defect_bar（9b5080bb）、marker_indicates_dir（99caaf76）、ray_extension + truncate_at_blocker（212895b5）、area_comparison + area_rank_maps_color（694f12f3）

**依赖链**：缺陷位置编码射线方向——射线从缺陷处发出并延伸——射线颜色由矩形的全局面积排名决定——射线在命中其他矩形时截断。方向提取依赖缺陷检测，颜色分配依赖跨对象面积比较，射线终点依赖其他矩形在空间中的位置。

矩形边缘的结构缺口既编码射线方向又是射线起点，射线颜色由全局面积排名而非矩形自身颜色决定。

**输入结构**：约 15x15 的黑(0)背景网格。3-4 个单色实心矩形（每个至少 3x4 像素，行列数各异），每个矩形颜色互不相同（如蓝(1)、品红(6)、橙(7)、青(8)等非黑非红非绿非黄非灰色）。每个矩形恰好缺失一个像素：该缺失像素位于矩形包围盒的某条边上，使得包围盒内有且仅有一个黑(0)像素。矩形之间有充分间距（包围盒之间至少间隔 3 个像素）。生成约束：不同矩形的缺陷分布在不同边上（即不会所有缺口都在顶边）；各矩形包围盒面积互不相等。

**规则**：
1. 对每个矩形，找到其包围盒内唯一的黑(0)像素——即缺陷位置。缺陷所在的边决定射线方向：缺陷在顶边 → 射线向上延伸；缺陷在右边 → 向右；缺陷在底边 → 向下；缺陷在左边 → 向左。若缺陷恰在角上（属于两条边），取短边方向（即矩形较短维度对应的边）。
2. 从缺陷像素位置出发（缺陷位置本身不着色），沿确定方向逐像素延伸射线。射线在遇到网格边缘或另一矩形的任意像素时停止（不包含终止点）。
3. 将所有矩形按包围盒面积（行数 x 列数）从小到大排列。面积排名映射到射线颜色：第 1 名（最小）→ 红(2)、第 2 名 → 绿(3)、第 3 名 → 黄(4)、第 4 名 → 灰(5)。
4. 用排名对应的颜色绘制射线。所有矩形自身（包括缺陷缺口处的黑像素）保持不变。

**关键洞察**：缺陷不是需要修补的瑕疵——它是方向信息的载体和射线的起点。射线颜色与矩形自身颜色完全无关，必须跨矩形做面积排名才能确定对应表，仅看单个示例中一个矩形无法归纳出颜色规则。

## 新题 3：散点三角推断正方形与缺角对角分类填充

**组合逻辑**：[ignore_distractors](创新：干扰物是散布的灰色像素而非独立精灵体) + [corners_define_square + infer_center_from_known_corners](创新：从添加微缩副本变为绘制完整正方形边框并填充内部) + [diagonal_position](创新：对角线位置从排布编码变为填充颜色的分类条件) + [fill](创新：填充颜色取决于缺失角的几何分类而非面积排名)

**来源原语**：corners_define_square + infer_center_from_known_corners（11e1fe23）、ignore_distractors（72ca375d / 0a1d4ef5）、fill（694f12f3）、diagonal_position（11e1fe23）

**依赖链**：干扰排除 → 有效三角点组识别 → 第四角推断和正方形确定 → 缺失角的对角线归属分类 → 填充颜色确定。每一步的输出是下一步的必要输入，且缺失角分类与填充颜色之间的映射需要对比多个正方形（不同缺角位置）才能归纳。

从散点中排除干扰、识别三角点组推断正方形，缺失角落在主对角线还是副对角线决定内部填充色。

**输入结构**：约 18x18 的黑(0)背景网格。散布若干孤立彩色像素。其中 2-3 组同色像素各恰好 3 个，分别构成某个轴对齐正方形的 3 个角（正方形边长至少 5，保证内部面积 >= 9 个像素可供填充）。每组使用不同颜色（如绿(3)、橙(7)、青(8)）。另有 4-6 个灰(5)孤立像素作为干扰，散布在网格中不构成任何有效正方形角点。生成约束：不同组定义的正方形包围盒互不重叠；每个正方形内部区域不含任何其他像素（无灰色干扰也无其他组像素）；各组缺失角的对角线方向有所不同（至少一组缺主对角线角，至少一组缺副对角线角）。

**规则**：
1. 忽略所有灰(5)像素（干扰物）。
2. 将剩余非黑非灰彩色像素按颜色分组。对每组验证：3 个同色像素是否恰好构成某个轴对齐正方形的 3 个角（即存在唯一第 4 点使 4 点构成正方形）。不构成有效三角点的组忽略。
3. 对每个有效组，推断缺失的第 4 角位置。用该组颜色绘制正方形的完整边框（4 条边各 1 像素宽，包含 4 个角点）。原有的 3 个角点像素被边框覆盖（颜色相同所以视觉不变）。
4. 判定缺失角的对角线归属——以正方形自身为参照，左上角和右下角为"主对角线角"，右上角和左下角为"副对角线角"。若缺失角是主对角线角（左上或右下），用红(2)填充正方形内部（边框以内的所有像素）；若缺失角是副对角线角（右上或左下），用蓝(1)填充内部。
5. 灰色干扰像素保留在原位（若干扰像素不在任何正方形内部或边框上，则不受影响）。

**关键洞察**：填充颜色既不取决于角点颜色也不取决于正方形大小——它完全由缺失角的几何位置（主对角线 vs 副对角线）决定。这一分类条件只有在看到多个不同缺角方向的正方形后才能归纳出来。

## 新题 4：尾部编码方向的滑动与阴影轨迹

**组合逻辑**：[marker_indicates_dir](保留：附属像素指示方向) + [translate + reach_edge](创新：精灵体不是滑向尾部方向而是远离尾部方向滑动) + [offset_shadow](创新：阴影不是静态偏移副本而是滑动路径上的运动轨迹) + [truncate_at_blocker](创新：不是射线截断而是滑动碰撞停止，且处理顺序成为隐蔽规则)

**来源原语**：marker_indicates_dir（99caaf76）、translate + reach_edge（99caaf76）、offset_shadow（310f3251）、truncate_at_blocker（212895b5）

**依赖链**：尾部方向解读 → 滑动方向确定 → 碰撞检测（依赖其他精灵体的最终位置，需确定处理顺序）→ 阴影轨迹绘制（依赖原位置和终位置的差）。处理顺序是一个隐蔽规则：离目标边缘更近的精灵体先滑动并先占位，影响后续精灵体的碰撞判定。

精灵体远离尾部滑动至边缘，留下灰色运动轨迹，碰撞时先到达者优先。

**输入结构**：约 12x12 的黑(0)背景网格。3-4 个小型单色 4-连通精灵体（每个 3-5 像素，形态不规则），每个精灵体颜色互不相同（如蓝(1)、红(2)、绿(3)、黄(4)）。每个精灵体在某一侧附着 1 个灰(5)像素（"尾部"），使精灵体本体加尾部构成单个 8-连通组件。尾部像素与精灵体本体的相对位置在上、下、左、右四个方向之一。生成约束：至少有一对精灵体的滑动路径在空间上可能冲突（即它们朝同一区域滑动，若不考虑碰撞会重叠）；各精灵体到其目标边缘的距离互不相等。

**规则**：
1. 确定每个精灵体的滑动方向：精灵体远离尾部方向移动。尾部在上方 → 精灵体向下滑动；尾部在右方 → 向左；尾部在下方 → 向上；尾部在左方 → 向右。
2. 确定处理顺序：计算每个精灵体本体（不含尾部）的前缘到目标网格边缘的距离（以像素计）。距离最小的先处理（离目标边缘最近者先滑动）。
3. 按处理顺序依次滑动每个精灵体本体（不含尾部）：沿滑动方向平移，直到精灵体前缘接触网格边缘或接触已完成滑动的其他精灵体（停在碰撞前一像素位置，不重叠）。
4. 将每个精灵体从原位置到终位置之间滑过的所有空像素涂为灰(5)——运动阴影轨迹。阴影仅覆盖精灵体本体扫过的矩形区域中原本为黑色的像素。
5. 尾部像素被擦除（恢复为黑(0)）。精灵体本体以原色绘制在终位置。
6. 若两条阴影轨迹在空间上重叠，后滑动的精灵体的阴影覆盖先滑动的。

**关键洞察**：尾部是方向密钥且会被消耗。处理顺序（离目标边缘近者先滑动）是一个隐蔽规则——它影响碰撞结果和阴影重叠层级，必须对比含碰撞的不同示例才能归纳出来。

## 新题 5：晶格螺旋可达性重涂色

**组合逻辑**：[lattice_grid](保留：规则晶格结构) + [spiral_drawing](创新：螺旋不是独立绘制几何图形，而是在已有晶格上的遍历算法) + [recolor](创新：重涂色区域由遍历可达性而非行列选择决定) + [truncate_at_blocker](创新：阻断的不是射线而是螺旋遍历路径)

**来源原语**：lattice_grid + marker_row_column_selection（4f537728）、spiral_drawing + origin_positioning（8b28cd80）、recolor（2204b7a8）、truncate_at_blocker（212895b5）

**依赖链**：标记节点确定螺旋起点 → 螺旋按晶格节点位置展开 → 遇到阻断节点时终止遍历 → 所有被遍历到的节点和连接边被重涂色。阻断节点的位置决定了螺旋能到达的范围——距离起点近但在螺旋路径后段的节点可能未被到达，而距离远但在螺旋路径早段的节点会被到达。这一"螺旋序 ≠ 空间距离"的区别是核心非显然规则。

标记节点发起晶格上的方形螺旋遍历，遇阻断节点时停止，被遍历到的节点重涂为标记色。

**输入结构**：约 15x15 的黑(0)背景网格。蓝(1)像素构成规则晶格：节点为 2x2 蓝色方块，节点间距为 3 像素（中心到中心），节点之间由 1 像素宽的蓝色连接线相连（水平和垂直方向）。晶格约为 4x4 = 16 个节点。其中一个节点的 2x2 方块被替换为红(2)（标记节点）。另有 1-2 个节点的 2x2 方块被替换为黄(4)（阻断节点）。其余均为蓝(1)节点和蓝(1)连接线。黑(0)填充所有空隙。生成约束：阻断节点不与标记节点相邻（螺旋至少能展开 2 圈）；阻断节点的位置使得至少有 1 个空间上距离标记较近但螺旋序较晚的蓝色节点未被到达。

**规则**：
1. 将晶格抽象为节点图：每个 2x2 方块是一个节点，节点间连接线是边。标记节点（红色）是螺旋起点。
2. 从标记节点出发，按方形螺旋顺序遍历晶格节点：初始方向向上，然后依次转右。臂长序列为 1, 1, 2, 2, 3, 3, ...（每两个臂长递增 1）。每"一步"是从当前节点移动到相邻节点。
3. 当螺旋下一步将到达一个黄色阻断节点时，终止遍历。阻断节点本身不被访问。若下一步超出晶格边界，跳过该步继续按螺旋方向尝试下一步（仅限跳过边界外的步，不跳过阻断节点）。
4. 将所有被螺旋遍历到的蓝色节点重涂为红(2)（与标记同色），同时将连接相邻已遍历节点的蓝色连接线也重涂为红(2)。
5. 标记节点本身保持红色。阻断节点保持黄色。所有未被遍历到的蓝色节点和连接线保持蓝色不变。

**关键洞察**：重涂范围不由 Manhattan 距离决定，而由螺旋遍历序决定。一个空间上很近的节点如果在螺旋路径上排在阻断节点之后，它将不会被重涂——这一点打破了"距离越近越先处理"的直觉。

## 新题 6：面积排名堆叠的跨轴反射着色

**组合逻辑**：[reflection_across_axis](创新：反射后不保留空间位置，而是按面积排名重新堆叠排列) + [area_comparison + sorting](创新：面积排名不决定颜色而是决定堆叠顺序) + [nearest_pairing + marker_color_paint](创新：颜色由目标侧最近标记像素提供而非反射区域内预置标记)

**来源原语**：reflection_across_axis（88207623）、area_comparison + sorting（694f12f3）、nearest_pairing（9aaea919）、marker_color_paint（88207623）

**依赖链**：反射提供镜像形状 → 面积排名决定堆叠顺序 → 标记像素距离匹配决定颜色。反射负责"形状从何而来"，排名负责"形状放在哪里"，标记负责"形状涂什么色"。三者分别解决形状、位置、颜色三个独立维度的问题，必须同时确定才能得到输出。

左侧精灵体反射至右侧后按面积排名从上到下堆叠，颜色由右侧最近标记像素提供。

**输入结构**：约 15x20 的黑(0)背景网格。一条 1 像素宽的红(2)垂直线段从顶到底将网格分为左右两区（位于约第 10 列）。左侧有 3-4 个单色 4-连通精灵体（每个 4-8 像素，形态不规则），颜色互不相同（如蓝(1)、绿(3)、品红(6)）但均非红色。各精灵体像素面积（像素数）互不相等。右侧有与左侧精灵体数量相同的孤立彩色像素（"标记像素"），每个标记像素颜色互不相同（如黄(4)、橙(7)、青(8)），散布在右侧不同位置。生成约束：左侧精灵体均不接触红色轴线；右侧标记像素均不在同一行上。

**规则**：
1. 将每个左侧精灵体水平反射到红色轴线的右侧（以轴线列为镜像轴）。
2. 反射不保留空间纵坐标。按精灵体面积从小到大排列，最小面积的反射体放置在最上方，最大面积的放置在最下方。具体放置方式：第一个（最小）反射体的包围盒顶行 = 轴线右侧区域的顶行（即行 0）；后续反射体紧接前一个反射体包围盒底行的下一行开始放置（无间隙堆叠）。水平位置：每个反射体的包围盒左列紧贴轴线右侧第 2 列（即轴线列 + 2）。
3. 每个反射体的颜色由右侧标记像素决定：计算每个标记像素到该反射体包围盒中心的 Manhattan 距离，取距离最小的标记像素的颜色作为反射体颜色。已被匹配的标记像素不再参与后续匹配（贪心匹配：按面积排名从小到大依次匹配，每次取当前剩余标记中距离最近的）。
4. 左侧原始精灵体保持不变。红色轴线保持不变。右侧标记像素被反射体覆盖时消失（反射体像素优先），未被覆盖的标记像素保留。

**关键洞察**：反射决定形状但不决定位置——位置由面积排名重新编排；颜色也不继承原色——由目标侧的标记像素距离匹配决定。三个维度各有独立的决定机制，必须同时推断。

## 新题 7：对称精灵体的压缩对角摘要

**组合逻辑**：[symmetry_filter](创新：对称性不用于筛选裁剪而是标记哪些精灵体参与摘要编码) + [shrink_copy](创新：缩小不是生成微缩几何副本而是将整个精灵体压缩为单像素颜色代码) + [diagonal_position](创新：对角线位置由精灵体在原图中的空间排序而非固定偏移决定) + [counting](保留：参与计数和定位)

**来源原语**：symmetry_filter（72ca375d）、shrink_copy（11e1fe23）、diagonal_position（11e1fe23）、counting（ae4f1146）

**依赖链**：对称性检测决定哪些精灵体被选中 → 选中精灵体按阅读顺序排序 → 每个精灵体被压缩为单像素 → 压缩像素按序排列在对角线上。对称性决定"谁被编码"，阅读顺序决定"编码到对角线哪个位置"，压缩决定"编码形式"。

对称精灵体被选中并按阅读顺序压缩为单像素，排列在从角点出发的主对角线上。

**输入结构**：约 15x15 的黑(0)背景网格。5-6 个小型单色 4-连通精灵体（每个 3-8 像素，形态各异），每个精灵体颜色互不相同（如蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)）。其中 2-3 个精灵体在包围盒内具有对称性（垂直、水平或 180 度旋转对称），其余不具有。网格左上角(0,0)有一个灰(5)像素作为对角线起点标记。生成约束：所有精灵体与左上角保持至少 4 像素间距（确保对角线摘要区域与精灵体不重叠）；各精灵体包围盒左上角的位置两两不同（确保阅读顺序无歧义）。

**规则**：
1. 对每个精灵体在其包围盒内进行对称性检测（垂直镜像、水平镜像、180 度旋转三种对称，满足任一即可）。
2. 将所有对称精灵体按"阅读顺序"排列：以包围盒左上角为基准，先按行号从小到大排序，行号相同时按列号从小到大排序。
3. 按此顺序，将第 k 个对称精灵体（k 从 1 开始）压缩为一个单像素，颜色为该精灵体的原色，放置在网格位置 (k, k)——即主对角线上距左上角第 k 步的位置。
4. 灰(5)起点标记像素保留在 (0, 0)。所有精灵体（对称和非对称）在原位保持不变。非对称精灵体不参与对角线摘要。

**关键洞察**：对角线上的颜色序列是所有对称精灵体按空间阅读顺序排列的压缩索引。必须同时掌握对称性判定和阅读顺序排序才能复现输出——仅看单个示例可能误以为是某些特定颜色固定出现在对角线上。

## 新题 8：精灵体自编码平铺方向与重复次数

**组合逻辑**：[self_as_stencil](创新：精灵体不仅是印章内容还编码了平铺参数——方向和次数) + [tiling](创新：平铺方向由包围盒长宽比决定而非固定的 NxN 瓦片) + [counting](创新：前景像素数决定重复次数而非与颜色数相关的缩放因子) + [boundary_clipping](保留：超出网格部分被裁剪)

**来源原语**：self_as_stencil（007bbfb7）、tiling（310f3251）、counting（ae4f1146 / 469497ad）、boundary_clipping（8b28cd80）

**依赖链**：包围盒长宽比编码平铺方向 → 前景像素数编码重复次数 → 按方向和次数执行平铺 → 超出网格边界的部分被裁剪。精灵体本身既是被平铺的内容又是平铺指令的载体——这种"数据即程序"的结构是源题中不存在的。

精灵体的长宽比决定平铺方向，前景像素数决定副本数量，自身就是被平铺的内容。

**输入结构**：约 12x12 的黑(0)背景网格。恰好一个小型单色 4-连通精灵体（3-7 像素），颜色为非黑色（如蓝(1)、红(2)、绿(3)、黄(4)等）。精灵体的包围盒可能是竖长（行数 > 列数）、横宽（列数 > 行数）或正方形（行数 = 列数）。精灵体不接触网格边缘（与每条边至少间隔 1 像素）。生成约束：不同示例中精灵体的包围盒长宽比和像素数各不相同，以便对比归纳方向和次数规则。

**规则**：
1. 计算精灵体包围盒的行数 H 和列数 W。
2. 确定平铺方向：若 H > W（竖长），沿垂直方向平铺（在精灵体上下方放置副本）；若 W > H（横宽），沿水平方向平铺（在精灵体左右方放置副本）；若 H = W（正方形），沿两个方向同时平铺（上下左右各放置副本，形成十字排列）。
3. 计算精灵体的前景像素数 N（非黑色像素数量）。总副本数（包含原始精灵体自身）= N。
4. 沿确定的方向放置 N 个副本（含原件）。副本之间无间隙：每个副本的包围盒紧邻前一个副本的包围盒。对于垂直平铺，原件位于中央，上下对称放置副本（若 N 为偶数，则上方比下方少一个）。对于水平平铺，原件位于中央，左右对称放置。对于十字平铺，原件位于中心，上下左右各延伸 (N-1)/4 个副本（向下取整），剩余副本按上、右、下、左顺序依次补足。
5. 所有超出网格边界的副本像素被裁剪（不绘制）。原始精灵体保持在原位，副本与原件颜色相同。

**关键洞察**：精灵体是"数据即程序"——它的几何属性（长宽比、像素数）隐式编码了变换参数（方向、次数），而它的像素模式又是被复制的内容。必须对比不同形状的精灵体才能发现长宽比→方向、像素数→次数这两条编码规则。
