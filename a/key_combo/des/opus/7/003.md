## 新题 1：对称性决定射线方向的障碍擦除

**组合逻辑**：[镜像/mirror](创新：对称检测不用于重涂色，而是决定射线方向) + [射线延伸/ray_cast] + [擦除/erase] + [反射对称/reflection_symmetry](创新：对称状态编码为方向信息) + [首个障碍/first_obstacle]

**来源原语**：镜像、反射对称（a8610ef7）；射线延伸、擦除、首个障碍（9f8de559）

**依赖链**：每个前景像素的对称状态决定射线方向（向轴外 vs 向轴内），射线方向决定擦除哪个障碍。对称检测与射线投射交织——不做对称判断就无法确定射线方向，不做射线投射就无法确定擦除目标。

根据前景像素是否拥有关于垂直中心轴的镜像伙伴，决定从该像素发出射线的方向，射线擦除途中首个障碍。

**输入结构**：黑(0)背景，约 11x11 网格。蓝(1)前景像素散布于网格中，部分像素关于网格垂直中心列形成镜像对，部分像素没有镜像伙伴（镜像位置为黑(0)）。灰(5)障碍像素分布在网格各处，不与任何蓝像素重叠。生成约束：每个蓝像素沿其射线方向上至少存在一个灰障碍；不同蓝像素的射线不会命中同一个灰障碍。

**规则**：
1. 确定网格的垂直中心列 c = (width - 1) / 2（网格宽度为奇数）。
2. 对每个蓝(1)前景像素 P 位于 (r, col)：
   - 检查镜像位置 (r, 2c - col) 是否也包含蓝(1)像素。
   - 若是（对称对）：从 P 沿水平方向**远离中心轴**投射射线（col < c 向左，col > c 向右，col = c 向上）。
   - 若否（孤立）：从 P 沿水平方向**朝向中心轴**投射射线（col < c 向右，col > c 向左，col = c 向下）。
3. 射线逐像素前进，遇到第一个灰(5)障碍像素时停止，将该障碍像素擦除为黑(0)。射线不改变途中其他像素。
4. 所有蓝像素保持不变。

**关键洞察**：对称检测的结果不是用来重涂色（与参考题 a8610ef7 不同），而是编码为一个方向信号——有镜像伙伴则向外射，无伙伴则向内射。需要对比多个示例才能归纳出"对称→向外、孤立→向内"的隐藏映射。

## 新题 2：对向行进轨迹揭示对称轴以完成残缺图案

**组合逻辑**：[滑动/sliding + 连线/draw_line](创新：行进轨迹的汇合列不再只是标记终点，而是编码几何信息) → [对称补全/symmetry_completion](创新：对称轴不从图案本身推断，而是由外部信号提供)

**来源原语**：滑动、连线、对侧配对、相向移动留迹汇合（29c11459）；对称补全、镜像对应、推断对称轴（981571dc）

**依赖链**：对向行进的汇合点确定了一条垂直轴线。该轴线是图案区域的对称轴，图案中的缺失像素通过该轴反射恢复。如果不做行进，对称轴有多个候选无法唯一确定；如果不做补全，行进轨迹本身无意义。

在同一网格中，对向像素对行进汇合揭示一条垂直轴线，该轴线恰好是残缺彩色图案的对称轴，据此反射补全图案。

**输入结构**：黑(0)背景，约 15x15 网格。在若干行（如第 2、7、12 行）的左右两端各有一个同色孤立像素，颜色取自蓝(1)、红(2)、绿(3)，左端像素位于第 0 列，右端像素位于最后一列，二者同行同色，构成对向配对。在其余行上，橙(7)像素形成一个关于某条垂直轴具有双边对称性的图案，但其中若干橙像素被擦除为黑(0)。生成约束：图案的缺失像素经过设计，使得从图案自身出发存在至少两条候选对称轴都能解释已有像素，但只有行进汇合列才是正确轴；所有配对的汇合列相同。

**规则**：
1. 识别所有对向配对：同一行的左右边界各有一个同色非黑像素即构成一对。
2. 每对中的两个像素沿所在行相向滑动，每步前进一格，留下自身颜色的轨迹。当二者相遇于同一列或相邻列时，将汇合格标记为灰(5)。（若该行宽度为偶数，则汇合格为中间偏左的一格。）
3. 所有灰(5)汇合格共享同一列 A，该列即为图案的垂直对称轴。
4. 对图案区域中每个被擦除为黑(0)的位置 (r, col)，计算其关于列 A 的镜像位置 (r, 2A - col)。若镜像位置为橙(7)，则将该位置恢复为橙(7)。
5. 输出保留行进轨迹、灰汇合标记和完成后的图案。

**关键洞察**：图案自身的残缺程度经过设计，使得仅凭图案无法唯一确定对称轴。行进汇合点是外部提供的、唯一可靠的轴线信息源。两种机制缺一不可。

## 新题 3：格点间隙连通决定腔室填色与优先级

**组合逻辑**：[泛洪填充/flood_fill] + [填充/fill] + [计数/counting](创新：计数结果不驱动重复次数，而是编码优先级权重) + [格点骨架/lattice_frame] + [封闭腔室/enclosed_cavity] + [可达性/reachability]

**来源原语**：泛洪填充、可达性（8f3a5a89）；填充、格点骨架、封闭腔室、标记像素（17b866bd）；计数（4852f2fa）

**依赖链**：泛洪填充通过格点间隙传播，确定每个标记可到达的腔室集合。多个标记的可达集合可能重叠——冲突腔室归属于可达腔室总数最少的标记（即"活动范围最受限的标记优先"）。填色操作依赖泛洪结果和全局计数排序，三者环环相扣。

多色标记坐落在格点腔室中，通过间隙泛洪扩散；可达腔室总数最少的标记在冲突区域拥有优先填色权。

**输入结构**：黑(0)背景，约 17x17 网格。青(8)像素构成正交格点骨架（横竖线交叉），将内部分割为约 3x3 或 4x4 大小的黑(0)封闭腔室，总计约 9-16 个腔室。骨架中有 2-4 个单像素间隙（青像素被替换为黑(0)），使相邻腔室通过间隙连通。2-3 个不同颜色的标记像素（如红(2)、蓝(1)、绿(3)），各位于不同腔室中。生成约束：至少有一个腔室被两个不同标记同时可达；每个标记至少可达 2 个腔室；不同标记的可达腔室总数互不相等。

**规则**：
1. 对每个标记像素 M，以 M 所在腔室为起点，通过骨架间隙进行泛洪填充（扩散只穿过黑(0)像素，不穿过青(8)骨架像素），记录 M 可达的所有腔室集合 R(M)。
2. 计算每个标记的可达腔室总数 |R(M)|。
3. 对每个可达腔室分配颜色：
   - 若该腔室仅被一个标记可达，填充为该标记的颜色。
   - 若被多个标记可达，填充为其中 |R(M)| 最小的标记的颜色（可达范围最受限者优先）。
4. 将标记像素本身也视为其所在腔室的一部分，随腔室一同填色（标记像素被覆盖）。
5. 不可达的腔室保持黑(0)。骨架保持青(8)不变。

**关键洞察**：冲突解决规则要求全局视角——不能独立处理每个标记，必须先统计所有标记的可达集合大小，再根据"最受限者优先"原则分配颜色。这使得局部泛洪结果与全局计数排序形成紧耦合。

## 新题 4：臂向决定镜像侧，瓦片对推导镜像体配色

**组合逻辑**：[镜像/mirror] + [拼接/concatenate] + [颜色映射/color_mapping](创新：映射不作用于全局像素，而仅作用于镜像副本) + [最长臂决定镜像侧/longest_arm_mirror_side] + [匹配对推导映射/pair_defines_mapping]

**来源原语**：镜像、拼接、擦除、最长臂决定镜像侧（9bebae7a）；颜色映射、匹配对推导映射（b0722778）

**依赖链**：十字标记决定在精灵体的哪一侧放置镜像副本（空间布局）；示例瓦片对提供颜色映射规则（配色方案）；镜像副本的颜色不是原色的简单复制，而是经过映射后的变体。三者缺一则输出无法确定——去掉标记不知放在哪侧，去掉映射不知用什么颜色，去掉镜像不知做什么操作。

一个多色精灵体需要在标记指定的一侧附加一个颜色变换后的镜像副本，变换规则由网格上方的示例瓦片对定义。

**输入结构**：黑(0)背景，约 13x16 网格。上部区域：两个大小相同（约 3x3）的多色小瓦片，水平相邻放置，间隔 1 列黑像素。两个瓦片的非黑像素形成相同的空间图案，但颜色不同——左瓦片使用红(2)和蓝(1)，右瓦片使用绿(3)和橙(7)（颜色一一对应：红→绿，蓝→橙）。下部区域：一个 4-连通多色精灵体（5-8 像素），使用与左瓦片相同的颜色集合（红(2)和蓝(1)）。精灵体附近有一个灰(5)像素构成的十字标记（一个交叉点和四条臂），其中恰好一条臂比其他臂长至少 2 格。生成约束：精灵体的边界框与十字标记不重叠；精灵体在指定侧的边界框外有足够空间放置镜像副本。

**规则**：
1. 从上部的瓦片对学习颜色映射：将左瓦片中每个位置的颜色映射到右瓦片相同位置的颜色。例如 红(2)→绿(3)，蓝(1)→橙(7)。黑(0)映射到黑(0)。
2. 确定十字标记中唯一最长的臂的方向（上/下/左/右）。将该方向顺时针旋转 90 度，得到镜像副本放置的方位：上→右，右→下，下→左，左→上。
3. 根据放置方位生成精灵体的镜像副本：左/右放置时水平翻转，上/下放置时垂直翻转。
4. 对镜像副本中的每个非黑像素，应用步骤 1 学到的颜色映射。
5. 将映射后的镜像副本紧贴精灵体边界框的指定侧放置。
6. 擦除十字标记和两个示例瓦片（全部设为黑(0)）。原精灵体保留原色不变。

**关键洞察**：镜像副本的颜色并非原色复制——它是颜色映射的产物。示例瓦片对的作用不是供裁剪，而是定义"原色→镜像色"的翻译规则。需要对比多个示例才能区分"镜像保持原色"和"镜像应用映射"这两种假设。

## 新题 5：中心投影标记发出对角射线，命中对象则重涂色

**组合逻辑**：[投影/project] + [射线延伸/ray_extend](创新：射线起点不是已有框体的角，而是由投影动态生成的标记) + [重涂色/recolor](创新：重涂色的触发条件是几何射线命中，而非属性检查) + [中心对齐/center_alignment] + [对角射线/diagonal_ray]

**来源原语**：投影、中心对齐、前景对象（54d82841）；射线延伸、对角射线（2b9ef948）；重涂色（a8610ef7）

**依赖链**：每个对象的水平中心列决定底行标记位置（投影），标记位置决定对角射线的起点和路径（射线延伸），射线是否命中其他对象决定该对象是否被重涂色（重涂色）。对象 A 的投影可能使射线命中对象 B，但不会命中自身——对象间通过投影-射线建立了间接的远程交互。

从每个前景对象的水平中心向底行投射标记，再从标记向左上和右上发出对角射线；被射线触及的对象全部重涂为黄(4)。

**输入结构**：黑(0)背景，约 14x14 网格。3-4 个单色前景对象散布在网格上半部（约前 10 行），每个对象由不同颜色的 3-6 个 4-连通像素构成（使用红(2)、蓝(1)、绿(3)、橙(7)等）。底行（最后一行）全部为黑(0)。生成约束：各对象的边界框互不重叠；每个对象的中心列与其他对象的边界框列范围不重叠（保证标记位置唯一对应一个对象）；至少有一个对象会被另一个对象的对角射线命中，至少有一个对象不被任何射线命中。

**规则**：
1. 对每个前景对象 O，计算其边界框的水平中心列 c_O = floor((min_col + max_col) / 2)。在底行（最后一行）的第 c_O 列放置一个黄(4)标记像素。
2. 从每个黄标记位置 (last_row, c_O) 出发，沿左上方（行-1, 列-1）和右上方（行-1, 列+1）两条对角线分别延伸射线。射线逐步前进，将经过的每个黑(0)像素涂为黄(4)。
3. 射线在以下条件之一下停止（不含触发停止的那个像素）：到达网格边界；遇到非黑(0)且非黄(4)的像素。
4. 对每个前景对象，检查其是否有至少一个像素的 4-邻域中包含黄(4)射线像素。若是，将该对象的所有像素重涂为黄(4)。
5. 未被任何射线触及（4-邻域中无黄(4)）的对象保持原色不变。

**关键洞察**：对象自身的投影产生的射线几乎不会命中自己（射线从对象正下方出发向上斜射，而对象在正上方），因此重涂色是对象间的远程效应——A 的投影射线可以"够到"远处的 B。空间布局决定了谁影响谁。

## 新题 6：周期平铺与双边对称的双重约束修复

**组合逻辑**：[平铺/tiling] + [对称补全/symmetry_completion](创新：两个独立约束同时施加，既不是平铺优先也不是对称优先，而是共同确定唯一解) + [修复/repair] + [周期重复/periodic_repetition] + [镜像对应/mirror_correspondence]

**来源原语**：平铺、修复噪声、周期重复（135a2760）；对称补全、修复、镜像对应（981571dc）

**依赖链**：这是一个同时约束满足问题，没有固定的执行顺序。完整输出必须同时是一个周期瓦片的平铺，又关于垂直中心轴具有双边对称性。部分缺失像素仅凭平铺可恢复，部分仅凭对称可恢复，还有部分必须两个约束联合才能唯一确定。

在一个有缺失像素的矩形区域中，输出需同时满足周期平铺性和垂直对称性；两个约束互相补充，缺一则解不唯一。

**输入结构**：黑(0)背景上有一个矩形区域（约 8x12），区域内包含 2-3 种颜色的像素（如红(2)、蓝(1)、绿(3)）和若干被擦除为黑(0)的缺失像素。区域的完整版本（正确输出）同时满足两个性质：(a) 存在一个小瓦片（约 3x4 或 4x3），该瓦片在水平和垂直方向各至少重复 2 次，恰好平铺整个区域；(b) 整个区域关于其垂直中心列具有双边对称性。缺失像素约占区域总像素的 20%-30%。生成约束：存在至少 2 个缺失像素，其在瓦片周期中的对应位置也全部缺失（单靠平铺无法恢复），但其对称镜像位置有幸存像素（对称可恢复）；同时存在至少 2 个缺失像素，其对称镜像位置也缺失（单靠对称无法恢复），但其在另一个周期位置有幸存像素（平铺可恢复）；还存在至少 1 个缺失像素需要先由一个约束恢复其"伙伴"像素后，另一个约束才能恢复它本身。

**规则**：
1. 确定矩形区域的边界。
2. 在区域内推断最小周期瓦片尺寸 (H_t, W_t)，要求 H_t 和 W_t 分别整除区域高度和宽度，且瓦片在每个方向至少重复 2 次。
3. 确定区域的垂直对称轴为其水平中心列。
4. 迭代修复：反复扫描所有缺失像素，对每个缺失位置 (r, c) 尝试以下恢复方式：
   - 周期恢复：查看同一瓦片位置在其他周期实例中的颜色（即位置 (r + k*H_t, c + l*W_t) 的非黑像素），若存在唯一非黑颜色则填入。
   - 对称恢复：查看镜像位置 (r, 2*axis - c) 的颜色，若非黑则填入。
5. 重复步骤 4 直到没有新像素被恢复。
6. 输出完全修复后的矩形区域（裁剪到区域边界）。

**关键洞察**：单独使用平铺约束或对称约束都无法恢复所有缺失像素——存在"死锁"位置，其所有周期副本和对称镜像都缺失。但一个约束恢复的像素会为另一个约束打开新的恢复路径，迭代交替最终收敛到唯一解。这是约束传播而非线性流水线。

## 新题 7：路径生长到达的框边颜色决定轨迹着色

**组合逻辑**：[生长/grow](创新：路径生长的终点不是网格边界，而是语义实体——矩形框的某条边) + [连线/connect](创新：连线不是从散落点到框边的直线，而是沿路径生长的弯曲轨迹) + [重涂色/recolor](创新：重涂色的颜色不由属性查表决定，而是由几何终点决定) + [遇障碍则绕行/detour_on_obstacle] + [颜色对应边/color_to_side]

**来源原语**：生长、遇障碍则绕行、起点像素、障碍像素（d9f24cd1）；连线、矩形框、颜色对应边（5daaa586）；重涂色（a8610ef7）

**依赖链**：路径生长的轨迹（含绕行）决定路径最终到达框的哪条边；框边颜色反过来决定整条路径轨迹的着色。路径轨迹形状、终点位置、轨迹颜色三者环环相扣——改变一个障碍就可能改变路径到达的框边，从而改变整条轨迹的颜色。

路径从底部起点向上生长并绕过障碍，最终到达彩色矩形框的某条边；整条路径轨迹被重涂为它所到达的那条框边的颜色。

**输入结构**：黑(0)背景，约 15x13 网格。一个矩形框占据网格中央区域（约 9x9），框的四条边各用不同颜色的单像素线绘制：上边红(2)、左边蓝(1)、右边绿(3)、下边黄(4)。角落像素颜色取所在两条边中的上边或左边的颜色。框内部和框外部均为黑(0)背景。框外下方区域有 2-3 个黄(4)起点像素，位于框下边的正下方若干行处。框外部散布着灰(5)障碍像素，位于起点和框之间。生成约束：每个起点像素通过向上生长并绕行后，能且仅能到达框的一条边（上/左/右之一，不会到达下边因为路径从下方来）；不同路径不会交叉或共享像素；至少有两条路径到达不同的边。

**规则**：
1. 对每个黄(4)起点像素 S，从 S 开始逐步向上生长路径：
   - 优先尝试向上移动一格（行-1，列不变）。
   - 若上方为灰(5)障碍，则尝试向右移动一格（行不变，列+1）。
   - 若右方也是障碍或已到达网格右边界，则向左移动一格（行不变，列-1）。
   - 记录路径经过的每个格子。
2. 路径在触碰到矩形框的任一边像素时停止（不覆盖框像素本身）。
3. 确定路径停止时相邻的框边颜色 C。
4. 将路径经过的所有格子（不含起点和框边像素）重涂为颜色 C。
5. 起点像素保持黄(4)不变。矩形框保持原样。

**关键洞察**：路径的颜色不在起点决定，而在终点决定——只有完成全部生长并到达框边后，才能回溯为整条路径赋色。障碍的布局同时影响路径形状和最终着色。

## 新题 8：引导掩码选定精灵体，间隙可达标记数决定重复次数

**组合逻辑**：[裁剪/crop](创新：裁剪目标由引导掩码空间选择而非颜色属性) + [泛洪填充/flood_fill](创新：泛洪从被选精灵体出发，穿透墙壁间隙，作用是计数而非着色) + [重复/repeat] + [引导掩码/guide_mask + 包围框包含/bbox_containment] + [标记计数驱动重复/marker_count_drives_repetition] + [可达性/reachability]

**来源原语**：裁剪、引导掩码、包围框包含、空心精灵体（bf699163）；泛洪填充、可达性、墙壁障碍（8f3a5a89）；重复、计数、标记计数驱动重复（4852f2fa）

**依赖链**：引导掩码选定精灵体模板（裁剪对象），精灵体位置决定泛洪填充的起点（可达性原点），泛洪穿过墙壁间隙到达的标记数决定重复次数（重复驱动）。三者形成一条因果链，但引导掩码同时承担了两个角色——选择模板和确定泛洪起点——使得这不是三个独立子任务的简单串联。

引导掩码框选一个精灵体作为模板；从该精灵体所在区域出发泛洪穿过墙壁间隙，可达的标记像素数量决定模板的水平重复次数。

**输入结构**：黑(0)背景，约 16x16 网格。3 个单色 3x3 空心方形精灵体（仅边框，中心为黑(0)），颜色分别为红(2)、绿(3)、橙(7)。蓝(1)墙壁线段将网格划分为 3-4 个区域，每个精灵体位于不同区域内。部分墙壁中有单像素间隙（蓝像素被替换为黑(0)），使某些相邻区域连通。灰(5)像素构成一个稀疏的引导掩码，其边界框恰好包围其中一个精灵体（且仅包围这一个）。黄(4)单像素标记散布在不同区域，每个区域最多一个标记。生成约束：被引导掩码选中的精灵体所在区域通过间隙与至少 1 个、至多 3 个其他区域连通；标记总数为 2-4 个，其中部分可达、部分不可达；可达标记数至少为 1。

**规则**：
1. 识别所有 3x3 空心方形精灵体（8 个边框像素同色，中心为黑(0)）。
2. 构建引导掩码：收集所有灰(5)像素，计算其边界框。
3. 选定引导掩码边界框完全包含的那个唯一精灵体 T 作为模板。
4. 从 T 的中心位置出发，进行泛洪填充：仅穿过黑(0)像素，蓝(1)墙壁像素阻断扩散。记录所有可达的格子。
5. 统计可达格子中包含的黄(4)标记像素数量 N。
6. 输出：将 T 裁剪为 3x3 精灵体，水平拼接 N 份副本，形成 3x(3N) 的输出网格。

**关键洞察**：引导掩码不仅选择"输出什么"（模板），还隐式确定了"输出多少份"（通过确定泛洪起点）。同一组标记在不同引导掩码选择下会产生不同的重复次数，因为可达性取决于起点位置。

## 新题 9：墙壁可达性门控精灵体的锚点对齐滑动

**组合逻辑**：[滑动对齐/slide_to_align] + [泛洪填充/flood_fill](创新：泛洪不用于着色或计数，而是用于判断"是否允许移动"的布尔门控) + [颜色匹配锚点/color_match_anchor] + [边缘位置决定轴/edge_position_determines_axis] + [可达性/reachability] + [墙壁障碍/wall_barrier]

**来源原语**：滑动对齐、颜色匹配锚点、边缘位置决定轴、多色精灵体、边界锚点（581f7754）；泛洪填充、可达性、墙壁障碍（8f3a5a89）

**依赖链**：颜色匹配将每个精灵体与边界锚点配对（目标确定），锚点的边缘位置确定滑动轴向（方向确定），泛洪填充判断精灵体能否经由无墙路径"看到"锚点（权限确定）。只有三个条件同时满足——有匹配锚点、知道滑动方向、可达性通过——精灵体才实际滑动。

多色精灵体需与同色边界锚点对齐，但只有当精灵体到锚点之间存在穿过墙壁间隙的可达路径时，滑动才被允许执行。

**输入结构**：黑(0)背景，约 14x14 网格。2-3 个多色精灵体（各 4-6 个 4-连通像素），每个精灵体内有一个少数色"标记像素"，标记颜色各不相同（如红(2)、绿(3)、橙(7)）。蓝(1)墙壁线段在网格内部形成部分屏障，但不触及网格四边（墙壁是"内部墙"）。网格四边上有孤立的锚点像素（非黑、4-邻域全为黑(0)），每个锚点颜色与某个精灵体的标记像素颜色相同。部分墙壁中有单像素间隙。生成约束：至少有一个精灵体的匹配锚点不可达（被完整墙壁阻隔），至少有一个精灵体的匹配锚点可达（通过间隙）；精灵体滑动后不会越出网格或与其他精灵体重叠。

**规则**：
1. 对每个精灵体 S，找到其标记像素颜色 C，匹配边界上颜色为 C 的锚点 A。
2. 从 S 的标记像素出发进行泛洪填充：穿过黑(0)像素，被蓝(1)墙壁阻断。判断锚点 A 是否在可达集合中。
3. 若 A 不可达：S 保持原位不动。
4. 若 A 可达：
   - A 在网格上边或下边（非角落）：将 S 水平滑动，使标记像素的列与 A 的列对齐。
   - A 在网格左边或右边（含角落）：将 S 垂直滑动，使标记像素的行与 A 的行对齐。
5. 输出中保留所有墙壁和锚点像素。

**关键洞察**：墙壁的作用不是物理阻挡精灵体的滑动路径，而是信息隔离——它们阻断泛洪传播，使精灵体无法"感知"被墙壁隔开的锚点，从而不执行对齐。墙壁是权限门控而非物理障碍。

## 新题 10：端点编码位移，障碍绕行留下弯曲迁移轨迹

**组合逻辑**：[平移/translate](创新：位移向量不直接作用于精灵体，而是定义一个目标位置，实际路径需绕行) + [生长/grow](创新：生长方向不固定为"向上"，而是朝目标位置的主方向) + [端点编码位移/endpoints_encode_disp] + [遇障碍则绕行/detour_on_obstacle] + [路径端点/path_endpoint]

**来源原语**：平移、端点编码位移、路径端点（2b9ef948）；生长、遇障碍则绕行、障碍像素（d9f24cd1）

**依赖链**：路径端点编码了位移向量（平移目标），但精灵体不能直接跳到目标位置——它必须沿主位移方向逐步移动，遇到障碍则垂直于主方向绕行。位移编码决定"去哪里"，障碍分布决定"怎么去"，两者交织生成最终的迁移轨迹。

灰色路径两端的彩色像素编码一个位移向量；精灵体沿该方向逐步迁移，遇障碍则垂直绕行，留下弯曲轨迹。

**输入结构**：黑(0)背景，约 14x14 网格。一个黄(4)精灵体（约 2x2 或 3x2 的小实心矩形）。一条灰(5)像素构成的路径（3-6 个像素，可弯折），两端分别连接一个红(2)像素和一个蓝(1)像素。橙(7)障碍像素散布在精灵体与目标位置之间的区域。生成约束：位移向量（从红端到蓝端）的主方向（水平或垂直中较大分量方向）上，精灵体与目标位置之间有足够空间；障碍不覆盖精灵体初始位置或目标位置；精灵体经绕行后能到达目标位置。

**规则**：
1. 找到灰(5)路径两端的红(2)像素 R 和蓝(1)像素 B。计算位移向量 D = B - R = (dr, dc)。
2. 将位移 D 应用于精灵体的左上角，得到目标位置 T。
3. 确定主移动方向：若 |dr| >= |dc| 则主方向为垂直（向上或向下取决于 dr 的符号），副方向为水平；否则主方向为水平，副方向为垂直。
4. 从精灵体当前位置开始，逐步将精灵体沿主方向移动一格：
   - 若精灵体在目标位置处沿主方向的下一格无橙(7)障碍像素与精灵体占据的格子重叠，则正常移动。
   - 若有障碍重叠，则改为沿副方向移动一格（方向选择使精灵体更接近目标的副方向坐标；若两者等距则选行号/列号较小的方向）。
5. 精灵体每离开一组格子，将那些格子标记为栗(9)轨迹色（除非该格已有其他非黑内容）。
6. 精灵体到达目标位置后停止。擦除灰路径和红蓝端点（设为黑(0)）。保留橙障碍。

**关键洞察**：灰色路径的弯折走向完全不影响位移——只有两端的彩色像素坐标差才有意义。但精灵体的实际迁移轨迹可能因障碍而高度弯曲，与编码的直线位移截然不同。
