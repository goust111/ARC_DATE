## 新题 1：平移后拓扑决定连线色

**组合逻辑**：[平移 + 颜色配对](已有) → [连线 + 同行同列对齐](已有) + [按孔洞数映射颜色](已有，创新：孔洞数决定的不是对象色而是连线色)

**来源原语**：平移(translate)、颜色配对(color_pairing)、嵌入标记像素(embedded_marker)、孤立控制点(isolated_control) 来自 54dc2872；连线(connect)、同行同列对齐(same_row_column_alignment) 来自 60a26a3e；按孔洞数映射颜色(hole_count_to_color_mapping)、连通分量(connected_component)、封闭区域(enclosed_region) 来自 0a2355a6

**依赖链**：颜色配对确定每个精灵体的平移目标 → 平移改变精灵体在网格中的绝对位置 → 新位置决定哪些精灵体的中心共享行或列 → 共享行或列的精灵体对之间如果路径畅通则绘制连线 → 每条连线的颜色取决于它连接的两个精灵体各自封闭的孔洞数之和。去掉平移则无法确定对齐关系，去掉孔洞计数则无法确定连线颜色，去掉连线则输出不完整。

将标记色配对的精灵体平移到对应控制点后，在行列对齐的精灵体对之间画连线，连线颜色由两端精灵体孔洞数之和决定。

**输入结构**：黑(0)背景，约 15x18 网格。网格中分布 4-6 个小型 4-连通单色精灵体，每个精灵体由 4-8 个同色像素构成（形状各异，有的是实心无孔，有的包含 1 或 2 个被完全包围的黑(0)孔洞），精灵体之间互不相邻。每个精灵体内恰好有一个像素颜色与体色不同，该像素是嵌入标记像素。各精灵体的标记色互不相同，可从红(2)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7) 中选取。在网格的其他位置（远离所有精灵体）散布与标记色一一对应的孤立单像素控制点（颜色与某个标记色相同）。生成约束：每个标记色恰好对应一个控制点；平移后精灵体互不重叠且不超出网格边界；平移后至少存在两对中心共享行或列的精灵体。

**规则**：
1. 对每个精灵体，找到颜色与其嵌入标记像素相同的孤立控制点，将整个精灵体平移使标记像素落在该控制点位置。从原位置擦除精灵体，消除已使用的控制点。
2. 对每个平移后的精灵体，计算其内部 4-连通封闭黑(0)区域的个数（孔洞数 h）。精灵体保留其体色不变。
3. 计算每个精灵体边界框的中心坐标（取边界框行范围和列范围的中值，向下取整）。
4. 对于中心在同一行的每对精灵体，按列坐标从左到右排序，仅连接相邻对：检查两个精灵体边界框之间的水平线段（从左精灵体边界框右边缘 +1 到右精灵体边界框左边缘 -1，行坐标为共享中心行），若该线段上所有像素均为黑(0)背景，则绘制连线。同一列的处理方式对称（垂直线段）。
5. 连线颜色取决于它连接的两个精灵体孔洞数之和 s：s=0 → 灰(5)，s=1 → 蓝(1)，s=2 → 绿(3)，s≥3 → 红(2)。
6. 若两条连线交叉于同一像素，后绘制的连线（先处理水平连线再处理垂直连线）覆盖先绘制的。

**关键洞察**：平移重新排列了精灵体的位置，改变了谁与谁对齐；而孔洞数是精灵体的拓扑不变量，不受平移影响——求解者必须同时推断空间重排和拓扑属性两套独立信息，两者在连线颜色处汇聚。

## 新题 2：镜像拼合涌现封闭区按象限上色

**组合逻辑**：[镜像 + 拼接](已有) → [洪泛填充](已有，创新：填充的是拼合后涌现的封闭区域) + [相对位置决定颜色](已有，创新：位置判断基于象限而非矩形内坐标)

**来源原语**：镜像(mirror)、拼接(concatenation)、四象限对称(four_quadrant_symmetry)、象限(quadrant) 来自 0c786b71；洪泛填充(flood_fill)、封闭背景区域(enclosed_bg) 来自 83302e8f；相对位置决定颜色(relative_position_determines_color) 来自 639f5a19

**依赖链**：镜像拼接将单一形状变成四象限对称图案 → 对称图案在接缝处产生原始输入中不存在的新封闭区域 → 洪泛填充识别每个封闭区域 → 区域最左上像素所在象限决定填充色。不做镜像则无封闭区域可填，不做洪泛填充则无法着色，不判断象限则颜色无法确定。

将输入网格镜像拼合成双倍尺寸的四象限对称图案，然后按象限位置对拼合后涌现的封闭背景区域分色填充。

**输入结构**：黑(0)背景，小型矩形网格（5x6 至 7x8）。网格中有一个青(8) 4-连通前景形状，由 8-15 个像素构成，形状不规则但连通，至少触及网格的一条边。形状本身不包围任何封闭背景区域（即所有黑(0)像素都与网格边界 4-连通）。生成约束：镜像拼合后至少产生 2 个互相独立的封闭背景区域，且至少有两个区域的最左上像素位于不同象限。

**规则**：
1. 构建双倍尺寸的输出网格（行数 2H，列数 2W）：原始网格放在右下象限（行 H..2H-1，列 W..2W-1）；原始网格的左右镜像放在左下象限（行 H..2H-1，列 0..W-1）；原始网格的上下镜像放在右上象限（行 0..H-1，列 W..2W-1）；原始网格的 180 度旋转放在左上象限（行 0..H-1，列 0..W-1）。
2. 在输出网格中，识别所有 4-连通的黑(0)背景区域。排除与网格外边界 4-连通的区域（非封闭区域）。
3. 对每个封闭背景区域，找到其所有像素中行最小、行相同时列最小的像素（最左上像素），判断该像素属于哪个象限：
   - 左上象限（行 < H 且 列 < W）→ 填品红(6)
   - 右上象限（行 < H 且 列 >= W）→ 填红(2)
   - 左下象限（行 >= H 且 列 < W）→ 填蓝(1)
   - 右下象限（行 >= H 且 列 >= W）→ 填绿(3)
4. 青(8)像素保持不变，与网格边界连通的背景区域保持黑(0)。

**关键洞察**：原始形状本身不产生封闭区域，但四象限镜像使得形状的对称副本在接缝处互相闭合，涌现出原始输入中不存在的新封闭区域；每个涌现区域的象限归属取决于它在拼合图中的位置。

## 新题 3：重力穿隙封口后格子完整性分色

**组合逻辑**：[重力下落 + 控制色定行为](已有) → [擦除 + 填充](已有，创新：下落过程中封口改变格子拓扑) → [洪泛填充 + 完整与缺损区异色](已有，创新：完整性判断依赖于被下落修改过的格子)

**来源原语**：重力下落(gravity_drop)、控制色定行为(control_color_determines_behavior)、穿透或停靠(pass_through_or_stop)、控制像素(control_pixel) 来自 963c33f8；洪泛填充(flood_fill)、格子框架(lattice_frame)、封闭背景区域(enclosed_bg)、完整与缺损区异色(intact_broken_differ) 来自 83302e8f；擦除(erase) 来自 54dc2872

**依赖链**：控制色决定每个像素的下落行为 → 红色像素穿过缺口时封住缺口，改变格子的连通结构 → 下落完成后，格子的完整性取决于哪些缺口被封住 → 封闭的完整单元格和因残留缺口而连通的破损区域获得不同颜色。去掉控制色逻辑则无法确定谁封口谁停靠，去掉封口机制则格子拓扑不变（退化为单逻辑），去掉完整性分类则无法着色。

让控制色不同的像素以不同方式穿越破损格子——红色像素穿过缺口时顺带封住缺口，蓝色像素遇格子栏则停住；下落完成后按格子单元格的完整性分色。

**输入结构**：黑(0)背景，约 14x14 网格。绿(3)线条构成矩形格子框架：水平和垂直的单像素宽线段划分出 3x3 或 4x4 的等大单元格（每个单元格约 3x3 像素），但某些绿(3)线段上有 1 像素宽的缺口（缺口处为黑(0)），使得相邻单元格通过缺口连通。在网格最顶行的若干列上各放置一个有色像素：红(2)或蓝(1)，每列最多一个，共 3-5 个。生成约束：红色像素所在列的正下方至少存在一个缺口；蓝色像素所在列的正下方至少存在一段完整的绿色横栏；下落完成后，至少存在一个因封口而变完整的单元格和一个仍然破损的区域。

**规则**：
1. 对每个顶行有色像素，按列独立处理下落：
   - 蓝(1)像素：向下移动直到紧邻绿(3)格子栏的上方或到达网格底边，停在该位置。蓝(1)像素不改变格子结构。
   - 红(2)像素：向下移动，忽略所有绿(3)格子栏（穿透），直到到达网格底边，停在最底行。红(2)像素经过的路径中，如果该路径上某个像素恰好是绿(3)线段上的缺口位置（即该像素为黑(0)且其左右或上下相邻像素为绿(3)），则将该缺口像素填为绿(3)，封住该缺口。
2. 从顶行擦除原始有色像素，在停靠位置绘制该有色像素。
3. 在修改后的格子中，识别每个 4-连通的黑(0)背景区域（不含绿线和有色像素）。
4. 对每个区域，比较其面积与其紧包围边界框面积：若面积等于边界框面积（区域恰好填满一个矩形，即完整单元格），填黄(4)；否则（区域通过残留缺口连通了多个单元格），填橙(7)。
5. 绿(3)格子线和有色像素保持不变。

**关键洞察**：红色像素在下落途中充当"修补剂"——它穿过缺口的副作用是封住缺口，而封口改变了格子拓扑，使某些原本破损的单元格变为完整。求解者必须模拟下落路径才能知道最终哪些缺口被封住，进而判断每个区域的完整性。

## 新题 4：弹性拉伸后周期列选择性变色

**组合逻辑**：[弹性拉伸 + 按目标尺寸调整](已有) ×  [列周期 + 周期列触发变色](已有，创新：周期列不仅触发变色，还决定哪些目标矩形接受拉伸) → 拉伸与周期的位置交互产生涌现差异

**来源原语**：弹性拉伸(elastic_stretching)、多色范例矩形(multicolor_exemplar_rect)、纯色目标矩形(solid_target_rect)、内部行程(interior_run)、按目标尺寸调整(resize_to_target) 来自 40f6cd08；列周期(column_periodicity)、周期列触发变色(periodic_column_triggers_recolor) 来自 ba26e723

**依赖链**：周期列标记首先筛选哪些目标矩形"有资格"接受弹性拉伸（矩形必须与某条周期列相交）→ 弹性拉伸将范例复制到有资格的目标中，边界行程固定、内部行程按目标尺寸缩放 → 拉伸完成后，在所有周期列上将非边框、非背景像素替换为品红(6)。去掉周期列判断则不知哪些目标被拉伸，去掉拉伸则目标为空，去掉后续变色则输出不正确。

只对与周期列相交的纯色目标矩形执行弹性拉伸，然后在周期列上对拉伸产物的内部像素变色。

**输入结构**：黑(0)背景，约 20x18 网格。一个多色范例矩形（约 4x5 像素）：外层边框为橙(7)，内部有两条色带——一条红(2)带和一条蓝(1)带，带的走向与边框平行（水平排列），范例矩形位于网格左上区域。网格中另有 4-6 个纯色橙(7)目标矩形，尺寸各异（宽 4-10，高 4-8），分散在网格各处，矩形之间互不重叠。在网格第 0 行的列 0、列 4、列 8、列 12、列 16... 处各放一个黄(4)标记像素，标示周期列（周期为 4）。生成约束：至少 2 个目标矩形与某条周期列相交，至少 1 个目标矩形不与任何周期列相交。

**规则**：
1. 识别范例矩形（唯一包含多种颜色的矩形），提取其行程编码：将相同行和相同列归并，识别边界行程（边框）和内部行程（色带）。
2. 对每个纯色橙(7)目标矩形，检查其列范围是否与任何周期列（列号 mod 4 == 0）相交：
   - 相交：对该目标执行弹性拉伸——保持边界行程不变，将内部行程（色带）按目标的宽度和高度缩放填充。
   - 不相交：用橙(7)边框保留目标矩形外形，内部全部填黄(4)（纯色填充，不使用范例图案）。
3. 在所有周期列（列号 mod 4 == 0）上，将弹性拉伸产物中的非橙(7)边框、非黑(0)背景像素替换为品红(6)。被纯色填充的目标矩形中的黄(4)像素不受此规则影响（它们已经是黄色）。
4. 删除第 0 行的黄(4)标记像素（恢复为黑(0)）。

**关键洞察**：周期列同时充当筛选条件和后处理目标——它先决定哪些矩形接受弹性拉伸（资格判定），拉伸完成后又对这些矩形的内部像素施加变色（后处理）。不同目标矩形相对于周期列的水平偏移不同，导致品红竖条切割拉伸图案的位置各异，使得即使源自同一范例的不同拉伸产物看起来也不同。

## 新题 5：双掩码布尔交集定位印章覆盖

**组合逻辑**：[布尔运算 + 双掩码交集](已有) → [印章覆盖 + 模板掩码](已有，创新：印章的放置位置由布尔交集决定，而非预设) + [行调色板](已有，创新：调色板为印章着色而非预印图案)

**来源原语**：布尔运算(boolean_op)、掩码区域(mask_region)、分隔线(divider_line)、双掩码交集输出(bg_intersection_out) 来自 6430c8c4；印章覆盖(stamp_overlay)、模板掩码(template_mask)、分隔网格(divider_grid)、行调色板(row_palette)、行标记(row_marker) 来自 5a5a2103

**依赖链**：两个掩码的单元格级布尔交集决定哪些位置是"活跃"的 → 模板掩码只被印章到活跃位置 → 每行的行标记颜色决定该行印章的颜色。去掉布尔运算则不知道在哪里印章，去掉印章则无输出图案，去掉行调色板则印章无法着色。

通过上下两层二进制掩码的交集确定活跃单元格，然后将模板图案按行调色板着色后印章到每个活跃位置。

**输入结构**：黑(0)背景，约 20x16 网格。网格被两条灰(5)全宽水平分隔行分成三个等高的水平带（上带、中带、下带），每带高约 4-5 行。每个带内部由灰(5)垂直分隔线进一步划分为 N 个等宽单元格（N 约 5-7），每个单元格约 3x3 像素。上带扮演掩码 A：部分单元格全填红(2)，其余保持黑(0)。中带扮演掩码 B：部分单元格全填蓝(1)，其余保持黑(0)。下带：大部分单元格为空黑(0)；恰好一个非首列单元格内包含一个小型模板图案（绿(3)像素，2-4 像素组成的不规则 4-连通形状）；首列的每行有一个青(8)标记像素作为下带的行调色板（下带的每一行一个颜色，如第一行青(8)、第二行栗(9)、第三行品红(6)，各行颜色可不同但均从非黑非灰中选取）。生成约束：上下掩码的交集（同时为前景的单元格集合）非空且不等于任一单个掩码。

**规则**：
1. 对上带和中带进行单元格级对齐：上带的第 k 个单元格对应中带的第 k 个单元格。
2. 一个单元格位置是"活跃"的，当且仅当上带该单元格有红(2)前景**且**中带该单元格有蓝(1)前景。
3. 读取下带中唯一非空非首列单元格的绿(3)模板图案。
4. 读取下带首列各行的青(8)/栗(9)/品红(6)标记作为行调色板。
5. 清空下带所有单元格（含模板源单元格和首列标记），全置为黑(0)。
6. 在下带的每个活跃单元格中，印章模板图案：模板图案的每个绿(3)像素按其在单元格内的相对坐标放置，颜色替换为该行对应的行调色板颜色。
7. 删除上带和中带及所有灰(5)分隔行，仅输出下带内容（高度等于一个带的高度，宽度等于原网格去掉垂直分隔线后各单元格拼接的宽度）。

**关键洞察**：任一掩码单独都无法确定输出图案——必须计算两个掩码的交集才能知道哪些位置印章模板。行调色板增加了第三层信息：即使两个活跃单元格在同一列，如果它们在模板中的行不同，印出的像素颜色也不同。

## 新题 6：路径绕行后按路径侧性分色填充

**组合逻辑**：[路径绘制 + 绕行 + 障碍色决定绕行](已有) → [洪泛填充](已有，创新：填充对象是路径与障碍围成的区域) + [相对位置决定颜色](已有，创新：位置判断标准不是象限而是"路径上方/下方")

**来源原语**：路径绘制(path_drawing)、绕行(detour)、障碍色决定绕行(obstacle_color_detour)、边界标记(border_marker)、障碍条(obstacle_bar)、路径轨迹(path_trace)、阻挡(blocking) 来自 96a8c0cd；洪泛填充(flood_fill)、封闭背景区域(enclosed_bg) 来自 83302e8f；相对位置决定颜色(relative_position_determines_color) 来自 639f5a19

**依赖链**：障碍颜色决定绕行方向 → 绕行方向决定路径的曲折形状 → 路径形状与障碍和网格边界共同围成封闭区域 → 每个封闭区域相对于路径的位置（上方或下方）决定其填充颜色。去掉障碍色逻辑则绕行方向不确定，去掉路径绘制则无封闭区域，去掉侧性判断则颜色不确定。

从边界标记出发向内画红色路径，遇蓝色障碍从左侧绕行、遇绿色障碍从右侧绕行；完成后对路径围成的封闭区域按"路径上方/下方"分色填充。

**输入结构**：黑(0)背景，约 12x14 网格。左边界某行有一个红(2)标记像素（边界标记），标示路径起点。网格内部有 3-5 条蓝(1)和绿(3)水平障碍条（每条 1 像素厚、2-4 像素长），垂直于标记的前进方向（向右），障碍条分布在路径可能经过的行附近。生成约束：障碍条不接触网格边界的上下边，障碍条之间不相邻；路径在绕行后总能恢复到原行继续前进；绕行产生的曲折路径与网格边界及障碍共同围成至少 2 个封闭黑(0)区域，且上方和下方各至少 1 个。

**规则**：
1. 从红(2)标记像素向右画红(2)路径轨迹。
2. 路径沿当前行一直向右前进。遇到障碍条时：
   - 蓝(1)障碍：路径在障碍左侧一列向上绕行——上移一格、右移越过障碍、下移回到原行，继续向右。（"左侧"相对于行进方向的左方，即上方。）
   - 绿(3)障碍：路径在障碍右侧一列向下绕行——下移一格、右移越过障碍、上移回到原行，继续向右。
3. 路径到达右边界后停止。所有路径经过的背景像素变为红(2)。障碍条像素保持原色不被覆盖。
4. 识别所有被红(2)路径 + 障碍条 + 网格边界完全封闭的 4-连通黑(0)背景区域。
5. 对每个封闭区域，判断其所有像素是否均位于路径轨迹的上方（行号小于路径在该列的行号）：若是则填黄(4)。判断其所有像素是否均位于路径轨迹的下方（行号大于路径在该列的行号）：若是则填橙(7)。
6. 与网格边界连通的非封闭背景区域保持黑(0)。

**关键洞察**：蓝色障碍使路径向上鼓包、绿色障碍使路径向下鼓包；向上鼓包在路径下方创造封闭区域（填橙），向下鼓包在路径上方创造封闭区域（填黄）。直觉上"蓝→上绕→下方有区域→橙"的间接关系是非显然的——障碍色不直接决定填充色，而是通过路径形状间接决定。

## 新题 7：自相似晶格复原后前缀编码分行变色

**组合逻辑**：[补全 + 自相似晶格映射 + 缩略图复原](已有) + [重涂色 + 编码映射 + 前缀色映射补全行](已有，创新：编码映射不作用于行模板，而是作用于晶格中的每行精灵体副本) → [标记 + 局部对应晶格坐标](已有)

**依赖链**：精灵体掩码 = 粗晶格掩码 → 恢复被遮挡行/列的副本位置 → 每行精灵体副本根据该行左侧前缀色映射获得独立的颜色方案 → 每个副本中局部坐标等于晶格坐标的像素标记为黄(4)。去掉自相似恢复则不知哪些插槽需要副本，去掉前缀编码则所有行同色（与参考题 456873bc 相同，非创新），去掉坐标标记则输出不完整。

利用精灵体的自相似性恢复被遮挡的插槽副本，然后通过每行的前缀色映射赋予各行副本不同的配色方案，最后在每个副本中标记其晶格坐标对应的像素。

**输入结构**：黑(0)背景，约 17x17 网格。网格逻辑上是一个 k×k 晶格（k=5），每个插槽大小 k×k（含 1 像素黑色分隔带）。一种前景色（红(2)）在部分插槽中形成同一个 k×k 精灵体图案的副本（精灵体内的前景像素形成一个 4-连通不规则形状，约占插槽面积的 40-60%）。一条灰(5)实心矩形条完全遮挡一整行插槽（如第 2 行的所有 k 个插槽被灰条覆盖）。在每行插槽的最左侧（第 0 列插槽的左边界外、分隔带内或与分隔带相邻的 1 像素列）有一个前缀色像素（可为蓝(1)、绿(3)、橙(7)、品红(6)、青(8)中的一个），每行颜色不同。生成约束：精灵体的前景掩码恰好与包含副本的插槽位置一一对应（自相似）；被遮挡行中至少有一个插槽应包含副本（可从自相似掩码推断）。

**规则**：
1. 识别精灵体图案：从可见的副本中提取 k×k 精灵体掩码（前景像素 = 1，背景 = 0）。
2. 将精灵体掩码解读为粗晶格的占位图：掩码中第 (i,j) 个像素为前景 ↔ 晶格中第 (i,j) 个插槽应包含一份副本。
3. 擦除灰色遮挡条，在每个应有副本的插槽（包括被遮挡行中的）重新绘制精灵体。
4. 对每行 i（i=0..k-1），读取该行的前缀色像素 C_i。将该行所有插槽中的精灵体副本从红(2)重涂为 C_i（前缀色映射：红(2) → C_i）。
5. 对每个插槽 (i,j) 中的副本，找到副本内部局部坐标为 (i,j) 的那个像素（如果该像素是前景像素），将其标记为黄(4)，覆盖步骤 4 的颜色。如果该像素本来就是背景，则不做标记。
6. 保持所有分隔带和背景不变。

**关键洞察**：自相似恢复解决"哪里放副本"，前缀编码解决"每行副本用什么颜色"，坐标标记解决"每个副本中哪个像素特殊"——三个独立信息源交汇在同一个输出上，缺少任何一个都无法完整确定输出。

## 新题 8：高度归一化后隐式对齐触发连线

**组合逻辑**：[对齐 + 最大高度归一化 + 基线对齐](已有，创新：归一化改变了嵌入标记的行位置) → [连线 + 同行同列对齐](已有，创新：连线条件基于归一化后才出现的对齐关系) + [仅相邻锚点间连接](已有)

**依赖链**：高度归一化改变青色段的高度 → 嵌入在青色段中的标记像素随之移动到新的行位置 → 归一化后，某些原本不在同一行的标记像素变为同行对齐 → 同行对齐且路径畅通的相邻标记对之间画连线。去掉归一化则标记位置不变、无法确定对齐关系，去掉连线则输出不完整。

将高度不等的双色竖条归一化到统一高度，归一化使得嵌入在竖条中的标记像素移动到新位置；然后在归一化后恰好对齐到同行的标记像素之间画水平连线。

**输入结构**：黑(0)背景，约 16x14 网格。一条红(2)标记行和紧邻其下的一条灰(5)标记行横跨网格，占据隔列的位置（如列 1、3、5、7...），两条标记行在这些列处各有一个像素。标记列之间的列为竖条列：每根竖条由紧邻红标记行上方的一段连续青(8)像素和紧邻灰标记行下方的一段连续蓝(1)像素组成。各竖条的青段高度不同（2-5 像素），蓝段高度也不同（1-4 像素）。在部分竖条的青段中，某一个青(8)像素被替换为黄(4)标记像素（标记像素的行位置 = 该竖条从红标记行往上数的第 m 行，不同竖条的 m 可能不同）。约 40-60% 的竖条含有黄色标记。生成约束：归一化后至少有两个标记像素落在同一行上，且它们之间的路径上无其他非背景像素阻挡。

**规则**：
1. 计算所有竖条中青段的最大高度 h_max。
2. 对每根竖条，将其青段向上延伸（或保持不变）使其高度恰好为 h_max，新增的青段像素从红标记行上方第一行开始往上填充，直到高度达到 h_max。如果竖条原本含有黄(4)标记像素，该标记像素在青段中的相对位置保持不变（即它到红标记行的距离不变）。
3. 对每根竖条，将其蓝段移至紧接灰标记行下方开始向下延伸，保持蓝段原有高度不变。蓝段下方到原蓝段底部之间的空隙填栗(9)。
4. 归一化完成后，收集所有黄(4)标记像素的坐标。对同一行的黄色标记，按列从左到右排序，仅考虑相邻对：如果两个相邻标记之间的水平线段上所有像素均为黑(0)背景，则在这些像素上画一条绿(3)水平连线。如果中间有非背景像素（如某根无标记竖条的青段），则不连线。
5. 红/灰标记行像素和所有竖条像素保持不变（连线不覆盖它们）。

**关键洞察**：归一化将所有青段拉伸到相同高度，但标记像素保持与基线的距离不变——因此原本在不同行的标记像素在归一化后仍可能在不同行（取决于它们到基线的原始距离），只有那些到基线距离相同的标记像素才会对齐。求解者必须先理解归一化机制，再推断哪些标记会对齐。

**规则**：
1. 从左上角 (0,0) 开始，初始方向向右，画绿(3)螺旋路径：
   - 每步前进一格，将当前格涂绿(3)。

   - 如果转向后仍无法前进（四个方向都不可行），则停止。
2. 螺旋绘制完成后，灰(5)障碍像素保留不变。

5. 与网格边界连通的非封闭黑(0)区域保持不变。

**关键洞察**：没有障碍时，顺时针螺旋会产生一个中心的封闭小区域（面积固定）；加入障碍后，螺旋被迫提前转向或跳过区域，打破了规则性，产生大小各异的封闭区域。障碍像素本身不被涂色，但它们作为"墙壁"参与封闭区域的边界判定。

**来源原语**：重涂色(recolor)、缺失中心(missing_center)、四向对齐(four_way_aligned)、微型条(micro_bar)、隐含十字(implied_plus) 来自 9f5f939b；连线(connect)、中心对角对齐(center_diagonal_alignment)、无障碍通路(unobstructed_path) 来自 55059096；忽略干扰项(ignore_distractors) 来自 0a2355a6

**依赖链**：四向对齐的微型条组合识别 → 推断隐含十字中心并标记 → 中心之间的对角对齐检测 → 对角路径上的无障碍通路检查（未成组微型条充当障碍）→ 通路畅通则画对角连线。去掉中心检测则不知道连线端点，去掉对角对齐则不知道哪些中心应连，去掉障碍检查则会错误连线。

先从散布的二像素微型条中识别隐含十字图案并标记其缺失中心，然后在对角对齐且路径畅通的中心之间画对角连线——路径上的散落微型条既是干扰项也是障碍物。

**输入结构**：黑(0)背景，约 14x14 网格。红(2)前景像素构成若干孤立的水平或垂直二像素微型条（每根条恰好 2 个相邻红像素，水平或垂直排列）。部分微型条四根一组构成隐含十字图案：一个空白中心像素的上下左右各 2-3 格处各有一根朝向中心的微型条（上方垂直条、下方垂直条、左方水平条、右方水平条），中心与每根条之间有恰好 1 个空像素间距。其余微型条不构成任何十字图案（干扰项）。生成约束：至少 3 个隐含十字，其中至少一对中心的行距等于列距（对角对齐）；至少一条对角通路被干扰微型条阻断，至少一条畅通。

**规则**：
1. 对每个黑(0)背景像素 (r,c)，检查它是否是隐含十字的中心：在四个基本方向上（上下左右），偏移 2-3 格处是否存在朝向 (r,c) 的红(2)二像素微型条，且偏移 1 格处为黑(0)背景。如果四个方向均满足，则 (r,c) 是隐含十字中心，将其标记为黄(4)。
2. 构成隐含十字的四根微型条保持红(2)不变。干扰微型条也保持红(2)不变。
3. 对每对黄(4)中心 (r1,c1) 和 (r2,c2)，检查是否对角对齐：|r1-r2| == |c1-c2| 且 > 0。
4. 对每对对角对齐的中心，检查从 (r1,c1) 到 (r2,c2) 的严格对角线段上（不含端点）的每个像素是否均为黑(0)背景。如果有任何红(2)像素（来自干扰微型条或隐含十字的组成条）阻挡该路径，则不连线。
5. 如果路径畅通，将路径上所有黑(0)像素涂为绿(3)，形成对角连线。
6. 若多条连线交叉，绿(3)像素互相覆盖无冲突（颜色相同）。连线不覆盖黄(4)端点。

**关键洞察**：微型条有三重身份——作为隐含十字的组成部分（标识中心）、作为干扰项（误导求解者寻找不存在的十字）、以及作为对角通路上的障碍物（阻止连线）。一根落在两个中心对角线上的干扰微型条会阻断本应存在的连线，使求解者必须同时考虑十字识别和通路检查两个层面。
