## 新题 1：贪心射线互阻

**组合逻辑**：[贪心选择](创新：按面积排序决定射线绘制顺序) + [射线延伸](创新：射线遇到先前射线即停止) + [方向指示](已有) → 迭代阻塞结构

**来源原语**：射线延伸(ray_extend) ← 5c0a986e；贪心选择(greedy_selection)、障碍像素(obstacle_pixel)、从大到小优先(largest_first_priority) ← 31adaf00；指示像素(indicator_pixel)、方向指示(direction_indication) ← b527c5c6；正方形(square) ← 5c0a986e

**依赖链**：面积排序决定处理顺序 → 先处理的射线成为后续射线的障碍 → 障碍截断后续射线长度。删除排序则无法确定谁阻挡谁；删除射线延伸则无输出；删除方向指示则无法确定射线方向。

根据面积从大到小依次从每个正方形发出方向射线，先绘制的射线成为后续射线的障碍物，从而截断后续射线的长度。

**输入结构**：约 15x15 黑(0)背景网格。包含 3-5 个不同颜色的实心正方形（各为蓝(1)、红(2)、绿(3)、黄(4)等，边长 2-4 像素不等，面积互不相同）。每个正方形外侧恰好有一个灰(5)指示像素，紧贴正方形边界的某一侧（上、下、左、右之一），且该方向上到网格边缘的路径初始全为黑(0)背景。各正方形互不相邻（边界框间距至少 2 像素）。生成约束：至少有两个正方形的射线路径存在交叉（即某个较小正方形的射线方向上会经过某个较大正方形的射线轨迹）。

**规则**：
1. 按正方形面积从大到小排序。若面积相同（生成时保证不会出现），以边界框左上角的行优先、列次优先的阅读顺序为先。
2. 依次处理每个正方形：确定射线方向——指示像素相对于正方形中心的方位即为射线方向（指示像素在正方形上方→向上延伸，在右方→向右延伸，以此类推）。
3. 从指示像素出发，沿该方向逐像素绘制射线，颜色为该正方形的颜色。射线每步前进一个像素，遇到以下情况之一即停止（不包含停止位置的像素）：(a) 下一个像素超出网格边界；(b) 下一个像素为非背景色（已有的正方形、或先前绘制的射线）。
4. 指示像素本身被重涂为该正方形的颜色，成为射线的起点。
5. 所有正方形的原始像素保持不变。

**关键洞察**：射线的可达长度不由自身决定，而由处理顺序中更早绘制的射线所产生的障碍决定。大正方形的射线优先绘制并占据空间，小正方形只能在剩余通道中延伸。需要对比多个示例才能归纳出"面积决定优先级"这一隐藏排序规则。

## 新题 2：循环位移改变封闭拓扑

**组合逻辑**：[循环位移](已有) + [洪泛填充](创新：作用于位移后的拓扑结构) + [重涂色](创新：标记像素颜色决定封闭区域填充色) → 变换-拓扑-分类链

**来源原语**：循环位移(cyclic_roll)、控制行(control_row)、控制列(control_column)、标记位定位移量(marker_is_shift)、双轴偏移编码(dual_axis_offset) ← 79cce52d；洪泛填充(flood_fill)、线条对象(line_object)、封闭区域(enclosed_region)、内外分区(in_out_partition)、边界连通分内外(border_in_out) ← 7b6016b9；重涂色(recolor) ← 8a371977

**依赖链**：控制行/列标记的位置决定位移量 → 位移改变线条对象的缠绕方式从而改变封闭拓扑 → 洪泛填充根据新拓扑区分内外 → 标记像素的颜色决定封闭区域的填充色。四步形成不可跳跃的信息链：不知位移量则不知拓扑；不知拓扑则无法区分内外；不知标记颜色则不知封闭区域填色。

将载荷中的线条对象按控制行/列标记的位置做双轴循环位移，然后根据位移后的拓扑判定封闭与外部区域，外部填绿、封闭区域填为标记像素的颜色。

**输入结构**：约 12x12 正方形网格。顶行为控制行：全部灰(5)，其中恰好一个像素为非灰非黑的颜色（如蓝(1)、红(2)或橙(7)等），该像素既编码列位移量（其零基列索引），也编码封闭区域的目标填充色。最左列为控制列：全部灰(5)，其中恰好一个像素与控制行标记同色，编码行位移量（其零基行索引）。控制行与控制列的左上角交汇像素为灰(5)。去掉控制行和控制列后的载荷区域（约 11x11）为黑(0)背景上的一个红(2) 4-连通线条对象，该线条对象在当前位置下形成至少一个封闭区域（4-连通背景不可达网格边界的区域）。生成约束：循环位移后，封闭区域的数量或位置必须与位移前不同（即位移确实改变了拓扑结构）。

**规则**：
1. 记录控制行标记像素的颜色 C 和零基列索引 dx，以及控制列标记像素的零基行索引 dy。
2. 移除控制行（顶行）和控制列（最左列），得到载荷网格。
3. 将载荷网格向右循环位移 dx 列（超出右边界的列回绕到左边界），然后向下循环位移 dy 行（超出底边界的行回绕到顶部）。
4. 在位移后的载荷网格上，以红(2)线条对象为墙壁执行 4-连通洪泛填充：从网格四条边界上的所有黑(0)像素出发，所有 4-连通可达的黑(0)像素标记为外部，重涂为绿(3)。
5. 剩余黑(0)像素（不可从边界 4-连通到达的）为封闭区域，重涂为颜色 C。
6. 红(2)线条对象像素保持不变。

**关键洞察**：循环位移使线条对象的两端在网格对侧"缝合"或"断开"，从根本上改变了哪些区域被封闭。同一个线条对象在不同位移下可以封闭完全不同的区域集合。仅看位移后的结果无法推断规则，必须对比位移前后的拓扑变化，并发现标记像素同时编码位移量和填充色的双重角色。

## 新题 3：标记计数决定同心填充深度

**组合逻辑**：[计数](创新：计数结果作为同心层填充的深度参数) + [同心层填充](创新：层数由外部计数决定而非框内空间) + [对角序映射色环](已有) → 参数编码结构

**来源原语**：同心层填充(concentric_fill)、空心矩形框(hollow_rect_frame)、嵌套层次(nesting_hierarchy)、对角序映射色环(diagonal_color_bands) ← 99306f82；计数(counting)、标记像素(marker_pixel) ← 358ba94e / a934301b；对角线标记(diagonal_marker) ← 99306f82

**依赖链**：标记像素计数 → 计数值作为同心带数量参数 → 对角色板提供带颜色序列。删除计数则不知填多少层；删除色板则不知每层什么颜色；删除填充则无输出。三者缺一不可。

统计每个空心矩形框内的黄色标记像素数量，该数量决定在框内绘制多少圈同心矩形带，带的颜色依次取自网格角落的对角色板序列。

**输入结构**：约 20x20 黑(0)背景网格。包含 3-4 个红(2)空心矩形框（1 像素厚的矩形边框），大小不同（内部空间至少 5x5），互不重叠且互不相邻。每个框内部散布若干黄(4)标记像素（1-4 个不等），位置随意但不与框边重合。在网格的左上角区域（所有框的外部），有一条从某像素出发沿右下对角方向排列的色板序列，每个像素一种不同颜色（从 {蓝(1), 绿(3), 灰(5), 橙(7)} 中取），共 4 个像素，依次紧邻排列（行列各递增 1）。生成约束：每个框内的标记数量互不相同；最大标记数量不超过色板长度（4）；框的内部空间足以容纳对应层数的同心带。

**规则**：
1. 识别所有红(2)空心矩形框，统计每个框内部黄(4)标记像素的数量 n。
2. 读取左上角的对角色板序列：沿右下对角方向依次读取各像素颜色，记为 P[0], P[1], P[2], P[3]。
3. 对每个框，在其内部绘制 n 圈同心矩形带：最外圈使用颜色 P[0]，次外圈使用 P[1]，依此类推。最内层的剩余中心区域由第 n 圈颜色填满（即最内层颜色为 P[n-1]）。
4. 黄(4)标记像素被同心带覆盖，不保留在输出中。
5. 框内无标记像素（n=0）时，内部保持黑(0)不变。
6. 红(2)框本身和对角色板序列像素保持不变。

**关键洞察**：黄色标记像素是数量令牌而非空间模板——它们的位置无关紧要，只有总数决定填充深度。一个有 3 个标记的框获得 3 圈同心带，无论标记分布在框内的哪里。必须对比多个框的标记数量与对应的同心带层数，才能归纳出"计数即深度"的规则。

## 新题 4：挖孔造通道与重力下落

**组合逻辑**：[挖孔](创新：挖出的孔洞不只是装饰，而是构成重力下落的通道) + [重力下落](创新：重力路径由挖孔结果决定) + [同色匹配](已有：匹配模板与块) → 地形构造-导航结构

**来源原语**：挖孔(punch_holes)、单色块(monochrome_block)、模板图案(motif_stencil)、同色匹配(same_color_matching)、保持行列顺序(preserve_row_col_order) ← 58f5dbd5；重力下落(gravity_drop)、可移动对象(movable_object)、通道对齐(channel_aligned) ← df9fd884

**依赖链**：同色匹配确定哪个模板与哪个块配对 → 挖孔在块内创建通道 → 重力下落沿通道运行。不知配对则不知挖哪些孔；不知孔洞则不知重力路径；不执行重力则可移动对象位置错误。

将同色模板图案从对应的实心块中挖出，形成孔洞通道；然后让位于块上方的灰色"砝码"像素受重力下落，砝码穿过挖出的孔洞继续下落，直到遇到实心表面或网格底部停止。

**输入结构**：约 16x20（宽x高）黑(0)背景网格。上半区有 2-3 个灰(5)单像素"砝码"，分散在不同列。中间区域有 2-3 个实心 5x5 单色块，颜色各不同（如蓝(1)、红(2)、绿(3)），每个块水平排列、互不重叠，各块之间有至少 1 列间距。每个块在其下方或侧方有一个同色的小模板图案（4-连通，3-5 像素，边界框不超过 3x3），不与任何块重叠。生成约束：每个砝码的列坐标落在某个块的列范围内；每个模板图案居中对齐到对应块时，挖出的孔洞中至少有一个与某个砝码的列坐标重合（保证至少一个砝码会穿过孔洞）；砝码均位于所有块的上方。

**规则**：
1. 按颜色匹配：将每个小模板图案与同色 5x5 块配对。
2. 将每个模板图案的边界框居中对齐到其配对块的 5x5 区域。将模板图案覆盖的位置从块中挖去（这些像素变为黑(0)背景）。
3. 从网格中擦除所有模板图案的原始位置（设为黑(0)）。
4. 对每个灰(5)砝码执行重力下落：砝码从当前位置逐行向下移动。砝码在其正下方的像素为黑(0)（包括被挖出的孔洞）时继续下落；当正下方像素为非黑非灰颜色（块的实心部分）或到达网格最底行时停止。砝码最终停在最后一个可到达的黑(0)位置上。
5. 砝码处理顺序为从上到下（行号小的先处理）、同行则从左到右。先落定的砝码占据其位置，后续砝码不可穿过已落定的砝码（已落定砝码视为非背景障碍）。
6. 输出包含挖孔后的块（带孔洞）和落定位置的灰(5)砝码。

**关键洞察**：同一个模板图案同时承担两个角色——作为视觉标识（颜色匹配块）和作为结构修改器（在块内创建重力通道）。砝码能否穿过某个块完全取决于该块被挖出的孔洞是否恰好在砝码的列上。不知道颜色匹配规则就无法确定挖孔位置，不知道挖孔位置就无法预测砝码终点。

## 新题 5：格子阵列位置决定指示像素的操作分支

**组合逻辑**：[边缘与内部区分](已有：分类) → [延伸|重涂色](创新：同类触发器根据位置执行不同操作) → 位置条件分支结构

**来源原语**：延伸(extend)、指示像素(indicator_pixel)、方向指示(direction_indication)、指示侧扩展至边界(extend_from_indicator_to_edge)、画布边界(canvas_boundary) ← b527c5c6；重涂色(recolor)、格子结构(lattice)、单元格区域(cell_region)、行列阵列位置(row_column_position)、边缘与内部区分(perimeter_interior_distinction) ← 8a371977

**依赖链**：格子结构确定阵列位置 → 位置分类（边缘/内部）决定操作类型 → 边缘单元执行延伸操作、内部单元执行填充操作 → 指示像素提供方向（边缘情况）或颜色（两种情况）。位置分类是操作选择的前提，操作类型决定指示像素的作用方式。

在格子阵列中，边缘单元格的指示像素向网格外侧发射延伸带，内部单元格的指示像素填充整个单元格区域。同一种输入元素（指示像素）在不同阵列位置产生完全不同的输出效果。

**输入结构**：约 17x17 网格。灰(5)格子线（1 像素宽）将网格划分为 4x4（即 4 行 4 列共 16 个）的矩形单元格区域，每个单元格内部约 3x3 像素。格子线覆盖网格的四条外边界以及内部的分隔线。所有单元格内部初始为黑(0)。其中 5-8 个单元格内包含一个彩色指示像素（颜色从 {蓝(1), 红(2), 绿(3), 黄(4)} 中取），该像素紧贴单元格四条内壁之一（即位于单元格内部区域的最北/最南/最东/最西行或列上，紧邻格子线）。其余单元格为空（全黑）。生成约束：边缘单元格（行索引为 0 或 3，或列索引为 0 或 3 的单元格）和内部单元格（行列索引均在 1-2 之间的单元格）中均有指示像素出现；指示像素所指方向为其紧贴的内壁朝向外侧的方向（如像素贴北壁则指向北方）。

**规则**：
1. 将 4x4 阵列中的单元格分为两类：边缘单元格（其阵列行号为 0 或 3、或阵列列号为 0 或 3）和内部单元格（阵列行号 1-2 且列号 1-2）。
2. 对于含指示像素的**边缘单元格**：确定指示像素所贴内壁的朝外方向。从指示像素出发，沿该方向穿过格子线向网格边缘延伸一条 1 像素宽的带，使用指示像素的颜色绘制，覆盖路径上的所有像素（包括穿过的灰(5)格子线像素），直到到达网格边缘（含边缘像素）。
3. 对于含指示像素的**内部单元格**：用指示像素的颜色填充该单元格的整个内部区域（所有黑(0)像素变为该颜色）。指示像素自身作为填充的一部分保留。
4. 无指示像素的单元格内部保持黑(0)。
5. 未被延伸带覆盖的灰(5)格子线保持不变。

**关键洞察**：规则对指示像素的处理取决于其所在单元格的阵列位置，而非像素本身的属性。相同颜色、相同朝向的指示像素在边缘单元格和内部单元格产生截然不同的效果（射线 vs 区域填充）。仅从单个示例中看到一种情况无法归纳出分支规则，必须同时观察边缘和内部的不同表现。

## 新题 6：标记计数门控平铺与擦除分支

**组合逻辑**：[计数](创新：计数结果作为三路分支的判据) → {0: 不变 | 1: [平铺](创新：使用跨区域引用的模板) | 2+: [擦除+重涂色]} → 计数-分支-跨区域引用结构

**来源原语**：计数(counting) ← 358ba94e / a934301b / 6455b5f5；平铺(tiling)、模板精灵体(template_sprite)、间距保持一致(gaps_preserved) ← 9b2a60aa；擦除(erase)、标记超阈值则擦除(erase_above_threshold)、标记包含于对象(marker_in_object) ← a934301b；分隔线(divider_line)、封闭区域(enclosed_region)、面积比较(area_comparison) ← 6455b5f5；重涂色(recolor) ← 6455b5f5

**依赖链**：计数蓝色标记 → 计数值决定走哪条分支 → 单标记分支需要从模板区域获取模板形状 → 模板区域的识别依赖面积比较（最小区域）。计数是分支入口，模板区域是跨区域信息传递，两者不可省略。

红色分隔线将网格划分为多个区域。统计每个区域内的蓝色标记数量：0 个标记的区域不变；恰好 1 个标记的区域用来自最小区域的模板进行平铺填充；2 个及以上标记的区域整体涂为灰色。

**输入结构**：约 18x18 黑(0)背景网格。红(2)分隔线（1 像素宽，水平或垂直贯穿网格）将网格划分为 5-7 个互不重叠的矩形区域。每个区域内部为黑(0)背景。其中一个区域面积最小（生成时保证唯一最小），内部包含一个绿(3)模板精灵体（4-连通，3-6 像素，不对称形状，边界框不超过 3x3）。其余区域内散布 0-3 个蓝(1)标记像素（单像素，位置随意）。生成约束：至少一个区域有 0 个标记，至少一个区域有恰好 1 个标记，至少一个区域有 2 个或更多标记（保证三个分支均可观察）；单标记区域的尺寸至少为模板边界框的 2 倍（保证平铺可见）。

**规则**：
1. 识别面积最小的区域为模板区域。提取其中绿(3)模板精灵体的形状及其相对于模板区域左上角的边界框位置。模板区域在输出中保持不变。
2. 对每个非模板区域，统计其内部蓝(1)标记像素的数量 n。
3. n = 0：区域内部保持黑(0)，不做任何改动。
4. n = 1：以该区域的左上角为起点，以模板精灵体边界框的宽和高为步幅（列步幅 = 边界框宽，行步幅 = 边界框高），在区域内重复平铺模板形状。每个平铺副本着色为蓝(1)。超出区域边界的平铺副本仅保留区域内的部分（裁剪）。原有的蓝(1)标记像素若被平铺覆盖则自然融入，若不被覆盖则保留。
5. n >= 2：擦除区域内所有蓝(1)标记像素，将区域内部整体填充为灰(5)。
6. 红(2)分隔线在输出中保持不变。

**关键洞察**：标记像素的数量不是一个连续变量，而是一个离散的分支选择器：零、一、多分别触发完全不同的操作（保持、平铺、覆盖）。单标记分支的平铺模板并不在本区域内定义，而需跨区域从最小区域获取——这种跨区域信息传递使得单独分析一个区域无法得出结果。需要多个示例才能区分三条分支，并发现模板来源的规则。

## 新题 7：形状匹配定目标、标记朝向定旋转

**组合逻辑**：[形状匹配](已有：确定配对) + [旋转](创新：旋转角度由标记像素与目标边沿指示的对应关系唯一确定) + [平移](已有) + [擦除](已有) → 多约束同时满足结构

**来源原语**：旋转(rotate) ← 94133066 / 6e4f6532；平移(translate) ← 6e4f6532；擦除(erase) ← 6e4f6532；形状匹配(shape_matching)、精灵体(sprite)、孔洞(hole) ← 97a05b5b；标记像素(marker_pixel)、标记颜色对应(marker_color_match)、标记色定朝向(marker_color_sets_orientation) ← 6e4f6532 / 94133066

**依赖链**：形状匹配确定哪个精灵体对应哪个槽位 → 对于有旋转对称性的精灵体，形状匹配不能唯一确定旋转角度 → 标记像素与槽位指示像素的位置对应关系消除旋转歧义 → 平移将旋转后的精灵体放入槽位。形状匹配和标记定向是两个独立约束，必须同时满足才能确定唯一输出。

将左侧的彩色精灵体旋转后嵌入右侧黄色底板上形状匹配的槽位中，旋转角度由精灵体上的蓝色标记像素与槽位旁的蓝色指示像素之间的方位对应关系唯一确定。

**输入结构**：约 16x16 黑(0)背景网格，被一条灰(5)垂直分隔线分为左右两半（各约 7 列宽）。
- 左半部分：包含 2-3 个绿(3)精灵体（4-连通，各 4-7 像素），互不接触。每个精灵体中恰好有一个像素为蓝(1)而非绿(3)，此为方向标记像素。精灵体的总形状（绿+蓝像素的并集）在 4 种旋转（0/90/180/270 度）下至少有两种旋转产生相同形状（即精灵体具有一定旋转对称性，使得纯形状匹配无法唯一确定旋转角度）。
- 右半部分：黄(4)填充的矩形底板，底板内有与精灵体数量相同的槽位（黑(0)连通区域），每个槽位的形状恰好与某个精灵体的总形状在某个旋转下匹配。每个槽位的外围（在黄(4)底板内，紧邻槽位边界外侧一个像素处）有恰好一个蓝(1)指示像素。
- 生成约束：每个精灵体恰好与一个槽位配对（双射）；对于每对配对，在所有形状兼容的旋转中，恰好只有一种旋转使得精灵体的蓝(1)标记像素旋转后位于槽位中靠近蓝(1)指示像素的那一侧（即标记像素在精灵体边界框的北/南/东/西侧，与指示像素相对于槽位的北/南/东/西方位一致）。

**规则**：
1. 对每个左侧精灵体，在右侧所有槽位中寻找形状匹配：将精灵体的总形状（绿+蓝像素并集）分别旋转 0/90/180/270 度，与每个槽位的黑(0)区域形状比较。找到形状一致的配对及其候选旋转集合。
2. 对每个配对，确定唯一旋转：检查槽位外侧蓝(1)指示像素相对于槽位边界框的方位（北/南/东/西）。在候选旋转中选择唯一的那个，使得精灵体旋转后其蓝(1)标记像素位于精灵体边界框的相同方位（北→北，南→南，东→东，西→西）。
3. 将旋转后的精灵体平移至槽位中：绿(3)和蓝(1)像素覆盖槽位的黑(0)像素。
4. 擦除左侧精灵体的原始位置（所有像素设为黑(0)）。
5. 灰(5)分隔线、黄(4)底板、槽位旁的蓝(1)指示像素保持不变。

**关键洞察**：形状匹配解决"去哪个槽位"的问题，但对于具有旋转对称性的精灵体，它无法确定"以哪个角度放入"。蓝色标记像素的存在打破了旋转对称性——它在精灵体的某一侧，必须对准槽位指示像素的方位。两个独立约束（形状一致 + 标记对准）共同确定唯一解，缺少任何一个都会产生歧义。
