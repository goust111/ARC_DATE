## 新题 1：镜像触发邻接传色

**组合逻辑**：[镜像/mirror](创新：镜像结果改变拓扑邻接关系) + [邻接传色/adjacency_transfer](已有) + [填充/fill](创新：填充目标由镜像后的邻接决定) ← 条件节点 [包围盒内翻转/flip_within_bbox] + [标记接触即赋色/marker_touch_color]

**来源原语**：镜像、包围盒、逐色独立变换 ← e74e1818；填充、空心矩形框 ← 94414823；邻接传色、中性遮罩、标记接触即赋色 ← b7256dcd

**依赖链**：镜像操作改变各颜色掩码的空间位置 → 位置变化导致与中性区域的 4-邻接关系发生改变 → 只有镜像后仍与中性区域邻接的颜色才能传色。镜像前邻接但镜像后不邻接的颜色被排除，镜像前不邻接但镜像后新产生邻接的颜色被引入。删除镜像步骤则无法确定哪些颜色最终传色；删除邻接传色则镜像结果无处应用。

对灰(5)中性区域重涂色：先将每种前景色掩码在各自包围盒内垂直镜像，再检查镜像后哪些颜色的掩码与灰(5)区域 4-邻接，据此将灰(5)区域染为对应颜色。

**输入结构**：约 12x12 的黑(0)背景网格。网格中有 2~3 个灰(5) 4-连通中性区域，每个区域为 4~8 像素的不规则形状。另有 3~4 种不同颜色（从蓝(1)、红(2)、绿(3)、黄(4)中选取）的前景掩码，每种颜色为一个 3~6 像素的 4-连通单色区域。各颜色掩码的包围盒互不重叠。生成约束：至少有一个颜色掩码在镜像前与某灰(5)区域 4-邻接但镜像后不再邻接，且至少有一个颜色掩码在镜像前不与任何灰(5)区域邻接但镜像后与某灰(5)区域 4-邻接。每个灰(5)区域在镜像后恰好被一种颜色掩码邻接。

**规则**：
1. 对每种非背景(0)、非灰(5)的前景颜色，找到该颜色所有像素的最小包围盒（矩形边界框）。
2. 在每个包围盒内，将该颜色掩码的每个像素 (r, c) 映射到 (r0 + r1 - r, c)，其中 r0、r1 分别是包围盒的顶行和底行。灰(5)区域和背景(0)不参与镜像。
3. 镜像完成后，对每个灰(5) 4-连通区域，检查其边界像素的 4-邻居中是否存在非背景、非灰的前景色像素。
4. 若某灰(5)区域恰好与一种前景色 4-邻接，将该灰(5)区域的所有像素重涂为该前景色。
5. 若某灰(5)区域不与任何前景色邻接，保持灰(5)不变。
6. 生成约束保证不存在某灰(5)区域同时与两种前景色邻接的情况。

**关键洞察**：镜像操作本身不产生新像素也不改变颜色，但它改变了掩码的空间位置，从而改变了与灰(5)区域的邻接拓扑——传色结果取决于镜像后的邻接关系而非镜像前的。

## 新题 2：封闭区域计数驱动循环位移

**组合逻辑**：[计数/counting](已有) + [重建/reconstruct](已有) + [循环位移/cyclic_roll](创新：位移量不再由标记像素行号编码，而由另一结构的封闭区域数决定) ← 条件节点 [区域数映射长度/region_count_to_length](创新：映射目标从条形长度变为位移量) + [忽略干扰项/ignore_distractors]

**来源原语**：计数、排序、重建、分隔框架、封闭区域、忽略干扰项 ← 89565ca0；裁剪、循环位移、控制列、标记位定位移量 ← 6d1d5c90

**依赖链**：必须先对分隔框架进行墙壁重建并计数封闭区域 → 区域数作为循环位移量应用于相邻的图案区域 → 裁剪掉分隔框架，只输出位移后的图案。删除计数步骤则位移量未知；删除位移步骤则计数结果无处使用。

读取左侧分隔框架中的封闭区域数，以此为量对右侧图案做向下循环位移，输出仅含位移后的图案。

**输入结构**：约 10x16 的黑(0)背景网格，由一条宽 1 像素的灰(5)竖线在第 6 列将网格分为左右两区。左区（列 0~5）包含一个用橙(7)线段绘制的矩形分隔框架，框架内部由橙(7)竖线或横线分隔成若干封闭的黑(0)背景区域（2~5 个）。框架线段可能被少量品红(6)噪声像素打断或遮挡。右区（列 7~15）包含一幅由蓝(1)和红(2)像素构成的彩色图案，图案占满右区的所有行。生成约束：左区封闭区域数严格小于网格总行数；不同示例中封闭区域数不同。

**规则**：
1. 在左区中，识别橙(7)像素组成的线段结构。忽略所有品红(6)像素（视为噪声）。对于被噪声打断的橙(7)线段，若某一行或某一列中橙(7)像素占据了该行/列在左区范围内的多数位置（超过一半），则将该行/列在左区范围内的缺失位置补全为橙(7)，完成墙壁重建。
2. 在重建后的左区中，计算被橙(7)墙壁完全围合的 4-连通黑(0)背景区域的数量，记为 N。
3. 删除左区和灰(5)分隔线，仅保留右区。
4. 将右区图案向下做循环位移 N 行：即原来第 r 行的内容移动到第 (r + N) mod H 行，其中 H 为网格总行数。
5. 输出位移后的右区图案（宽度 = 右区列数，高度 = 原网格行数）。

**关键洞察**：左区的分隔框架并非装饰——它的封闭区域数编码了右区图案的循环位移量。噪声像素的存在迫使求解者先重建墙壁才能正确计数。

## 新题 3：滑走外壳后射线从内核发射

**组合逻辑**：[滑动/slide](已有) + [擦除/erase](创新：滑动自动清除原位置) + [射线延伸/ray_extend](创新：射线中心不是输入中显式的控制像素，而是滑动操作暴露出的隐藏像素) + [重涂色/recolor](创新：对角邻居颜色来自已滑走的外壳色，需要追溯空间从属关系) ← 条件 [颜色决定方向/color_determines_dir] + [像素为射线中心/pixel_as_ray_center]

**来源原语**：滑动、空心矩形、网格边界、颜色编码方向、颜色决定方向 ← f3e62deb；射线延伸、重涂色、控制像素、整行整列射线、对角邻居、像素为射线中心 ← 140c817e

**依赖链**：颜色编码方向决定外壳滑向哪个边界 → 滑动移走外壳后暴露出内部的控制像素 → 控制像素成为射线中心发射十字射线 → 对角邻居的颜色取决于该控制像素原先被哪个颜色的外壳包围（空间从属关系在滑动后已被破坏，需从输入推断）。删除滑动则控制像素被遮挡无法发射射线；删除射线则滑动结果无后续变换；删除对角邻居着色则丢失外壳-内核从属信息。

将每个彩色空心方框滑向其颜色对应的网格边界，暴露出框内的控制像素；从每个控制像素发射十字射线，并在控制像素的对角邻居处标记其原始外壳的颜色。

**输入结构**：约 15x15 的黑(0)背景网格。网格中有 2~3 个 3x3 空心方框（8 像素边框、1 像素中心空洞），每个方框使用不同的颜色（从绿(3)、黄(4)、品红(6)、青(8)中选取）。每个方框的中心像素为蓝(1)控制像素（被方框包围，不可见于方框外部但存在于中心位置）。各方框互不重叠且距网格边界至少 2 像素。生成约束：每个方框滑到对应边界后不与其他已滑动方框重叠；每个控制像素的十字射线（整行整列）在输入中不经过其他方框的内部。颜色方向映射：绿(3)=左、黄(4)=下、品红(6)=上、青(8)=右。

**规则**：
1. 对每个空心方框，根据其颜色确定滑动方向：绿(3)向左、黄(4)向下、品红(6)向上、青(8)向右。
2. 将方框（8 个边框像素）从原位置擦除（变为黑(0)），然后将方框平移至其边框紧贴对应网格边界的位置（保持方框形状和颜色不变）。滑动按方框中心列/行从左到右、从上到下的顺序依次执行。
3. 所有方框滑走后，每个原方框中心的蓝(1)控制像素暴露出来（它们留在原位不动）。
4. 对每个蓝(1)控制像素，将其所在的整行和整列中所有黑(0)背景像素涂为蓝(1)。已被方框占据的像素不被覆盖。
5. 将每个蓝(1)控制像素自身重涂为红(2)。
6. 对每个控制像素，找到它在输入中被哪个颜色的空心方框包围（即输入中该控制像素上下左右 4-邻居均属于同一颜色方框的那个颜色）。将该控制像素的四个对角邻居位置（若在网格内且当前为黑(0)或蓝(1)）涂为该外壳颜色。
7. 后执行的操作覆盖先执行的：若对角邻居着色与射线着色冲突，对角邻居颜色优先。

**关键洞察**：控制像素在输入中被外壳完全遮挡，只有滑走外壳后才能定位它们。而对角邻居的颜色需要回溯输入中的空间包含关系——这一信息在滑动后已不可直接观察。

## 新题 4：压缩双掩码生成种子图案再按周期平铺

**组合逻辑**：[压缩/compress](已有) + [补全/complete](创新：补全的不是输入中可见的局部图案，而是压缩操作产生的新图案) + [平铺/tile](已有) ← 关系 [逐格比较/cell_comparison] + [列周期重复/column_period]

**来源原语**：压缩、堆叠掩码、逐格比较、双背景标记输出 ← fafffa47；平铺、补全、最小周期单元、列周期重复、最小周期扩展 ← d8c310e9

**依赖链**：两个堆叠掩码逐格比较产生压缩结果 → 压缩结果中涌现出列周期结构（该周期在任一输入掩码中均不可见） → 检测最小列周期并将其平铺至目标宽度。删除压缩步骤则无图案可供周期检测；删除周期检测则压缩结果无法被正确扩展。

将上下两个掩码逐格比较，在双背景位置标红，然后检测压缩结果的最小列周期并横向平铺至与输入同宽。

**输入结构**：约 6x12 的网格（偶数行），被水平中线等分为上下两个 3x12 的子网格。两个子网格共享同一背景色黑(0)。上半区使用蓝(1)作为前景色绘制一个图案，下半区使用绿(3)作为前景色绘制另一个图案。两个图案各自没有明显的短列周期，但它们的"双背景交集"（上下对应位置均为黑(0)的列集合）恰好呈现出一个 2~4 列的最小周期。输出网格高度 = 输入高度的一半（3 行），宽度 = 输入宽度。生成约束：压缩结果中红(2)像素的列分布必须具有精确的最小周期（不存在例外像素）；该最小周期严格整除输出宽度。

**规则**：
1. 将输入网格沿水平中线切分为上半区和下半区，两者行数、列数相同。
2. 逐格比较上半区和下半区：在对应位置 (r, c) 处，若上半区和下半区的像素均为黑(0)背景，则输出网格的 (r, c) 位置标记为红(2)；否则标记为黑(0)。得到一个与半区同尺寸的压缩网格。
3. 在压缩网格中检测最小列周期 P：找到满足"对所有行 r 和所有列 c，压缩网格 (r, c) == 压缩网格 (r, c mod P)"的最小正整数 P。
4. 取压缩网格的前 P 列作为周期单元，将其沿列方向重复平铺，直至填满输出宽度（输出宽度 = 输入宽度）。
5. 输出为该平铺后的网格（高度 = 输入高度/2，宽度 = 输入宽度），仅含黑(0)和红(2)两种颜色。

**关键洞察**：最小列周期不是任何一个输入掩码的属性，而是两个掩码的背景交集的涌现属性——只有先完成逐格压缩，周期结构才会显现。

## 新题 5：按封闭孔洞数排序精灵体的叠加顺序

**组合逻辑**：[计数/counting](创新：计数对象从分隔框架的封闭区域变为精灵体内部的孔洞) + [排序/sort](已有) + [裁剪/crop](已有) + [透明叠加/transparent_overlay](创新：叠加顺序不由面积决定，而由孔洞数决定) ← 条件 [区域数映射长度](创新：用于排序键) + [标记对齐/marker_alignment]

**来源原语**：计数、排序、封闭区域 ← 89565ca0；裁剪、透明叠加、目标对象、源精灵、共享标记、标记对齐、面积排序叠加 ← 83eb0a57

**依赖链**：每个源精灵体内的孔洞数需要先计数 → 孔洞数决定叠加的优先顺序（少孔先贴、多孔后贴，后贴覆盖先贴） → 标记对齐决定叠加位置。删除计数步骤则叠加顺序未知（无法从面积或其他直观属性推断）；删除标记对齐则叠加位置未知。

裁剪最大对象为画布，将各小精灵体按其内部孔洞数从少到多依次叠加到标记对齐位置上，多孔者覆盖少孔者。

**输入结构**：约 18x18 的黑(0)背景网格。网格中有一个最大的灰(5) 4-连通对象作为目标画布（约 10x10 像素，形状为不规则但大致矩形，内部含有若干橙(7)标记像素点）。另有 2~4 个较小的源精灵体散布在画布外部，每个精灵体由一种独特颜色（蓝(1)、红(2)、绿(3)、黄(4)中选取）的像素构成，尺寸约 3x3 到 5x5 像素。每个精灵体内部包含 0~3 个 4-连通黑(0)孔洞（被该精灵体颜色完全围合的黑(0)连通区域）。每个精灵体内部也含有橙(7)标记像素，这些标记像素的相对位置与目标画布中某些橙(7)标记像素的局部排列一致，作为对齐锚点。生成约束：各精灵体的孔洞数互不相同；各精灵体的标记对齐位置至少存在部分重叠区域（使叠加顺序可被观察到）。

**规则**：
1. 识别面积最大的非背景 4-连通对象作为目标画布。输出为该画布包围盒的裁剪。
2. 对其余每个源精灵体，计算其内部的 4-连通黑(0)封闭孔洞数（被该精灵体颜色的像素完全围合、不与网格边界连通的黑(0)区域数）。
3. 将所有源精灵体按孔洞数从小到大排序。孔洞数相同时（生成约束保证不会发生），按精灵体包围盒左上角的行优先、列其次排序。
4. 按排序顺序依次将精灵体叠加到目标画布上：对齐方式为将精灵体平移使其内部的橙(7)标记像素与目标画布中对应位置的橙(7)标记像素完全重合。
5. 叠加时，精灵体的非黑(0)像素覆盖画布上的已有像素；精灵体中黑(0)像素（包括孔洞）视为透明，不覆盖画布。
6. 后叠加的精灵体覆盖先叠加的，因此孔洞数最多的精灵体在最顶层。

**关键洞察**：叠加顺序不由精灵体面积决定（与参考题 83eb0a57 不同），而由精灵体内部孔洞数决定——这一属性需要对每个精灵体做封闭区域计数才能获得，且孔洞数与面积之间没有固定的单调关系。

**规则**：
1. 识别所有方向精灵体：含有灰(5) 8-连通像素群且内部恰嵌入一个非灰(5)非黑(0)标记像素的结构。识别所有方形图案块：由某种非背景非灰颜色的 1 像素宽正方形边框围合的区域。

4. 朝向映射为顺时针旋转角度：朝上 = 0 度、朝右 = 90 度、朝下 = 180 度、朝左 = 270 度。
5. 对每个配对的方形图案块（包含边框），以其几何中心为旋转中心做对应角度的顺时针旋转。
6. 输出：将所有旋转后的方形图案块按其标记颜色对应的精灵体标记像素在输入中的位置（从左到右扫描列坐标，列坐标相同时从上到下扫描行坐标），从左到右水平拼合成一行，块间无间隔。输出高度 = 图案块边长，宽度 = 图案块边长 x 配对数。

## 新题 8：双向路由在交叉点按路径长度决定优先色

**组合逻辑**：[连线/line_drawing](已有) + [填充/fill](创新：交叉点颜色不由绘制顺序决定，而由路径长度比较决定) ← 关系 [行列对齐/row_col_align](已有) + [经由中间点路由/routed_via_waypoint](创新：中间点从显式标记变为路径交叉位置) + 条件 [同行列端点间填充/fill_between_aligned_endpoints](已有)

**来源原语**：连线、标记像素、正交路径、经由中间点路由 ← 0e671a1a；连线、填充、行列对齐、同行列端点间填充 ← 253bf280

**依赖链**：每对同色标记像素之间画水平优先正交路径 → 多条路径在某些格子交叉 → 交叉格子的颜色由经过该格的路径中曼哈顿长度最短者的颜色决定。删除连线步骤则无路径可交叉；删除交叉优先级规则则交叉点颜色不确定。

为每对同色标记画水平优先正交路径，路径交叉处取经过该处的最短路径的颜色。

**输入结构**：约 12x12 的黑(0)背景网格。网格中有 3~4 种颜色的标记像素对，每种颜色恰好有 2 个像素（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。各标记像素位于不同的行和列上。灰(5)在输入中不出现。生成约束：至少两条路径在某个格子上交叉（即某个格子同时位于两条不同颜色路径的行经范围内）；不存在三条或更多路径在同一格子交叉的情况；各路径的曼哈顿长度（两端点间的行差绝对值加列差绝对值）互不相同。

**规则**：
1. 对每种颜色，找到其恰好 2 个标记像素 A 和 B。计算该路径的曼哈顿长度 L = |A.row - B.row| + |A.col - B.col|。
2. 对每对标记像素，从 A 向 B 画水平优先正交路径：先从 A 水平移动到 B 所在列（逐列移动，方向取决于 B 在 A 的左侧还是右侧），再从该列垂直移动到 B 所在行。路径沿途经过的所有格子（包括 A 和 B 自身）标记为该颜色。A 定义为两个标记中行号较小者；行号相同时列号较小者为 A。
3. 所有路径画完后，检查每个被标记的格子：若该格子仅被一条路径经过，保持该路径的颜色。若被两条路径经过（交叉），取这两条路径中曼哈顿长度 L 较小的那条路径的颜色。
4. 不在任何路径上的格子保持黑(0)背景。
5. 输出与输入同尺寸。

**关键洞察**：交叉点的颜色不由绘制顺序决定，而由经过该交叉点的路径中端点距离最短者"胜出"——这条规则无法从单个示例中确定（只能看到交叉点取了某种颜色），必须对比多个示例中不同长度路径交叉时哪种颜色保留才能归纳出"短路径优先"的规律。

**依赖链**：每个面板是两个列周期图案的叠合，冲突色标记重叠位置 → 将冲突色像素同时归入两色掩码后才能检测各自的列周期和逐帧偏移 → 用检测到的周期和偏移外推缺失色在下一帧的列位置 → 将外推结果叠加到模板帧上。删除冲突色分离则周期检测出错；删除周期检测则无法外推；删除叠加则输出不完整。

**输入结构**：约 5x24 的网格（5 行高），由灰(5)竖线等距分割为 4 个 5x5 的面板（面板间各有 1 列灰(5)分隔线，总宽 = 4x5 + 3x1 = 23 列；或根据实际调整使比例协调）。黑(0)为背景。前 3 个面板各自包含两种前景色的像素：蓝(1)和绿(3)。蓝(1)像素在每个面板中占据周期性列位置（如列周期 P_b = 2，每隔一列出现蓝像素列），且蓝像素占据的列集合在连续面板间逐帧向右偏移 1 列（即面板 k 中蓝像素出现在列 c 当且仅当 (c - k) mod P_b == 0）。绿(3)像素有另一个列周期 P_g（与 P_b 不同），也以固定步长逐帧偏移。两色像素在同一格子重叠时显示为红(2)（冲突色）。第 4 个面板（模板帧）只包含蓝(1)像素的下一帧位置（即帧编号 k=3 时蓝像素按规律外推的结果），绿(3)像素全部缺失（留为黑(0)），冲突位置也暂未标记。生成约束：两种颜色的列周期不同且均 >= 2；红(2)不用于除冲突标记外的其他用途；至少存在一个面板中蓝绿重叠位置出现红(2)。

**规则**：
1. 识别灰(5)分隔线，将输入分割为 4 个等尺寸面板，编号 k = 0, 1, 2, 3。
2. 在面板 0~2 中，蓝(1)和绿(3)各自占据若干列位置。红(2)像素是两色重叠的标志：对于红(2)位置，将该位置同时计入蓝(1)掩码和绿(3)掩码。
3. 对蓝(1)：观察其在面板 0~2 中的列位置集合，确定列周期 P_b 和逐帧列偏移量 d_b（面板 k 中蓝像素出现在列 c 满足 (c - k * d_b) mod P_b == 0 的最小 P_b 和 d_b）。对绿(3)：同样确定 P_g 和 d_g。
4. 面板 3 已包含蓝(1)的外推结果。用绿(3)的周期 P_g 和偏移量 d_g 计算绿(3)在 k=3 时应出现的列位置集合。
5. 在面板 3 的每一行中，在绿(3)预测列位置处：若当前为黑(0)则涂绿(3)；若当前为蓝(1)（即蓝绿重叠）则涂红(2)。
6. 输出为填充完整后的面板 3（单个面板尺寸，不含分隔线）。

**关键洞察**：红(2)冲突色是分离两个叠合图案的关键线索——它标识了两色重叠位置。如果忽视红(2)的双重归属而仅将其视为第三种独立颜色，则蓝和绿各自的列周期检测都会出错，导致外推失败。

**依赖链**：左半区分析（重建框架 → 计数封闭区域数 N） → 行键 N；右半区分析（过滤噪声 → 识别主色 C） → 列键 C；(N, C) 二维查表 → 输出模板。两个分析各自独立但缺一不可——只有 N 或只有 C 都无法唯一确定输出。这是多源汇聚结构，非线性流水线。

从输入的两个独立区域分别提取几何信号（封闭区域计数）和颜色信号（主色识别），以二者组合为键查编码表，输出对应的小型模板。

**输入结构**：约 7x15 的网格，由一列灰(5)竖线在中间将网格分为左半区（7x7）和右半区（7x7）。左半区：黑(0)背景上用橙(7)线段画一个矩形分隔框架，框架内有橙(7)内墙将其分为若干封闭区域。部分橙(7)线段被品红(6)噪声像素遮挡或打断。封闭区域数为 1、2 或 3 之一。右半区：黑(0)背景上散布若干前景像素，其中一种颜色出现次数最多（主色），其余颜色出现次数均少于主色（干扰色）。主色为蓝(1)、红(2)或绿(3)之一。生成约束：不同示例中 (N, C) 组合不同；至少需要 3 个示例才能排除错误的映射假设。

**规则**：
1. 左半区处理：忽略所有品红(6)像素。对橙(7)线段做墙壁重建——若某行/列在左半区范围内的橙(7)像素占多数（超过一半），则将该行/列在左半区内的缺失位置补全为橙(7)。重建后，计数被橙(7)墙壁完全围合的 4-连通黑(0)区域数，记为 N。
2. 右半区处理：统计每种非黑(0)颜色的像素数量。出现次数最多的颜色为主色 C。其余颜色为干扰项，忽略。
3. 以 (N, C) 为键查以下编码表，输出一个 3x3 的黑(0)背景网格，指定位置涂青(8)：
   - (1, 蓝(1))：左列 — (0,0)(1,0)(2,0)
   - (1, 红(2))：中行 — (1,0)(1,1)(1,2)
   - (1, 绿(3))：右列 — (0,2)(1,2)(2,2)
   - (2, 蓝(1))：顶行 — (0,0)(0,1)(0,2)
   - (2, 红(2))：主对角 — (0,0)(1,1)(2,2)
   - (2, 绿(3))：底行 — (2,0)(2,1)(2,2)
   - (3, 蓝(1))：副对角 — (0,2)(1,1)(2,0)
   - (3, 红(2))：四角 — (0,0)(0,2)(2,0)(2,2)
   - (3, 绿(3))：十字 — (0,1)(1,0)(1,1)(1,2)(2,1)
4. 输出为该 3x3 网格。

**关键洞察**：编码表是二维的——单独知道封闭区域数 N 只能缩小到 3 个候选模板，单独知道主色 C 也只能缩小到 3 个。求解者必须同时从输入的两个空间独立区域中提取两个不同类型的信号（几何计数 vs 颜色统计），才能唯一确定输出。这是多源汇聚结构，不同于任何参考题的单键映射。
