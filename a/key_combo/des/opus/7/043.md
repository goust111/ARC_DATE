## 新题 1：射线交叉点的同心环展开

**组合逻辑**：[ray_extend + seed_color_determines_extend](已有，从 178fcbfb) → [交叉点涌现为展开中心](创新——源题中射线独立，此处两组射线的笛卡尔积产生新锚点) → [concentric_fill + palette_color_by_distance](已有，从 9356391f，但作用对象从单一种子改为涌现交叉点)

**来源原语**：ray_extend / seed_pixel / seed_color_determines_extend（178fcbfb），concentric_fill / palette_row / chebyshev_index / palette_color_by_distance（9356391f），stamp_ring_at_cross 概念（ac3e2b04）

**依赖链**：种子颜色决定射线方向（红=纵、绿=横）；两组射线的每对交叉点成为同心环展开中心；色板行决定各环颜色；射线与环的重叠需按优先级解决——删掉射线无法定位中心，删掉色板无法确定环色，删掉同心展开则射线交叉毫无后续作用。

从散布的红/绿种子出发，红种子发射纵向射线、绿种子发射横向射线，在每对交叉点处以色板行颜色画出同心方环。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 第 0 行为色板条：从第 0 列起连续 3-4 个非背景色像素（例如红(2)、蓝(1)、黄(4)、绿(3)），其余第 0 行单元为黑(0)。
- 第 2 行及以下：散布若干孤立种子像素。红(2) 种子若干，绿(3) 种子若干。任意两个红种子不在同一列，任意两个绿种子不在同一行。
- 生成约束：至少 2 个红种子和 2 个绿种子，保证至少 4 个交叉点。所有红-绿配对的交叉点 (green_row, red_col) 均落在网格内。

**规则**：
1. 红(2) 种子发射纵向射线：将该种子所在列从第 1 行到末行全部填充灰(5)。绿(3) 种子发射横向射线：将该种子所在行全部填充灰(5)。色板行（第 0 行）不被射线覆盖。
2. 种子像素保持原色（红或绿），不被灰覆盖。
3. 对每对（红种子在列 c，绿种子在行 r），单元 (r, c) 为交叉中心。以该中心做同心方环展开：与中心切比雪夫距离为 d 的单元涂 palette[d]（0-索引）。若 d >= 色板长度，该单元不涂。展开裁剪到网格边界内。
4. 同心环像素覆盖灰色射线像素；但不覆盖种子像素。
5. 若两个交叉中心的同心环区域重叠，以欧氏距离较近的中心优先；距离相同则行号较小者优先，再同则列号较小者优先。

**关键洞察**：展开中心从未在输入中直接标记——它们是红种子列集与绿种子行集的笛卡尔积的涌现结果。中心数量等于两类种子数量之积，而非之和。

## 新题 2：掩码筛选的自相似嵌套

**组合逻辑**：[decode_block_to_mask](已有，从 15113be4) + [self_similar_nesting + foreground_positions_determine_stamp](已有，从 8f2ea7aa) → [掩码逐块过滤嵌套结果](创新——源题中掩码筛选已有格子内容，此处掩码作用于自相似展开后的每个块，产生选择性保留)

**来源原语**：self_similar_nesting / foreground_positions_determine_stamp / scale_up / sprite（8f2ea7aa），mask_matching / decode_block_to_mask / instruction_region / lattice_partition（15113be4）

**依赖链**：指令区域解码为 3x3 二值掩码 M → 母题提取并做自相似展开（9x9 输出）→ 掩码 M 对展开后每个 3x3 块内的像素做逐位过滤，仅保留 M 中标记的位置——删掉掩码解码则不知保留哪些位置，删掉自相似展开则没有可过滤的结构。

一个小母题做自相似展开得到大网格后，由另一区域编码的 3x3 掩码逐块过滤展开结果，只保留掩码标记位置的像素。

**输入结构**：
- 网格约 9x12，背景黑(0)。
- 左半部分（约 9x6）：一个指令区域，由灰(5) 网格线分割为 3x3 阵列的 2x2 子单元。部分子单元整体填充橙(7)（编码掩码"1"），其余为黑(0)（编码掩码"0"）。
- 右上角（约 3x3 区域）：一个单色紧凑母题，用红(2) 在黑背景上绘制，边界框恰好 3x3，前景像素 3-7 个，形状不规则（非矩形，4-连通）。
- 生成约束：母题边界框严格为 3x3 以匹配掩码维度。掩码中至少 2 个位置为"1"、至少 2 个为"0"，保证过滤有意义。

**规则**：
1. 解码指令区域：每个 2x2 子单元若整体为橙(7) 则掩码对应位置为 1，否则为 0。得到 3x3 二值掩码 M。
2. 提取右上角 3x3 母题。
3. 自相似嵌套展开：创建 9x9 输出网格。对母题中每个前景像素 (r, c)，将完整 3x3 母题粘贴到输出的块位置 (r, c)（块行 [3r, 3r+2] x 块列 [3c, 3c+2]）。其余块为全黑。
4. 掩码过滤：对每个已粘贴的 3x3 块，逐像素检查 M[local_r][local_c]。M 值为 0 的位置强制设为黑(0)，M 值为 1 的位置保留块中的原色。
5. 输出仅包含 9x9 结果网格，不包含指令区域和灰网格线。

**关键洞察**：掩码不是筛选原始母题——而是筛选自相似展开后每一份拷贝中的相同位置。一个母题像素即使通过了展开步骤被复制到输出，仍可能被掩码擦除。求解者必须先心算展开、再叠加掩码过滤。

## 新题 3：连通分量面积的螺旋仪表阵列

**组合逻辑**：[connected_component + area_comparison](已有，从 67385a82) → [sorting + ascending_by_count](已有，从 81c0276b / dc2aa30b) → [spiral_fill + gauge_output](已有，从 b0c4d837，但从单一计数扩展为多分量逐个编码) + [array_layout](已有，从 dc2aa30b，但排布的是仪表而非瓦片)

**来源原语**：connected_component / area_comparison（67385a82），sorting / ascending_by_count / frequency_statistic（81c0276b, dc2aa30b），spiral_fill / gauge_output / empty_rows_map_to_fill_amount（b0c4d837），array_layout（dc2aa30b）

**依赖链**：识别各连通分量并计算面积 → 按面积升序排序 → 每个分量生成一个 3x3 螺旋仪表、填充量等于该分量面积 → 仪表按排序顺序从左到右排列——删掉面积计算则不知填充量，删掉排序则不知排列顺序，删掉螺旋填充则无法编码。

将输入中各前景连通分量的面积提取出来，按大小排序后，逐个编码为 3x3 螺旋仪表从左到右排列输出。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 前景像素为单一颜色（如蓝(1)），形成 3-6 个不同的 4-连通对象。各对象面积在 1-8 像素之间，形状各异（有孤立点、线段、不规则团块等），任意两对象之间至少间隔 1 个背景像素。
- 生成约束：所有对象面积互不相同。

**规则**：
1. 找出所有 4-连通前景对象，计算每个对象的面积（像素数）。
2. 按面积升序排序。
3. 输出为一行 3x3 块，块之间以 1 列黑(0) 间隔。块数等于对象数。
4. 从左到右第 k 个块对应排序后第 k 个对象（最小面积在最左）。每个 3x3 块以顺时针螺旋从左上角开始填充，填充 A 个单元为蓝(1)（A = 该对象面积），其余单元为黑(0)。螺旋顺序：左上 → 上中 → 右上 → 右中 → 右下 → 下中 → 左下 → 左中 → 中心（共 9 个位置）。
5. 若某对象面积超过 9，则该 3x3 块全部填满蓝(1)。

**关键洞察**：原始对象的空间布局和具体形状在输出中被完全丢弃——只有面积信息被保留。求解者必须发现三个层次的规则：像素计数、排序准则、以及螺旋填充的路径顺序。

## 新题 4：分量条件分支的棋盘上采样

**组合逻辑**：[connected_component + area_comparison + multi_recolor_single](已有，从 67385a82，但从重涂色改为控制上采样模式选择) → [pixel_upscaling + pattern_substitution](已有，从 2072aba6，但替换模式不再全局统一，而是由分量面积条件分支决定)

**来源原语**：connected_component / area_comparison / multi_recolor_single / isolated_pixel（67385a82），pixel_upscaling / pattern_substitution / checkerboard_pattern / color_conditional_branch（2072aba6）

**依赖链**：连通分量分析将每个前景像素分类为"孤立"或"成组"→ 像素上采样时根据分类施加不同替换模式（孤立→纯色块，成组→棋盘块）——删掉分量分析则不知哪些像素孤立，删掉条件分支上采样则分类无用武之地。

网格做 2 倍上采样，但孤立前景像素扩展为纯色块，而属于多像素连通分量的前景像素扩展为棋盘格块，通过视觉差异标记出标记点与结构体。

**输入结构**：
- 网格约 8x8，背景黑(0)。
- 前景像素为绿(3)，形成以下混合：2-3 个孤立单像素（与其他绿像素 4-连通不相邻）和 1-2 个多像素 4-连通对象（每个 3-8 像素，形状不规则且非矩形）。
- 生成约束：任意两个对象（含孤立像素）之间至少间隔 2 个背景像素，保证 4-连通分量分析无歧义。至少 1 个孤立像素和至少 1 个多像素对象。

**规则**：
1. 识别所有 4-连通绿(3) 对象。面积 = 1 的为"孤立"，面积 > 1 的为"成组"。
2. 创建 2H x 2W 的输出网格。
3. 每个黑(0) 输入像素 (r, c) 映射为输出的 2x2 全黑块，位于 [2r, 2r+1] x [2c, 2c+1]。
4. 每个"孤立"绿像素映射为 2x2 纯绿(3) 块。
5. 每个"成组"绿像素映射为 2x2 棋盘块：[[蓝(1), 红(2)], [红(2), 蓝(1)]]。

**关键洞察**：替换模式并非全局统一——它依赖于每个像素所属连通分量的面积属性。两个相邻的绿像素各自变成棋盘块，但一个孤立的绿像素变成纯色块，使得分量边界在上采样后变得可视化。求解者必须先做连通分量分析，再逐像素决定替换模式。

## 新题 5：L 路径拐点处的旋转精灵印章

**组合逻辑**：[draw_line + L_path_connection + manhattan_path](已有，从 a2fd1cf0) → [拐点位置涌现为印章锚点](创新——源题中 L 路径仅为连线，此处拐点成为精灵的放置位置) → [stamp + anchor_positions_copy](已有，从 1b59e163) + [rotate_translate_to_fit](已有，从 1acc24af，但旋转角度由路径转向方向决定而非由凹槽形状匹配决定)

**来源原语**：draw_line / L_path_connection / manhattan_path / start_marker / end_marker（a2fd1cf0），stamp / sprite / anchor_marker / same_color_match（1b59e163），rotate_translate_to_fit（1acc24af）

**依赖链**：同色标记配对确定 L 路径端点 → L 路径几何确定拐点位置和转向方向 → 转向方向决定精灵旋转角度 → 精灵印章放置在拐点——删掉路径绘制则找不到拐点，删掉旋转规则则精灵朝向不确定，删掉印章则拐点信息无输出效果。

同色标记对之间画水平优先的 L 路径，在每条路径的拐点处印上参考精灵，精灵的旋转方向取决于路径在拐点处的转弯方向。

**输入结构**：
- 网格约 16x16，背景黑(0)。
- 左上角（边界框起于 (0,0)）有一个灰(5) 参考精灵，3-5 像素组成的不对称 4-连通小图形，边界框不超过 3x3。
- 2-3 对同色标记像素，每对使用唯一颜色（如红(2)、蓝(1)、绿(3)）。每对中两个标记在不同行且不同列。同对中行号较小者为起点，行号较大者为终点（行号相同则列号较小者为起点）。
- 生成约束：各对 L 路径的拐点位置（起点行, 终点列）处有足够空间放置精灵（精灵边界框 + 1 像素边距）。拐点之间、拐点与标记之间互不重叠。所有标记和拐点远离参考精灵区域。

**规则**：
1. 对每对同色标记，画 L 路径：从起点沿行方向水平延伸到终点所在列，再沿列方向竖直延伸到终点所在行。路径涂灰(5)，仅覆盖背景像素，不覆盖标记像素。
2. 拐点 = (起点行, 终点列)。
3. 根据路径在拐点处的转向确定旋转角度：
   - 向右再向下：0 度（不旋转）。
   - 向右再向上：顺时针 90 度。
   - 向左再向下：逆时针 90 度。
   - 向左再向上：180 度。
4. 将参考精灵按确定的角度旋转后，以拐点为精灵边界框中心印章到输出。印章覆盖背景和路径像素，但不覆盖标记像素。
5. 输出中左上角的原始参考精灵被擦除（替换为背景）。

**关键洞察**：拐点不只是 L 路径的几何副产品——它成为精灵的锚定位置，且路径的转弯方向锁定了精灵的朝向。求解者必须追踪每条路径以定位拐点，并对比不同转向方向的示例推断旋转规则。

## 新题 6：U 框液位驱动的种子射线与螺旋生长

**组合逻辑**：[u_shaped_frame + empty_rows_map_to_fill_amount](已有，从 b0c4d837，但从仪表输出改为驱动远程操作的参数源) → [ray_extend + seed_color_determines_extend](已有，从 178fcbfb，但射线长度不再是全跨而是由液位值 N 决定) → [spiral_grow + turn_priority_rule](已有，从 da515329，但起点从十字臂端改为射线端点，步数由 N 控制)

**来源原语**：spiral_fill / u_shaped_frame / gauge_output / empty_rows_map_to_fill_amount / interior_containment（b0c4d837），ray_extend / seed_pixel / seed_color_determines_extend / stripe（178fcbfb），spiral_grow / turn_priority_rule / spacing_constraint / arm_tip（da515329）

**依赖链**：U 框内液面以上空行数 = N → N 决定种子射线长度 → 射线端点成为螺旋起点 → N 同时决定螺旋步数——U 框是"控制面板"，删掉它则射线和螺旋长度无法确定；种子颜色决定射线方向，删掉颜色规则则射线朝向不确定；螺旋从射线端点生长，删掉射线则螺旋无起点。

U 框内的空余行数被读取为参数 N，N 同时决定画布其他区域中种子射线的延伸长度和射线端点处螺旋的生长步数。

**输入结构**：
- 网格约 18x18，背景黑(0)。
- 左上象限（约 8x8 区域）：一个开口朝上的 U 形框架，框架色蓝(1)，内部底部有红(2) 液体填充（底对齐矩形）。框架内部液面以上有 1-5 行空行。
- 右下区域（远离 U 框）：2-3 个孤立种子像素。红(2) 种子发射向下的纵向射线，绿(3) 种子发射向右的横向射线。
- 生成约束：种子位置保证长度最多为 6 的射线和最多 6 步的螺旋均在网格内且不进入 U 框区域。种子之间至少间隔 4 像素以防螺旋碰撞。

**规则**：
1. 计算 N = U 框内部液面（最高红(2) 行）以上的空行数。
2. 红(2) 种子发射向下纵向射线，长度 N 格（从种子下方第 1 格起向下 N 格）。射线涂橙(7)。
3. 绿(3) 种子发射向右横向射线，长度 N 格（从种子右方第 1 格起向右 N 格）。射线涂橙(7)。
4. 种子像素保持原色（红或绿），不被覆盖。
5. 从每条射线的端点（第 N 格）开始生长顺时针螺旋，涂黄(4)：第一步从射线前进方向顺时针转 90 度出发，后续每步遵循"优先右转 > 直行 > 左转"的规则。每步涂 1 格，共生长 N 步。
6. 螺旋步若将落在已有非背景像素上或超出网格边界，则该步跳过（步数消耗，但不涂色，螺旋前进方向不因跳过而改变）。

**关键洞察**：U 框是"控制面板"——其液位编码了一个参数，驱动画布上完全不相关的操作。没有 U 框的液位读数，种子射线和螺旋的长度均无法确定。求解者必须识别出液位高度与射线/螺旋长度之间的跨区域因果关系。

## 新题 7：面积门控的锚点环形印章与干扰项过滤

**组合逻辑**：[connected_component + area_comparison](已有，从 67385a82，但从重涂色判据改为印章资格的门控条件) → [stamp + anchor_positions_copy + same_color_match](已有，从 1b59e163) + [marker_ring + center_expansion](已有，从 ac3e2b04 / b60334d2，但环形图案是固定模板而非源对象形状的复制) + [ignore_distractors](已有，从 1b59e163，但干扰项的判定从"无源精灵的颜色"改为"面积未达标的分量的锚点颜色")

**来源原语**：connected_component / area_comparison / multi_recolor_single（67385a82），stamp / sprite / anchor_marker / destination_marker / same_color_match / anchor_positions_copy / ignore_distractors（1b59e163），marker_ring / stamp_ring_at_cross（ac3e2b04），center_expansion（b60334d2）

**依赖链**：连通分量面积分析 → 面积达标的分量为"合格源"，其锚点颜色激活对应目标标记 → 在目标标记处印 3x3 环形图案 → 面积未达标的分量虽然也有锚点和匹配标记，但被视为干扰项，连同不匹配的孤立标记一并擦除——删掉面积门控则所有分量都触发印章（错误），删掉颜色匹配则不知哪个标记接收哪个环，删掉干扰项过滤则残留多余元素。

只有面积超过隐含阈值的前景分量才有权将其锚点颜色的环形图案印到匹配的独立标记处；面积不足的分量虽然结构相同，却被视为干扰项并擦除。

**输入结构**：
- 网格约 16x16，背景黑(0)。
- 3-5 个不同的灰(5) 4-连通前景分量，面积从 2 到 12 像素不等，形状各异。每个分量内部恰好包含 1 个非灰像素（锚点），锚点颜色各不相同，取自 {红(2), 蓝(1), 绿(3), 黄(4)}。
- 散布的孤立标记像素（不与任何灰分量 4-连通相邻），部分颜色与锚点颜色匹配，另有 1-2 个颜色不匹配任何锚点的"干扰标记"。
- 生成约束：面积阈值 T 定义为所有分量面积的中位数（求解者需从示例推断）。面积 >= T 的为"合格"，至少 1 个分量合格、至少 1 个不合格。匹配合格锚点颜色的孤立标记周围有 3x3 空间用于环形印章（标记八邻域全为背景）。

**规则**：
1. 找出所有 4-连通灰(5) 分量，计算各面积。
2. 确定面积阈值 T（从示例推断——观察哪些分量触发了印章、哪些没有）。面积 >= T 的分量为"合格"。
3. 对每个合格分量，记录其锚点颜色 C。
4. 对每个颜色为 C 的孤立标记像素：以该标记为中心印 3x3 环——8 个周围像素涂灰(5)，中心保持颜色 C。
5. 所有原始灰分量（无论合格与否）擦除为背景。
6. 所有干扰标记（颜色不匹配任何合格锚点的孤立标记）擦除为背景。
7. 匹配非合格锚点颜色的孤立标记也擦除为背景。

**关键洞察**：面积阈值是隐藏参数——求解者必须对比多个示例才能发现哪些分量大小会激活印章。未达标分量在结构上与合格分量完全相同（都有锚点、都有匹配标记），但它们是"沉默"的干扰项。印章形状是固定的 3x3 环，与分量本身的形状无关——分量的形状只贡献面积信息。
