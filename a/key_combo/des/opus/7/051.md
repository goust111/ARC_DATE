## 新题 1：碎片合并后沿引导条压缩为计数线段

**组合逻辑**：[合并对齐碎片](已有) → [像素数决定长度](已有) → [压缩/compress](创新：压缩对象从单一内部物体变为合并后的碎片组，且同时处理多组) + [引导条决定朝向](已有)

**来源原语**：合并对齐碎片/merge_aligned_fragments (8fbca751), 像素数决定长度/pixel_count_length (c61be7dc), 压缩/compress (c61be7dc), 引导条/guide_bar (c61be7dc), 残缺矩形/fragmented_rectangle (8fbca751), 行列跨度重叠/span_overlap (8fbca751), 引导条决定朝向/guide_determines_dir (c61be7dc)

**依赖链**：碎片合并确定了每组的像素总数 → 像素总数成为压缩线段的长度 → 引导条方向决定线段朝向和居中位置 → 每组的质心位置决定线段在垂直轴上的放置。删除合并步骤则像素计数错误；删除引导条则方向未知；删除像素计数则长度不确定。

将多组散落碎片按行列跨度合并后，沿引导条方向各自压缩为一条以组像素数为长度的线段，线段沿垂直方向排列于各组质心位置。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 灰(5)引导结构占据边界区域：两条完整的平行条（均为水平或均为垂直，跨越整个网格宽或高）加上一条垂直于平行条的中心条（同样跨越整个网格）。三条灰条将内部区域分隔为若干区间。
- 在两条平行灰条之间的内部区域中，散布着若干青(8)前景碎片。每个碎片是 4-连通的单色区域，像素数在 2~8 之间，形状不规则。
- 某些碎片的边界框在行跨度或列跨度上有重叠（表示它们属于同一个不完整矩形的残片），其余碎片彼此在行列跨度上都不重叠。
- 生成约束：每个合并组包含 2~4 个碎片；合并后每组的像素总数不超过引导平行条之间的内部跨度长度；不同组的质心坐标（沿垂直于压缩轴的方向取整后）互不相同。

**规则**：
1. 识别所有 4-连通的青(8)碎片。
2. 传递合并：若两个碎片的边界框在行跨度或列跨度上有重叠，则归入同一组；传递闭包直到无法再合并。
3. 对每个合并组，统计组内青像素总数 P。
4. 读取引导条方向：若两条平行灰条为垂直方向，则压缩轴为垂直；若为水平方向，则压缩轴为水平。
5. 对每个合并组，计算其所有像素在垂直于压缩轴方向上的坐标平均值，四舍五入到最近整数，记为该组的放置行/列 C。
6. 在放置行/列 C 上，沿压缩轴方向绘制一条红(2)线段，长度为 P 像素，以灰色垂直中心条的位置为线段中心（若 P 为偶数，中心偏向中心条左/上侧一格）。
7. 擦除所有原始青(8)像素（设为黑(0)），保留灰(5)引导结构和新绘制的红(2)线段。

**关键洞察**：碎片的"碎"并不意味着每个碎片独立处理——行列跨度重叠暴露了碎片之间的隐含归属关系，必须先合并才能得到正确的像素计数；而引导条只提供方向和居中锚点，不提供任何关于碎片分组的信息。

## 新题 2：旋转补全像素的极值框定矩形边框

**组合逻辑**：[旋转/rotate](已有) + [缺失部分标记新色/missing_marked_new_color](已有) → [极值内缩定边框/frame_inset_from_extrema](创新：极值来源从预设标记变为旋转补全生成的像素) → [描边/draw_frame](已有) + [擦除/erase](已有)

**来源原语**：旋转/rotate (1b60fb0c), 缺失部分标记新色/missing_marked_new_color (1b60fb0c), 描边/draw_frame (928ad970), 极值内缩定边框/frame_inset_from_extrema (928ad970), 擦除/erase (fe45cba4)

**依赖链**：旋转补全产生红色标记像素 → 红色像素的行列极值定义了矩形边框的范围 → 在极值位置绘制绿色边框 → 擦除红色像素只留边框。删除旋转步骤则无红色像素；删除极值计算则边框范围未知；删除擦除则输出多余。

找到蓝色对象缺失的旋转对称部分，用该部分的空间极值绘制一个矩形边框，再擦除中间标记，输出边框作为缺失区域的几何摘要。

**输入结构**：
- 黑(0)背景，约 14x14 网格。
- 蓝(1)像素构成一个接近 4 重旋转对称的单连通对象，占据约 15~30 像素。该对象有一个明确的旋转中心（中心位于某个像素或四像素交汇点），但有一个象限方向的部分像素缺失（约 3~8 像素），使其旋转对称不完整。
- 除蓝色对象外，网格中无其他前景元素。
- 生成约束：缺失部分的像素位置在 90 度顺时针旋转蓝色像素后恰好落在黑色背景上；缺失像素的行跨度和列跨度均不小于 2（确保边框有面积）；缺失像素的极值矩形不与蓝色对象像素重叠。

**规则**：
1. 检测蓝(1)对象的旋转对称中心。
2. 将每个蓝像素绕中心顺时针旋转 90 度。若旋转目标位置为黑(0)，则在该位置涂红(2)。若目标位置已有蓝色像素则不做任何操作。
3. 收集所有红(2)像素的坐标，计算其最小行 r_min、最大行 r_max、最小列 c_min、最大列 c_max。
4. 以 (r_min, c_min) 为左上角、(r_max, c_max) 为右下角，绘制一个一像素宽的绿(3)矩形边框（边框像素恰好落在极值行列上）。
5. 擦除所有红(2)像素（设为黑(0)）。保留蓝(1)对象和绿(3)边框。若绿色边框与蓝色像素位置重叠，绿色覆盖蓝色。

**关键洞察**：边框的形状和位置完全由旋转补全生成的中间像素决定，而非由预先放置的标记点决定。求解者必须先完成旋转补全的心理模拟，才能推断边框的几何范围——边框是对"缺了什么"的空间度量。

## 新题 3：括号提取段内对称修复后按修复量排序堆叠

**组合逻辑**：[裁剪/crop + 括号界定提取范围](已有) → [对称补全/symmetry_completion](创新：对称域由提取段宽度定义而非全网格) → [排序/sorting](创新：排序键是修复像素数而非空间位置) → [堆叠/stacking](已有)

**来源原语**：裁剪/crop (505fff84), 括号界定提取范围/bracket_delimited_extraction (505fff84), 控制像素对/control_pixel_pair (505fff84), 对称补全/symmetry_completion (903d1b4a), 占位标记/placeholder_marker (903d1b4a), 双轴反射轨道/two_axis_orbit (903d1b4a→创新为单轴), 堆叠/stacking (505fff84), 排序/sorting (817e6c09)

**依赖链**：括号提取确定每段的边界和宽度 → 段宽度定义了对称轴位置（段水平中线）→ 按左右对称修复绿色占位符 → 修复的像素数成为排序键 → 按修复量升序堆叠输出行。四步紧耦合：提取定义对称域、对称修复产生计数信息、计数决定堆叠顺序。

从括号标记行中提取段，在每段内用左右对称修复绿色占位像素，按每段修复的像素数从少到多堆叠为输出。

**输入结构**：
- 黑(0)与红(2)交替构成的图案场，约 15x25 网格。
- 在若干行上（不一定连续，约 4~7 行），每行恰有一个蓝(1)像素和一个青(8)像素，蓝在左、青在右，构成控制像素对。所有控制像素对之间的内部宽度（蓝与青之间的格数）相同，记为 W。
- 每个被标记行中，蓝与青之间的 W 个像素构成一个"段"。段内大部分像素为红(2)和黑(0)的某种图案，但有若干像素被替换为绿(3)占位符（每段 1~4 个绿像素）。
- 每段在忽略绿像素后具有左右反射对称性（以段水平中线为对称轴）：对于每个绿像素，其关于段中线的镜像位置是一个非绿像素（红或黑）。
- 各段的绿像素数量互不相同。
- 生成约束：W 为奇数（对称轴恰好在中央列上）；每段内绿像素不出现在对称轴上；未被标记的行不含蓝或青像素。

**规则**：
1. 识别所有带有蓝(1)/青(8)控制对的行。
2. 对每个标记行，提取蓝和青之间（不含蓝青自身）的 W 个像素作为一段。
3. 对每段，以段的水平中线（第 (W-1)/2 列，0 索引）为对称轴，检查每个绿(3)像素的镜像位置，将绿像素替换为其镜像位置的颜色（红(2)或黑(0)）。记录该段修复的绿像素数 R。
4. 将所有修复后的段按 R 值升序排列。若 R 值相同（生成约束保证不会），按原始行号从小到大排列。
5. 将排好序的段从上到下堆叠为输出网格（输出宽度为 W，高度为标记行数）。

**关键洞察**：堆叠顺序不是输入中的空间顺序（行号），而是由对称修复的工作量决定。求解者必须先完成修复才能知道排列顺序，不能跳过修复步骤直接堆叠；同时修复的前提是正确提取段边界以定位对称轴。

## 新题 4：射线滑动距离排序后逐一印章模板

**组合逻辑**：[滑动/sliding + 射线对齐 + 碰撞停止](已有) → [排序/sorting](创新：排序键是滑动距离) → [印章覆盖/stamp](创新：模板来自网格中的独立精灵图，颜色取自标记色)

**来源原语**：滑动/sliding (a48eeaf7), 射线对齐/ray_alignment (a48eeaf7), 碰撞停止/collision_stop (a48eeaf7), 填充块/filled_block (a48eeaf7), 排序/sorting (817e6c09/68bc2e87), 印章覆盖/stamp (22233c11), 精灵图/sprite (2546ccf6/8d5021e8), 擦除/erase (ae3edfdc)

**依赖链**：标记像素沿射线向锚块滑动 → 滑动距离被记录 → 距离决定印章顺序（远者先印、近者后印覆盖）→ 在终点位置用标记颜色印章模板精灵 → 后印覆盖先印。删除滑动则终点未知且距离缺失；删除排序则覆盖优先级错误；删除模板则无印章内容。

多个彩色标记沿射线向中心锚块滑动后，按滑动距离从远到近依次在终点位置印章同一个模板精灵（取各标记自身颜色），后印覆盖先印。

**输入结构**：
- 黑(0)背景，约 16x16 网格。
- 一个青(8)实心 2x2 方块位于网格中偏心位置（非正中央），作为锚块。
- 4~6 个孤立标记像素，每个颜色各异（从红(2)、蓝(1)、绿(3)、黄(4)、橙(7)、栗(9)中选取），每个标记与锚块的 2x2 区域共享同一行、同一列或 45 度对角线。标记与锚块之间有至少 3 格间距。
- 一个灰(5)模板精灵位于网格某角落（不与锚块共享行列或对角线），由 3~5 个 4-连通像素构成不规则形状，其边界框不超过 3x3。
- 生成约束：所有标记滑动到锚块邻接环后，以各自终点为中心放置 3x3 边界框时，边界框互相重叠至少 1 个像素（确保印章顺序影响最终可见像素）；模板精灵的边界框左上角作为锚点。

**规则**：
1. 对每个彩色标记像素，沿其与锚块共享的射线（行、列或 45 度对角线）向锚块方向滑动，停在紧邻锚块 2x2 区域的环形外圈对应格位上。记录每个标记的滑动距离 D（经过的格数）。
2. 将标记按 D 从大到小排列（距离最远的排在最前）。D 相同时按原始位置的阅读序（从上到下、从左到右）排列。
3. 按排好的顺序依次执行印章操作：以当前标记的终点位置为基准点（对应模板精灵边界框的中心），将模板精灵的形状绘制到网格上，颜色使用该标记自身的颜色（替换灰色）。后执行的印章覆盖先执行的。
4. 擦除模板精灵的原始灰(5)像素（设为黑(0)）。
5. 擦除所有标记像素的原始位置（设为黑(0)）。保留锚块和所有印章结果。

**关键洞察**：锚块周围的最终图案是多个同形状不同颜色的模板叠加，可见颜色由滑动距离排序后的覆盖优先级决定——距锚块最近的标记最后印章因而在最顶层。求解者必须同时推断出模板形状、滑动终点和距离排序三个要素。

## 新题 5：分隔层异或叠加生成滑动目标场

**组合逻辑**：[异或叠加/xor_overlay](已有) + [裁剪/crop + 分隔行](已有) → [滑动/sliding](创新：滑动目标由异或结果动态确定) + [行列对齐/row_column_alignment](已有) → [擦除/erase](已有)

**来源原语**：异或叠加/xor_overlay (99b1bc43), 分隔行/separator_row (99b1bc43), 前景掩码/foreground_mask (99b1bc43), 前景不一致处涂色/disagreement_cells_painted (99b1bc43), 滑动/sliding (ae3edfdc), 行列对齐/row_column_alignment (ae3edfdc), 压缩到标记旁/compress_to_adjacent_marker (ae3edfdc), 擦除/erase (ae3edfdc)

**依赖链**：移除分隔行对齐上下掩码 → 异或计算生成绿色目标像素 → 黄色标记各自找到行列对齐的唯一绿色像素 → 标记沿共享轴向绿色像素滑动至其邻接格 → 输出保留绿色和滑动后的黄色。两条源操作共享中间状态：异或结果既是"掩码比较的输出"又是"滑动的输入目标场"。

上下两层掩码经异或得到差异像素场，散落的标记沿行列向最近的差异像素滑动聚拢，形成差异点周围的标记簇。

**输入结构**：
- 黑(0)背景，约 14x22 网格（高度为偶数加一：2H+1 行）。
- 第 H+1 行（0 索引第 H 行）为一条灰(5)全宽分隔行，仅此行含灰色。
- 上半区（行 0 ~ H-1）：蓝(1)像素构成一个前景图案（4-连通，约 8~15 像素），其余为黑(0)。
- 下半区（行 H+1 ~ 2H）：红(2)像素构成另一个前景图案（4-连通，约 8~15 像素），其余为黑(0)。上下半区高度相同、宽度相同。
- 下半区中另有 3~6 个孤立黄(4)标记像素，分散在红色图案之外。
- 生成约束：上下两个掩码的前景对称差（异或）恰好产生 3~6 个像素，且每个黄色标记与恰好一个异或像素共享行或列（不可同时共享行和列）；不同黄色标记对应不同的异或像素；黄色标记与其对应异或像素之间路径上无其他前景像素阻挡。

**规则**：
1. 移除灰(5)分隔行，将上半区和下半区逐格对齐（上半区行 r 对应下半区行 r）。
2. 对齐后对每个位置做异或判断：若恰好一个半区在该位置有前景像素（蓝或红），则标记为绿(3)；若两个半区在该位置都有前景或都无前景，则标记为黑(0)。得到一个 H 行的异或结果网格。
3. 将黄(4)标记像素的位置映射到对齐后网格中（下半区行 r 映射为对齐后行 r）。
4. 对每个黄色标记，找到与其共享行或列的唯一绿色像素。沿该共享轴方向将黄色标记滑动到紧邻绿色像素的格位上（绿色像素与黄色标记之间更近的一侧）。
5. 输出为 H 行宽度不变的网格，包含绿(3)异或像素和滑动到位的黄(4)标记。其余位置为黑(0)。

**关键洞察**：黄色标记的滑动目标是异或运算动态生成的，而非输入中预设的固定锚点。求解者必须先心算出异或结果，才能判断标记应向何处移动；仅看标记和掩码的空间关系无法直接推断终点。

## 新题 9：互补拼合矩形的面积编码平铺倍率

**组合逻辑**：[移动/move + 互补拼合/complement_fit](已有) → [平铺/tile + 交替翻转](创新：平铺倍率由拼合后矩形的面积与碎片面积之比决定) → [镜像/mirror](已有)

**来源原语**：移动/move (fe45cba4), 互补拼合/complement_fit (fe45cba4), 碎片/fragment (fe45cba4), 锚定物体/anchor_object (fe45cba4), 同色碎片拼成矩形/same_color_join (fe45cba4), 碎片触边锚不触边/frag_edge_anchor (fe45cba4), 平铺/tile (8d5021e8), 镜像/mirror (8d5021e8), 交替翻转平铺/alternating_reflections_tiling (8d5021e8), 精灵体/sprite (8d5021e8)

**依赖链**：识别触边碎片和锚定碎片 → 移动触边碎片与锚拼合成完整矩形 → 矩形面积 A 除以触边碎片像素数 F 得到比值 R → R 决定以拼合矩形为源瓦片的镜像平铺倍率（R 行 x R 列）→ 交替翻转平铺生成最终输出。拼合结果同时提供瓦片内容和平铺倍率，两者缺一不可。

将触边碎片移到锚碎片旁拼成矩形后，矩形面积与碎片面积之比决定镜像平铺的阵列大小，以该矩形为源瓦片做交替翻转平铺。

**输入结构**：
- 黑(0)背景，约 8x10 网格（较小，因为输出会被平铺放大）。
- 恰好一种前景颜色（从红(2)、蓝(1)、绿(3)、橙(7)中选取）出现两个 4-连通碎片：一个触碰网格左边缘（触边碎片），一个不触碰任何边缘（锚定碎片）。
- 触边碎片的像素数 F 为 2~5；锚定碎片的像素数为矩形总面积 A 减去 F，其中 A = W x H 恰好使 A/F 为整数且 A/F 属于 {2, 3}（即平铺倍率 R 为 2 或 3）。
- 平移触边碎片后可与锚定碎片拼合成 W x H 的实心矩形。
- 生成约束：拼合的平移偏移量唯一；拼合后矩形的 W 和 H 均不超过 5；网格中无其他前景颜色。

**规则**：
1. 识别前景颜色的两个 4-连通碎片，区分触边碎片（触碰左边缘）和锚定碎片（不触边）。
2. 找到唯一的平移向量，使触边碎片平移后与锚定碎片互补拼合成一个 W x H 实心矩形。
3. 计算触边碎片的像素数 F。计算矩形面积 A = W x H。令 R = A / F。
4. 清除原输入，以拼合后的矩形作为源瓦片。
5. 构建中间行带：将源瓦片水平镜像得到翻转副本，源瓦片与翻转副本左右交替排列共 R 列（第 1 列原始、第 2 列水平翻转、第 3 列原始...）。
6. 将中间行带垂直镜像得到翻转行带。原始行带与翻转行带上下交替排列共 R 行（第 1 行原始、第 2 行垂直翻转、第 3 行原始...）。
7. 输出为 R x R 瓦片阵列构成的网格，尺寸为 (R*H) x (R*W)。

**关键洞察**：平铺的阵列大小不是固定的常数，而是由碎片拼合后的面积比编码——拼合矩形面积越大（相对于碎片），平铺倍率越高。求解者必须完成拼合才能知道平铺规模，仅看碎片形状无法推断倍率。

**输入结构**：
- 黑(0)背景，约 18x18 网格。
- 3~5 个不同颜色的一像素宽空心矩形帧相互重叠（颜色从红(2)、蓝(1)、绿(3)、黄(4)、青(8)中选取）。帧的重叠关系使得每对相邻层之间至少有一个可见的遮挡像素。
- 帧的内部区域（帧边框围起的空间，不含边框本身）中散布着一些黑(0)和品红(6)像素。黑色像素的一部分构成完整的十字模板（中心像素及其上下左右四个邻居均为黑色），其余黑色像素不构成完整十字。品红像素是"干扰填充"，不参与任何规则。
- 生成约束：每个帧内部至少包含 1 个完整十字模板，至多 3 个；帧内部的十字模板之间互不重叠；不同帧内部的十字数量互不相同；十字模板完全在某个帧的内部（不跨越帧边界），且对于同时被多个帧包围的区域，十字归属于最小（面积最小）的包围帧。

**规则**：
1. 对每种前景颜色，从可见像素推断其帧的完整边界框。
2. 利用重叠位置的可见颜色推断从底到顶的完整遮挡层序。
3. 对每个帧，确定其"独占内部区域"——被该帧包围但不被任何更小帧包围的像素集合。
4. 在每个帧的独占内部区域中，检测完整的十字模板：找到每个黑(0)像素，其上下左右四个邻居也是黑(0)的，该中心及其四邻居构成一个十字。统计该帧包含的十字数量 K。
5. 输出为单列网格，从底到顶列出每层帧的颜色：层序第 i 层（从底部层 0 开始）的帧颜色连续填充 K_i 行（K_i 为该帧的十字数量）。最终输出高度等于所有帧十字数量之和。

**关键洞察**：层序和十字计数是两条独立的推理线索，但它们在输出格式中交汇——层序决定颜色的排列方向，十字计数决定每种颜色的行数。求解者不能只推断层序而忽略十字计数（否则不知道每色占几行），也不能只数十字而忽略层序（否则不知道颜色排列方向）。
