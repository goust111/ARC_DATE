## 新题 1：载体定向射线与垂直边界限长

**组合逻辑**：[颜色决定方向](从 9b4c17c4 的滑动方向编码创新为射线方向编码) + [射线延伸](已有) + [投射到最近边界](从 705a3229 的方向决定创新为长度决定) + [擦除](已有)

**来源原语**：颜色决定方向(color_determines_direction) ← 9b4c17c4；射线延伸(ray_extend) ← 705a3229；投射到最近边界(projection_to_nearest_edge) ← 705a3229；载体区域(carrier_region) ← 9b4c17c4；标记像素(marker_pixel) ← 705a3229；擦除(erase) ← 9b4c17c4

**依赖链**：载体颜色决定射线水平方向（蓝右/青左）→ 标记像素的垂直边界距离决定射线长度 → 射线按此方向和长度绘制 → 原标记被擦除还原为载体色。方向与长度分别由两个独立信息源决定，缺一不可。

从嵌入彩色载体区域中的标记像素出发，沿载体颜色编码的水平方向，画出长度等于标记到最近上下边界距离的射线，同时擦除原始标记。

**输入结构**：约 15x15 的网格，黑(0)背景。网格上有 2-3 个轴对齐的实心矩形区域，分别为蓝(1)或青(8)，每个区域约 4x6 至 5x8 像素。每个区域内部（不在区域边界上）有 1-2 个红(2)标记像素，标记不相邻。各矩形区域互不重叠，且与网格边界至少间隔 2 行/列。生成约束：每个标记到上下边界的最近距离不超过网格宽度的一半，保证射线不会超出网格；不同标记的射线路径互不交叉。

**规则**：
1. 对每个红(2)标记像素，确定其所在的载体区域颜色：蓝(1)表示射线方向为向右（列增方向），青(8)表示射线方向为向左（列减方向）。
2. 计算该标记到网格上边界（行 0）和下边界（行 H-1）的距离，取较小值 L = min(r, H-1-r)，其中 r 为标记所在行。
3. 从标记的水平相邻像素（按步骤 1 的方向）开始，连续绘制 L 个红(2)像素。如果下一个位置已有非黑(0)非本载体色像素，则射线在该位置之前停止（不覆盖该像素）。
4. 将原始标记像素的颜色还原为其载体区域的颜色（蓝或青）。
5. 各标记的射线绘制互相独立，可任意顺序处理（生成约束保证射线路径互不冲突）。

**关键洞察**：射线方向是水平的（由载体颜色编码），但射线长度由标记在垂直方向上到最近水平边界的距离决定——方向轴与限长轴正交，这一关系在单个示例中不易发现，需对比不同行高的标记才能归纳。

## 新题 2：旋转引发的交叉环标记

**组合逻辑**：[旋转](已有) → [交叉点检测](创新：旋转后产生的新交叉) → [交叉邻域环涂色](创新：环色由交叉对象类型决定)

**来源原语**：旋转(rotate) ← f0f8a26d；中心点不变(center_fixed) ← f0f8a26d；朝向交换长度保持(orient_swap_keep) ← f0f8a26d；交叉点(crossing_point) ← 67a423a3；全行条(full_row_bar) ← 67a423a3；全列条(full_column_bar) ← 67a423a3；交叉邻域环涂色(crossing_ring_recolor) ← 67a423a3；描边(outline) ← 67a423a3

**依赖链**：彩色短条原地旋转 90 度 → 旋转改变了每条短条与绿色参考行/列的空间关系 → 对新产生的交叉点施加环标记 → 环色由交叉类型决定（行交叉/列交叉/双交叉）。旋转步骤直接决定了哪些交叉存在以及在哪里。

将彩色短条旋转 90 度后，在它们与绿色参考行/列的交叉点周围画出颜色取决于交叉类型的 3x3 环。

**输入结构**：约 15x15 的网格，黑(0)背景。一行完全由绿(3)像素填满（全行条），一列完全由绿(3)像素填满（全列条），它们交叉于一个远离边界的像素。另有 3-5 条单像素宽的彩色短条（每条一种不同的非绿非黑颜色，如红(2)、蓝(1)、黄(4)、橙(7)等），长度为奇数（3-7 像素），可以是水平或垂直方向。各短条互不接触，且不与绿色参考行/列重叠。生成约束：每条短条旋转后完全在网格内部；旋转后至少有 2 条短条与绿色参考行或列产生交叉；交叉点与绿色行列自身的交叉点不重合。

**规则**：
1. 将每条彩色短条绕其中心像素旋转 90 度（水平变垂直、垂直变水平），长度和中心位置不变。绿色参考行列不旋转。
2. 旋转后，检测每条短条的像素是否与绿色全行条重合（同一行的像素）或与绿色全列条重合（同一列的像素）。
3. 对于仅与全行条交叉的像素：以该交叉点为中心，将周围 3x3 区域中的 8 个非中心像素涂为黄(4)。中心保留短条颜色。
4. 对于仅与全列条交叉的像素：以该交叉点为中心，将周围 3x3 区域中的 8 个非中心像素涂为橙(7)。中心保留短条颜色。
5. 对于同时与全行条和全列条交叉的像素（即该像素恰好落在绿色行列的交叉点上）：以该交叉点为中心，将周围 3x3 环涂为红(2)。中心保留短条颜色。
6. 环像素的绘制优先级：短条像素 > 环像素 > 绿色参考线像素 > 背景。即环不覆盖短条本身的其他像素，但会覆盖绿色参考线和背景。
7. 未产生任何交叉的旋转后短条保持原样，无环标记。

**关键洞察**：原本与参考行平行（无交叉）的水平短条，旋转后变为垂直，可能穿过参考行产生新交叉；反之亦然。交叉是否存在完全取决于旋转结果，且环的颜色编码了交叉类型（行/列/双），需要对比多个示例中不同交叉位置的环色才能归纳三色规则。

## 新题 3：嵌套层补全与邻接噪声清洗

**组合逻辑**：[补全](已有) + [大层先画小层覆盖](已有) → 结构/噪声分类(创新：补全结果定义哪些是噪声) → [邻接够归并否则删](创新：归并色由最内层邻接矩形决定)

**来源原语**：补全(complete) ← 5751f35e；稀疏矩形层(sparse_rect_layer) ← 5751f35e；嵌套矩形(nested_rectangle) ← 5751f35e；由外到内嵌套(outer_to_inner) ← 5751f35e；大层先画小层覆盖(large_first_small_over) ← 5751f35e；擦除(erase) ← 7e0986d6；噪点(noise_pixel) ← 7e0986d6；邻接(adjacency) ← 7e0986d6；邻接够归并否则删(merge_or_delete) ← 7e0986d6

**依赖链**：稀疏矩形层按面积从大到小补全为实心嵌套矩形 → 补全后，未被任何矩形层覆盖的灰色像素被识别为噪声 → 对每个噪声像素统计其与补全后矩形边界的正交邻接数 → 邻接数 >= 2 的噪声吸收为最内层邻接矩形的颜色，否则删除。补全步骤的结果直接决定了哪些像素是噪声以及噪声的邻接对象。

将稀疏嵌套矩形层补全为实心后，按邻接支持度决定散落灰色噪声的归属或删除。

**输入结构**：约 12x12 的网格，黑(0)背景。3-4 种非黑非灰颜色（如红(2)、蓝(1)、绿(3)），每种颜色有若干分散像素，标记一个轴对齐矩形层的采样点（每种颜色至少 4 个采样像素，分布在对应矩形的边和角上）。这些矩形的包围框面积互不相同，且严格嵌套（小矩形完全在大矩形内部）。另有 5-10 个灰(5)孤立像素散布在网格各处（有些靠近矩形边界，有些远离）。生成约束：每种颜色的采样像素能唯一确定一个矩形包围框；灰色像素不与任何采样像素的颜色相同。

**规则**：
1. 对每种非灰颜色，计算其所有采样像素的轴对齐包围框，作为该颜色的矩形层。
2. 按包围框面积从大到小排序。依次将每个矩形层内的所有像素涂为该层颜色（大层先画，小层后画覆盖）。
3. 补全完成后，检查每个灰(5)像素：
   - 统计其 4 连通邻居中有多少属于已补全矩形层（非黑非灰像素）。
   - 若邻接数 >= 2：将该灰像素重涂为其邻接矩形层中最内层（面积最小）的颜色。若邻接的矩形层只有一种，则涂为该种颜色。
   - 若邻接数 < 2：将该灰像素删除（设为黑(0)）。
4. 处理顺序不影响结果（每个灰像素的邻接判断基于补全后的矩形状态，不受其他灰像素处理的影响）。

**关键洞察**：噪声像素的命运完全取决于补全后的矩形结构——靠近嵌套边界的灰像素可能同时邻接两个不同层的矩形，此时它取最内层的颜色（因为画面上该位置的表面色就是最内层色）。这个"最内层优先"规则需要对比多个示例中处于不同嵌套位置的灰像素才能归纳。

## 新题 4：对称补形与分隔行双色填充

**组合逻辑**：[镜像](已有) → [擦除轮廓](创新：清除轮廓像素而非保留) → [全空行列检测](已有) → [填充](创新：分隔行将内部分为双色区) + [标记像素提供第二色](创新：外部孤立像素编码填充色)

**来源原语**：镜像(mirror) ← bf32578f；半侧轮廓(half_outline) ← bf32578f；对称轴(symmetry_axis) ← bf32578f；对称(symmetry) ← bf32578f；内部行段填充(fill_interior_spans) ← bf32578f；填充(fill) ← bf32578f；全空行列检测(detect_empty_row_col) ← da2b0fe3；分隔行列(separator_row_col) ← da2b0fe3；重涂色(recolor) ← da2b0fe3；标记像素(marker_pixel) ← 705a3229

**依赖链**：左半轮廓镜像生成完整对称闭合形状 → 擦除轮廓像素 → 在对称形状的包围框内部检测唯一全空行（分隔行）→ 分隔行将内部分为上下两区 → 上区填轮廓色、下区填外部标记像素色 → 分隔行涂绿横贯全网格。镜像决定形状，形状决定分隔行位置，标记像素决定下区颜色——三个信息源缺一不可。

将左半轮廓镜像为完整对称形状，擦除轮廓后按内部分隔行将上下区域分别填入轮廓色和外部标记色。

**输入结构**：约 13x13 的网格，黑(0)背景。蓝(1)前景像素构成一个垂直对称闭合轮廓的左半部分：轮廓的最右列紧邻网格的垂直中轴线左侧。左半轮廓约 6-10 行高，3-5 列宽，形成一个类似花瓶或钟形的弧线（不同示例中具体形状不同，但都是上下窄中间宽或上下宽中间窄的连通单色轮廓）。轮廓的某一内部行恰好没有前景像素（镜像后该行在完整形状的包围框内部仍为全空行）。网格的背景区域（不在镜像后形状内部的位置）有一个孤立的红(2)像素。生成约束：镜像后的完整形状包围框内部恰好有一条全空行；红色标记像素不在镜像后形状的包围框内部。

**规则**：
1. 确定蓝(1)半轮廓的最右列 c_max。垂直对称轴位于 c_max 与 c_max+1 之间。
2. 将半轮廓镜像到右侧：对每个蓝像素 (r, c)，在 (r, 2*c_max - c + 1) 处也涂蓝(1)（若原本为黑）。
3. 将完整轮廓的所有蓝像素擦除（设为黑(0)）。
4. 计算原完整轮廓的包围框。在包围框内部（不含包围框边界行），找到唯一的全黑行 r_sep，该行即为分隔行。
5. 对包围框内部 r_sep 以上的每一行，确定原轮廓在该行的最左和最右前景像素位置（即步骤 2 完成后、步骤 3 擦除前的轮廓边界），将这两个位置之间的所有像素（不含边界本身）填为蓝(1)。
6. 对包围框内部 r_sep 以下的每一行，用相同方法确定边界，将内部填为红(2)（红色来自背景中的孤立标记像素）。
7. 将 r_sep 行上从第 0 列到最后一列的所有像素涂为绿(3)。
8. 将背景中原来的红色标记像素擦除（设为黑(0)）。

**关键洞察**：轮廓色（蓝）自动成为上区填充色，但下区填充色来自一个看似无关的外部孤立像素——该像素的唯一作用是提供颜色编码。这个颜色来源需要对比不同示例（不同标记色对应不同下区颜色）才能发现。

## 新题 5：三角形定向配对滑动

**组合逻辑**：[方向指示](创新：三角形朝向不再驱动自身射线，而是驱动配对对象的滑动方向) + [滑动](已有) + [颜色索引匹配](创新：颜色匹配用于配对三角形与可移动对象) + [擦除](已有)

**来源原语**：方向指示(direction_indication) ← 25d487eb；三角形(triangle) ← 25d487eb；顶点反基底延伸(tip_away_from_base) ← 25d487eb；滑动(slide) ← 9b4c17c4；可移动对象(movable_object) ← 9b4c17c4；颜色索引匹配(color_index_matching) ← 7d18a6fb；擦除(erase) ← 9b4c17c4

**依赖链**：同色配对（三角形与可移动图形）→ 三角形朝向确定该配对的滑动方向 → 可移动图形沿该方向滑动直到碰撞或出界 → 按三角形顶点行序依次处理（先移的成为后移的障碍）→ 三角形擦除。配对、方向、顺序三者交织：缺少配对不知道谁滑、缺少三角形不知道方向、缺少顺序碰撞结果不确定。

将每个彩色三角形的朝向作为同色配对图形的滑动方向，按顶点行序依次滑动并擦除三角形。

**输入结构**：约 15x15 的网格，黑(0)背景。3-4 种颜色（如红(2)、蓝(1)、黄(4)、品红(6)），每种颜色恰好有两个对象：一个是小型实心直角三角形（3-6 像素，底边在某一基数方向上，如底在下则尖朝上），另一个是紧凑的 4 连通单色图形（3-6 像素，非三角形形状，不同示例中形状不同）。同色的两个对象不共享任何行或列。不同颜色的对象互不接触，且彼此之间至少间隔 1 个像素。生成约束：每个可移动图形沿其配对三角形的朝向滑动后不会与同色三角形重叠；各图形的滑动路径按处理顺序依次可解（不产生循环依赖）。

**规则**：
1. 对每种颜色，识别三角形和非三角形图形。三角形的判定标准：该 4 连通单色对象的形状为直角三角形（有一条边与行方向平行、一条边与列方向平行，斜边连接两端）。
2. 确定三角形的朝向：找到三角形的底边（与行或列平行的最长边），顶点（apex）为距底边最远的像素。朝向 = 从底边中心指向顶点的基数方向（上/下/左/右）。
3. 确定处理顺序：按三角形顶点的行坐标从小到大排序；行坐标相同时按列坐标从小到大排序。
4. 按顺序处理每个配对：将非三角形图形沿该三角形的朝向逐像素平移，直到图形的任一像素的下一个位置会落在非黑像素上或超出网格边界。图形停在最后一个合法位置。
5. 将三角形的所有像素擦除（设为黑(0)）。
6. 已滑动到位的图形像素视为障碍物，后续配对滑动时会在它们面前停下。

**关键洞察**：三角形本身不产生输出——它是一个方向指示器，用完即擦除。配对关系（同色）和处理顺序（顶点行序）都不是显然的：配对需要对比多个示例中不同颜色的三角形-图形组合来确认同色规则；处理顺序影响碰撞结果，需要在示例中观察先后滑动产生的级联障碍效应才能归纳。

## 新题 6：算术线外推与框色继承

**组合逻辑**：[外推](已有) + [等距共线](已有) → 射线路径追踪(创新：外推路径与矩形边框的空间碰撞决定停止点) → [最外层颜色继承](创新：继承的不是包含关系的颜色，而是碰撞终止处的框色) + [重涂色](已有)

**来源原语**：外推(extrapolate) ← 0b17323b；等距共线(equally_spaced_collinear) ← 0b17323b；等距标记点(equally_spaced_markers) ← 0b17323b；算术线(arithmetic_line) ← 0b17323b；边界内延续(continue_within_bounds) ← 0b17323b；矩形边框(rectangular_perimeter) ← 7d1f7ee8；严格包含(strict_containment) ← 7d1f7ee8；重涂色(recolor) ← 7d1f7ee8

**依赖链**：三点标记定义等距共线方向和步长 → 从最后一个标记向前外推 → 外推路径逐步检测碰撞目标 → 撞到矩形框边→外推线段（不含框像素）重涂为该框的颜色；撞到网格边界→保留灰色。空间配置（框的位置和方向）决定外推的终止色。

沿等距标记确定的方向外推直线，外推段的颜色继承自终止时碰到的矩形框颜色。

**输入结构**：约 18x18 的网格，黑(0)背景。2-3 组灰(5)标记三联体，每组 3 个像素等距共线（水平、垂直或 45 度对角方向，步长 1-3 像素）。网格上另有 3-4 个空心矩形边框（仅周长像素着色，内部为黑(0)），每个框一种独特颜色（如红(2)、蓝(1)、绿(3)、黄(4)）。矩形框大小约 4x4 至 6x6，互不重叠，与标记三联体也不重叠。生成约束：每组三联体的外推方向至多命中一个矩形框或网格边界；至少有一组命中框、至少有一组命中网格边界（以便对比两种情况）。

**规则**：
1. 对每组灰(5)三联体，按行优先（row-major）方向排列三个标记点，计算相邻点间的步向量 (dr, dc)。
2. 从第三个标记点开始，沿 (dr, dc) 方向逐步外推：下一位置 = 当前位置 + (dr, dc)。
3. 若下一位置在网格外：停止。已绘制的所有外推像素保持灰(5)。
4. 若下一位置是某矩形框的边框像素（非黑非灰）：停止（不绘制该位置）。将从第一个外推像素到当前位置的所有已绘制外推像素重涂为该框的颜色。
5. 若下一位置是黑(0)背景：在该位置绘制灰(5)，继续外推。
6. 原始三联体标记保持灰(5)不变。
7. 各组三联体独立处理，顺序不影响结果（生成约束保证路径互不交叉）。

**关键洞察**：外推线段的颜色不由标记自身决定，而由它"撞到什么"决定——同样的灰色三联体，指向蓝框就变蓝，指向红框就变红，指向网格外就保持灰。这一规则需要对比多组指向不同终点的外推线段才能归纳，且碰撞目标是框的边框像素（不是框的内部），这一几何细节也需仔细观察。

## 新题 7：旋转驱动的高度排序色带

**组合逻辑**：[旋转](已有) → [最高行决定序](创新：排序依据不是原始最高行，而是旋转后的最高行) → [排序](已有) + [压缩](已有)

**来源原语**：旋转(rotate) ← f0f8a26d；单像素宽条(thin_bar) ← f0f8a26d；中心点不变(center_fixed) ← f0f8a26d；朝向交换长度保持(orient_swap_keep) ← f0f8a26d；排序(sorting) ← 668eec9a；压缩(compress) ← 668eec9a；色条行(color_stripe_row) ← 668eec9a；最高行决定序(topmost_determines) ← 668eec9a；顺序排列(ordered_arrangement) ← 668eec9a

**依赖链**：彩色短条旋转 90 度 → 旋转改变每条短条的最高行（水平条变垂直后最高行上移，垂直条变水平后最高行下移至中心行）→ 按新最高行排序 → 输出压缩色带。旋转直接改变排序键，删去旋转则排序结果不同。

将彩色短条旋转 90 度后，按旋转后的最高行位置排序，输出为压缩色带摘要。

**输入结构**：约 15x15 的网格，黑(0)背景。4-5 条单像素宽的彩色短条，每条一种独特的非黑颜色（如红(2)、蓝(1)、绿(3)、黄(4)、品红(6)），长度为奇数（3-9 像素），可以是水平或垂直方向。各短条互不共享像素。生成约束：旋转后所有短条仍完全在网格内部；旋转后各短条的最高行互不相同（无需 tie-break）。

**规则**：
1. 将每条彩色短条绕其中心像素旋转 90 度（水平变垂直、垂直变水平），中心和长度不变。
2. 计算每条旋转后短条的最高行（即其像素中行坐标的最小值）。
3. 按最高行从小到大（从上到下）排列所有短条的颜色。
4. 输出一个 K x 3 的小网格（K = 短条数量），黑(0)背景。从上到下，每行填充一种颜色的 1x3 实心色带，颜色顺序为步骤 3 的排列顺序。

**关键洞察**：一条长 9 像素的水平条位于第 10 行，旋转后变为垂直条，中心仍在第 10 行，但最高行变为第 6 行（10 - 4 = 6）；而一条长 3 像素的垂直条原本最高行在第 3 行，旋转后变为水平条，最高行变为中心行第 4 行。旋转后的排序完全颠覆了原始位置的直觉顺序。需要对比输入中短条的方向/长度/位置与输出色带顺序的关系才能发现旋转这一中间步骤。

## 新题 8：跨瓦片对角标记与支持度过滤

**组合逻辑**：[平铺](已有) → [对角邻接标记](已有) → [邻接够归并否则删](创新：将噪声过滤规则应用于平铺产生的对角标记，跨瓦片边界的标记因互相支持而存活)

**来源原语**：平铺(tiling) ← 10fcaaa3；种子像素(seed_pixel) ← 10fcaaa3；对角邻接(diagonal_adjacency) ← 10fcaaa3；平铺后对角涂色(diagonal_marked_after_tiling) ← 10fcaaa3；擦除(erase) ← 7e0986d6；邻接(adjacency) ← 7e0986d6；邻接够归并否则删(merge_or_delete) ← 7e0986d6；噪点(noise_pixel) ← 7e0986d6

**依赖链**：小网格 2x2 平铺 → 平铺在瓦片边界创造了原始网格中不存在的邻接关系 → 对所有非黑像素的对角邻居涂青 → 跨瓦片边界处的青像素因相邻瓦片的种子/青像素而获得正交支持 → 正交邻居不足 2 个的青像素被删除。平铺决定了哪些对角标记有跨边界支持，过滤结果揭示瓦片边界结构。

将种子像素网格平铺后标记对角邻居为青色，再按正交邻接支持度过滤掉孤立的青色标记。

**输入结构**：约 5x5 的小网格，黑(0)背景。1-3 个非黑非青颜色的种子像素（如红(2)、蓝(1)、绿(3)），位置不同。种子不在网格的正中心（以免对称性导致平铺后结果过于均匀）。生成约束：至少有一个种子靠近网格边缘（距边界 0-1 像素），以保证平铺后跨边界效应明显。

**规则**：
1. 将输入网格在水平和垂直方向各复制一次，生成宽度和高度均为原来 2 倍的平铺网格（左上、右上、左下、右下四个象限各一份副本）。
2. 对平铺网格中每个非黑非青像素（种子），检查其 4 个对角邻居（左上、右上、左下、右下）。若对角邻居是黑(0)，则将其涂为青(8)。
3. 对所有刚涂成青(8)的像素，统计其 4 连通正交邻居（上下左右）中非黑像素的个数（包括种子像素和其他青像素）。
4. 若非黑正交邻居数 < 2：将该青像素删除（恢复为黑(0)）。
5. 若非黑正交邻居数 >= 2：该青像素保留。
6. 种子像素始终保留，不受过滤影响。

**关键洞察**：靠近原始网格边缘的种子在平铺后，其相邻瓦片中的副本与它距离很近。这两个副本各自产生的对角青标记在瓦片边界处彼此正交相邻，形成互相支持的青像素对，因此存活。远离边缘的种子产生的对角标记四周都是黑色，正交支持不足，被过滤删除。存活的青像素精确地标记了瓦片边界处的跨边界耦合位置。

## 新题 9：断线修复与长度编码重涂色

**组合逻辑**：[擦除对角噪声](已有) + [补线](已有) → 线段长度变化(创新：补线改变了线段的度量值) → [长度映射颜色](创新：完成后的长度作为编码键查表) + [重涂色](已有)

**来源原语**：补线(line_completion) ← 7b80bb43；擦除(erase) ← 7b80bb43；直线段(straight_line_segment) ← 7b80bb43；对角噪声(diagonal_noise) ← 7b80bb43；忽略干扰项(ignore_distractors) ← 7b80bb43；间隙长度限制(gap_length_constraint) ← 7b80bb43；长度映射颜色(length_maps_color) ← e048c9ed；条形段(bar_segment) ← e048c9ed；固定编码表(fixed_encoding) ← e048c9ed；计数(counting) ← e048c9ed；重涂色(recolor) ← e048c9ed

**依赖链**：删除对角噪声链 → 对角链的跨度决定可填补的最大间隙 → 填补间隙后线段长度改变 → 用完成后的新长度查编码图例 → 匹配的线段重涂为图例对应色，不匹配的保持原色。噪声清除和间隙填补直接改变了长度这一编码键，使得重涂色结果依赖于清洗步骤。

清除断线旁的对角噪声并补全间隙后，按完成长度查图例重涂每条线段的颜色。

**输入结构**：约 12x15 的网格，黑(0)背景。网格分为两个区域：左侧主区域（约占网格 3/4 宽度）和右上角图例区域（约 4x5 像素，用灰(5)边框围起）。主区域有 3-5 条灰(5)轴对齐直线段（水平或垂直），部分线段被打断为 2 段，断裂处间隙为 1-3 像素。每个断裂间隙附近有一条短的 45 度对角灰(5)像素链（2-4 像素，8 连通但与主线段 4 不连通），对角链的像素数 >= 间隙宽度。图例区域内有 3-4 条不同长度的小型水平色条，每条色条一种独特颜色（如红(2)、蓝(1)、绿(3)、黄(4)），长度各不相同（如 2、4、6、8 像素）。图例色条从上到下排列，之间间隔 1 行黑色。生成约束：每条主区域线段补全后的总长度恰好匹配图例中某一色条的长度；无两条主区域线段补全后长度相同。

**规则**：
1. 在主区域中，识别所有对角链：一个灰(5)像素若其所有灰色邻居都仅通过对角方向（8 连通但非 4 连通）相连，且不与任何轴对齐直线段 4 连通相邻，则属于对角链。将对角链的所有像素删除（设为黑(0)）。
2. 对每条残留的灰色直线段，检查其端点方向（沿线段的延伸轴）是否有同轴的另一段灰色线段，且中间间隙 <= 被删除的邻近对角链的像素数。若是，用灰(5)填充间隙，将两段合并为一条完整线段。
3. 测量每条完成后线段的总长度（像素数）。
4. 在图例区域中，读取每条色条的长度和颜色，建立长度→颜色映射表。
5. 对每条主区域线段：若其长度在映射表中有对应条目，将该线段所有像素重涂为对应颜色；若无对应条目，保持灰(5)不变。
6. 图例区域保持原样不变。

**关键洞察**：对角噪声链不仅是干扰项——它的长度同时编码了相邻间隙的最大可填补宽度。填补间隙改变了线段的实际长度，而新长度才是查表重涂色的键。如果不先清洗和补线，直接量长度会得到错误的颜色映射。这一因果链需要对比有断裂和无断裂的线段在不同示例中的表现才能完整归纳。
