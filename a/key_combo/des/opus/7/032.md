## 新题 1：分区异常瓦片的方位重涂

**组合逻辑**：[grid_partition + outlier_selection](从分区比较中筛出异常瓦片) -> [relative_position + recolor](用控制像素的相对方位决定区域内哪个单元格被重涂) -> [crop](裁出结果)

**来源原语**：grid_partition / separator_line（参考题 17）、outlier_selection / equality_comparison（参考题 19）、relative_position / control_pixel / recolor（参考题 6）、crop（参考题 19）

**依赖链**：分区比较产出"哪个瓦片是异常值"，方位重涂产出"该瓦片的 3x3 区域中哪一格被涂色"，两者缺一不可——不做比较不知道操作对象，不做方位解码不知道涂哪一格。裁剪依赖前两步的结果。

从网格分区中找出唯一与众不同的瓦片，在该瓦片内根据控制像素相对于灰(5)区域的方位将对应单元格涂为栗(9)色，裁出该 3x3 灰区域作为输出。

**输入结构**：
- 约 11x11 的网格，灰(5)色分隔行和分隔列将其均分为 3x3 共 9 个大小相同的瓦片（每个瓦片约 3x3）。
- 每个瓦片内部包含：一个由灰(5)像素组成的 3x3 实心正方形区域（位于瓦片中央），以及恰好一个非灰非背景的控制像素（位于瓦片的 3x3 灰区域之外的某个单元格）。
- 9 个瓦片中，恰好 8 个瓦片的控制像素颜色相同（如蓝(1)），1 个瓦片的控制像素颜色不同（如红(2)）。所有瓦片的灰区域结构相同。
- 背景色为黑(0)。
- 生成约束：控制像素不得位于灰区域上，各瓦片的控制像素在瓦片内的局部坐标可以不同。

**规则**：
1. 将 9 个瓦片按其灰区域以外的内容（控制像素的颜色）进行比较。恰好 1 个瓦片与其余 8 个不同（控制像素颜色不同），选定该瓦片为目标。
2. 在目标瓦片中，确定控制像素相对于 3x3 灰区域中心的方位：上方/同行/下方选择灰区域的顶行/中行/底行，左侧/同列/右侧选择灰区域的左列/中列/右列，得到灰区域中恰好一个单元格。
3. 将该单元格涂为栗(9)色，其余灰像素保持灰(5)。
4. 输出为该 3x3 灰区域（含涂色结果），尺寸 3x3。

**关键洞察**：必须先通过跨瓦片比较找到异常瓦片（仅看单个瓦片无法判断谁是异常），再用该瓦片内控制像素的空间方位解码涂色位置——两步推理交织在同一个瓦片结构上。

## 新题 2：柱状条算术决定杯形容器的填充高度

**组合逻辑**：[counting + height_arithmetic](对颜色匹配的柱状条做加减运算得到填充量) -> [fill + opening_direction](根据杯口朝向从封闭端开始填充) · 两路逻辑在"填多少"与"往哪填"上同时约束输出

**来源原语**：counting / height_arithmetic / color_encodes_sign / vertical_bar（参考题 14）、fill / cup_shape / opening_direction / interior_containment（参考题 13）

**依赖链**：柱状条的算术结果决定填充量（没有它不知道填多少），杯口朝向决定填充方向（没有它不知道从哪端开始填）。两个独立信息源在同一个杯体的内部像素上汇合。

根据与每个杯同色的柱状条的加减运算结果，从杯的封闭端向开口端填充对应数量的内部单元格。

**输入结构**：
- 约 15x20 的黑(0)背景网格，分为左右两个区域（无显式分隔线，靠间距自然区分）。
- 左区包含 2~3 个杯形容器，每个由单色像素（如蓝(1)、绿(3)、橙(7)）围成，形成三面封闭、一面开口的 U 形或倒 U 形或侧 U 形结构。每个杯的内部空腔宽 1 像素、深 3~6 像素。各杯颜色互不相同，开口朝向可以不同（上/下/左/右）。
- 右区包含若干底部对齐的 1 像素宽柱状条。每根条为青(8)或红(2)。每根条旁边紧邻一个与某杯同色的 1 像素标记（位于条的正下方一格），标明该条属于哪个杯。
- 对于每个杯，属于它的柱状条可能有多根，颜色为青(8)或红(2)。
- 生成约束：对每个杯，其青条高度之和减去红条高度之和的结果为正整数且不超过该杯内部空腔深度。

**规则**：
1. 对每个杯，收集右区中所有标记色与该杯颜色相同的柱状条。计算填充量 = 该杯所属青(8)条的高度之和 - 该杯所属红(2)条的高度之和。
2. 确定每个杯的开口朝向：开口是杯的边界框中唯一没有杯色像素封闭的那一侧。
3. 从杯的封闭端（与开口相对的一侧）开始，沿开口方向依次将空腔内的黑(0)像素涂为黄(4)，共涂"填充量"个像素。剩余空腔像素保持黑(0)。
4. 右区的柱状条和标记保持不变。杯的边框像素保持不变。

**关键洞察**：柱状条的颜色编码正负、标记色编码归属、杯口朝向编码方向——三个独立编码通道在一个空间操作（部分填充）中汇聚，缺少任何一个通道都无法确定输出。

## 新题 3：错切移墙后的标记行颜色互换

**组合逻辑**：[translate + shear + move_to_wall](物体移到对墙并逐行错切) ∩ [color_swap + opposite_edge_pair](标记行/列上的像素执行颜色对互换) · 错切改变了哪些像素落在标记行上，因此互换结果依赖错切

**来源原语**：translate / shear / move_to_wall / foreground_object / row_offset_incr（参考题 20）、color_swap / opposite_edge_pair / toggle_between_pairs / marker_pixel（参考题 3）

**依赖链**：错切决定物体的最终像素坐标，标记行决定哪些坐标上的像素被颜色互换。错切后物体的形状改变了哪些像素与标记行重合，因此互换结果不能在错切之前确定；反过来，不知道标记行位置也无法确定最终颜色。两步在空间上交织。

将贴墙物体移至对墙并施加逐行错切，然后对落在黄(4)标记行上的物体像素执行颜色对互换。

**输入结构**：
- 约 12x12 的网格，背景为黑(0)，底行为灰(5)地面行。
- 一个由两种颜色构成的前景物体（颜色对为青(8)/红(2)，像素混合排列，4-连通，约 6~10 像素）贴在左侧墙壁（最左列），底部紧接地面行。物体高 3~5 行、宽 2~3 列。
- 网格的上边缘和下边缘各有 1~2 个黄(4)标记像素，位于同一列形成对边标记对，标记 1~2 条完整行。
- 生成约束：标记行不与地面行重合；物体移到右墙后经错切，至少一个像素落在标记行上、至少一个不落在标记行上。

**规则**：
1. 将物体从原位置擦除（恢复为黑(0)）。
2. 将物体水平镜像后贴到右侧墙壁（最右列），底部仍紧接地面行，最上面 3 行保持与右墙对齐，从第 4 行起每多一行向左偏移 1 像素（逐行错切）。
3. 对错切后的物体，检查每个像素是否位于标记行（由黄(4)对边标记对选定的行）。若是，则对该像素执行颜色互换：青(8) <-> 红(2)。不在标记行上的像素颜色不变。
4. 地面行第一行中，从物体原始左墙位置到物体新右墙位置之间的地面像素涂为栗(9)。黄(4)标记像素保持不变。

**关键洞察**：颜色互换的结果依赖于错切后的像素坐标——同一个物体像素在错切前可能不在标记行上，错切后却落入标记行，因此必须先完成错切再判断互换，两步不可交换顺序也不可跳过。

## 新题 4：跨尺度形状配对选色驱动列传播

**组合逻辑**：[shape_matching + cross_scale_same_shape + return_smaller](跨尺度配对后提取较小者的颜色) -> [propagate + column_fill + bottom_marker_selects_column](用该颜色筛选底行标记列并向上传播)

**来源原语**：shape_matching / cross_scale_same_shape / return_smaller / scaled_object / distractor_object（参考题 4）、propagate / column_fill / bottom_marker_selects_column / vertical_color_band（参考题 2）

**依赖链**：跨尺度配对输出一个颜色值（较小配对对象的颜色），该颜色值作为筛选条件决定底行哪些标记列被激活并执行传播。没有配对就不知道激活哪些列，没有传播规则就不知道怎么填列。

通过跨尺度形状配对识别关键颜色，仅传播底行中该颜色标记所选定的列。

**输入结构**：
- 约 14x14 的黑(0)背景网格，概念上分为上下两部分（无显式分隔，靠垂直间距区分）。
- 上部包含 3 个单色连通对象（4-连通，各 4~12 像素，形状不规则），颜色分别为蓝(1)、绿(3)、橙(7)。其中两个对象形状相同但尺寸不同（一个是另一个的 2 倍或 3 倍线性缩放），第三个是干扰对象（形状与前两者不同）。较大者可能被画布边缘裁切。
- 下部为一个约 7 行的区域。底行（网格最后一行）包含若干非背景标记像素，颜色各异（从蓝(1)、绿(3)、橙(7)中选取），每个标记像素选定其所在列。被选定的列中散布着若干非背景彩色像素（颜色与该列底行标记相同）。
- 生成约束：跨尺度配对对象的较小者的颜色在底行标记中至少出现一次；底行标记中也存在其他颜色的标记（不被激活）。

**规则**：
1. 在上部 3 个对象中，找到形状相同但尺度不同的一对（将较小者按 2x 或 3x 缩放后与较大者的像素掩模匹配，忽略颜色）。记录较小对象的颜色，称为"激活色"。
2. 在底行中，仅选定颜色等于激活色的标记像素所在的列。
3. 对每个选定列，从底行向上扫描，维护当前颜色（初始为该列底行标记的颜色）。遇到非背景像素时更新当前颜色；遇到背景像素时将其替换为当前颜色。非选定列保持不变。
4. 上部对象保持不变。底行非激活色标记保持不变。

**关键洞察**：跨尺度形状配对的结果并非直接用于空间变换，而是产出一个颜色值作为"钥匙"，解锁底部哪些列参与传播——配对步骤和传播步骤通过颜色值这一中间语义紧密耦合。

## 新题 5：对角象限映射色驱动杯体射线方向

**组合逻辑**：[diagonal_mapping + marker_block](2x2 标记块的对角映射决定各象限颜色) ∩ [fill + ray_cast + opening_direction](杯口朝向决定是内部填充还是射线发射) · 颜色来源和操作类型由两个独立机制分别决定，在同一杯体上汇合

**来源原语**：diagonal_mapping / marker_block / marker_fills_diagonal_region（参考题 11）、fill / ray_cast / cup_shape / opening_direction / emit_from_opening / interior_containment（参考题 13）

**依赖链**：标记块对角映射提供"用什么颜色"，杯口朝向提供"做什么操作"（填充或射线）。两条信息分别编码在不同结构中，缺少任一条输出都不确定。

读取 2x2 标记块的对角映射色为四个象限的杯形容器着色，杯口朝向标记块则填充内部，杯口背向标记块则从开口发射射线。

**输入结构**：
- 约 13x13 的黑(0)背景网格。
- 网格中心区域有一个 2x2 的标记块，四个像素颜色互不相同（从蓝(1)、红(2)、绿(3)、橙(7)中选取）。
- 标记块的上下左右四个象限区域（标记块以外的空间按象限划分）中各有一个杯形容器。每个杯由灰(5)像素围成，三面封闭一面开口，内部空腔为 1~2 像素宽、2~4 像素深的黑(0)区域。
- 四个杯的开口朝向各不相同：其中 2 个杯的开口朝向标记块（即开口面对网格中心方向），另 2 个杯的开口背向标记块（即开口面对网格边缘方向）。
- 生成约束：每个杯完全位于其所在象限内，不跨越象限边界；杯的射线路径上在到达网格边缘前不会遇到其他非背景像素。

**规则**：
1. 确定标记块四个像素与象限的对角映射关系：标记块左上像素的颜色映射到右下象限，右上映射到左下，左下映射到右上，右下映射到左上。每个象限获得一个映射色。
2. 对每个象限中的杯形容器，判断其开口朝向：
   - 若开口朝向标记块（面向网格中心）：将杯内部空腔的所有黑(0)像素填充为该象限的映射色。
   - 若开口背向标记块（面向网格边缘）：不填充内部，改为从开口处向外（沿开口方向）发射一条直线射线，射线颜色为该象限的映射色，射线延伸至网格边缘。同时从开口的两个端点沿 45 度对角方向各发射一条射线，颜色相同，延伸至网格边缘。
3. 杯的灰(5)边框和标记块像素保持不变。

**关键洞察**：同一个杯的操作类型（填充 vs 射线）和操作颜色来自两个完全独立的编码结构——杯口朝向编码操作类型，标记块对角映射编码颜色——两者在杯体上交汇，单独任何一个都不能确定输出。

## 新题 6：精灵体锚点连线后按对角线段长度选择性擦除

**组合逻辑**：[connect + endpoint_match + color_role_swap](精灵体锚点间连线并交换颜色角色) -> [counting + longest_selected](度量连线中的对角线段长度，选出最长段) -> [erase](擦除未被选中的连线) · 连线结果是度量的前提，度量结果反过来决定保留哪些连线

**来源原语**：connect / endpoint_match / sprite / anchor / color_role_swap（参考题 9）、counting / diagonal_segment / longest_selected / parallel_diagonal_band（参考题 18）、erase（参考题 1）

**依赖链**：连线步骤产生新的线段，对角线段度量步骤在这些新线段上进行（没有连线就没有度量对象）。度量结果决定哪些连线被保留（没有度量就不知道擦除哪些）。三步环环相扣。

在精灵体锚点之间画连线并交换颜色角色，然后度量每条连线中对角方向的最长连续段，仅保留包含全局最长对角段的那条连线。

**输入结构**：
- 约 16x16 的黑(0)背景网格。
- 包含 3~4 个相同的小精灵体（4-连通，单色，每个约 3~5 像素，形状为非矩形的不规则连通块），颜色为绿(3)。每个精灵体有一个明确的中心锚点（精灵体边界框的中心像素）。
- 包含一条由蓝(1)像素组成的 8-连通直线段，连接两个精灵体的锚点（这两个精灵体的锚点恰好是线段的两个端点）。该线段可以是水平、垂直或对角方向。
- 生成约束：精灵体互不相邻；线段不穿过任何精灵体的非锚点像素；精灵体数量为 3 或 4 个（保证连线后有多条线段可比较）。

**规则**：
1. 执行颜色角色互换：在输出画布上，用蓝(1)画出所有精灵体锚点之间两两连线的直线段（8-连通最短路径）。在原始线段的两个端点位置，用绿(3)以锚点为中心印章精灵体图案。原始精灵体和原始线段从原位置擦除。
2. 对步骤 1 产生的所有蓝(1)连线段，逐条检查：将每条连线分解为水平段、垂直段和对角段（连续的同方向 8-连通像素序列），记录每条连线中最长对角段的长度。若连线为纯水平或纯垂直（无对角段），其对角段长度记为 0。
3. 选出包含全局最长对角段的那条连线（若有并列，选连接的两个锚点中行坐标较小者所在的那条；若仍并列，选列坐标较小者）。保留该连线及其两端的精灵体印章，擦除所有其他连线为黑(0)。其他位置的精灵体印章保持不变。

**关键洞察**：颜色角色互换产生了全新的线段集合，对角线段度量在这些新线段上执行——度量对象是互换步骤的产物，而非输入的原始结构，因此两步不可分离也不可跳过。

## 新题 7：平台槽位插入与柱状条高度偏移的双约束定位

**组合逻辑**：[rotate + size_matches_slot](旋转矩形块使其宽度匹配槽位) ∩ [height_arithmetic + color_encodes_sign](柱状条算术决定垂直偏移量) · 水平定位和垂直定位由两个独立机制分别确定，必须同时满足

**来源原语**：rotate / insert / rectangular_block / platform_slot / size_matches_slot / aligned_and_width_matched（参考题 5）、counting / height_arithmetic / color_encodes_sign / vertical_bar（参考题 14）

**依赖链**：槽位宽度匹配决定"放在哪个槽"（水平位置），柱状条算术决定"放在槽内多高"（垂直偏移）。两个约束同时作用于同一个矩形块的放置坐标，不是流水线而是并行约束汇合。

将矩形块旋转后插入宽度匹配的平台槽位，垂直放置高度由与该块同色的柱状条加减运算决定。

**输入结构**：
- 约 14x18 的黑(0)背景网格。
- 底部两行：最后一行为灰(5)实心平台行；倒数第二行由灰(5)分隔段和黑(0)间隙交替组成，间隙即槽位，宽度各不相同（2~4 像素宽），共 3 个槽位。每个槽位上方为空（黑(0)），深度至少 6 像素。
- 网格上部散布 3 个单色实心矩形块（4-连通），颜色互不相同（如蓝(1)、绿(3)、橙(7)），每个矩形一条边长为 2 像素、另一条边长为 2~4 像素。
- 网格右侧区域有若干底部对齐的 1 像素宽柱状条，每根为青(8)或红(2)。每根条底部紧邻一个 1 像素的色块，颜色与某个矩形块相同，标明该条属于哪个矩形块。
- 生成约束：每个矩形块恰好有一个宽度匹配的槽位（旋转使 2 像素边为高后，另一边宽度与某个槽位相同）；每个矩形块的柱状条算术结果（青条高度和 - 红条高度和）为 0 到 4 之间的非负整数。

**规则**：
1. 对每个矩形块，若需要则旋转使其 2 像素边为垂直方向（高度 = 2）。旋转后的宽度与某个槽位宽度相同，确定该块的目标槽位。
2. 对每个矩形块，计算其柱状条算术结果 = 所属青(8)条高度之和 - 所属红(2)条高度之和，记为偏移量 h。
3. 将每个矩形块放入其目标槽位：矩形底边距离平台行顶部 h 个像素（h=0 时底边紧贴平台行上方，h=1 时底边上移 1 格，依此类推）。矩形的水平位置与槽位左对齐。
4. 清除矩形块的原始位置为黑(0)。柱状条和标记保持不变。平台结构保持不变。

**关键洞察**：每个矩形块的最终位置由两个完全独立的编码同时决定——槽位宽度匹配编码水平坐标，柱状条算术编码垂直坐标——这是一个二维约束满足问题而非线性流水线。

## 新题 8：等差矩形笔画序列补全后按双色条对齐裁切

**组合逻辑**：[completion + arithmetic_progression](补全等差递推的矩形边框笔画序列) -> [align + same_color_align + top_row_reference](将双色条对齐到参考条) -> [erase · canvas_clips_visible](仅保留对齐后双色条所覆盖行上的笔画像素，其余笔画擦除) · 补全结果被对齐结果裁切，对齐结果依赖补全后的布局

**来源原语**：completion / rect_side_stroke / arithmetic_progression / canvas_clips_visible（参考题 10）、align / shift / two_color_bar / reference_bar / same_color_align / top_row_reference（参考题 12）、erase（参考题 1）

**依赖链**：等差补全产出完整的笔画序列（没有它不知道哪些像素存在），双色条对齐决定哪些行被"激活"（没有它不知道保留哪些行的笔画）。补全后的笔画空间位置和对齐后的行选择共同决定最终输出，缺一不可。

先补全等差矩形笔画序列，再将双色条对齐到参考条，仅保留对齐后各条所在行上的笔画像素。

**输入结构**：
- 约 15x15 的黑(0)背景网格。
- 网格中有 2~3 个蓝(1)色的矩形边框笔画（每个笔画是一个矩形的部分边——如顶边+右边、或左边+底边，呈 L 形或 U 形），边界框面积呈等差递增。序列中缺失 1~2 个中间成员。
- 网格的右侧区域有若干水平双色条（每条由相邻两个像素组成，分别为两种颜色，如绿(3)和橙(7)），分布在不同行上。最上方的一条是参考条，其余条的两色可能与参考条左右顺序相同或相反。
- 生成约束：补全后的笔画像素不与双色条区域重叠；等差序列的公差使得补全后的笔画在画布范围内至少有一部分可见。

**规则**：
1. 将已有的矩形边框笔画按边界框面积排序，计算相邻笔画间的行/列坐标公差，向两端延伸序列直到新成员的可见笔画像素数为零。用蓝(1)色绘制所有补全的笔画成员。
2. 识别最上方的双色条为参考条。对于每条非参考双色条，若其左侧像素颜色不在参考条的左列位置，则将该双色条整体水平平移使其左侧颜色对齐到参考条中同色像素所在列。
3. 对齐完成后，收集所有双色条（含参考条）所在的行号集合。在补全后的完整笔画序列中，仅保留位于这些行上的蓝(1)笔画像素，其余行的蓝(1)笔画像素擦除为黑(0)。
4. 所有双色条像素保持不变（包含对齐后的位置）。灰(5)背景填充不执行（与参考题 10 不同）。

**关键洞察**：等差序列补全和双色条对齐是两个独立的推理过程，但它们的结果在同一个画布上交汇——对齐后的行号集合"遮罩"了补全后的笔画，这个遮罩效果无法从任一步骤单独推断。
