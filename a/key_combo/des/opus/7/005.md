## 新题 1：射线碰撞涌现主干与正交连线

**组合逻辑**：[射线延伸](创新：两色像素分别发射水平/垂直射线) → [交叉涌现主干](创新：射线交汇点构成主干，非预设) → [连线到主干](已有原语)

**来源原语**：射线延伸(ray_extend) ← f8be4b64/bdad9b1f；交叉(crossing) ← bdad9b1f；连接到主干(connect_to_spine) ← bf89d739；控制像素(control_pixel) ← bf89d739；遇前景终止(stop_at_fg) ← f8be4b64；交叉点标记新色(crossing_cell_marked_new_color) ← bdad9b1f

**依赖链**：两组射线独立发射后在空间中交汇，交汇点集合涌现出主干结构；主干不是输入预设的，而是从射线交互中诞生的。随后，每个原始像素必须找到距离最近的主干点来连线——连线目标完全依赖于涌现的主干位置，删除射线步骤则主干不存在，删除连线步骤则像素与主干的关联丢失。

从两组正交射线的碰撞中涌现出主干结构，再将原始控制像素正交连接到这一涌现主干上。

**输入结构**：约 12x14 的黑(0)背景网格。散布 3-5 个红(2)像素和 3-5 个蓝(1)像素。所有红像素的行坐标互不相同（无两个红像素同行）；所有蓝像素的列坐标互不相同（无两个蓝像素同列）。红蓝像素之间也不共享行或列。生成约束：至少存在 2 个交叉点（即至少有 2 个红像素的行与蓝像素的列相交于空白区域）。红蓝像素彼此不相邻。

**规则**：
1. 从每个红(2)像素出发，沿其所在行向左和向右各延伸一条绿(3)射线，射线经过的每个背景(0)单元格变为绿(3)，遇到网格边界或已有非背景像素时停止（停止点不染色）。
2. 从每个蓝(1)像素出发，沿其所在列向上和向下各延伸一条绿(3)射线，规则同上。若射线经过的单元格已经是绿(3)（被先前的水平射线染色），则该单元格改为黄(4)，标记为交叉点。
3. 处理顺序：先绘制所有水平射线（红像素按行号从小到大），再绘制所有垂直射线（蓝像素按列号从小到大）。
4. 移除所有非交叉的绿(3)单元格（恢复为黑(0)）。仅保留黄(4)交叉点，这些点构成涌现主干。
5. 从每个原始红(2)像素出发，沿其所在行找到最近的黄(4)主干点，将该像素与该主干点之间的所有背景单元格染为红(2)。从每个原始蓝(1)像素出发，沿其所在列找到最近的黄(4)主干点，将该像素与该主干点之间的所有背景单元格染为蓝(1)。若某像素在其行（或列）上没有任何主干点，则该像素不画连线，仅保留自身。
6. 最终输出保留：原始红/蓝像素、黄(4)主干点、红/蓝连线段。

**关键洞察**：主干不是输入给定的——它从两组正交射线的空间交汇中涌现。仅看单个示例可能误以为黄色标记是手动放置的，需对比多个示例才能归纳出"主干 = 射线交叉点"这一生成规则。

## 新题 2：同心环逐层异或比较

**组合逻辑**：[深度排序提取环层](已有原语) ⊕ [逐层异或](创新：XOR 从平面掩码提升到结构化环层的逐层比较) → [重涂色输出环](已有原语)

**来源原语**：异或(xor) ← 3428a4f5；同心方框层(concentric_layer) ← 85c4e7cd/5c2c9af4；分隔行(separator_row) ← 3428a4f5；深度排序(depth_order) ← 85c4e7cd；对齐(alignment) ← 3428a4f5；重涂色(recolor) ← 85c4e7cd；逐像素异或输出(pixelwise_xor_output) ← 3428a4f5

**依赖链**：必须先从两半区各自提取同心环层并按深度对齐，才能进行逐层比较；XOR 判定必须在层级单位上进行（同深度整环比较），而非逐像素比较——因为同一环层内所有像素颜色相同，异或结果也一致。深度提取服务于比较对齐，比较结果服务于输出着色，三者缺一不可。

将输入的左右两组同心环按深度逐层对齐，相同深度的环做颜色异或比较：异则输出绿，同则输出黑。

**输入结构**：约 10x21 的网格（宽度为奇数）。正中央有一列黄(4)垂直分隔列，将网格分为左右两半，各约 10x10。左半区和右半区各包含一组同心矩形环，环数相同（2-4 层）。每层环一像素厚，颜色从红(2)、蓝(1)、绿(3)、灰(5)中选取（左右半区各自独立选色）。每半区的最外层环紧贴该半区的四条边界（即距该半区最近边缘距离为 0 的像素属于第 1 层）。两半区具有相同的行数和列数，且环层数相同。生成约束：至少有一个深度层的左右颜色不同，至少有一个深度层的左右颜色相同。

**规则**：
1. 识别黄(4)垂直分隔列，将输入分为左半区和右半区（均不含分隔列）。
2. 在每个半区中，按距该半区最近边缘的切比雪夫距离（即 min(到上、下、左、右边缘的距离)）对像素分层，距离为 0 的像素属于第 1 层（最外层），距离为 1 的属于第 2 层，依此类推。
3. 读取每个半区中各层的颜色（每层内颜色一致）。
4. 逐层比较左右半区的颜色：若第 d 层的左右颜色不同，则输出第 d 层颜色为绿(3)；若相同，则输出第 d 层颜色为黑(0)。
5. 输出网格尺寸等于一个半区的尺寸（行数 x 列数），填充同心环结构，第 d 层涂上步骤 4 确定的颜色。

**关键洞察**：XOR 不是逐像素施加，而是逐深度层施加——整环作为比较单元。仅看单个示例中某一绿色环，可能误以为是局部像素比较的结果；需对比多个示例才能确认比较粒度是"整层"而非"逐像素"。

## 新题 3：形状匹配配对锚点后滑动镜像

**组合逻辑**：[形状匹配](创新：归一化掩码匹配决定精灵-锚点配对) → [滑动](已有原语，方向由配对确定) → [镜像](已有原语，镜像轴由接触边确定)

**来源原语**：形状匹配(shape_matching) ← 2a5f8217；归一化形状匹配(normalized_shape_matching) ← 2a5f8217；滑动(slide) ← 11dc524f/a79310a0；镜像(mirror) ← 11dc524f；精灵体(sprite) ← 11dc524f；方块锚点(square_anchor) ← 11dc524f；接触边对齐(contact_edge_align) ← 11dc524f；锚点边为镜像轴(anchor_as_axis) ← 11dc524f；碰撞停止(collision_stop) ← 11dc524f

**依赖链**：形状匹配输出配对关系，配对确定每个精灵的目标锚点；目标锚点的方位决定滑动方向；滑动终点的接触边决定镜像轴。三步形成严格的信息传递链：匹配 → 方向 → 轴。删除匹配步骤，精灵不知道该走向哪个锚点；删除滑动步骤，无法确定镜像轴的位置；删除镜像步骤，只有平移没有反射。

通过归一化形状匹配将精灵配对到锚点，沿唯一基数方向滑动精灵至锚点接触，再以接触边为轴镜像生成反射副本。

**输入结构**：约 14x14 的黑(0)背景网格。包含 2-3 个小型 4-连通单色精灵，每个精灵由 3-6 个像素组成，各自颜色不同（从红(2)、蓝(1)、绿(3)中选取），归一化到包围盒后形状互不相同。另有 2-3 个灰(5)的 2x2 实心方块锚点，数量与精灵相同。每个锚点的某一侧（上、下、左或右）紧邻一个小型灰(5)指示形状，该指示形状的像素数与精灵相同，其归一化包围盒掩码恰好匹配某一个精灵的归一化包围盒掩码。每个精灵与其匹配的锚点之间沿唯一的基数方向（上下或左右）分隔，且分隔路径上无障碍物。生成约束：不同锚点的指示形状匹配不同的精灵（一一对应）；指示形状在锚点的哪一侧放置不影响规则（仅用于形状匹配，不编码方向）。

**规则**：
1. 对每个精灵和每个锚点旁的灰(5)指示形状，计算其归一化包围盒掩码（将像素平移到左上角对齐的最小矩形内的二值掩码）。
2. 将每个精灵匹配到唯一一个指示形状掩码相同的锚点。
3. 确定每个精灵与其匹配锚点之间的唯一基数分隔方向（精灵中心到锚点中心的主方向：水平或垂直，取绝对值较大的分量方向）。
4. 沿该方向滑动精灵，直到精灵最近的像素与锚点的朝向边相邻（4-连通相邻），精灵像素保持原色。
5. 以锚点的接触边（精灵接触到的那条边）为镜像轴，将滑动后的精灵反射到锚点的另一侧，反射副本着色为橙(7)。
6. 输出中擦除原始精灵位置、所有锚点及指示形状。仅保留滑动后的精灵（原色）和橙(7)镜像副本，背景为黑(0)。

**关键洞察**：灰色指示形状看似装饰，实际编码了形状匹配密钥——每个指示形状的归一化掩码唯一对应一个精灵，从而建立配对关系。不解决匹配问题，就无法确定滑动方向和镜像轴。

## 新题 4：嵌套环深度决定重涂色与选择性描边

**组合逻辑**：[空间嵌套分析](创新：通过包围关系推断深度，非直接读取几何距离) ⇒ { [重涂色](已有原语，深度驱动色映射), [描边](已有原语，深度奇偶决定描哪一侧) }（扇出结构：深度分析同时驱动两个下游操作）

**来源原语**：描边(outline) ← d931c21c；重涂色(recolor) ← d931c21c/85c4e7cd；封闭区域(enclosed_region) ← d931c21c；孔洞(hole) ← d931c21c；连通分量(connected_component) ← d931c21c；内外边界(inner_outer_bound) ← d931c21c；深度排序(depth_order) ← 85c4e7cd；内外边界分色(boundary_diff_color) ← d931c21c

**依赖链**：所有蓝色环视觉上相同，必须通过空间包围关系推断嵌套深度。深度信息同时驱动两个独立的下游变换：(a) 环体重涂色——深度映射到特定颜色；(b) 选择性描边——深度的奇偶性决定描外轮廓还是内轮廓。两个下游变换共享同一深度分析结果，但使用方式不同（一个用深度值，一个用奇偶性），形成扇出依赖。

分析蓝色闭合环的嵌套深度，按深度重涂每个环的颜色，同时根据深度奇偶性选择性地描绘外轮廓或内轮廓。

**输入结构**：约 15x15 的黑(0)背景网格。包含 3-5 个蓝(1)闭合环（每个环由 4-连通的蓝像素构成一个单像素厚的封闭轮廓，内部包围一个黑色孔洞区域）。某些环嵌套在其他环的孔洞内部，形成 2-3 层的嵌套层级。环的形状不限于矩形——可以是不规则但封闭的轮廓。每个环的像素数不同。生成约束：最深嵌套不超过 3 层；每层至少有一个环；不同层级的环不共享像素；每个环的孔洞是一个单连通黑色区域。

**规则**：
1. 对每个蓝(1)环，确定其嵌套深度：不被任何其他环的孔洞包围的环深度为 1；被恰好一个环的孔洞包围的环深度为 2；被两个环的孔洞逐层包围的环深度为 3。判定标准：环 A 包围环 B，当且仅当环 B 的所有像素都位于环 A 的孔洞区域（环 A 内部的黑色 4-连通分量，该分量不接触网格边缘）之内。
2. 按深度重涂色：深度 1 → 红(2)，深度 2 → 绿(3)，深度 3 → 黄(4)。
3. 选择性描边——对每个环，检查其深度的奇偶性：
   - 深度为奇数（1, 3）：在环的外侧描灰(5)轮廓——将与该环 8-相邻且位于环外部（不在环的孔洞内）的所有黑(0)单元格染为灰(5)。
   - 深度为偶数（2）：在环的内侧描橙(7)轮廓——将与该环 8-相邻且位于环的孔洞内部的所有黑(0)单元格染为橙(7)。
4. 描边处理顺序：从最深层环开始向外处理（深度大的先处理），以确保外层环的描边不被内层影响。若某个应被描边的单元格已被其他环的描边染色，则保留先染的颜色（深层优先）。

**关键洞察**：所有环在输入中颜色相同（蓝），求解者必须通过空间包围关系推断深度层级。深度值同时决定两件独立的事——环体颜色和描边侧（奇外偶内），仅看一个只有单层嵌套的示例无法区分"总是描外侧"和"奇数层描外侧"，需要对比不同嵌套深度的示例才能归纳规则。

## 新题 5：边框周期编码内部镜像轴

**组合逻辑**：[环形周期分析](已有原语) → [周期参数编码镜像轴](创新：周期结构的段/间比隐式编码变换指令) → [镜像补全](已有原语)

**来源原语**：环形周期(cyclic_period) ← 30f42897；边框段(border_segment) ← 30f42897；间隔等长重复(repeat_equal_gap) ← 30f42897；镜像(mirror) ← 93c31fbe/11dc524f；矩形框(rectangular_frame) ← 93c31fbe；内部图案(internal_pattern) ← 93c31fbe；宽高比决定镜像轴(aspect_ratio_mirror_axis) ← 93c31fbe

**依赖链**：边框上的周期装饰看似纯粹的装饰元素，实际编码了一条隐式指令——彩色段长与间隙长的大小关系决定内部图案应沿哪个轴镜像。不分析周期结构就无法确定镜像轴；不执行镜像就留下半空的内部。两者通过"段间比编码轴方向"这一隐式通道紧密耦合。

边框上的周期彩色段与间隙的长度比编码了镜像轴方向：段长 > 间隙则垂直镜像，间隙 > 段长则水平镜像。

**输入结构**：约 11x11 的网格。最外圈一像素构成矩形边框，边框底色为灰(5)。在边框上，有若干等长的红(2)连续段，段与段之间以等长的灰(5)间隙分隔，沿顺时针方向周期排列（段可能跨越边框的角）。边框内部（排除边框本身的区域）的一半包含一个由多色像素组成的非对称图案（使用蓝(1)、绿(3)、黄(4)等颜色），另一半为黑(0)背景。具体地：若镜像轴为垂直轴，图案位于左半区，右半区为黑；若为水平轴，图案位于上半区，下半区为黑。生成约束：红色段长度 n 和灰色间隙长度 g 满足 n =/= g（即段长和间隙长不相等）；边框周长能被 (n + g) 整除或近似整除（允许最后一个周期截断）；内部图案不接触边框。

**规则**：
1. 沿顺时针方向展开边框为一维序列，识别红(2)彩色段和灰(5)间隙段。测量彩色段长度 n 和间隙长度 g。
2. 比较 n 和 g：
   - 若 n > g，镜像轴为垂直轴（内部图案执行左右镜像）。
   - 若 g > n，镜像轴为水平轴（内部图案执行上下镜像）。
3. 将内部图案沿确定的轴反射到空白的另一半，反射副本保持原色。
4. 边框（包括彩色段和灰色段）保持不变。

**关键洞察**：边框装饰不是纯美学元素——彩色段与间隙的长度比是一条编码指令。仅看单个示例时，镜像轴方向可以用其他假设解释（如"总是左右镜像"或"图案在哪半边就往另一半镜像"），需对比段间比不同的多个示例才能确认编码规则。

## 新题 6：双源同心生长与异或干涉

**组合逻辑**：[等距对角种子 → 同心生长](已有原语) × 2 组 → [逐像素异或合并](创新：两组独立生长的同心图案进行空间异或，产生干涉纹样)

**来源原语**：生长(grow) ← 5c2c9af4；同心方框层(concentric_layer) ← 5c2c9af4/85c4e7cd；种子像素(seed_pixel) ← 5c2c9af4；等距对角排列(equi_diag_array) ← 5c2c9af4；间距决定同心重复(spacing_concentric_repeat) ← 5c2c9af4；异或(xor) ← 3428a4f5；逐像素异或输出(pixelwise_xor_output) ← 3428a4f5

**依赖链**：两组种子独立生成各自的同心方框图案（两个并行的生长过程），然后在同一画布上进行空间叠加。叠加规则不是简单覆盖，而是 XOR：仅单方占据的像素保留该方颜色，双方都占据的像素归为黑色。干涉纹样不可从任一组种子单独推导——它是两组生长图案在空间中交互的涌现结果。

两组不同颜色的对角种子各自生长出同心方框图案，然后在空间重叠处执行异或合并：仅一方有色则保留，双方都有色则归黑。

**输入结构**：约 17x17 的黑(0)背景网格。包含两组种子像素，每组 3 个同色像素排列在 45 度对角线上，组内像素等间距。第一组颜色为红(2)，第二组颜色为蓝(1)。两组的中心像素（每组 3 个中居中的那个）位于网格的不同位置，且两组的对角间距 d 可以不同（例如第一组 d=2，第二组 d=3）。生成约束：两组生长的同心方框在网格范围内至少有 4 个像素重叠；两组的中心像素相距足够远，使得各自至少能生长出 2 层同心方框。

**规则**：
1. 对每组 3 个对角种子，识别中心像素（居中的那个）和等间距 d。
2. 从第一组中心像素出发，以间距 d1 为周期向外生长同心方框边框（正方形轮廓），框边平行于网格轴。第一层方框的半边长为 d1（中心到边的切比雪夫距离），第二层为 2*d1，依此类推，直到方框完全超出网格范围。方框颜色为该组的颜色红(2)。
3. 对第二组执行相同操作，间距 d2，颜色蓝(1)。
4. 在输出网格上合并两组图案（包含种子像素和所有方框像素）：
   - 某像素仅被第一组占据 → 红(2)。
   - 某像素仅被第二组占据 → 蓝(1)。
   - 某像素被两组同时占据 → 黑(0)（异或抵消）。
   - 某像素两组都未占据 → 黑(0)（背景）。
5. 原始种子像素也参与异或规则（若某种子位置被另一组的方框覆盖，则该位置变黑）。

**关键洞察**：输出中的黑色"空洞"不是背景——它们是两组同心图案恰好重叠而异或抵消的结果。干涉纹样的形状取决于两个中心的相对位置和各自的间距比，形成类似波干涉的几何图案。需对比多个示例（不同中心距、不同间距）才能确认合并规则是异或而非简单叠加或覆盖。

## 新题 7：图例编码周期印章与正交交叉变色

**组合逻辑**：[图例位置对应](已有原语) → [沿行/列周期印章](创新：标记像素决定印章重复的轴向，行标记沿行铺，列标记沿列铺) → [交叉区域变色](创新：两组正交周期印章的重叠区域变为新色)

**来源原语**：印章覆盖(stamp) ← 20fb2937；图例精灵(legend_sprite) ← 20fb2937；标记像素(marker_pixel) ← 20fb2937；位置对应(positional_mapping) ← 20fb2937；周期间隔(periodic_space) ← 8403a5d5；交叉(crossing) ← bdad9b1f；交叉点标记新色(crossing_cell_marked_new_color) ← bdad9b1f；分隔行(separator_row) ← 20fb2937

**依赖链**：图例提供精灵形状和颜色；工作区中标记像素的颜色选择对应的精灵（位置对应），标记像素的位置决定印章沿哪行或哪列周期重复。两组印章序列分别沿行和列展开，在空间中正交排列。重叠区域（交叉）染上第三种颜色，产生不属于任一单独序列的涌现标记。删除图例则无法知道印章形状；删除周期铺设则无法定位交叉；删除交叉变色则输出缺少关键特征。

两个标记像素各自对应一个图例精灵，分别沿各自所在行和列周期铺设精灵副本，正交铺设的重叠区域变为黄色。

**输入结构**：约 15x17 的网格。左侧有一列灰(5)垂直分隔列，将网格分为左侧图例面板（约 3-4 列宽）和右侧工作区（约 12-13 列宽）。图例面板包含 2 个小型实心方形精灵（每个 2x2 或 3x3），分别为红(2)和蓝(1)，上下排列，互不接触。右侧工作区为黑(0)背景，包含恰好 2 个单像素标记：一个红(2)标记和一个蓝(1)标记。两个标记不在同一行也不在同一列。生成约束：工作区宽度和高度均至少为精灵边长的 4 倍（确保至少能铺设 2 个完整周期）；两个标记之间至少间隔 2 倍精灵边长。

**规则**：
1. 通过颜色匹配，将红(2)标记对应到红(2)图例精灵，蓝(1)标记对应到蓝(1)图例精灵。
2. 以红(2)标记为中心，将红色精灵沿标记所在行向左和向右周期铺设：每个精灵副本的中心与前一个精灵副本的中心间隔 (精灵边长 + 1) 个单元格。铺设直到精灵副本完全超出工作区边界为止。精灵绘制到工作区上，超出工作区的部分裁剪。
3. 以蓝(1)标记为中心，将蓝色精灵沿标记所在列向上和向下周期铺设，间隔规则同上。
4. 先绘制所有红色精灵副本，再绘制所有蓝色精灵副本。蓝色精灵副本覆盖红色精灵副本时，被同时覆盖的像素不取蓝色，而是变为黄(4)。即：红色精灵已绘制的区域与蓝色精灵新绘制的区域重叠之处变为黄(4)。
5. 灰(5)分隔列和图例面板在输出中保持不变。

**关键洞察**：两组周期印章各自形成规则的行/列条带，但它们的正交交叉区域产生黄色标记——这是两组独立周期结构的空间干涉。仅看单个示例可能误以为黄色是手动标注的特殊位置，需对比多个示例（不同标记位置、不同精灵尺寸）才能归纳出"黄色 = 行列印章重叠"这一规则。

## 新题 8：对称补全激活隐藏列触发整列涂色与平铺

**组合逻辑**：[对称补全](已有原语) → [列激活判定](创新：补全后新增的前景像素可能激活之前无前景的列) → [含前景列整列涂色](已有原语) → [平铺](已有原语)（链式依赖：补全改变了列选择的输入，列选择改变了平铺的图案）

**来源原语**：对称补全(symmetry_completion) ← 3631a71a/47996f11；掩码像素(masked_pixel) ← 3631a71a；对称轨道(symmetry_orbit) ← 3631a71a；同轨道色填补损坏(orbit_mate_restores_damage) ← 3631a71a；平铺(tiling) ← f5b8619d；列选择(column_selection) ← f5b8619d；前景列(foreground_column) ← f5b8619d；含前景列整列涂色(fg_col_full_recolor) ← f5b8619d

**依赖链**：粉色掩码战略性地隐藏了某些列中仅有的前景像素。补全前，这些列看似纯背景列，不会被选中涂色。对称补全恢复了被隐藏的前景像素，使这些列"被激活"——从无前景列变为有前景列。激活后的列集合决定了涂色范围，涂色后的图案决定了平铺结果。删除补全步骤，部分列不被选中，输出图案不同；删除列涂色，平铺内容不同；删除平铺，输出尺寸不同。每一步的输出实质性改变下一步的输入。

先用左右对称补全恢复被粉色掩码隐藏的像素，再将所有含前景像素的列整列涂青，最后将结果 2x2 平铺输出。

**输入结构**：约 7x7 的网格，背景为黑(0)。网格具有关于垂直中轴的左右对称结构（列索引 j 和 W-1-j 的像素颜色应对称），但若干像素被粉(6)掩码替换，破坏了直接可见的对称性。非掩码的前景像素使用红(2)或绿(3)（不使用青(8)和粉(6)作为前景色）。关键生成约束：至少有一列，其所有前景像素都被粉色掩码覆盖——即该列在补全前看起来完全没有前景像素（只有黑(0)和粉(6)），但在对称补全后该列会出现前景像素。掩码像素只出现在网格的一半（例如仅在右半区），保证对称轨道伙伴中至少有一个是可见的非掩码前景色。

**规则**：
1. 识别粉(6)像素为掩码。网格关于垂直中轴具有左右镜像对称性。
2. 对每个粉(6)像素，找到其关于垂直中轴的镜像位置。将粉色像素替换为镜像位置上的颜色（该颜色必为非粉色的前景色或背景色）。
3. 补全后，检查每一列：若该列包含至少一个非背景(非 0)像素，则该列为"前景列"。
4. 在所有前景列中，将剩余的背景(0)像素涂为青(8)。前景像素保持不变。
5. 将步骤 4 的结果作为基本瓦片，进行 2x2 平铺：输出宽度 = 2 倍输入宽度，输出高度 = 2 倍输入高度，四个象限各放一份完整的瓦片副本。

**关键洞察**：粉色掩码的位置经过精心设计——它们恰好覆盖了某些列中仅有的前景像素。补全前这些列似乎是"空列"，补全后才暴露出前景，触发整列涂色。仅看补全前的网格会低估前景列的数量，导致涂色和平铺结果错误。需对比多个示例才能确认"先补全再选列"的顺序，而非"先选列再补全"。
