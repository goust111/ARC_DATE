## 新题 1：偏转射线分区洪填

**组合逻辑**：[射线延伸](已有) + [障碍偏转](已有，创新：偏转方向由最近边决定而非固定向右) → [洪泛填充](已有，创新：填色由左边界射线所有权决定) + [轮廓围合](已有，创新：轮廓由射线动态生成而非预设)

**来源原语**：射线延伸(ray_extend) ← cad67732；障碍偏转(obstacle_deflection) ← 712bf12e；洪泛填充(flood_fill) ← 782b5218；轮廓围合(contour_enclosure) ← 753ea09b

**依赖链**：源像素颜色 → 射线颜色；障碍位置 → 射线偏转路径 → 射线网络拓扑 → 背景分区形状 → 每个分区的左边界射线所有权 → 该分区的填充颜色。删除射线延伸则无分区；删除障碍偏转则分区为平凡竖条纹；删除洪泛填充则只剩射线线条无区域着色。

从顶边彩色源像素发射向下射线，遇灰色障碍偏向最近侧边后继续下行；完成的射线网络将背景分为多个区域，每个区域以其左侧最近射线的颜色洪泛填充。

**输入结构**：约 15x15 网格，黑(0) 背景。顶行（第 0 行）有 3~4 个彩色源像素，颜色从 {红(2)、绿(3)、蓝(1)、黄(4)} 中选取，彼此不同色、不相邻，均匀分布在顶行。网格内部散布 5~8 个灰(5) 障碍像素，无两个障碍在同一行，且没有障碍与任何源像素同列。生成约束：障碍分布确保每条射线至多偏转 2 次，且不同射线的路径不在偏转后交叉。

**规则**：
1. 按源像素从左到右的顺序依次处理。对每个源像素，从其正下方开始逐格向下延伸射线，将经过的背景像素涂为该源像素的颜色。
2. 若当前格正下方是障碍像素或已有射线，则在当前行向距离较近的左右侧边偏移一格（距左边界的列数 < 距右边界的列数则向左，反之向右；距离相等时向左）。若该偏移格为背景，涂色后从偏移格继续向下；若偏移格也被占据或越界，该射线终止。
3. 若正下方为背景，正常涂色继续。射线抵达网格底行后自然终止。
4. 所有射线绘制完毕后，以所有射线像素和网格四边为壁垒，识别所有 4-连通黑(0) 背景区域。
5. 对每个背景区域，在该区域最左侧像素所在列，向左搜索最近的射线像素，该射线的颜色即为该区域的填充色。若该区域左侧无任何射线（位于最左射线的左边），则保持黑(0) 不填。
6. 灰(5) 障碍像素在输出中保留原色。射线像素保留。

**关键洞察**：填充颜色不由空间距离最近的射线决定，而由"左边界所有权"决定——每个区域的颜色取决于其左侧紧邻的那条射线。两个相邻区域可能左右紧贴同一条射线但得到不同颜色，因为一个以该射线为右壁，另一个以该射线为左壁。必须对比多个示例才能排除"最近射线"或"围合射线的多数色"等替代假说。

## 新题 2：周期选择多模板印章

**组合逻辑**：[周期推断](已有) + [粗模板精细替换](已有，创新：不同列的宏单元格选择不同控制精灵体) → [印章覆盖](已有，创新：多个模板参与印章而非单一模板)

**来源原语**：周期推断(period_inference) / 周期相位对应(periodic_phase_match) ← c663677b；印章覆盖(stamp_overlay) / 粗模板精细替换(coarse_to_fine_substitution) / 控制精灵体(control_sprite) / 宏单元格模式(macro_cell_pattern) ← 5833af48

**依赖链**：底部标记行 → 周期 P → 宏单元格列号 j → 相位 j mod P → 标记颜色 → 对应控制精灵体 → 替换该宏单元格的前景像素。删除周期推断则无法确定列-精灵体映射；删除印章覆盖则无法将精灵体展开到宏单元格尺寸。

底部标记行的最小重复周期决定每列宏单元格使用哪个控制精灵体进行粗→细替换。

**输入结构**：约 18x18 网格，黑(0) 背景。左侧纵向排列 2~3 个控制精灵体，每个精灵体为填满的矩形（约 3x3），内部由青(8) 和一种"标签色"两种颜色组成（标签色各不相同，从 {红(2)、绿(3)、蓝(1)} 中选取）。精灵体之间间隔 1 行黑色。右上方为宏单元格模式区：一个矩形块由灰(5) 和青(8) 的均匀宏单元格（每个宏单元格 3x3）组成，排列为 R 行 x C 列的宏网格（R, C 各 2~4）。底部第 1 行有一行标签色标记像素，颜色从左到右以最小周期 P 重复（2 <= P <= 3，P <= 控制精灵体数量）。生成约束：宏网格的列数 C >= P+1，以保证周期可被推断。

**规则**：
1. 读取底部标记行，找到其最小重复周期 P：即满足标记行中所有非黑像素按列相位一致的最小正整数 P。
2. 将宏单元格模式区的列从左到右编号 0, 1, ..., C-1。列 j 的相位 = j mod P。
3. 底部标记行中相位为 j mod P 的颜色为某标签色 L。选取左侧标签色为 L 的控制精灵体作为该列的印章模板。
4. 对每个青(8) 宏单元格：将该列对应的控制精灵体中的青(8) 像素图案印入该宏单元格对应的 3x3 输出区域；控制精灵体中的标签色像素对应位置输出为灰(5)。
5. 灰(5) 宏单元格保持为 3x3 全灰(5)。
6. 左侧控制精灵体区域和底部标记行在输出中保持不变。

**关键洞察**：参考题 5833af48 中只有一个控制精灵体应用于全部宏单元格；此题中每列宏单元格依据底部标记行的周期相位选用不同精灵体。求解者必须同时推断周期 P 和标签色→精灵体的映射关系，二者缺一不可。单个示例中即使能看到某些列用了某精灵体，但若不推断周期就无法外推到新宏网格尺寸。

## 新题 3：同色配对门控的底锚循环填行

**组合逻辑**：[同色配对](已有，作为门控条件而非直接着色依据) + [填充](已有) + [循环填充](已有，创新：循环相位由从底部起的激活行序号决定) + [擦除](已有，创新：不匹配的标记对被擦除)

**来源原语**：同色配对(same_color_pairing) / 画布边界(canvas_boundary) / 两端同色整行填充(full_row_fill_endpoints_match) ← 22eb0ac0；循环填充(cycle_fill) / 色彩循环(color_cycle) ← 72207abc；底行锚定(bottom_row_anchored) ← 1c56ad9f；擦除(erase) ← 12422b43

**依赖链**：左右边界标记颜色比较 → 行激活/不激活 → 激活行从底到顶编号 → 编号作为色彩循环索引 → 填充颜色。删除同色配对则不知哪些行激活；删除循环填充则不知填什么颜色；删除底行锚定则循环相位无法确定。

左右边界同色配对的行被激活；激活行按从底到顶的序号从独立色彩循环中取色整行填充，不匹配的行其标记被擦除。

**输入结构**：约 12x10 网格，黑(0) 背景。若干行（5~7 行）在最左列（列 0）和最右列各有一个前景标记像素。标记颜色从 {红(2)、绿(3)、蓝(1)、黄(4)、橙(7)} 中选取。部分行的左右标记同色（3~4 行），其余行左右标记异色。网格右上角有一个小型色彩循环参考：3 个像素纵向排列，颜色从 {青(8)、灰(5)、栗(9)} 中选取且互不相同，与标记颜色完全不同。生成约束：激活行（同色配对行）数量 >= 4 以充分展示循环；色彩循环长度 <= 3。

**规则**：
1. 逐行检查：若该行最左列和最右列都有前景像素且颜色相同，则该行为"激活行"。
2. 若左右标记颜色不同，该行为"不激活行"——将这两个标记像素擦除为黑(0)，行内其他像素不变。
3. 将所有激活行按从底到顶的顺序编号：最底部的激活行编号 0，往上依次 1, 2, 3, ...。
4. 读取右上角色彩循环参考，从上到下为序列 C = [c0, c1, c2]。
5. 编号为 k 的激活行整行（列 0 到最右列，包含边界）填充为 C[k mod len(C)]，覆盖原有标记像素。
6. 右上角色彩循环参考像素在输出中保持不变。

**关键洞察**：填充颜色与标记对自身的颜色完全无关——标记色只是门控判据（同色则激活，异色则擦除），填充色来自独立的色彩循环。求解者极易陷入"匹配色 = 填充色"的陷阱。此外，循环相位从底部开始计数而非从顶部，需要对比至少两个示例才能确认方向。

## 新题 4：区域邻接驱动的涨缩

**组合逻辑**：[洪泛填充](已有，创新：用于拓扑分析而非最终着色) + [计数](已有) + [区域邻接](已有) → [生长](已有，创新：生长量由邻域区域数决定) / [收缩](已有，创新：收缩量由邻域区域数决定) + [面积最大者](已有，作为豁免条件)

**来源原语**：洪泛填充(flood_fill) / 四连通分区(four_connected_partition) ← 782b5218；计数(counting) / 区域邻接(region_adjacency) ← e681b708；生长(grow) / 收缩(shrink) / 面积最大者(largest_area) / 最大外扩余内缩(max_grow_rest_shrink) ← df978a02

**依赖链**：前景对象作壁垒 → 4-连通背景区域分区 → 每个对象的邻域区域计数 B → B >= 3 则生长 B 像素 / B <= 2 则收缩 B 像素 → 面积最大的对象在 B <= 2 时豁免收缩。删除洪泛填充则无法确定区域拓扑；删除计数则无法确定涨缩方向和幅度；删除面积最大者豁免则规则不完备。

前景对象以全部非背景像素为壁垒分割背景为多个区域；每个对象按其接触的背景区域数量决定生长或收缩，面积最大者在低邻接数时豁免收缩。

**输入结构**：约 13x13 网格，黑(0) 背景。4~5 个单色 8-连通前景对象，每个对象颜色各异（从 {红(2)、蓝(1)、绿(3)、黄(4)、橙(7)} 中选取），每个对象为不规则形状（3~7 像素，非简单矩形）。对象互不接触（任意两个对象间至少隔 1 个背景像素）。对象的分布将背景分成 3~5 个 4-连通区域。生成约束：恰好 1~2 个对象的 B >= 3，恰好 1~2 个对象的 B <= 2，且面积最大的对象的 B <= 2（以便展示豁免规则）。

**规则**：
1. 将所有前景像素视为壁垒。对黑(0) 背景做 4-连通洪泛填充，识别所有背景区域并编号。
2. 对每个前景对象，计算其"边界邻域区域数" B：与该对象的像素 4-相邻的背景像素所属的不同背景区域的数量。
3. 若 B >= 3：该对象生长。在该对象的所有与背景 4-相邻的像素中，选择"邻域区域数最高"的背景像素（即该背景像素本身与最多不同背景区域 4-相邻），将其涂为该对象颜色。重复此过程共 B 次。同分时选最上方、再选最左方的像素。
4. 若 B <= 2 且该对象不是面积最大的对象：该对象收缩。从该对象边界像素（至少有一个 4-邻居为背景）中移除 B 个像素（涂为黑(0)）。优先移除"邻背景像素数最多"的边界像素；同分时选最下方、再选最右方。
5. 若 B <= 2 且该对象是所有对象中面积（像素数）最大的：该对象保持原样，不收缩。
6. 所有对象同时（基于原始输入状态）计算涨缩结果后一次性写入输出。

**关键洞察**：一个对象是涨是缩取决于一个拓扑属性——它接触多少个独立背景区域——而非局部几何特征（形状、面积、位置）。两个形状和面积相似的对象可能因为一个在"三叉路口"处（B=3）而另一个在"死胡同"处（B=1）而命运相反。面积最大者的豁免是一个需要至少两个示例才能归纳出的隐蔽规则，因为它仅在特定拓扑条件下触发。

## 新题 5：环界投射分区与内→外图例着色

**组合逻辑**：[同心正方形层](已有) + [嵌套层序](已有，创新：层界被投射为另一区域的分隔线) → [重涂色](已有，创新：图例从几何嵌套结构隐式导出) + [网格分区](已有，创新：分区线非显式画出而由环界投射产生)

**来源原语**：同心正方形层(concentric_ring) / 嵌套层序(nesting_order) / 色沿层序循环移(colors_cycle_by_nesting) ← bda2d7a6；重涂色(recolor) / 象限对应图例颜色(quadrant_mapped_by_legend) ← 58743b76；网格分区(grid_partition) / 分隔线(separator_line) / 分区区域(partitioned_region) ← 272f95fa

**依赖链**：左半区环结构 → 环层边界行列坐标 → 投射为右半区隐式分隔线 → 右半区矩形分区 → 同时，环色内→外序列 → 分区着色图例 → 右半区前景像素重涂色。删除环结构则分区线和图例均不可知；删除投射则右半区无分区；删除重涂色则无输出变化。

左半区的同心矩形环的层界行列坐标投射到右半区形成隐式分隔线，环色从内到外构成重涂色图例。

**依赖链**：顶边源像素颜色 → 路径颜色；端点位置 → 路径转弯行列 → 路径几何 → 路径网络拓扑 → 背景分区 → 每个分区的相邻路径像素集 → 各色路径像素计数 → 多数色 → 分区填色。删除路径绘制则无分区；删除端点则路径为直线、分区平凡；删除多数色投票则填色规则不确定。

顶边源像素向下画线，遇同色端点折弯形成 L 形路径；路径网络分区背景后，每区以其相邻路径像素中出现最多的颜色洪泛填充。

**输入结构**：约 14x14 网格，黑(0) 背景。顶行有 3~4 个彩色源像素（颜色各不相同，从 {红(2)、绿(3)、蓝(1)、黄(4)} 中选取）。网格内部有与每个源像素同色的 1 个端点像素（共 3~4 个端点），端点不在顶行，不在底行，不与任何源像素同列，各端点所在行互不相同。生成约束：各 L 形路径互不交叉（某条路径的水平段不经过另一条路径的垂直段所在的列-行交点）；路径网络与网格四边共同将背景分成至少 4 个 4-连通区域；至少有一个区域的多数色投票结果与其"最近路径"颜色不同（即存在一个区域被一条长路径的大量像素包围，但该路径不是最近的）。

**规则**：
1. 对每个顶边源像素，从其正下方（第 1 行同列）开始画垂直线段，颜色为源像素颜色。
2. 垂直线段向下延伸直到到达其同色端点所在行，然后转弯：画水平线段从当前列到端点列。水平段方向由端点列相对源像素列决定（端点在右则向右，在左则向左）。水平段终止于端点位置（含端点）。
3. 若源像素无同色端点（在此题生成约束下不会发生，但作为规则完备性说明：若无端点，垂直线段延伸到底行）。
4. 所有路径绘制完毕后，以路径像素和网格四边为壁垒，对黑(0) 背景做 4-连通洪泛填充，识别所有背景区域。
5. 对每个背景区域，统计与该区域 4-相邻的所有路径像素的颜色。计算每种颜色的像素个数。
6. 该区域填充为出现次数最多的颜色（多数色）。若两种颜色出现次数相同，选择其中在该区域边界上最先出现的颜色（按从上到下、从左到右扫描该区域的 4-邻居路径像素，先遇到的颜色优先）。
7. 路径像素本身保留原色，不被填充覆盖。

**关键洞察**：每条 L 形路径的弯折位置完全由端点坐标决定，但多条路径共同构成的分区拓扑是涌现的——移动一个端点会改变所有区域的形状和边界邻接关系。填充颜色通过多数色投票决定，这意味着一个区域的颜色不仅取决于"最近"的路径，而是取决于哪条路径贡献了最多的边界接触像素。一条横跨大半个网格的长水平段可以用大量像素"压倒"一条短的近邻路径，使远处的颜色反而成为填充色。

## 新题 11：平移拼合中的障碍引导路径与通配边缘

**组合逻辑**：[平移拼合](已有，创新：碎片到目标位置的路径受障碍约束) + [边缘匹配](已有) + [通配色](已有) + [路径生长](已有，创新：路径不是输出的一部分而是用于确定碎片平移顺序) + [障碍偏转](已有，创新：障碍决定碎片滑入顺序而非像素偏转)

**来源原语**：平移拼合(translate_and_tile) / 边缘匹配(edge_matching) / 通配色(wildcard_color) / 矩形碎片(rectangular_piece) / 角标记(corner_marker) ← 446ef5d2；路径生长(path_grow) / 障碍偏转(obstacle_deflection) / 障碍块(blocker) ← 712bf12e

**依赖链**：角标记位置 → 目标矩形位置和尺寸 → 碎片必须拼成此矩形；障碍块位置 → 碎片从各自原位滑向目标时哪些先到达（无障碍阻挡的先放置）→ 放置顺序 → 边缘匹配验证 + 通配色处理 → 重叠区以后放者覆盖。删除边缘匹配则拼合不唯一；删除障碍引导路径则放置顺序不确定；删除通配色则边缘约束过严无解。

散落的矩形碎片向角标记处拼合成完整矩形；碎片的放置顺序由各碎片原位到目标位是否被灰色障碍阻挡决定，先畅通的先放；拼合处边缘需匹配，目标矩形主色为通配色。

**输入结构**：约 16x16 网格，黑(0) 背景。一个 3 像素 L 形角标记（品红(6)，2x2 缺一格，缺口指示目标矩形的角落位置）位于网格某角附近。3~4 个矩形碎片散布在网格中，每个碎片约 3x4~4x5 像素，主要由蓝(1) 像素组成（蓝(1) 为通配色），每个碎片上有 2~4 个非蓝像素（从 {红(2)、绿(3)、黄(4)、橙(7)} 中选取）。1~3 个灰(5) 障碍像素位于碎片与目标矩形之间的路径上。生成约束：碎片可以无旋转地恰好拼成目标矩形；每对相邻碎片的接触边上，非通配像素（非蓝(1)）互相匹配或对面是通配色；至少一个碎片的直线路径（从碎片中心到目标区域中心）被障碍阻挡。

**规则**：
1. 识别角标记并确定目标矩形的位置和尺寸：角标记的缺口格为矩形的一个角，矩形尺寸由所有碎片面积之和确定（拼成恰好无空隙的矩形）。
2. 确定碎片放置顺序：对每个碎片，计算从碎片中心到目标矩形中心的曼哈顿距离路径上的灰(5) 障碍数量。障碍数少的碎片先放置；障碍数相同时，距离目标更近的碎片先放。
3. 按顺序将碎片平移（不旋转）到目标矩形内的唯一匹配位置：碎片的非蓝像素必须与已放置碎片的非蓝像素在接触边上一致；蓝(1) 为通配色，与任何颜色兼容。
4. 若两个碎片有重叠区域（仅可能在通配色处）：后放置的碎片覆盖先放置的。
5. 目标矩形外的区域（包括碎片原位置）在输出中为黑(0) 背景。角标记保留。灰(5) 障碍擦除为黑(0)。

**关键洞察**：参考题 446ef5d2 中碎片拼合的位置由边缘匹配唯一确定，不涉及顺序问题。此题中障碍引入了放置顺序，而顺序影响重叠处的最终颜色——同一拼合方案在不同障碍布局下可能产生不同输出。求解者必须先解码障碍→顺序规则，再用顺序指导拼合，两步紧密耦合。

## 新题 12：粗模板多层扩展与嵌套精灵体选择

**组合逻辑**：[粗模板精细替换](已有，创新：宏单元格的嵌套深度决定替换模板) + [印章覆盖](已有) + [嵌套层序](已有，创新：嵌套结构不在环上而在宏单元格网格自身层次上) + [镜像](已有，创新：偶数层精灵体水平镜像后印章)

**来源原语**：粗模板精细替换(coarse_to_fine_substitution) / 印章覆盖(stamp_overlay) / 控制精灵体(control_sprite) / 宏单元格模式(macro_cell_pattern) ← 5833af48；嵌套层序(nesting_order) ← bda2d7a6；镜像(mirror) ← cad67732

**依赖链**：宏单元格网格 → 每个宏单元格的嵌套深度（距网格边缘的最短步数）→ 深度 mod 精灵体数 → 选择精灵体 → 奇偶深度决定是否水平镜像 → 印章替换。删除嵌套层序则选择规则不明；删除镜像则输出缺少方向性变化；删除印章覆盖则无精细替换。

宏单元格模式中，每个激活的宏单元格按其在宏网格中的嵌套深度选择对应的控制精灵体，偶数深度层的精灵体在印章前水平镜像。

**输入结构**：约 18x18 网格，黑(0) 背景。右侧有一个由灰(5) 和青(8) 组成的宏单元格模式区，宏单元格大小 3x3，排列为 4x4 或 5x5 的宏网格。青(8) 宏单元格为"激活"，灰(5) 为"非激活"。激活的宏单元格形成一个大致中心对称或连通的图案。左侧纵向排列 2~3 个控制精灵体，每个 3x3，使用不同的前景色组合（如精灵体 A 用红(2)+黑(0)，精灵体 B 用绿(3)+黑(0)，精灵体 C 用黄(4)+黑(0)），精灵体之间间隔 1 行。生成约束：宏网格足够大以使嵌套深度 >= 精灵体数量；激活宏单元格的分布使至少存在 3 种不同嵌套深度。

**规则**：
1. 在宏网格层面（不是像素层面），计算每个激活宏单元格的嵌套深度：从该宏单元格到最近的宏网格边缘的最短 4-连通步数（仅沿激活宏单元格行走）。宏网格边缘上的激活宏单元格深度为 0；向内一步为 1，依此类推。孤立的激活宏单元格（4-邻域全为非激活或边界）深度为 0。
2. 从左侧自上而下读取控制精灵体列表 S = [S0, S1, S2, ...]。
3. 嵌套深度为 d 的激活宏单元格选择精灵体 S[d mod len(S)]。
4. 若 d 为偶数：将选中的精灵体水平镜像（左右翻转）后印入该宏单元格对应的 3x3 输出区域。
5. 若 d 为奇数：将选中的精灵体原样印入。
6. 非激活宏单元格（灰(5)）的 3x3 区域保持全灰(5)。
7. 左侧控制精灵体区域在输出中保持不变。

**关键洞察**：宏网格自身具有嵌套拓扑——边缘处的激活宏单元格是"外层"，被激活宏单元格包围的是"内层"。这种嵌套不依赖于同心矩形的规则几何，而取决于激活宏单元格的连通形状。同一精灵体可能在内外层交替出现（因 mod 循环），但镜像规则使奇偶层的朝向不同，产生一种"呼吸"般的视觉节奏。求解者必须在宏尺度上做嵌套分析，再在微尺度上做精灵体选择和镜像——跨尺度的推理是此题的核心难度。
