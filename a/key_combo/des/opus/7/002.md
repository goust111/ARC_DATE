## 新题 1：面积驱动坠落与框影残留

**组合逻辑**：[erase/denoise](保留原义) → [counting/area](作为位移参数) → [slide](下移距离=面积) → [draw_frame + erase](落点生成外框，形状本体擦除)

**来源原语**：erase/delete_unsupported(7f4411dc), slide/area_determines_displacement(8e301a54), draw_frame(e2092e0c), counting(1fad071e)

**依赖链**：降噪改变每个形状的实际面积 → 面积决定下移距离 → 落点位置决定外框绘制区域 → 形状本体被擦除，仅留框影。四步之间存在信息变换：噪声像素改变面积值、面积值编码为空间位移、位移后的包围盒成为绘图参数、最终输出形态（空心框）与输入形态（实心形状）完全不同。

将散落的小形状降噪后按各自面积向下坠落，坠落终点处仅保留其包围盒外框，形状本体消失。

**输入结构**：约 16x16 的黑(0)背景网格。上半区散布 3-5 个单色 4-连通小形状（每个 3-7 像素，颜色各不相同，可用红(2)、绿(3)、黄(4)、橙(7)等）。每个形状附近有 1-3 个与其同色的孤立噪声像素（与形状不 4-连通，且自身同色 4-邻居少于 2 个）。下半区为空白背景。生成约束：每个形状降噪后的面积不超过网格剩余下方行数（即形状坠落后不会完全超出网格底部）；各形状坠落后的包围盒互不重叠。

**规则**：
1. 降噪：对每个非黑像素，计算其同色 4-邻居数。同色 4-邻居少于 2 个的像素视为噪声，设为黑(0)。
2. 计算面积：对每个降噪后存活的 4-连通单色形状，计算其像素数 A。
3. 坠落：将每个形状整体向下平移 A 行（保持列坐标不变）。超出网格底部的像素被裁剪丢弃。
4. 生成框影：在每个形状坠落后的包围盒外围绘制 1 像素厚的矩形外框，颜色与该形状相同。
5. 擦除本体：将包围盒内部（框内区域）的所有像素设为黑(0)。最终输出中每个形状仅以其颜色的空心矩形框呈现。

**关键洞察**：噪声像素与形状同色，若不先降噪，面积计算会因噪声的偶然连通而出错；最终输出只有外框没有实体，求解者需从多个示例中发现"坠落后擦除本体、保留边框"这一非显然规则。

## 新题 2：种子触发掏空开通洪泛通道

**组合逻辑**：[containment](判断种子在矩形内/外) → [hollowing](含种子矩形被掏空+开口) → [flood_fill](背景种子发起洪泛) → [erase](清除内部种子)

**来源原语**：hollowing/keep_border_erase_interior(4347f46a), flood_fill/spread_from_seed_through_connected(9edfc990), containment(4347f46a), erase(7f4411dc)

**依赖链**：种子与矩形的包含关系决定矩形是否被掏空 → 掏空操作在最近墙面打开缺口，改变网格的连通拓扑 → 背景中的种子沿新拓扑洪泛填充 → 内部种子在完成掏空使命后被擦除。种子的空间角色因其位置分裂为两种：内部种子是"钥匙"（开门但不填充），背景种子是"水源"（填充但不开门）。

矩形内部的种子使该矩形被掏空并打开缺口，背景中的种子发起洪泛填充，沿缺口灌入掏空的矩形内部。

**输入结构**：约 14x14 的黑(0)背景网格。4-6 个不重叠的单色实心矩形（每个至少 4x4），颜色各不相同（如红(2)、绿(3)、黄(4)、品红(6)等）。部分矩形（至少 2 个）内部恰好包含 1 个灰(5)像素（"内部种子"），位于矩形内部非边框位置。背景区域（矩形外部的黑色区域）中有 1-2 个蓝(1)像素（"背景种子"）。生成约束：含内部种子的矩形之间通过掏空后能形成连通路径到至少一个背景种子；不含种子的矩形作为不可穿越的阻挡体分布在路径沿线。

**规则**：
1. 识别每个实心矩形，检查其内部是否包含灰(5)像素。
2. 含灰像素的矩形执行掏空：保留 1 像素厚边框，内部全部设为黑(0)。然后在边框上打开一个 1 像素缺口——缺口位置为该矩形边框上距灰像素原始位置最近的那个边框像素（若距两面墙等距，优先选北墙，再选西墙）。移除灰像素本身（设为黑(0)）。
3. 不含灰像素的矩形保持实心不变（作为洪泛阻挡体）。
4. 从每个蓝(1)背景种子出发，沿 4-连通黑(0)单元格进行洪泛填充，将到达的每个黑(0)单元格涂为蓝(1)。填充不穿越任何非黑像素（矩形边框为阻挡，但缺口处为黑(0)可通过）。
5. 所有矩形边框保持原色不变。

**关键洞察**：同为灰(5)像素，在矩形内部时是"开门钥匙"（触发掏空并决定缺口方位），在背景中时不存在此角色；同为种子，蓝(1)背景种子发起洪泛而灰(5)内部种子不发起洪泛——两种种子的功能由空间位置（是否被矩形包含）决定，需要对比多个示例才能分辨。

## 新题 3：朝向决定镜像方式，位置排序决定槽位着色

**组合逻辑**：[orientation_mapping](缺角方向 → 镜像类型) + [sort](按输入行坐标排序) → [mirror](按类型执行翻转) → [recolor](按槽位颜色重涂)

**来源原语**：orientation_mapping/missing_corner_determines_quadrant(a61ba2ce), sort/height_ordering(31f7f899), mirror(3af2c5a8/760b3cac), recolor/slot_retains_color(31f7f899), crop(a61ba2ce)

**依赖链**：每个 L 形精灵体的缺角方向编码了它应接受的镜像变换类型（水平翻转或垂直翻转） → 精灵体按其在输入中的行位置从上到下排序，确定放置顺序 → 按序将镜像后的精灵体放入底部基线上的槽位 → 每个槽位的预设颜色覆盖精灵体的原始颜色。朝向与排序分别控制形态与位置两个独立维度，最终在槽位重涂处汇合。

L 形精灵体的缺角方向决定翻转方式，按行位置排序后依次填入底部彩色槽位并重涂为槽位颜色。

**输入结构**：约 12x14 的黑(0)背景网格。上方区域散布 3-5 个红(2)色 L 形精灵体，每个占据 2x2 包围盒中的 3 个像素（一个角为黑(0)背景），各精灵体的缺角方向不全相同（可能有左上缺、右上缺、左下缺、右下缺四种朝向中的若干种）。各精灵体在输入中的行位置（包围盒顶边行号）互不相同。网格底部有一条 1 像素高的灰(5)基线横跨全宽。基线上方紧贴 N 个等宽彩色槽位标记（N = 精灵体数量），每个槽位为 2 像素宽、1 像素高的色块，颜色互不相同（如蓝(1)、绿(3)、黄(4)、橙(7)等），从左到右排列，槽位间无间隔。

**规则**：
1. 裁剪每个 L 形精灵体至其 2x2 包围盒。
2. 判断每个精灵体的缺角方向：
   - 缺角在左侧（左上或左下缺）→ 对该精灵体执行水平翻转（左右镜像）。
   - 缺角在右侧（右上或右下缺）→ 对该精灵体执行垂直翻转（上下镜像）。
3. 按精灵体在输入中的行位置从上到下排序（包围盒顶边行号小的排前面）。
4. 将排序后的精灵体依次放入基线上方的槽位（第 1 个放最左槽位，第 2 个放次左，以此类推），精灵体底边紧贴基线。
5. 将每个放置好的精灵体重涂为其所在槽位标记的颜色。
6. 清除输入中精灵体的原始位置（设为黑(0)），保留基线和槽位标记。

**关键洞察**：缺角在左 vs 右决定水平 vs 垂直翻转——这不是朝向到象限的映射（参考题 a61ba2ce），而是朝向到变换类型的映射，需要对比不同朝向的精灵体在输出中的形态差异才能归纳出翻转规则。排序依据是输入行位置而非面积或颜色。

## 新题 4：分块压缩后按标记计数重涂前缀

**组合逻辑**：[compress/grid_partitioning](3x3 分块取主色) + [denoise/ignore_marker_dominant](压缩时忽略灰噪声) → [counting](统计含标记块的总数 N) → [recolor](压缩输出中按扫描序重涂前 N 个像素)

**来源原语**：compress/grid_partitioning(5614dbcf), denoise/ignore_marker_dominant(5614dbcf), counting/count_as_bar_length(1fad071e), recolor(31f7f899/a09f6c25)

**依赖链**：压缩时需忽略灰噪声和红标记以提取每块的主色 → 但红标记的总数在压缩前被统计并记忆 → 压缩完成后，该计数决定输出中有多少像素被重涂为红色 → 重涂的选取规则是按从左到右、从上到下的扫描顺序取前 N 个非背景像素。标记在压缩中被"忽略"（不影响主色判定），却在重涂中被"记忆"（影响输出着色），这种双重角色是核心耦合。

大网格按 3x3 分块压缩为缩略图，块内红标记被忽略但其总数决定缩略图中有多少像素被重涂为红色。

**输入结构**：约 15x15（行列数均为 3 的倍数）的网格，背景为黑(0)。网格可视为 5x5 个 3x3 块的阵列。每个块内以某种非黑非灰非红的颜色为主色（至少占 7/9 个像素），主色可选蓝(1)、绿(3)、黄(4)、品红(6)、橙(7)等。部分像素为灰(5)噪声（随机分布在块内或块边界上，每块 0-2 个灰像素）。部分块内恰好含 1 个红(2)标记像素（不是噪声，而是特殊信号）。整个网格中含红标记的块共 N 个（N 在 1-5 之间）。生成约束：压缩后的 5x5 缩略图中非黑像素数量 >= N，使重涂有足够目标。

**规则**：
1. 将网格按 3x3 块分割（共 5x5 = 25 块）。
2. 统计含红(2)标记像素的块的总数 N（每块至多 1 个红标记）。
3. 压缩：对每个 3x3 块，忽略灰(5)和红(2)像素，取剩余像素中唯一的非黑颜色作为该块的主色。若块中除灰和红外只有黑(0)，则该块压缩为黑(0)。输出为 5x5 网格。
4. 重涂前缀：在 5x5 压缩输出中，按从左到右、从上到下的扫描顺序，将前 N 个非黑像素重涂为红(2)。已经是黑(0)的位置跳过不计。
5. 其余非黑像素保持压缩后的主色，黑像素保持黑色。

**关键洞察**：红(2)标记在压缩阶段被当作噪声忽略（不参与主色判定），但其计数信息穿越了压缩边界，在输出阶段以完全不同的形式重现（不是标记原位置，而是按扫描序重涂前缀）。需要多个示例才能区分"红标记位置"和"红重涂位置"之间的间接关系。

## 新题 5：膨胀路径光晕作为隐形射线屏障

**组合逻辑**：[dilate_intersect](两条路径各膨胀 1 格取并集) → 隐形屏障（不显示在输出中） → [ray_extend](从种子像素向四方延伸射线) → [erase](移除原始路径)

**来源原语**：dilate_intersect(f1bcbc2c), ray_extend(c1990cce), erase(7f4411dc), seed_pixel(9edfc990), blocker(9edfc990), path_component(f1bcbc2c)

**依赖链**：两条路径各自的 8-邻域膨胀取并集形成一个"光晕区域" → 该区域在输出中不可见，但作为射线延伸的阻挡面 → 从种子像素发出的射线遇到光晕或网格边缘即停止 → 原始路径被擦除，输出中仅有种子和射线。路径通过不可见的中间产物（光晕）控制射线长度，是一种"隐式编码"结构。

路径的膨胀光晕形成不可见的屏障，限制种子射线的延伸距离；最终输出不包含路径本身。

**输入结构**：约 15x15 的黑(0)背景网格。恰好有 2 条橙(7)色的 4-连通、1 像素宽的路径分量（每条 5-12 像素，蜿蜒但不分岔），两条路径互不接触且间距至少 2 像素。2-4 个种子像素分布在路径之外的背景区域，每个种子颜色各不相同（可用蓝(1)、红(2)、绿(3)、黄(4)等）。生成约束：每个种子的至少一个方向上的射线会被光晕阻挡（即种子不位于远离所有路径的网格角落），种子之间的射线不会相互阻挡（种子间距足够大或方向不冲突）。

**规则**：
1. 对每条橙(7)路径分量，计算其 8-邻域膨胀（每个路径像素向周围 8 个方向扩展 1 格）。取两条路径膨胀结果的并集，记为"光晕区域"。
2. 从每个种子像素出发，向上、下、左、右四个方向逐像素延伸射线。射线颜色与种子相同。
3. 射线在以下情况停止（不包含停止点本身）：碰到光晕区域的像素、碰到网格边缘、碰到另一条已绘制的射线像素。
4. 擦除所有橙(7)路径像素（设为黑(0)）。光晕区域本身不着色，也不显示在输出中。
5. 输出中仅包含：种子像素、从种子延伸的射线、黑(0)背景。

**关键洞察**：射线在看似空旷的位置突然停止，因为阻挡它们的光晕是不可见的中间计算产物。求解者必须从射线的截断位置反推出"路径膨胀 1 格"这一隐式屏障规则，而路径本身已被擦除，需要从输入和输出的对比中还原。

## 新题 6：连通分量计数决定像素放大倍率

**组合逻辑**：[counting](统计前景连通分量数 N) → [pixel_upscale](整个网格放大 N 倍) → [flood_fill](放大后从种子块洪泛) → [erase/clip](清除放大后的种子块本身)

**来源原语**：counting(1fad071e/8e301a54), pixel_upscale(f0afb749), flood_fill/spread_from_seed_through_connected(9edfc990), erase(7f4411dc), connected_component(8e301a54)

**依赖链**：前景连通分量的数量本身成为几何变换参数（放大倍率） → 放大后种子像素扩展为 NxN 色块 → 该色块发起洪泛填充，沿放大后的背景区域扩散 → 种子色块在填充完成后被擦除，仅留洪泛痕迹。分量计数同时影响所有对象的尺寸和种子的填充范围。

统计前景连通分量数作为放大倍率，放大后的种子像素发起洪泛填充并自行消失。

**输入结构**：约 6x6 的小网格，黑(0)背景。3-5 个单色 4-连通前景形状，颜色各不相同（如红(2)、绿(3)、黄(4)等），每个形状 2-4 像素，形状之间互不 4-连通。恰好 1 个蓝(1)种子像素位于背景区域（不与任何前景形状 4-相邻）。生成约束：前景分量数 N 在 2-4 之间；放大后的网格（6N x 6N）中种子色块不被前景色块完全包围（洪泛可达一定范围）。种子像素不计入前景分量数（蓝(1)是种子标记，不是前景形状）。

**规则**：
1. 统计输入中非黑、非蓝的 4-连通前景分量数量 N（蓝(1)种子不计入）。
2. 将整个输入网格像素放大 N 倍：每个像素变为 NxN 同色块，输出尺寸为 (行数xN) x (列数xN)。
3. 在放大后的网格中，蓝(1)种子已扩展为 NxN 蓝色块。从该色块的所有像素出发，沿 4-连通黑(0)单元格进行洪泛填充，将到达的黑(0)单元格涂为蓝(1)。填充不穿越任何非黑像素（放大后的前景色块为阻挡体）。
4. 洪泛完成后，擦除原始种子位置对应的 NxN 蓝色块（设为黑(0)），仅保留洪泛扩散到的蓝像素。
5. 所有前景色块保持放大后的颜色不变。

**关键洞察**：放大倍率不是固定常数，而是由网格中对象的数量动态决定的——增减一个前景形状会改变所有对象的放大尺寸和洪泛范围。种子在放大后既是洪泛源又被最终擦除，输出中蓝色区域的形状完全取决于前景色块对洪泛的阻挡拓扑。

## 新题 7：高度排序生成连接线并按排名重涂

**组合逻辑**：[sort/height_ordering](按高度排序确定排名) → [draw_line](在排名相邻的柱顶之间画对角连线) + [recolor](按排名赋色) → [crop](裁剪到最小包围盒)

**来源原语**：sort/height_ordering(31f7f899), draw_line(f0afb749), recolor/redistribute(31f7f899), crop(3de23699/a61ba2ce)

**依赖链**：高度排序建立柱体之间的序关系 → 序关系决定哪些柱体之间画连线（排名相邻者连线，而非空间相邻） → 排名同时决定柱体的最终颜色 → 最后裁剪移除多余背景。排序结果同时控制两个输出维度（连线拓扑和颜色映射），而非仅传递给下游的单一操作。

按高度为柱形条排名，排名相邻的柱顶之间画对角连线，柱体按排名重涂为固定色序。

**输入结构**：约 12x16 的黑(0)背景网格。底部有一条 1 像素高的灰(5)基线横跨全宽。基线上方有 4-6 根单色垂直柱形条，每根宽度为 1 像素，高度互不相同（2-10 像素不等），从基线向上延伸。每根柱体颜色各不相同（可用红(2)、绿(3)、黄(4)、品红(6)、橙(7)等）。柱体之间的水平间距不等（2-4 像素）。生成约束：柱体数量不超过 6（保证排名色序在可用颜色范围内）；各柱顶之间的对角连线不会穿过其他柱体。

**规则**：
1. 按高度从矮到高为所有柱体排名：最矮 = 排名 1，次矮 = 排名 2，以此类推。
2. 对排名相邻的每对柱体（排名 k 和排名 k+1），从排名 k 的柱顶像素到排名 k+1 的柱顶像素画一条 Bresenham 直线。线的颜色为排名较小者的重涂颜色（见步骤 3）。
3. 按排名重涂柱体颜色（忽略输入中的原始颜色）：排名 1 → 蓝(1)，排名 2 → 红(2)，排名 3 → 绿(3)，排名 4 → 黄(4)，排名 5 → 灰(5)，排名 6 → 品红(6)。
4. 基线保持灰(5)不变。
5. 将输出裁剪到包含所有非黑像素的最小矩形包围盒。

**关键洞察**：连线连接的是高度排名相邻的柱体，而非空间位置相邻的柱体——一根矮柱和一根高柱可能空间紧挨，但如果排名不相邻（中间夹有其他高度的柱），则不连线。需要多个示例对比才能发现连线依据是排名邻接而非空间邻接。

## 新题 8：对称类型决定印章方向，标记邻接决定印章颜色

**组合逻辑**：[symmetry_det_color](对称类型 → 印章方向) + [adjacency + counting](标记邻居数 → 印章颜色) → [stamp](在指定方向放置镜像副本)

**来源原语**：symmetry_det_color(a09f6c25), stamp/mirror(760b3cac), adjacency/delete_unsupported(7f4411dc), counting(1fad071e), marker_pixel(760b3cac)

**依赖链**：每个形状的反射对称类型决定副本的放置方向（对称→空间） → 形状的 8-邻域中灰标记像素的数量决定副本的颜色（邻接计数→着色） → 两个独立信息通道在 stamp 操作处汇合（方向+颜色共同定义输出）。任一通道缺失都无法确定完整输出。

形状的对称类型决定在哪个方向放置镜像副本，副本的颜色由形状周围灰标记像素的数量决定。

**输入结构**：约 14x14 的黑(0)背景网格。3-4 个单色 4-连通前景形状（每个 4-8 像素），颜色均为红(2)。每个形状恰好具有一种反射对称性：水平轴对称、垂直轴对称、或对角线对称（主对角线或副对角线）。形状之间间距至少 4 像素（为副本留出空间）。每个形状的 8-邻域周围散布 0-3 个灰(5)标记像素（标记像素与形状不 4-连通，仅 8-相邻于形状的某个像素）。生成约束：每个形状在其印章方向上有足够的空白空间放置与自身同尺寸的副本；各形状的副本放置区域互不重叠。

**规则**：
1. 对每个红(2)前景形状，判断其反射对称类型：
   - 水平轴对称 → 副本放置在形状正下方（形状包围盒下方紧邻同尺寸区域）。
   - 垂直轴对称 → 副本放置在形状正右方（形状包围盒右方紧邻同尺寸区域）。
   - 对角线对称 → 副本放置在形状右下方（包围盒右下方紧邻的对角位置）。
2. 副本是原形状沿对应轴的镜像翻转（水平对称 → 上下翻转副本，垂直对称 → 左右翻转副本，对角线对称 → 沿主对角线转置副本）。
3. 计算每个形状的 8-邻域中灰(5)标记像素的总数 M：
   - M = 0 → 副本颜色为蓝(1)。
   - M = 1 → 副本颜色为绿(3)。
   - M >= 2 → 副本颜色为黄(4)。
4. 原形状保持红(2)不变。灰(5)标记像素保留在原位。

**关键洞察**：对称类型和标记数量是两个完全独立的信息维度，分别控制"在哪里放"和"用什么颜色"。求解者容易误将颜色与对称类型绑定（因参考题 a09f6c25 就是这样做的），但实际上颜色取决于局部标记数量，需要找到同类型对称但不同标记数的形状来区分。

## 新题 9：部分匹配修复与双向色彩互换标记

**组合逻辑**：[pattern_match](模板匹配识别完整副本与损坏副本) → [color_swap](损坏副本中双向互换损坏色与正确色) → [draw_frame](仅对修复过的副本画框) → [completion](补全损坏像素)

**来源原语**：pattern_match/shape_match(e2092e0c), color_swap/inverted_color_mapping(7c66cb00), draw_frame(e2092e0c), completion/implied_region_recolor(52df9849), stencil_marker(e2092e0c)

**依赖链**：模板匹配区分完好副本与损坏副本（匹配） → 损坏副本中入侵色的身份触发双向色彩互换而非单向替换（色彩互换） → 互换后的副本需补全被入侵色覆盖的位置为模板正确色（补全） → 经过修复的副本用入侵色画框标记修复痕迹（框选）。色彩互换而非简单替换是核心非显然规则。

找到模板的损坏副本，执行双向色彩互换修复，并用入侵色为修复过的副本画框。

**输入结构**：约 14x14 的黑(0)背景网格。网格一角有一个 3x3 模板区域，紧邻其右侧和下侧各有一行/列灰(5)像素形成 L 形标记（与参考题 e2092e0c 相同的标记方式）。模板内使用 2 种非背景颜色构成图案（如蓝(1)和黄(4)组成的 3x3 图案）。网格其余区域分布着该模板的 3-5 个副本：部分副本与模板完全一致（"完好副本"），部分副本中有 1-3 个像素被替换为一种"入侵色"（与模板中任何颜色都不同的颜色，如红(2)）——这些是"损坏副本"。每个损坏副本的入侵色相同，但被替换的位置可以不同。生成约束：每个副本周围有至少 1 像素的背景间距（为画框留出空间）；入侵色在整个网格中仅出现在损坏副本内部。

**规则**：
1. 从灰(5) L 形标记处读取 3x3 模板图案。
2. 在网格中定位所有与模板完全匹配的 3x3 区域（完好副本）——不做任何修改。
3. 定位所有与模板部分匹配的 3x3 区域（损坏副本）：恰好有 1-3 个位置的颜色与模板不同，且不同位置的颜色均为同一入侵色。
4. 对每个损坏副本执行双向色彩互换：
   - 将副本中所有入侵色像素替换为该位置在模板中的正确颜色（修复损坏）。
   - 同时，将副本中所有与入侵色位置的模板正确颜色相同的其他像素替换为入侵色。即：如果位置 (i,j) 被入侵色覆盖，模板该位置本应是蓝(1)，则该副本中所有蓝(1)像素变为入侵色，所有入侵色像素变为蓝(1)。若损坏位置涉及多种模板颜色，依次对每种颜色执行互换，先处理在模板中出现次数较少的颜色。
5. 对每个经过修复的损坏副本，在其 3x3 区域外围画 1 像素厚的入侵色矩形框。
6. 完好副本不画框、不修改。模板区域和灰标记保持不变。

**关键洞察**：修复不是简单地将入侵色替换回模板色——而是双向互换，导致修复后的副本虽然结构与模板一致，但配色方案发生了系统性翻转。框的颜色恰好是入侵色，暗示"修复留下了痕迹"。需要对比完好副本和修复副本的颜色差异才能发现互换规则。
