## 新题 1：标记导向多方位重力

**组合逻辑**：[颜色匹配边/color_matches_side](创新：从单像素移动扩展为整体精灵滑动方向选择) + [滑动/sliding + 碰撞阻挡/collision_block] + [重力沉降/gravity_settle]（标注：颜色匹配边已有，滑动已有，创新在于标记像素作为方向指令嵌入精灵内部控制个体滑动方向）

**来源原语**：颜色匹配边/color_matches_side（d687bc17）、滑动/sliding + 碰撞阻挡/collision_block + 重力沉降/gravity_settle（d282b262）、标记像素/marker_pixel（dbc1a6ce, d687bc17）、边框/frame（d687bc17）

**依赖链**：边框四侧颜色定义四个方向标签 → 每个精灵内嵌的标记像素颜色决定该精灵的滑动方向 → 精灵之间和精灵与边框之间的碰撞阻挡决定终止位置 → 最终布局取决于初始空间关系与各自方向的交互

每个内部精灵根据其嵌入标记像素的颜色匹配边框某侧，整体朝该侧滑动直到碰撞停止。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格最外圈为一像素宽的矩形边框，四侧各用一种不同颜色：上侧红(2)、下侧蓝(1)、左侧黄(4)、右侧绿(3)，四个角像素为背景色。边框内部有 3~5 个互不重叠的小型 4-连通单色精灵（3~6 像素），精灵主体为灰(5)。每个精灵内部恰好有一个像素被替换为边框四侧颜色之一（红/蓝/黄/绿），作为方向标记。生成约束：同方向的精灵在该方向上的投影互不重叠（保证滑动路径唯一确定）。

**规则**：
1. 识别边框四侧颜色。每个精灵内嵌的彩色标记像素指定其滑动方向：红(2)→向上，蓝(1)→向下，黄(4)→向左，绿(3)→向右。
2. 将每个精灵视为刚体（保持内部形状和颜色不变），沿指定方向逐格滑动。
3. 精灵在碰到边框内侧或另一个已停止精灵时立即停止（4-连通邻接即视为碰撞）。
4. 处理顺序：按距目标边框侧的距离由近到远排序（距离定义为精灵边界框到目标侧边框的最近像素距离）；距离相同时按行优先、列优先的扫描序处理。较近的精灵先移动并固定，成为后续精灵的障碍。
5. 标记像素保留在精灵内部，不擦除。

**关键洞察**：标记像素不是独立移动的单像素对象（与 d687bc17 不同），而是嵌入在精灵体内的方向指令；滑动方向不统一（与 d282b262 的单一重力方向不同），由每个精灵自己的标记颜色独立决定，因此不同精灵可能相向运动并相互阻挡。

## 新题 2：转置触发区域填充

**组合逻辑**：[镜像/reflect + 沿主对角线转置](保留) + [区域填充/flood_fill](创新：填充由转置后种子像素的新位置触发) + [连通分量检测/connected_component_detection]（标注：转置已有，区域填充已有，创新在于转置改变种子与封闭区域的从属关系从而决定哪些区域被填充）

**来源原语**：镜像/reflect + 对角对称/diagonal_symmetry + 沿主对角线转置/transpose_along_diagonal（9dfd6313）、区域填充/flood_fill（1190bc91）、连通分量检测/connected_component_detection（12eac192）、分隔线/separator_line（e3fe1151）

**依赖链**：灰色墙壁将网格划分为多个封闭区域，种子像素位于部分区域内 → 转置操作同时改变墙壁结构和种子位置 → 转置后种子落入的新封闭区域被该种子颜色填充 → 未获得种子的区域保持背景色

将方阵沿主对角线转置后，种子像素落入的封闭区域被该种子颜色填充，未获种子的区域保持空白。

**输入结构**：一个 N x N 的方阵（N 约 9~13），背景为黑(0)。主对角线上所有像素为灰(5)，此外灰色还形成若干条单像素宽的水平或垂直墙壁线段（墙壁端点连接到主对角线或网格边缘），将网格内部划分为多个封闭的 4-连通背景区域。灰色墙壁关于主对角线不对称（转置后墙壁结构会改变，产生不同的区域划分）。散布 3~5 个单像素的彩色种子（使用红(2)、蓝(1)、绿(3)等不同颜色），每个种子位于某个封闭区域内的背景像素上。生成约束：转置后每个种子的新坐标不落在灰色像素上；转置后形成的新封闭区域中，至少一个区域不含任何种子，至少一个区域恰含一个种子；每个新区域至多获得一个种子。

**规则**：
1. 对整个 N x N 网格执行主对角线转置：将坐标 (r, c) 的像素移到 (c, r)。
2. 转置后，灰色结构形成新的墙壁布局，将网格分割为新的 4-连通背景封闭区域。
3. 对每个转置后位于背景像素上的彩色种子，用该种子的颜色对其所在封闭区域执行 4-连通 flood fill（仅覆盖黑(0)像素，灰色墙壁不被覆盖）。
4. 转置后没有种子落入的封闭区域保持黑(0)不变。
5. 若转置后某种子恰好落在灰色墙壁像素上（生成约束排除此情况，但规则完备性要求说明），该种子消失，不触发填充。

**关键洞察**：转置不仅是几何对称操作（如 9dfd6313 中的简单矩阵转置），还通过同时改变墙壁拓扑和种子位置来重新分配"谁填充谁"——同一种子在转置前后可能属于完全不同形状和大小的区域，需要从多个示例中归纳出转置而非其他变换。

## 新题 3：投射选择互补合并

**组合逻辑**：[投射/project](创新：投射结果用于选择参与合并的副本而非着色) + [补全/complete + 对齐合并取并集/align_merge_union + 各副本互补缺失/copies_complement] + [擦除/erase]（标注：投射已有，补全已有，创新在于投射作为选择机制决定哪些部分副本参与互补合并）

**来源原语**：投射/project + 碰撞阻挡/collision_blocking + 边界像素投射目标/border_projected_to_target（1f642eb9）、补全/complete + 对齐合并取并集/align_merge_union + 各副本互补缺失/copies_complement（f8cc533f）、标记像素/marker_pixel（dbc1a6ce）、目标对象/target_object（1f642eb9）、干扰对象/distractor_object（23b5c85d）

**依赖链**：边界蓝色标记向内投射射线 → 射线命中某个红色精灵的边界框 → 被命中的精灵被选中参与合并 → 未命中的精灵是干扰项被擦除 → 选中精灵的掩码对齐取并集得到完整模板 → 完整模板回填到每个选中位置

边界标记投射命中的部分精灵被选中参与互补合并，未命中的干扰精灵被擦除，合并后的完整模板回填到每个选中位置。

**输入结构**：约 15x18 的黑(0)背景网格。网格内散布 4~6 个红(2)的小型 4-连通精灵（4~8 像素），它们是同一个模板掩码的不完整副本，各自缺失不同部位的像素。网格四条边界上（第 0 行、最后一行、第 0 列、最后一列）有若干单像素的蓝(1)标记。每个边界标记沿垂直于所在边界的方向（上边→向下，下边→向上，左边→向右，右边→向左）投射射线，射线路径上恰好能进入某个红色精灵的边界框。部分红色精灵不被任何射线命中，作为干扰项。生成约束：被命中的精灵集合的像素并集恰好覆盖完整模板的所有像素（不多不少）；干扰精灵的像素集合是被选中精灵并集的真子集（不提供新像素信息）；所有精灵的边界框尺寸相同且互不重叠；每个蓝色标记的射线路径上恰好只有一个精灵的边界框。

**规则**：
1. 对每个边界蓝(1)标记，沿垂直于边界的方向向内投射射线，直到射线进入（首次接触）某个红色精灵的边界框。标记该精灵为"选中"。同一精灵可被多条射线重复命中，仍计为一个。
2. 将所有选中精灵的掩码裁剪到各自边界框，对齐到统一的左上角，取像素并集，得到完整模板掩码。
3. 在每个选中精灵的原始位置，以完整模板（左上角对齐该精灵边界框左上角）绘制红(2)像素，补全缺失部分。
4. 将所有未选中的干扰精灵擦除（其像素变为背景色黑(0)）。
5. 蓝(1)边界标记保留不变。

**关键洞察**：投射不再是将标记颜色画到目标表面（如 1f642eb9），而是作为筛选机制决定哪些不完整副本参与互补合并。干扰精灵的像素看似也能贡献信息，但因未被投射选中而必须被排除——需要从示例中发现投射选择这一隐蔽规则。

## 新题 4：跨区域频率排序

**组合逻辑**：[排序/sorting](创新：排序键由跨区域全局频率统计决定而非局部属性) + [分隔线/separator_line + 矩形区域/rect_region](保留) + [颜色多重集相同/same_color_multiset](创新：多重集统计不用于补全缺失而用于定义排序键) + [计数/counting]

**来源原语**：排序/sorting + 翻转顺序/reverse_order + 堆叠/stack（e21a174a）、分隔线/separator_line + 矩形区域/rect_region + 颜色多重集相同/same_color_multiset（e3fe1151）、计数/counting（e3fe1151）、填充/fill（e3fe1151）

**依赖链**：灰色十字分隔线将网格分为四个区域 → 统计全部四个区域中每种颜色的总出现条数 → 全局频率排名作为排序键 → 每个区域内部的彩色条按此全局排名重新排列垂直顺序

十字分隔的四个区域内，各区域的彩色水平条按跨区域全局颜色频率从上到下重新排序。

**输入结构**：约 13x13 的网格，背景为黑(0)。一条完整的灰(5)水平线和一条完整的灰(5)垂直线交叉形成十字，将网格分为四个等大矩形区域（交叉点为灰色）。每个区域内有 3~4 条水平单色条（每条宽度等于区域宽度、高度为 1 像素），颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取。四个区域使用相同的颜色集合，但每种颜色在各区域出现的次数可以不同。各区域内彩色条之间有黑色背景行间隔（条不一定紧密排列）。生成约束：全局范围内各颜色的总出现条数互不相同（保证排序无歧义）；每个区域内同一颜色最多出现两条。

**规则**：
1. 统计四个区域中每种颜色的水平条总数（如红共 5 条、蓝共 3 条、绿共 7 条、黄共 4 条）。
2. 按总条数从多到少排列，得到全局频率排名（如绿 > 红 > 黄 > 蓝）。
3. 在每个区域内，将该区域拥有的彩色条按全局频率排名从上到下重新排列：频率最高的颜色排在最上方，频率最低的排在最下方。
4. 重排后的条紧贴区域顶部逐行排列，条间无间隔。区域下方剩余空间填充黑(0)背景。
5. 区域内原有的每种颜色条数不变，仅调整垂直排列顺序。
6. 灰(5)分隔十字保持不变。

**关键洞察**：排序键不是每个区域内部的局部属性（如 e21a174a 中按空间位置排序），也不是颜色编号的数值大小，而是需要跨越分隔线统计全部四个区域的颜色条数才能确定的全局频率——单看任何一个区域无法推断正确的排序顺序。

## 新题 5：嵌套层拆解为印章模板

**组合逻辑**：[嵌套矩形层/nested_rect_layer + 嵌套层次/nesting_hierarchy](创新：剥离出的每层环形形状作为独立印章模板) + [印章覆盖/stamp_overlay + 空位接受印章/empty_accepts_stamp](创新：槽位通过内部尺寸匹配对应层) + [形状匹配/shape_matching]

**来源原语**：嵌套矩形层/nested_rect_layer + 嵌套层次/nesting_hierarchy + 颜色序列逆转/color_sequence_reversed（8dae5dfc）、印章覆盖/stamp_overlay + 空位接受印章/empty_accepts_stamp + 支撑签名匹配/support_match（e5062a87）、裁剪/crop（1cf80156）、实心矩形/solid_rectangle（23b5c85d）

**依赖链**：逐层剥离嵌套矩形 → 每层产生一个环形掩码（最内层为实心矩形）和对应颜色 → 灰色空框的内部尺寸与某层外部尺寸匹配 → 将该层的环形掩码以该层颜色填入对应灰色框内

逐层剥离嵌套矩形得到不同尺寸的环形掩码，每层颜色填入网格中内部尺寸匹配的灰色空矩形框内。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格左侧有一个嵌套矩形结构，由外到内依次为不同颜色的均匀一像素宽环形层（如最外层红(2)环、中层蓝(1)环、最内层绿(3)实心矩形），共 3~4 层。嵌套矩形各层的外部尺寸分别为例如 9x7、7x5、5x3、3x1（每层向内缩一像素）。网格右侧散布 3~4 个灰(5)单像素宽空心矩形框（内部为黑色背景），灰色框之间互不重叠。每个灰色框的内部空间尺寸（高度 x 宽度）恰好等于嵌套矩形中某一层的外部尺寸。生成约束：灰色框数量等于嵌套矩形层数；每种尺寸恰好出现一个灰色框，形成一一对应。

**规则**：
1. 从嵌套矩形的最外层开始逐层剥离：第 k 层的掩码 = 第 k 层外边界矩形区域减去第 k+1 层外边界矩形区域（像素差集），形成一个一像素宽的环形。最内层为实心矩形。记录每层颜色和外部尺寸（高 x 宽）。
2. 对每个灰色空心框，测量其内部空间的高度和宽度。
3. 将每个灰色框的内部尺寸与嵌套矩形各层的外部尺寸匹配。
4. 在匹配的灰色框内部，以对应层的颜色绘制该层的掩码（环形或实心矩形），居中于框内部空间（因尺寸恰好吻合，无需调整）。灰色框线保留不变。
5. 嵌套矩形源结构保留不变。

**关键洞察**：嵌套矩形不是在原位反转颜色顺序（如 8dae5dfc），而是被拆解为独立的几何模板，每个模板通过尺寸匹配寻找自己的目标槽位——空间嵌套关系被解构为尺寸配对关系。需要同时理解剥离机制和尺寸匹配规则才能求解。

## 新题 6：连线分割区域着色

**组合逻辑**：[连线/connect + 同行列对齐/row_col_aligned](创新：连线形成拓扑边界而非视觉连接) + [连通分量检测/connected_component_detection + 区域填充/flood_fill] + [计数/counting + 面积阈值筛选/area_threshold_filter](创新：面积最小的封闭区域被选中着色)

**来源原语**：连线/connect + 同行列对齐/row_col_aligned + 相邻标记间填充/fill_between_markers（dbc1a6ce）、连通分量检测/connected_component_detection + 面积阈值筛选/area_threshold_filter（12eac192）、区域填充/flood_fill（1190bc91）、标记像素/marker_pixel（dbc1a6ce）、重涂色/recolor（12eac192）

**依赖链**：同行/同列的红色标记之间画连线 → 连线网络将背景分割为多个 4-连通封闭区域 → 计算各区域面积 → 面积最小的唯一区域被涂为绿色

标记间的水平和垂直连线将网格分割为封闭区域，面积最小的封闭区域被涂色。

**输入结构**：约 12x12 的网格，背景为黑(0)。散布 6~10 个红(2)标记像素，部分标记与其他标记同行或同列。标记之间除了行列对齐关系外无其他前景元素。生成约束：标记间的水平和垂直连线完成后，连线网络（包含标记像素本身）将网格背景分割为至少 3 个 4-连通封闭区域；存在唯一面积最小的区域（无并列）；连线网络完全连通（所有红色像素通过连线 4-连通相连）。

**规则**：
1. 在每一行中，找到该行所有红(2)标记的列坐标并排序，在相邻标记之间（不含端点标记本身，因为端点已是红色）的所有背景像素上画红(2)线段。
2. 在每一列中，同样找到该列所有红(2)标记的行坐标并排序，在相邻标记之间的背景像素上画红(2)线段。
3. 连线完成后，红色线网（包括标记和连线）将网格的黑色背景分割为若干 4-连通区域。
4. 计算每个 4-连通背景区域的像素面积。
5. 将面积最小的唯一区域的所有像素重涂为绿(3)。其余背景区域保持黑(0)。
6. 红色线网保留不变。

**关键洞察**：连线的目的不是视觉连接标记对（如 dbc1a6ce 中的线段连接），而是构建拓扑边界来划分封闭区域——连线图案的几何形状决定了哪些区域被围出以及哪个最小，这需要全局分析连线形成的封闭网络结构，而非逐对分析标记。

## 新题 7：精灵滑移后原位图案互换

**组合逻辑**：[滑动/sliding + 碰撞阻挡/collision_block](保留) + [图案替换/pattern_swap + 同步替换/simultaneous_replacement](创新：滑移腾出的原位用于放置互换图案) + [透明叠加/transparent_overlay + 图层优先级/layer_priority](创新：滑移后位置覆盖互换图案)

**来源原语**：滑动/sliding + 碰撞阻挡/collision_block + 重力沉降/gravity_settle + 画布边界/canvas_boundary（d282b262）、图案替换/pattern_swap + 同步替换/simultaneous_replacement + 同尺寸边界框/same_size_bounding_box（3391f8c0）、透明叠加/transparent_overlay + 图层优先级/layer_priority（6a11f6da）、精灵体/sprite（e21a174a）

**依赖链**：记录所有精灵的原始位置 → 所有精灵同时向右滑动至碰撞停止 → 每个精灵的原始位置用另一颜色的精灵掩码模板填充（图案互换）→ 滑动后位置的精灵在上层覆盖可能重叠的填充图案

精灵右移后，每个精灵的原始位置用另一颜色的精灵掩码填充，重叠处滑移后的精灵优先显示。

**输入结构**：约 14x10 的网格，背景为黑(0)。恰好有两种前景颜色：红(2)和蓝(1)。每种颜色形成 2~3 个相同掩码的精灵副本（同色精灵形状完全相同）。红色精灵掩码和蓝色精灵掩码的边界框尺寸相同（如均为 3x3），但形状不同。精灵分布在网格中部和左侧，右侧留有足够空间。生成约束：所有精灵的边界框行范围互不重叠（即不同精灵占据不同的行段，保证水平滑动无跨行碰撞歧义）；每个精灵向右滑动后不超出画布右边界。

**规则**：
1. 记录每个精灵的原始位置（边界框左上角坐标）和颜色。
2. 将所有精灵视为刚体，同时向右滑动。处理顺序：最右边的精灵先固定位置，然后依次处理左边的精灵。每个精灵向右移动直到碰到画布右边界或已固定精灵的左侧。
3. 精灵滑动到新位置后，在每个红(2)精灵的原始位置绘制蓝色精灵的掩码模板（使用蓝(1)），在每个蓝(1)精灵的原始位置绘制红色精灵的掩码模板（使用红(2)）。模板左上角对齐原始边界框左上角。
4. 若滑动后的精灵像素与原始位置填充的模板像素在空间上重叠，滑动后的精灵在上层，覆盖模板像素。
5. 不重叠的区域正常显示各自颜色。

**关键洞察**：滑动不仅是空间重排（如 d282b262），还通过腾出位置为图案互换创造空间。互换不是在原位进行（如 3391f8c0），而是利用滑移留下的空隙。滑动距离直接控制原位与新位之间的重叠面积，因此改变一个精灵的初始位置会连锁影响互换可见的部分。

## 新题 8：序列外推定位加标记定向印章

**组合逻辑**：[序列外推/sequence_extrapolation + 恒定偏移平移/constant_offset_translation](保留) + [印章覆盖/stamp_overlay + 掩码变换匹配则补/transform_match_fill](创新：标记图案确定所需旋转/翻转变换) + [旋转/rotate + 镜像/mirror]（标注：外推确定位置、标记确定朝向，两条独立推理路径必须同时求解）

**来源原语**：序列外推/sequence_extrapolation + 恒定偏移平移/constant_offset_translation + 面板帧/panel_frame（351d6448）、印章覆盖/stamp_overlay + 掩码变换匹配则补/transform_match_fill + 模式匹配/pattern_match（7df24a62）、旋转/rotate + 镜像/mirror（7df24a62）、标记像素/marker_pixel（dbc1a6ce）、精灵体/sprite（e21a174a）

**依赖链**：已放置印章的位置序列呈恒定偏移 → 外推得到下一个印章位置坐标 → 该位置已有标记像素图案 → 标记图案与模板标记掩码的旋转/翻转变体匹配确定所需变换 → 将完整模板经该变换后放置在外推位置

从已有印章的位移序列外推下一个放置位置，根据该位置的标记像素确定旋转变换后放置完整印章。

**输入结构**：约 15x15 的黑(0)背景网格。有一个非对称的小型精灵模板（边界框 3x3 或 4x4，含 5~8 个像素），由填充色红(2)和标记色蓝(1)组成。标记色像素（2~3 个）构成模板内部的方向标识。网格中已有 2~3 个该模板的完整放置实例（红色和蓝色像素均存在），它们的位置（边界框左上角）呈等距排列（如每次向右偏移 4 列、向下偏移 2 行，偏移在各实例间恒定）。在按等距偏移外推出的下一个位置处，仅存在蓝(1)标记像素（其图案是模板的蓝色标记掩码经过某种旋转或反射后的变体），红(2)填充像素缺失（为背景色）。生成约束：模板的蓝色标记掩码在 8 种刚性变换（4 种旋转 x 2 种翻转）下产生的图案各不相同（保证变换可唯一确定）；外推位置完全在网格范围内；已有实例均为模板原始朝向（无旋转翻转）。

**规则**：
1. 识别所有已完整放置的模板实例（同时包含红(2)和蓝(1)像素的连通区域），记录每个实例的边界框左上角坐标。
2. 按实例位置的行优先排序，计算相邻实例之间的行偏移 dr 和列偏移 dc（应为常数）。
3. 在最后一个实例的基础上加 (dr, dc)，得到外推位置的左上角坐标。
4. 在外推位置的边界框内读取已有的蓝(1)像素图案。
5. 将模板的蓝色标记掩码分别做 8 种刚性变换（0/90/180/270 度旋转，各搭配是否水平翻转），找到与外推位置蓝色图案完全匹配的唯一变换。
6. 对完整模板（红色 + 蓝色像素）应用该变换，绘制在外推位置（左上角对齐外推坐标），红色像素覆盖背景，蓝色像素已存在故保持不变。
7. 已有的完整实例保留不变。

**关键洞察**：位置和朝向分别由两条独立的推理路径确定——位置来自序列外推（如 351d6448 的帧推断），朝向来自局部标记的变换匹配（如 7df24a62 的掩码匹配）。两者缺一不可：仅知位置不知朝向则无法正确放置，仅知朝向不知位置则无法确定在哪里放置。
