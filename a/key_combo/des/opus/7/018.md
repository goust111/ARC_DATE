## 新题 1：嵌套深度定向射线

**组合逻辑**：[bbox_containment](已有) → [encoding_map](创新：嵌套深度→方向编码) → [ray_cast](已有，作用对象和触发条件均改变)

**来源原语**：bbox_containment、connected_component（#12 9720b24f）；ray_cast、collision_stop（#9 80a900e0）；encoding_map（#1 77fdfe62、#8 b91ae062）；recolor（#4 23581191）

**依赖链**：包围框包含层级分析确定每个对象的嵌套深度 → 深度值编码为射线发射方向 → 从对象顶点沿编码方向发射射线直至碰撞停止。三个环节缺一不可：无包含分析则方向未知，无方向编码则射线无序，无射线发射则深度信息不产生可见输出。射线按深度顺序绘制，先绘制的射线成为后续射线的障碍物，引入了处理顺序依赖。

输入中嵌套于其他对象包围框内的小对象向特定方向发射射线，射线方向由嵌套层数决定。

**输入结构**：
- 网格约 14x14，背景黑(0)。
- 含 4-5 个单色 4-连通对象，每个对象颜色互不相同，使用蓝(1)、绿(3)、黄(4)、灰(5)、橙(7) 等颜色，每个对象 3-8 像素，形状为任意连通形态（非特定命名形状）。
- 对象之间像素互不相邻。部分较小对象位于较大对象的包围框内部（但不与大对象像素重叠——小对象占据大对象包围框区域内的背景空间），形成深度 0-2 的嵌套层级。
- 生成约束：无部分包含（一个对象的包围框要么严格在另一个内部，要么完全不在）；每个对象的顶端最左像素在编码方向上有至少 2 格的背景空间可供射线延伸。

**规则**：
1. 识别所有 4-连通单色非黑对象，计算每个对象的包围框。
2. 计算嵌套深度：对象 X 的深度 = 包围框严格包含 X 包围框的其他对象数量。
3. 方向编码：深度 mod 4 → {0: 上, 1: 右, 2: 下, 3: 左}。
4. 按嵌套深度从浅到深的顺序处理对象。对于每个对象，找到其最顶端像素（同行取最左列）。从该像素出发，沿编码方向逐格延伸射线：将路径上的每个背景(0)像素涂为该对象的颜色，遇到非背景像素或网格边界时停止（不涂停止位置）。
5. 先处理的射线所涂像素对后续射线而言是障碍物（非背景）。同深度对象按顶端像素的行号升序处理，行号相同则列号升序。
6. 所有原始对象像素保持不变。

**关键洞察**：射线方向不是对象自身形状或颜色的属性，而是由该对象在全局包围框嵌套层级中的位置决定；确定层级需要联合分析所有对象的空间关系。此外，处理顺序使浅层射线成为深层射线的障碍物，产生了单看局部对象无法预判的遮挡效应。

## 新题 2：对称对象定义全局镜像轴

**组合逻辑**：[symmetry + outlier_selection](已有，检测阶段) → [mirror](创新：镜像轴由检测结果的空间位置动态定义) → [translate](已有，反射即特殊平移)

**来源原语**：symmetry、outlier_selection、crop（#10 d56f2372）；mirror（#5 833dafe3、#15 4c4377d9）；translate（#13 681b3aeb）

**依赖链**：对称性检测识别唯一的"锚点"对象 → 锚点对象的对称轴成为全局反射轴 → 所有非锚点对象跨该轴反射。锚点自身不变换，它约束其余一切的变换方式。这不是"先检测再变换"的简单流水线——对称轴的位置取决于锚点对象在网格中的具体坐标，即检测结果直接编码了空间变换参数。

唯一具有垂直对称性的对象保持不动并充当镜像轴，所有其他对象跨该轴反射。

**输入结构**：
- 网格约 15x15，背景黑(0)。
- 含 3-4 个单色 4-连通对象，颜色互不相同（如红(2)、蓝(1)、绿(3)、黄(4)），每个对象 4-8 像素，形状为任意连通形态。
- 恰好一个对象的包围框裁剪后左右镜像不变（具有垂直镜像对称性）；其余对象均为非对称形状。
- 对称对象大致位于网格中部区域。
- 生成约束：网格足够宽，使得所有非对称对象的反射位置仍在网格内；各反射像素落在背景(0)上，不与对称对象或其他反射结果重叠。

**规则**：
1. 对每种非黑颜色，将该颜色的所有像素裁剪到其包围框。检测裁剪结果是否与其左右镜像相同。恰好一种颜色通过检测——该颜色的对象为"锚点"。
2. 确定锚点的垂直对称轴：其包围框的中心列，即 axis_col = floor((bbox_left + bbox_right) / 2)。
3. 对每个非锚点对象的每个像素 (r, c)，计算反射列 new_c = 2 * axis_col - c，行不变。
4. 擦除非锚点对象的原始像素（设为背景(0)），在反射位置绘制相同颜色的像素。
5. 锚点对象保持不变。
6. 若反射像素落在网格边界外，丢弃该像素。

**关键洞察**：对称对象并非被变换的目标——它是空间参照物，其几何属性（对称轴位置）动态定义了所有其他对象的变换规则；求解者必须先识别哪个对象具有对称性，再从该对象的坐标中推导出全局镜像轴。

## 新题 3：图案补全改变面积排名决定涂色命运

**组合逻辑**：[group_by_frame_color → pattern_union_completion](已有，来自 #3) → [area_ranking](已有，但排名输入被补全改变) → [recolor / erase](已有，由排名结果选择性触发)

**来源原语**：group_by_frame_color、pattern_union_completion、same_color_frames_share_motif（#3 42918530）；area_ranking（#18 a8d7556c）；pixel_upscale（#8 b91ae062）；erase（#12 9720b24f）

**依赖链**：同色边框分组 → 组内图案并集补全（改变了各组的实际像素数）→ 按补全后的图案大小排名 → 排名最高的组重涂为黄(4)，排名最低的组擦除，中间的组保留补全结果不变。核心耦合在于：补全步骤改变了像素计数，使得补全前的面积排名与补全后不同——如果跳过补全直接排名，会选错组。

将同色边框分组并补全共享图案后，按补全后的图案大小决定每组的命运：最大组升格涂色、最小组擦除、其余保留。

**输入结构**：
- 网格约 18x18，背景黑(0)。
- 含 4-6 个等大的彩色方形边框（外 5x5、内 3x3、单像素边框），按 2x3 或 3x2 网格排列，边框之间以 1 列/行背景分隔。
- 边框分 2-3 种颜色（如蓝(1)、红(2)、绿(3)），每种颜色有 2-3 个边框。
- 每个边框内部可能有若干与边框同色的像素构成部分图案。同色边框的内部图案是同一完整图案的不同子集（各自缺失不同位置）。
- 生成约束：至少存在一个颜色组，其补全后的图案像素数（每框内部着色像素数）大于另一组的补全前像素数，但小于该组的补全前像素数。即：补全操作使得排名发生逆转。

**规则**：
1. 识别所有彩色边框（单像素厚度的单色方形边界围成 3x3 内部区域的结构）。
2. 按边框颜色分组。
3. 并集补全：对每个颜色组，收集该组所有边框内部被着色的相对位置的并集，然后将并集中的所有位置填入该组每个边框的内部（使组内所有边框拥有相同的完整图案）。
4. 计算每组的"图案大小"= 补全后单个边框内部着色像素的数量（0-9 之间）。按图案大小降序排名。平局按该颜色的首个边框在光栅序（逐行从左到右、从上到下）中的出现位置升序排列。
5. 排名第 1 的组（图案最大）：将该组所有边框的全部像素（边界 + 内部着色像素）重涂为黄(4)。
6. 排名最末的组（图案最小）：将该组所有边框的全部像素擦除为背景(0)。
7. 其他中间排名的组：保留补全后的状态不变。

**关键洞察**：排名必须在补全之后进行——补全改变了各组的有效面积，使得补全前的"最大"组在补全后可能不再是最大。求解者需要先执行补全操作才能正确判断哪个组应被提升、哪个应被擦除。

## 新题 4：障碍感知的递增对角延伸

**组合逻辑**：[length_increment](已有) + [ray_cast + collision_stop](已有，碰撞对象从边界扩展为动态障碍) + [erase](创新：擦除条件由碰撞结果决定，且擦除改变后续障碍格局)

**来源原语**：diagonal_segment、same_antidiagonal、length_increment（#20 50c07299）；ray_cast、collision_stop（#9 80a900e0）；wall_barrier（#17 dd6b8c4b）；erase（#12 9720b24f、#20 50c07299）

**依赖链**：测量线段长度确定延伸量（L+1）→ 延伸时检测墙壁和其他线段的碰撞 → 完全被堵的线段被擦除 → 擦除改变了障碍地图，影响后续线段的延伸结果。处理顺序（最短优先）决定了哪些线段先尝试延伸或被擦除，这是一个迭代反馈结构，而非线性流水线。

每条对角线段尝试沿行进方向延伸比自身多一格的长度，遇墙停止；完全无法延伸的线段被擦除，可能为其他线段解除障碍。

**输入结构**：
- 网格约 12x15，背景黑(0)。
- 含灰(5)像素构成不规则墙壁障碍（不一定连通，散布于网格中）。
- 含 2-4 条对角线段，每条是沿单一对角线方向的连续同色像素串，颜色各不相同（如蓝(1)、红(2)、绿(3)），每条长度 2-4 像素。
- 每条线段有明确的行进方向：从起始端到末尾端沿对角线的方向（如左上→右下、右上→左下等）。
- 生成约束：至少一条线段的延伸端点紧邻墙壁（即第一个延伸像素就被墙壁阻挡，导致该线段被擦除）；至少一条线段可以自由延伸；至少两条线段长度不同。至少存在一种情况：线段 A 被擦除后，原本被 A 阻挡的线段 B 的延伸路径变为畅通。

**规则**：
1. 识别所有对角线段：沿主对角线或反对角线方向的同色像素极大连通串。记录每条线段的颜色、长度 L、行进方向（从第一个像素到最后一个像素的方向向量）。
2. 按长度升序处理线段。同长度按顶端像素行号升序排列，行号相同按列号升序。
3. 处理当前线段：尝试从其末端沿行进方向绘制 L+1 个新像素。逐个检查新位置：
   - 若位置在网格内且为背景(0)：涂上该线段的颜色。
   - 若位置超出网格、为墙壁灰(5)、或为其他线段/射线的像素：停止延伸（不涂该位置），结束该线段的处理。
4. 若延伸产生了 0 个新像素（第一个延伸位置就被阻挡）：擦除该线段的全部原始像素（设为背景(0)）。
5. 所有线段处理完毕后输出网格。墙壁像素始终保持不变。

**关键洞察**：处理顺序至关重要——短线段先处理，被擦除的短线段释放出空间，可能使长线段原本被阻挡的延伸路径变为畅通。求解者必须模拟迭代过程而非独立分析每条线段。

## 新题 5：十字交叉点激活封闭区域涂色

**组合逻辑**：[ray_extend + intersection_colored](已有，来自 #4，几何构造阶段) → [containment + recolor_if_hole](创新：触发条件从拓扑属性改为交叉点空间存在性) → [recolor](创新：涂色颜色由交叉点的行贡献者决定)

**来源原语**：ray_extend、row_col_intersection、intersection_colored（#4 23581191）；enclosed_region、connected_component、containment、recolor_if_hole（#11 810b9b61）；recolor、area_ranking（#18 a8d7556c）

**依赖链**：孤立种子像素生成全行全列十字线 → 不同色十字线的交叉点被标记为红(2) → 包含红标记的封闭区域被激活涂色 → 涂色颜色取决于哪个种子的行（非列）穿过该区域。四个环节环环相扣：无十字线则无交叉点，无交叉点则区域无激活信号，无区域识别则标记无作用对象，无行/列区分则涂色颜色不确定。

通过种子像素的十字线交叉产生红色标记，任何包含红色标记的封闭区域被涂为贡献了行方向穿越的那个种子的颜色。

**输入结构**：
- 网格约 14x14，背景黑(0)。
- 含 2-3 个孤立单像素"种子"，颜色互不相同（如橙(7)、青(8)），任意两个种子不在同一行或同一列。
- 含 2-3 个灰(5)像素构成的封闭边界形状。每个形状是一个 4-连通闭合环路，围成一个 3-8 像素的背景内部区域。形状之间不接触，形状不接触种子像素。
- 生成约束：至少一个封闭区域的内部包含某个"十字交叉点"位置（即该区域内部存在某个格子 (r,c)，使得 r 是种子 A 的行号且 c 是种子 B 的列号，A 与 B 颜色不同）；至少一个封闭区域内部不包含任何交叉点位置。每个包含交叉点的区域内最多只有一个种子的行穿过（即不存在两个不同种子的行号同时出现在同一个封闭区域的内部像素中）。种子像素本身不在任何封闭区域内部。

**规则**：
1. 识别所有非黑、非灰的孤立单像素（种子）。记录其颜色和坐标。
2. 对每个种子，将其所在行和列中所有背景(0)像素涂为该种子的颜色。灰(5)边界像素和其他种子像素不被覆盖。
3. 交叉检测：若某个格子在步骤 2 中被两个不同种子都要涂色（该格子同时在种子 A 的行上和种子 B 的列上，或反之），则该格子涂为红(2)。
4. 识别所有封闭区域：由灰(5)像素完全围成的 4-连通内部区域（内部像素在步骤 2-3 后可能是背景、种子色或红色）。
5. 对每个封闭区域：检查其内部是否包含至少一个红(2)像素。若包含：找到穿过该区域的种子行——即确定哪个种子的行号与该区域内部某些像素的行号相同。将该区域内所有非红像素涂为该种子的颜色。红像素保持红色。
6. 不含红像素的封闭区域：保持不变。
7. 灰(5)边界像素始终不变。

**关键洞察**：十字线的绘制不是最终目的——它产生的交叉标记充当封闭区域涂色的激活信号。决定涂色颜色时，必须区分交叉点的行贡献者和列贡献者——贡献行方向的种子决定区域颜色，这是一个需要对比多个示例才能归纳的非显然规则。

## 新题 6：压缩揭示隐藏循环移位用于预测

**组合逻辑**：[compress + block_sampling](已有，来自 #19) → [cyclic_shift + predict_next_cycle + col_fixed_color](已有，来自 #2，但作用在压缩产物上) → [pixel_upscale](已有，来自 #8，反向展开)

**来源原语**：partitioned_grid、compress、block_sampling、sparse_foreground_pixel（#19 5783df64）；cyclic_shift、predict_next_cycle、col_fixed_color（#2 e78887d1）；pixel_upscale（#8 b91ae062）

**依赖链**：大尺度分区网格中每个分区仅含一个前景像素 → 压缩后得到小网格 → 小网格中连续行呈循环左移关系，且每列有固定颜色 → 预测下一行 → 将预测结果按分区尺度展开为输出。循环模式在全尺度下不可见（前景像素分散在大网格各处），必须先压缩才能发现规律；预测在压缩空间完成后必须重新展开，三者缺一不可。

将稀疏分区网格压缩后发现隐藏的循环左移规律，预测下一行并展开为分区尺度的输出。

**输入结构**：
- 网格高度和宽度各可被块大小 B 整除（B = 3 或 4），总尺寸约 12x16 至 16x16。
- 背景黑(0)为最常见颜色。
- 网格隐式分为 R x C 的等大分区块（R 行 C 列，C = 4），每块大小 BxB。
- 每个分区块内恰好有一个非背景前景像素，其余为背景。
- 压缩后得到 R x C 的小网格。在该小网格中：每列 j 在所有行中颜色相同（列固定颜色 C_j），且第 i+1 行是第 i 行向左循环移位一个位置的结果。
- 同一列 j 的所有分区块中，前景像素的块内相对位置 (r_j, c_j) 相同（不同列可以不同）。
- R >= 3，确保至少 3 行压缩数据可供归纳循环规律。

**规则**：
1. 确定块大小 B 和分区布局 R x C。
2. 压缩：对每个分区块，提取其中唯一的非背景像素的颜色 → 得到 R x C 的压缩颜色网格。同时记录每列 j 的块内前景像素相对位置 (r_j, c_j)。
3. 观察压缩网格中的行间关系：第 i+1 行是第 i 行循环左移一位。每列 j 有固定颜色 C_j。
4. 预测下一行：将压缩网格最后一行循环左移一位。移位后第 j 列的颜色为 C_{(j+1) mod C}。
5. 输出：高度 B、宽度 C*B 的条带。第 j 个分区块（0-索引，从左到右）为 BxB 全背景，但在相对位置 (r_j, c_j) 放置一个颜色为预测第 j 列颜色的像素。

**关键洞察**：在全尺度网格中，前景像素散布各处，循环移位关系完全不可见。求解者必须先发现分区结构并进行压缩，才能在压缩空间中识别循环规律。这种"尺度变换揭示隐藏模式"的结构在参考题中不存在——参考题 #19 的压缩是终点，参考题 #2 的循环移位作用在可见精灵体上，本题将两者的结构关系嵌套在不同尺度层级中。

## 新题 7：标记消歧后按距离排序提取窗口序列

**组合逻辑**：[marker_identifies_window + max_marker_no_overlap](已有，来自 #16，检测过滤阶段) → [distance_ranked_fill](创新：排名对象从散布像素改为检测出的窗口) → [crop + assembly](已有，来自 #13，拼合对象改为排序后的窗口)

**来源原语**：marker_pixel、solid_window、marker_identifies_window、max_marker_no_overlap、center_pixel（#16 9caba7c3）；distance_ranked_fill、reachability（#17 dd6b8c4b）；translate、crop（#13 681b3aeb）

**依赖链**：红色标记像素在灰色前景材料中识别候选 3x3 窗口 → 最大标记集消歧确定哪些窗口是真正的目标 → 计算每个选中窗口中心到蓝色目标像素的曼哈顿距离 → 按距离升序将窗口裁剪排列为一行。消歧步骤决定"参与者名单"，距离排序决定"输出顺序"，两者缺一不可。

在灰色前景中检测标记标识的 3x3 窗口，消除重叠歧义后，按到目标像素的距离从近到远排成一行输出。

**输入结构**：
- 网格约 15x18，背景黑(0)。
- 含灰(5)前景材料，形成不规则连通区域。
- 多个红(2)标记像素嵌入灰色材料中。候选窗口定义为：一个 3x3 区域，其中所有 9 格非黑(0)，中心格为灰(5)，且至少含一个红(2)像素。
- 可能存在重叠候选（相邻的 3x3 区域共享部分红标记）。选中窗口 = 红像素集合不是任何其他候选红像素集合的真子集的候选。
- 一个唯一的蓝(1)像素位于背景上（不在任何灰色材料内），作为目标像素。
- 生成约束：消歧后剩余 3-5 个选中窗口。选中窗口之间无像素共享。目标像素距最近灰色材料至少 3 格。

**规则**：
1. 找到所有候选 3x3 窗口：9 格全为非黑，中心灰(5)，至少含一个红(2)。
2. 消歧：选出红像素集合为极大（不是任何其他候选红像素集合的真子集）的候选。
3. 计算每个选中窗口中心到蓝(1)目标像素的曼哈顿距离。
4. 按距离升序排列。平局按窗口中心行号升序，再按列号升序。
5. 输出：高度 3、宽度 = 3 x N（N = 选中窗口数）的新网格。从左到右按距离排名顺序放置每个窗口的 3x3 内容。窗口内所有像素保留原色（灰和红均保留）。
6. 蓝色目标像素和其余所有非窗口内容不出现在输出中。

**关键洞察**：消歧步骤物质性地改变了输出——被排除的候选窗口不出现在结果中。如果跳过消歧直接排距离，会包含伪窗口；如果跳过距离排序直接提取，窗口顺序不确定。两步都必须执行且顺序不可逆。

## 新题 8：旋转异或揭示象限着色的不对称掩码

**组合逻辑**：[rotate](已有，来自 #7) + [cell_by_cell_comparison + xor_difference](已有，来自 #6) → [corner_sets_quadrant + quadrant_member](已有，来自 #1，着色逻辑独立于前两步但三者结果在同一输出汇合)

**来源原语**：rotate、rotations_pinwheel（#7 7fe24cdd）；cell_by_cell_comparison、xor_difference、mark_differences（#6 34b99a2b）；corner_sets_quadrant、quadrant_member、corner_pixel、象限（#1 77fdfe62）；recolor（#1 77fdfe62、#16 9caba7c3）

**依赖链**：输入包含图案和四角图例像素 → 将图案（不含角像素）旋转 180° → 原图案与旋转图案逐像素异或比较 → 差异位置按所在象限涂上对应角图例的颜色，一致位置设为背景。三条独立信息流（旋转角度、差异检测方法、象限颜色映射）在输出阶段汇聚——任一缺失都无法产生正确输出。这是多源汇聚结构，非线性流水线。

将图案旋转 180 度后与原图异或，差异像素按所在象限涂上四角图例对应的颜色。

**输入结构**：
- 正方形网格，边长为偶数（如 8x8 或 10x10），背景黑(0)。
- 四个角格各有一个互不相同的非黑颜色像素作为象限图例：(0,0) = 蓝(1)，(0,W-1) = 红(2)，(H-1,0) = 绿(3)，(H-1,W-1) = 黄(4)（具体颜色因示例而异，但四角颜色互不相同且与灰(5)不同）。
- 除四角外的内部区域包含灰(5)像素构成的图案，背景为黑(0)。图案不具有 180° 旋转对称性（必有非对称特征）。
- 生成约束：原图案与 180° 旋转图案之间至少有 4 个差异位置，且四个象限中至少有两个象限包含差异位置。

**规则**：
1. 记录四角图例颜色：C_TL = (0,0) 处颜色，C_TR = (0,W-1) 处颜色，C_BL = (H-1,0) 处颜色，C_BR = (H-1,W-1) 处颜色。
2. 创建"图案网格"：将输入复制一份，四角格设为黑(0)。
3. 创建"旋转网格"：将图案网格绕中心旋转 180°。
4. 逐像素比较图案网格与旋转网格：值不同的位置为"差异格"，值相同的位置为"一致格"。
5. 构建输出（与输入同大小，初始化为黑(0)）：
   - 对每个差异格 (r, c)：
     - 若 r < H/2 且 c < W/2 → 涂 C_TL
     - 若 r < H/2 且 c >= W/2 → 涂 C_TR
     - 若 r >= H/2 且 c < W/2 → 涂 C_BL
     - 若 r >= H/2 且 c >= W/2 → 涂 C_BR
   - 一致格保持黑(0)。

**关键洞察**：输出同时编码了三种信息——旋转类型（180° 而非 90° 或镜像，需对比多示例确认）、对称性缺失的位置（异或掩码）、以及象限空间归属（角图例）。求解者必须同时推断旋转角度、比较方法和颜色映射规则，三者独立但汇合于同一输出，无法单独求解。
