## 新题 1：频率定位与条纹厚度编码的方框描边

**组合逻辑**：[计数/频率唯一性] → [条高决定框厚](创新：条纹高度不再用于构建嵌套同心方块，而是参数化描边框的厚度) → [描边](创新：框厚度由外部条纹编码决定，而非固定为 1)

**来源原语**：计数(counting)、频率唯一性(frequency_uniqueness)、最低频色定位目标(least_freq_color_locates) ← #9 (31aa019c)；色条(color_stripe)、条高决定框厚(stripe_height_as_thickness) ← #12 (45a5af55)；描边(outline)、框(frame) ← #9 (31aa019c)

**依赖链**：频率分析从散布像素中唯一确定目标像素及其颜色 → 目标颜色索引到条纹区域获取高度参数 → 以该高度为框厚围绕目标像素绘制方框

在散布像素中找到出现次数唯一的那种颜色的像素，以同色条纹的行高作为框厚度，围绕该像素绘制红色方框。

**输入结构**：
- 黑(0)背景网格，约 15x15。
- 网格左侧占据列 0-2 的区域自上而下紧密堆叠 3-4 条水平色条，每条横跨列 0-2、颜色各不相同（如红(2)高 1 行、绿(3)高 2 行、黄(4)高 3 行），色条之间无间隔。
- 网格右侧区域（列 4 以右）散布若干单像素点，使用与色条相同的颜色集合。其中大多数颜色各出现 2 次或以上，恰好一种颜色仅出现 1 次。
- 生成约束：恰好一种非黑颜色在右侧散布区域中的出现次数为 1（即频率唯一）；该颜色必须在左侧色条中有对应条；目标像素到网格边缘的距离 ≥ 对应色条高度（保证方框完整可绘）。

**规则**：
1. 统计右侧散布区域中每种非黑颜色的出现次数，找到出现恰好 1 次的颜色 C 及其像素坐标 P。
2. 在左侧色条区域中找到颜色为 C 的条纹，读取其行高 H。
3. 创建与输入同尺寸的全黑输出网格。
4. 以 P 为中心绘制一个边长为 (2H+1) 的实心红(2)正方形区域，然后将中心 1x1 像素恢复为颜色 C（即红色方框包裹着颜色 C 的中心点，框的壁厚为 H）。
5. 若方框任何部分超出网格边界，超出部分直接丢弃，仅绘制网格内的部分。
6. 左侧色条和右侧其他散布像素在输出中均不保留。

**关键洞察**：条纹高度在参考题中用于逐层构建同心方块的层厚，这里被重新解读为描边框的壁厚参数；频率分析和条纹高度两种独立编码必须交叉引用才能确定输出——仅凭频率知道"在哪"但不知道"画多大"，仅凭条纹知道"多厚"但不知道"画在哪"。

## 新题 2：散点计数参数化环形框内颜色轮换

**组合逻辑**：[计数](来自#9) → [环形连接 + 顺时针轮换](来自#5，创新：轮换步数不再固定为 1 步，由背景散点数量动态决定)

**来源原语**：计数(counting)、孤立像素(isolated_pixel) ← #9 (31aa019c)；环形连接(ring_connection)、空心方框(hollow_square)、连接线(connector_line)、内部遮罩(interior_mask)、顺时针轮换(clockwise_rotation) ← #5 (ad173014)

**依赖链**：统计背景中散布的橙色标记像素总数 N → N 成为环形拓扑上内部遮罩颜色顺时针轮换的步长

数出背景区域中橙色散点的个数 N，将环形连接的方框内部遮罩颜色沿环顺时针轮换 N 步。

**输入结构**：
- 黑(0)背景网格，约 20x20。
- 4-5 个红(2)空心方框（各边长 3-5 像素、壁厚 1 像素），由蓝(1)线段首尾相连形成一个闭合环路——每个方框恰好与两段蓝色线段的端点相邻，蓝色线段仅出现在连接方框的路径上。
- 每个方框内部（壁围起的区域）包含一个单色 4-连通遮罩图形（3-6 像素，形状各异，如阶梯形、短折线等，不同方框内形状不同），各方框内部遮罩颜色互不相同，使用绿(3)、黄(4)、灰(5)、品红(6)、栗(9)等颜色。
- 在方框和蓝色连接线之外的黑色背景区域，散布若干橙(7)单像素点（2-4 个），彼此不 4-相邻。
- 生成约束：方框数量 K ≥ 4；橙色散点数量 N 满足 1 ≤ N < K 且 N ≠ K（保证轮换不回到原位）；各方框内部遮罩颜色互不相同。

**规则**：
1. 统计黑色背景区域中橙(7)像素的总数量 N。
2. 将所有红色方框按其中心坐标相对于全部方框中心的几何重心的极角排序（以正上方为 0 度、顺时针递增），得到有序环序列 F1, F2, ..., Fk。
3. 输出保留所有红色方框壁、蓝色连接线、黑色背景和橙色散点不变。
4. 对每个方框 Fi，保持其内部遮罩的形状（像素位置）不变，但将遮罩颜色替换为环序列中前 N 个位置处方框的原始遮罩颜色：具体地，Fi 的新颜色 = F((i-1+N) mod K + 1) 原始遮罩颜色（即沿环逆时针取第 N 个方框的颜色，等价于所有颜色顺时针移动 N 步）。

**关键洞察**：橙色散点看似与环形拓扑无关的装饰物，实则其数量编码了颜色轮换的步长；参考题 #5 中轮换固定 1 步，这里需对比不同散点数量的示例才能归纳出"散点数 = 步长"的隐蔽规则。

## 新题 3：角标记颜色编码逐站印章的镜像朝向

**组合逻辑**：[角标记 + 包围框对齐](来自#1) × [印章覆盖](来自#2) × [镜像](来自#8，创新：镜像条件由角标记的对角颜色配对决定，而非源题中的边色比较) × [边色不符则翻转](来自#19，创新：从矩形边色比较泛化为角标记颜色模式判断)

**来源原语**：角标记(corner_marker)、包围框对齐(bounding_box_alignment) ← #1 (a1570a43)；印章覆盖(stamp)、锚点像素(anchor_pixel)、固定图案(fixed_pattern) ← #2 (a9f96cdd)；镜像(mirror)、裁剪(crop) ← #8 (7468f01a)；颜色匹配(color_match)、边色不符则翻转(mismatch_flip) ← #19 (846bdb03)

**依赖链**：角标记确定多个印章目标位置 → 每组角标记的对角颜色排列编码该位置处的印章变换方式 → 据此决定源图案是否需要水平镜像后再印章

将角落处的源图案印章到每个角标记矩形中心，根据各矩形左上角标记的颜色决定是否水平镜像。

**输入结构**：
- 黑(0)背景网格，约 18x18。
- 网格左上角区域放置一个小型非对称双色图案块（由绿(3)和黄(4)构成的 4-连通图形，约 3-5 像素，边界框约 3x3，左右不对称），作为印章源。
- 网格其余区域分布 2-3 组角标记集合，每组由 4 个角标记像素精确标定一个矩形区域的四角，矩形内部为黑(0)。角标记仅使用两种颜色：蓝(1)和红(2)。每组中处于同一对角线的两个角标记同色——即左上+右下同色，左下+右上同色。
- 不同矩形组的对角颜色配对可能不同：部分组"左上+右下=蓝(1)、左下+右上=红(2)"，部分组反过来。
- 所有矩形的内部尺寸相同，恰好等于源图案块的边界框尺寸。各矩形之间不重叠、不相邻。
- 生成约束：源图案块水平镜像后与原图不同（即左右不对称）；至少存在两组角标记且对角颜色配对方式不同（保证两种镜像情况都出现）。

**规则**：
1. 裁剪源图案块的最小边界框，得到印章模板 M。
2. 对每组角标记矩形：
   a. 读取左上角标记像素的颜色。
   b. 若左上角为蓝(1)：将 M 原样放入该矩形内部（左上对齐）。
   c. 若左上角为红(2)：将 M 水平镜像（列序翻转）后放入该矩形内部。
3. 输出中保留所有角标记像素。
4. 源图案块原始位置在输出中擦除为黑(0)。

**关键洞察**：角标记在参考题 #1 中仅定义目标位置，这里它们同时编码了"在哪"和"怎么变换"——对角线颜色模式是一个隐式的 1-bit 变换指令。需对比多组不同角标记颜色配对的示例才能归纳出"左上角颜色决定是否镜像"的规则。

## 新题 4：同色配对连线切割穿越的实心矩形

**组合逻辑**：[同色配对 + 连线](来自#14) → [穿越并分开/分裂](来自#7，创新：分裂不由移动矩形触发，而由连线路径的空间穿越触发) + [竖线交叉优先](来自#14，保留用于线段交叉冲突解决)

**来源原语**：标记像素(marker_pixel)、连线(draw_line)、同色配对(same_color_pairing)、行列对齐(row_col_align)、竖线交叉优先(vertical_priority_at_cross) ← #14 (40853293)；分裂(split)、实心矩形(solid_rectangle)、穿越并分开(pass_through_split) ← #7 (9f669b64)

**依赖链**：同色标记像素配对确定连线路径 → 连线路径穿过实心矩形时触发矩形沿垂直于线段方向分裂 → 线段交叉处适用竖线颜色优先规则

连接同色标记像素对画出线段，线段穿过灰色矩形时将矩形沿垂直方向切开、两半各外推一格。

**输入结构**：
- 黑(0)背景网格，约 16x16。
- 3-4 对标记像素，每对同色且共享同一行或同一列。使用蓝(1)、绿(3)、黄(4)，每种颜色恰好出现 2 个像素。
- 2-3 个灰(5)实心矩形（宽 2-4 像素、高 3-6 像素），放置在网格中。至少一条标记像素配对连线的路径必然穿过某个矩形的内部。
- 生成约束：每个矩形最多被一条线段穿过（避免多重切割歧义）；水平线段和竖直线段各至少一条；至少存在一处线段交叉（一条水平线段与一条竖直线段在某像素处重合）；矩形分裂后的两半不会超出网格边界。

**规则**：
1. 对每对同色标记像素，沿它们共享的行或列画出连接线段（含两端点），颜色为该对标记像素的颜色。
2. 若一条水平线段穿过某灰色矩形（线段的行坐标落在矩形的行范围内、线段的列范围与矩形列范围有交集）：将该矩形沿线段所在行切割为上下两部分，上半部分整体向上移动 1 格，下半部分整体向下移动 1 格，中间留出 1 格宽的间隙。间隙行内的线段像素可见。
3. 若一条竖直线段穿过某灰色矩形：类似地，沿线段所在列切割为左右两部分，左半向左移 1 格，右半向右移 1 格，留出 1 格宽间隙。
4. 线段交叉处（水平线段与竖直线段共享一个像素位置）：该像素显示竖直线段的颜色。
5. 处理顺序：先执行所有分裂操作（按矩形的左上角坐标从上到下、从左到右），再绘制所有线段（线段覆盖在分裂后的画布上）。

**关键洞察**：参考题 #7 中分裂由矩形自身运动穿越另一矩形触发，这里分裂由"画出的线条"穿越静止矩形触发——切割的位置和方向完全取决于标记像素配对的几何关系，而非矩形的运动方向。删去连线则无从知道切割位置，删去分裂则线段与矩形的交互消失。

## 新题 5：图例颜色互换重编精灵体方向路由

**组合逻辑**：[图例行内配对 + 同行颜色互换](来自#4) → [方向编码 + 色块决定输出位置](来自#10，创新：方向标记的颜色先经图例变换再编码方向，图例从装饰性重涂变为语义改写) + [拼接](来自#10，将精灵体拼接入九宫格)

**来源原语**：图例(legend)、图例行内配对(legend_row_pairing)、同行颜色互换(same_row_bidirectional_swap)、重涂色(recolor) ← #4 (0becf7df)；方向编码(direction_encoding)、着色标记(colored_marker)、精灵体(sprite)、色块决定输出位置(color_direction_determines_placement)、拼接(concatenate) ← #10 (a8c38be5)

**依赖链**：图例定义颜色双向交换规则 → 精灵体内方向标记颜色经图例交换后改变 → 交换后的新颜色重新编码目标方向 → 按新方向将精灵体放入九宫格

先用图例交换精灵体中方向标记的颜色，再按交换后的颜色确定各精灵体在输出九宫格中的放置位置。

**输入结构**：
- 黑(0)背景网格，约 15x15。
- 左上角放置一个 2x2 的图例方块，两行各含一对颜色：第一行 [红(2), 黄(4)]，第二行 [绿(3), 蓝(1)]。图例含义为红(2)↔黄(4)互换、绿(3)↔蓝(1)互换。
- 网格其余区域散布 4-8 个灰(5) 3x3 小方块（精灵体），彼此不相邻。每个精灵体的 9 个像素中，8 个为灰(5)，恰好 1 个为着色标记像素（使用红(2)、黄(4)、绿(3)、蓝(1)之一）。着色像素在方块内的位置（相对于中心）编码方向：上方=向上、右方=向右、右上=右上方，等等。中心着色则表示"中央"。
- 其中恰好一个精灵体全灰(5)（无着色像素），为空白方块。
- 生成约束：着色像素仅使用图例中出现的四种颜色；各精灵体的着色方向互不重复（包括空白方块代表的"中央"位置）。

**规则**：
1. 对每个非空白精灵体，将其内部着色像素按图例规则互换颜色：红(2)→黄(4)、黄(4)→红(2)、绿(3)→蓝(1)、蓝(1)→绿(3)。互换后的颜色保留在方块内原位置。
2. 互换后着色像素的位置（相对于方块中心）编码该精灵体的目标方向。
3. 创建一个 9x9 全灰(5)输出网格，视为 3x3 排列的九宫格（每格 3x3）。
4. 空白精灵体忽略（对应九宫格中央保持全灰）。
5. 将每个精灵体整块（含互换后的着色像素）放置到九宫格中其目标方向所指示的位置：向上→顶部中央格、右上→右上格、向右→右侧中央格，以此类推。

**关键洞察**：图例在参考题 #4 中做的是对象表面的装饰性重涂色，这里却改写了方向编码的语义——红色标记经互换变为黄色后，虽然位置不变，但若求解者忽略图例直接按原始颜色路由，会得到完全错误的输出。必须理解图例是在"重编地址"而非"重涂外观"。

## 新题 6：双侧掩码叠加后按交集分区条件重涂

**组合逻辑**：[透明叠加 + 双侧对齐 + 并集合并](来自#6) × [重涂色](创新：叠加产生三类分区——仅左、仅右、交集——各分区独立着色，着色规则由输入中的色标行编码)

**来源原语**：透明叠加(transparent_overlay)、并集合并(union_merge)、二值掩码(binary_mask)、分隔列(divider_column)、双侧对齐(bilateral_alignment) ← #6 (5d2a5c43)；重涂色(recolor) ← #4 (0becf7df)

**依赖链**：分隔列将输入拆为左右两面板 → 对齐叠加区分三类区域（仅左面板有标记 / 仅右面板有标记 / 两面板都有标记） → 底部色标行编码三类区域各自的输出颜色

将分隔列两侧的二值掩码对齐叠加，按像素属于"仅左"、"仅右"或"交集"三类分区分别涂上色标行指定的不同颜色。

**输入结构**：
- 黑(0)背景网格，行数约 12、列数约 (2W+1)，W 为每面板宽度（4-6 列）。
- 正中一列为蓝(1)分隔列，从第 0 行到倒数第 2 行完整填充（最后一行不含蓝色）。
- 分隔列左侧和右侧各为一个等尺寸面板（W 列 x (H-1) 行），面板中若干像素为黄(4)（标记像素），其余为黑(0)。
- 网格最后一行（色标行）包含三个等间距的单像素色标，从左到右依次为红(2)、绿(3)、橙(7)，其余位置为黑(0)。这三个色标分别对应"仅左面板有标记"、"仅右面板有标记"、"两面板都有标记"三种情况的输出颜色。
- 生成约束：左右面板的黄色标记存在部分重叠（对齐后同位置都有标记）和部分不重叠，保证三类分区均非空。

**规则**：
1. 移除分隔列和色标行，将左右面板按行列对齐。
2. 输出网格尺寸 = 单面板尺寸（W 列 x (H-1) 行）。
3. 对每个输出位置 (r, c)：
   - 若仅左面板 (r, c) 为黄(4)：输出该位置填充色标行第一色——红(2)。
   - 若仅右面板 (r, c) 为黄(4)：输出该位置填充色标行第二色——绿(3)。
   - 若两面板 (r, c) 均为黄(4)：输出该位置填充色标行第三色——橙(7)。
   - 若两面板 (r, c) 均为黑(0)：输出该位置为黑(0)。

**关键洞察**：参考题 #6 将两面板做简单并集并统一涂为青色；本题将叠加结果按集合论分为三个逻辑分区，各分区独立着色。色标行是隐蔽规则——它定义了三分区到输出颜色的映射，仅看叠加结构无法推断颜色选择，必须对比多个示例中色标颜色与输出的对应关系。

## 新题 7：射线汇聚落点处逐层构建同心方框

**组合逻辑**：[射线延伸 + 朝向编码方向](来自#3) → [嵌套包裹 + 逐层构建](来自#12，创新：层数和颜色序列不再由色条决定，而由射线汇聚情况决定——汇聚数量=层数，射线颜色按距离排序=层颜色序列)

**来源原语**：射线延伸(projectile_fire)、三角精灵体(triangle_sprite)、朝向编码方向(orientation_encodes_direction) ← #3 (409aa875)；嵌套包裹(nested_wrapping)、同心正方形层(concentric_square_frame)、逐层构建(layer_by_layer_build) ← #12 (45a5af55)；碰撞变色规则(collision_recolor_rule) ← #3 (409aa875)

**依赖链**：精灵体朝向确定射线方向 → 射线飞行落点成为构建中心 → 汇聚在同一落点的射线数量决定同心框层数 → 各射线源到落点的距离排序决定层颜色（近→内层，远→外层）

三像素精灵体发射射线，在每个落点处用命中该点的各射线颜色从内到外逐层构建同心方框。

**输入结构**：
- 黑(0)背景网格，约 21x21。
- 3-4 个三像素精灵体，每个由不同颜色构成（如红(2)、绿(3)、黄(4)、蓝(1)），每个精灵体为三像素直角弯折构型——两像素共线、第三像素在端点处垂直偏移一格，形成一个缺角的 2x2 区域。缺角方位编码发射方向（朝缺角对角方向发射）。
- 射线飞行距离固定为 5 格（从顶点即弯折拐角像素算起，沿发射方向直线前进 5 格）。
- 精灵体的位置和朝向经安排使得：部分落点仅被一条射线命中，至少一个落点被两条射线同时命中。
- 生成约束：所有落点距网格边缘至少 3 格（保证 5x5 同心框不越界）；落点之间间距足够大，构建的同心框互不重叠；精灵体本身不位于任何射线路径上。

**规则**：
1. 对每个精灵体，确定其顶点（弯折拐角像素）和发射方向（朝缺角对角方向），从顶点沿发射方向前进 5 格，标记落点坐标。
2. 擦除所有精灵体（原位置变为黑色）。
3. 对每个落点 L：
   a. 收集所有命中 L 的射线，按其源精灵体顶点到 L 的曼哈顿距离从近到远排序；若距离相同，按精灵体颜色编号从小到大排序。
   b. 排序后的第 1 条射线颜色填充落点中心 1x1 像素。
   c. 若有第 2 条射线，其颜色在中心外包裹一层厚度 1 的方框（整体形成 3x3 正方形）。
   d. 若有第 3 条射线，继续包裹（形成 5x5），以此类推。
4. 仅被 1 条射线命中的落点输出为 1x1 单像素。

**关键洞察**：射线汇聚的数量决定了同心框的层数——单射线落点仅为一个像素，多射线汇聚落点生长为多层同心结构。参考题 #12 从色条读取层参数，这里层参数完全由射线动力学的空间结果决定，精灵体的位置和朝向隐式编码了输出结构的复杂度。

## 新题 8：瓦片修复揭示周期性锚点驱动印章放置

**组合逻辑**：[平铺 + 补全 + 可见像素约束推断](来自#15) → [印章覆盖 + 相对坐标复制](来自#20，创新：锚点位置不在输入中直接可见，而是通过瓦片修复后才暴露出来——修复操作和锚点发现因果耦合)

**来源原语**：平铺(tiling)、补全(completion)、重复瓦片(repeating_tile)、遮挡区域(occluded_region)、可见像素约束推断(infer_from_visible) ← #15 (ca8f78db)；印章覆盖(stamp)、锚点像素(anchor_pixel)、控制像素(control_pixel)、相对坐标复制(relative_coord_copy) ← #20 (f5c89df1)；擦除(erase) ← #9 (31aa019c)

**依赖链**：可见像素推断出含红色锚点的重复瓦片周期 → 修复遮挡区域后露出被黑色覆盖的红色锚点像素 → 汇总所有红色锚点（原始可见 + 修复揭示），在每个锚点处印章源图案

先从可见像素推断重复瓦片并修复遮挡区域，修复后新出现的红色像素即为隐藏锚点，在所有锚点处印章一个源图案。

**输入结构**：
- 黑(0)背景网格，约 16x16。
- 网格上铺着一个二维重复瓦片图案，周期约 4x4，使用灰(5)、蓝(1)、绿(3)三种颜色。在每个瓦片周期内，恰好有一个固定位置的像素为红(2)——红色像素是瓦片图案本身的一部分，以周期 T 重复出现。
- 若干矩形区域被黑(0)像素覆盖（遮挡），隐藏了下方的瓦片内容（包括部分红色周期像素）。遮挡面积约占网格 20-40%。
- 网格右下角（未被遮挡的区域）放置一个独立的小型源图案（约 3x3，由黄(4)和橙(7)构成），与瓦片颜色完全不同。源图案紧邻一个红(2)像素作为参考锚点（该红色像素同时也是瓦片周期的一部分）。
- 生成约束：遮挡区域外的可见像素足以唯一推断瓦片周期（每种瓦片内颜色在可见区域都有至少一个完整周期的样本）；遮挡区域至少隐藏了 1 个红色周期像素；源图案不与任何遮挡区域重叠。

**规则**：
1. 将黑(0)像素视为未知值。根据所有可见的非黑像素（包括可见的红色周期像素和源图案像素），推断最小矩形重复周期 T。注意：源图案使用的颜色（黄(4)、橙(7)）不出现在瓦片中，推断 T 时应仅使用瓦片颜色（灰、蓝、绿、红）。
2. 用周期 T 填充所有被遮挡的黑色区域，恢复完整瓦片。此操作会揭示之前被遮挡的红(2)像素。
3. 汇总整个网格中所有红(2)像素的坐标集合 R（包括原本可见的和修复后揭示的）。
4. 以源图案旁的红(2)参考锚点为原点，计算源图案各非背景像素相对于该锚点的坐标偏移集合 D。
5. 对 R 中除参考锚点之外的每个红色像素位置 p，在 p 处按偏移集合 D 印章源图案（黄(4)和橙(7)像素覆盖该位置的瓦片颜色）。
6. 源图案和参考锚点在原位保留不变。

**关键洞察**：红色像素是瓦片周期的组成部分而非独立标记，被遮挡的红色像素在输入中不可见（显示为黑色）；不修复瓦片就不知道有多少个锚点、在哪里。修复操作和印章操作通过"锚点发现"因果耦合——前者的输出决定后者的目标集合。
