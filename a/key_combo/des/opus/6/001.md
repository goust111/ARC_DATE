## 新题 1：模板定向折叠

**组合逻辑**：[形状匹配/shape_matching](创新：匹配对象从"孔洞"变为"杆尾段轮廓") + [折叠/fold](创新：折叠方向由模板位置决定，替代原"空间大侧折入"条件) + [裁剪/crop](已有：提取杆尾段轮廓用于匹配)

**来源原语**：shape_matching, normalized_match (42f14c03); fold, hinge_marker, endpoint_marker, fixed_vs_free (230f2e48); crop (278e5215)

**依赖链**：折叠需要确定方向 → 方向取决于哪个模板与杆尾段形状匹配 → 匹配需要先裁剪出杆尾段的归一化轮廓 → 匹配到的模板的空间位置（在铰接标记的哪一侧）指定折叠的垂直方向。形状匹配不是独立筛选步骤，而是折叠操作的方向参数来源，两者不可拆分。

根据杆尾段的归一化轮廓找到匹配模板，模板相对铰接点的方位决定杆尾的折叠方向。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格中有 2~3 根红(2)直线杆（4-连通，单像素宽，长度 5~9 像素，水平或垂直放置）。每根杆上有一个灰(5)端点标记像素（位于杆的一端）和一个蓝(1)铰接标记像素（位于杆的内部，不在端点）。灰端点到蓝铰接之间的段为"固定段"，蓝铰接另一侧的红像素为"尾段"。尾段的长度在 2~4 像素之间，不同杆的尾段长度可以不同。另外，网格中散布 2~3 个绿(3)小图形（3~6 像素的 4-连通单色图形，形状各异，如折线、直角等），每个图形的归一化形状（平移归一化，不旋转不翻转）恰好与某根杆的尾段占据的像素集的归一化形状一一对应。每个绿图形位于其对应杆的铰接标记的严格某一侧（上方或下方，或左方或右方，具体指：对于水平杆，绿图形的质心在铰接标记的正上方或正下方半平面；对于垂直杆，绿图形的质心在铰接标记的正左方或正右方半平面）。生成约束：不同杆的尾段形状互不相同；每个绿模板恰好匹配一根杆的尾段；绿模板不与任何杆的像素相邻。

**规则**：
1. 对每根杆，提取其尾段（蓝铰接标记到非灰端的那一侧）占据的像素集，平移归一化为从 (0,0) 开始的坐标集。
2. 在所有绿图形中，找到归一化形状与该尾段完全相同的图形（唯一）。
3. 判断该绿图形的质心相对蓝铰接标记的方位：对于水平杆，取上/下；对于垂直杆，取左/右。
4. 擦除尾段的红像素（变为背景）。将尾段的像素以蓝铰接标记为起点，沿步骤 3 确定的垂直方向（相对于杆的主轴方向的垂直方向）逐像素重新绘制，保持长度和颜色（红）。
5. 固定段（含灰端点标记和蓝铰接标记）保持不变。绿模板图形擦除（变为背景）。
6. 各杆独立处理，处理顺序不影响结果（生成约束保证折叠后的像素不重叠）。

**关键洞察**：折叠方向不由"哪边空间大"决定，而由归一化形状匹配到的模板的空间位置编码——模板在铰接点的哪一侧，尾段就往哪一侧折。需要对比多个示例才能区分"模板定向"和"空间定向"这两种假说。

## 新题 2：周期栅栏路径

**组合逻辑**：[周期掩码/periodic_mask](创新：周期模式不用于绘制条纹，而用于定义寻路障碍行列) + [寻路/pathfinding](创新：障碍来源从局部 blocker 扩展为局部+全局两层) + [擦除/erase](已有：移除解码后的框架)

**来源原语**：periodic_mask, rectangular_frame, periodic_stripe, marker_bar (6a980be1); pathfinding, track_path, endpoint, obstacle, neighbor_exclusion, unique_safe_path (cc9053aa); erase (7b80bb43)

**依赖链**：寻路需要知道哪些轨道格不可通行 → 不可通行来自两个独立来源：(a) 橙色 blocker 的 8-邻域禁区（局部），(b) 框架内周期条纹标记的行或列上的所有轨道格（全局）→ 周期模式需要从框架结构中解码 → 解码后框架被擦除 → 剩余可通行轨道中存在唯一安全路径。周期掩码和寻路耦合在"障碍定义"这一决策节点上，而非前后串联。

从框架内的周期条纹推断出禁行/禁列，叠加局部 blocker 的邻域禁区后，在轨道图中找出两端点间的唯一安全路径。

**输入结构**：约 25x25 的网格，背景为黑(0)。网格中有一条青(8)4-连通轨道网络（多条水平和垂直线段交叉形成网格状路径，像素数约 80~120）。轨道上有恰好 2 个栗(9)端点像素（位于轨道的末端）。网格中散布 1~3 个橙(7)障碍像素（紧邻轨道但不在轨道上，或嵌入轨道中）。网格的一个角落（如右下角）有一个灰(5)单像素厚矩形边框（约 5x7 或 7x5），框内有两条平行的蓝(1)标记条（与框的长边平行，占满框内对应维度），标记条之间的区域在周期性间隔的行或列上填充红(2)像素（如每隔 2 行填充一行红），其余为黑背景。生成约束：从框内红像素的位置可唯一推断出周期间隔（周期为 2~4）和起始偏移；将该周期应用到整个网格的对应行或列后，落在这些行/列上的青轨道像素被标记为不可通行；加上橙 blocker 及其 8-邻域禁区后，两个栗端点之间恰好存在唯一的 4-连通简单路径（仅经过可通行的青/栗像素）。

**规则**：
1. 读取灰矩形框内的红像素位置，推断周期模式：确定是行周期还是列周期（由蓝标记条的朝向决定——标记条水平则为行周期，标记条垂直则为列周期），以及周期值和起始行/列编号（以框内红像素相对框内空间的位置为准，映射到全网格坐标）。
2. 将符合该周期模式的所有行（或列）标记为"禁行/禁列"。落在禁行/禁列上的青轨道像素变为不可通行。
3. 将每个橙像素及其 8-邻域内的青轨道像素也标记为不可通行。
4. 在剩余可通行的轨道图（青+栗像素中未被标记为不可通行的）中，找到两个栗端点之间的唯一 4-连通简单路径。
5. 将该路径上的青像素重涂为栗(9)。端点保持栗色。
6. 擦除灰框、蓝标记条、红周期像素（全部变为背景黑(0)）。橙障碍保持不变。

**关键洞察**：框架内的周期条纹不是要被延伸绘制到画布上（与参考题 6a980be1 完全不同），而是编码了"哪些行/列上的轨道格被封锁"的全局规则。求解者必须对比多个示例才能发现周期模式与路径可达性之间的关联，而非将条纹直接投射到输出。

## 新题 3：旋转后对角连接

**组合逻辑**：[旋转/rotate + 中心点不变/center_fixed](已有：每根条绕自身中心旋转 90 度) + [连线/connect + 对角偏移/diagonal_offset](创新：连接对象从"静态矩形对"变为"旋转后的条端点对"，连接的几何关系由旋转后的位置决定)

**来源原语**：rotate, thin_bar, center_fixed, orient_swap_keep (f0f8a26d); connect, same_color_rect_pair, diagonal_segment, diagonal_offset, diagonal_fill (342ae2ed)

**依赖链**：对角连接需要知道端点位置 → 端点位置取决于旋转后的条的位置 → 旋转改变了条的朝向和端点坐标 → 因此连接目标不是输入中可见的端点，而是必须先完成心算旋转才能确定的端点。旋转的输出是连接的输入前提，且两者作用于同一批对象（条既是旋转目标又是连接端点来源）。

将每根条绕中心旋转 90 度，然后用对角线段连接同色条对旋转后的最近对角端点。

**输入结构**：约 18x18 的网格，背景为黑(0)。网格中有 2~4 对单像素宽的前景条（4-连通，奇数长度 3~7 像素，水平或垂直放置）。每对条颜色相同，不同对颜色不同，使用红(2)、蓝(1)、绿(3)、黄(4)中的 2~4 种。同色的两根条在输入中不相邻、不共线。每根条的中心像素（奇数长度的正中像素）坐标确定。生成约束：每根条绕中心旋转 90 度后不超出网格边界；旋转后，同色两根条的端点中恰好存在一对端点具有对角偏移关系（即行差的绝对值等于列差的绝对值，且均不为 0）；旋转后不同条的像素不重叠；对角连接线段上的像素不与其他条或连接线段重叠。

**规则**：
1. 对每根条，保持其中心像素位置和长度不变，将朝向旋转 90 度（水平变垂直，垂直变水平）。擦除旋转前的像素，在新位置绘制旋转后的像素，颜色不变。
2. 对每对同色条（旋转后），找到具有对角偏移关系的那对端点（即两端点的行差绝对值等于列差绝对值）。
3. 在这对端点之间绘制 45 度对角线段（不含两个端点本身，因为端点已属于条），颜色与条相同。对角线段上的每个像素 (r, c) 满足 r 和 c 在两端点的 r 和 c 之间逐步各变化 1。
4. 各颜色独立处理，处理顺序不影响结果。

**关键洞察**：输入中同色条对的端点并不具有对角偏移关系——对角关系只在旋转之后才出现。求解者不能直接从输入几何中读出连接路径，必须先在心中完成所有条的旋转，然后才能判断哪些端点应被连接。单个示例中可能看到旋转和连接同时发生，但需要多个示例才能确认"先旋转再连接"的顺序，以及"对角偏移端点对"的选取标准。

## 新题 4：链式替换后的环色循环

**组合逻辑**：[重涂色/recolor + 链式替换/chain_replace](已有：按图例逐行替换颜色) + [循环移色/color_cycle + 反向循环/opposite_cycle](创新：循环移色作用于替换后的颜色，替换改变了哪些像素"同色"，从而改变循环的实际效果)

**来源原语**：recolor, chain_replace, two_col_legend, legend_row_order (e4888269); color_cycle, ring_object, corner_pixel, side_center_pixel, opposite_cycle, corner_side_group (46c35fc7)

**依赖链**：循环移色需要知道每个位置的当前颜色 → 当前颜色是链式替换后的结果而非输入颜色 → 链式替换改变了颜色分布，可能使原本不同色的位置变为同色，或使原本同色的位置变为不同色 → 这直接影响循环移色时"哪个颜色移到哪里"的最终视觉效果。两个操作的耦合点在于颜色状态的变换：替换改变了循环的操作数。

先按图例对环像素做链式颜色替换，再对替换后的颜色执行角位/边中反向循环。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格中有 2~3 个完整的 3x3 环（8 个前景像素围绕 1 个黑背景中心，每个环的 8 个像素使用 2~4 种颜色，颜色选自红(2)、蓝(1)、绿(3)、黄(4)、灰(5)、品红(6)）。不同环之间至少间隔 2 个像素。网格的左侧或右侧有一个 2 列 N 行（N 为 2~4）的竖直图例块，图例块与环不相邻。图例每行由左列颜色和右列颜色组成，表示"左色 → 右色"的替换规则。生成约束：图例中的替换颜色均出现在至少一个环上；链式替换后，每个环的 8 个位置仍然不全同色（至少包含 2 种不同颜色），以保证循环有可观察效果；图例的替换不产生环外影响（背景和图例本身不被替换）。

**规则**：
1. 读取两列图例，从上到下记录替换规则序列：(c1→c2), (c3→c4), ...
2. 对每个环的每个像素（不包含图例像素和背景像素），按图例行从上到下依次扫描：若当前像素颜色等于该行左列颜色，则替换为右列颜色，然后继续扫描后续行（即同一像素可被多次替换，后续行可以继续作用于已替换的颜色）。
3. 替换完成后，对每个环执行循环移色：将 4 个角位像素（左上、右上、右下、左下）的颜色顺时针循环移动一步（左上→右上→右下→左下→左上）；将 4 个边中像素（上中、右中、下中、左中）的颜色逆时针循环移动一步（上中→左中→下中→右中→上中）。
4. 图例保持不变。背景保持不变。环的中心保持黑色背景。

**关键洞察**：输出颜色既不是单纯替换的结果，也不是单纯循环的结果，而是两步操作按特定顺序复合的结果。仅凭单个示例，求解者可能误以为颜色变化全由替换完成（忽略循环），或误以为是先循环再替换。需要多个示例对比"替换后循环"与"循环后替换"的差异才能确定正确顺序。图例的链式特性（后行可修改前行的输出）进一步增加了辨别难度。

## 新题 5：邻接传色决定对接配对

**组合逻辑**：[重涂色/recolor + 邻接传色/adjacency_transfer](创新：传色结果不作为最终输出，而是作为对接配对的匹配键) + [对接拼合/docking](创新：对接配对标准从"连接点预标记"变为"传色后的颜色一致性") + [擦除/erase](已有：移除原始标记像素)

**来源原语**：recolor, adjacency_transfer, marker_pixel, neutral_mask, marker_touch_color (b7256dcd); docking, sprite, connector_pixel, docking_alignment, connector_color_match (20270e3b); erase (7b80bb43)

**依赖链**：对接需要知道哪些精灵体配对 → 配对标准是两个精灵体获得相同的"传入色" → 传入色由各精灵体 4-邻接的标记像素的颜色决定 → 标记像素的分布编码了配对信息 → 对接方向由精灵体上唯一的灰连接像素位置确定 → 传色和对接不是前后独立步骤，而是共享"颜色"这一语义通道：传色确定"谁和谁配对"，连接像素确定"怎么拼"。

通过邻接标记像素的颜色确定哪些精灵体配对，再按连接像素的位置对齐拼合。

**输入结构**：约 22x22 的网格，背景为黑(0)。网格中有 4~6 个青(8)4-连通精灵体（每个精灵体 6~12 像素，形状各异——非矩形的不规则连通区域）。每个精灵体内部恰好有 1 个灰(5)连接像素（替代精灵体该位置的青色），位于精灵体边界的某条边上（即该灰像素在精灵体的上、下、左或右边缘）。精灵体之间至少间隔 3 个像素。散布在精灵体周围的是标记像素，每个标记像素恰好与一个精灵体 4-邻接（紧贴精灵体边缘但不属于精灵体）。标记像素使用红(2)、蓝(1)、绿(3)中的颜色。每个精灵体恰好被 1 个标记像素触碰。恰好有 2 个精灵体被同色标记触碰，构成一个配对；另外 2 个精灵体被另一同色标记触碰，构成另一个配对（若有 6 个精灵体则有 3 对）。生成约束：同一配对中的两个精灵体的灰连接像素分别位于相对的边上（如一个在右边缘、另一个在左边缘，或一个在下边缘、另一个在上边缘）；将配对中的"插入方"精灵体平移使其灰连接像素与"底座方"灰连接像素相邻（按连接方向紧贴），拼合后的图形不超出网格边界且不与其他精灵体重叠。底座方定义为配对中边界框左上角坐标字典序更小的精灵体。

**规则**：
1. 对每个精灵体，找到与其 4-邻接的标记像素的颜色，记为该精灵体的"传入色"。
2. 将传入色相同的精灵体两两配对。
3. 对每个配对，确定底座方（边界框左上角坐标字典序较小者）和插入方。
4. 确定对接方向：底座方灰连接像素所在的边决定方向（如灰在右边缘 → 插入方从右侧对接）。将插入方平移，使其灰连接像素在底座方灰连接像素的对接方向上紧邻（相距 1 像素，4-邻接）。
5. 将两个精灵体合并（重叠区域不会发生，由生成约束保证）。将灰连接像素重涂为青(8)。
6. 擦除所有标记像素（变为背景黑(0)）。
7. 输出为整个网格（不裁剪），未参与对接的区域保持不变。

**关键洞察**：精灵体上的灰连接像素标记了"怎么拼"，但"谁和谁拼"不由连接像素决定，而由外部标记像素的颜色经邻接传递后的一致性决定。单看一个示例，可能误以为配对标准是空间距离最近或形状互补，需要多个示例才能发现是"标记颜色相同即配对"的规则。

## 新题 6：双色提取后孔洞图例填充

**组合逻辑**：[提取/extract + 行列乘积完整/row_col_product](已有：从混杂网格中识别并提取双色子图) + [填充/fill + 图例映射颜色/legend_maps_color](创新：图例不预置在输入中，而是从提取时丢弃的"非目标"区域中恢复) + [重涂色/recolor](已有：根据图例对孔洞着色)

**来源原语**：extract, bicolor_image, row_col_product (b71a7747); fill, color_legend, legend_maps_color (9385bd28); recolor (278e5215)

**依赖链**：填充孔洞需要颜色图例 → 图例隐藏在提取操作丢弃的那些行/列中 → 必须先完成提取（确定哪些行列属于双色图像）才能知道哪些行列是"剩余区域" → 从剩余区域中恢复图例 → 用图例填充双色图像中的背景孔洞。提取和图例恢复互为依赖：提取的副产品（丢弃行列）是图例恢复的输入。

**输入结构**：约 16x16 的网格。网格由多种颜色的像素组成。其中恰好存在一对颜色（如红(2)和蓝(1)），它们的像素占据的行集和列集的笛卡尔积被完全覆盖（即这两种颜色的像素出现在所有"活跃行 x 活跃列"的交叉格上，无遗漏）——这是双色目标图像。目标图像中有若干黑(0)背景孔洞（在活跃行x活跃列的交叉格上，原本应为两色之一，但实际为黑色的像素，占 3~8 个像素）。在目标图像的活跃行/列之外的区域（非活跃行或非活跃列上），存在一组颜色图例像素：一个 2 行 N 列（或 N 行 2 列）的小矩形块，其中一行/列为灰(5)填充，另一行/列显示一种颜色（如绿(3)或黄(4)），该颜色即为孔洞应填充的颜色。图例的行/列完全位于非活跃行/列上。网格中其他位置填充有橙(7)和品红(6)等干扰色像素，不满足行列乘积完整条件。生成约束：满足行列乘积条件的颜色对唯一；图例恰好位于非活跃区域；孔洞数量不为零。

**规则**：
1. 遍历所有颜色对，找到唯一满足行列乘积完整条件的颜色对 (A, B)：该颜色对的像素覆盖的行集 R 和列集 C 满足 |R| x |C| = 该颜色对在 RxC 区域内的像素数 + 该区域内的黑(0)像素数（即 RxC 区域内只有 A、B、黑三种颜色）。
2. 提取 RxC 子网格作为目标图像。
3. 在非活跃区域（行不在 R 或列不在 C 的位置）中，找到 2 行或 2 列的图例矩形块。图例中非灰的那行/列的颜色记为填充色 F。
4. 将目标图像中所有黑(0)孔洞像素重涂为填充色 F。
5. 输出为填充后的目标子图像（即 |R| x |C| 大小的网格）。

**关键洞察**：图例不是显式标注的独立组件，而是隐藏在提取操作"不要的"那些行列中。求解者必须先识别双色图像（排除干扰色），然后在被排除的区域中反向搜索图例。这种"提取的副产品包含后续操作所需信息"的结构关系在任何参考题中都不存在。需要多个示例对比孔洞填充色与图例颜色的对应关系才能确认规则。

## 新题 7：点对称选择裁剪目标并调色带重涂

**组合逻辑**：[点对称/point_symmetry + 绕中心点旋转对称/center_rotational](创新：点对称不用于"生成镜像副本"，而用于"检测哪个对象具有点对称性"作为选择条件) + [裁剪/crop](已有：裁剪选中对象) + [重涂色/recolor + 调色带指定列色/palette_assigns_color](已有：逐列用调色带颜色重涂)

**来源原语**：point_symmetry, center_rotational (e729b7be); crop (42f14c03, 278e5215); recolor, monochrome_mask, palette_strip, column_correspondence, palette_assigns_color (278e5215)

**依赖链**：调色带重涂需要知道作用于哪个对象 → 目标对象由点对称性检测选出 → 检测需要逐一测试每个前景对象是否绕自身几何中心具有 180 度旋转对称性 → 选出的对象被裁剪 → 裁剪结果被调色带逐列重涂。点对称性从"生成操作"变为"判别条件"，与裁剪和重涂形成三步耦合。

在多个前景对象中找到唯一具有 180 度旋转对称性的对象，裁剪其边界框，按调色带逐列重涂。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格中有 3~5 个灰(5)4-连通前景对象（每个 8~20 像素，形状各异）。其中恰好 1 个对象具有 180 度旋转对称性（即绕其边界框中心旋转 180 度后与自身完全重合），其余对象不具有此对称性。网格底部或顶部有一个 1 行 W 列的调色带（W 等于对称对象边界框的宽度），调色带由 2~4 种颜色组成（选自红(2)、蓝(1)、绿(3)、黄(4)），每列一个颜色。调色带与所有前景对象不相邻（至少间隔 1 行）。生成约束：恰好 1 个对象具有 180 度旋转对称性；调色带宽度恰好等于该对象边界框宽度；其他对象的边界框宽度至少有一个与调色带宽度不同（提供额外线索，但不是充分条件）。

**规则**：
1. 对每个灰(5)前景对象，测试其是否具有 180 度旋转对称性：提取对象的边界框内的像素集，将非对象像素视为背景；将该像素集绕边界框中心旋转 180 度；若旋转后与原像素集完全重合则判定为对称。
2. 选择唯一的对称对象，裁剪其边界框（大小为 H x W）。
3. 读取调色带（1 x W），第 j 列的颜色记为 P[j]。
4. 在裁剪结果中，对每个灰(5)像素，将其颜色替换为该像素所在列 j 对应的调色带颜色 P[j]。背景（黑(0)）像素保持不变。
5. 输出为 H x W 的重涂后子网格。

**关键洞察**：点对称性在本题中不是一个操作（不生成镜像副本），而是一个筛选条件——用于从多个候选对象中选出唯一的裁剪目标。这与参考题 e729b7be 中"补全对称副本"的用法完全不同。单个示例中，求解者可能误以为选择标准是"面积最大"或"最接近调色带"，需要多个示例才能排除这些假说并确认对称性是真正的选择标准。

## 新题 8：擦除对角噪声后按字形模板重建

**组合逻辑**：[擦除/erase + 补线/line_completion](创新：擦除噪声不是最终目的，而是为了暴露被遮盖的锚点标记) + [补全/reconstruct + 颜色对应形状/color_to_shape](创新：字形模板不由示例中的完整字形提供，而由清理后的线段拓扑结构编码)

**来源原语**：erase, line_completion, diagonal_noise, straight_line_segment, gap_length_constraint (7b80bb43); reconstruct, glyph_template, endpoint_marker, frame_bar, color_to_shape, anchor_position (98c475bf)

**依赖链**：字形重建需要锚点位置和字形模板 → 锚点被对角噪声像素遮盖，必须先擦除噪声 → 噪声擦除后露出端点标记像素 → 同时，清理后的直线段的数量和朝向编码了"使用哪个字形模板" → 字形模板库由输入中的边框竖条之间的完整字形提供 → 清理后线段的颜色与字形库中某个字形颜色匹配时，使用该字形。擦除、线段拓扑分析、颜色匹配和字形重建四步紧密耦合。

擦除对角噪声以暴露端点标记，利用清理后直线段的颜色查找对应字形模板，在端点标记位置重建字形。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格左右两侧各有一条灰(5)全高竖直边框条（各 1 像素宽，占满网格高度）。两条边框之间的区域分为上下两部分（无显式分隔，由内容区分）：
- **上半区（模板区）**：包含 1~2 个完整字形，每个字形由单一颜色的像素组成（选自红(2)、蓝(1)、绿(3)），字形为 3~5 像素高、3~5 像素宽的 4-连通图案（如十字、角形等不同结构），不同字形颜色不同。字形之间至少间隔 2 行。
- **下半区（工作区）**：包含若干与模板区字形颜色对应的前景色像素，但这些像素被对角噪声严重干扰——原本的水平或垂直直线段被对角阶梯状噪声像素（45 度链，与直线段同色，8-连通但 4-不连通于直线段）部分替代或遮盖。每条被干扰的线段上有 2 个黄(4)端点标记像素，分别位于该线段应有的起点和终点附近（可能被噪声像素覆盖后仅剩 1 个可见，另 1 个被噪声像素占据了位置——此时噪声擦除后该位置恢复为端点标记）。每种前景颜色在工作区恰好有一条被干扰的线段。

生成约束：对角噪声像素可通过"无正交同色邻居、仅有对角同色邻居"的标准唯一识别；擦除噪声并补全间隙后，每条线段恢复为完整的水平或垂直直线，且两端各有一个黄(4)端点标记；每条线段的颜色恰好匹配模板区中某个字形的颜色。

**规则**：
1. 在工作区中，识别对角噪声像素：与直线段同色、无正交方向的同色邻居、仅有对角方向的同色邻居的像素。将这些像素擦除（变为背景黑(0)）。
2. 补全因噪声擦除而产生的直线段间隙：在水平或垂直方向上，若同色像素之间的间隙长度不超过被擦除的相邻对角噪声的跨度，则用该颜色填补间隙。
3. 擦除和补全后，每条线段恢复为完整直线，两端各有一个黄(4)端点标记。记录每条线段的颜色 C 和其两个端点标记的行坐标。
4. 在模板区找到颜色为 C 的字形模板。
5. 擦除该线段（包括端点标记），在两个端点标记所在的行之间（含端点行），以端点标记的列为水平锚点，绘制字形模板。字形模板垂直居中于两个端点标记的行之间，水平居中于两个端点标记的列之间。
6. 各颜色独立处理。边框竖条和模板区保持不变。

**关键洞察**：对角噪声不仅仅是需要清除的视觉干扰——它遮盖了端点标记的位置，而端点标记决定了字形重建的锚点。擦除操作不是独立的预处理，它的结果直接为后续的字形定位提供必要输入。同时，线段的颜色是字形模板的查找键，但这一对应关系只有在噪声清理后线段完整可见时才能可靠读取。需要多个示例对比才能确认"颜色对应字形"的映射规则而非"位置对应字形"。

## 新题 9：侧边接触定色后位置图例填充

**组合逻辑**：[重涂色/recolor + 接触侧定色/contact_side_color](创新：接触侧确定的颜色不直接涂色，而是选择使用哪套位置图例) + [填充/fill + 位置对应颜色/position_to_color](创新：位置图例不唯一固定，而是多套图例由接触侧颜色索引)

**来源原语**：recolor, contact_side_color, multicolor_obj, side_marker, panel_region, contained_in (c3fa4749); fill, position_to_color, bordered_region, fixed_legend, fill_missing (a834deea)

**依赖链**：位置填充需要知道使用哪套图例 → 图例选择由面板区域的侧边标记颜色决定 → 侧边标记颜色检测需要识别"哪种颜色出现在对象触碰面板边界的那条边上" → 该检测结果不涂色（与参考题 c3fa4749 不同），而是索引到多套图例中的一套 → 然后按该图例的位置映射填充内部缺失位。接触侧定色和位置填充通过"颜色作为图例索引"这一语义桥梁耦合。

由对象触碰面板边界的侧边颜色选择对应的位置图例，再按图例填充对象内部的缺失位。

**输入结构**：约 18x18 的网格，背景为黑(0)。网格中有 2~3 个灰(5)面板区域（每个面板为 7x7 的实心灰正方形）。每个面板的 5x5 内部区域（去掉 1 像素厚的灰边框）包含一个 4-连通的前景对象（3~8 像素，颜色选自红(2)、蓝(1)、绿(3)中的某一种）。该对象恰好接触面板 5x5 内部区域的一条边（上、下、左或右），且对象在该边上的所有像素颜色一致（此颜色即为该对象的"侧边色"）。5x5 内部区域中，对象未覆盖的位置为黑(0)背景。网格的某个角落（如左下角）有一个颜色图例区，包含 2~3 套 3x3 的位置图例，每套图例的 9 个位置各有一个颜色编号（使用 ARC 颜色 1~9），不同图例的颜色分配不同。每套图例旁标有一个索引色像素（如红(2)像素旁放一套图例、蓝(1)像素旁放另一套），索引色像素为 1 个独立像素，4-邻接于对应图例的左侧或上侧。

生成约束：面板中对象的侧边色与某套图例的索引色相同；每种出现的侧边色恰好对应一套图例；不同面板中的对象可以有相同或不同的侧边色。

**规则**：
1. 对每个面板，识别其 5x5 内部区域中的前景对象，确定对象触碰内部边界的那条边，读取该边上的对象像素颜色作为"侧边色 S"。
2. 在图例区中，找到索引色等于 S 的那套 3x3 位置图例 L。
3. 将面板的 5x5 内部区域视为一个网格。对 5x5 中每个黑(0)背景位置 (r, c)（r, c 各从 0 到 4），查找位置图例 L 中对应位置 (r mod 3, c mod 3) 的颜色（当 5x5 大于 3x3 时，图例按周期平铺），如果该位置原本为黑(0)，则填充为图例颜色；如果该位置已被前景对象占据，保持不变。
4. 面板灰(5)边框保持不变。图例区保持不变。背景保持不变。

**关键洞察**：侧边颜色在本题中不用于"重涂对象"（与参考题 c3fa4749 不同），而用于"选择填充规则"——它是一个索引，指向多套位置图例中的某一套。同一颜色对象在不同面板中可能因位置不同而触碰不同边，但只要侧边色相同就使用同一图例。需要对比至少两个面板的输出才能确认"侧边色→图例"的映射关系，且需要排除"触碰哪条边→图例"这一干扰假说（因为不同面板中同色对象可能触碰不同边但使用相同图例）。
