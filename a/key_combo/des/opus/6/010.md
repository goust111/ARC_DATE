## 新题 1：周期-对称联合缺陷共识

**组合逻辑**：[平铺 tile](创新：用于推断平铺周期模板) + [对称补全 symmetry_completion](创新：用于平铺单元内部对称验证) + [缺陷标记 defect_mark](已有) → 联合约束过滤（新关系：两种独立约束的交集才认定缺陷）

**来源原语**：平铺 tile（参考题 30f42897）、对称补全 symmetry_completion / 推断对称轴 infer_symmetry_axes（参考题 981571dc）、缺陷标记 defect_mark / 邻域多数色 neighborhood_majority_color（参考题 de809cff）、环形周期 cyclic_period（参考题 30f42897）

**依赖链**：平铺周期检测 → 周期模板恢复 → 模板内对称轴推断 → 两种约束联合判定缺陷 → 标记。删去周期检测则无法分割平铺单元；删去对称分析则缺陷误判过多（周期约束单独会把故意的局部变化也标为缺陷）；删去联合过滤则无法区分真缺陷与设计性不对称。

从覆盖整个网格的平铺色彩图案中，找到同时违反周期重复和单元内对称的像素并标记为青(8)。

**输入结构**：约 16x16 网格。网格内部（排除 1 像素宽的黑(0)背景边框）被一个矩形平铺图案填满。平铺单元尺寸约 4x4 至 6x6，水平周期 W、垂直周期 H（各示例中 W、H 不同但均能被内部区域整除）。每个平铺单元内使用 3-4 种前景色，且该单元具有双轴对称或单轴对称（对称类型在各示例中可能不同）。整个网格中有 2-4 个像素被篡改为错误颜色（篡改后的颜色仍是 0-9 中的某个合法颜色，但与正确值不同）。此外，部分平铺单元内故意包含 1-2 个像素与其对称镜像位置颜色不同（设计性不对称），但这些像素在所有周期实例中一致出现（即周期约束不会标记它们）。生成约束：篡改像素不会恰好落在设计性不对称的位置上。

**规则**：
1. 在内部区域中，通过逐像素多数投票（对应位置在所有周期实例中的众数颜色）恢复平铺周期模板。周期 W 和 H 需从数据中推断：选择使所有实例间像素一致率最高的最小正整数 W 和 H。
2. 在恢复的周期模板内部，检测其双轴或单轴对称：对每个可能的对称轴（水平中线、垂直中线），统计非零像素对中颜色一致的比例，选择一致率 >= 80% 的轴作为对称轴。
3. 对网格中每个非背景像素，计算两个布尔标记：(a) 周期违规——该像素颜色与恢复模板中对应位置的众数颜色不同；(b) 对称违规——该像素颜色与其在平铺单元内通过所有已确认对称轴映射后的镜像位置颜色不同。
4. 仅当一个像素同时满足周期违规 AND 对称违规时，将其重涂为青(8)。只满足一种违规的像素保持原样。

**关键洞察**：单独的周期约束会误报设计性不对称像素（它们在单元内不对称但跨周期一致）；单独的对称约束会误报所有不对称像素（包括跨周期一致的设计性不对称）。只有两个独立约束的交集才精确定位真正的篡改缺陷。

## 新题 2：遮挡深度驱动的弹射距离

**组合逻辑**：[排序 sorting / 遮挡层序 occlusion_order](已有) + [弹射 ejection](创新：弹射距离由遮挡分析的层深决定，而非内容像素数) + [擦除 erase](已有)

**来源原语**：排序 sorting / 遮挡层序 occlusion_order / 空心矩形 hollow_rectangle / 重叠层 overlap_layer / 重叠定先后 overlap_determines（参考题 68bc2e87）、弹射 ejection / 尾刺 tail_spike / 擦除 erase / 尾部朝向决定射出 tail_determines_emission（参考题 3dc255db）

**依赖链**：空心矩形边框重建 → 重叠区域遮挡分析 → 自底向顶层序排列 → 层序编号作为弹射距离参数 → 定向弹射 + 擦除。层序分析的输出（层编号）不是最终答案而是弹射操作的数值参数，形成跨逻辑的定量依赖。

根据重叠空心矩形框的遮挡层深，将每个框内的内容像素沿尾刺方向弹射到与层深成正比的距离处。

**输入结构**：约 20x20 黑(0)背景网格。3-5 个空心矩形框（1 像素宽边框），每个框一种独特的非背景前景色（如红(2)、蓝(1)、绿(3)、黄(4)、灰(5)）。框之间部分重叠，重叠处仅显示最上层框的颜色。每个框的内部恰好包含一个内容像素，颜色为橙(7)。每个框有一个 1 像素的尾刺从边框某一侧向外突出（尾刺颜色与该框的边框色相同），各框的尾刺方向可能不同（上、下、左、右）。生成约束：各框的尾刺方向不相同且不指向其他框所在区域；各框的弹射路径互不交叉。

**规则**：
1. 对每个框，从其可见边框像素推断完整边界框（被遮挡的边框段由边界框几何恢复）。
2. 对所有两两重叠的边框像素，记录遮挡关系：在重叠位置可见的颜色对应的框在其下方被遮挡的框之上。
3. 用所有成对遮挡关系进行拓扑排序，得到从底(rank=1)到顶(rank=N)的唯一层序。
4. 识别每个框的尾刺方向（尾刺像素从边框向外延伸的方向即为弹射方向）。
5. 擦除所有框的边框和尾刺像素（设为背景色），同时擦除每个框内的橙(7)内容像素。
6. 对每个框，从其尾刺原始位置出发，沿弹射方向偏移 rank 个像素的位置绘制一个橙(7)像素。rank 为该框在步骤 3 中的层编号（最底层=1，最顶层=N）。
7. 输出仅保留弹射后的橙(7)像素，其余为背景。

**关键洞察**：弹射距离不由内容数量决定（每个框都只有一个内容像素），而由遮挡分析得出的层深编号决定。不做遮挡分析就无法知道每个橙点该放多远。

## 新题 3：容量-计数匹配的杯体灌注

**组合逻辑**：[计数 count](创新：对散落标记像素按色分组计数) + [填充 fill](创新：重力方向自底向上灌注杯体内腔) + [计数匹配 count_matching](创新：将杯体内腔容量与标记数量配对) + [擦除 erase](已有)

**来源原语**：计数 count / 计数映射尺寸 count_maps_to_size（参考题 878187ab）、填充 fill（参考题 878187ab）、计数匹配 count_matching（参考题 6e4f6532）、杯形框架 cup_frame / 尾刺 tail_spike（参考题 3dc255db）、擦除 erase（参考题 3dc255db）、标记像素 marker_pixel（参考题 d6e50e54）

**依赖链**：杯体内腔面积计算 → 标记像素分色计数 → 容量 == 计数的配对 → 配对色灌注杯体 + 擦除已用标记。容量计算和计数分别来自几何分析和枚举，二者独立计算后在匹配步骤汇合，形成多源汇聚结构。

将散落在网格中的同色标记像素按数量匹配到容量相同的杯形框架内，以匹配色重力灌注。

**输入结构**：约 18x18 黑(0)背景网格。3-4 个杯形框架（由灰(5)像素构成，每个杯是一个开口朝上的 U 形或类 U 形凹槽，边壁 1 像素宽，开口端无封盖）。各杯的内腔大小不同（内腔面积范围 3-7 像素）。杯体之间互不相邻（至少间隔 2 像素）。散落在杯体外部的区域有若干前景色标记像素（如红(2)、蓝(1)、绿(3)、黄(4)），每种颜色出现若干个（每种颜色的像素数恰好等于某一个杯的内腔面积，且不同颜色对应不同杯）。生成约束：标记颜色数 == 杯的数量；每种标记颜色的计数与恰好一个杯的内腔面积匹配，无歧义。

**规则**：
1. 对每个杯形框架，计算其内腔面积（被灰(5)边壁围起且从开口方向可达的背景像素数量）。
2. 对网格中所有非灰(5)、非黑(0)的前景像素，按颜色分组并计数。
3. 将每种标记颜色匹配到内腔面积等于该颜色像素数的杯（唯一配对）。
4. 对每个杯，用其匹配的标记颜色从内腔底部向上逐行填充（同一行内从左到右填充），直到填满整个内腔。
5. 擦除所有原始标记像素位置（设为背景色）。杯的灰(5)框架保持不变。

**关键洞察**：杯体的几何容量（需要分析凹槽形状）和标记的枚举计数（需要遍历网格）必须在匹配步骤中碰头——两条独立的分析路径汇合在一个等式上，决定了颜色分配。

## 新题 4：空间环序驱动的分割-换色-对角拼合

**组合逻辑**：[分割 split](已有) + [重涂色 recolor](创新：换色目标由空间环形顺序决定，非固定交换) + [对角邻接拼合 diagonal_adj_join](已有) + 空间环序推断（新关系：对象的空间位置隐式编码颜色流转方向）

**来源原语**：分割 split / 对角邻接拼合 diagonal_adj_join / 颜色互换且偏移 color_swap_offset / 双色物体 bicolor_object（参考题 fc4aaf52）、重涂色 recolor（参考题 de809cff）、环形周期 cyclic_period（参考题 30f42897）

**依赖链**：空间位置分析 → 环形顺序推断 → 各对象的"下一位"确定 → 分割 → 上半部换色为下一位对象的调色板 → 对角偏移拼合。环序推断是换色的决策节点：不知道顺序就不知道谁的颜色流向谁。

将环形排列的双色矩形对象各自水平分割，上半部采用环序中下一个对象的配色后对角拼回。

**输入结构**：约 20x20 黑(0)背景网格。4 个小矩形对象（各约 4x6 至 6x8 像素，偶数高度），分别位于网格的四个象限区域（左上、右上、右下、左下），彼此不相邻。每个对象使用两种前景色：一种为底色（占多数像素），一种为图案色（占少数像素，形成一个 4 连通的不规则小图形，3-6 像素）。四个对象共使用 8 种不同的前景色（即无颜色复用）。各示例中，4 个对象在网格中的精确位置不同，但始终各占一个象限。

**规则**：
1. 计算每个对象的边界框中心坐标，以网格中心为原点计算其极角（arctan2），按极角从小到大排列得到顺时针环形序列：对象 A → B → C → D → A。
2. 对每个对象，沿其边界框的水平中线将其分为上半部和下半部。
3. 对每个对象的上半部执行换色：将其底色替换为环序中下一位对象的底色，将其图案色替换为下一位对象的图案色。下半部保持原色不变。
4. 将换色后的上半部向右滑动，直到上半部的左下角像素与下半部的右上角像素呈对角相邻（即上半部左下角在下半部右上角的右上方一格）。
5. 输出中，上半部和下半部之间可能出现的间隙保持为背景色。

**关键洞察**：颜色流转方向（谁的上半部取谁的调色板）由对象在网格中的空间位置隐式编码为顺时针环序，而非由颜色本身或对象大小决定。仅凭一个示例可能把环序误判为逆时针或按行列顺序，需要多示例对比才能确定是极角排序的顺时针方向。

## 新题 5：轨迹编码方向的滑动与路径描绘

**组合逻辑**：[滑动 slide](创新：滑动方向由轨迹反向推断而非行列对齐隐含) + [射线延伸 ray_cast / 轨迹 trail](创新：轨迹从方向编码器变为滑动路径的绘制输出) + [重涂色 recolor](已有) + 碰撞优先级（新关系：路径交叉处由行程距离决定涂色优先）

**来源原语**：滑动 slide / 矩形 rectangle / 标记像素 marker_pixel / 行列对齐 row_col_aligned / 最近者进入内部 nearest_enters（参考题 d6e50e54）、射线延伸 ray_cast / 轨迹 trail / 反向投射 opposite_direction（参考题 9f8de559）、重涂色 recolor（参考题 d6e50e54）

**依赖链**：轨迹方向读取 → 反向确定滑动方向 → 到矩形的距离计算 → 最近者判定 → 滑动执行 → 路径描绘 → 交叉冲突解决。轨迹在输入中是方向编码，在输出中变成路径记录——同一概念的双重角色构成紧耦合。

读取每个标记像素的来向轨迹以确定其滑动方向，将其滑向矩形并沿路径留下颜色轨迹，交叉处由更远的标记覆盖。

**输入结构**：约 16x16 黑(0)背景网格。一个实心蓝(1)矩形（约 4x4 至 5x6）位于网格中央偏某方向。3-5 个栗(9)标记像素分布在矩形外部，每个标记与矩形在行或列上对齐（即与矩形的某行或某列共线）。每个标记像素旁有一条由 2-3 个红(2)像素组成的直线轨迹，轨迹从标记出发向远离矩形的方向延伸（即轨迹指向标记的来处）。生成约束：各标记到矩形最近边的曼哈顿距离互不相同；各标记的滑动路径至多两两交叉一次且不会三条共点。

**规则**：
1. 对每个标记像素，读取其红(2)轨迹的延伸方向。标记的滑动方向为轨迹方向的反方向（即朝向矩形）。
2. 计算每个标记沿滑动方向到矩形最近边的距离。
3. 距离最短的唯一标记为"进入者"——它滑动至矩形边界上与其对齐的像素位置（即进入矩形边界）。其余标记各自滑动至矩形对齐边外侧紧邻的一个像素位置（停在矩形外壁）。
4. 将蓝(1)矩形整体重涂为绿(3)。
5. 对每个标记，沿其从原始位置到最终位置的路径（含起点和终点，不含中间经过的矩形内部像素），将路径上的每个像素涂为栗(9)。
6. 若两条路径在某个像素位置交叉，该像素涂为行程距离更长的标记的颜色（栗(9)，但逻辑上是更远标记的路径覆盖更近标记的路径）。由于所有标记同色，交叉处用黄(4)标识以区分覆盖方——行程更长者的路径在交叉点涂黄(4)，行程更短者的路径在交叉点被覆盖（不可见）。
7. 擦除所有原始红(2)轨迹像素（设为背景色）。

**关键洞察**：输入中的红色轨迹仅用于编码方向信息，输出中被擦除；输出中的新路径记录了实际滑动轨迹，交叉处的黄色标识揭示了距离优先级。同一"轨迹"概念在输入和输出中扮演完全不同的角色。

## 新题 6：图例形状驱动的对称扩展印章

**组合逻辑**：[印章覆盖 stamp](创新：印章内容不是单色填充而是图例提供的结构化精灵) + [对称补全 symmetry_completion](创新：对称轴不用于修复既有像素，而是生成新的印章位置) + [位置对应 positional_mapping](已有) + 图例-对称交叉约束（新关系：图例决定印什么，对称决定在哪补印）

**来源原语**：印章覆盖 stamp / 图例精灵 legend_sprite / 分隔行 separator_row / 位置对应 positional_mapping / 图例色替换标记 legend_replaces_marker（参考题 20fb2937）、对称补全 symmetry_completion / 推断对称轴 infer_symmetry_axes / 镜像对应 mirror_correspondence / 缺失像素 missing_pixel（参考题 981571dc）

**依赖链**：图例配对（标记色 → 精灵形状）→ 工作区标记位置识别 → 标记位置印章 → 对称轴推断 → 镜像位置补印。图例提供"印什么"，标记提供"显式印在哪"，对称提供"隐式还要印在哪"——三条信息线在最终输出中汇合。

在分隔行下方的工作区中，将标记像素替换为图例配对的精灵，然后通过对称分析在未标记的镜像位置补印相同精灵。

**输入结构**：约 18x20 网格，黑(0)背景。顶部为图例区：包含 2-3 个 3x3 精灵（各精灵由一种前景色构成，内部含背景色孔洞形成不同图案，且每个精灵自身具有左右对称性）。每个精灵正下方（与精灵水平中心对齐）有一个标记像素，标记颜色与精灵颜色不同且各标记颜色互不相同（如橙(7)、栗(9)、黄(4)）。图例区下方有一行实心灰(5)分隔行。分隔行下方为工作区：包含一个由多种非标记非灰前景色（如蓝(1)、红(2)、绿(3)）构成的大型图案，该图案具有近似的左右双边对称（以工作区的垂直中线为轴）。工作区中散布着若干标记色像素（颜色属于图例中定义的标记色集合），位于图案中某些背景色位置上。生成约束：每种标记色在工作区中至少出现 1 次；至少有一个标记位置的左右镜像位置处没有任何标记（即需要对称补印）；精灵印章区域（3x3）不会覆盖到已有前景色像素上。

**规则**：
1. 在图例区中，按从左到右的顺序配对：第 k 个标记色对应第 k 个精灵。
2. 丢弃图例区和分隔行，保留工作区的尺寸和内容。
3. 对工作区中每个标记色像素，以该像素为中心放置其配对精灵的 3x3 图案（精灵中的前景色像素覆盖工作区对应位置，精灵中的背景色孔洞不覆盖、保留工作区原有内容）。
4. 推断工作区图案的垂直对称轴（从所有非标记的前景像素中，找使左右镜像一致性最高的垂直线 x = x0）。
5. 对每个已印章的位置 (r, c)，计算其镜像位置 (r, 2*x0 - c)。若镜像位置处没有已放置的印章，则在镜像位置补印相同的精灵（同样以镜像位置为中心放置 3x3 图案）。
6. 印章覆盖规则：印章像素覆盖背景色和标记色像素，但不覆盖非标记的前景色像素。先印显式标记位置，再印对称补充位置；同一位置被多次覆盖时后印覆盖先印。

**关键洞察**：仅看图例只能知道每种标记色对应什么精灵形状，但不知道有些精灵需要在未标记的镜像位置额外放置。仅看对称性只能发现图案不完全对称，但不知道该用什么形状去补。两条信息必须结合：图例提供"用什么补"，对称提供"在哪补"。

## 新题 7：嵌套环序作为堆叠指令

**组合逻辑**：[展开嵌套 unfold_nest / 嵌套层 nested_layer](创新：嵌套环不是变换目标而是变换规则的编码载体) + [排序 sorting](创新：排序键不来自对象属性而来自外部编码结构) + [遮挡层序 occlusion_order](已有但角色反转：从"分析遮挡得排序"变为"给定排序改遮挡") + 隐式指令解码（新关系：一种几何结构充当另一种几何结构的排序指令）

**来源原语**：展开嵌套 unfold_nest / 嵌套层 nested_layer / 逆序读取 reverse_order_read / 块序映射层序 block_order_maps_layer（参考题 8fff9e47）、排序 sorting / 遮挡层序 occlusion_order / 空心矩形 hollow_rectangle / 重叠层 overlap_layer / 重叠定先后 overlap_determines（参考题 68bc2e87）

**依赖链**：嵌套环层序读取（外→内 = 低优先→高优先）→ 颜色优先级序列提取 → 右侧重叠框重建 → 按新优先级重新渲染遮挡。嵌套环结构是指令而非数据——它不出现在输出中，但控制了输出的生成方式。

读取左侧嵌套同心环的由外到内颜色序列作为堆叠优先级，重新渲染右侧重叠空心矩形框的遮挡关系。

**输入结构**：约 14x28（宽大于高）网格，黑(0)背景。左半区（约 14x12）包含一个由 N 层（3-5 层）同心矩形环构成的嵌套图案，每层一种独特的前景色，最外层环最大，最内层为实心矩形核心。右半区（约 14x14）包含 N 个空心矩形框（1 像素宽边框），颜色集合与左半区的环颜色完全相同，框之间部分重叠。右半区框的当前可见遮挡顺序与左半区环的由外到内顺序不同。左右两区之间有 2 像素宽的背景间隔列。生成约束：左半区的 N 种颜色与右半区的 N 种颜色一一对应；右半区各框的完整边界框可从可见像素唯一推断。

**规则**：
1. 读取左半区的嵌套同心环：从最外层到最内层，记录颜色序列 C1, C2, ..., CN。定义优先级：C1 优先级最低（最底层），CN 优先级最高（最顶层）。
2. 对右半区的每个框，从其可见的边框像素推断完整的矩形边界框（被遮挡的边框段通过几何恢复）。
3. 按步骤 1 定义的优先级，重新渲染右半区的所有框：在干净的背景上，从最低优先级（C1）的框开始向上逐层绘制完整的 1 像素宽矩形边框，高优先级的框覆盖低优先级的框。
4. 输出仅包含右半区的重新渲染结果（左半区和间隔列不包含在输出中）。输出网格尺寸等于右半区尺寸。

**关键洞察**：左侧嵌套环不是需要变换的对象，而是一份"排序指令"——它的几何结构（由外到内的层序）隐式编码了右侧框应有的堆叠优先级。求解者必须识别出这种跨区域的编码关系，而非将左右两侧视为独立的变换任务。

## 新题 8：射线连接与级联染色

**组合逻辑**：[射线延伸 ray_cast](创新：射线不用于擦除而用于建立精灵间的连接) + [连线 connect](创新：连线端点由射线命中决定而非预定义) + [重涂色 recolor](创新：染色沿射线命中链级联传播) + 处理顺序依赖（新关系：射线长度决定处理顺序，先处理的染色影响后处理的颜色）

**来源原语**：射线延伸 ray_cast / 反向投射 opposite_direction / 首个障碍 first_obstacle（参考题 9f8de559）、连线 connect / 端点对应 endpoint_match / 颜色角色互换 color_role_swap（参考题 c6141b15）、重涂色 recolor（参考题 de809cff）、精灵体 sprite / 尾刺 tail_spike（参考题 3dc255db）

**依赖链**：尾刺方向读取 → 射线发射与命中检测 → 射线长度排序确定处理顺序 → 逐个连线 + 命中目标染色 → 被染色后的精灵以新颜色参与后续连线。处理顺序创造了级联效应：A 染了 B 的色，B 再以新色去染 C、画连线。

每个精灵沿尾刺方向射出射线命中另一精灵并将其染为自己的颜色，按射线长度从短到长依次处理，被染色的精灵以新颜色继续参与后续射线。

**输入结构**：约 18x18 黑(0)背景网格。4-5 个小型单色精灵体（各为 4 连通的不规则图形，3-5 像素，各精灵颜色互不相同，使用如红(2)、蓝(1)、绿(3)、黄(4)、灰(5)中的颜色）。每个精灵有一个 1 像素的尾刺从其边界向外突出（尾刺颜色与精灵主体相同）。尾刺的朝外方向即为该精灵的射线发射方向。生成约束：从每个精灵的尾刺沿发射方向射出的射线恰好命中另一个精灵的主体像素（不会射向空旷区域或射出网格边界）；各射线长度（尾刺尖端到命中像素的曼哈顿距离）互不相同；不存在两个精灵互相命中对方的情况（即射线命中图构成一棵有向树或森林，无环）。

**规则**：
1. 对每个精灵，识别其尾刺像素及其朝外方向（尾刺与精灵主体相邻的方向的反方向）。
2. 从每个尾刺的尖端出发，沿发射方向逐像素延伸射线，直到遇到第一个非背景像素（该像素属于另一个精灵的主体）。记录射线长度（经过的背景像素数 + 1）和命中的目标精灵。
3. 按射线长度从短到长对所有精灵排序，确定处理顺序。
4. 按顺序逐个处理每个精灵：
   a. 用该精灵当前颜色画一条连线，从其尾刺尖端沿发射方向直到命中目标的像素位置（含两端点，连线颜色 = 发射精灵当前颜色）。
   b. 将命中目标精灵的所有像素（含其尾刺）重涂为发射精灵的当前颜色。
5. 所有精灵处理完毕后，输出最终网格。精灵主体、尾刺、连线均保留。

**关键洞察**：由于按射线长度排序处理，先被染色的精灵在后续步骤中以新颜色发射射线和画连线。最终颜色分布取决于处理链的拓扑结构——一条长级联链（A→B→C→D）会让 A 的颜色传播到所有下游精灵。仅凭射线命中关系无法确定最终颜色，必须考虑处理顺序带来的级联效应。
