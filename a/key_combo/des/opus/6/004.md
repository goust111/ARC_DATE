## 新题 1：对角朝向决定轮廓绕行方向

**组合逻辑**：[分类/classify](已有) + [滑动/slide](已有) + [重涂色/recolor](已有)；创新点在于分类结果不直接映射颜色，而是决定空间操作的方向参数

**来源原语**：分类/classify、重涂色/recolor、对角线段/diagonal_bar、对角朝向/diagonal_orientation、多数朝向决定色/majority_orient_color（来自 1d61978c）；滑动/slide、障碍轮廓/obstacle_contour、轮廓邻接/contour_adjacency、最长贴边路径/longest_adjacent_path（来自 97c75046）

**依赖链**：对角朝向分类 → 多数/少数判定 → 轮廓绕行方向选择 → 终点定位 + 重涂色。分类结果作为路由决策注入空间操作，而非直接映射颜色；去掉分类则绕行方向不可知，去掉轮廓跟踪则终点不可知，去掉重涂色则输出颜色错误。

每个标记像素沿其对角线段的朝向被分为多数组或少数组，多数组沿障碍轮廓的较长侧绕行、少数组沿较短侧绕行，最终各自停留在绕行终点并按组别重涂色。

**输入结构**：黑(0)背景，约 15x15 网格。一个灰(5)连通障碍区域（不规则形状，约 15-25 像素，4-连通）占据网格中部。3-5 个蓝(1)标记像素散布在障碍周围，每个标记像素是一条短对角线段（2-3 像素，也为蓝(1)）的一个端点。每条对角线段要么沿 NW-SE 方向、要么沿 NE-SW 方向。每个标记像素恰好有一条水平或垂直的无遮挡视线通向障碍区域（视线上无其他前景像素）。生成约束：不同示例中标记的数量和朝向分布不同，以确保多数/少数组的归属在不同示例间变化；每个标记的视线方向也不固定。

**规则**：
1. 对每个标记像素，检查其所在对角线段的朝向：若该段上存在 NW-SE 方向的对角邻居（即左上或右下方向有同色像素），归入 NW-SE 组；若存在 NE-SW 方向的对角邻居，归入 NE-SW 组。
2. 统计两组的标记数量，标记数多的为"多数组"，少的为"少数组"。
3. 对每个标记，沿其唯一视线方向滑动，直到到达障碍区域前方最后一个背景像素（即与障碍 4-相邻的背景格）。
4. 从该落点出发，考虑沿障碍外轮廓的两个可能绕行方向（保持与障碍 4-相邻的前提下沿背景格行走）。多数组标记选择能走更长路径的方向，少数组标记选择能走更短路径的方向。沿所选方向行走直到路径终止（即下一个格子不再与障碍 4-相邻，或越出网格边界）。
5. 将标记放置在行走终点。擦除所有原始对角线段（包括标记的原始位置）。
6. 多数组标记重涂为青(8)，少数组标记重涂为红(2)。

**关键洞察**：对角朝向的分类不是为了直接给像素上色（源题 1d61978c 的用法），而是作为路由决策——决定每个标记在障碍轮廓上的绕行方向。求解者必须先完成分类和多数/少数判定，才能确定每个标记的空间运动方向。

## 新题 2：裂缝分片面积匹配入框

**组合逻辑**：[擦除/erase + 滑动/slide（裂缝分裂）](已有) → [计数/counting](已有) → [填充/fill](已有)；创新点在于裂缝分裂产生的碎片尺寸成为面积匹配的查找键

**来源原语**：擦除/erase、滑动/slide、裂缝标记线/fracture_line、前景对象/foreground_object、沿短轴分裂/split_along_short、两侧等距分离/halves_separate（来自 2faf500b）；计数/counting、填充/fill、轮廓对象/outline_object、行内腔/row_interior、面积匹配/area_matching、像素数等于腔面积/count_equals_cavity（来自 7acdf6d3）

**依赖链**：裂缝分裂 → 碎片像素计数 → 与框架内腔面积匹配 → 碎片颜色填入匹配框架。裂缝决定碎片尺寸（输入中无法直接读取），尺寸是匹配的唯一键；去掉裂缝步骤则碎片尺寸不可知，去掉面积匹配则碎片去向不可知。

将含有裂缝线的前景物体沿裂缝分裂为两半，每半的像素数恰好匹配某个空心框架的内腔面积，将对应半体的颜色填入匹配框架的内腔。

**输入结构**：黑(0)背景，约 18x18 网格。2-3 个多色前景物体，每个物体由一种主体颜色（各物体主体颜色互不相同，从蓝(1)、红(2)、绿(3)中选取）构成 4-连通的不规则形状（8-20 像素），内部有一条品红(6)裂缝标记线横穿物体的短轴方向（裂缝线为单像素宽，完整横跨短轴）。另有 4-6 个绿(3)...不对，框架颜色不应与物体主体颜色冲突。让我用灰(5)作为框架颜色。另有 4-6 个灰(5)空心矩形框架分散在网格中，远离前景物体。每个框架的行内腔面积（每行中最左和最右灰(5)像素之间的背景像素数之和）互不相同。生成约束：每个物体裂缝后产生的两个半体的像素数互不相同，且每个半体的像素数恰好等于某一个框架的内腔面积；不同半体不会匹配同一个框架。框架总数等于所有半体的总数。

**规则**：
1. 对每个前景物体，擦除其品红(6)裂缝标记线上的所有像素（替换为背景色）。
2. 裂缝擦除后，物体被分为两个不连通的半体。将裂缝两侧的主体像素各自沿垂直于裂缝的方向平移一格（远离裂缝方向），使两半分离。
3. 计算每个半体的主体像素数。
4. 对每个灰(5)框架，计算其行内腔面积：对框架边界框内的每一行，统计最左和最右灰(5)像素之间严格位于它们之间的背景像素数，求和。
5. 将每个半体与行内腔面积等于该半体像素数的唯一框架配对。
6. 擦除该半体在原位置的所有像素，将匹配框架的内腔像素全部涂为该半体的主体颜色。框架本身（灰(5)像素）不变。
7. 处理顺序：按半体像素数从小到大依次处理（不影响结果，因为各半体匹配不同框架）。

**关键洞察**：裂缝的位置和方向决定了每个碎片的像素数——这一信息在裂缝分裂之前无法获得。求解者必须在心中完成分裂操作，才能得到用于面积匹配的查找键。碎片尺寸是两个逻辑（分裂与填充）之间的隐式桥梁。

## 新题 3：跨障碍标记界定路径局部反转

**组合逻辑**：[跨障碍配对识别](已有，创新：配对结果不触发交换，而是界定反转区间) + [颜色序列反转/reverse_color_seq](已有) + [擦除/erase](已有)

**来源原语**：标记像素/marker_pixel、障碍段/barrier_segment、跨障碍配对/cross_barrier_pair、同行列两侧各一/one_each_side（来自 1efba499）；颜色序列反转/reverse_color_seq、单像素宽路径/one_pixel_path、端点像素/endpoint_pixel、端到端遍历/endpoint_traversal、形状不变仅反色序/shape_fixed_reversed（来自 5792cb4d）

**依赖链**：跨障碍标记配对 → 路径子段端点确定 → 局部颜色序列反转 + 标记擦除。障碍配对逻辑界定了反转的空间范围，反转逻辑在该范围内执行；去掉配对则反转边界不可知，去掉反转则配对无后续效果。

一条多色路径穿过障碍段，障碍两侧各有一个标记像素邻接路径；以这两个标记为界，反转它们之间路径子段的颜色序列，擦除标记。

**输入结构**：黑(0)背景，约 12x15 网格。一条灰(5)垂直障碍线段（单像素宽，跨越 5-8 行）位于网格中部偏左或偏右。一条 4-连通多色路径（单像素宽、无分支、至少 10 像素长）从网格一侧延伸到另一侧，途中穿过障碍线段中的一个间隙（障碍在该行缺少一个像素，路径从此通过）。路径上的颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，相邻像素颜色不同。两个品红(6)标记像素分别位于障碍的左侧和右侧，各自与路径上的某个像素 4-相邻但不在路径上。每个标记恰好与路径上的一个像素相邻。生成约束：两个标记之间的路径子段至少包含 4 个像素；路径在标记之外的部分至少各有 2 个像素。

**规则**：
1. 识别两个品红(6)标记像素，确认它们分别位于灰(5)障碍的两侧。
2. 找到每个标记 4-相邻的路径像素，记为 P_left 和 P_right（分别在障碍左侧和右侧）。
3. 沿路径从 P_left 走到 P_right（穿过障碍间隙），记录沿途的颜色序列 [c1, c2, ..., cn]。
4. 将这 n 个路径像素的颜色替换为 [cn, cn-1, ..., c1]（反转序列），像素位置不变。
5. 擦除两个品红(6)标记（替换为背景色）。
6. 路径上 P_left 和 P_right 之外的部分、障碍线段、以及所有背景像素保持不变。

**关键洞察**：跨障碍标记配对的逻辑（源题中用于交换标记位置）在此被重新用途化为界定反转操作的空间范围。求解者需要认出"障碍两侧各一个标记"的配对模式，但得出的不是交换操作而是区间反转——相同的检测条件触发了完全不同的变换。

## 新题 4：逐行异常值组装平铺种子

**组合逻辑**：[提取/extraction](已有) → [裁剪/crop](已有) → [平铺/tile](已有)；创新点在于提取过程构造出一个输入中不存在的复合种子图案，该图案再被周期性平铺

**来源原语**：提取/extraction、裁剪/crop、网格单元/lattice_cell、精灵体/sprite、逐行比较/row_wise_comparison、异常值选择/outlier_selection（来自 38007db0）；平铺/tile、种子图案/seed_motif、周期重复/periodic_repeat、填满网格/fill_grid（来自 9b30e358）

**依赖链**：逐行异常值识别 → 异常值裁剪并纵向堆叠为复合种子 → 水平周期平铺。异常值选择决定种子内容，种子内容决定平铺结果；去掉异常值检测则种子无法构造，去掉平铺则提取结果不是最终输出。

从格子网格的每行中找出唯一不同的单元，纵向堆叠成一个复合种子图案，再将该种子水平平铺充满输出网格。

**输入结构**：黑(0)背景，约 20x20 网格。黄(4)网格线将网格分成 R 行 C 列的等大方形单元（例如 4 行 x 5 列，每个单元内部 3x3）。每个单元内部有一个小型精灵体图案（使用蓝(1)、红(2)、绿(3)等颜色，不含黄(4)和黑(0)）。在每一格子行中，C-1 个单元的内部图案完全相同，恰好有 1 个单元的内部图案与该行其余单元不同（即"异常值"）。不同行的异常值图案互不相同，异常值在行内的列位置也不固定。生成约束：R 行的异常值纵向堆叠后形成的复合图案宽度等于单个单元内部宽度。

**规则**：
1. 对每一格子行（从上到下），比较该行所有单元的内部图案（仅比较单元内部像素，排除网格线），找到出现恰好一次的图案——即该行的异常值单元。
2. 裁剪每个异常值单元的内部图案（去除网格线，保留内部像素及其相对位置）。
3. 将 R 个裁剪后的异常值图案按原行顺序从上到下堆叠（第 1 行的异常值在最上方，第 R 行的在最下方），中间无间隔，形成一个高度为 R x 单元内部高度、宽度为单元内部宽度的复合种子图案。
4. 以该种子为单元，水平方向周期性平铺，直到充满宽度等于输入网格宽度的输出网格。输出网格高度等于种子高度。背景为黑(0)。输出中不包含网格线。
5. 若输出宽度不是种子宽度的整数倍，右侧不完整的部分按种子的对应列截取（保留左侧对齐的部分列）。

**关键洞察**：输入中不存在"种子图案"这一实体——它是从每行异常值中聚合构造出来的。求解者必须完成逐行异常值检测并理解堆叠逻辑，才能得到平铺的基本单元。提取是构造步骤而非简单的筛选步骤。

## 新题 5：柱状高度算术驱动楔形展开深度

**组合逻辑**：[计数/counting + 高度加减运算](已有) → [擦除/erase + 填充/fill + 逐行扩展楔形](已有)；创新点在于算术运算的结果不被渲染为可见柱状条，而是作为隐式参数控制另一个几何操作的幅度

**来源原语**：计数/counting、柱状条/vertical_bar、结果槽/result_slot、颜色编码正负/color_encodes_sign、高度加减运算/height_arithmetic（来自 37ce87bb）；擦除/erase、填充/fill、调色板行/palette_row、标记竖条/marker_bar、以缺口为中心/centered_on_gap、逐行扩展楔形/row_expand_wedge（来自 bae5c565）

**依赖链**：颜色编码加减 → 算术求和 → 楔形展开行数。算术结果是楔形展开的唯一深度参数；去掉算术则深度不可知，去掉楔形则算术结果无几何表达。

网格上半部有调色板行和标记竖条，下半部有正/负计数柱；正柱高度之和减去负柱高度之和，决定调色板从缺口向下展开多少行楔形。

**输入结构**：黑(0)背景，约 15x20 网格。顶行为调色板行：一行多色像素（从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)中选取）横跨网格全宽，其中恰好有一个黑(0)缺口。调色板行下方紧接一条垂直的橙(7)标记竖条（2-4 像素高），位于缺口所在列。网格下半部分（与上半部分之间有至少 3 行空白隔开）有若干底部对齐的单像素宽垂直柱状条：青(8)柱为正值，红(2)柱为负值。柱状条高度各异（1-6 像素），互不相邻，各占一列。生成约束：正柱高度总和严格大于负柱高度总和；结果值 H 不超过网格剩余可用行数（标记竖条底部到网格底边的距离）。

**规则**：
1. 计算所有青(8)柱的高度之和 S_pos，以及所有红(2)柱的高度之和 S_neg。
2. 计算展开深度 H = S_pos - S_neg。
3. 清除网格中除调色板行以外的所有内容（柱状条、标记竖条均擦除为背景色）。
4. 从调色板行的下一行开始，以缺口列为中心，逐行向下扩展楔形：第 k 行（k = 1, 2, ..., H）在缺口的左右各复制 k 个调色板列的颜色（从缺口向两侧取，若不足 k 列则取到调色板边界为止）。
5. 楔形中缺口列始终填充橙(7)（标记竖条的颜色）。
6. 展开恰好 H 行后停止，H 行以下保持背景色。

**关键洞察**：柱状条的高度算术（源题中产出一根可见的灰色结果柱）在此不产生任何可见输出，而是作为一个隐式数值参数注入到完全不同的几何操作（楔形展开）中。求解者需要识别两个在视觉上毫无关联的区域之间的数值桥梁。

## 新题 6：最小间距配对锚定错切变换

**组合逻辑**：[连线/connect](已有，创新：连线结果不作为输出的一部分而是确定铰点位置) + [错切/shear](已有，创新：铰点由输入的空间关系动态决定而非固定)

**来源原语**：连线/connect、填充/fill、对称标记对/mirrored_marker_pair、间隔段/gap_segment、中轴对称/center_axis_symmetry、最小间距对触发/min_gap_triggered（来自 5ad8a7c0）；错切/shear、前景网格/foreground_grid、对角线边缘/diagonal_edge、行偏移递变/row_offset_progress、行内容保持/row_content_preserved（来自 3cd86f4f）

**依赖链**：间距比较 → 最小间距对识别 → 铰点行确定 → 以铰点为轴的错切变换。间距分析决定铰点，铰点决定错切几何；去掉间距分析则铰点不可知，去掉错切则间距信息无空间效果。

多行对称标记对中间距最小的一对确定铰点行，前景矩形块以该行为轴进行错切变换。

**输入结构**：黑(0)背景，约 14x14 网格。网格中央有一个矩形前景块（约 6x6 至 8x8，所有像素为非黑非绿的多种颜色，内部无空白）。在前景块的上方和下方，各有 2-3 行包含绿(3)对称标记对：每行恰好有两个绿(3)像素，关于网格垂直中轴对称。不同行的标记对间距（两个绿(3)像素之间的水平距离）各不相同。标记对行与前景块之间可以有空行，也可以紧邻。生成约束：恰好有一对标记对的间距严格最小（无平局）；最小间距对所在行位于前景块的上方或下方（不在块内部）；前景块的行数不超过 8，确保错切后不超出网格边界。

**规则**：
1. 在所有绿(3)标记对行中，找到间距最小的那一对（间距 = 右侧绿像素列号 - 左侧绿像素列号 - 1）。
2. 该最小间距对所在的行号记为铰点行 R_hinge。
3. 擦除所有绿(3)标记对（全部替换为背景色），不进行连线填充。
4. 对前景块执行以 R_hinge 为轴的错切变换：前景块中每一行 r 的所有像素整体水平平移 (r - R_hinge) 格。正值向右移，负值向左移。
5. 平移后超出网格左右边界的像素丢弃；原位置腾出的格子变为背景色。
6. 每行内部的像素相对顺序保持不变（整行平移）。

**关键洞察**：对称标记对的间距对比（源题中选出最小间距对并连线）在此不产出连线——间距分析的目的是确定一个几何参数（铰点行位置），该参数控制一个完全不同的空间变换（错切）。求解者需要理解标记对的间距是编码的位置信息而非连线的前驱。

## 新题 7：计数排序框架瀑布堆叠

**组合逻辑**：[计数/counting](已有) → [排序/sort](已有) → [堆叠/stack](已有) + [绘点/draw_dots](已有)；创新点在于计数结果同时作为排序键和点数内容，框架的空间布局由计数结果全面重组

**来源原语**：计数/counting、擦除/erase、绘点/draw_dots、空心框架/hollow_frame、图案精灵体/pattern_sprite、同色匹配/same_color_matching、计数映射点数/count_maps_to_dots（来自 8f215267）；排序/sort、堆叠/stack、按频率降序/descending_freq（来自 bd283c4a）；按数量排序/count_ordering（来自 b1986d4b）

**依赖链**：同色匹配计数 → 计数值同时决定排序键和点数 → 排序决定堆叠顺序 → 堆叠 + 绘点生成输出。计数具有双重角色（排序 + 渲染），去掉计数则排序和点数均不可知；去掉排序则堆叠顺序不确定；去掉堆叠则框架保持原位。

统计每个空心框架的同色小图案数量，按数量降序将框架纵向堆叠，并在每个框架内部用点标示其数量。

**输入结构**：黑(0)背景，约 18x18 网格。3-5 个空心矩形框架，每个框架由单一颜色构成（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，各框架颜色互不相同），框架大小各异但内部至少 3 行 5 列（保证能容纳点）。若干小型单色图案精灵体（3-5 像素，4-连通，不规则形状）散布在框架之外的背景区域，每个精灵体的颜色与某一个框架颜色相同。每种颜色对应的精灵体数量互不相同（无平局），范围 1-5 个。生成约束：框架互不重叠且不与精灵体重叠。

**规则**：
1. 对每个框架颜色 C，统计网格中与之同色的精灵体数量，记为该框架的"计数值" T_C。
2. 擦除所有精灵体（替换为背景色）。
3. 将各框架按计数值从大到小排序。
4. 裁剪每个框架至其边界框，然后在新的输出网格上从上到下依次堆叠：计数值最大的框架在最上方，次大的在其下方，以此类推。所有框架左对齐。相邻框架之间间隔 1 行背景。输出网格宽度等于最宽框架的宽度，高度恰好容纳所有框架加间隔。
5. 在每个堆叠后的框架内部，沿框架内腔的中间行（若内腔行数为偶数则取上中行）从左侧内壁起每隔 1 个空格绘制一个点（点颜色为该框架自身颜色），共绘制 T_C 个点。即：第 1 个点在内壁左起第 1 列，第 2 个点在左起第 3 列，第 3 个点在左起第 5 列，以此类推。

**关键洞察**：计数值承担双重角色——既是排序的键（决定框架的上下位置），又是渲染的内容（决定框架内部绘制几个点）。求解者必须识别出同一数值在两个不同的操作中分别发挥作用。

## 新题 8：像素量排序驱动连接器对接顺序

**组合逻辑**：[计数/counting](已有) → [排序/sort](已有) → [拼接/stitch](已有，创新：对接顺序由计数值决定而非预设)；创新点在于对象的像素量大小决定组装的先后顺序，从而影响最终空间布局

**来源原语**：拼接/stitch、裁剪/crop、连接标记/connector_marker、前景物体/foreground_object、同色标记对齐对接/same_color_dock、标记侧面决定方向/marker_side_dir（来自 e9fc42f2）；计数/counting、排序/sort、按数量排序/count_ordering（来自 b1986d4b）；按频率降序/descending_freq（来自 bd283c4a）

**依赖链**：像素计数 → 尺寸排序 → 按排序顺序逐一对接。排序决定哪个物体先放置（作为锚），哪个后对接；不同排序顺序会导致不同的空间布局；去掉计数则排序无据，去掉对接则物体不组装。

多个带连接标记的前景物体按像素数从大到小依次对接组装：最大的先定位，后续物体通过同色连接标记逐一拼合。

**输入结构**：黑(0)背景，约 20x20 网格。3-4 个分离的 4-连通前景物体，每个物体的主体为灰(5)，形状不规则（6-20 像素），边界上有 1-2 个彩色连接标记像素（单像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取）。每种连接标记颜色恰好出现两次，分布在两个不同物体上。各物体的总像素数（主体 + 连接标记）互不相同。连接标记位于物体边界的外露侧（即该标记至少有一个 4-相邻格子是背景）。生成约束：按像素数排序后逐一对接时，每步恰好有唯一的连接标记颜色可以将当前物体与已放置的组合体匹配（无歧义选择）。

**规则**：
1. 计算每个物体的总像素数（灰(5)主体 + 所有连接标记像素）。
2. 按像素数从大到小排序。
3. 将最大的物体裁剪至其边界框，放置在输出的中心（若输出尺寸未定，先记录相对位置）。
4. 对排序中的下一个物体：找到该物体上与已放置组合体共享的连接标记颜色 C。将该物体平移，使该物体上颜色为 C 的标记像素与已放置组合体上颜色为 C 的标记像素 4-相邻，且两个标记分别在各自物体的外露侧相对。
5. 重复步骤 4 直到所有物体均已对接。
6. 对接完成后，擦除所有连接标记像素（替换为灰(5)主体色）。
7. 将最终组合体紧凑裁剪在背景上输出。

**关键洞察**：对接顺序并非由连接标记的颜色或位置决定，而是由物体的像素量排序决定。在求解的某些示例中，如果排序不同，同一组连接标记可能产生不同的空间拓扑。求解者需要发现排序规则是驱动组装过程的隐式逻辑。

## 新题 9：跨障碍交换后参照行对齐

**组合逻辑**：[交换/swap](已有) → [对齐/align](已有，创新：对齐操作仅在交换完成后的新位置上才有意义)；创新点在于交换创造了对齐操作的前提条件——交换前对齐无法触发

**来源原语**：交换/swap、擦除/erase、标记像素/marker_pixel、障碍段/barrier_segment、跨障碍配对/cross_barrier_pair、同行列两侧各一/one_each_side（来自 1efba499）；对齐/align、滑动/shift、双色条/two_color_bar、参考条/reference_bar、同色对齐/same_color_align、首行为参照/top_row_reference（来自 9968a131）

**依赖链**：跨障碍配对 → 交换移动 → 交换后的双色条进入参照行的管辖区域 → 对齐操作触发。交换将双色条从障碍一侧移到另一侧，使其首次受到参照行的对齐约束；去掉交换则双色条不在参照行一侧故无需对齐，去掉对齐则交换后颜色顺序可能错误。

双色条与标记像素跨障碍交换位置后，移至障碍另一侧的双色条需要根据参照行的颜色列对齐进行水平调整。

**输入结构**：黑(0)背景，约 12x15 网格。一条灰(5)水平障碍段横跨网格中部（单像素高，覆盖大部分列）。障碍上方靠近顶部有一个参考条：一行中两个相邻像素，颜色分别为蓝(1)和红(2)（如第 1 行的第 c 列为蓝(1)、第 c+1 列为红(2)）。障碍上方（参考条下方、障碍上方之间的区域）有若干行，每行包含一个双色条（两个相邻像素，各为蓝(1)和红(2)，顺序可能与参考条相同或相反）。障碍下方有同样数量的行，每行包含一个单独的标记像素（颜色为绿(3)），其列位置与障碍上方某个双色条的列位置在同一列范围内。每个双色条与其正下方（穿过障碍后同列）的标记像素构成跨障碍配对。生成约束：配对是一一对应的，每行至多一个双色条或标记。

**规则**：
1. 识别跨障碍配对：对穿过障碍段的每一列，检查障碍上方是否有双色条像素、下方是否有标记像素。在同一行或同一列范围内的双色条和标记像素形成配对（每对中双色条在上、标记在下）。
2. 执行交换：将每对中的双色条移至障碍正下方（紧贴障碍下一行，保持水平位置不变），将标记像素移至障碍正上方（紧贴障碍上一行，保持水平位置不变）。擦除双色条和标记的原始位置。
3. 交换后，双色条现在位于障碍下方。但障碍上方的参考条仍在原位。对齐规则：检查每个现位于障碍下方的双色条的左像素颜色是否与参考条的左像素颜色相同。若相同，该双色条位置不变。若不同（即双色条颜色顺序与参考条相反），将该双色条整体水平平移，使其左像素所在列对齐到参考条中与之同色的像素所在列。
4. 平移后腾出的格子变为背景色。标记像素（现在障碍上方）不受对齐规则影响。
5. 障碍段和参考条保持不变。

**关键洞察**：对齐操作是交换操作的"后置约束"——在交换之前，双色条位于障碍上方，与参照行同侧，理论上已经可以对齐，但实际上它们的位置在交换前是自由的（输入中可以有不对齐的条）。交换将它们推到障碍另一侧，此时对齐规则才被激活。求解者需要理解交换不只是移动，还是触发后续约束的前提。

## 新题 10：轴色决定碎片旋转后互补拼合

**组合逻辑**：[移动/move + 互补拼合/complement_fit](已有) + [旋转/rotate](已有，创新：旋转与否由碎片所在边缘的轴线颜色决定)；创新点在于轴线颜色编码了碎片的预处理方式（旋转/不旋转），预处理结果影响拼合的空间匹配

**来源原语**：移动/move、补全/complete、碎片/fragment、锚定物体/anchor_object、矩形/rectangle、互补拼合/complement_fit、同色碎片拼成矩形/same_color_join、碎片触边锚不触边/frag_edge_anchor（来自 fe45cba4）；旋转/rotate、坐标轴线/coordinate_axis_line、轴色决定旋转/axis_color_determines_rotation（来自 291dc1e1）

**依赖链**：碎片边缘位置检测 → 该边缘的轴线颜色判断 → 决定是否旋转碎片 → 旋转后的碎片与锚定物体互补拼合为矩形。轴色决定预处理；预处理影响拼合方式；去掉轴色判断则旋转决策不可知，去掉互补拼合则碎片目标位置不可知。

网格边缘有两条不同颜色的轴线，触及某轴线边缘的碎片需要根据该轴线颜色决定是否旋转 90 度，然后平移到其同色锚定物体旁完成矩形拼合。

**输入结构**：黑(0)背景，约 16x16 网格。两条轴线沿网格的两条相邻边缘延伸（例如左边缘为蓝(1)垂直轴线、上边缘为红(2)水平轴线），在角落像素处以黄(4)标记交点。网格内部有 2-3 对同色碎片组：每对由同一颜色（从绿(3)、灰(5)、橙(7)中选取，各对颜色互不相同）的两个 4-连通物体组成。每对中的一个物体（"碎片"）触及有轴线的网格边缘（即碎片的某些像素位于轴线所在的行或列上，与轴线 4-相邻），另一个物体（"锚"）不触及任何网格边缘。每对碎片和锚的像素可以拼合为一个实心矩形（但碎片可能需要旋转才能拼合）。生成约束：触及蓝(1)轴线边缘的碎片需要旋转 90 度顺时针后才能与其锚互补拼合为矩形；触及红(2)轴线边缘的碎片不需旋转即可直接平移拼合。轴线像素、交点像素不属于任何碎片。

**规则**：
1. 对每种前景颜色 C（排除轴线颜色蓝(1)、红(2)和交点颜色黄(4)），找到该颜色的两个 4-连通物体。将触及有轴线的网格边缘的物体标记为"碎片"，不触边的标记为"锚"。
2. 确定碎片触及的是哪条轴线的边缘：若碎片与蓝(1)轴线所在边缘相邻，则将碎片绕其边界框中心旋转 90 度顺时针。若碎片与红(2)轴线所在边缘相邻，则碎片保持原状。
3. 将（可能已旋转的）碎片平移到唯一使其与锚的并集恰好构成一个实心矩形的位置。
4. 擦除碎片原始位置的像素（替换为背景色），在新位置绘制碎片像素。
5. 锚、轴线和交点保持不变。其他颜色的碎片组独立处理，互不影响。

**关键洞察**：碎片需不需要旋转不是由碎片自身的形状决定的，而是由其所在边缘的轴线颜色决定的。同一形状的碎片如果贴在不同颜色的轴线旁，会经历不同的预处理。求解者必须先识别边缘的颜色编码体系，才能正确执行拼合。
