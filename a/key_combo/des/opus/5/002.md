## 新题 1：遮挡排序驱动的射线分区重涂色

**组合逻辑**：[occlusion_order + crossing_visibility](已有) → [ray_extend + order_determines_block](已有，创新：射线发射顺序由遮挡图决定而非空间位置) → [recolor + adjacency_color_transfer](已有，创新：每个分区继承其边界射线所属边框的颜色)

**来源原语**：occlusion_order, crossing_visibility, sort (c920a713); ray_extend, order_determines_block (1190bc91); recolor, adjacency_color_transfer (800d221b)

**依赖链**：必须先从边框交叉点的可见性推断出遮挡有向图，再将该图拓扑排序得到射线发射顺序；射线发射顺序决定了哪些射线先占位从而阻断后续射线，产生不同的空间分区；最后每个分区的颜色取决于界定它的射线属于哪个边框。三步中任何一步被跳过，后续都无法确定。

从重叠的彩色矩形边框中推断遮挡顺序，按该顺序从每个边框中心发射对角射线分割背景，再将每个分区涂为其边界射线所属边框的颜色。

**输入结构**：约 25x25 的黑(0)背景网格。包含 4 个单像素宽的轴对齐矩形边框，每个边框各用一种不同的前景色（如蓝(1)、红(2)、绿(3)、黄(4)）。边框之间有部分重叠，重叠处仅显示一种颜色——可见色覆盖被遮挡色，形成有向遮挡关系。每个边框的几何中心位置可从其可见像素的包围盒推断（即使某些边被遮挡，包围盒仍可确定）。生成约束：4 个边框的遮挡关系构成一条无环链（即存在唯一的拓扑排序），每对相邻边框至少有一个交叉点可见。

**规则**：
1. 对每个前景色，从其所有可见像素的包围盒恢复该矩形边框的完整几何形状（4 条边的行列范围）。
2. 对每对边框 A 和 B，检查它们边框线的交叉像素：若交叉位置显示 B 的颜色（即 B 遮挡了 A），记一条有向边 A->B。
3. 对所有有向边做拓扑排序，得到唯一顺序（最底层在前，最顶层在后）。
4. 按该拓扑顺序依次处理每个边框：从该边框几何中心向四个 45 度方向（左上、右上、左下、右下）发射射线，每条射线逐像素前进，遇到已被射线绘制过的像素或网格边界时停止（不含终点）。射线像素绘制为该边框的颜色。
5. 射线绘制完毕后，将所有仍为黑(0)的背景像素按以下规则涂色：对每个黑像素，找到其 4-连通区域的边界上最近的射线像素，涂为该射线像素的颜色。若 4-连通区域边界上有多种射线颜色，取接触像素数最多的颜色。
6. 原有的矩形边框像素（含被遮挡的部分）保持不变，恢复为各自的原色。

**关键洞察**：射线发射的先后顺序完全由边框的遮挡层级决定——底层边框先发射射线，其射线会阻断顶层边框后续的射线扩展，导致空间分区的形状依赖于遮挡图的拓扑结构而非边框的空间位置。

## 新题 2：面积匹配的模板印章填入轮廓腔体

**组合逻辑**：[count + area_matching](已有，创新：计数对象从源像素集变为模板图块，匹配目标从单个轮廓变为多个轮廓) → [stamp_overlay](已有，创新：印章不是按标记位置放置，而是按面积匹配结果放入对应腔体) → [erase](已有)

**来源原语**：stamp_overlay, template_tile, marker_position (e734a0e8); count, area_matching, outline_object, row_interior, erase (7acdf6d3); count_maps_to_size (878187ab)

**依赖链**：必须先同时计算每个模板的像素数和每个轮廓的腔体面积，再通过面积相等关系建立一一匹配，最后将匹配的模板印入对应腔体。跳过计数则无法建立匹配；跳过匹配则不知道哪个模板放入哪个腔体。

统计多个模板图块的像素数和多个封闭轮廓的内腔面积，按面积相等进行一一匹配，将每个模板印入其匹配轮廓的内腔并擦除模板原位。

**输入结构**：约 20x25 的黑(0)背景网格。网格中散布 3 个互不相邻的小型模板图块（每个 3~8 像素，4-连通，单色，各用不同颜色如蓝(1)、红(2)、绿(3)，形状不规则且各不相同）。另有 3 个用灰(5)像素绘制的封闭轮廓对象（单像素宽的 8-连通闭合环，内部全为黑(0)背景）。每个轮廓的行向内腔面积（对每一占用行，统计最左与最右轮廓像素之间的背景像素数之和）恰好等于某一个模板的像素数，且三对匹配互不冲突（即三个内腔面积互不相同）。模板与轮廓在空间上不接触。生成约束：每个轮廓的内腔是简单连通的（无内部岛屿），内腔的行数和列数都不小于对应模板的包围盒行数和列数。

**规则**：
1. 识别所有灰(5)的 8-连通闭合轮廓。对每个轮廓，计算其行向内腔面积：对该轮廓像素占据的每一行，统计该行上最左和最右灰像素之间（不含灰像素本身）的黑(0)像素数量，求和得到该轮廓的内腔面积。
2. 识别所有非黑、非灰的 4-连通前景色图块（即模板），统计每个模板的像素总数。
3. 将每个模板与内腔面积等于该模板像素数的轮廓配对（一一对应）。
4. 对每对匹配：将模板图块逐像素复制到对应轮廓的内腔中，以内腔包围盒的左上角为锚点，模板的包围盒左上角与之对齐。复制时保持模板的颜色不变。
5. 擦除模板在原位置的所有像素（替换为黑(0)）。
6. 灰色轮廓像素保持不变。

**关键洞察**：模板和轮廓之间没有颜色关联或空间邻近关系——唯一的配对线索是像素数与腔体面积的数值相等，必须两侧都计数才能建立对应。

## 新题 3：线路网络上的条纹传播与能量上限

**组合逻辑**：[wire_network + endpoint_pairing](已有) → [stripe_propagation + color_cycle](已有，创新：条纹沿非直线的线路路径传播而非沿行/列直线传播) → [length_maps_color + energy_caps_steps](创新组合：条形段长度编码能量值，限制条纹传播距离)

**来源原语**：wire_network, endpoint_pairing, transmit (a47bf94d); stripe_propagation, color_cycle, stripe_scope_difference (221dfab4); incremental_charge, energy_caps_steps (271d71e2); bar_segment, length_maps_color (e048c9ed)

**依赖链**：必须先识别线路网络并配对端点，再从条形段端读取能量值（长度），最后沿线路路径传播条纹直到能量耗尽。跳过端点配对则不知道传播方向；跳过能量读取则不知道在何处停止。

沿线路网络的路径传播颜色循环条纹，传播起点处的条形段长度决定最多能传播多少个条纹周期。

**输入结构**：约 20x20 的黑(0)背景网格。包含 3 条独立的灰(5)线路网络（单像素宽的 4-连通路径，可有拐弯但无分叉）。每条线路的一个端点紧邻一个水平单色条形段（条形段颜色为蓝(1)、红(2)或绿(3)之一，每条线路不同），条形段长度在 2~5 像素之间。另一端点无条形段。线路路径长度（灰色像素数）在 10~20 之间。生成约束：每条线路不与其他线路接触；条形段不与线路灰色像素重叠，仅端点的一个 4-邻居与条形段的一端相邻。

**规则**：
1. 识别所有灰(5)的 4-连通线路路径。每条线路有恰好两个端点（仅一个灰色 4-邻居的灰像素）。
2. 对每条线路，找到与某个彩色条形段相邻的端点作为"源端点"，另一端为"目标端点"。
3. 读取条形段的像素长度 L，作为该线路的能量值。
4. 从源端点出发，沿线路路径逐像素向目标端点前进。按固定的 3-色循环（红(2), 黄(4), 蓝(1)）依次给路径上的灰像素涂色：第 1 个涂红(2)，第 2 个涂黄(4)，第 3 个涂蓝(1)，第 4 个涂红(2)，依此循环。
5. 每完成一个完整的 3-色循环（即每涂 3 个像素），消耗 1 点能量。当能量耗尽（已消耗 L 个完整循环，即已涂 3*L 个像素）后，剩余路径像素保持灰(5)不变。若路径总长不足 3*L，则全部涂色（能量未耗尽）。
6. 条形段本身保持原色不变。

**关键洞察**：条纹不沿直线传播而是沿任意形状的线路路径蜿蜒前进——条形段长度限定了能量而非直接限定距离，因为能量按"完整循环数"计算而非按像素数计算，所以实际传播的像素数是能量值的 3 倍。

## 新题 4：对角线编码优先级的分区压缩与循环着色

**组合逻辑**：[separator_line → quadrant](已有) + [diagonal_line → count](创新组合：对角线像素数编码区域优先级) → [sort + cyclic_color_assignment](已有，创新：排序键来自对角线编码而非空间位置或面积) → [compress + denoise_majority](已有)

**来源原语**：compress, cross_separator, quadrant, denoise_majority (996ec1f3); sort, scan_order, cyclic_color_assignment (9473c6fb); diagonal_line, count_maps_to_size (878187ab)

**依赖链**：必须先用分隔线划分区域，再在每个区域内提取对角线并计数得到优先级，按优先级排序后循环分配颜色，最后压缩为小网格。跳过对角线计数则无法确定排序；跳过排序则循环着色结果不确定。

用分隔线将网格切分为若干区域，每个区域内的对角线段像素数编码该区域的优先级；按优先级排序后循环分配输出颜色，最终压缩为一个小网格。

**输入结构**：约 21x21 的黑(0)背景网格。一条完整的水平灰(5)行和一条完整的垂直灰(5)列将网格切分为 4 个矩形区域（类似十字分隔，但交叉点不一定在正中央）。每个区域内包含：(a) 若干散布的噪声像素（使用该区域的主色之外的随机前景色，共 2~4 个噪声像素）；(b) 一种数量最多的主色（蓝(1)、红(2)、绿(3)、黄(4)中的一种，每个区域的主色不同），以小块形式存在；(c) 恰好一条橙(7)的 45 度对角线段（3~7 像素长，8-连通，从左下到右上或从左上到右下）。四个区域的对角线段长度互不相同。生成约束：每个区域的主色像素数至少是噪声像素数的 3 倍。

**规则**：
1. 找到唯一的全灰(5)行和全灰(5)列，确定十字分隔线。
2. 十字分隔线将网格分为 4 个矩形区域（左上、右上、左下、右下）。
3. 对每个区域，识别其中的橙(7)对角线段并统计其像素数 D，作为该区域的优先级值。
4. 对每个区域，统计非黑(0)、非灰(5)、非橙(7)的前景色中出现次数最多的颜色，作为该区域的主色。
5. 将 4 个区域按优先级值 D 从小到大排序。
6. 按排序后的顺序，依次将各区域的输出色分配为循环序列中的颜色：第 1 个（最小 D）分配蓝(1)，第 2 个分配红(2)，第 3 个分配绿(3)，第 4 个分配黄(4)。
7. 输出一个 3x3 网格：中间行和中间列填灰(5)（对应分隔线），四个角落分别填入对应区域被分配的输出色（左上角对应左上区域，右上角对应右上区域，左下角对应左下区域，右下角对应右下区域）。

**关键洞察**：输出角落的颜色既不是区域的主色，也不是按区域空间位置直接决定的——而是由区域内对角线段的长度决定排序后再循环分配的结果。必须对比多个示例才能发现对角线长度才是排序键，而非主色本身或区域面积。

## 新题 5：镜像补全与种子区域传色

**组合逻辑**：[guide_line + axis_determines_op → mirror](已有) + [complete + occluded_shape](已有，创新：补全方式不是填包围盒而是跨轴镜像) → [seed_region + adjacency_color_transfer + adjacency_count_determines_color](已有，创新：传色目标从路径网络变为镜像补全区域)

**来源原语**：complete, occluded_shape, foreground_occlusion, implied_region_recolor (52df9849); mirror, guide_line, axis_determines_op (4e7e0eb9); seed_region, adjacency_color_transfer, adjacency_count_determines_color (800d221b)

**依赖链**：必须先识别引导线确定镜像轴，再将轴一侧的部分形状镜像到另一侧完成补全（得到补全区域的几何位置），最后根据补全区域与种子区域的邻接关系确定补全部分的颜色。跳过镜像则不知道补全的像素位置在哪里；跳过种子邻接则不知道补全部分用什么颜色。

跨引导线镜像补全不完整的前景形状，补全部分的颜色不继承原色，而由相邻种子区域的颜色决定。

**输入结构**：约 18x18 的黑(0)背景网格。包含 2 条灰(5)引导线（一条完整水平线，一条完整垂直线，它们不一定交叉——可能分布在网格的不同区域）。每条引导线的一侧有一个不完整的蓝(1)前景形状（4-连通，5~10 像素，形状不规则），该形状的像素全部位于引导线的一侧且至少有一个像素紧贴引导线。引导线的另一侧有一个小型种子区域（2~4 像素的 4-连通块），颜色为红(2)或绿(3)，紧邻引导线或距引导线 1~2 像素。生成约束：两条引导线分别对应不同的前景形状；每个形状的镜像补全区域与至少一个种子区域在 4-邻域上相邻；两个形状的镜像补全区域互不重叠；种子区域不与前景形状的原始像素相邻。

**规则**：
1. 识别所有完整的灰(5)水平行或垂直列，作为引导线。
2. 对每条引导线，识别其一侧紧贴引导线的蓝(1)前景形状。
3. 将该形状的所有像素关于引导线做镜像映射（水平引导线则上下翻转，垂直引导线则左右翻转），得到一组镜像像素位置。
4. 对每个镜像像素位置，检查其 4-邻域内是否存在种子区域（红(2)或绿(3)）像素。统计该镜像区域（所有镜像像素的集合）与每种种子颜色的总邻接像素对数。
5. 取邻接对数最多的种子颜色 C 作为该补全区域的颜色。若邻接对数相等，取在引导线方向上离引导线更近的种子区域的颜色。
6. 将所有镜像像素位置涂为颜色 C。
7. 原始蓝(1)形状、灰(5)引导线、种子区域像素均保持不变。

**关键洞察**：补全的几何形状由镜像决定，但补全的颜色由种子区域的邻接关系决定——同一个形状在不同示例中可能因为种子区域位置不同而被补全为不同颜色，迫使求解者同时推断几何规则和颜色规则。

## 新题 6：字形表查询驱动的边界循环铺设

**组合逻辑**：[table_lookup + glyph_cell + reference_table](已有) → [border_segment → cyclic_period + tile](已有，创新：铺设的颜色序列来自字形表查询结果而非单一颜色重复) → [alignment_verdict → repeat_equal_gap](创新组合：对齐判定结果改变铺设间距)

**来源原语**：tile, border_segment, cyclic_period, repeat_equal_gap (30f42897); table_lookup, glyph_cell, reference_table, alignment_verdict (d8e07eb2); decoding, encoding_map (65b59efc)

**依赖链**：必须先从边界段长度解码出行索引，再在字形表中查找该行得到颜色序列，然后判断该行是否满足对齐条件以确定间距参数，最后用颜色序列和间距在边界上循环铺设。跳过表查询则无铺设颜色序列；跳过对齐判定则间距不确定。

从边界段长度解码字形表行号，查出该行的颜色序列，根据该行的列对齐判定决定铺设间距，将颜色序列循环铺设在矩形边界上。

**输入结构**：约 20x22 的网格。上半部分（约前 10 行）是一个字形参考表：青(8)背景上排列着若干 3x3 的字形单元格，以品红(6)分隔列（1 像素宽）隔开，共 4 列 3 行 = 12 个字形。每个字形由其 3x3 区域内的非青色像素构成（使用蓝(1)、红(2)、绿(3)、黄(4)之一，每个字形单色）。上半部分和下半部分由一条完整的品红(6)水平分隔行隔开。下半部分（约后 10 行）是黑(0)背景的方形区域，该区域的矩形边界上有一段连续的橙(7)边界段（位于边界的某条边上，长度在 1~3 之间）。生成约束：字形表中每行的 4 个字形使用 4 种不同颜色；橙色边界段的长度不超过表的行数。

**规则**：
1. 识别品红(6)水平分隔行，将网格分为上方字形表和下方边界区域。
2. 在字形表中，用品红(6)垂直分隔列将每行分成若干 3x3 单元格。表的行号从上到下为 1, 2, 3...
3. 在下方区域的矩形边界上，找到橙(7)段并统计其长度 L。
4. 以 L 为行号，在字形表中查找第 L 行的所有字形，从左到右读取每个字形的颜色，得到颜色序列 [C1, C2, C3, C4]。
5. 检查第 L 行的 4 个字形的颜色是否恰好与表中某一列的 4 种颜色完全相同（顺序无关、仅检查集合相等）——即该行的颜色集合是否与某列的颜色集合一致。若一致，定义间距 G = 1；若不一致，定义间距 G = 2。
6. 从橙(7)段的起始位置出发，沿边界顺时针方向铺设：先绘制颜色序列 [C1, C2, C3, C4] 各占 1 个边界像素，然后跳过 G 个像素（保持黑(0)），再铺下一轮 [C1, C2, C3, C4]，再跳 G，如此循环直到回到起始位置。若剩余空间不足以放完一整个序列，则只放能放下的部分。
7. 橙(7)段的原始像素被铺设的颜色覆盖。上方字形表区域保持不变。

**关键洞察**：边界段的长度不是铺设的重复单元大小，而是字形表的行地址——必须经过"长度 -> 行号 -> 查表 -> 颜色序列"的间接解码才能确定铺设内容，并且表的列对齐属性决定了铺设间距。

## 新题 7：嵌入分类修复后的镜像滑动对齐

**组合逻辑**：[embedded_vs_isolated → repair](已有，创新：修复改变精灵体外形为后续步骤提供不同输入) → [separator_line + mirror + cross_axis_symmetry](已有，创新：对修复后的精灵体做局部镜像) → [slide_to_align + color_match_anchor + edge_position_determines_axis](已有)

**来源原语**：slide_to_align, multicolor_sprite, border_anchor, color_match_anchor, edge_position_determines_axis (581f7754); repair, embedded_vs_isolated, marker_pixel, main_object (8886d717); mirror, cross_axis_symmetry (538b439f); separator_line (538b439f)

**依赖链**：修复嵌入标记改变精灵体的像素组成 → 改变后的精灵体做镜像时产生不同的对称形状 → 镜像后的精灵体中孤立标记的位置发生变化 → 该标记位置决定了与锚点对齐时的偏移量。链条中任一步的结果都传递给下一步并产生实质性的几何变化。

先将多色精灵体中嵌入的标记像素修复为主色，再将修复后的精灵体沿其内部分隔线镜像翻转，最后将镜像后的精灵体滑动对齐到颜色匹配的边界锚点。

**输入结构**：约 18x18 的黑(0)背景网格。包含 2 个多色精灵体，每个约 4x5 像素的包围盒。每个精灵体有一种主色（蓝(1)或绿(3)），占据其大部分像素（6~12 个），外加 2~3 个橙(7)标记像素。标记像素中，1~2 个是嵌入的（其 4-邻居中至少 3 个为主色），其余是孤立的（其 4-邻居中至少 3 个为黑(0)背景，且与精灵体仅以 1 个 4-邻居相连）。每个精灵体内部包含一行或一列连续的灰(5)像素，作为该精灵体的局部分隔线（不延伸到精灵体外部），长度等于精灵体在该方向的跨度。网格的 4 条边界上各有 0~1 个孤立的锚点像素：蓝(1)锚点和绿(3)锚点各一个，位于不同的边界边上。生成约束：每个精灵体修复嵌入标记并镜像后，恰好剩余 1 个孤立标记像素；两个精灵体的滑动路径互不冲突。

**规则**：
1. 对每个精灵体，识别其主色（占多数的非黑、非灰、非橙颜色）。
2. 分类每个橙(7)标记像素：若其 4-邻居中主色像素数 >= 3，则为"嵌入"；否则为"孤立"。
3. 将所有嵌入标记像素重涂为该精灵体的主色。
4. 识别精灵体内部的灰(5)局部分隔线，确定它是水平还是垂直。
5. 将修复后的精灵体（含灰色分隔线但不含孤立标记）关于该分隔线做镜像：水平分隔线则上下翻转，垂直分隔线则左右翻转。镜像结果覆盖原精灵体位置（分隔线像素不动，两侧像素互换）。
6. 孤立标记像素随其所在侧一起参与镜像移动。镜像后定位每个精灵体剩余的孤立标记像素位置。
7. 在网格边界上找到颜色与精灵体主色相同的锚点。若锚点在上边或下边，将精灵体整体水平平移使孤立标记的列坐标与锚点的列坐标对齐。若锚点在左边或右边，将精灵体整体垂直平移使孤立标记的行坐标与锚点的行坐标对齐。
8. 平移后精灵体原位置恢复为黑(0)背景。

**关键洞察**：修复嵌入标记看似只是"消除噪声"，但它改变了精灵体的像素分布，导致镜像后孤立标记出现在不同位置——最终滑动对齐的偏移量因此改变。每一步的几何变换都实质性地影响最终输出。

## 新题 8：枢纽射线分区与种子洪泛的双向信息流

**组合逻辑**：[hub_square → ray_extend → ray_partition](创新组合：从枢纽中心发射射线分割空间，而非从线性序列的像素发射) + [seed_region + flood_fill](已有，创新：洪泛范围受射线分区约束) → [adjacency_count_determines_color](已有，创新：枢纽颜色由洪泛面积最大的种子决定——信息从分区回流到枢纽)

**来源原语**：path_network, hub_square, seed_region, adjacency_color_transfer, adjacency_count_determines_color (800d221b); ray_extend, ray_partition (1190bc91); flood_fill (1190bc91); separator_line, sep_color_fills_gap (538b439f)

**依赖链**：枢纽位置决定射线方向 → 射线分割空间为扇区 → 每个扇区内种子洪泛至扇区边界 → 洪泛面积决定枢纽颜色。信息从枢纽流出（射线）又流回枢纽（颜色），形成双向依赖。

从中心枢纽向四个对角方向发射射线将网格分割为扇区，每个扇区内的种子区域洪泛填充至射线边界，洪泛面积最大的种子颜色回传给枢纽中心。

**输入结构**：约 21x21 的黑(0)背景网格。网格中央偏某方向有一个 3x3 的灰(5)实心正方形作为枢纽。散布在网格中（枢纽外部）有 4 个小型种子区域（各 2~5 像素的 4-连通块），颜色分别为蓝(1)、红(2)、绿(3)、黄(4)。生成约束：枢纽不在网格正中心（使四个扇区面积不等）；4 个种子区域分布在枢纽的不同方位（但不要求每个对角扇区各一个——某些扇区可能无种子，某些扇区可能有两个）；种子区域不与枢纽相邻（至少间隔 2 像素）。

**规则**：
1. 找到 3x3 的灰(5)枢纽正方形，记其中心像素坐标为 (hr, hc)。
2. 从 (hr, hc) 向四个 45 度方向（左上、右上、左下、右下）各发射一条射线：射线逐像素沿对角方向前进，将经过的像素涂为灰(5)，直到到达网格边界为止。
3. 四条射线将网格分为 4 个扇区（上、下、左、右）。扇区的归属规则：射线像素和枢纽像素不属于任何扇区；其余像素按其相对于枢纽中心的方位归入扇区——正上方（行 < hr 且列 = hc 的列附近）为上扇区，依此类推。精确定义：像素 (r, c) 属于上扇区当 r < hr 且 |c - hc| < hr - r；属于右扇区当 c > hc 且 |r - hr| < c - hc；属于下扇区当 r > hr 且 |c - hc| < r - hr；属于左扇区当 c < hc 且 |r - hr| < hc - c。落在扇区边界上（|c - hc| = |r - hr|）的像素已被射线覆盖，归为灰色。
4. 对每个扇区，找到其中的种子区域。若该扇区有种子区域，从种子的每个像素出发做 4-连通洪泛填充：将扇区内所有可达的黑(0)像素涂为该种子的颜色，洪泛不跨越灰(5)射线像素、枢纽像素或网格边界。若一个扇区有多个种子，按包围盒左上角从上到下、从左到右的顺序依次洪泛，后洪泛的不覆盖已被涂色的像素。
5. 洪泛完成后，统计每种种子颜色的洪泛总面积（所有扇区中该颜色的洪泛像素数之和）。
6. 将枢纽 3x3 区域的中心像素 (hr, hc) 重涂为洪泛总面积最大的种子颜色。枢纽的其余 8 个像素保持灰(5)。若两种颜色面积相等，取在输入中种子区域像素数较少的那种颜色（即原始种子更小但洪泛更大，说明它占据了更大的空间）。

**关键洞察**：枢纽既是空间分割的"发射源"（射线从枢纽出发），又是颜色信息的"接收者"（颜色从洪泛结果回流）——信息先从枢纽向外流出划定边界，再从边界内的洪泛结果向枢纽回流，形成一个需要完整执行才能确定枢纽颜色的闭环。

## 新题 9：条形段长度排序渲染为同心方框

**组合逻辑**：[bar_segment + count + length_maps_color](已有) → [sort](已有，创新：排序依据从遮挡可见性变为条形段长度) → [redraw + concentric_frame](已有，创新：同心方框的颜色序列不来自重叠边框的拓扑排序，而来自条形段长度排序)

**来源原语**：counting, bar_segment, length_maps_color, fixed_encoding (e048c9ed); sort, redraw, concentric_frame, traverse_all_colors (c920a713); compress, denoise_majority (996ec1f3)

**依赖链**：必须先测量每个条形段的长度，再按长度排序确定从外到内的环顺序，最后将排序后的颜色渲染为同心方框。跳过长度测量则排序无依据；跳过排序则方框嵌套顺序不确定。

测量散布的水平条形段长度，按长度从大到小排序，将每个条形段的颜色渲染为从外到内的同心方框环。

**输入结构**：约 15x20 的黑(0)背景网格。包含 4~5 条水平单色条形段，每条占据一行中的若干连续像素，各条形段不在同一行。每条使用不同的前景色（从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取），长度在 2~8 之间且互不相同。条形段之间无重叠或接触。生成约束：条形段数量 N 满足 2*N - 1 <= min(网格行数, 网格列数)，以保证同心方框可以完整渲染。

**规则**：
1. 识别所有水平条形段（单色、占据连续列的前景像素行段）。
2. 记录每条的颜色和长度（像素数）。
3. 按长度从大到小排序。若存在长度相同的情况（生成约束已排除此情况，但作为规则完备性说明），取行号较小的优先。
4. 生成一个 (2N-1) x (2N-1) 的输出网格，其中 N 为条形段数量。
5. 最外圈（第 0 环）用排序后第 1 条（最长）的颜色绘制：即输出网格的第 0 行、第 2N-2 行、第 0 列、第 2N-2 列的所有像素涂为该颜色。
6. 第 k 环（k = 1, 2, ..., N-1）用排序后第 k+1 条的颜色绘制：第 k 行与第 2N-2-k 行在列范围 [k, 2N-2-k] 内、第 k 列与第 2N-2-k 列在行范围 [k, 2N-2-k] 内的像素涂为该颜色。
7. 环之间自然嵌套（内环覆盖外环在交角处的像素），最内圈（第 N-1 环）退化为单像素。

**关键洞察**：输入是一组一维的水平条形段，输出是二维的同心方框——两种完全不同的几何表示之间的桥梁是长度排序，必须意识到条形段的长度（而非颜色、位置或出现行号）决定了方框的嵌套顺序。

## 新题 10：分隔门控的令牌传输与形状循环碰撞

**组合逻辑**：[cross_separator + quadrant](已有，创新：分隔线上的间隙作为门控通道) + [transmit + token + shape_cycle_mapping](已有，创新：传输路径从线路网络变为分隔线间隙) → [scan_order + foreground_occlusion](创新组合：碰撞时按扫描序决定优先级)

**来源原语**：shape_transform, transmit, token, shape_cycle_mapping, endpoint_pairing (a47bf94d); cross_separator, quadrant (996ec1f3); scan_order (9473c6fb); foreground_occlusion (52df9849); translate (271d71e2)

**依赖链**：必须先识别分隔线上的间隙位置确定可传输方向，再按形状循环规则变换传输的令牌形状，最后若两个令牌试图进入同一象限则用扫描序解决碰撞。三步紧耦合：门控位置决定传输方向，传输触发形状变换，碰撞则需要扫描序判定。

令牌通过十字分隔线上的间隙传输到相邻象限，传输时形状按固定循环变换；若两个令牌目标象限相同，扫描序靠前的优先进入，另一个留在原位不变。

**输入结构**：约 17x17 的黑(0)背景网格。一条近乎完整的水平灰(5)行和一条近乎完整的垂直灰(5)列形成十字分隔线，将网格分为 4 个象限。十字线上恰有 2 个间隙（间隙 = 该位置的灰色像素被替换为黑(0)背景，每个间隙 1 像素宽）——一个在水平线上，一个在垂直线上，位于不同的半段。每个间隙连接两个相邻象限。4 个象限中恰有 2 个各包含一个 3x3 的单色令牌（实心方块、X 形或菱形之一），令牌颜色各不同（如蓝(1)和红(2)），放置在象限内部（不贴分隔线）。另外 2 个象限为空。形状定义：实心方块 = 3x3 全填充；X 形 = 四角 + 中心共 5 像素；菱形 = 中心 + 上下左右共 5 像素。生成约束：每个令牌至少通过一个间隙可到达一个空象限；十字线交叉点的像素始终为灰(5)。

**规则**：
1. 识别灰(5)十字分隔线及其上的 2 个间隙位置。
2. 每个间隙连接两个相邻象限。对每个含令牌的象限，若该象限与某间隙相邻（间隙在该象限的边界分隔线上），且间隙另一侧的象限为空，则该令牌可以传输到空象限。
3. 形状循环规则：实心方块 -> X 形 -> 菱形 -> 实心方块。令牌每通过一个间隙传输，形状前进一步。
4. 令牌传输时，保持颜色不变，在目标象限中放置变换后的形状。新令牌的中心位置为目标象限中心（象限行范围和列范围的中点，向下向右取整）。
5. 碰撞检测：若两个令牌都试图进入同一个空象限（通过不同的间隙），按扫描序（先比较令牌原象限的左上角行号，行号小的优先；行号相同则列号小的优先）决定谁进入。优先者传输并变换形状；另一个令牌留在原象限，形状和位置均不变。
6. 成功传输的令牌从原象限移除（原位恢复黑(0)）。
7. 分隔线（含间隙）保持不变——间隙仍为黑(0)，其余分隔像素仍为灰(5)。

**关键洞察**：分隔线不只是静态的区域划分——它上面的间隙充当传输通道，间隙的位置决定了哪些传输路径可行；而当多条可行路径汇聚到同一目标时，空间扫描序提供了一个需要对比多个示例才能归纳的隐蔽优先级规则。
