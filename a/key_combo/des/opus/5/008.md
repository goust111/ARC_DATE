## 新题 1：缺角编码逐位旋转的栅格印章

**组合逻辑**：[印章放置(stamp) + 栅格偏移(lattice_offset)](已有) → [缺角定位(missing_corner_loc)](创新：从标识三角形顶点改为编码旋转角度) → [旋转(rotate)](创新：每个印章副本独立旋转，角度由各自关联的缺角决定) → [重叠区域重涂(overlap_recolor)](已有)

**来源原语**：stamp、lattice_offset、overlap_recolor（来自 a395ee82）；rotate（来自 a32d8b75）；missing_corner_loc（来自 1478ab18）

**依赖链**：缺角位置编码每个栅格点的旋转角度 → 模板在各栅格点旋转后放置 → 多个旋转副本的空间重叠触发重涂色。旋转角度与放置位置由不同几何线索独立解码，但在空间重叠时产生交互。

将一个不规则模板按栅格布局印章式放置，每个副本的旋转角度由其关联的缺角方块独立编码，重叠区域重涂为第三色。

**输入结构**：约 20x20 的网格，背景黑(0)。网格中包含以下元素：
- **模板**：一个 4-连通单色小图形（蓝(1)，4~8 像素，不对称，无孔洞），作为最大的蓝(1)连通分量存在。
- **单像素布局点**：若干散布的单像素。其中恰好一个为蓝(1)（栅格原点），其余为红(2)（目标放置点）。所有布局点落在一个均匀间距的栅格上（间距等于模板边界框的宽和高）。布局点共 3~5 个。
- **缺角方块**：每个布局点（含原点）旁边紧邻一个 5x5 的灰(5)边框方块（3x3 内区域）。内区域的 4 个角中恰好 3 个标有绿(3)像素，1 个角缺失（为背景色）。不同方块的缺角位置可以不同。
- **生成约束**：各缺角方块不与模板或其他方块重叠；布局点的栅格间距保证印章副本至少存在一对空间重叠。

**规则**：
1. 识别模板：最大的蓝(1) 4-连通分量。
2. 识别布局点：所有蓝(1)和红(2)的单像素。蓝(1)单像素为原点。
3. 为每个布局点找到其最近的缺角方块。根据缺角位置确定旋转角度：左上角缺失 = 0度，右上角缺失 = 90度顺时针，右下角缺失 = 180度，左下角缺失 = 270度顺时针。
4. 将每个布局点相对于原点的偏移量转换为栅格单位（除以模板边界框宽/高）。
5. 在每个栅格位置放置模板的副本：先将模板按该位置的缺角编码角度旋转，再平移到对应的栅格坐标（以栅格单位乘以模板边界框尺寸计算像素偏移）。
6. 原点处的副本涂为红(2)而非蓝(1)。
7. 被两个或更多副本同时覆盖的像素重涂为黄(4)。
8. 擦除所有布局点单像素、缺角方块及其内部标记。

**关键洞察**：与参考题中所有副本共享同一旋转角度不同，此题每个副本拥有独立旋转角度，由各自关联的缺角方块编码。求解者必须同时解码位置（从栅格布局）和朝向（从缺角），两者交叉后才能判断重叠区域。

## 新题 2：射线分区内的受限重力与区域着色

**组合逻辑**：[射线分割区域(ray_partition) + 控制像素(control_pixel)](已有) → [重力下落(gravity_drop) + 缓冲行间距(cushion_row_gap)](创新：重力不作用于整个网格而是受限于射线划分的区域内) → [重涂色(recolor)](创新：着色由落点所在区域决定，区域色由调色板行编码)

**来源原语**：ray_partition、control_pixel（来自 4a21e3da）；gravity_drop、cushion_row_gap（来自 825aa9e9）；recolor（来自 1818057f）；调色板行(palette_row)（来自 bae5c565）

**依赖链**：控制像素射线划分区域 → 区域边界成为重力的底部障碍 → 精灵体在区域内下落 → 落点所在区域决定精灵体的重涂颜色。区域边界同时充当物理障碍和语义标签来源，形成双重用途的紧耦合。

控制像素在网格边缘发射射线将空间分为若干矩形区域；小精灵体在各自所属区域内受重力下落，落定后根据所在区域的调色板颜色重涂。

**输入结构**：约 18x18 的网格，背景黑(0)。包含：
- **调色板行**：最顶行为调色板，包含 2~4 个连续的单像素色块（如蓝(1)、绿(3)、红(2)、黄(4)），其余位置为背景。调色板色块从左到右排列，每个色块占 1 像素高、宽度等于该色块对应区域的列跨度。
- **控制像素**：2~3 个灰(5)单像素位于网格边缘（左、右或底边缘），各自位于不同的行或列。
- **精灵体**：3~5 个小型 4-连通单色图形（每个 3~6 像素），颜色各不相同（从蓝(1)、绿(3)、红(2)、橙(7)、栗(9)中选取），分布在网格中上部。
- **生成约束**：控制像素的射线将网格（除调色板行外）分为 2~4 个矩形区域；每个区域至少包含一个精灵体；精灵体初始位置不紧贴区域下边界；调色板色块数量等于区域数量。

**规则**：
1. 从每个灰(5)控制像素沿其所在行或列向网格内部发射射线，射线仅穿过背景像素（遇到非背景像素跳过），直到到达对边边缘。射线本身不绘制，仅用于划分区域。
2. 射线将网格（调色板行以下的部分）划分为若干矩形区域。区域按从左到右、从上到下排序，编号 1、2、3...
3. 调色板行的色块按从左到右顺序分别对应区域 1、2、3...的着色目标色。
4. 在每个区域内独立施加向下重力：区域内的所有精灵体向下平移，直到其底边距区域下边界（射线所在行或网格底边）恰好一行（缓冲间距 = 1行）。若多个精灵体在同一区域内垂直排列，上方精灵体落在下方精灵体的缓冲间距之上（即精灵体之间也保持 1 行缓冲）。精灵体保持原始形状不变，仅垂直平移。
5. 所有精灵体落定后，将每个精灵体重涂为其所在区域对应的调色板颜色。
6. 擦除调色板行和控制像素。输出仅保留背景和重涂后的精灵体。

**关键洞察**：射线边界同时扮演两个角色——重力的物理障碍和颜色映射的区域标识。一个精灵体的最终颜色取决于它掉进了哪个区域，而不是它的初始颜色或位置，因此必须先完成区域划分和重力模拟才能确定输出。

## 新题 3：凹槽匹配驱动的朝向链式消除

**组合逻辑**：[形状匹配(shape_matching) + 凹槽(notch) + 中心条(central_bar)](已有) → [朝向决定搜索线(facing_sets_search_line)](创新：朝向不由三角箭头编码，而由匹配件的质心偏移方向决定) → [逐步移动(stepwise_move) + 消除(consume) + 最近标记优先(nearest_marker_first)](创新：消除的不是独立标记而是散布的同色像素，每次消除延伸链条)

**来源原语**：shape_matching、notch、central_bar（来自 16b78196）；facing_sets_search_line、stepwise_move、consume、nearest_marker_first（来自 5545f144）；fixed_strip_width（来自 16b78196）

**依赖链**：凹槽形状决定哪个精灵体匹配（根件选择） → 根件的质心偏移决定链的生长方向 → 沿生长方向逐步消除最近的同色标记像素来延伸链条 → 链条宽度锁定于根件的条带宽度。四个环节层层依赖，删除任一环节链条无法生成。

精灵体按形状匹配嵌入中心条的凹槽，然后以根件的不对称方向为链式生长方向，逐步消除沿途最近的标记像素以延伸链条。

**输入结构**：约 20x20 的网格，背景黑(0)。包含：
- **中心条**：一个灰(5)实心水平条（约 2~3 行高，12~16 列宽），位于网格中部偏上。条的上边界或下边界有 2~3 个矩形凹槽（即背景色的缺口，从条的边界框边缘向内凹入，每个凹槽 2~4 像素宽、1~2 像素深）。
- **精灵体**：2~3 个小型单色 4-连通图形（每个 4~8 像素），颜色各不相同（如蓝(1)、红(2)、绿(3)），散布在中心条外围。每个精灵体的形状恰好能填充一个凹槽（但需要找到正确的匹配）。精灵体形状不对称——其质心不在边界框中心。
- **标记像素**：每种精灵体颜色对应若干散布的同色单像素（每色 3~6 个），分布在中心条的上下两侧。标记像素不与精灵体相邻。
- **生成约束**：每个凹槽恰好被一个精灵体的形状匹配（无歧义）；同色标记像素沿水平或垂直方向大致排列成可达的搜索线；精灵体质心偏移方向上至少有一个同色标记。

**规则**：
1. 对每个凹槽，找到形状恰好覆盖该缺口的精灵体，将其填入凹槽位置（颜色不变）。此精灵体称为该链条的"根件"。
2. 计算根件的质心相对于其边界框中心的偏移方向：若质心偏右则朝向为右，偏左为左，偏上为上，偏下为下（取偏移量绝对值较大的轴向）。此方向为链条的生长方向。
3. 根件的宽度（垂直于生长方向的跨度）定义链条的固定条带宽度。
4. 从根件出发，沿生长方向搜索最近的同色标记像素。找到后：消除该标记像素（变为背景），在根件端部的生长方向上延伸一个条带段（宽度 = 固定条带宽度，长度 = 根件端部到被消除标记像素之间的距离），颜色为该链的精灵体颜色。
5. 从新延伸段的末端继续沿同一方向搜索下一个最近的同色标记像素，重复步骤 4，直到该方向上无更多同色标记像素可达。
6. 所有链条独立生长。不同链条的延伸段若空间冲突（试图写入同一像素），按颜色编号较小者优先。
7. 擦除所有未被匹配的精灵体原始位置；保留中心条、根件和链条。

**关键洞察**：精灵体的形状同时承载两重信息——几何轮廓决定它匹配哪个凹槽，而形状的不对称性（质心偏移）决定链条向哪个方向生长。求解者必须先完成形状匹配，才能从匹配后的根件读取方向编码。

## 新题 4：前景射线切割与碎片金字塔重组

**组合逻辑**：[切割(cutting) + 射线分割区域(ray_partition) + 控制像素(control_pixel)](已有) → [滑动(sliding) + 边界归属决定保留(border_ownership_keeps)](已有) → [堆叠(stack) + 奇数宽度递增(odd_width_increment) + 基线对齐(baseline_aligned)](创新：滑动后的碎片不保持原形，而是将像素按金字塔规则重新排列)

**来源原语**：cutting、ray_partition、control_pixel、sliding、border_ownership_keeps（来自 4a21e3da）；stack、odd_width_increment、baseline_aligned（来自 3d6c6e23）

**依赖链**：控制像素射线切割前景对象 → 边界归属筛选保留碎片 → 碎片滑动到网格角落 → 碎片像素数决定金字塔层数 → 像素按金字塔规则重排。切割决定碎片像素数，像素数约束金字塔形状，形成跨步骤的数量耦合。

射线从边缘控制像素向内切割中心前景对象，保留靠近控制边的碎片滑到角落后，将碎片像素重新堆叠为底部对齐的居中金字塔。

**输入结构**：约 16x16 的网格，背景黑(0)。包含：
- **前景对象**：一个较大的蓝(1)单色 4-连通图形（20~30 像素），大致居中，形状不规则但无孔洞。
- **控制像素**：1~2 个红(2)单像素，位于网格边缘（每个在不同的边缘上）。
- **生成约束**：射线切割后，每个保留碎片的像素数为完全平方数（如 4、9、16），以确保金字塔完整。控制像素位置使得至少有 2 个保留碎片。

**规则**：
1. 从每个红(2)控制像素沿其所在行或列向网格内部发射射线。射线仅穿过背景像素（遇到蓝(1)前景像素时跳过，不中断射线，继续向前），直到对边边缘。
2. 射线将网格分为若干区域。蓝(1)前景对象被射线切割：位于切割线上的前景像素归属于包含控制像素所在边缘的区域。
3. 仅保留与控制像素共享网格边缘的区域中的蓝(1)碎片。其他区域的蓝(1)像素擦除为背景。若两个控制像素在不同边缘，各自边缘的区域碎片均保留。
4. 每个保留碎片向其所属控制边缘的最近角落滑动（平移到角落区域，碎片的边界框角对齐网格角落，留 1 像素边距）。
5. 滑动到角落后，碎片的像素被重新排列为底部对齐的居中金字塔：从底向上依次为宽度 2k-1, 2k-3, ..., 3, 1 的水平行（k 为层数，总像素 = k^2）。金字塔每行居中对齐，底行的中心列与角落区域的水平中心对齐，底行紧贴角落区域的底边（留 1 像素边距）。
6. 金字塔颜色保持蓝(1)。擦除控制像素。

**关键洞察**：切割位置决定每块碎片有多少像素，而像素数必须恰好是完全平方数才能形成完整金字塔。求解者需反向推断：生成约束保证像素数为平方数，因此金字塔层数 k = sqrt(像素数)，这将切割操作和堆叠操作通过数量关系紧密耦合。

## 新题 5：绕墙连线中缺口触发的楔形扩展

**组合逻辑**：[连接(connect) + 同色分量依序连接(same_color_chain) + 绕障碍最短路径(shortest_detour)](已有) → [以缺口为中心(centered_on_gap) + 逐行扩展楔形(row_expand_wedge)](创新：连线穿过墙体缺口时在出口侧触发楔形扩展) → 涌现效应：早期楔形成为后续连线的新障碍

**来源原语**：connect、same_color_chain、shortest_detour、obstacle_wall（来自 f8f52ecc）；centered_on_gap、row_expand_wedge、fill（来自 bae5c565）

**依赖链**：同色分量需要连线 → 连线遇墙体缺口时触发楔形扩展 → 楔形填充产生新的障碍区域 → 新障碍影响后续其他颜色的连线路径。处理顺序成为隐蔽规则的一部分——颜色处理顺序改变最终结果。

同色前景分量通过最短正交路径绕墙连接；连线穿过墙体缺口时，在出口侧展开同色楔形直到遇到另一堵墙或网格边缘，楔形反过来阻挡后续颜色的连线路由。

**输入结构**：约 18x18 的网格，背景黑(0)。包含：
- **障碍墙**：若干灰(5)直线段（水平或垂直，每段 4~8 像素长，1 像素宽），形成部分障碍。其中 1~2 面墙在中段有一个 1 像素宽的缺口（背景色断开墙段）。
- **前景分量**：2~3 种非背景、非灰色的前景颜色（如蓝(1)、红(2)、绿(3)）。每种颜色有 2~3 个小型 4-连通分量（每个 2~5 像素），分布在墙的两侧。
- **生成约束**：同色分量之间存在可达的 L 形路径（可能需穿过缺口）；至少一种颜色的连线必须穿过缺口；缺口位置使得楔形扩展后至少阻挡另一种颜色的直接路径。

**规则**：
1. 颜色处理顺序：按每种颜色的最上最左分量的位置排序（行优先，行相同则列优先），从上到下、从左到右。
2. 对每种颜色，按行主序读取其 4-连通分量，将相邻分量对用最短 L 形正交路径连接。路径仅穿过背景像素或同色像素，不穿过灰(5)墙或其他颜色像素。已有楔形区域视为障碍（除非与当前颜色相同）。
3. 当连线路径需通过墙的 1 像素缺口时：路径正常进入缺口，但在出口侧触发楔形扩展——从缺口出口像素开始，沿连线的前进方向（垂直于墙体），每一行（或列）比上一行在缺口两侧各宽 1 像素，填充当前连线颜色。楔形持续扩展，直到某一行的任一端遇到灰(5)墙、其他颜色像素、先前楔形、或网格边缘。
4. 楔形扩展完成后，该楔形区域成为固定障碍，后续颜色的连线和楔形不可穿越。
5. 所有连线和楔形绘制完毕后，灰(5)墙保留，背景保留。

**关键洞察**：颜色的处理顺序是隐蔽规则——仅看单个示例可能无法确定顺序对结果的影响，需要对比多个示例观察不同顺序导致不同楔形阻挡效果才能归纳出排序规则。楔形扩展是涌现效应：连线和墙体单独都不会产生楔形，只有连线穿过缺口时才触发。

## 新题 6：十字模式检测驱动的射线投射与障碍截断

**组合逻辑**：[模式检测(pattern_detection) + 邻域全匹配(all_neighbors_match)](已有) → [射线延伸(ray_extend) + 射线遇障停止(ray_stops_at_block) + 特定色为墙壁(specific_is_wall)](创新：射线源不再是预设矩形，而是从前景中动态检测出的十字图案) → [重涂色(recolor)](创新：射线路径着色，同时检测到的十字本身也变色)

**来源原语**：pattern_detection、all_neighbors_match、cross_pattern、recolor（来自 1818057f）；ray_extend、ray_stops_at_block、specific_is_wall、blocker_object、solid_rectangle（来自 6ffe8f07）

**依赖链**：前景形状的几何结构决定哪些像素构成十字 → 检测到的十字成为射线源 → 射线遇障碍物截断 → 射线路径被着色。删除模式检测则无射线源；删除障碍则射线过度延伸；删除射线则无输出变换。

在单色前景中检测所有嵌入的"+"十字图案并重涂为青色，然后从每个十字中心向四方发射青色射线，射线遇蓝色障碍物截断。

**输入结构**：约 15x15 的网格，背景黑(0)。包含：
- **前景形状**：一种颜色（黄(4)）构成若干形状，包括不规则斑块、线条和连通区域。其中一些区域内嵌含"+"十字图案（一个像素及其上下左右 4 邻均为黄(4)）。前景黄(4)像素总数约 30~50 个。
- **障碍物**：2~4 个蓝(1)小型实心矩形（每个 2x2 或 2x3 像素），散布在网格中，不与黄(4)前景相邻。
- **生成约束**：至少存在 2 个可检测的十字（其 4 邻均为黄(4)的像素）；十字可嵌入大块连通区域中（大块区域可能产生多个重叠的十字检测）；输入中无青(8)像素。

**规则**：
1. 检测所有十字中心：任何黄(4)像素，若其上、下、左、右 4 个正交邻居均为黄(4)，则该像素为十字中心。
2. 将每个十字中心及其 4 个正交邻居共 5 个像素重涂为青(8)。
3. 从每个十字中心向上、下、左、右 4 个方向发射射线。射线从中心出发逐像素延伸（跳过已涂青(8)的十字臂像素），将沿途的黑(0)背景像素涂为青(8)。
4. 射线遇到以下情况停止（不包含停止点本身）：蓝(1)障碍物像素、网格边缘。射线穿过黄(4)前景像素时，该像素保持黄(4)不变，射线继续前进。
5. 所有十字的射线均绘制完毕后，蓝(1)障碍物、黄(4)非十字前景像素保持原色不变。

**关键洞察**：大块填充区域内部会产生多个十字检测（例如一个 3x3 实心方块产生 1 个十字，一个 5x3 矩形产生 3 个十字），因此射线源的数量和位置由前景的几何形状涌现而非显式标注。求解者必须先分析前景的像素拓扑来确定射线源，才能预测射线投射结果。

## 新题 7：框架平铺与对接式色彩互换组装

**组合逻辑**：[平铺(tile) + 框架模板(frame_template) + 单元精灵(unit_sprite)](已有) → [同色匹配(same_color_matching) + 对接(dock)](创新：组合体不再按固定旋转放置，而是对接到颜色匹配的色条上) → [色彩互换(color_swap) + 颜色反转映射(inverted_color_mapping)](创新：组合体的配色由匹配色条的填充/边框色决定，形成反转映射)

**来源原语**：tile、frame_template、unit_sprite、separator_column（来自 a32d8b75）；dock、color_swap、inverted_color_mapping、two_tone_sprite、color_bar、same_color_matching（来自 7c66cb00）

**依赖链**：单元精灵平铺入框架生成组合体 → 组合体的外色匹配色条的填充色（反转匹配） → 匹配确定后执行色彩互换（外色→边框色，内色→填充色） → 组合体放置在匹配色条的水平位置。平铺决定组合体形状，颜色匹配决定对接目标，对接后执行色彩互换——三者通过颜色链式关联。

左面板的双色单元精灵被平铺到框架模板中形成放大组合体，然后按外色匹配到下方色条并执行色彩互换后放置。

**输入结构**：约 18x20 的网格，背景黑(0)。包含：
- **分隔列**：一列品红(6)像素从上到下将网格分为左面板（约 5~6 列宽）和右画布（约 12~13 列宽）。
- **左面板**（从上到下）：
  - **单元精灵**：一个 3x3 的双色小图形——外部像素为颜色 A（如蓝(1)），内部像素（中心 1 像素）为颜色 B（如红(2)）。
  - **框架模板**：一个灰(5)矩形网格（如 3x4 个单元格），每个单元格标记为活跃（灰(5)）或不活跃（背景）。活跃单元格构成不规则形状。
- **色条区域**（位于右画布下方 3~4 行）：2~3 根水平色条，每条跨越右画布大部分宽度，高 1 像素。每条色条有一个填充色和两端各 1 像素的边框色。不同色条的填充色各不相同。其中恰好一条的填充色等于单元精灵的外色 A。
- **右画布**：色条上方为空白背景区域，用于放置组合体。
- **生成约束**：框架中活跃单元格构成 4-连通图形；色条数量 >= 1；恰好一条色条的填充色与精灵外色匹配。

**规则**：
1. 将单元精灵平铺到框架模板的每个活跃单元格中：每个活跃格替换为一份单元精灵的副本，生成一个放大的组合体。组合体保留精灵的双色结构（外色 A、内色 B）。
2. 在右画布的色条中找到填充色等于组合体外色 A 的色条。
3. 执行色彩互换：组合体的外色 A 重涂为匹配色条的边框色；组合体的内色 B 重涂为匹配色条的填充色。
4. 将重涂后的组合体放置在右画布上，水平居中对齐匹配色条，垂直位置为组合体底边紧贴色条上方 1 行。
5. 擦除分隔列、左面板、所有色条。输出仅包含右画布区域（裁剪到右画布的列范围和原始行数）中的背景与组合体。

**关键洞察**：色彩互换的映射关系隐藏在色条的双色编码中——精灵的外色用于"寻找"匹配的色条，找到后外色反而被替换为色条的边框色（非显然的反转映射）。必须先平铺出组合体确定其外色，才能匹配色条，进而确定互换规则。

## 新题 8：锚点编码碎片放置与镜像对称约束验证

**组合逻辑**：[标记编码位置(marker_encodes_position) + 锚点对齐(anchor_alignment)](创新：编码的不是旋转角度而是碎片在输出矩形中的粗位置) → [拼图组装(jigsaw_assemble) + 镜像对称(mirror_symmetry)](创新：组装约束从自由拼接变为锚点引导的对称拼接) → [同色不相邻(same_color_no_touch)](已有，作为验证约束)

**来源原语**：marker_encodes_position、anchor_alignment（来自 a32d8b75）；jigsaw_assemble、mirror_symmetry、same_color_no_touch、corner_marker、fragment（来自 e8686506）

**依赖链**：角标记确定输出矩形尺寸 → 每个碎片的锚点编码方块确定其粗放置区域 → 镜像对称约束决定碎片是自对称还是成对放置 → 同色不相邻约束验证并微调最终位置。这是同时约束满足结构：位置编码、对称性、不相邻三条约束共同唯一确定输出，无固定执行顺序。

散布的彩色碎片根据各自锚点编码方块指示的粗位置，组装为左右镜像对称的矩形，且同色碎片不可 4-连通相邻。

**输入结构**：约 22x22 的网格，背景黑(0)。包含：
- **角标记**：4 个橙(7)单像素标记输出矩形的 4 个角落位置。这 4 个像素确定一个矩形（如 8x10）。
- **碎片**：4~6 个小型 4-连通单色图形（每个 3~6 像素），颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取。碎片散布在角标记定义的矩形外部区域。可能存在两个同色碎片。
- **锚点编码方块**：每个碎片旁（距离 1~2 像素内）有一个 5x5 灰(5)边框方块（3x3 内区域为背景）。内区域的某个位置有一个与该碎片同色的标记像素。标记在 3x3 内区域的行位置编码垂直对齐（上行=上三分之一区，中行=中三分之一区，下行=下三分之一区），列位置编码水平对齐（左列=左三分之一区，中列=中心列，右列=右三分之一区）。
- **生成约束**：碎片总像素数恰好等于输出矩形面积的一半（矩形列数为偶数，保证左右对称可行）；每个碎片要么锚点编码在中心列（则碎片本身左右对称），要么在左/右区（则存在镜像配对碎片在对称位置）；同色碎片的锚点编码保证在对称放置后不 4-连通相邻。

**规则**：
1. 从 4 个橙(7)角标记确定输出矩形的行范围和列范围。
2. 对每个碎片，找到其最近的 5x5 灰(5)边框方块。读取内区域中同色标记像素的行列位置，解码为目标区域：行位置 → 垂直三等分（上/中/下），列位置 → 水平三等分（左/中/右）。
3. 将碎片放置在输出矩形中对应的三分之一区域内：碎片的边界框中心对齐该区域的中心点。
4. 对于锚点编码在左区或右区的碎片：在矩形的镜像位置（左右翻转）放置该碎片的水平镜像副本。镜像副本颜色与原碎片相同。
5. 对于锚点编码在水平中心列的碎片：碎片跨越镜像轴放置，碎片本身必须左右对称（生成约束保证）。
6. 验证同色碎片（含镜像副本）不 4-连通相邻。若存在冲突，将冲突碎片沿远离镜像轴方向偏移 1 像素。
7. 输出矩形内的空白位置保持背景色。擦除矩形外所有元素。

**关键洞察**：锚点编码同时约束了碎片的位置和对称行为——水平中心列编码意味着碎片自对称，左/右区编码意味着碎片与其镜像副本成对出现。这种位置-对称的双重语义是参考题中不存在的新结构关系，必须同时理解锚点编码和对称规则才能正确组装。
