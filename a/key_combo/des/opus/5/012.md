## 新题 1：对称补全改写频率排名

**组合逻辑**：[对称补全(symmetry_complete)] → 频率重计算(创新：补全后的像素数改变频率排名) → [重涂色(recolor) + 少数色替换(minority_replaced)]

**来源原语**：对称补全、十字轴线、双轴对称（60d73be6）；重涂色、少数色替换（9caf5b84）

**依赖链**：对称补全向四象限镜像复制稀疏标记 → 各颜色的像素总数因复制量不同而发生排名逆转 → 频率排名决定哪些颜色被替换为指定颜色。删除对称补全步骤则无法得到正确的频率排名；删除重涂色步骤则对称补全本身不构成完整变换。

根据稀疏标记在十字轴线周围的分布完成双轴对称，然后将补全后频率最低的颜色替换为指定颜色。

**输入结构**：约 13x13 的网格。背景为黑(0)。灰(5) 填充恰好一整行和一整列，形成十字轴线，将网格分为四个象限。三种非背景非灰前景色——红(2)、蓝(1)、绿(3)——以孤立像素或 2~3 像素的小簇形式散布在各象限中，且不在十字轴线上。三种前景色的分布不均匀：在补全前，某些颜色仅出现在一个象限中（补全后获得 4 倍像素），某些颜色已在两个对称象限中各有一份（补全后仅获得 2 倍像素），某些颜色已分布在三个象限中（补全后几乎不增长）。橙(7) 不出现在输入中。生成约束：三种前景色补全前的像素数选取为使得补全后频率排名与补全前不同——至少有一对颜色的频率排名发生逆转。

**规则**：
1. 识别灰(5) 十字轴线（一整行 + 一整列）。
2. 对每个非背景非灰像素，将其颜色复制到关于十字行的镜像位置、关于十字列的镜像位置、以及关于两轴的对角镜像位置。若目标位置已有同色像素则不变；若目标位置在十字轴线上则跳过。
3. 补全后，统计每种非灰前景色的总像素数。
4. 保留总像素数排名前两位的颜色不变（若两色并列第二，则都保留）。
5. 将所有其他前景色像素替换为橙(7)。
6. 十字轴线和背景不变。

**关键洞察**：补全前像素少但集中在单一象限的颜色，补全后反而可能变成高频色（像素数翻 4 倍），而补全前像素较多但已分散在多象限的颜色增长有限——必须先完成对称补全，再计算频率，才能得到正确的重涂色结果。

## 新题 2：连接器对接组装决定平铺尺寸

**组合逻辑**：[拼接(stitch) + 同色标记对齐对接(same_color_dock)] → 像素计数(创新：组装结果的像素数编码输出尺寸) → [平铺(tile) + 模板瓦片(stencil_tile)]

**来源原语**：拼接、连接标记、同色标记对齐对接、标记侧面决定方向（e9fc42f2）；平铺、模板瓦片、像素数决定尺寸（f931b4a8）

**依赖链**：连接器对接将多个碎片拼成完整形状 → 完整形状的非背景像素总数决定输出网格的宽度和高度 → 模板瓦片以该尺寸铺满输出。拼接错误则像素数错误、输出尺寸错误；缺少平铺步骤则拼接本身无最终输出意义。

将带有连接标记的碎片对接拼合为一个整体，用整体中两种颜色的像素数分别作为输出宽度和高度，在该尺寸上平铺输入中的小模板瓦片。

**输入结构**：约 15x15 的网格。背景为黑(0)。网格上半区有 3~4 个 4-连通的多色碎片体，每个碎片体有一种主体色（红(2) 或蓝(1)）和 1~2 个连接标记像素（绿(3) 或黄(4)）位于碎片体的边界上。每种标记色恰好出现两次，分属不同碎片体。网格右下角有一个 3x3 的模板瓦片区域，由灰(5) 和品红(6) 组成几何图案，与碎片体不相邻。生成约束：碎片体可以通过匹配同色连接标记无冲突地对接成一个连通整体；对接后整体中红(2) 像素数在 3~8 之间，蓝(1) 像素数在 3~8 之间。

**规则**：
1. 裁剪右下角 3x3 模板瓦片并记录其图案。
2. 识别所有碎片体及其连接标记颜色。对于每种标记色，找到拥有该色标记的两个碎片体。
3. 平移碎片体使同色连接标记像素在其暴露的边界方向上相邻接触（标记像素所在碎片体边界的法线方向决定平移方向）。按标记色从出现位置最左上的一对开始依次对接。
4. 对接完成后，统计组装整体中红(2) 像素的总数记为 W，蓝(1) 像素的总数记为 H。
5. 创建 H 行 x W 列的输出网格，将 3x3 模板瓦片周期性平铺填满该网格（超出部分裁剪）。

**关键洞察**：输出网格的尺寸不是直接可读的数字，而是编码在对接组装后的几何结构中——必须正确完成所有连接器对接才能得到正确的像素计数，进而得到正确的平铺尺寸。

## 新题 3：图例驱动的精灵拉伸填充

**组合逻辑**：[图例精灵(legend_sprite) + 位置对应(positional_mapping)] → 颜色匹配选框(创新：图例标记色与空心矩形边框色配对) → [拉伸(stretch) + 包围盒映射(bbox_mapping) + 线段连接再填充(connect_then_fill)]

**来源原语**：图例精灵、分隔行、标记像素、位置对应、图例色替换标记（20fb2937）；拉伸、填充、空心矩形、包围盒映射、线段连接再填充（465b7d93）

**依赖链**：图例区的标记像素颜色与空心矩形的边框颜色配对 → 确定哪个精灵拉伸进哪个矩形 → 精灵的 bbox 映射到矩形内部 bbox 完成拉伸绘制与填充。配对错误则精灵进入错误的矩形；缺少拉伸步骤则图例仅做了选择无变换。

读取图例区的小精灵及其标记像素颜色，将每个精灵拉伸填入标记色与边框色匹配的空心矩形内部。

**输入结构**：约 18x12 的网格。背景为黑(0)。顶部 4 行为图例区：包含 2~3 个由灰(5) 像素组成的小精灵（每个 3~5 像素，4-连通，形状各异如折线、斜角等），精灵之间水平排列且不相邻。每个精灵正下方一行有一个标记像素，颜色各不相同，取自红(2)、蓝(1)、绿(3)。图例区下方有一行品红(6) 的完整分隔行。分隔行下方是工作区，其中有 2~3 个空心矩形，每个矩形由一像素厚的单色边框围成，边框颜色分别为红(2)、蓝(1)、绿(3)，与图例标记像素颜色一一对应。矩形内部全为背景色。矩形大小不同（内部从 3x3 到 6x6 不等），矩形之间不重叠不相邻。生成约束：每种标记颜色恰好对应一个矩形边框颜色；精灵像素数不超过矩形内部面积。

**规则**：
1. 识别分隔行（品红(6) 填满的完整行）。
2. 分隔行上方为图例区。在图例区中找到所有灰(5) 精灵及紧接其下方的标记像素颜色。按从左到右的顺序将每个标记像素与其正上方最近的精灵配对。
3. 分隔行下方为工作区。找到所有空心矩形及其边框颜色。
4. 将标记颜色与边框颜色相同的精灵-矩形配对。
5. 对每一对：将精灵的边界框四角映射到矩形内部区域的四角。精灵中每个像素映射到内部区域中对应的位置（行列分别做线性映射并四舍五入到最近整数格）。
6. 在矩形内部，对映射后相邻（在原精灵中 4-连通相邻）的像素对之间绘制水平或垂直直线段（取曼哈顿路径中先水平后垂直），颜色为该矩形的边框色。
7. 若绘制的线段围成了封闭区域，将封闭区域内的背景像素也填充为边框色。
8. 删除图例区和分隔行，仅输出工作区。

**关键洞察**：图例精灵不是要被等比缩放或逐像素复制的位图，而是线段拓扑的蓝图——精灵中像素间的连通关系决定了拉伸后在矩形内部绘制哪些线段，线段围成的区域再被填充。同一个精灵进入大矩形和小矩形会产生不同比例但拓扑相同的图案。

## 新题 4：宽度分流的重力下落与循环迁移涂色

**组合逻辑**：[重力下落(gravity_drop) + 宽度决定行为(width_determines_behavior)] → 停靠位置上色(创新：分隔行的局部颜色作为循环涂色源) → [重涂色(recolor) + 循环迁移(cyclic_migration)]

**来源原语**：重力下落、分隔行、宽度决定行为、穿透与停靠（84ba50d3）；循环迁移、重涂色、逐步推进（758abdf0）

**依赖链**：精灵宽度决定是穿透分隔行还是停靠在上方 → 穿透的精灵着陆在分隔行下方某行，其正下方的分隔行格子颜色决定精灵的新颜色 → 停靠的精灵保持原色但触发分隔行对应列的颜色向右循环迁移一步。删除宽度判断则无法确定精灵行为；删除循环迁移则停靠操作无后续效果。

多色精灵从网格顶部向多色分隔行下落：窄精灵穿透分隔行并被其正下方分隔行像素的颜色重涂，宽精灵停靠在分隔行上方并触发分隔行颜色的局部循环迁移。

**输入结构**：约 12x10 的网格。背景为黑(0)。网格中部有一行多色分隔行，由红(2)、蓝(1)、绿(3) 三种颜色的像素组成，每种颜色至少占 2 个连续列位，总共填满该行。分隔行上方散布 3~5 个灰(5) 精灵体，每个精灵为 4-连通单色图形（2~6 像素）。精灵分为窄型（最大水平跨度为 1 列）和宽型（最大水平跨度 >= 2 列）。分隔行下方全为背景。生成约束：窄型精灵的列位置必须在分隔行有色像素的范围内；各精灵水平范围互不重叠；至少有一个窄型和一个宽型精灵。

**规则**：
1. 识别分隔行（唯一一行包含多种非背景色且没有背景像素的行）。
2. 对每个灰(5) 精灵，计算其最大水平跨度（占据的不同列数）。
3. 窄型精灵（跨度 = 1 列）：清除原位置，将精灵整体下移至分隔行正下方第一行，保持列位置不变。然后将精灵颜色从灰(5) 替换为分隔行中该列像素的颜色。
4. 宽型精灵（跨度 >= 2 列）：清除原位置，将精灵整体下移至精灵底边紧贴分隔行上方一行的位置（即精灵最底行位于分隔行上方相邻行）。精灵保持灰(5) 不变。
5. 宽型精灵停靠后，对分隔行中被该精灵水平范围覆盖的所有列执行颜色循环迁移：这些列中的分隔行像素颜色按红(2)→蓝(1)→绿(3)→红(2) 的顺序前进一步。
6. 处理顺序：先处理所有窄型精灵（从左到右），再处理所有宽型精灵（从上到下）。窄型精灵读取迁移前的分隔行颜色；宽型精灵的迁移按处理顺序依次累积。

**关键洞察**：分隔行不是静态障碍物——宽型精灵的停靠会修改分隔行的颜色分布，而窄型精灵的最终颜色取决于分隔行的原始状态。处理顺序（窄先宽后）是隐蔽规则：必须对比多个示例才能确认窄型精灵读取的是迁移前的颜色。

## 新题 5：干扰项剔除后吸附锚块再按面积排序叠加

**组合逻辑**：[保留最大分量(keep_largest) + 忽略干扰项(ignore_distractors)] → [吸附(snap) + 最短距离分配(nearest_frame_assign)] → [透明叠加(transparent_overlay) + 面积排序叠加(area_sorted_overlay)]

**来源原语**：保留最大分量、忽略干扰项、按面积筛选（337b420f）；吸附、锚块、外框边缘、最近距离、最短距离分配、冲突优先级（1b8318e3）；透明叠加、面积排序叠加（83eb0a57）

**依赖链**：每个颜色簇中剔除干扰分量只留最大分量 → 剩余分量吸附到最近的锚块外框 → 多个分量吸附到同一锚块时按面积从大到小叠加（小的在上层）。剔除步骤决定了哪些分量参与后续吸附，错误剔除导致面积排序和叠加结果全错。

从每组同色像素中仅保留最大的连通分量，将保留的分量吸附到最近的灰色锚块周围，多分量共享锚块时按面积降序叠加。

**输入结构**：约 16x16 的网格。背景为黑(0)。网格中散布 2~3 个灰(5) 的 2x2 实心锚块，彼此间距至少 5 格。另有 3~4 种前景色（红(2)、蓝(1)、绿(3)、黄(4)），每种颜色恰好有两个 4-连通分量：一个较大的"真实"分量（4~8 像素，形状不规则）和一个较小的"干扰"分量（1~2 像素）。同色两个分量彼此不相邻且与其他颜色分量不相邻。生成约束：剔除干扰分量后，每个真实分量到最近锚块的国王步距离唯一确定（无平局）；可能有 2 个真实分量共享同一最近锚块。

**规则**：
1. 对每种非背景非灰前景色，找到该色的所有 4-连通分量。保留像素数最多的分量，擦除其余分量（置为背景色）。
2. 对每个保留的分量，计算其到每个灰(5) 锚块的最短国王步距离（分量中任意像素到锚块 2x2 区域中任意像素的国王步距离的最小值）。将分量分配给最近的锚块。
3. 对每个锚块，收集分配给它的所有分量。清除这些分量的原始位置。
4. 对每个分量，计算将其质心（像素坐标的算术平均值，四舍五入到最近整数）移动到锚块中心（2x2 块的中心取左上角像素坐标）所需的平移向量，将分量平移到锚块周围。
5. 同一锚块的多个分量按像素面积从大到小依次绘制（先画最大的，后画的覆盖先画的），因此面积最小的分量在最上层。
6. 锚块本身保持不变，不被分量覆盖。若分量平移后与锚块重叠，重叠部分保持锚块的灰(5)。

**关键洞察**：干扰分量的存在是一个陷阱——如果不先剔除它们，某些颜色的"最大分量"判定会错误，进而导致距离计算和锚块分配全盘偏差。同时，面积排序叠加的方向（大先小后）必须通过对比多个示例中重叠区域的最终颜色才能归纳。

## 新题 6：对角线段推进触发边缘满条的逐步扩展

**组合逻辑**：[平移绘制(translate_draw) + 长度递增(length_increment) + 同反对角线(same_antidiagonal)] → 到达边界触发生长(创新：对角线段到达边缘时触发满条生长) → [生长(grow) + 边缘满条(full_edge_bar) + 逐步推进(stepwise_advance)]

**来源原语**：平移绘制、对角线段、同反对角线、长度递增（50c07299）；生长、边缘满条、逐步推进（758abdf0）

**依赖链**：对角线段沿反对角线推进并增长一个像素 → 若推进后的线段触及网格边缘（某端点在第 0 行、末行、第 0 列或末列），则在该边缘上以线段颜色生长出一条满条，向内推进一格。对角推进的落点决定是否以及在哪条边上生长满条。

对角线段沿反对角线向右上方推进并加长一像素，若新线段的端点触及网格边缘，则在该边缘生成一条向内推进一格的满条。

**输入结构**：约 10x10 的网格。背景为黑(0)。网格中有 1~2 条由蓝(1) 像素组成的对角线段，每条线段位于单一反对角线上（即沿右上-左下方向），长度 2~4 像素。线段距离网格边缘至少 1 格。网格的某些边缘上可能已有部分红(2) 满条（占据整条边的完整行或列），也可能没有。生成约束：每条线段推进后长度增 1，推进方向统一为反对角线的右上方向（列增大、行减小）。推进后线段不会超出网格范围（至多刚好触及边缘）。两条线段不会推进到同一条边缘。

**规则**：
1. 对每条蓝(1) 对角线段：设其当前占据反对角线上列 c0..c1（c0 < c1），长度 L = c1 - c0 + 1。擦除当前线段。
2. 在同一反对角线上，绘制新线段占据列 c1+1..c1+L+1（长度 L+1），颜色仍为蓝(1)。若新线段超出网格列范围，超出部分不绘制。
3. 检查新线段的每个端点像素：若该像素位于网格第 0 行，则在第 0 行全行绘制红(2)（覆盖该行所有像素）；若位于末行，则在末行全行绘制红(2)；若位于第 0 列，则在第 0 列全列绘制红(2)；若位于末列，则在末列全列绘制红(2)。新绘制的红(2) 满条覆盖该行/列的所有先前内容（包括背景和蓝像素）。
4. 已存在的红(2) 满条各自向网格内部推进一格：顶边满条在第 1 行追加一行红(2)；底边满条在倒数第 2 行追加一行红(2)；左边满条在第 1 列追加一列红(2)；右边满条在倒数第 2 列追加一列红(2)。追加像素不覆盖蓝(1) 像素（蓝色优先）。
5. 多条线段按从左到右的顺序依次处理。

**关键洞察**：对角线段的推进是几何运动，边缘满条的生长是触发式扩展——两者通过"端点是否触及边缘"这一空间条件耦合。观察者必须同时追踪对角线段的落点和满条的扩展方向，才能正确推断输出。已有满条的向内推进是另一个隐蔽规则，需对比有/无已有满条的示例才能发现。

## 新题 7：嵌入标记选择规则示例并按连接方向印章

**组合逻辑**：[嵌入标记像素(embedded_marker) + 颜色配对(color_pairing)] → 选择规则(创新：标记色与规则示例的源色匹配来选择规则) → [印章放置(stamp) + 模板图案(stencil_pattern) + 颜色替换(color_substitution)] + [标记侧面决定方向(marker_side_dir)](创新：嵌入标记在精灵体内的相对位置决定印章方向)

**来源原语**：嵌入标记像素、多色精灵体、颜色配对（54dc2872）；规则示例、模板图案、颜色替换、示例定义规则（abc82100）；标记侧面决定方向（e9fc42f2）

**依赖链**：精灵体的嵌入标记颜色与规则示例的源色匹配→选定对应的模板图案和目标色→嵌入标记在精灵体边界框中的相对位置（上/下/左/右侧）决定模板图案的旋转角度→模板图案以标记位置为锚点、旋转后印章到精灵体上并重涂为目标色。颜色配对、方向判断、印章放置三步紧密耦合。

每个多色精灵体中的嵌入标记颜色决定适用哪条规则示例，标记在精灵体中的位置决定模板图案的旋转方向，旋转后的模板以目标颜色印章到标记位置。

**输入结构**：约 15x15 的网格。背景为黑(0)。网格中有 2~3 个多色精灵体，每个精灵体有一种主体色（红(2) 或蓝(1)，4~8 像素，4-连通，形状不规则）和一个嵌入标记像素（绿(3) 或黄(4)），标记像素位于精灵体边界框的某条边上（明确在上边、下边、左边或右边）。网格角落有 2 个规则示例区域，每个由一个源色像素与一个目标色像素 4-连通相邻组成，其延伸方向指向一个 2x2 或 2x3 的青(8) 模板图案（图案距源-目标像素对 1~2 格，沿延伸方向排列）。源色与嵌入标记色相同（绿(3) 或黄(4)），目标色为橙(7) 或品红(6)。精灵体之间、精灵体与规则示例之间互不相邻。生成约束：每种嵌入标记色恰好对应一条规则示例。

**规则**：
1. 识别规则示例：找到由源色像素和目标色像素组成的相邻对（源色为绿(3) 或黄(4)，目标色为非背景非源色的其他颜色），以及沿其延伸方向最近的青(8) 连通分量作为模板图案。记录每条规则的源色、目标色和模板图案形状。
2. 对每个精灵体，找到其中唯一的嵌入标记像素（颜色不同于主体色的像素）。
3. 将嵌入标记颜色与规则示例的源色匹配，选定该精灵体适用的规则。
4. 判断嵌入标记在精灵体边界框中的位置：若标记在边界框最上行则方向为"上"，最下行为"下"，最左列为"左"，最右列为"右"（若标记同时在角落，取行优先即先判断上/下）。
5. 模板图案默认朝向为"上"（规则示例中的原始方向）。根据精灵体标记方向旋转模板：上→不旋转，右→顺时针 90 度，下→180 度，左→逆时针 90 度。
6. 将旋转后的模板图案以嵌入标记位置为锚点（对齐到模板的左上角）印章绘制，颜色替换为规则的目标色。印章覆盖背景和已有精灵体像素。
7. 擦除所有规则示例区域（源像素、目标像素、青色模板）和所有嵌入标记像素（标记位置恢复为主体色）。

**关键洞察**：规则的选择和模板的旋转方向都编码在精灵体的局部结构中——嵌入标记的颜色是选择信号，其位置是方向信号。必须同时解码颜色和空间位置两层信息，才能正确完成印章放置。

## 新题 8：墙壁滑动后像素数决定正方形重排

**组合逻辑**：[滑动(slide) + 同色物体朝同色墙(same_color_wall) + 碰撞停止(collision_stop)] → 像素聚合计数(创新：同色物体滑动到墙壁后合并计数) → [压缩重排(repack) + 像素数定边长(pixel_count_determines_side) + 面积递增排列(area_ascending_order)]

**来源原语**：滑动、墙壁列、同色物体朝同色墙、近者优先不重叠、碰撞停止（f0100645）；压缩重排、像素数定边长、面积递增排列、排序（8abad3cf）

**依赖链**：同色物体滑动到各自的墙壁列 → 滑动后同色物体可能在墙壁旁合并为更大的连通区域 → 合并后每种颜色的总像素数决定其正方形边长 → 所有颜色的正方形按面积递增排列输出。滑动改变了物体之间的邻接关系，直接影响像素计数；计数决定正方形尺寸。

将不同颜色的散布物体分别滑向同色墙壁列，滑动后每种颜色的总像素数开方得到正方形边长，按面积从小到大排列输出。

**输入结构**：约 12x12 的网格。背景为黑(0)。最左列全部为红(2)，最右列全部为蓝(1)，形成两面彩色墙壁。网格中间区域散布若干红(2) 和蓝(1) 的 8-连通物体（每个 2~5 像素，形状不规则），以及若干绿(3) 物体。绿(3) 不对应任何墙壁。生成约束：红(2) 物体的总像素数（不含墙壁列）和蓝(1) 物体的总像素数（不含墙壁列）各自为完全平方数（如 4、9、16）；绿(3) 的总像素数也为完全平方数。各物体之间互不相邻。

**规则**：
1. 红(2) 物体向左滑向红(2) 墙壁列：按距左墙壁的距离从近到远依次处理。每个物体整体水平左移，直到物体的最左像素紧邻墙壁列或紧邻已停靠的红色物体的右边缘。清除物体原位置。
2. 蓝(1) 物体向右滑向蓝(1) 墙壁列：按距右墙壁的距离从近到远依次处理。每个物体整体水平右移，直到物体的最右像素紧邻墙壁列或紧邻已停靠的蓝色物体的左边缘。清除物体原位置。
3. 绿(3) 物体不移动，直接擦除（置为背景色）。
4. 统计滑动后网格中红(2) 的总像素数（包括墙壁列的像素），记为 Pr；蓝(1) 的总像素数（包括墙壁列的像素），记为 Pb；绿(3) 的原始总像素数，记为 Pg。
5. 创建新的输出网格。分别构建三个实心正方形：红色正方形边长 sqrt(Pr)，蓝色正方形边长 sqrt(Pb)，绿色正方形边长 sqrt(Pg)。
6. 将三个正方形按面积从小到大从左到右排列，底边对齐，相邻正方形之间留一列背景色间隔。输出网格高度为最大正方形的边长，宽度为三个正方形宽度加两列间隔之和。

**关键洞察**：墙壁列的像素也计入颜色总数——滑动不仅改变物体位置，还通过"合并到墙壁"增大了红/蓝的有效像素数。观察者必须注意墙壁像素是否计入，这需要对比多个示例中墙壁列长度与输出正方形边长的关系才能确认。绿色物体虽不滑动也不出现在中间结果中，但其像素数仍参与最终排列。

## 新题 9：十字轴分割象限内的控制标记驱动区域涂色

**组合逻辑**：[十字轴线(cross_axis) + 四象限(four_quadrants)] → 象限内标记解读(创新：十字轴线划分象限，每个象限内独立存在控制标记) → [控制标记(control_marker) + 标记指向目标(marker_points_to_target) + 重涂色(recolor)] → 象限间颜色传递(创新：一个象限的涂色结果作为另一象限标记的源色)

**来源原语**：十字轴线、四象限、双轴对称（60d73be6）；控制标记、标记指向目标、标记形状决定操作、单色区域、重涂色（21897d95）；四象限（f931b4a8）

**依赖链**：十字轴线将网格分为四个象限 → 每个象限内有控制标记指向目标区域进行涂色 → 按固定顺序（左上→右上→左下→右下）处理象限，前一象限的涂色结果通过十字轴线传递到下一象限的标记解读中。处理顺序是隐蔽规则，必须对比示例才能发现。

十字轴线将网格分为四象限，每个象限中的 T 形控制标记决定对目标区域的涂色，象限按特定顺序处理且前序象限的涂色结果影响后续象限标记的颜色源。

**输入结构**：约 13x13 的网格（奇数行列，确保十字轴线居中）。背景为黑(0)。灰(5) 填充中间整行和中间整列，形成十字轴线。四个象限各自为独立的马赛克区域：每个象限有 2~3 个由单色填充的矩形区域（颜色取自红(2)、蓝(1)、绿(3)、黄(4)），区域之间以背景色分隔。部分象限中存在一个由品红(6) 像素组成的 T 形控制标记（3 像素：两像素横杠 + 一像素竖杆），竖杆指向某个相邻的单色区域。不是每个象限都有标记。生成约束：至少两个象限有控制标记；至少一个后序象限的标记竖杆指向的目标区域颜色与前序象限某个被涂色的区域颜色相同。

**规则**：
1. 识别灰(5) 十字轴线（中间整行 + 中间整列），将网格划分为左上、右上、左下、右下四个象限。
2. 按左上→右上→左下→右下的顺序依次处理每个象限。
3. 在当前象限中，若存在品红(6) T 形标记：竖杆像素指向的方向确定目标——竖杆延伸方向上遇到的第一个非背景非品红区域即为目标区域。横杠两端像素的延伸方向上各遇到的第一个非背景非品红区域即为两个源区域。
4. 目标区域的新颜色 = 两个源区域颜色中，在当前网格（含先前象限的修改结果）中总像素数更少的那个颜色。若两个源区域同色，则目标区域涂为该色。
5. 将目标区域的所有像素替换为新颜色。擦除该象限中的品红(6) 标记像素（置为背景色）。
6. 若象限无标记，不做改变。
7. 所有象限处理完毕后输出最终网格。

**关键洞察**：象限并非独立处理——左上象限的涂色结果改变了全局某颜色的总像素数，进而影响右上象限标记中的"更少像素数"判断。必须发现正确的处理顺序（左上→右上→左下→右下），否则涂色结果错误。这一顺序只能通过对比多个示例推断。

## 新题 10：色段边界对齐后封闭区域填充

**组合逻辑**：[滑动(shift) + 边界对齐(edge_alignment) + 色段(color_run)] → 对齐产生封闭结构(创新：行内色段对齐后形成封闭矩形环) → [填充(fill) + 线段连接再填充(connect_then_fill)] + [擦除(erase)]

**来源原语**：滑动、对齐、边界对齐、色段、同行排列（984d8a3e）；填充、线段连接再填充（465b7d93）；擦除（多题共有）

**依赖链**：每行的色段左右滑动使边界对齐 → 对齐后相邻行的同色色段端点上下相连，形成封闭的矩形环 → 环内部的背景区域被填充为环的颜色 → 非环部分的色段被擦除。对齐步骤决定了哪些色段端点纵向相连，连通结果决定了哪些区域被填充。

将各行的主色段滑动使右边界对齐，对齐后纵向连续的同色段形成封闭矩形环，填充环内部并擦除不构成环的色段。

**输入结构**：约 10x12 的网格。背景为黑(0)。每行恰有一个由红(2)、蓝(1) 或绿(3) 组成的连续色段（3~8 像素宽），色段两侧为背景。不同行的色段颜色可能不同，但连续若干行的色段颜色相同。色段的右边界列位置各行不统一（左边界也不统一）。生成约束：存在至少两组连续同色行段（每组至少 2 行），且同组内的色段宽度不全相同（这样对齐后左边界位置不同，才能形成有内部空间的环）。不同组的颜色不同。

**规则**：
1. 对每行，找到该行唯一的非背景色段及其颜色、左边界列和右边界列。
2. 找到所有色段右边界列的最小值 R_min。
3. 将每行的色段水平滑动，使其右边界列恰好为 R_min。若色段宽度大于 R_min + 1（即滑动后左边界会小于 0），则将色段左边界截断到第 0 列。滑动不改变色段颜色和宽度（截断情况除外）。
4. 滑动后，找到所有"纵向同色连续组"：连续若干行的色段具有相同颜色，每组至少 2 行。
5. 对每个纵向同色连续组：这些行的色段右边界已对齐（都在 R_min 列），左边界可能不同。取组内左边界的最大值 L_max 和最小值 L_min。若 L_max > L_min，则这些色段形成一个开口朝左的阶梯形。将组内第一行和最后一行的色段从 L_min 扩展到 L_max（即在这两行中将 L_min 到 L_max 范围全部填充为该颜色），形成封闭矩形环。环内部（由 L_min 列、R_min 列、组首行、组末行围成的矩形中，不属于色段的背景像素）填充为该组颜色。
6. 若 L_max == L_min（组内所有色段完全重叠），则不形成环，将该组所有色段擦除（置为背景色）。
7. 不属于任何纵向连续组的孤立行色段也擦除。

**关键洞察**：边界对齐不只是视觉整理——它创造了纵向连通的条件，使原本水平独立的色段在纵向上形成封闭结构。只有当同组色段的左边界不完全相同时，对齐后才能围出内部空间供填充。对齐与填充通过"左边界差异"这一条件紧密耦合。

## 新题 11：连通分量面积排序控制印章缩放

**组合逻辑**：[裁剪(crop) + 连通分量(connected_component) + 面积递增排列(area_ascending_order)] → 排序结果编码缩放因子(创新：分量的面积排名决定印章的缩放倍数) → [印章放置(stamp) + 锚点标记(anchor_marker) + 颜色匹配(color_matching)] + [拉伸(stretch)]

**来源原语**：裁剪、连通分量、按面积筛选（337b420f）；面积递增排列、排序（8abad3cf）；印章放置、锚点标记、颜色匹配、最少色为锚点（a251c730）；拉伸（465b7d93）

**依赖链**：裁剪出源区域中的各个连通分量并按面积排序 → 面积排名第 k 的分量被缩放 k 倍 → 缩放后的分量按锚点标记颜色匹配印章到目标区域中的对应位置。面积排序决定缩放因子，颜色匹配决定放置位置，两者共同决定最终输出。

源区域中的连通分量按面积从小到大排名，排名即为缩放倍数，缩放后按锚点颜色匹配印章到目标区域。

**输入结构**：约 18x10 的网格。背景为黑(0)。网格左半部分为源区域，包含 3 个不同颜色（红(2)、蓝(1)、绿(3)）的 4-连通分量，每个分量 2~6 像素，形状各异，分量之间不相邻。每个分量中有一个像素颜色与其余不同，该像素颜色为黄(4)、灰(5)、品红(6) 之一，作为锚点标记（每个分量中最少的颜色）。网格右半部分为目标区域，全为背景色，其中有 3 个孤立的标记像素，颜色分别为黄(4)、灰(5)、品红(6)，与源区域的锚点颜色一一对应。生成约束：三个分量的面积（包括锚点像素）互不相等。缩放后的分量在目标区域中不会相互重叠也不会超出网格边界。

**规则**：
1. 在源区域中找到所有非背景连通分量。对每个分量，识别其主体色和锚点色（像素数最少的颜色）。
2. 将分量按总面积（像素数）从小到大排序，赋予排名 1、2、3。
3. 对排名为 k 的分量，将其裁剪到最小边界框，然后进行 k 倍等比缩放：原分量中每个像素扩展为 k x k 的像素块，保持颜色不变。
4. 在目标区域中找到与分量锚点色相同的标记像素。将缩放后的分量平移，使其缩放后的锚点像素块的左上角与目标标记像素对齐。
5. 将缩放后的分量绘制到目标区域，覆盖背景。若缩放后的分量之间有重叠，排名大的（面积大的、缩放倍数大的）先绘制，排名小的后绘制并覆盖在上层。
6. 擦除源区域的所有内容（置为背景色）。擦除目标区域中已被分量覆盖的标记像素。
7. 输出完整网格。

**关键洞察**：面积排名不只是排序标签——它直接转化为缩放倍数，使最小的分量保持原尺寸而最大的分量变成 3 倍大小。这意味着面积排序的结果会被"放大"体现在输出中：如果排序错误，不仅位置错误，大小也错误。必须对比示例中分量面积与输出中对应图案大小的关系才能发现这一规则。

## 新题 12：收缩与生长由中心距离决定方向并受对角约束

**组合逻辑**：[收缩(shrink) + 生长(grow) + 中心间隙(center_gap) + 面积最大者(largest_area)] → 方向约束(创新：生长/收缩方向受反对角线约束) → [对角线段(diagonal_segment) + 同反对角线(same_antidiagonal)]

**来源原语**：收缩、生长、中心间隙、面积最大者、最大外扩余内缩（df978a02）；对角线段、同反对角线（50c07299）

**依赖链**：四个前景对象指向中心间隙 → 面积最大者生长、其余收缩 → 但生长方向不是简单的"远离中心"，而是沿对象所在的反对角线方向延伸 → 收缩方向也沿对角线方向回退。对角线约束改变了生长/收缩的几何表现。

四个前景对象围绕中心间隙，面积最大者沿其所在反对角线方向向外生长，其余对象沿各自反对角线方向收缩一像素。

**输入结构**：约 11x11 的网格。背景为黑(0)。网格中心附近有一个 2x2 或 3x3 的背景色间隙（中心间隙）。四个 8-连通单色前景对象分布在中心间隙的四个对角方向（左上、右上、左下、右下），每个对象 3~8 像素，颜色各不相同（红(2)、蓝(1)、绿(3)、黄(4)）。每个对象的形态大致沿一条反对角线方向排列（像素分布的主轴近似为反对角线方向），且对象最靠近中心间隙的像素位于某条反对角线上。恰好一个对象面积最大。生成约束：每个对象至少有 2 个像素位于同一条反对角线上；对象之间不相邻。

**规则**：
1. 找到中心间隙：网格中心附近由背景色构成的最大正方形区域（到四个前景对象的聚合距离最小）。
2. 找到面积最大的前景对象。
3. 对非最大的三个对象：找到该对象中距中心间隙最近的像素（若有多个等距像素，取位于反对角线上的那个），将该像素擦除（置为背景色）。这是沿对角方向的收缩。
4. 对面积最大的对象：找到该对象中距中心间隙最远的像素 P。确定 P 所在的反对角线方向（右上-左下）。在该反对角线上、P 的远离中心一侧，添加两个像素（即在 P 的反对角线延伸方向上连续放置两个同色像素），颜色为该对象的颜色。若添加的像素超出网格边界则不绘制。
5. 若最大对象的最远像素不在任何明确的反对角线上（即其行列坐标之和不与对象其他像素共享），则取该对象中位于反对角线上的最远像素。

**关键洞察**：与原参考题（df978a02）中"朝远离中心方向生长"不同，这里生长方向被约束在反对角线上——对象的几何分布决定了它沿哪条对角线延伸。观察者必须发现生长不是任意方向的外扩，而是沿特定几何线的定向延伸，且延伸长度固定为两像素（而非原题的三像素帽），这需要对比多个示例才能确认。
