## 新题 1：对称补全决定重力距离

**组合逻辑**：[对称补全](已有) → [重力下落](已有，创新：位移量由补全后面积决定而非原始面积)

**来源原语**：对称补全(symmetry_completion) ← 0934a4d8；重力下落(gravity_drop) / 面积决定位移(area_determines_displacement) ← 8e301a54；超界裁剪(clip_beyond_edge) ← 8e301a54；双轴反射对称(biaxial_reflection_symmetry) ← 0934a4d8

**依赖链**：对称补全改变了每个对象的面积 → 补全后面积决定了下落距离 → 最终位置取决于补全效果，两步不可跳过

先补全每个对象的反射对称缺失像素，再将每个对象按补全后的面积做重力下落。

**输入结构**：黑(0)背景，约 12x18。3-5 个单色 4-连通前景对象，颜色互不相同（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。每个对象都具有近似单轴反射对称（水平或垂直），但缺失了对称轴一侧的 1-3 个像素（这些位置为背景色），使得该轴上的反射对称不完整。不同对象的缺失程度不同（有的缺 1 像素，有的缺 3 像素）。所有对象位于网格上半部（行 0 到行 8），彼此不接触且不共享行列。生成约束：每个对象的反射轴唯一可辨（通过其已存在的像素可确定唯一的反射方向和轴线位置）；补全后各对象互不重叠；补全后面积各不相同。

**规则**：
1. 对每个前景对象，找到其反射对称轴（水平或垂直——选择使已有像素最大限度对称的那条轴，每个对象恰好只有一条合法轴），将轴另一侧的缺失像素补上该对象的颜色，使对象关于该轴完全对称。
2. 计算每个对象补全后的像素面积 A。
3. 将每个补全后的对象整体向下平移 A 行。超出网格底部的像素裁剪丢弃。
4. 原位置清空为背景色。

**关键洞察**：两个补全前面积相同的对象，可能因为缺失像素数不同，补全后面积不同，导致下落距离不同。求解者必须先正确识别对称轴并补全，才能得到正确的位移量——跳过补全步骤直接用可见面积计算必然出错。

## 新题 2：稀疏精灵稠密化后充当放大瓦片

**组合逻辑**：[稠密化/加厚](已有) → [像素放大/平铺](已有，创新：瓦片不是直接给定的，而是从稀疏精灵稠密化而来；瓦片与掩码槽位的对应由空间位置决定)

**来源原语**：稠密化(densify) / 加厚(thicken) / 稀疏精灵体(sparse_sprite) ← db615bd4；像素放大(pixel_upscale) / 平铺(tile) / 掩码映射(mask_mapping) / 控制精灵(control_sprite) ← bf45cf4b；位置顺序(position_order) ← db615bd4；像素展开为瓦片(filled_pixel_expands_to_tile) ← bf45cf4b

**依赖链**：稀疏精灵必须先稠密化才能成为合法瓦片 → 控制精灵的掩码决定瓦片的放置位置 → 瓦片的分配顺序由稀疏精灵原始位置决定，三者环环相扣

将多个稀疏精灵稠密化为等尺寸的方形瓦片，再按空间位置顺序依次填入控制精灵的放大掩码槽位中。

**输入结构**：黑(0)背景，约 20x20。包含以下元素：
- 1 个小型稠密单色精灵（"控制精灵"），使用红(2)绘制，大小约 3x4 至 5x5 像素，内部有若干背景色(0)孔洞（形成二值掩码），位于网格右上角区域。
- 2-4 个较大的稀疏精灵，每个使用不同颜色（蓝(1)、绿(3)、黄(4)、品红(6)等），像素排列在步长为 2 的格点上（即每两个相邻前景像素之间间隔 1 个背景像素），散布在网格其余区域，彼此不接触。每个稀疏精灵的稠密化结果（填充格点间隙后）尺寸相同（如都是 3x3 或都是 4x4）。
- 生成约束：控制精灵中填充像素（红色像素）的数量恰好等于稀疏精灵的数量。稀疏精灵稠密化后的尺寸完全一致。

**规则**：
1. 对每个稀疏精灵，将其格点间隙填充（步长 2 变为步长 1），得到一个稠密的方形瓦片，保留该精灵的原有颜色。
2. 按原始稀疏精灵的左上角像素位置排序（先按行从上到下，行相同则按列从左到右），得到瓦片有序序列 T1, T2, ..., Tn。
3. 扫描控制精灵的边界框，从左上到右下逐行扫描：遇到红(2)像素（填充位），放置序列中的下一个瓦片；遇到背景像素（空位），放置与瓦片等大的纯背景区域。
4. 输出网格尺寸 = (控制精灵边界框高度 x 瓦片高度, 控制精灵边界框宽度 x 瓦片宽度)。

**关键洞察**：瓦片不是直接给定的——它们隐藏在稀疏精灵中，必须先执行稠密化才能获得。瓦片与控制掩码之间的对应关系由空间位置顺序决定（而非颜色匹配），求解者需要对比多个示例才能排除"按颜色编号排序"或"按面积排序"等错误假说。

## 新题 3：重力下落后对角交界处染色

**组合逻辑**：[重力下落/滑动](已有) → [重涂色](已有，创新：着色条件为后重力状态下不同色对象之间的纯对角邻接位置，而非源题中固定的框与内层关系)

**来源原语**：滑动(slide) / 重力下落(gravity_drop) / 面积决定位移(area_determines_displacement) ← 8e301a54；重涂色(recolor) / 仅对角邻接(diagonal_only_adj) / 对角邻接背景着色(diagonal_bg_color) ← 396d80d7；超界裁剪(clip_beyond_edge) ← 8e301a54

**依赖链**：每个对象先按面积做重力下落 → 下落后才能确定哪些背景像素处于不同色对象的纯对角交界位置 → 对交界像素着色，输出同时包含下落后的对象和新着色的像素

所有前景对象按各自像素面积向下滑动，然后在仅与两种不同颜色对象对角邻接（且无正交邻接）的背景像素上涂橙(7)标记色。

**输入结构**：黑(0)背景，约 12x15。4-6 个单色 4-连通前景对象，使用 2-3 种颜色（如蓝(1)和绿(3)），每种颜色有 2-3 个对象。每个对象 3-7 像素，形状不规则（非矩形、非对称均可），分布在网格上半部（行 0-6），彼此之间至少间隔 2 行 2 列。生成约束：下落后（每个对象下移等于自身面积的行数），至少存在 2 处不同色对象仅对角相邻的背景缝隙；下落后同色对象之间不直接正交接触；所有对象下落后至少部分保留在网格内。

**规则**：
1. 对每个前景对象，计算其像素面积 A。
2. 将每个对象整体向下平移 A 行，超出网格底部的像素裁剪丢弃。原位置清空为背景色。所有对象同时移动（互不阻挡）。
3. 在下落后的网格中，检查每个背景像素 P：若 P 的 8-邻域（对角方向）中存在至少两种不同的非背景颜色的像素，且 P 的 4-邻域（正交方向）中不存在任何非背景像素，则将 P 涂为橙(7)。
4. 所有前景对象保持各自原有颜色不变。

**关键洞察**：橙色标记只出现在不同颜色对象的"对角缝隙"处——两个不同色对象恰好斜对角相邻但不正交相邻的间隙位置。这些缝隙的存在完全取决于重力下落后的排列：面积不同的对象下落距离不同，哪些对象最终形成对角邻接必须逐个计算才能确定。

## 新题 4：边缘矩形滑动轨迹充当对称补全轴

**组合逻辑**：[滑动](已有，创新：轨迹条纹不作为最终输出保留，而作为反射轴的几何定义) → [对称补全](已有，创新：反射轴不从图案自身推导，而由外部滑动轨迹指定) → [擦除](创新组合：轨迹在完成辅助功能后被移除)

**来源原语**：滑动(slide) / 边缘矩形(edge_rectangle) / 轨迹条纹(trail_stripe) / 接触边缘(touching_edge) / 滑至对侧边缘(slide_to_opposite) ← b25e450b；对称补全(symmetry_completion) / 双轴反射对称(biaxial_reflection_symmetry) ← 0934a4d8；擦除(erase) ← 6ca952ad

**依赖链**：边缘矩形滑动产生轨迹条纹 → 轨迹条纹的行/列位置定义反射轴 → 以该轴为基准对残缺图案做镜像补全 → 移除轨迹和矩形后输出纯净的对称图案

将边缘矩形滑至对侧后产生的轨迹条纹作为反射轴，对网格中的残缺图案做镜像补全，最后擦除轨迹和矩形。

**输入结构**：黑(0)背景，约 14x14。包含以下元素：
- 一个多色图案，由 3-4 种颜色（蓝(1)、红(2)、绿(3)、黄(4)）的像素组成，占据网格大部分区域。该图案相对于某条垂直线具有左右反射对称性，但对称轴右侧（或左侧）的一片矩形区域被清空为背景色（"残缺区域"），使得图案的对称性不完整。
- 1 个灰(5)小矩形（1 像素宽、2 像素高或 2 像素宽、1 像素高），紧贴网格左边缘（或右/上/下边缘）。灰矩形所在的行（或列）恰好对应图案的对称轴位置。
- 生成约束：灰矩形滑至对侧后经过的路径所在行/列恰为图案的反射对称轴。残缺区域完全位于对称轴的一侧。灰矩形不与图案像素重叠。图案中对称轴另一侧的像素完整且足以唯一确定残缺区域中每个位置的颜色。

**规则**：
1. 将灰(5)矩形从当前接触的边缘滑至对侧边缘（如从左边缘滑至右边缘），在其经过的每个位置留下橙(7)轨迹像素，形成一条完整的行或列轨迹条纹。灰矩形最终停在对侧边缘。
2. 橙色轨迹条纹所在的行或列即为反射轴。
3. 以此轴为基准，对残缺侧的每个背景像素，复制其关于橙色轴的对称位置上的颜色。若对称位置也是背景色，则保持背景。
4. 删除所有橙色轨迹像素和灰色矩形像素（恢复为背景色(0)），输出完整的对称图案。

**关键洞察**：滑动操作的副产品（轨迹条纹）在源题 b25e450b 中是最终输出的一部分，但在此题中它被重新定义为对称补全操作的轴线参数——一个中间几何标记而非可见结果。求解者必须意识到灰矩形的位置不是"要移动的对象"，而是"编码了对称轴的位置信息"。

## 新题 5：帧序列外推叠加色彩循环轮换

**组合逻辑**：[外推/平移](已有) + [循环轮换/重涂色](已有，创新：两条独立的视觉规律——空间运动和色彩轮换——需同时从帧序列中提取并在外推帧中合并应用)

**来源原语**：外推(extrapolate) / 帧序列(frame_sequence) / 内部精灵(inner_sprite) / 等间距排列(equal_spacing) / 匀速运动延续(constant_motion) ← ba1aa698；循环轮换(cyclic_shift) / 重涂色(recolor) / 环绕角度排序(angular_order_around_center) ← 880c1354；平移(translate) ← ba1aa698

**依赖链**：帧序列同时编码空间运动规律和色彩轮换规律 → 外推需同时延续两条规律 → 只延续位置或只延续颜色均产生错误输出

从一排共享边界的帧面板中同时推断精灵的匀速运动轨迹和色彩循环规律，在外推的下一帧中合并应用两者。

**输入结构**：黑(0)背景。网格宽约 25-30，高约 8-10，由 3-4 个等宽面板横向排列组成，相邻面板共享 1 列垂直边界。每个面板内部：
- 灰(5)像素作为边框（顶行、底行、左右边界列；共享列同时属于相邻两个面板的边界）。
- 黑(0)填充区域。
- 一个 2x2 的小精灵（"核心块"），由 4 个像素组成，分别使用 4 种不同颜色（蓝(1)、红(2)、绿(3)、黄(4)各占一个像素）。精灵在每个面板中占据相同的列范围（相对于面板内部左边界的列偏移不变）。
- 精灵的行位置在面板间匀速变化：设第 k 个面板中精灵左上角相对面板内部顶行的行偏移为 d_k，则 d_{k+1} - d_k = 常数 delta_r（可为正或负整数）。
- 精灵的 2x2 像素颜色在面板间做顺时针循环轮换：将 2x2 块的四个位置按顺时针排列为 (左上, 右上, 右下, 左下)，每个后续面板中这四个位置的颜色相对前一面板顺时针旋转一个位置（即左上的颜色移到右上，右上移到右下，以此类推）。
- 生成约束：精灵在所有面板内完整可见（不超出边框内部区域）。delta_r 的值保证外推帧中精灵也完整可见。4 种颜色互不相同。

**规则**：
1. 识别面板序列及共享边界结构，确定面板内部宽度 W 和高度 H。
2. 检测精灵行位置变化模式：计算相邻面板间行偏移差 delta_r，确认为常数。
3. 检测精灵颜色轮换模式：比较相邻面板中精灵四个位置 (左上, 右上, 右下, 左下) 的颜色排列，确认每一步为顺时针单步循环。
4. 构建一个独立的输出面板（不与输入共享边界）：高度 = H + 2（含上下边框），宽度 = W + 2（含左右边框），边框色灰(5)，内部填充黑(0)。
5. 在输出面板中放置精灵：行偏移 = 最后一个面板的行偏移 + delta_r；颜色排列 = 最后一个面板的排列再顺时针旋转一步。列偏移与所有面板相同。

**关键洞察**：精灵同时编码了两种独立的变化规律——位置运动和颜色轮换。只追踪位置会得到正确位置但错误颜色；只追踪颜色会得到正确颜色但不知放在哪里。求解者必须从帧序列中同时提取两种模式并合并应用，两者缺一不可。

## 新题 6：形状分类计数决定环形换色步数

**组合逻辑**：[计数](已有，创新：计数对象不是区域或像素数，而是平移归一化后的形状等价类数量) + [循环轮换/重涂色](已有) + [擦除](已有)

**来源原语**：计数(counting) ← 89565ca0；循环轮换(cyclic_shift) / 重涂色(recolor) / 分隔结构(divider_structure) / 分离区域(separated_region) / 环绕角度排序(angular_order_around_center) ← 880c1354；擦除(erase) ← 6ca952ad；面积区分角色(area_determines_role) ← 6ca952ad；平移归一化(translate_normalize) / 形状相同(same_shape) ← ad38a9d0；小标记对象(small_marker_obj) ← 6ca952ad

**依赖链**：小对象按平移归一化分组 → 等价类数量 K 决定循环偏移步数 → 大区域按角度排序后做 K 步循环轮换 → 小对象被擦除。K、角度序、轮换操作三者缺一不可

统计散落小图形的形状种类数 K，将中心分隔器周围的大区域颜色按顺时针角度序环形移动 K 步，最后擦除所有小图形。

**输入结构**：黑(0)背景，约 15x15。包含：
- 网格中央有一个由黄(4)和橙(7)像素组成的十字形分隔器，水平臂和垂直臂各约 5-7 像素长，交叉于网格中心附近。黄(4)像素构成十字的主体，橙(7)像素为交叉中心的 1-2 个像素。
- 分隔器将周围空间分为 4 个象限区域。每个象限区域被一种单色前景填充（从蓝(1)、红(2)、绿(3)、品红(6)中选取四种不同颜色），每个区域是一个 4-连通的单色块（面积约 8-15 像素），形状由分隔器臂和网格边缘共同界定。
- 散布在网格中（位于大区域像素和分隔器像素之间的背景间隙中、或紧贴网格边缘处），有 4-8 个灰(5)小对象，每个面积 1-3 像素（4-连通）。这些小对象中存在形状重复：例如可能有 3 个单像素点、2 个水平 2 像素条、1 个垂直 2 像素条，共 3 种不同的翻译归一化形状。
- 生成约束：灰色小对象不与分隔器或大区域的像素正交相邻。不同示例中灰色小对象的总数可能不同，但形状等价类数量 K 在同一题的所有示例中保持一致（通过不同数量的重复来保持 K 恒定）。K < N（区域总数），使得轮换后的颜色分配与原始不同。

**规则**：
1. 按面积区分角色：面积 <= 3 的灰(5) 4-连通分量为"小标记对象"，其余非分隔器、非背景的前景为"大区域"。
2. 对每个小标记对象做平移归一化（将其像素坐标平移使最小行和最小列都为 0），得到归一化形状。按归一化形状分组，形状完全相同的归为一类。统计不同形状类别的数量 K。
3. 计算每个大区域的质心坐标。以分隔器交叉中心为原点，按屏幕坐标系顺时针方向（从正上方 12 点钟方向开始，即 -y 轴正方向，顺时针旋转）对各区域质心的角度排序，得到有序序列 R_0, R_1, ..., R_{N-1}。
4. 执行循环轮换：区域 R_i 获得区域 R_{(i - K) mod N} 的颜色。所有区域同时更新颜色。分隔器像素保持黄(4)和橙(7)不变。
5. 将所有灰(5)小标记对象擦除为背景色(0)。

**关键洞察**：轮换步数 K 编码在小灰对象的形状多样性中，而非它们的数量、位置或颜色。直觉上的错误假说"数有几个灰色小东西"（得到总数）或"看灰色小东西分布在几个象限"在不同示例中会给出不同的 K 值，只有"形状归一化后的种类数"在所有示例中一致——必须对比多个示例才能发现。

## 新题 7：射线分割空间决定载荷循环位移量

**组合逻辑**：[射线延伸](已有，创新：射线的功能从视觉装饰变为空间分割以产生可计数区域) → [计数](已有，创新：分别计数不同方位的区域数) → [循环位移](已有，创新：位移量从标记像素坐标编码改为区域计数编码)

**来源原语**：射线延伸(ray_cast) / 对角线段(diagonal_segment) / 端点发射(emit_from_endpoints) / 碰撞停止(collision_stop) ← 80a900e0；计数(counting) / 封闭区域(enclosed_region) ← 89565ca0；循环位移(cyclic_roll) / 双轴偏移编码(dual_axis_offset) ← 79cce52d；裁剪(crop) ← 79cce52d

**依赖链**：对角线段端点发射射线 → 射线将载荷外围空间分割为若干背景区域 → 左侧区域数和上方区域数分别决定垂直和水平循环位移量 → 对载荷执行双轴循环位移后裁剪输出

从灰色边框外的对角线段端点发射射线将周边空间分割为背景区域，分别计数边框左侧和上方的区域数作为载荷的垂直和水平循环位移量。

**输入结构**：黑(0)背景，约 15x15。包含以下元素：
- 网格中央有一个由灰(5)像素围成的空心矩形边框（如 7x7，边框宽度 1 像素），内部是一个多色载荷图案（使用蓝(1)、红(2)、绿(3)、黄(4)等颜色，形成一个非对称的彩色图案，占满边框内部的 5x5 区域）。
- 边框外左侧区域（边框左边界以左的列）有 1-2 条短的对角线段（每条 2-3 像素长），使用品红(6)绘制。对角线段方向为 45 度或 135 度。
- 边框外上方区域（边框上边界以上的行）有 1-2 条短的对角线段，同样使用品红(6)，方向为 45 度或 135 度。
- 生成约束：对角线段不接触灰色边框。边框外有至少 3 行/3 列的背景空间容纳射线延伸。射线沿线段方向延伸后最终碰到灰色边框或网格边缘而停止。左侧和上方的区域计数结果均不超过载荷尺寸（保证循环位移有意义）。

**规则**：
1. 对每条品红(6)对角线段，从其两个端点分别沿线段方向向外延伸射线（品红色像素），直到碰到非背景像素（灰色边框）或到达网格边缘为止。射线不覆盖终止位置上的非背景像素。
2. 射线画完后，计算灰色边框左侧空间（边框左边界以左、网格左边缘以右的矩形区域，含射线和线段像素）中的 4-连通纯背景(0)区域数量，记为 V。
3. 计算灰色边框上方空间（边框上边界以上、网格上边缘以下的矩形区域，含射线和线段像素）中的 4-连通纯背景(0)区域数量，记为 H。
4. 提取边框内部的载荷图案（不含灰色边框本身），尺寸为 h x w。
5. 将载荷向下循环位移 V 行（底部溢出的行回到顶部），再向右循环位移 H 列（右侧溢出的列回到左侧）。
6. 输出仅包含循环位移后的载荷（尺寸 h x w，无边框和射线）。

**关键洞察**：位移量不是由标记像素的坐标位置直接编码（如源题 79cce52d 中控制行/列的标记位置即为偏移量），而是通过射线对空间的几何分割间接编码——射线的数量、角度和位置决定了将空间切分为多少个区域，区域数才是位移参数。这使得求解者必须完成"射线延伸 → 空间分割 → 区域计数 → 位移应用"的三层推导，任何一步跳过都无法得到正确答案。
