## 新题 1：裂缝分裂后的互补形状配对填充

**组合逻辑**：[滑动/slide](创新：不再物理推开两半，而是用裂缝将对象分解为候选子形状) + [形状匹配/shape_match](已有) + [填充/fill](已有)

**来源原语**：slide、裂缝标记线/fracture_line、沿短轴分裂/split_along_short（参考题 2faf500b）；shape_match、模板缺口/template_gap、互补形状/complementary_shape、缺口形状唯一配对/unique_complement（参考题 18447a8d）

**依赖链**：裂缝分裂产生子形状 → 子形状的几何外形决定其与哪个模板缺口互补 → 互补匹配成功后才能确定填充位置和颜色。删除裂缝分裂步骤则子形状不存在、匹配无法进行；删除匹配步骤则不知道哪个子形状填入哪个缺口。

将带有裂缝标记线的前景对象沿裂缝分裂为两个子形状，再将每个子形状与模板缺口进行互补匹配，匹配成功的子形状填入缺口。

**输入结构**：黑(0)背景，网格约 18x18。网格分为上下两个水平区域，中间隔 1-2 行背景。上区域放置 3 个前景对象，每个对象是一种独立颜色（分别为绿(3)、黄(4)、橙(7)），每个对象是 4-连通的单色连通分量，约 8-12 像素。每个对象内部嵌有一条灰(5)裂缝标记线——宽 1 像素、沿对象包围框短轴方向完整贯穿对象。裂缝将每个对象分为两个子形状，且同一对象的两个子形状在归一化后形状不同。下区域放置 3 个蓝(1)模板矩形（约 5x5 至 7x7），每个矩形内部有一块不规则缺口（缺口由矩形内的背景色像素构成）。生成约束：每个对象的两个子形状中恰好有一个与某个模板缺口的归一化形状完全相同，且三个对象的匹配目标互不重复（一一对应）。

**规则**：
1. 对上区域的每个前景对象，定位其灰(5)裂缝标记线（1 像素宽、沿包围框短轴方向完整贯穿对象的灰色像素段）。
2. 移除裂缝像素（置为背景），将裂缝两侧的体色像素分为两个独立子形状。每个子形状归一化为相对于自身包围框左上角的坐标集合。
3. 对下区域的每个蓝(1)模板矩形，计算其缺口形状 = 模板矩形包围框内所有背景色像素的坐标集合，归一化为相对于缺口最小包围框左上角的坐标集合。
4. 将每个子形状与所有缺口形状匹配：归一化形状完全相同即为匹配（不旋转、不翻转）。每个缺口恰好匹配一个子形状。
5. 输出：将匹配成功的子形状填入对应模板缺口位置，填充颜色为该子形状的原体色。上区域中，匹配成功的子形状和裂缝线被擦除（置为背景），未匹配的子形状保留原位。模板矩形的蓝(1)像素保留不变。

**关键洞察**：待匹配的形状在输入中不可见——它们隐藏在完整对象的裂缝两侧，只有正确识别并移除裂缝标记线后，子形状才"浮现"，之后才能与模板缺口进行互补配对。

## 新题 2：描边围栏捕获重力落点触发空洞重涂

**组合逻辑**：[描边/draw_outline](已有) → [重力下落/gravity_drop](已有) → [重涂色/recolor](创新：重涂条件不再由对象自身属性决定，而由外部落点事件触发)

**来源原语**：draw_outline、前景对象/foreground_object、封闭孔洞/enclosed_hole、包含关系/containment、有孔触发重涂/hole_presence_triggers_recolor（参考题 aa4ec2a5）；gravity_drop、碰撞停止/collision_stop（参考题 36a08778、88e364bc）

**依赖链**：描边在对象周围创建一圈红色屏障 → 屏障改变重力下落路径（部分点被屏障拦截而无法进入空洞） → 落点是否落入空洞决定该对象是否被重涂。三步环环相扣：无描边则无屏障，落点路径不同；无重力则不知道哪些空洞被"命中"；无重涂则最终结果无法确定。

在前景对象周围画红色描边，描边形成围栏改变黄色散点的重力下落轨迹，最终根据散点是否落入对象的封闭空洞来决定是否重涂该对象。

**输入结构**：黑(0)背景，网格约 20x20。网格中散布 4-5 个蓝(1)前景对象，每个是 4-连通的单色连通分量，约 10-20 像素。其中 2-3 个对象内部有封闭空洞（对象包围框内被对象像素 4-连通包围的背景区域），其余对象为实心。在所有前景对象的上方（行号更小的位置），散布若干黄(4)单像素点，每个点下方的垂直路径上至少存在一个前景对象或其未来描边位置。生成约束：描边完成后，部分黄点的下落路径恰好通过某个空洞对象的空洞开口进入空洞内部，其余黄点被描边或对象表面拦截。至少一个空洞对象会被命中，至少一个空洞对象不会被命中。

**规则**：
1. 对网格中每个蓝(1)前景连通分量，在其 8-邻域的所有背景像素位置画红(2)描边（即对象边界向外扩 1 像素的壳层，仅占据原为背景的像素）。
2. 所有黄(4)像素执行重力下落：每个黄像素沿所在列逐行向下移动，遇到红(2)描边像素、蓝(1)对象像素、另一个已停止的黄像素、或网格底边时停止，停在障碍物正上方一格。多个黄像素在同一列时从最低的开始依次结算。
3. 下落结束后，检查每个含封闭空洞的蓝(1)对象：若至少一个黄像素停留在该对象封闭空洞内部（即停留位置处于对象包围框内、且该位置原为被对象像素 4-连通包围的背景像素），则该对象被"命中"。
4. 被命中的对象：将其蓝(1)体色重涂为青(8)，并将其所有封闭空洞（无论是否有黄像素）填充为品红(6)。品红填充覆盖空洞内已停留的黄像素。
5. 未被命中的空洞对象和所有实心对象保持蓝(1)不变。描边保持红(2)。未落入空洞的黄像素保留在其停止位置。

**关键洞察**：描边屏障在对象周围构建了额外的遮挡层，它既是视觉标记又是物理障碍——描边的存在改变了黄点的下落路径，使得只有特定列的黄点能穿过描边缺口进入空洞。重涂条件不再是对象自身"有洞就重涂"，而是"有洞且洞被外部事件命中才重涂"。

## 新题 3：控制条间距编码精灵体平铺周期

**组合逻辑**：[平铺/tile](创新：平铺周期不再由种子图案高度隐含给出，而由外部控制条间距显式编码) + [图案印章/stamp_glyph](创新：印章位置不再由占位符标记，而由周期计算确定)

**来源原语**：tile、控制条/control_bar、控制条周期延伸/control_periodic（参考题 34cfa167）；stamp_glyph、框架/frame、精灵体/sprite（参考题 edb79dae）；周期重复/periodic_repeat（参考题 9b30e358）

**依赖链**：控制条间距定义平铺周期 → 周期决定精灵体在框架内的放置位置 → 多种精灵体叠加时用控制条的左右顺序解决冲突。控制条提供参数，精灵体提供形状，框架提供域——三者缺一不可。

读取框架顶边控制条的颜色和间距，将对应颜色的精灵体以该间距为周期在框架内部二维平铺。

**输入结构**：黑(0)背景，网格约 22x22。网格中央有一个灰(5)矩形框架，框架线宽 1 像素，框架内部为背景色，内部区域约 14x14。框架外部散布 2-3 个小型精灵体，每个精灵体是一种独立颜色（如红(2)、绿(3)、橙(7)），每个精灵体为 4-连通单色图形、3-5 像素。沿框架顶边外侧（紧贴框架上方一行），放置若干宽 1 像素、高 1 像素的控制条像素，颜色与精灵体颜色对应。每种精灵体颜色恰好有 2 个控制条像素出现在顶边。生成约束：同色的两个控制条像素的水平间距（列号之差）能整除框架内部宽度；不同颜色的控制条像素互不重叠。

**规则**：
1. 对每种精灵体颜色 C，找到框架顶边外侧的两个颜色 C 控制条像素。设它们的列号为 c1 < c2，则平铺水平周期 Px = c2 - c1，水平起始偏移 Ox = c1 相对于框架内部左边界的列偏移。
2. 平铺垂直周期 Py = Px（正方形周期）。垂直起始偏移 Oy = 0（从框架内部第一行开始）。
3. 在框架内部，将精灵体 C 放置在所有满足以下条件的位置：精灵体左上角位于框架内部坐标 (Oy + k*Py, Ox + j*Px)，其中 j, k 为非负整数，且精灵体的所有像素都落在框架内部区域内（超出部分舍弃整个副本，不做裁剪）。
4. 若多个精灵体在同一像素位置重叠，以控制条像素中最靠左（列号最小的第一个控制条）的精灵体颜色优先显示。
5. 输出中保留框架线、所有平铺结果。框架外的精灵体原型和控制条像素被擦除（置为背景）。

**关键洞察**：控制条不再是框架边框的装饰图案——它们编码了精灵体在框架内部的平铺周期。不测量控制条间距就无法知道平铺参数，不识别精灵体就无法知道平铺内容，两个信息源在框架这一共同空间域中汇聚。

## 新题 4：计数奇偶门控架子渗透性的瀑布级联

**组合逻辑**：[重力下落/gravity_drop](已有) + [溢出扩散/overflow_spread](已有) + [计数/counting](创新：计数结果不再直接产出填充长度，而是作为奇偶门控改变架子的物理属性)

**来源原语**：gravity_drop、overflow_spread、水源/water_source、架子/shelf、级联分支/cascading_branch、碰撞停止/collision_stop（参考题 36a08778）；counting、计数像素/counter_pixel（参考题 2a28add5）

**依赖链**：计数架子上的标记点 → 奇偶性决定架子渗透/阻挡 → 渗透性改变瀑布级联路径 → 级联路径决定水流终点。计数和重力在同一空间结构（架子）上交互：计数改变架子属性，架子属性改变重力行为。

水流从顶部源头向下流动，遇到架子时根据架子上绿色标记点的奇偶数量决定架子是渗透（水穿过）还是阻挡（水溢出到两端），渗透/阻挡的判定从根本上改变了瀑布的级联分支拓扑。

**输入结构**：黑(0)背景，网格约 18x22。顶行有 1-2 个蓝(1)水源像素簇（每簇 1-3 像素宽）。网格中分布 4-6 条灰(5)水平架子段，每条架子为 1 像素高、4-10 像素宽，处于不同行。每条架子的表面（紧贴架子上方一行）散布若干绿(3)标记点像素，标记点的列号落在架子的水平范围内。生成约束：每条架子的绿色标记点数量在 1-4 之间；至少有一条架子标记点为奇数、至少一条为偶数；整个级联路径中至少存在一处因渗透/阻挡差异导致水流到达不同终点的分叉。

**规则**：
1. 对每条灰(5)架子，计数其正上方一行中与架子水平范围重叠的绿(3)标记点像素数量 N。
2. 若 N 为奇数：该架子为渗透架子——水流可以穿透它继续下落，架子不阻挡水流。
3. 若 N 为偶数：该架子为阻挡架子——水流被阻挡后沿架子表面水平扩散至架子两端，然后从两端各向外延伸 1 像素位置开始继续下落（即标准溢出）。
4. 水从蓝(1)源像素逐列向下流动，将经过的背景像素涂为蓝(1)。水流遇到阻挡架子时执行第 3 步的溢出。水流遇到渗透架子时直接穿过继续下落。水流到达网格底边时停止。
5. 多条水流在同一列相遇时合并为一条。水流不会穿过其他水流已占据的像素（自然合并，不阻挡）。
6. 输出中保留灰(5)架子和绿(3)标记点，蓝(1)水流覆盖在背景上。

**关键洞察**：绿色标记点不是装饰——它们的数量奇偶性决定每条架子是"实体墙"还是"虚空"。删除或添加一个标记点就能翻转一条架子的物理属性，从而将整棵瀑布级联树的拓扑结构彻底改变。

## 新题 5：对角锚点补全后按图例分层扩展填充

**组合逻辑**：[补全/complete](已有) + [扩展/expand](创新：扩展对象不存在于输入中，由补全步骤生成) + [填充/fill](已有) + 图例层级冲突解决

**来源原语**：complete、锚矩形/anchor_rectangle、对角对称/diagonal_symmetry（参考题 34cfa167）；expand、fill、散布点/sparse_dot、图例/legend、图例配色/legend_color_pair、图例顺序决定层级/legend_order_layer、冲突优先级/conflict_priority（参考题 305b1341）

**依赖链**：对角锚点补全 → 生成完整矩形区域 → 图例定义每种矩形颜色的填充色和层级 → 多矩形重叠时按图例顺序决定优先级。补全步骤产出扩展步骤的输入几何体；图例同时控制颜色映射和冲突解决——两条信息流在重叠区域交汇。

将多组对角放置的同色锚矩形对补全为完整四角矩形，然后各自向外扩展一圈，用图例指定的颜色填充扩展区域，重叠处按图例行序分层。

**输入结构**：黑(0)背景，网格约 20x20。网格中有 3 组锚矩形对，每组由两个相同颜色的实心小矩形（约 2x2 至 3x3）组成，分别位于某个隐含大矩形的对角位置（一个在左上、一个在右下）。三组颜色分别为红(2)、绿(3)、黄(4)。网格左上角有一个两列图例：图例占据第 0-1 列的前 3 行，每行左列为一种锚矩形颜色、右列为对应的填充颜色（如红(2)→蓝(1)、绿(3)→橙(7)、黄(4)→灰(5)）。生成约束：三组隐含大矩形互相有部分重叠，但锚矩形本身不重叠；图例区域不与任何锚矩形或隐含大矩形重叠。

**规则**：
1. 擦除图例区域（置为背景），但记录图例映射关系和行顺序。
2. 对每组同色锚矩形对，推断其隐含的大矩形：左上角 = 左上锚的左上角，右下角 = 右下锚的右下角。
3. 在隐含大矩形的四个角位置各放置一份锚矩形副本（两个角已有原始锚，另两个角为新补全）。补全的锚矩形使用与原始锚相同的颜色。
4. 将每个隐含大矩形的包围框向外扩展 1 像素（上下左右各多 1 行/列）。
5. 在每个扩展区域内，将背景像素填充为该组的图例映射填充色。已有的锚矩形像素不被覆盖。
6. 多组扩展区域重叠时，图例中行号更小（更靠上）的组优先——其填充色覆盖行号更大的组的填充色。锚矩形像素始终高于任何填充色。
7. 扩展区域超出网格边界的部分舍弃。

**关键洞察**：填充区域的边界在输入中不可见——它们由对角锚点对的几何推断产生。图例不仅映射颜色，其行顺序还隐式编码了多层重叠的优先级。必须先完成补全才能知道扩展范围，必须读取图例才能知道填充色和层级。

## 新题 6：包围框包含擦除后的幽灵阻挡周期射线

**组合逻辑**：[擦除/erase](已有) + [周期填充/periodic_fill + 射线延伸/ray_cast](已有)（创新：被擦除对象在物理上消失但在逻辑上仍作为射线阻挡物存在）

**来源原语**：erase、连通分量/connected_component、包围框/bounding_box、包围框包含/bbox_containment、异色包含则删/delete_if_contained_by_other_color（参考题 9720b24f）；periodic_fill、ray_cast、边界点/boundary_dot、周期步长/periodic_step、同余对齐/modular_alignment（参考题 16de56c4）

**依赖链**：包围框包含判定 → 擦除被包含对象但记录其包围框 → 周期射线从边界点射出 → 射线遇到存活对象像素或幽灵包围框时停止。擦除步骤的输出（哪些对象被删、哪些存活）直接决定射线的阻挡图——幽灵对象和存活对象共同构成射线的终止条件。

先按包围框包含规则擦除被大对象包含的小异色对象，然后从网格边缘的标记点射出周期性射线，射线被存活对象的像素和被擦除对象的"幽灵包围框"同时阻挡。

**输入结构**：黑(0)背景，网格约 20x20。网格中有 4-6 个 8-连通单色矩形轮廓（即矩形框，非实心），每个轮廓颜色各不相同（使用红(2)、绿(3)、蓝(1)、橙(7)等）。其中 1-2 个较小矩形轮廓的包围框完全被某个较大异色矩形轮廓的包围框包含。沿网格左边缘（第 0 列），放置若干标记点对：每种标记点颜色恰好出现 2 个，颜色与某个存活矩形轮廓的颜色相同。两个同色标记点位于不同行，它们的行号差定义周期。生成约束：每种标记点颜色对应的矩形轮廓必须是存活的（不被擦除的）；标记点颜色互不相同；射线路径上至少有一条射线会被幽灵包围框阻挡，且至少一条不会。

**规则**：
1. 找到所有 8-连通单色非背景矩形轮廓对象。
2. 若一个对象的包围框完全被另一个不同颜色对象的包围框包含，则擦除被包含对象（其像素置为背景）。记录被擦除对象的包围框区域为"幽灵区域"。
3. 对网格左边缘每对同色标记点（颜色 C，行号 r1 < r2）：周期 P = r2 - r1，偏移 = r1 mod P。
4. 从 r1 行开始，沿该行向右射出水平射线，在每一行 r（满足 r mod P == r1 mod P 的所有行）射出水平射线。
5. 每条射线从第 1 列开始向右逐像素推进，将背景像素涂为颜色 C。射线在以下情况停止（停止位置不涂色）：遇到任何存活对象的非背景像素；或射线像素进入某个幽灵区域的包围框范围内。
6. 存活的矩形轮廓像素保持不变。标记点保留在第 0 列。

**关键洞察**：被包围框包含规则擦除的对象在视觉上消失了，但其占据的矩形区域仍然是射线的"隐形墙"。求解者必须先完成包含判定、记住被删对象的位置，再将这些看不见的障碍物纳入射线终止计算——可见几何与不可见几何共同决定输出。

## 新题 7：地形坡向编码可移动像素的滑动方向

**组合逻辑**：[重力下落→滑动/slide](创新：滑动方向不是全局固定的"向下"，而是由每个区域的地形坡向局部编码) + [重涂色/recolor](创新：重涂条件由地形高度极值决定，而非直接由颜色属性决定)

**来源原语**：gravity_drop、可移动像素/movable_pixel、碰撞停止/collision_stop、编码映射/encoding_map（参考题 88e364bc）；recolor、地形轮廓/terrain_contour、列高度极值/column_height_extreme、最深与最浅列唯一/unique_deep_shallow（参考题 e45ef808）；分隔墙线/separator_wall、背景区域/background_region（参考题 3bd292e8）

**依赖链**：分隔墙划分区域 → 每个区域的地形轮廓坡向决定该区域的滑动方向 → 可移动像素按该方向滑动至碰撞停止 → 滑动后，地形最高和最低区域的可移动像素被重涂为特殊颜色。地形既是物理障碍又是方向编码器，双重角色不可分离。

红色墙线将网格分为多个区域，每个区域底部有灰色地形轮廓，黄色可移动像素根据所在区域地形的坡向滑动，最终地形最高区域和最低区域的像素被标记为特殊颜色。

**输入结构**：黑(0)背景，网格约 18x18。红(2)墙线（1 像素宽，水平或垂直线段）将网格分为 4-6 个矩形区域。每个区域底部有灰(5)地形轮廓——从区域底行向上、每列有一段连续的灰色像素，各列高度不同，形成一个不规则的地形剖面。每个区域的地形轮廓有明确的单调趋势：要么从左到右递增（左低右高），要么从左到右递减（左高右低）。每个区域中散布 2-4 个黄(4)可移动单像素，位于地形之上的空背景位置。生成约束：所有区域中恰好有一个区域的地形最高列高度是全局最大值（唯一），恰好有一个区域的地形最高列高度是全局最小值（唯一）；每个区域内的可移动像素在滑动后不会超出区域边界。

**规则**：
1. 识别红(2)墙线划分的所有矩形区域。
2. 对每个区域，分析其灰(5)地形轮廓的坡向：比较地形最左列高度和最右列高度。若最左列高度 < 最右列高度（左低右高），则该区域的滑动方向为"向右"；若最左列高度 > 最右列高度，则滑动方向为"向左"。
3. 每个区域内的所有黄(4)像素沿该区域的滑动方向水平移动，遇到以下障碍时停止在障碍前一格：红(2)墙线像素、灰(5)地形像素、区域边界（网格边缘）、另一个已停止的黄像素。同一区域内多个黄像素按滑动方向排序（向右滑则从最右边的像素开始处理，向左滑则从最左边的开始），逐个结算。
4. 滑动完成后，计算每个区域的地形峰值 = 该区域中灰(5)地形轮廓最高列的高度（像素数）。
5. 地形峰值全局最大的区域内所有黄(4)像素重涂为栗(9)。
6. 地形峰值全局最小的区域内所有黄(4)像素重涂为蓝(1)。
7. 其余区域的黄(4)像素保持黄色。墙线和地形不变。

**关键洞察**：地形轮廓扮演双重角色——它既是可移动像素的物理障碍（影响滑动终点），又通过坡向编码了滑动方向（影响滑动起始行为），还通过峰值高度决定了最终的重涂标记。三个功能耦合在同一个几何结构上，无法分离处理。

## 新题 8：裂缝分裂诱导二部图着色

**组合逻辑**：[滑动/slide](已有) + [重涂色/recolor](创新：重涂颜色由分裂后产生的图结构的二部图着色决定) — 结构解构型，非线性流水线

**来源原语**：slide、裂缝标记线/fracture_line、沿短轴分裂/split_along_short、两侧等距分离/halves_separate（参考题 2faf500b）；recolor、四邻接连通/four_neighbor_connect、二部图结构/bipartite_structure、交替着色/alternating_coloring（参考题 3bd292e8）

**依赖链**：裂缝识别 → 沿裂缝分裂并滑动分离 → 分离后的碎片构成邻接图（共享同一条裂缝的碎片互为邻居） → 邻接图是二部图，交替着色。裂缝同时承担三个角色：定义分裂位置、定义滑动方向、定义图邻接关系。这三个功能由同一组像素实现，无法跳步。

将一个含有多条内部裂缝线的大型单色对象沿裂缝分裂为多个碎片，碎片沿裂缝法线方向各滑动 1 像素分离，然后根据碎片间的原裂缝邻接关系构建二部图并交替着色。

**输入结构**：黑(0)背景，网格约 16x16。网格中有一个大型蓝(1)前景对象，占据网格中央约 10x10 的区域，形状大致为矩形但边缘可不规则。对象内部嵌有 2-4 条灰(5)裂缝标记线，每条裂缝为 1 像素宽，沿水平或垂直方向完整贯穿对象的一个局部区段（即裂缝的两端都到达对象边界或另一条裂缝）。裂缝线将对象分为 3-5 个 4-连通的蓝色碎片。生成约束：裂缝网络将对象分成的碎片邻接图是二部图（即不存在奇数环——这对于树形或网格形裂缝网络自然成立）；每个碎片至少 4 像素。

**规则**：
1. 识别所有灰(5)裂缝标记线。
2. 移除所有裂缝像素（置为背景）。此时蓝(1)像素被分为若干 4-连通碎片。
3. 对每个碎片，确定与其相邻的裂缝线方向：对于碎片边界上原本紧邻裂缝的像素，裂缝的方向即为该碎片在该侧的分离方向。每个碎片沿每条相邻裂缝的法线方向（垂直于裂缝）向远离裂缝的一侧平移 1 像素。若碎片两侧都有裂缝，则两个方向的平移叠加。
4. 构建碎片邻接图：若两个碎片在分裂前共享同一条裂缝线（裂缝两侧分别属于这两个碎片），则它们在图中相连。
5. 对邻接图进行二部图着色：包含原对象最左上角像素的碎片着绿(3)，与其图邻居着黄(4)，交替进行。
6. 输出中各碎片以着色后的颜色显示在平移后的位置。原裂缝位置和因平移产生的间隙均为背景色。

**关键洞察**：裂缝标记线是整道题的信息枢纽——它同时编码了三件事：在哪里切割（分裂位置）、往哪个方向推开（滑动法线方向）、谁和谁相邻（图的边）。看似简单的灰色线条其实承载了全部变换逻辑，三个推理步骤全部从同一组像素中提取不同维度的信息。
