## 新题 1：缩放模板级联激活网络

**组合逻辑**：[像素放大 + 缩放对应](从参考题1提取，创新为"缩放匹配揭示端口方向") → [级联激活 + 射线延伸](从参考题3提取，创新为"大型形状的端口方向由模板匹配旋转量决定") → [重涂色](已有原语，创新为"激活状态决定涂色")

**来源原语**：像素放大(pixel_upscale)、缩放对应(scale_correspondence)、八方向匹配(all_orientations_matching) 来自参考题 898e7135；级联激活(cascade_activation)、射线延伸(ray_extend)、端口编码射线(port_encodes_ray)、链式反应传播(chain_reaction_propagation) 来自参考题 5961cc34；重涂色(recolor) 来自参考题 2de01db2

**依赖链**：缩放匹配确定每个大型形状对应的小模板及旋转量 → 旋转量决定大型形状上端口的实际朝向 → 端口朝向决定射线发射方向 → 射线命中触发级联激活 → 激活状态决定最终涂色

从散布的小模板和大型形状之间建立缩放匹配关系，利用匹配所需的旋转量推导大型形状的端口方向，从起点出发通过端口射线逐级激活形状，将被激活的形状重涂为红(2)。

**输入结构**：约 25x25 的网格，背景为黑(0)。网格中散布着 3~4 个小模板（每个是 3~5 像素的单色 4-连通图形，颜色各不相同，形状各异且不对称）和 3~4 个大型形状。每个大型形状是某个小模板的 k 倍放大版本（k 由最小实心正方形块的边长确定，约为 2 或 3），可能经过 90 度旋转或翻转。每个小模板上恰好有 1 个绿(3)像素紧邻其边界，标记端口方向（绿像素相对于模板质心的方向即为端口射线方向）。网格底部有一个黄(4)像素紧贴一段短红(2)线段作为起始标记，红线段指向某个大型形状。生成约束：大型形状之间互不重叠；每个大型形状恰好对应一个小模板；至少有一个大型形状无法被起始射线的级联链到达。

**规则**：
1. 识别所有小模板（3~5 像素的非背景 4-连通分量，排除起始标记和绿像素）和所有大型形状（像素数 >= 小模板像素数 x k^2 的非背景 4-连通分量）。确定缩放因子 k = 大型形状中最小的实心正方形块的边长。
2. 对每个大型形状，按 k 倍降采样得到缩小版掩码，与每个小模板在 8 个方向（4 次旋转 x 是否翻转）下比较，找到唯一匹配的模板及所需的旋转/翻转变换 T。
3. 从起始标记的红线段方向发出一条射线（颜色为红(2)），射线沿红线段延伸方向逐像素前进，直到命中某个大型形状的边界或到达网格边缘。
4. 命中的大型形状被"激活"：将其所有像素重涂为红(2)。
5. 对被激活的大型形状，找到其匹配模板上的绿像素端口方向，将该方向施加变换 T 的旋转/翻转分量，得到大型形状上端口的实际射线方向。从大型形状边界沿该方向发出射线（颜色红(2)），射线宽度为 k 像素，逐像素前进直到命中另一个大型形状或到达网格边缘。
6. 重复步骤 4-5，直到没有新的形状被激活。
7. 输出：被激活的大型形状涂为红(2)，射线保留为红(2)，未激活的大型形状保持原色，小模板和绿像素、起始标记保持不变。

**关键洞察**：端口方向不是直接标注在大型形状上的，而是标注在小模板上——必须先通过缩放匹配确定旋转量，才能推算大型形状上端口的真实朝向；同一个模板的不同放大副本可能因旋转不同而射线方向完全不同。

## 新题 2：遮挡层序驱动的逐行主色反转

**组合逻辑**：[补全 + 遮挡层序](从参考题8提取，创新为"层序不用于重建输出，而用于确定每行的主色") → [反转 + 逐行独立](从参考题9提取，创新为"主色由遮挡关系而非像素频率决定") → [忽略干扰项](已有原语，创新为"非最高层可见色作为干扰项参与反转")

**来源原语**：补全(reconstruct)、遮挡层序(occlusion_order)、空心矩形精灵(ring_sprite)、遮挡碎片(occluded_fragment)、可见像素定边框(visible_defines_bbox)、忽略干扰项(ignore_distractors) 来自参考题 652646ff；反转(invert)、逐行独立(row_independent)、主色与背景互换(native_bg_swap) 来自参考题 2de01db2

**依赖链**：从可见碎片重建完整精灵体 → 根据被占位关系推断遮挡层序 → 每行中最高层精灵体的颜色成为该行主色 → 主色像素变背景、其余像素（含背景和低层颜色）变主色

从互相重叠的空心矩形精灵碎片中重建完整形状并推断前后层序，然后对每一行独立执行反转：该行最高层精灵的颜色与背景互换，低层颜色一律转为最高层颜色。

**输入结构**：约 20x20 的网格，背景为黑(0)。3~5 个不同颜色的空心矩形精灵（每个是 1 像素厚的矩形环，边长 5~8 像素不等）互相重叠放置。每个精灵只有部分像素可见——被上层精灵遮挡的位置显示上层的颜色。可能有 1~2 个噪声像素（颜色不属于任何精灵的模板位置），作为干扰项。精灵的颜色从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中选取。生成约束：每个精灵至少有 40% 的模板像素可见；遮挡关系构成全序（不存在循环遮挡）；至少有两行被不同的最高层精灵覆盖（使得不同行的主色不同）。

**规则**：
1. 识别每个颜色的可见像素集合。对每种颜色，将其可见像素拟合到一个空心矩形模板上（即找到一个矩形环使得所有可见像素都落在该环上）。忽略不属于任何矩形环模板的孤立像素（干扰项）。
2. 对每对精灵 A、B：如果 A 的模板上某些位置本应有 A 的颜色，但实际被 B 的颜色占据，则 B 在 A 之上。由此建立遮挡全序，从最高层到最低层。
3. 对输出网格的每一行独立处理：找出该行中所有精灵模板覆盖的区域，取遮挡层序中最高的那个精灵的颜色作为该行的"主色"。如果该行没有任何精灵覆盖，则该行保持全黑不变。
4. 在有主色的行中执行反转：该行中所有主色像素变为黑(0)；该行中所有非主色像素（包括原本的黑(0)背景和低层精灵颜色）变为主色。
5. 干扰项像素在步骤 1 中已被忽略（不属于任何模板），它们的位置在步骤 4 中按"非主色像素"规则处理，即变为当行主色。

**关键洞察**：每行的"主色"不是简单地数像素频率，而是由遮挡层序中覆盖该行的最高层精灵决定——同一个精灵在某些行是最高层、在另一些行不是，所以不同行的反转颜色可以不同；必须对比多个示例才能区分"频率最高"和"层序最高"这两种竞争假设。

## 新题 3：角落扩展射线碰撞网络

**组合逻辑**：[像素放大 + 朝向对应角 + 扩展至外角](从参考题13提取，创新为"扩展后的 L 臂成为射线发射源") → [射线延伸 + 碰撞转向规则 + 射线交汇](从参考题2提取，创新为"射线源不是带框块而是扩展角 L 的臂端") → [重涂色](已有原语，创新为"碰撞点颜色由射线来源的角落位置决定")

**来源原语**：角落标记(corner_marker)、朝向对应角(facing_corner)、扩展至外角(expand_to_corner) 来自参考题 b745798f；射线延伸(ray_extend)、射线交汇(beam_intersection)、碰撞停止(collision_stop)、碰撞转向规则(collision_turn_rule) 来自参考题 e12f9a14；重涂色(recolor) 来自参考题 ff2825db

**依赖链**：小 L 标记的朝向决定它映射到哪个外角 → 扩展后的角 L 两臂端点成为射线发射点 → 射线沿臂延伸方向向网格内部行进 → 不同角落的射线相遇时按碰撞规则交互 → 碰撞点的颜色由碰撞双方的角落位置共同决定

将散落在网格内的小 L 标记按朝向扩展到对应外角，再从每个扩展角 L 的两臂末端向内发射射线，射线碰撞时按夹角规则转向或合并，碰撞点涂为两条射线来源颜色的混合色。

**输入结构**：奇数边正方形网格（约 19x19 或 21x21），背景为黑(0)。网格内散布 2~4 个小 L 标记，每个是 2x2 区域内的 3 像素单色 4-连通 L 形（缺少一个角的 2x2 块），颜色各不相同，从蓝(1)、红(2)、绿(3)、黄(4)中选取。每个 L 的开口方向不同，指向四个对角方向之一。生成约束：不同标记映射到不同的外角（即最多 4 个标记，每个占据一个角）；网格足够大使得射线有空间碰撞。

**规则**：
1. 清空网格为黑(0)背景。
2. 对每个小 L 标记，根据其 L 开口的朝向确定映射的外角（开口朝左上 → 左上角，开口朝右上 → 右上角，开口朝左下 → 左下角，开口朝右下 → 右下角）。在该外角绘制同色的角 L，两臂长度各为 (网格边长-1)/2 像素，沿网格边缘延伸。
3. 从每个扩展角 L 的两臂末端（非角点端），向网格内部发射 1 像素宽的射线，颜色为该角 L 的颜色。射线方向与臂方向垂直且指向网格中心。射线逐像素前进，直到命中网格边缘、另一条已有射线或扩展角 L 的臂体。
4. 碰撞规则（按射线间夹角区分）：
   - 正交碰撞（两射线行进方向成 90 度）：两条射线均在碰撞点前 1 像素处停止，碰撞点本身留空（保持背景色），两条射线各自向夹角的角平分线方向偏转继续延伸 1 像素宽的对角线段，直到再次碰撞或到达边缘。
   - 对向碰撞（两射线行进方向成 180 度）：两条射线在相遇点合并停止，相遇点涂为灰(5)。
5. 碰撞点及偏转线段的颜色规则：如果两条碰撞射线颜色不同，偏转线段交替使用两种颜色（从碰撞点起每像素交替）；如果颜色相同，偏转线段保持该颜色。
6. 所有射线绘制完成后，扩展角 L 本身保持其原色不变。

**关键洞察**：射线的发射方向不是由标记本身的位置决定，而是由标记扩展到外角后臂的几何结构决定——同一个颜色的标记放在不同位置但朝向相同，射线方向完全一样；不同朝向的标记即使颜色相同，射线方向也不同。碰撞规则需要对比多个示例才能区分正交与对向两种情况。

## 新题 4：面板压缩后按轴距排序旋转堆叠

**组合逻辑**：[压缩 + 空行丢弃](从参考题11提取，创新为"压缩改变对象的相对位置，影响后续距离计算") → [排序 + 距离排序](从参考题7提取，创新为"距离基于压缩前的原始位置而非压缩后位置") → [旋转 + 轴色决定旋转](从参考题7提取，创新为"旋转判据来自面板到轴线的距离而非对象到轴线的距离") → [堆叠](从参考题7提取)

**来源原语**：压缩(compress)、分栏面板(panel)、分隔列(divider_column)、非空行(occupied_row)、空行丢弃(empty_rows_discarded)、逆序扫描(reverse_scan) 来自参考题 25c199f5；排序(sort)、旋转(rotate)、距离排序(distance_ordering)、堆叠(stacking)、坐标轴线(coordinate_axis_line)、轴色决定旋转(axis_color_determines_rotation) 来自参考题 291dc1e1；矩形(rectangle) 来自参考题 291dc1e1

**依赖链**：识别面板和分隔列 → 各面板独立压缩（丢弃全背景行）→ 记录每个矩形在压缩前面板中的原始位置 → 以两条边缘轴线为参考，按矩形到蓝轴的原始距离排序 → 矩形所在面板到红轴的距离决定是否旋转 90 度 → 按排序结果从上到下堆叠（可能已旋转的）矩形

将三个分栏面板中的矩形压缩去空行后，按各矩形在压缩前距蓝色轴线的原始距离排序，再根据矩形所属面板到红色轴线的距离决定是否旋转，最终堆叠输出。

**输入结构**：约 12x28 的宽网格，背景为黑(0)。两条灰(5)全高分隔列将网格分为三个等宽面板。每个面板内有 1~2 个不同颜色的实心矩形（3~6 像素宽，2~4 像素高），颜色从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中选取，各矩形颜色互不相同。网格的上边缘有一条蓝(1)水平线（1 像素高，贯穿整个网格宽度），左边缘有一条红(2)垂直线（1 像素宽，贯穿整个网格高度），两线在左上角交汇处为品红(6)。各面板中矩形之间有若干全背景行。生成约束：至少有两个面板各含 2 个矩形；矩形不与轴线重叠；不同面板中的矩形到蓝轴距离互不相同。

**规则**：
1. 识别三个面板（由灰(5)分隔列分隔）。识别蓝(1)水平轴线和红(2)垂直轴线（左上角品红(6)像素为两轴交点）。
2. 记录每个矩形在其面板中的原始位置：矩形到蓝轴（上边缘）的距离 = 矩形上边缘行号 - 蓝轴行号；矩形到红轴（左边缘）的距离 = 矩形所在面板的左边缘列号 - 红轴列号。
3. 对每个面板独立压缩：保留包含非背景像素的行，丢弃全背景行，将保留的行紧凑排列到面板底部，上方用背景行填充。
4. 对所有面板中的矩形按到蓝轴的原始距离从小到大排序（距离近的排前面）。
5. 对每个矩形判断旋转：计算其所在面板的中心列到红轴的距离。如果该距离大于网格宽度的一半，则将该矩形旋转 90 度逆时针（宽高互换）；否则不旋转。
6. 将排序后的矩形从上到下堆叠在输出网格中：输出网格宽度等于所有（旋转后）矩形的最大宽度，高度等于所有矩形高度之和。每个矩形水平居中放置，纵向紧密排列无间隔。背景为黑(0)。

**关键洞察**：压缩操作改变了矩形的视觉位置，但排序使用的是压缩前的原始距离——必须对比多个示例才能发现距离并非从压缩后的布局中计算；同时，旋转判据是面板级别的（面板到红轴的距离），而非矩形级别的，所以同一面板内的两个矩形要么都旋转要么都不旋转。

## 新题 5：十字遮罩修复后的二面体等价表

**组合逻辑**：[补全 + 从平行行列推断](从参考题19提取，创新为"修复遮罩是为了还原被隐藏的对象轮廓") → [形状匹配 + 旋转翻转等价](从参考题6提取，创新为"等价比较的对象由修复结果决定") → [绘制表格 + 等价涂指定色](从参考题6提取，创新为"表格的行列顺序由修复后新合并的连通分量面积决定")

**来源原语**：补全(complete)、十字遮罩(cross_mask)、行列对齐(row_col_aligned)、从平行行列推断(infer_from_parallel) 来自参考题 b7955b3c；形状匹配(shape_match)、归一化掩码(normalized_mask)、等价表格(equivalence_table)、旋转翻转等价(dihedral_equiv)、等价涂指定色(equiv_colored)、绘制表格(draw_table)、忽略干扰项(ignore_distractors)、边缘图例(edge_legend) 来自参考题 6165ea8f

**依赖链**：修复灰色十字遮罩还原底层颜色 → 修复后一些原本分离的同色区域合并为完整连通分量 → 识别所有完整对象并归一化掩码 → 按面积从大到小排序确定表格行列顺序 → 两两比较掩码的二面体等价性 → 绘制等价表格

修复网格中的灰色十字遮罩以还原完整的彩色拼图，将修复后浮现的完整对象提取并归一化，按面积排序后绘制二面体等价表格。

**输入结构**：约 18x18 的网格，无固定背景色（整个网格被不同颜色的矩形区域填满，类似拼图）。3~5 个灰(5)十字遮罩（每个为 3x3 的加号形，中心像素加上下左右各 1 像素）覆盖在拼图上。拼图由水平和垂直色带组成（每条色带 2~4 像素宽），颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取。部分十字遮罩恰好遮盖了两个同色区域之间的连接部位，导致修复前它们看似分离但修复后合并为一个连通分量。网格最右列有一列单色像素（每种前景色各一个，从上到下排列），作为图例但不参与修复和对象识别。生成约束：十字遮罩不重叠；至少有 2 个遮罩遮盖了同色区域的连接处；修复后的对象中至少有一对是二面体等价的、至少有一对不等价。

**规则**：
1. 将所有灰(5)像素标记为"未知"。对每个未知像素，在同一行或同一列中找到最近的非灰非图例像素，用该颜色填充。如果同行同列有不同颜色的候选，取与未知像素曼哈顿距离更近的那个；距离相同时取同行方向的颜色。
2. 修复完成后，忽略最右列图例像素，对网格中每种颜色提取所有 4-连通分量。每种颜色只保留面积最大的连通分量作为"主对象"，丢弃面积更小的碎片（干扰项）。
3. 对每个主对象裁切到紧凑边界框，得到归一化掩码。
4. 将所有主对象按面积（像素数）从大到小排序。面积相同时，按其边界框左上角从上到下、从左到右排序。
5. 绘制等价表格：沿顶部和左侧各放置一组 2x2 色块作为标签，颜色为对应主对象的颜色，标签之间隔 1 列/行背景色黑(0)。表格共 N 行 N 列（N = 主对象数）。
6. 对每个表格单元 (i, j)（i != j）：比较第 i 个和第 j 个主对象的归一化掩码，在 8 个方向（4 次 90 度旋转 x 是否水平翻转）下是否存在完全匹配。匹配则填 2x2 红(2)块，不匹配则填 2x2 灰(5)块。对角线单元 (i, i) 留为黑(0)背景。

**关键洞察**：十字遮罩不仅遮盖了颜色信息，还人为切断了某些对象的连通性——修复遮罩后原本分离的区域重新连通，改变了对象的数量和形状，进而影响等价判断的结果。仅看修复前的布局会得到错误的等价表。

## 新题 6：同心方阵按色频循环缩放后位移

**组合逻辑**：[计数](从参考题14提取，创新为"色频不用于选择颜色而用于确定循环步数") → [缩放 + 边长循环变换 + 同心定位](从参考题18提取，创新为"循环步数由外部色频决定而非固定为 1 步") → [平移 + 颜色编码位移](从参考题5提取，创新为"位移施加在缩放后的方阵上而非单像素上")

**来源原语**：计数(counting)、众数颜色决定输出(majority_color_out) 来自参考题 ff2825db；缩放(resize)、奇数边正方形(odd_side_square)、中心点(center_point)、同心定位(concentric_position)、边长循环变换(side_length_cycle) 来自参考题 522fdd07；平移(translate)、颜色编码位移(color_encoded_disp)、颜色决定偏移(color_determines_offset)、前景像素(foreground_pixel) 来自参考题 342dd610

**依赖链**：统计散布标记像素中各颜色的数量 → 每个方阵按自身颜色对应的标记数量在循环序列中前进相应步数 → 缩放后若两个方阵中心重合且新边长相同则合并（保留原来更靠近网格中心的那个） → 存活的方阵按自身颜色编码的位移向量平移

统计散布标记像素的颜色频率，以此决定每个同心奇数边正方形在尺寸循环中前进的步数，缩放后按颜色编码的位移向量平移到最终位置。

**输入结构**：约 25x25 的网格，背景为黑(0)。网格中有 3~5 个单色实心正方形，边长为奇数且属于集合 {1, 3, 5, 7, 9}，颜色各不相同，从橙(7)、红(2)、栗(9)、蓝(1)中选取。各方阵互不重叠，中心位置各异。网格中另外散布若干单独的前景像素（不与任何方阵相邻），颜色只从方阵使用的颜色中选取。生成约束：每种方阵颜色对应的散布像素数量在 1~4 之间；缩放后不会有两个方阵的中心恰好重合（除非题目设计需要合并的情况）；方阵颜色仅限橙(7)、红(2)、栗(9)、蓝(1)四种。

**规则**：
1. 识别所有实心奇数边正方形（边长属于 {1, 3, 5, 7, 9} 的 4-连通同色实心方块）和所有散布标记像素（不属于任何方阵的非背景孤立像素）。
2. 对每种方阵颜色 c，统计颜色为 c 的散布标记像素数量 n_c。
3. 对每个方阵，当前边长为 s，在循环序列 (1, 9, 7, 5, 3, 1, 9, 7, 5, 3, ...) 中从 s 出发前进 n_c 步，得到新边长 s'。保持方阵中心不变，将边长替换为 s'。循环规则：1→9→7→5→3→1→...
4. 清空画布为背景色。对每种颜色的位移规则为：橙(7)向上平移 2 格，红(2)向左平移 2 格，栗(9)向下平移 2 格，蓝(1)向右平移 1 格。
5. 对每个方阵，以其中心为锚点，施加颜色对应的位移向量，在新位置绘制边长为 s' 的同色实心正方形。超出网格边界的部分裁剪丢弃。
6. 如果两个方阵缩放后的新边长相同且平移后占据的区域有重叠，则后绘制的覆盖先绘制的。绘制顺序：按方阵中心到网格中心的曼哈顿距离从大到小绘制（离中心远的先画，近的后画覆盖）。
7. 散布标记像素不出现在输出中。

**关键洞察**：同一种颜色的标记像素数量越多，对应方阵在尺寸循环中跳跃越远——标记像素不是简单的装饰，而是编码了缩放的"步数参数"；需要对比多个示例才能发现颜色-位移映射（尤其区分橙向上、红向左等方向）以及计数-步数的关系。

## 新题 7：线段对齐编码的局部擦除深度

**组合逻辑**：[对齐 + 中位线为参考 + 裁剪](从参考题17提取，创新为"对齐后线段的长度差编码信息而非只是对齐本身") → [擦除 + 按对象局部裁切 + 相对自身定位](从参考题4提取，创新为"擦除的列数不固定为 2 而是由线段长度差决定") → [填充](已有原语，创新为"被擦除的区域用线段颜色填充而非留为背景")

**来源原语**：对齐(align)、线段(line_segment)、平行共向(parallel_codirectional)、中位线为参考(median_as_reference)、裁剪(trim) 来自参考题 e376de54；擦除(erase)、连通分量(connected_component)、局部边界列(local_bounding_col)、相对自身定位(self_relative_pos)、按对象局部裁切(local_bbox_crop) 来自参考题 52364a65；填充(fill) 来自参考题 2e65ae53

**依赖链**：将平行线段对齐到中位线 → 原始长度与中位线长度的差值成为擦除参数 → 每条线段颜色匹配一个同色连通分量 → 对该分量从局部左边缘起擦除"差值"列 → 被擦除的区域填充为该线段颜色（而非背景色）

将散布的平行线段对齐到中位线，利用每条线段被裁剪的量作为对同色对象从左侧擦除的列数，擦除后在原位置填入线段颜色形成条纹。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格左半区有 3~5 个同色 4-连通前景对象（每个 8~20 像素，形状不规则但至少占 3 列），颜色各不相同，从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取。网格右半区有与对象数量相同的水平线段，颜色与左半区对象一一对应（每种颜色恰好一条线段和一个对象）。线段长度各异（3~8 像素不等），起始列不同但都是水平方向。生成约束：线段数量为奇数（确保中位线唯一）；每条线段比中位线长度短的差值不超过该颜色对象的列跨度；至少有一条线段比中位线长（该对象不擦除）。

**规则**：
1. 识别右半区的所有水平线段。确定中位线段（按线段的垂直位置居中的那条；即按行号排序后取中间的线段）。记录中位线段的起始列和长度 L_med。
2. 对每条线段，将其起始位置对齐到中位线段的起始列，长度裁剪/扩展至 L_med。计算该线段的原始长度 L_orig 与 L_med 的差值 d = L_med - L_orig。如果 d <= 0（线段原本更长或等长），则 d 设为 0。
3. 在左半区找到与该线段同色的 4-连通前景对象。在该对象的局部边界框内，从对象最左边的列开始计数 d 列。
4. 将这 d 列中属于该对象的像素擦除（改为背景色黑(0)），同时在这 d 列中原本为背景色的像素填充为该对象的颜色。效果是：被擦除的列区域内，前景与背景反转。
5. 对象中 d 列之外的部分保持不变。输出中不保留右半区的线段（清除为背景色）。
6. 处理顺序：按对象边界框左上角从上到下处理，处理结果互不影响（各对象的局部擦除在各自的边界框内独立进行）。

**关键洞察**：线段的视觉作用不是装饰，而是隐式编码了每个对象的擦除深度——对齐到中位线的操作本身是信息提取手段而非最终目的；比中位线短的线段产生正的擦除深度，比中位线长或等长的线段意味着对象不被擦除。需要对比多个示例才能发现差值与擦除列数的对应关系。

## 新题 8：门控路径决定格子槽位填色

**组合逻辑**：[寻路 + 穿越门中心 + 走廊正交路径](从参考题10提取，创新为"路径不是连接两个标记而是从标记出发填充格子槽位") → [填充 + 槽位位置决定颜色](从参考题12提取，创新为"颜色不是由跨框架推断而是由到达该槽位的路径来源决定") → [连线 + 绘制](从参考题10提取，创新为"路径本身也是输出的一部分")

**来源原语**：寻路(pathfinding)、连线(draw_path)、平行墙壁(parallel_walls)、门段(door_segment)、标记像素(marker_pixel)、穿越门中心(through_door_center)、走廊正交路径(corridor_ortho_path) 来自参考题 7e576d6e；填充(fill)、格子框架(lattice_frame)、格子槽位(lattice_slot)、槽位位置决定颜色(slot_position_color)、跨框架对应(cross_frame_match) 来自参考题 2e65ae53；绘制(drawing) 来自参考题 13f06aa5

**依赖链**：识别格子框架的内部墙壁和门段位置 → 从每个彩色标记出发沿正交路径穿过门中心进入槽位 → 路径到达的槽位被填充为该标记的颜色 → 路径穿过门进入下一个相邻槽位时继续传播 → 两条路径同时到达一个槽位时按路径长度裁决

在格子框架的外侧放置彩色标记，每个标记沿正交路径穿过内部墙壁的门洞到达各个槽位，路径经过的槽位被填充为标记颜色，路径冲突时短路径优先。

**输入结构**：约 17x17 的网格，背景为黑(0)。灰(5)色 1 像素厚的线条构成一个 3x3 或 4x3 的格子框架（矩形网格状），将内部划分为若干矩形槽位（每个槽位 3x3 或 4x3 像素）。相邻槽位之间的灰色墙壁上各有恰好一个门（门 = 墙壁上 1 个被清除为背景色的像素）。格子框架外围的四条边上各有 0~2 个彩色标记像素（单像素，紧贴框架外壁），颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，共 3~5 个标记，颜色互不相同。框架外壁上也有门（外壁上被清除的像素），每个标记恰好与一个外壁门相邻。生成约束：从每个标记出发经过门可以到达至少 2 个槽位；所有槽位至少可被某个标记的路径到达；存在至少 1 个槽位可被两个不同标记的路径到达。

**规则**：
1. 识别格子框架（灰(5)线条）、门（灰色墙壁上的背景色缺口，每个门恰好 1 像素宽）、彩色标记（紧贴框架外壁的非背景非灰单像素）、槽位（灰色框架围成的矩形内部区域）。
2. 对每个标记像素，从其相邻的外壁门进入框架内部。路径规则：在槽位内部沿正交方向（水平或垂直）直线行进，方向为从入口门朝向槽位内部。路径到达对面墙壁时，如果该墙上有门，则穿过门进入相邻槽位并继续沿同一方向行进；如果无门，路径在当前槽位中转 90 度（优先向右转；右转方向也无门则向左转；两个方向都无门则路径终止），寻找有门的墙壁继续。
3. 路径经过的每个槽位被标记为该路径颜色的候选。记录从标记出发到进入该槽位所经过的门的数量作为"路径长度"。
4. 对每个槽位：如果只有一个标记的路径到达，填充该标记的颜色。如果有多个标记的路径到达，取路径长度最短的标记颜色填充；路径长度相同时，取标记像素距框架左上角曼哈顿距离更近的标记颜色。
5. 在输出中绘制路径：从每个标记出发的路径用该标记颜色在槽位背景上画 1 像素宽的线。路径线只画在最终获胜的槽位中（即该槽位被填充为该标记颜色的情况下才画该标记的路径线）。
6. 框架的灰色线条保持不变。标记像素保持不变。未被任何路径到达的槽位保持背景色（不应存在，见生成约束）。

**关键洞察**：槽位的颜色不是由其在框架中的位置静态决定的，而是由动态路径竞争的结果决定——同一个槽位在不同示例中可能因为标记位置和门的布局变化而被不同颜色的路径占据；需要多个示例才能归纳出路径长度优先的冲突解决规则和转向优先级。
