## 新题 1：密封框门控对称修复

**组合逻辑**：[包围/enclosure](创新：作为逻辑门控条件而非选择标准) + [对称补全/symmetry_completion](已有) + [重涂色/recolor](创新：用于"泄漏"惩罚) — 框的拓扑完整性决定内部是修复还是损坏

**来源原语**：enclosure、hollow_rectangle、object_with_hole_selected（参考题 #9 b9b7f026）；symmetry_completion、masked_pixel、symmetry_orbit_mapping（参考题 #2 47996f11）；recolor（参考题 #4 c8f0f002）

**依赖链**：框边界完整性检测的结果直接决定内部掩码像素适用哪种操作——密封框内走对称修复路径，破损框内走灰化惩罚路径。删掉完整性检测则无法区分两类框；删掉对称补全则密封框内的掩码无法恢复；删掉灰化规则则破损框内的掩码处理未定义。

密封框内利用镜像对称修复被遮掩的像素，破损框内将所有遮掩像素降级为灰色。

**输入结构**：
- 约 15x15 的网格，黑(0) 背景。
- 3~5 个不重叠的单色矩形框，每个框用不同颜色绘制（如红(2)、蓝(1)、绿(3)等），框线宽度为 1 像素。
- 每个框内部包含一个使用 2~3 种非框色、非背景色的图案，其中部分像素被品红(6) 掩码替代。掩码像素数约占框内总像素的 20%~40%。
- 部分框的边界是完整的（所有边框像素均存在），形成密封空心矩形；部分框的边界有 1~2 个缺口（缺口处为背景色），形成破损框。
- 框内图案（含掩码位置在内）关于框内部区域的左右中轴具有镜像对称性。
- 生成约束：每个密封框内，每个品红(6) 像素的左右镜像对应位置至少有一个是非品红的可见像素。框外不存在品红(6) 像素。

**规则**：
1. 对每个矩形框，检测其边界是否完整——即该框颜色的像素是否在框的边界框范围内形成闭合的一像素宽矩形环，无任何缺口。
2. 密封框处理：对框严格内部（不含边框本身）的每个品红(6) 像素，将其替换为该像素关于框内部区域左右中轴的镜像对应位置的颜色。若镜像对应位置也是品红(6)，则继续尝试上下中轴的镜像位置；若仍为品红(6)，则尝试 180° 旋转对应位置。生成约束保证至少有一个对应位置可提供有效颜色。
3. 破损框处理：将框严格内部的所有品红(6) 像素替换为灰(5)。
4. 框本身的像素、框内非品红像素、框外所有像素均保持不变。

**关键洞察**：框边界的一个像素缺口（拓扑属性）将整个内部区域从"对称修复"切换为"灰化惩罚"。求解者必须仔细检查每个框的完整性——密封与破损的视觉差异可能仅在一个像素——才能决定对掩码像素施加哪种变换。需要对比多个示例才能归纳出密封/破损导致不同行为的规则。

## 新题 2：重力沉降催生隐含十字

**组合逻辑**：[重力下落/gravity_drop + 碰撞停止/collision_stop](已有) → [隐含十字检测/implied_plus + 四向对齐/four_way_aligned](创新：检测对象从预置变为重力涌现) → [重涂色/recolor](已有，标记涌现中心)

**来源原语**：gravity_drop、collision_stop、obstacle（参考题 #1 28a6681f）；implied_plus、four_way_aligned、missing_center、micro_bar（参考题 #19 9f5f939b）；recolor（参考题 #4 c8f0f002）

**依赖链**：重力沉降决定微型条的最终位置→最终位置决定哪些条恰好构成十字排列→十字中心才被标记。删掉重力则条的位置不变、十字不涌现；删掉十字检测则不知标记哪里；删掉标记则无输出差异。

散落的微型条经重力沉降后在障碍物上方自发排列出十字图案，标记每个十字的空心中心。

**输入结构**：
- 约 15x18 的网格，黑(0) 背景。
- 绿(3) 的二像素条（水平或垂直），每个条是一个独立的 4-连通分量，共 10~16 个，散布在网格的中上部区域，彼此不相邻。
- 灰(5) 的水平线段作为静态障碍物（ledge），分布在不同高度，长度各异（3~8 像素），共 3~5 条。网格底边也视为障碍物。
- 输入中不存在黄(4) 像素。
- 生成约束：重力沉降后至少存在一个有效的隐含十字排列；输入状态下不存在任何有效的隐含十字排列。

**规则**：
1. 对所有绿(3) 二像素条施加重力：每个条作为刚体整体向下移动，直至其最低像素接触灰(5) 障碍物像素的正上方、另一个已沉降条的正上方、或网格底边。水平条在两个像素中较低者触底时停止；垂直条在底部像素触底时停止。按从下到上的顺序处理（最低的条先沉降）。
2. 所有条沉降完毕后，扫描每个背景像素 (r, c)：若在 (r, c) 的上方距离 2~3 处存在一个垂直绿条、下方距离 2~3 处存在一个垂直绿条、左方距离 2~3 处存在一个水平绿条、右方距离 2~3 处存在一个水平绿条，且 (r, c) 的四个直接相邻格（上下左右各 1 格）均为背景色，则 (r, c) 是一个隐含十字中心。
3. 将每个隐含十字中心像素重涂为黄(4)。
4. 其余所有像素（含沉降后的绿条、灰障碍物）保持不变。

**关键洞察**：十字图案在输入中不存在——它们是重力沉降的涌现结果。障碍物的位置和形状间接控制了哪些条会"碰巧"排列成十字。求解者必须先完整模拟重力过程，才能在沉降后的状态中检测十字。需要对比多个示例才能理解十字的精确距离约束（2~3 格偏移而非相邻）。

## 新题 3：交叠层序编码精灵体旋转

**组合逻辑**：[层序推断/infer_layer_order + 正交交叉/orthogonal_crossing + 交叉可见色为上层/visible_at_crossing_is_top](已有) → [同色匹配/same_color_matching](创新：从色层匹配变为条-精灵体匹配) → [旋转/rotate](创新：旋转角度由层序位置编码而非像素计数)→ [擦除/erase + 裁剪/crop](已有)

**来源原语**：infer_layer_order、orthogonal_crossing、visible_at_crossing_is_top、full_span_bar（参考题 #15 1a2e2828）；rotate、same_color_matching（参考题 #14 6ffbe589）；crop（参考题 #7 be94b721）；erase（参考题 #3 7d7772cc）

**依赖链**：交叉处可见颜色→推断条的层序→层序位置编码旋转角→匹配同色精灵体→旋转精灵体。删掉层序推断则无法确定旋转角；删掉同色匹配则不知哪个精灵体转多少度；删掉旋转则精灵体不变。

全幅条的交叠层序编码了同色小精灵体的旋转角度；条在输出中消失，仅留旋转后的精灵体。

**输入结构**：
- 约 20x20 的网格，黑(0) 背景。
- 3~5 个全幅条：部分水平（跨越网格全宽，高度 1 像素），部分垂直（跨越网格全高，宽度 1 像素）。每个条使用不同的颜色（从红(2)、绿(3)、蓝(1)、橙(7)、栗(9) 中选取）。至少有一对水平条和一对垂直条（保证存在交叉）。
- 垂直条与水平条在交叉处重叠，交叉像素显示层序中较高的条的颜色。
- 每个条的颜色对应一个小型单色精灵体（4-连通、3~7 像素的不规则形状），放置在网格四角附近不与任何条重叠的区域。精灵体的边界框不超过 4x4。
- 生成约束：所有交叉的可见色信息足以唯一确定完整的从底到顶层序（无平局）。条的数量 N 满足 3 <= N <= 5。

**规则**：
1. 识别每个全幅条：水平条的可见像素边界框跨越网格全宽，垂直条的可见像素边界框跨越网格全高。即使部分像素被上层条覆盖，条仍在对应行/列全长存在。
2. 在每个水平条与垂直条的交叉位置，观察该像素颜色——该颜色对应的条在层序中高于另一条。收集所有交叉处的约束，推断出唯一的从底（层 0）到顶（层 N-1）的完整层序。
3. 对每个精灵体，找到与其同色的条，获取该条的层位置 L（从底部 0 开始计数）。
4. 将该精灵体在其边界框内顺时针旋转 (L mod 4) x 90 度。L=0 不旋转，L=1 旋转 90 度，L=2 旋转 180 度，L=3 旋转 270 度。旋转以精灵体边界框中心为原点；若边界框非正方形，旋转后边界框的宽高互换。
5. 将所有条从网格中擦除（恢复为背景色）。将每个旋转后的精灵体放回其原始边界框的左上角位置（旋转可能改变边界框尺寸）。
6. 输出仅包含旋转后的精灵体，其余为黑(0) 背景。

**关键洞察**：全幅条是"编程指令"——它们的视觉重叠关系编码了旋转参数，然后从输出中消失。求解者必须先从交叉处的颜色可见性反向推断出完整层序（一个偏序重建问题），再将层序转化为旋转角度。条本身不是变换的对象，而是变换的规则载体。需要多个示例才能归纳出"层位置 mod 4 = 旋转次数"的关系。

## 新题 4：颜色比较门控双向重力

**组合逻辑**：[对齐比较/aligned_comparison + 颜色匹配定去向/color_match_dest](创新：比较结果不决定左右移位而是决定重力方向) + [重力下落/gravity_drop + 碰撞停止/collision_stop](创新：正向与反向重力共存于同一区域) + [重涂色/recolor](创新：仅对反向重力对象施加)

**来源原语**：aligned_comparison、color_match_dest、separator_line、reference_pixel、source_pixel（参考题 #3 7d7772cc）；gravity_drop、collision_stop（参考题 #1 28a6681f）；recolor（参考题 #4 c8f0f002）；erase（参考题 #3 7d7772cc）

**依赖链**：参考行提供颜色基准→每个底区像素与其列对应的参考像素比较→匹配者向下坠落/不匹配者向上浮升→浮升者额外变灰。删掉参考比较则无法区分方向；删掉重力则像素不移动；删掉变灰则浮升者与坠落者不可区分。

参考行像素按列定义颜色门；匹配的底区像素向下沉、不匹配的向上浮并变灰，在同一区域内形成颜色分层。

**输入结构**：
- 约 14x14 的网格，黑(0) 背景。
- 一条水平灰(5) 分隔线将网格分为上区（约 3 行）和下区（约 10 行）。分隔线跨越网格全宽，位于第 3~4 行。
- 上区紧邻分隔线的一行包含参考像素：每列至多一个非背景色像素（从红(2)、蓝(1)、绿(3)、黄(4)、橙(7) 中选取），部分列无参考像素（为背景色）。
- 下区散布着 8~14 个单像素前景色点，分布在不同的行和列。这些像素的颜色均取自参考行中出现的颜色。
- 无参考像素的列中不包含下区像素（生成约束）。
- 输入中不存在灰(5) 像素（除分隔线本身外）。

**规则**：
1. 对下区每个前景色像素 P 在列 c，找到上区参考行在列 c 的参考像素 R。
2. 若 P 的颜色与 R 相同（匹配）：P 向下移动（标准重力），逐行下移直至其正下方为网格底边或另一个已到位的像素。P 保持原色不变。
3. 若 P 的颜色与 R 不同（不匹配）：P 向上移动（反向重力），逐行上移直至其正上方为分隔线或另一个已到位的像素。P 被重涂为灰(5)。
4. 处理顺序：先处理所有向下移动的像素（按行从下到上），再处理所有向上移动的像素（按行从上到下）。同列同方向的像素按先到先停的顺序堆叠。
5. 分隔线和参考像素保持不变。原位置被擦除为背景色。

**关键洞察**：同一种颜色的像素在不同列可能有相反的命运——在一列中匹配参考而下沉保色，在另一列中不匹配参考而上浮变灰。颜色的"含义"是列依赖的，由该列的参考像素决定。求解者需要多个示例才能归纳出"匹配→下沉保色，不匹配→上浮变灰"这一双向规则以及处理顺序。

## 新题 5：压缩骨架中筛选对称异常值

**组合逻辑**：[压缩/downscale + 网格采样/grid_sampling + 每分区缩为单像素](已有) → [对称/symmetry + 对称图案选取/symmetric_selected + 异常值选择/outlier_selection](创新：对称检测作用于压缩表示而非原始网格) → [裁剪/crop](已有，但裁剪对象回到原始尺度)

**来源原语**：downscale、rectangular_partition、grid_sampling、each_partition_reduced_to_one_pixel（参考题 #6 90c28cc7）；symmetry、symmetric_selected、outlier_selection、color_mask（参考题 #16 d56f2372）；crop（参考题 #7 be94b721）

**依赖链**：每个精灵体先压缩为骨架→在骨架表示上做左右镜像对称检测→唯一对称的骨架指向其原始精灵体→裁剪原始精灵体输出。删掉压缩则无法在不等分区上判断对称性；删掉对称检测则无选择标准；删掉裁剪则无最终输出。

多个分区精灵体各自压缩为像素骨架后，唯一具有左右对称性的骨架对应的原始精灵体被裁剪输出。

**输入结构**：
- 约 22x22 的网格，黑(0) 背景。
- 3~4 个不重叠的多色分区精灵体，每个由若干单色矩形分区拼成（如参考题 #6 的棋盘式结构），分区尺寸不均匀（有的 2x3，有的 1x2 等）。每个精灵体整体约 6x6 到 10x10 像素。
- 每个精灵体内部使用 3~5 种非背景色，各分区颜色不同。
- 在原始尺度下，由于分区大小不等，无法直接判断颜色图案是否对称。
- 生成约束：恰好一个精灵体的压缩骨架（每个分区缩为一个像素后的网格）在颜色上具有左右镜像对称性；其余精灵体的骨架不具有此性质。

**规则**：
1. 对每个分区精灵体，检测其内部的矩形分区结构：找到所有 4-连通单色分量，收集各分量左上角的行列坐标，排序后得到分区行列网格。
2. 对每个精灵体，在分区行列网格的每个交叉点采样颜色（取该分区左上角像素的颜色），生成压缩骨架——一个小网格（约 3x3 到 5x5）。
3. 对每个压缩骨架，检查其是否等于自身的左右镜像（逐像素比较翻转后的骨架与原骨架）。
4. 选出唯一满足左右镜像对称的骨架，找到其对应的原始精灵体。
5. 裁剪该原始精灵体至其边界框，以黑(0) 填充非精灵体像素，作为输出。

**关键洞察**：对称性判断必须在压缩域中进行，而非原始域。原始精灵体因分区尺寸不等而外观不对称——一个分区 2x3、其镜像分区 1x2——但压缩到每分区一像素后对称性才显现。压缩操作不是预处理，而是"揭示隐藏属性"的必要变换。

## 新题 6：镜像恢复补丁按标记排序拼接

**组合逻辑**：[镜像/mirror + 反射恢复遮挡/reflection_recovers + 遮挡块/occluder](已有) → [按位置排序标记/sort_markers_by_position + 标记共行/markers_share_row_or_column](创新：排序不作用于模板复制品而是作用于恢复补丁) → [排序拼接/sort_and_concatenate](创新：拼接内容来自镜像恢复而非模板重涂)

**来源原语**：mirror、reflection_recovers、occluder、occluded_region、mirror_symmetry（参考题 #10 dc0a314f）；sort_and_concatenate、markers_share_row_or_column、single_pixel_marker、按位置排序标记（参考题 #12 12997ef3）；crop（参考题 #7 be94b721）

**依赖链**：每个遮挡块通过镜像恢复得到补丁→标记像素的颜色与遮挡块匹配→标记的空间顺序决定补丁拼接顺序→拼接输出。删掉镜像恢复则无补丁内容；删掉标记排序则补丁顺序不确定；两者缺一则输出无法确定。

多个遮挡块隐藏了对称图案的不同区域，通过镜像分别恢复后，按同色标记像素的排列顺序横向拼接输出。

**输入结构**：
- 约 20x20 的网格，黑(0) 背景。
- 网格中央有一个较大的多色图案（约 14x14），该图案关于其垂直中轴具有左右镜像对称性。
- 图案上有 2~4 个实心正方形遮挡块（边长 3~4），每个遮挡块使用不同的颜色（如红(2)、蓝(1)、橙(7) 等），这些颜色不出现在图案的其他位置。遮挡块覆盖了图案的部分区域。
- 所有遮挡块位于图案垂直中轴的同一侧（比如全在左半侧），以保证它们的镜像区域不被其他遮挡块覆盖。
- 在网格最下方一行（图案外），有与遮挡块同色的单像素标记，从左到右排列在同一行上。标记颜色与遮挡块颜色一一对应，但排列顺序与遮挡块在图案中的空间位置顺序不同。

**规则**：
1. 对每个遮挡块，定位其边界框区域，将该区域关于图案的垂直中轴做左右镜像映射，得到镜像区域。
2. 从镜像区域中读取图案内容（镜像区域不含遮挡块，因此内容完好），然后将读到的内容做左右翻转，得到该遮挡块下方被隐藏的恢复补丁。每个补丁的尺寸等于遮挡块的边长。
3. 读取最下方一行的标记像素，按从左到右排序。
4. 按标记排序顺序，依次取出与该标记同色的遮挡块对应的恢复补丁，将补丁水平拼接（从左到右无间隔相邻）。
5. 输出拼接后的条带。补丁高度相同（均为遮挡块边长），宽度也相同（正方形遮挡块），因此拼接后是一个矩形。

**关键洞察**：镜像恢复提供补丁的"内容"，标记排序提供补丁的"顺序"——两个独立信息源共同决定输出。求解者必须同时理解对称恢复的几何机制和标记排序的位置规则。标记顺序与遮挡块在图案中的空间位置无关（需多个示例确认这一点），迫使求解者识别标记行而非猜测位置映射。

## 新题 7：孔洞计数编码放大倍率

**组合逻辑**：[包围/enclosure + 含孔洞者选中/object_with_hole_selected](创新：从选出单一对象变为计数所有含孔对象) → [像素放大/pixel_upscale + 框内尺寸决定缩放/frame_size_sets_scale](创新：缩放因子不由框尺寸决定，而由孔洞计数决定) + [面积比较/area_comparison + 选取最大面积对象/largest_area_selected](创新：从选取输出对象变为选取画布)

**来源原语**：enclosure、hollow_rectangle、object_with_hole_selected、enclosed_region（参考题 #9 b9b7f026）；pixel_upscale、frame_size_sets_scale、pattern（参考题 #11 6b9890af）；area_comparison、largest_area_selected（参考题 #7 be94b721）；crop（参考题 #7 be94b721）

**依赖链**：孔洞检测→计数含孔对象数 K→K 作为放大倍率→最大孔洞的框提供画布→将放大后的图案填入画布。删掉孔洞检测则不知倍率也不知画布；删掉放大则无法填充；删掉面积选择则不知填入哪个框。

统计所有含有封闭背景孔洞的矩形框数量作为放大倍率，将小图案放大后填入孔洞面积最大的框内。

**输入结构**：
- 约 18x18 的网格，黑(0) 背景。
- 4~6 个不重叠的单色矩形对象，每个使用不同颜色（如红(2)、蓝(1)、绿(3)、黄(4)、橙(7) 等）。部分矩形是空心的（一像素宽边框围成矩形环，内部为背景色），部分是实心的（全部填充）。
- 空心矩形的内部尺寸各不相同（如 2x2、3x3、4x4 等）。
- 网格中另有一个小型多色图案精灵体（2x2 或 3x3），放置在远离所有矩形对象的位置，使用与矩形对象不同的颜色组合。
- 生成约束：空心矩形的数量 K 满足 2 <= K <= 4。内部面积最大的空心矩形的内部尺寸恰好等于图案精灵体尺寸乘以 K（即放大后的图案恰好能填满该框内部）。

**规则**：
1. 识别所有矩形对象。对每个矩形对象，检测其是否为空心矩形——即在其边界框范围内，边框像素形成完整的矩形环，且环内部存在仅由背景色组成的 4-连通区域，该区域不接触边界框的边缘。
2. 计数空心矩形的数量，记为 K。
3. 在所有空心矩形中，选出内部背景区域面积（像素数）最大的一个，作为"画布框"。
4. 将小型图案精灵体按倍率 K 进行像素放大：精灵体中每个像素扩展为 KxK 的同色块。
5. 将放大后的图案放入画布框的内部，左上角对齐画布框内部区域的左上角。
6. 输出仅包含画布框及其内部放大后的图案，裁剪到画布框的边界框范围。其余所有对象（其他矩形、原始小图案）不出现在输出中。

**关键洞察**：空心矩形同时扮演两个角色——它们的数量编码了放大倍率，其中面积最大者提供了放大后图案的容器。实心矩形是干扰项：它们外观与空心矩形相似（尤其当尺寸较小时），但既不参与计数也不参与画布选择。需要多个示例才能区分"孔洞计数 = 倍率"这一非显然编码关系。

## 新题 8：十字射线重写分区骨架

**组合逻辑**：[射线延伸/ray_extend + 交叉点重置背景/intersect_reset_bg + 实心方块/solid_block](已有) → [压缩/downscale + 网格采样/grid_sampling + 矩形分区/rectangular_partition](创新：压缩的对象是被射线修改后的分区精灵体，而非原始精灵体)

**来源原语**：ray_extend、intersect_reset_bg、solid_block、cross_pattern、row_col_align（参考题 #13 e9bb6954）；downscale、rectangular_partition、grid_sampling、each_partition_reduced_to_one_pixel（参考题 #6 90c28cc7）

**依赖链**：3x3 方块发射十字射线→射线穿过分区精灵体并覆写路径上的像素→压缩精灵体时采样被覆写后的像素→输出骨架与原始骨架不同。删掉射线则精灵体未被修改、骨架不变；删掉压缩则无法得到输出格式。射线的精确位置决定了哪些分区的采样点被覆盖，构成紧耦合。

外部方块发射的十字射线穿入分区精灵体重写了部分像素，再将被修改后的精灵体压缩为分区骨架输出。

**输入结构**：
- 约 20x20 的网格，黑(0) 背景。
- 网格中央有一个多色分区精灵体（约 10x10 像素），由 3~5 行 x 3~5 列的矩形分区拼成，分区尺寸不均（有 2x2、2x3、3x2 等），每个分区为单一颜色（从蓝(1)、绿(3)、黄(4)、橙(7)、栗(9) 中选取）。
- 精灵体外部有 2~3 个实心 3x3 方块，每个使用不同颜色（从红(2)、品红(6)、灰(5) 中选取），放置在精灵体的上方或左方区域。方块之间不相邻。
- 生成约束：每个方块的中心行或中心列至少有一个穿过分区精灵体内某个分区的左上角像素（即采样点）。不同方块的十字射线在精灵体外部可能交叉。

**规则**：
1. 对每个 3x3 方块，从其中心像素向四个方向（上下左右）延伸射线至网格边缘，使用该方块的颜色绘制整行和整列（如参考题 #13）。
2. 若两个不同颜色方块的射线在某像素交叉（一个的中心行射线与另一个的中心列射线交叉），该交叉像素重置为背景色(0)。
3. 射线绘制完毕后，检测分区精灵体的分区结构：在精灵体的边界框范围内，找到所有 4-连通单色分量的左上角坐标（注意分区颜色可能已被射线部分覆写，分区结构按原始边界确定——即使用未被射线覆写前的分区边界位置）。
4. 在每个分区的左上角像素处采样当前颜色（可能是原始分区色，也可能被射线覆写为方块色，也可能被交叉重置为背景色）。
5. 将采样结果排列为压缩骨架网格输出。

**关键洞察**：射线覆写操作和压缩采样操作在空间上通过"分区左上角像素"这个关键位置紧密耦合。方块的精确位置决定了其中心行/列是否恰好穿过某个分区的采样点——差一个像素就可能不覆盖任何采样点。交叉重置规则进一步增加了不确定性：两条射线的交叉点如果恰好落在采样点上，该分区会变成背景色而非射线色。需要多个示例才能明确采样的精确机制（取左上角而非中心或其他位置）。

## 新题 9：折线路径交织围合区域着色

**组合逻辑**：[连线/draw_line + 折线路径/folded_path + 中心偏移选角/center_offset_selects_corner](已有) → [包围/enclosure + 封闭区域/enclosed_region](创新：封闭区域由多条折线路径交互涌现而非预先存在) → [重涂色/recolor](已有，作用于涌现区域)

**来源原语**：draw_line、folded_path、center_offset_selects_corner、marker_pixel、column_alignment（参考题 #5 7ec998c9）；enclosure、enclosed_region（参考题 #9 b9b7f026）；recolor（参考题 #4 c8f0f002）

**依赖链**：每个标记像素决定一条折线路径→多条路径在网格中交织形成封闭区域→封闭区域被检测并着色。删掉路径绘制则无交织、无封闭；删掉封闭检测则无法识别区域；删掉着色则无输出差异。路径的涌现交互决定哪些区域被围合，这是非线性的——增删一条路径可能创造或消灭多个封闭区域。

多个标记像素各自生成一条折线路径，路径交织后围合出的封闭背景区域被着色标记。

**输入结构**：
- 约 14x14 的网格，灰(5) 背景。
- 3~5 个非背景色单像素标记，放置在不同列。每个标记使用相同颜色绿(3)。标记不在网格的第一行或最后一行（它们在中间某行）。
- 输入中不存在蓝(1) 或红(2) 像素。
- 生成约束：按照下述规则绘制所有折线路径后，至少存在一个由蓝(1) 像素完全围合的灰(5) 背景区域（4-连通灰色分量不接触网格边界）。

**规则**：
1. 对每个绿(3) 标记像素（位于列 c），绘制蓝(1) 折线路径：
   - 将标记所在列 c 的所有像素（从顶行到底行）涂为蓝(1)（标记像素本身也被覆盖）。
   - 判断列 c 是否为网格的唯一正中列（即网格宽度为奇数且 c 恰为中间列索引）：
     - 若是正中列：从该列顶端向右上角方向画水平线至右边界，从该列底端向左下角方向画水平线至左边界。
     - 若非正中列：从该列顶端向左上角方向画水平线至左边界，从该列底端向右下角方向画水平线至右边界。
   - 这里"画水平线至边界"指：从列 c 的顶行端点 (0, c) 沿第 0 行向目标边界方向逐像素涂蓝(1)；从列 c 的底行端点 (H-1, c) 沿第 H-1 行向目标边界方向逐像素涂蓝(1)。
2. 所有路径共享同一颜色蓝(1)；重叠处仍为蓝(1)。
3. 路径绘制完毕后，检测所有灰(5) 的 4-连通分量。若某个分量不接触网格的任何边界行或边界列（即完全被蓝(1) 像素和/或网格边界以外的空间围合），则该分量是一个封闭区域。
4. 将每个封闭区域的所有像素重涂为红(2)。
5. 其余灰(5) 像素（未被围合的背景）和蓝(1) 路径像素保持不变。

**关键洞察**：每条折线路径本身不围合任何区域（它只是一条从上到下贯穿网格的折线）。封闭区域是多条路径交互的涌现结果——两条相邻路径的垂直段加上它们各自在顶行和底行的水平段可能恰好围成一个矩形区域。标记的列位置和中心/非中心属性共同决定路径的形状，从而控制哪些区域被围合。增加一个标记可能同时创造和消灭封闭区域，使问题具有非单调的组合性质。
