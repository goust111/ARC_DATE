## 新题 1：标记块对角映射重涂远端形状

**组合逻辑**：[对角映射](已有) + [重涂色](创新：作用于远端形状的包围盒象限，而非标记块周围区域) + [包围盒](创新：作为象限划分的框架，而非裁剪边界)

**来源原语**：对角映射/diagonal_mapping（93b581b8）、重涂色/recolor（e7dd8335）、包围盒/bounding_box（e7dd8335）、标记块/marker_block（93b581b8）、半区/half_region（e7dd8335）

**依赖链**：标记块提供四色映射表 → 前景形状的包围盒定义四象限 → 对角映射决定每个象限的目标颜色 → 重涂色依据象限归属逐像素执行。移除标记块则无颜色来源；移除包围盒则无象限划分；移除对角映射则颜色分配规则不明。

将一个不规则前景形状按其包围盒象限分区，每个象限的前景像素被重涂为 2x2 标记块中对角位置单元格的颜色。

**输入结构**：约 12x12 的网格，背景为黑(0)。网格中有一个灰(5)的 4-连通不规则前景形状（15~25 像素，非矩形、非对称），其包围盒的高和宽均为偶数（生成约束）。网格中另有一个 2x2 的标记块，位于前景形状包围盒的外部（不与包围盒重叠或相邻），四个单元格分别为四种不同的非黑非灰颜色（如左上红(2)、右上蓝(1)、左下绿(3)、右下黄(4)；具体颜色因示例而异）。不同示例中前景形状的具体外形不同，标记块的位置和四色排列也不同。

**规则**：
1. 计算灰色前景形状的最小包围盒（最小行、最大行、最小列、最大列）。
2. 以包围盒行范围的中点和列范围的中点为分界，将包围盒划分为四个象限：左上、右上、左下、右下。中点行归入上半部分，中点列归入左半部分。
3. 对 2x2 标记块执行对角映射：标记块左上单元格的颜色 → 映射到包围盒的右下象限；标记块右上 → 左下；标记块左下 → 右上；标记块右下 → 左上。
4. 对每个位于包围盒内的灰色前景像素，根据其所属象限重涂为对应映射颜色。
5. 背景像素、标记块本身均保持不变。

**关键洞察**：标记块中每个单元格的颜色不是直接分配给同侧象限，而是对角交叉映射到包围盒的对角象限——这一隐蔽规则需要对比多个示例（标记块颜色排列不同时）才能归纳出来。

## 新题 2：地形轮廓截断标记相位条纹并高亮极值列

**组合逻辑**：[条纹图案 + 列对齐](已有) + [地形轮廓](创新：作为条纹的逐列截断边界) + [列高度极值](创新：在条纹列中选取极值列做特殊重涂) + [擦除](创新：排除标记列)

**来源原语**：条纹图案/stripe_pattern（834ec97d）、列对齐/col_alignment（834ec97d）、标记像素/marker_pixel（834ec97d）、地形轮廓/terrain_contour（e45ef808）、列高度极值/column_height_extreme（e45ef808）、擦除/erase（d255d7a7）、重涂色/recolor（e7dd8335）

**依赖链**：标记像素的列位置定义条纹相位 → 地形轮廓逐列提供截断高度 → 条纹仅绘制到地形表面上方 → 在所有条纹列中取地形最高列做特殊重涂。排除标记的条件与条纹相位、地形极值三方耦合：排除标记改变条纹列集合，进而可能改变极值列。

在地形上方按标记像素定义的列相位绘制竖条纹，条纹被地形表面截断；地形最高的条纹列被重涂为标记色。

**输入结构**：约 15x15 网格，背景黑(0)。底部 5~8 行为地形区：每列从网格底部向上有一段连续的绿(3)像素填充，各列高度不同（范围 2~8），形成参差的轮廓线。地形上方的区域中恰好有一个红(2)标记像素和一个黄(4)排除像素，二者不在同一列、不在同一行，均位于地形表面以上。其余空间为黑(0)背景。不同示例中地形高度分布、标记与排除像素的位置均不同。生成约束：在满足条纹相位且不被排除的列中，地形最高列唯一。

**规则**：
1. 标记像素所在列的奇偶性定义条纹相位：所有与标记列具有相同奇偶性的列为候选条纹列。
2. 将黄(4)排除像素所在列从候选集中移除，无论其奇偶性是否匹配。
3. 对每个剩余的候选条纹列，从第 0 行向下绘制黄(4)竖条纹，直到遇到该列第一个绿(3)地形像素所在行的前一行为止（不覆盖地形）。
4. 在所有绘制了条纹的列中，找到地形高度最大的列（即地形最高峰所在的条纹列），将该列的条纹颜色全部改为红(2)（标记像素的颜色）。
5. 擦除原始红(2)标记像素和黄(4)排除像素（置为黑(0)）。
6. 地形像素保持不变。

**关键洞察**：黄色排除像素不是条纹的来源，而是条纹的禁区——它阻止自己所在列被绘制条纹。这一「排除」语义与「相位」语义相反，需多个示例（排除列在不同位置时）才能辨别。

## 新题 3：原型匹配确定路由端点并标记穿越槽位

**组合逻辑**：[模式匹配/原型](已有) + [连线/正交路径](创新：端点不是固定标记像素，而是匹配发现的槽位中心) + [夹间区域](创新：不再按行列直线取夹间，而是沿正交路由路径穿越的非匹配槽位) + [经由中间点路由](创新：路由不经由显式路标，而是经由分隔线网络)

**来源原语**：模式匹配/pattern_match（d94c3b52）、原型/prototype（d94c3b52）、符号槽位/symbol_slot（d94c3b52）、连线/draw_line（0e671a1a）、正交路径/orthogonal_path（0e671a1a）、先横后纵路由/horizontal_then_vertical（0e671a1a）、夹间区域/between_region（d94c3b52）、匹配槽位重涂/match_slot_recolor（d94c3b52）

**依赖链**：原型匹配 → 确定路由端点集合 → 读取排列顺序 → 逐对端点做正交路由 → 路径穿越的非匹配槽位被标记为橙色。匹配结果同时决定端点和「不被标记」的保护身份，二者角色不可分离。

在符号槽位表中找到所有匹配原型的槽位，按阅读序依次用正交灰线连接相邻匹配槽位的中心；路径穿越的非匹配槽位符号被涂为橙色。

**输入结构**：约 15x19 网格，结构为用 1 像素宽灰(5)分隔线（含边框）分成的 3 行 4 列共 12 个 3x3 符号槽位表。每个槽位背景为黑(0)，可空或包含一个单色符号掩码（连通像素图案，3~7 像素，可占据 3x3 区域内的任意位置）。恰好一个槽位的符号颜色为青(8)，其 3x3 掩码为原型。其余非空槽位符号颜色各异（红(2)、蓝(1)、绿(3)、黄(4)等），其中部分槽位的掩码形状与原型相同（颜色不同）。不同示例中原型位置、匹配槽位数量与位置、非匹配槽位的填充均不同。生成约束：匹配槽位至少 3 个（含原型自身）；在阅读序下相邻匹配槽位的正交路径不会经过另一个匹配槽位的中心点。

**规则**：
1. 对每个非空槽位，提取其 3x3 掩码形状（仅看哪些像素被占据，忽略颜色）。与原型槽位的掩码形状比较。形状完全一致的槽位记为「匹配」（含原型自身）。
2. 将所有匹配槽位的符号像素重涂为青(8)。
3. 将匹配槽位按阅读序排列（先按槽位所在行从上到下，同行按列从左到右）。
4. 对阅读序中每一对相邻匹配槽位 (A, B)，从 A 的 3x3 区域中心像素到 B 的中心像素绘制正交路径：先沿水平方向移动到 B 中心所在列，再沿垂直方向移动到 B 中心所在行。路径像素涂为灰(5)。路径覆盖到分隔线时与分隔线颜色相同，不产生视觉变化。
5. 路径穿越某个非匹配槽位的 3x3 区域时，该槽位中所有原有的符号像素被重涂为橙(7)。路径穿越空槽位则不产生额外效果。
6. 匹配槽位即使被路径穿越也保持青(8)不变。
7. 所有分隔线和空槽位的黑色背景保持不变。

**关键洞察**：路由的端点不是预设的标记像素，而是通过形状匹配动态发现的；同时匹配身份赋予了「免疫穿越标记」的保护，使得匹配判断同时承载端点发现和穿越规则两个功能。

## 新题 4：活跃边识别驱动轨迹计数转矩形条纹

**组合逻辑**：[标记指示活跃边](已有) + [计数/像素数转为条纹](创新：计数对象从灰条形段变为散布的轨迹像素，且计数范围由矩形的行列域决定) + [擦除](已有) + [相邻接触](创新：不再是条段触矩形，而是轨迹像素按所属行列域分配到最近矩形)

**来源原语**：边缘带/edge_strip（d255d7a7）、标记指示活跃边/marker_active_edge（d255d7a7）、含轨迹色行列移动/trail_color_move（d255d7a7）、计数/counting（d93c6891）、像素数转为条纹/pixels_to_stripes（d93c6891）、矩形容器/rect_container（d93c6891）、擦除/erase（d255d7a7、d93c6891）

**依赖链**：栗色标记识别活跃边 → 活跃边方向决定「行域」还是「列域」分配 → 轨迹像素按域分配到各矩形 → 计数 → 条纹方向由活跃边决定 → 从矩形靠近活跃边的一侧开始填充。活跃边同时控制三个下游参数（分配轴、条纹方向、起始侧），构成单源多分支依赖。

识别活跃边方向，按行或列域将散布的轨迹像素分配给各矩形，再将各矩形的轨迹计数转为从靠近活跃边一侧起始的填充条纹。

**输入结构**：约 14x14 网格，背景黑(0)。网格的上、下、左、右四条边中恰好一条有 2 像素厚的边缘带，带中像素为橙(7)和栗(9)混合，其中栗(9)像素数量少于橙(7)且至少有 1 个。网格内部有 2~3 个实心橙(7)矩形（4-连通，每个至少 3x4），矩形彼此不相邻、不重叠。在矩形之外的黑色区域中散布着蓝(1)轨迹像素（4~15 个），各轨迹像素互不相邻。不同示例中活跃边位置（上/下/左/右）、矩形的数量和大小、轨迹像素的分布均不同。生成约束：每个矩形的行域（或列域，取决于活跃边方向）内至少有 1 个轨迹像素；轨迹计数不超过矩形在条纹方向上的尺寸。

**规则**：
1. 找到栗(9)像素，确定它们最靠近的网格边缘即为活跃边（上/下/左/右）。
2. 确定分配轴：若活跃边为左或右，则按「行域」分配——每个轨迹像素归属其所在行被哪个矩形的行范围覆盖的矩形；若活跃边为上或下，则按「列域」分配——每个轨迹像素归属其所在列被哪个矩形的列范围覆盖的矩形。若某轨迹像素不在任何矩形的对应域内，则忽略该像素。
3. 对每个矩形，统计分配到它的轨迹像素数量 N。
4. 在该矩形内部，从靠近活跃边的一侧开始，填充 N 条完整的行（若活跃边为上/下）或列（若活跃边为左/右），颜色为蓝(1)。若活跃边在上侧，则从矩形顶行向下填充；若在下侧，从底行向上；若在左侧，从最左列向右；若在右侧，从最右列向左。
5. 矩形中未被条纹覆盖的部分保持橙(7)。
6. 将所有原始蓝(1)轨迹像素擦除为黑(0)。
7. 将整条边缘带擦除为黑(0)，但栗(9)像素保留在原位。

**关键洞察**：活跃边不仅指示条纹填充方向，还决定轨迹像素如何被分配到各矩形——行域与列域的选择由同一个活跃边参数控制。这个「一参数多用途」的结构需要对比不同活跃边方向的示例才能完整归纳。

## 新题 5：周期瓦片提取后逐矩形局部位置重涂

**组合逻辑**：[裁剪/周期](已有) + [局部位置分类/角边内部分别涂色](创新：分类对象不是输入中的已知矩形，而是从提取瓦片中发现的前景矩形) + [最小周期含翻转](已有)

**来源原语**：裁剪/crop（2dee498d）、周期/period（2dee498d）、最小周期含翻转/smallest_period_flipped（2dee498d）、重涂色/recolor（b6afb2da）、局部位置分类/local_position_classification（b6afb2da）、角边内部分别涂色/corner_border_interior_recolored（b6afb2da）、矩形/rectangle（b6afb2da）

**依赖链**：检测最小周期含翻转 → 提取原始瓦片 → 在瓦片中识别前景矩形 → 对每个矩形做角/边/内部分类 → 按分类重涂。错误的周期检测会导致矩形在瓦片边界被截断，从而产生错误的角/边判断，整条链因此不可跳步。

从周期性重复（可含翻转副本）的网格中提取最小瓦片，然后将瓦片中每个前景矩形按角、边、内部分别重涂为蓝、黄、红。

**输入结构**：约 12x18 或 18x12 网格。网格由 2~4 个等宽（或等高）的矩形块沿一个轴拼接而成，每块是同一瓦片的原版或水平/垂直翻转版。每个瓦片内部：背景为黑(0)，前景为灰(5)，前景由 1~3 个互不相邻的实心矩形组成（每个矩形至少 2x3 或 3x2）。不同示例中瓦片内矩形的数量、位置、大小均不同，拼接方向（水平或垂直）和翻转方式也不同。生成约束：存在唯一最小周期。

**规则**：
1. 尝试从最小候选宽度（或高度）开始，检测沿拼接轴的周期。对每个候选周期，检查各块是否为第一块的原版、水平翻转或垂直翻转。取满足条件的最小周期。
2. 提取第一个块作为原始瓦片。
3. 在提取的瓦片中，识别所有灰(5)的 4-连通实心矩形区域。
4. 对每个矩形，将其四个角像素重涂为蓝(1)；将除角以外的边界像素重涂为黄(4)；将严格内部像素重涂为红(2)。对于只有 2 行或 2 列的矩形，所有像素都是角或边，无内部像素。

**关键洞察**：如果周期检测错误（比如取了实际周期的两倍），瓦片边界会切穿矩形，切出的局部形状不再是完整矩形，角/边/内部分类结果会完全改变。因此周期检测与位置分类通过矩形完整性紧密耦合。

1. 确定四个控制像素中最靠上的那个所在行为框顶行，最靠下的为框底行，最靠左的所在列为框左列，最靠右的为框右列。

6. 框外部背景保持黑(0)。

**关键洞察**：枢轴不在中心时，四个区域大小不对称，但填色规则是固定的「上区→顶色、下区→底色、左区→左色、右区→右色」。求解者需先理解框的构建，再理解对角线的分区逻辑，最后从不同枢轴位置的示例中归纳出区域-框边的对应关系。

1. 找到所有行中蓝色段右端所在列的最小值（最左的右端位置），记为目标列 C。

1. 忽略两个面板中所有栗(9)像素（将其视为背景）。
2. 左面板中剩余的非黑像素构成精灵模板。记录精灵中每种颜色每个像素的相对位置（相对于精灵任一固定参考点，如包围盒左上角）。

**关键洞察**：标记像素的颜色不是随意的，它指向精灵内部的一个特定像素位置来定义对齐锚点。这意味着同一个精灵在不同标记处会以不同的偏移量印章，而不是简单地以精灵中心对齐。这一锚定规则需要对比多个示例才能归纳出来。

## 新题 9：地形列深度编码精灵旋转角度

**组合逻辑**：[旋转/旋转关系](创新：旋转角度不由臂方向决定，而由地形几何属性隐式编码) + [地形轮廓/列高度极值](创新：地形高度不再用于标色，而是作为旋转参数的编码载体) + [擦除](已有)

**来源原语**：旋转/rotate（a416fc5b）、旋转关系/rotation_relation（a416fc5b）、地形轮廓/terrain_contour（e45ef808）、列高度极值/column_height_extreme（e45ef808）、擦除/erase（a416fc5b）、精灵体/sprite（e6721834）

**依赖链**：地形高度按列读取 → 对精灵中心列取高度 → 高度 mod 4 编码旋转角 → 精灵按该角旋转。地形是静态编码器，精灵是被编码控制的受体。去掉地形则旋转角不可知；去掉精灵则无旋转对象；去掉参考精灵则旋转后的目标形态不可知。

地形轮廓各列的高度隐式编码了上方各精灵的旋转角度：精灵中心列的地形高度对 4 取余决定旋转 0/90/180/270 度。

**规则**：
1. 识别左上角橙(7)精灵为参考方向（0 度旋转）。
2. 对每个蓝(1)精灵，计算其包围盒的中心列（左列 + 右列的整数均值）。
3. 查找该中心列的地形高度 H（即从网格底部连续绿色像素的数量）。
4. 计算 H mod 4：0 → 不旋转（0 度），1 → 顺时针 90 度，2 → 180 度，3 → 顺时针 270 度。
5. 将参考精灵按步骤 4 的角度顺时针旋转，以蓝色精灵的包围盒中心为放置中心，用蓝(1)绘制旋转后的形状。若旋转结果与原始蓝色精灵一致，则保持不变（验证性质）；否则替换。
6. 擦除左上角的橙(7)参考精灵（置为黑(0)）。
7. 地形和背景保持不变。

**关键洞察**：地形看似只是背景装饰，实际上它的列高度通过模运算编码了每个精灵的旋转角度。这个 mod 4 映射规则在单个示例中不可见（因为一个高度只对应一个旋转角度），必须对比多个精灵的地形高度和旋转状态才能归纳。

**规则**：

3. 取数量最多的瓦片类型，记其数量为 W、颜色为 C_max；取数量最少的类型，记其数量为 H。

6. 从矩形右下角像素出发，向左上方画一条 45 度上升的黄(4)对角线，同样限制在矩形内部。
7. 两条对角线若有交点，交点为黄(4)（后画覆盖先画）。
8. 下半区矩形外的区域保持黑(0)。

**关键洞察**：上半区的几何分解（瓦片覆盖）产生的信息不是留在原地（仅着色），而是被抽象为数量后传递到下半区构建一个全新的几何对象。求解者需要意识到上半区和下半区之间存在跨区信息传递，而不是独立的两道题。
