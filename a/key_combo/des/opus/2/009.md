## 新题 1：锚块压缩后按控制像素接缝拼接

**组合逻辑**：[压缩/compact_to_anchor](已有) → [裁剪/crop](已有) → [拼接/stitch + 接缝对齐/seam_alignment](创新：接缝对齐键由锚块内嵌控制像素提供，而非独立精灵体上的灰色标记)

**来源原语**：压缩(compress, f28a3cbb)、锚块(anchor_block, f28a3cbb)、射线像素(ray_pixel, f28a3cbb)、裁剪(crop, 234bbc79/7468f01a)、拼接(concatenate, 234bbc79)、控制像素(control_pixel, f5c89df1/234bbc79)、接缝对齐(seam_alignment, 234bbc79)

**依赖链**：压缩改变每组射线像素的空间分布，从而决定裁剪后每个色组的边界框形状；控制像素嵌入锚块后使锚块出现一个异色"孔洞"，该孔洞位置既影响压缩时射线像素的最终排列（射线像素紧缩到锚块表面，而孔洞处不算锚块表面），又作为拼接阶段的垂直对齐键。三个环节通过控制像素的双重角色紧密耦合。

将多组散布的同色射线像素紧缩到各自的锚块旁，裁剪每个色组，然后按锚块内嵌的控制像素对齐拼接成紧凑输出。

**输入结构**：约 20x20 的黑(0)背景网格。其中有 3~4 组前景色（如蓝(1)、红(2)、绿(3)、黄(4)），每组包含：一个 3x3 实心锚块（该色），锚块的 9 个像素中恰好有 1 个被替换为灰(5)控制像素（各组灰像素在锚块内的行位置各不相同）；若干同色像素散布在锚块的同行、同列或对角线射线方向上，与锚块之间隔有空白间距。不同色组的锚块互不相邻（边界框至少间隔 2 列），射线像素不跨越其他色组的锚块。生成约束：每组射线像素数量 2~5 个；各组锚块从左到右依次排列，保证裁剪后边界框不重叠。

**规则**：
1. 对每个色组，将该色的所有非锚块前景像素沿其射线方向（行/列/对角线）朝锚块紧缩，使它们紧贴锚块的外表面连续排列，不留间隙。灰(5)控制像素所在的位置视为锚块的一部分，不影响射线方向判断，但射线像素不可叠放到灰像素上（灰像素位置被占据）。
2. 紧缩完成后，为每个色组计算包含其锚块及所有已紧缩射线像素的最小矩形边界框，裁剪出该区域。裁剪区域内灰(5)像素保留。
3. 按锚块在原输入中的列位置从左到右排序。将裁剪块从左到右无间隙拼接，垂直方向上对齐各裁剪块中灰(5)控制像素所在的行，使所有灰像素落在输出的同一行。
4. 拼接完成后，将输出中所有灰(5)像素替换为其所在色组的前景色。
5. 输出网格的宽度等于所有裁剪块宽度之和，高度等于对齐后所需的最大范围。超出裁剪块范围的区域填充黑(0)背景。

**关键洞察**：灰控制像素同时扮演两个角色——它是锚块中的结构孔洞（影响压缩后射线像素的几何分布和边界框形状），又是拼接阶段的垂直对齐键。仅看单个示例无法确定对齐规则是依据灰像素行还是锚块中心行，必须对比多个示例（灰像素在锚块内不同行位置时对齐结果不同）才能归纳。

## 新题 2：对角平铺后按图例过滤涌现连通分量

**组合逻辑**：[平铺/tile + 对角线偏移复制/diagonal_offset_copy](已有) → [连通分量检测/connected_component](创新：检测对象不是原始输入而是平铺产生的涌现结构) → [图例过滤擦除/legend_as_filter + contains_all_target_colors](已有，但过滤对象是涌现分量)

**来源原语**：平铺(tile, d13f3404)、对角线偏移复制(diagonal_offset_copy, d13f3404)、画布加倍(canvas_doubling, d13f3404)、前景图案(foreground_motif, d13f3404)、擦除(erase, d59b0160)、连通分量(connected_component, d59b0160/a8d7556c)、图例区域(legend_region, d59b0160)、包含全部目标色(contains_all_target_colors, d59b0160)

**依赖链**：平铺将前景图案沿对角线复制到加倍画布上，不同副本的前景像素可能相邻融合，形成原始图案中不存在的大型多色连通分量（涌现结构）。图例中的目标色集合用来过滤这些涌现分量——只有同时包含所有目标色的分量才被擦除。涌现分量的色彩组成取决于平铺时哪些副本的哪些像素恰好相邻，这是一个非平凡的几何推理步骤。

对角平铺一个多色图案到加倍画布上，然后擦除所有同时包含图例指定全部目标色的涌现连通分量。

**输入结构**：约 8x8 的黑(0)背景网格（平铺后输出为 16x16）。左上角有一个 2x3 的图例区域：外圈 1 像素宽的橙(7)边框（底边和右边各一行/列），内部 1~2 个像素为目标色（如蓝(1)和绿(3)）。网格中其余位置有一个 4~6 像素的多色前景图案（4-连通，包含 2~3 种非背景非橙色的前景色，如蓝(1)、红(2)、绿(3)），图案内部各色像素相邻排列。图例区域与前景图案不相邻。生成约束：图案形状需保证在对角平铺后至少产生一个包含全部目标色的涌现连通分量，且至少产生一个不包含全部目标色的分量（以形成对比）。

**规则**：
1. 创建宽度和高度均为原输入两倍的输出画布，填充黑(0)背景。
2. 将图例区域原样复制到输出画布的左上角对应位置。
3. 对原输入中每个前景图案像素（非背景、非图例），将其颜色绘制到输出画布的位置 (r+k, c+k)，k = 0, 1, 2, ... 直到超出画布范围。不同偏移量的副本可能重叠；重叠时所有副本颜色一致（生成约束保证）。
4. 在输出画布上（排除图例区域），识别所有 4-连通的非背景连通分量。
5. 读取图例区域内部的目标色集合。擦除（填充黑(0)背景）所有同时包含全部目标色的连通分量。不包含全部目标色的分量保留不变。
6. 图例区域本身保留在输出中不被擦除。

**关键洞察**：哪些连通分量会被擦除并非在原始输入中可直接判断——必须先完成对角平铺，观察哪些不同色的像素因偏移重叠而变为 4-连通邻居，形成包含多种颜色的涌现分量，然后才能判断其是否满足图例过滤条件。单个示例可能不足以区分"擦除包含任一目标色的分量"和"擦除包含全部目标色的分量"，需对比多示例归纳。

## 新题 3：补全残缺矩形框以揭示格子结构再跨框推断槽位色

**组合逻辑**：[对称补全/frame_completion](创新：不是补全对称场景，而是补全残缺矩形框的缺失边段) → [格子槽位识别/lattice_slot](已有) → [跨框架对应推断/cross_frame_match + 填充/fill](已有)

**来源原语**：对称补全(frame_completion, 256b0a75)、矩形框(rectangular_frame, 256b0a75)、填充(fill, 2e65ae53/256b0a75)、推断(infer, 2e65ae53)、格子框架(lattice_frame, 2e65ae53)、格子槽位(lattice_slot, 2e65ae53)、跨框架对应(cross_frame_match, 2e65ae53)、槽位位置决定颜色(slot_position_color, 2e65ae53)

**依赖链**：每个矩形框有意缺失部分边段像素，导致内部格子线结构不完整、槽位边界模糊。必须先补全矩形框的缺失边段（根据已有边段推断完整矩形轮廓），才能看清内部分割线从而确定各槽位的逻辑行列位置。确定槽位位置后，跨多个框架收集已填色槽位的信息，推断每个逻辑位置的正确颜色，最后填充所有空槽。

补全多个残缺矩形框的缺失边段，识别其内部格子槽位结构，跨框架推断每个槽位位置的颜色并统一填充。

**输入结构**：约 25x25 的黑(0)背景网格。灰(5)线条构成 3~4 个矩形框架，每个框架的外边框为单像素宽灰线，内部有灰线将框架分割为 2x3 或 3x2 的矩形槽位网格（所有框架的槽位行列数相同）。每个框架有 1~3 段外边框像素被擦除（替换为背景色），使框架看起来不完整——缺失段长度 1~3 像素，但每条边至少保留过半像素，足以推断完整矩形位置。各框架内部分割线完整，未被擦除。部分槽位内部填有非背景非灰的前景色（如蓝(1)、红(2)、绿(3)、黄(4)），每个逻辑位置在所有框架中至多出现一种非背景色（不同框架的同一逻辑位置不会填入不同色）。所有框架合并后，每个逻辑位置至少在一个框架中有已填色槽位。生成约束：框架之间不相邻（边界框间距至少 2 像素）；每个框架至少有一个空槽位和一个已填槽位。

**规则**：
1. 对每个残缺矩形框，根据已有灰(5)边框像素推断完整矩形的四条边位置（利用已有像素的行列坐标确定矩形的上、下、左、右边界），补全所有缺失的边框像素为灰(5)。
2. 在每个已补全的框架内部，根据灰(5)内部分割线确定槽位网格结构——每个槽位是被灰线包围的矩形内部区域。为每个槽位标定逻辑行列坐标（左上槽位为 (0,0)）。
3. 遍历所有框架的所有槽位，收集每个逻辑坐标对应的已填颜色。
4. 将推断出的颜色填入所有框架中对应逻辑坐标的空槽位（用该颜色填满槽位内部所有像素）。
5. 保留所有灰(5)线条（边框和分割线）和背景色不变。

**关键洞察**：必须先完成框架补全，才能正确识别槽位边界——如果缺失的边段恰好与某条内部分割线相邻，不补全就无法判断那里是槽位边界还是两个槽位的合并区域。仅看单个框架无法推断所有槽位颜色（每个框架故意留空部分槽位），必须跨框架比较才能收集完整颜色映射。

## 新题 4：方向精灵体射线遇分隔线反射

**组合逻辑**：[质心偏移定向/centroid_bias_dir → 射线延伸/ray_extend](已有) → [分隔线反射](创新：分隔线不再决定"朝向/背离"，而是作为反射面改变射线方向) → [间隔涂色/dotted_ray_to_edge](已有)

**来源原语**：射线延伸(ray_extend, 13f06aa5)、绘制(drawing, 13f06aa5)、方向精灵体(directional_sprite, 13f06aa5)、标记像素(marker_pixel, 13f06aa5)、网格边界(grid_edge, 13f06aa5)、质心偏移定向(centroid_bias_dir, 13f06aa5)、间隔涂色至边界(dotted_ray_to_edge, 13f06aa5)、分隔线(divider_line, 8d510a79)、朝向与背离(toward_and_away, 8d510a79 -- 创新为反射语义)

**依赖链**：精灵体的体像素分布编码射线初始方向（质心偏移的反方向）；射线从标记像素出发沿该方向逐像素前进，遇到灰色分隔线时发生正交反射（水平射线变垂直、垂直射线变水平）继续前进。射线在反射前后都按间隔涂色规则（每隔一像素涂一次）绘制，且间隔计数跨反射点连续不重置。方向解码、反射行为、间隔规则三者紧密耦合。

从方向精灵体的标记像素发射间隔射线，射线遇灰色分隔线时正交反射，继续间隔涂色直至网格边界。

**输入结构**：约 18x18 的黑(0)背景网格。一条灰(5)直线贯穿网格（水平或垂直，占满整行/列），将网格分为两个区域。两侧各有 1~3 个方向精灵体，每个由 5~7 个橙(7)体像素（8-连通）和 1 个嵌入其中的单色标记像素组成。标记像素颜色各不相同（可为蓝(1)、红(2)、绿(3)、黄(4)中的一种）。每个精灵体的体像素在标记像素的一侧聚集（编码方向信息）：体像素质心相对于标记像素的偏移方向即为射线的反方向。所有精灵体的射线初始方向为上、下、左、右四者之一（不含对角线）。生成约束：所有精灵体形状属于同一个七像素体模板的 0/90/180/270 度旋转；每个精灵体的射线路径在反射前后不会穿过另一个精灵体。

**规则**：
1. 对每个精灵体，计算其橙(7)体像素的质心相对于标记像素的方向。射线方向为该方向的正反方向（即射线朝远离体像素质心的方向发射）。射线方向限定为上、下、左、右之一。
2. 从标记像素出发，沿射线方向逐像素前进。使用间隔涂色规则：从标记像素算起第 1 步涂色、第 2 步跳过、第 3 步涂色...（奇数步涂色，偶数步跳过），涂标记像素自身的颜色。
3. 当射线的下一个像素位于灰(5)分隔线上时，射线不涂该灰色像素，而是发生正交反射：若当前为水平方向则变为垂直方向（向离灰线较远的网格边界方向），若当前为垂直方向则变为水平方向（向离灰线较远的网格边界方向）。步数计数不重置，继续间隔涂色。
4. 反射后的射线继续前进直到到达网格边界（最后一个网格内像素涂色后停止）。
5. 如果射线方向直接朝向网格边界而不经过分隔线，则不发生反射，射线直接涂到边界为止。
6. 所有射线的涂色完成后，保留原始精灵体像素（橙色体和标记像素）和灰(5)分隔线不变。若两条射线的涂色像素重叠，后处理的射线（按标记像素到分隔线的距离从近到远排序）覆盖先处理的。

**关键洞察**：分隔线在参考题中是"吸引/排斥"轴，在本题中变为反射面——射线的最终轨迹是一个折线而非直线。间隔涂色的步数跨反射点连续计数，意味着反射前后的涂色位置不能独立计算，必须从起点一路追踪。仅看单个示例中某个精灵体的射线难以区分"反射后间隔重置"和"间隔连续"，需对比多个精灵体或多个示例才能归纳。

## 新题 5：检测单色边框提取中心色构建循环填充调色板

**组合逻辑**：[提取/extract + 忽略干扰项/ignore_distractors](已有) → [顺序排列/sequential_order](创新：提取结果的空间位置决定调色板顺序) → [循环填充/cyclic_fill + 标记高度决定长度/marker_height_run_len](已有)

**来源原语**：提取(extract, d9fac9be)、单色边框(monochrome_frame, d9fac9be)、中心像素(center_pixel, d9fac9be)、边框包围中心(frame_encloses_center, d9fac9be)、忽略干扰项(ignore_distractors, d9fac9be)、循环填充(cyclic_fill, e7b06bea)、擦除(erase, e7b06bea)、长度标记段(length_marker, e7b06bea)、顺序排列(sequential_order, e7b06bea)、标记高度决定长度(marker_height_run_len, e7b06bea)

**依赖链**：网格上散布着多个 3x3 单色边框（合法框）和同色干扰像素。必须正确识别合法框（8 个边框像素为同一前景色、中心为另一前景色），忽略干扰像素。合法框的中心色按框的空间位置从左到右排序，构成调色板序列。灰色标记段的高度给出每色运行长度。最终在指定列循环填充该调色板。错误识别任何一个框都会导致调色板顺序或内容错误，进而使循环填充结果完全不同。

从散布的 3x3 单色边框中提取中心色序列作为调色板，按灰标记段高度循环填入目标列。

**输入结构**：约 15x18 的黑(0)背景网格。网格上有 3~5 个有效的 3x3 单色边框：每个框的 8 个边界像素为同一种前景色（如蓝(1)），中心像素为另一种前景色（各框中心色可不同，如红(2)、绿(3)、黄(4)等）。同时网格上散布着若干与边框色相同的干扰像素（单独存在，不构成完整 3x3 框）。网格最右 1 列为全背景色的空列（目标列）。网格左上角有一段顶部对齐的垂直灰(5)标记段（高度 2~4 像素，宽度 1 像素）。生成约束：有效框之间不重叠、不相邻（边界框间距至少 1 像素）；干扰像素不与任何有效框的边界像素 4-连通相邻；所有有效框使用同一种边框色；各框中心色互不相同。

**规则**：
1. 扫描网格，找出所有满足以下条件的 3x3 窗口：8 个边界像素为同一非背景前景色，中心像素为不同于边框色和背景色的前景色。这些是有效单色边框。
2. 不满足上述条件的同色前景像素视为干扰项，忽略。
3. 将有效框按其左上角列坐标从小到大排序（列坐标相同时按行坐标从小到大），提取排序后的中心色序列作为调色板 P = [c1, c2, ..., cn]。
4. 读取灰(5)标记段的高度 H（标记段占据的连续行数）。
5. 在最右空列中，从第 0 行开始，循环填充调色板：先填 H 行 c1，再填 H 行 c2，...，填完 cn 后回到 c1，循环直至填满该列所有行。
6. 擦除所有有效框（边框像素和中心像素均替换为背景色）及所有干扰像素。保留灰(5)标记段和填充后的目标列。

**关键洞察**：干扰像素与有效框使用相同的边框色，唯一区分方式是检查完整 3x3 框结构。调色板的颜色内容和顺序完全由有效框的中心色及其空间位置决定——漏检或误检任何一个框都会导致调色板不同，循环填充结果随之改变。需对比多示例才能确认排序规则是按列优先还是按行优先。

## 新题 6：旋转多色模板使其宽高比匹配封闭区域后缩放填入

**组合逻辑**：[旋转/rotate](已有) → [像素放大/pixel_scale_up + 模板掩码形状对应/template_mask_correspondence](创新：对应关系不是模板与单个掩码之间，而是同一模板与多个不同尺寸封闭区域之间，每个区域可能需要不同旋转) → [填充/fill](已有)

**来源原语**：旋转(rotate, 103eff5b)、像素放大(pixel_scale_up, 103eff5b)、重涂色(recolor, 103eff5b)、多色模板(multicolor_template, 103eff5b)、模板掩码形状对应(template_mask_correspondence, 103eff5b)、旋转缩放后匹配(match_after_rotate_scale, 103eff5b)、封闭区域(enclosed_region, a8d7556c)、矩形框(rectangular_frame, 256b0a75)、填充(fill, 256b0a75/2e65ae53)

**依赖链**：每个矩形框围出的封闭区域有不同的宽高比。同一个小型多色模板需要被旋转到与目标区域宽高比匹配的朝向，然后整数倍放大以精确铺满该区域。不同区域可能需要不同的旋转角度。模板的旋转角度由目标区域的几何形状决定，缩放倍数由区域尺寸决定——两者都是从区域属性推导而非直接给出。

将同一个小型多色模板按不同旋转角度和缩放倍数填入多个封闭矩形区域，旋转角度由区域宽高比决定。

**输入结构**：约 20x20 的黑(0)背景网格。一个 2x3 或 3x2 的多色模板位于网格某角落，由 2~3 种非背景非灰色的前景色组成（如蓝(1)、红(2)、绿(3)），每个像素有独立颜色。网格中其余区域有 2~4 个灰(5)单像素线条绘制的矩形框（仅边框，内部为背景色）。各矩形框内部区域的宽高比为模板宽高比的整数倍旋转变体：若模板为 2x3，则某些区域为 4x6（0 度放大 2 倍）、某些为 6x4（90 度放大 2 倍）、某些为 6x9（0 度放大 3 倍）等。生成约束：每个封闭区域的内部尺寸恰好是模板（某个旋转态）的整数倍；矩形框之间不重叠不相邻；模板区域不与任何矩形框重叠。

**规则**：
1. 识别输入中的小型多色模板（唯一不被灰(5)框包围的非背景色区域）及其像素排列。
2. 识别所有灰(5)矩形框，计算每个框内部封闭区域的高度 H 和宽度 W。
3. 对每个封闭区域，测试模板的四种旋转（0/90/180/270 度），找到使旋转后模板的高宽比等于 H:W 的某个整数缩放的旋转角度。若模板为 h x w，则寻找旋转角度 theta 使得 H / h_theta = W / w_theta = 整数 S（其中 h_theta x w_theta 是旋转后模板尺寸）。
4. 将模板旋转 theta 度，然后将每个模板像素放大为 S x S 的色块，得到 H x W 的彩色图案，填入该封闭区域。
5. 若两个旋转角度均满足条件（如方形区域 + 方形模板），选择 0 度和 180 度中使模板左上像素颜色编号较小的那个旋转。
6. 保留灰(5)矩形框线条和原始模板不变。

**关键洞察**：模板只有一份，但不同封闭区域需要不同的旋转角度和缩放倍数。解题者必须从区域尺寸反推旋转和缩放参数，而非正向匹配。仅看单个区域的填充结果无法区分 0 度和 180 度旋转（都产生相同尺寸），必须对比模板原始方向与填充结果的颜色位置才能确认旋转规则。

## 新题 7：三连块缺角方向编码印章偏移目标

**组合逻辑**：[缺角定向/missing_corner + 对角偏移/diagonal_offset](创新：缺角不再决定"重涂色副本"的方向，而是决定印章复制的放置偏移方向) → [印章覆盖/stamp_overlay + 相对坐标复制/relative_coord_copy](已有，但锚点概念由三连块几何替代)

**依赖链**：源精灵体的形状通过锚点像素定义相对坐标系（什么被复制）。三连块的缺角位置编码一个对角方向（往哪里复制）。将精灵体印章到三连块位置沿缺角方向偏移一格的位置。精灵体形状、三连块位置、缺角方向三者缺一不可。不同三连块的缺角朝向不同，导致同一精灵体被印到不同对角方向的偏移位置。

读取源精灵体的形状，按每个三连块缺角编码的对角方向将精灵体印章到偏移位置。

**输入结构**：约 18x18 的黑(0)背景网格。一个蓝(1)多像素源精灵体（5~8 个蓝色像素，8-连通，形状不规则），其中恰好有 1 个像素为红(2)锚点像素（与蓝色像素 4-连通相邻）。网格中另有 3~5 个绿(3)三连块（每个三连块占据 2x2 区域中的 3 个像素，缺少一个角）。各三连块的缺角位置可为左上、右上、左下、右下四种之一。生成约束：三连块之间互不相邻（边界框间距至少 3 像素）；源精灵体不与任何三连块相邻；每个三连块按其缺角方向偏移一格后放置精灵体时，精灵体不超出网格边界且不与其他印章重叠。

**规则**：
1. 识别蓝(1)源精灵体及其红(2)锚点像素。记录每个蓝色像素相对于锚点的坐标偏移 {(dr_i, dc_i)}。
2. 对每个绿(3)三连块，确定其 2x2 边界框中缺失的角的位置（左上/右上/左下/右下），该位置编码一个对角方向向量：左上→(-1,-1)、右上→(-1,+1)、左下→(+1,-1)、右下→(+1,+1)。
3. 计算每个三连块的中心位置 C（三个像素坐标的行平均和列平均，向下取整）。
4. 印章目标位置为 T = C + 对角方向向量。以 T 为锚点，在 (T.r + dr_i, T.c + dc_i) 处绘制蓝(1)像素，复制源精灵体的形状。
5. 按三连块的中心位置从上到下（行坐标升序）、同行从左到右（列坐标升序）的顺序依次印章。后印章的覆盖先印章的重叠像素。
6. 印章完成后，擦除所有原始三连块（绿色像素替换为背景色）和原始源精灵体（蓝色和红色像素替换为背景色），仅保留印章结果。

**关键洞察**：三连块在本题中不产生"重涂色副本"（参考题 1e5d6875 的用法），而是作为方向编码器和位置标记器——其缺角的几何位置编码了印章的偏移方向。解题者必须同时理解精灵体的坐标系（由锚点定义）和三连块的方向编码（由缺角定义），才能确定每个印章的最终位置。仅看单个三连块的结果无法区分"朝缺角方向偏移"和"朝缺角对面方向偏移"，需对比多个不同朝向的三连块归纳。

将分隔列分开的多个色彩面板按底部边框序列编码的深度顺序透明叠加。

**输入结构**：约 15x20 的黑(0)背景网格。红(2)垂直分隔列将网格上方区域（顶部到倒数第 4 行）分为 3 个等宽面板。左面板的图案用蓝(1)绘制，中面板用绿(3)绘制，右面板用黄(4)绘制（各面板内黑(0)像素视为透明）。网格底部 3 行区域（在分隔列下方）排列着 3 个 3x3 单色边框：每个边框的 8 个边界像素为灰(5)，中心像素颜色为蓝(1)、绿(3)或黄(4)中的一种（三个边框的中心色互不相同，恰好覆盖三种面板色）。三个边框从左到右排列，互不相邻。生成约束：三个面板尺寸相同；各面板图案有部分像素在相同的相对位置（即叠加后会遮挡）；底部边框区域与面板区域被至少 1 行空行分隔。

**规则**：

6. 输出仅包含叠加后的画布，不包含分隔列、底部边框区域。

**关键洞察**：在参考题 cf98881b 中，面板的左中右位置直接决定深度顺序（右=底、中=中、左=顶），本题打破了这一直接对应——深度顺序被编码在底部的 3x3 边框序列中，面板的空间位置不携带深度信息。仅看单个示例中面板的左中右位置和叠加结果，可能误以为位置决定深度；必须对比多个示例（底部边框顺序不同导致相同面板位置产生不同叠加结果）才能排除位置假说，发现真正的编码机制。
