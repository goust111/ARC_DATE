## 新题 1：嵌套深度柱状图

**组合逻辑**：[containment_tree](创新：原用于规范化布局，此处作为深度数值编码器) → [counting](创新：计数嵌套层级而非面积) → [sort + fill/histogram_bar](已有排序与柱状生成，但排序键从面积改为拓扑深度)

**来源原语**：containment_tree、nested_frame、enclosed_region（2d0172a1）；counting、sort、histogram_bar、area_filtering（a3325580）；fill（7c8af763）

**依赖链**：不检测嵌套关系就无法算出深度；不算深度就无法确定柱高；不排序就无法确定柱的左右位置。三环缺一不可。

将多层嵌套的彩色矩形框按包含深度转换为等高柱状图——框的几何形状全部丢弃，只有拓扑深度和颜色存活。

**输入结构**：黑(0)背景，约15x15网格。3~5个不同颜色的空心矩形框（边框宽1像素），颜色取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)等，每色最多一个框。部分框嵌套在其他框的内部（边界框严格包含在外层框的内腔中），嵌套深度1~3层。最外层框之间互不相交。生成约束：任意两个框的边界像素不共享格子；同层级框的左上角列坐标互不相同。

**规则**：
1. 识别每个空心矩形框为一个4-连通单色前景连通分量。
2. 构建包含树：若框B的边界框严格位于框A的内腔（A边界框向内缩1像素后的区域）内，则A是B的父节点。
3. 计算每个框的嵌套深度：无父节点的框深度为1；父节点深度为d的框深度为d+1。
4. 将所有框按深度升序排列；深度相同时，按框边界框左上角的列坐标升序排列。
5. 输出网格：高度 = 最大深度值，宽度 = 框的数量。第i列（0起始，从左到右）对应排序后第i个框，该列从底行向上填充该框的颜色，填充高度等于该框的深度值，其余单元格为黑(0)。

**关键洞察**：嵌套的空间几何在输出中完全消失——包含关系被解码为一个数字（深度），而这个数字成了柱状图的高度。不理解"包含 = 深度编码"就无法从嵌套矩形推出柱状图。

## 新题 2：配对多米诺定向射线

**组合逻辑**：[four_neighbor_pairing](已有) → [erase](已有，擦除配对中的红像素) → [ray_extend](创新：射线方向由多米诺的红绿朝向编码，而非来自固定角点)

**来源原语**：bicolor_domino、four_neighbor_pairing、pair_recolor_erase、ignore_distractors（d90796e8）；ray_extend（85fa5666）；draw_line、boundary_pos（6cdd2623）

**依赖链**：不完成配对就无法区分真正的多米诺与干扰像素，也无法确定射线方向；射线方向完全由多米诺的红绿朝向决定；不发射射线就缺少主要输出结构。

找到所有红-绿正交配对，擦除红侧像素，并从该位置沿多米诺指向的方向发射一条青色射线。

**输入结构**：黑(0)背景，约12x15网格。散布红(2)和绿(3)像素，其中部分红-绿像素形成4-连通的两格多米诺（水平或垂直方向，一红一绿紧邻），其余红/绿像素为孤立干扰项。另有若干灰(5)像素作为障碍物。生成约束：每个多米诺的射线路径方向上至少有3格空间到达障碍物或边界；不同多米诺的射线路径互不重叠。

**规则**：
1. 识别所有4-连通的红(2)-绿(3)两格多米诺（恰好两个像素，一红一绿，共享一条边）。
2. 对每个多米诺，将红(2)像素位置设为黑(0)（擦除）。
3. 确定射线方向：从红像素位置出发，方向为"从绿像素指向红像素"的延长方向（即远离绿像素的方向）。例如：绿在左红在右则射线向右；绿在上红在下则射线向下。
4. 从红像素的原始位置开始（该位置本身也涂色），沿射线方向逐格涂青(8)，直到下一格为非黑像素（灰障碍、其他已有像素、网格边界外）时停止，终点格不涂色。
5. 未配对的红/绿像素和灰(5)像素保持不变。
6. 多米诺中的绿(3)像素保持绿色不变。

**关键洞察**：多米诺不仅仅是一个配对标记——它的红绿朝向编码了一个方向向量。不识别配对就不知道哪些像素是射线源，不分析朝向就不知道射线该往哪射。

## 新题 3：图例串扩展决定腔室填色

**组合逻辑**：[expand/legend_anchored_alignment](已有) → [fill/adjacent_majority_vote](创新：投票对象不是原始标记像素，而是扩展后被腔室墙壁裁剪的图例碎片)

**来源原语**：edge_legend_string、isolated_marker、color_position_matching、legend_anchored_alignment（5af49b42）；connected_chamber、separator_wall、fill、adjacent_majority_vote（7c8af763）

**依赖链**：不扩展图例就无法在腔室内产生足够的颜色分布来做多数投票；不检测腔室边界就不知道在哪裁剪扩展串；裁剪方式直接决定多数颜色，所以标记在腔室中的水平位置实质性影响最终结果。

在墙壁分隔的腔室内，将孤立标记像素扩展为图例串的片段（被墙壁裁剪），然后按各腔室中占多数的颜色填充整个腔室。

**输入结构**：约15x15网格。灰(5)墙壁将网格分隔为4~6个不规则腔室（4-连通的黑(0)区域）。网格最顶行（第0行）是一条水平图例串，由4~5个不同前景色像素排成一行（如蓝(1)、红(2)、绿(3)、黄(4)、橙(7)，从左至右各占一格），图例串紧贴左侧排列，其余顶行格为黑(0)。图例行下方由灰(5)墙分隔的各腔室内，每个腔室含1~2个孤立单像素标记，其颜色取自图例中某个位置的颜色。生成约束：每个腔室的水平跨度至少为3格；每个腔室中若有2个标记则颜色不同。

**规则**：
1. 识别灰(5)墙壁下方各4-连通的黑(0)腔室。
2. 对每个腔室中的每个孤立标记像素：在图例串中定位其颜色所在的列索引k（0起始）。将完整图例串水平复制到该标记所在行，平移使图例的第k格落在标记像素的列位置上。仅保留落在该腔室内部（不包含墙壁格和腔室外格子）的部分，其余裁剪丢弃。
3. 同一腔室内多个标记的扩展若有像素重叠：按标记像素行号升序处理，行号相同按列号升序，后处理的覆盖先处理的。
4. 扩展完成后，对每个腔室统计所有非黑(0)像素的颜色频率。将该腔室的全部黑(0)像素填充为出现次数最多的颜色；若存在平局，选择在图例串中位置靠左的颜色。
5. 灰(5)墙壁和图例行保持不变。扩展产生的非黑像素在填充后被填充色覆盖（即腔室内最终全为同一颜色）。

**关键洞察**：标记像素的扩展不是最终输出——它只是向腔室投射了颜色"选票"。腔室宽度和标记的水平位置共同决定哪些图例颜色被裁剪掉、哪些留下，从而改变多数投票的结果。相同颜色的标记在不同宽度的腔室中可能导致不同的填充色。

## 新题 4：控制边编码的相位平铺

**组合逻辑**：[crop/control_row + control_column](已有) → [tile](已有) → [cyclic_roll](创新：不是对整体payload做一次滚动，而是每个tile副本根据其网格坐标与控制量的乘积做独立相位偏移)

**来源原语**：control_row、control_column、dual_axis_offset、marker_is_shift、cyclic_roll、crop（79cce52d）；tile、seed_mask、repetition（58c02a16、a416b8f3）

**依赖链**：不读控制行/列就不知道偏移量；不平铺就没有重复结构可做偏移；偏移量与tile位置的乘积关系必须从多个示例对比才能归纳出来——单个示例可能误以为是简单平铺或全局滚动。

读取控制边上的标记位置作为偏移参数，将种子图案平铺后按每个副本的网格位置做独立循环位移，生成对角波浪式的周期图案。

**输入结构**：约13x13网格。顶行为控制行，由灰(5)像素填满，其中恰好1格为蓝(1)标记像素。最左列为控制列，由灰(5)像素填满，其中恰好1格为红(2)标记像素。顶行与最左列交叉处（第0行第0列）为灰(5)。控制行下方、控制列右侧为payload区域。payload区域的左上角有一个SxS（S=3或4）的种子图案，由黄(4)像素和黑(0)背景组成。种子图案右侧和下方的payload区域均为黑(0)。生成约束：payload区域的宽和高均为S的整数倍。

**规则**：
1. 读取蓝(1)标记在控制行中的零基列偏移H（从控制列右侧第一格算起，即标记列号减1）。
2. 读取红(2)标记在控制列中的零基行偏移V（从控制行下方第一格算起，即标记行号减1）。
3. 将种子图案（SxS）平铺填满整个payload区域（宽度方向重复 payload宽/S 次，高度方向重复 payload高/S 次）。
4. 对位于tile网格坐标(tx, ty)（0起始，tx为列方向索引，ty为行方向索引）的每个tile副本，将其内容循环右移 (tx * H) mod S 列，循环下移 (ty * V) mod S 行。
5. 输出仅包含payload区域（移除控制行和控制列）。

**关键洞察**：控制标记不是对整个画面做一次平移——它们参数化了一个逐副本的相位偏移公式。相同的种子图案在不同的控制标记位置下会生成完全不同的全局花纹。只看一个示例可能误以为是简单平铺或全局滚动，需要对比多个示例才能发现逐位置累加偏移的规律。

## 新题 5：螺旋路径选择印章目标

**组合逻辑**：[spiral_draw/turn_on_collision](创新：螺旋不绘制像素，而是在单元格阵列上追踪路径选择目标) → [stamp_overlay/seed_motif](已有印章机制，但目标由螺旋路径而非奇偶性决定)

**来源原语**：spiral_draw、turn_on_collision、path（28e73c20）；stamp_overlay、seed_motif、cell_array、open_cell、same_parity_receive_copy、separator_line（92e50de0）

**依赖链**：不画分隔线就没有单元格阵列供螺旋行走；不追踪螺旋就不知道哪些单元格被选中；不印章就缺少主要输出内容。螺旋的路径形状取决于阵列尺寸，阵列尺寸取决于分隔线位置。

在分隔线划分的单元格阵列上，从标记单元格出发追踪顺时针螺旋路径，将种子图案印入螺旋经过的每个单元格。

**输入结构**：约17x17网格。蓝(1)分隔线沿整行或整列贯穿，将网格划分为规则的单元格阵列（如5x5阵列，每个单元格内部约3x3格）。阵列中恰好一个单元格内含有一个红(2)小图案（2~4像素的4-连通形状，占据单元格内部的部分格子）。另有一个单元格内含有单个黄(4)标记像素（标记所在单元格无红色图案）。生成约束：阵列至少3x3；红图案和黄标记不在同一单元格；黄标记位于阵列的某个角落单元格。

**规则**：
1. 由蓝(1)分隔线切分出单元格阵列，记录每个单元格的行列索引和内部区域范围。
2. 找到含红(2)图案的单元格，记录图案各像素相对该单元格左上角内部起点的偏移量。
3. 从含黄(4)标记的单元格开始，在单元格阵列上追踪顺时针螺旋：初始方向向右。每步尝试前进到同方向的下一个单元格；若下一单元格已被访问或超出阵列范围，则顺时针转向90度再尝试。若转向后仍无法前进（四个方向均不可行），螺旋终止。
4. 将红图案（使用记录的偏移量）印入螺旋访问的每个单元格（包括起始单元格），颜色为红(2)。若某单元格因位于阵列边缘而内部区域不完整，超出范围的像素不绘制。
5. 黄(4)标记像素在输出中擦除（设为黑(0)）。蓝(1)分隔线保持不变。源图案单元格中的原始红像素保留。

**关键洞察**：选择哪些单元格接收图案副本不是由固定的奇偶规则决定的，而是由一条动态螺旋路径决定的。阵列的行列数直接影响螺旋形状，从而改变接收副本的单元格集合。黄标记的角落位置决定螺旋起点，但螺旋方向始终为顺时针。

## 新题 6：方向自适应的端口对接拼装

**组合逻辑**：[same_color_dock](已有) → [mirror](创新：翻转方向不由缺角决定，而由端口暴露面的朝向差异决定) → [stitch + crop](已有)

**来源原语**：connector_marker、same_color_dock、marker_side_dir、stitch、crop（e9fc42f2）；mirror、flip_by_missing_corner（ac0c5833）；sprite（ac0c5833）

**依赖链**：不匹配端口颜色就不知道哪些碎片要拼在一起；不分析端口暴露面朝向就不知道是否需要翻转以及翻转轴向；不翻转则端口可能朝向不对无法对接。

将多个碎片通过同色端口标记拼装为一体，当碎片的端口朝向与锚点不匹配时自动翻转碎片使端口面对面对齐。

**输入结构**：黑(0)背景，约15x15网格。3~4个多色4-连通前景物体，物体之间互不接触。每个物体有一个主体色（如灰(5)）和1~2个单像素端口标记，端口标记颜色取自红(2)、绿(3)、黄(4)、橙(7)等。每种端口颜色在所有物体中恰好出现两次（分属两个不同物体）。面积最大的物体为锚点。生成约束：每个端口像素恰好有一个暴露面（即恰好一个正交相邻格为黑(0)背景或网格外，其余三个正交相邻格为同物体的像素）；每对匹配端口的暴露面方向要么相反（如一左一右）要么相同（如都朝右）。

**规则**：
1. 识别面积最大的4-连通前景物体为锚点（面积 = 物体总像素数）。其余为碎片。
2. 对每个碎片，找到它与锚点共享的端口颜色c。
3. 确定锚点上颜色c端口像素的暴露面方向d_a（上/下/左/右）：该端口像素四个正交邻居中唯一不属于本物体的方向。碎片上颜色c端口像素的暴露面方向d_p同理。
4. 若d_a与d_p相反（如d_a=右, d_p=左），碎片无需翻转。将碎片平移，使碎片端口像素位于锚点端口像素沿d_a方向的相邻格子上。
5. 若d_a与d_p相同（如都为右），碎片需沿垂直于该方向的轴做镜像翻转（例如都朝右则沿水平轴做左右翻转）。翻转后碎片端口暴露面变为d_a的反方向，再按规则4平移对接。
6. 各碎片按其端口颜色在锚点上的出现位置排序（按锚点端口像素的行号升序，行号相同按列号升序）依次处理。后拼装碎片的像素覆盖先拼装碎片的像素。
7. 输出：拼装结果的紧凑裁剪框，背景为黑(0)。

**关键洞察**：端口颜色不仅标识"谁和谁对接"，端口的暴露面方向还编码了"是否需要翻转碎片"。不分析暴露面就不知道拼装方向，翻转错误会导致端口背对背无法贴合。

## 新题 7：面积分级的自相似展开

**组合逻辑**：[counting/area_filtering](已有) → [crop](已有) → [recursive_expand/self_similar_sub](创新：种子掩码和间隔填充色不来自边界图例，而由面积排名前两位的物体分别提供)

**来源原语**：counting、area_filtering、connected_component、ignore_distractors（a3325580）；recursive_expand、seed_mask、self_similar_sub、fg_bg_separate（58c02a16）；crop（2d0172a1）

**依赖链**：不计算面积就无法确定哪个物体充当种子、哪个提供间隔色；不裁剪最大物体就得不到种子掩码；不展开就缺少输出结构。第三名及更小的物体是干扰项，但必须计算它们的面积才能确认前两名的排名。

从多个不同大小的物体中，按面积选出最大者作为自相似种子掩码、次大者提供间隔填充色，执行一轮分形展开。

**输入结构**：黑(0)背景，约14x14网格。3~5个不同颜色的4-连通单色前景物体，面积（像素数）各不相同，取值范围3~12像素。每个物体颜色唯一，取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)等。物体之间互不接触、互不嵌套。生成约束：面积最大物体的边界框尺寸不超过5x5（保证展开后输出不超过25x25）；所有物体面积两两不同。

**规则**：
1. 计算每个前景4-连通单色物体的面积（像素数）。
2. 面积最大的物体：裁剪其边界框得到种子掩码M（尺寸HxW），其中该物体颜色C1的像素为前景，黑(0)为背景。
3. 面积第二大的物体：记录其颜色C2。
4. 执行一轮自相似替换：创建(H*H)行 x (W*W)列的输出网格。对种子掩码M中第r行第c列的格子（0起始）：若为前景(C1)，在输出的第(r*H)至第((r+1)*H-1)行、第(c*W)至第((c+1)*W-1)列放置种子掩码M的一个副本（前景像素用C1，背景像素用黑(0)）；若为背景(黑(0))，在对应区域填充纯色C2。
5. 其余物体（第三名及以下）全部丢弃，不出现在输出中。

**关键洞察**：两个面积排名不同的物体承担完全不同的角色——大者贡献"形状基因"（种子掩码），次大者仅贡献"颜色基因"（间隔填充色）。第三名及以下虽不参与输出，但必须被识别和排除才能确认前两名。

## 新题 8：镜像合并后按连通面积染色

**组合逻辑**：[mirror](已有) → [transparent_overlay/boolean_union](创新：合并对象是原始掩码和它自身的镜像，而非两个独立面板) → [counting + sort + recolor](创新：对合并后涌现的连通分量按面积排名分配颜色，颜色方案来自排名而非输入)

**来源原语**：transparent_overlay、boolean_union、foreground_mask、cell_alignment（dae9d2b5）；mirror、append_mirror_copy（6d0aefbc）；counting、sort、area_filtering（a3325580）；recolor（d90796e8）

**依赖链**：不镜像就没有第二份掩码用来合并；不做布尔并集就不会产生新的连通分量形态（涌现效应）；不按面积排名就无法确定各分量的输出颜色。面积排名的对象是合并后才涌现的形状，无法从输入单侧预判。

将一个前景掩码与其水平镜像做布尔并集，然后对涌现出的每个连通分量按面积大小分配不同的颜色。

**输入结构**：黑(0)背景，约10x10网格（列数为偶数）。网格中散布若干红(2)前景像素，形成1~3个不规则的4-连通分量。这些分量不关于网格垂直中线对称。生成约束：原始掩码与其水平镜像的布尔并集产生的4-连通分量数在2~4个之间，且各分量面积两两不同。

**规则**：
1. 将整个输入网格视为掩码A（前景 = 红(2)像素位置，背景 = 黑(0)位置）。
2. 将掩码A水平镜像（左右翻转列顺序）得到掩码B。
3. 计算布尔并集：在同尺寸网格上，某位置在A或B中任一为前景，则该位置为前景。
4. 在并集掩码中，找出所有4-连通前景分量，计算各分量面积（像素数）。
5. 按面积降序排列分量；面积相同时按分量最上方像素的行号升序排列，行号相同按最左列号升序排列。
6. 为排名第k（1起始）的分量分配颜色：第1名蓝(1)，第2名绿(3)，第3名黄(4)，第4名橙(7)。
7. 输出网格中，每个前景像素涂为其所属分量的分配颜色；背景像素保持黑(0)。

**关键洞察**：输出中的连通分量形状是原始图案与其镜像叠加后才涌现的——它们在输入中不直接可见。必须先在脑中完成镜像和合并，才能知道有几个分量、各有多大，从而确定染色方案。
