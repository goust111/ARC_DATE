## 新题 1：对称性决定射线方向

**组合逻辑**：[对称检测](创新：从"选出异常对象"改为"决定射线方向") + [射线延伸](创新：从"仅向右"改为"方向由对称性决定") + [奇偶交替] + [异常值选择](创新：从"裁剪输出"改为"赋予独特行为")

**来源原语**：对称检测/symmetry_detect (73ccf9c2, 662c240a), 射线延伸/ray_extend (97999447), 奇偶交替/parity_alternation (97999447), 前景对象/foreground_object (73ccf9c2), 唯一非轴对称/unique_asymmetric (73ccf9c2), 异常值选择/outlier_selection (73ccf9c2)

**依赖链**：对称检测的结果决定每个对象的射线方向 → 不同方向的射线在网格上铺展 → 射线交叉点处需要优先级规则消解冲突。三者缺一则输出不确定：无对称检测则方向未知，无射线延伸则无形状生成，无交叉规则则冲突像素颜色模糊。

对称性不再仅仅用于"选出哪个对象"，而是作为每个对象的行为分类器，将空间分析的结果转化为运动方向——这种"属性→方向"的映射在参考题中不存在。

**输入结构**：约 15x15 网格，黑(0)背景。散布 4-5 个小型单色 4-连通前景对象，每个对象颜色互不相同（使用蓝(1)、红(2)、绿(3)、黄(4)、橙(7)等），每个对象由 3-6 个像素组成，紧边界框不超过 3x3。对象之间互不相邻（紧边界框间距至少 2 像素）。其中恰好一个对象在其紧边界框内的前景掩码不等于其左右翻转（即不具备垂直轴对称性），其余所有对象均具备垂直轴对称性。生成约束：每个对象的最底行像素和最右列像素到网格边界至少留 1 行/列空间，以保证射线可见。

**规则**：
1. 对每个前景对象，取其紧边界框内的前景掩码，检测该掩码是否等于其左右镜像。
2. 垂直轴对称的对象：从该对象最底行的最左前景像素出发，向下逐格铺设射线直到网格底部边界。射线着色为交替模式：偏移量 0（起点下方紧邻像素）涂该对象颜色，偏移量 1 涂灰(5)，偏移量 2 涂该对象颜色，以此类推。
3. 非垂直轴对称的对象（唯一一个）：从该对象最右列的最上前景像素出发，向右逐格铺设射线直到网格右边界。着色模式同上：偏移量 0 涂该对象颜色，偏移量 1 涂灰(5)，交替进行。
4. 若两条射线占据同一像素，保留非对称对象射线的颜色（无论该像素位置是对象色还是灰(5)）。
5. 原始前景对象的像素保持不变，射线不覆盖其他对象的原始像素。

**关键洞察**：对称性检测在参考题中只做"选出/裁剪"，这里它变成了方向控制器——对称对象向下、非对称对象向右，且方向决定了哪些射线可能相交。只有同时理解对称性判定和射线延伸的交替规则，才能正确处理交叉像素。仅看一个示例可能误判"向右的那个"是因为颜色或位置特殊，需要多个示例（非对称对象换颜色、换位置）才能归纳出对称性是方向的真正决定因素。

## 新题 2：角标记矩形的条纹间距由外部精灵计数决定

**组合逻辑**：[角标记→矩形识别] + [计数](创新：从"点数表示"改为"决定填充疏密") + [填充](创新：从"整体红色填充"改为"条纹化填充，间距由外部信息决定") + [擦除]

**来源原语**：角标记/corner_marker (af902bf9), 四角标记围定内部/four_corners_define_interior (af902bf9), 填充/fill (af902bf9), 计数/counting (8f215267), 同色匹配/same_color_matching (8f215267), 图案精灵体/pattern_sprite (8f215267), 擦除/erase (8f215267)

**依赖链**：角标记 → 确定矩形几何区域；矩形内标签像素 → 确定填充颜色；外部同色精灵计数 → 确定条纹间距。三个独立信息源（几何、颜色、疏密）汇聚到一个填充操作上，删掉任何一个来源都无法确定输出。

角标记在参考题中直接触发整体填充；计数在参考题中映射为框内的点数。这里计数不画点，而是调制填充的空间频率——计数结果转化为几何参数，这种"数量→周期"的映射在参考题中不存在。

**输入结构**：约 15x15 网格，黑(0)背景。2-3 组黄(4)像素，每组恰好 4 个黄像素，构成一个轴对齐矩形的四个角（四个黄像素共享恰好两个行坐标和两个列坐标）。每个矩形内部（不含角）有恰好 1 个非黑非黄的"标签像素"，不同矩形的标签像素颜色互不相同（使用蓝(1)、红(2)、绿(3)等）。矩形之间不重叠（包括角），矩形内部高度至少 5 行（不含角行）。在所有矩形外部，散布若干小型 4-连通单色精灵体（每个 2-4 像素，非矩形形状），颜色从标签像素颜色集合中选取。每种标签颜色对应的外部精灵数量为 1-4 个。生成约束：每种标签颜色至少有 1 个外部精灵。

**规则**：
1. 识别每组 4 个黄(4)像素构成的矩形。矩形按左上角位置从左到右、从上到下排序处理。
2. 读取每个矩形内部的标签像素颜色 C。
3. 统计网格中所有矩形外部颜色为 C 的精灵体数量，记为 K。
4. 在矩形内部（不含四个角像素所在的行和列），从内部第 1 行开始，每隔 K 行涂一整行标签颜色 C 的水平条纹。具体地：内部行编号从 0 开始，行号对 (K+1) 取模为 0 的行涂 C 色，其余内部行保持黑(0)。
5. 擦除所有外部精灵体（恢复为黑(0)）。
6. 黄(4)角像素和标签像素保持不变。

**关键洞察**：矩形几何来自角标记，颜色来自内部标签，但条纹疏密来自外部精灵的数量——三个独立信息源决定一个输出。仅看一个示例可能误判条纹间距是固定值或由矩形尺寸决定，需要多个示例（同一矩形大小但不同精灵数量导致不同间距）才能发现计数与间距的关联。

## 新题 3：压缩采样后对称性决定平铺镜像模式

**组合逻辑**：[压缩/分区采样](已有) + [对称检测](创新：从"选出非对称瓦片"改为"决定平铺方式的分支条件") + [平铺+镜像](创新：从"固定中间行翻转"改为"镜像方向由对称分析结果决定")

**来源原语**：压缩/compress (5783df64), 分区采样/block_sampling (5783df64), 分区网格/partitioned_grid (5783df64), 对称检测/symmetry_detect (662c240a), 平铺/tiling (00576224), 镜像/mirror (00576224), 堆叠排列/stacked_layout (662c240a)

**依赖链**：压缩将大网格化为小网格 → 对小网格做转置对称检测（是否 A[r][c] == A[c][r]）→ 检测结果选择平铺时邻接副本的镜像轴方向。压缩决定了被检测的内容，对称性决定了平铺行为，三者环环相扣。

在参考题中，压缩是终止操作（输出就是压缩结果），对称检测用于从多个瓦片中"选一个"，平铺的翻转模式是固定的。这里压缩的输出不是最终答案而是中间产物，对称检测不做选择而是做决策分支，平铺模式不固定而是由对称分析动态决定。

**输入结构**：约 12x12 或 15x15 网格（边长为 3 的倍数），黑(0)背景。网格被隐式地均分为 3x3 的大块布局，每个大块尺寸相同。每个大块内恰好有 1 个非黑像素（颜色取自蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7)、青(8)、栗(9)），9 个大块的非黑像素颜色可重复。生成约束：不同示例中，有的压缩结果关于主对角线对称（A[r][c] == A[c][r] 对所有 r,c 成立），有的不对称，以便训练集覆盖两种分支。

**规则**：
1. 将输入网格按 3x3 大块布局划分，提取每个大块中唯一的非黑像素颜色，得到 3x3 的压缩网格 T。
2. 检测 T 是否关于主对角线对称：即对所有 0 <= r,c <= 2，是否 T[r][c] == T[c][r]。
3. 若 T 关于主对角线对称：构造 2x2 的瓦片阵列（输出为 6x6），其中 (0,0) 和 (1,1) 位置放 T 原样，(0,1) 和 (1,0) 位置放 T 的左右镜像。
4. 若 T 不关于主对角线对称：构造 2x2 的瓦片阵列（输出为 6x6），其中 (0,0) 和 (1,1) 位置放 T 原样，(0,1) 和 (1,0) 位置放 T 的上下镜像。
5. 输出即为 6x6 的瓦片阵列。

**关键洞察**：压缩结果的主对角线对称性不是要"选出"什么，而是一个隐式的分支开关——对称走左右镜像路径，不对称走上下镜像路径。从单个示例中只能看到一种镜像方式，必须看到两种才能归纳出对称性是决定镜像方向的条件。

## 新题 4：边界矩形按外部精灵计数决定内移距离

**组合逻辑**：[平移](创新：从"按自身尺寸内移"改为"按外部计数内移") + [计数+同色匹配](创新：从"映射为点数"改为"映射为平移距离") + [擦除] + [贴边定位]

**来源原语**：平移/translate (22208ba4), 贴边定位/border_aligned (22208ba4), 边界矩形/boundary_rectangle (22208ba4), 擦除/erase (22208ba4, 8f215267), 计数/counting (8f215267), 同色匹配/same_color_matching (8f215267), 图案精灵体/pattern_sprite (8f215267)

**依赖链**：同色精灵计数 → 确定每个矩形的平移距离 → 平移可能产生重叠 → 重叠需要优先级规则。计数驱动平移距离，平移产生的空间冲突需要额外规则解决——两层逻辑嵌套。

在参考题中，矩形按自身尺寸内移（距离是自含的），精灵计数映射为框内点数（纯表示）。这里计数结果驱动几何操作的参数——"数量→空间位移"的映射将两道参考题的核心机制以全新方式关联。

**输入结构**：约 14x14 网格，黑(0)背景。3-4 个单色实心矩形，每个矩形恰好贴合网格的一条边（上、下、左或右边界），同一条边至多一个矩形。矩形颜色互不相同（使用蓝(1)、红(2)、绿(3)、橙(7)等），每个矩形宽或高为 2-3 像素，沿贴边方向长度为 3-5 像素。网格内部（不触碰任何边界）散布若干小型 4-连通非矩形精灵体（每个 2-4 像素），颜色取自矩形颜色集合。生成约束：每种矩形颜色至少对应 1 个外部精灵，每种颜色对应的精灵数量为 1-3。矩形按计数值平移后不会超出网格边界。不同矩形平移后如果重叠，重叠区域面积不超过较小矩形面积的一半。

**规则**：
1. 对每个边界矩形颜色 C，统计网格内部颜色为 C 的精灵体数量，记为 K。
2. 将该矩形从其贴合的边界向网格内部方向平移 K 个像素（上边界矩形向下移 K，右边界矩形向左移 K，以此类推）。原位置恢复为黑(0)。
3. 擦除所有内部精灵体（恢复为黑(0)）。
4. 若两个平移后的矩形重叠，K 值较大的矩形覆盖在上层（相同 K 值时，贴合上边界或左边界的矩形优先）。

**关键洞察**：参考题中矩形按自身尺寸移动，距离信息是自包含的；这里距离信息来自散落的精灵——精灵不是装饰而是编码了平移参数。仅看一个示例可能认为平移距离与矩形尺寸或位置有关，需要多个示例（同尺寸矩形但精灵数量不同导致不同位移）才能发现真正的距离决定因素。

## 新题 5：半轮廓镜像补全后按图例颜色填充内部并擦除轮廓

**组合逻辑**：[镜像](创新：从"单一半轮廓→填充"改为"多个半轮廓，各自镜像") + [填充](创新：从"填充色=轮廓色"改为"填充色由外部图例决定") + [图例映射](创新：从"映射膨胀光晕色"改为"映射内部填充色") + [擦除](创新：轮廓本身作为构造辅助线被擦除)

**来源原语**：半侧轮廓/half_outline (bf32578f), 镜像/mirror (bf32578f), 填充/fill (bf32578f), 内部行段填充/fill_interior_spans (bf32578f), 对称/symmetry (bf32578f), 图例映射/legend_mapping (5adee1b2), 颜色图例/color_legend (5adee1b2), 擦除/erase (bf32578f), 重涂色/recolor (5adee1b2)

**依赖链**：镜像补全定义了封闭轮廓 → 封闭轮廓才有"内部"可以填充 → 填充颜色不来自轮廓本身而来自图例 → 填充后轮廓被擦除。四步缺一不可：无镜像则无封闭区域，无图例则不知填什么色，无擦除则轮廓残留影响输出。

半轮廓在参考题中是形状的一半，镜像后填充内部与轮廓同色。图例在参考题中用于决定膨胀光晕色。这里两者在"颜色归属"上产生了新的结构关系：轮廓色不再是填充色，而是图例查找键；图例不再服务于膨胀，而是服务于镜像后的内部填充。

**输入结构**：约 12x18 网格，黑(0)背景。网格顶部 2 行为图例区：每个图例条目占 1x2（左格为轮廓颜色，右格为对应的填充颜色），多个条目水平排列，条目间空 1 列黑(0)。图例下方为主区域，包含 2-3 个半轮廓，每个半轮廓是某个水平对称封闭形状的左半部分（含对称轴上的像素列），由其特定颜色绘制（使用蓝(1)、红(2)、绿(3)等，均在图例中有对应条目）。半轮廓的颜色互不相同。每个半轮廓的最右列（对称轴列）到其右侧有足够空间容纳镜像后的右半部分。不同半轮廓镜像补全后互不重叠。每个半轮廓宽 3-5 像素、高 4-7 像素，形状不规则但保证镜像后形成封闭轮廓（左半部分的每一行至少有 1 个前景像素，最上行和最下行的前景像素形成连续水平段）。

**规则**：
1. 识别图例区的颜色映射：左格颜色 → 右格颜色。
2. 对主区域中每个半轮廓 H（颜色为 C）：
   a. 找到 H 的最右列作为对称轴。
   b. 将 H 沿对称轴右侧镜像，生成完整的对称轮廓。
3. 对每个完整轮廓，逐行扫描：在每行中找到最左和最右的轮廓像素，将它们之间（不含两端）的黑(0)像素涂为图例中 C 对应的填充颜色。
4. 擦除所有轮廓像素（将颜色 C 的轮廓像素恢复为黑(0)），只保留填充区域和图例区。
5. 多个半轮廓按紧边界框左上角从左到右、从上到下的顺序依次处理。

**关键洞察**：轮廓只是构造辅助线——它定义了填充区域的边界，但自身最终被擦除。填充颜色不来自轮廓颜色，而是通过图例间接映射。仅看一个示例可能认为填充色是固定的或直接等于轮廓色，必须对比多个示例（不同轮廓色映射到不同填充色）才能发现图例的作用。

## 新题 6：控制精灵逐行对称分析决定瓦片戳印朝向

**组合逻辑**：[像素放大/瓦片戳印](已有骨架) + [对称检测](创新：从"对象级"细化到"逐行级"，决定每行的瓦片朝向) + [镜像](创新：不是对输出镜像，而是对瓦片本身做条件式左右翻转)

**来源原语**：像素放大/pixel_upscale (bf45cf4b), 控制精灵/control_sprite (bf45cf4b), 多色瓦片/polychrome_tile (bf45cf4b), 掩码映射/mask_mapping (bf45cf4b), 对称检测/symmetry_detect (73ccf9c2, 662c240a), 镜像/mirror (00576224)

**依赖链**：控制精灵的掩码决定哪些像素展开为瓦片 → 每个像素所在行的填充模式（该行中哪些列有前景）是否左右对称决定了瓦片正放还是翻转 → 瓦片的非对称性使得翻转在视觉上可区分。三者紧耦合：精灵形状决定展开位置，精灵的行内结构决定朝向，瓦片的非对称性使得朝向有意义。

在参考题中，所有填充像素都用同一朝向的瓦片；对称检测在参考题中用于选择对象，不用于控制行为参数。这里对称检测被细化到逐行层面，成为每个像素的瓦片朝向控制器——同一个精灵内不同行的像素可能拿到不同朝向的瓦片。

**输入结构**：约 10x10 网格，黑(0)背景。两个前景对象，互不接触：
- 一个单色（灰(5)）矩形边界框内的控制精灵，含若干黑(0)孔洞。边界框约 3x4 到 4x5 像素。精灵的某些行的前景像素分布左右对称（如该行第 0、3 列有前景，第 1、2 列也有前景，关于行中心对称），某些行不对称。
- 一个多色方形瓦片，边长 2 或 3，该瓦片不具备左右对称性（左右翻转后与原瓦片不同）。

生成约束：控制精灵的行数 >= 2，至少有一行对称、一行不对称。瓦片至少使用 2 种非黑非灰颜色。

**规则**：
1. 确定控制精灵的紧边界框及其内部的前景掩码 M（H 行 x W 列）。
2. 对 M 的每一行 r（0 <= r < H），提取该行的前景位模式 P_r（长度为 W 的布尔序列），检测 P_r 是否等于其左右翻转。
3. 构建输出网格：尺寸为 (H x tile_h) 行 x (W x tile_w) 列。
4. 对 M 中每个像素 (r, c)：
   - 若 M[r][c] 为背景(0)：对应的 tile_h x tile_w 输出区域全部填黑(0)。
   - 若 M[r][c] 为前景，且第 r 行对称：在对应输出区域戳印瓦片的原始朝向。
   - 若 M[r][c] 为前景，且第 r 行不对称：在对应输出区域戳印瓦片的左右镜像。
5. 像素按从上到下、从左到右顺序处理（因各区域不重叠，顺序不影响结果）。

**关键洞察**：瓦片的朝向不是全局统一的，而是由控制精灵的逐行对称性逐行决定。瓦片本身的非对称性是必要条件——若瓦片对称，则正放和翻转无区别，规则无法被观测。仅看一个示例中全部行碰巧都是对称或不对称的情况，会错误推断为"统一正放"或"统一翻转"，需要看到同一精灵内对称行和非对称行共存的示例才能归纳规则。

## 新题 7：多源射线交叉构成封闭区域后填充

**组合逻辑**：[射线延伸](创新：从"单方向"改为"四方向十字射线") + [边界包围内部](创新：从"行段内部"改为"射线网格围成的矩形区域") + [填充](创新：不是填充预定义轮廓，而是填充由射线涌现出的封闭区域)

**来源原语**：射线延伸/ray_extend (97999447), 孤立像素/isolated_pixel (97999447), 画布边界/canvas_boundary (97999447), 填充/fill (af902bf9, bf32578f), 边界包围内部/boundary_encloses_interior (62b74c02)

**依赖链**：每个孤立像素独立发射十字射线 → 多组射线在网格上交叉形成格子状图案 → 格子中完全被射线包围的矩形区域（即不能沿黑(0)像素 4-连通到达网格边界的连通分量）被识别并填充。填充目标不是预先给定的，而是从射线组合中涌现出来的——单个像素无法围成区域，必须至少两个像素的射线交叉才能产生封闭空间。

在参考题中，射线仅向右延伸且不涉及封闭；填充操作作用于已知的角标记围定矩形或半轮廓定义的内部。这里封闭区域是射线交叉的涌现结果——没有任何单一像素"拥有"被填充的区域。

**输入结构**：约 13x13 网格，黑(0)背景。2-4 个蓝(1)孤立像素（每个像素上下左右相邻像素均为黑(0)），无两个像素在同一行或同一列。生成约束：所有蓝像素不在网格最外圈（至少距边界 1 像素），以保证所有四个方向的射线至少有 1 像素长。蓝像素的数量和位置保证至少产生 1 个封闭区域。

**规则**：
1. 对每个蓝(1)像素，向上、下、左、右四个方向发射射线至网格边界，射线颜色为蓝(1)。射线包含起始像素本身。
2. 射线在同一像素交叉时保持蓝(1)（颜色一致，无冲突）。
3. 所有射线绘制完毕后，识别黑(0)像素的 4-连通分量。每个分量若不包含任何位于网格最外圈（第 0 行、最后一行、第 0 列、最后一列）的像素，则视为封闭区域。
4. 将所有封闭区域的像素填充为红(2)。
5. 蓝(1)射线像素和非封闭的黑(0)区域保持不变。

**关键洞察**：每个像素单独只画一个十字，无封闭区域可言。封闭区域是多个十字的射线相互"围栏"的结果——这是组合涌现效应。像素数量和相对位置决定了封闭区域的数量和大小。仅看一个示例可能误以为"所有黑色矩形都填红"，需要看到不同像素配置（有的产生多个封闭区域、有的只产生一个）才能发现"封闭性"是填充的真正条件。

## 新题 8：同心正方形缩放后按图例重涂色并解决重叠

**组合逻辑**：[缩放/边长循环](已有) + [图例映射](创新：从"映射光晕色"改为"映射缩放后的正方形颜色") + [重涂色] + 重叠优先级（涌现：缩放改变大小关系后原本不重叠的正方形可能重叠）

**来源原语**：缩放/scaling (522fdd07), 边长循环变换/side_length_cycle (522fdd07), 同心定位/concentric_position (522fdd07), 奇数边正方形/odd_side_square (522fdd07), 图例映射/legend_mapping (5adee1b2), 颜色图例/color_legend (5adee1b2), 重涂色/recolor (5adee1b2)

**依赖链**：边长循环改变正方形大小 → 大小变化导致原本不重叠的正方形可能重叠 → 重叠需要优先级规则 → 同时图例映射改变颜色 → 颜色变化意味着优先级不能简单地"看颜色"，必须追踪原始颜色。两条独立的变换（尺寸和颜色）通过重叠问题产生交互。

在参考题中，正方形缩放后不会重叠（各自保持中心），且颜色不变。图例在参考题中用于膨胀光晕。这里缩放可以使小正方形变大（1→7），与相邻正方形发生重叠；同时颜色通过图例重映射，使得追踪"谁覆盖谁"需要同时理解两条变换链。

**输入结构**：约 15x15 网格，黑(0)背景。左侧两列为图例区：每行的第 0 列为原始颜色，第 1 列为映射后颜色，不同行的条目用黑(0)行分隔。图例条目覆盖所有出现的正方形颜色。主区域（第 3 列起）包含 3-4 个实心单色正方形，边长为奇数且属于集合 {1, 3, 5, 7}，颜色互不相同（使用蓝(1)、红(2)、绿(3)、橙(7)等）。生成约束：正方形中心之间的曼哈顿距离足够小，使得某些正方形在边长循环后会发生重叠。至少有一个边长为 1 的正方形（会变为 7）。所有正方形缩放后仍在网格边界内。

**规则**：
1. 读取图例区的颜色映射：原始颜色 → 新颜色。
2. 对每个正方形，保持中心不变，将边长 n 循环为：n > 1 时变为 n - 2；n = 1 时变为 7。
3. 按新边长从大到小的顺序绘制正方形（即大正方形先绘制，小正方形后绘制覆盖在上层）。新边长相同时，中心行坐标较小的先绘制。
4. 每个正方形绘制时使用图例映射后的新颜色。
5. 图例区保持不变。

**关键洞察**：边长为 1 的像素点会膨胀为 7x7 大方块，可能吞没周围原本较大的正方形。但绘制顺序是"大先小后"，所以虽然变大的原小正方形面积最大，它可能被更晚绘制的小正方形（原本较大但缩小了的）部分覆盖。同时颜色经过图例重映射，使得视觉上需要逆向追踪：看到的新颜色→查图例反推原始颜色→推断原始边长→推断缩放行为。

## 新题 9：双掩码叠加后交界邻接染色

**组合逻辑**：[透明叠加/逐像素比较](创新：从"标记共同背景"改为"分类每个像素为交集/独占/共空") + [膨胀](创新：从"膨胀对象生成光晕"改为"膨胀交集区域检测邻接") + [重涂色](创新：根据像素的叠加分类和邻接关系决定颜色)

**来源原语**：透明叠加/overlay (94f9d214), 逐像素比较/per_pixel_comparison (94f9d214), 掩码/mask (94f9d214), 膨胀/dilate (5adee1b2), 连通分量/connected_component (5adee1b2), 重涂色/recolor (5adee1b2)

**依赖链**：逐像素比较将每个位置分为四类 → 膨胀交集区域的边界 → 膨胀扩展到的独占区域像素被特殊着色，扩展方向（来自哪个半区的独占像素）决定着色。比较产生类别，膨胀检测类别间的空间邻接，邻接方向决定最终颜色。

在参考题中，两个掩码的比较只标记"共同背景"，结果是单一类型的标记。膨胀在参考题中用于给对象添加光晕。这里比较产生多种类别（交集 vs 独占 vs 共空），膨胀不是扩展对象本身，而是检测交集区域与独占区域之间的空间接触关系——膨胀作为邻接探测器而非形态扩展器，这在参考题中不存在。

**输入结构**：约 10x20 网格，由上下两个 10x10 半区垂直堆叠组成。两个半区共享黑(0)背景。上半区包含一个或多个绿(3)前景对象（4-连通，总计 8-20 像素），下半区包含一个或多个蓝(1)前景对象（4-连通，总计 8-20 像素）。两个半区的前景图案有部分空间重叠（即上半区 (r,c) 处有前景，下半区同一相对位置 (r,c) 也有前景），也有各自独占的部分。生成约束：交集区域（两者都有前景的位置）至少有 3 个像素，且交集区域 4-连通。交集区域至少与一个上半区独占像素和一个下半区独占像素 4-邻接。

**规则**：
1. 将两个半区逐像素比较（按相对位置 (r,c)），生成一个 10x10 的分类网格：
   - 交集：上下半区该位置都是前景 → 标记为红(2)。
   - 上独占：仅上半区有前景 → 保持绿(3)。
   - 下独占：仅下半区有前景 → 保持蓝(1)。
   - 共空：两者都是背景 → 保持黑(0)。
2. 将交集区域（红(2)像素集合）膨胀 1 像素：对每个红(2)像素的 4 个邻格，若该邻格不是红(2)，则标记为"膨胀接触"。
3. 膨胀接触到的像素根据其原类别重涂色：
   - 若膨胀接触到的像素是上独占（绿(3)）→ 重涂为黄(4)。
   - 若膨胀接触到的像素是下独占（蓝(1)）→ 重涂为橙(7)。
   - 若膨胀接触到的像素是共空（黑(0)）→ 不变，保持黑(0)。
4. 未被膨胀接触的上独占像素保持绿(3)，下独占像素保持蓝(1)。
5. 输出为 10x10 网格（单半区尺寸）。

**关键洞察**：叠加比较产生的"交集边界"是关键——膨胀不是为了让交集变大，而是为了探测交集旁边紧邻的是谁的独占领地。被探测到的邻接像素获得新颜色（黄或橙），揭示了两个图案在边界处的接触关系。仅看一个示例可能认为黄/橙是按位置或大小分配的，需要多个示例（交集在不同位置，邻接方向不同）才能发现膨胀邻接是着色的真正条件。
