## 新题 1：拓扑排序叠加

**组合逻辑**：[计数](封闭孔洞数，非前景像素数) + [排序](按孔洞数) + [透明叠加](按排序结果确定图层优先级)（创新：孔洞数 -> 图层深度，源题中不存在此映射）

**来源原语**：计数(counting) ← dc2aa30b/e3721c99；排序(sorting) ← dc2aa30b；透明叠加(transparent_overlay) ← bbb1b8b6/281123b4；封闭区域(enclosed_region) ← e3721c99；图层优先级(layer_priority) ← 281123b4

**依赖链**：孔洞计数结果直接决定叠加图层顺序；不计数则无法排序，不排序则无法确定遮挡关系。三步之间信息不可跳过。

将多个具有不同数量封闭孔洞的彩色精灵体，按孔洞数排序后叠加到目标区域，孔洞越少的精灵体越靠前层。

**输入结构**：背景黑(0)，网格约 15x15。散布 3-5 个彩色精灵体，每个精灵体为单色 4-连通区域（5-15 像素），颜色互不相同且均非黑(0)、非灰(5)。每个精灵体拥有 0-3 个封闭背景孔洞（孔洞 = 完全被精灵体像素包围的黑(0)连通区域，不触及精灵体边界框的边）。各精灵体的孔洞数互不相同。网格中央有一个灰(5)空心矩形框（内部为黑(0)），其内部尺寸大于任何精灵体的边界框。生成约束：所有精灵体互不相邻，灰框不与任何精灵体重叠。

**规则**：
1. 对每个彩色精灵体，计算其封闭背景孔洞数（4-连通黑(0)区域，完全被该精灵体像素包围且不触及精灵体边界框的四条边）。
2. 按孔洞数从大到小排列精灵体（孔洞最多的排在最后层/最底层）。若孔洞数相同（生成时已保证不同，此条为完备性声明），按精灵体边界框左上角的行优先距离排序，距网格左上角更近者靠前层。
3. 擦除灰(5)矩形框。以灰框中心为对齐点，将排序后的精灵体依次叠加：从最底层（孔洞最多）开始绘制，到最顶层（孔洞最少）结束。每个精灵体以其边界框中心对齐灰框中心，保留原色，背景像素视为透明。后绘制的覆盖先绘制的。
4. 原始位置的精灵体被擦除（恢复为黑(0)）。

**关键洞察**：叠加的图层顺序不由空间位置决定，而由每个精灵体的拓扑属性（封闭孔洞数）决定。求解者必须先分析各精灵体的拓扑结构，才能推断遮挡关系。

## 新题 2：条纹采色弹射线

**组合逻辑**：[去噪/条纹检测](确定条纹方向和主色) + [射线延伸+边界反射](发射对角弹射线) + [重涂色](射线逐单元格继承所在条纹的主色)（创新：射线颜色不固定，由局部条纹身份动态决定）

**来源原语**：射线延伸(ray_extend) ← e179c5f4；边界反射(boundary_reflection) ← e179c5f4；去噪(denoise) ← e26a3af2；条纹行列(stripe_line) ← e26a3af2；主色占优(dominant_color) ← e26a3af2；重涂色(recolor) ← e26a3af2

**依赖链**：必须先检测条纹方向才能确定每条条纹的主色；射线路径的每个像素颜色依赖于它所在条纹的主色；条纹检测和射线追踪两个逻辑同时作用于同一网格，输出是二者交织的结果。

在带噪声的条纹网格上发射一条对角弹射线，射线经过每个单元格时继承该单元格所在条纹的主色，同时噪声被清除。

**输入结构**：网格约 12x12。网格由水平或垂直条纹构成（交替使用 2-3 种颜色，每条纹宽 1-2 行/列）。条纹上散布少量噪声像素（使用条纹色或其他颜色，总数不超过网格面积的 10%）。网格中有一个绿(3)种子像素，位于某条纹上。生成约束：条纹方向在水平和垂直之间二选一；绿(3)不用作任何条纹色。

**规则**：
1. 确定条纹方向：对每一行计算其出现最多的颜色（忽略绿(3)种子）的像素数，求所有行该数值之和得到水平分数；对列做同样计算得到垂直分数。取分数更高者为条纹方向。
2. 沿检测到的方向，确定每条条纹（行或列）的主色：该条纹中出现次数最多的颜色（忽略绿(3)），即为该条纹的主色。
3. 从绿(3)种子像素出发，沿右上方向（行-1，列+1）逐步前进。遇到左/右边界时水平反转方向；射线从网格顶部（行 < 0）飞出时停止。
4. 射线经过的每个单元格着色为该单元格所在条纹的主色（由步骤 2 确定）。
5. 将绿(3)种子像素替换为其所在条纹的主色。清除所有噪声：非射线路径上的单元格全部重涂为其所在条纹的主色。

**关键洞察**：射线不携带固定颜色——它是条纹结构的"采样器"，每经过一条新条纹就改变颜色。求解者必须同时理解条纹检测和射线追踪两套逻辑，才能预测射线路径上的颜色序列。

## 新题 3：整数降采样揭示隐藏旋转对称

**组合逻辑**：[降采样](揭示块状图案的小尺度结构) + [对称补全](在降采样层面检测并补全旋转对称缺失) + [像素放大+重涂色](将缺失块映射回原尺度并标记新色)（创新：对称性隐藏在整数缩放之下，须跨尺度推理）

**来源原语**：降采样(downsample) ← 6ecd11f4；整数缩放对应(int_scale_correspond) ← 6ecd11f4；对称补全(symmetry_completion) ← 1b60fb0c；旋转对称(rotational_symmetry) ← 1b60fb0c；缺失部分标记新色(missing_marked_new_color) ← 1b60fb0c；像素放大(pixel_upscale) ← 6aa20dc0

**依赖链**：原始网格中的图案由均匀块构成，肉眼难以直接识别旋转对称性；降采样后对称结构清晰可见，才能执行补全；补全结果须映射回原始尺度着色。三步环环相扣，跳过任何一步都无法求解。

大尺度块状图案隐藏着一个小尺度的近旋转对称结构；降采样后补全对称缺失，再将缺失块以新色标记回原始网格。

**输入结构**：网格约 12x12 或 15x15，背景黑(0)。网格上有一个绿(3)图案，由若干 3x3（或其他固定边长 k，k 在 2-4 之间）的均匀绑定块组成——每个块内所有像素同色（绿(3)或黑(0)）。将每个块视为一个"超级像素"后，绿块构成一个约 4x4 至 5x5 的二值图案。该二值图案几乎具有 180 度旋转对称性，但缺失 1-2 个绿块（对应位置为黑块）。生成约束：缺失块数不超过 2；旋转中心为二值图案的几何中心；缩放因子 k 在所有示例中固定。

**规则**：
1. 检测缩放因子 k：找到绿(3)像素构成的最小均匀块边长（所有绿色连通区域都是 k x k 的正方形，且左上角坐标是 k 的倍数）。
2. 将网格按 k x k 块降采样：每个块若包含绿(3)像素则记为 1，否则记为 0，得到一个小的二值矩阵。
3. 在二值矩阵中检测 180 度旋转对称：对每个值为 1 的位置 (r, c)，检查其关于矩阵中心的 180 度对称位置 (H-1-r, W-1-c)。若对称位置为 0，则该位置为"缺失块"。
4. 对每个缺失块，在原始网格中将对应的 k x k 区域全部涂为红(2)。
5. 保持所有原始绿(3)像素不变。

**关键洞察**：旋转对称性被整数缩放隐藏——在原始尺度上图案显得庞大而杂乱，只有先识别出块结构并降采样，对称性才变得可辨。求解者需要跨尺度推理：在小尺度检测对称、在大尺度执行着色。

## 新题 4：括号分道重力降落与像素计数排序

**组合逻辑**：[通道对齐](括号框定义列通道) + [重力下落](精灵体落入对应通道) + [计数+排序](通道内按像素数垂直排列)（创新：括号提供水平分区，像素计数决定垂直位序，两个独立维度的约束交织）

**来源原语**：括号框(bracket_frame) ← df9fd884；通道对齐(channel_aligned) ← df9fd884；重力下落(gravity_drop) ← df9fd884；目标底边对齐(target_base_aligned) ← df9fd884；排序(sorting) ← dc2aa30b；计数(counting) ← dc2aa30b；前景数决定排序(fg_count_determines_order) ← dc2aa30b

**依赖链**：括号框定义通道 -> 每个精灵体的水平中心决定其所属通道 -> 通道内多个精灵体按像素数排序 -> 排序结果决定垂直堆叠顺序。通道分配（空间）和像素排序（数值）必须同时满足才能确定最终位置。

多个小精灵体根据水平位置落入括号框定义的列通道中，通道内按像素数从少到多自底向上堆叠。

**输入结构**：网格约 15x20，背景黑(0)。顶部边缘有 2-3 个红(2)下开口括号框，每个括号框由一条水平顶边和两条垂直侧边构成（高 2-3 像素，内部宽 3-5 列），括号框之间至少隔 1 列。网格上半部分（括号框下方至网格中线之间）散布若干小精灵体（每个为单色 4-连通区域，3-7 像素，颜色各不相同且非红(2)非黑(0)）。每个精灵体的边界框宽度不超过任一括号框的内部宽度。生成约束：每个括号框的内部列范围恰好包含 2-3 个精灵体的水平中心；不同括号框的内部列范围互不重叠。

**规则**：
1. 识别所有红(2)括号框，记录每个括号框的内部列范围（左侧边右侧一列到右侧边左侧一列）。
2. 对每个精灵体，计算其边界框的水平中心列。将精灵体分配到内部列范围包含该中心列的括号框通道中。
3. 在每个通道内，按精灵体的像素数从小到大排序。若两个精灵体像素数相同，原始位置更靠上者（边界框顶行更小者）排在更下方（先放置）。
4. 擦除所有精灵体的原始位置（恢复为黑(0)）。
5. 在每个通道内，将排序后的精灵体从底部开始依次堆叠：像素数最少的精灵体的边界框底边与网格底边对齐；下一个精灵体的边界框底边紧接上一个精灵体的边界框顶边（无间隙）。每个精灵体的边界框水平居中于该通道的内部列范围。保持精灵体形状和颜色不变，仅改变位置。

**关键洞察**：水平归属由括号框的空间结构决定，垂直排列由像素计数的数值大小决定——求解者必须同时理解空间分区规则和数值排序规则，二者缺一不可。

## 新题 5：十字定位旋转印章

**组合逻辑**：[十字图案 → 对称轴定义](提取旋转中心与调色板) + [旋转](根据标记像素所在象限确定旋转角度) + [印章覆盖](将旋转后的图案印在标记位置)（创新：象限位置隐式编码旋转角度，十字同时提供中心参考和着色来源）

**来源原语**：十字图案(cross_pattern) ← 47c1f68c；对称轴定义(symmetry_axis_def) ← 47c1f68c；十字色作涂色源(cross_as_palette) ← 47c1f68c；旋转(rotate) ← 1b60fb0c/6150a2bd；印章覆盖(stamp) ← 88a10436；标记像素(marker_pixel) ← 88a10436/ded97339；中心对齐(center_align) ← 88a10436

**依赖链**：十字提供旋转参考中心和印章颜色 -> 标记像素的象限位置编码旋转角度 -> 旋转后的图案以标记为中心印章。移除十字、判断象限、执行旋转、着色印章四个环节紧密耦合。

移除中心十字后，将左上角的图案按标记像素所在象限对应的旋转角度印章到各标记位置，印章颜色采用十字色。

**输入结构**：奇数边长的正方形网格（约 11x11 至 15x15），背景黑(0)。一条完整的水平线和一条完整的垂直线以橙(7)交叉于网格中心，形成十字。左上象限内有一个蓝(1)小图案（4-连通，3-6 像素，不触及十字线，边界框为奇数行奇数列以确保有明确中心像素）。其他三个象限内各有 0 或 1 个绿(3)标记像素（总共 1-3 个标记），标记不在十字线上。生成约束：每个标记到十字中心的距离足够大，使得以标记为中心印章图案时不会超出网格边界；不同标记的印章区域互不重叠。

**规则**：
1. 记录十字中心坐标，然后擦除整条十字线（橙(7) -> 黑(0)）。
2. 保持左上象限的蓝(1)源图案不变。提取该图案的边界框内容作为印章模板（框内黑(0)像素视为透明）。
3. 对每个绿(3)标记像素，判断其相对于原十字中心所在的象限：
   - 右上象限：将模板顺时针旋转 90 度。
   - 右下象限：将模板旋转 180 度。
   - 左下象限：将模板顺时针旋转 270 度。
4. 将旋转后的模板以绿(3)标记像素为中心印章到网格上。印章中所有非透明像素着色为橙(7)（十字色），覆盖该位置原有内容（包括绿标记本身）。
5. 若多个印章区域有重叠（生成时已保证不重叠，此条为完备性声明），后处理的象限（按右上、右下、左下顺序）覆盖先处理的。

**关键洞察**：每个标记像素的象限位置隐式编码了旋转角度（右上=90、右下=180、左下=270），而十字既提供定位参考又提供着色来源。求解者需要从多个示例中归纳象限-角度的对应关系。

## 新题 6：格子编码门控链式填充

**组合逻辑**：[块解码为掩码](格子指令区解码为二值控制矩阵) + [形状匹配+拼接](精灵体匹配凹槽) + [链式填充](由解码掩码逐行门控链延伸)（创新：格子掩码不直接作用于像素，而是作为链式填充过程的"程序"，控制每条链的延伸步数）

**来源原语**：格子分割(lattice_partition) ← 15113be4；块解码为掩码(decode_block_to_mask) ← 15113be4；指令区域(instruction_region) ← 15113be4；拼接(assemble) ← 16b78196；链式填充(chain_fill) ← 16b78196；凹槽(notch) ← 16b78196；形状匹配(shape_matching) ← 16b78196；固定条带宽度(fixed_strip_width) ← 16b78196

**依赖链**：指令区域解码 -> 二值控制矩阵的列对应凹槽、行对应链步数 -> 精灵体匹配凹槽后启动链式填充 -> 每条链在控制矩阵对应位为 0 时截断。掩码解码结果直接改变链式填充的终止条件。

格子编码的指令区作为"程序"控制链式填充的步数：精灵体拼入横杆凹槽后沿链方向延伸，每走一步查询掩码，遇 0 则停。

**输入结构**：网格约 20x20，背景黑(0)。网格中部有一条灰(5)水平实心横杆（宽度占网格大部分，高 2-3 行）。横杆上边缘有 3 个凹槽（从横杆顶边向上凹入的矩形缺口，每个宽 2-4 列、深 1-2 行），凹槽间至少隔 2 列。横杆上方散布 3 个小精灵体（每个为单色 4-连通区域，3-8 像素，颜色各不相同且非灰(5)非黑(0)非黄(4)），每个精灵体的形状恰好能嵌入一个凹槽（精灵体的底部轮廓与凹槽形状互补）。网格左上角有一个 6x6 的指令区域，内部由黄(4)线分隔为 3x3 的格子，每个格子为 2x2 单元。部分格子内填充红(2)的 2x2 实心块（标记为 1），其余格子为黑(0)（标记为 0）。生成约束：指令区域的第一行（顶行的 3 个格子）至少有 1 个为 1；凹槽从左到右对应指令区域的列 0、1、2。

**规则**：
1. 解码指令区域：将 6x6 区域按黄(4)网格线分割为 3 列 x 3 行的格子。每个格子若包含红(2)的 2x2 块则为 1，否则为 0。得到一个 3x3 的二值控制矩阵 M，其中 M[row][col] 对应行 row（0=顶行）、列 col（0=左列）。
2. 将 3 个凹槽从左到右编号为 0、1、2，对应控制矩阵的列 0、1、2。
3. 对每个凹槽，找到形状匹配的精灵体（精灵体翻转后底部轮廓恰好填满凹槽）。将精灵体移入凹槽位置，这是链的第 0 步（根节点）。第 0 步始终执行（不受掩码控制）。
4. 链式向上延伸：第 s 步（s = 1, 2）时，检查控制矩阵 M[s][col]。若为 1，在前一步精灵体的正上方放置该精灵体的一个副本（形状、颜色不变，边界框底边紧接前一步边界框顶边）。若为 0，该链在此步停止，不再继续。
5. 擦除指令区域（恢复为黑(0)），擦除精灵体原始位置。

**关键洞察**：格子指令区不直接标记输出像素——它编码了一个"执行程序"，控制每条链延伸多远。不同凹槽的链可以有不同长度，取决于其对应列的掩码值分布。

## 新题 7：标记连线框架内弹性填充

**组合逻辑**：[连线+首尾跨度填充](标记像素连成矩形框架) + [弹性拉伸+模板填充](将多色范例弹性拉伸到框架内部)（创新：弹性填充的目标区域不是预置矩形，而是由标记连线动态构建的框架内部，框架尺寸决定拉伸参数）

**来源原语**：连线(connect) ← ded97339；同行列对齐(row_col_aligned) ← ded97339；首尾跨度填充(span_fill_between) ← ded97339；弹性拉伸(elastic_stretching) ← 40f6cd08；模板填充(template_filling) ← 40f6cd08；多色范例矩形(multicolor_exemplar_rect) ← 40f6cd08；内部行程(interior_run) ← 40f6cd08；按目标尺寸调整(resize_to_target) ← 40f6cd08

**依赖链**：标记像素位置 -> 连线形成矩形框 -> 框的内部尺寸 -> 弹性拉伸参数 -> 范例填入框内。不先连线就没有目标区域，不知道目标尺寸就无法确定拉伸方式。

四个标记像素通过行列跨度填充连成矩形框架，框架内部由弹性拉伸后的多色范例模板填充。

**输入结构**：网格约 15x15，背景黑(0)。4 个蓝(1)标记像素排布为一个轴对齐矩形的四个角——即存在两对标记同行、两对标记同列。矩形尺寸至少 5x5（含边框）。网格另一位置有一个小的多色范例矩形（3x3 或 4x4，包含 2-3 种非蓝(1)非黑(0)颜色的图案，四角同色作为范例的边框色）。范例矩形与标记像素互不重叠。生成约束：矩形框内部尺寸（高-2, 宽-2）在两个维度上分别不小于范例内部尺寸（范例高-2, 范例宽-2）。

**规则**：
1. 连线：对每一行，若该行包含至少 2 个蓝(1)标记像素，将最左标记到最右标记之间的所有像素涂蓝(1)。对每一列做同样操作。此步在 4 个角标记之间形成蓝(1)矩形边框。
2. 识别矩形边框的内部区域：严格位于蓝框之内的所有黑(0)像素组成的矩形区域，记其尺寸为 Ih x Iw。
3. 对多色范例矩形进行弹性拉伸以适配内部区域：
   - 将范例的行按连续相同行分组为行程（run）。边界行程（首行程和末行程）保持不变。选择中间行程中代表行包含最多不同颜色的行程作为弹性行程，将其重复次数调整为 Ih - (范例高度 - 该行程原始重复次数)。
   - 对列做同样操作，选择中间列行程中代表列包含最多不同颜色者作为弹性列行程，调整重复次数以匹配 Iw。
4. 将弹性拉伸后的范例图案填入蓝框内部区域。蓝框边框保留。

**关键洞察**：弹性填充的目标区域不是输入中预先给定的矩形，而是通过连线操作动态构建的。连线结果直接决定拉伸参数——框架越大，范例的弹性行程重复越多。

## 新题 8：镜像平铺重力坍缩与高度着色

**组合逻辑**：[平铺+镜像](交替翻转平铺扩展画布) + [重力下落](非背景像素全部向下坍缩) + [计数+重涂色](按列堆叠高度着色)（创新：对称平铺创造的均匀分布被重力打破，高度信息编码为颜色——从二维图案到一维柱状统计的降维变换）

**来源原语**：平铺(tiling) ← 8d5021e8/10fcaaa3；镜像(reflect) ← 8d5021e8；交替翻转平铺(alternating_reflections_tiling) ← 8d5021e8；重力下落(gravity_drop) ← df9fd884；计数(counting) ← dc2aa30b/e3721c99；重涂色(recolor) ← 1b60fb0c/e26a3af2

**依赖链**：平铺决定像素的空间分布 -> 重力改变像素的垂直位置 -> 每列的堆叠高度决定该列的最终颜色。平铺结果直接影响每列的像素密度，密度又决定重力后的堆叠高度和颜色。

将小图案以镜像方式平铺为 3x2 画布，然后对所有非背景像素施加重力向下坍缩，最后按每列堆叠高度重涂色。

**输入结构**：一个小网格（约 3x4 至 4x5），背景黑(0)，上面有若干蓝(1)像素形成一个简单的非对称图案（3-6 个蓝像素）。生成约束：图案不完全填满任何一列（确保重力有效果）；镜像平铺后至少存在 3 种不同的列堆叠高度（确保着色有区分度）。

**规则**：
1. 构建中间带：将原始输入与其水平翻转副本左右拼接，得到一个高度不变、宽度翻倍的中间带。
2. 将中间带垂直翻转，得到翻转带。
3. 按"翻转带—中间带—翻转带"从上到下堆叠，得到高度三倍、宽度两倍的平铺网格。
4. 对平铺网格施加重力：每一列中所有非黑(0)像素向下坠落到该列的最低可用位置（保持列内相对顺序但消除中间空隙，所有像素紧贴底边）。
5. 对每一列，计算非黑像素的堆叠高度 h（从底部连续非黑像素的数量）。按高度重涂该列的所有非黑像素：h=1 -> 蓝(1)，h=2 -> 红(2)，h=3 -> 绿(3)，h>=4 -> 黄(4)。仍为黑(0)的像素不变。

**关键洞察**：镜像平铺创造了左右对称的像素分布，但重力坍缩将二维对称图案转化为一维柱状高度图。高度到颜色的映射必须从多个示例中归纳——仅看一个示例可能无法区分"高度决定颜色"还是"列位置决定颜色"。

## 新题 9：双尺度遮罩面板叠合

**组合逻辑**：[降采样](粗粒度选择参与叠合的面板) + [掩码裁剪](细粒度选择面板内保留的像素) + [透明叠加+图层优先级](掩码密度决定叠合层序)（创新：同一个单色图案在两个尺度上分别编码不同信息——粗尺度编码面板选择、细尺度编码像素裁剪、密度编码层序——三重角色耦合）

**来源原语**：降采样(downsample) ← 6ecd11f4；掩码裁剪(mask_crop) ← 6ecd11f4；单色图案(mono_pattern) ← 6ecd11f4；整数缩放对应(int_scale_correspond) ← 6ecd11f4；面板(panel) ← bbb1b8b6/281123b4；分隔列(separator_column) ← bbb1b8b6/281123b4；透明叠加(transparent_overlay) ← bbb1b8b6/281123b4；图层优先级(layer_priority) ← 281123b4

**依赖链**：单色图案分为 4 个象限 -> 象限是否非空决定面板取舍（粗尺度） -> 非空象限的具体像素分布决定面板内像素裁剪（细尺度） -> 各象限的非黑像素密度决定叠合优先级。三层信息提取自同一个图案，相互依赖。

一个单色图案的四个象限同时编码三件事：哪些面板参与叠合、面板内哪些像素被保留、以及面板间的叠合层序。

**输入结构**：网格约 12x23，分上下两个区域。上方区域：4 个 5x5 面板从左到右排列，相邻面板之间由 1 列灰(5)分隔列隔开。每个面板内有黑(0)背景和一种唯一前景色（选自蓝(1)、红(2)、绿(3)、黄(4)四色之一），前景色像素形成一个小图案（3-8 像素）。下方区域：一个 10x10 的品红(6)单色图案（品红像素在黑(0)背景上），其四个 5x5 象限分别对应面板 1-4（左上象限 -> 面板 1，右上 -> 面板 2，左下 -> 面板 3，右下 -> 面板 4）。生成约束：至少有 1 个象限完全为黑(0)；参与叠合的面板至少有 2 个；不同象限的非黑像素数互不相同。

**规则**：
1. 将 10x10 单色图案分为 4 个 5x5 象限。每个象限对应一个面板（左上=面板1，右上=面板2，左下=面板3，右下=面板4）。
2. 粗尺度筛选：若某象限完全为黑(0)，对应面板被排除，不参与叠合。
3. 细尺度裁剪：对每个参与的面板，将其对应象限作为二值掩码（品红(6)位置=保留，黑(0)位置=裁剪为透明）。面板中仅掩码为品红的位置保留原前景色像素，其余位置变为透明。
4. 图层排序：统计每个参与象限中品红(6)像素的数量。像素数最少的面板为最前层（最后绘制），像素数最多的面板为最后层（最先绘制）。
5. 将所有参与面板按层序叠合到一个 5x5 的输出网格中：从最后层开始逐层绘制，后层覆盖前层。透明位置不覆盖。
6. 输出中不包含分隔列、单色图案或被排除面板的任何内容。

**关键洞察**：单色图案在三个层次上编码信息——象限是否非空决定面板参与与否，象限内具体像素决定面板裁剪形状，象限像素密度决定叠合优先级。求解者需要意识到同一视觉元素承载了三重角色。

## 新题 10：旋转匹配定向链式延伸

**组合逻辑**：[模板匹配+旋转](碎片与模板的旋转匹配确定匹配角度) + [链式填充](匹配角度编码链延伸方向) + [重建](先补全碎片再延伸)（创新：旋转角度不仅用于几何校正，同时编码链式填充的方向指令——同一参数的双重语义）

**来源原语**：旋转(rotate) ← 6aa20dc0/1b60fb0c；模板匹配(template_match) ← 6aa20dc0；缩放旋转对齐碎片(scale_rotate_align_frag) ← 6aa20dc0；碎片(fragment) ← 6aa20dc0；链式填充(chain_fill) ← 16b78196；重建(rebuild) ← c61be7dc

**依赖链**：碎片匹配确定旋转角度 -> 旋转角度同时用于补全碎片形状和确定链延伸方向 -> 链式填充沿确定方向放置旋转后模板副本。旋转角度承担双重职责，跳过匹配则既无法补全碎片也无法确定方向。

识别每个碎片是多色模板哪个旋转版本的部分残片，补全碎片后沿旋转角度编码的方向链式延伸模板副本直至网格边界。

**输入结构**：网格约 18x18，背景黑(0)。网格一角有一个完整的多色模板（约 3x4 至 4x3，包含 2-3 种非黑颜色，非对称以确保旋转版本可区分）。网格中散布 2-4 个碎片，每个碎片是模板某个旋转版本（0/90/180/270 度）的部分像素子集（保留 40%-70% 的非黑像素，颜色与旋转后模板一致）。碎片之间互不重叠，且与模板不重叠。生成约束：每个碎片仅匹配一个旋转角度（碎片的非黑像素是且仅是该旋转版本的子集）；从每个碎片位置沿编码方向延伸至少能放置 1 个完整副本才到达网格边界。

**规则**：
1. 识别完整模板：包含最多不同颜色的非黑 4-连通对象。
2. 对每个碎片（其余非黑 4-连通对象），尝试模板的 4 个旋转版本（0/90/180/270 度顺时针），找到使碎片的所有非黑像素位置和颜色均为旋转模板对应位置子集的唯一旋转角度。碎片的边界框左上角与旋转模板的边界框左上角对齐进行比较。
3. 旋转角度编码链延伸方向：0 度 -> 向右延伸，90 度 -> 向下延伸，180 度 -> 向左延伸，270 度 -> 向上延伸。
4. 先补全碎片：将碎片位置处的旋转模板完整绘制（补上碎片缺失的像素）。
5. 从补全后的碎片位置开始，沿编码方向链式放置旋转模板的完整副本：下一个副本的边界框紧接前一个副本的边界框（在延伸方向上无间隙相邻）。持续放置直到下一个副本的边界框会超出网格边界时停止。
6. 保持原始模板不变。不同碎片的链互相独立，若链与链之间有重叠，后处理的碎片（按碎片边界框左上角行优先排序，较大者后处理）覆盖先处理的。

**关键洞察**：旋转角度具有双重语义——它既是几何校正参数（用于补全碎片），又是方向指令（决定链延伸方向）。求解者需要意识到这一参数的双重用途，并从多个碎片的不同旋转角度和不同延伸方向中归纳出角度-方向的对应规则。
