## 新题 1：色彩多样性决定延伸射程

**组合逻辑**：[延伸(extend)](创新：延伸距离不再到达画布边界，而由色彩计数动态决定) + [计数(counting)](已有) + [方向指示(direction_indication)](已有) + [颜色数决定高度(color_count_height)](创新：从"高度"泛化为"延伸长度")

**来源原语**：延伸/方向指示/指示像素 ← b527c5c6；计数/颜色数决定高度/多色方块 ← fcc82909；色数决定倍率 ← d4b1c2b1

**依赖链**：指示像素确定延伸方向 → 色彩计数确定延伸距离 → 两者缺一则输出不确定。色彩计数同时受限于方块内的颜色组成，而方块的空间尺寸又决定了延伸带的宽度，三条信息流在同一个对象上交汇。

在每个多色方块上，根据其指示像素的朝向延伸一条色带，色带长度等于方块内非背景色的种数。

**输入结构**：约 15x15 的黑(0)背景网格。散布 3-5 个互不相邻的矩形色块（每块约 2x3 至 3x4 像素），每块内部填有 1-4 种非黑颜色的像素（颜色从蓝(1)、绿(3)、黄(4)、橙(7)、品红(6)中选取，不同块的颜色集合可以不同）。每块的边界上恰好有一个红(2)像素作为指示像素，位于上、下、左、右四边之一。指示像素不计入色彩计数。生成约束：每块的指示侧方向上留有足够空间容纳最大可能延伸长度（4 格）；各块的延伸带互不重叠。

**规则**：
1. 对每个矩形色块，统计其内部（不含红(2)指示像素）的不同非黑颜色种数，记为 K。
2. 从色块的指示像素一侧，沿指示方向向外延伸一条绿(3)色带：色带的宽度等于色块在垂直于延伸方向上的尺寸，色带的长度等于 K 格。
3. 将指示像素本身重涂为黄(4)。
4. 所有原始色块像素（除指示像素外）保持不变。
5. 处理顺序不影响结果（因为生成约束保证延伸带互不重叠）。

**关键洞察**：延伸距离不是固定到边界，而是由方块自身的色彩丰富度编码——同样朝向的方块因内部颜色数不同而产生不同长度的射出带，必须对比多个示例才能归纳出"色种数 = 长度"这一隐蔽规则。

## 新题 2：镜像生成射线源

**组合逻辑**：[镜像(mirror)](已有) → 创造新标记位置 → [射线延伸(ray_cast)](创新：射线源不是预置的，而是镜像操作的产物) + [重涂色(recolor)](已有) + [宽高比决定镜像轴(aspect_ratio_determines_mirror_axis)](已有，但同一属性同时控制射线方向)

**来源原语**：镜像/矩形框架/内部母题/宽高比决定镜像轴 ← 18419cfa；射线延伸/标记像素/重涂色/行对齐 ← 673ef223

**依赖链**：宽高比 → 决定镜像轴 → 镜像产生第二个标记像素 → 两个标记各发射射线 → 射线方向又由同一个镜像轴决定（垂直于镜像轴）。去掉镜像则缺少一半射线源；去掉射线则镜像不改变最终输出的射线部分。

在框架内镜像补全母题，同时用镜像产生的新红色标记像素作为射线源，沿垂直于镜像轴的方向发射绿色射线。

**输入结构**：约 18x18 的黑(0)背景网格。包含 2-3 个蓝(1)单像素宽矩形框架，框架之间互不接触。每个框架的宽高比明显偏向一个方向（宽框的宽 >= 高的 1.5 倍，高框的高 >= 宽的 1.5 倍）。每个框架内部有若干青(8)母题像素和恰好一个红(2)标记像素。母题像素和标记像素全部分布在框架内区域的一半侧（宽框在左半或右半，高框在上半或下半），另一半为黑色空白。生成约束：框架内部至少 5x5；标记像素不在镜像轴上；各框架的射线延伸范围不会触及另一个框架。

**规则**：
1. 对每个蓝(1)矩形框架，计算其内区域的宽高比。宽框（宽 > 高）以内区域的垂直中线为轴做左右镜像；高框（高 > 宽）以内区域的水平中线为轴做上下镜像。
2. 将框架内所有母题像素（含红(2)标记）关于上述轴镜像复制到对侧空白位置，镜像产生的新母题像素为青(8)，镜像产生的新标记像素为红(2)。
3. 从每个红(2)标记像素（原始的和镜像产生的各一个）出发，沿垂直于镜像轴的方向（宽框向上和向下，高框向左和向右）发射绿(3)射线，射线从标记像素的相邻格开始，逐格延伸直到碰到蓝(1)框架壁或其他非黑像素时停止（不覆盖终点像素）。
4. 所有原始红(2)标记像素和镜像产生的红(2)标记像素均重涂为黄(4)。
5. 蓝(1)框架像素和青(8)母题像素保持不变。
6. 多个框架按边界框左上角从左上到右下的顺序依次处理，但由于生成约束保证射线互不干扰，顺序不影响结果。

**关键洞察**：射线源不是输入中预置的固定结构，而是镜像操作的副产品——必须先完成镜像才能确定第二个射线源的位置，而镜像轴同时又控制射线方向，形成单一几何属性（宽高比）驱动两步操作的紧耦合。

## 新题 3：推移建墙、重力落定

**组合逻辑**：[推移(push)](已有) → 形成障碍物 → [滑动/重力沉降(sliding/gravity_settle)](创新：重力作用的障碍布局由前一步推移结果决定) + [碰撞阻挡(collision_blocking)](已有，但跨两阶段复用) + [擦除(erase)](已有)

**来源原语**：推移/固定标记/接触侧决定方向/推至边界停止 ← 5623160b；滑动/前景对象/碰撞阻挡/重力沉降 ← d282b262；擦除 ← 98cf29f8/fbf15a0b

**依赖链**：标记颜色区分两类对象 → 红色对象被推至边界形成新障碍 → 蓝色对象受重力下落时以推移后的红色对象为阻挡 → 最终布局依赖两阶段的交互结果。去掉推移则蓝色对象的落点完全不同；去掉重力则蓝色对象悬浮不动。

先将与栗色标记接触的红色精灵推至边界形成障碍，再让蓝色精灵在重力下沉降，以推移后的红色精灵和网格底边为阻挡。

**输入结构**：约 14x14 的黑(0)背景网格。包含若干栗(9)标记像素（固定不动，1-3 个，散布于网格中下部）。包含 2-3 个红(2)小精灵（每个为 4-连通单色区域，2-5 像素，形状不规则），每个红色精灵的某一侧恰好与一个栗(9)标记像素 4-邻接。另有 2-3 个蓝(1)小精灵（同样为 4-连通单色区域，2-5 像素，形状不规则），蓝色精灵不与任何栗色标记接触。生成约束：每个红色精灵仅在一个基本方向上与栗色标记接触；红色精灵推至边界后不会互相重叠；蓝色精灵下落路径上不存在歧义（每个蓝色精灵在下落过程中整体一起移动，不会被分割）。

**规则**：
1. **推移阶段**：对每个红(2)精灵，确定其与栗(9)标记像素的接触方向（上/下/左/右），将精灵从原位擦除，然后沿接触方向的反方向（即远离标记的方向）整体平移，直到精灵的任一像素触及网格边界或已定位的另一个红色精灵时停止。红色精灵按离目标边界近的优先处理（即沿推移方向距边界像素数最少的先推）。
2. **重力阶段**：对每个蓝(1)精灵，整体向下滑动，每次下移一行，直到精灵的任一像素的正下方为网格底边或一个已固定的对象（推移后的红色精灵、已沉降的蓝色精灵、或栗色标记）时停止。蓝色精灵按边界框底边行号从大到小处理（底部的先沉降）。
3. 栗(9)标记像素在输出中保持原位不变。
4. 所有精灵保持原始形状和颜色，仅位置改变。

**关键洞察**：两类精灵的颜色决定了它们参与哪个阶段——红色被推、蓝色受重力——但这一分类规则在单个示例中可能被误读为"所有对象都做同一种运动"。必须对比包含两种颜色精灵的多个示例，才能发现颜色→阶段的分派规则，以及推移先于重力的执行顺序。

## 新题 4：掩码并集定义印章模板

**组合逻辑**：[像素并集检测](已有) → 识别结果掩码 → [印章覆盖(stamp_overlay)](创新：模板不是直接给定的，而是由并集关系推导出来的) + [形状匹配(shape_matching)](已有) + [重涂色(recolor)](已有)

**来源原语**：像素并集/精灵体/双掩码并集等三 ← fea12743；印章覆盖/形状匹配/空槽位/支撑签名匹配/空位接受印章 ← e5062a87；重涂色 ← ddf7fa4f

**依赖链**：在精灵库中执行并集检测 → 并集结果掩码成为印章模板 → 在支撑图案中寻找匹配的空槽位 → 印章模板填入匹配槽位。去掉并集检测则不知道哪个掩码是模板；去掉印章覆盖则并集检测不改变下方图案。

从六个红色掩码中找出"A 并 B = C"的关系三元组，用 C 的掩码作为印章模板，填入下方灰色图案中形状匹配的空槽位。

**输入结构**：约 20x12 的黑(0)背景网格，由一条灰(5)水平分隔行分为上下两区。上区包含 6 个等大的方形子区域（排列为 3 列 2 行，每个子区域 4x4，子区域间隔 1 列黑色），每个子区域内有一个红(2)像素掩码（非空，1-8 个红色像素，其余为黑色）。恰好存在一组三元组 (A, B, C)，使得 A 的红色像素集合与 B 的红色像素集合的逐像素并集恰好等于 C 的红色像素集合，且 A 和 B 各自至少贡献一个 C 中没有被另一方覆盖的独有像素。下区包含一个灰(5)支撑图案：由灰色像素构成的不规则框架，内部有若干 4x4 的纯黑矩形空槽位，空槽位由灰色像素环绕。部分空槽位的形状（黑色区域内部被灰色像素部分填充后剩余的黑色连通区域的形状）与 C 的掩码形状一致，部分不一致。生成约束：上区的 6 个掩码保证三元组唯一（不存在第二组满足并集关系的三元组）；下区至少有 2 个匹配槽位和 1 个不匹配槽位。

**规则**：
1. 在上区的 6 个 4x4 掩码中，找到唯一的三元组 (A, B, C)，使得 A 和 B 的红色像素并集恰好等于 C 的红色像素。三元组的查找按行优先从左上到右下遍历所有 C(6,2)×4 种组合，取第一个满足条件的。
2. 在上区中，将 A 和 B 的像素重涂为青(8)，将 C 的像素重涂为绿(3)，其余三个掩码保持红(2)不变。
3. 以 C 的掩码形状（4x4 区域内绿色像素的相对位置）作为印章模板。
4. 在下区中，从左上到右下扫描所有 4x4 候选位置。若某位置的黑色区域形状与模板完全匹配（模板中绿色像素的位置对应黑色，其余位置对应灰色），则在该位置将模板对应的黑色像素涂为绿(3)。
5. 灰(5)分隔行和支撑像素保持不变。

**关键洞察**：印章模板并非直接给出，而是隐藏在上区六个掩码的代数关系中——求解者必须先发现并集关系以确定模板，再将该模板用于下区的空间匹配，两步推理缺一不可。

## 新题 5：链式旋转后奇偶变色

**组合逻辑**：[链式连接(chain_linkage)](已有) → [旋转(rotate)](已有) → [列奇偶交替(column_parity_swap)](创新：奇偶交替不作用于整行，而作用于旋转后的水平条内部) + [高度即宽度(height_equals_width)](已有，驱动链式步长和旋转后宽度)

**来源原语**：旋转/竖条/标记条/链式序列/链式连接/高度即宽度 ← 84551f4c；列奇偶交替/奇偶决定交换/棋盘格图案 ← e9afcf9a；重涂色 ← c074846d

**依赖链**：链式连接确定哪些竖条参与变换 → 旋转将竖条变为横条（高度变宽度）→ 横条内部按列奇偶交替填色。去掉链式连接则不知道哪些条参与；去掉旋转则无横条可做奇偶着色；去掉奇偶着色则旋转后所有格同色，失去棋盘效果。

从蓝色标记条出发沿链式规则选取竖条，将选中竖条旋转为横条后，横条内的像素按列奇偶在原色和交换色之间交替。

**输入结构**：约 12x20 的黑(0)背景网格（宽大于高）。底部对齐排列若干 1 格宽的竖条，每条从底边向上延伸不同高度（2-6 格）。竖条有两种颜色：蓝(1)为标记条，红(2)为体条。竖条之间可能有空列。所有竖条底部对齐于网格最底行。生成约束：从每个蓝色标记条出发，按链式规则（下一条的列号 = 当前条的列号 + 当前条的高度）恰好能跳到一个红色体条，链可延续多步但最终终止（下一步跳到的列号处无竖条或超出网格）。未被任何蓝色标记条的链式规则触及的红色竖条保持不变。蓝色标记条自身也参与旋转。

**规则**：
1. 对每个蓝(1)标记条，从其所在列 c 出发，重复执行：下一列号 = c + 当前条高度 h。若该列号处存在一根竖条（无论蓝或红），则将该竖条纳入链中并从该竖条继续；否则链终止。
2. 擦除链中所有竖条的原始像素。
3. 对链中每根竖条（含蓝色标记条自身），从其原始底部单元格开始，向右水平绘制一条长度等于该竖条原始高度的横条。横条内的像素按如下规则着色：设该横条在网格中占据的列号从左到右为 c0, c1, c2, ...，若 ci 为偶数列则填该竖条的原始颜色（蓝(1)或红(2)），若 ci 为奇数列则填交换色（蓝(1)↔红(2)互换）。
4. 未被任何链触及的竖条保持竖直形态和原色不变。
5. 链中多根横条可能在空间上相邻（因链式规则保证下一根横条的起始列紧接上一根横条的末尾列），相邻区域各自独立着色，无覆盖冲突。

**关键洞察**：链式连接的步长规则（"当前高度即下一步跨度"）需从示例中归纳；而旋转后横条内部的奇偶变色规则取决于每格在网格中的绝对列号（非横条内的相对位置），必须对比不同起始列的横条才能发现这是绝对列号奇偶而非相对偏移奇偶。

## 新题 6：连接杆长度索引调色板

**组合逻辑**：[滑动(slide)](已有) + [擦除(erase)](已有) + [重涂色(recolor)](创新：重涂的颜色不由控制像素的列范围决定，而由连接杆的几何长度索引调色板获取) + [计数(counting)](创新：计数对象从方块内色种数变为连接杆的单元格数)

**来源原语**：滑动/擦除/矩形体/连接杆/锚定物/沿杆滑至锚定物 ← 98cf29f8；重涂色/控制色决定填色 ← ddf7fa4f；计数 ← fcc82909；调色板/编码映射 ← 65b59efc

**依赖链**：连接杆长度 → 索引调色板获得目标颜色 → 滑动将矩形体推至锚定物旁 → 矩形体被重涂为目标颜色。连接杆同时编码了三个信息：滑动方向、滑动距离、目标颜色。去掉任何一个环节都无法确定最终输出。

每个矩形体沿连接杆滑至锚定物旁，连接杆被擦除，矩形体被重涂为调色板中第"连接杆长度"个颜色。

**输入结构**：约 16x16 的黑(0)背景网格。顶行为调色板行：从左到右依次排列 4 个单像素色块，颜色各不相同，从蓝(1)、绿(3)、黄(4)、橙(7)、品红(6)中选取，分别占据第 0、1、2、3 列（其余为黑色）。网格中散布 2-4 组"矩形体 + 连接杆 + 锚定物"三元组。每组中：矩形体为红(2)的实心小矩形（2x2 或 2x3 像素）；连接杆为红(2)的 1 格宽直线段，从矩形体的一条边向外延伸，方向为上下左右之一，长度 1-4 格；锚定物为灰(5)的实心矩形（与矩形体等宽或等高，取决于连接方向），位于连接杆的另一端之外紧邻位置。生成约束：各组互不接触；连接杆长度不超过调色板中颜色的个数；每组的连接杆长度至少有两组不同（以便归纳规则）。

**规则**：
1. 对每组三元组，测量连接杆的长度 L（连接杆占据的单元格数，不含矩形体和锚定物本身的像素）。
2. 从调色板行中，取第 L 个颜色（第 0 列为第 1 个，第 1 列为第 2 个，以此类推；即列号 = L-1）。
3. 擦除连接杆和矩形体原始位置的所有像素（设为黑(0)）。
4. 将矩形体沿连接方向平移 L 格（即矩形体恰好移动到锚定物旁边，紧邻锚定物），保持矩形体形状不变。
5. 将平移后的矩形体重涂为步骤 2 中获得的调色板颜色。
6. 锚定物和调色板行保持不变。
7. 各组独立处理，顺序不影响结果（因生成约束保证各组互不接触）。

**关键洞察**：连接杆不仅是一条"路径"，更是一个"索引编码"——其物理长度直接映射到调色板位置，决定矩形体的最终颜色。这一编码规则在单个示例中可能被误读为"矩形体总是变成某种固定颜色"，必须对比不同连接杆长度的示例才能发现长度→调色板索引的映射。

## 新题 7：角落裁剪后色种数放大

**组合逻辑**：[裁剪+拼接(crop+concatenate)](已有) + [像素放大(pixel_upscale)](已有) + [计数(counting)](创新：计数对象从单一 3x3 网格变为跨四个角落的合计色种数) + [角落对应(corner_correspondence)](已有) + [色数决定倍率(color_count_scale)](已有，但计数范围从全局扩展到四角聚合)

**来源原语**：裁剪/拼接/角落图案/角落对应/最小包围框收缩 ← bc1d5164；像素放大/计数/色数决定倍率/色块 ← d4b1c2b1

**依赖链**：角落裁剪确定基础图案 → 四角合计色种数确定放大倍率 → 裁剪结果被按此倍率像素放大。角落的颜色组成同时决定了图案内容和放大系数，一个角落增减一种颜色会同时改变图案和输出尺寸。

将四角图案裁剪拼合为最小方阵，再将该方阵按四角合计的非背景色种数进行像素放大。

**输入结构**：约 14x14 的黑(0)背景网格。四个角各有一组前景像素图案（每组占据一个 3x3 至 5x5 的正方形区域，对齐到对应角落），图案使用的颜色从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7)、青(8)中选取。四个角落区域大小相同（均为 SxS），但内部图案和颜色各异。角落区域之间用黑色分隔。每个角落至少有一个前景像素。生成约束：四角合计的非黑色种数在 2-4 之间（保证输出网格不超过 20x20）；各角落区域等大。

**规则**：
1. 确定四个角落图案的正方形区域边长 S（即四角中前景像素的最大包围正方形边长，若不等则取最大值，对较小的角落在远离角落的方向补黑色至 S×S）。
2. 构建一个 (2S+1) x (2S+1) 的中间网格：左上 SxS 填入左上角图案，右上 SxS 填入右上角图案，左下 SxS 填入左下角图案，右下 SxS 填入右下角图案，中间行和中间列为黑(0)分隔。
3. 统计中间网格中所有不同的非黑颜色种数，记为 K。
4. 将中间网格进行 K 倍像素放大：每个像素替换为一个 KxK 的同色方块。输出网格大小为 K(2S+1) x K(2S+1)。

**关键洞察**：角落图案的颜色承担双重角色——既构成图案内容，又通过总色种数控制输出尺寸。增加一种颜色会让输出在两个维度上同时增长，这种"内容即参数"的自指关系需要对比不同色种数的示例才能发现。

## 新题 8：重叠填充区驱动延伸方向

**组合逻辑**：[填充(fill)](已有) + [延伸(extend)](创新：延伸的起始区域不是矩形块，而是填充操作产生的动态区域) + [连线(draw_line)](已有) + [列投影重叠(column_projection_overlap)](已有) + [较长侧优先(longer_side_priority)](已有，决定填充发生在哪侧) + [方向指示(direction_indication)](创新：指示像素不在原始矩形上，而在填充生成的区域边缘)

**来源原语**：填充/边缘线段/分隔行/列投影重叠/较长侧优先 ← 770cc55f；延伸/连线/指示像素/方向指示/指示侧扩展至边界 ← b527c5c6

**依赖链**：边缘线段的列重叠 → 确定填充列范围 → 较长侧决定填充方向 → 填充区域的某边缘上出现指示像素 → 从填充区域沿指示方向延伸至画布边界。填充区域的形状决定了延伸带的宽度和起始位置，而指示像素的位置又依赖于填充结果。

先根据上下边缘线段的列重叠填充黄色区域，再从填充区域上的绿色指示像素一侧将黄色区域延伸至画布边界。

**输入结构**：约 12x15 的黑(0)背景网格。第 0 行（顶行）有一段连续的蓝(1)水平线段。最底行有一段连续的蓝(1)水平线段。网格中间某行为一整行红(2)分隔行。两段蓝色线段的列范围有部分重叠（重叠至少 2 列）。在其中一段蓝色线段的列范围内（该段较长者的一侧，即分隔行与该段之间的区域的一个角落边缘）放置一个绿(3)指示像素。绿色指示像素位于重叠列范围之内，且在填充将要发生的区域的某一侧边缘（上、下、左、右之一）。生成约束：指示像素不在分隔行上也不在蓝色线段上；指示像素的指示方向上有足够空间延伸至画布边界且不穿过分隔行或蓝色线段。

**规则**：
1. 计算顶行蓝(1)线段和底行蓝(1)线段的列范围交集（重叠列）。
2. 比较两段线段的长度。在较长线段一侧（若顶行线段更长，则在顶行线段与分隔行之间；若底行线段更长，则在分隔行与底行线段之间），将重叠列范围内的所有黑色像素填充为黄(4)，从较长线段的下方（或上方）一行开始，到分隔行的上方（或下方）一行结束。若两段等长，则填充顶行侧。
3. 确定绿(3)指示像素相对于黄(4)填充区域的位置（在填充区域的上边缘、下边缘、左边缘还是右边缘）。
4. 从黄(4)填充区域的指示像素一侧，向指示方向延伸一条黄(4)色带，色带宽度等于填充区域在垂直于延伸方向上的尺寸，色带一直延伸到画布边界（不覆盖蓝色线段、红色分隔行）。若延伸方向上遇到蓝色线段或红色分隔行，色带在其前一格停止。
5. 从绿(3)指示像素出发，沿指示方向画一条绿(3)直线，长度与色带相同，覆盖在色带的对应行或列上。
6. 绿(3)指示像素本身保留。蓝(1)线段、红(2)分隔行保持不变。

**关键洞察**：填充操作的结果不是最终输出，而是延伸操作的"起点结构"——填充区域的几何形状（宽度和位置）直接决定了延伸带的参数。指示像素虽然在输入中就存在，但它的"指示对象"（填充区域）在规则执行前并不存在，形成了空间指示关系跨越时序的非直觉耦合。
