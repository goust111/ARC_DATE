## 新题 1：形状频率门控旋转

**组合逻辑**：[计数/counting + 形状匹配/shape_matching](用形状频率分类产生激活条件) → [旋转/rotate](已有原语，但触发条件由频率分类决定) ↔ [重涂色/recolor](未激活的源像素原地变色)

**来源原语**：旋转/rotate、重涂色/recolor、同行或同列/same_row_or_col、距离保持不变/distance_preserved（来自 1a244afd）；计数/counting、形状匹配/shape_matching、唯一重复形分涂/unique_vs_repeated_recolor（来自 b230c067）；枢轴像素/pivot_pixel、源像素/source_pixel（来自 1a244afd）

**依赖链**：形状频率分类的结果决定哪些枢轴被"激活"；只有与激活枢轴配对的源像素才执行旋转，否则原地变色。频率分析与几何变换之间形成条件分支——删去频率分析则无法判断哪些源做旋转、哪些做变色；删去旋转/变色则频率分析无用。

对散落的小图形做全局形状频率分类，以此决定哪些枢轴被激活，再让与激活枢轴配对的源像素绕枢轴旋转、未激活的原地变色。

**输入结构**：约 15x15 网格，黑(0)背景。包含以下元素：
- 3~5 个蓝(1)孤立像素，作为枢轴。
- 3~5 个品红(6)孤立像素，作为源像素。每个源像素与恰好一个蓝枢轴处于同一行或同一列（输入保证一对一配对，且每对之间无其他前景像素阻隔）。
- 4~6 个绿(3)的小型 4-连通图形（每个 3~6 像素，形状各异但不固定为特定命名形状）。它们散布在网格中，与蓝/品红像素不相邻。在所有示例中，恰好有一个图形的归一化形状（平移不变的边界框掩码）在当前输入中仅出现一次（称为"独特形"），其余图形的归一化形状至少出现两次。

**规则**：
1. 将所有绿(3)图形按归一化边界框掩码分组，找出仅出现一次的独特形。
2. 计算独特形图形的边界框中心坐标 (cr, cc)。
3. 对每个蓝(1)枢轴，判断：枢轴是否与 (cr, cc) 处于同一行或同一列？若是，该枢轴被"激活"。
4. 对每个品红(6)源像素，找到与其同行或同列的唯一蓝枢轴：
   - 若该枢轴已激活：将源像素绕枢轴做 90 度逆时针旋转，在目标位置画橙(7)像素，擦除原品红像素。若目标位置超出网格边界，则该源像素直接消失。
   - 若该枢轴未激活：将源像素原地重涂为红(2)，不做位移。
5. 绿(3)图形和蓝(1)枢轴保持不变。
6. 若旋转后的目标位置与已有非背景像素重合，旋转像素覆盖已有像素。

**关键洞察**：绿色图形的形状频率（独特 vs 重复）决定了哪些枢轴被激活，从而将一个分类计数任务与一个几何旋转任务耦合在一起——两者单独都无法确定输出。

## 新题 2：射线交叉点重力下落

**组合逻辑**：[射线延伸/ray_extend + 连线/draw_line](已有原语) → [交叉检测](创新：源题中射线不会相交，此处多条射线在同一网格中产生交叉) → [重力下落/gravity_drop](交叉点作为新对象下落)

**来源原语**：射线延伸/ray_extend、连线/draw_line、行列对齐/row_col_align、对齐像素投射矩形/aligned_pixel_to_rect（来自 2c608aff）；重力下落/gravity_drop、分隔行/divider_row（来自 84ba50d3）；碰撞停止/collision_stop（来自 2c608aff, 332f06d7）

**依赖链**：射线延伸在网格中画线 → 多条线的交叉点是输入中不存在的涌现对象 → 这些涌现对象再经历重力下落到达最终位置。删去射线步骤则无交叉点；删去重力则交叉点位置不是最终答案。

从对齐像素向矩形发射同色射线，将多条射线的交叉点标记为新像素，再让这些交叉像素重力下落至分隔线上方。

**输入结构**：约 18x18 网格，灰(5)背景。包含以下元素：
- 一个单色矩形（红(2)，约 4x4~6x6），位于网格中上部。
- 4~8 个孤立像素，颜色可为蓝(1)、绿(3)或黄(4)，散布在矩形周围。部分孤立像素与矩形共享行或列（即行或列对齐）。
- 一条橙(7)全宽水平分隔行，位于网格下部（距底部 2~3 行）。
- 输入保证：至少有两条不同颜色的射线路径会在到达矩形前相互交叉（即存在至少一个交叉点）。射线路径上除背景外无其他障碍。

**规则**：
1. 识别灰(5)背景、红(2)矩形、橙(7)分隔行，其余非背景孤立像素为射线源。
2. 对每个与矩形行列对齐的孤立像素，沿其朝向矩形的基数方向画一条同色直线，从像素位置开始，到矩形边界的相邻像素为止（不覆盖矩形本身）。未与矩形对齐的孤立像素不画线。
3. 检测所有射线线段的交叉点：若同一像素位置被两条或以上不同颜色的射线经过，该位置标记为栗(9)像素（覆盖原有射线颜色）。
4. 将所有栗(9)交叉像素清除出原位置，然后逐个做重力下落：每个栗(9)像素从其原行开始垂直向下移动，直到碰到橙(7)分隔行的上一行或碰到另一个已落定的栗(9)像素的上一行，在该位置停止。下落顺序：按列从左到右，同列按原始行从下到上（靠近分隔行的先落）。
5. 射线线段（非交叉点部分）保留在原位。矩形、分隔行、背景、未对齐的孤立像素均不变。

**关键洞察**：交叉点在输入中不存在，是射线延伸的涌现产物；它们的最终位置取决于重力，而非它们在射线上的原始位置。

## 新题 3：边框拉伸收窄通道与交替转向路径

**组合逻辑**：[描边/outline + 拉伸/extrude](已有原语，但作用对象从画布边界变为通道内障碍物) → [路径模拟/path_simulation + 交替转向/alternating_turn](已有原语，但通道几何被拉伸步骤改变) ↔ [碰撞停止/collision_stop](拉伸产生新碰撞面)

**来源原语**：描边/outline、拉伸/extrude、边缘延伸角落留黑/edge_extrude_corner_black（来自 49d1d64f）；路径模拟/path_simulation、交替转向/alternating_turn、碰撞停止/collision_stop、颜色循环/color_cycle（来自 195c6913）；蜿蜒通道/winding_channel（来自 332f06d7）

**依赖链**：障碍物拉伸改变通道的有效宽度和形状 → 粒子路径模拟依赖于碰撞位置（由拉伸后的几何决定） → 交替转向方向在碰撞点切换。删去拉伸则通道未收窄、碰撞位置不同、路径完全改变；删去路径模拟则拉伸无用。

先将通道内的障碍物各向外拉伸一圈（角落留黑），收窄通道，再让粒子在改变后的通道中行进并按交替转向规则拐弯。

**输入结构**：约 20x20 网格，黑(0)背景。包含以下元素：
- 一条蜿蜒通道：由蓝(1)像素构成，宽度 3~5 像素，从网格左侧蜿蜒至右侧，至少有两个直角弯道。
- 通道内部有 2~4 个小型矩形障碍物：红(2)像素构成，每个约 1x1~2x2 像素，位于通道内部但不接触通道壁。障碍物之间互不相邻。
- 一个绿(3)起始标记像素：位于通道的一端（左侧入口处），与通道相邻。
- 一个黄(4) 2x2 终止标记块：位于通道的另一端（右侧出口处）。
- 输入保证：拉伸障碍物后通道仍然连通（至少 1 像素宽可通行），但某些弯道处会变得更窄。

**规则**：
1. 对通道内每个红(2)矩形障碍物，向上下左右各拉伸一个像素（即在障碍物四周各添加一圈红(2)边框），但四个新角落位置保持黑(0)不变。拉伸后若新像素超出通道范围（落在黑色背景上），该像素仍画为红(2)。
2. 从绿(3)标记出发，粒子进入通道，初始方向为从起始标记指向通道的方向（即朝通道内部的唯一基数方向）。
3. 粒子沿当前方向直线行进，逐像素涂色。涂色循环为：绿(3)、黄(4)、橙(7)，按像素步数循环（第 1 步绿、第 2 步黄、第 3 步橙、第 4 步绿……）。粒子涂色覆盖原有通道颜色。
4. 当粒子的下一步将进入非通道像素（黑色背景、红色障碍物、或网格边界）时，发生碰撞：
   - 在当前位置涂栗(9)标记。
   - 转向 90 度。第奇数次碰撞（第 1、3、5……次）向左转（逆时针），第偶数次碰撞（第 2、4、6……次）向右转（顺时针）。
   - 涂色循环不重置，继续从下一个颜色开始。
5. 若转向后的方向也被阻挡（下一步仍为非通道像素），粒子停止，不再移动。
6. 若粒子到达黄(4)终止标记的任一像素位置，粒子停止，该位置涂为栗(9)。
7. 起始标记位置被粒子第一步覆盖。终止标记中未被粒子到达的像素保持黄(4)。

**关键洞察**：障碍物的拉伸不是装饰性的边框——它改变了通道的有效几何，导致碰撞点发生位移，从而改变交替转向的整个序列和最终路径形态。

## 新题 4：精灵宽度门控面板叠加

**组合逻辑**：[重力下落/gravity_drop + 宽度决定行为/width_determines_behavior](已有原语，但行为从"穿透/停靠"变为"选择目标面板") → [透明叠加/transparent_overlay](已有原语，但叠加目标由重力落点决定) + [擦除/erase](移除精灵本身)

**来源原语**：重力下落/gravity_drop、宽度决定行为/width_determines_behavior、穿透与停靠/pass_through_or_stop（来自 84ba50d3）；透明叠加/transparent_overlay、前景不冲突/no_fg_collision、分隔对齐/separator_alignment（来自 e98196ab）；面板/panel（来自 d19f7514）；擦除/erase（来自 f45f5ca7）

**依赖链**：精灵的像素宽度决定它穿过几层分隔行 → 落点所在面板成为叠加的锚定面板 → 其余两个面板的前景并集叠加到锚定面板上。删去宽度判断则不知道选哪个面板；删去叠加则面板选择无用。

一个小精灵按宽度规则穿越分隔行落入三层面板之一，落点所在面板作为底板，其余两层面板的前景掩码叠加合并到底板上。

**输入结构**：约 21x10 网格（高 21，宽 10），黑(0)背景。包含以下元素：
- 三个等高面板（每个高 6 行），由两条灰(5)全宽水平分隔行隔开（分隔行在第 7 行和第 14 行，整体高度 = 6+1+6+1+6 = 20 行，第 21 行为精灵起始区）。实际布局：第 0 行为精灵区，第 1 行为第一条分隔行，第 2-7 行为面板 A，第 8 行为第二条分隔行，第 9-14 行为面板 B，第 15 行为第三条分隔行（可选），第 16-21 行为面板 C。（调整为更合理的布局。）
- 重新布局：第 0 行放置一个小精灵（见下）。第 1 行为灰(5)分隔行。第 2-7 行为面板 A（红(2)前景掩码若干像素）。第 8 行为灰(5)分隔行。第 9-14 行为面板 B（绿(3)前景掩码若干像素）。第 15 行为灰(5)分隔行。第 16-21 行为面板 C（蓝(1)前景掩码若干像素）。
- 第 0 行有一个小型 4-连通精灵，颜色为黄(4)，像素数 2~5，占据第 0 行的部分列。精灵的宽度（边界框列数）为 1、2 或 3。
- 三个面板的前景掩码在对齐后互不冲突（同一局部坐标最多一个面板有前景像素）。
- 输入保证精灵正下方各面板区域无前景像素阻挡。

**规则**：
1. 测量黄(4)精灵的边界框宽度（列数）W。
2. 精灵从第 0 行向下做重力下落：
   - W = 1：精灵穿过所有三条分隔行，落入面板 C（最底层）。落点为面板 C 中精灵所在列的最底行。
   - W = 2：精灵穿过第一条分隔行，被第二条分隔行阻挡，落入面板 B（中层）。精灵的最宽水平段紧贴第二条分隔行上方。
   - W >= 3：精灵被第一条分隔行阻挡，落入面板 A（顶层）。精灵的最宽水平段紧贴第一条分隔行上方。
3. 精灵落入的面板称为"锚定面板"。
4. 将另外两个面板的前景掩码按局部坐标（面板内行列）对齐到锚定面板上，做并集合并：凡有前景的位置都保留该前景颜色。
5. 输出为一个面板大小的网格（6 行 x 原宽），包含锚定面板原有前景 + 另外两个面板叠加的前景。
6. 精灵本身被擦除，不出现在输出中。分隔行不出现在输出中。

**关键洞察**：精灵的像素宽度不是装饰属性——它决定精灵穿越到哪一层，从而选择了哪个面板作为叠加的底板，最终改变了三个掩码的合并方式。

## 新题 5：居中对齐触发轮廓闭合与区域填充

**组合逻辑**：[平移对齐/translate_align](已有原语) → [轮廓围合/contour_enclosure](创新：对齐前轮廓不闭合，对齐后才产生封闭区域) → [填充/flood_fill](已有原语，但待填区域由对齐步骤涌现)

**来源原语**：平移对齐/translate_align、格元内居中/centered_within_cell、标记点阵/marker_lattice、格元/lattice_cell（来自 20981f0e）；填充/flood_fill、轮廓围合/contour_enclosure、封闭背景区域/enclosed_bg_region、小区域被填充/small_regions_filled（来自 753ea09b）；连通分量/connected_component（来自 60b61512, 753ea09b）

**依赖链**：精灵在格元中偏离中心 → 平移到中心后相邻精灵的轮廓片段首尾相接形成闭合轮廓 → 闭合轮廓围出的背景小区域被填充。删去对齐则轮廓不闭合无区域可填；删去填充则对齐效果不可观测。

将散落在格元中偏离中心的轮廓片段精灵居中对齐，使相邻片段拼合为闭合轮廓，再填充轮廓围出的背景区域。

**输入结构**：约 15x15 网格，黑(0)背景。包含以下元素：
- 一个由红(2)孤立像素构成的规则笛卡尔点阵（如 3x3 或 4x4 点阵），相邻标记点间距相等（如每隔 4 列 4 行一个标记点），标记点分布在网格内部。
- 在每个被标记点围出的格元（相邻四个标记点构成的矩形区域）中，有一个绿(3)的小型 4-连通图形（2~5 像素），形状为弧形或直角片段（非完整闭合形状）。每个图形在其格元内偏离中心位置（即图形的边界框中心不与格元中心重合）。
- 若将所有图形平移到各自格元的中心位置，相邻格元的图形片段在格元交界处恰好首尾相接，拼合为闭合的绿(3)轮廓线。
- 输入保证：偏移状态下，任意两个相邻图形不会接触（8-连通意义上不相邻），因此偏移状态下无闭合轮廓。

**规则**：
1. 识别红(2)标记点阵和格元划分。
2. 对每个格元中的绿(3)图形，计算其边界框中心与格元中心的偏移量 (dr, dc)。
3. 将每个图形平移 (-dr, -dc)，使其边界框中心与格元中心重合。平移后图形可能跨越格元边界（即部分像素进入相邻格元区域），这是预期行为。
4. 平移后，将所有绿(3)像素和红(2)标记点视为壁障，对背景(黑(0))做 4-连通区域分割。
5. 找出面积最大的背景连通区域（即网格外围的开放区域），标记为"外部"。
6. 所有非外部的背景连通区域（即被绿色闭合轮廓围出的小区域）填充为黄(4)。
7. 红(2)标记点和绿(3)像素（平移后位置）保持不变。

**关键洞察**：输入中的图形片段看似随意散落，但它们的形状经过设计，使得居中对齐后恰好拼合为闭合轮廓——对齐操作本身创造了填充操作的前提条件。

## 新题 6：旋转编码条带优先级排序与缺口填色

**组合逻辑**：[旋转/rotate + 距离保持不变/distance_preserved](已有原语，但旋转结果用于编码排序键而非视觉变换) → [排序/sorting](已有原语，排序键由旋转步骤产生) → [填充/filling + 按行序分段涂色/color_by_row_order](已有原语，但涂色顺序由排序结果决定)

**来源原语**：旋转/rotate、枢轴像素/pivot_pixel、源像素/source_pixel、同行或同列/same_row_or_col、距离保持不变/distance_preserved（来自 1a244afd）；排序/sorting、条缺口/bar_gap、按行序分段涂色/color_by_row_order（来自 cf133acc）；填充/filling（来自 cf133acc）

**依赖链**：旋转计算出目标位置的行号 → 行号作为排序键给各条带赋予优先级 → 优先级决定缺口处的填色。删去旋转则无排序键；删去排序则缺口颜色无法确定；删去填充则旋转和排序结果不可见。

**输入结构**：约 16x16 网格，黑(0)背景。包含以下元素：

- 与每条条带同色的一对像素：一个蓝(1)枢轴像素和一个与条带同色的源像素，位于网格右侧空白区域。每对中源像素与枢轴处于同一行或同一列。不同条带的枢轴-源对之间互不干扰。（修正：枢轴统一为品红(6)，源像素颜色与对应条带相同，以建立配对关系。）
- 品红(6)枢轴像素 3~5 个，每个与恰好一个源像素在同行或同列。源像素颜色各不相同，与某条条带颜色相同，建立一一对应。
- 输入保证：不同源像素旋转后的目标行号各不相同。

**规则**：
1. 对每个源像素，找到与其同行或同列的品红(6)枢轴，将源像素绕枢轴做 90 度逆时针旋转（保持距离），计算目标位置的行号 R。（目标像素本身不画出，R 仅用于排序。）
2. 通过源像素颜色找到对应的水平条带。将条带按其对应 R 值从小到大排序，得到名次 1, 2, 3, ...。
3. 对每条条带的缺口像素，填入该条带名次对应的颜色：名次 1 填蓝(1)、名次 2 填红(2)、名次 3 填绿(3)、名次 4 填黄(4)、名次 5 填灰(5)。
4. 条带本身颜色不变。品红(6)枢轴和源像素保留在原位不变。
5. 缺口仅有 1 个像素宽，填色后该像素成为名次色，与条带自身颜色可能不同。

**关键洞察**：旋转操作不产生任何视觉变化——它的唯一作用是生成一个隐式行号作为排序键，使得缺口填色顺序依赖于一个不在输入中显式呈现的几何计算结果。

## 新题 7：异或掩码指引滑块路径选择

**组合逻辑**：[异或合成/xor_compositing](已有原语，但产出物从最终输出变为路径标记) → [滑动/slide + 路径搜索/pathfinding](已有原语，但目标由异或结果动态确定) → [碰撞停止/collision_stop + 尺寸约束通行/size_constrains_passage](已有原语)

**来源原语**：异或合成/xor_compositing、半区掩码/half_mask、恰一为前景/exactly_one_foreground（来自 31d5ba1a）；滑动/slide、路径搜索/pathfinding、实心方块/solid_square、蜿蜒通道/winding_channel、尺寸约束通行/size_constrains_passage、碰撞停止/collision_stop（来自 332f06d7）

**依赖链**：两个掩码的异或产生目标标记 → 目标标记的位置决定滑块的移动方向和终点 → 通道宽度约束决定滑块能否到达。删去异或则目标未知；删去滑动则异或结果无用途。这是一种"解码-执行"双阶段结构，解码阶段的输出直接参数化了执行阶段。

先对两个掩码做异或得出目标位置，再让通道中的实心方块沿通道滑向该目标，途中受通道宽度约束。

**输入结构**：约 20x10 网格（高 20，宽 10），黑(0)背景。分为上下两大区域：
- 上半区（第 0-9 行）：等高分为两个子面板，各 5 行。上子面板有绿(3)前景掩码（若干散布像素），下子面板有灰(5)前景掩码（若干散布像素），其余为黑(0)背景。两个掩码的尺寸相同（5 行 x 10 列），可按位置对齐比较。
- 下半区（第 10-19 行）：一条蓝(1)蜿蜒通道（宽度 2~4 像素），从左侧延伸至右侧，至少有两个弯道。通道内有一个红(2) 2x2 实心方块（滑块），位于通道的一端。
- 输入保证：上半区异或后恰好有 1 个前景像素，该像素在下半区对应位置（行号减 10 映射）落在通道上。

**规则**：
1. 对上半区的两个子面板按位置对齐做异或：保留恰好一个子面板有前景的位置，标记为黄(4)。两个都有或都没有的位置保持黑(0)。
2. 将异或结果中的黄(4)像素位置映射到下半区：目标行 = 异或行 + 10，目标列不变。在下半区对应位置放置一个黄(4)目标标记。
3. 红(2)滑块沿蓝(1)通道向黄(4)目标滑动。滑块在通道中沿基数方向移动（每步选择能缩短与目标曼哈顿距离的方向；若有弯道则沿通道走向转弯）。
4. 滑块只能经过通道中完整容纳 2x2 的区段。若某段通道宽度不足 2，滑块无法通过，停在最远可达位置。
5. 若滑块到达目标位置，滑块覆盖黄(4)标记；若被阻挡则停在阻挡点前最后的合法位置。
6. 滑块原始位置填充为蓝(1)（通道色）。
7. 上半区的异或结果（黄色像素替换后的掩码区域）保持输出中显示；下半区显示滑动后的最终状态。

**关键洞察**：滑块的目的地不是直接给定的，而是必须通过两个掩码的对称差异来推断——空间推理和逻辑运算的结果共同确定了物理运动的终点。

## 新题 8：网格压缩与形状稀有度编码

**组合逻辑**：[形状匹配/shape_matching + 计数/counting](已有原语，但跨区域全局比较而非区域内) → [压缩/compress + 每区域折叠单像素/region_to_pixel](已有原语) ← [重涂色/recolor + 唯一重复形分涂/unique_vs_repeated_recolor](创新：不只二分，而是按频率梯度映射多种颜色)

**来源原语**：压缩/compress、分隔线/divider_line、网格分区/grid_partition、每区域折叠单像素/region_to_pixel（来自 780d0b14）；形状匹配/shape_matching、计数/counting、重涂色/recolor、唯一重复形分涂/unique_vs_repeated_recolor（来自 b230c067）；连通分量/connected_component（来自 60b61512, b230c067）

**依赖链**：全局形状匹配建立频率表 → 频率表给每个区域分配稀有度等级 → 稀有度等级决定压缩后像素的颜色。删去形状匹配则无频率信息；删去压缩则无法输出。这是"全局统计 → 局部决策 → 全局输出"的结构。

将网格分区中每个区域的图形做全局形状频率统计，按频率等级映射为不同颜色，再将整个分区网格压缩为每区域一个像素的小网格。

**输入结构**：约 17x17 网格，包含以下元素：
- 黑(0)全宽/全高分隔线将网格分为 3x3 或 4x3 的矩形区域（如每 5 行 5 列一个区域，间隔 1 像素黑色分隔线）。共 9~12 个区域。
- 每个区域内有恰好一个 4-连通的单色图形（颜色统一为灰(5)，3~8 像素），形状各异。区域内其余像素为白/某种背景色（用栗(9)作为区域内背景以区别于黑色分隔线）。
- 在所有区域中，某些图形的归一化形状（平移不变的边界框掩码）出现恰好一次（独特形），某些出现恰好两次（稀有形），某些出现三次或以上（常见形）。
- 输入保证：至少存在三种不同的频率等级。

**规则**：
1. 识别黑(0)分隔线，确定矩形区域的行列布局。
2. 提取每个区域内灰(5)图形的归一化边界框掩码。
3. 跨所有区域统计每种掩码的出现次数。
4. 按频率分级映射颜色：
   - 出现 1 次（独特形）→ 红(2)
   - 出现 2 次（稀有形）→ 黄(4)
   - 出现 3 次或以上（常见形）→ 蓝(1)
5. 输出一个与区域布局同维的小网格（如 3x3 或 4x3），每个像素的颜色为其对应区域的频率等级色。

**关键洞察**：输出颜色不编码任何区域的局部属性（大小、位置、原色），而编码一个只有通过跨区域全局形状比较才能获得的统计量——单独看任何一个区域都无法确定其输出颜色。

## 新题 9：射线方向决定补全朝向与镜像轴

**组合逻辑**：[射线延伸/ray_extend](已有原语) → [补全/completion + 缺失像素异色补/missing_diff_color_fill](已有原语，但补全方式由射线方向参数化) ↔ [镜像/mirror](创新：射线入射方向决定镜像轴)

**来源原语**：射线延伸/ray_extend、行列对齐/row_col_align、对齐像素投射矩形/aligned_pixel_to_rect（来自 2c608aff）；补全/completion、缺失像素异色补/missing_diff_color_fill、包围盒内部/inside_bbox（来自 60b61512）；镜像/mirror、交替翻转/alternating_flip（来自 eb281b96）；矩形/rectangle（来自 2c608aff）

**依赖链**：射线从孤立像素出发命中不完整图形的边界框 → 射线的入射方向（水平/垂直）同时决定两件事：(a) 补全后图形的填充色取射线颜色，(b) 补全后图形沿射线方向做镜像翻转。这三步不可分：无射线则不知道补全色和镜像轴；无补全则镜像无完整对象可操作；无镜像则射线方向的信息未被利用。

孤立像素向大矩形发射同色射线，射线经过不完整小图形时，用射线颜色补全该图形的缺失像素，并根据射线是水平还是垂直对补全后的图形做相应轴的镜像。

**输入结构**：约 18x18 网格，灰(5)背景。包含以下元素：
- 一个大型单色矩形（栗(9)，约 4x4~6x6），位于网格中央偏上。
- 3~5 个不完整的黄(4)小图形：每个 4-连通，占据一个 3x3 边界框的部分像素（2~6 个黄色像素，其余为灰色背景），散布在矩形周围。
- 3~5 个孤立像素，颜色为蓝(1)、红(2)或绿(3)（各不相同），部分与矩形行列对齐。
- 输入保证：每个与矩形对齐的孤立像素到矩形的射线路径上恰好经过一个不完整黄色图形的边界框。未与矩形对齐的孤立像素不产生射线，保持不变。

**规则**：
1. 识别灰(5)背景、栗(9)矩形、黄(4)不完整图形、其余孤立像素。
2. 对每个与矩形行或列对齐的孤立像素，从该像素向矩形方向发射同色射线（不覆盖矩形本身，到矩形边界前一格停止）。
3. 当射线经过某个黄色图形的 3x3 边界框时：
   a. 将该边界框内的缺失像素（灰色位置）填充为射线的颜色（而非橙色）。
   b. 判断射线方向：
      - 若射线为水平方向（左→右 或 右→左）：将补全后的 3x3 图形沿垂直中心列做左右镜像。
      - 若射线为垂直方向（上→下 或 下→上）：将补全后的 3x3 图形沿水平中心行做上下镜像。
   c. 镜像操作仅影响该 3x3 边界框内的像素（黄色原有像素 + 新填充像素都参与镜像）。
4. 射线线段本身（边界框外的部分）以射线颜色画出，保留在输出中。
5. 未被射线经过的黄色图形保持不变（不补全、不镜像）。
6. 若同一图形被两条射线经过（一条水平一条垂直），先执行水平射线的补全+镜像，再执行垂直射线的补全+镜像（等价于做 180 度旋转）。

**关键洞察**：射线的几何方向不只是路径属性——它编码了补全后图形的对称变换指令，使得同一个不完整图形在水平射线和垂直射线作用下产生不同的输出形态。

## 新题 10：东南支撑滑移后并集叠加

**组合逻辑**：[滑动/slide + 有后续像素则移/shift_if_pixel_beyond](已有原语，每个对象独立做东南支撑滑移) → [透明叠加/transparent_overlay + 并集取前景/union_foreground](创新：叠加对象不是面板而是滑移前后的同一对象的两个版本)

**来源原语**：滑动/slide、有后续像素则移/shift_if_pixel_beyond、支撑/support、前景对象/fg_object、轮廓边界/contour_bound（来自 025d127b）；透明叠加/transparent_overlay、并集取前景/union_foreground（来自 d19f7514）；重涂色/recolor（来自多题）

**依赖链**：东南支撑规则决定哪些像素移动、哪些不动 → 移动后的对象与原始对象在不同位置产生部分重叠 → 两个版本做并集叠加时，重叠区域和非重叠区域的涂色规则不同。删去滑移则无位移版本；删去叠加则滑移前版本丢失。

对每个对象按东南支撑规则滑移一步，然后将原始位置和滑移后位置的并集输出：仅原始位置有的像素涂为一种颜色，仅滑移后位置有的像素涂为另一种颜色，两者重叠的位置涂为第三种颜色。

**输入结构**：约 12x12 网格，黑(0)背景。包含以下元素：
- 2~3 个同色 4-连通对象，颜色为灰(5)，每个对象 5~10 像素，形状不规则（非矩形），互不相邻（8-连通意义上）。每个对象包含至少一个像素在其右下方（东南方向）有同对象的其他像素，也包含至少一个像素在其右下方没有同对象像素（即东南前沿像素）。
- 输入保证：各对象滑移后互不重叠，且不超出网格边界。

**规则**：
1. 对每个灰(5)对象，记录其原始像素位置集合 S_orig。
2. 按东南支撑规则计算滑移后位置：对对象中每个像素 (r,c)，若对象中存在另一个像素 (r',c') 满足 r' > r 且 c' > c，则 (r,c) 右移一列到 (r, c+1)；否则 (r,c) 不动。记录滑移后像素位置集合 S_shift。
3. 对每个对象，计算三个不相交子集：
   - A = S_orig - S_shift（仅在原始位置出现）→ 涂蓝(1)
   - B = S_shift - S_orig（仅在滑移后位置出现）→ 涂红(2)
   - C = S_orig ∩ S_shift（两个版本重叠）→ 涂黄(4)
4. 在输出网格上画出所有对象的 A、B、C 像素。不同对象之间保证无像素位置冲突。
5. 背景保持黑(0)。

**关键洞察**：并集叠加不是发生在两个空间分离的面板之间，而是发生在同一个对象的"移动前"和"移动后"两个版本之间——重叠像素揭示了对象的不动核心，非重叠像素揭示了运动的方向和范围。
