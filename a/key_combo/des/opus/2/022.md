## 新题 1：拓扑围栏门控双编码表

**组合逻辑**：[洪泛填充/flood_fill](用于内外分区) + [计数/counting](条形段长度测量) + [重涂色/recolor](双表门控编码) — 洪泛填充的分区结果决定每根条形段使用哪张编码表，形成拓扑→编码的门控关系

**来源原语**：洪泛填充/flood_fill、内外分区/in_out_partition、边界连通分内外/border_in_out（参考题 7b6016b9）；计数/counting、条形段/bar_segment、长度映射颜色/length_maps_color、固定编码表/fixed_encoding（参考题 e048c9ed）；重涂色/recolor（参考题 37d3e8b2）

**依赖链**：线条对象将网格分为内外区域 → 洪泛填充确定每根灰色条形段位于内部还是外部 → 内外分类选择对应的长度→颜色编码表 → 条形段按自身长度在所选编码表中查找目标颜色 → 重涂色。删除分区步骤则无法确定编码表，删除长度测量则无法确定颜色。

根据线条对象的内外分区，为不同区域的灰色条形段应用不同的长度→颜色编码表。

**输入结构**：约 14x14 网格，黑(0) 背景。一个绿(3) 4-连通正交线条对象横贯网格，其轮廓闭合形成至少一个封闭区域（也可能形成两个），线条对象的像素总数约 20-35。网格中散布 5-8 根灰(5) 水平条形段，每根长度在 2-5 像素之间，条形段为连续水平排列的灰(5) 像素，4-连通且不与线条对象相邻（间隔至少 1 个背景像素）。部分条形段位于线条对象围成的封闭区域内部，其余位于外部。每个封闭区域内至少有一根条形段，外部至少有一根。不同长度的条形段在内外区域均有出现。生成约束：条形段之间互不相邻，条形段不与线条对象的像素 4-邻接。

**规则**：
1. 保留绿(3) 线条对象不变。
2. 将线条对象视为墙壁，从网格四条边界出发做 4-连通洪泛填充：所有从边界可达的背景像素归为"外部"；不可达的背景像素归为"内部"。
3. 对每根灰(5) 条形段，判断其所有像素所在区域（保证同一条形段的像素全部位于同一区域）。
4. 外部条形段按长度重涂色：长度 2 → 蓝(1)，长度 3 → 红(2)，长度 4 → 黄(4)，长度 5 → 橙(7)。
5. 内部条形段按长度重涂色：长度 2 → 青(8)，长度 3 → 品红(6)，长度 4 → 栗(9)，长度 5 → 蓝(1)。
6. 背景像素保持黑(0)，不做内外着色。

**关键洞察**：相同长度的条形段可能被涂成完全不同的颜色——决定因素不是条形段自身的任何属性，而是它所在的拓扑区域。求解者必须先发现线条对象的围栏作用，再发现存在两张独立的编码表，最后对比多个示例归纳出每张表的具体映射。

## 新题 2：循环位移恢复周期性后补全壁纸

**组合逻辑**：[循环位移/cyclic_roll](由控制列编码偏移量) → [周期推断/period_inference](在对齐后的网格上发现瓦片周期) → [补全/completion](用推断出的瓦片填补缺损像素) — 不执行循环位移则周期不可检测，三步紧密耦合

**来源原语**：循环位移/cyclic_roll、控制列/control_column、标记像素/marker_pixel、标记位定位移量/marker_is_shift（参考题 6d1d5c90）；周期推断/period_inference、重复瓦片/repeating_tile、周期相位对应/periodic_phase_match、非缺损像素一致性/non_corrupted_consistency（参考题 c663677b）；补全/completion、缺损像素/corrupted_pixel（参考题 c663677b/484b58aa）

**依赖链**：控制列中红色标记的行坐标 r 编码了位移量 → 删除控制列后将剩余网格向上循环位移 r 行以恢复原始周期排列 → 在对齐后的网格上推断最小重复瓦片（行周期 × 列周期） → 用瓦片相位对应关系将黑(0) 缺损像素替换为正确颜色。跳过位移则非黑像素之间的相位不一致、无法发现有效周期；跳过周期推断则不知道填什么颜色。

读取控制列的行位移量，将错位的周期壁纸循环回正，然后推断瓦片周期并补全被破坏的像素。

**输入结构**：约 12x14 网格（含控制列共 14 列）。最左列为品红(6) 控制列，其中恰好一个像素为红(2)（标记），其余为品红(6)。右侧 13 列包含一张本应重复的彩色壁纸：原始瓦片尺寸约为 3x3 或 4x3，使用 3-4 种非黑颜色（如蓝(1)、黄(4)、绿(3)、橙(7)），但该壁纸在被破坏前已被整体向下循环位移了 r 行（r 为标记像素的行索引，0-indexed）。位移后的壁纸中约 15%-25% 的像素被替换为黑(0)，这些黑像素即为缺损。非黑像素的颜色是正确的（符合位移后的瓦片相位）。每个瓦片相位在位移后的网格中至少有一个非黑代表。生成约束：r >= 1 且 r 不等于瓦片行周期的整数倍（否则位移等于没移）。

**规则**：
1. 读取控制列中红(2) 标记像素的行索引 r（从 0 开始计数）。
2. 删除最左列（控制列），网格宽度减 1。
3. 将剩余网格向上循环位移 r 行：原来第 i 行移到第 (i - r) mod H 行，其中 H 为网格高度。
4. 在对齐后的网格上，寻找最小的行周期 pr 和列周期 pc，使得所有非黑像素在模 (pr, pc) 相位上颜色一致且无矛盾。
5. 从一致的非黑像素中还原出完整的 pr x pc 瓦片。
6. 将网格中每个黑(0) 像素替换为其 (row mod pr, col mod pc) 相位在瓦片中对应的颜色。
7. 输出补全后的无控制列网格。

**关键洞察**：壁纸在破坏前被偷偷位移过，导致直接做周期推断时非黑像素之间出现相位冲突、找不到小瓦片。控制列中的标记不只是一个要删掉的附属结构——它编码了恢复周期性的关键空间变换参数。

## 新题 3：对称性测试门控格点腔室的填充与擦除

**组合逻辑**：[筛选/filter](对称性检测) ⊕ [填充/fill | 擦除/erase](二元门控决策) — 对称性检测结果不是输出一个筛选后的子集，而是对每个腔室做"填充 vs 擦除"的分叉决策；筛选结果与腔室空间结构交织

**来源原语**：筛选/filter、对称性筛选目标/symmetry_filter、精灵体/sprite、干扰体/distractor（参考题 72ca375d）；填充/fill、擦除/erase、格点骨架/lattice_frame、封闭腔室/enclosed_cavity、标记指定腔室/marker_designates_cavity（参考题 17b866bd）；形状匹配/shape_match（参考题 72322fa7）

**依赖链**：格点骨架定义腔室边界 → 提取每个腔室中的精灵体 → 对每个精灵体做对称性测试 → 对称：用精灵体颜色填满整个腔室；不对称：擦除精灵体、腔室清空为背景色。对称性测试与腔室填充是门控关系，不是简单的筛选-输出。

检测格点腔室中每个精灵体的对称性：对称者扩展填满腔室，不对称者被清除。

**输入结构**：约 16x16 网格，黑(0) 背景。一个青(8) 格点骨架将网格划分为规则排列的封闭腔室（如 3x3 的腔室阵列，每个腔室内部为 3x3 的黑色空间）。格点骨架为一像素宽的青色十字线网格。每个腔室内部恰好包含一个单色精灵体（4-连通，3-6 像素），颜色从红(2)、蓝(1)、黄(4)、绿(3)、橙(7) 中取，同一颜色可出现在多个腔室。精灵体在腔室内部的位置不固定（不一定居中）。部分精灵体关于其边界框的某条轴具有反射对称或 180 度旋转对称；其余精灵体无任何对称性。生成约束：至少 3 个腔室含对称精灵体，至少 3 个腔室含不对称精灵体；同一颜色的精灵体可能有的对称有的不对称，以防止求解者按颜色猜测规则。

**规则**：
1. 识别青(8) 格点骨架划分出的所有封闭腔室。
2. 对每个腔室，提取其中的精灵体并裁剪到最小边界框。
3. 对每个精灵体的边界框检测以下对称性（至少满足一项即视为"对称"）：垂直轴反射、水平轴反射、180 度旋转对称。
4. 对称腔室：将腔室内部所有像素（原来的背景像素和精灵体像素）统一填充为该精灵体的颜色。
5. 不对称腔室：将腔室内部所有像素清除为黑(0)（擦除精灵体）。
6. 青(8) 格点骨架保持不变。

**关键洞察**：精灵体的几何对称性——而非其颜色、大小或位置——决定了腔室的命运。同一颜色的精灵体在不同腔室中可能一个被填充一个被擦除，因为形状不同。求解者必须对比多个示例才能排除颜色假设、聚焦到对称性条件。

## 新题 4：标记像素奇偶投票控制菱形轮廓的收缩与膨胀

**组合逻辑**：[计数/counting](标记像素归属与奇偶判定) → [收缩/shrink | 膨胀/dilate](条件分支) — 计数结果的奇偶性在菱形与标记之间建立了一个源题中不存在的门控关系：同一种操作（半径调整）的方向由内容物的统计性质决定

**来源原语**：收缩/shrink、膨胀/dilate、菱形轮廓/diamond_outline、半径微调/radius_adjust、颜色决定操作/color_det_operation（参考题 d753a70b）；计数/counting、投票/vote、标记像素/marker_pixel、标记归属区域/marker_in_region、最多标记区胜出/max_marker_wins（参考题 de1cd16c）；擦除/erase（参考题 17b866bd）

**依赖链**：识别每个菱形轮廓的中心和半径 → 计算每个菱形内部的栗色标记像素数量 → 判断奇偶性 → 偶数（含 0）：膨胀半径 +1；奇数：收缩半径 -1 → 清除所有标记像素。删除计数步骤则不知道收缩还是膨胀；删除菱形识别则不知道标记归属哪个菱形。

统计每个菱形轮廓内部标记像素的数量，偶数则膨胀、奇数则收缩，标记像素本身消失。

**输入结构**：16x16 橙(7) 背景网格。3-5 个一像素宽的曼哈顿菱形轮廓，颜色各不相同，从红(2)、蓝(1)、绿(3)、灰(5) 中取。每个菱形的半径在 2-5 之间（半径定义为从中心到顶点的曼哈顿距离）。菱形互不重叠，互不相邻。每个菱形内部散布 0-4 个栗(9) 标记像素，这些标记像素位于菱形轮廓严格内部（不在轮廓线上），且互不 4-邻接。生成约束：至少一个菱形内部标记数量为偶数（含 0），至少一个为奇数；半径为 2 的菱形内部标记数量不为奇数（避免收缩后半径变为 1 以下——或者，半径收缩到 0 时菱形消失，只保留中心像素）。被网格边界裁切的菱形不出现在本题中。

**规则**：
1. 识别每个菱形轮廓，确定其中心坐标 (cr, cc) 和半径 R（轮廓像素满足 |r - cr| + |c - cc| = R）。
2. 计算每个菱形严格内部（|r - cr| + |c - cc| < R）的栗(9) 标记像素数量 n。
3. 若 n 为偶数（含 0）：擦除原轮廓，以相同中心和颜色重绘半径为 R+1 的菱形轮廓。
4. 若 n 为奇数：擦除原轮廓，以相同中心和颜色重绘半径为 R-1 的菱形轮廓。若 R-1 = 0，则仅在中心像素处画一个该颜色的点。
5. 删除所有栗(9) 标记像素（设为橙(7) 背景色）。
6. 橙(7) 背景保持不变。

**关键洞察**：标记像素在输出中完全消失，它们的唯一作用是通过数量的奇偶性控制菱形的变换方向。求解者必须先发现标记与菱形的归属关系，再发现关键不在于数量的大小而在于其奇偶性——这是一条需要对比多个示例才能归纳的隐蔽规则。

## 新题 5：锚点连线的边数决定格点腔室填充色

**组合逻辑**：[连线/connect](锚点间连接) → [计数/counting](每个腔室被连线围绕的边数) → [填充/fill](边数映射颜色) — 连线拓扑结构决定了每个腔室的"被围程度"，这一空间统计量编码了填充颜色，三步中任何一步都无法跳过

**来源原语**：连线/connect、空心十字标记/hollow_plus_marker、同行同列对齐/same_row_column_alignment、仅相邻锚点间连接/connect_only_between_adjacent_anchors（参考题 60a26a3e）；计数/counting（参考题 e048c9ed/de1cd16c）；填充/fill、格点骨架/lattice_frame、封闭腔室/enclosed_cavity（参考题 17b866bd）；固定编码表/fixed_encoding（参考题 e048c9ed）

**依赖链**：识别格点交叉点处的空心十字标记 → 在同行/同列相邻的标记对之间画蓝色连线 → 对每个腔室，计算其四条边中有几条边上存在蓝色连线段 → 按边数查表填充腔室颜色。删除连线步骤则不知道哪些边被覆盖；删除计数则不知道填什么颜色。

在格点交叉点的空心标记之间画连线，然后统计每个腔室有几条边被连线覆盖，由此决定腔室的填充颜色。

**输入结构**：约 17x17 网格，黑(0) 背景。一个灰(5) 格点骨架形成规则的腔室阵列（如 3x3 共 9 个腔室），格点线宽 1 像素。格点骨架的交叉节点（十字线交汇处）共 (m+1)x(n+1) 个（如 4x4 = 16 个节点）。其中 4-8 个节点处放置红(2) 空心十字标记：每个标记为 3x3 区域，仅北、南、东、西四个臂像素存在（中心和四角为背景），标记中心恰好位于格点交叉点上。标记之间可能在同一行或同一列上对齐。腔室内部为黑(0) 背景，无其他前景像素。生成约束：至少存在一对同行或同列相邻的标记之间没有其他标记阻隔；腔室的四边被连线覆盖的边数在 0-4 之间均有出现。

**规则**：
1. 识别所有红(2) 空心十字标记，提取其中心坐标作为锚点。
2. 对同一行上的锚点按列坐标排序，对每对相邻锚点（中间无其他锚点），将两个标记之间的灰(5) 格点线上的背景像素涂为蓝(1)（不覆盖标记本身的红色像素和格点骨架的灰色像素，仅填充格点线段上原本为背景色的间隙）。
3. 对同一列上的锚点按行坐标排序，同样处理。
4. 对每个腔室，检查其上、下、左、右四条边界格点线段上是否存在蓝(1) 连线像素。一条边上有至少一个蓝色像素则计为"被覆盖"。统计被覆盖的边数 k（0 <= k <= 4）。
5. 按边数填充腔室内部所有黑(0) 像素：k=0 → 保持黑(0)（不填充），k=1 → 黄(4)，k=2 → 绿(3)，k=3 → 青(8)，k=4 → 品红(6)。
6. 格点骨架（灰色）、标记（红色）和连线（蓝色）均保留。

**关键洞察**：连线不是装饰——它们定义了每个腔室的"被围绕程度"。标记的位置决定了哪些边被连线覆盖，而这一拓扑信息（而非标记的数量或颜色）才是腔室填充色的编码来源。求解者需要先理解连线机制，再发现"边数→颜色"映射。

## 新题 6：重力沉降重新分配前景对象到条纹传播的覆盖范围

**组合逻辑**：[滑动/sliding](重力沉降) → [条纹传播/stripe_propagation](颜色循环叠加) → [重涂色/recolor](绿条纹行上的前景像素全行变色) — 重力改变了对象的行分布，条纹的周期位置是固定的，两者在空间上的交集决定了哪些对象被变色，形成空间耦合而非信息传递

**来源原语**：滑动/sliding、列内独立/column_independent、重力沉降/gravity_settling（参考题 1e0a9b12）；条纹传播/stripe_propagation、边界线段/border_segment、颜色循环/color_cycle、条纹范围差异/stripe_scope_difference（参考题 221dfab4）；重涂色/recolor、前景对象/foreground_object（参考题 37d3e8b2）

**依赖链**：前景像素按列独立下落 → 条纹从边界线段向对面边缘按固定周期传播（黄、黄、绿循环） → 黄色条纹仅在线段列跨度内绘制在背景上 → 绿色条纹将该行上所有非背景像素（包括沉降后的前景像素）重涂为绿色。重力决定了哪些前景像素落在绿条纹行上，从而决定了哪些被重涂。

前景像素先因重力下落，然后条纹从上边界传播；落在绿色条纹行上的对象像素被重涂为绿色。

**输入结构**：约 14x14 网格，黑(0) 背景。3-5 个红(2) 小前景对象（每个 3-8 像素，4-连通，形状不规则），散布在网格中上部的不同位置。一段 3-4 像素宽的黄(4) 线段位于网格顶部边界（第 0 行），占据连续的几列。前景对象与黄色线段不重叠、不在同一行。生成约束：重力沉降后，至少一个前景对象的部分像素落在绿色条纹对应的行上，至少一个前景对象完全不在任何绿色条纹行上；条纹从第 0 行向下传播，周期为 3（条纹行、间隔行、条纹行、间隔行...），颜色按黄(4)、黄(4)、绿(3) 循环，即第 0 行为黄、第 2 行为黄、第 4 行为绿、第 6 行为黄、第 8 行为黄、第 10 行为绿...

**规则**：
1. 黄(4) 边界线段固定不动。
2. 对所有红(2) 前景像素按列独立施加重力：每个红色像素在其列内向下滑动，直到碰到网格底边或另一个非背景像素为止。滑动后像素保持红(2)。
3. 从黄(4) 边界线段所在行（第 0 行）开始，向下每隔 1 行放置一条条纹（即条纹在第 0, 2, 4, 6, 8, 10... 行），每条条纹 1 像素高，条纹之间间隔 1 行（第 1, 3, 5... 行无条纹）。
4. 条纹颜色按黄(4)、黄(4)、绿(3) 的 3 周期循环：第 0 行条纹为黄，第 2 行为黄，第 4 行为绿，第 6 行为黄，第 8 行为黄，第 10 行为绿，以此类推。
5. 黄色条纹：仅在边界线段的列跨度范围内，将该行的背景像素涂为黄(4)。不覆盖已有的红(2) 像素。
6. 绿色条纹：将该行上所有非背景像素（无论列位置）重涂为绿(3)，同时在线段列跨度范围内将背景像素涂为绿(3)。
7. 不在任何条纹行上的红(2) 像素保持红色。

**关键洞察**：重力和条纹传播是两个独立的空间过程，但它们在行坐标上产生耦合：重力决定了前景像素的最终行位置，条纹的周期模式决定了哪些行是"绿色重涂行"。在输入中看起来远离条纹区域的对象，可能在沉降后恰好落入绿色条纹行，被意外地变为绿色。

## 新题 7：模板补全揭示中心色用于边框侧面匹配与迁移

**组合逻辑**：[补全/completion](从完整图案推断缺失部分) → [移动/move](由颜色匹配边决定目标位置) — 补全操作不仅修复了图案外观，更揭示了中心像素的颜色，而该颜色恰是决定移动目标的关键信息；补全的输出是移动规则的触发条件

**来源原语**：补全/completion、对称图案/symmetric_motif、模板精灵体/template_sprite、完整图案推断缺失/motif_infers_missing、形状匹配/shape_match（参考题 72322fa7）；移动/move、擦除/erase、边框/frame、颜色匹配边/color_matches_side、颜色决定目标边/color_determines_side（参考题 d687bc17）

**依赖链**：从完整的 3x3 图案学习"中心色 → 外壳色 + 外壳掩码"的模板 → 对每个仅有外壳的残缺图案，用模板推断其缺失的中心色 → 中心色与矩形边框的四条边颜色匹配 → 将补全后的图案从原位清除，迁移到匹配边框侧的内侧位置。如果不做补全，仅有外壳的图案的中心色未知，就无法确定移动目标。

补全残缺图案以揭示中心颜色，再将图案迁移到与该中心颜色对应的边框侧面内侧。

**输入结构**：约 13x13 网格，黑(0) 背景。一个一像素宽的矩形边框，四条边颜色不同：上边红(2)、下边蓝(1)、左边绿(3)、右边黄(4)，四个角落为黑(0)。边框内部（背景区域）散布以下元素：
- 1-2 个完整的 3x3 图案：中心像素为某颜色 C，周围按固定掩码分布的外壳像素为另一颜色 S（例如中心红(2) + 上下左右四臂橙(7)）。这些完整图案是模板示范。
- 2-4 个残缺图案：仅有外壳部分（与完整图案的外壳形状和颜色一致），中心像素缺失（为黑(0)）。根据外壳颜色 S 可以唯一确定中心色 C。
- 不同的外壳颜色对应不同的中心色，每种中心色恰好匹配边框的一条边。
生成约束：每个残缺图案的外壳颜色在完整图案中都有对应模板；不同残缺图案可能匹配相同的边框侧（此时按它们在边框内的位置从左上到右下的顺序排列放置，间隔 1 像素）；残缺图案之间互不相邻。

**规则**：
1. 扫描边框内部，找到所有完整的 3x3 图案（中心非黑且外壳完整），记录模板：外壳颜色 S → (中心色 C, 外壳掩码偏移集合)。
2. 对每个残缺图案（外壳存在但中心为黑(0)），根据其外壳颜色 S 查找模板，推断中心色 C，将中心像素填充为 C。
3. 确定每个已补全图案的中心色 C 对应边框的哪条边（红(2)→上边，蓝(1)→下边，绿(3)→左边，黄(4)→右边）。
4. 从原位清除该图案的所有像素（设为黑(0)）。
5. 将图案整体移动到目标边内侧：
   - 匹配上边或下边：图案的行坐标变为边框内侧第一行（上边）或最后一行（下边），列坐标保持原值。
   - 匹配左边或右边：图案的列坐标变为边框内侧第一列（左边）或最后一列（右边），行坐标保持原值。
6. 若多个图案移向同一边，按原位置从左上到右下（先按行再按列）排序放置，沿该边方向依次排列，图案之间间隔 1 像素。先放置的不被后放置的覆盖。
7. 完整图案（模板示范）在输出中保持原位不动。

**关键洞察**：残缺图案的外壳是可见的，但中心色是隐藏的。补全操作不仅仅是"修复外观"——它揭示了控制迁移目标的颜色编码。不做补全就不知道往哪条边移动；不知道边框颜色规则就无法理解补全后的颜色有何含义。

## 新题 8：对称性筛选精灵体与位置编码面板汇聚决定放置

**组合逻辑**：[筛选/filter](对称性选择目标) ⊕ [裁剪/crop](提取精灵体) ⊕ [放置/place](位置编码面板决定坐标) — 三个独立信息源（多个精灵体中哪个对称、对称精灵体的形状、编码面板的位置信号）汇聚到一个输出决策；不是流水线而是多源收敛结构

**来源原语**：筛选/filter、对称性筛选目标/symmetry_filter、精灵体/sprite、干扰体/distractor、裁剪/crop（参考题 72ca375d）；放置/place、标记编码位置/marker_encodes_position、锚点对齐/anchor_alignment（参考题 a32d8b75）；标记像素/marker_pixel（参考题 d687bc17）

**依赖链**：网格中有多个精灵体和一个位置编码面板。求解者需要同时解决两个子问题：(1) 哪个精灵体是目标？——通过对称性测试筛选；(2) 目标放在哪里？——通过编码面板中标记像素的位置解码。两个子问题的答案在放置操作中汇合。删除对称性筛选则不知道放什么；删除位置编码则不知道放哪里。

在多个精灵体中找到唯一对称的那个，裁剪后放置到位置编码面板指定的网格坐标处。

**输入结构**：约 15x15 网格，黑(0) 背景。网格主区域（约 12x12）散布 3-5 个单色精灵体，每个精灵体 4-8 像素、4-连通，颜色各不相同（从红(2)、蓝(1)、绿(3)、橙(7)、品红(6) 中取）。恰好一个精灵体关于其边界框具有某种对称性（垂直反射、水平反射或 180 度旋转），其余均为不对称的干扰体。网格右下角（或右上角等固定位置）有一个 5x5 的灰(5) 边框面板（外圈 1 像素宽灰色边框，内部 3x3 区域为黑(0) 背景）。该 3x3 内部恰有一个像素为栗(9)，其在 3x3 格中的位置编码了放置对齐方式。生成约束：精灵体互不相邻且不与面板相邻；对称精灵体的边界框不超过 4x4；面板位置固定（所有示例中面板都在同一角落）。

**规则**：
1. 识别所有精灵体（4-连通非黑非灰前景连通分量），裁剪到最小边界框。
2. 对每个精灵体测试对称性（垂直反射、水平反射、180 度旋转），选出唯一通过测试的精灵体作为目标。
3. 读取 5x5 面板内部 3x3 格中栗(9) 标记像素的位置 (pr, pc)，其中 pr 属于 {0, 1, 2}（上/中/下），pc 属于 {0, 1, 2}（左/中/右）。
4. 清除整个网格（所有精灵体和面板均清除为黑(0)）。
5. 将目标精灵体放置到清空后的网格上，对齐方式由 (pr, pc) 决定：
   - pr=0：精灵体边界框上边缘对齐网格第 0 行；pr=1：精灵体边界框垂直居中于网格；pr=2：精灵体边界框下边缘对齐网格最后一行。
   - pc=0：精灵体边界框左边缘对齐网格第 0 列；pc=1：精灵体边界框水平居中于网格；pc=2：精灵体边界框右边缘对齐网格最后一列。
   - 居中时若无法恰好居中（网格尺寸与精灵体尺寸奇偶不同），向上/向左取整（即 floor）。
6. 输出仅含黑(0) 背景和放置后的目标精灵体。

**关键洞察**：这道题不是流水线——对称性筛选和位置解码是两个独立的推理任务，它们的结果在放置操作中汇聚。求解者不能先做完一个再做另一个（两者无先后依赖），但必须同时解对才能产生正确输出。面板中标记的行列位置联合编码了两个独立的空间参数（垂直对齐和水平对齐），与精灵体的内容无关。
