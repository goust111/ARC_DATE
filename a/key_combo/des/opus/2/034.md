## 新题 1：偏转奇偶染色

**组合逻辑**：[flow_draw + step_deflection](已有) → [deflection_count_parity](创新：偏转次数作为属性提取) → [recolor](已有，但触发条件创新为奇偶判断)

**来源原语**：flow_draw、step_deflection、deflect_when_aligned（来自 f15e1fac）；recolor（来自 67385a82、22a4bbc2 等）

**依赖链**：流动绘制产生路径并积累偏转次数 → 偏转次数的奇偶性决定每条路径的最终颜色。删除流动步骤则无法计算偏转次数；删除奇偶判断则所有路径同色，无法区分。

从左边缘出发的水平流沿途被顶部偏转像素逐步偏移，最终根据每条流经历的偏转次数奇偶性分别染色。

**输入结构**：黑(0)背景网格，约 15x20。左边缘（第 0 列）上有若干青(8)像素，分布在不同行，每两个青像素之间至少间隔 2 行。顶部边缘（第 0 行）上有若干红(2)像素，分布在不同列。网格其余部分均为黑(0)。生成约束：青像素的数量为 3~6 个，红像素的数量为 3~8 个；各青像素的初始行位置和红像素的列位置经过选择，保证所有流路径在偏转后不会相互重叠，也不会超出网格下边界。

**规则**：
1. 每个青(8)像素从其位置向右发射一条水平流，逐列向右推进（列号递增）。
2. 流在推进到某一列时，若该列在第 0 行有红(2)像素，则流先向下偏移一行，再继续向右推进。流经过的每个单元格（包括偏移后的位置）都被标记为该流的路径像素。
3. 流到达网格右边缘（最后一列）后停止。
4. 统计每条流经历的偏转次数（即流路径中发生向下偏移的次数）。
5. 偏转次数为奇数的流，其全部路径像素涂为黄(4)。偏转次数为偶数（含 0）的流，路径像素保持青(8)。
6. 红(2)像素和黑(0)背景保持不变。

**关键洞察**：偏转次数是流动绘制与偏转像素交互后的涌现属性，其奇偶性——而非偏转本身的有无——决定了最终颜色，需要对比多个示例才能区分"奇偶"规则与"有无偏转"规则。

## 新题 2：滑动后包围框吞噬

**组合逻辑**：[slide + notch_determines_dir](已有) → [bbox_containment → erase](已有，但作用于滑动后的新位置，创新点在于包含关系是滑动的涌现结果) → [recolor](已有)

**来源原语**：slide、notch_determines_dir、edge_aligned（来自 320afe60）；erase、bbox_containment、delete_if_contained_by_other_color（来自 9720b24f）；recolor（来自多题）

**依赖链**：缺口检测决定滑动方向 → 滑动改变对象位置 → 新位置产生的包围框包含关系决定哪些对象被擦除 → 存活对象按其滑动方向染色。删除滑动步骤则位置不变、无新包含关系；删除包含检测则无法确定哪些对象消失。

带缺口的对象滑向右边缘、无缺口的滑向左边缘，滑动后若一个对象的包围框落入另一个的包围框内则被擦除，存活者按滑动方向染色。

**输入结构**：黄(4)背景网格，约 15x15。网格中有 4~6 个蓝(1)的 4-连通单色对象，每个对象占 4~12 像素，形状各异（不规则连通体，非简单矩形）。部分对象的包围框边界上存在由背景色构成的"缺口"——即该边界行/列上有背景像素位于两个对象像素之间。各对象在输入中互不接触，且包围框互不包含。生成约束：对象的尺寸和初始位置经过选择，使得滑动后恰好产生 1~2 对包围框包含关系；滑动路径上不会有其他对象阻挡。

**规则**：
1. 检查每个蓝(1)对象的包围框四条边界。若任一边界行或列上，存在背景像素位于该行/列上两个对象像素之间（即缺口），则该对象标记为"有缺口"。
2. 有缺口的对象向右滑动，保持行跨度不变，直到其包围框右边缘与网格右边缘齐平。无缺口的对象向左滑动，直到包围框左边缘与网格左边缘齐平。
3. 在所有对象滑动完成后的新位置上，计算每个对象的包围框。若对象 A 的包围框完全落在对象 B 的包围框内部（四条边均严格在 B 的对应边以内或重合），且 A 的像素数少于 B，则擦除 A（所有像素设为黄(4)背景）。
4. 存活的右滑对象重涂为绿(3)；存活的左滑对象重涂为红(2)。
5. 背景保持黄(4)不变。

**关键洞察**：输入中各对象的包围框互不包含，但滑动将它们压缩到网格两侧后产生了新的包含关系——需要推断出包含检测发生在滑动之后而非之前。

## 新题 3：对齐方向决定颜色通道变换的锚点复制

**组合逻辑**：[translate_and_copy + anchor_alignment](已有) → [row_or_column_aligned → 分支条件](创新：对齐方向编码为不同的颜色变换规则) → [recolor](已有，但按方向分支执行不同通道变换)

**来源原语**：translate_and_copy、anchor_alignment、anchor_offset_correspondence（来自 2c737e39）；row_or_column_aligned（来自 3490cc26）；recolor（来自多题）；color_coded_dir（来自 f3e62deb，创新改造为方向编码颜色变换而非方向编码运动）

**依赖链**：锚点对齐确定偏移量 → 对齐方向（水平/垂直）作为分支条件 → 不同分支对复制品执行不同的颜色通道替换。删除锚点对齐则无法确定复制位置；删除方向分支则所有副本颜色相同，无法解释输出差异。

将一个双色精灵体复制到各目标锚点处，水平对齐的副本替换蓝色通道为黄色，垂直对齐的副本替换红色通道为绿色。

**输入结构**：黑(0)背景网格，约 15x18。网格中有一个由蓝(1)和红(2)像素组成的多色精灵体（4-连通整体，约 6~10 像素），精灵体内部恰好包含一个灰(5)像素作为源锚点。网格其余位置散布 3~5 个孤立的灰(5)像素作为目标锚点。每个目标锚点要么与源锚点同行（水平对齐），要么与源锚点同列（垂直对齐），不存在既不同行也不同列的目标锚点。生成约束：目标锚点位置保证各副本之间、副本与源精灵体之间互不重叠；源精灵体同时包含蓝(1)和红(2)像素各至少 2 个。

**规则**：
1. 源精灵体（含灰(5)源锚点）保持原位不变。
2. 对每个目标锚点：
   - 计算从源锚点到该目标锚点的偏移向量。
   - 将源精灵体中所有非灰(5)像素按此偏移平移，绘制为副本。灰(5)源锚点不参与复制。
   - 绘制副本前，先将目标锚点位置设为黑(0)背景。
3. 颜色变换规则取决于对齐方向：
   - 若目标锚点与源锚点同行（水平对齐）：副本中所有蓝(1)像素变为黄(4)，红(2)像素保持红(2)。
   - 若目标锚点与源锚点同列（垂直对齐）：副本中所有红(2)像素变为绿(3)，蓝(1)像素保持蓝(1)。
4. 各副本按目标锚点从上到下、从左到右的顺序依次绘制；后绘制的像素覆盖先绘制的（实际因不重叠约束，此顺序不影响结果）。

**关键洞察**：同一个精灵体模板产生了两种视觉上不同的副本——颜色差异不是因为模板不同，而是因为复制方向（水平 vs 垂直）选择了不同的颜色通道进行替换。需要对比多个副本才能归纳出方向与颜色变换的对应关系。

## 新题 4：跨尺度形状匹配驱动区域洪泛

**组合逻辑**：[shape_matching + cross_scale_same_shape](已有) → [匹配结果作为条件选择目标区域](创新：匹配对的较小方提供目标区域，较大方提供填充颜色) → [flood_fill](已有，但填充颜色由跨区域配对关系决定)

**来源原语**：shape_matching、cross_scale_same_shape、return_smaller（来自 ce602527）；flood_fill、enclosed_region、divider_line、region_order（来自 7447852a）

**依赖链**：分隔线划分区域、每个区域含一个小对象 → 跨尺度形状匹配识别配对 → 配对中较小者所在区域被填充，填充颜色来自较大者的颜色。删除形状匹配则不知哪些区域该填充；删除洪泛填充则匹配结果无输出体现。

在分隔线划分的区域中，两对跨尺度同形对象通过形状匹配配对，较小者所在区域被填充为较大者的颜色。

**输入结构**：黑(0)背景网格，约 18x18。一条红(2)连续折线将网格分隔为 6~8 个封闭区域（折线从网格一侧延伸到另一侧，形成完整分隔）。每个区域内恰好包含一个 4-连通单色小对象（3~8 像素，形状各异——不规则连通体），使用的颜色从 {蓝(1)、绿(3)、黄(4)、灰(5)、橙(7)} 中选取，每个对象颜色唯一。恰好存在两对跨尺度同形配对：每对中一个对象是另一个的 2 倍缩放（像素掩码在 2x 放大后完全重合），两者颜色不同。其余对象与任何其他对象在任意整数缩放因子下都不匹配。生成约束：缩放匹配无歧义——每个对象至多属于一个匹配对；区域足够大以容纳对象和填充；2x 放大后的掩码比较忽略颜色，仅比较形状。

**规则**：
1. 找到所有红(2)分隔线划分的封闭区域。
2. 提取每个区域内的单色对象，计算其像素掩码（相对于自身包围框左上角的相对坐标集合）。
3. 对所有对象对进行跨尺度形状比较：将较小对象的掩码按 2 倍放大（每个像素扩展为 2x2 块），检查放大后的掩码是否与较大对象的掩码完全一致。
4. 对于每个匹配对：
   - 较小对象所在的区域内，所有黑(0)背景像素被洪泛填充为较大对象的颜色。
   - 较小对象自身的像素保持原色不变（悬浮在填充色之上）。
   - 较大对象所在区域不做任何改变。
5. 不属于任何匹配对的对象及其所在区域保持不变。
6. 红(2)分隔线保持不变。

**关键洞察**：填充颜色不是区域内对象自身的颜色，而是来自另一个区域中与之跨尺度同形的配对对象——需要先完成跨区域的形状匹配，才能确定每个区域应填充什么颜色。

## 新题 5：标记框抑制射线的双重角色

**组合逻辑**：[sparse_marker_highlight + inside_bbox → recolor](已有) ⟷ [ray_extend + extend_past_corner](已有)，两者通过"矩形角点是否落入标记框"形成竞争约束（创新：同一空间测试同时启用一个操作、禁用另一个操作）

**来源原语**：ray_extend、corner_diagonal_align、extend_past_corner（来自 ec883f72）；recolor、inside_bbox、sparse_marker_highlight、marker_pixel（来自 32597951）；solid_rectangle（来自 ec883f72）；hollow_frame（来自 ec883f72）

**依赖链**：标记像素的包围框同时决定两件事——(1) 矩形内哪些像素被高亮重涂，(2) 矩形的哪些角点丧失射线发射资格。两个操作通过同一个空间判断互斥地分配角点：落入标记框内的角点被重涂但不发射射线，落在标记框外的角点保持原色且发射射线。删除重涂步骤则无法确定哪些角点被抑制；删除射线步骤则标记框仅做高亮，失去角点竞争关系。

标记像素的包围框既高亮矩形内部像素，又抑制框内角点的对角射线，使得同一空间判断驱动两个相反效果。

**输入结构**：黑(0)背景网格，约 18x18。一个绿(3)实心轴对齐矩形（至少 5x5，非正方形）。一个蓝(1)空心矩形框（1 像素厚边框，内部为黑(0)，至少 10x10），绿矩形位于蓝框内部且四周有间距。若干散布的红(2)单像素标记（3~5 个）。生成约束：红标记的包围框恰好覆盖绿矩形的部分角点（至少 1 个、至多 3 个角点落在标记包围框严格内部或边界上）；每个未被抑制的绿矩形角点，沿远离矩形中心的对角方向延伸时，第一个遇到的非背景像素恰好是蓝框的一个角像素。

**规则**：
1. 计算所有红(2)标记像素的最小轴对齐包围框（含边界）。
2. 绿(3)矩形中，每个像素若其坐标落在红标记包围框内部或边界上，则重涂为黄(4)。
3. 对绿矩形的 4 个角点逐一检查：
   - 若该角点的像素在步骤 2 中已被重涂为黄(4)（即落在标记包围框内），则该角点不发射射线。
   - 若该角点的像素仍为绿(3)（落在标记包围框外），则从该角点沿远离矩形中心的对角方向发射射线。射线沿途检查每个像素：若遇到的第一个非黑(0)像素是蓝(1)框的角像素，则从该蓝框角像素的下一个对角位置开始，将射线路径上所有黑(0)像素涂为绿(3)，直到到达网格边缘。若第一个非黑(0)像素不是蓝框角像素，则不发射。
4. 红(2)标记像素、蓝(1)框像素、以及绿矩形中未被重涂的绿(3)像素均保持不变。

**关键洞察**：红标记像素的包围框扮演双重角色——既是高亮窗口（框内绿像素变黄），又是射线抑制器（框内角点不发射对角射线）。同一个空间测试的结果对两种操作产生相反的效果：被"选中"意味着被重涂但失去射线能力。

## 新题 6：贪心走廊长度决定邻域填充色

**组合逻辑**：[path_painting + greedy_traversal + nearest_unvisited_first](已有) → [corridor_length → 奇偶分支](创新：走廊长度作为涌现属性) → [flood_fill](已有，但填充颜色由走廊长度奇偶性决定)

**来源原语**：path_painting、greedy_traversal、start_block、target_block、corridor_path、row_or_column_aligned、line_of_sight_visible、nearest_unvisited_first、line_of_sight_blocked（来自 3490cc26）；flood_fill、enclosed_region（来自 7447852a）

**依赖链**：贪心最近可见块遍历决定走廊路径及其长度 → 走廊长度的奇偶性决定相邻封闭区域的填充颜色。删除贪心遍历则无走廊、无长度信息；删除填充规则则走廊长度无用途。走廊长度是遍历顺序的涌现属性——改变块的空间排列会改变遍历顺序，从而改变各段走廊的长度和对应的填充颜色。

贪心最近可见块遍历产生的走廊段，其长度的奇偶性决定了走廊旁封闭区域的填充颜色。

**输入结构**：黑(0)背景网格，约 20x20。一个红(2)的 2x2 方块（起始块）和 4~6 个青(8)的 2x2 方块（目标块）。若干灰(5)线段（水平或垂直，1 像素宽）将网格部分区域围成封闭区域（由灰线和/或网格边缘完全围合的连通黑色区域）。方块不与灰线重叠。生成约束：方块的排布保证贪心最近可见遍历能访问所有青块；每个封闭区域恰好与一段走廊 4-邻接（即该区域的某个边界像素与走廊的某个橙色像素 4-相邻）；各走廊段长度不全相同。

**规则**：
1. 从红(2)起始块开始贪心遍历：在当前块的同两行带或同两列带中，找到所有未访问的青(8)块中视线未被阻挡（中间无非背景像素）且距离最近的那个块。将当前块与该块之间的背景间隙涂为橙(7)。移至该块，重复此步骤，直到无法找到可见的未访问青块。
2. 每段橙(7)走廊的"长度"定义为该段中橙色像素的数量（不含两端方块的像素）。
3. 对每个灰线封闭区域：找到与该区域 4-邻接的走廊段（保证恰好一段）。
   - 若该走廊段长度为奇数，将该封闭区域内所有黑(0)像素洪泛填充为橙(7)。
   - 若该走廊段长度为偶数，将该封闭区域内所有黑(0)像素洪泛填充为黄(4)。
4. 非封闭区域的黑色区域不填充。红块保持红(2)，青块保持青(8)，灰线保持灰(5)。

**关键洞察**：走廊段的长度是贪心遍历顺序的涌现结果——同一组方块在不同空间排列下，遍历路径不同，走廊长度不同，导致相邻区域的填充颜色不同。需要对比多个示例来发现填充颜色与走廊长度奇偶性的对应关系。

## 新题 7：孤立像素过滤后的面积排序同心环

**组合逻辑**：[multi_recolor_single → 过滤](已有，创新改造为面积过滤器而非重涂) → [sort + area_ordering](已有) → [concentric_draw](已有，但输入经过过滤后环数和顺序改变)

**来源原语**：connected_component、isolated_pixel、area_comparison、multi_recolor_single（来自 67385a82，创新改造：单像素不是被保留原色而是被排除出排序）；sort、area_ordering、area_nesting_order（来自 5587a8d0）；concentric_draw、nested_square_ring（来自 5587a8d0）

**依赖链**：连通分量分析区分孤立像素与多像素对象 → 孤立像素的颜色被排除出面积统计 → 仅多像素对象参与面积排序 → 排序结果决定同心环嵌套顺序。删除孤立像素过滤则面积统计被污染、环数和嵌套顺序改变；删除面积排序则无法确定环的嵌套关系。

过滤掉仅由孤立单像素表示的颜色后，剩余颜色按多像素对象总面积排序，绘制为同心方环。

**输入结构**：黑(0)背景网格，约 12x12。网格上分布着多个单色 4-连通前景对象，使用 4~6 种不同颜色（从 {蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、橙(7)} 中选取）。每种颜色可能有多个对象。某些颜色既有多像素对象（面积 >= 2）又有孤立单像素；某些颜色只有孤立单像素而无多像素对象。各颜色的多像素对象总面积互不相同。生成约束：至少有 1 种颜色仅以孤立单像素形式出现（即该颜色在过滤后将被排除）；至少有 3 种颜色拥有多像素对象。

**规则**：
1. 找出所有 4-连通单色非黑(0)对象。
2. 对每种前景颜色，计算其"有效面积"= 该颜色所有面积 >= 2 的对象的像素总数。孤立单像素（面积 = 1 的 4-连通分量）不计入有效面积。
3. 若某颜色的有效面积为 0（即该颜色仅有孤立单像素），将其排除，不参与后续步骤。
4. 将剩余颜色按有效面积降序排列。若有效面积相同（生成约束保证不会出现，但作为兜底），按该颜色最大对象的包围框左上角坐标从上到下、从左到右排序。
5. 设参与排序的颜色数为 K。生成一个 (2K-1) x (2K-1) 的正方形输出网格。
6. 有效面积最大的颜色填充最外层环，次大的填充下一层环，依此类推，最小的填充中心像素。每层"环"是一圈 1 像素宽的正方形边框。

**关键洞察**：孤立单像素是干扰项——它们属于某种颜色，但不贡献有效面积。若某颜色仅有孤立像素则被完全排除，改变了输出的环数；若某颜色既有孤立像素又有多像素对象，孤立像素虽不改变该颜色的存在但降低了视觉上的"该颜色总量"假象。需要对比多个示例才能发现面积统计排除了单像素。

## 新题 8：周期瓦片补全与缺陷标记

**组合逻辑**：[completion + periodic_extension](已有) ⟷ [defect_mark](已有，创新改造：缺陷不是形状凹痕而是颜色异常) — 两个操作相互依赖：补全需要推断正确瓦片（忽略缺陷），缺陷检测需要补全后的理想瓦片作为基准

**来源原语**：completion、repeating_tile、placeholder_region、periodic_extension（来自 50a16a69）；defect_mark、denoise、neighborhood_majority_color（来自 de809cff，创新改造：从形状凹痕检测变为颜色异常检测）

**依赖链**：可见区域包含少量"染错"像素 → 通过多数投票从多个瓦片实例中推断出理想瓦片 → 用理想瓦片填充占位符区域 → 同时用理想瓦片反向检测可见区域中的缺陷像素并标记。补全和缺陷检测形成鸡生蛋问题：不知道理想瓦片就无法找缺陷，但缺陷污染了瓦片推断的输入。解法是跨瓦片实例的多数投票。

在包含少量颜色缺陷的重复瓦片中推断出理想图案，用它补全占位符区域并标记出可见区域中的缺陷像素。

**输入结构**：网格约 12x15。网格的左上区域是一个重复平铺的矩形瓦片图案，使用 2~3 种颜色（从 {蓝(1)、红(2)、绿(3)、黄(4)} 中选取），瓦片尺寸为 3x3 或 4x4。灰(5)占位符颜色填充了网格的底部若干行和/或右侧若干列（形成 L 形占位区）。在可见的（非占位符）瓦片区域中，有少量像素被"染错"——它们的颜色与理想瓦片在该位置应有的颜色不同，但染错后的颜色仍属于瓦片使用的颜色集合（而非无关颜色）。生成约束：可见区域包含至少 3 个完整的瓦片实例（保证多数投票可行）；每个瓦片实例中至多 1 个像素被染错；缺陷像素总数为 2~4 个。

**规则**：
1. 确定最小重复瓦片周期：找到最小的矩形尺寸 (h, w)，使得可见区域中绝大多数像素满足 pixel[r][c] == pixel[r % h][c % w] 的周期性规律。
2. 对瓦片中每个位置 (i, j)（0 <= i < h, 0 <= j < w），收集可见区域中所有映射到该位置的像素颜色（即所有满足 r % h == i 且 c % w == j 的可见像素），取多数颜色作为该位置的理想颜色。这一步通过多数投票消除了少数缺陷像素的干扰。
3. 用理想瓦片周期性填充占位符区域：每个灰(5)像素替换为其位置 (r % h, c % w) 对应的理想颜色。
4. 在原可见区域中，将每个与理想瓦片不匹配的像素（即缺陷像素）重涂为橙(7)。
5. 可见区域中与理想瓦片匹配的像素保持不变。

**关键洞察**：缺陷像素伪装为瓦片使用的合法颜色，不能通过"找出不属于调色板的颜色"来发现——必须先通过跨瓦片实例的多数投票重建理想图案，再用理想图案反向定位异常。这使得补全和缺陷检测成为一个不可分割的推理过程。
