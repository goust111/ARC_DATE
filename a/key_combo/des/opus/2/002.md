## 新题 1：棋盘格奇偶选择性颜色互换

**组合逻辑**：[生成网格/generate_grid](已有) + [颜色互换/color_swap](创新：由网格坐标奇偶性有条件触发，而非对全部对象统一执行) + [边长决定间距/side_length_determines_spacing](已有)

**来源原语**：生成网格、边长决定间距（695367ec）；颜色互换、对象内双色配对（45737921）；周期排布（d304284e）

**依赖链**：实心方块的边长 → 确定网格划分的单元格尺寸 → 为每个单元格计算行列索引 → 索引之和的奇偶性决定该单元格是否执行双色互换。删去网格划分则无法确定奇偶性；删去互换则输出与输入相同；删去奇偶判断则退化为全局互换（单逻辑）。

在网格单元格内按棋盘奇偶性选择性地互换双色图案的两种前景色。

**输入结构**：约 15x15 的黑(0)背景网格。灰(5)横线和竖线将网格切分为若干等尺寸的矩形单元格（例如 3x3 或 4x4）。网格左上角外侧放置一个与单元格同尺寸的实心方块（颜色任意，仅用于确认单元格边长）。每个单元格内包含一个由恰好两种非背景、非灰前景色（例如蓝(1)和红(2)）构成的小图案，图案像素数在 3~8 之间，4-连通。不同单元格的图案形状可以不同，但每个单元格内恰好出现同样的两种颜色。生成约束：网格至少 3x3 个单元格；每个单元格内两种颜色的像素数均 >= 1。

**规则**：
1. 识别灰(5)横线和竖线，确定单元格的行列划分。每个单元格的尺寸等于实心方块的边长。
2. 为每个单元格赋予行索引 r（从 0 起，自上而下）和列索引 c（从 0 起，自左而右）。
3. 若 (r + c) 为奇数，则将该单元格内的两种前景色互换（原来是蓝的像素变红，原来是红的变蓝）。若 (r + c) 为偶数，保持不变。
4. 移除所有灰色网格线（替换为黑(0)背景）。移除角落的实心方块（替换为黑(0)背景）。
5. 输出变换后的网格（不含灰线和实心方块）。

**关键洞察**：颜色互换不是全局统一的——它由网格坐标的奇偶性有条件地控制。必须先从灰线恢复网格结构才能判定每个单元格的坐标，再由坐标奇偶决定是否互换。网格结构是隐式编码在灰线中的变换参数。

## 新题 2：双向滑动对齐后按轮廓异或选择射线方向

**组合逻辑**：[平移/translate](创新：双向对称滑动，非单向) → [异或叠加/xor_overlay](创新：作用于两侧形状在分隔列上的行投影轮廓，非完整掩码) → [射线延伸/ray_cast](创新：射线方向由异或缺失侧决定)

**来源原语**：平移、边缘对齐、连通分量、分隔列（6e453dd6）；异或叠加、前景不一致处涂色（99b1bc43）；射线延伸（6e453dd6）

**依赖链**：双向滑动 → 两形状分别贴紧分隔列 → 逐行比较两侧是否有前景像素（异或判断）→ 仅在恰好一侧有前景的行上、向缺失侧发射射线。滑动决定对齐位置；异或决定哪些行激活；缺失方向决定射线朝向。三者缺一不可。

将分隔列两侧的形状滑向分隔列对齐，在行轮廓不匹配处向缺失侧发射射线。

**输入结构**：约 12x20 的黑(0)背景网格。一条全高的灰(5)竖直分隔列位于网格中部。左侧有一个蓝(1) 4-连通连通分量（3~12 像素，不规则形状），距分隔列若干列。右侧有一个红(2) 4-连通连通分量（同样 3~12 像素，不规则形状），距分隔列若干列。两个形状的垂直跨度（包围盒高度）相同，但在部分行上的存在性不同（即投影到列方向时，某些行只有一侧有像素）。生成约束：两形状至少在 1 行上仅一侧有前景像素，且至少在 1 行上两侧都有前景像素。

**规则**：
1. 将蓝(1)连通分量整体向右平移，直到其最右列紧贴分隔列左侧（即最右列 = 分隔列 - 1）。
2. 将红(2)连通分量整体向左平移，直到其最左列紧贴分隔列右侧（即最左列 = 分隔列 + 1）。
3. 对于分隔列覆盖的每一行，检查滑动后蓝形状在该行是否有像素（记为 L）、红形状在该行是否有像素（记为 R）。
4. 若 L=true 且 R=false（仅左侧有）：从分隔列向右发射一条蓝(1)射线，覆盖该行分隔列右侧的所有列直到网格右边界。
5. 若 L=false 且 R=true（仅右侧有）：从分隔列向左发射一条红(2)射线，覆盖该行分隔列左侧的所有列直到网格左边界。
6. 若 L=true 且 R=true，或 L=false 且 R=false：该行不发射射线。
7. 射线绘制在原始形状和分隔列之上（射线覆盖已有像素时后绘制的覆盖先绘制的）。

**关键洞察**：射线方向不是固定的——它由两个形状对齐后的行轮廓异或结果动态决定。缺失侧决定射线去向，形成一种"互补投射"：左形状的独有行向右投射，右形状的独有行向左投射。滑动创造对齐条件，异或选择激活行，缺失方向决定射线朝向，三者构成不可分割的推理链。

## 新题 3：克罗内克展开中每个前景瓦片按顺序累计旋转

**组合逻辑**：[印章覆盖/stamp_overlay + 克罗内克积/kronecker_product](已有) + [旋转/rotate + 逐槽位累计旋转/successive_rotation_per_slot](创新：旋转不再作用于分隔线划分的独立区域，而是嵌入克罗内克展开的每个前景格)

**来源原语**：印章覆盖、克罗内克积、二值掩码、色块面板、面板提供调色板（c803e39c）；旋转、逐槽位累计旋转、顺序排列（8e5a5113）

**依赖链**：面板提取颜色 → 外层掩码确定哪些格放瓦片 → 按阅读序给前景格编号 → 编号决定旋转角度 → 内层掩码旋转后印入对应格。外层掩码的前景格拓扑决定了编号序列，进而决定旋转；内层掩码提供旋转的对象；颜色面板提供着色。三者交织。

将外层掩码的每个前景格用内层掩码的旋转副本填充，旋转角度按阅读序每格递增 90 度。

**输入结构**：约 6x24 的黑(0)背景网格（宽度较大以容纳四个面板）。三条全高灰(5)竖直分隔列将网格分为四个等宽面板。面板 1（最左）：一个小型二值掩码（例如 3x3 至 4x4），前景色为白或任意非黑非灰色，背景为黑(0)——这是"内层瓦片"。面板 2：同尺寸的二值掩码，前景色可与面板 1 不同——这是"外层布局"。面板 3：一个与面板同宽同高的实心色块，颜色 C_fg（如蓝(1)）。面板 4：同尺寸实心色块，颜色 C_bg（如红(2)）。生成约束：外层掩码至少有 4 个前景像素（以展示旋转周期）；内层瓦片非对称（使旋转可观察）。

**规则**：
1. 从面板 3 读取前景色 C_fg，从面板 4 读取背景色 C_bg。
2. 将外层掩码（面板 2）的前景格按阅读序（从左到右、从上到下）编号为 0, 1, 2, 3, ...
3. 对编号为 k 的前景格：将内层瓦片（面板 1 的掩码）顺时针旋转 (k mod 4) x 90 度。旋转后，前景像素着色为 C_fg，背景像素着色为 C_bg。将结果填入输出中对应位置的块。
4. 外层掩码的背景格：对应输出块全部填 C_bg。
5. 输出尺寸 = 外层掩码行数 x 内层瓦片高度 行，外层掩码列数 x 内层瓦片宽度 列。

**关键洞察**：在 c803e39c 中所有瓦片副本相同；在 8e5a5113 中旋转作用于分隔线划分的独立区域。这里旋转嵌入了克罗内克展开结构——每个瓦片的旋转角度由其在外层掩码前景格中的阅读序位置决定，形成空间位置与旋转状态的耦合。仅看单个输出块无法确定旋转规则，必须对比多个块的旋转状态与其在外层布局中的序号关系。

## 新题 4：跨分隔线计数比较决定是否逐对象颜色互换

**组合逻辑**：[计数/counting + 两区域比较/region_comparison](已有) → [颜色互换/color_swap](创新：互换不再对所有对象统一执行，而是由跨区域计数比较的结果逐对象有条件触发)

**来源原语**：计数、选择、两区域比较、最大增长差、横分隔线（8597cfd7）；颜色互换、对象内双色配对、同对象内互换（45737921）

**依赖链**：灰线划分上下区域 → 对应对象配对 → 逐对象统计上下区域中两种颜色的像素比例 → 比例是否翻转决定下方对象是否执行颜色互换 → 输出仅包含（可能被互换的）下方对象。配对需要空间定位；互换判断需要跨区域计数；最终输出需要互换操作。三步不可分离。

比较分隔线上下对应对象中的双色比例，比例翻转的对象执行颜色互换，输出下半区。

**输入结构**：约 13x10 的黑(0)背景网格。一条全宽灰(5)水平分隔行位于网格正中。上半区和下半区各包含相同数量（2~4 个）的 4-连通矩形对象，每个对象为 3x3，由恰好两种非背景非灰前景色构成（例如蓝(1)和绿(3)）。上下对应对象的位置在各自半区中相同（即上半区第 r 行第 c 列的对象与下半区第 r 行第 c 列的对象对应）。对应对象使用相同的两种颜色，但两种颜色的像素数分配可能不同。例如上方对象中蓝(1)占 6 像素、绿(3)占 3 像素，而下方对应对象中蓝(1)占 4 像素、绿(3)占 5 像素（比例翻转了）。生成约束：至少一个对应对出现比例翻转，至少一个对应对不翻转；每个对象内两种颜色像素数均 >= 1 且不相等。

**规则**：
1. 识别灰(5)水平分隔行，将网格分为上半区和下半区。
2. 在上半区和下半区分别检测所有 3x3 的双色对象，按对象中心在半区内的 (行, 列) 坐标配对。
3. 对每对对应对象：设上方对象中颜色 A 的像素数为 U_A、颜色 B 的像素数为 U_B；下方对象中颜色 A 的像素数为 D_A、颜色 B 的像素数为 D_B。若上方多数色与下方多数色不同（即 U_A > U_B 但 D_A < D_B，或反之），则标记该对象为"翻转"。
4. 对标记为"翻转"的下方对象，将其内的颜色 A 像素全部替换为颜色 B、颜色 B 像素全部替换为颜色 A。未标记的下方对象保持不变。
5. 输出仅包含下半区（裁剪掉灰线和上半区），尺寸为原网格高度的一半 x 原网格宽度。

**关键洞察**：颜色互换不是全局的——每个对象是否互换由该对象自身的跨区域计数比较独立决定。上半区不出现在输出中，它纯粹作为比较基准存在。仅看下半区无法判断哪些对象被互换了，必须参照上半区。

## 新题 5：拼合碎片后在新封闭孔洞中印入模板

**组合逻辑**：[平移拼合/translate_and_tile + 边缘匹配/edge_matching](已有) → [印章覆盖/stamp_overlay + 尺寸匹配/size_matching](创新：印章目标不是预设的灰色区域，而是拼合后才涌现的封闭孔洞) + [封闭区域/enclosed_region](创新：封闭区域由拼合操作动态产生，非输入中预先存在)

**来源原语**：平移拼合、边缘匹配、矩形碎片、角标记、通配色（446ef5d2）；印章覆盖、多色模板、尺寸匹配、同尺寸替换（e76a88a6）；封闭区域（6e453dd6）

**依赖链**：碎片边缘匹配 → 确定拼合位置 → 拼合形成完整矩形 → 矩形内部出现封闭的背景孔洞（这些孔洞在碎片分散时不存在，只有相邻碎片拼合后边界封闭才产生）→ 孔洞尺寸与模板比较 → 尺寸匹配的孔洞被模板填充。拼合是产生孔洞的前提；模板印入以孔洞存在和尺寸匹配为条件。

拼合散布的碎片为完整矩形，然后在拼合产生的封闭孔洞中印入尺寸匹配的模板。

**输入结构**：约 18x18 的黑(0)背景网格。3~5 块矩形碎片散布在网格上，碎片的主体色为橙(7)，部分碎片内部有黑(0)像素（这些黑像素在碎片边界内但不构成封闭区域——它们位于碎片边缘，只有当相邻碎片拼合后才被封闭）。碎片之间不重叠。一个品红(6)的 3 像素 L 形角标记指示拼合后矩形的某个角（2x2 区域缺一格，缺口即角点）。网格上还有一个独立的小型多色模板（非橙非品红，例如由蓝(1)和红(2)构成，尺寸如 2x3 或 3x2），不与任何碎片相邻。生成约束：碎片拼合后恰好形成一个完整矩形；拼合后内部至少产生一个封闭的黑(0)矩形孔洞，且该孔洞尺寸与模板相同；可能还有不匹配尺寸的孔洞（保留为黑色）。

**规则**：
1. 识别品红(6)角标记，确定目标矩形的角点位置。
2. 将所有橙(7)碎片平移（不旋转）到角标记位置，通过边缘匹配拼合为一个完整矩形（橙色像素构成矩形外框和内部结构）。碰撞边缘处橙(7)作为通配色——只要非橙像素不冲突即可匹配。
3. 拼合完成后，在矩形内部寻找所有被橙色像素完全包围的 4-连通黑(0)区域（封闭孔洞）。
4. 对每个封闭孔洞：若其边界框尺寸（高 x 宽）与模板的尺寸完全相同，则将模板内容原样复制到该孔洞位置。若尺寸不匹配，孔洞保持黑(0)。
5. 移除角标记（替换为黑(0)背景）和原始模板位置（替换为黑(0)背景）。

**关键洞察**：封闭孔洞在输入中不存在——它们是拼合操作的涌现产物。碎片分散时，那些黑像素暴露在碎片边缘，不构成封闭区域；只有相邻碎片合并后，它们才被包围形成孔洞。必须先完成拼合才能确定哪些位置需要印入模板，而印入条件又依赖于孔洞与模板的尺寸匹配。

## 新题 6：补全对称表作为涂色查找表

**组合逻辑**：[补全/completion + 循环对称/cyclic_symmetry](已有) → [重涂色/recolor](创新：补全结果不作为直接输出，而是作为另一结构的颜色查找表) + [分隔线/divider_line + 槽位/slot](已有)

2. 补全后的 NxN 方阵即为颜色查找表 T，其中 T[r][c] 为一种颜色（编号 1~4）。

4. 移除左上角方阵区域（全部替换为黑(0)）。移除灰色网格线（替换为黑(0)）。

**关键洞察**：对称表不是输出的一部分——它是一个中间数据结构，编码了主网格的着色规则。补全操作（来自 73251a56）的结果不直接可见，而是作为查找表驱动另一个操作（重涂色）。求解者需要先在小方阵中归纳出循环对称规则并补全，然后理解补全结果是主网格的颜色映射。

## 新题 7：标记像素同时编码变换方式与目标颜色

**组合逻辑**：[镜像/mirror 或 旋转/rotate](创新：变换类型由标记的空间位置编码，非固定或递增) + [重涂色/recolor + 最近邻匹配/nearest_neighbor_matching](已有) + [印章覆盖/stamp_overlay + 尺寸匹配/size_matching](已有)

**来源原语**：镜像、旋转、模式匹配（7df24a62）；重涂色、最近邻匹配、重复精灵体、标记像素、标记主轴方向排列（50aad11f）；印章覆盖、尺寸匹配、同尺寸替换（e76a88a6）；相对方位、方位决定槽位（18286ef8）

**依赖链**：标记像素的颜色 → 确定目标颜色（重涂色参数）；标记像素相对于其最近灰色矩形的方位 → 确定变换类型（镜像/旋转参数）；源精灵体 → 提供印章模板。三个信息流在每个目标矩形处汇聚：需要同时知道标记颜色、标记方位、源模板才能产生正确输出。

**规则**：
1. 识别源模板：网格中唯一一个非灰、非单色、非单像素的多色连通区域。提取其包围盒内的图案。
2. 对每个灰(5)矩形，找到距离其包围盒中心最近的单像素标记。
3. 判断标记相对于灰矩形的方位：
   - 标记在矩形上方 → 不变换（原样）
   - 标记在矩形右侧 → 顺时针旋转 90 度
   - 标记在矩形下方 → 旋转 180 度
   - 标记在矩形左侧 → 顺时针旋转 270 度
4. 将源模板按步骤 3 确定的方式变换。
5. 将变换后的模板中所有非黑前景像素统一替换为该标记像素的颜色（重涂为单色）。
6. 将重涂后的变换模板覆盖到灰矩形的位置（替换灰色像素），模板中黑(0)像素处对应位置也置为黑(0)。
7. 移除所有标记像素（替换为黑(0)）。源模板保持不变。

**关键洞察**：每个标记像素是一个双通道编码器——颜色通道编码目标色，空间通道（相对方位）编码几何变换。在 50aad11f 中标记仅提供颜色；在 18286ef8 中控制像素仅提供位置信息。这里两个信息流合并到同一个像素上，求解者必须同时解读颜色语义和空间语义。

## 新题 8：逻辑交选定位置集合，集合内计数决定统一填充色

**组合逻辑**：[逻辑交/logical_AND + 逐像素对齐/pixel_align](已有) → [计数/counting + 选择/selection](创新：计数范围不是整个区域，而是被 AND 选中的子集) → [重涂色/recolor](创新：AND 结果的颜色不由 AND 操作本身决定，而由选中子集内的统计决定)

**输入结构**：约 9x13 的黑(0)背景网格。一条全高灰(5)竖直分隔列位于中间。左半区包含两种颜色的前景像素：蓝(1)和红(2)，散布在黑背景上（总共 8~15 个非黑像素）。右半区包含单色前景像素：绿(3)，散布在黑背景上。左半区和右半区尺寸相同（不含分隔列）。生成约束：两侧掩码的 AND（同时非黑的位置）至少有 3 个像素；AND 位置中蓝和红的数量不相等。

**规则**：
1. 定位灰(5)分隔列。将左半区的非黑像素视为掩码 A（保留颜色信息），右半区的非黑像素视为掩码 B（仅用作二值掩码）。

3. 计算交集：位置 (r, c) 被选中当且仅当 A 和 B 在该位置都为非黑。
4. 在所有被选中的位置上，统计左半区对应像素中蓝(1)的个数 n_blue 和红(2)的个数 n_red。
5. 设多数色 M = 蓝(1) 若 n_blue > n_red，否则 M = 红(2)。
6. 输出一个与半区同尺寸的网格：被选中的位置填 M，其余位置填黑(0)。

**关键洞察**：AND 操作（来自 0520fde7）确定空间选择，但不能决定输出颜色——在 0520fde7 中输出固定为红色。这里输出颜色由 AND 选中子集内的统计分布决定（来自 8597cfd7 的计数比较逻辑）。两个操作在同一像素集合上分别贡献"位置"和"颜色"两个正交维度，缺一则输出不确定。

## 新题 9：按封闭孔洞数排序裁剪后拼接精灵体

**组合逻辑**：[裁剪/crop + 重涂色/recolor + 最近邻匹配/nearest_neighbor_matching](已有) → [计数/counting](创新：计数对象不是像素而是封闭的拓扑孔洞) → [排序/sorting](创新：排序依据不是包围盒高度或空间位置，而是拓扑属性) → [拼接/pack](已有)

**规则**：
1. 识别所有橙(7)的 4-连通精灵体。对每个精灵体，计算其包围盒内被该精灵体完全 4-连通包围的黑(0)封闭区域数（孔洞数）。判断标准：一个黑(0)的 4-连通分量如果不与包围盒外部的黑(0)像素相连，则为封闭孔洞。

## 新题 10：双精灵体独立周期铺展产生干涉，重叠处异或变色

**组合逻辑**：[印章覆盖/stamp_overlay + 周期排布/periodic_layout](已有) x 2（两个独立的周期铺展）→ [异或叠加/xor_overlay](创新：不是两个分隔区域的静态掩码异或，而是两个独立周期系统的动态干涉)

**来源原语**：印章覆盖、周期排布、精灵体、周期内指定位变色（d304284e）；异或叠加、前景不一致处涂色（99b1bc43）

**依赖链**：精灵体 A 的包围盒 → 确定 A 的铺展周期 → 生成 A 的所有周期副本位置集合 S_A；精灵体 B 的包围盒 → 确定 B 的铺展周期 → 生成 B 的所有周期副本位置集合 S_B。S_A 和 S_B 独立确定，但在输出中必须处理重叠——重叠位置的颜色由异或规则决定。两个独立的周期系统产生的干涉图案是涌现效应。

两个精灵体各自周期铺展后叠加，仅一方有前景处保留该方颜色，双方都有前景处变为第三种颜色。

**输入结构**：约 16x16 的黑(0)背景网格。两个小型精灵体位于网格上：精灵体 A 为蓝(1)，包围盒约 3x3，像素数 4~7，4-连通；精灵体 B 为红(2)，包围盒约 3x4 或 4x3（与 A 不同尺寸），像素数 4~7，4-连通。两精灵体在输入中不重叠、不相邻。网格右下角有一个单独的绿(3)像素作为颜色提示（指示重叠色）。生成约束：两精灵体的周期铺展在网格范围内至少产生 2 个重叠前景像素位置；两精灵体各自至少能铺展出 2 个完整副本（含原始位置）。

**规则**：
1. 识别精灵体 A（蓝(1)）和精灵体 B（红(2)），提取各自的包围盒和掩码。读取绿(3)提示像素（记录颜色后移除）。
2. 对精灵体 A：以其包围盒左上角为起点，向右每隔（A 的宽度 + 1）列、向下每隔（A 的高度 + 1）行放置一个副本。副本超出网格边界的部分裁剪丢弃。所有副本颜色为蓝(1)。
3. 对精灵体 B：以其包围盒左上角为起点，同样向右每隔（B 的宽度 + 1）列、向下每隔（B 的高度 + 1）行放置一个副本。所有副本颜色为红(2)。
4. 将两组副本叠加到黑(0)画布上。对每个像素位置：
   - 若仅 A 有前景：填蓝(1)。
   - 若仅 B 有前景：填红(2)。
   - 若 A 和 B 都有前景（重叠）：填绿(3)（提示色）。
   - 若都无前景：填黑(0)。

**关键洞察**：两个精灵体的铺展周期不同（因包围盒尺寸不同），形成类似"拍频"的空间干涉。重叠位置的出现不取决于任何单个精灵体的属性，而是两个独立周期系统的公共位置——这是一种涌现效应。绿色像素的分布规律无法从单个精灵体的铺展中预测，必须同时推理两个周期系统的交集。仅凭一个示例可能无法区分"重叠变绿"和其他着色规则，需要对比多个示例中绿色出现的位置与两组铺展的几何关系。
