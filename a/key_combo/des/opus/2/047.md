## 新题 1：弹射光路选定填充目标

**组合逻辑**：[射线延伸 + 反射弹回](从单方向弹射扩展为空间选择器) → [填充](作用对象由射线路径动态决定，而非全部填充) + [仅填矩形内部](保留)

**来源原语**：射线延伸/ray_cast、反射弹回/reflection_bounce、对角遇边反射/diagonal_with_wall_reflection（来自 #4 a3df8b1e）；填充/fill、空心矩形/hollow_rectangle、仅填矩形内部/fill_interior_only（来自 #6 e73095fd）；孤立像素/isolated_pixel（来自 #4 a3df8b1e）

**依赖链**：蓝色像素发射弹射光路 → 光路轨迹穿过部分空心矩形 → 仅被光路穿过的矩形内部被填充。光路的弹射方向决定了哪些矩形被选中；若移除光路逻辑，则无法判断填充哪些矩形；若移除填充逻辑，光路仅是装饰线条。

从一个蓝色像素出发沿对角线弹射，路径穿过的空心灰色矩形被填充为黄色，未穿过的保持空心。

**输入结构**：约 12x12 的黑(0)背景网格。网格中有 3~5 个灰(5)空心矩形（仅 1 像素宽轮廓，内部为黑(0)），各矩形大小不同（边长 3~6），互不重叠且不相邻。网格中另有一个蓝(1)孤立像素，位于所有矩形之外。生成约束：蓝色像素的弹射路径至少穿过一个矩形但不穿过全部矩形，以确保选择效果可辨识。不同示例中蓝色像素位置不同，使得被选中的矩形集合不同。

**规则**：
1. 从蓝(1)像素出发，沿右上方 45° 对角线移动，将经过的每个格子涂为蓝(1)。
2. 当射线碰到网格左边界或右边界时，水平方向反转（左变右或右变左），垂直方向保持向上不变；碰到上边界时射线终止。射线穿越灰色轮廓线时不停止，继续前进。
3. 检查每个空心矩形：如果该矩形的轮廓线上有至少一个像素被蓝色射线经过（即该格子同时属于灰色轮廓和蓝色射线路径），则该矩形被"选中"。
4. 对每个被选中的矩形，将其内部（轮廓线围成的黑色区域）填充为黄(4)。轮廓线本身保持灰(5)不变。
5. 未被射线穿过的矩形保持原样（灰轮廓 + 黑内部）。蓝色射线路径和蓝色起始像素保留在输出中。

**关键洞察**：射线路径不是最终图案的一部分，而是一个空间选择机制——同一组矩形在不同弹射路径下产生不同的填充结果。需对比多个示例才能确认"穿过才填充"这一选择规则，而非"所有矩形都填充"或"距离最近的填充"。

## 新题 2：内部计数器决定边框铺贴间距

**组合逻辑**：[计数](作用对象从右列灰像素改为矩形内部灰像素) → [平铺 + 环形周期](间距由计数值动态决定，而非固定为段长) + [计数器消失](保留)

**来源原语**：计数/counting、计数器像素/counter_pixel、计数器消失/counter_disappears（来自 #1 e48d4e1a）；平铺/tile、边框段/border_segment、矩形边界/rectangular_border、环形周期/cyclic_period、间隔等长重复/repeat_equal_gap（来自 #2 30f42897）

**依赖链**：统计内部灰色像素数 → 该数值作为边框铺贴的间距参数 → 按此间距在周长上周期重复色段。灰色像素不参与边框图案，纯粹是数值编码；移除计数则间距未知，铺贴无法完成；移除铺贴则计数无用途。

统计矩形内部散布的灰色像素数量 n，以 n 为间距将边框上的色段沿周长环形重复铺贴，灰色像素在输出中消失。

**输入结构**：约 10x10 的网格，背景色为黑(0)。网格的矩形边框上有一段由某前景色（如红(2)）构成的连续色段（长度 2~4 像素），位于边框的某一侧。矩形内部（非边框位置）散布着若干灰(5)孤立像素（1~5 个），互不相邻，不接触边框。不同示例中灰色像素数量不同，色段长度和位置也可能不同。生成约束：色段长度 + 间距（灰像素数）的倍数不超过边框周长，保证至少能铺贴 2 次以上。

**规则**：
1. 统计矩形内部所有灰(5)像素的数量，记为 n。
2. 将矩形边框展开为顺时针环形路径（从左上角开始）。
3. 找到色段在该环形路径中的起始位置和长度 k。
4. 从色段起始位置开始，每隔 (k + n) 个边框格子重复放置一份同颜色、同长度的色段副本，在环形路径上循环直到铺满一圈（部分重叠或超出环形长度时截断多余部分）。
5. 灰(5)像素在输出中全部替换为黑(0)。

**关键洞察**：灰色像素既非背景也非边框图案的一部分，它们是对铺贴间距的数值编码。需对比不同示例中灰色像素数量与铺贴间距的对应关系才能确认"间距 = 灰色像素计数"而非"间距 = 色段长度"（后者是参考题 30f42897 的规则）。

## 新题 3：连线段围合区域按边界色填充

**组合逻辑**：[连线 + 同色配对 + 行列对齐](保留) → [填充 + 封闭区域](创新：由线段动态围成，非预设结构) + [竖线交叉优先](创新扩展：从交叉点颜色优先扩展为区域归属判定)

**来源原语**：连线/draw_line、标记像素/marker_pixel、线段/line_segment、同色配对/same_color_pairing、行列对齐/row_col_align、竖线交叉优先/vertical_priority_at_cross（来自 #5 40853293）；填充/fill、封闭区域/enclosed_region（来自 #6 e73095fd、#3 0a2355a6）；间隙区域/gap_region（来自 #12 d6ad076f）

**依赖链**：同色像素对连线 → 线段交叉形成格子状分区 → 交叉处竖线颜色优先 → 完全封闭的矩形区域按其左侧竖线颜色填充。线段绘制产生分区结构，分区结构决定填充颜色；删除连线则无分区，删除填充则连线仅为装饰。

在黑色网格上将同色标记像素对连成水平或竖直线段，线段交叉时竖线颜色优先；由线段完全围成的矩形区域按其左侧竖线颜色填充。

**输入结构**：约 11x11 的黑(0)背景网格。网格中有 4~6 种前景色（如红(2)、绿(3)、黄(4)、蓝(1)等），每种颜色恰好出现 2 个像素，两个同色像素共享同一行或同一列。至少有 2 对水平排列和 2 对竖直排列的像素对，确保线段交叉后能围成至少一个完全封闭的矩形区域。生成约束：不同颜色的像素对之间的线段必须有交叉（至少 2 个交叉点），且至少一个交叉点的四个象限中有一个象限被线段完全围合。不同示例中像素位置不同，使被围合的区域和对应的左侧竖线颜色不同。

**规则**：
1. 对每种前景色，在该色的两个像素之间（含端点）沿共享的行或列绘制 1 像素宽的线段。
2. 若一条水平线段和一条竖直线段在同一格子交叉，该格子涂竖直线段的颜色（竖线优先）。
3. 绘制完所有线段后，检查黑(0)连通区域：若某个 4-连通的黑色区域在上、下、左、右四个方向上均被线段像素包围（即该区域的边界框的四条边上均有线段像素），则该区域为"完全围合区域"。
4. 对每个完全围合区域，找到该区域边界框左侧紧邻的那条竖直线段的颜色 c，将该区域所有黑色像素填充为 c。
5. 未被完全围合的黑色区域保持黑(0)不变。线段像素本身不被填充覆盖。

**关键洞察**：竖线交叉优先规则不仅决定交叉点颜色，还隐式决定了被围合区域的"归属"——因为区域的左边界必定是某条竖线，该竖线的颜色既在交叉处胜出又成为区域的填充色。需对比多个示例才能确认填充色来自"左侧竖线"而非"任意边界线"或"占比最多的边界色"。

## 新题 4：镜像拼贴中的异常检测与提取

**组合逻辑**：[平铺 + 镜像 + 相邻槽位翻转](创新：从生成规则反转为检测模板) → [模式检测](创新：不是检测局部'+', 而是检测全局镜像结构中的异常) → [裁剪](创新：裁剪的目标不是面板，而是异常差异图)

**来源原语**：平铺/tiling、镜像/mirror、瓦片/tile、阵列排布/array_layout、相邻槽位翻转/adjacent_slot_flip（来自 #18 c48954c1）；模式检测/pattern_detection、唯一匹配/unique_match（来自 #14 269e22fb、#16 1818057f）；裁剪/crop（来自 #20 e50d258f）

**依赖链**：输入看似标准 3x3 镜像拼贴 → 根据中央瓦片和镜像规则推算每个槽位的期望内容 → 逐一比对找出唯一偏差槽位 → 提取该槽位与期望之间的差异像素。镜像拼贴结构本身就是隐式模板，无需外部参照物；删除镜像规则则无法生成期望图；删除比对则无法定位异常。

在一个看似完整的 3x3 镜像拼贴马赛克中，恰有一个槽位被篡改。找出该槽位并输出差异像素图。

**输入结构**：一个 (3m)x(3m) 的网格（m 为 3~5，即 9x9 至 15x15），被逻辑划分为 3x3 共 9 个 mxm 的槽位。中央槽位是原始瓦片。其余 8 个槽位中有 7 个严格遵循镜像拼贴规则（上下相邻行翻转、左右相邻列翻转、对角两者皆翻转），恰有 1 个槽位中存在 1~3 个像素与期望不同（被替换为网格中其他某种已有颜色）。瓦片使用 2~3 种颜色，非对称（以确保镜像后可区分方向）。生成约束：被篡改的像素不出现在瓦片的对称轴上，保证异常可被唯一检测。不同示例中异常槽位位置不同。

**规则**：
1. 将输入网格划分为 3x3 的槽位阵列，每个槽位大小为 mxm。
2. 取中央槽位（第 2 行第 2 列）作为参考瓦片 T。
3. 根据镜像拼贴规则计算每个槽位的期望内容：与中央同行同列的槽位无变换（但实际上只有中央本身）；上方或下方邻居将 T 的行顺序翻转；左方或右方邻居将 T 的列顺序翻转；四角槽位将 T 的行和列均翻转。
4. 逐一比对各槽位的实际内容与期望内容，找出唯一一个存在差异的槽位。
5. 输出一个 mxm 的网格：在差异位置标记红(2)，其余位置为黑(0)。

**关键洞察**：不存在显式的"正确模板"——8 份冗余副本中 7 份正确这一事实隐式定义了模板。需对比多个示例确认异常检测规则是"与中央的镜像比对"而非"与邻居的局部对称比对"或"与多数像素投票比对"。

## 新题 5：角落复制创造新邻接后填充间隙

**组合逻辑**：[复制 + 顺时针到下一角](保留) → [填充 + 两体之间 + 间隙区域涂色](创新：填充作用于复制动态产生的新邻接关系，而非输入中原有的间隙)

**来源原语**：复制/copy、角落对象/corner_object、接触两边缘/touching_two_edges、顺时针到下一角/clockwise_next、忽略干扰项/ignore_distractors（来自 #8 bc93ec48）；填充/fill、间隙区域/gap_region、两体之间/between_two_objects、间隙区域涂色/gap_region_recolor（来自 #12 d6ad076f）

**依赖链**：识别角落对象（忽略干扰项）→ 顺时针复制到下一角 → 复制后某些相邻角落的对象之间出现沿边缘的间隙 → 填充这些间隙。复制操作创造了输入中不存在的新空间邻接关系；若不先复制，间隙的两端不完整；若不填充，复制仅是位置变换。

将网格四角的对象各顺时针复制到下一个角落，然后将沿边缘相邻的角落对象之间的间隙涂为青色。

**输入结构**：约 12x12 的黑(0)背景网格。在 2~3 个角落处有单色 4-连通的前景对象（不同颜色，如红(2)、蓝(1)、绿(3)），每个对象的边界框触及该角落的两条边（如左上角的对象紧贴顶边和左边）。对象大小约 2x3 到 4x4 像素，形状各异。至少有一个角落为空（无对象）。网格内部可能有 1~2 个不触及任何边缘的干扰色块。生成约束：角落对象的大小使得顺时针复制后，沿同一边缘的两个相邻角落对象之间存在至少 2 格的黑色间隙（不会重叠）。不同示例中占据的角落不同。

**规则**：
1. 识别所有边界框触及网格两条相邻边的 4-连通前景对象，这些是角落对象。不触及两条边的对象是干扰项，忽略之。
2. 对每个角落对象，将其像素图案和颜色复制到顺时针方向的下一个角落（左上→右上，右上→右下，右下→左下，左下→左上），将边界框对齐到目标角落。源对象保留不动。若目标角落已有对象，复制内容覆盖已有像素。
3. 复制完成后，检查每条网格边缘（上、右、下、左）：若该边缘的两个角落都有对象（原有或刚复制来的），则沿该边缘找到两个对象之间的所有黑(0)像素（边缘行/列上、两个对象之间的连续黑色格子），将其涂为青(8)。
4. 干扰色块保持不变。间隙仅沿边缘行/列的一维方向填充，不向内部扩展。

**关键洞察**：间隙在输入中并不以"两个对象之间"的形式存在——某些角落在复制之前是空的，只有复制操作为它们带来了对象，才构成"两体之间"的间隙条件。需对比多个示例（不同角落配置）才能确认间隙填充仅发生在复制后两端均有对象的边缘上。

## 新题 6：双面板叠合后涌现的十字图案特殊着色

**组合逻辑**：[透明叠加 + 并集合并](保留) → [模式检测 + 邻域全匹配](创新：检测对象从预设前景改为叠合后涌现的新图案) → [重涂色](创新：仅对涌现十字施加，其余并集像素保持原色)

**来源原语**：透明叠加/transparent_overlay、二值掩码/binary_mask、分隔列/divider_column、双侧对齐/bilateral_alignment、并集合并/union_merge（来自 #11 5d2a5c43）；模式检测/pattern_detection、十字图案/cross_pattern、邻域全匹配/all_neighbors_match（来自 #16 1818057f）；重涂色/recolor（来自 #3 0a2355a6）

**依赖链**：左右面板叠合为并集掩码 → 并集中出现了单面板中不存在的 '+' 十字图案 → 仅这些涌现十字被特殊着色。若不叠合则十字不存在；若不检测十字则叠合仅是标准并集；两步信息变换紧密相关。

两个黄色面板通过蓝色分隔列分开，叠合后的并集掩码中涌现出完整的 '+' 十字，这些涌现十字被涂为红色，其余并集像素涂为青色。

**输入结构**：约 7x(2w+1) 的网格（w 为 3~5），中间一列为蓝(1)分隔列，左右各一个 7xw 的面板。每个面板为黑(0)背景上的黄(4)像素图案。单独看每个面板中均不包含完整的 5 像素 '+' 十字图案（即不存在某个黄色像素的上下左右 4 邻居全为黄色的情况）。但两个面板按行列对齐叠合后（取并集），至少存在 1 个完整的 '+' 十字。生成约束：叠合后的十字必须确实是"涌现"的——组成该十字的 5 个像素中至少有 1 个仅存在于左面板、至少有 1 个仅存在于右面板。不同示例中涌现十字的数量和位置不同。

**规则**：
1. 移除蓝(1)分隔列，将左面板和右面板按行列对齐叠合。
2. 对每个位置：若左面板或右面板（或两者）在该位置有黄(4)像素，则该位置为并集前景像素；否则为黑(0)。
3. 在并集掩码中检测 '+' 十字图案：若某个前景像素的上、下、左、右 4 个正交邻居均为前景像素，则该像素及其 4 个邻居构成一个十字。
4. 将所有属于十字的像素涂为红(2)。（一个像素可能同时属于多个十字的臂，仍涂红。）
5. 将所有不属于任何十字的前景像素涂为青(8)。
6. 背景保持黑(0)。输出网格大小为去掉分隔列后的面板大小（7xw）。

**关键洞察**：十字图案不存在于任何一个单独的面板中，它只在叠合之后才涌现——这意味着求解者不能在叠合之前检测十字，也不能跳过叠合直接输出。需对比多个示例才能确认特殊着色仅针对 '+' 形而非其他密集区域。

## 新题 7：标记计数双重编码：选面板并旋转

**组合逻辑**：[计数 + 最多标记面板输出](保留选择功能) + [计数 → 二面体变换](创新：同一计数值同时决定选择目标和变换方式) → [裁剪](保留) + [计数器消失](保留)

**来源原语**：计数/counting、标记像素/marker_pixel、矩形面板/rect_panel、标记归属面板/marker_in_panel、最多标记面板输出/max_marker_panel（来自 #20 e50d258f）；裁剪/crop（来自 #20 e50d258f）；二面体变换/dihedral_transformation（来自 #14 269e22fb）；计数器消失/counter_disappears（来自 #1 e48d4e1a）

**依赖链**：统计各面板红色标记数 → 选出最多红标记的面板 → 红标记数 mod 4 决定旋转次数 → 裁剪并旋转该面板 → 红标记在输出中消失。标记承担双重角色（选择 + 变换参数），删除任一功能均会简化为不同的（更简单的）题目。

多个面板中选出红色标记最多的那个，将其裁剪后顺时针旋转 90 度乘以红标记数对 4 取余的次数，红色标记在输出中变为背景色。

**输入结构**：约 7x18 的网格，由灰(5)分隔列分成 3 个大小相同的矩形面板（每个约 7x5）。每个面板内部由青(8)像素构成图案，并散布若干红(2)标记像素。不同面板中红色标记数量不同（如 1、2、3 个），确保有唯一的最大值。面板中的青色图案非对称（旋转后可区分方向）。生成约束：红标记数的最大值不超过 4；不同示例中最大标记数不同，使旋转角度不同（0°、90°、180°、270° 均需覆盖）。

**规则**：
1. 通过灰(5)分隔列将网格划分为多个矩形面板。
2. 统计每个面板中红(2)像素的数量。
3. 选出红色像素数量最多的面板（保证唯一）。
4. 计算旋转次数 r = 红色像素数 mod 4。
5. 裁剪该面板（不含分隔列），将其顺时针旋转 r 个 90°。
6. 在旋转后的结果中，将所有红(2)像素替换为黑(0)（标记消失，它们是指令而非内容）。
7. 输出为旋转后的面板。

**关键洞察**：红色标记像素身兼二职——既是选择该面板的"投票"，又是决定旋转角度的"指令编码"。它们在输出中消失证实了其指令本质。需对比不同示例（标记数不同导致旋转角度不同）才能确认旋转规则是"计数 mod 4 × 90°"而非固定旋转或无旋转。

## 新题 8：压缩创造对齐后同色连线

**组合逻辑**：[压缩 + 标记定压缩方向](保留压缩机制) → [连线 + 同色配对 + 行列对齐](创新：配对条件由压缩后的新位置动态决定) + [竖线交叉优先](保留)

**来源原语**：压缩/compact、边缘标记/edge_marker、标记定压缩方向/marker_sets_dir（来自 #7 5e6bbc0b）；连线/draw_line、同色配对/same_color_pairing、行列对齐/row_col_align、竖线交叉优先/vertical_priority_at_cross（来自 #5 40853293）；标记像素/marker_pixel（来自 #5 40853293）

**依赖链**：边缘标记确定压缩方向 → 所有彩色像素向该边缘压缩 → 压缩后部分同色像素对恰好落入同一行或同一列 → 仅对这些新对齐的同色对连线。压缩改变了像素的相对位置关系，创造了输入中不存在的行列对齐；标记位置决定压缩方向，进而决定哪些对最终对齐。

在黑色网格上散布同色像素对，边缘的青色标记决定压缩方向；压缩后恰好共享行或列的同色对被线段连接。

**输入结构**：约 10x10 的黑(0)背景网格。网格中有 3~5 种前景色（如红(2)、绿(3)、黄(4)、蓝(1)等），每种颜色恰好出现 2 个像素。在输入中，没有任何同色对共享同一行或同一列（即原始位置下无法直接连线）。网格的某一条边缘（上、下、左或右）上有一个青(8)标记像素。生成约束：将所有彩色像素按标记方向压缩后，至少有 2 对同色像素落入同一行或同一列（即产生可连线的对），但不是所有对都对齐（至少有 1 对压缩后仍不共享行列）。不同示例中标记位置不同（可能在不同边缘），导致不同的对被对齐。

**规则**：
1. 确定青(8)标记所在的边缘（上/下/左/右）。
2. 将所有非黑、非青像素向该边缘方向压缩：若标记在左边缘，每行中的彩色像素保持相对顺序不变地平移到该行最左端（从第 0 列起依次排列）；上/下/右边缘类推，按列或按行压缩。
3. 压缩后，检查每种颜色的两个像素是否共享同一行或同一列。
4. 对每对压缩后共享行或列的同色像素，在它们之间（含端点）沿该行或列绘制 1 像素宽的线段，颜色与该像素对相同。
5. 压缩后仍不共享行或列的同色对不绘制线段。
6. 若一条水平线段和一条竖直线段在同一格子交叉，该格子涂竖直线段的颜色。
7. 青色标记保留在输出中。

**关键洞察**：输入中没有任何同色对可以直接连线——连线的前提条件（行列对齐）完全由压缩操作创造。改变标记位置（从左变为上）会导致不同的对被对齐，产生完全不同的连线图案。需对比至少两个示例确认连线仅发生在"压缩后对齐的对"上而非所有同色对。

## 新题 9：掩码重塑拓扑后按剩余孔洞重涂色

**组合逻辑**：[擦除 + 掩码决定保留](创新：掩码不仅筛选像素，还改变对象的拓扑结构) → [计数 + 封闭区域 + 按孔洞数映射颜色](创新：计数作用于被掩码重塑后的对象，而非原始对象)

**来源原语**：擦除/erase、掩码像素/mask_pixel、掩码决定保留/mask_determines_keep（来自 #9 f76d97a5）；二值掩码/binary_mask、分隔列/divider_column、双侧对齐/bilateral_alignment（来自 #11 5d2a5c43）；重涂色/recolor、连通分量/connected_component、封闭区域/enclosed_region、按孔洞数映射颜色/hole_count_to_color_mapping（来自 #3 0a2355a6）

**依赖链**：左面板掩码叠加到右面板 → 掩码擦除右面板部分像素 → 擦除改变了右面板对象的拓扑结构（原有的孔洞可能合并或消失）→ 按新的孔洞数重涂色。掩码不只是过滤——它重塑了拓扑，而拓扑决定颜色。若不施加掩码，孔洞数与原始一致；若不计数孔洞，掩码仅是简单过滤。

左面板是黑/灰二值掩码，右面板有带孔洞的青色对象；将掩码施加于右面板后，部分对象像素被擦除，改变了孔洞数量，最终按剩余孔洞数重涂颜色。

**输入结构**：约 9x(2w+1) 的网格（w 为 4~6），中间一列为蓝(1)分隔列。左面板（9xw）：黑(0)和灰(5)的二值图案，灰色像素表示"保留"，黑色表示"擦除"。右面板（9xw）：黑(0)背景上有 2~4 个青(8) 4-连通对象，每个对象在其边界框内封闭 1~3 个 4-连通的黑色孔洞。对象互不相邻，形状各异（3~6 像素宽，非矩形，具有不同连通拓扑）。生成约束：掩码的设计使得至少一个对象在施加掩码后孔洞数发生变化（如原有 2 个孔洞的对象，掩码擦除了两孔之间的隔墙像素，使 2 个孔洞合并为 1 个），且至少一个对象的孔洞数不变。不同示例中掩码不同，导致不同对象的拓扑变化不同。

**规则**：
1. 移除蓝(1)分隔列，将左面板掩码叠加到右面板：右面板中，对应左面板灰(5)位置的像素保留不变，对应左面板黑(0)位置的像素被擦除（设为黑(0)）。
2. 擦除后，重新识别右面板中的 4-连通青(8)连通分量。（部分对象可能被掩码切断为多个分量，或保持完整但孔洞数改变。）
3. 对每个存活的 4-连通青色分量，统计其边界框内被该分量完全包围（4-连通意义下不与分量外部黑色连通）的黑色区域数量，即封闭孔洞数 h。
4. 按 h 重涂色：h=0（无孔洞）→ 黄(4)，h=1 → 蓝(1)，h=2 → 绿(3)，h=3 → 红(2)。
5. 输出仅为掩码处理后的右面板（不含分隔列和左面板），大小为 9xw。

**关键洞察**：掩码不是简单的可见/不可见滤镜——它通过擦除对象内部的关键像素（如孔洞间的隔墙）来改变对象的拓扑结构。同一个对象在不同掩码下可能有不同的孔洞数，从而被涂为不同颜色。需对比多个示例才能确认涂色依据是掩码施加后的孔洞数而非原始孔洞数。

## 新题 10：按孔洞数排序精灵体后垂直堆叠对齐

**组合逻辑**：[计数 + 封闭孔洞](保留计数功能) → [排序](创新：排序依据从面积改为拓扑属性——孔洞数) → [对齐 + 印章覆盖 + 对齐到锚点](创新：对齐后的堆叠顺序由排序结果决定)

**来源原语**：计数/counting、封闭区域/enclosed_region、封闭孔洞/enclosed_hole、按孔洞数映射颜色/hole_count_to_color_mapping（来自 #3 0a2355a6，此处映射的不是颜色而是排序键）；排序/sort、按面积降序/largest_to_smallest_area（来自 #10 20818e16，此处改为按孔洞数升序）；对齐/align、印章覆盖/stamp、锚点像素/anchor_pixel、对齐到锚点/aligned_to_anchor（来自 #17 e41c6fd3）；精灵体/sprite（来自 #17 e41c6fd3）

**依赖链**：为每个对象统计封闭孔洞数 → 按孔洞数升序排列 → 按排序顺序从上到下垂直堆叠 → 水平对齐到锚点对象的左列。孔洞数决定排序键，排序键决定垂直位置，锚点决定水平位置——三步环环相扣。

统计每个彩色对象的封闭孔洞数，按孔洞数从少到多排序，然后将所有对象水平对齐到青色锚点对象的左列并按排序顺序从上到下堆叠。

**输入结构**：约 15x15 的黑(0)背景网格。有 3~5 个不同颜色的 4-连通对象（如红(2)、绿(3)、黄(4)、橙(7)），每个占 8~20 像素，散布在网格各处，互不相邻。每个对象内部封闭 0~3 个 4-连通黑色孔洞，不同对象的孔洞数各不相同（保证排序唯一）。另有一个青(8) 4-连通对象作为锚点，它也有自己的孔洞数，参与排序。对象形状各异，不要求共享归一掩码。生成约束：所有对象的孔洞数两两不同；对象边界框高度之和加上对象间间距不超过输出网格的高度。

**规则**：
1. 识别所有 4-连通的非黑色连通分量（包括青(8)锚点对象）。
2. 对每个对象，统计其在边界框内完全封闭（4-连通不与外部黑色区域连通）的黑色区域数量 h。
3. 按 h 从小到大排序所有对象。若 h 相同（本题保证不会），则按原始位置从上到下从左到右排。
4. 创建黑色输出网格，高度为所有对象边界框高度之和加 (对象数 - 1) 行间距（每两个对象之间 1 行黑色间隔），宽度为所有对象边界框宽度中的最大值。
5. 按排序顺序从上到下放置每个对象：每个对象的左列对齐到输出网格的第 0 列（即锚点对象的左列对齐位置），保持对象原始形状和颜色不变。
6. 每个对象保留其原始颜色（包括青色锚点），不进行重涂色。

**关键洞察**：排序键不是几何属性（面积、宽度），而是拓扑属性（孔洞数），这需要求解者先理解孔洞计数，再发现排序规则。需对比多个示例确认排序键是孔洞数而非面积、颜色编号或原始垂直位置。
