## 新题 1：对称性决定生长方向

**组合逻辑**：[对称检测](创新：结果不再输出颜色指示像素，而是决定后续路径生长的方向参数) → [生长](已有) + [遇障碍则绕行](已有，绕行方向由主方向间接决定)

**来源原语**：
- 对称检测 symmetry_detection ← 44f52bb0
- 生长 grow ← d9f24cd1
- 图案 pattern ← 44f52bb0
- 起点像素 start_pixel ← d9f24cd1
- 障碍像素 blocker_pixel ← d9f24cd1
- 镜像轴 mirror_axis ← 44f52bb0
- 逐步推进 stepwise_advance ← d9f24cd1
- 对称否决定输出色 symmetric_vs_asym_color ← 44f52bb0（创新为对称否决定方向）
- 遇障碍则绕行 detour_on_obstacle ← d9f24cd1

**依赖链**：对称检测的布尔结果直接决定路径生长的主方向（上/右），主方向不同导致路径遭遇的障碍集合不同，绕行行为因此产生不同的路径形态。删除对称检测则方向未知；删除生长规则则无路径输出。

以单色小图案的水平对称性为条件，从相邻种子像素出发在对应方向上逐步生长路径，遇灰(5)障碍时向垂直于主方向的一侧绕行。

**输入结构**：
- 网格约 15x20，背景黑(0)。
- 3~4 个互不相邻的 3x3 单色图案（颜色为红(2)），由红(2)像素在黑(0)背景上构成；不同示例中同一题的图案形状不同，但尺寸固定为 3x3。
- 每个图案正下方紧邻一个种子像素，颜色为蓝(1)或绿(3)（同一输入中可有不同颜色的种子）。
- 灰(5)障碍像素散布于网格中，不接触网格外边缘，不与图案或种子重叠。
- 生成约束：图案之间至少间隔 4 个像素；不同图案生长出的路径不会交叉（障碍分布保证各路径的可达区域不重叠）。

**规则**：
1. 对每个 3x3 红(2)图案进行水平镜像对称检测：比较第 0 行与第 2 行的左右翻转，若相同则判定为对称，否则为非对称。
2. 若对称：从该图案下方的种子像素出发，主方向为**向上**（行号递减）；若非对称：主方向为**向右**（列号递增）。
3. 路径生长：从种子像素开始，每步尝试沿主方向前进一格。若目标格为灰(5)像素，则改为向**垂直于主方向的正方向**前进一格（主方向为上时绕行方向为右；主方向为右时绕行方向为下）。路径像素的颜色与种子像素相同。
4. 路径在到达网格边界时停止。若绕行方向也被阻挡（目标格为灰(5)或超出边界），路径同样停止。
5. 原始图案和种子像素保留在输出中；灰(5)障碍保留。

**关键洞察**：对称性检测在源题中输出一个颜色指示像素，此处它不产生直接可见输出，而是作为路径生长方向的隐式开关——求解者必须先推断"对称→向上、非对称→向右"的映射关系，才能预测路径走向。

## 新题 2：位置决定循环偏移的瓦片补全

**组合逻辑**：[补全](已有) + [循环移位](创新：偏移量不再逐行递增 1，而是由瓦片阵列坐标之和决定)

**来源原语**：
- 循环移位 cyclic_shift ← e78887d1
- 补全 complete ← 9ddd00f0
- 精灵网格 sprite_lattice ← e78887d1
- 瓦片阵列 tile_array ← 9ddd00f0
- 分隔行列 separator_row_col ← 9ddd00f0
- 阵列坐标编码 array_coord_encoding ← 9ddd00f0（创新：坐标不再编码为孔洞位置，而是编码为循环偏移量）
- 预测下一周期行 predict_next_cycle ← e78887d1（创新为预测任意位置的周期偏移）

**依赖链**：瓦片的阵列坐标决定循环偏移量，偏移量决定瓦片内图案的具体形态。推断基础图案需从已有瓦片反推（减去对应坐标的偏移量），验证一致性后才能正向填充空白瓦片。删除补全则无输出；删除循环偏移规则则无法确定空白瓦片应填什么。

从部分已知瓦片推断基础图案，然后按每个瓦片的阵列坐标计算循环偏移量，填充所有空白瓦片。

**输入结构**：
- 网格为 (n*k + k - 1) x (n*k + k - 1) 的正方形，其中 k 为瓦片边长（约 3~5），n 为每行/列的瓦片数（约 3~4）。背景绿(3)。
- 单行/列背景色绿(3)分隔相邻瓦片。
- 约 40%~60% 的瓦片已填充：每个已填充瓦片内部为黄(4)像素构成的图案（一个 k x k 的二值图案，黄(4)为前景，黑(0)为内部背景）。
- 其余瓦片为全黑(0)空白。
- 生成约束：每行和每列至少有一个已填充瓦片，以保证基础图案可被唯一推断。

**规则**：
1. 识别 n x n 瓦片阵列，每个瓦片大小 k x k，瓦片间由单行/列绿(3)分隔。
2. 对每个已填充瓦片（阵列坐标 (r, c)，行列均从 0 开始），其图案是基础图案 P 的**列循环左移** (r + c) mod k 步的结果。即将 P 的每一行视为长度 k 的序列，整体左移 (r + c) mod k 位，溢出部分从右侧回绕。
3. 从多个已填充瓦片反推基础图案 P：对阵列坐标 (r, c) 的瓦片图案执行列循环**右移** (r + c) mod k 步，所有结果应一致，该一致结果即为 P。
4. 对所有空白瓦片，计算其 (r + c) mod k，将 P 列循环左移该量后填入，前景用黄(4)，内部背景用黑(0)。
5. 分隔行列保持绿(3)不变。

**关键洞察**：同一基础图案在不同瓦片位置呈现不同外观，求解者不能直接复制已有瓦片，必须先发现"位置坐标之和决定偏移量"这一隐藏编码规则，反推出基础图案后才能正确填充。

## 新题 3：控制色引导重力下落至形状匹配的嵌入槽

**组合逻辑**：[重力下落](已有) + [形状匹配 → 嵌入](创新：匹配不再是静态查找，而是由下落路径动态遇到的候选框决定) + [控制色定行为](创新：控制色不再决定穿透/停靠障碍，而是决定跳过第几个形状匹配的候选框)

**来源原语**：
- 重力下落 gravity_drop ← 963c33f8
- 嵌入 embed ← 228f6490
- 形状匹配 shape_matching ← 228f6490
- 控制像素 control_pixel ← 963c33f8
- 孔洞 hole ← 228f6490
- 精灵体 sprite ← e78887d1 / 228f6490
- 矩形框 rect_frame ← 846bdb03
- 控制色定行为 control_color_determines_behavior ← 963c33f8
- 拼图块嵌入孔洞 piece_fits_hole ← 228f6490
- 穿透或停靠 pass_through_or_stop ← 963c33f8

**依赖链**：精灵体的外形决定它能嵌入哪些框的孔洞（形状匹配）；控制像素的颜色决定它在遇到第几个匹配框时停下（跳过规则）；下落路径上框的排列顺序决定实际嵌入位置。三者缺一不可：无形状匹配则不知道哪些框是候选；无控制色则不知道选第几个候选；无重力下落则不知道候选的遭遇顺序。

将顶部精灵体按重力下落，根据控制色跳过或停靠于形状匹配的嵌入框，最终嵌入对应孔洞。

**输入结构**：
- 网格约 20x12，背景黑(0)。
- 顶部 3 行内放置 2~3 个小型单色精灵体（4-连通，3~6 像素，形状各异，颜色为红(2)、蓝(1)或绿(3)之一）。每个精灵体的最底行中央有一个控制像素：黄(4)表示"停靠第一个匹配框"，橙(7)表示"跳过第一个匹配框，停靠第二个"。
- 网格中部和下部有 4~6 个灰(5)矩形框（1 像素宽的灰(5)边框），内部各含一个黑(0)孔洞。孔洞形状各异但与某些精灵体的外形完全相同（二值形状匹配，忽略颜色）。
- 每个精灵体在其正下方的竖直路径上至少有 2 个孔洞形状与之匹配的框（保证橙(7)控制色可停靠第二个）。
- 框之间互不重叠，精灵体下落路径上的框按从上到下排列。
- 生成约束：不同精灵体的下落列范围不重叠（各精灵体独立下落，互不干扰）。

**规则**：
1. 对每个精灵体，确定其下落路径：精灵体沿竖直方向（行号递增）逐步下落，保持其列范围不变。
2. 下落过程中，检测路径上的每个灰(5)矩形框：将框内孔洞形状与精灵体外形（去掉控制像素后的形状）进行二值匹配。
3. 若控制像素为黄(4)：精灵体在遇到的**第一个**形状匹配的框处停下。若控制像素为橙(7)：精灵体**跳过**第一个匹配框，在**第二个**匹配框处停下。
4. 停靠时，精灵体（不含控制像素）嵌入该框的孔洞中，颜色保持精灵体原色。控制像素消失。
5. 所有未被嵌入的框保持原样。顶部精灵体的原始位置变为黑(0)背景。

**关键洞察**：控制像素在源题中区分"穿透障碍"与"停靠障碍"，此处它被重新定义为"匹配候选的序号选择器"——求解者必须同时理解形状匹配（哪些框是候选）和控制色语义（选第几个候选），才能确定最终嵌入位置。

## 新题 4：少数色过滤后的自掩码展开

**组合逻辑**：[重涂色/频率过滤](创新：不是替换为统一颜色，而是将少数色像素清除为背景，从而改变全局掩码) → [掩码映射/像素放大](已有，但作用于过滤后的网格，掩码因过滤而改变)

**来源原语**：
- 重涂色 recolor ← 9caf5b84
- 掩码映射 mask_mapping ← 973e499e
- 像素放大 pixel_scale ← 973e499e
- 全局掩码 global_mask ← 973e499e
- 前景像素 foreground_pixel ← ac0a08a4
- 自身色选掩码 self_color_selects_mask ← 973e499e
- 频率排序 frequency_rank ← 9caf5b84
- 少数色替换 minority_replaced ← 9caf5b84（创新为少数色清除为背景）

**依赖链**：频率分析确定哪些颜色是少数色 → 少数色像素被清除为黑(0) → 清除后的网格同时作为展开操作的源网格和掩码模板。掩码模板因清除而改变，导致展开结果与直接展开原始网格完全不同。删除频率过滤则掩码错误；删除掩码展开则无放大输出。

先清除输入中少数色像素（设为背景），再将过滤后的网格作为模板执行自掩码展开。

**输入结构**：
- 输入为小网格，约 4x4 或 5x5。
- 包含 3~5 种非黑颜色（如红(2)、蓝(1)、绿(3)、黄(4)、灰(5)），各颜色像素数不同。
- 恰好有 2 种颜色的像素数并列最多（多数色），其余为少数色。
- 黑(0)不出现在输入中（保留作为过滤后的背景色和展开后的填充色）。
- 生成约束：多数色的像素数严格大于任何少数色的像素数，且两种多数色之间可以像素数相同。

**规则**：
1. 统计输入中每种颜色的像素数，找出像素数最多的两种颜色作为多数色。
2. 将所有少数色像素替换为黑(0)，得到过滤后的网格 G'。
3. 对 G' 执行自掩码展开：对 G' 中每个像素位置 (r, c)，生成一个与 G' 同尺寸的块。若 (r, c) 处颜色为 c_val（非黑），则块中所有颜色也为 c_val 的位置写 c_val，其余位置写黑(0)。若 (r, c) 处为黑(0)，则整个块全黑。
4. 将所有块按原始位置拼合，得到输出网格（尺寸为输入边长的平方）。

**关键洞察**：频率过滤不仅删除了少数色像素本身，还改变了多数色在掩码模板中的分布——由于少数色位置变成了黑(0)，这些位置在展开时不再贡献任何内容，导致输出中出现源题单独应用掩码映射时不会产生的"空洞"图案。求解者必须先识别并执行过滤，才能得到正确的展开模板。

## 新题 5：网格线切割连通分量后的内部重涂色

**组合逻辑**：[网格线绘制](创新：不是绘制在空白画布上，而是叠加到已有前景分量上作为切割工具) → [重涂色](创新：内部判定不再基于原始分量边界，而是基于网格线切割后产生的子区域边界)

**来源原语**：
- 网格线绘制 grid_line_drawing ← 332efdb3
- 重涂色 recolor ← 09c534e7
- 连通分量 connected_component ← 09c534e7
- 网格线 grid_line ← 332efdb3
- 单点标记 singleton_marker ← 09c534e7
- 实心内部 solid_interior ← 09c534e7
- 行列索引奇偶性 row_column_index_parity ← 332efdb3
- 邻域全包含 full_neighborhood_inside_component ← 09c534e7（创新：应用于子区域）

**依赖链**：网格线将原始连通分量切割为子区域 → 子区域的内部/边界分类取决于切割后的新边界 → 只有完全被同色像素包围的子区域内部像素才被重涂为标记色。删除网格线则不产生切割、"内部"判定退化为原题；删除重涂色则网格线叠加无后续用途。

在含有标记的前景连通分量上叠加周期网格线，将分量切割为子区域，然后将每个子区域中满足"8-邻域全在同一子区域内"的像素重涂为该分量的标记色。

**输入结构**：
- 网格约 15x15，背景黑(0)。网格边长为奇数。
- 2~3 个灰(5)的 4-连通前景分量，每个分量是不规则的团块（连通，面积约 20~40 像素，有凹凸但无孔洞）。
- 每个灰(5)分量内部恰好有一个单点标记像素，颜色各不相同（如红(2)、蓝(1)、绿(3)），标记位于分量的非边缘位置。
- 不同分量之间至少间隔 2 个像素。
- 生成约束：每个分量足够大，使得网格线切割后至少有一个子区域包含满足 8-邻域全包含条件的像素。

**规则**：
1. 在整个网格上叠加周期 2 的网格线图案：所有行索引或列索引为偶数的像素标记为"网格线位置"（行列索引从 0 开始）。
2. 对每个灰(5)前景分量，网格线位置处的像素被视为切割线——它们将分量分割为多个 4-连通子区域（仅考虑行列索引均为奇数的像素之间的连通性）。
3. 在每个子区域内，找出所有 8-邻域（含对角）全部属于**同一子区域**的像素（即该像素的 8 个邻居都不是网格线位置、不是背景、不属于其他子区域）。
4. 将步骤 3 中找到的像素重涂为该分量所含标记像素的颜色。其余灰(5)像素（包括网格线位置处的灰(5)像素和子区域边缘像素）保持灰(5)。
5. 标记像素本身保持原色不变。背景保持黑(0)。

**关键洞察**：网格线在源题中是在空白画布上绘制装饰图案，此处它变成了一种空间分析工具——叠加到已有结构上创造新的拓扑分区。重涂色的"内部"判定因此变得更细粒度：原本一个大团块只有一个内部区域，经网格线切割后可能产生多个独立的小内部区域，每个都被重涂。

## 新题 6：边界标记定向镜像嵌入

**组合逻辑**：[裁剪](已有) + [镜像](创新：镜像方向不再由边色不符触发，而是由目标框上的边界标记位置决定) + [嵌入](创新：嵌入同时改变颜色，标记同时指定镜像方向和输出颜色)

- 精灵体 sprite ← 9f27f097
- 标记指定观察方向 marker_view_dir ← f341894c（创新为标记指定镜像方向）
- 形状匹配 shape_matching ← 228f6490
- 颜色匹配 color_match ← 846bdb03

**依赖链**：形状匹配决定精灵体与框的配对 → 框上标记的位置决定镜像方向 → 镜像后的精灵体嵌入孔洞 → 标记的颜色决定嵌入后精灵体的最终颜色。四步环环相扣，每步输出影响下一步输入。

**输入结构**：
- 网格约 18x18，背景黑(0)。
- 3~4 个灰(5)矩形框（1 像素宽灰(5)边），内部为黑(0)孔洞，孔洞形状各异（不规则，3~8 像素的 4-连通形状）。
- 每个框的某一条边（上/下/左/右）的外侧中点处有一个彩色标记像素（红(2)、蓝(1)、绿(3)或黄(4)之一），标记紧贴框边外侧，不与其他元素重叠。
- 3~4 个独立的单色精灵体散布在框外的空白区域，颜色统一为灰(5)（与框边同色），形状与某个框的孔洞形状完全匹配（二值匹配）。每个精灵体恰好匹配一个框，每个框恰好被一个精灵体匹配。

**规则**：
1. 裁剪每个精灵体的紧致边界框。
2. 将每个精灵体与孔洞形状匹配的框配对（二值形状比较，忽略颜色）。
3. 根据配对框上标记像素的位置决定镜像方式：
   - 标记在框的**左边或右边** → 将精灵体**水平镜像**（左右翻转）。
   - 标记在框的**上边或下边** → 将精灵体**垂直镜像**（上下翻转）。
4. 将镜像后的精灵体嵌入对应框的孔洞中。
5. 嵌入后的精灵体颜色重涂为该框标记像素的颜色（而非原始灰色）。
6. 精灵体原始位置变为黑(0)背景。框的灰(5)边框和标记像素保留在输出中。

**关键洞察**：标记像素在源题中指定一个"观察方向"来排列近远端颜色，此处它被重新定义为镜像轴选择器和颜色源——同一个标记同时编码了空间变换信息（左右 vs 上下位置→翻转轴）和颜色信息（标记色→嵌入色），求解者必须从标记的位置和颜色中分别解读两种不同的指令。

## 新题 7：重力着陆点生成切比雪夫环形干涉图案

**组合逻辑**：[重力下落](创新：下落结果不是最终输出，而是确定后续环形填充的中心点) → [填充/切比雪夫距离环](创新：多个中心点各自产生环形图案，重叠区域需要距离优先级解决冲突)

**来源原语**：
- 重力下落 gravity_drop ← 963c33f8
- 填充 fill ← 759f3fd3
- 控制像素 control_pixel ← 963c33f8
- 障碍物 obstacle ← 963c33f8
- 交叉点中心 intersection_center ← 759f3fd3（创新为下落着陆点作为中心）
- 控制色定行为 control_color_determines_behavior ← 963c33f8
- 穿透或停靠 pass_through_or_stop ← 963c33f8
- 偶数切比雪夫距离 even_chebyshev_distance ← 759f3fd3

**依赖链**：控制色决定下落行为（穿透/停靠障碍） → 着陆位置成为环形中心 → 多个中心的环形图案在空间中干涉 → 重叠区域按"离哪个中心更近"解决冲突。下落规则决定中心位置，中心位置决定环形范围，环形范围的重叠产生涌现的干涉图案。

彩色像素从顶部按控制色规则下落至着陆位置，每个着陆点生成以自身颜色填充的偶数切比雪夫距离环，重叠区域由更近的中心独占。

**输入结构**：
- 网格约 20x20，背景黑(0)。
- 顶行（第 0 行）有 3~4 个彩色像素（红(2)、蓝(1)、绿(3)等，颜色各不相同），各自占据不同列。
- 每个彩色像素正下方一格（第 1 行同列）有一个控制像素：黄(4)表示"遇到灰(5)障碍停靠在其上方"；橙(7)表示"穿透灰(5)障碍继续下落直到网格底部"。
- 灰(5)障碍像素散布于网格中（单像素，不成团块），至少在部分彩色像素的下落路径上。
- 生成约束：每个彩色像素的下落路径上至少有 1 个灰(5)障碍；不同彩色像素占据不同列，下落路径互不干扰。

**规则**：
1. 对每个顶行彩色像素，读取其正下方的控制像素颜色。
2. 黄(4)控制：彩色像素沿其列向下移动，在遇到的第一个灰(5)障碍**正上方一格**停下，该位置为着陆点。若路径上无灰(5)障碍，则停在底行。
3. 橙(7)控制：彩色像素穿透所有灰(5)障碍，直接停在**底行**（该列的最后一行）。
4. 确定所有着陆点后，擦除顶行彩色像素、控制像素和所有灰(5)障碍，画布变为全黑(0)。
5. 对每个着陆点 (r_i, c_i)（颜色 color_i），计算网格中每个像素 (r, c) 到该着陆点的切比雪夫距离 d = max(|r - r_i|, |c - c_i|)。
6. 若 d 为偶数（含 d=0），则该像素是着陆点 i 的"环像素"候选，颜色为 color_i。
7. 当一个像素同时是多个着陆点的环像素候选时，选择**切比雪夫距离最小**的那个着陆点的颜色；若距离相同，选择**着陆点行号更小**（更高）的那个。
8. 奇数距离处的像素保持黑(0)。

**关键洞察**：重力下落在源题中直接产生输出像素，此处下落只是确定"种子位置"的手段——真正的输出图案是从这些种子位置扩散出的切比雪夫环。多个环的干涉图案无法通过单独分析任何一个下落像素得到，必须同时考虑所有着陆点的空间关系。

## 新题 8：路径绕行次数的频率排名决定重涂色

**组合逻辑**：[生长/寻路](已有) + [计数](创新：不是计数前景像素总数，而是计数每条路径的绕行步数) → [重涂色/频率过滤](创新：频率排序的对象不是颜色像素，而是路径的绕行次数值；众数决定保留或替换)

**来源原语**：

- 计数 counting ← ac0a08a4
- 重涂色 recolor ← 9caf5b84
- 起点像素 start_pixel ← d9f24cd1
- 障碍像素 blocker_pixel ← d9f24cd1
- 前景像素 foreground_pixel ← ac0a08a4
- 逐步推进 stepwise_advance ← d9f24cd1
- 频率排序 frequency_rank ← 9caf5b84
- 遇障碍则绕行 detour_on_obstacle ← d9f24cd1
- 少数色替换 minority_replaced ← 9caf5b84（创新为少数绕行次数的路径被替换颜色）

**依赖链**：路径生长产生具体路径形状 → 统计每条路径的绕行次数 → 绕行次数出现最多的那个数值对应的路径保留原色，其余路径重涂为橙(7)。路径形状决定绕行统计，统计结果决定哪些路径被重涂。删除生长则无路径；删除计数则不知道哪些路径属于多数/少数；删除重涂则无颜色变化。

红(2)路径从底行起点向上生长并绕行灰(5)障碍，然后统计各路径的绕行次数，绕行次数出现频率最高的路径保持红(2)，其余路径重涂为橙(7)。

**输入结构**：
- 网格约 12x15，背景黑(0)。
- 底行有 4~6 个红(2)起点像素，各自占据不同列，相邻起点列间距至少 2。
- 灰(5)障碍像素散布在网格内部（不在底行和顶行），各障碍为单像素。
- 生成约束：每条路径都能到达顶行（不会被完全阻断）；不同路径不交叉（各路径的列范围在生长过程中不重叠）。不同路径的绕行次数中，恰好有一个数值出现最频繁（唯一众数），其余路径的绕行次数不等于该众数。

**规则**：
1. 对每个底行红(2)起点像素，向上生长路径：每步尝试向上移动一格（行号减 1，列号不变）。若目标格为灰(5)障碍，改为向右移动一格（行号不变，列号加 1）。路径像素标为红(2)。到达第 0 行时停止。若右移目标也被阻挡或超出边界，路径在当前位置停止。
2. 统计每条路径的绕行次数（即该路径中向右移动的步数）。
3. 在所有路径的绕行次数集合中，找出出现次数最多的数值（众数）。
4. 绕行次数等于众数的路径保持红(2)不变。
5. 绕行次数不等于众数的路径整体重涂为橙(7)（包括起点像素在该路径上的部分）。
6. 灰(5)障碍保留在输出中。

**关键洞察**：源题中路径生长和频率排序分属完全不同的谜题类型——路径是空间操作，频率排序是统计操作。此处两者通过"绕行次数"这一桥梁连接：路径的几何形状产生一个数值属性（绕行次数），该数值属性再经过统计排序反过来决定路径的视觉表现（颜色）。求解者必须理解空间规则才能计数，又必须理解统计规则才能确定最终颜色。
