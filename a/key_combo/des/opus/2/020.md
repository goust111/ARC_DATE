## 新题 1：标记奇偶决定镜像轴，镜像覆盖擦除标记后重涂边框

**组合逻辑**：[计数/counting] → [镜像/mirror](创新：奇偶决定轴向) → [擦除/erase](创新：镜像落点覆盖标记触发擦除) → [重涂色/recolor](创新：残留标记数映射边框颜色)

**来源原语**：计数、标记像素、空心矩形、包含 ← d4c90558；镜像、最近邻归属、跨框中线反射入内 ← 6855a6e4；擦除 ← 1e81d6f9；精灵体 ← 1cf80156

**依赖链**：标记计数的奇偶性决定镜像轴向 → 镜像后的精灵体落点决定哪些标记被覆盖擦除 → 残余标记数量决定边框最终颜色。同一组灰标记同时充当计数源（决定镜像方式）和潜在覆盖目标（被镜像结果擦除），形成同一数据源上的双重角色耦合。

每个空心矩形框内的灰色标记像素数量的奇偶性决定如何镜像框内的精灵体，镜像副本覆盖位置的标记被擦除，残余标记数映射为边框最终颜色。

**输入结构**：黑(0)背景网格，约 20x20。网格中散布 2~4 个单色空心矩形框，每个框由不同的非黑非灰颜色构成（如红(2)、蓝(1)、绿(3)等），框为单像素厚度，内部区域至少 5x5。每个框内部包含：(a) 若干灰(5)标记像素（2~6 个），随机散布在框内空白处；(b) 恰好一个由橙(7)像素构成的 4-连通小图形（3~5 像素，不同示例中形状各异），完全在框内部且不与灰标记重叠。不同框内的标记数量保证奇偶性不全相同。各框之间互不接触，间距至少 2 像素。生成约束：每个精灵体的镜像副本落点至少覆盖一个灰标记但不覆盖全部灰标记，以确保残余标记数 R 满足 0 < R < N。

**规则**：
1. 对每个空心矩形框，计算其严格内部（不含框壁）的灰(5)标记像素总数 N。
2. 若 N 为奇数，将框内的橙(7)精灵体以框内部区域的垂直中心线为轴做水平镜像反射；若 N 为偶数，以框内部区域的水平中心线为轴做垂直镜像反射。若内部区域该维度边长为偶数，镜像轴取偏左（垂直轴）或偏上（水平轴）的中心线。反射副本绘制为橙(7)，原位置的精灵体保留不变（框内同时存在原件和镜像副本）。
3. 绘制镜像副本后，检查每个灰(5)标记像素的位置：若该位置现在被橙(7)像素（原件或副本）占据，将该标记擦除（该位置保持橙(7)）；未被覆盖的灰标记保持灰(5)不变。
4. 统计每个框内残余灰标记数量 R。若 R 为奇数，将该框边框颜色改为黄(4)；若 R 为偶数，改为栗(9)。框内其他像素（橙精灵体、残余灰标记、黑背景）不变。

**关键洞察**：同一组灰标记像素既作为计数输入决定镜像方向，又作为镜像操作的空间目标被选择性擦除——镜像方向不同导致的覆盖模式不同，因此标记的空间分布同时编码了变换方式和变换后果。需对比多个框或多个示例才能归纳奇偶→轴向的映射规则。

## 新题 2：字形解码重力方向，瓦片内下落后跨瓦片端点连线

**组合逻辑**：[编码映射/encoding_map](创新：字形解码为方向而非颜色) → [重力下落/gravity_drop] + [碰撞停止/collision_stop] → [连线/connect](创新：下落终点作为连线端点，连线前的端点位置由重力决定)

**来源原语**：编码字形、字形映射颜色 ← ed74f2f2（改造为字形映射方向）；重力下落、碰撞停止、封闭区域 ← 88e364bc；格子瓦片、连线、端点标记、同色同子格位置、同行列对齐 ← a096bf4d

**依赖链**：字形解码确定全局重力方向 → 每个瓦片内的彩色像素在该方向上滑动至碰撞停止 → 滑动终点的瓦片内子格位置成为连线端点 → 同色、同子格、同瓦片行或列的端点之间填充连线。不知方向则无法确定终点，不知终点则无法连线。

角落瓦片中的方向字形指定全局重力方向，所有普通瓦片内的彩色端点像素沿该方向滑动到底，然后在滑动后处于相同子格位置的同色端点之间（沿瓦片行或列）画连线。

**输入结构**：黑(0)背景网格，约 19x19。灰(5)分隔线将网格划分为 4x4 的等大瓦片阵列（每个瓦片内部 3x3，分隔线单像素宽）。左上角瓦片为方向编码区：其 3x3 内部含恰好 2 个栗(9)像素——一个位于正中央(1,1)，另一个与之 4-邻接，两者的相对偏移编码重力方向（(0,+1)=向右，(0,-1)=向左，(+1,0)=向下，(-1,0)=向上）。其余 15 个瓦片为普通瓦片：内部为黑(0)底，部分瓦片含 1 个彩色端点像素（红(2)、蓝(1)或绿(3)），每种颜色在所有普通瓦片中恰好出现 2~4 次。生成约束：同色端点至少有一对共享同一瓦片行或瓦片列；每个瓦片至多含 1 个端点像素；方向编码区不含端点。

**规则**：
1. 读取左上角瓦片的方向编码：中心栗像素到邻接栗像素的偏移即为重力方向向量 D。
2. 对每个含端点像素的普通瓦片，将该端点在瓦片 3x3 内部沿 D 方向逐格滑动，直到碰到瓦片内部边界（3x3 区域的边缘行/列）或另一个非黑像素时停止。端点像素移动到终点位置，原位置变为黑(0)。
3. 滑动完成后，记录每个端点的（颜色 C，终点所在子格位置 P，瓦片行 TR，瓦片列 TC）。
4. 对于共享相同颜色 C 和相同子格位置 P 的端点对：若它们在同一瓦片行 TR，则在它们之间的所有中间瓦片中，在子格位置 P 处填充颜色 C；若在同一瓦片列 TC，则沿瓦片列方向在中间瓦片的子格 P 处填充颜色 C。若既不同行也不同列则不连线。连线从左到右或从上到下处理；若某子格已有非黑像素，连线像素覆盖它。
5. 方向编码区保持不变。分隔线保持灰(5)不变。

**关键洞察**：端点在重力滑动前可能处于不同子格位置，滑动后才对齐到相同子格从而满足连线条件——重力方向决定了哪些端点对能够被连接，仅看静态输入无法判断连线关系，必须先解码方向并模拟滑动。需对比多个示例确认字形偏移→方向的编码规则。

## 新题 3：模板缺失像素沿编码方向滑落就位

**组合逻辑**：[补全/completion](创新：不在原地填充而是识别缺失像素集) → [编码映射/encoding_map] → [重力下落/gravity_drop] + [碰撞停止/collision_stop](创新：缺失像素从模板位置沿编码方向滑动到碰撞停止处就位)

**来源原语**：补全、模板、缺失用分隔色填充 ← 1e32b0e9（改造：不用分隔色填充而是滑动就位）；编码映射、边界图例 ← 88e364bc；重力下落、碰撞停止 ← 88e364bc

**依赖链**：模板对比确定哪些像素缺失 → 方向图例解码确定滑动方向 → 缺失像素从其模板对应位置出发沿方向滑动至碰撞停止。模板对比和方向解码是独立的两个输入源，但它们在滑动步骤中汇合——缺失像素的身份来自模板对比，运动方向来自图例解码，两者缺一不可。

将每个不完整副本与模板对比找出缺失像素，然后让缺失像素从模板对应位置出发沿图例编码的方向滑动，直到碰到已有像素或边界停止。

**输入结构**：黑(0)背景网格，约 15x21。网格由品红(6)分隔行分为上下两个区域。上区域左侧为 5x5 的完整模板图案（由红(2)和蓝(1)像素在黑底上构成，4-连通图形，像素数约 8~14），右侧为方向图例（一个 3x3 的品红(6)填充小方块，其内部有黑(0)中心点和一个黄(4)指示点，中心到指示的偏移编码方向，与 88e364bc 中的 border_legend 编码方式相同）。下区域包含 2~3 个与模板同尺寸(5x5)的不完整副本，彼此之间用至少 2 列黑像素分隔，每个副本缺失模板中 2~4 个像素（这些位置为黑(0)）。生成约束：缺失像素从其模板对应位置沿编码方向滑动后不会超出副本的 5x5 边界，且不会与副本中的已有像素发生同位置冲突（即终点位置在副本内为黑(0)）。

**规则**：
1. 识别品红(6)分隔行，将网格分为上区域和下区域。
2. 在上区域提取完整模板（左侧 5x5 图案）和方向图例（右侧 3x3 方块）。
3. 解码方向图例：找到 3x3 方块内的黑(0)中心点和黄(4)指示点，从中心到指示的偏移向量 D 即为滑动方向。
4. 对下区域的每个不完整副本：将其与模板逐像素对比，找出所有缺失像素位置（模板中非黑而副本中为黑的位置）。
5. 对每个缺失像素：以其在副本中的模板对应位置为起点，携带模板在该位置的颜色，沿方向 D 逐格滑动。滑动过程中跳过黑(0)空位，碰到副本 5x5 边界或碰到非黑像素时在前一格停止并放置该颜色。缺失像素按照与滑动方向垂直的扫描线顺序依次处理（若 D 为水平方向则按行从上到下、行内按 D 的反方向处理；若 D 为垂直方向则按列从左到右、列内按 D 的反方向处理），先放置的像素成为后续像素的障碍。
6. 分隔行、模板、图例均保持不变。

**关键洞察**：缺失像素不在原地填充而是沿编码方向"滑动"到新位置——最终输出既不是原模板（像素位置不同）也不是简单的残缺填补（填补发生在偏移位置），求解者必须同时理解模板差异和方向编码才能确定每个像素的归宿。需对比多个示例确认方向图例的编码规则。

## 新题 4：射线交叉计数选区域，同计数筛选连通体

**组合逻辑**：[射线延伸/ray_extend] → [计数/counting](创新：统计射线穿过区域的次数) → [裁剪/crop] + [连通检测/connected_component_detection] + [指定面积筛选/specific_area_filter](创新：面积阈值等于射线穿越数)

**来源原语**：射线延伸、控制像素、像素为射线中心 ← 140c817e；裁剪、连通检测、指定面积筛选、最大计数选择、矩形区域 ← 2c0b0aff；标记色连通体 ← 2c0b0aff

**依赖链**：控制像素发射全行全列射线 → 统计每个矩形区域被射线穿过的次数 K → 选择被穿过次数最多的区域裁剪输出 → 在裁剪区域中只保留面积恰好为 K 的 4-连通标记色物体，其余标记色物体擦除为填充色。射线穿越数同时决定"选哪个区域"和"保留什么面积的连通体"，形成同一派生量的双重用途耦合。

控制像素发射全行全列射线，被射线穿过最多次的矩形区域被裁剪输出，且仅保留面积恰好等于穿越次数的标记色连通体。

**输入结构**：黑(0)背景网格，约 22x22。网格中有 3~4 个互不重叠的实心矩形区域（每个由某种颜色填充，如蓝(1)、绿(3)、黄(4)等，面积约 5x5 至 7x7），每个区域内部散布若干红(2)标记色像素（3~10 个），这些红像素形成若干 4-连通物体，面积从 1 到 6 不等。在所有矩形区域之外的黑背景上，散布 2~4 个橙(7)控制像素。生成约束：(a) 各矩形区域被射线穿过的次数互不相同，存在唯一最大值；(b) 被穿过次数最多的区域内恰好存在至少一个面积等于该穿越次数的红色 4-连通物体，以及至少一个面积不等于该穿越次数的红色 4-连通物体。

**规则**：
1. 找到所有橙(7)控制像素。对每个控制像素，沿其所在行（整行）和所在列（整列）画虚拟射线（射线不改变任何像素颜色，仅用于计数）。
2. 对每个实心矩形区域，统计有多少条不同的射线（行射线或列射线）穿过它（即射线的行号落在区域行范围内，或射线的列号落在区域列范围内）。记该穿越次数为 K。
3. 选择 K 最大的唯一矩形区域。
4. 在该区域内，找到所有红(2)像素构成的 4-连通物体并计算每个物体的面积。保留面积恰好为 K 的物体（红像素不变），将面积不等于 K 的物体的所有红像素替换为该区域的填充色。
5. 输出为该区域的裁剪结果（仅包含该矩形区域本身，不含区域外内容）。

**关键洞察**：射线穿越计数 K 同时担任两个角色——选择哪个区域裁剪输出（最大 K），以及在该区域内保留哪些连通体（面积 = K）。求解者必须先完成射线计数才能知道筛选面积阈值是多少，不能跳过射线步骤直接筛选。需对比多个示例才能发现面积阈值与穿越次数的关联。

## 新题 5：二部图交替着色决定延伸墨色而非边缘条颜色

**组合逻辑**：[延伸/extend] + [交替着色/alternating_coloring](创新：延伸使用区域的交替颜色而非边缘条自身颜色) ← 两个独立来源的规则在"延伸颜色"这一决策点交汇

**来源原语**：延伸、边缘条、朝近端扩展、标记在两边之间 ← 642248e4；交替着色、二部图结构、四邻接连通、分隔墙线 ← 3bd292e8

**依赖链**：墙线结构同时决定两件事：(1) 二部图区域的交替着色，(2) 控制像素所在区域。边缘条决定延伸方向，但延伸颜色由控制像素所在区域的交替色决定而非边缘条颜色。墙线结构是两条规则的共享输入，延伸颜色的确定需要同时完成区域着色和方向判断。

控制像素向较近的边缘条方向延伸一格，但延伸使用的颜色不是边缘条的颜色，而是该控制像素所在的二部图区域的交替着色颜色。

**输入结构**：黑(0)背景网格，约 15x15。网格的第一行和最后一行分别被蓝(1)和红(2)完整填充，作为上下两条边缘条。两条边缘条之间的区域被品红(6)墙线分隔为若干 4-连通的黑(0)背景区域（墙线为单像素宽的 4-连通线段，从一条边缘条延伸到另一条或在中间终止，形成 3~6 个区域）。部分区域中各含恰好 1 个绿(3)控制像素（2~4 个控制像素总计），位于该区域的某个黑(0)位置上。生成约束：每个控制像素与上下两条边缘条的距离不相等（保证有唯一较近的边缘条）；墙线构成的区域邻接图是二部图（单像素宽墙线分隔的区域天然满足此条件）。

**规则**：
1. 保留两条边缘条（蓝(1)上方、红(2)下方）和品红(6)墙线不变。
2. 计算二部图交替着色：将包含网格左下角的区域着为灰(5)，通过墙线邻接交替着为灰(5)和黄(4)。在输出中，所有背景区域的黑(0)像素替换为该区域的交替色（灰(5)或黄(4)）。
3. 对每个绿(3)控制像素：沿上下方向比较它到上边缘条（蓝行）和下边缘条（红行）的像素距离，确定较近的边缘条方向。在较近方向上紧邻控制像素的下一个位置（上方或下方 1 格），将该像素涂为控制像素所在区域的交替色（灰(5)或黄(4)），覆盖该位置原有的交替色或背景色。
4. 控制像素本身保持绿(3)不变。

**关键洞察**：延伸的方向和延伸的颜色来自两套不同的规则——方向由边缘条距离决定（空间近端），颜色由墙线分隔产生的二部图着色决定（拓扑属性），两者在控制像素处交汇。求解者如果只注意到边缘条颜色或只注意到交替着色，都无法得到正确输出。需对比多个控制像素才能发现延伸色与所在区域交替色一致而非与边缘条颜色一致。

## 新题 6：压缩粗粒度地图后按瓦片对颜色映射重涂

**组合逻辑**：[压缩/compress] + [颜色映射/color_mapping](创新：压缩结果的颜色由独立的瓦片对规则重映射) ← 两个独立推导在输出步骤汇合

**来源原语**：压缩、粗粒度块、含标记涂标记色、阵列排布 ← e57337a4；颜色映射、匹配对推导映射、瓦片、分隔行、带内三瓦片对齐、应用于剩余瓦片 ← b0722778

**依赖链**：上区域压缩产生 3x3 颜色地图 → 下区域瓦片对推导颜色映射规则 → 将映射规则应用于 3x3 地图的每个像素。压缩步骤决定空间模式（哪些格子有标记），瓦片对步骤决定颜色变换（什么颜色变成什么），两者独立推导但最终在输出中汇合——去掉任一步骤都无法得出正确答案。

上半区的大网格压缩为 3x3 粗粒度地图，下半区的瓦片对提供颜色映射规则，最终将映射应用于压缩后的 3x3 地图得到输出。

**输入结构**：黑(0)背景网格，约 15x11。网格由一条完整的灰(5)水平分隔行分为上下两个区域。上区域为 9xW（W 可被 3 整除）的大网格，其中恰好使用两种颜色：蓝(1)为主填充色，红(2)为稀疏标记色。上区域可等分为 3x3 阵列的矩形块。下区域包含一行（或一列）恰好 3 个等大的小瓦片（每个约 2x2 或 3x3），由黑(0)间距分隔。三个瓦片中恰好两个具有相同的图案（在颜色重命名意义下），它们构成映射对；第三个瓦片的图案不同。映射对中源瓦片使用蓝(1)和红(2)，目标瓦片使用绿(3)和黄(4)（或其他两种颜色），由此定义映射：蓝(1)→绿(3)、红(2)→黄(4)（具体映射颜色因示例而异，需从瓦片对中推断）。生成约束：映射对中两个瓦片的图案结构相同但颜色不同，第三个瓦片图案与映射对不同。

**规则**：
1. 找到灰(5)分隔行，将网格分为上区域和下区域。
2. 将上区域等分为 3x3 阵列的矩形块。对每个块：若含任何红(2)标记像素，在 3x3 输出地图对应位置记为红(2)；否则记为蓝(1)。得到一个 3x3 的中间地图。
3. 在下区域找到 3 个小瓦片。通过逐像素比较（允许颜色重命名）找到图案相同的两个瓦片（映射对），确定源瓦片和目标瓦片（源瓦片使用与上区域相同的颜色集合 {蓝(1), 红(2)}），从源到目标建立颜色映射 M。
4. 将映射 M 应用于步骤 2 的 3x3 中间地图：将每个像素的颜色按 M 替换。
5. 输出为映射后的 3x3 网格。

**关键洞察**：输出的空间模式（哪些格子是哪种颜色）来自上区域的压缩，但输出的颜色值来自下区域的瓦片对映射——两条完全独立的推理线索在最终输出中汇合。仅看上区域无法知道输出颜色，仅看下区域无法知道输出图案。需对比多个示例才能发现映射对中哪个是源、哪个是目标。

## 新题 7：邻接精灵数量选框，精灵方位决定镜像内部的分区重涂

**组合逻辑**：[计数/counting] + [邻接接触/adjacency_contact] → [裁剪/crop](创新：邻接数量最大的框被选中) → [镜像/mirror] → [重涂色/recolor](创新：精灵在框外的方位决定镜像后各半区的涂色)

**来源原语**：裁剪、矩形框、最大面积选取 ← 1a6449f1（改造：选择标准从最大面积变为最大邻接数）；镜像 ← 6855a6e4；邻接接触 ← 5117e062；精灵体 ← 5117e062；计数 ← d4c90558；重涂色 ← b0722778

**依赖链**：统计每个框外壁 4-邻接的精灵数量 → 最大数量的框被选中 → 框内部做水平镜像 → 精灵在框左侧或右侧的位置决定对应半区用哪种颜色覆盖背景。选择、镜像和重涂三步通过同一组精灵耦合：精灵数量决定选择，精灵方位决定重涂颜色，镜像改变方位对应关系。

**规则**：
1. 对每个灰(5)矩形框，统计 4-邻接于其外壁的精灵数量。选择精灵数量最多的唯一框（记为目标框）。
2. 提取目标框的严格内部区域（不含框壁），对其内容做水平镜像（以内部区域的垂直中心线为轴，左右翻转所有非黑像素）。若内部宽度为偶数，镜像轴取偏左中心列。
3. 找到目标框左侧（框左壁外 4-邻接位置）精灵的颜色 CL 和右侧精灵的颜色 CR。
4. 在镜像后的内部区域中：左半区（垂直中心线及其左方）所有黑(0)背景像素涂为 CR，右半区（垂直中心线右方）所有黑(0)背景像素涂为 CL。非黑的图案像素保持镜像后的颜色不变。
5. 输出为目标框的严格内部区域（含镜像和重涂后的结果），不包含框壁和框外内容。

**关键洞察**：精灵在框周围的分布同时编码了两层信息——总数决定选哪个框，左右方位决定重涂颜色的分配——且重涂的左右颜色是交叉的（左精灵色涂右半、右精灵色涂左半），与直觉相反，需对比多个示例才能归纳出这种交叉映射。

## 新题 8：标记计数决定对角印章次数，碰框壁则反射回弹

**组合逻辑**：[计数/counting] → [印章覆盖/stamp] + [对角偏移重复/diag_offset_repeat](创新：印章次数由标记计数决定而非直到出界) → [镜像/mirror](创新：碰到框壁时反射回弹继续印章而非截断)

**来源原语**：印章覆盖、对角偏移重复、尺寸决定步幅 ← e619ca6e；计数、标记像素、空心矩形、包含 ← d4c90558；镜像、跨框中线反射入内 ← 6855a6e4

**依赖链**：标记计数 N 决定印章重复次数 → 精灵沿对角方向以自身尺寸为步幅印章 → 若某次印章的目标位置越过框壁，则将步幅方向的水平或垂直分量取反（反射）并在反射后的位置继续印章 → 直到完成 N 次印章。计数控制迭代次数，框壁控制轨迹拐点，三者缺一不可。

在每个空心矩形框内，根据灰标记数量决定对角印章的次数，当印章轨迹碰到框壁时像弹球一样反射方向继续。

**输入结构**：黑(0)背景网格，约 22x22。网格中有 2~3 个空心矩形框，每个框由不同颜色构成（如红(2)、蓝(1)等），单像素厚度，内部区域至少 8x8。每个框内部包含：(a) 若干灰(5)标记像素（2~5 个），散布在框内空白处；(b) 恰好一个由绿(3)像素构成的实心小矩形（2x2 或 2x3 或 3x2），位于框内部的某个角落附近（距角落 0~1 像素）。生成约束：各框内标记数量互不相同；小矩形的初始位置和框内部尺寸保证在印章 N 次的过程中所有反射都在框内部完成且印章位置不超出框壁。

**规则**：
1. 对每个空心矩形框，计算框内灰(5)标记像素数量 N。
2. 确定框内绿(3)小矩形的位置和尺寸（高 h、宽 w）。初始对角方向根据小矩形在框内部的位置确定：若小矩形靠近左上角则初始方向为 (+h, +w)（向右下）；靠近右上角则 (+h, -w)（向左下）；靠近左下角则 (-h, +w)（向右上）；靠近右下角则 (-h, -w)（向左上）。"靠近"定义为小矩形中心到该角落的曼哈顿距离最小。
3. 从小矩形当前位置出发，沿当前方向偏移一个步幅（行偏移 = h 或 -h，列偏移 = w 或 -w），尝试放置一个相同尺寸的绿(3)矩形副本。
   - 若副本完全在框内部区域内：放置副本，消耗 1 次印章计数。
   - 若副本的任何像素会落在框壁上或框壁外：不放置副本，而是将越界的那个维度的步幅分量取反（若行方向越界则翻转行分量，若列方向越界则翻转列分量，若同时越界则两者都翻转），然后从当前位置用新方向重新计算目标位置并放置副本，消耗 1 次印章计数。
4. 以上一次放置的副本位置为新的起点，重复步骤 3，直到累计印章 N 次（不含原始矩形本身）。
5. 印章过程中，副本覆盖所经过的灰标记像素（灰标记被绿色覆盖）。原始小矩形保持不变。框壁不变。框外不变。

**关键洞察**：标记数量控制弹球式印章路径的长度，而框的几何尺寸和小矩形的起始角落共同决定路径的拐点序列——仅知道标记数量无法预测路径（不知道何时反射），仅知道框的几何也无法预测路径（不知道走多少步）。需对比多个框才能发现印章次数等于标记数量。

## 新题 9：射线着色与二部图区域着色的同时约束

**组合逻辑**：[射线延伸/ray_extend] + [交替着色/alternating_coloring] → [重涂色/recolor](创新：每个背景像素的最终颜色由射线覆盖状态和所在区域的交替色共同决定，非流水线而是同时约束)

**来源原语**：射线延伸、控制像素、整行整列射线、像素为射线中心 ← 140c817e；交替着色、二部图结构、四邻接连通、分隔墙线 ← 3bd292e8；重涂色 ← 6c434453

**依赖链**：墙线结构同时是区域着色和射线传播的输入。区域着色和射线覆盖各自独立计算，但它们在每个像素处交汇决定最终颜色——射线覆盖的区域内像素获得混合色，未被射线覆盖的获得纯交替色。这是一个同时约束满足结构，不存在固定的先后顺序。

红色墙线将网格分为交替着色的区域，蓝色控制像素发射全行全列射线；每个背景像素的最终颜色由其所在区域的交替色和是否被射线覆盖共同决定。

**输入结构**：黑(0)背景网格，约 15x15。网格中有红(2)墙线（单像素宽的 4-连通线段），将黑(0)背景分隔为若干 4-连通区域（4~7 个区域）。部分区域中含有蓝(1)控制像素（共 2~3 个，每个区域至多 1 个），位于该区域的某个黑(0)位置上。生成约束：墙线结构保证区域邻接图为二部图（单像素宽墙线天然满足）；控制像素的射线至少穿过 2 个不同区域。

**规则**：
1. 红(2)墙线像素在输出中保持不变。
2. 计算二部图交替着色：将包含网格左下角像素的区域标记为灰(5)侧，通过墙线邻接交替标记为灰(5)和绿(3)。
3. 计算射线覆盖：对每个蓝(1)控制像素，标记其所在整行和整列的所有非墙线位置为"被射线覆盖"。
4. 对每个黑(0)背景像素，根据以下规则确定输出颜色：
   - 若该像素不被任何射线覆盖：涂为其所在区域的交替色（灰(5)或绿(3)）。
   - 若该像素被射线覆盖且所在区域为灰(5)侧：涂为橙(7)。
   - 若该像素被射线覆盖且所在区域为绿(3)侧：涂为品红(6)。
5. 蓝(1)控制像素本身在输出中涂为黄(4)（既非交替色也非射线色，作为标记保留）。

**关键洞察**：输出中每个像素的颜色是两个独立属性（区域归属、射线覆盖）的联合函数——不存在"先做 A 再做 B"的线性顺序，求解者必须同时理解两套规则并在每个像素处执行二维查表。橙(7)和品红(6)的出现条件（射线 + 特定区域侧）需对比多个示例中不同区域的射线覆盖情况才能归纳。

## 新题 10：排序框内标记数，排名决定方框变十字的颜色

**依赖链**：统计每个彩色框内灰标记数量 → 按数量升序排序获得排名 → 排名映射到预定义颜色序列 → 在输出中将每个框替换为由对应排名颜色构成的十字图案。排名颜色不是框本身的颜色也不是标记的颜色，而是由排序位置唯一确定——不排序就不知道颜色，不计数就不能排序。

统计每个彩色框内灰标记像素数量并升序排序，排名第 k 的框在输出中被替换为第 k 种预定义颜色的十字图案。

**输入结构**：黑(0)背景网格，约 18x18。网格中有 3~5 个 3x3 空心矩形框（8 像素构成的框壁 + 1 个中心像素为黑(0)），每个框使用不同的非黑非灰颜色（如红(2)、蓝(1)、绿(3)、黄(4)、品红(6)）。各框互不接触，间距至少 2 像素。在网格的其他位置（不与任何框重叠），散布若干灰(5)标记像素。每个灰标记与恰好一个框在同一行或同一列上对齐（曼哈顿距离最近的框，距离按框中心计算），归属于该框。生成约束：各框归属的灰标记数量互不相同（保证排序无并列）。

**规则**：
1. 对每个 3x3 空心矩形框，找到所有归属于它的灰(5)标记像素（每个灰标记归属于与其框中心曼哈顿距离最近的框；若距离相同，归属于行号更小的框；若行号也相同，归属于列号更小的框）。统计每个框的归属标记数量。
2. 将所有框按归属标记数量升序排列，获得排名（从 1 开始）。
3. 排名到颜色的映射为固定序列：排名 1 → 蓝(1)，排名 2 → 红(2)，排名 3 → 绿(3)，排名 4 → 黄(4)，排名 5 → 橙(7)。
4. 对每个框，将其 3x3 区域替换为十字图案：四个角像素设为黑(0)，中心像素和四个边邻像素（上、下、左、右）设为该框排名对应的颜色。
5. 所有灰(5)标记像素从输出中擦除（设为黑(0)）。其他黑(0)背景像素不变。

**关键洞察**：框在输入中的原始颜色在输出中被完全丢弃——输出颜色完全由标记计数的排名决定。求解者如果试图从框的原始颜色推断输出颜色会陷入死胡同，必须发现颜色来源是排序排名。需对比多个示例中不同框的标记数和输出颜色才能归纳出排名→颜色的固定映射。
