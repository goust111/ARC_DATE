## 新题 1：扩展揭示连通性——孤立十字灰化

**组合逻辑**：[扩展/expand] → [连通判定/connectivity_test](创新：在扩展后的形态上做连通判定，而非原始位置) → [重涂色/recolor](创新：根据扩展后是否孤立来决定涂色)

**来源原语**：expand(0962bcdd), connectivity_test(239be575), recolor(e0fb7511), cross_pattern(e21d9049/0962bcdd), ortho_diag_role_split(0962bcdd), connected_color_else_black(239be575), arm_center_split_growth(0962bcdd)

**依赖链**：扩展操作改变十字之间的空间关系 → 连通判定在扩展后的形态上运行，其结果完全依赖于扩展的输出 → 重涂色仅作用于连通判定标记为"孤立"的十字。删除扩展，所有十字一定孤立；删除连通判定，无法区分簇与孤立；删除重涂色，连通判定无下游效果。

将间距不等的小十字扩展后，相距恰当的十字变为相连成簇，孤立的十字被涂灰。

**输入结构**：
- 黑(0)背景网格，约15x15。
- 散布多个小型3x3十字图案，每个十字由臂色（N/S/E/W四个像素，同一颜色）和中心色（1个像素，不同于臂色）组成，两色均非黑(0)。不同十字可使用不同的臂色/中心色组合。
- 十字之间的中心距不等：某些十字对的中心间距恰好为4（曼哈顿距离，沿正交方向），使得扩展后两个5x5足迹共享边界或重叠1列/行；某些十字对的间距>=6，扩展后仍完全分离。
- 每个十字的3x3边界框互不重叠且不4-相邻。
- 生成约束：至少存在一对间距=4的同轴十字（扩展后产生连通），以及至少一个与所有其他十字间距>=6的十字（扩展后仍孤立）。

**规则**：
1. 对每个3x3十字执行扩展：臂色沿正交方向各延伸1像素（从中心出发，距离1处为原臂像素，距离2处为新延伸像素）；中心色填充5x5足迹的四个对角位置（NE/NW/SE/SW，距中心对角距离sqrt(2)的四个格子）。扩展后每个十字在5x5区域内占13个非背景像素。
2. 在扩展后的网格上，将所有非黑(0)像素以4-连通性构建连通分量（忽略颜色差异）。
3. 属于包含2个及以上原始十字中心的连通分量的十字：保持扩展后的全部像素不变。
4. 属于仅包含1个原始十字中心的连通分量（扩展后仍孤立）的十字：将该十字扩展后的所有13个像素全部重涂为灰(5)。
5. 处理顺序：先完成所有十字的扩展，再一次性执行连通判定，最后对孤立十字做重涂色。

**关键洞察**：扩展操作不仅是视觉放大——它实质性地改变了十字之间的连通拓扑。两个原本中心相距4的十字在扩展前互不接触，扩展后5x5足迹却可能共享边界像素而连为一体。求解者必须先推断扩展规则（臂色正交生长、中心色对角生长），再意识到连通判定是作用于扩展后的形态而非原始3x3位置——这需要对比多个示例中不同间距的十字对来归纳。

## 新题 2：桥接连通门控精灵对接

**组合逻辑**：[连通判定/connectivity_test](创新：用作对接操作的门控条件) + [旋转/rotate + 对接拼合/docking] + [擦除/erase]

**来源原语**：connectivity_test(239be575), rotate(2c181942), docking(2c181942), erase(edcc2ff0), hollow_square(2c181942), sprite(2c181942), bridge_path(239be575), color_match_pairing(2c181942), connectivity(239be575), symmetry_disambiguates_rotation(2c181942)

**依赖链**：连通判定筛选出哪些精灵有"对接资格" → 颜色匹配决定精灵对接到hub的哪条边 → 旋转由对称性消歧确定朝向。删除连通判定，所有精灵都会对接（产生多余/错误的结果）；删除颜色匹配，对接位置不确定；删除旋转消歧，朝向不确定。

仅与中心空心方框通过桥接路径相连的精灵才被旋转对接到匹配的边；断连精灵被擦除。

**输入结构**：
- 黑(0)背景网格，约18x18。
- 中央一个空心N x N正方形（hub），N约5-7。四条边各为不同颜色（例如顶边红(2)、底边绿(3)、左边蓝(1)、右边黄(4)），四角像素和内部为黑(0)背景。
- 散布2-4个单色精灵体，每个精灵是4-连通的非矩形小图形（3-8像素，形状各异，不同示例中同颜色的精灵形状不同）。每个精灵的颜色与hub某条边的颜色相同。
- 青(8)色桥接像素形成窄路径（宽度1像素的4-连通链），连接部分精灵到hub的外边界。
- 至少一个精灵没有任何青(8)色路径连接到hub。
- 生成约束：每种hub边颜色最多对应一个精灵；至少有一个精灵通过青(8)桥接与hub连通，至少一个不连通。每个需要对接的精灵恰好有一种旋转使其满足接触边对齐且沿接触轴对称。

**规则**：
1. 构建4-连通图：所有非黑(0)像素（hub边框 + 精灵 + 青(8)桥接）参与，忽略颜色差异。判定每个精灵是否与hub处于同一连通分量。
2. 与hub连通的精灵执行对接：
   a. 颜色匹配：精灵颜色对应hub的哪条边（顶/底/左/右）。
   b. 旋转精灵0/90/180/270度，选择使精灵的接触边恰好有N-2个连续像素可对齐hub该边内侧、且旋转后精灵沿接触边法线方向的轴镜像对称的那个旋转角度（左右边→需上下对称，上下边→需左右对称）。
   c. 将旋转后的精灵平移至紧贴hub对应边的外侧。
3. 与hub不连通的精灵：全部像素擦除为黑(0)。
4. 所有青(8)桥接像素擦除为黑(0)。
5. 输出仅包含hub和成功对接的精灵。

**关键洞察**：青色桥接路径是不可见的"资格认证"——它们在输出中完全消失，但决定了哪些精灵有权参与对接。求解者需要在多个示例中观察到：距离hub很近但没有桥接的精灵被擦除，而距离较远但有桥接的精灵反而被对接，从而归纳出"连通而非距离"才是筛选标准。

## 新题 3：区域压缩编码经镜像后解码为字形网格

**组合逻辑**：[压缩/compress] → [镜像/mirror](创新：在压缩后的符号矩阵层面做镜像，而非在像素层面) → [图案印章/stamp_glyph](创新：控制像素来自压缩结果而非直接散布)

**来源原语**：compress(9f236235), mirror(9f236235/c9e6f938), stamp_glyph(dfadab01), separator_bar(9f236235), uniform_region(9f236235), control_pixel(dfadab01), glyph_dictionary(dfadab01), grid_partition(9f236235), encoding_map(dfadab01), axial_symmetry(c9e6f938), regions_compressed_then_flipped(9f236235)

**依赖链**：压缩从大型分区网格中提取符号矩阵 → 镜像在符号层级扩展布局（非像素层级） → 印章将每个符号解码为字形图案。删除压缩，符号排列隐藏在大网格中无法提取；删除镜像，输出只有一半；删除印章，符号矩阵无法转化为最终图案。

将分隔线划分的区域网格压缩为颜色矩阵，左右镜像后用字形图例逐格替换为小图案。

**输入结构**：
- 约18x12网格（宽大于高）。灰(5)色分隔线（宽度1像素）将网格左半部分（约12列以内）分割为M行 x K列的矩形区域，M约3-4，K约2-3。每个区域内填充单一颜色，颜色从红(2)、绿(3)、蓝(1)、黄(4)中选取。
- 分隔线右侧的空间为字形图例区域：每个图例条目占1行，包含一个颜色指示方块（1x1像素，位于固定列）和对应的3x3字形图案（紧邻其右侧）。图例覆盖所有在区域中出现过的颜色。
- 每种颜色的3x3字形图案各不相同且使用栗(9)色绘制在黑(0)底上（如：红→实心3x3方块，绿→3x3空心框，蓝→3x3十字，黄→3x3对角线）。
- 生成约束：压缩后的M x K颜色矩阵不是左右对称的（确保镜像产生变化）。区域中至少使用3种不同颜色。

**规则**：
1. 识别灰(5)色分隔线网络，提取所有被分隔线完全包围的矩形区域。
2. 将每个区域替换为其内部颜色的1个像素，保留行列顺序，得到M x K的压缩颜色矩阵。
3. 将压缩矩阵左右镜像拼接：原矩阵在左，镜像在右，得到M x (2K)的扩展矩阵。例如原矩阵为[A B C]，扩展后为[A B C C B A]。
4. 读取字形图例：每种颜色 → 一个3x3字形图案。
5. 构建输出网格：大小为(3M) x (6K)。将扩展矩阵的每个像素替换为其对应颜色的3x3字形，按行列无间隔拼接。
6. 字形图例本身不出现在输出中。灰色分隔线不出现在输出中。

**关键洞察**：镜像翻转发生在压缩后的符号矩阵层面，而非最终的字形像素层面。这意味着输出右半部分的字形序列是左半部分的列序反转，但每个字形本身不被翻转。求解者必须对比多个示例才能区分"在符号层镜像后再解码"与"先解码再在像素层镜像"这两种不同的操作顺序（两者对非对称字形产生不同结果）。

## 新题 4：镜像配对过滤驱动的计数指示条

**组合逻辑**：[镜像对称检测/mirror_symmetry](创新：作用于整个对象而非逐像素) → [计数/counting](创新：仅统计通过镜像过滤的对象) + [重涂色/recolor] + [擦除/erase]

**来源原语**：mirror_symmetry(ce039d91), recolor(ce039d91/e0fb7511), counting(edcc2ff0), erase(edcc2ff0), indicator_bar(edcc2ff0), four_conn_object(edcc2ff0), fg_mask(ce039d91), marker_filters(edcc2ff0), recolor_if_mirror_pair(ce039d91), bar_equals_count(edcc2ff0), ignore_distractors(ce039d91)

**依赖链**：镜像配对检测确定哪些对象"存活" → 计数仅统计存活对象（依赖过滤结果） → 指示条长度由计数决定 → 重涂色标记存活对象 + 擦除不存活对象。删除镜像检测，计数错误地包含干扰项；删除计数，指示条无法生成；删除擦除，干扰项留在输出中。

擦除场景中无水平镜像配对的对象，将配对对象涂蓝，并在指示条中用颜色条编码每种颜色的配对对象计数。

**输入结构**：
- 约14x16网格（列数为偶数），黑(0)背景。
- 顶部2行为指示条：第0列放置若干单像素颜色标记（例如红(2)在(0,0)、绿(3)在(1,0)、黄(4)在(0,0)——不同示例标记数量和颜色不同），其余格子为黑(0)。
- 第2行起为场景面板。场景面板的有效宽度（列数）为偶数，存在明确的垂直中线。
- 场景面板中散布多个4-连通单色小对象，每个对象3-6像素，形状各异（不限定具体外形——可以是任意4-连通形状，不同示例中同颜色的对象形状可以不同）。每个对象使用指示条中某种标记颜色。
- 部分对象在场景面板中存在镜像配对：在相对于场景面板垂直中线的镜像位置，有另一个同色、同形状（整体翻转后吻合）的对象。
- 部分对象没有镜像配对（干扰项）。
- 生成约束：每种标记颜色至少有一对镜像配对对象（2个对象构成1对）和至少一个无配对干扰项。不同颜色的配对对象数量不同（使指示条长度有区分度）。

**规则**：
1. 对场景面板中的每个4-连通前景对象，检查镜像配对：在相对于场景面板垂直中线的镜像位置，是否存在一个同色的4-连通对象，使得将原对象的每个像素关于中线做列反射后，得到的像素集合与该镜像对象的像素集合完全重合。
2. 有镜像配对的对象（配对的两个对象都算）：将所有像素重涂为蓝(1)。
3. 无镜像配对的对象（干扰项）：将所有像素擦除为黑(0)。
4. 对指示条中的每个颜色标记：统计场景面板中原始颜色等于该标记颜色且具有镜像配对的对象个数（每个对象计为1，一对计为2）。将标记像素替换为从第0列开始的水平同色条，长度等于该计数值。若计数为0，擦除该标记像素。
5. 处理顺序：先检测配对 → 再执行重涂色和擦除 → 最后生成指示条。

**关键洞察**：镜像配对检测是对象级别的（整个4-连通对象必须整体配对），而非参考题 ce039d91 中的逐像素检测。一个对象中的某些像素可能恰好在中线对面有同色像素，但如果整个对象不完整地配对为同形镜像，仍判定为干扰项并被擦除。求解者必须对比多个示例来区分"逐像素镜像"与"整体对象镜像"这两种粒度的差异。

## 新题 5：十字扩展与射线延伸的方向依赖冲突

**组合逻辑**：[扩展/expand] + [射线延伸/ray_extend] + 方向依赖冲突解决(创新：两种空间操作同时产出，冲突优先级由射线朝向决定)

**来源原语**：expand(0962bcdd), ray_extend(9344f635), cross_pattern(0962bcdd), micro_marker(9344f635), row_column_bar(9344f635), ortho_diag_role_split(0962bcdd), orientation_determines_direction(9344f635), arm_center_split_growth(0962bcdd), row_overrides_column(9344f635), conflict_priority(9344f635)

**依赖链**：扩展和射线延伸各自独立产生像素覆盖 → 在重叠区域，冲突解决规则依赖射线朝向（行条 vs 列条）。删除扩展，没有十字足迹参与冲突；删除射线延伸，没有条纹参与冲突；删除方向依赖的冲突规则，重叠区域颜色不确定。

同时扩展十字和延伸骨牌射线；行条切穿十字，但列条被十字遮挡。

**输入结构**：
- 约14x14网格，黑(0)背景。
- 前景元素分两类：
  - **3x3两色十字**：臂色（N/S/E/W四像素）和中心色（1像素）各为一种非黑颜色，两色不同。约2-3个十字。
  - **2像素同色多米诺骨牌**：水平排列（1x2，两像素同行相邻）或垂直排列（2x1，两像素同列相邻），颜色非黑且与十字的臂色和中心色均不同。约2-4个骨牌，其中至少1个水平、至少1个垂直。
- 十字与骨牌的边界框互不重叠且不4-相邻。
- 生成约束：至少一个水平骨牌的所在行穿过某个十字的5x5扩展范围；至少一个垂直骨牌的所在列穿过某个十字的5x5扩展范围。不同十字可使用不同的臂色/中心色。

**规则**：
1. 扩展每个3x3十字：臂色沿正交方向各延伸1像素（5x5足迹的上/下/左/右端点）；中心色填充5x5足迹的四个对角位置。扩展后每个十字在5x5区域内占13个非背景像素。
2. 延伸每个骨牌为射线：水平骨牌 → 将骨牌颜色沿骨牌所在行绘制整行（行条）；垂直骨牌 → 将骨牌颜色沿骨牌所在列绘制整列（列条）。
3. 同一像素被多种操作覆盖时的冲突解决：
   a. 行条 vs 扩展十字：行条颜色覆盖十字颜色（行条优先级更高）。
   b. 列条 vs 扩展十字：十字颜色保留，列条被遮挡（十字优先级更高）。
   c. 行条 vs 列条（无十字参与）：行条覆盖列条。
4. 等效绘制顺序理解：先绘制所有列条 → 再绘制所有扩展十字 → 最后绘制所有行条。每层覆盖前一层在同位置的颜色。
5. 未被任何操作覆盖的像素保持黑(0)背景。

**关键洞察**：冲突优先级不是简单的"后画覆盖先画"全局规则，而是依赖射线的朝向：水平行条能穿透十字（行条 > 十字），但垂直列条被十字遮挡（十字 > 列条）。求解者需要在示例中分别观察水平射线穿过十字区域和垂直射线被十字阻断的现象，才能推断出这条方向不对称的分层规则。仅看一个示例可能误判为统一优先级。

## 新题 6：粒子路径访问序决定精灵拼接顺序

**组合逻辑**：[路径追踪/path_trace](创新：路径不绘制在输出中，而是作为隐式排序键) → [裁剪/crop] + [排序/sort](创新：排序依据是路径访问时刻而非空间位置) + [拼接/concatenate]

**来源原语**：path_trace(9bbf930d), crop(67636eac), sort(67636eac), concatenate(67636eac), particle(9bbf930d), corridor(9bbf930d), parallel_colored_bar(9bbf930d), connected_sprite(67636eac), same_color_flanking(9bbf930d), collision_turn(9bbf930d), collision_stop(9bbf930d), layout_axis_direction(67636eac), tight_packing_by_position(67636eac)

**依赖链**：路径追踪确定粒子经过哪些精灵以及经过的顺序 → 裁剪提取被路径选中的精灵 → 按路径访问顺序排列并拼接。删除路径追踪，选取和排序的依据不存在；删除裁剪，精灵无法提取为独立块；删除拼接，提取的块无法组装为输出。

粒子在走廊中运动，按经过精灵的先后顺序裁剪拼接这些精灵；未经过的精灵不出现在输出中。

**输入结构**：
- 约20x20网格，橙(7)背景。
- 彩色平行条纹分布在偶数行/列：每对同色条（相邻偶数行或相邻偶数列）之间的奇数行/列为走廊。条纹颜色各异（如红(2)、绿(3)、蓝(1)），每种颜色的条纹恰好成对出现。
- 品红(6)粒子：1个像素，位于第0列某个走廊行（奇数行）。
- 多个小型单色精灵嵌入走廊交叉口或走廊拐角处，每个精灵是4-连通的3-6像素小图形，颜色为黄(4)或栗(9)（与走廊条纹色和品红色均不同）。精灵之间不接触。约4-6个精灵。
- 生成约束：粒子按碰撞规则追踪的完整路径经过部分精灵的4-邻域但不经过全部精灵。不同示例中粒子起始行不同，导致路径不同进而访问不同精灵或以不同顺序访问。至少有1个精灵不被任何路径访问。

**规则**：
1. 从品红(6)粒子位置出发，沿走廊追踪路径：
   - 粒子在橙(7)背景格子上沿当前方向直行（初始方向为向右，即列递增方向）。
   - 碰到非背景像素（彩色条纹）时，粒子不进入该像素，而是转90度。转向规则：在与当前方向垂直的两个方向中，选择该方向上有一个橙(7)背景格子且该背景格子两侧被同色条纹夹着的那个方向。
   - 到达网格边缘或两个垂直方向均无合法走廊时停止。
   - 精灵像素不阻挡粒子——粒子视精灵像素为可通行（与背景等同）。
2. 记录粒子路径的有序坐标序列。
3. 对每个精灵，检查路径序列中是否存在与该精灵任一像素4-相邻的坐标。若存在，记录路径中首个满足此条件的坐标的序号（首次接近时刻）。
4. 仅保留被路径接近过的精灵。对每个保留的精灵，裁剪其最小边界框（边界框内仅保留精灵自身颜色像素，其余填黑(0)——不含走廊条纹、品红粒子或橙色背景）。
5. 按首次接近时刻从早到晚排序裁剪图。
6. 将排序后的裁剪图从左到右水平紧密拼接。若裁剪图高度不同，以顶部对齐，高度不足的部分填充黑(0)。
7. 输出为拼接后的条状网格。品红粒子、走廊条纹和橙色背景均不出现在输出中。

**关键洞察**：粒子的路径在输出中完全不可见——它既不被绘制，路径经过的格子也不被标记。路径的唯一作用是作为隐式的排序和筛选依据：决定哪些精灵出现在输出中，以及它们从左到右的排列顺序。求解者必须对比至少两个示例（不同粒子起始位置→不同路径→不同精灵子集和不同排列顺序）才能排除"按空间位置排序"的简单假设，归纳出"路径访问序"这一非显然的排序键。
