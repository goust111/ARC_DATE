## 新题 1：最长对角线选定行反转

**组合逻辑**：[计数/最长线段选中](创新：从对角线段度量变为行选择门控) + [反转/逐行独立](已有) → 对角线长度比较结果决定哪些行执行二值翻转

**来源原语**：计数/counting(aa300dc3), 最长线段选中/longest_selected(aa300dc3), 对角线段/diagonal_segment(aa300dc3), 反转/invert(2de01db2), 逐行独立/row_independent(2de01db2), 主色像素/dominant_pixel(2de01db2), 干扰色像素/distractor_pixel(2de01db2), 主色与背景互换/native_bg_swap(2de01db2)

**依赖链**：必须先度量所有灰色对角线段的长度并选出最长者，才能确定哪些行被选中；被选中的行才执行主色与背景的二值翻转。删除对角线度量环节，无法知道翻转哪些行；删除翻转规则，对角线度量失去作用目标。

在黑色网格中，用散布的灰色像素构成的隐藏对角线段来选定需要执行主色-背景二值翻转的行。

**输入结构**：
- 约 12x12 的网格，背景为黑(0)。
- 若干行包含前景色像素：每行有一种"主色"（该行中出现次数最多的非黑色），另外可能有少量其他非黑色的"干扰色"像素（每行最多 1~2 个干扰像素，颜色与该行主色不同）。不同行的主色可以相同也可以不同，使用蓝(1)、红(2)、黄(4)中的颜色。部分行全为黑色（空行）。
- 网格中散布着若干灰(5)像素。这些灰像素沿 45 度或 135 度方向排列，构成 2~4 条极大连续对角线段（每条至少 2 像素长）。灰像素不出现在含前景色像素的行中（即灰对角线段仅穿过空行或仅含背景的区域）。
- 生成约束：恰好有一条对角线段严格最长（不存在长度并列）。该最长段穿过的行中，至少两行包含前景色像素。

**规则**：
1. 找出所有极大连续灰(5)对角线段（45 度方向和 135 度方向均检查；一条极大段是指无法在同方向上再延长的连续灰像素序列）。
2. 比较所有段的长度，选出唯一最长的那条段。
3. 确定最长段所穿过的行集合 R（段中每个灰像素所在的行号）。
4. 对行集合 R 中每一行，若该行含有前景色像素则执行反转：将该行的主色像素变为黑(0)，将该行其余所有像素（包括原本的黑色背景像素和干扰色像素）变为该行的主色。若该行全为黑色则保持不变。
5. 不在行集合 R 中的行保持原样。
6. 将所有灰(5)像素变为黑(0)（灰标记在输出中消失）。

**关键洞察**：灰像素构成长度不等的隐藏对角线段，仅最长的那条有实际效果——它跨过的行才执行二值翻转。必须度量所有对角线段才能做出选择，而非简单地对每条对角线独立操作。

## 新题 2：X 折叠模板门控楔形填充区

**组合逻辑**：[折叠/对角到边映射](已有) → 折叠产物的逐列非零计数 → [填充/距离递变](创新：楔形行数由折叠结果决定而非固定公式)

**来源原语**：折叠/folding(ca8de6ea), 对角到边映射/diag_to_edge_map(ca8de6ea), 对角线像素/diag_pixel(ca8de6ea), 填充/fill(a65b410d), 距离递变/distance_gradient(a65b410d), 线段/segment(a65b410d), 三角楔形/triangular_wedge(a65b410d), 计数/counting(隐含)

**依赖链**：折叠将 5x5 X 压缩为 3x3 瓦片 → 瓦片每列的非黑像素计数决定对应线段上下方各能扩展多少行楔形填充。若删除折叠步骤，无法获得每列计数，楔形行数无依据；若删除楔形填充，折叠产物无用途。

将 5x5 对角线 X 折叠为 3x3 瓦片，用瓦片每列的非黑像素计数来控制三条水平线段各自楔形填充的扩展行数。

**输入结构**：
- 约 15x15 的网格，背景为黑(0)。
- 左上角有一个 5x5 区域，其中恰好 9 个位于两条对角线上的像素为前景色（可以是多种颜色，来自蓝(1)、红(2)、黄(4)、绿(3)），其余 16 个像素为黑(0)。这 9 个前景像素中部分可能被替换为黑(0)，但至少保留 5 个非黑像素（含中心点）。
- 网格右半部分有三条水平线段，分别位于不同行，每条左端对齐于同一列。三条线段颜色分别为绿(3)、蓝(1)、红(2)（从上到下），长度均为 L（约 3~5 像素）。三条线段之间至少间隔 4 行（为楔形填充留出空间）。
- 生成约束：5x5 X 折叠后的 3x3 瓦片每列至少有 1 个非黑像素、至多 3 个非黑像素。

**规则**：
1. 将左上角 5x5 X 区域按以下映射折叠为 3x3 瓦片：中心像素保持在 (1,1)；西北对角臂映射到顶行从左到中 (0,0)→(0,1)；东北臂映射到右列从上到中 (0,2)→(1,2)；西南臂映射到左列从中到下 (1,0)→(2,0)；东南臂映射到底行从中到右 (2,1)→(2,2)。
2. 统计 3x3 瓦片每列的非黑像素个数：记为 c0、c1、c2（列 0/1/2 的计数，取值范围 1~3）。
3. c0 对应第一条线段（绿(3)）：在该线段上方填充 c0 行楔形，每行宽度 = L + 距离线段的行数（即逐行向上扩展 1 像素），颜色为橙(7)。
4. c1 对应第二条线段（蓝(1)）：在该线段上方填充 c1 行楔形，规则同上，颜色为橙(7)。
5. c2 对应第三条线段（红(2)）：在该线段上方填充 c2 行楔形，规则同上，颜色为橙(7)。
6. 每条线段下方同样填充对应 c 值行数的楔形，每行宽度 = L - 距离线段的行数（逐行向下收缩 1 像素），颜色也为橙(7)。若某行宽度 <= 0 则不填充。
7. 保留三条原始线段不变。5x5 X 区域在输出中全部变为黑(0)。

**关键洞察**：楔形填充的行数不是常数，而是由 5x5 X 折叠后的 3x3 瓦片的列统计值决定的。必须先完成折叠和计数，才能确定每条线段的楔形范围。

## 新题 3：像素增长差排定叠加深度

**组合逻辑**：[计数/两区域比较](已有) → 增长差排序 → [透明叠加/前后遮挡](创新：叠加层序不由空间位置给出，而由计数结果动态决定)

**来源原语**：计数/counting(8597cfd7), 两区域比较/region_comparison(8597cfd7), 最大增长差/maximum_growth_difference(8597cfd7), 透明叠加/transparent_overlay(cf98881b), 前后遮挡/front_back_occlusion(cf98881b), 色彩面板/color_panel(cf98881b), 横分隔线/divider(8597cfd7), 选择/selection(8597cfd7)

**依赖链**：必须先在上下两区域中对每种颜色分别计数并计算增长差，才能排定叠加层序；叠加操作依赖于这一排序结果来决定遮挡优先级。去掉计数环节，叠加无确定的层序；去掉叠加环节，增长差排序无输出载体。

统计三种颜色在灰色分隔线上下区域的像素数量变化，增长最大者位于最前层，将下半区域的三块面板按此深度顺序叠合输出。

**输入结构**：
- 约 11x14 的网格（11 行，14 列），背景为黑(0)。
- 第 5 行（0-indexed）为一条全宽灰(5)水平分隔线。
- 分隔线上方（行 0~4）和下方（行 6~10）各有三块颜色面板，颜色分别为蓝(1)、红(2)、黄(4)。每块面板是一个与下半区域大小相同的矩形区域（5 行 x 14 列），面板内含若干该色前景像素，其余为黑(0)（黑色部分视为透明）。
- 上下两组面板空间上完全重合（每组三块面板叠在同一 5x14 区域内，各色像素互不重叠）。
- 每种颜色在上方区域的像素数与下方区域的像素数不同，且三种颜色的增长差（下方数 - 上方数）两两不等。
- 生成约束：下方区域中三种颜色的像素在某些位置存在空间重叠可能（即若叠合，部分单元格会有多种颜色竞争），确保叠合结果取决于层序。

**规则**：
1. 对分隔线上方和下方分别统计每种颜色（蓝(1)、红(2)、黄(4)）的前景像素数量。
2. 计算每种颜色的增长差 = 下方像素数 - 上方像素数。
3. 按增长差从小到大排序三种颜色。增长差最小的颜色层序最靠后（最先绘制，最底层），增长差最大的颜色层序最靠前（最后绘制，最顶层）。
4. 输出一个 5x14 的网格（即下半区域的尺寸）。在全黑画布上，按层序从底层到顶层依次绘制下方区域中各颜色的前景像素：先绘增长差最小的颜色的所有像素，再绘中间值颜色的所有像素（覆盖冲突位置），最后绘增长差最大的颜色的所有像素（覆盖冲突位置）。
5. 未被任何面板覆盖的单元格保持黑(0)。

**关键洞察**：上半区域纯粹是计数参考——它不直接参与输出，但通过与下半区域的像素数对比，隐式编码了叠加层序。三种颜色的深度优先级必须跨区域计算才能确定。

## 新题 4：双掩码布尔余集作为克罗内克种子

**组合逻辑**：[布尔运算/双掩码交集输出](创新：余集输出不作为最终结果，而作为种子掩码) → [像素放大/克罗内克自积](已有) → 余集结构被自相似放大

**来源原语**：布尔运算/boolean_op(6430c8c4), 对齐/alignment(6430c8c4), 双掩码交集输出/bg_intersection_out(6430c8c4), 掩码区域/mask_region(6430c8c4), 分隔线/divider_line(6430c8c4), 像素放大/pixel_upscale(80af3007), 掩码克罗内克自积/kronecker_self(80af3007), 二值掩码/binary_mask(80af3007), 自相似嵌套/self_similar_nest(80af3007)

**依赖链**：必须先从两个掩码的布尔余集运算中获得一个小型二值掩码，才能进行克罗内克自积展开。去掉布尔步骤，没有种子掩码；去掉克罗内克步骤，布尔余集只是一个小矩阵而非最终输出。

将两个由分隔线分开的前景掩码做布尔余集运算得到一个 3x3 二值掩码，再对该掩码执行克罗内克自积生成自相似的 9x9 输出。

**输入结构**：
- 约 7x3 的网格（7 行，3 列）。
- 第 3 行（0-indexed）为一条全宽橙(7)水平分隔线（1 像素高）。
- 分隔线上方为 3x3 区域，含蓝(1)前景像素和黑(0)背景像素。
- 分隔线下方为 3x3 区域，含红(2)前景像素和黑(0)背景像素。
- 两个 3x3 区域各有若干前景像素（各 3~6 个），布局使得它们的前景并集不覆盖全部 9 个位置（即余集非空），同时余集也不覆盖全部位置（即并集非空）。
- 生成约束：布尔余集（两个区域中均为背景的位置集合）恰好有 3~6 个"亮"位置，确保克罗内克自积的输出不过于稀疏也不过于密集。

**规则**：
1. 移除分隔线行，将上方 3x3 和下方 3x3 逐单元格对齐。
2. 计算布尔余集：若某位置在上方区域为黑(0) **且** 在下方区域也为黑(0)，则该位置为"亮"（on）；否则为"暗"（off）。得到一个 3x3 二值掩码 M。
3. 对 M 执行克罗内克自积：构建 9x9 输出网格，M 中每个"亮"位置替换为 M 自身的 3x3 副本（用绿(3)表示亮像素），每个"暗"位置替换为 3x3 全黑(0)块。
4. 输出 9x9 网格。

**关键洞察**：布尔余集运算本身不生成最终图案——它是一个中间步骤，其输出作为种子被克罗内克自积递归放大。两步操作之间存在信息变换：余集的空间分布决定了自相似结构的全局形态。

## 新题 5：标尺长度定位对称轴修复占位符

**组合逻辑**：[计数（标尺度量）](创新：标尺长度不控制重复次数，而定位对称轴偏移) → [对称补全/双轴反射轨道](已有，但轴位置由外部输入而非居中默认)

**来源原语**：对称补全/symmetry_completion(903d1b4a), 双轴反射轨道/two_axis_orbit(903d1b4a), 占位标记/placeholder_marker(903d1b4a), 轨道内唯一可见色/unique_color_in_orbit(903d1b4a), 标尺条/ruler_bar(9c1e755f), 端部附着/attached_at_end(9c1e755f), 标尺长度决定重复/ruler_length_repeat(9c1e755f), 重涂色/recolor(903d1b4a)

**依赖链**：必须先度量两条标尺的长度才能确定双轴反射的轴位置，之后才能定义反射轨道来修复绿色占位符。删除标尺度量，对称轴位置不确定，修复无法执行；删除对称补全，标尺度量失去意义。

度量从图案边缘伸出的两条灰色标尺的长度来定位水平和垂直对称轴，然后沿这两条轴的反射轨道修复所有绿色占位符。

**输入结构**：
- 约 12x12 的网格，背景为黑(0)。
- 网格中央偏右下有一个矩形彩色图案区域（约 7x7），包含多种前景色（来自蓝(1)、红(2)、黄(4)、品红(6)），部分像素被替换为绿(3)占位符。
- 从图案区域的**左边缘中点**向左延伸出一条水平灰(5)标尺条（长度 h 像素，1 <= h <= 图案宽度-1）。
- 从图案区域的**上边缘中点**向上延伸出一条垂直灰(5)标尺条（长度 v 像素，1 <= v <= 图案高度-1）。
- 两条标尺均为 1 像素宽的直线段，不进入图案内部。
- 生成约束：将垂直对称轴设在图案左边缘右移 h 列处、水平对称轴设在图案上边缘下移 v 行处后，图案中所有包含绿(3)的反射轨道（4 元组或 2 元组或单元组）内的非绿像素恰好有唯一一种颜色。图案中绿色占位符数量约占总像素的 20%~35%。

**规则**：
1. 度量水平灰标尺的长度 h（灰像素个数）和垂直灰标尺的长度 v。
2. 确定垂直对称轴位置：图案区域左边缘列号 + h（即从图案左侧向右偏移 h 列）。确定水平对称轴位置：图案区域上边缘行号 + v（即从图案顶部向下偏移 v 行）。
3. 对图案区域内每个像素，计算其在水平反射和垂直反射下的全部轨道伙伴（最多 4 个位置，含自身；轴上的位置伙伴可能少于 4 个）。
4. 对每个含绿(3)占位符的轨道，找到轨道中唯一的非绿、非黑前景色，用该色替换轨道内所有绿(3)像素。
5. 移除标尺：将所有灰(5)像素变为黑(0)。
6. 输出完整网格。

**关键洞察**：对称轴不在图案的几何中心，而是由外部标尺的物理长度指定。标尺并非装饰或重复计数器——它编码的是一个几何参数（轴偏移量），改变轴位置会完全改变每个占位符应修复为什么颜色。

1. 裁剪出框架内部矩形（去掉灰色框线）。
2. 将内部矩形等分为四个象限：左上、右上、左下、右下。

6. 从空心矩形顶部向上填充三角楔形：宽度从矩形宽度（3）开始，逐行向上扩展 1 像素（左右各扩 0.5 取整：向上第 d 行宽度 = 3 + 2d，居中于矩形中心列），颜色为 C_L。最多扩展到裁剪区域上边界。

8. 输出裁剪后的内部区域。

**关键洞察**：角标图例色不再只是给掩码着色——它决定了桥梁的色彩分裂方案和楔形的颜色及方向。两个像素的象限位置同时编码了三个操作（重涂、桥接分色、楔形填充方向）的参数。

**依赖链**：必须先从梳状结构解码计数值，才能排序；排序结果决定颜色在格子中的列位置和填充深度；镜像作为最终变换作用于已填充的格子。删除计数解码，排序无依据；删除格子填充，排序和镜像无输出载体；删除镜像，无法得到正确输出。

- 约 15x18 的网格，背景为黑(0)。

- 网格下半部分有 C 条垂直色条，从左到右排列，每条颜色各不相同（使用蓝(1)、红(2)、黄(4)、品红(6)、橙(7)中的 C 种）。每条色条宽 1 像素，高度约 2~3 像素。
- 每条色条底部紧接一个梳状结构：由交替的 3 像素宽实心行和 1 像素宽侧对行组成。实心行数量即为该色条编码的计数值 k（1 <= k <= R）。梳状结构使用与色条相同的颜色。
- 生成约束：C 条色条的计数值两两不等。

**规则**：
1. 对每条色条，解码其梳状结构中的实心 3 像素行数量，得到计数值 k。
2. 按计数值从小到大排列所有色条。排列结果定义一个颜色序列 [颜色_1, 颜色_2, ..., 颜色_C]（颜色_1 的计数最小）。
3. 在格子中填充：颜色_i 填入格子的第 i 列（i 从 0 开始，即计数最小的颜色填最左列）。在该列中从顶部向下填充 k_i 行（k_i 为该颜色的计数值），每个单元格填为该颜色。未被填充的单元格保持黑(0)。
4. 将填充完毕的格子（含灰色框线）水平镜像（左右翻转列顺序）。
5. 输出镜像后的格子区域（不含色条和梳状结构）。

**关键洞察**：梳状高度具有双重角色——既是排序键（决定哪种颜色进入哪一列），又是填充深度（决定该列填多少行）。镜像翻转使得最终输出中计数最小的颜色反而出现在最右列，增加了从输出反推规则的难度。

## 新题 8：克罗内克列密度路由颜色车道

**组合逻辑**：[像素放大/克罗内克自积](已有) → 列密度统计 → [滑动/颜色编码列](创新：车道列号不是颜色的固定映射，而由克罗内克结构动态决定)

**来源原语**：像素放大/pixel_upscale(80af3007), 掩码克罗内克自积/kronecker_self(80af3007), 二值掩码/binary_mask(80af3007), 自相似嵌套/self_similar_nest(80af3007), 滑动/slide(f45f5ca7), 擦除/erase(f45f5ca7), 边缘像素/edge_pixel(f45f5ca7), 颜色编码列/color_coded_col(f45f5ca7), 颜色决定目标列/color_determines_col(f45f5ca7), 计数/counting(隐含)

**依赖链**：必须先对 3x3 掩码执行克罗内克自积并统计 9x9 结果中各列的"亮"像素数，才能建立颜色→车道列号的映射表；之后才能将左边缘的有色像素滑入正确车道。删除克罗内克步骤，车道映射无来源；删除滑动步骤，克罗内克结构无实际应用。

将一个 3x3 二值掩码做克罗内克自积得到 9x9 结构，按各列亮像素数从多到少排序确定颜色→车道映射，再将左边缘的彩色像素滑入各自车道。

**输入结构**：
- 约 9x12 的网格，背景为黑(0)。
- 最左列（列 0）上散布着若干有色像素（每行最多一个），颜色来自蓝(1)、红(2)、黄(4)、绿(3)中的若干种（最多 4 种）。每种颜色至少出现 1 次。
- 网格右侧某处有一个 3x3 区域，其中部分像素为灰(5)（"亮"），其余为黑(0)（"暗"），构成一个二值掩码。亮像素数量在 3~6 之间。
- 生成约束：3x3 掩码的克罗内克自积产生的 9x9 结构中，各列亮像素数两两不等（确保车道排序无并列）。左边缘像素所用的颜色种类数不超过 9（实际至多 4 种）。网格行数 >= 9 以容纳克罗内克结构。

**规则**：
1. 提取 3x3 二值掩码 M（灰 = 亮，黑 = 暗）。
2. 计算 M 的克罗内克自积：构建 9x9 网格 K，M 中每个亮位置替换为 M 自身副本，每个暗位置替换为 3x3 全暗块。
3. 统计 K 中每列（列 0~8）的亮像素数量，得到 9 个列密度值。
4. 将这 9 列按密度从大到小排序。密度最大的列排名第 1，次大排名第 2，以此类推。
5. 确定左边缘像素中出现的颜色种类，按颜色在左边缘从上到下首次出现的顺序排列为 [c_1, c_2, c_3, ...]。
6. 建立车道映射：c_1 的目标车道 = 密度排名第 1 的列号，c_2 的目标车道 = 密度排名第 2 的列号，以此类推。
7. 擦除左边缘（列 0）所有有色像素（变为黑(0)）。
8. 对每个被擦除的像素，在其原始行、映射后的目标列绘制该颜色。
9. 将 3x3 掩码区域变为全黑(0)（掩码在输出中消失）。
10. 输出完整网格。

**关键洞察**：车道分配不是颜色的固有属性，而必须从 3x3 掩码的自相似展开结构中动态计算。同一种颜色在不同掩码下会被路由到完全不同的列，因此必须先完成克罗内克展开和密度统计。

- 约 15x15 的网格。

- 恰好一个区域内含有一个小型彩色瓦片图案（约 n x n，n 约 3~4，含多种前景色），且该瓦片内恰好有一整行或一整列由单一颜色填满（引导行/引导列）。其余区域均为纯背景色。

**规则**：
1. 识别栗(9)色的全行分隔线和全列分隔线，计算分区数：R 行 x C 列。
2. 找到唯一含有非背景色图案的区域，提取其中的 n x n 瓦片。
3. 在瓦片中识别引导线：若某行所有 n 个像素为同一非背景非栗色，则为引导行，记其行索引为 g；若某列所有 n 个像素为同一非背景非栗色，则为引导列，记其列索引为 g。

6. 若引导线是列：将瓦片复制到块列 g 的所有 R 个块位置中。其余块保持全黑。
7. 输出画布。

**关键洞察**：网格的宏观分区结构（分隔线数量）和微观瓦片内容（引导线位置）共同且不可分离地决定输出——分区数定画布大小，引导线定活跃带索引。两个层面的信息必须同时读取。

- 网格中有一个品红(6)控制像素，位于所有灰色矩形和精灵体之外。

**规则**：
1. 提取所有灰(5)矩形及其内部黑色孔洞掩码，按矩形边界框左上角坐标从上到下、同行从左到右排序，编号为 H_0, H_1, ..., H_{N-1}。
2. 提取所有彩色精灵及其掩码。对每个精灵，找到形状全等（二值掩码相同）的孔洞，建立自然匹配：精灵 S_j 自然匹配孔洞 H_{m(j)}。
3. 按自然匹配的孔洞编号对精灵排序：令精灵序列为 [S_{a0}, S_{a1}, ..., S_{a(N-1)}]，其中 S_{ai} 自然匹配 H_i。
4. 计算控制像素相对于所有灰色矩形群的总边界框的方位：
   - 垂直：控制像素在总边界框上方 → 行区 = 0；与总边界框同行带 → 行区 = 1；在总边界框下方 → 行区 = 2。
   - 水平：控制像素在总边界框左方 → 列区 = 0；与总边界框同列带 → 列区 = 1；在总边界框右方 → 列区 = 2。
   - 方位槽号 p = 行区 x 3 + 列区（取值 0~8）。
5. 循环偏移量 d = p mod N。
6. 对精灵序列做循环右移 d 位：新的配对方案为精灵 S_{ai} 嵌入孔洞 H_{(i + d) mod N}。
7. 按新配对方案将每个精灵粘贴到对应孔洞中（精灵像素替换孔洞中的黑色像素，保持精灵原色）。
8. 移除控制像素（品红像素变为黑(0)）。擦除所有精灵原位置（精灵原位像素变为黑(0)）。
9. 输出完整网格。

**关键洞察**：形状匹配给出的"自然"配对不一定是最终配对。控制像素的方位编码了一个循环偏移量，使精灵被重新分配到不同的孔洞中。同一组精灵和孔洞在不同控制像素位置下会产生完全不同的嵌入结果。
