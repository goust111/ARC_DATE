## 新题 1：NOR 掩码驱动精灵印章阵列

**组合逻辑**：[逻辑运算/NOR](已有) → [NOR 结果作为印章放置掩码](创新：NOR 输出从终态变为中间调度信号) → [印章覆盖/stamp](已有，但放置位置由外部逻辑运算决定而非自身颜色频率)

**来源原语**：逻辑运算/logical_op、二值掩模/binary_mask、分隔条/separator_bar、逐像素对应/pixelwise_correspond、逻辑或非合并/logical_NOR_combine（来自 1b2d62fb）；印章覆盖/stamp、精灵体/sprite、阵列排布/array_layout（来自 c3e719e8）

**依赖链**：NOR 运算的输出不再是最终答案，而是一个布尔放置掩码；该掩码决定 3x3 阵列中哪些槽位接收精灵体的完整拷贝。精灵体提供"印什么"，NOR 提供"印在哪"——两者缺一不可。

将两个二值掩码的 NOR 结果用作印章放置指令，把精灵体拷贝到 NOR 激活位置对应的输出阵列槽中。

**输入结构**：约 3x9 或 3x7 的网格（高 3 行，宽由两个面板 + 分隔列决定）与下方一个 3x3 精灵区域垂直排列，整体约 7x9。具体布局：
- 上半区包含两个 3x3 的二值掩模面板，左右排列，中间由一列蓝(1)分隔条隔开。每个掩模中，栗(9)表示激活像素，黑(0)表示非激活像素。
- 上半区与下半区之间有一行黑(0)空行。
- 下半区是一个 3x3 的彩色精灵体（使用 2-3 种非黑非栗非蓝颜色，例如红(2)、绿(3)、黄(4)），不含黑(0)像素。
- 生成约束：两个掩模的 NOR 结果至少有 2 个激活位且至少有 1 个非激活位，以确保输出不退化为全部印章或全部空白。

**规则**：
1. 定位蓝(1)分隔列，将上半区分为左掩模 L 和右掩模 R（均为 3x3）。
2. 逐像素计算 NOR(L, R)：当 L 和 R 在对应位置均为黑(0)（非激活）时，该位置为激活；其余为非激活。
3. 创建 9x9 的全黑(0)输出网格，将其划分为 3x3 的阵列槽（每个槽 3x3 像素）。
4. NOR 结果中第 r 行第 c 列为激活的位置，将精灵体完整拷贝到输出网格中第 r 行第 c 列对应的 3x3 槽中。非激活槽保持黑(0)。

**关键洞察**：放置掩码既非来自精灵体自身的颜色频率统计（区别于 c3e719e8），也非 NOR 运算的直接可视化（区别于 1b2d62fb），而是 NOR 的逻辑结果在语义上被重新解释为空间调度指令——需要先识别 NOR 逻辑，再理解其输出如何控制印章放置。

## 新题 2：杯口朝向决定对称轴的内部图案补全

**组合逻辑**：[开口朝向检测](已有) → [开口方向定义镜像轴](创新：开口方向从射线发射方向重新解释为对称轴方向) → [镜像/对称补全](已有，但轴由外部几何属性动态决定) → [洪泛填充/flood_fill](已有，填充镜像后剩余空腔)

**来源原语**：杯形轮廓/cup_outline、开口/opening、开口朝向/opening_direction、开口决定延伸向/opening_extend_dir（来自 d4f3cd78）；镜像/mirror、对称补全/symmetry_completion、对称/symmetry（来自 c35c1b4c / 47c1f68c）；洪泛填充/flood_fill、封闭区域/enclosed_region（来自 c0f76784）

**依赖链**：杯口方向决定对称轴的朝向（左右开口→垂直轴，上下开口→水平轴）；对称轴决定图案如何镜像复制到空白半区；镜像完成后仍可能存在的空白内部像素才由洪泛填充处理。三步之间，前一步的输出构成后一步的前提条件。

检测杯形轮廓的开口方向以确定内部图案的对称轴，将图案沿该轴镜像补全，再用轮廓色填充剩余内部空洞。

**输入结构**：约 12x12 的黑(0)背景网格。
- 一个灰(5)杯形轮廓：由一像素宽的灰(5)像素构成的近封闭矩形框（约 7x7 至 9x9），在上、下、左、右四边之一有一个 2-3 像素宽的缺口（开口）。不同示例中开口位于不同边。
- 杯内部（轮廓围合区域除去轮廓像素本身）分为两半：与开口相对的那一半包含一个由 2-3 种颜色（如红(2)、蓝(1)、黄(4)）组成的不规则小图案（4-连通，3~8 像素），另一半全为黑(0)。
- 杯外部全为黑(0)。
- 生成约束：图案严格位于内部空间与开口相对的那一半中（以内部空间中轴为界），且图案不接触轮廓像素（至少间隔 1 像素），以保证镜像后不与轮廓重叠。

**规则**：
1. 识别灰(5)杯形轮廓的开口位置：找到轮廓边界框四条边中缺少灰(5)像素的那段间隙所在的边。
2. 根据开口所在边确定对称轴：
   - 开口在右边 → 对称轴为杯内部空间的垂直中线（左右镜像）
   - 开口在左边 → 对称轴为杯内部空间的垂直中线（左右镜像）
   - 开口在上边 → 对称轴为杯内部空间的水平中线（上下镜像）
   - 开口在下边 → 对称轴为杯内部空间的水平中线（上下镜像）
3. 将图案中的每个彩色像素沿对称轴反射到另一半对称位置，保持原色。若反射目标位置已被轮廓占据（不应发生，见生成约束），则跳过该像素。
4. 镜像完成后，杯内部空间中仍为黑(0)的所有像素（既非原始图案、亦非镜像图案、亦非轮廓的位置）用灰(5)洪泛填充。
5. 杯外部区域和轮廓像素保持不变。

**关键洞察**：开口方向在源题 d4f3cd78 中决定射线发射方向，这里被重新解释为对称轴方向——开口所在的边揭示了图案"缺失的那一半"在哪里。必须对比多个示例（不同开口方向）才能归纳出开口与对称轴的对应关系。

## 新题 3：XOR 可见区约束下的对角调色板同心环绘制

**组合逻辑**：[异或/xor](已有) + [对角线标记读取调色板](已有) → [XOR 激活区域作为同心环的可见性遮罩](创新：XOR 不再是终态输出，而是空间约束层；同心环不再无条件铺满框内，而是被 XOR 遮罩裁剪) → [同心层填充/concentric_fill](已有，但受外部遮罩约束)

**来源原语**：异或/xor、分隔行/separator_row、掩码/mask、对齐/alignment、逐像素异或输出/pixelwise_xor_output（来自 3428a4f5）；同心层填充/concentric_fill、对角线标记/diagonal_marker、嵌套层次/nesting_hierarchy、对角序映射色环/diagonal_color_bands（来自 99306f82）

**依赖链**：XOR 运算产生一个布尔激活区域，该区域的边界框中心成为同心环的几何中心；对角线标记提供环的调色板；同心环仅在 XOR 激活像素上可见。三个信息源（两个掩模提供形状、对角标记提供颜色）通过 XOR + 同心距离映射交汇为输出。

对两个二值掩码取 XOR 得到激活区域，以该区域边界框中心为原点、对角线标记色序为调色板，在激活像素上绘制同心方环。

**输入结构**：约 13x11 的网格，分为三个区段：
- 上段：5 行 N 列（N 约 7~9）的二值掩模，红(2)为激活像素，黑(0)为非激活像素。
- 中段：一行黄(4)分隔行，宽度与掩模相同。
- 下段：5 行 N 列的二值掩模，格式同上。
- 在网格右下角或右侧空白区域，有 2~4 个单像素颜色标记沿右下方向排列成一条连续对角线（每个标记颜色不同且非红(2)、非黄(4)、非黑(0)，例如蓝(1)、绿(3)、橙(7)）。对角线从左上到右下依次为第 1、第 2、第 3 色。
- 生成约束：两个掩模的 XOR 结果至少有 8 个激活像素，且激活区域边界框至少 3x3，以保证至少 2 层同心环可见。对角标记数量不少于激活区域中心到边界框角的最大 Chebyshev 距离 +1。

**规则**：
1. 定位黄(4)分隔行，将网格分为上掩模 T 和下掩模 B（尺寸相同）。
2. 逐像素比较 T 和 B：凡对应位置一个为红(2)、另一个为黑(0)（即恰好有一个激活），标记为 XOR 激活；两者相同则标记为非激活。
3. 输出网格尺寸与每个掩模面板相同，初始化为全黑(0)。
4. 计算所有 XOR 激活像素构成的边界框，取该边界框的中心坐标 (cr, cc)（若边界框边长为偶数，取左上偏中心，即 floor((min_r+max_r)/2), floor((min_c+max_c)/2)）。
5. 读取对角线标记颜色序列，按从左上到右下的顺序索引为 palette[0], palette[1], ...
6. 对每个 XOR 激活像素 (r, c)，计算其到中心 (cr, cc) 的 Chebyshev 距离 d = max(|r-cr|, |c-cc|)。若 d < len(palette)，填充 palette[d]；若 d >= len(palette)，填充 palette[最后一个]。非激活像素保持黑(0)。

**关键洞察**：XOR 结果在源题 3428a4f5 中就是最终输出，这里它退化为一个中间布尔层，真正的输出由同心距离映射到对角调色板产生。求解者必须先发现 XOR 逻辑确定"哪些像素有颜色"，再发现 Chebyshev 距离确定"每个像素是什么颜色"——两个推理步骤缺一不可。

## 新题 4：箭头几何属性双重编码——方向与周期射线

**组合逻辑**：[横杆偏移定方向](已有) + [箭头杆长度作为周期步长](创新：杆长从静态形态属性重新解释为动态参数) → [射线延伸/ray_extend](已有，但从连续变为周期性) → [周期填充/periodic_fill](已有，但步长来自几何属性而非两个标记点的间距)

**来源原语**：箭头精灵/arrow_sprite、矩形边框/rectangular_frame、边框端点/frame_endpoint、朝向对齐/orientation_aligned、横杆偏移定方向/crossbar_determines（来自 689c358e）；射线延伸/ray_cast、周期步长/periodic_step、周期填充/periodic_fill、同余对齐/modular_alignment（来自 16de56c4）；计数/counting（来自 c3e719e8 / 9af7a82c）

**依赖链**：箭头精灵的横杆偏移决定方向（从 689c358e 继承），箭头杆的像素长度被重新解释为周期步长（全新结构关系），两者共同控制从边框端点向外发射的周期性射线。没有方向信息不知道射向哪，没有杆长信息不知道间隔多少像素打一个点。

从箭头精灵的横杆偏移读取方向、从杆长读取周期步长，在矩形边框外沿该方向每隔该步长打一个点。

**输入结构**：约 15x15 的黑(0)背景网格。
- 一个一像素宽的灰(5)矩形边框，约 7x7 至 9x9，位于网格中央偏置，保证边框到网格边缘在四个方向上均有至少 3 像素的空间。
- 边框内部为黑(0)背景，其中有 2~3 个单色 T 形箭头精灵（每个精灵由 6 个像素组成：一条长度为 3 或 4 的直线杆 + 一条长度为 3 的横杆，横杆在杆上偏向一端，偏向的那一端即为箭头指向的方向）。每个精灵颜色不同（从红(2)、蓝(1)、绿(3)、橙(7)、品红(6)中选取），精灵之间互不接触，且不接触边框。
- 边框外部全为黑(0)。
- 生成约束：每个箭头指向的方向上，从其杆的指向端出发沿该方向到达边框的路径上无其他精灵像素阻挡。不同箭头指向不同的边框边（不会有两个箭头射向同一段边框边）。

**规则**：
1. 对每个箭头精灵，通过横杆偏移确定指向方向（上/下/左/右）：横杆在杆上靠近哪一端，那一端就是箭头尖端方向（同 689c358e）。
2. 沿指向方向从箭头尖端出发，直线前进到边框，确定射中的边框像素位置 P。将 P 涂为该精灵的颜色（覆盖灰(5)）。
3. 计算该箭头杆的像素长度 k（杆是精灵中那条较长直线的像素数量，不含横杆独有像素）。
4. 从 P 出发沿同一方向向边框外部延伸。在距 P 为 k、2k、3k、... 的每个位置涂上该精灵的颜色，直到超出网格边界为止。中间位置保持黑(0)。
5. 同时，在边框上与 P 对边对称的位置（同行或同列的另一端边框像素）涂黑(0)（覆盖灰(5)）。
6. 不同精灵的射线互不交叉（由生成约束保证），边框上未被射中的像素保持灰(5)。

**关键洞察**：箭头精灵在源题 689c358e 中仅用于标记边框端点（方向信息），杆长从未被利用。这里杆长被赋予全新的语义——周期步长——使得同一个几何对象同时编码了方向和周期两个独立参数。求解者需要意识到"杆长 3 的箭头每隔 3 格打点，杆长 4 的箭头每隔 4 格打点"这一隐含规则，而非简单地画连续射线。

## 新题 5：拉伸线框涌现封闭区域后按面积分色填充

**组合逻辑**：[拉伸/stretch + 连线/connect](已有) → [拉伸后涌现封闭区域](创新：封闭区域不存在于原型中，是拉伸的涌现效应) → [洪泛填充/flood_fill](已有) + [面积决定填充色](已有，但面积由拉伸比例动态决定而非固定)

**来源原语**：拉伸/stretch、连线/connect、紧凑原型/compact_prototype、稀疏骨架锚点/sparse_anchor、线段/line_segment、顶点坐标映射/vertex_coord_mapping、行列独立拉伸/independent_stretch（来自 b0f4d537）；洪泛填充/flood_fill、封闭区域/enclosed_region、包围/enclosure、面积决定填充色/area_determines_fill_color（来自 c0f76784）

**依赖链**：紧凑原型拉伸到骨架锚点上形成放大的线框结构；拉伸后线框围合出封闭区域，这些区域的面积取决于锚点间距（不同示例不同）；封闭区域按面积映射到不同填充色。原型决定了拓扑（哪些区域会封闭），锚点间距决定了面积（面积决定颜色），两者必须同时推理。

将紧凑线框原型拉伸到黄色骨架锚点上，再将拉伸后涌现的各封闭区域按面积大小分别填充不同颜色。

**输入结构**：约 20x10 的网格，由灰(5)填充列分为左右两个面板。
- 左面板（紧凑原型，约 5x5）：黑(0)背景上，由红(2)像素组成的一像素宽线框图案，线框包含水平线段和垂直线段，在端点、拐角、交叉处形成 3~5 个图论顶点，线段围合出 2~3 个大小不同的封闭矩形区域（在紧凑原型中每个区域面积为 1~4 像素）。
- 分隔区：一列或多列灰(5)像素。
- 右面板（骨架画布，约 12x12 至 15x15）：黑(0)背景上散布若干黄(4)单像素点，点的数量和拓扑与左面板顶点一一对应（即排序后行坐标序列和列坐标序列分别可映射），但间距更大。
- 生成约束：黄(4)锚点间距保证拉伸后各封闭区域面积落入三个不重叠区间之一：1~6 像素（小）、7~15 像素（中）、16+ 像素（大）。不同示例的锚点间距不同，因此同一拓扑区域在不同示例中可能落入不同面积区间。

**规则**：
1. 在左面板中识别红(2)线框的图论顶点（端点、拐角、交叉点的坐标）。
2. 将顶点的行坐标排序和列坐标排序，分别与右面板中黄(4)锚点的行坐标排序和列坐标排序建立一一映射。
3. 对左面板中每段红(2)线段（连接两个相邻顶点的水平或垂直线段），在右面板上沿映射后的两个锚点之间绘制红(2)直线（覆盖所有中间像素），形成拉伸后的线框。
4. 识别拉伸后线框在右面板上围合的所有 4-连通黑(0)封闭区域（被红(2)像素完全包围的区域）。
5. 按面积填充每个封闭区域：
   - 面积 1~6 像素 → 填充蓝(1)
   - 面积 7~15 像素 → 填充绿(3)
   - 面积 16 像素及以上 → 填充橙(7)
6. 输出为右面板区域（不含灰分隔列和左面板），保留红(2)线框和黄(4)锚点，填充后的封闭区域显示对应颜色，非封闭的外部黑(0)区域不变。

**关键洞察**：紧凑原型中所有封闭区域面积都很小（1~4 像素），无法区分它们应归入哪个面积区间；只有拉伸到锚点后，面积才因间距差异而分化，从而分色填充。求解者必须理解拉伸是产生面积差异的原因，而非原型本身已经编码了颜色信息。

## 新题 6：双面板叠合后压缩降噪揭示隐藏图案

**组合逻辑**：[透明叠加/transparent_overlay](已有) → [叠合后形成可压缩的块结构](创新：分割信号到两个面板使得单面板压缩无意义) → [压缩/compress + 降噪/denoise](已有，但信号来源是叠合的涌现结构)

**来源原语**：透明叠加/transparent_overlay、擦除/erase、分隔行/separator_row、等高面板/equal_height_panel、分隔对齐/separator_alignment、前景不冲突/no_fg_collision（来自 e98196ab）；压缩/compress、降噪/denoise、瓦片/tile、噪声像素/noise_pixel、网格分块/grid_partitioning、忽略标记取主色/ignore_marker_dominant（来自 5614dbcf）

**依赖链**：两个面板各自持有最终低分辨率图案的一部分信号像素（互不重叠），同时都含有灰色噪声干扰。只有先叠合才能在每个 3x3 块内凑齐足够的信号像素，然后压缩降噪才能正确读出每块的主色。单独对任一面板压缩都会因信号不足而得到错误结果。

移除分隔行叠合两个等高面板的前景信号，再将合并后的大网格每 3x3 块压缩为一个像素（忽略灰色噪声），输出隐藏的低分辨率图案。

**输入结构**：约 19x9 的网格（高 19 行 = 9 行面板 + 1 行分隔 + 9 行面板，宽 9 列）。
- 中段：一行橙(7)分隔行，宽度等于面板宽度。
- 上面板（9 行 x 9 列）和下面板（9 行 x 9 列）：各自以黑(0)为背景。
  - 每个面板在若干位置有彩色前景像素（如红(2)、蓝(1)、绿(3)、黄(4)等），以及散布的灰(5)噪声像素（每个 3x3 块中 0~2 个灰像素）。
  - 两个面板的前景像素在相同局部坐标 (r, c) 处不冲突——即 T[r][c] 和 B[r][c] 不同时为非黑非灰颜色。
  - 将 9x9 网格划分为 3x3 的块格（共 3x3 = 9 个块），每个块在叠合后恰好包含一种主色彩色前景像素（该色至少占块内 5 个位置），其余位置为黑(0)或灰(5)噪声。但在叠合前，这些彩色像素被分配到两个面板中——上面板持有其中一部分，下面板持有另一部分，每个面板在该块内的彩色像素不超过 4 个。
- 生成约束：每个 3x3 块叠合后只含一种非黑非灰前景色（或全为黑和灰表示背景块）。灰(5)像素不超过块内 4 个位置。最终输出中至少有 2 种不同的非黑颜色。

**规则**：
1. 定位橙(7)分隔行，将网格分为上面板 T（9x9）和下面板 B（9x9）。
2. 删除分隔行，将 T 和 B 按局部坐标叠合：对每个位置 (r, c)，若 T[r][c] 为非黑(0)非灰(5)前景色则取 T[r][c]；否则若 B[r][c] 为非黑(0)非灰(5)前景色则取 B[r][c]；否则若任一面板该位置为灰(5)则取灰(5)；否则取黑(0)。得到 9x9 合并网格 M。
3. 将 M 划分为 9 个 3x3 块（行分 3 组、列分 3 组）。
4. 对每个 3x3 块：若块内存在非黑(0)非灰(5)的颜色，输出该颜色（块内只有一种这样的颜色）；否则输出黑(0)。灰(5)像素在此步骤中被忽略。
5. 输出为 3x3 的小网格。

**关键洞察**：信号被刻意分散到两个面板中，任何单独面板在某些 3x3 块内彩色像素不足，直接压缩会误判为背景或错误颜色。叠合不只是前置步骤——它是还原信号完整性的必要操作，使得后续压缩才能正确工作。求解者需要对比多个示例才能发现"分开压缩得到错误结果，必须先叠合"这一隐含约束。

## 新题 7：图例过滤决定哪些象限接收十字镜像图案

**组合逻辑**：[图例作为过滤器](已有) + [包含全部目标色判断](已有，但判断对象从连通分量变为象限区域) → [过滤结果选择性启用象限](创新：过滤机制与象限镜像耦合) → [镜像/mirror](已有，但仅作用于通过过滤的象限) + [擦除/erase](已有，作用于未通过过滤的象限) + [重涂色/recolor](已有，十字色作为镜像涂色源)

**来源原语**：图例区域/legend_region、图例作为过滤器/legend_as_filter、包含全部目标色/contains_all_target_colors、连通分量/connected_component、擦除/erase（来自 d59b0160）；十字图案/cross_pattern、前景遮罩/foreground_mask、象限/quadrant、对称轴定义/symmetry_axis_def、十字色作涂色源/cross_as_palette、镜像/mirror（来自 47c1f68c）；重涂色/recolor（来自 47c1f68c）

**依赖链**：图例列出目标色集合→逐象限检查是否包含全部目标色→通过的象限接收左上象限图案的镜像副本（用十字色涂色），未通过的象限被擦除清空→最后移除十字。图例过滤与象限镜像深度耦合：过滤结果决定"哪些象限参与对称"，而非简单删除匹配对象。

读取图例目标色，检查每个象限是否包含全部目标色，将左上象限的前景图案以十字色镜像到通过筛选的象限，擦除未通过的象限，最后移除十字。

**输入结构**：约 13x13 的网格（奇数边长以保证十字有整数中心）。
- 背景为黑(0)。
- 一条完整的水平线和一条完整的垂直线以相同颜色（如蓝(1)）穿过网格中心，形成十字图案，将网格分为四个象限（左上、右上、左下、右下）。
- 左上象限：包含一个由非黑(0)非蓝(1)颜色组成的小图案（4-连通，3~6 像素，使用 1~2 种颜色，如红(2)、绿(3)），不接触十字线。
- 其余三个象限（右上、左下、右下）：每个象限内有 1~3 个散布的单像素标记，颜色从红(2)、绿(3)、黄(4)、品红(6)中随机选取。
- 在网格的左上角（左上象限的最左上 3x3 区域内），有一个小图例区域：由一像素宽的灰(5)边框（仅底边和右边）围成的 2x2 内部空间，内部包含 1~2 种颜色的像素（目标色集合），例如内部有红(2)和绿(3)各一个像素。图例与左上象限的前景图案不重叠（图例在角落，图案在更中心的位置）。
- 生成约束：至少一个非左上象限通过过滤（其单像素标记的颜色集合包含图例中的全部目标色），至少一个不通过，以保证输出不退化为全部镜像或全部擦除。左上象限始终通过过滤（其前景图案包含全部目标色）。

**规则**：
1. 识别图例区域：找到灰(5)边框围成的区域，读取内部像素的颜色集合作为目标色集合 S。
2. 识别十字图案：找到贯穿网格的水平和垂直同色线，记录十字颜色 C 和中心坐标。
3. 提取左上象限的前景遮罩：左上象限中所有非黑(0)、非蓝(1)（非十字色）、非灰(5)（非图例边框色）的像素位置构成遮罩 M。
4. 对右上、左下、右下三个象限，分别检查其内部单像素标记的颜色集合是否包含全部目标色 S。记为"通过"或"未通过"。
5. 删除十字的行和列（将十字行和十字列上的所有像素设为黑(0)），同时删除图例区域（图例边框和内部像素全设为黑(0)）。网格尺寸不变。
6. 对左上象限：将遮罩 M 中每个像素重涂为十字颜色 C。
7. 对每个"通过"的象限：将遮罩 M 按该象限相对于左上象限的镜像方式（右上 = 水平翻转，左下 = 垂直翻转，右下 = 双向翻转）映射过去，映射后的每个像素涂为十字颜色 C。
8. 对每个"未通过"的象限：将该象限内所有非黑像素擦除为黑(0)。
9. 最终输出保留左上象限的重涂遮罩、通过象限的镜像遮罩，其余区域为黑(0)。

**关键洞察**：在源题 47c1f68c 中，镜像无条件覆盖所有四个象限；在 d59b0160 中，图例过滤用于擦除整个连通分量。这里图例过滤的对象变成了象限（而非连通分量），过滤结果不是"删除匹配者"而是"仅对匹配者执行镜像"——过滤与镜像的结构关系是全新的。必须对比多个示例才能发现"不同象限中标记颜色的完整性决定了该象限是否出现镜像图案"这一规则。
