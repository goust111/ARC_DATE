## 新题 1：孔洞导航——拓扑决定滑动方向

**组合逻辑**：[孔洞数映射](创新：映射目标从颜色改为方向) + [滑动] + [碰撞阻挡] + [墙分隔区域]

**来源原语**：孔洞数映射颜色(hole_count_to_color_mapping, e3721c99) → 创新为孔洞数映射方向；颜色决定方向(color_determines_direction, 9b4c17c4) → 创新为拓扑决定方向；滑动(slide, 9b4c17c4/05f2a901)；碰撞阻挡(collision_blocking, 05f2a901)；分隔墙(partition_wall, 62ab2642)；精灵体(sprite, e3721c99)；封闭区域(enclosed_region, e3721c99)

**依赖链**：精灵体的孔洞拓扑 → 解码滑动方向 → 灰墙约束滑动终点。三步缺一不可：没有孔洞计数则方向不确定；没有灰墙则无停止条件；没有滑动则无空间变换。

将每个精灵体按其内部孔洞数所编码的方向，在灰墙迷宫中滑动至撞墙停止。

**输入结构**：约 15x15 的网格。灰(5)像素构成单像素宽的墙，将黑(0)背景分隔为若干不规则区域。其中 3-4 个区域各包含一个单色 4-连通小精灵体（3-8 像素），精灵体颜色互不相同且非黑非灰，分别取自 {蓝(1)、红(2)、绿(3)、黄(4)}。每个精灵体具有不同数量的封闭孔洞（即被精灵体像素四面完全包围的黑色连通区域）：分别为 0、1、2、3 个孔洞。不同示例中精灵体的具体形状不同，但各自的孔洞数保持固定。生成约束：每个精灵体所在区域在其编码方向上有足够空间使其至少移动 1 格后撞墙；不同精灵体的滑动路径互不冲突。

**规则**：
1. 对每个精灵体，计算其封闭孔洞数（精灵体内部被四面包围的黑色 4-连通区域数量）。
2. 孔洞数编码滑动方向：0 个孔洞 → 向上，1 个 → 向右，2 个 → 向下，3 个 → 向左。
3. 每个精灵体沿其编码方向逐格滑动，保持形状和颜色不变，直到精灵体的边界框边缘与灰墙 4-连通相邻为止（即再移一格就会与灰墙重叠）。
4. 精灵体原位置还原为黑(0)背景。灰墙和不含精灵体的区域保持不变。

**关键洞察**：源题 e3721c99 中孔洞数映射到颜色（视觉属性），源题 9b4c17c4 中载体颜色映射到方向。本题将二者嫁接：拓扑属性（孔洞数）直接编码运动学属性（方向），创造了"拓扑→运动"的新结构关系。求解者必须意识到方向信号不在颜色中，而藏在形状的内部拓扑中。

## 新题 2：金字塔反射交叠——对称扩展遇交集着色

**组合逻辑**：[展开 + 交替填色](来自 db3e9e38) + [镜像](来自 a8610ef7) + [交集差集分别着色](创新：从前景掩码的反射检测推广到两个独立生成结构的几何交叠)

**来源原语**：展开(expand, db3e9e38)；交替填色(alternating_fill, db3e9e38)；中心对称展开(center_expand, db3e9e38)；镜像(mirror, a8610ef7)；反射对称(reflection_symmetry, a8610ef7)；交集差集分别着色(intersection_diff_colored, a8610ef7)

**依赖链**：线段属性 → 金字塔几何生成 → 水平中线镜像 → 交叠检测与三类着色。展开生成金字塔几何，镜像创造第二份拷贝，交叠检测将像素分为三类分别着色。删除展开则无几何体；删除镜像则无交叠对象；删除交集着色则无分类信号。

将一条竖直线段展开为交替色金字塔，关于水平中线镜像后，按交叠关系三类着色。

**输入结构**：约 12x15 的网格，黑(0)背景。网格上半区有一条蓝(1)竖直线段（3-5 格长），占据一个列的连续若干行。线段不跨越网格的水平中线。网格高度保证金字塔展开后不会超出上下边界。不同示例中线段的长度和列位置不同，但始终位于上半区。

**规则**：
1. 以线段的底端所在行为基底行，线段所在列为中心列，向下逐行展开居中对称行：基底行宽度 1（即线段本身的底端像素），每向下一行宽度增加 2（左右各扩 1），直到宽度超出网格列范围则停止。每个像素的颜色由其到中心列的水平距离 h 和到基底行的垂直距离 v 共同决定：若 (h + v) 为偶数则着蓝(1)，若为奇数则着绿(3)。
2. 将整个金字塔关于网格的水平中线（若网格高度为 H，中线在第 H/2 行与第 H/2+1 行之间）做上下镜像，生成第二份金字塔。镜像拷贝中每个像素保持其原始颜色不变。
3. 对网格中每个非背景像素位置：
   - 仅原始金字塔覆盖 → 保持其交替色（蓝(1)或绿(3)）。
   - 仅镜像金字塔覆盖 → 重涂为灰(5)。
   - 两者均覆盖（交叠区）→ 重涂为红(2)。
4. 其余位置保持黑(0)。

**关键洞察**：线段在上半区的垂直位置决定金字塔与其镜像的交叠面积——越靠近中线交叠越大，越靠近顶部交叠越小甚至为零。求解者需对比多个示例才能归纳出"交叠区着红、仅原始着原色、仅镜像着灰"的三分类规则，因为单个示例中三种情况可能不全出现。

## 新题 3：自指旋转——角点占用编码自身旋转角

**组合逻辑**：[分类 + 角点占用映射](创新：映射目标从标签数字改为旋转角度) + [旋转](来自 7fe24cdd) + [格元 + 分割线](来自 2546ccf6)

**来源原语**：分类(classification, 27a28665)；角点占用映射标签(corner_occupancy_to_label, 27a28665) → 创新为角点占用映射旋转角；旋转(rotate, 7fe24cdd)；阵列排布(array_layout, 7fe24cdd)；格元(lattice_cell, 2546ccf6)；分割线(divider_line, 2546ccf6)

**依赖链**：此题为自指结构——图案的角点像素既是分类信号又是被变换的数据本身。格元分割 → 提取角点占用 → 映射旋转角 → 旋转格元内容（含角点）。分类与旋转互为依赖：分类读取角点来决定旋转角，旋转改变角点位置。

每个格元的四角占用数编码该格元自身的旋转角度，对格元内容原地旋转。

**输入结构**：约 13x13 的网格。品红(6)像素构成等间距的完整水平线和垂直线（均为单像素宽），将网格分割为 3x3 或 4x4 的等大正方形格元阵列，每个格元内部为 3x3 的可用空间。每个格元内部含有一个由单一前景色（非黑非品红）构成的非对称图案，恰好占 5 个像素（即格元内 9 个位置中有 5 个被前景色占据、4 个为黑(0)背景）。不同格元的前景色和图案形状可以不同。生成约束：每个格元内图案的角点占用数只能是 0、1、2 或 4（不会出现 3）；同一网格内至少出现两种不同的角点占用数。

**规则**：
1. 沿品红(6)分割线将网格切分为格元，提取每个格元的 3x3 内部内容。
2. 对每个格元，检查其四个角位置（左上、右上、左下、右下）中有多少个被前景色占据：
   - 0 个角被占 → 不旋转（0度）。
   - 1 个角被占 → 顺时针旋转 90 度。
   - 2 个角被占 → 旋转 180 度。
   - 4 个角被占 → 逆时针旋转 90 度（即顺时针 270 度）。
3. 对每个格元的 3x3 内容施加对应旋转，旋转结果放回原格元位置。
4. 品红分割线保持不变。

**关键洞察**：这是一道自指谜题——角点像素同时扮演两个角色：它们是决定旋转角度的信号，也是被旋转的数据的一部分。旋转后角点位置改变，但分类是在旋转前完成的。求解者需要意识到信号嵌入在数据之中，而非来自外部标记。

## 新题 4：射线碰撞计数索引图例——几何探测映射符号颜色

**组合逻辑**：[射线延伸](来自 508bd3b6) + [碰撞检测](创新：从反弹改为计数碰撞次数) + [色条图例 + 图例顺序对应](创新：用碰撞计数作为图例索引)

**来源原语**：射线延伸(ray_cast, 508bd3b6)；对角射线(diagonal_ray, 2b9ef948)；碰撞反弹(collision_bounce, 508bd3b6) → 创新为碰撞计数；矩形障碍(rect_obstacle, 508bd3b6)；色条图例(color_bar_legend, 94be5b80)；图例顺序对应插槽(legend_order_to_slot, 94be5b80)；重涂色(recolor, 多题)；擦除(erase, 94be5b80)

**依赖链**：种子像素发射射线 → 射线与障碍的碰撞次数 → 碰撞数索引图例颜色 → 重涂种子像素。射线几何决定碰撞数；图例提供颜色映射；两者在碰撞计数处耦合。去掉射线则无碰撞数；去掉图例则无颜色映射；去掉障碍则所有种子相同。

从种子像素向四个对角方向发射射线，以各射线碰撞障碍的总次数索引色条图例，将种子重涂为对应颜色。

**输入结构**：约 15x18 的网格，黑(0)背景。网格顶部一行包含一个水平色条图例：3-4 个相邻单元格，从左到右分别为蓝(1)、红(2)、绿(3)、黄(4)（图例长度在不同示例中可为 3 或 4）。网格中散布 3-5 个灰(5)矩形障碍（每个为 2x2 至 3x4 的实心矩形），位置各异。另有 3-5 个青(8)种子像素分散于网格中，不与障碍或图例重叠。生成约束：每个种子像素在四条对角射线中至少有一条能碰到某个灰障碍；每个种子的碰撞总数在 1 到图例长度之间（没有碰撞数为 0 或超出图例长度的种子）；不同种子的碰撞总数至少有两种不同值。

**规则**：
1. 对每个青(8)种子像素，从该像素出发沿四个对角方向（左上、右上、左下、右下）各发射一条射线。每条射线逐像素延伸，遇到灰(5)障碍像素或网格边界时停止（不穿透、不反弹）。若射线停止是因为碰到灰障碍（而非网格边界），则计为一次碰撞。
2. 统计每个种子的四条射线的碰撞总数 C（0 <= C <= 4）。
3. 以碰撞数 C 作为图例索引（从左起第 C 个颜色，1-indexed）：C=1 → 图例第 1 色，C=2 → 图例第 2 色，以此类推。
4. 将种子像素从青(8)重涂为对应的图例颜色。射线路径不绘制（不在输出中出现）。
5. 擦除图例（图例区域变为黑(0)）。灰障碍保持不变。

**关键洞察**：在源题 508bd3b6 中射线碰撞导致方向反弹（物理模拟），在源题 94be5b80 中图例位置对应插槽顺序（符号映射）。本题用碰撞计数作为桥梁连接几何探测与符号编码——空间中障碍的分布决定了一个拓扑量（碰撞数），该量再映射到离散的颜色标签。求解者必须先理解射线几何，再发现碰撞数与图例索引的对应关系。

## 新题 5：缺格推断后压缩表——对称补全驱动摘要提取

**组合逻辑**：[对称补全 + 三存一缺推断](来自 2546ccf6) → [提取摘要 + 压缩](来自 ac6f9922)（前者输出是后者的前提条件）

**来源原语**：对称补全(symmetry_completion, 2546ccf6)；三存一缺推断(infer_missing_from_three, 2546ccf6)；块内对称(symmetry_within_block, 2546ccf6)；提取摘要(extract_summary, ac6f9922)；压缩(compress, ac6f9922)；封闭区域(enclosed_region, ac6f9922)；网格表格(grid_table, ac6f9922)；不接触边缘(not_touching_edge, ac6f9922)

**依赖链**：2x2 格中三格有图案 → 对称推断第四格 → 四格完备后压缩为 2x2 摘要。推断与压缩紧耦合：若跳过推断直接压缩，空格元会产生错误的背景色摘要；若只做推断不压缩，输出与输入尺寸相同但仅修补了一个格元。两步的组合产生了源题中不存在的逻辑链。

先通过三格镜像推断补全缺失的第四格图案，再将完整 2x2 表格压缩为每格一色的摘要。

**输入结构**：约 17x17 的网格。橙(7)像素构成单像素宽的十字形分割线（一条水平、一条垂直），将网格分为 2x2 共 4 个大小相等的矩形格元，每个格元内部约 8x8。4 个格元中有 3 个各含一个单色小图案（4-连通，4-10 像素），三个图案颜色相同（取自蓝(1)、红(2)、绿(3)之一），它们是同一基础形状在 2x2 块中对应位置的镜像变体（按格元相对位置做水平和/或垂直翻转）。第 4 个格元内部全为黑(0)背景，即缺失格元。生成约束：三个已有图案中任意一个经适当翻转后都能生成同一基础形状掩码；缺失格元的位置在不同示例中不同。

**规则**：
1. 识别橙(7)分割线，将网格切分为 2x2 的四个格元。
2. 找到空的格元（内部无非黑非橙像素的那个）。
3. 对三个已有图案，根据其在 2x2 块中相对于空格元的位置，分别做水平翻转、垂直翻转、或双向翻转，使其映射到空格元的坐标系。三份翻转结果应一致（因为它们是同一基础形状的不同镜像）。取此一致掩码作为推断图案。
4. 将推断出的图案以与其他三格相同的颜色绘入空格元。
5. 现在四格完备。对每个格元，提取其内部唯一的非黑非橙颜色作为该格元的摘要色。
6. 输出一个 2x2 的小网格，每个单元格填入对应格元的摘要色。

**关键洞察**：单独看这是一个 2x2 单色输出，看似可以直接从三个已有图案的颜色得出（因为四格同色）。但求解者需要对比多个示例才能确认第四格确实与前三格同色（而非某种变色规则），且必须理解"空格 → 推断 → 填入同色"这一完整链条。如果某示例中推断步骤被跳过，空格元输出背景色（黑(0)），与正确答案不同。

## 新题 6：四方汇聚拼合旋转——滑动组装后风车铺排

**组合逻辑**：[滑动 + 最短接触平移](来自 05f2a901) + [旋转 + 四旋转组成风车](来自 7fe24cdd)（滑动的结果成为旋转的输入单元）

**来源原语**：滑动(slide, 05f2a901)；最短接触平移(minimal_contact_shift, 05f2a901)；碰撞阻挡(collision_blocking, 05f2a901)；锚点方块(anchor_square, 05f2a901)；轴对齐(axis_aligned, 05f2a901)；旋转(rotate, 7fe24cdd)；四旋转组成风车(rotations_pinwheel, 7fe24cdd)；阵列排布(array_layout, 7fe24cdd)

**依赖链**：四个散落对象 → 分别向中心锚点最短接触平移 → 围绕锚点组成复合图形 → 以复合图形为瓦片做 2x2 四旋转风车拼贴。滑动步骤决定复合图形的确切形状，旋转步骤将该形状扩展为四倍面积的输出。删除滑动则复合图形不成立；删除旋转则仅得到一份复合图形。

四个散落对象沿轴向滑至中心锚点，组成复合体后做四方向旋转风车铺排。

**输入结构**：约 11x11 的正方形网格，黑(0)背景。网格正中有一个青(8) 2x2 锚点方块。四个象限各有一个小前景对象（4-连通，3-5 像素，形状非对称），颜色互不相同，分别为蓝(1)、红(2)、绿(3)、黄(4)。每个对象与锚点方块轴对齐——即该对象的行范围或列范围与锚点的行范围或列范围有重叠，使其可以沿某个基本方向（上/下/左/右）做直线平移到达锚点旁。生成约束：四个对象到锚点的最短接触平移路径互不冲突（平移后不会互相重叠）；每个对象平移后恰好与锚点 4-连通相邻。

**规则**：
1. 对每个前景对象，找到使其沿轴向（上、下、左、右之一）平移后与青(8)锚点首次 4-连通接触的最短平移。执行该平移，对象原位置还原为黑(0)。
2. 四个对象到位后，与锚点共同构成一个复合图形。提取包含整个复合图形的最小边界矩形作为瓦片（矩形内非对象非锚点的位置保持黑(0)）。
3. 将该瓦片做四方向旋转拼合输出：
   - 左上象限：瓦片原样。
   - 右上象限：瓦片顺时针 90 度旋转。
   - 左下象限：瓦片逆时针 90 度旋转。
   - 右下象限：瓦片旋转 180 度。
4. 输出网格大小为瓦片宽度 x2 乘以瓦片高度 x2。

**关键洞察**：输出的最终风车图案视觉上复杂，但产生它只需两步：先汇聚、后旋转。求解者需要反向推理——从输出的四象限对称性中识别出旋转关系，再从单个象限中识别出多个对象是滑动拼合的结果。锚点方块在两步中都起关键作用：第一步是汇聚目标，第二步是旋转中心。

## 新题 7：选取与对称的双重筛——序位选择叠加反射校验

**组合逻辑**：[每隔N选取 + 按位置排序](来自 22a4bbc2) AND [反射对称 + 交集差集着色](来自 a8610ef7)（两个独立条件同时约束输出，非线性流水线）

**来源原语**：每隔N选取(every_nth_selection, 22a4bbc2)；按位置排序(sort_by_position, 22a4bbc2)；重涂色(recolor, 22a4bbc2)；横条(horizontal_bar, 22a4bbc2)；反射对称(reflection_symmetry, a8610ef7)；交集差集分别着色(intersection_diff_colored, a8610ef7) → 创新为选取条件与对称条件的合取

**依赖链**：这是同时约束结构——输出颜色取决于两个独立条件的合取：(a) 该横条是否被 every-3rd 选中，(b) 该横条是否存在关于水平中线的对称配对。两条件独立评估、联合决定输出，无固定执行顺序。

每个横条的输出颜色由两个独立条件共同决定：序位选取与水平反射对称。

**输入结构**：约 15x12 的网格，黑(0)背景。包含 9-12 个蓝(1)实心水平矩形条（每条宽度至少 3 格、高度 1 格），沿垂直方向排列，条间有黑色间隔。各条的宽度和水平位置（左端列号）不全相同。部分横条在网格水平中线处有对称配对——即存在另一条横条，其行位置关于中线镜像对称，且宽度与列范围完全相同。生成约束：至少有 2 对互为反射对称的横条；至少有 2 个无反射配对的横条；横条总数使得 every-3rd 选取至少命中 3 条。

**规则**：
1. 将所有横条按其所在行从上到下排序，得到序号 1, 2, 3, ...。
2. 选取序号为 1, 4, 7, 10, ... 的横条（即从第 1 条起每隔 3 条选一条），标记为"被选中"。
3. 对每条横条，检查其是否存在反射对称配对：是否存在另一条横条位于关于网格水平中线的镜像行，且列范围完全相同。有配对则标记为"对称"。
4. 根据两个条件的组合决定输出颜色：
   - 被选中 且 对称 → 重涂为红(2)。
   - 被选中 且 不对称 → 重涂为黄(4)。
   - 未选中 且 对称 → 重涂为绿(3)。
   - 未选中 且 不对称 → 保持蓝(1)不变。
5. 背景保持黑(0)。

**关键洞察**：单看一个示例，求解者可能误以为颜色仅由序位或仅由对称性决定。必须对比多个示例才能发现颜色是两个独立布尔条件的 2x2 合取。这两个条件来自完全不同的领域——序位是离散序列属性，对称是几何空间属性——它们在逻辑上独立但在输出中耦合。

## 新题 8：分隔列反射印章的拓扑优先级——孔洞数决定遮挡叠放

**组合逻辑**：[镜像对应 + 分隔列](来自 dd2401ed) + [印章覆盖](来自 94be5b80) + [孔洞数映射](创新：映射目标从颜色改为叠放优先级)

**来源原语**：分隔列(separator_col, dd2401ed)；镜像对应(mirror_correspond, dd2401ed)；印章覆盖(stamp_overlay, 94be5b80)；精灵体(sprite, e3721c99/94be5b80)；孔洞数映射颜色(hole_count_to_color_mapping, e3721c99) → 创新为孔洞数映射叠放优先级；封闭区域(enclosed_region, e3721c99)；擦除(erase, dd2401ed)

**依赖链**：左侧精灵体 → 计算各自孔洞数 → 水平镜像到右侧 → 镜像体在右侧可能重叠 → 孔洞数多者优先覆盖。镜像提供位置，拓扑提供优先级，两者在重叠冲突处耦合。无镜像则无右侧内容；无孔洞计数则重叠无法确定性解决。

将左侧精灵体跨分隔列镜像印章到右侧，重叠时孔洞多者覆盖孔洞少者。

**输入结构**：约 12x20 的网格，黑(0)背景。网格中央有一条贯穿全高的灰(5)垂直分隔列。分隔列左侧有 2-3 个单色精灵体，颜色互不相同（取自 {蓝(1)、红(2)、绿(3)}），每个精灵体为 4-连通的不规则形状（5-10 像素），各自具有不同数量的封闭孔洞（被精灵体像素四面包围的黑色 4-连通区域）：分别为 0、1、2 个。分隔列右侧全为黑(0)。生成约束：将所有左侧精灵体关于分隔列水平镜像后，至少有一对精灵体的镜像体存在像素重叠；精灵体不接触分隔列（至少间隔 1 格）。

**规则**：
1. 对每个左侧精灵体，计算其封闭孔洞数。
2. 将每个左侧精灵体关于灰(5)分隔列做水平镜像，得到其在右侧的目标位置和形状（镜像后颜色不变）。
3. 在右侧绘制所有镜像体。若两个镜像体在某些像素位置重叠，则孔洞数更多的精灵体的像素优先绘制（覆盖孔洞数少的）。孔洞数相同时（生成约束保证不会出现），按原色在左侧出现位置从上到下为序，靠上的优先。
4. 擦除灰(5)分隔列（变为黑(0)）。
5. 左侧精灵体保持不变。

**关键洞察**：在源题 e3721c99 中孔洞数决定重涂颜色（语义映射），在源题 94be5b80 中印章覆盖按图例顺序确定（序列映射）。本题创造了新的结构关系：拓扑复杂度（孔洞数）决定 z-order 叠放优先级。求解者必须先数左侧每个精灵体的孔洞，再预测右侧镜像体重叠时谁覆盖谁。

## 新题 9：对角线段平移后的框架穿越计数着色

**组合逻辑**：[平移绘制 + 长度递增 + 同反对角线](来自 50c07299) + [计数](来自 f3cdc58f) + [封闭区域 + 不接触边缘](创新：框架区域作为计数目标而非摘要容器)

**来源原语**：平移绘制(translate_draw, 50c07299)；同反对角线(same_antidiagonal, 50c07299)；长度递增(length_increment, 50c07299)；计数(counting, f3cdc58f)；重涂色(recolor, 多题)；封闭区域(enclosed_region, ac6f9922)；不接触边缘(not_touching_edge, ac6f9922)

**依赖链**：线段属性 → 计算新位置和新长度 → 绘制于新位置 → 检测与框架的穿越数 → 穿越数决定线段颜色。平移生成新线段的位置（必须先算才知道与哪些框架重叠）；框架分布决定穿越数；穿越数决定最终颜色。删除平移则位置不变、穿越数不变；删除框架则计数无意义；删除计数则颜色不确定。

将反对角线段平移至下一段更长位置，根据新线段穿越的框架数量决定其最终颜色。

**输入结构**：约 15x15 的网格，黑(0)背景。包含一条由绿(3)像素组成的线段，位于某条反对角线上（即从左下到右上方向），长度 L（3-5 像素），占据列 c0 到 c1（c1 = c0 + L - 1）。另有 2-3 个灰(5)像素构成的空心矩形框架（每个框架为单像素宽的矩形边框，内部为黑(0)，大小约 4x4 至 6x6），分散于网格中。部分框架的位置恰好在该绿线段的下一段目标位置的路径上。生成约束：新线段（平移后）经过至少 1 个框架内部区域，且最多经过 3 个；框架彼此不重叠、不接触网格边缘。

**规则**：
1. 擦除当前绿(3)线段。
2. 按 50c07299 规则计算新线段位置：新线段起始列为 c1 + 1，结束列为 c1 + L + 1（长度 L + 1），沿同一条反对角线方向放置（每列行号递减 1）。
3. 在新位置绘制新线段。线段穿越框架时直接覆盖框架边框的灰像素（线段优先）。
4. 计算新线段穿越了多少个框架——即新线段的像素中有多少个落在某个框架的封闭内部区域（不含框架边框本身）内。统计的是穿越的不同框架数量（同一框架即使有多个线段像素穿过也只计 1 次）。
5. 根据穿越框架数 K 重涂线段颜色：K=0 → 绿(3)不变；K=1 → 黄(4)；K=2 → 红(2)；K=3 → 蓝(1)。
6. 灰(5)框架保持不变（被线段覆盖的框架像素除外，那些位置显示线段颜色）。

**关键洞察**：新线段的位置由纯代数规则（平移 + 递增）决定，但其最终颜色取决于空间上下文——它恰好穿过了多少个静态框架。求解者须先计算出新位置，再用该位置与框架做空间交叉检测，最后查颜色映射表。这三步的信息流是单向但不可跳过的。

## 新题 10：面积极值分流与边框导航——双准则同时约束对象命运

**组合逻辑**：[极值面积决定颜色](来自 62ab2642，创新：决定的不是颜色而是行为类别) AND [颜色匹配边 + 朝匹配边移动](来自 5034a0b5)（两条规则同时作用于同一组对象，非顺序执行）

**来源原语**：极值面积决定颜色(extreme_area_determines_color, 62ab2642) → 创新为极值面积决定行为分类；边框边(frame_side, 5034a0b5)；颜色匹配边(color_match_side, 5034a0b5)；朝匹配边移动(move_toward_match, 5034a0b5)；内部像素(interior_pixel, 5034a0b5)；连通区域(connected_region, 62ab2642)；擦除(erase, 多题)；重涂色(recolor, 多题)

**依赖链**：此题为同时约束结构——每个对象被两个独立准则同时评估：面积极值性（决定擦除/冻结/移动三类命运）和颜色-边框匹配（决定移动方向）。两准则对同一对象集并行生效，非先后执行。

按面积极值将内部对象分为擦除、冻结、移动三类，移动类再按颜色-边框匹配确定方向。

**输入结构**：约 12x12 的网格。最外一圈像素构成单像素宽的矩形边框：四个角落为黑(0)，上边全为蓝(1)，下边全为红(2)，左边全为绿(3)，右边全为黄(4)（四条边颜色互不相同）。边框内部为黑(0)背景，散布 4-6 个单色 4-连通前景对象，每个对象的颜色与某一条边框边颜色相同（即对象颜色取自 {蓝(1)、红(2)、绿(3)、黄(4)}），面积（像素数）各不相同。生成约束：面积最大和最小的对象各唯一；面积最大对象颜色与面积最小对象颜色不同；移动类对象（非最大非最小）中每种颜色最多一个；所有移动类对象沿其目标方向移动后不会重叠且不会到达已冻结对象的位置。

**规则**：
1. 计算所有内部前景对象的面积（4-连通像素数）。
2. 面积最小的对象 → 擦除（设为黑(0)，从网格中移除）。
3. 面积最大的对象 → 冻结：重涂为橙(7)，位置不变，后续步骤中充当障碍。
4. 其余对象 → 移动：每个对象的颜色匹配某条边框边，该对象向匹配边方向移动一格（蓝→上移一行，红→下移一行，绿→左移一列，黄→右移一列）。若对象已紧邻其匹配边（再移一格会与边框重叠），则保持不动。
5. 移动后若对象与冻结对象（橙(7)）4-连通相邻，则该移动对象也重涂为橙(7)。
6. 边框保持不变。

**关键洞察**：面积准则和颜色准则独立运作但结果交织——面积决定"做什么"（擦除/冻结/移动），颜色决定"怎么移"（方向）。最微妙的是第 5 步：移动后与冻结体接触导致级联冻结，这是两条规则交互产生的涌现效应，单看任一规则都无法预测。求解者需对比多个示例才能发现级联冻结规则。
