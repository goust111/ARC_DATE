## 新题 1：噪声过滤后的面积排序驱动同心方环调色板

**组合逻辑**：[connected_component + noise_pixel + area_comparison](来自 1f85a75f) → [面积排序创建隐式索引](创新：面积→空间距离的映射关系在源题中不存在) → [concentric_ring + chebyshev_distance + center_aligned](来自 ac0c2ac3)

**来源原语**：connected_component / noise_pixel / area_comparison / keep_largest_component（1f85a75f）；concentric_ring / chebyshev_distance / center_aligned / distance_mapping（ac0c2ac3）；detection（25d8a9c8）

**依赖链**：噪声过滤决定哪些分量参与排序 → 面积排序生成色彩索引序列 → 索引序列按切比雪夫距离映射到同心方环。删除噪声过滤则分量数量错误导致排序和环数不匹配；删除面积排序则无法确定颜色与环的对应；删除距离映射则无输出结构。

将散布在网格中的多色连通分量按面积排序，过滤噪声后，将排序结果映射为以网格中心为原点的同心方环配色。

**输入结构**：一个奇数边长的正方形网格（约 13x13），背景为黑(0)。网格中散布着若干 4-连通单色前景分量，每个分量使用不同颜色（从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7)中选取），面积各不相同（范围约 3~15 像素），形状为不规则连通体（非矩形）。此外有若干孤立的单像素前景点（面积=1），颜色可与某些分量相同或不同，作为噪声干扰。生成约束：有效分量（面积>1）的数量 K 满足 K <= (grid_side - 1) / 2，保证环数不超出网格范围；各有效分量面积互不相等。

**规则**：
1. 找到所有 4-连通单色前景分量，丢弃面积等于 1 的分量（噪声）。
2. 将剩余 K 个有效分量按面积从小到大排序。面积相同时（生成约束保证不会发生），按分量边界框左上角的行优先、列次之的顺序排列。
3. 输出为同尺寸全黑网格。设网格中心像素的切比雪夫距离为 0。对 d = 1, 2, ..., K，将切比雪夫距离恰好为 d 的所有像素填充为第 d 个分量（排序后）的颜色。
4. 切比雪夫距离为 0（中心像素）保持黑(0)。切比雪夫距离 > K 的像素也保持黑(0)。

**关键洞察**：分量的面积是一个隐式排序键，将无序的空间分布转换为有序的距离-颜色映射；噪声像素若不过滤会改变分量计数和排序，导致环配色全面错位。需要对比多个示例才能确认面积排序方向（升序）和噪声过滤阈值（面积=1）。

## 新题 2：区域宽高比编码射线方向，交叉点由源区域面积仲裁

**组合逻辑**：[rect_region + containment + marker_short_axis_div](来自 855e0971) → [射线延伸至全网格](创新：源题中线段止于区域边界，此处延伸到网格边缘) → [crossing + area_comparison 决定交叉色](创新：源题中交叉换色是固定互换，此处用面积比较仲裁)

**来源原语**：draw_line / marker_pixel / rect_region / containment / marker_short_axis_div（855e0971）；crossing / crossing_swapped_to_other_foreground / h_bar / v_bar（ba97ae07）；area_comparison（1f85a75f）；ray_extend（db93a21d）

**依赖链**：区域宽高比决定射线方向（宽→垂直线，高→水平线）→ 射线延伸到全网格后可能与来自其他区域的射线交叉 → 交叉点颜色由两条射线的源区域面积比较决定（面积大的区域颜色胜出）。删除宽高比规则则射线方向不确定；删除面积仲裁则交叉颜色不确定。

矩形区域内的标记沿区域短轴方向射出穿越全网格的射线；当来自不同区域的垂直射线与水平射线交叉时，面积更大的源区域的颜色占据交叉点。

**输入结构**：一个约 15x15 的网格，被划分为若干不重叠、不留缝的非正方形单色矩形区域（类似彩色马赛克拼贴），每个区域填充不同颜色（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取），背景无黑色间隙。部分区域（约 3~5 个）内部各含恰好一个黑(0)标记像素。生成约束：含标记的区域中，至少有一个宽>高（宽型）且至少有一个高>宽（高型），以保证存在方向不同的射线对；各含标记区域面积互不相等。

**规则**：
1. 对每个含标记的区域，判断其宽高比：若区域宽度 > 高度（宽型），射线方向为垂直（沿标记所在列，从网格第 0 行延伸到最后一行）；若区域高度 > 宽度（高型），射线方向为水平（沿标记所在行，从网格第 0 列延伸到最后一列）。
2. 每条射线使用其所在区域的颜色绘制，覆盖路径上的所有像素（包括穿过其他区域的部分）。
3. 绘制顺序：按源区域面积从小到大绘制射线。这意味着面积较大的区域的射线后绘制，在交叉点处覆盖面积较小区域的射线颜色。
4. 不含标记的区域保持原色不变（除非被射线穿过的像素被覆盖）。
5. 标记像素本身也被射线颜色覆盖（即被其所属区域的颜色填充，等同于消除标记）。

**关键洞察**：区域的几何形状（宽高比）隐式编码了射线方向，而非由标记位置或额外标注决定；交叉点的颜色不是简单互换，而是通过面积比较的优先级仲裁。需要对比多个示例才能归纳出"面积大优先"的仲裁规则（而非例如"后画覆盖先画"的位置规则）。

## 新题 3：障碍线触发滑动对象的颜色切换

**组合逻辑**：[sliding + collision_blocking + nearest_cardinal_attract + mass_affects_stops](来自 4093f84a) + [barrier_segment + cross_barrier_pair](来自 1efba499) + [toggle_between_pairs](来自 d2acf2cb)（创新：源题中障碍阻挡移动，此处障碍不阻挡但触发颜色切换；源题中颜色切换在固定位置的线段上发生，此处切换条件依赖于滑动路径是否穿越障碍）

**来源原语**：sliding / foreground_object / attractor / collision_blocking / nearest_cardinal_attract / mass_affects_stops（4093f84a）；barrier_segment / cross_barrier_pair（1efba499）；color_swap / toggle_between_pairs（d2acf2cb）

**依赖链**：吸附方向确定每个对象的滑动路径 → 路径是否穿越障碍线决定颜色是否切换 → 先到达的对象改变碰撞几何，影响后续对象的停靠位置（可能导致后续对象绕过或遭遇障碍）。三个机制同时约束最终结果。

散布的彩色对象朝中央灰色吸附体滑动并停靠；滑动路径穿越红色障碍线的对象，颜色按固定配对规则切换。

**输入结构**：一个约 14x14 的网格，背景为黑(0)。网格中央偏某方向放置一个灰(5)填充矩形（约 2x3 或 3x2，作为吸附体）。一条红(2)线段（水平或垂直，宽度 1 像素，长度 3~6 像素）位于吸附体某一侧，与吸附体平行但不相邻（间距 2~4 格）。网格中散布 4~6 个单像素彩色对象，颜色取自两组切换对：蓝(1)与青(8)为一对，绿(3)与黄(4)为一对。对象分布在吸附体四周，部分对象与吸附体之间隔着红色障碍线，部分不隔。生成约束：每个对象到吸附体的最短基方向（上/下/左/右）位移唯一（无并列最短）；对象互不在同一行或同一列上（避免初始碰撞歧义）。

**规则**：
1. 对每个彩色对象，计算其沿四个基方向到灰色吸附体表面的距离，选择最短的方向作为滑动方向。
2. 按距离从小到大的顺序依次处理对象（最近的先滑动）。
3. 每个对象沿其滑动方向移动，直到与灰色吸附体或之前已停靠的对象相邻为止（不重叠，停在紧邻位置）。
4. 判断该对象的滑动路径（从起点到终点之间经过的所有像素）是否穿越了红(2)障碍线的任何像素：若穿越，则对象颜色切换——蓝(1)变青(8)、青(8)变蓝(1)、绿(3)变黄(4)、黄(4)变绿(3)；若未穿越，颜色不变。
5. 对象以最终颜色停靠在终点位置。已停靠的对象成为后续对象的碰撞障碍（但不合并到灰色吸附体中——只有灰色吸附体本身是吸附目标，已停靠对象仅阻挡路径）。
6. 红色障碍线始终保持不变，不被移除也不被覆盖。
7. 原始位置的对象像素被清除（变为黑色背景）。

**关键洞察**：障碍线不阻挡运动，但改变经过它的对象的颜色属性；处理顺序至关重要——先停靠的对象会改变后续对象的可达路径，可能迫使后续对象绕行从而避开（或被迫穿越）障碍线，最终颜色因此改变。需要多个示例确认切换配对规则和障碍线的"穿越即切换"语义（而非"接触即切换"或"同侧即切换"）。

## 新题 4：最大分量对角铺贴，次大分量充当分隔行颜色

**组合逻辑**：[connected_component + area_comparison + keep_largest_component + crop](来自 1f85a75f) → [concatenate + diag_copy + diag_layout + blank_row_separator](来自 fb791726)（创新：源题中分隔色是固定的绿色，此处分隔色由次大分量的颜色动态决定；源题中没有分量筛选步骤）

**来源原语**：connected_component / noise_pixel / area_comparison / keep_largest_component / crop（1f85a75f）；concatenate / diag_copy / separator_row / diag_layout / blank_row_separator（fb791726）

**依赖链**：分量面积比较确定最大与次大分量 → 最大分量被裁剪并对角铺贴 → 次大分量颜色填入分隔行。删除面积比较则无法确定裁剪目标和分隔色；删除对角铺贴则无输出结构；删除分隔行规则则空白行未着色。

从多个分量中选出最大的进行裁剪和对角铺贴，用次大分量的颜色填充铺贴副本中的空白分隔行。

**输入结构**：一个约 10x10 的网格，背景为黑(0)。网格中有 3~5 个 4-连通单色前景分量，颜色互不相同（从红(2)、绿(3)、黄(4)、蓝(1)、橙(7)中选取）。最大分量（面积约 12~20 像素）的边界框内部具有"行对结构"——前景像素集中在成对的行中，每对之间有一整行全为黑色的空白分隔行。次大分量（面积约 5~10 像素）为不规则形状，位于网格其他位置。其余分量面积更小（2~4 像素）。生成约束：各分量面积互不相等；最大分量的边界框高度 H 和宽度 W 均为奇数（便于对角铺贴对称）；最大分量边界框内至少有 1 行全黑分隔行。

**规则**：
1. 找到所有 4-连通单色前景分量，按面积降序排列。面积相同时按边界框左上角行优先列次之排序（生成约束保证面积不同）。
2. 设最大分量颜色为 C1，次大分量颜色为 C2。
3. 裁剪最大分量的紧致边界框（H x W），保留分量像素为 C1，边界框内不属于分量的像素（内部空洞和分隔行）保持黑(0)。
4. 创建 2H x 2W 的全黑输出画布。将裁剪结果粘贴到左上角 (0,0)-(H-1,W-1) 和右下角 (H,W)-(2H-1,2W-1) 两个对角块中。
5. 在两个对角副本中，将原边界框中的全黑分隔行（该行在裁剪结果中所有像素均为黑(0)的行）的对应位置全部填充为 C2，且填充范围为该行在输出画布中的完整宽度（2W 像素），跨越两个对角块及中间区域。
6. 输出画布中未被副本或分隔行覆盖的区域保持黑(0)。

**关键洞察**：次大分量的唯一作用是提供分隔行颜色——它的形状和位置无关紧要，只有颜色和面积排名有意义。需要多个示例才能确认分隔色来源于次大分量（而非固定颜色或其他规则），以及分隔行的识别标准是"裁剪框内的全黑行"。

## 新题 5：叠加合并标记模式后旋转匹配填充目标框

**组合逻辑**：[overlay + filled_rectangle + marker_pixel + markers_merge + same_size_align](来自 25e02866) → [rotate + center_fixed](来自 f0f8a26d) + [pattern_match + transform_match_fill](来自 7df24a62)（创新：源题 25e02866 只合并不旋转；源题 7df24a62 不需先合并再匹配。此处合并产生的复合标记模式必须经旋转才能匹配目标，两步紧密依赖）

**来源原语**：overlay / filled_rectangle / marker_pixel / shared_base_color / same_size_align / markers_merge（25e02866）；rotate / center_fixed / orient_swap_keep（f0f8a26d）；pattern_match / transform_match_fill / rect_sprite（7df24a62）

**依赖链**：多个矩形的标记合并生成复合模式 → 复合模式经旋转/翻转变换与目标框内已有标记对齐 → 对齐后填充目标框。删除合并则模式不完整；删除旋转匹配则无法确定目标框中的放置方向。

将多个同尺寸灰色矩形中的彩色标记合并为一个复合模式，然后找到该模式的旋转/翻转变体，使其与目标框中已有的锚定标记对齐，最终将完整的合并模式填入目标框。

**输入结构**：一个约 18x18 的网格，背景为黑(0)。网格中有 2~3 个相同尺寸的灰(5)填充矩形（约 4x5 或 5x4），彼此分离。每个矩形内嵌有 1~3 个非灰非黑的标记像素（颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取），不同矩形的标记在对应局部坐标处不冲突（即同一局部位置至多一个矩形有非灰标记）。另有一个相同尺寸的灰(5)空心矩形框（仅边框为灰，内部为黑），框内有 1~2 个彩色锚定标记像素。生成约束：所有源矩形的标记合并后的复合模式，恰好有且仅有一个旋转/翻转变体（0/90/180/270 度旋转，可选左右翻转，共 8 种变换中恰好 1 种）使得复合模式的标记像素与目标框内的锚定标记在相同局部坐标上颜色一致；目标框尺寸与源矩形一致（可能宽高互换以适应旋转）。

**规则**：
1. 识别所有灰(5)填充矩形（内部全为灰和标记色的连通矩形区域）作为源矩形，以及灰(5)空心矩形框（仅边框为灰的矩形）作为目标框。
2. 对每个源矩形，提取其局部坐标系下的标记模式（非灰像素的位置和颜色）。
3. 将所有源矩形的标记模式叠加合并到同一局部坐标系中。由于生成约束保证无冲突，每个局部位置至多有一种标记颜色，其余为灰(5)底色。
4. 对合并后的标记模式（含灰底色的完整矩形），枚举全部 8 种刚性变换（4 种旋转 x 2 种翻转），找到使得变换后模式中的标记像素与目标框中已有锚定标记在相同局部坐标上颜色一致的唯一变换。
5. 将经过该变换的完整合并矩形（灰底色 + 全部合并标记）填充到目标框的位置，覆盖框内原有的黑色区域和锚定标记。目标框的灰色边框保持不变。

**关键洞察**：单个源矩形的标记不足以确定目标框中的旋转方向——只有合并后的复合模式才与锚定标记形成唯一匹配。源矩形的合并顺序无关紧要（因为无冲突），但合并本身是确定旋转的前提。需要多个示例确认"合并后旋转匹配"的流程，而非"分别旋转后叠加"。

## 新题 6：均匀行检测生成隐式障碍，标记跨障碍对称交换

**组合逻辑**：[detection + row + uniform_row_marked_else_black](来自 25d8a9c8)（创新：源题中均匀行被标记为灰色输出，此处均匀行被识别为障碍而非直接标记） → [swap + erase + barrier_segment + cross_barrier_pair + one_each_side](来自 1efba499)

**来源原语**：detection / row / uniform_row_marked_else_black（25d8a9c8）；swap / erase / marker_pixel / barrier_segment / cross_barrier_pair / one_each_side（1efba499）

**依赖链**：均匀行检测确定障碍位置（输入中并无显式障碍标记）→ 标记像素的跨障碍配对依赖于已识别的障碍行 → 配对后执行位置交换。删除检测则障碍位置不可知；删除交换则标记不移动。

先检测哪些行是单色均匀行（这些行充当隐式障碍），然后将位于障碍两侧同列的标记像素对称交换到障碍另一侧的紧邻位置。

**输入结构**：一个约 12x10 的网格。网格由若干行组成，部分行内所有像素颜色相同（均匀行，颜色不限，可以是蓝(1)、红(2)、绿(3)等任意非黑色），其余行包含多种颜色的混合像素。在非均匀行中，散布着若干黑(0)标记像素（与多彩背景形成对比）。生成约束：标记像素成对出现——每一对在同一列上，分别位于同一条均匀行的上方和下方（即一个在均匀行上方的某非均匀行，另一个在均匀行下方的某非均匀行），且两者之间恰好只隔着一条均匀行（它们之间可以有其他非均匀行，但有且仅有一条均匀行）；不存在落单的标记。

**规则**：
1. 逐行检测：若某行所有像素颜色完全相同，则该行为"障碍行"。
2. 对每一列，扫描该列中的黑(0)标记像素。对于同一列中被恰好一条障碍行分隔的一对标记（一个在障碍行上方，一个在下方），执行交换操作。
3. 交换规则：擦除两个标记像素的原位置（恢复为该位置在输入中被标记替换前的颜色——由于标记为黑(0)而非均匀行的颜色，交换后原位置恢复为黑(0)以外的值需要另行处理）。修正：由于输入中标记像素就是黑(0)，而这些行是非均匀行（包含多种颜色），标记像素的"原始颜色"未知。因此规则改为：将上方标记移动到障碍行下方的紧邻行（障碍行行号+1）的同一列，将下方标记移动到障碍行上方的紧邻行（障碍行行号-1）的同一列。两个新位置都涂黑(0)。两个原始位置恢复为所在行中最常见的非黑颜色。
4. 障碍行本身保持不变。无配对的标记保持不变。

**关键洞察**：障碍不是由特殊颜色或符号标出的——求解者必须从行的均匀性推断出哪些行充当障碍，这一隐式检测规则在单个示例中可能有多种解释（例如特定颜色的行是障碍），只有对比多个示例（均匀行颜色各不相同）才能归纳出"均匀性"才是判据。

## 新题 7：噪声过滤后的碎片拼装为镜像对称矩形

**组合逻辑**：[connected_component + noise_pixel + area_comparison](来自 1f85a75f)（筛选有效碎片） → [jigsaw_assemble + mirror_symmetry + same_color_no_touch](来自 e8686506)（创新：源题中不需要噪声过滤，此处噪声碎片会导致总面积错误和矩形尺寸不可行）

**来源原语**：connected_component / noise_pixel / area_comparison（1f85a75f）；jigsaw_assemble / symmetric_complete / fragment / mirror_symmetry / same_color_no_touch / corner_marker（e8686506）

**依赖链**：噪声过滤 → 正确总面积 → 正确矩形尺寸 → 可行的拼装方案。同时，镜像对称约束和同色不相邻约束共同限制拼装方式为唯一解。任一约束缺失都可能导致多解或无解。

过滤噪声像素后，将剩余彩色碎片平移拼装为一个左右镜像对称的矩形，且同色碎片不得 4-邻接。

**输入结构**：一个约 14x14 的网格，背景为黑(0)。网格中散布着若干 4-连通彩色碎片（3~6 个有效碎片，每个面积 3~8 像素，形状不规则，颜色从红(2)、绿(3)、蓝(1)、黄(4)、品红(6)中选取，允许不同碎片同色）。此外有 2~4 个孤立噪声像素（面积=1，颜色任意）。四个灰(5)单像素分布在网格角落附近，作为角标记提示输出矩形的定位。生成约束：有效碎片（面积>1 且非灰色）的总面积恰好可以分解为两个大于 1 的整数之积（即矩形的高 x 宽）；该矩形尺寸分解唯一（如 3x8 而非同时可行 4x6）；存在唯一的一种平移拼装方案满足左右镜像对称且同色碎片不 4-邻接。

**规则**：
1. 找到所有 4-连通前景分量。丢弃面积为 1 的分量（噪声像素）和灰(5)分量（角标记）。
2. 计算剩余有效碎片的总像素面积 S，将 S 分解为 H x W（H <= W）。
3. 将有效碎片平移（不旋转、不翻转）到一个 H x W 的矩形画布中，要求：(a) 碎片之间不重叠，完全填满矩形；(b) 最终矩形关于其竖直中轴线左右镜像对称；(c) 同色碎片在矩形中不得 4-邻接（上下左右相邻的像素不能是同一颜色的不同碎片的像素）。
4. 输出为该 H x W 矩形（不含角标记和噪声）。
5. 角标记仅用于提示输出为矩形结构，不出现在输出中。

**关键洞察**：噪声像素若被计入总面积，会导致矩形尺寸错误，从而无法拼装或得到错误结果。镜像对称约束大幅削减搜索空间，但仍需同色不邻接约束才能唯一确定拼法。需要多个示例确认噪声阈值（面积=1）和角标记不参与拼装。

## 新题 8：框内标记偏移编码滑动方向，对象留下扫过轨迹

**组合逻辑**：[square + outer_frame + size_doubled_nesting](来自 db93a21d) + [containment + marker_pixel](来自 855e0971)（创新：源题中标记决定分割线方向，此处标记在框内的偏移位置编码滑动方向） → [sliding + collision_blocking](来自 4093f84a) + [swept_trail](来自 5e6bbc0b)

**来源原语**：square / outer_frame（db93a21d）；containment / marker_pixel / rect_region（855e0971）；sliding / collision_blocking / nearest_cardinal_attract（4093f84a）；swept_trail / compact / marker_sets_dir（5e6bbc0b）

**依赖链**：标记在框内的偏移方向（标记相对于框中心的位置）编码滑动方向 → 框外对象沿该方向滑向框 → 碰撞阻挡决定停靠位置 → 滑动路径留下扫过轨迹。删除偏移编码则方向不可知；删除碰撞阻挡则对象堆叠出错；删除轨迹则丢失运动历史。

正方形框内的标记像素偏离中心的方向指示该框的"吸引方向"；框外对象从该方向被吸入并停靠在框的该侧表面，留下栗色扫过轨迹。

**输入结构**：一个约 16x16 的网格，背景为黑(0)。网格中有 2~3 个灰(5)空心正方形框（边长 3~5，仅边框为灰，内部为黑），彼此不重叠、不相邻。每个框的内部有恰好一个彩色标记像素（蓝(1)、红(2)或绿(3)），标记不在框的正中心，而是偏向框的某个基方向（偏上、偏下、偏左或偏右，不在对角线方向）。框外散布着若干单像素彩色对象（黄(4)、橙(7)、品红(6)），每个对象仅与一个框在同一行或同一列上（保证唯一最近框）。生成约束：每个框至少对应 1 个外部对象；各对象到其最近框的路径上无其他框阻挡；标记偏移方向与对象到达框的方向一致（即对象从标记所指方向被吸引）。

**规则**：
1. 对每个正方形框，确定其内部标记像素相对于框中心的偏移方向：标记在中心上方则方向为"上"，下方则"下"，左方则"左"，右方则"右"。此方向即为该框的吸引方向。
2. 对每个框外对象，找到与其同行或同列的最近框。该对象沿吸引方向的反方向对齐不必关心——对象始终直线滑向最近框（沿对象到框的基方向直线）。
3. 滑动规则：对象沿朝向最近框的基方向移动（若对象在框的左侧则向右滑，在上方则向下滑，等等），直到与该框的外边框或之前已停靠在该框旁的对象相邻为止。
4. 处理顺序：按对象到其目标框边框的距离从小到大处理（最近的先滑）。距离相同时按对象位置从上到下、从左到右。
5. 对象保持其原始颜色停靠在终点位置。
6. 对象滑动经过的路径上的每个像素（从原始位置到终点之间的所有中间像素，不含起点和终点）被填充为栗(9)色，作为扫过轨迹。若轨迹像素已被先前的轨迹占据，保持栗(9)不变。
7. 原始对象位置变为黑(0)背景（被轨迹起点旁的栗色或直接变黑，取决于是否有中间路径；若对象紧邻框则无轨迹，原位直接变黑）。
8. 框和框内标记保持不变。

**关键洞察**：框内标记的空间偏移是方向的隐式编码——标记本身不移动，不参与任何操作，仅通过其位置传递信息。这种"几何结构编码变换参数"的模式需要多个示例才能归纳（单个示例中方向也可能由对象位置或框的朝向决定）。累积阻挡使得处理顺序不可忽略。

## 新题 9：横竖条交叉后压缩，扫过轨迹标记原始交叉位置

**组合逻辑**：[h_bar + v_bar + crossing + crossing_swapped_to_other_foreground](来自 ba97ae07) + [compact + edge_marker + marker_sets_dir + swept_trail](来自 5e6bbc0b)（创新：源题中交叉和压缩是独立操作，此处压缩改变条的位置从而改变交叉的存在和位置，两者因果倒置——先交叉标记、后压缩，但标记是否保留取决于压缩后的几何）

**来源原语**：h_bar / v_bar / crossing / crossing_swapped_to_other_foreground（ba97ae07）；compact / edge_marker / marker_sets_dir / swept_trail / checkerboard_pattern（5e6bbc0b）

**依赖链**：交叉检测生成交叉标记 → 压缩移动条的位置（交叉标记随条移动）→ 压缩路径上的原始交叉位置留下扫过轨迹。交叉标记的最终位置取决于压缩方向和距离，而扫过轨迹记录了交叉标记的运动历史。

网格中的横条和竖条在交叉处互换颜色，然后所有条沿边缘标记指示的方向压缩；交叉区随条移动，原交叉位置留下栗色轨迹。

**输入结构**：一个约 12x14 的网格，背景为黑(0)。网格中有 2~3 条水平条（蓝(1)，占满各自行的所有列，宽度 1 像素）和 2~3 条垂直条（红(2)，占满各自列的所有行，宽度 1 像素）。水平条和垂直条在交叉处形成若干交叉点。网格某一边缘（上、下、左或右）上有一个青(8)标记像素，指示压缩方向。生成约束：横条和竖条不在网格边缘行/列上（留出压缩空间）；青色标记在边缘的非角落位置。

**规则**：
1. 识别所有全跨水平条（蓝(1)）和全跨垂直条（红(2)）。
2. 标记所有交叉点：水平条和垂直条交叉的像素。将每个交叉像素的颜色切换为另一种前景色——原为蓝(1)的交叉像素（即垂直条被水平条覆盖的位置）变为红(2)，原为红(2)的（即水平条被垂直条覆盖的位置）变为蓝(1)。由于交叉点同时属于两条，选择规则：交叉点显示为红(2)（即视觉上垂直条在上），切换后变为蓝(1)。
3. 根据青(8)标记的位置确定压缩方向：标记在左边缘→向左压缩，右边缘→向右压缩，上边缘→向上压缩，下边缘→向下压缩。
4. 压缩操作：将所有非背景像素（蓝、红、已切换的交叉像素）沿压缩方向推向该边缘，消除每一行（若水平压缩）或每一列（若垂直压缩）中的黑色间隙。像素的相对顺序在各行/列内保持不变。
5. 被压缩移动的像素在其原始位置到新位置之间留下栗(9)色扫过轨迹（不含新位置本身，包含原位置）。若像素未移动（已在边缘），无轨迹。
6. 青(8)标记像素保持不变。

**关键洞察**：交叉颜色切换必须在压缩之前完成——压缩改变了条的空间位置，但交叉关系由原始位置决定。栗色轨迹同时记录了横条和竖条的移动路径，在输出中形成的轨迹图案隐式反映了原始交叉的空间布局。需要多个示例确认操作顺序（先切换后压缩而非反过来）。

## 新题 10：链式序列决定碎片拼合顺序，边缘通配色匹配拼接

**组合逻辑**：[chained_sequence + chain_linkage + marker_bar + height_equals_width](来自 84551f4c)（创新：源题中链式用于连接竖条，此处链式用于确定矩形碎片的拼合顺序） → [translate_and_tile + rectangular_piece + edge_matching + wildcard_color](来自 446ef5d2)

**来源原语**：chained_sequence / chain_linkage / marker_bar / height_equals_width（84551f4c）；translate_and_tile / rectangular_piece / edge_matching / wildcard_color / corner_marker（446ef5d2）

**依赖链**：链式规则确定碎片序列（起始碎片的高度确定下一碎片的水平偏移）→ 序列中相邻碎片必须通过边缘匹配（通配色）验证拼合可行性 → 不可达碎片被排除。删除链式规则则拼合顺序不确定；删除边缘匹配则拼合对齐位置不确定。

从蓝色标记碎片出发，按链式规则（当前碎片高度=到下一碎片的列偏移）确定碎片拼合序列，然后沿水平方向拼接碎片，拼接边使用通配色匹配。

**输入结构**：一个约 16x16 的网格，背景为黑(0)。网格中散布着 4~6 个矩形碎片，每个碎片高度 2~5 像素、宽度 2~4 像素。碎片以橙(7)为主色（边缘像素大部分为橙色），内部有少量其他颜色的标记像素（红(2)、绿(3)、黄(4)等）。其中一个碎片的左上角像素为蓝(1)（起始标记）。碎片在网格中的位置满足链式约束：从起始碎片出发，存在一个碎片序列，其中每个碎片的左上角列坐标等于前一个碎片的左上角列坐标加上前一个碎片的高度。生成约束：链式序列中相邻碎片高度相同（以确保拼接时上下对齐）；橙(7)作为通配色，拼接边（左碎片的右边缘列与右碎片的左边缘列）上的非橙像素必须在对应行上颜色一致；至少有 1 个碎片不在链式序列中（干扰项）。

**规则**：
1. 识别所有矩形碎片（4-连通非黑区域，每个均为紧致矩形）。找到左上角含蓝(1)标记的碎片作为链首。
2. 从链首开始，寻找下一个碎片：其左上角列坐标 = 当前碎片左上角列坐标 + 当前碎片高度。若找到，将其加入链；继续以新碎片为当前碎片重复此步骤，直到无法找到下一个碎片。
3. 将链中的碎片按序列顺序从左到右水平拼接（去除碎片之间的间隙）。碎片在垂直方向上按各自顶部行对齐（所有碎片的第 0 行对齐）。
4. 拼接时验证边缘匹配：左碎片右边缘列和右碎片左边缘列在对应行位置上，若两侧都不是橙(7)则必须颜色相同；若至少一侧为橙(7)则视为匹配（橙色为通配色）。
5. 不在链式序列中的碎片被丢弃，不出现在输出中。
6. 输出为拼接后的矩形（高度 = 碎片高度，宽度 = 所有链式碎片宽度之和）。蓝(1)标记在输出中保持不变。

**关键洞察**：链式连接的跳转规则（高度=列偏移）与碎片的物理位置编码在输入的空间布局中——求解者必须同时理解链式选择规则和边缘匹配的通配色机制。未被链式连接的碎片是干扰项，需要多个示例确认链式规则（而非例如"按列坐标从左到右排序"）。
