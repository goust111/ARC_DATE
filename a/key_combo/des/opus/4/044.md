## 新题 1：射线通道多米诺吸附

**组合逻辑**：[射线延伸 ray_extension](创新：射线不绘出，仅作为运动通道判定) + [滑动 slide](创新：每条射线独立定义一个方向的重力，多方向同时存在) + [碰撞停止 collision_stop] + [近墙优先结算 nearest_first_settling](创新：墙替换为 3x3 中心块作为吸引终点)

**来源原语**：射线延伸、罗盘方向、中心向外辐射、排除中心像素 (1d398264)；滑动、碰撞停止、近墙优先结算、多米诺骨牌 (6ad5bdfd)

**依赖链**：3x3 块的八方向射线定义运动通道 → 仅当多米诺两个像素都在同一条射线上时该多米诺才获得运动能力 → 运动方向为沿射线朝 3x3 块中心滑动 → 按距中心近者优先结算，后续多米诺碰到已结算者停止

将 3x3 块的八方向射线作为独立重力通道，使散落的多米诺沿各自所在射线方向向中心滑动堆叠，跨射线的多米诺被钉住不动。

**输入结构**：约 20x20 的黑(0)背景网格。网格中某处有一个 3x3 填充方块，9 个像素全部为栗(9)色。网格上散布 6~10 个单色多米诺（每个多米诺为 2 个 4-连通的同色像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，不同多米诺颜色可相同或不同）。部分多米诺的两个像素恰好都落在从 3x3 块中心向外延伸的同一条罗盘方向直线上（8 个方向：上、下、左、右、左上、右上、左下、右下）；其余多米诺的两个像素跨越两条不同射线或不在任何射线上。生成约束：同一射线上的多米诺之间初始不相邻也不重叠；3x3 块距网格边界至少 4 像素；所有多米诺不与 3x3 块相邻。

**规则**：
1. 保持 3x3 栗(9)块不动，作为输出的基础。
2. 从 3x3 块的中心像素向八个罗盘方向（上、下、左、右、左上、右上、左下、右下）延伸虚拟直线至网格边界。这些直线不绘制，仅用于判定。
3. 对每个多米诺，检查其两个像素是否都落在同一条虚拟直线上。若否，该多米诺保持原位不动（钉住）。
4. 对满足条件的多米诺，沿其所在射线方向朝 3x3 块刚性滑动。按各多米诺距 3x3 块中心的曼哈顿距离从小到大依次结算（距离取两个像素中较近者的曼哈顿距离）。
5. 每个多米诺滑动直到其前沿像素的下一步位置会进入 3x3 块区域或已被已结算多米诺占据时停止。
6. 对角射线上的多米诺每步行列各移动 1 格（沿 45 度方向逐步移动）。
7. 钉住的多米诺不阻挡射线上其他多米诺的滑动路径（它们不在射线上，不构成障碍）；只有已结算在射线上的多米诺和 3x3 块本身才构成障碍。

**关键洞察**：3x3 块同时充当射线发射源（定义运动通道）和重力吸引终点——但只有两个像素严格共线于同一射线的多米诺才会被吸引，跨射线的多米诺被"钉住"，这个过滤条件无法从单个示例完全确认。

## 新题 2：遮挡优先序与标记计数的双源汇总

**组合逻辑**：[遮挡顺序 occlusion_order](保持：交叉处可见色建立优先级) + [计数 counting](保持：标记数决定行长) + [排序 sort](创新：排序键来自空间遮挡图而非数值大小)

**来源原语**：遮挡顺序、交叉处可见性、矩形边框、重绘 (c920a713)；计数、标记像素、标记数决定行长、按计数升序排列 (d4c90558)

**依赖链**：重叠矩形框在交叉像素处的可见色建立遮挡有向图 → 图的唯一拓扑序确定输出行排列顺序 → 同时每个框内的灰标记数量决定该框对应行的长度 → 两个独立分析汇合为最终输出

重叠矩形框的交叉遮挡关系决定输出行排列顺序，框内灰标记的数量决定每行长度，两个独立信息源必须同时求解才能确定输出。

**输入结构**：约 18x18 的黑(0)背景网格。3~5 个一像素宽的彩色矩形边框分布其上，每个框一种颜色（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，互不相同）。框之间存在两两重叠，在两框边缘交叉的像素处只有一种颜色可见——可见色框在该处遮挡另一框。灰(5)标记像素散布在各框的边界框内部（不在框边缘线上），每个框内有 1~5 个灰标记，且各框的灰标记数量互不相同。生成约束：所有框的两两遮挡关系构成一个有向无环图，且该图恰好有唯一拓扑排序（即存在唯一全序）；灰标记不落在任何两框边缘的交叉像素上；每个框至少与一个其他框有交叉。

**规则**：
1. 对每对边缘有交叉的框，检查交叉像素的颜色：可见色框优先级高于被遮挡框。
2. 由所有两两优先关系建立有向无环图，推导唯一全序（优先级从高到低）。
3. 对每个框，计算其轴对齐边界框内部（不含框边缘本身）的灰(5)标记像素数量 N。
4. 输出网格行数 = 框数，列数 = 所有框中最大的 N 值。第一行对应优先级最高的框，最后一行对应优先级最低的框。每行前 N 个像素为该框颜色（N 为该框的灰标记数），其余像素填黑(0)。

**关键洞察**：输出行排列顺序由空间遮挡图决定（而非按标记数量或颜色排序），行长度由标记计数决定——两个独立的信息提取（空间交叉分析和包含计数）必须同时完成才能确定任何一行的完整信息。

## 新题 3：指示像素定向的半菱形包络生长

**组合逻辑**：[包络生成 envelope_generation](创新：菱形方向由指示像素旋转确定，生成半菱形而非完整菱形) + [方向指示 direction_indication](保持：红像素标示生长方向) + [擦除 erase](创新：指示像素被消耗替换为矩形本色)

**来源原语**：包络生成、实心条、菱形轮廓、逐步收缩、中心对称 (c97c0139)；指示像素、方向指示、指示侧扩展至边界 (b527c5c6)；擦除 (d23f8c26)

**依赖链**：指示像素确定菱形包络向外生长的方向 → 矩形在指示侧的边长决定菱形底边宽度 → 包络从该侧向外逐行两端收缩 → 指示像素本身被消耗（替换为矩形自身颜色）

每个矩形上的红色指示像素指定一个方向，从该侧向外生长逐行收缩的青色半菱形包络，指示像素自身被矩形色覆盖消失。

**输入结构**：约 22x26 的黑(0)背景网格。2~4 个不同颜色的实心矩形分布其上（颜色从蓝(1)、绿(3)、黄(4)、橙(7)中选取，互不相同），尺寸在 3x3 到 5x7 之间（行x列）。每个矩形的边界上恰有一个红(2)像素，位于矩形上、下、左或右某一条边的中央位置（若该边像素数为偶数则取靠左或靠上的中间位置）。不同矩形的红像素可以指向不同方向。矩形之间互不接触，且每个矩形距网格边界至少 6 像素。生成约束：各矩形的包络生长区域互不重叠（即一个矩形的半菱形包络不会延伸到另一个矩形或其包络区域中）。

**规则**：
1. 对每个矩形，找到其红(2)指示像素。确定该像素位于矩形的哪条边（上/下/左/右），该边朝外的方向即为包络生长方向。
2. 将红(2)像素替换为该矩形自身的颜色（消耗指示像素）。
3. 以指示侧整条边为底边，沿生长方向向外生成青(8)像素区域：第 1 行（紧邻矩形外侧）宽度等于指示侧边的像素数，之后每行两端各缩进 1 像素，直到该行宽度缩为 1 时绘制最后一行后停止。若底边像素数为偶数，则缩减时左右交替少缩一侧（先缩右侧），使尖端偏左。
4. 包络像素仅绘制在黑(0)背景上；若某包络像素位置已有非背景像素则跳过不绘制。
5. 处理顺序：按矩形面积从大到小处理（面积大的矩形的包络先绘制）；面积相同时按矩形左上角从左到右、再从上到下排序。

**关键洞察**：指示像素同时确定了包络的生长方向和底边选择——方向决定了半菱形朝哪个方向"展开"，而底边长度决定了半菱形的宽度，两者从同一个红色标记中耦合提取。

## 新题 4：滑动距离编码缩放系数

**组合逻辑**：[滑动 slide](保持：竖条向边墙滑动) + [碰撞停止 collision_stop](保持：近者先结算) + [缩放 scale](创新：滑动距离直接成为缩放倍率) + [印章放置 stamp](创新：缩放后的图案替换竖条的最终位置)

**来源原语**：滑动、碰撞停止、近墙优先结算、边墙、墙面确定方向 (6ad5bdfd)；缩放、尺寸比编码缩放、图案母题 (b10624e5)；印章放置 (b10624e5)；竖条 (3906de3d)

**依赖链**：所有竖条向边墙滑动并按距墙近者先结算 → 每根竖条的滑动距离（实际移动格数）成为其缩放系数 → 网格角落的参考图案按该系数等比放大 → 放大后的图案以竖条最终位置为锚点印章放置，替换原竖条

竖条向墙滑动后各自的移动距离决定一个参考小图案的缩放倍率，缩放后的图案替换到竖条的最终位置处。

**输入结构**：约 22x20 的黑(0)背景网格。底边（最后一行）为一整行红(2)边墙。网格上方散布 3~4 根不同颜色的竖条（每根为 1 像素宽、2~3 像素高的垂直单色条，颜色从蓝(1)、绿(3)、黄(4)、橙(7)中选取，互不相同）。所有竖条位于不同列，离墙的初始距离（竖条最底端像素到墙的行距）在 1~4 之间且互不相同。网格左上角（从第 0 行第 0 列开始）有一个 2x2 的灰(5)参考图案，图案内恰有 3 个灰像素和 1 个黑像素（例如左上灰、右上灰、左下黑、右下灰，形成一个"缺角方块"）。生成约束：竖条不在同一列；参考图案不与任何竖条同列；滑动后竖条之间不互相阻挡（因为列不同）；每根竖条按其距离 D 放大参考图案后的 (2D)x(2D) 区域不超出网格边界且不与其他放大图案重叠。

**规则**：
1. 保留红(2)边墙不变。记录左上角 2x2 参考图案的形状（哪些位置是灰、哪些是黑），但在输出中擦除参考图案原始位置（替换为黑(0)）。
2. 将所有竖条沿垂直方向向边墙滑动。按竖条最底端像素到墙的行距从小到大依次结算：每根竖条向下刚性平移，直到其最底端像素的下一行为墙或已结算的障碍物时停止。记录每根竖条的滑动距离 D（实际向下移动的行数）。
3. 对每根竖条，将 2x2 参考图案等比放大为 (2D)x(2D) 的图案（每个原始像素扩展为 DxD 的同色方块）。将放大图案中所有灰(5)像素替换为该竖条的颜色。
4. 以竖条最终位置的最底端像素为锚点，将放大图案的底边右端对齐到该锚点，向左向上展开印章绘制。
5. 擦除所有竖条的原始位置像素（替换为黑(0)）。竖条的最终滑动位置本身也被放大图案覆盖（放大图案包含了竖条最终位置所在的区域）。
6. 若多个放大图案有重叠区域（理论上不应发生，但作为边界规则），后处理的（滑动距离更大的）覆盖先处理的。

**关键洞察**：物理模拟（重力滑动）产生的数值结果（移动距离）直接成为几何变换（缩放倍率）的参数——距离越远的竖条滑动越多步，对应的图案也越大，使得同一空间配置同时编码了位置和变换系数。

## 新题 5：连通性改变印章颜色粒度

**组合逻辑**：[连通判定 connectivity_test](创新：连通性改变印章操作的颜色决策粒度——从逐像素独立变为逐分量统一) + [印章覆盖 stamp](保持：源像素位置决定输出块位置) + [重涂色 recolor](创新：涂色来自连通分量的主色而非单像素自身色) + [分块对应 block_correspondence]

**来源原语**：连通判定、连通性、桥接路径 (239be575)；印章覆盖、重涂色、模板面板、分块对应、源色决定模板涂色 (b190f7f5)

**依赖链**：左面板中非黑像素做 4-连通分析形成若干连通分量 → 每个连通分量内最频繁的颜色成为代表色 → 输出中属于同一分量的所有像素位置的 NxN 块统一使用代表色重涂模板 → 孤立黑位置对应的块保持全黑

源面板中的像素按 4-连通性分组，同组像素共享组内主色来重涂模板印章，替代了逐像素独立决定颜色的原始规则。

**输入结构**：约 6x12 的网格，由左右两个 6x6 面板组成（中间无分隔线，左面板占第 0~5 列，右面板占第 6~11 列）。背景色为黑(0)。左面板（源面板）包含 5~8 个非黑像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取。其中部分相邻像素形成 4-连通的连通分量（每个分量 2~4 像素），部分像素孤立（分量大小为 1）。同一连通分量内的像素可能颜色不同（例如一个分量含 2 个蓝(1)像素和 1 个红(2)像素）。右面板（模板面板）包含一个由灰(5)像素组成的 4-连通小图形（3~5 像素），其余为黑。生成约束：每个连通分量有唯一的最频繁颜色（无并列）；左面板至少有 2 个大小 >= 2 的连通分量和 1 个孤立像素；左面板非黑像素不出现在第 0 行第 0 列（确保输出角落可辨识）。

**规则**：
1. 输出为 36x36（6x6 个块，每块 6x6）的网格，初始化为黑(0)。
2. 对左面板所有非黑像素做 4-连通分析（忽略颜色差异，仅区分黑 vs 非黑），找出所有连通分量。
3. 对每个连通分量，统计其中各颜色的像素数量，出现最多的颜色为该分量的"代表色"。
4. 对左面板中每个非黑像素位置 (r, c)（r 为行号，c 为列号，0-indexed），取其所属连通分量的代表色 C，将右面板模板中的灰(5)像素替换为 C，印章到输出的第 (r, c) 块（即输出行 r*6 到 r*6+5，列 c*6 到 c*6+5）。
5. 左面板中的黑像素位置对应的输出块保持全黑。
6. 孤立的非黑像素（连通分量大小为 1）视为独立分量，其代表色即自身颜色。

**关键洞察**：与原版印章题（b190f7f5）中每个像素独立决定模板颜色不同，这里连通性将相邻像素"绑定"为一组，组内少数派颜色被多数派覆盖——需要对比多个示例才能发现颜色决策的粒度是"连通分量"而非"单像素"。

## 新题 6：精灵体计数驱动金字塔生成与象限反射

**组合逻辑**：[计数 counting](保持：统计同色精灵体) + [居中金字塔生成](创新：计数值驱动金字塔高度，金字塔从数值"生成"而非预先存在) + [镜像 reflect](创新：反射轴由象限位置决定) + [擦除 erase](保持：精灵体被消耗)

**规则**：
1. 对每个象限，统计该象限内（不含分隔线、不含框架边缘）与框架同色的精灵体数量 N。每个独立的 4-连通图形算 1 个精灵体，不论其像素数。
2. 生成高度为 N 的居中金字塔：从顶到底依次为宽度 1, 3, 5, ..., 2N-1 的水平行，颜色为该象限框架色。
3. 根据象限位置对金字塔进行变换：
   - 左上象限：不变换（尖朝上，底在下）。
   - 右上象限：水平翻转（因金字塔左右对称，外观不变）。
   - 左下象限：垂直翻转（尖朝下，底在上）。
   - 右下象限：水平 + 垂直翻转（尖朝下）。
4. 将金字塔放入对应框架内部：
   - 未翻转或仅水平翻转的金字塔（上方两个象限）：底边与框架内壁下边对齐，水平居中。
   - 垂直翻转的金字塔（下方两个象限）：底边（翻转后在上方）与框架内壁上边对齐，水平居中。
5. 擦除所有精灵体（替换为黑(0)）。框架和分隔线保留。

**关键洞察**：精灵体数量不是像参考题那样显示为点或行长，而是转化为金字塔的几何形状——数量 N 同时决定了金字塔的高度（N 行）和底边宽度（2N-1），实现了从计数到几何结构的非线性映射。

## 新题 7：菱形包络形状与边缘近邻颜色的分离决策

**组合逻辑**：[包络生成 envelope_generation](保持：围绕条生成菱形包络) + [最近距离 nearest_distance](创新：决定包络颜色的不是条本身而是最近边缘线) + [重涂色 recolor](创新：重涂色对象是包络而非散落标记)

**来源原语**：包络生成、实心条、菱形轮廓、中心对称、逐步收缩 (c97c0139)；最近距离、边缘线、标记继承最近源色 (2204b7a8)；重涂色 (2204b7a8)

**依赖链**：每根灰条的长度和方向决定菱形包络的形状 → 但包络颜色不由条自身决定 → 而是由该条中心距左/右边缘线的水平距离决定颜色继承 → "形状"和"颜色"来自两个独立的空间分析

彩色条生成菱形包络，但包络颜色不由条本身决定，而由该条距两侧边缘线的远近继承——局部几何决定包络形状，全局位置决定包络颜色。

**输入结构**：约 20x25 的黑(0)背景网格。第 0 列（最左列）整列为蓝(1)，最后一列（最右列）整列为红(2），构成两条边缘线。中间区域散布 3~5 根灰(5)的实心条，每根为 1 像素宽、3~7 像素长的水平或垂直直线段。灰条之间互不接触，每根灰条距左右边缘至少 3 像素。生成约束：各条的菱形包络（按逐步收缩规则生成的完整菱形轮廓区域）互不重叠且不接触；没有灰条的中心像素到左右边缘的水平距离恰好相等（避免距离并列）。

**规则**：
1. 保留左边缘蓝(1)线和右边缘红(2)线不变。
2. 对每根灰(5)条，生成菱形包络：
   - 若为水平条（长度 L 像素），以条为中轴，向上和向下各逐行扩展：第 1 行（紧邻条的上/下方）宽度为 L-2（两端各缩 1），每再外一行再各缩 1，直到宽度缩至 0 停止。各行水平居中于条的中心。
   - 若为垂直条（长度 L 像素），同理但旋转 90 度：以条为中轴向左右扩展，每步两端各缩 1。
3. 确定每根条的包络颜色：计算该条中心像素到第 0 列的水平距离 d_left 和到最后一列的水平距离 d_right。若 d_left < d_right，包络用蓝(1)；若 d_right < d_left，包络用红(2)。
4. 用确定的颜色绘制包络像素，仅绘制在黑(0)背景位置上。灰(5)条本身保持灰色不变。
5. 处理顺序：按条的长度从大到小处理（长条的包络先绘制）；长度相同时按条中心的列号从小到大处理。后绘制的包络不覆盖先绘制的已着色像素。

**关键洞察**：包络的形状完全由条的局部属性（长度、方向）决定，但包络的颜色完全由条的全局属性（在网格中的水平位置）决定——解题者必须同时进行两个独立的空间分析才能确定每个包络像素的最终状态。

5. 输出中仅保留垂直虚线射线，所有原始水平内容消失。

**关键洞察**：水平方向的计数信息被"旋转 90 度"转化为垂直方向的几何长度——左侧计数控制向上延伸，右侧计数控制向下延伸。需要对比多个示例才能确认这种跨维度映射关系（而非上下等长或其他对称规则）。

**关键洞察**：输出的空间结构（同心嵌套顺序）由输入中不可见于输出的信息（条长度）决定——条在输入中是排序键，在输出中完全消失，解题者必须识别出条长度与嵌套层级的对应关系。

## 新题 10：多米诺距墙距离编码框架填充深度

多米诺的颜色将其配对到同色框架，多米诺距底墙的行距决定该框架内部从底侧向上填充多少行，多米诺自身被消耗消失。

**输入结构**：约 20x20 的黑(0)背景网格。最后一行（底边）为一整行灰(5)边墙。网格上半部分（约第 1~8 行区域）散布 3~4 个不同颜色的一像素宽空心矩形框架（颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取，互不相同），框架大小约 4x4 到 6x6（外尺寸），框架之间不重叠不接触。网格下半部分（约第 10~18 行区域，在框架下方、墙上方）散布 3~4 个多米诺（每个多米诺为 2 个 4-连通同色像素），每个多米诺的颜色恰好与某个框架颜色相同（一一对应）。不同多米诺位于不同的行高度，其底端像素到灰墙的行距在 1~6 之间且互不相同。生成约束：多米诺与框架之间通过颜色一一配对（每种颜色恰好出现一个框架和一个多米诺）；每个多米诺的距离值 D 不超过其配对框架的内部高度（框架外高度 - 2）；多米诺之间不在同一行（距离互不相同）。

**规则**：

2. 对每个多米诺，计算其底端像素所在行到灰墙所在行的行距 D（D = 墙行号 - 多米诺底端行号 - 1，即中间隔了多少空行加上多米诺自身不算）。更精确地说：D = 墙所在行号 - 多米诺最下方像素所在行号。
3. 通过颜色匹配将每个多米诺与同色框架配对。
4. 对每个框架，从其内部最底行开始向上填充 D 行（D 为配对多米诺的距离值），填充颜色为框架自身颜色。填充区域为框架内部（不含框架边缘），每行从框架内部左端到右端整行填满。
5. 擦除所有多米诺（替换为黑(0)）。框架边缘保持不变。
6. 若某框架无配对多米诺（理论上不应发生），该框架内部不填充。

**关键洞察**：多米诺的物理位置（距墙距离）编码了一个数值，该数值通过颜色配对远程控制另一个对象（框架）的填充深度——多米诺本身是"距离传感器"，在输出中完全消失，只留下它所测量的数值效果。
