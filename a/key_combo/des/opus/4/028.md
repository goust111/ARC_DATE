## 新题 1：墙厚编码旋转角

**组合逻辑**：[flood_fill](保留泛洪机制) + [rotate](创新：旋转角度由墙体几何属性隐式编码) + [inlay_fill](创新：模板嵌入位置由种子像素锚定)

**来源原语**：flood_fill / partial_enclosure / opening_direction / fill_seed（来自 b9e38dc0）；rotate / template / successive_rotation_per_slot（来自 8e5a5113）；inlay_fill（来自 67e490f4）

**依赖链**：每个半封闭墙的墙体厚度是一个隐式参数，必须先测量才能确定旋转角度；旋转角度决定模板的朝向，朝向决定嵌入后的像素布局；嵌入完成后剩余空间才能执行泛洪填充。三者缺一不可——不测厚度则旋转未知，不旋转则嵌入形状错误，不泛洪则输出不完整。

将外部模板按墙厚决定的角度旋转后嵌入各半封闭墙内部，再用种子颜色泛洪填充剩余空腔。

**输入结构**：背景黑(0)，网格约 20x20。网格中散布 3-4 个灰(5)像素构成的半封闭墙（U 形或 C 形，4-连通，每个墙体围出一个约 5x5 的内部区域，开口朝向不同方向）。关键差异：各墙体的壁厚不同——有的壁厚 1 像素，有的 2 像素，有的 3 像素（壁厚指沿垂直于壁面方向连续灰像素的层数）。每个封闭区内部恰好有一个非黑非灰的种子像素（颜色各异，如红(2)、蓝(1)、绿(3)等）。网格的一个角落（与所有墙体不重叠）放置一个单色模板图案：一个约 3x3 的非对称连通形状，颜色为橙(7)。生成约束：各墙体互不相邻，内部区域足够容纳模板；模板形状在 0°/90°/180° 旋转后均不同；每种壁厚值（1/2/3）至少出现一次。

**规则**：
1. 对每个半封闭墙，沿垂直于任意一段壁面的方向测量连续灰(5)像素层数，得到壁厚 t。
2. 壁厚映射旋转角：t=1 对应 0°（不旋转），t=2 对应 90° 顺时针，t=3 对应 180°。
3. 将模板按对应角度旋转，以种子像素为锚点（种子位置 = 旋转后模板的左上角），将旋转后的模板像素写入墙体内部。模板颜色保持橙(7)不变。
4. 将墙体内部所有剩余黑(0)像素泛洪填充为该墙体种子像素的颜色。种子像素本身被模板覆盖则消失；若种子不在模板覆盖范围内则保留其颜色并参与泛洪。
5. 墙体外部（含背景和模板原始位置）保持不变。处理顺序不影响结果（各墙体内部互不干涉）。

**关键洞察**：墙体厚度不是结构强度的装饰性差异——它是旋转参数的离散编码。求解者必须跨多个示例比对"壁厚变化"与"模板朝向变化"的对应关系，才能提取这条隐式规则。

## 新题 2：箭头链式激活与印章传播

**组合逻辑**：[cascade_activation](保留链式传播骨架) + [ray_extend + dir_inference](创新：箭头缺角定向取代端口定向) + [stamp_overlay](创新：印章形状固定为激活源而非激活目标)

**来源原语**：cascade_activation / chain_reaction_propagation / port_encodes_ray（来自 5961cc34）；arrowhead_sprite / missing_corner_dir / dir_inference（来自 6e19193c）；stamp_overlay / marker_anchors_sprite（来自 e6721834）

**依赖链**：箭头朝向推断决定射线方向，射线方向决定链式传播路径，传播路径决定哪些箭头被激活，激活状态决定哪些位置执行印章覆盖。印章使用初始激活源的原始朝向，因此源箭头的形状信息必须传递到每一步。

从唯一的红色箭头出发，沿其指向发射射线激活命中的下一个箭头，被激活箭头继续沿自身指向传播；每个激活点叠印初始红色箭头的原始形状。

**输入结构**：背景黑(0)，网格约 18x18。散布 5-7 个小箭头精灵体（每个占约 3x3 边界框，4-连通，约 5 像素，形如一个缺了一角的实心小方块），全部为绿(3)。每个箭头通过其缺角位置指示朝向：缺左上角→指向左上、缺右上角→指向右上……但本题简化为正交方向：缺顶行中间像素→指向上，缺底行中间像素→指向下，缺左列中间像素→指向左，缺右列中间像素→指向右。恰好一个箭头为红(2)而非绿——它是激活种子。生成约束：任意两个箭头的中心像素不共行也不共列（保证射线路径无歧义）；从红色箭头出发的链式传播至少经过 3 个绿色箭头后才终止于网格边界或无目标。

**规则**：
1. 识别红(2)箭头为起始点。推断其朝向（由缺失像素位置决定）。
2. 从红色箭头的中心像素出发，沿其朝向延伸一条 1 像素宽的射线（颜色红(2)），直到射线进入另一个箭头的边界框或到达网格边缘。
3. 若射线命中一个绿色箭头，将该箭头的所有像素重涂为红(2)——称为"激活"。
4. 被激活的箭头随即沿**自身**朝向发射新射线（颜色红(2)），重复步骤 2-3。
5. 链式传播终止条件：射线到达网格边缘、或命中已被激活的箭头（不重复激活）。
6. 在每个被激活（非起始）箭头的位置，叠印一份起始红色箭头的**原始形状与朝向**（即种子箭头的 3x3 掩码，保持种子朝向不变），以被激活箭头的中心像素为锚点。叠印像素覆盖被激活箭头自身的像素（颜色均为红(2)，形状变为种子形状）。
7. 未被激活的绿色箭头保持原样。所有射线路径上的像素保留为红(2)。

**关键洞察**：链式路径由每个箭头的自身朝向决定（局部信息），但叠印的形状始终来自全局唯一的种子箭头（全局信息）。求解者必须同时追踪两套独立信息：局部朝向决定"往哪传播"，全局种子形状决定"激活后变成什么样"。

## 新题 3：图例定义配对准则，双条件触发夹间填色

**组合逻辑**：[legend_row_pairing](创新：图例行不再驱动颜色互换，而是定义形状匹配的颜色配对准入条件) + [pattern_match](创新：匹配需同时满足形状相同 + 颜色属于图例配对) + [between_region recolor](保留夹间区域涂色)

**来源原语**：legend / legend_row_pairing / same_row_bidirectional_swap（来自 0becf7df）；pattern_match / prototype / symbol_slot / separator / between_region / match_slot_recolor（来自 d94c3b52）

**依赖链**：图例定义"哪两种颜色构成合法配对"——这不是操作而是匹配准入条件。形状匹配筛选出形状相同的槽位对，但只有颜色恰好属于同一图例行的才算有效配对。有效配对的位置决定夹间区域的范围。三层条件层层收窄：所有槽位 → 形状相同的子集 → 颜色配对合法的子集 → 夹间区域。去掉图例则配对条件缺失，去掉形状匹配则无法筛选对象，去掉夹间涂色则输出不完整。

图例行定义颜色配对准入；同行同列中形状相同且颜色属于同一图例配对的槽位之间的区域被高亮。

**输入结构**：背景黑(0)，网格约 15x17。左上角有一个 2x2 的图例块，两行分别包含两种不同颜色（如第一行：红(2)+蓝(1)，第二行：绿(3)+黄(4)）。图例与主区域之间隔 1 列背景。主区域被灰(5)分隔线（1 像素宽）划分为 4x5 或 5x5 的 3x3 符号槽位网格。每个槽位内有一个单色符号掩码（1-5 像素的 4-连通小形状），颜色为图例中出现的四种颜色之一。同一形状可能以不同颜色出现在多个槽位中。生成约束：至少存在 2 对满足双条件（形状相同 + 颜色配对合法）的槽位，它们之间的行或列上有非空的夹间槽位；同时存在形状相同但颜色不属于同一图例行的槽位对（干扰项，不应被高亮）。

**规则**：
1. 读取图例：每行两个颜色构成一个"合法配对"。如第一行红(2)+蓝(1)表示红蓝互为合法配对色。
2. 扫描所有符号槽位，提取每个槽位的 3x3 掩码形状和颜色。
3. 两个槽位构成"有效匹配对"当且仅当：(a) 它们的掩码形状完全相同（像素位置一致），且 (b) 它们的颜色分别是同一图例行中的两种颜色（如一个红一个蓝，或一个绿一个黄）。同色同形的两个槽位不构成有效匹配（配对必须是图例行内的两种不同颜色）。
4. 将所有有效匹配对中的槽位重涂为橙(7)（保留掩码形状，仅改颜色）。
5. 在符号槽位网格的每一行和每一列中，找到所有有效匹配槽位。对于同一行/列中相邻的两个有效匹配槽位（中间无其他有效匹配槽位），将它们之间的所有槽位重涂为品红(6)（保留掩码形状，仅改颜色）。
6. 未参与任何有效匹配的槽位保持原色。图例和分隔线不变。

**关键洞察**：图例不是颜色互换指令——它是匹配准入的元规则。形状相同是必要条件但不充分；颜色必须恰好跨越同一图例行的两端。这意味着改变图例内容会完全重构哪些槽位被高亮，求解者必须从多个示例中归纳出这一双条件筛选机制。

## 新题 4：同色精灵体计数参数化矩形拉伸距离

**组合逻辑**：[counting + shape_identity](创新：计数结果不用于选择输出对象，而是作为另一操作的数值参数) + [stretch](创新：拉伸距离由外部计数决定而非标记像素位置) + [recolor](创新：拉伸后的矩形边框颜色由最高频精灵体颜色决定)

**来源原语**：counting / sprite / shape_identity / most_frequent_sprite_output（来自 39a8645d）；stretch / hollow_rectangle / marker_pixel / marker_determines_stretch_endpoint（来自 b548a754）；recolor（来自多题）

**依赖链**：精灵体与矩形通过颜色建立对应关系（同色）；精灵体计数产生数值；数值参数化矩形拉伸距离；标记像素决定拉伸方向。计数与拉伸跨越了两类完全不同的几何对象，通过颜色桥接。去掉计数则拉伸距离未知，去掉标记则方向未知，去掉颜色桥则无法关联精灵体与矩形。

统计与每个空心矩形同色的小精灵体数量，该数量决定矩形朝其标记像素方向拉伸的像素距离。

**输入结构**：背景黑(0)，网格约 18x18。网格中有 2-3 个空心矩形（各自边框为不同单色，如红(2)、蓝(1)、绿(3)；边框 1 像素宽，内部为黑(0)；各矩形约 4x4 至 6x6）。每个矩形外部恰有一个灰(5)标记像素，位于矩形某一边的延长线上（与矩形同行或同列，距矩形边缘 3-8 像素）。网格空白区域散布若干小精灵体（8-连通，边界框 3x3，每个约 4-6 像素），每个精灵体为单色且颜色与某个矩形的边框色相同。同一颜色的精灵体可能有 1-4 个。生成约束：各矩形和精灵体互不重叠且互不相邻；每种矩形边框色至少有 1 个对应精灵体；拉伸后的矩形不超出网格边界且互不重叠。

**规则**：
1. 对每个空心矩形，找到所有与其边框颜色相同的小精灵体，计数得到 n。
2. 找到该矩形对应的灰(5)标记像素。标记像素与矩形的相对位置决定拉伸方向：标记在矩形上方→顶边向上拉伸，标记在右方→右边向右拉伸，以此类推。
3. 将矩形的对应边沿拉伸方向移动恰好 n 个像素。矩形保持空心结构：移动后重绘边框，内部保持黑(0)。
4. 标记像素在输出中消失（被拉伸后的矩形覆盖或移除）。若拉伸距离超过标记像素位置（即矩形边越过了标记），标记仍消失，矩形边停在拉伸 n 像素处。若拉伸 n 像素会超出网格边界，则裁剪至边界。
5. 矩形按左上角位置从左到右、从上到下依次处理。若拉伸后的矩形与另一个矩形的当前（已处理或未处理）占用区域重叠，拉伸距离缩减至刚好不重叠。
6. 精灵体在输出中保持不变。

**关键洞察**：精灵体计数不是为了选出最常见的形状（与参考题 39a8645d 的用法截然不同），而是作为一个数值参数注入到几何拉伸操作中。颜色是跨对象类型（精灵体 vs. 矩形）的隐式绑定键。

## 新题 5：对角射线交点定位对称补全中心

**组合逻辑**：[ray_extend + diagonal_dir](保留对角射线绘制) + [symmetry_completion + symmetry_orbit_mapping](创新：对称中心不预设，而是由射线交点动态确定)

**来源原语**：ray_extend / isolated_pixel / diagonal_dir / both_diags_through_pixel（来自 623ea044）；symmetry_completion / symmetric_pattern / masked_pixel / symmetry_orbit_mapping / full_symmetry_group_orbit_constraint（来自 47996f11）

**依赖链**：两个孤立像素的位置决定四条对角线的几何形状；对角线的交点提供对称中心坐标；对称中心是补全掩码像素的必要前提。没有孤立像素就没有射线，没有射线就没有交点，没有交点就无法确定对称中心，没有对称中心就无法补全图案。射线绘制和对称补全通过"交点即中心"这一几何关系紧耦合。

过两个孤立像素画对角线，交点即为部分图案的旋转对称中心，据此补全所有掩码像素。

**输入结构**：背景黑(0)，网格约 15x15（正方形）。网格上有两个孤立像素，颜色分别为红(2)和蓝(1)，位置使得过红像素的两条对角线与过蓝像素的两条对角线恰好有一个共同交点（即红像素与蓝像素不在同一行、同一列、同一对角线上，且各自两条对角线中恰有一对相交于网格内一点）。另外，网格上有一组绿(3)像素构成的部分图案（约 8-12 个像素，分布在交点周围），以及若干品红(6)掩码像素（约 4-6 个）。该部分图案加上掩码像素的位置，整体关于上述交点具有 C4（90° 旋转）对称性。生成约束：交点坐标为整数格点；绿色像素和品红像素均不与孤立像素或对角线路径重合；每个品红像素在其 C4 轨道中至少有一个绿色像素对应。

**规则**：
1. 定位两个孤立像素（红(2)和蓝(1)）。
2. 过每个孤立像素画两条完整对角线（从像素出发向四个 45° 方向延伸至网格边缘），用该像素的颜色绘制。红像素产生红色对角线，蓝像素产生蓝色对角线。
3. 找到红色对角线与蓝色对角线的唯一交点——该交点即为对称中心 C。若交点处有像素冲突（红线与蓝线交叉），该像素涂为黄(4)以标记中心。
4. 对每个品红(6)掩码像素，计算其关于中心 C 的 C4 轨道（依次旋转 90°、180°、270° 得到的三个对应位置）。在轨道中找到颜色为绿(3)的像素，将品红像素替换为绿(3)。
5. 若对角线像素与绿色图案像素位置重合，绿色图案优先（对角线不覆盖图案）。
6. 对角线像素与品红像素位置重合时，先完成品红→绿的替换，替换后的绿色优先于对角线。

**关键洞察**：对角射线不是输出的主体——它们是用于几何定位的辅助构造。两个看似无关的彩色点通过对角线交点这一几何关系，为远处的图案补全提供了必需的对称中心坐标。求解者需要意识到孤立像素的存在目的不是"画线"，而是"定位"。

## 新题 6：侧边标记方位选定镜像轴与拼接方向

**组合逻辑**：[mirror](创新：镜像轴不固定，由侧边标记的接触方位动态决定) + [crop](保留裁剪提取) + [concatenate](创新：拼接方向与镜像轴耦合) + [contact_side_color](创新：接触侧颜色不再重涂对象，而是成为拼接接缝的颜色)

**来源原语**：mirror / concatenate / flip_copy_stacked（来自 4c4377d9）；crop（来自 39a8645d）；side_marker / contact_side_color / panel_region / contained_in（来自 c3fa4749）

**依赖链**：侧边标记的方位编码了三重信息：(1) 镜像轴方向（上下标记→水平轴→垂直翻转，左右标记→垂直轴→水平翻转），(2) 拼接方向（镜像副本拼在标记所在侧），(3) 接缝颜色（标记颜色）。裁剪提取面板内的图案后，必须先根据标记方位确定镜像轴，再根据同一标记确定拼接方向和接缝颜色。去掉侧边标记则轴和方向均未知，去掉裁剪则无图案可操作，去掉镜像或拼接则输出不完整。

从各面板中裁剪图案，按侧边标记所在方位决定镜像轴，将原图与镜像副本沿标记方向拼接，用标记颜色画接缝线。

**输入结构**：背景黑(0)，网格约 16x16。网格中有 2-3 个单色面板区域（各自为不同颜色的实心矩形，约 5x5 至 7x7，如蓝(1)、绿(3)）。每个面板内部包含一个小的多色非对称图案（3-5 个像素，颜色与面板色不同，4-连通）。每个面板的恰好一条边上有一排侧边标记像素：该边的所有面板边框像素被替换为另一种颜色（如红(2)、黄(4)），形成 1 像素宽的标记条。标记条颜色与面板色和图案色均不同。生成约束：各面板互不相邻，距网格边缘至少 2 像素；每个面板的标记条位于不同方位（如一个在顶边，一个在右边），保证示例间方位有变化；图案关于任何轴都不对称（确保镜像操作可观察）。

**规则**：
1. 对每个面板，识别侧边标记条所在的边（顶/底/左/右）及其颜色 M。
2. 确定镜像轴：标记在顶边或底边→镜像轴为水平轴（沿图案水平中线翻转，即上下翻转）；标记在左边或右边→镜像轴为垂直轴（沿图案垂直中线翻转，即左右翻转）。
3. 裁剪面板内部的图案（不含面板边框和标记条），得到一个最小边界框的小网格，背景为面板颜色。
4. 对裁剪结果沿确定的轴做镜像，得到翻转副本。
5. 拼接：将翻转副本放在标记条所在方向。具体地：标记在顶边→翻转副本放在原图案上方；标记在右边→翻转副本放在原图案右方；以此类推。两者之间插入 1 像素宽的接缝行/列，颜色为标记颜色 M。
6. 输出：所有面板的拼接结果排列在黑色背景上，按面板在输入中的左上角位置从左到右排列，面板间隔 1 列黑色背景。输出高度为所有拼接结果中最高者，较矮的拼接结果顶部对齐、底部补黑(0)。

**关键洞察**：侧边标记是一个空间编码元素，用一个几何属性（方位）同时决定了镜像轴、拼接方向和接缝颜色三个参数。求解者必须意识到标记条不是要被"涂到对象上"的颜色指令（与参考题 c3fa4749 不同），而是一个多功能的几何指示器。

## 新题 7：顶行掩码约束下方泛洪填充的列范围

**组合逻辑**：[compress + mask_mapping](创新：压缩产生的列掩码不仅生成新行，还作为空间约束传递给下方操作) + [flood_fill + opening_direction](创新：泛洪填充被列掩码额外约束，只能在"活跃列"中扩展) + [obstacle_casts_shadow](保留障碍阴影)

**来源原语**：compress / recolor / top_row_mask / mask_mapping / fg_columns_new_color（来自 7e4d4f7c）；flood_fill / partial_enclosure / opening_direction / fill_seed / obstacle_casts_shadow（来自 b9e38dc0）

**依赖链**：顶行前景像素的位置产生一个列掩码（"活跃列"集合）。该掩码同时有两个用途：(1) 生成一行新的品红标记行（局部输出），(2) 约束下方所有泛洪填充只能在活跃列中扩展（全局约束）。泛洪填充本身还受障碍阴影限制。去掉顶行掩码则填充无列约束（结果完全不同），去掉泛洪填充则掩码只产生一行标记无实际作用，去掉障碍则填充范围过大。

从顶行提取前景列掩码，该掩码既生成一行压缩标记，又限制下方泛洪填充只能在对应列中扩展。

**输入结构**：背景黑(0)，网格约 14x16。顶部区域（行 0-2）为"控制条"：行 0 包含若干前景像素（如蓝(1)），散布在不同列位置，其余为黑(0)；行 1 在第 0 列有一个与行 0 前景同色的标记像素，其余为黑(0)；行 2 与行 1 相同。行 3 是一条灰(5)水平分隔线。下方区域（行 4-15）包含 2-3 个灰(5)半封闭墙（U 形，各约 4x6 内部区域，开口朝向不同方向），每个墙内有一个彩色种子像素（如红(2)、绿(3)）。墙体之间可能有 1-2 个孤立的栗(9)像素作为障碍物。生成约束：行 0 的前景像素至少 3 个，至少跨越半数列；每个封闭墙的内部区域跨越的列中，既有活跃列也有非活跃列（确保列约束可观察）；障碍物位于某个墙体开口方向的辐射路径上。

**规则**：
1. 提取行 0 的前景像素掩码：记录所有包含非黑像素的列号，这些列为"活跃列"。
2. 生成品红(6)标记行：在行 0 下方（分隔线上方），创建一行，其中活跃列的像素为品红(6)，非活跃列为黑(0)。该行插入在原行 2 的位置（原行 2 的标记像素删除，替换为品红标记行）。
3. 对下方区域的每个半封闭墙执行泛洪填充：从种子像素出发，用种子颜色填充墙内部的黑(0)像素，并通过墙的开口向外辐射。
4. **列约束**：泛洪填充（包括墙内部和辐射部分）只能填充位于活跃列中的像素。非活跃列中的像素即使相邻也不被填充，视为隐形墙壁。
5. 障碍物（栗(9)像素）沿辐射方向投射阴影：障碍物后方（沿开口方向的延长线上）的像素不被填充，即使在活跃列中。
6. 墙体、分隔线、障碍物、行 0 原始像素均保持不变。处理各墙体的顺序不影响结果（各墙体的填充区域互不干涉，因为生成约束保证无冲突）。

**关键洞察**：顶行掩码在参考题 7e4d4f7c 中仅用于生成一行压缩输出，但在本题中它同时作为全局空间约束传递到网格下方，将泛洪填充的二维扩展限制为仅在特定列中进行。这种跨区域的约束传播在任一参考题中都不存在。

## 新题 8：训练对示例教授路由规则，测试区域执行推断

**组合逻辑**：[analogy_inference + rule_inference](保留类比框架) + [line_drawing + routed_via_waypoint](创新：类比的对象不是像素图案而是抽象的路由算法) + [training_pair_mapping + palette_match_pairing](创新：配对标识从调色板匹配改为标记像素颜色集合匹配)

**来源原语**：analogy_inference / rule_inference / training_pair_mapping / palette_match_pairing / hollow_frame / sprite（来自 4c7dc4dd）；line_drawing / marker_pixel / orthogonal_path / routed_via_waypoint / horizontal_then_vertical（来自 0e671a1a）

**依赖链**：首先通过标记颜色集合匹配识别训练对（两个框中标记颜色完全相同）。然后比较训练源与训练目标中的路由路径，推断路由规则的变换（如从"先横后纵"变为"先纵后横"，或连接顺序从"按颜色编号"变为"按空间距离"）。最后将推断出的变换应用到测试框的标记像素上生成新路径。三步缺一不可：无配对则不知哪两个框构成训练集，无比较则规则未知，无应用则输出缺失。

观察训练对中路由路径的变换规则（如路由方向翻转、连接顺序改变），将该规则应用到新的标记像素布局上。

**输入结构**：背景黑(0)，网格约 22x22。网格中有三个彩色空心框（边框分别为红(2)、蓝(1)、绿(3)，各约 8x8 内部空间，边框 1 像素宽）。每个框的内部有 3 个标记像素（颜色为橙(7)、黄(4)、栗(9)中的子集——三个框中至少两个框的标记颜色集合完全相同，构成训练对；第三个框使用相同颜色集合但位置不同，为测试框）。训练源框内部：标记像素之间已画好灰(5)正交路径，路由方式为"先横后纵"（从起点水平移动到目标列，再垂直移动到目标行），连接顺序为按标记像素在框内从左到右排列。训练目标框内部：标记像素位置与训练源相同，但路径使用不同路由方式（如"先纵后横"），灰(5)路径已画好。测试框内部：只有标记像素，无路径。生成约束：训练源与训练目标中标记像素的位置完全相同，仅路径不同，确保路由规则变换可被唯一推断；测试框的标记像素位置与训练对不同（避免记忆路径）。三个框互不重叠，各自被至少 2 像素的背景间隔。

**规则**：
1. 识别三个空心框及各自内部的标记像素颜色集合。找到标记颜色集合相同的两个框——它们是训练对。剩余框为测试框。
2. 在训练源框中，分析灰(5)路径的路由方式：对每一段从标记 A 到标记 B 的路径，判断是"先横后纵"还是"先纵后横"（通过检查路径弯折点的位置）。记录连接顺序（哪个标记先连到哪个标记）。
3. 在训练目标框中，分析同样的路由方式和连接顺序。
4. 推断变换规则：路由方式如何改变（如"先横后纵"→"先纵后横"），连接顺序如何改变（如"从左到右"→"从右到左"，或"按上到下"→"按下到上"）。
5. 将变换规则应用到测试框：首先用训练源的路由方式和连接顺序虚拟生成路径，然后应用变换得到最终路径。用灰(5)在测试框内部画出变换后的正交路径。
6. 路径仅画在黑(0)像素上，标记像素保持原色。路径像素不超出框边界。若两段路径共享像素，该像素仍为灰(5)。
7. 输出：整个网格，训练源和训练目标保持不变，测试框内部新增灰(5)路径。

**关键洞察**：类比的对象不是像素图案的几何变换（如旋转、翻转），而是一个抽象的路由算法（路由方向 + 连接顺序）。求解者必须在算法层面提取"源路由策略→目标路由策略"的映射，然后将这个元规则泛化到新的空间布局上。这是一种高阶抽象——类比发生在操作规则而非操作对象上。
