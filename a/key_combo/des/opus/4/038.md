## 新题 1：缺口方向控制环色循环与内部溢出

**组合逻辑**：[缺口像素/gap_pixel + 缺口定射线向/gap_determines_ray](来自292dd178) → [循环移色/color_cycle + 反向循环/opposite_cycle + 角与边中分组/corner_side_group](来自46c35fc7，创新：循环方向不再固定，由缺口朝向决定) → [洪泛填充/flood_fill](来自292dd178，创新：填充色由循环前状态决定而非固定色)

**来源原语**：gap_pixel、gap_determines_ray（292dd178）；color_cycle、opposite_cycle、corner_side_group、ring_object、corner_pixel、side_center_pixel（46c35fc7）；flood_fill（292dd178）

**依赖链**：缺口位置决定循环方向 → 循环改变边框颜色分布 → 循环前缺口位置的颜色决定内部填充色。三个环节形成因果链：不知道缺口位置就无法确定循环方向，不执行循环就无法得到最终边框色，不记住循环前状态就无法确定填充色。

将带缺口的多色环形框按缺口朝向决定颜色循环方向，再用循环前缺口处的颜色填充环内部。

**输入结构**：黑(0)背景上有多个 5x5 的环形边框（8 个边框像素围绕 3x3 的黑(0)中心，其中中心的四周共 8 个边框位），每个环恰好缺少一个非角位的边框像素（即缺口在上、下、左或右边中某处）。每个环的 4 个角位像素使用同一种颜色 C_corner，4 个边中像素（去掉缺口后剩 3 个）使用另一种颜色 C_side，且不同环的颜色组合各不相同。网格约 18x18，包含 3-4 个环，环之间间距至少 2 像素，互不接触。生成约束：每个环的 C_corner 和 C_side 互不相同且都不是黑(0)。

**规则**：
1. 对每个环，定位缺失的边框像素（缺口）。缺口所在边决定缺口朝向：缺口在顶边→朝上，底边→朝下，左边→朝左，右边→朝右。
2. 若缺口朝上或朝右，角位像素颜色沿顺时针方向（左上→右上→右下→左下→左上）循环移动一步；若缺口朝下或朝左，角位像素颜色沿逆时针方向循环移动一步。
3. 边中像素（包含缺口位置在内的 4 个边中位）的颜色沿与角位相反的方向循环一步。缺口位置视为存在一个"虚拟像素"参与循环：它接收来源位置的颜色并传递给目标位置，但自身不显示在输出中（仍为黑(0)）。
4. 将每个环的 3x3 内部区域（中心像素及其被环围住的区域）填充为**循环前**缺口虚拟位置所持有的颜色（即循环前该边中位的 C_side）。
5. 背景和环外区域保持不变。

**关键洞察**：缺口方向既控制循环方向，又隐式编码了填充色——填充色是循环前缺口处的颜色，而非循环后的颜色，求解者必须同时追踪循环前后两种状态。

## 新题 2：封闭区域计数驱动精灵裁排

**组合逻辑**：[计数/counting + 封闭区域/enclosed_region](来自89565ca0) → [排序/sorting](来自f8ff0b80/89565ca0，创新：排序键从像素面积/区域数变为拓扑属性——内部孔洞数) → [裁剪/crop + 拼接/concatenate + 布局轴方向/layout_axis_direction](来自67636eac)

**来源原语**：counting、enclosed_region（89565ca0）；sorting、pixel_count（f8ff0b80）；crop、concatenate、connected_sprite、layout_axis_direction、tight_packing_by_position（67636eac）

**依赖链**：先对每个精灵体内部做洪泛填充计数孔洞 → 孔洞数作为排序键 → 排序结果决定裁剪后的拼接顺序。删除计数环节则无法确定排序键；删除排序则裁剪后无法确定拼接顺序。

统计每个精灵体内部封闭孔洞数，按孔洞数升序排列后沿布局轴紧密拼接裁剪图。

**输入结构**：黑(0)背景上有 4-6 个分离的单色 8-连通精灵体，全部使用同一种前景色（如蓝(1)）。每个精灵体是不规则形状（8-20 像素），可能含 0-3 个内部封闭的黑(0)区域（孔洞），即精灵体像素完全包围的背景连通区。所有精灵体的包围盒尺寸相同（如 5x5 或 6x6）。精灵体中心在行方向或列方向上的展布范围不等（一个方向明显大于另一个），由此定义布局轴。网格约 20x25。生成约束：至少有两个精灵体的孔洞数不同；精灵体互不接触且不触及网格边界。

**规则**：
1. 识别所有 8-连通的前景精灵体，裁剪至各自的最小包围盒。
2. 对每个精灵体，在其包围盒内统计被前景像素完全 4-连通包围的黑(0)连通区域数量（孔洞数）。
3. 按孔洞数从少到多排序。若两个精灵体孔洞数相同，按前景像素总数从少到多排序；若仍相同，按原始包围盒左上角坐标的行优先序排列（行号小的在前，行号相同则列号小的在前）。
4. 判定布局轴：若精灵体中心在列方向的展布范围严格大于行方向，则为水平布局；否则为垂直布局。
5. 按排序结果，沿布局轴方向紧密拼接所有裁剪后的包围盒，输出一个无间隙的拼接网格。

**关键洞察**：排序键不是可直接观察的像素数或空间位置，而是需要对每个精灵体内部做拓扑推理（封闭区域计数）才能获得的隐含属性，且仅凭单个示例可能无法区分"按孔洞数"与"按像素数"排序（需要看到两者不一致的示例才能确认规则）。

## 新题 3：三点定框与格子交叉混合填充

**组合逻辑**：[补全/complete + 包围盒/bounding_box + 三点定矩形框/three_pts_define_rect](来自e7639916) → [填充/fill + 连线/trace + 共行或共列/shared_row_col](来自e760a62e，创新：填充不在格子上而在完成的矩形框上，且混合色规则由框间重叠触发而非行列交叉) → [双色交叉混合色/intersect_blend_color](来自e760a62e，创新：混合发生在不同颜色矩形框的重叠区域)

**来源原语**：complete、bounding_box、three_pts_define_rect、marker_pixel、hollow_rect（e7639916）；fill、trace、shared_row_col、intersect_blend_color（e760a62e）

**依赖链**：三个标记像素定位包围盒 → 补全矩形边框 → 同色标记在框边上的共行/共列决定填充方向 → 不同色矩形的重叠区域触发混合色。补全步骤产生边框几何结构，填充步骤基于该结构延伸，混合规则基于多个填充结果的空间交集——三步之间存在几何信息的递进依赖。

从散落标记点补全矩形框，沿标记点共行/共列方向向框内填充条带，不同色条带重叠处混合为第三种颜色。

**输入结构**：黑(0)背景上有 2-3 组标记像素，每组 3 个同色像素。不同组使用不同颜色：第一组红(2)，第二组绿(3)，第三组（若有）橙(7)。每组的 3 个标记像素位于它们共同包围盒的边界上（角或边上），且三点足以唯一确定一个轴对齐的矩形。不同组的包围盒可以部分重叠但不完全包含。网格约 15x18。生成约束：同组 3 个像素不共线；不同组的矩形框至少有一列或一行的重叠。

**规则**：
1. 对每组同色标记像素，计算三点的最小包围盒，在包围盒的四边绘制蓝(1)矩形边框（1 像素宽）。原始标记像素保持原色覆盖在蓝(1)边框之上。
2. 对每组标记，检查组内是否有两个标记共享同一行或同一列。若两个标记共行，则沿该行从矩形左边框到右边框（含边框）填充该组的标记色。若两个标记共列，则沿该列从矩形上边框到下边框（含边框）填充该组的标记色。一组内可能同时有共行和共列的对。
3. 不同颜色的填充条带重叠的像素设为品红(6)。
4. 蓝(1)边框像素若被填充条带覆盖，显示条带色（或混合色）；若未被覆盖，保持蓝(1)。
5. 绘制和填充顺序不影响结果：条带色覆盖蓝边框，混合色覆盖单色条带，标记像素始终保持原色显示在最顶层。

**关键洞察**：标记像素同时承担两个角色——它们既是定义矩形边框的控制点（几何补全），又是定义填充条带方向的端点（共行/共列关系），而不同矩形之间的空间重叠产生了参考题中不存在的混合色交互。

## 新题 4：三角尖端投射条带与孤立像素交叉计数

**组合逻辑**：[射线延伸/ray_extend + 方向指示/direction_indication + 顶点反基底延伸/tip_away_from_base](来自25d487eb，创新：射线变为条带，宽度由三角形底边长度决定) → [计数/counting](来自f8ff0b80/89565ca0，创新：计数对象从像素面积/封闭区域变为穿过某点的条带数) → [重涂色/recolor + 颜色循环分配/cyclic_color_assignment](来自9473c6fb，创新：循环分配的触发条件从扫描序位置变为交叉计数)

**来源原语**：ray_extend、direction_indication、tip_away_from_base、triangle（25d487eb）；counting、pixel_count（f8ff0b80）；recolor、cyclic_color_assignment、isolated_pixel（9473c6fb）

**依赖链**：三角形方向决定投射方向 → 投射条带覆盖网格区域 → 孤立像素被多少条带穿过决定其重涂色。删掉方向判断则条带无法确定；删掉计数则无法区分不同孤立像素的颜色。

从每个三角形的尖端沿远离基底方向投射同色条带，统计每个孤立像素被多少条条带穿过，按交叉数重涂色。

**输入结构**：黑(0)背景上有 2-3 个单色填充三角形（不同三角形颜色不同，选自红(2)、绿(3)、蓝(1)），每个三角形朝某个基本方向（上、下、左、右），底边长 2-4 像素，高 3-5 像素。每个三角形的底边中央有一个灰(5)标记像素，标识基底位置。另外，网格上散布 4-8 个黄(4)孤立像素（互不相邻，不与三角形接触）。网格约 18x18。生成约束：至少有一个孤立像素被两条以上条带穿过；三角形之间不重叠。

**规则**：
1. 对每个三角形，找到灰(5)基底标记像素，确定其暴露侧（不被三角形覆盖的那一侧），投射方向为暴露侧的反方向（即从基底穿过三角形，经过尖端，继续向外）。
2. 从三角形尖端开始，沿投射方向延伸一个条带至网格边界。条带宽度等于三角形底边的像素长度，条带以尖端为中心对齐，使用该三角形的颜色绘制。条带覆盖路径上的背景像素，但不覆盖其他三角形或其他条带（先绘制的保留）。
3. 统计每个黄(4)孤立像素被多少条不同颜色的条带覆盖（条带像素与孤立像素位置重合即算覆盖，此时孤立像素被条带遮挡）。
4. 重涂每个孤立像素：被 0 条条带覆盖→保持黄(4)不变；被恰好 1 条条带覆盖→重涂为橙(7)；被 2 条及以上条带覆盖→重涂为栗(9)。未被覆盖的孤立像素仍显示为黄(4)。
5. 最终输出中，条带像素、三角形像素、灰(5)标记像素均保留，孤立像素按上述规则重涂后显示在条带之上（孤立像素层级最高）。

**关键洞察**：三角形不仅是方向指示器，其底边长度还编码了条带宽度——同样位置的孤立像素可能因三角形大小不同而落入或落出条带范围，因此求解者必须同时推断方向和宽度两个参数。

## 新题 5：矩形延伸轮廓的象限分层重涂

**组合逻辑**：[射线延伸/ray_extend + 标记排除对应行列/marker_excludes_row_col + 侧边带对齐/side_strip_align](来自9def23fe) → [重涂色/recolor + 象限与边距分层/quadrant_border_layer + 相对位置决定颜色/relative_position_determines_color](来自639f5a19，创新：象限着色不再作用于原始矩形，而是作用于被控制像素塑造后的不规则延伸轮廓) → [仅内部像素变色/only_interior_recolored + 内部与边框/interior_vs_border](来自bb43febb，创新：边框定义从简单矩形变为不规则延伸形状的外边界)

**来源原语**：ray_extend、marker_excludes_row_col、side_strip_align、solid_rectangle、control_pixel、extension_stripe（9def23fe）；recolor、quadrant_border_layer、relative_position_determines_color、frame_zone（639f5a19）；interior_vs_border、only_interior_recolored（bb43febb）

**依赖链**：控制像素排除行列 → 确定延伸轮廓 → 延伸轮廓的包围盒中心划分象限 → 象限决定边框色 → 内部区域统一填充。控制像素改变了延伸形状，延伸形状改变了象限划分方式，象限划分决定了最终颜色——信息在三步间逐级变换。

用控制像素塑造矩形的十字延伸轮廓，再对该轮廓按象限分层着色边框、统一填充内部。

**输入结构**：黑(0)背景上有一个青(8)实心矩形（约 6x8），矩形的上、下、左、右四个侧边带区域中散布若干栗(9)控制像素（每侧 0-3 个），每个控制像素位于矩形某条边的延长线上（与矩形共行或共列，位于矩形外侧）。网格约 20x22。生成约束：至少有一个侧面没有控制像素（即至少一个方向完全延伸）；每侧的控制像素不超过矩形在该方向的尺寸减一。

**规则**：
1. 对矩形的上方区域：矩形每一列若在上侧边带没有栗(9)控制像素，则将该列从矩形顶边向上延伸至网格边界，填充青(8)。有控制像素的列不延伸。下方、左方、右方同理。
2. 计算延伸后完整图形（原始矩形 + 所有延伸条纹）的最小包围盒，取包围盒的中心点（行中心取 (top+bottom)//2，列中心取 (left+right)//2）。
3. 以中心点为原点，将延伸图形的所有像素按象限着色其 2 像素厚边框：位于中心点严格左上方的边框像素→品红(6)；严格右上方→蓝(1)；严格左下方→红(2)；严格右下方→绿(3)。中心行和中心列上的边框像素归入其下方或右方象限（即中心行算下半，中心列算右半）。
4. "边框像素"定义：该像素的 4-邻域中至少有一个像素不属于延伸图形（即紧邻背景或网格外）。"内部像素"定义：4-邻域全部属于延伸图形。
5. 所有内部像素统一填充为黄(4)。
6. 栗(9)控制像素保持原位不变，显示在最顶层。

**关键洞察**：控制像素不仅排除了某些延伸条纹，还间接改变了延伸图形的包围盒中心位置，从而改变了象限划分——移除或增加一个控制像素可能使大片像素从一个象限翻转到另一个象限，导致颜色剧变。

## 新题 8：扫描序循环着色与反对角线一致性约束的同时满足

**组合逻辑**：[排序/sorting + 扫描序/scan_order + 长轴决定扫描/longer_axis_determines_scan + 颜色循环分配/cyclic_color_assignment](来自9473c6fb) ↔ [填充/fill + 反对角线等值/anti_diagonal_equivalence](来自4aab4007，创新：反对角线约束不用于修复缺损，而是作为与循环分配并行的第二约束)（双向约束同时满足，非线性流水线）

**来源原语**：sorting、scan_order、longer_axis_determines_scan、cyclic_color_assignment、isolated_pixel（9473c6fb）；fill、anti_diagonal_equivalence（4aab4007）；recolor（b1948b0a）

**依赖链**：这不是线性流水线——两条规则同时约束输出：(A) 孤立像素按扫描序循环分配颜色，(B) 同一反对角线上的像素必须同色。两条规则可能冲突：扫描序给出的颜色与反对角线邻居要求的颜色不同。冲突解决规则本身就是题目的核心推理。

在孤立像素集合上同时满足两条约束：扫描序循环着色和反对角线同色，冲突时反对角线约束优先，由最早被扫描到的像素决定该对角线的颜色。

**输入结构**：黑(0)背景上散布 10-16 个灰(5)孤立像素（4-连通互不相邻）。这些像素的包围盒的行展布和列展布不等（用于确定扫描方向）。部分像素恰好落在同一条反对角线上（即 row+col 相同），每条反对角线上最多 2-3 个像素。网格约 14x14。生成约束：至少有两条反对角线上各有 2 个以上的孤立像素；像素分布使得至少存在一个冲突（扫描序分配的颜色与反对角线先驱的颜色不同）。

**规则**：
1. 计算所有灰(5)孤立像素的包围盒。若行展布 >= 列展布，按行优先序扫描（行号小的在前，行号同则列号小的在前）；否则按列优先序扫描。
2. 准备颜色循环：红(2)、青(8)、灰(5)，按此顺序不断循环。
3. 按扫描序依次处理每个孤立像素。对当前像素，计算其反对角线索引 D = row + col。
4. 若 D 对应的反对角线上此前已有像素被分配了颜色 C_prev，则当前像素强制分配 C_prev（反对角线约束优先），且此次分配**不消耗**循环位置（循环指针不前进）。
5. 若 D 对应的反对角线上此前无像素被分配颜色，则当前像素取循环中的下一个颜色，循环指针前进一步。该颜色同时成为该反对角线的锁定颜色。
6. 将每个灰(5)孤立像素重涂为其分配的颜色。背景保持不变。

**关键洞察**：循环指针只在"首次定义反对角线颜色"时前进，在"跟随已定义的反对角线颜色"时跳过——这意味着像素的扫描位置和反对角线归属共同决定了颜色，且一个像素跳过循环会影响所有后续像素的颜色分配，形成连锁效应。仅看单个示例难以区分"是否消耗循环位"这条隐蔽规则。

**规则**：
