## 新题 1：噪声回收射线

**组合逻辑**：[擦除](已有) + [射线延伸](创新：射线长度由擦除计数决定) + [像素数守恒](创新：从全局统计约束变为按簇分配约束) + [八连通判定](已有)

**来源原语**：擦除/孤立像素/连通分量/八连通判定(42a50994), 射线延伸(1190bc91), 像素数守恒(88bcf3b4), 同色射线归属锚块(f28a3cbb→改造为"孤立像素归属最近簇")

**依赖链**：八连通分量标记 → 孤立像素识别与按最近簇归属分配 → 擦除孤立像素（得到各簇的回收计数） → 各簇向下发射射线（长度 = 该簇回收的孤立像素数） → 总前景像素数守恒

将每个孤立前景像素擦除后，按距离归属最近的簇，再从各簇底部向下发射等长于回收数的射线，总前景像素数不变。

**输入结构**：约 14x14 网格，黑(0)背景。单一前景色绿(3)。绿像素由若干孤立像素（8-连通大小为 1）和 3-5 个簇（每个簇为 8-连通分量，3~7 像素，形态各异——不限于矩形，可包含对角连接的不规则形状）组成。各簇之间互不相邻（最近像素曼哈顿距离 >= 3）。孤立像素散布于簇之间和周围。生成约束：每个簇的正下方至少有足够的空背景行来容纳其可能回收的最大射线长度；各簇底部像素所在列互不相同。

**规则**：
1. 使用 8-连通标记所有绿(3)连通分量。
2. 对每个大小为 1 的分量（孤立像素），计算它到每个大小 > 1 的分量（簇）中最近像素的曼哈顿距离，将该孤立像素归属于距离最小的簇。平局时归属于簇的边界框左上角列更小的簇；仍平局则归属行更小的簇。
3. 将所有孤立像素设为黑(0)。
4. 对每个簇，令 N = 归属于该簇的孤立像素个数。找到该簇中行坐标最大（最靠下）的像素；若有多个取列坐标最小的。从该像素正下方一格开始，向下连续绘制 N 个红(2)像素。若射线遇到非黑像素或超出网格下边界，在该位置停止（实际绘制数可少于 N）。
5. 簇的原始绿(3)像素保持不变。

**关键洞察**：擦除不只是清理噪声——被擦除的像素数量被回收为射线资源，通过空间归属规则分配给各簇。射线的长度取决于附近噪声密度，使得噪声多的区域产生更长的延伸。

## 新题 2：对角分类决定印章轴线

**组合逻辑**：[分类/对角朝向](已有) + [印章覆盖/周期排布](创新：印章方向由分类结果决定，而非固定) + [多数朝向决定色](创新：从仅决定颜色扩展为决定印章方向+颜色)

**来源原语**：分类/对角线段/对角朝向/多数朝向决定色(1d61978c), 印章覆盖/精灵体/周期排布/周期内指定位变色(d304284e)

**依赖链**：对角朝向分类 → 多数/少数朝向判定 → 多数朝向的线段沿水平方向周期印章、少数朝向的线段沿垂直方向周期印章 → 周期内每第 3 个副本变色

将对角线段按朝向分为多数派和少数派；多数派沿水平方向周期复制（每第 3 个副本变青），少数派沿垂直方向周期复制（每第 3 个副本变红），分类结果同时决定复制轴向和变色规则。

**输入结构**：约 20x20 网格，黑(0)背景。单一前景色灰(5)。灰像素形成若干互不相连的对角线段，每段 3~5 像素，沿某条 45 度对角线排列（NW-SE 方向或 NE-SW 方向）。线段总数 5~8 条，两种朝向都有但数量不等。各线段的边界框互不重叠，且边界框之间至少留有 2 列或 2 行的间隔。生成约束：网格足够大，使得每条线段在其印章方向上至少能放下 3 个副本（含原始）而不超出边界。

**规则**：
1. 识别每条对角线段的朝向：若线段像素从左上到右下递增则为 NW-SE 朝向，否则为 NE-SW 朝向。
2. 统计两种朝向的线段数量，多数朝向记为 M，少数朝向记为 m（数量相等时，NW-SE 为 M）。
3. 对每条 M 朝向的线段：以其原始位置为起点，向右每隔（线段边界框宽度 + 1）列放置一个副本，总共放置 3 个副本（含原始共 4 个）。在这 4 个位置中，第 3 个（从 0 计数的 index 2）副本重涂色为青(8)，其余保持灰(5)。超出网格右边界的部分裁剪丢弃。
4. 对每条 m 朝向的线段：以其原始位置为起点，向下每隔（线段边界框高度 + 1）行放置一个副本，总共放置 3 个副本（含原始共 4 个）。在这 4 个位置中，第 3 个（index 2）副本重涂色为红(2)，其余保持灰(5)。超出网格下边界的部分裁剪丢弃。
5. 若两条不同线段的印章副本在某像素重叠，后处理的线段（按原始线段边界框左上角从左到右、从上到下排序）覆盖先处理的。

**关键洞察**：对角朝向的多数/少数分类不仅决定颜色（如源题），而且决定了印章复制的方向轴。同一条线段的命运（水平扩展或垂直扩展）完全取决于全局统计结果，需要对比多个示例才能确认哪个朝向在该示例中是多数。

## 新题 3：跨尺度配对的表格位置涂色

**组合逻辑**：[形状匹配/跨尺度同形](已有) + [裁剪/返回较小者](创新：不再直接裁剪输出，而是保留在原位并重涂色) + [表格行列位/角落与内部分色](创新：涂色规则从固定映射变为依赖匹配结果的条件映射)

**来源原语**：形状匹配/跨尺度同形/缩放对象/干扰对象/返回较小者(ce602527), 分隔线网格/网格单元格/表格行列位/角落与内部分色(e9c9d9a1), 裁剪(ce602527), 擦除(42a50994)

**依赖链**：分隔线网格识别 → 各单元格内对象提取 → 跨单元格缩放形状匹配（2 倍） → 配对成功的保留较小者、擦除较大者与干扰对象 → 根据较小者所在单元格的表格位置决定涂色

在分隔线网格中找到形状相同但尺度不同的对象对，保留较小者并按其所在单元格位置（角落/内部/边缘）重涂色，擦除较大者和干扰对象。

**输入结构**：约 19x19 网格。绿(3)分隔线将画布分为 3x3 共 9 个单元格（每个单元格约 5x5），背景黑(0)。9 个单元格中有 6 个包含前景对象（各为不同颜色，从蓝(1)、红(2)、黄(4)、灰(5)、品红(6)、橙(7)中选取），3 个为空。6 个对象形成 2 对跨尺度匹配（每对中较大者占约 4x4 像素、较小者占约 2x2 像素，较小者的形状放大 2 倍后与较大者的形状逐像素一致），另有 2 个干扰对象不与任何其他对象匹配。对象均为 4-连通的不规则形状（非简单矩形）。生成约束：每对匹配的两个对象颜色不同；同一单元格最多一个对象。

**规则**：
1. 用绿(3)分隔线确定 3x3 表格结构，提取每个单元格内的前景对象（忽略分隔线颜色）。
2. 对所有对象两两比较：将较小对象的掩码放大 2 倍，若与某较大对象的掩码完全吻合，则形成一对匹配。每个对象最多属于一对。
3. 对每对匹配：擦除较大对象（设为黑(0)），保留较小对象在原位。
4. 擦除所有未匹配的干扰对象（设为黑(0)）。
5. 对每个被保留的较小对象，根据其所在单元格在 3x3 表格中的位置重涂色：四角单元格 → 红(2)，四条边非角单元格 → 黄(4)，正中心单元格 → 蓝(1)。
6. 绿(3)分隔线和空单元格保持不变。

**关键洞察**：最终颜色既不由对象的原始颜色决定，也不由匹配对的属性决定，而由存活对象在表格中的空间位置决定。形状匹配决定了"谁留下"，表格位置决定了"留下后变成什么颜色"——两套独立逻辑在同一输出上交汇。

## 新题 4：周期行延伸的墙壁裁剪

**组合逻辑**：[补全/周期平移/周期偏移延续行](已有) + [墙壁像素/扫描线区间/墙壁界定范围](创新：墙壁不再界定填充色带，而是裁剪周期延伸的行图案) + [标记列为参考](创新：标记列决定裁剪区间的参考锚点)

**来源原语**：补全/行图案/周期平移/周期偏移延续行/画布(53b68214), 墙壁像素/扫描线区间/墙壁界定范围/标记列为参考/单点标记(78e78cff)

**依赖链**：周期与水平偏移推断 → 行图案向下延伸至满 10 行 → 墙壁行上的延伸像素按扫描线区间裁剪（仅保留墙壁界定范围内的部分） → 无墙壁行的延伸像素完整保留

将顶部可见行的周期图案向下延伸填满画布，但在有墙壁像素的行上，延伸图案被裁剪为墙壁相对于标记列所界定的水平区间内的部分。

**输入结构**：10 列宽的网格，高度 10 行。背景黑(0)。顶部 4~5 行包含蓝(1)前景行图案（每行是上一行的水平位移版本，周期和偏移量待推断）。底部 5~6 行中：有 2~3 行包含灰(5)墙壁像素（每行有 1~2 个灰像素，分布在不同列），其余行为纯黑背景。一个红(2)单点标记像素位于网格中某行某列（不在顶部图案行内，不与墙壁像素同行同列）。生成约束：顶部图案行足够多以唯一确定周期和偏移量；每个墙壁行上的灰像素在标记列的两侧各至少有一个（或者仅有一侧，此时区间延伸到网格边缘）。

**规则**：
1. 从顶部已有行推断最小垂直周期 P 和每周期的水平偏移量 D（像素行 i+P 的掩码等于行 i 的掩码向右循环移位 D 格）。
2. 对每个缺失行 r（行 r 无蓝像素也无墙壁像素也非标记所在行），将行 r-P 的蓝色掩码右移 D 格后填入行 r，超出网格宽度的部分丢弃。
3. 对每个墙壁行 r（行 r 包含灰像素）：先按步骤 2 计算该行的完整延伸掩码。然后确定扫描线区间——找到标记列左侧最近的灰像素列 L 和标记列右侧（含标记列）最近的灰像素列 R；若仅有左侧灰像素，区间为 [L+1, 网格右边界]；若仅有右侧，区间为 [0, R-1]；若两侧都有，区间为 [L+1, R-1]。仅保留延伸掩码中列坐标落在区间内的蓝像素，区间外的设为黑(0)。
4. 灰(5)墙壁像素和红(2)标记像素保持原样，不被蓝色覆盖。若延伸像素与墙壁/标记重叠，墙壁/标记优先。
5. 顶部原始蓝色行图案保持不变。

**关键洞察**：周期延伸产生的是"候选像素"，墙壁裁剪决定哪些候选得以存活。两套规则作用在同一批行上——删除周期延伸则无像素可裁剪，删除墙壁裁剪则所有候选都保留，两者缺一不可。

## 新题 5：字形解码构建地形轮廓并标注极值

**组合逻辑**：[解码/字形图案/字形映射颜色行](创新：解码结果不直接作为输出行，而是作为地形高度参数) + [地形轮廓/列高度极值/最深与最浅列唯一](创新：地形不来自输入，而是由解码结果构建) + [重涂色](已有)

**来源原语**：解码/字形图案/排序/位置映射/字形映射颜色行(995c5fa3), 地形轮廓/列高度极值/最深与最浅列唯一/分隔行(e45ef808), 重涂色(e45ef808)

**依赖链**：字形位置排序 → 字形解码为颜色 → 颜色映射为高度值（隐式规则，需多示例归纳） → 按排序顺序构建地形列带 → 标注最高与最低列带顶部

将顶部的字形解码为颜色，每种颜色隐式对应一个地形高度；按字形从左到右的顺序在底部构建对应高度的彩色地形列带，最后标注最高带和最低带的顶边。

**输入结构**：约 15x15 网格，黑(0)背景。顶部区域（前 5 行）包含 3~4 个灰(5)/黑(0)字形图案，每个字形为 4x4 块，字形之间以 1 列黑色间隔分隔。每个字形是 4 种固定掩码之一（与参考题 995c5fa3 相同的 4 种掩码），每种掩码映射一种颜色：红(2)、青(8)、黄(4)、绿(3)。底部区域（后 10 行）为空黑背景。生成约束：3~4 个字形中包含至少 3 种不同掩码；字形之间水平间隔恰好 1 列。

**规则**：
1. 按水平位置从左到右提取各字形块，将每个字形解码为对应颜色。
2. 每种解码颜色隐式关联一个地形高度（需对比多个示例归纳）：红(2) → 高度 2 行，黄(4) → 高度 4 行，绿(3) → 高度 6 行，青(8) → 高度 3 行。
3. 在底部区域按字形的左到右顺序依次构建地形列带：第 k 个字形对应底部区域第 k 个列带（每个列带宽度 = 字形宽度 4 列），从网格最后一行向上填充对应高度的行数，填充色为该字形的解码颜色。列带之间留 1 列黑色间隔（与字形间隔对齐）。
4. 找到高度最大（最高）的列带，将该列带最顶行的所有像素重涂色为栗(9)。
5. 找到高度最小（最矮）的列带，将该列带最顶行的所有像素重涂色为品红(6)。若最高或最矮不唯一，选最右边的列带。
6. 顶部字形图案保持原样。

**关键洞察**：字形解码和地形构建是串联的——字形输出的"颜色"在此处不是最终涂色而是地形高度的编码键。颜色到高度的映射关系是隐式的（不是简单的颜色编号 = 高度），必须通过多个示例归纳。极值标注又依赖于构建完成的地形，形成三级依赖。

## 新题 6：锚块压缩后图元分解重涂色

**组合逻辑**：[压缩/射线像素紧缩至锚](已有) + [分解/基本图元/图元形状决定涂色](创新：被分解的形状不是输入直接给出的，而是压缩操作产生的) + [同色射线归属锚块](已有)

**来源原语**：压缩/锚块/射线像素/同色射线归属锚块/射线像素紧缩至锚(f28a3cbb), 分解/基本图元/图元形状决定涂色/前景对象(150deff5)

**依赖链**：识别各色锚块与射线像素 → 射线像素向锚块压缩 → 压缩后形成新连通形状 → 对新形状做图元分解（2x2 方块 / 1x3 或 3x1 长条） → 按图元类型重涂色

将散布在锚块射线方向上的同色像素压缩回锚块旁，压缩后形成的新形状被分解为标准图元并按形状重涂色。

**输入结构**：约 15x15 网格，黑(0)背景。包含 2~3 种非黑颜色（如蓝(1)、绿(3)、橙(7)）。每种颜色恰好有一个 3x3 实心锚块，以及若干同色散落像素沿 8-邻居直线射线方向（水平、垂直或 45 度对角线）分布在锚块外。每种颜色的散落像素总数为 3~6 个，分布在 1~3 条射线上。生成约束：每种颜色的散落像素压缩至锚块后，锚块 + 压缩像素形成的连通形状恰好可以被无重叠地分解为若干 2x2 方块和 1x3/3x1 长条的组合（不留余像素）。不同颜色的锚块和射线互不重叠。

**规则**：
1. 对每种前景色，识别其 3x3 锚块和所有同色散落像素。
2. 对每个散落像素，确定它所在的射线方向（连接它和锚块中心的 8-邻居直线方向）。
3. 将该射线上的所有散落像素向锚块方向压缩：每个散落像素沿射线移动至与锚块（或已压缩的像素）相邻的最近空位。压缩后清除原始散落位置。处理顺序：距锚块最远的像素先压缩。
4. 压缩完成后，将每种颜色的锚块 + 压缩像素视为一个整体连通形状。对该形状进行无重叠分解，分解为 2x2 方块和 1x3/3x1 长条。分解优先级：优先放置 2x2 方块（从形状边界框左上角逐行扫描，能放 2x2 就放），剩余部分分解为 1x3/3x1 长条。
5. 将每个 2x2 方块图元重涂色为青(8)，每个长条图元重涂色为红(2）。
6. 不同原始颜色的形状独立处理，互不影响。

**关键洞察**：分解的对象不是输入中直接可见的——它是压缩操作的产物。同样的散落像素分布如果以不同方式压缩会产生不同形状，而不同形状的图元分解结果（方块/长条比例）也不同。压缩和分解之间存在几何因果关系。

## 新题 7：网格线叠加前的分量计数决定单元格填充模式

**组合逻辑**：[网格线绘制/行列索引奇偶性](已有) + [连通分量/八连通判定](创新：连通分量的数量作为参数编码填充模式，而非用于擦除) + [填充/角落与内部分色/表格行列位](创新：填充模式由分量计数参数化)

**来源原语**：网格线绘制/方阵/行列索引奇偶性(332efdb3), 连通分量/八连通判定/孤立像素(42a50994), 填充/分隔线网格/网格单元格/表格行列位/角落与内部分色(e9c9d9a1)

**依赖链**：输入中前景像素的 8-连通分量计数 → 计数值的奇偶性决定后续填充模式 → 绘制网格线（覆盖前景像素） → 在网格线形成的单元格中按位置和模式填色

先统计输入中散落前景像素的连通分量数（这些像素会被网格线覆盖），然后绘制网格线，最后根据分量数的奇偶性选择不同的单元格填充配色方案。

**输入结构**：正方形网格，边长为奇数（9、11 或 13），全黑(0)背景上散落着若干绿(3)像素。绿像素位于任意位置（可在偶数行/列上，也可在奇数行/列上），形成若干 8-连通分量（每个分量 1~4 像素）。生成约束：绿像素总数 3~10 个；分量数在 2~6 之间；没有绿像素位于网格的四个角像素上。

**规则**：
1. 计算绿(3)像素的 8-连通分量数，记为 C。
2. 将所有绿(3)像素设为黑(0)（擦除，它们只是信息载体）。
3. 绘制周期-2 网格线：将每个行索引或列索引为偶数的像素涂为蓝(1)（与参考题 332efdb3 相同）。奇数行且奇数列的像素保持黑(0)，形成单元格。
4. 将网格线划定的奇数行-奇数列单元格按其在单元格网格中的位置填色：
   - 若 C 为奇数：四角单元格 → 红(2)，所有其他单元格 → 黑(0)不变。
   - 若 C 为偶数：四角单元格 → 黄(4)，严格内部单元格（不在单元格网格最外一圈） → 橙(7)，其余边缘非角单元格 → 黑(0)不变。
5. 蓝(1)网格线像素始终保持蓝色，不受单元格填色影响。

**关键洞察**：输入的绿色像素在输出中完全消失——它们唯一的作用是编码一个数值（分量数），而该数值决定了后续完全不同的填充模式。求解者必须先从绿色像素中提取信息，然后才能理解网格线后面的填色规则。信息提取和信息使用之间被网格线绘制"隔断"，需要跨步推理。

## 新题 8：隐含十字定位决定色段对齐目标

**组合逻辑**：[微型条/隐含十字/缺失中心/四向对齐](已有) + [滑动/对齐/色段/边界对齐](创新：对齐目标不再是固定的最小右边界，而是由隐含十字中心列决定) + [重涂色](已有)

**来源原语**：微型条/隐含十字/四向对齐/缺失中心(9f5f939b), 滑动/对齐/色段/同行排列/边界对齐(984d8a3e), 重涂色(9f5f939b)

**依赖链**：微型条排列检测 → 隐含十字中心定位 → 中心标记为黄 → 中心列作为色段对齐目标列 → 每行色段滑动使右边缘对齐到该列

在三色行结构中检测由微型条构成的隐含十字图案，找到十字中心列，然后将每行的中间色段滑动对齐到该中心列。

**输入结构**：约 12x15 网格，三种颜色构成行结构：品红(6)（左侧填充色）、灰(5)（中间色段）、橙(7)（右侧填充色）。每行恰好有一段连续灰(5)色段，左侧为品红(6)像素，右侧为橙(7)像素。此外，网格中散布着若干绿(3)二像素微型条（水平或垂直排列，每条恰好 2 像素），这些微型条叠加在三色行结构之上（占据的像素覆盖原底色）。恰好有 4 条绿微型条构成一个隐含十字：两条水平条和两条垂直条在某个中心像素的上下左右各偏移 2~3 格处对齐。可能存在 1~2 条不构成十字的干扰绿微型条。生成约束：恰好存在一个隐含十字中心；该中心像素的原底色为灰(5)色段的一部分或品红(6)/橙(7)填充色的一部分；灰(5)色段在不同行的右边缘列不全相同（即色段需要滑动才能对齐）。

**规则**：
1. 识别所有绿(3)二像素微型条。对每个背景色像素（非绿像素），检查上下左右四个方向各偏移 2~3 格处是否都有一条绿微型条与之对齐（水平微型条对齐左右，垂直微型条对齐上下）。若四个方向都满足，该像素为隐含十字中心。
2. 将隐含十字中心像素重涂色为黄(4)。
3. 记录十字中心所在的列为目标列 T。
4. 对每行：保持灰(5)色段的宽度不变，保持橙(7)右侧尾部像素数不变。滑动灰色段使其右边缘对齐到列 T（若色段过宽导致左端超出列 0，则将色段左端置于列 0）。灰色段左侧剩余空间填充品红(6)。
5. 所有绿(3)微型条（包括构成十字的和干扰的）在输出中保持原位不动，覆盖在滑动后的行结构之上。黄(4)中心标记也保持在滑动后的行结构之上。

**关键洞察**：色段对齐的目标不是来自色段自身的统计特征（如最小右边界），而是来自一个完全不同的视觉子系统——微型条构成的隐含十字。求解者必须同时解析两套独立的视觉结构（三色行 + 微型条十字），并理解十字中心为行对齐提供了锚点。
