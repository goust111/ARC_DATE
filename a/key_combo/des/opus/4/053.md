## 新题 1：镜像重建模板驱动碎片补全

**组合逻辑**：[镜像](创新：用于重建不完整模板，而非简单拼接翻转副本) + [透明叠加](创新：叠加镜像与原件以恢复完整形状) → [补全](创新：对重建后的模板进行碎片补全，模板本身在输入中不完整)

**来源原语**：镜像(6fa7a44f)、透明叠加(e3497940)、补全+碎片+模板精灵体+平移对齐+碎片锚定放置位(fd096ab6)

**依赖链**：模板在输入中只展示左半或右半，必须先镜像并与原件叠加才能恢复完整对称模板；只有拿到完整模板后，才能判断各碎片的平移对齐位置并补全——部分碎片的已有像素落在模板的镜像重建半侧，因此跳过镜像步骤将导致这些碎片无法匹配。

将一个只展示了一半的对称模板通过镜像叠加重建完整，再用完整模板补全散布在网格中的彩色碎片。

**输入结构**：约 15x15 的黑(0)背景网格。包含以下元素：
- 一个蓝(1)色的**半模板**：一个 4-连通的单色图形（约 8~15 像素），占据某个左右对称图案的左半或右半部分（含对称轴列）。该半模板的边界框约 5~8 行、3~5 列。
- 2~4 个**彩色碎片**：每个碎片由 2~5 个同色像素组成，颜色互不相同，均非蓝(1)、非黑(0)（例如红(2)、绿(3)、黄(4)、品红(6)）。每个碎片是完整模板在某个平移位置的子集像素。
- 生成约束：半模板严格为某个左右对称图案的一半（含中心轴列）；不同示例中半模板可能展示左半或右半；各碎片的补全后区域互不重叠，且不与蓝色半模板区域重叠；每个碎片至少有一个像素落在完整模板的镜像重建侧（即仅用半模板无法匹配该碎片）。

**规则**：
1. 确定蓝色半模板的对称轴列（半模板边界框中最靠近网格中心的竖直边缘列）。
2. 将半模板以对称轴列为轴做水平镜像，与原半模板透明叠加（非黑优先），得到完整的蓝色对称模板。
3. 对每个彩色碎片，寻找唯一的平移偏移量，使碎片的所有像素与完整模板在该偏移下的像素子集完全对齐。
4. 将完整模板在该偏移位置的所有空缺像素（碎片未覆盖的模板像素）用碎片的颜色填入。
5. 输出时，蓝色半模板被替换为完整的蓝色对称模板；各碎片在其匹配位置被补全；背景保持黑(0)。
6. 处理顺序：按碎片边界框左上角从左到右、从上到下依次处理。若两个补全区域理论上重叠（生成时已排除），后处理的覆盖先处理的。

**关键洞察**：输入中展示的蓝色模板是故意不完整的——它只是完整对称图案的一半。不进行镜像重建就无法匹配碎片，因为部分碎片的锚定像素恰好落在模板被省略的那一半上。

## 新题 2：散点计数决定十字臂长的中点放置

**组合逻辑**：[计数](创新：计数对象不是被放大的像素，而是独立的散点，其总数决定另一操作的几何参数) + [放置+中点定位](创新：放置的十字图案尺寸由全局计数动态决定，而非固定 3x3)

**来源原语**：计数+数量决定倍率+前景数为放大系数(ac0a08a4)、放置+十字图案+定位像素对+中点定位+中点居中放置(e9614598)

**依赖链**：红色散点的总数 N 决定十字臂长，蓝色像素对的中点决定放置位置——两组信息来源独立但在输出中汇合：缺少计数则十字尺寸不确定，缺少中点则放置位置不确定。两者缺一不可。

统计散布红点的数量作为十字臂长，在每对蓝色定位像素的中点放置该尺寸的绿色十字。

**输入结构**：约 14x14 的黑(0)背景网格。包含以下元素：
- 2~3 对蓝(1)**定位像素对**：每对中的两个像素在同一行或同一列上对齐，间距至少 6 格，中点落在整数坐标上。不同对的颜色均为蓝(1)，通过空间隔离区分配对（每对内部距离远小于对间距离；或生成时保证同行/同列的蓝像素恰好两个，形成唯一配对）。
- 2~5 个红(2)**散点像素**：随机分布在网格中，不位于任何定位对的中点附近（与任意中点的切比雪夫距离 > 预期最大臂长）。
- 生成约束：红色散点数量 N 满足 1 <= N <= 4；以 N 为臂长在每个中点放置的十字（中心 + 上下左右各 N 格）完全在网格内；各十字的占用区域互不重叠。

**规则**：
1. 统计网格中所有红(2)像素的总数，记为 N。
2. 对每对蓝(1)像素，计算其中点坐标 M = ((r1+r2)/2, (c1+c2)/2)。
3. 构造十字图案：中心格加上四个方向各 N 格的臂（总宽高 2N+1，呈加号形状）。
4. 将该十字以绿(3)色绘制在以 M 为中心的位置上。
5. 若两个十字重叠（生成时已排除），定位对内部距离较短的十字绘制在上层。
6. 蓝(1)像素和红(2)像素保留不变（最后绘制，覆盖任何十字像素）。

**关键洞察**：红色散点看似随机噪声，实际上它们的总数是控制所有十字尺寸的全局参数。增减一个红点会同时改变所有十字的大小。

## 新题 3：条纹识别驱动的像素归位

**组合逻辑**：[去噪/条纹识别](创新：条纹的主色分析不用于直接修复画面，而是为每个离位像素提供目标行地址) ←互相约束→ [滑动](创新：滑动目标不是统一的底部基线，而是由颜色匹配确定的特定行)

**来源原语**：去噪+条纹行列+主色占优+主色覆盖全行列(e26a3af2)、滑动+重力沉降+同列对齐(3618c87e)、噪声像素(e26a3af2)

**依赖链**：条纹识别为每个离位像素指定归位目标行（"去哪一行"取决于哪一行的条纹色与像素色匹配）；但若不先识别条纹就无法判断哪些像素是"离位"的、哪些是"噪声"——两步推理互相约束而非简单串联。

识别水平条纹的主色分布，将颜色与其他行条纹匹配的离位像素沿列滑动到对应的"归属行"，同时擦除颜色不匹配任何条纹的噪声像素。

**输入结构**：约 10x12 的网格，无统一背景色。包含以下元素：
- **水平条纹底板**：每行有一个明确的主色（占该行 70% 以上像素）。使用 3~5 种颜色，例如红(2)、绿(3)、黄(4)、蓝(1)等。条纹颜色可以重复（如第 1 行和第 5 行都是红(2)）。
- **离位像素**：每行有 0~2 个像素的颜色不是该行的主色，但该颜色等于网格中某另一行的主色。这些像素保持列坐标不变。
- **噪声像素**：每行有 0~1 个像素的颜色不等于网格中任何行的主色（例如使用条纹中未出现的橙(7)或栗(9)）。
- 生成约束：每行的主色即使去掉离位像素和噪声后仍然是该行最高频色（即离位像素不会改变主色判断）；每个离位像素的目标行唯一（只有一个行的主色与之匹配）或取最近行。

**规则**：
1. 确定每行的条纹主色：统计每行中各颜色的像素数，出现次数最多的颜色即为该行主色。
2. 遍历每行中的非主色像素：
   - 若该像素的颜色等于网格中某（些）行的主色，则该像素为**离位像素**。将其沿所在列滑动到距当前行最近的、主色与该像素颜色相同的行，放入该行的同一列位置。若存在上下等距的两个候选行，移向下方行。
   - 若该像素的颜色不等于任何行的主色，则该像素为**噪声像素**。将其擦除，替换为当前行的主色。
3. 移动后，若目标位置已有非主色像素（两个离位像素抢同一位置，生成时已排除此情况），保留行程更短的像素，另一个回退到原位并替换为原行主色。
4. 输出：每行恢复为纯主色行，离位像素出现在其归属行的对应列，噪声被清除。

**关键洞察**：条纹主色分析并非用于"去噪还原画面"（与 e26a3af2 不同），而是生成一张"行-色对应表"，充当滑动操作的目标地址。像素的去向完全由它自身颜色与全局条纹分布的匹配关系决定。

## 新题 4：L 朝向决定外角位与图例排位色的角落扩展

**组合逻辑**：[朝向对应角](创新：朝向不仅决定扩展目标角，还通过角的阅读序映射到图例位置以确定颜色) → [重涂色+排位对应+图例位映射色](创新：排位键不是空间布局位置，而是L朝向隐含的角序) → [扩展至外角](保留)

**来源原语**：角落标记+朝向对应角+扩展至外角(b745798f)、重涂色+颜色图例+排位对应+图例位映射色(fafd9572)、擦除(22806e14)

**依赖链**：L 标记的朝向同时编码两条信息——扩展去哪个外角、以及在图例中取哪个颜色。删掉图例则不知道用什么色扩展；删掉朝向分析则既不知道扩展到哪个角，也不知道取图例第几位。

根据 L 形标记的朝向确定其目标外角，再通过目标角的阅读序排位从颜色图例取色，以取得的颜色在对应外角绘制等长 L 形臂。

**输入结构**：约 13x13 的奇数边长正方形网格，橙(7)背景。包含以下元素：
- 2~4 个**L 形标记**：每个由 3 个同色像素组成，占据 2x2 边界框中缺失一个角的位置（即 4-连通 L 形）。每个标记颜色互不相同，均非橙(7)非黑(0)。标记分散在网格各处（位置不影响规则）。
- 一个**颜色图例**：位于网格中心附近，由 K 个像素组成（K = 标记数量）。图例像素排列为紧凑的一行或一列，颜色互不相同，均不同于任何标记颜色和背景色。
- 生成约束：每个标记的 L 朝向指向不同的外角（若有 4 个标记则四角各一；2~3 个标记则占据其中 2~3 个角，未占角无标记）。图例像素数恰好等于标记数。

**规则**：
1. 对每个 L 形标记，分析其在 2x2 边界框中缺失角的位置，确定朝向：缺失左上角 → 指向左上外角；缺失右上角 → 指向右上外角；缺失左下角 → 指向左下外角；缺失右下角 → 指向右下外角。
2. 将四个外角按阅读序编号：左上=1、右上=2、左下=3、右下=4。每个标记的目标角对应一个编号 R。
3. 将图例像素按阅读序（若为横排则从左到右；若为竖排则从上到下）编号为 C1, C2, ..., CK。
4. 标记获得颜色 C_R（取图例第 R 位的颜色，其中 R 为步骤 2 确定的角编号；若仅有部分角被使用，则仍按角的阅读序在图例中的位置对应，即出现的角按阅读序排列后第 1 个对应 C1、第 2 个对应 C2、以此类推）。
5. 在目标外角绘制 L 形臂：两条臂从外角像素出发，沿网格边缘向内延伸，臂长为 (gridSize-1)/2 个像素（含角点），颜色为步骤 4 确定的颜色。
6. 擦除所有原始标记和图例像素（替换为橙(7)背景）。

**关键洞察**：标记的空间位置完全无关紧要；唯一有意义的是它在 2x2 框中的缺角方向。这个朝向同时决定了两件事：画到哪个外角，以及从图例取第几个颜色。标记自身的原始颜色被丢弃。

## 新题 5：定位对中点处读取字形解码颜色填充远端区域

**组合逻辑**：[放置→中点定位](创新：中点不是"放"东西的位置，而是"读"东西的位置) → [字形映射颜色](创新：字形不与自身掩码配对，而是与远端的边框区域配对) → [填充+缺失位补色](创新：填充色来自远端字形解码而非固定图例)

**来源原语**：定位像素对+中点定位+中点居中放置(e9614598)、编码字形+字形映射颜色(ed74f2f2)、边框区域+缺失位补色+填充(a834deea)、配对(ed74f2f2)

**依赖链**：蓝色定位对→中点坐标→该处字形→解码出颜色→最近邻配对的边框区域→用解码色填充空缺。链条中任一环断裂都无法确定填充色或填充目标。同时，配对关系（哪个字形对应哪个区域）需在多个示例中观察近邻规律才能确认。

通过蓝色像素对的中点找到字形，解码字形获得颜色，再将该颜色填入与之最近的边框区域的空缺内部位。

**输入结构**：约 15x15 的黑(0)背景网格。包含以下元素：
- 2~3 对蓝(1)**定位像素对**：每对在同一行或同一列对齐，间距 4~8 格，中点落在整数坐标。各对之间间距较大。
- 在每个定位对的中点处，一个 3x3 的**编码字形**：由灰(5)和黑(0)像素组成，灰像素恰好 5 个，形成可辨识的几何图案（如加号形、T 形、阶梯形等，不同示例中使用不同图案集）。字形叠绘在中点的 3x3 区域上。
- 2~3 个**边框区域**：每个为 5x5 的黑(0)边框方块，内部 3x3。部分内部位已填入一种非黑非灰的颜色（该颜色即为正确的解码色，作为验证线索），其余内部位为黑(0)。
- 生成约束：每个字形与恰好一个边框区域配对（按中点到区域中心的欧氏距离最近，且无平局）。字形图案到颜色的映射在同一题的所有示例中保持一致（即同一图案总映射同一颜色）。边框区域中已有的彩色像素颜色与配对字形的解码色一致。字形区域与边框区域、蓝色像素均不重叠。

**规则**：
1. 对每对蓝(1)像素，计算中点 M。
2. 读取以 M 为中心的 3x3 区域中的灰(5)像素图案，识别为一个字形。
3. 用字形码本将字形解码为一种颜色（码本需从多个示例中归纳：观察字形图案与边框区域已有彩色像素的对应关系）。
4. 将每个字形与距其中点欧氏距离最近的边框区域配对。
5. 在配对的边框区域中，将所有仍为黑(0)的 3x3 内部位填入解码得到的颜色。已有彩色像素和黑(0)边框保持不变。
6. 蓝色定位像素、字形区域均保留不变。

**关键洞察**：蓝色像素对的中点不是"放置"目标而是"读取"坐标——在该处读取字形，解码出颜色后施加于远端的边框区域。字形码本无法从单个示例确定（同一示例中可能只出现 2 种字形），必须跨示例比较字形图案与填充色的对应关系。

## 新题 6：双射线碰撞点处放置十字

**组合逻辑**：[射线延伸+反弹](保留基本机制) ∥ [射线延伸+反弹](两条独立射线并行) → [放置+十字图案](创新：放置位置不由定位像素对决定，而由两条射线路径的交汇点涌现)

**来源原语**：射线延伸+反弹+箭头精灵体+墙壁像素+颜色继承+碰撞停止(142ca369)、放置+十字图案(e9614598)

**依赖链**：两条射线的轨迹各自独立计算（取决于箭头朝向和墙壁反弹），但十字放置位置是两条轨迹的交点——一个涌现结果。删除任一射线都无法确定交点；删除十字放置则两条射线只是各自画线，无组合产物。

两个箭头各发射一条对角线射线，射线遇墙反弹并继承墙色，两条射线路径首次交汇处放置绿色十字。

**输入结构**：约 15x15 的黑(0)背景网格。包含以下元素：
- 两个**箭头精灵体**：每个由 3 个同色像素组成的 L 形（占据 2x2 边界框缺一角），分别位于网格的不同边缘区域。两个箭头颜色不同（例如红(2)和蓝(1)）。
- 0~3 个**墙壁像素**：散布在网格内部，颜色各异（非红非蓝非黑非绿，例如黄(4)、灰(5)、品红(6)）。
- 生成约束：两箭头的射线在经过必要的反弹后必定在网格内相交；首个交汇点距离所有网格边缘至少 1 格（十字的 3x3 区域完全在网格内）。两箭头朝向不同。

**规则**：
1. 每个箭头从其 2x2 边界框的缺角方向发射一条对角线射线。
2. 射线前进时，将经过的黑(0)背景像素涂为射线当前颜色（初始为箭头自身颜色）。
3. 反弹规则（同 142ca369）：
   - 射线正前方遇到墙壁像素（下一步的行和列都被墙占据）：行方向和列方向同时反转（180 度折返）。
   - 射线侧面触及墙壁像素（下一步仅行或仅列被墙占据）：反转被占据的那个轴方向。
   - 反弹时射线继承墙壁像素的颜色，并将墙壁像素本身重涂为射线新颜色。
   - 遇到网格边界时，以同样的轴反转规则反弹，但不改变射线颜色。
4. 两条射线各自独立推进。当某条射线到达一个已被另一条射线涂色的像素时，该像素即为**碰撞点**。
5. 在碰撞点为中心放置一个 3x3 的绿(3)十字图案（加号形：中心 + 上下左右各 1 格），覆盖该区域已有颜色。
6. 碰撞发生后两条射线均停止延伸。若两条射线在同一步同时到达对方路径上的不同点，取行号较小的点（行号相同则取列号较小的）作为碰撞点。

**关键洞察**：十字的放置位置不由输入中的任何静态标记决定，而是两条射线轨迹交汇的涌现结果。墙壁像素通过改变反弹方向间接控制交汇点——移动一个墙壁像素可能完全改变十字的最终位置。

## 新题 7：折叠比较驱动差异点处的双色互换

**组合逻辑**：[折叠](创新：折叠不用于合并互补内容，而是作为比较工具产生"差异掩码") → [图案替换](创新：替换不是全局交换两种模板，而是仅在差异点处交换两种前景色) + [擦除](保留)

**来源原语**：折叠+分隔线+对称互补(e3497940)、图案替换+按颜色区分模板+同步替换(3391f8c0)、擦除(3391f8c0)

**依赖链**：折叠产生的差异掩码定义了"哪些位置执行色彩互换"——不折叠就不知道哪些是差异点（仅看一侧无法判断）；不做互换则差异点处的处理方式不确定（是取左侧还是右侧？答案是：取左侧但交换颜色）。

将网格沿分隔线折叠比较左右两半，在两半前景色不一致的位置对左半侧执行双色互换，输出仅保留修改后的左半侧。

**输入结构**：约 10x(2W+1) 的网格（W 为 5~7），共 11~15 列。包含以下元素：
- 一条竖直**分隔线**：灰(5)色，占据中间一列，贯穿全部行。
- 分隔线左右各 W 列的区域，均以黑(0)为背景，包含恰好两种前景色的像素（例如红(2)和蓝(1)）。
- 左右两半大体对称，但在若干位置（2~5 个像素）存在故意的**差异**：某些左半为红(2)的位置在右半为蓝(1)，或反之。
- 左右两半中前景像素与背景的分布一致（即两侧的前景像素占位在镜像对应位置上相同，仅颜色可能不同）。
- 生成约束：差异点仅出现在两侧都为前景的位置（不存在一侧前景另一侧背景的差异）。

**规则**：
1. 将右半区域水平镜像（左右翻转），与左半区域逐像素比较。
2. 一致的前景像素：在输出中保留左半的颜色。
3. 一致的背景像素：在输出中保留黑(0)。
4. **差异前景像素**（两侧都是前景但颜色不同）：在输出中将左半该位置的颜色互换——红(2)→蓝(1)，蓝(1)→红(2)。
5. 前景/背景不一致的像素（一侧前景另一侧背景）：保留前景色（生成时已排除此情况，但作为安全规则列出）。
6. 输出为左半区域的尺寸（W 列 x 全部行），不含分隔线和右半。

**关键洞察**：折叠的作用不是"合并两个互补半体"而是"对比两个近似半体"。差异点处不是简单地用某一侧覆盖另一侧，而是执行颜色互换——这意味着差异点的输出色既不等于左半原色，也不等于右半原色。需要多个示例才能排除"取右侧"或"取左侧"这两种更简单的假设。

## 新题 8：重力堆叠后按深度从图例取色

**组合逻辑**：[滑动+重力沉降](保留基本机制) → [计数](创新：计数的不是全局前景像素，而是每列局部堆叠高度) → [重涂色+排位对应+图例位映射色](创新：排位键不是对象的空间布局位置，而是堆叠内的深度层级)

**来源原语**：滑动+重力沉降+基线行+同列对齐(3618c87e)、计数(ac0a08a4)、重涂色+颜色图例+排位对应+图例位映射色(fafd9572)、深度排序(85c4e7cd)

**依赖链**：重力决定每个像素的最终位置和每列的堆叠高度→堆叠内的深度层级决定取图例第几位→图例颜色决定最终涂色。一个像素的输出颜色不仅取决于它自己，还取决于同列有多少其他像素（同列其他像素的增减改变该像素的深度层级）。

像素下落堆叠后，每个像素根据其在本列堆叠中从底部数起的深度层级，从顶部图例条中循环取色。

**输入结构**：约 10x10 的网格。包含以下元素：
- **基线行**：底部一行全为灰(5)。
- **前景像素**：各种非灰(5)、非黑(0)颜色的散布像素（如红(2)、蓝(1)、绿(3)、黄(4)等），分布在基线行上方的各行各列，每列 1~6 个。
- **图例条**：顶部一行的最左侧 L 个连续像素（L = 3~4），颜色互不相同且不含灰(5)和黑(0)。图例条右侧至行尾为黑(0)。
- 其余空位为黑(0)背景。
- 生成约束：图例条在顶行，不参与重力下落。基线行不参与重力下落。前景像素的原始颜色在规则中不起作用（仅位置有意义）。

**规则**：
1. 图例条和基线行保持不动。所有其他非黑(0)像素（前景像素）在各自列中下落，在基线行上方堆叠（最先到达的在最底部）。同列像素的下落顺序：原始行号较大的（更靠近基线的）先落位。
2. 堆叠完成后，为每列的堆叠分配深度层级：紧贴基线的像素深度为 1，其上一格深度为 2，以此类推。
3. 读取图例条从左到右的颜色序列 C1, C2, ..., CL。
4. 将每个堆叠像素重涂色：深度 d 的像素取颜色 C_{((d-1) mod L) + 1}（即深度 1→C1，深度 2→C2，...，深度 L→CL，深度 L+1→C1，循环）。
5. 输出中保留图例条、基线行、重涂后的堆叠像素。未被占据的位置为黑(0)。

**关键洞察**：像素的原始颜色在输出中完全被丢弃；输出颜色仅由两个因素决定：该像素在本列堆叠中的深度层级、以及图例条的颜色序列。同一列增加一个像素会改变该列所有现有像素的深度（整体上移一层），从而改变它们的颜色。

## 新题 9：楔形对角传播中墙壁注入替换色

**组合逻辑**：[填充+沿对角线传播+收缩楔形+逐行交换双色](保留楔形传播机制) ×交织× [反弹/墙壁交互+颜色继承](创新：墙壁不引起方向反弹而是沿对角线注入替换色，将双色交替中的一色永久替换)

**来源原语**：填充+顶行色带+收缩楔形+沿对角线传播+逐行交换双色(b5bb5719)、墙壁像素+颜色继承+碰撞停止(142ca369)、反弹(142ca369)

**依赖链**：楔形传播决定了哪些位置需要填色以及基础的双色交替图案；墙壁像素在传播路径中注入第三种颜色，改变其所在对角线上所有后续格子的颜色——传播机制与颜色注入在同一空间中逐行交织，无法分步执行。

顶行双色色带向下传播为收缩楔形，遇到墙壁像素时该对角线上的一种交替色被墙壁色永久替换。

**输入结构**：约 13x13 的橙(7)背景网格。包含以下元素：
- **顶行色带**：顶行的一个连续奇数宽度区间（5~9 像素），由红(2)和灰(5)严格交替填充（第一个像素为红(2)或灰(5)，依次交替）。区间外为橙(7)背景。
- 1~2 个**墙壁像素**：颜色各异（例如蓝(1)、绿(3)），位于色带区间下方、楔形未来覆盖区域内（即第 rw 行的列坐标在 span_left+rw 到 span_right-rw 之间）。
- 生成约束：墙壁像素互不在同一对角线上（每条从顶行出发的对角线最多一个墙壁）。楔形在到达网格底部之前因收缩而自然结束（即 span_width/2 < grid_height）。

**规则**：
1. 楔形传播基础规则（同 b5bb5719）：从顶行色带出发，第 r 行（r=0 为顶行）填充列范围 [span_left+r, span_right-r]。每个填充格 (r, c) 的颜色取自顶行第 c-r 列的颜色，再做 r 次红(2)↔灰(5)翻转（等效：r 为偶数保持原色，r 为奇数翻转）。
2. 墙壁交互规则：当楔形传播到达墙壁像素 (rw, cw) 时：
   - 墙壁像素本身保留不变（不被楔形覆盖）。
   - 确定该墙壁位置在无墙情况下本应获得的颜色 X（红(2)或灰(5)之一）。
   - 在同一条对角线上（从 (rw, cw) 沿对角线方向 (r+1, c+1) 或 (r+1, c-1)，取决于该格位于楔形中心的哪一侧：若 cw <= 楔形中心列则沿 (r+1, c+1)，若 cw > 中心列则沿 (r+1, c-1)），所有后续楔形格中本应为颜色 X 的格子改为墙壁像素的颜色。另一种交替色保持不变。
3. 若一个格子同时受多个墙壁影响（生成时已排除），后遇到的墙壁覆盖先前的替换色。
4. 楔形区域外的格子保持橙(7)背景。

**关键洞察**：楔形的双色交替图案是全局规律，但墙壁像素在局部注入第三种颜色，沿一条对角线"污染"后续所有格子。这种污染不是简单地覆盖一个点，而是替换交替序列中的一个颜色通道——视觉上表现为楔形中出现一条斜向的异色条带，条带的起点和颜色由墙壁决定。
