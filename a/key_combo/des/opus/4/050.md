## 新题 1：走廊印章旋转链

**组合逻辑**：[走廊路径+碰撞转向](已有) → [印章覆盖](已有，创新：印章位置由转弯点确定) → [旋转](已有，创新：累积旋转角由转弯历史编码)

**来源原语**：走廊路径/corridor_path、碰撞转向/collision_turn、起点条/start_bar、障碍像素/blocker_pixel、遇障碍直角转/right_turn_at_block（来自 6bcdb01e）；印章覆盖/stamp_overlay、精灵体/sprite（来自 e5062a87）；旋转/rotation（来自 b7cb93ac）

**依赖链**：走廊行走确定转弯点位置 → 每个转弯点的左转/右转决定累积旋转角增量 → 累积角度决定模板精灵在该转弯点的印章朝向。移除路径追踪则无法确定印章位置；移除累积旋转则所有印章朝向相同，丢失转弯历史编码。

沿走廊行走并在每个转弯点印章一个模板精灵，精灵的朝向由截至该点的累积转弯历史决定。

**输入结构**：
- 约 18x18 网格，黑(0)背景
- 灰(5)障碍像素定义一条单像素宽的走廊，走廊有 3-5 个直角拐弯
- 一根绿(3)起点条（2 像素，4-连通）触碰网格某一边缘：其中一个像素在边缘上，另一个在边缘内侧相邻位置
- 一个红(2)模板精灵位于网格角落，与走廊完全隔离。模板是 4-连通、3-5 像素的不规则小图形，不具有旋转对称性（即 0/90/180/270 度四个朝向各不相同）
- 生成约束：每个转弯点的 5x5 邻域内有足够的黑(0)空间容纳旋转后的模板而不与非黑像素重叠；走廊路径不会重复经过同一区域

**规则**：
1. 从起点条的边缘像素出发，初始前进方向为朝网格内侧（远离边缘的方向）
2. 沿前进方向逐格移动，将经过的每个黑(0)格涂为绿(3)
3. 维护一个"累积旋转角"变量，初始值为 0 度
4. 当前进方向上的下一格为灰(5)障碍时，到达转弯点：
   - 确定可转方向：检查当前前进方向的左侧（逆时针 90 度）和右侧（顺时针 90 度）相邻格。生成约束保证恰好一个方向为非障碍格
   - 若向右转（顺时针）：累积旋转角 += 90 度
   - 若向左转（逆时针）：累积旋转角 -= 90 度（等价地 += 270 度，对 360 度取模）
   - 将模板精灵按累积旋转角旋转（以模板包围框中心为旋转中心，0/90/180/270 度）
   - 以转弯点为中心，将旋转后的模板印章到网格上：仅覆盖黑(0)格，涂为红(2)；非黑格保持不变
   - 将前进方向更新为转弯后的新方向
5. 当前进方向上的下一格超出网格边界时停止
6. 模板精灵原始位置（角落处）的像素在输出中擦除为黑(0)

**关键洞察**：累积旋转使得每个印章的朝向编码了从起点到该转弯点的完整转弯序列。最后一个印章的朝向无法仅从局部信息推断——必须从起点开始追踪所有历史转弯才能确定。求解者需通过对比多个示例来区分"每次独立旋转"与"累积旋转"这两种可能规则。

## 新题 2：孔洞射线与边框调色定向

**组合逻辑**：[封闭孔洞检测](已有) + [单色边框中心提取](已有，创新：提取的中心色不再直接输出，而是为射线赋色) + [射线延伸](已有，创新：射线方向由边框相对位置编码) → 三源汇聚

**来源原语**：封闭孔洞/enclosed_hole、包含关系/containment、描边逻辑中的孔洞检测（来自 aa4ec2a5）；单色边框/monochrome_frame、中心像素/center_pixel、边框包围中心/frame_encloses_center、中心色为输出/center_color_output（来自 d9fac9be）；射线延伸/ray_extend、孔洞触发射线/hole_triggers_ray（来自 6e453dd6、981add89）；标记相对方位/marker_relative_position（来自 94414823）

**依赖链**：孔洞检测定义射线发射行 → 边框中心色定义射线颜色 → 边框相对位置定义射线方向。三个信息源各自不可替代：缺孔洞则无发射源，缺边框中心色则无法确定颜色，缺边框方位则无法确定方向。

检测前景对象中的封闭孔洞，以关联的 3x3 边框的中心色为射线颜色、边框方位为射线方向，从孔洞行/列向外发射彩色射线。

**输入结构**：
- 约 15x18 网格，黑(0)背景
- 2-3 个前景对象，各为单色（如蓝(1)、黄(4)等）的 4-连通区域，每个约 10-20 像素，形状不规则
- 部分对象（至少 1 个）包含 1-2 个封闭孔洞：孔洞是被该对象像素完全 4-连通包围的背景(0)区域
- 2-3 个散落的 3x3 单色边框：每个边框的 8 个边界像素为同一颜色（如红(2)、绿(3)等），中心像素为另一颜色（如橙(7)、品红(6)等）。边框颜色与前景对象颜色均不同
- 每个含孔洞的对象恰好关联一个边框：关联规则为边框中心与对象包围框中心的曼哈顿距离最近的那个边框。生成约束：距离无平局
- 不含孔洞的对象不关联任何边框
- 生成约束：每个边框至多关联一个对象；边框不与前景对象重叠

**规则**：
1. 识别所有前景对象（非背景、非边框的 4-连通区域）
2. 对每个对象执行孔洞检测：找出被该对象完全包围的 4-连通背景区域
3. 无孔洞的对象保持不变
4. 对含孔洞的对象：
   a. 找到关联边框（中心曼哈顿距离最近者）
   b. 射线颜色 = 该边框的中心像素颜色
   c. 确定射线方向——计算边框中心相对于对象包围框中心的偏移量，取绝对值较大的轴向（生成约束：两轴偏移量不相等）：
      - 边框在对象右侧（水平偏移占主导且为正） → 射线方向向右
      - 边框在对象左侧（水平偏移占主导且为负） → 射线方向向左
      - 边框在对象上方（垂直偏移占主导且为负） → 射线方向向上
      - 边框在对象下方（垂直偏移占主导且为正） → 射线方向向下
   d. 对于水平方向的射线：对每个与孔洞像素同行的行号，从对象在该行的边缘像素出发，沿射线方向逐格延伸，将黑(0)格涂为射线颜色，直到遇到非背景像素或网格边界为止（不含终点）
   e. 对于垂直方向的射线：对每个与孔洞像素同列的列号，从对象在该列的边缘像素出发，沿射线方向逐格延伸，规则同上
5. 边框和无孔洞的对象保持不变

**关键洞察**：3x3 边框同时编码两个独立信息——中心像素颜色编码射线的颜色，边框相对于对象的空间方位编码射线的发射方向。求解者必须分别识别这两条编码才能正确推断输出。仅凭单个示例无法区分"方向由边框方位决定"和"方向固定向右"等替代假说。

## 新题 3：对称分组与标记裁决描边

**组合逻辑**：[对称检测](已有，创新：用于将对象分为"参考组"与"候选组") + [内部标记计数](已有，创新：仅在候选组内执行计数) + [擦除](已有) + [描边](已有，创新：描边颜色由参考组对象通过空间就近关系跨组传递)

**来源原语**：对称/symmetry、对称图案选取/symmetric_selected、颜色掩码/color_mask、包围框/bounding_box（来自 d56f2372）；计数/counting、擦除/erase、稀疏标记/sparse_marker、内部标记计数/interior_marker_count、最少标记者选中/least_marker_selected（来自 54db823b）；描边/draw_outline、前景对象/foreground_object（来自 aa4ec2a5）

**依赖链**：对称性检测将对象分为参考组和候选组 → 候选组内按标记计数选出淘汰者执行擦除 → 幸存候选对象按距离最近的参考组对象获取描边颜色 → 执行描边。移除对称检测则无法分组；移除计数则无法在候选组内选择淘汰者；移除空间就近关系则无法确定描边颜色。

按垂直对称性将对象分为参考组和候选组；候选组中标记最少的被擦除，其余候选对象以最近参考对象的颜色描边。

**输入结构**：
- 约 16x16 网格，黑(0)背景
- 4-6 个前景对象，各为不同颜色的 4-连通区域（如蓝(1)、红(2)、绿(3)、黄(4)等），每个 8-15 像素，形状不规则
- 每个对象内部嵌有 1-4 个灰(5)标记像素：这些灰像素位于对象包围框内，被对象的同色像素包围（与对象共享边界但颜色为灰(5)）
- 部分对象具有垂直镜像对称性：将对象的包围框裁切（对称检测时将灰(5)标记视为对象自身颜色），若该裁切等于其左右翻转则为对称
- 生成约束：至少 1 个对称对象，至少 2 个非对称对象；非对称对象中各自的灰标记像素数量互不相同

**规则**：
1. 对每个前景对象，裁切其包围框。在裁切中将灰(5)像素视为对象颜色，检查是否具有垂直镜像对称性（裁切 == 裁切的左右翻转）
2. 对称对象归入"参考组"，不修改
3. 非对称对象归入"候选组"。统计每个候选对象内部的灰(5)标记像素数量
4. 候选组中灰标记数量最少的唯一对象被擦除：将其所有像素（含内部灰标记）设为背景(0)
5. 对每个幸存的候选对象：
   a. 找到距其包围框中心曼哈顿距离最近的参考组对象（以包围框中心间距计算；生成约束：距离无平局）
   b. 以该参考对象的颜色在幸存候选对象周围绘制 1 像素宽的 8-邻域描边
   c. 描边处理顺序：按候选对象包围框左上角的行优先、列次优先排序；后处理的描边像素覆盖先处理的
6. 参考组对象及其灰标记保持不变

**关键洞察**：对称性不是输出选取标准（不像 d56f2372 中直接裁出对称者），而是角色分配标准——对称对象变成颜色供应者，非对称对象变成被操作者。跨组的空间就近匹配决定了描边颜色的来源，使得对称组和候选组通过空间关系产生耦合，而非简单的分离处理。

## 新题 4：底标传播穿框种子变色

**组合逻辑**：[逐列传播](已有) + [空心矩形框+内含种子](创新：框作为传播色的"变色站"而非容器) + [重涂色](已有，创新：由种子-传播交互动态触发)

**来源原语**：传播/propagate、逐列填充/column_fill、底行标记像素/bottom_row_marker_pixel、纵向色带/vertical_color_band、底行标记选定列/bottom_marker_selects_column（来自 17b80ad2）；空心矩形框/hollow_rect_frame、标记像素/marker_pixel（来自 94414823）；重涂色/recolor、控制像素/control_pixel（来自 ddf7fa4f）；包含关系/containment（来自 776ffc46）

**依赖链**：底行标记启动逐列上行传播 → 传播遇到空心框时检测框内种子 → 有种子的框充当"变色站"改变后续传播色，无种子的框阻断传播。移除传播则无色带；移除框则退化为单色传播（等价于已有题 17b80ad2）；移除种子区分则无法判断框是变色还是阻断。

从底行标记向上传播颜色，每遇到含种子的空心框就切换传播色为种子色，遇空框则阻断。

**输入结构**：
- 约 18x15 网格，黑(0)背景
- 底行（最后一行）有 2-3 个非背景标记像素，颜色各异（如红(2)在第 3 列，绿(3)在第 9 列，蓝(1)在第 13 列），标示需要传播的列
- 3-5 个灰(5)单像素厚空心矩形框，分布在网格不同高度，每个框约 4-6 格宽、3-4 格高
- 部分框（至少 2 个）内部正中位置有一个"种子像素"——单个非背景、非灰的彩色像素（如橙(7)、品红(6)、黄(4)等）
- 部分框（至少 1 个）内部全为黑(0)（空框）
- 各框的列跨度经过不同的标记列；一个标记列可能经过 0-3 个框
- 生成约束：每个标记列至少经过一个框；框之间不重叠；种子像素颜色与底行标记颜色均不同

**规则**：
1. 对每个底行标记像素（位于列 c），从该列倒数第二行起向上逐行扫描至第 0 行
2. 维护变量"当前色"，初始值为该标记的颜色
3. 对扫描到的每个格 (r, c)：
   - 若为背景(0)：涂为"当前色"
   - 若为灰(5)（框边界的一部分）：保持灰色，继续向上扫描
   - 若为种子像素（非背景、非灰、非已涂色）：保持种子像素不变；将"当前色"更新为种子的颜色；继续向上扫描
   - 若为其他非背景色（如之前涂过的色带像素、其他对象）：保持不变，继续向上扫描
4. 若扫描进入一个空框（内部全为黑(0)且该框列范围包含当前列）：将框内部在当前列的背景格涂为"当前色"，然后传播终止——不再继续向上穿过该框的上边界
5. 未被底行标记指定的列不做任何修改

**关键洞察**：空心矩形框在此扮演双重角色——含种子的框是"变色中继站"，让色带在穿越后变色；空框则是"阻断墙"，终止传播。求解者必须同时理解传播机制和框内容的二元分类才能预测输出。一列经过多个含种子框时会产生多段不同颜色的色带，色带的颜色序列恰好是该列上方各种子颜色从下到上的读取序列。

## 新题 5：分隔符拓扑编码几何变换

**组合逻辑**：[网格分块](已有) + [分隔列/分隔线的拓扑结构](创新：拓扑结构不仅分割空间，还隐式编码变换指令) + [镜像/旋转](已有，创新：由分隔符拓扑选择具体变换类型)

**来源原语**：分隔列/separator_column（来自 6e453dd6，泛化为分隔线）；网格分块/grid_partitioning、裁剪/crop（来自 5bd6f4ac）；镜像/mirror（来自 59341089）；旋转/rotation（来自 b7cb93ac）；连通分量/connected_component（来自 6e453dd6）

**依赖链**：分隔线将网格分为若干块 → 统计每块四周的分隔线边数 → 水平分隔边与垂直分隔边的数量对比决定对该块施加何种几何变换 → 变换块内容后移除分隔线重新拼合。移除分隔线分析则不知施加何种变换；移除变换则输出仅是去掉分隔线的原图。

分隔线将网格分为若干块，每块周围的水平/垂直分隔边数量对比隐式编码了该块应执行的镜像或旋转操作。

**输入结构**：
- 约 15x15 网格，白(0)背景（此题中 0 为背景）
- 灰(5)分隔线（1 像素宽）将网格分为若干矩形块。分隔线可以是水平的或垂直的，形成不规则分区（不必是均匀的行列网格，但每个分区是完整矩形）
- 每个分区块内有一个小的彩色图案（2-6 个非背景像素），使用红(2)、蓝(1)、绿(3)等颜色，图案不具有任何对称性
- 生成约束：每个分区块至少有一条水平分隔边或一条垂直分隔边（不存在完全由网格边界围成的孤立块）；分区块尺寸足够容纳变换后的图案

**规则**：
1. 识别灰(5)分隔线并确定所有矩形分区块
2. 对每个分区块，统计其四条边的类型：
   - V = 该块与垂直分隔线相邻的边数（左侧和右侧各最多 1 条，故 V 为 0、1 或 2）
   - H = 该块与水平分隔线相邻的边数（上侧和下侧各最多 1 条，故 H 为 0、1 或 2）
   - 与网格外边界相邻的边不计入 V 或 H
3. 根据 V 与 H 的比较关系，对该块内容施加几何变换：
   - V > H → 将块内图案左右镜像
   - H > V → 将块内图案上下镜像
   - V == H（且 V > 0）→ 将块内图案旋转 180 度
4. 输出：将所有变换后的块放回原位置；移除所有灰(5)分隔线（分隔线所在行/列从输出中删除，输出网格相应缩小）

**关键洞察**：分隔线的功能不仅是空间分割，更是隐式的变换指令。每个分区块周围的分隔线拓扑结构同时承担了"分割"和"编码"两种角色——这是一种结构即指令的设计。求解者必须通过对比多个分区块的变换结果来归纳出"V vs H 决定变换类型"的规则，仅看单个块无法区分镜像和旋转。

## 新题 6：象限激活滑动碰撞计数重涂

**组合逻辑**：[象限映射+标记选区](已有，创新：标记不再映射颜色到象限，而是"激活"象限) + [平移/滑动](已有，创新：滑动方向固定向中心) + [计数](已有，创新：计数对象为路径上的障碍而非标记) + [重涂色](已有，创新：重涂由碰撞计数的比较结果决定)

**来源原语**：象限映射/quadrant_mapping、对角象限/diagonal_quadrant、标记相对方位/marker_relative_position、方位决定象限分配/position_quadrant_assign（来自 19bb5feb、94414823）；平移/translate、十字形/cross_shape、标记指示方向/marker_indicates_dir（来自 99caaf76）；计数/counting、障碍像素/blocker_pixel（来自 54db823b、6bcdb01e）；重涂色/recolor（来自 ddf7fa4f）

**依赖链**：标记方位 → 确定哪对对角象限被激活 → 激活象限内的十字精灵向中心滑动 → 沿途吞噬并计数障碍像素 → 两个激活精灵的碰撞计数比较 → 计数多者重涂蓝、少者重涂绿。每一步的输出都是下一步的必要输入。

外部标记激活一对对角象限；被激活象限中的十字精灵向中心滑动并计数途中障碍；碰撞数较多者涂蓝，较少者涂绿。

**输入结构**：
- 14x14 网格（偶数尺寸），黑(0)背景
- 一个灰(5)十字线将网格分为 4 个等大象限：灰水平线占据第 7 行全宽，灰垂直线占据第 7 列全高，在中心 (7,7) 交叉
- 每个象限内恰有一个十字形精灵（加号形：中心 + 上下左右 4 像素，共 5 像素），颜色各不相同且非灰非黑（如红(2)、绿(3)、黄(4)、品红(6)）
- 每个象限内散布 1-4 个橙(7)障碍像素
- 两个栗(9)标记像素位于灰十字线上（不在中心交叉点 (7,7)上）：
  - 若两个标记都在灰水平线上（第 7 行，分别在中心左侧和右侧）→ 激活主对角线象限组（左上 + 右下）
  - 若两个标记都在灰垂直线上（第 7 列，分别在中心上方和下方）→ 激活副对角线象限组（右上 + 左下）

**规则**：
1. 根据栗(9)标记的位置确定被激活的对角象限对
2. 未被激活象限中的十字精灵和障碍像素保持不变
3. 对每个被激活象限的十字精灵：
   a. 确定滑动方向：从该象限朝灰十字中心的方向（左上象限 → 向右下滑动；右下象限 → 向左上滑动；右上象限 → 向左下滑动；左下象限 → 向右上滑动）。滑动沿 45 度对角线方向逐步进行
   b. 每步移动整个十字精灵（5 像素一起平移 1 格行 + 1 格列）
   c. 每次移动前检查目标位置中是否有橙(7)障碍像素：若十字精灵的任何目标像素位置上有障碍，则消除该障碍（设为黑(0)），碰撞计数 +1
   d. 当十字精灵的任何像素即将进入灰(5)十字线的行或列时停止（精灵不与灰线重叠）
4. 比较两个激活精灵的碰撞计数（生成约束：两者计数不相等）：
   - 碰撞计数较多的精灵重涂为蓝(1)
   - 碰撞计数较少的精灵重涂为绿(3)
5. 灰十字线和栗标记保持不变

**关键洞察**：标记位置决定了哪两个象限参与竞赛，障碍的空间分布决定了各精灵的碰撞计数，计数的大小关系决定了最终颜色分配。三个互不相同的机制（象限选择、碰撞累积、比较重涂）链式耦合，且最终颜色不取决于精灵的原始颜色，而取决于障碍分布的不对称性。

## 新题 7：多色叶突坐标交叉印章

**组合逻辑**：[叶状突起选行列](已有，创新：突起多色化，颜色承载匹配信息) + [印章覆盖](已有，创新：印章位置由行列交叉点确定) + [颜色匹配](创新：行叶与列叶同色时才触发印章) + [擦除](已有)

**来源原语**：叶状突起/leaf_protrusion、突起定行列/leaf_selects_row_col（来自 f1cefba8）；印章覆盖/stamp_overlay、精灵体/sprite（来自 e5062a87、48f8583b）；颜色匹配/color_match（来自 981add89）；擦除/erase（来自 54db823b）

**依赖链**：叶突位置 → 确定选中的行和列 → 叶突颜色 → 在行列交叉点执行同色匹配过滤 → 匹配成功的交叉点放置对应颜色的模板印章。移除叶突位置则无坐标；移除颜色匹配则所有交叉点都印章（过多/错误）；移除模板则无印章内容。

矩形边框上的多色叶突标记选中行和列；只有颜色相同的行叶与列叶所确定的交叉点才会被印上对应颜色的模板精灵。

**输入结构**：
- 约 16x16 网格，黑(0)背景
- 一个灰(5)单像素厚矩形边框（约 10x10），内部填充黄(4)
- 矩形边框外侧有 4-6 个单像素叶突，每个叶突紧邻边框灰像素并向外延伸 1 格到黑(0)背景上：
  - 位于边框上边或下边的叶突：该叶突选中其所在列
  - 位于边框左边或右边的叶突：该叶突选中其所在行
  - 叶突颜色为红(2)、蓝(1)或绿(3)（不同叶突可同色可异色）
- 矩形外部、远离边框的位置有 2-3 个模板精灵，颜色分别为红(2)、蓝(1)、绿(3)，与叶突颜色一一对应。每个模板为 4-连通、3-5 像素的不规则小形状，不同颜色的模板形状不同
- 生成约束：至少存在一对同色的行叶与列叶；模板印章在有效交叉点处不会超出矩形内部区域；各印章之间不重叠

**规则**：
1. 识别每个叶突的颜色和类型（行选择 or 列选择）：
   - 叶突与灰(5)边框像素的相邻方向为上下（即叶突在边框正上方或正下方）→ 列选择叶突，选中该列
   - 叶突与灰(5)边框像素的相邻方向为左右（即叶突在边框正左方或正右方）→ 行选择叶突，选中该行
2. 枚举所有（行选择叶突 R，列选择叶突 C）配对：
   - 若 R 的颜色 == C 的颜色 → 该交叉点（R 选中的行，C 选中的列）被标记为"有效印章点"，印章颜色为该共同颜色
   - 若 R 的颜色 != C 的颜色 → 不标记
3. 对每个有效印章点，取对应颜色的模板精灵，将模板的包围框左上角对齐到该交叉点所在格，将模板像素印章到矩形内部：仅覆盖黄(4)的格（涂为模板颜色），不覆盖灰(5)边框或已印章的格
4. 处理顺序：按交叉点的行优先、列次优先顺序处理
5. 矩形外部的模板精灵在输出中擦除为黑(0)

**关键洞察**：叶突的功能被从"选行列后延伸射线"改造为"选行列后在交叉点印章"，且加入了颜色一致性门控——只有行叶和列叶颜色匹配时才产生印章。这意味着同一行被多个列叶交叉时，只有同色列叶的交叉点有效。求解者需通过多个示例区分"所有交叉点印章"与"同色交叉点印章"两种假说。

## 新题 8：形状字典与列权限双门过滤

**组合逻辑**：[形状匹配+框内参考色](已有，创新：匹配结果不直接重涂，而是生成"字典指派色") + [控制像素+列范围包含](已有，创新：控制色不直接填充，而是生成"列权限色") + [双门逻辑](创新：字典指派色与列权限色必须一致才能存活，否则擦除)

**来源原语**：形状匹配/shape_matching、空心矩形/hollow_rect、精灵体/sprite、框内参考色传同形/boxed_color_to_match、包含关系/containment（来自 776ffc46）；控制像素/control_pixel、列范围包含/column_span_contains、控制色决定填色/control_fill_color（来自 ddf7fa4f）；重涂色/recolor（来自 ddf7fa4f、776ffc46）；擦除/erase（来自 54db823b）

**依赖链**：灰框内精灵建立形状→颜色字典 → 自由精灵形状匹配得到"应得色" ‖ 顶行控制像素通过列包含得到"许可色" → 应得色==许可色 → 重涂存活；否则 → 擦除。两条独立分析路径在决策点汇合，缺任一路径则无法判断。

灰框中的参考精灵定义形状-颜色字典，顶行控制像素定义列-颜色权限表；自由精灵仅在字典指派色与列权限色一致时被重涂存活，否则被擦除。

**输入结构**：
- 约 18x15 网格，黑(0)背景
- 网格上部有 2-3 个灰(5)单像素厚空心矩形框（"参考框"），每个框内部封装一个小彩色精灵（4-连通，3-6 像素，形状各异，颜色各异如红(2)、蓝(1)、绿(3)）
- 顶行（第 0 行）有 3-5 个控制像素，颜色从红(2)、蓝(1)、绿(3)中取值，分布在不同列。同一颜色可出现多次
- 网格下部有 4-6 个自由精灵（4-连通，3-8 像素），颜色各异（可以是黄(4)、橙(7)、品红(6)等——与参考精灵颜色不同）
- 部分自由精灵的形状（像素掩码相对于包围框左上角的位置集合）与某个参考精灵的形状完全相同（不含旋转或翻转），其他自由精灵的形状与任何参考精灵都不匹配
- 生成约束：每个自由精灵的列跨度内至多包含 1 个顶行控制像素；至少 1 个自由精灵满足"形状匹配且颜色一致"（即会存活）；至少 1 个自由精灵因颜色不一致或无匹配而被擦除

**规则**：
1. 建立形状→颜色字典：对每个灰框内的参考精灵，提取其像素掩码（相对于包围框左上角的坐标集合）和颜色，记为字典条目
2. 对每个自由精灵：
   a. 提取其像素掩码，在字典中查找匹配（掩码完全相同）。若找到匹配：字典指派色 = 匹配的参考精灵颜色。若无匹配：字典指派色 = 空
   b. 找到该精灵列跨度（包围框最左列到最右列）内的顶行控制像素。若找到：列权限色 = 该控制像素颜色。若列跨度内无控制像素：列权限色 = 空
3. 决策：
   - 字典指派色 != 空 且 列权限色 != 空 且 字典指派色 == 列权限色 → 将自由精灵重涂为该颜色（存活）
   - 其余所有情况（无匹配、无控制像素、颜色不一致）→ 将自由精灵擦除为背景(0)
4. 灰框、参考精灵和顶行控制像素保持不变

**关键洞察**：此题的核心是"与"门结构——两条独立的信息通路（形状字典和列权限表）必须对同一个自由精灵给出一致的颜色判定，精灵才能存活。仅靠形状匹配或仅靠列权限都不足以决定输出。求解者需在示例中同时发现这两条规则并理解它们的交汇逻辑，单看任一维度都会产生矛盾。
