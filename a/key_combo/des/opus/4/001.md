## 新题 1：奇偶门控重力绕行

**组合逻辑**：[gravity_drop] + [coord_parity_match](创新：奇偶性决定障碍透明度) + [detour](创新：仅对奇偶不匹配的列生效) + [erase]（均为已有原语，组合方式为创新）

**来源原语**：gravity_drop / detour / source_column / obstacle_segment（来自 c87289bb、963c33f8）；coord_parity_match / parity_lattice（来自 d492a647）；erase（来自 f83cb3f6）

**依赖链**：坐标奇偶匹配判断为每条源列与每段障碍之间建立"是否阻挡"的布尔关系 --> 被阻挡的列触发绕行逻辑（选择障碍最近外侧） --> 未被阻挡的列直接穿透 --> 所有列延伸至底部

将顶行源列向下延伸至底部；每条源列遇到障碍线段时，根据列号与障碍行号的奇偶匹配关系决定穿透或绕行。

**输入结构**：约 15x18 黑(0)背景网格。第 0 行分布 3-5 个青(8)色源像素，各占不同列。网格中下区域有 2-3 条红(2)色水平障碍线段（每段为同一行内连续若干红色像素，长度 3-7 不等，各段所在行不同）。各障碍线段之间不共享行，且横向位置使得部分源列的正下方会穿过某条障碍。生成约束：每个源列正下方至少经过一条障碍线段；不同示例中障碍线段的行号奇偶性应有变化，以确保同一源列在不同示例中可能表现出不同行为。

**规则**：
1. 复制输入网格作为输出画布，保留所有红(2)色障碍线段不变。
2. 从每个源列像素的正下方开始，逐行向下绘制青(8)色像素，直到到达网格底行。
3. 当某源列的下行路径遇到一条红色障碍线段时，检查该源列的列号与该障碍线段所在行号的奇偶性：
   - 若列号与行号奇偶相同（同为奇或同为偶），该障碍对此列透明——源列穿透障碍继续向下延伸，障碍像素保持红色不被覆盖。
   - 若列号与行号奇偶不同，该障碍对此列为实体——源列在障碍正上方一行停止垂直延伸，沿该行水平绘制青色像素直到到达障碍线段的最近外侧端点（左端或右端，取距离源列更近的一侧；若距离相等取右侧），然后从该外侧端点的正下方继续垂直向下延伸。
4. 一条源列路径上可能遇到多条障碍线段，对每条障碍独立执行步骤 3 的判断。
5. 当两条不同源列的绕行路径在同一像素重合时，保留先处理的源列的颜色（处理顺序：按列号从左到右）。

**关键洞察**：同一条障碍线段对不同列的阻挡行为不同——并非由颜色或标记决定，而是由列号与障碍行号之间的奇偶匹配关系决定。求解者必须对比多个示例中同一障碍对不同列的不同反应，才能归纳出奇偶门控规则。

## 新题 2：投影宽度排序堆叠

**组合逻辑**：[compress / project_to_guide](创新：投射不规则图形而非散布像素) + [erase / erase_if_gap] + [sort / stacked_by_increasing_length](创新：排序依据为投影宽度而非原始长度)（均为已有原语，组合关系为创新）

**来源原语**：compress / project_to_guide / erase_if_gap / guide_bar / scattered_pixel（来自 f83cb3f6）；sort / stacked_by_increasing_length / segment / stripe（来自 beb8660c）

**依赖链**：guide_bar 间隙位置决定哪些图形存活（过滤） --> 投影宽度为存活图形定义排序键（信息变换） --> 排序结果决定堆叠顺序（空间重排）

将散布的不规则小图形投射到引导条上，擦除投影落入间隙的图形，存活图形按投影宽度排序后压缩为线段并右对齐堆叠。

**输入结构**：约 15x15 黑(0)背景网格。网格中部（约第 7 行）有一条红(2)色水平引导条，横跨大部分列但有 1-2 个间隙（间隙宽 1-2 列）。引导条上方和下方散布 4-6 个蓝(1)色 4 连通小图形（每个 3-6 像素，形态各异——非矩形的不规则形状，如弯折、斜置等），各图形之间互不接触。网格最底行有一条灰(5)色全宽条带。生成约束：每个蓝色图形的包围框宽度在 2-5 列之间；至少有一个图形的投影范围覆盖到引导条间隙；不同图形的投影宽度互不相等。

**规则**：
1. 对每个蓝(1)色小图形，计算其包围框的列范围 [c_min, c_max]。
2. 将该列范围垂直投射到引导条所在行：投影宽度 = [c_min, c_max] 范围内引导条上红色像素所占的列数（排除间隙列）。
3. 若投影宽度为 0（即图形的列范围完全落在间隙内）或图形列范围内存在间隙列，则擦除该图形（从画布上移除）。
4. 对存活图形按投影宽度从小到大排序（投影宽度相等时，按图形包围框左上角列号从左到右排序）。
5. 将每个存活图形压缩为 1 像素高的蓝(1)色水平线段，长度等于其投影宽度。
6. 在灰色条带正上方，从紧邻条带的行开始，逐行向上放置排序后的线段，每行一条，右对齐到网格右边缘。最短的线段在最靠近条带的行，最长的在最上方。
7. 清除所有蓝色图形的原始位置，仅保留引导条、灰色条带和堆叠后的线段。

**关键洞察**：排序的依据不是图形的像素数或包围框宽度，而是图形在引导条上的有效投影宽度——一个横跨 5 列的图形如果有 2 列落在间隙上，其投影宽度只有 3。投影步骤将不规则形状转换为可比较的一维量，同时间隙过滤改变了参与排序的集合。

## 新题 3：对称恢复揭示印章锚点

**组合逻辑**：[symmetry_completion / visible_recover_occluded] + [stamp / rarest_color_as_anchor](创新：锚点位置由对称恢复而非直接可见) + [crop]（均为已有原语，结构关系为创新——恢复步骤解锁放置步骤的必要信息）

**来源原语**：symmetry_completion / dihedral_symmetry / occluding_rect / visible_recover_occluded（来自 f4081712）；stamp / anchor_marker / rarest_color_as_anchor / bordered_rectangle / sprite（来自 a251c730）；crop（来自 9ba4a9aa、fc7cae8d）

**依赖链**：遮挡区域使锚点不可见 --> 二面体对称恢复还原被遮挡像素 --> 恢复出的锚点标记像素提供位置和颜色信息 --> 按锚点色匹配精灵体并放置 --> 裁剪输出

利用对称性恢复被遮挡区域中隐藏的锚点标记，再根据恢复的锚点颜色和位置将精灵体印章放入。

**输入结构**：约 20x12 网格，黑(0)背景。网格左侧（约占 5 列）有一个灰(5)色单像素边框矩形（源面板），内部包含 2 个多色精灵体（各 4-8 像素，4 连通，形态不规则），每个精灵体中恰好有 1 个颜色在该精灵体内只出现一次的锚点像素（两个精灵体的锚点色不同，锚点色从黄(4)、橙(7)中取）。网格右侧（约占 13x12 区域）有一个正方形图案，该图案具有完整的二面体对称性（90 度旋转和镜像不变），但其中有一块绿(3)色实心矩形（3x3 至 4x4）覆盖了部分图案。图案使用红(2)和蓝(1)两色构成几何纹样。被绿色矩形遮挡的区域下，有 2 个单像素锚点标记（颜色分别为黄(4)和橙(7)，与源面板精灵体的锚点色一一对应），但由于遮挡，这些锚点在输入中不可见。生成约束：对称图案的尺寸为奇数 x 奇数（如 11x11），保证旋转中心唯一；绿色矩形不覆盖对称中心；每个被遮挡的锚点至少有一个可见的对称等价位置供恢复。

**规则**：
1. 识别右侧正方形图案中的绿(3)色实心矩形为遮挡区域。
2. 对遮挡区域中的每个像素，利用图案的二面体对称性（4 个旋转 + 4 个镜像，共 8 个等价位置）找到所有未被遮挡的对称等价位置，取其颜色值还原被遮挡像素。若多个未遮挡等价位置存在，它们的颜色必然一致（由对称性保证）。
3. 恢复后，遮挡区域内出现锚点标记像素（黄(4)或橙(7)色），识别这些像素的位置。
4. 在源面板中，找到锚点色与目标锚点标记颜色相同的精灵体。
5. 将该精灵体平移到右侧图案中，使精灵体的锚点像素与恢复出的锚点标记像素重合。精灵体的非锚点像素覆盖目标位置的原有颜色。
6. 输出：恢复并放置精灵体后的右侧正方形图案区域（不含源面板和边框）。

**关键洞察**：印章放置的目标位置被遮挡矩形掩盖，求解者必须先通过对称性恢复揭示隐藏的锚点，才能确定精灵体放在哪里。对称恢复和印章放置缺一不可——跳过恢复则锚点不可知，跳过印章则恢复出的标记无用途。

## 新题 4：滑动碰撞形成腔体后填充

**组合逻辑**：[slide / collision_stop] + [flood_fill / enclosed_cavity](创新：腔体由滑动碰撞后的停止位置涌现而成) + [erase]（slide 和 flood_fill 均为已有原语，组合方式为创新——滑动结果创造填充对象）

**来源原语**：slide / collision_stop / sprite / contact_edge_align（来自 11dc524f）；flood_fill / enclosed_cavity / connectivity_reachable（来自 8b7bacbf）；dir_indication / marker_pixel（来自 760b3cac）；erase（来自 f83cb3f6）

**依赖链**：标记像素的相对位置编码滑动方向 --> 精灵体沿指定方向滑动直到碰撞停止 --> 停止后的精灵体+障碍物+网格边界围成封闭腔体 --> 腔体的边界精灵体决定填充色

多个精灵体沿标记指示方向滑动至碰撞停止，其终止位置与障碍物围成封闭区域，按边界归属填充。

**输入结构**：约 16x16 黑(0)背景网格。包含 3 个不同颜色的 4 连通不规则精灵体（各 5-8 像素），颜色从红(2)、蓝(1)、黄(4)中取。每个精灵体的 4 连通邻域中恰好有一个同色标记像素（不属于精灵体本身，与精灵体仅在一个方向上相邻），标记像素的相对位置指示滑动方向：标记在精灵体右侧表示向右滑，在下方表示向下滑，以此类推（仅限四个基本方向）。网格中另有 10-15 个灰(5)色障碍像素散布于固定位置，不与任何精灵体初始位置相邻。生成约束：每个精灵体沿其指示方向滑动后，必定会在碰到障碍物、网格边界或另一个已停止精灵体之前移动至少 2 格；滑动后的精灵体+障碍物+网格边界能围成至少 2 个封闭腔体（4 连通意义下的黑色连通分量被完全包围）；三个精灵体的滑动方向不全相同。

**规则**：
1. 确定每个精灵体的滑动方向：标记像素相对于精灵体包围框中心的基本方向（上/下/左/右）。
2. 按从上到下、从左到右的顺序（以精灵体包围框左上角为基准）依次处理每个精灵体：将精灵体整体沿指定方向平移，直到精灵体的任一像素即将与障碍像素、网格边界或已停止精灵体的像素重叠（即停在相邻位置，不重叠）。
3. 擦除所有标记像素和所有精灵体的原始位置（仅保留滑动后的位置）。
4. 在当前画布上（包含滑动后的精灵体和灰色障碍），找出所有被完全封闭的黑(0)色 4 连通区域——即无法通过 4 连通路径到达网格任意边界的黑色连通分量。
5. 对每个封闭腔体，检查其 4 连通边界上接触到哪些精灵体：
   - 若恰好接触一个精灵体，用该精灵体的颜色填充整个腔体。
   - 若接触多个精灵体，用其中像素数最少的精灵体的颜色填充（像素数相等时，取精灵体包围框左上角更靠左上的那个）。
   - 仅接触灰色障碍或网格边界但不接触任何精灵体的封闭腔体，保持黑色。

**关键洞察**：封闭腔体在输入中并不存在——它们是精灵体滑动碰撞后的停止位置与障碍物共同围合的涌现结构。填充颜色又取决于哪个精灵体构成了腔体边界，而这由滑动方向和碰撞顺序决定。三个步骤（方向解码、碰撞定位、边界归属填充）环环相扣。

## 新题 5：角落码展开同心框后奇偶过滤

**组合逻辑**：[symmetric_unfolding / corner_code_unfolds_concentric] + [erase](创新：由坐标奇偶性决定擦除目标) + [coord_parity_match](创新：从着色条件变为擦除条件)（均为已有原语，角色互换产生创新）

**来源原语**：symmetric_unfolding / corner_code / concentric_square_ring / corner_code_unfolds_concentric（来自 9d9215db）；coord_parity_match / parity_lattice / same_parity_colored（来自 d492a647）；erase（来自 f83cb3f6）；center_marker / marker_frame_color（来自 fc754716）

**依赖链**：角落编码确定同心框的颜色和层级 --> 对称展开生成完整同心框结构 --> 中心标记的坐标奇偶性定义保留格点 --> 不在保留格点上的框像素被擦除

将角落编码展开为同心正方形框，然后按中心标记定义的坐标奇偶格点过滤，擦除不匹配的框像素。

**输入结构**：约 15x15 奇数边长黑(0)背景正方形网格。网格的一个角落区域（如左上角，具体哪个角落由像素分布推断）有 3-5 个彩色像素，分布在奇坐标格点上（行列均为奇数的位置），颜色从红(2)、蓝(1)、黄(4)、橙(7)中取。这些像素构成角落编码：位于角落对角线上的像素编码对应同心层的四角颜色，位于角落水平/垂直侧边上的像素编码对应同心层对边颜色。网格正中心（第 7 行第 7 列，0-索引）有一个绿(3)色标记像素。生成约束：角落编码的像素足以定义 2-4 层同心正方形框；编码无冲突（每层仅指定一种颜色规则）；中心标记的行列坐标都为奇数（即位于奇-奇格点上）。

**规则**：
1. 识别角落编码所在的角落（选择与所有编码像素最近的网格角），将编码像素读取为该角落的局部坐标。
2. 按角落编码规则展开同心正方形框：
   - 对角线位置的编码像素（局部行 = 局部列）：其颜色赋予对应同心层的四个角。
   - 水平侧位置的编码像素（局部行 = 0 或在水平轴上）：其颜色赋予对应同心层的上下两条水平边。
   - 垂直侧位置的编码像素（局部列 = 0 或在垂直轴上）：其颜色赋予对应同心层的左右两条垂直边。
3. 展开后得到完整的多层同心正方形框图案。
4. 记录中心绿(3)色标记像素的坐标奇偶性 (row_parity, col_parity)。
5. 遍历所有同心框像素：保留行奇偶性 = row_parity 且列奇偶性 = col_parity 的像素，擦除（设为黑色）其余三种奇偶组合上的框像素。
6. 擦除中心绿色标记像素本身（设为黑色）。
7. 原始角落编码像素如果在保留格点上则保留，否则也被擦除。

**关键洞察**：同心框的结构由角落编码决定，但框上哪些像素最终可见由中心标记的坐标奇偶性过滤决定。两条规则同时作用产生"虚线同心框"效果——仅靠角落编码无法预知哪些像素被保留，仅靠奇偶过滤不知道过滤什么。需对比多个示例观察中心标记坐标变化对过滤结果的影响，才能归纳出奇偶过滤规则。

## 新题 6：棋盘格路径选环后反色填充

**组合逻辑**：[path_follow / path_connected] + [flood_fill / enclosed_cavity](创新：填充色来自棋盘格的非引导色) + [crop]（path_follow 和 flood_fill 均为已有原语，填充色的间接推导方式为创新）

**来源原语**：path_follow / checkerboard / ring_object / guide_pixel / path_connected / endpoint_adjacent（来自 9ba4a9aa）；flood_fill / enclosed_cavity / connectivity_reachable / seed_color_labels_fill（来自 8b7bacbf）；crop（来自 fc7cae8d）

**依赖链**：棋盘格相邻的引导色选择路径 --> 路径连接到目标环形对象 --> 棋盘格中的另一种颜色（非引导色）作为填充色 --> 填充环形对象的中心腔体 --> 裁剪输出目标环

沿引导路径从棋盘格追踪到目标环形对象，将环的中心腔体填充为棋盘格上未被用作引导的那种颜色，裁剪输出。

**输入结构**：约 18x18 黑(0)背景网格。包含一个 3x3 棋盘格对象（由两种颜色交替填充，如红(2)和蓝(1)，中心像素为红(2)）。包含 3-4 个 3x3 环形对象（外圈 8 像素为同一种非背景色，如灰(5)、黄(4)、橙(7)等各不同色；中心 1 像素为黑(0)，形成空腔）。棋盘格与各环形对象之间的空间有稀疏的引导像素，引导像素为单色（该色与棋盘格的两色之一相同，如蓝(1)），沿两格间距的 4 连通格点分布（即相邻引导像素之间间隔恰好一个空像素）。棋盘格恰好有一个引导像素与之相邻（4 连通），从该引导像素出发的路径仅连接到一个环形对象。生成约束：引导像素形成无分叉路径；路径终点恰好与一个环形对象 4 连通相邻；棋盘格中恰有两种颜色，其中一种与引导像素同色；不同示例中棋盘格的两种颜色和引导色的对应关系应有变化，以确保求解者必须对比才能发现"填充色 = 棋盘格非引导色"的规则。

**规则**：
1. 找到 3x3 棋盘格对象（5 个像素为一色、4 个为另一色的交替排列）。
2. 找到棋盘格 4 连通相邻的唯一引导像素，记录引导色 G。
3. 沿引导像素的两格间距 4 连通路径追踪（每步跳过一个空像素到达下一个引导像素），直到路径终端。
4. 找到与路径终端引导像素 4 连通相邻的唯一 3x3 环形对象。
5. 确定棋盘格中不等于 G 的另一种颜色 F。
6. 将目标环形对象的中心空腔（1 像素）填充为颜色 F。
7. 输出：裁剪出目标环形对象的 3x3 区域（包含填充后的中心）。

**关键洞察**：路径追踪决定"选哪个环"，但填充色既非路径色、也非环色，而是棋盘格中未被用作引导的那种颜色。这个间接推导关系需要对比多个示例——特别是棋盘格两色互换或引导色变化的情况——才能归纳出来。

## 新题 7：连线交叉后图例链式重涂

**组合逻辑**：[draw_line / same_color_pairing](创新：线段交叉为后续重涂提供初始颜色) + [recolor / chain_replace / legend_row_order](创新：链式替换作用于交叉生成的颜色) + [vertical_priority_at_cross]（draw_line 和 recolor 均为已有原语，交叉优先规则与链式替换的耦合为创新）

**来源原语**：draw_line / same_color_pairing / row_col_align / marker_pixel / vertical_priority_at_cross（来自 40853293）；recolor / chain_replace / two_col_legend / legend_row_order（来自 e4888269）

**依赖链**：同色配对确定连线端点 --> 交叉优先规则决定交叉点初始颜色 --> 交叉点初始颜色作为图例链式替换的输入 --> 链式替换后的颜色才是最终输出

连接同色标记对形成线段，交叉处按纵向优先确定初始颜色，然后对所有线段像素执行图例的链式颜色替换。

**输入结构**：约 14x14 黑(0)背景网格。左上角有一个 2 列 N 行（N = 2-3）的双列图例，由灰(5)色单像素边框包围（边框仅起视觉分隔作用，边框像素不参与替换）。图例每行左列和右列各一个颜色，表示一条替换规则。网格其余区域散布 4-6 对标记像素，每种颜色恰好出现两次，共 2-3 种颜色（从红(2)、蓝(1)、黄(4)、橙(7)中取）。每对同色标记像素共享行或列。生成约束：至少有一对水平线段与一对垂直线段发生交叉；图例中至少有一行的左列色等于某条纵向线段的颜色（即交叉处的优先色会被图例替换）；图例行数 >= 2，保证存在链式效果的可能性；不同示例中交叉位置和图例内容应有变化。

**规则**：
1. 识别图例区域（灰色边框内的 2 列色块），从上到下读取每行的替换规则 (左色 -> 右色)。
2. 对图例外的所有标记像素，找到每对同色标记（相同颜色、共享行或列的两个像素）。
3. 在每对标记之间画一条 1 像素宽的直线段（水平或垂直），颜色与标记相同，包含端点。
4. 当一条水平线段和一条垂直线段在同一像素交叉时，该像素保留纵向线段的颜色。
5. 线段绘制完成后，对画布上所有非背景、非图例边框的像素，依次执行图例的链式替换：
   - 从图例第 1 行开始：若像素当前颜色 = 左列色，则替换为右列色。
   - 继续检查图例第 2 行：若像素当前颜色（可能已被上一行替换过）= 左列色，则替换为右列色。
   - 依次处理所有图例行。
6. 图例区域（含边框）和背景保持不变。

**关键洞察**：交叉点的最终颜色取决于两步耦合——先由纵向优先规则决定初始颜色，再由图例链式替换决定最终颜色。如果交叉处横向线段颜色为红(2)、纵向为蓝(1)，则交叉点初始为蓝(1)；若图例有"蓝(1)->黄(4)"，则最终为黄(4)。去掉交叉优先规则则初始颜色不确定，去掉图例则颜色不会变换。两者缺一不可。

## 新题 8：像素膨胀改变间隙擦除判定

**组合逻辑**：[pixel_expand](创新：膨胀改变了投射范围) + [compress / project_to_guide / erase_if_gap](创新：间隙判定针对膨胀后而非膨胀前的范围)（pixel_expand 和 compress 均为已有原语，膨胀改变间隙判定结果的涌现效应为创新）

**来源原语**：pixel_expand / local_then_global_scale（来自 46f33fce）；compress / project_to_guide / guide_bar / erase_if_gap（来自 f83cb3f6）；scattered_pixel（来自 f83cb3f6）

**依赖链**：孤立像素先局部膨胀为 2x2 块 --> 膨胀后的块占据更宽的列范围 --> 新列范围可能覆盖引导条间隙 --> 覆盖间隙的块被擦除 --> 存活块保留在膨胀后的位置

将孤立像素膨胀为 2x2 块后，检查每个块的列范围是否覆盖引导条间隙；覆盖间隙的块被擦除，其余保留。

**输入结构**：约 12x12 黑(0)背景网格。网格中部（约第 5-6 行）有一条红(2)色水平引导条，横跨大部分列但有 1-2 个间隙（间隙宽 1 列）。引导条上方散布 4-6 个孤立非黑单像素（颜色从蓝(1)、黄(4)、橙(7)中取，可有重复），各像素之间至少间隔 2 行 2 列。生成约束：至少有一个像素在膨胀前其列不覆盖间隙，但膨胀后 2x2 块的列范围覆盖了间隙（即膨胀改变了擦除判定结果）；至少有一个像素膨胀前后都不覆盖间隙（作为存活对照）；像素距引导条至少 2 行。

**规则**：
1. 识别红(2)色水平引导条及其间隙位置（间隙 = 引导条所在行中的黑色像素列）。
2. 对每个孤立非黑非红像素，执行局部膨胀：以该像素位置为左上角，生成一个 2x2 同色块（即像素本身 + 右方 + 下方 + 右下方各 1 像素）。若 2x2 块的任何部分超出网格边界，则仅绘制网格内的部分。
3. 对每个膨胀后的 2x2 块，检查其列范围 [col, col+1] 内是否存在引导条间隙列：
   - 若列范围内存在间隙列，擦除整个 2x2 块（设为黑色）。
   - 若列范围内无间隙列，保留 2x2 块。
4. 引导条本身保持不变。
5. 输出画布包含引导条和所有存活的 2x2 块。

**关键洞察**：擦除判定并非基于像素的原始列位置，而是基于膨胀后 2x2 块的列范围。一个原本列号不在间隙上的像素，膨胀向右扩展一列后，新增的列可能恰好落在间隙上，导致整个块被擦除。这种"膨胀改变生存判定"的涌现效应是两步操作紧耦合的核心——单独执行膨胀不会擦除任何东西，单独执行间隙擦除对单像素不产生膨胀后才有的列覆盖，只有两者结合才产生差异化结果。
