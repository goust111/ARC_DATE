## 新题 1：拓扑门控的颜色位移印章

**组合逻辑**：[interior_containment](创新：空洞检测从"重涂色标准"变为"激活门控") → [color_encoded_disp](创新：颜色不再移动自身像素，而是编码印章目标偏移) → [stamp](创新：印章目标由颜色位移动态计算，而非固定占位对象)

**来源原语**：interior_containment, enclosed_region, objects_with_holes_recolored ← b2862040 | color_encoded_disp, foreground_pixel, color_determines_offset ← 342dd610 | stamp, mask_matching, source_colors_onto_placeholders ← 321b1fc6

**依赖链**：拓扑空洞检测筛选出"有效位移标记"（没有空洞的对象被淘汰）→ 有效标记的颜色被解码为位移方向与距离 → 源精灵体被印章到每个有效标记的位置加位移偏移处。三个环节紧耦合：删除门控则所有对象都触发印章（输出错误），删除颜色解码则无法确定印章位置，删除印章则前两步的筛选和解码毫无意义。

识别含空洞的前景对象作为有效位移标记，将其颜色解码为方向，在偏移位置印章源精灵体。

**输入结构**：
- 网格约 15x15，背景为黑(0)
- 网格左上区域有一个约 3x4 的多色源精灵体，由 2~3 种非黑颜色（如红(2)、绿(3)、黄(4)）构成不规则图案，每种颜色至少占 2 个像素
- 网格其余区域散布 4~6 个单色 4-连通小图形（每个 3~8 像素），每个图形仅使用橙(7)、蓝(1)、栗(9)、品红(6)四色之一
- 部分小图形的像素完全包围了一个或多个黑(0)背景像素（即存在 4-连通的内部空洞），部分小图形无空洞
- 不同示例中，哪些颜色的图形有空洞、哪些无空洞是变化的
- 生成约束：所有印章目标位置（有空洞图形的边界框左上角 + 位移向量）不超出网格边界；印章副本之间、印章副本与源精灵体之间不重叠；每种颜色的图形至少出现 1 个

**规则**：
1. 对每个非源精灵体的单色 4-连通前景图形，检测其是否包含 4-连通的内部背景空洞（被该图形像素完全包围的黑色连通区域）
2. 有空洞的图形标记为"有效标记"；无空洞的图形擦除为背景色
3. 颜色-位移映射表：橙(7) = 上移 3 格，蓝(1) = 右移 3 格，栗(9) = 下移 3 格，品红(6) = 左移 3 格
4. 对每个有效标记，计算印章目标位置 = 该标记边界框左上角坐标 + 对应颜色的位移向量
5. 在每个目标位置绘制源精灵体的完整副本，保留源精灵体的所有颜色
6. 擦除原始源精灵体和所有有效标记的像素（替换为背景色）
7. 绘制顺序：按目标位置行优先、列其次（从上到下、从左到右）；后绘制的覆盖先绘制的（生成时保证不重叠）

**关键洞察**：拓扑属性（空洞）和颜色语义（位移编码）是两层独立的筛选/解码机制，必须依次通过才能确定一个印章位置。仅看单个示例可能误以为"所有对象都触发印章"或"所有蓝色对象都印章到右侧"，只有对比多个示例中不同空洞状态才能归纳出门控规则。

## 新题 2：计数驱动的循环偏移填充

**组合逻辑**：[counting](保留计数逻辑) + [cyclic_adjacent](创新：循环偏移量从固定值 1 变为由外部计数动态决定) → [fill](保留空缺填充)

**来源原语**：counting, legend_box, foreground_object, color_keyed_row, count_to_dot_sequence ← 58490d8a | fill, vertical_band, cyclic_adjacent, gap_borrows_neighbor ← c4d1a9ae

**依赖链**：统计各颜色散落对象的数量 → 数量值成为对应色带的循环偏移步长 → 色带空缺按该步长从循环邻居借色填充。删除计数则偏移步长未知，删除循环填充则计数结果无用，删除色带结构则无处填充。

统计散落对象的颜色计数值，将其作为对应竖向色带借色时的循环偏移步长，实现由外部数量驱动的动态填充。

**输入结构**：
- 网格约 18x18，背景为黑(0)
- 网格下半区有 4~5 条竖向色带，每条占据连续 2~3 列，颜色互不相同（如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)），色带从左到右排列，相邻色带之间有 1~2 列黑色间隔
- 每条色带内部有若干单元格为黑(0)（空缺），空缺位置在各色带中不规律分布
- 网格上半区（色带区域之外）散布若干小型单色 4-连通对象（每个 2~4 像素），颜色与色带颜色一一对应
- 每种颜色的散落对象数量不同（1~4 个），且各色数量互不相同
- 生成约束：散落对象不与色带区域重叠；散落对象之间不相邻

**规则**：
1. 统计网格上半区每种颜色的独立 4-连通散落对象数量，记为 N_k（k 为颜色）
2. 将色带按从左到右的出现顺序编号，形成循环列表（最右色带的下一个是最左色带）
3. 对颜色为 k 的色带，在循环列表中向右偏移 N_k 步，找到目标色带，记其颜色为 C_k
4. 将色带 k 中所有空缺（黑色像素）填充为 C_k
5. 保留所有色带的原有前景像素不变；保留上半区所有像素（含散落对象）不变

**关键洞察**：源题 c4d1a9ae 中借色偏移固定为 1（总是借右邻色），这里偏移量由另一条独立逻辑（对象计数）动态决定。仅看单个示例无法区分"固定偏移 2"和"计数驱动偏移恰好为 2"，必须对比多个示例中不同颜色的偏移步长与对应散落对象计数值才能归纳出规则。

## 新题 3：尾部双义编码的象限着色

**组合逻辑**：[tail_vector](创新：尾部从"位移指令"变为"方向+数量"双义编码) → [split/quadrant](保留四等分) → [recolor](创新：着色范围由尾部长度决定，非外部标记)

**来源原语**：tail_vector, slide, tail_displacement, tail_determines_shift ← c6e1b8da | split, quadrant, corner_correspond, marker_color_to_quad ← e9ac8c9e | recolor ← 多题共有

**依赖链**：解码尾部延伸方向 → 映射到起始象限 → 解码尾部长度 → 确定从起始象限顺时针着色的象限数量 → 执行分割与选择性着色。方向与长度两层解码互不可替代，且都依赖尾部这一物理结构。

每个矩形的单色尾部同时编码起始象限（方向）和着色范围（长度），据此分割矩形为四象限并选择性着色。

**输入结构**：
- 网格约 16x16，背景为黑(0)
- 3~4 个灰(5)实心矩形，长宽均为偶数（范围 4x4 到 8x6），彼此不重叠且间距至少 2 格
- 每个矩形恰有一条单像素宽的彩色尾部从矩形某一边的中点位置向外延伸（上、下、左或右四个方向之一），尾部长度为 1~4 格
- 各矩形的尾部颜色互不相同（如红(2)、蓝(1)、绿(3)、黄(4)），尾部方向和长度在不同矩形间不完全一致
- 生成约束：尾部不超出网格边界；尾部不与其他矩形或尾部重叠；不同示例中同一颜色的尾部方向和长度可以不同（以防止求解者将颜色与方向绑定）

**规则**：
1. 将每个灰(5)矩形水平中线和垂直中线等分为四个象限：左上(TL)、右上(TR)、右下(BR)、左下(BL)
2. 尾部延伸方向映射到起始象限：向上 → TL，向右 → TR，向下 → BR，向左 → BL
3. 从起始象限开始，沿顺时针方向（TL → TR → BR → BL → TL ...），连续选取 L 个象限，其中 L = 尾部长度（1~4）
4. 将所有被选中的象限填充为该矩形的尾部颜色，未被选中的象限保持灰(5)
5. 擦除所有尾部像素（替换为背景色）

**关键洞察**：尾部在源题中只编码一种信息（位移），这里同时编码两种独立语义——方向决定起始象限，长度决定覆盖数量。单看一个示例（如尾部向上、长度 2、TL 和 TR 被着色）可能误以为"向上 = 涂上半部"，只有对比不同方向和长度的组合才能归纳出"方向定起点 + 长度定数量"的双义规则。

## 新题 4：压缩前置的引导掩码裁剪

**组合逻辑**：[compress/deduplicate](保留重复行列去重) → [guide_mask/bbox_containment](创新：引导掩码的有效框选范围在压缩后才成立) → [crop](保留裁剪)

**来源原语**：compress, deduplicate, adjacent_repeat, merge_identical_row_col ← e1baa8a4 | crop, guide_mask, hollow_sprite, bbox_containment, uniquely_enclosed ← bf699163

**依赖链**：识别重复行列并压缩 → 压缩同步改变引导掩码像素的相对位置 → 压缩后引导掩码的边界框恰好唯一框选一个目标图案 → 裁剪出该图案。压缩是选择的前提条件——不压缩则掩码框选范围错误。

先压缩含重复行列的膨胀网格，使引导掩码收拢到正确框选范围，再裁剪出唯一被框选的图案。

**输入结构**：
- 网格约 16x20，背景为黑(0)
- 网格实际上是一个约 8x8 的原始彩色图案经行列不均匀膨胀生成（不同行组重复 1~3 次，不同列组重复 1~3 次），使得图案中的对象在膨胀后被拉伸变形
- 原始图案中包含 3~4 个小型单色空心方形（3x3，由不同颜色如红(2)、蓝(1)、绿(3)构成，中心为背景色），分布在原始网格的不同位置
- 膨胀网格中散布若干品红(6)像素作为引导掩码，这些像素不落在空心方形的像素上，仅落在背景区域
- 生成约束：在膨胀网格中，品红像素的边界框包含 2 个或以上空心方形（因膨胀使空间被拉伸）；压缩回原始尺寸后，品红像素的边界框恰好仅完全包含 1 个空心方形

**规则**：
1. 识别所有最大重复行段（相邻完全相同的行，逐像素比较）和最大重复列段（相邻完全相同的列），每段保留第一行/列，删除其余重复行/列
2. 品红(6)引导掩码像素与网格内容同步经历压缩（其所在行/列若被删除则该掩码像素也被删除，若保留则保留）
3. 在压缩后的网格中，计算所有剩余品红(6)像素的边界框
4. 在压缩后的网格中，找到所有 3x3 空心方形（外圈为同一非黑非品红颜色、中心为黑色的 3x3 区域）
5. 确定唯一一个完全包含在品红边界框内的空心方形
6. 输出该空心方形的 3x3 紧凑裁剪（不含品红像素；品红像素若在裁剪区域内则替换为黑(0)）

**关键洞察**：在膨胀网格中，引导掩码的边界框因行列重复而被拉伸，看起来包含多个候选空心方形；只有先压缩去重，掩码才收拢到正确的唯一框选范围。求解者必须意识到压缩是选择的前提——在膨胀网格上直接裁剪会得到错误结果。

## 新题 5：对角连线的图例排名重涂色

**组合逻辑**：[connect/diagonal_alignment](保留对角连线) → [sort/length_ranking](创新：排名对象从竖条变为对角线段) → [recolor via color_legend](创新：图例不再选竖条而选对角线段，高度仍是排名索引)

**来源原语**：connect, diagonal_pixel_pair, diagonal_alignment ← db695cfb | sort, length_ranking, color_legend, legend_height_as_rank_index ← 97d7923e | recolor ← 多题共有

**依赖链**：连接同色对角像素对形成对角线段 → 测量各线段长度并排名 → 图例方块高度作为排名索引选中对应线段 → 被选中线段重涂为图例方块颜色。线段必须先画出才能测量排名，图例的双重语义（颜色 + 排名索引）是推理核心。

先连接对角像素对生成线段，再按线段长度排名，用图例高度作为排名索引重新着色各线段。

**输入结构**：
- 网格约 15x18，背景为黑(0)
- 网格左侧 3 列为图例区：包含 3~4 个单色小方块，各方块宽 1 格、高度各异（1~4 格），颜色互不相同（如红(2)、绿(3)、黄(4)、品红(6)），从上到下排列，方块之间有至少 1 行黑色间隔
- 网格右侧为主区域：包含 3~4 对蓝(1)像素，每对位于同一条对角线上（行差绝对值 = 列差绝对值），不同对的对角线互不交叉
- 每对蓝像素之间的对角距离（沿对角线的像素数）互不相同
- 生成约束：图例方块数量 = 像素对数量；图例高度值互不相同且取值为 1 到像素对数量的连续整数；各对角线段不共享任何像素

**规则**：
1. 在主区域中，连接每对蓝(1)像素：沿共享对角线方向（左上-右下或左下-右上）绘制蓝色对角线段，包含两端点及之间所有对角像素
2. 按对角线段长度（像素数）从长到短排名（最长 = 排名 1）
3. 对每个图例方块（颜色 K，高度 k）：找到排名为 k 的对角线段，将该线段所有像素重涂为颜色 K
4. 将图例区所有像素替换为背景色（擦除图例）
5. 保留主区域中未被任何图例选中的线段为蓝(1)不变（当图例数量 < 线段数量时生效；生成时保证图例数量 = 线段数量）

**关键洞察**：蓝(1)像素的颜色仅用于标识像素配对关系，不是最终输出颜色。线段必须先连接才能测量长度，然后图例的高度值作为排名索引（而非字面尺寸）选中对应线段并赋予新颜色。仅看单个示例容易误以为图例高度表示线段的目标长度，必须对比多个示例中高度值与实际线段长度的不匹配才能发现"高度 = 排名"的隐蔽规则。

## 新题 6：障碍触发变色的多彩螺旋

**组合逻辑**：[spiral_draw/turn_on_collision](创新：碰撞源从纯边界扩展为包含障碍像素) + [trigger_pixel](创新：触发效果从"分束"变为"切换绘制颜色") → [color_legend](创新：图例定义颜色循环序列而非排名索引)

**来源原语**：spiral_draw, square_canvas, path, rotation_dir, turn_on_collision ← 28e73c20 | trigger_pixel ← db695cfb | color_legend ← 97d7923e

**依赖链**：图例提供颜色循环序列 → 螺旋行进中遇到障碍物（触发像素）时转向且切换到序列中下一个颜色 → 遇到边界或已绘制单元格时仅转向不切换颜色 → 障碍物的空间位置间接控制了螺旋路径的颜色分段模式。

在含障碍像素的方格上绘制螺旋，仅障碍物触发的转向会切换绘制颜色，边界和自碰撞转向不切换，产生一条由障碍物位置决定颜色分段的多彩螺旋。

**输入结构**：
- 正方形网格（9x9 或 11x11），背景为黑(0)
- 网格最底行为图例行：从左到右排列 3~4 个彩色像素（如绿(3)、红(2)、蓝(1)、黄(4)），彩色像素之间有 1~2 格黑色间隔，定义颜色循环序列
- 网格内部（非底行）散布 2~4 个灰(5)障碍像素，彼此不相邻（8-连通意义下），不在网格角落
- 生成约束：螺旋路径能覆盖所有非障碍、非图例行的单元格；障碍像素彼此不相邻（保证每次转向序列中至多遇到一个障碍）

**规则**：
1. 从网格左上角 (0,0) 开始，初始方向为向右，初始颜色为图例序列第一色
2. 在当前位置绘制当前颜色
3. 检查当前方向的下一个单元格：
   - 若下一格在网格内、未被绘制、不是障碍、不是图例行：前进到下一格，回到步骤 2
   - 若下一格越界、已被绘制、或在图例行内：顺时针转向 90 度（不切换颜色），重新检查新方向的下一格；若连续四个方向都不可行则停止
   - 若下一格是障碍像素：切换到图例序列中的下一个颜色（循环），然后顺时针转向 90 度，重新检查新方向的下一格
4. 障碍像素在输出中保持灰(5)不变
5. 图例行在输出中保持不变

**关键洞察**：障碍物不改变螺旋的几何结构（只是被绕过），但它们是唯一触发颜色切换的事件——边界碰撞和自碰撞只引起转向而不变色。不同示例中障碍物位置不同导致颜色分段模式完全不同，迫使求解者追踪两种类型转向的区别，而非简单地观察颜色在空间中的位置规律。

## 新题 7：图例双义索引的精灵体排名平铺

**组合逻辑**：[area_ranking](创新：排名不再只选最大，而是按图例索引多选) + [legend_height_as_rank_index](保留高度作为排名索引) + [tile/pixel_count_sets_size_copies](创新：平铺尺寸不由精灵体自身像素数决定，而由图例高度同步决定)

**来源原语**：tile, array_layout, pixel_count_sets_size_copies ← 91413438 | crop, sprite, max_foreground_count_selected, area_ranking ← a87f7484 | sort, color_legend, legend_height_as_rank_index ← 97d7923e

**依赖链**：精灵体按前景像素数排名 → 图例高度 k 作为排名索引选中第 k 名精灵体 → 同一个 k 同时决定该精灵体的平铺方阵边长（k x k 个槽位）→ 各方阵横向拼接输出。高度的双义编码是核心——拆开任一含义都无法独立确定输出。

图例中每个色块的高度同时索引精灵体排名和决定平铺方阵尺寸，选中的精灵体被平铺到相应大小的方阵中并横向拼接。

**输入结构**：
- 网格分为上下两区，总尺寸约 10x15
- 上区：一个水平排列的精灵体条带，包含 4 个 3x3 的精灵体，紧密排列（共 3x12），每个精灵体使用不同的单一前景色（如红(2)、蓝(1)、绿(3)、橙(7)）绘制在黑(0)背景上，前景像素数量互不相同（例如分别为 3、5、7、9 个非黑像素）
- 上区与下区之间有 1 行全黑分隔
- 下区：一个图例行，包含 2~3 个单色小方块，各方块宽 1 格、高度为 1~3 格（不超过精灵体总数），颜色与精灵体颜色无关（如黄(4)、品红(6)、灰(5)），从左到右排列，方块之间有 1 格黑色间隔
- 生成约束：精灵体前景像素数量互不相同；图例高度值互不相同且每个值 ≤ 精灵体总数（4）；图例方块数量 ≤ 精灵体数量

**规则**：
1. 对上区 4 个精灵体，统计每个的非黑像素数量，按数量从多到少排名（最多 = 排名 1）
2. 对每个图例方块（颜色 K，高度 k），从左到右依次处理：
   a. 选中排名为 k 的精灵体
   b. 构建一个 k x k 的方阵画布（每个槽位为 3x3，画布总尺寸为 3k x 3k），背景为黑(0)
   c. 将选中精灵体的完整副本按行优先顺序填入全部 k^2 个槽位
3. 将所有图例方块对应的平铺方阵按图例从左到右的顺序水平拼接（方阵之间无间隔、无填充）
4. 输出拼接后的结果（输出高度 = 最大方阵的高度 = 3 x max(k)；较矮的方阵顶部对齐，下方空余区域填黑(0)）

**关键洞察**：图例高度 k 是一个双义编码——它既是"从排名列表中取第 k 个"的索引，又是"平铺为 k x k 方阵"的尺寸参数。单看一个示例容易误以为高度只控制选择或只控制尺寸，必须对比多个示例中高度值与排名和方阵大小的对应才能归纳出双义规则。

## 新题 8：遮挡恢复后的拓扑重涂色

**组合逻辑**：[occlusion_restore](保留遮挡恢复逻辑) → [interior_containment](创新：包含关系在恢复后才显现，输入中因遮挡不可见) → [recolor](创新：重涂条件由恢复后的空间拓扑决定)

**来源原语**：slide, occlusion_restore, solid_rectangle ← c6e1b8da | recolor, connected_component, enclosed_region, interior_containment, objects_with_holes_recolored ← b2862040

**依赖链**：推断被遮挡矩形的完整边界框 → 按面积排序恢复为完整矩形（大在下，小在上）→ 在恢复后的场景中检测哪些矩形的边界框完全包围了另一个矩形 → 将包围者重涂为青(8)。恢复是拓扑判断的前提——不恢复则无法判断包围关系。

恢复相互遮挡的矩形为完整形态，然后将恢复后完全包围其他矩形的矩形重涂为青色。

**输入结构**：
- 网格约 14x14，背景为黑(0)
- 4~5 个不同颜色的实心矩形（如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)），部分矩形相互重叠遮挡，被遮挡处显示为前面矩形的颜色
- 青(8)不出现在输入中
- 每个矩形至少有两条完整边可见（以便推断其完整边界框）
- 生成约束：恢复后至少有 1 个矩形的边界框严格包含另一个矩形的边界框（构成包围关系），至少有 1 个矩形不包围任何其他矩形；被遮挡的部分在输入中不可直接观察到包围关系（即包围者和被包围者之间存在遮挡）

**规则**：
1. 对每种前景颜色，根据该颜色可见像素的最小/最大行列坐标推断其完整矩形边界框
2. 按边界框面积从大到小排序
3. 按排序顺序依次在黑色画布上绘制完整实心矩形（大面积先画，小面积后画覆盖在上面），恢复所有被遮挡区域
4. 在恢复后的场景中，对每个矩形 A，检查是否存在另一个矩形 B 使得 A 的边界框四条边都严格在 B 对应边之外（即 A.top < B.top 且 A.bottom > B.bottom 且 A.left < B.left 且 A.right > B.right）
5. 若矩形 A 完全包围了至少一个其他矩形，则将 A 的所有像素（在最终输出中可见的部分）重涂为青(8)
6. 被包围的矩形保持其原始颜色不变
7. 若存在多层包围（A 包围 B，B 包围 C），A 和 B 都重涂为青(8)，C 不变

**关键洞察**：在输入中，由于矩形相互遮挡，包围关系被视觉上隐藏了——一个大矩形的部分边被另一个矩形覆盖，看不出它是否完全包围某个小矩形。只有先恢复完整形态（空间推理），才能进行拓扑判断（包围检测），然后才能决定重涂色。这三步形成严格的因果链，跳过任何一步都无法得出正确输出。
