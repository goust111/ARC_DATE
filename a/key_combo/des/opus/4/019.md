## 新题 1：通道重力与对齐轨迹

**组合逻辑**：[重力下落](创新：像素沿格子通道下落而非开放空间) + [连线/draw_line](创新：连线颜色由落点的对齐方式决定) + [行列对齐](标注对齐类型) + [背景通道](作为重力的约束边界)

**来源原语**：重力下落(b2bc3ffd), 连线/draw_line(253bf280), 行列对齐/row_col_align(253bf280), 背景通道/background_channel(b7f8a4d8), 带框瓦片/framed_tile(b7f8a4d8)

**依赖链**：格子通道结构约束重力路径 → 重力改变像素位置 → 落点位置决定同色对的对齐类型（同行/同列） → 对齐类型决定连线颜色。删除重力则落点位置错误；删除通道则运动路径不受约束；删除对齐判断则连线颜色无法确定。

将格子通道中散布的同色标记像素对按重力下落后，根据落点的行列对齐关系用不同颜色连线。

**输入结构**：约 15x15 网格。灰(5) 色格子框架将网格分割为规则的通道区域（框架宽度为 1 像素，内部通道为 2x2 或 3x3 的黑(0) 背景区域）。通道内散布着若干单像素标记，颜色取自 {红(2), 蓝(1), 绿(3), 橙(7)}，每种颜色恰好出现两次。标记像素之间互不相邻，且不与格子框架相邻。生成约束：每种颜色的两个标记位于不同的通道列或不同的通道行中，保证重力下落后至少有一对落在同一通道行或同一通道列。

**规则**：
1. 所有标记像素同时向下做重力下落：每个像素沿其所在通道列垂直下移，直到碰到格子框架像素、网格底边或已经落定的其他像素为止（停在障碍物正上方一格）。处理顺序：从最低行的像素开始逐行向上处理，同行内从左到右处理。
2. 落定后，对每种颜色的两个像素检查对齐关系：
   - 若两者位于同一通道行（即同一行带状背景区域内），则在两者之间沿该行的所有背景像素绘制黄(4) 线段（不含两端标记像素本身，线段穿过的格子框架像素保持灰(5) 不变，只涂背景像素）。
   - 若两者位于同一通道列（即同一列带状背景区域内），则在两者之间沿该列的所有背景像素绘制品红(6) 线段（同理，框架像素不变）。
   - 若两者既不在同一通道行也不在同一通道列，则不绘制任何线段。
3. 所有格子框架像素、标记像素、以及不在连线路径上的背景像素均保持不变。

**关键洞察**：重力下落改变了标记的空间关系——输入中不对齐的同色对可能在下落后变为对齐，而输入中看似对齐的对可能因不同的下落距离而错开。连线颜色编码了对齐的方向（行/列），只有在完成重力模拟后才能确定。

## 新题 2：镜像补全后的模板挖孔与紧凑排列

**组合逻辑**：[对称补全/symmetry_complete](作用于半填充色块) → [挖孔/punch_holes](创新：在补全后的色块上按同色模板挖孔) → [紧凑排列/compact_packing](保持原始顺序排列)

**来源原语**：对称补全/symmetry_complete(f25ffba3), 翻转对称/flip_symmetry(f25ffba3), 挖孔/punch_holes(58f5dbd5), 同色匹配/same_color_matching(58f5dbd5), 紧凑排列/compact_packing(58f5dbd5), 模板图案/motif_stencil(58f5dbd5), 半区/half_panel(f25ffba3)

**依赖链**：色块只有上半部有内容 → 镜像补全产生完整色块 → 完整色块的尺寸决定模板居中位置 → 同色模板在居中位置挖孔 → 挖孔后的色块按原始从上到下顺序紧凑排列为输出。删除补全则色块不完整、挖孔位置错误；删除挖孔则输出无孔洞；删除排列则输出布局不确定。

将半填充的色块镜像补全为完整方块，再用同色小模板在中心挖孔，最后紧凑排列输出。

**输入结构**：约 18x14 网格，黑(0) 背景。左侧区域从上到下排列 3 个单色实心矩形（颜色分别为红(2)、蓝(1)、绿(3)），每个矩形高度为偶数（4~6 像素），宽度 4~6 像素。每个矩形只有上半部分填充了颜色，下半部分为黑(0) 背景（即整个矩形边界框的下半区域是空的）。矩形之间垂直间隔至少 2 行。右侧区域：与每个矩形颜色对应，各有一个同色小模板精灵（2~4 像素的 4-连通图形），模板的边界框不超过 3x3。模板之间互不重叠，与左侧矩形不重叠。生成约束：每个模板的边界框严格小于其对应补全后矩形的尺寸，保证居中放置时不超出矩形边界。

**规则**：
1. 对左侧每个矩形，将其上半部分沿水平中线向下镜像翻转，填充下半部分，得到完整的实心矩形。
2. 将右侧每个模板与同色矩形配对。
3. 将模板在其配对矩形内居中放置（模板边界框的中心与矩形边界框的中心对齐，若尺寸差为奇数则偏向左上），将模板覆盖的像素设为黑(0)（挖孔）。
4. 输出网格：将 3 个挖孔后的矩形按其在输入中从上到下的顺序，垂直堆叠排列，矩形之间间隔 1 行黑(0)，整体外围留 1 像素黑(0) 边框。输出宽度为最宽矩形宽度加 2（含边框），较窄矩形在输出中水平居中。

**关键洞察**：色块在输入中只是半成品，必须先镜像补全才能确定完整尺寸。模板的居中位置依赖于补全后的完整尺寸而非输入中的半块尺寸——若直接在半块上挖孔，位置会完全错误。

## 新题 3：分隔线劈裂对象与逐带密度竞争

**组合逻辑**：[重力下落](创新：对象被分隔线劈裂为碎片后各自下落) + [计数/counting] + [洪泛填充/flood_fill] + [筛选/filtering](创新：按带状区域的密度筛选)

**来源原语**：重力下落/gravity_drop(b2bc3ffd), 计数/counting(29623171), 洪泛填充/flood_fill(29623171), 筛选/filtering(29623171), 分隔线/separator_line(29623171, 7c9b52a0), 分区区域/partitioned_region(29623171), 前景对象/foreground_object(423a55dc), 最密区域保留填充/densest_region_kept_filled(29623171)

**依赖链**：水平分隔线将跨区对象劈裂为碎片 → 碎片在各自所属带内独立下落 → 下落后统计每个带的前景像素总数 → 像素最多的带保留并洪泛填充，其余带清空。删除劈裂则碎片归属不确定；删除重力则密度分布错误；删除计数则无法选出优胜带。

跨越分隔线的对象被劈裂为独立碎片，各自在所属区域内下落后，按区域像素密度竞争决定存亡。

**输入结构**：约 15x15 网格，黑(0) 背景。2 条全宽红(2) 水平分隔行将网格分为 3 个水平带（上带、中带、下带），每带高度至少 4 行。网格中有 3~4 个单色 4-连通对象（颜色取自 {蓝(1), 绿(3), 橙(7), 青(8)}），每个对象 4~8 像素。其中至少 2 个对象跨越某条分隔行（即该对象的像素同时出现在分隔行的上方带和下方带中；分隔行本身不含对象像素）。其余对象完全位于某一个带内。生成约束：各对象颜色互不相同；每个带在劈裂和下落后至少包含 1 个像素；三个带在下落后的像素总数互不相等（避免平局）。

**规则**：
1. 沿每条红(2) 分隔行切割：跨越分隔行的对象被劈裂为独立碎片，每个碎片包含原对象在该带内的所有像素，保留原色和相对位置。不跨越分隔行的对象保持不变。
2. 在每个带内，对所有碎片和完整对象执行重力下落：每个像素在其所在列内向下移动，直到碰到该带的底边（分隔行或网格底边）或已落定的像素为止。处理顺序：从每带的最低行向上逐行处理。
3. 下落完成后，统计每个带内所有前景（非黑、非红）像素的总数。
4. 像素总数最多的带为优胜带：将该带内所有前景像素保留，并将该带内剩余的黑(0) 背景像素全部洪泛填充为灰(5)。其余带的所有前景像素清除为黑(0)（背景不变）。
5. 所有红(2) 分隔行保持不变。

**关键洞察**：对象跨带劈裂改变了各带的像素分配——一个大对象劈裂后可能在某带只留下少量碎片，使该带在密度竞争中落败。重力下落本身不改变像素总数，但它改变了像素的空间分布（这影响视觉识别但不影响计数——此处重力的作用是让碎片"归位"到带底部，使密度视觉上可读）。真正决定胜负的是劈裂后的像素分配。

## 新题 4：面积驱动的平移与优先级透明叠加

**组合逻辑**：[平移/translate](位移量 = 对象面积) + [透明叠加/transparent_overlay](创新：叠加冲突由面积决定优先级) + [同尺寸面板/same_size_panels] + [分隔线/separator_line]

**来源原语**：平移/translate(5521c0d9, b2bc3ffd), 位移等于面积/shift_equals_area(b2bc3ffd), 透明叠加/transparent_overlay(7c9b52a0), 同尺寸面板/same_size_panels(7c9b52a0), 非空标记合并/non_blank_mark_merge(7c9b52a0), 分隔线/separator_line(7c9b52a0), 面板/panel(7c9b52a0)

**依赖链**：面板内各对象面积不同 → 面积决定各自的上移距离 → 上移后对象在面板内的位置改变 → 三面板透明叠加时同一位置可能出现多色冲突 → 面积更大的对象在冲突中胜出。同一属性（面积）同时控制运动和优先级，形成自引用耦合。

将多面板中的对象按各自面积上移后透明叠加，冲突处由面积最大者胜出。

**输入结构**：约 16x15 网格。灰(5) 分隔色将网格分为 3 个等尺寸矩形面板（水平排列，每面板约 5x13 的内部区域，面板间由 1 列灰(5) 分隔，外围 1 像素灰(5) 边框）。每个面板内部背景为黑(0)，各含 1 个单色 4-连通对象（颜色从 {红(2), 蓝(1), 绿(3)} 中各取一种，三面板颜色互不相同）。对象大小各异（分别为 3、5、7 像素左右），位于面板下半部分。每个对象上方有足够的空白行容纳其上移距离（即面板高度 >= 对象最高行 + 对象面积）。生成约束：上移后至少有两个面板中的对象在叠加时产生重叠（即存在某个相对位置，至少两个面板在该位置都有非背景像素）。

**规则**：
1. 在每个面板内部，将对象整体向上平移，位移量等于该对象的像素数（面积）。若平移导致任何像素超出面板顶部边界，这些像素被裁剪丢弃。
2. 平移完成后，移除所有灰(5) 分隔结构，将三个面板透明叠加为一个面板大小的输出网格：
   - 若某位置仅一个面板有非背景色，直接使用该颜色。
   - 若某位置无面板有非背景色，输出为黑(0)。
   - 若某位置多个面板都有非背景色（冲突），取面积最大的那个对象的颜色。若面积相同（生成约束保证不会出现），取最左面板的颜色。
3. 输出网格尺寸与单个面板内部区域相同。

**关键洞察**：面积同时扮演两个角色——它既是上移的距离参数，又是叠加冲突的优先级。面积大的对象移动更远（位置变化更大），同时在重叠时又总是获胜。这意味着不能孤立地计算位移或优先级，必须理解面积的双重语义才能正确求解。

## 新题 5：格子位置选择性剪切与二面体分类着色

**组合逻辑**：[剪切变换/shear_transform](创新：仅对格子边缘位置的图形做剪切) + [形状匹配/shape_match](创新：将剪切后的图形与未剪切的图形做二面体等价比较) + [重涂色/recolor](根据匹配结果着色)

**来源原语**：剪切变换/shear_transform(423a55dc), 形状匹配/shape_match(6165ea8f), 旋转翻转等价/dihedral_equiv(6165ea8f), 重涂色/recolor(8a371977), 格子结构/lattice(8a371977), 单元格区域/cell_region(8a371977), 行列阵列位置/row_column_position(8a371977), 边缘与内部区分/perimeter_interior_distinction(8a371977), 偏移随行距增/offset_grows_with_distance(423a55dc), 底行锚点/bottom_anchor(423a55dc)

**依赖链**：格子结构定义单元格阵列 → 阵列位置决定边缘/内部分类 → 边缘单元格中的图形被剪切变换 → 变换后的图形作为比较目标 → 内部单元格的图形与变换后的边缘图形做二面体等价匹配 → 匹配结果决定内部单元格的着色。删除位置分类则不知道哪些图形该剪切；删除剪切则比较目标错误；删除匹配则着色无依据。

格子边缘单元格中的图形先做剪切变换，再与内部单元格的图形做旋转/翻转等价比较，匹配与否决定内部单元格的涂色。

**输入结构**：约 17x17 网格。灰(5) 格子线将网格分为 4x4 的单元格阵列（每个单元格内部为 3x3 的区域）。每个单元格中包含一个青(8) 的小图形（3~5 像素的 4-连通图形），图形完全位于其所在单元格的 3x3 区域内。不同单元格的图形形状各不相同（但某些图形在旋转/翻转下可能等价）。生成约束：至少存在 2 对"边缘图形剪切后与某个内部图形二面体等价"的匹配，以及至少 1 个不与任何剪切后边缘图形匹配的内部图形。

**规则**：
1. 识别阵列中的边缘单元格（行号或列号为 0 或 3 的单元格）和内部单元格（行号和列号均为 1 或 2 的单元格）。
2. 对每个边缘单元格的图形，执行左向剪切变换：以图形边界框的最底行为锚点，每行向左偏移量等于该行到锚点行的行距（即最底行偏移 0，上一行偏移 1，再上一行偏移 2...）。偏移后超出单元格左边界的像素被裁剪。将剪切结果归一化为紧边界框掩码。
3. 对每个内部单元格的图形，归一化为紧边界框掩码（不做剪切）。
4. 对每个内部单元格的掩码，检查是否与任何一个边缘单元格的剪切后掩码在二面体群（旋转 0/90/180/270 + 翻转后再旋转）下等价。
5. 着色：
   - 匹配成功的内部单元格：将该单元格的图形重涂为绿(3)，其余区域保持黑(0)。
   - 匹配失败的内部单元格：将该单元格的图形重涂为红(2)，其余区域保持黑(0)。
   - 所有边缘单元格的图形清除为黑(0)（仅保留格子线）。
6. 格子线保持灰(5) 不变。

**关键洞察**：直接比较边缘和内部图形不会得到正确结果——必须先对边缘图形执行剪切变换，产生变形后的目标形状，再进行等价判断。剪切变换是"隐藏"的预处理步骤，只有对比多个示例（有的内部图形在不剪切时匹配但剪切后不匹配，反之亦然）才能发现。

## 新题 6：颜色编码滑动门控连线路径

**组合逻辑**：[滑动/slide](颜色决定方向) + [连线/draw_line](创新：滑动后的方块位置作为连线障碍) + [填充/fill](同行列端点间填充)

**来源原语**：滑动/slide(f3e62deb), 颜色编码方向/color_coded_dir(f3e62deb), 颜色决定方向/color_determines_dir(f3e62deb), 空心矩形/hollow_rect(f3e62deb), 连线/draw_line(253bf280), 填充/fill(253bf280), 标记像素/marker_pixel(253bf280), 行列对齐/row_col_align(253bf280), 同行列端点间填充/fill_between_aligned_endpoints(253bf280)

**依赖链**：空心方块的颜色编码其滑动方向 → 滑动改变方块位置 → 方块新位置成为连线的障碍 → 红(2) 标记像素间的连线只在路径无方块阻挡时才绘制。删除滑动则障碍位置错误；删除障碍判断则所有对齐标记都会连线；颜色编码是滑动的前提。

将颜色编码方向的空心方块滑到边缘后，其最终位置阻挡或放行同色标记像素之间的连线。

**输入结构**：约 14x14 网格，黑(0) 背景。网格中有 3~4 个空心 3x3 方块（8 像素边框、中心为背景），颜色取自 {绿(3), 黄(4), 品红(6), 青(8)}——每种颜色最多出现一个方块。另有 4~6 个孤立的红(2) 标记像素散布在网格中，标记像素不与任何方块重叠。生成约束：红(2) 标记像素中存在至少 2 对同行或同列对齐的配对；在方块滑动后，至少有 1 对被方块阻挡（方块的最终位置占据了该对之间的路径像素），至少有 1 对路径畅通。

**规则**：
1. 按颜色将每个空心方块滑动到对应的网格边缘（绿(3)→左, 黄(4)→下, 品红(6)→上, 青(8)→右），方块整体平移直到其边界框紧贴目标边缘。滑动时方块穿过途中的所有红(2) 标记像素（标记像素不阻挡滑动）。如果多个方块滑向同一边缘且路径交叉，按离目标边缘远的先滑动的顺序处理（先到者不阻挡后到者，因为滑动是到边缘为止）。
2. 滑动完成后，检查每对同行的红(2) 标记像素（每行最多形成一对：若某行有恰好 2 个红标记，则为一对；多于 2 个则无配对）和每对同列的红(2) 标记像素（同理）。
3. 对每对配对：检查两个标记之间的直线路径上是否有任何方块像素（包括方块的边框和中心背景区域的边界框范围内的所有像素）占据。
   - 若路径无阻挡：用橙(7) 填充两标记之间的所有背景像素（不覆盖方块像素和标记像素本身）。
   - 若路径被阻挡：不绘制任何连线。
4. 所有方块像素、红(2) 标记像素保持不变。

**关键洞察**：方块在滑动前可能不在任何标记对的路径上，但滑动后可能恰好挡住某对连线路径——或者反过来，滑动前挡住的路径在方块移走后变为畅通。求解者必须先完成所有滑动，再判断路径通断。

## 新题 7：重力决序的模板配对与像素放大

**组合逻辑**：[重力下落/gravity_drop](创新：重力改变模板的水平排列顺序) → [顺序配对/ordered_pairing](由落定后的左右顺序决定) → [像素放大/pixel_expand](配对后执行)

**来源原语**：重力下落/gravity_drop(b2bc3ffd), 像素放大/pixel_expand(42f83767), 顺序配对/ordered_pairing(42f83767), 色卡/color_swatch(42f83767), 模板遮罩/stencil_mask(42f83767), 索引网格/index_grid(42f83767), 颜色到模板映射/color_stencil_map(42f83767), 全宽条纹/full_width_stripe(b2bc3ffd)

**依赖链**：模板漂浮在不同高度 → 重力让模板落到基准行上 → 落定后的水平排列顺序决定与色卡的配对 → 配对关系决定索引网格中每种颜色用哪个模板放大。删除重力则排列顺序错误；删除配对则放大映射不确定；删除放大则无输出。

悬浮的模板精灵在重力下落到基准线后，按落定位置的左右排序与色卡配对，再用配对关系放大索引网格。

**输入结构**：约 18x18 网格，黑(0) 背景。上方区域：3 个单色 3x3 模板精灵（每个精灵由灰(5) 像素组成，内部有黑(0) 孔洞形成不同图案），漂浮在不同高度和水平位置。上方区域底部有一条全宽黄(4) 基准行。中间有 1~2 行空白间隔。下方区域左侧：3 个 2x2 色卡方块从左到右排列（颜色分别为红(2)、蓝(1)、绿(3)），色卡之间间隔 1 列背景。下方区域右侧（与色卡同行或下方）：一个小的颜色索引网格（约 3x3），每个像素为红(2)、蓝(1) 或绿(3) 之一。生成约束：3 个模板的水平位置互不重叠；下落后三个模板在基准行上的左右顺序与其初始高度顺序不同（即重力确实改变了可观察的排列信息——实际上重力不改变水平位置，但初始的水平排列可能被求解者误认为是配对顺序，而实际配对顺序是下落后按左到右排列，即与初始水平位置一致）。

修正：重力下落不改变水平位置，所以"重力改变顺序"这一点需要重新设计。让我改为：模板在不同列悬浮，且有些模板上方有障碍物（其他模板），重力下落时上方模板先落，下方模板落在上方模板顶部，最终水平排列中某些模板被堆叠而非并列，需要取最终基准行上直接接触基准行的模板作为有效模板。

再修正：让我换一个更优雅的设计。模板悬浮在基准行上方不同高度。基准行上方还有一些灰(5) 障碍物（不构成完整模板）。重力下落后，模板可能被障碍物卡住在中途而不是落到基准行上。最终，只有落到基准行上的模板参与配对（按左到右顺序），被卡住的模板被忽略。

这增加了筛选逻辑，更有趣：

**输入结构（修正版）**：约 18x16 网格，黑(0) 背景。全宽黄(4) 基准行位于网格中部偏下。基准行上方区域有 4 个灰(5) 模板精灵（每个 3x3，由灰(5) 像素构成不同图案，含黑(0) 孔洞），漂浮在不同高度和列位置。此外，基准行上方还有 1~2 个孤立的橙(7) 障碍像素（单像素宽的平台），位于某些模板的正下方。下方区域：左侧有 3 个 2x2 色卡方块从左到右排列（颜色分别为红(2)、蓝(1)、绿(3)），间隔 1 列。右侧有一个 3x3 颜色索引网格。生成约束：4 个模板中恰好有 3 个在下落后直接接触基准行（另外 1 个被橙(7) 障碍卡住停在半空），保证有效模板恰好 3 个与 3 个色卡配对。

**规则**：
1. 基准行上方的所有灰(5) 模板精灵执行重力下落：每个模板作为一个整体（保持 3x3 形状不变）向下移动，直到其底行像素碰到基准行、橙(7) 障碍像素或另一个已落定的模板为止。处理顺序：从最低的模板开始逐个处理。
2. 下落完成后，筛选有效模板：底行直接接触黄(4) 基准行的模板为有效模板（即模板底行在基准行正上方一行）。被障碍物或其他模板卡住的模板为无效模板，从后续步骤中排除。
3. 将有效模板按其左边缘列号从小到大排序，与色卡从左到右配对（第 1 个有效模板配第 1 个色卡的颜色，以此类推）。
4. 用配对关系放大索引网格：对索引网格中每个像素，找到其颜色对应的色卡，再找到该色卡配对的模板。将该像素替换为模板的 3x3 图案，其中灰(5) 像素重涂为该像素的颜色，黑(0) 孔洞保持黑(0)。
5. 输出为放大后的网格（尺寸 = 索引网格行数x3 乘以 列数x3）。

**关键洞察**：4 个模板中只有 3 个是有效的，被障碍物卡住的那个是干扰项。求解者必须模拟重力下落来判断哪些模板到达基准行，然后才能确定正确的配对顺序。仅看初始位置的排列无法得到正确答案。

## 新题 8：层序推断决定射线透明度

**组合逻辑**：[层序推断/infer_layer_order](从交叉可见色推断层序) + [射线延伸/ray_extend](创新：最高层级的条带对射线透明) + [重涂色/recolor](穿透透明层的射线段变色)

**来源原语**：层序推断/infer_layer_order(1a2e2828), 正交交叉/orthogonal_crossing(1a2e2828), 交叉可见色为上层/visible_at_crossing_is_top(1a2e2828), 全幅条/full_span_bar(1a2e2828), 射线延伸/ray_extend(ac605cbb, 256b0a75), 重涂色/recolor(ac605cbb), 标记像素/marker_pixel(ac605cbb, 253bf280), 轨迹线段/trail_segment(ac605cbb), 行列对齐/row_col_align(253bf280)

**依赖链**：条带交叉处的可见色 → 推断层序 → 确定最高层条带 → 最高层条带对射线"透明"而其余条带阻挡射线 → 标记像素发射射线 → 射线遇非最高层条带停止，穿过最高层条带继续 → 穿过最高层的射线段被重涂色。删除层序推断则无法确定哪条带透明；删除射线则无需层序信息；删除重涂则无法区分穿透段。

从重叠条带的交叉颜色推断层序，最高层条带对标记像素发出的射线透明，穿透段变色标记。

**输入结构**：约 14x14 网格，黑(0) 背景。3~4 条全幅条带（每条宽 1~2 像素）：其中一部分为水平条（横跨整个网格宽度），另一部分为垂直条（纵贯整个网格高度），颜色从 {蓝(1), 绿(3), 品红(6), 橙(7)} 中各取一种。水平条和垂直条在交叉处重叠，交叉格显示层序较高那条的颜色。条带之外的背景区域中散布 2~3 个红(2) 标记像素，每个标记像素与某条条带同行或同列（即从标记出发沿行或列延伸必定会遇到至少一条条带）。生成约束：层序关系可从交叉处唯一确定（即交叉处提供的约束足以建立完全排序）；至少有 1 个标记像素发出的射线会遇到最高层条带（可穿过），且穿过后还会遇到另一条较低层条带（被阻挡）。

**规则**：
1. 识别所有全幅条带及其方向（水平/垂直）和颜色。
2. 在每个水平条与垂直条的交叉处，观察可见颜色：该颜色属于层序更高的条带。据此建立所有条带的完全层序（从低到高）。
3. 找出唯一的最高层条带。
4. 对每个红(2) 标记像素，向四个方向（上、下、左、右）发射射线：
   - 射线沿直线逐像素延伸，跳过黑(0) 背景像素（将其涂为灰(5) 作为射线轨迹）。
   - 当射线遇到非最高层的条带像素时，射线停止（不覆盖该条带像素，停在其前一格）。
   - 当射线遇到最高层条带时，射线穿过该条带继续前进（条带像素本身不变）。穿过最高层条带后的射线轨迹段改用黄(4) 绘制（而非灰(5)）。
   - 射线到达网格边缘时停止。
5. 若两条射线（来自不同标记或同一标记的不同方向）在同一个背景像素交汇，该像素涂灰(5)（不叠加为黄(4)，除非该像素在最高层条带之后的穿透段上，此时为黄(4)）。优先级：黄(4) > 灰(5) > 黑(0)。
6. 所有条带像素、红(2) 标记像素保持原色不变。

**关键洞察**：最高层条带不阻挡射线这一规则是隐蔽的——仅看单个示例，可能误以为所有条带都挡或都不挡。必须对比多个示例（不同层序导致不同条带"透明"）才能发现层序与透明性的关联。黄(4) 仅出现在穿透段上，是层序推断正确性的视觉验证。

## 新题 9：输入方块参数化格子后跨格连线交叉着色

**组合逻辑**：[生成网格/generate_grid](方块边长决定格子间距) + [连线/draw_line](创新：在生成的格子上按放大后的标记位置连线) + [填充/fill](连线交叉处变色)

**来源原语**：生成网格/generate_grid(695367ec), 边长决定间距/side_length_determines_spacing(695367ec), 等距参数化/uniform_parameterized_spacing(695367ec), 实心方块/solid_square(695367ec), 连线/draw_line(253bf280), 填充/fill(253bf280), 标记像素/marker_pixel(253bf280), 行列对齐/row_col_align(253bf280), 同行列端点间填充/fill_between_aligned_endpoints(253bf280), 轨迹交叉/trail_intersection(ac605cbb)

**依赖链**：输入方块边长 s → 决定格子间距 → 格子结构定义了粗格坐标系 → 标记像素在输入中的坐标映射到粗格坐标 → 同行/同列的标记对在粗格中连线 → 连线在粗格交叉处变色。方块参数改变格子间距，间距改变标记映射，映射改变连线和交叉位置。

**输入结构**：约 7x7 网格。左上角有一个青(8) 实心方块（边长 s = 2 或 3）。网格其余区域散布着若干标记像素：红(2) 标记和蓝(1) 标记各 2~3 个。标记像素不与方块重叠。生成约束：红(2) 标记中存在至少 1 对同行标记；蓝(1) 标记中存在至少 1 对同列标记；存在至少 1 个红色水平连线与蓝色垂直连线的交叉。

**规则**：
1. 读取左上角方块的边长 s 和颜色 c（青(8)）。
2. 生成 15x15 黑(0) 输出网格。从第 s 列开始，每隔 s+1 列绘制一条全高的颜色 c 竖线；从第 s 行开始，每隔 s+1 行绘制一条全宽的颜色 c 横线。这形成一个规则格子，单元格大小为 s x s。
3. 将输入网格中每个标记像素的坐标 (r, c) 映射到输出格子的对应单元格中心位置：输出行 = r * (s+1) + s//2，输出列 = c * (s+1) + s//2。在输出的该位置绘制对应颜色的标记像素。
4. 对输出中的每对同行的红(2) 标记像素（每行至多一对），用橙(7) 填充两者之间的所有黑(0) 背景像素（不覆盖格子线和标记像素）。
5. 对输出中的每对同列的蓝(1) 标记像素（每列至多一对），用绿(3) 填充两者之间的所有黑(0) 背景像素（不覆盖格子线和标记像素）。
6. 若某个像素同时处于水平橙(7) 填充和垂直绿(3) 填充的路径上（即交叉点），将其涂为黄(4)。
7. 格子线保持青(8) 不变。

**关键洞察**：方块边长 s 决定格子间距，间距又通过坐标映射公式影响标记在输出中的绝对位置。相同的输入标记布局在 s=2 和 s=3 时会产生不同的连线路径和交叉位置。求解者必须理解参数化映射才能预测输出。

**组合逻辑**：[压缩/compress](空心符号→单像素) + [形状匹配/shape_match](创新：压缩前的形状决定等价分组) + [滑动/slide](创新：同组像素作为整体联动滑动) + [重涂色/recolor](创新：组内颜色统一为组中最靠近目标边缘的成员颜色)

**来源原语**：压缩/compress(afe3afe9), 空心符号/hollow_symbol(afe3afe9), 边缘标记线/edge_marker_line(afe3afe9), 标记指示方向/marker_indicates_dir(afe3afe9), 栅格对齐/grid_aligned(afe3afe9), 形状匹配/shape_match(6165ea8f), 旋转翻转等价/dihedral_equiv(6165ea8f), 滑动/slide(afe3afe9, f3e62deb), 重涂色/recolor(8a371977)

**依赖链**：空心符号的形状决定等价分组 → 压缩为单像素丢失形状信息 → 但分组信息保留指导后续行为 → 同组像素联动滑动（任一成员被阻则全组停止） → 组内颜色统一为最靠近目标边缘的成员原色。删除形状分析则无分组；删除压缩则无法滑动单像素；删除联动则滑动结果错误；删除重涂则颜色无规律。

将空心符号按形状等价分组后压缩为单像素，同组像素联动滑向标记边缘，组内统一着色。

**输入结构**：约 18x18 网格，黑(0) 背景。网格某一边缘有一条全边长的蓝(1) 标记线（例如位于顶边，即第 0 行全为蓝(1)）。网格其余区域在粗格栅格上排列着 6~8 个空心 3x3 符号（每个符号为 8 像素边框围成的 3x3 方块，中心为黑(0)，边框像素构成不同图案），颜色取自 {红(2), 绿(3), 橙(7), 品红(6), 青(8)}，不同符号可以颜色不同。符号之间间隔至少 1 行或 1 列。生成约束：6~8 个符号中，存在 2~3 个等价组（每组 2~3 个符号的 3x3 掩码在二面体群下等价），且同一等价组内的符号颜色不全相同；每个符号恰好属于一个等价组。

**规则**：
1. 对每个空心 3x3 符号，提取其 3x3 边框掩码（忽略中心像素），归一化后进行二面体等价比较。将所有符号分为等价组。
2. 将每个空心 3x3 符号压缩为 1 个像素：取符号边界框中心位置的粗格坐标 (gr, gc)，在该位置放置该符号原始颜色的单像素。移除原始 3x3 符号的所有像素。
3. 确定滑动方向：蓝(1) 标记线的位置决定方向——顶边→下（即像素向下滑动），右边→左，底边→上，左边→右。（本规则采用"顺时针旋转 180 度"映射：标记在哪边，滑动方向就朝对面。）
4. 同组联动滑动：对每个等价组，将组内所有压缩像素同时沿滑动方向移动。组作为整体移动——每步所有成员同时前进一格。当组内任何一个成员的下一格被非本组像素（其他组的像素或网格边缘）阻挡时，整组停止。处理顺序：离目标边缘最近的组先滑动。
5. 组内重涂色：滑动完成后，对每个组，找到组内在滑动方向上最靠近目标边缘的成员（即在目标边缘方向上坐标最大/最小的那个成员）。将该组所有成员重涂为该成员的原始颜色。
6. 蓝(1) 标记线保持不变。

**关键洞察**：形状等价分析发生在压缩之前的 3x3 符号上，但其结果（分组）在压缩之后才发挥作用——约束滑动行为和决定颜色统一规则。压缩丢失了形状信息，因此求解者必须在心理上"记住"压缩前的分组，才能理解为什么某些像素联动而另一些不联动。这种跨步骤的信息传递是最大的推理障碍。
