## 新题 1：旋转变体索引的稀疏色表重涂

**组合逻辑**：[旋转 rotate](创新：旋转分析不是为了补全缺失成员，而是作为色表查询的索引键) → [位置索引 position_index] → [重涂色 recolor]（已有原语）

**来源原语**：旋转(rotate) ← be03b35f/6150a2bd；重涂色(recolor) ← 320afe60/88207623/2bee17df/09629e4f；分隔栅格(divider_grid) ← 09629e4f；位置索引(position_index) ← 09629e4f；稀疏单元色查找表(sparse_cell_color_lookup) ← 09629e4f；旋转族成员(rotation_family) ← be03b35f

**依赖链**：必须先对每个单元格的精灵体做旋转分析（确定它是基准形状的 0°/90°/180°/270° 变体），才能在稀疏键单元的四个位置中找到对应的颜色；没有旋转识别就无法查表，没有查表就无法重涂色。

将栅格中每个单元格的精灵体按其旋转变体查询稀疏键单元的色表，用查到的颜色重涂该精灵体。

**输入结构**：约 11x11 的网格，由单像素宽的灰(5)分隔线划分为 3x3 共 9 个单元格，每个单元格内部为 3x3 像素。8 个单元格各含一个小精灵体（3-6 个像素，4-连通，单色，黑(0)背景），该精灵体是某个不对称基准形状的四种 90° 旋转变体之一（基准形状在四种旋转下互不相同）。恰好 1 个单元格是"键单元"：它的非黑(0)非灰(5)像素数比其他单元格少（恰好 4 个彩色像素，其他单元格各有 5 个以上）。键单元的 4 个彩色像素分别位于其 3x3 内部的四个角位：左上角像素的颜色对应 0° 变体，右上角对应 90° 变体，右下角对应 180° 变体，左下角对应 270° 变体。这四个像素各不相同，从红(2)、蓝(1)、绿(3)、黄(4) 中取四种。不同示例中键单元的位置不同（可以是 9 个单元格中的任何一个），基准形状也不同。生成约束：每种旋转变体在 8 个非键单元中至少出现一次。

**规则**：
1. 沿灰(5)分隔线将网格分割为 9 个单元格。
2. 识别键单元：非黑(0)非灰(5)像素恰好为 4 个的那个单元格。
3. 读取键单元的色表：左上角像素颜色 → 0° 映射色，右上角 → 90°，右下角 → 180°，左下角 → 270°。
4. 从任一非键单元提取精灵体形状作为基准候选，通过 0°/90°/180°/270° 旋转生成四种标准变体。
5. 对每个非键单元，将其精灵体与四种标准变体逐一比较（像素集合匹配），确定其旋转变体编号（0°/90°/180°/270°）。
6. 用键单元色表中该变体编号对应的颜色重涂该单元格的所有精灵体像素。
7. 键单元本身、分隔线和背景不变。

**关键洞察**：键单元不只是调色板——它的四个角位编码了旋转变体到颜色的映射关系，求解者必须先完成几何旋转分析才能使用这张色表。

## 新题 2：连线路径定义分组的排序堆叠

**组合逻辑**：[连线 connect]（创新：连线不是装饰性填充，而是作为空间分组的定义机制）→ [排序 sorting]（已有原语）→ [堆叠 stacking]（已有原语）

**来源原语**：连线(connect) ← dbc1a6ce；标记像素(marker_pixel) ← dbc1a6ce/878187ab；同行列对齐(row_col_aligned) ← dbc1a6ce；相邻标记间填充(fill_between_markers) ← dbc1a6ce；堆叠(stacking) ← 4acc7107；排序(sorting) ← 4acc7107；位置排序(positional_ordering) ← 4acc7107；对齐紧凑排布(aligned_compact_layout) ← 4acc7107

**依赖链**：连线段的空间位置决定了哪些前景对象属于同一组（几何邻近性分组，非颜色分组），分组结构决定了堆叠的组成，组内排序依赖于对象的像素计数。三层逻辑逐级依赖：无连线则无分组，无分组则堆叠无从谈起。

将蓝色标记间的连线段作为空间走廊，按走廊邻近性将散落的前景对象分组，组内按像素数排序后紧凑堆叠输出。

**输入结构**：约 20x20 黑(0)背景网格。4-6 个小型单色 4-连通前景对象（各 3-8 像素），每个对象使用不同颜色（从红(2)、绿(3)、黄(4)、橙(7)、品红(6)中选取，不使用蓝(1)或青(8)）。6-10 个蓝(1)标记像素散布在网格中，部分标记共享同一行或同一列。对象不与标记像素重叠。生成约束：连线段形成后，每个对象至多被一条连线段的包围盒所触及；至少 3 个对象被某条连线段触及，至少 1 个对象不被任何连线段触及。

**规则**：
1. 对每一行中包含 2 个以上蓝(1)标记的行，按列坐标排序标记，在每对相邻标记之间的背景格上绘制青(8)水平连线段（不含标记本身的位置）。对列做同样处理，绘制垂直连线段。
2. 定义"触及"：一个前景对象被一条连线段触及，当且仅当该连线段至少有一个青(8)像素位于该对象包围盒内或与包围盒 4-相邻。
3. 每条连线段定义一个组：所有被该段触及的对象归入该组。若一个对象被多条连线段触及，它属于按扫描序（从上到下、从左到右）最先遇到的连线段所定义的组。
4. 未被任何连线段触及的对象各自成为独立的单元素组。
5. 组内对象按像素数降序排列（像素数相同则按包围盒左上角的扫描序排列）。
6. 将每组的对象裁剪到各自包围盒，按排序顺序从上到下垂直堆叠（相邻对象间留 1 行黑(0)背景间隔），在输出画布上底部对齐。
7. 组之间从左到右排列（间隔 1 列黑(0)背景），组的排列顺序为：连线段定义的组按其连线段起始像素的扫描序排列，单元素组排在最右侧（按原始位置扫描序排列）。
8. 输出画布的高度取所有组堆叠高度的最大值，宽度为所有组宽度之和加组间间隔。

**关键洞察**：蓝色标记看似只是独立的点状信号，实际上它们的行列对齐关系生成了空间走廊，走廊的位置把颜色各异的前景对象划分成了几何分组——分组依据是走廊的空间邻近性，而非对象自身的颜色属性。

## 新题 3：镜像足迹解码滑动方向与涂色

**组合逻辑**：[镜像 mirror]（创新：镜像不产生可见输出，而是构建坐标系用于解码标记位置）→ [滑动 slide]（创新：滑动方向由标记在镜像足迹中的相对位置编码）→ [重涂色 recolor]（已有原语）

**来源原语**：镜像(mirror) ← 88207623；轴线段(axis_segment) ← 88207623；标记像素(marker_pixel) ← 88207623；跨轴反射(reflection_across_axis) ← 88207623；标记色指定涂色(marker_color_paint) ← 88207623；滑动(slide) ← 320afe60；靠边对齐(edge_aligned) ← 320afe60；重涂色(recolor) ← 320afe60

**依赖链**：必须先计算镜像足迹（反射后的包围盒），才能判断标记像素在足迹中的相对位置；相对位置编码了滑动方向；标记的颜色同时指定重涂色。镜像操作本身不出现在输出中，它仅作为几何解码工具。

利用红色轴段的镜像足迹作为坐标参考系，从足迹内标记像素的方位读取滑动方向，再以标记颜色重涂滑动后的对象。

**输入结构**：约 15x15 黑(0)背景网格。3-4 条红(2)垂直线段（每条 3-5 像素高），不接触网格边缘。每条红线段的左侧或右侧恰好 8-相邻一个黄(4) 4-连通对象（3-7 像素，不对称形状）。在红线段的另一侧，位于该黄色对象镜像足迹（反射后包围盒）内的某个位置，恰好有一个单像素标记，颜色从蓝(1)、绿(3)、橙(7)、品红(6)中取（不与其他标记重复）。生成约束：每个标记在足迹包围盒内的位置明确落在上半区、下半区、左半区或右半区之一（不处于正中线上）；4 个方向（上/下/左/右）在所有对象中至多各出现一次；各对象滑动后互不重叠。

**规则**：
1. 对每条红(2)轴线段，找到与之 8-相邻的黄(4)对象。
2. 将该黄色对象的每个像素关于红线段所在列做水平反射，得到镜像像素集合；计算镜像像素集合的包围盒，即为"镜像足迹"。
3. 在镜像足迹的包围盒内找到唯一的标记像素。
4. 计算标记在足迹包围盒内的归一化坐标：row_frac = (标记行 - 包围盒顶行) / (包围盒高 - 1)，col_frac = (标记列 - 包围盒左列) / (包围盒宽 - 1)。
5. 判断方向：若 |row_frac - 0.5| >= |col_frac - 0.5|，则 row_frac < 0.5 → 向上滑动，row_frac >= 0.5 → 向下滑动；否则 col_frac < 0.5 → 向左滑动，col_frac >= 0.5 → 向右滑动。
6. 将原始黄色对象沿确定的方向平移，直到其前导边缘抵达网格边界（对象整体贴边，不超出）。
7. 将平移后的对象重涂为标记像素的颜色。
8. 从输出中移除所有红线段和标记像素，只保留背景和重涂后的滑动对象。

**关键洞察**：镜像操作从不在输出中留下痕迹——它仅作为几何坐标系存在，将标记像素的绝对位置转换为相对于对象形状的方位信号，从而编码了滑动方向。标记同时承载了方向信息（位置）和颜色信息（颜色值），实现了双重编码。

## 新题 4：走廊约束下的选择性对称补全

**组合逻辑**：[对称补全 symmetric_complete] ↔ [填充 fill]（双向约束：补全受走廊保护条件限制，走廊填充取决于补全结果；非流水线，为同时约束满足结构）

**来源原语**：对称补全(symmetric_complete) ← 8dab14c2；凸起(tab)/缺口(notch)/边界(boundary) ← 8dab14c2；对侧互补(opposite_side_complement) ← 8dab14c2；跨行列投射(cross_span_projection) ← 8dab14c2；填充(fill) ← 2bee17df；走廊(corridor) ← 2bee17df；边界像素(border_pixel) ← 2bee17df；对边连通(opposite_edge_connect) ← 2bee17df；无阻挡跨行列涂色(unobstructed_span_recolored) ← 2bee17df

**依赖链**：补全操作（将凸起/缺口投射到对侧）会在走廊路径上添加或移除像素，可能堵塞走廊。走廊的保护条件反过来限制了哪些补全可以执行。二者形成同时约束：求解者不能先独立完成所有补全再检查走廊，必须逐一评估每个补全是否与走廊保护冲突。

在保护现有走廊畅通的前提下，有选择地对厚实矩线形状的边界执行凸起/缺口的对侧互补，然后用绿色填充所有幸存走廊的内部。

**输入结构**：约 15x15 黑(0)背景网格。一个厚实的灰(5)矩线形前景对象（占网格面积约 40-60%，宽度至少 3 像素），其边界上有 3-5 个凸起（仅有 1 个前景 4-邻居的边界像素）和 3-5 个缺口（具有 3 个前景 4-邻居的背景像素）。网格四条边界的某些格（第 0 行、最后一行、第 0 列、最后一列）被涂上红(2)或青(8)。存在 2-3 条"走廊"：某行的最左和最右网格边界格均为彩色，且该行内部所有格要么是灰(5)形状内部、要么是黑(0)背景（无其他前景阻挡），对列同理。生成约束：至少 2 个凸起或缺口的对侧互补位置恰好落在某条走廊路径上（即补全该凸起/缺口会在走廊上新增或移除一个像素）。

**规则**：
1. 识别所有当前走廊：逐行检查——若最左格和最右格均为红(2)或青(8)，且它们之间的所有格均为灰(5)形状内部或黑(0)背景，则该行是走廊；对列同理。
2. 识别所有凸起和缺口：凸起是灰(5)像素中恰有 1 个灰(5) 4-邻居的边界像素；缺口是黑(0)像素中恰有 3 个灰(5) 4-邻居的背景像素。
3. 对每个凸起，计算其互补：在同一行或列上穿过形状到达对侧边界外一格的位置处移除一个灰(5)像素（形成缺口）。对每个缺口，计算其互补：在对侧边界外一格处添加一个灰(5)像素（形成凸起）。
4. 逐一检查每个候选补全：若添加或移除该像素后会使任何一条当前走廊的内部出现新的阻挡（背景格变为前景或前景格变为背景从而打破行列连续性），则该补全被禁止。
5. 执行所有未被禁止的补全。
6. 在完成补全后的网格上，重新检测所有走廊（按步骤 1 的定义），将每条走廊上所有黑(0)背景内部格涂为绿(3)。
7. 灰(5)形状内部、红(2)/青(8)边界格和分隔线不变。

**关键洞察**：求解者不能贪心地补全所有凸起和缺口——每个候选补全必须先通过走廊保护测试。走廊既是约束条件（限制补全），又是最终产出（决定绿色填充区域），二者互为前提，构成非流水线的约束满足结构。

## 新题 5：分形蓝图生成的走廊门控填充

**组合逻辑**：[缩放/自相似 scale]（已有原语）→ [填充 fill]（创新：填充的触发条件不是边界像素，而是蓝图补全后涌现的"少数单元走廊"）

**来源原语**：缩放(scale) ← b99e7126；分隔网格(separator_grid) ← b99e7126；少数单元(minority_cell)/多数单元(majority_cell) ← b99e7126；自相似(self_similarity) ← b99e7126；少数图案为蓝图(minority_pattern_as_blueprint) ← b99e7126；填充(fill) ← 2bee17df；走廊(corridor) ← 2bee17df；对边连通(opposite_edge_connect) ← 2bee17df；无阻挡跨行列涂色(unobstructed_span_recolored) ← 2bee17df

**依赖链**：分形蓝图决定哪些单元格变为少数单元（改变网格布局）→ 新布局决定哪些行/列的端点均为少数单元且中间全为多数单元（走廊结构）→ 走廊结构决定哪些多数单元的内部被填充。走廊是蓝图补全后的涌现属性，不可跳步。

**组合逻辑**：[平铺 tile]（已有原语）+ [计数 count]（创新：像素计数同时决定平铺重复次数和遮挡优先级，单一属性的双重角色）+ [缺口决定方向 notch_determines_dir]（创新：缺口不再决定滑动方向，而是决定平铺方向）+ [遮挡覆盖 occlusion_overwrite]（已有原语）

**依赖链**：缺口方位决定平铺方向（四向之一）；像素计数决定平铺重复次数；当不同对象的平铺区域重叠时，像素计数再次作为遮挡优先级裁判（像素少的对象在上层）。三个属性（缺口位置、像素数量、重叠区域）形成紧耦合：改变任一对象的缺口位置会改变其铺展方向从而改变重叠格局，改变像素数会同时改变铺展长度和遮挡优先级。

每个前景对象按其缺口朝向的方向平铺，重复次数等于其像素数，重叠区域由像素数更少的对象覆盖更多的对象。

**规则**：
1. 对每个对象，识别其缺口侧：检查包围盒四侧的边界像素行/列，找到存在"被同色像素夹着的背景间隙"的那一侧。
2. 缺口侧决定平铺方向：缺口在上侧 → 向上平铺，缺口在右侧 → 向右平铺，缺口在下侧 → 向下平铺，缺口在左侧 → 向左平铺。
3. 计数该对象的前景像素数 C，平铺 C 次（含原始位置，故新增 C-1 个副本）。
4. 将对象裁剪到包围盒后，沿平铺方向依次紧贴排列副本（每个副本的前导边紧接前一个副本的尾随边，无间隔）。
5. 超出网格边界的副本像素被裁剪丢弃。
6. 绘制顺序：按像素数 C 降序绘制各对象的平铺区域（像素最多的对象先画，最少的后画），后画的覆盖先画的。即像素数最少的对象在最顶层。
7. 若两个对象像素数相同（生成约束中已排除此情况，此条为防御性规则），以包围盒左上角扫描序靠前的优先在上层。

**关键洞察**：像素计数承担了双重角色——它既是"铺多少次"的计量器，又是"谁覆盖谁"的优先级排序依据。一个像素少的对象铺展范围小但在重叠处总能显现；一个像素多的对象铺展广阔但在任何冲突中都被压在下面。缺口方向则将这种铺展-遮挡博弈投射到特定的空间轴上。

**依赖链**：必须先从三个可见瓦片中识别旋转族关系（判断哪三个 90° 变体在场），才能生成第四个缺失变体的几何形状；同时必须从三个瓦片中归纳出颜色交替规则（相邻 90° 旋转的颜色互换关系），才能确定缺失变体的着色。旋转分析和颜色规则归纳必须同时完成，缺一不可。

从双色四角瓦片的三个已知旋转变体中推断缺失的第四个变体，并应用旋转族中相邻成员间的颜色互换规则，裁剪输出缺失瓦片。

**输入结构**：约 11x11 的奇数尺寸正方形网格。一条单像素宽的黑(0)十字线将网格分为四个相等的正方形角落瓦片（每个约 5x5）。三个角落瓦片包含由红(2)和蓝(1)两种颜色构成的图案（在黑(0)背景上，每种颜色至少 3 个像素），该图案是同一基准形状的三个不同 90° 旋转变体。基准形状不对称（四种旋转互不相同）。颜色分配规则：将四个角位按顺时针编号 0-3（左上=0，右上=1，右下=2，左下=3），编号为偶数的角使用原始颜色（红(2)像素在原位，蓝(1)像素在原位），编号为奇数的角使用互换颜色（原来红(2)的位置变蓝(1)，原来蓝(1)的位置变红(2)）。第四个角落瓦片填充为纯灰(5)（占位标记）。生成约束：占位标记可出现在任意一个角；三个可见瓦片足以唯一确定基准形状和颜色交替规则。

**规则**：
1. 读取三个非灰色角落瓦片的图案。
2. 将红(2)和蓝(1)合并为统一前景，提取前景掩码形状。
3. 通过旋转比较确定三个瓦片分别是基准形状的 0°、90°、180°、270° 中的哪三个变体，从而确定缺失的第四个旋转角度。
4. 生成缺失变体的前景掩码（将基准形状旋转到缺失角度）。
5. 确定缺失角的顺时针编号（左上=0，右上=1，右下=2，左下=3）。
6. 若编号为偶数：前景掩码中的像素保持基准形状的原始颜色分配（红(2)像素对应基准中的红位，蓝(1)对应蓝位）。若编号为奇数：将基准颜色分配互换（红位变蓝，蓝位变红）。
7. 输出仅为缺失瓦片（裁剪到角落瓦片尺寸），在黑(0)背景上绘制带正确颜色的旋转变体。

**关键洞察**：如果求解者只关注形状旋转而忽略颜色，会发现三个瓦片中有的红蓝配置一致，有的相反——这不是噪声，而是旋转族中由角位奇偶性驱动的系统性颜色交替规则。必须同时推断旋转和颜色规则才能正确着色缺失瓦片。
