## 新题 1：滑动距离编码填充高度

**组合逻辑**：[滑动/slide] → [计数/counting](创新：计量滑动位移而非像素数) → [延伸填充/extension_fill](创新：填充高度由位移决定而非列距离)；[固定障碍颜色] 决定填充方向（已有条件的创新组合）

**来源原语**：滑动/slide、同行阻挡/same_row_blocking、靠近障碍停止/stop_at_barrier（参考题 9c56f360）；延伸填充/extension_fill、距离控制高度/distance_controls_height（参考题 5207a7b5）；计数/counting（参考题 dce56571）

**依赖链**：滑动操作的位移量成为延伸填充的高度参数——不执行滑动就无法知道填充高度；障碍颜色同时决定停止位置和填充方向，将两个独立操作耦合在同一条件节点上。

将右侧边缘的彩色水平条滑向固定障碍，滑动距离决定在终点位置生成的垂直条高度，障碍颜色决定垂直条的延伸方向。

**输入结构**：约 15x20 的黑(0)背景网格。网格中散布若干单像素宽的固定障碍像素，颜色为绿(3)或橙(7)，每行至多一个。部分行的右侧边缘有一段 2~4 像素长的水平连续色块（可移动行程），颜色各不相同，选自蓝(1)、红(2)、黄(4)、品红(6)，每行至多一段。可移动行程与同行障碍之间全为黑(0)背景。生成约束：每段可移动行程所在行必须恰好有一个固定障碍；不同可移动行程之间不在相邻行（保证垂直填充不交叉）。

**规则**：
1. 逐行独立处理（从第 0 行到最后一行）。对每行中存在的可移动行程，将其整体向左滑动，直到行程的最左像素紧邻该行固定障碍像素的右侧。
2. 计算滑动位移 d = 行程最左像素的原始列号 - 行程最左像素的终止列号。
3. 擦除行程的原始位置（恢复为黑(0)）。
4. 在行程终止位置的最左列，以行程所在行为起点，绘制一条垂直色条，颜色与行程相同，长度为 d 个像素：
   - 若该行的固定障碍颜色为绿(3)，垂直条向上延伸（行号递减方向）。
   - 若该行的固定障碍颜色为橙(7)，垂直条向下延伸（行号递增方向）。
5. 垂直条超出网格边界的部分直接裁掉。
6. 固定障碍像素保持不变。若垂直条与其他已绘制的垂直条在同一像素重叠，先绘制的保留（后绘制的跳过该像素）。

**关键洞察**：滑动本身不是最终目标，滑动的位移量被重新解释为另一个几何维度的长度——一个操作的动态结果编码了另一个操作的参数。

## 新题 2：对称性门控路径路由

**组合逻辑**：[路径绘制/path_drawing] + [筛选/filter](创新：对称性检测作为路径实时路由条件而非输出筛选) + [绕行/detour](创新：绕行方向由对称性位置决定而非障碍颜色)

**来源原语**：路径绘制/path_drawing、绕行/detour、障碍条/obstacle_bar、阻挡/blocking（参考题 96a8c0cd）；筛选/filter、对称性筛选目标/symmetry_filter、精灵体/sprite（参考题 72ca375d）；边界标记/border_marker（参考题 f341894c）

**依赖链**：路径前进方向确定后，在每个"门"处必须判断两侧精灵体的对称性，对称性结果即时决定路径偏转方向——路径绘制与对称性筛选逐步交替耦合，不可分离。

从边界标记出发画路径，路径每遇到一对横跨通道的精灵体"门"，就从具有轴对称性的那一侧通过。

**输入结构**：约 20x15 的黑(0)背景网格。左侧边界上有一个红(2)标记像素，指示路径从左向右行进。网格内部沿水平方向排列 2~4 对"门"，每对门由上下两个单色小精灵体（4-连通，3~7 像素，颜色为灰(5)）组成，两个精灵体分别位于路径通道的上侧和下侧，中间留 1 像素宽的通道行。每对门中恰好一个精灵体具有垂直轴对称或水平轴对称性，另一个不具有任何轴对称性。不同门的对称精灵体可能在上侧也可能在下侧。门与门之间水平间距至少 3 列。生成约束：通道行在门与门之间保持连续；对称精灵体所在侧至少有 1 行空间供路径绕行。

**规则**：
1. 路径从左边界红(2)标记所在行出发，向右水平前进，逐像素绘制红(2)。
2. 当路径前方遇到一对门（即通道行被两侧精灵体夹住而非全空时），检测上侧和下侧精灵体的轴对称性（垂直轴或水平轴均算）。
3. 路径偏转到具有对称性的精灵体所在一侧通过：
   - 若对称精灵体在上侧，路径先向上移 1 行，水平穿过门的宽度，再向下移 1 行回到原通道行。
   - 若对称精灵体在下侧，路径先向下移 1 行，水平穿过门的宽度，再向上移 1 行回到原通道行。
4. 路径穿过所有门后继续水平前进直到右边界。
5. 仅在黑(0)背景像素上绘制红(2)路径；精灵体像素保持不变。

**关键洞察**：对称性不是用于筛选最终输出的静态属性，而是路径在每个决策节点的实时路由信号——必须逐门检测对称性才能确定路径走向。

## 新题 3：射线可见性驱动图案重涂色

**组合逻辑**：[射线投射/ray_cast] → [解码/decode](创新：射线命中的源区域颜色替代内部槽位作为解码键) → [重涂色/recolor]；多方向射线冲突时引入 [象限/quadrant] 分割

**来源原语**：射线投射/ray_cast、视线可达/line_of_sight、源区域/source_region（参考题 3d588dc9）；解码/decode、重涂色/recolor、重复图案/repeated_motif、图例映射/legend_mapping（参考题 1be83260）；象限/quadrant、位置对应/pos_correspond（参考题 7c008303）

**依赖链**：每个图案块的重涂色不由内部信息决定，而由外部射线可见性决定——必须先执行射线投射确定可见源区域，才能确定颜色映射；当水平和垂直方向命中不同源区域时，图案被拆分为象限，每个象限的颜色取决于该方向的可见源，形成二维解码。

网格中央的重复图案矩阵通过向四周射线投射找到边缘源区域，用命中的源颜色重涂每个图案块；当两个方向命中不同源时，图案块按象限分别着色。

**输入结构**：约 20x20 的黑(0)背景网格。中央区域有一个 R 行 C 列（R, C 各 2~4）的图案矩阵，图案之间无间隔紧密排列，每个图案为相同的 3x3 或 4x4 单色（灰(5)）掩码（含 1~3 个黑(0)孔洞）。矩阵外围的四条边缘（上、下、左、右）各放置 1~2 个单像素色块作为源区域，颜色选自蓝(1)、红(2)、绿(3)、黄(4)，每种颜色至多出现一次。源区域与矩阵之间的行/列全为黑(0)背景（射线通道畅通）。生成约束：每个图案块沿水平方向或垂直方向至少能射线命中一个源区域；不存在某图案块四个方向都无法命中任何源的情况。

**规则**：
1. 对矩阵中的每个图案块，从其中心位置分别向上、下、左、右四个方向投射射线（沿行或列直线前进），射线穿过黑(0)背景，遇到第一个非黑非灰像素时停止，记录该像素的颜色为该方向的"可见源色"。若射线到达网格边界仍未命中任何源，则该方向无可见源。
2. 收集该图案块的所有可见源色（去重）：
   - 若只有一种可见源色，将该图案块的所有灰(5)像素重涂为该颜色。
   - 若有两种可见源色，将图案块的边界框平分为四个象限（左上、右上、左下、右下，尺寸不等时上半/左半取 ceil）。水平方向（左或右）命中的源色涂左半两个象限的灰(5)像素，垂直方向（上或下）命中的源色涂右半两个象限的灰(5)像素。若同一轴两个方向命中不同颜色，取离该图案块更近的那个源。
3. 图案块内的黑(0)孔洞始终保持黑(0)。
4. 源区域像素和矩阵外的背景保持不变。
5. 图案块按从左上到右下逐个处理（行优先），处理顺序不影响结果因为各块独立。

**关键洞察**：颜色映射不是由内部图例给出的静态查找表，而是由每个图案块的空间位置和射线可见性动态决定的——同一颜色的源可能对不同图案块产生不同效果（整块涂色 vs 仅涂某些象限）。

## 新题 4：标记定位矩形的面积驱动缩放印章

**组合逻辑**：[角标记/corner_marker + 标记定位矩形/markers_locate_rectangle](已有) → [计数/counting](创新：计算矩形面积而非像素数) → [像素放大/pixel_scaling + 印章覆盖/stamp](创新：缩放因子由目标矩形面积与模板面积之比决定)

**来源原语**：角标记/corner_marker、标记定位矩形/markers_locate_rectangle、遮罩矩形/mask_rectangle、按标记色分组/group_by_marker_color、包围框修剪定位/bounding_box_trim_to_locate（参考题 1c02dbbe）；像素放大/pixel_scaling、印章覆盖/stamp、模板/template、缩放对应/scale_correspond、边长定缩放因子/side_sets_scale（参考题 447fd412）；擦除/erase（参考题 3d588dc9）

**依赖链**：标记定位确定矩形的几何尺寸→矩形面积除以模板面积得到缩放因子→缩放因子决定模板的放大倍率→放大后的模板印入矩形区域。标记颜色同时承担定位和着色双重角色。

用三点同色角标记定位灰色遮罩中的子矩形，每个子矩形的面积与固定模板的面积之比确定缩放倍率，将模板按该倍率放大后印入矩形，模板颜色替换为标记颜色。

**输入结构**：约 18x18 的黑(0)背景网格。网格中央有一个较大的灰(5)实心矩形遮罩（约 12x14）。遮罩外部散布若干彩色标记像素，按颜色分组，每组恰好 3 个同色像素，颜色选自红(2)、绿(3)、蓝(1)，共 2~3 组。每组 3 个标记的轴对齐包围框经过修剪后恰好框定遮罩内部一个全灰子矩形（修剪规则：四种单边裁切中，取内部全为灰(5)加标记色且恰含 1 个标记的那种）。网格左上角（遮罩外）有一个 2x2 的单色模板图案，颜色为黄(4)，其中恰好 3 个像素为黄(4)、1 个像素为黑(0)。生成约束：每个定位出的子矩形面积恰好是模板面积（3 像素）的完全平方倍（即 3, 12, 27, ...），使得缩放因子 k 为整数（k=1, 2, 3, ...）；子矩形的宽和高分别是模板宽和高的 k 倍；不同组定位的子矩形互不重叠。

**规则**：
1. 按颜色对标记像素分组。对每组 3 个同色标记，计算其轴对齐包围框。
2. 对包围框的四种单边修剪（去掉上边一行、去掉下边一行、去掉左边一列、去掉右边一列），选择使修剪后矩形内只含灰(5)和该标记色、且恰好包含该组 3 个标记中的 1 个的那种修剪方式，得到目标子矩形。
3. 将所有标记像素擦除为黑(0)。
4. 计算目标子矩形的面积 A_rect 和模板的非背景像素数 A_tmpl。缩放因子 k = sqrt(A_rect / A_tmpl)（由生成约束保证为整数）。
5. 将 2x2 模板中的每个像素放大为 k x k 的块，得到 2k x 2k 的放大模板。将放大模板中的黄(4)替换为该组标记的颜色。
6. 将放大后的模板印入目标子矩形，对齐子矩形的左上角。模板中黑(0)像素对应的位置保留灰(5)。
7. 各组按标记颜色的编号从小到大依次处理；实际上各组子矩形不重叠，顺序不影响结果。

**关键洞察**：标记的角色从源题中的"定位后直接重涂色"扩展为"定位后提取几何参数（面积）来驱动另一个操作（缩放印章）"——矩形不是被填色的目标，而是承载缩放信息的容器。

## 新题 5：投射物落点驱动模板印章与碰撞旋转

**组合逻辑**：[射线延伸/projectile_fire](已有) → [印章覆盖/stamp](创新：投射物落点作为印章锚点而非着色点) + [旋转/rotate](创新：双投射物碰撞触发印章旋转而非简单变色)

**来源原语**：射线延伸/projectile_fire、三角精灵体/triangle_sprite、朝向编码方向/orientation_encodes_direction、碰撞变色规则/collision_recolor_rule（参考题 409aa875）；印章覆盖/stamp、模板/template（参考题 447fd412）；旋转/rotate（参考题 2013d3e2）

**依赖链**：三角体朝向→投射方向→落点位置→印章锚点。碰撞检测（两个投射物落在同一像素）改变印章的旋转状态。印章放置顺序影响重叠处理。三个操作层层依赖，任一缺失都无法确定最终输出。

三角精灵体发射投射物，每个落点位置印上模板图案；若两个投射物落在同一位置，改为印上旋转 180 度的模板。

**输入结构**：约 20x20 的黑(0)背景网格。网格中有 3~5 个由 3 像素组成的三角精灵体，颜色为蓝(1)，形状为轴对齐的 L 形（占据一个 2x2 区域的 3 个像素，缺失一角）。网格右下角（与所有三角体不重叠的区域）有一个 3x3 的模板图案，由红(2)像素组成非全填充的连通图形（3~6 个红像素，其余为黑(0)）。三角体之间距离足够大，使得投射物落点不会落在其他三角体上。生成约束：恰好有 1~2 对投射物落在同一像素（碰撞），其余落点互不重合且不与三角体重叠。

**规则**：
1. 对每个三角精灵体，根据其 L 形缺失角的位置确定发射方向：投射物从缺失角的对角像素（即 L 的"顶点"）出发，沿缺失角的反方向发射，落点为距顶点 5 个像素处（曼哈顿距离沿发射方向的直线距离）。
2. 记录所有落点。标记碰撞点（两个投射物落在同一像素的位置）和普通落点（仅一个投射物）。
3. 在每个普通落点，以落点为模板边界框的中心（若模板边界框为奇数尺寸则精确居中，偶数尺寸则偏左上），绘制模板图案的原始朝向副本，颜色保持红(2)。
4. 在每个碰撞点，以碰撞点为中心，绘制模板图案旋转 180 度后的副本，颜色改为绿(3)。
5. 印章绘制顺序：先绘制所有普通落点的印章（按落点行号从小到大、同行列号从小到大），再绘制碰撞点的印章。后绘制的印章的非背景像素覆盖先绘制的。
6. 模板图案在右下角的原始位置保留不变。三角精灵体保留不变。印章超出网格边界的部分裁掉。

**关键洞察**：投射物在源题中仅产生单像素着色效果，这里投射物的落点升级为复杂图案的锚定位置，碰撞不再是简单变色而是触发几何变换（旋转），使得投射物物理学与图案印章之间产生源题中不存在的结构耦合。

## 新题 6：等分变色匹配条件的面板叠加

**组合逻辑**：[等分/equal_split + 重涂色/recolor](创新：分割产生的颜色模式作为叠加条件而非最终输出) → [透明叠加/transparent_overlay](创新：逐像素颜色匹配决定叠加而非整体重叠检测)

**来源原语**：等分/equal_split、重涂色/recolor、竖直条/vertical_bar、下半变色/lower_half_recolored（参考题 ce9e57f2）；透明叠加/transparent_overlay、面板/panel、分隔列/separator_column、面板对应/panel_correspondence、无重叠时叠加/overlay_no_overlap（参考题 bbb1b8b6）

**依赖链**：等分变色产生上下两色的模式→左右面板在同一位置的变色结果是否匹配，决定该位置是否执行叠加。两个操作深度交织：不做等分就无法判断匹配，不判断匹配就无法确定叠加区域。

左右面板各含竖直色条；先对每根色条做上下等分变色，再根据变色后左右面板对应位置的颜色是否一致来决定是否将右面板叠加到左面板。

**输入结构**：约 12x25 的黑(0)背景网格（高 12，宽 25）。中间一列为灰(5)分隔列，将网格分为左右两个 12x12 面板。每个面板中有 3~5 根宽 1 像素的竖直色条（4-连通垂直连续段，高度 4~10 像素），左面板色条颜色为红(2)，右面板色条颜色为蓝(1)。两面板中色条的列位置可能不同，部分列两侧都有色条，部分列仅一侧有。生成约束：至少有 2 列是两侧都有色条的（"配对列"），且配对列中至少有一列两侧色条高度相同、至少有一列两侧色条高度不同。

**规则**：
1. 对左面板的每根红(2)竖直色条，保留其上半 ceil(height/2) 像素为红(2)，将下半 floor(height/2) 像素重涂为黄(4)。
2. 对右面板的每根蓝(1)竖直色条，保留其上半 ceil(height/2) 像素为蓝(1)，将下半 floor(height/2) 像素重涂为黄(4)。
3. 以左面板作为输出画布。对右面板中的每个非黑像素位置 (r, c_right)，找到其在左面板中的对应位置 (r, c_left)（即 c_left = c_right）：
   - 若左面板该位置为黑(0)（空位），且右面板变色后该位置的颜色为黄(4)，则将右面板该像素的颜色（黄(4)）复制到左面板对应位置。
   - 若左面板该位置为黑(0)（空位），且右面板变色后该位置的颜色不是黄(4)（即仍为蓝(1)），则不复制。
   - 若左面板该位置非黑（已有颜色），则不复制。
4. 删除分隔列，输出仅为处理后的左面板（12x12）。

**关键洞察**：等分变色在源题中是最终变换，这里它变成一个中间信号发生器——变色产生的黄(4)像素是两面板之间的"握手协议"，只有两侧色条在下半部分重合的位置才能叠加，而等高的配对色条产生完全匹配的黄色段，不等高的则只有部分匹配。

1. 找到上边界的所有灰(5)标记像素，按列号从小到大排序，记为标记序列 M_0, M_1, ..., M_{n-1}。

5. 输出网格中不包含标记像素和原始前景区域的位置信息，仅保留颜色和面积。

**关键洞察**：标记在源题中控制邻近微型片段的排列顺序，这里标记的角色扩展为远程选取器——通过射线从边界跨越网格选中目标区域，并且标记沿边界的排列顺序编码了输出中的行顺序，使得空间位置信息被重新映射为输出的结构维度。

## 新题 8：旋转拼贴分解后原型互换再拼合

**组合逻辑**：[旋转/rotate + 裁剪/crop](已有：提取源瓦片) → [替换/replace](创新：对提取出的瓦片做原型互换) → [旋转/rotate](创新：用互换后的瓦片重建旋转拼贴)；整体形成分解-变换-重组的环形结构

**来源原语**：旋转/rotate、裁剪/crop、象限/quadrant、旋转对称/rotational_symmetry、提取原始瓦片/extract_source_tile（参考题 2013d3e2）；替换/replace、原型精灵/prototype_sprite、原型配对/prototype_pairing、互换原型/toggle_to_alternate_prototype（参考题 c7f57c3e）

**依赖链**：必须先分解旋转拼贴才能得到源瓦片→必须识别源瓦片属于哪个原型才能互换→必须将互换后的瓦片重新旋转 3 次才能重建拼贴。分解和重组共享旋转操作但方向相反，形成逻辑环路。

每个旋转拼贴由源瓦片及其三个旋转副本构成；提取源瓦片，将其互换为另一种原型图案，再用互换后的瓦片及其旋转副本重建拼贴。

**输入结构**：约 20x20 的黑(0)背景网格。网格中有 2~3 个互不重叠的旋转拼贴体，每个拼贴体占据一个偶数边长的正方形区域（如 6x6 或 8x8），分为四个等大象限。每个拼贴体的左上象限是"源瓦片"，右上象限是源瓦片顺时针旋转 90 度，左下象限是逆时针旋转 90 度，右下象限是旋转 180 度。所有拼贴体的源瓦片形状属于两种"原型"之一：原型 A 的像素颜色为红(2)，原型 B 的像素颜色为蓝(1)。两种原型的掩码形状不同（同尺寸但非背景像素位置不同），每种原型至少出现一次。生成约束：两种原型的像素数相同（保证互换后面积不变）；同一网格中同种原型的拼贴体边长可以不同（但瓦片掩码按比例一致，即均为同一基础掩码的整数倍缩放）。

**规则**：
1. 识别网格中所有旋转拼贴体（正方形区域，四个象限满足旋转关系）。
2. 对每个拼贴体，提取左上象限作为源瓦片。
3. 确定源瓦片属于原型 A（红(2)）还是原型 B（蓝(1)），基于其颜色判断。
4. 将源瓦片互换为另一种原型：
   - 若原为原型 A（红(2)），将瓦片的非背景像素位置替换为原型 B 的掩码形状，颜色改为蓝(1)。
   - 若原为原型 B（蓝(1)），将瓦片的非背景像素位置替换为原型 A 的掩码形状，颜色改为红(2)。
   - 原型掩码形状从该网格中最小边长的同类拼贴体的源瓦片获取基础模板，若目标拼贴体更大则等比缩放。
5. 用互换后的源瓦片重建四象限旋转拼贴：左上放互换瓦片，右上放顺时针 90 度旋转，左下放逆时针 90 度旋转，右下放 180 度旋转。
6. 将重建后的拼贴体写回原位置。背景像素保持不变。

**关键洞察**：源题中旋转分解是终点操作（提取后输出），原型互换是独立操作（就地替换）；这里两者形成分解-互换-重组的闭合回路，旋转既是分析工具（分解）也是合成工具（重建），同一操作在推理链中承担了对称的双重角色。

## 新题 9：绕行代价索引色彩图例

**组合逻辑**：[路径绘制/path_drawing + 绕行/detour](已有) → [计数/counting](创新：计量绕行的额外路径长度) → [解码/decode + 图例映射/legend_mapping](创新：绕行代价作为图例索引而非空间位置)

**来源原语**：路径绘制/path_drawing、绕行/detour、边界标记/border_marker、障碍条/obstacle_bar、阻挡/blocking、障碍色决定绕行/obstacle_color_detour（参考题 96a8c0cd）；计数/counting（参考题 dce56571）；解码/decode、色彩图例/color_legend、图例映射/legend_mapping（参考题 1be83260）

**依赖链**：路径遇到障碍→绕行方向由障碍颜色决定→绕行路径长度减去直行路径长度得到"代价"→代价值索引色彩图例→索引到的颜色用于绘制该段绕行路径。三个逻辑（路由、计量、着色）链式耦合且每步信息不可跳过。

从边界标记出发绘制路径，遇到障碍按颜色方向绕行；每段绕行的额外路径长度作为索引值，从色彩图例中查出对应颜色来绘制该段绕行。

**输入结构**：约 18x15 的黑(0)背景网格。上边界有一个红(2)标记像素，指示路径从上向下行进。网格内有 2~4 根水平障碍条（宽 3~7 像素、高 1 像素），颜色为蓝(1)或绿(3)，与路径行进方向垂直。网格底部边界有一行色彩图例：从左起第 0 列到第 k 列（k >= 最大可能绕行代价），每列一个不同颜色的像素，颜色选自黄(4)、品红(6)、橙(7)、青(8)、栗(9)，其余为黑(0)。生成约束：路径直行轨迹恰好会被每根障碍条阻挡（障碍条覆盖路径所在列）；障碍条与路径起点列之间有足够空间绕行；底部图例行不被路径覆盖（路径在到达图例行之前停止或图例行是网格最后一行且路径止于倒数第二行）。

**规则**：
1. 路径从上边界红(2)标记向下直行。
2. 当路径前方遇到障碍条时：
   - 蓝(1)障碍条：路径先向左移 1 列，再向下穿过障碍条所在行，再向右移 1 列回到原列，继续向下。
   - 绿(3)障碍条：路径先向右移 1 列，再向下穿过障碍条所在行，再向左移 1 列回到原列，继续向下。
3. 计算每次绕行的代价：绕行实际路径像素数 - 若直行通过该段的像素数。（直行通过 1 行只需 1 像素，绕行需要 1+1+1+1=4 像素走"门"字形，但障碍条宽度可能影响实际绕行路线。具体地：绕行路径 = 左/右移 1 步 + 向下走 1 步越过障碍行 + 右/左移 1 步回原列 = 共 3 步，而直行越过同一行仅 1 步，代价 = 3 - 1 = 2。若障碍条端点恰好阻挡了偏移列，路径需再多偏移 1 列，代价相应增大。）精确计算：绕行代价 = 绕行路径总步数 - 绕行起点行到绕行终点行的垂直距离。
4. 用绕行代价 d 作为索引（从 0 开始），查找底部图例行第 d 列的颜色。将该段绕行路径（非直行的那些像素）涂为该图例颜色。
5. 路径的直行段（未遇障碍的部分）保持红(2)。
6. 障碍条、图例行、背景保持不变。
7. 路径在到达图例行上方一行时停止（不覆盖图例行）。

**关键洞察**：绕行在源题中是纯几何操作（路径偏移后恢复），这里绕行的几何代价被赋予语义——它成为色彩图例的查找键，使得路径的局部几何形变量化为离散索引，从而将路径绘制与色彩解码耦合在一起。

## 新题 10：缩放因子调制偏移复制距离

**组合逻辑**：[缩放/scale](已有：识别精灵体的缩放因子) → [偏移复制/offset_copy](创新：偏移距离按缩放因子等比放大而非固定) + [路径需通畅/path_clearance](已有条件的新应用场景)

**来源原语**：偏移复制/offset_copy、阴影像素/shadow_pixel、路径需通畅/path_clearance（参考题 35ab12c3）；缩放/scale、原型精灵/prototype_sprite、锚点区域/anchor_region、缩放对应/scale_correspond（参考题 c7f57c3e）；忽略干扰项/ignore_distractors（参考题 72ca375d、3d588dc9）

**依赖链**：先识别每个精灵体的缩放因子→缩放因子决定阴影偏移的放大倍率→偏移路径上若有其他精灵体遮挡则裁剪阴影。缩放因子同时影响偏移距离和阴影尺寸，偏移路径通畅性又依赖所有精灵体的全局布局，形成局部参数与全局约束的交织。

网格中有同一原型的多个不同缩放实例，每个实例的锚点旁有阴影像素；将阴影偏移复制到精灵体边缘，偏移距离按该实例的缩放因子等比放大。

**输入结构**：约 25x25 的黑(0)背景网格。网格中有 3~4 个同一原型精灵体的不同缩放实例。原型为一个不规则的 4-连通单色掩码（基础尺寸约 3x3，4~6 像素），颜色为红(2)。缩放实例的缩放因子分别为 k=1, 2, 3（即 3x3, 6x6, 9x9 的边界框，每个基础像素放大为 kxk 块）。每个实例的锚点（边界框左上角像素）的右侧和/或下侧紧邻 1~2 个蓝(1)阴影像素（与锚点 4-连通相邻，位于精灵体边界框外）。网格中还有若干灰(5)单像素干扰点，散布在精灵体之间。生成约束：不同缩放实例之间至少间隔 2 像素（留出阴影扩展空间）；最大缩放实例的扩展阴影不超出网格边界。

**规则**：
1. 识别所有红(2) 4-连通区域作为精灵体实例。根据各实例边界框面积与最小实例边界框面积之比，计算每个实例的缩放因子 k（取平方根并四舍五入为整数）。
2. 对最小实例（k=1），找到其锚点（边界框左上角）的蓝(1)阴影像素，记录每个阴影像素相对于锚点的偏移向量 (dr, dc)。
3. 对每个实例（包括 k=1），将偏移向量放大为 (k*dr, k*dc)。
4. 沿精灵体边界框的对应边（阴影所在方向），从锚点对应位置出发，以放大后的偏移向量为步长，逐步复制阴影：在每个步长位置绘制一个 kxk 的蓝(1)块（与精灵体像素放大比例一致）。
5. 复制的阴影块若与任何红(2)精灵体像素或灰(5)干扰点重叠，则该阴影块整体不绘制（路径被遮挡，停止该方向的进一步复制）。
6. 已绘制的蓝(1)阴影块不阻挡其他实例的阴影路径。
7. 灰(5)干扰点保持不变，红(2)精灵体保持不变。
8. 各实例按缩放因子从小到大依次处理。

**关键洞察**：偏移复制在源题中以固定步长沿轮廓传播，这里步长本身成为缩放因子的函数——同一组阴影偏移在不同缩放实例上产生不同的传播距离，缩放因子从描述精灵体外观的属性转变为控制阴影动力学的参数。
