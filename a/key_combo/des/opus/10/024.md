## 新题 1：框选广播

**组合逻辑**：[enclosure/object_with_hole_selected](检测哪个单元格的精灵被空心框包围) → [stamp_overlay/same_parity_receive_copy](将被选精灵按局部偏移印入同奇偶空单元格) + [erase](擦除选择框)

**来源原语**：enclosure、hollow_rectangle、enclosed_region、object_with_hole_selected（b9b7f026）；stamp_overlay、cell_array、same_parity_receive_copy、open_cell（92e50de0）；erase（a416fc5b）；separated_tile_lattice、separator_line（cbded52d）

**依赖链**：空心框的存在同时决定了两件事——哪个精灵是广播源（框选逻辑），以及哪些单元格是广播目标（框所在单元格的奇偶性）。擦除框后框选信息消失，所以必须在擦除前完成源识别和奇偶判定。三个操作通过框这一共享结构紧耦合。

在分隔线格阵中，找到被空心框包围的那个精灵，将其印入所有同奇偶空单元格，然后擦除选择框。

**输入结构**：一个约 17x17 的网格，灰(5) 色全宽水平线和全高垂直线将其分为 4x4 共 16 个大小相等的 3x3 开放单元格。单元格内底色为黑(0)。其中 3-4 个单元格内各有一个蓝(1) 色小精灵（4-连通单色图形，3~5 像素，各单元格内精灵形状可不同但占据相同的局部偏移模式——即像素相对于单元格左上角的偏移集合相同）。恰好一个含精灵的单元格外围额外有一圈红(2) 色空心矩形框，完全包裹该精灵（框的内边界与精灵之间可有 0~1 像素间隙，框本身不覆盖分隔线）。其余单元格为空（仅含黑(0)底色）。生成约束：含精灵的单元格互不相邻（在单元格坐标系中曼哈顿距离 >= 2）；被框选的精灵与其他精灵形状相同（同一局部偏移集合）。

**规则**：
1. 找到所有被灰(5) 分隔线划分的开放单元格。
2. 在所有含蓝(1) 精灵的单元格中，找出唯一一个其精灵被红(2) 空心矩形框完全包围的单元格（记为源单元格 S）。判定方法：该单元格内存在一组红(2) 像素构成完整矩形边框，其内部包含蓝(1) 精灵且精灵不触碰红框边界。
3. 记录 S 内蓝(1) 精灵的像素相对于 S 左上角的偏移集合。记录 S 的单元格行列索引 (r, c)，计算奇偶类 P = (r + c) mod 2。
4. 对所有空单元格（不含任何非黑像素的单元格），若其行列索引满足 (r' + c') mod 2 = P，则将精灵偏移集合中的每个像素以该单元格左上角为锚点写入蓝(1)；若偏移位置超出单元格边界则舍弃该像素。
5. 将 S 中的红(2) 框像素替换为黑(0)（擦除选择框），S 内蓝(1) 精灵保持不变。
6. 已有精灵的非源单元格保持不变。

**关键洞察**：红色框既不出现在输出中，也不是装饰——它同时编码了"选谁"和"发往哪里"（通过自身所在单元格的奇偶性），是一个一次性使用后擦除的控制信号。

## 新题 2：旋转条揭示重叠

**组合逻辑**：[rotate/orient_swap_keep](将所有条旋转 90 度) → [logical_AND/pixel_align](检测旋转后两色条的逐像素重叠) + [recolor_by_origin](按来源颜色三分涂色)

**来源原语**：rotate、thin_bar、center_fixed、orient_swap_keep（f0f8a26d）；logical_AND、bitmask、pixel_align、both_mask_overlap（0520fde7）；recolor_by_origin（bcb3040b）

**依赖链**：旋转改变了每种颜色的占据像素集合，重叠检测只对旋转后的状态有意义（原始状态中蓝条全部水平、红条全部垂直，它们的交叉模式完全不同于旋转后的交叉模式）。三分涂色规则又依赖重叠检测的结果。删除旋转步骤，重叠检测的输入错误；删除重叠检测，无法区分三种颜色。

将水平蓝条和垂直红条各自旋转 90 度，然后按旋转后的重叠情况进行三色涂色。

**输入结构**：一个约 13x13 的网格，黑(0) 背景。网格上有若干蓝(1) 色单像素宽条和红(2) 色单像素宽条。所有蓝(1) 条均为水平方向，所有红(2) 条均为垂直方向。每根条长度为奇数（3~9 像素）。条之间互不重叠、互不相邻（任意两条的像素集合在 8-连通意义下不接触）。条的数量：蓝(1) 条 3~5 根，红(2) 条 3~5 根。生成约束：旋转后至少存在一对蓝条与红条在某像素重叠（即某根蓝条的中心行与某根红条的中心列的交点，在两者旋转后的覆盖范围内）。

**规则**：
1. 识别所有蓝(1) 水平条和红(2) 垂直条。对每根条，记录其中心像素坐标和长度。
2. 将每根条绕其中心像素旋转 90 度：水平变垂直，垂直变水平，长度和中心位置不变。
3. 清空网格为全黑(0)。
4. 绘制所有旋转后的条。对每个像素位置：
   - 若仅被旋转后的蓝条覆盖 → 蓝(1)。
   - 若仅被旋转后的红条覆盖 → 红(2)。
   - 若同时被旋转后的蓝条和红条覆盖 → 绿(3)。
   - 若不被任何条覆盖 → 黑(0)。
5. 超出网格边界的部分舍弃。

**关键洞察**：输入中蓝条全部水平、红条全部垂直，看起来互相垂直但几乎不交叉；旋转后蓝条变为垂直、红条变为水平，产生了全新的交叉结构。绿色像素只在旋转后的世界中才能被推导出来。

## 新题 3：十字射线划定象限，角标图例涂色

**组合逻辑**：[ray_extend/cross_pattern](从两个标记像素射出十字线) + [row_col_intersection/intersection_colored](标记交叉点) → [quadrant_member](十字线将网格分为四象限) → [corner_sets_quadrant/recolor](按角标图例重涂每个象限内的精灵)

**来源原语**：ray_extend、cross_pattern、row_col_intersection、intersection_colored、isolated_pixel（23581191）；quadrant、corner_pixel、quadrant_member、corner_sets_quadrant、frame、recolor（77fdfe62）

**依赖链**：十字线的位置由标记像素决定，象限边界由十字线决定，精灵涂色由象限归属和角标图例共同决定。十字线同时是可见的输出标记和不可见的象限分界线——删掉十字线绘制则象限边界不存在；删掉角标图例则涂色无据。

从两个标记像素画出完整十字线并标记交叉点，然后按角标颜色图例重涂各象限内的散落精灵。

**输入结构**：一个约 15x15 的网格，黑(0) 背景。两个孤立像素：一个橙(7)，一个青(8)，不在同行也不在同列。网格的四个角各有一个单像素色标：左上角 = 蓝(1)，右上角 = 红(2)，左下角 = 绿(3)，右下角 = 黄(4)。另有 4~6 个灰(5) 色小精灵（4-连通单色图形，3~6 像素）散落在网格内部，互不接触，不触碰网格边缘，也不与橙/青像素所在的行或列重合。生成约束：每个象限（由橙、青像素的行列确定）内至少有一个灰色精灵。

**规则**：
1. 找到橙(7) 像素坐标 (r1, c1) 和青(8) 像素坐标 (r2, c2)。
2. 将橙(7) 像素所在的整行和整列全部涂为橙(7)（覆盖黑色和灰色像素，但不覆盖角标像素和青(8) 像素）。
3. 将青(8) 像素所在的整行和整列全部涂为青(8)（覆盖黑色和灰色像素，但不覆盖角标像素和橙(7) 像素及已涂橙的像素）。
4. 橙行与青列的交叉点 (r1, c2)、青行与橙列的交叉点 (r2, c1) 涂为品红(6)。
5. 十字线将网格内部划分为四个象限：以 (r1, c1) 和 (r2, c2) 的行列为边界——左上象限（行 < min(r1,r2) 且列 < min(c1,c2)）、右上象限（行 < min(r1,r2) 且列 > max(c1,c2)）、左下象限（行 > max(r1,r2) 且列 < min(c1,c2)）、右下象限（行 > max(r1,r2) 且列 > max(c1,c2)）。
6. 对于每个灰(5) 精灵，判定其所有像素所在的象限（生成约束保证每个精灵完全位于某一象限内），将该精灵重涂为对应角标颜色：左上象限 → 蓝(1)，右上象限 → 红(2)，左下象限 → 绿(3)，右下象限 → 黄(4)。
7. 位于十字线之间的夹缝区域（行介于两标记行之间、或列介于两标记列之间）的灰(5) 像素保持不变（生成约束保证精灵不出现在此区域）。

**关键洞察**：十字线既是输出中的可见结构，又隐式定义了四象限的涂色区域。角标不是装饰而是按空间位置索引的颜色查找表。精灵被十字线覆盖的像素消失在线条中，所以精灵必须完全位于象限内部才能被正确涂色。

## 新题 4：嵌套框深度驱动旋转

**组合逻辑**：[enclosure](检测同心嵌套框的层数) → [rotate/rotation_relation](层数决定旋转角度) + [recolor](最外层框色转移给精灵) + [crop/ordering](裁剪并按空间位置排列输出)

**来源原语**：enclosure、hollow_rectangle、enclosed_region、object_with_hole_selected（b9b7f026）；rotate、rotation_relation（a416fc5b, fc7cae8d）；recolor（多题）；crop（多题）；ordering（1bfc4729）

**依赖链**：嵌套框的拓扑结构（层数）编码旋转参数——不检测嵌套关系就无法确定旋转量。最外层框的颜色决定输出精灵的颜色——不识别最外层就无法涂色。各组在网格中的水平位置决定输出排列顺序。三个独立信息（层数、外框色、水平位置）必须从同一嵌套结构中同时提取。

统计同心嵌套框层数以确定精灵旋转角度，用最外层框色重涂精灵，按各组水平位置排列裁剪结果。

**输入结构**：一个约 20x20 的网格，黑(0) 背景。网格上有 3 组互不相邻的嵌套结构。每组由若干同心空心矩形框组成，框与框之间有 1 像素间隔。同一组内所有框使用同一种非黑颜色（不同组使用不同颜色，从蓝(1)、红(2)、绿(3)、黄(4) 中选取）。三组的嵌套层数分别为 1、2、3（顺序随机）。每组最内层框的内部放置一个灰(5) 色小精灵（4-连通单色图形，4~6 像素，非旋转对称——即 90 度旋转后与原图不同）。三组精灵形状相同（同一偏移集合）。生成约束：三组在水平方向上互不重叠（边界框的列范围不交叉）。

**规则**：
1. 识别所有非黑、非灰的 4-连通单色对象，按颜色分组。每组的多个同色空心矩形框构成一组同心嵌套结构。
2. 对每组嵌套结构，计算嵌套层数 D（空心框的个数）。
3. 提取最内层框内部的灰(5) 精灵，记录其像素相对于精灵边界框左上角的偏移。
4. 将精灵绕其边界框中心顺时针旋转 90° x D。具体地：D=1 旋转 90°，D=2 旋转 180°，D=3 旋转 270°。
5. 将旋转后的精灵重涂为该组框的颜色（即最外层框的颜色）。
6. 裁剪旋转后精灵的紧致边界框。
7. 将三组裁剪结果从左到右排列（按各组嵌套结构在输入中边界框最左列的从小到大顺序），相邻裁剪结果之间插入一列黑(0) 像素作为间隔。

**关键洞察**：嵌套层数不是选择标准（所有组都被处理），而是编码旋转参数的空间密码——框的层数越多旋转角度越大。精灵形状相同但旋转不同，迫使求解者从嵌套拓扑推断变换参数而非死记输出形状。

## 新题 5：压缩去重揭示隐藏框，裁剪框内内容

**组合逻辑**：[compress/merge_identical_row_col](合并重复行列还原压缩前的网格) → [enclosure/hollow_rectangle](在压缩后的网格中识别空心矩形框) → [crop](裁剪框内区域) + [erase](将框色像素替换为背景)

**来源原语**：compress、deduplicate、merge_identical_row_col、adjacent_repeat（e1baa8a4）；enclosure、hollow_rectangle、enclosed_region、object_with_hole_selected（b9b7f026）；crop（多题）；erase（a416fc5b）

**依赖链**：拉伸后的网格中，框的行列比例被扭曲，空心矩形不再是视觉上的矩形（某些行/列被重复了不同次数）。必须先压缩才能恢复矩形几何，才能检测空心框。压缩后的框位置决定裁剪区域，框的颜色决定哪些像素需要擦除。若跳过压缩，框不可识别；若跳过框检测，裁剪范围不确定。

先压缩拉伸过的网格以还原空心矩形框的几何结构，再裁剪框内内容并擦除框色。

**输入结构**：一个约 14x18 的网格，无明显背景色（整个网格被颜色填满）。网格是一个较小网格（约 7x9）经行列不均匀拉伸得到的——每行被重复 1~3 次，每列被重复 1~3 次，且不同行/列的重复次数可能不同。在压缩还原后的 7x9 网格中：大部分像素使用 3~4 种颜色构成马赛克状图案；恰好一种颜色（红(2)）的像素构成一个完整的空心矩形框——框的边界框的四条边上所有像素均为红(2)，框内部像素为其他颜色且不含红(2)。框外也可能存在零星红(2) 像素（干扰项），但这些像素不构成完整的矩形边框。生成约束：压缩后的网格中只有一个颜色能构成完整空心矩形框。

**规则**：
1. 对输入网格执行行列压缩：逐行扫描，将每个最大相同相邻行组合并为一行；逐列扫描，将每个最大相同相邻列组合并为一列。得到压缩网格。
2. 在压缩网格中，对每种颜色检查其像素是否构成完整空心矩形框：找到该颜色的边界框，检查边界框四条边上是否全为该颜色，且边界框内部是否不含该颜色。找到唯一满足条件的颜色（红(2)）及其框。
3. 裁剪框内部区域（不包含框边界本身）。
4. 在裁剪结果中，将所有红(2) 像素替换为黑(0)（擦除干扰项——若框内碰巧有与框同色的像素，也一并清除）。
5. 输出裁剪并擦除后的子网格。

**关键洞察**：空心矩形框在拉伸状态下因行列重复次数不同而变成了"胖瘦不均"的形状，肉眼难以识别为矩形。压缩是恢复几何规律性的必要前置步骤——这是源题中"压缩"和"框检测"各自独立的用法在新结构下的融合。

## 新题 6：格阵内标记连线与局部色交换

**组合逻辑**：[same_row_col_align/local_offset_preserved](在瓦片坐标系中识别同色标记对齐关系) → [connect/draw_line](沿瓦片行/列连线，保持局部偏移) + [two_color_swap](双色路径交叉的瓦片内执行色互换)

**来源原语**：same_row_col_align、local_offset_preserved、separated_tile_lattice、marker_pixel（cbded52d）；connect、draw_line、straight_two_point（bcb3040b）；two_color_swap（b94a9452）

**依赖链**：连线在瓦片坐标系中执行（不是逐像素直线），且保持标记的局部偏移——这决定了路径经过哪些像素。双色路径是否在同一瓦片交叉取决于连线结果，而色交换只在交叉瓦片中发生。连线逻辑产生路径，路径的空间关系触发条件性色交换——两者通过瓦片结构紧密耦合。

在分隔线格阵中，沿瓦片行列连接同色标记对，在两色路径交叉的瓦片中互换两种标记色。

**输入结构**：一个约 15x15 的网格，灰(5) 色全宽水平线和全高垂直线将其分为 4x4 共 16 个等大 3x3 瓦片。每个瓦片有统一的底色黄(4)。部分瓦片内有一个标记像素，标记像素位于瓦片内的特定局部偏移位置（相对于瓦片左上角的行列偏移）。标记分两色：蓝(1) 和红(2)。每种颜色恰好出现 2 个标记。同色的两个标记满足以下条件之一：处于同一瓦片行（瓦片行索引相同），或处于同一瓦片列（瓦片列索引相同）。同色标记对的局部偏移相同（在各自瓦片内占据相同的相对位置）。不同色标记对的局部偏移可以不同。生成约束：蓝色连线路径和红色连线路径至少在一个瓦片中交叉（即至少有一个瓦片同时被两条路径经过）。

**规则**：
1. 识别灰(5) 分隔线，划分出 4x4 瓦片阵列。
2. 对蓝(1) 标记对：找到两个蓝标记所在的瓦片坐标和局部偏移。沿瓦片行或瓦片列（取决于对齐方向）遍历两标记之间的所有瓦片（含端点），在每个路径瓦片的相同局部偏移位置涂蓝(1)（覆盖原底色）。
3. 对红(2) 标记对：同上处理，在每个路径瓦片的相同局部偏移位置涂红(2)。
4. 连线完成后，检查是否有瓦片同时被蓝色路径和红色路径经过（即同一瓦片内存在蓝(1) 路径像素和红(2) 路径像素）。在这些交叉瓦片中，将蓝(1) 像素改为红(2)，将红(2) 像素改为蓝(1)（双色互换）。
5. 非路径瓦片保持原样。

**关键洞察**：连线在瓦片坐标而非像素坐标中进行，路径的"交叉"也在瓦片粒度判断——两条路径经过同一瓦片即视为交叉，即使它们在瓦片内的实际像素位置不同。交叉触发的是整个瓦片内两色互换，而非单个像素操作。

## 新题 7：行列交叉构建印章模板，奇偶广播

**组合逻辑**：[column_selection + row_col_intersection](蓝色标记选列、红色标记选行，交叉点标记为第三色) → [stamp_overlay/same_parity_receive_copy](将构建的模板印入同奇偶空单元格)

**来源原语**：column_selection、fg_col_full_recolor（f5b8619d）；row_col_intersection、intersection_colored（23581191）；stamp_overlay、same_parity_receive_copy、cell_array、open_cell、separator_line（92e50de0）；local_offset_preserved（cbded52d）

**依赖链**：蓝色和红色标记分别选择列和行，两者的交叉产生第三色——模板的结构同时取决于两种标记的空间位置。模板只在种子单元格内生成，然后按种子单元格的奇偶性广播到其他空单元格。列选择、行选择、交叉着色三个逻辑汇聚成模板，模板再通过奇偶广播扩散——是一个多源汇聚+扇出的拓扑结构。

在格阵的种子单元格中，蓝色标记选定列、红色标记选定行，交叉点着黄色，构成印章模板，广播到同奇偶空单元格。

**输入结构**：一个约 19x19 的网格，灰(5) 色全宽分隔线将其分为 3x3 共 9 个等大 5x5 单元格。所有单元格底色为黑(0)。恰好一个单元格（种子单元格）内包含若干蓝(1) 像素和若干红(2) 像素。蓝(1) 像素分布在种子单元格的 1~3 个不同局部列中，红(2) 像素分布在种子单元格的 1~2 个不同局部行中。同一局部列内的蓝色像素可在不同行，同一局部行内的红色像素可在不同列。其余 8 个单元格均为空。生成约束：蓝色标记列和红色标记行至少有一个交叉点（即至少存在一个像素位置同时在某蓝色列和某红色行上）；该交叉位置在输入中为黑(0)（非蓝也非红）。

**规则**：
1. 识别灰(5) 分隔线，划分出 3x3 单元格阵列。
2. 找到包含非黑像素的种子单元格 S，记录其单元格索引 (rs, cs)。
3. 在 S 内，标记所有包含蓝(1) 像素的局部列集合 C_blue，和所有包含红(2) 像素的局部行集合 R_red。
4. 构建印章模板（5x5 网格）：
   - 位于 R_red 中某行且 C_blue 中某列的交叉位置 → 黄(4)。
   - 位于 C_blue 中某列但不在 R_red 中任何行 → 蓝(1)。
   - 位于 R_red 中某行但不在 C_blue 中任何列 → 红(2)。
   - 其余位置 → 黑(0)。
5. 计算种子单元格的奇偶类 P = (rs + cs) mod 2。
6. 对所有空单元格（不含任何非黑像素），若其单元格索引 (r', c') 满足 (r' + c') mod 2 = P，则将印章模板写入该单元格。
7. 种子单元格本身的内容替换为印章模板（蓝/红标记像素被模板覆盖）。

**关键洞察**：蓝色和红色标记不是输出的一部分——它们是构建指令，定义了哪些列/行被"激活"。黄色只出现在两者都被激活的交叉点，形成逻辑 AND 的视觉表达。印章模板是从两组标记推导出的派生结构，而非输入中直接可见的图案。

## 新题 8：引导边定向旋转后像素放大

**组合逻辑**：[guide_edge/color_match_orientation](引导边颜色与边框控制匹配，确定旋转/镜像方式) → [rotate + reflect](对精灵执行二面体变换) → [crop](裁剪掉引导边) → [pixel_scaling](将裁剪结果放大)

**来源原语**：guide_edge、frame_control、color_match_orientation（fc7cae8d）；rotate、reflect（fc7cae8d, f560132c）；crop（多题）；pixel_scaling、foreground_shape、bounding_box、scale_with_gaps（f25fbde4）

**依赖链**：引导边的颜色匹配决定旋转/镜像方式——不检测引导边就无法确定正确的变换。变换后必须裁剪掉引导边才能得到纯净的精灵内容。裁剪结果再被像素放大——放大尺度取决于裁剪后精灵的尺寸。引导边→变换→裁剪→放大构成严格的信息依赖链，且引导边同时编码了变换方向和裁剪位置（引导边在哪一侧决定从哪一侧裁掉）。

按引导边与边框控制的颜色匹配关系旋转/镜像中央精灵，裁剪引导边后将结果放大两倍。

**输入结构**：一个约 12x12 的网格，黑(0) 背景。网格的四条边中，恰好有两条相邻边（如上边和右边、左边和下边等）由两种不同的纯色填满——例如上边全部为蓝(1)，右边全部为红(2)（角落像素归属于先扫描到的边）。网格中央有一个矩形色块（约 4x5 或 5x4），使用绿(3) 填充内部。该色块的某两条相邻边（各 1 像素宽）分别涂有蓝(1) 和红(2)——这两条是引导边，其颜色与网格边框的两种颜色一一对应。引导边的朝向可能与边框控制不一致（例如蓝色引导边在色块左侧，但蓝色边框控制在网格上方）。生成约束：恰好存在一种二面体变换（旋转 0°/90°/180°/270° 可选配水平/垂直镜像）使得变换后引导边朝向与边框控制朝向一致。

**规则**：
1. 识别网格边框上两种非黑颜色及其所在边（上/下/左/右）。
2. 识别中央矩形色块及其两条引导边（1 像素宽、颜色为边框控制色之一的边）。
3. 找到唯一的二面体变换（旋转+可选镜像），使得色块的蓝(1) 引导边面朝网格的蓝(1) 边框方向，且红(2) 引导边面朝网格的红(2) 边框方向。
4. 对色块（含引导边）执行该变换。
5. 从变换后的色块中裁剪掉两条引导边（各 1 像素宽，分别在匹配方向的那一侧），只保留绿(3) 内部区域。
6. 将裁剪结果进行 2 倍像素放大：每个像素替换为 2x2 同色块。
7. 输出放大后的网格（仅含放大后的绿(3) 区域，背景间隙也一并放大）。

**关键洞察**：引导边是一次性使用的控制信息——它编码了变换方向，用完即裁掉，不出现在最终输出中。像素放大使得裁剪后的小精灵变为更大的输出，如果跳过裁剪直接放大，引导边会被错误地保留并放大。

## 新题 9：位掩码 AND 选择瓦片复制轴

**组合逻辑**：[logical_AND/both_mask_overlap](对两个掩码求逐像素 AND) → [encoding_map](AND 结果的几何形状编码复制方向) + [axial_dup/first_half_extract](沿编码方向对第三区域执行轴向操作)

**来源原语**：logical_AND、bitmask、pixel_align、separator_col、both_mask_overlap（0520fde7）；encoding_map（77fdfe62, f560132c）；axial_dup、first_half_extract、repeated_tile（7b7f7511）；separator_line（92e50de0）

**依赖链**：AND 运算产生一个几何图案，该图案不是输出本身而是控制信号——其形状特征（水平对称还是垂直对称）决定了对另一区域的操作方向。AND 的计算需要两个掩码区域的信息，操作方向的判读需要 AND 结果的几何分析，最终的轴向操作需要方向信息和第三区域的内容。三个区域各自独立，但通过 AND→几何判读→轴向操作这条链紧密耦合。

用两个掩码的逐像素 AND 结果的对称性质判断复制方向，对第三区域沿该方向取半。

**输入结构**：一个约 9x21 的网格，由两条全高灰(5) 垂直分隔线分为三个等宽区域（每区约 9x7）。左区和中区各包含一个蓝(1)/黑(0) 位掩码图案（蓝色标记活跃像素，黑色标记非活跃像素）。两掩码尺寸相同。右区包含一个彩色图案（使用红(2)、绿(3)、黄(4) 等多种颜色），且右区的图案沿某一轴是两个相同半区的复制（即右区是某个更小图案沿水平方向或垂直方向复制一次得到的）。生成约束：左区和中区掩码的 AND 结果恰好具有唯一一种轴对称（水平对称或垂直对称，不会同时具有两种对称）；AND 结果对称轴的方向与右区的复制轴方向一致。

**规则**：
1. 识别两条灰(5) 垂直分隔线，将网格分为左区 L、中区 M、右区 R。
2. 逐像素计算 L 和 M 的 AND：对应位置均为蓝(1) → 红(2)，否则 → 黑(0)。得到 AND 图案 A。
3. 分析 A 的对称性：
   - 若 A 关于水平中线对称（上半与下半镜像相同） → 复制方向 = 垂直（上下复制）。
   - 若 A 关于垂直中线对称（左半与右半镜像相同） → 复制方向 = 水平（左右复制）。
4. 沿复制方向将 R 等分为两半，取第一半（垂直方向取上半，水平方向取左半）。
5. 输出提取的半区图案。

**关键洞察**：AND 运算的结果不是最终答案而是一条元指令——它的几何对称性编码了对另一区域应执行何种轴向操作。求解者必须先完成掩码运算，再分析结果的全局对称性，最后将这个判断应用到完全不同的第三区域上。三个区域的信息汇聚在一条非显然的推理链中。

## 新题 10：控制标记重涂区域后，按半区分色绘制边框

**组合逻辑**：[marker_points_to_target/control_marker](T 标记指定重涂目标区域) + [erase](擦除标记) → [border_drawing/half_color_split](根据重涂后的最终状态绘制边框，并按上下半区分色)

**来源原语**：control_marker、marker_points_to_target、marker_shape_determines_operation、monochrome_region、erase（21897d95）；border_drawing、half_color_split、ordering（1bfc4729）；recolor（多题）

**依赖链**：T 标记首先改变区域颜色分布，然后边框绘制依赖于重涂后的状态——具体来说，边框的分色规则需要知道重涂后上半区和下半区各自的主色调（出现面积最大的非黑色）。如果不先执行重涂，边框颜色就会基于错误的颜色分布。标记擦除必须在边框绘制之前完成，否则标记像素会干扰主色调计算。

先按 T 标记重涂区域并擦除标记，再统计上下半区主色调，以此为边框分色。

**输入结构**：一个约 14x14 的网格，由若干单色区域组成马赛克图案（区域使用蓝(1)、红(2)、绿(3)、黄(4) 四种颜色，无黑色背景——整个网格被颜色填满）。网格高度为偶数。区域边界上有 1~2 个蓝(1) 色 T 形控制标记（3 像素：一个茎像素 + 两个对角像素）。茎像素指向目标区域，对角像素背后标识源区域。生成约束：重涂操作完成后，上半区（行 0 至 H/2-1）面积最大的颜色与下半区（行 H/2 至 H-1）面积最大的颜色不同。

**规则**：
1. 对每个蓝(1) T 形控制标记：
   - 茎像素相邻的非蓝区域为目标区域。
   - 两个对角像素背后的区域为源区域。
   - 将目标区域的所有像素重涂为源区域的颜色。
2. 擦除所有蓝(1) 标记像素：将每个标记像素替换为其所在源区域的最终颜色。
3. 将网格沿水平中线分为上半区和下半区。
4. 统计上半区中面积最大的颜色 C_top，和下半区中面积最大的颜色 C_bot。若出现面积并列，取在该半区中边界框面积（行数 x 列数）最大的那个颜色对应的区域的颜色。
5. 绘制网格最外圈 1 像素宽的边框：
   - 上半区范围内的边框像素（顶边全部 + 左右边的上半段）涂为 C_top。
   - 下半区范围内的边框像素（底边全部 + 左右边的下半段）涂为 C_bot。
6. 边框覆盖原有像素（边框像素直接替换为对应颜色）。

**关键洞察**：控制标记不仅改变局部区域颜色，还间接影响了全局的颜色分布统计——这决定了边框的分色方案。求解者必须意识到重涂是边框着色的前置条件，两者通过"颜色面积统计"这一中间变量隐式耦合。
