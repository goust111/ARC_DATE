## 新题 1：嵌套层投票淘汰

**组合逻辑**：[补全/complete] → [由外到内嵌套/outer_to_inner + 大层先画小层覆盖/large_first_small_over]（已有） → [计数/counting + 投票/vote + 标记归属区域/marker_in_region]（已有，但作用对象从平面区域变为嵌套层级） → [擦除/erase]（创新：由投票结果触发，仅保留胜出层）

**来源原语**：补全、由外到内嵌套、大层先画小层覆盖（参考题 5751f35e）；计数、投票、标记归属区域、最多标记区胜出（参考题 de1cd16c）；擦除（参考题 782b5218）

**依赖链**：稀疏矩形层必须先补全为完整嵌套矩形，才能确定每层的独占区域；有了独占区域才能将标记像素归属到具体层级；归属完成后计数投票决定胜出层；投票结果驱动擦除/保留。四步串联，任一步缺失后续均无法执行。

将散落在嵌套矩形层间的稀疏标记像素归属到各层并计数，保留标记最多的那层矩形、擦除其余层。

**输入结构**：
- 约 15x15 网格，黑(0) 背景。
- 3 个同心轴对齐矩形层，每层用不同颜色的稀疏采样像素表示（如外层蓝(1)、中层红(2)、内层绿(3)）。每层仅呈现部分边缘像素（每条边至少 2 个像素、角像素至少保留 1 个），足以唯一确定其矩形边界框。三层边界框面积互不相同且严格嵌套（外层包含中层，中层包含内层），相邻层之间至少间隔 1 行 1 列。
- 黄(4) 标记像素散布在网格上，总数 5~9 个。每个标记像素的 4-邻域内至少有一个属于某层独占区域的像素（即不被更内层覆盖的区域），保证归属无歧义。不同层获得的标记数互不相同。
- 生成约束：任意两层的标记数严格不等；标记像素不落在任何层的矩形边缘上。

**规则**：
1. 对每种非标记前景色，取其像素的边界框作为该层的完整矩形。
2. 按矩形面积从大到小（外→内）依次填充：先将外层矩形内部全部涂为外层色，再将中层矩形内部全部涂为中层色，最后将内层矩形内部全部涂为内层色。后涂覆先涂。
3. 填充完成后，每个像素所属的层由其最终颜色确定（即最内层包含它的矩形层）。对每个黄(4) 标记像素，将其归属到其所在位置最终颜色对应的矩形层。
4. 统计每层获得的标记数，选出标记数最多的唯一胜出层。
5. 输出：在黑(0) 背景上仅绘制胜出层的完整实心矩形（用胜出层颜色），擦除其他所有层和标记像素。

**关键洞察**：标记像素不是直接按物理邻近归属，而是依据嵌套补全后的覆盖结果归属——一个看似在外层区域的标记可能实际落在中层矩形范围内，因此必须先完成嵌套绘制才能正确归属。

## 新题 2：锚块洪泛过滤压缩

**组合逻辑**：[洪泛填充/flood_fill + 内外分区/inside_outside_partition]（已有） ⊗ [压缩/compress + 射线像素紧缩至锚/compact_to_anchor]（已有）（"⊗"表示共享锚块作为双重角色节点：既是洪泛起点又是压缩目标）

**来源原语**：洪泛填充、内外分区（参考题 7491f3cf, 782b5218）；压缩、锚块、射线像素、同色射线归属锚块、射线像素紧缩至锚（参考题 f28a3cbb）；墙壁边界（参考题 7491f3cf）

**依赖链**：锚块中心既是洪泛填充的种子点又是压缩的目标点——洪泛填充由锚块发出、被墙壁阻挡，产生可达区域（inside）；仅可达区域内的射线像素被保留并压缩向锚块，不可达区域的射线像素被擦除。锚块的空间位置同时决定了洪泛的形状和压缩的方向，两个操作通过同一个对象耦合。

以锚块为中心洪泛填充确定可达区域，仅保留可达区域内的射线像素并将它们压缩贴紧锚块。

**输入结构**：
- 约 15x15 网格，黑(0) 背景。
- 灰(5) 像素组成一道墙壁，从网格的一条边连通到另一条边（不一定直线，可以折线），将网格分为两个 4-连通区域。
- 一个 3x3 纯蓝(1) 实心锚块位于墙壁的一侧。
- 若干蓝(1) 单像素（射线像素）散布在网格两侧，每个射线像素与锚块中心在同一行、同一列或同一 45 度对角线上（即沿 8-邻域直线方向对齐）。两侧各有至少 2 个射线像素。
- 生成约束：锚块不与墙壁相邻（至少间隔 1 个像素）；同一方向上的射线像素之间互不相邻。

**规则**：
1. 以锚块中心为起点，进行 4-连通洪泛填充，灰(5) 墙壁像素为阻隔——所有可达的黑(0) 像素及锚块自身像素构成"可达区域"。
2. 对于每个蓝(1) 射线像素：若它在可达区域内，保留；若不在，擦除为黑(0)。
3. 对保留的射线像素，沿其与锚块中心的对齐方向（行/列/对角线）向锚块滑动，依次紧贴锚块或前一个已压缩的射线像素停下（即填满锚块边缘向外的连续格子）。压缩顺序：距锚块近的先压缩。
4. 墙壁像素保持灰(5) 不变，锚块保持蓝(1) 不变。

**关键洞察**：锚块同时扮演洪泛种子和压缩吸引子两个角色，墙壁的走向决定了哪些射线像素存活，从而间接决定了压缩后的最终图案形状。

## 新题 3：剪切揭示对角连通

**组合逻辑**：[剪切变换/shear_transform + 偏移随行距增/offset_grows_with_distance]（已有） → [连线/connect + 中心对角对齐/center_diagonal_alignment + 无障碍通路/unobstructed_path]（已有，但对齐关系由剪切动态产生而非输入中预设）

**来源原语**：剪切变换、偏移随行距增、底行锚点、前景对象（参考题 423a55dc）；连线、中心对角对齐、无障碍通路、十字图案（参考题 55059096）

**依赖链**：输入中的十字图案彼此不处于任何 45 度对角线上，因此无法直接连线。剪切变换按底行锚定逐行左移后，部分十字图案的中心恰好落到同一对角线上，此时才产生可连通的对。连线的存在与否完全取决于剪切后的坐标，两步不可分离。

对多个十字图案施加左向剪切变换，再连接因剪切而新出现的对角对齐的图案中心。

**输入结构**：
- 约 16x16 网格，黑(0) 背景。
- 4~6 个绿(3) 十字图案（每个 5 像素：中心 + 四个基数方向邻居），各自独立，互不相邻（任意两个十字的边界框不重叠）。
- 在输入中，任意两个十字中心的行差与列差的绝对值互不相等（即没有现成的 45 度对角对齐关系）。
- 生成约束：存在一个公共底行 b（所有十字像素的最下行），使得剪切后至少有一对十字中心落在同一 45 度对角线上且路径无障碍；剪切后所有十字像素仍在网格内或仅被左边界裁剪。

**规则**：
1. 确定所有十字像素中最下方的行号 b（底行锚点）。
2. 剪切变换：将每个十字的每个像素 (r, c) 移动到 (r, c - (b - r))。若目标列 < 0，该像素被裁剪丢弃。
3. 剪切后，重新计算每个幸存十字的中心位置。若某个十字因裁剪丢失了中心像素，该十字整体被擦除。
4. 对所有幸存十字的中心，检查每对中心：若行差绝对值 = 列差绝对值（即处于 45 度对角线），且两中心之间对角线路径上的所有内部像素均为黑(0) 背景，则在这些内部像素上绘制红(2)。
5. 被裁剪的十字区域变为黑(0)。剪切后的十字像素保持绿(3)。

**关键洞察**：输入中看不到任何对角对齐关系——对角连通纯粹是剪切变换的涌现产物；求解者必须先在脑中完成剪切、再检查对齐，两步推理缺一不可。

## 新题 4：射线计数柱状排序

**组合逻辑**：[压缩/compress + 同色射线归属锚块/ray_belongs_anchor]（已有，简化为计数而非实际压缩） → [计数/count]（已有） → [排序/sort + 高度编码数量/height_encodes_count]（已有，但编码的数量来源从梳状结构变为射线数目）

**来源原语**：压缩、锚块、射线像素、同色射线归属锚块（参考题 f28a3cbb）；计数、排序、高度编码数量、色条（参考题 a1aa0c1e）

**依赖链**：射线像素的空间分布隐含了每个锚块的"权重"（射线数）；计数操作将空间信息转化为数值；排序操作将数值转化为全新的空间布局（柱状图）。三步之间信息形态依次转换（空间→数值→不同空间），删除任何一步都无法得到输出。

统计每个彩色锚块拥有的射线像素数，将锚块颜色按射线数升序输出为高度不同的纯色柱状图。

**输入结构**：
- 约 18x15 网格，黑(0) 背景。
- 3~4 个 3x3 纯色实心锚块，每个颜色不同（如蓝(1)、红(2)、绿(3)、黄(4)），彼此互不相邻（边界框之间至少间隔 2 个像素）。
- 每个锚块在其行、列或 45 度对角线方向上散布有 1~6 个同色单像素（射线像素）。不同锚块的射线数互不相同。射线像素之间互不相邻，且不与其他颜色的锚块或射线重叠。
- 生成约束：每种颜色的射线数严格不等。

**规则**：
1. 对每种非背景颜色，将该色的 3x3 实心块识别为锚块，其余同色单像素为射线像素。
2. 统计每种颜色的射线像素数目 n。
3. 输出网格大小：宽度 = 锚块数目，高度 = 最大射线数。
4. 按射线数从小到大（升序）将锚块颜色排列为从左到右的列。每列从底部向上填充该锚块颜色共 n 行，其余填黑(0)。
5. 若两种颜色射线数相同（生成保证不会发生），按锚块中心行号从小到大 tie-break。

**关键洞察**：输入是一张大网格上散落的彩色块和点，输出是一张小柱状图——两者在空间结构上毫无相似之处；求解者必须意识到射线数目是隐含的排序键，且输出格式完全由数值驱动。

## 新题 5：洪泛分区双种子铺贴

**组合逻辑**：[洪泛填充/flood_fill + 内外分区/inside_outside_partition + 掩码选择源面板/mask_selects_source_panel]（已有，但选择对象从源面板变为种子图案） ⊗ [平铺/tiling + 保持种子相位/preserve_seed_phase + 图案填满空腔/pattern_fills_cavity]（已有，但空腔由洪泛分区动态定义而非预设矩形）

**来源原语**：洪泛填充、内外分区、掩码选择源面板、墙壁边界、指示像素（参考题 7491f3cf）；平铺、种子图案、保持种子相位、图案填满空腔、矩形空腔（参考题 a57f2f04）

**依赖链**：洪泛填充从指示像素出发、被墙壁阻隔，产生内/外两个区域。每个区域内恰好有一个种子图案。分区结果同时决定了"哪个种子属于哪个区域"和"区域的铺贴范围"。种子的相位（其在区域内的绝对位置 mod 瓦片尺寸）必须保留。两个操作共享分区结果，且种子归属依赖分区。

用墙壁和指示像素将网格洪泛分为内/外两区，分别用各区内的种子图案周期铺满该区。

**输入结构**：
- 约 15x15 网格，黑(0) 背景。
- 灰(5) 像素组成墙壁，从网格一侧连通到另一侧（可折线），将非墙像素分为恰好两个 4-连通区域。
- 一个橙(7) 指示像素位于其中一个区域内，且与墙壁不相邻（至少间隔 1 像素），该像素是 8-邻域孤立的（8 邻居中无其他橙像素）。
- 一个小蓝(1) 种子图案（2x2 或 2x3 矩形内的非全满子图案，至少 2 个蓝像素）位于包含指示像素的区域内。
- 一个小红(2) 种子图案（同规格但形状与蓝种子不同）位于另一个区域内。
- 两个种子图案的边界框不重叠。种子图案的边界框完全在其所属区域内。
- 生成约束：每个区域的尺寸是对应种子边界框尺寸的整数倍加上若干偏移（保证铺贴完整覆盖时边缘可能裁剪但相位唯一确定）。

**规则**：
1. 以橙(7) 指示像素为起点，4-连通洪泛填充，灰(5) 墙壁阻隔——可达区域为"内区"，不可达的非墙区域为"外区"。
2. 识别内区中的蓝(1) 种子：取蓝像素的边界框为瓦片 A。识别外区中的红(2) 种子：取红像素的边界框为瓦片 B。
3. 对内区的每个像素 (r, c)：计算 (r mod 瓦片A高度, c mod 瓦片A宽度) 对应瓦片 A 中的位置；若该位置是蓝(1)，涂蓝(1)；否则保持黑(0)。相位锚定：种子在内区中的实际位置就是相位原点（即种子左上角坐标 mod 瓦片尺寸 = 0）。
4. 对外区同理，用瓦片 B 铺贴，涂红(2)。
5. 墙壁保持灰(5)。指示像素被铺贴覆盖（不保留）。

## 新题 7：去噪条纹作为滑动目标

**组合逻辑**：[去噪/denoise + 主色占优/dominant_color + 主色覆盖全行列/dominant_fills_line]（已有） → [滑动/sliding + 同色配对/same_color_pairing + 无匹配色则删除/unmatched_deleted]（已有，但"满行列条"由去噪动态生成而非输入中预设）

**来源原语**：去噪、重涂色、条纹行列、噪声像素、主色占优、主色覆盖全行列（参考题 e26a3af2）；滑动、同色配对、无匹配色则删除、孤立像素、满行列条（参考题 1a07d186）

**依赖链**：输入中的条纹被噪声污染，条纹的真实颜色不确定。孤立像素需要滑向与其同色的条纹，但条纹颜色在去噪前不可知。去噪确定了条纹真色后，同色配对才能成立。同时，噪声像素和孤立像素可能同色，必须先区分条纹噪声和待滑动像素，而这需要知道条纹方向——条纹方向本身也是去噪的结果。

先去噪恢复被污染条纹的真实颜色和方向，再将条纹外的孤立像素滑向同色条纹。

**输入结构**：
- 约 12x12 网格。
- 底层是竖直条纹：3~4 条全高竖直条纹（每条宽 1 像素），颜色互不相同（如蓝(1)、红(2)、绿(3)），条纹之间间隔 2~3 列黑(0)。
- 噪声：每条条纹上有 1~2 个像素被替换为其他条纹颜色或黑(0)（但每列的主色仍是原条纹色且占该列像素数的严格多数）。
- 孤立像素：在非条纹列（间隔区域）上散布 3~5 个单像素，颜色为某条条纹的真实颜色（去噪后才能确认匹配）。部分孤立像素的颜色可能恰好是噪声色（即其颜色与某条条纹的噪声像素相同、但与该条纹的真实颜色不同）。
- 至少一个孤立像素的颜色不匹配任何条纹的去噪真色。
- 生成约束：每列中主色像素数严格超过该列总像素数的一半。

**规则**：
1. 确定条纹方向：分别计算"水平条纹"和"竖直条纹"解释下的全行/列主色计数之和，取和更大者为条纹方向（此设置中为竖直）。
2. 去噪：将每条条纹列全部涂为该列的主色（唯一占优颜色），覆盖噪声。
3. 识别孤立像素：位于非条纹列上的非黑非背景单像素即为孤立像素（条纹列上的像素已被去噪覆盖，不算孤立像素）。
4. 对每个孤立像素：若其颜色与某条去噪后条纹的颜色匹配，将该像素水平滑动至最近的该色条纹列（若左右等距，取左侧），在该条纹列的同行位置涂上该色（若该位置已有条纹色则覆盖无效果）。
5. 颜色不匹配任何去噪条纹的孤立像素：擦除为黑(0)。

**关键洞察**：去噪和滑动共享同一组颜色信息——条纹的去噪结果决定了哪些孤立像素被接纳、哪些被淘汰；若跳过去噪直接尝试匹配，噪声像素会造成错误配对。

## 新题 8：分区计数奇偶定滑向

**组合逻辑**：[洪泛填充/flood_fill + 四连通分区/four_connected_partition + 角落锚定/corner_anchor]（已有） → [计数/counting + 奇偶性/parity]（已有原语，但作用于分区内像素计数而非对象边长） → [滑动/sliding + 碰撞阻挡/collision_blocking]（已有，但滑动方向由计数奇偶动态决定）

**来源原语**：洪泛填充、四连通分区、角落锚定、分隔墙（参考题 782b5218）；计数、奇偶性（参考题 22806e14, a1aa0c1e）；滑动、碰撞阻挡、孤立像素（参考题 1a07d186）

**依赖链**：墙壁分区 → 每区的孤立像素计数 → 计数的奇偶性决定滑动方向 → 滑动执行。分区决定计数边界，计数决定方向，方向决定运动结果——三层逻辑层层依赖。从单个示例无法确定"奇数→向墙、偶数→离墙"的规则，必须对比多个示例。

- 蓝(1) 孤立像素散布在两个区域中，每区 2~5 个，两区的像素数目一奇一偶。孤立像素互不相邻，且不与墙壁相邻。

1. 以左下角像素为种子，4-连通洪泛填充，红(2) 墙壁阻隔——可达区域为"下区"，不可达区域为"上区"。

5. 红(2) 墙壁保持不变。滑动后原位置变为黑(0)。

**关键洞察**：同一批蓝像素在不同示例中可能向墙壁滑也可能向边缘滑，取决于同区域内其他像素的总数——必须对比多个示例的计数才能归纳出奇偶规则。

1. 补全矩形框：对每条边，将该边上的缺口像素填为该边的颜色。角像素取水平边颜色。

7. 原位置变为黑(0)。

## 新题 10：障碍跳跃螺旋与段计数变色

**组合逻辑**：[螺旋绘制/spiral_drawing + 递增步长/increasing_step_length + 方向分色/direction_based_color_split]（已有） ⊗ [障碍偏转绕行/obstacle_deflection + 障碍块/blocker]（已有，但偏转方式从平移改为跳过） ⊗ [计数/counting + 奇偶性/parity]（已有原语，但计数对象从区域内标记变为螺旋段内跳过的格数）（"⊗"表示三路原语在同一螺旋段上同时作用：障碍跳过改变几何、跳过计数决定颜色、方向分色作为默认色规则）

**来源原语**：螺旋绘制、中心标记、调色板、递增步长、边界截断、方向分色（参考题 08573cc6）；障碍偏转绕行、障碍块（参考题 69889d6e）；计数、奇偶性（参考题 22806e14, a1aa0c1e）

**依赖链**：障碍的空间位置决定了螺旋段中哪些格子被跳过（几何效果），同时被跳过的格数触发奇偶判断改变该段颜色（色彩效果）。同一个障碍同时影响两个输出维度（形状和颜色），且两种效果不可独立推断。

从中心螺旋向外画臂，遇障碍时跳过但延长步长，若一段中跳过的格数为奇数则整段变色。

**输入结构**：
- 约 18x18 网格，黑(0) 背景。
- 一个灰(5) 中心标记像素。
- 调色板：网格左上角 (0,0) 为蓝(1)，(0,1) 为红(2)。
- 2~4 个橙(7) 障碍像素（各自独立，互不相邻），散布在螺旋预计经过的路径上。
- 生成约束：障碍像素不在中心标记的 8-邻域内；不在调色板位置上；至少一个螺旋段经过奇数个障碍、至少一段经过偶数个（含 0 个）障碍。

**规则**：
1. 从中心标记出发，按照左→下→右→上的方向循环绘制螺旋，段长度依次为 2、3、4、5...（第 k 段长度为 k+1）。
2. 绘制每段时逐格前进。若下一格是障碍像素，跳过该格（不绘制、不改变障碍色）并继续前进，但段的"有效绘制长度"不变——即跳过的格不计入已绘制格数，段总共需要绘制段长度个非障碍格。
3. 统计每段跳过的障碍数 s：
   - 若 s = 0：该段使用方向分色规则——水平段（左/右）用蓝(1)，垂直段（上/下）用红(2)。
   - 若 s 为奇数：整段用绿(3)。
   - 若 s 为偶数且 s > 0：整段用黄(4)。
4. 若一段在绘制完指定长度前到达网格边界（非障碍阻挡），该段绘制已覆盖的部分并终止整个螺旋。
5. 中心标记保持灰(5)。障碍保持橙(7)。调色板像素保持原色。

**关键洞察**：障碍对螺旋的影响是双重的——几何上拉长了段的物理跨度（跳过格不画但继续走），色彩上通过跳过计数的奇偶性覆盖了默认的方向分色规则；同一个障碍位置同时改变了螺旋的形状和颜色编码。
