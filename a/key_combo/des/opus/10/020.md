## 新题 1：标记距离编码瓦片周期的噪声修复

**组合逻辑**：[标记像素·距离读取](创新：距离编码周期) + [修复噪声·多数投票] + [擦除]（标记像素的"定位"功能被重构为"参数编码"功能）

**来源原语**：标记像素/marker_pixel（fbf15a0b）、修复噪声/repair_noise（135a2760）、周期瓦片/periodic_tile（135a2760）、擦除/erase（fbf15a0b）、框架分区/frame_partition（135a2760）、忽略干扰项/ignore_distractors（135a2760）

**依赖链**：标记像素的空间距离 → 确定瓦片周期 → 以此周期修复噪声图案 → 擦除标记。没有标记距离就无法推断正确的周期；没有正确的周期，多种瓦片尺寸都能部分匹配噪声数据，无法唯一确定修复结果。

在框架分区的噪声网格中，每个分区内嵌入的一对标记像素的曼哈顿距离即该分区的瓦片周期；以此周期修复噪声并擦除标记。

**输入结构**：约 15x15 的网格，背景黑(0)。灰(5) 色的满行/满列将网格分割为 3~4 个矩形分区。每个分区内有一种前景色（各分区颜色不同，例如红(2)、蓝(1)、绿(3)）构成的周期性图案，但其中 2~4 个像素被错误地替换为黑(0) 或其他颜色（噪声）。每个分区内还有恰好两个橙(7) 标记像素，位于分区内部（不在灰色分隔线上），且不与图案像素重叠。生成约束：每个分区的两个橙(7) 标记之间的曼哈顿距离恰好等于该分区图案的行方向周期与列方向周期（两者相等，即瓦片为正方形 PxP）；不同分区的标记距离可以不同。

**规则**：
1. 对每个灰(5) 分隔的矩形分区，找到其内部的两个橙(7) 标记像素，计算它们之间的曼哈顿距离 D。
2. 该分区的瓦片尺寸为 DxD。将分区内的非橙(7)、非灰(5) 像素按行列坐标对 D 取余，对每个余数位置做多数投票，确定正确的瓦片单元。
3. 用正确的瓦片单元重新铺满该分区（替换所有噪声像素）。
4. 将两个橙(7) 标记像素设为黑(0)（背景色）。
5. 灰(5) 分隔线保持不变。

**关键洞察**：标记像素并非图案内容，也不是用于选择半区或定位的标签——它们的空间距离编码了一个数值参数（瓦片周期），这个参数是修复噪声的前提。需要对比多个示例才能归纳出"曼哈顿距离 = 瓦片周期"这一编码规则。

## 新题 2：双轴杯体弹射的笛卡尔碰撞

**组合逻辑**：[弹射·双向独立](创新：分为垂直弹射组和水平弹射组) + [行列交叉·碰撞检测](创新：交叉点变色) + [像素数守恒]

**来源原语**：弹射/ejection（3dc255db）、尾部朝向决定射出/tail_determines_emission（3dc255db）、行列交叉/row_col_intersection（2281f1f4）、像素数守恒/pixel_count_conservation（3dc255db）、擦除/erase（3dc255db）

**依赖链**：各杯体独立弹射内容像素 → 垂直弹射和水平弹射的路径在网格中形成行列交叉 → 交叉点发生碰撞需特殊着色。弹射方向由杯体尾刺决定，但碰撞位置只有两组弹射路径同时到达才会出现——单独一组弹射无法产生碰撞色。

沿两个正交方向弹射杯体内容后，垂直路径和水平路径交叉的像素变为碰撞色。

**输入结构**：约 12x12 的网格，背景黑(0)。网格上方边缘附近有 2~3 个杯形框架，尾刺朝下（即开口朝上），边框各用不同颜色（如蓝(1)、绿(3)），每个杯口内有 1~4 个黄(4) 内容像素。网格左侧边缘附近另有 2~3 个杯形框架，尾刺朝右（即开口朝左），边框用另一组不同颜色（如红(2)、灰(5)），杯口内同样有 1~4 个黄(4) 内容像素。各杯形框架由 3~5 个边框像素构成，杯口为 1~2 个像素宽的开口，尾刺为 1 像素突出。生成约束：所有杯体互不重叠且弹射路径不与其他杯体框架相交。

**规则**：
1. 对每个杯体，计数其内容像素数 N，擦除杯口内所有黄(4) 内容像素（还原为黑(0)）。
2. 从杯体尾刺端点起，沿尾刺方向（上方杯体朝下、左侧杯体朝右）连续绘制 N 个黄(4) 像素。如果超出网格边界则丢弃超出部分。
3. 对每个网格单元格，检查是否同时被一条垂直弹射路径（来自上方杯体）和一条水平弹射路径（来自左侧杯体）经过。若是，将该单元格涂为橙(7) 而非黄(4)。
4. 仅被一条弹射路径经过的单元格保持黄(4)。
5. 杯体边框像素保持原色不变。

**关键洞察**：碰撞色(橙(7))只出现在垂直弹射线段和水平弹射线段的交叉点上，这是一个笛卡尔积结构——但其行列坐标由各杯体的内容数量和尾刺位置联合决定，而非由边缘标记的固定位置给出。需对比多个示例才能区分"单路径=黄色"和"双路径交叉=橙色"。

## 新题 3：载体色控滑动后的对角线同余铺满

**组合逻辑**：[滑动·颜色决定方向] + [循环填充·同余类交错](创新：在滑动后的新位置上执行同余延伸，且限制在载体带内)

**来源原语**：滑动/slide（9b4c17c4）、颜色决定方向/color_determines_direction（9b4c17c4）、载体区域/carrier_region（9b4c17c4）、循环填充/cyclic_fill（05269061）、同余类交错铺满/congruence_interlaced（05269061）、对角线/diagonal（05269061）

**依赖链**：载体颜色决定对角线段的水平滑动方向 → 滑动改变对角线的列坐标 → 以新坐标为基准做模 3 同余延伸 → 延伸被限制在载体带的行范围内。滑动结果直接改变同余类的相位，因此同一对角线在不同载体中会产生完全不同的铺满图案。

将对角线段按载体色方向滑至载体边缘后，在载体带内以模 3 同余类铺满该对角线。

**输入结构**：约 10x10 的网格，无背景——网格被水平载体带完全填满。载体带交替为蓝(1) 和青(8)，每带 3~4 行高，覆盖整个网格宽度。每个载体带内含一条对角线段（3~5 像素长），颜色各不相同且非蓝非青非黑（如红(2)、绿(3)、黄(4)、橙(7)），斜率方向统一（均为左上→右下或均为右上→左下）。生成约束：每条对角线段严格在其载体带的行范围内；各带的对角线段互不接触。

**规则**：
1. 识别每条对角线段及其所在载体带的颜色。
2. 水平滑动对角线段：蓝(1) 载体 → 整体右移，直至线段最右端像素的列坐标等于载体带的最右列（即网格右边缘）；青(8) 载体 → 整体左移，直至线段最左端像素的列坐标等于载体带的最左列（即列 0）。滑动过程中对角线段形状不变，滑动前的原始位置还原为载体色。
3. 以滑动后的对角线段为种子，在载体带行范围内做模 3 同余延伸：沿列方向每隔 3 列重复绘制同斜率的完整对角线（仅覆盖载体色像素，不覆盖已有的其他对角线色像素），裁切到载体带的行范围。
4. 若两个相邻载体带的同余延伸在边界行产生冲突（同一单元格被两个带的延伸同时覆盖），上方载体带的颜色优先。

**关键洞察**：载体色决定对角线的锚定边缘（左或右），锚定位置决定同余相位，因此同一根对角线在蓝载体和青载体中会产生镜像式的铺满结果。必须先滑动再铺满，两步的耦合不可跳过。

## 新题 4：字形面积解码为沟槽着色指令

**组合逻辑**：[解码指令·面积→颜色映射](创新：字形面积编码颜色而非方向) + [间隙填充·逐段涂色](创新：每段沟槽独立着色)

**来源原语**：解码指令/decode_instructions（136b0064）、字形指令/glyph_instruction（136b0064）、编码映射/encoding_map（136b0064）、间隙填充/gap_fill（137f0df0）、分区涂色/zone_coloring（137f0df0）、网格沟槽/lattice_gutter（137f0df0）、分隔列/separator_column（136b0064）、顺序读取/sequential_reading（136b0064）、块阵列/block_array（137f0df0）

**依赖链**：右侧字形面积 → 解码为颜色序列 → 左侧沟槽段按固定枚举顺序 → 逐段涂上解码的颜色。字形解码和沟槽结构互为必要：没有字形就不知道涂什么颜色，没有沟槽结构就不知道涂在哪里，两者的配对顺序由枚举规则决定。

将分隔列右侧字形的像素面积解码为颜色，按枚举顺序逐一涂入左侧块阵列的沟槽段。

**输入结构**：约 14x18 的网格，背景黑(0)。一条满高灰(5) 分隔列将网格分为左右两部分。左侧：青(8) 的 2x2 方块组成矩形阵列（如 3 行 4 列方块），方块之间有 1 像素宽的黑(0) 沟槽（含水平沟槽和垂直沟槽）。右侧：从上到下排列若干独立的 3x3 字形，每个字形为单一前景色（颜色可各不相同）的 4-连通区域，位于 3x3 边界框内，字形之间至少隔 1 行黑(0)。字形总数等于左侧沟槽段总数（水平沟槽段数 + 垂直沟槽段数）。生成约束：每个字形的像素面积在 3~7 之间；各字形面积不必互不相同。沟槽段定义：一段水平沟槽 = 两个水平相邻方块之间的 1x1 间隙在同一沟槽行内的连续黑(0) 段；一段垂直沟槽 = 两个垂直相邻方块之间的 1x1 间隙在同一沟槽列内的连续黑(0) 段。

**规则**：
1. 输出网格去除灰(5) 分隔列及其右侧所有内容，仅保留左侧部分（宽度 = 原左侧宽度）。
2. 从上到下读取右侧所有字形，计算每个字形的像素面积 A（3x3 边界框内前景色像素数）。
3. 面积→颜色映射：A=3 → 红(2)，A=4 → 绿(3)，A=5 → 蓝(1)，A=6 → 黄(4)，A=7 → 橙(7)。
4. 枚举左侧沟槽段：先枚举所有水平沟槽段（从最上方沟槽行开始，每行内从左到右），再枚举所有垂直沟槽段（从最左方沟槽列开始，每列内从上到下）。
5. 将第 i 个字形解码得到的颜色涂入第 i 个沟槽段的所有黑(0) 像素。
6. 青(8) 方块保持不变。

**关键洞察**：字形的空间形状无关紧要，唯一重要的是像素计数（面积）——面积编码颜色。沟槽段的枚举顺序（先水平后垂直）在视觉上没有显式提示，必须对比多个示例才能归纳。

## 新题 5：框架双重身份——缩放基准与条纹掩码源

**组合逻辑**：[像素放大·框内尺寸决定缩放] + [周期掩码·条纹覆盖](创新：条纹位置来自框架内部的标记条，缩放和条纹同源于框架)

**来源原语**：像素放大/pixel_upscale（6b9890af）、框内尺寸决定缩放/frame_size_sets_scale（6b9890af）、包含于框架内/in_frame（6b9890af）、周期条纹/periodic_stripe（6a980be1）、周期掩码/periodic_mask（6a980be1）、标记条/marker_bar（6a980be1）、图案/pattern（6b9890af）

**依赖链**：红框内部尺寸 ÷ 小图案尺寸 = 缩放因子 → 缩放图案填满框内 → 框内蓝色标记条的行（或列）位置构成周期掩码 → 在缩放后的图案上沿这些行（或列）用红色覆盖。框架同时提供缩放参数和条纹位置信息，两个信息来源共享同一结构但用途完全不同。

将小图案按红框内部尺寸缩放后，用框内蓝色标记条指定的周期行（或列）叠加红色条纹。

**输入结构**：约 15x15 的网格，背景黑(0)。一个红(2) 正方形空心框（1 像素厚边框，内部 NxN，N 为 6、9 或 12 等，保证是小图案边长的整数倍）。框内部的 N 行中，有若干等间距的行被蓝(1) 像素填满（形成水平标记条），其余行为黑(0)。网格其他位置有一个独立的小图案（如 3x3），由非红、非蓝、非黑的颜色组成（如绿(3)、黄(4)、灰(5) 的组合），为 4-连通区域。生成约束：蓝(1) 标记条的间距一致（等间距周期），至少出现 2 条；小图案的边长整除 N。

**规则**：
1. 计算缩放因子 S = N / 小图案边长。
2. 对小图案进行 S 倍最近邻缩放，得到 NxN 的放大图案。
3. 将放大图案覆盖到红框内部（替换所有黑(0) 和蓝(1) 像素）。
4. 找到蓝(1) 标记条在框内部的行坐标集合（相对于框内部的局部坐标）。
5. 在放大图案上，将这些行坐标对应的所有像素重新涂为红(2)，覆盖已缩放的图案内容。
6. 输出仅裁剪到红框边界框范围（包含红框边框和修改后的内部），其余区域不输出。

**关键洞察**：红框同时扮演两个角色——它的内部尺寸给出缩放倍数，它内部的蓝色标记条给出条纹掩码位置。蓝色标记条在输出中不保留，它们是嵌入框架内的结构指令，缩放完成后被条纹覆盖取代。需对比多个示例才能发现蓝色条不是输出内容而是掩码指令。

## 新题 6：对齐后按边缘标记匹配性决定镜像

**组合逻辑**：[对齐·边界对齐] + [镜像·标记匹配/不匹配触发](创新：镜像条件基于两端标记一致性，且在对齐之后评估)

**来源原语**：对齐/align（984d8a3e）、边界对齐/edge_alignment（984d8a3e）、色段/color_run（984d8a3e）、同行排列/row_arrangement（984d8a3e）、镜像/mirror（846bdb03）、边色不符则翻转/mismatch_flip（846bdb03）、颜色匹配/color_match（846bdb03）、标记像素/marker_pixel（fbf15a0b）

**依赖链**：所有行的色段右对齐 → 对齐改变了各行的像素布局 → 读取每行两端的标记像素颜色 → 若两端标记不匹配则镜像该行内容。对齐步骤改变了行内容的空间位置，而镜像决策依赖对齐后的标记关系——如果跳过对齐直接判断镜像，结果会不同。

将各行色段右对齐后，根据每行左右端标记像素是否同色来决定该行是否水平镜像。

**输入结构**：约 10x12 的网格。使用五种颜色：绿(3) 为中间色段、蓝(1) 为左侧填充色、红(2) 为右侧填充色、黄(4) 和橙(7) 为边缘标记色。每行结构：最左列（列 0）是一个标记像素，为黄(4) 或橙(7)；最右列是另一个标记像素，为黄(4) 或橙(7)；中间列从左到右依次是若干蓝(1) 像素、一段连续绿(3) 色段（长度逐行不同）、若干红(2) 像素。不同行中绿(3) 色段的起止列不同（右边缘参差不齐）。生成约束：每行恰好一段连续绿(3)；行数至少 5 行；至少有一行的两端标记同色，至少有一行的两端标记异色。

**规则**：
1. 找到所有行中绿(3) 色段右边缘列坐标的最小值 C_min。
2. 对每行，将绿(3) 色段水平左移，使其右边缘对齐到列 C_min（若色段起点会移到列 1 之前，则色段起点固定在列 1）。绿(3) 段左侧用蓝(1) 填充，右侧用红(2) 填充（标记列不参与移动，保持原位）。
3. 对齐完成后，逐行检查：若该行列 0 的标记色与最右列的标记色相同（同为黄(4) 或同为橙(7)），保持该行不变。
4. 若该行列 0 的标记色与最右列的标记色不同（一黄一橙），则将该行列 1 到倒数第 2 列的内容水平镜像翻转（标记像素本身不参与翻转，留在原列原色）。
5. 两端标记像素在输出中保持其原始颜色和位置。

**关键洞察**：镜像判断发生在对齐之后，因此对齐步骤实质性地改变了镜像的效果（翻转的是重排后的内容，而非原始布局）。标记像素的功能从"定位"转变为"二元条件开关"——它们的颜色配对关系（匹配/不匹配）控制操作选择，而非指示空间位置。

## 新题 7：列敏感的缺角补全与循环背景填充

**组合逻辑**：[补全·缺角填色](创新：补全颜色由顶行色序的对应列决定，非固定色) + [循环填充·分隔下填色](创新：补全后的像素成为填充障碍)

**来源原语**：补全/completion（3aa6fb7a）、缺角补全正方形/missing_corner_completes_square（3aa6fb7a）、填充/fill（bd4472b8）、顶行色序/top_row_color_sequence（bd4472b8）、分隔行/separator_row（bd4472b8）、分隔下循环填色/below_separator_cycle_fill（bd4472b8）、包围框内部/inside_bbox（3aa6fb7a）

**依赖链**：顶行色序 → 决定每列的补全颜色 → L 形对象的缺角按所在列获取颜色 → 补全后的 2x2 方块阻断循环填充的流向 → 填充最终以顶行色序逐列循环但绕过所有非背景像素。补全和填充共享同一个颜色源（顶行色序），但补全在填充之前执行，补全结果改变了填充的"背景"定义。

在灰色分隔行下方，先将 L 形对象的缺角补全为该列对应的顶行颜色，再用顶行色序循环填充剩余背景。

**输入结构**：约 10x10 的网格，背景黑(0)。顶行（第 0 行）包含一个宽度等于网格列数的颜色序列，每个单元格为红(2)、蓝(1)、绿(3) 中的一种，构成可辨识的重复模式（如 [红,蓝,绿,红,蓝,绿,...] 或 [红,红,蓝,绿,红,红,蓝,绿,...]）。第 1 行为满行灰(5) 分隔行。第 2 行及以下为黑(0) 背景，其中散布 3~5 个青(8) L 形对象（每个为 3 像素的 4-连通区域，恰好占据某个 2x2 边界框中的 3 个格子，缺少 1 个角）。生成约束：各 L 形对象的 2x2 边界框互不重叠；每个 L 的缺失角所在列在不同示例中可以不同（以迫使求解者发现列→颜色映射规则）。

**规则**：
1. 保持顶行和灰(5) 分隔行不变。
2. 对灰(5) 行下方每个青(8) L 形对象，找到其 2x2 边界框中唯一的黑(0) 缺角单元格，记其列坐标为 c。
3. 将该缺角单元格涂为顶行第 c 列的颜色（如列 c 处顶行为蓝(1)，则补为蓝(1)）。青(8) 像素保持不变。
4. 补全全部完成后，将灰(5) 行下方所有仍为黑(0) 的单元格填充为顶行色序的循环：每个单元格 (r, c) 填入顶行第 c 列的颜色。
5. 已有的青(8) 像素和步骤 3 中补全的像素均不被覆盖。

**关键洞察**：补全颜色不是固定的蓝色（与原始 L 补全题不同），而是由缺角所在列从顶行色序中查询得到。这意味着不同位置的 L 形对象即使形状相同、缺角方位相同，补全颜色也可能不同。循环填充看似会覆盖一切背景，但补全的像素先于填充执行，成为填充时的非背景障碍，改变了"哪些格子需要填充"的集合。

## 新题 8：单调最短路径并集上的周期色条投影

**组合逻辑**：[路径填充·最短路径并集](提供路径通道) + [周期延伸·长度即周期](沿路径通道做周期着色) + [近者优先](短周期条优先占位)

**来源原语**：路径填充/path_fill（692cd3b6）、最短路径并集/monotone_shortest_path_union（692cd3b6）、门框/doorway_frame（692cd3b6）、走廊路径/corridor_path（692cd3b6）、周期延伸/periodic_extension（1ae2feb7）、长度即周期/length_as_period（1ae2feb7）、色条/color_bar（1ae2feb7）、近者优先/nearest_first_priority（1ae2feb7）、门洞朝向/doorway_orientation（692cd3b6）

**依赖链**：两个门框的外部门洞确定走廊端点 → 计算所有最短单调路径的并集形成通道 → 通道上每个单元格获得一个沿路径的距离值 → 色条长度作为周期，对距离值取余后判断着色 → 短色条优先，先着色的不被覆盖。路径结构和色条周期互不可省：没有路径不知道"在哪里涂"，没有色条不知道"涂什么颜色"。

在两个门框之间的最短单调路径并集上，按色条长度为周期做交替着色。

**输入结构**：约 16x16 的网格，背景黑(0)。两个小型门框对象，各为灰(5) 的 3x3 空心框（1 像素厚），每个框中心有一个绿(3) 标记像素，该标记的四个 4-邻居中恰好有一个为黑(0)（门洞间隙），门洞间隙外一格为黑(0)（外部门洞单元格）。两个门框位于网格不同区域，相距足够远以形成多条最短单调路径。此外，网格某一边缘（如底部）附近有 2~3 条水平色条，颜色各异（如红(2) 长 3 像素、蓝(1) 长 5 像素），色条间水平不重叠。生成约束：门框之间无非背景像素阻挡单调路径；色条长度互不相等。

**规则**：
1. 找到两个门框各自的外部门洞单元格 A 和 B。
2. 计算 A 到 B 的所有最短单调路径的并集：每步只允许行或列方向上朝目标移近的步骤，仅经过黑(0) 背景像素。门洞间隙也纳入路径并集。
3. 从 A 出发，对路径并集中的每个单元格计算沿路径的最短距离 d（曼哈顿距离到 A）。
4. 按色条长度从短到长排序处理。对当前色条（颜色 C、长度 L）：将路径并集中 d mod L == 0 的所有尚未着色的单元格涂为颜色 C。
5. 处理完所有色条后，路径并集中仍未着色的单元格涂为黄(4)。
6. 门框和绿(3) 标记保持不变。色条本身保持不变。

**关键洞察**：路径并集中的分支意味着多个单元格可能有相同的距离值 d，它们会被同一周期着色——路径的分叉结构直接影响了周期条纹的视觉形态，这不同于线性通道上的简单周期重复。需对比多个示例才能发现"色条长度=周期"以及"短周期优先"的规则。

## 新题 9：递归种子展开按区域内外分色方案

**组合逻辑**：[递归展开·自相似替换] + [分区涂色·按边界框内外分色](创新：同一递归瓦片在区域内用主色、区域外用副色)

**来源原语**：递归展开/recursive_expand（58c02a16）、自相似替换/self_similar_sub（58c02a16）、前景背景分别替换/fg_bg_separate（58c02a16）、边界图例/border_legend（58c02a16）、分区涂色/zone_coloring（137f0df0）、按边界框内外分色/color_by_bounding_box_membership（137f0df0）、边界框/bounding_box（137f0df0）、框架分区/frame_partition（135a2760）

**依赖链**：从种子区域提取二值掩码 → 做一级递归展开得到扩展瓦片 → 灰色分隔线划分的各区域各有已有内容的边界框 → 边界框内部用红色版瓦片平铺、外部用栗色版瓦片平铺。递归展开和区域分色互为必需：没有展开就没有瓦片可铺；没有区域边界框就不知道用哪套配色。

将递归展开的种子瓦片按区域内外边界框分别用主色和副色铺满各分区。

**输入结构**：约 15x15 的网格，背景黑(0)。左上角有一个小矩形区域（如 4x4），内含红(2) 和黑(0) 构成的二值图案（红(2) 像素为前景），该区域的最后一行和最后一列为实心栗(9) 像素（L 形边界图例）。网格其余部分被蓝(1) 的满行/满列分割为 2~3 个矩形分区。每个分区内预先有一些散落的灰(5) 像素（3~8 个），形成一个不规则的 4-连通小区域，构成该分区的"内容"。生成约束：种子区域（去除栗(9) 边界后）的边长整除每个分区的行数和列数；各分区的灰(5) 内容区域的边界框严格小于分区本身。

**规则**：
1. 从左上角区域提取种子掩码：去除栗(9) 边界行和列，剩余区域中红(2) 为 1、黑(0) 为 0。
2. 一级递归展开：将种子掩码中每个 1（红(2)）替换为种子掩码本身（以红(2) 绘制），每个 0（黑(0)）替换为种子掩码本身（以栗(9) 绘制）。得到扩展瓦片。
3. 对每个蓝(1) 分隔的矩形分区，计算其内部灰(5) 像素的边界框（最小包围矩形）。
4. 将扩展瓦片平铺到该分区中：对于边界框内部的单元格，使用红(2) 版的瓦片像素（瓦片中为 1 的位置涂红(2)，为 0 的位置涂黑(0)）；对于边界框外部但仍在分区内的单元格，使用栗(9) 版的瓦片像素（瓦片中为 1 的位置涂栗(9)，为 0 的位置涂黑(0)）。
5. 灰(5) 像素被瓦片覆盖（不保留）。
6. 蓝(1) 分隔线和左上角种子区域（含栗(9) 边界）保持不变。

**关键洞察**：同一个递归瓦片在每个分区中以两种配色方案呈现，分界线是该分区内灰(5) 内容的边界框——边界框"内"用主色（红），"外"用副色（栗）。灰(5) 像素本身并不出现在输出中，它们的唯一作用是定义边界框位置。

## 新题 10：对角同余交叉点的环形印章

**组合逻辑**：[循环填充·同余类交错] × 2（两组反向对角线独立延伸） + [印章覆盖·交叉点印章](创新：印章位置由两组同余延伸的交叉点涌现) + [擦除]（模板环消耗后消失）

**来源原语**：循环填充/cyclic_fill（05269061）、同余类交错铺满/congruence_interlaced（05269061）、对角线/diagonal（05269061）、等距偏移/equidistant_offset（05269061）、印章覆盖/stamp（ac3e2b04）、交叉点印章环形/stamp_ring_at_cross（ac3e2b04）、标记环/marker_ring（ac3e2b04）、擦除/erase（fbf15a0b）

**依赖链**：两组反向斜率对角线各自做模 3 同余延伸 → 两组延伸线的交叉点被计算出来 → 交叉点涂为特殊色 → 在每个交叉点处印章一个环形 → 环形模板在印章完成后被擦除。交叉点的位置只能通过两组同余延伸的叠加涌现，单独一组对角线无法确定印章位置。

两组反向对角线各自做同余延伸后，在其交叉点处印章环形并擦除模板环。

**输入结构**：约 12x12 的网格，背景黑(0)。包含两组对角线段：第一组为 2~3 条红(2) 对角线段（斜率为左上→右下，即每步行+1列+1），每段 3~5 像素长；第二组为 2~3 条蓝(1) 对角线段（斜率为右上→左下，即每步行+1列-1），每段 3~5 像素长。此外，网格中有一个绿(3) 的 3x3 空心环（8 个绿(3) 像素环绕 1 个黑(0) 中心），不与任何对角线重叠。生成约束：各对角线段互不重叠，且两组对角线的同余延伸必然在网格内产生至少 2 个交叉点；绿(3) 环不位于任何预期交叉点的 3x3 邻域内。

**规则**：
1. 对每条红(2) 对角线段，做模 3 同余延伸：沿左上→右下方向，从该段所在的对角线出发，每隔 3 列偏移绘制平行对角线，仅覆盖黑(0) 背景像素，涂为红(2)。裁切到网格边界。
2. 对每条蓝(1) 对角线段，做模 3 同余延伸：沿右上→左下方向，从该段所在的对角线出发，每隔 3 列偏移绘制平行对角线，仅覆盖黑(0) 背景像素，涂为蓝(1)。裁切到网格边界。
3. 找到所有同时被红(2) 延伸和蓝(1) 延伸覆盖的单元格（即两组同余延伸的交叉点）。将这些单元格涂为黄(4)。
4. 以每个黄(4) 交叉点为中心，印章一个 3x3 绿(3) 空心环：将以该点为中心的 3x3 区域中 8 个外围单元格涂为绿(3)，但不覆盖红(2)、蓝(1) 或黄(4) 像素（仅覆盖黑(0) 背景）。中心保持黄(4)。超出网格边界的环像素丢弃。
5. 擦除原始的绿(3) 环模板（将其 8 个绿(3) 像素设为黑(0)）。

**关键洞察**：交叉点并非输入中存在的对象，而是两组独立同余延伸叠加后涌现的结构。印章形状来自输入中的模板环，但模板本身在使用后被擦除——它是一次性指令，不是输出内容。需对比多个示例才能确认交叉点涂黄、环形印章仅覆盖背景这两条规则。
