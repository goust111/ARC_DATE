## 新题 1：方向指示印章

**组合逻辑**：[形状匹配/shape_matching] → [标记指定观察方向/marker_view_dir](创新：方向指示从边界标记移到外部精灵的附属红像素上) → [印章覆盖/stamp_overlay](创新：印章方向由附属指示像素决定而非模板位置)

**来源原语**：形状匹配/shape_matching(42f14c03), 标记颜色配对/marker_color_pairing(414297c0), 标记指定观察方向/marker_view_dir(f341894c), 朝向决定粘贴侧/orientation_determines_side(4c177718), 印章覆盖/stamp_overlay(414297c0), 裁剪/crop(42f14c03), 外部精灵/external_sprite(414297c0), 标记像素/marker_pixel(414297c0)

**依赖链**：标记像素的颜色决定配对哪个外部精灵 → 该精灵的红色附属像素位置决定印章方向 → 方向与标记位置共同决定印章在目标矩形上的落点。三者缺一则输出不可确定。

在灰色目标矩形内部，根据标记像素的颜色找到对应的外部精灵，再依据精灵上的红色方向指示像素决定印章粘贴的朝向，将精灵图案印在标记像素旁。

**输入结构**：
- 约 15x15 网格，背景黑(0)。
- 中央有一个灰(5)填充矩形（约 8x8 至 10x10），矩形内部散布 2-3 个孤立的标记像素，每个标记像素颜色不同（例如蓝(1)、绿(3)、橙(7)），各标记像素距矩形边缘至少 2 格。
- 矩形外部有 2-3 个小型单色精灵体（4-连通，3-6 像素，不规则形状），每个精灵的颜色与矩形内的一个标记像素颜色相同。
- 每个外部精灵的边界框外侧恰好有一个红(2)像素与其 4-邻接（位于精灵边界框的上方、下方、左方或右方某一侧），作为方向指示。
- 不同精灵的边界框尺寸互不相同。不同示例中同类精灵的具体形状不同。
- 生成约束：所有精灵印章到矩形上后互不重叠；印章不超出矩形边界。

**规则**：
1. 裁剪灰色矩形到其边界框作为输出基底。
2. 对矩形内的每个标记像素，找到颜色相同的外部精灵。
3. 检查该精灵的红(2)指示像素相对于精灵边界框的位置——上方、下方、左方或右方——确定印章方向：
   - 红像素在精灵上方 → 精灵的顶边紧贴标记像素下方（精灵印在标记正下方）；
   - 红像素在精灵下方 → 精灵的底边紧贴标记像素上方（精灵印在标记正上方）；
   - 红像素在精灵左方 → 精灵的左边紧贴标记像素右方（精灵印在标记正右方）；
   - 红像素在精灵右方 → 精灵的右边紧贴标记像素左方（精灵印在标记正左方）。
4. 仅印章精灵自身颜色的像素（不印红色指示像素），将其绘制到输出基底的对应位置。超出输出边界的像素丢弃。
5. 若多个印章有重叠像素，距矩形左上角曼哈顿距离更近的标记像素对应的印章优先（距离相同则行号更小的优先，再相同则列号更小的优先）。
6. 标记像素本身保留原色不被印章覆盖。

**关键洞察**：红色指示像素永远不被印入输出——它仅编码印章的粘贴朝向。同一个精灵形状若搭配不同位置的红色指示像素，会被印在标记像素的不同侧；需要对比多个示例才能确认方向编码规则而非位置复制。

## 新题 2：面积驱动轨道滑动

**组合逻辑**：[计数/counting](创新：面积不再决定垂直位移而是轨道槽位步数) + [滑动/sliding](创新：从单步推进改为 N 步推进) + [朝近端扩展/toward_nearer_expand](创新：从单像素扩展改为整个对象的滑动方向和重涂色来源) → 碰撞排序（新增）

**来源原语**：计数/counting(b2bc3ffd), 位移等于面积/shift_equals_area(b2bc3ffd), 滑动/sliding(5168d44c), 沿轨道进一槽位/advance_one_slot(5168d44c), 轨道点/track_dot(5168d44c), 等距排列/evenly_spaced(5168d44c), 边缘条/edge_bar(642248e4), 朝近端扩展/toward_nearer_expand(642248e4), 重涂色/recolor(f341894c)

**依赖链**：每个对象的面积 → 确定滑动步数；对象与两侧边缘条的距离 → 确定滑动方向和重涂色颜色；多个对象在同一轨道上碰撞 → 必须按与目标条距离排序依次处理。面积、方向、碰撞三者交织决定最终位置和颜色。

多个不同大小的前景对象沿轨道各自滑动"面积数"个槽位，方向朝向较近的边缘条，滑动后重涂为该条的颜色；若发生碰撞则近者优先，远者停在碰撞前最后空位。

**输入结构**：
- 约 18x10 网格，背景黑(0)。
- 一条竖直轨道：在某一列上等距排列绿(3)单像素点（间距 S，约 2-3 格），贯穿网格中部。
- 2-3 个小型单色前景对象（4-连通，每个 2-5 像素，颜色各不相同，不使用绿(3)/蓝(1)/红(2)/黑(0)），每个对象覆盖恰好一个轨道点位置（该点被对象遮挡）。
- 两条全宽水平边缘条：蓝(1)位于第 0 行（顶部），红(2)位于最后一行（底部）。
- 生成约束：各对象互不重叠；每个对象的像素数不超过总轨道槽位数的一半；滑动后不会超出轨道范围（但可能相互碰撞）。

**规则**：
1. 对每个前景对象，计算其像素数 N。
2. 比较该对象中心行到蓝(1)顶部条和红(2)底部条的行距离，确定较近的条。
3. 沿轨道方向（竖直）将对象滑动 N 个槽位（每个槽位 = 轨道点间距 S），方向朝向较近的边缘条（离顶部条近则上滑，离底部条近则下滑）。若到两条距离相等，则朝上滑动。
4. 滑动后，将对象重涂为较近边缘条的颜色（蓝(1)或红(2)）。
5. 处理顺序：按各对象到其目标边缘条的初始距离排序，近者先处理。若一个对象滑动后会占据已被先处理对象占据的轨道位置，则该对象停在碰撞前的最后一个空槽位上。
6. 被对象离开的轨道点恢复为绿(3)；被对象新覆盖的轨道点被遮挡。

**关键洞察**：面积既是位移量又是碰撞的间接原因——面积大的对象移动远，更容易与其他对象碰撞。处理顺序取决于初始位置与目标条的距离而非面积本身，这意味着一个小对象可能因为离目标近而先处理，从而阻挡后续更大的对象。需要多个示例区分"面积=步数"与"面积=像素距离"。

## 新题 3：贪心直角路径网络与颜色角色互换

**组合逻辑**：[贪心遍历/greedy_traversal] + [画线/draw_line · 直角路径/right_angle_path](创新：从两点间 L 路径变为贪心链式 L 路径网络) → [颜色角色互换/color_role_swap](创新：互换对象不是精灵与线段，而是路径与端点)

**来源原语**：贪心遍历/greedy_traversal(3490cc26), 最近未访问优先/nearest_unvisited_first(3490cc26), 画线/draw_line(d4a91cb9), 直角路径/right_angle_path(d4a91cb9), 拐角由终点列定/corner_at_target_col(d4a91cb9), 颜色角色互换/color_role_swap(c6141b15), 端点像素/endpoint_pixel(d4a91cb9)

**依赖链**：贪心最近邻顺序 → 决定路径拓扑（谁连谁）；直角路径规则 → 决定路径几何（L 形拐弯位置）；颜色互换 → 全局翻转结果的视觉语义。必须先完成完整遍历并绘制所有路径，才能执行互换。

从红色起点出发，以贪心最近邻方式依次用黄色 L 形直角路径连接所有青色端点，完成后将路径颜色与端点颜色互换。

**输入结构**：
- 约 14x14 网格，背景黑(0)。
- 一个红(2)单像素作为起点。
- 4-6 个青(8)单像素散布在网格中。
- 没有任何两个像素（含红色）处于同一行或同一列。
- 生成约束：贪心最近邻遍历可以访问所有青像素（不会出现无法到达的情况）；各 L 形路径互不经过任何其他端点像素。

**规则**：
1. 从红(2)像素出发，找到曼哈顿距离最近的未访问青(8)像素。距离相同时，选行号更小的；行号也相同则选列号更小的。
2. 从当前像素绘制黄(4) L 形直角路径：先水平画到目标像素所在列，再垂直画到目标像素所在行。拐角位于当前像素的行与目标像素的列交汇处。路径不覆盖起点和终点像素本身。
3. 将当前位置移至该青像素，重复步骤 1-2 直到所有青像素都已访问。
4. 执行颜色角色互换：所有黄(4)路径像素变为青(8)，所有原始青(8)端点像素变为黄(4)，红(2)起点像素也变为黄(4)。
5. 背景像素不变。

**关键洞察**：互换后输出的视觉含义反转——"连接线"呈现为青色（原来是端点色），"节点"呈现为黄色（原来是路径色）。求解者必须逆向推断：先"反转"颜色以还原路径结构，再分析贪心遍历顺序和 L 形规则。仅看一个示例可能误以为青色是路径、黄色是端点，需要多个示例才能发现颜色互换的存在。

## 新题 4：对接拼装与涌现孔洞填充

**组合逻辑**：[拼接/stitch · 同色标记对齐对接/same_color_dock] + [填充/fill · 封闭孔洞/enclosed_hole](创新：被填充的孔洞不来自任何单个对象，而是多个对象对接后涌现的新封闭区域)

**来源原语**：拼接/stitch(e9fc42f2), 同色标记对齐对接/same_color_dock(e9fc42f2), 标记侧面决定方向/marker_side_dir(e9fc42f2), 连接标记/connector_marker(e9fc42f2), 填充/fill(e73095fd), 封闭孔洞/enclosed_hole(e73095fd), 连通分量/connected_component(a8d7556c)

**依赖链**：连接标记颜色配对 → 确定哪些对象对接；标记的暴露侧 → 确定对接方向和平移向量；对接后的组合形状 → 涌现出新的封闭黑色区域；封闭检测 → 确定哪些区域被填充。对接结果改变了填充的输入结构。

将带有彩色连接标记的灰色对象按同色标记对接拼装，拼装后在组合体内涌现的封闭黑色区域用黄色填充。

**输入结构**：
- 约 20x20 网格，背景黑(0)。
- 3-4 个灰(5)前景对象（4-连通，每个 8-15 像素），形状不规则，各有凹凸但单独观察时内部无封闭孔洞（即每个对象的边界框内，所有黑色像素都与外部黑色区域 4-连通）。
- 每个对象的边缘上有 1-2 个单像素彩色连接标记（如蓝(1)、绿(3)、橙(7)），每种标记颜色在所有对象中恰好出现两次，形成配对。
- 每个连接标记的「暴露侧」：标记像素在上/下/左/右四个方向中，有且仅有一个方向的相邻像素是背景黑(0)而非对象灰(5)，该方向即为暴露侧。
- 生成约束：按规则对接后，至少形成一个新的封闭黑色区域（4-连通黑色像素完全被灰色像素包围）。对接时不同对象的灰色像素不会重叠（取并集）。

**规则**：
1. 对每种出现两次的连接标记颜色，找到携带该颜色的两个对象。
2. 确定每个标记的暴露侧方向。
3. 平移其中一个对象，使两个同色标记 4-邻接，且各自的暴露侧彼此相对（例如一个标记暴露侧朝右，另一个朝左，则两者左右邻接）。
4. 连接标记配对按标记在输入中首次出现的扫描顺序处理（从上到下、从左到右扫描，先遇到的标记颜色先处理）。若平移导致对象像素与已放置的像素重合，保留两者的并集。
5. 对接完成后，将所有连接标记像素替换为灰(5)。
6. 在拼装后的组合结构中，找到所有被灰(5)像素完全 4-连通包围的黑(0)区域（即不与网格外部黑色区域连通的黑色连通分量），填充为黄(4)。

**关键洞察**：没有任何单个对象拥有封闭孔洞——所有被填充的黄色区域都是对接后才涌现的。对接顺序和连接方向共同决定了哪些凹陷会被封闭，而标记的暴露侧朝向是推理对接方向的唯一线索。需要多个示例来确认"暴露侧相对"这一对接规则。

## 新题 5：射线星图与轨道点终止重涂

**组合逻辑**：[射线延伸/ray_extend · 基数方向循环填/cardinal_cyclic_fill](保留循环填模式) + [轨道点/track_dot](创新：轨道点从滑动槽位变为射线终止器) + [重涂色/recolor](创新：终止点被重涂为射线在该位置"本应涂"的颜色)

**来源原语**：射线延伸/ray_extend(fe9372f3), 基数方向循环填/cardinal_cyclic_fill(fe9372f3), 对角均匀色/diag_uniform_color(fe9372f3), 十字图案/plus_pattern(fe9372f3), 轨道点/track_dot(5168d44c), 等距排列/evenly_spaced(5168d44c), 重涂色/recolor(f341894c)

**依赖链**：红色十字 → 八方向射线的起点；轨道点位置 → 基数射线的终止距离（决定射线长度和循环模式截断位置）；射线到终止点的距离 → 计算该点在循环中的颜色 → 重涂轨道点颜色。射线几何和重涂颜色双重依赖轨道点的位置。

从红色十字向八方延伸射线——基数方向用青-青-黄循环填色、对角方向用灰色均匀填色；基数射线遇到轨道点即停，并将该轨道点重涂为射线在该位置本应涂的循环颜色。

**输入结构**：
- 约 15x15 网格，背景黑(0)。
- 一个红(2)五像素十字图案（中心 + 四个基数方向邻居），位于网格中偏离中心的位置。
- 绿(3)单像素轨道点等距排列在十字中心所在行（水平方向），位于十字两侧各至少 2 个，间距 2-4 格。
- 蓝(1)单像素轨道点等距排列在十字中心所在列（竖直方向），位于十字上下各至少 2 个，间距 2-4 格。
- 轨道点不与红色十字像素重叠。
- 生成约束：所有轨道点与十字臂端的距离至少为 1（射线至少画出一个像素才遇到轨道点）。

**规则**：
1. 保留红(2)十字的所有像素。
2. 从十字的每个基数方向臂端（即十字在上/下/左/右方向的末端像素）开始，沿该方向向外逐像素延伸，颜色按周期模式"青(8)、青(8)、黄(4)"循环（距臂端 1 格→青(8)，2 格→青(8)，3 格→黄(4)，4 格→青(8)，5 格→青(8)，6 格→黄(4)，以此类推）。射线在遇到第一个轨道点之前停止——即轨道点所在格不被射线颜色覆盖。
3. 从十字中心的四个对角邻格（左上、右上、左下、右下）开始，各沿对角方向延伸灰(5)射线直到网格边缘。
4. 对每个终止了基数射线的轨道点（即该轨道点是某条基数射线方向上第一个遇到的非黑像素），计算该轨道点到对应臂端的距离 D（格数），按循环模式确定射线在该距离处"本应涂"的颜色（D mod 3 == 1 → 青(8)，D mod 3 == 2 → 青(8)，D mod 3 == 0 → 黄(4)）。将该轨道点重涂为此颜色。
5. 未被任何基数射线到达的轨道点保持原色（绿(3)或蓝(1)）。
6. 若基数射线与对角射线在某像素位置重叠，基数射线颜色优先。

**关键洞察**：轨道点既是射线的"墙壁"又是射线颜色的"吸收器"——点的最终颜色编码了射线到该点的距离信息。十字偏离中心意味着四条基数射线长度各不相同，四个轨道点被重涂为不同的循环颜色。仅看一个示例无法区分"轨道点始终变青"和"轨道点颜色随距离变化"。

## 新题 6：逐对象外扩与涌现围合填充

**组合逻辑**：[拉伸/extrude](创新：从整个网格边缘外扩变为逐对象 1 像素膨胀) + [连通分量/connected_component · 封闭区域/enclosed_region](保留) + [填充/fill](创新：填充对象不是矩形内部而是多个膨胀边框围合的涌现孔洞) + [重涂色/recolor](新增：膨胀重叠区域的特殊标记)

**来源原语**：拉伸/extrude(49d1d64f), 边缘延伸角落留黑/edge_extrude_corner_black(49d1d64f), 连通分量/connected_component(a8d7556c), 封闭区域/enclosed_region(a8d7556c), 填充/fill(e73095fd), 封闭孔洞/enclosed_hole(e73095fd), 重涂色/recolor(a8d7556c)

**依赖链**：每个对象独立膨胀 → 膨胀边框相遇产生重叠标记 → 多个膨胀边框的组合形成封闭围合 → 围合内部被填充。任何一个环节缺失，输出都无法确定：不膨胀就没有边框，不检测重叠就无法标记，不检测围合就不知道填什么。

每个前景对象向外膨胀 1 像素形成灰色边框，两个对象边框重叠处标红，当多个对象的边框围合出封闭黑色区域时用黄色填充。

**输入结构**：
- 约 14x14 网格，背景黑(0)。
- 3-5 个小型单色前景对象（4-连通，每个 3-8 像素，每个对象颜色不同，不使用灰(5)/红(2)/黄(4)/黑(0)），散布在网格中。
- 部分对象距离较近（膨胀后边框会重叠），部分较远（不重叠）。
- 生成约束：至少有一组相邻对象，其膨胀边框的组合能围合出至少一个封闭黑色区域。对象本身不互相 4-邻接（相距至少 2 格）。

**规则**：
1. 对每个前景对象，计算其 1 像素膨胀边框：所有与该对象至少一个像素 4-邻接的黑(0)背景格。
2. 每个膨胀格的归属：
   - 若仅被一个对象的膨胀覆盖，涂灰(5)。
   - 若被两个或以上对象的膨胀同时覆盖，涂红(2)。
3. 原始对象像素保留其原色，不被膨胀覆盖。
4. 完成所有膨胀和重叠标记后，在整个网格中寻找所有 4-连通黑(0)区域，判断它们是否被非黑像素（原对象色、灰(5)、红(2)的任意组合）完全 4-连通包围（即该黑色连通分量无法通过 4-连通路径到达网格的任何边缘行/列的黑像素）。
5. 将所有被完全包围的黑(0)连通分量填充为黄(4)。

**关键洞察**：没有任何单独的对象能形成封闭围合——黄色区域仅在多个对象的膨胀边框共同封闭缝隙时涌现。红色重叠标记不是装饰性的，它揭示了哪些边框贡献于围合。改变任一对象的位置会改变围合是否存在，体现了全局涌现效应。

## 新题 7：周期填充的视线约束

**组合逻辑**：[填充/fill · 平移等价/translation_equivalence](保留周期填充逻辑) × [视线可见/line_of_sight_visible · 视线遮挡判断/line_of_sight_blocked](创新：从贪心路径寻找中的可见性判断变为填充操作的门控条件) + [边界标记/boundary_marker · 标记指定观察方向/marker_view_dir](创新：标记不再指向微型片段而是向内投射可见区域)

**来源原语**：填充/fill(484b58aa), 平移等价/translation_equivalence(484b58aa), 平移向量决定填充/translation_sets_fill(484b58aa), 周期性格/periodic_lattice(484b58aa), 缺失像素/missing_pixel(484b58aa), 视线可见/line_of_sight_visible(3490cc26), 视线遮挡判断/line_of_sight_blocked(3490cc26), 边界标记/boundary_marker(f341894c), 标记指定观察方向/marker_view_dir(f341894c)

**依赖链**：周期平移分析 → 确定每个黑色空缺"应该是什么颜色"；边界标记的观察方向 → 定义视线射线；墙壁像素 → 遮挡视线。最终输出 = 周期颜色 ∩ 视线可达。两个独立的分析系统（周期结构 vs 视线几何）在每个空缺像素处交汇，缺一不可。

一个有黑色空缺的周期彩色图案，利用周期平移向量确定每个空缺应填什么颜色，但仅填充从边界红色标记沿视线可见的空缺，被灰色墙壁遮挡的空缺保持黑色。

**输入结构**：
- 约 14x14 网格。
- 网格内有一个由 2-3 种非黑、非红、非灰颜色构成的周期彩色图案（如蓝(1)、绿(3)、橙(7)），其中部分像素缺失为黑(0)。所有可见的非黑、非灰、非红像素之间遵循一个一致的平移周期。
- 2-4 个灰(5)单像素或小型灰色块（2-3 像素，4-连通）散布在图案区域内，作为视线遮挡"墙壁"。这些灰像素不属于周期图案。
- 在网格的边界行/列上（第 0 行、最后一行、第 0 列、最后一列），有 2-4 个红(2)标记像素。每个标记的观察方向为垂直于其所在边向内：顶行标记向下看，底行标记向上看，左列标记向右看，右列标记向左看。
- 生成约束：至少有一个黑色空缺被墙壁遮挡而不可见；至少有一个黑色空缺从某标记可见而被填充。

**规则**：
1. 忽略墙壁和标记，仅对非黑、非灰、非红的像素进行周期分析：找到使重叠可见像素支持度最大且无颜色矛盾的非零平移向量（如 484b58aa 所述）。
2. 利用该平移向量及其逆，对每个黑(0)空缺确定其所属周期等价类中的可见颜色，得出该空缺"应填"的颜色。
3. 对每个红(2)标记，沿其观察方向投射视线射线（水平或垂直直线）。一个黑色空缺被标记"可见"当且仅当：标记与该空缺在同一行（左/右方向标记）或同一列（上/下方向标记），且标记与空缺之间的直线路径上不存在任何灰(5)墙壁像素，也不存在任何非黑的周期图案像素（非黑非灰非红像素也阻挡视线）。
4. 仅填充至少从一个标记可见的黑色空缺，填充颜色为步骤 2 确定的周期颜色。
5. 不可见的空缺保留黑(0)。
6. 标记像素、墙壁像素和所有已有的周期图案像素保持不变。

**关键洞察**：周期分析回答"填什么颜色"，视线分析回答"填不填"——两个独立的推理系统在每个空缺处交汇。一个被墙壁挡住的空缺即使周期颜色完全确定也不会被填充。仅看一个示例无法分辨"只填靠近边界的空缺"和"只填视线可达的空缺"。

## 新题 8：格点补全与形状键孔洞填色

**组合逻辑**：[补全/completion · 笛卡尔积缺位填充/cartesian_product_gap_fill](保留格点补全) → [形状匹配/shape_matching · 归一化形状对应/normalized_match](创新：从选择带孔对象变为在补全后的精灵中为孔洞匹配颜色) + [填充/fill](创新：填充对象是格点补全后才完整出现的所有精灵的孔洞) + [忽略干扰项/ignore_distractors](保留)

**来源原语**：补全/completion(5b526a93), 笛卡尔积缺位填充/cartesian_product_gap_fill(5b526a93), 格点对齐/lattice_alignment(5b526a93), 同形精灵体/identical_sprite(5b526a93), 形状匹配/shape_matching(42f14c03), 归一化形状对应/normalized_match(42f14c03), 忽略干扰项/ignore_distractors(42f14c03), 填充/fill(e73095fd), 带孔对象/object_with_holes(42f14c03), 标记形状/marker_shape(42f14c03)

**依赖链**：格点结构识别 → 补全缺失位置 → 新精灵也带有孔洞 → 需要确定孔洞的填充色 → 必须通过外部标记形状的归一化匹配来确定 → 干扰标记必须被排除。补全在先（否则不知道有多少孔洞需要填），形状匹配在后（确定颜色），两者紧耦合。

在部分填充的矩形格点上补全缺失的灰色精灵副本，然后通过外部标记形状与精灵内部孔洞的归一化匹配来确定每种孔洞的填充颜色。

**输入结构**：
- 约 20x20 网格，背景黑(0)。
- 4-6 个灰(5)精灵，外形完全相同（4-连通，每个 10-20 像素），排列在一个矩形格点上（行间距和列间距均匀）。至少有一个完整的行和一个完整的列被占据，其余格点位置为空。
- 每个精灵内部有恰好 2 个不同形状的孔洞（边界框内的 4-连通黑色区域），所有精灵的孔洞在相对位置和形状上完全一致。两个孔洞的形状不同（例如一个是 3 像素的 L 形连通区域，另一个是 2 像素的直线连通区域）。
- 网格上格点区域之外散布 3-4 个小型彩色标记形状（每个 2-5 像素，4-连通，各使用不同颜色，不使用灰(5)/黑(0)），其中恰好 2 个标记的归一化形状（将形状平移使其边界框左上角对齐原点后逐像素比较）分别与精灵的两种孔洞形状匹配。其余标记为干扰项。
- 生成约束：格点至少缺 2 个位置需要补全；干扰标记的形状与任何孔洞形状都不匹配。

**规则**：
1. 识别精灵外形和格点结构（行起始位置集合和列起始位置集合）。
2. 在所有笛卡尔积位置（行 × 列）中找到空缺位置，印章灰(5)精灵副本填充所有空缺。
3. 对精灵内部的两种孔洞形状，分别将其归一化（平移使边界框左上角位于原点）。
4. 对每个外部标记形状，同样归一化后与两种孔洞形状逐像素比较。匹配成功的标记颜色即为该种孔洞的填充色。不匹配的标记为干扰项。
5. 用匹配的标记颜色填充所有精灵（含原始精灵和新补全精灵）中对应形状的孔洞。
6. 移除所有外部标记形状（替换为黑(0)背景）。

**关键洞察**：格点补全必须先于孔洞填充——新补全的精灵同样有孔洞需要填充。填充颜色由形状匹配决定而非标记位置或颜色本身——将一个 L 形蓝标记和一个直线形绿标记对调颜色会改变孔洞填充结果。干扰标记考验求解者是否正确理解了匹配规则。

## 新题 9：逻辑或合并后的近端扩展

**组合逻辑**：[逻辑或合并/logical_or_merge](保留双面板合并) + [延伸/extend · 朝近端扩展/toward_nearer_expand](创新：从单个控制像素的延伸变为合并后涌现的控制像素集合的延伸) + [边缘条/edge_bar · 标记在两边之间/marker_between_edges](保留)

**来源原语**：逻辑或合并/logical_or_merge(195ba7dc), 掩码/mask(195ba7dc), 分隔列/separator_column(195ba7dc), 沿轴对齐/axis_aligned(195ba7dc), 延伸/extend(642248e4), 朝近端扩展/toward_nearer_expand(642248e4), 边缘条/edge_bar(642248e4), 控制像素/control_pixel(642248e4), 标记在两边之间/marker_between_edges(642248e4), 重涂色/recolor(195ba7dc)

**依赖链**：两个面板逻辑或合并 → 产生新的控制像素集合（包含仅属于一个面板的和两个面板共有的）→ 每个控制像素到两条边缘条的距离 → 决定扩展方向和颜色 → 两面板共有的控制像素用特殊冲突色扩展。合并改变了控制像素的集合，距离判断改变了扩展结果。

将红色分隔列两侧的面板按逻辑或合并控制像素，然后每个合并后的控制像素向较近的边缘条方向扩展一格，扩展色取自该边缘条；若控制像素在两个面板中都出现，则扩展色改为黄色冲突标记。

**输入结构**：
- 约 22x10 网格，背景黑(0)。
- 一条全高红(2)分隔列将网格分为左右两个等大面板（各约 10x10）。
- 每个面板内部结构：
  - 两条全高竖直边缘条：蓝(1)位于面板最左列，绿(3)位于面板最右列。
  - 边缘条之间散布 3-5 个橙(7)单像素控制像素。
- 两个面板的边缘条位置对称（左面板的蓝条在左、绿条在右；右面板同理），但控制像素位置不同（部分重合，部分各自独有）。
- 生成约束：至少有一个位置两面板都有控制像素（重合点）；至少有一个位置仅一个面板有控制像素（非重合点）；至少有一个控制像素到两条边缘条等距。

**规则**：
1. 移除红色分隔列。将两个面板的控制像素逻辑或合并到一个面板尺寸的画布上：若左面板或右面板（或两者）在某位置有橙(7)像素，则合并结果中该位置为橙(7)。边缘条取左面板的（蓝(1)在左列，绿(3)在右列）。
2. 记录每个合并后的橙(7)控制像素的来源：仅来自左面板、仅来自右面板、或两面板共有。
3. 对每个合并后的控制像素，比较其列坐标到蓝(1)边缘条和绿(3)边缘条的水平距离：
   - 若离蓝条更近：向蓝条方向（左方）在同一行扩展一个像素。
   - 若离绿条更近：向绿条方向（右方）在同一行扩展一个像素。
   - 若等距：同时向两个方向各扩展一个像素。
4. 扩展像素的颜色：
   - 若该控制像素仅来自一个面板，扩展色为它朝向的边缘条颜色（蓝(1)或绿(3)）。
   - 若该控制像素为两面板共有，扩展色为黄(4)。
   - 等距情况下两个扩展像素都使用同一规则确定颜色。
5. 若扩展像素落在已有非黑像素（控制像素或边缘条）上，该扩展被取消（不覆盖）。
6. 控制像素本身保留橙(7)色。

**关键洞察**：逻辑或合并不仅增加了控制像素的数量，还创造了"共有像素"这一类别——它们的扩展颜色与"独有像素"不同。一个在左面板中离蓝条近的像素合并后仍离蓝条近（位置不变），但如果右面板也有该位置的像素，它就变成共有像素，扩展色从蓝/绿变为黄。需要多个示例对比才能发现"共有 vs 独有"影响扩展颜色。
