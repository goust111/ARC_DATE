## 新题 1：对角线分区下的双域边缘-内部重涂色

**组合逻辑**：[填充/fill + 重涂色/recolor](对角线标记重新定义区域边界) + [对角线边界/diagonal_boundary](从三角楔形区域提取，改造为格子分区线) + [边缘与内部区分/perimeter_interior_distinction](从全局格子改造为分区内局部判定)

**来源原语**：填充/fill (d5d6de2d, 896d5239), 重涂色/recolor (8a371977), 格子结构/lattice + 单元格区域/cell_region + 行列阵列位置/row_column_position + 边缘与内部区分/perimeter_interior_distinction (8a371977), 对角线标记/diagonal_marker + 对角线边界/diagonal_boundary (896d5239), 标记像素/marker_pixel (896d5239)

**依赖链**：对角线标记像素定义一条穿过格子的分区线 -> 分区线将格子单元格划分为两个域 -> 每个域内独立判定边缘/内部 -> 边缘/内部身份决定重涂色颜色，且两个域使用不同色对。删去分区线则无法确定域边界，删去边缘/内部判定则无法确定颜色。

对角线标记将格子切分为两个域，域内边缘单元格与内部单元格分别重涂为不同颜色，两域使用不同色对。

**输入结构**：黑(0)背景上，灰(5)像素构成一个规则格子结构（单像素宽的水平线和竖直线交叉），将网格分隔为至少 4x4 的矩形单元格阵列（每个单元格约 2x2 至 4x4 像素），所有单元格初始填充黑(0)。网格约 20x20 至 25x25。绿(3)标记像素散布于若干单元格内（每个被标记单元格恰好包含一个绿像素），这些绿像素沿一条近似 45 度的对角线排列，从格子阵列的某个边缘单元格延伸到对侧边缘单元格。生成约束：对角线上相邻两个绿标记所在的单元格在行列坐标上各差 1（即严格沿主对角线方向穿过格子阵列）；每个单元格内至多一个绿标记。

**规则**：
1. 识别灰(5)格子结构和其定义的矩形单元格阵列。记阵列共 R 行 C 列。
2. 找到所有含绿(3)标记的单元格，它们定义一条从阵列某角到对角的对角线路径。
3. 将单元格分为三类：(a) 对角线单元格——包含绿标记的单元格；(b) 上域单元格——在对角线严格上方（行列坐标满足 col < diag_col_at_row）的单元格；(c) 下域单元格——在对角线严格下方的单元格。
4. 对上域：该域内紧邻对角线或紧邻格子阵列外边缘的单元格视为该域的"边缘单元格"，其余为"内部单元格"。上域边缘单元格填充红(2)，上域内部单元格填充蓝(1)。
5. 对下域：同理判定边缘与内部。下域边缘单元格填充黄(4)，下域内部单元格填充橙(7)。
6. 对角线单元格本身填充灰(5)（与格子线同色，视觉上融入格子）。
7. 格子线像素保持灰(5)不变。

**关键洞察**：对角线标记不是要填充的三角区域（与 896d5239 不同），而是一条分类边界；它将一个统一的格子阵列切分为两个子域，使得同一个单元格在全局格子中可能是内部，但在其所属子域中变为边缘——"边缘"的含义被分区线重新定义了。两个域的色对映射需要对比多个示例才能归纳。

## 新题 2：空心框擦除后内部填充的重力压缩

**组合逻辑**：[擦除/erase + 填充/fill](空心框的边界擦除与内部填充) -> [重力下落/gravity_drop](填充像素在框擦除后受重力作用滑动) + [标记指示方向/marker_indicates_dir](边缘标记线确定重力方向)

**来源原语**：擦除/erase + 填充/fill + 空心矩形/hollow_rectangle + 封闭区域/enclosed_region + 边框包围内部/frame_encloses_interior + 空心内部变色/interior_recolor (d5d6de2d), 重力下落/gravity_drop + 边缘标记线/edge_marker_line + 标记指示方向/marker_indicates_dir (afe3afe9)

**依赖链**：边缘标记线确定重力方向 -> 空心框边界被擦除 -> 框的封闭内部被填充为指定颜色 -> 填充像素作为自由物质在重力方向上滑动至网格边缘或堆叠 -> 多个框的填充物可能在重力方向上合并堆叠。删去框则无填充物可供重力作用；删去重力则输出仅是静态填充；删去标记线则重力方向不确定。

擦除多个空心矩形框的边界，将各自内部填充为绿色，然后按边缘标记线指示的方向施加重力，使填充像素滑落堆叠。

**输入结构**：黑(0)背景上有 2 至 4 个红(2)像素构成的空心矩形框（单像素宽边框，内部全黑，每个框的边界框在 3x3 至 7x7 之间）。各框互不重叠且互不相邻（边界框之间至少间隔 1 像素）。网格的一条完整边缘（上、下、左、右之一）被蓝(1)像素填满，形成一条边缘标记线。网格约 15x15 至 20x20。生成约束：所有红框的边框像素严格在网格内部（不接触网格边缘），蓝标记线恰好占据一条边缘的全部像素。

**规则**：
1. 识别蓝(1)边缘标记线所在的边缘。按顺时针边缘行进规则确定重力方向：顶边 -> 向右，右边 -> 向下，底边 -> 向左，左边 -> 向上。
2. 将所有红(2)框边界像素擦除为黑(0)。
3. 对每个原空心框，识别其严格内部区域（原先被框边界包围的黑色矩形区域），将该区域所有像素填充为绿(3)。
4. 擦除蓝(1)边缘标记线（全部变为黑(0)）。
5. 对所有绿(3)像素施加重力：每个绿像素沿重力方向滑动，直到碰到网格边缘或另一个绿像素时停止。处理顺序：沿重力方向从远端到近端逐个处理（例如重力向下时，从最底行的绿像素开始向上逐行处理），保证不会出现穿越。
6. 输出最终网格：仅包含黑(0)背景和重力压缩后的绿(3)像素。

**关键洞察**：空心框的边界在源题(d5d6de2d)中只是标记要删除的东西，但这里擦除边界后释放出的填充矩形成为重力场中的自由物质——不同大小的框产生不同面积的填充块，重力压缩后它们在同一方向上堆叠，最终形态取决于各框内部的宽度和面积而非框的位置。重力方向的编码规则（顺时针边缘映射）需要对比多个示例才能归纳。

## 新题 3：散布对象计数决定模板精灵体的缩放倍率

**组合逻辑**：[计数/counting](统计散布对象数量) -> [像素放大/pixel_scaling](计数值作为缩放因子) -> [平铺/tiling + 控制像素对应副本/control_pixel_to_copy](缩放后的模板沿控制线复制)

**来源原语**：计数/counting + 连通分量/connected_component + 数量决定边长/count_determines_side (d0f5fe59), 像素放大/pixel_scaling (4522001f), 模板精灵体/template_sprite + 控制像素行/control_pixel_line + 控制像素对应副本/control_pixel_to_copy + 间距保持一致/gaps_preserved (9b2a60aa), 重涂色/recolor (9b2a60aa)

**依赖链**：计数散布对象得到 N -> N 作为像素放大因子将模板精灵体缩放 -> 缩放后的模板沿控制像素行复制，每个副本重涂为对应控制像素的颜色，副本间距由控制像素间距按 N 倍展开。删去计数则缩放因子未知；删去模板则无内容可缩放；删去控制线则副本数量和颜色不确定。

统计网格中散布小对象的数量 N，将模板精灵体的每个像素放大为 NxN 块，然后沿控制像素行排列多个缩放副本。

**输入结构**：黑(0)背景上有三类元素。(a) 模板精灵体：一个红(2)的 4-连通单色小图形（3 至 6 像素），位于网格左上区域。(b) 控制像素行：一行水平排列的孤立像素（各像素颜色各异，其中恰好一个为红(2)与模板同色），位于网格底部某一行，各控制像素之间间隔 1 至 3 个黑背景像素。(c) 散布对象：2 至 4 个灰(5)的 4-连通小图形（每个 2 至 4 像素），散布在网格右半区域，各对象互不相邻且不与模板或控制线接触。网格约 20x25 至 25x30。生成约束：控制像素的间距和缩放后模板的尺寸保证所有副本能在网格宽度内排下且互不重叠。

**规则**：
1. 识别红(2) 4-连通模板精灵体，记录其形状（相对像素坐标集合）和边界框。
2. 识别灰(5) 4-连通散布对象，计数得到 N。
3. 将模板精灵体像素放大 N 倍：每个像素变为 NxN 的色块，边界框从 (h, w) 变为 (h*N, w*N)。
4. 读取控制像素行，从左到右排列。与红(2)控制像素对应的副本是模板自身（保持红色）；其他控制像素对应的副本使用该控制像素的颜色重涂。
5. 副本排列：以控制像素行的位置为基准，每个控制像素的水平位置映射为对应缩放副本的左边缘列坐标。具体地，设控制像素行中相邻两个像素的列间距为 d，则对应两个副本的左边缘列间距为 d * N。所有副本的底边行与控制像素行对齐。
6. 清除原始模板、散布对象和控制像素行；输出仅包含黑背景和排列好的缩放副本。

**关键洞察**：散布的灰色对象不参与输出的任何视觉内容——它们只是计数令牌，其数量编码了缩放因子。这与 d0f5fe59 中对象数量决定输出边长的思路同构，但在这里数量决定的是模板的缩放倍率而非网格大小。求解者需要对比不同示例中散布对象数量与输出模板尺寸的对应关系，才能归纳出"数量即缩放因子"这一非显然规则。

## 新题 4：四向对称面板裁剪后按接触边重涂色

**组合逻辑**：[裁剪/crop + 四向反射对称/four_way_reflective_symmetry](提取对称面板的典范象限) -> [重涂色/recolor + 接触侧定色/contact_side_color](象限边界作为隐式侧边标记)

**来源原语**：裁剪/crop + 前景面板/foreground_panel + 象限/quadrant + 四向反射对称/four_way_reflective_symmetry + 角落象限提取/corner_quadrant_extraction (73182012), 重涂色/recolor + 多色对象/multicolor_obj + 接触侧定色/contact_side_color + 包含于/contained_in (c3fa4749)

**依赖链**：识别面板的四向反射对称 -> 提取左上象限作为典范区域 -> 象限内的小对象各自接触象限的某一条边 -> 接触边的方位决定该对象的输出颜色。删去对称识别则无法确定象限边界（面板裁剪位置不确定）；删去接触边规则则无法确定颜色。

从一个四向对称的大面板中提取左上象限，然后根据象限内每个小对象接触象限哪一边来决定其重涂颜色。

**输入结构**：灰(5)背景上有一个较大的蓝(1)前景面板（偶数行偶数列，约 12x12 至 16x16 像素），面板展示四向反射对称（左右、上下、180 度）。面板内嵌入若干小的非蓝单色 4-连通图形（每个 2 至 5 像素），这些小图形在面板内的排布也遵守四向对称（即四个象限内小图形的位置互为镜像）。每个小图形在其所在象限内恰好接触象限矩形边界的一条边（上、下、左、右之一），且不同时接触两条边。小图形在输入中统一为红(2)色。网格约 18x18 至 22x22。生成约束：面板严格位于网格内部（不接触网格边缘），每个象限内有 2 至 4 个小图形，各接触不同的边。

**规则**：
1. 识别蓝(1)前景面板的边界框并裁剪。
2. 验证面板具有四向反射对称：左上象限水平翻转 = 右上象限，垂直翻转 = 左下象限，180 度旋转 = 右下象限。
3. 提取左上象限（面板行数/2 x 面板列数/2）。
4. 在左上象限中找到所有红(2) 4-连通小图形。
5. 对每个小图形，判断它接触象限矩形的哪一条边（图形至少有一个像素位于象限的第 0 行/最末行/第 0 列/最末列）：
   - 接触上边（第 0 行）-> 重涂为绿(3)
   - 接触右边（最末列）-> 重涂为黄(4)
   - 接触下边（最末行）-> 重涂为橙(7)
   - 接触左边（第 0 列）-> 重涂为品红(6)
6. 蓝(1)面板像素保持不变。输出为重涂色后的左上象限。

**关键洞察**：象限的边界在源题(73182012)中只是裁剪线，但在这里它同时充当了侧边标记的角色——对象接触的是象限边界而非显式的标记像素。这意味着求解者必须先正确识别对称并确定象限切割位置，才能知道每个对象"接触哪一边"——象限切割位置的错误会导致所有颜色判断错误。边-颜色映射需要对比多个示例才能确定。

## 新题 5：空心框界定的平移图案相位偏移区

**组合逻辑**：[补全/complete + 平移对称/translational_symmetry](将部分图案扩展为全幅平铺) + [擦除/erase + 空心矩形/hollow_rectangle](框边界标记相位偏移区域后被擦除) + [相位偏移/phase_shift](框内部的图案发生相位偏移)

**来源原语**：补全/complete + 平移周期图案/translation_pattern + 平移对称/translational_symmetry + 相位偏移/phase_shift (caa06a1f), 擦除/erase + 空心矩形/hollow_rectangle + 封闭区域/enclosed_region + 边框包围内部/frame_encloses_interior (d5d6de2d)

**依赖链**：识别前景像素的平移周期 -> 将部分图案补全为全幅平铺 -> 识别空心矩形框界定的区域 -> 框内部的图案整体向右平移一个周期单元的列宽 -> 框边界被擦除。框定义了相位偏移发生在哪里；图案定义了被偏移的内容；两者缺一不可。

将部分平移图案补全为全幅，然后在空心矩形框圈定的区域内将图案相位右移一个周期，最后擦除框边界。

**输入结构**：非黑背景色（由网格边缘最常见颜色推断，如灰(5)）上有蓝(1)前景像素构成的部分平移周期图案，图案覆盖网格的约 60%-80% 区域（其余为纯背景）。平移周期为 (pr, pc)，其中 pc >= 2。网格中还有 1 至 2 个红(2)像素构成的空心矩形框（单像素宽边框），框的尺寸在 4x4 至 8x8 之间，框内部全为背景色或部分包含蓝色图案像素。框不与网格边缘接触，框之间不重叠。网格约 15x15 至 20x20。生成约束：框的宽度至少为 pc+2（保证框内部至少包含一个完整周期列宽）；图案的平移周期在行和列方向上均至少为 2。

**规则**：
1. 从网格边缘推断背景色。
2. 检测蓝(1)前景像素的平移周期 (pr, pc)。
3. 将图案通过平移对称补全，使蓝(1)像素覆盖整个网格（忽略红框，假设框下方也应有图案）。
4. 识别所有红(2)空心矩形框，确定各框的严格内部区域。
5. 对每个框的内部区域：将该区域内的图案整体向右循环平移 pc 列（即一个完整周期列宽）。溢出右边界的像素循环回到框内部的左侧。
6. 将所有红(2)框边界像素擦除为背景色。
7. 输出大小与输入相同。

**关键洞察**：空心框在源题(d5d6de2d)中标记的是"要擦除的边界和要填充的内部"，但这里框标记的是"图案相位发生跳变的空间窗口"——框本身不贡献输出内容，它是一个元指令，指定哪片区域的图案需要错位。求解者如果把框当作填充容器（按 d5d6de2d 的思路）会得到完全错误的结果。相位偏移量恰好等于一个平移周期的列宽，这一点需要对比多个示例（不同周期宽度对应不同偏移量）才能归纳。

## 新题 6：多精灵体最近配对滑动与条件镜像

**组合逻辑**：[最近配对/nearest_pairing](精灵体与锚点配对) + [滑动/slide + 碰撞停止/collision_stop](配对后沿基方向滑动) + [镜像/mirror + 锚点边为镜像轴/anchor_as_axis](接触锚点时产生镜像副本) -> [条件分支：碰撞对象类型决定是否镜像]

**来源原语**：滑动/slide + 镜像/mirror + 精灵体/sprite + 方块锚点/square_anchor + 接触边对齐/contact_edge_align + 锚点边为镜像轴/anchor_as_axis + 碰撞停止/collision_stop (11dc524f), 最近配对/nearest_pairing + 移动/transfer (9aaea919)

**依赖链**：多个精灵体和多个锚点在网格上 -> 按最近曼哈顿距离将每个精灵体与唯一锚点配对 -> 每个精灵体沿其与配对锚点的唯一基方向滑动 -> 滑动中若先碰到另一个精灵体的已停止位置，则当前精灵体就地停止，不产生镜像 -> 若未被阻挡而碰到锚点，则在锚点近边产生镜像副本。配对决定滑动方向；滑动顺序和空间布局决定谁先停下来并可能阻挡后续精灵体；阻挡与否决定是否发生镜像。

将多个精灵体按最近距离配对到方块锚点，滑动至锚点并在接触边产生镜像副本；但被其他已停止精灵体阻挡的精灵体就地停止且不镜像。

**输入结构**：黑(0)背景上有 2 至 4 个不同颜色的 8-连通单色精灵体（每个 4 至 8 像素，形状各异但均非实心 2x2 方块），以及同样数量的灰(5)实心 2x2 方块锚点。每个精灵体与其最近锚点之间存在唯一的基方向分离（精灵体的边界框中心与锚点中心严格在同一行或同一列上）。网格约 18x18 至 25x25。生成约束：最近配对无歧义（每个精灵体有唯一最近锚点，且该锚点也将该精灵体作为其最近精灵体）；至少有一个精灵体的滑动路径会被另一个已停止的精灵体阻挡（以确保条件分支被触发）。

**规则**：
1. 识别所有非黑、非灰的 8-连通精灵体和所有灰(5) 2x2 锚点。
2. 对每个精灵体，找到曼哈顿距离最近的锚点，建立一一配对。
3. 确定每对的基方向（精灵体中心指向锚点中心的方向：上/下/左/右）。
4. 按精灵体与其配对锚点的距离从小到大依次处理每个精灵体（距离最短的最先滑动）。
5. 滑动当前精灵体：沿基方向逐像素平移精灵体，直到发生以下之一：
   - (a) 精灵体的前沿像素与其配对锚点的近边像素 4-相邻 -> 停止，在锚点近边产生精灵体的镜像副本（镜像副本颜色为灰(5)即锚点色）。保留滑动后的原精灵体（保持原色）。
   - (b) 精灵体的前沿像素与任何已停止的精灵体或已生成的镜像副本的像素 4-相邻 -> 停止，不产生镜像。保留滑动后的原精灵体。
6. 锚点本身在输出中被擦除（被镜像副本占据或留为背景）。
7. 清除所有精灵体的原始位置（滑动前的像素变为黑背景）。

**关键洞察**：源题(11dc524f)中只有一个精灵体和一个锚点，不存在阻挡问题。多精灵体场景下，最近配对(9aaea919)引入了处理顺序——先移动距离近的精灵体，它们停下后可能占据路径，阻挡距离远的精灵体。阻挡与否决定了一个关键分支：被阻挡的精灵体不产生镜像副本。这个条件分支是两个源题中都不存在的涌现效应，需要对比有阻挡和无阻挡的示例才能归纳出来。

## 新题 7：双功能边缘标记的符号压缩频率直方图

**组合逻辑**：[压缩/compress + 栅格对齐/grid_aligned](空心符号压缩为单像素) + [忽略干扰项/ignore_distractors](标记线颜色同时标识干扰色) + [计数/counting + 频率统计/frequency_statistic + 排序/sorting + 按计数升序/ascending_by_count](压缩后按颜色频率生成直方图) + [标记指示方向/marker_indicates_dir](同一标记线同时指示直方图排列方向)

**来源原语**：压缩/compress + 空心符号/hollow_symbol + 边缘标记线/edge_marker_line + 栅格对齐/grid_aligned + 标记指示方向/marker_indicates_dir (afe3afe9), 计数/counting + 排序/sorting + 频率统计/frequency_statistic + 按计数升序/ascending_by_count + 表格单元/table_cell + 网格分隔线/grid_separator (81c0276b), 忽略干扰项/ignore_distractors (9110e3c5)

**依赖链**：边缘标记线的颜色确定哪些符号是干扰项（同色即干扰）-> 边缘标记线的位置确定直方图的排列方向 -> 非干扰符号被压缩为单像素 -> 按颜色频率排序生成直方图。标记线同时承担两个角色（过滤器 + 方向指示器），删去任一角色信息都无法完成任务。

将粗格上的空心符号压缩为像素，过滤掉与边缘标记线同色的干扰符号，按剩余颜色频率升序排列为直方图，排列方向由标记线所在边缘决定。

**输入结构**：黑(0)背景上，前景像素排列在一个粗栅格上（行间距和列间距均为 3，即每个栅格单元占 3x3 像素）。每个占据的栅格单元包含一个空心 3x3 符号（8 个边缘像素有色、中心像素为黑背景），各符号为单色，颜色从红(2)、绿(3)、黄(4)、品红(6)、橙(7)中取值。栅格约 4x4 至 6x6 个单元（网格约 12x12 至 18x18 像素）。网格的恰好一条完整边缘被某种颜色的像素填满，形成边缘标记线，该颜色与至少一种符号颜色相同。生成约束：至少有 3 种不同的非干扰符号颜色；干扰色符号至少有 1 个；非干扰色中各颜色的符号数量互不相同（保证排序无歧义）。

**规则**：
1. 识别边缘标记线：找到被同一颜色完全填满的网格边缘，记该颜色为 D。
2. 过滤：颜色为 D 的空心符号是干扰项，忽略它们。
3. 压缩：将每个剩余空心符号替换为其所在粗栅格单元左上角的一个单色像素。
4. 频率统计：统计每种剩余颜色的符号数量。
5. 确定排列方向：标记线所在边缘按顺时针行进映射——顶边 -> 直方图条从左向右延伸（水平条，各条从上到下按频率升序排列）；右边 -> 直方图条从上向下延伸（垂直条，各条从右到左按频率升序排列）；底边 -> 直方图条从右向左延伸；左边 -> 直方图条从下向上延伸。
6. 输出直方图：输出网格大小为（颜色种类数 x 最大频率），每个颜色一行（或一列，取决于方向），长度为该颜色的频率，用该颜色填充，其余位置为黑(0)背景。行/列按频率升序排列（频率最小的在起始侧）。

**关键洞察**：边缘标记线在源题(afe3afe9)中只指示压缩方向，在这里它同时承担了第二个角色——其颜色标识哪些符号是干扰项（源自 9110e3c5 的"忽略干扰项"概念）。这种双功能编码是源题中都不存在的结构关系：标记线的位置信息和颜色信息各自驱动不同的逻辑分支，改变标记线的位置改变输出排列方向，改变标记线的颜色改变哪些符号被过滤。求解者需要同时发现这两层含义。

## 新题 8：链式竖条旋转后按列段分组的调色板重涂

**组合逻辑**：[链式连接/chain_linkage + 高度即宽度/height_equals_width + 旋转/rotate](竖条链式旋转为横条) -> [按列段分组匹配/column_run_group_match](旋转后的横条按水平位置形成列段组) -> [顺序一一对应/order_correspondence + 调色板列/palette_column](列段组按序对应调色板颜色重涂)

**来源原语**：旋转/rotate + 竖条/vertical_bar + 标记条/marker_bar + 链式序列/chained_sequence + 链式连接/chain_linkage + 高度即宽度/height_equals_width (84551f4c), 重涂色/recolor + 调色板列/palette_column + 目标列段/target_column_run + 顺序一一对应/order_correspondence + 按列段分组匹配/column_run_group_match (9b365c51)

**依赖链**：蓝标记条开始链式遍历 -> 链中每根竖条旋转为横条（高度变宽度）-> 旋转后的横条在水平方向上可能首尾相接或有间隔，按水平连续性分组为"列段组" -> 调色板列从左到右依次对应各列段组 -> 每个列段组中的所有横条重涂为对应调色板颜色。链决定了哪些竖条参与旋转；旋转改变了空间布局从而决定了分组方式；分组方式决定了调色板的对应关系。

从蓝色标记条开始沿链式规则收集竖条并旋转为横条，然后将相邻横条分组为列段，按调色板列顺序重涂每个列段组。

**输入结构**：黑(0)背景上，网格底部对齐有若干单像素宽的竖条，全部为红(2)色，高度各不相同（2 至 6 像素）。其中 1 至 2 根竖条为蓝(1)色（链起始标记）。网格左侧有 2 至 4 根全高度的单像素宽调色板列，颜色各异（如绿(3)、黄(4)、橙(7)、品红(6)），从左到右排列。网格约 12x20 至 15x25。生成约束：从每个蓝色标记条出发，按链式规则（下一根竖条的列坐标 = 当前竖条列坐标 + 当前竖条高度）恰好可以到达若干红色竖条，形成不中断的链；不被任何蓝色标记链到达的红色竖条视为"未链接条"；调色板列的数量等于所有链旋转后形成的列段组总数。

**规则**：
1. 识别左侧调色板列，从左到右记录颜色序列 P1, P2, ..., Pk。
2. 对每根蓝(1)标记竖条，按链式规则向右遍历：设当前竖条高度为 h、列坐标为 c，则下一根竖条位于列 c+h，若该列存在底部对齐的红色竖条则纳入链中，否则链终止。
3. 将链中每根竖条（含蓝色起始条）从垂直旋转为水平：以该竖条的底部像素为锚点，向右延伸，长度等于原高度，颜色暂为白(保持原色用于分组)。清除原竖条的垂直像素。
4. 旋转后的横条按列段分组：若两根相邻横条（按锚点列坐标排序）的水平跨度首尾相接（前一根的右端列 + 1 = 后一根的左端列），则归为同一列段组；否则分属不同组。
5. 将所有列段组按其最左列坐标从左到右排序，依次对应调色板颜色 P1, P2, ...。将每个列段组中所有横条像素重涂为对应的调色板颜色。
6. 未被任何链到达的红色竖条保持不变（垂直、红色）。
7. 擦除调色板列（变为黑背景）。

**关键洞察**：源题(84551f4c)中旋转后的横条只是简单地画出来，不存在"分组"概念。源题(9b365c51)中列段分组作用于静态目标图形。这里，链式旋转的结果动态地决定了哪些横条首尾相接——一根较长竖条旋转后占据更多水平空间，可能将原本分开的短横条"桥接"到同一组，或自身占据整组。这种"旋转结果决定分组结构"是两个源题中都不存在的涌现关系。求解者需要先理解链式旋转才能预测分组，而分组错误会导致调色板映射全部偏移。

## 新题 9：空心框内部的标记角定向对角扩展与面积优先叠压

**组合逻辑**：[擦除/erase + 填充/fill + 边框包围内部/frame_encloses_interior](空心框擦除后识别内部区域) + [标记位决定展开/marker_pos_sets_expansion + 对角方向/diagonal_dir](标记像素的角落位置决定对角扩展方向) + [贪心选择/greedy_selection + 从大到小优先/largest_first_priority + 非重叠约束/non_overlapping_constraint](扩展区域冲突时按面积优先级解决)

**来源原语**：擦除/erase + 填充/fill + 空心矩形/hollow_rectangle + 封闭区域/enclosed_region + 边框包围内部/frame_encloses_interior (d5d6de2d), 标记像素/marker_pixel + 标记位决定展开/marker_pos_sets_expansion + 对角方向/diagonal_dir + 填充色块/fill_block (4522001f), 贪心选择/greedy_selection + 从大到小优先/largest_first_priority + 非重叠约束/non_overlapping_constraint (31adaf00)

**依赖链**：每个空心框擦除后产生一个内部矩形区域 -> 框内角落的标记像素指定对角扩展方向 -> 每个内部区域沿指定对角方向产生一个偏移副本（原位 + 对角偏移位各一个色块）-> 不同框的扩展区域可能重叠 -> 面积较大的框的扩展区域优先占据重叠像素。框决定了区域形状；标记决定了扩展方向；面积优先规则决定了冲突解决——三者缺一不可。

擦除多个空心框边界后，按各框内角落标记的对角方向扩展其内部填充，扩展冲突时面积大的框优先。

**输入结构**：黑(0)背景上有 2 至 4 个不同颜色的空心矩形框（单像素宽边框，颜色各异，从蓝(1)、红(2)、绿(3)、黄(4)中取值），大小各不相同（内部区域从 2x2 到 5x5 不等）。每个框的内部有一个灰(5)标记像素，位于内部区域的四个角落之一（左上、右上、左下、右下）。网格约 18x18 至 22x22。生成约束：各框互不重叠且间距足够（至少间隔 2 像素）；每个框的对角扩展后至少有一对框的扩展区域存在重叠（以触发冲突解决）；扩展区域不超出网格边界。

**规则**：
1. 识别所有空心矩形框及其颜色。
2. 对每个框：记录其内部区域的矩形范围（不含边框像素），记录灰(5)标记像素在内部区域中的角落位置。
3. 擦除所有框的边框像素（变为黑背景）。擦除灰标记像素。
4. 对每个框，确定对角扩展方向：标记在左上角 -> 向右下扩展；标记在右上角 -> 向左下扩展；标记在左下角 -> 向右上扩展；标记在右下角 -> 向左上扩展（方向是从标记指向其对角）。
5. 对每个框，生成两个色块：(a) 原位色块——在内部区域的原始位置填充该框的颜色；(b) 偏移色块——将内部区域沿扩展方向平移（行偏移 = 内部区域高度，列偏移 = 内部区域宽度，符号由方向决定），在平移后的位置填充该框的颜色。
6. 冲突解决：按框的内部面积从大到小排序处理。先处理面积最大的框（绘制其两个色块），后处理面积较小的框。后绘制的色块不覆盖已绘制的像素（已占据像素保持先绘制者的颜色）。
7. 输出最终网格。

**关键洞察**：源题(4522001f)中对角扩展作用于一个 2x2 的微小结构，输出是固定的 4x4 块对。这里，对角扩展作用于任意大小的矩形内部，且多个框的扩展可能空间冲突——冲突解决引入了源题(31adaf00)的面积优先贪心策略，但规则方向相反：面积大的框优先绘制但后绘制者不覆盖，这意味着面积小的框在非重叠区域仍然可见。这种"先大后小、不覆盖"的规则与 31adaf00 的"先大后小、占据"逻辑形似但细节不同，需要对比有重叠和无重叠的示例才能归纳出精确的冲突解决机制。
