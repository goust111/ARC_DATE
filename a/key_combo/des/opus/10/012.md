## 新题 1：标记计数选变换类型

**组合逻辑**：[计数(counting)](创新：计数结果不作为数值参数，而作为离散分支选择器) + [镜像(reflect)](创新：三种几何变换共用同一放置规则，由外部条件选择) + [标记像素(marker_pixel)](创新：标记嵌入精灵体内部，既是精灵的一部分又是控制信号)

**来源原语**：计数(counting) ← 42a15761/dce56571；镜像(reflect) ← 538b439f；标记像素(marker_pixel) ← 7df24a62/7bb29440；分隔线(separator_line) ← 538b439f；精灵体(sprite) ← 3391f8c0/e78887d1

**依赖链**：嵌入式标记像素的计数结果决定该精灵使用哪种几何变换（垂直翻转/水平翻转/180度旋转），变换结果再经跨分隔线的镜像放置生成输出。删去计数→无法确定变换类型；删去变换→无输出形状；删去镜像放置→精灵无法定位到输出区域。

根据每个精灵内部嵌入的黄色标记像素数量，选择不同的几何变换方式，再将变换后的精灵镜像放置到分隔线另一侧。

**输入结构**：约 14x14 的网格。黑(0)背景。一条灰(5)水平分隔线横跨全宽，将网格分为上下两半。上半区有 3-5 个互不相邻的 4-连通单色小精灵（每个精灵 3-6 像素，使用红(2)、蓝(1)、绿(3)等颜色，不同精灵颜色可能不同）。每个精灵内部有 0、1 或 2 个像素被替换为黄(4)标记像素（标记位置属于精灵的边界框内部，占据原本应为精灵颜色的位置）。不同示例中同类精灵的具体形状不同（如一个示例中 5 像素的精灵呈十字形，另一个示例中呈 Z 字形）。下半区初始为空（全黑）。生成约束：每个精灵的边界框不超过 4x4；精灵间水平间距至少 2 像素；上半区与分隔线之间至少有 1 行空行；下半区有足够空间容纳所有变换后的精灵。

**规则**：
1. 对上半区每个精灵，统计其边界框内黄(4)标记像素的个数 M。
2. 根据 M 选择变换方式：M=0 → 上下翻转（垂直翻转）；M=1 → 左右翻转（水平翻转）；M=2 → 旋转 180 度。
3. 对精灵的非黄色像素掩码执行所选变换（黄色标记的位置在变换时视为该精灵颜色的一部分参与几何变换，但输出中恢复为精灵的主体颜色，不保留黄色）。
4. 将变换后的精灵放置到分隔线下方的镜像位置：列范围与原精灵相同，行位置为原精灵到分隔线距离的对称位置（若精灵最近行距分隔线 d 行，则变换后精灵最近行在分隔线下方 d 行）。
5. 上半区的原始精灵（含黄色标记）保持不变。分隔线保持不变。

**关键洞察**：黄色标记看似是精灵的一部分，实际是控制信号——其数量编码了三种变换的选择。仅凭单个示例无法确定 M→变换类型的映射关系（例如不知道 M=1 对应水平翻转还是旋转），必须对比多个示例中不同 M 值精灵的输入输出形状差异才能归纳出映射表。

## 新题 2：图例编码连接拓扑

**组合逻辑**：[图例(legend)](创新：图例行不映射颜色而编码空间拓扑类型) + [连线(line_drawing)](创新：同一操作有三种几何模式，由外部编码选择) + [同色配对(same_color_pairing)](已有原语) + [对角线段连接(diagonal_segment_connect)](已有原语)

**来源原语**：图例(legend) ← 305b1341；连线(line_drawing) ← 29700607；同色配对(same_color_pairing) ← 29700607/1f876c06；对角线段连接(diagonal_segment_connect) ← 1f876c06；端点对(endpoint_pair) ← 1f876c06

**依赖链**：图例的行序位编码连接拓扑类型（直线/对角线/L形），每种颜色的两个端点依据其在图例中的行序位选择相应的连接策略。删去图例→不知道哪种颜色用哪种连线方式；删去同色配对→不知道端点对；删去连线→无输出。图例与连线之间的关系是"编码→解码"，不是"先做A再做B"。

图例的行位置编码每种颜色端点对的连接几何类型——直线、对角线或 L 形路径。

**输入结构**：约 14x14 的网格。黑(0)背景。列 0 的前 3 行构成单列图例，每行一个不同颜色的像素（如行 0: 红(2)，行 1: 蓝(1)，行 2: 绿(3)）。网格其余区域（列 1 以右），每种图例颜色恰好出现 2 次，形成端点对。不同示例中，图例中的颜色排列顺序不同（例如一个示例中红在行 0、蓝在行 1，另一个示例中蓝在行 0、红在行 1），但同一示例中图例行顺序与连接类型的对应关系固定。生成约束：行 0 颜色的端点对共享同一行或同一列（保证直线连接可行）；行 1 颜色的端点对的行差绝对值等于列差绝对值（保证 45 度对角线可行）；行 2 颜色的端点对不在同行同列且行差不等于列差（保证只能用 L 形连接）；所有连线路径互不相交。

**规则**：
1. 读取图例：行 0 的颜色记为 C0，行 1 记为 C1，行 2 记为 C2。
2. 清除图例列（列 0 的前 3 行设为黑(0)）。
3. C0 的端点对：用该颜色绘制一条水平或垂直直线段连接两点（包含两端点及之间所有像素）。
4. C1 的端点对：用该颜色绘制一条 45 度对角线段连接两点（包含两端点及之间所有像素）。
5. C2 的端点对：用该颜色绘制一条 L 形路径连接两点——先从一个端点沿水平方向行进到另一个端点所在列，再沿垂直方向行进到另一个端点。若存在两条等长 L 形路径（先水平后垂直 vs. 先垂直后水平），选择先水平后垂直的路径。
6. 所有原始端点像素保持不变。

**关键洞察**：图例在参考题 305b1341 中编码颜色映射关系，但在本题中编码的是空间拓扑类型——这是对"图例"概念的本质性重构。仅看单个示例可能误以为每种颜色总是用某一固定的连接方式，必须对比多个示例（图例行顺序不同，连接方式随之变化）才能发现行位置才是决定因素。

## 新题 3：锚点距离定描边尺寸

**组合逻辑**：[描边(outline)](创新：描边尺寸不再固定，由外部距离计算决定) + [切比雪夫距离(chebyshev_dist)](创新：距离不再决定填充方块大小，而决定空心描边半径) + [标记色决定描边色(marker_color_determines_outline)](已有原语) + [冲突优先级(conflict_priority)](创新：优先级由距离值决定而非图例顺序)

**来源原语**：描边(outline) ← 913fb3ed；切比雪夫距离(chebyshev_dist) ← ff72ca3e；标记色决定描边色(marker_color_determines_outline) ← 913fb3ed；孤立像素(isolated_pixel) ← 913fb3ed；阻挡像素→锚点像素 ← ff72ca3e；冲突优先级(conflict_priority) ← 305b1341

**依赖链**：锚点距离计算 → 确定描边半径（不可跳过：无距离则不知道画多大）；标记颜色 → 确定描边颜色（不可跳过：无颜色映射则不知道用什么色）；距离值 → 确定重叠优先级（不可跳过：多描边重叠时无法决定谁覆盖谁）。三条规则平行生效，共同约束每个像素的最终颜色。

每个彩色标记像素根据到最近灰色锚点的切比雪夫距离画出相应大小的空心方框，颜色由标记色映射决定，重叠时近锚点者优先。

**输入结构**：约 15x15 的网格。黑(0)背景。3-5 个孤立的彩色标记像素，颜色取自 {绿(3), 青(8), 红(2)}。3-5 个灰(5)锚点像素散布于网格中。标记像素与锚点像素互不相邻（曼哈顿距离至少 2）。不同示例中标记和锚点的位置不同，但颜色→描边色的映射关系固定。生成约束：每个标记的切比雪夫距离 D 满足 2 <= D <= 5；所有描边框（边长 2D-1）不超出网格边界；描边框不覆盖任何锚点或标记像素。

**规则**：
1. 对每个彩色标记像素，计算其到最近灰(5)锚点的切比雪夫距离 D。
2. 以标记像素为中心，绘制边长为 (2D-1) 的空心正方形描边框（即描边位于距中心 D-1 的切比雪夫环上）。
3. 描边颜色由标记颜色决定：绿(3) → 品红(6)，青(8) → 黄(4)，红(2) → 蓝(1)。
4. 若两个描边框在某像素重叠，D 值较小的标记的描边优先显示；若 D 值相同，边界框左上角按阅读序（先上后左）靠前者优先。
5. 原始标记像素和灰色锚点像素始终保留，不被描边覆盖。描边仅覆盖黑色背景像素。

**关键洞察**：参考题 913fb3ed 的描边总是固定 3x3，参考题 ff72ca3e 的距离决定实心方块大小。本题将两者融合——距离决定空心描边的尺寸，创造出"距离→几何尺寸"和"颜色→外观"两条独立推理轴，求解者必须同时归纳两个维度的规则。

## 新题 4：阻挡像素驱动连线策略回退

**组合逻辑**：[连线(line_drawing)](创新：同一对端点有三种候选连接策略，按优先级回退) + [阻挡像素(blocker_pixel)](创新：阻挡不只是终止线段，而是迫使整条连线切换几何策略) + [同色配对(same_color_pairing)](已有原语) + [对角线段连接(diagonal_segment_connect)](创新：对角连接不再是唯一方式，而是回退选项之一)

**来源原语**：连线(line_drawing) ← 29700607；阻挡像素(blocker_pixel) ← ff72ca3e；同色配对(same_color_pairing) ← 29700607/1f876c06；对角线段连接(diagonal_segment_connect) ← 1f876c06；有端点则转弯(endpoint_triggers_turn) ← 29700607

**依赖链**：同色配对确定端点对 → 尝试首选 L 形路径 → 阻挡像素判定是否可行 → 若被阻则回退到对角线 → 再判定 → 若再被阻则回退到替代 L 形。阻挡像素的位置同时影响多对端点的策略选择，且策略选择是全局的（一对的连线路径可能阻挡另一对的候选路径）。

同色端点对依次尝试 L 形路径、对角线、替代 L 形路径连接，每遇灰色阻挡即回退到下一策略。

**输入结构**：约 13x13 的网格。黑(0)背景。3-4 种前景色（如红(2)、蓝(1)、绿(3)、橙(7)），每种颜色恰好出现 2 个像素作为端点对。若干灰(5)阻挡像素散布。不同示例中端点和阻挡的位置不同，导致同一颜色在不同示例中可能使用不同的连接策略。生成约束：每对端点至少有一种策略可行（即三种策略中至少一种路径上无灰色阻挡）；不同颜色的最终连线路径互不相交（保证规则无歧义）。

**规则**：
1. 识别每种前景颜色的两个端点（记为 A 和 B），按颜色分组。
2. 对每对端点，按以下优先级尝试连接策略（以先成功者为准）：
   - **策略一（L 形-竖先横后）**：从 A 沿垂直方向行进到 B 所在行，再沿水平方向行进到 B。若该路径上（不含 A、B 本身）存在任何灰(5)像素，此策略失败。
   - **策略二（对角线）**：从 A 到 B 绘制 45 度对角线段。前提：A 和 B 的行差绝对值等于列差绝对值。若前提不满足或路径上存在灰(5)像素，此策略失败。
   - **策略三（L 形-横先竖后）**：从 A 沿水平方向行进到 B 所在列，再沿垂直方向行进到 B。若路径上存在灰(5)像素，此策略也失败（此时该对不连线，但生成约束保证这不会发生）。
3. 用端点颜色绘制所选策略的连线路径（覆盖路径上的黑色背景像素）。
4. 所有原始端点和灰色阻挡像素保持不变。

**关键洞察**：在参考题中，阻挡像素只是被动地终止射线或限定区域大小。本题中阻挡像素是主动的"策略开关"——它们的位置决定每对端点使用哪种连接拓扑。求解者必须对比多个示例（同色端点对在不同阻挡布局下使用不同策略）才能发现三种策略的优先级回退链。

## 新题 5：散布点扩展后按内嵌灰标记筛选

**组合逻辑**：[扩展(expand)](已有原语) + [裁剪(crop)](已有原语) + [计数(counting)](创新：计数对象是扩展后才被"捕获"的外部像素) + [散布点(sparse_dot)](已有原语) + [最少标记数→筛选条件](创新：标记的选择功能在扩展完成后才生效)

**来源原语**：扩展(expand) ← 305b1341；裁剪(crop) ← 23b5c85d/7bb29440；计数(counting) ← 42a15761/dce56571；散布点(sparse_dot) ← 305b1341；最少标记数(minimum_marker_count) ← 7bb29440；最小面积矩形保留(smallest_rect_retained) ← 23b5c85d

**依赖链**：散布点按颜色分组 → 扩展各组边界框并填充（必须先完成才能确定矩形范围）→ 计数每个扩展矩形内部的灰色像素（灰色像素在扩展前对分组无影响，扩展后才成为被"包围"的对象）→ 按灰色计数筛选并裁剪。灰色像素的双重角色是耦合的核心：它们不参与扩展，但扩展结果决定了哪些灰色像素"属于"哪个矩形。

将不同颜色的散布点各自扩展为填充矩形，然后选出内含灰色标记最少的矩形作为裁剪输出。

**输入结构**：约 15x15 的网格。黑(0)背景。3-4 种非灰非黑前景色（如红(2)、蓝(1)、绿(3)），每种颜色有 2-4 个散布点。另有若干灰(5)孤立像素散布于网格各处。不同颜色的散布点在空间上互不重叠（各颜色的边界框扩展 1 像素后仍不相交）。灰(5)像素可能落在某些颜色扩展后的矩形范围内，也可能落在所有矩形之外。不同示例中各颜色散布点的数量和位置不同，导致扩展矩形的大小和"捕获"的灰色像素数量不同。生成约束：恰好有一种颜色的扩展矩形内灰色像素数量严格最少（无平局）。

**规则**：
1. 对每种非灰前景色 C，找到所有颜色为 C 的散布点，计算其最小边界框，向四个方向各扩展 1 像素（不超出网格边界）。
2. 在扩展后的边界框内，将所有黑(0)背景像素填充为颜色 C。保留框内所有已有的非黑像素（包括灰(5)像素和其他颜色的点，但因生成约束，框内不会有其他颜色的散布点）。
3. 对每个扩展矩形，统计其内部灰(5)像素的个数。
4. 选择灰色像素个数最少的那个扩展矩形。
5. 输出为该矩形的裁剪结果：输出网格的尺寸等于该矩形的尺寸，包含其内部所有像素的原始颜色（填充色、原始散布点色、灰色像素均保留）。

**关键洞察**：灰色像素在扩展阶段完全是旁观者（不属于任何颜色组，不影响边界框计算），但在选择阶段变成了关键判据。求解者必须先理解扩展规则（复用自 305b1341），然后才能理解灰色像素的选择功能（类似 7bb29440 的标记筛选，但筛选对象是扩展后才存在的矩形）。两步操作不可独立求解。

## 新题 6：边界标记定平铺维度与棋盘反转

**组合逻辑**：[计数(counting)](创新：按边界方位分别计数，得到两个独立维度) + [平铺(tiling)](创新：平铺倍数不是固定的，而由计数动态决定) + [颜色反转(color_invert)](创新：反转不是全局的，而按棋盘格位选择性施加) + [边界定位(boundary_pos)](创新：边界位置不用于定线方向，而编码平铺参数)

**来源原语**：计数(counting) ← 42a15761/dce56571；平铺(tiling) ← 48131b3c；颜色反转(color_invert) ← 48131b3c；边界定位(boundary_pos) ← 6cdd2623；标记像素(marker_pixel) ← 多题；画布边界(canvas_boundary) ← 6cdd2623；二值图案(binary_pattern) ← 48131b3c

**依赖链**：边界标记的上下/左右分类 → 分别计数得到 V 和 H（不可跳过：无计数则不知平铺维度）→ 平铺 H列xV行 排布（不可跳过：无维度则无法平铺）→ 按 (i+j) 奇偶决定是否反转（不可跳过：反转模式依赖平铺维度，V 和 H 共同决定棋盘格图案）。三步间有信息变换：计数→整数，整数→几何排布，排布位置→布尔选择。

网格边界上的标记像素分上下和左右两组分别计数，得到的两个数决定二值图案的平铺行列数，并以棋盘格方式交替施加颜色反转。

**输入结构**：约 10x10 的网格。中央区域有一个小的二值图案（黑(0) + 一种前景色，如红(2)），尺寸约 3x3 或 3x4，占据网格的中心位置。网格的四条边界（第 0 行、最后一行、第 0 列、最后一列）上散布着若干橙(7)标记像素。标记只出现在边界上，内部无橙色像素。不同示例中标记数量和位置不同，但总在边界上。生成约束：上边界+下边界的标记总数 V 满足 2 <= V <= 4；左边界+右边界的标记总数 H 满足 2 <= H <= 4；输出网格尺寸为 (图案高度 x V) 行 x (图案宽度 x H) 列，不超过 20x20。

**规则**：
1. 统计上边界（第 0 行）和下边界（最后一行）的橙(7)标记像素总数，记为 V。
2. 统计左边界（第 0 列）和右边界（最后一列）的橙(7)标记像素总数，记为 H。
3. 提取中央二值图案（其边界框恰好包含所有前景色像素的最小矩形区域，含内部黑色像素）。
4. 构造输出网格：将图案平铺为 V 行 x H 列的阵列。
5. 对阵列中位置 (i, j)（0-indexed）的图案副本：若 (i+j) 为偶数，放置原始图案；若 (i+j) 为奇数，放置颜色反转图案（前景色与黑(0)互换）。
6. 输出网格中不包含边界标记。

**关键洞察**：边界标记在参考题 6cdd2623 中决定线的方向（上下边→竖线，左右边→横线），本题中则编码平铺维度（上下边→行数，左右边→列数）——同一"边界位置→参数"的结构关系被赋予了全新语义。棋盘反转使得 V 和 H 的具体数值不仅决定输出大小，还决定反转图案的空间分布，两者紧耦合。

## 新题 7：角侧多样性竞争决定填充与描边

**组合逻辑**：[计数(counting)](创新：计数对象是颜色种类数而非像素个数) + [填充(fill)](创新：填充目标和填充色都由比较结果动态决定) + [描边(outline)](创新：描边是否执行以及描边色由同一个比较结果的另一分支决定) + [角与边中分组(corner_side_group)](创新：分组不用于循环移色，而用于两组间的"竞争")

**来源原语**：计数(counting) ← 42a15761；填充(fill) ← ff72ca3e/305b1341；描边(outline) ← 913fb3ed；角与边中分组(corner_side_group) ← 46c35fc7；环形前景(ring_object) ← 46c35fc7；角位像素(corner_pixel) ← 46c35fc7；边中像素(side_center_pixel) ← 46c35fc7；空心矩形(hollow_square) ← 913fb3ed

**依赖链**：角位/边中分组 → 分别统计各组颜色多样性 Cc 和 Cs → 比较 Cc 与 Cs（分支节点，不可跳过）→ 比较结果决定：(a) 哪组提供中心填充色，(b) 哪组提供描边色，(c) 是否绘制描边。三条输出规则都依赖同一个比较结果，且"胜者填中心、败者画外框"的角色分配是非显然的。

在每个 3x3 环形对象中，比较角位像素与边中像素的颜色多样性，多样性更高的一组提供中心填充色，另一组提供 5x5 描边色；若相等则特殊处理。

**输入结构**：约 15x15 的网格。黑(0)背景。3-4 个 3x3 环形前景对象，彼此间距至少 3 像素（保证 5x5 描边不重叠）。每个环由 8 个前景像素围绕 1 个黑色中心构成。每个环的 4 个角位像素和 4 个边中像素可使用不同颜色，颜色取自 {红(2), 蓝(1), 绿(3), 黄(4), 品红(6), 橙(7)}。不同环的颜色分布不同——有的角位多样性高于边中，有的反之，有的相等。不同示例中同一位置的环的具体颜色不同。

**规则**：
1. 对每个 3x3 环形对象，将其 8 个像素分为角位组（4 个：左上、右上、左下、右下）和边中组（4 个：上中、右中、下中、左中）。
2. 统计角位组中不同颜色的种类数 Cc，统计边中组中不同颜色的种类数 Cs。
3. 若 Cc > Cs：
   - 用角位组中出现次数最多的颜色填充环的中心像素。若角位组内多色并列最多，选在角位组中按阅读序（左上→右上→左下→右下）最先出现的颜色。
   - 以边中组中出现次数最多的颜色（同样的并列规则，阅读序为上中→右中→下中→左中）绘制以环中心为中心的 5x5 空心正方形描边。描边仅覆盖黑色背景像素。
4. 若 Cc < Cs：
   - 用边中组的众数颜色填充中心。
   - 用角位组的众数颜色绘制 5x5 描边。
5. 若 Cc == Cs：
   - 用灰(5)填充中心。不绘制描边。
6. 原始环形像素保持不变。

**关键洞察**：参考题 46c35fc7 中角位和边中分组用于两组独立的循环移色。本题中这两组变成了竞争关系——多样性高者"赢得"中心填充权，低者"输"到外围描边。相等则两败（灰色中心、无描边）。这种竞争产生的角色互换（哪组填中心 vs. 哪组画描边）是跨示例才能归纳的隐蔽规则。

## 新题 8：垂直线对隐式定义矩形的面积优先填充

**组合逻辑**：[填充(fill)](创新：填充目标不是显式给定的矩形，而是从线段交叉隐式推断的矩形) + [连线(line_drawing)](创新：线段不是输出，而是输入中编码矩形参数的结构) + [同色配对(same_color_pairing)](创新：配对对象不是点而是线段) + [冲突优先级(conflict_priority)](创新：优先级基于推断出的面积而非给定顺序)

**来源原语**：填充(fill) ← 305b1341/ff72ca3e；连线→线段结构 ← 29700607；同色配对(same_color_pairing) ← 29700607/1f876c06；交叉点(crossing_point) ← 67a423a3；冲突优先级(conflict_priority) ← 305b1341；实心矩形(solid_rectangle) ← 23b5c85d/538b439f

**依赖链**：同色线段配对（一横一竖）→ 交叉点确定矩形角点 → 线段长度隐式定义矩形宽高 → 填充推断出的矩形 → 面积决定重叠优先级。整条链中矩形从未显式出现，是从线段几何推断的产物。删去配对→不知道哪两条线段属于同一矩形；删去交叉→不知道矩形定位；删去面积优先→重叠区域无法确定颜色。

每种颜色有一条水平线段和一条垂直线段，两者交叉点是隐式矩形的一个角，线段长度定义矩形的宽高，重叠时面积小的矩形优先。

**输入结构**：约 14x14 的网格。黑(0)背景。3-4 种前景色（如红(2)、蓝(1)、绿(3)、黄(4)），每种颜色恰好有一条水平线段（宽度 1 像素、长度 3-6 像素）和一条垂直线段（宽度 1 像素、长度 3-6 像素）。同色的水平和垂直线段恰好交于一个像素（交叉点）。不同颜色的线段可能在空间上交叉，但同色线段对之间的交叉点唯一。不同示例中线段位置不同，导致推断出的矩形大小和重叠关系不同。生成约束：每种颜色的两条线段共享恰好一个像素（交叉点）。

**规则**：
1. 对每种前景色 C，识别其水平线段和垂直线段。两段交于一点，该点为矩形的一个角。
2. 水平线段从交叉点向某方向延伸——矩形沿水平方向从交叉点向线段延伸的反方向扩展，宽度等于水平线段长度。垂直线段同理——矩形沿垂直方向从交叉点向线段延伸的反方向扩展，高度等于垂直线段长度。
   - 具体地：若水平线段从交叉点向右延伸，则矩形从交叉点向左展开，宽度=水平线段长度；若向左延伸，则矩形向右展开。垂直类似：若向下延伸，矩形向上展开；若向上延伸，矩形向下展开。
3. 用颜色 C 填充该矩形区域的所有像素（包括背景像素和其他颜色的填充像素）。
4. 所有颜色的矩形同时计算（不存在处理顺序），但重叠区域的颜色由面积决定：面积较小的矩形优先（其颜色显示在重叠区域）。若面积相同，交叉点行号较小者优先；行号也相同则列号较小者优先。
5. 所有原始线段像素保持不变（始终显示在最前层，不被填充覆盖）。

**关键洞察**：矩形在输入中不存在——它们必须从两条垂直线段的交叉几何关系中推断出来。线段不仅提供尺寸信息（长度=矩形边长），还提供方向信息（线段延伸方向的反向=矩形展开方向）。这种"线段即矩形的边、交叉点即矩形的角"的隐式编码关系在参考题中不存在，是对线段和交叉点原语的全新结构组合。

## 新题 9：前景面积决定拉直方向与镜像轴

**组合逻辑**：[拉直(straighten)](创新：拉直方向不固定，由面积与空间约束的比较决定) + [镜像(reflect)](创新：镜像轴不是预设的分隔线，而由面积比较的分支结果选择) + [计数(counting)](创新：计数结果既是线段长度又是分支条件) + [分隔线(separator_line)](创新：两条分隔线中只有一条被用作镜像轴，具体哪条由计数决定)

**来源原语**：拉直(straighten) ← dce56571；镜像(reflect) ← 538b439f；计数(counting) ← dce56571；分隔线(separator_line) ← 538b439f；前景掩码(foreground_mask) ← dce56571；跨轴对称(cross_axis_symmetry) ← 538b439f；居中放置(center_placed) ← dce56571

**依赖链**：计数前景像素 N → N 与象限宽度 W 比较（分支条件，不可跳过）→ 比较结果同时决定拉直方向（水平 or 垂直）和镜像轴（竖分隔线 or 横分隔线）→ 执行拉直 + 镜像。N 同时充当三个角色：线段长度、分支判据、间接的轴选择器——删去任何一个角色都使题目不可解。

将不规则前景掩码拉直为线段，像素总数决定线段长度、拉直方向和使用哪条分隔线进行镜像。

**输入结构**：约 12x14 的网格。黑(0)背景。一条灰(5)水平分隔线和一条灰(5)垂直分隔线相交于网格中心附近，将网格分为 4 个象限。恰好一个象限中有一个 4-连通的单色不规则前景掩码（颜色为红(2)、蓝(1)或绿(3)等非灰非黑色），像素数 N 在 3-8 之间。其余三个象限为空（全黑）。不同示例中前景掩码的形状、大小和所在象限不同。生成约束：设前景所在象限的宽度为 W（列数），高度为 H（行数）；若 N <= W 则 N <= H 也成立（保证两种情况下线段都能放下），若 N > W 则 N <= H（保证垂直拉直可行）。

**规则**：
1. 统计前景掩码的像素总数 N，记录其颜色 C 和所在象限 Q。
2. 擦除原始前景掩码（设为黑(0)）。
3. 设 Q 的宽度为 W（Q 的列数范围）。
4. 若 N <= W：
   - 在 Q 内，沿紧邻垂直分隔线的那一列所在行范围的中间行，水平放置一条长度为 N 的 C 色线段。线段从垂直分隔线一侧开始，向 Q 的内部方向延伸。
   - 将该线段关于垂直分隔线镜像到对面象限（镜像后颜色不变）。
5. 若 N > W：
   - 在 Q 内，沿紧邻水平分隔线的那一行所在列范围的中间列，垂直放置一条长度为 N 的 C 色线段。线段从水平分隔线一侧开始，向 Q 的内部方向延伸。
   - 将该线段关于水平分隔线镜像到对面象限（镜像后颜色不变）。
6. 两条分隔线保持不变。未涉及的象限保持不变。

**关键洞察**：参考题 dce56571 中拉直总是水平的且居中放置，参考题 538b439f 中镜像轴总是唯一的。本题中 N 与 W 的大小关系同时决定了拉直方向和镜像轴——这是一个分支条件同时控制两个操作参数的结构，在任何参考题中都不存在。求解者必须对比"掩码像素少时横向拉直+竖轴镜像"与"掩码像素多时纵向拉直+横轴镜像"的示例才能归纳出分支规则。
