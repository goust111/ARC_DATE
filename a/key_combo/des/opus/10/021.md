## 新题 1：孔洞计数决定叠加层序

**组合逻辑**：[计数/counting](创新：计数对象从"封闭背景区域"变为决定"图层优先级"的排序键) + [透明叠加/transparent_overlay](创新：层序不由面板位置决定，而由孔洞数动态决定) + [裁剪/crop]

**来源原语**：计数/counting、封闭背景区域(参考题 37d3e8b2)；透明叠加/transparent_overlay、图层优先级/layer_priority(参考题 ea9794b1)；裁剪/crop(参考题 9ecd008a)

**依赖链**：计数每个面板中前景对象的孔洞数 → 孔洞数建立面板之间的图层优先级 → 按此优先级执行透明叠加得到输出。孔洞数计数的结果决定了叠加的层序，二者不可分离：不数孔洞就不知道谁在上层，不叠加就无法产生输出。

根据每个面板中前景图形的封闭孔洞数量确定叠加层序，孔洞越多的面板越后绘制（在最上层），将多个面板合成为一个输出。

**输入结构**：约 15x31 的网格，黑(0)背景。一条灰(5)色的竖直分隔线将网格等分为三个约 15x10 的面板。每个面板内有一个单色 4-连通前景图形（三个面板分别使用红(2)、蓝(1)、绿(3)），每个图形是大致矩形的填充块但内部被挖去了 1 到 3 个互不相邻的矩形孔洞（孔洞为黑(0)背景色，每个孔洞 2~4 像素），三个图形的孔洞数互不相同。三个图形的边界框大小相同（均为约 8x7），但在各自面板内的位置略有偏移（行偏移范围 0~3、列偏移范围 0~2），使得叠加时图形之间存在部分重叠区域。生成约束：三个图形的孔洞数严格为三个不同的值（来自 {1,2,3} 的排列），且每个面板只有一个前景色。

**规则**：
1. 识别灰(5)分隔线，将网格裁剪为三个等大面板，丢弃分隔线列。
2. 统计每个面板中前景图形内部封闭的黑(0)背景连通分量数目（即孔洞数）。
3. 建立叠加层序：孔洞数最少的面板最先绘制（最底层），孔洞数最多的面板最后绘制（最顶层）。
4. 创建一个与单个面板等大的黑(0)背景输出画布。
5. 按层序依次将每个面板的非背景像素绘制到输出画布上（后绘制的覆盖先绘制的同位置像素）。

**关键洞察**：面板的叠加顺序不由其左中右位置决定，而由面板内图形的孔洞数决定——这是一个需要对比多个示例才能发现的隐蔽规则，因为仅看单个示例时，求解者可能误以为层序由面板位置或颜色编号决定。

## 新题 2：标记位移量驱动条纹相位

**组合逻辑**：[循环位移/cyclic_roll](创新：位移量不来自单一控制列，而是由分布在网格边缘的多个标记像素各自决定其所在列的行偏移) + [滑动/sliding + 条纹图案/stripe_pattern](创新：条纹不再由单个标记的列决定相位，而是每列独立位移后形成错位条纹)

**来源原语**：循环位移/cyclic_roll、控制列/control_column、标记位定位移量/marker_is_shift(参考题 6d1d5c90)；滑动/sliding、条纹图案/stripe_pattern、标记像素/marker_pixel、列对齐/col_alignment(参考题 834ec97d)

**依赖链**：底行标记像素的颜色编码每列的循环位移量 → 位移改变条纹图案在每列的垂直偏移 → 原本均匀的水平条纹在输出中呈现阶梯状错位。标记像素的读取与条纹生成是同一规则的两面：不读标记就不知道位移量，不生成条纹就没有被位移的对象。

读取底行标记像素的颜色来确定每列的循环下移量，将统一的水平条纹图案按列独立滚动，产生阶梯状错位条纹。

**输入结构**：约 12x10 的网格，黑(0)背景。网格的最底行是控制行：每个单元格要么是黑(0)（表示不位移），要么是以下四种颜色之一——蓝(1)表示下移 1 行、红(2)表示下移 2 行、绿(3)表示下移 3 行、黄(4)表示下移 4 行。网格的其余行（除最底行外）构成一个水平条纹图案：从第 0 行起，奇数行全部为灰(5)，偶数行全部为黑(0)，形成均匀的水平条纹。生成约束：网格至少 10 行高（不含控制行至少 9 行），控制行中至少有 3 个非黑标记且至少使用两种不同的标记颜色。

**规则**：
1. 将最底行识别为控制行并从输出中移除。
2. 读取控制行每个单元格的颜色：黑(0)→位移量 0、蓝(1)→1、红(2)→2、绿(3)→3、黄(4)→4。
3. 对剩余的条纹区域，逐列独立地将该列的像素循环下移对应的位移量（列底部溢出的像素回卷到列顶部）。
4. 输出为移除控制行后的、按列独立循环位移过的网格。

**关键洞察**：颜色在此处不代表视觉属性而是数值编码——蓝(1)到黄(4)编码了 1~4 的位移量。求解者需要对比多个示例才能建立"标记颜色→位移量"的映射，因为单个示例中可能只出现部分颜色。

## 新题 3：形状匹配配对后镜像印章

**组合逻辑**：[形状匹配/shape_matching](创新：不再用于重涂色，而是建立"谁印到谁"的配对关系) + [镜像/mirror](创新：镜像不由颜色触发，而由配对中源与目标的相对位置决定方向) + [印章覆盖/stamp](创新：印章的内容来自匹配到的模板，而非来自固定的邻域模板)

**来源原语**：形状匹配/shape_matching、归一化形状匹配/normalized_shape_matching、模板对象/template_object(参考题 2a5f8217)；镜像/mirror、特定标记触发镜像/marker_triggers_mirror(参考题 3e980e27)；印章覆盖/stamp(参考题 39e1d7f9)

**依赖链**：归一化形状匹配建立大图形与小图形的配对 → 配对决定哪个大图形印到哪个小图形位置 → 大图形相对于小图形的水平位置决定是否镜像 → 镜像后的大图形以小图形为锚点印章覆盖。四个环节环环相扣：不匹配就不知道配对，不知道配对就无法决定镜像方向，不镜像就无法正确印章。

通过归一化形状匹配将大图形与同形状的小图形配对，然后将大图形（可能需要镜像）印章到小图形所在位置。

**输入结构**：约 20x20 的网格，黑(0)背景。网格中有若干（3~4 个）"大图形"：每个是一个多色 4-连通精灵体，占据约 4x4~6x6 的边界框，内部有 2~3 种非黑颜色构成的图案。同时有等量的"小图形"：每个是一个单色 4-连通图形，仅 3~6 像素，颜色为灰(5)。每个小图形的归一化像素掩码（在边界框内的相对形状）恰好匹配某一个大图形的外轮廓（即大图形所有非黑像素位置的归一化掩码），形成一一对应。大图形和小图形在网格中互不接触（间隔至少 2 行或 2 列）。生成约束：每对配对的归一化形状唯一，不同对之间的形状互不相同；每个大图形的边界框不与其他大图形或任何小图形的边界框重叠。

**规则**：
1. 识别所有 4-连通前景图形，按边界框面积分为大图形组和小图形组（小图形组颜色均为灰(5)且面积显著小于大图形）。
2. 对每个大图形，提取其非黑像素在边界框内的归一化掩码；对每个小图形同样提取归一化掩码。
3. 按归一化掩码相同的原则，将每个大图形与唯一的小图形配对。
4. 对每对配对：若大图形的边界框中心列在其配对小图形的边界框中心列的左侧，则将大图形水平镜像（左右翻转）；否则保持原样。
5. 将（可能镜像后的）大图形以小图形的边界框左上角为锚点，印章覆盖到输出网格上（大图形的非黑像素覆盖输出对应位置）。同时移除原来大图形所在位置的像素（置为黑(0)背景）和小图形像素。
6. 若多个印章覆盖区域有重叠，按大图形边界框左上角从上到下、从左到右的顺序依次绘制，后绘制的覆盖先绘制的。

**关键洞察**：小图形不是装饰——它们的形状是查找配对大图形的索引键，它们的位置是大图形搬运的目标锚点。镜像方向由源与目标的相对水平位置隐式决定，需要对比多个示例中不同左右关系的配对才能归纳出此规则。

## 新题 4：周期修补后按象限指引重涂色

**组合逻辑**：[补全/repair + 平铺/tiling](创新：修补后的完整瓦片不是最终输出，而是中间产物) + [重涂色/recolor + 色彩指引块/color_guide](创新：指引块不直接映射象限颜色，而是将修补后瓦片中的每种前景色替换为指引块对应位置的颜色)

**来源原语**：补全/repair、平铺/tiling、周期瓦片/periodic_tile、缺失单元/missing_cell、最小周期推断填补/smallest_period_inferred_fill(参考题 29ec7d0e)；重涂色/recolor、色彩指引块/color_guide、指引色映射象限/guide_maps_quadrant(参考题 7c008303)

**依赖链**：周期修补产出完整瓦片并恢复全网格 → 恢复后才能识别网格中有多少种前景色 → 前景色按首次出现的行优先扫描顺序排列 → 与指引块中的颜色按位置一一对应 → 执行全局重涂色。修补与重涂色不可分离：不修补就缺失部分像素无法确定前景色集合；指引块映射关系依赖于修补后的完整色彩信息。

先用最小周期推断修补网格中的缺失像素，再根据指引色块将修补后的前景颜色全局替换。

**输入结构**：约 12x12 的网格。网格整体是一个周期为 p（p 在 3~4 之间）的重复色彩表格，使用 2~3 种非黑前景色（如红(2)、蓝(1)、绿(3)）和黑(0)背景色。网格中有若干（5~10 个）单元格被置为黑(0)作为缺失项，但每个周期位置至少在其他位置出现一次非缺失值。网格右下角有一个 1xK 的色彩指引条（K 等于前景色数目，约 2~3），用灰(5)边框包围以区分。指引条内从左到右依次放置 K 种颜色，如黄(4)、橙(7)、品红(6)。生成约束：指引条的颜色均不在主网格的前景色集合中；指引条位于主网格的周期区域之外（不干扰周期推断）。

**规则**：
1. 识别并分离灰(5)边框包围的指引条（位于右下角），提取其中的 K 种颜色序列。
2. 对主网格（排除指引条区域），推断最小周期 p 使得所有非黑单元格在 (row mod p, col mod p) 位置上颜色一致。
3. 构建 pxp 的基础瓦片，用该瓦片替换主网格中所有黑(0)缺失单元格，完成修补。
4. 统计修补后主网格中出现的所有非黑前景色，按行优先扫描顺序（从第 0 行第 0 列开始逐行扫描）记录每种颜色首次出现的位置，按此顺序排列前景色序列。
5. 将前景色序列的第 i 种颜色全局替换为指引条的第 i 种颜色（i 从 0 起）。
6. 输出替换后的主网格（不含指引条和灰边框）。

**关键洞察**：指引条的颜色映射目标不是固定的——它映射的是修补后才能完全确定的前景色集合。仅看未修补的网格可能会遗漏被完全挖去的某种前景色，导致映射错位。

## 新题 5：极值控制像素定框后框内射线交汇填色

**组合逻辑**：[描框/draw_frame + 极值行列/extreme_row_col](创新：矩形框不是最终输出，而是限定射线传播的边界) + [射线延伸/ray_cast + 碰撞停止/collision_stop](创新：射线不从菱形轮廓端点发出，而是从框内的枢轴像素沿四个对角方向发出，碰到矩形框边界停止) + [填充/fill](创新：射线将矩形框内部划分为区域，每个区域用枢轴像素的颜色填充)

**来源原语**：描框/draw_frame、控制像素/control_pixel、枢轴像素/pivot_pixel、极值行列/extreme_row_col、控制极值定矩形/ctrl_extremes_rect(参考题 e4075551)；射线延伸/ray_cast、碰撞停止/collision_stop(参考题 80a900e0)；填充/fill(参考题 93b581b8)

**依赖链**：四个控制像素的极值行列定义矩形框 → 矩形框约束射线的传播范围 → 枢轴像素发出的对角射线碰到框边界停止 → 射线将框内空间分割为若干区域 → 区域用特定规则填色。描框、射线、填充三步环环相扣：不画框则射线无边界可停、不发射线则无法分割区域、不分割则无法填色。

四个控制像素确定矩形框边界，框内枢轴像素向四个对角方向发射射线直至碰到框边，射线将框内划分为区域并用枢轴颜色填充射线经过的像素。

**输入结构**：约 18x18 的网格，黑(0)背景。网格中有四个单像素控制点，颜色各不相同（分别为蓝(1)、红(2)、绿(3)、黄(4)），它们的行列坐标构成四个极值：最上方像素（行最小）、最下方像素（行最大）、最左方像素（列最小）、最右方像素（列最大），四个极值分别由四个不同的控制点承担（即没有一个控制点同时是两个方向的极值）。网格中还有恰好一个橙(7)色的枢轴像素，其行坐标严格介于最上和最下控制点之间，列坐标严格介于最左和最右控制点之间。生成约束：枢轴像素到四条矩形边的距离均至少为 2（保证射线有足够长度可见）；四个控制点互不共行也互不共列。

**规则**：
1. 找到四个控制像素，确定最上行 r_top（最上控制点的行）、最下行 r_bot（最下控制点的行）、最左列 c_left（最左控制点的列）、最右列 c_right（最右控制点的列）。
2. 绘制矩形框：顶边为第 r_top 行从 c_left 到 c_right 全部涂为最上控制点的颜色；底边同理涂最下控制点颜色；左边为第 c_left 列从 r_top+1 到 r_bot-1 涂为最左控制点颜色；右边同理涂最右控制点颜色。四个角像素由水平边（顶边/底边）优先覆盖。
3. 从橙(7)枢轴像素出发，沿四个对角方向（左上、右上、左下、右下）各发射一条射线。每条射线逐步延伸（每步行列各变化 1），将经过的黑(0)背景像素涂为灰(5)，碰到非黑像素（矩形框边界或控制点）时停止（不覆盖终点像素）。
4. 枢轴像素自身保持橙(7)不变。
5. 矩形框外部和框边界上的像素不受射线影响。

**关键洞察**：控制像素同时承担两个角色——它们的极值位置定义了矩形框的几何形状，而它们的颜色分别标注了矩形框的四条边。枢轴像素发出的对角射线创造了一个X形分割，但射线的长度完全由矩形框的形状和枢轴位置共同决定。

## 新题 6：面积筛选后描边再按尺寸分类重涂色

**组合逻辑**：[擦除/erase + 面积筛选/area_filtering](创新：擦除不由标记计数决定，而是用面积阈值筛选) + [描边/outline + 尺寸分类/size_classification](创新：描边不仅限于特定尺寸类，而是所有存活对象都描边，描边颜色由对象尺寸类别决定) + [重涂色/recolor](创新：对象本体被重涂为统一色，个体信息转移到边框颜色上)

**来源原语**：擦除/erase、面积筛选/area_filtering、最少标记者选中/least_marker_selected(参考题 54db823b)；描边/outline、尺寸分类/size_classification、微型对象描边/micro_obj_outlined(参考题 b27ca6d3)；重涂色/recolor(参考题 37d3e8b2)；计数/counting(参考题 a3325580)

**依赖链**：计算所有前景对象的面积 → 面积最大的类别确定存活对象（同时该最大面积值成为面积阈值） → 擦除低于阈值的对象 → 对存活对象按面积分为"大""小"两档 → 大档描绿(3)边框、小档描黄(4)边框 → 对象本体统一重涂为灰(5)。擦除、描边、重涂色三步依赖于同一组面积计算结果，但各自利用不同方面。

先擦除面积不属于最大面积类别的前景对象，再对存活对象按面积分档描不同颜色的边框，最后将对象本体重涂为统一颜色。

**输入结构**：约 16x16 的网格，黑(0)背景。网格中散布着 6~8 个单色 4-连通前景对象，颜色各异（使用蓝(1)、红(2)、绿(3)、黄(4)、橙(7)、品红(6)中的若干种，每个对象一种颜色但不同对象可同色）。每个对象是不规则的 4-连通图形，面积在 3~12 像素之间。对象可分为三档面积：小档（3~4 像素，约 2 个对象）、中档（6~7 像素，约 2~3 个对象）、大档（10~12 像素，约 2~3 个对象）。各对象互不相邻（边界框间隔至少 1 个背景像素）。生成约束：至少有两个对象属于最大面积档且面积相同；各档的面积值互不重叠，保证分档无歧义。

**规则**：
1. 找到所有 4-连通前景对象，计算每个对象的像素面积。
2. 找到出现次数最多的面积值（即最大面积类别中对象数最多的那个面积值；若有多个面积值并列出现次数最多，取面积值最大的那个）。
3. 将面积不等于该值的所有对象擦除（像素置为黑(0)背景）。
4. 对剩余存活对象：计算它们的面积中位数 M（若对象数为偶数，取较小的中间值）。面积 > M 的对象归为"大档"，面积 <= M 的归为"小档"。
5. 将所有存活对象的本体像素重涂为灰(5)。
6. 对每个存活对象，扩展其边界框各方向 1 个像素（裁剪至网格边缘），在扩展框的周长上所有当前为黑(0)的像素涂为边框色：大档涂绿(3)，小档涂黄(4)。按对象边界框左上角从上到下、同行从左到右的顺序依次处理，后处理的边框像素覆盖先处理的。

**关键洞察**：面积在此题中承担三重角色——筛选存活者、分档决定边框颜色、以及隐式地确定处理顺序。求解者容易只注意到筛选作用而忽略分档规则，需要对比存活对象的边框颜色差异才能发现尺寸分类机制。

2. 对每个面板，找到面板水平中线（行数除以 2 取整），将中线作为上下镜像对称轴。

6. 输出拼接后的网格。

**关键洞察**：面板编号与选取方向的对应关系（偶数面板取上半、奇数面板取下半）是隐蔽规则，仅看单个示例无法确定。且必须先完成对称补全再选取，否则缺失区域恰好落在被选取的半幅内时输出会有黑色空洞。

## 新题 8：格网印章后按邻域密度擦除

**组合逻辑**：[印章覆盖/stamp + 邻域模板/neighborhood_template](创新：印章后的结果不是最终输出，而是中间状态) + [计数/counting + 擦除/erase](创新：计数对象不是孔洞或标记，而是每个格网单元的非背景邻居数，用于决定擦除)

**来源原语**：印章覆盖/stamp、标记单元格/marker_cell、邻域模板/neighborhood_template、格网/lattice、分隔线划分/separator_partition、示例邻域传递同色/exemplar_copied_to_same_color(参考题 39e1d7f9)；计数/counting(参考题 37d3e8b2)；擦除/erase(参考题 54db823b)

**依赖链**：识别装饰标记的邻域模板并印章到所有同色标记 → 印章改变了格网中各单元格的颜色分布 → 在印章后的格网上统计每个非背景单元格的 4-邻域中非背景邻居数 → 邻居数低于阈值的单元格被擦除。印章操作直接改变了后续计数的输入，二者不可独立求解。

在格网中将示例标记的邻域模板印章到所有同色标记后，擦除那些非背景邻居不足的孤立单元格。

**输入结构**：约 13x13 的网格。灰(5)色的水平和竖直分隔线将网格划分为一个 4x4 的格网（每个格网单元约 3x3 含分隔线外的 2x2 可用像素），黑(0)背景。格网中大多数单元格为背景色。有一个蓝(1)色的"装饰标记"单元格，其上、下、左、右四个相邻格网单元中有 2~3 个被涂为不同颜色（红(2)、绿(3)、黄(4)之一），构成邻域模板。另有 2~4 个独立的蓝(1)色标记单元格散布在格网中其他位置（无邻域装饰）。生成约束：装饰标记是唯一一个蓝(1)单元格周围有非背景邻居的蓝单元格；印章时超出格网边界的偏移被丢弃；不同印章之间不会在同一单元格产生冲突（即各独立蓝标记的邻域模板投影不重叠）。

**规则**：
1. 将网格压缩为格网表示（每个分隔线间的单元格取一个值）。
2. 找到唯一的装饰蓝(1)标记——即在格网中蓝(1)单元格中唯一一个至少有一个非背景 4-邻域邻居的。
3. 提取装饰标记的邻域模板：记录其上/下/左/右邻居中非背景单元格的相对偏移和颜色。
4. 对格网中所有其他蓝(1)标记单元格，将邻域模板的每个偏移应用到该标记位置：若偏移后的位置在格网范围内且当前为背景色，则涂上模板中对应的颜色。蓝标记自身保持蓝色不变。
5. 印章完成后，扫描格网中所有非背景单元格，统计每个单元格的 4-邻域（上下左右格网邻居）中非背景单元格的数目。
6. 将非背景邻居数为 0 的非背景单元格擦除（置为背景黑(0)）。装饰标记和其他蓝标记不受此规则豁免——若它们的邻居数也为 0 则同样被擦除。
7. 将格网还原为完整网格输出（恢复分隔线和单元格尺寸）。

**关键洞察**：印章操作本身能"拯救"某些原本孤立的单元格——当两个蓝标记的印章邻域恰好相邻时，印章产物互相成为对方的邻居而存活；而那些印章邻域落在格网边缘、无法获得足够邻居的单元格则被清除。求解者需要先完成印章再做邻居计数，顺序颠倒会导致错误结果。

## 新题 9：颜色互换编码旋转方向后排序拼接

**组合逻辑**：[颜色互换/color_swap](创新：互换不是最终变换，而是编码了一个布尔信号——精灵体是否需要旋转 180 度) + [排序/sort + 面积排序/area_ordering](创新：排序不是为了拼接展示，而是为了确定最终输出中精灵体的排列顺序) + [拼接/concatenate + 基线对齐排列/baseline_aligned_pack](保留底边对齐的拼接方式)

**来源原语**：颜色互换/color_swap、双色源图案/two_color_source_pattern、原位颜色互换/in_place_color_swap(参考题 2b01abd0)；排序/sort、拼接/concatenate、面积排序/area_ordering、基线对齐排列/baseline_aligned_pack、精灵体/sprite(参考题 4df5b0ae)

**依赖链**：识别每个精灵体是否处于颜色互换状态 → 互换状态决定该精灵体是否旋转 180 度 → 计算精灵体面积用于排序 → 按面积从小到大排列并底边对齐拼接输出。颜色互换与旋转的耦合是隐蔽规则：精灵体的两种颜色是否被互换了，编码了是否需要旋转的指令。

每个双色精灵体若处于颜色互换状态则旋转 180 度，然后按面积排序后底边对齐拼接为一行输出。

**输入结构**：约 12x20 的网格，黑(0)背景。网格中散布着 4~5 个互不接触的双色精灵体。每个精灵体是一个 4-连通图形，使用恰好两种非黑颜色（如红(2)与蓝(1)），面积约 5~10 像素，边界框约 3x3~4x4。网格的最底行是一个"色彩参考条"：从左到右以 2 像素为一组，每组两个相邻像素分别展示一对颜色的"标准顺序"（如先红(2)后蓝(1)表示红为主色蓝为副色）。参考条中颜色对的数目等于精灵体数目，且每个精灵体恰好使用参考条中某一对的两种颜色。每个精灵体内，像素数较多的颜色为实际"主色"、较少的为"副色"。生成约束：每个精灵体内两种颜色的像素数不同（保证主副色明确）；每对颜色组合在参考条中只出现一次，各精灵体的颜色对互不相同；各精灵体面积互不相同。

**规则**：
1. 识别最底行的色彩参考条并分离。将参考条中每个 2 像素组解读为一个颜色对：左像素为标准主色、右像素为标准副色。
2. 对每个精灵体，确定其两种颜色中像素数较多者为实际主色、较少者为实际副色。
3. 将每个精灵体的实际主色/副色与参考条中的标准主色/副色对比：若实际主色等于标准主色（即颜色未互换），则该精灵体保持原样；若实际主色等于标准副色（即颜色已互换），则将该精灵体旋转 180 度（上下翻转加左右翻转）。
4. 计算每个精灵体的像素面积。
5. 将所有精灵体（可能已旋转）按面积从小到大排列，从左到右紧密拼接，底边对齐。精灵体之间无间隔。
6. 输出网格高度等于最大精灵体边界框的高度，宽度等于所有精灵体边界框宽度之和，背景为黑(0)。

**关键洞察**：颜色的主副关系是否与参考条一致，是一个隐式的布尔开关。求解者需要发现参考条的作用不是装饰而是定义了"正常"的颜色分配，偏离标准分配的精灵体需要被翻转回"正确"朝向。

## 新题 10：对角填充区域内平铺周期图案

**组合逻辑**：[填充/fill + 标记块/marker_block + 对角映射/diagonal_mapping](创新：对角映射不仅确定填色区域，还确定填充内容——不再是单色填充，而是用周期图案填充) + [平铺/tiling + 周期瓦片/periodic_tile](创新：瓦片不是从残缺网格推断，而是从标记块本身的颜色排列中提取)

**来源原语**：填充/fill、标记块/marker_block、象限区域/quadrant_region、对角映射/diagonal_mapping、标记色填对角区/marker_fills_diagonal_region(参考题 93b581b8)；平铺/tiling、周期瓦片/periodic_tile(参考题 29ec7d0e)

**依赖链**：标记块的颜色排列既定义了四个对角区域的映射关系，也同时构成了用于填充的周期瓦片 → 每个对角区域用标记块作为基础瓦片进行周期平铺填充 → 平铺超出区域边界的部分被裁剪。标记块同时承担"区域指引"和"瓦片模板"两个角色，缺一不可。

2x2 标记块的四种颜色指定四个对角区域的填充，每个区域用整个 2x2 标记块作为周期瓦片平铺填充（而非单色填充）。

**输入结构**：约 12x12 的网格，黑(0)背景。网格中央偏离中心处有一个 2x2 的标记块，四个像素颜色互不相同（如左上红(2)、右上蓝(1)、左下绿(3)、右下黄(4)）。标记块不位于网格的最边缘（距每条边至少 3 个像素），其余所有像素为黑(0)背景。生成约束：标记块的四种颜色均为非黑色且互不相同。

**规则**：
1. 定位 2x2 标记块的位置，记其左上角为 (r, c)。
2. 定义四个对角区域（不含标记块自身的 2x2 区域）：
   - 左上区域：行 < r 且列 < c 的所有像素。
   - 右上区域：行 < r 且列 > c+1 的所有像素。
   - 左下区域：行 > r+1 且列 < c 的所有像素。
   - 右下区域：行 > r+1 且列 > c+1 的所有像素。
3. 对角映射关系：标记块右下角颜色黄(4) → 左上区域；标记块左下角颜色绿(3) → 右上区域；标记块右上角颜色蓝(1) → 左下区域；标记块左上角颜色红(2) → 右下区域。（每个像素填充到对角线方向相反的区域。）
4. 对每个对角区域，用整个 2x2 标记块（原始排列，不旋转）作为周期瓦片进行平铺：区域内坐标 (i, j) 处的颜色取标记块的 (i mod 2, j mod 2) 位置的颜色。
5. 标记块自身和四个对角区域之间的"十字带"区域（与标记块同行或同列的像素，但不在标记块内部）保持黑(0)不变。
6. 输出整个网格。

**关键洞察**：标记块的功能是双重的——它的每个像素的颜色在对角映射规则中指定了"哪个区域被激活"，同时整个 2x2 块作为周期瓦片定义了填充的图案纹理。这意味着修改标记块中任一像素的颜色会同时改变区域分配和填充纹理，二者不可分离。

**依赖链**：找到四个控制像素确定矩形范围 → 四个控制像素中最上方和最左方的颜色成为棋盘格的两种颜色 → 在矩形框内部填充棋盘格图案 → 矩形框边界用剩余两个控制像素的颜色交替着色。连线（画框边）与棋盘格生成依赖于同一组控制像素的位置和颜色信息，但使用方式完全不同。

**规则**：
1. 找到四个控制像素，确定最上行 r_top、最下行 r_bot、最左列 c_left、最右列 c_right。
2. 确定棋盘格的两种颜色：色 A 为最上方控制点的颜色，色 B 为最左方控制点的颜色。
3. 确定边框的两种颜色：色 C 为最下方控制点的颜色，色 D 为最右方控制点的颜色。
4. 绘制矩形边框：边框像素位于第 r_top 行、第 r_bot 行（水平边）以及第 c_left 列、第 c_right 列（垂直边）的 r_top 到 r_bot 范围内。边框像素按 (行+列) 的奇偶交替使用色 C 和色 D：(行+列) 为偶数涂色 C，奇数涂色 D。
5. 在矩形框内部（r_top+1 到 r_bot-1 行，c_left+1 到 c_right-1 列）填充棋盘格图案：(行+列) 为偶数涂色 A，奇数涂色 B。
6. 四个控制点原来的位置被边框或内部图案覆盖。框外保持黑(0)背景。

**关键洞察**：四个控制像素被分成两组发挥不同作用：位于上方和左方的贡献棋盘格内部颜色，位于下方和右方的贡献边框颜色。这种按方位分组的规则需要对比多个示例（控制点颜色变化但分组规则不变）才能归纳。

## 新题 13：镜像产生双色图案后按面积差异擦除半边

7. 移除分隔线列，将保留侧裁剪输出（输出宽度为原宽度减 1 再除以 2）。

**关键洞察**：镜像加颜色互换后，两侧看起来形状完全相同但颜色分配相反。选择保留哪一侧的规则基于"主色面积更大的一侧胜出"——由于互换后镜像侧的主色变少了，实际上总是保留原始源侧。但求解者需要理解整个镜像-互换-比较的逻辑链才能确信这一规则，因为不同示例中源侧可能在左也可能在右。

## 新题 14：稀疏标记计数决定精灵体排序键后柱状图输出

**关键洞察**：标记像素在输入中是矩形内部的"杂质"，但它们的数量同时编码了两种信息——排列顺序和输出高度。求解者可能先注意到标记数与高度的关系，但需要进一步发现排序规则才能完全确定输出。

## 新题 15：邻域模板作为对称补全的线索后印章传播

**组合逻辑**：[对称补全/symmetry_completion](创新：补全的对象不是一个大网格，而是邻域模板本身——模板只给出一半，需推断另一半) + [印章覆盖/stamp](创新：印章使用的是补全后的完整模板，而非直接读取的模板) + [描边/outline](创新：印章完成后对每个印章产物描边以标记其边界)

**来源原语**：对称补全/symmetry_completion、镜像/mirror、缺失区域/missing_patch(参考题 9ecd008a)；印章覆盖/stamp、邻域模板/neighborhood_template、标记单元格/marker_cell、示例邻域传递同色/exemplar_copied_to_same_color(参考题 39e1d7f9)；描边/outline、边框/border_frame(参考题 b27ca6d3)

**依赖链**：装饰标记的邻域只有半边有颜色（另半边为背景）→ 推断邻域模板具有左右对称性并补全 → 用完整模板印章到所有同色标记 → 对每个印章结果描边。补全是印章的前提：不补全则印出的图案不完整；描边依赖于印章产物的形状。

装饰标记周围的邻域模板只有一半被着色，通过左右对称性推断完整模板后，印章到所有同色标记并对印章结果描边。

**输入结构**：约 15x15 的网格，黑(0)背景。网格中有一个蓝(1)色的"装饰标记"像素，其 3x3 邻域（以标记为中心）中，左半部分（标记左侧及标记所在列）有 2~3 个像素被涂为非黑非蓝颜色（如红(2)、绿(3)），右半部分（标记右侧列）全为黑(0)背景。完整的邻域模板应具有左右对称性（以标记所在列为对称轴）。网格中另有 2~4 个孤立的蓝(1)色像素散布在其他位置，它们的 3x3 邻域全为黑(0)背景。生成约束：所有蓝标记及其 3x3 邻域扩展后的 5x5 区域互不重叠（保证描边空间充足）；装饰标记与非装饰标记的区分依据是是否有非黑非蓝邻居。

**规则**：
1. 找到所有蓝(1)像素。唯一一个 3x3 邻域中含非黑非蓝像素的蓝像素为装饰标记，其余为普通标记。
2. 提取装饰标记的半边邻域模板（以标记为中心的 3x3 区域内，所有非黑非蓝像素的相对偏移和颜色）。
3. 将模板关于标记所在列做左右镜像补全：对每个模板像素 (dr, dc)，添加 (dr, -dc) 处的像素（若尚不存在），颜色与 (dr, dc) 相同。标记自身 (0,0) 保持蓝(1)。
4. 将补全后的完整 3x3 模板印章到每个普通蓝标记位置：以普通标记为中心，将模板的每个非背景偏移位置涂上对应颜色（超出网格边界的偏移丢弃；标记自身保持蓝(1)）。
5. 对装饰标记也执行同样的补全绘制（将其右半边补上镜像颜色）。
6. 对网格中每个蓝(1)标记（包括装饰标记和普通标记），将以该标记为中心的 3x3 区域视为一个对象，扩展其边界框各方向 1 像素（裁剪至网格边缘），在扩展框的周长上所有当前为黑(0)的像素涂为灰(5)。按标记从上到下、从左到右的顺序依次处理。

**关键洞察**：装饰标记看似只有一半信息，但隐含了对称性约束——求解者需要发现模板是左右对称的，从而推断出缺失的右半部分。仅有半边模板时印章结果不对称，对比多个示例可发现所有印章产物都是对称的，从而反推补全规则。
