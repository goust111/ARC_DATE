## 新题 1：分裂编码印章——颜色定旋转、位置定涂色

**组合逻辑**：[印章覆盖stamp] + [旋转rotate](创新：源像素颜色编码旋转角度，而非直接涂色) + [最近边归属nearest_side_assignment](创新：用于确定印章涂色，而非掩码归属)

**来源原语**：
- 印章覆盖(stamp)、模板面板(template_panel)、前景像素(foreground_pixel)、分块对应(block_correspondence)、源色决定模板涂色 ← b190f7f5
- 旋转(rotate)、标记色定朝向(marker_color_sets_orientation) ← 6e4f6532
- 最近边归属(nearest_side_assignment)、最近边决定涂色(recolor_by_nearest_frame_side)、边框边(frame_side) ← 9aec4887

**依赖链**：源像素同时编码两个独立信号：颜色通道编码旋转角度（颜色→旋转），位置通道通过输出块到边缘的距离编码涂色（位置→涂色）。两条信息通道从同一源像素分叉，又在同一印章实例上汇合——旋转决定模板朝向，最近边决定模板颜色。缺少任一通道均无法确定完整输出。

每个源前景像素在输出中展开为一个旋转后、按输出位置区域涂色的模板副本。

**输入结构**：约 13x6 的网格，黑(0)背景。上部为一个 4x4 源面板，包含 2~4 个散落的非背景像素，颜色仅取自 {红(2), 绿(3), 蓝(1)}，其余为黑(0)。源面板下方隔一行背景后，是一个 4x4 模板面板，由灰(5)像素构成一个非对称的 4-连通图形（3~7 像素，在 0/90/180/270 四种旋转下两两不同），其余为黑(0)。在整个网格四条边的中点位置各有一个单像素颜色标记：上边中点=黄(4)，右边中点=橙(7)，下边中点=品红(6)，左边中点=栗(9)（边长为偶数时标记偏左或偏上）。生成约束：源面板中前景像素互不相邻；模板图形在四种旋转下两两不同。

**规则**：
1. 创建 16x16 输出网格，初始化为黑(0)。
2. 对源面板中每个非背景像素 (r, c)（0-indexed）：
   a. 根据颜色确定旋转角度：红(2)→0，绿(3)→顺时针 90，蓝(1)→顺时针 180。
   b. 将模板面板按该角度旋转（以模板 4x4 边界框中心为旋转中心）。
   c. 计算输出中第 (r, c) 个 4x4 块的中心行列 (R, C) = (r*4+1.5, c*4+1.5)。比较该中心到输出四边的距离：上距离=R，下距离=15-R，左距离=C，右距离=15-C。取最小距离对应的边；若存在并列，按上、左、下、右优先级选取。
   d. 用所选边对应的颜色标记（黄(4)/栗(9)/品红(6)/橙(7)）替换旋转后模板中所有灰(5)像素。
   e. 将涂色后的旋转模板放入输出的第 (r, c) 个 4x4 块（块起始坐标 = (r*4, c*4)）。
3. 未被印章覆盖的输出像素保持黑(0)。

**关键洞察**：同一源像素的颜色与位置分别编码旋转和涂色两个独立维度，必须分别解码并在印章上合成；仅看单个示例难以区分"颜色决定涂色"还是"颜色决定旋转"，需要对比多个示例中相同颜色在不同位置的输出来归纳两条规则。

## 新题 2：曼哈顿领地竞争与计数直方图

**组合逻辑**：[生长grow](创新：多种子同步曼哈顿距离竞争) + [计数counting](对生长结果的领地面积计数) + [填充fill / 计数编码为条长count_as_bar_length](创新：领地面积→直方图条高) + [忽略干扰项ignore_distractors](创新：距离并列区域不计入任何种子)

**来源原语**：
- 生长(grow)、逐步推进(stepwise_advance) ← 758abdf0
- 碰撞停止(collision_stop) ← 142ca369
- 计数(counting)、计数编码为条长(count_as_bar_length)、条形图(bar_chart)、忽略干扰项(ignore_distractors) ← 1fad071e
- 排序(sort)、顺序对应(ordinal_correspondence) ← f3cdc58f

**依赖链**：种子的空间分布决定曼哈顿领地划分→领地面积产生计数→计数转化为直方图条高→种子的输入位置顺序决定直方图列序。空间模拟的结果驱动聚合，聚合结果驱动渲染布局，删去任一步骤输出无法确定。

多个种子像素同时向外生长争夺领地，每个种子的最终领地面积被编码为直方图中对应颜色柱的高度。

**输入结构**：约 12x12 的网格，黑(0)背景。散布 3~5 个种子像素，每个种子颜色各不相同，取自 {红(2), 蓝(1), 绿(3), 黄(4), 橙(7)}。种子之间互不相邻（至少间隔 2 个像素）。网格中无其他前景元素。生成约束：种子数量 N 满足 N <= 网格行数，以保证直方图可容纳；不同种子到任一背景像素的曼哈顿距离不全相同（即总存在唯一最近种子的像素）。

**规则**：
1. 对网格中每个背景像素，计算其到所有种子的曼哈顿距离，归属于距离最小的种子。若存在两个或以上种子距离并列最小，该像素归为"争议区"，不计入任何种子领地。
2. 每个种子的领地面积 = 归属于该种子的像素数 + 1（种子自身）。
3. 按种子在输入网格中的列位置从左到右排序；若列相同则按行位置从上到下排序。
4. 输出为一个 N 列的直方图网格，宽度 = 种子数 N，高度 = 最大领地面积。每列对应排序后的一个种子，从底行向上填充该种子颜色，填充行数 = 该种子领地面积。未填充的单元格为黑(0)。

**关键洞察**：领地面积依赖所有种子的空间关系（非两两独立），改变任一种子位置会改变所有领地大小；争议区（并列距离）不计入任何种子的面积，需要对比多个示例才能归纳出并列处理规则。

## 新题 3：补线构建封闭域与图例定色填充

**组合逻辑**：[补线line_completion](已有) + [洪泛填充flood_fill](创新：作用于补线后涌现的新封闭区域，而非预存区域) + [图例映射颜色legend_maps_color](创新：图例的键是封闭区域的边界颜色而非标记颜色)

**来源原语**：
- 补线(line_completion)、直线段(straight_line_segment)、间隙长度限制(gap_length_constraint) ← 7b80bb43
- 洪泛填充(flood_fill)、封闭区域(enclosed_region)、区域可达性(region_reachability) ← 543a7ed5
- 颜色图例(color_legend)、图例映射颜色(legend_maps_color) ← 9385bd28

**依赖链**：补线闭合间隙→间隙闭合后涌现出原本不存在的封闭区域→封闭区域的边界颜色查图例→图例给出填充色。补线是填充的前提（不补线则不封闭），图例是填充色的来源（不查图例则不知涂什么色）。三步环环相扣，删去补线步骤则区域不封闭，删去图例则填充色不确定。

断裂的彩色线段被补全后围合出新的封闭区域，每个封闭区域根据其边界线颜色查找图例确定填充色。

**输入结构**：约 15x15 的网格，黑(0)背景。3~5 条彩色直线段（水平或垂直），每条是同色像素的连续行/列段（长度 4~10 像素），颜色取自 {红(2), 蓝(1), 绿(3)}。部分线段中间有恰好 1 像素宽的间隙（该位置为黑(0)）。线段的端点位置经过安排，使得补全间隙后，某些不同颜色或同颜色的线段首尾相接或垂直交汇，围合出 1~3 个封闭矩形区域。网格左下角有一个竖直排列的颜色图例，每行为两个相邻像素：左像素为键色（红(2)/蓝(1)/绿(3)之一），右像素为值色（黄(4)/灰(5)/橙(7)之一），图例行数等于所用线段颜色种类数。生成约束：每个封闭区域的边界像素恰好只含一种线段颜色（即每个封闭区域由同一颜色的线段围合而成）；间隙宽度恰好为 1 像素；图例中键色不重复。

**规则**：
1. 扫描每条线段，若线段中存在恰好 1 像素的间隙（间隙两侧均为同色像素），则用该线段颜色填补间隙。
2. 补线完成后，识别所有封闭区域：从网格边界出发，通过黑(0)像素进行 4-连通洪泛扩展，标记所有可达的背景像素为"外部"。未被标记的黑(0)像素群构成封闭区域。
3. 对每个封闭区域，检查其 4-邻接的非背景像素颜色——根据生成约束，这些像素均为同一颜色 C。
4. 在图例中查找键色 = C 的行，取其值色 V。将该封闭区域的所有像素填充为 V。
5. 图例像素、线段像素（含补全的像素）及外部背景像素保持不变。

**关键洞察**：补线是封闭区域涌现的前提——输入中不存在封闭区域，只有补全间隙后才会形成；填充色不由边界颜色直接决定，而是通过图例间接映射，需要对比多个示例确认图例查表规则而非"边界色即填充色"。

## 新题 4：缺陷计数排序与修补裁剪拼排

**组合逻辑**：[计数counting](创新：计数修补前的缺陷数，作为排序键) + [修补repair](已有) + [裁剪crop](已有) + [排序sort](创新：排序键为缺陷计数，而非空间位置) + [边缘指示方向edge_indicates_direction](创新：决定输出排列轴向与对齐侧)

**来源原语**：
- 修补(repair)、嵌入与孤立(embedded_vs_isolated)、边缘线(edge_line)、边缘指示方向(edge_indicates_direction) ← 8886d717
- 计数(counting) ← 1fad071e, f3cdc58f
- 排序(sort)、裁剪(crop)、顺序对应(ordinal_correspondence) ← 8e1813be
- 尺寸分类(size_classification) ← aedd82e4

**依赖链**：缺陷计数必须在修补前完成（修补后缺陷消失，无法回溯计数）→修补后裁剪得到干净对象→缺陷计数作为排序键决定输出排列顺序→边缘线决定排列轴向和对齐方向。计数与修补在时序上耦合（必须先数后修），排序依赖计数结果，布局依赖边缘线方向，四步紧耦合。

多个带缺陷标记的对象被修补、裁剪后，按修补前的缺陷数量排序，沿边缘线指示的方向排列输出。

**输入结构**：约 20x15 的网格，黑(0)背景。3~4 个分离的 4-连通单色对象，每个对象由蓝(1)像素构成（4~12 像素），对象之间至少间隔 2 行/列。每个对象内部有 1~4 个像素被替换为红(2)（缺陷标记），这些红(2)像素在对象内部——即其 4-邻居中至少 3 个为蓝(1)或红(2)。网格的一条完整边（上/下/左/右之一）由灰(5)像素铺满（厚度 1 像素），其余三边无灰色像素。生成约束：各对象的缺陷数两两不同；每个对象的蓝(1)+红(2)像素合并后为 4-连通。

**规则**：
1. 识别每个 4-连通的蓝(1)+红(2)混合分量为一个对象。
2. 记录每个对象中红(2)像素的数量作为该对象的缺陷计数 D。
3. 将每个对象中的红(2)像素重涂为蓝(1)（修补）。
4. 计算每个修补后对象的最小边界框并裁剪。
5. 确定灰(5)边缘线所在边：
   - 水平边缘线（上或下）：裁剪对象按 D 从小到大从左到右排列，相邻对象之间隔 1 列黑(0)。若边缘线在上边，所有对象顶端对齐输出顶行；若在下边，所有对象底端对齐输出底行。
   - 垂直边缘线（左或右）：裁剪对象按 D 从小到大从上到下排列，相邻对象之间隔 1 行黑(0)。若边缘线在左边，所有对象左端对齐输出左列；若在右边，所有对象右端对齐输出右列。
6. 输出网格尺寸恰好容纳所有裁剪对象及间隔，灰(5)边缘线不出现在输出中。

**关键洞察**：排序键是修补前的缺陷数——修补后缺陷消失，排序键必须在修补之前提取；边缘线的位置同时编码排列轴向（水平/垂直）和对齐侧（上/下/左/右），需要对比多个示例中边缘线位置与输出布局的关系才能归纳此规则。

## 新题 5：图案联合补全与拓扑条件描边

**组合逻辑**：[对称补全pattern_union_completion] + [分组grouping / 按边框颜色分组group_by_frame_color](已有) + [描边outline](创新：描边颜色由补全后是否产生孔洞决定) + [洪泛填充flood_fill](创新：仅对含孔洞的边框执行填充)

**来源原语**：
- 对称补全(pattern_union_completion)、分组(grouping)、彩色边框(colored_frame)、内部图案(internal_motif)、同色框共享图案(same_color_frames_share_motif)、按边框颜色分组(group_by_frame_color) ← 42918530
- 描边(outline)、洪泛填充(flood_fill)、封闭区域(enclosed_region)、外部邻接区域(exterior_adj_region)、区域可达性(region_reachability)、孔洞填色轮廓描色(holes_fill_outline) ← 543a7ed5

**依赖链**：同色框分组→组内联合补全图案→补全可能改变内部拓扑（创建或消除孔洞）→孔洞存在性决定该颜色组所有边框的描边颜色（有孔洞→绿(3)描边+黄(4)填孔，无孔洞→黄(4)描边无需填充）。补全结果决定拓扑，拓扑决定描边颜色，形成跨步骤的条件分支。

同色彩色边框共享内部图案后，依据补全后图案是否形成封闭孔洞，分别施加不同颜色的外描边和孔洞填充。

**输入结构**：约 18x18 的网格，黑(0)背景。2x3 或 3x2 的矩形阵列排布了 6 个大小相同的彩色边框，相邻边框之间以 1 列/行黑(0)分隔。每个边框为 5x5 的单像素厚实心方形边界，边界像素为该边框颜色。边框颜色取自 {红(2), 蓝(1), 品红(6)}，每种颜色恰好出现 2 个边框。部分边框内部（3x3 区域）含有与边框同色的额外像素（1~4 个），构成该边框的内部图案；其余内部位置为黑(0)。绿(3)和黄(4)不在输入中出现。生成约束：每种颜色的两个边框内部图案不完全相同（至少有一个位置不同）；至少一种颜色的联合图案在补全后会围合出一个黑(0)孔洞（即联合后的同色像素将某个内部黑(0)像素从边框外部切断），至少一种颜色的联合图案不会产生孔洞。

**规则**：
1. 按边框颜色将 6 个边框分为 3 组，每组 2 个。
2. 对每组，收集两个边框内部 3x3 区域中同色像素的相对位置并取并集，得到该颜色组的联合图案。
3. 将联合图案写入该组的每一个边框内部（将并集中有而原边框中无的位置涂上边框颜色）。
4. 对每个补全后的边框，检查其 5x5 范围内的拓扑：在边框内部 3x3 区域中，从该区域的四条边出发通过黑(0)像素做 4-连通扩展，无法到达的黑(0)像素构成孔洞。
5. 对每种颜色组判定：
   - 若联合图案产生了孔洞：该组所有边框的孔洞像素填充为黄(4)；在每个边框的 5x5 外围（与边框 8-邻接的背景像素）涂绿(3)作为外描边。
   - 若联合图案未产生孔洞：在每个边框的 5x5 外围（与边框 8-邻接的背景像素）涂黄(4)作为外描边，无需填充。
6. 若两个相邻边框的描边区域重叠（在它们之间的 1 像素间隔处），绿(3)优先于黄(4)。
7. 边框像素和补全后的内部像素保持不变。

**关键洞察**：描边颜色不是固定的——它取决于联合补全后图案的拓扑性质（是否有孔洞），而补全本身取决于同色边框的分组和并集运算。同一组的两个边框总是获得相同的描边颜色（因为它们共享同一联合图案的拓扑），但不同颜色组可能获得不同描边颜色。需要对比多个示例中"有孔"和"无孔"组的描边差异才能归纳条件规则。

## 新题 6：对角配对矩形与空间区域定色

**组合逻辑**：[对角配对diagonal_pairing](已有) + [填充fill](创新：填充色非来自图例而来自最近边归属) + [最近边归属nearest_side_assignment](创新：作用于矩形中心而非单个像素) + [处理顺序保护processing_order_protection](创新：面积小的矩形优先覆盖大的)

**来源原语**：
- 对角配对(diagonal_pairing)、填充(fill)、拐角标记(corner_marker)、处理顺序保护(processing_order_protection) ← 9385bd28
- 最近边归属(nearest_side_assignment)、最近边决定涂色(recolor_by_nearest_frame_side)、边框边(frame_side) ← 9aec4887
- 擦除(erase) ← 758abdf0

**依赖链**：同色标记配对确定矩形几何→矩形中心位置做最近边判定→最近边颜色指示符确定填充色→矩形重叠时面积优先级解决冲突。配对提供空间几何，最近边提供颜色信号，面积提供冲突仲裁——三个来源不同的信息在矩形上交汇。

同色标记像素对角配对定义矩形区域，每个矩形依据其中心到网格边缘的距离确定填充色，重叠区域由面积更小的矩形占优。

**输入结构**：约 16x16 的网格，黑(0)背景。散布 2~4 对标记像素，每对颜色相同且每种颜色恰好出现 2 个像素，标记颜色取自 {红(2), 蓝(1), 绿(3), 品红(6)}。每对标记位于各自定义矩形的对角位置（即一个在左上角附近、另一个在右下角附近，或左下+右上）。网格四条边的中点位置各有一个单像素颜色指示符：上边=黄(4)，右边=橙(7)，下边=灰(5)，左边=栗(9)。生成约束：任意两个矩形若重叠则面积不同（不存在面积相同的重叠矩形对）；每个矩形中心到四条边的最小距离唯一（无平距）；标记像素不位于网格边缘。

**规则**：
1. 对每种标记颜色，找到该颜色的两个像素，以它们为对角顶点确定一个轴对齐矩形（含边界）。
2. 对每个矩形，计算其中心坐标（边界框的行/列中点）。计算该中心到网格上/下/左/右四条边的距离（行距或列距）。选取距离最小的边。
3. 该边中点处的颜色指示符即为该矩形的填充色。
4. 将每个矩形区域（含边界行列）内的所有像素填充为该矩形的填充色。
5. 若两个矩形区域有重叠，面积较小（像素总数较少）的矩形后绘制，覆盖先绘制的大矩形。即：按面积从大到小依次填充，小面积矩形在最上层。
6. 标记像素被矩形填充覆盖。四条边上的颜色指示符从输出中擦除（置为黑(0)）。
7. 未被任何矩形覆盖的像素保持黑(0)。

**关键洞察**：标记像素的颜色仅用于配对（确定哪两个像素定义同一矩形），与填充色无关；填充色完全由矩形在网格中的空间位置决定——这种"颜色只是 ID、位置才是信号"的分离需要对比多个示例才能识别，因为单个示例中标记色和填充色的对应关系可能恰好看起来像直接映射。

## 新题 7：清洗对角噪声后的模板印章

**组合逻辑**：[擦除erase / 补线line_completion](创新：噪声清洗作为印章的前置步骤，而非最终输出) + [印章覆盖stamp](已有) + [源色决定模板涂色source_color_determines_template_recolor](已有)

**来源原语**：
- 擦除(erase)、补线(line_completion)、对角噪声(diagonal_noise)、直线段(straight_line_segment)、间隙长度限制(gap_length_constraint) ← 7b80bb43
- 印章覆盖(stamp)、模板面板(template_panel)、前景像素(foreground_pixel)、分块对应(block_correspondence)、源色决定模板涂色(source_color_determines_template_recolor) ← b190f7f5

**依赖链**：模板面板含对角噪声→必须先清洗（擦除对角像素+补全间隙）得到真实模板→清洗后的模板才能用于印章操作→源像素颜色决定每个印章副本的涂色。清洗是印章的前提条件——不清洗则印章形状错误，清洗规则本身需从模板面板中推断。

被对角噪声污染的模板经清洗还原后，按源面板中每个前景像素的颜色涂色并印章到对应输出位置。

**输入结构**：约 15x12 的网格，黑(0)背景。上部为一个 3x3 的源面板，包含 2~4 个非背景像素，颜色取自 {红(2), 蓝(1), 绿(3), 黄(4)}，其余为黑(0)。源面板下方隔一行背景后，是一个 5x5 的模板面板，由灰(5)像素构成，但受到对角噪声污染：部分灰(5)像素偏移到了对角方向的邻近位置，原位置留下黑(0)间隙。具体地：模板中存在若干灰(5)像素仅有对角方向的灰(5)邻居而无正交方向的灰(5)邻居（即 4-邻域中无灰色），这些像素为对角噪声。同时，原本应存在灰(5)像素的位置出现了 1 像素宽的间隙。生成约束：清洗后的真实模板为一个 4-连通灰(5)图形（3~8 像素），具有明确的非对称形状；对角噪声像素数量为 1~3 个；每个间隙宽度恰好为 1 像素且位于水平或垂直灰(5)像素序列中间。

**规则**：
1. 清洗模板面板：
   a. 识别对角噪声像素：在 5x5 模板区域内，找到所有灰(5)像素，其 4-邻域（上下左右）中没有任何灰(5)像素，但 8-邻域中至少有一个灰(5)像素。将这些像素擦除为黑(0)。
   b. 补全间隙：在 5x5 模板区域内，扫描每行和每列，若某个黑(0)像素的同行/同列两侧紧邻灰(5)像素（即该像素是两个灰(5)像素之间恰好 1 像素宽的间隙），将其补为灰(5)。
   c. 若步骤 a 和 b 产生冲突（同一像素既被擦除又被补全），以补全为准。
2. 创建 15x15 输出网格（3 行 x 3 列的 5x5 块），初始化为黑(0)。
3. 对源面板中每个非背景像素 (r, c)：
   a. 复制清洗后的模板，将其中所有灰(5)像素替换为该源像素的颜色。
   b. 将涂色后的模板放入输出的第 (r, c) 个 5x5 块（块起始坐标 = (r*5, c*5)）。
4. 未被印章覆盖的输出像素保持黑(0)。

**关键洞察**：模板的真实形状是隐藏的——输入中的模板被噪声污染，求解者必须先推断清洗规则（对角孤立像素是噪声、单像素间隙需补全）才能得到正确模板；若直接使用污染模板进行印章，输出形状将与预期不符。需要对比多个示例确认噪声模式的识别标准。

## 新题 8：循环偏移对齐的分隔表重涂色

**组合逻辑**：[循环迁移cyclic_migration](创新：标记在分隔表中做行方向循环偏移，而非沿边缘条推进) + [行列对齐row_col_align](已有，但对齐关系基于偏移后的虚拟位置而非原始位置) + [重涂色recolor / 对齐标记定颜色aligned_marker_color](已有)

**来源原语**：
- 循环迁移(cyclic_migration)、逐步推进(stepwise_advance) ← 758abdf0
- 分隔线网格(separator_grid)、掩码区域(mask_region)、单像素标记(singleton_marker)、行列对齐(row_col_align)、对齐标记定颜色(aligned_marker_color) ← ef26cbf6
- 重涂色(recolor) ← 多题共用

**依赖链**：标记做循环偏移得到虚拟新位置→虚拟位置决定行/列对齐关系→对齐关系确定每个掩码区域匹配哪个标记→匹配标记的颜色决定掩码重涂色。偏移改变对齐配置，对齐决定重涂色映射——不理解偏移就无法解释看似"错位"的颜色分配。

分隔表中的标记像素经过循环行偏移后，按偏移后的位置与掩码区域做行列对齐，用匹配标记的颜色重涂掩码。

**输入结构**：约 13x13 的网格。灰(5)像素构成完整的水平和垂直分隔线，将网格分割为 3x3 共 9 个矩形单元格（每个单元格约 3x3 像素，分隔线宽 1 像素）。9 个单元格中：恰好 3 个单元格各包含一个单像素标记，颜色各不相同，取自 {蓝(1), 绿(3), 橙(7)}；恰好 3 个单元格各包含一个小掩码图案（2~4 个红(2)像素构成的 4-连通图形），形状各不相同；其余 3 个单元格为纯黑(0)背景。3 个标记分布于不同的表行且不同的表列（类似置换矩阵的排列）。3 个掩码也分布于不同的表行且不同的表列。生成约束：标记与掩码不在同一单元格；在循环偏移 1 行后，每个掩码恰好与一个标记共享同一表行或同一表列（唯一匹配）。

**规则**：
1. 识别分隔线、标记单元格和掩码单元格在 3x3 表格中的位置 (表行, 表列)。
2. 将每个标记的表行位置循环下移 1 行：表行 0→1，表行 1→2，表行 2→0。表列不变。得到每个标记的虚拟位置。
3. 对每个掩码单元格，找到虚拟位置与该掩码共享同一表行或同一表列的唯一标记（根据生成约束恰好存在一个）。
4. 将该掩码中的所有红(2)像素重涂为匹配标记的颜色。
5. 标记像素保持不变（留在原始位置）。
6. 分隔线、空单元格和背景像素保持不变。

**关键洞察**：表面上看标记与掩码的颜色分配似乎无规律——直接用标记的原始位置做行列对齐会得到错误匹配。必须发现标记存在一个隐含的循环行偏移（向下 1 行），偏移后的虚拟位置才与掩码正确对齐。这个偏移规则需要对比多个示例中标记原始位置与掩码涂色结果的关系才能归纳出来。
