## 新题 1：孔洞容量门控寻路

**组合逻辑**：[计数 counting](创新：孔洞数作为通行容量) + [寻路 pathfinding](创新：容量约束下的路径选择) + [填充 fill](创新：路径经过时填满孔洞作为"已用"标记)

**来源原语**：计数/背景孔洞/孔洞数量唯一(358ba94e), 寻路/走廊正交路径/门段(7e576d6e), 填充(7acdf6d3)

**依赖链**：孔洞计数决定每个块的通行容量 → 容量约束与空间布局共同决定唯一可行路径 → 路径经过时填充孔洞消耗容量，使同一块不可被后续路径重复使用

输入网格中散布着带孔洞的前景块，路径必须穿过孔洞数匹配的块才能连通两端标记，穿越即填洞、消耗容量。

**输入结构**：黑(0)背景，约 18x18 网格。蓝(1)前景色形成 4~6 个互不相连的实心矩形块（每个约 4x4 至 5x5），每个块内部挖去 1~3 个黑(0)孔洞像素（孔洞位于块的严格内部，不触及块边界）。网格的左边缘和右边缘各有一个红(2)标记像素。生成约束：恰好存在一条从左标记到右标记的正交路径，该路径依次穿过若干块，每穿过一个块消耗该块恰好一个孔洞；不存在第二条满足容量约束的路径。块之间的空隙至少 2 像素宽，保证路径在块外部可自由正交行走。

**规则**：
1. 识别所有蓝(1)矩形块，计数每个块内部的黑(0)孔洞像素数，记为该块的"容量"。
2. 从左边缘红(2)标记出发，沿黑(0)背景做正交行走（曼哈顿路径）。路径可以进入一个蓝(1)块，但仅当该块剩余容量 > 0 时允许通过；通过后容量减 1。
3. 路径到达右边缘红(2)标记时结束。
4. 输出时：路径经过的背景像素涂红(2)；路径穿过块时，将该块内部的一个孔洞像素涂红(2)（选择块内行号最小、行号相同则列号最小的那个孔洞）；其余像素不变。

**关键洞察**：块的内部孔洞数不只是视觉特征，而是路径的通行许可证——每个孔洞代表一次通过权，路径规划必须同时满足空间可达性和容量约束，两者缺一不可。

## 新题 2：膨胀交叠通道上的对边触发色互换

**组合逻辑**：[膨胀求交 dilate_intersect](已有) + [颜色互换 color_swap](创新：仅在膨胀通道与边缘标记选定线段的交集区域执行互换)

**来源原语**：膨胀求交/路径组件/通道/两路径间隙重叠区(f1bcbc2c), 颜色互换/标记像素/网格边缘/对边配对/配对间像素互换(d2acf2cb)

**依赖链**：两条路径的膨胀交叠定义出通道几何 → 对边黄标记选定行/列线段 → 通道几何与标记线段的交集区域才执行颜色互换；通道外的标记线段不互换，标记线段外的通道也不互换

输入中两条橙色路径的一像素膨胀交叠产生中间通道，但只有通道中被对边黄标记选中的那些像素才执行黑-青/品红-橙色互换。

**输入结构**：黑(0)背景，约 15x15 网格。橙(7)前景色形成两条 4-连通的单像素宽路径组件，两条路径大致平行但不接触，间距 2~3 像素，路径之间的间隙中散布着少量黑(0)、青(8)、品红(6)像素。网格的上下边缘（或左右边缘）各有 2~3 个黄(4)标记像素，形成对边配对——每对黄标记处于同一行（若上下对边）或同一列（若左右对边），标记之间的严格内部像素构成"选定线段"。生成约束：至少有一条选定线段穿过两路径之间的间隙区域，且至少有一条选定线段完全不经过间隙区域。

**规则**：
1. 将两条橙(7)路径各自在 8-邻域膨胀 1 像素，取两个膨胀结果的交集，得到中间通道（不包含橙(7)路径自身的像素）。
2. 识别所有黄(4)对边标记对。每对标记选定一条直线段（行段或列段），线段的严格内部像素（不含两端黄像素）构成"选定区域"。
3. 计算通道与所有选定区域的交集。仅对交集中的像素执行颜色互换：黑(0) <-> 青(8)，品红(6) <-> 橙(7)。
4. 黄(4)标记像素保持不变。通道中不在选定区域内的像素保持不变。选定区域中不在通道内的像素保持不变。所有其他像素保持不变。

**关键洞察**：颜色互换的空间范围不由单一规则决定——它是两个独立几何构造（路径膨胀交叠产生的通道、边缘标记选定的线段）的交集，求解者必须同时推断这两层结构才能确定哪些像素变化。

## 新题 3：旋转翻转不变的形状频次决定宏块激活压缩图

**组合逻辑**：[排序/形状频次分组 sorting+shape_frequency_grouping](创新：频次不再决定平移方向，而是决定宏块激活状态) + [压缩 compress](创新：激活状态压缩为小网格) + [计数 counting](辅助：频次计算)

**来源原语**：排序/形状频次分组/旋转翻转不变/共享与唯一形状(62593bfd), 压缩/宏块格阵/粗粒度块/含标记涂标记色(e57337a4), 计数(58490d8a)

**依赖链**：提取每个宏块内的精灵体形状 → 在旋转/翻转等价下分组 → 频次 ≥ 2 的组对应的宏块被"激活" → 将激活状态压缩为小网格输出

将大网格中每个宏块的精灵体按旋转翻转等价归组，拥有"共享形状"（频次 ≥ 2）的宏块被激活，最终输出激活状态的压缩图。

**输入结构**：黑(0)背景，约 18x18 网格，高度和宽度各可被 3 整除（6x6 宏块阵列，每个宏块 3x3）。每个宏块内部包含一个由蓝(1)像素组成的 4-连通小图形（2~5 像素），形状各异（不规则，无固定名称）。共有 36 个宏块，其中若干对宏块的蓝色图形在旋转和/或翻转下等价（即属于同一标准形）。生成约束：至少存在 2 组"共享形状"（频次 ≥ 2），且至少存在 3 个"唯一形状"（频次 = 1）；不同组的标准形互不相同。

**规则**：
1. 将网格划分为 6x6 的宏块阵列（每块 3x3）。提取每个宏块中蓝(1)像素的相对位置，得到该块的精灵体形状。
2. 对每个精灵体，计算其在 4 种旋转 x 2 种翻转（共 8 种变换）下的所有等价形式，取字典序最小者作为标准形。
3. 统计每种标准形出现的次数。将频次 ≥ 2 的标准形对应的所有宏块标记为"激活"，频次 = 1 的标记为"未激活"。
4. 输出 6x6 网格：激活的宏块对应像素涂红(2)，未激活的对应像素涂黑(0)。

**关键洞察**：压缩输出的每个像素不是简单地检测宏块是否有前景——而是取决于该宏块的精灵体形状是否在整个网格中有旋转/翻转等价的"同伴"，需要全局比较才能判定激活状态。

## 新题 4：枢轴旋转后沿新方向延续周期图案

**组合逻辑**：[旋转 rotate](已有：绕枢轴四分之一转) + [平铺/周期延续 tile](创新：旋转改变了延续方向，周期图案必须在新方向上正确衔接)

**来源原语**：旋转/枢轴标记/绕点旋转/顺时针四分之一圈(c074846d), 平铺/周期图案/周期/宽度加倍延续周期(963e52fc)

**依赖链**：识别线段内部的周期图案 → 绕枢轴顺时针旋转 90° 得到新方向 → 沿新方向继续延续同一周期直至网格边界；旋转改变了图案的空间朝向，周期的"下一个单元"必须基于旋转后的坐标系计算

一条带有内部周期颜色图案的线段绕灰标记旋转 90 度后，沿新方向继续延续同一周期直到碰壁，同时原位置线段变绿。

**输入结构**：黑(0)背景，约 15x15 网格。一个灰(5)像素作为枢轴标记。一条从枢轴出发、沿水平或垂直方向延伸的线段（长度 4~8 像素），线段上的像素交替使用红(2)和蓝(1)两种颜色，形成周期为 2 的图案（即红蓝红蓝...或蓝红蓝红...），紧邻枢轴的第一个像素的颜色记为 C1。生成约束：顺时针旋转 90° 后的新方向上，从枢轴到网格边界的距离 ≥ 原线段长度 + 3，确保延续有足够空间。原线段方向上枢轴位于一端（线段从枢轴向一个方向延伸）。

**规则**：
1. 找到灰(5)枢轴和与之相邻的非黑非灰线段像素，确定线段方向（枢轴→线段末端的方向向量）。
2. 记录线段的周期颜色序列（从紧邻枢轴的像素开始：C1, C2, C1, C2, ...）和线段长度 L。
3. 将原线段的所有像素重涂为绿(3)（标记旧位置）。
4. 将方向向量顺时针旋转 90°，得到新方向。从枢轴沿新方向绘制新线段：前 L 个像素重复原周期（第 1 个像素=C1，第 2 个=C2，...），然后继续延续同一周期直到下一个像素超出网格边界为止。
5. 灰(5)枢轴像素保持不变。

**关键洞察**：旋转不只是改变了一根线段的位置——它改变了周期图案的延续方向，而延续长度取决于旋转后新方向上的可用空间，这是旋转前无法预知的。原线段的周期信息必须被"读取"后才能在新方向上正确续写。

## 新题 5：图例框计数编码组装蓝图

**组合逻辑**：[计数 counting](已有：统计外部对象数) + [填充图例 populate_legend](创新：图例不仅记录计数，其点序列同时编码组装蓝图的列宽) + [拼图组装 jigsaw_assemble](创新：组装的列分配由图例编码决定)

**来源原语**：计数/图例框/颜色索引行/计数映射点序列(58490d8a), 拼图组装/碎片/镜像对称(e8686506), 面积匹配(7acdf6d3)

**依赖链**：统计每种颜色的碎片数 → 图例中填入点序列 → 点序列的长度等于该颜色在输出矩形中占据的列数 → 按图例行顺序（从上到下）排列各色列带 → 将碎片组装进对应颜色的列带中

散落的多色碎片需被组装进一个矩形，而每种颜色分配到多少列由图例框的计数点序列决定——点数越多，列带越宽。

**输入结构**：黑(0)背景，约 20x20 网格。左侧有一个灰(5)边框的矩形图例框（约 4 行 x 10 列），图例框最左列的非黑像素分别为红(2)、蓝(1)、绿(3)（从上到下，共 3 种键色），其余位置为黑(0)。图例框外部散布着若干 4-连通的小碎片（每个碎片 2~5 像素），每个碎片单色，颜色为三种键色之一。每种颜色的碎片数量互不相同，范围 2~5。生成约束：所有碎片的总像素数 = 输出矩形的面积（输出矩形高度 = 碎片中最大的高度跨度，宽度 = 各颜色碎片数之和）；每种颜色的碎片总像素面积恰好能无间隙无重叠地填满对应宽度的列带。

**规则**：
1. 识别图例框中的 3 种键色及其从上到下的顺序。
2. 对每种键色，统计图例框外部属于该颜色的独立碎片数目 N_c。在图例框中该键色所在行，从键色像素右侧每隔一个像素绘制一个该键色的点，共 N_c 个点（即位置为键色列+2, +4, ..., +2*N_c）。
3. 确定输出矩形：高度 H = 所有碎片中边界框高度的最大值，宽度 W = N_red + N_blue + N_green。按图例从上到下的键色顺序，输出矩形从左到右依次分配 N_c 列给每种颜色。
4. 将每种颜色的碎片按边界框左上角的行优先顺序（行号小优先，行号相同则列号小优先）依次放入该颜色的列带中，紧贴列带顶部，从左到右排列，碎片间无间隙。
5. 输出仅包含组装完成的矩形（裁剪输出），不包含图例框。

**关键洞察**：图例框同时扮演两个角色——计数显示器和组装蓝图。碎片数量不只是统计结果，它直接决定了输出矩形中对应颜色的列宽度，使得计数逻辑和空间组装逻辑通过图例这个中介紧密耦合。

## 新题 6：异常值矫正后的双轴对称恢复

**组合逻辑**：[异常值提取/检测 outlier_extraction+detection](创新：异常值不是被裁剪输出，而是被就地矫正) + [对称补全 symmetry_completion](创新：必须先矫正异常才能正确执行对称恢复)

**来源原语**：异常值提取/孔洞数量唯一/前景块/背景孔洞(358ba94e), 对称补全/实心标记矩形/双轴镜像对称/遮挡由镜像恢复(67b4a34d)

**依赖链**：网格具有双轴对称性，但被两种干扰破坏：(a) 一个实心标记矩形遮挡了部分区域，(b) 一对应当对称的块被篡改为异常图案 → 必须先通过对比其他对称位的块来检测异常 → 矫正异常块为正确内容 → 再利用已矫正的对称性恢复标记矩形下的隐藏内容 → 输出整个矫正并恢复后的网格

网格本应双轴对称，但一个块被篡改、另一区域被遮挡；需先识别并修复篡改块，再利用恢复的对称性补全遮挡区。

**输入结构**：黑(0)背景，约 15x15 网格（奇数边长，确保对称轴穿过中心行/列）。网格整体用红(2)、蓝(1)、绿(3)像素构成一个关于水平轴和垂直轴都对称的图案（双轴对称），但有两处破坏：(a) 一个品红(6)实心矩形（约 3x3 至 4x4）遮挡了部分区域（品红仅出现在此矩形中）；(b) 在远离品红矩形的位置，一个约 3x3 的区域被篡改——其内容与其三个对称镜像位置的内容不一致（篡改后使用的颜色仍为红/蓝/绿，但图案不同）。生成约束：品红矩形不跨越对称轴；篡改区域与品红矩形不重叠且不处于彼此的对称位；篡改区域的三个对称镜像位置内容一致（仅篡改区域本身不同），使异常可唯一检测。

**规则**：
1. 找到品红(6)实心矩形的位置和尺寸，记录其覆盖的像素坐标集合 M。
2. 对网格中所有不在 M 中的像素，检查其关于水平轴和垂直轴的三个镜像位置（也排除 M 中的位置）。如果某个像素 p 与其可见镜像位置的像素值不一致，则 p 属于"疑似异常区域"。
3. 将所有疑似异常像素聚类为 4-连通分量。对每个分量中的每个像素，取其镜像位置中出现最多的颜色值（多数表决，三个镜像位置中至少两个一致）作为正确值，将该像素矫正为正确值。
4. 矫正完成后，对 M 中的每个品红像素，查找其关于水平轴和/或垂直轴的镜像位置（此时所有非 M 像素均已正确），复制镜像值替换品红像素。若某品红像素的镜像位置也在 M 中，则使用 180° 旋转对称位置的值。
5. 输出整个矫正并恢复后的网格（与输入同尺寸）。

**关键洞察**：两种破坏互相干扰——如果不先修复篡改块，就无法确定对称模板是什么；而篡改块本身又需要通过对称性来检测。求解者必须意识到三个镜像中的"多数表决"可以在遮挡存在的情况下同时定位异常和确定正确值，两步逻辑本质上是同一个对称推理的两面。

## 新题 7：对边标记指定对称轴后压缩图的对称化

**组合逻辑**：[压缩 compress](已有：宏块存在性检测) + [对称补全 symmetry_completion](创新：对称轴不是从图案本身推断，而是由外部边缘标记指定) + [标记像素/对边配对](创新：边缘标记不直接操作像素，而是指定压缩图的对称约束)

**来源原语**：压缩/宏块格阵/粗粒度块/含标记涂标记色(e57337a4), 对称补全/双轴镜像对称(67b4a34d), 标记像素/网格边缘/对边配对(d2acf2cb)

**依赖链**：将大网格压缩为 NxN 存在性图 → 边缘黄标记指定压缩图的对称轴方向 → 对压缩图执行对称化（不对称的位置取"激活"的并集） → 输出对称化后的压缩图

大网格先被压缩为宏块存在性小图，再根据对边黄标记决定对称轴方向，将小图强制对称化输出。

**输入结构**：黑(0)背景，约 20x20 网格，高度和宽度各可被 4 整除（形成 4x4 宏块阵列，每个宏块 5x5）。部分宏块内含有散布的红(2)标记像素（1~3 个，位置不固定），其余宏块全为黑(0)。网格的一对对边（上下或左右）的中央位置各有一个黄(4)像素。生成约束：含红标记的宏块分布不关于黄标记指定的轴对称（否则对称化无效果），但关于另一条轴可能对称也可能不对称。黄标记恰好出现在对边的中心位置，明确指示对称轴方向（上下对边 → 水平对称轴；左右对边 → 垂直对称轴）。

**规则**：
1. 将网格划分为 4x4 的宏块阵列（每块 5x5）。对每个宏块，检测其中是否包含至少一个红(2)像素，是则记为"激活"(1)，否则记为"未激活"(0)，得到 4x4 压缩图。
2. 识别黄(4)标记像素位于哪对对边。若位于上下边缘，对称轴为水平中轴（压缩图的第 1 行与第 4 行镜像，第 2 行与第 3 行镜像）；若位于左右边缘，对称轴为垂直中轴（压缩图的第 1 列与第 4 列镜像，第 2 列与第 3 列镜像）。
3. 对压缩图执行对称化：对于每对镜像位置 (a, b)，若 a 或 b 至少一个为"激活"，则将两者都设为"激活"（取并集）。
4. 输出 4x4 网格：激活位置涂红(2)，未激活位置涂黑(0)。

**关键洞察**：对称轴不是从压缩图的内容中推断的（压缩图本身不对称），而是由外部的边缘标记显式指定的。求解者必须先完成压缩以理解"什么被操作"，再利用标记理解"怎么操作"，两层信息来自不同的视觉元素。

## 新题 8：排序决定路站后的交替着色连线

**组合逻辑**：[排序 sorting](创新：排序结果决定哪些对象成为路径节点、哪些被擦除) + [连线 draw_path](创新：路径沿排序后的节点序列绘制) + [擦除 erase](已有) + [交替着色 alternating_coloring](创新：路径段之间的颜色交替由节点间距奇偶性决定)

**来源原语**：排序/沿轴排列/奇偶交替选择/忽略干扰项(817e6c09), 连线/走廊正交路径(7e576d6e), 擦除(7acdf6d3), 交替着色(a6f40cea)

**依赖链**：将小方块按水平位置排序 → 奇数排名的方块保留为路站，偶数排名的擦除为干扰项 → 在相邻路站间绘制正交路径 → 每段路径的颜色在红蓝间交替，但交替的起始相位由前一段路径的最后像素颜色决定

按水平位置排序后，奇数位的小方块成为路站、偶数位的被擦除，相邻路站间绘制红蓝交替着色的正交路径。

**输入结构**：黑(0)背景，约 16x16 网格。5~7 个绿(3)的 2x2 小方块散布在网格中，各方块左边缘的列号互不相同。网格上下边缘分别有一个灰(5)标记像素，分别位于最左和最右方块的正上方和正下方附近（灰标记标识路径的起点和终点）。生成约束：方块之间水平间距 ≥ 3 像素，确保路径空间充足；方块数量为奇数（保证排序后末位是奇数排名，即保留）。

**规则**：
1. 找出所有绿(3) 2x2 方块，按左边缘列号从左到右排序，排名从 1 开始。
2. 奇数排名（1, 3, 5, ...）的方块保留，偶数排名（2, 4, 6, ...）的方块擦除为黑(0)。
3. 从上方灰(5)标记出发，依次连接每个保留方块的中心（按从左到右顺序），最后连接到下方灰(5)标记。连接方式：先垂直移动到目标行，再水平移动到目标列（先纵后横的曼哈顿路径）。
4. 路径着色：第一段（灰标记到第一个路站）涂红(2)。此后每段路径的起始颜色与前一段路径的末尾颜色不同——若前段末尾为红(2)则本段起始为蓝(1)，反之亦然。每段路径内部每走 2 个像素切换一次颜色（即每 2 像素一组交替着色）。
5. 灰(5)标记像素和保留的绿(3)方块保持不变。路径像素覆盖在黑(0)背景上。

**关键洞察**：排序不只是一个预处理步骤——它同时决定了三件事：哪些对象存活、路径的几何形状、以及路径各段交替着色的相位。删除排序步骤，路站选择、路径拓扑和颜色相位全部无法确定。

## 新题 9：位置顺序编码旋转角的稠密化精灵体装框

**组合逻辑**：[稠密化 densify](已有：稀疏精灵体转实心) + [旋转 rotate](创新：旋转角度由精灵体的位置顺序编码) + [填入 insert](创新：旋转后的精灵体按顺序等距放入框内)

**来源原语**：稠密化/加厚/稀疏精灵体/稀疏边框/位置顺序/等距排列入框(db615bd4), 旋转/绕点旋转/顺时针四分之一圈(c074846d)

**依赖链**：识别外部稀疏精灵体并按位置排序 → 位置序号 mod 4 决定旋转角度（0°/90°/180°/270°） → 稠密化精灵体 → 将稠密化并旋转后的结果等距装入框内

框外的稀疏精灵体先按出现位置排序，序号决定各自的旋转角度，稠密化后按序装入框中。

**输入结构**：黑(0)背景，约 20x20 网格。一个由橙(7)像素构成的大稀疏矩形边框（边框像素在每条边上每隔一个像素出现一次，形成虚线式边框，整体围成约 12x14 的矩形区域）。框外散布着 4 个单色稀疏精灵体，每个精灵体使用不同颜色（红(2)、蓝(1)、绿(3)、黄(4)各一个），每个精灵体的像素也位于 2-步格点上（即相邻像素间距为 2）。4 个精灵体稠密化后的尺寸均为 3x3 以内。框是竖长型（高度 > 宽度）。生成约束：4 个精灵体的中心位置互不在同一行且互不在同一列，保证位置排序无歧义。

**规则**：
1. 识别橙(7)稀疏边框，确定其内部矩形区域。将边框稠密化为实心 1 像素边框（即在原稀疏边框的空隙处补上橙(7)像素）。
2. 识别框外的 4 个稀疏精灵体。对每个精灵体，将其 2-步格点像素填充为连续实心块（每个稀疏像素扩展为覆盖其与相邻格点之间所有空隙的区域），得到稠密形态。
3. 按精灵体中心位置从上到下排序（框是竖长型），排名从 0 开始。中心位置 = 精灵体所有像素行坐标的中位数。
4. 将排名为 k 的精灵体顺时针旋转 (k mod 4) x 90°（即排名 0 不旋转，排名 1 旋转 90°，排名 2 旋转 180°，排名 3 旋转 270°）。
5. 清除框内区域为黑(0)，然后将 4 个旋转后的稠密精灵体从上到下等距放入框内（精灵体之间的垂直间隙相等，且顶部/底部与框边的间隙也与精灵体间隙相等）。水平方向居中放置。精灵体保持各自原色。
6. 清除框外所有稀疏精灵体像素为黑(0)。

**关键洞察**：精灵体在输入中的空间位置不只是布局信息——它编码了旋转指令。位置靠上的精灵体不旋转，依次递增 90 度。求解者必须同时推断位置→旋转的编码规则和稠密化→装框的空间规则，两者缺一不可。

## 新题 10：对称恢复揭示隐藏的周期瓦片

**组合逻辑**：[对称补全 symmetry_completion](已有：镜像恢复遮挡区) + [裁剪 crop](已有) + [周期检测/平铺 tile](创新：完整网格暗含一个最小周期瓦片，需恢复遮挡后才可检测)

**来源原语**：对称补全/实心标记矩形/双轴镜像对称/遮挡由镜像恢复(67b4a34d), 裁剪(358ba94e), 平铺/周期图案/周期(963e52fc)

**依赖链**：网格具有周期性但被实心标记矩形遮挡 → 遮挡打断了周期，直接检测会得到错误周期或检测失败 → 利用网格同时具有的镜像对称性恢复遮挡区 → 恢复后检测最小水平周期 → 裁剪出一个完整周期瓦片作为输出

网格同时具有左右对称性和水平周期性，但遮挡矩形打断了两者；先用对称性恢复遮挡，再提取最小周期瓦片。

**输入结构**：黑(0)背景，约 16x12 网格（宽度 > 高度）。网格内用红(2)、蓝(1)、绿(3)像素构成一个图案，该图案同时满足：(a) 关于垂直中轴左右镜像对称；(b) 具有水平周期 P（P 整除宽度的一半，P 的范围为 3~5）。一个品红(6)实心矩形（约 3x4）遮挡了网格中的一块区域。生成约束：品红矩形不跨越垂直中轴（确保其镜像位置完全可见）；品红矩形的宽度 < P（确保它不会完整覆盖一个周期）；网格中品红仅出现在该遮挡矩形中。

**规则**：
1. 找到品红(6)实心矩形，记录其覆盖的像素坐标集合 M。
2. 对 M 中的每个像素 (r, c)，计算其关于垂直中轴的镜像位置 (r, W-1-c)（W 为网格宽度）。将镜像位置的颜色值复制到 (r, c)，替换品红。
3. 恢复后的完整网格具有水平周期性。检测最小水平周期 P：找到最小的正整数 P 使得对所有 (r, c) 有 grid[r][c] = grid[r][c+P]（在列范围内）。
4. 从网格左上角裁剪出高度 = 网格高度、宽度 = P 的矩形作为输出。

**关键洞察**：周期性和对称性是同一个图案的两种结构属性，但遮挡同时破坏了两者。对称性可以独立于周期性来恢复遮挡（只需镜像），而周期性只有在遮挡恢复后才能被正确检测。求解者需要识别出应当先用哪种结构属性修复、再用哪种提取答案。
