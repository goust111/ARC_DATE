## 新题 1：平移封区着色

**组合逻辑**：[平移/translate](原有) + [洪泛填充/flood_fill](原有) + [重涂色/recolor](创新：填充色由封闭区域边界上的平移对象颜色决定)

**来源原语**：平移、按自身宽度平移（64a7c07e）；洪泛填充、区域封闭、孤立背景区域填充（a5313dff）；重涂色（多源）

**依赖链**：每个对象的边界框宽度决定其平移距离 → 平移后的新位置与已有墙壁共同构成壁障 → 壁障拓扑决定哪些背景区域被封闭 → 每个封闭区域的填充色取决于其边界上哪个平移后对象提供了最多相邻壁障像素

一句话总结：将各色对象按自身宽度右移，移后对象与红墙共同围出封闭区域，按边界贡献最多的对象颜色填充这些区域。

**输入结构**：约 14x14 网格，黑(0)背景。红(2)像素构成若干水平和竖直的一像素宽墙壁线段，分布于网格中部形成不完全的栅栏结构（墙壁之间存在缺口，各缺口宽 2~5 像素）。另有 3~5 个单色 4-连通小对象（3~6 像素，每个对象颜色互不相同，使用蓝(1)、绿(3)、黄(4)、品红(6)等），散布于网格左半区。每个对象的边界框宽度恰好等于它到其右侧最近红墙缺口的水平距离，使得右移后对象恰好堵住该缺口。生成约束：各对象的移动路径互不重叠，每个对象移动后不会超出网格边界；移动后恰好有 2~4 个背景区域变为封闭；每个封闭区域的边界上仅有一个平移后对象提供相邻像素（不存在多对象共享边界的歧义情况）。

**规则**：
1. 找到所有非红、非黑的 4-连通前景对象，计算每个对象边界框的宽度 w。
2. 将每个对象整体向右平移 w 个像素，原位置变为背景黑(0)。
3. 以红(2)墙壁 + 平移后的各色对象像素共同作为壁障。从网格四条边界出发，用 4-连通洪泛标记所有可达背景像素。
4. 所有未被标记的背景像素即为封闭区域。对每个封闭区域，检查其 4-邻域边界上的非红壁障像素属于哪个平移后对象，将该区域所有像素填充为该对象的颜色。
5. 红墙壁保持不变，平移后的对象保持不变。

**关键洞察**：对象的宽度既是平移距离又是"钥匙尺寸"——只有宽度恰好等于缺口宽度的对象才能封住缺口，产生新的封闭区域；宽度不匹配的对象虽然移动了，但不会封闭任何区域。

## 新题 2：断线补全与封闭来源着色

**组合逻辑**：[补全/completion](原有) + [洪泛填充/flood_fill](原有) + [重涂色/recolor](创新：填充色由封闭区域是否依赖补全像素才封闭决定)

**来源原语**：补全、相邻像素标有效线、缺口补另色（4612dd53）；洪泛填充、区域封闭、孤立背景区域填充（a5313dff）；重涂色（多源）

**依赖链**：相邻像素对判定有效线 → 有效线上的缺口被补全 → 补全后网格线构成壁障 → 壁障拓扑决定封闭区域 → 区域边界是否包含补全像素决定填充色

一句话总结：补全断裂的网格线后，区分"原本就封闭的区域"和"因补全才封闭的区域"，分别用不同颜色填充。

**输入结构**：约 12x12 网格，黑(0)背景。蓝(1)像素构成一组不完整的直线网格（水平线和竖直线各 2~4 条）。每条有效线上至少存在一对水平相邻（对于水平线）或竖直相邻（对于竖直线）的蓝像素对，用于标识该行/列为有效线。有效线上存在若干单像素或双像素宽的缺口（黑色间断）。网格中部分区域仅由原始蓝像素就完全封闭（不经过任何缺口），其余区域需要缺口被填补后才形成封闭。生成约束：无效行/列（无相邻蓝像素对的行/列）上的孤立蓝点不影响封闭判断；补全后至少存在 1 个"原封闭"区域和 1 个"因补全封闭"区域。

**规则**：
1. 检查每一行和每一列：若该行/列在前景边界框范围内包含至少一对水平/竖直相邻的蓝(1)像素，则标记该行/列为有效线。
2. 对每条有效线，将其在前景边界框范围内所有黑(0)缺口像素填充为红(2)。保留所有原始蓝像素不变。
3. 以蓝(1) + 红(2)像素共同作为壁障，从网格边界出发 4-连通洪泛标记可达背景。
4. 对每个未标记的封闭背景区域，检查其 4-邻域边界像素中是否包含至少一个红(2)像素（即补全填充的缺口像素）：
   - 若边界上**无**红像素（完全由原始蓝像素封闭）：填充为绿(3)。
   - 若边界上**有**红像素（依赖补全才封闭）：填充为黄(4)。

**关键洞察**：同一网格中的封闭区域分为两类——被原始蓝线天然围住的区域和需要断线修补后才围住的区域。补全操作不仅创造了新封闭，还留下了红色"修补痕迹"，使两类区域在边界颜色上可区分。仅看单个示例可能误以为所有封闭区域颜色相同，必须对比多个示例才能归纳出分类条件。

## 新题 3：朝向编码旋转印章与重叠变色

**组合逻辑**：[印章覆盖/stamp_overlay](原有) + [朝向编码方向/orientation_encodes_direction](创新改造为朝向编码旋转角度) + [重涂色/recolor](创新：重叠区域变色)

**来源原语**：印章覆盖、相对坐标复制、锚点像素、控制像素（f5c89df1）；三角精灵体、朝向编码方向（409aa875）；重涂色、碰撞变色规则（409aa875）

**依赖链**：锚点相邻度选出源掩码坐标系原点 → 提取相对坐标掩码 → 每个目标处三角精灵体的缺角位置编码旋转角 → 掩码旋转后印章到目标点 → 多印章重叠的像素按碰撞规则变色

一句话总结：从锚点提取图案掩码，在每个目标处按三角朝向旋转后印章，重叠像素变为特殊颜色。

**输入结构**：约 15x15 网格，黑(0)背景。包含以下元素：
- 一组蓝(1)像素构成的源掩码（4-连通，5~8 像素，非对称形状以使旋转后图案可区分），旁边紧邻一个红(2)锚点像素。锚点像素是蓝色源掩码 4-邻域内唯一的非蓝非黑像素。
- 3~4 个绿(3)目标标记像素，彼此相距足够远（至少 6 像素间距）。
- 每个绿目标像素旁边（同行或同列，相距 1 像素）有一个灰(5)三像素 L 形三角精灵体。L 形由 3 个像素组成，占据 2x2 区域的三个格子，缺失的那个角编码旋转方向。
- 生成约束：源掩码的边界框不超过 4x4；至少有一对目标点的印章区域存在 1~3 像素的重叠；三角精灵体的四种朝向（缺左上、缺右上、缺右下、缺左下）至少出现两种不同朝向。

**规则**：
1. 找到红(2)锚点像素，提取蓝(1)源掩码中每个像素相对于锚点的坐标偏移集合 S。
2. 对每个绿(3)目标像素，找到与之相邻的灰(5) L 形三角精灵体，根据缺角位置确定旋转角度：缺左上角 = 不旋转(0)，缺右上角 = 顺时针 90，缺右下角 = 180，缺左下角 = 顺时针 270。
3. 将偏移集合 S 按该角度旋转（以原点为中心，(dr,dc) 在 90 旋转下变为 (dc,-dr)），得到旋转后的偏移集合 S'。
4. 以绿目标像素为原点，在 S' 对应的位置印章蓝(1)像素。先擦除原始源掩码、锚点和所有灰色三角精灵体，再逐个印章。绿目标像素本身保留为绿(3)。
5. 若某个像素被两个或更多印章同时覆盖，将该像素涂为黄(4)而非蓝(1)。

**关键洞察**：三角精灵体的形状不仅标记了目标位置（这在源题中已有），更编码了图案的旋转角度——一种从源题"朝向编码发射方向"到"朝向编码旋转角"的创新映射。重叠变色进一步要求求解者追踪所有旋转后印章的空间分布，而非逐个独立处理。

## 新题 4：实心内部可铺性决定涂色分支

**组合逻辑**：[重涂色/recolor](原有) + [平铺/tiling](创新：平铺作为分类判据而非覆盖操作) + [邻域全包含/full_neighborhood_inside_component](原有)

**来源原语**：重涂色、连通分量、单点标记、实心内部、邻域全包含、标记在分量内（09c534e7）；平铺、精确覆盖按形着色（626c0bcc）

**依赖链**：8-邻域全包含测试提取每个分量的实心内部 → 内部形状的 2x2 可铺性分类 → 分类结果选择涂色方案（标记色或固定替代色）

一句话总结：提取每个前景分量的实心内部，若内部能被 2x2 方块精确铺满则涂标记色，否则涂橙色。

**输入结构**：约 15x15 网格，黑(0)背景。绿(3)像素构成 3~5 个 4-连通分量，每个分量由单像素宽的走廊和较厚的实心团块（4x4 至 6x6 像素范围）组成。每个分量内部恰含一个单点标记像素（颜色各不相同，使用蓝(1)、红(2)、黄(4)、品红(6)等），标记位于团块的实心内部区域内（即标记的 8-邻域全为绿或为其自身）。各分量的团块形状不同：部分团块侵蚀 1 像素后的内部恰好为偶数行x偶数列的矩形（可被 2x2 精确铺满），其余团块的内部为奇数边长矩形或含有 L 形凹口（无法被 2x2 精确铺满）。生成约束：至少有一个分量可铺、一个不可铺；走廊部分不产生实心内部像素（宽度 <=2）；标记像素不计入铺满测试（测试对象仅为绿色内部像素）。

**规则**：
1. 对每个绿(3) 4-连通分量，找到其中所有**实心内部像素**：即 8-邻域（含自身共 9 格）全部属于该分量的绿(3)像素（标记像素视为属于该分量）。
2. 对每个分量的实心内部像素集合（排除标记像素本身），测试能否被不重叠的 2x2 方块精确覆盖（每个内部像素恰好属于一个 2x2 方块，无遗漏无重叠）。
3. 若可铺：将该分量的全部实心内部像素涂为该分量标记像素的颜色。
4. 若不可铺：将该分量的全部实心内部像素涂为橙(7)。
5. 分量的走廊像素、团块边缘像素、标记像素和背景均保持不变。

**关键洞察**：侵蚀后的内部形状是否能被 2x2 方块精确铺满，取决于该形状的连通区域是否每个维度都为偶数——这不能从团块外轮廓直接判断，因为侵蚀会改变形状的奇偶性。一个 5x5 团块的内部是 3x3（不可铺），而 6x6 的内部是 4x4（可铺），但两者外观上的差异仅一行一列。

## 新题 5：射线命中触发链式替换

**组合逻辑**：[射线延伸/projectile_fire](原有) + [重涂色/recolor](原有：链式替换规则) + [朝向编码方向/orientation_encodes_direction](原有)

**来源原语**：射线延伸、三角精灵体、朝向编码方向、碰撞变色规则（409aa875）；重涂色、双列图例、图例行序决定替换、逐行顺序链式替换（e4888269）

**依赖链**：三角朝向确定射线方向 → 射线轨迹决定命中目标 → 命中次数和先后顺序决定链式替换的执行轮数 → 图例链式替换规则决定最终颜色

一句话总结：三角精灵体发射射线命中其他对象，每次命中触发一轮图例链式颜色替换，多次命中则多轮替换叠加。

**输入结构**：约 14x14 网格，黑(0)背景。包含：
- 4~6 个三像素 L 形精灵体，每个由 3 个像素占据 2x2 区域中的三格，颜色各不相同（使用蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)中的若干种）。各精灵体彼此间保持足够距离（至少 3 格间距），沿行或列大致对齐，使射线可命中。
- 一个 2 列 N 行的竖直双列图例，位于网格右下角，以灰(5)像素为边框包围。图例每行左列为源色、右列为目标色，共 3~4 行。图例不参与射线交互。
- 生成约束：至少有一个精灵体被恰好一条射线命中，另一个被恰好两条射线命中（以验证多轮替换效果）；图例中至少存在一组链式映射（如蓝→红出现在红→绿之前，使得蓝经一轮变红、经两轮变绿）；图例本身不在任何射线路径上。

**规则**：
1. 对每个 L 形精灵体，确定其缺角方向，据此得到发射方向（朝缺角的对角方向发射——即偏离实体部分的方向）。射线从精灵体的顶点像素出发，沿发射方向逐格延伸，直到碰到另一个精灵体的任意像素或到达网格边界为止。射线路径上的像素不改变颜色（射线不可见）。
2. 记录每个精灵体被命中的次数 k 和命中它的各条射线的来源距离（从射手顶点到被命中精灵体的曼哈顿距离）。
3. 对每个被命中的精灵体，按来源距离从近到远的顺序依次执行 k 轮链式替换。每轮替换：取精灵体当前颜色 c，从图例第一行到最后一行扫描——每当 c 等于该行左列颜色时，将 c 更新为右列颜色，继续向下扫描后续行（一轮内可多次更新）。一轮结束后 c 即为该轮替换的结果，作为下一轮的输入。
4. 将被命中精灵体的所有 3 个像素涂为最终颜色。未被命中的精灵体保持原色。图例保持不变。

**关键洞察**：命中次数不同导致链式替换执行不同轮数，同一初始颜色经一轮和两轮替换可到达不同的最终颜色。求解者必须同时推断射线方向规则、命中判定，以及图例的链式（而非单步）替换语义，三者缺一不可。

## 新题 6：图例选型缩放印章入异尺寸框

**组合逻辑**：[缩放/scaling](原有) + [印章覆盖/stamp_overlay](原有) + [重涂色/recolor](创新：框色而非控制色决定墨色)

**来源原语**：缩放、指示区域、对齐匹配、指示色定缩放对位（57aa92db）；图例模板、插槽阵列、控制像素、颜色映射模板、控制色查找图例（c64f1187）；空心矩形、尺寸匹配（f21745ec）；重涂色（多源）

**依赖链**：控制像素颜色在图例中查找模板图案 → 框的内腔尺寸与模板尺寸之比决定缩放倍数 → 缩放后的模板居中印入框内 → 印章墨色取框的边框色而非控制色

一句话总结：在每个矩形框内按控制像素查图例选模板，按框尺寸缩放后居中印章，墨色随框色变化。

**输入结构**：约 16x16 网格，黑(0)背景。包含：
- 网格左上角一个图例区：2~3 个彩色标记像素（如蓝(1)、红(2)、绿(3)），每个标记右下方紧邻一个 2x2 灰(5)模板图案（模板内的灰像素表示"有墨"位置，黑像素表示"无墨"位置；不同标记对应不同的 2x2 二值模式）。
- 网格其余区域散布 3~4 个一像素宽空心矩形框，每个框颜色不同（使用黄(4)、品红(6)、橙(7)、青(8)等），框的内腔宽高均为偶数（4x4、6x6 或 4x6 等），各框互不重叠。
- 每个框的内腔中恰好有一个控制像素，其颜色为图例中某个标记色（蓝、红或绿）。控制像素在内腔中的位置随意。
- 生成约束：所有内腔尺寸均为 2 的整数倍，保证缩放倍数为整数；不同框可以选中同一图例模板但因框尺寸不同而产生不同缩放结果。

**规则**：
1. 读取图例：每个彩色标记像素与其右下方的 2x2 灰色模板构成一条映射记录"标记色 → 2x2 二值模式"。
2. 对每个空心矩形框，读取其内腔中控制像素的颜色，在图例中查找对应的 2x2 模板。
3. 计算缩放倍数：水平倍数 = 内腔宽度 / 2，竖直倍数 = 内腔高度 / 2。将 2x2 模板按此倍数整数缩放（每个模板像素扩展为 水平倍数 x 竖直倍数 的矩形块）。
4. 将缩放后的模板居中放入内腔（缩放后模板恰好填满整个内腔）。模板中"有墨"位置涂为该框的**边框颜色**（而非控制像素的颜色），"无墨"位置保持黑(0)。
5. 擦除控制像素（变为黑(0)）。图例和框边框保持不变。

**关键洞察**：控制像素和框的边框色承担不同角色——控制色选择"画什么图案"，边框色决定"用什么颜色画"。两者分离意味着同一图案在不同颜色的框中以不同颜色呈现，且同一框尺寸搭配不同图案产生不同结果。

## 新题 7：条纹变色篡改角标记匹配条件

**组合逻辑**：[条纹传播/stripe_propagation](原有) + [重涂色/recolor](条纹的附带效果) + [裁剪/crop](原有) → 结构为：条件修改型（条纹改变后续操作的触发条件）

**来源原语**：条纹传播、边界线段、颜色循环、条纹范围差异（221dfab4）；重涂色（221dfab4 中绿条纹对全行/列的重涂色效果）；角标记、中心对象、包围关系、标记色与对象同色（da6e95e5）；裁剪（da6e95e5）

**依赖链**：条纹从边界传播 → 绿色条纹重涂整行/列上所有非背景像素 → 某些角标记的颜色被篡改 → 篡改后重新评估"标记色与中心对象同色"条件 → 条件成立的簇的中心对象被裁剪输出

一句话总结：条纹传播改变某些角标记的颜色，使原本不自洽的标记簇变为自洽（或反之），由此选出目标簇并裁剪其中心对象。

**输入结构**：约 18x18 网格，黑(0)背景。包含：
- 3~4 个标记簇，每个簇由四个同色角标记像素（单像素，位于中心对象边界框的四角外侧各 1 格）围绕一个单色中心对象（3x3~4x4 的 4-连通小图形）。各簇的标记色和中心对象色如下精心安排：初始状态下无任何簇的标记色等于中心对象色（即初始无自洽簇）。
- 网格的一条边界上有一段黄(4)线段（2~3 像素宽），线段的列/行跨度覆盖某些簇的角标记所在列/行。
- 生成约束：条纹传播产生的绿(3)条纹行/列恰好经过某一个簇的全部四个角标记，将其颜色统一改为绿(3)；该簇的中心对象恰好也是绿(3)，因此在条纹重涂后该簇变为自洽。其余簇的角标记不在绿条纹路径上，或即使被重涂后仍与中心对象颜色不匹配。条纹传播的黄色条纹仅在边界线段列跨度内绘制，不影响簇的颜色匹配判断。

**规则**：
1. 从边界黄(4)线段出发向对侧边界传播条纹。条纹每隔 1 行/列的间距放置，颜色按黄(4)、黄(4)、绿(3)循环。黄色条纹仅在线段跨度范围内绘制像素。绿(3)色条纹将该行/列上所有非背景像素重涂为绿(3)。
2. 条纹传播完成后，对每个标记簇检查：四个角标记是否全部同色，且该色是否等于中心对象的颜色。
3. 找到唯一满足条件的自洽簇，裁剪其中心对象的边界框（保留内部背景像素），作为输出。

**关键洞察**：条纹传播并非装饰，而是通过绿色条纹的"全行/列重涂"副作用改写角标记的颜色。哪个簇被选中取决于绿条纹恰好覆盖了哪些标记——这由条纹起点位置和传播步距共同决定。求解者必须先计算条纹着陆位置，再判断颜色匹配，两步推理不可跳过。

## 新题 8：前景铺块分类驱动瓦片排序与着色

**组合逻辑**：[平铺/tiling](创新：铺块分析作为分类依据而非视觉操作) + [排序/sorting](原有) + [重排/rearrange](原有) + [重涂色/recolor](原有)

**来源原语**：平铺、小型瓦片、前景掩码、瓦片互锁拼合、精确覆盖按形着色（626c0bcc）；排序、计数、重排、瓦片、分隔线、阵列排布、前景数决定排序（dc2aa30b）；重涂色（多源）

**依赖链**：对每个瓦片内前景掩码尝试 2x2 精确覆盖 → 覆盖所需的 2x2 方块数量作为排序键 → 排序后重排瓦片阵列 → 按铺块数量区间对前景重涂色

一句话总结：将九宫格瓦片按各自前景图案的最小 2x2 铺块数排序重排，并按铺块数着色。

**输入结构**：约 11x11 网格，由两条完整黑(0)行和两条完整黑(0)列将网格分割为 3x3 共 9 个 3x3 瓦片（与 dc2aa30b 布局相同）。每个瓦片内包含若干蓝(1)前景像素和灰(5)背景像素（瓦片局部背景为灰(5)而非黑，以区分分隔线）。各瓦片的蓝像素数量不全相同（范围 2~8 像素）。所有瓦片的蓝色前景掩码均可被若干不重叠的 2x2 方块精确覆盖（每个蓝像素恰好属于一个 2x2 方块，2x2 方块的四格可以有灰像素但至少一格为蓝；实际这里简化为：2x2 方块内全蓝才算有效覆盖）。生成约束：9 个瓦片的铺块数（覆盖其蓝色前景所需的最少 2x2 全蓝方块数）互不相同，保证排序无歧义。不可被 2x2 全蓝方块精确覆盖的蓝像素视为零散像素，不计入铺块数但计入后续着色。

**规则**：
1. 对每个 3x3 瓦片，找出其蓝(1)前景掩码能放入的最大数量的不重叠 2x2 全蓝方块（贪心：从左上到右下扫描，遇到可以放置 2x2 全蓝方块的位置就放置）。记录该瓦片的铺块数 n。
2. 按铺块数 n 从小到大排序 9 个瓦片。
3. 将排序后的瓦片从底行左侧开始、逐行从左到右、从底行到顶行依次放入 3x3 阵列的槽位中（即最小铺块数的瓦片在左下角，最大的在右上角）。
4. 重排完成后，对每个瓦片的蓝(1)前景像素重涂色：
   - 铺块数 n = 0（全为零散像素，无完整 2x2 块）：涂为红(2)。
   - 铺块数 n = 1：涂为绿(3)。
   - 铺块数 n >= 2：涂为黄(4)。
5. 分隔线和灰(5)瓦片背景保持不变。

**关键洞察**：排序的键值不是简单的像素计数（那只需数数），而是需要对每个瓦片做 2x2 铺块分析——一种几何推理。两个蓝像素数相同的瓦片因形状不同，可能有不同的铺块数（如 4 个蓝像素排成一行只能铺 0 个 2x2 块，而排成田字能铺 1 个）。着色区间进一步依赖铺块分析结果，使得排序和着色通过铺块数这一中间量紧密耦合。
