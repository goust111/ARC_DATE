## 新题 1：反弹路径上的字形印章与反馈式碰撞

**组合逻辑**：[射线延伸 + 边界反射](已有) → [字形字典 + 图案印章](已有，创新：印章位置由反弹点确定，印章选择由反弹方向编码) → [碰撞停止](已有，创新：已印字形成为新障碍终止射线)

**来源原语**：射线延伸 ray_extend、边界反射 boundary_reflection（e179c5f4）；图案印章 stamp_glyph、字形字典 glyph_dictionary、编码映射 encoding_map（dfadab01）；碰撞停止 collision_stop（2c608aff）；重涂色 recolor（多题）

**依赖链**：射线的反弹轨迹决定了字形的印章位置；反弹时撞击的是左墙还是右墙决定了印哪种字形（编码映射）；已印出的字形占据网格像素后成为新的障碍物，射线若下一步会撞上已印字形则立即停止——因此字形反过来约束了射线的存活长度。三者构成反馈环：射线产生印章位置→印章改变网格→网格终止射线。

从一个起点像素出发，沿对角线反弹前行，每次撞墙时根据撞击方向查字典印出对应字形，直到射线撞上自己印出的字形为止。

**输入结构**：黑(0)背景，约 15x20 网格。网格上方（第 0 行或第 1 行）有一个字形字典区：两个并排的 3x3 小图案，分别用蓝(1)和红(2)像素绘制，它们之间用一列灰(5)像素分隔。左侧 3x3 图案代表"左墙反弹字形"，右侧代表"右墙反弹字形"。字典区下方隔一行黑(0)分隔行后是主场景区。主场景区为纯黑(0)背景，其中恰好有一个绿(3)像素作为射线起点，位于中下部某处。生成约束：起点位置保证射线至少能反弹两次再被字形阻挡；两个 3x3 字形图案互不相同且均为 4-连通的单色图案（3~6 个非零像素）。

**规则**：
1. 从绿(3)起点像素出发，沿右上对角线（每步行-1、列+1）前进，用绿(3)逐像素绘制轨迹。
2. 当下一步的列坐标超出网格右边界时，水平方向反转（改为左上对角线），标记此次为"右墙反弹"；当下一步的列坐标低于 0 时，水平方向反转（改为右上对角线），标记此次为"左墙反弹"。反弹后继续前进。若下一步的行坐标低于字典区分隔行（即将进入字典区），射线终止。
3. 每次反弹发生时，以反弹点像素为中心的 3x3 区域印上对应字形：左墙反弹印左字典图案，右墙反弹印右字典图案。印章使用该字形字典中的原始颜色（蓝(1)或红(2)）。印章仅覆盖字形图案中非零的像素位置；若印章区域部分超出网格边界，超出部分裁剪丢弃。
4. 射线在每一步前进前检测：若下一个像素位置已被非黑(0)、非绿(3)的颜色占据（即被之前印出的字形占据），则射线立即停止，不绘制该像素。
5. 射线停止后，将所有剩余黑(0)像素（不含字典区）替换为灰(5)。

**关键洞察**：射线的存活长度不由网格大小决定，而由它自己印出的字形在何时恰好挡住它的前进路线决定——这是一个自终止反馈系统，需要对比多个示例才能发现字形选择与反弹方向的编码关系。

## 新题 2：指示器延伸虚线与交叉处频率择色填充

**组合逻辑**：[延伸 + 指示像素 + 方向指示](已有) → [虚线段生成](创新：延伸的带不是实心的，而是间隔虚线) → [单像素间隙补填](已有，创新：间隙颜色由交叉处两条虚线的颜色频率比较决定)

**来源原语**：延伸 extend、指示像素 indicator_pixel、方向指示 direction_indication、画布边界 canvas_boundary（b527c5c6）；虚线段 dashed_segment、单像素间隙补填 single_gap_filled（a699fb00）；频率比较 frequency_compare（a6953f00）；重涂色 recolor（多题）

**依赖链**：每个矩形的指示像素确定延伸方向 → 延伸绘制为间隔虚线（1 像素色、1 像素黑交替）→ 不同矩形的虚线在网格上可能交叉 → 交叉点的间隙填充颜色取决于两条交叉虚线各自颜色在全局的出现频率，取较稀有者。删去虚线化步骤，就没有间隙可填；删去频率比较，交叉处颜色无法确定。

将带有指示像素的彩色矩形沿指示方向延伸为虚线至画布边缘，然后在交叉的虚线间隙处填入全局更稀有的那条虚线颜色。

**输入结构**：黑(0)背景，约 18x18 网格。散布 3~5 个单色实心小矩形（2~3 行 x 2~3 列），每个矩形的颜色互不相同，从蓝(1)、红(2)、绿(3)、黄(4)、品红(6)中取。每个矩形的边界上恰好有一个橙(7)像素作为指示像素，该橙(7)像素所在边决定延伸方向（位于顶边→向上延伸，位于右边→向右延伸，依此类推）。矩形之间互不相邻（任意两个矩形的边界框间距至少 2 行 2 列）。生成约束：至少有两个矩形的延伸方向互为垂直（一个水平延伸、一个垂直延伸），保证存在交叉。

**规则**：
1. 对每个矩形，从指示像素所在边向外延伸一条单像素宽的虚线，直到画布边缘。虚线使用该矩形的颜色，模式为：1 个矩形色像素、1 个黑(0)像素、1 个矩形色像素、1 个黑(0)像素……起始于矩形边缘外的第一个像素（色），逐像素交替。
2. 延伸线的列（水平延伸时）或行（垂直延伸时）与指示像素对齐——即虚线恰好从指示像素位置沿延伸方向射出。
3. 统计每种矩形颜色在输入网格中的总像素数（仅计矩形本体，不含指示像素和延伸线），得到各颜色的全局频率。
4. 所有虚线绘制完成后，检查每个黑(0)像素：若该像素在某条水平虚线的间隙中（即左、右邻居均为同一颜色 C1 的虚线像素）且同时在某条垂直虚线的间隙中（即上、下邻居均为同一颜色 C2 的虚线像素），则该像素为交叉间隙。
5. 交叉间隙的填充规则：比较 C1 和 C2 的全局频率，将该像素涂为频率更低（更稀有）的颜色。若频率相同，涂为行号更小（更靠上）的那条虚线的颜色。
6. 非交叉的普通虚线间隙（左右有同色邻居但上下没有，或反之）不做任何填充。
7. 指示像素保留为橙(7)不变。

**关键洞察**：单纯的虚线间隙补填规则（左右邻居同色即填）在此题中被交叉条件改写：只有同时处于两条不同虚线的交叉间隙才触发填充，且填充颜色由矩形面积（全局频率）的比较决定——需要多个示例来区分"普通间隙不填"与"交叉间隙填稀有色"两条规则。

## 新题 3：面板对侧色原型匹配重涂

**组合逻辑**：[模式匹配 + 原型 + 符号槽位](已有) ↔ [所属面板 + 对侧面板色](已有，创新：匹配槽位的重涂色不再固定为原型色，而由其所在面板的对侧面板色决定) + [夹间区域](已有，创新：夹间区域颜色由本侧面板色决定)

**来源原语**：模式匹配 pattern_match、原型 prototype、符号槽位 symbol_slot、分隔线 separator、夹间区域 between_region（d94c3b52）；所属面板 panel_membership、对侧面板色 opposite_panel_color（9b5080bb）；重涂色 recolor（多题）

**依赖链**：先识别原型图案的形状掩码 → 在两侧面板的所有槽位中匹配 → 匹配槽位的重涂色取决于它所在面板的对侧面板色（不是原型色本身）→ 同一面板内、同一行或列上、两个连续匹配槽位之间的槽位用本侧面板色重涂。匹配检测和面板归属构成同时约束：改变面板划分会改变重涂颜色，改变匹配结果会改变哪些槽位被涂。

在双面板分区的符号表中找出所有与原型形状匹配的槽位，将它们涂上对侧面板颜色，将同面板内匹配槽位之间的夹间槽位涂上本侧面板颜色。

**输入结构**：黑(0)背景，约 19x19 网格。网格被一条垂直的灰(5)分隔线（宽 1 列）从中间分为左、右两个面板。左面板底色为蓝(1)，右面板底色为红(2)。每个面板内部是一个由灰(5)单像素线分隔的 3x3 符号槽位表格（每个槽位为 3x3 像素区域）。左面板有 3 行 x 3 列共 9 个槽位，右面板也有 3 行 x 3 列共 9 个槽位。每个槽位要么为空（全为对应面板底色），要么包含一个用单色绘制的符号掩码（用绿(3)、黄(4)、品红(6)或橙(7)之一，同一面板内可有多种颜色的符号）。恰好有一个槽位中的符号用青(8)绘制，这是原型槽位——它可以出现在任一面板中。生成约束：青(8)原型的 3x3 形状掩码在两个面板中至少各有 1 个匹配（即其他颜色的符号中至少各有 1 个与原型形状相同），且至少在一个面板的某行或某列中存在两个连续匹配槽位之间夹有非匹配槽位。

**规则**：
1. 提取青(8)原型槽位的 3x3 二值形状掩码（有色像素=1，面板底色=0）。
2. 对所有非青(8)槽位，提取其 3x3 形状掩码并与原型掩码比较——形状完全相同则标记为"匹配"（不论颜色）。
3. 对每个匹配槽位，将其符号像素重涂为该槽位所在面板的**对侧面板底色**：若匹配槽位在左面板（底色蓝(1)），则将其符号色改为红(2)；若在右面板（底色红(2)），则改为蓝(1)。
4. 在每个面板内部，对每一表格行和每一表格列：若两个匹配槽位之间（沿该行/列方向）恰好夹着一个或多个非匹配槽位，则将这些夹间槽位中的所有符号像素重涂为**本侧面板底色**（左面板内夹间→蓝(1)，右面板内夹间→红(2)）。
5. 原型槽位本身保留青(8)不变。所有灰(5)分隔线和面板底色像素保持不变。

**关键洞察**：原型匹配是纯粹的形状比较（忽略颜色），但重涂结果却完全由面板归属决定——同一个形状匹配在左面板被涂红(2)、在右面板被涂蓝(1)。需要对比跨面板的多个示例才能归纳出"对侧面板色"这条隐蔽规则，而非简单地"匹配就涂原型色"。

## 新题 4：边界框过滤的重力落标与落距决定印章大小

**组合逻辑**：[包含于边界框 + 仅处理区域内标记 + 忽略干扰项](已有) → [重力下落 + 编码映射（方向）](已有，创新：方向不由图例给出，而由标记像素相对矩形中心的位置编码) → [印章覆盖 + 空心矩形](已有，创新：印章尺寸由下落距离动态决定)

**来源原语**：包含于边界框 in_bounding_box、仅处理区域内标记 markers_inside_only、忽略干扰项 ignore_distractors、印章覆盖 stamp、空心矩形 hollow_rectangle（a04b2602）；重力下落 gravity_drop、可移动像素 movable_pixel（88e364bc）；编码映射 encoding_map（dfadab01）；擦除 erase（aabf363d）

**依赖链**：边界框测试过滤有效标记 → 标记相对矩形中心的方位编码下落方向 → 标记沿该方向下落直到碰壁 → 下落经过的像素距离 d 决定在落点印出的空心矩形边长（2d+1）。删去边界框过滤，干扰标记会产生错误印章；删去方位编码，方向不可知；删去距离计算，印章尺寸不可知。

将矩形框内的有效标记按其方位下落至框壁，在落点印出边长等于落距函数的空心方框，忽略框外干扰标记。

**输入结构**：黑(0)背景，约 20x20 网格。散布 2~3 个绿(3)空心矩形框（框线宽 1 像素，内部为黑(0)，边长 7~11 像素不等）。每个绿(3)框内部有 1~2 个红(2)标记像素，分布在框内不同位置。框外也散布 2~3 个红(2)像素作为干扰项。生成约束：框内标记像素不在框的正中心行或正中心列上（保证方位判断不产生歧义）；不同框的边界框互不重叠；框内标记离框壁至少 2 像素距离（保证印章空间足够）。

**规则**：
1. 识别所有绿(3)4-连通矩形框。对每个红(2)像素，判断是否位于某个绿(3)矩形框的边界框内部（不含框线本身）——在内部则为"有效标记"，否则为"干扰标记"。
2. 擦除所有干扰标记（改为黑(0)）。
3. 对每个有效标记，计算其相对于所在绿(3)框中心的方位：若标记在中心正上方（行号小于中心行，列号等于中心列）→下落方向为上（朝顶边框线）；若在右上方（行号 < 中心行且列号 > 中心列）→下落方向为朝右上对角最近的边（取行差与列差中较小者对应的边）；以此类推八方位。简化规则：将标记到中心的行差 dr 和列差 dc 取符号，下落方向即 (sign(dr), sign(dc)) 的反方向——即标记朝远离中心的方向推向框壁。
4. 标记沿下落方向逐像素移动，直到下一步是绿(3)框线或网格边界时停止。记录移动的像素数为落距 d。将标记的原位置恢复为黑(0)，在停止位置保留红(2)。
5. 在标记停止位置为中心，绘制一个边长为 (2d+1) 的蓝(1)空心矩形框（仅绘制外框线，宽 1 像素）。若该空心矩形部分超出网格边界或与绿(3)框线重叠，超出/重叠部分裁剪丢弃（不绘制）。
6. 若两个印章矩形的像素重叠，后处理的覆盖先处理的（处理顺序：按有效标记的原始行号从小到大、行号相同时列号从小到大）。
7. 绿(3)框线和红(2)停止位置标记保持不变，不被蓝(1)印章覆盖。

**关键洞察**：印章尺寸不是常量，而是由标记在框内的初始位置到框壁的距离动态决定的——需要对比多个示例中标记位置与印章大小的对应关系才能归纳出 (2d+1) 公式。下落方向的"反中心方位"编码也需要多个不同方位的标记来验证。

## 新题 5：控制条升降序列驱动的竖向色带阶梯填充

**组合逻辑**：[控制条 + 条长决定序列 + 长度递增后递减](已有) → [竖向色带 + 循环相邻 + 空缺借邻色填充](已有，创新：填充高度不均匀，由升降序列逐带指定) → [填充](已有)

**来源原语**：控制条 control_bar、生成序列 generate_seq、长度递增后递减 length_rise_fall、条长决定序列 bar_length_seq（5d588b4d）；竖向色带 vertical_band、循环相邻 cyclic_adjacent、空缺借邻色填充 gap_borrows_neighbor（c4d1a9ae）；填充 fill（a699fb00, c4d1a9ae）

**依赖链**：控制条长度 n → 生成升降序列 1,2,...,n,...,1 → 序列的第 k 项指定第 k 个竖向色带从底部向上填充多少行间隙 → 填充颜色由色带的循环右邻色带决定。删去控制条→填充高度无法确定；删去升降序列→每带高度无差异；删去循环相邻→填充颜色无法确定。

读取控制条长度生成升降序列，以序列值控制各竖向色带的间隙填充行数，填充颜色取右邻色带的颜色。

**输入结构**：黑(0)背景，约 15x15 网格。第 0 行最左侧有一段连续的橙(7)水平控制条（长度 n，2 <= n <= 5），其余第 0 行为黑(0)。第 1 行至最后一行构成主区域。主区域中有 (2n-1) 个竖向色带，每个色带宽 1 列，色带之间用 1 列黑(0)间隔分开（即色带占奇数列或偶数列，间隔占另一组列）。色带从左到右使用不同颜色，颜色从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、品红(6)中依次取用，若超过 6 带则颜色循环复用。每个色带内部，部分行是该色带的颜色，部分行是黑(0)间隙——间隙散布在色带中上部区域，下部连续区域为色带原色。生成约束：每个色带内的间隙行数至少为 n（保证升降序列的最大值填充需求可被满足）；色带条数恰好为 (2n-1)。

**规则**：
1. 读取第 0 行橙(7)控制条长度 n。
2. 生成升降序列 S = [1, 2, ..., n-1, n, n-1, ..., 2, 1]，共 (2n-1) 项。
3. 将主区域中的竖向色带从左到右编号为 k=1, 2, ..., 2n-1。
4. 对第 k 个色带，从该色带最底部的间隙行开始向上数 S[k] 个间隙行，将这些间隙行中该色带列的黑(0)像素填充为第 (k mod (2n-1))+1 个色带的颜色（即右邻色带的颜色，最右色带的右邻为最左色带，循环）。
5. 若色带内的间隙行总数少于 S[k]，则该色带的所有间隙行全部填充。
6. 控制条所在行（第 0 行）保持不变。色带中非间隙的原色像素保持不变。色带间的黑(0)间隔列保持不变。

**关键洞察**：控制条长度同时决定了两件事——色带的数量（2n-1）和每带的填充行数曲线（升降序列形状）。在中间色带填充最多、两侧最少，形成一个"阶梯金字塔"效果。需要对比不同 n 值的示例才能归纳出序列生成规则与循环借色规则的共同作用。

## 新题 6：对称补全计数驱动的角落裁剪选择

**组合逻辑**：[对称补全 + 凸起 + 缺口 + 对侧互补](已有) → [计数聚合](创新：统计每侧补全数量) → [裁剪 + 角落区域](已有，创新：由补全最多的侧面决定裁剪哪个角) + [频率比较](已有，作为平局仲裁)

**来源原语**：对称补全 symmetric_complete、凸起 tab、缺口 notch、对侧互补 opposite_side_complement、跨行列投射 cross_span_projection（8dab14c2）；裁剪 crop、角落区域 corner_region、频率比较 frequency_compare、重复色或稀有色 repeat_or_rare（a6953f00）

**依赖链**：先执行对称补全（产生新像素）→ 统计四侧各产生了多少个补全像素 → 补全最多的侧面决定裁剪方向 → 平局时用角落色频率仲裁。删去对称补全→没有计数依据；删去计数→不知裁剪哪个角；删去频率仲裁→平局时无法决定。

先完成矩形体的凸缺口对称补全，然后统计各边补全数量，以最多补全边所指角落裁剪出输出子网格。

**输入结构**：黑(0)背景，约 15x15 网格。中央有一个大型单色（蓝(1)）的厚实直角多面体（约占网格面积的 40~60%），形状大致为矩形但四边有若干 1 像素的凸起(tab)和缺口(notch)。凸起是从主体边缘向外伸出的 1 像素突起（仅 1 个 4-邻居属于主体）；缺口是主体边缘向内凹陷的 1 像素缺失（有 3 个 4-邻居属于主体）。四个角落各有一个 3x3 的小色块：左上角 3x3 为红(2)，右上角 3x3 为绿(3)，左下角 3x3 为黄(4)，右下角 3x3 为品红(6)。生成约束：四侧的 tab/notch 数量不全相同，以保证存在唯一最多侧（或至多两侧并列需要仲裁）；中央主体与四角色块不接触（间距至少 1 像素）。

**规则**：
1. 对中央蓝(1)主体执行对称补全：每个凸起(tab)沿其所在行或列投射到主体的对侧边缘，在对侧外部添加 1 个蓝(1)像素（镜像凸起）；每个缺口(notch)沿其所在行或列投射到对侧边缘外部位置，删除该位置的蓝(1)像素（镜像缺口）。若一个缺口紧邻某凸起（与该凸起 4-相邻），则该缺口属于凸起的局部边界形状，不作为独立源处理。
2. 统计四侧（上、下、左、右）各自产生的补全变化总数（含新增的镜像凸起和新增的镜像缺口）。
3. 选出补全变化最多的侧面。侧面与角落的映射：上侧→右上角，下侧→左下角，左侧→左上角，右侧→右下角。
4. 若两侧并列最多：取两侧共同指向的角落（如上侧和右侧并列→右上角）。若两侧指向不同角落（如上侧和下侧并列），则比较两个候选角落的 3x3 色块颜色在整个网格中的全局频率（含主体、色块所有像素），选频率更低（更稀有）的颜色所在角落。
5. 输出为选中角落的 3x3 子网格。

**关键洞察**：对称补全不仅是一个几何操作，它的副产品（各侧补全计数）成为后续裁剪决策的信号——这将一个空间变换与一个统计决策紧密绑定。需要多个示例来归纳侧面→角落的映射表以及平局仲裁的频率规则。

## 新题 7：旋转风车拼接后的边界涌现交叉着色

**组合逻辑**：[旋转 + 拼接 + 四旋转组成风车](已有) → [轨迹交叉检测](已有，创新：交叉不是来自显式轨迹，而是旋转拼接后象限边界上前景像素的碰撞涌现) → [重涂色 + 编码映射](已有，创新：交叉颜色由碰撞的旋转角度对编码)

**来源原语**：旋转 rotate、拼接 concatenate、四旋转组成风车 four_rot_pinwheel、阵列排布 array_layout（ed98d772）；轨迹交叉 trail_intersection（ac605cbb）；重涂色 recolor、编码映射 encoding_map（dfadab01）；背景色替换 background_replaced（e179c5f4）

**依赖链**：输入方块经四旋转排列为 2x2 风车 → 象限边界处不同旋转副本的前景像素可能在相邻像素位置形成碰撞对 → 碰撞对的颜色由两个相邻象限的旋转角度差决定（编码映射）。删去旋转→没有四象限；删去碰撞检测→不知哪些像素需要重涂；删去角度编码→重涂颜色不可知。

将输入精灵体排列为四旋转风车，然后在象限交界处检测前景碰撞，根据碰撞双方的旋转角度对将碰撞像素重涂为编码颜色。

**输入结构**：黑(0)背景的正方形网格，边长 n（4 <= n <= 6）。网格中有若干绿(3)前景像素构成一个不对称的 4-连通小图形（3~8 像素），占据网格的某个角落或边缘区域（保证旋转后在边界处产生碰撞）。生成约束：该图形不具有 90 度旋转对称性（保证四个旋转副本互不相同）；至少在一对相邻象限的交界处，来自两侧的前景像素存在 4-邻接关系。

**规则**：
1. 将输入 n x n 网格排列为 2x2 风车，输出尺寸 2n x 2n：左上象限放原图、右上象限放逆时针旋转 90 度、左下象限放顺时针旋转 90 度（即逆时针 270 度）、右下象限放旋转 180 度。（注意：此处象限排列方式不同于参考题 ed98d772，需从示例归纳。）
2. 拼接完成后，扫描所有象限交界线（水平中线和垂直中线）。对于交界线两侧的每一对 4-邻接像素 (p, q)，若 p 和 q 均为前景色（绿(3)）且分别属于不同象限，则标记 (p, q) 为"碰撞对"。
3. 碰撞对的重涂颜色由两个象限的旋转角度差决定：角度差 90 度（相邻象限水平或垂直相接）→将碰撞对的两个像素都涂为红(2)；角度差 180 度（对角象限在角点处 4-邻接，仅当两像素分别在对角象限且在中心点旁 4-邻接时发生）→涂为黄(4)。
4. 非碰撞的前景像素保留绿(3)。背景像素保留黑(0)。
5. 若某个像素同时属于多个碰撞对（极端情况下中心点附近可能发生），优先使用角度差更大的编码颜色（180 度优先于 90 度）。

**关键洞察**：碰撞不是显式设计的轨迹交叉，而是旋转拼接后的几何涌现——同一个像素在原图中远离边缘，但某个旋转副本可能将它推到交界处。重涂颜色看似任意，实际由角度差编码——需要构造不同碰撞位置的示例才能区分 90 度碰撞与 180 度碰撞的着色规则。

## 新题 8：引导像素消失后的对齐连线与面板反色着色

**组合逻辑**：[连线 + 行列对齐 + 对齐像素投射矩形 + 碰撞停止](已有) ↔ [所属面板 + 对侧面板色](已有，创新：连线颜色不用像素自身颜色，而用其所在面板的对侧色) + [引导像素 + 角落色转移后消](已有，创新：引导色仅在线段交叉点生效)

**来源原语**：连线 draw_line/connect、行列对齐 row_col_align、对齐像素投射矩形 aligned_pixel_to_rect、碰撞停止 collision_stop（2c608aff）；所属面板 panel_membership、对侧面板色 opposite_panel_color（9b5080bb）；引导像素 guide_pixel、角落色转移后消 corner_color_transfer_vanish（aabf363d）；轨迹交叉 trail_intersection（ac605cbb）；擦除 erase（aabf363d）

**依赖链**：孤立像素沿行列对齐方向向中心矩形画线 → 线的颜色由像素所在面板的对侧色决定（面板归属约束连线颜色）→ 两条线交叉的像素改用角落引导色 → 引导像素自身消失。删去面板→连线颜色不确定；删去引导色→交叉点颜色不确定；删去对齐连线→没有线段可交叉。

孤立像素向中心矩形画对侧面板色的连线，线段交叉处改涂角落引导色，引导像素随后消失。

**输入结构**：约 17x17 网格。背景分为左右两个面板：左半区底色蓝(1)，右半区底色红(2)，分界线为正中间的一列灰(5)像素。网格中心（跨越分界线或偏某侧）有一个灰(5)实心矩形（3~5 行 x 3~5 列）。矩形两侧散布 3~5 个孤立的单像素标记，颜色各异（从绿(3)、黄(4)、品红(6)、橙(7)中取），有些在左面板，有些在右面板。每个标记像素与灰(5)中心矩形共享行或列（即行对齐或列对齐，保证可画直线到矩形）。网格左下角有一个青(8)引导像素。生成约束：至少存在两条连线（一条水平、一条垂直）会在中心矩形附近交叉；所有标记像素不在同一行或同一列上。

**规则**：
1. 识别灰(5)中心矩形。将每个非灰(5)、非面板底色的孤立像素视为标记。
2. 对每个标记，判断其所在面板（在灰(5)分界线左侧→左面板蓝(1)，右侧→右面板红(2)）。
3. 从每个标记沿其与中心矩形对齐的方向（共享行→水平方向，共享列→垂直方向）画一条直线，直到碰到灰(5)矩形边缘的前一个像素为止（不覆盖矩形本身）。连线颜色为标记所在面板的**对侧面板底色**（左面板标记→线色红(2)，右面板标记→线色蓝(1)）。
4. 所有连线绘制完成后，检测交叉：若某像素被两条不同标记的连线同时经过，将该像素改涂为左下角引导像素的颜色——青(8)。
5. 擦除左下角的青(8)引导像素（改为其所在面板的底色蓝(1)）。
6. 标记像素本身保留原色不变。灰(5)矩形和分界线保持不变。面板底色中仅被连线经过的像素改变颜色。

**关键洞察**：连线颜色与标记自身颜色无关，而由标记的空间位置（所在面板）决定——左面板的标记画出的线反而是红色，右面板的反而是蓝色。引导像素的功能也非直觉：它不重涂所有前景，只影响交叉点，且完成使命后自我消除。需要对比多个示例（不同面板的标记产生不同色的线）才能归纳出"对侧面板色连线"规则。
