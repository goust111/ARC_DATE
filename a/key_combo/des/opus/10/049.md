## 新题 1：重力落位后按标记近邻上色

**组合逻辑**：[重力下落](已有) + [最近邻选择](已有) → [重涂色](创新：着色依据是运动后而非运动前的位置关系)

**来源原语**：重力下落/gravity_drop（6ad5bdfd）、碰撞停止/collision_stop（6ad5bdfd）、近墙优先结算/nearest_first_settling（6ad5bdfd）、边墙/edge_wall（6ad5bdfd）、标记像素/marker_pixel（6df30ad6）、最近邻选择/nearest_neighbor_selection（6df30ad6）、重涂色/recolor（6df30ad6）、擦除/erase（6df30ad6）、欧氏距离最小/minimum_euclidean_distance（6df30ad6）

**依赖链**：重力下落改变碎片的空间位置 → 位置改变导致每块碎片的最近标记像素可能与滑动前不同 → 必须先完成物理模拟才能确定着色方案；同时，标记像素不参与滑动（固定地标），形成"运动体 vs. 固定参照"的新结构关系

将固定的彩色标记像素作为空间锚点，灰色碎片滑向边墙堆叠后，按落位后与各标记的欧氏距离为每块碎片选色。

**输入结构**：约 15x15 的网格，黑(0)背景。左侧有一列完整的蓝(1)边墙（占满整列）。网格中散布 4~6 块灰(5)的 4-连通多连块碎片（每块 3~7 像素，形状各异，无两块全等）。另有 3~5 个孤立的彩色标记像素，每个标记颜色互不相同且不为黑(0)、灰(5)、蓝(1)（可用红(2)、绿(3)、黄(4)、品红(6)、橙(7)等）。标记像素散布在碎片之间或碎片与边墙之间的空隙中。生成约束：碎片之间互不接触，标记像素不在任何碎片的 4-邻域内；碎片数量不超过标记数量。

**规则**：
1. 所有灰(5)碎片向左侧蓝(1)边墙滑动。标记像素固定不动，不参与滑动。
2. 离边墙最近（即左边界列号最小）的碎片优先结算；碎片整体刚性平移，逐列左移直到下一步会与边墙、另一已结算碎片或网格边界重叠时停止。
3. 若两块碎片的左边界列号相同，按其边界框左上角行号较小者优先。
4. 全部碎片结算后，对每块碎片，计算该碎片所有像素到每个标记像素的欧氏距离平方的最小值，取最小值最小的那个标记像素的颜色作为该碎片的目标色。若存在平局，选行号更小的标记；行号仍相同则选列号更小的。
5. 将每块碎片重涂为其目标色。擦除所有标记像素（置为黑(0)）。蓝(1)边墙保持不变。

**关键洞察**：标记像素是不动的空间锚点，碎片是移动的被着色体。滑动前某碎片可能离红标记最近，但滑动堆叠后它可能移到了绿标记旁——最终颜色由终态位置决定，不由初始位置决定。

## 新题 2：双面板重力沉降后取并集

**组合逻辑**：[重力下落](已有) → [透明叠加 + 布尔并集](创新：叠加的不是原始掩码而是物理模拟后的沉降态)

**来源原语**：重力下落/gravity_drop（6ad5bdfd）、边墙/edge_wall（6ad5bdfd）、近墙优先结算/nearest_first_settling（6ad5bdfd）、碰撞停止/collision_stop（6ad5bdfd）、多米诺骨牌/domino（6ad5bdfd）、并列面板/side_by_side_panel（dae9d2b5）、透明叠加/transparent_overlay（dae9d2b5）、逐格对齐/cell_alignment（dae9d2b5）、布尔并集合并/boolean_union（dae9d2b5）、分隔列/divider_column（5d2a5c43）

**依赖链**：两个面板各自内部进行独立的重力沉降 → 沉降改变前景像素的空间分布 → 沉降后的掩码才是并集运算的输入；跳过沉降直接取并集会得到完全不同的结果

两个并列面板各含散布的多米诺骨牌和底部边墙；骨牌先在各自面板内下落堆叠，然后对两个沉降态取逐格布尔并集，输出单面板。

**输入结构**：约 12x25 的网格：两个 12x12 面板水平排列，中间由一列蓝(1)分隔列隔开。每个面板内：黑(0)背景，底行为一行完整的灰(5)边墙。面板中散布 4~6 个单色水平或垂直多米诺骨牌（每块恰好 2 像素），各骨牌颜色互不相同（可为红(2)、绿(3)、黄(4)、品红(6)、橙(7)等非黑非蓝非灰色）。左右面板的骨牌数量可不同、颜色可不同。生成约束：每个面板内骨牌互不相邻，骨牌不与边墙相邻。

**规则**：
1. 在每个面板内独立执行重力下落：所有骨牌向下（朝灰(5)边墙方向）滑动。离边墙最近的骨牌优先结算。骨牌刚性平移，逐行下移，碰到边墙、已结算骨牌或面板底边时停止。同距离的骨牌按边界框左上角列号从左到右依次结算。
2. 两个面板均沉降完成后，移除蓝(1)分隔列，将左右面板按行列逐格对齐。
3. 对齐后的每个格位：若左面板或右面板（或两者）在该位置有前景像素（非黑非灰），则输出品红(6)；否则输出黑(0)。灰(5)边墙行不出现在输出中——输出仅包含边墙上方的区域。
4. 输出为一个 11x12 的单面板（去掉底部边墙行）。

**关键洞察**：取并集的对象不是两个面板的原始布局，而是各自经过重力沉降后的状态。同样的骨牌在不同初始高度会沉降到不同位置，使得并集结果与原始掩码的并集截然不同。

## 新题 3：频率筛选决定连线或擦除

**组合逻辑**：[计数 + 频率排序](已有) → [连线](创新：频率决定哪些色连、哪些色擦) + [擦除](创新：擦除后腾出新路径空间)

**来源原语**：计数/counting（f8b3ba0a）、频率排序/frequency_ordering（f8b3ba0a）、跳过最高频/skip_most_frequent（f8b3ba0a）、连线/connect（f8f52ecc）、同色分量依序连接/same_color_chain（f8f52ecc）、障碍墙/obstacle_wall（f8f52ecc）、绕障碍最短路径/shortest_detour（f8f52ecc）、擦除/erase（6df30ad6）

**依赖链**：计数各色连通分量数量 → 频率最高的颜色被判定为干扰色并擦除 → 擦除腾出的空间成为其余颜色连线时的可用通道 → 连线路径依赖擦除结果，三者形成信息变换链而非简单传递

统计每种前景色的连通分量数，分量最多的颜色被视为噪声并擦除；其余颜色的分量通过绕障碍最短路径连接，擦除区域为连线提供了新的通行空间。

**输入结构**：约 16x16 的网格，黑(0)背景。青(8)像素构成若干不相连的短墙段（每段 2~4 像素的水平或垂直线段，共 3~5 段），作为固定障碍。另有 3~4 种非黑非青前景色（如红(2)、绿(3)、黄(4)、品红(6)），每种颜色出现为若干 4-连通分量（每个分量 2~5 像素的不规则形状）。其中恰好一种颜色的分量数严格多于其他所有颜色（如该色有 5 个分量，其他色各有 2~3 个）。分量较少的颜色中，每种至少有 2 个分量。生成约束：各分量之间至少间隔 1 格空行/空列；高频色的分量分散在网格各处，且至少有一个位于两个低频色分量之间、阻断了它们的直接连线路径。

**规则**：
1. 对每种非黑(0)非青(8)的前景色，统计其 4-连通分量的数量。
2. 分量数最多的颜色被标记为噪声色。将该颜色的所有像素擦除为黑(0)。若存在平局，选在输入网格中从上到下、从左到右扫描时最先遇到的颜色。
3. 擦除完成后，对每种剩余的非黑非青前景色，按行优先顺序（先比较分量边界框左上角的行号，再比较列号）排列其分量。
4. 对每种颜色，依序连接相邻分量对：从第 1 个分量到第 2 个，从第 2 个到第 3 个，依此类推。连线路径规则：从源分量任一像素到目标分量任一像素的最短 L 形路径（至多一个直角弯），路径只能通过黑(0)格或同色格，不能穿越青(8)墙段或其他颜色的像素。若两种弯法路径等长，保持先沿当前行方向再拐弯的优先。
5. 连线像素涂为对应颜色。青(8)墙段保持不动。

**关键洞察**：高频色不仅被删除，它原先占据的位置释放为空地——这些新空地恰好可以被低频色的连线路径利用。如果不先擦除高频色，某些低频色的分量对之间可能无合法 L 形路径。

## 新题 4：最大分量定反射轴，其余分量被镜像

**组合逻辑**：[按面积筛选 + 保留最大分量](创新：最大分量不被操作，而是编码操作参数) → [镜像](创新：轴由最大分量的形状隐式决定)

**来源原语**：连通分量/connected_component（337b420f）、按面积筛选/size_filtered（337b420f）、保留最大分量/keep_largest（337b420f）、忽略干扰项/ignore_distractors（337b420f）、镜像/mirror（4e7e0eb9）、轴线决定变换/axis_determines_op（4e7e0eb9）

**依赖链**：识别最大分量 → 其边界框长宽比决定反射轴方向 → 其边界框中心线成为反射轴 → 所有非最大分量以此轴为参照镜像 → 最大分量本身不变且充当碰撞遮挡；面积比较、轴推断、镜像执行、冲突消解四步缺一不可

在多个散布的彩色连通分量中找到像素数最多的那个；它的边界框长宽比决定反射轴方向，边界框中心线即为轴；其余分量关于此轴镜像，与最大分量重叠的像素被丢弃。

**输入结构**：约 15x15 的网格，黑(0)背景。包含 4~6 个 4-连通的单色分量，每个分量颜色互不相同（可用红(2)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7)等）。每个分量 3~10 像素，形状不规则（非矩形、非对称）。恰好一个分量的像素数严格大于其他所有分量。生成约束：最大分量大致位于网格中央区域；其余分量分布在最大分量周围；最大分量的边界框宽度与高度不相等（保证轴方向唯一）；镜像后至少有一个小分量与最大分量部分重叠。

**规则**：
1. 计算每个 4-连通分量的像素数。选出像素数最多的分量为"锚分量"。若存在平局，选边界框左上角行号更小者；仍平局则选列号更小者。
2. 计算锚分量的边界框。若边界框宽度 > 高度，反射轴为通过边界框中心行的水平线（上下镜像）；若高度 > 宽度，反射轴为通过边界框中心列的垂直线（左右镜像）。中心行 = (top + bottom) / 2（取下整），中心列 = (left + right) / 2（取下整）。
3. 锚分量保持不动，保留原色、原位。
4. 对每个非锚分量，将其所有像素关于反射轴做镜像。镜像后的像素若落在网格外则丢弃；若落在锚分量已有像素上则丢弃（锚分量优先）；若落在另一个已镜像分量的像素上，则后处理的分量覆盖先处理的（处理顺序：按原始分量边界框左上角行优先、列次优先排序）。
5. 非锚分量在原始位置的像素被擦除（置为黑(0)），仅保留其镜像位置的像素。

**关键洞察**：最大分量同时扮演三个角色——它的面积决定了它被选中为锚、它的几何形状编码了反射轴方向、它的物理占位充当了镜像结果的遮挡屏障。三个角色缺一不可。

## 新题 5：控制像素的双重身份——定义拉伸边界并成为连线端点

**组合逻辑**：[拉伸 + 控制点定拉伸界](已有) → [连线 + 绕障碍最短路径](创新：拉伸后的图形成为连线的新障碍，控制像素既是拉伸参数又是连线端点)

**来源原语**：拉伸/stretch（baf41dbf）、重绘/redraw（baf41dbf）、直角线条图/rectilinear_drawing（baf41dbf）、控制像素/control_pixel（baf41dbf）、边缘对齐控制点/edges_align_control（baf41dbf）、控制点定拉伸界/control_stretch_bound（baf41dbf）、连线/connect（f8f52ecc）、同色分量依序连接/same_color_chain（f8f52ecc）、障碍墙/obstacle_wall（f8f52ecc）、绕障碍最短路径/shortest_detour（f8f52ecc）

**依赖链**：控制像素定义拉伸目标矩形 → 拉伸线条图 → 拉伸后的线条图面积扩大成为新的障碍区域 → 同色控制像素对之间需要连线、连线路径必须绕开拉伸后的线条图和青墙 → 控制像素在"拉伸"和"连线"两个阶段扮演完全不同的角色，两步缺一不可

将直角线条图拉伸到控制像素指定的边界后，相同颜色的控制像素对之间用最短 L 形路径连线，拉伸后的线条图和固定墙段均为路径障碍。

**输入结构**：约 18x18 的网格，黑(0)背景。网格中有一个绿(3)的连通直角线条图（由若干完整的水平和垂直线段组成，线段宽度 1 像素，整体 4-连通，占据约 5x5 的区域）。线条图外部散布若干彩色控制像素，每个控制像素位于线条图当前边界框的某一侧外一格处。控制像素共 3 种非绿非黑颜色（如红(2)、黄(4)、品红(6)），每种颜色恰好出现 2 个像素。同色的两个控制像素分别位于线条图的不同侧（如一个在上侧、一个在右侧）。另有若干青(8)的短墙段（每段 2~3 像素，共 2~4 段），分布在控制像素附近但不与线条图相邻。生成约束：所有控制像素恰好在线条图边界框外一格处，且它们共同定义的目标矩形严格大于原始边界框；拉伸后的线条图不会覆盖任何控制像素或青墙段；每对同色控制像素之间在拉伸后的网格中存在至少一条合法的 L 形路径。

**规则**：
1. 找到绿(3)线条图的最小边界框。每个控制像素位于该边界框某侧外一格处——根据所有控制像素的位置确定目标矩形（使得每个控制像素恰好在目标矩形对应侧外一格处）。
2. 将线条图拉伸至目标矩形：原始边界框的四条外边线段移动到目标矩形的对应边，内部的水平/垂直线段在拉伸后的矩形内按比例重新绘制横跨整个宽度/高度。拉伸后的线条图仍为绿(3)。
3. 拉伸完成后，对每种控制像素颜色，将该色的两个像素视为一对端点。按颜色在输入中首次出现的扫描顺序（从上到下、从左到右）依次处理各色对。
4. 对每对端点，找从一个端点到另一个端点的最短 L 形路径（至多一个直角弯）。路径只能通过黑(0)格，不能穿越绿(3)拉伸线条图、青(8)墙段、其他颜色的控制像素或已绘制的连线。路径像素涂为对应控制像素颜色。
5. 若两种等长的 L 形路径都合法，选择先沿水平方向再拐垂直方向的路径。若仍都合法，选先向行号减小方向或列号减小方向移动的路径。
6. 控制像素本身保留原色不变。

**关键洞察**：同一组控制像素在第一阶段是拉伸的定位参数，在第二阶段变为连线的端点。拉伸使线条图扩张，而扩张后的线条图恰好横亘在需要连线的控制像素对之间——控制像素自己定义了阻碍自己连线的障碍形状。

## 新题 6：带噪声的平移对称图案遮挡恢复

**组合逻辑**：[计数 + 少数色替换](创新：频率分析用于识别噪声而非直接替换) → [补全 + 对称轨道](创新：补全对象同时包含噪声区和遮挡区，但识别机制不同) → [裁剪](已有)

**来源原语**：计数/counting（f8b3ba0a）、少数色替换/minority_replaced（9caf5b84）、补全/completion（f9012d9b）、平移对称图案/translational_pattern（f9012d9b）、对称轨道/symmetry_orbit（f9012d9b）、遮挡矩形/occluding_rect（f9012d9b）、对称恢复遮挡/symmetry_restores（f9012d9b）、裁剪/crop（f9012d9b）

**依赖链**：频率分析识别噪声色（少数色）→ 噪声色被排除后才能准确检测平移周期 → 平移对称既用于恢复噪声像素也用于恢复遮挡像素 → 最终裁剪输出遮挡区域。噪声和遮挡是两种不同的"缺损"，需要不同的检测手段（频率 vs. 空间连通性）但共享同一个恢复机制（对称轨道），形成诊断分叉-恢复汇合的结构

在一个具有平移对称性的彩色图案上，黑色矩形遮挡了一部分，同时部分未遮挡像素被随机替换为少数色噪声；先用频率识别噪声、再用平移对称恢复所有缺损，最后裁剪输出遮挡区。

**输入结构**：约 14x14 的网格，无真正背景色——整个网格本质上是一个平移对称的彩色瓦片图案（瓦片大小约 3x3 或 4x4），使用 3~4 种颜色（如红(2)、绿(3)、蓝(1)、黄(4)）。网格中有一个约 4x5 的矩形区域全部填充为黑(0)（遮挡矩形），位置不在网格边缘。在遮挡矩形之外，有 5~8 个像素被随机替换为橙(7)（噪声色）。橙(7)不出现在原始图案中。生成约束：瓦片至少在两个方向上各重复 3 次以上，确保每个被遮挡位置至少有一个非黑非橙的对称轨道伙伴可供恢复；噪声像素不聚集在一起（两两不 4-相邻）。

**规则**：
1. 统计所有非黑(0)像素的颜色频率。出现次数最少的颜色即为噪声色（在本题中为橙(7)）。将所有噪声色像素标记为"待恢复"，但暂不修改。
2. 仅使用非黑(0)、非噪声色的像素来检测平移对称周期：找到最小的水平周期 dx 和垂直周期 dy，使得对所有有效像素 (r, c)，有 color(r, c) == color(r+dy, c+dx)（忽略黑和噪声位置）。
3. 恢复噪声像素：对每个噪声色像素 (r, c)，找到其平移轨道中最近的非黑非噪声像素 (r+k*dy, c+k*dx)，将 (r, c) 的颜色设为该像素的颜色。若 k 为正负皆可，优先选 |k| 最小的。
4. 恢复遮挡像素：对遮挡矩形中每个黑(0)像素 (r, c)，用同样的平移轨道方法从已恢复的网格中找到非黑像素填充。
5. 输出仅为遮挡矩形区域的裁剪结果（恢复后的内容）。

**关键洞察**：噪声和遮挡都是"错误值"，但检测方式不同：噪声通过频率异常识别（全局统计），遮挡通过空间连通性识别（黑色矩形）。然而两者的恢复机制相同（平移对称轨道），且噪声必须先被识别并排除，否则会干扰对称周期的检测——构成不可跳步的诊断链。

## 新题 7：空心方框变十字后重力堆叠咬合

**组合逻辑**：[方框换为十字掩模](已有) → [重力下落 + 碰撞停止](创新：十字形的凹角允许异形咬合堆叠，产生不同于方形堆叠的紧密图案)

**来源原语**：空心矩形/hollow_rect（6c434453）、方框换为十字掩模/square_to_cross_mask（6c434453）、重涂色/recolor（6c434453）、擦除/erase（6c434453）、重力下落/gravity_drop（6ad5bdfd）、边墙/edge_wall（6ad5bdfd）、碰撞停止/collision_stop（6ad5bdfd）、近墙优先结算/nearest_first_settling（6ad5bdfd）

**依赖链**：形状变换（方框→十字）改变碰撞几何 → 重力堆叠时十字形的凹角允许相邻十字的臂伸入 → 产生的堆叠图案在方框形态下不可能出现 → 冲突消解依赖原始位置（变换前）；形变和物理模拟之间存在几何耦合

将散布的彩色 3x3 空心方框各自变换为同色十字（加号）形，然后所有十字形向边墙方向做重力下落；十字的凹角结构使得相邻十字可以局部咬合。

**输入结构**：约 15x12 的网格，黑(0)背景。底行为一行完整的灰(5)边墙。网格中散布 5~7 个 3x3 空心方框（即 8 像素的方框，中心为黑(0)），每个方框颜色互不相同（可用红(2)、绿(3)、黄(4)、蓝(1)、品红(6)、橙(7)、青(8)等非黑非灰色）。生成约束：方框之间至少间隔 1 格（边界框不相邻）；所有方框位于灰(5)边墙上方至少 2 行处。

**规则**：
1. 对每个 3x3 空心方框，执行十字变换：擦除四个角像素（置为黑(0)），保留上、下、左、右四个边邻像素和中心位置。将中心像素涂为该方框的颜色（原为黑(0)）。变换后每个十字形占 5 像素（形如加号）。
2. 所有十字形向下（朝灰(5)边墙方向）滑动。距边墙最近（即中心行号最大）的十字优先结算。
3. 每个十字整体刚性下移，逐行移动，在下一步任何像素会与灰(5)边墙、已结算十字的像素或网格底边重叠时停止。
4. 若两个十字中心行号相同，按中心列号从左到右依次结算。
5. 十字堆叠时可以"咬合"——一个十字的凹角区域（四个角位置是空的）允许相邻十字的臂端伸入，只要不发生像素级重叠。
6. 灰(5)边墙保持不变。所有十字保留各自原色。

**关键洞察**：如果不执行方框→十字变换而是直接堆叠方框，方框之间无法咬合，只会简单垒叠。十字形的四个凹角恰好容纳相邻十字的臂端，使堆叠后的整体高度低于方框堆叠、且产生交错的棋盘式咬合图案——这种涌现效应来自形变与物理模拟的几何耦合。

## 新题 8：按原始位置近邻上色的拼合碎片

**组合逻辑**：[拼合填充](已有) + [最近邻选择 + 重涂色](创新：颜色信息来自拼合前的空间关系，显示在拼合后的布局中，跨越两个时态)

**来源原语**：拼合填充/packing（b7cb93ac）、多连块碎片/polyomino_fragment（b7cb93ac）、紧凑矩形/compact_rectangle（b7cb93ac）、无重叠拼合/non_overlap_packing（b7cb93ac）、按面积降序放置/descending_area_place（b7cb93ac）、标记像素/marker_pixel（6df30ad6）、最近邻选择/nearest_neighbor_selection（6df30ad6）、重涂色/recolor（6df30ad6）、擦除/erase（6df30ad6）、欧氏距离最小/minimum_euclidean_distance（6df30ad6）

**依赖链**：拼合前记录每块碎片与各标记的距离关系 → 拼合改变碎片的物理位置但不改变其颜色归属 → 输出中的颜色编码的是拼合前的空间信息；拼合和着色分别依赖空间布局的不同时态，形成跨时态引用

将灰色碎片拼合成紧凑矩形，但每块碎片的输出颜色由它在拼合前离哪个彩色标记最近来决定。

**输入结构**：约 15x15 的网格，黑(0)背景。散布 4~6 块灰(5)的 4-连通多连块碎片（每块 3~8 像素，形状各异）。另有 2~4 个孤立的彩色标记像素，颜色互不相同（如红(2)、绿(3)、黄(4)、品红(6)等，不为黑(0)或灰(5)）。碎片总像素数恰好等于一个紧凑矩形的面积（如 4x6=24 像素）。生成约束：碎片之间互不接触；标记像素不在任何碎片内部或 4-邻域内；碎片数量不少于标记数量（允许多块碎片被同一标记"认领"）。

**规则**：
1. 对每块灰(5)碎片，计算其所有像素到每个标记像素的欧氏距离平方的最小值。选最小值最小的标记为该碎片的"归属标记"，记录其颜色。若平局，选行号更小的标记；仍平局选列号更小的。
2. 将所有碎片按像素数从大到小排序（像素数相同则按原始位置边界框左上角先行后列排序）。
3. 依序将碎片拼入最小面积的紧凑矩形中：对每块碎片，依次尝试原始方向、水平翻转、顺时针 90 度旋转、顺时针 90 度旋转后翻转、180 度旋转、180 度旋转后翻转、270 度旋转、270 度旋转后翻转，在每种方向下从矩形左上角到右下角逐格扫描，选择第一个不与已放置碎片重叠的位置。
4. 将拼合后的每块碎片涂为其步骤 1 中记录的归属标记颜色（不再是灰色）。
5. 输出仅为拼合后的紧凑矩形。标记像素和原始布局不出现在输出中。

**关键洞察**：输出矩形中的颜色分布编码了碎片在拼合前与各标记的空间亲疏关系——这是一种跨时态信息：空间关系在旧布局中度量，但颜色在新布局中呈现。仅看输出无法反推着色逻辑，必须参照原始位置。

## 新题 9：互遮挡图案的双层对称恢复

**组合逻辑**：[对称补全](创新：两个图案互为对方的遮挡源，形成循环依赖) + [叠加](创新：叠加顺序由面积比较决定) + [双轴反射对称](已有)

**来源原语**：对称补全/symmetry_completion（0934a4d8）、双轴反射对称/biaxial_reflection_symmetry（0934a4d8）、标记遮挡区域/marker_occludes_region（0934a4d8）、对称恢复遮挡/symmetry_restores（f9012d9b）、叠加/overlay（337b420f）、按面积筛选/size_filtered（337b420f）

**依赖链**：识别两组颜色为两个独立图层 → 每个图层将对方的像素视为遮挡 → 各自利用双轴反射对称恢复被遮挡的区域 → 但恢复时需要知道对方的完整形态以确定遮挡范围 → 两个图层的恢复互为前提条件（循环约束） → 利用对称性迭代或同时求解打破循环 → 最后按前景面积决定叠加顺序输出

两个各自具有双轴反射对称性的彩色图案在同一网格中互相遮挡；需同时恢复两者的完整形态，面积更大者绘制在上层。

**输入结构**：约 12x12 的网格，黑(0)背景。网格中有两组颜色的前景像素：A 组使用红(2)和蓝(1)（A 组的像素在完整状态下具有关于网格中心的双轴反射对称性），B 组使用绿(3)和黄(4)（B 组的像素在完整状态下同样具有关于网格中心的双轴反射对称性）。但当前状态中，A 组和 B 组的像素在某些位置重叠——重叠处只显示一个图层的颜色，另一图层的对应像素被"遮挡"（不可见）。每组至少有 70% 的像素可见（未被遮挡），确保对称性可被识别。生成约束：两组图案的对称中心相同（均为网格中心）；每组图案在可见部分中的对称性足以唯一确定完整图案；两组图案不完全重叠（各有独占区域）。

**规则**：
1. 将非黑像素按颜色分为两组：{红(2), 蓝(1)} 为 A 组，{绿(3), 黄(4)} 为 B 组。
2. 对 A 组：将所有 B 组像素位置视为"可能遮挡区"。在 A 组的可见像素中检测双轴反射对称性（对称中心为网格中心）。对每个 B 组像素位置，如果 A 组的对称轨道表明该位置应有 A 组像素，则恢复该像素的颜色（红(2)或蓝(1)，由对称伙伴决定）。
3. 对 B 组：同理，将所有 A 组像素位置视为"可能遮挡区"，用 B 组的双轴对称性恢复被遮挡像素。
4. 计算恢复后 A 组和 B 组各自的前景像素总数。
5. 在黑(0)背景上先绘制像素数较少的组（底层），再绘制像素数较多的组（顶层）。若像素数相同，A 组在上。重叠位置由顶层颜色覆盖。

**关键洞察**：与单图案遮挡恢复不同，这里两个图案互为对方的遮挡源——要恢复 A 就需要知道哪些位置是 B 遮挡的，而 B 本身也不完整。突破口是：每组都有足够多的可见像素来独立检测自身的对称性，因此恢复过程可以并行而不需要知道对方的完整形态。

## 新题 10：嵌套框架深度编码滑动方向

**组合逻辑**：[嵌套层次](创新：嵌套深度不用于颜色操作而是编码运动方向) → [滑动](创新：方向不由颜色决定而由结构层次决定) + [碰撞停止](已有)

**来源原语**：嵌套层次/nesting_hierarchy（8dae5dfc）、嵌套矩形层/nested_rect_layer（8dae5dfc）、滑动/slide（f3e62deb）、颜色编码方向/color_coded_dir（f3e62deb）、空心矩形/hollow_rect（f3e62deb）、碰撞停止/collision_stop（6ad5bdfd）

**依赖链**：解析空心矩形的嵌套关系并计算每层深度 → 深度值映射为方向（而非颜色映射方向）→ 内部的小精灵体按其所处嵌套层的深度方向滑动 → 框架边界同时充当方向编码器和物理阻挡；嵌套分析和滑动模拟通过"方向编码"紧耦合

多层嵌套的彩色空心矩形框架中，每层框架的嵌套深度编码一个滑动方向；框架内的小精灵体沿所在层编码的方向滑动到框架边界。

**输入结构**：约 18x18 的网格，黑(0)背景。包含 2~3 组嵌套的空心矩形框架。每组由 2~3 层嵌套的空心矩形组成（即一个矩形框内包含一个更小的矩形框，更小的内部可能还有一个）。每层框架颜色不同（可用红(2)、蓝(1)、绿(3)、黄(4)、品红(6)等）。最内层框架内部有 1~2 个灰(5)的小精灵体（4-连通、3~5 像素的不规则形状）。不同组的嵌套框架之间不重叠、不嵌套。生成约束：每个精灵体与其所在框架的四边都有至少 1 格间距；同一框架内的多个精灵体之间有至少 1 格间距；嵌套深度最大不超过 3。

**规则**：
1. 确定每个空心矩形框架的嵌套深度：不被任何其他框架包含的框架深度为 0，被一层框架包含的深度为 1，被两层包含的深度为 2，依此类推。
2. 深度到方向的映射：深度 0 → 向右，深度 1 → 向下，深度 2 → 向左，深度 3 → 向上（若有更深层则循环）。
3. 每个精灵体位于某个最内层框架内部。找到直接包含该精灵体的最内层框架，使用该框架的深度所对应的方向作为精灵体的滑动方向。
4. 精灵体沿其方向刚性滑动，逐格移动，当下一步任何像素会与框架边界、另一个已结算精灵体或网格边界重叠时停止。
5. 处理顺序：按精灵体到其滑动方向目标边界的距离从小到大结算（最近目标边界的先动）。距离相同时按精灵体边界框左上角行优先、列次优先排序。
6. 所有框架保持不变，仅精灵体移动。

**关键洞察**：框架的颜色是干扰信息——方向不由颜色决定（不同于参考题 f3e62deb），而由嵌套的结构层次决定。求解者必须忽略颜色线索、转而分析几何包含关系来推断方向，这需要对比多个示例中不同颜色在不同嵌套深度时精灵体的运动方向。

## 新题 11：旋转角度由复制次数决定的精灵体印章

**组合逻辑**：[复制放置 + 标记交叉定位](已有) → [旋转](创新：旋转角度不是固定的，由该精灵体的目标位置数量决定) + [计数](创新：计数对象是目标位置而非分量数) → [叠加优先级由目标数排序决定](创新)

**来源原语**：复制放置/replicate_stamp（247ef758）、标记交叉定位/marker_intersection_positioning（247ef758）、精灵体/sprite（247ef758）、框架标记/frame_marker（247ef758）、分隔列/divider_column（247ef758）、颜色匹配配对/color_match_pairing（247ef758）、旋转/rotation（b7cb93ac）、计数/counting（f8b3ba0a）、排序/sorting（f8b3ba0a）

**依赖链**：解析框架标记确定每种颜色的目标行列交叉位置 → 统计每种颜色的目标位置数 → 目标数决定对应精灵体的旋转角度 → 旋转后的精灵体被印章到各目标位置 → 目标数还决定重叠时的绘制优先级（目标多的覆盖目标少的）；计数结果同时控制旋转和优先级两个不同维度

在带框架标记的网格中，每个精灵体被复制到其颜色匹配的所有标记交叉位置，但精灵体的旋转角度由它拥有的目标位置数量决定，重叠时目标位置更多的精灵体绘制在上层。

**输入结构**：约 20x20 的网格，黑(0)背景。右侧有一个矩形框架（由灰(5)像素构成的 1 像素宽边框，内部为黑(0)），框架的上下边和左右边上各有若干彩色标记像素替换灰(5)像素。标记颜色来自 {红(2), 绿(3), 黄(4), 品红(6)} 中的 3~4 种。每种颜色在框架的上边和下边各出现 0~2 次（定义目标列），在左边和右边各出现 0~2 次（定义目标行）。某颜色在上下边均出现的列号与在左右边均出现的行号的笛卡尔积即为该颜色的目标位置集。网格左侧有一个窄条区域（宽 4~5 列），被一列品红(6)... 不对，分隔列颜色不能和标记色冲突。

让我重新设计这个。

实际上让我重新想分隔列的颜色。用栗(9)作为分隔列。

左侧窄条区域（宽约 5 列），被一列栗(9)分隔列与框架区域分开。窄条内从上到下排列 3~4 个精灵体，精灵体之间由至少 1 行黑(0)分隔。每个精灵体是 3x3 的单色 4-连通图形（3~5 像素），颜色与框架标记颜色一一对应。生成约束：每种标记颜色至少有 1 个目标位置；精灵体颜色与标记颜色一一匹配；不同颜色的目标位置数不全相同（至少两种颜色的目标数不同）。

**规则**：
1. 解析框架标记：对每种标记颜色，找出该颜色同时出现在框架上边和下边的列号集合 C，以及同时出现在左边和右边的行号集合 R。该颜色的目标位置集为 R x C（笛卡尔积），即所有 (r, c) 对，其中 r 来自 R，c 来自 C。
2. 统计每种颜色的目标位置数量 N。
3. 根据 N 确定旋转角度：N=1 时不旋转（0 度），N=2 时顺时针旋转 90 度，N=3 时旋转 180 度，N=4 时顺时针旋转 270 度，N>4 时角度 = ((N-1) mod 4) * 90 度。
4. 将旋转后的精灵体以目标位置为中心印章到框架内部。精灵体的中心像素（3x3 边界框的中心）对齐到目标位置。超出框架内部的像素丢弃。
5. 按目标位置数从少到多的顺序印章各颜色（目标少的先画、多的后画覆盖）。同一颜色内按目标位置从上到下、从左到右的顺序印章。目标数相同的颜色，按精灵体在左侧窄条中从上到下出现的顺序排序（上方的先画）。
6. 左侧窄条、分隔列和框架边框不出现在输出中。输出仅为框架内部区域。

**关键洞察**：目标位置的数量不仅决定"在哪里印章"，还决定"印章前怎么旋转"和"重叠时谁在上层"——同一个计数值同时控制了三个不同维度的行为。需要对比多个示例才能同时归纳出旋转规则和优先级规则。
