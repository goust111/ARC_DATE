## 新题 1：分隔线截断垂直射线

**组合逻辑**：[射线延伸](已有) + [连线/分隔线生成](创新：标记在矩形内展开为水平分隔线，分隔线从"仅在矩形内部起装饰作用"变为"射线延伸的截止障碍") → 两个原本无关的操作通过"分隔线=射线边界"产生耦合

**来源原语**：
- 射线延伸(ray_extend) / 沿列填至底(fill_column_to_bottom) ← d037b0a7
- 连线(draw_line) / 标记沿短轴展分割(marker_short_axis_div) / 包含(containment) ← 855e0971
- 前景源像素(foreground_source) ← d037b0a7
- 矩形区域(rect_region) / 标记像素(marker_pixel) ← 855e0971

**依赖链**：标记像素在矩形内展开成横向分隔线 → 分隔线成为射线延伸的截止边界。若不先生成分隔线，无法知道射线在何处终止；若无射线延伸，分隔线本身不构成最终输出的关键变化。

在由矩形区域分割的网格中，标记生成水平分隔线，上方的源像素向下延伸射线至最近的分隔线处停止。

**输入结构**：
- 约 15x15 的黑(0)背景网格。
- 网格被若干非黑单色填充矩形区域（各为不同颜色，如蓝(1)、红(2)、绿(3)等）水平分割为"条带"，每个矩形区域占据完整的行范围，宽度等于网格宽度，矩形之间紧密垂直堆叠、无间隔。
- 每个矩形区域的高度不小于3行。部分矩形区域内含有1个黑(0)标记像素（标记所在行不是该区域的首行或末行）。
- 在最上方矩形区域之上，有1~3行黑(0)行，其中包含孤立的黄(4)前景源像素，每列最多一个源像素。
- 生成约束：任意一列中最多只有一个源像素；含标记像素的矩形区域中标记所在列不存在源像素以外的非黑非区域色像素。

**规则**：
1. 对每个含有黑(0)标记像素的矩形区域，将该标记像素所在行的整行（仅限该矩形区域内部宽度范围）替换为黑(0)，形成水平分隔线。矩形区域的其余像素保持原色。
2. 对每个黄(4)源像素（位于最上方黑(0)行中），从其所在位置的下一行开始逐行向下延伸黄(4)色：
   - 经过矩形区域时，将该列内的矩形区域像素覆盖为黄(4)。
   - 当射线在某列遇到步骤1中生成的黑(0)分隔线时，射线在分隔线的上一行停止（不包含分隔线所在行）。
   - 若该列路径上无分隔线，射线延伸至网格底部。
3. 无源像素的列保持不变。

**关键洞察**：分隔线并非预设的固定结构——它由矩形内部标记的行位置决定，而射线的终止完全依赖于分隔线是否存在及其位置。必须先推理出哪些行被展开为分隔线，才能确定每条射线的长度。

## 新题 2：计数器偏移的端点配对行填充

**组合逻辑**：[填充](已有：同色端点行填充) + [计数](创新：计数值不再偏移一个十字图案，而是偏移填充后整行条的垂直位置) + [平移](创新：平移对象从十字图案变为行条)

**来源原语**：
- 填充(fill) / 同色配对(same_color_pairing) / 两端同色整行填充(full_row_fill_endpoints_match) ← 22eb0ac0
- 计数(counting) / 计数决定偏移(count_determines_offset) / 计数器消失(counter_disappears) ← e48d4e1a
- 平移(translate) ← e48d4e1a
- 标记像素(marker_pixel) / 画布边界(canvas_boundary) / 计数器像素(counter_pixel) ← 22eb0ac0, e48d4e1a

**依赖链**：先判断哪些行满足端点同色条件 → 对满足条件的行生成整行填充 → 计数灰色像素 → 将每条填充行向下平移对应的行数。跳过端点判断则不知道填哪些行；跳过计数则不知道偏移量；跳过平移则行位置错误。

根据左右边界标记颜色是否一致决定哪些行要填充，然后将填充行统一向下平移灰色计数器指定的行数。

**输入结构**：
- 约 12x12 的黑(0)背景网格。
- 若干行的最左列（第0列）和最右列（第W-1列）各有一个非黑非灰前景像素，颜色来自蓝(1)、红(2)、绿(3)、黄(4)，两端颜色可能相同也可能不同。每行至多有一对这样的边界标记。
- 网格最右列的最上方连续若干格为灰(5)像素，其余格为黑(0)。灰像素数量为1~4。
- 标记行和灰像素行不重叠（标记不出现在含灰像素的行中）。
- 生成约束：填充并平移后的行不会超出网格底部边界；不同填充行平移后不会重叠到同一行。

**规则**：
1. 计算最右列中从顶部开始连续灰(5)像素的数量，记为偏移量 N。
2. 对每一行，检查第0列和第W-1列的标记颜色：
   - 若两端标记颜色相同，则该行为"激活行"——用该标记颜色填充该行从第0列到第W-1列的所有像素。
   - 若两端颜色不同或缺少标记，该行不激活，原有标记像素在输出中清除为黑(0)。
3. 将所有激活行从原始行位置向下平移 N 行：原来在第 r 行的填充行在输出中出现在第 r+N 行，原位置变为黑(0)。
4. 移除所有灰(5)像素（输出中最右列顶部恢复为黑(0)）。

**关键洞察**：灰色计数器表面上与行填充无关——它的真正作用是给所有填充行施加统一的垂直位移。仅看一个示例可能误以为填充行"天然在那个位置"，必须对比不同 N 值的示例才能归纳出计数器与位移量的对应关系。

## 新题 3：角落复制后的邻接多数重涂色

**组合逻辑**：[复制+平移](已有：角落对象顺时针复制) + [重涂色](创新：复制品的颜色不再保留源色，而由目标角落附近标记像素的边邻接多数决重新确定)

**来源原语**：
- 复制(copy) / 平移(translate) / 顺时针到下一角(clockwise_next) / 忽略干扰项(ignore_distractors) ← bc93ec48
- 重涂色(recolor) / 边邻接计数(edge_adjacency_count) / 邻接多数决(adjacency_majority_rule) ← 477d2879
- 角落对象(corner_object) / 接触两边缘(touching_two_edges) ← bc93ec48
- 连通分量(connected_component) / 标记像素(marker_pixel) ← 477d2879

**依赖链**：识别角落对象 → 顺时针确定目标角落 → 在目标位置放置对象掩码 → 统计放置位置与周围标记像素的边邻接数 → 多数决确定涂色。复制决定了对象的目标位置，目标位置决定了哪些标记参与邻接计数，邻接计数决定了最终颜色。

将角落对象顺时针复制到下一个角落，复制品的颜色由目标角落附近标记像素的边邻接多数决定。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 2~3个角落各有一个单色前景对象（颜色如蓝(1)、绿(3)，仅用于识别源对象，不影响复制品颜色），每个对象为3~8像素的4-连通单色图形，包围盒接触该角落的两条相邻网格边界。各角落对象形状各异。
- 网格中散布若干孤立标记像素（颜色包括红(2)、黄(4)、品红(6)等，每种至少2个），标记像素不与任何角落对象的包围盒重叠，也不在网格边界上。部分标记像素靠近空角落或目标角落位置。
- 可能有1~2个不接触任何角落（不同时接触两条相邻边界）的前景对象作为干扰项。
- 生成约束：每个目标角落附近至少有2种不同颜色的标记像素，且各色的边邻接数互不相等，保证多数决无歧义。

**规则**：
1. 识别角落对象：包围盒同时接触网格的两条相邻边界（如左边界+上边界=左上角）的4-连通单色前景组件。仅接触一条边或不接触边的对象为干扰项，不参与复制。
2. 对每个角落对象，确定顺时针方向的下一个角落（左上→右上，右上→右下，右下→左下，左下→左上）作为目标角落。
3. 将角落对象的像素掩码复制到目标角落，包围盒对齐目标角落的两条边界。掩码方向保持不变（不旋转）。
4. 确定复制品的颜色：统计复制品在目标位置的所有像素与网格中每种标记颜色像素的共享边数（4-邻接），选择共享边数最多的标记颜色作为复制品的颜色。
5. 源角落的原始对象保留不变。标记像素保留不变。干扰项保留不变。
6. 若目标角落已有源对象（来自另一个角落），复制品的像素覆盖该位置。

**关键洞察**：角落复制看似应保持原色，但复制品的颜色其实完全由目标角落的局部标记分布决定——必须先完成空间复制以确定目标像素位置，才能计算与标记的邻接关系，而邻接关系反过来决定复制品的视觉呈现。

## 新题 4：旋转匹配嵌套后按方位半区重涂色

**组合逻辑**：[形状匹配+旋转/翻转](已有) → [嵌套放置](已有) → [重涂色](创新：重涂色的目标不再是固定的"包围盒下半区"，而是取决于嵌套时所用旋转角度——旋转后哪些像素落入框架坐标系的下半区)

**来源原语**：
- 形状匹配(shape_match) / 旋转(rotate) / 翻转(flip) / 八方向匹配(all_orientations_matching) ← 898e7135
- 嵌套放置(nest_inside) / 孔洞数匹配(hole_count_matching) ← 8698868d（匹配键在此创新为形状匹配）
- 重涂色(recolor) / 半区(half_region) / 半区变色(half_recolored) ← e7dd8335
- 框架(frame) / 孔洞槽位(hole_slot) / 拼块(piece) / 包围盒(bounding_box) ← 898e7135, e7dd8335

**依赖链**：形状匹配确定拼块与槽位的对应关系及所需旋转/翻转 → 嵌套放置确定拼块在框架中的坐标 → 在框架坐标系中判定"下半区"并将该区域的拼块像素重涂为红(2)。匹配决定方向，方向决定哪些像素在下半区，下半区决定重涂范围。

将拼块按形状匹配旋转后嵌入框架孔洞，然后将嵌入后位于框架坐标系下半区的拼块像素重涂为红色。

**输入结构**：
- 约 18x18 的黑(0)背景网格。
- 网格中央有一个灰(5)单色框架，为一像素厚的矩形边框，内部含2~3个独立的黑(0)孔洞区域。孔洞为各自不同形状的4-连通区域（3~6像素），每个孔洞包围盒高度为偶数行。
- 框架外部散布2~3个小型单色拼块（颜色各不相同，如蓝(1)、绿(3)、橙(7)），每个拼块是一个4-连通图形（3~6像素），需经旋转或翻转后恰好匹配某一个孔洞的形状。拼块颜色唯一且不与灰(5)或黑(0)相同。
- 生成约束：拼块与孔洞一一对应；每个拼块恰好在8种方向变换（4次旋转x2次翻转）中匹配一个孔洞；拼块形状非4-fold对称（使旋转可区分）；孔洞包围盒高度均为偶数。

**规则**：
1. 提取框架内部的各连通黑(0)孔洞区域作为槽位。
2. 对每个外部拼块，在8种方向变换中找到与某个槽位形状完全匹配的变换，记录所用变换。
3. 将匹配后的拼块（已应用旋转/翻转）放入对应槽位位置，像素颜色保持拼块原色。
4. 对每个已放置的拼块，将其所在孔洞的包围盒按高度等分为上半区和下半区。位于下半区行范围的拼块像素重涂为红(2)，上半区行范围的像素保持原色。
5. 框架本身的灰(5)像素保持不变。背景保持黑(0)。

**关键洞察**：拼块在嵌入前必须旋转才能匹配孔洞形状，而旋转改变了像素的相对位置——原本在拼块"上方"的像素经旋转后可能变成在框架坐标系中的"下方"。必须追踪旋转变换信息才能正确判断哪些像素该被重涂。

## 新题 5：对齐端点连线的调色板循环着色

**组合逻辑**：[连线](已有：对齐标记对之间填充) + [循环填充](创新：循环颜色分配的对象从"一列的逐行格子"变为"多条独立连线段"，运行长度从"每个格子"变为"每条线段") + [擦除](已有)

**来源原语**：
- 连线(draw_line) / 填充(fill) / 行列对齐(row_col_align) / 同行列端点间填充(fill_between_aligned_endpoints) ← 253bf280
- 循环填充(cyclic_fill) / 标记高度决定长度(marker_height_run_len) ← e7b06bea
- 擦除(erase) ← e7b06bea
- 标记像素(marker_pixel) / 线段(line_segment) / 调色板列(palette_col) / 长度标记段(length_marker) ← 253bf280, e7b06bea

**依赖链**：识别对齐标记对并生成连线段 → 按空间顺序排列连线段 → 读取调色板颜色序列和运行长度 → 将颜色按运行长度循环分配给各连线段。连线数量和顺序影响颜色分配结果；调色板和运行长度决定着色模式；两者缺一不可。

对齐的标记对之间画连线，每条连线的颜色由右侧调色板按灰段高度为运行长度循环分配。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 网格中散布若干孤立的青(8)标记像素。每行含0个或2个标记，每列含0个或2个标记。共有4~6对可连接的标记对（包含同行对和同列对）。
- 网格最右侧2~3列为调色板列，每列从第0行到最末行填满同一种颜色（不是黑(0)、灰(5)或青(8)），如红(2)、绿(3)、黄(4)，各列颜色不同。调色板列从左到右定义颜色顺序。
- 调色板列的左侧紧邻一列，该列顶端有一段连续灰(5)像素（1~3格），其余为黑(0)。灰段高度定义运行长度 K。
- 标记像素不出现在调色板列或灰段列中。
- 生成约束：同行对和同列对的连线段在非端点处不相交；连线段总数大于 K 以体现循环效果。

**规则**：
1. 识别所有对齐标记对：同一行恰好有2个青(8)标记为行对，同一列恰好有2个青(8)标记为列对。
2. 按以下顺序排列所有连线段：计算每条连线段中点坐标（行、列），按行坐标从小到大排序；行坐标相同时按列坐标从小到大排序。
3. 读取调色板列颜色序列 C1, C2, ..., Cm（从左到右）。读取灰段高度 K。
4. 按排列顺序为第 i 条连线段（i 从1开始）分配颜色：颜色索引 = ((ceil(i / K) - 1) mod m) + 1，即前 K 条连线段使用 C1，接下来 K 条使用 C2，依此循环。
5. 对每条连线段，用分配的颜色填充两个标记像素之间（不含标记本身）的所有黑(0)格子。标记像素保持青(8)不变。
6. 擦除所有调色板列和灰段列（替换为黑(0)）。

**关键洞察**：连线段本身无颜色信息——它的颜色完全由"它是第几条被处理的连线"决定，而处理顺序取决于所有连线段的空间分布。必须先找出所有连线段并排序，再结合调色板循环规则，才能确定每条线的颜色。

## 新题 6：色数编码控制印章旋转方向

**组合逻辑**：[印章覆盖](已有：源精灵覆盖占位对象) + [计数](创新：不再统计颜色数以映射线型，而是统计标签区的色数以决定精灵的旋转角度) + [旋转](创新：旋转不再用于形状匹配搜索，而是作为精灵印章的方向变换)

- 计数(counting) / 色数映射线型(count_maps_line) ← 6e02f1e3（创新为色数映射旋转）

- 擦除(erase) ← 321b1fc6
- 精灵体(sprite) / 占位对象(placeholder) / 整幅画布(full_canvas) ← 321b1fc6, 6e02f1e3

**依赖链**：识别源精灵和各占位对象 → 对每个占位对象统计其相邻标签区的不同颜色数 → 色数映射旋转角度 → 将旋转后的精灵颜色印到占位对象上 → 擦除标签区和源精灵。色数决定旋转，旋转决定印章图案——删掉任一步都无法得到正确输出。

每个占位对象旁的小标签区包含不同数量的颜色，色数决定源精灵印到该占位对象时的旋转角度。

**输入结构**：
- 约 16x16 的黑(0)背景网格。
- 一个多色源精灵体（由2~3种非黑颜色组成的4-连通图形，约4~8像素，形状非4-fold对称以便旋转后可区分方向）。
- 3个灰(5)单色占位对象，每个与源精灵具有相同的归一化掩码（形状相同但颜色为灰(5)）。占位对象间隔至少3格。
- 每个占位对象的正右侧（紧邻包围盒右边界外1列处）有一个3x3的标签区域，标签区域内的像素来自颜色集{蓝(1)、红(2)、绿(3)}，可能全部相同（1种色）、包含两种（2种色）、或包含三种（3种色）。
- 生成约束：3个标签区的不同颜色数互不相同（分别为1、2、3）；源精灵的形状在90度旋转后与原形不同。

**规则**：
1. 识别源精灵（唯一的多色4-连通非灰前景组件）。
2. 识别占位对象（灰(5)单色组件，掩码与源精灵归一化掩码相同）。
3. 对每个占位对象，计算其右侧3x3标签区的不同颜色数 D：
   - D=1 → 不旋转（0度）
   - D=2 → 顺时针旋转90度
   - D=3 → 顺时针旋转180度
4. 将源精灵按对应角度旋转后的颜色图案印到占位对象的位置（覆盖灰色像素）。旋转中心为精灵包围盒中心，旋转后对齐占位对象包围盒的左上角。
5. 擦除源精灵（替换为黑(0)）和所有3x3标签区域（替换为黑(0)）。

**关键洞察**：标签区看似是装饰性元素，实则编码了旋转指令。仅看一个示例可能误以为精灵总是以固定方向被印章——必须对比多个示例才能发现标签区色数与旋转角度的映射关系。

## 新题 7：人字形遮罩下的配对激活列填充

**组合逻辑**：[射线延伸](创新：向下填充不再无条件触发，需额外满足同行配对条件方可激活) + [擦除](已有) ← 同色配对(创新：配对不再触发整行填充，而是作为射线激活的前提条件之一) + [列遮挡](已有)

**来源原语**：
- 射线延伸(ray_cast) / 列遮挡(column_coverage) / 遮挡列延伸至边(covered_col_to_edge) ← 6d58a25d
- 擦除(erase) ← 321b1fc6
- 同色配对(same_color_pairing) / 两端同色整行填充(full_row_fill_endpoints_match) ← 22eb0ac0（创新为配对激活射线）
- 前景对象(foreground_object) / 标记像素(marker_pixel) / 画布边界(canvas_boundary) ← 6d58a25d, 22eb0ac0

**依赖链**：人字形对象定义哪些列有"遮罩" → 散布像素必须同时满足两个独立条件才能激活列填充：(1)所在列被人字形遮罩覆盖；(2)同一行存在另一个同色像素。单独满足任一条件的像素不触发填充。两个条件互不决定，必须同时验证。

在人字形覆盖的列中，仅当某像素在同一行有同色配对时才激活向下的列填充；未配对或不在遮罩列中的像素被擦除。

**输入结构**：
- 约 12x15 的黑(0)背景网格。
- 网格上部有一个橙(7)人字形对象（V形或倒V形），由单色4-连通像素构成，水平跨度覆盖部分但非全部列。
- 人字形下方散布若干孤立像素，颜色来自{蓝(1)、红(2)、绿(3)、黄(4)}。每行0~2个散布像素，各散布像素所在行互不相同（每行至多2个）。
- 部分行恰好有2个散布像素且颜色相同（配对），部分行恰好有2个但颜色不同（不配对），部分行只有1个。
- 散布像素可能在人字形覆盖的列中，也可能不在。
- 生成约束：至少有2个像素同时满足"所在列被人字形覆盖"且"同行有同色配对"；至少有1个像素仅满足其中一个条件（用于验证双条件必要性）。

**规则**：
1. 确定人字形覆盖的列集合：若某列中存在至少一个橙(7)像素，则该列被覆盖。
2. 对每个散布像素 P（非橙(7)、非黑(0)），检查两个条件：
   - 条件A：P 所在列属于人字形覆盖的列集合。
   - 条件B：P 所在行中存在另一个与 P 颜色相同的散布像素。
3. 若条件A和条件B同时满足：从人字形在该列的最低橙(7)像素的下一行开始，向下用 P 的颜色填充该列直到网格底部。若同列有多个同时满足双条件的像素（来自不同行），使用行号最小（最靠上）的那个像素的颜色。
4. 不满足双条件的散布像素从输出中擦除（替换为黑(0)）。
5. 满足双条件的散布像素本身也在输出中擦除（仅作为激活信号，不保留）。
6. 人字形本身保持不变。

**关键洞察**：同行配对和列遮罩是两个完全独立的条件维度——行配对由颜色决定，列遮罩由几何结构决定。仅看一个示例容易误认为"所有被覆盖列的像素都向下填充"或"所有配对像素都向下填充"，只有对比多个示例才能发现双条件缺一不可。

## 新题 8：计数器编码叠加优先级的矩形合并

**组合逻辑**：[透明叠加](创新：叠加时的冲突解决不再要求"标记无冲突"，而是由计数器确定的优先级决定胜出者) + [计数](创新：计数值不再编码空间偏移或半径，而是编码矩形的叠加层级)

**来源原语**：
- 透明叠加(overlay) / 同尺寸对齐(same_size_align) / 标记无冲突合并(markers_merge) ← 25e02866（创新为有冲突的优先级合并）
- 计数(counting) / 计数决定偏移(count_determines_offset) / 计数器消失(counter_disappears) ← e48d4e1a（创新为计数编码优先级）
- 填充矩形(filled_rectangle) / 共享底色(shared_base_color) / 标记像素(marker_pixel) / 计数器像素(counter_pixel) ← 25e02866, e48d4e1a

**依赖链**：识别各同尺寸矩形 → 统计各矩形中灰色像素数量 → 按数量建立优先级排序 → 以优先级解决叠加冲突。计数决定优先级，优先级决定冲突位置的颜色——无法跳过任一步骤。

多个同尺寸填充矩形叠加为一个，标记像素在相同相对位置冲突时由各矩形内灰色计数像素的数量决定优先级。

**输入结构**：
- 约 14x14 的黑(0)背景网格。
- 3~4个相同尺寸（如5x5）的填充矩形，在网格中分散放置、互不重叠。每个矩形有相同的底色青(8)。
- 每个矩形内含有若干非底色的标记像素（颜色来自蓝(1)、红(2)、绿(3)、黄(4)），标记位于矩形内部不同的相对位置。不同矩形的标记像素可能出现在相同的相对位置但颜色不同（冲突位置）。
- 每个矩形的最底行含有0~3个灰(5)像素，用于编码该矩形的优先级。灰像素数量在各矩形间互不相同。
- 生成约束：至少存在2个相对位置处有标记颜色冲突（即不同矩形在该相对位置有不同颜色的标记）。

**规则**：
1. 识别所有同尺寸填充矩形（以底色青(8)的连通矩形区域识别）。
2. 统计每个矩形最底行中灰(5)像素的数量 G。G 值越大优先级越高。
3. 将每个矩形中的灰(5)像素替换为底色青(8)（灰色仅用于编码优先级，不出现在输出中）。
4. 创建一个与矩形尺寸相同的输出矩形，初始填充为底色青(8)。
5. 按优先级从低到高的顺序，依次将每个矩形的非底色标记像素写入输出矩形的对应相对位置。后写入的（优先级更高的）覆盖先写入的。
6. 输出仅为合并后的单个矩形，置于黑(0)背景上（位置为网格左上角对齐）。

**关键洞察**：各矩形表面上完全对称——大小相同、底色相同。但灰色像素数量编码了隐含的"层级"信息，这决定了标记冲突时谁的颜色胜出。不统计灰色像素就无法确定合并结果。
