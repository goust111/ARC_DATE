## 新题 1：通道切割重力

**组合逻辑**：[射线延伸](创新：标记像素发射垂直射线划分通道边界) + [擦除](已有) + [重力下落](已有) + [宽度决定行为](创新：宽度由通道切割产生的碎片宽度决定)

**来源原语**：射线延伸/ray_extend（1190bc91, d07ae81c）、标记像素/marker_pixel（fcb5c309, dd2401ed, e734a0e8）、分隔行/divider_row（84ba50d3）、擦除/erase（456873bc, dd2401ed）、重力下落/gravity_drop（84ba50d3）、宽度决定行为/width_determines_behavior（84ba50d3）、穿透与停靠/pass_through_or_stop（84ba50d3）、射线遮挡分区/ray_partition（1190bc91）

**依赖链**：标记像素发射垂直射线 → 射线划分出纵向通道 → 精灵体被通道边界切割成碎片 → 碎片宽度决定其重力行为（单列碎片穿透分隔行落底、多列碎片停靠在分隔行上方）。射线起源位置间接决定了重力下落的终点——改变任一标记像素的列位置，碎片的宽度和命运都会不同。

标记像素在分隔行上发射垂直射线将网格列分为通道，精灵体被通道边界切分为碎片后，单列碎片穿透分隔行落到底部，多列碎片停靠在分隔行上方。

**输入结构**：
- 约 15x15 黑(0)背景网格
- 红(2)像素组成一条完整的水平分隔行（横跨整行宽度）
- 分隔行上有 2~3 个黄(4)标记像素，占据分隔行中不同列的位置（替换该位置原有的红(2)像素）
- 分隔行上方分布有 2~4 个蓝(1)的 4-连通精灵体（每个 3~8 像素，形态不规则、各不相同），部分精灵体的水平跨度覆盖了某个黄(4)标记像素正上方的列
- 生成约束：精灵体之间互不接触；精灵体不接触分隔行；每个精灵体在切割后至少产生一个单列碎片和一个多列碎片（以确保两种重力行为都被激活）；各碎片的下落路径在列方向上互不冲突

**规则**：
1. 从每个黄(4)标记像素所在列向上发射一条垂直射线，射线覆盖从网格顶行到分隔行上一行的所有行（射线本身不绘制像素，仅作为虚拟通道边界）
2. 虚拟射线将网格的列空间分为若干连续的纵向通道：左边缘到第一条射线为第一通道，两条相邻射线之间为一个通道，最右射线到右边缘为最后一个通道。射线所在列归属于其左侧通道
3. 对每个蓝(1)精灵体，若其像素分布在多个通道中，则沿通道边界将其拆分为独立碎片——每个碎片是原精灵体中属于同一通道的所有像素构成的连通子集
4. 擦除所有原始蓝(1)精灵体像素和黄(4)标记像素（标记位置恢复为红(2)以修复分隔行）
5. 每个碎片独立下落，按以下规则确定终点：
   - 碎片水平跨度为 1 列：穿透红(2)分隔行，下落到该列的网格底行（若同列有先落下的碎片则堆叠在其上方）
   - 碎片水平跨度 > 1 列：下落到分隔行正上方（碎片最底行像素紧贴分隔行上一行；若上方有先落下的碎片则堆叠在其上方）
6. 碎片处理顺序：按碎片最底行像素的行号从大到小处理（靠近分隔行的先落）；若行号相同，按最左列从小到大处理
7. 碎片下落时保持内部像素的相对位置不变，整体平移

**关键洞察**：标记像素并不直接参与重力运算——它们是隐式的"切割刀"，通过射线间接决定碎片的宽度，从而改变碎片的重力命运。求解者必须先从标记像素推断通道边界，再模拟切割，最后才能确定各碎片的行为。

## 新题 2：连接杆编码周期平铺

**组合逻辑**：[擦除](已有) + [平铺](创新：平铺方向由连接杆几何结构编码) + [周期内指定位变色](创新：变色周期由连接杆长度编码)

**来源原语**：连接杆/connector_stem（98cf29f8）、擦除/erase（98cf29f8）、平铺/tiling（e8dc4411）、指示决定方向色/indicator_dir_color（e8dc4411）、邻接触碰/adjacency_touch（e8dc4411）、周期排布/periodic_layout（d304284e）、周期内指定位变色/cyclic_pos_recolored（d304284e）

**依赖链**：连接杆方向 → 决定平铺延伸方向；连接杆长度 → 决定重涂色的周期间隔；杆末端标记颜色 → 决定变色目标色。三个参数全部从同一个几何结构中提取，形成紧密的信息编码关系。

每个精灵体的连接杆方向决定平铺延伸方向，连接杆长度 L 决定周期——每连续 L 个副本中最后一个被重涂为杆末端标记的颜色。

**输入结构**：
- 约 20x20 黑(0)背景网格
- 2~3 个不同颜色的精灵体，每个为 4-连通单色前景对象（3~6 像素，非矩形非对称），颜色各不相同（如蓝(1)、绿(3)）
- 每个精灵体有一条同色的单像素宽直线连接杆（长度 2~4 像素）沿某个正方向（上/下/左/右）延伸
- 每条连接杆的远端（远离精灵体的末端像素）紧邻一个不同颜色的单像素标记（标记与杆末端 4-邻域接触），各标记颜色互不相同且与精灵体颜色不同（如红(2)、黄(4)）
- 生成约束：各精灵体沿其杆方向的平铺路径互不交叉（边界框投影不重叠）；精灵体分布在网格的不同区域；至少有一个精灵体的杆方向不是向下

**规则**：
1. 对每个精灵体，识别其连接杆：从精灵体边缘沿某正方向延伸的同色单像素宽直线段。杆的方向即为平铺方向，杆的长度 L 为杆像素数（不含精灵体本体像素，不含末端标记像素）
2. 记录杆末端紧邻的单像素标记的颜色，作为该精灵体的变色目标色
3. 擦除所有连接杆像素和末端标记像素（精灵体本体保留）
4. 沿连接杆方向，以精灵体边界框在该方向的尺寸 + 1 为步幅，从精灵体的相邻位置开始，依次放置精灵体的副本，直到副本完全超出网格边缘（部分超出的副本保留网格内部分，裁剪掉超出部分）
5. 将原始精灵体视为序列中的第 1 号元素。副本依次编号为 2, 3, 4, ...。在每组连续 L 个元素中，编号为 L 的倍数的元素被重涂为该精灵体的变色目标色，其余保持原色
6. 不同精灵体的平铺序列若发生像素重叠（因生成约束此情况不会出现，仅作保险规则），按精灵体边界框左上角的行优先、列次优先排序，靠后的覆盖靠前的

**关键洞察**：连接杆在源题中是滑动路径（编码距离和方向以供物体平移），但在本题中被重新诠释为参数编码器——同一根杆同时编码了"往哪铺"（方向）和"每几个变色"（长度=周期），两个参数从同一个几何结构中提取。求解者必须意识到杆的长度不是无关细节而是关键参数。

## 新题 3：对称补全驱动计数蛇形摘要

**组合逻辑**：[对称补全](已有) + [计数](创新：计数对象是补全后的像素而非原始像素) + [排序](已有) + [蛇形填充](已有)

**来源原语**：对称补全/symmetry_completion（929ab4e9）、八重对称轨道/eightfold_orbit（929ab4e9）、轨道内唯一可见色/unique_color_in_orbit（929ab4e9）、遮罩像素/mask_pixel（929ab4e9）、计数/counting（5289ad53）、分类计数/categorical_count（5289ad53）、排序/sort（cdecee7f）、蛇形填充/boustrophedon_fill（cdecee7f）、奇行反序/odd_row_reversed（cdecee7f）

**依赖链**：遮罩像素隐藏了部分前景 → 对称补全恢复被遮罩的像素 → 恢复的像素改变了各颜色的计数结果 → 按补全后的计数排序颜色 → 以蛇形顺序将排序后的颜色填入摘要网格。若跳过补全直接计数，结果会不同。

先用八重对称补全恢复被遮罩的像素，再统计各前景色的像素数并按降序排列，以蛇形顺序将每种颜色按其计数填入 3x3 摘要网格。

**输入结构**：
- 一个正方形网格（边长 9 或 11，为奇数），黑(0)背景
- 恰好 3 种非黑前景色（从蓝(1)、红(2)、绿(3)、黄(4)中选取）形成具有八重对称性的图案（关于水平轴、垂直轴、主对角线、副对角线均对称）
- 灰(5)作为遮罩色，覆盖了若干本应有前景色的位置（将原有前景色替换为灰(5)）
- 忽略灰(5)后，每个八重对称轨道中至少有一个非黑(0)非灰(5)的可见像素
- 生成约束：补全后 3 种前景色的像素数两两不同，且三者之和恰好为 9；至少一种颜色的补全前可见计数与补全后计数不同（即遮罩确实隐藏了某些颜色的像素）

**规则**：
1. 识别灰(5)为遮罩色
2. 对每个灰(5)像素，计算其在正方形的八重对称群下的完整轨道（恒等、90/180/270度旋转、水平/垂直/主对角/副对角反射，共 8 个变换，去重后得到轨道）
3. 在该轨道的所有位置中找到唯一的非黑(0)非灰(5)颜色，将该灰(5)像素替换为此颜色
4. 补全完成后，统计每种非黑前景色的总像素数
5. 按像素数从多到少排序 3 种颜色（生成约束保证无并列）
6. 创建 3x3 黑(0)输出网格
7. 按排序顺序依次填入各颜色：第一种颜色填入其像素数个格子，紧接着第二种颜色填入其像素数个格子，最后第三种颜色填入剩余格子。填充路径为蛇形——第 0 行从左到右，第 1 行从右到左，第 2 行从左到右

**关键洞察**：遮罩不是均匀覆盖各颜色的——某些颜色被遮罩的比例更高，导致补全前后该颜色的排名发生变化。求解者如果直接统计可见像素会得到错误的排序，必须先完成对称补全才能获得正确计数。

## 新题 4：最大框裁剪后内部空轴镜像

**组合逻辑**：[裁剪](已有) + [全空行列检测](创新：空白行列不用于涂色而用于确定镜像轴) + [镜像](创新：镜像轴由裁剪内容的结构隐式确定) + [异常值选择](已有)

**来源原语**：裁剪/crop（fcb5c309）、矩形框架/rect_frame（fcb5c309）、面积最大选取/largest_area_select（fcb5c309）、最大框决定裁切/largest_frame_crops（fcb5c309）、全空行列检测/detect_empty_row_col（da2b0fe3）、包围框内部/inside_bbox（da2b0fe3）、镜像/mirror（6fa7a44f, ad3b40cf）、沿轴反射/reflect_along_axis（ad3b40cf）、最少像素颜色/min_pixel_color（ad3b40cf）、异常值选择/outlier_selection（ad3b40cf）

**依赖链**：面积最大选取 → 确定裁剪目标框架；裁剪 → 获得框内内容；全空行列检测 → 在框内内容中找到镜像轴；异常值选择 → 确定被镜像的颜色。四个判据交汇在最终的镜像操作上：框选什么、轴在哪里、镜像什么颜色分别由不同的检测步骤决定。

裁剪面积最大的矩形框的内容后，框内唯一的全空行或列成为镜像轴，将其中像素数最少的前景色沿该轴反射到对侧。

**输入结构**：
- 约 16x18 黑(0)背景网格
- 灰(5)像素组成 2~3 个完整的单像素厚闭合矩形框架（每个框架是一个矩形的四条边）
- 面积最大的框架（按框架围成的内部面积计算）内部有两种前景色的不规则像素分布：蓝(1)和红(2)的 4-连通小对象（每种颜色 1~3 个对象，每个对象 2~5 像素）
- 该最大框架内部恰好有一条完全为黑(0)的行或列（不含灰(5)框架边框本身），将内部空间分为两半
- 蓝(1)和红(2)的像素总数不同（其中一种明显少于另一种，少的那种像素数不超过 4）
- 较小的框架内部可能有散落的前景像素，也可能为全空
- 生成约束：最大框架的内部面积严格大于所有其他框架（唯一最大）；最大框架内部恰好有一条全空行或全空列（不多不少）

**规则**：
1. 识别灰(5)构成的所有矩形框架，计算每个框架的内部面积（框架围成的矩形去掉边框后的行数 x 列数）
2. 选取内部面积唯一最大的框架
3. 裁剪该框架的边界框（包含灰(5)边框），作为输出的基础画布
4. 在画布中，检测框架内部（不含灰(5)边框行列）是否存在完全为黑(0)的行或列；找到唯一的那条，作为反射轴
5. 在框架内部的两种前景色（蓝(1)和红(2)）中，选取像素总数较少的颜色作为待反射色
6. 将待反射色的每个像素关于反射轴做镜像：若轴是水平的（某一行），像素 (r, c) 映射到 (2*axis_row - r, c)；若轴是垂直的（某一列），像素 (r, c) 映射到 (r, 2*axis_col - c)
7. 在镜像位置绘制待反射色的像素；若镜像位置已有非黑像素，保留原有像素不覆盖
8. 输出为裁剪后的画布（仅最大框架的边界框区域）

**关键洞察**：三个独立的选择机制（面积最大 → 选框、全空行列 → 定轴、最少像素 → 选色）必须全部正确才能得到正确输出。求解者在第一个示例中可能猜对其中一两个，但需要对比多个示例（不同框架大小排列、不同轴方向、不同颜色数量关系）才能归纳出全部三个选择规则。

## 新题 5：沿杆滑动后对角射线受锚定物阻挡

**组合逻辑**：[滑动](已有) + [擦除](已有) + [射线延伸](创新：射线起点由滑动终点决定) + [重涂色](创新：射线经过的标记像素变色) + [碰撞阻挡](创新：锚定物既是滑动目标又是射线挡板)

**来源原语**：滑动/slide（98cf29f8）、连接杆/connector_stem（98cf29f8）、锚定物/anchor_object（98cf29f8）、沿杆滑至锚定物/slide_stem_to_anchor（98cf29f8）、擦除/erase（98cf29f8）、碰撞阻挡/collision_blocking（98cf29f8）、射线延伸/ray_extend（1190bc91, d07ae81c）、对角线激活/diagonal_activation（d07ae81c）、标记像素/marker_pixel（fcb5c309, d07ae81c）、重涂色/recolor（d07ae81c）

**依赖链**：精灵体沿连接杆滑动至锚定物旁（滑动终点由杆长度决定）→ 从终点位置的每个精灵像素发射对角射线 → 锚定物作为射线挡板截断射线 → 射线路径上的标记像素被激活变色。锚定物扮演双重角色——既决定滑动的目的地，又限制射线的传播范围。

将带连接杆的精灵体沿杆滑动到锚定物旁，然后从精灵体的最终位置发射四方向对角射线，射线被锚定物阻挡截止，路径上经过的标记像素被重涂为黄(4)。

**输入结构**：
- 约 18x18 黑(0)背景网格
- 一个红(2)的实心矩形锚定物（约 2x3 到 3x4，形状为矩形）
- 一个蓝(1)的 4-连通精灵体（3~5 像素，非矩形），通过一条蓝(1)的单像素宽直线连接杆（长度 2~5 像素）沿某个正方向（上/下/左/右）延伸，杆的延伸方向指向锚定物
- 4~6 个绿(3)的单像素标记散布在网格各处（不在精灵体、连接杆或锚定物上）
- 生成约束：精灵体沿杆方向平移杆长度后，精灵体边缘恰好与锚定物边缘相邻（间距 1 像素或紧贴）；精灵体滑动后不超出网格边界；至少 2 个绿(3)标记位于滑动后精灵体的对角射线路径上且未被锚定物阻挡

**规则**：
1. 识别红(2)矩形锚定物、蓝(1)精灵体和蓝(1)连接杆、绿(3)标记像素
2. 确定连接杆方向（从精灵体向杆延伸的方向）和长度 L（杆的像素数，不含精灵体像素）
3. 擦除蓝(1)精灵体和连接杆的所有像素（恢复为黑(0)）
4. 将精灵体沿连接杆方向平移 L 个像素，在新位置绘制蓝(1)精灵体
5. 从滑动后精灵体的每个像素位置，发射四条 45 度对角射线（NE、NW、SE、SW 方向），逐像素延伸
6. 射线遇到以下情况停止（不含停止点本身）：红(2)锚定物像素、蓝(1)精灵体自身像素（其他起点的射线已绘制的不算）、网格边缘
7. 射线经过的每个黑(0)背景像素重涂为蓝(1)
8. 射线经过绿(3)标记像素时，将该标记像素重涂为黄(4)，射线不停止继续前进
9. 锚定物保持红(2)不变；未被射线经过的绿(3)标记保持不变

**关键洞察**：锚定物同时扮演两个完全不同的几何角色——作为滑动的目标体（决定精灵体落在哪里），又作为射线的遮挡体（决定射线能照到哪里）。锚定物的形状和位置通过这两个角色间接决定了哪些标记像素会被激活，形成了不可拆分的三体耦合（精灵体位置、锚定物形状、标记像素分布）。

## 新题 6：双镜像约束下的旋转匹配放置

**组合逻辑**：[旋转](已有) + [镜像](创新：锚点同时约束原像和镜像两个放置位置) + [形状匹配](已有) + [稀疏像素引导放置](创新：部分锚点属于原像、部分属于镜像，事先不可区分)

**来源原语**：旋转/rotate（0e206a2e）、镜像/mirror（6fa7a44f, ad3b40cf）、形状匹配/shape_matching（1caeab9d）、颜色一致对齐/color_consistent_align（0e206a2e）、稀疏像素引导放置/sparse_pixels_guide_placement（0e206a2e）、翻转后拼接/flip_append（6fa7a44f）、沿轴反射/reflect_along_axis（ad3b40cf）

**依赖链**：稀疏锚点像素同时约束精灵体原像（上半区）和镜像（下半区）的位置和颜色 → 求解者无法事先区分哪些锚点属于原像、哪些属于镜像 → 必须同时搜索旋转变体和放置位置使原像+镜像一起覆盖所有锚点 → 这是一个同时约束满足问题而非线性流水线。

从 8 种旋转/翻转变体中找到唯一一种，使精灵体放在上半区、其上下镜像放在下半区对称位置后，两者合计覆盖所有散布的锚点像素且颜色完全一致。

**输入结构**：
- 约 12x16（宽 x 高）黑(0)背景网格，高度为偶数
- 一个多色精灵体（由蓝(1)和红(2)像素组成，4-连通，约 6~10 像素，非对称——8 种旋转/翻转变体两两不同），位于网格的某个角落区域
- 6~10 个散布的单像素锚点（颜色为蓝(1)或红(2)），分布在网格的上半区（行 0 到行 height/2-1）和下半区（行 height/2 到行 height-1）
- 网格的水平中线（行 height/2 的位置）是隐含的镜像轴
- 生成约束：恰好只有一个旋转/翻转变体和一个上半区放置位置满足以下条件——将该变体放在上半区该位置后，其关于水平中线的上下镜像放在下半区对称位置，两个放置合计的所有前景像素与全部锚点像素在位置和颜色上完全一致（锚点不多不少恰好被覆盖）；精灵体原像和镜像不跨越中线，不与角落的原始精灵体重叠

**规则**：
1. 分离精灵体（最大多色连通对象）和单像素锚点（孤立的蓝(1)或红(2)像素）
2. 确定网格高度 H，水平中线轴位于行 H/2（中线本身不属于上半区或下半区，但若 H 为偶数则中线在行 H/2 和行 H/2-1 之间）
3. 生成精灵体的 8 种变体（0/90/180/270 度旋转，每种可选是否左右翻转）
4. 对每种变体和上半区的每个可能放置位置（变体完全位于行 0 到行 H/2-1 内）：
   a. 在该位置放置变体
   b. 将变体关于水平中线做上下镜像，计算镜像位置（每个像素 (r, c) 映射到 (H-1-r, c)）
   c. 检查：原像和镜像的所有前景像素的位置和颜色集合是否与所有锚点像素的位置和颜色集合完全相同
5. 选择唯一满足条件的变体和位置
6. 擦除原始精灵体（角落区域的）和所有锚点像素
7. 在确定的位置绘制变体原像（蓝(1)和红(2)像素），在镜像位置绘制上下镜像
8. 原像和镜像不会重叠（生成约束保证）

**关键洞察**：锚点中有些属于上半区的原像、有些属于下半区的镜像，但求解者无法事先判断哪些是哪些。仅看上半区的锚点可能存在多个旋转变体都能匹配，加入下半区锚点的约束后才收敛到唯一解。这迫使求解者将旋转搜索和镜像约束作为一个整体问题同时求解，而非分步执行。

## 新题 7：指示方向平铺后全局重力堆叠

**组合逻辑**：[平铺](已有) + [重力下落](创新：对平铺完成后的全部副本施加重力) + [碰撞阻挡](创新：不同方向平铺产生的副本在重力下互相碰撞堆叠) + [指示决定方向色](已有)

**来源原语**：平铺/tiling（e8dc4411）、指示像素/indicator_pixel（e8dc4411）、邻接触碰/adjacency_touch（e8dc4411）、指示决定方向色/indicator_dir_color（e8dc4411）、重力下落/gravity_drop（84ba50d3）、碰撞阻挡/collision_blocking（98cf29f8）、穿透与停靠/pass_through_or_stop（84ba50d3）

**依赖链**：指示像素方向 → 决定各方向的平铺路径 → 平铺产生多方向的彩色副本 → 全局重力将所有副本（含原始模板）向下拉 → 不同颜色的副本在下落中碰撞堆叠。平铺的空间布局决定了重力后的堆叠形态，而堆叠结果与任何单一平铺方向的输出都不同。

将黑色模板沿各指示像素方向平铺并着色后，对全部副本施加向下重力，副本之间碰撞堆叠形成最终布局。

**输入结构**：
- 约 18x18 灰(5)背景网格
- 一个黑(0)的 4-连通模板对象（约 3x3 边界框，3~6 像素，非矩形），位于网格上半区
- 2~3 个单像素指示对象紧邻模板边界（与模板的某个像素 4-邻域接触），颜色各不相同且非灰(5)非黑(0)（如红(2)、蓝(1)、绿(3)）
- 生成约束：至少一个指示像素指向上方或水平方向（使平铺后存在"悬空"的副本需要重力下落）；各方向的平铺副本的边界框列范围可以重叠（以产生碰撞堆叠）

**规则**：
1. 识别灰(5)背景、黑(0)模板对象和紧邻模板的单像素指示对象
2. 对每个指示像素，确定其相对于模板的方向（从模板中心指向指示像素的方向：上/下/左/右，取最近的正方向）和颜色
3. 擦除所有指示像素（恢复为灰(5)背景）
4. 沿每个指示方向，以模板边界框在该方向的尺寸 + 1 为步幅，从模板相邻位置开始放置副本。副本使用对应指示像素的颜色（非黑(0)），直到副本完全超出网格边缘（部分超出者保留网格内部分）
5. 原始黑(0)模板保持不变
6. 对全部非灰(5)像素（包括黑(0)模板像素和所有彩色副本像素）施加向下重力：每个非灰像素在其所在列独立下落，落到网格底行或落到该列已堆积的非灰像素上方时停止
7. 同一列中多个像素的下落顺序：从最底行的像素开始处理，依次向上（自然重力堆积顺序）
8. 像素颜色在下落过程中保持不变

**关键洞察**：向上和向左/向右方向的平铺副本在重力作用下会向下坠落并与向下方向的副本碰撞堆叠，形成一个非直觉的最终布局。求解者不能只看平铺结果或只看重力结果——必须先完成平铺再施加重力，两步不可分割。尤其是向上平铺的副本反而最终可能落在最下方（经过最长距离的下落），而向下平铺的副本已在底部附近保持不动。

## 新题 8：双框角色分配——模板印章入最大空矩形

**依赖链**：识别两个框架并判断角色（大框→画布，小框→模板）→ 裁剪大框内容作为画布 → 裁剪小框内容提取模板 → 在画布中搜索最大全空矩形 → 将模板印章到该空矩形的左上角。印章位置不由标记像素指定，而由画布自身的空白结构隐式决定。

- 大框架（内部约 8x8 到 10x10）内有红(2)的不规则前景图案（多个 4-连通对象，每个 3~6 像素），图案之间和周围存在黑(0)空白区域
- 小框架（内部约 3x3 到 4x4）内有蓝(1)的紧凑图案（一个 4-连通对象，3~6 像素），作为模板
- 生成约束：大框架内部面积严格大于小框架内部面积；大框架内部的唯一最大全黑矩形（边长至少为 2）的尺寸大于等于小框架模板的边界框尺寸；该最大全黑矩形面积唯一（无并列）

**规则**：
1. 识别灰(5)构成的两个矩形框架
2. 按框架内部面积（不含边框）区分大框架和小框架

8. 在对齐位置印章模板：模板中蓝(1)像素覆盖画布对应位置（无论该位置原为何色），模板中黑(0)像素不覆盖
9. 输出为修改后的画布

**关键洞察**：两个框架外观相似（都是灰(5)矩形边框），但扮演完全不同的角色——一个提供画布，另一个提供印章。求解者必须从面积大小推断角色分工，并进一步理解印章位置不是由标记指定的，而是由画布自身的空白结构（最大空矩形）隐式决定——这与源题中标记像素直接指定放置位置的机制完全不同。

## 新题 9：重叠框架遮挡深度推断

**组合逻辑**：[搜索](创新：从不完整的可见边缘反推完整矩形框架) + [排序](创新：排序依据是从重叠遮挡关系中推断的深度序) + [压缩](已有) + [处理顺序决定遮挡](创新：可见层级反映绘制顺序的逆序)

**来源原语**：裁剪/crop（fcb5c309）、矩形框架/rect_frame（fcb5c309）、排序/sort（cdecee7f）、压缩/compress（cdecee7f）、碰撞阻挡/collision_blocking（98cf29f8）、处理顺序决定遮挡/order_determines_block（1190bc91）、面积最大选取/largest_area_select（fcb5c309）

**依赖链**：识别各颜色构成的（可能不完整的）矩形框架 → 在框架重叠区域判断哪种颜色遮挡了哪种颜色 → 从成对遮挡关系构建全局深度排序 → 按从前到后顺序输出颜色序列。这是一个结构解构问题——输入是多个结构叠加后的混合体，求解者需要分离并推断交互规则。

从相互重叠的彩色矩形框中推断各框架的前后遮挡顺序，按从最前层到最后层的深度序输出一行颜色条。

**输入结构**：
- 约 14x14 黑(0)背景网格
- 3~4 种不同前景色（如红(2)、绿(3)、蓝(1)、黄(4)）各自构成一个单像素厚的闭合矩形框架
- 各框架大小不同（约 4x4 到 9x9），在网格中互有重叠
- 重叠处仅显示遮挡顺序中更靠前（更上层）框架的颜色，被遮挡的像素不可见（显示为黑(0)背景或被上层颜色替代）
- 框架的遮挡顺序是一个全序（无循环遮挡：不存在 A 挡 B、B 挡 C、C 挡 A 的情况）
- 生成约束：每对相邻深度层级的框架至少有一段边发生重叠（使求解者可以从可见信息推断出完整的遮挡顺序）；最前层框架完全可见（所有四条边完整）；至少有一个框架被遮挡了一条以上的边段

**规则**：
1. 识别每种前景色的所有可见像素。从可见像素和被遮挡的缺口推断每种颜色原本构成的完整矩形框架的位置和大小（框架是闭合矩形边框，缺失的像素被上层框架遮挡）
2. 对每对颜色 A 和 B，检查它们的完整框架在网格上是否有重叠位置。若某个重叠位置上显示的是颜色 A 而颜色 B 的框架边也应通过此处但不可见，则 A 在 B 前面（A 遮挡 B）
3. 对所有成对遮挡关系做拓扑排序，得到从前到后的完整深度排序
4. 创建 1 行 K 列的输出网格（K = 框架数），从左到右依次填入从最前层到最后层框架的颜色

**关键洞察**：最前层框架的所有边都完整可见，容易识别。但内层框架的部分边被遮挡，求解者必须从残余可见边段推断完整的矩形几何（利用矩形框架的结构约束：四条边、直角），然后才能判断哪些位置是"应有但被遮挡"的。遮挡关系的推断依赖于框架重建，而框架重建又受到遮挡的干扰——两者需要迭代求解。

## 新题 10：对角偏移平铺中的晶格坐标标记

**组合逻辑**：[对角偏移重复](已有) + [标记](创新：每个副本内的标记位置由晶格坐标决定) + [尺寸决定步幅](已有) + [局部对应晶格坐标](创新：从全局晶格坐标映射到局部像素坐标)

**来源原语**：对角偏移重复/diag_offset_repeat（e619ca6e）、尺寸决定步幅/size_determines_stride（e619ca6e）、实心矩形/solid_rect（e619ca6e）、裁剪/clip（e619ca6e）、自相似晶格映射/self_similar_lattice_mapping（456873bc）、局部对应晶格坐标/local_maps_lattice_coord（456873bc）、标记/mark（456873bc）、重涂色/recolor（456873bc）

**依赖链**：矩形尺寸决定对角偏移步幅 → 沿两个向下对角方向放置副本 → 每个副本在对角晶格中获得一个坐标 (i, j) → 坐标通过取模映射到副本内部的一个像素位置 → 该像素被标记为另一种颜色。每个副本外观几乎相同但内部各有一个独特的标记点，标记位置编码了其全局晶格坐标。

将实心矩形沿两个向下对角方向按自身尺寸为步幅重复放置，每个副本内标记一个像素——标记位置是该副本在对角晶格中的坐标对矩形尺寸取模后的内部像素。

**输入结构**：
- 约 20x20 黑(0)背景网格
- 一个红(2)实心矩形（高 h 行 x 宽 w 列，约 3x3 到 4x4）
- 矩形内恰好有一个像素被涂为青(8)，位于矩形内部的第 0 行第 0 列（即左上角，表示原始矩形的晶格坐标 (0,0)）
- 矩形位于网格中偏上偏中的位置，使得至少向两个对角方向各能放置 2 个完整或部分副本
- 生成约束：h 和 w 均至少为 3（以确保取模映射不退化）

**规则**：
1. 识别红(2)实心矩形及其内部的青(8)标记像素，确定矩形的高 h 和宽 w
2. 将原始矩形的晶格坐标定义为 (0, 0)
3. 沿向下-左对角方向，以步幅 (h, -w) 放置副本，依次编号为 (1, -1), (2, -2), ...；直到副本完全超出网格（部分超出者保留网格内部分并裁剪）
4. 沿向下-右对角方向，以步幅 (h, w) 放置副本，依次编号为 (1, 1), (2, 2), ...；同样裁剪和停止
5. 每个副本（包括原始矩形）全部绘制为红(2)实心矩形
6. 对每个副本，取其晶格坐标 (i, j)，计算内部标记位置：标记行 = |i| mod h，标记列 = |j| mod w
7. 将该副本内部第（标记行）行第（标记列）列的像素从红(2)重涂为青(8)
8. 若副本被裁剪导致标记位置不在网格内，则该副本没有可见标记

**关键洞察**：每个副本看起来几乎相同（都是红色实心矩形），但内部各有一个独特的青色标记点。标记点的位置不是随机的——它系统性地编码了该副本在全局对角晶格中的坐标。求解者必须发现晶格坐标到局部像素坐标的取模映射关系，而这种映射只有在对比多个副本的标记位置后才能归纳得出。
