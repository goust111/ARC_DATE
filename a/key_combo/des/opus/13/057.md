## 新题 1：掏空即通道——路径穿越实心矩形

**组合逻辑**：[路径生长](创新：遇障碍不偏转而是穿透掏空后的内腔) + [掏空](创新：由路径碰撞动态触发，非预设全部掏空) + [重涂色](创新：穿越事件触发路径后续颜色转变)

**来源原语**：路径生长(path_grow)、控制像素(control_pixel)、底行起始(bottom_row_origin) ← #1 712bf12e；掏空(hollowing)、实心矩形(solid_rectangle)、保留边擦除内部(keep_border_erase_interior) ← #7 4347f46a；重涂色(recolor) ← #4 36fdfd69

**依赖链**：路径生长决定哪些矩形被碰撞 → 碰撞触发掏空，打通矩形内腔形成通道 → 穿越矩形事件使路径后续段变色 → 先处理的路径掏空矩形后，后续路径若碰到同一矩形的边框（已掏空，无法再次穿透）则停止，因此处理顺序产生路径间的竞争依赖

控制像素向上生长的路径穿透并掏空所遇的实心矩形，穿越后路径变色为红(2)；已被掏空的矩形边框会阻断后续路径。

**输入结构**：
- 黑(0)背景网格，约 15x20。
- 底行（最后一行）包含 2~4 个控制像素，颜色各不相同，取自蓝(1)、绿(3)、teal(8)中不重复选取。各控制像素不在同一列。
- 底行上方散布 3~5 个实心灰(5)矩形，每个至少 3 行 x 3 列（确保有严格内部）。矩形之间互不重叠、互不相邻（间距至少 1 个黑像素），且不接触底行。
- 生成约束：每个控制像素的正上方列范围内至少存在一个灰矩形可被碰撞；不同控制像素可能碰撞不同矩形，也可能有两个控制像素的列穿过同一个矩形。

**规则**：
1. 按列坐标从左到右的顺序逐一处理各控制像素。
2. 对当前控制像素 (r_bottom, c)，令当前路径颜色 = 该控制像素的颜色，从 (r_bottom - 1, c) 开始逐步向上生长：
   - 2a. 若上方单元格为黑(0)（背景），将其涂为当前路径颜色，继续向上一步。
   - 2b. 若上方单元格为灰(5)且属于一个**尚未被掏空**的实心矩形：
     - 对该矩形执行掏空：保留其 1 像素厚的灰(5)边框，将严格内部全部设为黑(0)。
     - 路径从该矩形底边框进入，穿过刚清空的内部（沿当前列垂直向上，将内部的每个黑像素涂为当前路径颜色），从顶边框穿出。边框像素本身保持灰(5)不被路径涂色。
     - 穿出顶边框后（即顶边框上方一个单元格起），当前路径颜色切换为红(2)。后续所有步骤使用红(2)。
   - 2c. 若上方单元格为灰(5)且属于一个**已被掏空**的矩形的边框，路径停止（无法二次穿透）。
   - 2d. 若上方单元格超出网格上边界，路径停止。
   - 2e. 若上方单元格为非黑、非灰的其他颜色（即另一条路径已涂过的像素），路径停止。
3. 所有路径处理完毕后的网格即为输出。

**关键洞察**：掏空不是预先对所有矩形执行，而是由路径碰撞按需触发；同一矩形只能被第一条碰到它的路径穿透，之后变为不可穿透的空心边框。因此路径的左右处理顺序直接决定哪条路径能穿越、哪条被阻断。

## 新题 2：屏障邻域计数决定重涂色

**组合逻辑**：[计数](创新：不是全局背景区域计数，而是逐屏障统计其邻接的不同背景区域数) + [重涂色](创新：重涂依据为局部邻域区域数而非全局序号或位置) + [连通分量](创新：连通分量分析同时服务于区域识别和邻域计数两步)

**来源原语**：计数(counting)、背景区域(bg_region)、连通分量(connected_component)、前景屏障(fg_barrier)、区域数编码像素列(region_count_as_col) ← #12 e872b94a；重涂色(recolor)、按位置排序(sort_by_position) ← #15 22a4bbc2；邻接传色(adjacency_color_transfer) ← #17 800d221b（创新改造：由传色变为计数决定色）

**依赖链**：前景屏障分割背景为多个 4-连通区域 → 对每段屏障（4-连通前景分量），统计其像素 4-邻域中出现了几个不同的背景区域 → 该邻域区域数映射为目标颜色 → 逐段屏障按映射重涂

将每段前景屏障根据它所分隔（邻接）的不同背景区域数量重涂为不同颜色。

**输入结构**：
- 黑(0)背景网格，约 12x12。
- 前景为灰(5)像素，形成若干不规则的薄型屏障（宽度 1 像素的路径状连通分量，长度 3~10 像素），共 4~6 段互不相连的 4-连通屏障。
- 屏障将黑(0)背景分割为多个 4-连通的背景区域（至少 3 个区域）。
- 生成约束：存在至少一段屏障仅邻接 1 个背景区域（如一段"死胡同"式屏障伸入一个大区域内部），至少一段邻接 2 个，至少一段邻接 3 个或更多。不同的邻接数在多个示例中对应一致的颜色。

**规则**：
1. 识别所有 4-连通的黑(0)背景区域，为每个区域分配唯一 ID。
2. 识别所有 4-连通的灰(5)前景屏障分量。
3. 对每段屏障，收集其所有像素的 4-邻域中出现的所有不同背景区域 ID，去重后计数，得到该屏障的"邻域区域数" K。
4. 按以下映射重涂该屏障的所有像素：
   - K = 1 → 蓝(1)
   - K = 2 → 红(2)
   - K >= 3 → 黄(4)
5. 背景像素保持黑(0)不变。

**关键洞察**：全局背景区域总数是干扰信息——决定每段屏障颜色的不是全局有多少区域，而是该段屏障自身邻接了几个不同区域。一段看似重要的长屏障如果两侧属于同一个区域（如 U 形包围），它的邻域区域数可能仅为 1。颜色映射规则（1→蓝、2→红、3+→黄）需要对比多个示例才能归纳。

## 新题 3：碎片合并后按面积分支处理

**组合逻辑**：[补全/合并对齐碎片](已有) + [掏空](创新：仅对面积达标的合并矩形执行) + [重涂色](创新：仅对面积不达标的合并矩形执行) → 面积阈值驱动操作分支

**来源原语**：补全(complete)、合并对齐碎片(merge_aligned_fragments)、残缺矩形(fragmented_rectangle)、连通分量(connected_component)、行列跨度重叠(span_overlap) ← #10 8fbca751；掏空(hollowing)、保留边擦除内部(keep_border_erase_interior) ← #7 4347f46a；重涂色(recolor) ← #4 36fdfd69

**依赖链**：碎片合并确定每个完整矩形的边界 → 矩形面积（行数 x 列数）作为分支判断依据 → 面积 >= 9 的矩形执行掏空（边框保留原色，内部涂黄(4)） → 面积 < 9 的矩形整体填充为红(2) → 两种后续操作使用不同颜色，且掏空操作本身要求矩形足够大才有"内部"可掏

将分散的前景碎片按行列跨度重叠规则合并为完整矩形后，大矩形掏空为黄(4)内腔边框，小矩形整体填充为红(2)。

**输入结构**：
- 黑(0)背景网格，约 15x15。
- 前景为 teal(8) 像素，分布为若干不规则碎片（每个碎片是 4-连通的 teal 像素团，3~8 像素不等）。
- 碎片属于 3~5 个不同的"隐含矩形"：同一矩形的碎片分布在该矩形边界框的角落或边缘附近，碎片之间可能不 4-连通但边界框在行跨度或列跨度上重叠。
- 不同矩形的碎片边界框在行跨度和列跨度上均不重叠（即可通过传递合并完全区分不同矩形）。
- 生成约束：合并后的矩形中至少有一个面积 >= 9（即至少 3x3），至少有一个面积 < 9（如 2x3 = 6）。所有矩形面积不等，以避免歧义。

**规则**：
1. 找到所有 4-连通的 teal(8) 碎片。
2. 传递合并边界框在行跨度或列跨度上有重叠的碎片组（与参考题 #10 相同的合并逻辑）。
3. 对每个合并组，计算其包含边界框的面积 S = 高 x 宽。
4. 若 S >= 9：
   - 将边界框的 1 像素厚边框涂为 teal(8)（保留原色）。
   - 将严格内部全部涂为黄(4)。
5. 若 S < 9：
   - 将边界框内所有像素（含边框）涂为红(2)。
6. 边界框外的黑(0)背景不变。

**关键洞察**：同样的合并逻辑产生的矩形，因面积不同而走向完全不同的处理分支。面积阈值 9 本身需要从多个示例中归纳（观察哪些矩形被掏空、哪些被填实），而不能仅从单一示例确定。

## 新题 4：连线长度排序决定叠加层序

**组合逻辑**：[连线/直角路径](已有) + [排序](创新：排序键为路径曼哈顿长度而非空间位置) + [透明叠加/前后遮挡](创新：遮挡层序由计算属性——路径长度——决定，而非面板位置)

**来源原语**：连线(draw_line)、直角路径(right_angle_path)、端点像素(endpoint_pixel)、行列交汇(row_col_intersection)、拐角由终点列定(corner_at_target_col) ← #20 d4a91cb9；排序(sort)、距离优先排序(distance_priority_ordering) ← #6 b5ca7ac4；透明叠加(transparent_overlay)、前后遮挡(front_back_occlusion) ← #19 cf98881b

**依赖链**：端点配对确定各条路径 → 直角连线生成 L 形路径 → 各路径的曼哈顿长度成为可计算属性 → 按长度排序决定绘制层序（长的先画，短的后画覆盖） → 交叉处的最终颜色由最短路径决定

用直角路径连接各对同色端点后，按路径长度从长到短依次绘制；交叉处短路径覆盖长路径。

**输入结构**：
- 黑(0)背景网格，约 15x15。
- 网格中有 3~4 对端点像素。每对由相同颜色标识，不同对使用不同颜色，颜色取自蓝(1)、绿(3)、黄(4)、橙(7)。
- 每对的两个像素不在同一行也不在同一列。
- 生成约束：至少两条路径在绘制后会产生交叉（即路径经过同一个单元格）。各端点像素互不相邻，不在网格边缘行/列上。

**规则**：
1. 每对同色端点中，行坐标较小的为起点 A，行坐标较大的为终点 B。
2. 对每对端点，绘制 L 形直角路径：从 A 沿其所在行水平画到 B 所在列，再从该列沿垂直方向画到 B。路径使用该对端点的颜色。路径包含起点和终点像素。
3. 计算每条路径的曼哈顿长度 = |A.row - B.row| + |A.col - B.col|。
4. 将所有路径按曼哈顿长度从大到小排序。长度相同时，按起点 A 的行坐标从大到小排序（行坐标更大的先画）。
5. 按排序结果依次将路径绘制到输出网格上：后绘制的路径覆盖先绘制的。
6. 端点像素始终保留其原始颜色（不被覆盖）。

**关键洞察**：交叉单元格的最终颜色不由颜色值本身、端点位置或绘制路径的空间关系决定，而由路径的曼哈顿长度比较决定——更短的路径总是在更上层。求解者必须计算路径长度并推断"短路径优先"的隐含规则。

## 新题 5：镜像构建模板后按标记数筛选印章

**组合逻辑**：[对称补全/镜像](创新：补全结果不是最终输出，而是供后续印章使用的模板) + [计数](创新：计数结果作为印章筛选条件而非选取输出) + [印章覆盖](创新：模板非预存，由镜像补全动态生成)

**来源原语**：对称补全(symmetry_complete)、镜像(mirror)、翻转对称(flip_symmetry)、半区(half_panel)、空白半区补全(fill_blank_half) ← #3 f25ffba3；印章覆盖(stamp_overlay)、模板图块(template_tile)、标记像素(marker_pixel)、仅标记格被覆盖(only_marked_cover) ← #2 e734a0e8；计数(counting)、标记归属面板(marker_in_panel)、最多标记面板输出(max_marker_panel) ← #18 e50d258f（创新改造：不是选最多标记的面板输出，而是按特定标记数筛选印章目标）

**依赖链**：半填充的模板源经镜像补全生成完整对称模板 → 各目标区域中红(2)标记像素计数 → 计数恰好等于特定值的区域被选为印章目标 → 完整模板透明叠加到选中的目标区域上 → 未选中的区域保持不变

将半填充的小图案镜像补全为完整对称模板，再将模板透明印入恰好含有特定数量红色标记的目标区域中。

**输入结构**：
- 黑(0)背景网格，约 16x16。
- 网格左上角有一个灰(5)边框围成的小矩形区域（模板源），内部为 4 行 x W 列（W 约 3~5）。该内部的下半部分（底 2 行）含有蓝(1)和/或 teal(8)像素构成的小图案（4-连通，3~6 像素），上半部分（顶 2 行）全为黑(0)。
- 网格其余位置散布 3~5 个同样由灰(5)边框围成的目标矩形区域，每个内部尺寸与模板源相同（4 行 x W 列）。每个目标内部包含：
  - 绿(3)像素构成的已有图案（与模板源图案不同）。
  - 0~3 个红(2)标记像素，分布在目标内部的任意位置（不与绿像素重叠）。
- 生成约束：至少一个目标恰好含 2 个红标记，至少一个目标含非 2 个红标记（0、1 或 3 个）。各目标的红标记数不全相同。

**规则**：
1. 对模板源执行垂直镜像补全：将内部底 2 行按行倒序复制到顶 2 行，生成关于水平中轴对称的完整 4 x W 模板。模板的颜色保持与底 2 行一致（蓝(1)/teal(8)），黑(0)像素视为透明。
2. 统计每个目标区域内部的红(2)标记像素数量。
3. 对每个红标记数恰好 = 2 的目标区域：
   - 将完整模板透明叠加到该目标内部：模板左上角对齐目标内部左上角。模板中非黑像素覆盖目标对应位置的像素（包括覆盖绿像素和红标记）；模板中黑(0)像素不改变目标对应位置。
4. 对红标记数 != 2 的目标区域：保持不变（包括红标记也保留）。
5. 所有被印章覆盖的目标区域中，未被模板非黑像素覆盖的红(2)标记像素在输出中擦除为黑(0)。
6. 灰(5)边框和模板源区域在输出中保持不变。

**关键洞察**：模板在输入中不完整——必须先通过镜像补全构造出来，才能知道印章的内容。同时，印章目标的筛选阈值（恰好 2 个红标记）不是显式给出的，需要对比多个示例中哪些目标被印章、哪些未被印章来归纳。

## 新题 6：印章构建障碍场驱动路径偏转

**组合逻辑**：[印章覆盖](已有，作为第一阶段变换) + [路径生长](已有，作为第二阶段变换) + [障碍偏转](创新：障碍场不是预设，而是由第一阶段印章结果动态构成)

**来源原语**：印章覆盖(stamp_overlay)、分隔网格(separator_grid)、模板图块(template_tile)、标记像素(marker_pixel)、标记指定放置位置(marker_position)、仅标记格被覆盖(only_marked_cover) ← #2 e734a0e8；路径生长(path_grow)、控制像素(control_pixel)、底行起始(bottom_row_origin)、障碍偏转(obstacle_deflection)、逐步攀升(step_by_step_climb) ← #1 712bf12e

**依赖链**：标记像素确定哪些图块接受印章 → 印章将模板复制到标记图块中（新增前景像素改变网格状态） → 路径从底行控制像素向上生长 → 印章产生的前景像素与原有分隔线共同构成障碍场 → 不同标记配置导致不同障碍布局，从而产生不同的路径偏转形态

先将模板图块印入标记所指的网格单元，再从底行控制像素向上生长路径，被印章产物和分隔线共同构成的障碍场偏转。

**输入结构**：
- 黑(0)背景网格，约 15x18。
- 灰(5)的等间距全行和全列将网格分割为 3x3 或 4x3 的等大矩形图块（每个图块内部约 3x4 像素）。灰线宽度 1 像素。
- 其中一个图块（模板图块）的内部含有一个由橙(7)像素组成的小图案（4-连通，3~5 像素）。其余图块内部要么全为黑(0)（空白图块），要么含有一个红(2)标记像素（标记图块）。标记图块中除红标记外均为黑(0)。
- 底行（最后一行，属于灰分隔线或其下方的像素行）下方额外有一行，包含 1~3 个 teal(8) 控制像素，列坐标位于某些图块列的内部范围内。
- 生成约束：标记图块至少 2 个。控制像素至少 1 个。模板图块不在底行图块中。

**规则**：
1. **印章阶段**：将模板图块的内部图案精确复制到每个标记图块的对应位置（左上角对齐）。红(2)标记像素在复制后被橙(7)图案或黑(0)覆盖（标记被替换）。模板图块本身保持不变。
2. **路径生长阶段**：从每个 teal(8) 控制像素出发，向上逐步生长路径：
   - 2a. 若上方单元格为黑(0)，涂为 teal(8) 并继续向上。
   - 2b. 若上方单元格为灰(5)（分隔线）或橙(7)（原有或印章产生的图案像素），视为障碍：向右偏移一列，在当前行涂 teal(8)；若右侧单元格也非黑(0)或超出网格，路径停止。偏移后从新位置继续向上。
   - 2c. 若上方超出网格，路径停止。
3. 多条路径按控制像素从左到右依次处理。后处理路径视先前路径的 teal(8) 像素也为障碍（会导致偏转）。

**关键洞察**：路径偏转的位置不仅由原始分隔网格决定，更由印章阶段动态放置的橙色图案决定。求解者必须先推断出印章规则（模板复制到标记图块），在脑中完成印章操作后，才能正确模拟路径偏转。两阶段的因果顺序（先印章后路径）是隐含的，需要从输入输出对中推断。
