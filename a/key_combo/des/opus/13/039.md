## 新题 1：滑动精灵撞击矩形触发位置分类重涂

**组合逻辑**：[方向编码](创新：从着色标记扩展为精灵内部标记像素编码方向) → [滑动] → [碰撞停止] → [局部位置分类 + 重涂色](创新：分类涂色的颜色来自精灵的双色结构而非固定色)

**来源原语**：滑动/sliding、方向编码/direction_encoding（a8c38be5）；碰撞停止/collision_stop（9bbf930d）；重涂色/recolor、局部位置分类/local_position_classification、矩形/rectangle（b6afb2da）；标记像素/marker_pixel（88a10436）

**依赖链**：精灵内部标记像素的相对位置编码滑动方向 → 精灵沿该方向滑动直到碰撞一个矩形停下 → 碰撞确定哪个矩形被选中 → 该矩形按角/边/内部分类重涂，涂色颜色由精灵的标记色和主体色分别提供。删除方向编码则不知往哪滑；删除碰撞则不知选哪个矩形；删除位置分类则不知怎么涂。

将每个携带方向标记的小精灵滑向它编码的方向，碰撞一个灰色矩形后，用精灵的双色结构对该矩形进行角/边/内部重涂。

**输入结构**：
- 背景：黑(0)。网格约 15x15。
- 2~3 个实心灰(5)矩形（每个至少 4x4），散布在网格中部区域，彼此不相邻、不接触网格边缘。
- 2~3 个小型单色精灵（每个 3~6 像素，4-连通，非矩形轮廓，各自颜色不同，选自红(2)、绿(3)、蓝(1)），分布在矩形外围。
- 每个精灵内部恰有 1 个像素颜色与该精灵主体色不同，称为"方向标记像素"（颜色选自黄(4)、橙(7)、栗(9)等与主体色不同的颜色）。
- 方向标记像素位于精灵包围盒中心的上/下/左/右某一侧（不在正中心），其相对位置编码滑动方向：标记在中心上方→向上滑，标记在右侧→向右滑，以此类推。
- 生成约束：每个精灵沿其编码方向直线滑动时，路径上恰好会遇到一个灰矩形（不会遇到其他精灵或第二个矩形）。不同精灵撞击不同矩形（一一对应）。

**规则**：
1. 对每个精灵，确定其方向标记像素相对于精灵包围盒中心的方位（上/下/左/右），该方位即为滑动方向。
2. 将整个精灵（含标记像素）沿该方向逐格平移，直到精灵的任一像素的下一步会与某灰矩形的像素重叠，此时精灵停在重叠前的最后合法位置。
3. 停下后，识别精灵紧邻的那个灰矩形为其"目标矩形"。
4. 对目标矩形执行位置分类重涂：矩形的四个角像素涂为精灵的方向标记色；矩形的非角边缘像素涂为精灵的主体色；矩形的严格内部像素保持灰(5)不变。
5. 精灵本身从网格上擦除（其最终停留位置的像素恢复为背景色）。
6. 未被任何精灵撞击的灰矩形保持原样。
7. 处理顺序：按精灵初始包围盒左上角从左到右排列，左列相同时从上到下。此顺序仅影响叙述清晰性，因为各精灵撞击不同矩形且互不干扰。

**关键洞察**：精灵的双色结构承担双重角色——方向标记像素的位置编码了滑动方向，而标记色和主体色分别成为目标矩形角和边的重涂颜色；同一个标记像素既是运动指令又是涂色素材。

## 新题 2：粒子路径长度决定杯体填充水位

**组合逻辑**：[路径追踪 + 碰撞转向](已有) → [路径长度计算](创新：路径追踪的输出不是轨迹本身，而是量化为长度) → [填充](创新：填充行数由路径长度决定，而非简单的填满) → [追加封盖层](已有，条件触发)

**来源原语**：路径追踪/path_trace、碰撞转向/collision_turn、碰撞停止/collision_stop、走廊/corridor、平行色条/parallel_colored_bar、同色夹道/same_color_flanking（9bbf930d）；填充/fill、杯状轮廓/cup_outline、标记像素/marker_pixel、标记色决定填充/marker_color_sets_fill、追加封盖层/cap_layer_added、内部包含/containment（444801d8）

**依赖链**：标记像素发射粒子 → 粒子在色条走廊中追踪路径（转向、停止） → 路径总步数作为量化信息 → 该步数映射为杯体自底向上的填充行数 → 若填满则追加封盖层。删除路径追踪则不知填多少行；删除杯体则无处填充；删除标记色则不知填什么颜色。

从每个杯中的标记像素向上发射粒子，粒子穿过由平行色条构成的走廊系统，路径总步数决定杯体自底向上填充多少行。

**输入结构**：
- 背景：黑(0)。网格约 20x15。
- 下半区（约第 10~14 行）：2~3 个蓝(1)杯状轮廓（U 形，顶部开口，每个宽 3~5 列、高 4~6 行），杯体间不重叠且横向间隔至少 2 列。
- 每个杯内部（黑色区域）恰有 1 个非蓝非黑的标记像素，颜色互不相同（选自红(2)、绿(3)、黄(4)等）。
- 上半区（约第 0~8 行）：若干水平色条（每条 1 像素高、宽度 3~8 像素），颜色选自灰(5)、橙(7)、栗(9)等，成对出现在相邻偶数行上，同色条对之间的奇数行形成走廊（与 9bbf930d 相同的走廊结构）。
- 走廊系统排列方式使得从每个杯正上方向上出发的粒子可以进入走廊系统，经过若干次碰撞转向后最终在网格边缘或死胡同停止。
- 生成约束：每个粒子的路径总步数不超过杯内部高度的 3 倍（保证填充行数可以用整除 2 映射到合理范围内）。各粒子路径互不经过同一像素。

**规则**：
1. 从每个标记像素位置发射一个虚拟粒子，初始方向为向上。
2. 粒子逐格移动。穿过背景像素时继续直行。碰到色条像素时无法前进，向左或右转 90 度进入由同色条对夹出的走廊（即找到垂直于当前方向、两侧被同色条像素夹住的背景行），具体转入哪侧由走廊存在侧决定（同 9bbf930d 逻辑）。
3. 粒子在到达网格边缘或所有方向均被阻挡时停止。记录该粒子从出发到停止经过的总格数（含起点，不含已被色条占据的格子——即仅计背景格步数）。
4. 杯体填充行数 = floor(总步数 / 2)，但不超过杯内部高度。从杯内部的最底行开始向上逐行填充，颜色为该杯标记像素的颜色。
5. 若填充行数恰好等于杯内部高度（杯被填满），则在杯开口正上方添加一行封盖层：宽度与杯外侧宽度相同，颜色为标记像素颜色。
6. 上半区的色条和走廊结构保持不变。标记像素被填充色覆盖。
7. 各杯独立处理，互不影响。

**关键洞察**：上方的色条走廊系统看似与下方的杯子无关，但粒子在走廊中的行进长度直接决定了杯子的填充水位——路径追踪操作的输出不是视觉轨迹，而是一个抽象数值，该数值跨区域传递给填充操作。

## 新题 3：射线屏障阻断顺时针角落复制

**组合逻辑**：[射线延伸 + 端点发射](已有) → [碰撞停止](已有) → [射线形成屏障](创新：射线的作用从视觉标记变为逻辑门控) → [顺时针角落复制](已有，但受屏障条件门控)

**来源原语**：射线延伸/ray_cast、端点发射/emit_from_endpoints、碰撞停止/collision_stop、对角线段/diagonal_segment（80a900e0）；复制/copy、顺时针到下一角/clockwise_next、角落对象/corner_object、接触两边缘/touching_two_edges（bc93ec48）

**依赖链**：对角线段的端点发射射线 → 射线遇非背景像素或边缘停止 → 射线像素构成屏障 → 检查每个角落对象到其顺时针下一角的边缘路径是否被射线阻断 → 未阻断则复制，阻断则不复制。删除射线则所有角都复制（退化为 bc93ec48）；删除复制规则则射线无意义。

对角线段端点发射射线形成屏障线，角落对象只有在通往顺时针下一角的边缘路径未被射线阻断时才执行复制。

**输入结构**：
- 背景：黑(0)。网格约 15x15。
- 2~4 个彩色角落对象，各自锚定在网格的不同角（触及该角的两条边缘），每个对象 4-连通、4~8 像素、颜色互不相同（选自红(2)、绿(3)、蓝(1)、黄(4)）。
- 1~2 条短对角线段，每条 2~3 像素长，颜色灰(5)，位于网格边缘附近但不在角落区域内。
- 生成约束：对角线段的位置使得从其端点向外发射的对角射线（方向为远离网格中心的对角方向）恰好穿过某些"边缘路径带"（连接相邻两角的行带或列带），从而阻断部分顺时针复制，但不阻断全部。至少有一个角落对象的复制被阻断，至少有一个不被阻断。

**规则**：
1. 保持所有已有元素不变。
2. 对每条灰(5)对角线段，从其两个端点分别发射一条对角射线。射线方向为远离网格中心的对角方向（即朝最近的网格角方向）。射线逐格延伸，将经过的背景像素涂为灰(5)，遇到非背景像素或到达网格边缘时停止（停止点不涂色）。
3. 定义"边缘路径带"：从一个角到其顺时针方向下一个角的路径沿网格边缘行进——左上到右上的路径带是第 0 行，右上到右下的路径带是最后一列，右下到左下的路径带是最后一行，左下到左上的路径带是第 0 列。
4. 对每个角落对象，检查从它到顺时针下一角的边缘路径带上是否存在任何灰(5)射线像素。若路径带上无射线像素（未被阻断），则将该角落对象复制到顺时针下一角，对齐方式为将对象包围盒贴合目标角的两条边缘。
5. 若路径带上存在射线像素（被阻断），则该角落对象不执行复制。
6. 复制处理顺序：左上、右上、右下、左下。若目标角已有对象（原始或先前复制的），新复制的对象覆盖已有像素。
7. 若某个角没有角落对象，则跳过该角（无复制来源）。

**关键洞察**：对角线段和射线看似只是视觉装饰，实际上它们构成了逻辑门控——射线是否穿过两角之间的边缘路径带决定了复制是否被"放行"，使得本来完全对称的顺时针复制变得选择性生效。

## 新题 4：分区计数排序精灵并条件镜像

**组合逻辑**：[网格分区](已有) → [计数](已有) → [排序](已有) → [裁剪 + 堆叠](已有) + [镜像](创新：计数结果同时作为排序键和镜像触发条件，一个量化结果驱动两种不同操作)

**来源原语**：计数/counting、网格分区/grid_partition、分隔线/separator_line、标记像素/marker_pixel（6773b310）；排序/sorting、裁剪/crop（b7999b51）；镜像/mirror（4e7e0eb9）；精灵体/sprite（88a10436）；堆叠/stack（20818e16）

**依赖链**：分隔线划分区域 → 各区域内计数栗色标记像素 → 标记数作为排序键将各区域精灵排序 → 标记数同时作为镜像触发条件（最大值区域的精灵被镜像） → 裁剪精灵后按排序结果上下堆叠输出。计数结果同时流向排序和条件判断两条下游——一个输入分叉为两种用途。

按分隔线将网格分区，统计每区的栗色标记数，按标记数排序各区精灵并上下堆叠输出，其中标记数最多的区域的精灵额外做水平镜像。

**输入结构**：
- 背景：黑(0)。网格约 18x18。
- 黄(4)分隔线（完整的横行和纵列）将网格分为 3x3 共 9 个矩形区域。
- 每个区域内包含：(a) 一个小型单色精灵（3~6 像素，4-连通，非矩形不规则形状），各区域精灵颜色互不相同，选自红(2)、绿(3)、蓝(1)、灰(5)、橙(7)、品红(6)、青(8)中的不同颜色；(b) 0~3 个栗(9)标记像素，散布在该区域的背景空格中，不与精灵像素相邻。
- 生成约束：9 个区域中恰有一个区域的栗色标记数严格最大（无并列最大值）。至少有 2 个区域的标记数为 0（用于测试跳过逻辑）。各区域标记数之间无全部相同的情况。

**规则**：
1. 用黄(4)分隔线将网格分为 9 个矩形区域。
2. 统计每个区域内栗(9)标记像素的数量。
3. 丢弃标记数为 0 的区域（不参与输出）。
4. 将剩余区域按标记数升序排序。标记数相同时，按区域在输入网格中的阅读顺序（左到右、上到下）排列。
5. 裁剪每个参与区域的精灵（取精灵像素的最小包围盒）。
6. 标记数严格最大的那个区域的精灵在裁剪后做水平镜像（左右翻转）。
7. 按排序结果将精灵自上而下堆叠：第一个（标记数最小的）精灵在最顶部，依次向下排列。相邻精灵之间间隔 1 行背景。
8. 输出宽度 = 所有参与精灵裁剪宽度的最大值。宽度不足的精灵左对齐，右侧补背景。
9. 精灵保持各自原始颜色。栗色标记像素和黄色分隔线均不出现在输出中。

**关键洞察**：栗色标记的计数结果承担双重角色——既是决定堆叠顺序的排序键，又是触发镜像变换的判据；求解者必须从多个示例中归纳出"最大计数区域被镜像"这条隐蔽规则，因为单个示例中无法区分"被镜像"是因为计数最大还是因为其他空间属性。

## 新题 5：补全周期矩阵后按频率重涂少数色

**组合逻辑**：[周期检测](已有) → [补全](已有，创新：补全对象从锚矩形扩展为整个周期矩阵) → [频率排序 + 少数色替换](已有，创新：补全步骤实质性改变了频率统计的输入数据)

**来源原语**：补全/complete、平铺/tile、周期/period（34cfa167, 963e52fc）；频率排序/frequency_rank、少数色替换/minority_replaced、重涂色/recolor（9caf5b84）；锚矩形/anchor_rectangle（34cfa167）

**依赖链**：检测矩形排列的空间周期 → 按周期补全被截断区域的缺失矩形 → 补全后统计各颜色总像素数 → 保留最频繁的两种颜色、将其余颜色替换为橙(7)。补全步骤可能逆转频率排名（补全前的少数色在补全后可能变为多数色），因此不能跳过补全直接做频率替换。

检测矩形排列的周期并补全被截断的右侧区域，然后统计补全后的颜色频率，将出现次数不在前两名的颜色全部替换为橙色。

**输入结构**：
- 背景：黑(0)。网格约 15x20。
- 网格中有若干小实心矩形（每个 2x2 或 2x3），使用 3~4 种颜色（选自红(2)、蓝(1)、绿(3)、黄(4)）。
- 矩形按空间周期排列：沿水平方向以固定间距（如每 4~5 列一个）重复，沿垂直方向以固定间距（如每 3~4 行一个）重复，形成规则网格状分布。每个周期位置上矩形的颜色也有确定的周期性规律（如红-蓝-绿-红-蓝-绿...）。
- 网格的右侧约 30%~40% 区域的矩形缺失（该区域为纯背景），造成周期图案截断。
- 生成约束：在不完整（截断）状态下，某种颜色（如绿(3)）的矩形像素数恰好排在第 3 或更后，属于少数色；但在周期补全之后，该颜色的缺失矩形被补回，其总像素数上升到前 2 名以内。另有一种颜色在补全前排前 2 但补全后仍在前 2（保证补全确实改变了排名结构但不改变所有颜色的排名）。

**规则**：
1. 检测矩形排列的空间周期：找到最小的水平周期 Px 和垂直周期 Py，使得已有矩形的位置和颜色可被该周期完全解释。
2. 按检测到的周期，在截断区域补全所有缺失的矩形：在每个本应有矩形但实际为空的周期位置上，绘制对应颜色的矩形。
3. 在补全后的完整网格上，统计每种矩形颜色的总像素数（不含背景）。
4. 保留像素数排名前 2 的两种颜色不变。若第 2 名和第 3 名存在像素数并列，则保留在输入中（补全前）首次出现位置更靠左上的颜色。
5. 将所有其他颜色（第 3 名及以后）的矩形像素替换为橙(7)。
6. 背景保持不变。

**关键洞察**：补全操作不只是视觉修复——它实质性地改变了各颜色的像素频率统计。如果在补全前做频率替换，会得到错误的结果，因为被截断区域恰好集中了某种颜色的大量矩形。求解者必须先补全再统计，两步的顺序不可颠倒。

## 新题 6：小图案几何结构隐式编码变换指令

**组合逻辑**：[几何结构编码](创新：将方向编码原语扩展为"几何属性编码操作类型") → [编码映射](已有) → [镜像 / 局部位置分类重涂 / 平铺](各自已有，但由编码动态选择)

**来源原语**：方向编码/direction_encoding（a8c38be5）；编码映射/encoding_map（dfadab01）；镜像/mirror、轴线决定变换/axis_determines_op（4e7e0eb9）；重涂色/recolor、局部位置分类/local_position_classification（b6afb2da）；平铺/tile（963e52fc）；模板面板/template_panel（b190f7f5）

**依赖链**：读取指令图案的几何属性（对称性、连通性） → 映射到变换类型 → 将变换施加于参考精灵的副本 → 输出所有变换结果并排排列。几何属性和变换类型之间的映射只能通过对比多个示例归纳得到（隐式编码），删除指令图案则无法确定变换，删除参考精灵则无变换对象。

左侧面板是参考精灵模板，右侧排列的小型 3x3 图案的几何属性各自编码一种变换操作；按图案的编码依次变换参考精灵的副本，并排输出。

**输入结构**：
- 背景：黑(0)。网格约 20x10。
- 左侧面板（约第 0~5 列）：一个灰(5)单色参考精灵，约 4x4 像素，4-连通，具有可区分的角、边和内部像素（即至少 3x3 包围盒且有内部像素），形状不对称（左右不对称、上下不对称）。
- 右侧面板（约第 7~19 列）：水平排列 2~3 个 3x3 的"指令图案"，相邻图案间隔 1 列背景。每个指令图案使用一种非灰前景色（选自红(2)、绿(3)、蓝(1)等），在黑(0)背景上绘制。
- 指令图案的三种几何类型（每个示例中至少出现两种不同类型）：
  - "横线型"：3x3 中，中间行（第 1 行）三个像素全部填色，其余像素为背景。视觉上是一条水平线。
  - "竖线型"：3x3 中，中间列（第 1 列）三个像素全部填色，其余像素为背景。视觉上是一条垂直线。
  - "散点型"：3x3 中，四个角位置的像素填色，中心和边中点均为背景。视觉上是四个散落的角点。
- 生成约束：不同示例中，同一种几何类型对应的指令图案颜色不同（颜色不是编码信号，几何结构才是）。

**规则**：
1. 识别左侧参考精灵，裁剪其最小包围盒。
2. 从左到右读取右侧每个 3x3 指令图案，判断其几何类型：
   - 横线型（中间行全填色）→ 对参考精灵做上下镜像（水平轴翻转）。
   - 竖线型（中间列全填色）→ 对参考精灵做左右镜像（垂直轴翻转）。
   - 散点型（四角填色）→ 对参考精灵做 2x2 平铺（将精灵在水平和垂直方向各重复一次，生成 2 倍宽 2 倍高的图案）。
3. 每次变换产生的结果使用对应指令图案的前景色重涂（替换灰(5)精灵像素为该指令色）。
4. 输出：将所有变换结果从左到右并排放置，相邻结果间隔 1 列背景。输出高度 = 所有结果中最大高度；高度不足的结果顶部对齐，下方补背景。
5. 左侧参考精灵和右侧指令图案均不保留在输出中。

**关键洞察**：3x3 指令图案不是要输出的内容，而是变换指令的编码器——其几何结构（横线/竖线/四角散点）直接映射为镜像轴方向或平铺操作。求解者需要从多个示例中归纳"线的方向即翻转轴"以及"角点意味着平铺"的隐式映射关系。

## 新题 7：跨尺度形状匹配决定重涂色与堆叠顺序

**组合逻辑**：[形状匹配 + 跨尺度同形](已有) → [缩放因子提取](创新：缩放因子不是用来选择返回哪个，而是作为堆叠顺序的排序键) → [堆叠 + 中心对齐](已有，创新：堆叠物是小形状但涂大形状的颜色) → [忽略干扰项](已有)

**来源原语**：形状匹配/shape_matching、跨尺度同形/cross_scale_same_shape、忽略干扰项/ignore_distractors（ce602527）；堆叠/stack、角对齐/corner_aligned、按面积降序/largest_to_smallest_area（20818e16）；印章覆盖/stamp、中心对齐/center_align、标记像素/marker_pixel（88a10436）

**依赖链**：形状匹配建立小-大配对 → 缩放因子作为排序键 → 大形状颜色跨配对传递给小形状 → 重涂后的小形状按缩放因子顺序堆叠在标记位置。配对错误则颜色错误且顺序错误；缩放因子不仅是匹配验证信息更是排序信息；颜色来自配对伙伴而非自身。

将小形状与大形状按跨尺度同形配对，用大形状的颜色重涂对应的小形状，然后按缩放因子从大到小将重涂后的小形状堆叠在灰色标记位置。

**输入结构**：
- 背景：黑(0)。网格约 18x18。
- 3~4 个小型彩色形状（每个 2~4 像素，4-连通），颜色互不相同（选自红(2)、绿(3)、蓝(1)）。
- 3~4 个大型彩色形状（每个 8~16 像素，4-连通），颜色互不相同且不与任何小形状同色（选自黄(4)、橙(7)、栗(9)）。
- 每个小形状恰好与一个大形状形状相同（将小形状各像素坐标放大 2 倍或 3 倍后，与某个大形状的像素掩码逐点匹配）。缩放因子可以是 2 或 3，且并非所有配对的缩放因子都相同。
- 1 个额外的干扰形状（小型或大型均可，颜色区别于上述所有颜色，如品红(6)），与任何其他形状都无法跨尺度匹配。
- 1 个灰(5)标记像素，位于网格中某处背景区域，不与任何形状相邻。
- 生成约束：各形状在网格中互不重叠、互不相邻。小形状和大形状混杂分布，无固定的空间分组。

**规则**：
1. 对每个小形状，将其像素掩码（相对于包围盒左上角的坐标集）依次放大 2 倍和 3 倍，检查是否与某个大形状的像素掩码匹配（忽略颜色，仅比较形状）。记录匹配成功的缩放因子。
2. 未能与任何大形状匹配的形状视为干扰项，丢弃（不参与输出）。同样，未能与任何小形状匹配的大形状也丢弃。
3. 对每个成功配对的小形状：裁剪其最小包围盒，将其所有像素重涂为其配对大形状的颜色。
4. 按缩放因子从大到小排序配对（缩放因子大的先绘制，作为底层）。缩放因子相同时，按大形状的像素总数降序排列（像素多的先绘制）。
5. 将所有重涂后的小形状以灰(5)标记像素为公共中心点逐层堆叠：每个小形状的包围盒中心对齐标记像素位置，先绘制的在底层、后绘制的覆盖底层。
6. 灰(5)标记像素被堆叠覆盖。

**关键洞察**：小形状和大形状之间存在颜色交叉引用——输出使用小形状的几何形状但大形状的颜色，迫使求解者正确建立跨尺度配对；而缩放因子（一个几何属性）控制着堆叠顺序（一个空间安排），将形状分析与图层排列耦合在一起。

## 新题 8：对角连线交叉产生封闭区域并按边界长度填色

**组合逻辑**：[连线 + 对角偏移](已有) → [多连线交叉产生封闭区域](创新：单对连线不产生封闭区域，但多对交叉后涌现封闭区域) → [计数边界像素](创新：连线长度从单纯的视觉连接变为影响填充色的量化信息) → [填充](已有，颜色由边界计数决定)

**来源原语**：连线/connect、对角偏移/diagonal_offset、同色矩形对/same_color_rect_pair、对角补全连接/diagonal_fill（342ae2ed）；计数/counting（6773b310）；填充/fill、内部包含/containment（444801d8）；重涂色/recolor（b6afb2da）

**依赖链**：同色矩形对之间画对角连线 → 不同颜色的连线相互交叉 → 交叉产生原本不存在的封闭区域（涌现效应） → 统计每个封闭区域边界上各颜色连线段的像素数 → 边界贡献最多像素的连线颜色成为该区域的填充色。单独一对连线无法产生封闭区域，必须多对交互才有意义。

多组同色矩形对之间的对角连线相互交叉形成封闭区域，每个封闭区域用其边界上贡献像素最多的连线颜色填充。

**输入结构**：
- 背景：黑(0)。网格约 16x16。
- 3~4 对同色矩形对，每对由两个 2x2 实心矩形组成，颜色互不相同（选自红(2)、蓝(1)、绿(3)、黄(4)）。
- 每对矩形对角偏移放置：一个在左上、一个在右下，两者面对的角在同一条 45 度对角线上（与 342ae2ed 相同的布局）。
- 各对矩形的对角连线（若画出）会在网格中某些位置相互交叉。
- 生成约束：至少存在 2 次不同颜色连线的交叉，使得交叉后产生至少 1 个被非背景像素完全包围（4-连通边界）的背景区域。各矩形间互不重叠。

**规则**：
1. 对每对同色矩形，在其面对的两个角之间绘制对角连线：从上方矩形面对角的下方相邻像素开始，到下方矩形面对角的上方相邻像素结束，沿 45 度方向逐像素绘制，颜色为该矩形对的颜色。已有非背景像素的位置跳过（不覆盖矩形像素和其他连线像素），在该位置保持已有颜色不变，连线继续前进。
2. 连线绘制顺序：按矩形对中上方矩形的左上角坐标从左到右排列，左列相同时从上到下。连线像素绘制时，若目标位置已被先前连线占据，则保留先前颜色（先到先占）。
3. 绘制完所有连线后，识别所有被非背景像素完全包围的背景区域（4-连通的背景连通分量，其中不包含任何与网格边缘相邻的像素）。
4. 对每个封闭区域，统计其 4-连通边界（紧邻区域像素的非背景像素）中各颜色的像素数。
5. 用边界像素数最多的颜色填充该封闭区域。若最多像素数存在并列，选择在连线绘制顺序中较早绘制的那条连线的颜色。
6. 未被封闭的背景区域保持不变。所有矩形和连线像素保持不变。

**关键洞察**：单独任何一对矩形的对角连线都不会形成封闭区域——封闭区域是多条不同颜色连线交叉后涌现出来的几何结构；填充颜色取决于哪条连线对该区域的边界贡献最多像素，这将连线长度这一几何量转化为填充色选择的判据。
