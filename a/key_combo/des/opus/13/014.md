## 新题 1：重力落点决定磁吸锚与面板反色

**组合逻辑**：[gravity_drop] → [snap + nearest_frame_assign](创新：重力后的落点位置取代原始位置决定最近锚) → [recolor + opposite_panel_color](创新：反色取自锚所属面板的对侧面板色)

**来源原语**：gravity_drop / cushion_row_gap (825aa9e9), snap / nearest_frame_assign / anchor_block / outer_frame (1b8318e3), recolor / opposite_panel_color / panel_membership (9b5080bb)

**依赖链**：重力改变像素落点 → 落点决定最近锚块 → 锚块所属面板决定反色来源。删除重力步骤则最近锚分配完全不同；删除面板反色则只有位置信息无颜色变换；三环节缺一不可。

将散落的彩色像素先做重力下落，再磁吸到落点附近灰色锚块的外框上，最终按锚块所属面板赋予对侧面板颜色。

**输入结构**：约 15x20 的网格。背景黑(0)。网格被一条垂直的灰(5)分隔线（位于中间列）分成左右两个面板，左面板底色为蓝(1)、右面板底色为红(2)，分隔线仅一列宽。每个面板内有 2~3 个灰(5) 2x2 锚块，锚块不与分隔线相邻，锚块之间曼哈顿距离至少 5。网格上半部散布 4~6 个绿(3)孤立像素（单像素），所有绿像素的初始行号小于所有锚块的最高行号。面板底色仅填充最底部两行（作为地板），其余面板区域为黑(0)背景。生成约束：每个绿像素在重力下落后与其最近锚块的归属必须唯一（不出现等距歧义）。

**规则**：
1. 将所有绿(3)像素在各自所在列内向下移动，直到碰到面板地板行的上方一行（cushion = 1 行）或碰到灰(5)锚块正上方一行时停止（即不落入锚块所在行或其正上方行）。同列有多个绿像素时，下方的先落位，上方的堆叠在其上方。
2. 对每个落位后的绿像素，计算其与每个灰(5) 2x2 锚块的国际象棋距离（king-move distance，即 Chebyshev 距离），选择距离最小的锚块。将该像素移动到该锚块的单格外框（4x4 区域减去 2x2 核心的 12 个格）中离落位点最近的空格上（若最近空格已被占，选次近空格）。
3. 确定每个锚块属于左面板还是右面板（依据锚块中心列与分隔线的位置关系）。左面板的锚块对应对侧色为红(2)；右面板的锚块对应对侧色为蓝(1)。将吸附到该锚块的所有像素重涂为该对侧颜色。
4. 分隔线、面板地板、灰色锚块均保持不变。原始绿像素位置恢复为黑(0)背景。

**关键洞察**：绿像素的最终颜色不由其自身属性决定，而由重力落点间接决定——落点改变了"最近锚块"的归属，而锚块的面板身份又反转了颜色。同一个绿像素在不同的初始列会得到不同的输出颜色。

## 新题 2：重力生成障碍后的分叉射线模拟

**组合逻辑**：[gravity_drop](创新：下落的色块转化为射线障碍) → [ray_extend + branching + collision_generates_side_wakes](创新：障碍集合包含重力生成的新障碍)

**来源原语**：gravity_drop / cushion_row_gap / movable_object (825aa9e9), ray_extend / branching / collision_generates_side_wakes / seed_pixel / obstacle_pixel / row_propagation (79fb03f4)

**依赖链**：重力决定色块落位 → 落位色块成为障碍 → 障碍布局决定射线路径与分叉模式。不执行重力则障碍布局不同，射线路径完全改变；无射线模拟则重力结果无后续变换。

悬浮色块先做重力下落成为固定障碍，然后从左边缘种子像素发射水平射线，遇障碍产生侧翼尾迹与分叉。

**输入结构**：约 18x18 的网格。背景为黑(0)。最左列有 2~3 个绿(3)种子像素（它们固定在最左列的不同行）。网格中散布 3~5 个红(2)固定障碍像素（单像素，位于网格中下部，不在最左列）。网格上半部有 2~4 个橙(7)小色块（每个为 1x2 或 2x1 的连通体），它们悬浮在空中（下方有空间可以下落）。网格最底行为灰(5)地板（整行填充）。生成约束：橙色块下落后不会落到种子像素所在行（不遮挡种子）；下落后至少有一个橙色块恰好落在某个种子像素的射线路径上（确保产生交互）。

**规则**：
1. 所有橙(7)色块在各自所在列内向下做重力下落，直到触碰灰(5)地板上方一行（cushion = 1）或触碰已有障碍/已落位色块的上方一行时停止。下落顺序：行号大的先落位。
2. 落位后的橙(7)像素全部重涂为红(2)，与原有红色障碍像素合并为统一障碍集合。原橙色位置恢复为黑(0)。
3. 从每个绿(3)种子像素出发，向右发射水平射线（涂绿色）。射线传播规则与参考题 79fb03f4 相同：
   - 射线沿行向右逐格涂绿(3)，遇背景则继续。
   - 遇红(2)障碍时停止，障碍像素保持红色不变。在障碍像素的上下各一格、左一格组成的"三格侧翼尾迹"范围内，将可用的背景格涂绿(3)。侧翼尾迹被其他障碍占据则该侧跳过。
   - 若被撞障碍的左上和左下对角格均为红(2)障碍，则当前射线终止，在上下两行各产生一条新的向右全射线（从障碍右侧一格开始）。
4. 灰(5)地板和所有红(2)障碍保持不变。射线到达网格右边界时自然终止。

**关键洞察**：射线路径的分叉模式完全取决于障碍的空间分布，而障碍分布的一部分是由重力下落动态生成的。仅看橙色块的初始位置无法推断射线结果，必须先完成重力模拟。

## 新题 3：交替平移后对角连线与触发点分束

**组合逻辑**：[alternating_shift + parity_determines_dir] → [connect + diagonal_alignment](创新：连线的对角对是平移后涌现的，非原始存在) → [trigger_splits_beam](创新：触发点作用于连线而非预设对角线)

**来源原语**：alternating_shift / ordering / parity_determines_dir / mono_foreground_obj (4364c1c4), connect / diagonal_alignment / diagonal_pixel_pair (db695cfb), trigger_splits_beam / trigger_pixel (db695cfb)

**依赖链**：交替平移改变对象位置 → 新位置产生原本不存在的对角对齐 → 对角连线穿过触发点时分束。删除平移则对角关系不同；删除触发分束则连线无后续效应；三步紧耦合。

多个单色对象先按垂直排名交替左右平移，平移后新产生对角对齐关系的对象对被连线，连线经过触发像素处产生垂直分束射线。

**输入结构**：约 16x16 的网格。背景为黑(0)。有 5~7 个蓝(1)单色 4-连通前景对象，每个对象 3~6 像素，形状各异（非特定命名形状），每个对象的包围框顶行互不相同，从而有唯一的从上到下排序。网格中另有 2~4 个品红(6)孤立像素（触发像素），分布在网格中部区域。生成约束：在交替平移（奇数排名左移 1 列、偶数排名右移 1 列）之后，恰好有 2~3 对蓝色对象的质心落在同一条 45 度或 135 度对角线上（平移前不在同一对角线上）；至少有一条对角连线经过某个品红像素。

**规则**：
1. 按包围框顶行从小到大排序所有蓝(1)对象，排名从 1 开始。奇数排名的对象整体左移 1 列，偶数排名的对象整体右移 1 列。移出网格边界的像素丢弃。腾出的原始位置恢复为黑(0)。
2. 在平移后的位置上，计算每个蓝色对象的质心（像素坐标平均值，取整到最近整数）。若两个对象的质心行差的绝对值等于质心列差的绝对值（即在同一 45 度或 135 度对角线上），则称它们"对角对齐"。
3. 对每对对角对齐的对象，用绿(3)画一条从一个质心到另一个质心的对角线段（逐格走 45 度方向）。若线段经过蓝(1)像素，该蓝色像素保持不变（绿色不覆盖蓝色）。若线段经过品红(6)触发像素，触发像素保持品红色。
4. 对每个被对角连线穿过的品红(6)触发像素，从该像素出发沿连线的垂直方向（即旋转 90 度的对角方向）向两侧发射品红(6)射线，射线延伸至网格边界。射线经过黑(0)背景格时涂品红(6)；遇到任何非背景像素时停止（不覆盖、不穿透）。
5. 未被任何对角连线穿过的品红(6)触发像素保持原位不变，不产生射线。

**关键洞察**：对角对齐关系是交替平移后涌现的几何结构——平移前这些对象不在同一对角线上。求解者必须先推断出平移规则（奇偶→方向），才能确定哪些对象会产生连线，进而确定哪些触发像素会分束。

## 新题 4：形状匹配编码旋转后异色补全

**组合逻辑**：[same_shape + translate_normalize](创新：匹配目标是外部提示精灵体而非同类对象) → [rotate + pixel_count_encodes_rotation](创新：旋转量由匹配到的提示精灵体像素数编码) → [completion + missing_diff_color_fill](创新：补全作用于旋转后的几何形态)

**来源原语**：same_shape / translate_normalize / placeholder_obj (ad38a9d0), rotate / pixel_count_encodes_rotation / cue_sprite / same_color_matching (6ffbe589), completion / missing_diff_color_fill / connected_component / inside_bbox (60b61512)

**依赖链**：形状匹配确定旋转量来源 → 旋转改变对象朝向与包围框内空位分布 → 补全填充取决于旋转后的空位。任一步骤删除都导致输出错误。

将不完整的彩色对象与外部单色提示体做形状匹配以确定旋转角度，旋转后对包围框内缺失像素做异色补全。

**输入结构**：约 14x18 的网格。背景为黑(0)。网格左侧区域有 3 个不同颜色的 4-连通不完整对象（如红(2)、绿(3)、蓝(1)），每个对象 5~8 像素，各自的包围框为 4x4，包围框内有 2~4 个黑(0)空位。三个对象互不相邻（包围框不重叠）。网格右侧区域有 3 个灰(5)小精灵体（提示），每个提示精灵体 3~6 像素，形状各异。每个提示精灵体的平移归一化形状恰好等于某个左侧对象去除空位后的平移归一化形状（可能需要旋转 0/90/180/270 度后匹配）。三个提示精灵体的像素数分别对应旋转角度：像素数 mod 4 = 0 不旋转，= 1 顺时针 90 度，= 2 顺时针 180 度，= 3 顺时针 270 度。生成约束：每个左侧对象恰好匹配一个右侧提示（一一对应）；三个旋转量互不相同。

**规则**：
1. 提取每个左侧彩色对象的非空像素集合，做平移归一化（将最小行列移到原点）。对每个右侧灰色提示精灵体同样做平移归一化。
2. 对每个左侧对象，逐一尝试将其归一化形状旋转 0/90/180/270 度，与每个提示的归一化形状比较。找到匹配的提示。
3. 该对象的旋转角度 = 匹配提示的像素数 mod 4 x 90 度（顺时针）。以对象包围框中心为旋转中心，将对象整体旋转该角度。旋转后的像素位置取整到最近网格格点。
4. 在旋转后对象的新 4x4 包围框内，将所有黑(0)空位涂为黄(4)。对象原色像素保持不变。
5. 右侧灰色提示精灵体在输出中擦除为黑(0)背景。网格其余区域不变。

**关键洞察**：旋转改变了包围框内空位的空间分布——同一个对象旋转 90 度后，需要补全的位置完全不同。求解者必须先通过形状匹配找到正确的提示精灵体，才能知道旋转多少度，才能知道在哪里补全。

## 新题 5：吸引-排斥滑动与标记编码的互斥区

**组合逻辑**：[slide + color_determines_direction + toward_and_away](创新：滑动方向由颜色和分隔线位置共同决定) + [pixel_count_encodes_radius + exclusion_zone](创新：排斥半径编码从射线障碍域转用于滑动停止条件) → 同时约束满足

**来源原语**：slide / color_determines_direction / movable_object (9b4c17c4), toward_and_away / divider_line / color_determines_ray_direction (8d510a79), pixel_count_encodes_radius / exclusion_zone (cb2d8a2c), marker_pixel (b457fec5)

**依赖链**：颜色决定滑动方向（朝向/背离分隔线），标记像素数编码每个对象的排斥半径，滑动距离受其他对象排斥区的约束。方向、距离、约束三者交织为同时满足的约束集，删除任一信息源都无法确定最终位置。

彩色矩形沿水平方向朝向或背离灰色分隔线滑动，但每个矩形携带标记像素编码自身的排斥半径，任何矩形不得进入他者的排斥区。

**输入结构**：约 15x20 的网格。背景为黑(0)。一条垂直灰(5)分隔线位于网格中部（如第 10 列），仅一列宽，贯穿全高。分隔线两侧各有 2~3 个彩色实心矩形（2x2 或 2x3 或 3x2），同侧矩形在不同行、互不重叠。左侧矩形颜色为红(2)，右侧矩形颜色为蓝(1)。每个矩形的正上方紧邻 1~3 个绿(3)标记像素（排成水平行，个数 1~3），标记像素不与任何矩形重叠。生成约束：所有矩形在滑动后不会重叠，也不会越过分隔线；至少有一对矩形的滑动被另一个矩形的排斥区截停（非被分隔线或边界截停）。

**规则**：
1. 每个矩形的排斥半径 = 其正上方绿(3)标记像素的个数。排斥区定义为以矩形包围框为中心、向外扩展排斥半径格的矩形区域（Chebyshev 膨胀）。
2. 红(2)矩形向右滑动（朝向分隔线）；蓝(1)矩形向左滑动（朝向分隔线）。每个矩形的目标位置是包围框紧贴分隔线（但不覆盖分隔线）。
3. 所有矩形同时尝试向目标滑动。若某矩形在滑动过程中其包围框进入了另一个矩形的排斥区（以另一个矩形的最终位置计算），则该矩形停在刚好不进入排斥区的位置。当多个约束冲突时，按矩形离分隔线的初始距离从近到远依次确定最终位置（近者优先占位）。
4. 滑动后矩形保持原色和原形状。绿(3)标记像素不移动，保留在原位。腾出的原矩形位置恢复为黑(0)。分隔线不变。

**关键洞察**：每个矩形的排斥区大小由标记编码，但排斥区约束的是其他矩形的运动而非自身——标记越多的矩形越"排斥"邻居。求解者需同时考虑方向规则和互斥约束，不能逐个独立计算。

## 新题 6：载体色编码水平滑动后擦除载体触发重力下落

**组合逻辑**：[slide + color_determines_direction + inside_carrier] → [erase](创新：擦除载体而非擦除移动体) → [gravity_drop + cushion_row_gap](创新：重力作用于滑动后失去载体支撑的对象)

**来源原语**：slide / color_determines_direction / carrier_region / inside_carrier / movable_object (9b4c17c4), erase (1b8318e3), gravity_drop / cushion_row_gap / obstacle / adjacency_blocking (825aa9e9)

**依赖链**：载体色决定滑动方向 → 滑动改变对象水平位置 → 擦除载体移除支撑 → 重力将对象从滑动后位置下落到障碍物上方。四步环环相扣：滑动位置决定对象在哪一列下落；载体擦除后才触发重力；最终位置同时取决于水平滑动和垂直下落。

红色对象先在载体内水平滑动至载体边缘，然后载体区域被擦除，失去支撑的红色对象向下做重力下落至灰色障碍物上方。

**输入结构**：约 16x16 的网格。背景为黑(0)。网格中有 3~4 个水平载体区域，每个载体是一条水平色带（宽度 8~12 格、高度 2~3 格），颜色为蓝(1)或青(8)，不同载体在不同行且互不接触。每个载体内嵌有一个红(2)小矩形对象（2x2 或 1x3），红色对象完全在载体内部，左右两侧均有空间。网格底部有灰(5)不规则障碍物（若干灰色像素组成的平台，高度 1~2 格，不连续分布）。生成约束：所有载体的行范围高于所有灰色障碍物；红色对象下落后不会互相重叠。

**规则**：
1. 对每个红(2)对象，识别其所属载体（完全包含该对象的蓝(1)或青(8)色带）。
2. 蓝(1)载体中的红色对象向右滑动，直到其包围框右边缘与载体右边缘齐平。青(8)载体中的红色对象向左滑动，直到其包围框左边缘与载体左边缘齐平。滑动后红色对象仍在载体内。
3. 将所有蓝(1)和青(8)载体像素擦除为黑(0)背景。红色对象保留在滑动后位置。
4. 所有红(2)对象在各自所在列内向下做重力下落。下落停止条件：触碰灰(5)障碍像素正上方一行（cushion = 1 行），或触碰网格底边正上方一行，或触碰另一个已落位的红色对象正上方。下落顺序：初始行号大（更靠下）的对象先落位。
5. 红色对象保持原形状和颜色。灰色障碍保持不变。腾出的位置恢复为黑(0)。

**关键洞察**：红色对象的最终位置是二维的——水平坐标由载体色编码的滑动方向决定，垂直坐标由擦除载体后的重力下落决定。不做滑动则对象在错误的列下落；不擦除载体则对象不下落。两步组合产生了任一步单独都不会产生的最终位置。

## 新题 7：孔洞计数双重驱动：重涂色与射线排斥半径

**组合逻辑**：[counting + enclosed_background_region](共享计算) → 并行分支：[recolor + hole_count_to_color_mapping] 与 [ray_extend + obstacle_avoidance + pixel_count_encodes_radius](创新：孔洞数作为排斥半径而非标记像素数)

**来源原语**：counting / enclosed_background_region / foreground_object / hole_count_to_color_mapping (37d3e8b2), ray_extend / obstacle_avoidance / pixel_count_encodes_radius / exclusion_zone / path_start (cb2d8a2c), recolor (9b5080bb)

**依赖链**：孔洞计数同时服务于两个下游任务——(a) 决定对象颜色，(b) 决定对象的排斥半径。重涂色改变了对象的视觉属性，排斥半径改变了射线路径。两个分支共享同一个上游计算，且射线路径必须绕开已重涂色的对象（排斥区大小由孔洞数决定），所以颜色和路径在空间上交互。

对前景对象按内部孔洞数重涂色，同时以孔洞数为排斥半径从边缘种子发射绕障射线。

**输入结构**：约 18x18 的网格。背景为黑(0)。网格中有 4~5 个灰(5) 4-连通前景对象，每个对象是填充矩形（约 3x3 到 5x5），内部挖有 1~3 个黑(0)背景孔洞（每个孔洞为单个黑色像素）。对象之间间距至少 3 格。网格左边缘（第 0 列）有 1~2 个绿(3)种子像素，位于不同行。生成约束：不同对象的孔洞数互不相同（1、2、3 分别出现）；种子像素所在行不与任何对象的行范围重叠。

**规则**：
1. 对每个灰(5)前景对象，计算其包围框内被对象完全围合的黑(0)背景连通分量的数量（即孔洞数 H）。
2. 重涂色：按孔洞数 H 将对象所有灰色像素重涂——H=1 → 蓝(1)，H=2 → 红(2)，H=3 → 橙(7)。孔洞内的黑色像素保持黑色。
3. 每个对象的排斥半径 = H。排斥区为以对象包围框为基础向外 Chebyshev 膨胀 H 格的矩形区域。
4. 从每个绿(3)种子像素出发，向右发射水平射线（涂绿色）。射线前进时必须与所有对象的排斥区保持距离——射线像素不得进入任何排斥区内。若射线被排斥区阻挡，则在阻挡点沿垂直方向（上或下，选择能更快绕过排斥区的方向）绕行，绕过排斥区后恢复水平前进。射线到达网格右边缘终止。
5. 绕行时若上下两个方向等距，选向上。射线路径不得穿过任何非背景像素（重涂色后的对象像素也算阻挡）。种子像素保持绿色。

**关键洞察**：孔洞数是唯一的信息来源，但它同时编码了两个完全不同维度的输出特征——颜色和排斥半径。孔洞多的对象不仅颜色不同，还在空间上对射线产生更大的排斥效应，迫使射线走更远的弯路。

## 新题 8：重叠框架分解与遮挡深度定序重涂色

**组合逻辑**：[counting](创新：计数对象为可见角点，用于推断遮挡关系) + [recolor + conflict_priority](创新：遮挡深度序作为重涂色的排序依据) → 结构解构型

**来源原语**：counting (37d3e8b2, 4852f2fa), recolor (9b5080bb), conflict_priority (1b8318e3), ordering (4364c1c4), connected_component (60b61512), inside_bbox / bounding_box (60b61512, f25fbde4)

**依赖链**：框架边缘像素叠加为单色图案 → 必须通过角点可见性分解出独立框架 → 角点分析确定遮挡深度 → 深度序决定每个框架的颜色。不完成分解就无法知道有几个框架；不确定深度就无法分配颜色。

多个同色空心矩形框重叠为单色图案，根据角点遮挡关系推断深度顺序并按深度重涂色。

**输入结构**：约 14x14 的网格。背景为黑(0)。网格中有 3~4 个灰(5)空心矩形框相互重叠。每个矩形框仅由边框像素组成（1 像素宽边框），内部为黑(0)背景。所有框架统一为灰(5)色，重叠处仅显示一个灰色像素（看不出属于哪个框架）。矩形框的尺寸互不相同（宽和高的组合唯一）。生成约束：每个矩形框至少有一个角点（四角之一）未被其他框架的边缘遮挡（即可见），使得深度排序可唯一确定；任意两个框架不完全包含关系（即一个框架不完全在另一个内部）；框架之间存在 T 形交叉点（一个框架的边终止于另一个框架的边上）。

**规则**：
1. 将所有灰(5)像素视为候选边框像素集合。识别其中所有可能的轴对齐矩形框：枚举所有四角组合 (r1,c1,r2,c2)，验证该矩形的四条边是否全部包含在灰色像素集中（允许与其他框共享像素）。从最大矩形开始贪心匹配，确保每个矩形的尺寸(宽,高)组合唯一。
2. 确定遮挡深度（1 = 最前方）。规则：在 T 形交叉点处（一个框架的边在某处垂直穿过另一个框架的边并终止），被穿过的框架在前方（深度更浅），终止的框架在后方（深度更深）。若框架 A 的边穿过框架 B 的边而终止，则 B 在 A 前方。用所有 T 形交叉点的约束做拓扑排序，得到唯一深度序。
3. 按深度序重涂色：深度 1（最前方）→ 红(2)，深度 2 → 蓝(1)，深度 3 → 绿(3)，深度 4 → 黄(4)。
4. 重涂色时，重叠像素归属前方框架（深度值较小者）。每个框架的所有边框像素（包括与后方框架重叠的像素）涂为该框架的颜色。框架内部的黑色背景保持不变。

**关键洞察**：所有框架都是同一颜色，重叠使得单独的框架结构不可直接观察。求解者必须从 T 形交叉点推断"谁在谁前面"——这是一个空间推理问题，而非简单的属性检测。深度序不是由大小或位置直接决定的，而是由遮挡几何关系决定。

## 新题 9：最短路径转弯计数驱动端点区域缩放

**组合逻辑**：[pathfinding + unique_shortest_path](寻路) → [counting](创新：计数对象为路径的转弯次数而非孔洞) → [pixel_scaling + crop](创新：缩放因子由转弯计数编码)

**来源原语**：pathfinding / unique_shortest_path / endpoint_pixel / blocker_pixel / four_neighbor_connect / shortest_path (b15fca0b), counting (37d3e8b2), pixel_scaling / crop / bounding_box / scale_with_gaps (f25fbde4), recolor (9b5080bb)

**依赖链**：最短路径的几何形状决定转弯次数 → 转弯次数编码缩放因子 → 缩放因子应用于端点所在区域的裁剪放大。路径形状是计算中间量，不直接出现在最终输出中。

在迷宫中找两个端点间的最短路径，统计路径转弯次数，以转弯数作为倍率裁剪并放大其中一个端点周围的特征区域。

**输入结构**：约 15x15 的网格。背景为黑(0)。蓝(1)像素组成迷宫墙壁（稀疏分布，形成通道）。恰好两个红(2)端点像素，分别位于网格的不同区域。其中一个端点（称为"目标端点"）周围 3x3 范围内有一个由黄(4)像素组成的小图案（2~4 个黄色像素，形成某种非对称图形）；另一个端点（"起始端点"）周围无黄色像素。生成约束：两端点间存在唯一最短 4-邻接路径（不经过蓝色墙壁）；该最短路径的转弯次数在 2~4 之间（保证缩放因子合理）；目标端点的 3x3 邻域不含蓝色墙壁。

**规则**：
1. 找到两个红(2)端点间的唯一最短 4-邻接路径，蓝(1)像素为不可通行墙壁。路径包含两个端点本身。
2. 将路径上除两个端点外的黑(0)像素涂为灰(5)（标记路径，但端点保持红色）。
3. 统计路径的转弯次数 T：路径中方向改变的位置数量（从水平变为垂直或反之即为一次转弯）。
4. 识别目标端点（周围有黄(4)像素的那个端点）。以目标端点为中心裁剪 3x3 区域。
5. 将该 3x3 裁剪区域做像素放大，倍率 = T（即每个像素变为 TxT 的块）。放大后的区域即为最终输出（输出尺寸为 3T x 3T）。

**关键洞察**：路径本身不是最终输出的主体——它的几何形状（转弯次数）编码了一个数值参数，该参数控制了一个看似无关的缩放操作。求解者需要意识到转弯次数是连接寻路步骤和缩放步骤的桥梁。
