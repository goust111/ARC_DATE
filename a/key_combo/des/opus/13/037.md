## 新题 1：孔洞分流——有孔填充、无孔滑移

**组合逻辑**：[封闭孔洞检测](已有) → 条件分支{[擦除+填充](创新：填充色继承框色) | [滑动+碰撞停止](创新：滑向右边缘而非特定列)}

**来源原语**：封闭孔洞(enclosed_hole) ← ac2e8ecf；擦除(erase)+填充(fill)+空心内部变色(interior_recolor) ← d5d6de2d；滑动(slide)+碰撞停止(collision_stop) ← ac2e8ecf/9c56f360

**依赖链**：孔洞检测的结果决定对该对象施加哪一种操作——有孔对象走"擦框填洞"分支，无孔对象走"平移堆叠"分支。两个分支的操作完全不同，删除孔洞检测则无法确定任何对象的处理方式；删除任一分支则该类对象无法正确变换。

将有孔洞的封闭框变为实心填充块、将无孔洞的开放精灵滑移至右侧边缘堆叠，孔洞的拓扑属性决定分支走向。

**输入结构**：黑(0)背景，约 14x16 网格。包含 4-6 个单色 4-连通前景对象，颜色取自蓝(1)、红(2)、绿(3)、黄(4)。其中一部分对象是空心矩形框（单像素厚的矩形边框，内部为背景色，即存在封闭孔洞），边框尺寸约 3x3 至 5x5；另一部分对象是开放精灵（4-连通单色小图形，3-8 像素，无封闭背景孔洞），形状因示例而异（不固定为特定外形）。所有对象互不重叠、互不相邻。网格右侧至少留有 8 列空白，以容纳滑移后的精灵堆叠。生成约束：不同开放精灵的行范围（bounding box 的行跨度）可以重叠，但各精灵滑移到右侧后不会超出网格边界。

**规则**：
1. 对每个前景对象做拓扑分类：若该对象的 4-连通像素围合出至少一个纯背景色区域（即存在封闭孔洞），则归为"封闭类"；否则归为"开放类"。
2. 封闭类处理：将该对象的所有边框像素擦除为背景(0)；将其原来围合的背景孔洞区域全部填充为该对象的原始颜色。即边框消失，孔洞变为实心色块。
3. 开放类处理：将该对象从原位擦除；然后将其整体（保持形状不变）水平滑移至网格最右侧。具体放置方式：保持对象 bounding box 的行位置不变，将 bounding box 的右边缘贴靠网格右边界（最后一列）；若该位置与已放置的其他开放类对象重叠，则向左移动直到不重叠为止。处理顺序：按各开放对象原始 bounding box 右边缘列号从大到小（最靠右的最先处理）。
4. 所有未被上述操作涉及的像素保持不变。

**关键洞察**：决定一个对象命运的不是它的颜色或大小，而是它是否围合出背景孔洞——这个拓扑属性将对象分流到两种截然不同的变换路径。

## 新题 2：象限镜像着色——模板反射 + 多数票决色

**组合逻辑**：[计数+多数标记色](已有) → [镜像+象限排布](创新：镜像方向由象限位置决定) → [重涂色](创新：涂色由投票结果而非查找表决定)

**来源原语**：计数(counting)+多数标记色涂色(majority_marker_color) ← e681b708；镜像(mirror)+象限排布(quadrant_layout)+双轴反射(biaxial_reflection) ← 67e8384a；重涂色(recolor) ← c64f1187/14754a24；图例模板(legend_template) ← c64f1187

**依赖链**：模板的形状定义了各象限要放置的图案轮廓；象限位置决定镜像方向（水平/垂直/双轴）；标记像素的多数票决色决定各象限图案的颜色。三者缺一不可——没有模板则无形状可放，没有镜像规则则方向错误，没有投票计数则颜色未知。

将左上角模板按象限位置做双轴镜像放入其余三个象限，每个象限中的模板颜色由该象限内标记像素的多数颜色决定。

**输入结构**：黑(0)背景，约 17x17 网格（奇数尺寸以保证中心分割线）。灰(5)单像素十字线将网格分为四个大小相等的象限（一条水平线贯穿整行，一条垂直线贯穿整列，交于网格中心点）。左上象限内有一个用青(8)绘制的非对称单色图案（4-连通，8-15 像素，形状因示例而异），占据象限内部分单元格。其余三个象限（右上、左下、右下）各包含 5-9 个孤立的单像素标记，颜色取自蓝(1)、红(2)、绿(3)、黄(4)，分布在象限内随机位置。生成约束：每个非模板象限中恰好有一种颜色的标记数严格多于其他任何颜色（无平局）。模板图案不具备水平或垂直对称性（以确保镜像后可区分方向）。

**规则**：
1. 识别左上象限中的青(8)图案为模板。
2. 对其余三个象限，分别统计该象限内各颜色标记像素的数量，选出数量最多的颜色作为该象限的"指定色"。
3. 将模板放入各象限，镜像方式由象限位置决定：右上象限 = 水平翻转（左右镜像）；左下象限 = 垂直翻转（上下镜像）；右下象限 = 水平+垂直双轴翻转（等价于 180 度旋转）。放置时，模板在目标象限内的相对位置与原模板在左上象限内的相对位置关于对应轴对称。
4. 将放入的模板像素从青(8)重涂为该象限的指定色。
5. 擦除所有原始标记像素（替换为背景色）。
6. 左上象限的原始青(8)模板保持不变。灰(5)分割线保持不变。

**关键洞察**：模板的形状通过镜像传播到各象限，但颜色信息并非来自模板本身，而是由各象限内分散标记的统计多数投票独立决定——形状和颜色的信息源完全分离。

## 新题 3：腔室内射线交替着色——奇偶反转由壁标记数决定

**组合逻辑**：[洪泛填充](已有) → [射线延伸+奇偶交替](创新：交替相位由外部条件翻转) ← [计数+条件判断](创新：壁标记奇偶数决定射线相位)

**来源原语**：洪泛填充(flood_fill)+区域邻接(region_adjacency) ← e681b708；射线延伸(ray_extend)+奇偶交替(parity_alternation)+交替填充至边界(alternating_fill_to_edge) ← 97999447；计数(counting) ← 39a8645d/e681b708；墙壁线段(wall_segment) ← e681b708；标记像素(marker_pixel) ← e681b708/dc433765

**依赖链**：洪泛填充划定腔室边界→确定哪些壁标记属于哪个腔室→计数壁标记→奇偶性翻转射线交替相位。射线的起点由腔室内的发射像素决定，终点由腔室壁决定，着色的奇偶相位由壁标记计数决定。这是一个三源汇聚结构：腔室分割、射线几何、标记计数三条信息流同时约束最终着色。

在由墙壁分隔的腔室中，从发射像素发出四方向射线并交替着色；壁上灰色标记的数量决定该腔室内射线的交替相位是否反转。

**输入结构**：黑(0)背景，约 16x16 网格。蓝(1)单像素线段组成墙壁，将网格划分为 3-5 个矩形腔室（墙壁由水平和垂直线段构成，线段端点接在网格边界或其他线段上）。每个腔室内恰好有一个"发射像素"，颜色取自红(2)、绿(3)、黄(4)、品红(6)、橙(7)——各腔室的发射颜色互不相同。在蓝(1)墙壁上散布若干灰(5)孤立标记像素（灰像素替换了该位置原本的蓝色，即它在墙壁线段上但颜色为灰而非蓝）。每个腔室周围墙壁上有 0-4 个灰标记。生成约束：每个腔室的发射像素不紧邻墙壁（与最近墙壁至少隔 1 个背景单元格）；各腔室至少 5x5 大小以容纳可见射线；灰标记不出现在墙壁交叉点上。

**规则**：
1. 将灰(5)标记视为墙壁的一部分（它们阻挡射线且不被射线覆盖），然后从背景色区域洪泛填充以识别各个腔室。
2. 对每个腔室的发射像素，向上、下、左、右四个方向延伸射线。每条射线从发射像素的相邻单元格开始，逐格延伸，遇到墙壁像素（蓝或灰）或网格边界时停止（停止位置不着色）。
3. 默认交替相位（正相）：从发射像素算起，距离为偶数(2,4,6,...)的射线格涂发射像素的颜色，距离为奇数(1,3,5,...)的射线格涂灰(5)。发射像素本身保持原色不变。
4. 统计每个腔室四周墙壁上灰(5)标记的总数。若总数为奇数，则该腔室的交替相位反转（反相）：奇数距离涂发射色，偶数距离涂灰(5)。若总数为偶数（含 0），保持正相不变。
5. 墙壁像素（蓝和灰标记）全部保持不变。

**关键洞察**：射线的几何模式（交替条纹）看似只取决于发射位置和墙壁距离，但其色彩相位还受到一个隐蔽的外部条件控制——腔室周边灰标记的奇偶性；这条规则仅靠单个示例几乎无法归纳，必须对比多个具有不同标记数量的腔室才能发现。

## 新题 4：双色对象对撞——滑移碰停、互换着色、缝隙填补

**组合逻辑**：[滑动+碰撞停止](已有) → [颜色互换](创新：互换发生在滑移之后) → [填充](创新：缝隙颜色取决于互换之前的少数色)

**来源原语**：滑动(slide)+碰撞停止(collision_stop) ← ac2e8ecf/9c56f360；颜色互换(color_swap)+对象内双色配对(bicolor_pairing_within_object)+同对象内互换(swap_within_same_object) ← 45737921；填充(fill) ← d5d6de2d/0a938d79；分离(separation) ← ac2e8ecf

**依赖链**：滑移产生空间邻接（原本分离的对象对碰到一起）→碰停留出1列缝隙→颜色互换改变对象外观→缝隙的填充色由互换前左侧对象的少数色决定。这是一条时序依赖链：缝隙颜色引用的是变换前的状态，而最终显示的对象颜色是变换后的状态——求解者必须同时追踪变换前后两个时态。

将水平配对的双色对象相向滑移至碰停（留1列缝隙），互换每个对象内的两种颜色，然后用左侧对象互换前的少数色填充缝隙列。

**输入结构**：黑(0)背景，约 14x18 网格。包含 2-3 对双色对象，每对由两个 3x3 实心正方形组成。每个 3x3 对象恰好使用两种非背景色，其中一种占 5 个像素（多数色），另一种占 4 个像素（少数色）。同一对的两个对象使用相同的两种颜色（但像素分布不同）。不同对使用不同的颜色组合。每对中的两个对象位于同一行带（bounding box 行范围相同），中间水平间隔 4-8 列背景。各对之间行带不重叠。颜色取自蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、橙(7)。生成约束：同一对中的两个对象的少数色和多数色可以不同（即左对象中 A 是多数色 B 是少数色，右对象中可能 A 是少数色 B 是多数色）。

**规则**：
1. 识别每对对象：两个 3x3 对象共享相同的两种颜色且行范围完全重合，即为一对。
2. 每对中的两个对象相向滑移：左对象右移、右对象左移，直到两者的 bounding box 之间恰好留有 1 列空隙（即 bounding box 水平间距 = 1）。
3. 滑移完成后，对每个 3x3 对象执行颜色互换：原多数色变为少数色，原少数色变为多数色（像素位置不变，仅颜色交换）。
4. 填充缝隙：两个对象之间的 1 列 x 3 行空隙（3 个像素），全部填充为**左侧对象在互换前的少数色**。
5. 其余所有像素保持背景色。

**关键洞察**：缝隙列的颜色不是来自任何对象的当前外观，而是来自左侧对象在颜色互换发生之前的少数色——求解者必须记忆变换前的状态来确定一个变换后才出现的元素的颜色。

## 新题 5：频率排序精灵图鉴——计数、排序、印章拼装

**组合逻辑**：[连通分量检测+形状相同](已有) → [计数+面积排序](创新：排序依据是出现频率而非面积) → [印章覆盖+擦除](创新：将去重后的精灵按频率序印入图鉴区)

**来源原语**：连通分量检测(connected_component_detection)+形状相同(shape_identity)+最高频精灵输出(most_frequent_sprite_output) ← 39a8645d；计数(counting) ← 39a8645d/e681b708；排序(sort)+面积排序(area_ordering) ← 4df5b0ae；印章覆盖(stamp_overlay) ← c64f1187/414297c0；擦除(erase) ← d5d6de2d/c62e2108；拼接(concatenate)+基线对齐排列(baseline_aligned_pack) ← 4df5b0ae

**依赖链**：连通分量检测→提取所有精灵→归一化为类型→计数每种类型的出现次数→按频率排序→在图鉴区从左到右印章排列。计数结果同时决定排序位置和（隐蔽规则）精灵在图鉴中的涂色深浅：出现次数最少的保留原色，每多出现一次则用灰(5)替换精灵中像素值最小的一个非背景像素。

将网格中散布的各类小精灵去重、按出现频率升序排列并印入底部图鉴条，同时擦除所有原始精灵。

**输入结构**：黑(0)背景，约 20x20 网格。主区域（上方 16-17 行）散布 10-18 个小型单色 4-连通精灵，每个精灵 bounding box 不超过 3x3。精灵共有 3-4 种不同类型（以归一化后的 bounding box 掩码 + 颜色判定类型是否相同）。每种类型出现次数互不相同（无平局），范围在 2-6 次。网格最底部 3 行是一条贯穿全宽的灰(5)水平条带（图鉴区），条带内初始全部为灰(5)。颜色取自蓝(1)、红(2)、绿(3)、黄(4)、橙(7)。生成约束：图鉴条宽度足以容纳所有去重类型（每类占 3 列 + 类间 1 列分隔）。

**规则**：
1. 检测主区域中所有 4-连通前景精灵（不含图鉴区）。
2. 将每个精灵归一化为其 bounding box 内的掩码（相对像素坐标 + 颜色），得到精灵类型。
3. 统计每种类型的出现次数。
4. 将去重后的类型按出现次数升序排列（出现最少的排最左）。
5. 在图鉴条中从左起第 1 列开始，依次印入每种类型的 3x3 bounding box 掩码（保留原色），相邻类型之间留 1 列灰(5)分隔。精灵在图鉴条的 3 行中垂直居中（若精灵高度 < 3 则顶部对齐）。
6. 擦除主区域中所有原始精灵（替换为背景色）。
7. 图鉴条中未被精灵占据的位置保持灰(5)。

**关键洞察**：输出并非简单地复制某个精灵（如 39a8645d 只输出最高频的一种），而是要对所有类型做聚合统计后按频率排成序列——排序依据不是几何属性（面积/位置），而是需要遍历全网格才能获得的频率信息。

## 新题 6：条形码编码的双轴镜像平铺——长度即重复数、颜色即边框色

**组合逻辑**：[控制条→数值编码](创新：条长度编码平铺重复数) + [平铺+双轴反射](已有) + [填充](创新：条颜色编码分隔线颜色)

**来源原语**：控制条(control_bar)+跨度对齐(span_alignment)+沿控制条重复(repeat_along_bar) ← c62e2108；平铺(tiling)+双轴反射(biaxial_reflection)+象限排布(quadrant_layout) ← 67e8384a；填充(fill) ← d5d6de2d/0a938d79；擦除(erase) ← c62e2108；精灵体(sprite) ← 39a8645d/4df5b0ae

**依赖链**：水平控制条的长度决定平铺列数，垂直控制条的长度决定平铺行数——几何长度被隐式编码为数值参数。控制条的颜色决定对应方向分隔线的颜色——同一个对象同时编码了数值和颜色两种信息。平铺模式为双轴反射（非简单复制），使相邻瓦片呈镜像衔接。三层信息（尺寸、颜色、反射方向）缺一不可。

从两根控制条中解码平铺网格的行列数和分隔线颜色，然后用双轴镜像反射方式将精灵平铺为该尺寸的阵列，并在瓦片间绘制彩色分隔线。

**输入结构**：黑(0)背景，约 22x22 网格。包含三个互不重叠的元素：(a) 一个非对称单色小精灵（4-连通，bounding box 为 3x3 或 3x4），颜色为青(8)；(b) 一根水平控制条（单像素高，长度 2-4），颜色为红(2)；(c) 一根垂直控制条（单像素宽，长度 2-4），颜色为绿(3)。三者在网格中相互分离，无对齐关系。精灵不具备水平或垂直对称性（以保证反射后可区分方向）。生成约束：设精灵 bounding box 宽 W 高 H，水平条长度 C，垂直条长度 R，则网格至少需 C*W + (C-1) 列宽和 R*H + (R-1) 行高以容纳完整平铺及分隔线。

**规则**：
1. 读取水平控制条的长度 C（像素数）和垂直控制条的长度 R（像素数）。
2. 构建一个 R 行 x C 列的瓦片阵列。每个瓦片是精灵 bounding box 的一个拷贝，方向由瓦片在阵列中的行列位置决定：
   - 行号和列号均从 0 起计。
   - 列号为奇数时，对该列的瓦片做水平翻转（左右镜像）。
   - 行号为奇数时，对该行的瓦片做垂直翻转（上下镜像）。
   - 若行号和列号均为奇数，则同时做水平+垂直翻转。
3. 在相邻瓦片列之间插入 1 列宽的分隔线，颜色为水平控制条的颜色（红(2)）。
4. 在相邻瓦片行之间插入 1 行高的分隔线，颜色为垂直控制条的颜色（绿(3)）。
5. 分隔线交叉点（行分隔与列分隔的交汇单元格）使用垂直控制条的颜色（绿(3)优先）。
6. 整个平铺阵列（含分隔线）的左上角放置在精灵原始 bounding box 的左上角位置。
7. 擦除原始的水平控制条和垂直控制条（替换为背景色）。

**关键洞察**：控制条不是像 c62e2108 中那样指示方向和终止线，而是通过自身长度隐式编码了一个整数参数（重复次数），同时通过自身颜色编码了另一个参数（分隔线颜色）——同一个几何对象承载了双重信息。

## 新题 7：重力坠落遇菱形平台——包络生成构建隐形阻挡面

**组合逻辑**：[包络生成](已有) → [擦除](已有) → [滑动(重力)+碰撞停止](创新：碰撞面不是原始对象而是由包络生成的菱形轮廓)

**来源原语**：包络生成(envelope_generation)+逐步收缩(stepwise_shrink)+菱形轮廓(diamond_outline)+实心条(solid_bar) ← c97c0139；擦除(erase) ← d5d6de2d/c62e2108；滑动(slide)+碰撞停止(collision_stop)+堆叠(stack) ← ac2e8ecf/9c56f360

**依赖链**：条的长度和位置→包络生成确定菱形轮廓→擦除原条→菱形轮廓成为碰撞面→精灵在重力下落时撞到菱形轮廓（而非条本身）而停止。包络生成和重力滑动通过碰撞面紧密耦合：没有包络就没有平台、没有重力就无需平台、擦除条使得碰撞面的来源变为间接推理。

水平条生成菱形包络轮廓后自身消失，小精灵在重力作用下坠落，遇到菱形轮廓或网格底部时停止。

**输入结构**：黑(0)背景，约 18x18 网格。上半区散布 3-5 个小型单色精灵（4-连通，3-6 像素，bounding box 不超过 3x3），颜色取自蓝(1)、红(2)、绿(3)、黄(4)，形状因示例而异。中下区有 2-3 根水平实心条（单像素高，长度 3-7 像素），颜色统一为橙(7)，各条分布在不同行，互不对齐。条的水平位置和长度各不相同。生成约束：精灵均位于所有条的上方；各精灵的列范围至少部分落入某根条的菱形包络范围内（即精灵下落路径上会遇到菱形平台）；不同精灵下落后不会相互重叠（列范围不重叠，或虽重叠但在不同的菱形层级上停住）。

**规则**：
1. 对每根橙(7)水平条，生成菱形包络轮廓：以条为中心水平线，半径 r = floor((条长度 - 1) / 2)，向上、向下各延伸 r 行。第 k 行（k = 1, 2, ..., r）的轮廓像素为：条水平中心向左右各缩进 k 格后的两个端点。轮廓像素着色为青(8)。条本身的像素也替换为青(8)（成为菱形的中心线）。
2. 擦除原始条——即上一步已将条的像素并入菱形轮廓（青色），不再保留橙色。
3. 将每个精灵向下滑移（重力），保持列位置和形状不变：
   - 精灵逐行下移，直到其最底行像素的下一行遇到青(8)菱形轮廓像素、另一个已停止的精灵像素、或网格底部边界。
   - 精灵停在碰撞位置的上方（不覆盖碰撞像素）。
   - 处理顺序：按精灵初始位置从下到上（最低的精灵最先处理），以保证先落位的精灵可成为后续精灵的碰撞面。
4. 精灵原位置擦除为背景色。青(8)菱形轮廓和所有非碰撞区域的背景保持不变。

**关键洞察**：精灵并非直接落在条上，而是落在条"不可见的影响范围"——菱形包络轮廓上。条越长，菱形越大，能接住越偏离条正下方的精灵；条本身在输出中已不存在，求解者必须先从条长度推算出菱形平台的形状和位置，再模拟重力坠落。
