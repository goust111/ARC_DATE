## 新题 1：L 标记编码区域重力方向

**组合逻辑**：[检测/朝向对应角](将 L 朝向从"选择外角"创新为"编码重力方向") + [重力下落](从全局统一方向创新为按区域独立方向) + [擦除](清除方向标记)

**来源原语**：朝向对应角/facing_corner（b745798f）、角落标记/corner_marker（b745798f）、重力下落/gravity_drop（88e364bc）、封闭区域/enclosed_region（88e364bc/00d62c1b）、碰撞停止/collision_stop（88e364bc）、擦除/erase（1a07d186）

**依赖链**：L 标记的朝向决定该区域的重力方向 → 重力方向决定可移动像素的滑动轨迹 → 区域边界决定碰撞停止位置。三者缺一不可：不解码朝向则方向未知；不识别区域则碰撞边界不存在；不施加重力则无变换。

将封闭区域内的 L 标记朝向解码为重力方向，驱动同区域内的散落像素沿该方向滑动堆叠，然后擦除标记本身。

**输入结构**：约 13x13 的网格，黑(0)背景。灰(5)线段将网格分隔为 3~4 个互不连通的矩形封闭区域（灰线宽 1 像素，构成完整的矩形隔墙）。每个区域内部包含：(a) 恰好一个单色 4-连通 3 像素 L 形标记（占据 2x2 边界框的三个格子），颜色为红(2)；(b) 1~3 个散落的单像素，颜色各异（从蓝(1)、绿(3)、黄(4)、橙(7)中选取），不与 L 标记相邻。不同区域内的 L 标记朝向不同（四种朝向至少出现两种）。生成约束：每个区域至少 4x4 大小，散落像素在其重力方向上有足够空间滑动至少 1 格。

**规则**：
1. 识别灰(5)隔墙围成的所有矩形封闭区域。
2. 在每个区域中定位红(2) L 标记，确定其朝向。L 标记占据 2x2 框的三格，空缺格的位置即为 L 的"开口方向"。重力方向的映射规则为：开口朝右下 → 重力向左上；开口朝左下 → 重力向右上；开口朝右上 → 重力向左下；开口朝左上 → 重力向右下。即重力方向与开口方向相反，沿 45 度对角线。
3. 擦除该区域内的红(2) L 标记（置为黑(0)背景）。
4. 将该区域内所有非背景、非隔墙的散落像素沿重力方向的两个分量依次滑动：先沿垂直分量滑动直到碰到隔墙或区域边界或另一像素，再沿水平分量滑动直到碰到隔墙或区域边界或另一像素。处理顺序：沿重力方向，距目标角最远的像素先处理。
5. 灰(5)隔墙保持不变。

**关键洞察**：L 标记不是装饰而是方向编码器——其开口方向的反向即为区域重力。需要对比多个示例（不同朝向、不同区域）才能归纳出开口方向与重力方向之间的反向映射规则。

## 新题 2：单色行计数决定非单色行的缩放倍率

**组合逻辑**：[检测/单色行标记](保留原逻辑) → [计数](将"前景像素计数"创新为"单色行计数") → [像素放大](将"整体缩放"创新为"按行选择性缩放") + [重涂色](将单色行重涂为统一颜色)

**来源原语**：检测/detection（25d8a9c8）、单色行标记否则黑/uniform_row_marked_else_black（25d8a9c8）、计数/counting（ac0a08a4）、前景数为放大系数/foreground_count_as_scale_factor（ac0a08a4）、像素放大/pixel_scale（ac0a08a4）、重涂色/recolor（25d8a9c8）

**依赖链**：检测哪些行是单色行 → 计数这些行的数量 N → N 成为非单色行的垂直缩放倍率 → 单色行自身不缩放但被重涂。单色行同时扮演"参数提供者"和"例外对象"的双重角色，这种自指关系需要多示例对比才能发现。

统计输入中所有像素完全相同的行的数量 N，将所有非单色行垂直拉伸 N 倍，同时将单色行本身重涂为灰色且不拉伸。

**输入结构**：约 5x7 的小网格（5 列 7 行），使用黑(0)、蓝(1)、红(2)、绿(3)、黄(4) 五种颜色。部分行所有单元格颜色相同（单色行），其余行包含至少两种不同颜色（混色行）。单色行的颜色可以各不相同。单色行数量在不同示例中不同（如一个示例有 2 行单色行，另一个有 3 行）。生成约束：至少有 2 行单色行且至少有 2 行混色行；网格宽度在所有示例中一致。

**规则**：
1. 逐行检查：若某行所有单元格颜色完全相同，则标记为"单色行"。
2. 计数所有单色行的数量，记为 N。
3. 构造输出网格，宽度与输入相同，高度 = 单色行数 x 1 + 混色行数 x N。
4. 从输入顶部到底部依次处理每一行：若该行是单色行，将其所有像素重涂为灰(5)，作为输出中的 1 行写入；若该行是混色行，将其原样复制 N 次（垂直拉伸 N 倍）写入输出。
5. 各行在输出中的相对顺序与输入一致。

**关键洞察**：单色行的自指性——它们的数量决定了其他行的缩放倍率，而自身却不被缩放。仅看单个示例时，缩放倍率可能与其他特征（如颜色种类数）巧合一致，必须对比多个示例（不同数量的单色行）才能确认"单色行计数=缩放因子"这一规则。

## 新题 3：对称性检测选择洪泛填充目标，同行对称瓦片提供填充颜色

**组合逻辑**：[对称检测](保留原逻辑，作为决策门) → [洪泛填充](从"全局填充封闭区域"创新为"按对称性条件选择性填充") + [同色配对](创新为"同行瓦片间的颜色借用")

**来源原语**：对称检测/symmetry_detect（662c240a）、选无对角对称瓦片/select_asym_tile（662c240a）、瓦片/tile（662c240a）、洪泛填充/flood_fill（00d62c1b）、封闭区域/enclosed_region（00d62c1b）、拓扑内外/topological_in_out（00d62c1b）、仅填封闭内部/fill_enclosed_only（00d62c1b）

**依赖链**：对称性测试决定哪些瓦片的封闭区域需要填充（非对称→填充，对称→不填）→ 填充颜色不是固定值，而是从同一瓦片行中对称瓦片的轮廓颜色借用 → 因此对称瓦片同时担任"排除对象"和"颜色源"的双重角色。

在瓦片网格中，仅对关于主对角线不对称的瓦片执行封闭区域洪泛填充，填充颜色取自同一行中对称瓦片的轮廓颜色。

**输入结构**：约 14x14 的网格，黑(0)背景。网格被灰(5)分隔线（宽 1 像素）划分为 3x3 共 9 个大小相等的正方形瓦片（每个约 4x4）。每个瓦片内部包含一个单色闭合轮廓（4-连通，围成至少 1 个背景像素的内部区域），轮廓颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取，不同瓦片颜色可以相同也可以不同。部分瓦片的轮廓图案关于主对角线对称（即转置后与自身相同），其余不对称。生成约束：每一行瓦片（3 个瓦片）中恰好有 1 个对称瓦片和 2 个非对称瓦片；对称瓦片的轮廓颜色与同行非对称瓦片的轮廓颜色不同。

**规则**：
1. 将网格沿灰(5)分隔线切分为 3x3 = 9 个瓦片。
2. 对每个瓦片，提取其内部图案（不含分隔线），判断是否关于主对角线对称：将图案转置，若与原图案逐像素相同则为对称，否则为非对称。
3. 对于对称瓦片：保持不变，不做任何操作。
4. 对于非对称瓦片：找到该瓦片所在行（同一水平行的 3 个瓦片中）的那个对称瓦片，读取其轮廓颜色 C。用颜色 C 洪泛填充该非对称瓦片的闭合轮廓内部区域（轮廓本身保留原色不变，仅内部背景像素被重涂为 C）。
5. 灰(5)分隔线保持不变。

**关键洞察**：对称性检测不仅是筛选器（决定谁被填充），还间接决定了填充颜色（通过交叉引用同行的对称瓦片）。需要对比多个示例才能发现"颜色来自同行对称瓦片"这一跨瓦片引用规则——单个示例中颜色来源可能有多种合理解释。

## 新题 4：种子生长构建容器，散落像素受重力下落入容器

**组合逻辑**：[生长/间隔行生成](将"向下生长"创新为"向上生长构建屏障结构") → [重力下落/碰撞停止](在生长结构形成的容器中执行) + [擦除/无匹配色则删除](清除未被容器接住的像素)

**来源原语**：生长/grow（af726779）、间隔行生成/gap_row_generate（af726779）、相邻间隔/adjacent_gap（af726779）、种子行/seed_row（af726779）、重力下落/gravity_drop（88e364bc）、碰撞停止/collision_stop（88e364bc）、可移动像素/movable_pixel（88e364bc）、擦除/erase（1a07d186）

**依赖链**：种子像素的间距决定生长结构的形态 → 生长结构构成重力下落的碰撞壁 → 散落像素的最终位置由容器形状决定 → 落在容器外的像素被擦除。生长步骤的输出是重力步骤的输入前提。

底部种子行向上生长出倒三角分支结构，该结构形成碰撞屏障；上方散落的彩色像素向下坠落，碰到屏障或底边时停止，未被任何屏障拦截而落到底边以下（超出网格）的像素被删除。

**输入结构**：约 15x15 的网格，绿(3)背景。底部行（第 14 行，0-indexed）包含若干橙(7)种子像素，种子之间有绿(3)背景间隔，间隔宽度不一。网格上半部分（第 0~7 行左右）散布着若干孤立单像素，颜色从蓝(1)、红(2)、黄(4)、品红(6)中选取，每个像素四周均为背景（不与其他前景像素 4-连通相邻）。生成约束：种子像素至少 3 个；散落像素至少 4 个；种子间至少存在一个宽度为 1 的间隔（保证生长可产生子代）。

**规则**：
1. 从底部种子行开始，向上执行间隔繁殖生长：在当前活跃行上方第 2 行，对于每对相邻活跃像素，若它们在当前活跃行之间的中间位置是背景，则在上方第 2 行的该中间列放置一个子代像素。第一代子代颜色为品红(6)，第二代为橙(7)，依此交替。当某代无法产生任何子代或下一代行超出网格顶部时，生长停止。
2. 生长完成后，所有生长结构像素（橙(7)种子 + 所有生长子代）成为不可移动的固定屏障。
3. 对每个散落的彩色像素施加向下重力：该像素沿其所在列向下移动，遇到第一个屏障像素时停在该屏障正上方一格。若该列下方无任何屏障像素，则该像素移动到底部行；若底部行该列已被种子占据，则停在种子正上方一格。
4. 处理顺序：按行从下到上处理散落像素（行号大的先处理），同行则从左到右。先落下的像素本身也成为后续像素的碰撞障碍。
5. 保留所有屏障像素的颜色不变。

**关键洞察**：种子间距编码了容器的几何形状——间距越小，生长产生的分支越密、越早终止；间距越大，分支延伸越高。散落像素的最终位置完全由这个隐式容器结构决定。需要对比多个示例（不同种子间距）才能理解生长规则如何塑造容器。

## 新题 5：矩形中心十字线构建滑轨，同色像素沿轨滑向矩形

**组合逻辑**：[连线/画布全长十字线](保留原逻辑，生成轨道网络) + [滑动/同色配对](将"滑向满行列条"创新为"沿十字轨道滑向同色矩形中心") + [擦除/无匹配色则删除](清除不在轨道上的像素) + [原对象遮挡叠加](矩形覆盖轨道)

**来源原语**：连线/draw_line（41e4d17e）、画布全长十字线/canvas_spanning_cross（41e4d17e）、空心矩形/hollow_rectangle（41e4d17e）、中心对齐/center_alignment（41e4d17e）、原对象遮挡叠加/object_occludes_overlay（41e4d17e）、滑动/sliding（1a07d186）、同色配对/same_color_pairing（1a07d186）、碰撞阻挡/collision_blocking（1a07d186）、无匹配色则删除/unmatched_deleted（1a07d186）、孤立像素/isolated_pixel（1a07d186）

**依赖链**：矩形位置决定十字线位置 → 十字线构成可滑动轨道 → 孤立像素是否在某条同色矩形的轨道上决定其命运（滑动 vs 删除）→ 矩形最终覆盖在轨道之上。四步逻辑中，轨道生成、颜色匹配、空间约束缺一不可。

为每个彩色空心矩形绘制贯穿画布的十字线轨道，然后将同色孤立像素沿轨道滑向矩形，不在任何同色轨道上的像素被删除。

**输入结构**：约 15x15 的网格，黑(0)背景。包含 2~3 个小型空心矩形（边框宽 1 像素、内部为背景，边框 4-连通，尺寸约 3x3 到 5x5），每个矩形使用不同的前景颜色（从蓝(1)、红(2)、绿(3)中选取）。矩形之间互不接触，且任意两个矩形的中心行互不相同、中心列也互不相同。网格中另有 4~8 个散落的孤立单像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取——部分颜色与某个矩形匹配，部分颜色不与任何矩形匹配（如黄(4)）。生成约束：每个矩形至少有 1 个同色孤立像素恰好在其中心行或中心列上；至少有 1 个孤立像素不在任何同色矩形的中心行或中心列上。

**规则**：
1. 对每个空心矩形，计算其中心坐标（上下边中间行、左右边中间列）。
2. 绘制轨道：沿每个矩形的中心行画一条贯穿整行的灰(5)水平线，沿中心列画一条贯穿整列的灰(5)垂直线。绘制顺序：按矩形中心行从上到下；后绘制的轨道覆盖先绘制的。
3. 将原始矩形（含边框颜色）重新绘制在轨道之上（矩形像素遮挡轨道像素）。
4. 对每个孤立像素：若其颜色与某矩形颜色相同，且该像素恰好位于该矩形的水平或垂直轨道上（即与矩形中心同行或同列），则该像素沿轨道方向朝矩形中心滑动，在碰到矩形外边框时停止（停在边框外侧相邻格）。若像素同时在水平和垂直轨道上（即恰在交叉点），则不移动。
5. 若孤立像素的颜色不与任何矩形匹配，或虽匹配但不在对应轨道上，则删除该像素（置为背景）。
6. 滑动后像素保留原色，覆盖轨道颜色。

**关键洞察**：矩形既是视觉对象又是轨道生成器——其位置决定了轨道网络的拓扑。一个像素能否存活取决于两个独立条件的交集：颜色匹配 AND 空间上位于匹配轨道。仅凭单个示例难以区分"颜色匹配即滑动"和"颜色匹配且在轨道上才滑动"这两种候选规则。

## 新题 6：逐行跨度填充揭示面积，按面积排序后紧凑堆叠

**组合逻辑**：[填充/逐行跨度填充](保留原逻辑，将稀疏轮廓变为实心) → [排序/位置排序](将"按位置排序"创新为"按填充后面积排序") → [堆叠/对齐紧凑排布](保留原逻辑) + [裁剪](提取各形状的最小边界框)

**来源原语**：填充/fill（22168020）、逐行跨度填充/row_span_fill（22168020）、行内边界配对/row_boundary_pairing（22168020）、轮廓线/outline（22168020）、堆叠/stacking（4acc7107）、排序/sorting（4acc7107）、对齐紧凑排布/aligned_compact_layout（4acc7107）、裁剪/crop（662c240a）、单色前景对象/monochrome_foreground_object（4acc7107）

**依赖链**：逐行跨度填充将稀疏轮廓变为实心形状 → 实心面积（像素计数）成为排序键 → 排序决定堆叠顺序 → 裁剪+堆叠产生最终输出。填充步骤的结果直接决定排序结果——如果不执行填充，轮廓像素数量接近而面积差异大的形状会被错误排序。

**输入结构**：约 12x18 的网格（12 列 18 行），黑(0)背景。包含 3~4 个单色 8-连通轮廓，每个轮廓在其占据的每一行恰好有 2 个前景像素（左右边界对），形成类似菱形或梯形的斜边轮廓。不同轮廓使用不同颜色（蓝(1)、红(2)、绿(3)、橙(7)），轮廓之间不重叠（行范围可重叠，但列范围不重叠）。不同轮廓的行跨度不同、宽度不同，因此填充后面积各不相同。生成约束：至少有两个轮廓的边界像素总数接近（差 <= 2），但填充后面积差异明显（差 >= 5），以确保必须填充才能正确排序。

**规则**：
1. 对每个轮廓，逐行找到该行的两个边界像素，将它们之间（含端点）的所有像素涂为该轮廓的颜色，得到实心形状。
2. 计算每个实心形状的面积（前景像素总数）。
3. 按面积从小到大排序。面积相同时，按原始最上方行号从小到大排序（行号小的排前面）。
4. 将排好序的形状依次裁剪为最小边界框。
5. 在与输入同宽的输出网格中，从底部向上依次放置裁剪后的形状：面积最大的贴底、面积最小的在最上方。每两个相邻形状之间留 1 行黑(0)间隔。所有形状左对齐（边界框左边缘对齐到输出网格第 0 列）。输出高度 = 所有裁剪后形状高度之和 + (形状数 - 1) 行间隔。

**关键洞察**：稀疏轮廓隐藏了真实面积——两个轮廓的边界像素数量可能接近，但填充后面积差异很大（一个窄高、一个矮宽）。排序键是填充后面积而非边界像素数或边界框面积。需要对比多个示例才能确认面积而非其他几何量是排序依据。

## 新题 7：等差间距补全横竖条后在交叉点标记特殊颜色

**组合逻辑**：[补全/等差递推](保留原逻辑，补全缺失的条) → [重涂色/交叉区换前景色](将"两色交叉互换"创新为"交叉点统一标记为第三种颜色") + [描边/交叉邻域环涂色](将"环形描边"创新为"交叉点单像素重涂")

**依赖链**：识别现有条的等差间距 → 补全缺失条 → 完整条网络产生所有交叉点 → 交叉点被重涂为第三种颜色。补全步骤改变了交叉点的数量和位置——缺失条被补全后产生的新交叉点是仅凭原始输入无法预测的。

**输入结构**：约 15x15 的网格，黑(0)背景。包含若干贯穿全宽的蓝(1)水平条（宽 1 像素）和若干贯穿全高的红(2)垂直条（宽 1 像素）。水平条的行位置构成一个等差数列（公差 d_h >= 2），但其中 1~2 个成员缺失。垂直条的列位置构成另一个等差数列（公差 d_v >= 2），其中也有 1~2 个成员缺失。现有的横竖条交叉处显示的颜色为蓝(1)或红(2)之一（取决于绘制顺序，但这不影响输出）。生成约束：水平条至少出现 3 个（缺失前至少 4 个成员）；垂直条至少出现 3 个（缺失前至少 4 个成员）；等差数列的首末成员均存在（便于推断公差）。

**规则**：
1. 分别收集所有蓝(1)水平条的行坐标和所有红(2)垂直条的列坐标。
2. 对行坐标序列，求相邻差的最大公约数作为公差 d_h，确定完整的等差数列范围（以最小行坐标为首项、最大行坐标为末项），补全所有缺失的行——在缺失行位置绘制蓝(1)贯穿全宽的水平条。
3. 对列坐标序列同理，求公差 d_v，补全缺失的红(2)垂直条。
4. 在补全后的完整网格中，所有横条与竖条交叉的像素（即同时属于某条水平条和某条垂直条的像素）统一重涂为黄(4)。
5. 非交叉的条像素保留原色（蓝或红）。

**关键洞察**：补全步骤不是简单的"画更多线"——它通过等差推断产生了额外的交叉点。输出中黄(4)标记的数量 = 完整横条数 x 完整竖条数，而不是原有可见交叉数。需要多个示例（不同的缺失位置和公差）来确认等差补全规则和交叉标记规则是联动的。

## 新题 8：深度交替着色的墙隙分支射线

**组合逻辑**：[射线延伸/从边缘推进](保留原逻辑) + [分支/墙段开口分支](保留原逻辑) + [交替变色](将"生长交替"创新为"射线深度交替") → 三者融合产生深度编码的分支树

**来源原语**：射线延伸/ray_extend（f9a67cb5）、分支/branch（f9a67cb5）、墙段开口分支/branch_at_opening（f9a67cb5）、从边缘推进/advance_from_edge（f9a67cb5）、边缘标记/edge_marker（f9a67cb5）、墙段/wall_segment（f9a67cb5）、交替变色/alternating_color（af726779）

**依赖链**：射线方向由边缘标记位置决定 → 墙段位置决定分支点 → 墙段缺口位置决定分支方向 → 穿越的墙段数量决定当前段的颜色。深度着色依赖于分支拓扑，而分支拓扑依赖于墙段布局。整个推理链不可分割。

从边缘标记向内发射射线，遇到墙段时在其缺口处分支继续，每穿越一道墙颜色交替一次，最终生成一棵深度编码的分支树。

**输入结构**：约 15x15 的网格，黑(0)背景。恰好 1 个蓝(1)标记像素位于网格的某条边（上/下/左/右边）。网格内部有 2~4 道灰(5)墙段，每道墙是一条水平或垂直的连续灰色线段（长度 3~10 像素），与射线前进方向垂直。每道墙段至少有 1 个像素宽的缺口（墙段不贯穿全宽/全高，缺口处为背景色）。墙段之间互不接触。生成约束：标记像素的射线前进方向垂直于第一道墙；每道墙的缺口至少 1 个且至少有 1 个缺口在射线可达路径上；墙段按与标记像素的距离排列，不会出现射线绕过墙的情况。

**规则**：
1. 从蓝(1)边缘标记出发，向网格内部发射射线（方向垂直于标记所在边，指向内部）。
2. 射线沿前进方向逐像素绘制。初始段颜色为蓝(1)（深度 0）。
3. 当射线遇到灰(5)墙段时停止前进。找到该墙段的所有缺口（墙段同一行/列中不属于墙的背景位置，且在墙段的列/行范围内）。在墙段面向射线来源的一侧，绘制从射线终点沿墙方向延伸到每个缺口对面的连接线，颜色与当前射线段相同。
4. 从每个缺口位置（墙段另一侧），生成一条新的分支射线，继续沿原始前进方向前进。新分支的颜色按深度交替：深度 0 蓝(1)、深度 1 红(2)、深度 2 蓝(1)、深度 3 红(2)……（每穿越一道墙深度加 1，颜色在蓝(1)和红(2)之间交替）。
5. 每条分支射线遇到下一道墙时重复步骤 3~4，深度递增。
6. 射线到达网格边界时停止。
7. 灰(5)墙段像素保持不变。当射线像素与墙段像素重叠时，保留墙段颜色。

**关键洞察**：颜色交替编码了射线穿越的墙段数量——观察某段射线的颜色即可推断其穿越了偶数还是奇数道墙。分支的拓扑结构由墙段缺口决定，同一射线可在一道墙上产生多个分支。需要多个示例（不同的墙段数量和缺口位置）才能同时归纳出"分支规则"和"深度着色规则"。

## 新题 9：距离调制的角落扩展与重叠分层

**组合逻辑**：[像素放大/扩展至外角](将"固定臂长"创新为"距离调制臂长") + [重涂色](用于重叠冲突解决) + [距离/距离决定阶梯高度](将"距离决定高度"创新为"距离决定扩展幅度和优先级")

**来源原语**：像素放大/pixel_scale（b745798f）、扩展至外角/expand_to_corner（b745798f）、角落标记/corner_marker（b745798f）、朝向对应角/facing_corner（b745798f）、距离/distance（b8cdaf2b）、距离决定阶梯高度/distance_determines_step_height（b8cdaf2b）、重涂色/recolor（ba97ae07）

**依赖链**：L 标记朝向决定目标角 → 标记到目标角的曼哈顿距离决定扩展臂长 → 多标记指向同一角时，距离决定分层优先级（近者覆盖远者）。距离同时控制尺寸和优先级，这种双重作用是源题中不存在的。

每个 L 标记扩展为其目标角的角 L，臂长由标记到角的距离决定；多标记竞争同一角时，距离较近的覆盖较远的。

**输入结构**：约 11x11 的奇数正方形网格，黑(0)背景。包含 3~5 个单色 4-连通 3 像素 L 形标记（每个占 2x2 框的三格），每个标记颜色不同（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取）。标记分布在网格内部各处。至少有两个标记的 L 朝向指向同一个外角（四角之一）。生成约束：所有标记互不相邻（任意两个标记的 2x2 框不重叠也不 4-连通相邻）；至少一个角被两个以上标记指向；各标记到其目标角的曼哈顿距离互不相同。

**规则**：
1. 清除网格为黑(0)背景。
2. 对每个 L 标记，确定其朝向及对应的目标外角（与 b745798f 相同的朝向→角映射：L 的开口方向指向的外角即为目标角）。
3. 计算每个标记中心（2x2 框中心取左上格）到其目标角的曼哈顿距离 D。
4. 该标记扩展为目标角的角 L，两条臂沿角的两个边方向延伸，每条臂长度为 ceil(D / 2) 像素（含角点）。
5. 绘制顺序：按 D 从大到小绘制（距离远的先画）。后绘制的角 L 覆盖先绘制的。因此当多个标记指向同一角时，距离最近的标记的颜色最终可见于角落处，距离较远的标记的臂可能部分被覆盖。
6. 不指向任何角的标记（不存在此情况，每个 L 都有唯一目标角）。

**关键洞察**：距离的双重角色——它同时决定扩展的尺寸（臂长）和绘制的优先级（近者后画，覆盖远者）。在源题 b745798f 中所有标记臂长相同且不存在冲突，在源题 b8cdaf2b 中距离仅决定高度不涉及冲突。这里距离同时绑定了尺寸和分层，需要多示例对比才能发现两个规则共享同一参数。

## 新题 10：下采样压缩格点后绘制端点转向路径

**组合逻辑**：[下采样/保留偶索引交叉](保留原逻辑，压缩稀疏格点) → [路径绘制/有端点则转弯](将"原始网格路径"创新为"压缩后网格路径") + [无端点则延伸](保留原逻辑)

**来源原语**：下采样/downsample（68b67ca3）、保留偶索引交叉/keep_even_crossings（68b67ca3）、奇偶索引分离/even_odd_index_separation（68b67ca3）、分隔行列/separator_rows_and_columns（68b67ca3）、路径绘制/path_drawing（29700607）、连线/line_drawing（29700607）、边缘源像素/edge_source_pixel（29700607）、同色端点/same_color_endpoint（29700607）、同色配对/same_color_matching（29700607）、有端点则转弯/endpoint_triggers_turn（29700607）、无端点则延伸/no_endpoint_extends（29700607）

**依赖链**：下采样移除分隔行列 → 压缩后的格点重新定义了像素之间的邻接关系 → 路径绘制在压缩后的拓扑上执行 → 源像素和端点的位置在压缩后才能正确度量距离和方向。下采样不是预处理而是改变了路径绘制的空间语义。

移除稀疏格点中的分隔行列得到紧凑网格，然后在紧凑网格中从顶行源像素向下绘制路径，遇到同色端点时水平转弯。

**输入结构**：约 14x14 的偶数尺寸网格，黑(0)背景。所有奇数索引行和奇数索引列均为黑(0)背景（分隔行列）。偶数行偶数列的交叉位置（"格点"）包含有意义的颜色。第 0 行（偶数行）的若干格点位置有一段连续的非背景像素，每个像素颜色不同（如蓝(1)在列 0、红(2)在列 2、绿(3)在列 4），构成顶部源像素带。其余偶数行偶数列的格点位置大部分为黑(0)背景，但散布着 0~3 个端点像素，每个端点的颜色与顶部源像素带中的某个颜色相同。每种源颜色最多有 1 个端点。生成约束：至少有 1 种源颜色有端点，至少有 1 种源颜色无端点；端点不在第 0 行；格点坐标均为偶数。

**规则**：
1. 下采样：保留所有偶数行偶数列交叉处的像素，丢弃所有奇数行和奇数列。输出网格的高度和宽度均为输入的一半。
2. 在压缩后的网格中，识别顶行（对应原始第 0 行）中的连续非背景像素带，每个像素为一个"源"。
3. 对每个源像素（颜色 C，位于压缩后网格的列 j）：
   a. 在压缩网格中寻找颜色为 C 的非顶行像素作为端点。
   b. 若存在端点（位于行 r_e、列 c_e）：从 (0, j) 向下画垂直线段到行 r_e（含端点），然后从 (r_e, j) 向端点 (r_e, c_e) 画水平线段（含端点）。整条路径颜色为 C。
   c. 若不存在端点：从 (0, j) 向下画垂直线段直到压缩网格的底行。颜色为 C。
4. 路径像素覆盖背景像素。当两条路径像素重叠时，后绘制的覆盖先绘制的（绘制顺序按源像素从左到右）。
5. 非路径的背景像素保持黑(0)。

**关键洞察**：在原始稀疏网格中，源像素与端点之间被大量分隔行列隔开，路径的连通性看起来不直观。下采样将分隔行列去除后，源和端点之间的空间关系变得清晰，路径才能有意义地绘制。两步逻辑的耦合在于：不做下采样就无法正确建立源-端点的空间对应关系（距离和方向在稀疏网格中被分隔行列扭曲）。
