## 新题 1：旋转条带与跨色交叉标记

**组合逻辑**：[旋转(rotate)](已有，从单色扩展到多色场景) + [跨色重叠变色(cross_color_overlap_recolor)](已有，从阶梯扩展触发改为旋转触发) → 全局交叉检测

**来源原语**：旋转(rotate)、中心点不变(center_fixed) ← f0f8a26d；跨色重叠变色(cross_color_overlap_recolor) ← 58e15b12；单像素宽条(thin_bar) ← f0f8a26d

**依赖链**：旋转决定每根条带的最终占据位置 → 多色条带的占据区域产生交叉 → 交叉像素触发重涂色规则。删除旋转则无法确定交叉位置；删除交叉检测则输出只是旋转结果，不涉及颜色变换。

将多色细条各自绕中心旋转 90 度后，不同颜色交叉的像素统一染为品红(6)。

**输入结构**：
- 背景为黑(0)，网格约 15x15。
- 网格中散布 3~5 根单像素宽的实心直条（水平或竖直，奇数长度，3~9 像素），每根一种颜色，使用蓝(1)、红(2)、绿(3)、黄(4) 等互不相同的颜色。
- 各条带互不接触（4-连通意义上不相邻），且每根条带绕自身中心旋转 90 度后仍完全在网格内。
- 品红(6) 不出现在输入中。
- 生成约束：条带的中心点行列坐标互不相同，保证旋转后至少存在一对不同颜色条带的交叉。

**规则**：
1. 清空画布为黑(0)。
2. 对每根条带，保持其中心像素位置和长度不变，将水平条变为竖直条、竖直条变为水平条（即绕中心旋转 90 度）。
3. 将所有旋转后的条带绘制到画布上。对于每个像素位置：
   - 若仅被一根条带覆盖，涂该条带的颜色。
   - 若被两根或更多不同颜色的条带覆盖，涂品红(6)。
   - 若未被任何条带覆盖，保持黑(0)。
4. 同色条带不会交叉（每种颜色只有一根条带）。

**关键洞察**：输入中条带互不接触，旋转后才产生交叉；品红像素的位置无法直接从输入读取，必须先完成所有旋转再做全局交叉检测。隐蔽规则在于品红的触发条件——需对比多个示例才能确认"仅限不同颜色交叉"而非"所有重叠"。

## 新题 2：碎片补全后按图例膨胀光环

**组合逻辑**：[补全(completion)](已有) + [图例映射(legend_mapping)](已有) → [膨胀(dilate)](已有，作用于补全后的完整形状而非原始对象)

**来源原语**：补全(completion)、平移对齐(translate_align)、模板精灵体(template_sprite)、碎片(fragment) ← fd096ab6；膨胀(dilate)、颜色图例(color_legend)、图例映射(legend_mapping)、封闭孔洞(enclosed_hole)、孔洞保留不填(holes_preserved) ← 5adee1b2

**依赖链**：补全决定每个碎片的完整形状和边界框 → 完整形状确定膨胀区域 → 图例映射决定光环颜色。补全改变了膨胀的几何输入（碎片不完整时无法确定正确的边界框）；图例改变了膨胀的颜色输出。三者缺一不可。

用碎片锚定的模板位置补全每个彩色副本，再按左侧图例为每种颜色的完整副本绘制一圈光环色带。

**输入结构**：
- 背景为黑(0)，网格约 18x20。
- 左侧边缘有 2~3 个 2x2 图例块，每个图例块左列为某种前景色、右列为该色对应的光环色。图例块之间至少隔一行黑像素。图例中不使用品红(6)。
- 网格中央偏右有一个灰(5) 色的完整模板形状：一个 4-连通单色图形，5~10 像素，可含 1 个封闭孔洞（孔洞内为黑像素）。模板形状不规则（非简单矩形）。
- 另有 2~3 组彩色碎片，每组一种颜色（与图例左列颜色对应），每组碎片是模板形状的一个平移副本的部分像素（至少 2 像素）。不同颜色的碎片放置位置互不重叠，且补全后的副本互不重叠、不与模板重叠。
- 生成约束：每组碎片对应唯一一个平移位置（碎片的像素是该位置模板掩码的真子集）。补全后所有副本的膨胀区域（边界框扩展 1 像素并裁剪到网格内）不重叠。

**规则**：
1. 识别灰(5) 色连通分量为模板掩码。
2. 对每种非灰前景色，找到唯一的平移偏移使得模板掩码平移后能覆盖该色所有已有像素。将模板掩码在该偏移位置的所有缺失像素补上该色，得到该色的完整副本。
3. 对每个完整副本，取其紧边界框向四周各扩展 1 像素（裁剪到网格边界内）。在扩展区域中，将黑(0) 背景像素涂为图例映射的光环色，但模板孔洞对应位置（副本内部被黑像素完全包围的连通区域）不涂光环色，保持黑(0)。
4. 灰色模板本身不做膨胀处理，保持原样。
5. 绘制顺序：先画所有补全像素，再画所有光环像素。光环像素不覆盖任何已有前景像素。

**关键洞察**：碎片只是模板的部分像素，补全后的完整形状才能确定正确的膨胀边界框；若直接对碎片做膨胀，光环形状会错误。孔洞保留规则需对比多个示例才能归纳——有孔洞的副本与无孔洞位置的副本光环表现不同。

## 新题 3：压缩掩码交集生成种子后沿对角扩展

**组合逻辑**：[压缩(compress)](已有) → [对角方向(diagonal_dir)](创新：方向由种子在画布中的象限位置决定，非由标记像素的局部 2x2 构型决定) → [填充(fill)](已有，线性延伸填充)

**来源原语**：压缩(compress)、堆叠掩码(stacked_mask)、背景交集(bg_intersection)、逐格比较(cell_comparison) ← fafffa47；对角方向(diagonal_dir)、标记像素(marker_pixel)、填充色块(fill_block) ← 4522001f

**依赖链**：压缩产生种子像素的位置 → 每个种子的位置决定其对角扩展方向 → 扩展长度由输入条带的高度决定。压缩步骤的输出是扩展步骤的输入；删除压缩则无种子可扩展，删除对角方向规则则不知向哪扩展。

将上下两层掩码的共同背景位置作为种子，每个种子沿离画布中心最远的对角方向射出固定长度的彩色射线。

**输入结构**：
- 网格约 14x7（宽大于高），由上下两个 7x7 的正方形区域纵向堆叠构成。
- 两个区域共享同一种背景色黑(0)。
- 上层区域：在黑背景上有若干蓝(1) 像素构成的前景图案（4-连通，3~8 像素）。
- 下层区域：在黑背景上有若干绿(3) 像素构成的前景图案（4-连通，3~8 像素）。
- 上层和下层的前景图案形状不同，但保证至少有 2 个位置在两层中都是黑(0) 背景（即交集非空），且交集位置不在 7x7 子网格的正中心行或正中心列上。
- 生成约束：每个交集种子沿其对角方向延伸 3 像素的路径完全在 7x7 输出画布内，且不同种子的射线路径互不重叠。

**规则**：
1. 逐像素比较上层和下层：若某位置在两层中都是黑(0)，标记该位置为种子。
2. 输出为一个 7x7 的黑(0) 画布。
3. 对每个种子，确定其在 7x7 画布中的象限位置（以画布中心为参考点，行 < 中心行且列 < 中心列为左上象限，依此类推），象限决定对角方向：左上象限 → 向左上延伸，右上象限 → 向右上延伸，左下象限 → 向左下延伸，右下象限 → 向右下延伸。
4. 从种子位置（含）起，沿确定的对角方向连续绘制 3 个红(2) 像素（种子本身 + 沿对角方向 2 步）。超出画布边界的像素不绘制。
5. 若两条射线经过同一像素，该像素仍为红(2)（同色不冲突）。

**关键洞察**：种子位置由两层掩码的交集决定，不可直接从任一层读取；对角方向规则与源题完全不同——源题用局部 2x2 构型编码方向，此处用种子相对画布中心的全局位置编码方向，需对比多个示例中不同象限的种子才能归纳。

## 新题 4：缩放拼块匹配孔洞后按内部标记重涂色

**组合逻辑**：[形状匹配(shape_match) + 缩放(scale)](已有) → [重涂色(recolor)](已有，从连通分量边界/内部判别改为匹配放置后的内部判别) ← 两步紧耦合于放置后的几何结构

**来源原语**：形状匹配(shape_match)、缩放(scale)、旋转(rotate)、翻转(flip)、框架(frame)、孔洞槽位(hole_slot)、拼块(piece)、缩放对应(scale_correspondence)、八方向匹配(all_orientations_matching) ← 898e7135；重涂色(recolor)、单点标记(singleton_marker)、实心内部(solid_interior)、标记在分量内(marker_inside_component)、邻域全包含(full_neighborhood_inside_component) ← 09c534e7

**依赖链**：形状匹配 + 缩放确定每块拼块放入哪个孔洞及其旋转/翻转方式 → 放置后拼块的像素布局决定哪些像素通过 3x3 邻域内部测试 → 每块拼块内的单点标记颜色决定这些内部像素的最终涂色。匹配决定了几何布局，几何布局决定了内部像素集合，标记决定了颜色——三层依赖不可跳步。

将外部拼块按缩放和旋转匹配到框架孔洞中，放置后将每块拼块的厚实内部像素重涂为该拼块内嵌标记的颜色。

**输入结构**：
- 背景为黑(0)，网格约 20x20。
- 一个灰(5) 色的单连通框架占据网格大部分区域，框架内有 2~3 个不同形状的黑(0) 孔洞。每个孔洞为 4-连通区域，面积 6~15 像素，形状不规则。
- 框架外部散布 2~3 个拼块，每个拼块由 kxk 块（k 为最小实心正方形拼块的边长，k=2 或 3）组成，是某个孔洞的 k 倍放大版本（可能经过旋转/翻转）。每个拼块使用不同的颜色（如蓝(1)、绿(3)、黄(4)）。
- 每个拼块的某个 kxk 子块中恰好有 1 个像素被替换为另一种颜色（该颜色在整个网格中仅作为标记出现），作为单点标记。标记颜色互不相同，使用红(2)、橙(7)、青(8) 等。
- 生成约束：每个拼块唯一匹配一个孔洞（在 8 种旋转/翻转中恰有一种匹配成功）。标记像素位于拼块内部（放置后其 3x3 邻域全在拼块内）。

**规则**：
1. 提取框架内的黑(0) 连通区域作为孔洞槽位。
2. 提取框架外的非黑连通分量作为拼块（忽略标记像素的颜色差异，将拼块视为包含标记的整体）。
3. 对每个拼块，将其下采样 k 倍得到像素级形状，与每个孔洞在 8 种旋转/翻转下比较，找到唯一匹配。
4. 将拼块放入匹配的孔洞位置（输出以框架为背景，孔洞处填入对应拼块颜色）。放置时拼块按匹配所需的旋转/翻转变换，标记像素一并变换。
5. 对每个已放置的拼块，找出"内部像素"：即 3x3 邻域（8 个邻居）全部属于同一拼块的像素。将这些内部像素重涂为该拼块内单点标记的颜色。
6. 拼块的边界像素（至少有一个邻居不属于该拼块）保持拼块原色不变。标记像素本身若满足内部测试也重涂为标记色（即保持不变），若不满足则保持标记色。

**关键洞察**：内部像素的判定依赖于拼块在孔洞中的精确放置方式——相同拼块以不同旋转放入不同形状的孔洞，其内部像素集合完全不同。标记色只能在放置后才能确定作用范围。

## 新题 5：面板逐像素差异筛选独占框架后按封闭面积决胜

**组合逻辑**：[逐像素比较(pixel_comparison)](已有) → [面积比较(area_comparison) + 最大内部面积胜出(largest_interior_wins)](创新：比较对象从所有框架改为仅差异筛选出的独占框架) → [输出纯色小块(output_solid_block)](已有)

**来源原语**：逐像素比较(pixel_comparison)、面板(panel)、分隔列(separator_col)、面板对齐(panel_align)、差异分类着色(diff_class_color) ← d47aa2ff；计数(counting)、比较(compare)、空心矩形(hollow_rectangle)、封闭区域(enclosed_region)、面积比较(area_comparison)、最大内部面积胜出(largest_interior_wins)、输出纯色小块(output_solid_block) ← 445eab21

**依赖链**：逐像素比较识别出哪些框架是某面板独占的 → 独占框架的封闭区域面积之和决定哪一侧胜出 → 胜出侧决定输出颜色。比较步骤筛选了面积计算的对象集合——如果跳过比较直接算所有框架面积，结果会不同；如果跳过面积计算直接选侧，则无法确定输出。

比较两个面板中的空心矩形框，找出各自独占的框架，以独占框架总内部面积较大的一侧的分隔线颜色作为输出。

**输入结构**：
- 网格约 11x23（高度 11，宽度 23），中间第 12 列为一条实心分隔列，颜色为灰(5)。分隔列左右各有一个 11x11 的面板。
- 每个面板的背景为黑(0)，其中各有 3~4 个单像素厚的空心矩形框架，每个框架一种颜色。两个面板中出现的颜色集合有交集也有差集。
- "共享框架"：颜色、尺寸、位置（在面板内的相对坐标）完全相同的框架，在两侧都出现。
- "独占框架"：仅出现在一侧面板中的框架（颜色可能在另一侧也有但形状/位置不同，视为独占）。
- 每侧至少有 1 个独占框架。两侧独占框架的总内部面积不相等。
- 生成约束：框架之间互不重叠，框架颜色在同一面板内互不相同。

**规则**：
1. 移除分隔列，将左面板和右面板按位置对齐，逐像素比较。

3. 对每侧面板，计算其所有独占框架的内部面积之和（内部面积 = 框架边界严格内部的像素数）。
4. 总内部面积较大的一侧胜出。输出一个 2x2 的纯色方块，颜色为胜出侧面积最大的那个独占框架的颜色。

**关键洞察**：不是比较所有框架的面积，而是先通过面板对比筛选出独占框架再比较——共享框架是干扰项，必须排除。需对比多个示例才能确认"共享框架不参与面积计算"这一隐蔽规则。

## 新题 6：指令掩码选定格子单元后多区域多重集均衡

4. 对每个选中单元，其空位应填入使该单元多重集与完整多重集一致的那个颜色。

**关键洞察**：掩码不仅仅是视觉标记，它决定了哪些单元参与均衡——如果将所有 8 个候选单元都纳入均衡，未被选中的异常单元会破坏多重集推断。需要对比多个示例（掩码不同导致选中集合不同）才能确认掩码的过滤作用。

## 新题 7：尾部向量双重编码：位移距离与阶梯扩展周期

**组合逻辑**：[滑动(slide)](已有) + [阶梯扩展(stepped_expansion)](创新：扩展周期由尾部长度而非条带高度决定) ← 尾部几何特征同时编码两种不同信息

**来源原语**：滑动(slide)、实心矩形(solid_rectangle)、尾部向量(tail_vector)、尾部指示位移(tail_displacement)、尾部决定平移(tail_determines_shift) ← c6e1b8da；阶梯扩展(stepped_expansion)、周期性步长(periodic_step_length)、重涂色(recolor) ← 58e15b12

**依赖链**：尾部长度同时编码滑动距离和扩展周期 → 滑动决定矩形最终位置 → 扩展周期决定光环的阶梯形状。同一几何特征（尾部长度）被两个不同操作消费，缺少任一操作都无法确定输出的一部分。这不是线性流水线——两个操作并行读取同一输入特征，各自产生不同效果后叠加到输出。

每个带尾矩形按尾部方向和长度滑动，然后以尾部长度为周期沿尾部方向做阶梯扩展光环。

**输入结构**：
- 背景为黑(0)，网格约 20x20。
- 2~3 个彩色实心矩形（宽 2~4、高 2~4），每个有一条从某一侧中央伸出的单像素宽尾部（尾部长度 2~4 像素，与矩形同色）。尾部方向为四个基本方向之一（上、下、左、右）。不同矩形颜色不同，使用蓝(1)、红(2)、绿(3) 等。
- 矩形和尾部互不接触。
- 品红(6) 不出现在输入中。
- 生成约束：每个矩形滑动后仍在网格内。滑动后矩形互不重叠。扩展光环可以超出网格（超出部分裁剪）。不同矩形的光环若重叠，重叠像素变为品红(6)。

**规则**：
1. 对每个带尾矩形，记录其尾部方向 D 和尾部长度 L。
2. 丢弃尾部，将矩形本体沿方向 D 平移 L 个像素。
3. 对每个滑动后的矩形，沿方向 D 做阶梯扩展：从矩形的 D 方向那条边开始，每 L 行（或列）向 D 方向延伸一层，同时向两侧各扩展 1 列（或行）。具体地：
   - 第 1 阶：矩形 D 方向边外的前 L 行（列），宽度 = 矩形宽度 + 2。
   - 第 2 阶：紧接第 1 阶外的 L 行（列），宽度 = 矩形宽度 + 4。
   - 依此类推，直到扩展超出网格边界。
   - 每阶使用矩形自身颜色绘制。
4. 先绘制所有矩形本体（滑动后位置），再绘制所有阶梯扩展像素。矩形本体不被扩展覆盖。
5. 若两个不同颜色的阶梯扩展像素占据同一位置，该位置涂品红(6)。扩展像素不覆盖任何矩形本体。

**关键洞察**：尾部长度是双重编码——既决定矩形滑多远，又决定阶梯扩展的周期步长。这在任何单一参考题中都不存在：c6e1b8da 中尾部只编码位移，58e15b12 中周期由条带高度编码。需对比多个示例（不同尾部长度产生不同位移和不同阶梯宽度）才能发现这一双重角色。
