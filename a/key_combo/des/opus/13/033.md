## 新题 1：配对多米诺定向对角射线

**组合逻辑**：[四邻接配对(four_neighbor_pairing)](已有) + [擦除(erase)](已有) + [射线延伸(ray_extend)](创新：方向由多米诺朝向编码，仅射两条对角线而非四条) + [碰撞停止(collision_stop)](创新：灰像素作为射线阻挡物而非滑动障碍)

**来源原语**：四邻接配对、双色多米诺、配对则变色擦除(d90796e8)；射线延伸、对角放射、延伸至边界(ea786f4a)；碰撞停止(17829a00)；忽略干扰项(d90796e8/de809cff)

**依赖链**：多米诺配对识别决定哪些像素成为射线发射源 → 多米诺的方向向量编码射线应沿哪两条对角线发射 → 灰像素既不参与配对（干扰项）又充当射线阻挡物（双重角色）

在黑色网格中，识别红-绿双色多米诺，擦除红侧，从绿侧向红→绿方向的两条对角线射出绿色射线，灰像素阻挡射线。

**输入结构**：约 15x15 的黑(0)背景网格。散布若干红(2)像素和绿(3)像素；其中部分红-绿像素形成 4-连通的双色多米诺（恰好一个红像素与一个绿像素 4-邻接），其余红/绿像素为孤立的干扰项（与任何异色像素均不 4-邻接）。另有若干灰(5)像素散布于网格中。生成约束：每个红像素最多与一个绿像素 4-邻接（配对唯一），灰像素不与任何红/绿像素 4-邻接。不同示例中多米诺的数量（2~5 个）、朝向（上下左右均出现）和位置各异。

**规则**：
1. 识别所有 4-连通的红(2)-绿(3)双色多米诺。未配对的红/绿像素是干扰项，原样保留。
2. 对每个多米诺，按绿像素的行列坐标排序（行小优先，行相同则列小优先），依此顺序处理：
   a. 将红(2)像素设为黑(0)（擦除）。
   b. 绿(3)像素成为射线发射原点。
   c. 计算方向向量：从红像素指向绿像素的方向（上/下/左/右四种之一）。
   d. 从绿像素出发，沿方向向量的两条对角分量方向各画一条射线。具体规则：若方向向量为"向右"（列增），则射线方向为右上(行减列增)和右下(行增列增)；若为"向左"（列减），则为左上(行减列减)和左下(行增列减)；若为"向下"（行增），则为左下(行增列减)和右下(行增列增)；若为"向上"（行减），则为左上(行减列减)和右上(行减列增)。
   e. 每条射线从绿像素的下一格开始逐格延伸，颜色为绿(3)。射线在以下情况停止（不含停止点）：遇到灰(5)像素、遇到网格边界之外、遇到另一个未被擦除的红(2)或绿(3)像素。射线可以覆盖黑(0)背景和已有的绿(3)射线像素。
3. 灰(5)像素和未配对的干扰像素始终保留不变。

**关键洞察**：红像素在每个多米诺中承担双重信息编码——它既标识了配对关系（使绿像素成为射线源），又通过自身相对于绿像素的位置编码了射线发射方向。仅看单个示例可能只见到一种朝向，需对比多个示例才能归纳出"红→绿方向向量决定对角线选择"的完整映射规则。

## 新题 2：形状匹配分类驱动色条定向滑动

**组合逻辑**：[形状匹配(shape_match) + 压缩(compress) + 旋转反射等价(rotation_reflection_eq)](已有) → [重涂色(recolor)](创新：匹配结果决定重涂颜色) → [滑动(slide) + 同色滑向同色边(slide_to_match)](创新：重涂后的颜色决定滑动方向)

**来源原语**：形状匹配、压缩、旋转反射等价、原型对象、候选对象、游程压缩后比较(bd14c3bf)；滑动、边界色条、同色滑向同色边、碰撞停止(17829a00)；重涂色(bd14c3bf/de809cff)；擦除(多题)

**依赖链**：游程压缩后的形状比较将候选对象分为"匹配"与"不匹配"两类 → 分类结果决定重涂颜色 → 重涂颜色与边界色条匹配关系决定滑动方向 → 碰撞停止决定最终位置。每一步的输出是下一步的必要输入，无法跳过。

将候选对象与原型进行游程压缩后的形状比较，匹配者涂为上边色条颜色并上滑，不匹配者涂为下边色条颜色并下滑。

**输入结构**：约 18x18 的黑(0)背景网格。第 0 行为红(2)全宽色条，最后一行为蓝(1)全宽色条。网格中央偏上有一个灰(5)原型对象（4-连通单色，4~8 像素，不规则形状，无孔洞）。网格中散布 4~6 个黄(4)候选对象（各为 4-连通单色，3~10 像素）；部分候选对象是原型的拉伸变体（沿行或列方向重复了某些行/列），部分与原型形状无关。生成约束：原型对象不在第 0 行或最后一行；所有候选对象互不重叠且不与原型重叠；每列最多容纳一个候选对象的边界框，以避免滑动路径冲突。不同示例中原型形状不同、候选数量和匹配/不匹配比例各异。

**规则**：
1. 裁剪灰(5)原型对象到其边界框，得到原型掩码 P。
2. 对每个黄(4)候选对象，裁剪到边界框后执行游程压缩：逐行扫描，将连续相同像素值的行（列）合并为一行（列），消除拉伸。得到压缩掩码 C。
3. 将 C 与 P 在 4 种旋转 x 2 种翻转 = 8 种变换下逐一比较。若任一变换下 C 与 P 的非零掩码逐像素一致，则该候选"匹配"；否则"不匹配"。
4. 匹配的候选对象重涂为红(2)，不匹配的候选对象重涂为蓝(1)。
5. 擦除灰(5)原型对象（设为黑(0)）。
6. 红(2)候选对象向上滑动，直到其边界框顶行到达第 1 行（紧邻顶部色条）或碰到另一个已停止的前景对象（边界框底行与对方顶行相邻时停止）。按原始行坐标从小到大依次滑动（离顶部色条近的先滑）。
7. 蓝(1)候选对象向下滑动，直到其边界框底行到达倒数第 2 行（紧邻底部色条）或碰到另一个已停止的前景对象。按原始行坐标从大到小依次滑动（离底部色条近的先滑）。

**关键洞察**：原型对象充当分类器而非操作目标——它不出现在输出中，但决定了所有候选对象的命运。游程压缩使得视觉上大小不同的对象可以被判为"匹配"，这一隐蔽规则需对比多个示例（尤其是看到被拉伸的候选仍被判为匹配）才能发现。

## 新题 3：碰撞触发裂缝分裂的定向滑动

**组合逻辑**：[滑动(slide) + 同色滑向同色边(slide_to_match)](已有) → [碰撞停止(collision_stop)](创新：碰撞不再导致停止，而是触发裂缝激活) → [裂缝标记线(fracture_line) + 沿短轴分裂(split_along_short) + 擦除(erase)](创新：裂缝为休眠机制，仅在碰撞时激活) → [滑动(slide)](前半体继续滑动)

**来源原语**：滑动、边界色条、同色滑向同色边、碰撞停止(17829a00)；裂缝标记线、沿短轴分裂、擦除、两侧等距分离(2faf500b)

**依赖链**：色条颜色匹配决定滑动方向 → 滑动过程中是否发生碰撞决定裂缝是否激活 → 裂缝位置决定分裂后两个半体的形状和位置 → 前半体（靠近目标色条的一半）继续滑动到目标。碰撞是裂缝激活的唯一触发条件，两个逻辑不可分离。

对象携带休眠裂缝线向目标色条滑动；若途中碰撞则裂缝激活、对象分裂，靠近目标的半体继续前进，远离目标的半体留在碰撞点。

**输入结构**：约 15x18 的黑(0)背景网格。第 0 行为红(2)全宽色条，最后一行为绿(3)全宽色条。网格中有 3~5 个前景对象：部分为红(2)、部分为绿(3)，各 4-连通、5~12 像素、非正方形边界框。每个对象内部有恰好一条由黄(4)像素组成的裂缝线，沿对象边界框较短轴的方向完整横贯对象（若宽>高则裂缝为竖直线贯穿所有行；若高>宽则为水平线贯穿所有列）。另有 1~2 个灰(5)障碍块（2x2 或 3x3 实心方块）散布于网格中，不含裂缝。生成约束：对象沿滑动方向排列时，至少有一个对象的滑动路径上存在另一个对象或障碍块（保证至少发生一次碰撞），同时至少有一个对象可以无碰撞地到达目标色条。不同示例中碰撞和无碰撞的对象组合不同。

**规则**：
1. 红(2)对象向上滑动（朝第 0 行红色条），绿(3)对象向下滑动（朝最后一行绿色条）。灰(5)障碍块不移动。
2. 按照对象到其目标色条的距离从小到大排序，距离相同则按列坐标从小到大。依此顺序逐个处理每个对象的滑动。
3. 对象沿滑动方向逐行移动。若对象到达目标色条（边界框的前沿行紧邻色条）时未发生碰撞：
   a. 对象停止。
   b. 裂缝线上的黄(4)像素被对象自身颜色覆盖（裂缝愈合），输出中看不到裂缝。
4. 若对象在滑动途中碰撞（对象的前沿行将要进入已被其他前景对象或灰障碍块占据的行）：
   a. 对象在碰撞前一行停止。
   b. 裂缝激活：擦除所有黄(4)裂缝像素（设为黑(0)），对象沿裂缝分裂为两个半体，两半之间出现 1 像素宽的黑色间隙。
   c. 靠近目标色条的半体（"前半体"）继续沿原方向滑动，直到到达目标色条或再次碰撞。前半体已无裂缝，若再碰撞则直接停止。
   d. 远离目标色条的半体（"后半体"）留在原地不再移动。
5. 碰撞检测基于整个对象（含裂缝像素）的边界框前沿行与已有前景像素的重叠。
6. 所有对象处理完毕后，色条和灰障碍块保持不变。

**关键洞察**：裂缝线是休眠的断层——未碰撞时它与对象融为一体并在到达目标后消失，碰撞时它才激活并将对象一分为二。需对比至少两个示例（一个含碰撞、一个无碰撞）才能发现裂缝的条件激活机制。

## 新题 4：分区计数编码印章平铺规模

**组合逻辑**：[计数(counting) + 分隔栅格(divider_grid)](已有) → [分区数定输出尺寸(partition_sets_size)](创新：分区数不直接定义输出尺寸，而是定义印章平铺的网格维度) → [印章覆盖(stamp) + 控制色选中则印章(stamp_where_control)](创新：控制信号分散在网格的不同区域中，需先识别再汇总)

**来源原语**：计数、分隔栅格、矩形区域、分区数定输出尺寸(1190e5a7)；印章覆盖、源图案、像素到块映射、控制色选中则印章(ad7e01d0)

**依赖链**：分隔栅格的行列数决定输出平铺网格的维度 → 各区域是否含控制像素决定平铺网格中哪些位置印章 → 含精灵图案的区域提供印章内容。三类信息分布在同一栅格的不同区域中，缺一不可。

灰色分隔线将网格划分为 R 行 C 列的区域；其中一个区域藏有精灵图案、其余区域有的含控制像素有的为空；输出为 R x C 的精灵平铺图，仅在含控制像素的区域位置处印章。

**输入结构**：约 16x16 的黑(0)背景网格。灰(5)全行线和全列线将网格划分为 R 行 x C 列的等大矩形区域（R, C 各为 2~4，不同示例取值不同）。恰好一个区域内含一个由蓝(1)和红(2)像素构成的小型精灵图案（4-连通，3~6 像素，不规则形状），该图案不触碰区域边界。若干其他区域各含恰好一个黄(4)像素（位于该区域中央），称为"控制区域"。剩余区域为纯黑(0)（"空区域"）。含精灵图案的区域视为控制区域（隐含"开"状态）。生成约束：至少有 2 个控制区域（含精灵区域）且至少有 1 个空区域。不同示例中 R、C 值不同、控制区域的分布模式不同。

**规则**：
1. 识别灰(5)分隔线，计算区域网格维度 R（行方向的区域数）和 C（列方向的区域数）。
2. 定位含精灵图案的区域，裁剪其中的蓝(1)/红(2)图案到最小边界框，得到印章模板 S（保留原色，背景为黑(0)）。
3. 构建 R x C 的二值控制矩阵 M：含黄(4)控制像素的区域和含精灵图案的区域标记为 1，纯黑空区域标记为 0。
4. 输出网格大小 = (R x S 的高度) 行 x (C x S 的宽度) 列，无分隔线。
5. 对控制矩阵 M 中每个值为 1 的位置 (i, j)：将印章模板 S 复制到输出网格的第 (i * S高, j * S宽) 起始位置处。值为 0 的位置保持纯黑。
6. 黄(4)控制像素不出现在输出中（它们仅作为开关信号）。

**关键洞察**：分隔栅格的拓扑结构（R x C）同时编码了两层信息——宏观层面决定输出的平铺网格维度，微观层面各区域的占用状态决定哪些格子获得印章。需对比不同 R x C 值的示例才能确认分区数与输出尺寸的乘法关系。

## 新题 5：调色板重定义凹痕修复色

**组合逻辑**：[去噪(denoise)](已有) → [缺陷标记(defect_mark) + 邻域多数色(neighborhood_majority_color)](已有) → [调色板图例(palette_legend) + 编码映射(encoding_map)](创新：调色板不再用于填充封闭区域，而是重定义缺陷修复的颜色映射)

**来源原语**：去噪、缺陷标记、邻域多数色、前景区域、凹痕(de809cff)；调色板图例、编码映射、边框色映射填充色(dbff022c)；填充(dbff022c/db7260a4)

**依赖链**：去噪清理边界干扰 → 清洁后的邻域多数色正确识别凹痕所属区域 → 区域颜色作为查找键在调色板中查询修复色 → 用查询到的颜色填充凹痕。调色板打破了"反色修复"的直觉假设，没有它修复色无法确定。

清理前景区域的边界噪声后，用调色板图例将每个黑色凹痕修复为查表确定的颜色，而非直觉上的"对面前景色"。

**输入结构**：约 15x15 的黑(0)背景网格。两个大型前景区域（各约 20~35 像素），一个为红(2)、一个为绿(3)，形状为不规则连通块（非矩形，有凹凸边缘）。每个区域内部有 1~3 个单像素或双像素的黑(0)凹痕（被前景色完全包围的黑像素）。区域边界处有 2~4 个孤立的单像素干扰斑点（颜色为对方区域色或自身色，但与自身区域不 4-连通）。网格右侧边缘有一个 2x2 调色板块：左列为前景色键 [红(2), 绿(3)]（从上到下），右列为映射目标色 [蓝(1), 黄(4)]（对应位置），即红→蓝、绿→黄。生成约束：两个前景区域互不 4-连通、凹痕不在区域边界行/列、干扰斑点与最近的前景区域像素距离 >= 2。不同示例中调色板映射的目标色不同（如红→橙、绿→品红），以迫使求解者依赖调色板而非记忆固定映射。

**规则**：
1. 去噪：对网格中每个非黑非灰像素，若它的 4 个正交邻居中没有任何同色像素，则为孤立干扰斑点，设为黑(0)。
2. 读取调色板：定位右侧边缘的 2x2 块，左列为键色、右列为值色，建立映射 {红(2)→蓝(1), 绿(3)→黄(4)}（具体映射因示例而异）。
3. 对网格中每个黑(0)像素（排除调色板所在位置和网格边界行/列上的像素），检查其 3x3 邻域（以该像素为中心的 9 格）：
   a. 统计邻域中各前景色的像素数。
   b. 若存在一种前景色占邻域中非黑像素的多数（> 50%），则该黑像素为该色区域的凹痕。
   c. 在调色板中查找该前景色，得到修复色，将该黑像素填充为修复色。
   d. 若无多数色（邻域无前景色或两色持平），该黑像素保持不变。
4. 调色板块本身保留不变。

**关键洞察**：仅看单个示例时，修复色看似可能是"另一个前景色"或某个固定颜色，但对比多个示例后会发现修复色随调色板变化——调色板是修复逻辑的外部参数，而非装饰。

## 新题 6：重力激活容器触发精灵印章

**组合逻辑**：[重力下落(gravity_drop) + 列对齐落入(column_fall_in)](已有) → [填充(fill) + 容器(container)](已有) → [印章覆盖(stamp) + 源图案(source_pattern)](创新：容器激活不仅触发填充，还在容器上方印章精灵图案) + [无容器则铺满底行(no_container_floor)](已有，作为对照分支)

**来源原语**：重力下落、列对齐落入、容器、填充、无容器则铺满底行、标记像素(db7260a4)；印章覆盖、源图案、控制色选中则印章(ad7e01d0)

**依赖链**：标记像素的列坐标决定哪个容器被激活 → 激活同时触发两个操作：容器内填充 + 容器开口上方印章 → 印章位置由容器的空间位置决定（非标记像素位置）。印章逻辑依赖容器激活，容器激活依赖重力落入，三层因果不可拆分。

顶行标记像素沿列下落；若落入 U 形容器则填充容器并在其上方印章精灵图案；若未命中任何容器则仅在底行留下痕迹。

**输入结构**：约 18x20 的黑(0)背景网格。第 0 行有 2~4 个黄(4)标记像素（各占不同列，互不相邻）。网格下半区域有 2~3 个红(2)U 形容器：每个容器由两条竖直侧壁（各 3~5 像素高）和一条连接底部的水平底边构成，内部为黑(0)空腔，开口朝上。容器宽度 3~5 列，各容器互不重叠且不在同一行。网格左下角（与容器不重叠的区域）有一个由蓝(1)和绿(3)像素构成的 3x3 精灵图案（源图案），以其边界框定义。生成约束：至少一个标记像素的列落在某容器的水平跨度内，至少一个标记像素的列不落在任何容器内。不同示例中容器位置和标记列不同。

**规则**：
1. 从输出中移除所有黄(4)标记像素（设为黑(0)）。
2. 定位源图案区域：左下角中由蓝(1)/绿(3)像素构成的 3x3 块，裁剪为印章模板 S。源图案在输出中被擦除（设为黑(0)）。
3. 对每个标记像素（按列坐标从左到右处理）：
   a. 确定该标记的列坐标 col。
   b. 检查是否存在某个 U 形容器，使得 col 落在该容器左侧壁列与右侧壁列之间（含端点）。
   c. 若命中容器：
      - 将该容器内部空腔（侧壁之间、底边之上的所有黑像素）填充为黄(4)。
      - 将印章模板 S 以容器开口中心列为水平对称轴、以容器顶行上方第 1 行为 S 底行，印章到网格上。若印章超出网格上边界则裁剪。
      - 若多个标记命中同一容器，填充和印章只执行一次（幂等）。
   d. 若未命中任何容器：
      - 将网格最后一行第 col 列的像素设为黄(4)。不执行印章。
4. 若两个不同容器的印章在空间上重叠（容器开口很近），列坐标较小的容器的印章先绘制，列坐标较大的后绘制并覆盖重叠部分。
5. 红(2)容器结构（侧壁和底边）保持不变。

**关键洞察**：容器激活是一个"一石二鸟"的触发——同一个重力落入事件同时引发填充（在容器内部）和印章（在容器外部上方）两个空间分离的操作。仅看无碰撞的标记像素会以为规则只是"底行标记"，必须对比命中容器的示例才能发现完整的激活-印章机制。

## 新题 7：空心框排序拼接后标记射线

**组合逻辑**：[仅保留空心对象(hollow_only_retained) + 忽略干扰项(ignore_distractors)](已有) → [排序(sort) + 沿主轴排列(along_main_axis) + 拼接(concatenate)](已有) → [方向指示(direction_indication)](创新：标记像素在框边界上的位置编码射线方向) → [射线延伸(ray_extend) + 延伸至边界(extend_to_edge)](创新：射线从拼接后的新位置发射，非原始位置)

**来源原语**：空心矩形、实心方块、仅保留空心对象、忽略干扰项、排序、沿主轴排列、拼接(a680ac02)；射线延伸、延伸至边界(ea786f4a)；方向指示(25d487eb)；标记像素(25d487eb/db7260a4)

**依赖链**：干扰项过滤决定哪些对象参与后续 → 排序+拼接改变对象的绝对位置 → 标记像素在框边上的位置编码方向信息 → 射线从拼接后的新位置出发（非原位置），故必须先完成拼接才能确定射线起点。四步顺序依赖。

过滤掉实心干扰方块后，将空心框按位置排序拼接成条带，再从每个框边界上的橙色标记像素向其指示方向射出射线。

**输入结构**：约 15x20 的黑(0)背景网格。散布 3~5 个 4x4 空心矩形框（各边 1 像素宽的边框、内部 2x2 为黑(0)空腔），框体颜色各不相同（从红(2)、蓝(1)、绿(3)、黄(4)中选取）。另有 1~2 个 4x4 灰(5)实心方块作为干扰项。每个空心框的外边界上恰好有一个像素被替换为橙(7)（标记像素），标记像素位于框的上、下、左或右边的中间位置。生成约束：空心框的位置在列方向上的跨度大于行方向（保证水平拼接）或反之（保证垂直拼接），不同示例方向不同；各对象互不重叠且间距 >= 2 像素。

**规则**：
1. 识别并丢弃所有实心方块（灰(5)干扰项），仅保留空心矩形框。
2. 计算所有空心框的位置分布：若框的列坐标跨度 > 行坐标跨度，按各框边界框左上角的列坐标从小到大排序（列相同则行小优先），拼接方向为水平；反之按行坐标排序，拼接方向为垂直。
3. 将排序后的空心框沿拼接方向依次紧密排列（边与边相邻，无间隙），起始位置为输出网格的 (0,0)。输出网格大小 = 拼接后条带的边界框大小加上射线延伸所需的空间（在拼接方向上等于条带长度，在垂直方向上等于网格对应维度取 max(条带宽度+10, 原网格该维度)，上限为 30）。
4. 对每个拼接后的空心框，定位其橙(7)标记像素在框边界上的位置：
   - 标记在框的顶边 → 射线方向为向上。
   - 标记在框的底边 → 射线方向为向下。
   - 标记在框的左边 → 射线方向为向左。
   - 标记在框的右边 → 射线方向为向右。
5. 从标记像素的拼接后坐标出发，沿射线方向逐格绘制橙(7)像素，直到到达输出网格边界（含边界行/列本身）。射线覆盖路径上的黑(0)像素；若遇到另一个框的非黑像素，射线停止于该像素的前一格（不覆盖框体）。
6. 框体内部空腔和框体像素（含橙标记像素本身）保持不变。

**关键洞察**：标记像素的信息在排序拼接前后发生了语义迁移——在原始网格中它标记方向，在拼接后的条带中它成为射线的发射点。必须对比多个示例才能确认：(a) 实心块被丢弃、(b) 标记位置编码方向、(c) 射线从拼接后位置而非原始位置出发。

## 新题 8：相邻区域标记色交换填充

**组合逻辑**：[洪泛填充(flood_fill) + 封闭区域(enclosed_region)](已有) + [四邻接配对(four_neighbor_pairing)](创新：配对单位从像素升级为区域，通过共享边判定邻接) + [颜色匹配(color_matching)](创新：同色标记不配对，异色标记才配对并交换) → [填充(fill)](颜色由配对关系决定)

**来源原语**：四邻接配对、配对则变色擦除(d90796e8)；洪泛填充、位置排序、封闭区域(941d9a10)；颜色匹配(17829a00)；填充(dbff022c/db7260a4)

**依赖链**：灰色分隔线定义区域边界 → 区域邻接关系构建图结构 → 标记像素颜色 + 邻接关系决定配对 → 配对关系决定填充模式（交换 vs 自填）。区域几何结构（邻接）与标记颜色（属性）共同决定输出，单独知道任一方面都不够。

灰色线划分出多个封闭区域，部分区域含彩色标记像素；相邻区域中不同色标记互相交换颜色来填充对方区域，孤立标记用自身颜色填充所在区域。

**输入结构**：约 14x14 的黑(0)背景网格。灰(5)线段（宽 1 像素的水平和垂直线段，不一定贯穿全网格）将网格划分为 4~7 个不规则封闭区域（每个区域为 4-连通的黑像素连通块，被灰线和/或网格边界完全包围）。其中 3~5 个区域各含恰好一个彩色标记像素（颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取），其余区域无标记（纯黑）。生成约束：至少存在一对相邻区域（共享至少一段灰色边界线）各含不同色标记（确保交换发生）；至少存在一个含标记的区域，其所有相邻的含标记区域的标记色都与自身相同或该区域无相邻含标记区域（确保自填发生）。每个标记像素不在灰线上、不在网格边界行/列上。不同示例中区域拓扑和标记颜色分配不同。

**规则**：
1. 识别灰(5)分隔线，通过洪泛填充找到所有黑(0)连通区域（4-连通）。
2. 建立区域邻接图：若两个区域之间存在一段灰(5)像素使得一侧为区域 A 的像素、另一侧为区域 B 的像素（灰像素的 4-邻居分别属于两个区域），则 A 和 B 邻接。
3. 对每个含标记像素的区域，在其邻接区域中寻找含**不同颜色**标记的区域：
   a. 若找到恰好一个：两个区域构成"交换对"。
   b. 若找到多个：选择标记像素与自身标记像素欧氏距离最近的那个作为配对对象（唯一配对）。每个区域最多参与一个交换对。配对按标记像素行坐标从小到大、行相同则列坐标从小到大的顺序贪心匹配（先匹配的优先）。
   c. 若找不到（所有邻接含标记区域都与自身同色，或无邻接含标记区域）：该区域为"孤立标记"。
4. 对每个交换对 (A, B)：用 B 的标记颜色洪泛填充区域 A（覆盖所有黑像素，包括 A 自身的标记像素位置），用 A 的标记颜色洪泛填充区域 B。
5. 对每个孤立标记区域：用自身标记颜色洪泛填充该区域。
6. 无标记的区域保持黑(0)不变。
7. 灰(5)分隔线保持不变。

**关键洞察**：标记像素之间通过共享灰色墙壁"握手"——异色邻接标记交换颜色来填充对方领地，而同色邻接或无邻接的标记只能用自己的颜色。仅看填充结果无法区分"交换"与"自填"，必须对比包含两种情况的示例才能发现配对交换机制。
