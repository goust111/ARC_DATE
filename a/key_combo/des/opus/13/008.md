## 新题 1：字形解码决定框内母题镜像轴

**组合逻辑**：[解码(decode)](创新：字形编码从颜色映射改为几何指令映射) + [镜像(mirror)](已有) ← [字形图案(glyph_pattern)](已有) + [矩形框架(rectangular_frame)](已有) + [内部母题(interior_motif)](已有)

**来源原语**：解码(decode)、字形图案(glyph_pattern)、位置映射(positional_mapping) ← 995c5fa3；镜像(mirror)、矩形框架(rectangular_frame)、内部母题(interior_motif)、宽高比决定镜像轴 ← 18419cfa

**依赖链**：字形解码的输出（镜像方向指令）直接决定镜像操作的轴参数。若不解码字形，则无法确定镜像轴（框架宽高比被故意设为正方形以消除几何线索）；若不执行镜像，则解码结果无用途。两步缺一不可。

将每个正方形框架内的字形图案解码为镜像方向指令，据此对框内母题执行水平或垂直镜像补全。

**输入结构**：黑(0)背景，约 20x20 网格。网格上有 2~3 个蓝(1)色正方形空心框架（边长 7~9，壁厚 1 像素），彼此不重叠不相邻。每个框架的内部左上角 3x3 区域含一个灰(5)/黑(0)构成的字形图案（4-连通，由 3~5 个灰(5)像素组成，不同示例中具体形状不同）。框架内部其余位置包含一个红(2)色母题（4-连通，3~8 像素，偏置在框架内部的某一半区域——左半或上半）。生成约束：每个框架严格为正方形，使宽高比无法提供镜像轴信息；同一输入中不同框架的字形图案可不同；母题不与字形图案重叠。

**规则**：
1. 识别所有蓝(1)正方形框架，按边界框左上角从上到下、从左到右排序依次处理。
2. 对每个框架，提取其内部左上角 3x3 区域的灰(5)字形图案。
3. 解码字形：输入中恰好有两类字形。通过对比多个示例可归纳出映射——一类字形编码"水平镜像"（左右翻转），另一类编码"垂直镜像"（上下翻转）。具体哪类字形对应哪个轴需从示例中归纳，不由字形外观直接暗示。
4. 将框架内的红(2)母题按解码出的轴方向进行镜像，镜像中心为框架内部区域（不含框壁）的中心线。
5. 输出为原母题与其镜像的并集；字形图案在输出中清除为黑(0)；框架和背景保持不变。

**关键洞察**：框架刻意设为正方形，使宽高比无法作为镜像轴的线索；求解者必须识别并解码字形图案才能确定每个框架的镜像方向，而字形到轴的映射只能通过对比多个示例归纳。

## 新题 2：标记选中对象重力下落与障碍堆叠

**组合逻辑**：[裁剪→识别](已有) + [重力下落(gravity_drop)](已有，创新：选中对象整体下落而非单像素令牌) ← [标记像素(marker_pixel)](已有) + [前景对象(foreground_object)](已有) + [邻接接触(adjacency_contact)](已有) + [碰撞停止(collision_stop)](已有)

**来源原语**：裁剪(crop)、标记像素(marker_pixel)、前景对象(foreground_object)、邻接接触(adjacency_contact)、标记选中邻接体(marker_selects_neighbor) ← 48d8fb45；重力下落(gravity_drop)、碰撞停止(collision_stop) ← 2b83f449

**依赖链**：标记选择决定哪些对象被"释放"参与重力下落，未被选中的对象保持原位充当障碍物。下落轨迹和最终停靠位置取决于障碍物的布局，而障碍物正是未被标记选中的对象。选择与物理模拟紧密耦合：改变标记位置会同时改变参与者和环境。

灰色标记像素选中与之相邻的前景对象，被选中对象向下做整体刚体下落，未选中对象保持原位成为障碍，下落对象遇障碍或网格底部停止。

**输入结构**：黑(0)背景，约 15x18 网格。网格上有 4~6 个红(2)色 4-连通小图形（每个 3~6 像素，形状各异，不同示例中具体形态不同），彼此在水平和垂直方向上都不重叠（任意两个图形的边界框不共享行也不共享列）。其中 2~3 个图形的某个 4-连通邻居位置有一个灰(5)像素（标记像素），标记像素不与其他图形相邻。未被标记的图形分布在网格的中下部。生成约束：每个标记像素恰好与一个图形 4-连通相邻；被选中图形位于未选中图形的上方（保证下落方向有意义）；被选中图形在下落路径上不会互相碰撞（各自占据不同的列范围）。

**规则**：
1. 识别所有红(2)4-连通图形。
2. 识别所有灰(5)标记像素。每个标记像素恰好与一个红色图形 4-连通相邻，该图形被标记为"选中"。
3. 移除所有灰(5)标记像素（变为黑(0)）。
4. 未被选中的红色图形保持原位不变，作为障碍。
5. 每个被选中的图形整体向下平移（保持形状不变），直到图形的任一像素的正下方一格是障碍像素、其他选中图形的已停靠像素或网格底部边界。按图形边界框底边行号从大到小的顺序依次处理下落（最低的先落）。
6. 输出保持原始网格尺寸，显示所有图形在最终位置。

**关键洞察**：标记像素不仅选择参与者，还隐式定义了物理环境——未被标记的对象成为阻碍下落的地形，求解者必须同时理解选择机制和重力模拟才能确定输出。

## 新题 3：阶梯墙生成走廊与方块滑行

**组合逻辑**：[连线(connect) + 阶梯图案(staircase_pattern)](已有) → [滑动(slide) + 路径搜索(pathfinding)](已有，创新：通道由阶梯操作动态生成而非预设) ← [锚点像素(anchor_pixel)](已有) + [实心方块(solid_square)](已有) + [目标标记(destination_marker)](已有) + [碰撞停止(collision_stop)](已有)

**来源原语**：连线(connect)、阶梯图案(staircase_pattern)、锚点像素(anchor_pixel)、点对称(point_symmetry)、步长固定(fixed_step_length) ← d06dbe63；滑动(slide)、路径搜索(pathfinding)、实心方块(solid_square)、蜿蜒通道(winding_channel)、目标标记(destination_marker)、尺寸约束通行(size_constrains_passage)、碰撞停止(collision_stop) ← 332f06d7

**依赖链**：阶梯图案的生成结果构成通道的墙壁，墙壁布局决定方块的滑行路径。没有阶梯生成就没有通道；没有滑行就没有理由生成阶梯。锚点位置同时决定墙壁几何形状和通道拓扑。

从锚点生成对称阶梯图案作为通道墙壁，然后将一个 2x2 方块沿生成的通道滑向目标位置。

**输入结构**：黑(0)背景，约 18x18 网格。网格上有 1 个青(8)色锚点像素和若干灰(5)色散布像素（4~8 个，不与锚点相邻）。另有 1 个绿(3)色 2x2 实心方块位于网格的一角附近，1 个橙(7)色 2x2 实心方块（目标标记）位于另一位置。生成约束：锚点不在网格边缘；灰(5)像素在锚点的阶梯延伸路径上充当阶梯终止点（具体位置保证阶梯生成后形成的墙壁与网格边界之间存在宽度恰好为 2 的通道）；绿色方块和橙色方块都位于通道内部可达位置。

**规则**：
1. 从青(8)锚点出发，沿四个对角方向（左上、右上、左下、右下）各生成灰(5)色阶梯臂，每级阶梯步长为 2（水平走 2 格再垂直走 2 格交替）。
2. 每条阶梯臂延伸至遇到已有灰(5)像素或网格边界时停止（不覆盖已有灰(5)像素）。锚点像素在输出中保持青(8)色。
3. 生成的灰(5)阶梯墙与原有灰(5)像素共同构成通道壁。
4. 绿(3)2x2 方块沿通道滑动：方块沿当前方向逐格移动，当 2x2 区域的前方紧邻通道壁或网格边界时停止。方块只能在通道宽度允许的方向上移动（宽度 >= 2 的方向）。
5. 方块沿可通行路径向橙(7)目标方块移动。若路径可达，绿色方块覆盖橙色方块的位置，绿色方块原始位置变为黑(0)。若因通道宽度不足（某处宽度 < 2）而不可达，绿色方块停在最远可达位置。
6. 输出保持网格尺寸，显示阶梯墙、锚点和方块的最终位置。

**关键洞察**：通道不是预先给定的，而是由阶梯生成操作动态构建的——求解者必须先推断阶梯规则以确定墙壁几何，再在生成的通道中完成路径搜索，两步紧密串联。

## 新题 4：降采样掩码门控菱形内射线填充

**组合逻辑**：[降采样(downsample)](已有) + [射线延伸(ray_extend)](已有，创新：掩码逐格门控射线是否可穿透) ← [单色图案(mono_pattern)](已有) + [菱形框(diamond_frame)](已有) + [侧标记(side_marker)](已有) + [整数缩放对应(int_scale_correspond)](已有) + [遇阻停止→掩码门控停止](创新)

**来源原语**：降采样(downsample)、单色图案(mono_pattern)、整数缩放对应(int_scale_correspond) ← 6ecd11f4；射线延伸(ray_extend)、菱形框(diamond_frame)、侧标记(side_marker)、框内填充(fill_inside_frame)、遇阻停止(stop_at_blocker) ← 95755ff2

**依赖链**：降采样将大图案压缩为二值掩码，掩码的每个格点映射到菱形内部的一个区域。射线从侧标记射入菱形后，每穿过一个掩码格点对应的区域，需查询该格点：掩码为非黑则允许通过，为黑则射线终止。没有降采样就无法得到掩码，射线会无限延伸；没有射线发射机制，掩码只是数据。

侧标记向菱形内部发射射线，射线能否穿过每个区域由一个大图案降采样后的二值掩码逐区域门控。

**输入结构**：黑(0)背景，约 20x20 网格。网格包含：(A) 一个红(2)色一像素宽空心菱形框（对角线长约 11~13），内部有若干区域；(B) 菱形四边外侧各有 0~2 个彩色侧标记像素（颜色从蓝(1)、绿(3)、黄(4)、橙(7)中选取，每个标记颜色不同），位于菱形边界框的对应边上；(C) 网格的另一侧有一个大型单色栗(9)图案，该图案是某个小型二值矩阵按整数比例（比例 = 菱形内部对角线长度 / 小矩阵边长，通常为 2 或 3）放大后的结果，小矩阵尺寸与菱形内部可被等分的区域数匹配。生成约束：菱形内部初始全为黑(0)背景；侧标记不在菱形顶点位置；大图案与菱形不重叠。

**规则**：
1. 将栗(9)大图案裁剪并降采样到小矩阵（按整数缩放比例），得到二值掩码：非黑 → 通, 黑 → 阻。
2. 将菱形内部区域按行列等分为与掩码同尺寸的格点网格（每个格点对应菱形内部的一个正方形子区域）。
3. 每个侧标记沿其所在边的法线方向向菱形内部发射射线（顶侧向下，底侧向上，左侧向右，右侧向左）。
4. 射线逐格点前进：进入一个格点对应的子区域时，查询掩码对应位置——若为"通"，则将该子区域内射线经过的严格菱形内部背景像素染为标记颜色，继续前进；若为"阻"，射线立即终止，该子区域不染色。
5. 射线到达菱形对侧框边时也终止。多条射线交叉时，后处理的射线颜色覆盖先处理的（处理顺序：上侧标记→右侧→下侧→左侧）。
6. 菱形框、侧标记、大图案在输出中保持不变。

**关键洞察**：大图案不是直接作为视觉对象参与输出，而是经降采样后成为一张隐藏的"通行证地图"，逐区域控制射线能否穿透——求解者需同时理解降采样的缩放关系和射线的门控机制。

## 新题 5：头序列循环索引驱动对边段颜色互换

**组合逻辑**：[颜色互换(color_swap)](已有，创新：互换色对不固定而由循环头序列动态指定) + [平铺逻辑中的循环索引](已有) ← [头序列(header_sequence)](已有) + [网格边缘(grid_edge)](已有) + [线段(line_segment)](已有) + [对边配对(opposite_edge_pair)](已有) + [对角索引映射→段序号索引映射](创新)

**来源原语**：平铺(tiling)、头序列(header_sequence)、对角索引映射(diag_index_map)、循环头序列倍增(cyclic_header_doubled) ← 539a4f51；颜色互换(color_swap)、线段(line_segment)、网格边缘(grid_edge)、对边配对(opposite_edge_pair)、配对间像素互换(toggle_between_pairs) ← d2acf2cb

**依赖链**：头序列的颜色定义了互换色对的候选池。对边标记对定义了需要互换的段。段的排列顺序索引到头序列中取出循环色对。没有头序列就不知道每段该用哪对颜色互换；没有对边标记就不知道在哪些段上执行互换；段的排列顺序是连接两者的桥梁。

网格顶行的头序列循环提供颜色对，对边黄色标记指定行/列段，按段的位置顺序从头序列中取连续两色作为该段的互换色对。

**输入结构**：黑(0)背景，约 14x14 网格。顶行（第 0 行）是一段不含黑色的头序列，由 K 种颜色组成（K 在 3~5 之间，颜色从蓝(1)、红(2)、绿(3)、青(8)、栗(9)中选取），序列长度等于网格宽度。黄(4)标记像素成对出现在网格的左右边缘（同一行的第 0 列和最后一列各一个）或上下边缘（同一列的第 0 行和最后一行各一个，此时该列的顶行像素既是头序列的一部分也是标记的一端）。左右对标记 2~3 对，选取不同行；上下对不超过 1 对。每对标记之间的严格内部像素使用恰好两种非黑颜色（从头序列中出现的颜色里选取，不同段的内部颜色对可以不同）。生成约束：头序列不含黄(4)；行对标记和列对标记互不冲突（不共享格点）；每段内部恰好包含两种非黑颜色。

**规则**：
1. 提取顶行头序列（去掉黄(4)标记像素后剩余的颜色序列），长度为 L。
2. 识别所有黄(4)对边标记对：左右边缘同行配对为行段，上下边缘同列配对为列段。
3. 将所有段按标记位置排序：行段按行号从小到大，列段按列号从小到大；行段全部排在列段前面。
4. 对第 i 段（从 0 开始计数），从头序列中取出循环位置 (2i mod L) 和 ((2i+1) mod L) 处的两个颜色 C_a 和 C_b，构成该段的互换色对。
5. 将该段严格内部（不含端点标记）的所有 C_a 像素改为 C_b，所有 C_b 像素改为 C_a。其他颜色的像素保持不变。

**关键洞察**：互换色对不是固定的（如原题 d2acf2cb 中黑↔青、品红↔橙），而是由头序列按循环索引动态分配——求解者必须同时从示例中归纳出段的排序规则和头序列的循环索引规则才能确定每段的互换行为。

**输入结构**：黑(0)背景，约 14x20（高大于宽）网格。一条品红(6)色水平分隔线将网格分为上下两区。上区包含一个彩色矩阵（占据上区全部空间，无黑色背景），该矩阵是某个小矩阵（3x3 到 5x5）经行列膨胀后的结果——每行被重复 2~3 次，每列被重复 2~3 次（不同行的重复次数可不同，不同列的重复次数也可不同）。小矩阵满足对角索引性质：其首行与首列相同，且每格颜色等于首行/首列序列在 max(row, col) 位置的颜色。小矩阵使用的颜色从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)、橙(7)中选取（不含黑(0)）。下区完全为黑(0)空白，尺寸为正方形，边长等于上区压缩后小矩阵边长的两倍。生成约束：上区膨胀矩阵的行列重复模式在不同示例中不同（防止求解者直接记忆固定的压缩比例）。

**规则**：
1. 对上区的膨胀矩阵执行压缩：识别所有最大相同相邻行组（从上到下连续内容完全相同的行），每组保留第一行；对列同理（从左到右连续内容完全相同的列，每组保留第一列）。得到压缩后的小矩阵。
2. 提取小矩阵的首行作为头序列 H，长度为 K。
3. 去掉头序列 H 末尾连续的黑(0)元素（若有），得到有效头序列 H'，长度为 K'。（本题中小矩阵不含黑色，故通常 K' = K。）
4. 将 H' 循环扩展至长度 2K'，记为 H''（即 H'' = H' 重复两次拼接后取前 2K' 个）。
5. 在下区填充一个 2K' x 2K' 的正方形，每格 (r, c) 的颜色为 H''[max(r, c)]。
6. 分隔线和上区在输出中保持不变。

**关键洞察**：头序列不是直接给定的（如原题 539a4f51），而是隐藏在膨胀矩阵的冗余结构中——求解者必须先完成压缩去重（逆向工程数据生成过程），才能获得驱动平铺的指令，两步形成"解码数据→生成图案"的紧耦合流水线。
