## 新题 1：路径遍历顺序决定面板叠加优先级

**组合逻辑**：[端到端遍历](创新：从路径遍历中提取颜色首现顺序) → [图层优先级](创新：优先级由路径首现序定义而非固定循环位置) → [透明叠加](已有) → [裁剪](已有，输出仅保留叠加结果)

**来源原语**：端到端遍历、单像素宽路径、端点像素 ← 5792cb4d；透明叠加、图层优先级、面板 ← 281123b4；分隔行 ← dc46ea44；重涂色 ← 多题

**依赖链**：路径遍历提取颜色首现序列 → 首现序列定义图层优先级 → 优先级决定面板重叠区域的颜色归属。删除路径则优先级不可知；删除面板则无叠加对象。

用一句话概括：沿多色路径行走提取颜色首现顺序，以此决定上方各色面板的前后叠加层次，输出重叠后的复合图像。

**输入结构**：
- 网格约 14x18，黑(0)背景。
- 一条全宽灰(5)分隔行将网格分为上区和下区。
- 上区：3 块纯色实心矩形面板（每块高 3 行，宽 4-8 列不等），颜色分别为红(2)、蓝(1)、绿(3)三种不同前景色。3 块面板按上到下排列，相邻面板之间有 1 行黑(0)间隔。各面板的列范围部分重叠——至少两块面板共享某些列。
- 下区：一条 4-连通单像素宽路径（无分叉，恰好两个端点），仅使用与上区面板相同的 3 种颜色，每种颜色至少出现 1 次。路径不触碰分隔行。
- 生成约束：路径的颜色首现顺序与面板从上到下的空间排列顺序不同，确保优先级不可直接从空间位置推断。

**规则**：
1. 确定路径起点：选择行索引较小的端点（若行索引相同，选列索引较小者）。从起点遍历到另一端点，记录每种颜色首次出现的顺序，得到长度为 3 的颜色序列 [c1, c2, c3]。
2. 分配图层优先级：c1 = 优先级 1（最底层，先画），c2 = 优先级 2，c3 = 优先级 3（最顶层，后画覆盖先画）。
3. 构建输出网格：高 3 行（与单块面板等高），宽为所有面板列范围的并集。初始化为黑(0)。
4. 按优先级从低到高的顺序绘制面板：将每块面板投影到输出的行范围内（所有面板共享相同的 3 行输出空间）。后绘制的面板在重叠列处覆盖先绘制的颜色。
5. 仅输出这个 3 行的复合图像。分隔行、下区和间隔行均不出现在输出中。

**关键洞察**：路径不是装饰——它编码了叠加的层次顺序。遍历过程中颜色的首现顺序（而非面板在输入中的空间位置）决定了哪种颜色在重叠区域胜出。需要对比多个示例才能确认"首现序 = 优先级"这一映射规则。

## 新题 2：图元分解计数驱动轮廓腔填充

**组合逻辑**：[分解 + 基本图元](创新：分解的结果不直接重涂色，而是作为计数输入) → [计数](已有) → [面积匹配](创新：用分解计数而非源像素数做匹配) → [填充](已有，填入轮廓腔内)

**来源原语**：分解、基本图元、图元形状决定涂色 ← 150deff5；计数 ← f8b3ba0a；轮廓对象、行内腔、面积匹配、像素数等于腔面积 ← 7acdf6d3；填充 ← 7acdf6d3

**依赖链**：分解复合形状为图元 → 按类型计数 → 计数结果与轮廓腔面积匹配 → 匹配成功的腔被填入对应颜色。分解结果改变计数值，计数值决定填充目标——三步之间有实质信息变换。

用一句话概括：将灰色复合体分解为正方形和长条两种图元并分别计数，以计数值匹配轮廓对象的内腔面积，用图元类型对应的颜色填充匹配到的腔。

**输入结构**：
- 网格约 16x16，黑(0)背景。
- 一个灰(5)复合形状（单个 4-连通区域，10-18 像素），可唯一分解为若干 2x2 正方形和若干 1x3 或 3x1 长条。该形状位于网格的一个象限。
- 网格其他位置有 2 到 3 个轮廓对象，每个轮廓用不同的前景色绘制（如蓝(1)、红(2)、绿(3)），每个轮廓是 1 像素厚的封闭环形，围成一个内腔。各轮廓的内腔面积（逐行统计：每行中轮廓最左像素与最右像素之间的背景像素数之和）互不相同。其中恰好有两个腔面积分别等于正方形计数 S 和长条计数 R。
- 生成约束：灰色形状的分解方式唯一（不存在两种合法分解给出不同的 S 和 R 值）。各轮廓的内腔面积两两不同。

**规则**：
1. 将灰(5)复合形状分解为不重叠的图元，仅允许两种类型：2x2 正方形和 1x3 或 3x1 长条。每个灰色像素恰好属于一个图元。
2. 统计 2x2 正方形的数量 S 和长条的数量 R。
3. 对每个轮廓对象，计算其行跨度内腔面积：在轮廓占据的每一行上，统计最左轮廓像素与最右轮廓像素之间严格内部的背景像素数，跨行求和。
4. 内腔面积等于 S 的轮廓：将其整个内腔填充为青(8)。
5. 内腔面积等于 R 的轮廓：将其整个内腔填充为红(2)。
6. 内腔面积既不等于 S 也不等于 R 的轮廓：保持不变（内腔仍为黑(0)）。
7. 灰色复合形状保留在原位，不被擦除或重涂。

**关键洞察**：灰色形状的作用不是视觉输出（不同于源题中的就地重涂），而是一个"编码器"——其分解结果产生的数值信息在空间上跨区域选择了填充目标。图元类型到颜色的映射（正方形→青、长条→红）复用了分解逻辑但施加在完全不同的空间语境中。

## 新题 3：拉丁方解编码精灵体旋转参数

**组合逻辑**：[补全 + 拉丁方约束](创新：补全结果不是最终输出而是中间指令) → [计数](创新：读取特定颜色在完成列中的行位置作为数值) → [旋转](创新：旋转量由拉丁方单元格值决定而非由标记像素决定)

**来源原语**：补全、色表、空白单元、拉丁方约束、行列唯一约束 ← 4cd1b7b2；旋转 ← 0e206a2e / 6aa20dc0 / ecaa0ec1；精灵体 ← 多题；分隔行 ← dc46ea44

**依赖链**：补全拉丁方（唯一解）→ 读取每列中关键色的行位置 → 行位置作为旋转量应用于对应精灵体。若不补全则旋转量未知；关键色需要对比多个示例才能识别。

用一句话概括：补全一个部分填充的拉丁方色表，以每列中黄色所在行号作为对应精灵体的 90 度旋转次数，输出旋转后的精灵体。

**输入结构**：
- 网格约 14x18，黑(0)背景。
- 一条全宽灰(5)分隔行将网格分为上区和下区。
- 上区：一个 4x4 像素区域表示部分填充的拉丁方。调色板为{蓝(1)、红(2)、绿(3)、黄(4)}。黑(0)像素为空白。已填入的单元格满足行列唯一性约束。部分填充具有唯一补全方案。
- 下区：4 个小型单色精灵体（每个 3x3 至 4x4 像素，各为不同的非对称 4-连通形状），颜色分别为蓝(1)、红(2)、绿(3)、黄(4)。精灵体从左到右排列并有间隔，使得精灵体 j 位于拉丁方第 j 列的正下方（j = 0,1,2,3，从左到右）。
- 生成约束：每个精灵体不具有 90 度旋转对称性（确保每种旋转产生视觉上不同的结果）。

**规则**：
1. 补全拉丁方：将每个黑(0)单元格替换为{蓝(1)、红(2)、绿(3)、黄(4)}中满足行列唯一性的唯一颜色。
2. 对每列 j（0-3，从左到右），在已补全的列中找到黄(4)所在的行索引 r（0-3，从上到下）。
3. 第 j 列下方的精灵体原地旋转 r x 90 度顺时针（0 = 不旋转，1 = 90° CW，2 = 180°，3 = 270° CW）。旋转以精灵体边界框中心为轴心，若中心落在半像素处则向左上取整。
4. 仅输出下区（含旋转后的精灵体）。上区和分隔行被丢弃。

**关键洞察**：黄(4)是"关键色"——它在每列中的行位置控制旋转量。这是一条隐蔽规则：仅凭单个示例，任何颜色都可能是关键色；必须对比多个示例才能确认始终是黄色起决定作用。拉丁方是中间计算过程而非最终答案。

## 新题 4：双重编码对角标记控制精灵体变换

**组合逻辑**：[对角配对](创新：对角方向编码旋转方向而非用于生成字形) + [旋转 + 角落对应](创新：旋转方向由标记空间排列而非标记位置推断) + [颜色配对](创新：标记颜色同时编码目标位置) + [平移 + 擦除](已有)

**来源原语**：对角配对、角标记像素 ← f35d900a；旋转、角落对应、标记定旋转源目 ← ecaa0ec1；颜色配对 ← 54dc2872；平移、擦除 ← 54dc2872；精灵体 ← 多题

**依赖链**：识别标记对 → 对角方向推断旋转方向（TL-BR 对角 → 顺时针 90°，TR-BL 对角 → 逆时针 90°）AND 标记颜色推断目标精灵体 → 旋转精灵体 → 平移至目标位置。标记同时编码旋转和目的地两种独立信息，缺一不可。

用一句话概括：每个精灵体旁的同色标记对既通过对角方向编码旋转方向，又通过颜色指定目标精灵体，旋转后的精灵体移至颜色匹配的目标位置。

**输入结构**：
- 网格约 14x14，黑(0)背景。
- 3 个小型单色精灵体（每个为 3x3 的非对称 4-连通形状，各自颜色不同，取自{蓝(1)、红(2)、绿(3)}）。精灵体互不重叠、互不接触，各有明确的边界框。
- 每个精灵体的边界框外对角位置放置恰好 2 个同色标记像素：两个标记分别位于边界框对角方向外扩一格的位置（例如，一个在左上角外扩位置，一个在右下角外扩位置；或一个在右上角外扩位置，一个在左下角外扩位置）。同一标记对的两个像素颜色相同，且该颜色等于另一个精灵体的主体颜色。
- 3 个标记对的颜色构成循环置换：精灵体 A 的标记色 = 精灵体 B 的主体色，精灵体 B 的标记色 = 精灵体 C 的主体色，精灵体 C 的标记色 = 精灵体 A 的主体色。
- 生成约束：每个精灵体均无 90 度旋转对称性；每个标记对要么在 TL-BR 对角线上，要么在 TR-BL 对角线上（同一对内部不混合）。

**规则**：
1. 对每个精灵体，识别其边界框外对角方向的 2 个同色标记像素。
2. 判断标记对的对角类型：
   - 标记分别位于边界框左上外扩和右下外扩 → 该精灵体旋转 90° 顺时针。
   - 标记分别位于边界框右上外扩和左下外扩 → 该精灵体旋转 90° 逆时针。
3. 确定目标位置：标记对的颜色与某个精灵体的主体颜色相同，该精灵体的边界框中心即为目标位置。
4. 先计算所有精灵体的旋转结果和目标位置，然后同时执行所有平移（每个旋转后的精灵体移动至其目标精灵体的原始边界框中心对齐，被替换的精灵体同时移走——所有移动基于原始位置计算，不级联）。
5. 擦除所有标记像素（设为黑(0)）。

**关键洞察**：同一对标记像素编码了两种独立信息——它们的空间排列（占据哪两个角）决定旋转方向，它们的颜色决定目标位置。两种信息互不可替代，必须同时从标记中读取。

## 新题 5：路径像素数作为循环轮换参数

**组合逻辑**：[端到端遍历 + 单像素宽路径](创新：路径不携带有意义的颜色信息，其像素数才是信息) → [计数](创新：计数对象是路径像素而非对象数量) → [循环轮换](创新：轮换量可变而非固定为 1) + [环绕角度排序](已有) → [擦除](已有)

**来源原语**：单像素宽路径、端到端遍历 ← 5792cb4d；计数 ← f8b3ba0a；循环轮换、环绕角度排序、分离区域、分隔结构 ← 880c1354；擦除 ← 54dc2872

**依赖链**：计数路径像素 → 路径长度 L 对区域数 N 取模 → 得到循环轮换量 K → 按角度排序区域 → 轮换颜色 → 擦除路径。不测量路径则 K 未知；不做角度排序则轮换方向未定义。

用一句话概括：计算单色路径的像素数量，以此作为周围各区域颜色沿角度排序的循环轮换步数，然后擦除路径。

**输入结构**：
- 网格约 15x15，黑(0)背景。
- 中心：一个小型分隔结构（十字形或加号形，约 5-7 像素），颜色为橙(7)，质心大致位于网格中心。
- 分隔结构周围：4 到 6 个单色 4-连通区域，每个区域颜色不同（取自{蓝(1)、红(2)、绿(3)、黄(4)、品红(6)、青(8)}中的若干种）。区域互不接触，也不接触分隔结构。
- 一条单色 4-连通单像素宽路径，颜色为灰(5)，穿越背景区域但不触碰任何彩色区域或分隔结构。路径恰好有两个端点，无分叉。路径长度在 3 到 15 像素之间。
- 生成约束：轮换量 K = (路径长度) mod N 不为 0 且不为 1（确保轮换效果非平凡且与源题固定 1 步轮换不同），其中 N 为区域数量。

**规则**：
1. 计算灰(5)路径的像素总数，记为 L。
2. 识别所有非分隔结构、非路径的前景区域，记其数量为 N。
3. 计算轮换量 K = L mod N。
4. 计算橙(7)分隔结构的质心坐标。
5. 按各区域质心相对于分隔结构质心的角度排序：以屏幕坐标系中正右方向为 0 度，顺时针递增（右 = 0°，下 = 90°，左 = 180°，上 = 270°），得到区域序列 [R_0, R_1, ..., R_{N-1}]。
6. 循环轮换颜色：角度位置 i 的区域接收角度位置 (i - K) mod N 处区域的原始颜色。区域形状和位置不变，仅颜色改变。
7. 擦除灰色路径（所有路径像素设为黑(0)）。分隔结构保持不变。

**关键洞察**：路径是一个计数器而非导管——其长度编码了轮换幅度，而其颜色和形状无关紧要。求解者必须同时测量路径长度并确定角度排序，才能预测输出。

## 新题 7：视线方向决定宽高归一化方式

**组合逻辑**：[视线对齐 + 最近邻](创新：视线方向不用于驱动滑动目标而用于选择归一化模式) + [宽高互换 + 归一化朝向](创新：归一化方向不是固定产出两份而是由外部空间关系条件分支决定) + [滑动](已有，归一化后沿视线方向靠近方块) + [颜色配对](已有，按颜色匹配矩形与方块) + [擦除](已有)

**依赖链**：颜色匹配矩形与方块 → 判断视线轴向（水平还是垂直）→ 轴向决定归一化方向（水平→横向，垂直→纵向）→ 归一化 → 沿视线滑动至方块旁 → 擦除方块。空间关系编码了条件分支逻辑。

用一句话概括：每个彩色矩形与同色 2x2 方块配对，视线轴向决定矩形归一化为横版还是竖版，然后矩形沿视线方向滑动至方块旁。

**输入结构**：
- 网格约 14x20，黑(0)背景。
- 3 到 4 个不同颜色的单色实心矩形（如蓝(1) 2x5、红(2) 4x3、绿(3) 1x6），分散放置，互不接触。每个矩形宽高不等（非正方形）。
- 每个矩形对应一个同色的 2x2 实心方块，放置在网格其他位置。每个方块与其配对矩形之间仅共享行范围（方块某些行在矩形行范围内，但列位置不同）或仅共享列范围（方块某些列在矩形列范围内，但行位置不同），不会同时共享两者。这决定了视线是水平还是垂直。
- 方块不与任何矩形重叠，也不与配对矩形相邻。
- 生成约束：每对矩形-方块之间的视线路径（连接它们的行或列）上没有其他前景对象阻挡。不同矩形滑动后不会互相碰撞。

**规则**：
1. 对每种前景颜色，识别矩形（超过 4 像素的对象）和配对的 2x2 方块（恰好 4 像素的对象）。
2. 判断视线轴向：
   - 方块的行范围与矩形的行范围有交集 → 视线为水平方向。
   - 方块的列范围与矩形的列范围有交集 → 视线为垂直方向。
3. 根据视线归一化矩形：
   - 水平视线 → 横向：若矩形高 > 宽，交换宽高（旋转 90°）。归一化后的矩形重新居中于原中心（半像素时向左上取整）。若已为横向则不变。
   - 垂直视线 → 纵向：若矩形宽 > 高，交换宽高。重新居中。若已为纵向则不变。
4. 将归一化后的矩形沿视线轴向朝方块方向滑动，逐像素移动，直到矩形最近边缘与方块最近边缘相邻（间隔恰好 1 像素，无重叠）。
5. 擦除所有 2x2 方块（设为黑(0)）。
6. 处理顺序：先对所有矩形执行归一化，再同时执行滑动。

**关键洞察**：视线轴向不仅是移动方向——它决定了形状归一化规则。水平空间关系强制横向归一化，垂直空间关系强制纵向归一化。这种空间排列与形状变换之间的条件关联是核心的非显然环节。

- 生成约束：干扰区域在角度排序中位于两个其他区域之间，其移除会改变角度邻接图（使原本不相邻的两个区域变为相邻）。

**规则**：
1. 统计每个非分隔结构前景区域的像素总数。
2. 识别像素最多的区域（干扰项），将其所有像素擦除为黑(0)。
3. 计算灰(5)分隔结构的质心坐标。
4. 将剩余区域按其质心相对于分隔结构质心的角度排序，以屏幕坐标系正右方向为 0 度顺时针递增。

6. 若两条路径的像素位置重叠，后绘制的路径覆盖先绘制的。绘制顺序沿角度序列依次进行（区域 0-1 之间的路径先画，再画 1-2，以此类推，最后画 N-1 到 0 的环绕路径）。

**关键洞察**：最大区域是一个诱饵，必须先识别并移除才能正确连接。如果保留干扰项，它会改变角度邻接关系，导致连线连错区域对。干扰项的角度位置被特意设计在两个幸存区域之间，使得其移除从根本上改变了连接图。

## 新题 10：路径颜色首现序反转定义区域重涂映射

**组合逻辑**：[颜色序列反转 + 单像素宽路径 + 端到端遍历](创新：反转不施加于路径本身而用于构造颜色置换) → [重涂色](创新：重涂规则由路径反转产生而非预定义) → [颜色配对](创新：配对关系动态生成而非由空间标记固定) + [擦除](已有)

**来源原语**：颜色序列反转、单像素宽路径、端到端遍历、形状不变仅反色序 ← 5792cb4d；重涂色 ← 150deff5 / 880c1354 等；分离区域 ← 880c1354；颜色配对 ← 54dc2872；擦除 ← 54dc2872

**依赖链**：遍历路径记录颜色首现序 → 反转首现序 → 逐位配对构造颜色置换 → 对区域施加置换 → 擦除路径。路径被当作指令读取然后销毁，而非自身被变换。

用一句话概括：沿多色路径行走提取颜色首现顺序，将其反转得到颜色置换映射，以此重涂网格上同色的各单色区域，最后擦除路径。

**输入结构**：
- 网格约 14x14，黑(0)背景。
- 一条 4-连通单像素宽路径（无分叉，恰好两个端点），使用 N 种不同的前景色（N = 3 或 4），每种颜色至少出现 1 次。路径共 6-12 个像素，位于网格的一个部分（如上半部）。
- N 个单色 4-连通区域（每个 5-15 像素，每个颜色不同），位于网格的另一个部分（如下半部）。这 N 个区域恰好使用与路径相同的 N 种颜色。区域互不接触，也不接触路径。
- 生成约束：路径的首现序列及其反转所产生的颜色置换不是恒等映射（至少一种颜色映射到不同颜色）。行索引较小（若行索引相同则列索引较小）的端点为指定起点。

**规则**：
1. 从行索引较小的端点（若行索引相同则列索引较小）出发，沿路径遍历到另一端点。记录每种颜色首次出现的顺序，得到首现序列 [c_1, c_2, ..., c_N]（c_1 是最先遇到的新颜色，c_N 是最后遇到的新颜色）。
2. 反转首现序列：[c_N, c_{N-1}, ..., c_1]。
3. 构建颜色置换映射：c_1 → c_N，c_2 → c_{N-1}，...，c_N → c_1。即首现序中第 i 个颜色映射到反转序中第 i 个颜色。
4. 对所有区域施加该颜色映射：每个颜色为 X 的区域，其所有像素重涂为映射后的颜色。
5. 擦除路径（所有路径像素设为黑(0)）。

**关键洞察**：路径不是被变换的对象——它被"读取"然后"销毁"。它的颜色序列及其反转共同定义了一个颜色置换，该置换作用于远处的独立对象。路径的空间结构（哪个像素连着哪个）创建了序列；反转操作创建了置换；远处的区域接收变换。这与源题（路径上颜色就地反转）在角色上完全不同。
