## 新题 1：同心菱形层叠——按线段长度排序着色

**组合逻辑**：[排序(sorting)] + [同心层填充(concentric_layer_filling)，创新：由方形层改为菱形（曼哈顿距离）层] + [按长度降序(desc_segment_length)] + [菱形轮廓(diamond_outline)]

**来源原语**：排序(sorting)、同心层填充(concentric_layer_filling)、按长度降序(desc_segment_length) 来自 3ee1011a；菱形轮廓(diamond_outline) 来自 d753a70b；单色线段(mono_segment) 来自 3ee1011a

**依赖链**：需先测量各线段长度 → 按长度降序排序确定由外到内的层序 → 以曼哈顿距离轮廓（菱形）而非切比雪夫距离轮廓（正方形）绘制同心层。排序产出的层序直接驱动菱形层的径向分配；菱形几何改变了层面积的增长率，使得同一排序结果在视觉上与方形同心层完全不同。

将散布在输入网格上的多条单色线段，按长度从大到小排序后，绘制为以最长线段长度为外径的同心菱形层叠图案。

**输入结构**：约 15x15 的黑(0)背景网格。网格中散布着 3~5 条互不相邻的水平或垂直单色线段，每条线段颜色各不相同（从红(2)、绿(3)、蓝(1)、黄(4)、品红(6) 中选取），长度互不相同且在 2~7 之间。线段之间至少间隔 2 个像素，不会触碰或交叉。单像素噪点不会出现。生成约束：线段数量 N 不超过 5 条，最长线段长度 L 满足 2L-1 <= 15，以保证输出菱形可容纳在 (2L-1)x(2L-1) 网格内。

**规则**：
1. 识别输入中所有单色线段（4-连通、沿单一方向的连续同色像素序列），记录每条线段的颜色和长度。
2. 按线段长度从大到小排序。若长度相同（生成约束保证不会出现），按线段左上角像素的行号升序、再列号升序打破平局。
3. 设最长线段长度为 L，创建 (2L-1)x(2L-1) 的黑(0)背景输出网格，中心像素坐标为 (L-1, L-1)。
4. 从最外层开始，第 k 条线段（k 从 0 开始）的颜色填充所有满足 manhattan_distance(pixel, center) 在区间 [L-1-k, L-1-k] 上的像素（即恰好等于 L-1-k 的所有像素构成一个菱形轮廓）。若线段数量 N < L，则内部未被分配的层（manhattan_distance < L-N）保持黑(0)背景。
5. 当有 N 条线段时，恰好绘制 N 个菱形轮廓层，第 0 层（最外）半径为 L-1，第 N-1 层（最内）半径为 L-N。中心像素仅当 L-N = 0（即 N = L）时被最内层颜色填充。

**关键洞察**：输入中线段的位置和朝向（水平/垂直）完全无关紧要；它们的长度既决定了菱形半径的排列顺序，又（通过最长线段）决定了输出网格尺寸——这是一个用线段长度同时编码排序键和几何参数的双重编码。

## 新题 2：遮挡层序驱动蛇形压缩编码

**组合逻辑**：[遮挡层序(occlusion_order)] → [排序(sorting)] → [压缩(compress) + 蛇形填充(boustrophedon_fill)]

**来源原语**：堆叠(stacking)、排序(sorting)、遮挡层序(occlusion_order)、空心矩形精灵(ring_sprite)、遮挡碎片(occluded_fragment) 来自 652646ff；压缩(compress)、蛇形填充(boustrophedon_fill)、列序排列(column_order) 来自 cdecee7f

**依赖链**：需先从重叠碎片中重建遮挡关系图 → 拓扑排序得到从顶到底的层序 → 将层序编码为蛇形填充的颜色序列写入紧凑输出网格。遮挡分析的结果不是用来重建完整精灵（如源题 652646ff），而是用来生成一个序列索引驱动蛇形布局（如源题 cdecee7f 的结构，但排序键是遮挡深度而非列位置）。

从多个部分重叠的同模板彩色环形精灵中推断遮挡层次，将从顶层到底层的颜色序列以蛇形读取顺序压缩写入一个紧凑矩形输出。

**输入结构**：约 20x20 的黑(0)背景网格。包含 4~9 个彩色环形精灵（空心矩形，均为相同的 4x4 外框、内部 2x2 为空的模板，共 12 个前景像素），每个精灵使用不同的单一颜色（从 1~9 中选取）。精灵之间部分重叠：上层精灵的像素覆盖下层精灵的模板位置。可能存在少量（不超过 2 个）单像素噪点，其像素不落在任何精灵的模板位置上。生成约束：每个精灵至少有 4 个像素可见（未被其他精灵遮挡且未超出网格边界），以确保可识别模板位置；遮挡关系构成有向无环图（无循环遮挡）。

**规则**：
1. 识别每个颜色的精灵：找到所有前景颜色，对每种颜色，检查其可见像素是否全部落在某个 4x4 环形模板（外框 12 像素、内部 2x2 空洞）的一个平移副本上。若像素数少于 4 或不符合模板，标记为噪点，忽略。
2. 对每个合法精灵，定位其完整模板位置。检查模板中每个应有该颜色却没有的位置：占据该位置的颜色即是"遮挡者"。建立遮挡关系：遮挡者在被遮挡者之上。
3. 对遮挡关系进行拓扑排序，得到从顶层（最前）到底层（最后）的颜色序列。若存在拓扑排序中的平局（两个精灵之间无直接或间接遮挡关系），按精灵左上角行号升序、再列号升序打破。
4. 设精灵总数为 N。创建一个行数为 ceil(N/3)、列数为 3 的黑(0)背景输出网格。
5. 按蛇形顺序将颜色序列写入输出：第 0 行从左到右，第 1 行从右到左，第 2 行从左到右，依此交替。若 N 不是 3 的倍数，最后一行的剩余单元格保持黑(0)。

**关键洞察**：遮挡分析在源题 652646ff 中用于重建完整精灵的空间堆叠，但此题中遮挡深度被重新编码为一维序列索引；蛇形填充在源题 cdecee7f 中由输入列位置驱动，但此题中驱动它的是一个从空间重叠关系中推断出的拓扑排序——两种原本无关的信息编码方式被结构性地耦合。

## 新题 3：印章覆盖后链式颜色替换

**组合逻辑**：[印章覆盖(stamp_overlay)] + [行调色板(row_palette) → 重涂色(recolor)] → [逐行顺序链式替换(chain_replace)]

**来源原语**：印章覆盖(stamp_overlay)、分隔网格(divider_grid)、模板掩码(template_mask)、行标记(row_marker)、行调色板(row_palette) 来自 5a5a2103；重涂色(recolor)、逐行顺序链式替换(chain_replace)、双列图例(two_col_legend)、图例行序决定替换(legend_row_order) 来自 e4888269

**依赖链**：先读取模板并按行标记色印章到各单元格 → 行标记色替换模板中的主色后，某些新产生的颜色恰好落入链式替换图例的输入色域，触发进一步变换。链式替换的结果依赖于印章后的颜色分布：若先做链式替换再印章，结果完全不同，因为模板的原始颜色与行标记色的交互方式在两种执行顺序下不一致。

在分隔网格中将模板掩码按行标记色印章到所有单元格后，再根据图例逐行链式替换最终颜色。

**输入结构**：约 17x17 的黑(0)背景网格。灰(5)色的完整水平线和垂直线将网格分为 3x3 共 9 个等大的正方形单元格（每个单元格内部约 4x4）。第一列（左侧 3 个单元格）的内容如下：每个单元格的中心像素是一个单色行标记（3 行分别为红(2)、蓝(1)、绿(3)），其余像素为黑(0)背景。第二列顶部单元格包含一个 2 列 N 行的双列图例块（N=2 或 3），图例紧贴单元格左上角放置，每行左色→右色表示一条替换规则（例如第一行"红(2)→黄(4)"，第二行"黄(4)→品红(6)"）。第三列顶部单元格包含一个多色模板掩码（3~4 个非背景像素构成一个小图案，使用的颜色包含模板主色和一种辅色）。其余单元格为纯黑(0)。生成约束：行标记色、图例中出现的色、模板中的色互有交集——至少一个行标记色是图例的某条替换规则的输入色或与其链式连通，以保证链式替换不是空操作。

**规则**：
1. 识别灰(5)分隔线划分的 3x3 单元格布局。
2. 在第一列每个单元格中提取行标记色（非背景、非灰的唯一颜色像素）。
3. 在第二列顶部单元格中提取双列图例：逐行读取，每行左像素色为"源色"，右像素色为"目标色"，行序从上到下编号。
4. 在第三列顶部单元格中提取模板掩码：记录所有非背景像素相对于单元格左上角的偏移及颜色。模板中像素数最多的非背景色为"模板主色"。
5. 印章阶段：对每个非图例、非标记的单元格（共 3 行 x 2 列 = 6 个目标单元格，即第二列下两个和第三列全部三个，加上第二列中间和底部），将模板掩码绘制到单元格内；绘制时将模板主色替换为该单元格所在行的行标记色，模板辅色保持不变。
6. 链式替换阶段：对每个目标单元格中的每个非背景像素，按图例行序从上到下逐条扫描：若当前像素颜色等于该行的源色，则替换为该行的目标色，然后继续扫描后续行（即同一像素可被多次替换，形成链）。
7. 分隔线保持灰(5)不变。行标记单元格和图例单元格保持原样不变。

**关键洞察**：印章阶段将行标记色注入模板，可能创造出新的颜色实例，而这些新实例恰好匹配链式替换图例的某条规则——因此不同行的最终输出颜色不仅取决于行标记色本身，还取决于该色在替换链中的位置深度。同一个模板在不同行的最终颜色可能经历不同长度的替换链。

## 新题 4：计数方块设定同心环宽度

**组合逻辑**：[计数(counting) + 忽略干扰项(ignore_distractors)] → [排序(sorting) + 由外到内嵌套(outside_in_nesting)] → [同心层填充(concentric_layer_filling)，创新：层厚度由计数值决定而非固定为 1]

**来源原语**：计数(counting)、正方形块(square_block)、干扰体(distractor)、忽略干扰项(ignore_distractors) 来自 1fad071e；排序(sorting)、同心层填充(concentric_layer_filling)、由外到内嵌套(outside_in_nesting) 来自 3ee1011a；频率排序(frequency_ranking) 来自 9565186b

**依赖链**：需先对每种颜色计数其合法 2x2 方块数（过滤单像素噪点）→ 按计数值降序排列得到由外到内的层序 → 每种颜色的方块计数同时决定该颜色在同心正方形图案中的环宽度（像素层数）。计数值承担双重角色：既是排序键又是几何参数，删除计数环节则层序和层宽度均无法确定。

统计各色 2x2 方块的数量（忽略同色单像素噪点），以计数值为环宽度、按计数从大到小绘制同心正方形层叠图案。

**输入结构**：约 18x18 的黑(0)背景网格。包含 3~4 种非背景色，每种颜色有若干个完全分离的 2x2 实心方块和若干个同色单像素噪点（干扰体）。不同颜色的方块和噪点之间互不相邻（8-连通意义下至少间隔 1 像素）。颜色从蓝(1)、红(2)、绿(3)、黄(4)、品红(6) 中选取。生成约束：每种颜色的 2x2 方块数量互不相同，范围在 1~4 之间；所有颜色的方块计数之和 S 满足 2S+1 <= 19，以保证输出网格不超过 19x19。

**规则**：
1. 扫描输入中每个 2x2 窗口，找出完全由同一非背景色填充的窗口，记录为该颜色的一个合法方块。同一颜色的多个合法方块不重叠（生成约束保证）。
2. 忽略所有非 2x2 方块的像素（包括同色单像素噪点和属于背景的像素）。
3. 对每种颜色统计其合法方块数量 c_i。
4. 按 c_i 从大到小排序。平局不会出现（生成约束保证）。
5. 设所有颜色的计数之和为 S。创建 (2S+1)x(2S+1) 的黑(0)背景输出网格，中心为 (S, S)。
6. 从最外层开始依次分配：排序后第 1 种颜色（计数最大，设为 c_1）占据最外 c_1 层同心正方形环（即切比雪夫距离从 S 到 S-c_1+1 的所有像素）；第 2 种颜色占据接下来的 c_2 层环；依次类推。
7. 最内侧如有剩余像素（当所有层恰好填满到中心时不会有剩余），保持黑(0)。

**关键洞察**：源题 1fad071e 中计数编码为条形图的一维长度，源题 3ee1011a 中同心层每层固定 1 像素宽。此题中计数值同时充当排序键和环宽度——这意味着方块最多的颜色不仅排在最外圈，而且占据最厚的环带，使得二维面积与一维计数之间形成非线性放大关系。

## 新题 5：镜像平铺后按角标像素分象限重涂色

**组合逻辑**：[镜像(mirror) + 平铺(tiling) → 四象限排布(four_quadrant_layout)] + [角标像素(corner_pixel) + 象限归属(quadrant_member) → 重涂色(recolor)]

**来源原语**：镜像(mirror)、平铺(tiling)、四象限排布(four_quadrant_layout)、画布(canvas)、翻转形成对称铺展(mirror_symmetric_expand) 来自 62c24649；角标像素(corner_pixel)、象限(quadrant)、象限归属(quadrant_member)、角标色定象限涂色(corner_sets_quadrant)、裁剪(crop)、重涂色(recolor) 来自 77fdfe62

**依赖链**：四个角标像素标记了各象限的"替代色" → 先移除角标像素并将图案镜像展开为四象限 → 在每个象限中，将图案内的特定颜色（所有象限共用同一个"可替换色"，即输入中非背景、非角标的出现频率最高的颜色）替换为该象限对应的角标色。镜像创建了空间结构，角标定义了该结构内的颜色差异——两者缺一不可。

**输入结构**：约 6x6 的网格（不含角标时为 4x4 的有效图案区）。四个角落像素（(0,0)、(0,W-1)、(H-1,0)、(H-1,W-1)）各为一个不同的单色标记，颜色从黄(4)、品红(6)、橙(7)、青(8) 中选取四种。其余区域在黑(0)背景上绘有一个多色图案，使用 2~3 种非背景色（如红(2)、蓝(1)、绿(3)），其中一种颜色的像素数明显多于其他（该色即"可替换色"）。角标色与图案色完全不重叠。生成约束：图案中可替换色的像素数严格大于任何其他非背景色的像素数，以保证唯一确定。

**规则**：
1. 读取四个角落像素的颜色作为象限图例：左上角色 → 左上象限，右上角色 → 右上象限，左下角色 → 左下象限，右下角色 → 右下象限。
2. 将四个角落像素替换为黑(0)背景，得到清理后的源图案 P（尺寸 HxW）。
3. 识别源图案 P 中的"可替换色"：在所有非背景色中，像素数量最多的那种颜色。
4. 构造 (2H)x(2W) 的输出网格，分四个象限放置 P 的镜像副本：
   - 左上象限：P 原样
   - 右上象限：P 的左右镜像
   - 左下象限：P 的上下镜像
   - 右下象限：P 的上下+左右镜像（等价于 180 度旋转）
5. 在每个象限中，将所有"可替换色"像素替换为该象限对应的角标色。其他颜色（背景和非可替换前景色）保持不变。

**关键洞察**：镜像操作在源题 62c24649 中产生纯对称图案，角标重涂色在源题 77fdfe62 中作用于裁剪后的掩码。此题中镜像和角标重涂同时作用于同一图案——镜像保证了四个象限的几何结构完全对称，但角标重涂打破了颜色对称，使输出呈现"形状对称但颜色分区"的独特视觉效果。必须同时理解两层规则才能得出正确输出。

## 新题 6：压缩射线像素至锚块并重建周期色序

**组合逻辑**：[周期重复(periodic_repeat) → 补全(complete)] + [压缩/滑动(compress/slide) + 射线像素紧缩至锚(compact_to_anchor)]

**来源原语**：压缩(compress)、滑动(slide)、锚块(anchor_block)、射线像素(ray_pixel)、同色射线归属锚块(ray_belongs_anchor)、射线像素紧缩至锚(compact_to_anchor) 来自 f28a3cbb；射线延伸(ray_extend)、周期重复(periodic_repeat)、对角色带(diag_color_band) 来自 cad67732；补全(complete) 来自 90f3ed37

**依赖链**：每条射线上的像素展示一个多色周期序列的不完整采样（某些周期位置的像素缺失）→ 需先识别射线方向和所属锚块 → 沿射线读取可见像素并推断底层周期模式 → 将完整的周期序列（含补全的缺失位置）紧缩到锚块相邻位置。补全依赖于周期识别，紧缩依赖于补全后的完整序列。

将散布在射线方向上的不完整周期色序像素补全后，压缩堆叠到对应锚块旁。

**输入结构**：约 20x20 的黑(0)背景网格。包含 2 个不同颜色的 3x3 实心锚块（例如红(2)和蓝(1)），分别位于网格的不同区域，互不相邻。从每个锚块出发，沿 2~4 个方向（上/下/左/右/四个对角线中选取）有一条射线，射线上的像素按照一个周期为 2 或 3 的多色序列排列，但序列中有 1~2 个位置的像素缺失（被擦除为背景色）。射线上的像素颜色从绿(3)、黄(4)、品红(6)、橙(7)、青(8) 中选取，不包含任何锚块色。每条射线上至少保留该周期序列的 2 个完整周期的可见像素（以确保周期可识别）。生成约束：不同锚块的射线互不交叉；射线像素与锚块之间可能存在背景间隙（像素并非紧邻锚块）。

**规则**：
1. 识别所有 3x3 实心单色前景块为锚块。
2. 对每个锚块，沿 8 个方向（上、下、左、右、四条对角线）扫描：收集该方向上从锚块边缘开始到网格边界或另一个锚块之间的所有非背景像素，记录每个像素的颜色和距锚块边缘的步数（按该方向的单位步长计算）。
3. 对每条有至少 2 个非背景像素的射线，将可见像素按步数排列，推断底层周期模式：找到最短周期长度 p，使得所有可见像素的颜色与其步数 mod p 的映射一致。
4. 利用推断出的周期模式补全缺失位置：对射线上从步数 1 到最远可见像素步数之间的每个步数，若该位置为背景（缺失），则根据步数 mod p 填入正确颜色。
5. 擦除输入中所有非锚块的前景像素。将每条射线的完整序列（含补全像素）紧缩到锚块的对应方向上，从紧邻锚块边缘的第一个位置开始连续排列，保持序列的原始颜色顺序（离锚块近的步数排在前面）。
6. 锚块本身保持不变。

**关键洞察**：源题 f28a3cbb 中压缩的是同色像素，无需识别模式；源题 cad67732 中周期模式用于向外延伸而非向内压缩。此题中周期识别和压缩的方向相反——先从稀疏采样中重建完整序列（需要跨间隙的模式推断），再将结果向内紧缩。如果跳过周期补全直接压缩，缺失位置将产生错误的颜色间距。

## 新题 7：前缀补全量决定垂直平移距离

**组合逻辑**：[前缀匹配(prefix_matching) + 补全/外推(complete/extrapolate)] → [平移(translate)，创新：移动距离由补全的列数决定而非自身高度]

**来源原语**：补全(complete)、外推(extrapolate)、前缀匹配(prefix_matching)、行组(row_group)、列状态序列(column_state_sequence)、完整模式续写缺失(missing_suffix_continued_from_pattern) 来自 90f3ed37；平移(translate)、移动自身高度(shift_own_height)、无重叠间距(non_overlap_spacing) 来自 5521c0d9

**依赖链**：每个下方行组是顶部完整模式的前缀 → 补全缺失后缀（用蓝(1)标记新增部分）→ 每个行组向上平移的距离等于该行组新增的列数（非自身高度）。补全步骤的输出量直接成为平移步骤的输入参数：补全越少的行组（前缀越长）移动越短，补全越多的行组移动越远。

将各行组按参考模式补全缺失列后，以新增列数为距离向上平移。

**输入结构**：约 20x25 的黑(0)背景网格。顶部有一个横跨全宽的完整行组（1~3 行高），使用红(2)色绘制一个列状态模式（例如：某些列有像素、某些列无像素，构成一个从左到右的状态序列）。下方有 2~4 个行组，每个行组的高度与顶部行组相同，使用相同的红(2)色，但每个行组只覆盖从最左列开始的一段前缀（即右侧若干列缺失）。不同下方行组的前缀长度互不相同。每个行组上方有足够的空白行（至少 max(补全列数) 行），以容纳向上平移。生成约束：顶部模式的列状态序列至少包含 4 种不同的列状态转换点；各行组的前缀终止点各不相同。

**规则**：
1. 识别顶部行组：找到网格中最上方的连续非背景行带，该行带横跨网格全宽（或覆盖了最多列）。这是完整参考模式。
2. 识别下方行组：找到其余各个独立的非背景行带（通过至少一行全黑背景与其他行组分隔）。
3. 对每个下方行组，将其列状态序列与顶部参考模式的列状态序列进行前缀匹配。确定该行组已完成的前缀长度 p 和需要续写的后缀长度 s = 总列数 - p。
4. 补全阶段：对每个下方行组，将缺失的后缀列用蓝(1)色按参考模式续写。补全后的行组宽度等于参考模式宽度。
5. 平移阶段：将每个下方行组（含补全部分）整体向上平移 s 行（s = 该行组新增的列数）。原位置清除为黑(0)背景。
6. 顶部参考行组保持原位不变。
7. 若平移后的行组与顶部行组或其他已平移行组在空间上冲突（占据同一像素），后平移的行组覆盖先存在的内容。平移处理顺序：从上到下依次处理各下方行组。

**关键洞察**：源题 90f3ed37 中补全是终点操作（补全后即输出），源题 5521c0d9 中平移距离由对象自身几何属性（高度）固定决定。此题中补全的"副产品"（新增列数）成为平移的"驱动参数"——前缀越短的行组补全越多、移动越远，形成一种"缺失越多则补偿越大"的反直觉动态：信息最不完整的行组在输出中反而位移最大。

## 新题 8：双向颜色互换改变频率排名后保留新冠军

**组合逻辑**：[图例行内配对(legend_row_pairing) + 同行颜色互换(same_row_bidirectional_swap)] → [计数(counting) + 频率排序(frequency_ranking)] → [最高频保留余替(most_frequent_kept_rest_replaced)]

**来源原语**：重涂色(recolor)、图例(legend)、多色前景对象(multicolor_foreground_object)、图例行内配对(legend_row_pairing)、同行颜色互换(same_row_bidirectional_swap) 来自 0becf7df；重涂色(recolor)、计数(counting)、频率排序(frequency_ranking)、最高频保留余替(most_frequent_kept_rest_replaced) 来自 9565186b

**依赖链**：图例定义的双向互换改变了各颜色的像素数量 → 互换后的新频率排名决定了哪个颜色被保留 → 仅保留新的最高频颜色，其余替换为灰(5)。互换步骤和频率筛选步骤缺一不可：不做互换则频率排名不同（保留的颜色错误），不做频率筛选则互换后的多色结果无法化简为最终输出。

先按图例交换颜色对，再统计交换后各色频率，仅保留最高频色、其余像素替换为灰色。

**输入结构**：约 12x12 的黑(0)背景网格。左上角有一个 2x2 的色块图例，占据位置 (0,0)~(1,1)，四个像素分别为：(0,0)=A色, (0,1)=B色, (1,0)=C色, (1,1)=D色，其中 A-B 为第一对互换色，C-D 为第二对互换色（四种颜色从红(2)、蓝(1)、绿(3)、黄(4) 中选取，各不相同）。网格其他区域（与图例不相邻的部分）包含一个由这四种颜色构成的多色前景对象（一个 4-连通连通体，约 20~40 像素），对象形状为不规则的连通区域。生成约束：互换前，颜色 A 的像素数严格大于颜色 B 的像素数（A 是互换前最高频色之一）；互换后，颜色 B 的像素数（原来的 A 的数量）严格大于其他所有颜色的像素数（即互换使 B 成为新的唯一最高频色）。这保证了互换确实改变了"冠军"。

**规则**：
1. 读取左上角 2x2 图例。第一行 (A, B) 为第一对互换色，第二行 (C, D) 为第二对互换色。
2. 对网格中所有非图例、非背景的前景像素，同时执行双向互换：所有颜色 A 的像素变为 B，所有颜色 B 变为 A，所有颜色 C 变为 D，所有颜色 D 变为 C。互换是同时进行的（基于原始颜色），不是顺序替换。
3. 互换完成后，统计所有前景像素（非背景、非图例位置）中每种颜色的像素数量。
4. 找到唯一的最高频颜色（生成约束保证唯一）。
5. 保留最高频颜色的所有像素在原位，将所有其他前景像素替换为灰(5)色。
6. 图例本身和背景像素保持不变。

**关键洞察**：源题 0becf7df 中互换是终点操作（互换即输出），源题 9565186b 中频率排名基于原始输入色。此题中互换导致原本数量最多的颜色 A 被交换到了 B 的位置上（但现在叫 B），而原本的 B 变成了 A——频率排名的"冠军"不是通过数量增减而是通过名称交换实现的。求解者必须先做互换再数频率，才能得到正确的保留色；如果直接数原始频率，会保留错误的颜色。

## 新题 9：弹性拉伸范例按端点连接规则展开到目标面板

**组合逻辑**：[弹性拉伸(elastic_stretching) + 内部行程(interior_run)] + [端点标记(endpoint_marker) + 连接跨越(connection_span)] → [按目标尺寸调整(resize_to_target)，创新：逐行选择性拉伸]

**来源原语**：弹性拉伸(elastic_stretching)、模板填充(template_filling)、多色范例矩形(multicolor_exemplar_rect)、纯色目标矩形(solid_target_rect)、内部行程(interior_run)、按目标尺寸调整(resize_to_target) 来自 40f6cd08；拉伸(stretch)、填充(fill)、分隔线(divider)、参考面板(reference_panel)、端点标记(endpoint_marker)、连接跨越(connection_span)、压缩与展开(compress_expand) 来自 9841fdad

**依赖链**：左面板中的多色范例包含边界行程和内部行程 → 右面板的端点标记指示哪些行需要弹性拉伸、哪些行只需局部复制 → 拉伸宽度由右面板的激活列跨度决定，而拉伸的方式（仅拉伸内部行程）来自范例的行程编码结构。端点标记将范例的全局拉伸分解为逐行条件拉伸。

读取左面板中的多色范例，按右面板各行的端点连接情况选择性弹性拉伸并写入右面板。

**输入结构**：约 12x20 的网格。灰(5)色边框围绕整个网格（1 像素宽）。一条灰(5)色垂直分隔线将内部分为左右两个面板，各面板内部宽度不同（左面板约 4~5 列宽，右面板约 10~12 列宽）。左面板在边框和分隔线之间各有 1 列黑(0)边距列，中间 2~3 列为激活列，包含一个多色范例图案：范例高度约 4~6 行，使用 2~3 种非背景色（如红(2)、蓝(1)、绿(3)），每行有一个可识别的行程编码结构——行的两端各有 1 像素宽的"边界行程"，中间有若干像素的"内部行程"（可能使用不同颜色）。右面板在边框和分隔线之间同样各有 1 列边距列，中间为激活列（约 8~10 列），全部为黑(0)背景，但部分行的激活列两端各有一个 2 像素宽的彩色端点标记。端点标记的行位置对应范例的行位置。生成约束：右面板激活列宽度严格大于左面板激活列宽度。

**规则**：
1. 识别边框、分隔线，确定左右面板及各自的激活列范围。
2. 从左面板激活列中提取范例图案，逐行记录行程编码：每行拆分为左边界行程（最左 1 像素）、内部行程（中间所有像素）、右边界行程（最右 1 像素）。
3. 检查右面板激活列中每行的端点标记情况，分三类：
   - **双端连接**：该行的激活列左端 2 像素和右端 2 像素均为非背景色 → 将范例该行弹性拉伸至右面板激活列全宽。拉伸方法：左边界行程复制到左端 1 像素，右边界行程复制到右端 1 像素，内部行程拉伸填满中间所有像素（使用内部行程的颜色重复填充）。
   - **仅左端**：该行仅左端 2 像素为非背景色 → 将范例该行的左边界行程复制到右面板左端 1 像素，内部行程仅复制 1 像素到其右侧，其余保持黑(0)。
   - **仅右端**：该行仅右端 2 像素为非背景色 → 将范例该行的右边界行程复制到右面板右端 1 像素，内部行程仅复制 1 像素到其左侧，其余保持黑(0)。
   - **无端点**：该行无端点标记 → 保持黑(0)，不复制任何范例内容。
4. 端点标记像素本身保留在输出中不变。
5. 左面板保持原样不变。

**关键洞察**：源题 40f6cd08 中弹性拉伸均匀应用于每个目标矩形的所有行，源题 9841fdad 中端点标记控制的是简单的行复制和连接填充。此题中端点标记将弹性拉伸从"整体操作"分解为"逐行条件操作"——同一个范例的不同行在右面板中可能呈现完全不同的宽度（全拉伸 vs. 局部复制 vs. 缺失），使输出图案的形状取决于端点标记的行分布模式。

**组合逻辑**：[颜色决定操作(color_det_operation) + 收缩(shrink)/膨胀(dilate) + 半径微调(radius_adjust)] → [排序(sorting) + 由外到内嵌套(outside_in_nesting)] → [同心层填充(concentric_layer_filling)，创新：菱形层 + 排序基于变换后半径]

**来源原语**：收缩(shrink)、膨胀(dilate)、菱形轮廓(diamond_outline)、颜色决定操作(color_det_operation)、半径微调(radius_adjust) 来自 d753a70b；排序(sorting)、同心层填充(concentric_layer_filling)、由外到内嵌套(outside_in_nesting)、按长度降序(desc_segment_length) 来自 3ee1011a

**依赖链**：输入中多个独立菱形轮廓各有不同颜色和半径 → 颜色决定该菱形收缩还是膨胀一层（修改半径）→ 修改后的半径可能改变原有的大小排序 → 按修改后半径从大到小重新排序 → 以新半径在公共中心绘制同心菱形层叠。收缩/膨胀步骤的输出（修改后半径）直接改变排序结果，而排序结果决定了同心层叠的层序——删除任何一步都无法得到正确输出。

先按颜色规则收缩或膨胀各菱形轮廓的半径，再按新半径排序绘制为同心菱形层叠图案。

**输入结构**：约 16x16 的橙(7)背景网格。包含 3~5 个独立的曼哈顿距离菱形轮廓（1 像素宽的菱形环），各有不同的中心位置和半径。每个菱形使用以下颜色之一：红(2)表示"收缩"，灰(5)表示"膨胀"，蓝(1)或绿(3)表示"不变"。各菱形的初始半径互不相同，范围在 2~6 之间。菱形之间互不重叠且不相邻。生成约束：红色菱形的半径至少为 2（收缩后半径至少为 1）；收缩/膨胀后各菱形的新半径仍互不相同（不会因微调产生相同半径）；存在至少一对菱形在微调后大小顺序发生反转（即初始时 A 半径 > B 半径，微调后 A 的新半径 < B 的新半径）。

**规则**：
1. 识别所有菱形轮廓：在橙(7)背景上找到每个非背景色的连通体，验证其像素是否落在某个曼哈顿距离轮廓 {(r,c) : |r-cr|+|c-cc| = R} 上。记录每个菱形的颜色和初始半径 R。
2. 按颜色规则修改半径：
   - 红(2)色菱形：新半径 = R - 1
   - 灰(5)色菱形：新半径 = R + 1
   - 蓝(1)色或绿(3)色菱形：新半径 = R（不变）
3. 按新半径从大到小排序。新半径相同的情况不会出现（生成约束保证）。
4. 设最大新半径为 R_max。创建 (2*R_max+1) x (2*R_max+1) 的橙(7)背景输出网格，中心为 (R_max, R_max)。
5. 从最外层开始，按排序顺序依次绘制每个菱形的单像素宽轮廓：第 k 个菱形（k 从 0 开始）绘制在曼哈顿距离等于 R_max - k 的所有位置上，颜色保持该菱形的原色。
6. 如果菱形数量 N 少于 R_max + 1，则内部未分配的层保持橙(7)背景。

**关键洞察**：源题 d753a70b 中收缩/膨胀是原地操作（菱形保持原位），源题 3ee1011a 中排序基于输入的原始属性（线段长度不变）。此题中收缩/膨胀修改了菱形的"有效半径"，而这个有效半径才是排序键——因此颜色不仅决定了几何变换的方向（收缩 vs 膨胀），还间接改变了该菱形在最终同心排列中的径向位置。必须先理解颜色→半径变换的规则，才能预测排序后的正确层序。
