## 新题 1：形状频次驱动模板旋转印章

**组合逻辑**：[形状匹配 + 计数](从频次分析中获取全局属性) → [旋转](频次 mod 4 映射旋转角) → [印章覆盖](旋转后的模板覆盖原位)

**来源原语**：形状匹配/shape_matching、唯一重复形分涂/unique_vs_repeated_recolor（来自 b230c067）；旋转/rotate、逐槽位累计旋转/successive_rotation_per_slot（来自 8e5a5113）；印章覆盖/stamp_overlay、缩放对应/scale_correspond（来自 447fd412）

**依赖链**：形状分组是全局操作，决定每组的成员数 f；f mod 4 产生旋转索引，驱动模板的旋转角度；旋转后的模板被印章到对应精灵体位置。单个精灵体的输出旋转角无法仅凭自身确定——必须统计全网格同形精灵体数量。

将散布的同色精灵体按形状分组，每组成员数决定一个模板旋转角度，用旋转后的模板替换每个精灵体。

**输入结构**：约 12x15 的黑(0)背景网格。左上角 4x4 区域内有一个蓝(1)的小型非对称模板（3x3 边界框，3~5 像素，4-连通，无旋转对称性，例如不规则 L 状或阶梯状）。网格其余区域散布 5~8 个绿(3)的小精灵体，每个 3~6 像素，4-连通，边界框均不超过 3x3。精灵体之间间距至少 3 像素（边界框不重叠且不相邻）。精灵体中存在 2~3 种不同的归一化形状：至少一种形状只出现一次，至少一种出现 2 次以上。生成约束：模板边界框恰好 3x3；所有精灵体边界框均在 3x3 以内，保证印章后不互相重叠。

**规则**：
1. 识别模板：左上角 4x4 区域内的蓝(1)连通分量。
2. 识别所有绿(3)精灵体，计算每个精灵体的归一化边界框掩模（平移使左上角对齐到 (0,0)）。
3. 按归一化掩模分组。统计每组成员数 f。
4. 计算旋转索引 r = f mod 4。将模板顺时针旋转 90°×r：r=0 不旋转，r=1 旋转 90°，r=2 旋转 180°，r=3 旋转 270°。
5. 对每个精灵体：擦除其绿(3)像素，将该精灵体所在组对应的旋转模板印章到该精灵体边界框左上角位置。模板中蓝(1)像素输出蓝(1)，模板中黑(0)像素输出黑(0)。
6. 原左上角的模板区域同样擦除为黑(0)。
7. 各精灵体边界框互不重叠，处理顺序不影响结果。

**关键洞察**：任一精灵体的输出旋转角度取决于全网格中与之同形的精灵体总数——这是一个全局属性驱动局部几何变换的过程；不比较所有精灵体的形状就无法确定任何一个的旋转角。

## 新题 2：重力沉降重构贪心路径拓扑

**组合逻辑**：[滑动/重力沉降](所有刚体右移至稳定) → [连线/贪心遍历](在沉降后的布局上求最近可见路径)

**来源原语**：滑动/sliding、重力沉降/gravity_settle、碰撞阻挡/collision_block（来自 d282b262）；连线/path_painting、贪心遍历/greedy_traversal、视线可见/line_of_sight_visible、最近未访问优先/nearest_unvisited_first（来自 3490cc26）

**依赖链**：重力将所有方块向右推至稳定位置，改变了方块之间的相对距离和对齐关系；贪心路径依赖沉降后的视线可达性和距离排序。沉降前看似对齐的方块可能被挤入的第三块遮挡，而沉降前不对齐的方块可能因堆叠而进入同一行/列带。

将所有 2x2 方块向右滑动至稳定后，从红色起始块沿视线贪心遍历青色目标块并涂橙色走廊。

**输入结构**：约 15x15 的黑(0)背景网格。包含 1 个红(2)的 2x2 起始块和 4~6 个青(8)的 2x2 目标块。方块在原始布局中散布于不同位置，没有两个方块在初始状态下同时处于同一 2-行带或 2-列带中。部分方块在向右滑动后会进入同一水平 2-行带或垂直 2-列带（产生新的视线对齐）。生成约束：向右滑动后所有方块不重叠；从红块出发至少存在一条经过所有可达青块的贪心路径。

**规则**：
1. 将每个 2x2 方块（红或青）视为刚体。
2. 同步向右滑动：每步每个方块右移一列，若目标格在网格内且未被其他方块占据则移动。重复直到无方块可移动（被右边界或已稳定方块阻挡）。
3. 在沉降后的布局上执行贪心遍历：
   a. 从当前方块出发，找到所有与当前方块同处一条水平 2-行带或垂直 2-列带的未访问青块，且两者之间的背景格中无非背景像素（视线可达）。
   b. 在可达的未访问青块中选最近者（中心之间曼哈顿距离最小）。若距离相等，优先选行号较小者。
   c. 在当前方块与被选方块之间的背景格涂橙(7)。
   d. 移动到被选方块，重复步骤 a。
4. 当从当前位置无法看到任何未访问青块时停止。
5. 所有方块保持原色（红保持红，青保持青），橙色仅覆盖背景像素。

**关键洞察**：贪心路径是在沉降后的几何布局上计算的，而非原始布局。原本远离的方块可能因向右挤压而紧邻，原本对齐的方块可能被第三块的沉降位置遮挡视线——求解者必须先完成物理模拟才能规划路径。

## 新题 3：象限叠加涌现长对角线后交替涂色

**组合逻辑**：[透明叠加/裁剪](四象限非背景优先合并) → [涌现对角线段] → [奇偶交替涂色](在合并后的全局对角线上执行)

**来源原语**：透明叠加/transparent_overlay、裁剪/crop、象限区/quadrant、分隔十字/separator_cross、非背景优先合并/nonbackground_priority_merge（来自 a68b268e）；重涂色/recolor、奇偶交替涂色/alternating_parity_recolor、对角线段/diagonal_segment、序列索引/sequential_index（来自 a5f85a15）

**依赖链**：四象限各含短对角线片段 → 叠加合并时，不同象限的片段可能在对应位置接续形成更长对角线 → 交替涂色的奇偶索引取决于合并后的完整对角线长度和起点，而非任何单一象限内的片段。叠加改变了对角线段的长度，进而改变了哪些像素被涂为黄色。

将四个象限按非背景优先规则叠加为一个网格，再在合并结果的每条极大右下对角线段中将奇数位像素涂黄。

**输入结构**：11x11 的网格（奇数尺寸，使中心十字恰好分割）。灰(5)的全跨分隔十字（一整行 + 一整列穿过中心）将网格分为 4 个等大的 5x5 象限。每个象限用黑(0)背景加一种独有的前景色绘制对角线像素段：左上用红(2)，右上用蓝(1)，左下用绿(3)，右下用橙(7)。每个象限含 1~3 条短的右下对角线段（每段 2~4 像素）。生成约束：至少有一对来自不同象限的段在叠加后的对应坐标上沿右下方向首尾衔接，形成一条比任何单象限段都长的合并对角线；保证涌现效果改变交替涂色结果。

**规则**：
1. 移除灰(5)分隔十字。
2. 将四个 5x5 象限叠加为一个 5x5 输出网格：对每个格，按行主序扫描象限（左上→右上→左下→右下），取第一个非黑(0)像素；若四个象限的对应格都是黑(0)，输出黑(0)。
3. 在合并后的 5x5 网格中，找到所有极大右下对角线段（沿 (行+1, 列+1) 方向连续非黑像素的最长序列，不可再延伸）。
4. 在每条段内，从左上端开始编索引 0, 1, 2, ...。偶数索引像素保持合并后的颜色不变，奇数索引像素涂为黄(4)。
5. 不在任何右下对角线段上的非黑像素以及黑背景像素保持不变。

**关键洞察**：叠加可以创造出比任何单一象限中都长的对角线段。段长度变化导致交替涂色的奇偶分界点发生位移——例如一个原本 2 像素的段（仅第 2 个像素变黄）与另一象限的段合并后变为 4 像素段（第 2、4 个像素变黄），后半段的涂色模式完全由合并行为决定。

## 新题 4：十字检测播种邻域参数化同心扩展

**组合逻辑**：[局部模板匹配](检测黑色十字图案中心) + [计数](对角邻域青像素数) → [填充/中心扩展](同心菱形环扩展，颜色和优先级均由对角邻域数决定)

**来源原语**：重涂色/recolor、十字图案/plus_pattern、正交邻接/orthogonal_adjacency、局部模板匹配/local_template_match（来自 7e02026e）；填充/flood_fill、距离决定调色板/distance_determines_palette、循环色带/cyclic_color_bands（来自 13e47133）；中心扩展/center_expansion（来自 913fb3ed）

**依赖链**：十字模板检测在青黑网格中找到种子点 → 每个种子的对角邻域青像素数 d 同时决定扩展颜色和冲突优先级 → 同心菱形环从种子向外生长直到遇青或边界 → 重叠区域由 d 值裁决。同一网格结构同时承担三个角色：定义十字可出现的位置（黑区）、参数化扩展（对角邻域）、限制扩展范围（青屏障）。

在青黑网格中检测黑色十字图案，从每个十字中心向外绘制同心菱形环，环的颜色和冲突优先级由该中心对角方向的青像素邻居数决定。

**输入结构**：约 14x14 的网格，仅含黑(0)和青(8)两种颜色。青像素构成不规则的连通区域和边界线。在黑色区域中，若干位置满足十字图案条件：中心像素为黑，其上下左右四个正交邻居也均为黑（共 5 个黑像素组成 + 形）。每个十字中心有 0~4 个对角邻居（(r-1,c-1)、(r-1,c+1)、(r+1,c-1)、(r+1,c+1) 四格中为青的个数）为青(8)。生成约束：存在 3~5 个有效十字中心，至少有两个中心的对角青邻居数不同；十字中心之间间距至少 4 格，确保扩展区域有实质重叠。

**规则**：
1. 找到每个黑(0)像素，若其上(N)、下(S)、左(W)、右(E)四个正交邻居也为黑(0)，则该像素为十字中心。
2. 对每个十字中心，统计其 4 个对角邻居中有多少个是青(8)，记为 d（0 <= d <= 4）。
3. 按 d 分配扩展颜色：d=0 → 蓝(1)，d=1 → 红(2)，d=2 → 绿(3)，d=3 → 黄(4)，d=4 → 橙(7)。
4. 从每个十字中心向外，按曼哈顿距离 k = 0, 1, 2, ... 逐层扩展：将距离为 k 的所有黑(0)格涂为该中心的分配颜色。扩展在某方向遇到青(8)像素或网格边界时停止（青像素永不被覆盖）。十字的四条臂（距离 1 的正交邻居）作为第 1 层被涂色。
5. 当两个不同中心的扩展覆盖同一格时，d 值较大的中心优先。若 d 相等，行号较小的中心优先；行号也相等则列号较小的优先。
6. 所有青(8)像素在输出中保持不变。

**关键洞察**：同一网格结构同时扮演三重角色——青像素围出黑区决定了十字能在哪里形成（检测），对角位置的青像素数量决定了扩展的颜色和冲突优先级（参数化），而青像素又构成扩展的物理屏障（范围限制）。移动一个青像素可能同时改变哪些十字被检测到、它们的颜色分配、以及它们能扩展多远。

## 新题 5：重力变换自引用印章

**组合逻辑**：[滑动/重力沉降](列内下沉) → [自身为模板 + 非背景处印章](沉降后的精灵体同时充当模板和印章内容)

**来源原语**：滑动/sliding、重力沉降/gravity_settle（来自 d282b262）；像素放大/pixel_upscale、印章覆盖/stamp_overlay、自身为模板/self_as_stencil、非背景处印章/stamp_at_nonbg（来自 007bbfb7）

**依赖链**：重力改变精灵体的内部布局 → 改变后的精灵体同时作为「模板」（决定哪些输出块被填充）和「印章」（决定填充内容）。一次变换同时改变输出的两个独立维度：哪些块被选中以及块内画什么。这是乘法式耦合，非加法式。

将小精灵体中的像素按列下沉（重力），然后用沉降后的精灵体自印章——在每个非黑格对应的输出块中粘贴整个沉降后的精灵体。

**输入结构**：4x4 的小网格，含 3~6 个非黑像素，使用 1~3 种非黑颜色（如红(2)、蓝(1)、绿(3)），其余为黑(0)背景。部分像素处于「悬浮」状态（同列下方有黑格）。生成约束：重力沉降后的布局与原始布局不同（至少一个像素下移）；沉降后至少有 3 个非黑像素以产生有意义的自印章输出。输出尺寸为 16x16。

**规则**：
1. 在 4x4 输入中，逐列执行下沉：将每列中所有非黑像素向下滑动，堆叠在该列底部，保持列内像素的原始上下顺序。
2. 将沉降后的 4x4 网格记为 S。
3. 创建 16x16 的输出网格（输入尺寸的 4 倍），划分为 4x4 个块，每块 4x4，一一对应 S 中的格。
4. 对 S 中每个格 (r, c)：
   - 若 S[r][c] 为非黑色，将完整的 S 粘贴到输出中对应块的位置：output[r*4+i][c*4+j] = S[i][j]，其中 i, j 遍历 0..3。
   - 若 S[r][c] 为黑(0)，对应输出块全部为黑(0)。

**关键洞察**：重力不仅仅是预处理——它同时改变了「哪些块被填充」（模板角色）和「块内填什么」（印章角色）。一个从第 0 行掉到第 3 行的像素，在模板层面从「顶部块行」移到「底部块行」，同时在印章层面改变了内部图案的布局。求解者必须意识到沉降后的同一个精灵体同时扮演两个角色。

## 新题 6：旋转生成迷宫墙壁后穿门寻路

**组合逻辑**：[旋转 + 逐槽位累计旋转](从模板生成每个区域的墙壁) → [寻路/连线](在生成的墙壁中穿越门中心绘制路径)

**来源原语**：旋转/rotate、模板/template、分隔线/divider_line、槽位/slot、顺序排列/sequential_order、逐槽位累计旋转/successive_rotation_per_slot（来自 8e5a5113）；连线/draw_path、寻路/pathfinding、平行墙壁/parallel_walls、门段/door_segment、穿越门中心/through_door_center、走廊正交路径/corridor_ortho_path、标记像素/marker_pixel（来自 7e576d6e）

**依赖链**：旋转规则从单一模板生成每个区域的墙壁布局 → 墙壁布局决定门的位置 → 门的位置约束从起点到终点的唯一有效路径。不推断旋转规则就无法预测门在哪里，不知道门的位置就无法画路径。

从一个带门的墙壁模板出发，逐区域旋转填充空槽位以生成迷宫，然后绘制穿越所有门中心的标记色路径。

**输入结构**：约 15x17 的网格。灰(5)全跨垂直分隔线将网格分为 4 个等宽区域（每区域约 4 列宽，15 行高）。最左区域包含一个墙壁模板：一条青(8)横线跨满区域宽度位于某行，线上有一个 3 像素宽的间隙（门），其余为黑(0)。右侧 3 个区域均为黑(0)（空槽位）。两个红(2)标记像素分别位于最左区域（墙壁上方或下方）和最右区域。生成约束：旋转后每个区域恰好有一道墙和一个门；门的位置在不同区域互不相同（旋转产生的偏移保证之字形路径）；各区域宽度足以容纳旋转后的墙壁图案。

**规则**：
1. 识别第一（最左）区域内的墙壁模板：提取区域边界内的图案（忽略灰分隔线）。
2. 将模板逐区域旋转后填充：
   - 区域 2：模板顺时针旋转 90°
   - 区域 3：模板旋转 180°
   - 区域 4：模板顺时针旋转 270°
3. 每次旋转将横墙变为纵墙（或反之），门的间隙也随之旋转到新的位置。
4. 绘制红(2)路径从一个标记到另一个标记：
   a. 在每个区域的走廊（墙壁与区域边界之间的空间）中，路径沿正交方向行进到本区域墙壁的门中心。
   b. 穿过门中心后继续行进到下一区域的走廊。
   c. 在相邻区域之间，路径通过灰分隔线列自由穿行。
5. 路径仅使用水平和垂直线段。路径像素仅覆盖黑(0)背景，不覆盖墙壁或标记。

**关键洞察**：输入中大部分墙壁不存在——它们由旋转规则生成。求解者必须从示例中推断旋转规则来预测每个区域的门位置，然后在这些预测的门之间规划路径。旋转步骤和寻路步骤不可分割：不知道旋转规则就不知道门在哪里，不寻路则旋转只是装饰。

## 新题 7：交替对角涂色的奇数像素数驱动描边半径

**组合逻辑**：[奇偶交替涂色](对角线段内奇数位涂黄) → [计数](统计每段产生的黄色像素数 Y) → [描边/中心扩展](以段中点为中心画边长 2Y+1 的空心方框)

**来源原语**：重涂色/recolor、奇偶交替涂色/alternating_parity_recolor、对角线段/diagonal_segment、序列索引/sequential_index（来自 a5f85a15）；计数/counting、颜色数决定高度/color_count_height（来自 fcc82909）；描边/outline、空心矩形/hollow_square、中心扩展/center_expansion（来自 913fb3ed）

**依赖链**：交替涂色将每段中奇数位像素变黄 → 黄色像素数 Y = floor(段长/2) 成为描边参数 → 以段中点为中心的空心方框边长 = 2Y+1。涂色步骤不只是装饰——它直接计算出了描边尺寸的输入参数。删除交替涂色则描边半径无法确定。

在每条对角线段上执行奇偶交替涂色，然后统计每段的黄色像素数作为该段中点处空心描边框的半径。

**输入结构**：约 14x14 的黑(0)背景网格。包含 3~5 条由红(2)像素构成的极大右下对角线段，各段长度不同（2~6 像素）。各段之间间距足够大（中点之间至少 8 格），使得最大的描边框也不会超出网格或与其他段的本体重叠。生成约束：各段长度至少有两种不同值；最长段的描边框不超出网格边界。

**规则**：
1. 找到所有极大右下对角线段（沿 (行+1, 列+1) 方向的连续红(2)像素序列）。
2. 在每段内，从左上端开始编索引 0, 1, 2, ...。将奇数索引位的像素从红(2)涂为黄(4)；偶数索引位保持红(2)。
3. 统计每段中黄(4)像素的数量 Y（即 floor(段长/2)）。
4. 确定每段的中点像素：若段长为 L，中点为索引 floor(L/2) 处的像素。
5. 以中点像素为中心，在输出中画一个边长为 (2Y+1) 的空心正方形（1 像素宽的绿(3)边框）。空心正方形的中心与中点像素重合。
6. 当多个空心方框重叠时，来自更长段（Y 更大）的方框优先绘制在上层。若 Y 相同，中点行号更小的优先；行号也相同则列号更小的优先。
7. 对角线段像素（红和黄）不被方框覆盖——它们始终显示在最上层。

**关键洞察**：交替涂色不仅仅是视觉效果——它生成的黄色像素数量直接决定了每条段的描边框大小。一条长度为 5 的段产生 2 个黄像素，得到 5x5 的框；一条长度为 3 的段产生 1 个黄像素，得到 3x3 的框。涂色是计算步骤，不是最终展示步骤。

## 新题 8：梳齿高度编码滚动量，边带颜色序分配轴

**组合逻辑**：[压缩/计数](读取梳状结构齿数) + [排序/序列索引](边带颜色左右顺序) → [循环位移](两轴滚动量由上述两步交叉确定)

**来源原语**：压缩/compress、计数/count、排序/sort、色条/color_bar、梳状结构/comb_motif、高度编码数量/height_encodes_count（来自 a1aa0c1e）；循环位移/cyclic_roll、控制行/control_row、双轴偏移编码/dual_axis_offset、标记位定位移量/marker_is_shift（来自 79cce52d）

**依赖链**：梳状结构的齿数编码两个滚动量 → 边带像素的左右颜色顺序决定哪个滚动量分配到哪个轴 → 有效载荷按解码出的两轴量循环位移。三个独立输入特征（梳齿高度、边带顺序、有效载荷内容）必须交叉引用。仅看梳齿不知道轴分配，仅看边带不知道滚动量。

读取两组梳状结构的齿数作为滚动量，由底部边带的颜色左右顺序决定哪个量对应纵轴哪个对应横轴，然后对有效载荷执行循环位移。

**输入结构**：约 12x14 的网格，分为三个区域：
1. **有效载荷**（左上，6x6）：由红(2)、蓝(1)、绿(3)像素在黑(0)背景上组成的彩色图案，是待滚动的内容。
2. **梳状区**（右侧，约 6 列 x 8 行）：两根垂直梳状结构，各用一种独有颜色——一根黄(4)，一根橙(7)。每根梳是一条该色的垂直柱（1 像素宽），柱上有若干水平齿向左延伸（每颗齿为 1 像素的水平凸出，位于不同行）。两根梳的齿数不同（如 2 齿和 4 齿），均在 1~5 之间。两根梳之间有至少 1 列的间隔。
3. **边带**（底部一整行，全宽）：灰(5)背景上恰好有两个彩色像素——一个黄(4)、一个橙(7)，分别位于不同列。不同示例中二者的左右顺序不同。
生成约束：梳的齿数在有效载荷尺寸范围内（1~5）；两根梳齿数不同；有效载荷图案在两个方向上的循环位移均产生可区分的不同结果。

**规则**：
1. 对梳状区中的每根梳，统计其水平齿的数量（从垂直柱向左延伸的单像素凸出数）。分别记为 C_yellow（黄梳齿数）和 C_orange（橙梳齿数）。
2. 读取底部边带，从左到右扫描。先出现的颜色编码**纵向**（向下）滚动量，后出现的颜色编码**横向**（向右）滚动量。
3. 查找对应滚动量：若黄在左，则纵向滚动 = C_yellow，横向滚动 = C_orange；若橙在左，则纵向滚动 = C_orange，横向滚动 = C_yellow。
4. 对有效载荷执行循环位移：先将所有行整体向下移动纵向量（溢出底部的行回卷到顶部），再将所有列整体向右移动横向量（溢出右侧的列回卷到左侧）。
5. 输出仅为滚动后的 6x6 有效载荷，丢弃梳状区和边带。

**关键洞察**：滚动量和轴分配来自两套独立的编码机制，必须交叉引用才能解码。梳齿编码了幅度，但边带的颜色左右顺序决定了哪个幅度对应哪个轴。交换边带中两个像素的左右位置就完全改变输出，尽管梳状结构没有任何变化。

## 新题 9：重叠空心矩形遮挡解码层序

**组合逻辑**：[描边/空心矩形识别](从遮挡图中重建完整轮廓) + [层级优先推断](通过交叠点的可见色判断前后关系) → [排序/压缩](输出从前到后的颜色序列)

**来源原语**：描边/outline、空心矩形/hollow_square（来自 913fb3ed）；透明叠加/transparent_overlay、层级优先/layer_priority、非背景优先合并/nonbackground_priority_merge（来自 a68b268e）；计数/counting、排序/sort（来自 a1aa0c1e）；裁剪/crop（来自 a68b268e）

**依赖链**：输入是已叠加完成的最终图像 → 求解者必须逆向识别各空心矩形的完整轮廓（包括被遮挡的部分）→ 在重叠点分析可见色推断哪个矩形在哪个之上 → 构建全序 → 输出排好序的颜色行。这是结构解码问题，不是空间变换。

从多个重叠空心矩形的遮挡图中推断堆叠顺序，输出从最前到最后层的颜色序列。

**输入结构**：约 12x12 的黑(0)背景网格，含 3~5 个互相部分重叠的空心矩形（1 像素宽的边框，无填充）。每个矩形使用一种独有颜色：如红(2)、蓝(1)、绿(3)、黄(4)、橙(7)。矩形大小各不相同（边界框从 3x3 到 8x8 不等），位置有偏移使得两两之间至少存在一个像素位置的边框重叠。在重叠像素处，仅「最上层」矩形的颜色可见（如同从后往前依次绘制）。输出为 1 行 N 列的网格（N 为矩形数量）。生成约束：遮挡关系定义一个唯一全序（不存在无法比较的矩形对——任意两个矩形至少在一个像素处重叠）；每个矩形至少有一条完整边可见，使得其完整轮廓可被推断。

**规则**：
1. 识别网格中存在的空心矩形集合。对每种颜色，根据其可见的边框像素段推断完整矩形轮廓（部分边框可能被更高层矩形遮挡而不可见）。推断方法：每个矩形是轴对齐的完整空心矩形，可从可见的角点或相邻两条边确定。
2. 判断堆叠顺序：对每对矩形 A 和 B，找到它们边框理论上重叠的像素位置。若该位置可见色为 A 的颜色，则 A 在 B 之上；反之 B 在 A 之上。
3. 从所有两两比较中构建全序：最前（最上）到最后（最下）。
4. 输出 1 行 N 列的网格：从左到右依次为最前层到最后层矩形的颜色。

**关键洞察**：求解者看到的是一堆交错的彩色线段，必须先逆向重建出每个矩形的完整几何形状（包括被遮挡的部分），然后在每个重叠点推断哪个在前。一个被大面积遮挡的矩形可能仅凭极少的可见像素被识别，使得层序推断极度依赖对完整轮廓的正确重建。

## 新题 10：标记带划分驱动列局部涂色后平铺

**组合逻辑**：[扩展/中点划分归属](标记像素定义横带边界) + [计数/列选择](带内含前景的列被选中涂色) → [平铺](涂色后的结果 2x2 平铺)

**来源原语**：扩展/expand、边框绘制/frame_drawing、单像素标记/single_pixel_marker、横带/horizontal_band、按行排序/sorted_by_row、中点划分归属/midpoint_band_assignment（来自 0f63c0b9）；重涂色/recolor、前景列/foreground_column、列选择/column_selection、含前景列整列涂色/fg_col_full_recolor（来自 f5b8619d）；平铺/tiling（来自 f5b8619d）

**依赖链**：标记像素行位置 → 中点划分产生横带边界 → 每个横带内独立判断哪些列含前景 → 这些列在该带内的黑背景格被涂青 → 带内的涂色决策在不同带之间独立（同一列在上带可能涂色而在下带不涂） → 涂色完成后整体 2x2 平铺。列选择是带局部的，而非全局的——这是与参考题 f5b8619d 的核心区别。

按标记像素的行位置中点划分横带，在每个横带内独立执行列选择涂色，然后将结果 2x2 平铺。

**输入结构**：约 7x7 的黑(0)背景网格（输出为 14x14）。含 2~3 个孤立的单像素标记，每个使用不同颜色（如红(2)、蓝(1)），位于不同行。另有若干绿(3)前景像素稀疏分布。标记像素和绿像素均不在网格边缘行。生成约束：标记行互不相同；至少存在一列在某个横带内含绿像素而在另一横带内不含（确保带局部列选择产生带间差异）。

**规则**：
1. 按行号排序所有标记像素。在相邻标记行之间取中点（向下取整）作为横带分界行。网格顶部到第一个中点为第一带，相邻中点之间为中间带，最后一个中点到网格底部为最后一带。
2. 对每个横带独立执行：扫描该带行范围内的每一列，若该列在此行范围内存在至少一个绿(3)像素，则将该列在此带行范围内的所有黑(0)像素涂为青(8)。绿(3)像素和标记像素本身保持不变。
3. 将步骤 2 完成后的 7x7 网格进行 2x2 平铺：水平重复 2 次、垂直重复 2 次，输出 14x14 网格。

**关键洞察**：列涂色判断是横带局部的——同一列可能在上带因有绿像素而整列涂青，在下带因无绿像素而保持黑色。这使得输出平铺图案中出现「断列」效果（同一列在不同横带区域有不同颜色），而这种效果在原始参考题的全局列选择中不会出现。标记位置同时决定了带边界（哪些行属于哪个带）和带内有哪些前景像素可用。
