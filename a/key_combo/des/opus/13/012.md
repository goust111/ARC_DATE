## 新题 1：对角链分类驱动标记淘汰

**组合逻辑**：[对角链式连接/diagonal_chain](已有) + [计数/counting](已有) → 分支决策 → [重涂色/recolor](创新：仅对链式区域执行) | [擦除/erase](创新：阈值由拓扑分类决定)

**来源原语**：recolor、erase、counting（参考题 10: a934301b）；eight_conn_region、diagonal_chain、diagonal_touch_recolor（参考题 3: ecb67b6d）；marker_pixel、marker_in_object、erase_above_threshold（参考题 10: a934301b）

**依赖链**：对每个 8-连通前景区域做 4-连通分解并判定是否为对角链 → 分类结果决定走哪条规则分支 → 链式区域无条件重涂色；非链式区域进入标记计数 → 计数结果决定保留或擦除。拓扑分类和标记计数缺一不可：没有分类不知道走哪条分支，没有计数不知道非链式区域是否存活。

输入中包含拓扑结构各异的区域和散落的标记像素，输出中链式区域统一变为青(8)色，非链式区域根据内部标记数量或保留原色或被完全擦除。

**输入结构**：约 15x15 网格，黑(0)背景。橙(7)色前景像素构成 5~7 个互不接触的 8-连通区域，每个区域约 4~12 像素。区域的形态多样：部分区域由多个 4-连通瓣体仅通过对角角点相连形成非分叉的对角阶梯链（如从左上到右下的锯齿状），其余区域为紧凑块状、矩形条带或包含分叉的不规则团簇。蓝(1)标记像素散落在部分区域内部（与橙像素相邻但不与其 4-连通），每个区域内有 0~3 个蓝标记。生成约束：至少有 2 个对角链区域和 2 个非链区域；非链区域中至少 1 个含 0 或 1 个标记（保留），至少 1 个含 2 个以上标记（擦除）。

**规则**：
1. 将每个橙(7) 8-连通区域分解为 4-连通瓣体。
2. 判定区域类型：若该区域的所有瓣体仅通过对角角点接触，且形成非分叉的链或环（即每个瓣体至多与 2 个其他瓣体对角接触），则该区域为"对角链"；否则为"非链"。单个 4-连通区域如果自身是沿对角线排列的阶梯形（每行恰一个像素且逐行平移一列），也算作对角链。
3. 对角链区域：将该区域所有像素（橙和蓝）统一重涂为青(8)。蓝标记对该分支无影响。
4. 非链区域：统计区域内蓝(1)标记像素的数量。若数量 >= 2，将该区域所有像素（橙和蓝）擦除为背景黑(0)。若数量 < 2（即 0 或 1），保持该区域所有像素不变。
5. 不属于任何区域的孤立蓝(1)像素（若存在）保持原位。

**关键洞察**：同样的蓝色标记像素在不同拓扑类型的区域中扮演完全不同的角色——在对角链区域中它们被无条件吸收为青色，在非链区域中它们是生死判官。必须先做拓扑分类才能决定标记的语义。

## 新题 2：矩形纵深既是存活阈值又是着色参数

**组合逻辑**：[边距深度/edge_distance_depth](创新：同时用于阈值比较和着色分层) + [计数/counting](已有) → [擦除/erase](已有：超阈值擦除) | [循环填充/concentric_fill](已有：分层涂色)

**来源原语**：concentric_fill、solid_rectangle、concentric_layer、edge_distance_depth、odd_even_alternating_color（参考题 19: 516b51b7）；erase、counting、marker_pixel、marker_in_object、erase_above_threshold（参考题 10: a934301b）

**依赖链**：每个矩形的最小半径 D = floor(min(宽, 高) / 2) 同时决定两件事：(1) 与内部标记数比较决定存活；(2) 若存活则 D 决定同心层的总层数和着色模式。不能跳过尺寸计算（不知道阈值也不知道层数），不能跳过标记计数（不知道是否擦除）。

矩形的紧凑程度同时决定其存活门槛和存活后的内部图案——薄长矩形低阈值易被擦除且层数少，方正矩形高阈值难被擦除且层数多。

**输入结构**：约 18x18 网格，黑(0)背景。4~6 个绿(3)实心轴对齐矩形，尺寸从约 2x4 到 7x8 不等，互不接触也不重叠。红(2)标记像素散落在部分矩形内部（占据矩形内的背景位置——即标记不替换绿像素，而是出现在矩形包围盒内部的位置上，与绿像素相邻）。每个矩形内有 0~5 个红标记。生成约束：至少 1 个矩形因标记过多被擦除，至少 2 个矩形存活并展示不同层数的同心图案。标记不出现在矩形外部。

**规则**：
1. 对每个绿(3)实心矩形，计算其纵深 D = floor(min(宽, 高) / 2)。例如 3x5 矩形的 D = 1，4x6 矩形的 D = 2，7x8 矩形的 D = 3。
2. 统计该矩形包围盒内的红(2)标记像素数量。
3. 若红标记数 > D：将该矩形的所有像素（绿和红）擦除为背景黑(0)。
4. 若红标记数 <= D：对该矩形执行同心层涂色——矩形内每个像素的"层深"定义为该像素到矩形边界的切比雪夫距离（即 min(到四条边的距离)）。层深 0（最外层边框）保持绿(3)；层深为奇数的像素涂为黄(4)；层深为正偶数的像素涂为蓝(1)。红(2)标记像素保持红色不变，覆盖在同心图案之上。
5. 矩形外部的黑(0)背景保持不变。

**关键洞察**：矩形的几何属性（最小半维）在规则中承担双重角色——既是标记数量的存活阈值，又是同心层着色的深度上限。这两个角色通过同一个空间量 D 耦合，而非独立参数。

## 新题 3：十字中心检测为括号提取注入内容

**组合逻辑**：[四向对齐/four_way_aligned + 缺失中心/missing_center](已有) → 内容生成 → [括号界定提取范围/bracket_delimited_extraction](已有) → [堆叠/stacking](已有)

**来源原语**：recolor、micro_bar、implied_plus、four_way_aligned、missing_center（参考题 4: 9f5f939b）；crop、stacking、control_pixel_pair、row_segment、bracket_delimited_extraction、equal_width_segments_stacked_in_row_order（参考题 5: 505fff84）

**依赖链**：检测隐含十字中心并标黄 → 黄色像素成为网格内容的一部分 → 括号提取收割含黄色的行段 → 堆叠生成输出。跳过十字检测则输出中缺少黄色中心信息；跳过括号提取则不知道输出包含哪些行段。

在散布微型条的网格中检测隐含十字并标记中心，然后用括号界定符提取特定行段并堆叠，输出中既有原始内容又有检测生成的标记。

**输入结构**：约 20x20 网格，黑(0)背景。灰(5)水平和竖直 2 像素微型条（每条恰好 2 像素，宽 1 像素）散布于网格中。部分微型条按四向对齐排列：以某个背景像素为中心，上下左右各有一条同方向的微型条（竖直条在上下，水平条在左右），中心与每条微型条之间隔 1 像素背景，微型条距中心 2~3 格。这样的四元组构成一个隐含十字。还有一些不参与十字的孤立微型条。另外，某些行上存在成对的控制像素：每行至多一个蓝(1)像素在左侧、一个青(8)像素在右侧，所有此类行的蓝青间距相同。生成约束：至少 2 个隐含十字的中心恰好位于被括号界定的行上（即中心所在行同时有蓝青控制对），至少 1 个中心不在任何括号行上（其标黄效果对输出不可见）。括号行有 4~6 行。

**规则**：
1. 扫描整个网格，找到所有满足以下条件的背景像素 P：P 的上方第 2~3 行同列有灰(5)竖直微型条，下方第 2~3 行同列有灰(5)竖直微型条，左方第 2~3 列同行有灰(5)水平微型条，右方第 2~3 列同行有灰(5)水平微型条。P 上下左右紧邻（距离 1）的四个像素必须为背景。将 P 涂为黄(4)。
2. 识别所有带蓝(1)-青(8)控制对的行，从上到下排列。
3. 对每个括号行，复制蓝与青之间（不含蓝和青本身）的所有像素作为一行输出段。该段中可能包含灰(5)微型条片段、黄(4)中心标记、或黑(0)背景。
4. 将所有输出段按行从上到下的顺序堆叠，组成输出网格。输出宽度 = 蓝青间距，输出高度 = 括号行数。

**关键洞察**：十字中心检测是一个纯几何推理步骤，它在网格中"凭空"创造黄色像素；括号提取是一个独立的空间裁剪机制。两者的耦合在于：检测产生的内容能否出现在最终输出中，完全取决于它碰巧落入了哪些括号行——十字的位置和括号的位置共同决定输出。

## 新题 4：逐行着色揭示隐藏的对角链结构

**组合逻辑**：[每行独立取色/per_row_color](已有) → 颜色边界重塑 4-连通结构 → [对角链式连接/diagonal_chain](创新：对重涂后的多色区域做分解) → [擦除/erase](创新：由结构测试触发)

**来源原语**：recolor、placeholder_pixel、row_control_color、same_row_align、per_row_color（参考题 12: c7d4e6ad）；recolor、eight_conn_region、diagonal_chain、diagonal_touch_recolor（参考题 3: ecb67b6d）

**依赖链**：逐行着色将均色区域变为多色 → 多色导致同一 8-连通区域内的像素按颜色分裂为多个 4-连通子区域 → 子区域的接触方式决定该区域是否为对角链 → 对角链区域保留重涂结果，非链区域擦除。着色、分裂、判定三步环环相扣。

灰色占位区域被行控制色逐行着色后，原本均质的区域变成了按行分色的条带图案；只有那些条带恰好形成对角阶梯连接的区域才在输出中保留。

**输入结构**：约 16x16 网格，黑(0)背景。灰(5)像素构成 4~6 个互不接触的 8-连通区域，每个区域约 5~15 像素，形态各异（有的是对角阶梯状，有的是紧凑块状，有的是不规则弯折）。最右列为控制列：每个含灰像素的行在最右列有恰好一个彩色控制像素，颜色从 {红(2), 蓝(1), 绿(3)} 中取。不含灰像素的行在最右列为背景黑(0)。生成约束：控制列颜色的分配方式使得至少 2 个区域在着色后形成对角链（即相邻行的颜色不同，且区域形态恰好使不同色的子区域仅对角接触），至少 1 个区域着色后不形成对角链（相邻行同色或子区域有边对边接触）。至少存在一个区域，其外形看似可能是对角链，但因两个相邻行获得了相同的控制色而合并为一个 4-连通子区域，破坏了链式结构。

**规则**：
1. 对每个含灰(5)像素的行，读取最右列控制像素的颜色 C。将该行所有灰(5)像素替换为 C。灰色区域现在变为多色区域。
2. 对每个原始 8-连通区域（以原灰像素位置为准），将其重涂后的像素按颜色分组。同色且 4-连通的像素构成一个"子区域"。
3. 对角链测试：检查该区域的所有子区域是否仅通过对角角点接触（非边对边），且形成不分叉的链（每个子区域至多与 2 个其他子区域对角邻接）。
4. 通过测试的区域：保留其重涂后的彩色像素。
5. 未通过测试的区域：将该区域所有像素擦除为背景黑(0)。
6. 控制列的像素始终保留不变。

**关键洞察**：逐行着色不仅是视觉变换——它在区域内部制造颜色边界，而这些边界的位置取决于区域的行跨度和控制色的分配。同一个灰色形状在不同的控制色组合下可能通过或不通过对角链测试。控制列不只提供颜色，它隐式编码了结构判定的答案。

## 新题 5：边框图案补全后的频率排序柱堆叠

**组合逻辑**：[对称补全/pattern_union_completion](已有) → 像素总量改变 → [计数/counting](已有) + [排序/sort + 逐列填充/column_fill](已有：改变频率排名)

**来源原语**：pattern_union_completion、colored_frame、internal_motif、same_color_frames_share_motif、group_by_frame_color（参考题 8: 42918530）；sort、counting、stacking、descending_freq、column_fill（参考题 14: bd283c4a）

**依赖链**：同色边框之间共享图案并补全 → 补全增加各颜色的总像素数 → 各颜色的频率排名因补全量不同而可能改变 → 按新的频率排名做降序列堆叠。补全步骤影响计数，计数影响排序，排序决定输出布局。

将表格式边框阵列中不完整的同色边框补全后，统计各边框颜色的总像素数，按频率从高到低堆叠到同尺寸输出网格中。

**输入结构**：约 17x17 网格，黑(0)背景。网格被均匀划分为 3x3 共 9 个等大的子区域（约 5x5 每个），子区域之间由 1 像素宽的背景行列隔开。每个子区域是一个"边框"：有 1 像素宽的实色边框线围成方形。边框颜色从 {红(2), 蓝(1), 绿(3)} 中取，每种颜色恰好出现 3 个边框。每个边框内部可能有若干像素与边框同色（内部图案），其余为背景。同色的 3 个边框中，每个边框包含部分内部图案位置，三者的并集构成完整图案。生成约束：每种颜色的完整图案像素数不同。补全前和补全后三种颜色的频率排名不同（即补全改变了"谁最多"）。

**规则**：
1. 将 9 个边框按边框颜色分为 3 组（每组 3 个）。
2. 对每组，收集组内所有边框中内部图案像素的相对位置（相对于边框左上角的偏移量），取并集。
3. 将并集图案写回该组的每个边框——在所有边框中，并集中的每个相对位置都涂上该组的颜色。
4. 补全结束后，统计整个网格中每种边框颜色的总像素数（包括边框线本身和内部图案）。
5. 以整个网格尺寸为输出尺寸，将所有像素按颜色频率从高到低排列为连续色块，按逐列从底到顶、从左到右的顺序填充。最高频颜色先填。填完最高频后紧接着填次高频，以此类推。未填满的剩余位置为背景黑(0)。

**关键洞察**：补全步骤看似只是"复制粘贴图案"，但不同颜色组的图案完整度差异不同，补全带来的像素增量各异，可能逆转补全前的频率排名。最终的列堆叠顺序只有在完成跨边框的图案共享后才能确定。

## 新题 6：标记前进改变柱体有效跨度从而重塑间隙填充拓扑

**组合逻辑**：[尺寸排序/size_ordering + 半段位置保持/half_position_kept](已有) → 标记迁移改变颜色分布 → [行列跨度重叠/row_span_overlap + 间隙区域/gap_region + 无遮挡才填充/fill_if_unobstructed](创新：标记色分裂柱体的有效跨度)

**来源原语**：recolor、translate、vertical_bar、marker_segment、size_ordering、half_position_kept（参考题 1: 48634b99）；fill、foreground_rectangle、row_span_overlap、gap_region、fill_if_unobstructed（参考题 6: ef135b50）

**依赖链**：标记从当前柱迁移到下一更高柱（保持上/下半段位置） → 迁移改变两根柱的颜色组成 → 间隙填充将同一柱的不同颜色半段视为独立的行跨度区域 → 哪些间隙被填充取决于迁移后的行跨度重叠情况。

竖条上的标记段前进到下一更高竖条后，间隙填充规则将标记色与柱体色分别计算行跨度重叠，产生的桥接图案因标记移动而改变。

**输入结构**：约 15x20 网格，黑(0)背景。5~7 根绿(3)竖条（每根宽 1 像素），高度互不相同且都是偶数（如 4, 6, 8, 10, 12, 14 像素）。竖条水平排列，间距 2~4 列不等。恰好一根竖条的上半段或下半段被涂为红(2)而非绿(3)——这是标记段。生成约束：竖条从左到右的位置顺序与高度顺序无关（即不是按高度排列的）。存在至少一个间隙，其填充结果在标记迁移前后不同。

**规则**：
1. 找到含红(2)标记段的竖条，记其高度为 H。将该竖条的红(2)半段恢复为绿(3)。
2. 找到高度为 H+2 的竖条。将该竖条的对应半段（若原标记在上半段则新标记也在上半段，反之亦然）涂为红(2)。
3. 标记迁移完成后，评估间隙填充。将每根竖条中的连续同色段视为独立的矩形区域（宽 1 像素）。例如一根高 10 的竖条若上半段为红(2)、下半段为绿(3)，则视为两个独立区域：一个 1x5 红区和一个 1x5 绿区。
4. 对于任意两个水平相邻且行跨度有重叠的区域对（可以是同色或异色），检查它们之间的列间隙内是否有第三个区域的包围盒穿过该间隙的共享行跨度。若无遮挡，则在间隙的共享行跨度范围内填充栗(9)色。
5. 多个区域对的填充区域若重叠，后评估的覆盖先评估的。评估顺序：按区域对中左侧区域的列号从左到右、行号从上到下。
6. 原始竖条像素（包括标记迁移后的红绿像素）保持不变，不被栗色覆盖。

**关键洞察**：标记的前进不只是颜色搬运——它将目标竖条一分为二（红半段和绿半段），改变了该竖条与其邻居之间行跨度重叠的格局。一个原本因完整竖条而"被遮挡"的间隙，可能因竖条被标记色分裂而变成"无遮挡"的，反之亦然。

## 新题 7：分隔表对齐定位 + 模板行映射 + 标记色覆写

**组合逻辑**：[列对齐/col_alignment + 前缀色映射补全行/prefix_map_complete](已有) → 补全确定前景掩码位置 → [行列对齐/row_col_align + 对齐标记定颜色/aligned_marker_color](创新：将补全结果作为待覆写的掩码区域)

**来源原语**：complete、recolor、template_row、prefix_segment、col_alignment、prefix_map_complete、encoding_map（参考题 15: 82819916）；recolor、separator_grid、mask_region、singleton_marker、row_col_align、aligned_marker_color（参考题 11: ef26cbf6）

**依赖链**：分隔线将网格划分为表格 → 特定行的单元格包含模板图案 → 其他单元格用前缀片段与模板列对齐来解码颜色映射并补全 → 补全后的彩色像素成为掩码 → 在掩码单元格所在的表行或表列中寻找单像素标记 → 用标记色覆写掩码。模板补全和标记覆写通过表格的行列坐标系耦合。

在分隔线划分的表格中，先用模板行的编码映射补全各单元格的图案，然后用表行/表列中对齐的单像素标记色统一覆写每个补全单元格的所有前景像素。

**输入结构**：约 17x17 网格。灰(5)水平线和竖直线将网格划分为 4x4 共 16 个等大的矩形单元格（每个约 3x3 内部空间）。第一行的 4 个单元格各含一个两色图案作为模板——每个模板单元格内有若干像素为蓝(1)、其余为红(2)，形成该列位置的编码模式。其余 12 个单元格中：部分单元格（"前缀单元格"）在左侧若干列有连续的非背景像素（前缀片段），颜色使用绿(3)和黄(4)两种色中的组合，右侧为黑(0)背景；另有 3~4 个单元格（"标记单元格"）仅含一个橙(7)单像素标记。生成约束：每个前缀单元格与其列对齐的模板单元格有相同宽度的前缀覆盖，前缀中的绿(3)和黄(4)与模板中的蓝(1)和红(2)建立一一映射。每个前缀单元格所在的表行或表列中恰有一个标记单元格。

**规则**：
1. 识别第一行 4 个模板单元格的内部图案。每个模板内像素序列为蓝(1)和红(2)的排列。
2. 对每个前缀单元格，将其前缀中每个像素与同列模板单元格中对应位置的像素配对，建立颜色映射（如绿→蓝、黄→红，或绿→红、黄→蓝）。
3. 用该映射将模板的完整图案翻译为该前缀单元格的完整图案。补全后的单元格内所有位置都被绿或黄填满。
4. 对每个补全后的前缀单元格，找到与其共享表行或表列的唯一标记单元格，读取该标记的橙(7)——但注意：此题中标记色不一定是橙(7)，标记像素使用的颜色即为覆写色。（实际上每个标记像素各自独立着色，颜色从 {品红(6), 橙(7), 青(8), 栗(9)} 中取。）
5. 将该前缀单元格内所有前景像素（补全后的绿/黄）统一替换为对应标记像素的颜色。
6. 背景像素、灰(5)分隔线、模板单元格和标记单元格保持不变。

**关键洞察**：模板补全确定了"哪些位置有前景"（掩码的形状），但这些位置的最终颜色不由补全结果决定，而是由表格行列坐标系中对齐的标记色决定。补全是中间态，不是终态——它提供空间信息（在哪），标记提供颜色信息（涂什么色），两者通过分隔线表格的坐标系关联。

## 新题 8：楔形填充区域与面板掩码的透明叠加

**组合逻辑**：[对角线边界/diagonal_boundary + 标记定义楔形范围/marker_define_wedge](已有) → 填充生成右面板前景 → [面板对应/panel_correspondence + 无重叠时叠加/overlay_no_overlap](创新：叠加的右面板内容不是给定的而是推理出的)

**来源原语**：fill、marker_pixel、triangular_wedge、diagonal_boundary、marker_define_wedge（参考题 17: 896d5239）；transparent_overlay、panel、separator_column、foreground_mask、panel_correspondence、overlay_no_overlap（参考题 16: bbb1b8b6）

**依赖链**：右面板中的绿标记像素暗示三角楔形边界 → 填充楔形区域生成青色掩码 → 移除分隔列后将右面板的掩码叠加到左面板 → 仅在不重叠处叠加。楔形推理决定叠加掩码的形状，掩码形状决定叠加的兼容性。

左面板有一个蓝色前景图案，右面板有稀疏的绿色对角线标记；先从标记推断三角楔形并填充青色，然后将填充结果透明叠加到左面板的空白区域。

**输入结构**：约 13x27 网格（宽型）。一根橙(7)竖直分隔列（高度占满，宽 1 列）将网格分为左右两个等大的面板（各约 13x13）。左面板：黑(0)背景上有蓝(1)前景像素构成一个 4-连通不规则形状（约 15~30 像素），形状不靠近面板边缘。右面板：黑(0)背景上有若干绿(3)像素。绿像素排列在 45 度对角线方向上，定义 1~2 个三角楔形区域的边界。每个楔形由一个顶点和两条从顶点出发的对角射线构成，射线上间隔出现绿像素作为边界线索。生成约束：填充后的楔形区域与左面板蓝色形状存在部分位置重叠、部分不重叠。若有 2 个楔形，其中一个与左面板蓝色完全不重叠（可以叠加），另一个存在重叠（不能叠加）。

**规则**：
1. 在右面板中，识别三角楔形：对每个作为楔形顶点的绿(3)像素，找到两条从该顶点出发的 45 度对角射线（四个朝向中选两条相邻的，形成 90 度角）。射线上必须在相同距离处各有一个绿线索像素。楔形高度 = 最远的共享线索距离。
2. 填充每个楔形：将楔形三角区域内部（由顶点和两条对角边界线围成的直角三角形）中所有非绿的像素涂为青(8)。绿(3)标记像素本身保持绿色。
3. 移除分隔列。以左面板为输出画布（保持蓝色图案不变）。
4. 对右面板中的每个独立楔形区域（含其绿标记和青填充），检查该区域的所有前景像素（绿和青）在对应左面板位置上是否全部为背景黑(0)。
5. 若该楔形区域与左面板完全不重叠：将该区域的绿(3)和青(8)像素复制到左面板的对应位置。
6. 若该楔形区域与左面板存在任何重叠（任一前景像素对应位置在左面板也是前景）：完全忽略该楔形，不复制任何像素。
7. 输出即为叠加后的左面板。

**关键洞察**：叠加的目标掩码不是直接给出的固定图案——它需要通过稀疏对角线标记的几何推理来构建。这意味着求解者必须先完成一个空间推理子问题（从散点推断三角形），然后用推理结果参与另一个空间判断（重叠兼容性测试）。两层推理共用相同的坐标空间但逻辑独立。
