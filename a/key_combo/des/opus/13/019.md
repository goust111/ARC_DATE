## 新题 1：像素计数定旋转角的模板印章

**组合逻辑**：[计数counting](创新：像素数编码旋转角) + [旋转rotate](创新：旋转角由外部计数决定而非固定) + [印章覆盖stamp_overlay](已有) + [擦除erase](已有)

**来源原语**：计数(ae58858e)、旋转(ed36ccf7)、印章覆盖(d6542281)、擦除(aabf363d)、连通分量(a8d7556c)、多色精灵体(d6542281)

**依赖链**：散落的单色小对象的像素数量编码了旋转参数 → 旋转参数决定模板精灵体的朝向 → 旋转后的精灵体印章到小对象的位置 → 小对象被消耗。像素计数、旋转、印章三步紧耦合：不计数就不知道旋转多少度，不旋转就不知道印什么形状，不知道小对象位置就不知道印在哪里。

每个散落的小对象既是放置位置的标记，也是旋转指令的编码——其像素数量决定模板旋转多少个 90 度后印章到该位置。

**输入结构**：约 15x15 的网格，黑(0) 背景。左上角区域放置一个多色模板精灵体（约 3x4 像素，使用红(2) 和蓝(1) 两种颜色构成不对称图案，保证四种旋转态互不相同）。网格其他区域散布 3-4 个绿(3) 单色 4-连通小对象，每个对象的像素数量分别为 1、2、3 或 4 个像素（不同示例中同类对象的具体形状不同，但像素数量与旋转角的映射关系保持一致）。各小对象的边界框互不重叠，且与模板精灵体间隔至少 2 个像素。生成约束：每个小对象的边界框中心向四周扩展模板精灵体的边界框尺寸后不超出网格边界，且扩展区域互不重叠。

**规则**：
1. 识别模板精灵体（左上角的红(2)+蓝(1) 多色对象）及所有绿(3) 4-连通小对象。
2. 对每个绿色小对象，计算其像素数量 N。旋转角度 = (N - 1) x 90 度顺时针。即：1 像素→0 度，2 像素→90 度顺时针，3 像素→180 度，4 像素→270 度顺时针。
3. 将模板精灵体按对应角度旋转后，以该绿色小对象的边界框中心为锚点进行印章覆盖（模板的边界框中心对齐锚点）。印章保留模板原有的红(2)+蓝(1) 颜色。
4. 擦除所有绿(3) 小对象的像素（替换为黑(0)）。被印章覆盖的绿色像素同样被替换。
5. 原始模板精灵体保持不变。

**关键洞察**：每个小对象承载双重信息——其位置标记印章的放置点，其大小（像素数）编码了模板应如何旋转。必须对比多个示例才能确定"像素数 → 旋转角"的具体映射规则（而非其他可能的映射如像素数→缩放）。

## 新题 2：射线投射构建动态障碍后的跨障碍交换

**组合逻辑**：[射线延伸ray_extend](创新：射线的产物不是最终输出，而是为后续操作构建障碍) + [交换swap](创新：交换的障碍来自计算生成而非输入预设) + [擦除erase](已有)

**来源原语**：射线延伸+实心矩形+障碍对象+射线遇障停止+特定色为墙壁(6ffe8f07)、交换+障碍段+跨障碍配对+同行列两侧各一(1efba499)、擦除(3d588dc9)

**依赖链**：实心矩形向外投射射线，蓝色障碍物截断射线 → 射线轨迹形成黄色障碍段 → 散落的标记像素根据黄色障碍段进行跨障碍配对交换。射线投射的结果构建了交换操作的前提条件：不计算射线就不知道障碍在哪里，不知道障碍就无法确定哪些标记构成配对。

射线从矩形出发被障碍截断后形成新的隔墙，散落的标记像素依据这些隔墙进行跨墙位置交换。

**输入结构**：约 16x16 的网格，黑(0) 背景。中心附近有一个青(8) 实心矩形（约 2x3）。网格中散布 3-5 个蓝(1) 单像素作为射线截断障碍。另有若干成对的红(2) 和绿(3) 单像素标记，分布在射线将要经过的路径两侧（每对由一个红像素和一个绿像素组成，位于同一行或同一列，且在射线路径的两侧各一个）。生成约束：青色矩形的每一行和每一列上的射线路径至少经过一个蓝色障碍；每对红绿标记恰好被一条射线路径分隔（即该行或列上的射线段将红、绿标记分在两侧）。

**规则**：
1. 从青(8) 矩形的每一行向左、向右投射射线，从每一列向上、向下投射射线。射线经过的黑(0) 像素变为黄(4)。射线遇到蓝(1) 障碍像素时停止（不包含蓝像素本身，即蓝像素保持蓝色）。射线不覆盖非黑色像素。
2. 黄(4) 射线段现在作为障碍段。扫描每一行和每一列：若某行或列恰好穿过一段连续的黄色障碍段，且该障碍段的两侧各有恰好一个非黑非黄非蓝非青的标记像素，则这两个标记构成一个跨障碍配对。
3. 对每个配对，将两个标记交换到障碍段对侧紧邻的位置：原在障碍段左侧的标记移动到障碍段右端紧邻的右侧一格（若该行方向），原在右侧的移动到左端紧邻的左侧一格；上下方向同理。原位置擦除为黑(0)。
4. 若某行或列上只有一侧有标记像素（另一侧无标记），不做任何操作。
5. 青色矩形、蓝色障碍、黄色射线段在输出中保持不变。

**关键洞察**：交换操作依赖的障碍墙并非输入中预设的，而是通过射线投射计算生成的——必须先完成射线投射才能确定哪些标记构成可交换的配对以及交换的目标位置。蓝色像素同时扮演两个角色：截断射线（间接决定障碍墙的长度和位置）和间接控制交换行为。

## 新题 3：嵌套区域深度决定周期性填充颜色

**组合逻辑**：[洪泛填充flood_fill](创新：填充目标由嵌套深度和面积排名的双重索引决定) + [排序sorting](创新：在每个深度层内部独立排序) + [重涂色recolor](已有)

**来源原语**：洪泛填充+排序+等间隔采样填充+区域排列顺序(7447852a)、封闭区域+面积排名(a8d7556c)、边缘与内部区分(8a371977)、空心矩形+内部区域(d37a1ef5)

**依赖链**：灰色边界构成嵌套结构 → 分析每个封闭区域的嵌套深度 → 同一深度的区域按面积排序 → 按周期规则（隔一选一）选取目标区域 → 深度值决定填充颜色。嵌套深度同时控制"选哪些区域"（通过周期采样在同深度内筛选）和"用什么颜色"（深度映射到颜色），两者缺一不可。

灰色墙壁围成多层嵌套区域，每层内按面积排序后隔一填充，填充颜色由嵌套层数决定。

**输入结构**：约 14x14 的网格，黑(0) 背景。灰(5) 像素构成嵌套的矩形或准矩形边界，形成 3-4 层深度的嵌套结构。最外层灰色边界紧贴网格边缘或距边缘 1 像素。内层边界嵌套在外层内部，同一深度可以有多个互不连通的封闭区域（即同一层可并列多个独立的灰色围框）。每个封闭区域的面积在 4-20 像素之间。生成约束：同一深度至少有 2 个封闭区域（以便周期采样有意义）；不同深度的区域面积范围有重叠（防止仅凭面积推断深度）。

**规则**：
1. 识别所有被灰(5) 墙壁围成的 4-连通黑(0) 封闭区域。
2. 计算每个区域的嵌套深度 D：从该区域出发到达网格边缘需要穿越的灰色边界数量。紧邻网格边缘且外侧无灰色边界的区域深度为 0（若存在），被一层灰色边界包围的区域深度为 1，以此类推。
3. 在每个深度层内，将所有区域按面积从大到小排序。面积相同时按边界框左上角的行优先、列次之排序。
4. 在每个深度层的排序序列中，选取索引为偶数的区域（第 0、2、4、... 个，即隔一选一），对选中的区域执行洪泛填充。
5. 填充颜色由深度决定：深度 1 → 红(2)，深度 2 → 蓝(1)，深度 3 → 绿(3)，深度 4 → 黄(4)。深度 0 的区域不填充。
6. 未被选中的区域保持黑(0)，灰色边界保持不变。

**关键洞察**：填充决策是双重索引的——嵌套深度决定颜色，面积排名在同层内决定周期选取。单看一个示例可能无法区分"按面积填充"和"按位置填充"，必须对比多个示例中同深度不同面积区域的填充/不填充状态才能归纳出周期采样规则。

## 新题 4：反射图案的端点选择性膨胀

**组合逻辑**：[镜像reflect](已有) + [扩展expand](创新：膨胀不均匀，由反射后图案的局部连通性决定哪些像素膨胀) + [计数counting](创新：计数邻居数作为膨胀条件而非直接输出) + [擦除erase](已有)

**来源原语**：镜像+稀疏标记线+平行对称轴+跨标记线反射(66ac4c3b)、扩展+正交对角分工(0962bcdd)、计数(ae58858e)、引导像素+角落定位+角落色转移后消(aabf363d)

**依赖链**：引导像素提供颜色 → 前景图案跨标记线反射生成副本 → 副本的每个像素检测其在副本内的 4-邻居连通数 → 邻居数 <= 1 的端点像素向四方膨胀一格，邻居数 >= 2 的内部像素不膨胀。反射决定了副本的形状，形状的局部拓扑（端点 vs 内部）决定了膨胀行为——同一个反射操作的输出在不同位置产生不同的后续变换。

前景图案跨标记线反射后，反射副本的末端像素向外膨胀、内部像素保持不变，形成一个拓扑敏感的生长图案。

**输入结构**：约 14x12 的网格，黑(0) 背景。一条水平稀疏标记线由灰(5) 像素组成，位于网格的中间行附近（如第 5 行），标记线上的灰色像素间隔 2-3 格（即非连续，仅在若干列上有灰色像素）。标记线上方有一个红(2) 前景图案（不规则形状，4-8 个 4-连通像素，整体不对称，包含至少 2 个端点——即仅有 1 个 4-邻居属于该图案的像素）。网格左下角有一个蓝(1) 引导像素。生成约束：图案与标记线之间至少间隔 1 行；反射后的图案（含膨胀后的额外像素）不超出网格边界；图案反射后的位置不与原图案重叠。

**规则**：
1. 读取左下角的引导像素颜色（蓝(1)），然后将该像素擦除为黑(0)。
2. 将红(2) 前景图案以稀疏标记线所在行为对称轴进行垂直镜像反射。反射副本的每个像素以引导颜色蓝(1) 绘制。
3. 对反射副本中的每个蓝(1) 像素，计算其在副本内的 4-连通邻居数量（即上下左右四个方向中有多少个同属反射副本的蓝色像素）。
4. 邻居数 <= 1 的像素为端点像素：将其四个基数方向（上下左右）各膨胀 1 格，膨胀像素同为蓝(1)。膨胀仅覆盖黑(0) 像素，不覆盖红(2) 原图案、灰(5) 标记线或已有的蓝(1) 像素。
5. 邻居数 >= 2 的像素为内部像素，不做任何膨胀。
6. 原始红(2) 图案和灰(5) 标记线保持不变。

**关键洞察**：反射副本并非均匀膨胀——其形状的拓扑特征（端点 vs 连接处）自动决定了哪些部分会生长。不同示例中原图案的形状不同，导致端点位置不同，因此膨胀模式也不同。必须理解"端点检测 → 选择性膨胀"这一规则，而非试图记忆某种固定的膨胀图案。

## 新题 5：封闭性与面积的同时约束决定重涂色

**组合逻辑**：[洪泛填充flood_fill](创新：用于拓扑分类而非直接填色) + [计数counting](创新：面积阈值由同类对象的中位数动态决定) + [重涂色recolor](创新：颜色由两个独立约束的交叉结果决定)

**来源原语**：洪泛填充(7447852a)、连通分量+面积排名(a8d7556c)、重涂色+面积超阈值则变色(ae58858e)、边缘与内部区分(8a371977)、封闭区域(a8d7556c)

**依赖链**：灰色墙壁构成迷宫 → 对每个红色连通分量做拓扑分类（是否被完全封闭） → 仅对封闭类分量计算面积中位数作为阈值 → 面积 >= 中位数的封闭分量涂蓝，面积 < 中位数的封闭分量涂绿 → 非封闭分量保持红色不变。拓扑分类和面积阈值是两个独立维度的约束，必须同时满足才能确定输出颜色。

灰色迷宫中的红色连通分量根据是否被完全封闭分为两类，封闭类内部再按面积中位数阈值分涂两种颜色。

**输入结构**：约 13x13 的网格，黑(0) 背景。灰(5) 像素构成不规则的迷宫状墙壁结构（非网格化，有弯折和分叉）。红(2) 前景像素散布于迷宫内部，形成 5-7 个 4-连通分量，面积各异（2-10 像素）。部分红色分量被灰色墙壁完全包围（从该分量出发，沿黑色像素 4-连通路径无法到达网格边缘），其余分量可通过黑色像素路径连通到网格边缘。生成约束：完全封闭的红色分量至少有 3 个（使中位数有意义）；封闭分量的面积不全相同；至少有一个封闭分量面积高于中位数且一个低于中位数。

**规则**：
1. 识别灰(5) 墙壁和所有红(2) 4-连通分量。
2. 对每个红色分量进行拓扑封闭性测试：从该分量的任意相邻黑(0) 像素出发，沿 4-连通黑色像素做洪泛扩展。若洪泛扩展无法到达网格边缘任何一行一列的边缘像素（所有路径都被灰色墙壁截断），则该分量为"封闭类"；否则为"通达类"。
3. 收集所有封闭类分量的面积（像素数），计算中位数 M。若封闭类分量数为偶数，M 取较小的中间值。
4. 将面积 >= M 的封闭类分量重涂色为蓝(1)。
5. 将面积 < M 的封闭类分量重涂色为绿(3)。
6. 通达类分量保持红(2) 不变。
7. 灰色墙壁和黑色背景保持不变。

**关键洞察**：颜色变换不是简单的"大变蓝、小变绿"——只有在拓扑上被完全封闭的分量才参与面积比较。通达类分量无论面积大小都保持红色。需要对比多个示例才能分离出"封闭性"和"面积阈值"这两个独立约束维度。

## 新题 6：散落计数像素控制基元图案的平铺次数

**组合逻辑**：[计数counting](创新：孤立像素作为计数编码而非独立对象) + [平铺tiling](创新：平铺次数由外部计数决定而非几何规律) + [擦除erase](已有) + [冲突优先级conflict_priority](创新：优先级由计数值决定)

**来源原语**：计数(ae58858e)、平铺+逐级展开(762cd429)、连通分量(a8d7556c)、冲突优先级(d6542281)、擦除(aabf363d/3d588dc9)

**依赖链**：每个基元图案附近的孤立同色像素数量 → 该图案的平铺副本数 → 平铺产生的空间延展可能与其他图案的平铺区域重叠 → 重叠冲突由计数值（平铺次数）决定优先级。计数编码了平铺指令，平铺产生的空间冲突又回溯到计数值来解决——同一个量同时控制"做多少"和"谁赢"。

每个小图案旁的孤立同色像素告诉你该图案要平铺多少份，平铺区域重叠时平铺次数多的优先。

**输入结构**：约 14x14 的网格，黑(0) 背景。包含 2-3 个基元图案，每个为 2x2 的 4-连通单色块，颜色各不相同（如红(2)、蓝(1)、绿(3)）。每个基元图案的周围 3 格范围内散布若干孤立的同色单像素（即与图案颜色相同但不与图案 4-连通的独立像素），数量为 1-3 个。这些孤立像素与图案之间不 4-连通（至少隔 1 格黑色像素）。不同图案的孤立像素互不相邻。生成约束：各图案按不同方向平铺后至少有一对图案的平铺区域存在重叠；各图案的孤立像素数量互不相同。

**规则**：
1. 识别每个 2x2 基元图案及其附近（曼哈顿距离 <= 3 且同色的）孤立单像素。孤立像素的定义：与任何同色 2x2 图案不 4-连通的同色单像素。
2. 计数每个图案关联的孤立像素数量 K。
3. 从每个图案的原始位置出发，向右平铺 K 个额外副本（共 K+1 个实例，含原始图案）。副本之间紧邻（列方向无间隔），每个副本为原始图案的完全复制。
4. 擦除所有孤立计数像素（替换为黑(0)）。
5. 若不同图案的平铺区域在某些像素上重叠，则 K 值较大的图案优先（其颜色覆盖 K 值较小的图案）。若 K 值相同（生成约束已排除此情况），则按图案原始位置从左到右、从上到下的顺序决定优先级。
6. 原始图案位置处的像素由平铺结果决定（可能被更高优先级的其他图案覆盖）。

**关键洞察**：孤立像素不是噪声或装饰，它们是计数标签——与图案同色但不相连的像素数量编码了平铺指令。同一个计数值既控制平铺规模又决定重叠时的优先级，形成自洽的"多者胜"逻辑。

**依赖链**：模板区的多个模板按面积排序获得编号 → 窗口格中心标记像素的颜色通过固定映射指向编号 → 对应编号的模板被印章到该窗口格内。排序结果创建了一个动态图例——模板的面积排名决定其编号，标记颜色查询该编号——这种间接映射在任何源题中都不存在。

**规则**：
1. 识别底部保留区的 3 个模板形状及其面积（像素数）。
2. 按面积从小到大排序，赋予编号：最小 → 编号 1，中间 → 编号 2，最大 → 编号 3。
3. 窗口格中心标记颜色到编号的映射：红(2) → 编号 1，蓝(1) → 编号 2，绿(3) → 编号 3。
4. 对每个窗口格，根据其中心标记颜色查找对应编号，取该编号的模板形状，将模板居中印章到该 3x3 窗口格内。印章使用模板的原始颜色。若模板小于 3x3，则居中放置（边界框中心对齐窗口格中心），未覆盖的窗口格像素保持黑(0)。
5. 擦除底部保留区的所有模板形状（替换为黑(0)）。
6. 中心标记像素被模板印章覆盖（模板中心位置的像素替换标记颜色）。灰色分隔线保持不变。

**关键洞察**：标记颜色不直接对应模板颜色——它对应的是模板的面积排名编号。若更换模板（改变各模板的面积大小关系），同一个标记颜色可能指向不同的模板。必须对比不同示例中模板面积与窗口格内容的对应关系才能归纳出"颜色→排名编号→模板"的间接映射。

## 新题 8：滑动构建障碍后的射线绘制

**组合逻辑**：[滑动sliding](创新：滑动的目的不是移动对象到最终位置，而是构建后续操作的空间条件) + [射线延伸ray_extend](创新：射线路径由滑动后的对象位置决定) + [擦除erase](已有)

**来源原语**：滑动+前景对象+方向+固定步长平移(25ff71a9)、射线延伸+障碍对象+射线遇障停止+特定色为墙壁(6ffe8f07)、擦除(3d588dc9)

**依赖链**：方向标记指示每个蓝色对象的滑动方向 → 对象滑到边缘或碰到其他对象后停止 → 停止位置的蓝色对象成为射线障碍 → 从红色源点向四方投射射线，遇蓝色障碍停止。滑动的结果决定了障碍的空间分布，障碍分布决定了射线的长度和覆盖范围——输入中看到的对象位置不是最终起作用的位置。

蓝色对象按方向标记滑动到最终位置后充当射线障碍，红色源点投射的射线在这些动态障碍处截止。

**输入结构**：约 14x14 的网格，黑(0) 背景。中心有一个红(2) 单像素作为射线源点。网格中散布 3-4 个蓝(1) 小对象（每个 2-3 像素的 4-连通块，不同示例中形状不同）。每个蓝色对象的某一侧紧邻一个黄(4) 单像素作为方向标记：黄像素在蓝对象上方表示向上滑，在下方表示向下滑，在左侧表示向左滑，在右侧表示向右滑。黄像素与蓝对象的相邻关系是 4-连通的（上下左右之一）。生成约束：每个蓝色对象恰好有一个相邻黄色方向标记；滑动后所有蓝色对象互不重叠且不覆盖红色源点；至少有一个蓝色对象滑动后位于红色源点的某个基数方向上（确保至少一条射线被截断）。

**规则**：
1. 对每个蓝(1) 对象，识别其相邻的黄(4) 方向标记。黄像素相对于蓝对象的方位即为滑动方向（黄在蓝的北侧 → 滑向北，以此类推）。
2. 将每个蓝色对象沿其滑动方向整体平移，直到对象的前沿像素碰到网格边缘或碰到另一个已经停止的对象（按距网格边缘由近到远的顺序依次处理——即最靠近滑动方向目标边缘的对象最先滑动并固定）。
3. 擦除所有黄(4) 方向标记像素（替换为黑(0)）。
4. 从红(2) 源点向上、下、左、右四个基数方向投射射线。射线经过的黑(0) 像素变为绿(3)。射线遇到蓝(1) 对象的像素时停止（不包含蓝色像素本身）。射线遇到网格边缘也停止。
5. 红色源点保持红(2)，蓝色对象保持蓝(1)。

**关键洞察**：输入中蓝色对象的位置是"初始位置"而非"最终位置"——求解者必须在脑中执行滑动操作来确定对象的最终位置，然后才能判断射线的长度。黄色方向标记是消耗性指令，执行后消失。

## 新题 9：外推帧位置遇周期障碍后弹跳并变色

**组合逻辑**：[外推extrapolate](创新：外推不是简单线性延续，遇障碍时方向反转) + [重涂色recolor](创新：重涂色由外推后的空间位置在色彩图例中的映射决定) + [等间隔采样periodic](创新：周期性结构作为碰撞障碍而非填充规则)

**来源原语**：外推+帧序列+内部精灵+等间距排列+匀速运动延续(ba1aa698)、重涂色(ae58858e)、等间隔采样填充(7447852a)、障碍段+跨障碍配对(1efba499)

**依赖链**：帧序列显示精灵匀速运动 → 外推下一帧位置 → 检查外推位置是否与周期性障碍行重合 → 若重合则反转垂直运动方向重新外推 → 最终行位置落入哪个颜色图例的行范围 → 精灵重涂为该颜色。外推、碰撞检测、方向反转、颜色查找形成一个有分支的推理链：是否碰撞决定是否需要反转，反转改变最终位置，最终位置决定颜色。

帧序列中匀速运动的精灵被外推到下一帧，若外推位置碰到周期障碍行则弹回，最终行位置在色彩图例中查找决定精灵颜色。

**输入结构**：约 10x24 的网格，黑(0) 背景。左侧排列 3 个等宽的帧面板（每个约 10x6），灰(5) 边框，黑(0) 内部填充。每个面板内有一个红(2) 小精灵（2-3 像素的 4-连通块，各帧形状相同），精灵在各帧中的列位置相同，行位置呈等差递变（如每帧下移 2 行）。网格右侧有一个窄的纵向区域（约 10x3），其中包含：(a) 品红(6) 水平短线段，位于周期性行位置（如第 2、5、8 行），表示障碍行；(b) 三段纵向色块分别为蓝(1)、绿(3)、黄(4)，每段覆盖不同的行范围（如蓝覆盖第 1-3 行、绿覆盖第 4-6 行、黄覆盖第 7-9 行），作为色彩图例。生成约束：精灵的匀速运动外推到第 4 帧时恰好落在某个品红障碍行上（触发弹跳），弹跳后的新位置落在某个色彩图例范围内且不再碰到障碍行。

**规则**：
1. 从 3 个帧面板中提取精灵的行位置序列，计算每帧的行位移量 dR（应为常数）。
2. 外推第 4 帧（输出帧）的精灵行位置：上一帧行位置 + dR。
3. 检查外推行位置是否与右侧任一品红(6) 障碍行的行坐标重合（障碍行的行坐标相对于帧面板的内部坐标系）。
4. 若重合（碰撞）：将行位移量取反（dR → -dR），重新计算第 4 帧行位置 = 上一帧行位置 + (-dR)。
5. 确定最终行位置落入右侧哪个色块的行范围内。将精灵重涂为该色块的颜色。
6. 输出一个独立的帧面板（与输入面板同尺寸），包含灰色边框、黑色填充和正确位置与颜色的精灵。输入面板和右侧图例区不包含在输出中。

**关键洞察**：直觉上的"线性外推"只在精灵不碰到障碍行时正确。品红障碍行是隐式的碰撞边界，碰撞后精灵弹回而非穿越。必须对比多个示例——有碰撞的和无碰撞的——才能归纳出弹跳规则而非误认为所有精灵都简单线性外推。

## 新题 10：控制矩阵编码膨胀量与优先级的十字图案扩展

**组合逻辑**：[扩展expand](创新：膨胀量不固定，由外部控制矩阵编码) + [索引映射index_mapping](创新：映射值不是颜色而是几何变换参数) + [冲突优先级conflict_priority](创新：优先级与膨胀量正相关，形成自洽的"大者胜"规则)

**来源原语**：扩展+十字图案+正交对角分工+臂色中心色分延(0962bcdd)、索引映射+控制矩阵+模板格点+行列位置对应+按控制色重涂(33b52de3)、冲突优先级(d6542281)、标记像素+标记框内保护(d37a1ef5)

**依赖链**：控制矩阵的每个单元颜色 → 查表得到对应十字图案的臂膨胀量 → 膨胀量决定十字的最终占地面积 → 相邻十字膨胀后可能在空间上重叠 → 膨胀量较大的十字在重叠区域优先。控制矩阵同时编码了"变多大"和"谁赢"——两个看似独立的规则由同一个量统一驱动。

一组十字图案按控制矩阵指定的膨胀量扩展臂长，膨胀重叠时膨胀量大者覆盖小者。

**输入结构**：约 17x17 的网格，黑(0) 背景。一个 3x3 的十字图案阵列，相邻十字之间间隔 2 像素（即中心间距为 5）。每个十字图案为标准的 3x3 尺寸：中心 1 像素为灰(5)，四臂各 1 像素为灰(5)，对角位置为黑(0)（即加号形状，全为灰色）。网格右下角区域（与十字阵列不重叠）放置一个 3x3 的控制矩阵，每个单元为一个单像素，颜色为红(2)、蓝(1) 或绿(3) 三种之一。控制矩阵的行列位置与十字阵列的行列一一对应（控制矩阵第 i 行第 j 列的颜色控制十字阵列第 i 行第 j 列的十字）。网格中可能散布若干黄(4) 标记像素，位于十字图案的膨胀路径上。生成约束：至少有一对相邻十字的膨胀区域存在重叠。

**规则**：
1. 读取 3x3 控制矩阵，建立颜色到膨胀量的映射：绿(3) → 膨胀 0（保持原始 3x3 十字），红(2) → 臂各向外膨胀 1 格（变为 5x5 占地，臂长 2），蓝(1) → 臂各向外膨胀 2 格（变为 7x7 占地，臂长 3）。
2. 对每个十字，根据其对应控制色确定膨胀量。膨胀仅沿四个基数方向（上下左右），膨胀像素使用灰(5)。中心像素重涂为其对应的控制色（红/蓝/绿）。
3. 黄(4) 标记像素受保护：膨胀不覆盖黄色像素。膨胀在黄色像素处中断但不停止——跳过该位置继续向外膨胀剩余格数（即黄色像素在臂上留下一个空洞）。
4. 若两个相邻十字的膨胀区域在某些像素上重叠，膨胀量较大的十字优先（其灰色像素保留）。膨胀量相同时，阵列位置靠上、靠左的十字优先。
5. 控制矩阵在输出中保持不变。黄色标记像素保持不变。

**关键洞察**：控制矩阵看似只是一个颜色图例，实际上它编码了一个几何参数（膨胀量）和一个优先级规则（膨胀量越大优先级越高）。这意味着蓝色控制的十字不仅最大，而且在争夺空间时一定赢——"大者胜"是一个自洽的涌现规则，不需要额外的优先级表。
