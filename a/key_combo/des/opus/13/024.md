## 新题 1：对称推断隐形墙壁，限制向下射线长度

**组合逻辑**：[对称补全](创新：不输出补全结果，而是将补全推断出的像素作为隐形障碍物) + [射线延伸/填充](创新：射线终止条件依赖于推断出的障碍，而非可见障碍)

**来源原语**：对称补全(symmetry_completion) ← 9ecd008a；射线延伸/填充(ray_extend/fill) ← d037b0a7；镜像(mirror) ← 9ecd008a；同列传播(same_column_propagation) ← d037b0a7；前景源像素(foreground_source) ← d037b0a7；缺失区域(missing_patch) ← 9ecd008a

**依赖链**：对称补全推断出的像素位置决定了射线的终止行——不先完成对称推断，就无法确定任何射线的正确长度；而射线本身是输出的主体内容，对称补全的结果仅作为中间约束使用，不直接出现在最终输出中。

将左右对称图案中缺失的像素推断出来作为隐形障碍，控制顶部源像素向下射线的终止位置，输出仅包含射线和原始可见结构。

**输入结构**：约 15x15 的网格，背景为黑(0)。网格中有一个由红(2)像素组成的图案，该图案关于网格的垂直中轴具有左右镜像对称性，但右半侧有若干像素被擦除（显示为黑(0)），形成 1~3 个不连续的缺口（每个缺口为 1~3 个像素）。网格第 0 行（最顶行）有 2~4 个孤立的源像素，颜色各不相同（从蓝(1)、绿(3)、黄(4)、灰(5)中选取），每个源像素占据不同的列。红色图案位于网格的中下部（约第 4 行到第 12 行之间），与源像素所在行之间有至少 2 行的间隔。生成约束：每个源像素所在列必须至少穿过一个红色像素位置或一个被擦除的缺口位置（即该列上在红色图案范围内存在原始红色像素或应由对称推断恢复的像素）。

**规则**：
1. 识别红(2)图案关于网格垂直中轴的镜像对称性，推断出右半侧被擦除的像素位置及颜色（均为红(2)）。这些推断像素不绘制到输出中，仅作为中间信息使用。
2. 对于第 0 行每个源像素（位于列 c），从第 1 行开始沿列 c 向下逐行检查：若该行该列为黑(0)背景，则将该单元格涂为源像素的颜色；若该行该列为非背景像素（包括原始可见的红(2)像素或步骤 1 中推断出的隐形红(2)像素），则射线在该行的前一行停止（不覆盖该非背景像素）。若列 c 上直到网格底部都没有非背景像素或隐形推断像素，则射线填充至网格最底行。
3. 输出网格 = 输入网格 + 所有射线填充的像素。被擦除的缺口在输出中保持为黑(0)（不恢复），源像素保留在第 0 行。

**关键洞察**：右半侧的缺口看似无关紧要，实际上那些被擦除位置上"应存在但不可见"的红色像素充当了某些射线的终止墙壁——求解者必须先通过对称性推断出这些隐形像素的位置，才能确定对应射线的正确长度。仅从一个示例无法区分"射线遇可见红像素停止"与"射线遇推断红像素也停止"这两条规则，需对比多个示例才能归纳。

## 新题 2：十字形模式检测生成虚拟锚点，驱动跨度连线

**组合逻辑**：[模式检测](创新：检测结果不用于重涂色，而是生成一组虚拟锚点坐标) → [连线/跨度填充](创新：连线端点不是输入中的孤立标记，而是模式检测动态生成的锚点)

**来源原语**：模式检测(pattern_detection) ← 1818057f；连线(connect) ← ded97339；十字图案(cross_pattern) ← 1818057f；线段(line_segment) ← ded97339；邻域全匹配(all_neighbors_match) ← 1818057f；首尾跨度填充(span_fill_between) ← ded97339；行列对齐(row_col_alignment) ← ded97339

**依赖链**：模式检测的输出（十字中心点集合）直接构成连线操作的端点集合——没有检测就没有端点，没有连线则检测结果无处使用。两个操作共享同一中间数据结构（锚点坐标集），且这组锚点在输入中没有任何视觉标记区分。

在前景噪声中找到所有局部十字形结构的中心，以这些中心为锚点，沿共享行或列绘制连接线段。

**输入结构**：约 18x18 的网格，背景为黑(0)。网格中散布着黄(4)前景像素，总数约 40~60 个。这些像素中，部分恰好构成若干十字形局部结构——即某个黄(4)像素的上、下、左、右四个正交邻居也是黄(4)。其余黄(4)像素是干扰噪声，不构成完整十字。十字形结构有 3~5 个，它们的中心像素互不相邻（任意两个中心之间的曼哈顿距离至少为 5）。生成约束：至少有 2 对十字中心共享同一行，至少有 1 对共享同一列；不存在 3 个十字中心恰好共线的情况（以避免"相邻"定义的歧义）。

**规则**：
1. 扫描所有黄(4)像素，找到每个"十字中心"——即上、下、左、右四个正交邻居均为黄(4)的像素。记录所有十字中心的坐标集合 S。
2. 对于 S 中共享同一行的每一对中心 (r, c1) 和 (r, c2)（c1 < c2），将该行从列 c1+1 到列 c2-1 的所有像素涂为蓝(1)（不覆盖端点处的黄(4)像素）。
3. 对于 S 中共享同一列的每一对中心 (r1, c) 和 (r2, c)（r1 < r2），将该列从行 r1+1 到行 r2-1 的所有像素涂为蓝(1)（不覆盖端点处的黄(4)像素）。
4. 若蓝(1)连接线段经过的某个单元格已经是黄(4)（噪声或十字臂），蓝(1)覆盖黄(4)。
5. 输出网格保留所有原始黄(4)像素（除被蓝覆盖的外），并增加蓝(1)连接线段。

**关键洞察**：黄色像素中哪些是"有意义的锚点"、哪些是无关噪声，完全取决于局部十字形模式检测的结果——连线的端点不是预先标记的，而是从结构中涌现的。仅一个示例可能无法确定"什么样的局部结构才算合格锚点"，需要对比多个示例中不同噪声布局下的连线结果来归纳十字中心的判定条件。

## 新题 3：包围盒推断虚拟矩形框，约束滑动体的终止位置

**组合逻辑**：[包围盒推断](创新：三点定矩形框的结果不绘制为可见边框，而是生成虚拟碰撞边界) + [滑动](创新：滑动终止条件来自虚拟边界而非实体锚定物)

**来源原语**：补全/包围盒(complete/bounding_box) ← e7639916；滑动(slide) ← 98cf29f8；擦除(erase) ← 98cf29f8；标记像素(marker_pixel) ← e7639916；矩形体(rectangular_body) ← 98cf29f8；连接杆(connector_stem) ← 98cf29f8；三点定矩形框(three_pts_define_rect) ← e7639916；碰撞阻挡(collision_blocking) ← 98cf29f8

**依赖链**：包围盒推断生成虚拟矩形边界，滑动操作以该边界为碰撞面——没有包围盒推断，滑动没有目标；没有滑动，包围盒推断的结果无处体现。两个逻辑通过"虚拟碰撞面"这一中间概念紧密耦合，且该碰撞面在输入和输出中都不可见。

由散落标记像素推断出的隐形矩形框充当碰撞边界，迫使带杆矩形体沿杆滑动至该边界处停下。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格上有 2~3 组颜色不同的元素，每组包含：(a) 恰好 3 个同色标记像素（如红(2)），分布在各自共享包围盒的边界上；(b) 一个同色的可滑动复合体，由一个 2x3 或 3x2 的实心矩形体和一条从矩形体某边中点延伸出的单像素宽直线杆（长度 2~5 像素）组成。不同组使用不同颜色（从红(2)、绿(3)、蓝(1)中选取）。生成约束：每组的杆方向指向该组三点包围盒的某条边，且矩形体沿杆方向平移后，其近端恰好抵达包围盒边界（不超出、不重叠其他组的元素）。各组元素互不重叠，包围盒之间也互不重叠。

**规则**：
1. 按颜色将元素分组。对每组中的 3 个标记像素，计算它们的共享包围盒（最小外接矩形）。该包围盒不绘制，仅记录其四条边的坐标。
2. 对每组的可滑动复合体，识别杆的方向（上/下/左/右）。擦除整个复合体（矩形体 + 杆均变为黑(0)）。
3. 将矩形体沿杆方向平移，平移距离等于杆的长度（以像素数计）。若平移后矩形体的前端恰好落在该组包围盒边界上或紧邻包围盒边界内侧一个像素处，则将矩形体绘制在新位置。杆不保留。
4. 标记像素在输出中保留原位不变。
5. 处理顺序不影响结果（各组互不干涉）。

**关键洞察**：滑动目的地在输入中没有任何实体对应物——它是从三个散落标记像素推断出的虚拟矩形边界。求解者必须先从标记像素的空间分布反推包围盒的几何形状，然后才能验证矩形体的滑动是否合理。单个示例可能无法区分"滑动距离等于杆长"和"滑动到某固定位置"这两种假设，需要多示例对比。

## 新题 4：面积排名决定同心正方形的循环缩放步数

**组合逻辑**：[排序/面积比较](创新：排序结果不用于产生列表输出或选择单一对象，而是生成逐对象差异化的变换参数) + [循环缩放](创新：每个对象的缩放步数不固定为 1，而是由其面积排名决定)

**来源原语**：排序(sorting) ← f8ff0b80；计数(counting) ← f8ff0b80；缩放/循环(resize/cyclic) ← 522fdd07；面积排序(area_ordering) ← f8ff0b80；面积比较(area_comparison) ← be94b721；奇数边正方形(odd_side_square) ← 522fdd07；中心点(center_point) ← 522fdd07；同心定位(concentric_position) ← 522fdd07；边长循环变换(side_length_cycle) ← 522fdd07

**依赖链**：排序产生排名序号，排名序号作为循环缩放的步数参数——不排序则无法确定每个正方形的缩放量，不缩放则排序结果没有几何意义。排序和缩放通过"排名→步数"的映射函数紧密耦合，且该映射关系必须从多示例中归纳。

将多个奇数边正方形按面积排序，排名越靠后（面积越小）在边长循环中前进越多步，实现差异化的同心缩放。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格上有 3~5 个不重叠的实心奇数边正方形，颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)、灰(5)中选取），边长从 {1, 3, 5, 7, 9} 中取值且互不相同。各正方形的中心位置分散在网格中，彼此留有足够间距（任意两个正方形的边界框不重叠，且各正方形在最大可能缩放后仍不超出网格边界或互相重叠）。生成约束：正方形数量 n 满足 3 <= n <= 5，且每个正方形在循环缩放 n-1 步后的新边长所需空间不超出网格，不与其他正方形缩放后的边界框重叠。

**规则**：
1. 找到所有实心奇数边正方形，记录每个的颜色、中心坐标和边长。
2. 按面积（像素数）从大到小排序，排名从 0 开始（最大面积的排名为 0）。
3. 对排名为 k 的正方形，在边长循环 1 → 9 → 7 → 5 → 3 → 1 → 9 → ... 中前进 k+1 步。即：排名 0 前进 1 步，排名 1 前进 2 步，排名 2 前进 3 步，以此类推。
4. 清空画布为黑(0)。在每个正方形的原始中心位置绘制其新边长的同色实心正方形。
5. 边长循环规则：边长 n > 1 时下一步为 n-2；边长 n = 1 时下一步为 9。多步则连续应用。

**关键洞察**：所有正方形都进行循环缩放，但步数不同——面积最大者仅缩一步，面积最小者缩最多步。求解者不仅要识别循环缩放规则，还要发现面积排名与步数之间的递增映射关系，这需要对比多个示例中不同初始边长组合的变换结果。

## 新题 5：异或合成掩码筛选交替重涂目标

**组合逻辑**：[异或合成](创新：异或结果不直接输出，而是作为空间过滤器选择哪些对象参与后续操作) + [交替重涂](创新：交替选择的候选集不是所有同类对象，而是经异或筛选后的子集)

**来源原语**：异或合成(xor_compositing) ← 31d5ba1a；重涂色(recolor) ← 817e6c09；小方块(small_square) ← 817e6c09；半区掩码(half_mask) ← 31d5ba1a；对齐(alignment) ← 31d5ba1a；沿轴排列(axis_arrangement) ← 817e6c09；恰一为前景(exactly_one_foreground) ← 31d5ba1a；奇偶交替选择(alternating_parity_selection) ← 817e6c09

**依赖链**：异或合成确定哪些空间位置被"激活"，从而筛选出参与交替重涂的对象子集——不做异或则无法确定候选集，不做交替重涂则异或结果没有后续效果。异或的输出作为空间选择器流入重涂操作的输入约束中，且两步使用的空间坐标系统经对齐后共享。

上下两半区通过异或合成得出激活掩码，仅落在激活区内的小方块参与从右到左的交替重涂。

**输入结构**：高度为偶数的网格（约 14x14），背景为黑(0)。网格沿水平中线分为上半区和下半区，各占一半高度。上半区包含：(a) 一个由灰(5)像素组成的不规则前景掩码（约占上半区面积的 30%~50%），(b) 5~7 个红(2)的 2x2 实心小方块，分散排列在上半区内，各方块左边缘列坐标互不相同，方块可以位于灰色掩码之上也可以位于黑色背景之上。下半区包含一个由灰(5)像素组成的不规则前景掩码，其形状与上半区的灰色掩码不同（部分区域重叠、部分区域仅其一有灰色），下半区没有红色方块。生成约束：上下半区的灰色掩码异或后，至少有 3 个红色方块的中心像素位于异或"激活"区（即恰好一个半区有灰色的位置）内，至少有 1 个方块的中心像素不在激活区内。

**规则**：
1. 将上半区的灰(5)掩码与下半区的灰(5)掩码按位置对齐（上半区的第 i 行对应下半区的第 i 行，列不变）。
2. 计算异或掩码：位置 (i, j) 被"激活"当且仅当上半区对应位置和下半区对应位置中恰好有一个是灰(5)像素（另一个为黑(0)背景）。该掩码不直接绘制。
3. 在上半区的红(2)方块中，筛选出中心像素（方块左上角偏移 (0,0) 处的像素）落在激活掩码内的方块，称为"激活方块"。
4. 将激活方块按其左边缘列坐标从右到左排序，排名从 0 开始。
5. 排名为偶数（0, 2, 4, ...）的激活方块重涂为青(8)，排名为奇数的保持红(2)不变。
6. 未被激活的方块保持红(2)不变。输出网格 = 输入的上半区（含重涂后的方块），下半区原样保留。

**关键洞察**：下半区看起来像装饰性的对称内容，实际上它与上半区的异或差异决定了哪些红色方块被"选中"参与交替重涂——下半区是一个隐式的选择器。求解者必须先理解异或筛选机制，再在筛选后的子集上发现交替重涂规则。

5. 射线延伸到网格边界时停止。将射线路径上的所有黑(0)像素涂为绿(3)。
6. 原始对角线段、橙(7)区块和红(2)标记点在输出中保留不变。

## 新题 8：面积排序驱动的优先级滑动与互相碰撞

**组合逻辑**：[排序/面积比较](创新：排序结果决定操作执行顺序，而非选择或输出) + [滑动](创新：多个滑动体按优先级依次执行，先滑动的成为后滑动者的实体障碍) + [碰撞阻挡](创新：障碍物不是静态的，而是由先前滑动产生的动态障碍)

**来源原语**：排序(sorting) ← f8ff0b80；滑动(slide) ← 98cf29f8；擦除(erase) ← 98cf29f8；面积比较(area_comparison) ← be94b721；矩形体(rectangular_body) ← 98cf29f8；连接杆(connector_stem) ← 98cf29f8；碰撞阻挡(collision_blocking) ← 98cf29f8；沿杆滑至锚定物(slide_stem_to_anchor) ← 98cf29f8；面积排序(area_ordering) ← f8ff0b80

**依赖链**：面积排序决定滑动执行顺序，而执行顺序直接影响最终位置——因为先滑动到位的矩形体成为后续滑动体的物理障碍，改变它们的停止位置。这不是线性流水线（A→B→C），而是一种"排序产生调度序，调度序决定物理交互结果"的非线性耦合——同样的输入，若排序规则不同，输出也完全不同。

多个带杆矩形体按面积从大到小依次滑动，先滑到位的成为后续滑动者的碰撞障碍，最终位置取决于处理顺序。

**输入结构**：约 20x20 的网格，背景为黑(0)。网格上有 3~4 个颜色各不相同的可滑动复合体（从红(2)、蓝(1)、绿(3)、黄(4)中选取），每个复合体由一个实心矩形体（宽 2~4 像素、高 2~4 像素，各复合体面积互不相同）和一条从矩形体某边中点延伸的单像素宽直线杆（长度 3~8 像素）组成。网格边缘（上/下/左/右中的某一侧）作为所有滑动体的公共目标壁面。各复合体的杆方向均指向同一侧边缘。生成约束：各复合体的杆方向相同（均朝向同一边），但位于不同的行或列上；至少有 2 个复合体的滑动路径在投影方向上存在重叠（即它们沿滑动方向的坐标范围有交集），使得先滑动者会挡住后滑动者。

**规则**：
1. 找到所有可滑动复合体，计算每个矩形体的面积（宽 x 高，像素数）。
2. 按面积从大到小排序。面积最大者优先级最高，最先滑动。
3. 按优先级从高到低依次处理每个复合体：
   a. 擦除该复合体（矩形体 + 杆均变为黑(0)）。
   b. 将矩形体沿杆方向平移，直到矩形体的前端碰到网格边缘或碰到任何已滑动到位的其他矩形体（前端紧邻障碍物，不重叠）。
   c. 将矩形体绘制在新位置。杆不保留。
4. 输出网格仅包含所有矩形体在最终位置的绘制结果，背景为黑(0)。

**关键洞察**：面积排序不只是分类信息——它决定了物理交互的因果链。大矩形先滑动到边缘，成为小矩形的障碍物，使小矩形提前停下。相同的输入若按面积从小到大处理，结果将完全不同。求解者必须同时归纳出排序规则和碰撞规则，缺一无法复现输出。

1. 找到所有 4-连通单色前景连通分量，计算各自像素面积。
2. 选出面积最大的唯一连通分量，裁剪其边界框得到一个 kxk 的二值模板（对象像素为 1，背景像素为 0），其中 k = 3 或 4。
3. 读取栗(9)标记像素确定输出着色色为栗(9)。
4. 创建一个边长为 12（若 k=3）或 16（若 k=4）的黑(0)输出画布。
5. 将 kxk 二值模板以周期 k 在输出画布上平铺（水平和垂直方向均重复），模板中值为 1 的位置涂为栗(9)，值为 0 的位置保持黑(0)。
6. 干扰对象和标记像素不出现在输出中。

**关键洞察**：最大连通分量不是"答案"而是"密码"——它的几何轮廓编码了平铺模板的形状。干扰对象的面积提供了排除依据，而栗色标记像素看似无关却决定了输出的颜色。求解者必须跨越"选择→解码→生成"三个层次才能理解输入到输出的完整映射。
