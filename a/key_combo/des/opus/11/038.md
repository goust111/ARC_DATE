## 新题 1：桥接簇孔洞总数决定颜色

**组合逻辑**：[connectivity_test](将桥接路径作为对象间的连通通道，原用于二元判定，此处用于多对象聚类) + [counting/enclosed_region](对簇内所有对象的封闭孔洞求和，原为单对象属性，此处升级为聚合属性) -> [recolor](按聚合孔洞总数映射颜色)

**来源原语**：connectivity_test/bridge_path/connectivity(参考题19 239be575), enclosed_region/hole_count_to_color_mapping(参考题1 0a2355a6), recolor(参考题1, 16), connected_component(参考题1, 15, 16)

**依赖链**：桥接路径将对象分组为连通簇 -> 簇内各对象的封闭孔洞数逐一计算后求和 -> 总和作为整簇的颜色键，映射到目标颜色 -> 所有簇内像素（含桥接段）统一重涂色。连通分组决定了孔洞聚合的范围，孔洞总数决定了颜色选择——去掉任一环节，剩余部分无法求解。

将桥接连通的多个含孔对象视为一个拓扑整体，按聚合孔洞总数而非单个对象的孔洞数来决定颜色。

**输入结构**：约 15x15 的网格。黑(0)背景。3~5 个青(8)色 4-连通前景对象散布其中，每个对象为不规则闭合形状（8~20 像素），内部各自包围 1~3 个 4-连通的黑(0)封闭孔洞（即完全被该对象的青色像素围住、无法沿黑色像素到达网格边界的黑色区域）。部分对象之间通过 1 像素宽的青(8)轴对齐桥接路径相连（水平或垂直直线段，不分叉），其余对象孤立。不同对象的边界框互不重叠，桥接路径仅连接两个对象的边界像素且中间不经过第三个对象。生成约束：每个簇的孔洞总数落在 1~4 范围内；至少存在一个包含 2 个以上对象的簇和一个孤立对象。

**规则**：
1. 在所有青(8)像素上执行 4-连通分析，将通过桥接路径相连的对象归入同一簇。
2. 对每个簇，逐一识别簇内各对象内部的封闭黑(0)区域（封闭区域定义：由对象的青色像素 4-连通围住的黑色 4-连通分量，且该分量无法沿黑色像素路径到达网格的任何边界行/列）。
3. 将簇内所有对象的封闭孔洞数求和，得到该簇的孔洞总数 S。
4. 按 S 重涂色簇内所有青(8)像素（包括桥接路径像素）：S=1 -> 蓝(1)，S=2 -> 绿(3)，S=3 -> 红(2)，S>=4 -> 黄(4)。
5. 黑(0)背景保持不变。

**关键洞察**：单个对象的形状和孔洞数不直接决定颜色；必须先通过桥接路径确定连通簇，再将簇内所有对象的拓扑属性聚合，才能查找颜色映射。孤立对象以自身孔洞数参与映射，而桥接对象的颜色取决于整簇的拓扑总量。

## 新题 2：射线探测互补形状并填充缺口

**组合逻辑**：[ray_extend](从源形状的发射器向左延伸探测射线，原用于绘制可见线条，此处用作空间搜索探针，不留痕迹) + [shape_match/complementary_shape](射线碰到模板时执行形状互补测试，原为静态配对，此处由射线动态触发) -> [fill](互补匹配成功时将源形状颜色填入模板缺口)

**来源原语**：ray_extend(参考题2 ac3e2b04, 参考题17 bdad9b1f), shape_match/complementary_shape/unique_complement(参考题12 18447a8d), template_gap/source_shape(参考题12), fill(参考题12), marker_pixel(参考题3, 13, 15)

**依赖链**：发射器的位置和方向决定射线扫过哪些模板 -> 射线在每个模板处触发互补形状测试 -> 测试结果决定射线是停止并填充还是穿透继续 -> 填充操作将源颜色写入匹配的模板缺口。射线提供搜索路径，互补测试提供匹配判据，填充完成变换——三者在"射线碰撞时测试、通过则停止"这一决策点紧密耦合。

从源形状发出的探测射线沿途检查模板的缺口形状，仅在互补匹配时停止并将源颜色填入缺口。

**输入结构**：约 18x18 的网格。黑(0)背景。左侧区域（约前 5 列）放置 2~3 个模板块，每个模板块是一个单色矩形区域（如蓝(1)、灰(5)、品红(6)，每个模板颜色不同），内部包含一个 3~5 像素的不规则 4-连通背景色(黑(0))缺口（即模板矩形中被扣除的部分）。右侧区域（约后 5 列）放置等数量的源形状，每个源形状是 3~5 像素的 4-连通单色图形（如红(2)、绿(3)、黄(4），每个源形状颜色不同），且每个源形状的最左列有一个紧邻的橙(7)发射器像素（与源形状在同一行、位于源形状左侧一列）。中间区域为空白黑(0)走廊。生成约束：每个源形状（平移归一化后）恰好与一个模板缺口（平移归一化后）形状相同，形成唯一配对；不同模板的缺口形状互不相同。

**规则**：
1. 对每个橙(7)发射器像素，从其位置向左逐列延伸一条不可见射线（不绘制任何像素）。
2. 当射线进入某个模板块所占的列范围时，将该发射器对应的源形状与该模板的缺口进行互补测试：将源形状和缺口分别平移使其最小边界框左上角对齐原点，比较二者像素集合是否完全相同。
3. 若匹配成功：将模板缺口内的黑(0)像素重涂为该源形状的颜色；擦除原位置的源形状和发射器像素（置为黑(0)）；该射线终止。
4. 若匹配失败：射线穿过该模板继续向左搜索下一个模板。
5. 若射线到达网格左边界仍未找到匹配，源形状和发射器保持不变。
6. 多条射线之间互不干扰。处理顺序为从上到下（按发射器像素的行号），行号相同时从左到右。

**关键洞察**：射线不仅仅是连接线，而是逐模板扫描的空间搜索器——源形状可能跳过不匹配的模板，继续向左寻找真正互补的目标。射线碰撞只是候选，互补测试才是决策点。

## 新题 3：多掩码叠加的面积排名冲突裁决

**组合逻辑**：[overlay/per_pixel_comparison](三层掩码逐像素叠加统计覆盖数，原为二层比较，此处扩展到三层并产生三种覆盖情况) + [counting/area_ranking](计算各掩码的全局前景面积并排名，原用于直接映射颜色，此处用作覆盖冲突的裁决依据) -> [recolor](按覆盖数和裁决结果决定每个像素的输出颜色)

**来源原语**：overlay/per_pixel_comparison/both_background_marked_foreground(参考题7 94f9d214), counting/area_ranking/area_determines_color(参考题16 e8593010), recolor(参考题1, 7, 16), mask(参考题7), separator_row(参考题4)

**依赖链**：三层掩码叠加产生每个像素的覆盖计数 -> 覆盖数为 2 时需裁决使用哪个颜色 -> 裁决依据是两个竞争掩码的全局面积排名 -> 面积较大者的颜色胜出。局部像素状态（覆盖数）和全局统计量（面积排名）在双重覆盖像素处交汇——去掉面积排名，双覆盖像素颜色不确定；去掉逐像素叠加，不知道哪些像素需要裁决。

将三层掩码按覆盖数分类，三重覆盖标为特殊色，双重覆盖由全局面积排名裁决胜者颜色，单覆盖保留原色。

**输入结构**：约 20x12 的网格（较高）。网格被两条灰(5)水平分隔行分为三个等高条带（每带约 4 行）。三个条带共享相同宽度。条带 1 的前景色为蓝(1)，条带 2 为红(2)，条带 3 为绿(3)，各条带的背景为黑(0)。每个条带中，前景色像素形成一个不规则的 4-连通图案，覆盖该条带约 30%~60% 的单元格。生成约束：三个条带的前景图案各不相同；存在至少一些位置三个条带都有前景、一些位置恰好两个有前景、一些位置恰好一个有前景、一些位置三个都没有前景。

**规则**：
1. 移除两条灰(5)分隔行，将三个条带对齐为一个与单个条带尺寸相同的输出网格。
2. 对输出网格的每个像素位置 (r, c)，统计三个条带中在该位置有前景像素的条带数 N。
3. N=0：输出黑(0)。
4. N=1：输出该唯一条带的前景色。
5. N=3：输出黄(4)。
6. N=2：计算参与覆盖的两个条带各自的全局前景面积（该条带中前景像素的总数）。输出面积较大的那个条带的前景色。若两个条带面积相同，输出位置靠上（在输入中条带序号较小）的那个条带的前景色。

**关键洞察**：双覆盖像素的颜色无法仅凭局部信息决定——必须计算两个竞争条带的全局前景面积，用面积排名打破平局。这意味着单个像素的输出可能依赖于远离它的其他前景像素的存在与否。

## 新题 4：重力下落穿越漏洞容器的路径转向

**组合逻辑**：[gravity_drop](标记从顶行下落，原为直线落入容器或铺底，此处下落路径可被容器壁洞口偏转) + [enclosed_region/container](容器壁的完整性决定捕获或泄漏，原为二元判定"有容器/无容器"，此处壁洞位置产生方向性路由) -> [fill](被完整容器捕获的标记填充容器内部；未被捕获的标记铺满底行)

**来源原语**：gravity_drop/column_fall_in/no_container_floor(参考题13 db7260a4), container(参考题13), enclosed_region(参考题1), fill(参考题13), pathfinding/detour_on_obstacle(参考题10 d9f24cd1), marker_pixel(参考题13)

**依赖链**：标记从顶行开始沿列下落 -> 遇到容器时检测壁完整性 -> 完整容器捕获标记并触发内部填充 -> 有漏洞的容器将标记从洞口排出，偏移到洞口外侧列继续下落 -> 最终未被捕获的标记铺满底行。容器壁的结构不仅决定"是否捕获"，还通过洞口位置决定"偏向哪一列"，从而改变后续遇到的容器序列。

彩色标记从顶行下落，完整容器捕获标记并填充内部，壁有漏洞的容器将标记从洞口弹出并偏转列坐标继续下落。

**输入结构**：约 12x18 的网格（较宽矮改为窄高）。黑(0)背景。顶行有 2~3 个彩色单像素标记（如红(2)、蓝(1)、绿(3)），分别占据不同的列。下方分布 3~5 个灰(5)色 U 形容器：每个容器由两条垂直侧壁（各 2~4 像素高）和一条连接底部的水平底壁组成，内部为黑(0)空腔。部分容器的一条侧壁上有恰好一个缺失像素（漏洞），另一部分容器的壁完全完整。容器位于不同的垂直高度，列范围可部分重叠但容器之间不相互接触（边界框间距至少 1 列）。生成约束：每个标记的初始列落在至少一个容器的水平跨度内；标记列各不相同；经过所有路径偏转后，每个标记最终恰好被一个完整容器捕获或到达底行。

**规则**：
1. 擦除每个标记像素，将其原位置置为黑(0)。
2. 对每个标记，从其初始列、第 1 行（顶行下方）开始逐行向下模拟：
   a. 若当前位置正下方是黑(0)或已出网格：继续向下一行。
   b. 若当前位置正下方碰到某容器的侧壁顶端或底壁：
      - 检查该容器的两条侧壁是否都完整（无缺失像素）。
      - **壁完整**：标记被捕获。将该容器空腔内所有黑(0)像素填充为标记的颜色。该标记的模拟结束。
      - **壁有漏洞**：标记从漏洞泄出。确定漏洞在左壁还是右壁：若漏洞在左壁，标记转移到容器左壁左侧一列；若漏洞在右壁，标记转移到容器右壁右侧一列。标记从漏洞所在的行继续向下模拟。
   c. 若标记到达网格最底行仍未被任何完整容器捕获：将整个底行所有像素填充为标记的颜色。
3. 标记按初始列从左到右依次处理。若两个标记最终都要填充底行，后处理的标记颜色覆盖先处理的（底行取最后到达者的颜色）。若两个标记指向同一个完整容器，先到达的标记填充该容器，后到达的标记视该容器为不可穿透的实体（其顶边阻挡下落，标记停留在容器正上方一格，不填充任何内容）。

**关键洞察**：容器壁的漏洞不仅仅是一个拓扑缺陷——它是一个方向性路由器，将标记的列坐标偏移到完全不同的垂直通道上。一个标记可能被第一个容器的漏洞弹到另一列，落入第二个容器被捕获，而如果第一个容器完好则标记根本不会到达第二个容器。

## 新题 5：对称补全揭示隐藏连接端点

**组合逻辑**：[symmetry_completion/infer_missing_from_three](在 2x2 格元块中从三个已知精灵推断第四个，原为最终输出，此处推断结果仅为中间步骤) + [connect/same_row_col_align](在所有标记像素之间按同行同列规则连线，原为已知标记间的操作，此处连接对象包含推断出的新标记) -> [recolor/crossing_cell_marked_new_color](两条不同偏移的连接线交叉时将交叉像素重涂为特殊颜色)

**来源原语**：symmetry_completion/block_symmetry/infer_missing_from_three(参考题14 2546ccf6), lattice_cell/divider_line/sprite(参考题14), connect/same_row_col_align/local_offset_preserved(参考题20 cbded52d), separated_tile_lattice(参考题20), crossing/crossing_cell_marked_new_color(参考题17 bdad9b1f), recolor(参考题17)

**依赖链**：对称补全推断出缺失格元中的精灵，其中包含此前不可见的标记像素 -> 这些新标记与已有标记一起参与同行/同列连接规则 -> 连接线在某些格元内产生交叉 -> 交叉像素被标记为特殊颜色。对称补全是信息生成步骤（揭示隐藏标记），连接是信息传播步骤（基于完整标记集拓展结构），交叉标色是最终判定——跳过补全则标记集不完整、连接图案错误。

通过对称推断补全缺失格元中的精灵（含隐藏标记），然后用完整的标记集在格阵中建立同偏移连接线，交叉点标为特殊颜色。

**输入结构**：约 15x15 的网格。灰(5)色分隔线组成的网格将画布分为 3x3 阵列的等大矩形格元（每个格元内部约 4x4）。每个格元要么为空（全黑(0)），要么包含一个小精灵（2~4 像素的单色 4-连通图形）。精灵使用的颜色：蓝(1)、红(2)、绿(3)，每种颜色对应一个 2x2 格元块中的同色精灵组。在每个 2x2 格元块中，恰好 3 个格元有精灵、1 个为空；三个已知精灵是同一图案按其在 2x2 块中的位置做水平/垂直翻转后的变体。部分精灵的内部包含一个额外的橙(7)标记像素，位于格元内的特定局部偏移位置。生成约束：每个 2x2 块的对角精灵翻转后一致；推断出的第四个精灵也会在对应翻转位置包含橙(7)标记（如果对角精灵有标记的话）；至少存在两对同局部偏移的标记分布在同一格元行或列中，且至少一对包含推断出的标记。

**规则**：
1. 对每个 2x2 格元块，找到空格元。取对角位置的精灵，对其同时做水平和垂直翻转，将结果绘制到空格元中，颜色与对角精灵相同（包括其中的橙(7)标记像素也一并翻转放置）。
2. 补全所有空格元后，收集网格中所有橙(7)标记像素（含原有的和新推断出的）。对每个标记，记录其所在的格元行号、格元列号、以及在格元内的局部偏移 (lr, lc)。
3. 对于共享相同局部偏移 (lr, lc) 的标记组：若组内存在两个标记位于同一格元行（格元行号相同），则在它们之间的所有中间格元中，在相同局部偏移 (lr, lc) 处绘制橙(7)像素，形成水平连接线。同理处理同一格元列的标记对，形成垂直连接线。连接线仅绘制在格元内部的对应偏移位置，不覆盖分隔线。
4. 若在某个格元内，两条不同局部偏移的连接线都经过该格元（即该格元内有两个不同偏移位置都被连接线绘制了橙(7)像素），则将这两个像素中后绘制的那个（垂直连接线的像素）重涂为黄(4)。若同一格元内有超过两条线经过，所有交叉偏移位置的像素均重涂为黄(4)。

**关键洞察**：对称补全不是最终答案——它揭示了隐藏在空格元中的标记像素。这些推断出的标记参与后续的连接步骤，因此跳过补全会导致连接图案不完整。求解者必须先完成拓扑推断，才能看到完整的连接端点集合。

## 新题 6：旋转互补对接拼合

**组合逻辑**：[rotate](对移动件尝试四种旋转角度，原为整体旋转，此处旋转是搜索变量而非固定操作) + [shape_match/complementary_shape](旋转后的移动件边缘轮廓必须与静止件的对接边互补，原为平面形状配对，此处为边缘轮廓的一维互补测试) -> [stitch/same_color_dock](按连接标记颜色配对后将两件拼合为一体，原为平移对接，此处需旋转才能对接)

**来源原语**：rotate(参考题9 ed36ccf7), shape_match/complementary_shape/unique_complement(参考题12 18447a8d), stitch/same_color_dock/connector_marker/marker_side_dir(参考题18 e9fc42f2), crop(参考题18)

**依赖链**：连接器颜色配对确定哪两个对象必须拼合 -> 连接器在各自对象上的边位置确定对接方向 -> 对移动件逐一尝试 0/90/180/270 度旋转 -> 每种旋转下检测对接边的轮廓是否与静止件互补（凸凹吻合、无重叠无间隙） -> 唯一满足互补条件的旋转即为正确旋转 -> 将旋转后的移动件平移至连接器相邻位置完成拼合。旋转角度不是预设的，而是由几何互补约束唯一确定的。

按同色连接器配对两个对象，找到使对接边轮廓完全互补的唯一旋转角度，将旋转后的移动件拼合到静止件旁边。

**输入结构**：约 16x16 的网格。黑(0)背景。2~3 对前景对象散布在网格中，边界框间距至少 2 像素。每个对象是一个 4-连通的单色图形（4~8 像素），体色各不相同（使用灰(5)、橙(7)、黄(4)、青(8)、栗(9)中的不同颜色）。每个对象的边界上恰好有一个连接器像素，颜色与体色不同，属于一种配对色（红(2)、绿(3)、蓝(1)）。同一对的两个对象共享同一连接器颜色，不同对使用不同连接器颜色。连接器像素位于对象边界上，朝外侧（即连接器的某个 4-邻居为黑(0)背景）。在每对中，一个对象的连接器在其上边或左边（称为"移动件"），另一个的连接器在其下边或右边（称为"静止件"）。生成约束：对每对对象，恰好存在一个旋转角度（0/90/180/270 度）使得移动件旋转后、连接器对齐邻接时，两件在对接边上逐行（或逐列）的轮廓完全互补（移动件凸出的位置对应静止件凹入的位置，反之亦然），且合并后无像素重叠。

**规则**：
1. 按连接器颜色将对象配对。
2. 对每对，确定移动件和静止件：连接器朝向上或左的为移动件，朝向下或右的为静止件。
3. 对移动件依次尝试旋转 0、90、180、270 度（以其边界框中心为旋转中心）。每种旋转后，将移动件的连接器像素与静止件的连接器像素对齐为 4-相邻（移动件连接器的外侧朝向静止件连接器的外侧），检查对接边上两件的轮廓是否完全互补：沿对接边逐行（水平对接）或逐列（垂直对接）检查，移动件伸出的像素数 + 静止件伸出的像素数 = 对接边总长度（即凸凹恰好吻合），且两件的所有像素无重叠。
4. 取唯一满足条件的旋转角度，将移动件旋转后平移到对接位置。
5. 擦除移动件原位置的所有像素（置为黑(0)）。
6. 连接器像素保留各自的配对颜色。
7. 各对独立处理，处理顺序不影响结果（生成约束保证各对拼合区域互不冲突）。

**关键洞察**：旋转角度不是规则预设的常量，而是由对接边的几何互补条件唯一确定的搜索结果。求解者必须对每种旋转执行边缘轮廓匹配测试，才能确定正确的拼合方式。这不是"旋转后放置"，而是"为了能放置而寻找旋转"。

## 新题 7：字形查表位置作为连通性图判定

**组合逻辑**：[table_lookup](查询字形在参考表中定位匹配单元格，原为标记匹配单元格，此处匹配单元格的位置坐标成为下一步输入) + [connectivity_test](将匹配单元格的表内位置视为图节点，检测 4-连通性，原用于空间像素的连通判定，此处重新解释为表格坐标系上的抽象图连通性) -> [fill](根据连通性判定结果填充裁决带颜色)

**来源原语**：table_lookup/glyph_cell/reference_table/query_row(参考题4 d8e07eb2), alignment_verdict(参考题4), connectivity_test/connectivity/connected_color_else_black(参考题19 239be575), fill(参考题4, 11), separator_row(参考题4)

**依赖链**：查表定位将每个查询字形映射到参考表中的坐标 -> 这些坐标构成一个节点集合 -> 在表格的行列网格上对节点集合执行 4-连通判定 -> 判定结果（连通/不连通）决定裁决带的颜色。查表提供"在哪里"，连通测试判断"是否相连"——表的空间结构被重新解释为抽象图的拓扑结构。

在参考表中定位与查询字形匹配的单元格，然后检查这些匹配位置在表格坐标中是否构成一个 4-连通的子图来输出裁决。

**输入结构**：约 18x14 的网格。青(8)背景。两条全宽品红(6)水平分隔行将网格分为三个水平条带。顶部条带（查询带）：一行 3~4 个字形单元格，每个单元格为 5x5 区域，内部中央有一个 3x3 的彩色图案（颜色和形状各不相同，如蓝(1)的 L 形、红(2)的十字形、绿(3)的对角线等）。中间条带（参考表）：一个 3x4 或 4x3 的字形单元格阵列，使用相同的 5x5 单元格规格，每个单元格包含唯一的 3x3 彩色图案。参考表包含所有查询字形以及额外的干扰字形。底部条带（裁决带）：2~3 行高，初始全部为青(8)背景。生成约束：查询字形在表中各有唯一精确匹配（颜色和形状均相同）；匹配的表内位置在不同示例中有时构成 4-连通子图、有时不构成。

**规则**：
1. 对每个查询字形，在参考表中寻找精确匹配（3x3 图案的颜色和形状均完全相同的单元格）。
2. 将每个匹配单元格所在的表内位置标记为绿(3)填充（仅填充该单元格内 3x3 图案周围的青(8)背景像素，图案本身保持原色）。
3. 将匹配单元格视为表格行列坐标系中的节点。两个匹配节点"相连"当且仅当它们在表格中水平或垂直相邻（中间无未匹配的单元格间隔，即二者的表格行号差 + 列号差 = 1）。
4. 检查所有匹配节点是否构成一个 4-连通子图（从任一匹配节点出发，沿相邻匹配节点可到达所有其他匹配节点）。
5. 若连通：将裁决带填充为绿(3)，同时将查询带内的青(8)背景像素也填充为绿(3)。
6. 若不连通：将裁决带填充为红(2)，查询带保持不变。

**关键洞察**：裁决不再是关于行列对齐的（源题中检查匹配位置是否构成完整的一行或一列），而是关于匹配位置在表格坐标系中的图论连通性。一组匹配可能排成 L 形或弯折路径仍然连通，也可能排成对角线却不连通——判断标准是 4-邻接可达性而非几何排列。

## 新题 8：障碍绕行水平迁移与地面轨迹记录

**组合逻辑**：[pathfinding/detour_on_obstacle](精灵水平移动时遇到障碍向上绕行一行再前进一步，原为垂直生长时水平绕行，此处将运动主方向旋转 90 度并作用于多像素精灵而非单像素路径) + [mirrored_position](精灵的目标位置是其水平镜像位置，原为直接平移到镜像点，此处镜像位置仅为目标，实际到达位置受绕行偏移影响) -> [fill/floor_row](在地面行上用精灵颜色绘制从起点列到终点列的水平轨迹，原为铺满底行或填充容器，此处记录实际水平行程)

**来源原语**：pathfinding/stepwise_advance/detour_on_obstacle/blocker_pixel(参考题10 d9f24cd1), mirrored_position/orientation_preserved(参考题8 8ee62060), translate(参考题8), floor_row/move_to_wall(参考题5 9f41bd9c), fill(参考题5, 13)

**依赖链**：镜像位置定义目标列 -> 精灵向目标水平移动 -> 障碍触发垂直绕行，改变精灵的最终行位置 -> 地面行记录精灵的水平起止范围。镜像提供方向目标，障碍改变实际轨迹，地面轨迹仅反映水平投影——三者在"目标 vs 实际路径 vs 记录"的三角关系中紧密耦合。删除镜像则无目标方向；删除绕行则精灵直达镜像位置（地面轨迹可直接计算）；删除地面轨迹则丢失水平行程信息。

精灵向水平镜像位置移动，遇灰色障碍时上移一行绕行，到达后在地面行绘制起止列之间的水平轨迹。

**输入结构**：约 14x10 的网格。黑(0)背景。最底行为实心栗(9)地面行。2~3 个小型彩色精灵（各 3~5 像素，4-连通，颜色各不相同，如蓝(1)、红(2)、绿(3)），每个精灵紧贴网格的左边缘或右边缘，位于地面行正上方（精灵的最底行像素在地面行上方一行）。灰(5)障碍像素散布在网格中部区域（不紧贴左右边缘），每个障碍为单个像素。生成约束：同一列中不会有两个障碍上下相邻；每个精灵的镜像列范围不与另一个精灵的镜像列范围重叠；所有路径可完成（不存在某列被障碍完全封锁导致精灵无法通过的情况）；精灵边界框高度不超过 2 行。

**规则**：
1. 对每个精灵，计算其水平镜像目标位置：若精灵边界框的左列为 c0、宽度为 w，则目标左列为 grid_width - w - c0。
2. 将精灵视为刚体，从当前位置向目标位置逐列水平移动（每步移动一列，方向为从当前列指向目标列）。每步检查：
   a. 若精灵在下一列的所有像素位置均为黑(0)或栗(9)地面（即无灰(5)障碍阻挡）：精灵水平平移一列。
   b. 若精灵在下一列的任一像素位置被灰(5)障碍占据：精灵先整体上移一行（所有像素行号 -1），然后水平平移一列。若上移后精灵的任一像素超出网格顶部，该像素被裁剪（丢弃）。
3. 精灵到达目标列后，在最终位置绘制精灵（保持原色和内部布局）。将精灵从原位置擦除（置为黑(0)）。
4. 在栗(9)地面行上，从精灵原始左列到最终左列之间（含两端）的所有像素，重涂为精灵的颜色。若最终左列在原始左列的左边，则范围为 [最终左列, 原始左列]；否则为 [原始左列, 最终左列]。
5. 精灵按其最底行像素的行号从大到小处理（更靠近地面的先处理）。行号相同时按列号从左到右处理。不同精灵的地面轨迹若重叠，后处理的精灵的颜色覆盖先处理的。

**关键洞察**：镜像位置只决定目标列，不决定目标行——障碍绕行会将精灵向上推移，因此精灵的最终行位置可能高于其初始行位置。地面轨迹仅记录水平投影（起止列），隐藏了垂直偏移信息。求解者必须逐步模拟路径才能确定精灵的真实最终位置和轨迹长度。
