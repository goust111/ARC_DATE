## 新题 1：重力碰撞生成同心生长种子

**组合逻辑**：[重力下落](保留碰撞阻挡机制) → [生长/描边](创新：生长层数由下落距离决定，非预设间距)

**来源原语**：重力下落/gravity_drop(5ffb2104), 碰撞阻挡/collision_blocking(5ffb2104), 生长/grow(5c2c9af4), 同心方框层/concentric_layer(5c2c9af4), 重力远近序处理/gravity_far_to_near(5ffb2104)

**依赖链**：重力解算确定每个对象的停靠位置和行进距离 → 停靠位置成为同心生长的种子点 → 行进距离成为该种子的生长层数。删除重力步骤则无法获知种子位置和层数；删除生长步骤则碰撞信息无处使用。

将多个单色小图形向右施加重力使其碰撞堆叠，每个图形的停靠点生长出同心方框，层数等于其滑行距离。

**输入结构**：黑(0)背景，约 20x20 网格。3~5 个单色小图形（各为 4-连通、2~4 像素的不规则形状），颜色各不相同（从红(2)、绿(3)、黄(4)、青(8)中选取），散布在网格左半区的不同行上，彼此不在同一行重叠。网格右侧边界为阻挡壁。生成约束：各图形的水平投影不重叠（即不存在两个图形占据相同的行范围且列范围有交集的情况），保证重力解算无歧义。

**规则**：
1. 将所有图形视为刚体，向右施加重力。按原始位置从右到左的顺序依次处理（最右者先落定），每个图形水平右移直到其任意像素碰到网格右边界或已落定图形的像素的左邻格。
2. 记录每个图形的滑行距离 D（起始最右列到终止最右列之差）。
3. 清除所有图形像素。以每个图形落定后的质心位置（所有像素坐标的算术平均，四舍五入到最近整数格）为种子，用该图形的颜色向外生长 D 层同心正方形边框（第 1 层为种子外扩 1 格的 8 邻域框，第 k 层为外扩 k 格的框）。
4. 若不同图形的同心框像素重叠，滑行距离更大的图形优先（其颜色覆盖距离更小者）；距离相同时，原始位置更靠右的图形优先。
5. 种子像素本身保留对应图形的颜色。

**关键洞察**：同心生长的层数不是输入中可直接读取的属性，而是重力模拟的副产品——必须先完成碰撞解算才能确定每个种子应生长多少层。

## 新题 2：对象计数驱动母题循环填充次数

**组合逻辑**：[计数](保留颜色索引机制) → [循环填充](创新：循环次数由计数结果决定，非无限填满)

**来源原语**：计数/counting(58490d8a), 颜色索引行/color_keyed_row(58490d8a), 图例框/legend_box(58490d8a), 循环填充/cyclic_fill(12422b43), 母题行/motif_rows(12422b43), 标记界定母题/marker_delimits_motif(12422b43), 擦除/erase(12422b43)

**依赖链**：图例框提供颜色-母题映射 → 计数确定每个颜色的重复次数 → 循环填充按次数堆叠母题。删除计数则不知填多少次；删除图例则不知填什么图案。

统计网格中各颜色对象的数量，以此决定图例框中对应母题向下循环重复的完整次数。

**输入结构**：黑(0)背景，约 18x18 网格。左侧有一个灰(5)边框包围的图例区域（约 4 列宽、覆盖网格全部行高），图例区域内部为黑色背景，其中最左列非灰的像素为 2~4 个颜色键（如红(2)、蓝(1)、绿(3)），每个颜色键的右侧同行有 2~3 个像素组成的小母题图案。图例区域外的网格散布着若干 4-连通单色小对象（3~6 像素），颜色与图例键颜色对应，每种颜色有 1~4 个独立对象。生成约束：图例中各颜色键所在行互不相邻（至少间隔 1 行黑色），且母题图案高度均为 1 行。

**规则**：
1. 识别灰(5)边框围成的图例区域，提取其中各颜色键及其同行的母题图案（键像素右侧到灰边框之间的非黑像素序列）。
2. 对每个颜色键 C，计数图例区域外颜色为 C 的独立 4-连通对象数量，记为 N_C。
3. 输出网格仅保留图例区域（含灰边框）。在图例区域右侧的空白画布中，从顶行开始，按图例中颜色键从上到下的顺序，依次将各母题垂直堆叠：颜色 C 的母题连续重复 N_C 行，然后紧接下一个颜色的母题重复其对应次数，直到所有颜色处理完毕。
4. 擦除图例外原有的所有散布对象。若堆叠超出网格底部则截断。

**关键洞察**：循环填充的次数不来自网格的空间容量，而来自对象计数——必须先正确分割并计数外部对象才能确定每段母题重复多少次。

## 新题 3：边框中心色编码附近对象的运动方向

**组合逻辑**：[提取](创新：中心色不作为输出而作为方向指令) + [滑动/重力下落](创新：方向非固定而由局部编码决定) + [擦除]

**来源原语**：提取/extract(d9fac9be), 单色边框/monochrome_frame(d9fac9be), 中心像素/center_pixel(d9fac9be), 忽略干扰项/ignore_distractors(d9fac9be), 滑动/slide(d6e50e54), 最近距离/nearest_distance(d6e50e54), 碰撞阻挡/collision_blocking(5ffb2104)

**依赖链**：识别边框结构并提取中心色 → 中心色编码方向 → 每个对象找最近边框获取方向 → 按方向滑动并碰撞阻挡。删除提取步骤则方向未知；删除最近距离匹配则对象无法关联到方向源。

散布的前景对象各自向最近的 3x3 边框所指示的方向滑动，直到碰壁或碰到其他对象。

**输入结构**：黑(0)背景，约 18x18 网格。网格中有 3~4 个完整的 3x3 单色边框（8 个边界像素为灰(5)，中心像素为红(2)、蓝(1)、绿(3)或黄(4)之一），各边框之间间距至少 4 格。另有 3~5 个 4-连通单色前景对象（橙(7)，3~5 像素不规则形状）散布在网格上，每个对象与至少一个边框有明确的曼哈顿距离最近关系（不存在到两个边框等距的对象）。此外有若干孤立的灰(5)像素作为干扰项，它们不构成完整 3x3 边框。生成约束：各前景对象按其指定方向滑动时的路径互不冲突（不存在两个对象面对面滑动的情况）。

**规则**：
1. 扫描网格，识别所有完整的 3x3 单色边框（3x3 窗口中 8 个边界像素相同且中心像素为不同的非黑非灰颜色）。不完整的灰像素为干扰项。
2. 方向编码：中心为红(2)=向下，蓝(1)=向左，绿(3)=向右，黄(4)=向上。
3. 对每个橙色前景对象，计算其质心到每个边框中心的曼哈顿距离，选择最近的边框，读取该边框的方向编码。
4. 按照与目标方向边界的距离从近到远的顺序处理对象（最近边界者先移动）。每个对象沿指定方向整体平移，直到其任意像素触及网格边界或已就位对象的相邻格。
5. 输出中擦除所有边框（含中心）和干扰灰像素，仅保留滑动后的橙色对象。

**关键洞察**：方向信息隐藏在 3x3 边框的中心像素颜色中——必须先从干扰项中识别出合法边框，提取中心色，再将其解释为运动指令，颜色到方向的映射规则需对比多个示例才能归纳。

## 新题 4：检测到的列周期同时决定印章内容和间距

**组合逻辑**：[平铺/周期检测](保留最小周期寻找) → [印章覆盖](创新：间距和模板尺寸均由检测到的周期值 P 决定)

**来源原语**：平铺/tile(d8c310e9), 最小周期单元/minimal_period(d8c310e9), 列周期重复/column_period(d8c310e9), 印章覆盖/stamp(b4a43f3b), 分隔行/separator_row(b4a43f3b), 掩码标记/mask_marker(b4a43f3b), 标记位置接收模板/marker_receive_template(b4a43f3b)

**依赖链**：上方面板的周期分析得出 P → P 确定模板的列宽（裁取一个周期） → P 同时确定下方面板的印章间隔 → 标记行决定哪些间隔位置实际被印章。删除周期检测则模板宽度和间距均未知；删除标记则所有位置都被填充，失去选择性。

检测上方图案的最小列周期 P，将单周期宽度的模板按间隔 P 印到下方画布中有标记的位置。

**输入结构**：黑(0)背景，约 14x20（14 行 20 列）网格。第 7 行为实心灰(5)分隔行。上方 6 行：一段部分可见的水平周期图案，由红(2)和蓝(1)像素构成，从最左列开始连续绘制若干列后停止（剩余列为黑色背景），其最小列周期 P 在 3~5 之间。下方 7 行：一个与上方等宽的画布，其中某些列的第一行（紧接分隔行下方）有绿(3)标记像素，标记像素之间的列间距恰为 P 的倍数。生成约束：上方图案至少展示 2 个完整周期以保证周期可检测；标记列的位置均对齐到 P 的整数倍列号（以最左列为 0 基准）。

**规则**：
1. 分析分隔行上方图案，找到使所有可见前景像素在行内按列坐标模 P 一致的最小正整数 P。
2. 提取列 0 到 P-1 的上方图案作为模板瓦片（高度 = 上方面板行数，宽度 = P）。
3. 在下方画布中，找到所有绿(3)标记像素所在的列号集合 S。
4. 对每个列号 c 属于 S：将模板瓦片印到下方画布的列 c 至 c+P-1、行为分隔行下方第 2 行起（跳过标记行）。若印章超出网格右边界则截断。
5. 输出保留分隔行和上方图案不变，下方画布中非印章区域保持黑色，标记行的绿像素被擦除。

**关键洞察**：周期值 P 同时承担两个角色——它既是从上方图案裁取模板的宽度参数，也是下方印章放置的间距约束。这个双重依赖使得 P 的误判会导致模板内容和印章位置同时出错。

## 新题 5：边框环路的凸弯数决定容器滑动能量

**组合逻辑**：[环路追踪 + 分类涂色](保留凸/凹分类) → [逐步充能/平移](创新：能量预算来自边框几何属性而非内部灰格数)

**来源原语**：环路追踪/trace_cycle(15663ba9), 分类涂色/classify_and_color(15663ba9), 弯折像素/bend_pixel(15663ba9), 多数转向为凸/majority_turn_is_convex(15663ba9), 逐步充能/incremental_charge(271d71e2), 带边框容器/bordered_container(271d71e2), 目标标记/destination_marker(271d71e2), 颜色匹配配对/color_match_pairing(271d71e2), 能量上限步数/energy_caps_steps(271d71e2)

**依赖链**：追踪容器边框环路 → 分类弯折像素为凸/凹 → 凸弯数 = 容器可滑动步数 → 容器向目标标记滑动时内部灰格逐步充能。删除环路分析则能量未知；删除充能机制则无法观察实际移动了几步。

追踪每个容器黑色边框形成的闭合环路，统计凸弯折数作为该容器的移动能量上限，然后容器向同色目标滑动相应步数。

**输入结构**：品红(6)背景，约 16x20 网格。2~3 个黑(0)边框容器，每个容器的边框为 1 像素宽的闭合正交环路（非标准矩形——含有凸凹折角，使得边框不是简单的矩形框而是类似阶梯形或 L 形的闭合路径），内部填充灰(5)像素。每个容器外侧某一边中央有一个栗(9)色头精灵（1 像素），在头精灵延伸的同一轴向远处有一个栗(9)色目标标记（1 像素）。不同容器的头精灵和目标标记颜色相同但轴向可不同（水平或垂直）。生成约束：每个容器的凸弯数在 4~8 之间；目标标记距容器的距离大于凸弯数（确保容器不会越过目标）。

**规则**：
1. 对每个容器，追踪其黑(0)边框像素构成的闭合正交环路。在环路中，每个像素根据前后方向判定为直行或弯折；弯折像素中转向方向为多数方向的为凸弯，少数方向的为凹弯。
2. 统计每个容器边框的凸弯数量，记为 E（该容器的能量）。
3. 每个容器识别其紧邻的头精灵(9)及同轴向的目标标记(9)，确定运动方向（从头精灵指向目标标记）。
4. 容器整体（含边框和内部）沿运动方向平移 E 步。每移动一步，从运动方向前端起将一个灰(5)内部像素变为橙(7)（充能）。若灰格耗尽则停止（即使 E 未用完）。
5. 输出中凸弯像素标记为黄(4)，凹弯像素标记为红(2)，直行像素保持黑(0)。

**关键洞察**：容器的移动能力不由内部空间大小决定，而由其边框的几何复杂度（凸弯折数量）决定——边框越复杂（更多凸角），容器能移动越远。这需要先完成环路追踪和弯折分类才能确定移动步数。

## 新题 6：外部对象空间分布统计决定矩形象限着色

**组合逻辑**：[分割/象限](保留四等分机制) + [计数](创新：计数对象的空间方位而非仅数量) → [重涂色](创新：颜色由方位计数结果决定而非由标记像素指定)

**来源原语**：分割/split(e9ac8c9e), 实心矩形/solid_rect(e9ac8c9e), 象限/quadrant(e9ac8c9e), 重涂色/recolor(e9ac8c9e), 计数/counting(58490d8a), 前景对象/foreground_object(58490d8a), 最近距离/nearest_distance(d6e50e54), 角落对应/corner_correspond(e9ac8c9e)

**依赖链**：识别灰色矩形并四等分 → 统计矩形外部各象限方向的对象数量 → 数量最多的方向对应的颜色填充该象限。删除分割则无象限目标；删除计数则颜色来源未知；删除空间方位判定则计数无法对应到象限。

将灰色矩形四等分后，每个象限被涂为其对角外侧区域中数量最多的那种颜色对象的颜色。

**输入结构**：黑(0)背景，约 17x17 网格。中央有一个灰(5)实心矩形（宽高均为偶数，约 6x6 或 8x8）。矩形外的四个对角方向区域（左上、右上、左下、右下）各散布着若干小型 4-连通单色对象（2~4 像素），颜色从红(2)、蓝(1)、绿(3)、黄(4)中选取。每个对角区域包含 2~4 种颜色的对象，每种颜色 1~3 个对象，且每个区域中数量最多的颜色唯一（无并列）。生成约束：四个区域中数量最多的颜色互不相同。

**规则**：
1. 找到灰(5)实心矩形，计算其中心点坐标。
2. 将矩形水平和垂直各等分为四个象限：左上、右上、左下、右下。
3. 对矩形外的每个前景对象，根据其质心相对于矩形中心的位置归入四个对角区域之一（左上区域：质心在矩形中心的左方且上方，依此类推）。
4. 对每个对角区域，统计各颜色的独立对象数量，确定该区域中数量最多的颜色 C_max。
5. 将矩形对应象限（与区域同侧）整体涂为 C_max：左上区域的 C_max 涂左上象限，依此类推。
6. 输出中保留矩形外的所有前景对象不变。

**关键洞察**：象限颜色不来自紧邻的标记像素（如参考题中的对角标记），而来自对整个对角区域的统计分析——必须正确划分空间区域、归类对象、计数并比较才能确定每个象限的颜色。

## 新题 7：精灵拼合孔洞同时满足边缘颜色匹配约束

**组合逻辑**：[拼合填充](保留精确面积覆盖约束) + [平移拼合/边缘匹配](创新：将边缘匹配从矩形组装引入孔洞填充，形成双重约束)

**来源原语**：拼合填充/tiling_fill(184a9768), 源精灵体/source_sprite(184a9768), 封闭孔洞/enclosed_hole(184a9768), 大型单色对象/large_monochrome_object(184a9768), 精灵精确拼合孔洞/sprites_exactly_tile_holes(184a9768), 边缘匹配/edge_matching(446ef5d2), 通配色/wildcard_color(446ef5d2), 擦除/erase(184a9768)

**依赖链**：识别孔洞和精灵 → 面积匹配筛选可行精灵子集 → 尝试放置时检查边缘颜色匹配 → 通配色简化匹配但不消除约束。仅靠面积匹配有多解，加入边缘匹配后解唯一。删除面积约束则无法确定放置区域；删除边缘匹配则有多个合法拼合方案。

将多色精灵无旋转地平移嵌入大型对象的孔洞中，要求精灵精确覆盖孔洞面积且相邻精灵的接触边颜色一致。

**输入结构**：黑(0)背景，约 18x18 网格。一个蓝(1)大型单色对象（不规则形状，约占网格 40% 面积）内部有 1~2 个封闭背景孔洞（每个孔洞为 4-连通黑色区域，面积 6~12 像素，形状不规则）。网格其余区域散布着 2~4 个源精灵体，每个精灵为多色（含 2~3 种颜色，从红(2)、绿(3)、黄(4)、橙(7)中选取），像素数为 3~6，形状不规则。蓝(1)为通配色。生成约束：精灵的总像素数恰好等于所有孔洞的总面积；存在唯一的放置方案使得精灵精确覆盖所有孔洞且相邻精灵接触像素颜色一致或至少一方为蓝(1)。

**规则**：
1. 识别蓝(1)大型对象内部的所有封闭黑色孔洞。
2. 识别蓝(1)对象外部的所有源精灵体（多色 4-连通前景分量）。
3. 将每个精灵无旋转平移到孔洞内的某个位置，使得：(a) 所有精灵像素恰好覆盖所有孔洞像素（精确拼合），(b) 任意两个精灵若有像素 4-邻接，则接触处两像素须颜色相同或至少一个为蓝(1)（蓝色为通配色，与任何颜色兼容）。
4. 擦除精灵的原始位置。输出中孔洞被精灵填满，大型蓝色对象和背景不变。

**关键洞察**：面积精确覆盖产生有限候选方案，但仅凭面积可能有多解——边缘颜色匹配（以蓝为通配）作为第二层约束将解缩减为唯一。求解者必须同时考虑几何拼合和颜色兼容性两个维度。

## 新题 8：标记像素密度决定局部像素放大倍率

**组合逻辑**：[计数](创新：统计局部区域内标记密度) → [像素放大](创新：放大倍率不固定而由局部计数决定) + [擦除]

**来源原语**：像素放大/pixel_upscale(9172f3a0), 每像素扩展为色块/each_pixel_expanded_to_block(9172f3a0), 逐像素映射/per_pixel_mapping(9172f3a0), 计数/counting(58490d8a), 标记像素/marker_pixel(32597951), 包围框内部/inside_bbox(32597951), 稀疏标记框定高亮/sparse_marker_highlight(32597951), 擦除/erase(184a9768)

**依赖链**：确定前景图案的包围框 → 计数框内标记像素数量 N → N 成为放大倍率 → 将图案每像素扩展为 NxN 色块。删除计数则倍率未知（不同示例中倍率不同）；删除包围框识别则不知在哪里计数。

前景图案内散布的标记像素数量决定该图案的像素放大倍率，输出为放大后的图案（标记被擦除）。

**输入结构**：黑(0)背景，约 12x12 网格。网格中央有一个小型前景图案（3x3 或 4x4 的区域，由红(2)和蓝(1)像素组成非对称图形，部分像素为黑色背景）。图案的包围框内散布有 2~4 个绿(3)标记像素，位于图案中原本为黑色背景的格子上。图案外无任何前景像素。生成约束：标记像素数 N 满足图案尺寸 * N 不超过 20（保证输出网格合理大小）；标记像素仅出现在图案包围框内的黑色背景格上，不与图案前景像素重叠。

**规则**：
1. 找到所有非黑非绿像素构成的前景图案，计算其最小包围框。
2. 统计包围框内绿(3)标记像素的数量 N。
3. 将包围框内的图案（忽略绿色标记，将绿色标记位置视为黑色背景）进行 N 倍像素放大：包围框内的每个格子（含前景色和黑色背景）扩展为 NxN 的色块。
4. 输出为放大后的网格（尺寸 = 原包围框尺寸 * N），不包含任何绿色像素。

**关键洞察**：放大倍率是隐式编码在输入中的——标记像素的"数量"而非"位置"承载了关键信息。不同示例中标记数量不同导致放大倍率不同，必须对比多个示例才能归纳出"计数即倍率"的规则。
