## 新题 1：边界色少数派决定腔体填充

**组合逻辑**：[counting](创新：对象从"内部面积"变为"边界颜色频率") + [flood_fill](创新：填充色不来自种子自身，而来自频率分析结果) + [enclosed_cavity](已有) + [seed_pixel → boundary_anchor](创新：种子从"颜色提供者"变为"标记哪个腔体需要处理")

**来源原语**：counting (868de0fa), flood_fill + enclosed_cavity + seed_pixel + connectivity_reachable (8b7bacbf), endpoint_traversal (5792cb4d)

**依赖链**：灰色标记像素指定需要填充的腔体 → 分析该腔体边界上各颜色的像素数 → 频率最低的颜色成为填充色 → 洪泛填充腔体。标记像素只负责"选哪个腔体"，填充色由边界的统计属性决定，两步缺一不可。

识别被灰色标记的封闭腔体，统计其边界上各非灰色颜色的出现频率，用频率最低的边界色填充该腔体。

**输入结构**：黑(0)背景网格，约 15x15。网格上有由多种颜色绘制的 1 像素宽线条画（使用 {蓝(1), 红(2), 绿(3), 黄(4)} 中的 2-3 种颜色），线条均为 4-连通，相互连接形成若干完全封闭的腔体（3-5 个）。每个腔体是被非黑像素完全 4-包围的黑(0)连通区域。其中 2-3 个腔体的内部恰好有一个灰(5)像素（标记像素），其余腔体内部无标记（作为干扰项保持空白）。每个被标记腔体的边界至少使用 2 种非灰颜色，且这些颜色的像素数各不相同（无并列）。不同被标记腔体的最少频次边界色可以相同也可以不同。

**规则**：
1. 识别所有封闭腔体：找到所有被非黑像素完全 4-包围的极大黑(0) 4-连通区域。
2. 对每个腔体，检查其内部是否包含灰(5)标记像素。若无标记，跳过该腔体（保持空白）。
3. 对有标记的腔体，收集其边界（所有与该腔体至少 4-相邻的非黑像素）。
4. 统计边界上每种非灰颜色的像素数量。
5. 选出像素数最少的那种颜色作为填充色。
6. 用填充色洪泛填充该腔体的所有黑(0)像素（灰标记像素也被填充色覆盖）。
7. 所有边界像素（线条画）保持不变。各腔体独立处理，互不影响。

**关键洞察**：灰色标记只负责"哪些腔体要处理"，不决定填充颜色；填充颜色源自边界色的频率统计中的少数派，需对比多个腔体才能归纳出"频率最低"这条规则。

## 新题 2：标记定向平移后跨轴镜像

**组合逻辑**：[move](创新：标记不移动自身，而指挥另一个对象移动) + [mirror](创新：镜像轴由移动目的地隐式定义) + [recolor](已有：镜像副本变色) + [color_matches_side](创新：从"颜色匹配边框侧"扩展为"颜色同时编码平移方向和镜像轴")

**来源原语**：move + color_matches_side + color_determines_side (d687bc17), mirror + recolor + marker_pixel + adjacency (2bcee788), frame (d687bc17)

**依赖链**：标记像素颜色匹配某一边框侧 → 该侧决定图案的平移方向 → 图案平移至该侧内壁 → 平移后的位置定义出与该侧平行的镜像轴 → 图案跨轴镜像产生副本 → 副本重涂色。平移目的地和镜像轴是同一个几何决定的两个面，标记颜色一次性编码了两个操作的参数。

根据标记像素颜色找到匹配的边框侧，将图案平移至该侧内壁，再跨平行轴镜像产生变色副本。

**输入结构**：黑(0)背景网格，约 12x12。最外圈是 1 像素宽的矩形边框，四侧各用一种不同颜色：上红(2)、下蓝(1)、左绿(3)、右黄(4)。四角像素为黑(0)。边框围成的内部区域为黑(0)背景。内部有一个由灰(5)像素组成的小型 4-连通图形（3-6 像素，无孔洞，不与边框接触，形状各示例不同），以及一个与该图形 4-相邻的单像素标记，标记颜色为四种边框侧颜色之一。生成约束：图案加上平移距离和镜像副本后不超出边框内部空间；标记像素只有一个。

**规则**：
1. 识别灰(5)图形和与之 4-相邻的彩色标记像素。
2. 标记颜色匹配某边框侧（红(2)→上、蓝(1)→下、绿(3)→左、黄(4)→右），确定目标侧。
3. 将灰色图形整体平移至目标侧内壁：若目标侧为上，则图形整体上移使其最高行紧贴上边框内壁（第 1 行）；若为左，则整体左移使最左列紧贴左边框内壁（第 1 列）；下、右类似。保持图形的形状和相对坐标不变。
4. 擦除标记像素（变为黑(0)）。
5. 以目标侧的平行中轴为镜像轴（例如目标侧为上/下时，镜像轴是内部区域的水平中线；目标侧为左/右时，镜像轴是垂直中线），将平移后的灰色图形镜像到轴的另一侧。
6. 镜像副本重涂色为橙(7)。原始灰色图形保持灰(5)不变。
7. 若镜像后某像素落在边框上或超出网格，该像素舍弃。

**关键洞察**：标记颜色一次编码两个操作参数——平移方向（匹配哪一侧）和镜像轴（与该侧平行的中轴），但这两个参数在视觉上表现为一个颜色选择，需要多个示例才能拆解出完整规则。

## 新题 3：杯体填充奇偶溢出生长

**组合逻辑**：[fill](已有：杯体内标记色填充) + [counting](创新：计数对象从"空心矩形面积"变为"已填充像素数") + [parity_sets_fill → parity_triggers_growth](创新：奇偶不再决定填充色，而决定是否触发生长) + [grow](创新：生长起点从"种子行"变为"杯底边缘"，生长形态从平行行变为逐行缩窄三角滴落)

**来源原语**：fill + cup_outline + marker_color_sets_fill + cap_layer_added (444801d8), counting + parity_sets_fill (868de0fa), grow + alternating_color (af726779)

**依赖链**：标记色填充杯体 → 计数填充像素 → 奇偶判断 → 偶数则停止（只保留填充和封盖），奇数则从杯底向下生长交替色三角滴落。计数结果决定是否触发生长——不填充就无法计数，不计数就不知道是否生长。

用标记色填充蓝色杯体并加封盖层，然后统计各杯体填充面积：偶数面积的杯体到此为止，奇数面积的杯体从底部向下生长逐行缩窄的交替色三角滴。

**输入结构**：黑(0)背景网格，约 16x20。网格中有 2-4 个蓝(1)像素组成的杯状轮廓：每个杯由一条 U 形蓝(1)连通曲线构成，开口朝上，内部为黑(0)空腔。各杯大小不同（宽 3-6 像素，高 3-5 像素），水平排列且互不接触。每个杯内部恰好有一个非黑、非蓝的单色标记像素（使用 {红(2), 绿(3), 黄(4), 灰(5)} 中不重复的颜色）。杯与网格底边之间留有足够空间（至少 5 行）。生成约束：各杯的内部像素数（不含蓝边框像素）各不相同，且至少一个为偶数、至少一个为奇数。

**规则**：
1. 对每个蓝(1)杯状轮廓，找到其内部的标记像素颜色 C。
2. 用颜色 C 填充杯体内部所有黑(0)像素（标记像素本身已经是 C，保持不变）。
3. 在杯口正上方一行，将与杯口等宽的像素段涂为颜色 C（封盖层）。
4. 计算该杯体内部被填充为 C 的像素总数（不含封盖层、不含蓝边框）。
5. 若总数为偶数：该杯体处理完毕，无额外操作。
6. 若总数为奇数：从杯体蓝(1)底边正下方一行开始，向下生长交替色行。第一行用品红(6)，第二行用橙(7)，依次交替。每一行比上一行左右各缩进 1 像素。当行宽缩至 0 像素或下一行超出网格底边时停止。
7. 各杯体独立处理。蓝色轮廓保持不变。

**关键洞察**：封盖层的生成是无条件的（所有杯都加），但滴落生长是有条件的（仅奇数面积触发）。需要对比偶数面积杯（无滴落）和奇数面积杯（有滴落）的示例才能发现奇偶这条隐蔽规则。

## 新题 4：双面板空交集生成定向生长种子

**组合逻辑**：[logical_operation](已有：双面板逐格比较) + [intersect_empty → seed_generation](创新："双空交集"从最终输出变为生长的种子来源) + [grow](创新：生长方向由控制行标记编码，而非固有的向下生长) + [crop](已有：裁去分隔和控制结构)

**来源原语**：logical_operation + cell_comparison + separator_column + equal_width_panel + intersect_empty_fill (f2829549), grow + alternating_color (af726779), crop + control_row + marker_is_shift (79cce52d)

**依赖链**：控制行提供方向参数 → 裁去控制行和分隔列 → 双面板逐格比较找到双空像素 → 双空像素成为生长种子 → 种子沿控制行指定方向生长至遇到前景像素。控制行参数决定生长行为，面板交集决定生长起点，两者汇聚于生长操作。

裁去控制行和分隔列，在左右面板的空白交集位置放置种子，种子沿控制行标记编码的方向生长至碰到前景像素。

**输入结构**：黑(0)背景网格，约 13x15（奇数列宽以容纳分隔列）。最顶行为控制行：整行为灰(5)底色，其中一个像素为红(2)标记。红(2)标记的列位置编码生长方向——位于控制行左四分之一区域表示向左生长，右四分之一表示向右，中左四分之一表示向上，中右四分之一表示向下。第 2 行起，网格正中列为 1 像素宽的灰(5)分隔列，将剩余区域分为等宽的左面板和右面板。两面板各自包含若干非黑前景像素（左面板用蓝(1)，右面板用黄(4)），形成不同的稀疏图案。生成约束：两面板的共同空白像素（双空交集）至少 3 个且不超过 8 个；沿指定方向生长时各种子的生长路径互不冲突（不交叉也不重叠）。

**规则**：
1. 读取控制行中红(2)标记的列位置 c。设控制行总宽为 W。若 c < W/4，生长方向为向左；若 W/4 <= c < W/2，方向为向上；若 W/2 <= c < 3W/4，方向为向下；若 c >= 3W/4，方向为向右。
2. 移除控制行（第 0 行）和分隔列，得到左面板和右面板。
3. 将左面板和右面板按相同坐标逐格比较：若某位置在两个面板中均为黑(0)（背景），则在输出网格对应位置标记为绿(3)种子像素。
4. 保留两个面板中所有非黑前景像素（蓝(1)和黄(4)保留在原位）。
5. 从每个绿(3)种子像素出发，沿步骤 1 确定的方向逐像素延伸，将路径上的黑(0)背景像素涂为绿(3)，直到碰到非黑像素（蓝(1)、黄(4)或另一条绿(3)生长路径的像素）或到达网格边缘时停止（不覆盖终点处的非黑像素）。
6. 输出网格尺寸 = 去掉控制行和分隔列后的面板并排尺寸（高度 = 原高度 - 1，宽度 = 原宽度 - 1）。

**关键洞察**：控制行标记不是偏移量（不像 79cce52d 那样编码位移），而是方向编码器——其位置落在四个区间中的哪一个决定了生长方向。双空交集也不是最终输出（不像 f2829549），而是中间产物——生长的起点。两个独立来源（控制行 + 面板交集）的信息汇聚在生长操作上。

## 新题 5：端点定侧的半字形镜像补全

**组合逻辑**：[erase](已有) + [reconstruct](创新：模板是半字形而非完整字形) + [mirror](创新：镜像不是独立操作，而是补全不完整重建的必要步骤) + [endpoint_marker](创新：标记所在列决定半字形放置侧和镜像方向)

**来源原语**：erase + reconstruct + frame_bar + endpoint_marker + glyph_template + color_to_shape + anchor_position (98c475bf), mirror + mirror_toward_marker_recolor (2bcee788)

**依赖链**：参考半字形定义模板 → 擦除参考字形 → 端点标记对的列位置（左列 / 右列 / 两列都有）决定三件事：（a）用哪一半作为模板，（b）放置在哪一侧，（c）是否需要镜像补全。重建和镜像不是独立步骤，而是由标记位置统一控制的一体化补全流程。

擦除参考半字形，根据各端点标记对所在的列位置，在锚定行重建半字形并镜像补全为完整对称字形。

**输入结构**：网格为 20 行高、约 12 列宽。最左列和最右列为同色（栗(9)）的满高竖条边框。边框之间为黑(0)背景的内部区域，内部区域列宽为 W（偶数，约 10）。内部区域包含：一个由颜色 A（如蓝(1)）绘制的半字形参考模板——该字形仅占据内部左半侧（第 0 列到第 W/2-1 列）或仅占据右半侧（第 W/2 列到第 W-1 列），关于内部垂直中轴不对称。另有 1-2 种其他颜色（如红(2)、绿(3)）的端点标记对：每个标记对由两个同色像素组成，位于同一行，分别处于内部区域的第一列和/或最后一列。标记对有三种配置：（i）两个标记均在内部左侧第一列；（ii）两个标记均在内部右侧最后一列；（iii）一个在第一列、一个在最后一列。生成约束：不同颜色的标记对所在行互不重叠；重建后的字形互不重叠。

**规则**：
1. 记录参考半字形（颜色 A）的形状和它占据的侧（左半或右半）。
2. 擦除参考半字形（所有颜色 A 的像素变为黑(0)）。
3. 对每个端点标记对（颜色 B），检查其两个像素的列位置：
   - 若两个标记均在内部第一列（左侧）：在标记所在行为锚点，将参考半字形绘制在左半侧（使用颜色 B），然后将其沿内部垂直中轴向右镜像，得到完整对称字形（镜像部分也使用颜色 B）。
   - 若两个标记均在内部最后一列（右侧）：在标记所在行为锚点，将参考半字形绘制在右半侧（使用颜色 B），然后向左镜像补全。
   - 若标记分处两侧（一个在第一列、一个在最后一列）：在标记所在行为锚点，直接绘制参考半字形在其原始侧（使用颜色 B），再镜像到另一侧（也用颜色 B），等价于对称放置。
4. 锚点定位规则：将参考半字形的横向中心行对齐到标记像素所在行。
5. 保留栗(9)边框不变。端点标记像素被重建的字形覆盖。

**关键洞察**：标记对的列配置（双左 / 双右 / 一左一右）不只是位置信息，而是隐式地编码了"从哪侧开始重建"和"向哪侧镜像"。必须对比三种不同配置的示例才能完整归纳规则。模板本身是不完整的半字形——这一点只有在看到输出总是对称的之后才能推断。

## 新题 6：对角色对矩形作为生长屏障

**组合逻辑**：[pair_defines_rect + fill](已有：同色对定义矩形并填充) + [grow](创新：生长被已填充矩形的边界阻挡) + [alternating_color](已有：交替色) + [containment → barrier](创新："包含"关系反转为"排斥/阻挡"——矩形不是被填充的目标，而是阻止其他操作进入的墙)

**来源原语**：fill + diagonal_pairing + pair_defines_rect (56ff96f3), grow + alternating_color + adjacent_gap (af726779), containment (868de0fa)

**依赖链**：同色像素对定义矩形 → 矩形被填充为该色 → 绿色种子开始四方向生长 → 生长在矩形边界处被阻挡。两个操作（填充矩形、种子生长）同时作用于同一网格，矩形的空间位置直接塑造了生长区域的形状——去掉矩形则生长无界，去掉生长则只有矩形。

同色像素对标记矩形对角并填充为该色，同时绿色种子向四方向交替色生长，生长在矩形边界处停止。

**输入结构**：黑(0)背景网格，约 14x14。网格中有 2-3 种颜色（从 {蓝(1), 红(2), 黄(4)} 中选取），每种颜色恰好出现 2 个孤立像素，位于不同行不同列。另有 1-2 个绿(3)的孤立种子像素。所有像素互不相邻（曼哈顿距离 >= 2）。生成约束：各色对定义的矩形互不重叠；种子像素不在任何矩形区域内；矩形不紧贴网格边缘（至少留 1 像素间距）。

**规则**：
1. 对每种出现恰好 2 次的颜色 C，取其两个像素为对角，填充以它们为对角的轴对齐矩形（包含边界）为颜色 C。
2. 对每个绿(3)种子像素，同时向上、下、左、右四个方向逐步生长。第 1 步涂品红(6)，第 2 步涂橙(7)，第 3 步涂品红(6)，以此类推交替。
3. 生长在某方向上遇到以下情况时，该方向停止（其他方向可继续）：遇到已填充矩形的边界像素（颜色为某个 C），或到达网格边缘。停止时不覆盖终点处的矩形像素或超出网格。
4. 若两个种子的生长路径在某像素相遇，先到达的保留（按步数，步数相同则按种子从左到右、从上到下的顺序优先）。
5. 完成后，擦除绿(3)种子像素本身（变为黑(0)）。

**关键洞察**：同色像素对构建的填充矩形不是谜题的输出重点——它们充当生长的物理屏障，使得每个种子的生长区域呈现被矩形切割后的不规则形状。矩形的位置和种子的位置共同决定了最终图案，两者缺一不可。

## 新题 7：反转掩码印章叠加于色对锚点

**组合逻辑**：[invert + paired_color_mapping](创新：反转结果不是最终输出，而是生成印章模板) + [diagonal_pairing + pair_defines_rect](创新：色对不仅定义矩形填充区，还提供印章放置锚点) + [stamp_overlay](创新：印章内容来自反转运算而非目录区域) + 层叠冲突解决

**来源原语**：invert + paired_color_mapping (6ea4a07e), fill + diagonal_pairing + pair_defines_rect (56ff96f3), stamp_overlay + template_matching (3ed85e70)

**依赖链**：小掩码区域经反转+配对色映射生成印章模板 → 同色像素对定义矩形并计算中心点 → 印章在中心点处盖印 → 矩形填充在印章下方作为底色。反转生成内容（印章模板），色对生成位置（锚点）和底色（矩形填充），三者汇聚为最终分层输出。

用反转和配对色映射将小掩码变为印章模板，在各同色对矩形的中心叠印该模板，矩形自身填充为底层。

**输入结构**：黑(0)背景网格，约 14x14。左上角有一个 3x3 的子区域，用栗(9)单像素边框圈出：框内为 3x3 的单色掩码（使用灰(5)、绿(3)或青(8)中的一种作为前景色，黑(0)为背景），掩码中前景像素 2-4 个，形成简单图案。栗(9)框外、网格其余区域中有 2-3 种颜色（从 {蓝(1), 红(2), 黄(4)} 中选取），每种颜色恰好出现 2 个孤立像素。各色对定义的矩形互不重叠，且不与左上角掩码框重叠。掩码框占据网格第 0-4 行、第 0-4 列（含框线）。

**规则**：
1. 提取栗(9)框内的 3x3 掩码。对掩码进行反转：前景像素变为黑(0)，黑(0)背景像素变为配对色。配对色映射规则：灰(5)→黄(4)，绿(3)→蓝(1)，青(8)→红(2)。反转后的 3x3 图案即为印章模板。
2. 擦除栗(9)框及其内容（框区域全部变为黑(0)）。
3. 对每种出现恰好 2 次的颜色 C（在框外区域），取两个像素的轴对齐矩形。填充该矩形为颜色 C。
4. 计算每个矩形的中心位置（行中心 = (r1+r2)/2 向下取整，列中心 = (c1+c2)/2 向下取整）。
5. 将印章模板以中心对齐方式盖印在每个矩形中心：印章的中心像素 (1,1) 对齐到矩形中心。印章中的黑(0)像素为透明（不覆盖），非黑像素覆盖底层。
6. 印章叠印顺序：按矩形面积从大到小处理。面积相同时，按矩形左上角从上到下、从左到右处理。后印的覆盖先印的。
7. 超出网格的印章像素舍弃。

**关键洞察**：配对色映射（灰→黄、绿→蓝、青→红）是一条需要对比多个示例才能归纳的隐蔽规则，它决定了印章的颜色。同色像素对既提供了矩形底色又提供了印章锚点，这两个角色在任何参考题中都不同时出现。

## 新题 8：边框内路径反转驱动腔体着色

**组合逻辑**：[reverse_color_seq](创新：反转不只是视觉变换，其结果的端点色成为另一操作的输入参数) + [flood_fill](创新：填充色不预设，由路径反转后的端点色动态决定) + [rectangular_frame + border_encloses_content](创新：边框不是裁剪目标，而是路径走向判定的参考系)

**来源原语**：reverse_color_seq + one_pixel_path + endpoint_pixel + endpoint_traversal + shape_fixed_reversed (5792cb4d), flood_fill + enclosed_region (868de0fa), rectangular_frame + border_encloses_content (1a6449f1)

**依赖链**：识别边框和内部路径 → 根据端点与边框的位置关系确定行走起点 → 反转路径颜色序列 → 反转后的起点处颜色（即原终点色）成为内部空白区域的填充色。反转操作提取了信息（远端颜色），这一信息通过端点传递给填充操作。

在各矩形边框内找到多色路径，从离边框左上角最近的端点开始行走并反转色序，然后用反转后起点处的新颜色填充边框内的剩余空白。

**输入结构**：黑(0)背景网格，约 14x16。网格中有 2-3 个不重叠、不嵌套的完整矩形边框（每个边框用一种单色绘制，从 {灰(5), 栗(9)} 中选取，1 像素宽）。每个边框的内部包含：一条由多种前景色（从 {蓝(1), 红(2), 绿(3), 黄(4), 品红(6), 橙(7)} 中选取 3-5 种）组成的 4-连通、1 像素宽路径（无分支），路径有恰好 2 个端点，其余为黑(0)空白。路径不接触边框像素（与边框至少间隔 1 像素）。路径的两个端点颜色不同。生成约束：每个边框的内部面积至少 4x4；路径占内部面积的 30%-60%。

**规则**：
1. 识别每个完整矩形边框及其内部区域。
2. 在每个边框的内部找到唯一的 4-连通单像素宽路径。
3. 找到路径的两个端点。选择离边框左上角（内部区域的左上角）曼哈顿距离更近的端点作为行走起点。若距离相同，选行号更小的；仍相同则选列号更小的。
4. 从起点到终点行走路径，收集颜色序列。将颜色序列反转后重新涂在路径上（路径的几何形状不变，仅颜色序列翻转）。
5. 反转完成后，起点处的新颜色 = 原终点处的颜色。将该颜色用于洪泛填充该边框内部所有剩余黑(0)像素。
6. 边框像素保持不变。各边框独立处理。

**关键洞察**：路径色序反转不是最终目的——它是一种"信息搬运"机制：将远端端点的颜色搬运到近端端点，而这个搬运来的颜色恰好成为内部空白区域的填充色。只有理解了反转和填充之间的因果链，才能正确求解。

## 新题 9：压缩分区后连接同色对的正交路由

**组合逻辑**：[downscale + rectangular_partition](已有：分区压缩) + [line_drawing](创新：路由对象不是预设标记像素，而是压缩后涌现出的同色像素对) + [diagonal_pairing → compressed_pairing](创新："同色对"概念从原始像素扩展到压缩表示中的分区色) + [horizontal_then_vertical](已有：先横后纵路由)

**来源原语**：downscale + rectangular_partition + grid_sampling + each_partition_reduced_to_one_pixel (90c28cc7), line_drawing + orthogonal_path + horizontal_then_vertical (0e671a1a), diagonal_pairing + pair_defines_rect (56ff96f3, 概念层面：同色配对)

**依赖链**：分区网格压缩为小网格 → 在小网格中发现恰好出现 2 次的颜色 → 这些色对成为路由端点 → 正交路由连接各端点对。压缩改变了空间布局，路由在压缩后的新空间中进行——不压缩则无法得到正确的路由端点位置。

将彩色分区网格压缩为每分区一像素，在压缩结果中找到恰好出现两次的颜色对，用灰色正交路径连接每对。

**输入结构**：黑(0)背景网格，约 15x15。网格的中央区域（约 12x12）为一个由矩形分区组成的马赛克：每个分区是一个单色矩形块（使用 {蓝(1), 红(2), 绿(3), 黄(4), 品红(6), 橙(7), 青(8)} 中的颜色），分区大小不一（宽 2-4 像素，高 2-4 像素），紧密排列无间隙。马赛克包含约 4x4 到 6x6 个分区。其中恰好有 2-3 种颜色各出现在 2 个分区中（即压缩后这些颜色各出现 2 次），其余颜色各出现 1 次或 3 次以上。马赛克外围为黑(0)背景。生成约束：各色对在压缩后的小网格中不处于同一行同一列（路径非退化）；不同色对的路由路径互不交叉。

**规则**：
1. 检测马赛克区域中的所有矩形分区。收集每个分区的左上角行列坐标（排序后的唯一行集合和列集合即分区网格线）。
2. 将马赛克压缩为小网格：每个分区变为一个像素，颜色取该分区的颜色（采样左上角即可）。
3. 在小网格中，找出恰好出现 2 次的所有颜色。
4. 对每种出现 2 次的颜色 C，连接其两个像素：从第一个像素（行号较小者；行号相同则列号较小者）出发，先水平移动到第二个像素的列，再垂直移动到第二个像素的行。路径上所有中间像素（不含两端的 C 像素）涂为灰(5)。
5. 若路径中间经过一个已有颜色的像素（非黑非灰），跳过该像素不覆盖（路径在该处断开但视觉上仍可理解为连通）。
6. 出现 1 次或 3 次以上的颜色不参与路由。
7. 输出仅为压缩后的小网格（带路由线），不包含原始大网格。

**关键洞察**：路由端点不是预设在输入中的标记像素，而是通过压缩操作从分区颜色分布中涌现出来的——只有压缩后才能看出哪些颜色恰好出现两次。压缩不只是简化显示，它重新定义了"哪些对象要连接"。

## 新题 10：色匹配区域面积驱动循环位移

**组合逻辑**：[cyclic_roll](创新：位移量不来自控制行/列标记位置，而来自一个区域的面积值) + [counting](创新：计数对象从"奇偶判定"变为"位移参数提取") + [color_matches_side → color_matches_region](创新："颜色匹配"从匹配边框侧扩展为匹配任意区域，标记色选定参数源区域)

**来源原语**：cyclic_roll + marker_is_shift (79cce52d), counting + parity_sets_fill (868de0fa, 概念层面：面积计算), color_matches_side (d687bc17, 概念层面：颜色匹配选择), enclosed_region (868de0fa)

**依赖链**：标记像素颜色匹配某个封闭区域 → 计算该区域面积 → 面积值取模后成为循环位移量 → 对整个网格执行位移。颜色匹配回答"哪个区域的面积？"，计数回答"面积是多少？"，位移将面积转化为空间变换——三步形成信息提取链。

找到颜色与背景标记匹配的封闭区域，用其面积对网格尺寸取模得到循环位移量，据此位移全网格。

**输入结构**：黑(0)背景网格，约 11x11。网格中有 3-4 个由不同颜色（从 {蓝(1), 红(2), 绿(3), 黄(4)} 中选取）绘制的实心封闭区域（4-连通单色连通分量，每个 4-12 像素，形状不规则，各示例中同类区域形状不同）。区域间互不接触（间隔至少 1 像素）。网格最底行的最右侧有一个品红(6)的单像素标记。该标记的左侧紧邻一个像素，其颜色与网格中某个封闭区域的颜色相同（如该像素为红(2)，则网格中存在一个红(2)区域）。生成约束：被指定区域的面积对网格宽度取模后不为 0，对网格高度取模后也不为 0；各区域面积互不相同。

**规则**：
1. 在网格最底行找到品红(6)标记像素。读取标记左侧紧邻像素的颜色 C。
2. 在网格中找到颜色为 C 的 4-连通封闭区域，计算其面积 A（像素数）。
3. 设网格宽度为 W、高度为 H。
4. 将网格所有像素（包括所有区域和背景，但不包括最底行的标记结构）整体循环右移 A mod W 列。
5. 再将结果整体循环下移 A mod H 行。
6. 移除最底行中的品红(6)标记像素及其左邻的颜色指示像素（均变为黑(0)）。
7. 输出循环位移后的网格。

**关键洞察**：位移量不是直接读取的标记位置，而是通过"颜色匹配→面积计算→取模"的间接推理链得到的。标记像素本身不携带位移信息——它只是一个指针，指向某个区域，而那个区域的几何属性才编码了变换参数。需要多个示例才能归纳出面积→位移量的映射规则。
