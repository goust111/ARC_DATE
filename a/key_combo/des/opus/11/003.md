## 新题 1：对称性筛选决定滑动方向与重涂色

**组合逻辑**：[对称/symmetry](创新：从选择输出物变为决定是否重涂色) + [重涂色/recolor](创新：对称性判断结果驱动颜色翻转) + [滑动/slide](已有) + [碰撞停止/collision_stop](已有)

**来源原语**：对称/symmetry、对称图案选取/symmetric_selected（P17 d56f2372）；滑动/translate、墙壁列/wall_column、同色物体朝同色墙/same_color_wall、碰撞停止/collision_stop、近者优先不重叠/nearest_first（P10 f0100645）；重涂色/recolor（P7 b94a9452、P13 7d1f7ee8）；精灵体/sprite（P12 39a8645d）

**依赖链**：对称性测试决定每个精灵体是否被重涂色 → 重涂色改变精灵体颜色 → 颜色决定滑动方向（匹配哪面墙） → 滑动顺序和碰撞决定最终位置。删除对称测试则无法确定哪些精灵体要变色；删除重涂色则所有精灵体保持原色、仅有一面墙有目标；删除滑动则无空间变换。

在一个有双色墙壁列的网格中，对每个小精灵体做对称性判断：对称者保持原色滑向同色墙，不对称者互换为另一面墙的颜色后滑向该墙。

**输入结构**：约 18x18 的黑(0)背景网格。左列全为蓝(1)，右列全为红(2)，作为两面墙壁列。网格内部散布 4~6 个单色小精灵体（每个为 4-连通、3~6 像素、边界框不超过 3x3 的不规则图形），颜色为蓝(1)或红(2)。每个精灵体互不相邻（边界框间至少间隔 1 列背景）。生成约束：蓝精灵体和红精灵体各至少 2 个；其中至少各有一个具有垂直镜像对称性、至少各有一个不具有垂直镜像对称性。

**规则**：
1. 识别左列蓝(1)墙和右列红(2)墙。
2. 对每个精灵体，裁剪到其边界框，判断该裁剪图案是否关于垂直中轴左右镜像对称。
3. 对称的精灵体保持原色不变。不对称的精灵体做双色互换：蓝(1)像素全部变为红(2)，红(2)像素全部变为蓝(1)。
4. 互换后，所有精灵体按照距离其目标墙的远近排序（近者优先）。目标墙 = 与精灵体当前颜色相同的墙（蓝精灵体目标为左墙，红精灵体目标为右墙）。
5. 按上述顺序依次将每个精灵体水平滑向其目标墙，保持行位置不变，直到精灵体的最近像素紧贴墙壁列或紧贴已经抵达的另一个精灵体，不可重叠。
6. 两面墙壁列保持不变。

**关键洞察**：对称性不是用来选择"输出哪个精灵体"，而是用来反转精灵体颜色——这改变了它的滑动方向，使得原本应该向左滑的精灵体在不对称时反而向右滑。需要对比多个示例才能发现"不对称 → 互换颜色"这一隐蔽规则。

## 新题 2：分隔格内标记计数驱动印章重复次数

**组合逻辑**：[分隔栅格/divider_grid](已有) + [计数/count](创新：在分隔格单元内计数标记) → [印章覆盖/stamp](创新：计数结果决定印章重复次数) + [同色配对/same_color_pairing](创新：标记颜色决定印章颜色)

**来源原语**：分隔栅格/divider_grid、沿行列填充间隙/fill_gap_along_row_col（P1 06df4c85）；计数/count、计数映射尺寸/count_maps_to_size（P14 878187ab）；印章覆盖/stamp_repeat（P8 985ae207）；精灵体/sprite、形状相同/shape_identity（P12 39a8645d）；同色配对/same_color_pairing（P1 06df4c85）

**依赖链**：分隔栅格定义了计数的空间单元边界 → 每个单元内标记像素的数量和颜色被统计 → 计数结果决定在该单元中印章几次 → 标记颜色决定印章用什么颜色 → 单元的相对位置（与原型单元同行 vs 同列）决定印章排列方向。删除分隔栅格则无法确定计数范围和排列空间；删除计数则无法确定重复次数；删除印章则无输出内容。

在分隔栅格中，根据每个单元格内标记像素的数量和颜色，将原型精灵体印章相应次数地复制到该单元格中。

**输入结构**：约 15x15 的黑(0)背景网格。灰(5)色的完整水平线和垂直线将网格分成 3x3 共 9 个矩形单元格（每个单元格内部约 3x3 至 4x4 像素）。其中一个单元格（固定在左上角位置）包含一个单色原型精灵体（4-连通、3~5 像素的不规则图形，颜色为绿(3)），该精灵体占据单元格内部分像素。其余单元格中，部分包含若干同色标记像素（单个像素，不相邻），颜色为蓝(1)、红(2)或黄(4)中的一种——同一单元格内所有标记像素颜色相同。部分单元格为空（仅有背景）。生成约束：含标记的单元格至少 3 个；每个含标记单元格的标记数量在 1~3 之间；原型精灵体可放入任一单元格内部（即精灵体边界框不超过单元格内部尺寸）。

**规则**：
1. 识别灰(5)分隔线确定的 3x3 单元格布局，以及左上角单元格中的原型精灵体形状。
2. 对每个非原型单元格，统计其中标记像素的数量 N 和颜色 C。空单元格（N=0）在输出中保持为背景。
3. 在每个含标记的单元格中，用颜色 C 绘制原型精灵体的 N 个副本，排列规则如下：
   - 若该单元格与原型单元格在同一行：N 个副本沿垂直方向依次排列，第一个副本的左上角对齐单元格内部左上角，相邻副本紧贴（无间隔）。
   - 若该单元格与原型单元格在同一列：N 个副本沿水平方向依次排列，第一个副本的左上角对齐单元格内部左上角，相邻副本紧贴。
   - 若既不同行也不同列：N 个副本沿对角线方向排列（每个副本相对前一个向右下偏移 1 像素）。
4. 超出单元格边界的副本像素被截断丢弃。
5. 原型单元格在输出中保持原样（精灵体保留绿(3)色）。灰(5)分隔线保持不变。

**关键洞察**：分隔栅格同时承担三重角色——划定计数边界、提供排列空间、通过相对位置编码排列方向。需要对比多个示例才能归纳出"同行排纵向、同列排横向、其余排对角"的方向规则。

## 新题 3：边界投射选中外层矩形框并触发包含层级重涂色

**组合逻辑**：[投射/project](创新：从命中目标对象变为命中矩形边框) + [严格包含/strict_containment](已有) → [重涂色/recolor](创新：投射命中的边框颜色向内层传播) + [碰撞阻挡/collision_blocking](创新：近距优先级解决多投射冲突)

**来源原语**：投射/project、画布边界/canvas_boundary、边界像素投射目标/border_projected_to_target、碰撞阻挡/collision_blocking（P15 1f642eb9）；严格包含/strict_containment、矩形边框/rectangular_perimeter、最外层颜色继承/outermost_color_inheritance、重涂色/recolor（P13 7d1f7ee8）；标记像素/marker_pixel（多题）

**依赖链**：边界标记像素向内投射确定命中哪个矩形边框 → 命中的边框成为"着色根" → 该边框内部严格包含的所有矩形边框和非背景像素全部重涂为投射标记的颜色 → 多个投射命中同一边框时，投射距离更短的标记优先。删除投射则没有选择机制（不知道哪些边框要变色）；删除包含层级则变色不会传播到内层；删除距离优先级则多重投射时结果不确定。

将画布边界上的彩色标记像素向内投射，命中嵌套矩形框的最外层边框后，将该边框及其所有内层内容统一重涂为标记颜色。

**输入结构**：约 20x20 的黑(0)背景网格。网格中有 2~3 组嵌套矩形边框（每组为 1~3 层严格包含关系的单色矩形边框，每层颜色不同，颜色取自蓝(1)、红(2)、绿(3)、黄(4)、灰(5)）。各组矩形之间互不相交也互不包含。画布的四条边上散布 2~4 个单像素标记，颜色为橙(7)或品红(6)，每个标记沿其对应的行或列方向至少能直线到达一个矩形边框组的最外层边框（路径上无其他非背景障碍）。生成约束：每个最外层矩形边框至多被两个边界标记投射命中；至少有一个最外层边框被恰好两个不同颜色的标记命中（用于体现距离优先级规则）；至少有一个最外层边框不被任何标记命中。

**规则**：
1. 识别画布边界上的标记像素及其颜色。
2. 每个标记沿行或列向网格内部做直线投射（与 P15 相同：上边/下边标记垂直投射，左边/右边标记水平投射），直到碰到第一个非背景像素所属的矩形边框。该边框即为"命中边框"。
3. 对每个被命中的最外层矩形边框：若仅被一个标记命中，将该边框本身及其内部所有严格包含的矩形边框和非背景像素全部重涂为该标记的颜色。
4. 若同一最外层边框被两个标记命中：取投射距离（标记到命中点的曼哈顿距离）更短的标记的颜色执行上述重涂。若距离相等，取行号更小的标记优先（行号相同则取列号更小的）。
5. 未被任何标记命中的矩形边框组保持原色不变。
6. 标记像素本身保留在输出中，不被移除。

**关键洞察**：投射的功能不是将标记颜色"贴"到碰撞点（如 P15），而是将标记颜色"灌"入整个包含层级——单点投射触发了层级性传播。需要对比多个示例才能归纳距离优先级的冲突解决规则。

## 新题 4：镜像恢复遮挡区域后将恢复图案作为印章模板

**组合逻辑**：[镜像/mirror](已有) + [反射恢复遮挡/reflection_recovers](创新：恢复结果不是最终输出，而是中间模板) → [印章覆盖/stamp](已有) + [特定标记触发镜像/marker_triggers_mirror](已有，但作用于恢复出的模板)

**来源原语**：镜像/mirror、遮挡块/occluder、被遮区域/occluded_region、镜像对称/mirror_symmetry、反射恢复遮挡/reflection_recovers（P18 dc0a314f）；印章覆盖/stamp、标记像素/marker_pixel、颜色配对/color_pairing、标记色匹配目标位/marker_color_matches_dest、特定标记触发镜像/marker_triggers_mirror（P6 3e980e27）

**依赖链**：镜像对称恢复被遮挡的图案 → 恢复出的图案成为印章模板（这在 P18 中不存在——P18 的恢复结果就是最终输出） → 散落的绿(3)/红(2)标记像素指定印章目的地 → 绿(3)标记处原样印章、红(2)标记处左右镜像后印章。删除恢复步骤则无模板可印章；删除印章则恢复结果仅是一个局部碎片、无法生成完整输出；删除颜色触发镜像则无法区分两种印章方式。

利用场景的镜像对称性恢复被遮挡的图案，然后将该恢复图案作为印章模板，根据标记像素颜色决定是否镜像后印章到各个标记位置。

**输入结构**：约 20x20 的黑(0)背景网格。网格中存在一个关于垂直中轴镜像对称的多色图案（使用蓝(1)、黄(4)、灰(5)等颜色，占据网格中央约 10x10 区域）。图案内有一个 3x3 至 4x4 的实心栗(9)色正方形遮挡块，覆盖了部分图案。遮挡块不跨越对称轴（即其镜像位置处的图案完好可见）。在图案外部（距离图案边界至少 2 像素），散布 2~4 个孤立的单像素标记，颜色为绿(3)或红(2)。生成约束：绿(3)和红(2)标记各至少 1 个；标记之间间距足够大，使得以标记为中心放置恢复图案后各副本不重叠；遮挡块下方的图案至少包含 2 种颜色的像素。

**规则**：
1. 识别栗(9)色实心正方形为遮挡块。
2. 找到遮挡块边界框关于场景垂直中轴的镜像区域。将镜像区域的内容反射回遮挡块位置，恢复被遮挡的图案碎片。恢复出的碎片即为"印章模板"，尺寸等于遮挡块尺寸。
3. 清除整个对称图案和遮挡块，保留黑(0)背景和所有标记像素。
4. 对每个绿(3)标记像素：以该标记所在位置为模板的左上角，将印章模板原样绘制到画布上。
5. 对每个红(2)标记像素：将印章模板做左右镜像后，以该标记所在位置为模板的左上角绘制到画布上。
6. 标记像素本身被印章内容覆盖（若印章范围覆盖了标记位置）。若多个印章范围重叠（不应出现，由生成约束保证），后绘制的覆盖先绘制的。

**关键洞察**：遮挡恢复的目的不是修复画面——恢复出的碎片被从原场景中"取出"，变成了一个可复用的印章模板。需要对比多个示例才能发现"绿=原样、红=镜像"的颜色-操作映射。

## 新题 5：对角射线穿越精灵体的交叉计数决定填充颜色

**组合逻辑**：[射线延伸/ray_extend](创新：射线不被精灵体阻挡而是穿透) + [计数/count](创新：计数射线与精灵体的交叉次数) → [填充/fill](创新：交叉次数决定填充颜色)

**来源原语**：射线延伸/ray_extend、源像素/source_pixel、边缘起始/edge_origin、对角方向/diagonal_direction（P11 69889d6e）；计数/count（P12 39a8645d、P14 878187ab）；填充/fill（P1 06df4c85）；精灵体/sprite（P12 39a8645d）；障碍块/blocker（P11 69889d6e）

**依赖链**：底边源像素发射对角射线 → 射线穿透精灵体（不停止） → 统计每个精灵体被多少条不同射线穿过 → 交叉计数决定精灵体内部的填充颜色（1 条 = 源像素色，2 条以上 = 灰色，0 条 = 不变）。删除射线则无法确定交叉关系；删除计数则无法区分单次和多次交叉；删除填充则无输出变化。

从底边源像素发射的对角射线穿透散布的小精灵体，根据每个精灵体被穿过的射线数量决定其内部填充颜色。

**输入结构**：约 16x20 的黑(0)背景网格（宽 20、高 16）。底行上有 2~4 个单像素源像素，颜色各不相同，取自蓝(1)、红(2)、绿(3)。网格内部散布 4~6 个灰(5)色单色小精灵体（4-连通、4~8 像素、边界框不超过 3x3）。精灵体互不接触（边界框间至少 1 像素间隔）。生成约束：每个源像素发出的 45 度对角射线（向右上方延伸至网格边缘）至少穿过 1 个精灵体；至少有 1 个精灵体被恰好 1 条射线穿过，至少有 1 个精灵体被 2 条或以上射线穿过，至少有 1 个精灵体不被任何射线穿过。

**规则**：
1. 识别底行上的源像素及其颜色。
2. 每个源像素向右上方发射 45 度对角射线（每步行减 1、列加 1），射线一直延伸到网格边缘，不会被任何像素阻挡。射线本身不在输出中绘制。
3. 对每个精灵体，统计有多少条不同的对角射线经过了该精灵体的至少一个像素（记为交叉数 K）。
4. 若 K = 0：该精灵体在输出中保持原样（灰(5)色）。
5. 若 K = 1：找到穿过该精灵体的那条唯一射线对应的源像素颜色 C。将该精灵体的所有像素重涂为 C。
6. 若 K >= 2：将该精灵体的所有像素重涂为黄(4)。
7. 底行源像素在输出中保留原色不变。

**关键洞察**：射线是"透明"的侦测工具而非绘制工具——它不画线、不停止，只是标记穿过了哪些精灵体。需要对比多个示例才能发现 K >= 2 统一使用黄(4)而非混合颜色的规则。

## 新题 6：射线存活性生成外层掩码驱动克罗内克积

**组合逻辑**：[射线延伸/ray_extend](创新：射线是否到达对侧边缘编码为二值信号) → [克罗内克积/kronecker_product](创新：外层掩码由射线存活性动态生成而非直接给定) + [面板提供调色板/panel_as_palette](已有)

**来源原语**：射线延伸/ray_extend、障碍块/blocker、源像素/source_pixel、边缘起始/edge_origin（P11 69889d6e）；克罗内克积/kronecker_product、二值掩码/binary_mask、色块面板/color_panel、面板提供调色板/panel_as_palette（P5 c803e39c）；分隔列/separator_column（P4 5545f144、P5 c803e39c）

**依赖链**：左边缘的源像素发射水平射线 → 障碍块阻挡部分射线 → 到达右侧分隔列的射线标记为"存活"，形成一个 Nx1 的二值列向量（存活=前景、被挡=背景） → 该列向量作为克罗内克积的外层掩码 → 与右侧面板中的内层二值掩码做克罗内克积 → 两个色块面板提供调色板。删除射线则外层掩码未知；删除克罗内克积则存活列表无法扩展为二维图案。

左边缘源像素的射线被障碍块选择性阻挡，存活射线形成的二值向量与面板中的内层掩码做克罗内克积，生成最终图案。

**输入结构**：约 Nx(M+1+K) 的黑(0)背景网格，被一条灰(5)满高分隔列分为左右两区。左区约 Nx M（N 约 5~8 行，M 约 8~12 列）：左列（第 0 列）的每个像素为红(2)色源像素；左区内部散布若干蓝(1)色障碍块（单像素或 1x2/2x1 小块），每行至多一个障碍块。右区约 Nx K（K 约 6~8 列）：紧贴分隔列右侧放置一个 P x Q 的二值掩码面板（前景绿(3)、背景黑(0)，P,Q 约 3~4），以及两个 1x1 色块——一个橙(7)色方块和一个品红(6)色方块。生成约束：N >= P，使克罗内克积有意义；左区中至少有 2 行的射线能到达分隔列、至少有 1 行的射线被障碍块完全阻挡；障碍块不在第 0 列（不遮挡源像素本身）。

**规则**：
1. 识别灰(5)分隔列，将网格分为左区和右区。
2. 左区：每个源像素（左列红(2)像素）向右发射水平射线，射线沿行前进直到碰到障碍块（蓝(1)像素）或到达分隔列。若射线到达分隔列（中途未被任何障碍块阻挡），记该行为"存活"（前景=1）；否则记为"阻挡"（背景=0）。
3. 将 N 行的存活/阻挡状态排列为一个 Nx1 的二值列向量 V。
4. 从右区提取 PxQ 的二值掩码 M_inner 和两个调色板颜色 C_fg=橙(7)、C_bg=品红(6)。
5. 计算克罗内克积 V (x) M_inner：对 V 中每个前景元素，放置一个 PxQ 的 M_inner 副本（前景像素涂 C_fg、背景像素涂 C_bg）；对 V 中每个背景元素，放置一个 PxQ 的全 C_bg 块。
6. 输出仅为克罗内克积结果（尺寸 (N*P) x Q），不包含原始左区、分隔列或右区面板。

**关键洞察**：克罗内克积的外层掩码不是直接给定的（与 P5 不同），而是由射线-障碍块交互动态生成的——改变障碍块位置就改变了外层掩码，从而改变整个输出图案。需要对比多个示例才能发现外层掩码来自射线存活性而非某个显式面板。

## 新题 7：对称掩码裁剪为地形图，非对称物体在地形上做重力下落

**组合逻辑**：[对称图案选取/symmetric_selected](创新：对称掩码不作为输出，而是定义输出画布的"地形") + [裁剪/crop](已有) → [重力下落/gravity_drop](创新：下落地形由另一个操作的中间结果提供) + [碰撞停止/collision_stop](已有)

**来源原语**：对称/symmetry、对称图案选取/symmetric_selected、颜色掩码/color_mask、裁剪/crop（P17 d56f2372）；重力下落/gravity_drop、碰撞停止/collision_stop（P10 f0100645）；前景物体/foreground_object（P10 f0100645）

**依赖链**：多个颜色掩码中选出对称掩码 → 裁剪对称掩码得到一个二值地形图（前景=地面，背景=空气） → 非对称掩码中的连通分量作为下落物体 → 物体从地形顶部下落，在地面或其他已停稳物体上停止。删除对称选择则无法区分地形和物体；删除裁剪则地形尺寸未定；删除重力下落则物体无放置规则。这是一个同时约束满足结构：对称掩码同时编码了"输出画布是什么"和"地面在哪里"。

从多个颜色掩码中识别出对称掩码作为地形，将剩余掩码的连通分量在该地形中做重力下落。

**输入结构**：约 14x14 的黑(0)背景网格。网格内有 3~4 种非背景颜色的掩码（每种颜色的所有像素构成一个掩码）。恰好一种颜色的掩码（裁剪到边界框后）关于垂直中轴左右对称，其颜色取自灰(5)或栗(9)。其余颜色的掩码不对称，每种颜色可能含 1~2 个 4-连通分量，每个分量 2~5 像素。生成约束：对称掩码裁剪后的边界框高度 >= 6、宽度 >= 5；对称掩码中前景像素不全集中在底部（即"地形"中存在空洞或悬空平台，使重力下落路径不平凡）；非对称物体的总数 >= 3；非对称物体的最大宽度不超过对称掩码裁剪宽度。

**规则**：
1. 对每种非背景颜色，将该颜色的所有像素裁剪到其边界框，判断是否左右镜像对称。
2. 恰好一种颜色 T 的掩码是对称的。将该掩码裁剪到其边界框，得到一个 HxW 的地形图：颜色 T 的像素 = 地面（固态），背景像素 = 空气。
3. 创建一个 HxW 的黑(0)输出画布。将地形图的地面像素涂为颜色 T。
4. 收集所有非对称颜色掩码的 4-连通分量，每个分量裁剪到其边界框，保留其原色和内部形状。
5. 按分量原始位置的列坐标从左到右排序（列坐标相同则行坐标小的优先）。依次将每个分量放入输出画布：
   - 分量的水平位置（左边界列号）= 该分量在原始网格中的列坐标减去对称掩码边界框的左列坐标（即对齐到地形坐标系），若超出画布宽度则右截断。
   - 分量从画布顶部（行 0）开始逐行下落，直到分量的任一像素的正下方一行是地面像素或已停稳的物体像素，此时停止。
   - 若分量在顶行就已碰到地面，则分量放置在顶行。
6. 后放置的物体像素覆盖先放置的物体像素（但不覆盖地面像素——物体停在地面之上）。

**关键洞察**：对称掩码在 P17 中是被选出直接输出的目标，但这里它的角色完全不同——它定义了一个"物理世界"的地形，其他物体在这个地形中受重力约束。需要对比多个示例才能发现对称掩码不是输出主体，而是输出中的地面结构。

## 新题 8：逐步消除标记的顺序编码分隔格单元的填充色序

**组合逻辑**：[逐步移动/stepwise_move + 消除/consume](已有) + [朝向决定搜索线/facing_sets_search_line](已有) → [填充/fill](创新：消除顺序映射到分隔格单元的着色) + [分隔栅格/divider_grid](创新：分隔线交叉点编码了消除路径的拐点)

**来源原语**：逐步移动/stepwise_move、消除/consume、三角精灵体/triangle_sprite、朝向决定搜索线/facing_sets_search_line、最近标记优先/nearest_marker_first（P4 5545f144）；填充/fill、分隔栅格/divider_grid、沿行列填充间隙/fill_gap_along_row_col（P1 06df4c85）

**依赖链**：三角精灵体按朝向消除最近标记、每次消除后变向 → 消除序列产生一个有序颜色列表 → 分隔栅格将画布分成多个单元格 → 精灵体穿越的单元格按穿越顺序被填充为消除序列中对应位置的颜色。删除消除则无颜色序列来源；删除分隔栅格则无法确定填充的空间单元；删除朝向机制则消除路径不确定。

三角精灵体在分隔栅格中逐步消除标记，消除的颜色序列反过来决定所经过每个分隔格单元的填充色。

**输入结构**：约 15x15 的黑(0)背景网格。橙(7)色的完整水平线和垂直线将网格分为 3x3 或 4x3 的单元格布局。一个单元格中包含一个由红(2)色像素构成的三角形精灵体（约 3~4 像素组成箭头形，尖端指向某个基本方向——上/下/左/右），占据该单元格的部分区域。其余若干单元格中各有一个单像素标记，颜色取自蓝(1)、绿(3)、黄(4)、灰(5)（同一网格中各标记颜色可不同也可重复）。精灵体沿朝向方向的搜索线上至少有一个标记像素（可跨越分隔线）。生成约束：标记数量 3~5 个；从精灵体出发按"消除最近→变向→消除最近→变向→..."的规则可消除所有标记（即全局存在唯一消除路径）；精灵体经过的分隔格单元数量等于标记数量。

**规则**：
1. 识别橙(7)分隔线确定的单元格布局。
2. 找到包含三角精灵体的单元格，确定精灵体朝向（尖端指向的基本方向）。
3. 沿朝向方向的半直线搜索最近标记像素（忽略分隔线——标记可在任何单元格中）。精灵体的中心移动到该标记位置，消除该标记，记录该标记的颜色为序列中的第 1 个颜色。精灵体朝向变为消除方向。
4. 重复步骤 3：沿新朝向搜索下一个最近标记，消除并记录颜色，变向。直到无更多标记可消除。
5. 得到一个有序颜色序列 [C1, C2, ..., Cn]。
6. 回溯精灵体的移动轨迹，按轨迹顺序列出精灵体依次经过的不同单元格（精灵体起始单元格不计，每个单元格仅在首次进入时计数）。得到有序单元格序列 [Cell1, Cell2, ..., Celln]。
7. 将 Cell_i 的全部背景像素填充为颜色 C_i。
8. 输出中：分隔线保持橙(7)不变；精灵体从画面中消失（起始单元格变为背景色）；标记像素已被消除；被填充的单元格整体呈纯色。未被经过的单元格保持黑(0)背景。

**关键洞察**：消除序列不仅记录了"吃掉了什么"，还编码了"沿途每个房间应该涂什么颜色"——消除顺序和空间穿越顺序形成了一一映射。需要对比多个示例才能发现颜色的空间分配规则是按穿越单元格顺序而非按标记所在单元格着色。

## 新题 9：视线匹配延伸路径后由包含层级决定尾部重涂颜色

**组合逻辑**：[视线匹配/sightline_matching](已有) + [射线延伸/ray_extend → 连线/connect](已有) + [间距编码尾长/gap_distance_encodes_tail_length](已有) → [严格包含/strict_containment](创新：包含关系覆写了颜色传递规则) + [重涂色/recolor](创新：重涂颜色由标记所在的矩形边框层级决定，而非标记自身颜色)

**来源原语**：视线匹配/sightline_matching、路径对象/path_object、标记像素/marker_pixel、间距编码尾长/gap_distance_encodes_tail_length、重涂色/recolor（P19 696d4842）；严格包含/strict_containment、矩形边框/rectangular_perimeter、最外层颜色继承/outermost_color_inheritance（P13 7d1f7ee8）

**依赖链**：标记像素与路径端点通过视线匹配建立一一配对 → 填充间隙将路径延伸到标记 → 间隙距离编码了尾部重涂长度 → 但重涂颜色不是标记自身颜色，而是"包围该标记的最内层矩形边框的颜色"（若标记不在任何边框内，才退回使用标记自身颜色）。删除视线匹配则无法配对；删除间距编码则尾长未知；删除包含层级则退化为 P19。

将标记像素与路径端点做视线配对并延伸连接，但路径尾部的重涂颜色不取标记自身颜色，而取包围标记的最内层矩形边框的颜色。

**输入结构**：约 18x18 的黑(0)背景网格。网格中有 2~3 个单色无分支正交路径对象（每个为 4-连通、单像素宽、恰好两个端点的折线，颜色各不同，取自蓝(1)、绿(3)、橙(7)），长度 4~8 像素。同时有 2~3 个孤立单像素标记，颜色取自黄(4)、品红(6)、青(8)。每个标记沿某行或列方向能直线看到恰好一个路径端点（中间全为背景像素）。此外，网格中有 1~2 组嵌套矩形边框（每组 1~2 层，颜色取自红(2)、灰(5)、栗(9)，与路径和标记颜色均不同）。部分标记位于某个矩形边框的严格内部，部分标记不在任何边框内。生成约束：标记与路径对象数量相同，形成唯一的一一配对；每个标记到配对路径端点之间的间隙距离 >= 1 且不超过路径长度；至少一个标记在某矩形边框内部，至少一个标记不在任何边框内部。

**规则**：
1. 识别所有路径对象（单像素宽、无分支、恰两端点的 4-连通单色折线）和所有孤立标记像素。
2. 建立标记与路径的唯一一一配对：每个标记沿行或列方向直线可达某个路径端点（中间无非背景像素），该端点所属路径即为配对路径。
3. 对每对配对：用路径对象的颜色填充标记与路径端点之间的背景间隙像素（不覆盖标记本身），将路径延伸到标记旁。记间隙长度为 G。
4. 确定尾部重涂颜色 R：
   - 若该标记严格位于某矩形边框的内部，找到包围该标记的最内层矩形边框，R = 该边框的颜色。
   - 若该标记不在任何矩形边框内部，R = 该标记自身的颜色。
5. 从配对路径的另一个端点（非配对端）开始，沿路径方向将路径上的前 G 个像素重涂为颜色 R（保留路径形状，仅变色）。若 G 超过路径长度则将整条路径重涂。
6. 矩形边框在输出中保持原样不变。标记像素保持原色不变。

**关键洞察**：标记像素的空间位置暗含了一个"颜色查找表"——标记被哪个矩形框包围决定了它传递什么颜色给配对路径，而不是直接用标记自身的颜色。需要对比多个示例（一个标记在框内、一个在框外）才能归纳出这个间接颜色传递规则。
