## 新题 1：轮廓编码方向重力

**组合逻辑**：[解码(decode)](创新：轮廓形状编码运动方向而非颜色相位) + [滑动(sliding)](已有) + [碰撞阻挡(collision_block)](已有) → 终态输出

**来源原语**：解码/相位编码(eee78d87), 滑动/重力沉降/碰撞阻挡(d282b262), 轮廓字形(eee78d87), 前景对象(d282b262)

**依赖链**：每个对象的轮廓形状决定其滑动方向（解码结果控制滑动参数），多对象同时滑动时碰撞阻挡产生顺序依赖——先到达边界的对象成为后续对象的障碍，最终布局由解码+碰撞的交互决定。

将每个前景精灵按其外接轮廓的方向编码滑动至边界或碰撞停止，输出终态布局。

**输入结构**：约 14x14 网格，黑(0)背景。含 3~5 个互不相邻的单色 4-连通前景精灵（每个 4~8 像素），颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)中选取）。每个精灵的最小外接矩形(bbox)为 3x3，其中精灵像素构成一种方向轮廓：若 bbox 顶行中间列有像素且底行中间列无像素，编码"向上"；若底行中间列有像素且顶行中间列无像素，编码"向下"；若左列中间行有像素且右列中间行无像素，编码"向左"；若右列中间行有像素且左列中间行无像素，编码"向右"。生成约束：每个精灵恰好满足上述四种编码之一；不同精灵的编码方向可以相同也可以不同。

**规则**：
1. 对每个精灵，检测其 3x3 bbox 的方向编码像素位置，确定其运动方向（上/下/左/右）。
2. 所有精灵同时沿各自方向每步移动一格。
3. 若某精灵下一步的目标位置与网格边界重合或与另一个已停止精灵的像素重合，则该精灵停止。
4. 重复步骤 2-3 直到所有精灵停止。
5. 输出终态网格，精灵保持原色和原形状，仅位置改变。

**关键洞察**：精灵的几何轮廓不是装饰——它编码了运动方向。必须对比多个示例才能确定 bbox 中哪个位置的像素对应哪个方向，因为单个示例中无法区分"形状恰好如此"和"形状编码方向"。

## 新题 2：异或选区内的墙壁扫描线填充

**组合逻辑**：[异或(xor)](已有) → 选区掩码 → [填充(fill)](已有，但作用区域由异或结果限定) + [墙壁界定范围(wall_bounds_span)](创新：墙壁不再独立界定，而是在异或激活的行内才生效)

**来源原语**：异或/逐像素异或输出(3428a4f5), 填充/墙壁界定范围/扫描线区间/墙壁像素(78e78cff), 分隔行(3428a4f5), 掩码(3428a4f5)

**依赖链**：异或产生一个中间选区掩码（不是最终输出），该掩码决定哪些行参与后续的扫描线填充；墙壁像素独立于两个掩码存在，但只在被异或选中的行上发挥界定作用。删掉异或步骤则无法确定填充行，删掉墙壁则无法确定填充宽度。

对上下两个二值掩码做异或得到激活行集合，在激活行上按墙壁像素界定的区间进行填充。

**输入结构**：约 15x11 网格。顶部区域（5 行）为红(2)/黑(0)二值掩码 A；中间 1 行为黄(4)分隔行；下方区域（5 行）为红(2)/黑(0)二值掩码 B；掩码 A 和 B 同宽同高。在分隔行下方另有 1 行间隔后，底部额外 2~3 行包含灰(5)墙壁像素，这些灰像素散布在某些列上（每行 2~4 个灰像素）。生成约束：墙壁行数与掩码高度相同（即 5 行），墙壁区域与掩码区域行数一一对应；异或结果中至少有 2 行为"激活"（存在差异像素）。

**规则**：
1. 定位黄(4)分隔行，将其上方和下方的同尺寸区域识别为掩码 A 和掩码 B。
2. 逐行对 A 和 B 进行异或运算：该行存在至少一个位置 A 与 B 不同则该行为"激活行"，否则为"非激活行"。
3. 在底部墙壁区域中，对每个激活行找到其对应行（按从上到下顺序第 k 个激活行对应墙壁区域第 k 行）的灰(5)像素位置。
4. 在输出中，对每个激活行：在对应墙壁行的最左灰像素列和最右灰像素列之间（含端点），将背景像素涂为绿(3)。非激活行输出为全黑。
5. 输出尺寸为掩码高度 x 掩码宽度，仅包含绿(3)填充和黑(0)背景（掩码、分隔行、墙壁均不出现在输出中）。

**关键洞察**：异或结果不直接显示在输出中——它是一个隐式的行选择器，控制哪些行接受墙壁定义的填充。必须对比多个示例才能发现"激活行与墙壁行的对应关系是按序配对而非按行号对应"。

## 新题 3：面积排名决定镜像轴

**组合逻辑**：[计数(counting)](已有) + [排序(sorting)](已有) → 排名 → [镜像(mirror)](创新：镜像轴由排名决定而非固定)

**来源原语**：计数/排序/面积排序/按像素数降序(f8ff0b80), 镜像/镜像对应(74dd1130, 9bebae7a), 精灵体(9bebae7a), 前景色掩码(f8ff0b80)

**依赖链**：计数产生面积值，排序产生排名，排名决定每个精灵的镜像方式。三步紧耦合——不计数则无法排序，不排序则无法分配镜像轴，不镜像则无法生成输出。

统计每个前景精灵的像素数并排序，排名决定该精灵的反射轴类型，输出所有精灵经各自轴反射后的结果。

**输入结构**：约 12x12 网格，黑(0)背景。恰好 3 个互不相邻的单色 4-连通前景精灵，颜色分别为蓝(1)、红(2)、绿(3)，每个精灵 3~7 像素且三者像素数互不相同。每个精灵非对称（不具备水平/垂直/对角对称性）。生成约束：三个精灵的 bbox 之间至少间隔 2 格；每个精灵的 bbox 距离网格边界有足够空间容纳其镜像副本。

**规则**：
1. 统计每个精灵的像素数，按像素数从大到小排列为排名 1、2、3。
2. 排名 1 的精灵：以其 bbox 的水平中轴为轴做上下镜像，镜像副本紧贴在原件下方（若原件在下则副本在上），保持原色。
3. 排名 2 的精灵：以其 bbox 的垂直中轴为轴做左右镜像，镜像副本紧贴在原件右侧（若原件在右则副本在左），保持原色。
4. 排名 3 的精灵：以其 bbox 的主对角线为轴做转置反射（行列互换），镜像副本放置在原件的右下方，与原件共享 bbox 左上角，保持原色。
5. 输出保留原始精灵并添加各自的镜像副本。背景保持黑(0)。

**关键洞察**：镜像轴不是由位置或颜色决定的——必须先数像素、排名次，才能知道每个精灵该怎么反射。单个示例中可能误以为"蓝色=水平镜像"，需要对比多个示例（颜色与排名关系变化）才能归纳出正确规则。

## 新题 4：对称补全轴由面积匹配确定

**组合逻辑**：[计数(counting)](已有) + [面积匹配(area_matching)](创新：匹配目标从腔体变为对称轴候选) → 轴选择 → [对称补全(symmetry_completion)](已有，但轴由前序决定)

**来源原语**：计数/面积匹配/像素数等于腔面积(7acdf6d3), 对称补全/推断对称轴/双轴对称图案/缺失像素(981571dc), 源像素集(7acdf6d3)

**依赖链**：图案有多个可能的对称轴，每个轴对应不同的补全结果。独立的"指示像素集"的像素数编码了正确轴的标识。面积匹配不再选择填充目标，而是选择对称轴——这是一个全新的结构关系。

在一个被部分擦除的图案中，通过统计独立指示像素的数量来确定应使用哪条对称轴进行补全。

**输入结构**：约 11x11 网格，黑(0)背景。主体为一个多色图案（使用蓝(1)、红(2)、绿(3)中的 2~3 种），该图案原本具备双轴对称性（水平轴和垂直轴），但被擦除了若干像素（变为黑(0)）。擦除方式使得仅用水平轴补全和仅用垂直轴补全会产生不同结果（即某些位置只能通过特定轴的镜像对应点恢复）。网格右下角有一小簇橙(7)像素（2~4 个，4-连通），与主图案不接触。生成约束：擦除的像素分布使得"水平轴补全后的非黑像素总数"和"垂直轴补全后的非黑像素总数"互不相同；橙像素的数量等于两个补全候选中某一个的非黑像素总数除以 10（向下取整）。

**规则**：
1. 识别主图案区域（非橙、非黑像素的连通区域及其 bbox）和橙(7)指示像素集。
2. 统计橙像素的数量 N。
3. 对主图案分别尝试水平轴补全和垂直轴补全，计算每种补全后的非黑像素总数，分别为 H 和 V。
4. 计算 H/10（向下取整）和 V/10（向下取整），选择与 N 相等的那个所对应的轴。
5. 用该轴对主图案执行对称补全：对每个黑(0)像素，取其关于选定轴的镜像位置的颜色填入。
6. 输出仅包含补全后的主图案（与主图案 bbox 相同大小），不含橙指示像素。

**关键洞察**：图案看似可以用任意轴补全（两轴都能产生"合理"的对称结果），但只有一种是正确的。正确轴的选择需要通过外部像素计数间接推断——这个"面积编码"关系在单个示例中几乎不可见，必须对比多个示例才能发现橙像素数与补全面积的除以 10 关系。

## 新题 5：墙壁限定滑动后标记臂决定拼接方向

**组合逻辑**：[滑动(sliding)](已有) + [墙壁界定范围(wall_bounds_span)](创新：墙壁作为滑动终止条件而非填充边界) → 中间布局 → [拼接(concatenate)](已有) + [最长臂决定镜像侧(longest_arm_mirror_side)](创新：决定拼接方向而非镜像方向)

**来源原语**：滑动/碰撞阻挡(d282b262), 墙壁像素/墙壁界定范围(78e78cff), 拼接/相邻拼接(9bebae7a), 十字标记/最长臂决定镜像侧(9bebae7a), 精灵体(9bebae7a)

**依赖链**：精灵沿十字标记最长臂方向滑动，直到碰到墙壁像素停止（滑动方向+终止条件的耦合）。停止后，精灵与其碰到的墙壁形成相邻关系，此时以墙壁为轴将精灵镜像拼接到墙壁另一侧。删除滑动步骤则精灵不在墙壁旁边无法拼接，删除方向编码则不知道往哪滑，删除拼接则无法产生最终图形。

精灵按十字标记编码的方向滑动至墙壁，然后以墙壁为对称轴镜像拼接。

**输入结构**：约 13x13 网格，黑(0)背景。包含：(a) 一个蓝(1)单色 4-连通精灵（4~6 像素，非对称形状）；(b) 一个红(2)十字标记（由 1 个中心像素和 4 个方向臂组成，其中一个臂比其余臂长 1~2 格，总共 5~7 像素）；(c) 一条灰(5)墙壁线段（水平或垂直，长度 5~8 像素，连续直线）。十字标记的最长臂指向墙壁所在方向。精灵位于十字标记和墙壁之间的空间内（即沿最长臂方向，精灵在标记和墙壁之间）。生成约束：精灵与墙壁之间有 2~4 格空隙；墙壁另一侧有足够空间容纳精灵的镜像。

**规则**：
1. 识别红(2)十字标记，找到其唯一最长臂的方向（上/下/左/右）。
2. 将蓝(1)精灵沿最长臂方向逐格滑动，直到精灵的某个像素的下一步位置与灰(5)墙壁像素相邻（4-连通相邻即停止，精灵不覆盖墙壁）。
3. 以灰(5)墙壁线段为对称轴，将停止后的蓝精灵做镜像反射，产生一个绿(3)镜像副本放置在墙壁另一侧的对应位置。
4. 输出保留滑动后的蓝精灵（在墙壁旁的位置）和绿(3)镜像副本。擦除红(2)十字标记。灰(5)墙壁保留。

**关键洞察**：十字标记同时编码了两个信息——滑动方向和（间接地）镜像轴方向，因为精灵总是滑向墙壁，而墙壁就是镜像轴。单个示例可能误以为"精灵直接镜像到墙壁对面而不经过滑动"，需要对比多个示例（精灵与墙壁距离不同但结果中精灵总是紧贴墙壁）才能发现滑动步骤的存在。

## 新题 6：递归印章位置由内外分离决定

**组合逻辑**：[内外分离(interior_exterior_sep)](创新：分离结果决定印章位置而非仅做涂色) → 位置选择 → [印章覆盖(stamp_overlay)](已有) + [像素放大(pixel_expand)](已有)

**来源原语**：内外分离/前景矩形/矩形内部/保留边框涂内部(50cb2852), 印章覆盖/递归印章/控制像素(cce03e0d), 像素放大(cce03e0d, 007bbfb7)

**依赖链**：首先从输入中识别矩形并分离出内部和边框。边框像素的位置（在缩小到 1 像素后）充当"控制像素"的角色——在按比例放大的输出网格中，对应边框位置的块接收完整输入图案的印章，对应内部位置的块保持另一种处理。删除内外分离则无法确定哪些位置是边框，删除印章则无法生成放大后的图案。

识别矩形的边框像素作为印章控制位置，将整个输入图案印章到放大网格中边框对应的块中。

**输入结构**：约 5x5 网格，黑(0)背景。包含一个有色的实心矩形（3x3 或 4x4），矩形使用两种颜色：边框像素为红(2)，内部像素为蓝(1)。矩形可以不在网格正中（即网格中矩形外有黑色背景区域）。生成约束：矩形至少 3x3 以保证存在内部像素。

**规则**：
1. 识别输入中的有色矩形，区分边框像素（红(2)，矩形最外圈一层）和内部像素（蓝(1)，矩形去掉外圈的部分）。
2. 创建与输入同尺寸的二值控制网格：红像素位置标记为"印章位"，其余位置标记为"空位"。
3. 构建输出：输出尺寸为输入高度的平方 x 输入宽度的平方。将输出划分为与输入同尺寸的块网格（每块大小等于输入尺寸）。
4. 对于控制网格中每个"印章位"，将整个输入图案（含矩形和背景）完整复制到输出对应块中。
5. 对于控制网格中每个"空位"，对应输出块全部填充黄(4)。
6. 输出即为拼接后的完整块网格。

**关键洞察**：矩形的颜色分层（红边框/蓝内部）不是简单的装饰性涂色——它暗示了一种"控制信号"。边框的几何位置被提取为递归印章的控制模板，使得输出的宏观结构呈现空心矩形轮廓的分形特征。需要对比示例确认"红色=印章位"而非"所有非黑=印章位"。

## 新题 7：颜色反转平铺与碰撞终态叠加

**组合逻辑**：[颜色反转(color_invert)](已有) + [平铺(tile)](已有) → 背景层 → [滑动(sliding)](已有) + [碰撞阻挡(collision_block)](已有) → 前景层 → 叠加（同时约束满足）

**来源原语**：颜色反转/反转后再平铺(48131b3c), 平铺/二值图案(48131b3c), 滑动/重力沉降/碰撞阻挡/前景对象(d282b262), 画布边界(d282b262)

**依赖链**：输入同时编码两个信息——(a)一个小图案用于反转平铺产生背景，(b)若干前景精灵需要滑动至终态。最终输出是前景终态覆盖在反转平铺的背景之上。两个系统共享输入空间但规则独立，必须同时正确处理才能得到完整输出。非线性结构：两条处理路径从同一输入分叉，最后汇合。

从同一输入中提取图案做颜色反转平铺生成背景，同时对前景精灵做重力滑动，最终将滑动终态叠加在平铺背景上。

**输入结构**：约 6x6 网格，黑(0)背景。网格左上角 3x3 区域包含一个灰(5)/黑(0)二值小图案（至少 3 个灰像素）。网格其余区域散布 2~3 个小型单色精灵（每个 2~3 像素，4-连通），颜色从蓝(1)、红(2)、绿(3)中选取且互不相同。精灵不与左上角 3x3 图案重叠。生成约束：精灵之间互不相邻；精灵右侧或下方有足够空间滑动。

**规则**：
1. 提取左上角 3x3 区域作为"种子图案"。
2. 对种子图案做颜色反转：灰(5)变为黑(0)，黑(0)变为灰(5)。
3. 将反转后的 3x3 图案平铺 2x2，得到 6x6 的背景层。
4. 识别输入中 3x3 区域之外的所有前景精灵，对它们执行向右重力滑动：每个精灵同时向右移动，碰到网格右边界或已停止精灵则停止。
5. 输出为 6x6 网格：先放置背景层（步骤 3 的平铺结果），再将步骤 4 的精灵终态位置叠加在背景层之上（精灵像素覆盖背景像素）。

**关键洞察**：左上角 3x3 区域既是输入的一部分又是背景生成的种子——它在输出中"消失"（被自身的反转平铺覆盖），但其信息以反转形式铺满整个背景。求解者必须同时理解"图案反转平铺"和"精灵重力滑动"两条独立规则，并意识到它们应用于输入的不同部分后汇合为同一输出。

## 新题 8：轮廓腔体面积匹配后用查表颜色填充

**组合逻辑**：[计数(counting)](已有) + [面积匹配(area_matching)](已有) → 目标选择 → [查表替换(lookup_replace)](创新：查表的key不是颜色而是面积差值) + [填充(fill)](已有)

**来源原语**：计数/面积匹配/像素数等于腔面积(7acdf6d3), 轮廓对象/源像素集/行内腔(7acdf6d3), 查表替换/颜色决定输出/颜色映射符号(d4469b4b), 固定符号(d4469b4b)

**依赖链**：首先统计多个轮廓对象的腔体面积和多个色块的像素数。色块像素数与腔体面积配对（面积匹配），配对后色块的颜色不直接填入腔体——而是作为查表的 key，通过输入中的色卡图例确定真正的填充颜色。三步顺序依赖且每步输出改变下步输入性质。

将色块按面积匹配到对应轮廓腔体中，但填充颜色通过色卡图例间接查表确定。

**输入结构**：约 14x14 网格，黑(0)背景。包含：(a) 2~3 个灰(5)轮廓对象（每个是一个 8-连通的空心环形/U形轮廓，内部有腔体，腔体面积各不相同，范围 3~8 像素）；(b) 2~3 个分散的单色色块（4-连通，颜色从蓝(1)、红(2)、绿(3)中选取，像素数分别等于某个腔体面积）；(c) 网格最底行为色卡图例：由 2~3 对相邻像素对组成，每对中左像素为源色（蓝/红/绿之一），右像素为目标色（黄(4)、橙(7)、品红(6)之一）。生成约束：色块数等于轮廓数；每个色块恰好匹配一个腔体面积（一一对应）；图例中每种源色恰好出现一次。

**规则**：
1. 识别所有灰(5)轮廓对象，计算每个轮廓的行内腔面积（每行中最左灰像素和最右灰像素之间的黑像素数之和）。
2. 统计每个非灰前景色块的像素数。
3. 将色块与轮廓配对：像素数等于腔体面积的色块与该轮廓配对。
4. 读取最底行色卡图例：每对相邻像素中，左像素颜色为"源色"，右像素颜色为"目标色"，建立映射表。
5. 对每个配对：擦除原色块像素，在配对轮廓的腔体位置填入该色块颜色经查表映射后的目标色。
6. 输出保留灰轮廓，腔体内填充目标色，原色块位置变为黑(0)，最底行图例保留。

**关键洞察**：色块的颜色有双重含义——它的像素数决定它"去哪里"（面积匹配），它的色值决定腔体"填什么色"（经图例间接转换）。直接把色块颜色填入腔体是错误的；必须发现底行图例的存在并理解其映射关系。
