## 新题 1：双掩码交集定位印章阵列

**组合逻辑**：[逻辑交(logical_AND)](从颜色掩码扩展为空间定位器) + [印章覆盖(stamp)](从固定槽位改为由AND结果动态确定位置) + [擦除(erase)](清除源面板)

**来源原语**：逻辑交 ← 0520fde7; 印章覆盖 ← 363442ee; 分隔列 ← 0520fde7/363442ee; 精灵体 ← 363442ee

**依赖链**：AND运算的输出像素坐标直接成为stamp的放置锚点；stamp内容来自第三面板的精灵体提取；两步缺一不可——没有AND无法确定位置，没有精灵体无法确定内容。

将三面板中左右掩码的逐像素交集转化为印章放置坐标，在输出画布上以交集像素为中心绘制第三面板的精灵体。

**输入结构**：约 7x19 的网格，由两条灰(5)满高分隔列将网格分为三个等宽面板（每面板宽 5 列）。左面板和中面板为同尺寸的二值掩码：黑(0)为"关"，蓝(1)为"开"，各有 3~6 个"开"像素散布其中。右面板在黑(0)背景上有一个红(2)色的 4-连通小精灵体（3~5 像素，非对称），精灵体的边界框不超过 3x3。生成约束：左右掩码的AND结果至少有 2 个"开"像素；精灵体以各AND像素为中心放置时，所有印章均在输出画布内且互不重叠。

**规则**：
1. 识别两条灰(5)分隔列，将网格分为左掩码、中掩码、右精灵面板。
2. 逐像素比较左掩码和中掩码：仅当两者对应位置均为蓝(1)时标记为"命中"。
3. 提取右面板中红(2)精灵体的边界框作为印章模板。
4. 创建与单面板同尺寸的纯黑(0)输出画布。
5. 对每个"命中"坐标，以该坐标为印章模板中心对齐点，将精灵体绘制到输出画布。处理顺序：从上到下、同行从左到右。若后绘制的印章与先前印章有像素重叠，后者覆盖先者。
6. 输出仅包含该画布（丢弃分隔列和原始三面板）。

**关键洞察**：AND运算不再仅产出一个重叠标记颜色，而是产出一组坐标；这组坐标成为后续空间操作的定位参数——逻辑运算的输出从"值"变为"位置集合"。

## 新题 2：射线距离驱动循环调色板赋色

**组合逻辑**：[射线延伸(ray_cast)](从向下填充改为向上测距) + [循环填充(cyclic_fill)](从固定游程改为以射线距离为索引取色) + [列遮挡(column_coverage)](作为射线存活的筛选条件)

**来源原语**：射线延伸 ← 6d58a25d; 循环填充 ← e7b06bea; 调色板列 ← e7b06bea; 列遮挡 ← 6d58a25d; 控制条 ← 5d588b4d

**依赖链**：控制条的覆盖范围决定哪些列上的像素"存活"；射线向上测距得到距离值；距离值对调色板长度取模选色——三步环环相扣，跳过任一步均无法确定输出颜色。

下方散布的前景像素向上发射射线到控制条，射线穿越的背景距离决定该像素在调色板中的循环取色索引。

**输入结构**：约 12x12 的网格，黑(0)背景。顶部第 0 行有一条橙(7)水平控制条，从第 1 列开始，长度 4~8 列（不一定到右边界）。网格右边界最后一列为调色板列：从第 1 行起自上而下排列 3~4 种不同颜色的单像素（如红(2)、绿(3)、黄(4)），调色板像素之间无间隔，紧密排列，其余行为黑(0)。在控制条以下的区域（第 1 行至倒数第 1 行），散布 5~8 个蓝(1)前景像素，部分在控制条覆盖列内，部分在覆盖列外。生成约束：调色板至少 3 色；控制条覆盖列内至少有 3 个蓝像素。

**规则**：
1. 识别顶行橙(7)控制条，记录其覆盖的列范围。识别右侧调色板列中自上而下的颜色序列 P[0], P[1], ..., P[k-1]。
2. 对每个蓝(1)像素：检查其所在列是否在控制条覆盖范围内。若不在范围内，该像素在输出中被擦除为黑(0)。
3. 若在范围内，从该像素位置向上逐行计数纯黑(0)背景像素数（不计入控制条本身和该像素本身），直到触碰控制条的下边缘，记距离为 d。
4. 计算索引 i = d mod k（k 为调色板长度），将该像素重涂为 P[i]。
5. 输出网格保持原尺寸，控制条和调色板列均保持不变，仅蓝像素被替换或擦除。

**关键洞察**：射线不是画线，而是量尺——其长度编码了一个离散索引，将几何距离转译为调色板中的循环地址。

## 新题 3：滑动镜像围合后按面积选择性填充

**组合逻辑**：[滑动(slide)+镜像(mirror)](产生几何围合的涌现效应) + [洪泛填充(flood_fill)](识别封闭区域) + [面积比较(area_comparison)](决定哪些区域被填色)

**来源原语**：滑动+镜像 ← 11dc524f; 洪泛填充 ← 543a7ed5; 封闭区域 ← 543a7ed5/445eab21; 面积比较 ← 445eab21; 方块锚点 ← 11dc524f

**依赖链**：滑动+镜像改变几何形态→新几何可能产生封闭区域（涌现）→洪泛填充检测封闭性→面积比较筛选填充目标。不执行滑动镜像则无封闭区域产生；不做洪泛填充则无法知道哪些区域封闭；不做面积比较则无法决定填哪个。

多组精灵体滑向各自锚点并镜像，镜像对拼可能围合出封闭区域；仅面积最大的封闭区域被填色输出。

**输入结构**：约 15x15 的黑(0)背景网格。包含 2~3 组"精灵体+方块锚点"配对。每个精灵体为单色 4-连通图形（4~7 像素，形状不规则且非对称），颜色各不相同（如蓝(1)、红(2)、绿(3)）。每组对应一个同色的 2x2 实心方块锚点。精灵体与其同色锚点在同一行或同一列上，且之间仅有黑(0)背景（无阻挡）。生成约束：至少一组精灵体在滑动并镜像后，原件与镜像件共同形成一个 4-连通封闭边界（内部至少有 1 个黑像素被完全包围）；各组的滑动路径互不交叉。

**规则**：
1. 对每组精灵体-锚点配对：沿它们的基数方向连线将精灵体直线滑动，直至精灵体的前缘触碰方块锚点的近边。
2. 以锚点近边为镜像轴，生成精灵体的镜像副本，绘制在轴的另一侧，使用锚点颜色。移除原锚点像素。
3. 对所有组完成上述操作后，在结果网格上执行背景连通性分析：从网格四边出发洪泛标记所有 4-连通可达的黑(0)像素为"外部"。
4. 未被标记的黑(0)像素即为封闭区域。计算每个封闭连通分量的像素面积。
5. 选择面积最大的封闭区域，将其所有像素填充为黄(4)。若存在面积相同的多个最大区域，选择左上角像素行号更小的那个；行号也相同则选列号更小的。
6. 其余封闭区域保持黑(0)不变。

**关键洞察**：滑动镜像本身不以"围合"为目的，但特定的非对称形状在对拼后会涌现出封闭边界——求解者需先预判镜像结果的几何形态，再从多个候选围合中比较面积。

## 新题 4：描边迭代深度编码旋转角度

**组合逻辑**：[描边(outline)](从单层外框改为迭代计层) + [旋转(rotate)](角度由描边深度动态决定) + [区域可达性(region_reachability)](判断描边空间是否足够)

**来源原语**：描边 ← 543a7ed5; 旋转 ← 1a244afd; 区域可达性 ← 543a7ed5; 枢轴像素 ← 1a244afd; 距离保持不变 ← 1a244afd

**依赖链**：描边迭代次数取决于对象间距和网格边界（空间测量）→次数直接编码旋转角度→旋转改变对象形态。测量和变换紧耦合：不测量则不知角度，不旋转则无形态变化。

对每个前景对象计算可向外扩展描边的最大层数，该层数乘以90度作为该对象绕自身中心的顺时针旋转角度。

**输入结构**：约 13x13 的黑(0)背景网格。包含 3~4 个互不接触的单色前景对象（颜色各不相同，如蓝(1)、红(2)、绿(3)、黄(4)），每个对象为 4-连通非对称图形（3~6 像素），各对象的边界框不超过 4x4。对象之间以及对象到网格边缘的最短距离不等（有的间距 1，有的间距 3 以上）。生成约束：至少一个对象的最大描边层数为 0（紧邻另一对象或网格边界），至少一个对象的最大描边层数 >=2。

**规则**：
1. 对每个前景对象 O，计算其"描边深度" depth(O)：从 O 的当前边界开始，尝试向外扩展一层8-邻接描边像素（仅占据黑(0)背景），检查该层是否会触碰任何其他前景对象的像素或与其他对象的描边层冲突。若不冲突则该层成立，继续尝试下一层；否则停止。depth(O) = 成功扩展的最大层数。描边扩展顺序按对象边界框左上角坐标从左上到右下逐个处理，先处理的对象其描边层占据空间后，后续对象的描边空间相应减少。
2. 计算旋转角度：angle(O) = (depth(O) mod 4) * 90 度。
3. 以每个对象边界框的中心（向下取整）为旋转枢轴，将对象顺时针旋转 angle(O) 度。旋转后超出网格边界的像素丢弃。
4. 输出网格仅包含旋转后的对象像素（保持原色），其余为黑(0)。描边层本身不出现在输出中。

**关键洞察**：描边不是视觉装饰而是空间量尺——能展开几层描边反映了对象的"呼吸空间"，这个隐式度量被转译为旋转指令。且描边顺序造成非对称性：先处理的对象会"吃掉"后处理对象的空间。

## 新题 5：频率计数双重编码：排序行序 + 周期瓦片间距

**组合逻辑**：[计数(counting)+排序(sorting)](确定输出行顺序) + [平铺(tiling)](以计数值为周期参数生成行内图案) + [频率统计(frequency_statistic)](同一测量值服务于两个不同用途)

**来源原语**：计数+排序 ← 81c0276b; 平铺 ← e95e3d8e/135a2760; 频率统计 ← 81c0276b; 按计数升序 ← 81c0276b; 周期瓦片 ← e95e3d8e

**依赖链**：颜色频率同时决定两件事——行排列顺序（升序）和行内瓦片周期（频率值即间距）。计数是共享的信息源，它的输出分叉到两个独立用途，任何一个用途缺失都会导致输出不唯一。

统计前景色频率，按频率升序各生成一行，行内以"1个色像素 + (频率-1)个背景像素"为瓦片周期左对齐平铺。

**输入结构**：约 10x10 的黑(0)背景网格。散布着 3~5 种非背景颜色的前景像素（如红(2)、绿(3)、蓝(1)、黄(4)），每种颜色出现 2~6 次不等，位置随机。网格中无任何结构（无线条、无分隔、无分组），纯粹是散点。生成约束：各颜色频率互不相同；最大频率不超过输出宽度的一半（保证瓦片至少能重复两次）。

**规则**：
1. 统计每种非黑(0)颜色在输入网格中出现的像素数，记为 freq(c)。
2. 将颜色按 freq 升序排列。freq 最小的颜色排第 0 行，依此类推。
3. 输出宽度等于输入宽度 W，输出高度等于颜色种数。
4. 对排在第 r 行的颜色 c（其频率为 f = freq(c)）：构造长度为 f 的瓦片单元 = [c, 黑(0), 黑(0), ..., 黑(0)]（1 个 c 像素后跟 f-1 个黑像素）。将该瓦片从第 0 列开始向右重复平铺直到填满 W 列（末尾不足一个完整瓦片则截断）。
5. 输出仅包含上述行矩阵。

**关键洞察**：同一个数值（频率）在两个维度上发挥作用——纵向决定行排列的优先级，横向决定行内图案的疏密节奏。仅看单个示例无法区分"频率决定排序"和"频率决定间距"哪个是巧合哪个是规则，必须对比多个示例。

## 新题 6：框架擦除后内部区域按角度循环换色

**组合逻辑**：[擦除(erase)](去除框架边界) + [循环轮换(cyclic_shift)](颜色沿角度序列移位) + [环绕角度排序(angular_order_around_center)](确定轮换顺序) + [洪泛填充(flood_fill)](识别并填色内部区域)

**来源原语**：擦除 ← d5d6de2d; 循环轮换 ← 880c1354; 环绕角度排序 ← 880c1354; 空心矩形 ← d5d6de2d/445eab21; 封闭区域 ← d5d6de2d/543a7ed5; 洪泛填充 ← 543a7ed5

**依赖链**：框架颜色提供调色板→擦除框架后内部区域需重新着色→角度排序确定区域间的循环顺序→循环移位将每个区域的颜色替换为角度序列中前一个区域的原始框架色。框架同时是"要移除的结构"和"颜色信息的来源"，这种双重角色制造了紧耦合。

多个彩色空心矩形的边框被擦除，其原本的封闭内部按照质心角度排序后循环继承相邻框架的颜色。

**输入结构**：约 14x14 的黑(0)背景网格。包含 3~5 个不同颜色的单像素厚空心矩形框（如红(2)、蓝(1)、绿(3)、黄(4)），各框互不重叠也不嵌套，各框内部均为黑(0)。框的尺寸在 3x3 到 6x6 之间不等。各框的质心分布在网格的不同方位（不共线）。生成约束：各框颜色互不相同；框的质心相对于网格中心点的角度（以正上方为 0 度顺时针度量）互不相同。

**规则**：
1. 识别所有单像素厚空心矩形框，记录每个框的颜色 c_i 和其边界框严格内部区域的像素坐标集 R_i。
2. 计算每个框 i 的内部区域质心（内部像素坐标的算术平均）。
3. 计算网格中心点 G =（(行数-1)/2, (列数-1)/2）。
4. 对每个区域质心，计算其相对于 G 的角度：以 G 正上方为 0 度，顺时针增长。按角度升序排列区域，得到序列 R_0, R_1, ..., R_{n-1}，其原始框架颜色序列为 c_0, c_1, ..., c_{n-1}。
5. 擦除所有矩形框像素为黑(0)。
6. 对每个区域 R_i，将其所有像素填充为 c_{(i-1+n) mod n}，即角度序列中前一个区域的框架颜色。
7. 输出保持原网格尺寸，仅有填充后的内部区域为非黑色。

**关键洞察**：框架的颜色在被擦除前必须先被记录，因为擦除后这些颜色信息就丢失了；而这些颜色恰恰是后续填充的来源——且不是填回自己的区域，而是循环移位后填入邻居的区域。角度排序作为隐含的"邻居"定义需要对比多个示例才能归纳。

## 新题 7：控制条编码反转选择 + 块网格状态翻转

**组合逻辑**：[生成序列(generate_seq)](控制条长度产生rise-fall序列) + [反转编码(invert_code)](序列值决定块的翻转/保持) + [块网格(block_grid)](操作对象)

**来源原语**：生成序列 ← 5d588b4d; 反转编码 ← 6350f1f4; 块网格 ← 6350f1f4; 控制条 ← 5d588b4d; 递增递减游程 ← 5d588b4d; 精灵与空白互逆 ← 6350f1f4

**依赖链**：控制条长度 n 生成 rise-fall 序列 → 序列中每个元素的奇偶性决定对应块是否翻转 → 翻转需要已知精灵体模板（从未被翻转的块推断）。三者缺一不可：不读控制条则无序列；无序列则不知哪些块翻转；不识别精灵体则无法执行翻转。

顶行控制条长度生成递增递减序列，序列各元素的奇偶性逐块决定块网格中每个宏单元是执行精灵-空白翻转还是保持原状。

**输入结构**：约 13x13 的网格。顶部第 0 行有一条品红(6)水平控制条从第 0 列开始，长度 n（2~4）。第 1 行起为一个块网格结构：黑(0)分隔行和分隔列将剩余区域划分为大小相等的方块（每块 3x3 或 4x4）。每个块要么包含一个两色精灵体（由栗(9)和青(8)组成的固定图案），要么是用青(8)填满的均匀空白块。精灵体在所有"精灵块"中相同。灰(5)像素出现在少数块中作为噪声（通配符）。生成约束：n 值使得 rise-fall 序列长度 (2n-1) 不超过块总数；至少有 2 个完好的精灵块可用于推断模板。

**规则**：
1. 读取顶行品红(6)控制条的长度 n。
2. 生成 rise-fall 序列 S = [1, 2, ..., n, n-1, ..., 2, 1]，长度为 2n-1。
3. 识别块网格，将所有块按从左到右、从上到下顺序编号为 B_0, B_1, ...。
4. 从所有完全无灰(5)噪声且含两种颜色（栗(9)和青(8)）的块中，通过多数投票推断精灵体模板。
5. 对前 2n-1 个块，依次对应序列元素 S[j]：若 S[j] 为奇数，则翻转该块（精灵块→用青(8)填满的空白块；空白块→绘制精灵体模板）。若 S[j] 为偶数，保持该块不变。灰(5)像素在判断块状态时视为通配符（匹配精灵或空白均可），翻转后按目标状态正确绘制。
6. 超出序列长度的块（第 2n-1 个之后）保持不变。
7. 输出中分隔行列保持黑(0)（包括原有的灰噪声也清除为黑），控制条行被移除（输出比输入少一行）。

**关键洞察**：控制条不直接告诉你"翻转哪些块"，而是给出一个长度参数，由该参数生成的序列的奇偶模式才是真正的指令——这是一种间接编码，需要先生成序列再逐位解读。

## 新题 8：同色边界配对触发行填充 + 填充长度受标记段高度约束

**组合逻辑**：[填充(fill)](同色端点配对触发行填充，但长度受限) + [长度标记段(length_marker)](标记高度限制填充的最大扩展距离) + [两端同色整行填充(full_row_fill_endpoints_match)](作为触发条件但规则被修改)

**来源原语**：填充+两端同色 ← 22eb0ac0; 长度标记段+标记高度决定长度 ← e7b06bea; 画布边界 ← 22eb0ac0

**依赖链**：同色端点判断决定哪些行有资格被填充→标记段高度决定填充从端点向内延伸的最大像素数→两者共同约束输出，缺少端点判断则不知填哪行，缺少长度约束则不知填多远。

左右边界同色的行被激活填充，但填充不是整行，而是从两端各向内延伸至多 h 个像素（h 由灰色标记段高度给出），中间可能留空。

**输入结构**：约 11x11 的黑(0)背景网格。左边界（第 0 列）和右边界（最后一列）上散布着成对的彩色标记像素：某些行两端颜色相同（如都是红(2)），某些行两端颜色不同（如左蓝(1)右绿(3)），某些行两端无标记（均为黑(0)）。网格内另有一段灰(5)垂直连续像素，位于某列的上方（从第 0 行开始向下延伸 h 行，2 <= h <= 4），不在左右边界列上。生成约束：有同色对的行数 >= 3；网格宽度 > 2h+1（保证两侧填充不会在中间相遇时也有不相遇的情况存在）。

**规则**：
1. 识别灰(5)垂直连续段，计算其高度 h。
2. 对每行检查第 0 列和最后一列的像素颜色：若两者颜色相同且非黑(0)，该行被激活，激活色为该共享颜色。
3. 对每个被激活的行：从第 0 列的标记像素开始向右（不含边界本身）填充激活色，最多填充 h 个像素；从最后一列的标记像素开始向左（不含边界本身）填充激活色，最多填充 h 个像素。若左侧填充和右侧填充在中间相遇或重叠，重叠区域仍为该激活色。
4. 非激活行（两端颜色不同或为黑）保持不变。
5. 灰(5)标记段在输出中被擦除为黑(0)。边界上的标记像素保持不变。

**关键洞察**：原始的"同色端点整行填充"规则被长度标记段截断——标记段高度作为全局参数限制了所有行的填充半径，使得宽行的中间可能留空，形成对称的双侧渐入效果。需对比不同宽度的示例才能区分"填充到相遇"和"填充到 h 就停"。

## 新题 9：隐式几何编码变换指令

**组合逻辑**：[像素放大(pixel_scaling)](缩放因子由几何结构编码) + [旋转(rotate)](角度由几何结构编码) + [控制条(control_bar)](其长度和方向隐式编码变换参数)

**来源原语**：像素放大 ← 4522001f; 旋转 ← 1a244afd; 控制条 ← 5d588b4d; 条长决定序列 ← 5d588b4d; 标记像素 ← 多题

**依赖链**：输入的几何布局本身就是变换程序——水平条长度编码缩放因子，垂直条长度编码旋转次数，条的颜色决定执行顺序。这是同时约束满足结构：先缩放再旋转和先旋转再缩放结果不同，必须从条颜色推断顺序。

输入中的指令条以其长度和方向编码对目标精灵体的变换参数，条的颜色优先级决定变换执行顺序。

**输入结构**：约 9x9 的黑(0)背景网格。包含三类元素：(1) 一个灰(5)色的小精灵体（3~5 像素，4-连通，非对称），位于网格中部偏左上。(2) 一条水平的红(2)控制条（长度 2 或 3，表示缩放因子 s）。(3) 一条垂直的蓝(1)控制条（长度 1~3，表示顺时针旋转 90 度的次数 r）。两条控制条位于精灵体的不同侧，互不接触也不接触精灵体。生成约束：精灵体缩放 s 倍并旋转后的边界框能在合理尺寸的输出网格内放下（输出尺寸 = 精灵体边界框缩放后的尺寸）。

**规则**：
1. 识别灰(5)精灵体，提取其边界框内的图案作为变换目标。
2. 识别红(2)水平条，其像素长度为缩放因子 s。
3. 识别蓝(1)垂直条，其像素长度为旋转次数 r（旋转角度 = r * 90 度顺时针）。
4. 确定执行顺序：红(2)优先于蓝(1)，即先执行缩放，再执行旋转。（隐含规则：颜色编号小的先执行。）
5. 缩放：将精灵体的每个像素扩展为 s x s 的像素块。
6. 旋转：将缩放后的图案绕其中心顺时针旋转 r * 90 度。
7. 输出为恰好容纳旋转后图案的最小矩形网格，精灵体像素保持灰(5)，背景为黑(0)。

**关键洞察**：输入的空间布局本身就是"程序代码"——条的物理属性（方向编码变换类型，长度编码参数值，颜色编码执行优先级）需要全部正确解读才能得到唯一输出。颜色编号与执行顺序的对应关系是隐蔽规则，需对比多个示例（不同 r、s 值以及可能交换的条颜色）才能归纳。

## 新题 10：图例位置映射 + 射线遮挡选择性印章

**组合逻辑**：[位置对应(positional_mapping)](图例精灵与标记色的对应关系) + [射线延伸(ray_cast)](从标记向上发射射线判断可达性) + [印章覆盖(stamp)](将图例精灵印在通过射线测试的标记位置) + [列遮挡(column_coverage)](遮挡物阻断射线则标记不被印章)

**来源原语**：位置对应+图例精灵 ← 20fb2937; 射线延伸+列遮挡 ← 6d58a25d; 印章覆盖 ← 363442ee; 分隔行 ← 20fb2937; 标记像素 ← 20fb2937/363442ee

**依赖链**：图例建立颜色→精灵体的映射（查表）；射线测试筛选哪些标记有资格被印章（空间过滤）；印章操作将精灵体放置到通过筛选的位置（绘制）。三步链式依赖：没有图例无法知道印什么，没有射线无法知道在哪印，没有印章则无最终输出。

下方标记像素向上发射射线，只有射线能无阻碍到达分隔行的标记才获得图例精灵体的印章替换；被中间障碍物遮挡的标记保持不变。

**输入结构**：约 14x12 的网格，黑(0)背景。结构从上到下分三段：(1) 图例区（约 3 行）：包含 2~3 个等尺寸的小正方形精灵体（3x3，各不同色，如红(2)、绿(3)、蓝(1)），每个精灵体正下方一行有一个对应标记色像素（如精灵体下方为黄(4)表示"黄标记→该精灵"）。(2) 一行灰(5)满宽分隔行。(3) 下方工作区（约 8 行）：散布着与图例标记色相同的彩色像素（如黄(4)、橙(7)等），作为待印章的目标标记。工作区中还有若干栗(9)色障碍物像素散布其中。生成约束：部分标记像素正上方至分隔行的路径无障碍（射线畅通），部分被栗(9)像素阻断；每种标记色至少有一个畅通和一个被阻断的实例。

**规则**：
1. 识别灰(5)分隔行，将其上方划为图例区，下方划为工作区。
2. 在图例区中，按从左到右顺序，将每个精灵体与其正下方的标记色像素配对，建立映射表：标记色 → 精灵体图案。
3. 对工作区中每个标记色像素 M：从 M 位置向上逐行扫描，检查其所在列中 M 与分隔行之间是否存在任何非黑(0)像素（栗(9)障碍物）。若存在障碍物，该标记"被遮挡"，在输出中保持为原标记色像素不变。
4. 若无障碍物（射线畅通），查映射表找到对应精灵体，以 M 的位置为精灵体中心对齐点，将精灵体印章到输出中。印章覆盖 M 本身及周围像素。
5. 输出仅包含工作区（分隔行及以上被裁剪掉）。栗(9)障碍物在输出中被擦除为黑(0)。印章按标记从上到下、同行从左到右顺序绘制，后绘制的覆盖先绘制的。

**关键洞察**：图例提供"印什么"的信息，但并非所有标记都有资格接收印章——射线遮挡测试作为空间过滤器，使得同一颜色的标记在不同位置有截然不同的命运。求解者需同时理解查表映射和几何遮挡两套独立逻辑。
