## 新题 1：排序涌现对称

**组合逻辑**：[排序 sort] + [滑动 sliding](创新：排序结果不是最终输出，而是生成待补全的对称前体) → [对称补全 symmetry_completion](创新：对已排序堆叠结构执行双轴镜像补全，标记色需从排序后的近对称结构中推断)

**来源原语**：排序 sort / 滑动 sliding（beb8660c）；对称补全 symmetry_completion / 双轴镜像 biaxial_mirror / 标记色空洞 marker_color_hole（b8825c91）

**依赖链**：排序+右对齐堆叠将散乱线段重组为一个近对称结构；该结构中有一种颜色出现在本应对称的位置上，是待补全的标记色。对称补全依赖排序产生的空间布局才能识别对称轴和标记色。若不排序，线段散落无对称性可言；若不补全，排序结果仍含标记色空洞。

将散乱的彩色水平线段按长度排序右对齐堆叠后，所得图案在水平和垂直轴上近似对称，其中一种颜色标记了对称缺口，用该颜色对称轨道上的已知色替换这些标记即得输出。

**输入结构**：约 12x12 的黑(0)背景网格。底行是一条占满宽度的灰(5)条带。上方散布 4~6 条单像素厚的水平线段，每条线段颜色各不相同（从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)、青(8)中选取），长度互不相同（范围 2~10 像素）。其中恰好一条线段的颜色是品红(6)，这是标记色（但求解者事先不知道哪种颜色是标记色）。各线段初始行位置随机，互不重叠。生成约束：当所有线段按长度从短到长排列并右对齐堆叠于灰条带上方时，非标记色线段构成一个在水平中轴和垂直中轴上都对称的图案，而标记色线段恰好占据了某些对称轨道中的缺失位置。不同示例中标记色线段的长度和位置不同，但标记色始终是品红(6)。

**规则**：
1. 将所有水平线段（不含底部灰条带）按像素长度从短到长排序。
2. 从灰条带正上方一行开始，依次向上逐行放置排序后的线段，每条线段右端对齐网格右边缘。清除线段原始位置的像素。
3. 在排序堆叠后的图案中，识别品红(6)为标记色：它是唯一一种颜色，当将其视为空洞时，剩余像素在水平中轴和垂直中轴上形成完美的反射对称。
4. 对每个四元反射轨道（原位、水平镜像、垂直镜像、180度旋转），用该轨道中已知的非标记颜色替换所有品红(6)像素。
5. 灰条带保持不变。

**关键洞察**：标记色无法从散乱输入中直接看出；必须先排序堆叠使对称结构浮现，才能通过对称性分析反推哪种颜色是标记色——排序是对称分析的前置条件，而非独立步骤。

## 新题 2：重力沉降定嵌套环序

**组合逻辑**：[重力下落 gravity_drop] + [碰撞停止 collision_stop]（创新：重力模拟的结果不直接保留，而是提取每种颜色的沉降像素数）→ [排序 sort / 面积排序 area_ordering] → [同心环绘制 concentric_draw]（创新：环序由重力后各色像素计数决定，而非输入中对象的原始面积）

**来源原语**：重力下落 gravity_drop / 碰撞停止 collision_stop / 盆地 basin / 障碍物 obstacle（28a6681f）；同心环绘制 concentric_draw / 面积排序 area_ordering / 嵌套方环 nested_square_ring（5587a8d0）；排序 sort（beb8660c）

**依赖链**：重力模拟决定每种颜色有多少像素最终沉降到盆地中（部分像素可能卡在障碍物上方而不计入盆地）。沉降计数排序后确定同心环的由外到内顺序。若不模拟重力，无法得知各色的有效沉降数；若不绘制同心环，重力结果只是一堆像素无抽象输出。

将彩色像素在障碍物构成的盆地中做重力沉降，统计落入最底层盆地的各色像素数量，按数量从大到小绘制同心方环。

**输入结构**：约 15x15 的黑(0)背景网格。底部和两侧有栗(9)色的静态墙壁形成一个大盆地，盆地内有 1~2 个栗(9)色水平台阶（宽 3~5 像素），将盆地分为高低不同的区域。盆地上方悬浮着 3~5 种颜色的像素团（每种颜色 3~8 个像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取），各色像素团分布在不同列上方。生成约束：每种颜色的像素总数互不相同；部分像素因台阶阻挡会卡在高处而不落入最底层盆地；至少有两种颜色的"落入最底层盆地的数量"与其"总像素数"不同（即障碍物确实改变了有效计数排名）。

**规则**：
1. 对每个彩色像素执行重力下落：像素垂直向下移动，遇到栗(9)墙壁或已沉降像素时停止。像素不做水平或对角滑动，仅垂直下落。
2. 统计每种颜色落入最底层行区域（即与盆地底部栗色墙壁直接接触或堆叠在底部沉降物上的像素）的数量。卡在中间台阶上方的像素不计入。
3. 按沉降数量从大到小排序各颜色。
4. 创建边长为 2K-1 的正方形输出（K = 颜色种数），绘制同心方环：最外环用沉降数量最多的颜色，依次向内，最中心像素用沉降数量最少的颜色。
5. 若两种颜色沉降数量相同（生成时保证不会出现），按该颜色在输入中最左出现列从左到右排先后。

**关键洞察**：同心环的颜色顺序不由输入中各色对象的原始面积决定，而由重力模拟后的有效沉降数决定——障碍物台阶会截留部分像素，使原本最多的颜色可能因截留而排名下降。

## 新题 3：弯折数与格点位置联合索引重涂

**组合逻辑**：[计数 counting / 弯折数分类 bend_count_class]（创新：弯折数不直接映射颜色，而是作为控制矩阵的行索引）+ [索引映射 index_mapping / 行列位置对应 row_column_correspondence]（创新：列索引由对象在网格中的水平排名决定）→ [重涂色 recolor / 按控制色重涂 recolor_by_control]

**来源原语**：计数 counting / 弯折数分类 bend_count_class / 弯折形状 bent_shape / 拐角 corner_bend（e509e548）；索引映射 index_mapping / 控制矩阵 control_matrix / 行列位置对应 row_column_correspondence（33b52de3）；重涂色 recolor（多题）

**依赖链**：弯折数产生行索引，空间水平排名产生列索引，两者共同确定控制矩阵中的颜色。仅有弯折数无法确定颜色（同弯折数的对象可能得到不同颜色），仅有位置也无法确定颜色（同位置排名的对象可能因弯折数不同而颜色不同）。

统计每个绿色弯折形状的拐角数作为行索引，按形状的水平位置排名作为列索引，在控制矩阵中查找对应颜色并重涂该形状。

**输入结构**：约 14x14 的黑(0)背景网格。网格中散布 6~9 个绿(3)色的 4-连通小形状（每个 3~6 像素），每个形状是单像素宽的弯折路径，含 1、2 或 3 个 L 型拐角。各形状互不相邻（边界框不重叠），水平位置（边界框左边缘列号）互不相同。网格的一个角落（如右下角）放置一个 3xM 的控制矩阵（M = 各弯折数类别中对象的最大个数），矩阵中每个像素是非黑非绿的颜色（从蓝(1)、红(2)、黄(4)、灰(5)、品红(6)、橙(7)、青(8)中选取），矩阵的 3 行对应弯折数 1/2/3。生成约束：具有相同弯折数的形状数量不超过 M；控制矩阵的行数恰好为 3（对应 3 种弯折数），列数等于同一弯折数类别中形状个数的最大值。

**规则**：
1. 找到所有绿(3)色 4-连通形状，对每个形状计算其 L 型拐角数（在所有 2x2 子区域中检查 L 型弯折模式，含四个旋转变体）。
2. 将弯折数映射为控制矩阵的行索引：弯折数 1 → 第 0 行，弯折数 2 → 第 1 行，弯折数 3 → 第 2 行。
3. 在同一弯折数类别内，按形状边界框左边缘的列号从小到大排序，排名（从 0 开始）作为列索引。
4. 用控制矩阵中 (行索引, 列索引) 处的颜色替换该形状的所有绿色像素。
5. 控制矩阵本身从输出中擦除（替换为背景色）。

**关键洞察**：弯折数和水平位置是两个独立维度，任何一个维度单独都无法确定目标颜色；必须同时分析拓扑属性（弯折数）和空间属性（水平排名）才能正确索引控制矩阵。

## 新题 4：旋转掩码驱动的像素放大

**组合逻辑**：[旋转 rotate / 标记定旋转源目 marker_rot_src_tgt]（创新：旋转不作用于对象的空间位置，而是作用于像素放大所用的掩码模板）+ [像素放大 pixel_scale / 自身色选掩码 self_color_selects_mask]（创新：每个块内的掩码是旋转后的全局网格而非原始网格）+ [擦除 erase]

**来源原语**：旋转 rotate / 单像素标记 singleton_marker / 缺角方形标记 missing_corner_marker / 角落对应 corner_correspond / 标记定旋转源目 marker_rot_src_tgt（ecaa0ec1）；像素放大 pixel_scale / 自身色选掩码 self_color_selects_mask / 全局掩码 global_mask / 块单元 block_cell（973e499e）；擦除 erase（ecaa0ec1）

**依赖链**：旋转标记决定旋转角度；旋转角度改变像素放大使用的掩码模板（用旋转后的网格替代原始网格作为掩码参考）；若不解读旋转标记，掩码模板未知；若不执行像素放大，旋转角度没有视觉输出。旋转不改变任何像素的位置，而是改变放大过程中"谁与谁共享掩码位置"的映射关系。

根据标记像素推断旋转角度，将输入网格（去除标记后）做像素放大，但每个块中的掩码使用旋转后的网格而非原始网格来确定。

**输入结构**：约 5x5 的彩色网格（无主导背景色；使用 3~4 种颜色，从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取；黑(0)保留为放大后的空白）。网格四角之一的外侧（紧邻该角但在网格边界之外——实际实现为网格尺寸扩展 1 行 1 列以容纳标记）有一个品红(6)色单像素标记，另一角外侧有一个由 3 个灰(5)像素组成的缺角方形标记（形成 L 形）。生成约束：核心网格为 NxN（N=4 或 5），标记所在行列使实际输入尺寸为 (N+1)x(N+1) 或更大；标记角的选择保证旋转角度为 90 度、180 度或 270 度之一；核心网格在任何旋转下的色位分布均不相同（保证旋转角度可从输出结构唯一确定）。

**规则**：
1. 识别品红(6)单像素标记和灰(5)缺角方形标记，确定它们各自邻接核心网格的哪个角。
2. 品红标记邻接的角为旋转源角，缺角方形缺失角指向的方位邻接的角为旋转目标角。将源角映射到目标角所需的顺时针 90 度旋转次数即为旋转量 R。
3. 从输入中移除所有标记像素，提取 NxN 核心网格 G。
4. 计算旋转后的网格 G' = 将 G 顺时针旋转 R 次。
5. 执行像素放大：输出大小为 (N*N)x(N*N)。对核心网格 G 中位置 (r,c) 处颜色为 c_val 的像素，生成一个 NxN 块放置在输出的 (r*N, c*N) 位置。块内 (i,j) 处：若 G'[i][j] == c_val，则写入 c_val；否则写入黑(0)。
6. 即：每个像素的放大块不是用原始网格 G 做掩码，而是用旋转后的网格 G' 做掩码。

**关键洞察**：旋转不改变任何像素的空间位置，而是改变像素放大的掩码参考系——同样的颜色在不同旋转下会在块内的不同位置出现，产生完全不同的放大图案。这是"对操作的参数施加变换"而非"对数据施加变换"。

## 新题 5：叠加显孔、形状匹配填色后裁剪

**组合逻辑**：[透明叠加 transparent_overlay / 逐像素对齐 cell_align / 并集取前景 union_foreground]（创新：叠加不产生最终输出，而是揭示隐藏的孔洞边界）→ [填充 fill / 形状匹配 shape_matching / 归一化形状对应 normalized_match]（创新：需填充的孔洞只在叠加后才完整可见）→ [裁剪 crop]

**来源原语**：透明叠加 transparent_overlay / 面板 panel / 逐像素对齐 cell_align / 并集取前景 union_foreground（d19f7514）；填充 fill / 带孔对象 object_with_holes / 标记形状 marker_shape / 形状匹配 shape_matching / 归一化形状对应 normalized_match（42f14c03）；裁剪 crop（42f14c03, 890034e9）

**依赖链**：输入分上下两面板，各面板单独看时对象轮廓不完整（各自有不同的缺失区域）。叠加两面板的前景并集后，对象轮廓完整浮现，但其内部存在背景色孔洞。这些孔洞的归一化形状与面板外的标记形状匹配，用标记颜色填充。最后裁剪出该对象的边界框。若不叠加，孔洞形状不完整；若不做形状匹配填充，裁剪输出仍有背景色孔洞。

将上下两面板叠加合并前景轮廓，在合并后的对象中找到背景色孔洞，用与孔洞归一化形状匹配的外部标记形状的颜色填充，最终裁剪出该对象。

**输入结构**：约 20x10 的黑(0)背景网格，高度为偶数，水平中线将网格分为上下两个等大面板（各约 10x10）。上面板包含一个灰(5)色前景对象的部分轮廓（约 6x6 边界框内，8~15 个像素），下面板包含同一对象的另一部分轮廓（同样灰(5)色），两者在对应位置上互补但有部分重叠——叠加后形成一个完整的封闭灰色轮廓。该完整轮廓内部有 2~3 个不同形状的黑色孔洞（每个孔洞 2~4 像素的 4-连通区域）。上面板或下面板的角落区域各放置 2~3 个独立的标记形状，每个标记形状是不同颜色（从红(2)、绿(3)、黄(4)、橙(7)中选取）的小 4-连通图形，其归一化形状（平移到原点后的像素集合）与某一个孔洞匹配。生成约束：每个孔洞恰好匹配一个标记形状（允许旋转或翻转后匹配）；上面板单独无法看出所有孔洞的完整形状；标记形状不与对象轮廓重叠。

**规则**：
1. 将上下面板逐像素对齐，对每个位置取前景并集：若上面板或下面板对应位置为非黑色，输出该非黑色；均为黑色则输出黑色。
2. 在合并结果中，识别灰(5)色封闭轮廓及其内部的黑(0)色 4-连通孔洞分量。
3. 对每个孔洞，计算其归一化形状（将像素坐标平移使最小行列为 0），在所有 4 种旋转和 2 种翻转下生成变体。
4. 将每个孔洞的归一化形状变体与各标记形状的归一化形状匹配。匹配成功则用该标记的颜色填充孔洞的所有像素。
5. 裁剪合并后对象的边界框作为最终输出（包含已填充的孔洞、灰色轮廓，不含标记形状和面板外区域）。

**关键洞察**：任何单一面板都无法暴露完整的孔洞形状——上面板的轮廓缺失恰好遮蔽了部分孔洞边界，必须先合并两面板的互补信息，才能获得可用于形状匹配的完整孔洞。

## 新题 6：标记像素定域、域内像素堆叠成金字塔

**组合逻辑**：[描边 draw_frame / 极值内缩定边框 frame_inset_from_extrema]（创新：边框不作为绘制输出，而是定义独立的堆叠区域边界）+ [堆叠 stack / 重排 rearrange / 奇数宽度递增 odd_width_increment / 基线对齐 baseline_aligned]（创新：每个区域独立堆叠，金字塔大小由区域内像素数决定）+ [擦除 erase]

**来源原语**：描边 draw_frame / 标记像素 marker_pixel / 空心矩形 rectangular_frame / 包围 bounding / 极值内缩定边框 frame_inset_from_extrema（928ad970）；堆叠 stack / 重排 rearrange / 前景列像素 column_pixels / 居中金字塔 centered_pyramid / 基线对齐 baseline_aligned / 奇数宽度递增 odd_width_increment（3d6c6e23）

**依赖链**：标记像素的极值位置确定区域边界（内缩 1 像素）；区域边界划分空间，决定哪些前景像素属于哪个区域；区域内像素按列收集后堆叠为居中金字塔。若无标记定域，像素归属不明；若不堆叠，区域划分无后续操作。

用标记像素组划定多个矩形区域，将每个区域内的散落列像素在该区域底部堆叠为居中金字塔。

**输入结构**：约 18x18 的黑(0)背景网格。网格中有 2~3 组灰(5)色标记像素，每组恰好 4 个，分布在网格的不同位置，每组的 4 个标记像素具有唯一的最上、最下、最左、最右极值（即组内没有两个标记共享同一极值行或极值列）。各组定义的矩形区域（从极值内缩 1 像素）互不重叠。每个区域内散布若干彩色前景像素（颜色从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取），这些像素分布在不同列上，每列上可能有多个像素。生成约束：每个区域内前景像素的总数是某个正整数的平方（如 1、4、9、16），且每列上的前景像素数之和等于从 1 开始的连续奇数序列（1, 3, 5, ...）的某个前缀的某种排列（即像素总数必须是完全平方数）；不同区域的金字塔大小至少有一对不同。

**规则**：
1. 识别每组 4 个灰(5)标记像素，根据它们的行列极值确定矩形边界：上边 = 最小行 + 1，下边 = 最大行 - 1，左边 = 最小列 + 1，右边 = 最大列 - 1。
2. 对每个矩形区域，收集其内部所有非黑非灰的前景像素。按列从左到右、每列从上到下读取颜色序列。
3. 将该颜色序列重组为居中金字塔：第一个像素成为顶行（宽 1，水平居中于区域），接下来 3 个像素成为第二行（宽 3，居中），接下来 5 个像素成为第三行（宽 5，居中），以此类推。金字塔底行与区域下边对齐。
4. 清除区域内原始像素位置，将金字塔绘制在区域底部居中位置。
5. 擦除所有灰(5)标记像素（替换为黑(0)背景）。区域外的像素不变。

**关键洞察**：标记像素的排列不是用来画框的——它们是空间分区器，将网格划分为独立的金字塔堆叠工厂；每个工厂的产出形态（金字塔层数）由其辖区内的像素存量决定，而非由标记位置的几何形态决定。

## 新题 7：双印章叠加、控制矩阵裁决冲突

**组合逻辑**：[印章覆盖 stamping / 周期排布 periodic_layout]（创新：两个不同精灵体同时进行周期印章）+ [透明叠加 transparent_overlay / 逐像素对齐 cell_align]（创新：叠加两层印章结果）+ [索引映射 index_mapping / 控制矩阵 control_matrix / 按控制色重涂 recolor_by_control]（创新：控制矩阵不重涂既有对象，而是裁决两层叠加的冲突像素取哪一层的颜色）

**来源原语**：印章覆盖 stamping / 精灵体 sprite / 周期排布 periodic_layout（d304284e）；透明叠加 transparent_overlay / 逐像素对齐 cell_align / 并集取前景 union_foreground（d19f7514）；索引映射 index_mapping / 控制矩阵 control_matrix / 行列位置对应 row_column_correspondence / 按控制色重涂 recolor_by_control（33b52de3）

**依赖链**：两个精灵体各自周期印章生成两层前景图案，两层叠加产生冲突区域（均为前景的位置）。控制矩阵以周期格点的行列坐标为索引，指定冲突位置保留哪一层。三步缺一不可：不印章则无图案；不叠加则只有单层无冲突；无控制矩阵则冲突区域颜色不确定。

两个精灵体分别在网格上周期印章，叠加两层印章图案，在冲突位置（两层均有前景像素）用控制矩阵查表决定保留哪一层的颜色。

**输入结构**：约 16x16 的黑(0)背景网格。左上角紧贴的 2~3 行 x 2~3 列区域放置精灵体 A（蓝(1)色前景，含 3~5 个像素的不规则 4-连通形状）。紧邻精灵体 A 右侧（隔 1 列背景）放置精灵体 B（红(2)色前景，与 A 尺寸相同的边界框但形状不同）。网格右下角放置一个 PxQ 的控制矩阵（P = 纵向印章周期数, Q = 横向印章周期数），矩阵中每个像素为蓝(1)或红(2)，表示该格点位置冲突时保留哪个精灵体的颜色。生成约束：两个精灵体的边界框尺寸相同（如均为 3x3）；周期间距 = 边界框宽度 + 1（水平）和 边界框高度 + 1（垂直）；至少存在 3 个周期格点位置两层均有前景像素（即存在冲突）；控制矩阵中蓝和红均至少出现一次。

**规则**：
1. 以精灵体 A 的边界框左上角为起点，按水平间距（bbox 宽 + 1）和垂直间距（bbox 高 + 1）在整个网格上周期印章精灵体 A 的掩码，所有前景像素着蓝(1)色。超出网格部分裁剪。得到图层 L_A。
2. 以精灵体 B 的边界框左上角为起点，使用相同的水平和垂直间距周期印章精灵体 B 的掩码，所有前景像素着红(2)色。得到图层 L_B。
3. 初始化输出为黑(0)背景。对每个像素位置 (r,c)：
   - 若仅 L_A 有前景 → 输出蓝(1)
   - 若仅 L_B 有前景 → 输出红(2)
   - 若两层均有前景（冲突）→ 计算该位置属于哪个周期格点 (gi, gj)（gi = 行偏移 / 垂直间距，gj = 列偏移 / 水平间距，两个精灵体共享同一格点坐标系），查控制矩阵 (gi, gj) 处的颜色：蓝则保留 L_A，红则保留 L_B
   - 若两层均无前景 → 输出黑(0)
4. 擦除控制矩阵区域（替换为背景色）和原始精灵体区域中未被周期印章覆盖的部分。

**关键洞察**：冲突解决规则不是固定优先级（如"后画的覆盖先画的"），而是逐格点由外部控制矩阵指定——同一对精灵体在不同格点位置可以有不同的冲突裁决结果，这使得叠加输出呈现非均匀的图案。

## 新题 8：周期约束下的断线修复与噪声擦除

**组合逻辑**：[擦除 erase]（创新：擦除对象不仅是对角噪声，还包括不符合周期约束的孤立前景像素）+ [补线 line_completion / 间隙长度限制 gap_length_constraint]（创新：间隙填充不仅由局部连续性判断，还需全局周期一致性验证）+ [补全 complete / 周期平铺图案 periodic_tile / 被遮挡 occluded]（创新：周期性不用于填充被遮挡区域，而是作为线条修复的验证约束）

**来源原语**：擦除 erase / 对角噪声 diagonal_noise / 忽略干扰项 ignore_distractors / 间隙长度限制 gap_length_constraint（7b80bb43）；补线 line_completion / 直线段 straight_line_segment（7b80bb43）；补全 complete / 周期平铺图案 periodic_tile / 被遮挡 occluded（abbfd121）

**依赖链**：输入是一个由水平和垂直线条构成的周期网格图案，但被两种损坏破坏：(a) 对角线噪声像素添加在线条附近；(b) 部分线条段被擦除形成断口。修复过程中，擦除噪声依赖区分"属于周期线条图案的像素"和"不属于的噪声像素"；补线需要知道周期间距以确定哪些间隙应填充、填充到什么位置。周期性分析为两个操作提供共同约束：噪声判定和间隙填充都不能独立于周期结构完成。

擦除不属于底层周期线条图案的对角噪声像素，并依据周期间距修复线条中的断口。

**输入结构**：约 15x15 的黑(0)背景网格。底层结构是由蓝(1)色水平线和蓝(1)色垂直线构成的周期网格，水平线间距 h（3~5 行），垂直线间距 w（3~5 列），线条宽度 1 像素。该周期网格被两种损坏破坏：(a) 每条线上有 1~3 个断口，每个断口长度 1~3 像素（断口处像素被替换为黑色背景）；(b) 在断口附近及其他随机位置，添加了若干蓝(1)色对角噪声像素——这些像素不与任何蓝色线条正交相邻（4-连通），仅与其他蓝色像素对角相邻（8-连通但非 4-连通）。此外，还有 2~4 个蓝(1)色干扰像素，它们虽然与某条线 4-连通相邻，但出现在不符合周期间距的位置上。生成约束：断口不出现在线条交叉点；周期间距从未损坏的线条段可推断（至少有两条完整的水平线和两条完整的垂直线未被完全中断）；对角噪声像素总数 >= 3 以确保非空。

**规则**：
1. 从输入中识别所有蓝(1)像素的正交连通分量。长度 >= 3 且为纯水平或纯垂直的分量是可靠线段。
2. 从可靠线段推断周期间距：水平线的行坐标之间的最大公约数模式确定 h，垂直线的列坐标确定 w。
3. 擦除对角噪声：删除所有与线条仅对角相邻（无 4-连通蓝色邻居）的蓝色像素。
4. 擦除周期外干扰：删除所有位于不符合周期行坐标（对水平线）或周期列坐标（对垂直线）的蓝色像素。一个蓝色像素"符合周期"当且仅当它所在的行是某条水平周期线的行，或它所在的列是某条垂直周期线的列。
5. 补线：对每条周期线（由周期间距确定的所有应存在线条的行和列），扫描该行/列上的间隙（连续背景像素段）。若间隙长度 <= 3 且间隙两侧在该行/列上有蓝色像素，则用蓝(1)色填充该间隙。
6. 保留所有线条交叉点。

**关键洞察**：对角噪声和周期外干扰像素颜色与线条相同，仅凭局部连通性无法可靠区分——必须先推断全局周期间距作为判据，而周期间距的推断又需要先忽略噪声找到可靠线段。两步互为前提，形成引导式迭代而非简单的线性流水线。

## 新题 9：位移路径引导射线方向与端点裁剪

**组合逻辑**：[平移 translate / 端点编码位移 endpoints_encode_disp]（创新：位移向量不平移对象，而是编码射线方向）+ [射线延伸 ray_extend / 延伸至边界 extend_to_edge]（创新：射线起点和方向由位移路径决定而非固定为对角方向）+ [裁剪 crop / 包含 containment]

**来源原语**：平移 translate / 路径端点 path_endpoint / 端点编码位移 endpoints_encode_disp（2b9ef948）；射线延伸 ray_extend / 对角放射 diagonal_radiation / 延伸至边界 extend_to_edge / 孤立像素 isolated_pixel（ea786f4a, 2b9ef948）；裁剪 crop / 包含 containment（42f14c03, 890034e9）

**依赖链**：位移路径的两个彩色端点编码一个方向向量；从路径起始端点出发，沿该方向绘制射线至网格边界。多条路径产生多条射线。所有射线和端点的联合边界框裁剪为输出。若不解码路径位移，射线方向未知；若不画射线，裁剪区域无法确定（裁剪框由射线端点极值决定）。

解码每条灰色路径两端彩色端点的位移向量作为射线方向，从起始端点沿该方向画射线至网格边界，裁剪所有射线和端点的最小边界框。

**输入结构**：约 15x15 的黑(0)背景网格。网格中有 2~4 条独立的灰(5)色路径（每条路径是 4-连通的灰色像素链，宽度 1 像素，可弯折），每条路径的两个末端各连接一个彩色端点像素。每条路径的起始端点为绿(3)色，终止端点为黄(4)色（或统一地：每条路径两端颜色相同但不同路径颜色不同，从蓝(1)、红(2)、绿(3)、橙(7)中选取）。生成约束：每条路径的位移向量（从绿端点到黄端点的行列差）归一化后为 8 个罗盘方向之一（上、下、左、右、四个对角）；不同路径的归一化方向互不相同；从绿端点沿该方向画射线不会经过其他路径的像素；各路径互不相邻。

**规则**：
1. 识别每条灰(5)色 4-连通路径及其两个非灰端点。将颜色编号较小的端点定为起始端点，颜色编号较大的定为终止端点。（生成时保证每条路径两端颜色编号不同。）
2. 计算位移向量：从起始端点到终止端点的 (delta_row, delta_col)。将其归一化为单位步长方向 (sign(delta_row), sign(delta_col))，得到射线方向。
3. 从起始端点位置出发（包含起始端点自身），沿归一化方向每步走 1 格，用起始端点的颜色绘制射线像素，直到到达网格边界（最后一个仍在网格内的位置）。
4. 擦除所有灰色路径像素和终止端点像素。
5. 计算所有保留的非背景像素（射线像素 + 起始端点）的最小边界框，裁剪该区域作为输出。

**关键洞察**：灰色路径的弯折走向是干扰信息——真正有用的只有两个端点的相对位置差；路径的存在是为了在视觉上混淆方向判断，迫使求解者提取端点坐标而非追踪路径形状。

**依赖链**：每个精灵体配一个控制像素，控制像素相对于输出画布中心的方位决定精灵体的印章位置（如左上/正上/右上等九宫格位置）。多个精灵体印章到同一画布后，按边界框面积从大到小绘制（大的先画、小的后画），小精灵体覆盖大精灵体的重叠区域。方位选择和面积排序缺一不可：不看方位则印章位置不确定，不按面积排序则重叠区域颜色不确定。

每个精灵体的控制像素的方位决定其在输出画布上的九宫格落点，多个精灵体按面积从大到小依次绘制，小者覆盖大者。

**输入结构**：约 18x18 的黑(0)背景网格。网格中有 3~5 个不同颜色的精灵体（4-连通单色小图形，每个 3~8 像素，颜色从蓝(1)、红(2)、绿(3)、橙(7)、青(8)中选取），各精灵体分散在网格上半区，互不相邻。网格下半区中心有一个 9x9 的灰(5)色填充正方形作为输出画布标记。每个精灵体附近（边界框外 1~2 像素处）有一个品红(6)色控制像素。生成约束：各控制像素相对于灰色正方形中心的方位（九宫格：上/下/左/右/左上/右上/左下/右下/中心）互不相同；精灵体的边界框面积（宽x高）互不相同；所有精灵体的边界框均不超过 3x3。

**规则**：
1. 识别灰(5)正方形画布，记其中心为 (cr, cc)。
2. 对每个精灵体，找到其关联的品红(6)控制像素（与该精灵体边界框曼哈顿距离最近的品红像素）。
3. 判断控制像素相对于画布中心的方位：行维度——控制像素行 < cr 则"上"，= cr 则"中"，> cr 则"下"；列维度——控制像素列 < cc 则"左"，= cc 则"中"，> cc 则"右"。两维度组合得到九宫格位置。
4. 将 9x9 画布等分为 3x3 的九宫格区域（每个 3x3）。每个精灵体的边界框左上角对齐到对应九宫格区域的左上角。
5. 按精灵体边界框面积从大到小排序，依次绘制。先画面积大的，后画面积小的——后画的覆盖先画的像素。
6. 输出为 9x9 画布区域。擦除画布外所有内容（精灵体原始位置、控制像素、灰色背景填充替换为精灵体绘制结果，未被覆盖的画布位置保持黑(0)背景）。

**关键洞察**：控制像素的方位信息和精灵体的面积信息分别决定了"画在哪里"和"谁画在谁上面"——两个完全独立的属性共同决定最终像素颜色，仅知其一无法确定输出。
