## 新题 1：滑动吞噬标记后按吞噬数重涂色

**组合逻辑**：[滑动(slide)](创新：滑动路径覆盖散布标记) → [计数(counting)](创新：统计被覆盖的标记数) → [重涂色(recolor)](按吞噬数映射目标色)

**来源原语**：滑动(slide) ← f3e62deb/3906de3d；计数(counting) ← 1190e5a7/9565186b；重涂色(recolor) ← aabf363d/bb43febb；碰撞阻挡(collision_blocking) ← 3906de3d；边缘实心条(solid_edge_bar) ← 13713586

**依赖链**：滑动改变精灵的空间位置 → 新位置决定精灵覆盖了哪些标记像素 → 被覆盖的标记数量决定精灵的最终颜色。计数结果只有在滑动完成后才能确定，重涂色规则只有在计数完成后才能执行。

将散布的标记像素视为"资源"，每个精灵滑向边缘时吞噬路径上的标记，吞噬数量决定最终颜色。

**输入结构**：约 15x15 黑(0)背景网格。顶部第 0 行为灰(5)实心条（满行）。网格中散布 3-5 个单色精灵体（每个精灵为 4-连通单色形状，3-6 像素，颜色各不相同，可为红(2)、绿(3)、蓝(1)、橙(7)等）。精灵体分布在第 3-12 行之间。网格中另有 8-15 个孤立的黄(4)标记像素，散布在各行各列，不与任何精灵相邻。生成约束：每个精灵所在列的正上方（从精灵顶部到灰条之间）至少有 1 个黄标记像素；不同精灵的列范围（bounding box 水平投影）互不重叠。

**规则**：
1. 识别顶部灰(5)满行为边缘实心条，确定滑动方向为向上。
2. 每个精灵整体向上平移，直到其 bounding box 顶边紧贴灰条下方（即 bounding box 顶行 = 第 1 行）。
3. 精灵在滑动过程中，其 bounding box 扫过的矩形区域（从原始位置到最终位置的竖直条带）内所有黄(4)标记像素被"吞噬"——在输出中这些黄像素消失（变为黑(0)）。
4. 统计每个精灵吞噬的黄标记像素数量 N。
5. 根据 N 重涂精灵颜色：N=1 → 红(2)；N=2 → 蓝(1)；N=3 → 绿(3)；N>=4 → 品红(6)。精灵形状不变，仅颜色改变。
6. 不在任何精灵列范围内的黄标记像素保持不变。灰条保持不变。

**关键洞察**：精灵的最终颜色不取决于它的初始颜色或位置，而取决于它滑动路径上恰好有多少标记像素——这是一种"空间采样"决定属性的规则，只有理解了滑动路径的几何范围后才能确定计数。

## 新题 2：旋转对称补全像素作为射线源点

**组合逻辑**：[对称补全(symmetry_completion)](检测缺失臂并填充) → [射线延伸(ray_extend)](创新：补全像素成为射线起点，方向由对称中心决定)

**来源原语**：对称补全(symmetry_completion) ← 1b60fb0c；射线延伸(ray_extend) ← 13713586/25d487eb；旋转对称(rotational_symmetry) ← 1b60fb0c；方向指示(direction_indication) ← 25d487eb

**依赖链**：旋转对称分析确定哪些像素缺失 → 补全像素的位置决定射线的起点 → 补全像素相对于对称中心的方位决定射线方向。不完成对称分析就无法知道射线从哪里出发、往哪里延伸。

识别旋转对称缺失臂，补全后的新像素自动成为向外辐射射线的发射点。

**输入结构**：约 13x13 黑(0)背景网格。中心区域有一个蓝(1)像素组成的图案，该图案具有 4 重旋转对称性（绕中心旋转 90 度自重合），但恰好缺少一个方位的"臂"（约 3-5 个像素的连通区域）。完整的三个臂从中心向外延伸 3-4 格，呈辐射状。缺失臂对应的位置为黑(0)背景。整个蓝图案约 12-20 像素，对称中心在网格的大致中心。对称中心到网格边缘的距离至少为 5 格（确保射线有足够延伸空间）。

**规则**：
1. 确定蓝(1)图案的旋转对称中心（所有蓝像素集合在 90 度旋转下与自身最大重合的中心点）。
2. 将现有蓝像素顺时针旋转 90 度；旋转后落在黑(0)位置的像素即为缺失的补全像素，将这些位置标记为红(2)。
3. 对每个红(2)补全像素，计算它相对于对称中心的方向向量（行偏移 dr, 列偏移 dc）。
4. 将方向向量归一化为单位步长（dr 和 dc 各自取符号值 -1/0/+1），得到射线方向。
5. 从每个红像素出发，沿该方向逐格延伸射线，将路径上的黑(0)像素涂为红(2)，直到到达网格边界（最后一个涂色像素为边界行/列上的像素）。
6. 射线遇到非黑像素（蓝(1)或已有红(2)）时停止，不覆盖该像素。
7. 原始蓝(1)像素保持不变。

**关键洞察**：补全像素承担双重角色——它既是对称修复的结果，又是射线延伸的源头。射线方向无需额外标记指示，而是由补全像素自身在对称结构中的径向位置隐式编码。

## 新题 3：分区数决定外推步数后嵌套放置

**组合逻辑**：[计数(counting)](统计框架内部分区数) → [序列外推(sequence_extrapolation)](创新：分区数作为外推步数参数) → [嵌套放置(nest_inside)](将外推结果放入对应框架)

**来源原语**：计数(counting) ← 1190e5a7；序列外推(sequence_extrapolation) ← 351d6448；嵌套放置(nest_inside) ← 8698868d；分隔栅格(divider_grid) ← 1190e5a7；面板帧(panel_frame) ← 351d6448；空心框架(hollow_frame) ← 8698868d；恒定偏移平移(constant_offset_translation) ← 351d6448

**依赖链**：框架内部的分隔栏数量决定要外推多少步 → 动画序列被外推到第 N 帧 → 第 N 帧的精灵图案被放入提供 N 值的那个框架内部。三步操作形成参数化循环：结构属性→运算参数→结果放回同一结构。

每个空心框架内部的横隔栏数量告诉你动画要往前推几帧，推出的那帧精灵放回该框架。

**输入结构**：约 20x14 黑(0)背景网格，由一条灰(5)竖直满列分隔为左右两区。左区（约 20x5）：4 个等高小面板纵向堆叠，面板间由灰(5)满行分隔；每个面板约 4x5，内含一个绿(3)小精灵（3-4 像素的 4-连通形状），精灵在各面板中沿固定方向逐帧平移 1 格（如每帧右移 1 列），背景为黑(0)。右区（约 20x8）：2-3 个蓝(1)空心正方形框架（外框尺寸 6x6，边框 1 像素厚，内部 4x4），框架竖直排列互不重叠。每个框架内部有 0-3 条橙(7)满宽横隔栏（宽 1 像素，横跨框架内部 4 列）。不同框架的横隔栏数量互不相同。生成约束：动画序列的外推方向和步长保证在最大所需步数内精灵不会超出面板尺寸。

**规则**：
1. 识别左区的动画序列：从上到下 4 帧，推断绿精灵的逐帧平移向量（行偏移, 列偏移）。
2. 对右区每个蓝框架，统计其内部橙(7)横隔栏的数量 N。
3. 将动画序列从第 4 帧继续外推 N 步，得到第 (4+N) 帧的精灵位置和形状。
4. 将外推得到的精灵（保持绿(3)色和原始形状）放置到对应框架的内部区域中心（精灵 bounding box 中心对齐框架内部区域中心，若无法精确居中则偏左上）。
5. 放置精灵时，擦除该框架内部的所有橙(7)横隔栏（变为黑(0)）。
6. 灰分隔线、蓝框架边框、左区内容保持不变。

**关键洞察**：框架的内部结构（隔栏数量）不是装饰性特征，而是编码了一个运算参数——它决定了动画要向未来推演多远。这使得同一个动画序列对不同框架产生不同的嵌套结果。

## 新题 4：平行四边形围合区域的像素密度决定重涂色

**组合逻辑**：[连线/平行四边形构造(line_drawing)] → [计数(counting)](创新：以几何构造的围合区域作为计数容器) → [重涂色(recolor)](按密度排名分配颜色)

**来源原语**：连线(line_drawing) ← cb227835；对角分解(diag_decompose) ← cb227835；标记像素(marker_pixel) ← cb227835/992798f6；计数(counting) ← 9565186b/1190e5a7；重涂色(recolor) ← 9565186b/bb43febb；频率排序(frequency_ranking) ← 9565186b

**依赖链**：标记像素对的位置决定平行四边形的几何形状 → 几何形状决定围合区域的边界 → 区域边界决定哪些散布像素被包含 → 包含数量的排名决定各区域的重涂颜色。不做几何构造就无法定义计数边界，不做计数排名就无法确定颜色分配。

构造平行四边形形成"计数篮"，各篮内捕获的散布像素数量决定篮子本身的最终颜色。

**输入结构**：约 18x18 黑(0)背景网格。网格中有恰好 3 对标记像素，每对同色：第一对红(2)、第二对蓝(1)、第三对橙(7)。每对中两个标记像素的行列偏移同时具有行分量和列分量（即不在同一行也不在同一列），且行列偏移幅度不等。网格中另散布 15-25 个灰(5)孤立像素（互不相邻，不与标记像素相邻）。生成约束：三个平行四边形互不重叠；每个平行四边形内部至少包含 2 个灰像素；三个平行四边形内部的灰像素数量互不相同。

**规则**：
1. 对每对同色标记像素，将两点之间的向量分解为一个 45 度对角向量和一个剩余的水平/竖直向量（与参考题 cb227835 相同的分解方式）。
2. 以这两个分向量为邻边、两个标记像素为对角顶点，绘制平行四边形轮廓。轮廓颜色为绿(3)，使用逐像素 Bresenham 风格画线（对角段沿 45 度逐像素，轴对齐段沿行/列逐像素）。标记像素本身被绿色覆盖。
3. 确定每个平行四边形的"内部"：被绿(3)轮廓完全围合的黑(0)或灰(5)像素集合（使用 4-连通洪水填充从轮廓内侧开始判定）。
4. 统计每个平行四边形内部的灰(5)像素数量。
5. 按灰像素数量从多到少排序三个平行四边形。将内含灰像素最多的平行四边形内部所有灰(5)像素重涂为红(2)；第二多的重涂为蓝(1)；最少的重涂为黄(4)。
6. 绿(3)轮廓像素、不在任何平行四边形内部的灰(5)像素、黑(0)背景均保持不变。

**关键洞察**：平行四边形不是输入中已有的结构，而是由标记像素对的空间关系"生成"的几何容器。重涂色规则依赖于对这些动态生成容器内部内容的统计排名——容器形状、内容多少、最终颜色三者形成不可跳步的推理链。

## 新题 5：凸耳定向镜像后切比雪夫连线

**组合逻辑**：[镜像(mirror)](凸耳决定轴向) → [连线(connect)](创新：镜像副本作为路径终点，切比雪夫路径连接原件与副本)

**来源原语**：镜像(mirror) ← dc2e9a9d；凸耳(tab) ← dc2e9a9d；连线(connect) ← 992798f6；切比雪夫最短路径(chebyshev_shortest) ← 992798f6；对侧放置(opposite_place) ← dc2e9a9d；颜色按方位定(color_by_orient) ← dc2e9a9d

**依赖链**：凸耳方位决定镜像轴 → 镜像轴决定副本放置位置 → 原件与副本的相对位置决定路径几何 → 路径颜色由凸耳轴向（水平/竖直）决定。镜像创造了连线的目标端点，连线的形态又反过来依赖于镜像的方向选择。

每个带凸耳的轮廓先镜像到对面，然后原件与镜像副本之间用最短国际象棋王步路径连接。

**输入结构**：约 17x17 黑(0)背景网格。网格中有 2 个绿(3)空心轮廓对象（4-连通，每个约 8-12 像素，形成不规则封闭环，bounding box 约 4x4 到 5x5）。每个轮廓在其 bounding box 的恰好一条边上有一个单像素凸耳（超出 bbox 的 1 个绿像素）。两个轮廓的凸耳方向不同（一个在左或右，另一个在上或下）。两个轮廓位于网格中部偏各自镜像方向的一侧（确保镜像副本有空间放置且不超出网格）。生成约束：两个轮廓及其镜像副本的 bounding box 互不重叠；原件到副本之间有至少 3 格的空白间隔。

**规则**：
1. 对每个绿(3)轮廓，识别凸耳像素（bbox 外的唯一绿像素），确定凸耳方向：
   - 凸耳在 bbox 左侧或右侧 → 水平镜像轴
   - 凸耳在 bbox 上方或下方 → 竖直镜像轴
2. 将轮廓（含凸耳）沿镜像轴翻转，放置到 bbox 对侧（与原件 bbox 之间间隔 1 格背景行/列）。副本颜色规则：水平镜像的副本涂蓝(1)；竖直镜像的副本涂青(8)。
3. 对每对原件-副本，找到原件上离副本最近的像素 P 和副本上离原件最近的像素 Q（Chebyshev 距离最小的一对；若存在多对等距，选行号最小的，再选列号最小的）。
4. 从 P 向 Q 画一条 Chebyshev 最短路径（国际象棋王步：可走 8 方向，每步行列各变化 0 或 1）。路径上每个中间像素（不含 P 和 Q 本身）涂色：若该轮廓是水平镜像的，路径涂橙(7)；若是竖直镜像的，路径涂品红(6)。
5. 两条路径互不影响（生成约束保证路径不交叉）。原始绿(3)像素保持不变。

**关键洞察**：镜像操作不仅产生视觉副本，更创造了连线操作所需的端点——没有镜像就没有目标可连。凸耳这个单一几何特征同时决定了三件事：镜像方向、副本颜色、路径颜色。

## 新题 6：像素面积决定滑动优先级与遮挡裁决

**组合逻辑**：[计数(counting)](统计各精灵面积) → [滑动(slide)](创新：面积排名决定处理顺序) → [遮挡覆盖(occlusion_overwrite)](创新：面积作为遮挡优先级的裁决依据)

**来源原语**：计数(counting) ← 9565186b；滑动(slide/sliding) ← 3906de3d/f3e62deb；碰撞阻挡(collision_blocking) ← 3906de3d；遮挡覆盖(occlusion_overwrite) ← 13713586；边缘实心条(solid_edge_bar) ← 13713586；按距离排序绘制(draw_ordered_by_distance) ← 13713586；频率排序(frequency_ranking) ← 9565186b

**依赖链**：像素面积统计 → 决定滑动处理顺序（大优先） → 先到者成为后续精灵的物理障碍 → 若最终 bounding box 重叠，面积大者覆盖面积小者的重叠像素。同一个属性（面积）贯穿三个决策层级，不做面积排序就无法确定任何后续步骤。

精灵按面积从大到小依次向边缘滑动并堆叠，体积大的先定位且在重叠时享有遮挡优先权。

**输入结构**：约 16x16 黑(0)背景网格。第 0 行为栗(9)实心满行条。网格中有 4-5 个单色精灵体，颜色互不相同（可为红(2)、绿(3)、蓝(1)、黄(4)、品红(6)），每个精灵是 4-连通形状，像素数在 3-8 之间且互不相同。精灵分布在第 4-14 行之间。生成约束：至少有两个精灵的 bounding box 在列方向有 1-2 列重叠（保证滑动后可能产生遮挡冲突）。

**规则**：
1. 统计每个精灵的像素数量（面积），按面积从大到小排序。面积相同时（由生成约束保证不会出现），按 bounding box 左上角行号从小到大排序。
2. 按排序顺序依次处理每个精灵：将精灵整体向上滑动，保持形状不变。精灵停止条件为：其 bounding box 顶行到达第 1 行（紧贴栗色条下方），或者其任一像素的目标位置已被先前停止的精灵占据。
3. 所有精灵停止后，检查遮挡冲突：若两个已停止精灵的像素占据了同一个格子（因形状不规则且列方向有重叠导致），面积较大的精灵保留该格子像素，面积较小的精灵在该格子的像素被擦除为黑(0)。
4. 栗(9)实心条保持不变。原始位置的精灵像素全部清除（输出中精灵只出现在滑动后的新位置）。

**关键洞察**：面积不仅是一个被动统计量，而是同时扮演"调度器"（决定谁先移动）和"裁判"（决定冲突中谁胜出）两个角色。先移动者占据有利位置，又因面积大而在遮挡时获胜——这两个优势来自同一属性但通过不同机制生效。

## 新题 7：矩形内部提取后布尔叠加生成印章模板

**组合逻辑**：[重涂色/内部提取](提取矩形内部像素集) → [透明叠加(transparent_overlay)](创新：叠加对象不是面板而是提取出的内部掩码) → [印章覆盖(stamp)](创新：叠加结果成为印章模板复制到多个占位对象)

**来源原语**：重涂色(recolor) ← bb43febb；内部与边框(interior_vs_border) ← bb43febb；透明叠加(transparent_overlay) ← dae9d2b5；布尔并集合并(boolean_union) ← dae9d2b5；印章覆盖(stamp) ← 321b1fc6；掩码匹配(mask_matching) ← 321b1fc6；占位对象(placeholder) ← 321b1fc6；实心矩形(filled_rectangle) ← bb43febb

**依赖链**：两个矩形各自的内部像素集 → 布尔并集产生组合掩码 → 该掩码作为印章源被复制到各占位对象。印章的形状不是直接可见的，必须先做内部提取再做合并才能得到。

从重叠矩形的内部区域推导出组合掩码，再将该掩码批量复制到远处的占位形状上。

**输入结构**：约 18x12 黑(0)背景网格，由一条灰(5)竖直满列（第 8 列）分为左区（列 0-7）和右区（列 9-17）。左区有两个实心矩形，矩形 A 为红(2)色（高宽至少 4x4），矩形 B 为蓝(1)色（高宽至少 4x4）。两个矩形有部分区域重叠（重叠区域至少 2x2）。重叠处颜色为蓝(1)（B 在 A 上层）。右区有 2-3 个黄(4)单色占位对象（4-连通形状），每个占位对象的归一化掩码（相对于自身 bbox 的像素位置集合）与即将生成的组合掩码完全相同。生成约束：矩形 A 和 B 的内部区域的布尔并集（见规则）形成一个连通形状，该形状的归一化掩码与右区占位对象匹配。

**规则**：
1. 在左区识别两个实心矩形（红 A、蓝 B），确定各自的 1 像素边框和内部区域。
2. 提取矩形 A 的内部像素位置集合 S_A（边框内所有格子，不论当前颜色）。
3. 提取矩形 B 的内部像素位置集合 S_B。
4. 计算布尔并集 S = S_A ∪ S_B，得到组合掩码。将该掩码归一化（平移使 bbox 左上角为 (0,0)）。
5. 在右区，将每个黄(4)占位对象替换为组合掩码：在占位对象 bbox 位置处，按掩码形状涂品红(6)像素，占位对象原有的黄(4)像素全部替换。
6. 左区处理：将矩形 A 和矩形 B 的所有像素（边框+内部）擦除为黑(0)。
7. 灰(5)分隔列保持不变。

**关键洞察**：印章模板并非输入中直接可见的任何形状，而是通过两个矩形内部区域的布尔运算"隐式合成"的。求解者必须理解内部提取规则、执行空间集合运算，才能推断出印章应该长什么样。
