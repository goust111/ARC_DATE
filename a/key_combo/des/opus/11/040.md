## 新题 1：邻接投票决定补全颜色

**组合逻辑**：[补全(complete)] + [边邻接计数(edge_adjacency_count) → 邻接多数决(adjacency_majority_rule)]（创新：投票结果不是给已有分量重涂色，而是决定缺失像素的补全颜色） → [填充(fill)]

**来源原语**：补全(complete, 6d75e8bb)、边邻接计数(edge_adjacency_count, 477d2879)、邻接多数决(adjacency_majority_rule, 477d2879)、填充(fill, 6d75e8bb)、不完整矩形(incomplete_rect, 6d75e8bb)、标记像素(marker_pixel, 477d2879)

**依赖链**：补全操作需要知道用什么颜色填充缺失像素 → 填充颜色由标记像素的邻接多数投票决定 → 标记像素的分布反过来受不完整矩形的边界框位置约束（只有边界框边缘上的标记参与投票）

根据不完整矩形边界上的标记像素投票，用得票最多的标记颜色填充矩形缺失部分。

**输入结构**：黑(0)背景，约 12x12 至 16x16 网格。网格中有 2~4 个不完整的单色矩形（各用不同颜色，如蓝(1)、绿(3)、黄(4)），每个矩形缺失若干连续像素（缺失处为黑(0)，但仍在矩形边界框内部）。每个矩形的边界框边缘（含外扩一格）上散布着若干单像素标记，标记颜色取自红(2)、灰(5)、品红(6)中的 2~3 种，不同矩形周围的标记颜色分布不同。每个矩形周围至少有 3 个标记像素，且恰好有一种标记颜色的边邻接数量严格最大（无平局）。矩形互不重叠，矩形与标记也不重叠。生成约束：每个矩形的边界框之间至少间隔 2 格，保证标记像素可被唯一归属到最近的矩形。

**规则**：
1. 找出每个不完整矩形的边界框（即该矩形颜色所有像素的最小外接矩形）。
2. 对每个矩形，收集与其边界框边缘有至少一条公共边（4-邻接）的所有标记像素（标记像素指颜色为红(2)、灰(5)或品红(6)的单像素）。
3. 统计每种标记颜色与该矩形边界框边缘的 4-邻接边数总和（一个标记像素可能与边界框有 1~2 条公共边）。
4. 选择邻接边数最多的标记颜色作为该矩形的补全颜色。
5. 将该矩形边界框内所有黑(0)像素填充为步骤 4 确定的补全颜色。
6. 标记像素本身保持不变，不被擦除也不被覆盖。

**关键洞察**：补全颜色不是固定的，也不来自矩形自身——它由矩形周围标记像素的空间投票结果决定；同一种标记颜色在不同矩形旁边可能赢也可能输，取决于局部的边邻接数量。

## 新题 2：路径连接定义交换拓扑

**组合逻辑**：[路径追踪(path_follow)] → [重分配(redistribute)]（创新：路径不是用来定位目标，而是定义哪些插槽之间交换内容） + [槽位保持颜色(slot_retains_color)]

**来源原语**：路径追踪(path_follow, 9ba4a9aa)、引导像素(guide_pixel, 9ba4a9aa)、重分配(redistribute, 31f7f899)、柱状条(vertical_bar, 31f7f899)、基线(baseline, 31f7f899)、槽位保持颜色(slot_retains_color, 31f7f899)、路径连接(path_connected, 9ba4a9aa)

**依赖链**：路径追踪确定哪两个插槽被连接 → 连接关系决定交换配对 → 交换时柱状条的形状（高度轮廓）互换但各插槽保持自己的颜色

通过引导路径确定柱状条配对关系，交换配对柱状条的高度轮廓，同时保持各位置原有颜色。

**输入结构**：黑(0)背景，约 15x20 网格。底部有一行橙(7)基线横跨全宽。基线上方有 4~6 根单色柱状条（每根宽 1 列，高度 2~8 格不等），颜色各不相同，取自蓝(1)、红(2)、绿(3)、黄(4)、品红(6)。基线下方（网格下半部分）有灰(5)引导像素组成的路径，路径在 2 格间距的正交网格上跳跃（每步水平或垂直移动 2 格），形成若干互不相交的路径段，每段恰好连接两根柱状条正下方的列。柱状条数量为偶数，每根恰好被一条路径连接到另一根，无柱状条落单。不同路径之间不共享像素也不交叉。

**规则**：
1. 识别基线上方的每根柱状条，记录其列位置、颜色和高度轮廓。
2. 在基线下方，从每根柱状条正下方的列出发，沿灰(5)引导像素逐步追踪（每步沿行或列方向跳 2 格到下一个灰像素），找到路径另一端对应的柱状条列。这样得到若干配对关系。
3. 对于每一对被路径连接的柱状条 A 和 B：将 A 的高度轮廓（即高度值）赋给 B 的位置，将 B 的高度轮廓赋给 A 的位置。
4. 交换后，每个位置的柱状条仍然保持该位置原来的颜色，只是高度改变。
5. 基线和引导路径保持不变。

**关键洞察**：引导路径不是用来"找到目标然后裁剪输出"，而是定义了一张配对图；求解者必须先追踪所有路径确定配对关系，再执行交换——路径拓扑决定了重分配方案。

## 新题 3：投射生成掩码驱动补全

**组合逻辑**：[压缩/投射到引导条(project_to_guide)] → [二值掩码(binary_mask)]（创新：投射结果不是最终输出，而是生成一个选择掩码） → [补全(complete) + 擦除(erase)]

**来源原语**：压缩(compress, f83cb3f6)、投射到引导条(project_to_guide, f83cb3f6)、引导条(guide_bar, f83cb3f6)、散布像素(scattered_pixel, f83cb3f6)、投射落间隙则擦(erase_if_gap, f83cb3f6)、补全(complete, 6d75e8bb)、二值掩码(binary_mask, 506d28a5)、不完整矩形(incomplete_rect, 6d75e8bb)

**依赖链**：散布像素投射到引导条，在引导条上产生"有信号/无信号"的二值掩码 → 这个掩码决定不完整矩形的哪些列被补全、哪些列被擦除 → 补全和擦除操作依赖投射产生的掩码，而非直接依赖散布像素的位置

将散布像素沿垂直方向投射到引导条上生成列掩码，用该掩码决定不完整矩形中哪些列补全、哪些列擦除。

**输入结构**：黑(0)背景，约 14x14 网格。网格中部有一行水平红(2)引导条，宽度等于网格宽度，可能有若干 1 格宽的间隙（间隙处为黑(0)）。引导条上方散布若干蓝(1)单像素（每列至多一个散布像素）。引导条下方有一个不完整的绿(3)矩形：该矩形跨越若干列，部分列有完整的绿色像素填充（从某行到某行），部分列完全缺失（全为黑(0)）。矩形的行范围可通过已有绿色列的上下边界推断。生成约束：散布像素所在的列，有些与矩形的缺失列重合，有些与矩形的已有列重合；引导条的间隙位置与矩形的列范围有部分重叠。

**规则**：
1. 将每个蓝(1)散布像素沿垂直方向投射到红(2)引导条上：若该像素所在列的引导条位置是红(2)（非间隙），则该列标记为"有信号"；若该列引导条位置是黑(0)间隙，则投射无效，该列标记为"无信号"。没有散布像素的列也标记为"无信号"。
2. 确定绿(3)不完整矩形的完整边界框：行范围取所有绿色像素的最小行到最大行，列范围取所有绿色像素的最小列到最大列。
3. 对矩形列范围内的每一列：若该列在步骤 1 中被标记为"有信号"，则将该列在矩形行范围内的所有黑(0)像素填充为绿(3)（补全）；若标记为"无信号"，则将该列在矩形行范围内的所有绿(3)像素擦除为黑(0)。
4. 引导条和散布像素保持不变。

**关键洞察**：引导条不只是散布像素的投射目标——它的间隙同时过滤掉部分投射，使投射结果成为一个稀疏掩码；这个掩码再反过来控制另一个结构（矩形）的补全与擦除，形成"上方散布 → 中间引导条过滤 → 下方矩形选择性变形"的三层信息传递。

## 新题 4：封闭区域的压缩签名决定重涂色

**组合逻辑**：[压缩(compress) + 连续重复折叠(dup_collapsed)]（创新：压缩不是最终输出，而是提取每个区域的"签名"） → [计数(counting)] → [面积比较(area_comparison) → 极值区域分别涂色(extreme_regions_recolor)]（创新：比较的不是面积，而是压缩签名的长度）

**来源原语**：压缩(compress, 746b3537)、连续重复折叠(dup_collapsed, 746b3537)、色带(color_stripe, 746b3537)、计数(counting, 6455b5f5)、封闭区域(enclosed_region, 6455b5f5)、分隔线(divider_line, 6455b5f5)、面积比较(area_comparison, 6455b5f5)、极值区域分别涂色(extreme_regions_recolor, 6455b5f5)、重涂色(recolor, 6455b5f5)

**依赖链**：分隔线划分出封闭区域 → 每个区域内的色带被压缩为去重序列 → 压缩后序列的长度（不同颜色交替数）作为该区域的特征值 → 特征值最小和最大的区域分别被重涂不同颜色

将分隔线划分的每个区域内的色带压缩为去重序列，按序列长度的极值对区域重涂色。

**输入结构**：黑(0)背景，约 15x15 网格。灰(5)分隔线（1 像素宽的水平线和垂直线）将网格划分为 4~6 个矩形封闭区域。每个区域内部填充有水平色带——由 2~4 种颜色（取自蓝(1)、红(2)、绿(3)、黄(4)、品红(6)）组成的全宽水平条纹，每条条纹厚 1~3 行。不同区域的条纹模式不同：有些区域条纹交替频繁（如蓝-红-蓝-红-绿，压缩后长度 5），有些区域条纹单调（如蓝-蓝-蓝-红，压缩后长度 2）。生成约束：各区域压缩后序列长度互不相同，保证最小和最大值唯一。

**规则**：
1. 识别灰(5)分隔线划分出的所有矩形封闭区域。
2. 对每个区域，从上到下逐行读取行颜色（每行在该区域内为单一颜色），得到颜色序列。
3. 对该序列做连续重复折叠：将连续相同颜色合并为一个，得到去重后的颜色序列。记录去重序列的长度。
4. 找出去重序列长度最小的区域和最大的区域。
5. 将最小长度区域内所有非灰像素重涂为青(8)；将最大长度区域内所有非灰像素重涂为橙(7)。
6. 其余区域保持原色不变。灰(5)分隔线始终保持不变。

**关键洞察**：排序的依据不是区域的几何面积，而是区域内色带经压缩后的"信息复杂度"（去重长度）；外观上面积相近的区域可能因为条纹模式的复杂度不同而得到完全不同的处理。

## 新题 5：十字检测锚定射线延伸

**组合逻辑**：[模式检测(pattern_detection) + 邻域全匹配(all_neighbors_match)]（检测十字图案的中心） → [射线延伸(ray_extend)]（创新：射线从检测到的十字中心出发，而非从线段端点出发） → [重涂色(recolor) + 交集差集分别着色(intersection_diff_colored)]

**来源原语**：模式检测(pattern_detection, 1818057f)、十字图案(cross_pattern, 1818057f)、邻域全匹配(all_neighbors_match, 1818057f)、射线延伸(ray_extend, faa9f03d)、重涂色(recolor, a8610ef7)、交集差集分别着色(intersection_diff_colored, a8610ef7)、前景对象(foreground_object, 1818057f)

**依赖链**：模式检测找出前景中所有十字图案的中心 → 从每个中心向四方延伸射线直到碰到前景边界 → 射线覆盖的像素与原始十字像素分别着不同颜色；若两条射线交叉，交叉点用第三种颜色

从前景形状中检测所有"+"十字中心，从中心向四方延伸射线至形状边界，对十字、射线、交叉点分别着色。

**输入结构**：黑(0)背景，约 15x15 网格。一个由蓝(1)像素组成的大型 4-连通前景形状（约 40~80 像素），形状不规则但内部有若干自然形成的"+"十字结构（即某个蓝像素的上下左右 4 个邻居都是蓝像素）。十字中心数量为 2~4 个。形状足够大，使得从十字中心沿四个方向延伸时，射线在碰到形状边界之前能经过至少 2 个像素。生成约束：至少有一对十字中心的射线会在形状内部交叉（即某个像素同时位于两个不同中心射线的路径上）。

**规则**：
1. 识别前景形状中所有"+"十字中心：即蓝(1)像素 p，使得 p 的上、下、左、右 4 个邻居均为蓝(1)。
2. 对每个十字中心，标记其自身及上下左右 4 个邻居共 5 个像素为"十字像素"。
3. 从每个十字中心出发，沿上、下、左、右四个方向逐格延伸。延伸时跳过已标记的十字像素（即从十字臂的末端之后开始），继续向外延伸直到遇到黑(0)背景像素为止（不包含该黑像素）。将路径上经过的所有蓝(1)像素标记为"射线像素"。
4. 重涂色规则：
   - 十字像素（步骤 2 标记的）重涂为红(2)。
   - 仅被标记为射线像素（步骤 3）且不属于任何十字的像素：若仅属于一个中心的射线，重涂为黄(4)；若同时属于两个或更多中心的射线（交叉点），重涂为绿(3)。
   - 既不属于十字也不属于射线的蓝(1)前景像素保持蓝(1)不变。
5. 背景像素保持黑(0)不变。

**关键洞察**：十字检测不是重涂色的终点，而是射线延伸的起点；射线交叉产生的第三类像素需要对比所有射线的覆盖范围才能识别，迫使求解者同时追踪多个中心的扩展路径。

## 新题 6：面积驱动平移与引导条间隙过滤着陆

**组合逻辑**：[平移(translate) + 位移等于面积(shift_equals_area)] → [引导条(guide_bar) + 投射落间隙则擦(erase_if_gap)]（创新：间隙过滤不是在投射时发生，而是在着陆时——平移到达位置后，检查着陆列是否对齐引导条间隙）

**关键洞察**：叠加结果不是最终输出——棋盘格的坐标奇偶性像一张镂空面具一样遮盖了一半的叠加结果；求解者需要同时理解叠加来源分类和空间过滤两层逻辑，且两者无法分开推理（过滤后才能确认最终颜色）。

7. 中心条保持灰(5)不变。

**关键洞察**：形状匹配不仅决定"谁填入凹槽"，还隐式决定了链的生长方向和宽度约束；拉伸的递增量使链环不是简单重复而是逐级膨胀，求解者需要从示例中归纳出"第 k 环比根多 k 行"的递增规律。

## 新题 11：螺旋路径上的邻接投票重涂色

**组合逻辑**：[螺旋绘制(spiral_drawing) + 起点定位(origin_positioning)]（画出螺旋路径） → [边邻接计数(edge_adjacency_count) + 邻接多数决(adjacency_majority_rule)]（创新：投票不是发生在静态连通分量之间，而是发生在螺旋路径经过的不同颜色区域之间） → [重涂色(recolor)]

**来源原语**：螺旋绘制(spiral_drawing, 8b28cd80)、起点定位(origin_positioning, 8b28cd80)、格点阵列(node_lattice, 8b28cd80)、边邻接计数(edge_adjacency_count, 477d2879)、邻接多数决(adjacency_majority_rule, 477d2879)、重涂色(recolor, 477d2879)、标记像素(marker_pixel, 477d2879)

**依赖链**：从标记像素出发绘制螺旋路径 → 螺旋路径穿过多个不同颜色的区域 → 统计螺旋路径像素与每种区域颜色的边邻接数 → 用邻接最多的区域颜色重涂螺旋路径

从标记像素出发画螺旋，用螺旋路径与周围彩色区域的邻接投票结果给螺旋着色。

**输入结构**：黑(0)背景，约 13x13 网格。网格上有 3~4 个不同颜色的矩形区域（各为实心矩形，颜色取自蓝(1)、红(2)、绿(3)、黄(4)，各占 6~15 像素），区域之间至少间隔 1 格，不重叠。网格中有一个灰(5)标记像素，位于某两个区域之间的空白处。生成约束：以标记像素为中心画出方形螺旋时，螺旋路径会经过多个区域的边缘旁边（4-邻接），但螺旋本身不覆盖任何区域像素（螺旋只画在黑(0)背景上）；螺旋路径与不同区域的 4-邻接边数各不相同，保证投票有唯一赢家。

**规则**：
1. 从灰(5)标记像素出发，画一条方形螺旋路径：沿上→右→下→左方向交替前进，步长序列为 1, 1, 2, 2, 3, 3, ...。仅在黑(0)背景像素上绘制；若下一步落在非黑像素或超出网格边界，跳过该步但继续螺旋计数（不中断螺旋）。
2. 螺旋绘制持续到连续 4 个方向的步全部跳过（即螺旋已无法继续扩展）时停止。
3. 将所有被螺旋覆盖的像素标记为螺旋像素（暂标为灰(5)）。
4. 对每种非黑、非灰颜色 C，统计螺旋像素与颜色 C 区域像素之间的 4-邻接边总数（即螺旋像素和 C 像素有多少对共享边）。
5. 将所有螺旋像素重涂为邻接边数最大的颜色 C。
6. 原来的矩形区域和标记像素保持不变。

**关键洞察**：螺旋不是装饰或最终图案——它是一条"探针"，其路径形状由中心点位置决定，而路径与各区域的接触量反过来决定了螺旋自身的颜色；螺旋的几何形状隐式编码了投票权重。

## 新题 12：端点朝向控制印章方向与全宽基线着色

**组合逻辑**：[端点朝向(endpoint_facing)] → [印章覆盖(stamp) + 中心对齐(center_align)]（创新：印章方向由线段端点朝向旋转决定，而非固定方向） → [全宽填充(full_width_fill) + 基线行(baseline_row)]（创新：全宽行的颜色由该行上所有印章像素的多数颜色决定）

**来源原语**：端点朝向(endpoint_facing, faa9f03d)、线段网络(line_network, faa9f03d)、印章覆盖(stamp, 88a10436)、精灵体(sprite, 88a10436)、中心对齐(center_align, 88a10436)、标记像素(marker_pixel, 88a10436)、全宽填充(full_width_fill, 3f23242b)、基线行(baseline_row, 3f23242b)、形状展开(shape_expansion, 3f23242b)

**依赖链**：线段端点的朝向决定印章的旋转角度 → 印章被放置在端点处 → 所有印章放置完成后，基线行上可能出现多种颜色的印章像素 → 基线行用该行上出现最多的印章颜色做全宽填充

在线段端点处沿端点朝向印章精灵体，然后用基线行上出现最多的印章颜色做全宽填充。

**输入结构**：黑(0)背景，约 14x14 网格。网格下部第 3 行（距底部）有一行灰(5)基线（全宽，1 像素厚）。基线上方有 2~4 条单像素宽的正交线段（水平或垂直，长度 3~6 格），颜色取自蓝(1)、红(2)、绿(3)，线段之间互不相交。每条线段有 1~2 个开放端点（端点处没有连接其他线段的像素，即该方向的下一格为黑(0)）。网格左下角（基线下方）有一个小型精灵体模板（3x3 以内的非对称 4-连通图形，颜色为黄(4)），精灵体的边界框为奇数行 x 奇数列，有明确中心。生成约束：线段端点处印章精灵体后不会超出网格边界；各印章之间互不重叠；基线行上至少有两种不同颜色的印章像素落入。

**规则**：
1. 识别每条线段的每个开放端点及其朝向（端点朝向为从线段内部指向端点外侧的方向：上、下、左、右）。
2. 对每个端点，将精灵体模板旋转，使模板的默认朝向（向上）对齐到端点的朝向方向。旋转为 90 度倍数（向上 = 0 度，向右 = 90 度，向下 = 180 度，向左 = 270 度）。
3. 将旋转后的精灵体以端点像素为中心印章到网格上。印章时使用端点所属线段的颜色（非模板原色），透明覆盖（只画非黑像素，不覆盖已有非黑像素）。
4. 所有端点印章完成后，检查基线行上的所有非灰像素。统计每种颜色的像素数量。
5. 将整行基线用数量最多的那种颜色替换（原灰(5)变为该颜色，全宽填充）。
6. 精灵体模板区域（左下角）从网格中擦除（变为黑(0)）。

**关键洞察**：端点朝向不只是修复线段的辅助信息——它控制了印章的旋转角度，进而决定印章像素落在网格的哪些位置；基线行的最终颜色取决于各印章与基线行的空间交叉情况，这由端点朝向间接决定。

## 新题 13：裁剪压缩后的条带序列作为排序键重排区域

**组合逻辑**：[裁剪(crop)] → [压缩(compress) + 连续重复折叠(dup_collapsed)] → [排序(sort) + 重分配(redistribute)]（创新：排序键不是几何属性如高度，而是压缩后的抽象序列；重分配操作交换的是整个区域内容而非单维形状）

**来源原语**：裁剪(crop, cd3c21df)、压缩(compress, 746b3537)、连续重复折叠(dup_collapsed, 746b3537)、色带(color_stripe, 746b3537)、条带方向(stripe_orient, 746b3537)、排序(sort, 31f7f899)、重分配(redistribute, 31f7f899)、封闭区域(enclosed_region, 6455b5f5)、分隔线(divider_line, 6455b5f5)

**依赖链**：分隔线划分出封闭区域 → 每个区域内部有色带 → 裁剪每个区域并压缩其色带 → 压缩后序列的长度作为排序键 → 按长度从短到长重排各区域的内容到从左到右的位置

按区域内色带的压缩复杂度从低到高，重新排列各区域的全部内容。

**输入结构**：黑(0)背景，约 12x18 网格。红(2)垂直分隔线（1 像素宽，全高）将网格等分为 3~5 个同宽矩形区域（各区域宽 3~4 列）。每个区域内部完全填充水平色带：由若干颜色（取自蓝(1)、绿(3)、黄(4)、灰(5)、品红(6)、橙(7)）组成的全宽水平条纹，每条条纹厚 1~3 行。不同区域的条纹模式不同，压缩后去重序列的长度各不相同。生成约束：区域数量 >= 3，各区域压缩序列长度严格递增排列时不与当前从左到右的顺序相同（即至少需要交换一次）。

**规则**：
1. 识别红(2)垂直分隔线，确定各矩形区域的列范围。从左到右编号为位置 1, 2, 3, ...。
2. 对每个区域，从上到下逐行读取该区域内的条纹颜色，得到颜色序列。对序列做连续重复折叠（合并相邻重复颜色），记录折叠后的序列长度 L。
3. 按 L 从小到大对各区域排序。L 相同时按区域内最上方条纹颜色在输入中从左到右首次出现的位置排先后。
4. 将排序后的区域内容（包含原始未压缩的色带，保持原行高度和配色）依次填入从左到右的各位置。每个位置的列宽不变，行高不变，直接替换原有内容。
5. 红(2)分隔线保持不变。

**关键洞察**：求解者不能仅靠视觉上的"条纹密度"猜测排序——必须实际执行压缩算法（合并相邻重复颜色）得到精确的长度值，因为厚条纹和薄条纹压缩后长度可能相同或不同，与视觉密度无直接对应。

## 新题 14：连通分量面积编码平移向量

**组合逻辑**：[计数(counting) + 面积比较(area_comparison)]（创新：面积不是用来重涂色，而是编码为两个分量的平移距离） → [平移(translate)] → [透明叠加(transparent_overlay) + 交集差集分别着色(intersection_diff_colored)]

**来源原语**：计数(counting, b2bc3ffd/6455b5f5)、面积比较(area_comparison, 6455b5f5)、连通分量(connected_component, 477d2879)、平移(translate, b2bc3ffd)、透明叠加(transparent_overlay, 506d28a5)、交集差集分别着色(intersection_diff_colored, a8610ef7)、重涂色(recolor, a8610ef7)

**依赖链**：两个连通分量各有自己的面积 → 面积较小的分量向右平移（距离 = 自身面积），面积较大的分量向左平移（距离 = 自身面积） → 两者平移后可能部分重叠 → 重叠区域、仅左分量区域、仅右分量区域分别着不同颜色

两个分量各以自身面积为距离相向平移，平移后的重叠与差集分别着色。

**输入结构**：黑(0)背景，约 12x20 网格（宽大于高）。网格中有恰好两个 4-连通单色前景分量，颜色均为蓝(1)，分布在网格的左半部和右半部（水平方向有明显间隔，间隔至少 4 格）。左侧分量面积 3~6 像素，右侧分量面积 3~6 像素，两者面积不同。每个分量为不规则的小图形（非矩形）。生成约束：左侧分量向右平移其面积对应的列数后，与右侧分量向左平移其面积对应的列数后，两者在网格内有部分重叠（至少 1 像素）；平移后所有像素仍在网格范围内。

**规则**：
1. 识别两个蓝(1) 4-连通分量，分别计算面积（像素数）。面积较小的记为分量 S，面积较大的记为分量 L。面积相同时，左侧分量为 S。
2. 将分量 S 从原位置擦除，整体向右水平平移 |S| 列（|S| = S 的面积）。
3. 将分量 L 从原位置擦除，整体向左水平平移 |L| 列（|L| = L 的面积）。
4. 在平移后的位置重新绘制两个分量。对每个像素位置：
   - 若只有分量 S 覆盖 → 涂红(2)。
   - 若只有分量 L 覆盖 → 涂绿(3)。
   - 若两个分量都覆盖（重叠）→ 涂黄(4)。
   - 其余位置保持黑(0)。

**关键洞察**：面积不仅是分类属性——它直接转化为物理位移量，使得面积较大的分量移动更远；重叠区域的存在和形状同时取决于两个分量各自的面积（位移量）和形状（几何轮廓），无法从单一分量推断。
