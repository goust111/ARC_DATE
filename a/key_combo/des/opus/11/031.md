## 新题 1：重力穿越门控框架

**组合逻辑**：[重力下落](创新：遇框时判断颜色匹配决定通过/停靠) + [洪泛填充](创新：通过缺口后沿缺口方向改变下落轴) + [边框缺口](创新：缺口不再触发射线，而是重定向重力轴)

**来源原语**：重力下落/gravity_drop (963c33f8), 洪泛填充/flood_fill (551d5bf1), 空心矩形/rectangular_frame (551d5bf1), 边框缺口/border_gap (551d5bf1), 控制色定行为/control_color_determines_behavior (963c33f8), 碰撞停止/collision_stop (332f06d7)

**依赖链**：颜色匹配决定像素能否穿越框架 -> 缺口位置决定穿越后的运动方向 -> 运动方向改变后遇到下一个框架又触发新一轮匹配判断。三者形成循环依赖：每次穿越改变方向，方向改变后遇到的框架颜色不同，又触发不同的匹配结果。

一句话：彩色像素在重力作用下穿越多层带缺口的矩形框架，同色框架可穿过且缺口方向重定向运动轴，异色框架则阻挡停靠。

**输入结构**：黑(0)背景，约 18x18 网格。顶部有 2~4 个单色前景像素（每个 1 像素，颜色各异，从蓝(1)、红(2)、绿(3)、黄(4)中选取），分布在不同列。网格中散布 3~5 个空心矩形框架（4-连通单像素宽边框，内部 3x3 至 5x5 的空腔），每个框架用上述四色之一绘制。每个框架恰好有一个非角落边框像素缺失（缺口），缺口可在上、下、左、右任一侧。框架之间互不重叠，且在水平和垂直方向上至少间隔 2 像素。生成约束：每个下落像素的运动路径上至少经过 2 个框架，路径之间互不交叉。

**规则**：
1. 每个顶部前景像素初始向下运动（重力方向 = 下）。
2. 像素沿当前运动方向逐格移动。遇到框架边框像素时进行颜色匹配判断：
   - 若像素颜色与框架颜色相同：像素穿过框架，从缺口位置离开。离开后运动方向变为缺口朝外的方向（上侧缺口 -> 向上，右侧缺口 -> 向右，依此类推）。
   - 若像素颜色与框架颜色不同：像素停在碰撞前一格（即框架外侧紧邻的背景像素位置），保留像素原色。
3. 像素运动直到停靠（碰撞异色框架或到达网格边界）。到达网格边界时像素停在边界最后一个格子。
4. 多个像素独立运动，互不影响。若两个像素最终落在同一格，后停靠的覆盖先停靠的（按初始列从左到右的顺序依次处理）。
5. 输出保留所有框架（含缺口），背景不变，仅改变像素的最终位置。

**关键洞察**：缺口不是装饰性缺陷，而是运动方向的转向阀；同一个像素可能先向下、穿过一个框架后转向右、再穿过另一个框架后转向上，轨迹呈折线形。颜色匹配和缺口方向两个判断交替作用，缺一不可。

## 新题 2：反射重叠的距离优先涂色

**组合逻辑**：[镜像/跨轴反射](保留) + [重涂色](创新：涂色由标记像素指定，但重叠区域按原始距轴距离解决冲突) + [逐格比较](创新：比较反射后的落点是否重叠，而非比较两个掩码)

**来源原语**：镜像/mirror (88207623), 重涂色/recolor (12997ef3), 跨轴反射/reflection_across_axis (88207623), 标记色指定涂色/marker_color_paint (88207623), 逐格比较/cell_comparison (fafffa47), 标记像素/marker_pixel (581f7754)

**依赖链**：反射产生镜像位置 -> 多个镜像可能重叠 -> 重叠必须按源图形距轴的远近分优先级 -> 标记像素为非重叠区域提供涂色。反射结果决定了哪些格子需要冲突解决，而冲突解决依赖反射前的空间距离信息。

一句话：将轴一侧的多个图形反射到另一侧，非重叠区域由对侧标记像素指定颜色，重叠区域由距轴更近的原始图形获得涂色优先权。

**输入结构**：黑(0)背景，约 15x20 网格。一条灰(5)像素组成的垂直线段位于网格中部（贯穿所有行或大部分行），作为反射轴。轴左侧有 2~4 个互不相邻的单色 4-连通前景图形（每个 3~8 像素，形状不规则，颜色从蓝(1)、红(2)、绿(3)中选取，颜色可重复）。轴右侧有若干孤立标记像素（每个 1 像素，颜色从黄(4)、橙(7)、品红(6)中选取），每个标记像素位于恰好一个左侧图形反射后的覆盖区域内（不在重叠区域内）。生成约束：至少有一对图形反射后存在 2 像素以上的重叠区域；每个非重叠反射区域内恰好有一个标记像素；不同图形反射后的重叠区域内不放置标记像素。

**规则**：
1. 保留灰(5)反射轴和所有左侧原始图形不变。
2. 将每个左侧图形关于灰色轴列做水平镜像反射，计算每个反射像素的目标位置 (r, 2*axis_col - c)。
3. 对于仅被一个反射图形覆盖的目标格子（非重叠）：查找该反射区域内的标记像素，用标记像素的颜色涂该反射图形的所有非重叠格子。
4. 对于被多个反射图形同时覆盖的目标格子（重叠）：计算每个竞争图形的最近边框像素到轴的水平距离（像素数），距轴更近的图形优先——该格子涂为该优先图形对应的标记颜色。距离相同时，边界框上边缘行号更小的图形优先。
5. 移除所有标记像素（标记像素仅用于指示颜色，不出现在输出中）。

**关键洞察**：反射本身制造了空间冲突（重叠），而解决冲突需要回溯到反射前的距离信息——镜像操作和冲突解决之间存在因果环路：不做反射不知道哪里重叠，不知道原始距离不能解决重叠。需要对比多个示例才能归纳距离优先规则。

## 新题 3：枢轴反射位移驱动区域循环滚动

**组合逻辑**：[旋转/绕枢轴半周旋转](保留) + [循环位移](创新：位移量由反射产生的空间位移距离决定) + [裁剪](创新：枢轴位置划分数据区域的滚动范围)

**来源原语**：旋转/rotate (90347967), 枢轴像素/pivot_pixel (90347967), 绕枢轴半周旋转/half_turn_around_pivot (90347967), 循环位移/cyclic_roll (6d1d5c90), 行偏移编码/row_offset_encode (6d1d5c90), 前景掩码/foreground_mask (90347967)

**依赖链**：枢轴位置决定反射中心 -> 反射后图形质心的垂直位移量 = 循环滚动行数 -> 枢轴的水平位置还同时划分网格为左右两个数据区域 -> 仅对包含反射图形的那半区域执行滚动。枢轴同时承担"反射中心"和"区域分界"双重角色，删除任一功能都无法求解。

一句话：将小图形关于枢轴做 180 度点对称反射，反射前后质心的垂直距离决定包含反射落点的那半网格的循环下滚行数。

**输入结构**：黑(0)背景，约 14x14 网格。一个灰(5)枢轴像素位于网格内部（不在边缘行列）。枢轴的某一侧（左或右）有一个蓝(1)色 4-连通前景图形（3~6 像素，形状不规则）。网格其余区域散布若干红(2)和绿(3)的装饰像素（每种 3~6 个，均匀分布在枢轴两侧），这些装饰像素构成需要被滚动的"数据内容"。生成约束：前景图形关于枢轴反射后的落点全部在网格内且不与装饰像素重叠；反射前后质心的垂直距离为正整数（向下位移）且不超过网格高度的一半。

**规则**：
1. 将蓝(1)前景图形的每个像素 (r, c) 反射到 (2*pivot_r - r, 2*pivot_c - c)，反射副本保持蓝(1)色。原始图形保留。
2. 计算原始图形质心行坐标 r_orig 和反射图形质心行坐标 r_refl（均四舍五入到最近整数）。令 d = |r_refl - r_orig|。
3. 以枢轴所在列为分界线，将网格分为左半区（列 < pivot_col）和右半区（列 > pivot_col）。枢轴所在列本身不属于任何半区。
4. 确定反射图形落在哪个半区（按反射图形质心列判断）。对该半区内所有行（包含该半区的装饰像素和反射图形像素）执行循环下滚 d 行：每个像素的行坐标变为 (r + d) mod grid_height。另一半区和枢轴列保持不变。
5. 枢轴像素保留在原位。

**关键洞察**：枢轴的双重角色——既是反射的几何中心，又是区域划分的分界线——使得一个像素同时承载了两个独立逻辑的关键参数。反射距离隐式编码了滚动量，必须对比多个示例（不同枢轴位置、不同图形位置）才能归纳出这一数值关系。

## 新题 4：棋盘格奇偶性决定封闭区域填充优先级

**组合逻辑**：[洪泛填充](保留) + [重涂色](创新：涂色由标记像素决定，但选哪个标记取决于棋盘格奇偶性) + [逐格比较](创新：比较标记所在格的棋盘奇偶，而非比较两个掩码)

**来源原语**：洪泛填充/flood_fill (4b6b68e5), 轮廓框/outline_frame (4b6b68e5), 封闭区域/enclosed_region (4b6b68e5), 标记在封闭区域内/marker_in_enclosed_region (4b6b68e5), 多数色决定填充/majority_color_fill (4b6b68e5), 棋盘格图案/checkerboard_pattern (80a900e0), 忽略干扰项/ignore_distractors (4b6b68e5)

**依赖链**：必须先识别棋盘格底层图案确定每格的奇偶性 -> 再识别轮廓框和封闭区域 -> 在封闭区域内根据奇偶性筛选标记像素 -> 筛选后的标记集合中取多数色作为填充色。棋盘奇偶性作为隐藏筛选层，改变了"多数色"的计算基数。

一句话：在棋盘格背景上识别轮廓框围成的封闭区域，仅统计位于棋盘暗格上的标记像素的多数颜色，用该颜色填充整个封闭区域。

**输入结构**：约 16x16 网格。背景为棋盘格图案：黑(0)和白(灰(5))交替排列（左上角 (0,0) 为黑(0)，(0,1) 为灰(5)，依此类推）。灰(5)色同时作为轮廓框的颜色——轮廓框的像素恰好占据棋盘格中灰(5)的位置，因此轮廓框与棋盘背景的灰色部分视觉上融合（求解者需通过连通性区分框和背景）。每个轮廓框为 4-连通封闭环形（内部 4x4 至 6x6 空腔），共 2~3 个，互不重叠。每个封闭区域内有 3~5 个孤立标记像素，颜色从蓝(1)、红(2)、绿(3)、黄(4)中选取。标记像素分布在暗格（黑(0)位置，即 (r+c) 为偶数的格子）和亮格（灰(5)位置，即 (r+c) 为奇数的格子）上。生成约束：每个封闭区域内，暗格上的标记像素存在唯一多数色，且该多数色与亮格上标记像素的多数色不同。

**规则**：
1. 识别棋盘格图案：(r+c) 为偶数的格子为"暗格"，(r+c) 为奇数的格子为"亮格"。
2. 识别灰(5)轮廓框：所有 4-连通的灰(5)像素组成的连通分量中，形成封闭环的（其内部存在无法不穿越灰色像素而到达网格边界的区域）为轮廓框。
3. 对每个封闭区域，收集区域内所有非灰(5)、非黑(0)的标记像素。
4. 仅保留位于暗格（(r+c) 为偶数）上的标记像素，忽略亮格上的标记像素（亮格标记是干扰项）。
5. 在保留的暗格标记中统计颜色出现次数，取出现次数最多的颜色作为该区域的填充色。
6. 将该封闭区域内所有非轮廓框的格子（包括暗格和亮格）全部涂为填充色。轮廓框本身保持灰(5)不变。
7. 封闭区域外的棋盘格背景和任何开放轮廓保持不变。区域外的孤立标记像素全部擦除（涂为其所在格的棋盘底色）。

**关键洞察**：棋盘格图案不仅是背景装饰，更是一个隐藏的二元分类器——它将标记像素分为"有效"和"干扰"两组。如果忽略棋盘奇偶而直接统计所有标记，会得到错误的多数色（因为生成约束保证了暗格多数色与全体多数色不同）。必须对比多个示例才能发现奇偶性的筛选作用。

## 新题 5：通道宽度与锚点颜色双重门控的精灵体滑动

**组合逻辑**：[滑动/pathfinding](创新：滑动路径受通道宽度约束) + [颜色匹配锚点](创新：匹配对象从单一锚点扩展为通道末端的锚点) + [尺寸约束通行](保留，但约束的是精灵体的边界框而非实心方块)

**来源原语**：滑动/slide (332f06d7), 路径搜索/pathfinding (332f06d7), 多色精灵体/multicolor_sprite (581f7754), 蜿蜒通道/winding_channel (332f06d7), 边界锚点/border_anchor (581f7754), 颜色匹配锚点/color_match_anchor (581f7754), 尺寸约束通行/size_constrains_passage (332f06d7), 标记像素/marker_pixel (581f7754)

**依赖链**：精灵体的边界框尺寸决定它能通过哪些通道（宽度门控） -> 可通行的通道可能有多条 -> 精灵体中的标记像素颜色与通道末端锚点颜色匹配决定走哪条通道（颜色门控） -> 最终位置由通道的几何路径决定。尺寸过滤和颜色匹配是两个独立的筛选维度，必须同时满足。

一句话：多色精灵体沿蜿蜒通道滑动到与其标记像素同色的边界锚点处，但只有边界框能通过所有瓶颈的通道才可通行。

**输入结构**：黑(0)背景，约 20x20 网格。橙(7)色像素形成 2~3 条蜿蜒通道（每条通道宽 2~4 格，长度跨越网格大部分区域，通道之间不相交）。每条通道的一端（靠近网格内部）为开口，另一端延伸到网格边缘处有一个 1 像素的边界锚点（锚点颜色从蓝(1)、红(2)、绿(3)中选取，每条通道末端锚点颜色不同）。网格内部有 2~3 个多色精灵体（每个精灵体为 4-连通的 2x2 至 3x3 边界框内的像素图案，由一种主色和一个标记像素组成；主色从黄(4)、品红(6)中选取，标记像素颜色与某个锚点颜色相同）。每个精灵体位于某条通道的开口附近（相邻但不在通道内部）。生成约束：每个精灵体的标记颜色恰好匹配一个锚点颜色；每条通道沿途至少有一处瓶颈（最窄处宽度可能小于某些精灵体的边界框宽或高）；至少有一个精灵体因边界框尺寸超过某通道瓶颈而无法通行其颜色匹配的通道（该精灵体留在原位）。

**规则**：
1. 对每个精灵体，找到其标记像素颜色匹配的边界锚点，确定目标通道。
2. 检查目标通道沿途每处截面的宽度（垂直于通道方向测量）：若所有截面的宽度都 >= 精灵体边界框在该截面方向上的对应尺寸（水平截面比较边界框高度，垂直截面比较边界框宽度），则通道可通行。
3. 可通行：将精灵体沿通道滑动到锚点处——精灵体的标记像素与锚点重合（锚点被覆盖），精灵体其余像素占据锚点相邻的通道格子。精灵体原位置涂为黑(0)背景。
4. 不可通行：精灵体保持原位不动。
5. 通道像素（橙(7)）在精灵体经过后保持不变（精灵体叠在通道上方）。未被精灵体覆盖的锚点保持原色。

**关键洞察**：仅凭颜色匹配会将精灵体指向一条通道，但尺寸约束可能否决该路径——此时精灵体不会退而求其次选择其他通道，而是直接留在原位。两个筛选条件（颜色 AND 尺寸）缺一不可，且它们的判断对象不同（颜色看锚点，尺寸看通道瓶颈），必须对比多个示例才能分辨两种门控机制。

## 新题 6：堆叠掩码交集计数驱动模板像素放大

**组合逻辑**：[压缩/逐格比较](保留) + [像素放大/pixel_scale](创新：放大倍率不再预设，而由掩码交集像素数决定) + [种子选择模板](创新：种子不再是框内已有像素，而是交集图案本身匹配模板)

**来源原语**：压缩/compress (fafffa47), 堆叠掩码/stacked_mask (fafffa47), 逐格比较/cell_comparison (fafffa47), 双背景标记输出/both_bg_marks (fafffa47), 像素放大/pixel_scale (8a6d367c), 模板/template (8a6d367c), 种子选择模板/seed_selects_template (8a6d367c), 框内匹配/frame_interior_match (8a6d367c)

**依赖链**：两个掩码逐格比较产生交集标记 -> 交集标记的空间图案用于匹配模板（图案选择） -> 交集标记的像素数量用于决定放大倍率（数量编码） -> 被选中的模板以该倍率放大后作为输出。同一个交集结果被同时读取了两种信息（图案和数量），分别决定了两个不同参数。

一句话：将两个堆叠掩码逐格比较得到交集标记，交集的形状匹配某个模板，交集的像素数量决定该模板的放大倍率，输出放大后的模板。

**输入结构**：约 12x20 网格，纵向分三个区域。上区（约 5 行）：2~4 个小模板，每个模板为单色 4-连通图形（2~4 像素），颜色各异（从蓝(1)、红(2)、绿(3)、黄(4)中选取），模板之间水平排列，间隔至少 2 列。中区和下区各为一个 5xW 的掩码（W = 网格宽度），两个掩码之间用一行栗(9)色分隔条隔开。每个掩码以黑(0)为底色，分别包含一种前景色的像素图案（中区用品红(6)，下区用橙(7)）。生成约束：两个掩码逐格比较后，"双底色"位置（即中区该格为黑(0)且下区同位置也为黑(0)）的集合形成的形状，经平移后恰好匹配上区某一个模板的形状；该匹配是唯一的（其他模板形状不匹配）；交集像素数量为 2、3 或 4（即放大倍率为 2x、3x 或 4x）。

**规则**：
1. 以栗(9)分隔条为界，提取中区掩码和下区掩码（大小相同）。
2. 逐格比较：同一位置 (r, c) 在中区和下区都是黑(0)背景时，标记为红(2)交集像素；否则标记为黑(0)。得到一个交集掩码。
3. 将交集掩码中所有红(2)像素的坐标集合，平移使其边界框左上角对齐 (0,0)，得到归一化形状。
4. 在上区的模板中，找到形状与归一化交集完全匹配的模板（像素集合平移后全等）。
5. 令 n = 交集红(2)像素的数量。将匹配到的模板做 n 倍像素放大（每个模板像素变为 nxn 的同色方块）。
6. 输出仅包含放大后的模板，背景为黑(0)。输出网格大小 = 模板边界框高 * n 行 x 模板边界框宽 * n 列。

**关键洞察**：交集结果被双重利用——形状选模板、数量定倍率。求解者如果只关注形状匹配或只关注计数，都无法独立确定输出。必须对比多个示例才能发现计数与倍率的映射关系，以及形状匹配的选择逻辑。

## 新题 7：对称恢复揭示种子选择裁剪区域

**组合逻辑**：[补全/对称恢复](保留) + [裁剪](创新：裁剪区域不预设，由恢复内容中的种子像素位置决定) + [种子选择模板](创新：种子不选模板，而选裁剪边界)

**来源原语**：补全/complete (f9012d9b), 平移对称图案/translational_pattern (f9012d9b), 对称轨道/symmetry_orbit (f9012d9b), 对称恢复遮挡/symmetry_restores (f9012d9b), 裁剪/crop (6ffbe589), 种子像素/seed_pixel (8a6d367c), 标记像素/marker_pixel (581f7754)

**依赖链**：对称恢复填补遮挡区域 -> 恢复的内容中可能出现原本被遮挡的种子像素 -> 种子像素的位置定义了裁剪矩形的一个角点 -> 裁剪矩形的对角点由另一个可见的种子像素给出 -> 最终输出为该矩形内的恢复后图案。恢复是裁剪的前提，但裁剪区域也依赖于恢复结果中的内容——形成先恢复后定位的信息流。

一句话：先用平移对称性恢复被遮挡的区域，再用恢复出的隐藏种子像素和已有的可见种子像素确定裁剪矩形，输出该矩形内的图案。

**输入结构**：约 15x15 网格。网格被一个平移对称的多色图案铺满（无单一背景色），图案的最小重复单元为 3x3 至 5x5（重复单元内使用 3~4 种颜色，从蓝(1)、红(2)、绿(3)、黄(4)、橙(7)中选取）。网格中有一个黑(0)矩形遮挡区域（3x3 至 6x6），覆盖了部分图案。遮挡区域外有一个可见的品红(6)种子像素（占据图案中某个本应为其他颜色的位置）。遮挡区域内有一个被隐藏的品红(6)种子像素（在被遮挡前该位置为品红(6)，现在被黑(0)覆盖）。生成约束：两个品红(6)种子像素分别作为一个矩形的左上角和右下角（或右上角和左下角——可见种子的行列坐标均不等于隐藏种子的行列坐标）；该裁剪矩形完全在网格范围内。

**规则**：
1. 识别黑(0)像素为遮挡区域。
2. 检测图案的平移对称性（忽略黑(0)像素和品红(6)像素）。
3. 利用对称轨道恢复每个黑(0)像素的原始颜色：对于遮挡区域内的每个像素 (r, c)，在其平移对称轨道中找到一个非黑(0)、非品红(6)的像素，复制其颜色到 (r, c)。
4. 恢复后检查：若遮挡区域内某个位置在所有对称轨道中的对应位置均为品红(6)（或该位置本身的轨道成员中有品红(6)且其余非遮挡轨道成员也是品红(6)），则该位置恢复为品红(6)——这就是隐藏种子像素。
5. 现在网格上有两个品红(6)像素。以它们为对角顶点定义一个轴对齐矩形：左上角 = (min(r1,r2), min(c1,c2))，右下角 = (max(r1,r2), max(c1,c2))。
6. 输出该矩形范围内的图案（含矩形边界上的像素），品红(6)种子像素保留在输出中。

**关键洞察**：恢复遮挡不是最终目的而是中间步骤——恢复操作的价值在于揭示了一个被遮挡的定位信标（种子像素），该信标与可见信标配对后才确定了输出的裁剪范围。仅凭一个示例可能无法确定"品红像素定义裁剪角点"这条规则，需要对比多个示例。

## 新题 8：基线归一化改变缺口邻接色从而决定射线颜色

**组合逻辑**：[对齐/基线归一化](保留) + [射线延伸](创新：射线颜色不再由缺口所属框架决定，而由归一化后缺口处实际邻接的竖条颜色决定) + [缺口方向决定射线](保留方向规则，但颜色规则改为动态依赖归一化结果)

**来源原语**：对齐/align (41ace6b5), 填充/fill (41ace6b5), 基线对齐/baseline_aligned (41ace6b5), 最大高度归一化/max_height_normalize (41ace6b5), 双色竖条/two_color_bar (41ace6b5), 标记行/marker_row (41ace6b5), 射线延伸/ray_extend (551d5bf1), 空心矩形/rectangular_frame (551d5bf1), 边框缺口/border_gap (551d5bf1), 缺口方向决定射线/gap_direction_determines_ray (551d5bf1)

**依赖链**：归一化将竖条的上段色（青(8)）统一拉伸到最大高度 -> 拉伸改变了竖条与框架缺口的空间邻接关系 -> 缺口处原本邻接的可能是背景或下段色（蓝(1)），归一化后可能变为青(8) -> 射线颜色取缺口内侧紧邻像素的颜色 -> 因此归一化操作的副作用通过空间邻接间接决定了射线颜色。删除归一化则射线颜色错误，删除射线则输出不完整。

一句话：先将矩形框内的双色竖条按基线归一化上段高度，再从框架缺口向外发射射线，射线颜色取决于归一化后缺口内侧实际邻接的竖条颜色。

**输入结构**：黑(0)背景，约 18x18 网格。2~3 个灰(5)色空心矩形框架（4-连通单像素宽边框，内部宽 3~5 列、高 6~10 行），互不重叠。每个框架恰好有一个非角落边框像素缺失（缺口）。框架内部每列有一个双色竖条：上段为青(8)、下段为蓝(1)，两色在同一列内连续且下段底部对齐到框架底部内侧。不同列的青(8)段高度不同（1~4 行不等）。框架内部的顶部若干行可能为黑(0)（竖条上方的空隙）。每个框架内部有一行红(2)标记像素作为基线，位于所有青(8)段之上（红(2)行与最高青(8)段的顶部紧邻或间隔 1 行）。生成约束：归一化后至少有一个框架的缺口内侧邻接色从蓝(1)变为青(8)（即该缺口所在行在归一化前属于蓝(1)区域，归一化后被青(8)向下扩展覆盖）；至少有一个框架的缺口内侧邻接色归一化前后不变。

**规则**：
1. 对每个框架，找到内部红(2)标记行。
2. 在每个框架内部，令 h_max = 该框架内所有列中青(8)段的最大高度。
3. 归一化：对每个内部列，将青(8)段从红(2)标记行向下扩展至恰好 h_max 行（向下覆盖原有的黑(0)或蓝(1)像素，涂为青(8)）。青(8)以下到框架底部的区域保持为蓝(1)。
4. 归一化完成后，对每个框架的缺口：
   a. 确定缺口所在的边框侧（上/下/左/右）以及缺口在内部侧紧邻的那个像素的颜色（可能是青(8)、蓝(1)、红(2)或黑(0)）。
   b. 从缺口向外（垂直于缺口所在边，远离框架方向）发射一条射线，射线颜色 = 步骤 4a 中确定的邻接色。
   c. 射线逐格向外延伸，将经过的黑(0)背景像素涂为射线颜色，直到碰到非黑(0)像素或网格边界时停止（不覆盖终点的非黑像素）。
5. 保留所有框架边框（含缺口位置仍为黑(0)）、归一化后的内部竖条、红(2)标记行不变。

**关键洞察**：射线颜色不是由缺口"属于哪个框架"静态决定的，而是由归一化操作动态改变的空间邻接关系决定的。如果没有归一化步骤直接发射射线，部分射线颜色会是蓝(1)，但归一化后变成了青(8)——两个操作通过共享的空间状态紧密耦合。必须对比归一化前后的变化才能理解射线颜色的真正来源。
