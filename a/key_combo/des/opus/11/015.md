## 新题 1：边框方向射线与交叉优先

**组合逻辑**：[延伸/连线](创新：由边框颜色匹配定义射线方向，射线贯穿至边框而非仅移动一格) + [交叉优先规则](已有原语) + [裁剪区背景替换](已有原语)

**来源原语**：平移/朝匹配边移动(5034a0b5)、连线/竖线交叉优先(40853293)、裁剪/裁剪区背景替换(a740d043)

**依赖链**：边框四边颜色定义内部像素的射线方向 → 射线从每个内部像素出发沿匹配方向贯穿至边框 → 射线交叉点由竖线优先规则解决颜色冲突 → 最终裁剪至所有射线像素的紧致边界框

一句话总结：每个内部像素根据其颜色对应的边框边方向发射一条射线到边框，交叉处竖线颜色优先，输出为所有射线像素的紧致裁剪。

**输入结构**：约 11x11 的网格。最外一圈是一个矩形边框：四个角为黑(0)，顶边为红(2)、底边为蓝(1)、左边为绿(3)、右边为黄(4)，各边颜色互不相同且为单色实心条。边框内部大部分为黑(0)背景，散布 4~7 个前景像素，每个像素的颜色恰好等于某一条边框边的颜色（即只可能是红(2)、蓝(1)、绿(3)、黄(4)之一）。每种边框颜色在内部至少出现一次。生成约束：任意两个内部像素不共享同一行或同一列（保证每条射线至多与另一条射线产生一个交叉点）。

**规则**：
1. 识别边框四边颜色：顶边色、底边色、左边色、右边色（均为角落之间的实心段）。
2. 对每个非背景内部像素，根据其颜色确定射线方向：与顶边同色 → 向上；与底边同色 → 向下；与左边同色 → 向左；与右边同色 → 向右。
3. 从该像素位置起（含自身），沿确定方向逐格填充同色像素，直到到达边框内边界（不包含边框像素本身）为止。
4. 当一条水平射线和一条竖直射线在同一格交叉时，该格颜色取竖直射线的颜色。
5. 计算所有射线像素（含起点、含交叉结果）的紧致边界框，裁剪到该边界框。裁剪区域内的背景像素保留为黑(0)。

**关键洞察**：内部像素不是滑动一格，而是生成一条贯穿射线；交叉冲突规则（竖线优先）只有在射线实际交叉时才可见——需要对比多个示例中不同射线布局才能归纳出方向无关、仅凭水平/竖直分类的优先级规则。

## 新题 2：控制射线切割后孔洞面积决定填充色

**组合逻辑**：[切割/射线分割](已有原语) + [计数/封闭面积](已有原语) + [填充/面积阈值决定颜色](创新：阈值应用于切割后碎片的孔洞面积而非原始对象)

**来源原语**：切割/射线分割/边界归属决定保留(4a21e3da)、计数/封闭背景区域(8ba14f53)、填充/面积阈值决定颜色(84f2aca1)

**依赖链**：控制像素发射射线将前景精灵体切割成碎片 → 仅保留与控制边相邻区域中的碎片 → 统计每个保留碎片内的封闭背景像素数 → 根据孔洞面积阈值选择填充色

一句话总结：用网格边缘控制像素发出的射线将一个带孔洞的精灵体切割成碎片，保留碰触控制边的碎片，再根据各碎片内孔洞面积填充不同颜色。

**输入结构**：约 13x13 的黑(0)背景网格。中央偏置一个单色前景精灵体（绿(3)，约 30~50 像素的 4-连通不规则形状），内部包含 2~4 个独立的黑(0)封闭孔洞（各孔洞面积 1~6 像素不等）。网格边缘（第 0 行、最后一行、第 0 列或最后一列）上有 1~2 个红(2)控制像素。生成约束：每个控制像素所在的行或列必须穿过精灵体（射线能实际切割到精灵体）；两个控制像素分别在不同的边上（一个在行边缘，一个在列边缘），保证切割产生至少 3 块碎片。

**规则**：
1. 从每个控制像素出发，沿其所在边的法线方向（顶边/底边上的控制像素沿列方向，左边/右边上的控制像素沿行方向）向内绘制一条切割射线。射线覆盖该行或列上的所有背景像素（跳过前景像素，即射线不会改变前景像素的颜色，但仍在逻辑上将路径两侧分隔）。
2. 射线将网格划分为若干区域。对精灵体的每个 4-连通碎片，判断其所在区域是否与控制像素所在的网格边缘相邻（碎片的某个像素到该边缘之间存在纯背景/射线路径的连通性）。仅保留与至少一条控制边相邻的碎片，其余碎片擦除为黑(0)。
3. 对每个保留的碎片，统计其内部封闭的背景像素数（被碎片的前景像素完全 4-连通包围、无法通过背景像素 4-连通到达碎片边界框外部的黑像素）。注意：切割可能将原始孔洞打开（孔洞边界被射线截断后不再封闭），此时该孔洞不计入面积。
4. 根据封闭孔洞面积填充：面积为 0（无封闭孔洞）→ 不填充，保持碎片原色；面积 1~2 → 用灰(5)填充所有封闭孔洞像素；面积 3 及以上 → 用橙(7)填充所有封闭孔洞像素。
5. 输出为整个网格（含射线痕迹为黑(0)背景），保留碎片和填充结果。

**关键洞察**：切割射线可能截断原始孔洞的边界，使原本封闭的孔洞变成开放缺口——同一个原始孔洞在不同碎片中的"存活"状态取决于射线切割位置，因此填充颜色不能从原始孔洞面积直接推出，必须在切割后重新计算。

## 新题 3：行前缀延展后按调色带逐列重涂色

**组合逻辑**：[延伸/前缀图案闭合延展](已有原语) + [重涂色/逐列调色带映射](创新：调色带映射的对象是延展后产生的边界色像素，而非预先存在的蒙版)

**来源原语**：延伸/封闭行段/前缀图案闭合延展(62b74c02)、重涂色/调色带/逐列对应(278e5215)

**依赖链**：每行左侧前缀的边界色延展填满中间空隙并在右端复制内部图案 → 调色带的逐列颜色替换掉延展后的边界色 → 内部图案像素不受调色带影响

一句话总结：先将每行的左侧封闭前缀延展至全行宽度，再用网格下方的调色带逐列替换延展产生的边界色，内部图案色保持不变。

**输入结构**：上半区为约 7 行 x 9 列的主图案区，下半区为 1 行 x 9 列的调色带行（与主图案等宽），两者之间隔一行黑(0)分隔行。主图案区每行的结构：从第 0 列起有一个连续非背景前缀（3~5 格），前缀首尾两格为同一颜色（称"边界色"，红(2)），中间 1~3 格为不同颜色的内部图案像素（可含蓝(1)、绿(3)、黄(4)等），前缀右侧全为黑(0)背景。不同行的边界色相同（均为红(2)），但内部图案像素的颜色和数量可以逐行不同。调色带行包含 9 个像素，每个位置为一种非背景颜色（可包含品红(6)、橙(7)、青(8)等），代表该列的重涂色目标。生成约束：调色带中不出现红(2)（边界色），也不出现任何内部图案像素使用的颜色（蓝(1)、绿(3)、黄(4)），保证重涂结果无歧义。

**规则**：
1. 对主图案区的每一行，识别左侧连续非背景前缀。前缀的第一个和最后一个像素颜色相同，此颜色为该行的边界色。
2. 延展规则：保持前缀不动；从前缀末尾到行的倒数第二格（含），全部填充边界色；行的最后若干格（数量 = 前缀长度 - 1）复制前缀去掉第一个像素后的内容（即前缀的第 2 格到末尾格），完成闭合。
3. 延展完成后，对主图案区的每一列 c，读取调色带行第 c 个位置的颜色 P(c)。
4. 逐列重涂色：将该列中所有等于边界色（红(2)）的像素替换为 P(c)。内部图案像素（非边界色、非背景色的像素）不做替换。
5. 输出仅包含主图案区（不含分隔行和调色带行）。

**关键洞察**：延展操作在前缀右侧生成了大量连续的边界色像素——正是这些延展产生的像素成为重涂色的目标。未经延展的行右侧全为背景色，不会被调色带影响；延展后每列的边界色像素数量和分布各不相同，使得逐列重涂产生丰富的视觉差异。必须对比多个示例才能分离出"边界色被替换、内部图案色被保留"这条隐蔽规则。

## 新题 4：引导掩码选定精灵体后按边框方向平移

**组合逻辑**：[裁剪/引导掩码选择](已有原语) + [平移/边框颜色匹配方向](创新：平移作用于被选定的单个精灵体的各像素而非所有内部像素，且平移距离由精灵体内匹配色像素到该边的距离差异编码)

**来源原语**：裁剪/引导掩码/唯一被框选对象(bf699163)、平移/边框边/颜色匹配边/朝匹配边移动(5034a0b5)

**依赖链**：引导掩码的包围框确定目标精灵体 → 边框四边颜色为精灵体各像素提供平移方向 → 每个像素按其颜色对应的方向移动一格 → 输出为平移后精灵体的紧致裁剪

一句话总结：在多个空心精灵体中用引导掩码选中一个，然后将选中精灵体中各像素根据其颜色匹配的边框边方向各移动一格，输出为移动后的紧致裁剪。

**输入结构**：约 15x15 的网格。最外一圈为矩形边框：四角为黑(0)，顶边为蓝(1)、底边为黄(4)、左边为红(2)、右边为绿(3)，各边颜色互不相同。边框内部为黑(0)背景，包含 3~4 个 3x3 空心方块精灵体（外环为 8 个像素，中心为黑(0)）。每个精灵体的 8 个外环像素的颜色来自 {蓝(1), 红(2), 绿(3), 黄(4)} 四种边框色的子集，不同精灵体的颜色组合不同。另有若干品红(6)的散布像素构成引导掩码（品红不属于任何边框颜色），其包围框恰好框住且仅框住一个精灵体。生成约束：各精灵体互不相邻（包围框不重叠，间隔至少 2 格）；被选中的精灵体距边框至少 2 格（平移后不会与边框重叠）；精灵体中不出现黑(0)像素在外环位置上。

**规则**：
1. 找到所有 3x3 空心方块精灵体（外环 8 像素非背景、中心为背景的 3x3 区域）。
2. 找到引导掩码：所有非背景、不属于任何精灵体的像素（品红(6)像素）。计算引导掩码像素的包围框。
3. 选取完全落在引导掩码包围框内的唯一精灵体作为目标。
4. 对目标精灵体的每个像素，确定其颜色对应的边框边方向：与顶边同色 → 上移一格；与底边同色 → 下移一格；与左边同色 → 左移一格；与右边同色 → 右移一格。
5. 所有像素同时移动（不存在先后顺序）。若两个像素移动后占据同一格，保留沿竖直方向移动的像素的颜色（与新题 1 的交叉规则一致）。
6. 输出为移动后所有像素的紧致边界框裁剪，裁剪内的背景保留为黑(0)。

**关键洞察**：引导掩码决定"操作哪个精灵体"（选择），边框颜色决定"怎么操作每个像素"（方向），两个信息源完全独立——求解者必须同时识别选择机制和变换规则才能生成正确输出。仅看一个示例无法区分"是整个精灵体统一移动还是各像素分别移动"，需要对比多个示例中不同颜色分布的精灵体才能发现逐像素方向规则。

## 新题 5：邻接清洗改变朝向后按类别计入面板

**组合逻辑**：[擦除/邻接不足则删除](已有原语) + [分类/朝向分组](创新：朝向判定基于清洗后的包围框长宽比而非预定义的固定形状) + [填充/计数映射槽位](已有原语)

**来源原语**：擦除/邻接/邻接不足则删除(7f4411dc)、分类/朝向分组/朝向决定面板(d5c634a2)、填充/面板/槽位/计数映射槽位(d5c634a2)

**依赖链**：邻接清洗删除支撑不足的像素 → 清洗可能截除精灵体的细长突起，改变其包围框长宽比 → 长宽比决定朝向分类（横向/纵向） → 两类计数分别填入左右面板槽位

一句话总结：先用邻接支撑规则清洗噪点和精灵体的薄弱突起，然后根据清洗后各精灵体的包围框长宽比分为横向和纵向两类，分别统计数量填入左右面板。

**输入结构**：约 15x15 的黑(0)背景网格。包含 4~6 个单色 4-连通前景精灵体，每个精灵体由 8~20 个像素组成，颜色为红(2)。部分精灵体有一个 1 像素宽的细长突起（1~3 格长，该突起的像素仅有 1 个同色 4-邻居）。另有若干随机散布的红(2)噪点像素（与精灵体不 4-连通，每个噪点的同色 4-邻居数为 0 或 1）。生成约束：每个精灵体在清洗前的包围框长宽比与清洗后可能不同——至少有一个精灵体在清洗前是纵向（高>宽）但清洗掉顶部或底部突起后变为横向（宽>=高），或反之。各精灵体互不相邻。

**规则**：
1. 对每个红(2)像素，计算其红(2)的 4-邻居数。将邻居数少于 2 的像素擦除为黑(0)。
2. 重复步骤 1 直到无像素被擦除（迭代清洗，因为一次擦除可能使原本有 2 个邻居的像素失去邻居）。
3. 对清洗后的每个 4-连通红(2)精灵体，计算其紧致包围框。若包围框宽度严格大于高度，分类为"横向"；否则（高度 >= 宽度）分类为"纵向"。
4. 统计横向精灵体数量 H 和纵向精灵体数量 V。
5. 输出为 3x6 的黑(0)网格，分为左 3x3 面板和右 3x3 面板。左面板记录横向数量：按左上→左下→右上→右下的顺序，前 H 个角落格填充绿(3)。右面板记录纵向数量：同样顺序，前 V 个角落格填充蓝(1)。

**关键洞察**：迭代清洗可以连锁删除——一个突起末端像素被删后，下一个突起像素也失去足够邻居而被删，导致整条突起被逐步清除。这种清洗会改变精灵体的包围框形状，从而可能翻转其横纵分类。求解者必须模拟完整的迭代清洗过程才能得到正确的分类结果，不能仅看原始形状。

## 新题 6：同色配对连线后裁剪至交叉点边界框

**组合逻辑**：[连线/同色配对](已有原语) + [裁剪/边界框包围](创新：裁剪的前景掩模不是原始像素，而是连线操作涌现的交叉点集合)

**来源原语**：连线/同色配对/行列对齐/竖线交叉优先(40853293)、裁剪/边界框包围/裁剪区背景替换(a740d043)

**依赖链**：同色像素对之间绘制连线段 → 线段交叉处产生交叉点（颜色由竖线优先规则决定） → 收集所有交叉点的位置 → 裁剪到交叉点集合的紧致边界框 → 裁剪区内保留所有线段像素，背景替换为黑(0)

一句话总结：在同色配对像素之间画线段，找出所有线段交叉点，输出为这些交叉点的紧致边界框内的全部线段内容。

**输入结构**：约 12x12 的黑(0)背景网格。包含 4~6 种非背景颜色，每种颜色恰好出现 2 个像素，且每对同色像素共享同一行或同一列。生成约束：至少有 2 对线段会相互交叉（一对是水平线段，另一对是竖直线段，且水平段和竖直段有交集格）；至少有 1 对线段不与任何其他线段交叉（以便求解者发现裁剪边界不包含该线段）。所有像素互不重叠。

**规则**：
1. 对每种颜色，找到该颜色的两个像素。若它们在同一行，绘制水平线段（填充该行上两个像素之间的所有格，包含端点）；若同一列，绘制竖直线段（填充该列上两像素之间的所有格，包含端点）。
2. 当一条水平线段和一条竖直线段经过同一格时，产生交叉。该格颜色取竖直线段的颜色。
3. 收集所有交叉点的坐标集合 S。
4. 计算 S 的紧致边界框（最小行、最大行、最小列、最大列）。
5. 裁剪到该边界框。裁剪区域内的所有线段像素（包括交叉点和非交叉点）保留其绘制后的颜色，背景像素为黑(0)。

**关键洞察**：裁剪区域完全由交叉点的位置决定，而非由原始标记像素或所有线段决定。没有与任何其他线段交叉的线段可能整条落在裁剪框外而完全消失。求解者需要先画出所有线段、识别交叉点、再用交叉点（而非原始点）定义裁剪范围——这是一个涌现属性驱动后续操作的结构。

## 新题 7：双倍放大对角标记后邻接过滤揭示密度

**组合逻辑**：[像素放大/对角标记](已有原语) + [擦除/邻接不足则删除](创新：邻接阈值应用于放大后的对角标记像素而非原始前景，实现隐式对角线密度筛选)

**来源原语**：像素放大/对角共线/共对角背景标记(f0afb749)、擦除/邻接/邻接不足则删除(7f4411dc)

**依赖链**：前景像素放大为 2x2 实心块 → 与前景共 NW-SE 对角线的背景格标记蓝(1)对角线 → 对所有蓝标记像素做邻接过滤：蓝像素的非背景 4-邻居少于 2 个则擦除 → 存活的蓝标记勾勒出高密度对角线

一句话总结：将前景像素 2 倍放大并在共享 NW-SE 对角线的背景格上画蓝色对角标记，再擦除邻接支撑不足的蓝色标记像素，仅保留有多个前景像素共享的对角线上的标记。

**输入结构**：约 7x7 的黑(0)背景网格，包含 4~8 个非背景前景像素（颜色可为红(2)、绿(3)、黄(4)等多种）。前景像素分布使得某些 NW-SE 对角线上有 2 个及以上前景像素（称"密集对角线"），某些对角线上仅有 1 个前景像素（称"稀疏对角线"）。生成约束：至少有 2 条密集对角线和 1 条稀疏对角线；蓝(1)不作为输入前景像素的颜色使用。

**规则**：
1. 创建一个高宽均为输入 2 倍的输出画布，初始全为黑(0)。
2. 对每个输入前景像素（行 r，列 c，颜色 v），在输出画布的 (2r, 2c) 到 (2r+1, 2c+1) 的 2x2 区域填充颜色 v。
3. 对每个输入背景像素（行 r，列 c），检查是否存在至少一个前景像素与 (r, c) 在同一条 NW-SE 对角线上（即行-列之差相同）。若是，在输出画布的对应 2x2 区域中，仅将主对角线位置——(2r, 2c) 和 (2r+1, 2c+1)——标记为蓝(1)，其余两格保持黑(0)。
4. 对输出画布中每个蓝(1)像素，计算其非黑(0)的 4-邻居数。若少于 2 个，擦除为黑(0)。此步骤仅执行一次（非迭代）。
5. 输出最终画布。

**关键洞察**：在稀疏对角线上，蓝色标记的 2x2 对角像素之间间隔较大（中间仅有黑色背景），邻接支撑不足而被擦除；在密集对角线上，多个前景块和蓝色标记在放大后形成连续链条，蓝色像素获得足够的非背景邻居而存活。这使得邻接过滤在不显式计数的情况下实现了"对角线上前景密度 >= 2 才保留标记"的效果——一个涌现的密度筛选机制。

## 新题 8：双轴对称恢复遮挡区后提取中轴列摘要

**组合逻辑**：[对称补全/遮挡由镜像恢复](已有原语) + [裁剪/仅保留中轴](创新：中轴列恰好穿过被遮挡区域，必须先恢复才可提取) + [压缩/计数摘要](创新：对中轴列上的颜色段做游程压缩输出)

**来源原语**：对称补全/双轴镜像对称/遮挡由镜像恢复(67b4a34d)、裁剪/中轴列/仅保留中轴(d23f8c26)、压缩/顺序排列(8ba14f53)

**依赖链**：双轴对称图案被实心标记矩形遮挡 → 利用水平和竖直镜像恢复被遮挡像素 → 提取恢复后完整图案的中轴列 → 对中轴列做游程编码：连续同色段压缩为 (颜色, 长度) 对，输出为一行宽的竖条，每段用对应颜色填充对应长度

一句话总结：恢复被遮挡的双轴对称图案，提取其中轴列，将中轴列的连续同色段按顺序输出为压缩后的竖条。

**输入结构**：约 11x11（奇数宽度）的彩色网格，具有水平和竖直镜像对称性，包含 3~5 种非背景颜色构成的对称图案。一个约 3x3~4x4 的灰(5)实心矩形遮挡了图案的一部分。生成约束：灰(5)标记矩形的列范围必须覆盖网格的中间列（第 (W-1)/2 列，W 为网格宽度），即遮挡区域与中轴列有交集；灰(5)不作为图案自身的颜色使用；图案的中轴列在恢复后包含至少 3 个不同的颜色段（含背景色段）。

**规则**：
1. 找到灰(5)像素构成的实心矩形区域，记为遮挡区 M。
2. 对 M 中每个像素 (r, c)，通过水平镜像找到其对称位置 (r, W-1-c)，通过竖直镜像找到 (H-1-r, c)，通过中心对称找到 (H-1-r, W-1-c)。在这些对称位置中找到不是灰(5)的值，将其填入 (r, c)。若水平和竖直镜像位置都不是灰(5)，优先使用水平镜像位置的值。
3. 恢复完成后，提取中间列（第 (W-1)/2 列）的全部像素，形成一个长度为 H 的颜色序列。
4. 对该序列做游程编码：将连续相同颜色的像素段压缩为一个段，记录颜色和段长度。
5. 输出为 1 列宽的网格：从上到下，第 i 个段用其颜色填充段长度个格子。输出总高度 = 中轴列中不同游程段的段长之和（即等于原始中轴列高度 H）。

**关键洞察**：如果不进行对称恢复就直接提取中轴列，会得到若干灰(5)像素混入，导致游程编码出错（灰色段是虚假的遮挡色而非图案色）。恢复和提取在空间上交叉——中轴列正好穿过遮挡区，使得两步操作在同一组像素上产生因果依赖，而非简单的顺序传递。需对比多个示例才能发现"灰色是遮挡标记而非图案色"以及"对称恢复优先级（水平优先）"这两条隐蔽规则。
