Input structure
- 背景为 Black。
- 网格中有若干条 Grey 的细道路（1 像素宽的正交折线），互不连接，每条是一条独立连通折线，恰有两个端点。
- 每条道路的一个端点紧贴一小片单色"种子区"（实心色块，非 Grey、非 Black、非 Azure，不同道路的种子色可不同）。
- 每条道路的另一个端点紧贴一个空心方框（边框为 Azure，内部为一片被边框完全包围的 Black 区域）。

Rule
- 第一步（道路染色）：对每条 Grey 道路，找出它两端中紧贴种子区的那一端，把整条道路重绘为该种子区的颜色。需归纳出"道路从它接触的种子区继承颜色"。
- 第二步（找方框端）：每条已染色道路的另一端紧贴一个 Azure 方框，需归纳出"染色道路指向它要作用的那个方框"——配对关系由道路另一端的位置决定。
- 第三步（填框）：用该道路当前的颜色，把它所指 Azure 方框内部被边框包围的 Black 区域整体填满为该颜色；Azure 边框保持不变。所有道路保留染色后的结果，种子区不变。

Key insight
- 颜色先从种子区流入道路（第一层），再从道路流入方框（第三层），中间还要靠"道路另一端"完成道路与方框的配对（第二层）；颜色的最终归属（哪个种子色填进哪个框）跨越了道路这个中介，单看任一方框无法直接读出它该填什么色。

- 取自参考题 2（沿路径网络从相邻种子区继承颜色）与参考题 12（沿 Grey 轨迹的端点确定作用目标、做色彩的间接转移）的机制；变异点在于参考题 2 染完色即结束，本题把染色结果作为第三阶段"填框"的输入，并用道路两端分别承担"取色端"与"作用端"，形成种子→道路→方框的三层颜色管道，配对关系藏在道路另一端，避免层塌缩。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
