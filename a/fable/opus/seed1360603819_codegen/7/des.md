<new_puzzle>
- `description`：根据每个图例条所统计的"目标颜色对象个数"为索引，从一列彩色刻度中选出对应高度的颜色，再用该颜色把对应对象重绘。

Input structure:
- 背景为 Black。
- 网格左侧有一条紧贴左边缘、宽度为一列的竖直"刻度尺"：自上而下由若干个单像素组成，每个像素一种颜色，互不相同，构成一个有序的颜色序列（例如自上而下依次为 Red、Green、Yellow、Azure……）。刻度尺与右侧场景之间隔着一整列 Black 背景。
- 刻度尺右侧的主场景里散布着若干 4-连通的前景对象，每个对象是一种单色的实心团块。同一种颜色可能出现在多个分散的对象上。
- 主场景中每种出现的"团块颜色"都对应一组对象；不同团块颜色之间互不相邻。

Rule:
- 第一步（统计层）：对主场景中出现的每一种团块颜色，数出该颜色在主场景中有多少个 4-连通对象，得到一个计数 k（k ≥ 1）。
- 第二步（索引层）：把计数 k 当作刻度尺上的位置序号——从刻度尺顶端往下数第 k 个像素，取出它的颜色 c。
- 第三步（重绘层）：把该团块颜色的所有对象的全部像素都重绘为颜色 c，对象形状与位置不变。刻度尺本身、背景保持不变。

Key insight:
- 团块颜色本身不是输出颜色；它只用来分组并数出"个数"，这个个数是去刻度尺上"第几格"取色的指针。解题者必须先发现"对象个数→刻度位置→取色"这条链，单看任一对象的输入输出无法推出取色规则，因为取色依赖跨对象的全局计数。
- `source`：取自参考题 3（用图例/计数把对象分组并统计个数的机制）与参考题 13（角落标签像素作为"分组键"的机制）。变异点/新组合点：参考题 3 的计数只是用来画长度条，这里把"计数值"二次利用为竖直刻度尺上的位置索引去取一个全新的颜色，从而把"数个数"和"按序号查色表"两层非平凡归纳串联起来，推理链不同于任何单一参考题。
</new_puzzle>

<new_puzzle>
- `description`：先用每个外框缺口的"个数"匹配到唯一一个等数量孔洞的实心印章对象，再把该印章沿缺口所指方向平铺进框内直到填满框的内腔。

Input structure:
- 背景为 Black。
- 网格中有若干个 Grey 的矩形"框"：每个框是一圈一像素厚的 Grey 边框，内部为 Black 的空腔。每个框的边框上挖掉了 g 个像素（g 个缺口），这些缺口全部开在框的同一条边上（同一侧），缺口数 g 在不同框之间各不相同。
- 网格中另有若干个"印章对象"：每个印章是一个单色的实心小矩形团块，团块内部被挖掉了若干个 Black 的单像素孔洞，孔洞个数 h 在不同印章之间各不相同。印章颜色互不相同，且都不是 Grey。

Rule:
- 第一步（配对层）：对每个框，数出它的缺口个数 g；找到唯一一个孔洞个数 h 等于 g 的印章对象，把这个印章与该框配对。
- 第二步（定向层）：观察该框缺口所在的那一条边，缺口所在边的"朝向"即为填充方向——若缺口开在框的左边，则印章从框内左侧开始向右逐列平铺；缺口开在上边则从顶部向下逐行平铺；其余方向同理。
- 第三步（平铺层）：用配对到的印章（保持其原始朝向，不旋转不翻转）按上一步确定的方向，在框的内腔里一个紧挨一个地重复平铺，直到把整个内腔铺满（最后一块若超出内腔则裁掉超出部分）。框边框、缺口、其它背景保持不变；原印章对象在原位清除为背景。

Key insight:
- 缺口个数与孔洞个数都不是直接画出来的数字，而是要分别数出来再做"等量配对"；配对之后还要从缺口的几何位置读出平铺方向。三件事（数缺口、按等量找印章、按缺口边定向平铺）彼此依赖，缺一层都无法定位与填满正确的框。
- `source`：取自参考题 7（用空腔/区域计数把工具与框配对的机制）、参考题 8（把单一模板对象盖印复制到多个目标格的机制）与参考题 1（用标记决定外向方向的机制）。变异点/新组合点：参考题 7 用"空腔尺寸"配对且只填一次，这里改为"缺口个数=孔洞个数"做等量配对，并把方向从缺口边读出，再用参考题 8 的"盖印"升级为"沿方向反复平铺直至填满"，三层归纳的组合是全新的。
</new_puzzle>

<new_puzzle>
- `description`：把每个 3×3 箭头精灵按其中心颜色匹配到同色实心方块，沿箭头所指方向发射一串等间隔副本，副本数量等于该方块的边长。

Input structure:
- 背景为 Black。
- 网格中有若干个 3×3 的"箭头精灵"：每个精灵外圈八个像素是同一种边框色，构成一个朝某一个基本方向（上/下/左/右）的实心箭头形状（箭头由三像素以上构成，具有明确指向性，例如朝右的箭头在中列三像素加右侧尖端）；精灵正中心一个像素是另一种"控制色"。
- 网格中另有若干个单色的实心正方形方块（边长各不相同，例如 2×2、3×3、4×4）。每个方块的颜色恰好等于某一个精灵的中心控制色，且一一对应。
- 所有对象互不重叠，颜色互不相同。

Rule:
- 第一步（配对层）：对每个箭头精灵，读出其中心控制色，找到颜色与之相同的那个实心正方形方块，将二者配对。
- 第二步（读数层）：测量配对方块的边长 s（s 个像素的边）。
- 第三步（发射层）：沿该精灵箭头所指的基本方向，从精灵当前位置出发，每隔三个像素（步长 3）复制整个 3×3 精灵一次，共复制出 s 个副本（含贴出的第一个副本，总计停在第 s 个）。复制时整块精灵照搬（包括中心控制色），副本可覆盖沿途的背景；若某个副本会超出网格边界，则停止发射（不画出界副本）。原精灵、原方块、其余背景保持不变。

Key insight:
- 中心像素不是用来上色的，而是"去哪个方块配对"的钥匙；方块的边长不是用来画方块的，而是被二次利用为"发射几个副本"的计数；箭头方向决定射线方向。三层各自归纳——配对靠中心色、数量靠方块边长、方向靠箭头朝向——任意一层缺失都无法确定副本的数量与落点。
- `source`：取自参考题 9（中心像素作为配对钥匙、整块 3×3 精灵沿方向平铺的机制）与参考题 7（用对象的某个可见计数量驱动后续变换）。变异点/新组合点：参考题 9 的平铺"直到首次与方块重叠即停"，这里把停止条件替换为"由配对方块的边长决定固定的副本个数"，并显式引入箭头指向作为方向源，使"配对→读边长作为计数→定量发射"成为三层互相依赖的新推理链。
</new_puzzle>

<new_puzzle>
- `description`：用每行成对标记的全局出现频次给各行排序，再据此把各行括号内的载荷内容整体重排。

Input structure:
- 背景为 Black。
- 网格分为若干内容行，行与行之间没有分隔线但每行的内容独立。
- 每一行恰好有一对同色的"括号标记"像素（左右各一个单像素，颜色相同），两个标记之间夹着一段连续的、由各色单像素组成的"载荷"（载荷里的像素颜色与标记色不同）。不同行的标记色可能相同也可能不同。
- 每行的载荷长度都相等（即左右标记之间的格子数相同），且各行的左右标记列位置一致对齐。

Rule:
- 第一步（提取层）：对每一行，识别出该行的成对标记颜色 m，以及两标记之间那段载荷（一串有序的彩色像素）。
- 第二步（排序层）：统计每一种标记颜色 m 在整个网格中一共出现了多少对（即用了该标记色的行数），据此给所有行排出一个全局顺序——标记色出现对数越多的行排在越前面（若出现对数相同，则按这些行从上到下的原始顺序保持相对次序）。
- 第三步（重排层）：保持每行的标记位置与标记颜色不变，但把各行的"载荷内容"按上一步得到的全局顺序重新分配：排序第 1 位的那行的载荷放到网格最上面那一行的标记之间，排序第 2 位的载荷放到第二行的标记之间，依此类推。除标记之间的载荷被替换外，其余像素（标记本身、行外背景）保持不变。

Key insight:
- 每行标记色的"全局出现频次"是隐藏在跨行统计里的排序键，单看一行无法得知它该排第几；载荷与排序键（标记色频次）分处不同维度，必须先做全局频次统计、再据此重排载荷，两层缺一不可。
- `source`：取自参考题 19（恢复一个隐藏的全局顺序并据此重排的机制）与参考题 14（用跨对象的全局关系定出唯一顺序再重绘的机制）。变异点/新组合点：参考题 19/14 用"覆盖叠层关系/交叉图"求顺序，这里改用"标记颜色的全局出现频次"作为排序键，且排序的产物不是输出一列颜色，而是去驱动各行载荷内容的搬移，使"统计频次→定序→按序重排载荷"成为新的两层推理路径。
</new_puzzle>

<new_puzzle>
- `description`：先用左右镜像对称补全被实心方块遮挡的彩色图案，再在补全后的图案里找出唯一的 '+' 十字基序并把它及其四邻染成 Azure。

Input structure:
- 网格是一块带有左右镜像对称的彩色图案（即整幅图关于竖直中轴线左右对称），背景为 Black，图案由多种颜色的前景像素构成。
- 图案上有且仅有一个单色的实心矩形"遮挡块"（一种在图案别处不出现的纯色，例如 Maroon），它盖住了原本图案中的一小片区域，破坏了那一片的对称外观。
- 在被遮挡区域恢复后的完整图案中，恰好存在一处 '+' 十字基序：某个前景像素的上下左右四个正交邻居都是与它同色的前景像素，构成一个紧凑的五格十字（且不嵌在更大的实心块里）。

Rule:
- 第一步（去遮挡补全层）：识别那个唯一的、整体范围为实心矩形的遮挡色，确定被它盖住的区域。利用图案的左右镜像对称，把遮挡区域内每个像素用其关于竖直中轴线的镜像位置上的、未被遮挡的对应像素颜色填回，从而恢复出完整无遮挡的图案。
- 第二步（识别层）：在补全后的完整图案中，搜索 '+' 十字基序——中心像素与其上下左右四邻同色且这五格构成孤立十字。
- 第三步（标记层）：把找到的那个十字的中心及四个邻居共五格全部染成 Azure。其余像素保持补全后的样子不变。

Key insight:
- 十字基序的一部分可能正落在被遮挡区域里，因此必须先用对称把图案补全，才能完整看到十字并定位；不先补全就会漏掉或错认十字。补全（靠对称）与识别（靠局部十字结构）是两层各自非平凡的归纳，且后者依赖前者的产物。
- `source`：取自参考题 10（用镜像对称恢复被实心标记遮挡的区域的机制）与参考题 12（识别紧凑 '+' 十字基序并染色的机制）。变异点/新组合点：参考题 10 只做补全后直接输出补全图，参考题 12 只在已知图上找十字；这里把二者串成"先补全、后在补全结果上找十字标记"，使关键基序可能恰好藏在遮挡处，迫使解题者先完成对称补全这一层，推理链与任一参考题都不同。

<new_puzzle>
- `description`：用每个对象的孔洞数到图例里查出对应颜色，并按孔洞数从多到少由外向内嵌套，把整批对象重绘成一组同心方框。

Input structure:
- 背景为 Black。
- 网格顶部有一条紧贴上边缘、高度为一行的水平"图例带"：图例带里自左向右排着若干个单像素，每个像素一种颜色，互不相同；这条颜色序列定义了一个有序的"颜色梯子"（位置 1、2、3…各对应一种颜色）。图例带下方隔着一整行 Black 背景与主场景分开。
- 主场景里散布着若干个 4-连通的单色实心团块，每个团块内部挖有若干个 Black 单像素孔洞，孔洞个数在不同团块之间各不相同（孔洞个数 ≥ 1）。团块颜色彼此不同，且都不等于图例带里的颜色。

Rule:
- 第一步（查色层）：对每个团块，数出它内部的孔洞个数 k；到图例带上从左往右数第 k 个像素，取出该位置的颜色 c，作为这个团块的"新颜色"。
- 第二步（定序层）：按各团块的孔洞个数从多到少给所有团块排一个由外到内的嵌套次序（孔洞最多者最外层；若两团块孔洞数相同，则按其原始位置从左到右再从上到下决定相对内外）。
- 第三步（重绘层）：丢弃所有团块的原始形状与位置，在场景中央自外向内画出一组一像素厚的同心正方形方框：最外层方框用孔洞最多团块查到的颜色 c，向内每一层依次用排序后下一个团块查到的颜色，相邻方框之间留一格 Black 间隔。图例带保持不变。

Key insight:
- 孔洞数有双重作用：既是去图例梯子上查"新颜色"的索引（查色层），又是决定同心框由外到内嵌套顺序的排序键（定序层）；两层都依赖"数孔洞"但归纳出的是完全不同的两件事，且最终输出是与输入形状无关的同心框，必须两层都完成才能确定每一圈的颜色与位置。
- `source`：取自参考题 11（无视原始几何、只按嵌套关系重绘为规范同心框的机制）、参考题 6（用孔洞/计数作为隐含查表键的机制）与参考题 19（恢复一个隐藏的全局排序的机制）。变异点/新组合点：参考题 11 的同心结构来自"包含树"，这里改为用"孔洞数排序"凭空决定嵌套顺序，并额外用孔洞数去图例查颜色，使"数孔洞→查色→再用孔洞数定外内序→画同心框"成为三层依赖的新推理链。
</new_puzzle>
