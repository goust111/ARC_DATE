按每个箭头的指向把它读成"把某色对象推到对面墙"的指令，但推哪种颜色由箭头尾部的小色块决定，推到位后再把堆叠在一起的同色对象数量换算成新染色。
</description>

Input structure:
- 背景为 Black。网格四周各有一段 Grey 边墙。
- 网格内散落着若干个单色实心小团块对象，颜色取自 Red、Green、Yellow、Azure（每种颜色可有多个对象，大小不一）。
- 网格内另有 1 到 3 个箭头标记：每个箭头由 3 个像素构成（一个箭头尖加一段两格的箭杆），明确指向上下左右之一；每个箭头的箭杆尾端紧贴一个单像素小色块，颜色取自上面四种对象色之一，表示"这条指令作用于哪种颜色的对象"。

Rule:
- 第一层（指令解析）：每个箭头解析为一条指令——尾部小色块的颜色 c 指定被作用的对象颜色，箭头尖的指向给出推动方向 d。
- 第二层（沿向推靠）：对每条指令，把网格中所有颜色为 c 的对象沿方向 d 平移，直到各自最前缘抵达该方向上的 Grey 边墙（或抵达另一个已停住的同指令对象的后缘）为止，对象之间不重叠、保持原形，按离墙近者先停的顺序紧密贴靠。箭头本身与小色块在输出中清除。
- 第三层（按堆叠数换色）：推靠完成后，统计每条指令里沿该方向"紧贴成一列/一行"的同色对象个数 m。把这一串贴靠在一起的对象整体重新染色：m=1 保持原色，m=2 染成 Maroon，m=3 染成 Magenta，m≥4 染成 Orange。未被任何箭头指令作用的对象保持原样原位不动。

Key insight:
- 箭头不能只看指向，还要读尾部小色块才知道作用对象，这是第一层的隐蔽点；推靠是第二层；而最终颜色既不来自对象原色也不来自箭头，而来自"推到一起后堆了几个"，这是第三层。判断依据（推哪种、堆几个）分别位于箭头和推靠结果两处，单看一个对象无法同时读出三层。
</description>

source:
- 取自参考题 7/15（边缘标记/箭头给出方向、沿向移动到接触处停止）的方向移动机制、参考题 8（控制像素同时编码"作用对象"与"动作"）的"一个标记携带多重指令"机制、以及参考题 9/10（用可数的对象个数换算输出属性，此处堆叠数→颜色）的计数染色机制；变异点/新组合点：把"箭头方向"与"作用颜色"拆成箭头尖与尾部色块两个分量（第一层），并在"推靠停止"这一常见物理隐喻之上加挂一个非物理的第三层——用推靠后形成的堆叠数量重新染色，使本应塌缩成单层的"沿向移动"题获得真正的多层归纳深度，规避注意事项 8 的物理隐喻陷阱。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
