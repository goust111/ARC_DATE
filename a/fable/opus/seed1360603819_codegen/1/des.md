<new_puzzle>
<description>
先用每个图例方块的孔洞数量把"数量"翻译成"颜色"，再用这些颜色按从大到小的顺序重绘散落的灰色对象。
</description>

Input structure
- 背景为 Black。
- 网格上方有一条 Grey 分隔横线把网格分成两个区域。
- 上区是图例：若干个互不接触的实心 Maroon 方块，每个方块内部挖有数量不等的 Black 孔洞（即被背景色穿透的内部像素），不同方块的孔洞数量互不相同。每个方块紧贴其上方或下方写有一个单像素的"标签色"（Blue、Red、Green、Yellow、Azure、Magenta 之一），表示"孔洞数 = 该标签色"的对应关系。
- 下区是若干个互不接触的 Grey 实心 4-连通对象，形状各异、大小各异，散落分布。

Rule
- 第一步（建立查表）：统计上区每个 Maroon 图例方块的 Black 孔洞个数，把该孔洞数与紧邻它的标签色配成一对，得到"孔洞数 → 颜色"的映射表。
- 第二步（排序赋色）：把下区所有 Grey 对象按其像素面积从大到小排序，依次赋予孔洞数 1、2、3…… 所对应的颜色，即面积最大的对象用"孔洞数=1"映射到的颜色，第二大的用"孔洞数=2"的颜色，以此类推。
- 保持每个 Grey 对象的形状和位置不变，只替换其颜色；上区图例、分隔线、背景全部保持不变。

Key insight
- 图例不是直接给颜色，而是通过"孔洞数量"间接编码颜色；下区对象上没有任何关于自己该用哪种颜色的线索，必须先解出"孔洞数→颜色"表，再用"面积排名→孔洞数"这条独立的隐藏规律去查表。两层判断依据都不在被变换对象自身。
- source：取自参考题 1（用孔洞/内部对象作为"槽位摘要"的间接编码思想）与参考题 9/19（用一个可数视觉量充当查表键）。变异点：把"孔洞数量"作为映射表的键而非直接结果，并叠加"面积排名→键"这条第二层独立映射，使被变换对象与赋色依据彻底分离，避免层塌缩。
</new_puzzle>

<new_puzzle>
<description>
先从框架四条边的颜色读出每个对象的目标出口边，再用对象自身的对称类型决定它能否沿该方向滑行，最后让它滑向出口缺口停下。
</description>

Input structure
- 网格有一圈一像素厚的矩形外框，四个角为 Black 背景。
- 外框的上、下、左、右四条边各为一种互不相同的纯色（取自 Blue、Red、Green、Yellow 四色）。每条边上恰好有一个长度为三像素的 Black 缺口，缺口在该边上的位置各不相同。
- 内部背景为 Black，散布若干个 4-连通的单色实心对象，每个对象的颜色恰好等于四条边颜色之一，且每个对象都具有唯一一种反射对称：水平对称或垂直对称。

Rule
- 第一步（确定出口）：每个内部对象的颜色与某一条边的颜色相同，那条同色边就是该对象的目标边；该边上的三像素 Black 缺口即为该对象的出口位置。
- 第二步（判定可动性）：根据对象自身的反射对称类型决定它能沿哪条轴平移——水平对称的对象只能沿垂直方向（上下）移动，垂直对称的对象只能沿水平方向（左右）移动；若"指向目标边的方向"与该对象允许的移动轴不一致（例如目标边在左侧，但对象是水平对称只能上下动），则该对象不动，保持原位。
- 第三步（滑行入位）：可移动的对象沿其允许的轴方向平移，直到其外接框前缘正对目标边缺口的中心列/行并紧贴外框内沿停下；途中若与已停好的对象相撞则在相撞前一格停下。
- 外框、缺口、背景保持不变，最终输出对象的新位置。

Key insight
- 每个对象不携带"该往哪走"的标签：方向来自"同色边"这一跨对象全局关系（第一层），而"能不能朝那个方向走、走哪条轴"由对象自身的对称类型决定（第二层），两层共同约束下才能算出落点，缺任一层都会算错目标或方向。
- source：取自参考题 17（彩色框边作为方向标签）、参考题 19（用反射对称类型作为分类依据）与参考题 14（把对象停靠到指定边界口）。变异点：把"框边颜色"从"逐像素移动一格"升级为"为整个对象指定出口"，并用对称类型门控可行轴，使方向与可动性分属两层独立归纳。
</new_puzzle>

<new_puzzle>
<description>
先按每种颜色的像素总数排出名次，再用名次决定每支箭头发射几条平行射线，最后让射线沿箭头方向画到撞墙为止。
</description>

Input structure
- 背景为 Azure。
- 网格各处散布若干个 Grey 的实心矩形"墙"，作为射线的阻挡物。
- 网格中散布若干支极简箭头对象，每支箭头为单色（颜色取自 Red、Green、Yellow、Magenta、Maroon 等），不同颜色的箭头其像素总数互不相同。每支箭头由一段长度为三像素的直线段（杆）加上杆尾端外侧一个像素（尾翼）构成，箭头从尾翼指向杆的另一端（无尾翼端为箭头指向，确保指向性；箭头沿水平或垂直方向）。

Rule
- 第一步（颜色排名）：把所有箭头颜色按其在网格中的像素总数从多到少排名，得到第 1、2、3…… 名。
- 第二步（名次定射线条数）：排名第 k 名的颜色，其每支箭头都要发射 k 条紧贴的平行射线——以箭头指向为前进方向，从箭头无尾翼端那一格出发的中线为第一条，再朝尾翼相反的横向逐条增补，共 k 条（k=1 只有中线，k=2 中线加一侧，k=3 中线加两侧，依此类推）。
- 第三步（射线传播）：每条射线沿箭头方向逐格前进，用该箭头自身的颜色覆盖 Azure 背景，直到撞到任意非背景像素（Grey 墙、其他对象或已画射线）或网格边缘为止，撞墙格不上色。
- 原箭头对象、Grey 墙、背景保持不变，叠加新画出的射线。

Key insight
- 箭头自身只给出方向与颜色，但"发射几条射线"完全由它所属颜色在全局的像素总数排名决定——这是一个跨对象的全局比较，写在被变换对象之外（第一层）；只有先得到名次，才能知道该箭头的射线宽度（第二层），再让射线撞墙停下（第三层）。对单支箭头做一次输入输出对比无法读出排名规则。
- source：取自参考题 9/20（用颜色像素总量做比较/排序）、参考题 6/18（沿方向投射射线、由形状编码方向）与参考题 11（用一个计数值决定几何延展量）。变异点：把"像素总数排名"作为射线条数的隐藏键，使同一支箭头在不同样例里因全局排名变化而吐出不同宽度的射线，且方向、条数、停止三件事分属三层。
</new_puzzle>

<new_puzzle>
<description>
先复原被遮挡的周期底纹，再数出每个遮挡矩形压住了几种不同底色，最后据此把矩形整体重涂成对应结果色。
</description>

Input structure
- 整张网格本应铺满一个小周期的行/列重复底纹（由两到三种颜色构成，例如 Blue 与 Green 交替的小图案，最多三种底色）。
- 底纹之上盖着若干个互不接触的单色实心 Maroon 矩形（高与宽均大于一），把底纹的一部分覆盖掉。
- 矩形的颜色统一为 Maroon，仅作占位用途，本身不携带信息。

Rule
- 第一步（恢复底纹）：把每个 Maroon 矩形视为遮罩，根据矩形之外仍可见的像素推断出最小的重复瓷砖，从而恢复出"如果没有遮挡，每个被盖住的格子原本应是什么颜色"。
- 第二步（点数底色种类）：对每个 Maroon 矩形，数出它所覆盖区域在恢复后的底纹里包含了几种不同的颜色，记为 t。
- 第三步（按种类数重涂矩形）：把该矩形整体重涂为一种结果色——覆盖 1 种底色的矩形涂 Yellow，覆盖 2 种的涂 Red，覆盖 3 种的涂 Grey。
- 底纹的可见部分、背景保持不变，仅替换各 Maroon 矩形的颜色（被矩形盖住的底纹不复原显示，仍由重涂后的纯色覆盖）。

Key insight
- 矩形表面看不出任何信息（全是 Maroon），必须先把不可见的底纹重建出来（第一层非平凡归纳），才能数出每个矩形压住了几种底色（第二层），再据此查"种类数→结果色"表（第三层）。判断依据藏在被遮挡的底纹里，而非矩形本身，杜绝了层塌缩。
- source：取自参考题 13（用可见像素重建周期底纹、矩形为占位遮挡）与参考题 1/19（用一个可数量决定颜色）。变异点：参考题 13 直接输出复原后的底纹，本题反其道把"复原"仅当作中间产物，真正输出的是"每个遮挡块压住几种底色"这一派生统计量映射到的颜色，推理终点完全不同。
</new_puzzle>

<new_puzzle>
<description>
先用各动态色跨面板出现的频率排出节拍快慢，再按节拍快慢的顺序把它们叠画到最后一帧模板上并处理重叠覆盖。
</description>

Input structure
- 网格由一排三个或更多个等大面板拼成（相邻面板间有一像素 Grey 分隔线）。
- 最后一个面板是静态模板，只含固定的 Black 背景与若干固定的 Grey 结构像素。
- 每个更早的面板都等于模板再叠加一些"动态色"像素（动态色取自 Blue、Red、Green、Yellow、Magenta，模板里不含这些色）。
- 每种动态色在这串早面板里按各自固定的间隔规律出现：有的每个面板都出现（快），有的隔一个面板出现一次（中），有的隔两个面板才出现一次（慢）；同一动态色每次出现时其形状与在面板内的位置保持不变。

Rule
- 第一步（测节拍）：对每种动态色，数出它在早面板序列中总共出现了几次，出现次数越多节拍越快。
- 第二步（排序）：把所有动态色按出现次数从多到少（节拍由快到慢）排序；若出现次数相同，则按其在面板内最靠上、再最靠左的像素位置排序。
- 第三步（按序叠画并解决重叠）：以最后一帧模板为画布，按上一步排好的顺序，依次把每种动态色"在其最后一次出现时的那块形状"叠画到模板上；后画的色若与先画的色像素重叠，则覆盖先画的色。
- 输出单个面板大小的网格（即叠完后的模板帧），不保留任何早面板与分隔线。

Key insight
- 解题者必须先识别"哪些是动态色、各自的出现频率"（第一层，需跨面板统计），再把频率转成一个叠画优先级顺序（第二层），最后处理重叠覆盖关系（第三层）。频率与顺序都来自跨面板的时间规律，单看任何一个面板都读不出节拍，避免层塌缩。
- source：取自参考题 2（带框序列面板、动态色按时间规律出现、以模板为画布）与参考题 7/9（用计数排序决定处理次序）。变异点：参考题 2 是沿轴外推区间预测下一帧，本题不外推位置，而是把"出现频率"抽象成叠画优先级，并引入重叠覆盖这一新的第三层冲突解决机制。
</new_puzzle>

<new_puzzle>
<description>
先用两种对角走向像素的多寡判定主走向，再沿主走向把线段延伸到网格边，最后在主次走向交叉处打上结点色。
</description>

Input structure
- 背景为 Black。
- 前景只有一种颜色 Azure，构成若干条一像素宽的对角短线段，每段要么沿 NW/SE 走向，要么沿 NE/SW 走向。
- 每个 Azure 前景像素恰属于一条对角线段（即只有一个对角方向上有同色邻居）。

Rule
- 第一步（定主走向）：分别统计 NW/SE 走向和 NE/SW 走向的 Azure 像素总数，像素较多的那个走向为"主走向"，较少的为"次走向"。
- 第二步（延伸主走向）：把每条属于主走向的线段，沿其对角方向双向延伸，逐格用 Azure 覆盖 Black，直到触及网格边缘；次走向的线段保持原长不延伸。
- 第三步（标记交叉）：延伸完成后，凡是同时落在一条（已延伸的）主走向线和一条次走向线上的格子——即两走向在此交叉的格点——改涂为 Red。
- 背景保持不变，输出延伸后的主走向线、原样的次走向线、以及交叉处的 Red 结点。

Key insight
- "哪个走向该延伸"不是看单条线段自身，而是看两走向像素的全局多寡对比（第一层）；延伸之后才可能产生新的交叉点（第二层的产物喂给第三层）；交叉点的判定依赖第二层延伸后的结果，三层严格前后依赖。对任意单条线段做输入输出对比，既看不出谁是主走向，也看不出交叉会落在哪。
- source：取自参考题 20（按两种对角走向像素多寡分类）、参考题 18/6（沿对角方向投射射线）与参考题 8/14（用交叉/接触关系派生新标记）。变异点：参考题 20 只是给两走向各自换色，本题把"多寡判定"升级为"决定哪一组延伸"，并新增"延伸后交叉点"这一只有完成前两层才会出现的第三层标记。
</new_puzzle>
