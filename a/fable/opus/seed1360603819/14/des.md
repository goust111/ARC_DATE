- `description`：先用图例区把"孔洞数"翻译成"移动方向"，再依据该方向把每个实心对象推到对面墙边，并在原位留下一个该对象颜色的单像素残影。
- `Input structure`：
  - 背景为 Black。
  - 网格左侧有一列竖直排列的"图例对象"：每个图例对象是一个 Magenta 的实心方块，方块内部恰好挖掉若干个 Black 孔洞（孔洞数 1~4 各对应一个图例），方块紧贴该图例右侧画有一个 3 像素的箭头（由三个同色像素构成、明确指向上/下/左/右四个方向之一，箭头颜色为 Grey）。因此图例区建立了"孔洞数 → 方向"的对应表。
  - 网格主区（图例列右侧）散布着若干个互不接触的实心矩形"棋子对象"，每个棋子是单一非背景颜色（如 Red、Green、Yellow、Azure 等，各棋子颜色互不相同），棋子内部也恰好挖掉若干个 Black 孔洞。
- `Rule`：
  - 第一层：从左侧图例区归纳出"孔洞数 → 箭头方向"的映射表（孔洞数是棋子上肉眼可数的属性，但它指向哪个方向必须通过图例归纳）。
  - 第二层：对主区每个棋子，数出它的孔洞数，查表得到它的移动方向；沿该方向把整个棋子平移，直到它的前缘紧贴网格边界（移动过程中忽略其它棋子，棋子在终态若重叠时按棋子在输入中从上到下、从左到右的顺序后到者覆盖先到者）。
  - 第三层：每个棋子被移走后，在它原来 bbox 的几何中心格画上一个该棋子颜色的单像素残影；若中心格落在另一棋子的终态位置上，则残影被棋子覆盖。
  - 图例区在输出中原样保留。
- `Key insight`：孔洞数本身不是答案，它只是查图例表的钥匙；真正的方向信息写在图例区而非棋子身上，因此对单个棋子做输入输出对比无法读出方向规则。
- `source`：取自参考题 11（用散落标记建立"某可见标量 → 调色板/属性"的查表映射）与参考题 9（颜色/属性作为运动指令把对象推走）的机制；变异点在于把"属性→指令"的对应表从题目隐含先验改成必须从同图网格的独立图例区主动归纳，并叠加第三层"原位残影"，使方向表、推动、残影三层互相依赖。
</new_puzzle>

<new_puzzle>
- `description`：把每根竖直彩条按高度排名映射到一排固定颜色插槽，再用"相邻插槽的高度差"决定在重排后的彩条之间画出连接桥。
- `Input structure`：
  - 背景为 Black，底部有一整行 Grey 基线横贯网格。
  - 基线之上立着若干根互不接触的竖直单色彩条，每根从基线向上生长，高度各不相同，颜色互不相同（如 Red、Blue、Green、Yellow、Azure、Magenta 等）。彩条的横向位置即为"插槽"，每个插槽记住自己原本的 x 位置与原本的颜色。
- `Rule`：
  - 第一层：把彩条按高度从矮到高排名，把插槽按原始 x 位置从左到右排名；第 i 矮的彩条形状放进第 i 左的插槽，并重新着色为该插槽原本的颜色（即矮高被重排，但每个插槽保留自己的 x 与颜色身份）。
  - 第二层：重排完成后，沿插槽从左到右两两相邻地比较彩条高度。对每一对相邻彩条，在它们之间那一列 Black 空隙中、于"较矮彩条顶端高度 + 1"那一行起，向较高彩条方向画一条单像素 Grey 水平桥，长度恰好等于这一对彩条的高度差（高度差作为"几格"长度，不是公式）。桥的颜色统一为 Grey。
- `Key insight`：第一层让解题者意识到颜色与形状被解耦（插槽守住颜色、形状被按高度重新分配）；第二层则要求发现"相邻高度差 → 桥长"这一非显然的二次规律，且桥所在的位置与长度依赖第一层重排后的新高度序列，单看任一彩条无法读出桥规则。
- `source`：取自参考题 15（彩条按高度排名重分配到固定颜色插槽）的核心机制，并以参考题 12/18 的"画出贯穿/连接的线条"为线索做机制变异；新组合点是在排序重着色之后再叠加一层"相邻高度差驱动的连接桥"，使排序结果成为第二层的输入，构成真正的两层依赖。
</new_puzzle>

- `description`：每个画框先按其框内"种子像素"补全成完整的缩放模板，再依据该模板的镜像对称类型把画框整体推向对应的网格边，并在原位留下空框。
- `Input structure`：
  - 背景为 Azure。
  - 网格上方排有一排小的彩色"模板掩码"，每个模板是一个紧凑的 Magenta 二值小图案（互不相同），它们是候选模板库。
  - 网格下方散布着若干个矩形"画框"，每个画框是 1 像素宽的 Grey 边框，框内只填有零星几个 Green "种子像素"，且框的内部尺寸恰好是某一个上方模板 bbox 的整数倍放大。
- `Rule`：
  - 第一层：对每个画框，在上方模板库中找出唯一一个"块状放大后能覆盖框内全部种子像素"的模板（种子像素揭示应补全哪个模板），把框内重置为背景并用 Green 画出该模板的整块放大图。
  - 第二层：观察补全后图案的镜像对称性——若图案是左右镜像对称，则把整个画框（含边框与填充）水平推到网格的最右侧；若是上下镜像对称，则推到最底部；若两种对称都满足，则推到右下角；若都不满足，则原地不动。
  - 第三层：在画框被推走后（即第二层判定为需移动的画框），于其原始位置留下一个仅由 Grey 边框组成的空框（内部为背景），作为"已迁出"标记；原地不动的画框不留空框。
- `Key insight`：种子像素只指明补全哪个模板，而模板补全后的对称类型才决定迁移方向——对称性是一个必须在第一层产物之上才能判读的二次属性，单看种子或单看空框都无法同时得到补全规则与迁移规则。
- `source`：取自参考题 2（种子像素选定上方模板并块状放大补全）的核心机制，叠加参考题 7/19 中"对称性作为决定性约束"的思路做机制变异与重组；新组合点是把补全后的对称类型当作第二层的迁移指令，再加第三层"留空框"，三层逐级依赖。
</new_puzzle>

<new_puzzle>
- `description`：先从"成对的源-靶颜色样例"归纳颜色替换规则，再把每个被替换像素旁的 Teal 模板拓印过去，最后把拓印图案按源像素所在的网格象限旋转。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干孤立的单像素"源点"，颜色各异。
  - 有少数几处"规则样例"：两个 4 邻接的彩色像素构成一个有向对（源色像素 → 靶色像素），其延长方向触及一个 Azure 的小连通图案，该图案即为"模板印章"（题中以 Azure 表示 teal）。
  - 其余 Azure 图案是待用的印章副本；其余源色单像素是待被替换的目标。
- `Rule`：
  - 第一层：从每个规则样例读出"源色 → 靶色"的替换映射，以及该样例锚点处的 Azure 模板形状。
  - 第二层：把该 Azure 模板拓印到每一个同为"源色"的其它单像素上（以锚点对齐到源像素），并把拓印出的图案整体重新着色为"靶色"。
  - 第三层：根据被替换源像素位于整张网格的哪个象限（以网格几何中点把网格粗略分为左上/右上/左下/右下四象限），对拓印上去的图案做旋转——左上不转、右上顺时针 90°、右下 180°、左下逆时针 90°。
  - 输出时移除所有原始 Azure 模板与规则样例用到的像素，只保留拓印结果。
- `Key insight`：颜色替换、模板拓印、按象限旋转三件事的线索分别来自规则样例、Azure 印章、源像素的全局位置，三者位于网格不同位置，任何单个对象的输入输出对比都无法同时暴露三层规则。
- `source`：取自参考题 8（成对像素定义颜色替换 + teal 模板作为可重着色印章拓印到同色像素）的核心机制，叠加一层来自参考题 13 思路的"全局位置 → 几何变换（旋转）"做机制变异；新组合点是让拓印图案的朝向由源像素的象限位置决定，构成替换→拓印→旋转的三层管道。
</new_puzzle>

<new_puzzle>
- `description`：每个实心矩形先按其内部孔洞数复制成若干份，再沿对象指向的射线方向逐份收窄地排列，最后把不同对象拖尾的重叠格统一改为 Grey。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干互不接触的单色实心矩形对象，颜色互不相同。
  - 每个矩形内部挖有若干 Black 孔洞（1~3 个），孔洞数是可数的视觉量。
  - 每个矩形紧贴其一条边外侧画有一个 3 像素的同色箭头（三像素构成、明确指向上/下/左/右之一），指明该对象的"发射方向"。
- `Rule`：
  - 第一层：对每个矩形，数出其孔洞数 N，这决定该对象连同原件共生成 N 个副本（孔洞在副本中保持原样）。
  - 第二层：沿箭头方向，把 N 个副本首尾相接地排成一列，相邻副本之间留一格 Black 间隙；每生成下一个副本时，其在垂直于发射方向上的尺寸减少 1 像素（从靠近原件的一侧裁掉一行/一列），形成逐级收窄的"拖尾"。原件为最宽的一份。
  - 第三层：所有对象处理完毕后，若任意两个对象的拖尾在某格发生重叠，则该重叠格统一改为 Grey；箭头在输出中被移除。
- `Key insight`：孔洞数不是直接画在网格上的"份数"，需要解题者发现"孔洞数 = 副本份数"；而"逐份收窄"与"重叠变 Grey"是叠在其上的两个必须分别归纳的二次规律，三层之间依次依赖。
- `source`：取自参考题 9/18 的"箭头/方向指令发射"与参考题 14 的"对象被规范化地复制成多份排列"机制做重组，叠加参考题 5/20 的"重叠/碰撞着色"思路；新组合点是用孔洞数控制份数、用方向控制排列、用逐份收窄制造拖尾、再用重叠变 Grey 收尾，构成三层需主动归纳的多层管道。
</new_puzzle>

<new_puzzle>
- `description`：每个标记先沿视线滑到障碍轮廓的尽头落点，再依据落点所在网格行的奇偶在落点处画出一个朝向网格中心的短箭头。
- `Input structure`：
  - 背景为 Black。
  - 网格中有一个 Grey 的连通障碍区域。
  - 有若干个单像素 Red 标记，每个标记到障碍恰有一条水平或竖直视线。
- `Rule`：
  - 第一层：对每个标记，沿其视线找到撞上障碍前的最后一格背景，再从该格尝试沿障碍外轮廓的两个对角转向，选择能与障碍保持 4 邻接最长的那一条，把标记移动到该轮廓段的终点落点。
  - 第二层：落点确定后，依据落点所在行号是奇数行还是偶数行，在落点处画出一个 3 像素的 Blue 短箭头：若落点为奇数行，箭头沿水平方向指向网格中心（落点偏左则向右、偏右则向左）；若为偶数行，箭头沿竖直方向指向网格中心（落点偏上则向下、偏下则向上）。箭头由三个 Blue 像素构成并明确指向单一方向。
  - 原 Grey 障碍保留不变。
- `Key insight`：第一层要求发现"标记沿轮廓滑到尽头"这一非显然落点规律；第二层的箭头方向并不写在标记或障碍上，而是由落点的行奇偶与落点相对网格中心的位置共同决定，必须在第一层落点产物之上才能归纳。
- `source`：取自参考题 16（标记沿障碍外轮廓滑到轮廓段尽头作为落点）的核心机制，叠加参考题 9/18 的方向箭头与一层"奇偶 → 几何朝向"的判定做机制变异；新组合点是让第二层的箭头方向依赖第一层算出的落点（行奇偶 + 相对中心位置），构成滑动定位与朝向判定的两层依赖结构。
</new_puzzle>
