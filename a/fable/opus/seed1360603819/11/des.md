<new_puzzle>
<description>
先用图例把每个外部小图块的孔洞数翻译成一个颜色，再按该颜色把图块塞进框架内形状匹配的孔洞里。
</description>

Input structure:
- 背景为 Black。网格中央有一个 Grey 的实心矩形框架（一圈 Grey 边框，内部挖空为 Black）。
- 框架内部有若干 Black 的孔洞区域，每个孔洞是一个独立的连通形状，彼此不接触。
- 框架外部散落着若干 Magenta 的小图块（monochrome），每个图块的轮廓形状与某一个内部孔洞的形状全等（允许旋转或翻转）；每个图块内部可能挖有 0 到 4 个 Black 的单像素小孔。
- 网格的最左一列从上到下排列着一组「图例」单像素：每个图例像素占据单独一行，颜色取自 {Blue, Red, Green, Yellow, Orange} 中的某几种，它们出现的先后顺序（从上到下）即第 0、1、2、3、4 个孔洞数对应的颜色。

Rule:
- 第一层：读最左列的图例像素，从上到下第 k 个图例像素的颜色，就是「孔洞数 = k」所映射的填充色。
- 第二层：对每个外部 Magenta 图块，数出它内部 Black 小孔的个数 h（0 到 4），通过图例把 h 翻译成对应的填充色 c。
- 第三层：把图块的外轮廓形状（忽略其内部小孔）与框架内部各孔洞形状逐一比对（允许旋转/翻转），找到唯一全等的孔洞，用颜色 c 把整个孔洞填实。
- 输出：裁剪到框架的 bounding box，框架本身保持 Grey，所有孔洞被对应颜色填满；外部图块与图例不出现在输出中。

Key insight:
- 图块身上有两条独立信息且服务于不同层：它的「形状」决定填哪个孔洞，它的「内部小孔数」经图例决定填什么颜色。两者缺一不可，且颜色映射规则写在网格别处（最左列图例），与图块本身分离，无法靠单个图块的输入输出对比推出。

source: 取自参考题 3（用外部 sprite 的形状匹配内部孔洞并以其颜色填充）与参考题 1/16（用网格别处的图例/共识把一个可数属性翻译成颜色）的机制。新组合点：参考题 3 里 sprite 的颜色直接就是填充色（一层），这里把「填充色」改为由图块的孔洞数经最左列图例间接决定（多一层翻译），使形状匹配与颜色决定彻底解耦为两条独立推理链。
</new_puzzle>

<new_puzzle>
<description>
每个箭头沿其指向发射射线，射线经过的障碍点个数只用于给所有箭头排名次，名次值才是该箭头要画出的同色尾迹长度。
</description>

Input structure:
- 背景为 Black。网格内散落若干 Grey 的「障碍点」单像素，作为可被射线击中的前景。
- 网格四条边的内侧各贴着若干箭头。每个箭头由 3 个同色像素排成一条直线的「箭身」加 1 个同色像素的「箭尖」构成，箭尖那端即为指向；颜色取自 {Red, Green, Blue, Yellow, Orange, Magenta, Azure}，各箭头颜色互不相同。上边的箭头朝下、下边朝上、左边朝右、右边朝左，均指向网格内部。
- 箭头之间不共线、互不遮挡。

Rule:
- 第一层：每个箭头从箭尖出发沿其指向画一条贯穿网格的射线，数出射线路径上经过的 Grey 障碍点个数 n（可能为 0、1、2、3...）。
- 第二层：把所有箭头按各自的 n 值从大到小排成名次，n 最大者为名次 1，次之名次 2，依此类推；若有箭头 n 相同，则其颜色名按字母序靠前者名次更靠前。每个箭头的「尾迹长度」L = 它的名次值。
- 第三层：把每个箭头沿其指向的「反方向」（从箭身尾端那一格起，朝网格内部延伸）连续涂 L 格该箭头颜色的实心尾迹；遇网格边界则截断。
- 输出：保留所有 Grey 障碍点与原箭头，叠加各箭头按名次算出的同色尾迹。

Key insight:
- 射线击中的障碍点个数本身不是答案，它只用来给所有箭头排出一个全局名次；真正画出的尾迹长度是「名次」而非「击中数」。解题者必须先发现「数击中数」，再发现「击中数只用于跨箭头排序、名次才是长度」这一非显然的二次转译，最后才知道往哪画、画多长。

source: 取自参考题 10/14（标记沿方向发射射线、与前景交互）与参考题 12/20（把对象按某可见量排名次、名次决定最终几何尺寸）的机制。变异点：参考题里射线本身就是结果，这里射线只负责「计数」，计数再喂给一个跨箭头排序层产生名次，名次才转成尾迹长度，三层依次依赖、单看一个箭头无法读出排序规则。
</new_puzzle>

<new_puzzle>
<description>
用每种颜色的对象个数当行号去查一张两列颜色表，再把该颜色的所有对象重绘成查到的目标颜色。
</description>

Input structure:
- 背景为 Black。网格右侧有一条竖直的「替换表」：一个连通、完全填实的两列方块，从上到下每行是一对颜色（左列一格、右列一格），表中不含 Black。
- 网格左侧区域散落着若干 monochrome 的 4-连通对象，其颜色都取自替换表「右列」出现过的颜色；同一种颜色可能有多个独立对象，不同颜色的对象个数各不相同。
- 替换表的行数足够覆盖左侧所有出现过的「对象个数」取值。

Rule:
- 第一层：把左侧对象按颜色分组，数出每种颜色各有多少个独立的 4-连通对象，得到该颜色的计数 c（如 Red 有 3 个对象则 c=3）。
- 第二层：以替换表「右列」颜色识别哪些行参与（右列颜色 = 一种待改对象的原色）；同时用计数 c 当行号查表——从最上一行记为第 1 行，第 c 行的左列颜色即为该种颜色对象要改成的目标色。
- 第三层：把该颜色的所有对象整体重绘成查到的目标色，形状与位置保持不变。
- 输出：替换表原样保留；左侧每个对象按其颜色对应的计数查表后被重绘为新颜色。

Key insight:
- 对象的「数量」不是答案，而是查表的行号索引；表的「右列」用来识别哪些对象参与（右列颜色 = 待改对象原色），「左列」给出改成什么色，行的纵向位置（行号）才是与计数挂钩的键。解题者要先发现「数对象个数」，再发现「个数 = 第几行」，再发现「同一行左右两列分别是原色匹配键和目标色」这一双重用途。

source: 取自参考题 16（纵向两列图例定义颜色替换、行序是指令的一部分）与参考题 15（按颜色统计连通对象个数）的机制。新组合点：参考题 16 是「按颜色查行」，这里改成「按对象计数当行号查行」，使图例行序不再表示替换顺序而表示数值索引；统计层（参考 15）的产物（计数）成为查表层的输入，三层严格串联。
</new_puzzle>

<new_puzzle>
<description>
先从多数方块归纳出「位置决定主题色」的隐藏规律，再用它定位唯一染错色的方块并把它纠正为应有的颜色。
</description>

Input structure:
- 网格被等宽的单行/单列 Black 分隔线切成一个规整的方块阵列（如 3×3 共 9 块，每块同尺寸）。
- 每一块内部都有同一张「底图」：底图由 Grey 描出一个固定形状（在所有块里像素位置完全相同），形状内部的格子被填上某一种「主题色」。
- 绝大多数块遵循同一条隐藏的染色规则，即块在阵列中的「位置」决定其主题色（例如同一行的块用同一种主题色，而不同行用不同主题色）。恰有一块违反这条共识：它的主题色用错了。
- 主题色取自 {Red, Green, Blue, Yellow, Orange} 中的若干种。

Rule:
- 第一层：跨多个块比对，归纳出合法块共同遵循的「位置 → 主题色」对应关系（如『同一行同色』）。这条规则必须跨块归纳才能确定。
- 第二层：用归纳出的规则逐块核对每块的主题色，找出唯一一块不符合规则的「异常块」。
- 第三层：把异常块的主题色改成它按第一层规则、由其位置推出的「应有颜色」，其余块、Grey 底图与所有分隔线保持不变。
- 输出：整张阵列，仅异常块被纠正为合规颜色。

Key insight:
- 哪块异常无法靠单块判断——必须先从多数块归纳出「位置决定颜色」的隐藏函数关系，再用这条关系既定位异常、又算出它的正确颜色。判定依据（染色规则）来自全体块的共识，与被纠正的那一块分离，单看异常块自身的输入输出对比读不出规则。

source: 取自参考题 1（用重复副本的多数共识恢复出错的那一份）与参考题 9/20（位置在阵列/坐标系中编码某属性）的机制。变异点：参考题 1 的共识是「逐像素取多数色恢复缺失」，这里把共识升级为「位置→颜色」的函数关系（需归纳一条规则而非逐格投票），定位异常与计算正确值都依赖这条被归纳出的关系。
</new_puzzle>

<new_puzzle>
<description>
两条彩色边线分工：到上边线的远近决定矩形的堆叠先后，到左边线的名次决定它被纵向复制成几份。
</description>

Input structure:
- 背景为 Black。网格上边贴着一整行的 Blue 横线，左边贴着一整列的 Red 竖线（一横一竖两条边线）。
- 网格内部散落若干 monochrome 实心小矩形，颜色各异（取自 {Green, Yellow, Orange, Magenta, Azure, Grey, Maroon}），尺寸可不同，互不接触。

Rule:
- 第一层：以 Blue 横线为主轴。把每个矩形按它到 Blue 横线的距离（顶边离上边有几行，作为『几步』而非公式）从近到远排序，得到堆叠的处理顺序；距离相同时离 Red 竖线近者排前。
- 第二层：以 Red 竖线为次轴。把所有矩形按它们到 Red 竖线的距离也排个名次，最近者名次 1、次之名次 2…（同距离用与第一层相同的 tie-break）；每个矩形的「份数」= 它的名次值。
- 第三层：构造输出。按第一层顺序自上而下处理每个矩形：把它按其份数纵向连续复制那么多份（每份紧贴上一份正下方，形状颜色不变），整组水平居中；相邻矩形组之间空一行 Black。
- 输出：一张新网格，所有矩形按「离上边线近者在上」堆叠，每个矩形按「离左边线的名次」被纵向复制成对应份数。

Key insight:
- 两条边线承担两件完全不同的事：Blue（主轴）只决定谁先谁后（堆叠顺序），Red（次轴）只决定每个矩形复制几份（数量）。两层互相独立又都需归纳——解题者要先看穿「上边线管顺序、左边线管份数」，再分别从距离排名推出顺序与份数，最后才能正确组装；任一层错位都会得到不同输出。

source: 取自参考题 20（两条彩色边线构成坐标系，到各轴的距离分别决定排序与变换）与参考题 12（用某可见量的名次决定最终几何规模）的机制。变异点：参考题 20 里第二个轴决定「旋转」，这里改成「到次轴的名次决定纵向复制份数」，把排序与计数复制两种机制嫁接到同一坐标系上，使两条边线各自独立喂给两个不同的推理层。
</new_puzzle>

<new_puzzle>
<description>
按每个对象的孔洞数把它归类到点数相同的彩色框里，再把它重绘进框内并继承框的颜色。
</description>

Input structure:
- 背景为 Black。网格左侧竖直排列着若干个空心彩色「收纳框」：每个框是一圈单色边框、内部为 Black，边框颜色取自 {Red, Green, Blue, Yellow}，自上而下排列；每个框右侧紧贴着一串同框色的单像素点，点的个数（1 到 4 个）表示这个框接收「孔洞数 = 该点数」的对象。
- 网格右侧散落若干 Grey 的 monochrome 对象，每个对象内部挖有 1 到 4 个 Black 孔洞，形状各异、互不接触，且数量保证各框都装得下分给它的对象。

Rule:
- 第一层：读每个框右侧的同色点串，数出点数 d，建立映射「孔洞数 d → 该框」。
- 第二层：对右侧每个 Grey 对象，数出其内部 Black 孔洞个数 h，按第一层映射把它分配给点数等于 h 的那个框。
- 第三层：把对象按其原形状（保持朝向、不缩放）画进所属框的内部空腔，并改用该框的边框颜色填色；同一个框若分到多个对象，则这些对象在框内自上而下依次排列、互不重叠。
- 输出：左侧每个框内部填入被分配并重新着色为框色的对象；右侧原 Grey 对象清除为 Black，框与点串标签保留。

Key insight:
- 框的「点数」与对象的「孔洞数」是分别藏在网格两侧的两组可数量，必须先各自数出再做匹配；填充颜色不是直接给的，而是由匹配到的框继承。解题者要先发现「点数 = 接收的孔洞数」这条桥接规则，再数对象孔洞做归类，最后才知道往哪个框放、用什么颜色——三层各自需要主动归纳且严格串联。

source: 取自参考题 15（按可数属性分桶的直方图思想）、参考题 13（孤立标记经匹配后『去原位、在目标处重画』）与参考题 3（用属性匹配后继承目标颜色）的机制。新组合点：把分桶键从颜色改为孔洞数，且桶（框）的接收键由框旁点数标签隐式给出（需先归纳），分桶后再继承框色重画，使计数、匹配、重着色三步完全解耦。
</new_puzzle>
