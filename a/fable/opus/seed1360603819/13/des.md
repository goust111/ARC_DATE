<new_puzzle>
<description>
按图例孔洞数把散落的彩色对象配对成"染料-模具"，再用染料颜色重绘对应模具，并把每个模具沿其孔洞缺口方向滑到网格边缘。
</description>

Input structure:
- 背景为 Azure（最常见颜色）。
- 网格左上角有一列纵向图例：从第 0 行起连续若干行，每行第 0 列是一个 Grey 像素，其右侧（第 1 列）是一个彩色像素（染料颜色，互不相同）。图例 Grey 像素个数等于图例行数。
- 图例之外，散布着若干 Grey 实心矩形"模具"，每个模具内部恰好挖掉若干个连通的 Black 孔洞区域（每个孔洞是一块 4-连通的 Black 区域）。
- 每个模具至少有一个孔洞，且其中恰好有一个孔洞接触到了模具的外边缘（形成一个朝某方向开口的缺口），其余孔洞都被 Grey 完全包围。

Rule:
- 清除图例列（恢复为背景）。
- 对每个模具，数出它内部"被 Grey 完全包围的封闭孔洞"个数（不含接触模具边缘的那个开口缺口）。
- 图例第 k 行（从上往下数，k 从 1 开始）所配的封闭孔洞数就是 k：即拥有 k 个封闭孔洞的模具，配到图例第 k 行的染料颜色。把该模具的所有 Grey 像素重绘成这个染料颜色（封闭孔洞仍保持 Black，开口缺口保留）。
- 重绘后，看每个模具那唯一接触边缘的开口缺口朝向哪个方向（上/下/左/右），把整个模具沿该方向平移，直到模具的该侧贴住网格边界为止；模具原位置清为背景。

Key insight:
- 配色键是"封闭孔洞数"而非孔洞总数——边缘开口缺口既是计数时必须排除的干扰，又同时是第二层决定滑动方向的指示器；同一个缺口在两层中扮演相反角色。

source: 取自参考题 2（按连通孔洞数配对 frame 与 sprite 的机制）与参考题 13（按边缘接触方向滑到对面边缘）。变异点：把"孔洞计数"和"边缘方向滑动"用同一个缺口耦合起来——缺口既要在计数层被排除，又要在滑动层被当作方向源，并额外引入参考题 15/19 式的"图例索引→颜色"配色层，使三层之间形成依赖链。
</new_puzzle>

<new_puzzle>
<description>
按每个对象的像素面积排序，依次把它们沿同一条 Green 轨道发射，前一个对象停在轨道末端，后一个对象停在前一个对象的紧邻处，最终在轨道上堆成一列。
</description>

Input structure:
- 背景为 Black。
- 网格中部有一条贯穿整行的水平 Green 单像素轨道（占满某一行的所有列）。
- 轨道上方散布着若干互不相同颜色的 4-连通实心对象（每个对象一种颜色，面积各不相同，面积均在 2 到 8 之间）。
- 轨道左端第 0 列那一格是 Red（发射口标记），其余轨道格为 Green。

Rule:
- 把每个上方对象先"压扁"成一条水平线段：线段长度等于该对象的像素个数，颜色保持该对象原色（对象原位置清为背景）。
- 按面积从大到小给所有对象排序（面积互不相同，排序唯一）。
- 依次把这些水平线段放到轨道所在行上：面积最大的那条线段先发射，靠右端贴住网格右边界停下；下一条（面积次大）线段紧贴着前一条的左端停下；依此类推，所有线段在轨道行上从右到左、无缝排成一列。
- 轨道上原有的 Green 像素被线段覆盖的部分变为线段颜色，未被覆盖的 Green 与 Red 标记保留。

Key insight:
- 面积既决定线段长度，又决定发射顺序（堆叠优先级）——大对象先落、占据末端，小对象后落、向内挤；两层都以"面积"为枢纽但用途完全不同。

source: 取自参考题 4（把对象按像素数压扁成定长线段）、参考题 5（用面积作为几何量）与参考题 3（从一端向内打包停靠）。变异点：用"面积"同时驱动"线段长度"和"发射排序优先级"两层，且第二层的停靠位置依赖第一层产出的所有线段长度（前一条停在哪决定后一条停在哪），形成串行依赖而非并行规则。
</new_puzzle>

<new_puzzle>
<description>
先用每个对象的形状孔洞数在图例中查到它的"层级"，再按层级从高到低把所有对象逐个叠放到一个公共的堆叠锚点上，高层级覆盖低层级。
</description>

Input structure:
- 背景为 Grey。
- 网格右侧有一列纵向图例：连续若干行，每行是一个单独的彩色像素（互不相同），从上到下代表层级 1、2、3……（最上为层级 1）。
- 图例之外散布着若干 4-连通的彩色对象，每个对象一种颜色（颜色与图例颜色不重合），每个对象内部恰好挖了若干个 Black 孔洞（4-连通的封闭 Black 区域，每个对象孔洞数互不相同）。
- 网格左上区域有一个孤立的 Maroon 单像素，作为公共堆叠锚点。

Rule:
- 清除图例列和 Maroon 锚点像素（都恢复为背景）。
- 对每个对象，数出它的封闭孔洞个数 h；图例第 h 行的颜色就是这个对象的"目标颜色"，把该对象重绘成目标颜色（孔洞仍为 Black）。同时该对象的"层级"就是 h（孔洞越多层级越高）。
- 把每个对象整体平移，使其包围盒左上角对齐到原 Maroon 锚点所在的位置（所有对象都搬到同一个锚点叠放，保持各自形状与重绘后的颜色）。
- 叠放顺序按层级从低到高绘制：先画层级最低（孔洞最少）的对象，再画更高层级的对象覆盖在上面；当多个对象在同一格重叠时，层级高者的颜色覆盖层级低者；任一对象的 Black 孔洞格视为透明，不覆盖下层已有颜色。
- 输出网格尺寸为能容纳叠放结果的最小矩形（以锚点为左上角向右下延展，恰好包住所有对象的并集）。

Key insight:
- "孔洞数"是一个三用枢纽：它既经图例查表决定重绘颜色，又直接定义叠放层级（绘制优先级），还隐式地通过"透明孔洞"影响最终可见像素——必须先归纳图例的孔洞→层级映射，再归纳层级→叠放顺序，缺一不可。

source: 取自参考题 2（连通孔洞数）、参考题 12（图例顺序即层序、按优先级从后往前覆盖绘制）与参考题 1（把多个对象按 top→bottom 层序重建堆叠）。变异点：把"孔洞数"升格为同时编码"颜色"与"层级"的双键，并让 Black 孔洞充当叠放时的透明遮罩，使最终可见结果取决于三层的联合推理而非任一层单独可读。
</new_puzzle>

<new_puzzle>
<description>
找出每个 Yellow 标记所指向的轨道末端 gate，把标记沿轨道送到 gate 旁，再依据该 gate 两端的颜色对标记自身做颜色替换。
</description>

Input structure:
- 背景为 Black。
- 网格中有若干互不相交的 4-连通前景组件，每个组件由：一条 Azure 路径（连成一串的 Azure 像素）、一个 Yellow 单像素标记（位于路径某一端附近）、以及位于路径另一端的一个 gate 构成。
- gate 是一个三像素直线 motif：中心是一个 Azure 像素（与路径相连），其两侧紧邻各有一个端像素，两个端像素同色，但不同组件的 gate 端色可能不同（端色取自 Red、Green、Magenta、Orange 中的一种）。

Rule:
- 对每个组件：擦除 Yellow 标记和所有 Azure 路径像素，只保留 gate 的中心 Azure 像素与它的两个端像素。
- 在紧邻 gate 中心、但不位于两个端像素之间连线上的那个 Azure 路径格（即路径接入 gate 的那一格）放置一个标记像素。
- 标记像素的颜色不再是 Yellow，而是替换为该组件 gate 两端的端色：若两端为 Red→新标记画成 Green，Green→画成 Red，Magenta→画成 Orange，Orange→画成 Magenta（即在 {Red,Green} 内互换、在 {Magenta,Orange} 内互换）。
- 没有同时包含标记与 gate 的组件保持不变。

Key insight:
- 必须先归纳"标记沿路径走到 gate 旁停下"这一空间机制，再独立归纳"gate 端色 → 新标记色"这一成对互换的配色规律——两层判据分处组件的两端，单看一个对象的输入输出无法同时读出落点与新颜色的对应关系。

source: 取自参考题 14（标记沿路径走到 gate 旁停下、擦除路径只留 gate 中心）与参考题 19/17（用"另一处"的颜色决定最终上色，且颜色为成对互换关系）。变异点：把参考题 14 原本"保持灰色标记"的结尾替换为"由 gate 端色经成对互换决定标记新色"，使颜色层成为独立的第二归纳层，且落点层与配色层的线索分置路径两端，杜绝层塌缩。
</new_puzzle>

<new_puzzle>
<description>
把每个磁极像素绕其同行/同列配对的枢轴旋转 90 度落点，再按落点处所属象限的指示色给落点上色。
</description>

Input structure:
- 背景为 Black。
- 网格被一条贯穿的水平 Grey 线和一条贯穿的垂直 Grey 线分成四个象限（两条 Grey 线交于一点）。
- 四个象限的外侧角落各有一个单独的指示色像素：左上角、右上角、左下角、右下角各一个，颜色取自 Red、Green、Magenta、Orange（互不相同），用来标识该象限的"上色色"。
- 前景还有 Blue 枢轴像素与 Azure 源像素：每个 Azure 源都能与某个 Blue 枢轴在同一行或同一列上一一配对。

Rule:
- 移除所有 Azure 源像素和四个角落的指示色像素。
- 对每对（源,枢轴）：保持源到枢轴的距离不变，但把这个偏移向量逆时针旋转 90 度，得到落点（若落点出界则该源消失）。
- 落点落在哪个象限（由两条 Grey 线划分，Grey 线本身保留不变），就把落点像素画成该象限角落原来的那个指示色。
- Blue 枢轴、Grey 十字线保持不变。

Key insight:
- 第一层须归纳"绕同行/同列枢轴逆时针旋转 90 度"的几何落点规律；第二层须归纳"落点所在象限 → 角落指示色"的映射——上色依据是落点最终所处的位置（全局区域信息），而非源或枢轴自身携带的颜色，因此必须先算出落点才能确定颜色。

source: 取自参考题 16（Azure 源绕同行/同列 Blue 枢轴逆时针旋转 90 度，落点上色）与参考题 6/15（用所在区域/邻接对象决定颜色）。变异点：把参考题 16 中"落点一律上 Orange"的固定上色，替换为"由落点所落象限的指示色决定"，新增一个依赖第一层落点结果的区域配色层，并用 Grey 十字把网格分区，使颜色判据与被变换像素彻底分离。
</new_puzzle>
