<description>
先根据每个被框区域内最深处的标记颜色确定该区域的颜色循环，再以"距边界几步"向内画同心矩形带，最后把循环里出现过的标记颜色对应的整圈搬运/抹除到另一区域。
</description>

Input structure:
- 背景为 Black。整张网格被若干条贯穿全宽或全高的 Grey 直线分割成多个矩形区域（每条分割线一格宽）。
- 每个矩形区域内部都是纯 Black，区域中散落着 2 到 4 个孤立的单像素标记，标记颜色取自 Red、Green、Yellow、Azure、Maroon 中的几种，且每个标记到该区域边界的"步数深度"互不相同（步数 = 从区域边框向内数到该像素需要走几格，最外圈一格为深度 0）。
- 在所有区域之外、网格最下方有一行控制带：控制带是一排连续的单像素，颜色从左到右排列，长度等于网格被分割出的区域数。

Rule:
- 第一层（每区域调色板）：对每个区域，把它内部的标记像素按"深度由浅到深"排序，得到一个颜色序列；若深度 0 那一圈上没有任何标记，则把该区域原本的 Black 作为序列首位。这个序列就是该区域的调色板。
- 第二层（同心重绘）：在每个区域内，把每一格按它的深度上色——深度第 k 圈用调色板里第 k 个颜色，调色板用完后从头循环，从最外圈向内一圈一圈铺满，形成向内辐射的同心矩形框。
- 第三层（跨区域搬运）：读取最下方控制带，控制带第 i 个像素的颜色指定"第 i 个区域（按从上到下、从左到右顺序编号）"。对每个区域 i，找出它调色板中深度最浅的那个标记颜色 c；在第 i+1 个区域（控制带顺序的下一个）中，把该区域同心带里所有颜色为 c 的整圈像素替换为 Grey。控制带最后一个像素对应的区域不再向后搬运。

Key insight:
- 标记的深度不是用来定位的，而是用来给颜色排定循环次序；只有先归纳出"深度→调色板位置"这层映射，才能正确铺出同心带。控制带是一条跨区域的引用链，把某区域最浅标记色作为"要在下一个区域里抹除的圈"，三层缺一不可。
</description>

source:
- 取自参考题 6（标记按距边界深度排成调色板、向内画同心矩形带）的核心机制；变异点/新组合点：在参考题 6 的两步之上再叠加参考题 8 的"控制行作为发射器/引用链"思想，把控制带改造成跨区域引用——第 i 区域的最浅标记色决定要在第 i+1 区域里抹掉的整圈，使第三层依赖前两层产出的调色板，形成参考题没有的跨区域传递推理。
</new_puzzle>

<new_puzzle>
<description>
用图例方块上孔洞的个数把每个散落对象匹配到一种输出颜色，再按对象自身的像素数量把它重画成一条等长的射线，射线方向由该对象所在行/列里第一个遇到的墙决定。
</description>

Input structure:
- 背景为 Black。网格最上方有一块图例区：图例由 3 到 5 个并排的 Grey 实心小方块组成，每个方块内部挖空出不同个数的 Black 孔洞（1 个、2 个、3 个……），每个方块正下方紧贴一个单像素的"输出色样"（颜色取自 Red、Green、Yellow、Azure、Maroon），表示"含这么多孔洞的对象"应被染成这个颜色。
- 图例下方的主区域中散落着若干个 Maroon 实心团块对象（4-连通），每个对象内部也挖出 1 到若干个 Black 孔洞。
- 主区域的四条外边各有一段 Blue 实心边条（每条边最多一段，作为"墙"），不同对象可能朝向不同的墙；保证每个对象所在的行或列上只有唯一一段墙正对着它。

Rule:
- 第一层（孔洞匹配颜色）：数出每个散落对象内部的孔洞个数，去图例里找孔洞个数相同的方块，读出它下方的输出色样颜色，作为该对象的目标颜色。
- 第二层（像素数定长度）：数出该对象的实心像素总数 N（不含孔洞）。该对象将被替换成一条长度恰为 N 的一格宽射线。
- 第三层（墙定方向）：分别朝上下左右四个方向看，找出该对象所在的行或列上那段 Blue 墙所在的方向作为射线方向。清除原对象，从对象原本所占区域的中心格起，沿该方向画出长度 N、颜色为第一层得到的目标色的射线，遇到网格边界即止。

Key insight:
- 对象的原始颜色（Maroon）只是占位；真正的颜色来自"孔洞数→图例"的查表，长度来自"像素数→等长射线"，方向来自"哪面墙"。三种属性分别从对象的三个不同侧面读出且互不重叠，必须三层全部归纳才能复原。
</description>

source:
- 取自参考题 14（用图例把对象属性映射到输出颜色）的"图例查表上色"机制、参考题 9/10（用一个可数的几何量当作另一个等量几何量，此处像素数→等长射线）、以及参考题 7/15（边缘标记/墙决定方向）的"标记定方向"机制；变异点/新组合点：把"图例键"从颜色或形状改为"孔洞个数"，并让同一对象同时承载三个正交属性（孔洞数管颜色、像素数管长度、所在行列的墙管方向），三层互不依赖同一处线索，构成参考题没有的三维属性解耦推理。
</new_puzzle>

<new_puzzle>
<description>
把每个实心小方块按它内部点缀像素的颜色归类，统计每种颜色的方块数量，再按数量从多到少把这些颜色在网格底部从左到右排成一行直方柱，柱高等于该颜色的方块数。
</description>

Input structure:
- 背景为 Black。网格上半部散落着若干个 3×3 的 Grey 实心小方块，彼此不相邻。
- 每个小方块的正中心格被替换成一个点缀色像素，颜色取自 Red、Green、Yellow、Azure 之一，表示该方块的"类别"。
- 不同类别的方块数量不同，且没有两个类别的数量相同（保证排序唯一）。

Rule:
- 第一层（按点缀色分类计数）：把所有小方块按中心点缀色分类，数出每个类别有几个方块。
- 第二层（按数量排序定列序）：把出现过的类别颜色按"方块数量从多到少"排序；数量最多的排在最左，依次向右。
- 第三层（画直方柱）：清空整张网格为 Black。在网格底部，从最左列开始，为排序后的每个类别画一根一格宽、贴着底边向上生长的实心竖柱，柱子颜色为该类别的点缀色，柱高恰等于该类别的方块数量；相邻两根柱子之间空出恰好一列 Black。

Key insight:
- 小方块的 Grey 外壳是干扰，真正的信息是中心点缀色；解题者必须先把"方块→类别"归纳出来，再发现"类别数量决定柱子的左右次序"，最后才能把抽象的计数结果落地成几何直方图。原始方块的位置与最终柱子位置完全无关。
</description>

source:
- 取自参考题 16/13（图例/标记定义类别集合并据此过滤或选取）的"按内部标记归类"机制、参考题 9（用可数量匹配/选择目标）的计数机制、以及参考题 10（按某属性排序决定输出次序）的"排序定序"机制；变异点/新组合点：参考题里计数通常只用于匹配一个目标，这里把"计数"升级为统计直方图——计数结果同时决定列的左右次序（排序）和柱的高度（落地几何），且输出是全新生成的直方图而非对原对象的就地变换，构成参考题没有的"统计→排序→几何化"三层管道。
</new_puzzle>

<new_puzzle>
<description>
从带刻度锚条推断出一个周期，用这个周期在两个对角锚块之间补全外框刻度，并把刻度全部染成网格别处那个孤立"种子像素"指定的颜色。
</description>

Input structure:
- 背景为 Black。网格中有两个同样大小的同色（Azure）实心矩形锚块，分别位于一个更大隐含矩形的左上角与右下角（第一个在第二个的上方偏左）。
- 左上锚块的正右侧紧贴两根一格宽的竖直 Yellow 控制条，两条之间留有固定的间距（这就是周期的前两个刻度）；左上锚块的正下方同样紧贴两根一格宽的水平 Yellow 控制条，间距与竖直方向一致。
- 在网格的某个空白角落，有一个孤立的单像素"种子"，颜色取自 Red、Green、Maroon 之一。

Rule:
- 第一层（推周期 + 补角）：把左上锚块复制到隐含大矩形缺失的右上角与左下角，使四角各有一个同样的锚块。
- 第二层（周期延展外框）：从两根竖直控制条之间的间距读出周期 p；以 p 为间隔，在左右两列锚块之间沿顶边和底边补出一排刻度点（位置为每隔 p 格一个），同理用水平控制条的周期沿左边和右边补出刻度点，形成一圈离散刻度构成的外框；锚块之间普通的边线格保持 Black。
- 第三层（种子选染）：读出孤立种子像素的颜色 s。把第二层补出的所有刻度点染成 s（不是 Yellow）；四角锚块保持 Azure。原始的两根 Yellow 控制条在输出中也随之并入外框、改染成 s。

Key insight:
- 两根控制条只是周期的前两个刻度，必须先归纳"间距即周期"才能把刻度延展到整个外框；而刻度该用什么颜色，又必须去网格别处那个孤立种子像素里读取。周期来自一处、颜色来自另一处，且补角是延展的前提，三层环环相扣。
</description>

source:
- 取自参考题 11（小控制条是周期帧的前两个刻度、对角锚补全缺角）的核心机制、以及参考题 1/8（孤立标记/控制像素指定颜色）的"远处单像素定颜色"机制；变异点/新组合点：参考题 11 用控制条颜色自身画框，这里把"画什么颜色"从控制条上剥离、交给网格别处一个孤立种子像素决定，使"周期"与"颜色"分居两处，迫使解题者把周期推断和颜色查找分成两层独立归纳，避免参考题 11 中颜色与周期同源导致的层塌缩。
</new_puzzle>

<new_puzzle>
<description>
按每个箭头的指向把它读成"把某色对象推到对面墙"的指令，但推哪种颜色由箭头尾部的小色块决定，推到位后再把堆叠在一起的同色对象数量换算成新染色。
</description>

Input structure:
- 背景为 Black。网格四周各有一段 Grey 边墙。
- 网格内散落着若干个单色实心小团块对象，颜色取自 Red、Green、Yellow、Azure（每种颜色可有多个对象，大小不一）。
- 网格内另有 1 到 3 个箭头标记：每个箭头由 3 个像素构成（一个箭头尖加一段两格的箭杆），明确指向上下左右之一；每个箭头的箭杆尾端紧贴一个单像素小色块，颜色取自上面四种对象色之一，表示"这条指令作用于哪种颜色的对象"。

Rule:
- 第一层（指令解析）：每个箭头解析为一条指令——尾部小色块的颜色 c 指定被作用的对象颜色，箭头尖的指向给出推动方向 d。
- 第二层（沿向推靠）：对每条指令，把网格中所有颜色为 c 的对象沿方向 d 平移，直到各自最前缘抵达该方向上的 Grey 边墙（或抵达另一个已停住的同指令对象的后缘）为止，对象之间不重叠、保持原形，按离墙近者先停的顺序紧密贴靠。箭头本身与小色块在输出中清除。
- 第三层（按堆叠数换色）：推靠完成后，统计每条指令里沿该方向"紧贴成一列/一行"的同色对象个数 m。把这一串贴靠在一起的对象整体重新染色：m=1 保持原色，m=2 染成 Maroon，m=3 染成 Magenta，m≥4 染成 Orange。未被任何箭头指令作用的对象保持原样原位不动。

Key insight:
- 箭头不能只看指向，还要读尾部小色块才知道作用对象，这是第一层的隐蔽点；推靠是第二层；而最终颜色既不来自对象原色也不来自箭头，而来自"推到一起后堆了几个"，这是第三层。判断依据（推哪种、堆几个）分别位于箭头和推靠结果两处，单看一个对象无法同时读出三层。
</description>

source:
- 取自参考题 7/15（边缘标记/箭头给出方向、沿向移动到接触处停止）的方向移动机制、参考题 8（控制像素同时编码"作用对象"与"动作"）的"一个标记携带多重指令"机制、以及参考题 9/10（用可数的对象个数换算输出属性，此处堆叠数→颜色）的计数染色机制；变异点/新组合点：把"箭头方向"与"作用颜色"拆成箭头尖与尾部色块两个分量（第一层），并在"推靠停止"这一常见物理隐喻之上加挂一个非物理的第三层——用推靠后形成的堆叠数量重新染色，使本应塌缩成单层的"沿向移动"题获得真正的多层归纳深度，规避注意事项 8 的物理隐喻陷阱。
</new_puzzle>
