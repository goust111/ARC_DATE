- `description`：用左侧孔洞图例把每个矩形对象映射到一种填充色，再按该填充色对应的"槽位编号"将对象重新堆叠到右侧的对齐塔中。
- `Input structure`：
  - 背景为 Black（主导色）。
  - 网格左上角有一列竖直排布的图例标记：每个图例是一个 2 像素宽的小方块组，左半格为某个图例色（Blue、Green、Red、Yellow、Magenta 之一），右半格画着 1 到 4 个 Grey 的孔洞像素（孔洞数互不相同），表示"该数量的孔洞 → 此图例色"。
  - 网格中部散布着若干个 Azure 的实心矩形框对象（每个为一圈 Azure 边框包围一块 Black 内部，内部被 Azure 内壁分隔成若干个 4-连通的 Black 封闭小室，小室数量为 1 到 4）。
  - 网格最右侧有一根贯穿全高的 Orange 竖直分隔条，分隔条右边是一片空白的 Black 区域（输出塔区）。
- `Rule`：
  - 第一层：对每个 Azure 矩形框对象，数出它内部被边框完全包围的 4-连通 Black 封闭小室个数；用这个个数到左侧图例中查到对应的图例色（孔洞数等于小室数的那条图例）。
  - 第二层：图例在竖直方向上的排列顺序（从上到下）定义了图例色的"槽位编号"：最上面的图例为槽位 0，往下依次递增。每个对象由其匹配到的图例色获得一个槽位编号。
  - 输出：清空所有原始 Azure 矩形框；在右侧 Orange 分隔条右边，从顶部开始逐行向下堆叠，把每个对象重画为一个 1×k 的水平实心横条（k = 该对象的小室数），横条颜色为它匹配到的图例色；横条所在的行号等于它的槽位编号，左端紧贴 Orange 分隔条。若多个对象落在同一槽位编号行，则按它们原本在网格中从左到右的次序，沿同一行依次接续画出（之间留一个 Black 间隔）。Orange 分隔条与左侧图例保留不变。
- `Key insight`：对象自身只暴露"小室数"这一个可见量；这个数先经孔洞图例翻译成颜色，再经图例的竖直排列翻译成输出行位置——颜色和行位置都不写在对象身上，必须跨越两套图例两次归纳。
- `source`：取自参考题 16（用孔洞/小室计数匹配颜色图例的机制）与参考题 4、15（左侧位置图例定义映射）。新组合点：把"计数→颜色"和"图例竖直顺序→输出行槽位"串成两层依赖管道——第一层产物（颜色）成为查第二层（槽位行）的键，对象本身既不含颜色也不含目标行，避免了层塌缩。

<new_puzzle>
- `description`：先由顶部控制条决定每根竖直彩条向左还是向右循环借色，再让每根彩条按它新得到的颜色对应的方向在底部图例查到的步数水平平移。
- `Input structure`：
  - 背景为 Black（主导色）。
  - 网格顶部第一行是一根贯穿全宽的控制条，由 Blue 和 Red 两种像素交替组成；每一段控制像素恰好覆盖其正下方某一根彩条所在的列。
  - 网格中部有若干根 1 像素宽、底部对齐的竖直单色彩条，颜色互不相同（取自 Green、Yellow、Magenta、Azure、Maroon），各占一个不同的列，从左到右排列。
  - 网格底部有一行 Grey 的脚注图例：在每一根彩条的正下方，画着 1 到 3 个 Grey 像素的小水平段，表示"该列对象的平移步数"。
- `Rule`：
  - 第一层（借色）：把彩条从左到右排序。控制条决定每根彩条的取色方向——正上方控制像素为 Red 的彩条，取它"右边相邻彩条"的颜色；为 Blue 的彩条，取它"左边相邻彩条"的颜色（两端按环形回绕）。每根彩条保持自身高度与所在列不变，只把整根的颜色替换为借到的新颜色。
  - 第二层（平移）：底部 Grey 图例段的长度给出每根彩条要平移的步数 n。平移方向由该彩条"借色的方向"决定：从右邻借色的彩条向右平移 n 步；从左邻借色的彩条向左平移 n 步。平移后彩条仍底部对齐，超出网格的部分裁掉。
  - 输出：删除顶部控制条与底部 Grey 图例（恢复为 Black），保留平移后的彩条。
- `Key insight`：彩条最终的位置由两层叠加决定——先用控制条做循环借色得到"新颜色"，借色方向（左邻/右邻）隐含在第一层里，第二层的平移方向正是从"借自哪一侧"读出，而平移步数另由底部图例独立给出，三处线索（控制条、相邻彩条、底部图例）都在对象之外。
- `source`：取自参考题 8、14（循环借相邻色的机制）与参考题 5（顶部控制条选择行为）。变异点：把"借色"从静态重绘升级为"借色 + 由借色方向触发的水平平移"，平移方向不是直接给出而是从第一层的借色方向反推，使两层产生强依赖。

<new_puzzle>
- `description`：三层管道——先用角标记找出自配色簇并读出其中心对象的形状，再以该形状为模板，在网格其余每个由四个同色角标记围成的簇里，把中心对象重绘成模板形状并染成该簇角标记的颜色。
- `Input structure`：
  - 背景为 Black（主导色）。
  - 网格中分布着若干个"簇"。每个簇由四个同色的小角标记（每个角标记为一个 2×2 的实心方块，颜色取自 Red、Green、Yellow、Magenta、Azure、Maroon）摆在一个矩形区域的四角，中心包围着一个单色 4-连通对象（中心对象的颜色与角标记可同可不同）。
  - 恰好存在一个"自配色簇"：其中心对象的颜色与它四个角标记的颜色相同；其余簇的中心对象颜色都与角标记不同。
  - 不同簇的中心对象形状各异，角标记颜色互不相同。
- `Rule`：
  - 第一层：找到唯一的自配色簇（中心对象颜色 = 角标记颜色）。它的中心对象形状被取作"模板形状"。
  - 第二层：对每一个非自配色簇，读出它四个角标记的颜色，作为该簇的"目标色"。
  - 第三层：把每个非自配色簇的中心对象整体替换为模板形状（模板形状以原中心对象的包围盒中心对齐放置，模板的占据像素照搬，方向不旋转），并染成该簇的目标色。自配色簇本身保持不变；所有角标记保持不变。
  - 输出：网格尺寸不变，仅中心对象被改写。
- `Key insight`：模板"长什么样"来自一个簇，模板"染成什么颜色"来自每个簇自己的角标记，而"哪个簇提供模板"由颜色自配这一隐蔽条件锁定——三层各自独立归纳，单看任一被改写的簇无法同时读出模板来源、目标色规则和自配判据。
- `source`：取自参考题 18（四角同色标记包围中心对象、并以"自配色"挑选特殊簇的机制）与参考题 12、11（把一个对象的形状作为模板施加到别处）。新组合点：自配色簇不再是"答案"而升级为"模板供应者"，其形状被广播到所有其他簇并各自重新着色，形成形状来源、着色来源、选取判据三层。

<new_puzzle>
- `description`：三层管道——先按每个方块的边长奇偶把它分到两组，再用顶部图例查到每组对应的填充色，最后把每个方块的中心十字按其组色绘出，且只有当方块边长在同组中排名为最大时才额外画满整圈边框。
- `Input structure`：
  - 背景为 Black（主导色）。
  - 网格顶部有两个并排的 2×2 图例方块：左图例左半为 Grey、右半为某填充色 A，代表"奇数边长组 → 颜色 A"；右图例左半为 Orange、右半为另一填充色 B，代表"偶数边长组 → 颜色 B"。颜色 A、B 取自 Blue、Green、Yellow、Magenta、Azure、Maroon 中两种不同色。
  - 图例下方散布着若干个 Red 的实心正方形对象（边长 2 到 7 不等，互相分离，边长可重复）。
- `Rule`：
  - 第一层：判断每个 Red 正方形的边长奇偶，把所有方块分成"奇数边长组"和"偶数边长组"。
  - 第二层：用顶部图例把奇数组映射到颜色 A、偶数组映射到颜色 B（Grey 标头对应奇数、Orange 标头对应偶数是图例固定语义，需从样例归纳标头与奇偶的绑定）。
  - 第三层：对每个方块，在其几何中心画一个十字标记（中心像素加上下左右四个相邻像素，共 5 像素；奇数边长方块有唯一中心像素，偶数边长方块取其 2×2 中心块的左上像素为基准），十字颜色为该方块所在组的图例色。此外，在每一组内部按边长排序，只有边长最大的那个方块（同组内若并列最大则全部）额外把它的整圈外边框（最外一圈像素）重染为该组图例色。
  - 输出：方块内部其余 Red 像素保持不变，未被改写的背景不变。
- `Key insight`：方块自身只给出"边长"一个量，但边长既经奇偶判断决定染哪种组色（查图例第二层），又经组内排名决定是否加画边框（第三层）；图例标头 Grey/Orange 与奇偶的绑定关系必须从样例推出，三层互相依赖且判据都不写在单个方块上。
- `source`：取自参考题 6（奇数边正方形标中心十字的机制）与参考题 10（按某属性在组内排序取极值）和参考题 4、15（顶部/标头图例映射颜色）。变异点：把"奇偶"从直接结果升级为"分组键"，分组键经图例翻译成颜色，再叠加"组内边长排名极值才加边框"的第三层，使中心十字与边框两种标记由两层不同归纳分别触发。

<new_puzzle>
- `description`：先把每种颜色的两个同色矩形之间补上对角连接段，再统计每条对角段穿过了多少个背景格，用这个长度在底部刻度尺上查到一种端点色，给该对角段的两端各盖一枚端点色印章。
- `Input structure`：
  - 背景为 Black（主导色）。
  - 网格主体中，每种前景色（取自 Green、Yellow、Magenta、Azure、Maroon）都恰好以两个分离的实心矩形对象出现；同色的两个矩形对角错位，朝向彼此的两个角落在一条 45 度斜线上。
  - 网格底部有一根贯穿全宽的刻度尺：它由若干段不同颜色的水平区段拼成（颜色取自 Blue、Red、Orange、Grey），从左到右每段的长度依次为 1、2、3、4……表示"对角段长度为 L → 对应第 L 段的颜色"。
- `Rule`：
  - 第一层：对每种前景色，找到两个矩形朝向彼此的最近角，在它们之间的 45 度斜线上，仅给中间的 Black 像素染上该前景色，画出对角连接段（不含已属于矩形的两个端点像素）。
  - 第二层：数出刚画出的这段对角连接里新染色的像素个数 L（即两矩形间的对角"步数"）。
  - 第三层：用 L 到底部刻度尺上查色——找到刻度尺上长度恰为 L 的那一段的颜色，作为端点色；在该对角连接段两端（即两个矩形朝向彼此的那两个角像素本身）各覆盖一个该端点色的单像素印章。
  - 输出：保留所有原始矩形（除被印章覆盖的两个角像素外）、新画的对角段与底部刻度尺；网格尺寸不变。
- `Key insight`：每条对角段的端点颜色不写在该颜色对象上，而由"它被画出来后的长度"经底部刻度尺翻译得到；必须先完成连接（第一层）才能数出长度（第二层），再据长度查尺取色（第三层），三层严格串行依赖。
- `source`：取自参考题 20（同色矩形间补对角连接段的机制）与参考题 3、19（用一个几何计数作为查表键去取另一属性）。新组合点：把对角连接从终点升级为中间产物——连接的长度成为查底部刻度尺取端点色的键，使原本一层的题变成"连接→量长→查色盖章"三层。
</new_puzzle>
