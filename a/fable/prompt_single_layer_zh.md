注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式等人类能够直观感受计算的内容。
   - **禁止使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算（取模） / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数等复杂且不易被看出来的计算都是禁止使用的。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息（例如颜色id和颜色亮度是禁止使用的）或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式，但注意描述需正确且符合该对象作用，例如箭头需要有指向性，至少为三像素。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7. 单层题的全部难度来自核心机制的隐蔽性，有三条标准：
   - 假设对抗：解题者单看第一个训练样例时，应该会先形成一个貌似成立的更显然假设，需要对比多个样例才能推翻它、找到真正规律。如果一个样例就能猜到规则，说明机制太透明。
   - 感知难度：优先把核心规律建立在需要仔细观察才能看清的结构关系上，避开解题者最先会枚举的一眼即可验证的常见属性（对象大小、颜色异同、像素数量、是否对称等）。
   - 线索与对象分离：决定一个对象如何变换的依据，尽量不要完全写在该对象自己身上。如果对任意单个对象做一次输入输出对比就能直接读出完整规则，该题为零隐蔽，必须重做。
8. 优先从参考题的机制出发进行变异或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
9. 关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，可以放心使用。本轮每道新题都必须恰好一层：
   - ✓ 合格的单层："发现配对标准是 X"→"按配对结果直接重绘" — 只有一个归纳点，后续执行是机械的。
   - ✗ 超出范围的多层："先通过孔洞数量匹配颜色图例"→"再用匹配到的颜色重绘对象" — 两步各需归纳，属于多层题，本轮不要生成。

   **禁止通过堆叠推理阶段、堆叠 tie-break 规则或复杂数学公式来加难度**；难度只能来自注意事项 7 所述的隐蔽性。

生成后对生成的题执行以下五项审查（审查内容不需要保存到文件）：
1. 原创性与取材
  机制内核允许取自参考题，但新题的归纳点与推理路径不得与任何一道参考题相同，也不可只是替换颜色、方向、对象类型等表层要素。同时核对 `source` 字段：每道题都标注了来源参考题，且取材与变异点描述属实。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。没有使用上述注意事项第二条禁止使用的复杂计算。
5. 层级与隐蔽性审查
  逐题检查：若某题需要两个各自归纳的阶段才能解出，超出本轮范围，必须简化为单层。同时按注意事项 7 检查隐蔽性：是否存在能撑过第一个样例的错误假设；规则是否会被单个对象的一次前后对比直接读出（若是则不合格）。
