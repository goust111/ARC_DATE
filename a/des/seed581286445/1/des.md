<new_puzzle>
description：根据框架内部的彩色种子像素推断其所属的外部模板，再利用模板放大后的孔洞位置从散落精灵中选取匹配件填入框架。

Input structure：
- 背景为最常见颜色（black）。
- 网格上方散布着若干小型彩色精灵（sprite），每个精灵由单一非背景颜色的 4-连通像素组成，形状各异，包围盒尺寸不超过 5×5。
- 网格中部偏上有若干小型模板图案，每个模板是一个由某种颜色绘制的小型二值图案（如 3×3 或 4×4 的包围盒），其中部分像素为该颜色、其余为背景色，形成带矩形孔洞的图案。不同模板使用不同颜色，模板之间互不接触。
- 网格下方有一个由 grey 像素围成的单像素厚矩形框架，框架内部尺寸是某个模板包围盒尺寸的整数倍（例如模板为 3×4，框架内部为 9×12，则倍率为 3）。
- 框架内部大部分为背景色，但其中散布着少量"种子像素"，这些种子像素的颜色与某一个模板的颜色相同，且它们的位置恰好落在该模板图案按整数倍放大后前景像素对应的网格位置上（即种子像素是放大模板的部分采样）。
- 框架内部模板孔洞放大后形成的每个矩形背景区域，其尺寸恰好与某个外部精灵的包围盒尺寸相同。

Rule：
- 第一步：识别框架内部种子像素的颜色，找到与之颜色匹配的外部模板。将该模板按整数比例放大（倍率 = 框架内部尺寸 ÷ 模板包围盒尺寸），使放大后的图案恰好填满框架内部。用模板颜色填充所有放大后模板前景位置对应的框架内部像素。
- 第二步：放大后模板的每个孔洞在框架内形成一个矩形背景区域。将每个矩形区域的尺寸与各外部精灵的包围盒尺寸比对，找到唯一匹配的精灵，将该精灵（保持原色和形状）放入该矩形区域的左上角对齐位置。
- 输出为填充完成后的框架区域（含 grey 框架边框），框架外部内容不出现在输出中。

Key insight：种子像素不仅指示选择哪个模板，还通过模板放大后的孔洞位置定义了精灵的放置槽；解题者需先完成"种子→模板匹配→放大填充"的推理，再进行"孔洞→精灵尺寸配对"的推理——两步归纳缺一不可。
</new_puzzle>

description：将网格中散落的彩色环形对象按照嵌套包含关系排序，然后在输出中将每条包含链重新绘制为标准的同心矩形框序列。

Input structure：
- 背景为 black。
- 网格中散布着若干不同颜色的 4-连通单色对象。每个对象都是封闭的环形——即对象像素围成一圈，内部有一块由背景色填充的矩形孔洞。
- 部分对象的孔洞内恰好完整地包含另一个环形对象（被包含对象的全部像素严格位于包含者的孔洞区域内），形成嵌套关系。
- 每个孔洞内最多包含一个对象，因此包含关系形成若干条互不相交的线性链（不会出现分叉）。
- 最内层对象的孔洞内不再包含任何对象。
- 网格中可能存在多条独立的包含链（例如 2-3 条）。

Rule：
- 对每条包含链，从最外层到最内层提取颜色序列。设链长度为 L。
- 每条链输出为一个 (2L−1)×(2L−1) 的小方阵：最外层颜色绘制最外圈单像素厚矩形框，次外层颜色绘制向内缩一格的矩形框，依此类推，最内层颜色填充正中心的单个像素。
- 多条链的输出方阵按链在输入中最外层对象从左到右的顺序水平排列，方阵之间用 1 列背景色分隔。若各链长度不同，短链方阵垂直居中对齐，多余行填背景色。
- 输出网格的高度为最长链对应方阵的边长，宽度为所有方阵宽度之和加上间隔列。

Key insight：解题者必须先从不规则的嵌套环形中识别"谁包含谁"的拓扑包含关系（而非位置的左右上下关系），再将这种层级关系转化为标准化的同心矩形——核心推理在于发现包含关系是排序的依据，输出形式则是归纳的第二层。
</new_puzzle>

<new_puzzle>
description：利用网格边缘的方向标记确定每个内部对象的投射方向，再根据对象自身孔洞数量决定投射步数，在投射终点绘制该对象的镜像副本。

Input structure：
- 背景为 black。
- 网格的四条边缘（第一行、最后一行、第一列、最后一列）上各有若干单像素的 red 标记点，其余边缘像素为背景色。
- 网格内部（非边缘区域）散布着若干小型彩色对象（非 red、非背景色），每个对象是一个 4-连通单色区域，包围盒不超过 5×5。某些对象内部有由背景色构成的孔洞（一个 1×1 背景像素的四个 4-连通邻居都是该对象像素，则算一个孔洞）。
- 每个内部对象恰好与某条边缘上的一个 red 标记点在同一行或同一列对齐（即对象包围盒的行范围包含该 red 点所在行，或对象包围盒的列范围包含该 red 点所在列）。每个对象仅与一个 red 标记对齐，每个 red 标记也只对应一个对象。

Rule：
- 确定投射方向：若 red 标记在顶部边缘且与对象同列范围内，则方向为向上；在底部边缘则向下；在左侧边缘且与对象同行范围内则向左；在右侧边缘则向右。
- 数出该对象内部的孔洞数量 N（N ≥ 1 且 ≤ 4）。
- 沿投射方向，将对象整体平移 N 次，每次平移距离等于对象在投射方向上的包围盒跨度。即总平移距离 = N × 对象在该方向的跨度。
- 在平移终点位置绘制该对象的镜像副本：若投射方向为上或下，则做左右镜像；若投射方向为左或右，则做上下镜像。副本使用与原对象相同的颜色。
- 原始对象保留不变，red 标记点保留不变。若副本超出网格边界则裁剪掉越界部分。

Key insight：解题者需完成三层独立的归纳——通过对齐关系将对象与 red 标记配对以确定方向（第一层），数出对象内部孔洞得到平移倍数（第二层），理解副本是镜像而非原样复制（第三层）——三者共同决定最终结果。
</new_puzzle>

description：在由分隔线划分的多面板网格中，根据面板边缘颜色条的配对"握手"确定面板的正确拼接顺序，合并后输出完整拼图。

Input structure：
- 背景为 black。
- 网格被若干条完整的单像素 grey 分隔线（贯通整行或整列的直线）划分为 4 到 6 个矩形面板。
- 每个面板内部包含一个由某种颜色填充的图案（不同面板图案颜色不同），图案不接触面板边界。
- 每个面板的内侧紧贴边界的一行或一列上，可能有一段连续的彩色条（1 像素宽，长度等于面板在该方向的尺寸），这种彩色条称为"边缘条"。边缘条的颜色不同于该面板的图案颜色，也不是背景色或 grey。
- 每个面板有 0 到 4 条边缘条（分布在上、下、左、右四侧中的若干侧）。
- 配对规则：面板 A 右侧有颜色为 C 的边缘条，且面板 B 左侧也有颜色为 C 的边缘条，则 A 在 B 的左边。同理，A 下侧与 B 上侧颜色相同，则 A 在 B 的上方。
- 所有面板通过边缘条配对可以唯一拼成一个矩形布局（例如 2×2 或 2×3 排列）。所有面板的内部尺寸（不含边缘条）相同。

Rule：
- 提取每个面板四侧的边缘条颜色。
- 通过颜色匹配确定面板间的上下左右邻接关系。
- 输出中，按确定的顺序拼接各面板：每个面板仅保留去除边缘条后的内部图案区域（边缘条在输出中消失），面板之间无间隔地直接拼合。
- Grey 分隔线不出现在输出中。
- 输出网格尺寸 = 单个面板内部尺寸 × 排列的行列数。

Key insight：面板在输入网格中的位置是被打乱的，不能直接反映其正确空间关系；解题者必须发现边缘条是"握手协议"——同色边缘条标记了相邻面板的接触面——并通过颜色匹配重建二维拼接顺序。
</new_puzzle>

<new_puzzle>
description：识别网格中多组"钥匙-锁"配对，根据缺口与凸出尺寸匹配确定配对关系，再根据锁缺口方向旋转钥匙并将其嵌入锁中。

Input structure：
- 背景为 black。
- 网格中散布着若干"锁"对象和"钥匙"对象，互不重叠。
- 每个锁是一个由 grey 像素组成的实心矩形，但矩形的某一侧边缘中段有一个矩形缺口（缺口处为背景色，缺口不在角落，而是居中于该侧边缘）。缺口出现在上、下、左、右四侧之一，且各个锁的缺口方向和尺寸各不相同。缺口尺寸描述为"宽 W × 深 D"：W 是缺口沿边缘方向的像素数，D 是缺口向矩形内部延伸的像素数。
- 每个钥匙由某种彩色（非 grey、非背景）像素组成，形状为一个矩形主体附带一侧（固定为右侧）的矩形凸出。钥匙主体和凸出共同构成一个 L 形或 T 形的连通图案。凸出部分的尺寸为"高 H × 宽 W_k"（H 是凸出沿主体边缘方向的像素数，W_k 是凸出向外延伸的像素数）。
- 每个钥匙凸出的 (H, W_k) 恰好与某个锁缺口的 (W, D) 在可能的旋转下匹配：即 (H, W_k) = (W, D) 或 (H, W_k) = (D, W)。匹配是唯一的一一对应。

Rule：
- 通过凸出与缺口的尺寸匹配，将每个钥匙与锁一一配对。
- 确定锁的缺口朝向（上/下/左/右）。
- 将钥匙整体旋转 0°/90°/180°/270°（顺时针），使钥匙的凸出部分朝向与锁缺口朝向相反的方向（即凸出朝向锁内部方向）。旋转映射：缺口朝左→凸出朝右→旋转 0°；缺口朝上→凸出朝下→旋转 90°；缺口朝右→凸出朝左→旋转 180°；缺口朝下→凸出朝上→旋转 270°。
- 将旋转后的钥匙平移至锁的位置：凸出部分恰好嵌入缺口内（像素对齐，凸出填满缺口），钥匙主体紧贴锁的缺口侧外部。
- 输出中，锁和嵌入后的钥匙都保留，钥匙原始位置变为背景色。其余像素不变。

Key insight：解题者需同时推理两个非显然的对应关系——通过缺口与凸出的尺寸匹配（可能需要考虑旋转后宽高互换）确定"谁配谁"，再通过缺口方位确定旋转角度"怎么转"——两层推理交织在一起，仅靠单一线索无法完成任务。
</new_puzzle>

<new_puzzle>
description：根据散落的彩色标记像素数量确定每个矩形区域的生长层数，再从区域对角方向的特殊像素读取生长颜色，向外绘制对应层数的同心矩形环。

Input structure：
- 背景为 black。
- 网格中有若干实心彩色矩形区域（颜色各不相同，如 blue、green、orange、maroon 等），矩形之间保持足够间距。
- 每个矩形外侧紧邻的一圈像素中（曼哈顿距离为 1 的位置），散布着 1 到 4 个 yellow 标记像素。这些 yellow 像素位于矩形的上、下、左、右四侧的外邻位置（不在对角位置）。
- 每个矩形的四个对角方向（矩形包围盒四个角各向外对角偏移一格的位置）中，恰好有一个位置放置了一个单像素的特殊颜色点（非背景、非 yellow、非该矩形自身颜色），此颜色即为该区域将要使用的"环颜色"。其余三个对角位置为背景色。

Rule：
- 对每个矩形区域，数出其外侧紧邻位置上的 yellow 标记像素数量 N（1 ≤ N ≤ 4）。
- 读取该矩形对角方向上的特殊颜色像素的颜色 C。
- 以该矩形为核心，向外依次绘制 N 层同心矩形环，每层厚 1 像素，颜色均为 C。第 1 层环紧贴矩形外侧，第 2 层紧贴第 1 层外侧，以此类推。
- 若某层环的像素位置已被其他矩形区域或其他矩形的环占据，则该像素不绘制（不覆盖已有内容）。
- 输出中，yellow 标记像素和对角特殊颜色像素均被移除（被环覆盖则显示环色，否则变为背景色）。矩形本身保持不变。

Key insight：解题者需完成两层独立的信息提取——yellow 标记的数量编码了"生长多少层"（定量信息来自四侧），对角位置的特殊颜色编码了"用什么颜色生长"（定性信息来自角落）——两种线索来源于矩形周围不同方位的不同类型标记，必须分别识别后结合使用。
</new_puzzle>

<new_puzzle>
description：将输入中交错排列的彩色条纹图案拆分为两组独立图层，分别按各自的平移偏移量对齐后叠加，生成合成输出。

Input structure：
- 背景为 black。
- 网格中有一个矩形区域被完全填满（无背景色），由水平条纹组成。条纹使用两种不同颜色交替出现，例如奇数行为颜色 A 的条纹，偶数行为颜色 B 的条纹（或反之）。
- 每条条纹是一行像素，其中大部分像素为该条纹的主色（A 或 B），但有若干像素被替换为一种"标记色"（如 red），形成该条纹内的图案。
- 关键观察：同色条纹（如所有 A 色条纹）中的标记色像素如果按条纹顺序上下堆叠，会形成某个图形，但该图形在不同条纹间存在固定的水平偏移——即每隔一条 A 色条纹，标记图案向右偏移固定像素数 dA。B 色条纹同理，有自己的偏移量 dB。
- 矩形区域外四角之一有一个 2×1 的小色块，上方像素颜色为 A、下方为 B，指示输出中 A 图层在上、B 图层在下的叠放顺序。

Rule：
- 将所有 A 色条纹提取出来，按原始行顺序排列，并将每条条纹反向平移以消除偏移（即将第 k 条 A 色条纹向左移动 k×dA 像素，循环移位），得到 A 图层的对齐图案。
- 同样处理所有 B 色条纹，得到 B 图层的对齐图案。
- A 图层和 B 图层各自形成一个矩形图案（高度 = 该色条纹数，宽度 = 条纹长度）。
- 按色块指示的顺序，将两个图层上下拼接（A 在上 B 在下）输出。输出中仅显示标记色像素的位置（用原标记色绘制），其余位置为背景色。

Key insight：交错排列的条纹隐藏了两个独立的信息图层，每层内部还有递进的水平偏移使图案难以直接辨认——解题者需先发现"奇偶分层"，再归纳每层的"等差偏移"规律并反向校正，最后按指示顺序合成输出。
</new_puzzle>
