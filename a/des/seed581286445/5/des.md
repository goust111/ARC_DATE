<new_puzzle>
根据封闭区域内部"种子"像素的颜色，从区域的颜色图例面板中查找对应的填充纹理，并将该纹理平铺填满整个封闭区域。

Input structure
- 网格由一种主背景色构成。
- 网格左侧或顶部有一个矩形"图例面板"，面板内分成若干等大的小格，每个小格的左上角有一个单像素颜色标记，小格内其余像素构成一个 3×3 的二色纹理图案（由该标记色与背景色交替排列）。
- 网格其余区域中，有若干用同一种边框色（如 Grey）绘制的封闭矩形区域，区域内部全部为背景色，但每个区域内部恰好有一个非背景、非边框色的单像素"种子"。
- 种子像素的颜色一定与图例面板中某个小格的标记色相同。

Rule
- 保持边框和图例面板不变。
- 对每个封闭矩形区域，找到其内部种子像素的颜色，在图例面板中匹配具有相同标记色的小格，取出该小格的 3×3 纹理图案。
- 以区域左上角为起点，将该 3×3 纹理图案以平铺方式填满整个封闭区域内部（种子像素被纹理覆盖）。

Key insight
种子像素不是填充色本身，而是查表索引——解题者需先识别图例面板中颜色与纹理的映射关系，再将正确的纹理平铺到对应区域，形成"颜色→查表→纹理铺设"的两层推理。
</new_puzzle>

<new_puzzle>
将网格中散落的同色像素对连线，当两条不同颜色的连线交叉时，在交叉点处绘制交叉色标记，并根据交叉点数量截断较短的连线。

Input structure
- 背景色为 Black。
- 网格中有若干种前景色，每种前景色恰好出现两个单像素点，分布在不同的行和列上。
- 同色的两个像素点总是一个在另一个的严格水平或严格垂直方向上（即共享同一行或同一列）。
- 不同颜色的连线可能会在某些像素位置交叉。

Rule
- 对每种前景色，在其两个同色像素之间沿共享的行或列画一条直线段（包含两端点），线段颜色与像素相同。
- 所有颜色的线段同时绘制后，检查每个像素位置：若该位置被两条或更多不同颜色的线段同时覆盖，则将该位置标记为 Red（交叉标记色）。
- 对每种前景色，统计其线段上 Red 交叉标记的数量 N；若 N > 0，则从线段的两端各向内收缩 N 个像素（即从两端各删去 N 个像素，包括端点本身），收缩后剩余部分保持原色，被删去的非交叉位置恢复为背景色。
- 若收缩后线段长度不足以保留任何像素，则整条线段消失（全部恢复为背景色），但交叉标记 Red 仍然保留。

Key insight
解题者需要先完成"连线"操作来发现交叉点，再利用交叉点数量反过来修剪线段本身——产出依赖于中间结果的反馈，形成"画线→检测交叉→按交叉数截断"的三层推理链。
</new_puzzle>

<new_puzzle>
在网格中找到所有相同形状但不同颜色的对象，按照它们的面积从小到大排序，然后将每个对象重新着色为排序序列中下一个对象的原始颜色（循环排列）。

Input structure
- 背景色为 Black。
- 网格中散布着若干个 4-连通的单色前景对象，每个对象由单一非背景色构成。
- 所有对象具有完全相同的形状（平移后重合），但颜色各不相同，且面积（像素数）也各不相同——这里"相同形状"指的是对象内部像素的相对排列一致，但对象所占用的像素总数相同。
- 实际上，所有对象的像素数量相同（形状相同则面积必然相同）。区分排序的关键属性不是面积，而是对象的"包围盒面积"（最小外接矩形的行数×列数）。不同对象虽然像素形状相同，但在网格中的旋转状态不同（0°、90°、180°、270°），导致包围盒尺寸不同。

Rule
- 识别网格中所有前景对象，确认它们是同一形状的不同旋转版本。
- 计算每个对象的包围盒面积（行数×列数）。
- 按包围盒面积从小到大排序；若相同，则按对象左上角的行号从小到大排序。
- 将排序后的颜色序列循环右移一位：即排序中第一个对象获得最后一个对象的颜色，第二个获得第一个的颜色，依此类推。
- 每个对象在原位置重新着色为分配到的新颜色，形状和位置不变。

Key insight
对象表面上"形状相同"，解题者需要注意到它们其实是同一模板的不同旋转态，而旋转导致包围盒不同；排序键是包围盒而非像素数或位置，颜色的循环移位规则需要从多个样例中归纳——"识别旋转→按包围盒排序→循环换色"构成三层推理。
</new_puzzle>

<new_puzzle>
网格中的彩色"门"对象控制着相邻通道的通断：打开的门让通道中的信号色通过，关闭的门则阻断信号并在阻断处标记警示色。

Input structure
- 背景色为 Black。
- 网格被 Grey 色的水平或垂直单像素厚墙壁分隔成若干矩形通道（通道宽度为 1 行或 1 列）。
- 每面墙壁上恰好有一个非 Grey、非背景的单像素"门"，门的颜色为 Green 或 Maroon。
- 每条通道的一端（靠近网格边缘的一端）有一个 Azure 色单像素"信号源"。

Rule
- 信号从每个 Azure 信号源出发，沿通道方向传播，将通道中的背景像素染为 Azure。
- 当信号到达一面墙壁时，检查墙壁上的门颜色：
  - 若门为 Green（开门），信号穿过墙壁继续在下一条通道中传播。
  - 若门为 Maroon（关门），信号被阻断；将门的 Maroon 像素改为 Red，信号不再向前传播。
- 信号持续传播直到遇到 Maroon 门、网格边界、或通道尽头。
- 所有未被信号到达的通道像素保持为背景色。Grey 墙壁和 Green 门保持不变。

Key insight
解题者需要先理解门的颜色编码（Green = 通行，Maroon = 阻断），再追踪信号的级联传播路径——关键在于发现门色决定通断、信号可跨越多面墙壁级联传播、以及阻断时门色变化这三条规则的叠加，而非简单的单步填充。
</new_puzzle>

<new_puzzle>
将网格中的多色拼图碎片按照边缘互锁关系拼合到指定框架中，碎片的摆放顺序由隐含的层叠规则决定。

Input structure
- 背景色为 Black。
- 网格分为左右两个区域，由一条 Grey 垂直分隔线隔开。
- 右侧区域是一个与碎片总面积匹配的空矩形框架（框架边框为 Grey，内部为背景色）。
- 左侧区域散布着若干个单色 4-连通碎片，每个碎片颜色不同。
- 每个碎片的边缘有凸出部分（多出 1 像素的突起）和凹入部分（缺少 1 像素的缺口），凸凹像素沿碎片的某一边排列。
- 两个碎片能拼合，当且仅当一个碎片的凸出部分恰好嵌入另一个碎片的凹入部分（形状互补）。

Rule
- 找到所有碎片之间的边缘互锁配对关系（凸对凹）。
- 从左侧区域面积最大的碎片开始，将其放置在右侧框架的左上角。
- 按照互锁关系，依次将与已放置碎片相邻的下一块碎片拼接上去——拼接方向由凸凹边所在的朝向决定（凸出朝右则新碎片放在右侧，凸出朝下则新碎片放在下方）。
- 当一个碎片与已放置碎片的凸凹互锁后，凸凹像素合并（凸出像素填入凹入缺口，合并后该行/列变为平齐），合并处的像素颜色采用后放置碎片的颜色。
- 所有碎片拼合完毕后，左侧区域清空为背景色。

Key insight
解题者需要先通过边缘形状的互补性识别碎片之间的配对关系，再确定拼合顺序（从最大碎片开始、按邻接关系扩展），最后理解合并处的颜色覆盖规则——"形状互补配对→拼合顺序→覆盖规则"形成三层推理结构。
</new_puzzle>

<new_puzzle>
网格中每个彩色对象都是一把"钥匙"，其形状编码了需要解锁的"锁孔"位置；解锁后锁孔区域被填充为钥匙的颜色，而钥匙本身消失。

Input structure
- 背景色为 Black。
- 网格中有一个大型 Grey 矩形区域作为"锁面板"，锁面板内部有若干个由背景色构成的"锁孔"——每个锁孔是一个与某把钥匙形状完全相同的连通区域（背景色洞）。
- 锁面板外部散布着若干个不同颜色的单色 4-连通前景对象，即"钥匙"。
- 每把钥匙的形状（平移后）与锁面板内恰好一个锁孔的形状完全匹配。
- 钥匙可能需要旋转 90° 的整数倍才能与锁孔匹配，但不需要翻转。

Rule
- 对每把钥匙，尝试 0°、90°、180°、270° 四种旋转，找到锁面板内与之形状完全匹配的唯一锁孔。
- 将匹配的锁孔区域填充为该钥匙的颜色。
- 将钥匙原来所在的位置清除为背景色。
- 锁面板的 Grey 边框和未匹配区域保持不变。

Key insight
解题者需要先识别"钥匙形状 = 锁孔形状"的对应关系（可能需要心理旋转），再执行"钥匙消失、锁孔填色"的变换——核心挑战在于跨区域的形状匹配需要考虑旋转，而非简单的颜色或位置对应。
</new_puzzle>

<new_puzzle>
网格中的箭头指示了颜色传递方向：每个彩色方块沿箭头方向将自身颜色"推送"到下一个方块，形成级联传递链，链尾方块获得链首颜色，链首方块获得背景色。

Input structure
- 背景色为 Black。
- 网格中散布着若干个大小相同的正方形彩色方块（如 3×3），每个方块为单一非背景色，方块之间不相邻。
- 每两个相邻（水平或垂直方向上最近的一对）方块之间恰好有一个单像素的 Grey 箭头标记。箭头标记的具体形状为：箭头是由 3 个 Grey 像素组成的 L 形——一个像素在中心，另外两个像素分别在中心的同一侧相邻位置，形成指向某个方向的视觉箭头（例如指向右的箭头：中心像素 + 上方像素 + 下方像素构成">"形）。
- 箭头始终指向两个方块中的一个，表示颜色传递方向：从箭头背离的方块传向箭头指向的方块。
- 所有方块和箭头形成一条或多条不分叉的链。

Rule
- 沿每条链的箭头方向追踪传递路径。
- 链中每个方块的颜色被替换为其上游方块（箭头来源方向）的颜色。
- 链首方块（没有上游的方块）变为背景色 Black。
- 箭头标记在输出中被清除为背景色。
- 链尾方块获得其上游方块的原始颜色（即传递前的颜色，非传递后的）。所有传递同时发生，使用各方块的原始颜色。

Key insight
解题者需要先从箭头的朝向识别传递方向，再追踪完整的传递链，最后理解颜色是"同时传递"而非逐步覆盖——"箭头方向解码→链路追踪→同步颜色移位"形成三层推理，其中同步传递的语义容易与逐步传递混淆。
</new_puzzle>

<new_puzzle>
网格包含若干"画笔"对象和一个"画布"区域；每把画笔的颜色和朝向决定它在画布上绘制的笔画位置与方向，笔画长度则由画笔自身的像素数决定。

Input structure
- 背景色为 Black。
- 网格右下角有一个矩形"画布"区域，边框为 Grey，内部为背景色。
- 画布外部散布着若干"画笔"对象，每个画笔是一个单色的 4-连通线段（水平或垂直的一排像素，长度 2-6 不等），颜色各不相同。
- 每个画笔的一端有一个相邻的单像素 Yellow 标记，位于画笔的某一侧（上/下/左/右），表示该画笔的"笔尖方向"。
- 画布的一条边（上边或左边）上按等间距排列着与画笔同色的单像素"锚点"。

Rule
- 将每个画笔与画布边上同色的锚点配对。
- 从锚点出发，沿画笔的笔尖方向（由 Yellow 标记相对于画笔的方位决定）在画布内部绘制一条直线笔画。
- 笔画的长度等于该画笔的像素数（不含 Yellow 标记）。
- 笔画颜色与画笔颜色相同。
- 画笔和 Yellow 标记在输出中保持不变；画布内未被笔画覆盖的区域保持为背景色。

Key insight
解题者需要同时解码三种信息——颜色配对（画笔↔锚点）、方向（Yellow 标记的相对位置）、长度（画笔像素数）——并将它们组合才能确定画布上每条笔画的完整参数。单独看任何一条规则都很简单，但三者的交叉组合构成了需要多样例才能归纳的推理挑战。
</new_puzzle>
