<new_puzzle>
根据孔洞数量选择颜色图例，再用选中的颜色重绘对象的内部填充。

Input structure
- 背景为黑色。
- 网格分为两个区域：左侧是"图例区"，右侧是"操作区"，两者之间由一列灰色分隔线隔开。
- 图例区包含若干小的实心正方形色块（如 red、blue、green），每个色块下方紧挨着一行由 yellow 像素组成的点阵，点的数量各不相同（1 到 5 个），作为该颜色的编号标签。
- 操作区包含若干由 maroon 像素构成的封闭空心矩形框（边框宽度 1 像素），每个矩形框的内部完全为黑色背景，但矩形框的边框上有若干个 1 像素的缺口（孔洞），孔洞数量与图例区的某个 yellow 点阵数量一一对应。

Rule
- 对操作区中的每个空心矩形框，数出其边框上的孔洞数量。
- 在图例区中找到 yellow 点数与该孔洞数量相同的色块，获取该色块的颜色。
- 将该矩形框内部（不含边框）的所有黑色像素重绘为匹配到的颜色。
- 图例区和分隔线保持不变，矩形框的 maroon 边框也保持不变。

Key insight
孔洞数量不是装饰——它是查找图例的索引键；解题者需要先发现"孔洞数 = 标签点数"的对应关系，然后才能确定填充颜色。两步推理缺一不可：识别计数对应关系是第一层，执行颜色填充是第二层。
</new_puzzle>

<new_puzzle>
将散落的单色碎片旋转拼入唯一匹配的容器凹槽中，旋转角度由容器缺口方向决定。

Input structure
- 背景为黑色。
- 网格中有若干由 grey 像素构成的大型 L 形或 U 形容器，每个容器有且仅有一个矩形凹槽开口朝向四个正方向之一（上、下、左、右）。
- 网格中散落着与容器数量相同的小型单色碎片（颜色各不相同，如 red、blue、green 等），每个碎片是一个不规则但连通的 4-连通对象。
- 每个碎片的形状恰好能以某个 90 度倍数的旋转后精确填入某一个容器的凹槽。碎片的原始朝向统一为"开口朝上"对应的基准形态。

Rule
- 对每个容器，确定其凹槽开口朝向的方向（上、下、左、右）。
- 找到形状匹配该凹槽的碎片（旋转后形状与凹槽完全吻合的唯一碎片）。
- 将碎片按容器开口方向旋转到正确朝向：开口朝上则不旋转，朝右则顺时针 90 度，朝下则 180 度，朝左则逆时针 90 度。
- 将旋转后的碎片放置到容器凹槽的精确位置，碎片保持其原始颜色。
- 原始位置的碎片被清除为黑色背景。

Key insight
容器的开口方向同时编码了两个信息：哪个碎片属于它（形状匹配）以及碎片需要旋转多少度。解题者必须先通过形状匹配建立碎片-容器配对，再通过开口方向确定旋转量——这两步推理相互独立且都不显然。
</new_puzzle>

<new_puzzle>
沿每个箭头指向的方向传播颜色波纹，波纹在碰撞时按距离优先级覆盖。

Input structure
- 背景为黑色。
- 网格中散布若干由 5 个像素构成的箭头形状，每个箭头由一种非黑非灰颜色绘制。箭头的绘制方式：一个中心像素，加上指向方向的一个像素（箭头尖端），再加上垂直于指向方向、位于中心像素后方一格的三个像素（箭头尾部横杠）。箭头可指向上、下、左、右四个方向之一。
- 网格边缘可能有若干 grey 像素作为墙壁障碍。

Rule
- 保留所有箭头和灰色墙壁不变。
- 从每个箭头的尖端像素开始，沿箭头指向的方向逐格发射波纹：将该方向上从尖端往外的所有黑色像素染为箭头的颜色，直到碰到网格边缘、灰色墙壁或另一个箭头的本体像素为止。
- 当两个箭头的波纹在同一像素相遇时（即该像素同时在两个波纹的路径上），采用以下优先级规则：距离自己箭头尖端更近的波纹获胜；若距离相同，则保持黑色不染色。

Key insight
每个箭头的方向和位置共同决定其波纹的覆盖范围，但真正的难点在于发现碰撞处的 tie-break 规则——不是简单的颜色优先级，而是"谁离自己的源更近谁获胜"，距离相等则留空。这需要解题者从重叠区域的染色模式中逆向推断出距离比较规则。
</new_puzzle>

<new_puzzle>
根据封闭区域内种子像素的颜色对区域染色，再将染色区域的面积转换为该区域边框上等距排列的标记点。

Input structure
- 背景为黑色。
- 网格中有若干由 grey 像素绘制的封闭多边形轮廓（边框宽 1 像素，各多边形互不接触，形状为简单的轴对齐矩形或 L 形）。
- 每个封闭区域内部恰好有一个非黑非灰的"种子"像素（颜色各不同，如 red、blue、green、yellow 等）。
- 每个封闭区域的内部面积（黑色像素数，不含种子和边框）各不相同且均不超过 10。

Rule
- 第一步：对每个封闭区域，将其内部所有黑色像素染为种子像素的颜色（种子本身保持不变）。
- 第二步：数出每个区域被染色的像素数量（即内部面积减去种子占的 1 格）。
- 第三步：在该区域的 grey 边框上，从边框的左上角像素开始，沿边框顺时针方向，每隔一个边框像素放置一个种子颜色的标记点（即将该 grey 像素改为种子颜色），总共放置的标记点数量等于第二步数出的染色像素数量。若标记点数量超过边框像素数的一半则环绕继续放置。

Key insight
解题者首先需要发现种子颜色扩散填充区域的简单规则，但仅此不够——第二层规则是将内部面积"投影"到边框上成为等距标记点。面积与边框标记的对应关系是核心隐蔽机制：同一个数值既是填充面积又是边框标记的数量，这种跨域映射需要从多个样例中归纳。
</new_puzzle>

<new_puzzle>
在棋盘格背景上，根据彩色锚点对的连线方向选择对称轴类型，再将锚点之间的图案做镜像翻折并变色。

Input structure
- 背景为由两种颜色（azure 和 black）交替排列的棋盘格图案，覆盖整个网格。
- 网格中有若干对同色"锚点"像素（每种非背景颜色恰好出现两次），锚点颜色可以是 red、green、yellow、magenta 等。
- 每对同色锚点要么在同一行、要么在同一列、要么在同一条 45 度对角线上。
- 在某些锚点对之间的棋盘格区域内，存在由 orange 像素构成的不对称小图案（3-5 个像素的连通块），该图案位于连线的一侧。

Rule
- 对每对同色锚点，确定它们的连线方向：水平、垂直或对角线。
- 该连线即为镜像对称轴。
- 将连线一侧的 orange 图案沿该对称轴镜像翻折到另一侧，镜像后的像素用该对锚点的颜色绘制（而非 orange）。
- 原始 orange 图案保持不变。
- 锚点本身保持不变。
- 棋盘格背景中被覆盖的像素直接被新颜色替换。

Key insight
解题者需要完成三层推理：（1）通过颜色配对找到锚点对；（2）判断每对锚点的连线方向从而确定对称轴的类型（水平/垂直/对角）；（3）发现镜像后的颜色不是 orange 而是锚点颜色。棋盘格背景增加了视觉干扰，使得对称轴和镜像位置的判断更具挑战性。
</new_puzzle>

<new_puzzle>
将网格中的"影子"对象还原为完整对象，影子的缺失部分由光源位置和照射方向决定。

Input structure
- 背景为黑色。
- 网格的某一条外边缘（上、下、左或右）上有一个 yellow 像素，代表"光源"。
- 网格中散布若干由不同颜色构成的小型 4-连通对象（3-6 像素），每个对象都是某种完整形状的"影子"——即完整形状被光源照射后，朝向光源的那一侧边缘像素被"照亮"而消失（变为背景色），剩下的像素构成当前可见的影子。
- 每个影子对象旁边（光源对侧方向）紧贴着一个同色的单像素"参考点"，标记完整形状中距光源最远的那个像素位置。

Rule
- 确定光源在网格的哪条边上（由 yellow 像素位置决定）以及光照方向（从边缘指向网格内部）。
- 对每个影子对象，在其朝向光源的一侧补全缺失的像素：具体地，对影子中每个"暴露"像素（即在光源方向上没有同色邻居的像素），在其光源方向上添加一个同色像素。
- 参考点保持不变，它属于完整对象的一部分。
- 光源像素在输出中被移除（变为黑色）。

Key insight
解题者首先要从 yellow 像素推断光源位置和光照方向，然后理解"影子"是被光照剥离了迎光面像素后的残余。补全规则的核心在于识别每个对象的"暴露边缘"——即面向光源且缺少遮挡的那些像素——并向光源方向生长一层。参考点的存在帮助验证完整形状，但不参与补全逻辑本身。
</new_puzzle>

<new_puzzle>
将多条交叉的灰色路径按边缘端点的颜色和宽度配对后染色，交叉处颜色由路径连通性决定。

Input structure
- 背景为黑色。
- 网格的四条边上分布着若干彩色像素作为"端点"，每种颜色恰好在边缘出现两次（构成一对）。
- 网格内部有若干条宽度为 1 像素的路径，由 grey 像素绘制，路径从一个边缘端点延伸到另一个边缘端点。
- 各路径在内部发生交叉，交叉处的像素仍为 grey。
- 每个边缘端点的宽度（沿边缘方向连续的同色像素数）为 1 到 3 个像素不等；同一对端点（同色）的宽度相同。

Rule
- 通过颜色和宽度的双重匹配确定端点配对：同色且同宽的两个边缘端点为一对。
- 对每条 grey 路径，追踪其从一个端点到配对端点的完整路径像素。
- 将该路径上的所有 grey 像素重绘为端点的颜色。
- 交叉处的像素归属于从该像素出发沿路径方向能到达的两个端点中颜色匹配的那条路径。

Key insight
路径本身全是 grey 的，无法直接看出哪条路径连接哪对端点。解题者必须先通过端点宽度匹配建立配对关系（第一层），再通过路径追踪确定每条路径的归属（第二层），最后用端点颜色对路径染色（第三层）。交叉处的颜色归属是最难推断的部分，需要理解路径的连通性。
</new_puzzle>
