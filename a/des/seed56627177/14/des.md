<description>
根据每个封闭区域内部标记像素的颜色，从共享调色板中选取对应颜色来填充该区域的边框。

Input structure:
- 背景为黑色。网格中有若干由灰色像素构成的封闭矩形边框（宽度为1像素），边框之间互不接触。
- 每个灰色矩形边框的内部恰好包含一个或多个彩色单像素标记，这些标记散落在内部的不同位置。
- 网格的某个角落（例如左上角）存在一个小型调色板区域：一列纵向排列的彩色像素，每种颜色恰好出现一次，从上到下依次排列。调色板中的颜色种类与矩形边框的数量相同。

Rule:
- 对每个灰色矩形边框，统计其内部彩色标记像素的数量 N。
- 在调色板列中，从上往下第 N 个颜色即为该边框的目标颜色。
- 将该灰色边框的所有像素替换为目标颜色，清除边框内部的所有标记像素（变为黑色背景），保留调色板区域不变。

Key insight:
内部标记的位置和颜色是干扰项，真正决定边框颜色的是标记的数量；数量作为索引查询角落调色板，将"计数"与"查表"两层推理串联起来。
</description>

<description>
将网格中散落的彩色碎片按形状互补关系配对，拼合成完整的矩形后移动到指定锚点位置。

Input structure:
- 背景为黑色。网格中有若干彩色的不规则形状碎片（每个碎片是4-连通的单色区域）。
- 同时存在若干红色单像素锚点，数量等于碎片数量的一半。
- 每两个碎片恰好能拼合成一个无间隙、无重叠的实心矩形；同一配对中的两个碎片颜色不同。
- 每个可拼合矩形的面积各不相同。

Rule:
- 找到所有能互补拼合成完整矩形的碎片对：将每个碎片放入其最小外接矩形中，若两个碎片的外接矩形尺寸相同，且一个碎片填充的像素恰好是另一个碎片在该矩形中未填充的像素，则它们构成一对。
- 将每对碎片按面积从小到大排序，与红色锚点按从左到右、从上到下的行优先顺序一一对应。
- 以红色锚点为拼合矩形的左上角，绘制完整的拼合矩形：原本属于第一个碎片的像素保留其颜色，原本属于第二个碎片的像素保留其颜色。清除原始碎片位置和红色锚点。

Key insight:
碎片的颜色和位置并不直接指示配对关系；必须先通过形状互补性识别哪两个碎片能拼成矩形，再通过面积排序将配对结果映射到锚点位置——形状匹配与排序映射构成两层独立推理。
</description>
</new_puzzle>

<description>
沿每个箭头形状指示的方向，将箭头自身"展开"为一条彩色轨迹，轨迹长度由箭头尾部的宽度决定。

Input structure:
- 背景为黑色。网格中有若干彩色箭头形状，每个箭头由同一颜色的像素组成。
- 每个箭头由两部分构成：一个矩形"尾部"（宽度 W 像素、高度或长度至少2像素）和一个三角形"头部"（从尾部的一端向某个基本方向逐行收缩至1像素的尖端）。箭头朝向四个基本方向之一（上、下、左、右）。
- 例如，一个朝右的箭头：左侧是一个高 W、宽若干像素的矩形尾部，右侧是一个从高度 W 逐行减少1像素（上下各缩进半像素）直到1像素宽的三角形头部。
- 网格中还散布着灰色的单像素墙壁障碍物。

Rule:
- 对每个箭头，确定其朝向方向 D 和尾部宽度 W。
- 从箭头尖端沿方向 D 发射一条宽度为1像素的射线，长度恰好为 W 个像素。如果射线遇到网格边界或灰色墙壁则在障碍物前停止（实际长度可能小于 W）。
- 射线使用箭头自身的颜色绘制。箭头本身保留不变，灰色墙壁保留不变。

Key insight:
箭头的朝向决定射线方向，但射线的长度并非由箭头总面积或长度决定，而是由其垂直于朝向方向的尾部"截面宽度"编码——需要从箭头形状中分别解读方向信息和数值信息两层含义。
</description>

<description>
将网格中每个彩色环形的缺口朝向作为旋转指令，依次对环内的图案执行旋转变换。

Input structure:
- 背景为黑色。网格中有若干不重叠的彩色环形结构，每个环形由单一颜色的像素组成，形成一个正方形空心框（外边长至少5像素，框宽1像素），但框的某一侧边的正中央缺少恰好1个像素，形成一个缺口。
- 每个环形框的内部（被框包围的区域）包含一个由另一种颜色绘制的小型图案（非对称形状，以便区分旋转结果）。
- 所有环形框的内部图案使用同一种颜色（例如蓝色），但形状各不相同。

Rule:
- 缺口在上侧 → 不旋转（0度）。
- 缺口在右侧 → 将内部图案顺时针旋转90度。
- 缺口在下侧 → 将内部图案旋转180度。
- 缺口在左侧 → 将内部图案逆时针旋转90度（即顺时针270度）。
- 旋转以内部区域的中心为轴，旋转后的图案仍绘制在同一环形框内部。环形框本身（含缺口）保持不变。

Key insight:
环形框的缺口位置不是装饰性特征，而是一个旋转指令编码；解题者需要先发现缺口方位与旋转角度之间的对应关系，再将其应用于每个框内各不相同的图案——指令解码与空间变换构成两层推理。
</description>

<description>
根据连接线的拓扑结构确定每个节点区域的绘制层级，用层级顺序覆盖重叠区域的颜色。

Input structure:
- 背景为黑色。网格中有若干彩色的小型实心矩形"节点"（每个节点颜色不同，尺寸均为2x2）。
- 节点之间由灰色单像素宽的直线段（水平或垂直）连接，形成一棵树结构（无环、全连通）。每条灰色线段连接恰好两个节点，从一个节点的边缘出发沿直线到达另一个节点的边缘。
- 树中有一个明显的根节点：它是唯一一个仅连接一条灰色线段的节点（即度为1的叶节点中位于网格最上方的那个）。

Rule:
- 从根节点开始，沿树结构进行广度优先遍历，确定每个节点的层级（根为第0层，根的邻居为第1层，以此类推）。
- 以每个节点的2x2位置为中心，向外扩展绘制一个实心正方形色块，边长 = 3 + 2 * 层级（第0层边长3，第1层边长5，第2层边长7...），颜色为该节点的颜色。
- 绘制顺序为从最深层到最浅层（即层级最大的节点先画，根节点最后画），因此浅层节点的色块会覆盖深层节点的色块。灰色连接线在输出中被清除（变为黑色），但会被色块覆盖的部分显示色块颜色。

Key insight:
灰色线段构成的树结构并非装饰，它编码了节点的层级关系；层级同时决定了色块大小和绘制优先级——解题者需要先从连接拓扑中推断出层级，再理解"层级越浅、色块越小但绘制越晚（覆盖在上层）"的反直觉渲染规则，形成拓扑解析、尺寸映射、覆盖顺序三层推理。
</description>

<description>
将网格中的彩色像素沿其所在象限指向中心的方向折叠，与对称位置的像素进行颜色混合。

Input structure:
- 网格为正方形且边长为偶数（例如8x8）。背景为黑色。
- 网格可被十字线（中间的行分界和列分界）分为四个大小相等的象限（左上、右上、左下、右下）。
- 每个象限中散布着若干单色像素，颜色来自以下四种之一：红色、蓝色、绿色、黄色。同一象限内所有非背景像素颜色相同，但四个象限的颜色各不相同。

Rule:
- 输出网格的尺寸为输入的一半（即一个象限的大小）。
- 将四个象限叠合到同一个象限大小的画布上：左上象限保持原样；右上象限沿垂直轴左右翻转后叠合；左下象限沿水平轴上下翻转后叠合；右下象限沿两个轴同时翻转（即旋转180度）后叠合。
- 对于叠合后的每个像素位置：若恰好只有一个象限在该位置有非背景像素，则输出该颜色；若有两个或更多象限在该位置有非背景像素，则输出橙色；若所有象限在该位置均为背景，则输出黑色。

Key insight:
四个象限各自的像素图案看似独立，但它们共享一个通过折叠对齐的隐含坐标系；解题者需要先发现四种折叠方式（对应四个象限的镜像关系），再理解重叠处的颜色合并规则——空间折叠与冲突检测构成两层不同性质的推理。
</description>

<description>
识别网格中被"锁"保护的"宝箱"，用与锁匹配的"钥匙"颜色解锁后显示箱内隐藏图案。

Input structure:
- 背景为黑色。网格中有若干灰色实心矩形"宝箱"（内部全灰，尺寸各不相同但均至少3x3）。
- 每个宝箱的某一条外侧边上紧贴着一个2x1或1x2的彩色"锁"（由两个同色像素组成），锁的颜色各不相同。
- 网格中其他位置散布着若干彩色的小型图案"钥匙"，每把钥匙是一个由单一颜色像素组成的4-连通形状（面积2-6像素），颜色与某个锁的颜色相同。每种锁的颜色恰好对应一把钥匙。
- 每把钥匙的形状恰好能放入对应宝箱的内部区域（钥匙的外接矩形不超过宝箱内部尺寸）。

Rule:
- 通过颜色匹配将每把钥匙与对应的锁配对，从而确定每把钥匙属于哪个宝箱。
- 将钥匙的形状"印入"对应宝箱的内部：钥匙图案放置在宝箱内部区域的中心位置（若无法精确居中则偏左偏上），使用钥匙的颜色绘制。
- 宝箱内部未被钥匙占据的像素保持灰色。宝箱外框保持灰色。锁保持原色。清除原始钥匙位置的像素（变为黑色）。

Key insight:
灰色矩形看似普通的实心块，但它们是等待被"解锁"的容器；颜色匹配建立锁-钥对应关系，而钥匙形状决定箱内最终图案——颜色配对与形状转移构成两层推理，且钥匙的空间位置与宝箱位置无关，不能靠邻近性猜测。
</description>
</new_puzzle>
