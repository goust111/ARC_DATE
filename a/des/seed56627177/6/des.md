- `description`：根据框架内部孔洞的形状从色板中选取匹配的填充块，将其嵌入孔洞位置。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格中有若干个由同一颜色（如 grey）绘制的矩形框架（一像素宽的空心矩形），每个框架内部有一个由背景色构成的不规则孔洞形状（即框架内部并非全空，而是部分被框架色填充，剩余背景色区域构成一个连通的孔洞轮廓）。
  - 网格的一侧（如底部）有一排彼此分隔的小型彩色色块（如 red、blue、green、orange），每个色块是一个紧凑的 4-连通形状，放置在各自独立的小边界框内。

- `Rule`：
  - 对每个框架，提取其内部孔洞的形状（背景色连通区域相对于框架内部左上角的相对坐标集合）。
  - 在底部色板中找到与该孔洞形状全等（允许平移，不允许旋转或翻转）的色块。
  - 将匹配色块的颜色填入框架内部对应的孔洞位置，框架本身保持不变。
  - 色板区域在输出中被清除为背景色。

- `Key insight`：解题者需要先"看出"每个框架内部的负空间形状，再将其与色板中的正空间形状进行匹配——这是一个图-底反转的匹配过程，而非直接的颜色或位置对应。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色路径片段按颜色分组，每组内按片段长度从短到长排序，然后依序首尾拼接成一条从指定起点出发的连续折线。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格中散布着若干条直线段（水平或垂直，宽度为 1 像素），每条线段是一个单色的 4-连通对象。多条线段可能共享同一颜色（如有 3 条 red 线段、2 条 blue 线段）。
  - 每种颜色恰好有一个单像素标记点（marker），其颜色与该组线段相同，位于网格边缘（上/下/左/右边缘的某一格），标记点不与任何同色线段相邻。
  - 每个标记点恰好紧贴网格的某一条边，由此可推断该颜色折线的起始方向：贴上边缘则起始向下，贴下边缘则起始向上，贴左边缘则起始向右，贴右边缘则起始向左。

- `Rule`：
  - 对每种颜色，收集该颜色的所有线段，按像素长度从短到长排序。
  - 从该颜色的边缘标记点出发，沿标记点所指示的起始方向绘制第一条（最短的）线段。
  - 后续每条线段从前一条线段的末端开始，方向交替：若前一段是水平的则本段垂直，若前一段是垂直的则本段水平。当需要选择正负方向时（如垂直段可向上或向下），选择使线段不超出网格边界的方向；若两个方向都合法，选择朝向网格中心的方向。
  - 原始散落的线段和标记点被清除，仅保留拼接后的折线。

- `Key insight`：解题者必须完成两层推理——第一层是发现同色线段需要按长度排序（而非按空间位置），第二层是发现排序后的线段交替水平/垂直地从边缘标记点依次拼接。仅从最终输出的折线外观很难直接看出排序规则，必须对比输入中散落线段的长度才能归纳出来。
</new_puzzle>

<new_puzzle>
- `description`：利用彩色种子像素在网格线交叉构成的房间地图中执行洪水填充，但填充会被门洞传递到相邻房间，并在传递时变换为门洞指定的颜色。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格中有由一种墙壁颜色（如 grey）绘制的正交线段网络，将网格分割成若干个封闭的矩形"房间"。
  - 每面墙上可能有一个单像素的"门洞"：该像素不是墙壁色也不是背景色，而是某种其他颜色（如 red、blue、green 等）。门洞连接相邻的两个房间。
  - 恰好有一个房间内部包含一个非背景、非墙壁的单像素种子点（seed），种子颜色与该房间任何门洞颜色都不同。

- `Rule`：
  - 从种子所在房间开始，将整个房间内部（背景像素）填充为种子的颜色。
  - 当填充到达一扇门洞时，填充穿过门洞进入相邻房间，但颜色变为该门洞像素的颜色。相邻房间整体被填充为门洞颜色。
  - 若相邻房间还有其他门洞通往更远的房间，填充继续传递，颜色再次变为新门洞的颜色。
  - 墙壁和门洞像素本身保持不变，只有房间内部的背景像素被填充。
  - 若一个房间有多扇门通往同一个未填充房间，使用最先被填充到达的那扇门的颜色（即离种子房间拓扑距离更近的路径优先；若距离相同，选择门洞行号较小的；行号也相同则选择列号较小的）。

- `Key insight`：解题者需要分两层推理：第一层是识别出墙壁网络将网格分成房间、门洞是墙上的彩色缺口；第二层是发现填充颜色在穿过每扇门时会"变色"为门的颜色，而非保持种子色不变——这使得最终每个房间的颜色取决于从种子到该房间的路径上最后一扇门的颜色。
</new_puzzle>

<new_puzzle>
- `description`：将输入网格中的多个彩色形状视为透明层的俯视叠加图，推断出各层的前后遮挡顺序，然后按该顺序将它们从左到右水平排列输出。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格中可见若干个不同颜色的前景区域，它们彼此部分重叠。每个颜色对应一个完整的填充矩形，但由于层叠遮挡，底层矩形的部分像素被顶层矩形覆盖而不可见。
  - 每个矩形的颜色唯一（不同矩形颜色不同）。
  - 所有矩形尺寸相同（如都是 4x3）。

- `Rule`：
  - 推断每个颜色矩形的完整边界框：可见部分加上被其他颜色遮挡的部分。由可见像素的分布可确定每个矩形的完整位置（因为矩形的至少两条相邻边是完整可见的）。
  - 确定遮挡顺序：若颜色 A 在与颜色 B 重叠区域中可见，则 A 在 B 之上。由所有这样的成对关系推出唯一的从底到顶的全序。
  - 输出网格高度等于矩形高度，宽度等于（矩形数量 × 矩形宽度）。
  - 从左到右按**从底层到顶层**的顺序，依次绘制每个完整矩形（纯色填充），矩形之间无间隔。

- `Key insight`：解题者需要先"透视"遮挡关系，还原每个被部分覆盖的矩形的完整范围，然后根据重叠处的可见颜色推断分层顺序——最终输出是一个将三维深度信息"展开"为水平序列的过程。这与参考题 11（线条交叉排序）的排序推理相关，但此题需要额外还原被遮挡对象的完整形状，且输出形式完全不同。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色对象根据其内部标记像素的数量选择对应的变换模板，然后按模板对自身执行形变。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格分为上下两个区域，由一条水平的分隔线（如 maroon 色的完整行）隔开。
  - **上方区域（模板区）**：包含若干个变换模板，每个模板由两部分组成——左侧是一个用 grey 绘制的"输入形状"，右侧紧邻一个用 grey 绘制的"输出形状"。每对模板之间有背景色间隔。每个模板的输入形状内部恰好包含 N 个 azure 像素（N 从 1 开始依次递增），用于标识该模板的编号。模板的输出形状展示了输入形状经过某种几何变换后的结果（如旋转 90 度、水平翻转、向右平移两格等），但 azure 标记像素不出现在输出形状中。
  - **下方区域（工作区）**：包含若干个彩色前景对象（各自颜色不同，如 red、blue、green），每个对象内部嵌有若干个 azure 像素。

- `Rule`：
  - 数出每个工作区对象内部 azure 像素的数量 N。
  - 在模板区找到编号为 N 的模板（即输入形状内含 N 个 azure 标记的那对模板）。
  - 观察该模板从输入形状到输出形状发生了什么几何变换（旋转、翻转等）。
  - 对工作区中的该对象施加相同的几何变换（保持对象颜色不变，azure 标记像素在变换后保留）。变换以对象边界框中心为锚点原地进行。
  - 清除模板区和分隔线，输出仅包含变换后的工作区。

- `Key insight`：解题者需要完成三层推理：第一层是识别出上方区域是成对的"变换前→变换后"模板、azure 像素数量是模板编号；第二层是从每对模板中归纳出具体的几何变换类型；第三层是将推断出的变换应用到下方具有相同 azure 数量的工作对象上。模板不直接告诉你"旋转90度"，而是通过形状示例让你自己推断变换类型。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到由边框颜色围成的封闭区域，根据区域内"窗户"图案的朝向决定该区域在输出中的摆放位置和旋转方式，最终将所有区域拼合成一个紧凑的矩形输出。

- `Input structure`：
  - 背景为主色（如 black）。
  - 网格中散布着若干个由同一边框颜色（如 grey）围成的小矩形封闭区域，内部填充各不相同的纯色（如 red、blue、green 等）。
  - 每个封闭区域的边框上恰好有一个单像素的"窗户"标记：边框某一侧的正中间一格被替换为另一种特殊颜色（如 yellow）。窗户可以出现在上、下、左、右四侧之一。
  - 所有封闭区域的内部尺寸相同（如都是 3x2）。

- `Rule`：
  - 输出是一个 2x2 的区域拼合网格（若有 4 个区域），不含边框和窗户，仅输出每个区域的内部填充色块。
  - 窗户朝上的区域放在输出的左上角，窗户朝右的放在右上角，窗户朝下的放在右下角，窗户朝左的放在左下角。
  - 每个区域的内部内容需要旋转，使得其窗户方向统一朝上后再放置（即窗户朝右的区域逆时针旋转 90 度，窗户朝下的旋转 180 度，窗户朝左的顺时针旋转 90 度）。
  - 若某个朝向没有对应的区域，该位置填充背景色。

- `Key insight`：解题者需要先识别边框上的"窗户"标记及其朝向，然后发现窗户朝向同时决定了两件事：该区域在输出拼图中的位置（朝向到象限的映射）以及需要施加的旋转角度（统一朝上）。单独看位置规则或旋转规则都不够，必须同时理解两者的耦合关系。
</new_puzzle>

<new_puzzle>
- `description`：在棋盘状网格中，根据每个格子四周邻居的颜色投票结果决定该格子在输出中的颜色，但投票权重由一个隐藏在角落的小型权重矩阵决定。

- `Input structure`：
  - 网格被均匀分割为 N×N 个大小相同的正方形格子（如 5x5 个格子，每个格子为 3x3 像素），格子之间没有间隔。
  - 每个格子内部填充为单一颜色，共使用两种前景色（如 red 和 blue）。
  - 网格的左上角有一个 3x3 的特殊区域（恰好占据一个格子的位置），该区域不是纯色填充，而是包含由第三种颜色（如 yellow）绘制的图案：3x3 内部分像素为 yellow，其余为背景色。yellow 像素的位置编码了方向权重——上、下、左、右、以及四个对角方向中，哪些方向的邻居"有投票权"。

- `Rule`：
  - 将左上角 3x3 格子视为方向掩码：中心像素忽略，周围 8 个位置中标为 yellow 的方向表示"有投票权的邻居方向"。
  - 对网格中每个非角落的格子，统计其在有投票权方向上的邻居格子的颜色。颜色票数更多的一方成为该格子在输出中的颜色。若票数相等，保持原色不变。
  - 左上角的掩码格子自身在输出中按照同样的投票规则处理（将其原色视为其在掩码图案下方的底色）。
  - 超出网格边界的邻居不参与投票。

- `Key insight`：解题者需要首先发现左上角格子的图案并非普通数据，而是一个"方向掩码"，定义了哪些邻居方向参与投票；然后发现每个格子的输出颜色是由这些特定方向邻居的多数投票决定的。掩码的存在使得简单的"看邻居"规则变得不透明——不同的掩码会产生截然不同的输出图案。
</new_puzzle>
