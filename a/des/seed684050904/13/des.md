## 第一步：分析与思考

### 参考题中涉及的基础操作

从20道参考题中，可以提炼出以下基础操作类别：

1. **空间变换**：平移（题4、5、8、18）、旋转/镜像（题3、9）、缩放（题7、10、13）
2. **区域划分与填充**：flood-fill分区（题1）、内外判断（题1、18）、周期性平铺（题2、16）
3. **对象识别与分类**：连通分量检测（题4、12）、包含关系/嵌套检测（题11、12）、边界锚定（题3、5）
4. **属性提取与编码**：面积→位移（题4）、颜色→方向（题5、6）、计数→宽度（题20）
5. **模板匹配与印章**：sprite对齐（题17）、图案恢复（题2）
6. **路径与传播**：沿路径移动（题15）、射线投射（题18）、重力落下（题8）
7. **轮廓操作**：外轮廓提取（题19）、形状规范化（题11、13）
8. **标记/指示器驱动**：标记决定方向（题6、7）、标记决定选择（题1、12、20）

### 非显而易见的串联方式

- **属性编码反转**：一个对象的几何属性（如孔洞数量、凸度、对称轴方向）可以编码为另一个对象的变换参数，而非直接的数值映射。
- **拓扑信息驱动几何操作**：连通性、包围关系、邻接图等拓扑信息可以决定着色、排序或路由方案。
- **负空间作为信息载体**：对象之间的间隙、背景区域的形状、孔洞的排列本身构成有意义的模式。
- **多对象协作**：多个分散的对象共同编码一条信息（如共线性暗示方向、颜色序列暗示排列顺序）。
- **上下文切换**：同一类对象在不同局部环境下遵循不同规则，环境本身需要被识别。
- **自指属性**：对象的某个属性（如形状复杂度、像素数、跨越的行列数）反过来控制自己的变换方式，而不是由外部标记指定。
- **间接寻址**：一个对象的颜色或位置不直接给出答案，而是作为"指针"指向另一个对象或区域，需要两次间接引用才能得到最终答案。
- **对称性破缺检测**：一组看似对称的结构中，某个局部存在微小的不对称，这种破缺本身就是信号。

<new_puzzle>
<description>
根据每个封闭框架上"裂缝"所在的边，从网格角落的色标中查找对应颜色来填充框架内部。

Input structure:
- 背景为 black。
- 网格中散布若干由 grey 像素绘制的空心矩形框（框线宽度为1像素），大小和位置各不相同，互不重叠。
- 每个矩形框在其四条边之一上恰好有一个单像素缺口（该位置本应为 grey 但为 black），使框不完全封闭。缺口可能出现在顶边、底边、左边或右边。
- 网格的四个角落各有一个单像素色标：左上角 = red，右上角 = blue，右下角 = green，左下角 = yellow。这四个色标远离任何矩形框。

Rule:
- 保留所有 grey 框线像素和四个角落色标不变。
- 对每个矩形框，确定其缺口在哪条边上：
  - 顶边缺口 → 取左上角色标颜色 red。
  - 右边缺口 → 取右上角色标颜色 blue。
  - 底边缺口 → 取右下角色标颜色 green。
  - 左边缺口 → 取左下角色标颜色 yellow。
- 将该矩形框内部所有 black 像素填充为对应颜色。缺口位置本身保持 black。

Key insight:
解题者必须注意到两件隐蔽的事情：(1) 每个矩形框恰好有一处边上的微小缺口，需要仔细逐边检查才能发现；(2) 角落色标按"顶→右上、右→右下…"并非简单的上下左右映射，而是以顺时针方向将边与角一一对应。核心推理是缺口方位通过角落色标间接指定填充色。
</description>

<new_puzzle>
<description>
网格中散布着不规则前景对象；每个对象根据自身形状中水平邻接对与垂直邻接对的多寡决定移动轴向，再根据质心位于网格哪一半决定朝向，移动距离等于对象在正交维度上的跨度。

Input structure:
- 背景为 black。
- 网格中有若干互不接触的单色 4-连通前景对象，每个对象颜色各不相同。
- 对象形状不规则，且每个对象内部水平相邻像素对的数量 H 与垂直相邻像素对的数量 V 严格不等。
- 对象之间留有足够空间，不会因移动而互相碰撞。

Rule:
- 对每个前景对象，扫描其所有像素，统计水平方向上相邻同色像素对数 H（即 (r,c) 和 (r,c+1) 都属于该对象的个数）和垂直方向上相邻同色像素对数 V（即 (r,c) 和 (r+1,c) 都属于该对象的个数）。
- 若 H > V，对象沿水平方向移动；若 V > H，对象沿垂直方向移动。
- 移动朝向：水平移动时，若对象质心的列坐标 < 网格宽度/2 则向左，否则向右；垂直移动时，若对象质心的行坐标 < 网格高度/2 则向上，否则向下。
- 移动距离：水平移动时，距离等于对象所占的不同行数（即对象的垂直跨度）；垂直移动时，距离等于对象所占的不同列数（即对象的水平跨度）。
- 原始位置清除为 black；超出网格的像素被裁剪。

Key insight:
对象形状本身编码了运动参数——水平延展的对象水平移动，垂直延展的对象垂直移动——但判据不是粗糙的宽高比而是内部邻接对计数。更反直觉的是，移动距离由正交维度的跨度决定（水平走的对象用行跨度做距离），形成一种"交叉编码"。
</description>
</new_puzzle>

<new_puzzle>
<description>
在一张被墙壁分割成若干房间的平面图中，根据每个房间拥有的"门"（墙壁开口）数量为其填上不同颜色。

Input structure:
- 背景为 black。
- grey 像素构成宽度为1像素的直线墙壁网络，将网格内部区域分割成若干矩形房间。墙壁彼此相连，形成连通的网格状结构。
- 部分墙壁段上存在单像素宽的开口（"门"）：即一段连续 grey 墙壁中有一个像素缺失为 black，使相邻房间通过该开口连通。
- 网格最外圈（边缘）全部为 grey 墙壁，将所有房间封闭在内部。
- 外部（网格边缘之外）不存在房间。

Rule:
- 保留所有 grey 墙壁像素不变。
- 用 4-连通 flood-fill 从每个被墙壁围起来的 black 区域出发，识别每个房间。由于门也是 black 像素，通过门相连的区域属于同一连通分量；因此"房间"不是简单的连通分量，而是定义为由 grey 墙壁四面围成的最小矩形区域。
- 对每个矩形房间，检查其四面墙壁上有几个单像素开口（门）。
- 门数 = 1 → 填 red；门数 = 2 → 填 blue；门数 = 3 → 填 green；门数 = 4 → 填 yellow。
- 门数 = 0（完全封闭）→ 保持 black。

Key insight:
由于门是 black 像素、与背景同色，flood-fill 会将通过门相连的多个房间合并为一个连通分量——这是一个陷阱。解题者必须先还原矩形格局（把每段墙壁的缺口当作墙来找出最小矩形隔间），再逐个数门。核心推理是"门的数量决定颜色"，而非房间面积、位置或连通性。
</description>
</new_puzzle>

<description>
网格中有若干彩色"箭头"对象和一个灰色目标区域；每个箭头沿自身指向方向射出一条射线，射线在目标区域内留下该箭头颜色的痕迹，多条射线交叉处取最后到达的颜色。

Input structure:
- 背景为 black。
- 网格中有一个由 grey 像素填充的矩形区域（"画布"），位于网格中央偏位。
- 画布外部散布着若干彩色箭头对象（每个箭头颜色不同，如 red、blue、green、yellow 等）。
- 每个箭头由5个像素组成：一个像素作为尖端，另外4个像素组成箭尾。箭尾为 2x2 正方形，尖端从箭尾的一条边的中点向外延伸1像素。尖端相对于箭尾的位置决定箭头的指向方向（尖端在箭尾上方 → 指向上方；尖端在箭尾右侧 → 指向右方，以此类推）。
- 每个箭头沿其指向方向的延长线会穿过灰色画布区域。

Rule:
- 保留所有箭头对象不变。
- 对每个箭头，从其尖端出发沿指向方向画一条1像素宽的射线。
- 射线上属于灰色画布范围内的像素被替换为该箭头的颜色。
- 射线到达画布的另一侧边缘后停止（不穿透整个网格）。
- 若多条射线经过画布内同一像素，该像素的颜色取所有经过射线中箭头距画布最远者的颜色（即来自更远处的射线优先覆盖近处的）。
- 画布内未被任何射线经过的像素保持 grey。

Key insight:
解题者需要通过5像素箭头的形状判断出指向方向，然后追踪射线在画布上的轨迹。关键难点在于冲突解决规则——不是简单的"后覆盖先"或"先覆盖后"，而是距画布更远的箭头优先，这模拟了"远处射来的光更强"的非直觉逻辑。
</description>
</new_puzzle>

<description>
网格中散布的对象各有一个"影子方向"，由隐藏在网格边缘的同行或同列光源标记决定；对象沿背光方向投射与自身等宽（或等高）的阴影条纹直到碰壁。

Input structure:
- 背景为 black。
- 网格中有若干互不重叠的单色 4-连通前景对象（每个颜色不同）。
- 网格的四条边缘上分布着若干 maroon 单像素点（"光源"）。每个前景对象恰好与一个 maroon 光源像素位于严格同一行或严格同一列上（不会同时有同行和同列的光源）。
- 前景对象与其对应光源之间的直线路径上没有其他前景对象。

Rule:
- 保留所有前景对象和 maroon 光源不变。
- 对每个前景对象，找到与其严格同行或同列的唯一 maroon 光源。
- 光照方向 = 从光源指向对象的方向（上/下/左/右之一）。
- 阴影方向 = 光照方向的反方向（即背光方向）。
- 对该对象的每一个像素，从该像素出发沿阴影方向逐格延伸，将沿途 black 像素涂为 grey，直到碰到网格边缘或碰到任何非 black 像素为止。
- 阴影颜色统一为 grey，与对象自身颜色无关。

Key insight:
解题者必须先注意到边缘上微小的 maroon 点，然后建立每个对象与其光源的配对关系（同行或同列的唯一配对）。光源的位置决定了阴影朝哪个方向投射。所有对象使用同一种 grey 阴影色，因此颜色不能帮助区分来源，只有方向和位置能揭示规则。
</description>

<new_puzzle>
<description>
网格中有若干对同色标记像素；每对标记定义一条"折痕"，将折痕一侧的 grey 图案镜像翻折到另一侧并叠合。

Input structure:
- 背景为 black。
- 网格中散布着 grey 像素构成的前景图案（可以是任意形状的 4-连通或多个分量）。
- 另有若干对彩色标记像素（每种非 black、非 grey 颜色恰好出现两个像素，构成一对）。例如一对 red 像素、一对 blue 像素等。
- 每对标记要么在严格同一行上（水平对），要么在严格同一列上（垂直对），不会是对角线。
- 不同对的标记颜色各不相同。

Rule:
- 对每一对同色标记，计算折叠轴位置：
  - 水平对（同行）：折叠轴是通过两个标记列坐标中点的垂直线。
  - 垂直对（同列）：折叠轴是通过两个标记行坐标中点的水平线。
- 从所有折叠对中，按标记对之间距离从大到小依次执行折叠。
- 每次折叠：取折叠轴远离网格中心一侧的所有 grey 像素，将其沿轴做镜像映射到另一侧。若镜像目标位置已有 grey 像素则保持 grey；若为 black 则填入 grey。原来远端的 grey 像素被清除为 black。
- 所有折叠完成后，移除全部彩色标记像素（替换为 black）。

Key insight:
解题者需要：(1) 发现同色像素恰好成对，理解它们标记折叠轴；(2) 领悟折叠方向总是从距网格中心较远一侧折向较近一侧；(3) 注意多次折叠按距离排序执行，顺序影响最终结果。核心推理是颜色配对 → 折叠轴 → 方向 → 叠合的多步间接逻辑链。
</description>

<new_puzzle>
<description>
网格中每个前景对象旁边紧贴着若干单像素"选票"；将每个对象移动到得票最多的方向的网格边缘。

Input structure:
- 背景为 black。
- 网格中有若干互不接触的、形状各异的单色 4-连通前景对象（每个颜色不同）。
- 每个前景对象的外部（8-邻接但不属于该对象的像素中）有若干 orange 单像素点，称为"选票"。
- 每张选票与其服务的对象 8-邻接（即紧贴对象边缘），且每张选票仅 8-邻接一个前景对象（不会夹在两个对象之间）。
- 选票分布在对象的上方、下方、左方或右方（相对于对象边界框）。

Rule:
- 对每个前景对象，将其周围的 orange 选票按方位分类：位于对象边界框顶边之上的算"上票"，底边之下的算"下票"，左边之左的算"左票"，右边之右的算"右票"。若一张选票在角落位置（同时在两个方位），归入行方向（即上或下优先于左或右）。
- 统计四个方向的票数，得票最多的方向即为该对象的移动方向。若有平票，按上、右、下、左的优先级打破。
- 将对象整体平移到该方向的网格边缘（即对象边界框的对应边与网格边缘对齐），保持对象在正交方向上的位置不变。
- 清除所有 orange 选票像素。
- 原始对象位置清除为 black。

Key insight:
解题者起初可能以为 orange 点是随机噪声或装饰，实际上它们是"投票"。关键是发现 orange 点的方位分布直接决定对象的移动方向，且需要按方位计数来"多数表决"。投票机制作为对象行为的驱动方式十分隐蔽。
</description>
</new_puzzle>
