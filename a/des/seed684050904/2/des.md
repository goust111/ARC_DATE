## 第一步：分析与思考

### 参考题中的基础操作归纳

从 20 道参考题中，我提取出以下基础操作类别：

1. **空间填充与传播**：洪水填充（puzzle 14）、扫描线填充（puzzle 1）、射线延伸（puzzle 17）、路径延伸（puzzle 9）
2. **对象匹配与对应**：颜色键匹配（puzzle 10 中心色→矩形）、形状等价判断（puzzle 6）、路径追踪目标寻找（puzzle 5）
3. **结构解码与图例读取**：图例作为过滤器（puzzle 15）、图例作为计数画布（puzzle 12）、微缩图例解码（puzzle 19）
4. **几何变换**：镜像（puzzle 20）、对角线方向判断（puzzle 17）、旋转门（puzzle 16）
5. **拓扑分析**：连通性分类（puzzle 2 的 4-连通 vs 8-连通）、蛇形路径线性化（puzzle 18）、最短路径（puzzle 13）
6. **位置关系编码**：相对方向决定行为（puzzle 7 红→青的方向选择侧面）、栅格槽位索引（puzzle 8）、带状循环调色（puzzle 11）

### 非显而易见的串联方式思考

- **拓扑属性作为隐含分类标签**：一个对象的"孔洞数"（genus）可以作为决定其颜色或变换方式的隐含键。这种信息在视觉上是可感知的，但需要解题者主动去"数"——结合了 puzzle 2 的拓扑分析和 puzzle 12 的计数思路，但键本身从拓扑特征而非显式图例中获取。

- **负空间作为信息载体**：类似 puzzle 14 中填充封闭区域的思路，但进一步地，两个对象之间夹出的背景空隙本身可以构成有意义的形状或编码信息——对象只是"模具"，信息在空隙中。

- **背景的隐含结构作为参数来源**：puzzle 8 中栅格框的槽位索引启发了一种思路——如果背景本身不是均匀的而是有结构的（如条纹、渐变、棋盘），那么前景对象在背景中的"位置"可以从背景结构中读取隐含参数（如条纹宽度决定生长尺寸）。

- **边界接触模式作为布尔编码**：对象与网格四边界的接触情况构成一个 4-bit 布尔向量，可以编码 16 种状态。这与 puzzle 7 中方向决定行为的思路类似，但从二元方向扩展到多维布尔组合。

- **障碍物作为条件分支触发器**：puzzle 13 中障碍物（墙壁）影响路径选择，可以扩展为：障碍物不仅阻挡路径，还改变操作的类型——同一种变换在无障碍时走方案 A，有障碍时切换为方案 B。

- **对象内部颜色统计驱动全局变换**：结合 puzzle 15 的颜色集过滤和 puzzle 12 的计数，可以让对象内部的颜色分布（多数色、少数色、平局）驱动对象级别的统一变换，引入空间加权打破平局。

- **自相似/递归结构的参数提取**：puzzle 19 中微缩图例编码完整格局的思路可以推广——一个小对象的几何特征（如宽度、像素数）直接作为另一个操作的数值参数。

- **双壁夹道定义通道**：不同于单一壁色定义的边界，两种不同颜色的壁在空间中的"缝隙"定义了隐含的通道结构，类似于地理中河谷由两侧山脊定义。

<description>
根据每个封闭轮廓内部被分隔出的独立空腔数量，对各空腔填充不同颜色。

Input structure:
- 背景为 black。
- 网格中有若干个由 blue 像素绘制的封闭轮廓。每个轮廓是一圈 4-连通的 blue 像素，形成闭合环状。
- 各轮廓互不相交，且顶层轮廓之间不存在包含关系。
- 部分轮廓内部是一整块连通的 black 区域（单个空腔）；部分轮廓内部被额外的 blue 像素墙分隔成多个不连通的 black 区域（多个空腔）。
- 内部空腔是指被 blue 像素完全围住、不与网格外部 black 区域 4-连通的 black 连通分量。
- 不同轮廓内部的空腔数量各不相同，范围在 1 到 4 之间。

Rule:
- 对每个顶层封闭轮廓，找出其内部所有独立空腔（即被 blue 像素包围的、不与外部 black 连通的 4-连通 black 区域）。
- 统计空腔数量 N。
- 按以下映射填充所有空腔中的 black 像素：N=1 → red；N=2 → green；N=3 → yellow；N=4 → magenta。
- 同一轮廓内的所有空腔使用相同颜色。
- blue 轮廓像素保持不变。网格外部的 black 背景不变。

Key insight:
- 外部背景和内部空腔在视觉上都是 black，解题者必须通过连通性判断哪些 black 区域是"内部"的。关键在于对同一轮廓内部的所有空腔进行计数——空腔的数量（而非大小、形状或位置）是决定填充颜色的唯一因素。

将散落的彩色碎片旋转后嵌入同色边框内的空缺区域，实现负空间拼图。

Input structure:
- 背景为 black。
- 网格中有若干个矩形边框，每个边框由一种独特颜色的像素绘制（如 red 边框、green 边框、orange 边框），边框线宽为 1 像素，边框为完整的矩形环。
- 每个边框内部大部分为 black（空缺），但存在一块 grey 区域占据了部分内部空间。边框内部的空缺区域（black 像素）形成一个特定形状。
- 在所有边框外部的网格空间中，有若干小型彩色碎片对象。每个碎片由若干连续的同色像素组成，碎片的颜色与某个边框颜色完全相同。
- 每种边框颜色恰好对应一个外部碎片。
- 碎片的形状与对应边框内部的空缺区域形状在四种旋转（0°、90°、180°、270°）之一下完全吻合，且只有一种旋转角度能精确匹配。

Rule:
- 将每个碎片按颜色匹配到同色边框。
- 找到碎片旋转至能恰好填满边框内部空缺的唯一旋转角度。
- 在输出中，将边框内部空缺区域填充为该边框的颜色（等效于将旋转后的碎片放入空缺）。
- 边框线保持不变，grey 区域保持不变。
- 外部的碎片对象从网格中移除（变为 black）。

Key insight:
- 碎片在网格中呈现的朝向不一定是正确的嵌入朝向——解题者需要在脑中旋转碎片与空缺形状进行匹配。空缺的形状由 grey 填充物和边框共同"雕刻"出来，是一个负空间识别问题。颜色匹配是显而易见的第一步，但旋转对齐是真正的推理挑战。
</description>

<description>
沿箭头指向将同行或同列的彩色像素序列紧凑推入相邻矩形容器内。

Input structure:
- 背景为 black。
- 网格中有若干个 grey 填充的实心矩形，称为"容器"。
- 每个容器的某一条边（上、下、左或右）外侧紧邻一个 red 像素构成的箭头标记。箭头标记由 5 个 red 像素组成：3 个像素排成一行或一列构成箭头杆，杆的一端两侧各延伸 1 个像素构成箭头尖。箭头尖指向容器。例如，一个向右指的箭头为：第一列一个 red 像素，第二列上中下三个 red 像素，第三列一个 red 像素（中间行），整体呈 ">" 形。
- 在箭头杆的反方向延伸线上（与箭头杆中间行或中间列共线），散布着若干非 black、非 grey、非 red 的彩色像素。这些彩色像素不相邻——它们之间由 black 像素分隔。

Rule:
- 对每个箭头，沿箭头杆的反方向延伸，收集共线上所有彩色像素，按从近到远的顺序排列（离箭头近的排在前）。
- 将这些像素按顺序推入容器：沿箭头方向，第一个像素放在容器内部紧邻箭头所指边的第一个位置（在箭头杆共线的行或列上），第二个放在下一格（沿箭头方向更深一格），依次排列。
- 推入的彩色像素覆盖容器原有的 grey 像素。
- 输出中，箭头标记和外部彩色像素被清除为 black。
- 容器内未被覆盖的 grey 像素保持 grey。

Key insight:
- 箭头的朝向同时编码了两个信息：收集外部像素的方向（反方向）和推入容器的方向（正方向）。外部像素之间的间距是无关信息——它们被紧凑地压入容器中，只保留颜色顺序。解题者需要理解"收集-压缩-推入"这个三步管道操作。
</description>
</new_puzzle>

<description>
根据前景对象与网格四条边界的接触情况，在对象未接触的方向上绘制补全边框线。

Input structure:
- 背景为 black。
- 网格中散布着若干个不同颜色的 4-连通前景对象，每个对象使用唯一颜色（如 red、green、blue、yellow 等）。
- 每个对象形状不规则，大小不一。
- 部分对象的某些像素位于网格边界行或列上（第 0 行、最后一行、第 0 列、最后一列），即该对象"接触"了对应的边界。一个对象可能接触 0 到 4 条边界。

Rule:
- 对每个前景对象，检测它接触了哪些网格边界（上、下、左、右）。
- 对于该对象**未接触**的每一个方向，在其 bounding box 对应一侧外扩一行或一列的位置，绘制一条 azure 边框线：
  - 未接触上边界 → 在 bounding box 顶部上方一行，从 bounding box 最左列到最右列画一条 azure 水平线。
  - 未接触下边界 → 在 bounding box 底部下方一行画同样的水平线。
  - 未接触左边界 → 在 bounding box 左侧左方一列，从 bounding box 最顶行到最底行画一条 azure 垂直线。
  - 未接触右边界 → 在右侧右方一列画同样的垂直线。
- 若对象接触了某条边界，则该方向不画边框线。
- 边框线若超出网格范围则不绘制越界部分。
- 对象本身像素颜色不变。不同对象的边框线若重叠，重叠像素为 azure。

Key insight:
- 边框线出现在对象**缺失**边界接触的方向，而非接触的方向。这是一个互补逻辑：接触越多边界的对象反而边框线越少。解题者容易先假设边框标记的是"接触方向"，需要通过对比多个样例才能发现规则恰好相反。触边判断仅看该对象是否有像素恰好在边界行/列上，与对象到边界的距离无关。
</description>

<description>
为每对同色标记像素绘制 L 形连接路径，路径的弯折方向由灰色障碍物决定。

Input structure:
- 背景为 black。
- 网格中有若干种颜色的标记像素（如 red、blue、green、yellow 等），每种颜色恰好出现两个像素，形成一对。
- 网格中还有若干 grey 像素组成的障碍物区域（4-连通的不规则块状）。
- 同色的两个标记像素不在同一行且不在同一列（保证需要拐弯连接）。

Rule:
- 对每一对同色标记像素 A 和 B（A 为行号较小的；若行号相同则列号较小的为 A）：
- 默认路径为"先水平后垂直"：从 A 出发水平移动到与 B 同列的位置，再垂直移动到 B。这条路径形成一个 L 形，拐点在 (A的行, B的列)。
- 检查默认路径上的所有像素（不含 A 和 B 本身）是否与任何 grey 障碍物像素重叠。
- 若不重叠，则使用默认路径：将路径上所有 black 像素着色为该对的颜色。
- 若重叠，则切换为"先垂直后水平"：从 A 垂直移动到与 B 同行，再水平移动到 B，拐点在 (B的行, A的列)。将该备选路径上所有 black 像素着色为该对的颜色。
- 题目保证对每一对标记，两种 L 形路径中至少有一种不被障碍物阻挡。
- 标记像素 A 和 B 本身保留原色。grey 障碍物保持不变。

Key insight:
- 每对标记之间有且仅有两种 L 形路径选择。障碍物是路径方案的"开关"：无障碍时走默认方案，有障碍时切换为备选方案。解题者需要注意到部分路径走了"非直觉"的弯折方向，进而发现 grey 块在路径中的阻挡作用触发了弯折方向的翻转。
</description>

<description>
将单像素种子扩展为实心正方形，正方形的边长由种子所在的背景条纹宽度决定。

Input structure:
- 网格的背景由交替的垂直条纹组成：两种颜色（如 blue 和 green）交替排列，每条条纹的宽度不一，可能是 1、2、3 或 4 像素宽。条纹从网格最左列排到最右列，完整覆盖整个网格。
- 在某些条纹上有单个 red 像素（种子），每个种子占据一个像素位置，位于某条条纹的范围内。
- 种子之间间距足够大，保证生长后的正方形互不重叠（或题目允许重叠区域仍为 red）。

Rule:
- 对每个 red 种子像素，确定它所在的垂直条纹。条纹由同色连续列构成：找出包含该种子列的、颜色相同的最大连续列范围，其宽度为 W。
- 以该种子像素为中心，生成一个 W×W 的实心 red 正方形。中心定义：若 W 为奇数，种子在正方形正中心；若 W 为偶数，种子在中心偏左上的位置（即正方形左上角为 (种子行 - floor((W-1)/2), 种子列 - floor((W-1)/2))）。
- 正方形的 red 像素覆盖原有的背景条纹颜色。
- 若正方形超出网格边界则截断，只绘制网格内的部分。
- 条纹中未被正方形覆盖的部分保持原有条纹颜色。

Key insight:
- 种子像素本身不携带任何尺寸信息——它的生长大小完全取决于它恰好落在哪条条纹上，而条纹的宽度就是正方形的边长。解题者需要首先识别出背景并非单一颜色而是有结构的交替条纹，然后发现不同种子生长出不同大小正方形的原因在于它们所在条纹宽度不同。背景条纹是隐含的"刻度尺"。
</description>

<description>
对网格中的多色对象进行"颜色多数投票"统一着色，平票时由空间质心距离打破僵局。

Input structure:
- 背景为 black。
- 网格中有若干个相互分离的多色 4-连通对象（每个对象内部由 2 到 4 种不同非 black 颜色的像素混合组成）。
- 对象之间无接触（任意两个对象之间至少隔一个 black 像素）。
- 每个对象的形状各异，像素数在 5 到 25 之间。

Rule:
- 对每个对象，统计其内部各颜色的像素数量。
- 若某颜色的像素数严格多于其他颜色，则将该对象的所有像素统一着色为该颜色（多数色获胜）。
- 若出现两种或多种颜色的像素数并列最多（平票），则对每种并列颜色计算：该颜色所有像素到该对象 bounding box 几何中心点（中心点坐标 = (最小行+最大行)/2, (最小列+最大列)/2，可为非整数）的曼哈顿距离之和。选择距离之和最小的颜色（即该颜色的像素群更靠近对象中心）。
- 输出中，每个对象变为纯色，保持原形状。背景保持 black。

Key insight:
- 对大部分对象，简单计数即可确定结果，使得"多数投票"看似已经是完整规则。但少数对象故意设计为平票，迫使解题者发现隐含的打破平局机制：颜色的空间分布（哪种颜色更集中在对象中心附近）才是决胜因素。解题者需要同时关注"多少"和"在哪"两个维度。
</description>

<description>
根据小型"钥匙"对象的缺口方向，选择大型"锁"对象上对应方向的开口进行颜色标记。

Input structure:
- 背景为 black。
- 网格中有若干对"钥匙-锁"组合。
- 每把"锁"是一个 5×5 的 grey 像素方块，其四条边的正中央各有一个可能为 black 的像素（即四个方向上各有一个潜在开口）。每把锁恰好有 1 到 3 个开口（对应方向的边中央像素为 black 而非 grey）。
- 每把"钥匙"是一个 3×3 的彩色像素方块（颜色各不相同，如 red、blue、green 等），其四条边的正中央恰好有一个像素为 black（即钥匙有唯一一个缺口，指示一个方向）。
- 每把钥匙与最近的锁配对（曼哈顿距离最近，且保证配对唯一无歧义）。

Rule:
- 将每把钥匙与最近的锁配对。
- 读取钥匙的缺口方向（上、下、左、右）。
- 在配对的锁上，找到与钥匙缺口方向相同的开口位置。
- 若该方向上锁确实有开口（black 像素），则将该开口像素着色为钥匙的颜色。
- 若该方向上锁没有开口（已经是 grey），则不做任何改变。
- 锁的其他开口保持 black。钥匙对象从网格中移除（变为 black）。

Key insight:
- 钥匙的缺口方向是一个方向指令，指定了要操作锁上的哪个开口。解题者需要先分辨出 3×3 和 5×5 两种不同尺寸的方块分别扮演钥匙和锁的角色，然后发现钥匙上唯一的缺口位置编码了方向信息，最后将该方向信息应用到锁的对应位置。
</description>
