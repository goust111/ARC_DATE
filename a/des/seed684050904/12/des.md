## 第一步：基础操作分析与非显而易见的串联思考

### 参考题中的基础操作归纳

从20道参考题中提炼出以下基础操作类别：

1. **空间重排/排序**：按面积、位置、类型排序后重新放置（题1, 11）
2. **形状匹配与填充**：用外部sprite的形状匹配内部孔洞并上色（题2, 20）
3. **射线/路径投射**：从标记点沿方向发射射线，与之相交的对象受影响（题3, 4）
4. **修复/补全网络**：根据标记点修复断裂的线段网络（题5）
5. **锚点对齐/滑动**：根据边界锚点的位置滑动sprite对齐（题6）
6. **镜像与轨迹追踪**：通过镜像关系和4-连通轨迹确定移动终点（题7）
7. **面板合并/选择**：从多个面板中按位置规则选取子集合并（题8）
8. **可达性与距离排序**：洪水填充判断可达性，再按距离排序（题9）
9. **维度压缩与掩码生成**：将L形结构压缩为行并生成掩码行（题10）
10. **内部结构分类**：根据内部是否空心来分类（题11）
11. **间接颜色传递/查找**：颜色作为查找键进行间接赋值（题12）
12. **嵌套计数直方图**：将方块计数渲染为嵌套的视觉直方图（题13）
13. **边带迁移**：将边缘图案带移到对边（题14）
14. **行内颜色反转**：将每行的主色与其余部分互换（题15）
15. **区域重涂与标记控制**：T形标记控制区域重涂方向（题17）
16. **外角标记**：对完整正方形对象标记外角（题18）
17. **锚点复制分发**：将sprite按锚点颜色复制到所有同色标记位置（题19）

### 非显而易见的串联方式思考

- **计数结果作为空间索引**：一个对象的某种属性（如孔洞数、像素数）不仅用于匹配，还可以编码为坐标偏移或选择条件。
- **拓扑属性作为隐式排序键**：对象的连通分量数、周长/面积比、凸性等拓扑特征可以定义一个不易察觉的排序。
- **颜色频率编码优先级**：某颜色在全局出现的频次决定了其操作优先级或覆盖关系。
- **对称性缺口作为指令**：一个几乎对称的对象中，打破对称的那个像素或区域本身编码了变换方向或类型。
- **邻接颜色序列作为密码**：某像素周围的颜色排列顺序可以编码一条指令（移动方向、旋转角度等）。
- **对象之间的相对几何关系（而非绝对位置）决定输出**：两个对象之间的距离差、角度关系、包含关系等。
- **空白区域的形状本身携带信息**：背景中未被占据的连通区域的形状可以作为模板或指令。

<new_puzzle>
- `description`：根据每个封闭区域内被"污染"像素的数量，用对应数量的彩色层从外向内逐层收缩填充该区域。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 grey 像素围成的封闭矩形区域（grey 形成一像素宽的边框，区域内部为 black）。
  - 每个封闭区域内部散布着若干 red 单像素点（"污染"标记）。
  - 区域大小各异（最小 3×3 内部，最大约 10×10 内部），每个区域内的 red 像素数量不同（范围 1-4）。

- `Rule`：
  - 统计每个 grey 封闭矩形区域内部的 red 像素数量 N。
  - 移除所有 red 像素（变回 black）。
  - 从该区域的内部边界开始，向内逐层收缩填充：第 1 层（紧贴 grey 边框的一圈内部像素）填充为 blue，第 2 层填充为 green，第 3 层填充为 yellow，第 4 层填充为 magenta。只填充 N 层，内部剩余像素保持 black。
  - 颜色顺序固定为 blue → green → yellow → magenta，每层是上一层向内收缩一个像素的矩形环。
  - grey 边框本身保持不变。

- `Key insight`：散落的 red 像素并不决定填充位置，它们的数量控制了收缩填充的层数；解题者需要发现"计数 → 层数"的映射关系，而非关注 red 像素的具体坐标。
</new_puzzle>

<new_puzzle>
- `description`：根据每个 sprite 的凸包缺口方向，将该 sprite 沿缺口方向平移直到抵达网格边缘。

- `Input structure`：
  - 背景为 azure。
  - 网格中散布着若干单色 4-连通 sprite，每个 sprite 使用不同的非背景色（如 red、green、blue、yellow 等）。
  - 每个 sprite 的形状是一个"缺角矩形"——即一个完整矩形被移除了恰好一个角上的一个像素。具体来说，sprite 的 bounding box 是 W×H 的矩形，其中恰好有一个角像素缺失（为背景色），其余所有 bounding box 内的像素均为该 sprite 的颜色。
  - 缺失的角可以是左上、右上、左下、右下中的任意一个，每个 sprite 各不相同。

- `Rule`：
  - 对每个 sprite，找出其 bounding box 中缺失的那个角像素的位置（左上、右上、左下、右下）。
  - 缺失角决定移动方向：左上角缺失 → 向左上方向（即同时向左和向上）平移；右上角缺失 → 向右上平移；左下角缺失 → 向左下平移；右下角缺失 → 向右下平移。
  - 平移距离：沿对角线方向逐步移动，每步行列各偏移 1，直到 sprite 的 bounding box 的任意一边触及网格边缘为止。
  - 原位置的像素变回背景色 azure。
  - 多个 sprite 之间不会发生碰撞（题目保证）。

- `Key insight`：缺失的角看起来像是随意的形状瑕疵，实际上它是一个方向指令——解题者需要发现"缺角位置 = 对角线移动方向"的编码关系，而非将其视为噪音或损坏。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散布的彩色线段按颜色配对，然后沿配对线段的中垂线方向在两者中点处绘制一个新标记。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干水平或垂直的短线段（长度 2-5 像素），每种颜色恰好出现两条线段（即线段按颜色配对）。
  - 可用颜色包括 red、blue、green、yellow、orange 等，每种颜色最多两条。
  - 每条线段是严格水平或严格垂直的连续同色像素。
  - 同色的两条线段总是平行的（都水平或都垂直）。

- `Rule`：
  - 对每对同色线段，计算它们的中心点（每条线段中心为其像素坐标的算术平均，取整）。
  - 在两条线段中心点连线的中点位置（取整），放置一个 grey 像素。
  - 如果同色的两条线段都是水平的，则在该 grey 像素处绘制一条垂直的 grey 短线段，长度等于两条原始线段的间距（行数差）除以 2（向下取整），以 grey 像素为中心向上下各延伸该长度。
  - 如果同色的两条线段都是垂直的，则在该 grey 像素处绘制一条水平的 grey 短线段，长度等于两条原始线段的间距（列数差）除以 2（向下取整），以 grey 像素为中心向左右各延伸该长度。
  - 原始彩色线段保持不变。

- `Key insight`：解题者需要首先发现颜色配对关系，然后理解输出标记的位置和朝向都由配对线段的空间关系决定——标记出现在两者的几何中点，朝向与原线段垂直，长度与间距成比例。
</new_puzzle>

<new_puzzle>
- `description`：每个封闭区域根据其内部唯一标记色的"稀有度排名"来决定该区域的填充色。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 maroon 像素组成的一像素宽的封闭矩形边框，形成多个互不重叠的矩形区域。
  - 每个矩形区域内部恰好有一个单像素标记，颜色各异（取自 red、blue、green、yellow、orange 等）。
  - 同一种标记颜色可能出现在多个不同区域中（即多个区域共享同一标记颜色）。
  - 网格上另有一个独立的"调色板行"：位于网格最底部一行，从左到右排列着若干不同颜色的单像素，相邻像素之间用 black 间隔。调色板行中的颜色数量等于标记颜色的种类数。

- `Rule`：
  - 统计每种标记颜色在所有区域中出现的总次数。
  - 按出现次数从少到多排序（出现次数最少的排名第 1，即最稀有）。若次数相同，按颜色在网格中首次出现的行号从小到大排序。
  - 调色板行中的颜色从左到右对应排名第 1、第 2、第 3 ……的填充色。
  - 对每个区域：找到其标记颜色的稀有度排名 k，然后用调色板行中第 k 个颜色填充该区域的全部内部像素（覆盖原标记像素）。
  - maroon 边框保持不变。调色板行保持不变。

- `Key insight`：标记颜色本身不直接决定填充色——解题者需要发现标记颜色的全局频率排名才是真正的索引键，再通过调色板行的位置间接获得填充色。这是一个两层间接映射：标记色 → 频率排名 → 调色板位置 → 填充色。
</new_puzzle>

<new_puzzle>
- `description`：识别每个 sprite 内部的"指针"像素方向，沿该方向查找最近的目标 sprite，然后将指针 sprite 的颜色覆写到目标 sprite 上。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干 3×3 的单色方块 sprite，每个 sprite 使用不同的非背景色。
  - 每个 3×3 sprite 中，恰好有一个边缘中点像素（上中、下中、左中、右中四选一）被替换为 grey，形成一个"指针"缺口。具体地说：一个 3×3 方块本应有 9 个同色像素，但其中一个位于某条边中点的像素变成了 grey。
  - 各 sprite 之间在网格上互不接触，至少间隔一个像素。

- `Rule`：
  - 对每个 sprite，找到其 grey 像素的位置。grey 像素位于 3×3 方块的上边中点表示方向"上"，下边中点表示"下"，左边中点表示"左"，右边中点表示"右"。
  - 从该 sprite 的中心像素出发，沿 grey 指针所指的反方向（即从 grey 指针穿过中心后继续延伸的方向——例如 grey 在上边中点，则方向为"下"）发射一条射线。
  - 射线碰到的第一个非 black、非 grey 像素所属的 3×3 sprite 即为"目标 sprite"。
  - 将目标 sprite 的所有 8 个非 grey 像素重新着色为指针 sprite 的颜色（目标 sprite 的 grey 指针像素保持 grey 不变）。
  - 指针 sprite 本身保持不变。
  - 如果射线在到达网格边界前未碰到任何 sprite，则该指针 sprite 无效，不做任何操作。

- `Key insight`：grey 像素看似是 sprite 的缺损，实际上它编码了射线发射方向——方向是从 grey 缺口穿过中心的延长线方向。解题者需要同时理解两件事：(1) 缺口位置决定方向，(2) 方向是 grey 缺口的对侧方向，而非缺口本身所在的方向。
</new_puzzle>

<new_puzzle>
- `description`：根据每对同色边界锚点之间围成的矩形区域面积来决定该矩形的填充图案密度。

- `Input structure`：
  - 背景为 azure。
  - 网格的四条边上分布着若干彩色单像素锚点（非背景色、非 grey），每种颜色恰好出现两个锚点，且这两个锚点一定分别位于不同的边上（如一个在顶边、一个在左边）。
  - 可用锚点颜色包括 red、blue、green、yellow、orange 等。
  - 网格内部初始全为 azure 背景。

- `Rule`：
  - 对每对同色锚点，以两个锚点为对角顶点确定一个轴对齐矩形区域。
  - 计算该矩形区域的内部面积（不含锚点所在的边界行/列，即宽和高各减 1 后相乘）。
  - 填充规则根据面积大小分级：
    - 面积 ≤ 9：用该锚点颜色完全填满矩形内部（实心填充）。
    - 面积 10-25：用该锚点颜色绘制矩形内部的棋盘格图案（从矩形内部左上角开始，奇数位置填色、偶数位置保持背景，行列位置之和为偶数时填色）。
    - 面积 > 25：仅用该锚点颜色绘制矩形内部的边框（一像素宽的矩形环），内部保持背景色。
  - 锚点本身保持不变。
  - 当多个矩形区域重叠时，面积较小的矩形的填充覆盖在面积较大的之上。

- `Key insight`：解题者需要发现同色锚点配对定义矩形，更关键的是面积阈值决定填充样式——面积越小越密、越大越稀疏。这是一个从全局几何属性到局部图案密度的非直觉映射。
</new_puzzle>

<new_puzzle>
- `description`：将散布的单像素标记视为"投票"，每个标记为距它最近的彩色对象投票，得票最多的对象保留，其余对象被擦除。

- `Input structure`：
  - 背景为 black。
  - 网格中有 3-5 个形状各异的单色 4-连通 sprite（每个 sprite 使用不同颜色，如 red、blue、green、yellow 等），大小约 4-8 像素。
  - 网格中另有若干 grey 单像素点散布在 sprite 之外的背景区域中，数量约 8-15 个。

- `Rule`：
  - 对每个 grey 像素，计算它到每个 sprite 的曼哈顿距离（定义为该 grey 像素到该 sprite 所有像素中曼哈顿距离最小值）。
  - 将该 grey 像素"投票"给距离最近的 sprite。若两个 sprite 距离并列最近，投票给行号更小的 sprite（即 sprite 中行号最小的像素的行号更小者优先）。
  - 统计每个 sprite 获得的总投票数。
  - 保留得票最多的 sprite 不变。若得票并列，保留所有并列者。
  - 将其余 sprite 的所有像素擦除为背景色 black。
  - 所有 grey 投票像素也擦除为 black。

- `Key insight`：grey 像素看似是无关的噪声，实际上它们构成了一个分布式投票系统——解题者需要发现每个 grey 像素按最近距离"归属"于某个 sprite，最终的去留由投票多数决定。空间分布本身编码了选择逻辑。
</new_puzzle>

<new_puzzle>
- `description`：根据同色连通区域的边界接触模式（接触网格的哪条边），为每个区域选择不同的变换操作。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干单色 4-连通区域，全部使用同一种前景色（如 blue）。每个区域形状各异（不规则多连通块，大小约 3-10 像素）。
  - 这些区域分散在网格中，部分区域的像素紧贴网格边缘（即像素位于第 0 行、最后一行、第 0 列或最后一列），部分区域完全位于网格内部不接触任何边。

- `Rule`：
  - 对每个 4-连通区域，判断它接触了网格的哪些边（上边 = 第 0 行、下边 = 最后一行、左边 = 第 0 列、右边 = 最后一列）：
    - 不接触任何边（完全内部）：保持原色 blue 不变。
    - 仅接触一条边：将该区域重新着色为 red。
    - 接触恰好两条边：将该区域重新着色为 green。
    - 接触三条或四条边：将该区域重新着色为 yellow。
  - 着色后，每个区域的形状和位置不变，仅颜色改变。

- `Key insight`：所有区域初始颜色相同，输出中却出现了多种颜色——解题者需要发现区分它们的关键不是形状、大小或位置，而是"接触网格边缘的边数"这一容易被忽视的拓扑属性。
</new_puzzle>
