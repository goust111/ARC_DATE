## 第一步：基础操作分析与非显而易见的串联思路

### 参考题中涉及的基础操作梳理

1. **算术编码**（#1）：用物理属性（高度）编码数值，用颜色编码符号（正/负），进行加减运算。
2. **轮廓绘制与孔洞检测**（#2）：检测连通分量是否包含封闭孔洞，根据结果决定重着色方案。
3. **射线发射**（#3, #10, #14）：从特定点沿特定方向发射射线，直到碰到障碍物或边界。
4. **包围盒包含关系**（#4）：通过 bbox 的几何包含判断层级关系，决定删除。
5. **缩略图/图例映射**（#5, #6, #13, #16）：用小型模式作为索引或图例，映射到大型网格中。
6. **方向编码与滑动**（#7, #15）：通过标记像素的相对位置编码方向信息，驱动物体移动或射线转向。
7. **路径规划**（#8）：在迷宫中通过门中心点连接路径。
8. **模板锚定与重建**（#9）：端点标记作为锚点，重建完整图案。
9. **图层叠加**（#11）：多个同尺寸矩形按局部坐标叠加标记像素。
10. **缩放与反射**（#12）：根据锚点大小比例缩放图案，根据象限位置反射。
11. **推动/弹射**（#17）：检测接触方向，沿反方向推至边界。
12. **螺旋生长**（#18）：turtle graphics 风格的路径生长规则。
13. **模板复制到标记位置**（#19）：识别标记单元格，将模板精确复制。
14. **局部裁剪**（#20）：在每个对象的局部坐标系中删除部分列。

### 非显而易见的串联方式思考

- **拓扑属性驱动颜色选择**：对象的连通性质（如孔洞数量、分支数）不用来做轮廓，而是用来索引颜色表，或者用来决定变换方向。
- **对象间距编码指令**：不是对象本身的形状或颜色，而是对象之间的间距（空白区域的宽度/高度）编码了某种参数。
- **影子投射与遮挡**：从一个光源方向投射对象的"影子"，影子的形状揭示被遮挡的信息。
- **对称性缺失作为信号**：本该对称的图案中缺失的部分恰恰编码了需要执行的操作。
- **路径交叉产生新颜色**：两条不同颜色的路径交叉时产生混合色（如两个颜色的交集位置着第三种颜色）。
- **面积排序决定涂色顺序**：多个对象按面积排序，排序结果决定它们被赋予的颜色或位置。
- **邻接图作为隐含结构**：对象之间的邻接关系形成一个隐含图，该图的属性（如度数）决定变换规则。

<new_puzzle>
- `description`：根据每个封闭区域边界上不同颜色片段的数量，用对应的颜色填充该区域。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由彩色像素围成的封闭区域（围墙），每个区域的围墙由多种颜色的连续片段拼接而成（例如一段 red、一段 blue、一段 green 依次首尾相连围成一个闭合形状）。
  - 网格底部或右侧有一个小型图例条，由上到下（或由左到右）排列着若干颜色块，每个颜色块是一个单像素方块。图例条中第 k 个位置的颜色表示"当边界片段数量为 k 时应填充的颜色"。
  - 每个封闭区域的内部初始为 black（背景色）。

- `Rule`：
  - 保持所有围墙像素不变。
  - 对于每个封闭区域，沿其边界行走，统计边界上不同颜色的连续片段数量 N（同色相邻像素算一个片段，颜色切换则片段数加一）。
  - 在图例条中查找第 N 个位置对应的颜色 C。
  - 将该封闭区域的内部全部填充为颜色 C。
  - 图例条本身在输出中保持不变。

- `Key insight`：填充颜色不取决于围墙用了哪些颜色，而取决于围墙上颜色切换了多少次——即边界被分成了几段不同颜色的连续片段。图例条将这个计数映射到填充颜色。

<new_puzzle>
- `description`：将散落的彩色像素沿其最近同色像素的方向"吸附"移动，直到与同色像素相邻为止。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干彩色像素（非 black），共使用 2 至 4 种颜色。
  - 同一种颜色的像素分为两类：（a）由多个像素组成的紧凑"磁铁"簇（4-连通分量，至少 3 个像素），以及（b）远离磁铁簇的孤立单像素"碎片"。
  - 每种颜色恰好有一个磁铁簇和若干碎片。每个碎片与其同色磁铁簇之间的曼哈顿路径上不存在其他非背景像素的阻挡（即沿行或列方向有无障碍直线路径可达同色簇的某一行或某一列）。

- `Rule`：
  - 磁铁簇保持原位不动。
  - 对每个碎片像素，找到与其同色的磁铁簇。
  - 碎片沿曼哈顿距离最短的方向（先水平后垂直，若水平距离为零则纯垂直）朝磁铁簇移动。碎片从原位消失，出现在磁铁簇边缘的第一个空 black 像素处——即沿移动方向紧贴磁铁簇（或已吸附碎片）停下。
  - 若多个碎片沿同方向吸附到同一簇，按距离从近到远依次贴靠堆叠。
  - 所有其他像素保持不变。

- `Key insight`：颜色是吸附目标的标识；碎片不是简单地平移到簇中心，而是像磁铁一样沿最短轴向路径滑动到簇的表面并堆叠。解题者需要识别"簇"与"碎片"的角色区分（通过大小判断），并推断出吸附方向和停靠位置。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色对象根据其自身形状中隐含的箭头方向进行平移，平移距离等于该对象的面积。

- `Input structure`：
  - 背景为 grey。
  - 网格中有若干单色 4-连通对象，每个对象使用不同于 grey 的颜色。
  - 每个对象的形状是一个"带尖端的不规则形状"——即形状在上、下、左、右四个方向之一有一个明显的单像素突出尖端（尖端像素仅有一个 4-连通邻居属于该对象），而其余方向的轮廓相对平整。这个尖端指示了该对象应平移的方向。
  - 对象的面积（像素总数）在 2 到 6 之间。
  - 对象之间在平移前互不重叠，且平移后也不会超出网格边界。

- `Rule`：
  - 识别每个对象形状中的尖端像素（仅有一个 4-连通同色邻居的像素）。若有多个这样的像素，选择距对象质心最远的那个作为尖端。
  - 尖端相对于对象质心的方向（上/下/左/右，取主方向）即为该对象的平移方向。
  - 平移距离等于该对象的像素面积。
  - 将对象从原位置擦除（恢复为 grey），在新位置绘制。

- `Key insight`：对象既是被移动的物体，也是移动指令的载体——形状中的尖端编码方向，面积编码距离。解题者需要同时从形状中"读出"方向和从大小中"读出"距离。
</new_puzzle>

- `description`：将网格中由分隔线划分的多个子区域按照各自内部标记像素所指定的旋转角度分别旋转。

- `Input structure`：
  - 背景为 black。
  - 一组完整贯穿网格的 maroon 水平线和垂直线将网格划分为若干大小相同的正方形子区域（例如 3x3 或 4x4 的方格，每个方格由 maroon 线分隔）。
  - 每个正方形子区域内部包含一个由某种非 black、非 maroon 颜色绘制的小图案（sprite）。
  - 每个子区域的某一个角落像素被着为 red。具体是哪个角落（左上/右上/左下/右下）因子区域而异。

- `Rule`：
  - 保持 maroon 分隔线不变。
  - 对每个子区域，检查 red 像素位于哪个角落：
    - 左上角 → 不旋转（0°）。
    - 右上角 → 顺时针旋转 90°。
    - 右下角 → 旋转 180°。
    - 左下角 → 顺时针旋转 270°（即逆时针 90°）。
  - 将该子区域内的所有非 maroon 内容（包括 sprite 和 red 角标）按指定角度绕子区域中心旋转。
  - 旋转后写回原子区域位置。

- `Key insight`：每个子区域的角落标记像素位置不是装饰，而是旋转指令。解题者需要注意到 red 像素总在角落，且其位置与旋转角度之间存在固定对应关系（角落位置本身就是旋转后左上角的去向）。
</new_puzzle>

<new_puzzle>
- `description`：根据每条彩色"管道"连接的两个端口颜色，对管道本身重新着色为两端口颜色的混合结果。

- `Input structure`：
  - 背景为 black。
  - 网格边缘分布着若干成对的彩色"端口"像素（每对相同颜色，分布在网格的不同边上）。可用的端口颜色包括 red、blue、yellow。
  - 网格内部有若干条 grey 的单像素宽"管道"路径（4-连通），每条管道的两个端点分别与网格边缘上的两个端口像素 4-连通相邻。
  - 每条管道连接的两个端口颜色可能相同也可能不同。
  - 网格中还有一个小型 2x3 或 3x2 的颜色混合图例，位于网格的某个角落区域。图例以矩阵形式展示：行和列分别标注两种输入颜色，交叉单元格显示混合后的输出颜色。例如 red+blue → magenta, red+yellow → orange, blue+yellow → green, red+red → red, blue+blue → blue, yellow+yellow → yellow。

- `Rule`：
  - 保持端口像素和图例不变。
  - 对每条 grey 管道，找到它两端连接的端口颜色 A 和 B。
  - 在图例中查找 (A, B) 对应的混合颜色 C。
  - 将该管道的所有 grey 像素重新着色为 C。

- `Key insight`：grey 管道是待着色的载体，其最终颜色不取决于管道本身，而取决于管道两端所连接的端口颜色组合。解题者需要（1）追踪每条管道到边缘找到两个端口，（2）理解图例是一个颜色混合查找表，（3）将查找结果应用于管道。
</new_puzzle>

- `description`：在网格中找到所有"窗户"对象，根据窗户内部被遮挡的格子数量，在窗户外部对应方向绘制等长的旗杆。

- `Input structure`：
  - 背景为 azure。
  - 网格中有若干由 blue 像素构成的矩形"窗框"（中空矩形边框，内部为规整的网格状结构）。每个窗框内部被 blue 的细线分隔成若干等大的小格子（如同窗户的多格玻璃）。
  - 部分小格子被 orange 像素填满（表示"被遮挡/被窗帘挡住的格子"），其余小格子保持 azure 背景色（"透明格子"）。
  - 每个窗框的正上方一格处有一个单独的 red 像素标记。

- `Rule`：
  - 保持所有窗框、格子填充和 red 标记不变。
  - 对每个窗框，计算其内部被 orange 填充的格子数量 N。
  - 从 red 标记像素开始，向上绘制一条长度为 N 个像素的 red 竖直线（"旗杆"），即从 red 标记向上延伸 N 个像素（不含标记自身）。
  - 若旗杆会超出网格顶部边界，则截断至边界。

- `Key insight`：窗户内部 orange 格子的数量编码了旗杆长度。解题者需要注意到每个窗户的 orange 格子数量各不相同，且这个数量精确对应其上方旗杆的长度——窗户的"遮挡程度"转化为外部标记的"延伸距离"。

- `description`：根据两个形状之间的重叠关系，在重叠区域保留特定颜色，非重叠区域擦除，且保留哪种颜色取决于哪个形状的面积更大。

- `Input structure`：
  - 背景为 black。
  - 网格中恰好有两个不同颜色的 4-连通对象，它们的边界框有部分重叠（即两个对象各占一些像素，有些像素位置被两个对象同时覆盖——在输入中，重叠位置显示为其中一个对象的颜色，具体是哪个在不同样例中不同）。
  - 在网格的一个角落有一个 2x1 的小色块对，左侧像素的颜色与面积较大的对象相同，右侧像素的颜色与面积较小的对象相同。这个色块对作为"大小提示"帮助确认哪个对象更大。

- `Rule`：
  - 找到两个对象各自的完整形状范围（包括被对方遮挡的部分——被遮挡部分的形状可通过对象的可见部分推断：每个对象都是凸形状，即填满其可见像素的凸包）。
  - 计算两个凸包的重叠区域。
  - 输出仅保留重叠区域的像素，颜色使用面积较大的那个对象的颜色。
  - 非重叠区域和背景均设为 black。
  - 角落的大小提示色块对在输出中移除。

- `Key insight`：两个半透明对象叠放在一起，解题者需要还原出各自的完整凸形状，计算交集区域，并用面积大者的颜色涂色。角落色块暗示了大小关系而非颜色优先级。
</new_puzzle>

<new_puzzle>
- `description`：沿每个对象的"脊线"方向将对象拉伸至网格边界，拉伸颜色由脊线长度与横截面宽度的比值决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个不同颜色的细长矩形对象（宽 1-2 像素，长 3-8 像素），可以是水平或垂直朝向。
  - 网格右下角有一个小型颜色图例：两行像素，第一行是 green，第二行是 yellow。表示"脊线长度 > 横截面宽度的 2 倍时用 green 拉伸，否则用 yellow 拉伸"。

- `Rule`：
  - 对每个矩形对象，识别其长轴方向（脊线方向）和短轴方向。
  - 脊线长度 L = 长轴方向的像素数，横截面宽度 W = 短轴方向的像素数。
  - 若 L > 2W，拉伸颜色为 green；否则拉伸颜色为 yellow。
  - 沿长轴方向，从对象的两端分别延伸拉伸颜色的像素，宽度与对象相同，直到触及网格边界或遇到其他非 black 像素。
  - 原对象像素保持原色不变。

- `Key insight`：拉伸方向由对象自身的朝向（长轴）决定，而拉伸的颜色不是对象本身的颜色，而是由对象的长宽比（形状属性）通过图例查表决定的。解题者需要同时读取形状的几何属性和图例的映射规则。
</new_puzzle>
