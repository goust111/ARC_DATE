# 分析与思考

## 基础操作提取

从20道参考题中，我提取出以下核心基础操作：

1. **空间投射/射线（Ray casting）**：从源对象沿方向发射射线，遇到阻挡物停止（题3、4）
2. **滑动/平移（Sliding/Translation）**：对象沿方向移动到目标位置（题1、11）
3. **对接/匹配（Docking/Matching）**：根据属性将对象与目标配对（题2、16）
4. **折叠/旋转（Folding/Rotation）**：在铰链点处改变方向（题10、19）
5. **填充/泛洪（Flooding/Filling）**：根据连通性填充区域（题7、9）
6. **拓扑分析（Topology）**：通过孔洞数量等拓扑特征分类（题20）
7. **层次/遮挡排序（Layering/Occlusion）**：通过交叉可见性推断绘制顺序（题5）
8. **控制信号解码（Control decoding）**：网格中的标记编码控制参数（题17、18）
9. **模板/模具合成（Template composition）**：将颜色与形状模板组合（题12）
10. **边界特征配对（Boundary pairing）**：对称地在对侧添加互补特征（题14）
11. **扩展/生长（Extension/Growth）**：根据规则扩展对象（题6、8）
12. **角色互换（Role swap）**：连接器与标记互换位置/角色（题13）

## 非显而易见的串联方式思考

- **拓扑特征作为空间操作的参数**：一个对象的孔洞数量不仅用来匹配颜色，还可以决定它需要移动多少步、旋转多少度、或者射线延伸多远。
- **遮挡关系编码为路径指令**：对象之间的覆盖顺序不只确定绘制层次，还可以编码一条遍历路径，路径本身再指导颜色传播。
- **边界形状作为密钥**：对象在边界处的凹凸模式可以作为"钥匙"，匹配另一个对象的"锁"，决定哪些对象该合并。
- **投影的交叉点作为新对象的种子**：从不同对象投射的射线交汇处生成新结构。
- **对象的面积差值编码位移量**：不同对象的面积比较结果不仅用来分类，还可以直接作为平移的像素数。
- **连通路径上的颜色序列作为"程序"**：沿路径读取的颜色顺序指定了一系列变换操作。
- **对称性缺陷定位操作目标**：本应对称的结构中的不对称部分标识了需要修复或变换的位置。

<new_puzzle>
<description>
从每个彩色种子像素沿其所在行和列扫描，统计到达网格边缘前经过的同色像素数量，将该数量作为生长半径，以种子为中心绘制对应大小的实心菱形。

Input structure
- 黑色背景网格，尺寸不超过 25x25。
- 网格中散布若干单独的彩色像素（种子），每个种子颜色互不相同。
- 在部分种子的同行或同列上，还存在与该种子同色的额外像素（计数标记），这些标记像素彼此不相邻，也不与种子相邻。

Rule
- 对每个种子像素，分别沿其所在行（左右两个方向）和所在列（上下两个方向）扫描，统计该行和该列中与种子同色的标记像素总数 N。
- 以种子像素为中心，绘制曼哈顿距离 <= N 的实心菱形，颜色为种子颜色。
- 若多个菱形重叠，后处理的种子（按从上到下、从左到右的种子位置顺序）覆盖先处理的。
- 行列中不存在同色标记的种子（N=0）保持为单个像素不变。

Key insight
- 解题者必须意识到散落在同行同列的同色像素不是装饰，而是"计数器"，它们的数量决定了菱形的大小；颜色匹配将标记与种子关联，空间共线性确定哪些标记属于哪个种子。
</description>
</new_puzzle>

<new_puzzle>
<description>
在网格中找到每个封闭围栏内部的单色信号像素，根据信号像素相对于围栏几何中心的象限位置，将围栏整体向该象限方向的对角线方向平移，直到碰到网格边缘或另一个围栏。

Input structure
- 灰色背景网格，尺寸不超过 25x25。
- 网格中有若干由 maroon 色像素组成的一像素宽的封闭矩形围栏（每个围栏是一个完整的矩形环）。
- 每个围栏内部恰好有一个非背景、非 maroon 的彩色像素（信号像素），位于围栏内部的某个象限区域（左上、右上、左下、右下）。
- 围栏之间不重叠，初始时互不接触。

Rule
- 计算每个围栏内部区域的几何中心（内部矩形区域的中心点，若为半像素则取偏左上的整数坐标）。
- 判断信号像素相对于该几何中心的位置：若在中心左上方则方向为左上（-1,-1），右上方则为右上（-1,+1），左下方则为左下（+1,-1），右下方则为右下（+1,+1）。
- 将整个围栏（包含信号像素）沿该对角线方向逐步平移，每步移动一个像素，直到围栏的外边缘接触到网格边界或另一个已停止的围栏的外边缘。
- 处理顺序：距离网格最近角落最近的围栏优先处理（按围栏中心到四个角落的最小曼哈顿距离排序，距离小的先移动并先固定）。
- 信号像素在输出中保留在围栏内相对位置不变。

Key insight
- 关键洞见是信号像素不是颜色标签而是方向指示器——它相对于围栏中心的象限位置编码了围栏的移动方向。解题者需要从多个样例中对比信号像素位置与围栏移动方向的对应关系才能发现这一规则。
</description>
</new_puzzle>

<new_puzzle>
<description>
将网格中的多段折线按照它们的转弯方向序列进行排序，然后用排序后的顺序重新分配折线颜色（最短转弯序列对应第一种颜色）。

Input structure
- 黑色背景网格，尺寸不超过 20x20。
- 网格中有 3 到 5 条不同颜色的折线，每条折线由一像素宽的彩色路径组成。
- 每条折线是 4-连通的，从一个端点到另一个端点形成不分叉的路径。
- 折线之间不接触、不交叉。
- 网格底部有一行由这些颜色组成的从左到右排列的单像素色块，作为颜色顺序参考条（定义第1色、第2色...）。

Rule
- 对每条折线，从任一端点出发沿路径行走，记录每次方向改变（转弯）。将"左转"记为 L、"右转"记为 R，得到该折线的转弯序列字符串。
- 注意：折线的两个行走方向会产生互为镜像的序列（L和R互换），取字典序较小的那个作为标准序列。
- 将所有折线按标准转弯序列的字典序排序。
- 排序后的第 k 条折线被重新着色为参考条中第 k 个颜色。
- 折线的形状和位置不变，只改变颜色。参考条在输出中移除。

Key insight
- 解题者需要意识到颜色变化与折线的几何形状有关，而关键属性不是长度、面积或位置，而是沿路径行走时的转弯方向序列。参考条提供了目标颜色的排列顺序，转弯序列的字典序建立了折线到颜色的映射。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格中每个彩色区域的凸包与其实际形状之间的差集（"缺口"区域）被填充为另一种指定颜色，而原始形状保持不变。

Input structure
- 白色（用 grey 表示）背景网格，尺寸不超过 25x25。
- 网格中有若干互不接触的单色前景对象，每个对象是一个连通的非凸多格骨牌形状（即形状不是凸的，存在凹陷）。
- 每个对象旁边（8-连通邻接但不重叠）恰好有一个单独的不同颜色的像素，称为"标签像素"。

Rule
- 对每个前景对象，计算其所有像素坐标的凸包（最小凸多边形）。
- 找出凸包覆盖但对象未覆盖的网格单元格（即凸包内部的"缺口"像素，这些像素当前是背景色）。
- 将这些缺口像素填充为该对象旁边标签像素的颜色。
- 原始对象像素颜色不变，标签像素在输出中移除（变为背景色）。

Key insight
- 解题者需要识别出变换的核心是"凸包补全"——输出中新增的像素恰好是将原始非凸形状变为凸形状所需的部分。标签像素不参与形状计算，仅提供填充颜色。这要求解题者理解凸包的几何概念，但在视觉上这相当直觉：填充的就是形状"凹进去"的部分。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格被分成若干由边框分隔的房间，每个房间有一扇"门"（边框上的缺口）。从指定的起始房间出发，按照房间内地砖颜色指定的路径规则依次穿过各房间，最终在每个被访问的房间地板上留下足迹标记。

Input structure
- 黑色背景网格，尺寸不超过 30x30。
- Azure 色的一像素宽线条将网格划分为若干矩形房间。
- 每个房间的 azure 边框上恰好有 1 到 3 个一像素宽的缺口（门），缺口处为黑色背景。
- 每个房间内部的地板为黑色背景，但恰好有一个像素为非黑非 azure 的颜色（地砖标记）。
- 恰好有一个房间的地砖标记为 red（起始房间），其余房间的地砖标记为 green、yellow、blue 或 magenta。
- 每个房间内的地砖标记位于房间内部的某个位置（上半部、下半部、左半部、右半部），该位置指示离开该房间时应走的方向（上、下、左、右）。

Rule
- 从 red 标记的起始房间开始。
- 在当前房间中，观察地砖标记在房间内部的相对位置：若标记在房间内部上半部分则方向为"上"，下半部分为"下"，左半部分为"左"，右半部分为"右"（若恰好在中心线上，以行优先：先判断上下，再判断左右）。
- 沿该方向寻找当前房间边框上的门，穿过该门进入相邻房间。
- 在被访问的每个房间（包括起始房间）中，将该房间的整个内部地板区域（所有黑色背景像素）填充为 orange 色，地砖标记像素保持原色。
- 当到达一个房间在指示方向上没有门时，路径终止。
- Azure 边框在输出中保持不变。

Key insight
- 解题者必须发现两个隐蔽的机制：(1) 每个房间内的彩色像素位置编码了离开方向而非仅仅是标签；(2) 只有沿路径被访问到的房间才会被填充，未访问的房间保持原样。这要求解题者同时关注空间布局（门的位置）和房间内标记的相对位置来追踪路径。
</description>
</new_puzzle>

<new_puzzle>
<description>
将网格中每个前景对象的"视觉重心"连线，形成的连线图案替换原始对象；原始对象消失，只保留连线。

Input structure
- 黑色背景网格，尺寸不超过 20x20。
- 网格中有 3 到 6 个互不接触的单色前景对象，每个对象由一种唯一颜色的连通像素组成。
- 每个对象的形状不规则，面积至少为 4 个像素。
- 网格边缘有一条由所有对象颜色按特定顺序排列的单像素色带（位于顶部一行或左侧一列），作为连接顺序指示。

Rule
- 计算每个前景对象的视觉重心：所有属于该对象的像素坐标的算术平均值（行平均和列平均），四舍五入到最近的整数坐标。
- 读取边缘色带中颜色的排列顺序，定义连接路径：第1色的重心连到第2色的重心，第2色连到第3色，依此类推。
- 在黑色背景上，用 green 色像素绘制每段连接线，使用 Bresenham 直线算法（标准光栅化直线）。
- 每个对象的重心位置用该对象原始颜色标记为一个单像素点。
- 原始对象的其余像素全部清除为黑色背景。色带也清除。

Key insight
- 解题者需要理解输出中的线段连接的是原始对象的"中心"，而连接顺序由边缘色带编码。关键在于将不规则形状抽象为单点（重心），再用色带读取连接顺序，两层信息编码缺一不可。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格中散布着成对的同色标记，每对标记定义一个矩形区域，该区域内的所有现有图案以该对标记的颜色对应的旋转角度进行原地旋转。

Input structure
- 黑色背景网格，尺寸不超过 25x25。
- 网格中有一个由 grey 色像素绘制的图案（任意连通或非连通形状）。
- 网格中散布着若干成对的彩色标记像素，每种非黑非 grey 的颜色恰好出现两次。
- 每对同色标记定义一个轴对齐的矩形区域（以两个标记为对角）。
- 不同颜色标记定义的矩形区域互不重叠。
- 网格角落处有一个 2x2 的颜色图例：第一行两个格子分别为某颜色和 "90" 的视觉编码（该颜色后跟一个旋转指示），实际实现为：red 对应顺时针 90 度、blue 对应 180 度、green 对应顺时针 270 度（即逆时针 90 度）。

Rule
- 识别每对同色标记，确定它们围成的矩形子区域。
- 根据该颜色对应的旋转角度（red=90 度顺时针，blue=180 度，green=270 度顺时针），将该矩形区域内的所有像素（包括 grey 图案和黑色背景）进行原地旋转。旋转中心为矩形中心。
- 若矩形不是正方形，旋转后矩形的尺寸会变化（宽高互换），旋转后的内容放置在以原矩形中心为中心的新矩形位置。
- 标记像素本身在旋转完成后移除（变为黑色）。
- 颜色图例在输出中保留不变。

Key insight
- 解题者必须发现三层编码：(1) 同色像素对定义操作区域；(2) 标记颜色通过图例映射到旋转角度；(3) 旋转仅作用于被标记框选的局部区域而非全局。难点在于同时解读区域定义和旋转映射。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格中有多个不同大小的同色矩形，每个矩形内部有一条从某边出发的短线段（"指针"）。将每个矩形沿指针方向"推出"其内容——矩形的内部行或列从指针端开始逐行/列弹出，在矩形外侧堆叠形成镜像展开。

Input structure
- Azure 色背景网格，尺寸不超过 25x25。
- 网格中有若干由 maroon 色边框围成的矩形区域（一像素宽边框），矩形内部填充有多色图案。
- 每个矩形的一条边框内侧有一条 2-3 像素长的 yellow 短线段（指针），指向矩形外部的方向（上、下、左或右），指针与边框平行并紧贴在内侧。

Rule
- 对每个矩形，确定指针所在的边（上边、下边、左边或右边），指针指向该边的外侧方向。
- 将矩形内部的图案沿指针方向进行"翻转展开"：将内部内容沿指针所在边进行镜像翻转，放置在矩形外侧紧邻的位置。
- 具体地：若指针在右边，将矩形内部内容沿右边框做左右镜像，镜像结果紧贴右边框外侧放置。
- 原始矩形（包括边框和内部内容）保持不变。
- 指针（yellow 像素）在输出中移除（恢复为原内部图案的颜色或背景色）。
- 若展开后的内容超出网格边界，则截断到网格边界。

Key insight
- 指针不是指示移动方向，而是指示镜像展开方向。解题者需要从样例中发现矩形外侧新出现的图案恰好是矩形内容沿某边的镜像，而指针的位置确定了镜像轴的选择。
</description>
</new_puzzle>
