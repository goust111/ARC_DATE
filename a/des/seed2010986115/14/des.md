<description>
根据框架内部孔洞的形状匹配外部色块图例，再用图例指定的颜色填充孔洞所在对象的轮廓。

Input structure:
- 背景为主色（black）。
- 网格左侧或底部有一列"形状-颜色"图例：每个图例条目由一个小的前景色形状（2-4像素，形如L形、T形、直线等）紧邻一个单色块组成，形状和色块之间无间隔。
- 网格主区域中有若干用同一种颜色（如 grey）绘制的矩形框架（一像素宽边框），每个框架内部包含一个由背景色构成的孔洞，孔洞的形状与某个图例条目中的小形状完全一致（平移后重合，不旋转不翻转）。
- 每个框架外部边框颜色相同，孔洞形状各不相同。

Rule:
- 对每个矩形框架，提取其内部孔洞的形状（背景色像素在框架内部形成的连通区域的相对坐标）。
- 在图例中找到形状完全匹配的条目（平移对齐后像素一致）。
- 读取该图例条目中紧邻形状的色块颜色。
- 将该框架的所有边框像素重新着色为图例指定的颜色，孔洞保持为背景色不变。
- 图例区域在输出中保持原样不变。

Key insight:
框架本身的颜色不携带信息，真正的分类依据是框架内部负空间（孔洞）的几何形状；解题者必须先识别孔洞形状，再与图例做匹配，最后才能确定重着色的目标颜色——这构成"形状识别→图例查找→颜色映射"的三层推理。
</description>

<description>
将散落的彩色箭头精灵按其指向方向依次推入对应边缘的停靠槽中，箭头到达槽位后以槽的颜色重绘。

Input structure:
- 背景为主色（black）。
- 网格四条边各有若干单像素宽的"停靠槽"标记：每个标记是一个非背景色像素，位于边缘行或列上，不同边的标记颜色可能不同。上边缘的标记表示从上方接收、下边缘的标记表示从下方接收，左右同理。
- 网格内部散布若干由同一前景色（如 red）绘制的箭头形精灵。每个箭头精灵恰好占据5个像素：一个十字中心像素加上沿四个正方向之一延伸的两个像素构成箭头杆，以及垂直于杆方向的两个像素构成箭头尖端，整体呈"指向某方向"的箭头形状。具体地，箭头朝上时形状为：第1行中间一个像素，第2行左中右三个像素，第3行中间一个像素（共5像素，尖端朝上）。朝其他方向时按相应旋转。
- 每个箭头的指向方向对应网格的上、下、左、右四个边之一。

Rule:
- 对每个箭头精灵，确定其指向方向（上/下/左/右）。
- 沿该方向找到箭头尖端像素所在行或列上的边缘停靠槽标记。若箭头朝上，则在箭头尖端所在列的上边缘寻找标记；若朝左，则在箭头尖端所在行的左边缘寻找标记。
- 将箭头精灵平移至该方向的边缘，使箭头尖端像素恰好与停靠槽标记重合。
- 平移后的箭头精灵用停靠槽标记的颜色重绘所有5个像素。
- 擦除箭头原始位置的像素（还原为背景色）。

Key insight:
箭头的朝向不仅决定移动方向，还决定了在哪条边缘上搜索匹配槽位；而最终颜色由目标槽位的颜色决定，非箭头自身颜色——解题者需要同时推断方向-边缘-列/行对齐三重关系。
</description>

<description>
在网格中找到被"围墙"分隔的若干区域，根据每个区域内散落标记像素的数量从区域间的共享围墙上打开对应数量的缺口，缺口位置由标记像素的投影位置决定。

Input structure:
- 背景为主色（black）。
- 一种前景色（如 grey）构成一像素宽的正交围墙网络，将网格分割为若干矩形封闭区域。围墙构成完整的网格状分隔（类似棋盘格的线条），每条围墙线从一侧延伸到另一侧或与其他围墙相交。
- 每个封闭区域内部散布零个或多个标记像素，标记像素使用与围墙不同的各种非背景色（如 red、blue、green 等），每个区域内所有标记像素颜色相同但不同区域可以不同。
- 标记像素不与围墙相邻（至少间隔一个背景像素）。

Rule:
- 对每个封闭区域，数出其中标记像素的数量 N。
- 对该区域的每一面围墙（上/下/左/右），检查标记像素在该面围墙方向上的投影：即如果围墙在区域上方，则看每个标记像素的列坐标是否落在该段围墙的范围内。
- 对每个有标记像素投影到的围墙段，在投影位置处将围墙像素擦除为背景色（打开缺口）。每个标记像素恰好在其最近的一面围墙上打开一个缺口：标记像素距哪面围墙最近，就在那面围墙的对应行或列处打开。
- 若区域内无标记像素（N=0），则该区域四面围墙保持完整不变。
- 标记像素本身在输出中被擦除（变为背景色）。

Key insight:
标记像素同时编码两层信息：其数量决定缺口总数，其空间位置（距哪面墙最近以及在墙上的投影坐标）决定缺口在哪面墙的哪个位置打开。解题者必须先理解"最近墙面"的分配规则，再理解"列/行投影"的定位规则。
</description>

<description>
将网格中多个相同模板的旋转副本还原为统一朝向，旋转角度由每个副本内部唯一的色点标记所在象限决定。

Input structure:
- 背景为主色（black）。
- 网格中散布若干互不重叠的前景精灵，它们都是同一个非对称模板的旋转副本（0°、90°、180°、270°四种朝向之一）。
- 每个精灵由两种颜色构成：主体颜色（如 blue，占大多数像素）和恰好一个标记像素（如 red）。
- 模板本身是非对称的（四种旋转各不相同），大致为矩形但带有缺角或突起。
- 每个精灵内部的红色标记像素位于精灵边界框的四个象限之一（左上、右上、左下、右下），标记所在象限因旋转状态不同而不同。

Rule:
- 确定模板的"标准朝向"：在所有精灵中，找到标记像素位于边界框左上象限的那个精灵，其朝向定义为标准朝向（0°）。
- 对于标记在右上象限的精灵，判定其为顺时针旋转了90°；标记在右下象限的为旋转了180°；标记在左下象限的为旋转了270°。
- 将每个精灵逆旋转回标准朝向（0°），精灵的边界框中心位置保持不变。
- 旋转后若精灵像素超出网格边界，则裁剪掉超出部分。

Key insight:
所有精灵看起来形状相似但朝向各异，解题者必须先发现它们是同一模板的旋转，再通过标记像素在边界框内的相对位置（象限）推断每个副本的旋转角度——标记像素不是装饰，而是旋转状态的编码器。
</description>
</new_puzzle>

<description>
根据两个重叠半透明图层的颜色叠加结果，还原出后层图案，前层图案由边缘线索确定。

Input structure:
- 网格整体为一个矩形区域，无额外背景边距。
- 网格中使用三种非背景颜色（如 red、blue、magenta）和一种背景色（black）。
- 网格的最上一行和最左一列是"索引行"和"索引列"，由背景色和一种前景色（如 red）组成，它们共同定义了一个二值矩阵（前层掩码）：若索引行第 j 列为 red 且索引列第 i 行为 red，则前层掩码位置 (i,j) 为"开"（前层存在），否则为"关"。
- 去掉索引行和索引列后的内部区域是"叠加结果"网格。该网格中每个像素的颜色遵循如下叠加规则：
  - 若前层掩码为"开"且后层也有前景：显示为第三种混合色（magenta）。
  - 若仅前层为"开"（后层为背景）：显示前层颜色（red）。
  - 若仅后层有前景（前层为"关"）：显示后层颜色（blue）。
  - 若两层都为背景：显示背景色（black）。

Rule:
- 从索引行和索引列重建前层掩码：内部位置 (i,j) 的前层状态 = 索引列第 i 行有前景色 AND 索引行第 j 列有前景色。
- 对叠加结果网格中的每个像素：
  - 若为混合色（magenta）→ 前层开、后层有前景 → 输出后层颜色（blue）。
  - 若为前层色（red）→ 前层开、后层无前景 → 输出背景色（black）。
  - 若为后层色（blue）→ 前层关、后层有前景 → 输出后层颜色（blue）。
  - 若为背景色（black）→ 前层关、后层无前景 → 输出背景色（black）。
- 输出网格与内部区域同尺寸（去掉索引行和索引列），只显示还原出的后层图案。

Key insight:
索引行和索引列看似普通的边框装饰，实际编码了前层掩码的行列分解（外积结构）；混合色的出现揭示了两层重叠的位置。解题者需先理解索引行列的外积含义来重建前层，再利用颜色叠加逻辑反推后层——这形成"掩码重建→叠加解码→图层分离"的三层推理链。
</description>
</new_puzzle>
