- `description`：根据封闭区域内"种子"像素的颜色，在颜色图例中查找对应的填充图案，再将该图案平铺到整个封闭区域内。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由灰色（grey）像素围成的不规则封闭区域，每个区域内部恰好有一个非黑色、非灰色的"种子"像素（如 red、blue、green 等）。
  - 网格的右侧或底部有一个用灰色边框隔开的"图例区"，图例区内包含若干小方块，每个小方块的左上角像素是一种颜色标识（与种子颜色一一对应），其余部分是一个 2x2 或 3x3 的小型填充图案（由两种非背景色组成的固定 pattern，如棋盘格、条纹、L 形等）。

- `Rule`：
  - 第一步：识别每个封闭区域内种子像素的颜色。
  - 第二步：在图例区中找到左上角颜色标识与该种子颜色匹配的图例方块，提取其填充图案。
  - 第三步：以种子像素所在位置为锚点，将提取到的填充图案以周期性平铺（tiling）的方式填满整个封闭区域的所有黑色像素。种子像素本身被图案覆盖。灰色边界像素不被改变。
  - 图例区在输出中保持不变。

- `Key insight`：种子颜色不是直接用于填充的颜色，而是一个查找键——它指向图例中一个多色图案。解题者必须先建立"种子颜色 -> 图例图案"的映射关系，再理解图案是以种子位置为锚点进行周期平铺的。这两步推理缺一不可：仅看到种子颜色并不能得知填充内容，仅看到图例图案也不知道填充到哪里。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的彩色碎片沿箭头指向的方向滑动，按碎片的面积从小到大依次堆叠到箭头尖端所在的目标框架内。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有一个用 maroon 颜色绘制的矩形框架（空心），框架内部为黑色。
  - 框架外散布着若干彩色碎片（每个碎片是一个由单一非背景色构成的连通区域，形状不规则但面积各不相同）。
  - 每个碎片旁边有一个由同色像素组成的箭头标记：箭头由一条长度为 2 的直线段加上末端一个垂直于方向的 1 像素构成（形如 ">"），箭头指向上、下、左、右四个方向之一，且箭头方向总是指向框架的方向。

- `Rule`：
  - 第一步：计算每个碎片的面积（像素数量），按面积从小到大排序。
  - 第二步：按排序顺序依次处理每个碎片。将碎片沿其箭头指向的方向平移，直到碎片的前沿接触到框架内壁或已放置的碎片为止。
  - 第三步：碎片进入框架后保持原始形状不变，箭头标记在输出中消失。
  - 框架本身保持不变。碎片之间不重叠——后放入的碎片堆叠在先放入的碎片之上（即靠近框架入口侧）。

- `Key insight`：核心难点在于发现碎片的放置顺序由面积决定——面积最小的碎片最先到达框架最深处，面积最大的碎片最后放置、离入口最近。仅看到箭头方向容易误以为碎片是同时滑入的，但堆叠结果表明存在一个隐含的排序规则。解题者需要从多个样例中归纳出"面积排序"这一非显然的前置逻辑。
</new_puzzle>

<new_puzzle>
- `description`：根据"路径模板"中拐弯的方向序列，从一组候选色带中选出匹配的色带，并将其颜色依次涂到路径上。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格上半部分包含一条由灰色（grey）像素构成的单像素宽折线路径，路径从一端起始，经若干次直角拐弯后到达另一端。路径上每个拐弯处要么向左转、要么向右转（相对于行进方向）。
  - 网格下半部分有若干水平排列的候选"色带"，每条色带是一行连续的彩色像素，不同色带之间用黑色行隔开。每条色带由两种颜色交替组成，例如 red-blue-red-blue 或 green-yellow-green。每条色带的长度等于路径的拐弯次数加一。
  - 每条色带左端有一个标识像素（azure 或 orange），标识像素不属于色带本身。azure 表示该色带编码为"左=第一色，右=第二色"，orange 表示"左=第二色，右=第一色"。

- `Rule`：
  - 第一步：沿路径行走，记录拐弯方向序列（左或右）。
  - 第二步：对于每条候选色带，根据其标识像素确定左右与两种颜色的对应关系，然后将拐弯序列翻译成一个颜色序列。
  - 第三步：找到唯一一条色带，使得翻译后的颜色序列与色带本身的颜色完全匹配（即色带的第 k 个像素颜色等于第 k 个拐弯对应的颜色，色带首尾像素对应路径起始段和结束段）。
  - 第四步：将路径的每一段（两个拐弯之间的直线部分）涂上色带中对应位置的颜色。路径起始段涂色带第一个颜色，依此类推。
  - 输出中候选色带区域被清除为黑色，只保留涂色后的路径。

- `Key insight`：解题者必须发现路径的几何特征（拐弯方向序列）与色带之间存在编码-解码关系，且标识像素控制着左右到颜色的映射方式。这需要同时理解路径的空间拓扑、色带的颜色模式以及标识像素的翻转作用——三层信息交叉验证才能确定正确的色带。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多个"窗户"形状根据其内部缺失格子的位置进行分组配对，然后用配对伙伴的边框颜色填充各自的缺失格子。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散布着若干"窗户"对象。每个窗户是一个 3x3 或 4x4 的矩形区域，边框由某种非黑色颜色绘制（如 red、blue、green 等），内部为一个规则的格子图案（由边框色的细线将内部分成若干小格）。
  - 每个窗户的内部恰好有一个小格是黑色的（即"缺失格子"），其余小格填充着边框颜色。
  - 缺失格子在窗户内的位置各不相同（如左上、右下、中间等）。
  - 每两个窗户构成一对，配对条件是：一个窗户缺失格子的位置与另一个窗户缺失格子的位置关于窗户中心呈 180 度旋转对称。例如，一个窗户的左上格缺失，另一个窗户的右下格缺失，则它们配对。

- `Rule`：
  - 第一步：识别所有窗户对象及其缺失格子的位置（在窗户内部的相对坐标）。
  - 第二步：将缺失位置互为 180 度旋转对称的两个窗户配对。
  - 第三步：对于每一对窗户，将窗户 A 的缺失格子填充为窗户 B 的边框颜色，将窗户 B 的缺失格子填充为窗户 A 的边框颜色。
  - 其余所有像素保持不变。

- `Key insight`：表面上看，每个窗户只是"有一个洞需要填色"，但填充的颜色并非自身的边框色，而是来自配对伙伴。配对规则基于缺失位置的旋转对称性——这要求解题者首先发现缺失位置之间的几何互补关系，然后才能确定颜色来源。两层推理环环相扣：不理解配对规则就无法确定填充颜色，不观察颜色交换就难以归纳配对规则。
</new_puzzle>

<new_puzzle>
- `description`：将"信号塔"发出的彩色信号沿连接线传播到"接收器"，信号在经过"滤波器"节点时颜色发生规则性变换，最终用变换后的颜色填充接收器。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有三类对象：
    - **信号塔**：3x3 的实心方块，颜色各不相同（如 red、blue、green），每个信号塔的正上方有一个 1 像素的 maroon 标记。
    - **接收器**：3x3 的空心方框（仅边框为 grey，内部为黑色）。
    - **滤波器**：1x3 或 3x1 的小条，由两种颜色组成——两端像素颜色相同（"输入色"），中间像素为另一种颜色（"输出色"）。
  - 灰色（grey）单像素宽的直线段（水平或垂直）连接信号塔、滤波器和接收器，形成从信号塔到接收器的路径。每条路径上可能经过零个或多个滤波器。

- `Rule`：
  - 第一步：沿灰色连接线追踪从每个信号塔到其对应接收器的路径。
  - 第二步：信号颜色初始为信号塔的颜色。每当路径经过一个滤波器时，检查当前信号颜色是否等于该滤波器的"输入色"（两端像素的颜色）。如果匹配，信号颜色变换为"输出色"（中间像素的颜色）；如果不匹配，信号颜色不变，直接通过。
  - 第三步：信号到达接收器后，用最终的信号颜色填充接收器内部（将黑色内部替换为信号颜色）。
  - 连接线、信号塔、滤波器在输出中保持不变。

- `Key insight`：解题者需要发现三层递进的规律：（1）灰色线段构成信号传播的路径拓扑；（2）滤波器的结构（两端同色=输入，中间=输出）编码了一个条件颜色变换规则；（3）信号颜色沿路径依次经过滤波器时可能发生链式变换——最终填入接收器的颜色取决于初始颜色和路径上所有滤波器的顺序应用。仅观察起点和终点颜色不够，必须理解中间滤波器的条件匹配机制。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中由边框围成的多个房间，每个房间有一扇"门"（边框缺口），根据门的朝向在房间外沿门方向铺设一条"走廊"，走廊的宽度等于门的宽度，走廊的颜色由房间内唯一彩色像素决定，走廊延伸直到碰到另一个房间的外壁或网格边界。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干用 grey 像素绘制的矩形房间（空心矩形边框），每个房间的边框上恰好有一处连续缺口（即"门"），门的宽度为 1-3 个像素。
  - 每个房间内部（边框围成的区域）有且仅有一个非黑色、非灰色的彩色像素（如 red、green、blue 等），位置随机。
  - 各房间之间有足够的黑色间距。

- `Rule`：
  - 第一步：识别每个房间的边框、门的位置和朝向（门在上边、下边、左边还是右边）。
  - 第二步：确定每个房间内部的彩色像素颜色。
  - 第三步：从门的缺口处向外延伸，沿门朝向的方向绘制一条矩形走廊。走廊的宽度等于门的宽度（与门缺口等宽），走廊的颜色为房间内彩色像素的颜色。
  - 第四步：走廊向外延伸，直到走廊的前沿碰到另一个房间的灰色外壁或到达网格边缘为止。走廊不穿过也不覆盖任何灰色像素。
  - 房间内部和边框保持不变。

- `Key insight`：解题者首先需要理解门缺口是走廊的"出口"，门的宽度直接决定走廊宽度。然后需要发现走廊颜色并非来自边框或门本身，而是来自房间深处的那个孤立彩色像素——这个像素在视觉上与门没有直接联系，需要推理才能建立"房间内颜色 -> 走廊颜色"的关联。走廊的终止条件（遇到其他房间外壁）则增加了空间推理的层次。
</new_puzzle>

<new_puzzle>
- `description`：在分隔线划分的多个子网格中，每个子网格包含一个"印章"和若干"墨点"，需要将印章在墨点位置逐一盖印，盖印顺序由墨点与印章的距离（从近到远）决定，且后盖的印章会覆盖先盖的。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格被 azure 颜色的水平线和垂直线分割成若干矩形子网格（类似九宫格布局）。
  - 每个子网格内包含：
    - 一个"印章"：由某种非背景、非 azure 颜色构成的小型连通图案（如 T 形、L 形等），大小约 2x2 到 4x4，位于子网格的固定位置（如左上角区域）。
    - 若干"墨点"：散布在子网格其余位置的单像素标记，每个墨点的颜色与印章颜色不同，且各墨点颜色互不相同。

- `Rule`：
  - 第一步：在每个子网格中，识别印章图案和所有墨点的位置。
  - 第二步：目测判断每个墨点离印章中心的远近（墨点数量少，通常 2-4 个，肉眼即可区分远近）。
  - 第三步：按从近到远的顺序，依次将印章图案以每个墨点为中心位置"盖印"——即将印章的形状以墨点的颜色绘制到网格上，印章图案的中心对齐墨点位置。
  - 第四步：后盖的印章覆盖先盖的印章（即距离远的墨点对应的盖印结果可以覆盖距离近的）。印章原始位置的图案在输出中被清除为黑色。墨点像素本身被盖印图案覆盖。
  - azure 分隔线保持不变。

- `Key insight`：解题者需要发现三个非显然的规律：（1）印章图案是一个"模板"，墨点位置是"盖印目标"；（2）墨点的颜色决定了该次盖印使用的颜色；（3）盖印的先后顺序由距离决定，而这一顺序通过重叠区域的颜色归属才能被观察到——只有通过仔细对比重叠处保留的是哪个墨点的颜色，才能反推出"后盖覆盖先盖"的远近顺序规则。
</new_puzzle>
