- `description`：将散落的单色碎片按颜色匹配到对应的矩形框架中，碎片进入框架后需按框架开口方向的反方向平移至紧靠对边。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中存在若干个不同颜色的矩形框架（空心矩形），每个框架恰好在一条边上有一个连续的缺口（缺口宽度大于 1 像素）。框架的颜色各不相同。
  - 网格中另有若干个与框架颜色一一对应的小型实心碎片（4-连通的不规则形状），每个碎片的颜色与某个框架颜色相同，且碎片的形状恰好能嵌入对应框架的缺口。
  - 碎片位于其对应框架的外部，且位于缺口方向的一侧。

- `Rule`：
  - 第一步：识别每个碎片与框架的颜色匹配关系，以及框架缺口所在的边（上、下、左、右）。
  - 第二步：将碎片沿垂直于缺口边的方向滑入框架内部，滑动方向为从缺口侧朝向对边，碎片一直滑动直到碰到框架的对边内壁为止。
  - 第三步：碎片到达最终位置后，将缺口处原本缺失的框架边界像素补全（用框架颜色填充），使框架变为完整的封闭矩形。
  - 框架外部原碎片位置恢复为背景色。

- `Key insight`：碎片不是直接填入缺口位置，而是穿过缺口后继续滑动到框架的对边。解题者需要识别出缺口方向决定了碎片的运动方向，而终点是对边而非缺口本身，这一"穿透"机制是非显然的核心规律。
</new_puzzle>

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有一条由 grey 颜色绘制的完整水平线和一条完整垂直线，将网格分为四个象限。

  - 同一种颜色只出现一次。

  - 以灰色十字线的交叉点为网格中心。
  - 每个对象根据其所在象限被赋予一个旋转角度：右上象限 = 0°，左上象限 = 顺时针 90°，左下象限 = 顺时针 180°，右下象限 = 顺时针 270°。
  - 将每个对象按其对应角度进行旋转。
  - 所有旋转后的对象按面积从大到小排序，依次以网格中心为锚点（对象的边界框中心对齐到网格中心）进行叠加绘制，面积小的对象后画因此在最上层。
  - 灰色十字线在输出中被移除（恢复为背景色）。

- `Key insight`：解题者需要发现两层独立的规律——第一层是象限位置与旋转角度的映射关系（并非对称翻转，而是累进旋转），第二层是叠加顺序由面积决定（大的先画、小的覆盖）。两层规律都需要从样例中分别归纳。
</new_puzzle>

- `description`：沿每个箭头指向的方向发射与箭头等长的射线，射线颜色由箭头所指向的目标对象的颜色决定。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中存在若干个由不同颜色绘制的小型实心矩形对象（宽高均 ≥ 2）。
  - 网格中还存在若干个由 grey 颜色绘制的箭头。每个箭头由一条直线段（水平或垂直，长度 ≥ 2 像素）和一个位于线段一端的单像素三角尖端组成：尖端位于线段延伸方向的前方，偏离线段主轴一个像素（例如，一个向右的水平箭头，其尖端在线段最右端像素的右上方或右下方，形成一个">"形末端）。箭头的"长度"定义为线段部分的像素数（不含尖端）。
  - 每个箭头的尖端方向上一定存在一个矩形对象（沿箭头方向做射线能最先命中该对象）。

- `Rule`：
  - 第一步：对每个箭头，确定其指向方向（由尖端决定）和长度（线段像素数）。
  - 第二步：沿箭头方向做射线投射，找到最先命中的矩形对象，记录该对象的颜色。
  - 第三步：从箭头尖端开始，沿箭头方向继续延伸一条新射线，射线长度等于箭头的线段长度，射线颜色为第二步中获取的目标对象颜色。
  - 保留所有原始对象和箭头不变，仅添加新的射线像素。射线像素不覆盖已有非背景像素。

- `Key insight`：射线的长度编码在箭头自身的几何属性中（线段长度），而射线的颜色编码在箭头与环境的空间关系中（指向哪个对象）。解题者需要分别从两个不同来源推断同一条射线的两个属性，这构成了两层独立的归纳。
</new_puzzle>

<new_puzzle>
- `description`：在分格棋盘中，每个格子的填充颜色由该格子所在行的行标记颜色和所在列的列标记颜色共同决定：取两种标记颜色在色带图例中的位置之和，对色带长度取循环后查找对应颜色。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格被 grey 线条分割为若干等大的方格（类似棋盘），形成 R 行 × C 列的方格阵列。
  - 方格阵列的左侧有一列标记像素，每行一个，颜色各异，作为该行的"行标记"。
  - 方格阵列的上方有一行标记像素，每列一个，颜色各异，作为该列的"列标记"。
  - 网格的某个角落（如左上角）有一条由若干不同颜色像素排成的短色带，作为颜色图例，长度为 L（L ≤ 6）。色带中每个像素位置编号从 0 到 L-1。
  - 行标记和列标记使用的颜色均来自色带中出现的颜色。

- `Rule`：
  - 对色带中的每种颜色赋予位置编号（从 0 开始）。
  - 对于方格阵列中第 i 行、第 j 列的格子：找到第 i 行的行标记颜色在色带中的位置编号 a，找到第 j 列的列标记颜色在色带中的位置编号 b，计算 (a + b)，若超过 L-1 则从头循环（即 (a + b) mod L，但此处循环是视觉上色带首尾相接的自然循环），取色带中对应位置的颜色填充该格子。
  - 输出中保留 grey 分格线、行列标记和色带。

- `Key insight`：解题者需要发现三层结构——第一层是识别色带作为颜色顺序的图例，第二层是发现行标记和列标记各自映射到色带中的位置编号，第三层是发现格子颜色由两个编号之和在色带上循环查找得到。单看行或列都无法解释格子颜色的变化规律，必须同时考虑行列的联合作用。
</new_puzzle>

<new_puzzle>
- `description`：每对同色像素之间的连线段作为"刀"，切割它所穿过的所有多色对象，被切割的部分沿垂直于刀的方向分离一个像素的间距。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中存在若干个由不同颜色绘制的实心矩形对象（每种颜色一个矩形）。
  - 网格中还存在若干对 red 像素（red 不用于矩形），每对 red 像素在同一行或同一列上对齐，且两个像素之间有一定距离。

- `Rule`：
  - 对每对同行/同列的 red 像素，在它们之间画一条虚拟的直线段（水平或垂直），这条线段即为"切割线"。
  - 切割线穿过的每个矩形被沿切割线分成两部分。
  - 分割后，矩形的两个部分沿垂直于切割线的方向各自向外平移 1 个像素（即两部分之间形成 2 像素宽的间隙，间隙中心在原切割线位置）。
  - 如果一个矩形被多条切割线穿过，则依次应用所有切割（先水平后垂直），每次切割都会将已有碎片进一步分裂和位移。
  - 输出中移除所有 red 像素。

- `Key insight`：red 像素对定义了隐形的切割线，而不是路径或连接。解题者需要先识别出 red 像素的配对关系和连线含义，再理解切割后的分离方向（垂直于切割线而非沿着切割线），最后还要处理多刀叠加切割的顺序效应。
</new_puzzle>

<new_puzzle>
- `description`：网格中的每个"种子"像素按照其相邻的方向标记所指示的方向，生长出与种子颜色相同的线段，线段长度等于种子所在封闭房间的面积。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中存在由 grey 像素绘制的墙壁，墙壁将网格划分为若干个封闭的矩形房间（每个房间的内部为黑色）。
  - 每个房间内部恰好有一个非黑、非灰的彩色"种子"像素。
  - 每个种子像素恰好有一个 4-邻接的 azure 像素位于同一房间内，该 azure 像素位于种子像素的上、下、左或右方，指示生长方向（azure 在种子的哪一侧，种子就朝那个方向生长）。

- `Rule`：
  - 对每个房间，计算房间内部的面积（黑色像素 + 种子像素 + azure 像素的总数）。
  - 种子像素从自身位置开始，朝 azure 标记所指示的方向，穿过墙壁延伸到房间外部，画出一条与种子颜色相同的直线段。
  - 线段长度（像素数，不含种子本身）等于该房间的内部面积。
  - 线段可以覆盖墙壁像素和其他房间的内容，但不覆盖其他种子像素。
  - 输出中移除所有 azure 标记像素（恢复为背景色），保留墙壁和种子。

- `Key insight`：解题者需要先理解 azure 像素不是装饰而是方向指针，再发现线段长度由房间面积决定——而房间面积是视觉上可数但不显然与线段长度关联的量。方向来自局部（邻接标记），长度来自全局（房间尺寸），两者融合构成核心双层推理。
</new_puzzle>
