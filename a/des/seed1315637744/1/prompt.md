<description>
Expand the colored runs from the left reference panel into the blank right panel.

Input structure:
- A uniform rectangular frame surrounds the grid.
- One full-height divider of the frame color splits a left reference panel

  connected by same-color horizontal runs.

Rule:
- Keep the original grid and paint only in the right panel's active columns.
- A source run exactly matching the left endpoint slot is copied to the left
  two columns of the right active span.
- A source run exactly matching the right endpoint slot is copied to the right
  two columns of the right active span.
- A source run connecting the endpoint slots is stretched across the entire
  right active span.

Key insight:
The left panel is a compressed legend for the right panel: endpoint markers
stay two pixels wide, while connectors between endpoints expand to fill the
distance between them.

<reference_puzzle index="2" source="train" puzzle_id="e9fc42f2" lines="26-43">
<description>
Assemble the foreground objects by docking equal-colored boundary markers edge-to-edge.

Input structure
The grid has a dominant background color and several 4-connected multicolor foreground
objects.  One foreground color is the body color; the less frequent foreground colors are
boundary connector markers, and each marker color appears once as a free end or twice as a
matched docking pair.

Rule
Crop each foreground object to its bounding box and translate the objects so that the two
occurrences of every paired connector color touch on their exposed boundary sides.  Preserve
each object's orientation and colors, then return the tight crop around the assembled
foreground on the original background color.

Key insight
The colored marker pixels are ports: matching colors specify which objects must touch, and
the marker's side of its object determines the direction of the translation.
</description>

<description>
Sort scattered 4×4 squares into two columns by type: frames left, solids right.

Input structure:

Key insight: Frame vs solid is determined solely by whether the 2×2 interior matches bg.

<reference_puzzle index="5" source="train" puzzle_id="e39e9282" lines="73-81">
<description>
Project maroon markers into adjacent grey or pink 3x3 squares, erasing grey squares afterward.

Input structure
The grid has a dominant background, solid 3x3 grey and/or pink squares, and maroon marker pixels or segments directly touching one side of exactly one square.
Rule
Grey squares are erased; their adjacent maroon markers stay in place and stamp the nearest edge cell inside the grey square. Pink squares stay pink; their adjacent maroon markers disappear and stamp the corresponding cell on the square's middle row or middle column.
Key insight
The side touched by a marker determines the projection: grey uses the near edge, while pink uses the centerline, preserving the marker's coordinate along that side.

<description>
Slide multi-color sprites to align their marker pixels with matching isolated border anchors.

Input structure:
- bg = most common color.
- Multi-color sprites in the interior; each has a minority-color "marker" pixel.
- Isolated border pixels (non-bg with all 4-neighbors bg) act as anchors.

Rule:
- Match each sprite to the border anchor sharing its marker color.
- Top/bottom-edge anchor (non-corner): slide sprite horizontally so marker column = anchor column.
- Left/right-edge anchor (or corner): slide sprite vertically so marker row = anchor row.

Key insight: The anchor's edge position determines the slide axis — top/bottom means horizontal, left/right (or corner) means vertical.

<reference_puzzle index="7" source="train" puzzle_id="652646ff" lines="84-105">
<description>
Recover each partially hidden 6x6 ring sprite and stack complete copies from top layer to bottom layer.

Input structure:
- The dominant color is the background.
- Several non-background colors are visible fragments of the same 12-pixel
  outline ring in a 6x6 box; small off-template marker pixels are noise.
- Ring fragments overlap, so upper rings replace some expected pixels of
  lower rings, and a ring may also be clipped by the input boundary.

Rule:
- Identify every substantial color whose pixels all lie on one translated
  copy of the ring template.
- For each missing in-bounds template pixel, the color currently occupying
  that pixel is above the hidden ring.
- Topologically sort these occlusion relations from top to bottom, then draw
  one complete 6x6 ring for each color in that order on a background canvas.

Key insight:
- The output is not a crop of the scene; it is the layer stack of complete
  ring sprites reconstructed from their visible fragments.
</description>
</reference_puzzle>

<reference_puzzle index="11" source="eval" puzzle_id="800d221b" lines="7-22">
<description>
Recolor a path-network by adjacent seed regions.

Input structure:
- bg = most common color.
- Path color P forms a thin orthogonal network with a solid square hub (NxN).
- Seed colors appear in colored regions (non-bg, non-P) adjacent to path branches.

Rule:
- Infer P as the non-bg color whose largest component is most network-like.
- Find the largest solid k×k all-P square (the hub); exclude it from recoloring.
- Recolor each path branch to the seed-region color it touches most.
- Recolor the hub center pixel to the seed whose branches touch the hub most.

Key insight: The hub stays uncolored; branches inherit color from adjacent seed regions by adjacency count.
</description>
</reference_puzzle>

<reference_puzzle index="12" source="train" puzzle_id="84551f4c" lines="42-53">
<description>
Rotate each blue-started chain of bottom-aligned vertical bars into horizontal bars resting on the same baseline.
Input structure
- The grid has a background and bottom-aligned, one-cell-wide vertical bars.
- Blue bars are markers; red bars are body bars that may be chained after a marker.
Rule
- Starting at each blue bar, repeatedly include the next red bar whose column is exactly the current bar's column plus the current bar's height.
- Clear every included vertical bar, then redraw each included bar horizontally to the right from its original bottom cell, with length equal to its vertical height.
- Red bars that are not reached from a blue marker remain unchanged.
Key insight
- A vertical bar's height is also the width it occupies after rotation, so the chain follows immediate horizontal contact after each rotated bar.
</description>

<reference_puzzle index="13" source="train" puzzle_id="902510d5" lines="58-80">
<description>
Keep the largest 8-connected motif and replace the corner/control pixels with a solid corner triangle.

Input structure
- The background is the dominant color.
- Exactly one grid corner contains a foreground control pixel; it gives the
  corner from which the triangle is painted.
- There is one unique largest 8-connected monochrome foreground object, the
  motif that remains in the output; all other foreground pixels are controls.
- Every foreground component outside that motif is a singleton control pixel.
- The fill color is the unique control color that appears in at least two
  non-corner control pixels.

Rule
- Start from a blank background canvas and redraw only the largest motif.
- Count the non-corner control pixels; that count is the triangle side.
- Paint the fill color on the right-triangle region where those two distances
  from the marked corner's edges sum to less than the side length.

Key insight
- The scattered singleton controls are counted into a compact triangular
  stack at the marked corner; only the largest motif is not part of the count.
</description>
</reference_puzzle>

<description>
Extract the color of each noisy block in a row/column lattice and mirror the coarse grid horizontally.

Input structure:
- A background surrounds a rectangular lattice of monochrome foreground blocks.
- Consecutive rows in a lattice band share the same set of visible foreground colors.
- Consecutive columns in a lattice band share the same set of visible foreground colors.
- Each row-band/column-band intersection has one foreground color, with possible background holes.

Rule:
- Group non-empty rows and columns into consecutive bands by their foreground color sets.
- Replace each lattice cell by the single foreground color inside that row/column-band intersection.

- Whole-row and whole-column color sets reveal the hidden lattice even when neighboring cells share a color or contain holes.

<description>
Replicate a pre-drawn corner pattern to every other marker-bearing corner.

- bg = most frequent color. Hollow 0-frames (possibly partial L-shapes); each

Rule

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式等人类能够直观感受计算的内容。
   - **禁止使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算（取模） / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数等复杂且不易被看出来的计算都是禁止使用的。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息（例如颜色id和颜色亮度是禁止使用的）或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
8. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
9. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。以两层结构为例：
   - ✗ 伪两层："找到缺口方向"→"把东西推到对面" — 第一步肉眼可见，实际只有一层推理。
   - ✓ 真两层："通过孔洞数量匹配颜色图例"→"用匹配到的颜色重绘对象" — 两步都需要非平凡的归纳。

   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
10. 在符合ARC题目和提示词要求的基础上，鼓励尝试创新规则为多层结构的题目，不局限于两层，可以创新三层或四层结构的题目，但不可为了多结构层数违背要求。

生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述参考题相同或类似，不可只是替换颜色、方向、对象类型等表层要素。判断标准：新题的核心推理路径应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。没有使用上述注意事项第二条禁止使用的复杂计算。
