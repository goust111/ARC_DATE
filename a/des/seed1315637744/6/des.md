<new_puzzle>
用每个封闭区域内的标记像素颜色，沿区域边界内侧绘制与标记像素数量等长的色带。

Input structure
- 黑色背景上有若干由灰色像素围成的封闭区域（形状不规则但边界连续且为4-连通）。
- 每个封闭区域内部恰好包含一个或多个同色的标记像素（颜色各异，如红、蓝、绿等），这些标记像素散落在区域内部。
- 每个封闭区域的灰色边界上恰好有一个缺口（一个像素宽），缺口位置在不同区域中各不相同（可能在顶部、底部、左侧或右侧的边界上）。

Rule
- 对每个封闭区域，数出其内部标记像素的个数 N。
- 从缺口位置出发，沿着区域边界的内侧（紧贴灰色墙壁内部一格），按顺时针方向绘制 N 个像素长的色带，颜色为该区域标记像素的颜色。
- 原始标记像素在输出中被清除为背景色；灰色边界和缺口保持不变。

Key insight
- 标记像素的数量决定色带长度，缺口位置决定色带起点，顺时针方向决定色带延伸方向——三个独立线索共同决定最终输出，需要解题者分别识别并组合。
</new_puzzle>

<new_puzzle>
将网格中散落的彩色碎片按形状匹配拼回各自的框架轮廓中，并根据框架边框颜色决定碎片是否需要旋转。

Input structure
- 黑色背景网格上散布着若干个由不同颜色绘制的矩形框架（仅边框，内部为空），每个框架的内部轮廓形成一个特定的凹凸形状。
- 在框架之外的区域散落着与框架数量相同的彩色碎片（实心连通块），每个碎片的形状恰好能填入某一个框架的内部空间。
- 框架边框使用两种颜色之一：红色或蓝色。碎片本身有各自独立的颜色（绿、黄、橙等），与框架颜色不同。

Rule
- 将每个碎片与其形状匹配的框架配对：碎片的形状与框架内部空腔的形状完全一致（可能需要180度旋转）。
- 若框架边框为红色，则将碎片原样（不旋转）平移填入框架内部。
- 若框架边框为蓝色，则将碎片旋转180度后填入框架内部。
- 输出中碎片的原始位置清除为背景色，碎片出现在对应框架内部。

Key insight
- 第一层推理是形状匹配——碎片与框架内腔的几何配对；第二层推理是框架边框颜色编码了是否需要旋转，解题者需要从样例中归纳出红色=原样、蓝色=旋转180度的隐含规则。
</new_puzzle>

<new_puzzle>
沿着箭头精灵指示的方向传播"染色波"，波经过的每个对象继承前一个对象的颜色，形成颜色链式移位。

Input structure
- 黑色背景上有一行或一列排列的若干个小型单色对象（形状各异但大小相近，颜色互不相同），对象之间有空隙。
- 在这组对象的一端（起始端），紧邻第一个对象外侧有一个由灰色像素构成的箭头形精灵，箭头指向对象排列的方向（向右或向下）。
- 在对象排列的另一端（末尾端）之外，有一个单独的"源色像素"，其颜色与所有现有对象颜色均不同。

Rule
- 按箭头方向，从末尾端的源色像素开始，依次将每个对象的颜色替换为其在箭头方向上后一个位置的颜色。具体而言：最后一个对象变为源色像素的颜色，倒数第二个对象变为原来最后一个对象的颜色，依此类推。
- 第一个对象（箭头端）变为原来第二个对象的颜色。
- 原来第一个对象的颜色消失（不出现在输出中）。
- 所有对象的形状和位置不变，仅颜色按箭头方向整体移位一格。箭头精灵和源色像素在输出中被移除。

Key insight
- 箭头指示的不是物理移动方向，而是颜色传播方向；源色像素从末端注入，所有颜色沿箭头方向整体平移一步——相当于一个颜色队列的入队/出队操作，需要解题者识别出"颜色循环移位"而非"对象移动"。
</new_puzzle>

<new_puzzle>
根据网格中"种子图案"的对称性类型，选择对应的扩展策略将种子放大到整个网格。

Input structure
- 网格被均匀分为四个象限（由一条水平分隔线和一条垂直分隔线划分，分隔线为灰色）。
- 左上象限包含一个由多种颜色构成的小型图案（种子图案），其余三个象限为黑色背景。
- 在网格的四个角落各有一个单像素标记：左上角和右下角的标记颜色相同（标记色A），左下角和右上角的标记颜色相同（标记色B）。标记色A和标记色B分别为两种不同的颜色。
- 种子图案本身可能具有以下对称性之一：水平对称、垂直对称、旋转对称（180度）、或无对称性。

Rule
- 检测种子图案的对称性类型：
  - 若种子图案具有水平轴对称：将种子图案水平翻转到右上象限，垂直翻转到左下象限，水平+垂直翻转到右下象限。
  - 若种子图案具有垂直轴对称：将种子图案顺时针旋转90度到右上象限，旋转180度到右下象限，旋转270度到左下象限。
  - 若种子图案具有180度旋转对称：将种子图案仅复制到对角象限（右下），右上和左下保持空白。
  - 若种子图案无任何对称性：将种子图案原样复制到所有三个空象限。
- 四个角落的标记像素在输出中保持不变。

Key insight
- 角落标记像素是干扰项，真正决定扩展方式的是种子图案自身的对称性质——解题者必须先分析种子图案的对称类型，再选择对应的扩展操作，这构成了"属性检测→条件分支"的双层推理。
</new_puzzle>

<new_puzzle>
将网格中多个"信号塔"对象按其天线方向两两配对连线，连线颜色由配对双方的颜色混合规则决定。

Input structure
- 黑色背景上散布着偶数个"信号塔"对象。每个信号塔由一个 3×3 的实心彩色方块和一根从方块某条边中点向外延伸 2 像素的单像素宽"天线"组成（天线颜色与方块颜色相同）。
- 天线方向为上、下、左、右之一，指示该信号塔的"发射方向"。
- 所有信号塔的方块颜色各不相同，但仅使用红、蓝、黄三种颜色中的两种。

Rule
- 将天线方向相对的信号塔配对：一个天线朝左的塔与一个天线朝右的塔配对（它们可以在同一行，也可以不在同一行）；一个天线朝上的塔与一个天线朝下的塔配对。若同一方向有多个候选，则选择天线延长线距离最近的一对（沿天线方向投影后，两根天线延长线之间间隔最少的配对）。
- 配对后，在两个塔的天线尖端之间绘制一条直线段（水平或垂直，沿天线的公共轴方向）。
- 连线颜色规则：若两个塔颜色相同，连线为该颜色；若两个塔颜色不同（例如一红一蓝），连线颜色为第三种未被使用的颜色（黄）。即连线颜色始终是三原色中两塔均未使用的那种。
- 信号塔本身（方块和天线）在输出中保持不变。

Key insight
- 第一层推理是通过天线方向的对立关系（左↔右、上↔下）实现配对；第二层推理是连线颜色的"补色"规则——同色连同色、异色连第三色——需要解题者从样例中归纳出三色互补的混合逻辑。
</new_puzzle>

<new_puzzle>
在迷宫网格中，根据钥匙颜色打开对应颜色的门，然后沿通道将钥匙的形状印章传递到终点。

Input structure
- 黑色背景网格中有灰色像素构成的迷宫墙壁，形成若干条通道。
- 迷宫中有一个起点标记（白色单像素）和一个终点标记（白色 2×2 方块）。
- 通道中散布着若干"门"——横跨通道的单像素宽彩色线段（例如红色、蓝色、绿色），每扇门完全阻断通道。
- 在起点附近的通道中放置着若干"钥匙"——小型彩色对象（3-5 像素的连通块），每把钥匙的颜色与某扇门的颜色相同。
- 从起点到终点只有一条可行路径（不考虑门的阻挡）。

Rule
- 沿从起点到终点的唯一路径前进。
- 遇到一扇门时，该门被同色钥匙"打开"：门的像素被清除为背景色。
- 钥匙按路径上遇到的顺序依次使用：路径上第一把遇到的钥匙打开路径上第一扇遇到的门（颜色必须匹配，题目保证匹配）。
- 每把钥匙在使用后（打开门后），其形状（像素图案）被"印"在门原来的位置：以门的中心像素为锚点，将钥匙的形状图案居中绘制，颜色改为灰色。
- 起点标记和终点标记在输出中保持不变；未使用的钥匙保持原位。

Key insight
- 表面上这是一个路径寻找题，但真正的推理在于：钥匙不仅仅是"开门"的功能对象，它的几何形状会被转印到门的位置——解题者需要发现"形状转移"这一隐藏机制，而不仅仅是颜色匹配的消除。
</new_puzzle>

<new_puzzle>
将网格中的彩色像素视为"棋子"，按照它们所在区域的隐含棋盘格奇偶性，将奇格棋子的颜色映射到偶格棋子上。

Input structure
- 网格背景由两种颜色交替排列形成棋盘格图案（如黑色和灰色交替）。
- 棋盘格上散布着若干彩色像素（非黑非灰），每个彩色像素恰好占据一个格子。
- 彩色像素总是成对出现：每种非背景颜色恰好出现两次，一次在"奇格"（黑色背景格）上，一次在"偶格"（灰色背景格）上。

Rule
- 对每一对同色像素，保留位于偶格（灰色背景格）上的那个像素不变。
- 将位于奇格（黑色背景格）上的像素移除（恢复为黑色背景）。
- 然后，对每个保留的偶格像素，在其正上方/下方/左方/右方最近的同为偶格的空位处（即距离最近的灰色背景偶格），绘制一个同色像素副本。
- 棋盘格背景本身保持不变。

Key insight
- 第一层推理是识别出背景的棋盘格结构并理解奇偶格的区分——这决定了哪些像素被保留、哪些被删除；第二层推理是保留像素的"复制扩展"规则遵循偶格跳跃而非简单相邻，解题者需要发现扩展目标也受棋盘格奇偶约束。
</new_puzzle>
