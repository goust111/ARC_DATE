- `description`：根据彩色种子像素在网格中生长出树状分支结构，分支方向由相邻围栏缺口决定，分支长度由种子所在封闭区域的面积决定。

- `Input structure`：
  - 背景色为 black。网格中有若干由 grey 像素构成的不规则封闭围栏（围栏为单像素宽的连通闭合边界）。
  - 每个围栏内部恰好有一个彩色种子像素（颜色各不相同，可能为 red、blue、green、yellow、orange 等）。
  - 每个围栏边界上有一个或多个缺口（围栏断开一格的位置）。
  - 围栏外部为 black 背景，围栏之间不重叠。

- `Rule`：
  - 第一步：确定每个围栏内部空腔的面积（即围栏内部 black 像素的数量，不含种子像素本身），该面积值记为 N。
  - 第二步：从每个缺口位置向外（朝远离围栏内部的方向）发射一条与种子同色的直线射线，射线长度恰好为 N 个像素。射线方向为从种子中心穿过缺口位置的四方向（上/下/左/右）中最接近的一个。若射线遇到其他围栏的 grey 像素则停止（不覆盖围栏）。
  - 第三步：种子像素本身保留，围栏保留，射线绘制在 black 背景上。

- `Key insight`：围栏的缺口位置决定射线方向，而围栏内部的面积（一个需要数像素才能获得的视觉量）决定射线长度——解题者必须同时发现这两个独立规律并将它们关联起来。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的单色碎片拼入目标框架的空槽中，拼入时需根据框架边界上的颜色标记对碎片进行旋转，使碎片的特定边朝向标记所在的方向。

- `Input structure`：
  - 背景色为 black。网格中有一个由 maroon 像素构成的大型矩形框架（单像素宽边框），框架内部被 maroon 的内墙分隔为若干矩形空槽（每个槽大小不同）。
  - 框架外部散落着若干单色碎片（每个碎片颜色不同，如 blue、green、red 等），每个碎片的形状恰好与某个空槽的形状相同（可能需要 0°/90°/180°/270° 旋转才能匹配）。
  - 每个碎片有一个特殊的标记像素：碎片中恰好有一个像素的颜色与碎片主体不同（为 yellow），该 yellow 像素位于碎片的某条边上。
  - 每个空槽的边框上（maroon 边框的外侧紧邻处）也有一个 yellow 像素标记，位于槽的某条边上。

- `Rule`：
  - 第一步——形状匹配：将每个碎片的形状（忽略旋转）与各空槽的形状进行匹配，找到唯一对应的槽。
  - 第二步——旋转定向：旋转碎片使碎片上的 yellow 标记像素与空槽边框上的 yellow 标记像素位于同一侧（例如：槽的 yellow 在其北边框上，则碎片须旋转到其 yellow 位于碎片北边）。
  - 第三步——放置：将旋转后的碎片填入空槽，yellow 标记像素替换为碎片主体颜色（即最终输出中不保留 yellow）。

- `Key insight`：形状匹配确定"哪块去哪里"，而 yellow 标记的方位对齐确定"怎么旋转"——这是两层独立的推理，缺一不可。仅靠形状匹配会有多种旋转可能，yellow 标记消除了歧义。
</new_puzzle>

<new_puzzle>
- `description`：在网格中识别由不同颜色构成的"信号塔"和"接收器"，信号塔向四个正方向广播信号线，信号线穿过接收器时根据接收器内部图案对信号线进行颜色调制。

- `Input structure`：
  - 背景色为 black。
  - 信号塔：由 3×3 的纯色方块表示（颜色各异，如 red、blue、green 等），位于网格中的不同位置。
  - 接收器：由 3×3 的方块表示，其外圈 8 个像素为 grey，中心 1 个像素为某种非 black、非 grey 的颜色（称为接收器的"滤波色"）。
  - 信号塔和接收器之间有足够的 black 空间。

- `Rule`：
  - 第一步——广播：每个信号塔从其四条边（上/下/左/右）的中心像素出发，沿该方向发射一条单像素宽的直线，颜色为信号塔的颜色，一直延伸到网格边界。信号线不覆盖任何非 black 像素（遇到已有对象则跳过该像素继续延伸）。
  - 第二步——调制：当某条信号线穿过某个接收器时（即信号线经过接收器所占的 3×3 区域），从接收器之后（远离信号塔的一侧）开始，信号线的颜色变为接收器的滤波色，直到遇到下一个接收器再次被调制，或到达网格边界。
  - 第三步——叠加：若同一个像素位置被多条信号线覆盖，保留后到达的信号线的颜色（即距离信号塔更远的信号线的颜色没有优先级区别——按信号塔在网格中从上到下、从左到右的顺序，后处理的信号塔的线覆盖先处理的）。

- `Key insight`：解题者需要先理解信号塔的广播机制（四方向射线），再发现接收器的调制作用（穿过后颜色改变），这两层规则叠加才能正确预测输出。接收器本身不改变形态，但它作为"颜色滤镜"改变了经过它的信号线后半段的颜色。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布着若干形状相同但大小不同的同构图形，根据图形内部"眼睛"标记的数量将它们分组，然后按组用不同颜色的外轮廓将同组图形连接起来。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干由 azure 像素绘制的封闭图形（每个图形由单像素宽的 azure 边界构成，内部为 black）。这些图形形状各异（如 L 形框、T 形框、矩形框等）。
  - 每个图形内部有若干 red 单像素点，称为"眼睛"。不同图形内部的"眼睛"数量为 1 到 4 不等。
  - 网格的最底行（或最右列）有一排颜色样本：从左到右依次为 green、yellow、orange、maroon 各一个像素，它们分别对应眼睛数量 1、2、3、4。

- `Rule`：
  - 第一步——分组：统计每个 azure 图形内部的 red 眼睛数量，将眼睛数量相同的图形归为一组。
  - 第二步——着色：根据底部颜色样本，为每组确定对应颜色（1 个眼睛 → green，2 个 → yellow，3 个 → orange，4 个 → maroon）。
  - 第三步——连线：同一组内的所有图形，按它们在网格中从左到右的顺序（若水平位置相同则从上到下），用该组对应颜色画一条单像素宽的曼哈顿路径（先水平后垂直的 L 形折线）连接相邻图形的中心点（图形包围盒的视觉中心）。连线绘制在 black 背景上，不覆盖 azure 图形本身（遇到 azure 像素则跳过）。
  - 保留所有原有的 azure 图形、red 眼睛和底部颜色样本。

- `Key insight`：解题者需要发现三层结构——首先识别"眼睛"数量作为分组依据（而非图形形状或大小），然后发现底部色带是分组到颜色的映射图例，最后理解同组图形之间的连线规则。任何一层的遗漏都会导致错误输出。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干彩色"印章"图案和一个灰色"画布"矩形区域，印章需要按照画布边缘的颜色指示条被盖印到画布上的对应位置，且印章之间存在遮挡优先级。

- `Input structure`：
  - 背景色为 black。
  - 画布：一个由 grey 像素填充的矩形区域（尺寸约 10×10 到 15×15），位于网格的中央偏下位置。
  - 画布的顶边外侧紧邻一排颜色标记像素（每个标记占一格，颜色各不相同），标记的水平位置各异。画布的左边外侧紧邻一列颜色标记像素，标记的垂直位置各异。顶边标记和左边标记的颜色一一配对（相同颜色恰好出现一次在顶边、一次在左边）。
  - 印章：网格中画布以外的区域散布着若干小型彩色图案（每个印章为 3×3 到 5×5 的非黑色像素组合），每个印章的主体颜色各不相同。每个印章的主体颜色与画布边缘某对标记的颜色相同。

- `Rule`：
  - 第一步——定位：每个印章的放置位置由其颜色对应的顶边标记（确定列坐标）和左边标记（确定行坐标）的交叉点决定。印章的左上角对齐到画布内部该交叉点对应的位置。
  - 第二步——排序与遮挡：印章按其面积（非 black 像素数量）从小到大的顺序依次盖印到画布上。面积小的先盖，面积大的后盖，因此大印章会遮挡小印章的部分区域。
  - 第三步——输出：输出仅包含画布区域（裁剪到画布的包围盒），画布上未被印章覆盖的位置保持 grey。

- `Key insight`：解题者需要先发现边缘标记的"行列交叉定位"机制（类似坐标系），再发现印章的遮挡顺序由面积决定——这两个规则分别控制"放哪里"和"谁在上面"，缺少任一层推理都无法得到正确结果。
</new_puzzle>
