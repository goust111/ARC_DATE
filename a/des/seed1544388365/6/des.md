- `Input structure`：背景为 black。网格上方有若干成对的小色块图例，每对图例由两个不同颜色的相邻实心小方块组成（例如 red-green 一对、blue-orange 一对），每对之间用一列 grey 分隔。网格下方有若干用 grey 线条围成的矩形框架，每个框架内部包含一个由某种颜色绘制的不规则碎片图案（碎片形状各异，占据框架内的部分格子），碎片颜色与某一对图例中的其中一个颜色相同。

- `Rule`：
  1. 对每个框架，找到其内部碎片的颜色，然后在上方图例区找到包含该颜色的那一对色块图例。

- `Key insight`：解题者需要先建立颜色配对关系（从图例中识别哪两个颜色是一对），再用这个配对关系完成颜色替换——配对关系本身是需要归纳的非显然结构，而不是简单的一一映射。

- `Input structure`：背景为 black。网格中有若干用不同颜色绘制的小型实心矩形对象（宽高均不超过 3 格），以及若干由两个像素组成的短线段（水平或垂直排列）。每条短线段的颜色与某个矩形对象的颜色相同，且每个矩形对象恰好有一条或多条与之同色的短线段。每条短线段的一端像素为该颜色，另一端像素为 maroon，maroon 端表示箭头的尖端方向（即移动方向）。

- `Rule`：
  1. 对每个矩形对象，找到所有与之同色的短线段。
  2. 每条短线段表示一次移动指令：从非 maroon 端指向 maroon 端的方向即为移动方向（上、下、左、右之一），移动距离固定为该矩形对象自身在移动方向上的边长。
  3. 如果一个对象有多条线段指令，按线段在网格中从上到下、从左到右的顺序依次执行。
  4. 擦除所有短线段，仅保留移动后的矩形对象。

- `Key insight`：短线段的方向编码需要识别 maroon 像素作为箭头尖端，这是一个非显然的方向解码层；移动距离与对象自身尺寸绑定而非固定常数，是第二个需要归纳的隐蔽规则。

- `Input structure`：背景为 black。网格中有若干用 grey 像素绘制的一像素宽的封闭轮廓，形成多个不同大小但形状可归类的封闭区域（例如正方形、L 形、T 形等，同一种形状可能出现不同大小的版本）。少数封闭区域内部已经被填上了一个彩色像素（称为颜色种子），每种形状类别恰好有一个区域包含种子。其余同类形状的区域内部为空（black）。

- `Rule`：
  1. 将所有封闭区域按形状分类——两个区域属于同一类当且仅当它们的轮廓形状在旋转和镜像下同构（忽略大小差异，仅看拓扑形状：正方形归正方形、L 形归 L 形等）。

  4. Grey 轮廓线保持不变。

- `Key insight`：解题者必须先完成形状分类（识别哪些区域是"同一种形状"），然后通过种子像素建立形状-颜色映射，最后执行填充——形状分类本身需要忽略大小、旋转和镜像的干扰，这是核心推理难点。

- `description`：将网格中多个带缺口的环形轮廓按缺口朝向排列成一条路径，路径方向由缺口的链式接续决定。

- `Input structure`：背景为 black。网格中散布着若干个大小相同的环形轮廓对象（每个环由某种颜色的像素组成，形成一个 5x5 的空心正方形框，但其中一条边的中间一个像素缺失，形成一个单像素缺口）。所有环的颜色相同（例如 green）。网格右下角有一个用 red 绘制的小型 1x1 像素标记。另外，网格左上角有一个用 azure 绘制的小型 1x1 像素标记。

- `Rule`：
  1. 输出网格的大小根据环的数量 N 确定：输出为 1 行 N 列（或 N 行 1 列，取决于路径方向）的排列结果，每个单元格为 5x5。
  2. 从 azure 标记最近的那个环开始，该环作为路径的第一个环。
  3. 该环的缺口朝向（上、下、左、右）决定下一个环的寻找方向：沿缺口方向找到最近的另一个环，将其作为路径的下一个。

  5. 输出时，将这些环按路径顺序从左到右紧密排列在一行中（去除原始间距），保持每个环自身的朝向不变。

- `Key insight`：缺口不仅是环的视觉特征，更是一个隐含的"指针"——每个环的缺口指向下一个环的位置，解题者需要发现这个链式指向关系才能确定正确的排列顺序。起点由 azure 标记确定，这是一个辅助但必要的信息。
</new_puzzle>

- `description`：将输入网格中的多层嵌套彩色边框拆解，按照嵌套深度将每层边框投射到输出网格的对应行中，形成一个深度-颜色编码的条形摘要。

- `Input structure`：背景为 black。输入网格包含多层嵌套的矩形边框，每层边框为一像素宽、由不同颜色绘制。最外层边框最大，逐层向内嵌套，每层与上一层之间间隔一格 black 空隙。最内层中心可能有一个实心彩色小方块（1x1 或 2x2）作为核心对象。网格中存在多组这样的嵌套结构（2-3 组），每组的层数可能不同，颜色组合也不同。

- `Rule`：
  1. 识别网格中每组独立的嵌套边框结构。
  2. 对每组结构，从外到内记录每层边框的颜色序列。如果存在核心对象，其颜色作为序列的最后一个元素。
  3. 输出网格的列数等于所有组中最大嵌套层数，行数等于组数。
  4. 在输出网格的第 i 行中，从左到右依次填入第 i 组结构的颜色序列（第 1 列 = 最外层颜色，第 2 列 = 次外层颜色，依此类推）。如果某组层数不足，剩余格子保持 black。

- `Key insight`：解题者需要完成两层推理：第一层是识别空间上的嵌套层级关系（哪个边框包含哪个边框），第二层是理解输出是一个将空间嵌套"展平"为线性序列的压缩映射——嵌套深度被编码为水平位置，而不同的嵌套组被编码为不同的行。

- `description`：用网格边缘的颜色标记行列定义一张隐式查找表，再根据前景对象所跨越的行列交叉颜色对其进行重新着色。

- `Input structure`：背景为 black。网格的最上方一行和最左方一列充当标记轴：顶行的每个格子填有某种颜色（从可用颜色中选取，可重复），左列的每个格子也填有某种颜色。这两条标记轴的交叉点（左上角）为 grey。网格内部（去除标记轴后的区域）散布着若干个用 grey 绘制的小型 4-连通实心对象（形状各异，每个对象占 2-5 个格子）。

- `Rule`：
  1. 对于网格内部的每个 grey 对象，找到该对象所占据的所有格子的行号和列号。
  2. 收集该对象所有格子对应的顶行标记颜色（按列号查）和左列标记颜色（按行号查）。
  3. 如果该对象所涉及的所有顶行标记颜色一致，且所有左列标记颜色也一致，并且这两个颜色相同，则将该对象重新着色为该颜色。
  4. 如果顶行和左列标记颜色不完全一致或二者不相同，则该对象保持 grey 不变。
  5. 标记轴保持不变。

- `Key insight`：边缘标记构成一个行列颜色查找表，但关键的隐蔽性在于"一致性条件"——只有当一个对象恰好完全落在标记颜色相同的行列交叉区域时才会变色，这要求解题者不仅理解查找表的存在，还要归纳出触发变色的一致性判定规则。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的"种子像素"沿其相邻模板对象的轮廓形状进行等比例生长，生成放大版的轮廓副本。

- `Input structure`：背景为 black。网格中有若干用不同颜色绘制的小型轮廓对象（每个对象为 3x3 大小的空心图案，例如空心方框、空心 L 形、空心十字等，由该颜色的像素描出边缘，内部为 black）。每个轮廓对象旁边（4-邻接方向上紧贴）有一个单独的彩色像素，称为"种子像素"，其颜色与旁边的轮廓对象不同。不同轮廓对象的种子颜色互不相同。

- `Rule`：
  1. 对每个种子像素，找到与之 4-邻接的轮廓对象。
  2. 将该轮廓对象的 3x3 图案以 2 倍比例放大为 6x6 图案（每个像素变为 2x2 的块）。
  3. 擦除原始的轮廓对象和种子像素。
  4. 将放大后的 6x6 图案放置在种子像素原来的位置，以种子像素所在的格子作为放大图案的锚点（锚点为放大图案中最靠近原轮廓对象方向的角）。放大图案使用种子像素的颜色绘制，而非原轮廓对象的颜色。

- `Key insight`：解题者需要发现三层关系：（1）种子像素与轮廓对象的配对关系（通过邻接），（2）放大操作的比例因子（从输入输出对比归纳为 2 倍），（3）放大后的着色使用种子颜色而非模板颜色——颜色来源的"反转"是核心隐蔽点。
</new_puzzle>
