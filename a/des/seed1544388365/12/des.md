- `description`：根据每个封闭区域内部散落像素的颜色，从色带图例中查找对应行，用该行的填充颜色覆盖整个区域。
- `Input structure`：网格以一种主背景色填充。左侧或顶部有一个竖直色带图例，每行由两列组成：左列是索引颜色，右列是填充颜色。网格主区域中有若干由 grey 像素围成的封闭区域（4-连通闭合边界），每个区域内部散落着恰好一种非背景、非 grey 的颜色像素（数量不等，但颜色唯一）。
- `Rule`：
  1. 识别所有由 grey 边界围成的封闭区域。
  2. 对每个区域，找到其内部散落像素的颜色 c。
  3. 在色带图例中找到左列颜色等于 c 的那一行，读取右列颜色 f。
  4. 将该区域内部所有背景像素替换为颜色 f，移除原来的散落像素（也替换为 f）。
  5. grey 边界和图例本身保持不变。
- `Key insight`：散落像素不是装饰，而是查表键——它的颜色在图例中映射到另一种颜色，该颜色才是区域的真正填充色。解题者需要先发现"区域内像素颜色 = 图例索引"这一非显然对应关系，再完成填充。
</new_puzzle>

- `description`：将网格中多个相同形状但内部图案各异的瓷砖，按照其缺失像素的位置进行互补拼合，输出一块完整无缺的合成瓷砖。
- `Input structure`：网格背景为 black。网格中排列着若干大小相同的矩形瓷砖（用 grey 分隔线隔开）。每块瓷砖内部有相同的几何轮廓（例如一个十字或 L 形），但每块瓷砖的轮廓上有若干像素被挖空（显示为背景色），且不同瓷砖被挖空的位置互不重叠。每块瓷砖的非挖空轮廓像素使用各自不同的颜色。
- `Rule`：
  1. 识别所有瓷砖，确认它们拥有相同的外形尺寸。
  2. 将所有瓷砖叠加：对于合成瓷砖中的每个位置，如果所有瓷砖中恰好有一块在该位置为非背景色，则输出该颜色；如果该位置在所有瓷砖中均为背景色，则输出背景色。
  3. 输出仅为一块瓷砖大小的网格，包含叠加后的完整图案。
- `Key insight`：每块瓷砖都是完整图案的一个"颜色通道切片"——各瓷砖的非空像素位置互斥且互补。解题者需要发现这些瓷砖共享一个隐含的完整形状，并且每块瓷砖恰好贡献了该形状中自己颜色对应的那部分像素。
</new_puzzle>

<new_puzzle>
- `description`：根据每个对象的孔洞数量决定其在输出网格中的排列层级，同一层级的对象按面积从小到大从左到右排列。
- `Input structure`：网格背景为 black。网格中散布着若干单色 4-连通前景对象，每个对象的颜色各不相同。部分对象内部有被前景像素完全包围的背景孔洞（孔洞数量为 0、1 或 2）。
- `Rule`：
  1. 对每个前景对象，计算其内部孔洞数量 h（被该对象的前景像素 4-连通包围的背景连通分量数）。
  2. 按 h 值将对象分组：h=0 的对象排在输出网格最上面一行区域，h=1 排在中间行区域，h=2 排在最下面行区域。
  3. 在每个行区域内，将对象按像素面积从小到大、从左到右排列，对象之间留一列背景间隔。
  4. 每个对象保留其原始形状和颜色，紧凑地贴到对应行区域的顶部。不同行区域之间留一行背景间隔。
- `Key insight`：对象的孔洞数量是一个需要主动识别的分类属性——它决定对象被放到哪一"层"；而面积排序则是每层内部的第二层规则。解题者必须先归纳出"孔洞数 = 行号"的对应，再归纳出"面积 = 列序"的对应。
</new_puzzle>

<new_puzzle>
- `description`：每个前景精灵内部的唯一异色像素既标记了旋转角度，又指定了目标画布上的粘贴位置，精灵需旋转后粘贴到画布对应位置。
- `Input structure`：网格背景为 black，分为左右两个区域（由一列 grey 分隔线隔开）。左侧区域包含若干独立的小型精灵（4-连通前景对象），每个精灵有一种主体颜色和恰好一个嵌入的异色像素（marker）。右侧区域是一个较大的空白画布（背景色），画布上散布着若干单像素标记点，每个标记点的颜色与左侧某个精灵的 marker 颜色一一对应。
- `Rule`：
  1. 对每个精灵，找到其 marker 像素，记录 marker 在精灵边界框内的相对位置（四个角之一：左上、右上、左下、右下）。
  2. marker 的相对位置编码了旋转角度：左上 = 0 度，右上 = 顺时针 90 度，右下 = 180 度，左下 = 顺时针 270 度。
  3. 在右侧画布上找到与该 marker 同色的标记点。
  4. 将精灵按编码的角度旋转后，以 marker 像素对齐标记点的位置，粘贴到画布上（marker 像素本身不绘制，仅用于定位）。
  5. 输出仅包含右侧画布区域。
- `Key insight`：marker 像素承担了双重角色——其颜色用于匹配目标位置，其在精灵中的角落位置编码了旋转方向。解题者需要同时发现颜色匹配规则和位置-旋转编码规则，二者缺一不可。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到被遮挡对象的完整形状，通过与未遮挡同色对象的形状比较来还原被遮挡部分，然后用遮挡色标记出被还原的像素。
- `Input structure`：网格背景为 black。网格中有若干单色 4-连通前景对象，颜色各不相同。某些对象成对出现（颜色相同），其中一个是完整的，另一个被另一种前景颜色的对象部分遮挡（遮挡对象覆盖在被遮挡对象之上）。未配对的对象（颜色唯一）不受影响。
- `Rule`：
  1. 按颜色将前景对象分组。只出现一次的颜色对应的对象保持不变。
  2. 对于出现两次的颜色，其中像素数较多的为完整参考对象，像素数较少的为被遮挡对象。
  3. 将完整参考对象的形状（边界框内的相对像素分布）平移对齐到被遮挡对象的位置：通过被遮挡对象已可见的像素与参考对象像素的重合关系确定对齐偏移量。
  4. 对齐后，参考对象中有而被遮挡对象中缺失的像素位置，即为被遮挡的像素。将这些被遮挡位置的颜色改为 yellow（标记色），同时保留该位置原本的遮挡对象颜色不变——即在遮挡对象之上叠加 yellow 像素。
  5. 完整参考对象从网格中移除（替换为背景色）。
- `Key insight`：解题者需要先发现"同色成对"的分组规则，再理解完整对象是残缺对象的模板，最后推断出"差集标黄、模板移除"的输出方式。三层推理环环相扣：分组 -> 模板对齐 -> 差集标记。
</new_puzzle>

<new_puzzle>
- `description`：网格中的箭头形状指向某个方向，箭头尾部的彩色条纹序列需沿箭头方向"射出"，在路径上重复铺展直到碰到网格边界。
- `Input structure`：网格背景为 black。网格中有若干由 grey 像素构成的箭头形精灵，每个箭头由一个三角形箭头尖（指向上、下、左、右四个方向之一）和一个矩形箭身组成。箭头尖为等腰三角形：若箭头指向右，则箭头尖为三行，中间行突出一个像素，上下两行各缩进一个像素；其余方向类推。箭身宽度为 1 个像素（沿箭头方向的长条）。箭身内部填充了一段由 2-4 种颜色组成的条纹序列（条纹方向与箭头指向垂直，即箭头指向左右时条纹为竖直单像素线条，箭头指向上下时条纹为水平单像素线条）。箭头尖部分仅由 grey 像素组成，内部无条纹。
- `Rule`：
  1. 识别每个箭头的指向方向 d（由三角形箭头尖的朝向决定）。
  2. 读取箭身内部的条纹颜色序列（从箭尾到箭头方向依次读取）。
  3. 从箭头尖端的前方一个像素开始，沿方向 d 逐步绘制条纹：每一步绘制一个与条纹等宽的像素（颜色按序列循环），直到到达网格边界。
  4. 箭头本身（grey 像素和内部条纹）保持不变。
- `Key insight`：箭头同时编码了两个信息——方向和"子弹"的颜色模式。解题者需要先识别箭头方向，再发现箭身条纹是一个需要周期性延伸的颜色模板，而非静态装饰。
</new_puzzle>

<new_puzzle>
- `description`：网格中每个矩形框内的小图案需要根据框边框颜色在色环上的位置进行颜色循环替换。
- `Input structure`：网格背景为 black。网格中有若干不重叠的矩形边框，每个边框由单一颜色的像素绘制（宽度为 1 像素），不同边框颜色不同，框内有一个由多种前景色组成的小图案（图案不接触边框）。网格某个角落有一个单行的色环图例：由 N 个不同颜色的像素排成一横排，表示一个循环色序（首尾相接）。色环图例中的颜色包含了所有边框颜色和所有图案中出现的颜色。
- `Rule`：
  1. 读取色环图例，记录颜色的循环顺序，假设为 c_0, c_1, ..., c_{N-1}。
  2. 对每个矩形边框，确定其边框颜色在色环中的位置索引 k。
  3. 将框内图案中出现的每种颜色，在色环中向后偏移 k 个位置（循环取模），得到新颜色。
  4. 用新颜色替换框内对应像素。边框本身颜色不变，背景不变，色环图例不变。
- `Key insight`：边框颜色不仅是装饰——它在色环中的位置决定了一个偏移量，该偏移量作用于框内所有颜色的循环替换。解题者需要先发现色环的存在和顺序，再发现边框颜色 = 偏移键的映射关系，最后将两者组合完成颜色变换。
</new_puzzle>
