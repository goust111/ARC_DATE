- `description`：根据封闭区域内部标记色的种类数选择对应的边框模板，用该模板的形状重绘区域边框。

- `Input structure`：
  - 背景色为 black，网格中散布若干由单一颜色绘制的封闭矩形边框（边框宽一像素）。
  - 每个矩形边框内部可能包含零个或多个不同颜色的单像素标记点（标记色与边框色、背景色均不同）。
  - 网格的最上方一行排列着若干小型"模板边框"，每个模板边框由不同颜色绘制，形状各异（普通矩形、缺角矩形、带缺口矩形等），且模板按从左到右的顺序分别对应"内部有 1 种标记色""内部有 2 种标记色""内部有 3 种标记色"……依此类推。没有标记色（0 种）的边框保持原样不变。

- `Rule`：
  - 首先识别最上方一行中的模板边框序列，按从左到右的排列顺序编号为 1、2、3……
  - 对网格中每个非模板的封闭矩形边框，统计其内部包含多少种不同的标记颜色，得到数量 N。
  - 若 N = 0，该边框保持不变。
  - 若 N >= 1，取第 N 个模板边框的形状（归一化到相同尺寸），用该形状替换当前边框的边界像素：将模板形状缩放到当前边框的实际尺寸，保留边框原有颜色，但边界的形状改为模板的形状（例如模板右上角缺一个像素，则当前边框右上角也去掉一个像素）。
  - 内部标记点保持不变。

- `Key insight`：模板的选择不取决于标记的颜色本身，而取决于标记颜色的种类数；模板排列顺序隐含了数量到形状的映射关系，解题者需要先发现"数种类数"这一步，再发现"模板按序号对应"这一步。
</new_puzzle>

- `description`：将散落的彩色路径片段按颜色分组，每组内部根据片段端口朝向拼接成完整路径，再将完整路径投射到对应颜色标记的输出区域中。

- `Input structure`：
  - 背景色为 black。
  - 网格分为左右两个区域，由一列 grey 像素分隔。
  - 左侧区域包含若干彩色路径片段：每个片段由 2-4 个同色像素组成的直线段（水平或垂直），不同颜色的片段互不接触。同一颜色可能有多个片段散布在左侧不同位置。
  - 每个片段的一端有一个 maroon 像素紧邻（上下左右之一），表示该片段的"接口端"。
  - 右侧区域有若干小矩形框（由 grey 边框围成），每个框内部左上角有一个单像素的颜色标记，标记颜色恰好对应左侧某种片段颜色。框内部其余像素为 black。

- `Rule`：
  - 对于每种颜色，收集左侧所有该颜色的片段。
  - 将同色片段按"接口端对接口端"的方式首尾拼接：第一个片段的非接口端为起点，接口端连接第二个片段的接口端，第二个片段的非接口端再连接第三个片段的接口端，依此类推。拼接顺序由片段在左侧区域中从上到下、从左到右的出现顺序决定。
  - 拼接后得到一条折线路径。将该路径的起点对齐到右侧对应颜色标记框内部的左上角（标记像素的正下方一格），然后在框内绘制该路径，使用该颜色填充路径经过的像素。
  - 颜色标记像素本身保持不变。

- `Key insight`：左侧片段的 maroon 接口标记指示了拼接方向，而片段的空间排列顺序决定了拼接次序；解题者必须同时理解"接口端决定朝向"和"空间顺序决定拼接序"两层规则，才能在右侧框中正确还原完整路径。
</new_puzzle>

- `description`：用网格边缘的颜色箭头指示的方向对每行或每列的非背景像素进行循环移位，移位量由同行或同列对侧边框上的标记像素数量决定。

- `Input structure`：
  - 背景色为 black，网格内部有一个由多种颜色组成的图案。
  - 网格的最外一圈像素（第 0 行、最后一行、第 0 列、最后一列）构成"控制边框"，控制边框中大部分像素为 grey。
  - 控制边框上某些位置有彩色箭头标记：箭头由 3 个同色像素组成，呈 L 形排列，L 形的朝向指示方向（向右：一个像素在左，两个像素在右侧上下排列；向下：一个像素在上，两个像素在下方左右排列；向左和向上类推）。
  - 箭头出现在某一行的左端或右端边框上，表示该行需要水平移位；箭头出现在某一列的上端或下端边框上，表示该列需要垂直移位。
  - 在同一行或同一列的控制边框另一端，可能有若干 azure 单像素标记。

- `Rule`：
  - 对于每个箭头，确定它控制的行或列，以及移位方向（由 L 形朝向决定）。
  - 统计该行或列的控制边框对侧（即箭头不在的那一端）上 azure 标记像素的数量 K。
  - 将该行或列内部（不含边框）的所有非背景像素沿箭头方向循环移位 K 步（像素移出一端后从另一端回来）。背景像素不参与移位，只有非背景像素的位置发生变化。
  - 没有箭头的行/列保持不变。控制边框本身从输出中移除，输出网格仅包含内部区域。

- `Key insight`：箭头的 L 形朝向编码了移位方向，而移位量并非来自箭头本身，而是来自同一行/列对侧边框上的 azure 标记数量。解题者需要分别识别"方向来源"和"步数来源"位于边框的两端这一空间分离关系。
</new_puzzle>

- `description`：在网格中找到被遮挡的矩形层叠顺序，根据层叠关系由底到顶重新分配颜色深浅。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干部分重叠的实心矩形，每个矩形使用不同的颜色。
  - 当两个矩形重叠时，前景矩形的像素覆盖背景矩形的像素（即像画家算法一样，后绘制的在上面）。
  - 网格右侧有一列从上到下排列的单像素色块，颜色依次为 red、orange、yellow、green、blue（具体颜色数量与矩形数量相同），作为"深浅色板"。

- `Rule`：
  - 首先通过观察重叠遮挡关系推断矩形的层叠顺序：如果矩形 A 的边缘被矩形 B 打断（即 A 的完整矩形形状被 B 遮挡了一部分），则 A 在 B 下方。利用所有这样的遮挡对关系确定从底（最下层）到顶（最上层）的完整排序。
  - 然后读取右侧色板从上到下的颜色序列。
  - 将层叠顺序中最底层的矩形重绘为色板第一个颜色（最上方），第二底层重绘为色板第二个颜色，依此类推，最顶层矩形重绘为色板最后一个颜色（最下方）。
  - 重绘时保持遮挡关系不变：仍然是上层矩形遮挡下层矩形，只是每个矩形的颜色按层叠深度被替换为色板中对应位置的颜色。
  - 右侧色板在输出中移除。

- `Key insight`：解题者需要先通过视觉遮挡线索（哪个矩形的边缘被截断）推断出不可见的层叠深度顺序，这是第一层推理；然后理解色板从上到下的排列对应从底到顶的层叠顺序，完成颜色重映射，这是第二层推理。矩形的原始颜色与最终颜色没有任何对应关系。
</new_puzzle>

- `description`：根据每个封闭区域的"出口"数量，从区域中心向每个出口方向发射对应长度的射线。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干由 grey 像素绘制的一像素宽的封闭矩形框。
  - 每个矩形框的边上有若干"出口"：即边框上缺失一个像素的位置（该位置为 black 而非 grey）。
  - 每个矩形框的正中心有一个彩色像素（颜色各不相同），作为该区域的"源点"。
  - 矩形框内部其余像素为 black。

- `Rule`：
  - 对每个矩形框，统计其边上的出口总数 N。
  - 找到每个出口的位置，确定出口相对于框中心的方向（上、下、左、右之一，取出口所在边的朝向）。
  - 从中心源点出发，向每个出口的方向绘制一条直线射线，射线长度为 N 个像素（不含源点本身），使用源点的颜色。射线穿过框的边界和出口向外延伸。
  - 如果射线经过 grey 边框像素（非出口位置），该 grey 像素被射线颜色覆盖。
  - 源点本身保持不变，框的其余 grey 像素保持不变。

- `Key insight`：射线的方向由出口位置决定，但射线的长度由出口的总数决定——这意味着出口越多的框，每条射线反而越长。解题者需要发现"出口数量同时决定射线条数和射线长度"这一双重角色，这是核心的非显然规律。
</new_puzzle>

- `description`：将嵌套方框的层级结构"展开"为水平排列的独立方框序列，每个方框的大小和颜色保持不变。

- `Input structure`：
  - 背景色为 black。
  - 输入网格中有若干同心嵌套的矩形边框（每个边框宽一像素），从外到内每层使用不同的颜色。
  - 相邻两层边框之间间隔恰好一个像素（即内层边框与外层边框之间有一像素宽的 black 间隙）。
  - 最内层边框内部可能有一个实心的小矩形（也是某种颜色）。

- `Rule`：
  - 从外到内依次识别每一层边框及其颜色和尺寸。
  - 构造输出网格：高度等于最外层边框的高度，宽度为所有层的宽度之和再加上层与层之间各一列 black 间隔。
  - 将每层边框按从外到内的顺序从左到右水平排列在输出网格中：最外层边框画在最左边，次外层画在其右边（间隔一列 black），依此类推。
  - 每层边框在输出中垂直居中对齐（相对于输出网格的高度居中）。
  - 如果最内层是实心矩形而非边框，同样作为最右边的一个元素输出。

- `Key insight`：解题者需要识别出"嵌套"结构并理解它是一种压缩的序列表示——同心嵌套的层级关系被"展开"为从左到右的空间序列。核心洞见在于嵌套深度映射为水平位置，而每层的几何属性（大小、颜色）在展开后保持不变。
</new_puzzle>

- `description`：根据每个彩色区域与底部"种子图案"的形状匹配结果，决定对该区域执行保留、旋转还是翻转操作。

- `Input structure`：
  - 背景色为 black。
  - 网格底部有三个并排的小方框（由 grey 边框围成），每个方框内部包含一个用不同颜色绘制的小图案（3x3 以内），这三个图案分别作为"保留模板""顺时针旋转 90 度模板"和"水平翻转模板"——三个方框从左到右分别对应这三种操作。
  - 网格上方散布着若干较大的彩色连通区域（每个区域由单一颜色构成），每个区域的形状在归一化（裁剪出最小包围矩形后平移到原点）后恰好与三个模板之一的归一化形状完全相同（可能需要旋转 0/90/180/270 度才能匹配）。

- `Rule`：
  - 将每个上方区域的形状归一化后与三个模板的归一化形状进行匹配（允许旋转 0/90/180/270 度匹配）。
  - 匹配到第一个模板（"保留模板"）的区域：保持原位不变。
  - 匹配到第二个模板（"旋转 90 度模板"）的区域：以该区域最小包围矩形的中心为旋转中心，将整个区域顺时针旋转 90 度。
  - 匹配到第三个模板（"水平翻转模板"）的区域：以该区域最小包围矩形的垂直中轴线为轴进行水平翻转。
  - 底部的模板方框在输出中保持不变。

- `Key insight`：模板本身不是直接描绘操作方式的图标（如箭头），而是通过形状匹配来分类——解题者先要发现上方区域与底部模板之间的形状对应关系（第一层），再要推断每个模板位置代表何种变换操作（第二层）。模板匹配时需要考虑旋转等价性增加了匹配的难度。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中隐藏的"印章-印泥"配对关系，将印章形状用印泥颜色盖印到由锚点指定的位置。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干彩色连通对象，分为三类角色：
    - "印章"：较大的单色连通区域（面积 >= 4 像素），形状不规则。
    - "印泥"：2x2 的实心小方块，颜色与任何印章颜色不同。
    - "锚点"：单个像素，颜色与某个印泥颜色相同。
  - 每个印章恰好与一个印泥在四连通方向上相邻（即印章的某个像素与印泥的某个像素上下左右紧邻）。
  - 每个印泥的颜色在网格中恰好有一个对应的锚点。

- `Rule`：
  - 通过四连通邻接关系将每个印章与其相邻的印泥配对。
  - 对于每个配对：找到与印泥同色的锚点位置。
  - 将印章的形状（保持朝向不变）平移，使印章中距离印泥最近的那个像素对齐到锚点位置。
  - 用印泥的颜色（而非印章的原始颜色）在新位置绘制印章的形状。
  - 清除原始印章和印泥的像素（变为 black），保留锚点像素。

- `Key insight`：解题者需要发现三层关系：（1）通过邻接发现印章-印泥配对；（2）通过颜色匹配发现印泥-锚点的远程对应；（3）理解印章以印泥颜色而非自身颜色被"盖印"到锚点位置。印章的原始颜色仅用于区分不同印章，不出现在输出中。
</new_puzzle>
