<description>
Invert each row's native foreground color against the black background.

Input structure
- A black-background grid whose rows each have one native foreground color plus optional distractor colors.
- The native row color is the most frequent non-bg color in that row; if tied, its run starts leftmost among tied colors.

Rule
- For each row independently, turn pixels of the native row color into bg.
- Turn every other pixel in that row, including bg and distractor colors, into the native row color.

Key insight
- Distractor colors are not preserved objects; they mark cells that participate in the binary complement of the row's native color.
</description>

<description>
Add a quantity-color label in the top marker column for each horizontal bar.

- Below the marker row, every non-empty source row contains one solid monochrome horizontal bar to the left of the marker column.
- Source rows are staggered every other row.

Rule
- Copy the input grid.
- For each source bar, read its quantity as the bar length.
- Paint the quantity color in the marker column on the same row as the bar:
  2->1, 3->4, 4->9, 5->6.

Key insight
- The grey marker supplies the result column, while each bar supplies a small quantity with a fixed color code.
</description>

<reference_puzzle index="3" source="train" puzzle_id="54dc2872" lines="52-69">
<description>
Move each marked L-shaped sprite onto the separate pixel matching its marker color.

Input structure
- The background is the dominant color.
- Foreground has 4-connected multicolor sprites and isolated one-pixel controls.
- Each sprite has one repeated body color in an L shape plus one embedded marker
  pixel of a different color.

Rule
- If the embedded marker color also appears as a separate isolated control pixel,
  translate the whole sprite so the body L-bend lands on that control pixel.
- Clear each moved sprite from its old position, clear its consumed control pixel,
  then paste all translated sprites; sprites without a matching control stay put.

Key insight
- The marker color pairs a sprite with its destination control, while the L-bend
  gives the orientation-independent anchor cell to place on that destination.
</description>
</reference_puzzle>

<reference_puzzle index="4" source="train" puzzle_id="d968ffd4" lines="15-28">
<description>
Extend each of two aligned rectangular marker objects toward the other, filling half of the gap across the full perpendicular span.

Input structure
- A dominant background contains exactly two solid, same-sized monochromatic rectangles.
- The rectangles share either the same row span or the same column span, with a background gap between their facing edges.

Rule
- If the rectangles are side-by-side, color the left half of the inter-object gap across every row with the left object's color, and the right half with the right object's color.
- If one rectangle is above the other, color the upper half of the gap across every column with the upper object's color, and the lower half with the lower object's color.
- When the gap length is odd, leave the center row/column as background.

Key insight
- The marker objects are endpoints of an axial corridor; their own size identifies the facing edge, while the filled corridor spans the whole grid perpendicular to that axis.
</description>
</reference_puzzle>

<reference_puzzle index="5" source="eval" puzzle_id="31f7f899" lines="7-21">
<description>
Sort vertical bars by height and redistribute them across fixed colored slots.

Input structure:
- bg background; a horizontal base line of a single color spans the full grid width.
- Several monochrome vertical bars of distinct colors rise upward from the base line.

Rule:
- Rank bar shapes by height (shortest to tallest).
- Rank original x-positions (slots) left to right.
- Place the i-th shortest shape into the i-th leftmost slot, recoloring it to that slot's original color.
- The base line is preserved unchanged.

Key insight: Each slot keeps its x-position and color identity; only the bar silhouettes are redistributed among slots by height order.
</description>
</reference_puzzle>

<reference_puzzle index="6" source="eval" puzzle_id="4a21e3da" lines="8-20">

Cut a sprite along border-control rays and slide pieces to grid corners.

Rule:

- Rays partition the grid; fg on the cut line stays in place.
- Cut pieces in regions touching a control edge slide to that corner; others vanish.

Key insight: Only regions sharing a border edge with a control pixel keep their piece; the ray skips fg cells.

<reference_puzzle index="13" source="eval" puzzle_id="7b3084d4" lines="253-266">
<description>
Assemble colored rectangular sprites into a single tiled rectangle, anchored by a marker pixel.

Input structure:
- bg = most common color. Several solid-colored rectangular sprites scattered on the grid.
- One sprite has a unique single-pixel marker (different color) at one corner — this is the anchor.

Rule:
- Identify the anchor sprite (contains the marker pixel) and the remaining pieces.
- Rotate the anchor so the marker pixel lands at position (0,0) of the output.
- Pack all remaining pieces (allowing 90° rotations) to tile a complete rectangle with no gaps.

Key insight: The lone marker pixel picks the anchor and fixes the output orientation — it must sit at the top-left corner.
</description>

<reference_puzzle index="14" source="train" puzzle_id="52df9849" lines="49-67">
<description>
Complete each partially hidden simple foreground shape by recoloring the occluding pixels in its footprint.

Input structure
- The grid has a dominant background and several solid foreground shapes.
- Some shapes are partially hidden by other foreground colors, but their full
  footprint is still indicated by a foreground-filled bbox or by a foreground-
  filled 45-degree diagonal line.

Rule
- For each foreground color, complete its full rectangular bbox when that bbox
  contains no background and includes other colors.
- Otherwise, complete its 45-degree diagonal line when all visible pixels lie
  on that line and the hidden line cells are foreground, not background.
- Recolor only those hidden footprint pixels; leave all other pixels unchanged.

Key insight
- The occluded cells are exactly the non-background cells inside a simple
  shape's implied footprint, so completing shapes is a local recoloring problem.
</description>
</reference_puzzle>

<reference_puzzle index="15" source="train" puzzle_id="c6141b15" lines="84-95">
<description>
Swap a connector segment with repeated marker sprites by connecting the marker anchors and stamping the sprite at the segment endpoints.

Input structure
The grid has one background color and exactly two foreground colors. One foreground color forms a single straight 8-connected segment. The other foreground color forms two or more identical centered sprites.

Rule
Build a background canvas of the same size. Draw straight connector-color segments between every pair of original sprite anchors. Then stamp the marker sprite, using its centered anchor, onto the two endpoints of the original connector segment.

Key insight
The original segment endpoints are the destinations for the repeated sprite, while the original sprite centers become the vertices of the new connector-color complete graph.
</description>
</reference_puzzle>

<reference_puzzle index="16" source="train" puzzle_id="78e78cff" lines="71-91">
<description>
Recolor the row-wise passage indicated by wall pixels with the singleton marker color.

Input structure:
- A dominant background contains one singleton marker pixel and one wall color.
- Wall pixels lie on several rows and form left/right limits around the marker column.
- Empty rows between the top and bottom wall rows are open horizontal passages.

Rule:
- On a wall row, paint background pixels between the nearest wall strictly
  left of the marker column and the nearest wall at or right of it; if only
  one side is present, paint from that wall to the opposite grid edge.
- On empty rows between the top and bottom wall rows, paint the whole row.
- On empty rows outside the wall-row band, reuse the nearest end wall-row interval.
- Preserve wall pixels and the original marker pixel.

Key insight:
- The wall color defines scanline limits relative to the marker column; the
  marker color fills those implied horizontal spans rather than flood-filling
  through connected background.
</description>
</reference_puzzle>

<reference_puzzle index="17" source="train" puzzle_id="753ea09b" lines="60-79">
<description>
Fill the small background compartments bounded by the long contour color.

Input structure:
- The grid has one dominant background color and two foreground colors.
- The more frequent foreground color forms long 8-connected contour fragments.
- The other foreground color is a fixed distractor/obstacle color that partitions
  the background but is never recolored.

Rule:
- Split the background into 4-connected regions using all foreground pixels as
  barriers.
- Keep the two largest background regions as the outside of the contour drawing.
- Recolor every other background region that touches a long contour component
  to the contour color; leave all foreground pixels unchanged.

Key insight:
The apparent area fill is exactly a component-level fill of bounded background
compartments, not a row-wise interpolation between individual contour pixels.
</description>

<reference_puzzle index="18" source="train" puzzle_id="bd283c4a" lines="7-23">
<description>
Pack all pixels into color-frequency runs along bottom-up columns.

Input structure
The input is a rectangular grid whose colors are all foreground material;
only the number of pixels of each color matters. In the observed task
instances, every present color has a distinct pixel count.

Rule
Count the pixels of each color and order the colors from most frequent to
least frequent. Rewrite a same-size grid by placing each color's full count
as one contiguous run while scanning columns from left to right and, within
each column, from bottom to top.

Key insight
The output preserves the multiset of colors but discards all original
positions, turning the grid into a frequency-sorted column packing.
</description>

<description>
Repack each non-background color group as a solid square ordered by increasing size.

Input structure
The grid has one dominant background color, and each other color has a
perfect-square pixel count. Those square side lengths are unique.

Rule
Convert every non-background color into a filled square whose side length is
the square root of its pixel count. Place the squares from left to right in

The original geometry of each color is discarded; only the color's total
pixel count determines the size of its packed output square.

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式等人类能够直观感受计算的内容。
   - **不建议使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算 / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数等复杂且不易被看出来的计算。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息（例如颜色id是不可用的）或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 5 个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
8. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
9. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。以两层结构为例：
   - ✗ 伪两层："找到缺口方向"→"把东西推到对面" — 第一步肉眼可见，实际只有一层推理。
   - ✓ 真两层："通过孔洞数量匹配颜色图例"→"用匹配到的颜色重绘对象" — 两步都需要非平凡的归纳。

   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
10. 在符合ARC题目和提示词要求的基础上，鼓励尝试创新规则为多层结构的题目，不局限于两层，可以创新三层或四层结构的题目，但不可为了多结构层数违背要求。

生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述参考题相同或类似，不可只是替换颜色、方向、对象类型等表层要素。判断标准：新题的核心推理路径应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。
