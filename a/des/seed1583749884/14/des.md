- `description`：在由连接线组成的网络中，将每个节点的颜色传递给通过连接线可达的下游节点，上游节点保留原色，下游节点接收混合后的颜色。

- `Input structure`：
  - 背景为 Azure。
  - 网格中有若干个 2x2 的彩色实心方块作为"节点"（使用 Red、Blue、Green 等颜色）。
  - 节点之间由 Grey 的一像素宽正交线段连接。每条连接线上有一个 Maroon 箭头标记（占一像素，位于连接线的中间位置附近），箭头的相对位置指示信息流动方向（箭头偏向目标节点一侧）。

- `Rule`：
  - 对每条连接线，根据 Maroon 箭头标记的位置确定信息流动方向：从远离箭头的节点（源）到靠近箭头的节点（目标）。
  - 每个目标节点接收其所有源节点颜色中面积最大（在源节点中像素数最多）的颜色，并用该颜色替换自身。
  - 没有入边的节点保持原色不变。
  - 连接线和箭头标记保持不变。

- `Key insight`：Maroon 箭头像素的偏移方向编码了信息流方向；颜色传递基于"面积最大的源"选择——两层规则需要分别归纳。
</new_puzzle>

<new_puzzle>
- `description`：将每个对象的形状"压扁"到其 bbox 的较短边上，形成一条与较短边等长的色条，色条的颜色密度反映原对象在该方向上的像素覆盖率。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干个 4-连通单色前景对象（使用不同颜色如 Red、Blue、Green），每个对象的 bbox 为非正方形矩形。

- `Rule`：
  - 对每个对象，确定其 bbox 的短边方向。
  - 将对象沿长边方向"投影"到短边上：对短边上的每个位置，数出该行/列上对象占据的像素数 K 和 bbox 长边长度 L。
  - 如果 K == L（该行/列全部被对象覆盖），在输出中该位置绘制对象的原色。
  - 如果 K < L 但 K > 0（部分覆盖），在输出中该位置绘制 Grey。
  - 如果 K == 0（无覆盖），在输出中该位置为背景色。
  - 输出中每个对象的投影色条放置在原始 bbox 的短边位置上。清除原始对象的其他像素。

- `Key insight`：对象被降维为一维投影，覆盖率决定了是原色还是 Grey——这是一种从二维形状到一维密度摘要的压缩。
</new_puzzle>

- `description`：在每个被框包围的区域中，根据框的颜色在图例中查找对应的旋转角度，然后将框内部的图案旋转该角度。

- `Input structure`：
  - 背景为 Black。
  - 网格左上角有一个小的颜色-旋转图例：3-4 行，每行包含一个颜色色块和旁边的旋转标记（0/1/2/3 个 Yellow 点，分别代表旋转 0/90/180/270 度）。
  - 网格中有若干个由不同颜色的一像素厚矩形边框围成的区域，框内部包含一个 Grey 像素绘制的小型图案。

- `Rule`：
  - 对每个彩色框，在图例中找到与框颜色匹配的行，读取其旋转标记中的 Yellow 点数量 N。
  - 将框内部的 Grey 图案顺时针旋转 N * 90 度。
  - 保持框边缘和图例不变。

- `Key insight`：框的颜色不影响内部图案的颜色，而是通过图例间接编码了旋转角度——颜色是"查找键"而非"着色指令"。
</new_puzzle>

- `description`：将散落在网格中的方向箭头精灵作为指令，按指令顺序将一个移动对象逐步平移，最终输出对象的终点位置。

- `Input structure`：
  - 背景为 Black。
  - 网格中有一个 Red 的 2x2 实心方块作为"移动对象"，位于网格的某个位置。
  - 网格中散布着若干个由 3 像素组成的箭头精灵（使用 Green 颜色），每个箭头由一个"头部"像素和两个"尾部"像素组成，形成指向上/下/左/右的箭头形状（头部像素在尾部的前方）。
  - 每个箭头精灵旁边有一个 Yellow 单像素数字标记，标记值为 1-4 的数量（即旁边有 1-4 个 Yellow 像素紧密排列）。

- `Rule`：
  - 按 Yellow 数字标记从小到大的顺序处理箭头（标记 1 先执行，标记 2 其次，以此类推）。
  - 对每个箭头，将移动对象沿箭头指向的方向平移 2 格。
  - 清除所有箭头和数字标记为背景色。
  - 清除移动对象的原始位置为背景色，仅在最终位置绘制 Red 方块。

- `Key insight`：箭头编码方向，Yellow 标记编码执行顺序——两层信息共同决定了移动路径；解题者需要先发现顺序编码，再理解方向和步长的固定规则。
</new_puzzle>

<new_puzzle>
- `description`：根据每个对象与最近网格边缘的距离，选择将其放大（距离远）或缩小（距离近），放大/缩小后的对象放置在原 bbox 中心。

- `Input structure`：
  - 背景为 Azure。
  - 网格中有若干个 4-连通单色前景对象（使用不同颜色），每个对象为简单形状（矩形或 L 形），面积为 2-6 像素。
  - 对象分布在网格各处，距离网格边缘的最近距离各不相同。

- `Rule`：
  - 对每个对象，计算其 bbox 到最近网格边缘的距离（bbox 边缘到网格边缘的最小像素间隔）D。
  - 如果 D >= 3（距离远，位于中心区域）：将对象的每个像素扩展为 2x2 的方块（放大 2 倍），以原 bbox 中心为基准放置。
  - 如果 D < 3（距离近，位于边缘区域）：将对象缩小为其 bbox 的中心像素（仅保留 bbox 中心的一个像素）。
  - 清除原始对象的其他像素为背景色。

- `Key insight`：距离阈值将对象分为两类并应用不同变换——解题者需要发现"与边缘的距离"这个隐含的分类标准及其对应的放大/缩小操作。
</new_puzzle>
