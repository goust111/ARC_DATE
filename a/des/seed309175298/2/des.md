- `description`：将网格中散落的彩色路径段按颜色接力拼接，形成一条从起点标记到终点标记的连续路径，路径段之间的空隙用各段颜色的"握手协议"桥接填充。

- `Input structure`：
  - 背景为 Black。网格上有一个 Green 单像素标记（起点）和一个 Red 单像素标记（终点）。
  - 网格中散布着若干条由不同颜色像素组成的短路径段（每段 3-6 像素长，水平或垂直）。每条路径段是单色的，可能的颜色包括 Blue、Yellow、Orange、Azure、Magenta。
  - 每条路径段的两端各有一个"端口像素"：该端口像素的颜色与相邻下一段路径的颜色相同（即端口颜色提示了应该连接哪一段）。
  - 起点 Green 像素的一个四邻居方向上紧邻第一段路径的端口颜色像素。终点 Red 像素同理紧邻最后一段路径。

- `Rule`：
  - 从起点出发，找到与起点相邻的第一段路径（通过端口颜色识别）。
  - 沿该路径段走到另一端的端口像素，端口像素的颜色指示下一段路径的颜色。在网格中找到具有该颜色的路径段中，其某一端口颜色与当前段颜色匹配的那一段（双向握手匹配）。
  - 将两段路径之间的空隙（沿直线方向的 Black 像素）填充为当前段的颜色。
  - 依次拼接所有路径段直到到达终点。
  - 输出为完整连通路径，起点和终点标记保留。

- `Key insight`：端口颜色构成双向握手协议——当前段末端的端口颜色指向下一段的主体颜色，而下一段对应端的端口颜色必须等于当前段的主体颜色，这样才能唯一确定连接顺序。解题者需要发现这一对称匹配机制才能正确排列路径段。
</new_puzzle>

- `Key insight`：解题者需要两层推理——第一层是意识到隐藏图案与参考图案存在刚性变换关系（而非任意不同的图案），第二层是利用孔洞处有限的可见像素作为约束条件，排除不可能的变换方式，锁定唯一正确的变换。孔洞的数量和位置经过精心设计，使得仅一种变换与所有可见像素一致。

  - 网格中有一个孤立的 Maroon 单像素标记，位于所有嵌套组之外。

- `Rule`：
  - 对于每组嵌套矩形，识别所有嵌套层级（从最内层到最外层编号为第 1 层、第 2 层...）。

  - 观察该嵌套组与 Maroon 标记的相对位置：如果 Maroon 标记位于该组的上方或左方，则序列正序（从左到右）对应从内到外；如果 Maroon 标记位于该组的下方或右方，则序列逆序（从右到左）对应从内到外。
  - 将每层 Grey 边框重新着色为对应位置的颜色。如果颜色数量少于嵌套层数，未分配颜色的层保持 Grey 不变。
  - 最内层中心的彩色像素序列在输出中被移除（替换为 Black）。

- `Key insight`：解题者需要先识别出"最内层中心的像素序列是着色指令"这一非显然关系（第一层推理），然后发现 Maroon 标记的空间位置决定了序列的读取方向（正序或逆序）——这是第二层推理。关键隐蔽性在于：所有边框初始都是同色 Grey，且 Maroon 标记看似与嵌套组无关，解题者需要将其与着色方向关联起来。

- `Input structure`：
  - 背景为 Black。网格上有若干个（3-5 个）大小相同的矩形"窗口"，每个窗口由 Grey 边框围成，内部尺寸相同（如 5x5 或 6x6）。

  - 每个窗口的 Grey 边框的某一条边上有一个由 Azure 像素标记的小偏移指示器：在边框顶边或左边上的 1-2 个连续 Azure 像素，其位置（距边框角的像素数）表示该窗口的行/列偏移量。顶边的 Azure 标记表示列偏移，左边的 Azure 标记表示行偏移。

  - 存在一个隐藏的母版图案，尺寸大于窗口内部尺寸。每个窗口展示的是母版图案在特定行列偏移下的裁剪视图。

  - 输出为每个窗口内部图案的补全版本：对于每个窗口，用母版图案在对应偏移下的完整裁剪视图替换原来的残缺视图。窗口边框和 Azure 标记保持不变。

- `Key insight`：解题者需要三层推理——第一层是发现所有窗口展示的是同一母版的不同局部（通过观察重叠区域的一致性）；第二层是发现边框上的 Azure 标记编码了偏移量（而非装饰）；第三层是利用偏移量将所有窗口的已知像素拼合到统一坐标系中，从而推断出每个窗口缺失的像素。

- `description`：网格中的彩色"印章"对象沿 Grey 轨道滑动并在轨道的 Maroon 标记处发生颜色转换，最终在终点位置停止，留下分段变色的轨迹。

- `Input structure`：
  - 背景为 Black。网格中有若干独立的"印章-轨道"组合。
  - 每个印章是一个 2x2 的纯色小方块（颜色可为 Red、Blue、Yellow、Orange），位于其对应轨道的起始端。
  - 每条轨道由 Grey 像素组成，宽度为 1 像素，形成一条从印章位置出发的折线路径（仅包含水平和垂直段，在转角处呈直角弯折）。轨道的末端有一个与印章初始颜色相同的单像素标记，表示终点。
  - 每条轨道上有若干 Maroon 像素散布在 Grey 像素之间，这些是"变色标记"。

- `Rule`：
  - 印章沿轨道从起始位置向终点方向滑动。印章的左上角沿轨道路径逐像素移动。
  - 印章经过的区域（印章 2x2 覆盖的所有像素位置）被着色为印章当前的颜色，形成轨迹。
  - 每当印章左上角经过一个 Maroon 变色标记时，印章的颜色按照固定循环序列变化：Red -> Orange -> Yellow -> Blue -> Red。即 Red 变为 Orange，Orange 变为 Yellow，Yellow 变为 Blue，Blue 变为 Red。
  - 印章滑动到终点标记处停止，终点标记被印章覆盖。
  - 轨道的 Grey 像素和 Maroon 标记被轨迹覆盖后不再可见。未被印章覆盖的 Grey 轨道像素保持不变。

- `Key insight`：解题者需要同时发现三个非显然的规则：（1）印章是沿着 Grey 轨道的折线路径移动而非直线移动，移动方向由轨道形状决定；（2）Maroon 像素不是障碍物而是触发颜色变化的标记；（3）颜色变化遵循特定的固定循环序列 Red-Orange-Yellow-Blue。仅观察最终的彩色轨迹形状和颜色分段，解题者需要逆向推理出轨道路径和颜色转换规则。
</new_puzzle>

- `description`：根据网格中"信号塔"发射的彩色射线在 Green "棱镜"处的分裂与方向偏转规则，预测射线网络的最终覆盖区域和颜色叠加结果。

- `Input structure`：
  - 背景为 Black。网格边缘有若干"信号塔"，每个信号塔是一个 2x1 或 1x2 的彩色矩形，紧贴网格边缘放置。信号塔的长边方向平行于其所贴边缘，颜色可为 Red、Blue 或 Yellow。
  - 信号塔向网格内部发射射线，方向为垂直于其所贴边缘指向网格内部。
  - 网格内部散布着若干"棱镜"，每个棱镜是一个 Green 单像素。
  - 网格内部还可能有若干 Grey 像素作为"墙壁"。

- `Rule`：
  - 每个信号塔沿垂直于边缘的方向发射一条宽度为 2 像素（与信号塔等宽）的射线，颜色与信号塔相同。射线逐像素延伸直到遇到墙壁（Grey）或网格边界时停止。
  - 射线遇到棱镜（Green 像素）时：射线穿过棱镜继续前进，同时棱镜额外向射线来源方向的左右两个垂直方向各发射一条宽度为 1 像素的新射线，颜色与原射线相同。新射线同样遇墙壁或边界停止，遇棱镜时再次分裂。
  - 当两条不同颜色的射线覆盖同一像素时，颜色叠加：Red + Blue = Magenta，Red + Yellow = Orange，Blue + Yellow = Azure。
  - 棱镜像素本身被经过的射线颜色覆盖。信号塔保留原色不变。

- `Key insight`：解题者需要先理解射线从信号塔出发的传播方向（垂直于边缘），再发现棱镜的分裂机制（主射线穿透、同时向两侧发射窄射线），最后理解颜色叠加规则。关键隐蔽性在于分裂后射线宽度减半且可级联分裂，最终颜色叠加的结果需要追踪多条射线的路径交叉才能确定。
</new_puzzle>
