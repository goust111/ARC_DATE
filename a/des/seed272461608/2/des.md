<description>
根据边框上的颜色标尺确定各封闭区域的填充颜色，再按区域面积从小到大的顺序逐层覆盖绘制。

Input structure:
- bg = black。网格中有一种颜色（如 grey）绘制的不规则墙壁线条，将网格分割为若干封闭区域（不同面积）。
- 网格最上方一行是颜色标尺：从左到右排列着若干不同颜色的色块（如 red、blue、green、yellow），每个色块占据连续的若干格，色块的宽度各不相同。
- 每个封闭区域内部为 black（空）。

Rule:
- 首先识别所有被墙壁围成的封闭区域，计算每个区域的面积（像素数量）。
- 将所有区域按面积从小到大排序；同时将标尺中的色块按宽度从小到大排序。
- 按排序顺序一一对应：面积最小的区域填充宽度最小的色块颜色，面积第二小的区域填充宽度第二小的色块颜色，依此类推。
- 绘制顺序为面积从小到大：先填充小区域，再填充大区域。若大区域与小区域共享边界像素，大区域的填充不会覆盖小区域已填充的内容（即小区域优先保留）。
- 墙壁线条和标尺行在输出中保持不变。

Key insight: 标尺色块的宽度本身就是排序键——需要将色块宽度的排名与封闭区域面积的排名进行匹配，而非简单的位置对应。
</description>

<description>
识别网格中散落的小图案（stamp），找到与之形状相同但颜色不同的"影子"轮廓，将 stamp 的颜色方案移植到影子上，同时影子的朝向决定了颜色映射的翻转方式。

Input structure:
- bg = azure。网格中散布着若干对对象：每对包含一个彩色小图案（stamp，由 2-3 种非背景色组成，约 3x3 至 5x5 大小）和一个同形状的单色轮廓（shadow，用 grey 绘制）。
- stamp 和 shadow 的形状完全相同，但 shadow 可能相对 stamp 发生了水平翻转、垂直翻转或 180 度旋转（四种朝向之一）。
- 每个 stamp 内部有一个唯一的 maroon 像素作为锚点；每个 shadow 内部也有一个 maroon 像素作为锚点。
- stamp 与 shadow 通过锚点颜色（maroon）配对：整个网格中 stamp 和 shadow 数量相同且一一配对。

Rule:
- 对每一对 stamp-shadow：首先通过形状匹配确定 shadow 相对于 stamp 的变换方式（无变换、水平翻转、垂直翻转或 180 度旋转）。
- 将 stamp 的多色图案按照同样的变换方式变换后，逐像素覆盖到 shadow 的位置上，替换掉 grey 像素。
- maroon 锚点像素在输出中保持 maroon 不变。
- stamp 的原始位置在输出中被擦除为背景色。

Key insight: 解题者需要先通过形状比对推断出每个影子的翻转/旋转方式，然后将这个变换应用于颜色图案的移植——颜色映射的方向取决于几何变换的方向，两步推理缺一不可。
</description>

<description>
在网格中找到由不同颜色线段组成的"电路"，根据交叉点处的优先级规则确定信号传播路径，最终点亮路径终点处的指示灯。

Input structure:
- bg = black。网格中有若干条水平或垂直的单色线段（颜色各异，如 red、blue、green、yellow、orange），线段宽度为 1 像素。
- 某些线段会在交叉点处相交（两条不同颜色的线段共享一个格子）。交叉点处显示的颜色为后绘制的线段颜色（即视觉上可见的颜色）。
- 网格边缘有若干 magenta 像素作为"信号源"，每个信号源恰好位于某条线段的端点。
- 网格中还有若干 maroon 像素作为"指示灯"，每个指示灯也恰好位于某条线段的端点。

Rule:
- 信号从每个 magenta 信号源出发，沿其所在线段传播。
- 当信号到达一个交叉点时：如果交叉点可见颜色与当前传播线段颜色相同（即当前线段在交叉点上层），信号继续沿当前线段直行；如果交叉点可见颜色不同（即当前线段在交叉点下层），信号被迫转弯到交叉的另一条线段上继续传播。
- 信号最终到达某个 maroon 指示灯时，将该指示灯变为 green。
- 若信号到达线段末端但该末端既非指示灯也非交叉点，则信号消失。
- 所有线段和未被点亮的指示灯在输出中保持不变。

Key insight: 交叉点的可见颜色编码了"上下层"关系——信号在下层线段会被强制转弯，在上层线段则直行通过。解题者必须先从交叉点颜色推断出层叠关系，再追踪信号路径。
</description>

<description>
将网格中的彩色碎片按照"拼图边缘吻合"的规则组装成若干完整矩形，再根据每个矩形内部的颜色分布决定其在输出网格中的排列位置。

Input structure:
- bg = black。网格中散布着若干彩色碎片（不规则形状，每个碎片由单一非背景色组成，约占 3-8 个像素）。
- 每个碎片的边缘有若干 yellow 像素作为"接口"标记，接口标记位于碎片外侧紧邻碎片边缘的位置（即接口像素与碎片像素 4-邻接但不属于碎片本身）。
- 网格右下角有一个小的参考区域，用 grey 边框围起，内部展示了目标矩形的尺寸（一个空心矩形轮廓）。

Rule:
- 每两个碎片如果能通过平移拼合（不旋转不翻转），使得一个碎片的某个 yellow 接口恰好与另一个碎片的某个 yellow 接口重合，则它们属于同一组。
- 将同组碎片全部拼合后，恰好组成一个与参考矩形尺寸相同的实心矩形（接口像素在拼合后被碎片颜色覆盖）。
- 输出网格中：将所有拼好的矩形按照矩形中包含的颜色种类数从少到多，从左到右紧密排列（矩形之间间隔 1 列黑色），垂直方向顶部对齐。
- 输出网格大小恰好容纳所有矩形及间隔。

Key insight: yellow 接口标记是拼图的"榫卯"——解题者需要找到接口能精确重合的碎片对来完成分组，然后再通过颜色种类数确定输出排列顺序，这是两层独立的推理。
</description>

<description>
根据网格中"种子"像素的颜色在图例色环中的相邻关系，决定种子生长方向，让种子沿指定方向生长出与邻色相同颜色的枝条，直到碰到障碍物或网格边缘。

Input structure:
- bg = black。网格左上角有一个 3x3 的"色环"图例：九个格子排列成正方形，中心格为 black，外圈 8 个格子按顺时针方向各填一种不同颜色（如从正上方开始顺时针依次为 red、orange、yellow、green、azure、blue、magenta、maroon），形成一个颜色的环形序列。
- 网格其余区域散布着若干"种子"像素（非背景色的孤立单像素）和若干 grey 的矩形障碍块。
- 每个种子的颜色必定是色环中出现的 8 种颜色之一。

Rule:
- 对于每个种子像素，在色环中找到该颜色的位置，然后找到色环中该颜色顺时针方向的下一个颜色（称为"目标色"）。
- 色环中目标色相对于种子色的空间位置（上、右上、右、右下、下、左下、左、左上）决定了种子的生长方向。
- 种子沿该方向逐格生长，每个新生长的像素颜色为目标色，直到碰到障碍块、其他种子的枝条或网格边缘为止。
- 种子自身像素保留原色不变。色环图例在输出中保持不变。

Key insight: 色环不仅编码了颜色的"后继"关系来决定枝条颜色，其空间布局还同时编码了生长方向——解题者必须同时从色环中读取两种信息（下一颜色 + 方向），这两层语义被压缩在同一个图例结构中。
</description>

<description>
在网格中识别多个嵌套框架，根据框架的嵌套层级决定内部填充物的变换方式，最内层对象经历所有外层指定的变换叠加。

Input structure:
- bg = black。网格中有若干矩形框架（仅边框，内部空心），框架可以嵌套（一个框架完全包含在另一个框架内部）。
- 每个框架使用单一颜色绘制，不同框架颜色不同。
- 每个框架的上边框中间有一个特殊标记像素，颜色与框架不同，用于指示该层框架对应的变换类型：red 标记 = 水平翻转，blue 标记 = 垂直翻转，green 标记 = 顺时针旋转 90 度，yellow 标记 = 逆时针旋转 90 度。
- 最内层框架内有一个小的非对称彩色图案（目标对象），由 2-3 种颜色组成。

Rule:
- 识别所有框架及其嵌套关系（从最外层到最内层排序）。
- 从最内层框架开始，向外逐层读取每个框架上边框的标记颜色，确定对应的变换操作。
- 将最内层的目标对象依次施加从内到外每一层框架指定的变换（先施加最内层框架的变换，再施加次内层的，依此类推）。
- 输出仅包含经过所有变换后的目标对象（紧密裁剪），不保留任何框架。

Key insight: 嵌套框架形成了一个变换操作的"栈"——解题者需要先识别嵌套层次，再从内到外读取并叠加各层变换指令，多层变换的复合效果并非每一步的简单叠加所能直觉预测。
</description>

<description>
根据网格中路径的拐弯模式与一个二色编码条的对应关系，对路径分段染色。

Input structure:
- bg = azure。网格中有一条由 grey 像素组成的单像素宽折线路径，从网格左边缘某处开始，到右边缘某处结束，路径仅做水平或垂直方向的移动，每次转弯为 90 度。
- 网格底部有一个编码条：一行由 red 和 green 交替组成的像素序列，长度等于路径的拐弯次数。
- 路径起点处有一个 yellow 像素标记起始端。

Rule:
- 从 yellow 标记的起始端开始，沿路径行进。路径被拐弯点自然地分为若干直线段（第一段是从起点到第一个拐弯，第二段是从第一个拐弯到第二个拐弯，依此类推，最后一段到终点）。
- 依次读取编码条的每个像素：遇到第 k 个拐弯时，读取编码条第 k 个像素的颜色。
- 如果编码条像素为 red，则将该拐弯之后的下一段路径染为 red；如果为 green，则染为 green。
- 第一段路径（起点到第一个拐弯之前）保持 yellow。
- 拐弯点像素本身染为其后方路径段的颜色。

Key insight: 编码条并非直接对应路径段的颜色——它对应的是"拐弯事件"，每个拐弯决定了其后续段的颜色。解题者需要先追踪路径识别出所有拐弯点的顺序，再将编码条逐个映射到拐弯后的路径段上。
</description>
</new_puzzle>
