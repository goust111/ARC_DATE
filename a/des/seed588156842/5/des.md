- `description`：根据彩色边框碎片推断完整矩形的位置与尺寸，用碎片颜色填充矩形内部，再按矩形面积从小到大依次叠放到输出画布上。

- `Input structure`：
  - 背景色 = black。
  - 网格中散布若干"边框碎片"——每个碎片是一段连续的水平或垂直直线段（长度 >= 2），颜色各不相同（如 red、blue、green、yellow 等）。
  - 每种颜色恰好有 2 段碎片，分别位于同一矩形的两条对边上（例如一段在顶边、另一段在底边；或一段在左边、另一段在右边）。两段碎片的长度相同，且在垂直于碎片方向上对齐（即列坐标或行坐标完全重合）。
  - 碎片之间不会重叠，碎片段本身就是矩形边框的一部分。

- `Rule`：
  - 第一层：对每种颜色，找到它的两段碎片。两段碎片确定了一个完整矩形——碎片所在的行/列即为矩形的两条对边，碎片的起止坐标即为另一对边的位置。由此可唯一复原出完整的矩形轮廓。
  - 第二层：用该颜色实心填充整个矩形区域（包括边框和内部）。
  - 第三层：计算每个矩形的面积（宽 x 高，像素数），按面积从小到大的顺序依次将矩形绘制到输出网格上。面积小的先画，面积大的后画并覆盖先前内容。最终输出网格尺寸与输入相同。

- `Key insight`：同色碎片对是矩形对边的残留线索，需要跨越空间将它们配对并复原完整矩形；叠放顺序由面积决定——面积最大的矩形最后绘制，因此位于最上层，遮挡较小的矩形。
</new_puzzle>

- `description`：在网格中找到散布的彩色"种子"像素和灰色"围墙"线段，每颗种子向四个正交方向生长直线直到碰到围墙或网格边界，生长线段的长度决定该种子在输出中被替换为多大的实心正方形。

- `Input structure`：
  - 背景色 = black。
  - 若干灰色（grey）线段（水平或垂直，长度 >= 3）充当围墙，位置各异。
  - 若干彩色单像素"种子"（颜色互不相同，如 red、blue、green 等），散布在围墙之间的空隙中。每颗种子与任何围墙或其他种子不相邻。

- `Rule`：
  - 第一层——测距：从每颗种子出发，分别向上、下、左、右四个方向延伸，直到碰到灰色围墙像素或网格边缘为止（不包含围墙像素本身）。记录四个方向上各自能延伸的像素数。取四个值中的最小值，记为 D。
  - 第二层——生长：以种子像素为中心，绘制一个边长为 (2D-1) 的实心正方形，颜色与种子相同。正方形以种子为几何中心（即种子在正方形正中央）。若 D=1 则正方形就是种子本身（1x1）。
  - 围墙和背景保持不变。若正方形区域与围墙重叠，围墙像素不被覆盖（正方形在围墙处截断）。

- `Key insight`：种子到四面围墙的最近距离决定了生长尺寸——需要先在四个方向上分别"探测"障碍物距离，再取最小值作为正方形半径。围墙既是空间分隔物，又是尺寸编码器。
</new_puzzle>

<new_puzzle>
- `description`：网格中有多个不同颜色的连通区域（"岛屿"），以及一张由小色块组成的"路由表"；根据路由表指定的颜色映射关系，在相应颜色的岛屿之间画出最短的正交直线桥梁，桥梁颜色取自路由表中的第三色。

- `Input structure`：
  - 背景色 = black。
  - 网格被一条灰色（grey）水平分隔线分为上下两个区域。
  - 上方区域：包含若干不同颜色的连通区域（"岛屿"），每个岛屿是一块形状不规则的实心色块（如 red、blue、green、yellow 等）。岛屿之间有黑色间隔，不直接相邻。
  - 下方区域：是"路由表"，由若干行组成，每行恰好包含 3 个相邻的彩色像素，形如 [颜色A, 颜色C, 颜色B]。颜色A 和颜色B 分别对应上方某个岛屿的颜色，颜色C 是这两个岛屿之间桥梁应使用的颜色。

- `Rule`：
  - 第一层——解析路由表：读取下方区域每一行的三元组 [A, C, B]，确定需要在颜色 A 的岛屿和颜色 B 的岛屿之间建桥，桥的颜色为 C。
  - 第二层——寻找最近边缘对：对于每对需连接的岛屿 (A, B)，找到岛屿 A 边缘像素与岛屿 B 边缘像素之间正交方向（水平或垂直，不含对角线）上间距最小的一对像素。这对像素之间必须在同一行或同一列上，且中间全是黑色背景。
  - 第三层——画桥：在这对像素之间的黑色背景上画一条直线（水平或垂直），颜色为 C。桥梁不覆盖岛屿本身的像素，只填充中间的黑色间隔。
  - 输出网格仅包含上方区域（去掉灰色分隔线和路由表），其余内容不变。

- `Key insight`：路由表是一个间接编码——中间像素是桥梁颜色而非岛屿颜色，解题者需要识别三元组的"两端定岛、中间定桥色"结构；然后在空间中找到两岛之间最短的正交通道来放置桥梁。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干"模板窗口"和一组散布的"印章"小图案；每个印章的轮廓形状恰好与某个模板窗口内的黑色孔洞吻合，需要将印章旋转/翻转后嵌入对应窗口的孔洞中，同时印章的颜色决定窗口边框的重新着色。

- `Input structure`：
  - 背景色 = black。
  - 若干"模板窗口"：每个窗口是一个由灰色（grey）构成的实心矩形，内部挖去了一个不规则形状的孔洞（孔洞区域为黑色）。不同窗口的孔洞形状各不相同。窗口的边框颜色初始均为灰色。
  - 若干"印章"：散布在窗口外部的小型彩色连通区域（如 red、blue、green、orange），每个印章的形状（在某种旋转/翻转下）恰好与某个窗口孔洞的形状完全一致（像素数和排列完全匹配）。每个印章颜色唯一，不同印章颜色不同。

- `Rule`：
  - 第一层——形状匹配：对每个印章，尝试 0/90/180/270 度旋转以及水平翻转（共 8 种变换），找到与某个窗口孔洞形状完全匹配的变换方式。每个印章恰好匹配一个窗口，每个窗口恰好被一个印章匹配。
  - 第二层——嵌入孔洞：将经过正确变换后的印章放入窗口孔洞中，用印章的颜色填充孔洞区域。
  - 第三层——边框重染色：将该窗口的灰色边框像素全部重新着色为该印章的颜色。最终每个窗口变成一个完整的、统一颜色的实心矩形。
  - 输出网格中，所有印章的原始位置变为黑色背景。

- `Key insight`：解题者需要将散布的印章与窗口孔洞进行旋转不变的形状匹配——这是核心的空间推理挑战；而印章颜色不仅填充孔洞，还"传染"给整个窗口边框，使得最终输出中窗口变成统一颜色的实心矩形，这一额外效果需要从样例中归纳发现。
</new_puzzle>

<new_puzzle>
- `description`：网格中有一条由多种颜色交替组成的"指令路径"和若干单色矩形"画布块"；路径上每段同色线段编码一个绘图指令——颜色决定目标画布块，线段长度决定在该画布块上画多长的线条，线段的行进方向决定在画布块上的绘制方向。

- `Input structure`：
  - 背景色 = black。
  - 网格中有若干小型单色实心矩形"画布块"（如一个 red 的 5x5 矩形、一个 blue 的 6x6 矩形等），散布在网格各处。每个画布块颜色唯一。
  - 一条连续的"指令路径"从网格的某个边缘出发，由相邻像素（仅正交方向）连成，蜿蜒穿过网格。路径由多段不同颜色的线段首尾相接组成，每段线段是纯直线（水平或垂直），且颜色与某个画布块的颜色相同。路径上相邻两段颜色必不相同。
  - 路径不穿过任何画布块。

- `Rule`：
  - 第一层——分段解析路径：沿路径从起点（位于网格边缘的端点）开始行走，将路径按颜色变化拆分成若干段。记录每段的颜色 C、长度 L（像素数）、以及行进方向 Dir（上/下/左/右）。
  - 第二层——定位目标画布：每段的颜色 C 指向颜色为 C 的画布块。
  - 第三层——在画布上绘制：在目标画布块内部，从一个"游标"位置出发，沿方向 Dir 绘制 L 个 maroon 色像素。每个画布块维护独立的游标，初始位置为画布块左上角。每次绘制完成后，游标移动到本次绘制线段的终点的下一个像素处（沿绘制方向）。若游标到达画布块边缘，则折返到下一行/列的起始位置（类似打字机换行）。
  - 输出网格仅包含各画布块（带有在其上绘制的 maroon 线条），背景和指令路径均清除为黑色。

- `Key insight`：指令路径是一种顺序编码——颜色选择目标、长度选择绘制量、方向选择绘制朝向。解题者需要先识别出路径是"程序"而画布块是"屏幕"，再按顺序逐段解码执行指令。路径的蜿蜒走向本身不影响画布上的绘制，真正起作用的是每段的三个属性（颜色、长度、方向），这种间接性构成了核心推理难度。
</new_puzzle>
