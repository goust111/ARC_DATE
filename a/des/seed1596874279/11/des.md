<new_puzzle>
根据框架内部染色区域的形状匹配，将分散的色块拼入对应的镂空模板，并用模板边框颜色重新着色拼入的色块。

Input structure：
- 背景为黑色。网格中散布着若干单色的不规则小形状（"碎片"），每个碎片颜色各不相同。
- 网格中另有若干由不同颜色边框围成的封闭矩形框架，每个框架内部为黑色背景加一个镂空区域（即框架内部有一块连通的黑色空洞，形状不规则）。
- 每个碎片的形状恰好与某个框架内部的镂空区域形状完全吻合（可能需要平移，但不旋转不翻转）。
- 碎片数量与框架数量相等，且一一对应。

Rule：
- 对每个框架，找到与其镂空区域形状完全匹配的碎片。
- 将该碎片平移到框架镂空区域的位置，使其恰好填满镂空。
- 填入后，碎片的颜色不保留原色，而是改为该框架边框的颜色。
- 原碎片位置变为黑色背景。框架本身保持不变。

Key insight：
- 解题需要两层推理：第一层是通过形状匹配找到碎片与框架的配对关系；第二层是发现填入的颜色不是碎片原色而是框架边框色——这要求解题者在观察样例时注意到颜色发生了替换，而非简单搬运。
</new_puzzle>

<new_puzzle>
根据每个封闭区域内标记像素的数量，从颜色序列图例中查找对应颜色，用该颜色填充整个区域。

Input structure：
- 网格由灰色线条分割成若干大小不等的封闭矩形区域，背景为黑色。
- 网格的最底部一行（或最右侧一列）是一条颜色序列图例：从左到右（或从上到下）依次排列着不同颜色的单像素点，位置编号为 1、2、3……，之间用黑色像素间隔。
- 每个封闭区域内部散布着若干橙色的标记像素，数量从 1 到图例长度不等。不同区域的标记数量可能不同，但每个区域至少有 1 个标记。

Rule：
- 数出每个封闭区域内橙色标记像素的数量 N。
- 在颜色序列图例中找到第 N 个位置对应的颜色。
- 用该颜色填充整个封闭区域（覆盖原来的黑色背景和橙色标记），灰色边界线保持不变。
- 颜色序列图例本身在输出中被清除为黑色。

Key insight：
- 标记像素本身并非直接提供颜色信息，它们的数量才是通往正确颜色的索引键；图例不是装饰，而是必须被读取的查找表。解题者需要先发现"计数→查表"的两步管道，而非试图从标记颜色或位置推断填充规则。
</new_puzzle>

<new_puzzle>
将网格中每个箭头形标记所指向方向上的第一个单色矩形对象，沿箭头反方向推移，推移距离等于箭头尾部拖尾像素的长度。

Input structure：
- 背景为黑色。网格中有若干单色实心矩形对象，颜色各不相同。
- 网格中另有若干由红色像素组成的箭头标记。每个箭头由一个 3×3 的箭头头部和一条从箭头头部背面延伸出的直线尾部组成。箭头头部的绘制方式：中心像素为红色，指向方向上的三个像素（正前方及两个前侧对角）为红色，其余位置为背景色。尾部是从中心像素向箭头反方向延伸的连续红色像素直线。
- 每个箭头严格指向上、下、左、右四个方向之一。
- 沿箭头指向方向延伸，必定能在该行或该列上遇到一个矩形对象的边缘。

Rule：
- 对每个箭头标记，确定其指向方向和尾部长度 L（仅计尾部像素，不含中心像素）。
- 沿箭头指向方向找到第一个矩形对象。
- 将该矩形对象沿箭头的反方向（即从箭头头部朝向尾部的方向）平移 L 个像素。
- 矩形对象原位置变为黑色背景；箭头标记本身在输出中被擦除。

Key insight：
- 箭头的指向方向用于锁定目标对象，但实际的移动方向是箭头的反方向——解题者容易误以为对象沿箭头方向移动。此外，尾部长度编码了移动距离，而非箭头与对象之间的间距。
</new_puzzle>

<new_puzzle>
在被隔板分割的多个子区域中，每个区域包含一个不完整的环形图案和一个颜色提示像素；根据提示像素的颜色在全局图例中查找对应的补全方式，将环形缺口补全。

Input structure：
- 背景为黑色。蓝色的实线行和列将网格分割为若干矩形子区域。
- 网格的左上角子区域是全局图例区：其中包含若干小的完整环形图案（每个环是一圈单色像素围成的空心正方形，边长为 3），每个环使用不同颜色，且每个环在不同位置有一个缺口（某条边的中间像素缺失）。每个环的正中心有一个与环颜色不同的单像素标签色。
- 其余每个子区域包含：一个与图例中某个环颜色相同的不完整环（环的某条边中间像素缺失，形成缺口），以及一个位于区域角落的单像素提示，其颜色对应图例中某个环的标签色。

Rule：
- 对每个非图例子区域，读取角落提示像素的颜色。
- 在图例中找到中心标签色与该提示颜色相同的环。
- 观察图例中该环的缺口位于哪一侧（上、下、左、右）。
- 将当前子区域中的不完整环在相同侧补上缺失的像素，使其变为完整环。注意：当前子区域的环本身可能在任意侧有缺口，但补全方式是将缺口移到图例指定的位置——即先补全所有缺口，再在图例指定的位置重新打开缺口。
- 提示像素在输出中被擦除为黑色。

Key insight：
- 解题者必须完成三步推理：（1）识别图例区中每个环的标签色和缺口方位的对应关系；（2）通过子区域的提示色在图例中查找匹配项；（3）理解补全规则不是"补上现有缺口"，而是"重塑为图例所示的缺口模式"。第三步是最隐蔽的——直觉上以为是简单补全，实际上是按图例重新配置缺口方向。
</new_puzzle>

<new_puzzle>
根据每行彩色种子像素的颜色顺序，在该行生成对应宽度的交替色带，色带宽度由种子像素之间的间距编码。

Input structure：
- 网格背景为黑色，高度较小（约 5-10 行），宽度较大（约 20-30 列）。
- 每行包含 2 到 4 个孤立的彩色种子像素（各像素颜色可不同），散布在该行的不同列位置上，其余位置为黑色。
- 不同行的种子像素数量、颜色和位置各不相同。

Rule：
- 对每一行，按从左到右的顺序读取种子像素的颜色，形成颜色序列（例如 [Red, Green, Blue]）。
- 计算相邻种子像素之间的水平间距（即列差减一），得到间距序列（例如间距为 [3, 5]）。
- 第一个间距值定义色带的单元宽度 W。
- 从该行最左端（第 0 列）开始，用颜色序列循环填充：先画 W 列的第一种颜色，再画 W 列的第二种颜色，依此类推；颜色用完后循环回第一种颜色，直到填满整行。
- 种子像素本身被色带覆盖，不再单独可见。

Key insight：
- 种子像素承载双重信息：它们的颜色决定色带的调色板顺序，而它们之间的第一个间距决定每段色带的宽度。解题者容易只关注颜色而忽略间距的编码作用，或者误以为每个间距对应不同宽度——实际上只有第一个间距是有效的宽度参数。
</new_puzzle>

<new_puzzle>
将网格中散布的同色像素簇按簇的大小排序，然后依次堆叠到网格底部，堆叠顺序由一个独立的颜色排列条决定。

Input structure：
- 背景为黑色。网格中散布着若干不同颜色的像素簇（4-连通区域），每种颜色恰好出现一个簇，簇的形状为不规则但连通。
- 网格最顶行是一条颜色排列条：由若干不同颜色的单像素从左到右排列，颜色与网格中的簇颜色一一对应，像素之间用黑色间隔。

Rule：
- 计算每个颜色簇的像素数量（面积）。
- 按面积从大到小排序。
- 将排序后的簇依次从网格底部开始向上堆叠：面积最大的簇最先放置在底部，保持簇的原始形状，但水平位置由颜色排列条决定——该颜色在排列条中的列位置即为簇的包围盒左边缘所对齐的列。
- 垂直方向上，每个簇的包围盒底边紧贴已堆叠内容的顶部（第一个簇紧贴网格底边）。
- 簇的原始位置变为黑色；颜色排列条在输出中被清除。

Key insight：
- 解题涉及三层独立推理：（1）发现堆叠的垂直顺序由面积大小决定（而非颜色排列条的顺序）；（2）发现水平对齐位置由颜色排列条中的列位置控制；（3）发现簇保持原始形状而非被压缩为矩形。三层信息分别来自不同的视觉线索，任何一层的错误归纳都会导致输出错误。
</new_puzzle>

<new_puzzle>
沿每个标记像素所在行和列画出十字线，十字线在遇到同色边界条时停止；然后统计每个矩形区域内十字线交叉点的数量，用该数量对应的图例颜色填充该区域。

Input structure：
- 背景为黑色。绿色的完整水平线和垂直线将网格分割为若干矩形区域（类似棋盘格分割）。
- 部分矩形区域内有一个孤立的黄色标记像素。
- 网格右下角有一个小的图例区域（被绿色线框住）：其中垂直排列着若干不同颜色的色块，从上到下分别代表数字 0、1、2、3……

Rule：
- 对每个黄色标记像素，沿其所在行向左和向右、沿其所在列向上和向下画出黄色十字线。十字线在遇到绿色分割线时停止（不越过绿色线）。
- 十字线画完后，检查每个矩形区域（不含图例区）内黄色十字线段交叉点的数量 N（即区域内同时位于某条水平线段和某条垂直线段上的像素数）。
- 在图例中找到第 N 个位置对应的颜色（从 0 开始计数，0 表示无交叉点）。
- 用该颜色填充整个矩形区域，覆盖内部所有内容（包括黄色线段和标记像素），绿色分割线保持不变。
- 图例区域在输出中保持不变。

Key insight：
- 解题者需要先理解十字线的传播规则（被绿色线阻断），然后意识到关键量不是标记像素的数量或线段的长度，而是不同线段在区域内的交叉点数。这是一个从"局部标记→全局传播→区域统计→图例查找"的四步管道，每一步都需要独立归纳。
</new_puzzle>
