- `description`：根据每个封闭区域内部的"种子"颜色，从区域边界向内逐层收缩填充渐变色环，层数由种子像素的数量决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干用同一种颜色（如 grey）绘制的不规则封闭轮廓，各轮廓互不相交。
  - 每个封闭轮廓的内部散布着 1~4 个同色"种子"像素（颜色各异，如 red、blue、green 等），种子像素不在轮廓边界上。

- `Rule`：
  - 对每个封闭轮廓区域，计数其内部种子像素的数量 N。
  - 从轮廓边界向内做 N 层"收缩"：第 1 层（紧贴轮廓内侧的一圈 4-连通像素）用种子的颜色填充；第 2 层（紧贴第 1 层内侧）用第二个预设颜色填充；以此类推。颜色序列固定为 red -> green -> blue -> yellow，循环使用，但只填 N 层。
  - 收缩后剩余的内部区域保持 black。
  - 轮廓本身颜色不变；种子像素被所在层的填充色覆盖。
  - 输出网格尺寸与输入相同。

- `Key insight`：种子像素的数量决定了向内填充的层数，而填充颜色遵循固定序列——解题者需要同时归纳出"计数 -> 层数"映射和"固定色序"两个独立规律。
</new_puzzle>

- `description`：网格中的多个小图案（stamp）各自充当"印章"，根据它们在输入中的朝向，在对应方向上重复盖印，印出的副本颜色逐次变淡（按预设色阶递减）。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干独立的小型非对称 4-连通图案（每个不超过 4x4 像素），各自由单一颜色构成。
  - 每个图案在其 bounding box 中恰好有且仅有一行或一列是完全填满的（即该行/列的每个格子都是图案像素）——这条"满行/满列"指示了该图案的盖印方向：满行意味着水平盖印（向右），满列意味着垂直盖印（向下）。

- `Rule`：
  - 识别每个图案的满行/满列方向。
  - 从图案的原始位置开始，沿该方向以图案 bounding box 的宽度（水平时）或高度（垂直时）为步长，依次放置图案的副本。
  - 第 1 个副本（原始位置）保持原色；后续每个副本按照固定色阶降低一级。色阶从高到低为：red -> orange -> yellow -> green -> azure -> blue -> grey。图案的初始颜色在色阶中的位置决定起点，每多盖一次降一级。
  - 当颜色降至 grey 以下（色阶耗尽）或副本超出网格边界时停止。
  - 不同图案的盖印轨迹若重叠，后处理的图案覆盖先处理的（处理顺序为从上到下、从左到右）。

- `Key insight`：解题者需要发现两层规律——第一层是"满行/满列决定方向"这一隐含的方向编码机制，第二层是"颜色沿固定色阶逐次递减"的衰减规则。两层信息分别编码在图案的形状结构和颜色中。
</new_puzzle>

- `description`：网格中的每个彩色矩形区域根据其内部"指针"像素的偏移位置确定射线方向，射线击中其他区域后使其变为射线颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有 3~5 个不重叠的矩形实心彩色区域（各自颜色不同，如 red、blue、green 等），每个区域的面积在 3x3 到 5x5 之间。
  - 每个矩形区域内部恰好有一个 maroon 像素（"指针"），其余像素为该区域的主色。指针在区域内的相对位置指示方向：指针在区域的上半部分表示"向上"，下半部分表示"向下"，左半部分表示"向左"，右半部分表示"向右"。当指针在角落时，取离对应边界更近的那个轴作为方向（例如指针在左上角且距左边界只有 0 格而距上边界有 1 格，则向左）。

- `Rule`：
  - 每个区域从指针所指方向的区域边界中心点发出一条 1 像素宽的射线，颜色为该区域的主色。
  - 射线沿该方向直线延伸，直到遇到另一个区域的边界或网格边界。
  - 如果射线击中了另一个区域，该被击中区域的所有像素（maroon 指针除外）变为射线的颜色（即发射区域的颜色）。
  - 射线在网格上保留可见。
  - 变色后的区域不再发射新射线（只有保持原始颜色的区域才发射）。处理顺序为从上到下、从左到右逐个区域处理。

- `Key insight`：指针的空间位置编码了方向信息（不是箭头形状而是偏移量），解题者需要从样例中发现"指针在区域哪一侧 -> 射线朝哪个方向"的映射，再理解射线击中后的"传染式变色"规则。
</new_puzzle>

- `Input structure`：
  - 背景为 black。
  - 网格中有 2~4 个由 grey 像素构成的 U 形或 C 形"容器"（即三面封闭、一面开口的结构），每个容器开口朝向上、下、左或右之一，各容器的开口方向可能不同。容器内部初始为 black。

- `Rule`：
  - 每个碎片根据颜色匹配到对应容器。
  - 将碎片沿容器开口方向的反方向"吸入"容器：碎片保持自身形状，沿开口的反方向平移进入容器内部，直到碰到容器底壁或已堆积的其他碎片。

  - 标记像素和容器 grey 边框保持不变，输出网格尺寸不变。

- `Key insight`：解题需要三层推理——第一层识别容器的开口方向，第二层通过颜色标记将碎片分配到正确容器，第三层理解碎片沿反方向吸入并按距离排序堆积的物理规则。

- `Input structure`：

  - 锁孔的数量等于钥匙的数量。每个锁孔的内部面积恰好等于某一把钥匙的面积，且在 0/90/180/270 度旋转下，恰好有唯一一把钥匙的形状与该锁孔内部形状完全吻合。

  - 每条轨道上有 0~2 个"车厢"：车厢是 3x1 的水平小矩形，位于轨道正上方一行，由某种非轨道颜色的单色构成。
  - 每个车厢的中间像素被替换为 maroon（"方向标记"）或 orange（"方向标记"）。maroon 表示车厢应向上移动到相邻轨道，orange 表示向下移动到相邻轨道。
  - 每个车厢的两端像素颜色与某条目标轨道的颜色相同（但不是当前所在轨道的颜色）。

  - 读取车厢两端的颜色，确定目标轨道。

- `Key insight`：解题者需要同时解码两种信息——车厢端部颜色告诉"去哪条轨道"，中间标记颜色告诉"先往哪个方向走"，两者结合才能确定车厢的最终位置。方向标记避免了歧义（当目标轨道在上方和下方都存在同色轨道时）。

  - 网格中有 2~4 组配对元素，每组包含一个"时钟"和一个"附属图案"，两者通过一条 grey 单像素连线相连（4-连通）。

  - 附属图案是一个不超过 4x4 的小型彩色非对称 4-连通图案（颜色非 azure、非 red、非 grey）。

- `Rule`：
  - 读取每个时钟的指针方向：上 = 不旋转（0 度），右 = 顺时针 90 度，下 = 顺时针 180 度，左 = 顺时针 270 度。

  - 旋转后的附属图案放置在原位（bounding box 中心不变）。
  - 删除所有时钟和 grey 连线（填回 black），只保留旋转后的附属图案。

- `Key insight`：时钟的指针位置是对旋转量的空间编码——解题者必须先建立"指针方向 -> 旋转角度"的映射表，然后将其应用到配对的附属图案上。由于附属图案是非对称的，旋转效果在视觉上非常明显，有助于验证推断。
</new_puzzle>
