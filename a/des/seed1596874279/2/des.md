<new_puzzle>
根据每个封闭区域内部散布标记点的数量，从颜色图例条中选取对应颜色，为该区域填色。

Input structure：
- 背景色为 black。网格中有一个由 grey 像素绘制的不规则封闭框架，框架将网格内部划分为若干个互不相通的封闭区域（每个区域的面积各不相同）。
- 框架内部的每个封闭区域中散布着若干个 red 标记像素（数量为 1 到 N，每个区域的标记数量互不相同）。
- 网格底部（框架之外）有一条水平颜色图例条：从左到右依次排列 N 个不同颜色的色块，每个色块宽 1 像素、高 1 像素，颜色互不相同且不包含 black、grey 或 red。色块之间无间隔，紧密排列。

Rule：
- 数出每个封闭区域内 red 标记像素的数量 K（K ≥ 1）。
- 在颜色图例条中，从左到右第 K 个色块即为该区域的目标颜色。
- 将该封闭区域内所有 black 背景像素和 red 标记像素都填充为目标颜色。
- grey 框架像素保持不变。
- 颜色图例条在输出中移除（即底部图例区域变为 black 背景）。

Key insight：
- 解题需要两层独立归纳：第一层是发现"区域内 red 点的数量"是索引键；第二层是发现底部色条是按位置编号的颜色字典，数量与位置的对应关系需要从多个样例中验证。
</new_puzzle>

<new_puzzle>
将网格中散落的彩色碎片按照颜色归组，每组碎片沿各自的对称轴做镜像补全，再将补全后的完整图形平移到以该组几何中心为基准的对齐位置。

Input structure：
- 背景色为 black。网格中散布着若干组彩色像素，每组使用一种独特的非背景颜色（如 blue、green、orange 等）。
- 每组彩色像素构成某个图形的"半边"——即一个关于某条水平或垂直轴线对称的图形被沿轴线切掉了一半，只保留了其中一侧的像素。
- 每组像素的切割边缘（即缺失侧的轮廓）形成一条平直的边界线，该边界线方向（水平或垂直）暗示了镜像轴的方向。
- 不同颜色组的切割方向可能不同（有的沿水平轴、有的沿垂直轴）。

Rule：
- 对每种非背景颜色，找到该颜色所有像素的集合。
- 确定该组像素的平直切割边：即该组像素的边界框中，像素紧贴且填满的那一侧边缘（例如所有像素的最左列都有像素占据，说明左侧是保留侧、右侧被切掉）。
- 以该平直边缘所在的行或列为镜像轴，将现有像素镜像翻转到缺失的一侧，生成完整的对称图形。
- 镜像生成的新像素使用与原像素相同的颜色。
- 若镜像区域与其他颜色组的像素发生重叠，后补全的像素覆盖先存在的像素（但在实际题目设计中，各组间距足够大，不会重叠）。

Key insight：
- 第一层归纳：识别出每组单色像素是某个对称图形的半边，而非完整图形。第二层归纳：每组的镜像轴方向和位置不同，需要逐组通过分析像素分布的"齐平边"来独立判断镜像方向——齐平边就是轴所在的位置。
</new_puzzle>

<new_puzzle>
利用网格边缘的颜色信号条确定每行每列的"活跃颜色"，在行列交叉点处根据优先级规则填入对应颜色。

Input structure：
- 背景色为 black。网格尺寸约为 12×12 到 20×20。
- 网格最左列为"行信号列"：每行最多有一个非 black 像素，其颜色指示该行的活跃颜色。某些行的信号位为 black，表示该行无活跃颜色。
- 网格最上行为"列信号行"：每列最多有一个非 black 像素，其颜色指示该列的活跃颜色。某些列的信号位为 black，表示该列无活跃颜色。
- 左上角单元格（第 0 行第 0 列）始终为 black，不参与信号。
- 网格内部（排除第 0 行和第 0 列的区域）有一个由 grey 像素绘制的不规则遮罩图案，其余内部单元格为 black。

Rule：
- 对于内部区域（行≥1，列≥1）的每个单元格 (r, c)：
  - 如果该单元格是 grey 遮罩像素，则保持 grey 不变。
  - 如果该行有活跃颜色 Cr 且该列有活跃颜色 Cc：
    - 若 Cr == Cc，填入该颜色。
    - 若 Cr ≠ Cc，填入 Cr（行优先）。
  - 如果只有该行有活跃颜色（列信号为 black），则不填色，保持 black。
  - 如果只有该列有活跃颜色（行信号为 black），则不填色，保持 black。
  - 如果行列均无活跃颜色，保持 black。
- 输出中保留第 0 行和第 0 列的信号像素不变。

Key insight：
- 第一层归纳：边缘的彩色像素不是装饰，而是行/列的颜色指令。第二层归纳：只有行列信号同时存在时交叉点才会被激活，且行列颜色冲突时存在行优先的隐含优先级规则——这必须从样例中对比不同颜色交叉的情况才能发现。第三层归纳：grey 遮罩区域屏蔽了所有填色规则，无论信号如何都保持不变。
</new_puzzle>

<new_puzzle>
根据封闭围栏内"种子像素"的颜色，选择对应的生长模板，将模板图案从种子位置向外扩展填充到围栏内部。

Input structure：
- 背景色为 black。网格中有若干个由 grey 像素构成的封闭矩形围栏（每个围栏为空心矩形框，框线宽度为 1 像素）。
- 每个围栏内部恰好有一个非 black、非 grey 的"种子像素"，位于围栏内部的某个位置。不同围栏内的种子颜色可能相同也可能不同。
- 网格的某个角落（例如右下角）有一块"模板字典区域"，用 maroon 边框围起。字典区域内部被 maroon 分隔线分成若干个等大的小格子，每个小格子内绘有一个由某种颜色构成的小型图案（如十字形、L 形、菱形等）。每个小格子的图案颜色各不相同，且与某个种子颜色对应。

Rule：
- 在模板字典中，找到与种子颜色相同的图案所在的小格子，提取该图案的形状（忽略颜色，只看形状）。
- 以种子像素在围栏内部的位置为中心，将该图案的形状以种子颜色铺贴（平铺/重复）填满围栏内部的所有 black 像素。铺贴方式：将图案视为一个周期性瓦片，种子位置对应图案的中心像素，向四周周期性重复该图案，直到围栏边界为止。
- 围栏外超出的部分裁剪掉。grey 围栏像素保持不变。
- 模板字典区域在输出中移除（变为 black）。

Key insight：
- 第一层归纳：种子颜色是字典查询的键，需要在字典区域中找到颜色匹配的模板。第二层归纳：模板不是直接放置一次，而是以种子为锚点进行周期性平铺，填满整个围栏空间——这一点需要从围栏大小不同但图案周期一致的多个样例中归纳出来。
</new_puzzle>

<new_puzzle>
按照"传送门"配对规则，将每个移动对象从入口传送门的位置弹出到匹配的出口传送门，保持对象相对传送门的朝向关系。

Input structure：
- 背景色为 black。网格中有若干对彩色"传送门标记"：每对由两个相同颜色的单像素组成（例如两个 blue 像素、两个 red 像素等），分散在网格各处。每种颜色恰好出现两个像素，构成一对传送门。
- 网格中另有若干个由 grey 像素组成的小型连通对象（形状各异，如 T 形、方块、折线等）。
- 每个 grey 对象恰好有一个单元格与某个传送门标记四邻接（上下左右相邻）。该传送门标记即为该对象的"入口传送门"。同色的另一个传送门标记即为"出口传送门"。
- 每个传送门标记最多与一个 grey 对象相邻。

Rule：
- 对每个 grey 对象，找到与其四邻接的传送门标记颜色 C，然后找到颜色 C 的另一个传送门标记位置（出口）。
- 确定对象相对于入口传送门的空间布局（对象在入口的哪一侧展开：上方、下方、左方、右方）。
- 在出口传送门旁，以相同的相对方向放置该对象的副本（即如果对象在入口的上方，则副本也放在出口的上方）。
- 原始对象从原位置擦除（变为 black），入口和出口传送门标记保留。
- 对象副本使用 grey 绘制，与原对象形状完全相同。

Key insight：
- 第一层归纳：每个对象旁边的彩色单像素不是对象的一部分，而是"地址标签"，同色的另一个单像素是目的地。第二层归纳：传送不是简单的位置复制——对象相对于入口标记的方向关系必须在出口处保持一致，这要求解题者分辨对象在传送门的哪一侧并将该空间关系映射到出口。
</new_puzzle>

<new_puzzle>
在棋盘格背景上，根据每个彩色对象所覆盖的两种棋盘格颜色面积之差，决定该对象应沿主对角线方向还是副对角线方向滑动一格。

Input structure：
- 网格由两种颜色交替排列构成棋盘格背景（如 azure 和 white，其中 azure 占据 (r+c) 为偶数的格子，white 占据 (r+c) 为奇数的格子）。
- 棋盘格上有若干个由不同鲜艳颜色（如 red、green、orange、magenta 等）绘制的小型填充对象，每个对象为 4-连通的连通区域，面积不超过 6 个像素。
- 每个对象覆盖的棋盘格格子中，一部分原本是 azure，另一部分原本是 white。

Rule：
- 对每个彩色对象，统计它覆盖了多少个 azure 底色格子（记为 A）和多少个 white 底色格子（记为 W）。底色由棋盘格的 (r+c) 奇偶性决定。
- 若 A > W（对象覆盖的 azure 格子更多），则将该对象整体沿主对角线方向（右下方）平移 1 格。
- 若 W > A（对象覆盖的 white 格子更多），则将该对象整体沿副对角线方向（右上方）平移 1 格。
- 若 A == W，则该对象不移动。
- 移动后，原位置恢复为棋盘格背景色。新位置的对象像素覆盖棋盘格。

Key insight：
- 第一层归纳：对象不是随机移动，移动方向与棋盘格有关。第二层归纳：每个对象的移动方向取决于它所压在的两种棋盘格颜色的面积对比——这是一种隐藏在棋盘格背景中的"投票机制"，解题者需要将对象与其下方的棋盘格底色建立关联才能发现规律。
</new_puzzle>

<new_puzzle>
将网格中的彩色路径段按端点颜色标记依次首尾相连，拼接成一条不间断的蛇形路径，输出拼接后的紧凑网格。

Input structure：
- 背景色为 black。网格中有若干条由 grey 像素构成的路径段（每条路径段是一个宽度为 1 像素的 4-连通曲线，无分叉）。
- 每条路径段的两个端点（度为 1 的像素）各被一个彩色像素覆盖（替换了 grey），颜色来自 red、blue、green、orange、magenta 等。
- 拼接规则由端点颜色编码：同色的两个端点应该对接。每种颜色恰好出现两次，分别在两条不同路径段的端点上。

Rule：
- 找到所有路径段及其端点颜色。
- 从唯一一条拥有某种"起始标记"的路径开始——起始路径的特征是它有一个端点颜色在全局中只出现一次（即该颜色只标记了一个端点，没有配对）。另一种等价判断：将所有路径段视为图的边、端点颜色视为节点，起始和终止路径各有一个"悬挂"端点颜色。
- 从起始路径的悬挂端开始，沿路径走到另一端，读取该端颜色 C，找到颜色 C 出现在的另一条路径段，从该端沿路径走到对面端，如此反复，直到走完所有路径段。
- 将按行走顺序排列的像素序列从左到右、从上到下依次填入一个紧凑矩形网格中（矩形宽度等于路径总像素数的某个因数，使矩形尽可能接近正方形）。
- 输出网格中，原来的彩色端点像素恢复为 grey（即输出全部为 grey 像素构成的矩形块）。

Key insight：
- 第一层归纳：端点颜色不代表路径的属性，而是"接口编号"，同色端点表示两条路径在此对接。第二层归纳：路径段之间的拼接顺序由颜色配对的链式结构唯一确定——这形成一条哈密顿链，需要从颜色配对中推导出全局顺序。第三层归纳：拼接后的像素序列被重排进紧凑矩形，输出尺寸与输入网格无关。
</new_puzzle>

<new_puzzle>
将网格中每个"窗框"对象内部的格子图案作为缩略地图，指示该窗框在输出网格中应被放置的位置。

Input structure：
- 背景色为 black。网格中有若干个由不同颜色绘制的矩形空心框（"窗框"），每个窗框由单色边框围成，框线宽 1 像素，内部为若干格子。
- 每个窗框内部被该窗框自身的边框颜色的浅色网格线分成 R×C 的小格子（R 行 C 列），所有窗框的内部网格尺寸 R×C 相同。
- 在每个窗框的内部网格中，恰好有一个格子被填为 maroon（其余格子为 black）。
- 所有窗框的外部尺寸相同。

Rule：
- 确定所有窗框内部网格的共同尺寸 R×C。
- 创建一个 R×C 的输出布局网格，每个布局格子的尺寸等于一个窗框的外部尺寸。
- 对每个窗框，读取其内部 maroon 格子的位置 (r, c)，将该窗框放置到输出布局网格的第 r 行第 c 列。
- 未被窗框占据的布局格子填充为 black。
- 输出中每个窗框保留原样（包括边框和内部格子），但 maroon 标记格子变为 black（擦除定位标记）。

Key insight：
- 第一层归纳：每个窗框内部的格子图案不是装饰，而是一张缩略的"座位表"——maroon 格子指示该窗框应被放到输出中的哪个位置。第二层归纳：输出网格的尺寸由窗框内部格子数决定，而非由输入网格的尺寸决定。解题者需要理解"对象内部的图案编码了该对象在输出中的全局坐标"这一元层级关系。
</new_puzzle>
