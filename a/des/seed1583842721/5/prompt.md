Delete connected components whose colors match a legend swatch.

<description>
Slide each inner colored object horizontally into the same-colored vertical wall until it touches an obstacle.

Input structure
- The background is the dominant color.
- The only foreground colors are two non-background colors.
- One foreground color fills the left column and the other fills the right column.
- Extra 8-connected objects of each wall color appear away from that color's wall.

Rule
- Clear the extra objects from their original positions.
- For each wall color, process its 8-connected extra objects from nearest to farthest from the matching wall.
- Slide each object horizontally toward its matching wall as far as possible without overlapping the wall or an already settled object of the same color.
- Keep the two vertical wall columns fixed.

Key insight
- The side columns act like color-specific gravity walls: same-colored objects compact sideways against their own wall while preserving each object's shape.
</description>
</reference_puzzle>

<description>
Composite two pattern tiles into a fourth panel using flood-fill from an indicator pixel.

Input structure:

Rule:
- Flood-fill (4-conn) from indicator, blocked by wall → inside region.
- Inside → non-bg from panel 1; outside → non-bg from panel 2.
- Wall → panel 1 if non-bg; panel 2 fallback when wall is 4-connected.

Key insight: The cue panel's isolated indicator and wall partition the tile into inside/outside masks that select between the two source panels.

<description>
Transfer each colored marker to its adjacent neutral mask component, then erase the markers.

- The background is the most common color.
- The neutral mask color is the unique most frequent foreground color.
- Other foreground colors are marker pixels that may touch neutral 4-connected mask components.
Rule
- Remove every marker pixel by recoloring it to the background.
- For each 4-connected neutral mask component, find marker colors touching it by edge adjacency.
- If a component touches one marker color, recolor the whole neutral component to that marker color.
- If a component touches no marker color, leave it neutral.
Key insight
- Marker pixels label neighboring neutral regions but are not part of the final colored objects.

Rule:
- Infer the vertical and horizontal reflection axes from the visible (non-zero) pixels.
- For each black pixel, recover its color from the mirrored position across either axis or both.

Key insight: The reflection axes are not given — they must be deduced from the surviving pixels by finding the axes that best preserve the existing symmetry.

<description>
Red diamond outlines contract by one layer and gray diamond outlines expand by one layer while other objects stay fixed.

Input structure
- A 16x16 orange-background grid contains one-cell-thick Manhattan-diamond outlines.

Rule
- Clear all red and gray pixels.
- Red objects are redrawn with the same diamond center and radius minus one.
- Gray objects are redrawn with radius plus one; an ambiguous edge-clipped growing arc continues away from the nearest perpendicular edge.
Key insight
- The task is not about moving whole objects: each changing object is a contour of a diamond, and the visible operation is one step of contour contraction or expansion.

<reference_puzzle index="11" source="eval" puzzle_id="7666fa5d" lines="12-26">
<description>
Fill the parallelogram-shaped region between parallel anti-diagonal line segments with red.

Input structure:
- bg = most common color.
- One non-bg color forms short diagonal segments, each lying on a single anti-diagonal (r+c = const).
- Segments come in parallel pairs bounding a region to be filled.

Rule:
- For each main-diagonal axis (r−c = const), collect anti-diagonal segments whose span covers that axis.
- Sort those segments by their anti-diagonal index (r+c).
- Fill all bg cells lying strictly between consecutive segment pairs along that axis with red (color 2).

Key insight: The two diagonal directions decouple — segments sit on anti-diagonals, and filling sweeps along main diagonals between them, forming parallelogram regions.
</description>
</reference_puzzle>

<reference_puzzle index="12" source="eval" puzzle_id="195c6913" lines="37-52">
<description>
Simulate particles along a path with alternating turn direction at collisions.

Input structure:
- Top-left: 2x2 monochrome blocks define a repeating color cycle (left-to-right).
- Isolated single pixels of a cycle color: start markers adjacent to the path.
- A 2x2 monochrome block of a distinct color: end marker.

Rule:
- Each start marker launches a particle moving straight, painting cycle colors in order.
- On hitting a boundary, paint that cell with the end color and turn 90°.
- Turn direction alternates: odd collisions → left (CCW), even → right (CW).
- If the scheduled turn is blocked, the particle stops.

Key insight: The alternating left/right turn rule is the core mechanism; without it the path would be trivial.
</description>
</reference_puzzle>

<reference_puzzle index="13" source="train" puzzle_id="17829a00" lines="21-36">
<description>
Move each colored object vertically until it touches the matching top or bottom border bar.

Input structure:
- The background is the dominant color.
- The top row is a full-width bar in one foreground color and the bottom row is a full-width bar in another.
- All other foreground pixels are 8-connected monochrome objects whose color matches one of those bars.

Rule:
- Top-bar-colored objects move upward so their bbox top is row 1.
- Bottom-bar-colored objects move downward so their bbox bottom is the row above the bottom bar.
- A downward-moving one-column segment whose landing overlaps its source becomes the continuous vertical segment swept between them.

Key insight:
The horizontal bars are destination anchors: color determines which border an object slides toward, while columns and object shape are otherwise preserved.
</description>
</reference_puzzle>

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（较为简单的计算）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式。
   - **禁止使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算 / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号进行排序；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 排序或优先级规则必须基于网格中可见的属性（如位置、面积、数量），不得依赖颜色名称的字母顺序或颜色编号等先验知识。
7. 每个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
8. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
9. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
10. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。
   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**禁止用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
11. 层数可以是两层、三层或更多——不必拘泥于两层。若题目的机制天然适合更深的嵌套，鼓励向三层及以上尝试；但层数本身不是目的，每一层都必须有独立的归纳价值。
12. **严禁用复杂数学或复杂算法来制造层级深度或增加难度。** 这是最常见的失败模式：为了凑层数或提升难度，引入注意事项第 2 条禁止列表中的复杂计算（二进制编码、距离公式、模运算、BFS、全局最优匹配等）。简单计算（计数、比大小、奇偶判断等）作为层的一部分是允许的，但复杂计算本身不构成有价值的推理层，也不应被用来提升难度。例如：
   - 好的两层："颜色配对找到对应模板 → 碎片相对于模板的方位决定旋转角度"（两层都是视觉关系）
   - 坏的两层："数出内部标记个数 N → 将 N 转为二进制画出柱状图"（第二层是复杂数学运算，不是视觉发现）

生成后对生成的题执行以下六项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述参考题相同或类似，不可只是替换颜色、方向、对象类型等表层要素。判断标准：新题的核心推理路径应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。禁止使用上述禁用的数学知识和人类不可用的信息（颜色id排序等）。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。
5. 数学/算法清洁性
  对每道题逐条检查：规则中是否隐含了注意事项第 2 条禁止列表中的复杂计算或复杂算法？简单计算（计数、比大小、奇偶等）不在此列，但需警惕以下常见的伪装形式：
  - 用"扩散""传播"包装的 BFS / 最短路
  - 用"编码""解码"包装的二进制转换
  - 用"优先级""竞争"包装的全局最优匹配
  - 用"模拟""时间步"包装的迭代仿真
  若发现任何一项，必须将该步骤替换为简单视觉机制，或删除该题重新生成。
6. 层级有效性与内部一致性
  逐题检查以下两点，发现问题需要重写该题：
  - **层级是否会坍缩**：每一层是否都对最终输出有独立贡献？是否存在某一层无论怎么变化都不影响下一层结果的情况？（例如规则号称"先用 A 选出 B，再用 B 控制 C"，但 A 的所有可能取值都导出同一个 B，第一层实际无效，整道题坍缩为单层。）
  - **层级是否"感知透明"**：某一层的结果是否无需从样例中归纳、仅靠直觉就能看出？（例如"数嵌套层数""找面积最大的色块""看缺口在哪一侧"等——这些是直接读取而非推理，不算独立的归纳层。真正的层应该是：如果只看单个样例，无法确定该层的规则，必须对比多个样例才能发现。）
  - **规则是否自相矛盾**：题目内部是否存在隐性冲突或未覆盖的退化情况？（例如两条优先级条件在某些输入下会冲突，或某个对象没有标记、某个区域无内部像素时规则失效。）

若任意一题未通过上述六项审查中的任何一项，丢弃该题并重新生成一道替代题，替代题同样需要通过全部六项审查后才可保留。
