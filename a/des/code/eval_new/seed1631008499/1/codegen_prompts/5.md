- `description`：根据网格中标尺刻度对物体进行测量，然后用测量值控制另一组物体的变换幅度。
- `Input structure`：
  - 背景色为 black。
  - 网格左侧有一把垂直"标尺"：由一列 grey 像素构成，标尺上每隔固定间距有一个 maroon 像素作为"刻度线"（例如每隔 3 格一个刻度）。
  - 网格中央区域有若干彩色水平条（每条由单一颜色的连续水平像素组成），每条的左端恰好对齐标尺的某个位置。每条水平条的右端延伸长度不同。
  - 网格右侧区域有若干小型彩色方块图案（正方形，边长为 2 或 3 像素），每个方块颜色与某条水平条颜色相同，建立一一对应。
- `Rule`：
  - 第一层推理——读取标尺：观察标尺上相邻 maroon 刻度之间的间距，确定"一个刻度单位"等于多少像素行。
  - 第二层推理——测量条长：每条水平条的像素长度除以刻度单位间距（整除），得到该条的"测量值"（一个小整数，通常 1-5）。
  - 第三层推理——变换方块：找到与每条水平条同色的右侧方块，将该方块沿四个方向等量外扩，外扩的像素层数等于该条的测量值。外扩使用该方块的颜色。例如测量值为 2，则一个 2×2 的方块变为 6×6（上下左右各加 2 层）。
  - 输出网格仅包含变换后的方块（移除标尺和水平条），方块保持原始中心位置不变，背景为 black。
- `Key insight`：标尺的刻度间距是隐含的度量单位，解题者必须先从标尺上归纳出这个单位，再用它去"测量"水平条的长度，最后将测量结果作为方块膨胀的参数。三步推理链环环相扣：刻度间距→条长度→膨胀幅度。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
