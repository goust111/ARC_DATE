- `Input structure`：
  - bg = 背景色（black）。
  - 网格被若干条贯穿整个网格的水平线和竖直线划分成矩形区域。这些线条使用两种颜色之一绘制：red 或 blue。
  - 每个矩形区域内部有一个小型非对称图案（由某种非背景、非 red、非 blue 的颜色绘制，如 yellow 或 green），图案不接触区域边界线。
  - 图案在每个区域中的相对位置（相对于区域左上角的偏移）可能不同。

- `Rule`：
  - 对每个矩形区域，检查其四条边界线（上、下、左、右）的颜色：
    - 上边界线和下边界线颜色相同，且左边界线和右边界线颜色相同 → 图案保持不变。
    - 上边界线和下边界线颜色不同，且左边界线和右边界线颜色相同 → 图案进行垂直翻转（上下翻转）。
    - 上边界线和下边界线颜色相同，且左边界线和右边界线颜色不同 → 图案进行水平翻转（左右翻转）。
    - 上边界线和下边界线颜色不同，且左边界线和右边界线颜色不同 → 图案旋转 180 度。
  - 对于处在网格最外边缘的区域，缺失的边界线视为与对面边界线颜色相同（即不产生翻转效果）。
  - 输出网格尺寸和分隔线保持不变，每个区域内的图案被替换为变换后的版本，图案相对于区域中心进行对称变换。

- `Key insight`：分隔线的颜色看起来只是装饰，但实际上它们编码了变换指令。解题者需要发现"同色 vs 异色"这一二元判断分别控制水平和垂直两个轴的翻转——这是一个将颜色对称性映射到几何对称性的隐蔽对应关系。两条轴的判断相互独立，组合出四种变换结果。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
