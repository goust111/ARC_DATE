  - 网格中还有若干 grey 的单像素或小线段，作为"墙壁"障碍物。
  - 信号塔的臂不会穿过墙壁（即臂在遇到墙壁前终止）。

- `Rule`：
  - 第一层推理：确定每个信号塔的覆盖范围。覆盖范围定义为：从信号塔中心出发，沿上、下、左、右四个方向，臂能到达的最远距离（以臂的实际长度为准，不超过墙壁）。以该距离为半臂长，信号塔覆盖一个以中心为中心的矩形区域（宽 = 左臂长 + 右臂长 + 1，高 = 上臂长 + 下臂长 + 1）。
  - 第二层推理：对于网格中每个 black 背景像素，判断它落在哪些信号塔的覆盖矩形内。若仅被一个信号塔覆盖，则染成该塔的颜色。若被多个信号塔覆盖（重叠区域），则比较这些塔中朝向该像素方向的臂的长度——臂更长的塔"信号更强"，该像素染成信号更强的塔的颜色。若臂长相同，则该像素保持 black（信号抵消）。
  - 墙壁像素始终保持 grey，信号塔本身的像素保持原色不变。
  - 输出为所有背景像素染色后的完整网格。

- `Key insight`：十字形的臂长不仅决定覆盖矩形的大小（可见的几何属性），还在重叠区域充当信号强度的比较依据——解题者需要先从臂长推断覆盖范围（第一层），再发现重叠区域的"臂长比较"仲裁规则（第二层），两者缺一不可。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
