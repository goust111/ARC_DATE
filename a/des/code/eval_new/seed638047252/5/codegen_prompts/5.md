在网格中根据"路标"箭头依次连接散布的彩色节点，形成一条有序路径，路径线段的颜色由起点节点决定，终点节点决定下一段颜色。

Input structure:
- bg = 最常见颜色（如 black）。
- 若干个 3x3 的单色实心方块散布在网格中，每个方块颜色各不相同，称为"节点"。
- 每个节点（除最后一个外）的某一侧（上/下/左/右）紧邻一个由同色像素构成的 L 形"路标"箭头（占据 2x2 区域中的 3 个像素，缺失的角指示射出方向）。路标颜色与其所属节点颜色相同。
- 有一个节点没有路标，它是路径的终点。
- 有一个节点的路标颜色与节点自身颜色不同——路标使用的是另一个节点的颜色——它是路径的起点。起点节点路标的颜色指向它应连接的下一个节点。

Rule:
- 找到起点节点（路标颜色 ≠ 节点自身颜色的那个）。
- 起点节点的路标颜色 C₁ 指示下一个要连接的节点（即颜色为 C₁ 的节点）。
- 从起点中心沿路标箭头指示的方向（由 L 形缺角决定：缺角在 2x2 的哪个角落决定了向上/下/左/右中的一个方向）画一条一像素宽的直线段，颜色为起点节点的颜色，直到到达目标节点（C₁）的同行或同列，然后转 90° 朝向目标节点画到目标节点边缘停止。转角处的像素属于第一段颜色。
- 到达 C₁ 节点后，C₁ 节点的路标指示下一个目标节点 C₂，重复上述过程：从 C₁ 出发，画 C₁ 颜色的线段到 C₂。
- 依次类推，直到到达终点节点（无路标的节点）。
- 所有节点保持不变，路标箭头保持不变。

Key insight: 解题者需要发现三层嵌套规则——(1) 路标的 L 形缺角编码行进方向，(2) 路标颜色与节点颜色不同时标识起点、路标颜色指向下一目标节点形成链式连接顺序，(3) 连线采用正交折线且颜色继承出发节点——三层结构共同决定了路径拓扑和着色方案。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
