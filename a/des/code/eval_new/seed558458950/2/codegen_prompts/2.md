- `Input structure`：
  - 背景色 = black。
  - 网格中有若干个由 grey 像素绘制的矩形框（仅边框，内部为黑色），每个框的左上角外侧紧邻一个单色标记像素（如 red、blue、green 等），表示该框"接收"哪种颜色的碎片。

- `Rule`：
  - 第一层推理——归属匹配：每个碎片根据自身颜色归属到标记色相同的收纳框。
  - 第二层推理——方位映射放置：对于每个碎片，计算其重心相对于目标框中心的大致方位（上方、下方、左方、右方，取行差和列差中绝对值较大的方向；若相等则优先取垂直方向）。碎片被平移放入框的内部，贴靠对应方位的内壁。若同方位有多个碎片，则按碎片面积从大到小依次从内壁向框中心堆叠（紧贴排列，无间隔）。
  - 碎片原始位置处变为背景色；框的 grey 边框保留不变。

- `Key insight`：碎片的颜色决定"去哪个框"，但碎片在框内的摆放位置取决于它在输入网格中相对于目标框的空间方位——这一隐含的方位映射规则需要从多个样例中归纳发现。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
