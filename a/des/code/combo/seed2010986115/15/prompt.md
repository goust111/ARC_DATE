<description>
Untangle overlapping colored rectangular frames into concentric square frames ordered by their visible crossings.

Input structure
- The background contains several one-cell-thick axis-aligned rectangular frames, one color per frame.
- Frames overlap, and the visible color at an overlap records a directed crossing from the hidden frame to the visible frame.
- Each foreground color still has visible pixels on the perimeter of its full rectangular bounding box.

Rule
- Infer each color's full rectangular frame from the bounding box of its visible pixels.
- Add a directed edge A -> B when B is visible at a crossing of A and B's frame perimeters.
- Find the unique path that visits every frame color once, then render those colors as one-pixel-thick concentric square frames from outside to inside.

Key insight
- The output is not a crop of the input; the crossing graph gives a single frame order, and that order is redrawn as nested rings.

<description>
Expand the colored runs from the left reference panel into the blank right panel.

Input structure:
- A uniform rectangular frame surrounds the grid.
- One full-height divider of the frame color splits a left reference panel
  from a blank right panel.
- Both panels have one background margin column on each side of their active
  columns; the left active columns contain two-column endpoint slots, possibly
  connected by same-color horizontal runs.

Rule:
- Keep the original grid and paint only in the right panel's active columns.
- A source run exactly matching the left endpoint slot is copied to the left
  two columns of the right active span.
- A source run exactly matching the right endpoint slot is copied to the right
  two columns of the right active span.
- A source run connecting the endpoint slots is stretched across the entire
  right active span.

Key insight:
The left panel is a compressed legend for the right panel: endpoint markers
stay two pixels wide, while connectors between endpoints expand to fill the
distance between them.

<description>
Move each colored object vertically until it touches the matching top or bottom border bar.

Input structure:
- The background is the dominant color.
- The top row is a full-width bar in one foreground color and the bottom row is a full-width bar in another.
- All other foreground pixels are 8-connected monochrome objects whose color matches one of those bars.

Rule:
- Top-bar-colored objects move upward so their bbox top is row 1.
- Bottom-bar-colored objects move downward so their bbox bottom is the row above the bottom bar.
- A downward-moving one-column segment whose landing overlaps its source becomes the continuous vertical segment swept between them.

Key insight:
The horizontal bars are destination anchors: color determines which border an object slides toward, while columns and object shape are otherwise preserved.
</description>

<description>
Move each gray marker along its green path until it reaches the cell next to a black-green-black gate, erasing the path behind it.

- Place the marker on the unique path-color pixel adjacent to the gate center but not between the two gate ends.

Key insight: The black-green-black motif marks the stopping gate; the gray marker consumes the connected green path until it rests on the path cell immediately beside that gate.

<description>
Recover the bottom-to-top stacking order of overlaid rectangular color frames.

<description>
Eject content pixels from cup-shaped frames outward along each cup's tail direction.

Input structure:
- bg = background. Hollow cup/Y/funnel frames, each a unique border color.
- Each cup has a convergent tail spike on one side and an open mouth on the opposite side.
- Content pixels (a single non-border color per cup) sit inside the cup's mouth interior.

Rule:
- For each cup, identify its tail spike and tail direction.
- Erase all content pixels from the mouth interior.
- Draw a straight line of content-colored pixels from the spike outward in the tail direction,
  one pixel per erased content pixel; cells beyond the grid edge are dropped.

Key insight: The tail spike is the unique convergent point whose outward direction is opposite
the mouth opening where the content lives.
</description>

<description>
Recover the repeating background pattern hidden under the largest solid rectangle.

Input structure:
- The grid is covered by a small row/column periodic pattern.
- Several non-pattern colors form solid rectangular foreground objects that
  overwrite the pattern.
- The requested output region is the largest of those solid rectangles.

Rule:
- Find every 4-connected monochromatic object whose bounding box is a filled
  rectangle with both dimensions greater than one.
- Treat those rectangles as masks, infer the smallest repeating tile that is
  consistent with all remaining visible pixels, and repaint the largest
  rectangle's coordinates with that tile.

Key insight: The rectangle colors are occluders; the visible pixels outside
them are enough to reconstruct the original periodic background underneath.

<description>
Recolor every target pixel by following the ordered two-column substitution legend.

Input structure
- A dominant background surrounds one multicolor vertical legend: a connected,
  fully filled two-column block with one color pair per row.
- Other non-background pixels or objects are the targets; divider or frame
  pixels are ordinary target-side structure that remain unchanged unless their
  color is rewritten by the legend.

Rule
- Read the legend rows from top to bottom as substitutions from the left
  column color to the right column color.
- For each non-background pixel outside the legend, scan those rows in order;
  whenever the current color equals the row's left color, replace it with the
  row's right color and keep scanning lower rows.
- Leave the legend itself and background pixels unchanged.

Key insight
- The same color may be rewritten multiple times, but only by substitutions
  that appear later in the vertical legend, so the row order is part of the
  symbol instruction.
</description>

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式等人类能够直观感受计算的内容。
   - **不建议使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算 / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数等复杂且不易被看出来的计算。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息（例如颜色id是不可用的）或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。

6. 5 个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
8. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
9. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。以两层结构为例：
   - ✗ 伪两层："找到缺口方向"→"把东西推到对面" — 第一步肉眼可见，实际只有一层推理。
   - ✓ 真两层："通过孔洞数量匹配颜色图例"→"用匹配到的颜色重绘对象" — 两步都需要非平凡的归纳。

   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
10. 在符合ARC题目和提示词要求的基础上，鼓励尝试创新规则为多层结构的题目，不局限于两层，可以创新三层或四层结构的题目，但不可为了多结构层数违背要求。

1. 原创性

2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性

4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。
