网格中的每个封闭区域内含有一个"种子图案"和一个"方向箭头"；将种子图案沿箭头方向平铺复制，直到填满整个封闭区域。

Input structure:
- 背景为主色（如 black）。网格中有若干由 grey 像素绘制的不规则但封闭的围墙区域（围墙为单像素宽的连通闭合曲线，内部为背景色）。
- 每个围墙内部包含两个元素：（a）一个由某种非背景、非 grey 颜色组成的小型连通图案（种子图案），位于围墙内部的某个位置；（b）一个由 red 像素组成的 L 形箭头标记，由两段垂直线段组成——较长的一段表示主方向（水平或垂直），较短的一段（长度为 1 像素）连接在较长段的一端并垂直于主方向，形成箭头尖端，箭头尖端所指方向即为平铺方向。
- 种子图案的外接矩形能整除围墙内部区域在平铺方向上的长度。

Rule:
- 对每个围墙区域，识别其内部的种子图案和箭头方向。
- 将种子图案的外接矩形作为瓦片单元。
- 从种子图案当前位置开始，沿箭头指向的方向反复复制瓦片单元，直到到达围墙边界。每次复制时，新瓦片紧接前一个瓦片放置（无间隔）。
- 移除 red 箭头标记（恢复为背景色）。围墙保持不变。

Key insight:
解题者需要先识别 L 形标记的方向编码方式（较短端指向平铺方向），再理解种子图案是瓦片单元而非装饰物。箭头解码和瓦片平铺是两个独立的非显然推理层。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
