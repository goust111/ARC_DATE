- `Input structure`：
  - 背景为 Black。
  - 网格中散布若干个由 Grey 像素围成的封闭矩形区域（3x3 至 6x6 不等），每个区域内部恰好有一个由非背景、非 Grey 颜色组成的 L 形碎片（占据 3 个像素，构成直角形状）。
  - 在网格的某个角落有一个"模板字典"：一组并排的小方块，每个方块内展示一个完整的 L 形图案（占据 3 个像素）及其对应颜色，L 形的开口朝向四个基本方向之一（上、下、左、右）。模板字典中的每个 L 形颜色各不相同。

- `Rule`：
  - 第一步（模板匹配）：对于每个封闭区域内的 L 形碎片，在模板字典中找到颜色相同的完整 L 形模板。碎片可能经过旋转，需要确定碎片相对于模板的旋转量，从而推断出碎片在封闭区域内的实际朝向（即 L 形开口面向的方向）。
  - 第二步（边框延伸）：根据 L 形开口朝向的方向，从封闭矩形区域的对应边（开口朝左则取左边，朝上则取上边，以此类推）向外延伸一条与该边等宽的单像素厚边框，颜色与 L 形碎片颜色相同，延伸长度等于封闭区域内 L 形碎片未覆盖的空白像素数量。
  - 其余所有像素保持不变。

- `Key insight`：碎片本身只是模板的旋转副本——解题者必须先通过颜色匹配找到对应模板，再通过比对碎片与模板的形状差异推断旋转量和开口方向；开口方向决定了边框延伸的朝向，而区域内空白数量决定延伸长度。这是两层独立的非显然归纳。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
