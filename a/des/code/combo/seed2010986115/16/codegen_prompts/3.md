- `Input structure`：
  - 背景为 Black。
  - 网格的上边缘和左边缘各有若干段连续的彩色条带（由 Red、Blue、Green、Yellow 等颜色构成），条带之间由背景色间隔分隔。每段条带占据边缘的连续若干个像素。
  - 网格内部散布若干个由 Grey 构成的矩形实心障碍物。
  - 在网格的右下角有一个小的"颜色配对表"：一个 N×2 的小矩阵，左列是条带可能的颜色，右列是对应的"阴影颜色"（例如 Red 对应 Orange，Blue 对应 Magenta，Green 对应 Maroon，Yellow 对应 Azure）。

- `Rule`：
  - 上边缘的每段条带向下投射一束与条带等宽的垂直光柱（将条带正下方的整列背景像素染为条带颜色），直到碰到障碍物或网格底边为止。
  - 左边缘的每段条带向右投射一束与条带等高的水平光柱（将条带正右方的整行背景像素染为条带颜色），直到碰到障碍物或网格右边为止。
  - 当水平光柱与垂直光柱在同一个背景像素上交叉时，该像素保留上边缘光柱的颜色（上边缘光柱优先）。
  - 当光柱碰到障碍物时，光柱停止。同时，在障碍物被光柱照射的那一面（即障碍物面向光源的边缘像素），将这些 Grey 像素重新染色为颜色配对表中该光柱颜色对应的阴影颜色。障碍物未被照射的面保持 Grey。
  - 背景色像素若未被任何光柱覆盖则保持 Black。

- `Key insight`：解题者需要同时处理两个方向的投射并理解交叉优先级规则，但真正的隐蔽层在于障碍物表面的染色——阴影颜色不是光柱颜色本身，而是需要查阅右下角的配对表来确定。两层推理缺一不可：投射几何 + 配对表查找。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
