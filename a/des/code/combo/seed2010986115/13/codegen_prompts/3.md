将每个前景对象沿其内部"裂缝线"一分为二，然后根据裂缝线上标记点的颜色决定哪半部分保留、哪半部分被擦除。

Input structure:
- 背景为最常见颜色（如 black）。
- 网格中有若干大型单色前景对象（如 blue、green、red），每个对象内部恰好被一条由背景色构成的单像素宽直线（水平或垂直）贯穿，将对象分成两半——这条线称为"裂缝线"。
- 每条裂缝线上恰好有一个非背景、非对象颜色的标记像素（如 yellow、orange）。
- 网格角落有一个 2x2 的图例块：左上和右下各一个像素为背景色，另外两个像素分别为两种标记颜色。图例中标记颜色所在的位置（左下 vs 右上）编码了保留规则的方向。

Rule:
- 对每个被裂缝线分割的对象，确定裂缝线的方向（水平或垂直）以及标记像素在裂缝线上的位置。
- 查看图例：如果标记颜色在图例中位于左下角，则保留该标记颜色所在裂缝线以下（水平裂缝）或以左（垂直裂缝）的半部分；如果标记颜色在图例中位于右上角，则保留以上或以右的半部分。
- 被擦除的半部分变为背景色，裂缝线和标记像素也变为背景色，保留的半部分颜色不变。

Key insight:
第一层推理需要识别对象内部的背景色直线是"裂缝"而非普通间隙，并注意裂缝上的标记像素；第二层推理需要破解角落图例的编码——标记颜色在图例中的空间位置（左下 vs 右上）映射为保留方向（下/左 vs 上/右），这是一个非平凡的空间-语义映射。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
