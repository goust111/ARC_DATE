Input structure：
- 背景为黑色。
- 网格中散布若干由同一颜色（如 blue）绘制的矩形框架，每个框架恰好缺失一条边（即四边中有一边完全缺失，形成一个 U 形开口）。
- 框架内部区域全部为黑色背景。
- 在所有框架的外部，散布若干单色小方块（2x2），每个小方块的颜色各不相同。每个小方块恰好紧贴某一个框架的外侧，且紧贴的那一面正对该框架的缺失边所在方位。
- 也存在一些小方块紧贴在框架的完整边外侧，这些是干扰项。

Rule：
- 对每个框架，找到其缺失边的方位（上、下、左、右）。
- 在紧贴该框架外侧的所有小方块中，找到位于缺失边对面方位的那个小方块（即：若缺失边在上方，则选取紧贴框架下方外侧的小方块；若缺失边在左方，则选取紧贴框架右方外侧的小方块）。
- 用该小方块的颜色填充框架内部的全部黑色区域。
- 框架本身的颜色、所有小方块均保持不变。

Key insight：
- 缺失边的方位不是直接指向填充色源，而是需要取其对面方位——开口朝上的框架要去下方找色源。紧贴完整边的小方块是干扰项，解题者需要先判断缺失边方位，再做方向反转，才能确定正确的颜色来源。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
