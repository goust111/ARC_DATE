将散落的彩色箭头精灵按其指向方向依次推入对应边缘的停靠槽中，箭头到达槽位后以槽的颜色重绘。

Input structure:
- 背景为主色（black）。
- 网格四条边各有若干单像素宽的"停靠槽"标记：每个标记是一个非背景色像素，位于边缘行或列上，不同边的标记颜色可能不同。上边缘的标记表示从上方接收、下边缘的标记表示从下方接收，左右同理。
- 网格内部散布若干由同一前景色（如 red）绘制的箭头形精灵。每个箭头精灵恰好占据5个像素：一个十字中心像素加上沿四个正方向之一延伸的两个像素构成箭头杆，以及垂直于杆方向的两个像素构成箭头尖端，整体呈"指向某方向"的箭头形状。具体地，箭头朝上时形状为：第1行中间一个像素，第2行左中右三个像素，第3行中间一个像素（共5像素，尖端朝上）。朝其他方向时按相应旋转。
- 每个箭头的指向方向对应网格的上、下、左、右四个边之一。

Rule:
- 对每个箭头精灵，确定其指向方向（上/下/左/右）。
- 沿该方向找到箭头尖端像素所在行或列上的边缘停靠槽标记。若箭头朝上，则在箭头尖端所在列的上边缘寻找标记；若朝左，则在箭头尖端所在行的左边缘寻找标记。
- 将箭头精灵平移至该方向的边缘，使箭头尖端像素恰好与停靠槽标记重合。
- 平移后的箭头精灵用停靠槽标记的颜色重绘所有5个像素。
- 擦除箭头原始位置的像素（还原为背景色）。

Key insight:
箭头的朝向不仅决定移动方向，还决定了在哪条边缘上搜索匹配槽位；而最终颜色由目标槽位的颜色决定，非箭头自身颜色——解题者需要同时推断方向-边缘-列/行对齐三重关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
