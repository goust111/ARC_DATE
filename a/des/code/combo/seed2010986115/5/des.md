- `description`：根据每个封闭区域内部种子色块的朝向，选择对应的填充模板对该区域进行着色。
- `Input structure`：
  - 背景为黑色（Black）。
  - 灰色（Grey）像素构成若干不规则但封闭的单像素宽围栏，将网格分割成多个互不相通的封闭区域。
  - 每个封闭区域内部恰好有一个由两个相邻同色像素组成的"种子色块"，种子色块的颜色各不相同（可能为 Red、Blue、Green、Yellow 等）。两个像素的排列方向为水平或垂直。
  - 网格的一个角落（例如左上角）存在一个独立的"模板区"，模板区由灰色围栏包围，内部包含两个子区域：一个标注"水平"模板、一个标注"垂直"模板。每个子区域内用橙色（Orange）像素画出一个小型填充图案（例如水平条纹、垂直条纹、棋盘格等），两个子区域的图案不同。模板区内的两个子区域分别包含一个水平排列的双像素标记和一个垂直排列的双像素标记，标记颜色为 Azure，用于指示该子区域对应的朝向。
- `Rule`：
  - 首先识别模板区中两种填充图案：水平种子对应的图案 P_h 和垂直种子对应的图案 P_v。图案以橙色像素的相对坐标集合表示。
  - 对网格中每个非模板的封闭区域，判断其内部种子色块是水平排列还是垂直排列。
  - 若种子色块为水平排列，则用该种子的颜色按照 P_h 图案平铺填充整个封闭区域的黑色像素（图案以种子色块左上角为锚点进行周期性平铺，仅填充区域内部的黑色像素，不覆盖种子本身和灰色围栏）。
  - 若种子色块为垂直排列，则用该种子的颜色按照 P_v 图案平铺填充。
  - 模板区在输出中保持不变。灰色围栏保持不变。
- `Key insight`：解题者需要完成两层推理：第一层是识别模板区中 Azure 标记的朝向与橙色图案之间的对应关系，建立"朝向→图案"的映射；第二层是观察每个封闭区域内种子色块的排列方向，选取正确的填充图案并用种子自身的颜色进行平铺。种子色块的颜色和朝向是两个独立维度——颜色决定填充色，朝向决定填充纹理。
</new_puzzle>

- `description`：将散落的彩色碎片按形状匹配拼入对应的灰色镂空模具中，碎片需要旋转到正确朝向后才能嵌入。
- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中有若干灰色（Grey）实心矩形块，每个矩形块内部被挖去了一个不规则的连通区域（镂空部分显示为黑色），形成"模具"。每个模具的镂空形状各不相同。
  - 每个灰色矩形块的外边框上恰好有一个单像素的彩色标记点（颜色各不相同，如 Red、Blue、Green 等），标记点位于矩形的上、下、左、右四条边中的某一条上。
  - 网格的空白区域散落着若干彩色碎片，每个碎片是一个单色的 4-连通区域，碎片颜色与某个模具的边框标记颜色相同。每个碎片的形状与恰好一个模具的镂空形状全等（可能需要旋转 0°、90°、180° 或 270°）。
- `Rule`：
  - 通过颜色匹配将每个碎片与其对应的模具配对（碎片颜色 = 模具边框标记颜色）。
  - 确定旋转角度：模具边框上标记点所在的边指示碎片嵌入时的"入口方向"。具体地，碎片在散落状态下的最上方像素行视为碎片的"头部"；旋转碎片使其"头部"朝向标记点所在边的内侧方向（标记在上边 → 头部朝下即旋转 180°；标记在右边 → 头部朝左即旋转 90° 逆时针；标记在下边 → 头部不旋转即 0°；标记在左边 → 头部朝右即旋转 90° 顺时针）。
  - 将旋转后的碎片精确放入模具的镂空区域中（碎片像素替换镂空处的黑色像素）。
  - 清除原始散落碎片的位置（恢复为黑色背景）。
- `Key insight`：解题者需要三层推理：第一层是通过颜色将碎片与模具配对；第二层是识别碎片形状与镂空形状的全等关系（可能需要心理旋转）；第三层是发现标记点位置编码了旋转方向的规则——标记不是装饰，而是指定碎片应如何旋转后才能正确嵌入。
</new_puzzle>

- `description`：根据每条路径穿越彩色门的颜色种类组合，从训练样例中归纳混色规则，对路径终点区域进行填色。
- `Input structure`：
  - 背景为黑色（Black）。
  - 灰色（Grey）像素构成单像素宽的直线段网络，形成若干条从网格边缘出发向内延伸的路径。路径不分叉，每条路径从边缘起始，终止于一个 3×3 的灰色实心方块（"终点站"）。
  - 路径上间隔分布着若干"门"：每扇门是横跨路径的一对彩色像素（路径像素两侧各一个），门的颜色从以下三种中选取：Red、Blue、Yellow。同一条路径上可能有多扇不同颜色的门。
  - 所有终点站在输入中内部为灰色实心。
- `Rule`：
  - 沿每条路径从边缘起点向终点站方向遍历，记录经过的门的颜色种类集合（忽略重复，只关心出现了哪些颜色）。
  - 根据颜色组合确定终点站的填充色：
    - 若只经过 Red 门 → 终点站填 Red。
    - 若只经过 Blue 门 → 终点站填 Blue。
    - 若只经过 Yellow 门 → 终点站填 Yellow。
    - 若经过 Red + Blue → 终点站填 Magenta。
    - 若经过 Red + Yellow → 终点站填 Orange。
    - 若经过 Blue + Yellow → 终点站填 Green。
    - 若经过 Red + Blue + Yellow → 终点站填 Maroon。
  - 用对应颜色填充终点站 3×3 方块的中心 1 个像素（周围 8 个灰色像素作为边框保持不变）。
  - 路径本身和门保持不变。
- `Key insight`：解题者需要两层非平凡推理：第一层是从网格中识别路径拓扑，确定哪些门属于哪条路径；第二层是从多个训练样例中归纳出颜色种类的组合映射规则——这是题目自定义的离散映射表，需要通过观察不同路径的门颜色组合与终点站填色的对应关系来总结。每扇门的出现次数不影响结果，只有颜色种类参与组合。

- `description`：将网格中每个彩色对象按照其所在象限对应的复合变换方式（由角落指示器决定）进行几何变换，并将结果叠加到目标象限。
- `Input structure`：
  - 背景为黑色（Black）。
  - Azure 颜色的像素构成一个贯穿整个网格的十字线（一条完整的水平线和一条完整的垂直线交于网格中心），将网格分为四个象限。
  - 四个象限中各有零个或多个单色 4-连通对象（颜色可为 Red、Green、Yellow、Blue 等）。对象不接触十字线。
  - 在十字线与网格边缘的四个交汇角落处（即网格的四个角各留出一个 2×2 区域），各有一个 2×2 的指示色块。四个角的指示色块颜色两两配对：对角线上的两个角颜色相同（例如左上角和右下角都为 Red，右上角和左下角都为 Green）。共有两种指示颜色，分别对应两种变换方式。
- `Rule`：
  - 识别两种指示颜色及其对应的变换方式。需从训练样例中归纳：一种指示颜色代表"沿十字线做镜像翻转"（对象翻转到十字线对侧的镜像位置，形状发生左右或上下翻转），另一种指示颜色代表"关于网格中心做 180° 点对称旋转"（对象旋转到关于中心点对称的象限，形状旋转 180°）。
  - 每个象限由其相邻的两个角落指示。对该象限中的对象，先执行与该象限同行的水平边角落（位于上边或下边）指示的变换，再执行与该象限同列的垂直边角落（位于左边或右边）指示的变换，得到最终的目标位置和形状。
  - 变换后的对象绘制到目标位置，原始对象保留在原位。
  - 十字线和角落指示色块保持不变。若变换后的对象与其他像素重叠，后绘制的覆盖先绘制的（按象限从左上、右上、左下、右下的顺序处理）。
- `Key insight`：解题者需要三层推理：第一层是发现角落色块是变换指示器而非装饰，注意到对角颜色相同这一结构线索；第二层是从训练样例中归纳出每种指示颜色对应哪种几何变换（镜像翻转 vs 点对称旋转）；第三层是理解每个象限受两个角落的复合变换控制，两步变换的施加顺序由角落的空间位置（水平边 vs 垂直边）决定，复合后的结果与单步变换不同。
</new_puzzle>

<new_puzzle>
- `description`：根据每个封闭房间内"窗户"的数量，从色带图例中查找对应颜色填充房间地板，并将窗户封闭为墙壁色。
- `Input structure`：
  - 背景为黑色（Black）。
  - 灰色（Grey）像素构成单像素宽的墙壁网络，将网格划分为若干互不连通的矩形"房间"。每个房间内部为黑色。
  - 墙壁上存在一些"窗户"：窗户是墙壁线段中被替换为 Azure 颜色的单个像素。每个窗户像素的两侧分别连接一个房间和网格外部（或另一个房间）。一个房间拥有的窗户数量是该房间四面墙上所有 Azure 像素的总数（范围在 1 到 5 之间）。
  - 网格的底部有一条水平的"色带图例"，与主网格之间由一行灰色墙壁分隔。色带由 5 个连续的彩色单元格组成，从左到右依次为第 1 格到第 5 格，每格颜色不同（例如依次为 Red、Blue、Green、Yellow、Magenta）。色带下方无额外内容。
- `Rule`：
  - 数出每个房间四面墙壁上 Azure 像素（窗户）的总数 N（1 ≤ N ≤ 5）。
  - 在底部色带图例中找到从左数第 N 格的颜色 C。
  - 用颜色 C 填充该房间内部所有黑色像素（不覆盖灰色墙壁像素，也不覆盖窗户像素所在位置）。
  - 将该房间墙壁上的所有 Azure 窗户像素改为灰色（Grey），使窗户"关闭"变回普通墙壁。
  - 色带图例本身在输出中保持不变。网格外部的黑色背景保持不变。
- `Key insight`：解题者需要两层非平凡推理：第一层是发现墙壁中穿插的 Azure 像素不是随机噪声或装饰，而是可以按房间归属进行计数的"窗户"标记，其数量是区分各房间的关键属性；第二层是发现底部色带是一个以位置为索引的颜色查找表——窗户数量 N 对应色带中第 N 个位置的颜色。输出中窗户被封回灰色这一变化进一步确认了窗户仅作为输入中的计数线索，不参与最终结构。
</new_puzzle>
