Input structure:
- 背景为black。网格被一条水平azure线和一条垂直azure线精确地分为四个象限。
- 每个象限内包含：恰好一个由单一非black非azure颜色构成的4-连通对象，以及恰好一个由yellow像素构成的箭头标记。
- 箭头标记由3个yellow像素组成：一个中心像素和两个与中心像素相邻的像素，三者构成一个指向上、下、左或右的箭头形状（例如指向右的箭头：中心像素左侧一个像素加上中心像素上方一个像素加上中心像素本身，形成直角折线指向右方）。具体地：指向右=中心+左+上三像素组成的直角折线开口朝右，指向左=中心+右+上三像素组成的直角折线开口朝左，指向上=中心+下+左三像素组成的直角折线开口朝上，指向下=中心+上+左三像素组成的直角折线开口朝下。

Rule:
- 对每个象限中的对象，根据该象限内箭头指向的方向进行翻转：箭头指左或指右则水平翻转，箭头指上或指下则垂直翻转。
- 输出为一个新的画布（大小等于单个象限的内部空间大小，不含azure分隔线），背景为black。

Key insight:
解题包含三层独立推理：（1）识别箭头方向并理解其编码的翻转轴（水平翻转还是垂直翻转）；（2）按面积排序决定绘制顺序；（3）多对象合成到单一画布时的覆盖逻辑。箭头的形状需要从样例中归纳出方向与翻转轴的对应关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
