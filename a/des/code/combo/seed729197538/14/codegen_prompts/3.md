- `description`：利用网格中"路径交叉点"的邻居颜色投票决定交叉点自身的着色，然后将每条路径上非交叉点的像素替换为该路径所经过的所有交叉点颜色中出现最多的那个颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条由 grey 像素构成的直线路径（水平或垂直），宽度为 1 像素。
  - 这些路径相互交叉，交叉点处为 grey。
  - 在某些路径的非交叉位置上，紧邻路径（上下或左右相邻，但不在路径上）放置有单个彩色像素（如 red、blue、green、yellow 等），这些是"投票标记"。
  - 每个交叉点的四个正交邻居中，可能有 0 到 4 个投票标记。

- `Rule`：
  - 第一层推理（交叉点着色）：对每个交叉点，收集其四个正交邻居位置中所有投票标记的颜色。如果存在投票标记，则交叉点着色为出现次数最多的颜色（若平局，则选择在上、右、下、左优先顺序中最先出现的颜色）。如果交叉点周围没有投票标记，则保持 grey。
  - 第二层推理（路径着色）：每条路径（水平或垂直的连续 grey 段）经过若干个交叉点。统计该路径上所有已着色（非 grey）交叉点的颜色，将路径上所有非交叉点的 grey 像素替换为这些颜色中出现最多的颜色。若该路径上没有已着色的交叉点，则路径保持 grey。
  - 投票标记像素在输出中保持原样。

- `Key insight`：交叉点是两条路径的共享节点——解题者首先需要发现交叉点颜色由局部邻居投票决定，然后需要发现路径颜色由其所有交叉点颜色的全局多数投票决定。两层投票机制层层递进，第二层依赖第一层的结果。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
