在一个包含多个相似但略有差异的图案副本的网格中，找出每对副本之间的差异像素，并用差异像素的局部坐标作为平移向量，将一个隐藏在角落的小型"种子"图案沿该向量方向复制。

Input structure：
- 背景为 black。
- 网格中有一个由某种颜色（如 blue）绘制的"参考图案"，以及该图案的若干个副本，副本使用与参考图案相同的颜色。参考图案和每个副本尺寸、形状几乎完全相同，但每个副本恰好有一个像素位置与参考图案不同（要么多了一个像素，要么少了一个像素）。
- 网格的某个角落有一个由 red 像素组成的小型图案（"种子"），尺寸远小于参考图案。
- 参考图案位于网格的固定位置（如左上区域），可通过其完整性和位置识别。

Rule：
- 将每个副本与参考图案逐像素比较，找出差异像素在副本内部的局部坐标 (dr, dc)。
- 每个差异点的局部坐标 (dr, dc) 定义一个平移向量。
- 将 red 种子图案按每个平移向量分别复制一份：即在种子图案原始位置的基础上偏移 (dr, dc) 处绘制一份种子图案的副本（使用 green 颜色）。
- 参考图案、blue 副本和原始 red 种子在输出中保持不变。

Key insight：
- 第一层推理：需要识别哪个 blue 图案是"参考"（最完整或位于特定位置的那个），哪些是副本；第二层推理：需要发现每个副本与参考之间恰好一个像素的差异，并提取差异的局部坐标；第三层推理：需要理解这些局部坐标不是标记位置，而是作为平移向量施加到种子图案上，从而生成种子的多份偏移副本。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
