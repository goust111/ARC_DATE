将网格中散落的同色像素对视为"传送门"，把每个非传送门的前景对象通过其接触的传送门颜色转移到同色传送门的对称位置，并在转移后按目标传送门的局部朝向旋转对象。

Input structure：
- 背景为 black。
- 网格中有若干成对出现的单像素标记，每对共享同一颜色（如 red、blue、green 等），每种颜色恰好出现两个像素，构成一对传送门。
- 每个传送门像素恰好与一个由 grey 像素组成的 4-连通前景对象相邻（4-邻域接触）。
- 每个传送门像素位于其相邻对象的某一侧（上、下、左、右），这个方位定义了该传送门的"入口朝向"。

Rule：
- 对每个前景对象，找到与其 4-邻域接触的传送门像素的颜色，再找到同颜色的另一个传送门像素。
- 计算两个传送门像素的"入口朝向"之间的旋转差（例如：源传送门朝向为"右"即对象在传送门左侧，目标传送门朝向为"下"即目标对象应出现在传送门上方，则旋转差为顺时针 90 度）。
- 将该前景对象按此旋转差旋转后，放置到目标传送门像素的对应朝向一侧，使旋转后的对象与目标传送门像素相邻。
- 源位置的对象和传送门像素均被擦除（变为背景色）。

Key insight：
- 第一层推理：需要识别成对同色像素是传送门，对象通过传送门转移位置；第二层推理：需要发现传送门的朝向（即传送门相对于对象的方位）决定了对象在目标位置的旋转角度——这不是简单的平移，而是带旋转的映射。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
