<description>
根据每个封闭区域内部散点的颜色，在边栏颜色图例中查找对应的填充色，再用该填充色替换区域内所有散点。

Input structure:
- 背景为主色（如 black）。
- 网格中存在若干个由同一颜色绘制的封闭矩形边框（边框宽度为 1 像素），每个边框颜色各不相同。
- 在网格的最左列，有一列竖排的颜色图例：每个图例条目由上下两个相邻像素组成，上方像素颜色是"散点颜色"，下方像素颜色是"填充颜色"。相邻图例条目之间间隔至少一个背景像素。
- 每个封闭矩形边框的内部散布着若干个同色的单像素散点，散点颜色与边框颜色不同。不同矩形内部的散点颜色可能不同。

Rule:
- 对每个封闭矩形边框，识别其内部所有散点的颜色（每个矩形内部只有一种散点颜色）。
- 在最左列的颜色图例中查找该散点颜色对应的填充颜色（即图例条目中上方像素匹配散点颜色时，下方像素即为填充颜色）。
- 将该矩形边框内部的所有散点像素替换为查找到的填充颜色。
- 边框本身、图例本身以及背景均保持不变。

Key insight:
- 解题需要两步非平凡归纳：第一步是发现边栏的双像素条目构成颜色映射图例（上→下 = 散点色→填充色）；第二步是发现每个矩形内部的散点颜色充当查表键，而非边框颜色。两层结构缺一不可。
</description>

<description>
将网格中成对的同色锚点用直线连接，连线穿过的每个前景对象整体按该连线颜色重新着色，锚点自身消失。

Input structure:
- 背景为主色（如 black）。
- 网格中散布着若干个不同颜色的 4-连通单色前景对象（面积 >= 3），形状各异。
- 另有若干对孤立的单像素锚点，每对锚点颜色相同且在整个网格中只出现两个该色像素；不同对锚点颜色不同。
- 每对锚点要么处于同一行，要么处于同一列（即可用水平或垂直直线连接）。
- 每条锚点连线恰好穿过一个或多个前景对象的像素。

Rule:
- 对每对同色锚点，沿它们之间的行或列画一条虚拟直线（不实际画出）。
- 沿该直线穿过的所有前景对象（即直线上有像素属于该对象），将整个对象（包括直线未经过的像素）全部重新着色为该对锚点的颜色。
- 锚点像素本身在输出中被擦除为背景色。
- 未被任何连线穿过的前景对象保持原色不变。
- 题目设计保证不会有一个对象被多条连线穿过。

Key insight:
- 第一层推理：识别出孤立单像素是成对的锚点，且每对处于同行或同列；第二层推理：发现连线不是简单地画出来，而是作为"选择器"——穿过哪个对象就将整个对象染成连线的颜色，锚点自身消失。
</description>

<description>
每个彩色种子像素向四个正方向发射射线，射线长度等于该种子所在封闭房间的内部空白面积；射线遇到墙壁提前截断，否则穿出房间继续延伸。

Input structure:
- 背景为主色（如 black）。
- 一种颜色（如 grey）构成若干个封闭的矩形"房间"，即用 grey 像素围成的完整矩形边框（1 像素宽）。各房间大小不同，互不重叠，房间之间有背景间隔。
- 每个房间内部恰好有一个非背景、非边框色的彩色单像素"种子"，不同房间的种子颜色可能相同也可能不同。
- 房间外部全是背景色。

Rule:
- 对每个房间，计算其内部空白像素数量（即边框围成的内部面积减去种子占用的 1 个像素）。该数值记为 L。
- 从种子位置向上、下、左、右四个方向各发射一条射线，每条射线最大长度为 L 个像素。
- 射线逐像素延伸：遇到 grey 边框像素时立即截断（不覆盖边框像素），遇到背景像素则将其绘制为种子颜色，遇到网格边界则停止。
- 射线可以穿出房间的开口——但由于房间是完整封闭的矩形，射线在房间内部必然会碰到边框而截断。因此射线只在房间内部生效，长度受 L 和边框位置双重限制。
- 种子像素本身保持不变，边框保持不变。

Key insight:
- 第一层推理：发现每个种子发射的射线长度并非固定，而是由其所在房间的空白面积决定——需要数出房间内部的空像素数。第二层推理：不同大小的房间产生不同长度的射线，而种子在房间内的偏心位置导致四个方向的射线实际被墙壁截断的长度各不相同——射线的"最大长度"和"实际长度"之间的差异是关键观察点。
</description>
</new_puzzle>

<description>
在由分隔线划分的若干子区域中，每个区域内的前景形状按照该区域内标记像素数量进行 90 度顺时针旋转，旋转中心为形状内嵌入的异色锚点像素。

Input structure:
- 背景为主色（如 black）。
- 一种颜色（如 blue）形成若干条完整的横向和纵向分隔线，将整个网格划分为矩形子区域。
- 每个子区域内恰好包含一个由某种前景色构成的 4-连通形状（面积 >= 2），以及 1 至 3 个 red 单像素标记。
- 每个形状内部有一个特殊的"锚点像素"，其颜色与形状其余像素不同（如形状为 green，锚点为 yellow）。该锚点在每个形状中唯一。

Rule:
- 对每个子区域，数出该区域内 red 标记像素的个数 N（N 取值 1、2 或 3）。
- 将该区域内的前景形状以锚点像素为旋转中心，顺时针旋转 N * 90 度。
- 旋转后的形状绘制在输出中，锚点位置不变；若旋转后形状超出子区域边界则沿边界裁剪不绘制。
- 擦除原始形状位置中与旋转后位置不重叠的像素（恢复为背景色）。
- Red 标记像素在输出中被擦除为背景色。
- 分隔线保持不变。

Key insight:
- 第一层推理：发现 red 标记的数量决定了旋转次数（1 个 = 90 度，2 个 = 180 度，3 个 = 270 度），而非标记的位置或排列方式。第二层推理：旋转中心不是形状的几何中心或区域中心，而是形状内部嵌入的那个异色锚点像素——需要同时识别出锚点的存在和它作为旋转支点的功能。
</description>

<description>
将网格中散落的同色像素组按颜色分组，计算每组的最小包围矩形面积，根据面积排名在底部图例色条中查找对应位次的颜色，用该颜色替换整组像素。

Input structure:
- 背景为主色（如 black）。
- 网格底部最后一行是一条颜色图例条，从左到右排列着若干个不同颜色的单像素，彼此紧邻，颜色各不相同。图例条中的颜色总数等于上方前景颜色组的数量。图例条从左到右表示名次：最左 = 第 1 名（最小面积），依次递增。
- 网格其余区域散布着若干种颜色的前景像素。同一颜色的所有前景像素构成一组。
- 每组像素在空间上可能不连通（即同色像素可以分散在网格各处）。

Rule:
- 对每种前景颜色组，计算其所有像素的最小包围矩形的面积（即包含该组所有像素的最小轴对齐矩形的宽 * 高）。
- 将所有颜色组按其包围矩形面积从小到大排序，得到排名（题目保证面积互不相同）。
- 排名第 k 的颜色组，其所有像素被重新着色为底部图例条从左数第 k 个颜色。
- 底部图例条在输出中保持不变。
- 背景保持不变。

Key insight:
- 第一层推理：需要发现每组同色像素的最小包围矩形面积是关键属性——尽管像素可能稀疏分布，但其 bounding box 面积才是排序依据，而非像素个数或连通区域数。第二层推理：底部色条是一个按位次排列的重着色图例，位次对应面积排名而非空间位置关系，需要将排序结果映射到图例上完成颜色替换。
</description>

<new_puzzle>
<description>
每个前景对象的封闭孔洞数量决定平移方向（由四角方向标记指定），孔洞面积之和决定平移距离。

Input structure:
- 背景为主色（如 black）。
- 网格的四个角各有一个 2x2 的彩色方块作为方向标记，四个角的颜色各不相同。这四个角分别对应四个平移方向：左上角 = 向左，右上角 = 向上，左下角 = 向下，右下角 = 向右。
- 网格中央区域分布着若干个 4-连通的单色前景对象（颜色与四个角标记均不同），每个对象包含 1 至 4 个由背景色构成的封闭孔洞（孔洞定义：被该对象像素完全 4-连通包围的背景连通区域）。
- 不同对象的孔洞数量不同，恰好覆盖 1 到 4 的某个子集。

Rule:
- 对每个前景对象，数出其封闭孔洞的数量 H（1 至 4）。
- H = 1 对应左上角标记的方向（向左），H = 2 对应右上角标记的方向（向上），H = 3 对应左下角标记的方向（向下），H = 4 对应右下角标记的方向（向右）。
- 计算该对象所有孔洞的总面积（总像素数）S。
- 将该对象从原位置擦除为背景色，沿对应方向平移 S 个像素后重新绘制。
- 孔洞随对象一起移动（保持形状不变）。
- 若平移后对象部分超出网格边界，则超出部分裁剪不绘制。
- 四角的方向标记在输出中保持不变。

Key insight:
- 第一层推理：发现四角的彩色方块不是装饰而是方向编码图例，且孔洞数量是查表键——1 个孔洞对应哪个角需要从样例中归纳出固定映射。第二层推理：平移距离并非固定，而是由孔洞的面积之和决定——不仅要数孔洞个数确定方向，还要量孔洞大小确定距离。两个属性（数量→方向，面积→距离）同时从孔洞中提取，构成双重编码。
</description>

<description>
沿箭头形状所指方向搜索目标对象，将目标对象"吸回"到箭头尾部放置，并按箭头颜色重新着色。

Input structure:
- 背景为主色（如 black）。
- 网格中有若干个"箭头"形状，每个箭头由两部分组成：一个 1 像素宽的水平或垂直直线段（长度 >= 2）作为"杆"，以及杆的一端附带一个由 3 个像素构成的三角尖端。以向右的箭头为例：杆为水平线段，尖端在杆最右端像素的右侧一列，由该列上中下三行中的上、中、下三个像素组成（中间像素与杆对齐，上下像素在中间像素的上方和下方各一行），形成 ">" 形。向左、向上、向下的箭头类似地旋转。杆和尖端使用同一种颜色。
- 网格中还有若干个由不同颜色构成的小型 4-连通前景对象（面积 2 至 6），这些是"目标对象"。
- 每个箭头的尖端方向上，沿射线可以遇到恰好一个目标对象（射线扫描沿杆的延长线方向）。

Rule:
- 对每个箭头，从尖端沿箭头所指方向做射线扫描（沿杆的延长线方向），找到射线碰到的第一个目标对象。
- 将该目标对象从原位置擦除为背景色。
- 将目标对象的形状（保持原始朝向不变）平移到箭头杆的尾端（与尖端相反的一端），使得目标对象最靠近箭头方向的边缘像素紧贴杆尾端外侧 1 像素处。
- 目标对象被重新着色为箭头的颜色。
- 箭头本身保持不变。

Key insight:
- 第一层推理：需要识别出箭头的方向性结构——杆加三角尖端的组合编码了方向，方向决定了射线搜索的路径。第二层推理：目标对象不是被推向箭头所指方向，而是被"吸回"到箭头尾部并变色——这是一个反直觉的操作方向，需要从样例中归纳出"尖端搜索、尾部放置"的规则，而非直觉上的"尖端推送"。
</description>
</new_puzzle>
