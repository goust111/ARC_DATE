在由分隔线划分的若干子区域中，每个区域内的前景形状按照该区域内标记像素数量进行 90 度顺时针旋转，旋转中心为形状内嵌入的异色锚点像素。

Input structure:
- 背景为主色（如 black）。
- 一种颜色（如 blue）形成若干条完整的横向和纵向分隔线，将整个网格划分为矩形子区域。
- 每个子区域内恰好包含一个由某种前景色构成的 4-连通形状（面积 >= 2），以及 1 至 3 个 red 单像素标记。
- 每个形状内部有一个特殊的"锚点像素"，其颜色与形状其余像素不同（如形状为 green，锚点为 yellow）。该锚点在每个形状中唯一。

Rule:
- 对每个子区域，数出该区域内 red 标记像素的个数 N（N 取值 1、2 或 3）。
- 将该区域内的前景形状以锚点像素为旋转中心，顺时针旋转 N * 90 度。
- 旋转后的形状绘制在输出中，锚点位置不变；若旋转后形状超出子区域边界则沿边界裁剪不绘制。
- 擦除原始形状位置中与旋转后位置不重叠的像素（恢复为背景色）。
- Red 标记像素在输出中被擦除为背景色。
- 分隔线保持不变。

Key insight:
- 第一层推理：发现 red 标记的数量决定了旋转次数（1 个 = 90 度，2 个 = 180 度，3 个 = 270 度），而非标记的位置或排列方式。第二层推理：旋转中心不是形状的几何中心或区域中心，而是形状内部嵌入的那个异色锚点像素——需要同时识别出锚点的存在和它作为旋转支点的功能。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
