将网格中散落的同色像素组按颜色分组，计算每组的最小包围矩形面积，根据面积排名在底部图例色条中查找对应位次的颜色，用该颜色替换整组像素。

Input structure:
- 背景为主色（如 black）。
- 网格底部最后一行是一条颜色图例条，从左到右排列着若干个不同颜色的单像素，彼此紧邻，颜色各不相同。图例条中的颜色总数等于上方前景颜色组的数量。图例条从左到右表示名次：最左 = 第 1 名（最小面积），依次递增。
- 网格其余区域散布着若干种颜色的前景像素。同一颜色的所有前景像素构成一组。
- 每组像素在空间上可能不连通（即同色像素可以分散在网格各处）。

Rule:
- 对每种前景颜色组，计算其所有像素的最小包围矩形的面积（即包含该组所有像素的最小轴对齐矩形的宽 * 高）。
- 将所有颜色组按其包围矩形面积从小到大排序，得到排名（题目保证面积互不相同）。
- 排名第 k 的颜色组，其所有像素被重新着色为底部图例条从左数第 k 个颜色。
- 底部图例条在输出中保持不变。
- 背景保持不变。

Key insight:
- 第一层推理：需要发现每组同色像素的最小包围矩形面积是关键属性——尽管像素可能稀疏分布，但其 bounding box 面积才是排序依据，而非像素个数或连通区域数。第二层推理：底部色条是一个按位次排列的重着色图例，位次对应面积排名而非空间位置关系，需要将排序结果映射到图例上完成颜色替换。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
