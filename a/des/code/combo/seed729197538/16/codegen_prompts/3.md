每个彩色种子像素向四个正方向发射射线，射线长度等于该种子所在封闭房间的内部空白面积；射线遇到墙壁提前截断，否则穿出房间继续延伸。

Input structure:
- 背景为主色（如 black）。
- 一种颜色（如 grey）构成若干个封闭的矩形"房间"，即用 grey 像素围成的完整矩形边框（1 像素宽）。各房间大小不同，互不重叠，房间之间有背景间隔。
- 每个房间内部恰好有一个非背景、非边框色的彩色单像素"种子"，不同房间的种子颜色可能相同也可能不同。
- 房间外部全是背景色。

Rule:
- 对每个房间，计算其内部空白像素数量（即边框围成的内部面积减去种子占用的 1 个像素）。该数值记为 L。
- 从种子位置向上、下、左、右四个方向各发射一条射线，每条射线最大长度为 L 个像素。
- 射线逐像素延伸：遇到 grey 边框像素时立即截断（不覆盖边框像素），遇到背景像素则将其绘制为种子颜色，遇到网格边界则停止。
- 射线可以穿出房间的开口——但由于房间是完整封闭的矩形，射线在房间内部必然会碰到边框而截断。因此射线只在房间内部生效，长度受 L 和边框位置双重限制。
- 种子像素本身保持不变，边框保持不变。

Key insight:
- 第一层推理：发现每个种子发射的射线长度并非固定，而是由其所在房间的空白面积决定——需要数出房间内部的空像素数。第二层推理：不同大小的房间产生不同长度的射线，而种子在房间内的偏心位置导致四个方向的射线实际被墙壁截断的长度各不相同——射线的"最大长度"和"实际长度"之间的差异是关键观察点。
</description>

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
