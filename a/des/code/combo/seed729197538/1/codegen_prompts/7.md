网格中有若干由不同颜色绘制的连通区域和一条贯穿网格的 grey 分界线；根据每个区域的多数像素落在分界线哪一侧，将该区域整体搬移到对侧的镜像位置，同时颜色变为该侧已有区域的颜色。

Input structure:
- 背景为 black 的网格。
- 网格中有一条由 grey 像素组成的完整直线（水平或垂直），将网格分为大小相等的两半（若网格为奇数宽/高，则 grey 线占据中间行/列）。
- 两侧各有若干个由不同颜色绘制的 4-连通前景区域。每个区域完全位于一侧（不跨越 grey 线）。
- 每一侧恰好有一个区域的形状与对侧某个区域的形状完全相同（经镜像翻转后逐像素匹配），但颜色不同。这两个互为镜像的区域称为"配对区域"。
- 每一侧还有一个"孤立区域"，在对侧没有形状匹配的配对。

Rule:
- 识别 grey 分界线的方向（水平或垂直）。
- 对每一侧的每个前景区域，尝试在对侧找到形状镜像匹配的区域（沿 grey 线做镜像翻转后形状相同）。
- 对于成功配对的区域：保持两个区域都不变，但将各自的颜色交换——即左侧配对区域变为右侧配对区域的原色，右侧配对区域变为左侧配对区域的原色。
- 对于孤立区域（无配对）：将其沿 grey 线镜像翻转到对侧，颜色保持不变。原始位置恢复为背景色。
- grey 分界线保持不变。

Key insight:
解题者需要先识别分界线，再通过形状的镜像匹配找到配对关系——配对区域交换颜色而孤立区域翻转位置，两种不同的变换规则取决于是否存在镜像配对，这一分支逻辑需要从多个样例中归纳得出。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
