网格中有若干条不同颜色的折线路径，每条路径上散布着若干"门"像素；统计每条路径穿过的门的数量，然后在路径的起点处沿垂直于路径起始方向生成对应长度的标记条。

Input structure
- 背景为黑色。
- 若干条不同颜色的 1 像素宽折线路径（每条路径由单一颜色构成，如 red、blue、green），路径由水平段和垂直段的直角转折连接而成，每条路径有两个端点（度为 1 的像素）。
- 路径上散布着若干 maroon 色的像素点，称为"门"。这些门像素覆盖在路径像素之上（即门的位置处路径颜色被替换为 maroon）。
- 每条路径的一个端点标记为 yellow（起点），另一个端点保持路径本色（终点）。起点像素为 yellow 色，不是路径颜色。

Rule
- 对每条路径，沿路径从 yellow 起点走到终点，统计路径上 maroon 门像素的数量 K。
- 从 yellow 起点位置出发，沿路径前进方向的垂直方向（即如果路径在起点处向右延伸，则标记条向上或向下生长；如果路径在起点处向下延伸，则标记条向左或右生长——取不与路径重叠的那一侧）绘制一条长度为 K 的标记条，颜色为该路径的颜色。
- 路径本身（包括门像素和起点）保持不变。

Key insight
- 解题者面临三层推理：(1) 识别出 maroon 像素是"门"而非路径的一部分——它们打断了路径颜色但在拓扑上属于路径；(2) 统计每条路径上的门数量；(3) 标记条的生长方向由起点处路径的朝向决定，标记条垂直于路径起始方向延伸。前两层需要归纳，第三层需要空间推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
