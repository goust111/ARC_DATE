<description>
每个彩色对象像"印章"一样，在网格上沿自身形状暗示的方向周期性复制，复制次数等于对象旁边标记像素的数量。

Input structure
- 背景为 black。网格中有若干个 4-连通的单色对象，每个对象的颜色各不相同。
- 每个对象紧邻（8-连通相邻但不重叠）若干个 grey 标记像素，这些标记像素的数量表示复制次数。
- 每个对象的形状具有唯一的不对称性，暗示一个方向：对象的像素质量分布偏向某一侧（即对象的 bounding box 中，像素集中在某个象限或某条边），该偏向方向的反方向即为复制的行进方向。具体判定方式：将对象的 bounding box 一分为四，像素最多的象限所在的方向为"重心偏向"，复制方向为其对角方向。

Rule
- 对每个对象，确定其复制方向（重心偏向的对角方向）和复制次数 n（相邻 grey 像素数量）。
- 沿复制方向，以对象 bounding box 的尺寸为步长，依次放置 n 个该对象的副本。副本保持原始形状和颜色。
- 清除所有 grey 标记像素。
- 若副本超出网格边界则裁剪。

Key insight
解题者需要先发现 grey 标记数量编码复制次数（通过对比不同样例中标记数与副本数的对应关系），再发现复制方向由对象自身形状的不对称性决定（而非标记像素的位置），两层规律都需要从样例中主动归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
