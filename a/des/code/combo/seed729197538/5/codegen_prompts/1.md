根据封闭区域内部的孔洞数量，从颜色图例中查找对应颜色，再用该颜色填充区域边框。

Input structure
- 背景为 black。网格中有若干由 grey 像素围成的封闭区域（一像素宽的闭合边框），每个区域内部可能包含零个或多个由 blue 像素构成的小实心方块（孔洞标记）。
- 网格的一角（例如左下角）有一个竖直排列的颜色图例：图例由若干行组成，每行左侧是一个用 grey 像素写成的简单计数符号（一个点、两个点、三个点……分别表示数量 1、2、3……），右侧紧邻一个彩色像素（如 red、green、yellow、orange 等），表示该数量对应的填充颜色。零个孔洞对应图例中没有计数符号、仅有彩色像素的那一行。

Rule
- 对每个 grey 封闭区域，数出其内部 blue 小方块的个数 n。
- 在颜色图例中找到数量 n 对应的颜色 c。
- 将该封闭区域的 grey 边框像素全部替换为颜色 c，同时清除区域内部的所有 blue 小方块（变为 black）。
- 图例本身保持不变。

Key insight
孔洞数量并非直接决定颜色——需要先识别图例中计数符号与颜色的映射关系，再用这层映射把每个区域的孔洞计数翻译成边框颜色。两步归纳缺一不可：一是发现"数孔洞"，二是发现"查图例"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
