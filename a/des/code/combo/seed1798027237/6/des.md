- `description`：根据彩色锚点之间的连线方向，在每条连线的中点位置生成与连线长度等大的正方形色块，色块颜色由角落色表的查找规则决定。

- `Input structure`：
  - 背景为 Black。
  - 网格上散布若干单像素的彩色锚点（颜色从 Red、Blue、Green、Yellow、Orange 中选取）。
  - 部分锚点之间存在用 Grey 像素绘制的水平或垂直直线段连接（线段不含端点锚点本身）。
  - 每个锚点最多参与两条 Grey 连线。
  - 输入中还包含一个位于网格角落的 2x2 色表：色表有两行，每行左格为一种锚点颜色，右格为另一种锚点颜色，表示这两种颜色"混合"后的结果颜色等于右格颜色。（例如左 Red 右 Blue 表示 Red+Blue→Blue；左 Green 右 Yellow 表示 Green+Yellow→Yellow。）

- `Rule`：
  - 保留所有锚点像素不变，擦除所有 Grey 连线像素。
  - 对每条原 Grey 连线，计算连线像素数量 N（不含两端锚点）。
  - 在该连线的中点位置（若 N 为偶数则取靠近行/列号较小端的像素位置）为中心，绘制一个边长为 N 的实心正方形。
  - 正方形的颜色确定方式：取该连线两端锚点的颜色，查色表——若色表某行恰好包含这两种颜色（不论左右顺序），则正方形使用色表中该行右格的颜色；若色表中无匹配行，则正方形使用两端锚点中行号较小者的颜色。
  - 正方形绘制时不覆盖已有的锚点像素。

- `Key insight`：
  Grey 连线不是装饰而是度量工具——其长度决定生成色块的尺寸，其空间中点决定色块位置；角落色表提供了一个非显然的颜色合成查找规则，解题者必须同时发现"长度→尺寸"和"色表查找→颜色"两层独立机制。
</new_puzzle>

- `description`：将散落的彩色碎片滑入与其形状互补的框架缺口中，滑入方向由碎片上的单个 Red 标记像素指示。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干用 Blue 像素绘制的矩形空心框架（边框厚度为 1 像素），每个框架的边框上有一处连续缺口（缺口是边框上连续缺失的若干像素）。
  - 网格中另有若干 4-连通的彩色碎片对象（颜色非 Black、非 Blue、非 Red），每个碎片的形状恰好能填满某个框架缺口的空间。
  - 每个碎片上恰好有一个 Red 像素，该 Red 像素位于碎片的某一侧边缘，指示滑入方向：Red 像素相对于碎片其余像素整体中心所在的方向就是碎片要滑动的方向（上、下、左、右四选一）。
  - 碎片数量与框架数量相等，且每个碎片恰好与一个框架的缺口形状匹配。

- `Rule`：
  - 对每个彩色碎片，确定其 Red 标记像素相对于碎片其余像素中心的方向（上/下/左/右），该方向即为碎片的滑动方向。
  - 沿该方向寻找最近的 Blue 框架缺口，将碎片平移至恰好填入缺口位置（碎片的轮廓与缺口的形状完全吻合，碎片像素占据原本缺口处的空白位置）。
  - 碎片填入后，Red 标记像素变为碎片本身的颜色（即 Red 像素消失，被碎片颜色替代）。
  - 碎片原来的位置清除为 Black 背景。

- `Key insight`：
  解题需要两层推理：第一层是识别 Red 标记的"方向指示"功能——它不是碎片的一部分而是运动方向的编码；第二层是通过形状匹配找到碎片与缺口的配对关系。方向和形状两条线索必须同时正确才能确定最终位置。
</new_puzzle>

- `description`：根据封闭区域内种子像素的数量，从角落色环图例中选取对应颜色重绘该区域的边界墙。

- `Input structure`：
  - 背景为 Black。
  - 网格中有用 Grey 像素绘制的一组墙段，这些墙将网格分割成若干 4-连通的封闭背景区域。
  - 部分封闭区域内包含一个或多个彩色种子像素（颜色各异，可能为 Red、Green、Blue、Yellow、Orange 等）。
  - 网格的左上角有一个色环图例：图例是一列纵向排列的彩色像素，从上到下依次为不同颜色，共 K 个像素（K 等于所有区域中种子数量的最大值）。色环图例中的颜色互不相同。

- `Rule`：
  - 首先，对每个封闭区域，计算其内部种子像素的数量 C。
  - 然后，在色环图例中找到从上往下第 C 个颜色（第 1 个对应图例最上方的颜色）。
  - 将该封闭区域的所有相邻 Grey 墙像素重绘为该颜色。一面墙若同时与两个区域相邻，使用种子数量较多的那个区域对应的颜色；若两侧种子数量相同，使用色环图例中排列靠前（靠上）的那个颜色。
  - 不含任何种子的封闭区域，其相邻墙保持 Grey 不变。
  - 种子像素本身保持不变。

- `Key insight`：
  解题的核心在于三层递进推理：首先识别色环图例的"索引"功能；然后发现种子数量是查表键而非种子颜色本身；最后理解共享墙的归属冲突解决规则。种子的颜色是干扰项，真正起作用的是数量。
</new_puzzle>

- `description`：按照路径上收集的颜色标记顺序，逐层为起点核心对象"穿上"同心轮廓环。

- `Input structure`：
  - 背景为 Black。
  - 网格中有一个用 Azure 像素绘制的小型核心对象（任意形状的 4-连通区域，面积约 3-6 像素）。
  - 从核心对象的某一侧延伸出一条单像素宽的 Grey 路径（水平或垂直直线段与直角拐弯组成的折线路径）。
  - Grey 路径上间隔分布着若干彩色标记像素（非 Black、非 Grey、非 Azure），每个标记替换路径上的一个 Grey 像素。路径从核心对象出发，沿途依次经过这些标记。
  - 各标记颜色可能相同也可能不同。

- `Rule`：
  - 沿 Grey 路径从核心对象出发，按到达顺序收集所有彩色标记。假设依次收集到的颜色为 C1, C2, C3, ...
  - 擦除整条 Grey 路径和路径上的所有标记。
  - 以核心对象为第 0 层，对核心对象做逐层同心轮廓扩展：
    - 第 1 层轮廓：核心对象所有像素的 4-邻域中属于背景的像素集合，用颜色 C1 填充。
    - 第 2 层轮廓：第 1 层轮廓所有像素的 4-邻域中属于背景的像素集合（排除已填充区域），用颜色 C2 填充。
    - 以此类推，直到所有标记颜色用完。
  - 核心对象保持 Azure 不变。

- `Key insight`：
  路径本身不是输出的一部分，而是一个"颜色指令序列"的编码载体。解题者需要发现两个非显然的映射：路径上标记的空间顺序决定颜色的涂刷层序，而核心对象的形状决定每层轮廓的几何形态。路径的走向和长度是干扰信息，只有标记的遍历顺序才有意义。

- `description`：识别每对镜像对称的对象，将远侧对象沿 Maroon 标记的对称轴翻折合并到近侧，重叠时近侧优先。

- `Input structure`：
  - 背景为 Black。
  - 网格中有偶数个彩色 4-连通对象，对象颜色从 Red、Green、Blue、Yellow、Orange、Magenta 中选取。
  - 这些对象两两配对，每对中的两个对象形状互为镜像（可能是左右镜像或上下镜像）。每对中两个对象颜色不同。
  - 网格中有一条由若干不连续的 Maroon 单像素点标记的行或列，这条行或列就是镜像对象的对称轴。
  - 每对镜像对象分别位于其对称轴的两侧，且到对称轴的距离不一定相等。

- `Rule`：
  - 找到 Maroon 像素所在的行或列，确定对称轴方向（水平轴或垂直轴）。
  - 对每对镜像对象，将距离对称轴较远的那个对象沿对称轴翻折，使其镜像后与较近的对象部分或完全重叠。
  - 重叠区域的像素：若两个对象在同一位置都有非背景像素，保留较近对象（距对称轴更近的那个）的颜色；若只有一个有非背景像素，保留该颜色。
  - 翻折后，远侧对象的原位置清除为 Black。
  - 擦除所有 Maroon 对称轴标记像素。
  - 最终输出裁剪为包含所有非背景像素的最小矩形。

- `Key insight`：
  解题有三层推理：第一层是发现零散的 Maroon 像素实际上标记的是一条完整的对称轴线（而非独立的标记点）；第二层是识别哪些对象互为镜像配对——需要通过形状匹配而非颜色匹配来判断；第三层是理解折叠方向始终是"远的折向近的"，且重叠时近侧对象具有优先权。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的传送门配对连接，使每个移动对象穿过入口门后从出口门的对应位置射出，射出方向由门框缺口朝向决定。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干用不同颜色绘制的 3x3 空心方框（边框 1 像素厚，内部 1x1 为 Black），每个方框的边框上恰好有一个像素缺口。这些方框即为"传送门"。
  - 颜色相同的方框恰好出现两个，构成一对传送门（入口和出口由移动对象的运动方向决定）。
  - 网格中另有若干 Grey 像素组成的 4-连通移动对象，每个移动对象为一条单像素宽的直线段（水平或垂直），且该线段的延长线方向上恰好有一个传送门，线段正朝向该门的缺口。

- `Rule`：
  - 每个 Grey 移动对象沿其自身方向（水平线段向左或向右、垂直线段向上或向下，由其与最近传送门的相对位置确定）移动，直到线段的前端像素进入该传送门的缺口位置。
  - 此时该移动对象"传送"到同色配对门：从配对门的缺口位置射出，射出方向为配对门缺口朝外的方向。
  - 射出后的对象保持原来的长度和 Grey 颜色，放置在配对门缺口外侧沿射出方向的连续位置上。
  - 移动对象原位置清除为 Black；两个传送门保持不变。

- `Key insight`：
  解题需要理解三个非显然的机制：首先，门框缺口的位置同时编码了"入口接收方向"和"出口射出方向"两个信息；其次，颜色匹配决定了传送配对关系；最后，移动对象的朝向决定了它进入哪个门——同色的两个门中，对象朝向缺口的那个才是入口。
</new_puzzle>

<new_puzzle>
- `description`：根据容器间底部管道的连通关系，将连通容器组内的液体重新均匀分配，统一颜色取自原始液面最高者。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干用 Grey 像素绘制的"U 形容器"：每个容器由两条垂直线段（左壁和右壁）和一条水平线段（底部）连接而成，顶部敞开。所有容器底部在同一行，内部宽度相同均为 W 像素，但左右壁高度可能不同（取两壁中较矮的为容器有效高度）。
  - 每个容器内部底部以上填充了若干行连续的彩色像素，代表"液体"。每个容器的液体颜色各不相同。液体从容器底部向上连续填充，填充宽度等于容器内部宽度 W。
  - 容器之间通过底部的一条水平 Maroon 像素管道相连（管道在容器底部所在行的下一行，连接相邻容器底部的正下方位置）。并非所有相邻容器之间都有管道。

- `Rule`：
  - 通过 Maroon 管道确定哪些容器相连。管道直接相连的容器构成一组连通容器（传递闭包：A 连 B、B 连 C 则 A、B、C 同组）。
  - 对每组连通容器，计算该组所有液体像素的总行数之和 T 和该组容器的总数 N。
  - 将液体重新分配：每个容器的液面高度设为 T / N 向下取整行（即尽量均分），剩余的行数按从左到右的容器顺序每个容器多填一行，直到余量分完。
  - 每个容器重新填充时，液体颜色使用该组中液面原本最高的容器的颜色。若有多个容器液面高度相同且最高，使用最左边那个的颜色。
  - Grey 容器壁和 Maroon 管道保持不变。
  - 未被管道连通的孤立容器保持原样不变。

- `Key insight`：
  解题者首先需要通过 Maroon 管道识别容器的连通分组（而非简单地配对所有相邻容器），然后理解液体总量在组内均匀重分配的"连通器"原理，最后发现统一颜色取自原始液面最高者——这三层推理缺一不可，且管道连通性可能跳过中间容器形成非直觉的分组。
</new_puzzle>
