<new_puzzle index="4">
根据每个矩形对象内部"指针像素"的位置推断指向方向，沿指向追踪出对象间的有向链，链的起点颜色覆盖终点对象的颜色。

Input structure
- 背景为 grey 的网格上有若干互不接触的实心矩形对象，每个矩形使用不同的前景色（如 red、blue、green、yellow、orange 等）。
- 每个矩形对象内部恰好有一个 black 像素作为"指针像素"。指针像素位于矩形四条边之一的内侧中点（例如，若矩形宽 5 高 3，指针在右边中点即第 2 行最右列），该边指示对象的"指向方向"（指针贴右边则指向右方，贴上边则指向上方，以此类推）。
- 从每个对象沿其指向方向看去，在该直线方向上存在另一个矩形对象（中间隔着背景像素）。
- 对象间的指向关系构成若干条不分叉的有向链（无环路），每条链有唯一起点（无入边的对象）和唯一终点（指向方向上无更多对象的对象）。

Rule
- 对每个矩形，根据 black 指针像素贴近矩形哪条边来确定其指向方向。
- 沿指向方向找到下一个矩形对象，建立有向链。
- 找到每条链的起点对象（没有被链中其他对象指向的那个）。
- 将链终点对象的颜色替换为链起点对象的颜色。链中间的对象颜色保持不变。
- 所有 black 指针像素在输出中被替换为其所在矩形当前的颜色（即指针消失，融入矩形）。

Key insight
解题者需要依次完成三层推理：(1) 从 black 像素在矩形内部的偏心位置推断每个对象的指向方向；(2) 沿方向追踪建立对象间的有向链拓扑；(3) 理解颜色传播规则是"起点颜色覆盖终点"而非逐级传递。指针位置编码方向这一步是核心隐蔽性所在。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
