在被灰色线划分的区域中，根据每个区域内"种子图案"的自身对称类型，选择不同的翻转铺满策略来填充该区域的四个角落。

Input structure:
- 背景为黑色。灰色单像素宽的水平线和垂直线将网格划分为若干矩形区域。
- 每个区域内有一个小型彩色图案（种子图案），由一种非背景非灰色的颜色绘制，占据区域的一个角落，大小不超过区域面积的四分之一。
- 种子图案本身可能具有以下对称性之一：（a）仅关于水平轴对称，（b）仅关于垂直轴对称，（c）关于两条轴都对称（即同时水平和垂直对称），（d）无任何轴对称性。

Rule:
- 对每个区域，识别种子图案所在的角落位置（左上、右上、左下、右下）以及种子图案的对称类型。
- 根据对称类型决定铺满方式：
  - 仅水平轴对称：将种子图案上下翻转后放置到同侧的上方或下方角落（即竖直方向的对面角落），形成上下两份图案。
  - 仅垂直轴对称：将种子图案左右翻转后放置到同行的另一侧角落（即水平方向的对面角落），形成左右两份图案。
  - 双轴对称：将种子图案分别翻转后填充到全部四个角落。
  - 无对称性：将种子图案旋转 180 度后放置到对角线方向的那个角落，只填充两个对角。
- 原始种子图案保持不变，灰色分隔线保持不变。

Key insight: 解题者不能简单地对所有区域执行统一的"复制到四角"操作——必须先判断每个种子图案自身的对称类型，再据此选择对应的铺满策略。对称类型的判别是第一层非显然推理，铺满方式的差异化选择是第二层推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
