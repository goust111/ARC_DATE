Input structure：
- 背景为主色（如 Black）。

- 外部碎片从原位置擦除（变为背景色）。
- 框架本身颜色不变，背景不变。

Key insight：
- 解题者需要先从框架中提取每个孔洞的精确形状，再在外部碎片中进行形状匹配——这是第一层推理（形状识别与配对）。第二层推理在于：匹配成功后，碎片的颜色决定了孔洞的填充色，颜色信息无法从框架本身获得，必须通过形状匹配间接获取。

网格中的彩色条纹图案被若干"遮罩窗口"截取，输出仅保留窗口内可见的条纹，但条纹的颜色需根据窗口边框颜色在预设调色板行中查表替换。

Input structure：
- 背景为主色（如 Black）。
- 网格顶部有一行"调色板行"，由若干两像素高的色块组成，每个色块占一列：上方像素为"键色"，下方像素为"值色"，形成颜色映射对。
- 调色板行下方是主画布区域，其中绘有若干全宽的水平彩色条纹（每条条纹高 1 像素，颜色各不相同，条纹之间无间隔）。
- 画布上叠加了若干矩形"窗口"，每个窗口由单像素宽的单色边框围成（边框颜色为调色板行中某个"键色"）。窗口内部可以看到被截取的条纹。
- 不同窗口的边框颜色可能不同。

Rule：
- 创建一个与主画布同尺寸的纯背景输出网格（不含调色板行）。
- 对每个窗口，在调色板行中查找其边框颜色对应的"值色"。
- 窗口内部可见的所有条纹像素，在输出中用该"值色"替换原条纹颜色后绘制到对应位置。
- 窗口外部的区域输出为背景色。边框本身不绘制。
- 若多个窗口重叠，后处理的窗口（边框颜色在调色板行中位置更靠右的窗口）覆盖先前的像素。

Key insight：
- 第一层推理：窗口起到空间裁剪作用——只有窗口内的条纹被保留。第二层推理：窗口边框的颜色不是装饰性的，而是通过调色板行查表决定输出中条纹的重新着色方案。解题者需要同时理解"空间选择"和"颜色映射"两个独立机制的叠加。
</description>

<description>
识别网格中由不同颜色构成的嵌套环结构，将每层环"展开"为输出网格中对应行的水平色带，环从外到内的顺序对应行从上到下的顺序，色带长度等于该环的像素总数。

Input structure：
- 背景为主色（如 Black）。
- 网格中央有一个由多层同心矩形环嵌套而成的结构，每层环为单像素宽、颜色各不相同（如最外层 Red、次外层 Blue、再内层 Green，最内层为一个实心小矩形，颜色如 Yellow）。
- 嵌套层数在 3 到 5 层之间。
- 每层环的颜色在整个网格中是唯一的（不会出现在环结构之外）。

Rule：
- 输出网格的宽度等于最外层环的像素总数，高度等于嵌套层数。
- 最外层环对应输出的第 1 行：从第 1 列开始，用该环的颜色绘制一段水平色带，色带长度等于该环的像素数量，其余列为背景色。
- 次外层环对应输出的第 2 行，以此类推，最内层（实心矩形视为最内环）对应最后一行。
- 每行色带从第 1 列开始，左对齐。

Key insight：
- 第一层推理：需要将视觉上的二维同心矩形结构识别为分层的嵌套环，并确定从外到内的层序。第二层推理：每层环的像素总数（一个需要数数的量）被编码为输出中对应色带的长度——这是一种从二维空间量到一维长度量的维度转换，解题者必须意识到"环的面积"变成了"线段的长度"。

<description>
网格中有多个带缺口的矩形框，每个框旁边有一个独立的小图案；将小图案旋转到与缺口朝向对齐后嵌入缺口位置，旋转方向由缺口相对于框中心的方位决定。

Input structure：
- 背景为主色（如 Black）。
- 网格中散布若干矩形空心框，每个框由单像素宽的单一颜色（如 Grey）线段构成，但其中一条边的中段缺失了若干连续像素，形成一个"缺口"。
- 每个框的缺口大小（缺失像素数）不同。
- 每个框的外部近旁（不与框接触，间隔至少 1 像素）有一个与缺口大小相同的小型 4-连通彩色图案（颜色非背景、非框色），图案始终呈水平排列（即初始朝向为水平）。
- 每个框恰好对应一个图案，通过距离最近的关系配对。

Rule：
- 对每个矩形框，确定缺口位于框的哪条边（上、下、左、右）。
- 如果缺口在上边或下边，图案无需旋转（保持水平），直接平移到缺口位置填入。
- 如果缺口在左边，将图案顺时针旋转 90 度后填入缺口位置。
- 如果缺口在右边，将图案逆时针旋转 90 度后填入缺口位置。
- 填入后图案的像素恰好填满缺口的缺失位置，图案原始位置被擦除为背景色。
- 框的其余部分和背景不变。

Key insight：
- 第一层推理：需要将框与图案通过空间邻近性配对，并识别出每个框上缺口的精确位置和朝向。第二层推理：图案的旋转方向不是任意的，而是由缺口所在边决定的固定映射规则（上下不转、左顺右逆），解题者需要从多个样例中归纳出这一方位-旋转对应关系。
</description>

<description>
网格中有多个同色十字形标记，每个十字的四个臂长度不等；输出中每个十字被替换为一个实心矩形，矩形的宽度等于水平臂总展幅、高度等于垂直臂总展幅，矩形颜色由该十字最短臂的朝向在角落图例中查找决定。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干十字形对象，每个十字由一个中心像素和四个方向（上、下、左、右）的臂组成，臂为同色单像素宽的直线段。
- 每个十字的四个臂长度互不相同（如上臂 3 像素、下臂 1 像素、左臂 2 像素、右臂 4 像素）。
- 所有十字使用同一种前景色（如 Azure）。
- 网格的四个角落各有一个单像素的彩色标记（左上角、右上角、左下角、右下角），颜色各不相同（如 Red、Green、Blue、Yellow），分别对应上、右、下、左四个方向。

Rule：
- 对每个十字，找到其最短的臂，确定该臂的朝向（上/下/左/右）。
- 根据角落标记的方向映射（左上角色=上方向、右上角色=右方向、左下角色=下方向、右下角色=左方向），将十字替换为对应颜色的实心矩形。
- 矩形以十字中心为中心，宽度等于左臂+右臂+1，高度等于上臂+下臂+1。
- 角落标记在输出中保持不变。

Key insight：
- 第一层推理：需要识别四个角落像素不是随机噪声而是方向-颜色映射图例，角落的空间位置编码了方向含义。第二层推理：十字的最短臂是关键属性——它的朝向决定了在图例中查找哪个颜色，从而决定矩形的填充色。第三层推理：矩形的尺寸由臂长综合决定，将线性十字结构转化为面状矩形。
</description>
