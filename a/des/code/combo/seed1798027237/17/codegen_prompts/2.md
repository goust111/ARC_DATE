在网格中找到由边框颜色围成的封闭房间，根据房间内种子像素的颜色对房间分组，同组房间内的所有独立小对象按面积从大到小依次继承组内其他房间中对应排名对象的颜色。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干由单一颜色（如 Orange）线段围成的矩形封闭"房间"，房间之间不重叠。
- 每个房间内部左上角有一个单像素的"种子"像素，种子颜色从 Red、Blue、Green 等颜色中取值。种子颜色相同的房间属于同一组，每组恰好有两个房间。
- 每个房间内部（除种子外）还散布着若干 4-连通的小型单色对象，这些对象的颜色各不相同，且与种子颜色、边框颜色、背景色均不同。
- 同组的两个房间内小对象数量相同。

Rule：
- 通过种子颜色将房间配对分组。
- 在每组的两个房间内，分别将小对象按面积从大到小排序。
- 排名第 k 的对象获得对方房间中排名第 k 的对象的颜色（即同组两房间的对应排名对象互换颜色）。
- 种子像素、边框、背景均保持不变。

Key insight：
- 第一层推理：需要识别种子像素的分组功能——相同种子颜色的房间是配对的。第二层推理：需要发现面积排序建立了两个房间中对象之间的一一映射，且颜色是跨房间交换而非简单替换。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
