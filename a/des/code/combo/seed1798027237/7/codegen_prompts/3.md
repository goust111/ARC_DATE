将散落在网格中的小型"箭头"精灵按其指向方向依次堆叠到网格中央的十字准线上。

Input structure
- 背景为黑色的奇数边长正方形网格。
- 网格正中央有一个由 grey 像素组成的十字准线：一条完整的水平中线和一条完整的垂直中线（交叉处也是 grey）。
- 网格中散布若干彩色"箭头"精灵，每个箭头由 5 个同色像素组成：一个 1x3 或 3x1 的柄加上柄一端的垂直方向两侧各伸出 1 像素构成箭头尖端。箭头的朝向由尖端相对于柄的方向决定（上、下、左、右四种朝向之一）。
- 同一颜色可能有多个箭头，不同颜色的箭头数量不同。

Rule
- 统计每种朝向（上、下、左、右）的箭头总数 N。
- 从十字准线的中心交叉点出发，沿该朝向的准线臂方向，将距中心最近的 N 个 grey 像素替换为 red。
- 清除所有原始箭头精灵（恢复为黑色背景），十字准线其余部分保持 grey 不变。

Key insight
- 箭头的颜色是干扰项——真正重要的是箭头的朝向。解题者需要先忽略颜色差异，按朝向分组计数，再将计数转化为十字准线上从中心向外延伸的 red 标记长度。第一层推理在于发现颜色无关、朝向才是分类依据；第二层在于发现计数与准线臂上的染色长度之间的对应关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
