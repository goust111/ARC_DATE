<description>
根据彩色种子像素在网格分区中的位置，用种子颜色沿分区边界生长出与种子所在象限对应方向的L形枝条，枝条长度由该分区内背景像素的行数决定。

Input structure:
- 背景为 Black。网格被若干条贯穿整行或整列的 Grey 直线分割成矩形分区。
- 每个分区内恰好有一个彩色种子像素（颜色各不相同，可能为 Red、Blue、Green、Yellow、Orange 等）。
- 种子像素位于分区内部某处，其余分区内像素均为 Black 背景。

Rule:
- 对每个分区，先判断种子像素位于该分区四个象限中的哪一个（以分区中心为基准，分为左上、右上、左下、右下）。
- 象限决定L形枝条的生长方向：左上象限→枝条向右再向下；右上象限→枝条向左再向下；左下象限→枝条向右再向上；右下象限→枝条向左再向上。即枝条始终朝对角方向展开。
- 枝条的每一段长度等于该分区内纯背景行的总数（不含种子所在行和 Grey 边界行）。
- 枝条从种子像素出发，先沿水平方向画出第一段，再从第一段末端沿垂直方向画出第二段，颜色与种子相同。
- Grey 分割线和种子像素本身保持不变。

Key insight:
种子在分区内的相对位置（象限）决定枝条的朝向，而分区内空行数编码了枝条长度——解题者必须同时归纳出方向规则和长度规则，两者缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
