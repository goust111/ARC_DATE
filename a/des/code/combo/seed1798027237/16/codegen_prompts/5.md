- `description`：在网格中找到由框架颜色编码的旋转指令，将框架内的图案按指定次数旋转 90 度后放回原位。

- `Input structure`：
  - 网格以 black 为背景色。
  - 网格中有若干个独立的矩形框架，每个框架由一圈一像素宽的彩色边框围成（边框颜色各不相同）。
  - 每个框架内部包含一个由另一种颜色绘制的非对称图案（图案颜色与边框颜色不同，图案在旋转 0°/90°/180°/270° 下各不相同，以便区分旋转结果）。
  - 网格的某个角落（如左上角）有一个色板区域：色板由若干行组成，每行包含一个颜色像素后跟若干个 grey 小圆点（单像素），排列为 "颜色像素 + N 个 grey 点" 的形式。颜色像素的颜色与某个框架的边框颜色对应，N 的值为 1、2 或 3。

- `Rule`：
  - 移除色板区域（将其还原为背景色）。
  - 对每个框架：
    1. 在色板中找到与该框架边框颜色相同的行。
    2. 读取该行中 grey 点的数量 N。
    3. 将框架内部的图案顺时针旋转 N×90 度。
    4. 将旋转后的图案放回框架内部原来的位置。
  - 框架边框本身保持不变。

- `Key insight`：
  - 第一层推理是发现色板中每行的 grey 点数量编码了旋转次数，而非其他几何属性；第二层推理是发现色板行的颜色与框架边框颜色的对应关系——通过颜色匹配确定哪个框架应用哪个旋转量；第三层是正确执行顺时针旋转并将结果放回原始框架内（需要注意旋转中心为框架内部的中心）。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
