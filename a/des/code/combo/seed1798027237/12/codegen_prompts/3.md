- `description`：每个前景对象沿其内部箭头标记所指方向平移，平移距离等于该对象所包含的特定标记像素的数量。
- `Input structure`：背景为最常见颜色。网格中有若干单色 4-连通前景对象，每个对象的颜色各不相同。每个对象内部嵌入了若干 red 像素（标记点）和恰好一个由 yellow 像素组成的箭头形状。箭头由三个像素构成：一个箭头尖端像素和两个斜向翼像素，箭头尖端相对于翼像素的位置指示方向——若尖端在翼像素的正上方则指向上，正下方则指向下，正左方则指向左，正右方则指向右。具体而言，指向上的箭头为：尖端在上，左下和右下各一个翼像素；指向下的箭头为：尖端在下，左上和右上各一个翼像素；指向左的箭头为：尖端在左，右上和右下各一个翼像素；指向右的箭头为：尖端在右，左上和左下各一个翼像素。箭头嵌在对象内部，与对象像素共存于同一单元格中（即这些格子既属于对象又被标记为 yellow）。
- `Rule`：对每个对象：（1）读取箭头方向：根据 yellow 箭头的三个像素的排列确定上/下/左/右方向；（2）计数该对象内部 red 标记像素的数量 n；（3）将整个对象（包括其中的 yellow 和 red 像素）沿箭头方向平移 n 格。平移后，原位置恢复为背景色。如果多个对象平移后存在重叠，后处理的对象覆盖先处理的（按对象左上角坐标从上到下、从左到右的顺序处理）。箭头和标记像素在输出中保持原样（不被对象颜色覆盖）。
- `Key insight`：解题者需要同时从对象内部提取两种不同信息——箭头的几何朝向决定方向，红色标记的数量决定距离——这两个要素共同决定平移变换，缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
