根据每行/每列中彩色标记像素的存在性，决定该行/列在输出中被保留还是被折叠删除，从而压缩网格。

Input structure：
- 背景为 black。
- 网格中有一个由 grey 像素构成的大型图案（如字母、几何形状等），占据网格的大部分区域。
- 某些行的最左侧（第 0 列）有 red 单像素标记，某些列的最顶部（第 0 行）有 blue 单像素标记。
- 标记像素不与 grey 图案重叠。

Rule：
- 第一层：统计每行左侧 red 标记的存在性——有 red 标记的行标记为"保留行"，无标记的行标记为"删除行"。同理，有 blue 标记的列为"保留列"，无标记的列为"删除列"。
- 第二层：从网格中移除所有"删除行"和"删除列"，将剩余的行和列紧凑拼合成一个更小的输出网格。
- 输出网格中仅包含 grey 图案像素和 black 背景，所有标记像素（red、blue）在输出中不保留（它们所在的边缘行/列如果被保留，则标记像素替换为 black）。

Key insight：
标记像素看似是装饰性的边框点缀，实际上它们编码了一个行列选择掩码——解题者必须意识到标记不是要被复制或移动的对象，而是控制网格结构本身被压缩的指令，这在 ARC 题目中是一种反直觉的元操作。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
