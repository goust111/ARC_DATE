<description>
根据嵌套框架的层级关系，将散落的彩色碎片填入对应层级的框架环中。

Input structure：
- 背景为 black。
- 网格中有若干同心的单像素厚矩形框架，每个框架由不同颜色绘制（如 red、blue、green 等），框架之间有间隔行/列。
- 在网格的一侧（如右侧或下方）有一个独立的"碎片区"，其中包含若干小的彩色连通块，每个连通块的颜色与某个框架颜色相同，形状为该框架某一边的局部片段。
- 每个框架恰好缺失一段连续的边（即该边上有一段被背景色替代的缺口）。

Rule：
- 首先识别每个框架的颜色及其缺口位置和长度。
- 在碎片区中找到与该框架颜色匹配的碎片。
- 将碎片旋转或翻转（若需要），使其方向与缺口所在边一致，然后将其填入缺口位置，恢复框架的完整性。
- 碎片区在输出中被清除为背景色。

Key insight：
碎片的颜色决定它属于哪个框架层，但碎片的朝向不一定与缺口朝向一致——需要根据缺口所在边（上/下/左/右）推断碎片需要的旋转变换，才能正确嵌入。
</description>
</new_puzzle>

<description>
根据种子像素的颜色在图例色带中的位置，确定生长方向和步数，从种子处生长出彩色射线。

Input structure：
- 背景为 black。
- 网格顶部有一行水平色带（legend），由若干不同颜色的连续段组成，从左到右排列（例如：red 占 3 格、blue 占 2 格、green 占 4 格……）。色带下方有一行 grey 分隔行。
- 分隔行下方的主网格区域散布着若干单像素"种子"，每个种子的颜色与色带中某一颜色相同。
- 每个种子像素的正上方或正下方紧邻一个 maroon 像素，作为方向标记：maroon 在种子上方表示种子向下生长，maroon 在种子下方表示种子向上生长。

Rule：
- 对于每个种子像素，在色带中找到该颜色段，记其段长度为 L。
- 种子沿 maroon 标记指示的方向（向上或向下）生长一条长度为 L 的竖直射线（包含种子自身），射线颜色与种子相同。
- 若射线长度超出网格边界，则在边界处截断。
- maroon 标记像素在输出中被清除为背景色。

Key insight：
色带不仅是颜色图例，每种颜色在色带中占据的宽度编码了该颜色射线的生长长度；方向则由每个种子旁的 maroon 标记独立指定——两层信息分别来自全局图例和局部标记。
</description>
</new_puzzle>

<description>
将网格中由通道连接的多个房间按照通道上的颜色门标记进行房间内部重着色。

Input structure：
- 背景为 black。
- 网格中有若干由 grey 墙壁围成的封闭矩形"房间"，每个房间内部填充为 black（空心）。
- 相邻房间之间的共享墙壁上恰好有一个单像素的彩色"门"（非 grey、非 black 的颜色），表示两个房间之间的通道。
- 网格边缘有一个特殊的"源房间"，其内部已填充某种颜色（如 blue），该房间是唯一一个初始非空的房间。

Rule：
- 从源房间出发，源房间的内部颜色为初始颜色。
- 当颜色通过一扇门传播到相邻房间时，该房间的内部填充色变为门的颜色（而非源房间的颜色）。
- 从该新着色的房间继续向外传播：经过下一扇门时，下一个房间的填充色同样取决于该扇门自身的颜色。
- 若一个房间有多扇门连接不同房间，则颜色分别通过每扇门独立传播。
- grey 墙壁和门像素本身保持不变。

Key insight：
房间的最终颜色不是从源头传递的，而是由进入该房间的那扇门的颜色决定的——每扇门是一个颜色变换器而非颜色通道，这使得传播路径上的颜色不断变化。
</description>
</new_puzzle>

<description>
根据每个对象内部孔洞的形状在模板库中匹配模板，然后用模板的外轮廓替换该对象的外轮廓。

Input structure：
- 背景为 black。
- 网格左侧有一个"模板库"区域，由 grey 竖线与主区域分隔。模板库中从上到下排列着若干小型模板对，每对包含：左边一个小的彩色实心形状（"钥匙"），右边一个稍大的彩色框架形状（"锁"），两者颜色相同。每对模板之间由一行 black 间隔。
- 主区域中散布着若干较大的彩色实心对象（各不同色），每个对象内部恰好有一个由背景色构成的孔洞（4-连通的 black 区域完全被对象包围）。

Rule：
- 提取每个主区域对象内部孔洞的形状（相对于孔洞自身的边界框）。
- 在模板库中，找到"钥匙"形状与该孔洞形状完全匹配的那一对模板（可能需要旋转 0°/90°/180°/270° 来匹配）。
- 取该模板对中的"锁"形状，将其以对象的颜色绘制，替换掉原对象。新对象的中心与原对象的中心对齐。
- 原对象（包括其孔洞）被完全移除，仅保留新绘制的"锁"形状。
- 模板库区域在输出中保持不变。

Key insight：
对象外表面的形状在变换中被完全抛弃——真正起决定作用的是对象内部"看不见"的孔洞形状，它作为索引在模板库中查找匹配的钥匙，进而决定替换后的外轮廓。这要求解题者忽略外形而关注负空间。
</description>
</new_puzzle>

<description>
将散落的彩色箭头沿其指向方向依次拼接成链，并用每个箭头的尾部颜色标记绘制连接路径。

Input structure：
- 背景为 black。
- 网格中有若干由同色像素构成的"箭头"对象，每个箭头由一个 3x1 或 1x3 的杆和一个 3 像素的 V 形箭尖组成（箭尖朝上/下/左/右之一），整体占据约 3x3 的区域。每个箭头有唯一的主体颜色。
- 每个箭头的杆的末端（远离箭尖的一端）有一个不同颜色的单像素"尾标"。
- 网格角落有一个 2x2 的 orange 方块作为"起点标记"。

Rule：
- 从起点标记出发，找到距离起点最近的箭头（按箭头中心到起点的视觉距离）。
- 沿该箭头的指向方向画一条该箭头尾标颜色的直线路径，从箭头箭尖出发延伸，直到碰到下一个箭头的杆部（路径不覆盖箭头本身的像素）。
- 到达的下一个箭头重复此过程：从该箭头箭尖出发，沿其指向方向画该箭头尾标颜色的路径，直到碰到再下一个箭头或网格边界。
- 所有箭头保留在原位，起点标记保留，仅在箭头之间的空白区域添加连接路径。
- 链中箭头的顺序由路径的物理延伸方向唯一确定（每个箭头的指向方向上恰好有一个下一个箭头）。

Key insight：
连接路径的颜色不由路径终点的箭头决定，而由路径起点箭头的尾标颜色决定——尾标是一个容易被忽略的单像素标记，它将颜色信息从一个箭头"发射"到下一段路径上，形成颜色-方向的双重编码链。
</description>

<description>
根据每行/每列中彩色标记像素的存在性，决定该行/列在输出中被保留还是被折叠删除，从而压缩网格。

Input structure：
- 背景为 black。
- 网格中有一个由 grey 像素构成的大型图案（如字母、几何形状等），占据网格的大部分区域。
- 某些行的最左侧（第 0 列）有 red 单像素标记，某些列的最顶部（第 0 行）有 blue 单像素标记。
- 标记像素不与 grey 图案重叠。

Rule：
- 第一层：统计每行左侧 red 标记的存在性——有 red 标记的行标记为"保留行"，无标记的行标记为"删除行"。同理，有 blue 标记的列为"保留列"，无标记的列为"删除列"。
- 第二层：从网格中移除所有"删除行"和"删除列"，将剩余的行和列紧凑拼合成一个更小的输出网格。
- 输出网格中仅包含 grey 图案像素和 black 背景，所有标记像素（red、blue）在输出中不保留（它们所在的边缘行/列如果被保留，则标记像素替换为 black）。

Key insight：
标记像素看似是装饰性的边框点缀，实际上它们编码了一个行列选择掩码——解题者必须意识到标记不是要被复制或移动的对象，而是控制网格结构本身被压缩的指令，这在 ARC 题目中是一种反直觉的元操作。
</description>
</new_puzzle>

<description>
将对称图案中被噪声打断的对称轴识别出来，用轴两侧的完好部分互相修复对方的缺损区域。

Input structure：
- 背景为 black。
- 网格中有一个由某种前景色（如 green）构成的大型图案，该图案原本具有严格的单轴对称性（水平轴或垂直轴），但对称轴两侧各有若干像素被替换为不同的"噪声颜色"（如 red 和 blue，两侧的噪声颜色不同）。
- 对称轴本身没有可见的标记线——需要从图案的整体结构推断。
- 噪声像素的数量和位置在两侧不对称（即左侧被 red 破坏的区域与右侧被 blue 破坏的区域位置不同）。

Rule：
- 识别图案的对称轴（通过比较行/列找到使大部分像素对称的唯一轴线）。
- 对于轴一侧被噪声颜色替换的每个像素，用轴另一侧对应镜像位置的像素值来恢复它。
- 如果镜像位置本身也是噪声像素（极少出现的情况），则两个位置都恢复为前景色。
- 输出为完全对称的、无噪声的纯净图案（仅前景色和背景色）。

Key insight：
两种不同的噪声颜色是关键线索——它们标识了两侧各自的损坏区域，使得解题者能够确认"这些像素是错误的"而非图案的固有特征。对称轴的位置必须通过全局结构推断而非局部标记读取，构成第一层推理；利用对称性交叉修复构成第二层推理。
</description>
</new_puzzle>
