根据框架内部缺口的朝向，从外部精灵库中选取对应方向的精灵，再按精灵自身像素数量与框架空腔面积的匹配度决定配对关系。

Input structure：
- 背景为 Black。网格中有若干个由 Grey 像素构成的矩形框架（边框厚度为 1 像素）。
- 每个框架的四条边上恰好有一个单像素缺口（缺口位置可在上、下、左、右任意一边）。
- 框架外部散布着若干个由不同颜色构成的小型精灵（连通分量），每个精灵具有明确的朝向特征：精灵整体形状类似一个箭头，箭头尖端朝上、下、左或右。箭头的绘制方式为：一条 3 像素长的直线段加上尖端处向两侧各伸出 1 像素的翼，共 5 像素组成。
- 外部精灵的颜色各不相同，且每种朝向恰好有若干个精灵。

Rule：
- 对每个框架，确定其缺口所在的边（上、下、左、右），然后在外部精灵中找到箭头朝向与缺口方向相同的所有精灵。
- 在这些候选精灵中，选择像素数量（连通分量面积）与框架内部空腔面积最接近的那个精灵。
- 用该精灵的颜色填满框架的内部空腔（不包括边框本身），精灵本身从原位置擦除。
- 未被选中的外部精灵保持不变。

Key insight：
缺口方向是第一层筛选键，将精灵按朝向分组；面积匹配是第二层选择键，将同组精灵与具体框架配对。解题者需要先发现"缺口方向 = 箭头朝向"这一对应规则，再发现"面积最近匹配"这一分配规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
