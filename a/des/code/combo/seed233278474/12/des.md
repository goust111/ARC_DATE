- `description`：根据彩色边框内嵌套小图案的"指纹"匹配，将分散的碎片拼合到正确的边框容器中并补全缺失区域。

- `Input structure`：
  - 背景为 black。
  - 网格中散布若干个由单色边框围成的矩形容器（边框颜色各不相同，如 red、blue、green 等），每个容器内部大部分为背景色，但在容器内左上角保留一个 2x2 的"指纹"色块（由两种颜色组成的固定 2x2 图案）。
  - 网格中另有若干个自由漂浮的 4-连通小碎片（每个碎片为单色，形状各异，面积在 3-8 像素之间），每个碎片内部也嵌有一个 1 像素的标记点，标记点颜色与某个容器的边框颜色相同。
  - 每个容器恰好对应一个碎片（通过碎片标记点颜色 = 容器边框颜色来配对）。

- `Rule`：
  - 第一步（配对）：对每个自由碎片，找到其内部标记点颜色对应的边框容器。
  - 第二步（放置）：将碎片的 2x2 包围盒左上角与容器内指纹色块进行比对——碎片的标记点在碎片包围盒内的相对位置，决定了碎片应放置在容器内部的哪个象限（左上、右上、左下、右下）。具体而言：标记点在碎片包围盒的左上象限 → 放入容器内部左上象限；右上 → 右上；左下 → 左下；右下 → 右下。
  - 第三步（绘制）：将碎片（保留原色，去除标记点）绘制到目标象限中，碎片紧贴该象限的角落对齐。原碎片从原始位置清除。

- `Key insight`：标记点颜色完成容器配对，而标记点在碎片自身包围盒中的相对位置编码了碎片在容器内的放置象限——解题者需要先发现配对机制，再发现位置编码机制，形成两层独立推理。
</new_puzzle>

- `description`：将网格中的彩色路径段按长度排序后首尾相连，重新铺设为一条从起点出发的连续折线。

- `Input structure`：
  - 背景为 grey。
  - 网格中有一个 green 像素作为起点标记。
  - 散布着若干条互不相连的水平或垂直直线段（每条线段为单一颜色，颜色互不相同，使用 red、blue、orange、maroon、magenta 等）。每条线段长度不同（2-6 像素）。
  - 每条线段的一个端点旁紧贴一个 azure 像素作为"头端"标记，标明该线段的起始端。

- `Rule`：
  - 第一步（排序）：按照每条线段的长度从短到长排序。若长度相同，按线段颜色在网格中首次出现的行号从小到大排序。
  - 第二步（方向读取）：每条线段自带方向——从 azure 头端标记指向线段另一端的方向（上、下、左、右之一）。
  - 第三步（拼接绘制）：从 green 起点出发，按排序顺序依次绘制每条线段。第一条线段从起点出发，沿该线段自带方向画出对应长度的像素（使用该线段的原色）。后续每条线段从上一条线段的终点出发，先向下走一格（画为 black 作为连接点），再沿该线段自带方向画出对应长度。
  - 输出网格上只保留起点标记、连接点和重新铺设的各色线段，背景仍为 grey，原始散布的线段和 azure 标记全部清除。

- `Key insight`：线段长度决定拼接顺序，azure 标记编码每段的行进方向——解题者必须同时发现排序规则和方向编码规则，才能正确重建折线路径。
</new_puzzle>

- `description`：利用封闭区域内的"种子"颜色，沿区域缺口方向向外生长出与种子数量等长的彩色刺突，刺突方向由区域缺口位置决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个由 green 像素围成的封闭矩形区域（边框为 green，厚度 1 像素）。每个矩形边框在恰好一条边上有一个 1 像素宽的缺口（缺口位置在该边的中央）。
  - 每个封闭矩形内部散布着若干个单像素的"种子"，所有种子为同一种非 green、非 black 的颜色（如 red、blue、orange 等），不同矩形的种子颜色可以不同。
  - 矩形大小在 4x4 到 8x8 之间（含边框）。

- `Rule`：
  - 第一步（计数）：数出每个矩形内部种子像素的数量 N。
  - 第二步（确定方向）：缺口所在的边决定刺突的生长方向——缺口在上边 → 刺突向上；缺口在下边 → 向下；缺口在左边 → 向左；缺口在右边 → 向右。
  - 第三步（生长刺突）：从缺口位置出发，沿确定的方向向外延伸 N 个像素，使用该矩形内种子的颜色绘制。刺突为 1 像素宽的直线。
  - 矩形边框和内部种子保持不变。

- `Key insight`：缺口不是"出口"而是"方向指示器"，种子不是"填充物"而是"长度编码器"——解题者需要发现缺口编码方向、种子数量编码长度这两个独立机制，并将它们组合。
</new_puzzle>

- `description`：网格中的彩色"齿轮"通过连接轴形成传动链，驱动齿轮的朝向沿链条级联传递，相邻齿轮的指针方向按奇偶规则翻转。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个 3x3 的十字形图案（中心 1 像素 + 上下左右各 1 像素，共 5 像素），每个十字称为一个"齿轮"。
  - 每个齿轮的中心像素为一种颜色（称为"本体色"），四个臂中恰好有一个臂的颜色与其他三个不同——这个独特臂称为"指针"，指针所在方向（上/下/左/右）表示齿轮的当前朝向。其他三个臂与中心同色。
  - 齿轮之间通过 2 像素长的水平或垂直"轴"相连（轴为 maroon 色）。轴连接两个齿轮相邻的臂端。
  - 网格中恰好有一个齿轮的中心像素为 red（"驱动齿轮"），其余齿轮中心为其他颜色。

- `Rule`：
  - 第一步（识别传动链）：从驱动齿轮出发，沿 maroon 轴找到所有直接或间接相连的齿轮，形成传动链。
  - 第二步（级联翻转）：驱动齿轮的指针方向保持不变。对于传动链中每个非驱动齿轮，将其指针方向翻转为原方向的 180 度对称方向（上↔下，左↔右）——如果该齿轮与驱动齿轮之间经过奇数根轴；若经过偶数根轴则保持原方向不变。
  - 第三步（绘制）：输出网格中，每个齿轮的指针臂移动到新方向，指针臂原位置恢复为本体色，新位置变为指针色。轴和背景不变。

- `Key insight`：轴的奇偶性决定旋转方向的传递——就像真实齿轮啮合时相邻齿轮反转。解题者需要先识别"指针"概念和传动链拓扑，再发现奇偶翻转规则，构成两层推理。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布的单色碎片根据边缘锯齿图案的互补性进行配对，然后沿匹配边对齐拼合成完整矩形。

- `Input structure`：
  - 背景为 azure。
  - 网格中散布偶数个（通常 4-6 个）单色矩形碎片，每个碎片为不同颜色（如 red、blue、green、yellow、magenta、orange）。
  - 每个碎片是一个大致矩形的区域（高度 3-5、宽度 4-7），但恰好有一条边不是平直的——该边有 1 像素深的凹凸锯齿图案（凸出或凹入背景 1 像素）。每个碎片只有一条边有锯齿。
  - 锯齿图案的形状（凸凹序列）在配对碎片之间互补：一个碎片的凸位对应另一个碎片的凹位，反之亦然，类似拼图的榫卯。

- `Rule`：
  - 第一步（识别锯齿边）：对每个碎片，找到其非平直的那条边及锯齿图案（表示为凸/凹序列）。
  - 第二步（配对）：两个碎片的锯齿图案互补（一个的凸凹序列恰好是另一个的凹凸序列）时，它们是一对。每个碎片恰好有唯一配对。
  - 第三步（合并）：将配对的两个碎片沿锯齿边对齐拼合——凸出部分嵌入凹陷部分，使得两个碎片无缝拼接成一个更大的矩形。拼合后的矩形放置在输出网格中，按配对顺序从左到右排列，相邻拼合体之间留 1 列背景色间隔。每个拼合体内部保留两个碎片各自的原色。

- `Key insight`：碎片的锯齿凸凹序列是配对密钥——解题者需要先发现锯齿边是"编码"而非随机噪声，再发现互补匹配规则，最后理解拼合的空间对齐方式。三层递进的推理构成了题目的难度核心。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色"信号塔"向四周广播射线，射线在遇到"棱镜"时分裂为垂直方向的两条分支，不同颜色射线交叉处产生混合色。

- `Input structure`：
  - 背景为 black，网格大小约 15x15。
  - 网格中有 2-3 个"信号塔"：每个信号塔是一个 1x1 的彩色像素（颜色为 red、blue 或 yellow 之一，互不相同）。
  - 网格中有若干个"棱镜"：每个棱镜是一个 1x1 的 grey 像素。
  - 网格中有若干个"墙壁"：每个墙壁是一个 1x1 的 maroon 像素，信号无法穿过。
  - 信号塔、棱镜、墙壁之间有足够的空间。

- `Rule`：
  - 第一步（信号广播）：每个信号塔沿上、下、左、右四个方向发出射线，射线颜色与信号塔颜色相同。射线逐格延伸，遇到墙壁或网格边界停止。射线经过的背景格被染为射线颜色。
  - 第二步（棱镜转向）：当射线到达一个棱镜时，射线不穿过棱镜，而是从棱镜位置向与原方向垂直的两个方向各发出一条新射线继续传播。新射线的颜色保持不变。棱镜自身保持 grey 不变。
  - 第三步（颜色叠加）：如果一个背景格被两条不同颜色的射线同时覆盖，该格变为 green（red+blue）、orange（red+yellow）或 azure（blue+yellow）。若被三种颜色同时覆盖，变为 white（用 grey 表示）。同色射线重叠不改变颜色。
  - 信号塔、棱镜、墙壁的位置和颜色在输出中保持不变。

- `Key insight`：棱镜将直线信号分裂为垂直方向的两条分支，使得信号覆盖范围从十字形变为更复杂的网络。解题者需要先理解射线传播和棱镜转向机制，再发现颜色混合规则——两层机制叠加后，输出图案的来源不再直观可追溯，增加了逆向推理的难度。
</new_puzzle>

- `description`：网格中每个彩色对象根据其内部孔洞相对于中心的偏移方向，在该方向上生成自身的镜像副本并紧贴放置。

- `Input structure`：
  - 背景为 black，网格大小约 20x20。
  - 网格中有 2-4 个互不重叠的单色 4-连通对象（颜色各不相同，如 red、blue、green、orange）。
  - 每个对象大致为 4x4 到 6x6 的实心块状结构，但内部恰好有一个 1 像素的孔洞（背景色）。孔洞不在对象的边缘，而是在对象内部。
  - 每个对象周围有足够的空白空间。

- `Rule`：
  - 第一步（定位孔洞）：找到每个对象内部唯一的孔洞像素位置。
  - 第二步（确定投影方向）：孔洞相对于对象包围盒中心的偏移方向决定投影方向。若孔洞在中心偏上 → 向上投影；偏下 → 向下；偏左 → 向左；偏右 → 向右。若孔洞恰好在水平或垂直中线上，取偏移量更大的轴方向。
  - 第三步（生成镜像）：将整个对象沿投影方向进行镜像翻转（上/下方向则做上下镜像，左/右方向则做左右镜像），然后将镜像副本紧贴对象在投影方向一侧放置（镜像副本与原对象之间无间隔，边缘相邻）。镜像副本使用 yellow 颜色绘制，而非对象原色。
  - 原对象保持不变（含孔洞）。

- `Key insight`：孔洞位置不是缺陷而是方向编码器——解题者需要先发现孔洞偏移与投影方向的对应关系，再理解镜像翻转和放置规则。孔洞作为"隐藏指令"的设计使得机制不易被直接看穿。
</new_puzzle>
