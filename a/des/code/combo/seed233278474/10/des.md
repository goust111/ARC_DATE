<description>
根据轮廓形状在色彩图例中查找匹配项，再用图例指定的填充色重绘轮廓内部。

Input structure
- 网格背景为 Black。
- 左侧有一个纵向排列的色彩图例区：每个图例条目由一个小型闭合轮廓（用 Grey 绘制，宽度为一个像素）和紧贴其右侧的一个 2x1 色块组成，色块颜色各不相同（如 Red、Blue、Green 等）。图例条目之间用至少一行 Black 背景分隔。
- 右侧散布着若干用 Grey 像素绘制的一像素宽闭合轮廓对象，每个轮廓内部全为 Black 背景。这些轮廓的形状各异，但每个都与图例中的某一个轮廓在平移归一化后完全一致。

Rule
- 将右侧每个 Grey 闭合轮廓的形状提取出来，做平移归一化（即将其紧凑包围盒对齐到原点）。
- 在左侧图例中找到形状完全一致的轮廓条目，读取该条目右侧色块的颜色。
- 用该颜色填充右侧对应轮廓内部的所有 Black 像素（即轮廓围成的区域），轮廓本身保持 Grey 不变。
- 图例区域保持原样不变。

Key insight
轮廓本身并不改变颜色——改变的是内部填充；解题需要先通过形状匹配建立轮廓与图例的对应关系，再从图例中提取出填充颜色，这构成两层独立的推理步骤。
</description>

<description>
识别每个面板中的"种子像素"颜色，按种子颜色在隐含调色板中的排列顺序决定该面板应执行的旋转角度，最终旋转面板内容。

Input structure
- 网格由 Maroon 色的单像素宽分隔线划分为若干等大的正方形面板（如 5x5）。
- 每个面板内有一个用某种颜色绘制的图案（由多个像素组成），以及恰好一个位于面板固定角落（左上角）的单独"种子像素"，种子像素的颜色与该面板图案颜色不同。
- 所有面板的图案颜色相同（如 Azure），但种子像素颜色各不相同。
- 网格底部额外有一行单像素高的色条，从左到右排列着所有出现过的种子颜色，每种颜色占一格，颜色之间无间隔。这行色条即为"调色板行"。

Rule
- 读取底部调色板行中的颜色顺序，从左到右编号为 0、1、2、3（对应旋转 0°、90°顺时针、180°、270°顺时针）。
- 对每个面板，找到其左上角的种子像素颜色，查找该颜色在调色板行中的位置编号 k。
- 将该面板内的图案（不含种子像素）绕面板中心顺时针旋转 k×90°。
- 输出中移除种子像素（恢复为 Black 背景），仅保留旋转后的图案。调色板行和分隔线保持不变。

Key insight
种子像素不参与图案，而是充当索引标签；旋转量不由图案本身的朝向决定，而需通过底部调色板行的排列顺序间接映射，因此解题者必须先发现调色板行的编码含义，再推断每个面板的旋转角度。
</description>

<description>
将散落的彩色碎片按颜色配对合并为完整矩形，再按合并后矩形的面积从小到大堆叠到输出画布上。

Input structure
- 背景为 Black 的网格中散布着若干彩色对象（4-连通区域），每种非背景颜色恰好出现两个分离的对象。
- 每对同色对象的紧凑包围盒大小相同，但其中的像素图案互补——即将两个对象的掩码在同一包围盒内做像素级 OR 合并后，恰好填满一个完整的实心矩形。
- 不同颜色对的矩形大小各不相同。

Rule
- 对每种颜色，找到两个同色对象，将它们各自的掩码平移归一化到包围盒左上角对齐后做 OR 合并，得到该颜色的完整实心矩形。
- 将所有颜色的矩形按面积从小到大排序。
- 在一个新的输出画布上（大小恰好能容纳最大矩形），将所有矩形以左上角对齐堆叠绘制：面积最小的矩形最后绘制（在最上层），面积最大的最先绘制（在最下层）。
- 每个矩形保留其原始颜色。

Key insight
解题需要三层推理：首先发现同色对象是互补碎片；其次将碎片合并还原为完整矩形；最后按面积排序进行分层堆叠。互补关系和堆叠顺序都不是一眼可见的，需要分别归纳。
</description>

<description>
根据每个封闭区域内部标记像素的数量选择对应的边框样式模板，用该模板重绘区域边框。

Input structure
- 背景为 Black。
- 网格中有若干用 Grey 像素绘制的一像素宽封闭矩形边框，各矩形互不重叠、互不接触。
- 每个矩形边框内部散布着若干 Red 标记像素（数量从 1 到 4 不等），其余内部为 Black。
- 网格的最上方有一个水平排列的"样式图例区"：包含 4 个小矩形边框模板，从左到右排列，之间用 Black 列分隔。这 4 个模板大小相同（如 3x3），但各自的边框使用不同颜色（如 Blue、Green、Yellow、Orange），且边框图案不同——第 1 个模板为完整实心边框，第 2 个模板在每条边中央缺一个像素，第 3 个模板仅保留四个角像素，第 4 个模板仅保留四条边的中点像素。模板内部全为 Black。

Rule
- 数出每个 Grey 矩形内部的 Red 标记像素数量 n（1 ≤ n ≤ 4）。
- 在图例区中，从左到右第 n 个模板即为该矩形应采用的边框样式。
- 将该 Grey 矩形的边框替换为对应模板的边框样式和颜色：将模板的边框图案按比例映射到目标矩形的边框上（模板每条边的像素图案沿目标矩形对应边做周期性平铺）。
- 移除矩形内部的所有 Red 标记像素（恢复为 Black）。
- 图例区保持不变。

Key insight
Red 标记像素的数量不是用来做算术运算的——它是一个索引，指向图例区中的某个边框样式模板。解题者必须先发现"计数→索引"的映射关系，再理解模板的边框图案如何平铺到不同大小的矩形上。
</description>

<description>
沿每个箭头指示的方向传播其颜色，直到遇到墙壁像素；当两条不同颜色的传播路径交汇时，交汇格染为第三种由颜色混合规则决定的颜色。

Input structure
- 背景为 Black 的网格中有若干 Grey 像素构成的一像素宽直线段，充当"墙壁"。墙壁将网格划分为若干连通的通道区域。
- 网格中散布着若干"箭头标记"，每个箭头由一个彩色像素（箭头头部）和与之正交相邻的一个同色像素（箭头尾部）组成，共占 2 个像素。箭头的朝向为从尾部指向头部的方向（上、下、左、右之一）。
- 每个箭头的颜色为 Red、Blue 或 Yellow 之一。
- 网格右下角有一个 3x3 的"混合图例"：行标和列标分别为 Red、Blue、Yellow 各一个像素，图例内 3x3 区域中每个格子的颜色表示对应行色与列色混合后的结果（如 Red+Blue=Magenta，Red+Yellow=Orange，Blue+Yellow=Green，同色混合=原色）。

Rule
- 从每个箭头的头部像素开始，沿箭头朝向逐格绘制该箭头的颜色，直到碰到墙壁像素、网格边界、或另一个箭头的头部像素为止（不覆盖这些阻挡物）。
- 所有箭头同时传播（非顺序执行）。若某个 Black 背景格子恰好被两条不同颜色的传播路径同时覆盖，则查找右下角混合图例，将该格子染为两色混合后的结果颜色。
- 若某格仅被一条路径覆盖，直接染为该路径颜色。
- 墙壁、箭头原始像素、以及混合图例区域保持不变。

Key insight
单纯的颜色传播是第一层推理，但混合规则的存在迫使解题者同时追踪多条传播路径的交汇点，并从图例中查找混合结果——这要求解题者先理解传播机制，再发现混合图例的编码方式，最后将两者结合。交汇判定和颜色混合构成了需要独立归纳的第二层推理。
</description>

<new_puzzle>
<description>
将每个对象按其内部孔洞的连通数分组，同组对象排列到输出网格的同一行中，行的排列顺序由孔洞数从少到多决定；同一行内对象的左右顺序由其原始位置的列坐标从左到右决定。

Input structure
- 背景为 Black 的网格中散布着若干 4-连通的单色对象（同一对象内所有像素颜色相同，不同对象颜色可能不同）。
- 每个对象内部可能包含 0 到 3 个"孔洞"——即被对象像素完全包围的 Black 连通区域（4-连通）。
- 对象之间互不接触。

Rule
- 对每个对象，计算其内部孔洞的数量（被该对象的像素完全 4-连通包围的 Black 区域的个数）。
- 将所有对象按孔洞数分组：孔洞数相同的对象归为一组。
- 输出网格的每一行对应一组，行从上到下按孔洞数递增排列（0 个孔洞在最上方）。
- 同一行内的对象按照它们在输入网格中包围盒左上角的列坐标从左到右排列，对象之间用一列 Black 背景分隔。每个对象以其紧凑包围盒形式绘制。
- 不同行之间用一行 Black 背景分隔。
- 输出网格的宽度为所有行中最宽者，较短的行右侧用 Black 填充；高度为所有行高度之和加行间分隔行数。

Key insight
颜色和形状都是干扰项——分组的唯一依据是孔洞数量这一拓扑属性，而非颜色或外形。解题者需要先发现孔洞计数作为分组键，再理解行排序和行内排序的双重规则。孔洞数量虽然需要"计数"，但由于数量极少（0-3），人眼可以直接识别。
</description>

<new_puzzle>
<description>
在由彩色像素构成的路径网络中，找到从起点标记到终点标记的唯一无分叉通路，并将通路上的所有像素统一重绘为终点标记的颜色。

Input structure
- 背景为 Black。
- 网格中有由多种颜色像素构成的单像素宽路径网络：路径像素之间通过 4-连通相连，形成若干分支和交叉点。路径中的像素颜色多样但与规则无关（是干扰信息）。
- 网格中恰好有两个特殊标记：一个 Red 的 2x2 实心方块（起点标记）和一个 Blue 的 2x2 实心方块（终点标记）。每个标记的某一条边与路径网络的某个端点像素 4-连通相邻。
- 路径网络中存在从起点标记相邻像素到终点标记相邻像素的唯一一条无分叉简单路径（即沿路径走时每一步只有一个前进方向，不计来路）。

Rule
- 从起点标记（Red 2x2）相邻的路径像素出发，沿路径网络行走。在每个路径像素处，检查其 4-连通邻居中除来路外的路径像素数量：若恰好只有一个前进方向则继续前进；若遇到分叉（多个前进方向）则停止该分支探索并回溯。
- 找到从起点到终点的唯一无分叉通路。
- 将该通路上的所有路径像素重绘为终点标记的颜色（Blue）。
- 路径网络中不在该通路上的像素保持原色不变。
- 两个 2x2 标记保持原样不变。

Key insight
路径像素的颜色是纯粹的干扰——解题者必须忽略颜色信息，转而关注路径的拓扑结构。"无分叉"是筛选正确路径的唯一标准，而终点标记的颜色才决定了重绘颜色。解题者需要先发现路径选择规则（无分叉），再发现重绘颜色的来源（终点标记），这构成两层推理。
</description>
</new_puzzle>
