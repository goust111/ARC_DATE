Input structure:
- 背景为黑色。网格中有若干条水平的灰色条带（高度为 1 像素，长度各异），每条条带代表一条"传送带"，不同传送带之间有至少两行黑色间隔。
- 每条传送带的最左端像素和最右端像素分别被替换为一个非灰色的彩色"端点标记"（例如左端为 Red，右端为 Blue），这两个端点颜色互不相同。
- 传送带上方紧邻的那一行中，在传送带水平范围内散布着若干单像素的彩色"货物"，每个货物可能是各种颜色。

Rule:
- 对每条传送带，读取其左端点颜色 L 和右端点颜色 R。
- 传送带上方的货物中，颜色为 L 或 R 的货物被保留；颜色既非 L 也非 R 的货物被清除为黑色。
- 保留的货物进一步分拣：颜色为 L 的货物向左平移，在传送带范围内紧靠左端点正上方依次向右排列（保持在上方那一行，互相紧邻无间隔）；颜色为 R 的货物向右平移，在传送带范围内紧靠右端点正上方依次向左排列。
- 传送带本身（包括端点标记）保持不变。

Key insight:
- 第一层推理需要发现端点标记不仅标示传送带的边界，还定义了该传送带"允许通过"的颜色集合，充当筛选器的角色。第二层推理需要发现被保留的货物不是原地不动，而是按其颜色被"吸引"到对应颜色端点的那一侧紧密聚集，实现了按颜色的双向分拣。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
