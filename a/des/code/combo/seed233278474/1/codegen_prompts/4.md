<new_puzzle index="4">
- `description`：根据种子像素周围 Grey 边框的缺口模式确定生长方向，按同色像素的全局计数确定分支长度，生成树状结构。

- `Input structure`：
  - 背景为 Black。
  - 网格中散布着若干单独的彩色像素（每种颜色出现 2-6 次），这些像素互不相邻（4-连通意义下孤立）。
  - 其中恰好有一个像素被一圈 Grey 像素包围（形成 3x3 的方框，中心为彩色像素），该像素为"种子像素"。

- `Rule`：
  - 第一层：确定分支方向。观察种子像素 3x3 Grey 边框的四条边（上、下、左、右各 3 格），找出哪些边有缺口（缺少至少 1 个 Grey 像素）。每条有缺口的边对应一个分支方向——缺口在上边则向上生长分支，缺口在右边则向右生长分支，以此类推。完整的边不产生分支。
  - 第二层：确定分支长度。统计种子像素颜色在整个网格中出现的总次数 N（包括种子自身）。每条分支从种子像素的相邻格出发，沿对应方向延伸 N 个像素，颜色与种子相同。
  - 第三层：分支端点标记。每条分支的末端像素（最远端）被改为 Maroon 色。
  - 原有的所有散布彩色像素（除种子外）保持不变。Grey 边框保持不变。

- `Key insight`：Grey 边框的缺口模式编码了分支的方向集合，而分支长度来自一个需要在全图范围内计数的同色统计量——解题者需要同时发现"缺口 -> 方向"和"同色计数 -> 长度"两个独立的编码规则，两者缺一不可。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
