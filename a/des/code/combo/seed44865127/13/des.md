- `description`：将网格中每个矩形区域的内部图案"投影"到其最近的网格边缘上，投影方向由区域内标记像素的位置决定。

- `Input structure`：
  - 背景为主色。
  - 若干不同颜色的实心矩形区域，每个区域内部有一个小型非bg图案。
  - 每个区域内恰好有一个grey单像素标记，位于区域的某一边附近。

- `Rule`：
  - 对每个区域，标记像素所靠近的边决定投影方向（靠近上边→向上投影，靠近右边→向右投影，以此类推）。
  - 将区域内的图案沿投影方向"压扁"到该方向的网格边缘上：图案的每一列（垂直投影时）或每一行（水平投影时）被压缩为该列/行中非bg像素数量长度的色条，紧贴边缘。
  - 色条使用图案的原始颜色。
  - 清除所有原始矩形区域和标记。

- `Key insight`：标记位置编码投影方向，投影是"按列/行统计然后边缘对齐"的操作而非简单平移。图案的二维结构被压缩为一维的边缘直方图。

<new_puzzle>
- `description`：在包含"密码锁"和"钥匙"的网格中，钥匙的颜色序列必须与锁的缺口颜色序列匹配后才能解锁——解锁后锁的内部被填充为钥匙的体色。

- `Input structure`：
  - 背景为主色。
  - "密码锁"：一个大型矩形框架，框架由多种颜色的像素组成（每边的颜色可能不同），内部为bg。框架有若干单像素缺口，每个缺口相邻的框架像素颜色构成"密码序列"（从上到下、从左到右读取缺口相邻色）。
  - "钥匙"：散布在网格中的小型彩色精灵，每个精灵由一种"体色"和若干"齿色"像素组成。齿色像素从体的一侧伸出，形成颜色序列。

- `Rule`：
  - 对每个密码锁，读取其缺口相邻色的序列。
  - 对每把钥匙，读取其齿色序列。
  - 当钥匙的齿色序列与锁的密码序列完全匹配时，该钥匙解锁该锁。
  - 解锁后，锁的内部填充为钥匙的体色。
  - 清除已使用的钥匙，保留未匹配的钥匙和锁。

- `Key insight`：匹配键不是形状而是颜色序列——缺口附近的颜色编码了密码，钥匙的齿色编码了钥匙码。体色是填充色而非匹配键。
</new_puzzle>

<new_puzzle>
- `description`：根据每个前景对象的"凹凸特征"从图例中选择填充图案，用选定图案填充对象的包围盒中的bg像素。

- `Input structure`：
  - 背景为主色。
  - 网格顶部有一行图例：若干小型2x2图案块从左到右排列，间隔一列bg。图例块使用不同颜色。
  - 图例下方有若干单色4-连通前景对象。
  - 每个对象的包围盒是矩形，对象本身可能不填满包围盒（有凹陷）。
  - 每个对象的凹陷数量（包围盒内bg连通区域的数量）在0-4之间。

- `Rule`：
  - 对每个对象统计凹陷数量 k。
  - 从图例中选取第 k+1 个图案块（从左起第1个对应0个凹陷）。
  - 将该图案在对象的包围盒中平铺，但只填充bg像素位置。
  - 保留对象原色像素和图例不变。

- `Key insight`：凹陷数量是图案选择的索引键——对象的"缺了多少块"决定了用哪种图案填补。图例的顺序位置隐式编码了从0开始的索引值。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的L形、T形和十字形对象分别用不同的"展开"方式转换为直线段，展开方式由形状类型决定。

- `Input structure`：
  - 背景为主色。
  - 若干同色4-连通前景对象，形状为以下三种之一：
    - L形：两段互相垂直的直线段在端点连接。
    - T形：一段直线段的中点连接另一段垂直线段的端点。
    - 十字形：两段互相垂直的直线段在中点交叉。
  - 对象使用同一种前景色。

- `Rule`：
  - L形：保留较长的一段不动，将较短的一段旋转到较长段的延长线上，形成一条直线。
  - T形：保留较长的主干不动，将分支段移动到主干的延长方向的端点，贴合主干延伸。
  - 十字形：保留水平段不动，将垂直段的两半分别移动到水平段的左右两端延伸。
  - 清除原始位置的多余像素。

- `Key insight`：每种形状有特定的"展开规则"，需要先识别形状类型（L/T/十字），再应用对应的变换。形状识别是第一层推理，展开方式选择是第二层。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到被"遮挡"的前景对象（部分像素被另一种颜色覆盖），根据对象形状的对称性推断被遮挡部分的位置，并用对象颜色修复遮挡。

- `Input structure`：
  - 背景为主色。
  - 若干不同颜色的前景对象，某些对象之间存在遮挡关系。
  - 被遮挡的对象原本具有某种对称性（水平或垂直），但遮挡破坏了这种对称性。
  - 遮挡者的颜色与被遮挡者不同。

- `Rule`：
  - 对每个前景颜色，从其可见像素推断其完整的对称形状。
  - 如果可见像素几乎关于某轴对称但缺少部分镜像像素：
    - 确定缺失位置（镜像位置应有自身颜色但当前被其他颜色占据）。
    - 将遮挡像素替换为被遮挡对象的颜色。
  - 无对称性缺失的对象保持不变。

- `Key insight`：修复依据是对称性而非简单的空间扩展——只有在镜像位置被其他颜色占据的情况下才进行修复。需要先为每个对象确定正确的对称轴，再利用对称性推断被覆盖的位置。
</new_puzzle>
