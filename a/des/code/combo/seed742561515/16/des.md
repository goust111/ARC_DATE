- `description`：根据框架内部色块的拓扑排列推断缺失色块的颜色，然后将完整的色块图案作为印章盖到网格中所有同色框架的内部。

- `Input structure`：
  - 背景为 black。
  - 网格中散布若干大小相同的正方形空心框架（边框宽度为 1 像素），每个框架由单一颜色绘制（如 red、blue、green 等）。
  - 每个框架内部被等分为 2×2 的四个格子，其中若干格子已填充了非背景、非框架颜色的色块，其余格子为空（black）。
  - 网格中恰好有一个框架的内部四个格子全部填满（无空缺），该框架称为"模板框架"。
  - 其余框架各自缺少 1-3 个格子的填充。
  - 所有框架（含模板框架）的框架颜色互不相同。

- `Rule`：
  - 找到内部四格全部填满的模板框架，读取其 2×2 色块排列作为"完整图案"。
  - 对每个非模板框架，将其内部已有色块与模板图案做位置对照，推断出缺失位置应填的颜色。
  - 将缺失位置补上对应颜色，使所有框架内部的 2×2 图案与模板框架完全一致。
  - 框架本身的颜色和位置保持不变，背景不变。

- `Key insight`：解题者需要先识别哪个框架是完整的模板（通过内部填充数判断），然后将模板的空间色彩排列映射到其余框架上补全缺失——两步都需要非显然推理：第一步需要理解"完整性"的判定标准，第二步需要理解位置对应而非颜色对应。
</new_puzzle>

- `description`：将散落的彩色 L 形碎片按颜色配对拼合成完整矩形，然后按矩形面积从小到大将它们堆叠排列到输出网格的指定锚点位置。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干 4-连通的彩色对象，每种非背景颜色恰好出现两个独立对象。
  - 每对同色对象的形状互补：将它们像拼图一样拼在一起（其中一个需要旋转 180 度）可以组成一个无缝的实心矩形。
  - 网格底部有一行 grey 像素标记，标记行中有一个单独的 maroon 像素作为锚点。

- `Rule`：
  - 对每种颜色，找到两个同色对象，将其中一个旋转 180 度后与另一个拼合，确定它们组成的矩形尺寸。
  - 按拼合后矩形的面积从小到大排序。
  - 清空网格（保留 grey 标记行），以锚点 maroon 像素为底部中心，从下往上依次水平居中堆叠各矩形，矩形之间无间隔。
  - 每个矩形用其对应颜色实心填充。

- `Key insight`：解题者首先需要发现同色对象互补拼合的关系（而非简单匹配），然后需要推断排序依据是拼合后的矩形面积而非对象本身的像素数，最后理解堆叠的锚点和方向规则。
</new_puzzle>

<new_puzzle>
- `description`：沿着彩色路径的方向传播"染色波"，路径上每个交叉点处根据先到颜色决定后续分支的染色权。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 grey 像素绘成的一像素宽直线路径（水平或垂直），路径之间在交叉点处相交形成网络。
  - 在网络的若干末端（度为 1 的端点）各放置一个不同颜色的单像素种子（如 red、blue、green 等）。
  - 每个种子紧邻一条 grey 路径的端点。

- `Rule`：
  - 所有种子同时开始沿其相邻的 grey 路径传播，每步染色一个 grey 像素为种子颜色，速度相同（每步一像素）。
  - 当两种颜色的波前同时到达同一个 grey 像素时，该像素染为 yellow（混合标记）。
  - 当波前到达一个交叉点时，它继续沿所有可通行的分支传播，但不进入已被其他颜色占据的路径像素。
  - 传播持续直到所有 grey 像素都被染色或标记。
  - 种子像素自身保持原色不变。

- `Key insight`：解题者需要模拟多源同步扩散过程，关键在于理解"同时到达"产生特殊标记色，以及交叉点处的分支传播规则——这不是简单的洪水填充，而是竞争式领地划分，碰撞边界用第三种颜色标记。
</new_puzzle>

<new_puzzle>
- `description`：根据小型"指令方块"中箭头的朝向和颜色，对网格中同色的大型图案执行对应的翻转或旋转变换。

- `Input structure`：
  - 背景为 azure。
  - 网格被一条 grey 水平分割线分为上下两个区域。
  - 上方区域包含若干彩色的 4-连通图案对象，每个图案颜色唯一。
  - 下方区域包含若干 3×3 的"指令方块"，每个指令方块的外围 8 格为某种颜色（与上方某个图案颜色相同），中心 1 格为 black。
  - 每个指令方块的外围 8 格中，恰好有一个格子被替换为 maroon 像素，形成一个"箭头"指向中心的某个方向（上、下、左、右、四个对角之一）。

- `Rule`：
  - 将每个指令方块与上方同色图案配对。
  - maroon 像素相对于中心的方位决定变换类型：
    - 上方 → 垂直翻转（上下镜像）
    - 下方 → 保持不变
    - 左方 → 水平翻转（左右镜像）
    - 右方 → 旋转 180 度
    - 左上 → 逆时针旋转 90 度
    - 右上 → 顺时针旋转 90 度
    - 左下 → 沿主对角线转置
    - 右下 → 沿副对角线转置
  - 对上方每个图案原地执行对应变换（以图案的包围盒左上角为锚点重新绘制）。
  - 下方区域（含指令方块和分割线）在输出中被移除，输出仅保留上方区域。

- `Key insight`：解题者需要两层推理——第一层是理解 3×3 指令方块中 maroon 标记的位置编码了一个方向，第二层是发现每个方向映射到一种特定的几何变换，而这种映射关系需要从多个样例中归纳得出（方向与变换的对应并非直觉上显然）。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多个"信封"对象拆开，根据信封的开口方向展开内部隐藏的图案，并将展开后的图案拼接到信封的开口侧。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干互不重叠的"信封"对象。每个信封由一个实心矩形区域构成，外层为一种颜色（信封颜色），内层隐藏着一个较小的彩色图案。
  - 每个信封的某一条边（上、下、左或右）有一个缺口：该边中间连续若干像素为背景色，形成"开口"。
  - 信封的内部图案被信封颜色完全包裹，仅通过开口方向可以推测展开方向。
  - 内部图案的形状和颜色各异，但其宽度或高度（取决于开口方向）与开口尺寸一致。

- `Rule`：
  - 对每个信封，确定其开口所在的边和方向。
  - 将信封内部的隐藏图案沿开口方向"滑出"：在开口外侧、紧邻信封的位置绘制该图案。具体来说，图案从信封内部的原始位置沿开口方向平移，直到图案完全离开信封区域。
  - 信封内部原本被图案占据的像素替换为信封颜色（即信封变为完整的实心矩形，开口除外）。
  - 开口保持不变（仍为背景色）。

- `Key insight`：解题者需要首先识别信封结构和开口位置（这需要理解矩形边界上的缺口含义），然后推断内部图案的存在并理解"滑出"机制——图案沿开口方向完整平移到信封外部，而信封自身被填补完整。关键在于认识到信封是容器、开口是出口方向、内部非信封色像素是待展开的内容。
</new_puzzle>

<new_puzzle>
- `description`：利用散落的颜色碎片重建一幅被"碎纸机"切割并打乱列顺序的图像，切割宽度由图像边缘的刻度标记决定。

- `Input structure`：
  - 背景为 black。
  - 网格的主要区域是一个由多种颜色组成的矩形图像区域，但该图像已被垂直切割成若干等宽的竖条，竖条的左右顺序被打乱。
  - 图像区域的正上方有一行 grey 刻度标记，每隔固定间距放置一个 grey 像素，标示切割位置。
  - 图像区域的正下方有一行彩色序号标记：从左到右依次排列若干单像素色块，颜色各异。
  - 每个竖条的最顶部一行像素中，恰好有一个像素的颜色与某个序号标记颜色相同，作为该竖条的"标签"。

- `Rule`：
  - 根据 grey 刻度标记确定切割宽度（相邻两个 grey 像素之间的间距）。
  - 按此宽度将图像区域分割为若干竖条。
  - 读取每个竖条顶行中的彩色标签像素，与下方序号标记行的颜色从左到右逐一匹配。
  - 按照序号标记行中颜色从左到右的顺序，重新排列各竖条。
  - 输出重新排列后的图像区域，移除刻度标记行和序号标记行，同时将每个竖条顶行的标签像素恢复为该位置在图案中的本来颜色（即用该竖条第二行同列的像素颜色覆盖标签像素）。

- `Key insight`：解题者需要三层推理——第一层是从刻度标记推断切割宽度，第二层是在每个竖条中找到颜色标签并与序号行建立对应关系，第三层是理解序号行的空间顺序就是竖条的正确排列顺序。整个过程模拟了"碎纸复原"但用纯视觉线索替代了拼接边缘匹配。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到由边框颜色编码的"窗户"，根据窗户内已有色块的对称缺失模式补全窗户内容，对称类型由窗户边框的形状特征决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干矩形"窗户"，每个窗户由一像素宽的彩色边框围成，内部包含一些彩色像素图案和空白（black）区域。
  - 每个窗户的边框在四条边上可能有细微差异：某些边的边框是双层的（即该边有两像素宽），而其余边是单层的。
  - 双层边所在的边定义了一条对称轴：若上下两条边是双层的，则对称轴为水平中线；若左右两条边是双层的，则对称轴为垂直中线；若四条边都是双层的，则同时沿两条中线对称（即点对称）。

- `Rule`：
  - 对每个窗户，检查其四条边框的厚度（单层或双层），确定对称类型。
  - 仅水平双层边 → 沿水平中线做上下镜像补全。
  - 仅垂直双层边 → 沿垂直中线做左右镜像补全。
  - 四边均双层 → 同时沿水平和垂直中线做双轴镜像补全（等价于 180 度旋转对称）。
  - 补全时，已有像素不变，空白位置用对称位置的颜色填充。若对称位置也为空白，则保持空白。
  - 窗户边框本身不变。

- `Key insight`：解题者需要先注意到边框厚度的微妙差异（单层 vs 双层），然后推断出厚度编码了对称类型，最后按对应的对称方式补全内部图案。难点在于边框厚度差异很细微，且对称类型的编码规则需要跨多个样例归纳。
</new_puzzle>
