- `description`：根据每个封闭区域内标记像素的颜色，跨区域查找对应的缺口标签，用目标缺口的方位决定当前区域内图案的挤出方向，将图案从缺口投影到外部背景上。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由灰色（grey）线段围成的封闭矩形区域，每个区域的边界上恰好有一个单像素宽的缺口。
  - 每个封闭区域内部包含一个由某种非灰色、非黑色前景色构成的小型图案（由多个像素组成的4连通形状），以及恰好一个不同颜色的单独标记像素。
  - 每个矩形区域的缺口外侧紧邻一个单像素颜色标签（紧贴缺口外部），标签颜色各不相同，且与区域内图案的颜色和标记像素的颜色都不同。
  - 标记像素的颜色在整个网格中与某个其他区域的缺口外侧标签颜色一致——这构成跨区域的指向关系。

- `Rule`：
  - 第一步匹配：每个区域内的标记像素颜色指向另一个区域——找到缺口外侧标签颜色与该标记像素颜色相同的那个目标区域。
  - 第二步确定方向：目标区域的缺口位于其灰色边界的哪一侧（上、下、左、右），该方位即为当前区域内图案的挤出方向。
  - 第三步投影：将当前区域内的图案（不含标记像素）从当前区域的缺口处沿确定的方向平移到区域外部的黑色背景上。图案整体保持形状不变，其最靠近缺口方向的一行/列像素紧邻缺口外侧放置。
  - 原始区域内的图案和标记像素被清除为黑色，灰色边界、缺口和缺口外侧标签保持不变。

- `Key insight`：标记像素不是装饰，而是跨区域的指针——它的颜色将当前区域链接到另一个区域的缺口标签，而目标缺口的方位才决定了当前图案的移动方向。解题者需要先建立"标记颜色→缺口标签颜色"的跨区域对应关系，再用目标区域的缺口朝向反过来驱动当前区域的图案投影。这包含两层非显然推理：一是发现颜色指针的跨区域匹配机制，二是理解"方向来自目标而非自身"的间接控制逻辑。
</new_puzzle>

- `description`：将网格中散布的同色像素群按其包围盒的宽高比分类，匹配底部图例中的标准几何图元，再以像素数量为尺寸参数在包围盒中心重绘对应图元。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格上方散布着若干种前景色的孤立像素（每种颜色3到7个像素，同色像素互不相邻）。
  - 网格底部两行是颜色图例区：从左到右排列着三个小型标准图元示例，每个图元用独有的颜色绘制——第一个是一个3像素高、2像素宽的实心矩形（6像素），第二个是一个5像素的十字形（中心1格加上下左右各延伸1格），第三个是一个4像素的L形（垂直2格加水平向右延伸1格，呈直角）。图例中的三种颜色不出现在上方散布区域中。
  - 图例区与上方散布区域之间有至少一行黑色间隔。

- `Rule`：
  - 对上方散布区域的每种前景色，收集该颜色所有像素位置，计算最小包围矩形的宽 W 和高 H。
  - 按宽高比分类匹配图例图元：若 W 和 H 相等或差值不超过1（近似正方形），匹配十字形图元；若 W 比 H 大2或以上（明显横宽），匹配实心矩形图元；若 H 比 W 大2或以上（明显纵高），匹配L形图元。
  - 该颜色的像素总数 N 决定输出图元的大小：十字形的每臂长度为 N-1（总像素为4*(N-1)-3）；矩形的短边为2、长边为 N；L形的长边为 N-1、短边为2。
  - 在输出中，抹去该颜色的所有原始散布像素，在该组包围盒的中心位置绘制对应的缩放图元，使用该组原始颜色。图元以其自身中心对齐包围盒中心。
  - 图例区原样保留。

- `Key insight`：散布像素的空间分布形态不是随机的——它们的包围盒宽高比隐含编码了"该组应被重绘为哪种几何图元"，而像素数量编码了图元尺寸。解题者需要先从图例区认出三种标准形状，再发现包围盒的形状特征是将像素组映射到图元类型的分类依据，最后用计数来确定缩放参数。
</new_puzzle>

- `description`：网格中每个灰色封闭对象根据其内部孔洞数量，在左侧调色板中查找对应颜色并重新着色，调色板的索引位置对应孔洞计数。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格最左列有一列垂直排列的单像素色块，从上到下排列着不同颜色（例如从上到下依次为红 red、绿 green、蓝 blue、黄 yellow），形成一个有序调色板，色块之间间隔一个黑色像素。调色板中第一个颜色对应"0个孔洞"，第二个对应"1个孔洞"，以此类推。
  - 网格中部和右侧散布着若干个由灰色（grey）像素构成的8连通对象，大小和形状各异。每个灰色对象是一个封闭或半封闭的不规则形状，内部可能包含0个、1个或多个由黑色背景构成的孔洞。孔洞定义为完全被灰色像素4连通包围的黑色连通区域（4连通）。
  - 每个灰色对象的孔洞数量不超过调色板长度减1。
  - 所有灰色对象之间互不接触。

- `Rule`：
  - 读取最左列调色板，从上到下建立索引：第1个颜色→0个孔洞，第2个颜色→1个孔洞，第3个颜色→2个孔洞，依此类推。
  - 对每个灰色8连通对象，识别其内部被灰色完全包围的黑色4连通区域，统计这些孔洞的数量 H。
  - 将该灰色对象的所有像素重新着色为调色板中索引为 H 的颜色（第 H+1 个色块）。
  - 孔洞区域本身保持为黑色，不填充。
  - 输出中移除调色板色块（调色板位置恢复为黑色）。

- `Key insight`：灰色对象表面看起来形状各异、大小不一，但真正的分类依据不是外形轮廓、面积或位置，而是拓扑属性——内部孔洞的数量。调色板提供了从拓扑量到颜色的查找表，但解题者需要先意识到孔洞计数是唯一相关的分类维度，再在边缘找到并正确解读调色板的索引规则。

- `description`：网格中每个房间内的彩色种子像素根据颜色图例确定其生长方向集合，种子沿对应方向延伸射线直到遇到墙壁，在房间内形成方向受控的枝状结构。

- `Input structure`：
  - 背景为黑色（black）。
  - 灰色（grey）像素构成单像素宽的直线墙壁，将网格划分为若干个矩形房间。所有墙壁形成完整的矩形网格分割（横竖交叉的灰色线）。
  - 每个房间内部恰好有一个非黑色、非灰色的单像素种子，颜色为红（red）、蓝（blue）或绿（green）三种之一。
  - 网格左上角有一个由灰色墙壁围起的特殊图例区域，内部包含三个并排的3×3示例格。每个示例格中心为一种颜色的像素，从该中心沿特定方向延伸了1格同色像素，其余位置为黑色：红色中心向上和向下各延伸1格（即红色占据一条垂直3像素线段）；蓝色中心向左和向右各延伸1格（即蓝色占据一条水平3像素线段）；绿色中心向上下左右各延伸1格（即绿色占据一个5像素十字形）。三个示例格之间用灰色线分隔。

- `Rule`：
  - 从图例区解读颜色-方向映射：红色→上、下两个方向（垂直延伸），蓝色→左、右两个方向（水平延伸），绿色→上、下、左、右四个方向（十字延伸）。
  - 对图例区以外的每个房间，找到其内部的种子像素，确定其颜色。
  - 从种子位置出发，沿该颜色对应的每个方向，逐像素延伸同色像素，直到下一个位置是灰色墙壁或网格边缘时停止（不覆盖墙壁像素）。
  - 种子像素本身保留。图例区域保持不变。
  - 所有其他黑色背景像素和灰色墙壁保持不变。

- `Key insight`：种子的颜色不仅标识"画什么颜色"，更编码了"往哪些方向画"——这是一种颜色即指令的间接编码。解题者需要先从图例区破译三种颜色分别对应的方向集合，再将该映射规则应用到每个房间的种子上。图例是一个需要主动解读的行为编码表，而非仅仅是调色板。
</new_puzzle>

<new_puzzle>
- `description`：网格中的箭头形状为同色源对象编码了两个独立指令——箭头朝向决定镜像翻转轴（水平或垂直），箭头相对于源对象的方位决定镜像副本的放置侧，最终擦除箭头并在指定位置绘制源对象的镜像。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干对同色配对的前景对象，每对由一个"源对象"和一个"箭头"组成，颜色相同用于配对。不同颜色对之间互不影响。
  - 源对象：任意不规则的4连通形状，面积至少4像素。
  - 箭头：由同色5个像素构成的标准箭头形状。箭头的绘制方式固定为：3个像素构成直线箭杆（水平或垂直连续排列），箭杆的一端（箭头尖端侧）的前一个像素位置的两侧各有1个像素，构成箭头的三角尖端。具体地：若箭头朝右，则箭杆为3个水平像素，箭杆最右端的右侧1格为尖端中心，尖端中心的上下各1格各有1个像素（但因箭头总共5像素，实际结构为：箭杆3像素水平排列，箭杆末端像素的上方和下方各1像素）。其他方向类推——箭杆末端像素在垂直于箭杆的方向上两侧各延伸1像素。
  - 每种前景色恰好出现一个源对象和一个箭头。
  - 箭头位于源对象的正上方、正下方、正左方或正右方（箭头 bounding box 的中心与源对象 bounding box 的中心在一个坐标轴上严格对齐，另一轴上箭头在源对象外侧）。

- `Rule`：
  - 第一步配对：通过颜色将每个箭头与其对应的源对象匹配。通过面积区分箭头（恰好5像素）和源对象（大于5像素）。
  - 第二步确定翻转轴：箭头尖端朝上或朝下时，对源对象执行上下翻转（沿水平轴镜像）；箭头尖端朝左或朝右时，对源对象执行左右翻转（沿垂直轴镜像）。
  - 第三步确定放置位置：镜像副本放置在源对象的箭头所指方向一侧。副本的 bounding box 近边缘与源对象 bounding box 在箭头方向上的远边缘之间间隔2个像素（即中间空2格黑色）。
  - 第四步绘制：保留源对象不变，在计算位置绘制镜像副本（使用同色）。擦除该颜色的箭头像素（恢复为黑色）。

- `Key insight`：箭头同时编码了两个独立信息通道——其尖端朝向编码镜像类型（上下翻转还是左右翻转），其相对于源对象的空间方位编码镜像副本的放置方向。解题者需要先通过面积差异识别出5像素的箭头并与源对象区分开，再分别解读朝向和位置这两条独立的指令通道，缺一不可。
</new_puzzle>

- `description`：根据彩色区域被灰色切割线分成的碎片数量对颜色排序，将排序结果编码为输出网格底部从左到右排列的色块序列。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个不同前景色的4连通区域（例如红 red、蓝 blue、绿 green、黄 yellow、橙 orange），每个区域是一块面积较大的连通色块，形状不规则。
  - 若干条灰色（grey）直线贯穿网格（水平或垂直，从一侧边缘到另一侧边缘，宽度为1像素）。这些灰色线覆盖在彩色区域之上——灰色线经过彩色区域时，将该区域的对应像素覆盖为灰色，从而可能把一个原本连通的彩色区域在视觉上切割成多个不连通的碎片。
  - 网格最底部预留两行黑色空行，用于放置排序结果。
  - 每种前景色的碎片数量（被灰色线切割后的4连通分量数）互不相同，保证排序唯一。

- `Rule`：
  - 对每种前景色，在当前网格中统计该颜色的像素形成的4连通分量数量 K（灰色线已将某些位置覆盖，所以被切断处的像素不存在，直接统计剩余同色像素的连通分量数即可）。
  - 按 K 值从小到大对所有前景色排序。
  - 在底部预留行中，从左到右依次绘制排序后每种颜色的2×2实心色块，色块之间间隔1列黑色。第一个色块的左上角位于倒数第二行、第1列。
  - 网格上方的所有彩色区域、灰色线和黑色背景保持不变。

- `Key insight`：灰色线不仅是视觉上的分隔装饰，它是"切割工具"——每种颜色被切成的碎片数量是排序的关键。解题者需要先理解灰色线对彩色区域的切割效应（碎片计数），再发现底部色块序列是按碎片数从少到多排列的。这包含两层推理：一是识别"灰色线切割→碎片计数"的机制，二是发现"碎片数→排序→底部编码"的输出规则。
</new_puzzle>
