<new_puzzle index="2">
将散落的彩色碎片按形状互补性拼合，并用两块碎片颜色的混合规则决定拼合体的最终颜色。

Input structure
- 背景为主色（black）。网格中散布着若干 4-连通的彩色碎片（每个碎片为单一颜色）。
- 每个碎片的形状恰好能与另一个碎片拼合成一个完整的矩形（即两块碎片的边界箱尺寸相同，像素位置互补——一个碎片占据的格子恰好是另一个碎片在同尺寸边界箱内未占据的格子）。
- 互补碎片对的颜色各不相同。网格中还存在一个位于右下角的小型 2×N 颜色查找表：每行包含两个颜色像素，表示"当这两种颜色的碎片拼合时，结果矩形使用第三种颜色"——第三种颜色绘制在该行右侧紧邻的一个额外像素中。

Rule
- 识别所有互补碎片对：两个碎片的边界箱尺寸相同，且像素位置在边界箱坐标系中完全互补。
- 将每对碎片平移拼合到同一位置（以两者中位置靠左上的碎片为锚点）。
- 在颜色查找表中找到与这对碎片两种颜色匹配的行，将拼合后的完整矩形统一涂为该行指定的第三种颜色。
- 删除查找表本身，背景保持不变。

Key insight
- 第一层推理是空间互补性——需要发现哪些碎片在形状上恰好拼成矩形；第二层推理是颜色映射——拼合后的颜色既不是碎片 A 的颜色也不是碎片 B 的颜色，而是由查找表决定的第三种颜色。两层规则缺一不可。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
