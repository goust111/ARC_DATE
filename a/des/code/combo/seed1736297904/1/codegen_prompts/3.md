- `description`：沿分隔线对两侧同色对象进行面积比较，胜出对象镜像复制到对面一侧，落败对象被擦除。
- `Input structure`：背景为最常见颜色。网格正中有一条贯穿全宽（水平）或全高（垂直）的单像素分隔线（使用独特颜色，如 maroon）。分隔线两侧各分布着若干单色四连通前景对象，颜色各异。两侧的对象在颜色上形成一一配对关系——即左侧（或上侧）某颜色的对象在右侧（或下侧）也有且仅有一个同颜色的对象，但两者的位置和大小不同。
- `Rule`：
  1. 对每一对同颜色的对象，比较它们的像素数量（面积）。
  2. 面积较大的对象"胜出"，面积较小的对象"落败"。
  3. 落败的对象被擦除为背景色。
  4. 将胜出对象沿分隔线做镜像反射，复制到对面一侧（落败对象原来所在的区域附近），镜像副本使用胜出对象的颜色。镜像的锚点为对象包围盒中心关于分隔线的对称位置。
  5. 如果镜像位置与其他已存在的胜出对象重叠，则重叠像素保留距离分隔线更近的对象的颜色。
  6. 分隔线本身保持不变，胜出对象的原始副本也保留。
- `Key insight`：解题者需要先发现两侧对象的颜色配对关系，再发现面积比较决定胜负方向，最后才是镜像操作——三层推理环环相扣，而表面看上去像是简单的对称题。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
