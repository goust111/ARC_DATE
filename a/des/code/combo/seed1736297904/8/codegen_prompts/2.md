- `Input structure`：背景为 Black。网格中有若干条水平或垂直的单色色带（宽度为 1 像素、长度跨越大半个网格）。网格中另有若干箭头形精灵，每个箭头由 5 个像素组成：一个尖端像素和与之相邻的一个 1×3 或 3×1 矩形体。箭头朝向（上/下/左/右）由尖端相对于矩形体的方位决定。每个箭头的颜色与恰好一条色带的颜色相同，且箭头的指向方向指向该同色色带。同一颜色不会有两个箭头。
- `Rule`：
  1. 对每个箭头，沿其尖端所指方向找到与之颜色相同的色带。
  2. 将箭头从网格中移除（恢复为背景 Black）。
  3. 在该色带上，以箭头尖端沿指向方向投影到色带时所对准的位置为中心，擦除与箭头矩形体等宽（3 像素）的一段，形成缺口（恢复为 Black）。
  4. 若箭头水平指向一条垂直色带，则缺口为该垂直色带上连续 3 个像素被擦除；若箭头垂直指向一条水平色带，则缺口为该水平色带上连续 3 个像素被擦除。
  5. 没有被箭头指向的色带保持不变。
- `Key insight`：解题者首先需要识别箭头的朝向和颜色配对关系（箭头颜色 = 目标色带颜色），然后理解箭头并非"印"在色带上，而是"击穿"色带——箭头消失的同时在色带上留下精确的缺口。缺口的位置由箭头沿指向方向的投影位置决定，缺口宽度由箭头体的宽度决定。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
