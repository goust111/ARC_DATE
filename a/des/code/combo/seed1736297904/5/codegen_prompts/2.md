<new_puzzle index="2">
- `description`：将网格中散落的同色像素簇按照各簇的像素数量排序，然后用排序后的顺序重新分配颜色——最小的簇获得原本最大簇的颜色，最大的簇获得原本最小簇的颜色，依此类推。
- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个 4-连通的前景色簇（每个簇内部颜色相同），每个簇的颜色互不相同。
  - 每个簇的像素数量也互不相同（保证排序无歧义）。
  - 簇的形状各异，可以是 L 形、线段、小方块等。
- `Rule`：
  - 按像素数量从小到大排列所有簇，得到尺寸序列 S1 < S2 < … < Sn。
  - 同时按像素数量从小到大记录它们原本的颜色序列 C1, C2, …, Cn。
  - 将颜色序列反转为 Cn, Cn-1, …, C1，然后重新赋予：尺寸最小的簇 S1 获得颜色 Cn，尺寸次小的簇 S2 获得颜色 Cn-1，以此类推。
  - 每个簇的形状和位置不变，仅颜色改变。
- `Key insight`：解题者需要同时完成两件非平凡的归纳：（1）发现排序的依据是每个簇的面积（像素数量），而非位置、颜色本身或形状；（2）发现颜色的重分配方式是"大小反转映射"——最小换最大的颜色。单独看任何一个簇的变化都无法得出规则，必须纵览全局排序关系。
</new_puzzle>

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
