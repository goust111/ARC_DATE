- `description`：根据边框颜色在图例中查找对应的填充图案，将图案平铺入每个边框围成的空心矩形内部。

- `Input structure`：
  - 黑色背景上有一块图例区域和若干散布的空心矩形。
  - 图例区域位于网格顶部，由一条灰色水平分隔线与下方区域隔开。
  - 图例区域内包含若干小型"样本块"：每个样本块由一个 1 像素厚的单色边框围成一个 3×3 的内部区域，内部填有某种两色或单色的重复图案（如棋盘格、横条纹、竖条纹等）。不同样本块的边框颜色互不相同。
  - 分隔线下方散布着若干较大的空心矩形，每个矩形由 1 像素厚的单色边框围成，内部全为黑色。这些矩形的边框颜色各自对应图例中某一个样本块的边框颜色。矩形的内部尺寸不一，但宽和高均 ≥ 3。

- `Rule`：
  - 第一步——建立图例映射：在图例区域中，为每个样本块提取其边框颜色 C 和其内部 3×3 的图案 P(C)。
  - 第二步——填充下方矩形：对于分隔线下方的每个空心矩形，找到其边框颜色 C，从图例中查到 P(C)，然后将 P(C) 以平铺（tile）方式填满该矩形的内部区域（从矩形内部的左上角开始，按行按列重复图案，超出部分截断）。
  - 边框本身和分隔线保持不变。

- `Key insight`：边框颜色不是装饰，而是通往图例的查找键；解题者必须先在图例中建立"颜色 → 图案"的对应关系，然后才能知道每个矩形内部应该填什么。图案的平铺对齐方式（始终从矩形内部左上角开始）是隐含的第二层规则，需要从多个不同尺寸的矩形样例中归纳出来。

- `description`：将网格中散落的同色像素簇识别为箭头形状，根据箭头指向的方向从尖端射出一条同色射线，射线遇到障碍物或网格边界时停止，然后将箭头本身擦除。

- `Input structure`：
  - 背景为黑色的矩形网格。
  - 网格上散布着若干 4-连通的前景色簇，每个簇由恰好两种颜色组成：一种"主体色"构成箭头的杆部（直线段，长度 ≥ 2），另一种"尖端色"构成箭头的头部（恰好 1 个像素，位于杆部的一端）。
  - 箭头杆部严格沿水平或垂直方向排列。尖端像素位于杆部某一端的延长线方向上、紧邻杆部末端。
  - 箭头之间不相邻（任意两个簇的像素之间 4-邻域不接触）。
  - 网格上可能还有若干单色矩形障碍物（非黑色，也不与任何箭头颜色相同），静止不动。

- `Rule`：
  - 确定每个箭头的指向：箭头从杆部尾端指向尖端像素所在的方向（上 / 下 / 左 / 右）。
  - 从尖端像素的位置开始，沿箭头指向的方向逐像素画出一条射线，颜色为尖端色。射线在碰到第一个非黑色像素（障碍物或网格中已有的前景像素）之前的最后一个黑色像素处停止（不覆盖障碍物），或到达网格边缘时停止。
  - 所有射线同时计算（即判断障碍时仅考虑原始输入中的非背景像素，射线之间互不阻挡）。
  - 绘制完所有射线后，将所有箭头像素（杆部 + 尖端）擦除为黑色，只保留射线和障碍物。

- `Key insight`：解题者需要完成两层推理——第一层是从每个像素簇的形状中辨认出"箭头"结构，并通过尖端像素相对于杆部的位置推断指向方向；第二层是理解射线的绘制规则（从尖端出发、遇障碍停止、箭头本身消失）。箭头的方向不由位置或颜色决定，而由其内部两色像素的几何排布决定。
</new_puzzle>

- `description`：在一组嵌套的同心矩形环中，根据每层环上缺口的数量查阅角落调色板，对环重新着色：缺口数相同的环染为相同颜色，缺口数不同的环染为不同颜色。

- `Input structure`：
  - 黑色背景上有一组严格嵌套的同心矩形环（不一定正方形），共享同一个中心点。所有环在输入中均为同一种前景色（如灰色）。
  - 每个环是 1 像素厚的矩形轮廓线，但某些环上有若干"缺口"——即轮廓线上有 1 个像素被擦成了黑色。缺口仅出现在环的边上（不在角上）。
  - 不同环上的缺口数量可能相同，也可能不同；缺口数量范围为 0 到 4。
  - 网格左上角放有一个小的调色板条：从左到右依次为 5 个不同颜色的像素（如 blue、red、green、yellow、magenta），分别代表缺口数 0、1、2、3、4 对应的输出颜色。

- `Rule`：
  - 第一步——读取调色板：从左上角调色板条中读出 5 个颜色，建立映射：palette[0]、palette[1]、palette[2]、palette[3]、palette[4]。
  - 第二步——计数缺口：对每个矩形环，数出其轮廓线上被擦除为黑色的像素数量 k。
  - 第三步——重新着色：将该环上所有仍存在的前景像素重新着色为 palette[k]。缺口处保持黑色不变。
  - 调色板条本身在输出中保持不变。

- `Key insight`：所有环在输入中看起来颜色相同，解题者不能靠颜色区分它们——必须逐环检查缺口数量，然后去角落调色板中查找对应颜色。调色板的存在容易被忽视（因为它很小且在角落），而缺口数量作为索引键是核心的非显然规则。
</new_puzzle>

- `description`：网格中有若干由墙壁围成的封闭房间，每个房间内有一个彩色"种子"像素和一条灰色"路径"；将种子的颜色沿路径扩散着色，然后根据路径末端所触碰的墙壁方位，在墙壁外侧对应位置放置一个同色标记。

- `Input structure`：
  - 黑色背景上有若干由 maroon 色像素围成的封闭矩形房间（墙壁厚度为 1 像素）。房间之间不重叠、不相邻。
  - 每个房间内部包含：恰好 1 个非黑非灰非 maroon 的彩色"种子"像素；以及由灰色像素组成的一条 4-连通路径（宽度为 1 像素，无分叉）。路径的一端与种子像素 4-相邻，另一端与房间某面墙壁的内侧 4-相邻。
  - 路径不接触房间的角落像素，且路径末端只接触一面墙（不在墙角处）。

- `Rule`：
  - 第一步——着色路径：将每个房间内的灰色路径像素全部染为该房间种子像素的颜色。
  - 第二步——确定出口方向：找到路径末端（远离种子的那一端）所接触的那面墙。判断该墙是房间的上墙、下墙、左墙还是右墙。
  - 第三步——放置外部标记：在该面墙的外侧、与路径末端正对的位置（即末端像素沿垂直于墙壁的方向向外平移 1 格的位置），放置一个与种子同色的像素。
  - 墙壁（maroon）保持不变；种子像素保持不变。

- `Key insight`：解题者首先需要理解灰色路径的"导管"作用（将颜色从种子引导到墙壁），然后需要发现路径末端所接触的墙壁决定了标记出现在房间外的哪一侧。路径的弯曲和长短是干扰项——真正有意义的只有路径末端触墙的位置和方向。颜色传递和空间投射是两个需要分别归纳的推理层。
</new_puzzle>

- `description`：网格中有若干由前景色构成的闭合图形和内部的切割线；按每个图形被切割出的子区域数量排序，然后用网格底部调色板中的颜色序列依次对图形轮廓重新着色。

- `Input structure`：
  - 黑色背景上有若干互不接触的闭合图形，每个图形由同一种前景色（如 blue）的 1 像素厚轮廓线围成。
  - 某些图形内部存在由另一种颜色（如 red）绘制的直线段（"切割线"），这些线段的两端分别接触图形轮廓的两侧（将图形内部空间分割为多个子区域）。切割线严格沿水平或垂直方向，宽度为 1 像素。
  - 一个图形内部可能有 0 条、1 条或多条切割线；多条切割线可以交叉。
  - 网格底部有一行调色板：从左到右依次排列若干不同颜色的像素（数量等于图形的总数），中间用黑色像素间隔。

- `Rule`：
  - 第一步——计数子区域：对每个闭合图形，计算其内部被切割线分割后形成的 4-连通黑色子区域数量（无切割线则为 1 个子区域）。
  - 第二步——排序：将所有图形按子区域数量从少到多排列。若数量相同，按图形轮廓左上角的位置从左到右排列。
  - 第三步——着色：将排序后第 i 个图形的轮廓颜色改为调色板中从左到右第 i 个颜色。切割线保持原色不变。图形内部（子区域）保持黑色。
  - 调色板行在输出中被擦除为黑色。

- `Key insight`：解题者需要发现图形的重新着色不取决于其位置、大小或原始颜色，而取决于内部被切割线分割出的子区域数量。切割线容易被误认为装饰或损坏，但它们其实是决定排序的关键信息。调色板行提供了颜色序列，但其映射顺序（按子区域数排序）是需要从样例中归纳的隐藏规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布着若干单色小型 L 形对象作为旋转指令，以及若干同色边框包围的目标方块；通过颜色匹配将指令与目标配对，根据 L 形开口方向将目标方块内的图案旋转相应角度。

- `Input structure`：
  - 黑色背景上有若干互不接触的元素，分为两类：
  - 第一类——"指令块"：小型单色 4-连通对象，形状为 L 形，每个 L 恰好占 3 个像素，排列成直角。L 的朝向编码旋转角度：开口朝右（即像素占据左上、左下、右下三个位置）表示顺时针 90°，开口朝上（即像素占据左下、右下、右上三个位置）表示 180°，开口朝左（即像素占据左上、右上、右下三个位置）表示逆时针 90°。不会出现开口朝下的 L。
  - 第二类——"目标框"：由同一种颜色的 1 像素厚正方形边框围成的区域（内部尺寸为 N×N，N ≥ 2），框内包含由多种颜色组成的图案。
  - 每种非黑色前景色最多出现在一个指令块和一个目标框中。一个指令块和一个目标框颜色相同时构成配对。可能存在没有配对指令块的目标框（这些框不变）。

- `Rule`：
  - 第一步——配对：将每个指令块按其颜色与同色目标框配对。
  - 第二步——解码旋转：根据指令块 L 形的开口方向确定旋转角度（开口朝右 → 顺时针 90°；开口朝上 → 180°；开口朝左 → 逆时针 90°）。
  - 第三步——旋转图案：将配对目标框内部的 N×N 图案按指定角度绕其中心旋转，结果写回原位。边框本身不变。
  - 没有配对指令块的目标框保持不变。指令块在输出中被擦除为黑色。

- `Key insight`：解题者面对两层非显然推理。第一层是识别出小型 L 形像素簇不是随意噪声，而是编码旋转方向的"指令"——这需要从多个样例中对比 L 的朝向与框内图案的变化来归纳。第二层是理解颜色匹配机制：指令块的颜色不影响旋转内容，而是作为查找键定位应该旋转哪个目标框。两层规则都无法仅从单个样例中确认。
</new_puzzle>

<new_puzzle>
- `description`：网格中有一个大型多色马赛克图案和若干散落在外的单色小方块；每个小方块的形状编码了操作类型（扩张或收缩），其颜色指定了马赛克中哪种颜色区域执行该操作。

- `Input structure`：
  - 黑色背景。
  - 网格中央有一个大型矩形区域，内部由多种颜色的像素拼成马赛克图案（无黑色像素），各颜色形成不规则的 4-连通区域。
  - 马赛克外部散布着若干小型单色对象（与马赛克不相邻）。每个小对象为以下两种形状之一：
    - "实心 2×2 方块"（4 个像素排成 2×2）：表示"扩张"指令。
    - "空心 2×2 方块"（仅 4 个角像素，形成 3×3 范围内四角各一个像素、中心和边中点为黑色的图案，即像素位于左上、右上、左下、右下四个位置，中间 5 格为黑色）：表示"收缩"指令。
  - 每种出现在小对象中的颜色恰好也出现在马赛克中；但马赛克中可能有些颜色没有对应的小对象（这些颜色不变）。

- `Rule`：
  - 第一步——读取指令：对每个外部小对象，记录其颜色 C 和指令类型 T（实心 = 扩张，空心 = 收缩）。
  - 第二步——执行变换（所有颜色同时处理，基于原始输入状态）：
    - 扩张：对马赛克中颜色 C 的每个像素，检查其 4-邻域；若邻域中有不属于 C 的像素 P，则在输出中将 P 的位置覆盖为 C。
    - 收缩：对马赛克中颜色 C 的每个像素，若其 4-邻域中存在不属于 C 的像素，则该像素为边缘像素；在输出中将该边缘像素替换为其 4-邻域中出现次数最多的非 C 颜色。
  - 所有扩张和收缩基于原始状态同时计算，再一次性写入输出。当扩张冲突时（两种颜色同时想扩张到同一像素），该像素保持原色不变。
  - 外部小对象在输出中被擦除为黑色。

- `Key insight`：解题者需要破解两层编码：第一层是理解小方块的形状（实心 vs 空心）是操作类型的编码，而不是大小或位置的差异；第二层是理解小方块的颜色决定了马赛克中哪个区域被操作。"扩张"和"收缩"是形态学操作，但在小网格上的视觉效果很直观——边缘像素向外长出一圈或向内消失一圈。
</new_puzzle>
