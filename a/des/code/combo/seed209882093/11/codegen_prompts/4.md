将输入中每个前景精灵体按其内部孔洞的形状裁剪后，嵌入到另一个拥有相同形状孔洞的精灵体中。

Input structure：
- 背景为 black。
- 网格中有若干互不重叠的单色前景精灵体（4-连通色块），每个精灵体内部可能有零个或一个"孔洞"（被精灵体完全包围的 black 连通区域）。
- 有孔洞的精灵体保证：每个孔洞的形状（二值掩码，不考虑旋转和翻转）恰好与另一个精灵体的外轮廓形状相同——即该另一精灵体能恰好嵌入此孔洞中（可能需要旋转或翻转）。
- 每个精灵体要么有一个孔洞（作为"容器"），要么没有孔洞且其整体形状匹配某个容器的孔洞（作为"嵌件"）。容器与嵌件保证一一配对。

Rule：
- 对每个有孔洞的"容器"精灵体，找到外轮廓形状（旋转/翻转后）与该孔洞形状一致的"嵌件"精灵体。
- 将嵌件以正确的旋转/翻转方式放入容器的孔洞中，嵌件保持自身颜色。
- 嵌件原来的位置恢复为 black 背景。
- 没有配对关系的像素保持不变。

Key insight：
- 解题者需要将每个精灵体的"负空间"（孔洞形状）与其他精灵体的"正空间"（外轮廓）进行形状匹配——这是一个图形-背景反转的认知跳跃。匹配后还需确定正确的旋转/翻转，构成"负空间识别→形状匹配→变换嵌入"的多层推理。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支至少有机会出现。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
