- `description`：根据每个封闭区域内部"种子像素"的颜色，在区域的边界墙壁上染上对应颜色，但仅染那些与相邻区域共享的墙壁段——共享墙壁的颜色由两侧种子颜色混合决定（取两色中编号较小者）。

- `Input structure`：
  - 背景为 black。
  - Grey 像素构成一张连通的网格状墙壁网络，将整个网格分割为若干封闭矩形区域。
  - 每个封闭区域内部恰好有一个非 black、非 grey 的单像素"种子"，颜色各不相同（可能为 red、blue、green、yellow、orange 等）。
  - 墙壁厚度为 1 像素，区域大小不等。

- `Rule`：
  - 第一步：识别所有由 grey 墙壁围成的封闭矩形区域，以及每个区域内部的种子像素颜色。
  - 第二步：对于每段墙壁（一条连续的 grey 像素直线段），判断它分隔了哪两个区域。如果墙壁只与一个区域相邻（即处于网格最外边界），则该墙壁保持 grey 不变。
  - 第三步：对于分隔两个区域的内部墙壁段，将该墙壁段上的所有像素重新染色。染色规则为：取两侧区域种子颜色中颜色编号较小的那个颜色（颜色编号顺序：blue < red < green < yellow < grey < magenta < orange < azure < maroon）。
  - 第四步：种子像素本身在输出中被擦除（变为 black），区域内部其余像素保持 black 不变。

- `Key insight`：解题者首先需要发现墙壁颜色并非简单复制某一侧种子颜色，而是由两侧种子颜色共同决定；其次需要归纳出"取编号较小者"这一混合规则——这要求解题者从多个样例中对比不同颜色对的墙壁结果来推断出隐含的颜色优先级顺序。
</new_puzzle>

- `Input structure`：
  - 背景为 black。
  - Azure 像素构成墙壁，形成若干封闭的矩形"房间"。
  - 每个房间内部填充着一种纯色"地板"（可能为 green、yellow、orange、maroon 等），不同房间的地板颜色各异。

  - 有些房间之间没有门（完全隔开），有些房间之间有一扇门。

- `Rule`：
  - 第一步：识别所有房间及其地板颜色，并计算每个房间的面积（地板像素总数）。
  - 第二步：对于每扇门，比较它连接的两个房间的面积。将面积较小的房间的所有地板像素重新染为面积较大房间的地板颜色。如果两个房间面积相同，则两个房间都保持不变。
  - 第三步：用 red 像素填入每扇门的缺口位置（即将原本缺失的 azure 像素位置设为 red），封堵所有门。
  - 第四步：所有墙壁（azure）保持不变，未通过门连接的房间保持原样。

- `Key insight`：解题者需要先识别"门"是墙壁上的单像素缺口而非随机空隙，然后理解颜色传播的方向性——面积大的房间"吞噬"面积小的房间。门的封堵用 red 标记则是最终确认规则的线索。这道题的两层推理在于：第一层是发现门的拓扑连接关系决定了哪些房间会交互；第二层是发现面积比较决定了颜色流向。
</new_puzzle>

- `description`：网格中散布着若干彩色"箭头"形状，每个箭头指向一个方向；将每个箭头沿其指向方向平移，直到箭头的尖端像素恰好与另一个对象（非背景、非自身）相邻为止，然后在箭头原始位置留下与箭头同色的单像素"尾迹点"。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个 3×3 的箭头形状，每个箭头由 5 个同色像素组成。箭头的绘制方式：以 3×3 区域为范围，中心像素必定填充；指向方向的一侧有 3 个像素填充（指向方向的正前方 1 个 + 该前方像素两侧的 2 个对角像素），构成"箭头尖端"的三角形；尾部方向仅有中心正后方 1 个像素填充，构成"箭杆"。例如，一个向右指的箭头占据：中心 (r,c)、右 (r,c+1)、右上 (r-1,c+1)、右下 (r+1,c+1)、左 (r,c-1)。
  - 网格中还有若干静止的"目标块"——由 magenta 像素构成的小矩形（2×2 或 3×1 等），它们不移动。
  - 箭头的颜色可以是 blue、red、green、yellow、orange 等。

- `Rule`：
  - 第一步：识别每个箭头的形状并确定其指向方向（上、下、左、右四选一）。
  - 第二步：将每个箭头沿其指向方向逐像素平移。平移停止条件：箭头整体中最前方的像素（尖端行/列）再向前一步将与非 black 像素（magenta 目标块或网格边界）重叠或相邻。具体地，箭头停在其尖端像素的前方一格恰好是非 black 或越界的位置。
  - 第三步：在箭头原始位置的中心像素处留下一个与箭头同色的单像素点作为"尾迹"。箭头原位其余像素变为 black。
  - 第四步：所有箭头同时计算停止位置（不考虑其他箭头的移动——即用原始网格来判断碰撞），然后同时放置到最终位置。

- `Key insight`：解题者首先需要从不对称的 5 像素形状中解读出方向信息（第一层推理：形状编码方向——缺口对面就是指向），然后理解箭头平移到恰好"停靠"在目标块旁边而非重叠的位置（第二层推理：停止条件的精确语义），最后注意到原位留下的尾迹点是额外输出要素。

- `description`：网格被分成上下两半：上半部分包含若干彩色图案模板和一条颜色序列条；下半部分是一个空白画布。根据颜色序列条中的颜色顺序，将对应模板依次水平拼接地"印"到下半部分画布上，但每个模板在印之前需要旋转——旋转角度由该模板中非背景像素的数量决定。

- `Input structure`：
  - 整个网格由一条横贯全宽的 grey 水平分隔线分为上、下两个区域。
  - 上半区域包含：
    - 若干个大小相同的正方形模板（例如 4×4），彼此间隔排列在同一行区域内，每个模板内部有一种独特颜色的图案（由该颜色像素在 black 背景上绘成的非对称形状）。模板之间靠 black 间距分隔，没有边框。
    - 在模板行的下方、grey 分隔线的上方，有一行单像素高的"颜色序列条"，由若干个彩色像素组成，每个像素的颜色对应上方某个模板的颜色。序列条中可能有重复颜色（同一模板被引用多次）。
  - 下半区域为纯 black 画布，宽度等于（模板宽度 × 序列条像素数），高度等于模板高度。

- `Rule`：
  - 第一步：识别上方所有模板，并建立"颜色 → 模板图案"的映射。
  - 第二步：读取颜色序列条，从左到右得到一个颜色序列。
  - 第三步：对于序列中的每个颜色，找到对应的模板。数该模板中非 black 像素的总数 N，计算旋转量 = (N mod 4) × 90 度顺时针旋转（mod 4 的结果为 0 则不旋转，1 则旋转 90°，2 则旋转 180°，3 则旋转 270°）。
  - 第四步：将旋转后的模板按序列顺序从左到右依次紧密拼接，绘制到下半区域的画布上。
  - 第五步：上半区域在输出中保持不变。

- `Key insight`：第一层推理是发现颜色序列条是"打印指令"——它指定了模板的选取和排列顺序；第二层推理是发现每个模板需要旋转，且旋转角度编码在模板自身的像素计数中（计数 mod 4 映射到旋转量）。解题者需要注意到同一颜色模板在不同位置出现时旋转角度相同，由此反推出编码规则。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到若干对颜色相同的小方框，每对方框之间用同色 L 形折线连接；折线的转弯方式（先水平后垂直，还是先垂直后水平）由方框中心像素是否为孔洞来决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干对小图形（3×3 大小的方框），每对图形颜色相同但位置不同。每种颜色恰好出现两个方框。颜色可能为 red、blue、green、yellow、orange 等。
  - 每个 3×3 方框由 8 个同色边框像素包围中心位置构成。关键区别在于：某些方框的中心像素为 black（即有"孔洞"），某些方框的中心像素被填充为与边框相同的颜色（即"实心"）。
  - 同色的两个方框不在同一行也不在同一列。

- `Rule`：
  - 第一步：按颜色配对所有方框，每种颜色得到一对。
  - 第二步：确定连线的转弯方式。统计同色一对方框中孔洞的数量：
    - 如果两个方框都有孔洞（中心为 black），则连线路径为"先水平后垂直"——从一个方框的中心位置出发，水平走到与另一个方框中心同列，再垂直走到另一个方框中心。
    - 如果两个方框都是实心（中心已填色），则连线路径为"先垂直后水平"——从一个方框中心出发，垂直走到与另一个方框中心同行，再水平走到另一个方框中心。
    - 如果一个有孔洞、一个实心（混合情况），则连线路径为"先水平后垂直"从有孔洞的方框出发画到实心方框。
  - 第三步：在连线路径上的所有 black 像素位置绘制与方框同色的像素（连线宽度 1 像素）。连线包含转角处的像素。如果连线路径经过方框边框像素，则跳过该像素（已有颜色）。
  - 第四步：所有方框本身保持不变。

- `Key insight`：解题者需要先发现每对同色方框之间会产生 L 形连线，然后注意到不同颜色对的 L 形转弯方向不一致。关键的第二层推理是发现转弯方向的决定因素不在于方框的相对空间位置，而在于方框中心像素是否填充——这个微小的 1 像素结构差异编码了路径的拐弯规则。解题者必须仔细对比方框内部细节才能归纳出规律。
</new_puzzle>

- `description`：网格中有一个大型"棋盘"区域和若干散落在棋盘外的单色小碎片；将每个碎片"吸入"棋盘中与其形状完全匹配的空缺位置，碎片放入后颜色被棋盘的交替图案覆盖。

- `Input structure`：
  - 背景为 black。
  - 网格中有一个大型矩形区域（如 10×12），内部填充着两种颜色交替的棋盘图案（如 azure 和 green 交替，类似国际象棋棋盘，每格 1×1 像素）。棋盘左上角像素为 azure。
  - 棋盘中有若干处"空洞"——一些连续的像素被替换为 black，形成不规则的小形状（每个空洞 2-5 个像素，形状各异，均为 4-连通）。
  - 棋盘外部散落着若干小碎片，每个碎片是一个单色的 4-连通图形（颜色为 red、yellow、magenta、orange 等非棋盘色）。每个碎片的形状恰好与棋盘中某个空洞的形状完全一致（仅需平移匹配，不需要旋转或翻转）。
  - 碎片数量与空洞数量相同，一一对应。

- `Rule`：
  - 第一步：识别棋盘中所有 black 空洞区域的形状和位置。
  - 第二步：将棋盘外每个彩色碎片与棋盘中形状匹配的空洞配对（仅通过平移匹配形状轮廓）。
  - 第三步：将碎片放入对应空洞的位置。放入后，碎片的每个像素根据棋盘坐标的奇偶性着色：
    - 如果该像素在棋盘中的位置满足（行号 + 列号）为偶数，则涂为 azure。
    - 如果该像素在棋盘中的位置满足（行号 + 列号）为奇数，则涂为 green。
    - 其中行号和列号以棋盘左上角为原点从 0 开始计算。
  - 第四步：碎片原始位置变为 black（碎片从棋盘外消失）。棋盘的空洞被完整修复，恢复完美的棋盘交替图案。

- `Key insight`：解题者的第一层推理是发现碎片与空洞的形状配对关系（需要视觉上逐一匹配形状轮廓）；第二层推理是发现碎片放入后颜色并非保持原色，而是完全被棋盘的交替色覆盖——即碎片的原始颜色是无关的干扰信息，真正的填充色由棋盘自身的奇偶规律决定。碎片的原始颜色仅用于在视觉上区分不同碎片，不携带规则信息。

<new_puzzle>
- `description`：网格中有若干由不同颜色组成的"信号塔"（从底部向上生长的垂直色条），每座塔向两侧水平发射其高度范围内的"信号波"；两座相邻塔的信号在中间地带交汇时，较高塔的颜色覆盖较矮塔的颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条垂直的、不同颜色的"塔"，每座塔占 1 列宽度，由该颜色的像素从网格底部边缘向上连续填充到某一高度（不同塔高度不同）。各塔之间间隔若干列 black 空白。
  - 塔的颜色可为 red、blue、green、yellow、orange、maroon 等，每座塔颜色唯一（不重复）。
  - 塔的数量为 3-6 座，高度在 2-8 像素之间，塔间距在 2-6 列之间。

- `Rule`：
  - 第一步：识别所有塔的位置（列号）、颜色和高度。
  - 第二步：每座塔从其高度范围内的所有行（即从底行到塔顶所在行），向左和向右水平发射信号。信号覆盖范围：从塔所在列向左/右延伸，直到遇到相邻塔的列（不含该相邻塔本身的列）或网格边缘。被信号覆盖的 black 像素将被染为该塔的颜色。
  - 第三步：当两座相邻塔的信号在中间空白列的某些行上重叠时（即该行高度在两座塔高度的较小值以内），该重叠行上的像素全部显示为较高塔的颜色。
  - 第四步：在某些行上，若只有一座塔够高（该行超过了较矮塔的高度），则该行中间区域仅被较高塔的信号覆盖，显示较高塔的颜色。
  - 第五步：塔本身的像素保持原色不变。网格上方（所有塔高度以上的行）和两端最外侧（最左塔左边、最右塔右边）也由最近的塔的信号覆盖。

- `Key insight`：第一层推理是发现塔向两侧广播了水平色带——每座塔把自己的颜色水平扩展到左右相邻塔之间的所有空白列，但仅限于自身高度以内的行。第二层推理是发现两塔信号交汇区域不是简单的颜色叠加或交替，而是"高者胜"规则——更高的塔在所有重叠行中完全压制较矮塔的颜色。解题者需要从多个样例中观察交汇区域的颜色归属，结合塔的高度信息，才能归纳出这条隐含的竞争规则。
</new_puzzle>
