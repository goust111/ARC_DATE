- `Input structure`：
  - 背景为黑色（black）。
  - 网格被若干条完整的灰色（grey）水平线或垂直线分割成矩形子区域（类似棋盘格分区）。
  - 每个子区域内包含一个由 maroon 色构成的实心矩形块（大小不一），矩形块中混有少量（1-5 个）与背景相同的黑色"缺陷像素"（即矩形内部的空洞）。
  - 在网格的最底部一行（位于最后一条灰色分隔线之下）排列着一行彩色像素序列，从左到右依次为不同颜色（如 red、blue、green、yellow、orange），每种颜色占一格，形成一个有序的"颜色调色板"。
- `Rule`：
  - 对每个子区域，数出其 maroon 矩形块内部的缺陷像素（黑色空洞）数量 N。
  - 在底部颜色调色板中，取从左起第 N 个颜色（N=1 对应最左边的颜色）。
  - 将该子区域内所有 maroon 像素（包括缺陷位置，即填补空洞）替换为选中的颜色，形成一个完整的实心矩形。
  - 灰色分隔线和底部调色板行保持不变。
- `Key insight`：解题者需要完成两层非显然推理：第一层是发现每个矩形块内的"缺陷数量"是关键属性而非随机噪声；第二层是发现底部那行像素不是装饰而是一个位次索引的调色板，缺陷数量作为索引来选择重着色的颜色。单看颜色或单看缺陷都无法解题，必须将两者关联。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支至少有机会出现。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
