- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散落着若干成对的单像素标记，每对标记颜色相同且每种颜色恰好出现两个像素。不同对的颜色互不相同。

  - 网格中还有一个由 azure 色构成的 3x3 参考图例块，位于角落。图例块中，中心像素为 azure，八个方向中恰好有四个位置也是 azure，形成一个"十字"或"X"形状，标示了"水平/垂直"或"对角"两组方向的视觉样板。
- `Rule`：
  - 对于每一对同色像素，计算两者的中点位置（保证中点落在整数格点上）。
  - 判断两点连线方向：若为水平或垂直，则在中点处绘制一个 3x3 的"十字"形（中心 + 上下左右四格），颜色为该对像素的颜色；若为对角线方向，则在中点处绘制一个 3x3 的"X"形（中心 + 四个对角格），颜色为该对像素的颜色。
  - 擦除原始的两个标记像素。
  - 角落的 azure 参考图例保持不变。
- `Key insight`：角落的 azure 图例是解码密钥——它示范了两种方向类别分别对应的 3x3 图案（十字 vs X），解题者需要先从图例中归纳出"连线方向→图案形状"的映射规则，再对每对像素应用该规则。中点位置和方向判断都是视觉直觉可完成的。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支至少有机会出现。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
