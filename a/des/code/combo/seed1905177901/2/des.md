- `description`：根据面板内前景对象的边界缺口方向，从相邻面板中选择对应方向的对象进行颜色交换，再将交换后的对象嵌入缺口位置。
- `Input structure`：背景为 Black。Grey 分隔列将网格分为若干等宽面板。每个面板包含一个 4-连通的单色前景对象，对象的边界框（bbox）某一侧恰好有一个由背景色构成的矩形缺口（凹陷）。缺口的方向可以是上、下、左或右。
- `Rule`：
  - 识别每个面板内对象的缺口方向。
  - 缺口朝左的对象与其左侧相邻面板中的对象配对；缺口朝右的与右侧配对；缺口朝上的与上方行对齐的面板配对；缺口朝下的与下方配对。
  - 配对的两个对象交换颜色。
  - 将每个对象裁剪为缺口的互补形状，嵌入配对方的缺口中，形成完整矩形。
  - 清除原始面板中被转移的像素。
- `Key insight`：缺口方向同时编码了配对对象的选择和嵌入方向——解题者需要先发现缺口方向决定配对关系，再发现颜色交换和形状互补的嵌入机制。
</new_puzzle>

<new_puzzle>
- `description`：在网格的分隔框架内，根据每个单元格中标记像素的数量选择该单元格应显示参考面板中哪一行的图案，并用标记颜色替换图案的前景色。
- `Input structure`：背景为 Black。网格被 Grey 分隔线划分为若干等大的方形单元格。左侧一列单元格组成参考面板，每个参考单元格内有一个由 Azure 构成的不同二值图案（binary pattern）。其余单元格为目标区域，每个目标单元格内散布着 1 到 N 个同色标记像素（N 等于参考面板的行数），颜色各异。
- `Rule`：
  - 统计每个目标单元格内标记像素的数量 k。
  - 从参考面板中选择第 k 行的图案模板。
  - 将该模板缩放到目标单元格大小，用目标单元格中标记像素的颜色替换模板中的 Azure 前景像素。
  - 清除原标记像素。
- `Key insight`：标记像素数量是索引参考图案的键，标记颜色是重绘图案的颜料——两个属性各自承担独立的角色，缺一则输出无法确定。
</new_puzzle>

<new_puzzle>
- `description`：识别输入中颜色条带的周期性排列模式，找到被"污染"的异常条带，用推断出的正确颜色修复它，并在修复位置标注 Maroon 边框。
- `Input structure`：背景为 Black。网格由若干等宽的水平或垂直彩色条带交替排列组成，条带之间由一像素宽的背景行/列分隔。条带的颜色序列遵循一个长度为 3 到 5 的周期循环。恰好有一条条带的颜色不符合该周期规律（被污染）。
- `Rule`：
  - 推断条带颜色序列的最小重复周期。
  - 找到不符合周期的异常条带。
  - 将异常条带的颜色替换为周期规律预测的正确颜色。
  - 在修复后的条带两侧（沿条带长度方向的两条边）各添加一像素宽的 Maroon 标记线。
- `Key insight`：条带序列的周期性是隐含的全局规律，解题者必须通过对比多条条带推断周期长度和模式，而非简单地识别局部异常。
</new_puzzle>

<new_puzzle>
- `description`：将多个重叠的单色矩形框架按遮挡关系排序为层叠序列，然后用这个序列重建为同心嵌套框架。
- `Input structure`：背景为 Black。若干不同颜色的一像素厚矩形框架散布在网格中，框架之间有部分重叠。在重叠位置，上层框架的颜色遮挡下层框架的颜色。每个颜色的框架可以从其可见像素推断出完整的 bbox。
- `Rule`：
  - 从每种颜色的可见像素推断其完整矩形框架的 bbox。
  - 在重叠位置，可见颜色为上层，被遮挡颜色为下层，由此建立遮挡偏序关系。
  - 对所有框架颜色进行拓扑排序，得到从底层到顶层的唯一序列。
  - 以底层颜色为最外层、顶层颜色为最内层，重新绘制为居中的同心嵌套矩形框架，每层之间间隔一像素背景。
- `Key insight`：重叠位置的颜色可见性揭示了层叠顺序，而输出并非简单地还原原始位置——而是将这个顺序转化为全新的同心嵌套几何结构。
</new_puzzle>

<new_puzzle>
- `description`：在由路径连接的节点网络中，根据路径颜色决定节点间的颜色传递方向，最终使每个节点的颜色由其入边路径的颜色混合决定。
- `Input structure`：背景为 Black。若干 3x3 的实心彩色方块作为节点散布在网格中，节点颜色各不相同。节点之间由一像素宽的彩色路径连接（路径颜色与两端节点均不同）。每条路径是水平或垂直的直线段，连接两个节点的相对边。
- `Rule`：
  - 每条路径的颜色与其两端节点之一相同：该节点为发送方，另一端为接收方。但此处路径颜色与两端都不同，因此改用以下规则：路径颜色更接近（在可用颜色列表中位置更近的）哪个节点颜色，那个节点为发送方。
  - 实际规则：对每个节点，收集所有连入路径的颜色。如果一个节点恰好有两条入边路径，其输出颜色为两条路径颜色中像素面积更大者（路径更长者）。如果只有一条入边路径，输出颜色为该路径颜色。无入边路径则保持原色。
  - 用新颜色重绘每个 3x3 节点方块，路径保持不变。
- `Key insight`：路径不仅是连接结构，其颜色和长度共同编码了节点颜色的更新规则——解题者需要发现路径方向性（哪端发送哪端接收）以及长度优先的混合机制。
</new_puzzle>
