根据网格中彩色种子像素的颜色在色阶面板中的排列位置，让每个种子向四个正交方向生长出对应长度的十字形射线，射线被其他种子的射线或网格边界截断。

Input structure:
- 背景为黑色。
- 网格左侧有一列垂直排列的色阶面板：从上到下依次排列若干不同颜色的像素（每种颜色一个像素，无间隔），面板与主网格之间有一列黑色间隔。
- 主网格区域中散布着若干单像素的彩色种子，每个种子的颜色都出现在左侧色阶面板中。

Rule:
- 左侧色阶面板保持不变，仅用于查表。
- 对每个种子像素，读取其颜色在左侧色阶面板中从上到下的位置序号（最上方为1，其次为2，依此类推）。
- 该位置序号即为种子的"生长半径"：从种子位置出发，向上、下、左、右四个方向各延伸该数量的像素，用种子自身的颜色绘制射线。
- 射线不进入左侧面板区域，也不超出网格边界。
- 若两条射线发生重叠，生长半径较大的种子的颜色优先（覆盖半径较小的）。
- 种子像素本身保留其颜色。

Key insight:
色阶面板不仅定义了合法颜色集合，更隐含了一个"颜色到数值"的映射关系——颜色在面板中的垂直位置直接决定了该种子的十字射线长度。解题者需要先发现面板位置与射线长度的对应关系，再理解射线重叠时的优先级规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
