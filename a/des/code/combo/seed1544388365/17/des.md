根据框架内部色块的形状匹配外部模板，再用模板上的标记色替换框架边框对应段的颜色。

Input structure
- 背景为主色。网格中散布若干由单一颜色绘制的一像素宽矩形框架（边框闭合），每个框架内部有一个由另一种颜色构成的小型连通形状（如 L 形、T 形、十字形等）。
- 网格边缘区域放置若干"模板"：每个模板是一个与某框架内部形状全等（可能经旋转或翻转）的小形状，该形状由与框架内部相同的颜色绘制，且模板的某一侧紧邻一个单像素标记点，标记点使用一种与框架边框颜色不同的新颜色。

Rule
- 对每个框架，在所有模板中找到与其内部形状全等（允许旋转和翻转）的那个模板。
- 确定模板上标记点相对于形状的方位（上、下、左、右）。将框架与模板的形状对齐后，该方位对应框架的某一条边（上边、下边、左边、右边）。
- 将框架该条边的所有像素重新着色为标记点的颜色，其余边框像素保持原色，框架内部形状和背景均不变。

Key insight
内部形状是一把"钥匙"，通过形状匹配找到对应的模板；模板上标记点的方位指定框架的哪一条边需要变色，标记点的颜色决定新颜色。解题者需要先完成形状匹配（含旋转/翻转），再将标记方位映射回框架的边。
</new_puzzle>

将散落的彩色路径片段按颜色拼合，再根据拼合后路径的转弯方向决定路径端点处标记色块的放置侧。

Input structure
- 背景为主色。网格中有若干条由不同颜色绘制的一像素宽路径片段，每条路径片段是直线段（水平或垂直），长度在 2–6 像素之间。
- 同一颜色的路径片段恰好有两段，且它们的一个端点在同一行或同一列上对齐（中间隔着背景），可以通过一条直角弯折连接起来形成一条 L 形路径。
- 每条路径片段的非对齐端（即远离配对片段的那个端点）旁边紧邻一个灰色（grey）单像素标记点。

Rule
- 对每种颜色，将两段路径片段用一条同色直角连接线补全，形成完整的 L 形路径（连接线填充两段之间的间隔，拐角处恰好有一个像素）。
- 确定 L 形路径的弯折方向：从第一段的非对齐端沿路径走到拐角再到第二段的非对齐端，观察在拐角处是左转还是右转。
- 对于每个灰色标记点，将其移动到路径该端点的另一侧：如果弯折方向为左转，则标记点移到路径端点行进方向的右侧；如果弯折方向为右转，则标记点移到路径端点行进方向的左侧。标记点的原位置恢复为背景色。

Key insight
同色片段的空间对齐关系决定了连接方式，而连接后形成的 L 形路径的弯折手性（左转/右转）反过来控制端点标记的放置侧。解题者需要先推断出如何补全路径，再根据路径的全局几何属性重新安排标记位置。
</new_puzzle>

根据种子色块在网格分区中的数量选择图案字典中的对应图案，再将该图案平铺填充整个分区。

Input structure
- 背景为主色。网格被若干条一像素宽的黑色（black）直线分割为矩形分区（分区大小不完全相同但都是偶数边长）。
- 每个分区内部有 1–3 个散布的单像素"种子"色块，所有种子使用同一种非黑非背景的颜色（如 red）。
- 网格某个角落（如左上角）有一个独立的"图案字典"区域，用黑色边框隔开。字典内包含三个小方格，分别编号为位置 1、2、3（从左到右排列），每个方格内有一个用另一种颜色（如 blue）绘制的 2×2 微型图案（如实心方块、对角线、L 形等各不相同）。

Rule
- 对每个分区，数出其中种子色块的数量 N（1、2 或 3）。
- 从图案字典中取出编号为 N 的微型图案。
- 将该 2×2 图案按 (分区宽度/2) × (分区高度/2) 的倍数进行平铺，填满整个分区的内部（不覆盖黑色分割线），使用图案字典中的颜色绘制。
- 种子色块保持原样不被覆盖（种子色块所在像素仍保留种子颜色）。

Key insight
种子数量是图案选择的索引键，而非空间位置信息；分区的几何尺寸决定图案的平铺次数。解题者需要先发现数量→图案的映射关系，再理解平铺的缩放逻辑。
</new_puzzle>

<new_puzzle>
根据封闭区域内"投票色块"的多数颜色决定该区域的边框颜色，再将少数色块沿边框中心点对称弹射到镜像位置。

Input structure
- 背景为主色。网格中有若干个由灰色（grey）像素围成的一像素宽封闭矩形边框，边框之间不重叠不相邻。
- 每个边框内部散布着若干单像素色块，这些色块只使用两种颜色（例如 red 和 green），每个边框内两种颜色的数量不相等。
- 边框外部的背景区域没有任何色块。

Rule
- 对每个封闭边框，统计内部两种颜色的色块数量，确定多数颜色和少数颜色。
- 将该边框的所有灰色像素重新着色为多数颜色。
- 对每个少数颜色的色块，计算它相对于边框内部矩形中心的位置，将其移动到关于中心的点对称位置。若对称位置已有色块（无论什么颜色），则少数色块不移动，保留在原位。
- 少数颜色色块本身保持原色不变。

Key insight
多数颜色决定了边框的新颜色（"投票"机制），而少数颜色色块被"反弹"到中心对称位置。解题者需要先发现颜色计数决定边框颜色的规则，再独立发现少数色块的点对称迁移规则——两个子规则作用于不同的视觉元素（边框 vs 内部色块），必须分别归纳。
</new_puzzle>

<new_puzzle>
根据管道网络的连通性将源色块的颜色传播到各终端，再根据终端接收到的颜色混合结果选择输出色。

Input structure
- 背景为主色。网格中有一个由黑色（black）像素构成的一像素宽管道网络，管道沿水平和垂直方向延伸并在交叉点处分叉。
- 管道网络的若干末端（死胡同位置）各有一个彩色单像素"终端"标记，终端颜色均为灰色（grey）。
- 管道网络的另外若干末端各有一个非灰非黑非背景的彩色单像素"源色块"，每个源色块颜色可能不同（如 red、blue、green 等）。
- 管道网络中的某些交叉点处有一个 maroon 像素"阀门"，阀门阻断该交叉点处垂直方向的连通（水平方向仍可通过），即颜色只能沿水平方向穿过阀门所在交叉点。

Rule
- 从每个源色块出发，沿管道网络传播其颜色。在每个分叉处颜色向所有可达方向继续传播，但不可穿过阀门的垂直方向。
- 对每个灰色终端，收集所有能到达它的源色块的颜色集合。
- 如果只有一种颜色到达该终端，则将终端重新着色为该颜色。
- 如果有多种颜色到达该终端，则将终端重新着色为 yellow。
- 如果没有颜色到达该终端（被阀门完全阻断），则终端保持灰色不变。
- 管道网络和源色块本身保持不变。

Key insight
管道的拓扑连通决定了哪些源色块能到达哪些终端，而阀门的方向性阻断打破了交叉点的全连通假设。解题者需要先理解阀门仅阻断垂直方向这一隐含规则，再通过路径追踪确定每个终端的颜色来源，最后根据颜色数量（单一/混合/无）执行不同的着色规则。
</new_puzzle>

沿传送带路径循环移动彩色货物，传送带的转动方向由路径环绕的内部标记颜色决定。

Input structure
- 背景为主色。网格中有若干条由黑色（black）像素绘制的一像素宽闭合环形路径，每条路径形成一个简单的矩形环（即矩形边框，四角为直角）。
- 每条环形路径上间隔放置着若干彩色像素（各种非黑非背景颜色），这些彩色像素替换了路径上对应位置的黑色像素，它们是"货物"。
- 每条环形路径围成的内部区域中央有一个单像素标记，标记颜色为 red 或 blue。

Rule
- 对每条环形路径，读取其内部标记的颜色。
- 如果标记为 red，将路径上所有货物沿顺时针方向移动一格（货物从当前位置移到路径上的下一个位置，按顺时针排序）。
- 如果标记为 blue，将路径上所有货物沿逆时针方向移动一格。
- 货物移动后，它离开的位置恢复为黑色（路径色）。货物保持自身颜色不变。
- 路径上的黑色像素和内部标记均保持不变。

Key insight
内部标记不是装饰而是控制信号，它的颜色编码了传送方向。解题者需要先将标记颜色与移动方向建立映射（red→顺时针，blue→逆时针），再对每条路径独立执行循环位移。路径的矩形几何形状使得"顺时针/逆时针下一格"可以通过沿边框行走直观确定。
</new_puzzle>

<new_puzzle>
将网格中的彩色碎片按形状归类到对应的容器轮廓中，容器的缺口方向决定碎片插入时的旋转角度。

Input structure
- 背景为主色。网格中有若干个由 azure 像素绘制的一像素宽"容器"轮廓，每个容器是一个矩形框但恰好缺少一条完整的边（上、下、左或右），形成一个 U 形或 C 形开口。
- 每个容器的内部面积各不相同。
- 网格中还散布着若干个由不同颜色绘制的实心矩形"碎片"（每个碎片是一个填满的小矩形），碎片的面积恰好等于某个容器的内部面积，且每个碎片与一个容器唯一配对。
- 碎片的初始朝向（宽×高）可能与容器内部空间的朝向不同。

Rule
- 对每个碎片，通过面积匹配找到其对应的容器。
- 确定容器的缺口方向（上、下、左、右）。
- 将碎片旋转（0°或 90°）使其尺寸适配容器内部空间，然后将碎片平移填入容器内部。
- 碎片填入后，缺口处的容器边不补全——碎片的对应边直接暴露在开口处。
- 碎片原始位置的像素恢复为背景色。

Key insight
面积相等是碎片与容器配对的键，但碎片可能需要旋转 90° 才能适配容器内部的宽高比。缺口方向本身不影响旋转决策，仅影响视觉外观——真正的旋转判断来自容器内部空间的宽高比与碎片宽高比的匹配。解题者需要先通过面积匹配建立配对关系，再通过几何适配确定旋转。
</new_puzzle>
