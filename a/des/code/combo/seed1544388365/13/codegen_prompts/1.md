- `description`：根据彩色种子块的颜色在灰色管道网络中传播染色，并在管道交叉点按混色规则生成新颜色。

- `Input structure`：
  - 背景为 Black。
  - 灰色（Grey）像素构成若干条一像素宽的水平或垂直管道，管道之间存在交叉点（即灰色像素同时属于一条水平管道和一条垂直管道的位置）。
  - 在某些管道的端点（管道最外侧的灰色像素）处，紧邻管道外侧放置一个彩色像素（非 Black、非 Grey），称为"种子块"。每条管道最多有一个种子块，种子块的颜色互不相同。
  - 管道网络整体尺寸不超过 25x25，管道数量为 3-6 条，交叉点数量为 2-6 个。

- `Rule`：
  - 第一步——管道染色：每个种子块将自身的颜色沿其所在管道的方向传播，把该管道上所有灰色像素替换为种子块的颜色。种子块自身保持不变。没有种子块的管道保持灰色不变。
  - 第二步——交叉点混色：对于每个交叉点，检查经过该点的水平管道和垂直管道是否都已被染色（即都不是灰色）。如果两条管道都被染色，则该交叉点的像素颜色按以下固定映射规则确定：Red + Blue → Magenta，Red + Yellow → Orange，Blue + Yellow → Green，Red + Green → Maroon，Blue + Green → Azure。如果只有一条管道被染色，交叉点保持该管道的颜色。如果两条都未被染色，交叉点保持灰色。
  - 种子块本身在输出中被擦除（替换为 Black）。

- `Key insight`：解题者需要先识别管道网络的拓扑结构和种子块的位置以确定每条管道的染色，然后在交叉点处发现隐含的颜色混合规则——这是一个两步归纳过程：第一层是"种子沿管道传播"，第二层是"交叉点按双色混合表生成新颜色"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
