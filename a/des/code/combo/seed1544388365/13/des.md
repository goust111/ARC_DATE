- `description`：根据彩色种子块的颜色在灰色管道网络中传播染色，并在管道交叉点按混色规则生成新颜色。

- `Input structure`：
  - 背景为 Black。
  - 灰色（Grey）像素构成若干条一像素宽的水平或垂直管道，管道之间存在交叉点（即灰色像素同时属于一条水平管道和一条垂直管道的位置）。
  - 在某些管道的端点（管道最外侧的灰色像素）处，紧邻管道外侧放置一个彩色像素（非 Black、非 Grey），称为"种子块"。每条管道最多有一个种子块，种子块的颜色互不相同。
  - 管道网络整体尺寸不超过 25x25，管道数量为 3-6 条，交叉点数量为 2-6 个。

- `Rule`：
  - 第一步——管道染色：每个种子块将自身的颜色沿其所在管道的方向传播，把该管道上所有灰色像素替换为种子块的颜色。种子块自身保持不变。没有种子块的管道保持灰色不变。
  - 第二步——交叉点混色：对于每个交叉点，检查经过该点的水平管道和垂直管道是否都已被染色（即都不是灰色）。如果两条管道都被染色，则该交叉点的像素颜色按以下固定映射规则确定：Red + Blue → Magenta，Red + Yellow → Orange，Blue + Yellow → Green，Red + Green → Maroon，Blue + Green → Azure。如果只有一条管道被染色，交叉点保持该管道的颜色。如果两条都未被染色，交叉点保持灰色。
  - 种子块本身在输出中被擦除（替换为 Black）。

- `Key insight`：解题者需要先识别管道网络的拓扑结构和种子块的位置以确定每条管道的染色，然后在交叉点处发现隐含的颜色混合规则——这是一个两步归纳过程：第一层是"种子沿管道传播"，第二层是"交叉点按双色混合表生成新颜色"。
</new_puzzle>

- `description`：将散落的同色碎片拼合还原为完整矩形，并按碎片数量决定矩形在输出网格中的垂直排列顺序。

- `Input structure`：
  - 背景为 Black。
  - 网格中散落着若干个彩色的 4-连通碎片（每个碎片是一组同色像素的连通区域）。
  - 同一颜色的所有碎片恰好可以无重叠、无间隙地拼合成一个实心矩形（碎片之间仅需平移即可拼合，无需旋转或翻转）。
  - 不同颜色对应不同的矩形，每种颜色有 2-4 个碎片，颜色种类为 2-4 种。
  - 每个碎片的形状不规则，但同色碎片的像素总数等于目标矩形的面积。

- `Rule`：
  - 对每种颜色，找到其所有碎片。根据碎片的相对空间位置关系（碎片之间的相对偏移量），将它们平移拼合，形成一个完整的实心矩形。拼合方式唯一：保持碎片之间原始的相对行列偏移，消除碎片之间的空隙后恰好构成矩形。具体操作为：取所有同色碎片像素的坐标，计算它们的最小外接矩形，将所有碎片整体向左上对齐后检验是否填满矩形——若未填满，则将碎片间的空行/空列压缩移除直到无空隙。
  - 统计每种颜色的碎片数量。碎片数量最少的颜色对应的矩形排在输出网格的最上方，碎片数量最多的排在最下方。碎片数量相同时，矩形面积较小的排在上方。
  - 输出网格的宽度等于所有矩形宽度的最大值，每个矩形左对齐放置，矩形之间无间隔紧密排列。输出网格的高度等于所有矩形高度之和。

- `Key insight`：第一层推理需要发现同色碎片可以通过平移拼合成矩形（需要识别碎片间的空间互补关系）；第二层推理需要发现输出中矩形的排列顺序由碎片数量决定，而非由颜色、面积或输入中的位置决定。
</new_puzzle>

- `description`：用框内小图案作为"印章模板"，在框外每个同色锚点处按锚点的邻域缺口方向旋转后盖章。

- `Input structure`：
  - 背景为 Black。
  - 网格中有一个由某种颜色（如 Blue）构成的一像素厚矩形框。框的内部包含一个由另一种颜色（如 Red）绘制的小型非对称图案（不超过 5x5），该图案有一个特征：它恰好有一个像素紧贴框的某一条内边（上/下/左/右），该像素称为"接触点"，其所贴的边称为"基准边"。
  - 框的外部散布着若干个与框同色（Blue）的孤立单像素，称为"锚点"。
  - 每个锚点恰好与一个非背景色的单像素标记相邻（4-连通），该标记的颜色与框内图案的颜色相同（Red）。标记相对于锚点的方向（上/下/左/右）称为"指示方向"。

- `Rule`：
  - 将框内图案视为印章模板，以接触点为参考原点。基准边朝向定义模板的默认方向。
  - 对每个锚点，计算"指示方向"（标记相对于锚点的方向）。将模板旋转，使基准边的朝向与指示方向一致（例如模板默认基准边朝上，而指示方向朝右，则模板顺时针旋转 90 度）。
  - 将旋转后的模板以接触点对齐到锚点位置，盖印到网格上。盖印时，模板的非背景像素覆盖网格对应位置（若超出网格边界则裁剪）。
  - 框本身和框内原始图案在输出中被擦除（替换为 Black）。锚点和标记像素被模板像素覆盖。

- `Key insight`：解题者首先要在框内识别图案与框边的接触关系以确定模板的"默认朝向"；然后要发现每个锚点旁的标记像素编码了旋转角度；最后将旋转后的模板正确对齐盖章。三层结构：模板提取→旋转编码解读→对齐盖印。
</new_puzzle>

- `description`：根据彩色路径的层叠遮挡关系推断绘制顺序，然后将最晚绘制的路径沿其方向延伸至网格边界。

- `Input structure`：
  - 背景为 Black。
  - 网格中有 3-5 条彩色路径，每条路径由一种独特的非背景颜色构成，宽度为一像素。
  - 每条路径是严格的水平线段或垂直线段（不弯折）。
  - 路径之间存在交叉：当两条路径在某个像素点重叠时，只有一条路径的颜色可见（即"上层"路径遮挡了"下层"路径）。
  - 每条路径的两个端点中，至少有一个端点可见（未被遮挡）。

- `Rule`：
  - 第一步——重建遮挡顺序：在每个交叉点处，可见的颜色属于上层路径，被遮挡的颜色属于下层路径。利用所有交叉点的信息，推断出所有路径的完整绘制顺序（从最先绘制/最底层到最后绘制/最顶层）。该顺序是唯一确定的全序。
  - 第二步——延伸最顶层路径：找到最后绘制的（最顶层的）路径。将该路径沿其方向（水平或垂直）向两端延伸，直到到达网格边界。延伸部分使用该路径的颜色绘制，覆盖途中的所有像素（包括其他路径的像素和背景像素）。
  - 其余路径和背景保持不变。

- `Key insight`：第一层推理需要从交叉点的可见颜色中归纳出路径之间的层叠偏序关系，并排出完整顺序；第二层推理需要发现只有最顶层路径会被延伸，且延伸方向由路径自身的走向决定。关键难点在于遮挡顺序不是直接给出的，需要从多个交叉点的局部信息中全局推断。
</new_puzzle>

- `Input structure`：
  - 背景为 Black。
  - 网格中包含若干个嵌套的矩形边框，每个边框由一像素厚的彩色线条构成。最外层边框使用一种颜色（如 Blue），其内部可能包含第二层边框（使用另一种颜色，如 Red），第二层内部可能包含第三层边框（如 Green），以此类推，最多嵌套 3-4 层。
  - 每层边框所围的区域内（不包括更内层边框的区域）散布着若干个由 Grey 像素构成的小型 4-连通对象（每个对象 2-6 个像素）。
  - 每个灰色小对象完全位于某一层边框区域内，不跨越边框。

- `Rule`：
  - 确定每个灰色对象所在的嵌套层级 d（最外层边框内为 d=1，第二层边框内为 d=2，以此类推）。
  - 对每个灰色对象，计算其重心（所有像素行坐标的平均值和列坐标的平均值，四舍五入取整）与其所在边框区域重心的相对位置。
  - 将该对象整体向其所在边框区域的中心平移 d 个像素（即层级越深，收缩越多）。平移方向为从对象重心指向区域重心的方向，分解为水平和垂直两个分量分别移动。若移动后对象会与边框重叠，则移动到恰好不重叠的位置停止。
  - 边框本身保持不变。对象移动后原位置恢复为 Black。

- `Key insight`：第一层推理需要识别边框的嵌套层级结构（通过颜色区分和空间包含关系）；第二层推理需要发现灰色对象的移动距离等于其所在的嵌套深度值——颜色不同的边框不仅区分层级，还隐式编码了收缩量；第三层是确定收缩方向为朝向各自区域的中心。
</new_puzzle>

- `description`：将网格中的彩色"信号塔"按高度排序，然后让每座塔向两侧发射与其高度等长的水平射线，射线颜色由相邻塔的颜色决定。

- `Input structure`：
  - 背景为 Black。
  - 网格底部有一行连续的 Grey 像素作为"地面"。
  - 地面上方竖立着若干"信号塔"，每座塔是一列宽一像素、从地面向上延伸的同色竖条。不同塔的颜色互不相同，高度（像素数）也互不相同。塔与塔之间至少间隔 2 列。
  - 塔的数量为 3-5 座，高度范围为 2-8 像素。

- `Rule`：
  - 第一步——确定射线颜色：对每座塔，找到它左侧最近的塔和右侧最近的塔。该塔向左发射的射线颜色为左侧邻塔的颜色；向右发射的射线颜色为右侧邻塔的颜色。最左侧的塔没有左邻，不发射左射线；最右侧的塔没有右邻，不发射右射线。
  - 第二步——确定射线发射高度和长度：每座塔的射线从塔顶所在行向左右水平发射。射线长度等于该塔的高度（像素数）。射线从塔顶像素的左侧/右侧紧邻位置开始绘制，水平延伸相应数量的像素。若射线遇到另一座塔的像素则在该处停止（不覆盖其他塔）。
  - 塔本身和地面保持不变。

- `Key insight`：第一层推理需要发现射线的颜色不是塔自身的颜色，而是来自相邻塔的颜色（需要对比多个样例才能归纳出"借色"规则）；第二层推理需要发现射线长度等于塔的高度——一个垂直属性被转化为水平量。两层规则都不是一眼可见的，需要从样例中分别归纳。
</new_puzzle>

<new_puzzle>
- `description`：在棋盘格分区的网格中，根据每个分区内标记像素的奇偶性翻转该分区的前景/背景，再将相邻同色分区合并边界。

- `Input structure`：
  - 网格被等间距的水平和垂直 Grey 分隔线划分为大小相同的矩形分区（每个分区为 3x3 至 5x5 的内部区域）。分隔线宽度为一像素。
  - 每个分区的内部由背景色 Black 和一种前景色 Blue 构成，形成某种局部图案。
  - 部分分区中包含一个或多个 Red 标记像素，这些标记像素位于分区内部的任意位置。

- `Rule`：
  - 对每个分区，统计其内部 Red 标记像素的数量。
  - 如果 Red 标记数量为奇数，则翻转该分区内部的前景和背景：所有 Blue 像素变为 Black，所有 Black 像素变为 Blue。Red 标记像素本身在翻转后被移除（变为翻转后对应的颜色，即视为原本是 Black 位置则变为 Blue，原本是 Blue 位置则变为 Black）。
  - 如果 Red 标记数量为偶数（包括 0），则该分区保持不变，仅移除 Red 标记像素（恢复为标记下方原本的颜色：若标记覆盖了 Blue 则恢复为 Blue，若覆盖了 Black 则恢复为 Black；在样例中标记始终放置在 Black 像素上，因此移除后恢复为 Black）。
  - Grey 分隔线保持不变。

- `Key insight`：第一层推理需要发现 Red 标记的数量控制翻转行为（而非标记的位置）；第二层需要归纳出奇偶判定规则——不是简单的"有标记就翻转"，而是奇数个标记才翻转。解题者必须仔细对比有 1 个标记、2 个标记和 0 个标记的分区的变化差异才能得出规则。
</new_puzzle>
