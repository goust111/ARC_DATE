- `description`：将网格中的多个同色"信号塔"向外发射正交射线直到碰到边界或障碍，射线交叉点处生成新颜色，新颜色由交叉的两条射线所属信号塔的颜色通过固定的颜色混合表决定。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干个单像素的"信号塔"，使用 2–3 种不同颜色（例如 red、blue、yellow），每种颜色有 1–3 个信号塔。
  - 网格中还有若干个 grey 像素作为"墙壁"障碍物，分布在不同位置。
  - 网格角落处有一个 3×3 的颜色混合表：表的第一行和第一列分别标注了信号塔可用的颜色（如 red、blue、yellow），表格内部的交叉格填有混合结果颜色（例如 red×blue → magenta，red×yellow → orange，blue×yellow → green）。

- `Rule`：
  - 每个信号塔向上、下、左、右四个方向发射射线，射线为该信号塔的颜色，从信号塔位置开始沿直线延伸，直到碰到网格边界或 grey 墙壁为止（不覆盖墙壁）。
  - 射线可以覆盖背景像素，但不覆盖其他信号塔。
  - 当两条不同颜色的射线经过同一个像素时，该像素不使用任一射线的颜色，而是查阅角落的颜色混合表，使用两种颜色对应的混合结果颜色。
  - 如果三条或以上射线交叉在同一像素，优先使用离该像素最近的两个信号塔所发射的射线进行混合。
  - 同色射线交叉时保持原色不变。
  - 颜色混合表在输出中保持不变；grey 墙壁保持不变；信号塔本身保持不变。

- `Key insight`：解题者需要三层推理——首先发现信号塔发射正交射线的规则，然后发现射线交叉处的颜色不是简单覆盖而是混合，最后发现角落的小网格是颜色混合的查找表而非装饰。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
