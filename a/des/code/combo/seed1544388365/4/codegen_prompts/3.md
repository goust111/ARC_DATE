在输入网格中找到多个同形但颜色不同的"印章"对象，根据每个印章底部附带的彩色条纹序列确定它们的堆叠顺序，然后将所有印章叠印到同一位置，按该顺序从下往上覆盖。

Input structure：
- 背景为 azure。
- 网格中分散着若干个形状完全相同但颜色各异的连通对象（"印章"），每个印章由单一前景色构成。
- 每个印章的正下方紧贴着一行彩色条纹（高度为 1 的水平像素序列），条纹的长度等于印章的宽度。
- 每个条纹由其他印章的颜色组成（不包含自身颜色），条纹中从左到右的颜色顺序编码了该印章相对于其他印章的"深度排名"。
- 输出网格的尺寸等于单个印章的外接矩形大小。

Rule：
- 识别所有印章及其各自的颜色和条纹。
- 每个印章的条纹代表"在我之下的印章，从最底层到紧挨我下方"的颜色序列。因此条纹最长的印章在最顶层，条纹为空（无条纹）的印章在最底层。
- 根据条纹长度从短到长排列印章，得到从底到顶的堆叠顺序。
- 创建一个与单个印章外接矩形同大的输出网格，背景为 azure。
- 按堆叠顺序依次将每个印章（以其原始形状和颜色）绘制到输出网格的相同位置，后绘制的覆盖先绘制的。

Key insight：
印章的空间位置是干扰信息，条纹长度而非印章位置才决定堆叠顺序——解题者需要先发现条纹编码深度的规律，再理解条纹长度与层级的对应关系，最后执行叠印操作。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
