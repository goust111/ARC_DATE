- `description`：将网格中多个带缺口的环形轮廓按缺口朝向排列成一条路径，路径方向由缺口的链式接续决定。

- `Input structure`：背景为 black。网格中散布着若干个大小相同的环形轮廓对象（每个环由某种颜色的像素组成，形成一个 5x5 的空心正方形框，但其中一条边的中间一个像素缺失，形成一个单像素缺口）。所有环的颜色相同（例如 green）。网格右下角有一个用 red 绘制的小型 1x1 像素标记。另外，网格左上角有一个用 azure 绘制的小型 1x1 像素标记。

- `Rule`：
  1. 输出网格的大小根据环的数量 N 确定：输出为 1 行 N 列（或 N 行 1 列，取决于路径方向）的排列结果，每个单元格为 5x5。
  2. 从 azure 标记最近的那个环开始，该环作为路径的第一个环。
  3. 该环的缺口朝向（上、下、左、右）决定下一个环的寻找方向：沿缺口方向找到最近的另一个环，将其作为路径的下一个。
  4. 依次重复：每次取当前环的缺口方向，沿该方向找到最近的下一个未访问环，直到所有环都被串入路径。
  5. 输出时，将这些环按路径顺序从左到右紧密排列在一行中（去除原始间距），保持每个环自身的朝向不变。

- `Key insight`：缺口不仅是环的视觉特征，更是一个隐含的"指针"——每个环的缺口指向下一个环的位置，解题者需要发现这个链式指向关系才能确定正确的排列顺序。起点由 azure 标记确定，这是一个辅助但必要的信息。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
