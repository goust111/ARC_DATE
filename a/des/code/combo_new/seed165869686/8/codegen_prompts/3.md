Input structure：
- 背景色（bg）为网格中最常见的颜色。
- 网格的最左列或最右列中，某些行包含一个由 red 像素构成的 3 像素箭头（一个水平线段像素加上两个斜向像素构成箭头尖），箭头朝左或朝右。没有箭头的行保持全背景色。
- 在有箭头的每一行中（箭头列之外的区域），散布着若干不同颜色的非背景色像素点，每种颜色在该行中出现 1 到 3 次。
- 同一行中不同颜色像素的出现次数可能不同。

Rule：
- 对于每个包含箭头的行，确定箭头方向（左或右）。
- 收集该行中所有非背景、非箭头颜色的像素，按颜色分组，记录每种颜色的像素数量。
- 将所有像素从原位置清除。
- 按照颜色在该行中首次出现的列位置从靠近箭头侧到远离箭头侧排序。
- 将排序后的颜色组依次紧密排列到箭头所指方向的墙壁边（若箭头朝右，则从该行最右端开始向左堆叠；若箭头朝左，则从该行最左端——箭头之后的第一个可用位置——开始向右堆叠）。每个颜色组内部连续排列，组与组之间紧密相邻无间隔。
- 箭头本身在输出中被移除（替换为背景色）。

Key insight：箭头不仅编码了堆叠方向，还隐含了排序基准——颜色组的堆叠顺序取决于它们原始位置与箭头的远近关系（离箭头近的颜色先贴墙），而非按颜色本身的某种属性排序。解题者需要先理解方向编码，再发现排序规则依赖于空间位置，构成两层推理。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
