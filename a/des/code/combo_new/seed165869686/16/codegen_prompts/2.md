- `description`：将散落的形状按照各自包含的颜色种类数进行分组，同组形状合并为紧凑排列的复合体输出。

- `Input structure`：
  - 背景为azure。
  - 网格中散布若干个不规则的4-连通多色对象（每个对象由2到4种颜色的像素组成，对象之间不接触）。
  - 每个对象的外形和大小各不相同，但同一个对象内部的颜色种类数是可数的（范围在2到4之间）。

- `Rule`：
  - 统计每个对象内部包含的不同颜色数量 N。
  - 将具有相同 N 值的对象归为一组。
  - 对每组，按对象面积从大到小的顺序，将对象的最小外接矩形从左到右水平排列（对象在其外接矩形内保持原始形状和颜色），相邻外接矩形之间间隔一列背景色，所有对象底部对齐。
  - 各组之间用两列背景色分隔，组的排列顺序为 N 从小到大（即颜色种类少的组在左）。
  - 输出网格的高度为所有对象外接矩形中最高的那个，宽度为所有组加上分隔列的总宽度。

- `Key insight`：解题者首先需要发现分组依据不是形状、大小或位置，而是每个对象内部的颜色多样性；然后需要推断组内的排序规则（按面积）和组间的排列顺序（按颜色种类数）。这是两层独立的归纳。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
