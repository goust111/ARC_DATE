description: 根据框架边框上的缺口位置，将框架内部的彩色碎片向缺口反方向滑动堆叠，再用框架自身的颜色重新着色堆叠后的碎片。

Input structure:
- 背景为 black。网格中散布若干大小不同的矩形空心框架，每个框架由单一颜色绘制（如 red、blue、green 等），框架线宽为 1 像素。
- 每个框架的四条边中恰好有一条边存在一个连续缺口（缺口宽度 >= 2 像素，缺口处为 black 背景色）。
- 框架内部散布若干小型单色连通碎片（每个碎片 2-4 像素），碎片颜色与框架颜色不同，且同一个框架内部的碎片可能有多种颜色。

Rule:
- 对每个框架，首先确定缺口所在的边（上、下、左、右）。
- 将框架内部所有碎片沿缺口的反方向滑动（即远离缺口方向），直到碎片触碰框架的对侧内壁或已堆叠的碎片为止（类似重力效果，碎片保持自身形状不变）。滑动顺序为：距离对侧内壁最近的碎片先滑动。
- 滑动完成后，将所有堆叠碎片的颜色统一替换为框架自身的颜色。
- 框架线条保持不变，缺口保持不变。

Key insight: 缺口不是碎片的出口，而是"重力方向"的反向指示器——碎片向远离缺口的方向堆叠；第二层推理在于碎片最终颜色由所属框架决定，而非碎片原有颜色，解题者需要从多个样例中发现这一着色替换规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
