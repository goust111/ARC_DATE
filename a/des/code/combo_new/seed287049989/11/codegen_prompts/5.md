Input structure
- 背景为主色（如 black）。
- 网格正中有一列 grey 分隔线将网格分为等宽的左面板和右面板。
- 左面板包含若干个小型彩色形状（各不相同颜色，如 red、blue、green），每个形状占据不超过 4x4 的区域。这些形状是某个完整对称图案的一个"折叠片段"。
- 折叠类型判断依据：观察形状包围盒内的像素分布——
  - 若形状像素同时填满了包围盒的最右列和最底行（即右下角像素存在），则该形状是完整图案的左上四分之一，需沿右边缘和下边缘双轴镜像展开为 4 倍大小。
  - 若形状像素填满了包围盒的最右列但最底行未全部填满，则该形状是完整图案的左半部分，需沿右边缘单轴左右镜像展开。
  - 若形状像素填满了包围盒的最底行但最右列未全部填满，则该形状是完整图案的上半部分，需沿下边缘单轴上下镜像展开。
- 右面板中，每种出现在左面板的颜色恰好有一个单独的种子像素，标记展开后完整图案的中心位置。

Rule
- 对左面板中的每个彩色形状 S（颜色 C），按上述规则判断折叠类型。
- 根据折叠类型执行镜像展开，得到完整图案。双轴展开时：先将 S 沿右边缘向右镜像得到上半部分，再将整个上半部分沿下边缘向下镜像得到完整图案。单轴展开时，仅沿对应边缘镜像一次。
- 在右面板中找到颜色 C 的种子像素位置 P，以 P 为完整图案的几何中心，绘制完整图案。
- 输出仅包含右面板（裁去左面板和分隔线），宽度为原始右面板宽度。

Key insight
解题者需要先发现左面板的形状不是完整图案而是需要展开的片段（第一层推理），再通过观察形状包围盒边缘的填充情况区分"四分之一折叠"和"二分之一折叠"及其轴向（第二层推理），最后将展开结果正确放置到右面板种子位置（第三层推理）。折叠类型的判断隐藏在边缘像素的微妙差异中。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
