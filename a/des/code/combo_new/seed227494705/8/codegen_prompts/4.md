<new_puzzle index="4">
- `description`：识别每个前景对象轮廓上的凹陷缺口方向，然后让对象沿缺口方向"生长"出自身的镜像翻转副本，使缺口与凸起互补吻合。

- `Input structure`：
  - 背景为 black。
  - 网格上有若干个互不接触的前景对象，每个对象由单一颜色构成，形状为近似矩形但在某一条边上有一个凹陷缺口（缺口为 1~2 像素深的矩形凹槽）。
  - 每个对象的颜色各不相同。
  - 对象之间有足够空间容纳生长后的副本。

- `Rule`：
  - 第一层推理：对每个对象，检测其四条外边界（上、下、左、右），找到包含凹陷缺口的那条边。凹陷缺口的定义是：该边上有连续的背景像素向对象内部凹入。缺口所在的边指示了"生长方向"（缺口在右边 → 向右生长；缺口在上边 → 向上生长，以此类推）。
  - 第二层推理：沿生长方向，在对象的该侧紧邻位置放置该对象沿生长方向轴的镜像翻转副本。例如缺口在右边，则将对象沿垂直轴左右翻转后，紧贴在对象的右侧。翻转副本使用与原对象相同的颜色。
  - 关键细节：原对象的缺口位置与翻转副本的对应凸起恰好互补吻合，形成一个无缝拼接的对称整体。如果对象本身已关于该轴对称，副本仍然放置（结果为原对象沿生长方向加倍）。
  - 原对象保持不变，仅新增翻转副本。

- `Key insight`：缺口不是"损坏"——它既是方向指示器（告诉你往哪个方向扩展），又是形状匹配锚点（翻转后的凸起恰好填入缺口）。解题者需要同时发现缺口的方向编码功能和镜像拼接机制。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
