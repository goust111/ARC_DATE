网格包含若干"画笔"对象和一个"画布"区域；每把画笔的颜色和朝向决定它在画布上绘制的笔画位置与方向，笔画长度则由画笔自身的像素数决定。

Input structure
- 背景色为 Black。
- 网格右下角有一个矩形"画布"区域，边框为 Grey，内部为背景色。
- 画布外部散布着若干"画笔"对象，每个画笔是一个单色的 4-连通线段（水平或垂直的一排像素，长度 2-6 不等），颜色各不相同。
- 每个画笔的一端有一个相邻的单像素 Yellow 标记，位于画笔的某一侧（上/下/左/右），表示该画笔的"笔尖方向"。
- 画布的一条边（上边或左边）上按等间距排列着与画笔同色的单像素"锚点"。

Rule
- 将每个画笔与画布边上同色的锚点配对。
- 从锚点出发，沿画笔的笔尖方向（由 Yellow 标记相对于画笔的方位决定）在画布内部绘制一条直线笔画。
- 笔画的长度等于该画笔的像素数（不含 Yellow 标记）。
- 笔画颜色与画笔颜色相同。
- 画笔和 Yellow 标记在输出中保持不变；画布内未被笔画覆盖的区域保持为背景色。

Key insight
解题者需要同时解码三种信息——颜色配对（画笔↔锚点）、方向（Yellow 标记的相对位置）、长度（画笔像素数）——并将它们组合才能确定画布上每条笔画的完整参数。单独看任何一条规则都很简单，但三者的交叉组合构成了需要多样例才能归纳的推理挑战。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
