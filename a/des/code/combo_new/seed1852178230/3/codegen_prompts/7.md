- `Input structure`：
  - 背景为黑色。
  - 网格中有若干互不重叠的彩色图案对象，每个对象占据一个正方形边界框（边长为奇数，如 5×5 或 7×7）。
  - 每个图案原本具有 180 度旋转对称性（绕其中心旋转 180 度后与自身重合），但其中恰好有一个像素的颜色被"篡改"，破坏了这一对称性。
  - 被篡改的像素不在图案中心。

- `Rule`：
  - 对每个图案，找到其中心点，将图案绕中心旋转 180 度。
  - 比较原始图案与旋转后的图案，找到唯一不匹配的像素对（位置 P 和其旋转对应位置 P'）。
  - 在这对不匹配像素中，确定哪个是"缺陷"：与其 4-邻域中多数颜色不一致的那个为缺陷像素。
  - 将缺陷像素的颜色替换为其旋转对称位置上像素的颜色。
  - 其余所有像素保持不变。

- `Key insight`：解题者首先需要发现所有图案"几乎"具有 180 度旋转对称性这一隐含结构特征，然后定位破坏对称性的唯一缺陷，最后利用邻域一致性作为 tie-breaker 来区分"正确像素"和"被篡改像素"——三层推理环环相扣。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
