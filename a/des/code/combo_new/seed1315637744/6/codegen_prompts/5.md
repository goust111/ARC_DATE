Input structure
- 黑色背景上散布着偶数个"信号塔"对象。每个信号塔由一个 3×3 的实心彩色方块和一根从方块某条边中点向外延伸 2 像素的单像素宽"天线"组成（天线颜色与方块颜色相同）。
- 天线方向为上、下、左、右之一，指示该信号塔的"发射方向"。
- 所有信号塔的方块颜色各不相同，但仅使用红、蓝、黄三种颜色中的两种。

Rule
- 将天线方向相对的信号塔配对：一个天线朝左的塔与一个天线朝右的塔配对（它们可以在同一行，也可以不在同一行）；一个天线朝上的塔与一个天线朝下的塔配对。若同一方向有多个候选，则选择天线延长线距离最近的一对（沿天线方向投影后，两根天线延长线之间间隔最少的配对）。
- 配对后，在两个塔的天线尖端之间绘制一条直线段（水平或垂直，沿天线的公共轴方向）。
- 连线颜色规则：若两个塔颜色相同，连线为该颜色；若两个塔颜色不同（例如一红一蓝），连线颜色为第三种未被使用的颜色（黄）。即连线颜色始终是三原色中两塔均未使用的那种。
- 信号塔本身（方块和天线）在输出中保持不变。

Key insight
- 第一层推理是通过天线方向的对立关系（左↔右、上↔下）实现配对；第二层推理是连线颜色的"补色"规则——同色连同色、异色连第三色——需要解题者从样例中归纳出三色互补的混合逻辑。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
