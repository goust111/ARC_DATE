- `Input structure`：
  - 背景为主色调（如 black）。
  - 网格中散布若干大小相同的矩形框架（由同一种颜色绘制的一像素宽边框），每个框架恰好缺少一条边（上、下、左或右），框架内部为背景色。

  - 精灵的颜色各不相同，且均与所有框架颜色不同。

- `Rule`：
  - 第一层：对每个框架，识别其缺失边所在的方向（上、下、左或右）。
  - 第二层：在所有精灵中，找到凸出方向与框架缺失边方向相对（即凸出指向缺口方向的反面）的那个精灵——例如框架缺失上边，则选凸出朝下的精灵。将该精灵旋转或翻转，使其凸出方向指向框架缺失边的方向（朝上）。
  - 第三层：将精灵的包围盒映射到框架内部区域（将精灵包围盒的四角对齐到框架内部的四角，精灵前景像素对应位置用框架边框颜色绘制，其余保持背景色）。原始精灵从网格中擦除。

- `Key insight`：
  框架的缺口方向不是直接决定填充内容的，而是作为索引去匹配精灵的凸出朝向；精灵的最终颜色由框架自身的边框色决定，而非精灵原色。解题者需要先发现"缺口方向↔精灵凸出方向的反向配对"规则，再发现颜色继承规则。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
