- `Input structure`：
  - 背景为 black。
  - 网格中有若干条不同颜色的路径碎片。每条路径由同一颜色的多段一像素宽的水平或垂直线段组成（每段长度至少 2 像素），同一路径的所有碎片端点两两之间恰好有一对可以通过直角折线（先水平再垂直，或先垂直再水平）连接且路径不重叠。
  - 每条路径的其中一个端点像素被替换为 yellow，标记为起点。
  - 网格中另有若干 red 的单像素散布在路径附近（不接触任何路径），作为干扰物。

- `Rule`：
  - 第一步——拼接路径：对每种颜色，找到所有碎片的自由端点（仅有一个同色邻居的像素），将可以通过一次直角弯折相连且不穿越其他已有像素的端点对连接起来，连线颜色与路径相同。连接后每条路径成为一条从 yellow 起点出发的连续折线。
  - 第二步——绘制栅栏柱：从 yellow 起点沿路径前进，每隔 3 个像素（即在路径的第 4、第 7、第 10 个像素处，以此类推），在路径的垂直方向上交替向两侧延伸一个 green 像素。第一个栅栏柱向路径行进方向的左侧延伸，第二个向右侧，依此交替。若延伸位置已有非 black 像素则跳过该柱但交替顺序不跳过。
  - red 干扰像素在输出中保留不变。

- `Key insight`：第一层推理是发现碎片按颜色分组后需要通过直角折线拼接成完整路径；第二层推理是发现栅栏柱的放置规则——等间距、左右交替、垂直于局部路径方向。两层规则都需要从样例中独立归纳。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
