根据种子像素的颜色在封闭区域内生长出与该区域边界形状相似的缩小版轮廓。

Input structure：
- 背景为主色调。网格中有若干由同一颜色（如 grey）绘制的封闭轮廓（一像素宽，形成闭合多边形，内部为背景色）。
- 每个封闭轮廓内部恰好有一个非背景、非轮廓色的单像素"种子"。
- 种子有两种可能的颜色：red 或 blue。

Rule：
- 对每个封闭轮廓，计算其内部区域（不含轮廓线本身）。
- 如果种子颜色为 red：在轮廓内部绘制一圈向内收缩一像素的同形轮廓（即原轮廓每个像素向内移动一格后的位置），用 red 绘制。
- 如果种子颜色为 blue：在轮廓内部绘制向内收缩两像素的同形轮廓，用 blue 绘制。
- 收缩轮廓仅保留与原轮廓拓扑一致的像素（若收缩后某段消失则不绘制）。
- 种子像素本身在输出中擦除为背景色。原始 grey 轮廓保持不变。

Key insight：种子的颜色决定了收缩的层数（red=1层、blue=2层），解题者需要先归纳出颜色与收缩深度的对应关系，再理解"收缩轮廓"是将边界整体向内侵蚀指定步数后的结果。
</new_puzzle>

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
