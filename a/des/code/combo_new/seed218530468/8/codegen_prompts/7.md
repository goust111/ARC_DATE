- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个"洋葱"结构，彼此不重叠。每个洋葱由 2-4 层同心嵌套的矩形框组成，每层框为一像素宽的 grey 色环，相邻两层框之间间隔一个像素的背景色。
  - 每个洋葱结构的最内层中心位置有一个 1×1 的彩色像素（"核心"），核心颜色在不同洋葱之间互不相同。
  - 网格的某个角落有一个调色板区域：由若干行组成，每行以一个彩色像素开头（该颜色与某个洋葱的核心颜色相同），紧随其后是 2-4 个不同颜色的像素（数量与对应洋葱的层数相同），形成一个有序颜色序列。不同行之间由一行背景色间隔。

- `Rule`：
  - 第一步（匹配核心到调色板）：对每个洋葱结构，读取其核心颜色 C，在调色板中找到以 C 开头的那一行。
  - 第二步（读取着色序列）：该行中核心颜色 C 之后的像素依次为 C1, C2, C3...，分别对应从最内层框到最外层框的着色颜色。
  - 第三步（逐层着色）：将最内层矩形框的所有 grey 像素重绘为 C1，第二层框重绘为 C2，以此类推直到最外层。核心像素本身在输出中保持原色不变。
  - 调色板区域在输出中被完全擦除为背景色。

- `Key insight`：所有框架初始都是相同的 grey 色，肉眼无法区分不同洋葱结构该用什么颜色——必须依靠最内层核心像素在调色板中查表获得整个着色方案，形成"核心决定外壳外观"的由内而外的三层推理链：识别核心颜色 → 调色板查找 → 按序逐层着色。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
