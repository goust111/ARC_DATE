- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由 azure 像素构成的矩形"窗框"。每个窗框是单像素宽的矩形环，且在某一条边（上、下、左或右）上有一个连续缺口。缺口的宽度等于窗框内部在该边方向上的完整跨度（即缺口把那条边完全移除）。
  - 每个窗框内部包含一个由某种颜色（如 red、green、blue 等，各窗框不同）构成的小型图案，占据内部的部分像素。
  - 每个窗框内部还散落着若干个 yellow 单像素标记点（位于内部图案之外的黑色空白像素上），数量在 1 到 4 之间。
  - 不同窗框之间有足够间距。

- `Rule`：
  - 对每个窗框：
    1. 确定缺口所在的边——该边方向即为图案的"发射方向"（缺口在上边则向上发射，缺口在右边则向右发射，依此类推）。
    2. 数出窗框内部 yellow 标记点的数量 N。
    3. 将窗框内部的彩色图案（不含 yellow 标记和 azure 边框）沿发射方向平移复制 N 次。第 k 次复制（k = 1, 2, ..., N）的偏移量为 k 乘以窗框在发射方向上的外部尺寸（包含边框的总宽度或总高度）。
  - 原窗框及其全部内容保持不变。
  - 复制出的图案若部分超出网格边界则截断丢弃超出部分。

- `Key insight`：
  - 解题包含三层非显然推理：（1）缺口方向编码了发射方向——需要发现"缺口 = 出口"的隐喻而非仅仅是形状缺陷；（2）yellow 标记数量编码了复制次数——需要从多个样例中归纳出数量与复制的对应关系；（3）复制间距由窗框自身外部尺寸决定——不是固定间距也不是图案自身尺寸，需要从样例中测量推断。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
9. `main(grid)` 必须带一段 docstring，按 `ARC_code` 参考题的格式分四部分书写：首行用一句话概述转换目标；随后 `Input structure:` 描述输入网格中的对象/背景/标记/边界/组件；`Rule:` 给出从输入到输出的确定性变换规则；`Key insight:` 点明解题核心洞见。该 docstring 供下游相似度/索引流程（按 `main` 的 docstring 抽取机制标签）使用，缺失会导致此题无法被收录为参考题。
