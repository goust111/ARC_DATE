- `Input structure`：
  - 背景为黑色（black）。
  - 网格被若干条完整的灰色（grey）水平线和垂直线分割成一个 M×N 的矩形子区域网格（例如 2×3 或 3×3）。每条灰色线贯穿网格的整个宽度或高度。
  - 每个子区域内部包含一个由某种非黑非灰颜色绘制的前景图案（形状各异，可能是小十字、小方块、L 形等）。不同子区域的图案形状和颜色可以不同。
  - 每个子区域的灰色边框上恰好有两个彩色（非黑非灰）的单像素标签，位于该子区域边框的不同边上。这两个标签颜色互不相同，也与该子区域内部图案的颜色不同。
  - 标签的位置决定其角色：位于子区域上边框或左边框上的标签为"发送标签"，位于子区域下边框或右边框上的标签为"接收标签"。
  - 配对规则：当区域 A 的发送标签颜色与区域 B 的接收标签颜色相同时，A 的图案应传递到 B。每个区域恰好作为发送方一次、作为接收方一次，所有区域形成若干个不重复的置换环。

- `Rule`：
  1. 识别所有由灰色分隔线划分出的子区域。
  2. 在每个子区域的灰色边框上找到两个彩色标签像素。
  3. 根据标签位置区分角色：在子区域上边框或左边框上的为发送标签，在下边框或右边框上的为接收标签。
  4. 建立传递映射：对每个区域 A，找到接收标签颜色与 A 的发送标签颜色匹配的区域 B，A→B 为一条传递边。
  5. 将每个区域 A 的前景图案（保持原始形状和颜色不变）复制到其目标区域 B 中。图案在目标区域中放置于与其在源区域中相同的相对位置（相对于子区域左上角的偏移不变）。
  6. 所有标签像素在输出中恢复为灰色。灰色分隔线保持不变。

- `Key insight`：解题者需要先发现边框上的彩色像素不是装饰而是控制图案流向的配对信号，再推断出标签的发送/接收角色由其在边框上的位置决定（上/左=发送，下/右=接收），最后根据颜色匹配建立区域间的图案传递关系。三层推理为："识别标签像素的功能意义"→"通过边框位置区分发送与接收角色"→"颜色配对确定传递目标"。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
