  - 每座桥梁的中点位置旁有一个 green 像素标记，指示传送方向：green 像素不在桥梁上，而是位于桥梁中点的垂直偏移一格处。对于水平桥梁，green 在中点上方一格表示源岛在左、目标岛在右；green 在中点下方一格表示源岛在右、目标岛在左。对于垂直桥梁，green 在中点左侧一格表示源岛在上、目标岛在下；green 在中点右侧一格表示源岛在下、目标岛在上。

- `Rule`：
  - 对每座桥梁，根据 green 标记确定源岛和目标岛。
  - 从源岛取出内部图案。
  - 根据桥梁从源岛出发的方向计算旋转量：图案需要旋转，使其在源岛中"面朝的方向"（即图案所在的源岛边框侧）转向桥梁指向目标岛的方向。具体地：若桥梁从源岛的右边框出发则不旋转；从左边框出发则旋转 180 度；从下边框出发则顺时针旋转 90 度；从上边框出发则逆时针旋转 90 度。
  - 将旋转后的图案放入目标岛的内部区域（居中放置），替换目标岛原有的图案。目标岛原有图案被清除为 black。
  - 源岛的图案保持不变。所有桥梁、grey 边框和 green 标记保持不变。

- `Key insight`：green 偏移像素同时编码了方向和源/目标关系——解题者需要先破解 green 标记的"偏移即箭头"语义，再发现图案需要根据桥梁走向旋转以对齐目标岛的朝向，这构成两层独立的推理。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
