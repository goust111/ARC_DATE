- `Input structure`：
  - 背景为主色（black）。
  - 网格中散布若干个由单一颜色绘制的一像素厚矩形框架（如 blue、green、red 等不同颜色），每个框架恰好有一条边缺失，形成 U 形开口。
  - 每个框架的某一个角落像素被替换为另一种非背景、非框架颜色的角标色（角标色在整个网格中唯一对应一种碎片颜色）。
  - 网格中另有若干个由不同颜色绘制的小型不规则 4-连通碎片（占 2-5 像素），每种碎片颜色恰好与某个框架角标色相同。
  - 碎片数量与框架数量一一对应。

- `Rule`：
  - 第一步（匹配）：每个框架通过其角标颜色找到颜色相同的碎片——角标颜色 = 碎片颜色，建立配对关系。
  - 第二步（旋转与嵌入）：将配对碎片旋转（0°/90°/180°/270°），使碎片的形状能从框架的缺口方向滑入并紧贴缺口对面的内壁。碎片被放置在框架内部、紧靠缺口对面那条边的位置，水平或垂直居中于该边。
  - 第三步（重新着色）：嵌入后的碎片不保留自身原色，而是重新着色为框架本身的颜色。
  - 原始碎片位置擦除为背景色；角标像素保留不变。

- `Key insight`：角标色是配对索引，而非碎片在输出中的最终颜色；碎片最终颜色由目标框架的主体色决定。缺口朝向同时决定了碎片需要旋转的角度和放置的位置。解题者需要先通过角标建立配对，再根据缺口方向推断旋转，最后理解重新着色规则——三层推理缺一不可。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
