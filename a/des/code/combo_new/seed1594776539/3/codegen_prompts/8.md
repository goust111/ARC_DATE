- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干棵互不 4-连通的"像素树"。每棵树由多种颜色的像素组成，整体 4-连通。
  - 每棵树的结构特征：恰好有一个像素只有一个同树 4-连通邻居且位于树的空间中心区域——这是"根"。从根出发，树逐层向外延展和分叉，直到最外层的多个叶子像素（每个叶子只有一个同树 4-连通邻居，且位于树的外围）。
  - 树的每一层使用统一的单一颜色，且相邻层颜色不同。根为颜色 A，与根相邻的下一层为颜色 B，再下一层为颜色 C，直到最外层叶子为颜色 Z。每棵树至少有 3 层颜色。

- `Rule`：
  - 对每棵树，通过以下方法识别根和叶子：所有只有一个同树 4-连通邻居的像素是"端点"；其中位于树的空间中心（即坐标最接近所有树像素平均位置的那个端点）的是根，其余端点是叶子。
  - 记录根的原始颜色 A 和叶子的原始颜色 Z。
  - 将所有叶子像素的颜色替换为 A。
  - 将根像素的颜色替换为 Z。
  - 树的中间层（颜色 B、C 等）像素保持不变。
  - 背景保持不变。

- `Key insight`：解题者需要首先识别像素群的"树"拓扑结构——特别是区分根和叶子（两者都只有一个邻居，但根在中心、叶在外围），然后发现变换规则是最内层和最外层的颜色互换而中间层不变。关键困难在于：根和叶子在局部结构上看起来相似（都是端点），需要通过空间位置（中心 vs. 外围）来区分，这是第一层归纳；首尾颜色互换而非简单替换是第二层归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
