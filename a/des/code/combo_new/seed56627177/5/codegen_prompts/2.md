将散落的单色碎片旋转拼入唯一匹配的容器凹槽中，旋转角度由容器缺口方向决定。

Input structure
- 背景为黑色。
- 网格中有若干由 grey 像素构成的大型 L 形或 U 形容器，每个容器有且仅有一个矩形凹槽开口朝向四个正方向之一（上、下、左、右）。
- 网格中散落着与容器数量相同的小型单色碎片（颜色各不相同，如 red、blue、green 等），每个碎片是一个不规则但连通的 4-连通对象。
- 每个碎片的形状恰好能以某个 90 度倍数的旋转后精确填入某一个容器的凹槽。碎片的原始朝向统一为"开口朝上"对应的基准形态。

Rule
- 对每个容器，确定其凹槽开口朝向的方向（上、下、左、右）。
- 找到形状匹配该凹槽的碎片（旋转后形状与凹槽完全吻合的唯一碎片）。
- 将碎片按容器开口方向旋转到正确朝向：开口朝上则不旋转，朝右则顺时针 90 度，朝下则 180 度，朝左则逆时针 90 度。
- 将旋转后的碎片放置到容器凹槽的精确位置，碎片保持其原始颜色。
- 原始位置的碎片被清除为黑色背景。

Key insight
容器的开口方向同时编码了两个信息：哪个碎片属于它（形状匹配）以及碎片需要旋转多少度。解题者必须先通过形状匹配建立碎片-容器配对，再通过开口方向确定旋转量——这两步推理相互独立且都不显然。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
