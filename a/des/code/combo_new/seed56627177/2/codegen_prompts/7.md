将网格中的环形轨道上的彩色珠子按照轨道内部指示器的颜色进行循环移位，移位步数等于指示器颜色在轨道上出现的珠子数量。

Input structure
- 背景为 black。
- 网格中有若干个独立的闭合环形轨道，每个轨道由一圈连续的彩色像素组成（轨道像素两两四方向相邻，形成一个恰好一像素宽的封闭环路，无分叉）。
- 轨道上的像素由若干种不同颜色组成，相同颜色的像素形成连续的弧段（称为"珠子"）。
- 每个环形轨道围成的内部区域中恰好有一个单像素的指示器，颜色为轨道上出现的某种珠子颜色。

Rule
- 对每个环形轨道，读取其内部指示器的颜色 C。
- 数出轨道上颜色为 C 的像素总数，记为 S。
- 将轨道上所有像素沿轨道的顺时针方向循环移位 S 步（每个像素的颜色沿顺时针方向传递 S 个位置）。
- 顺时针方向的定义：从轨道最上方的最左像素出发，优先向右行进，始终保持内部区域在右手侧。
- 指示器像素保持不变。

Key insight
- 第一层推理：指示器的颜色不是标记"哪个珠子要动"，而是编码"移多少步"——步数等于该颜色在轨道上的像素数量，需要从多个样例中归纳出计数-移位的对应关系。第二层推理：移位是沿轨道的循环移位而非空间平移，需要理解环形拓扑上的旋转操作。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
