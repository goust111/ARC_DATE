将散落在网格中的彩色三角形箭头按其指向方向移动到网格边缘，沿边的精确落点由颜色匹配的边缘标记条决定。

Input structure:
- 背景为 black。网格的四条边上各有零或一段连续的彩色边缘标记条（宽1像素，长度不等，颜色各不相同，紧贴网格边缘）。
- 网格内部散布着若干由不同颜色构成的小型三角形箭头精灵（每个箭头由5个像素组成：3像素构成底边横排或竖排的一行，2像素构成在底边中央像素的前方叠起的尖端，整体形成指向上、下、左、右某个方向的箭头形状）。
- 每个箭头的颜色与某一条边缘标记条的颜色相同。

Rule:
- 对每个箭头，根据其尖端朝向确定移动方向（尖端朝上则向上移动，以此类推）。
- 将箭头从当前位置移除，沿指向方向平移，直到箭头的前端像素紧贴网格边界。
- 箭头沿边方向的最终位置由其颜色对应的边缘标记条决定：箭头的中轴线对齐到标记条的中心位置。
- 若箭头指向的边恰好没有标记条，则箭头指向的边上一定有与之同色的标记条（题目保证每个箭头都能找到匹配的标记条在其指向的边上）。
- 其余像素保持不变。

Key insight:
解题者需要分两步归纳：（1）箭头的几何形状编码了移动方向，（2）箭头的颜色与边缘标记条的匹配关系决定了它沿边的精确落点——方向和定位是两套独立的编码系统。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
