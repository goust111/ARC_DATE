- `Input structure`：
  - 背景色为 black。
  - 网格中有若干水平或垂直的彩色线段（一像素宽，长度 2-5 像素）。每条线段由单一颜色组成。
  - 网格中还散布着若干单像素的方块标记，每个方块标记的颜色与某条线段的颜色相同。
  - 每种颜色恰好对应一条线段和一个方块标记。
  - 方块标记总是位于其对应线段的延长线方向上（即线段某一端沿线段方向延伸可到达方块标记），但两者之间有间隔。

- `Rule`：
  - 对每条线段，确定其对应的同色方块标记所在的方向（线段的哪一端朝向标记）。
  - 从线段朝向标记的那一端开始，沿线段方向延伸，新增的像素数量等于线段原始长度。延伸像素使用该线段的颜色。
  - 延伸不会超过方块标记的位置；如果延伸恰好到达或经过标记，则延伸到标记位置为止（标记像素被线段颜色覆盖）。
  - 方块标记如果不在延伸路径上，保持不变。

- `Key insight`：线段的生长方向由同色标记的位置决定，而生长长度由线段自身的像素数量决定——这意味着短线段长得少、长线段长得多。解题者需要同时建立两个非显然的关联：颜色匹配确定方向，自身长度确定生长量。两层推理：第一层是发现同色标记指示方向，第二层是发现"生长量 = 自身长度"的数量法则。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
