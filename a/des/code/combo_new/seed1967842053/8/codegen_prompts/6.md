在分层地图中，每个高度层的颜色环向内收缩一格后露出下层颜色，最终形成嵌套等高线效果。

Input structure：
- 网格表示一幅俯视"地形图"。背景为 black，代表最低层（高度 0）。
- 网格中有若干彩色区域，每种颜色代表一个高度层。高度层的排列满足嵌套关系：高层区域完全被低层区域包围（如 blue 区域包围 red 区域，red 区域包围 green 区域）。
- 高度层从外到内依次递增，颜色顺序在所有样例中固定（例如外层为 blue、中层为 red、内层为 green）。
- 每个颜色区域是一个 4-连通的区域，形状不规则但始终为凸形或近凸形。

Rule：
- 输出网格尺寸与输入相同。
- 每个颜色区域向内收缩一格：将该颜色区域的最外圈像素（即 4-邻接方向上至少有一个不属于该区域的像素的那些像素）移除。
- 被移除的像素显示为其下一层的颜色：最外层颜色被移除后露出 black（高度 0）；中间层被移除后露出外层颜色；内层被移除后露出中间层颜色。
- 若某个颜色区域收缩后完全消失（面积太小），则该区域所有像素显示为下层颜色。
- 不属于任何彩色区域的 black 像素保持不变。

Key insight：
- 解题者需要先识别出颜色区域之间的嵌套包含关系（从而确定高度层序），再理解每层独立收缩并露出下层的"剥皮"操作。嵌套关系的判断和收缩操作是两个独立的推理步骤——单纯观察收缩无法解题，还必须理解层级关系才能确定收缩后露出的颜色。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
