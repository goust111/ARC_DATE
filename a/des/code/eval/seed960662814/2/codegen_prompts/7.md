  - 网格中有若干个矩形"容器"：每个容器由 azure 边框围成，内部大部分被某种颜色 C 填充，但留有一个不规则的空缺区域（空缺处为 bg）。
  - 每个容器的边框四条边中，恰好有一条边上的某段像素被替换为另一种颜色（非 azure），形成"色带标记"。色带可出现在上、下、左、右任一边。
  - 网格中散布着若干个由 grey 像素组成的不规则碎片，每个碎片的形状恰好与某个容器的空缺区域形状互补——但可能需要水平或竖直镜像后才能完全吻合。

- `Rule`：
  - 第一层：形状匹配——每个碎片的形状（像素集合的相对位置）经过适当镜像变换后，恰好能填满某个容器的空缺区域。通过形状互补性找到碎片-容器配对。
  - 第二层：色带解码镜像——容器边框上色带标记的位置决定镜像方式：色带在上边或下边 = 碎片需水平镜像（左右翻转）后填入；色带在左边或右边 = 碎片需竖直镜像（上下翻转）后填入。

  - 碎片原始位置变为 bg。容器边框（含色带标记）在输出中保持不变。

- `Key insight`：解题者需要先通过形状互补找到配对（这本身需要考虑镜像），再发现色带位置编码了具体的镜像轴向，两层推理相互依赖——不知道镜像方式就无法确认形状是否匹配，而镜像方式又隐藏在边框标记中。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
