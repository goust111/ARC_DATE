- `description`：根据嵌套框架的层数对框架内的种子像素进行"开花"扩展，层数越深则花瓣越大。

- `Input structure`：
  - 背景色 bg 为黑色。
  - 网格中有若干组嵌套的矩形空心框架。外层框架用一种颜色绘制（如 blue），内层框架用另一种颜色绘制（如 green），若有第三层则用第三种颜色（如 red）。框架之间用 bg 分隔，每层框架宽度为 1 像素。
  - 在最内层框架的内部区域中，有一个或几个孤立的单色像素（种子），颜色为 yellow。

- `Rule`：
  - 第一步（计算嵌套深度）：对每组嵌套框架，数出从最外层到包裹种子的最内层共有几层框架。例如一层框架深度为 1，两层嵌套为 2，三层嵌套为 3。
  - 第二步（扩展种子）：以每个种子像素为中心，向上下左右四个方向各延伸 N 个像素（N = 嵌套深度），形成一个十字形"花瓣"，花瓣颜色为 magenta。花瓣不超出最内层框架的边界；若遇到框架壁则截断。
  - 第三步（标记中心）：种子像素自身保持 yellow 不变，作为花瓣中心标记。
  - 框架本身保持不变。

- `Key insight`：嵌套深度并非一眼可见的数字，需要解题者主动识别框架的包含关系并逐层计数；然后这个计数值被转化为花瓣的几何扩展长度——两步推理缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
