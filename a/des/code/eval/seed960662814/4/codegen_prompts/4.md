- `Input structure`：
  - bg = 最常见颜色（如 black）。网格分为左右两个区域，由一列 grey 像素分隔。
  - 左侧区域包含一个由单一颜色（如 maroon）绘制的空心轮廓形状（目标容器），轮廓内部为 bg。在轮廓的左上角内侧有一个 1 像素的 red 标记点，表示容器内部坐标系的原点 (0,0)。
  - 右侧区域散布着若干小型彩色碎片（2×2 至 4×4），每个碎片使用一种独特颜色绘制主体。每个碎片内部恰好包含两个特殊像素：一个 red 像素和一个 green 像素。red 像素在碎片内的相对位置编码该碎片在目标容器中的"行偏移"（red 像素距碎片顶边的行数 = 碎片放入容器后距原点的行数）；green 像素在碎片内的相对位置编码"列偏移"（green 像素距碎片左边的列数 = 碎片放入容器后距原点的列数）。

- `Rule`：
  - 第一层推理：识别左侧容器的内部区域和原点标记，建立目标坐标系。
  - 第二层推理：对每个右侧碎片，读取 red 像素的行内相对位置得到目标行号，读取 green 像素的列内相对位置得到目标列号。
  - 将碎片（移除 red 和 green 标记像素后，标记位置改为碎片主体颜色）放置到容器内部对应坐标处。碎片不重叠，恰好填满容器内部。
  - 输出为仅包含填充完毕的容器区域（含轮廓），紧凑裁切。

- `Key insight`：碎片内的 red 和 green 像素不是装饰，而是用各自在碎片内部的相对位置分别编码行和列的"放置坐标"——解题者必须发现这种一维位置到坐标的映射关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
