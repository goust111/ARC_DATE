- `description`：根据边框颜色链式查找源精灵，将源精灵的形状印入目标框架内部，印入时使用框架自身的边框颜色。

- `Input structure`：
  - bg = black。网格中散布若干大小不同的矩形框架（hollow rectangles），每个框架由单一颜色的一像素宽边框构成，内部为 bg。
  - 框架外另有若干小型实心精灵（sprites），每个精灵由一种颜色绘制，形状各异（L形、T形、十字等），尺寸严格小于所有框架的内部空间。
  - 每个精灵的颜色与恰好一个框架的边框颜色相同；每个框架的内部左上角有一个单像素标记点（marker），其颜色与某个精灵的颜色相同。

- `Rule`：
  - 第一步（链式查找）：对每个框架 F，读取其内部标记点的颜色 C_marker。找到颜色为 C_marker 的那个精灵 S——这就是 F 的"源精灵"。
  - 第二步（形状印入）：将源精灵 S 的形状（保持原始朝向，不旋转不翻转）居中放置到框架 F 的内部区域。印入时，精灵的所有像素使用框架 F 自身的边框颜色而非精灵原色。
  - 第三步（清理）：移除框架外所有原始精灵和框架内部的标记点。

- `Key insight`：框架内部的标记点颜色是一个间接指针，指向另一个精灵作为形状模板；最终印入的颜色却由框架自身决定——颜色查找和颜色着色是解耦的两步推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
