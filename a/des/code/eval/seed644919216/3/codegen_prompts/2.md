- `description`：识别网格中多条彩色路径的交叉点，并根据交叉处两条路径的颜色混合规则生成新颜色标记。

- `Input structure`：
  - 背景为 azure。
  - 网格中有若干条单像素宽的4-连通路径，每条路径用一种唯一颜色绘制（如 red、green、yellow、blue 等）。
  - 路径之间可能交叉：交叉点处像素颜色为两条路径中某一条的颜色（即被后绘制的路径覆盖）。
  - 网格左上角有一个小的"混合表"：一个 N×N 的矩阵（N 为路径数量），行头和列头各标记了一种路径颜色，矩阵单元格中填有一种结果颜色，表示该行颜色与该列颜色交叉时应产生的输出颜色。

- `Rule`：
  - 首先识别所有路径：每种非背景、非混合表颜色构成一条4-连通路径。
  - 找到所有交叉点：交叉点是这样的像素——它属于路径 A，但其4-邻居中恰好有两个属于路径 B（且 B 的两个邻居分别在该点的对侧，即一个在上一个在下，或一个在左一个在右），说明路径 B 穿过该点。交叉点处实际存储的颜色是 A 或 B 之一。
  - 判断交叉点涉及的两条路径颜色（通过查看该点及其4-邻居可确定：该点沿水平方向的两个邻居属于同一颜色路径，沿垂直方向的两个邻居属于另一颜色路径）。
  - 在混合表中查找这两种颜色对应的结果颜色，将交叉点像素替换为该结果颜色。
  - 非交叉像素保持不变，混合表保留在输出中。

- `Key insight`：交叉点的检测需要空间推理（判断两条路径确实穿越同一点而非仅仅相邻），而交叉后的颜色并非简单覆盖，而是需要查表获取——解题者必须先发现交叉检测的几何条件，再发现混合表的查表机制。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
