- `description`：在棋盘格状的网格中，根据每个区块内"指针"像素的朝向，从相邻区块借用图案并旋转后填入。

- `Input structure`：
  - 网格被 maroon 色的单像素宽网格线均匀划分为 K×K 个等大的正方形区块（例如每个区块 5×5 像素）。
  - 每个区块要么包含一个彩色图案（由若干非 black、非 maroon 像素组成的形状，背景为 black），要么只包含一个"指针"——指针是一个由 3 个同色像素组成的 L 形标记（一个拐角像素加两个分别沿水平和垂直方向延伸的像素），其 L 形开口朝向上、下、左、右四个方向之一。
  - 包含图案的区块没有指针；包含指针的区块没有图案（内部其余为 black）。

- `Rule`：
  - 对每个含指针的区块，确定指针 L 形的开口朝向 D（上/下/左/右）。
  - 沿方向 D 找到相邻的区块（跨过 maroon 网格线），该相邻区块必定包含一个图案。
  - 将该图案复制到指针所在区块中，但需要旋转：如果指针开口朝上，则图案不旋转（0°）；朝右旋转 90°顺时针；朝下旋转 180°；朝左旋转 270°顺时针。
  - 旋转后的图案替换指针区块的内容（指针本身被移除）。
  - 包含原始图案的区块保持不变。

- `Key insight`：指针的朝向承载双重信息——既指示"从哪个方向的邻居借图案"，又决定"借来的图案旋转多少度"。解题者需要先识别 L 形指针的朝向约定（开口方向而非臂方向），再发现朝向与旋转角度的对应关系，这两步都不平凡。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
