- `description`：在一个包含多层嵌套边框的网格中，根据边框的颜色序列推断几何变换指令，对最内层图案依序执行变换。

- `Input structure`：
  - 背景色为 black。
  - 网格中包含若干组嵌套的彩色矩形边框。每组由 2 到 4 层单像素宽的矩形边框组成，层层嵌套（外层包裹内层），每层边框颜色不同。
  - 最内层边框包围的区域内有一个小型彩色图案（sprite），颜色与所有边框颜色均不同。
  - 不同组的嵌套边框在网格上互不重叠。

- `Rule`：
  - 第一层推理（读取变换指令）：从外到内读取每组嵌套边框的颜色序列。该颜色序列编码了一系列几何变换操作，每种颜色对应一种固定变换：
    - red = 顺时针旋转 90 度
    - blue = 水平翻转（左右镜像）
    - green = 垂直翻转（上下镜像）
    - orange = 顺时针旋转 180 度
    这个颜色-变换的映射关系需要从训练样例中归纳得出。
  - 第二层推理（依序执行变换）：按从外到内的顺序，将对应的变换依次施加到最内层的 sprite 上。例如外层为 red、内层为 blue，则先将 sprite 顺时针旋转 90 度，再水平翻转。
  - 输出：移除所有嵌套边框，仅保留变换后的 sprite，放置在该组嵌套边框原来最内层区域的中心位置。背景保持 black。

- `Key insight`：边框不是装饰——其颜色序列构成一个"变换程序"，解题者需要先破解颜色与变换的对应关系（从多个样例中归纳），再按嵌套顺序"执行"该程序来变换内部图案。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
