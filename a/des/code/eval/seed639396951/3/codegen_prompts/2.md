- `Input structure`：
  - 背景色为灰色（grey）。
  - 网格中有若干水平的"土壤条"：每条土壤是一段连续的棕色（maroon）水平像素行，长度各异，分布在网格的不同行上。
  - 每条土壤条的正上方一行（紧邻）有一个"种子"：种子是由某种非背景、非棕色颜色构成的小型连通块（1-4个像素），形状各异（如单像素、水平两像素、L形三像素、T形三像素等）。
  - 种子的颜色各不相同（如红色、蓝色、绿色、黄色等），且种子水平居中放置于其对应土壤条的上方。

- `Rule`：
  - 第一步：将每个种子与其正下方紧邻的土壤条配对。
  - 第二步：统计种子的像素数量 N。
  - 第三步：以种子为顶层模板，向下生长 N 层（不含种子本身这一层）。每一层是将种子形状沿水平轴做镜像翻转后、再向左右各扩展一个像素的结果。具体地：第 k 层（k=1,2,...,N）相对于种子的行偏移为 k，其图案为种子形状水平镜像后左右各外扩 k 个像素的版本，颜色与种子相同。
  - 第四步：生长的图案不得超出土壤条的水平范围——任何超出土壤条左右端点的像素被裁剪掉。生长的图案绘制在灰色背景上，覆盖背景像素但不覆盖土壤条本身。
  - 种子保留在原位不变，土壤条也保留不变。

- `Key insight`：解题者需要发现两个非平凡规律——种子像素数决定生长层数（而非土壤条长度或其他属性），以及每层的形状是种子镜像后逐层水平扩展的结果。土壤条的长度起到裁剪边界的作用，进一步隐藏了生长规则，因为不同样例中裁剪效果不同，解题者需要区分"被裁剪"和"本来就不生长"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
