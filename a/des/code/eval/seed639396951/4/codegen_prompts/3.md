利用网格中箭头精灵指示的方向和框内种子图案的形状，沿箭头方向逐步"生长"种子图案，每步扩展一层轮廓像素，生长层数由箭头的长度决定。

Input structure:
- 背景色 = black。
- 网格上有若干个小矩形边框（grey 色，宽 1 像素），每个边框内部包含一个由某种颜色绘制的小型种子图案（如 2x2 方块、十字形、L 形等），种子图案不接触边框。
- 每个边框外侧恰好有一个箭头精灵：箭头由一条直线段（水平或垂直）加上末端的一个三角形箭头尖构成。箭头尖由 3 个像素组成，排列方式为：沿直线段方向的最前端 1 个像素加上垂直于直线段方向的两侧各 1 个像素。箭头颜色与对应边框内种子图案颜色相同。箭头尖指向远离边框的方向。箭头的直线段长度（不含箭头尖的 3 个像素）为 N 个像素。

Rule:
- 移除所有 grey 边框和箭头精灵。
- 对每个种子图案，沿箭头指向的方向执行 N 次"定向膨胀"：每次膨胀仅在箭头指向的那一侧（上/下/左/右）为图案当前轮廓添加一层新像素（颜色与种子相同）。具体来说，若箭头朝右，则每次膨胀将图案最右边每个像素的右邻居（若为背景色）设为种子颜色。
- 膨胀后的图案留在种子的原始位置，向箭头方向单侧扩展。
- 若两个图案膨胀后重叠，重叠像素保留先膨胀完成的图案颜色（即按种子图案从上到下、从左到右的顺序依次处理）。

Key insight: 解题者需要同时归纳两层规则——第一层是箭头长度编码生长步数，第二层是生长方向为单侧定向膨胀而非四面膨胀。箭头的颜色匹配机制将箭头与种子配对，而箭头朝向和长度分别编码了膨胀的方向和次数。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
