- `Input structure`：
  - bg = 最常见颜色（如 black）。
  - 若干条彩色直线路径段（水平或垂直），每条路径由单一非bg颜色绘制，长度≥3像素。路径之间互不交叉、互不接触。
  - 若干"信号条"散布在网格边缘区域（不与任何路径接触）。每个信号条是一个 1×3（水平）或 3×1（垂直）的小条，由三个不同颜色的像素依次排列组成。每个信号条的三个像素颜色中，恰好有一个颜色与网格中某条路径的颜色相同。

- `Rule`：
  - 第一层推理——信号与路径配对：每个信号条中包含一个与某条路径颜色匹配的像素，将该信号条与该路径配对。每条路径恰好配对一个信号条。
  - 第二层推理——操作轴确定：信号条的排列方向决定被操作路径的方向约束——1×3水平信号条操作水平路径，3×1垂直信号条操作垂直路径。
  - 第三层推理——操作类型：在信号条的三个像素中，匹配颜色像素的位置决定操作类型。若匹配色在首位（水平条的左端或垂直条的上端），则路径从起始端（水平路径的左端、垂直路径的上端）截去1个像素；若匹配色在末位（水平条的右端或垂直条的下端），则路径从末端截去1个像素；若匹配色在中间位，则路径两端各延伸1个像素。
  - 输出中信号条被移除，路径按操作结果重新绘制，其余内容不变。

- `Key insight`：每个信号条是一个三重编码器——通过颜色匹配确定目标、通过朝向确定操作轴、通过匹配色在条中的位置确定操作类型——解题者需逐层解码这三重信息才能确定对每条路径的变换。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
