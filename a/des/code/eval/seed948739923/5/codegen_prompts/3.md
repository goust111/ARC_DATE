- `description`：利用网格边缘的"指令条"对中央图案的每一行或每一列独立执行平移操作，实现图案的扭曲变形。
- `Input structure`：
  - 背景色为 black。
  - 网格中央有一个由多种颜色组成的矩形图案（约 6×6 至 10×10），图案内部有明显的彩色花纹。
  - 网格的顶部边缘有一行"指令条"：该行的某些格子被涂上了 orange 色，其余为背景色。orange 像素的位置编码了平移信息。
  - 网格的左侧边缘有一列"指令条"：该列的某些格子被涂上了 azure 色，其余为背景色。
- `Rule`：
  - 第一层规则（需要归纳）：顶部指令条中，每个 orange 像素的列坐标对应中央图案的对应列。数出每段连续 orange 像素的长度 L，该长度就是对应列需要向下循环平移的格数。若某列在指令条中无 orange 像素，则该列不平移。
  - 第二层规则（需要归纳）：左侧指令条中，每个 azure 像素的行坐标对应中央图案的对应行。连续 azure 像素段的长度就是该行需要向右循环平移的格数。
  - 执行顺序：先执行列平移（按顶部指令），再执行行平移（按左侧指令）。循环平移意味着移出图案边界的像素从另一侧重新出现。
  - 输出网格仅包含变形后的中央图案（裁剪到图案的原始边界框大小），指令条不出现在输出中。
- `Key insight`：解题者首先需要发现边缘的彩色像素不是装饰而是指令编码，然后需要归纳出"连续像素段长度 = 平移量"这一映射规则，最后还需要发现列平移和行平移是按特定顺序依次执行的（而非同时执行），顺序不同会导致完全不同的结果。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
