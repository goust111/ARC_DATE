<new_puzzle>
- `description`：根据封闭区域内部"种子"精灵的朝向，选择对应的外部模板精灵填入该区域，并按种子指示的方向旋转模板。
- `Input structure`：
  - 背景色（black）占大部分网格。
  - 一组 grey 线条将网格划分为若干不规则的封闭区域（区域大小约 5×5 至 8×8）。
  - 每个封闭区域内部有一个由单一颜色绘制的小型"种子"精灵（3~4 个像素），形状为 L 形。L 形有四种朝向（开口朝上/下/左/右），每种朝向使用不同颜色（如 red、blue、green、yellow 四种颜色之一）。
  - 网格外围（grey 墙壁之外的边缘区域）放置着若干小型模板精灵，每个模板精灵的颜色与某种种子颜色相同，形状各不相同（非 L 形），大小约 3×3 至 4×4。
- `Rule`：
  - 第一步：通过颜色匹配，将每个区域内的种子与网格边缘的同色模板精灵配对。
  - 第二步：根据种子 L 形的开口朝向决定旋转量——开口朝右为 0°，开口朝下为顺时针 90°，开口朝左为 180°，开口朝上为顺时针 270°。
  - 第三步：将配对的模板精灵按该旋转量旋转后，居中放入对应封闭区域内（替换掉种子精灵），颜色保持模板精灵的原色。grey 墙壁和边缘模板在输出中保持不变。
- `Key insight`：种子的颜色决定"用哪个模板"，种子 L 形的开口朝向决定"怎么旋转模板"——两层信息编码在同一个小精灵中，需要解题者分别归纳颜色匹配规则和朝向-旋转映射规则。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片沿各自颜色对应的"轨道线"滑动到终点，碎片之间在轨道交叉处按先后顺序叠放。
- `Input structure`：
  - 背景色为 black。
  - 网格中有若干条由不同颜色绘制的单像素宽路径线（如 red 线、blue 线、green 线），每条线从网格的一条边出发，经过若干转弯，终止于网格内部的一个特殊标记点（该标记点用 maroon 像素标注）。路径线之间可能存在交叉（交叉点处两种颜色重叠，显示为 grey）。
  - 每条路径线的起始端（靠近网格边缘的一端）附近放置着一个与该路径同色的小型碎片精灵（约 2×3 或 3×2 像素的不规则形状）。碎片不在路径上，而是紧邻路径起点。
- `Rule`：
  - 每个碎片沿其同色路径从起点端滑向 maroon 终点端。碎片的左上角锚定在路径像素上，沿路径逐格移动。
  - 碎片最终停在路径的 maroon 终点处（碎片左上角对齐终点像素）。
  - 滑动后，路径线本身被擦除（变回背景色），只保留到达终点位置的碎片和 maroon 终点标记。
  - 若两条路径的终点相邻或重叠区域有碎片像素冲突，按路径长度从短到长的顺序决定优先级——路径越短的碎片画在最上层（后绘制，覆盖先前的像素）。
- `Key insight`：解题者需要先识别出路径线与碎片的颜色配对关系，然后理解碎片是沿路径"传送"到终点而非简单平移，最后发现交叉处的 grey 像素其实是两条路径的叠加，从而正确还原每条独立路径的走向。
</new_puzzle>

<new_puzzle>
- `description`：利用网格边缘的"指令条"对中央图案的每一行或每一列独立执行平移操作，实现图案的扭曲变形。
- `Input structure`：
  - 背景色为 black。
  - 网格中央有一个由多种颜色组成的矩形图案（约 6×6 至 10×10），图案内部有明显的彩色花纹。
  - 网格的顶部边缘有一行"指令条"：该行的某些格子被涂上了 orange 色，其余为背景色。orange 像素的位置编码了平移信息。
  - 网格的左侧边缘有一列"指令条"：该列的某些格子被涂上了 azure 色，其余为背景色。
- `Rule`：
  - 第一层规则（需要归纳）：顶部指令条中，每个 orange 像素的列坐标对应中央图案的对应列。数出每段连续 orange 像素的长度 L，该长度就是对应列需要向下循环平移的格数。若某列在指令条中无 orange 像素，则该列不平移。
  - 第二层规则（需要归纳）：左侧指令条中，每个 azure 像素的行坐标对应中央图案的对应行。连续 azure 像素段的长度就是该行需要向右循环平移的格数。
  - 执行顺序：先执行列平移（按顶部指令），再执行行平移（按左侧指令）。循环平移意味着移出图案边界的像素从另一侧重新出现。
  - 输出网格仅包含变形后的中央图案（裁剪到图案的原始边界框大小），指令条不出现在输出中。
- `Key insight`：解题者首先需要发现边缘的彩色像素不是装饰而是指令编码，然后需要归纳出"连续像素段长度 = 平移量"这一映射规则，最后还需要发现列平移和行平移是按特定顺序依次执行的（而非同时执行），顺序不同会导致完全不同的结果。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中多个"容器"对象的缺口位置和内部标记颜色，从外部颜色库中选取匹配颜色的"液体"精灵，通过缺口方向将液体灌入容器内部。
- `Input structure`：
  - 背景色为 black。
  - 网格中有 2~4 个由 grey 像素绘制的矩形"容器"轮廓（每个约 5×5 至 7×7）。每个容器的四条边中恰好有一条边存在一个 2 像素宽的缺口（缺口位置不固定，可能在任意一侧的任意位置）。
  - 每个容器内部的中心位置有一个单像素标记，标记颜色各不相同（如 red、blue、green 等）。
  - 网格的空白区域散布着若干小型彩色精灵（每个约 2×3 像素），每个精灵由单一颜色绘制，精灵颜色与某个容器内部标记颜色相同。同一颜色可能有多个精灵，但形状各不相同。
- `Rule`：
  - 第一步：将每个容器的内部标记颜色与外部同色精灵匹配。
  - 第二步：在同色精灵中，选择能恰好通过容器缺口的那个精灵——即精灵在缺口平行方向上的尺寸不超过缺口宽度（2 像素）。若需要旋转 90° 才能通过缺口则进行旋转。
  - 第三步：将选中的精灵放置在容器内部，紧贴缺口对面的内壁。精灵的朝向由缺口方向决定：缺口在顶部，精灵贴底部内壁；缺口在右侧，精灵贴左侧内壁；以此类推。
  - 输出中，内部标记像素被精灵覆盖（如果位置重叠），外部未被选用的精灵保留在原位，容器轮廓不变。
- `Key insight`：解题者需要同时归纳三层非显然规则：颜色匹配确定候选精灵集合，缺口宽度约束筛选出唯一可行精灵，缺口方向决定精灵在容器内的放置位置和朝向。任何一层遗漏都无法正确还原输出。
</new_puzzle>

<new_puzzle>
- `description`：根据每个彩色区域的"邻域签名"（与之相邻的其他颜色的组合）在输出中重新着色，使具有相同邻域签名的区域获得相同的新颜色。
- `Input structure`：
  - 背景色为 black。
  - 网格被划分为若干个不规则的连通区域（类似地图着色），每个区域为单一颜色，共使用 4~5 种非背景颜色（如 red、blue、green、yellow、orange）。区域之间通过 4-邻接（上下左右）相邻。
  - 网格右侧或底部有一个小型"色卡"面板，面板由 grey 边框包围。面板内有若干行，每行展示一种"邻域签名模式"：左侧是一个新颜色的色块（如 maroon 或 azure），右侧紧跟 1~3 个小色块，表示该签名所包含的邻居颜色集合。
- `Rule`：
  - 第一步：对网格中每个彩色连通区域，找出它的所有 4-邻接相邻区域的颜色集合（去重后排序），形成该区域的"邻域签名"。区域自身的颜色不计入签名。
  - 第二步：在色卡面板中，找到与该区域邻域签名匹配的条目（右侧小色块集合与签名完全一致的那一行）。
  - 第三步：将该区域重新着色为色卡条目左侧对应的新颜色。
  - 输出中，色卡面板被移除（变为背景色），网格中所有区域均已按新颜色重绘。black 背景和区域的形状、边界完全不变。
- `Key insight`：解题者需要先发现区域的重新着色不取决于区域本身的原始颜色，而取决于它"被哪些颜色的区域包围"——这是一个关于拓扑邻接关系的规则。然后需要发现色卡面板是一个查找表，将邻域签名映射到新颜色。两层归纳缺一不可：一层是"签名 = 邻居颜色集合"，另一层是"签名通过色卡映射到新颜色"。
</new_puzzle>
