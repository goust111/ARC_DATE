- `Input structure`：
  - 背景色为黑色（Black）。
  - 网格边缘（第一行、最后一行、第一列、最后一列）上分布着若干单像素的彩色"信号塔"，颜色从以下集合中选取：Red、Blue、Yellow。每个信号塔的位置不在四个角上。
  - 网格内部完全为黑色背景（输入时）。
  - 网格的某些行和某些列上有 Grey 像素组成的完整横线或竖线，作为"屏蔽墙"。

- `Rule`：
  - 第一层推理——射线发射：每个位于上/下边缘的信号塔沿其所在列向网格内部发射一条垂直射线（从边缘朝向网格中心方向）；每个位于左/右边缘的信号塔沿其所在行向网格内部发射一条水平射线（从边缘朝向网格中心方向）。射线遇到 Grey 屏蔽墙时终止（不穿过屏蔽墙）。
  - 第二层推理——颜色混合规则：射线本身不可见（不绘制）。只有当两条不同方向的射线（一条水平、一条垂直）在同一个像素交叉时，该像素被填充颜色。若两条射线颜色相同，交叉点为该颜色。若两条射线颜色不同，则按照以下视觉直觉的混合规则：Red + Blue = Magenta，Red + Yellow = Orange，Blue + Yellow = Green。
  - 若某个像素位置有三条或更多射线交叉，只取其中的一条水平和一条垂直射线进行混合（优先选颜色不同的一对以产生混合色；若颜色全同则直接填该颜色）。
  - 信号塔自身保留在输出中，Grey 屏蔽墙也保留。

- `Key insight`：解题者首先要发现只有射线交叉点才产生输出像素（而非射线本身），然后要归纳出颜色混合的映射表——这两层规则缺一不可。屏蔽墙截断射线的机制进一步增加了推理的空间复杂度，使得不能简单地"对每个塔画一条线"就得到答案。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
