- `Key insight`：解题者需要发现双重线索系统——归属色负责"碎片该送往哪个框"，而碎片内归属色像素的几何位置则用于与框内锚点对齐以确定精确的平移量。最终只有 maroon 像素被印入框内，归属色仅充当路由和定位工具，这种"颜色作为元信息而非最终输出"的设计构成核心隐蔽性。

- `description`：网格中的彩色管道网络将"源"容器中的颜色传输到"目标"容器，颜色在管道分叉处只选择最宽的支路流入，最终每个目标容器被填上到达它的颜色。

- `Input structure`：
  - 背景色为 black。网格中有若干由 grey 像素绘制的结构，包括两类：
    - "容器"：grey 围成的小矩形封闭空间（内部为 black 或已填色）。部分容器内部已填有某种非 grey、非 black 的颜色（如 red、blue、green），这些是"源容器"；其余容器内部全为 black，是"目标容器"。
    - "管道"：从容器壁的开口处延伸出去的通道，由两条平行的 grey 墙围成，中间的 black 空隙是流通路径。管道可以水平或垂直延伸，管道宽度（两侧 grey 墙之间 black 空隙的像素数）为 1 到 3 不等。管道可以在 T 形或十字形节点处分叉成多条支路。
  - 每个源容器恰好有一个开口连接管道网络；每个目标容器也各有一个开口。管道网络中不存在环路。

- `Rule`：
  - 第一步（网络追踪）：从每个源容器的开口出发，沿管道通道追踪所有可达的路径和目标容器。
  - 第二步（分流规则）：当管道在分叉节点分成多条支路时，源的颜色只流入通道宽度最大（即 black 空隙截面像素数最多）的那条支路。若存在多条等宽的最宽支路，则颜色同时流入所有这些等宽支路。
  - 第三步（填色）：沿着选定路径追踪到末端的目标容器，将该目标容器的内部全部填上源容器的颜色。若某目标容器无法被任何源到达，则保持 black。
  - 管道本身（grey 墙和中间的 black 空隙）在输出中保持不变，仅目标容器内部被填色。

- `Key insight`：解题者需要先读懂管道网络的连通拓扑，再发现分叉处的"宽度优先"选路规则——不是所有分支都传播颜色，而是只走截面最宽的管道。网络拓扑理解是第一层推理，宽度筛选是第二层推理，二者共同决定最终哪些目标被哪种颜色填充。
</new_puzzle>

  - 右侧区域：一个用 grey 边框围起来的竖直色条表，包含 N 个格子（N 等于左侧形状的数量），每格填一种颜色，从上到下排列。每种颜色恰好与左侧某个形状的颜色相同。最上面一格代表最外层（层级 N），最下面一格代表最内层（层级 1）。

- `Rule`：
  - 第一步（孔洞计数）：对左侧每个彩色形状，数出其内部封闭 black 孔洞的数量 H（H 从 0 开始）。
  - 第二步（层级映射）：孔洞数量为 0 的形状对应层级 1（最内层，即色条表最下面一格），孔洞数量为 1 的对应层级 2（倒数第二格），以此类推，孔洞数量为 H 的对应层级 H+1。验证方式：色条表中从下往上第 (H+1) 格的颜色应与该形状颜色一致。
  - 第三步（同心嵌套重绘）：输出网格仅包含重绘后的同心正方形结构，居于输出网格中央。层级 1（最内层）绘制为 1×1 的实心像素；层级 2 在其外围绘制一圈宽度为 1 像素的正方形边框；层级 3 再在外围绘制一圈；以此类推直到最外层。每层使用该层级对应形状的颜色。
  - 左侧原始形状、grey 分隔线和右侧色条表在输出中均不出现，输出仅有同心正方形结构，背景为 black。

- `Key insight`：色条表看似直接给出了嵌套顺序，但解题者必须先发现"孔洞数量"才是将左侧形状与色条表层级关联的隐藏键。没有孔洞的形状被安排在最内层，孔洞最多的在最外层——孔洞数编码了嵌套深度。两层推理：发现孔洞-层级对应关系是第一层，理解同心嵌套的绘制规则是第二层。

- `description`：网格中由彩色像素构成的直线段在交汇节点处形成一棵树，根据"直行继承、转弯保持"的规则沿树传播颜色，最终将所有路径段重新着色。

- `Input structure`：
  - 背景色为 black。网格中有若干由不同颜色像素（非 black）绘制的直线段（严格水平或严格垂直，宽度为 1 像素，长度至少 2 像素）。
  - 某些直线段的端点与另一条直线段的端点在 4-连通方向上相距恰好 1 像素，二者以此相邻构成 L 形、T 形交汇。每个交汇节点连接 2 或 3 条路径段。
  - 整个路径段网络构成一棵无环的树结构。恰好有一条路径段的一个端点不与任何其他路径段相邻——这个自由端点是"根端"，该路径段是"根段"。
  - 在网格的某个角落（四角之一），有一个 2×2 的实心小方块，其颜色与网格中所有路径段的颜色均不同——这是"根色标记"。

- `Rule`：
  - 第一步（建树）：以根段的自由端点为根，沿路径段交汇网络构建一棵树。每条路径段是树的一条边，交汇节点是分支点。
  - 第二步（根段变色）：根段的颜色变为根色标记（角落 2×2 方块）的颜色。
  - 第三步（颜色继承传播）：从根段向叶节点方向逐层传播颜色。在每个分支节点处，判断父段的方向（水平或垂直）与每个子段的方向：
    - 若子段与父段方向相同（直行延续，如父段水平、子段也水平），则子段继承父段的（可能已被继承修改过的）颜色。
    - 若子段与父段方向垂直（转弯，如父段水平、子段垂直），则子段保持自身原始颜色不变。
  - 第四步（重绘）：按照继承结果，将每条路径段的所有像素重新着色为其最终颜色。根色标记在输出中保持不变，背景保持 black。

- `Key insight`：解题者需要完成三层推理：（1）找到唯一自由端点以识别根段，（2）发现角落色块赋予根段新颜色，（3）发现颜色传播遵循"直行继承父色、转弯保持原色"的规则。直行方向上颜色会链式传播形成长距离染色，而转弯处会阻断传播——这种方向敏感的继承机制是核心难点。

- `Rule`：
  - 第一步（配对与缺口识别）：按颜色将每个印章与其对应边框配对。识别每个边框缺口所在的边（上/下/左/右）。

- `description`：在被少量"污点"打断的棋盘格图案中，修复每个污点为正确的棋盘色，同时在网格的 black 边框上用 green 标记投影出所有污点原始位置的行和列。

- `Input structure`：
  - 网格最外一圈（第 0 行、最后一行、第 0 列、最后一列）全部为 black，构成边框。
  - 边框内部呈现两种颜色（如 blue 和 orange）的标准棋盘格交替图案：任意两个 4-连通相邻的内部像素颜色不同。
  - 在棋盘格内部散布着少量（3 到 6 个）"污点"像素——这些像素的颜色为 red，打破了局部的棋盘交替规则。污点彼此不相邻（任意两个污点之间至少间隔 2 个像素）。

- `Rule`：
  - 第一步（棋盘相位推断）：对每个 red 污点，检查其 4-连通邻居中 blue 和 orange 像素的数量。由于棋盘格的交替性质，多数邻居的颜色就是该位置邻居应有的颜色，而该位置本身应为对立色。即：若邻居中 blue 多于 orange，则该位置应为 orange；若 orange 多于 blue，则该位置应为 blue。
  - 第二步（修复污点）：将每个 red 像素替换为第一步推断出的正确棋盘颜色。
  - 第三步（边框标注）：对于每个原本为 red 污点的位置 (r, c)，在 black 边框上进行标记——将第 0 行第 c 列的像素设为 green，同时将第 r 行第 0 列的像素设为 green。若多个污点共享同一行或同一列，该边框位置仍只设一个 green。
  - 输出网格中棋盘格完整无缺（无 red 像素），black 边框上有 green 标记指示原始污点的列（顶边）和行（左边）。

- `Key insight`：解题者需要三层推理：（1）看出内部的整体结构是一个被少量 red 杂色打断的棋盘格——需要忽略 red 后"脑补"出完整的全局交替模式；（2）发现修复规则依赖邻域多数色的对立色来确定正确颜色；（3）注意到 black 边框上出现了新的 green 像素，它们不是随机的，而是污点位置行列坐标的投影。全局模式识别、局部修复规则和坐标投影三层环环相扣。
</new_puzzle>
