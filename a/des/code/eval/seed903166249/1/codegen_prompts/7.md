- `description`：在棋盘格状的双色背景上，识别被"印章"图案覆盖的区域，根据印章下方被遮盖的棋盘格颜色反转印章自身的颜色。

- `Input structure`：
  - 网格由两种颜色（azure 和 orange）交替排列构成标准棋盘格背景（每个格子为 1x1 像素，相邻像素颜色不同）。
  - 网格上叠放了若干"印章"图案，每个印章是一个由单一非背景色（如 red、green、blue、magenta 等）构成的小型连通体（4-连通），完全遮盖了其下方的部分棋盘格像素。
  - 不同印章的颜色各不相同，形状各异，彼此不重叠。

- `Rule`：
  - 第一步：对于每个印章，确定其覆盖区域下方的棋盘格本应是什么颜色。由于棋盘格是完全规则的，可以根据每个像素的行列位置推断其应有的棋盘格颜色（同一行中相邻像素颜色交替，每行的起始颜色也交替）。
  - 第二步：统计每个印章覆盖的像素中，本应为 azure 的像素数（记为 Na）和本应为 orange 的像素数（记为 No）。
  - 第三步：如果 Na > No（即印章下方 azure 占多数），则将该印章的所有像素颜色替换为 orange。如果 No > Na，则替换为 azure。如果 Na == No，印章颜色保持不变。
  - 棋盘格背景中未被印章覆盖的部分保持不变。

- `Key insight`：解题者需要先意识到背景是完美棋盘格、印章遮盖了部分格子，然后推断出被遮盖位置的"隐藏"棋盘格颜色，最后发现印章的新颜色取决于其下方被遮盖较多的那种棋盘格颜色的反面——这要求在不可见信息上做推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
