- `description`：根据框架内部的彩色种子像素，向外生长出颜色交替的同心边框，再依据种子数量裁剪边框层数。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散布若干大小相同的空心矩形框架，框架颜色统一为灰色（grey）。
  - 每个框架的内部区域包含若干彩色种子像素（颜色各异，如 red、blue、green 等），种子像素随机分布在框架内部的黑色背景上。
  - 每个框架内部恰好有两种不同颜色的种子像素。

- `Rule`：
  - 第一步：对于每个框架，识别其内部的两种种子颜色，按种子像素数量从多到少排序，得到颜色序列 [c1, c2]（c1 数量更多）。
  - 第二步：从框架的灰色边界开始，向外逐层扩展同心矩形边框。第一层外框涂 c1，第二层涂 c2，第三层涂 c1……交替循环。
  - 第三步：外扩的总层数等于该框架内部种子像素的总数（两种颜色之和）。
  - 框架本身的灰色边界保持不变。框架内部保持原样（种子像素和黑色背景均保留）。
  - 若不同框架的外扩层发生重叠，后绘制的像素覆盖先绘制的（按框架从左到右、从上到下的顺序处理）。

- `Key insight`：种子颜色的数量比较决定了同心环的颜色交替顺序，而种子总数决定了环的层数——解题者需要同时发现"颜色排序规则"和"计数驱动层数"这两层独立逻辑。
</new_puzzle>

- `description`：将散落的彩色碎片按颜色配对后，以两块碎片的重叠轮廓为模板，在配对中点处印出合并图案。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散布偶数个小型彩色连通体（4-连通），每个连通体由单一非黑色颜色构成，形状各异。
  - 这些连通体可以按颜色配对：每种颜色恰好出现两个连通体，形状不同。
  - 在网格的某个固定位置（如左下角）有一个由黄色（yellow）像素构成的小十字标记，作为输出定位锚点。

- `Rule`：
  - 第一步：按颜色将连通体配对。对于每一对同色连通体 A 和 B，将它们的形状紧凑裁剪为最小包围矩形内的二值掩码。
  - 第二步：将 A 的掩码与 B 的掩码左上角对齐后叠加（逻辑或），得到合并掩码。合并掩码中同时属于 A 和 B 的像素（逻辑与的部分）涂为该对的原始颜色；仅属于 A 的像素涂为灰色（grey）；仅属于 B 的像素涂为白色（azure）。
  - 第三步：将所有配对的合并掩码按原始颜色在色谱中的顺序（red < blue < green < magenta < orange < maroon）从左到右水平排列，间隔一列黑色，整体锚定于黄色十字标记的右上方。
  - 原始网格中的所有连通体和黄色标记保留不变。

- `Key insight`：解题者必须先识别颜色配对关系，再理解叠加操作中"交集/差集"的三色编码含义，最后发现排列顺序由颜色本身在样例中的相对位置（可从多个样例的输出排列归纳）决定。

- `description`：在由墙壁分隔的房间网格中，根据每个房间内箭头的指向，将箭头颜色传递到相邻房间，直到碰到已着色房间为止，最终每个房间获得唯一填充色。

- `Input structure`：
  - 背景为黑色（black）。
  - 灰色（grey）像素构成一个规则的网格状墙壁系统，将整个网格划分为大小相等的矩形房间（例如每个房间内部为 5x5）。
  - 部分房间内包含一个由单一颜色绘制的箭头图案。箭头由一个 3x1 或 1x3 的矩形"杆"加上一个三角形"头"构成，头部指向上、下、左或右四个方向之一。不同房间的箭头颜色各不相同。
  - 其余房间内部全为黑色（空房间）。

- `Rule`：
  - 第一步：识别每个含箭头房间的箭头颜色和指向方向。
  - 第二步：从每个箭头房间出发，沿箭头指向方向，穿过墙壁进入相邻房间。如果该相邻房间是空房间，则将其整个内部填充为箭头的颜色，然后继续沿同一方向传递到下一个相邻房间，重复此过程。
  - 第三步：传递在以下情况停止：(a) 到达网格边界外；(b) 遇到一个已经包含箭头的房间（该房间不被覆盖）；(c) 遇到一个已经被其他箭头填充过的房间（该房间不被覆盖）。
  - 箭头房间本身保持原样（箭头图案不变）。墙壁保持灰色不变。
  - 处理顺序：所有箭头同时发射（若两个箭头同时到达同一空房间，则该房间填充为两种颜色中在输入网格中位置更靠左上方的箭头颜色）。

- `Key insight`：解题者需要先识别箭头的绘制方式以确定方向，然后理解颜色沿箭头方向的"射线传播"机制以及碰撞停止规则——方向判断和传播终止条件是两层需要归纳的规律。
</new_puzzle>

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中包含一个大型连通"锁"图案，由蓝色（blue）像素构成，形状近似矩形但在边缘处有若干矩形缺口（凹槽），每个缺口的形状和大小各不相同。
  - 网格中另有若干小型"钥匙"连通体，每个钥匙由一种独特的非蓝、非黑颜色构成（如 red、green、orange、magenta 等）。每把钥匙的形状恰好与锁上某个缺口互补——即钥匙旋转 0/90/180/270 度后可以精确填满某个缺口。
  - 钥匙数量与缺口数量相等，且一一对应。

- `Rule`：
  - 第一步：对每个缺口，找到与之形状互补的钥匙（可能需要旋转 0/90/180/270 度）。互补的判定标准是：将钥匙的紧凑掩码放入缺口的紧凑包围框后，钥匙像素恰好填满缺口中的所有黑色空位，不多不少。
  - 第二步：将匹配的钥匙（经适当旋转后）平移到缺口位置，填入缺口，像素颜色为钥匙的原始颜色。
  - 第三步：对于锁图案中与该缺口直接相邻（4-连通共享边）的所有蓝色像素，将它们的颜色也改为该钥匙的颜色。这一着色仅扩展一层——即只有直接与被填入钥匙像素相邻的蓝色像素变色，更远处的蓝色像素保持不变。
  - 原始钥匙在其初始位置被移除（替换为黑色背景）。

- `Key insight`：解题者先要通过形状互补关系（含旋转）完成钥匙-缺口的配对，这已经需要空间推理；然后还需发现第二层隐含规则——插入钥匙后，钥匙颜色会"感染"锁上与缺口直接接触的一层蓝色像素，这是从多个样例中才能归纳出的非显然效果。

- `description`：识别网格中由不同颜色线段围成的封闭区域，按区域的边数（三边、四边、五边等）分类，然后用图例指定的颜色填充区域内部。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干条不同颜色的直线段（水平或垂直，宽度为 1 像素），线段由 red、blue、green、orange、magenta 等颜色绘制。
  - 这些线段相互交叉或端点相接，在网格上围成若干封闭区域。每个封闭区域的边界由多条线段拼接而成。
  - 网格的某个角落（例如右下角）有一个"图例区"：若干小的填充色块从上到下排列，每个色块左侧有一条由灰色（grey）像素构成的短横线，短横线的长度（像素数）代表边数。例如长度为 3 的短横线旁边的色块为 yellow，意为三边区域填充黄色。

- `Rule`：
  - 第一步：找出所有由线段围成的封闭区域。一个封闭区域的"边数"定义为其边界上参与构成该区域的线段数量（一条连续同色线段算一条边）。
  - 第二步：查阅图例区，找到每个边数对应的填充颜色。图例中灰色短横线的像素长度即代表该行对应的边数。
  - 第三步：将每个封闭区域内部（不含边界线段本身）的所有黑色像素填充为该边数对应的颜色。
  - 边界线段保持原色不变。图例区保持不变。未被封闭的开放区域不做任何处理。

- `Key insight`：解题者需要先"数边"——即正确识别每个封闭区域由几条独立线段围成，然后通过图例区的长度-颜色映射完成查表填色。数边本身需要区分"同一条线段经过交叉点后是否仍算同一条边"（判断标准是颜色是否连续相同），而图例查表则是第二层需要归纳的对应关系。
</new_puzzle>

- `description`：将网格中的彩色路径按交叉点拆分为独立线段，根据每段的长度在对应端点处生成等长的垂直分支。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干条彩色路径，每条路径由单一颜色的像素构成（如 red、blue、green 等），宽度为 1 像素，仅沿水平或垂直方向延伸。
  - 不同颜色的路径在某些位置交叉（共享同一像素位置）。交叉点处的像素颜色为黄色（yellow），标记交叉。
  - 每条路径的两个末端（非交叉点的端点）处有一个由灰色（grey）像素构成的 1x1 方块标记。

- `Rule`：
  - 第一步：以黄色交叉点为分隔，将每条彩色路径拆分为独立线段。每条线段是两个端点（灰色标记或黄色交叉点）之间的连续同色像素序列。
  - 第二步：计算每条线段的长度（像素数，不含端点标记）。
  - 第三步：在每条线段的灰色端点处（如果有的话），沿与该线段垂直的方向生长一条同色分支。分支的长度等于该线段的长度。分支方向的选择规则：优先向下（对于水平线段）或向右（对于垂直线段）；如果该方向会碰到已有像素，则反向生长。
  - 黄色交叉点处不生长分支。灰色端点标记保留。原始路径保留。

- `Key insight`：解题者首先需要理解黄色像素是交叉分隔符而非路径的一部分，据此正确拆分线段并计算长度；然后需要发现分支生长的方向选择规则（垂直于原线段、有优先方向）和长度等于原线段长度这两个独立规律。
</new_puzzle>

- `description`：在棋盘格状的双色背景上，识别被"印章"图案覆盖的区域，根据印章下方被遮盖的棋盘格颜色反转印章自身的颜色。

- `Input structure`：
  - 网格由两种颜色（azure 和 orange）交替排列构成标准棋盘格背景（每个格子为 1x1 像素，相邻像素颜色不同）。
  - 网格上叠放了若干"印章"图案，每个印章是一个由单一非背景色（如 red、green、blue、magenta 等）构成的小型连通体（4-连通），完全遮盖了其下方的部分棋盘格像素。
  - 不同印章的颜色各不相同，形状各异，彼此不重叠。

- `Rule`：
  - 第一步：对于每个印章，确定其覆盖区域下方的棋盘格本应是什么颜色。由于棋盘格是完全规则的，可以根据每个像素的行列位置推断其应有的棋盘格颜色（同一行中相邻像素颜色交替，每行的起始颜色也交替）。
  - 第二步：统计每个印章覆盖的像素中，本应为 azure 的像素数（记为 Na）和本应为 orange 的像素数（记为 No）。
  - 第三步：如果 Na > No（即印章下方 azure 占多数），则将该印章的所有像素颜色替换为 orange。如果 No > Na，则替换为 azure。如果 Na == No，印章颜色保持不变。
  - 棋盘格背景中未被印章覆盖的部分保持不变。

- `Key insight`：解题者需要先意识到背景是完美棋盘格、印章遮盖了部分格子，然后推断出被遮盖位置的"隐藏"棋盘格颜色，最后发现印章的新颜色取决于其下方被遮盖较多的那种棋盘格颜色的反面——这要求在不可见信息上做推理。
</new_puzzle>
