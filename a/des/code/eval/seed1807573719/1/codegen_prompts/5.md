Input structure:
- 背景色为黑色（black）。网格中有若干个矩形"窗户"，每个窗户由单像素宽的彩色边框围成（不同窗户边框颜色不同）。
- 每个窗户内部有一个由另一种颜色绘制的小图案（3x3 至 5x5 大小），图案不一定对称。
- 窗户之间互不重叠，且间距至少 2 像素。

Rule:
- 第一步：分析每个窗户内部图案的对称性类型：
  -- 若图案仅有水平对称轴（左右镜像对称），标记方向为"上下"。
  -- 若图案仅有垂直对称轴（上下镜像对称），标记方向为"左右"。
  -- 若图案同时有水平和垂直对称轴（双轴对称），标记方向为"四方"。
  -- 若图案无任何对称轴，不绘制箭头。
- 第二步：根据标记方向，在窗户外侧对应方位绘制箭头。箭头由边框同色像素绘制，形状为：沿指向方向延伸 2 像素的线段，末端左右各加 1 像素形成箭尖（即末端为 3 像素的横排或竖排，加上 2 像素的杆）。
  -- "上下"方向：在窗户正上方和正下方各画一个箭头，箭头位于边框顶边和底边的中点外侧，分别指向上和下。
  -- "左右"方向：在窗户正左方和正右方各画一个箭头，箭头位于边框左边和右边的中点外侧，分别指向左和右。
  -- "四方"方向：在窗户四个方位各画一个箭头。
- 箭头起点紧贴窗户边框外侧中点位置。

Key insight: 解题者需要先识别每个内部图案属于哪种对称性类别（这不是直接可见的，需要心理旋转或翻转来验证），然后将对称性类型映射到箭头方位——对称轴的方向与箭头的方向是垂直关系（水平对称轴对应上下箭头），这一映射本身也需要从样例中归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
