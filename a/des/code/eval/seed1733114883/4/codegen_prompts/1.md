- `Input structure`：
  - 背景色（bg）为最常见颜色。
  - 网格中散布若干由 grey 像素围成的封闭矩形区域（边框为 grey，内部为 bg）。
  - 每个封闭区域内部有一个由某种非 bg、非 grey 颜色绘成的小型"种子图案"（3-6 个像素组成的连通体），该图案整体呈现一个视觉方向——即图案的像素分布明显偏向某一侧（例如像素集中在左侧则朝左，集中在上方则朝上）。具体判定方式：将种子图案的像素集合投影到其最小包围盒中心，比较上/下/左/右四个半区各自的像素数，像素最多的半区即为图案的"朝向"方向。
  - 不同区域内种子图案的颜色可以不同。

- `Rule`：
  - 第一步：对每个封闭区域，确定其内部种子图案的朝向方向 D（上/下/左/右）和像素总数 N。
  - 第二步：从该封闭区域的 grey 边框在方向 D 上的外侧中点开始，沿方向 D 向外绘制一条长度为 N 个像素的直线段，颜色与种子图案相同。若线段遇到网格边界则截断。
  - 封闭区域本身和种子图案在输出中保持不变。

- `Key insight`：种子图案同时编码了两个信息——其像素分布的偏向确定了藤蔓生长方向，其像素数量确定了藤蔓长度。解题者必须先发现方向编码规则，再发现长度编码规则，两层推理缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
