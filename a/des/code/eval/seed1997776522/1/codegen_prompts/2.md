沿着彩色路径行走，在每个拐弯处根据转向方向在外侧播种颜色标记，播种颜色与转向方向相反。

Input structure:
- bg = black。网格中有一条由 green 像素构成的单像素宽的 4-连通路径（无分叉），路径从网格的某一条边的像素出发，蜿蜒后终止于另一条边的像素。
- 路径的起点（靠近网格边缘的端点，若两端都在边缘则取行号更小的，行号相同则取列号更小的）旁边恰好有两个紧贴的彩色像素：一个 red、一个 blue，分别位于起点相对于路径初始前进方向的左侧和右侧。

Rule:
- 从路径起点出发，确定初始前进方向（沿路径走向下一个 green 像素的方向）。根据起点旁 red 和 blue 的位置确定"左色"和"右色"：若 red 在前进方向左侧则左色 = red、右色 = blue，反之亦然。
- 沿路径逐格行走。每当路径发生 90 度转弯时，判断是左拐还是右拐。
- 若左拐：在拐弯格的右侧（外侧）紧邻的背景格上放置"左色"像素。
- 若右拐：在拐弯格的左侧（外侧）紧邻的背景格上放置"右色"像素。
- 即播种颜色与转弯方向相反——左拐播右侧但用左色，右拐播左侧但用右色。
- 若外侧目标格已被非背景色占据，则跳过不播种。
- 路径本身和起点旁的 red/blue 标记保持不变。

Key insight: 起点旁的两色标记定义了左右颜色约定，但播种规则是"反向"的——左拐时在外侧（右侧）播左色，右拐时在外侧（左侧）播右色。解题者必须先从标记推断左右颜色映射，再发现转弯方向与播种颜色之间的反转关系，这两步归纳缺一不可。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
