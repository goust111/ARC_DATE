- `description`：在被分隔线划分的网格中，每个单元格内的"种子像素"按照相邻单元格的内容决定生长方向，最终填充出完整图案。

- `Input structure`：
  - 网格被 maroon 色的单像素宽分隔线划分为 N×N 个大小相同的正方形单元格（例如每个单元格 5×5）。
  - 大部分单元格完全为背景色 black。
  - 少数单元格中包含 1-3 个非背景色的"种子像素"，每个种子像素位于单元格内部的某个位置。
  - 网格的最上方一行单元格和最左方一列单元格是"指令行/列"：这些单元格内部包含简单的方向指示图案——一条从单元格中心出发的短线段（2-3 像素长），指向上、下、左、右四个方向之一，用 azure 色绘制。

- `Rule`：
  - 第一层推理：识别指令行和指令列。每个非指令单元格的位置由其所在的列对应的指令列单元格和所在的行对应的指令行单元格共同控制。
  - 第二层推理：列指令给出水平生长方向（左或右），行指令给出垂直生长方向（上或下）。两个方向合成一个对角方向（例如"右"+"下"= 右下方向）。
  - 第三层推理：对于每个含种子像素的单元格，从每个种子像素出发，沿合成的对角方向逐像素填充（颜色与种子相同），直到碰到单元格边界为止。
  - 输出为完成填充后的整个网格，分隔线和指令单元格保持不变。

- `Key insight`：种子像素的生长方向并非由自身位置决定，而是由该单元格在网格中的行列坐标所对应的两个远端指令单元格交叉指定——解题者必须发现行指令和列指令的"交叉查表"机制。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
