- `Input structure`：
  - 背景色为 black。
  - 网格中有若干独立的"转盘"结构，每个转盘由以下部分组成：
    - 一个由某种非背景色（如 red、blue、green 等）绘制的正方形环形轨道（边长 5-7 像素的正方形轮廓，1 像素宽）。
    - 轨道上有一个 1 像素的缺口（该位置为 black 而非轨道色），缺口位于轨道的某条边上。
    - 轨道内部（被轨道包围的区域）有一个由多种颜色组成的非对称图案，图案占据内部的部分格子（其余为 black）。
  - 在网格的某个角落有一个"颜色-数字图例"：若干行排列，每行是一个 1×1 的彩色像素后跟 1-3 个 yellow 像素，彩色像素的颜色与某个转盘轨道颜色相同，yellow 像素的数量表示一个数值。

- `Rule`：
  - 第一层推理——读取旋转量：在图例中找到与每个转盘轨道颜色匹配的行，该行的 yellow 像素数量即为旋转步数 N。
  - 第二层推理——确定旋转方向：缺口的位置决定旋转方向。缺口在顶边或右边 → 顺时针旋转；缺口在底边或左边 → 逆时针旋转。
  - 第三层推理——执行旋转：将转盘内部的图案视为一个小网格，围绕其中心顺/逆时针旋转 N 个 90°（即 N mod 4 次 90° 旋转）。旋转后的图案放回轨道内部。
  - 轨道本身（包括缺口）在输出中保持不变。图例区域在输出中被移除（变为 black）。

- `Key insight`：解题者需要同时从两个不同来源提取信息——图例提供旋转量，缺口位置提供旋转方向——然后将两者结合施加到内部图案上。单看图例或单看缺口都无法完整确定变换。缺口作为方向编码器的角色是最隐蔽的一层，因为它看起来像是轨道的"损坏"而非信息载体。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
