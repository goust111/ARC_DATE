- `Input structure`：
  - 背景色 bg（黑色）填充整个网格。
  - 灰色（grey）线条将网格分成若干大小相同的矩形分区（如 6x6 或 8x8 的分区），灰色线条为单像素宽的完整行和列。
  - 部分分区内有一个单独的彩色种子像素（位于分区内部某处），种子颜色来自有限的颜色集合（如红色、蓝色、绿色、黄色）。
  - 网格的一个角落（如左上角）有一个颜色-形态图例区：图例区包含若干小方格，每个方格左侧是一个颜色像素，右侧是一个 3x3 的二值形态模板（用 maroon 表示填充、bg 表示空），展示该颜色对应的生长模板。
- `Rule`：
  - 根据每个种子像素的颜色，在图例中查找其对应的 3x3 形态模板。
  - 以种子像素为中心，将 3x3 模板盖印到分区中（模板中心对齐种子位置）。
  - 然后以第一次盖印产生的每个新像素为中心，再次盖印同一模板，如此迭代扩展，直到生长区域到达分区的灰色边界为止。
  - 所有生长的像素颜色与种子颜色相同。
  - 若同一分区内有两个不同颜色的种子，两者同时生长；当一方的生长区域遇到另一方已占据的像素时停止（先占先得，同步扩展）。
  - 输出中灰色分区线和图例保持不变。
- `Key insight`：颜色不仅仅标识对象，还编码了生长的方向模式——不同颜色产生截然不同的空间填充形态（如十字形扩展 vs 对角线扩展）。解题者需要先破解图例中颜色与模板的映射，再理解迭代生长的机制，最后处理双种子竞争的边界情况。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
