网格中的箭头指示器指向某个目标对象，将目标对象的形状"投影"到箭头的尾部，箭头本身在输出中消失。

Input structure:
- 背景为 Black。网格中散布着若干小型彩色对象（3-8 像素，形状各异，如 L 形、T 形、方块等），每个对象为单一颜色。
- 网格中还有若干由 Azure 像素绘制的箭头指示器。每个箭头由一条 3-5 像素的直线段（箭头柄）加上末端的一个像素偏移构成箭头尖端，箭头整体呈现明确的指向方向（上、下、左、右四个方向之一）。箭头的绘制方式：柄为一条水平或垂直直线，尖端像素位于柄末端沿指向方向前进一格再向垂直于柄的方向偏移一格的位置（形成">"形状的简化箭头）。
- 每个箭头沿其指向方向延伸，在该方向上最先遇到的彩色对象即为该箭头的目标对象。

Rule:
- 对每个箭头，沿其指向方向找到最近的彩色对象作为目标。
- 将目标对象的形状（相对像素模式）复制到箭头尾端（即箭头柄远离尖端的那一端），使得复制图案的最靠近箭头的边缘紧贴箭头尾端。
- 复制图案的颜色取目标对象的颜色（而非箭头的 Azure 颜色）。
- 箭头本身（Azure 像素）在输出中被移除（变为 Black）。
- 原始目标对象保持不变。

Key insight: 解题的第一层推理是识别箭头的结构并判断其指向方向；第二层推理是发现箭头指向的目标对象的形状被"反向投射"到箭头尾部——箭头不是标记目标，而是将目标的形状搬运到自己的反方向末端。解题者需要先理解箭头的方向语义，再归纳出形状复制的放置规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
