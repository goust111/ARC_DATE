- `description`：在棋盘式分区中，根据每个分区内"种子"像素与分区边界的相对位置，从种子向最近的边界方向生长出与种子同色的矩形色块，色块的大小由同一分区内另一个标记物的面积决定。

- `Input structure`：
  - 背景色为 black。
  - 网格被 maroon 色的单像素宽网格线均匀分割成若干大小相同的矩形分区（如每个分区 6×6 或 7×7 内部空间）。
  - 每个分区内部恰好包含两个对象：
    1. 一个单像素的"种子"，颜色为 red、blue、green 或 yellow 之一，位于分区内部的某个位置。
    2. 一个由 azure 色绘制的小型连通块（1~6 个像素），形状不规则，位于分区内部的另一个位置。

- `Rule`：
  - 第一层推理——确定生长方向：对每个分区，观察种子像素的位置。找到种子距离分区四条内边界（上、下、左、右）中最近的那条边界，该方向即为生长方向（若有并列则选择优先级：上 > 右 > 下 > 左）。
  - 第二层推理——确定生长尺寸：计数同一分区内 azure 连通块的像素数量 A。在生长方向上，从种子出发绘制一个宽 1 像素、长 A 像素的色条（使用种子的颜色），色条从种子位置向最近边界方向延伸。若色条长度超出分区边界则截断到边界。
  - 种子像素本身被色条覆盖（色条包含种子所在位置）。azure 连通块保持不变。maroon 网格线保持不变。

- `Key insight`：azure 块看似装饰，实则其面积编码了生长长度；种子的位置看似随机，实则其与边界的相对关系决定了生长方向——解题者需要同时发现"位置→方向"和"面积→长度"两条独立的编码规则，二者共同决定最终输出。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
