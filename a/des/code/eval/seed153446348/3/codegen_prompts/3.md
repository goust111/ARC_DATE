description：在被部分遮挡的棋盘格图案中，利用可见方格推断遮挡物下方的棋盘相位，然后根据遮挡物颜色在图例中的指示决定是还原棋盘还是用遮挡物颜色永久覆盖。

Input structure：
- 网格呈现一个由两种颜色（如 azure 和 yellow）交替组成的棋盘格图案，每个格子大小为 NxN（N 通过观察可得，通常为 2 或 3）。
- 棋盘上放置了若干矩形遮挡物，每个遮挡物是一个实心单色矩形（使用 red、green、blue 等颜色），完全覆盖了其下方的棋盘格子。
- 在网格的某个角落（如右下角），有一个小的颜色图例区域，背景为 black，其中列出了每种遮挡物颜色对应的操作标记——标记为该颜色像素组成的一行，像素数量为 1 表示"完全移除该遮挡物，还原下方棋盘"，像素数量为 2 表示"移除遮挡物，但将下方棋盘格子全部替换为该遮挡物的颜色"。

Rule：
- 第一步：从可见的棋盘区域推断完整棋盘的相位（即哪些位置应该是 azure，哪些应该是 yellow），包括被遮挡区域下方的原始颜色。
- 第二步：读取角落图例，确定每种遮挡物颜色的处理方式——像素数为 1 表示还原，像素数为 2 表示永久覆盖。
- 第三步：对每个遮挡物，根据其颜色在图例中的指示执行操作——要么还原为下方棋盘色，要么用遮挡物颜色永久覆盖该区域。
- 输出网格尺寸与输入相同，图例区域保持不变。

Key insight：第一层推理需要从棋盘的可见部分推断遮挡区域下方的原始图案（相位恢复），第二层推理需要破译图例中的编码来决定每个遮挡物是"揭开"还是"印上"——两种操作产生截然不同的输出，且必须正确解读图例才能区分。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
