<new_puzzle index="3">
- `description`：利用网格中的"种子像素"生长出图案，生长方向由种子周围的箭头指示像素决定，生长步数由同色种子的数量决定。
- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干组彩色像素。每组由以下部分构成：
    - 一个"种子像素"：某种非背景色（如 red、blue 等）的单个像素。
    - "方向指示像素"：与种子像素在四方向（上下左右）上直接相邻的、颜色为 green 的像素。每个种子至少有一个 green 邻居，green 邻居所在方向即为该种子的生长方向（可以有多个方向）。
  - 同一颜色的种子可能有多个，分布在网格不同位置。

- `Rule`：
  - 第一层：对每种非背景、非 green 的颜色 C，数出颜色为 C 的种子像素的总数量 N。
  - 第二层：对每个颜色 C 的种子，沿其 green 邻居指示的每个方向，从种子位置出发，连续绘制 N 个像素（用颜色 C 填充），覆盖背景色像素。如果射线在 N 步之内碰到网格边界或非背景像素，则在该处停止（不覆盖非背景像素）。
  - 输出中 green 方向指示像素被移除（还原为背景色），种子像素保留，新生长的射线像素以种子颜色绘制。

- `Key insight`：green 像素是方向编码器而非装饰；同色种子的全局计数决定了每条射线的长度——解题者必须先"数种子"获得长度参数，再"看绿色"获得方向参数，两步信息来源完全不同。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。

8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
