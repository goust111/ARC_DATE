- `description`：根据边框颜色与内部碎片的对应关系，将散落的碎片拼回正确的边框内部，并按边框缺口方向决定碎片的旋转角度。
- `Input structure`：
  - 背景为 black。
  - 网格中分布着若干不同颜色的矩形空心边框（hollow rectangular frames），每个边框的四条边中恰好有一条边存在缺口（一段连续的背景色像素断开了边框线）。
  - 边框内部全部为背景色（空白）。
  - 边框外部散落着若干由非背景色像素组成的小型连通图案（碎片），每个碎片的颜色与某个边框的颜色相同。
  - 每个碎片的形状恰好能填满对应边框的内部区域（碎片面积等于边框内部面积），但碎片可能需要旋转 0°/90°/180°/270° 才能正确放入。

- `Rule`：
  - 第一层：通过颜色匹配，将每个碎片与对应的边框配对（碎片颜色 = 边框颜色）。
  - 第二层：确定每个边框的缺口方向（上/下/左/右），缺口方向编码了碎片需要旋转的角度：上=0°，右=90°，下=180°，左=270°。将碎片按此角度旋转后，放入边框内部区域（碎片左上角对齐内部区域左上角）。
  - 输出中，碎片从原来的散落位置消失，出现在对应边框内部；边框本身和缺口保持不变。

- `Key insight`：颜色匹配只是第一步；边框缺口的方位不仅仅是视觉装饰，而是编码了碎片旋转角度的隐藏图例——解题者必须发现"缺口在哪一侧"与"碎片旋转几个90°"之间的固定映射关系。
</new_puzzle>

- `description`：将网格中的多个彩色连通区域按照"谁包围谁"的嵌套层级关系重新着色，最外层用第一种颜色，每深入一层换下一种颜色，颜色顺序由独立的色带图例指定。
- `Input structure`：
  - 背景为 black。
  - 网格顶部有一行水平色带（color strip），由若干不同颜色的连续段组成，从左到右排列（例如：red-red-blue-blue-green-green-yellow-yellow），每种颜色占若干像素宽。
  - 网格下方主区域包含多个闭合环形轮廓（用 grey 像素绘制），这些环形轮廓彼此嵌套——最外层的大环包围着较小的环，较小的环又包围着更小的环，形成多层嵌套结构（类似同心环）。各环之间不相交、不共享像素。
  - 环形轮廓内部和环形轮廓之间的空间全部为背景色。

- `Rule`：
  - 第一层：识别色带中颜色从左到右的顺序，建立层级→颜色的映射（第1种颜色对应最外层，第2种对应次外层，依此类推）。
  - 第二层：分析主区域中的 grey 环形轮廓，确定嵌套层级关系。最外层的环（不被任何其他环包围的）为第1层，被恰好一个环包围的为第2层，以此类推。
  - 第三层：将每个环的 grey 像素替换为其层级对应的颜色（根据色带顺序）。同时，将每层环与下一层环之间的背景区域也填充为该层环的颜色。最内层环的内部区域填充最内层的颜色。
  - 输出中，色带被移除，只保留重新着色后的主区域。

- `Key insight`：色带不是装饰而是颜色分配的图例；解题者需要先从嵌套拓扑中提取层级信息，再将层级映射到色带指定的颜色序列上——两步推理缺一不可。
</new_puzzle>

- `description`：利用网格中的"种子像素"生长出图案，生长方向由种子周围的箭头指示像素决定，生长步数由同色种子的数量决定。
- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干组彩色像素。每组由以下部分构成：
    - 一个"种子像素"：某种非背景色（如 red、blue 等）的单个像素。
    - "方向指示像素"：与种子像素在四方向（上下左右）上直接相邻的、颜色为 green 的像素。每个种子至少有一个 green 邻居，green 邻居所在方向即为该种子的生长方向（可以有多个方向）。
  - 同一颜色的种子可能有多个，分布在网格不同位置。

- `Rule`：
  - 第一层：对每种非背景、非 green 的颜色 C，数出颜色为 C 的种子像素的总数量 N。
  - 第二层：对每个颜色 C 的种子，沿其 green 邻居指示的每个方向，从种子位置出发，连续绘制 N 个像素（用颜色 C 填充），覆盖背景色像素。如果射线在 N 步之内碰到网格边界或非背景像素，则在该处停止（不覆盖非背景像素）。
  - 输出中 green 方向指示像素被移除（还原为背景色），种子像素保留，新生长的射线像素以种子颜色绘制。

- `Key insight`：green 像素是方向编码器而非装饰；同色种子的全局计数决定了每条射线的长度——解题者必须先"数种子"获得长度参数，再"看绿色"获得方向参数，两步信息来源完全不同。
</new_puzzle>

- `description`：在一个被分隔线划分的网格中，每个子区域内有一个彩色图案和若干标记点；根据标记点的位置关系对图案施加镜像变换，再根据相邻区域的图案颜色关系决定是否交换区域内容。
- `Input structure`：
  - 背景为 black。
  - 网格由 grey 单像素宽的水平线和垂直线分隔成若干大小相等的矩形子区域（cell），形成规则的行列网格布局。
  - 每个子区域内部包含：
    - 一个由某种非背景、非 grey 颜色（如 red、blue、yellow 等）组成的小型图案（占据子区域内的部分像素）。
    - 恰好一个 maroon 像素作为标记点，位于子区域内部的四个角落之一（左上/右上/左下/右下）。

- `Rule`：
  - 第一层（局部镜像）：每个子区域中，maroon 标记点所在的角落决定了镜像轴的位置。标记在左上或右下角→沿主对角线（左上-右下）翻转该区域的图案；标记在右上或左下角→沿副对角线（右上-左下）翻转该区域的图案。翻转后 maroon 标记点被移除。
  - 第二层（配对交换）：翻转完成后，检查每对水平相邻的子区域。如果左侧区域的图案颜色与右侧区域的图案颜色相同，则交换这两个区域的图案内容（图案位置互换）。若不同则保持不变。
  - 输出保留 grey 分隔线，子区域内显示最终变换结果。

- `Key insight`：maroon 标记点的角落位置不是随意的，它编码了对角线翻转的类型；但仅完成翻转还不够——翻转后颜色一致的相邻区域会发生内容交换，这第二层规则需要从多个样例中额外归纳发现。
</new_puzzle>

- `description`：根据网格中"路径"的拐弯模式在一张颜色查找表中检索对应颜色，然后用该颜色填充路径所围成的封闭区域。
- `Input structure`：
  - 背景为 black。
  - 网格右上角有一个小型颜色查找表（lookup table）：一个由 grey 边框围起的 N×N 小网格，每个格子填充不同颜色。查找表的行和列分别对应从 0 到 N-1 的索引。
  - 网格主区域中有若干由 grey 像素绘制的闭合路径（每条路径是一个单像素宽的封闭环，内部全为背景色）。
  - 每条路径形状为直角多边形（仅有水平和垂直线段，所有拐弯都是 90°）。

- `Rule`：
  - 第一层（提取路径特征）：对每条闭合路径，分别计数其"左拐弯"数量和"右拐弯"数量。沿路径顺时针行走时，向左转为左拐弯，向右转为右拐弯。对于任何简单直角多边形闭合路径，顺时针行走时的左拐弯和右拐弯数量之和为路径的总角数。
  - 第二层（查表映射）：以左拐弯数量作为行索引、右拐弯数量作为列索引，在右上角的查找表中检索对应颜色。
  - 第三层（填充）：将路径内部的背景区域填充为查找表检索到的颜色。路径本身的 grey 像素保持不变。
  - 输出中查找表被移除。

- `Key insight`：封闭路径的形状差异不只是视觉装饰——左拐和右拐的分别计数构成了一个二维索引坐标，用于在查找表中定位填充颜色。解题者需要先发现"拐弯方向分类计数"这个非显然的特征提取方式，再发现它与查找表的行列对应关系。
</new_puzzle>

  - 输出中尺寸图例被移除，只保留主区域。

- `Key insight`：散落像素既通过颜色编码归属关系，又通过数量编码尺寸信息——解题者需要先完成"按颜色分组并计数"的归属推理，再发现"计数值=图例中的正方形边长"的映射关系，最后执行居中放置。三个层级的推理环环相扣。

<new_puzzle>
- `description`：从网格中的多对"源-靶"色块推断颜色替换规则，然后将该规则应用到一个大型混合色图案上，同时按照特定空间掩码选择性地执行替换。
- `Input structure`：
  - 背景为 black。
  - 网格上半部分包含若干个"规则演示对"：每对由一个小正方形色块（源色块，纯色填充）和一个紧邻其右侧的相同大小小正方形色块（靶色块，纯色填充）组成，中间由一列 green 像素分隔。源色块和靶色块颜色不同。不同的规则对展示了不同的颜色替换关系。
  - 网格下半部分左侧有一个较大的矩形图案（混合图案），由多种颜色像素组成，其中部分颜色出现在上方的规则演示对的"源"中。
  - 网格下半部分右侧有一个与混合图案大小相同的掩码图案（mask），由 azure 像素和背景色组成。azure 像素标记了需要执行颜色替换的位置，背景色标记了保持原样的位置。

- `Rule`：
  - 第一层（提取规则）：从上半部分的规则演示对中提取所有颜色映射关系：源色→靶色。
  - 第二层（掩码叠加）：将掩码图案对齐到混合图案上。对于混合图案中每个像素位置：如果掩码对应位置为 azure，且该像素的颜色在规则映射中存在，则将其替换为映射后的靶色；否则保持原色不变。
  - 输出仅包含变换后的混合图案（移除上半部分的规则对和掩码图案）。

- `Key insight`：上半部分不是无关信息而是"颜色翻译词典"；但即使推断出词典，也不能全局替换——右侧的 azure 掩码限定了替换范围。解题者需要同时发现"词典"和"掩码"这两个独立的控制机制，并理解它们如何协同作用。
</new_puzzle>
