根据每个对象"影子"的投射方向推断全局光源位置，再为缺少影子的对象补画正确方向和长度的影子。

Input structure:
- 背景色为黄色（yellow）。网格上有若干小型连通对象（每个由 2-5 个像素组成），颜色各异（如红色 red、蓝色 blue、绿色 green 等），称为"实体"。
- 部分实体旁边有一组灰色（grey）像素，形状和实体完全相同但沿某个方向平移了固定距离——这组灰色像素称为"影子"。影子始终位于实体的同一侧（所有有影子的实体，其影子相对实体的偏移方向相同），偏移距离为 1 或 2 个像素。
- 有些实体没有影子（旁边没有灰色像素）。

Rule:
- 第一步（推断光源方向）：观察所有已有影子的实体，确定影子相对实体的统一偏移方向（如"向右下偏移 1 格"意味着影子中每个像素的坐标 = 实体对应像素坐标 + (1,1)）。所有影子的偏移向量相同。
- 第二步（推断偏移距离）：通过已有影子确认偏移距离（1 或 2）。
- 第三步（补画影子）：为每个缺少影子的实体，按照相同的偏移方向和距离绘制灰色影子。影子像素绘制在实体像素之下（即如果影子位置已被其他实体占据，则该影子像素不绘制）。已有影子的实体保持不变。

Key insight:
解题者必须先从多个"有影子"的实体中归纳出全局一致的偏移向量（方向+距离），然后将同一向量应用于"无影子"的实体——关键在于偏移方向不是直接标注的，需要从多个样例中通过影子与实体的空间关系推断。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
