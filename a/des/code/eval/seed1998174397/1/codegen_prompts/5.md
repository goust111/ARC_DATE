将散落的拼图块按缺口方向和榫头方向互锁拼合，拼合后整体旋转至缺口朝向网格外侧的方向。

Input structure:
- 背景色为黑色（black）。网格中散布若干个 5x5 的彩色方块（每个方块为单一颜色，各不相同，如红色 red、蓝色 blue、绿色 green、黄色 yellow 等）。
- 每个 5x5 方块的四条边之一上有一个 1x1 的缺口（即该边中央的像素缺失，显示为黑色），称为"凹槽"；另一条边（与凹槽所在边不相邻的那条对边）的中央向外凸出一个 1x1 的像素，称为"榫头"。其余两条边平整。
- 缺口和榫头总是位于对边——即如果凹槽在左边，榫头就在右边，反之亦然；如果凹槽在上边，榫头就在下边，反之亦然。

Rule:
- 第一步（配对拼合）：找到榫头方向指向另一块凹槽方向的配对。具体地，如果方块 A 的榫头朝右，方块 B 的凹槽朝左，则 A 的榫头可以插入 B 的凹槽——将 B 放置在 A 的右侧，A 的凸出像素恰好填入 B 的凹口。所有方块恰好形成一条不分叉的链（每块最多一个榫头被连接、一个凹槽被连接）。
- 第二步（整链拼装）：按链的顺序将所有方块无间隙地排列在一起（榫头填入凹槽，方块之间紧密贴合，榫头像素与凹槽像素重合为榫头方块的颜色）。
- 第三步（旋转定向）：观察拼装后的长条形整体，链的首块（只有榫头被连接、凹槽空闲的那块）的凹槽方向决定输出朝向：凹槽朝上则整体不旋转（长条水平排列，首块凹槽在顶部）；凹槽朝左则整体顺时针旋转 90 度；凹槽朝下则旋转 180 度；凹槽朝右则逆时针旋转 90 度。最终输出为旋转后的拼合结果，背景裁切到最小外接矩形。

Key insight:
解题者先要通过凹槽和榫头的方向匹配发现配对规则（第一层推理），再通过链式组装确定排列顺序（第二层推理），最后发现首块凹槽方向控制整体旋转（第三层推理）——三层规则逐步揭示，仅看单个样例难以同时归纳出全部。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
