  - 对每个框架，首先确定缺口所在的边（上、下、左、右）。

  - 副本放置在框架外部，紧邻缺口，其镜像锚点对齐缺口的中心位置。
  - 框架本身、原空腔填充、种子像素均保留不变。

- `Key insight`：缺口方向决定镜像轴，种子颜色决定副本颜色——解题者必须同时推断出"缺口→翻转方向"和"种子→颜色替换"两层独立规则，才能还原变换。

- `description`：在一个包含多个彩色区域和灰色"管道"的网格中，每个区域通过管道将自身颜色"注入"到管道连接的目标格子中，管道交叉处的颜色由多个来源混合决定。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由不同颜色构成的小型实心矩形块（2×2 或 3×3），称为"源头"，每个源头颜色不同，可使用 red、blue、green、yellow、magenta 等。
  - 灰色（grey）像素构成宽度为 1 的正交管道网络，从每个源头的某一边延伸出去。每条管道是连续的灰色像素线（水平或垂直），管道可以转弯（形成 L 形），管道之间可以交叉。
  - 管道的末端（远离源头的一端）是一个黑色背景中的单像素空位（即管道最后一个灰色像素的下一格是黑色）。
  - 有些管道末端的空位被多条来自不同源头的管道共享（交汇点）。

- `Rule`：
  - 从每个源头出发，沿其连接的灰色管道追踪到末端空位。
  - 如果某个末端空位只被一个源头的管道到达，则将该空位填充为该源头的颜色。
  - 如果某个末端空位被恰好两个源头的管道到达，则根据以下固定颜色混合规则填充：red + blue → magenta，red + yellow → orange，blue + yellow → green，red + green → maroon，blue + green → azure。若遇到其他组合（如 magenta + yellow），则填充为灰色。
  - 如果某个末端空位被三个或更多源头到达，则填充为灰色（grey）。
  - 管道本身保持灰色，源头保持不变。

- `Key insight`：解题者首先需要理解管道的拓扑连接（追踪每条管道从哪个源头出发），然后在交汇点需要推断出颜色混合规则。两层推理缺一不可：仅看管道走向不够，还必须归纳出混合映射表。
</new_puzzle>

- `Input structure`：

  - 网格中有多层嵌套的矩形框架，由不同颜色构成（例如最外层为 blue 框架，中间层为 red 框架，最内层为 green 框架）。每层框架是 1 像素宽的矩形边框，框架之间有间隔（至少 1 像素的黑色间隙）。
  - 最内层框架内部包含一个由 yellow 像素构成的小型非对称图案（例如 L 形、T 形等，占据 3-5 个像素）。
  - 每层框架（除最内层外）的外侧恰好有一个由 orange 像素构成的箭头标记。箭头由 3 个像素组成：一个箭杆像素和两个箭头尖端像素，形成一个指向上、下、左或右的箭头。箭头紧贴在该层框架的外边缘。
  - 箭头的绘制方式：若指向上，则为一个竖直像素在下、上方一个像素、上方像素的左右各一个像素构成倒 V 形；指向右则为横向的 > 形，以此类推。

- `Rule`：
  - 从最内层开始，将内层图案复制到下一层框架的内部空间中。
  - 复制时，图案需要按照当前层框架外侧箭头的指向进行旋转：箭头指向上表示不旋转（0 度），指向右表示顺时针旋转 90 度，指向下表示旋转 180 度，指向左表示逆时针旋转 90 度（即顺时针 270 度）。
  - 旋转后的图案放置在该层框架内部的中心位置（若无法精确居中则偏向左上）。
  - 继续向外层重复此过程：取上一步放置好的图案，再根据外层框架的箭头旋转，放入外层框架的内部空间中心。
  - 最终输出中，所有框架保留，箭头保留，每一层框架内部都有一个经过累积旋转的图案副本。

- `Key insight`：解题者需要发现旋转是累积的——每过一层框架，图案会额外旋转一次，最终图案的朝向是所有层箭头旋转角度的叠加。同时必须识别出箭头方向与旋转角度的映射关系以及嵌套框架的层级从内到外的处理顺序。

- `Input structure`：

  - 每条路径的起点处（路径的一个端点）紧邻一个 2x2 的彩色方块（"信号源"），方块颜色各不相同（如 red、blue、yellow 等）。
  - 路径的终点处（另一端点）是一个 1x1 的黑色空位（即路径最后一个灰色像素旁的黑色格子）。
  - 某些路径的中途有"滤波器"节点：路径上的某个灰色像素被替换为 maroon 像素。每条路径上最多有一个滤波器节点。
  - 网格角落有一个 2x2 的颜色转换表：左列两个像素分别为两种输入颜色，右列对应像素为它们经过滤波器后的输出颜色。

- `Rule`：
  - 从每条路径的信号源出发，信号携带源方块的颜色沿灰色路径传播到终点。
  - 如果路径上没有 maroon 滤波器节点，信号颜色不变，在终点空位处放置一个与信号源相同颜色的像素。
  - 如果路径上有 maroon 滤波器节点，信号经过该节点时颜色按照角落转换表进行变换，然后继续传播到终点，在终点放置变换后的颜色。
  - 路径、信号源方块、滤波器节点和转换表均保持不变。

- `Key insight`：解题者需要分三步推理：（1）追踪每条路径的走向确定起点和终点，（2）识别路径上是否存在 maroon 滤波器节点，（3）从角落的转换表中归纳出颜色映射规则。滤波器的存在与否导致同色信号源可能产生不同颜色的输出，这是关键的隐蔽性来源。

- `description`：根据对称轴标记线的形态将网格中的不完整图案补全为对称图形，不同标记线形态对应不同的对称操作。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由不同颜色构成的不完整图案，每个图案占据网格的一个局部区域。
  - 每个图案附近有一条由 azure 像素构成的标记线（长度 3-8 像素），标记线有三种形态：
    - 实线（连续的 azure 像素）：表示沿该线做镜像对称补全。
    - 虚线（azure 像素与黑色间隔交替，即每隔一个像素放一个 azure）：表示沿该线做滑移反射补全（先镜像翻转，再沿标记线方向平移 1 格）。
    - 双线（两条平行的相邻 azure 线）：表示以两线之间的中轴为中心做 180 度旋转对称补全。
  - 标记线始终为水平或垂直方向。每个图案恰好关联一条最近的标记线。

- `Rule`：
  - 对每个不完整图案，找到距离它最近的 azure 标记线。
  - 根据标记线的形态确定对称类型：
    - 实线：将图案沿标记线做镜像翻转，将翻转后的像素填入标记线另一侧的对应位置（不覆盖已有非黑像素）。
    - 虚线：将图案沿标记线做镜像翻转，然后沿标记线方向整体平移 1 像素后填入。
    - 双线：将图案以双线中轴为中心旋转 180 度，填入对应位置。
  - 标记线本身在输出中保留不变。

- `Key insight`：解题者必须先识别出标记线有三种不同形态（实线、虚线、双线），再归纳出每种形态对应不同的对称操作——表面上看所有标记线都是 azure 色，但细微的结构差异编码了完全不同的变换类型。
</new_puzzle>
