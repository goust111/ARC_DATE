- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由不同颜色构成的小型实心矩形块（2×2 或 3×3），称为"源头"，每个源头颜色不同，可使用 red、blue、green、yellow、magenta 等。
  - 灰色（grey）像素构成宽度为 1 的正交管道网络，从每个源头的某一边延伸出去。每条管道是连续的灰色像素线（水平或垂直），管道可以转弯（形成 L 形），管道之间可以交叉。
  - 管道的末端（远离源头的一端）是一个黑色背景中的单像素空位（即管道最后一个灰色像素的下一格是黑色）。
  - 有些管道末端的空位被多条来自不同源头的管道共享（交汇点）。

- `Rule`：
  - 从每个源头出发，沿其连接的灰色管道追踪到末端空位。
  - 如果某个末端空位只被一个源头的管道到达，则将该空位填充为该源头的颜色。
  - 如果某个末端空位被恰好两个源头的管道到达，则根据以下固定颜色混合规则填充：red + blue → magenta，red + yellow → orange，blue + yellow → green，red + green → maroon，blue + green → azure。若遇到其他组合（如 magenta + yellow），则填充为灰色。
  - 如果某个末端空位被三个或更多源头到达，则填充为灰色（grey）。
  - 管道本身保持灰色，源头保持不变。

- `Key insight`：解题者首先需要理解管道的拓扑连接（追踪每条管道从哪个源头出发），然后在交汇点需要推断出颜色混合规则。两层推理缺一不可：仅看管道走向不够，还必须归纳出混合映射表。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
