- `Input structure`：
  - bg = 最常见颜色（Black）。
  - 网格中有若干互不重叠的矩形彩色区域（每个区域为单一颜色填充的实心矩形，颜色各不相同）。
  - 每个矩形区域内部用背景色（Black）挖出一个小型连通形状（即区域内有一个黑色的"孔洞"），孔洞形状为以下三种之一：
    - 水平线段（宽 >= 2，高 = 1）：代表"水平翻转"指令。
    - 垂直线段（宽 = 1，高 >= 2）：代表"垂直翻转"指令。
    - L 形（由一条水平线段和一条垂直线段在端点相连组成的直角形状）：代表"顺时针旋转 90 度"指令。
  - 每个区域恰好有一个孔洞，孔洞不接触区域的边框。

- `Rule`：
  - 对每个彩色矩形区域，识别其内部孔洞的形状类别（水平线段 / 垂直线段 / L 形）。
  - 将该矩形区域（包含孔洞）作为整体，按孔洞指示的变换方式进行几何变换：
    - 水平线段孔洞 -> 将整个区域沿垂直中轴左右镜像翻转。
    - 垂直线段孔洞 -> 将整个区域沿水平中轴上下镜像翻转。
    - L 形孔洞 -> 将整个区域顺时针旋转 90 度。
  - 变换后的区域放回原位（外接矩形中心不变；若旋转导致宽高互换，则以中心为锚点重新放置）。
  - 背景和其他区域不受影响。

- `Key insight`：孔洞不是需要被填补的缺损，而是嵌入在对象内部的"指令编码"。解题者需要先意识到孔洞形状是有意义的符号（而非随机缺失），再将三类形状映射到三种不同的几何变换。指令与执行对象合为一体的设计增加了识别难度。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
