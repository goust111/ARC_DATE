根据封闭区域内部的彩色种子像素确定该区域的"所属颜色"，再利用区域边界上的缺口方向，将该颜色沿缺口方向向外喷射射线，射线宽度等于缺口的像素宽度。

Input structure:
- 背景为 black。灰色 (grey) 像素构成若干封闭的不规则多边形轮廓，每个轮廓的边界上恰好有一个连续缺口（缺口处无灰色像素）。
- 每个封闭区域内部散布着若干同色的非黑非灰像素（如 red、blue、green 等），这些像素的颜色各区域互不相同，作为"种子"标识该区域的所属颜色。
- 缺口总是位于轮廓的正上、正下、正左或正右的某一段边上，且缺口为连续的一段缺失。

Rule:
- 第一步（归纳区域颜色）：对每个灰色封闭轮廓，找到其内部所有非黑非灰像素的颜色，该颜色即为此区域的"喷射颜色"。
- 第二步（确定喷射方向与宽度）：找到轮廓边界上的缺口位置；缺口所在的方向（上/下/左/右）即喷射方向；缺口跨越的像素数即射线的宽度。
- 第三步（绘制射线）：从缺口位置出发，沿缺口方向向外绘制一条宽度等于缺口宽度的直线射线，颜色为该区域的喷射颜色，射线一直延伸到网格边界为止。射线不覆盖灰色像素或其他已有的非黑像素。
- 灰色轮廓和内部种子像素保持不变。

Key insight: 解题者需要先完成"种子颜色→区域归属"的匹配，再独立发现"缺口方向决定喷射方向、缺口宽度决定射线宽度"这一几何编码规则——两步推理缺一不可，且第二步的宽度编码不易从单个样例中确认。
</description>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
