Input structure:
- 背景为 black。若干个由 grey 像素构成的矩形空心框（容器），每个容器内部被统一填充为一种非黑非灰的颜色（如 red、blue、green、yellow 等），不同容器的填充色可能相同也可能不同。
- 容器之间通过 grey 像素构成的单像素宽正交折线管道相连。每条管道连接恰好两个容器（管道的两端分别接触两个不同容器的灰色边框）。
- 每条管道的中间某处有一个非灰非黑的彩色像素替代了原本的灰色管道像素，该像素即为"阀门"。

Rule:
- 第一步（识别结构）：找出所有容器、管道及管道上的阀门。确定每条管道连接的两个容器。
- 第二步（判断激活）：对每条管道，检查其阀门颜色是否与管道两端中恰好一个容器的填充色相同。若匹配则该管道"激活"；若阀门颜色与两端容器都不匹配、或与两端都匹配，则该管道不激活。
- 第三步（执行交换）：对所有激活的管道，同时交换其两端容器的填充色。即：若管道连接容器 A（红色填充）和容器 B（蓝色填充），且阀门为红色（匹配容器 A），则交换后容器 A 变为蓝色填充，容器 B 变为红色填充。
- 所有交换同时发生（不串联）。阀门像素、管道和容器边框保持不变。

Key insight: 解题者需要首先发现管道-阀门-容器的拓扑连接结构，然后独立归纳出"阀门颜色匹配恰好一端才激活"的非对称激活条件（这排除了"两端都匹配"的情况，增加了隐蔽性），最后理解交换是同时执行而非顺序传播。三层推理中，激活条件的精确规则最难从少量样例中确认。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
