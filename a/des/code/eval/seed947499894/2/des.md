- `Input structure`：
  - 背景色（bg）为网格中最常见的颜色。
  - 若干用同一种边框色绘制的矩形空心框架（如 green 边框），每个框架内部包含一个由另一种颜色填充的小型形状（如 L 形、T 形、十字形等），形状各不相同。
  - 在框架外部散布着若干"钥匙"图案：每个钥匙由一个小型形状头部和一条从头部某侧延伸出的单像素短柄组成。钥匙头部的形状与某个框架内的填充形状完全一致（颜色可能不同），短柄的方向（上/下/左/右）指示展开方向。
  - 钥匙头部的颜色各不相同，短柄颜色与头部相同。

- `Rule`：
  - 第一步（匹配）：将每个钥匙的头部形状与框架内部的填充形状做形状匹配（忽略颜色，仅比较形状轮廓），确定该钥匙对应哪个框架。
  - 第二步（展开）：钥匙短柄所指的方向即为展开方向。将匹配到的框架内部所有非背景像素提取出来，从框架原始位置开始，沿展开方向平移复制整个内部图案，每次偏移量为框架在该方向上的尺寸（宽或高），重复复制直到到达网格边缘。展开过程中框架边框不复制，仅复制内部内容。
  - 复制出的内容使用钥匙头部的颜色而非原框架内填充色。

- `Key insight`：解题需要两步非平凡推理——首先通过形状匹配（而非颜色）将钥匙与框架配对，然后从钥匙的短柄方向推断展开方向并用钥匙颜色重绘。形状匹配与方向编码缺一不可。
</new_puzzle>

- `description`：识别噪声遮罩下的隐藏连接关系，利用连接拓扑对区域重新着色，使同一连通分量内的区域颜色一致。

- `Input structure`：
  - 背景色（bg）为最常见颜色（如 black）。
  - 网格中有若干不同颜色的矩形色块，彼此不重叠。
  - 色块之间存在由单一"通道色"（如 grey）绘制的单像素宽通道线段，连接某些色块对。通道线段沿水平或垂直方向延伸，两端分别触及所连接的两个色块边缘。
  - 额外有一种"噪声色"（如 maroon）的散布像素，随机出现在网格的背景区域中。部分噪声像素可能恰好落在通道线段上，将通道打断为不连续的片段。

- `Rule`：
  - 第一步（通道修复与连接识别）：沿每条通道线段的行或列扫描，若一条直线上两端分别触及两个色块、且中间除背景和噪声外只有通道色像素，则认定该通道有效连接这两个色块（忽略噪声造成的断裂）。仅凭通道色片段的共线性和端点邻接判断连接，无需计算距离。
  - 第二步（连通分量着色）：将所有通过有效通道直接或间接相连的色块归为同一组。每组内所有色块统一重绘为该组中面积最大的色块的颜色。通道线段和噪声像素在输出中全部擦除为背景色。

- `Key insight`：噪声像素制造了视觉干扰，解题者必须先识别出"通道被噪声打断但实际仍然有效连接"这一隐蔽规则，再利用连通分量关系确定每组的代表色（最大面积者）。两层推理——修复连接与分组着色——都需要非平凡的归纳。
</new_puzzle>

- `description`：根据种子色块在参考网格中的位置查找对应的变换指令，对主画布上同色对象执行指令所编码的几何操作。

- `Input structure`：
  - 背景色（bg）为最常见颜色。
  - 网格被一条贯穿整行的分隔线（如 grey 色的完整水平线）分为上下两个区域。
  - 上方区域（参考网格）：一个 N x N 的小方阵被更细的分隔线划分为 N x N 个单元格。每个单元格内要么为空（全背景），要么包含一个简单的小图案（如单像素、2x1 横条、1x2 竖条、2x2 方块），图案颜色与单元格所在行列相关。参考网格的第一列的每个单元格内各有一个不同颜色的单像素标记，代表该行对应的颜色。第一行的每个单元格内各有一个小图案，代表该列对应的操作类型：单像素 = 不变、2x1 横条 = 水平翻转、1x2 竖条 = 垂直翻转、2x2 方块 = 旋转 180 度。
  - 下方区域（主画布）：散布着若干较大的多色对象，每个对象使用上述颜色之一作为主体色，对象形状各异。每个对象旁边紧邻一个由另一种颜色绘制的单像素"指令标记"，该标记的颜色也出现在参考网格的第一列中。

- `Rule`：
  - 第一步（查表）：对于主画布上的每个对象，找到其主体色对应的参考网格行（通过第一列颜色匹配），再找到其指令标记颜色对应的参考网格行，取这两行交叉的列。该列第一行的图案编码了操作类型。
  - 第二步（变换）：按查到的操作类型对该对象执行相应的几何变换（不变 / 水平翻转 / 垂直翻转 / 旋转 180 度），对象保持在原位（边界框中心不变）。
  - 指令标记在输出中移除。

- `Key insight`：参考网格是一张二维查找表，行由对象主体色索引、列由指令标记色索引；列头图案形象地编码了几何操作类型。解题者须先理解查找表结构，再将视觉化的操作编码映射为具体变换——两步都需要独立归纳。
</new_puzzle>

- `Input structure`：
  - 背景色（bg）为最常见颜色（如 black）。
  - 网格中有若干由单一轨道色（如 grey）绘制的闭合环形轨道。每条轨道是一个由单像素宽线段组成的矩形环路，沿水平和垂直方向行进。
  - 不同轨道可能在某些位置共享像素（交叉点），交叉点处该像素同时属于两条轨道。
  - 每条轨道上有一个或多个由某种标记色（如 yellow）绘制的单像素标记，标记位于轨道像素上（替换该位置的轨道色）。
  - 每条轨道上恰好有一个由非背景、非轨道、非标记颜色填充的色块（2x2 或 1x1），色块位于轨道的某个直线段上，色块的颜色各不相同。色块相邻的轨道像素表明色块的行进方向：色块沿轨道顺时针方向移动。

- `Rule`：
  - 第一步（计数）：数出色块当前所在轨道上 yellow 标记的数量 K。
  - 第二步（移动）：将色块沿轨道顺时针方向移动 K 步（每步移动一个像素位置）。若色块在移动过程中到达一个交叉点，它必须切换到另一条轨道继续移动（保持前进方向不回头）。
  - 移动后的色块绘制在新位置，原位置恢复为轨道色。标记像素保持不变。

- `Key insight`：解题者需先识别闭合轨道结构与顺时针行进方向，再数出标记数量作为移动步数，最后处理交叉点处的轨道切换。三层结构（方向判定、步数计数、交叉切换）中，轨道切换规则是最隐蔽的一层，需要从多个样例中对比交叉点前后色块的轨道归属才能归纳出来。
</new_puzzle>

- `description`：将散落的碎片根据边缘锯齿形状拼接成完整矩形，再按碎片原始颜色在拼接后的矩形中绘制分界线。

- `Input structure`：
  - 背景色（bg）为最常见颜色（如 black）。
  - 网格中散布着若干不规则形状的碎片，每个碎片由单一颜色填充（各碎片颜色不同）。
  - 每个碎片的一部分边缘是平直的（属于最终矩形的外边缘），另一部分边缘呈锯齿/阶梯状（属于与相邻碎片的拼接缝）。
  - 所有碎片恰好能无缝拼合成一个完整的矩形，锯齿边缘互补咬合。
  - 网格中另有一个由 grey 色绘制的小矩形"色板"，色板被细线分为若干格子，每格填充一种颜色，颜色排列顺序从左到右对应碎片在最终矩形中从左到右的排列顺序。

- `Rule`：
  - 第一步（拼接匹配）：通过碎片的锯齿边缘互补形状，确定哪些碎片彼此相邻。平直边缘朝外的一侧确定了碎片在矩形中的位置（例如左侧平直 = 碎片位于矩形最左列）。
  - 第二步（排列验证）：色板中颜色的左右顺序给出碎片的水平排列约束，用于验证或消除拼接歧义。
  - 第三步（输出绘制）：将所有碎片拼合到一个紧凑矩形中，全部重绘为统一颜色（色板边框色 grey），但在原碎片分界线处（锯齿咬合缝）绘制一像素宽的分界线，分界线颜色为该缝左侧碎片的原始颜色。

- `Key insight`：锯齿边缘的互补匹配是核心视觉推理——解题者需要像拼拼图一样找到凹凸吻合的边缘对。色板提供排列顺序的额外线索。最终输出中碎片被统一着色、仅保留彩色分界线的反转呈现方式增加了从输出反推规则的难度。

- `description`：在网格中识别"发射器-反射镜-接收器"光路系统，光线颜色在每次反射时按照反射镜上的色点变化。

- `Input structure`：
  - 背景色（bg）为最常见颜色（如 black）。
  - 若干"发射器"：位于网格边缘的单像素，颜色各异（如 red、blue 等），表示光线的初始颜色。发射器所在的边缘位置决定光线的初始方向（从边缘向内，水平或垂直）。
  - 若干"反射镜"：由 grey 色绘制的 2 像素长对角线段（占据两个对角相邻的格子），朝向为"\"或"/"，决定光线的反射方向（水平变垂直、垂直变水平）。每个反射镜的两个像素中，其中一个像素上叠加了一个非 grey 的彩色点，该彩色点的颜色称为该反射镜的"变色色"。
  - 若干"接收器"：位于网格边缘的单像素，颜色为 white，等待被光线到达后着色。

- `Rule`：
  - 从每个发射器出发，沿初始方向发射一条光线，光线颜色为发射器颜色。
  - 光线沿直线行进，在经过的每个背景像素上绘制当前光线颜色。
  - 当光线遇到反射镜时，按反射镜朝向改变行进方向（"\"使右行变下行、下行变右行、左行变上行、上行变左行；"/"使右行变上行、上行变右行、左行变下行、下行变左行）。
  - 反射后，光线颜色变为该反射镜上彩色点的颜色，后续绘制使用新颜色。
  - 光线继续行进直到到达网格边缘。若到达接收器位置，接收器像素被染为光线此时的颜色。
  - 若光线到达非接收器的边缘位置，光线终止，不做特殊处理。

- `Key insight`：解题者须同时追踪光线的空间路径（反射镜朝向决定转弯方向）和颜色演变（每次反射后颜色切换为反射镜上的彩色点颜色）。路径追踪本身已是一层推理，颜色随反射变化是隐蔽的第二层——需要从多个样例中观察光线颜色在反射前后的变化才能归纳出变色规则。
</new_puzzle>

<new_puzzle>
- `description`：根据容器内液面高度差驱动连通容器间的液体流动，直到所有相连容器液面持平。

- `Input structure`：
  - 背景色（bg）为最常见颜色（如 azure）。
  - 若干"容器"：由 grey 色绘制的 U 形或矩形杯状结构（底部和两侧有壁，顶部开口），每个容器宽度相同（内部宽 3 像素），高度可能不同。
  - 容器内部底部有若干行像素被填充为某种颜色（如 blue），表示该容器内的"液体"，液面高度即填充行数。不同容器内液体颜色可能不同。
  - 容器之间在底部通过单像素宽的水平"管道"（与容器壁同色 grey）相连。管道连接在两个容器壁底部的同一行高度上。只有管道直接相连的容器之间液体才能流通。
  - 每根管道上有一个"阀门"像素：若阀门颜色为 green，管道开启；若为 red，管道关闭。

- `Rule`：
  - 第一步（识别连通组）：通过开启的管道（阀门为 green）将容器分组——管道开启且直接相连的容器属于同一连通组。关闭的管道（阀门为 red）阻断连通。
  - 第二步（液面均衡）：在每个连通组内，计算所有容器的液体像素总数，然后将液体在组内所有容器间重新均匀分配（从各容器底部开始向上填充）。若总像素数不能被容器数整除，多余的像素优先分配给组内最左边的容器（每个容器最多多分一个像素行乘以容器内宽）。
  - 第三步（颜色混合）：若连通组内存在不同颜色的液体，均衡后的液体统一使用组内出现频次最多的液体颜色。若频次相同，使用组内最左容器的液体颜色。
  - 管道、阀门和容器壁在输出中保持不变。

- `Key insight`：解题者首先需要通过阀门颜色判断管道通断来确定连通组（第一层），然后理解液面均衡的物理直觉——液体总量守恒并在连通容器间平均分配（第二层），最后处理混色规则（第三层）。阀门的开关是最隐蔽的关键——它决定了哪些容器参与均衡。
</new_puzzle>
