- `Input structure`：

  - 网格顶部有一个小矩形图例区域，内部包含若干水平排列的颜色对：每对由两个相邻的 2x1 色块组成（左色块和右色块），颜色对之间用 bg 隔开。

  - 部分封闭边框内部还包含用另一种颜色绘制的小型图案（如十字、L形等），这些内部图案的颜色也出现在图例中。

- `Rule`：
  - 读取图例中的颜色对映射：每对中左色 → 右色、右色 → 左色，形成双向映射。

    1. 找到该边框颜色在图例中的配对颜色。
    2. 将边框颜色替换为配对颜色。
    3. 将边框围成的内部区域（原来为 bg 的像素）全部填充为边框的原始颜色。
    4. 如果内部有小型图案，该图案同样按图例映射替换颜色。
  - 图例区域在输出中被擦除（填充为 bg）。
  - 网格尺寸不变。

- `Key insight`：图例定义了一组颜色互换对，边框与填充之间发生颜色角色反转——边框变成配对色，而边框的原色反而成为内部填充色，形成"颜色身份交换"。解题者需要先从图例归纳出双向映射关系，再理解边框色与填充色之间的反转逻辑。

- `description`：将散落的彩色路径片段按照端口颜色匹配拼接成完整路径，然后沿路径方向逐段涂上渐变色序。

- `Input structure`：
  - 背景色 bg 填充网格。
  - 网格中散布着若干条短的直线段（水平或垂直，长度 3-6 像素），每条线段的主体为 grey，但两个端点各有一个彩色像素（称为"端口"）。
  - 网格某个角落有一个 1 行 N 列的色带（N 等于线段数量），色带中从左到右排列着 N 种不同颜色，这就是渐变色序。
  - 每条线段的两个端口颜色不同；整个网格中，每种端口颜色恰好出现两次（分属两条不同线段），但链条的首尾两端各有一个端口颜色仅出现一次。

- `Rule`：
  - 通过端口颜色匹配将线段首尾相接：线段 A 的某端口颜色 = 线段 B 的某端口颜色 → A、B 在该端连接。
  - 链条的起点是拥有全局唯一端口颜色的那条线段的那个唯一端口一侧；从该端开始，依次遍历所有线段，形成一条有序链。
  - 将所有线段在网格中保持原位，但将第 k 条线段（按链序，k 从 1 开始）的 grey 主体像素重新着色为色带中第 k 个颜色。
  - 端口像素在输出中被擦除为 bg。
  - 色带在输出中被擦除为 bg。

- `Key insight`：端口颜色是线段之间的"握手信号"——相同端口色意味着两条线段在此连接。解题者需要先通过端口配对建立线段的拓扑链序，再利用色带对链上的线段逐一着色。两层推理缺一不可：第一层是端口匹配建链，第二层是链序映射色带。
</new_puzzle>

- `Input structure`：
  - 背景色 bg 填充网格。
  - 网格中有一条 maroon 色的垂直线贯穿整个网格高度，将网格分为左右两半（左半和右半宽度相同，右半足够容纳最大缩放后的形状）。
  - 左半部分包含若干个用不同颜色绘制的封闭形状（实心填充的连通区域，每个形状使用一种颜色，形状各异但都是由若干方块组成的简单多连通体，面积约 3-8 个像素）。
  - 每个封闭形状内部嵌有若干个 red 色的"种子像素"（1x1 的点），种子像素位于形状的像素位置上（即种子像素替换了形状原色的某些像素），数量为 1、2 或 3。

- `Rule`：
  - 对左半部分的每个彩色封闭形状：
    1. 数出该形状中 red 种子像素的数量 N（N = 1, 2, 或 3）。
    2. 将该形状相对于 maroon 对称轴做水平镜像，得到其在右半部分的目标锚点位置。
    3. 在目标位置绘制该形状的缩放版本：N=1 时保持原尺寸（1x），N=2 时每个像素变为 2x2 块（2x 放大），N=3 时每个像素变为 3x3 块（3x 放大）。缩放以镜像后形状的最小包围盒左上角为锚点向右下扩展。
    4. 缩放副本使用与原形状相同的颜色（非 red），不含 red 种子像素。
  - 左半部分的原始形状和种子像素保留不变。
  - maroon 对称轴保留。

- `Key insight`：种子像素表面上像是形状内部的标记点，但它们的数量实际编码了镜像副本的缩放倍率。解题者需要先发现"种子数量 = 缩放因子"这一隐含规则，再理解镜像 + 缩放的组合变换。
</new_puzzle>

- `Input structure`：
  - 网格由一个较大的 MxM 内区域和环绕该区域的单像素宽边框带组成（网格总尺寸为 (M+2)x(M+2)）。

  - 边框带的左边和右边标记行：左边框中某些行位置有非 black 像素，表示"选取该行"。
  - 上边框的标记像素颜色各不相同，左边框的标记像素颜色也各不相同；这些颜色仅用于标识，不影响输出颜色。

- `Rule`：
  - 从上边框中收集所有被标记的列号（即非 black 像素所在的列），按从左到右的顺序排列，共 P 个。
  - 从左边框中收集所有被标记的行号（即非 black 像素所在的行），按从上到下的顺序排列，共 Q 个。
  - 输出网格大小为 Q 行 x P 列。
  - 输出网格的第 (i, j) 个像素颜色 = 内区域中第 i 个被标记行与第 j 个被标记列交叉处的像素颜色。
  - 即输出是内区域按照边框标记抽取对应行和列后形成的子矩阵。

- `Key insight`：边框上的标记不是装饰，而是行列选择器——它们指定了从内区域中抽取哪些行和列。解题者需要先识别边框标记与行列选取的对应关系，然后理解输出是原图案的稀疏采样重组。第一层推理是发现边框标记的"选取"语义，第二层是理解行列交叉形成子矩阵的组装逻辑。

- `description`：识别网格中的"模板区域"和"指令区域"，根据指令区域中彩色像素相对于准星的空间偏移，对模板图案执行多次定向复制与叠加，生成最终图案。

- `Input structure`：
  - 背景色 bg 填充网格。
  - 一条 azure 色的完整水平线将网格分为上下两部分。
  - 上半部分（模板区域）：包含一个用某种颜色 C 绘制的小型连通图案（占据约 3x3 到 5x5 的范围），图案周围为 bg。
  - 下半部分（指令区域）：包含一个用 grey 绘制的十字准星（一个中心像素加上、下、左、右各延伸 1 个像素，共 5 个像素），以及若干个散落的彩色像素点（非 bg、非 grey、非 azure），每个彩色像素点的颜色各不相同。

- `Rule`：
  - 输出网格仅包含下半部分的尺寸（去掉上半部分和 azure 分隔线）。
  - grey 十字准星的中心位置作为输出的"原点"。
  - 在原点处放置模板图案的一份副本（以模板图案的中心与原点对齐），使用模板原色 C。
  - 对指令区域中每个彩色像素点：计算该像素相对于 grey 准星中心的行偏移 dr 和列偏移 dc。在输出中，以 (原点行+dr, 原点列+dc) 为中心放置模板图案的一份副本，并将该副本的颜色替换为该彩色像素的颜色。
  - 叠加时，后放置的副本覆盖先放置的。放置顺序为：先放原色副本（在原点），然后按彩色像素到准星中心的像素步数（先行后列逐行扫描顺序中靠前者优先被覆盖、靠后者后绘制）依次放置。
  - 准星本身不出现在输出中（被图案覆盖或保持 bg）。

- `Key insight`：指令区域中的彩色像素不是图案本身，而是一张"复制指令地图"——每个彩色点的位置（相对于准星中心的偏移）指定了模板副本应被放置的位置，其颜色指定了该副本的着色。解题者需要先识别准星作为参考原点的角色，再理解彩色散点编码的是空间偏移而非图案内容。第一层推理是分离模板与指令的功能角色，第二层是解码偏移映射关系，第三层是理解叠加覆盖的优先级规则。

- `description`：根据封闭围栏内部"钥匙色"与外部"锁对象"的颜色层级匹配关系，将锁对象旋转后放入围栏内部对应位置并重着色。

- `Input structure`：
  - 背景色 bg 填充网格。
  - 网格中有一个用 green 像素绘制的大型封闭矩形围栏（仅围栏边框，宽度为 1 像素，内部为 bg）。
  - 围栏内部在四条边的中点位置各有一个单独的彩色像素（称为"钥匙"），四个钥匙颜色互不相同，且都不是 green。
  - 围栏外部散布着四个小型彩色对象（每个对象是一个约 3x3 的连通形状）。每个对象由两种颜色组成：一种"外层色"构成对象的外围像素（与 bg 相邻的像素），一种"内层色"构成对象不与 bg 相邻的内部像素。
  - 每个外部对象的外层色恰好与围栏内某个钥匙的颜色相同。

- `Rule`：
  - 通过外层色匹配，将每个外部对象与围栏内对应的钥匙配对。
  - 确定每个钥匙在围栏的哪条边上（上、下、左、右）。
  - 将配对的外部对象旋转（0/90/180/270 度），使得对象的外层像素朝向围栏内侧（即：上边钥匙对应的对象旋转到外层在下方、内层在上方；右边钥匙对应的对象旋转到外层在左方、内层在右方；下边钥匙对应的对象旋转到外层在上方、内层在下方；左边钥匙对应的对象旋转到外层在右方、内层在左方）。
  - 将旋转后的对象放置在围栏内部，以钥匙像素的位置为锚点：对象外层中最靠近围栏边的那一行/列像素与钥匙像素所在的行/列对齐，且对象紧贴围栏内壁。
  - 放置后，将对象的外层色全部替换为 green（与围栏同色），仅保留内层色不变。
  - 擦除围栏外部的原始对象。钥匙像素被放入的对象覆盖。

- `Key insight`：钥匙像素是颜色配对的桥梁，同时其在围栏边上的方位编码了对象需要旋转的朝向和放入围栏的入口方向。解题者需要先发现"外层色 = 钥匙色"的匹配规则，再推断出钥匙的方位决定旋转方向，最后理解外层色被围栏色"吸收"的重着色逻辑。三层推理环环相扣。
</new_puzzle>

- `description`：在包含遮挡关系的多层堆叠矩形中，按可见面积大小排序，将完整矩形依序放入右侧的排列槽位中。

- `Input structure`：
  - 背景色 bg 填充网格。
  - 网格左半部分（堆叠区）：包含若干个（3-5 个）不同颜色的实心矩形，它们互相部分重叠，上层矩形覆盖下层矩形的部分像素，形成遮挡关系。每个矩形颜色唯一且不为 bg。
  - 网格右半部分（槽位区）：包含与左侧矩形数量相同的空矩形槽位，每个槽位用 grey 单像素边框绘制，内部为 bg。槽位大小相同（足以容纳最大的矩形），从上到下垂直排列，槽位之间有 bg 间隔。

- `Rule`：
  - 在堆叠区中，对每个彩色矩形计算其可见像素数量（即该颜色在堆叠区中实际可见、未被上层矩形遮挡的像素数）。
  - 按可见像素数量从大到小排序（可见像素最多的排第一）。
  - 将每个矩形的完整形状（包括被遮挡的部分，恢复为完整矩形）按排序顺序依次放入右侧槽位中：排名第一的放入最上面的槽位，排名第二的放入第二个槽位，以此类推。矩形在槽位内左上角对齐。
  - 堆叠区在输出中被清空为 bg。
  - 槽位的 grey 边框保留。

- `Key insight`：排序依据不是矩形的实际大小或图层顺序，而是其在堆叠中的可见面积——这要求解题者先通过颜色边界推断出每个矩形的完整形状和遮挡层次，然后心算每个矩形露出了多少像素。第一层推理是从堆叠区中还原每个矩形的完整尺寸（包括被遮住的部分），第二层推理是发现排序键是"可见面积"而非"总面积"或"图层深度"。
</new_puzzle>
