- `Input structure`：
  - 背景色为 black。
  - 网格被 grey 色的直线（水平和垂直）划分为若干矩形"房间"。
  - 每个房间内部包含：
    - 一个由 2-4 种非背景色像素构成的小型图案（4-连通区域），位于房间的某一侧。
    - 一条 maroon 色的直线段（水平或垂直，1 像素宽），充当"镜子"，位于房间内部将房间分为两半——图案所在的一半和空白的一半。
  - 每个房间的一条 grey 边界上附着若干成对的彩色像素点：每对由两个相邻像素组成，一个位于边界线上（替换原本的 grey），另一个紧邻其内侧（位于房间内部紧贴边界的位置）。这对像素表示颜色映射关系：边界上的像素颜色 A 映射为内侧像素颜色 B。每个房间可能有 1-3 对这样的映射标记。

- `Rule`：
  - 第一步（反射）：将图案以 maroon 镜子线段为对称轴进行镜像反射，在镜子另一侧的空白区域生成反射像。
  - 第二步（颜色重映射）：读取该房间边界上的颜色映射对。对反射像中的每个像素，若其颜色出现在某个映射对的源色（边界上的那个）中，则将其替换为对应的目标色（内侧的那个）。未被映射覆盖的颜色保持不变。
  - 第三步：原始图案保持不变。maroon 镜子线段保持不变。颜色映射标记保持不变。

- `Key insight`：反射本身是直观的几何操作，但解题者需要额外发现边界上的成对像素构成了颜色映射表，并将该映射选择性地应用于反射像而非原像。两层规则——几何反射与颜色重映射——通过镜子和边界标记分别编码，需要独立归纳后组合。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
