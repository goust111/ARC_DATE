- `description`：根据边框内的"种子图案"和边框外的"调色板条"，将种子图案按调色板指定的颜色分层展开为同心嵌套轮廓。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有一个较大的单色矩形边框（如 green），边框内部包含一个小型多色图案（种子图案），由若干不同颜色的像素组成，每种颜色形成一个连通区域。
  - 边框外侧某处有一条水平或垂直排列的"调色板条"：由若干不同颜色的像素紧密排成一行或一列，颜色互不重复，其中包含种子图案中出现的所有颜色。

- `Rule`：
  - 调色板条中颜色的排列顺序定义了"展开优先级"：排在前面的颜色先展开，排在后面的后展开。
  - 对种子图案中的每种颜色区域，按照调色板条中该颜色的顺位依次处理：顺位第 1 的颜色区域保持原位不变；顺位第 2 的颜色区域向外扩展 1 层轮廓（即在该区域的所有外侧相邻黑色像素处填充该颜色）；顺位第 3 的颜色区域向外扩展 2 层轮廓；以此类推，顺位第 N 的颜色区域向外扩展 N-1 层轮廓。
  - 扩展时，后展开的颜色轮廓不会覆盖已有的非黑色像素。
  - 最终输出仅保留种子图案展开后的结果区域（紧凑裁剪），边框和调色板条均被移除。

- `Key insight`：调色板条既编码了颜色集合，又通过排列顺序隐式编码了每种颜色的膨胀层数；解题者需要发现"顺位即膨胀半径"这一非显然映射，再理解多色轮廓的叠放遮挡规则。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片"磁吸"回它们原属的镂空模板中，碎片的旋转角度由形状匹配决定，碎片最终颜色由模板缺口方向上最近的"染色带"决定。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个灰色（grey）的矩形模板，每个模板内部被镂去了一块不规则形状的区域（形成空洞），空洞形状各不相同。每个模板的边框恰好有一处单像素宽的缺口（开口）。
  - 网格中散落着若干个单色小碎片（非灰色、非黑色），每个碎片的形状恰好与某个模板的空洞形状相同（可能需要旋转 0°/90°/180°/270°，但不需要翻转）。
  - 网格中还有若干条水平或垂直的单像素宽"染色带"，每条染色带颜色不同，横跨整个网格宽度或高度。

- `Rule`：
  - 第一步（形状匹配与旋转）：将每个碎片与空洞形状匹配，确定对应的模板。匹配时允许旋转碎片（0°/90°/180°/270°），选择能使碎片恰好填入空洞的旋转角度。
  - 第二步（染色规则）：确定模板缺口所朝的方向（上/下/左/右）。从缺口方向看去，找到该方向上距离模板最近的一条染色带，碎片最终使用该染色带的颜色。
  - 第三步（填充）：将碎片以正确旋转角度和正确颜色填入对应模板的空洞中。碎片原始位置清除为黑色，染色带保留不变。

- `Key insight`：解题包含三层独立推理——先通过形状匹配找到碎片-模板配对，再通过缺口朝向确定"视线方向"以选取染色带颜色，最后执行旋转填充。缺口方向同时编码了碎片的旋转对齐信息和颜色来源方向，这一双重语义是核心难点。
</new_puzzle>

- `description`：在棋盘式网格中，每个彩色方块根据其相邻方块的颜色"投票"结果决定自身变色，平票时由隐藏的优先级图例裁决。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格被等间距的灰色（grey）细线分割为规则的方格阵列（如 5×5 或 6×6 个格子）。
  - 每个格子内部要么为黑色（空），要么被填充为某种非黑非灰的颜色（如 red、blue、green、yellow 等），形成一个彩色方块。
  - 网格外侧的右下角有一个小型"优先级图例"：若干颜色像素从上到下排成一列，表示颜色的优先级排序（最上方优先级最高）。

- `Rule`：
  - 对每个非空的彩色方块，检查其上下左右四个正交相邻格子中非空格子的颜色。
  - 如果相邻的非空格子中存在某一种颜色出现次数严格大于其他任何颜色（即存在唯一众数），则该方块变为该众数颜色。
  - 如果出现平票（两种或以上颜色出现次数相同且并列最多），则查看优先级图例，平票颜色中优先级最高的胜出，方块变为该颜色。
  - 如果一个方块的四个相邻格子全部为空（无邻居），该方块保持不变。
  - 原本为空的格子始终保持为空。
  - 所有方块同时更新（使用输入状态判定，非逐个更新）。

- `Key insight`：解题者首先需要发现"邻居投票决定颜色"这一局部规则，然后需要注意到平票情况下还有一个隐藏的优先级图例作为 tie-breaker。图例的位置和作用不会在第一时间被注意到——只有当解题者遇到投票平局无法解释的样例时，才会回头发现图例的存在和意义。

- `description`：根据网格中"路径"经过"色门"的顺序，查找散落的颜色映射方块，将路径的各段依次染成对应的目标颜色。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有一条由灰色（grey）像素组成的连续单像素宽路径（无分叉、无交叉），路径的两个端点各有一个特殊标记：一端为 maroon 像素（起点），另一端为 azure 像素（终点）。
  - 路径上某些位置的灰色像素被替换为其他彩色像素（如 red、green、blue、yellow 等），这些彩色像素称为"色门"，它们嵌在路径中。
  - 网格中另有若干独立的小型彩色方块（2×2），每个方块的四个像素中：左上角像素为一种颜色（称为"目标色"），其余三个像素为另一种统一颜色（称为"索引色"）。每个方块的索引色与某个色门颜色相同。

- `Rule`：
  - 从起点（maroon）沿路径走向终点（azure），记录沿途经过色门的颜色顺序。
  - 对每个色门颜色，在散落的方块中找到索引色与之匹配的方块，读取其左上角像素的目标色。
  - 路径被色门自然分割为若干段。从起点到第一个色门之间的路径段染为第一个色门对应的目标色；第一个色门到第二个色门之间的段染为第二个色门对应的目标色；以此类推，最后一个色门到终点之间的段染为最后一个色门对应的目标色。
  - 色门像素本身也被染为对应的目标色。起点和终点标记像素保持不变。散落的方块在输出中被移除。

- `Key insight`：解题需要三层推理的串联——第一层是识别路径的走向与起止点，第二层是发现色门将路径分段并记录颜色序列，第三层是发现散落方块是"索引色→目标色"的查找表，将色门颜色映射为实际的染色颜色。三层信息来源在空间上分离（路径、色门、方块），需要将它们关联起来才能得到正确输出。
</new_puzzle>

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个"信号塔"：每个信号塔是一个 3×3 的单色方块（颜色各不相同，如 red、blue、green 等），方块的某一侧正中央向外延伸出一个同色单像素突起（天线），天线突出的方向表示该塔的发射方向（上/下/左/右）。
  - 网格中还散布着若干个 1×1 的灰色（grey）像素，称为"镜面"。每个镜面像素的某个对角相邻位置紧邻一个 maroon 像素，用于标记镜面的朝向：maroon 在镜面的左上方或右下方表示该镜面为"\"方向（将水平光线转为垂直，垂直转为水平，入射方向顺时针旋转 90°）；maroon 在镜面的右上方或左下方表示该镜面为"/"方向（入射方向逆时针旋转 90°）。

- `Rule`：
  - 每个信号塔从天线尖端沿天线方向发射一条单像素宽的光线，光线颜色与信号塔相同。
  - 光线在黑色背景上直线传播，直到遇到以下情况之一：(a) 到达网格边界，光线停止；(b) 遇到镜面像素，光线按镜面朝向反射 90° 后继续传播（光线不会停留在镜面上，而是从镜面位置沿新方向继续）；(c) 遇到信号塔方块本体（3×3 区域），光线停止。
  - 光线经过的所有黑色像素都被染为该光线的颜色。
  - 如果两条或多条不同颜色的光线经过同一个像素，该像素被标记为 yellow。
  - 镜面像素和 maroon 标记像素在输出中保持不变。

- `Key insight`：解题者首先要识别信号塔的结构并推断天线方向编码了发射方向，然后要理解镜面的反射机制（通过 maroon 标记的对角位置判断镜面角度），最后还要发现多光线交汇处的特殊标记规则。难点在于镜面朝向的编码方式不直观——需要从样例中归纳出 maroon 相对位置与反射方向的对应关系。

- `description`：识别网格中被"围墙"包围的封闭区域，根据区域内"钥匙"像素的颜色在对应颜色的围墙上打开缺口，然后将区域内的图案沿缺口方向平移到围墙外。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由单一非黑颜色构成的封闭矩形围墙（如 red 围墙、blue 围墙等），每个围墙是一圈单像素宽的矩形边框，围墙颜色各不相同。
  - 每个围墙内部包含：(a) 一个由灰色（grey）像素组成的小型图案（形状各异）；(b) 恰好一个单独的彩色像素（钥匙），钥匙的颜色与当前围墙颜色不同，但与网格中另一个围墙的颜色相同。
  - 围墙之间互不接触，不重叠。

- `Rule`：
  - 对每个围墙，读取其内部钥匙像素的颜色——该颜色指向另一个围墙（称为"目标围墙"）。
  - 在目标围墙上，找到距离钥匙像素所在围墙最近的那一面墙壁（上/下/左/右四面墙中选择两个围墙之间直线距离最短的那一侧），在该面墙壁的正中央打开一个单像素宽的缺口（移除该位置的围墙像素）。
  - 将钥匙所在围墙内的灰色图案，沿着从该围墙朝向目标围墙的方向（取上下左右中与两围墙中心连线最接近的正交方向）平移出当前围墙。图案被移动到当前围墙外侧紧邻处，图案在原位置被清除为黑色。
  - 钥匙像素在输出中被移除（变为黑色）。围墙的缺口保留。

- `Key insight`：解题涉及两层跨对象推理：第一层是通过钥匙颜色建立围墙之间的配对关系（颜色交叉引用），第二层是钥匙不仅决定了在哪个围墙上开缺口，还隐式决定了图案的平移方向——方向由两个围墙的空间相对位置决定。解题者需要从样例中发现"钥匙颜色=目标围墙"以及"相对方位决定缺口位置和弹出方向"这两条规则的协同作用。
</new_puzzle>

- `description`：将网格中的多个散落"容器"按其内部颜色标记的层级关系组装成嵌套结构，内层容器缩放后嵌入外层容器中 azure 十字标记指定的位置。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散布着若干个矩形"容器"，每个容器由一种独特颜色的单像素宽边框构成（如 red、blue、green、orange 等）。
  - 每个容器内部有一个小型单像素标记点，标记点的颜色与另一个容器的边框颜色相同——表示"本容器应嵌入该颜色容器内部"。没有标记点的容器是最外层根容器。
  - 部分容器内部还有一个由 azure 像素组成的小十字标记（"+"形，由 5 个像素组成：一个中心像素和上下左右各一个像素），标记了嵌入子容器时子容器中心应对齐的位置。

- `Rule`：
  - 通过标记点颜色建立容器的嵌套层级树：标记点颜色指向的容器即为父容器。
  - 从最内层容器开始，逐层向外组装：将子容器（含其已组装的内部内容）等比缩放至恰好能放入父容器内部空间的最大整数倍尺寸（宽和高分别取能放入的最大整数倍，保持原始宽高的像素比例）。
  - 缩放后的子容器中心对齐到父容器内 azure 十字标记的中心位置后放置。放置后，azure 十字标记被子容器覆盖而消失。
  - 标记点在输出中被移除。最终输出为紧凑裁剪后的完整嵌套结构。

- `Key insight`：解题者首先需要通过颜色交叉引用建立嵌套层级树（哪个容器套在哪个里面），然后需要发现 azure 十字标记编码了子容器的放置锚点位置，最后要理解缩放适配规则。三层推理依次递进：层级关系推断→定位锚点识别→缩放适配计算。
</new_puzzle>
