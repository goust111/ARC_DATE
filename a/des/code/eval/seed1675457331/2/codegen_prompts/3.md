  - 模板区包含 2-4 个互不重叠的小型彩色图案（每个图案占据 3x3 到 5x5 的范围，由单一非背景色绘制）。每个图案具有某种对称性：仅水平对称、仅垂直对称、既水平又垂直对称（即具有两轴对称）、或无对称性。
  - 画布区有若干与模板区图案同色的单像素标记点，每个标记点颜色唯一对应一个模板图案。画布区还散布着若干 Maroon 色的小方块（2x2），每个方块与恰好一个标记点正交相邻。

- `Rule`：
  - 第一层推理——对称性分类决定变换：检测每个模板图案的对称性类型：
    - 仅水平对称 -> 将图案上下翻转。
    - 仅垂直对称 -> 将图案左右翻转。
    - 两轴对称 -> 将图案旋转 180 度。
    - 无对称性 -> 图案保持原样不变。
  - 第二层推理——锚点定位与印刻：将变换后的图案以对应颜色标记点为中心印刻到画布上。印刻时，若图案像素与 Maroon 方块重叠，则图案像素优先覆盖 Maroon。Maroon 方块中未被覆盖的像素保持 Maroon 不变。模板区保持原样不变。
  - 第三层推理——Maroon 方块的隐含约束：每个 Maroon 方块指示其相邻标记点的图案印刻后应恰好覆盖该方块的至少一个像素。如果同一标记点周围有多个 Maroon 方块，它们共同约束了图案的正确旋转/翻转选择（当对称性分类产生歧义时，Maroon 方块的位置可用于验证）。

- `Key insight`：图案自身的对称性类型隐含编码了应使用的变换方式——解题者必须先识别每个图案属于哪种对称类别，才能确定正确的变换；这不是直接可见的属性标签，而需要对图案结构进行分析归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
