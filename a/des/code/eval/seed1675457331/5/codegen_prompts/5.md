- `description`：将源区域中的图案沿着同色"导管"路径传送到目标区域，导管上的 red 转弯标记决定图案在传送过程中顺时针旋转的累计角度。
- `Input structure`：
  - bg = 黑色。网格中有若干用彩色边框围成的矩形区域，分为两类：
  - "源区域"：边框内部包含一个彩色图案（sprite），边框颜色各不相同（如 blue、green、orange 等）。
  - "目标区域"：边框内部为空（全 bg），边框颜色与某个源区域的边框颜色相同（颜色一一配对）。
  - "导管"：从每个源区域的边框某侧伸出一条单像素宽的同色路径（像素颜色与该区域边框色相同），沿水平或垂直方向延伸，经过若干次 90 度转弯后连接到对应目标区域的边框上。
  - "旋转标记"：导管每次 90 度转弯处的拐角像素为 red（而非导管颜色），路径上的非转弯像素保持导管颜色不变。
- `Rule`：
  - 对每种边框颜色 C，找到颜色为 C 的源区域和目标区域。
  - 沿导管从源区域追踪到目标区域，统计路径上 red 旋转标记的数量 R。
  - 将源区域的内部图案顺时针旋转 (R mod 4) × 90 度。
  - 将旋转后的图案放入目标区域的内部（左上角对齐）。
  - 输出中导管路径、旋转标记和所有边框均保留不变。
- `Key insight`：边框颜色建立源→目标的配对关系，但解题者还需要沿导管追踪路径，并发现转弯处的 red 像素不仅标示路径走向，更隐含地编码了图案的旋转次数。"颜色配对→路径追踪→计数转弯→旋转图案"构成四层推理链。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
