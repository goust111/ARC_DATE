- `Input structure`：
  - bg = 最常见颜色。
  - 网格中散布着若干组同色像素对：每种非bg颜色恰好出现2个像素，它们要么在同一行，要么在同一列（不会是对角线）。共有若干种颜色，各自形成一对。
  - 网格右下角有一个小型颜色图例区域，由一条grey色边框围成。图例内部从上到下排列若干行，每行包含：左侧一个小矩形色块（面积各不相同，从1到若干个像素），右侧紧邻一个单像素色标。图例中的小矩形面积值互不相同。

- `Rule`：
  - 第一层（建桥）：对每一对同色像素，沿它们共享的行或列方向，在两个像素之间画一条连线（包含两个端点），颜色与该对像素相同。这些连线即为"桥梁"。
  - 第二层（围区域）：所有桥梁加上网格边界共同围成若干个封闭区域。识别每个完全被桥梁和/或网格边界包围的bg区域，计算其面积（bg像素数）。
  - 第三层（图例填色）：在图例中找到面积值等于该区域面积的那一行，用该行右侧色标的颜色填充该封闭区域。若没有匹配的图例条目，则区域保持bg色不变。
  - 输出保留所有桥梁线段和图例，仅填充匹配的封闭区域。

- `Key insight`：同色像素对定义了桥梁的位置，桥梁组合围成的区域面积是查找图例的键——需要先构建桥梁、再识别封闭区域、最后通过面积匹配完成填色，三层推理环环相扣。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
