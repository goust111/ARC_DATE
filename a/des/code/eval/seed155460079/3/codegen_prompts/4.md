- `Input structure`：背景为 Black。网格上半部分有一个"模板库"：若干个小型图案排成一行，每个图案由某种颜色绘制（如 Blue、Green、Red 等），每个图案都是严格的上下对称图形（关于自身水平中轴对称）。网格下半部分散布着若干个与模板库中图案尺寸和形状相近的"目标对象"，每个目标对象使用 Grey 像素绘制，但其中恰好有 1-2 个像素被"破坏"——即被替换成了某个彩色像素（颜色与模板库中某个模板的颜色一致）。每个目标对象原本应该与模板库中的某一个模板形状相同。
- `Rule`：
  1. 对每个目标对象，找到其中被替换的彩色像素，该颜色指向模板库中对应颜色的模板。
  2. 将该模板的形状与目标对象当前的 Grey 像素进行对比，找到目标对象"缺失"的像素位置（模板有但目标对象没有 Grey 像素的位置）和"多余"的像素位置（目标对象有 Grey 但模板对应位置没有的位置）。
  3. 修复目标对象：补上缺失的像素（用 Grey），移除多余的像素（变为 Black），同时将彩色破坏标记像素也恢复为 Grey。最终目标对象变成与匹配模板完全一致的形状，全部为 Grey。
  4. 模板库保持不变。
- `Key insight`：彩色"破坏"像素既是破坏本身，又是指示应该使用哪个模板来修复的线索——解题者需要先识别这一双重角色（颜色编码匹配关系），再通过模板与破损对象的形状对比完成修复，两步推理缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
