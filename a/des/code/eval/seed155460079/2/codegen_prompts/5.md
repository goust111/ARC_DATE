Input structure:
- 背景为黑色。网格被灰色的十字线（一条水平线和一条竖直线贯穿整个网格）分割为四个象限区域。
- 每个象限中有一个由某种颜色绘制的小型非对称图案（"印章"，大小约3×3到5×5像素），位于该象限的某个固定位置（如靠近十字线交叉点的角落）。
- 每个象限中还散布着1到3个孤立的单像素标记点，标记点的颜色与该象限的印章颜色相同。
- 印章图案是非对称的（即水平翻转或竖直翻转后与原图不同）。

Rule:
- 首先识别十字线将网格分成的四个象限，以及十字线的交叉点位置。
- 在每个象限中，识别印章图案（连通的多像素块）和标记点（孤立的单像素）。
- 对于每个标记点，以标记点为中心放置印章图案的一个副本。但放置前需要根据该象限相对于左上象限的位置关系进行镜像变换：
  - 左上象限：不翻转，直接放置原始印章。
  - 右上象限：将印章水平翻转后放置。
  - 左下象限：将印章竖直翻转后放置。
  - 右下象限：将印章同时水平和竖直翻转（等价于旋转180°）后放置。
- 印章副本放置时，若超出网格边界则裁剪；印章副本不覆盖灰色十字线像素和已有的印章图案。
- 输出中原始标记点被印章副本覆盖。

Key insight:
表面上看每个象限独立操作，但真正的隐蔽规则是翻转方式并非由标记点的局部属性决定，而是由象限在全局坐标系中的位置决定——左上不翻转、右上水平翻转、左下竖直翻转、右下双翻转。解题者需要跨象限比较印章副本的朝向才能归纳出这条全局对称性规则，这是超越"在标记点放置印章"这一显然操作之上的第二层推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
