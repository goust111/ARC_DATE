网格中的彩色环形轨道上有多个"车厢"在运行，每个轨道的旋转方向由轨道中心标记决定；车厢移动的步数等于同一轨道上车厢的数量；车厢到达特殊颜色站点时改变自身颜色。

Input structure:
- 背景为黑色。网格中有若干互不重叠的封闭环形轨道，每条轨道由单一颜色的像素构成（轨道颜色各不相同），形成一个宽度为1像素的闭合环路（形状为矩形环、L形环或其他直角折线环路，所有转弯均为直角）。
- 每条轨道的环路所围成的内部区域中心附近有一个标记像素：红色标记表示顺时针旋转，蓝色标记表示逆时针旋转。
- 轨道上某些像素被替换为不同于轨道颜色的彩色像素，这些是"车厢"（每条轨道上有1到3个车厢）。
- 轨道上还可能有绿色像素作为"站点"，站点数量为0或1个。

Rule:
- 对每条轨道，数出该轨道上车厢的数量 N。
- 根据轨道中心的标记颜色确定旋转方向（红色=顺时针，蓝色=逆时针）。
- 将该轨道上的每个车厢沿轨道路径按确定的方向移动 N 步（每步移动到轨道上相邻的下一个像素位置）。
- 车厢移动后，若其新位置恰好在一个绿色站点上，则车厢颜色变为绿色（原站点被车厢占据，不再显示为绿色）。若车厢离开了站点，站点恢复绿色。
- 车厢移动后原来的位置恢复为轨道颜色。
- 中心标记像素在输出中保留。

Key insight:
第一层推理是识别环形轨道的走向和旋转方向（由中心标记编码）；第二层推理是发现移动步数并非固定常数，而是等于同轨道上车厢的数量——一个需要从多个样例中对比才能归纳出的规律；第三层是站点触发的颜色变化规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
