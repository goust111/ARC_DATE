  - 网格中心有一个小型彩色图案（核心图案），由若干非背景色像素组成，占据约 3×3 至 5×5 的区域。
  - 核心图案外围有若干层同心矩形框架，每层框架由单像素宽的 grey 线条组成，相邻框架之间间隔 1 像素的背景色。
  - 每层框架的四个角落中，恰好有一个角落的 grey 像素被替换为一个彩色像素（非 grey、非背景色），其余三个角落保持 grey。该彩色角落的**颜色**和**位置**共同编码一种变换操作。

- `Rule`：
  - 第一层推理——解码变换指令：每层框架的彩色角落编码如下：
    - 颜色为 red：旋转操作。角落在左上 = 旋转 90° 顺时针，右上 = 旋转 180°，右下 = 旋转 90° 逆时针，左下 = 不旋转（即 0°）。
    - 颜色为 blue：翻转操作。角落在左上或右上 = 水平翻转（左右镜像），角落在左下或右下 = 垂直翻转（上下镜像）。
    - 颜色为 green：颜色替换操作。将核心图案中出现次数最少的颜色替换为 green，角落位置不影响此操作。
  - 第二层推理——确定执行顺序并叠加：从最外层框架到最内层框架的顺序依次读取变换指令，形成一个操作序列。将核心图案按该序列依次执行每一步变换。
  - 输出仅包含最终变换后的核心图案（紧凑裁剪，去掉所有框架和多余背景）。

- `Key insight`：框架不是装饰而是指令栈——角落标记的颜色决定变换类型，角落的位置决定变换参数，框架的嵌套层级决定执行顺序。解题者必须同时归纳颜色-操作映射和位置-参数映射两套规则，并正确识别由外到内的执行顺序。
