- `Input structure`：
  - 背景色（black）。
  - 网格中散布着若干 2×2 的彩色方块，称为"信号塔"，每个塔有唯一颜色（如 red、blue、green 等）。
  - 某些塔之间由单像素宽的水平或垂直 grey 直线连接（线段端点紧邻塔的边缘像素）。每条 grey 连线的正中间有一个彩色像素，称为"频率标记"，其颜色为 orange、azure 或 yellow 之一。
  - 频率标记的颜色编码传播模式：orange = 从两端同时向中间扩散；azure = 仅从较大颜色编号的塔向较小的扩散（颜色大小按塔在网格中从左到右、从上到下首次出现的顺序）；yellow = 从两端交替扩散（左/上端先走一格，右/下端再走一格，交替进行）。

- `Rule`：
  - 第一层推理——识别传播模式：找到每条连线中间的频率标记颜色，确定该连线使用哪种扩散规则。
  - 第二层推理——执行扩散：沿着 grey 连线像素，将塔的颜色向外扩散，覆盖 grey 像素。
    - orange 模式：两端的塔同时各自从靠近自己的一端开始，逐像素向中间涂上自己的颜色，在正中间（频率标记位置）相遇，频率标记像素变为两端塔颜色中在网格中出现位置更靠上的那个颜色。
    - azure 模式：仅一端的塔颜色覆盖整条连线（含频率标记），另一端不扩散。
    - yellow 模式：两端交替扩散，最终连线上形成两色交替条纹，频率标记像素被先到达的一端覆盖。
  - 信号塔本身保持不变。频率标记位置被扩散颜色覆盖。

- `Key insight`：连线中间的单像素频率标记不仅是装饰，它编码了该连线上两个塔之间完全不同的颜色扩散行为——解题者需要归纳出三种标记颜色对应三种截然不同的填充模式。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
