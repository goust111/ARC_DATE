- `description`：根据网格中"箭头"指示的方向和底部"标尺"编码的步数与色序，将源对象沿箭头方向复制多次，每次副本颜色按标尺色序循环变化。

- `Input structure`：
  - 背景色 = black。
  - 网格中有若干彩色连通形状（"源对象"），每个源对象旁边紧邻一个由 maroon 像素组成的箭头。箭头的绘制方式：一条 3 像素长的直线段（水平或垂直）加上末端两侧各偏移一个像素构成箭头尖端，例如向右箭头为三个水平像素 `(r,c)(r,c+1)(r,c+2)` 加上 `(r-1,c+2)` 和 `(r+1,c+2)` 构成 ">" 形，共 5 个像素。箭头指向上、下、左、右四个方向之一。
  - 网格底部有一条水平的"标尺"：由若干彩色像素组成的一行，从左到右排列。标尺中像素的总数表示每个源对象需要复制的次数 K；标尺中颜色从左到右的顺序定义了复制品的颜色循环序列 C1, C2, ..., CK。

- `Rule`：
  - 第一步：读取底部标尺，确定复制次数 K = 标尺像素总数，以及颜色序列 C1, C2, ..., CK。
  - 第二步：对每个源对象，确定其紧邻箭头的朝向方向 D。
  - 第三步：沿方向 D，以源对象的包围盒在该方向上的尺寸为步长，依次放置 K 个副本。第 i 个副本的颜色为 Ci（标尺第 i 个像素的颜色），副本形状与源对象完全相同。
  - 第四步：源对象本身保留原色不变。箭头在输出中移除（用背景色覆盖）。标尺在输出中保留。
  - 如果副本超出网格边界则截断（只绘制网格内部分）。

- `Key insight`：箭头仅决定方向，标尺同时编码了"复制几次"和"每次用什么颜色"两个信息——解题者必须意识到标尺长度 = 复制次数，标尺色序 = 副本颜色序列。这两个信息来源的分离与合并构成核心推理难点。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
