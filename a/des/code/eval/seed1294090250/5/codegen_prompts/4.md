描述：根据网格中"窗户"图案上被遮挡的格子位置，从候选补丁库中选取正确的补丁填入，选择依据是补丁边缘轮廓与窗户缺损边缘的互补吻合。

Input structure:
- bg = 最常见颜色（如 black）。
- 网格左侧有一个大型"窗户"：由某种颜色（如 blue）绘制的规则方格图案，类似棋盘格或网格线。窗户中有一个矩形区域被 bg 覆盖（即被"打破"），形成一个洞。洞的边缘处，窗户图案被截断，留下不规则的锯齿状边缘轮廓。
- 网格右侧有若干候选"补丁"，每个补丁是一个与洞尺寸相同的矩形区域，由不同颜色绘制。每个补丁内部也有图案，其边缘处的图案形状各不相同。
- 候选补丁之间用 grey 分隔线隔开。

Rule:
- 检查窗户洞的四条边缘，提取窗户图案在边缘处被截断后留下的锯齿轮廓。
- 对每个候选补丁，检查其四条边缘的图案轮廓。
- 选择边缘轮廓与窗户洞的截断轮廓完全互补（即拼在一起恰好恢复完整图案）的补丁。
- 将选中的补丁填入洞中，补丁颜色变为窗户颜色（blue）。
- 未选中的补丁和分隔线从输出中擦除。

Key insight: 核心推理不是简单的形状匹配，而是需要理解"互补"的概念——补丁边缘的凸起必须对应窗户边缘的凹陷，就像拼图一样。解题者需要先识别窗户的规则图案结构，然后推断出截断处应有的完整样貌，再找到与之互补的补丁。这比直接的形状匹配多了一层"图案还原"的推理。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
