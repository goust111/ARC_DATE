Input structure:
- bg = 最常见颜色（如 black）。网格中有若干互不重叠的封闭矩形边框，每个边框由单一非背景色绘制，宽度为一个像素。

Rule:
- 第一层推理：数出每个边框内部 orange 种子像素的数量 N（1 ≤ N ≤ 4）。
- 第二层推理：根据 N 的值对该边框执行对应的几何变换：
  - N=1：保持原样不变（恒等变换）。
  - N=2：将边框沿其水平中轴做上下翻转（垂直镜像）。
  - N=3：将边框绕其中心顺时针旋转 90 度。
  - N=4：将边框缩小为原来的一半尺寸（长宽各取一半，向下取整），放置在原边框区域的左上角，原边框其余区域填为背景色。
- 所有种子像素在输出中被移除（变为背景色）。变换后的边框保持原来的颜色。
- 若旋转后的边框超出原占用区域，则裁剪到原区域范围内。

Key insight: 种子数量不是简单的计数——它是一个查找键，映射到四种截然不同的空间变换；解题者必须从样例中同时归纳出"计数→变换类型"的映射表和每种变换的具体操作。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
