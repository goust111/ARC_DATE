  - 每个封闭多边形内部恰好有一个单像素的"种子"，颜色与图例中模板图案的颜色相同（red）。

- `Rule`：
  - 第一步：识别图例区内的模板图案，提取其 bounding box 内的二值形状。

- `Key insight`：种子像素不仅标记"在哪里生长"，它在区域内的象限位置同时编码了模板的变换方式（翻转/旋转）和锚定角——解题者必须先从图例识别模板形状，再从种子位置推断变换，两层推理缺一不可。

  - 一个棱镜只响应第一条到达它的射线（按信号塔到棱镜的像素步数计，步数少者优先；若并列则按信号塔在网格中从上到下从左到右的顺序优先），后续到达的射线在棱镜处直接终止不产生新射线。
  - 输出网格中保留所有信号塔、棱镜和滤镜标记的原始像素，同时绘制所有射线轨迹。射线像素覆盖 black 背景但不覆盖任何已有的非 black 像素。

- `Key insight`：棱镜同时执行"转向"和"变色"两个操作——解题者必须先从棱镜旁的滤镜标记推断输出颜色，再根据射线入射方向推断转向后的出射方向；多个信号塔的射线竞争同一个棱镜时的优先级规则构成第三层推理。

- `Input structure`：
  - 背景为 black，网格大小约 20×20 到 28×28。
  - 网格的最外一圈像素形成一个 grey 色的完整边框。
  - 边框的顶边和底边上有若干单像素的彩色标记（非 grey、非 black），它们标记了特定的列位置。

  - 网格内部（边框以内）全部为 black。

- `Rule`：
  - 第一步：对每种出现的非 grey 颜色 C，收集 C 在顶边和底边上标记的所有列位置，以及 C 在左边和右边上标记的所有行位置。

  - 第四步：十字的臂从中心点向上、下、左、右各延伸"臂长"个像素，但不超出 grey 边框内侧。若不同颜色的十字臂像素重叠，后绘制的颜色覆盖先绘制的（按颜色名英文字母序决定绘制顺序，字母序靠后的最后绘制）。

- `Key insight`：边框标记同时编码了两层信息——位置和数量。列标记和行标记的笛卡尔积定义了十字的放置位置，而同一颜色在所有四边上的标记总数定义了十字的臂长。解题者必须分别发现"交叉定位"和"计数定长"这两个独立的规则层。

- `description`：在网格中由管道连接的容器之间传递颜色，根据管道上阀门标记的颜色决定流向，根据汇入颜色的组合决定目标容器的填充色。

- `Input structure`：
  - 背景为 black。
  - 若干用 grey 像素绘制的矩形空心容器（内部为 black 或填有单色像素），容器大小各异但均为矩形轮廓。
  - 部分容器内部已经填充了某种非 grey、非 black 的颜色，这些是"源容器"。
  - 部分容器内部为空（全 black），这些是"目标容器"。
  - 容器之间由 grey 色的单像素宽管道连接——管道是从一个容器壁上某个缺口出发，沿水平或垂直方向延伸，通过直角弯折到达另一个容器壁上的缺口。每条管道连接恰好两个容器。
  - 管道上可能有一个单像素的彩色"阀门"标记（非 grey、非 black），位于管道的某个拐弯处或直线段上。

- `Rule`：
  - 第一步：识别所有容器和管道，建立容器之间的连接关系图。
  - 第二步：确定流向——管道上如果有阀门标记，则该管道只允许从阀门标记颜色与容器内液体颜色相同的那一端流向另一端。如果管道无阀门标记，则液体从已填充的容器流向空容器。
  - 第三步：当一个空容器通过管道连接到恰好一个已填充的源容器时，该目标容器被填充为源容器的颜色。当一个空容器通过管道连接到两个已填充且颜色不同的源容器时，目标容器被填充为以下混合规则的结果：red + blue = magenta，red + yellow = orange，blue + yellow = green。其他颜色组合不存在。当连接到两个同色源容器时，目标容器填充为该相同颜色。
  - 第四步：输出网格中，所有目标容器的内部（grey 墙壁内侧的 black 区域）被填充为推断出的颜色。源容器、管道和阀门保持不变。

- `Key insight`：解题者需要从管道和阀门的结构中推断液体的流向（阀门颜色匹配机制），然后根据流入的颜色组合推断混合结果。流向推断和颜色混合是两个独立的推理层，而阀门颜色作为流向的"密钥"增加了第三层隐蔽性。
</new_puzzle>

- `Input structure`：
  - 背景为 black。
  - 网格中央有多层嵌套的矩形彩色边框，每层边框使用不同颜色（如最外层 red、中层 blue、最内层 green），边框宽度为 1 像素。

  - 最内层边框内部有一个小型彩色图案（"载荷"），使用与任何边框颜色都不同的颜色（如 yellow）。

- `Rule`：
  - 第一步：从最内层边框开始向外处理。最内层边框的缺口方向（上/下/左/右）决定了载荷的初始移动方向。
  - 第二步：载荷沿该方向穿过缺口，到达内层与中层之间的夹层空间。
  - 第三步：到达中层边框后，中层边框的缺口方向决定了载荷的下一步移动方向。载荷被平移到中层缺口对应的那一侧，再穿过中层缺口。
  - 第四步：对每一层重复此过程，直到载荷穿过最外层边框的缺口。
  - 第五步：输出中，所有嵌套边框保持原样（包括缺口），载荷最终被绘制在最外层边框外侧、紧贴最外层缺口的位置。载荷相对于缺口的放置方式为：载荷的 bounding box 边缘紧贴缺口外侧，且在缺口方向的垂直方向上居中对齐（若载荷宽度与缺口宽度不同则以缺口中心对齐载荷中心）。

- `Key insight`：每层边框的缺口独立决定了载荷在该层的"出口方向"，解题者必须逐层追踪缺口位置才能确定载荷的最终落点。多层嵌套意味着需要串联多次方向判断——单看一层缺口无法得出答案，必须从内到外依次处理。

- `Input structure`：
  - 背景为 black。
  - 网格的一侧（如顶部几行）有一个矩形的"调色板矩阵"——一个 R行 C列 的小网格，每个格子填充不同的颜色，用 grey 细线分隔。
  - 调色板矩阵的行数和列数与下方散布的图案模板的 bounding box 行数和列数相同。
  - 网格的其余区域散布着若干图案副本，它们形状完全相同（同一个模板的平移副本，无旋转无翻转），但每个副本使用不同的单一非 black 颜色绘制。
  - 每个副本中恰好有一个像素被"挖掉"（该位置为 black 而非副本颜色），模拟一个缺失点。不同副本的缺失点在模板内的相对位置不同。

- `Rule`：
  - 第一步：识别所有图案副本并确定共同模板形状。
  - 第二步：对每个副本，找到其缺失像素在模板 bounding box 中的相对坐标 (r, c)。
  - 第三步：查找调色板矩阵中第 r 行第 c 列的颜色 C_new。
  - 第四步：将该副本的所有像素（包括补上缺失点）重新绘制为颜色 C_new，替换原本的颜色。

- `Key insight`：每个副本的原始颜色是干扰项——真正决定输出颜色的是缺失像素的位置。解题者必须先发现所有副本共享同一模板形状（通过对比找到缺失点），再发现缺失点坐标与调色板矩阵的行列对应关系。"缺失即地址"是核心的隐蔽洞见。
</new_puzzle>
