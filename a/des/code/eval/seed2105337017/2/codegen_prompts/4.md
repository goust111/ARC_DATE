- `Input structure`：
  - 背景为 black，网格大小约 20×20 到 28×28。
  - 网格的最外一圈像素形成一个 grey 色的完整边框。
  - 边框的顶边和底边上有若干单像素的彩色标记（非 grey、非 black），它们标记了特定的列位置。
  - 边框的左边和右边上也有若干单像素的彩色标记，它们标记了特定的行位置。
  - 同一种颜色在顶/底边上出现的次数可能不同（0到3次），在左/右边上也类似。
  - 网格内部（边框以内）全部为 black。

- `Rule`：
  - 第一步：对每种出现的非 grey 颜色 C，收集 C 在顶边和底边上标记的所有列位置，以及 C 在左边和右边上标记的所有行位置。
  - 第二步：对颜色 C 的每个标记列 col 与每个标记行 row 的交叉点 (row, col)，绘制一个颜色为 C 的十字图案（中心点 + 四个方向的臂）。
  - 第三步：十字的臂长 = 颜色 C 在所有四条边框边上出现的标记总数。例如 C 在顶边出现2次、底边1次、左边1次、右边0次，则臂长为4。
  - 第四步：十字的臂从中心点向上、下、左、右各延伸"臂长"个像素，但不超出 grey 边框内侧。若不同颜色的十字臂像素重叠，后绘制的颜色覆盖先绘制的（按颜色名英文字母序决定绘制顺序，字母序靠后的最后绘制）。

- `Key insight`：边框标记同时编码了两层信息——位置和数量。列标记和行标记的笛卡尔积定义了十字的放置位置，而同一颜色在所有四边上的标记总数定义了十字的臂长。解题者必须分别发现"交叉定位"和"计数定长"这两个独立的规则层。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
