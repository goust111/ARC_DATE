- `description`：将散落的彩色碎片按颜色配对，每对碎片沿它们的公共对称轴合并为一个完整的对称图形，然后按合并后图形的面积从小到大排列在输出网格中。

- `Input structure`：
  - 背景为 black。
  - 若干彩色连通分量（8-连通）散布在网格上，每种非背景色恰好出现两个连通分量。
  - 同色的两个分量形状互为某种对称关系的"半体"——它们可以沿某条水平线、垂直线或对角线拼合为一个左右/上下/对角对称的完整图形。
  - 两个同色分量之间没有重叠，且它们的 bounding box 不接触。

- `Rule`：
  - 第一步：将同色的两个分量配对。对于每一对，尝试所有可能的拼合方式（平移一个分量使其与另一个分量对接），找到唯一能使合并结果关于某条轴完全对称的拼合位置。
  - 第二步：在该拼合位置将两个分量合并为一个完整图形（重叠像素取该颜色即可）。
  - 第三步：计算每个合并后图形的像素总数（面积）。
  - 第四步：输出网格中，将所有合并后的图形按面积从小到大、从左到右依次紧凑排列（图形之间间隔 1 列 black），每个图形的 bounding box 顶部对齐到输出网格的第一行。

- `Key insight`：碎片不是简单地"靠拢"——解题者需要发现它们是沿一条隐含对称轴被切割的半体，并且必须找到使拼合结果严格对称的唯一位置；排序则提供了验证合并正确性的额外信号。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
