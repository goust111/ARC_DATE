- `description`：根据框架内部的彩色种子像素确定生长方向，再依据框架边缘的刻度标记确定生长长度，在框架外部绘制对应的彩色射线。
- `Input structure`：
  - 背景色为网格中最常见的颜色。
  - 网格中有若干单色矩形框架（仅由边框像素构成，内部为背景色），每个框架使用不同的非背景色。
  - 每个框架的内部恰好有一个彩色种子像素（颜色与框架边框不同），该种子像素紧邻框架的某一条内壁（上/下/左/右），但不位于角落。种子像素所贴靠的那条内壁决定了射线将从框架的哪一面射出（即从该面向外发射）。
  - 每个框架的外侧边缘上，有若干小刻度标记像素（颜色为 grey），这些刻度标记分布在框架外壁的某一侧。刻度标记的数量即为射线的长度（以像素为单位）。
- `Rule`：
  - 对每个框架，找到其内部的种子像素，确定种子贴靠的内壁方向——射线从该方向的框架外壁中心位置向外发射。
  - 统计该框架外侧的 grey 刻度标记像素数量 N。
  - 从框架外壁的中心位置出发，沿确定的方向向外绘制长度为 N 的射线，射线颜色与种子像素颜色相同。
  - 框架本体、种子像素和刻度标记在输出中保持不变。
- `Key insight`：种子像素的位置编码了射线的方向（贴靠哪面墙就从哪面射出），而框架外部的刻度数量编码了射线的长度——两层信息分别藏在框架内部和外部，需要分别识别并组合。
</new_puzzle>

- `Input structure`：
  - 背景色为网格中最常见的颜色。
  - 网格中央有一个大型的多色"模板"对象，其主体由单一颜色（如 blue）构成，内部挖有若干不规则形状的空槽（背景色区域）。
  - 每个空槽的边缘恰好有一个单像素的彩色标记（非模板色、非背景色），标记颜色各不相同。这个标记像素位于空槽轮廓的某一侧（上/下/左/右边缘）。
  - 网格的外围散落着若干小型彩色碎片，每个碎片由单一颜色构成，碎片颜色与某个空槽的标记颜色一一对应。
  - 每个碎片上也有一个单像素的特殊标记（颜色为 red），位于碎片轮廓的某一侧。
- `Rule`：
  - 根据颜色将每个碎片与模板中对应标记颜色的空槽配对。
  - 碎片的形状（不含 red 标记像素）与对应空槽的形状完全吻合（可能需要 0°/90°/180°/270° 旋转）。
  - 确定唯一正确旋转的方式：旋转碎片使其 red 标记像素与空槽边缘的彩色标记像素重合在同一侧（即碎片的 red 标记在嵌入后应紧邻空槽的彩色标记）。
  - 将旋转后的碎片平移嵌入空槽中，碎片像素替换空槽中的背景色。Red 标记像素不写入输出。
- `Key insight`：颜色匹配解决碎片与槽的对应关系，但仅靠形状无法确定唯一旋转——碎片上的 red 标记与空槽边缘的彩色标记必须对齐，这一"锚点对齐"约束才能消除旋转歧义。
</new_puzzle>

- `Key insight`：连接线的颜色不是直接用来填充容器的——它是图例查找的索引键；真正的填充内容隐藏在角落图例的右半部分。多条线连入同一容器时，图例中的排列顺序充当优先级仲裁。

- `description`：识别网格中被噪声像素污染的对称图形，根据对称类型修复噪声，再按修复后的面积从小到大重新排列。
- `Input structure`：
  - 背景色为网格中最常见的颜色。
  - 网格中散落着若干彩色图形，每个图形由单一非背景色构成。
  - 每个图形"本应"是某种对称形状（水平对称、垂直对称或 90° 旋转对称），但被少量噪声像素破坏：有些像素被错误地移除（变成了背景色），有些位置被错误地添加了同色像素。噪声像素的数量不超过图形总像素数的 1/4。
  - 网格底部有一行彩色标记行，从左到右排列着与各图形颜色相同的单像素点，它们的横坐标间隔均匀，标记行定义了输出中每个图形的放置位置（水平居中对齐于标记点）。
- `Rule`：
  - 对每个图形，尝试三种对称类型（水平翻转、垂直翻转、90° 旋转对称），选择需要修改最少像素就能恢复的那种对称类型。
  - 按照选定的对称类型修复图形：添加缺失的像素、移除多余的像素，使图形严格满足该对称性。
  - 计算修复后每个图形的像素面积。
  - 在输出网格中，将修复后的图形按面积从小到大排列，分别放置于底部标记行各标记点的正上方（图形底边紧贴标记行上方一行，水平居中于标记点）。
  - 标记行在输出中保留。
- `Key insight`：第一层推理是发现每个图形"应该"具有对称性并找出正确的对称类型（需要从噪声中识别出最接近的对称形式），第二层推理是发现输出中的排列顺序由修复后的面积决定，而非按输入位置或颜色排列。
</new_puzzle>

- `description`：将网格中的彩色信号沿管道网络传播，在交叉节点处按混色规则生成新颜色，最终为管道的末端端口着色。
- `Input structure`：
  - 背景色为网格中最常见的颜色。
  - Grey 像素构成一个正交管道网络：直线段（水平或垂直，宽度 1 像素）在 T 形或十字形交叉节点处相连。管道网络中没有环路（即为树形结构）。
  - 管道网络的若干叶子端点（度为 1 的末端像素）旁边紧邻一个彩色像素（非 grey、非背景色），这些是"信号源"。每个信号源的颜色各不相同。
  - 管道网络的其余叶子端点旁边没有彩色像素，这些是"端口"（需要被着色的目标）。
  - 网格一角有一个小型"混色图例"：若干 1x3 的水平条，每条的左右两端是两种输入颜色，中间像素是它们混合后产生的输出颜色（例如 red + blue → magenta）。
- `Rule`：
  - 每个信号源的颜色沿管道向网络内部传播。
  - 当两条携带不同颜色信号的管道在交叉节点汇合时，查阅混色图例，将两种颜色混合为图例中定义的新颜色，新颜色继续沿剩余管道传播。
  - 传播持续直到信号到达每个端口。
  - 将每个端口像素（原为 grey）着色为到达该端口的最终信号颜色。
  - 管道网络的 grey 像素（非端口部分）和信号源像素在输出中保持不变。
- `Key insight`：第一层推理需要发现管道网络的树形拓扑结构以及信号沿管道传播的机制；第二层推理需要发现交叉节点处的颜色不是简单覆盖或保留，而是通过角落的混色图例查表生成全新的颜色；第三层推理在于当网络有多级交叉时，前一级混合的结果会作为下一级混合的输入，形成链式混色。
</new_puzzle>

- `Input structure`：
  - 背景色为网格中最常见的颜色。
  - 网格中有若干较大的矩形容器，由 black 像素绘制完整边框（1 像素宽）。每个容器的边框上有 1 到 3 个缺口（缺口处的 black 像素被替换为背景色，每个缺口宽度恰好为 1 像素）。
  - 每个容器内部（被边框围起的区域）中央有一个小型的形状标记，形状标记由 grey 像素绘制，可能是以下形状之一：十字形（+）、T 形、L 形。
  - 网格边缘的空白区域有若干"印章模板"，每个印章模板由某种非 black、非 grey、非背景色的彩色像素组成，其外轮廓恰好是上述三种形状之一（十字形、T 形或 L 形），但尺寸比容器内部的形状标记更大，恰好能铺满容器内部空间。
- `Rule`：
  - 对每个容器，识别其内部的 grey 形状标记类型（十字/T/L）。
  - 在网格边缘找到外轮廓与该类型匹配的印章模板（形状相同，尺寸匹配容器内部）。
  - 统计该容器边框上的缺口数量 K，将印章模板顺时针旋转 K×90°。
  - 将旋转后的印章模板居中盖入容器内部，覆盖 grey 形状标记。
  - 容器边框（含缺口）在输出中保持不变，边缘的印章模板原件也保留。
- `Key insight`：形状标记解决"选哪个印章"的问题，但仅此不够——缺口数量编码了旋转角度，这是第二层需要独立归纳的规则。解题者必须先发现形状匹配机制，再发现缺口计数与旋转的对应关系。

- `description`：在分层地图中，根据海拔等高线的嵌套层数为每层区域着色，同时用山顶标记的颜色覆盖该山峰的所有等高线。
- `Input structure`：

  - 网格中有若干组嵌套的闭合环（等高线），每组由 green 像素绘制的闭合曲线（1 像素宽、4 连通闭合）构成。环层层嵌套，最内层环内部面积最小。
  - 每组嵌套环的最内层中心有一个彩色"山顶标记"像素（非 green、非背景色），不同组的山顶标记颜色各不相同。
  - 网格底部有一个调色板行：从左到右排列着若干颜色方块，每个方块为 1x1 像素，颜色各不相同。调色板中颜色的排列顺序代表从浅到深的海拔着色梯度（左端最浅 = 最外层，右端最深 = 最内层）。
- `Rule`：
  - 对每组嵌套等高线，计算嵌套层数（从外到内编号 1, 2, 3, ...）。
  - 将等高线之间的每个环形区域（以及最内层环内部区域）按其层级编号 i，填充调色板行中第 i 个颜色。
  - 将该组所有 green 等高线像素替换为该组山顶标记的颜色（使得不同山峰的等高线颜色不同）。
  - 山顶标记像素本身保留原色。调色板行在输出中保留。
  - 等高线外部的背景色区域保持不变。
- `Key insight`：第一层推理是发现嵌套层数与调色板位置的对应关系（层级决定填充色）；第二层推理是发现等高线本身的颜色不保持 green，而是被最内层的山顶标记颜色覆盖——这将不同山峰的等高线在视觉上区分开来。两层规则分别控制"区域填什么色"和"线画什么色"。
</new_puzzle>
