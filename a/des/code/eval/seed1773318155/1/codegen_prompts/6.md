- `description`：网格中散布着若干对颜色相同的"门"像素和连接它们的灰色"通道"；根据通道的转弯次数决定每对门的最终颜色变换。

- `Input structure`：
  - bg = black。网格中有若干条由 grey 像素构成的单像素宽路径（通道），每条通道连接两个端点。
  - 每条通道的两个端点各有一个彩色像素（"门"），同一条通道两端的门颜色相同。不同通道的门颜色不同，用以区分通道归属。门的颜色可以是 red、blue、green、yellow、orange 等。
  - 通道在网格中可以直行或直角转弯，但不会分叉，也不会与其他通道交叉。每条通道的转弯次数在 0 到 4 之间。

- `Rule`：
  - 第一层推理——通道追踪与转弯计数：沿每条 grey 通道从一端走到另一端，数出通道中直角转弯的次数 T（即方向改变的次数，方向只有上下左右四种）。
  - 第二层推理——颜色循环变换：定义颜色循环序列为 red → blue → green → yellow → orange → red ...（共 5 种颜色循环）。将每对门的原始颜色在此循环中向前推进 T 步，得到新颜色。将两个门像素都改为新颜色。
  - 通道本身（grey 像素）在输出中保持不变。

- `Key insight`：转弯次数是一个需要主动追踪才能获得的视觉量（而非一眼可见的属性），而颜色循环规则需要从多个样例中归纳出固定的循环顺序。两层推理相互独立但缺一不可：不数转弯就无法确定偏移量，不发现颜色循环就无法确定目标颜色。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
