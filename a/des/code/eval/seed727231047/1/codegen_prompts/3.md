- `description`：在网格中，箭头形状指示传播方向，将箭头尾部的图案沿箭头方向复制到箭头前方，且复制次数由箭头的长度决定。

- `Input structure`：
  - 背景为黑色。
  - 网格中包含若干"箭头"和若干"图案块"。
  - 每个箭头由一种颜色绘制，形状为：一条水平或垂直的直线段（箭杆，长度 L 像素），加上末端的一个三角箭头尖（由3个像素组成的"V"形，指向上/下/左/右之一）。具体地：若箭头朝右，则箭杆为水平线段，箭杆右端上方一格和下方一格各有一个同色像素，与箭杆右端像素共同构成向右的三角尖。其他方向类推。
  - 每个箭头的尾端（与箭头尖相反的一端）紧邻一个小型矩形图案块（由多种颜色像素组成，尺寸不超过 4×4）。图案块与箭头尾端之间间隔恰好1个像素。
  - 箭头的颜色与其对应图案块中的任何颜色都不同。

- `Rule`：
  - 对每个箭头，确定其指向方向和箭杆长度 L（不含箭头尖的3个像素）。
  - 从箭头尖端开始，沿箭头指向方向，以图案块自身尺寸为步长，连续复制图案块 L 次。
  - 每次复制时，图案块的朝向保持不变。相邻两个复制之间紧密排列，无间隔。
  - 复制完成后，原始箭头（箭杆和箭头尖）从网格中移除（变为黑色背景），原始图案块保留在原位。

- `Key insight`：箭头同时编码了两个信息——方向和数量。解题者首先需要识别箭头的几何结构以确定传播方向，然后需要发现箭杆的像素长度等于图案的复制次数，而非仅仅是"沿方向填满"。箭头本身在输出中消失这一点也需要从样例中归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
