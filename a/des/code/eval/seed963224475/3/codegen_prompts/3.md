<new_puzzle index="3">
- `description`：在由彩色围墙分隔的多个房间中，根据房间内"传送门"对的颜色匹配关系，将物体从一个房间经传送门转移到另一个房间，保持物体相对于入口门的空间朝向。

- `Input structure`：
  - 背景色 = black。
  - 网格被 grey 色的线条分割成若干矩形"房间"（grey 线构成完整的网格状分隔）。
  - 每个房间的墙壁（grey 线）上有 1-2 个由非 grey、非背景色的像素替换的位置，这些是"传送门"，每个传送门占据墙壁上连续的 2 个像素，颜色相同。
  - 相同颜色的传送门在整个网格中恰好出现两次，分别位于不同房间的墙壁上，构成一对。
  - 恰好有一个房间内包含一个由 maroon 色像素构成的小型连通图案（"物体"），且该房间有一个传送门。

- `Rule`：
  - 找到物体所在的房间及其传送门颜色 C。
  - 在另一个房间中找到相同颜色 C 的配对传送门（"出口门"）。
  - 确定物体相对于入口门的位置关系：物体中每个像素相对于入口门中心的行偏移和列偏移。
  - 将物体从原房间擦除。根据出口门所在墙壁的朝向，对偏移量进行旋转：若入口门在房间的上墙、出口门在目标房间的右墙，则物体顺时针旋转 90° 后放置；两门朝向相同则不旋转；以此类推（旋转角度 = 出口门墙壁朝向 - 入口门墙壁朝向，以顺时针 90° 为单位）。最终将旋转后的物体绘制到出口门内侧对应位置。
  - 墙壁朝向定义：上墙 = 0°，右墙 = 90°，下墙 = 180°，左墙 = 270°。

- `Key insight`：解题的核心在于两层推理——首先通过颜色匹配找到传送门对，然后根据入口门和出口门各自所在墙壁的朝向差异推断物体需要旋转的角度。仅靠颜色匹配或仅靠旋转都无法单独解题。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
