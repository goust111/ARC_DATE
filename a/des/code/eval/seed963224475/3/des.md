- `description`：根据封闭区域内"钥匙"形状与边框上"锁孔"形状的轮廓匹配，将钥匙传送到对应锁孔位置，并用锁孔边框的颜色重新上色。

- `Input structure`：
  - 背景色 = black。
  - 网格中散布若干封闭的彩色矩形边框（"锁"），每个边框的一条边上有一个由背景色构成的缺口图案（"锁孔"），缺口形状各不相同（如 L 形缺口、T 形缺口、阶梯形缺口等，均为 2-4 像素的连通缺口）。
  - 每个边框内部有一个由另一种颜色绘制的小型连通图案（"钥匙"），钥匙的形状与某个锁孔的缺口形状完全相同（像素级匹配），但颜色不同。
  - 钥匙不一定在与其匹配的锁内部——它可能在任意一个锁的内部。

- `Rule`：
  - 第一步（匹配）：提取每个锁边框上的缺口形状（将缺口像素的相对坐标归一化），同时提取每把钥匙的形状（同样归一化）。将形状完全相同的钥匙与锁孔配对。
  - 第二步（传送与重绘）：将每把钥匙从原位置擦除（填回背景色），然后将其绘制到匹配锁的缺口位置，精确填充缺口的像素。填充时使用该锁边框的颜色，而非钥匙原来的颜色。
  - 所有锁的其余部分保持不变。

- `Key insight`：钥匙与锁的匹配依据是形状轮廓的像素级一致性，而非颜色或空间邻近关系；匹配完成后，钥匙需要"变色"为锁的颜色来填补缺口，相当于修复了边框。
</new_puzzle>

<new_puzzle>
- `description`：利用网格边缘的方向箭头确定每个彩色区域的"生长方向"，再根据区域内种子像素的数量决定生长步数，从而扩展区域。

- `Input structure`：
  - 背景色 = black。
  - 网格中有若干不同颜色的小型连通区域（"种子簇"），每个种子簇由 1-5 个同色像素组成，形状各异。
  - 网格的四条边上各有若干箭头标记。每个箭头由 3 个同色像素组成：一个"头部"像素紧贴边缘，两个"尾部"像素在头部的内侧呈 V 字形排列。箭头颜色与某个种子簇的颜色相同。箭头指向的方向（从尾部中点朝向头部）为上、下、左或右之一。
  - 每种颜色恰好对应一个箭头和一个种子簇。

- `Rule`：
  - 第一步（方向确定）：对每种非背景颜色，在边缘找到同色箭头，读取其指向的方向 D（上/下/左/右）。
  - 第二步（步数确定）：数出该颜色种子簇中的像素数量 N。
  - 第三步（生长）：从种子簇的每个像素出发，沿方向 D 连续填充 N 个像素（用该颜色填充）。若遇到网格边界则停止。生长过程中不覆盖其他已有颜色的像素。
  - 输出中保留原始种子簇像素和箭头标记。

- `Key insight`：解题需要两层独立归纳——箭头编码了生长方向（通过箭头朝向），种子簇的像素计数编码了生长距离。两者必须正确关联到同一颜色才能得出正确输出。
</new_puzzle>

<new_puzzle>
- `description`：在由彩色围墙分隔的多个房间中，根据房间内"传送门"对的颜色匹配关系，将物体从一个房间经传送门转移到另一个房间，保持物体相对于入口门的空间朝向。

- `Input structure`：
  - 背景色 = black。
  - 网格被 grey 色的线条分割成若干矩形"房间"（grey 线构成完整的网格状分隔）。
  - 每个房间的墙壁（grey 线）上有 1-2 个由非 grey、非背景色的像素替换的位置，这些是"传送门"，每个传送门占据墙壁上连续的 2 个像素，颜色相同。
  - 相同颜色的传送门在整个网格中恰好出现两次，分别位于不同房间的墙壁上，构成一对。
  - 恰好有一个房间内包含一个由 maroon 色像素构成的小型连通图案（"物体"），且该房间有一个传送门。

- `Rule`：
  - 找到物体所在的房间及其传送门颜色 C。
  - 在另一个房间中找到相同颜色 C 的配对传送门（"出口门"）。
  - 确定物体相对于入口门的位置关系：物体中每个像素相对于入口门中心的行偏移和列偏移。
  - 将物体从原房间擦除。根据出口门所在墙壁的朝向，对偏移量进行旋转：若入口门在房间的上墙、出口门在目标房间的右墙，则物体顺时针旋转 90° 后放置；两门朝向相同则不旋转；以此类推（旋转角度 = 出口门墙壁朝向 - 入口门墙壁朝向，以顺时针 90° 为单位）。最终将旋转后的物体绘制到出口门内侧对应位置。
  - 墙壁朝向定义：上墙 = 0°，右墙 = 90°，下墙 = 180°，左墙 = 270°。

- `Key insight`：解题的核心在于两层推理——首先通过颜色匹配找到传送门对，然后根据入口门和出口门各自所在墙壁的朝向差异推断物体需要旋转的角度。仅靠颜色匹配或仅靠旋转都无法单独解题。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片按照"拼接指纹"组装成完整矩形，再依据矩形内隐藏的对称性类型对整个矩形执行相应的翻转变换输出。

- `Input structure`：
  - 背景色 = azure。
  - 网格中散布若干不规则形状的彩色碎片（每个碎片是一个 4-连通的非背景像素区域），碎片之间不重叠、不相邻。
  - 每个碎片的边缘有一些像素使用了一种特殊的"指纹色"（green），其余像素为该碎片自身的主色（各碎片主色不同）。
  - 碎片可以无缝拼合成一个紧凑的矩形。拼合依据：两个碎片的拼接边上，green 指纹像素的位置完全互补（一个碎片边缘的 green 像素对应另一个碎片边缘的非 green 像素，反之亦然）。
  - 拼合后的矩形中，所有 green 像素恰好落在碎片之间的接缝处。

- `Rule`：
  - 第一步（拼合）：通过匹配碎片边缘的 green 指纹互补模式，确定碎片之间的邻接关系和相对位置，将所有碎片拼合成一个完整矩形。拼合时碎片不旋转、不翻转，仅平移。
  - 第二步（识别对称性）：观察拼合后矩形中 green 像素构成的图案。这些 green 像素形成一个简单的指示符号：若 green 像素图案关于矩形的水平中轴对称，则执行上下翻转；若关于垂直中轴对称，则执行左右翻转；若同时关于两轴对称，则旋转 180°。
  - 第三步（变换输出）：对拼合后的矩形执行上述翻转/旋转，然后将所有 green 像素替换为其所在碎片的主色（即消除接缝痕迹），输出最终矩形。

- `Key insight`：解题需要三层推理——先通过边缘指纹互补完成拼图，再从拼合结果中 green 像素形成的全局图案中识别对称性类型以决定变换方式，最后执行变换并清除指纹色。green 像素同时承担了"拼接线索"和"变换指令"双重角色。
</new_puzzle>

<new_puzzle>
- `description`：在网格中识别由不同颜色构成的"容器"与"液体"，根据容器的开口方向判断液体是否会"流出"，并模拟液体沿重力方向沉降到容器底部的最终状态。

- `Input structure`：
  - 背景色 = azure。
  - 网格中有若干 U 形或 C 形的彩色结构（"容器"），每个容器由单一非背景色的像素组成，形成三面封闭、一面开口的形状。容器的开口可以朝上、下、左或右。
  - 每个容器内部有若干散落的像素（"液体"），液体颜色与容器颜色不同，也与背景色不同。液体像素位于容器的封闭内部空间中。
  - 网格左下角有一个由 3 个 red 像素组成的箭头，指向上、下、左或右之一，表示"重力方向"。箭头绘制方式：1 个头部像素在指向方向的前端，2 个尾部像素在后方呈 V 字形排列。

- `Rule`：
  - 读取左下角箭头确定重力方向 G。
  - 对于每个容器，判断其开口方向是否与重力方向 G 相同。
    - 若开口方向与 G 相同（即容器的开口朝向重力方向，例如重力向下且容器开口朝下），则液体会"流出"：擦除容器内所有液体像素，并从容器开口处沿重力方向绘制等量的液体像素直到碰到网格边界或其他非背景像素。
    - 若开口方向与 G 不同，则液体留在容器内，但沿重力方向 G 沉降：将容器内的液体像素整体平移到容器内部空间中靠近重力方向那一侧，紧贴容器内壁堆叠。
  - 容器本身保持不变。

- `Key insight`：解题需要两层推理——首先通过角落箭头确定全局的"重力方向"（这个方向在不同样例中会变化），然后对每个容器分别判断其开口是否与重力同向来决定液体是流出还是沉降。同一网格中不同朝向的容器会表现出不同的行为。
</new_puzzle>

<new_puzzle>
- `description`：在包含多个图层叠加的网格中，通过角落色块解码图层的叠放顺序，再根据每个图层边框上标记点的位置提取该图层的特定行或列，最终将提取结果按顺序拼接输出。

- `Input structure`：
  - 背景色 = black。
  - 网格中有若干同尺寸（如 6x6）的正方形彩色边框（仅 1 像素宽的边框线，内部为背景色），它们在网格上部分重叠放置。每个边框颜色不同。
  - 每个边框的某一条边（上/下/左/右）的外侧中央有一个 1 像素的 yellow 标记点，紧贴该边。
  - 网格的右下角有一个小的垂直色条（1 列宽，高度等于边框数量），从上到下排列了所有边框的颜色，每种颜色占 1 个像素。

- `Rule`：
  - 第一步（解码顺序）：右下角色条从上到下给出了图层的输出排列顺序。
  - 第二步（提取切片）：对于每个边框，找到其 yellow 标记点所在的边。标记点在上边或下边，则提取该边框内部区域的中间行（若内部高度为偶数则取上半中间行）；标记点在左边或右边，则提取该边框内部区域的中间列。提取结果为一条 1 像素宽的线段。注意：重叠区域中，若边框内部某像素被另一个边框的边框线覆盖，则该像素显示为覆盖者的颜色而非背景色，提取时使用实际可见的颜色。
  - 第三步（拼接输出）：按右下角色条规定的顺序，将提取出的线段依次排列。若线段为行则水平排列、垂直堆叠；若线段为列则垂直排列、水平堆叠。输出为一个紧凑的矩形。

- `Key insight`：解题包含三层非平凡推理——首先需要从角落色条中读取隐含的排列顺序（而非默认的空间位置顺序），其次需要理解 yellow 标记点的位置编码了"切哪个方向"的信息，最后在提取切片时必须考虑图层重叠导致的颜色遮挡效果。三层信息缺一不可。
</new_puzzle>

<new_puzzle>
- `description`：根据网格中"信号塔"发射的彩色射线在"镜面"上的反射路径，确定射线最终照亮的区域，并用射线颜色填充该区域。

- `Input structure`：
  - 背景色 = black。
  - 网格中有若干 1x1 的彩色像素作为"信号塔"，每个信号塔颜色不同（非 black、非 grey）。
  - 网格中有若干由 grey 像素组成的直线段（水平或垂直），作为"镜面"。每面镜子长度为 3-6 像素。
  - 网格中有若干由 maroon 像素组成的小型矩形区域（2x2 或 3x3），作为"屏幕"，这些是需要被照亮的目标区域。
  - 每个信号塔恰好有一面镜子与其处于同一行或同一列（轴对齐），信号塔朝向该镜子发射射线。

- `Rule`：
  - 每个信号塔沿其所在行或列向最近的同行/同列镜子发射一条射线（射线沿该方向传播直到碰到镜子）。
  - 射线碰到镜子后发生 90° 反射：水平射线碰到垂直镜子后变为垂直方向继续传播（方向取决于镜子相对于碰撞点的偏移侧），垂直射线碰到水平镜子后变为水平方向继续传播。反射后的射线继续传播直到碰到屏幕或网格边界。
  - 若反射后的射线路径经过某个 maroon 屏幕，则将该屏幕的所有像素替换为信号塔的颜色。
  - 射线路径本身（信号塔到镜子、镜子到屏幕的直线像素）不绘制在输出中。信号塔和镜子保持原样。未被射线命中的屏幕保持 maroon 色不变。

- `Key insight`：解题者需要先识别每个信号塔与哪面镜子轴对齐以确定射线初始方向，再根据镜面的朝向推断反射后的路径，最后判断反射路径是否命中屏幕。核心难度在于反射方向的推断——必须同时考虑入射方向和镜面朝向（水平/垂直）才能确定出射方向。
</new_puzzle>
