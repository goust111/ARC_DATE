在双层网格中执行"编织"操作：根据交叉点的标记颜色决定哪条带在上、哪条带在下，最终用遮挡关系决定每个交叉像素的可见颜色。

Input structure:
- 背景为black。网格中有若干水平条带和若干竖直条带，每条带宽度为1像素，各条带颜色互不相同（使用red、blue、green、orange、yellow、maroon等颜色）。
- 水平条带和竖直条带在网格中形成若干交叉点。每个交叉点处恰好有一个小标记：该标记位于交叉点的右下方对角邻居位置（即交叉点坐标为(r,c)，标记在(r+1,c+1)处），标记颜色为azure或magenta之一。
- 条带的非交叉部分正常显示为条带自身颜色。

Rule:
- 第一步（读取编织指令）：每个交叉点右下角的标记决定交叉处的上下关系。azure标记表示"水平在上"（交叉点显示水平条带颜色），magenta标记表示"竖直在上"（交叉点显示竖直条带颜色）。
- 第二步（验证编织合法性）：沿每条水平条带从左到右依次检查其各个交叉点：该条带的上下状态必须严格交替（上-下-上-下...或下-上-下-上...），如同真实编织。如果输入中的标记已经满足交替规律，则直接使用；如果某个标记打破了交替规律，则翻转该标记（azure变magenta或反之）以恢复交替。
- 第三步（渲染交叉点）：根据最终确定的上下关系，每个交叉点像素显示"在上"的那条带的颜色。移除所有右下角的标记像素（标记位置恢复为black）。

Key insight:
标记颜色看似直接决定了遮挡关系，但实际上存在"编织合法性修正"这一隐蔽层——解题者必须先注意到真实编织的交替约束，才能理解为什么某些交叉点的输出颜色与标记指示不一致。标记中故意设置的少量"错误"迫使解题者发现交替规律而非简单查表。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
