根据"信号塔"的高度和颜色，在网格上生成扇形广播区域；信号被墙壁阻挡后在墙壁另一侧产生"阴影盲区"，最终未被任何信号覆盖的区域标记为特殊颜色。

Input structure:
- 背景为black。网格底部有一条水平的grey基准线，贯穿整个网格宽度。
- 基准线上方竖立着若干"信号塔"：每座塔是一列从基准线向上延伸的同色像素柱（颜色各异，如red、blue、green、orange），高度从2到6不等。
- 网格中散布若干单独的maroon像素作为"墙壁"，不与任何信号塔相邻。

Rule:
- 第一步（确定广播范围）：每座信号塔以其顶部像素为中心，向左上和右上两个对角方向发射信号射线。左侧射线沿左上方45度延伸，右侧射线沿右上方45度延伸。两条射线之间（包含射线本身）的所有格子构成该塔的"广播扇区"。射线延伸长度等于塔的高度（像素数）。扇区内所有black格子被染成该塔的颜色。
- 第二步（墙壁遮挡）：若射线路径上遇到maroon墙壁像素，射线在该点停止。墙壁正后方（沿射线方向继续延伸的区域）形成"阴影"——该阴影区域内如果之前被染色，则恢复为black。阴影区域的宽度为1列，长度为射线剩余的未走完距离。
- 第三步（盲区标记）：所有步骤完成后，基准线上方仍为black的格子（不包括maroon墙壁本身）被标记为yellow，表示"信号盲区"。

Key insight:
塔的高度同时决定了射线长度和扇区宽度，这一双重作用使得高塔的覆盖面积呈非线性增长——解题者需要领悟高度与面积的几何关系而非简单线性对应。墙壁的遮挡效果需要沿射线方向追踪，这要求解题者理解遮挡是方向性的而非全向的。最终的盲区标记将前两步的结果整合为一个可视化判断。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
