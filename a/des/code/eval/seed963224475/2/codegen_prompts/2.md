- `description`：在被隔墙分割的网格区域中，根据每个区域内种子像素的颜色和数量，用对应颜色的同心矩形环从外向内间隔填充该区域，彩色环的条数等于种子数量。
- `Input structure`：
  - 背景为 black。网格被 green 色单像素宽的直线（水平和垂直贯穿整个网格）分割为若干矩形区域。
  - 每个矩形区域内部为 black 背景，包含 1 到 4 个同色的种子像素（颜色为非 black、非 green 的某种颜色，如 red、blue、orange 等）。不同区域的种子颜色可能相同也可能不同。
  - 种子像素在区域内的位置随机，不影响输出结果。
- `Rule`：
  - 对每个矩形区域：
    1. 读取区域内种子像素的颜色 C 和数量 N。
    2. 从区域最外一圈像素开始（紧贴 green 隔墙或网格边缘的内侧第一圈），向内逐层编号为第 1 层、第 2 层、第 3 层……
    3. 奇数编号层（第 1、3、5…层）为"彩色槽位"，偶数编号层（第 2、4、6…层）保持 black 不填。
    4. 从外向内，仅填充前 N 个彩色槽位（即前 N 个奇数层）为颜色 C。更内部的所有层保持 black。
  - green 隔墙保持不变。
- `Key insight`：第一层推理是发现种子颜色决定填充色——这相对容易从样例中观察到。第二层推理是发现彩色环之间存在间隔（奇偶交替），且彩色环的条数等于种子像素的数量——这需要对比不同区域中种子数量不同时环数的差异才能归纳。单纯"数量决定填充深度"和"间隔排列"这两个规律叠加在一起，增加了从样例中归纳的难度。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
