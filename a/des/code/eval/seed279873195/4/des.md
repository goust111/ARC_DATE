- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干 L 形或直线形的"管道片段"，每个片段由 azure 像素构成主体，两个端口各用一个彩色像素标记（端口颜色可以是 red、green、yellow、magenta 等）。
  - 网格中有若干"过滤器"：一个 2×1 或 1×2 的小方块，紧贴在某个管道片段的主体旁边。过滤器的一半为颜色 A，另一半为颜色 B，表示"颜色 A 经过此过滤器后变为颜色 B"。过滤器的朝向（A 在前还是 B 在前）与管道的传播方向一致：沿传播方向先遇到的是输入色 A，后遇到的是输出色 B。
  - 有一个起点标记：一个独立的单色像素，紧邻某条管道片段的端口，颜色与该端口不同，表示种子颜色。
  - 有一个终点标记：一个 maroon 像素，紧邻某条管道片段的端口。

- `Rule`：
  - 第一步（管道拼接）：两个管道片段的端口颜色相同且在同一行或同一列上时，它们通过该端口对接。将所有可配对的端口连接起来，用 azure 像素填充端口之间的间隙，形成从起点到终点的连续管道。
  - 第二步（颜色传播）：从起点出发，种子颜色沿管道传播，将管道主体的 azure 像素全部替换为当前传播颜色。
  - 第三步（过滤器变色）：当传播经过一个过滤器时，如果当前颜色等于过滤器的输入色 A，则从此处开始传播颜色变为 B；如果不等于 A，则颜色不变，继续传播。
  - 输出网格中，管道被染成传播后的颜色（可能分段不同色），端口像素被 azure 覆盖，过滤器保留原样。

- `Key insight`：第一层推理需发现端口颜色匹配规则来确定管道拼接顺序；第二层推理需发现过滤器的条件性——它只在当前颜色匹配输入色时才替换，否则颜色穿透不变，这使得过滤器的排列顺序和管道走向共同决定最终配色。
</new_puzzle>

- `Key insight`：解题需要先从窗户在墙壁上的位置推断光照方向（需要观察多个样例来确认窗户位置与光照方向的对应关系），然后理解家具在光照方向上投射的是等宽的条状阴影。不同房间的窗户可能在不同墙壁上，因此光照方向是逐房间独立判定的，不是全局统一的。

  - 形态图案若超出网格边界则截断。墙壁保持不变。规则图例在输出中移除（输出仅包含主区域）。

- `Key insight`：解题需要三层归纳——首先发现视线被墙壁阻挡这一机制（而非简单的邻接或全局计数），然后发现 V=0 导致棋子消失而非变换，最后发现 V 值是查找图例中形态图案的键。三层机制叠加使得仅从单个样例难以同时推断所有规则。

- `description`：将网格中彩色种子沿灰色轨道滑动到最近的交叉点，两颗种子在交叉点相遇后混合生成新颜色，并用混合色填充交叉点相邻的封闭区域。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干水平和垂直的"轨道"，由 grey 像素构成，宽度为 1 像素。水平轨道与垂直轨道在某些位置相交，形成交叉点。
  - 轨道上散布着若干"种子"像素，每颗种子为单个彩色像素（如 red、blue、yellow），占据某条轨道上的一个位置（替代了该位置的 grey 像素）。每条轨道上最多有一颗种子。
  - 轨道将网格中的 black 区域分割成若干封闭矩形区域。

- `Rule`：
  - 第一步（种子滑动）：每颗种子沿其所在轨道向最近的交叉点滑动。若种子位于水平轨道上，则向左或向右滑到最近的交叉点；若位于垂直轨道上，则向上或向下滑到最近的交叉点。种子滑动后，原位置恢复为 grey，种子出现在交叉点上。
  - 第二步（颜色混合）：如果一个交叉点上恰好有两颗种子到达（一颗来自水平轨道，一颗来自垂直轨道），则该交叉点生成混合色。混合规则为固定配对：red + blue = magenta，red + yellow = orange，blue + yellow = green。若两颗种子颜色相同，则混合色即为该颜色本身。
  - 第三步（区域填充）：交叉点处的混合色向其相邻的封闭矩形区域扩散——将交叉点四周（上、下、左、右）紧邻的 black 封闭区域全部填充为混合色。若交叉点只有一颗种子到达（无混合发生），则不填充任何区域，该种子停留在交叉点上保持原色。
  - 轨道保持 grey（除发生混合的交叉点被混合色覆盖外）。未参与混合的种子保留原色和位置。

- `Key insight`：第一层推理需发现种子的滑动目标是最近的交叉点（而非轨道端点或某个固定方向）；第二层需发现只有两颗种子在同一交叉点相遇才触发混合和填充，单颗种子到达交叉点不产生任何效果；第三层需发现填充范围是交叉点四周被轨道围成的封闭矩形区域，而非沿轨道方向传播。

- `description`：根据封闭区域内标记点的颜色在边框颜色映射表中查找目标色，然后将该区域的边框重新着色，同时根据标记点的数量决定边框的绘制样式（实线、虚线或双线）。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干封闭矩形区域，每个区域由 grey 单像素宽的边框围成。区域大小各异，互不重叠。
  - 每个封闭区域内部有 1 至 3 个彩色单像素标记点（如 red、blue、green 等），其余内部像素为 black。
  - 网格右上角有一个"颜色映射表"：一个小矩形区域，内部排列着若干行，每行包含两个相邻的彩色像素——左侧像素为"查找色"，右侧像素为"目标色"。

- `Rule`：
  - 第一步（确定目标颜色）：对每个封闭区域，找到其内部所有标记点。取所有标记点中出现最多的那种颜色（若有并列则取在颜色映射表中排位靠上的），在颜色映射表的"查找色"列中找到匹配项，读取对应的"目标色"。
  - 第二步（确定边框样式）：统计该区域内部标记点的总数 N。若 N=1，边框样式为"实线"——边框所有像素都着色；若 N=2，边框样式为"虚线"——边框像素每隔一个着色一个、交替留空（从左上角开始着色）；若 N=3，边框样式为"双线"——在原边框外侧再画一圈同色边框，形成 2 像素宽的边框。
  - 第三步（重绘边框）：将该区域的 grey 边框替换为目标色，并按确定的样式绘制。内部标记点在输出中被擦除（替换为 black）。颜色映射表在输出中移除。

- `Key insight`：解题需要两层独立归纳——第一层发现标记点的主要颜色通过映射表转换为边框颜色（颜色的间接映射而非直接使用），第二层发现标记点的数量编码了三种不同的边框绘制样式。两层信息来源相同（标记点）但提取的属性不同（颜色 vs 数量），这增加了规则发现的难度。
</new_puzzle>
