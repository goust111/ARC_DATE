在包含多个嵌套环的同心结构中，根据环的层级关系和颜色标记规则，将内层环的图案"展开"复制到外层环的对应边上。

Input structure:
- bg = 黑色。
- 网格中有若干组同心矩形环结构。每组由2至3层嵌套的不同颜色空心矩形环组成（边框宽1像素），环与环之间间隔1像素的 bg 间隙。
- 最内层环的内部填充了一个由某种颜色绘制的小型图案（连通的非 bg 像素组成的形状）。
- 每层环的四条边中，恰好有一条边上嵌有一个 red 单像素标记（替换该边上某个像素）。

Rule:
- 第一步（识别展开方向）：每层环上 red 标记所在的边指示"展开方向"——内层环的图案将被复制到该边的外侧方向。
- 第二步（逐层展开）：从最内层开始向外处理。取最内层环内部的图案，将其沿最内层环 red 标记所在边的法线方向平移，放置到最内层环与次外层环之间的间隙中（图案的参考点对齐到 red 标记的位置）。
- 第三步（颜色继承）：被复制的图案不保留原色，而是改为它被放入的那一层间隙的外层环的颜色。
- 第四步（递归）：将刚放好的图案视为新的"内部图案"，继续按次外层环的 red 标记方向展开到下一层间隙，颜色改为更外层环的颜色。重复直到所有层处理完毕。
- 原始最内层图案保留不变，所有环结构保持不变，red 标记也保留。

Key insight: red 标记编码展开方向，每一层可能指向不同方向，形成折叠路径；颜色继承规则使得同一个图案在不同层呈现不同颜色——解题者必须理解"方向由标记决定、颜色由目标层决定"这一双重映射，并掌握从内到外的递归展开顺序。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
