- `description`：根据边框形状的缺口位置确定内部图案的旋转方向，再依据旋转后图案的颜色层叠顺序重新着色。
- `Input structure`：
  - 背景为 Black。
  - 网格中散布若干矩形边框，每个边框由单一颜色（如 Blue、Red、Green 等）的一像素线条围成，边框内部包含一个由两种颜色组成的小图案（3x3 或 4x4）。
  - 每个边框恰好有一个缺口（缺少一个边框像素），缺口位于上、下、左、右四条边之一。
  - 网格右下角有一个颜色图例区域：由两列色块组成，左列为"源颜色"，右列为"目标颜色"，每行表示一组映射关系。

- `Rule`：
  - 第一步（旋转）：根据每个边框缺口所在的边确定旋转角度——缺口在上边表示不旋转（0°），缺口在右边表示顺时针旋转 90°，缺口在下边表示旋转 180°，缺口在左边表示顺时针旋转 270°。将边框内部的图案按此角度旋转。
  - 第二步（重着色）：旋转完成后，查找右下角的颜色图例，将图案中每个像素的颜色按图例的映射关系替换为对应的目标颜色。若某颜色不在图例中，则保持不变。
  - 边框本身及其缺口保持原样不变。

- `Key insight`：缺口位置不是装饰——它编码了内部图案需要旋转的角度；旋转后还需要根据外部图例进行颜色替换，形成"几何变换 + 颜色映射"的双层推理。
</new_puzzle>

- `description`：将散落的碎片拼回被遮挡区域，拼接依据是碎片边缘轮廓与遮挡区域边界的锯齿互补匹配。
- `Input structure`：
  - 背景为 Azure。
  - 网格中央有一个大型多色图案，其中一块矩形区域被 Grey 色实心矩形完全遮盖。
  - Grey 矩形的四条边界处，大型图案的像素形成不规则的锯齿状轮廓（即边界不是直线，而是有凸出和凹陷的台阶形状）。
  - 网格边缘区域散布着若干小的多色碎片，每个碎片的一条边也呈现锯齿状轮廓。
  - 每个碎片恰好对应 Grey 遮挡区域某一侧的一段边界——碎片的锯齿边与遮挡区域对应侧的锯齿边完全互补（凸对凹、凹对凸）。

- `Rule`：
  - 第一步（匹配）：对每个碎片，检查其锯齿边缘的轮廓形状，找到 Grey 遮挡区域四条边界中与之互补的那一段。互补的判定标准：将碎片平移到遮挡区域边界旁时，碎片的锯齿凸起恰好填入边界的凹陷处，且碎片的凹陷处恰好对应边界的凸起处，整体严丝合缝。
  - 第二步（放置）：将碎片放置到 Grey 遮挡区域内对应的位置，碎片的锯齿边紧贴遮挡区域的边界。碎片仅需平移，不需要旋转或翻转。
  - 所有碎片放置后恰好完全填满整个 Grey 遮挡区域，输出中不再有 Grey 像素。

- `Key insight`：碎片不是通过颜色而是通过边缘几何轮廓的互补性来确定归属位置的——这类似拼图的咬合关系；解题者必须先忽略颜色信息，关注锯齿形状的空间互补。
</new_puzzle>

<new_puzzle>
- `description`：利用种子像素的颜色从颜色-方向编码表中查出生长方向，再让种子沿该方向生长出与其所在封闭区域面积等长的射线。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干由 Maroon 色线条围成的封闭区域（多边形房间），每个区域内部恰好有一个非 Black 非 Maroon 的单像素"种子"。
  - 网格的一个角落（如左上角）有一个小型编码表：表格由若干行组成，每行包含一个颜色色块和紧邻的一个箭头形状。箭头由同色像素构成，形状指示方向——向上的箭头（底部宽、顶部尖的三角形，3 像素宽 2 像素高）、向下的箭头（顶部宽、底部尖）、向左的箭头（右侧宽、左侧尖）、向右的箭头（左侧宽、右侧尖）。每种颜色恰好对应一个方向。

- `Rule`：
  - 第一步（查表确定方向）：读取角落编码表，建立颜色到方向的映射。对每个种子像素，根据其颜色查出对应的生长方向。
  - 第二步（计算区域面积）：数出种子所在封闭区域内部的 Black 像素总数（不含种子本身和 Maroon 边界）。该数值即为射线长度 N。
  - 第三步（生长射线）：从种子像素出发，沿查表得到的方向画一条长度为 N 的射线（N 个像素），颜色与种子相同。射线穿过 Maroon 墙壁和其他区域，不受阻挡。
  - Maroon 墙壁保持不变；若射线与墙壁像素重叠，射线颜色覆盖墙壁颜色。

- `Key insight`：三层推理——第一层需要识别角落的颜色-箭头编码表并建立映射，第二层需要将种子的封闭区域面积与射线长度关联起来，第三层是执行生长操作。编码表的存在使得颜色不再直接决定方向，必须先"查字典"。
</new_puzzle>

- `Input structure`：
  - 背景为 Yellow。
  - 网格中有若干形状相同但内部图案不同的小矩形片段（如 4x3 大小），每个片段有一个 Grey 边框包围着内部的多色图案。
  - 片段之间由单像素宽的彩色连接线相连——连接线从一个片段的 Grey 边框出发，经过若干直角转弯，连接到另一个片段的 Grey 边框。
  - 连接线有两种颜色：Red 和 Blue。
  - 网格底部有一行等距排列的空槽位（用 Magenta 边框标识的空矩形区域），槽位数量等于片段数量。
  - 最左侧的一个片段旁有一个 Green 单像素标记，标识起始片段。

- `Rule`：
  - 第一步（确定排列顺序）：从 Green 标记的起始片段出发，沿连接线逐步访问下一个片段，形成一条链式遍历顺序。每个片段恰好被访问一次。
  - 第二步（确定翻转方式）：到达每个片段所经过的连接线颜色决定该片段是否翻转——若经过 Red 连接线到达，则将该片段水平翻转（左右镜像）；若经过 Blue 连接线到达，则保持原样不变。起始片段不翻转。
  - 第三步（填入槽位）：按遍历顺序将片段（翻转后的版本）依次从左到右填入底部的 Magenta 槽位中。

- `Key insight`：双层推理——第一层需要通过连接线追踪确定片段的排列顺序（这不是简单的空间位置排序），第二层需要发现连接线颜色编码了翻转指令。两层信息共同决定输出。
</new_puzzle>

- `description`：识别网格中被隐藏的对称轴类型，用对称轴的类型决定如何合并重叠的双层图案。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干独立的矩形区域，每个区域内包含两层图案的叠加：底层图案用较暗的颜色（Maroon、Blue、Green 之一）绘制，顶层图案用较亮的颜色（Orange、Azure、Yellow 对应绘制）。两层图案在部分像素位置重叠，重叠处显示为顶层颜色。
  - 每个矩形区域外侧的某一条边上有一个单像素标记，标记颜色为 Red 或 Magenta。
  - 在每个矩形区域中，底层图案（暗色）具有某种对称性——要么关于水平中轴对称，要么关于垂直中轴对称，要么关于主对角线对称。顶层图案（亮色）不具有任何对称性。

- `Rule`：
  - 第一步（恢复底层）：在每个矩形区域中，利用底层图案的对称性恢复被顶层遮挡的底层像素。具体方法：找出底层颜色的可见像素，判断其对称类型（水平/垂直/对角线），然后将被顶层覆盖的底层像素通过对称性补全。
  - 第二步（选择输出层）：根据矩形外侧标记的颜色决定输出内容——Red 标记表示输出恢复后的完整底层图案（仅暗色像素，背景为 Black），Magenta 标记表示输出顶层图案（仅亮色像素，包括原本被底层遮挡的部分也要通过底层补全后"挖去"底层得到）。
  - 输出网格仅包含所选图层的内容，每个矩形区域裁剪为紧凑大小后按原始空间顺序排列。

- `Key insight`：三层推理——第一层需要从混合图案中分离出两个颜色层并发现底层具有对称性，第二层需要利用对称性恢复被遮挡的完整底层，第三层需要理解外部标记颜色编码了"选择哪一层输出"的指令。对称类型不是给定的，必须从可见像素中自行推断。
</new_puzzle>

- `description`：将网格中管道网络的断口用正确颜色修补，修补颜色由断口两端的管道颜色混合规则决定。
- `Input structure`：
  - 背景为 Grey。
  - 网格中有若干条由不同颜色绘制的单像素宽管道线段（水平或垂直方向），管道颜色包括 Red、Blue、Yellow、Green。
  - 部分管道之间存在断口——两条不同颜色的管道末端之间相隔 1-3 个 Grey 像素的间隙，且两条管道的末端在同一行或同一列上正对。
  - 网格的一角有一个颜色混合图例：图例由若干小方块组成，每个方块左半边是一种颜色、右半边是另一种颜色，下方紧贴一个小方块显示混合结果颜色。例如 Red+Blue 下方标注 Magenta，Red+Yellow 下方标注 Orange，Blue+Yellow 下方标注 Green，等等。
  - 部分管道末端是"死端"（仅一侧有管道面对断口，另一侧没有对应的管道），这些断口不需要修补。

- `Rule`：
  - 第一步（识别断口对）：扫描网格找到所有正对的管道末端对——两条管道在同一行或同一列上，末端之间仅隔 Grey 背景像素，中间无其他管道或对象阻挡。忽略死端。
  - 第二步（查找混合颜色）：对每对断口，取两端管道的颜色，在角落的混合图例中查找这两种颜色的混合结果颜色。
  - 第三步（修补断口）：用查到的混合颜色填充断口间的所有 Grey 像素，将两条管道连接起来。
  - 若两条管道颜色相同，则直接用该颜色填充断口，无需查图例。

- `Key insight`：双层推理——第一层需要在管道网络中识别哪些断口是需要修补的"正对"对（排除死端），第二层需要发现修补颜色不是简单取某一端的颜色，而是通过角落图例将两端颜色"混合"后得到的新颜色。图例是解码关键。
</new_puzzle>

- `description`：将嵌套框架中每一层框架的颜色作为索引，从外部调色板中读取对应的填充图案，由外向内逐层填充。
- `Input structure`：
  - 背景为 Black。
  - 网格主体包含一组同心嵌套的矩形框架（如 3-5 层），每层框架由不同颜色的单像素线条构成，框架之间有 2-3 像素的间隔（填充为 Black）。最内层框架内部也是 Black。
  - 网格右侧有一个调色板区域：由若干小矩形块纵向排列，每个小矩形块左侧边缘有一个单像素颜色标识，右侧是一个 2x2 或 3x3 的小型填充图案（由两种颜色交替组成，如棋盘格、条纹、十字等不同纹理）。

- `Rule`：
  - 第一步（匹配框架与图案）：对每层框架，根据框架线条的颜色在右侧调色板中找到颜色标识相同的条目，读取其对应的填充图案。
  - 第二步（由外向内填充）：从最外层框架开始，将该层框架与下一层框架之间的间隔区域用对应的填充图案进行周期性平铺填充。最内层框架的内部用最内层框架颜色对应的图案填充。
  - 第三步（处理覆盖）：框架线条本身保持原色不变，不被图案覆盖。填充图案从该层间隔区域的左上角开始平铺，超出区域的部分裁剪。
  - 调色板区域在输出中被移除（输出网格仅包含嵌套框架区域的紧凑裁剪）。

- `Key insight`：双层推理——第一层需要识别嵌套框架的层次结构并将每层框架颜色与调色板条目匹配，第二层需要理解填充图案是周期性平铺的纹理而非单次拷贝，且填充方向是由外向内逐层进行。框架颜色既是视觉结构也是查表索引，一物两用。
</new_puzzle>
