- `Input structure`：
  - 背景为 Black。
  - 网格中有若干由 Maroon 色线条围成的封闭区域（多边形房间），每个区域内部恰好有一个非 Black 非 Maroon 的单像素"种子"。
  - 网格的一个角落（如左上角）有一个小型编码表：表格由若干行组成，每行包含一个颜色色块和紧邻的一个箭头形状。箭头由同色像素构成，形状指示方向——向上的箭头（底部宽、顶部尖的三角形，3 像素宽 2 像素高）、向下的箭头（顶部宽、底部尖）、向左的箭头（右侧宽、左侧尖）、向右的箭头（左侧宽、右侧尖）。每种颜色恰好对应一个方向。

- `Rule`：
  - 第一步（查表确定方向）：读取角落编码表，建立颜色到方向的映射。对每个种子像素，根据其颜色查出对应的生长方向。
  - 第二步（计算区域面积）：数出种子所在封闭区域内部的 Black 像素总数（不含种子本身和 Maroon 边界）。该数值即为射线长度 N。
  - 第三步（生长射线）：从种子像素出发，沿查表得到的方向画一条长度为 N 的射线（N 个像素），颜色与种子相同。射线穿过 Maroon 墙壁和其他区域，不受阻挡。
  - Maroon 墙壁保持不变；若射线与墙壁像素重叠，射线颜色覆盖墙壁颜色。

- `Key insight`：三层推理——第一层需要识别角落的颜色-箭头编码表并建立映射，第二层需要将种子的封闭区域面积与射线长度关联起来，第三层是执行生长操作。编码表的存在使得颜色不再直接决定方向，必须先"查字典"。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
