  - 背景色为 black。网格尺寸约 15x15 至 25x25。

  - 箭头的绘制方式：每个箭头由 3 个像素组成，呈 L 形排列。L 形的长边（2 像素）为箭头杆，短边（1 像素）垂直于杆的末端伸出，形成箭头尖端。箭头指向的方向为从杆的起点朝杆的末端（即尖端所在端）的方向。箭头颜色为单一颜色（如 red、blue、green 等）。
  - 货物对象：由 maroon 像素组成的小型连通图形（3-6 像素，形状各异），散布在网格各处。
  - 箭头和货物对象之间不接触，且箭头沿指向方向延伸的直线上至少会遇到一个货物对象。
- `Rule`：
  - 对每个箭头：
    - 确定箭头的指向方向（上、下、左、右之一）和箭头杆起点的位置（即远离尖端的那一端）。
    - 从箭头尖端沿指向方向扫描，找到该方向上遇到的第一个货物对象。
    - 将该货物对象从原位置移除（变为背景色）。
    - 将货物对象搬运到箭头杆起点的对称位置：即以箭头杆起点为基准，货物对象相对于箭头尖端的偏移量取反后放置。换言之，货物出现在箭头的"背后"，与原货物到箭头尖端的距离相同。
    - 搬运后的货物对象颜色从 maroon 替换为该箭头的颜色。
  - 箭头像素在输出中保留不变。
  - 未被任何箭头指向的货物对象保持不变。
- `Key insight`：第一层推理需要识别 3 像素 L 形为箭头并确定其指向方向；第二层推理需要发现箭头的作用是"抓取"前方最近的货物并将其搬到身后对称位置；第三层推理需要发现箭头颜色决定了搬运后货物的重新着色。箭头既是方向指示器、又是距离参照点、又是颜色指令，一个对象承载三重语义。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
