  - 背景色为 black。
  - 网格中有若干成对出现的同色小方块（2x2），每种颜色恰好出现两个方块，构成一对"传送门"。颜色可能包括 red、blue、green、orange 等，共 2-4 对。
  - 每对传送门的两个方块分别位于网格的不同位置。
  - 网格某一条边上有一个 maroon 色的单像素"发射器"，以及紧邻发射器内侧的一个 yellow 色箭头标记（由 3 个像素组成的 L 形或直线形），指示射线的初始发射方向（上、下、左、右四个基本方向之一）。

- `Rule`：
  - 从发射器出发，沿 yellow 箭头指示的方向发射一条 maroon 色射线（逐像素延伸）。
  - 射线沿途如果碰到某个传送门方块的边缘像素，射线立即从该传送门的配对方块的对应边缘位置射出。射出方向为入射方向的延续（保持不变），但射线从配对方块的对侧边缘开始继续。
  - 射线从传送门出口射出后，颜色变为该出口传送门方块的颜色。
  - 射线继续延伸，可以再次进入其他传送门（或同一对的另一个），规则相同。
  - 射线到达网格边界时停止。
  - 传送门方块本身保留原色不变，射线覆盖的背景像素被着色。

- `Key insight`：解题者需要逐层拆解三个嵌套机制——第一层：识别同色方块对构成传送门（颜色配对）；第二层：理解射线遇到传送门时的空间映射关系（从一个方块进入，从配对方块的对侧射出，方向不变）；第三层：射线颜色在每次传送后继承出口门的颜色，因此最终路径呈现分段变色的特征。仅靠单个样例很难区分这三层规则，需要多个样例中不同的门排列和射线路径来逐一验证。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
