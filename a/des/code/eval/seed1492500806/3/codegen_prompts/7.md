- `description`：网格中的彩色像素构成一棵隐含的树结构，根据树的层级关系对每层节点施加不同的颜色变换，输出变换后的树形图案。
- `Input structure`：背景为 Black 的网格中，有一个由 Grey 像素组成的点作为"根节点"，位于网格上方。从根节点出发，向下延伸出由 Grey 像素组成的垂直或对角线段（"树枝"），树枝末端连接着彩色像素节点。这些彩色节点可以继续向下延伸新的 Grey 树枝，连接更深层的彩色节点，形成一棵层级树。每层节点的颜色各不相同（第一层可能是 Red，第二层是 Blue，第三层是 Green 等）。在网格最左侧一列，从上到下排列着若干小的颜色方块（2×2），构成"变换图例"——每个方块的左半是一种颜色（输入色），右半是另一种颜色（输出色），表示颜色映射关系。
- `Rule`：根据变换图例中的颜色映射，将树中每个彩色节点的颜色替换为映射后的颜色。Grey 根节点和 Grey 树枝保持不变。关键约束是：颜色映射的应用具有层级依赖性——第 N 层节点的映射必须在第 N-1 层映射完成后才能确定，因为映射规则是"将当前颜色映射为图例中对应的输出色，但若该节点的父节点映射后的输出色与该节点的当前输入色相同，则该节点不进行映射，保持原色"。换言之，子节点会"避让"与已变换的父节点颜色相同的情况。变换图例中的方块本身在输出中被移除（替换为 Black）。
- `Key insight`：表面上看是简单的查表换色，但隐含的层级依赖条件使得换色过程必须自顶向下逐层进行。解题者需要先识别出树的层级结构（通过 Grey 树枝的连接关系），再识别图例中的颜色映射，最后理解"子节点避让父节点新色"的条件规则。这三层认知结构使得问题远比表面的颜色替换复杂。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
