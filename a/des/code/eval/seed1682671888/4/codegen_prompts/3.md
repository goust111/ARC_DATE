- `Input structure`：
  - bg = 最常见颜色。
  - 网格中有若干条由 grey 像素绘制的单像素宽路径，路径沿水平或垂直方向延伸，在某些位置形成十字交叉或 T 形交叉。
  - 每条路径的一个端点处有一个彩色起点标记（单像素，颜色各异，如 red、green、blue 等），位于路径末端且与路径的第一个 grey 像素 4-邻接。
  - 每条路径的另一个端点处有一个 maroon 的终点标记（单像素），与路径末端的 grey 像素 4-邻接。
  - 在每个交叉口（grey 像素在至少三个方向上有 grey 邻居的位置）处，恰好有一个与交叉口中心 4-邻接的 bg 位置被着色为 yellow 或 orange，作为方向指示器。

- `Rule`：
  - 信号从每个彩色起点出发，沿 grey 路径传播，将经过的 grey 像素染成起点的颜色。
  - 当信号到达一个交叉口时，检查方向指示器相对于信号行进方向的位置：指示器在行进方向的左侧 → 信号左转；指示器在行进方向的右侧 → 信号右转；指示器在信号正前方的侧方不存在（即指示器在来路方向）→ 信号直行。
  - 信号到达 maroon 终点时停止。统计从起点到终点经过的路径像素数量（含起点和终点像素）。
  - 在终点位置，向上绘制一个高度等于该路径像素数量的单像素宽竖直柱，颜色为起点颜色。竖直柱从终点位置向上延伸。
  - 交叉口的方向指示器像素在输出中保持不变。

- `Key insight`：解题者需要先理解方向指示器的相对方位编码（左/右是相对于信号行进方向，而非绝对方向），再发现路径长度转化为竖直柱高度的计数映射——方向解码和计数-几何转换是两个需要分别归纳的规则层。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
