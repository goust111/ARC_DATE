- `description`：根据边框上的彩色锚点确定对象所属区域，再依据区域内"模板孔洞"的形状对对象进行裁剪，最终将裁剪后的对象拼贴到输出网格的对应区域中。

- `Input structure`：
  - bg = 最常见颜色（背景色）。
  - 网格被一条贯穿整行的灰色(Grey)分隔线和一条贯穿整列的灰色分隔线分成四个象限。
  - 每个象限的外边框边缘上各有一个单像素彩色锚点（四个象限的锚点颜色两两不同，共使用四种非背景、非灰色的颜色）。
  - 每个象限内部包含一个由该象限锚点颜色绘制的实心矩形块（3×3 至 5×5 不等）。
  - 在灰色分隔线的交叉点附近（不属于任何象限的中央区域），有一个由背景色和非背景色构成的小型"模板"图案。模板图案是一个与实心矩形块同尺寸的方块，内部有若干像素被挖去（设为背景色），形成孔洞形状。模板图案中非背景像素使用 Maroon 色。
  - 另外，在网格的四个角落区域各有一个小型单色精灵（sprite），颜色与四个象限的锚点颜色一一对应，每个精灵的形状各不相同。

- `Rule`：
  - 第一层推理——区域匹配：将每个角落精灵按其颜色匹配到对应锚点颜色的象限。
  - 第二层推理——模板裁剪：将中央模板的孔洞形状作为"饼干模具"应用到每个象限的实心矩形块上：模板中为背景色的位置，在矩形块上也变为背景色（挖去）；模板中为 Maroon 的位置保留矩形块原色。
  - 第三层推理——精灵填充：将匹配到该象限的角落精灵的形状与被挖去的孔洞形状进行叠加——精灵的非背景像素若落在孔洞位置，则用精灵的颜色填充该孔洞像素；若精灵像素落在非孔洞位置，则忽略。
  - 输出网格仅包含四个经过裁剪和填充后的矩形块，按原始象限位置排列，中间由一行/一列灰色分隔。

- `Key insight`：角落精灵的颜色决定了它属于哪个象限，而中央模板的孔洞形状既决定了矩形块的裁剪方式，也定义了精灵颜色可以"渗入"的位置——精灵实际上是孔洞的补色填充物。

<new_puzzle>
- `description`：根据种子像素的颜色在网格中生长出有向"藤蔓"，藤蔓的生长方向由相邻导轨条的朝向决定，藤蔓在交叉时按颜色优先级覆盖。

- `Input structure`：
  - bg = 最常见颜色（背景色）。
  - 网格中散布着若干短小的单色线段（长度 2-4 像素），称为"导轨"。每条导轨为水平或垂直方向，颜色为 Grey。
  - 在部分导轨的一端（紧邻导轨端点、垂直于导轨方向的位置）有一个彩色单像素"种子"。不同种子使用不同颜色（如 Red、Blue、Green、Orange 等）。
  - 每个种子恰好紧邻一条导轨的某一端。

- `Rule`：
  - 从每个种子出发，沿其相邻导轨的方向延伸一条藤蔓（与导轨同向）。藤蔓颜色与种子颜色相同。
  - 藤蔓在前进过程中，如果下一个位置遇到另一条导轨（Grey 线段），则藤蔓转弯：新方向为该导轨的朝向。藤蔓转弯后继续沿新方向前进。
  - 藤蔓在以下情况停止：到达网格边界、或下一个位置已被同色藤蔓占据（即自身路径形成环）。
  - 如果两条不同颜色的藤蔓在同一像素交叉，按以下视觉规则决定覆盖：像素数量较少的藤蔓（即总长度较短的那条）覆盖在上层。若长度相同，保留先遇到该像素的藤蔓颜色（即按种子在网格中从上到下、从左到右的扫描顺序）。
  - 导轨自身（Grey 像素）在输出中保持不变。

- `Key insight`：导轨不仅是障碍物，更是方向编码器——藤蔓"读取"导轨的朝向来决定转弯方向，形成一个由导轨网络定义的确定性路径。解题者需要先理解导轨作为方向信号的角色，再追踪每条藤蔓的完整路径。
</new_puzzle>

- `description`：识别网格中由边框围成的封闭房间，根据房间内"钥匙"精灵的形状找到匹配的"锁孔"（墙壁缺口），然后将钥匙精灵的颜色沿缺口方向向外喷射，填充到相邻房间中。

- `Input structure`：
  - bg = 最常见颜色（背景色）。
  - Azure 色的线段构成墙壁，将网格分割为若干封闭的矩形房间。每面墙壁上可能有一个或多个缺口（宽度 1-3 像素的间断）。
  - 每个房间内部可能包含：
    - 一个小型彩色精灵（"钥匙"），由 2-4 个像素组成，形状各异（L形、T形、直线形等），颜色为非背景、非 Azure 的某种颜色。
    - 或者房间为空（无精灵）。
  - 每个缺口的形状（即缺口内被省略的墙壁像素的排列方式）也构成一个 pattern，与某个钥匙精灵的形状相同（经旋转或翻转后匹配）。

- `Rule`：
  - 第一层推理——形状匹配：对于每个包含钥匙精灵的房间，检查该房间所有墙壁上的缺口。将钥匙精灵的形状（允许旋转和翻转）与缺口形状进行匹配，找到形状一致的那个缺口。
  - 第二层推理——颜色喷射：从匹配的缺口出发，沿缺口朝向的方向（即从当前房间穿过缺口进入相邻房间的方向），用钥匙的颜色填充一条射线。射线宽度等于缺口宽度，射线一直延伸到碰到下一面 Azure 墙壁为止。
  - 钥匙精灵本身在输出中保持原位不变。未被匹配的缺口保持为背景色。

- `Key insight`：缺口不是随机的墙壁破损，而是编码了"只有形状匹配的钥匙才能打开"的信息。解题者必须先发现钥匙形状与缺口形状的对应关系，然后才能确定喷射的方向和范围。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片按照隐含的层级关系逐层嵌套组装，每层的嵌套位置由碎片边缘的单像素颜色标记指定。

- `Input structure`：
  - bg = 最常见颜色（背景色）。
  - 网格中散布着若干矩形单色碎片（每个碎片是一个实心矩形，大小各异，颜色各不相同）。
  - 每个碎片的边缘上可能有 0 或 1 个单像素标记，标记的颜色与另一个碎片的主体颜色相同。
  - 恰好有一个碎片没有被任何其他碎片的标记所引用——它是最外层的"底座"。
  - 恰好有一个碎片的边缘上没有标记——它是最内层的"核心"。

- `Rule`：
  - 第一层推理——确定嵌套顺序：通过标记颜色建立碎片之间的引用链。碎片 A 边缘的标记颜色若等于碎片 B 的主体颜色，则 B 嵌套进 A 的内部。从底座开始，沿引用链逐层向内排列。
  - 第二层推理——确定嵌套位置：标记像素在碎片 A 边缘上的位置（上/下/左/右的哪条边、以及沿该边的偏移量）决定了碎片 B 在 A 内部的放置位置。具体规则：标记在 A 的上边 → B 的顶边与 A 的顶边内侧对齐；标记在 A 的左边 → B 的左边与 A 的左边内侧对齐；以此类推。标记沿该边的偏移比例（标记位置占该边长度的比例）决定 B 在垂直于该边方向上的对齐位置（按相同比例放置）。
  - 第三层推理——组装输出：从底座开始，逐层将碎片嵌入。内层碎片覆盖外层碎片的像素。输出网格为底座的 bounding box 大小。

- `Key insight`：边缘标记同时编码了两个信息——"谁嵌套进来"（颜色）和"嵌套在哪里"（位置）。解题者需要先通过颜色链建立层级关系，再通过标记的空间位置确定几何放置，两步推理缺一不可。
</new_puzzle>

- `description`：在网格中识别多个"信号塔"及其覆盖范围，根据覆盖重叠情况对区域进行混色填充，同时被遮罩图案屏蔽的区域不接收任何信号。

- `Input structure`：
  - bg = 最常见颜色（背景色），通常为 Black。
  - 网格中散布着若干个"信号塔"：每个信号塔由一个 1×1 的彩色像素（塔芯）和紧邻塔芯的一圈同色像素组成，整体为 3×3 的实心方块，颜色各不相同（如 Red、Blue、Green、Yellow 等）。
  - 每个信号塔的 3×3 方块的四条边的中心像素（上、下、左、右各一个）中，有 1-4 个被替换为 Orange 色，称为"天线"。天线的位置指示该信号塔向哪些方向广播。
  - 网格中还有一个由 Grey 色像素构成的连通图案，称为"遮罩"。遮罩可以是任意形状。

- `Rule`：
  - 第一层推理——确定广播方向：每个信号塔从其 Orange 天线所在的方向发射"信号带"。信号带从塔芯出发，沿天线方向延伸至网格边界。信号带的宽度为 3 像素（与信号塔等宽），颜色为塔芯颜色。
  - 第二层推理——遮罩屏蔽：Grey 遮罩所覆盖的像素不接收任何信号。信号带遇到遮罩像素时，该像素保持 Grey 不变，但信号带不会被阻断——信号会穿过遮罩继续传播到遮罩后方的区域。
  - 第三层推理——重叠混色：当两条不同颜色的信号带覆盖同一个非遮罩像素时，该像素的颜色按以下规则确定：Red + Blue → Magenta，Red + Green → Yellow，Blue + Green → Azure。若三条或更多信号带重叠，按两两混色规则依次叠加（按颜色在上述列表中的出现顺序）。若同色信号带重叠，保持该颜色不变。
  - 信号塔本身（3×3 方块）在输出中保持不变。

- `Key insight`：天线位置编码了广播方向，而遮罩创造了"信号阴影"但不阻断传播——解题者需要先追踪每个塔的信号覆盖区域，再理解遮罩的穿透特性，最后处理重叠区域的混色逻辑。三层规则相互独立但共同决定最终输出。
</new_puzzle>

- `description`：根据网格边缘的彩色刻度尺读取坐标，将散落的单像素标记连线后，在线段交汇处生成由交汇颜色决定的填充图案。

- `Input structure`：
  - bg = 最常见颜色（背景色）。
  - 网格的顶部边缘和左侧边缘各有一行/一列"刻度尺"：刻度尺由交替出现的背景色和彩色像素组成，彩色像素的颜色不重复，每种颜色在顶部和左侧各出现恰好一次。
  - 网格内部（刻度尺以内的区域）散布着若干单像素标记。每个标记的颜色与某个刻度尺颜色相同。
  - 网格内部还存在若干小型（2×2 或 3×3）的单色"图章"精灵，每个图章精灵的颜色各不相同，且与刻度尺颜色均不相同。图章精灵内部有特定形状（非实心，有孔洞或缺角）。

- `Rule`：
  - 第一层推理——坐标对齐：每个内部标记像素的颜色对应顶部刻度尺和左侧刻度尺上的同色刻度。从顶部刻度向下画一条垂直线，从左侧刻度向右画一条水平线。标记像素必然位于这两条线的交点上（这验证了颜色-坐标的对应关系）。
  - 第二层推理——交叉检测：找到所有由不同颜色标记产生的线段的交叉点。即：标记 A 的垂直线与标记 B 的水平线的交点，以及标记 A 的水平线与标记 B 的垂直线的交点。
  - 第三层推理——图章放置：在每个交叉点处，选择与该交叉点距离最近的图章精灵（视觉上最近的那个），将该图章的形状以交叉点为中心复制一份，颜色使用产生该交叉的两个标记颜色中、在刻度尺上位置更靠前（更靠近左上角）的那个颜色。原始标记像素和刻度尺在输出中保持不变。

- `Key insight`：刻度尺将颜色编码为坐标，每个标记像素隐含地定义了一对正交线段；解题者需要先破解颜色-坐标映射，再发现线段交叉产生图章放置的规则，最后确定图章选择和着色逻辑。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中被分隔线划分的区域，将每个区域内的图案视为一条"指令"，按区域从左到右的顺序依次对一个初始画布执行变换操作，最终输出变换后的画布。

- `Input structure`：
  - bg = 最常见颜色（背景色），通常为 Black。
  - 网格被若干条竖直的 Maroon 色分隔线（贯穿整列）分成若干个等宽区域（通常 3-5 个区域）。
  - 最左侧的区域包含一个小型彩色图案，称为"初始画布"（例如一个 4×4 的多色图案）。
  - 其余每个区域内包含一个"指令图案"，由以下元素构成：
    - 一个与画布同尺寸的网格轮廓（由 Grey 像素勾勒的边框）。
    - 轮廓内部分位置有彩色像素，表示"在画布的这些位置用这些颜色覆盖"。
    - 轮廓外部可能有一个方向箭头（由 Red 像素组成的 L 形或直线形标记，指向上/下/左/右四个方向之一）。箭头由 3 个像素组成：一条 2 像素的线段加一个垂直于线段末端的像素，整体指向某个方向。

- `Rule`：
  - 第一层推理——指令解析：每个指令区域编码一个操作。若区域内只有轮廓和内部彩色像素（无箭头），则操作为"覆盖"——将彩色像素覆盖到画布对应位置。若区域内有箭头，则操作为"先将当前画布沿箭头方向平移一格（溢出部分丢弃，空出部分填充背景色），再执行覆盖"。
  - 第二层推理——顺序执行：从左到右依次读取每个指令区域，将操作按顺序应用到画布上。每一步的输出作为下一步的输入。
  - 输出网格仅包含最终画布（与初始画布同尺寸）。

- `Key insight`：每个分隔区域不是独立的图案，而是一条按顺序执行的"指令"。解题者需要先理解区域即指令的隐喻，再区分"覆盖"和"平移+覆盖"两种操作模式（由箭头的有无决定），最后按顺序模拟执行才能得到正确输出。
</new_puzzle>
