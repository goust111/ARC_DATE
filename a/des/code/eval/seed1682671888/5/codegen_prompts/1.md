Input structure:
- bg = 背景色（Black）。网格中有若干用同一种边框色（如 Blue）绘制的不规则封闭轮廓，每个轮廓围出一块区域。
- 网格右下角有一个"模板图例区"，用 Grey 线框隔开。图例区内纵向排列着若干小型标准形状（如 3×3 十字、3×3 L 形、3×3 T 形等），每个标准形状用独特的颜色绘制。每个标准形状旁边紧邻一个由 1-3 个不同颜色像素组成的"签名"（signature）——这些像素的颜色组合与排列方式是唯一的。
- 每个主网格封闭轮廓的内部散落着若干与某个签名完全相同的颜色像素（颜色种类与相对位置模式一致），但可能被平移到了区域内的任意位置。

Rule:
- 第一步：对每个封闭轮廓，收集其内部所有非背景、非边框色的像素，提取它们的颜色集合与相对位置模式（平移无关），与图例区中各签名进行匹配，找到对应的模板形状。
- 第二步：计算该封闭轮廓的外接矩形中心，以此中心为锚点，将匹配到的模板形状放大到与该轮廓外接矩形等宽等高（每个模板像素扩展为 k×k 的块，k = 外接矩形边长 ÷ 模板边长，向下取整），用边框色绘制放大后的模板形状，替换掉原来的不规则轮廓。
- 第三步：清除轮廓内部的签名像素，内部回归背景色。

Key insight: 内部散落的彩色碎片不是装饰，而是一组"颜色签名"，用于在图例中查找该区域应当呈现的标准形状；解题者需要先识别签名匹配机制，再理解轮廓被模板形状替换的缩放规则。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
