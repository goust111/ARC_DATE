根据箭头指向在网格中建立"投影链"，每个对象将自身形状沿箭头方向投影到下一个对象表面，并按投影顺序叠加着色。

Input structure:
- bg = 背景色（Black）。网格中散布着若干由单一颜色填充的小型矩形色块（宽高均 ≤ 5），每个色块颜色各不相同。
- 每个色块的某一侧边（上、下、左或右）外紧邻一个由 Red 像素组成的三像素箭头。箭头形状为：沿色块边缘外侧一格放置一个 Red 中心像素，然后在该中心像素的垂直于指向方向的两侧各放置一个 Red 像素，构成一个指向外侧的"V"形尖端。箭头尖端朝外的方向即为该色块的投影方向。

Rule:
- 第一步（建立投影链）：从每个色块出发，沿其箭头方向做直线延伸，找到射线上碰到的第一个其他色块——该色块即为投影目标。如果射线方向上没有其他色块，则该色块是链的末端。由此所有色块形成若干条单向链。
- 第二步（执行投影）：沿链从起点到末端依次处理。当色块 A 投影到色块 B 时，将 A 的矩形形状以 A 的颜色"印"在 B 所在的位置上：投影的锚点为 B 沿投影方向的迎面边的中心像素，A 的形状以该锚点为中心对齐绘制。投影的像素覆盖在 B 之上。
- 第三步：处理完所有投影后，移除所有 Red 箭头像素，将箭头位置恢复为背景色。原色块保持原位不动。

Key insight: 箭头不仅指示方向，还隐含了投影链的拓扑顺序——解题者需要先通过箭头方向和射线命中关系重建整条链的先后顺序，再理解"形状印到目标表面"的对齐规则；多层叠加时后投影覆盖先投影的结果。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
