- `Input structure`：
  - bg = black。
  - 网格被红色（red）的十字线（一条完整的水平线和一条完整的垂直线）分成四个矩形分区（左上、右上、左下、右下）。
  - 四个分区中，恰好有两个对角分区（如左上和右下，或右上和左下）各包含一个单独的彩色种子像素（非红、非黑的颜色），另外两个对角分区的边界处（紧邻红色十字线的那一行或一列）绘有由灰色（grey）像素组成的图案片段。
  - 灰色图案片段为一维排列（沿着紧邻十字线的一行或一列），可能有间断。

- `Rule`：
  - 第一层（识别种子与图案的配对关系）：每个种子像素与其水平方向相邻的分区中的灰色图案配对（左上的种子配对右上分区底边的图案，右下的种子配对左下分区顶边的图案；或类似的对称配对）。具体规则：种子所在分区的水平邻居分区中，靠近十字线的那一行/列的灰色图案即为该种子的"生长模板"。
  - 第二层（解读生长模板）：灰色模板是一维的像素序列（有灰色和背景色两种），将其解读为生长指令：灰色像素 = 向前伸展1格，背景色像素 = 向侧方偏移1格（偏移方向固定为：若种子在十字线左侧则向左偏，若在右侧则向右偏）。
  - 第三层（执行生长）：从种子像素开始，沿垂直方向（远离十字线的方向）逐步执行模板指令，用种子的颜色逐像素绘制生长路径。若路径碰到网格边界则停止。模板读完后若未到边界，则循环重复模板继续生长。

- `Key insight`：种子本身只提供颜色和起点，其生长形状完全由另一个分区的边界图案编码——解题者必须跨分区寻找配对关系，再将一维图案解码为二维路径指令，形成"跨区配对 → 图案解码 → 路径生成"的三层结构。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
