- `description`：根据彩色框架内部的隔断结构选择对应的填充模板，再用框架自身颜色对模板着色后嵌入框架内部。

- `Input structure`：
  - bg = black。
  - 网格中散布着若干不同颜色的矩形空心框架（边厚1像素），每个框架内部被同色的水平或垂直隔墙分割成若干个大小不等的背景色房间。
  - 网格的一个边缘（例如底部两行）排列着若干灰色（grey）小型模板图案，每个模板是一个由灰色像素组成的紧凑连通形状，放置在独立的小方格区域内，各模板之间用背景色间隔。每个模板的像素数量各不相同。

- `Rule`：
  - 第一层：对每个彩色框架，数出其内部被隔墙分割出的独立房间的数量 N。
  - 第二层：在底部模板区中找到像素数恰好等于 N 的那个灰色模板。
  - 第三层：将该模板的灰色像素全部替换为框架的颜色，然后将着色后的模板放置到框架内部最大房间的左上角（模板保持原始朝向，不旋转不翻转）。
  - 输出时底部模板区域保持不变，仅框架内部发生变化。

- `Key insight`：框架内部隔断产生的房间数是匹配模板的索引键；模板被重新着色为框架颜色后才嵌入，形成"计数 → 查找 → 着色放置"的三层推理链。
</new_puzzle>

- `description`：沿彩色路径行走，在每个拐弯处根据转向方向向外侧射出与路径同色的射线，射线长度等于刚走过的直线段的像素长度。

- `Input structure`：
  - bg = black。
  - 网格中有一条或多条单像素宽的彩色折线路径（每条路径使用不同颜色），每条路径由若干水平和垂直的直线段首尾相连组成，形成若干直角拐弯。
  - 每条路径的一端有一个同色的 2x1 或 1x2 矩形块作为"起点标记"，标记的朝向（水平或垂直）指示路径的初始行走方向。

- `Rule`：
  - 从起点标记出发，沿路径依次经过每个直线段。
  - 在每个拐弯处，判断转向方向（左转或右转）。
  - 向拐弯的外侧方向（即转弯圆弧的外侧，若左转则向右侧，若右转则向左侧）发射一条与路径同色的射线。
  - 射线的长度（像素数）等于刚刚走过的那一段直线段的像素长度（不含拐弯像素本身）。
  - 射线从拐弯像素出发，沿外侧方向延伸，遇到非背景像素或网格边界时提前截断。
  - 路径本身保持不变，仅新增射线像素。

- `Key insight`：需要先从起点标记推断行走方向以确定每个拐弯的左右转性质（同一个拐弯从不同方向走过来左右转相反），再用前一段的长度决定射线长度——行走方向和段长度两层信息共同决定射线的方位与尺寸。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的单色碎片按颜色分组后拼合还原为完整矩形，再根据每个矩形内部的孔洞图案在指定画布区域盖章。

- `Input structure`：
  - bg = black。
  - 网格分为左右两个区域，由一列灰色（grey）分隔线隔开。
  - 左侧区域：散布着若干彩色像素碎片。同一颜色的所有碎片恰好能无重叠地拼合成一个完整矩形（碎片仅需平移，不需旋转或翻转）。每种颜色拼合后的矩形内部恰好包含一个或多个背景色孔洞（连通的背景色区域）。
  - 右侧区域：一片空白的背景色画布，画布左上角有一个小的红色（red）起始标记像素。

- `Rule`：
  - 第一层（拼合）：将左侧区域中每种颜色的碎片通过平移拼合成一个完整矩形。拼合方式唯一——对每种颜色，碎片之间的相对位置关系使得它们恰好铺满一个矩形区域（除了孔洞位置）。
  - 第二层（提取印章）：从每个拼合后的矩形中提取孔洞图案作为"印章"。印章即矩形范围内所有背景色像素的位置集合。
  - 第三层（盖章）：按颜色在色谱中的顺序（red, orange, yellow, green, azure, blue, magenta），从红色起始标记开始，在右侧画布上水平依次排列各印章图案。每个印章用其对应矩形的颜色绘制（即原本的孔洞位置现在填上颜色），印章之间水平间隔1列背景色。

- `Key insight`：碎片的空间分布隐藏了拼合后矩形的孔洞信息；必须先完成拼合才能看到孔洞图案，再将孔洞"反转"为印章颜色输出——"拼合 → 提取反转 → 排列盖章"构成三层推理。
</new_puzzle>

<new_puzzle>
- `description`：在棋盘格背景上，根据每个彩色环的缺口方位和环内标记像素的颜色，向缺口方向生长出特定颜色的阶梯状枝条。

- `Input structure`：
  - bg = 由 black 和 grey 组成的棋盘格图案（交替排列）。
  - 网格中散布着若干由单一颜色像素构成的空心环（每个环是一个 5x5 的正方形边框，边框厚度为1像素，恰好缺少一条边上的中间3个像素，形成一个宽3像素的缺口）。不同的环使用不同颜色。
  - 每个环的内部（3x3的区域）中央像素为背景色，但在中央像素的上下左右四个邻居位置中，恰好有一个位置放置了一个与环颜色不同的"标记像素"，其余三个邻居为背景色。

- `Rule`：
  - 第一层（确定生长方向）：每个环有一个缺口（缺少3个像素的那条边），缺口所在方向即为枝条的生长方向（上、下、左或右）。
  - 第二层（确定枝条颜色）：枝条的颜色由环内部的标记像素颜色决定，而非环本身的颜色。
  - 第三层（生长阶梯枝条）：从缺口的中央像素位置开始，沿生长方向每前进2个像素绘制一个标记色像素，同时每前进一步后向固定侧方向（由标记像素相对于环中心的偏移方向决定：若标记在中心的左边，则阶梯向左偏；若在右边则向右偏；若在上方则根据生长方向映射为左或右偏）偏移1个像素，形成阶梯状。枝条生长直到碰到网格边界或碰到另一个环的像素为止。
  - 环本身和标记像素在输出中保持不变。

- `Key insight`：缺口方向决定枝条往哪走，标记像素颜色决定枝条画什么颜色，标记像素的位置决定阶梯偏向哪一侧——三个视觉线索分别控制三个不同的输出属性，需要分别识别并正确组合。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到由边框颜色编码的嵌套矩形层级，从最内层开始逐层向外扩展填充，每层填充颜色由更外一层边框决定。

- `Input structure`：
  - bg = black。
  - 网格中央有若干层同心嵌套的矩形边框，每层边框使用不同颜色，边框厚度均为1像素。相邻两层边框之间隔着1像素宽的背景色间隙。
  - 最内层矩形边框围成的内部区域全部为背景色。
  - 网格的四个角落各放置一个 2x2 的小色块，这四个色块可能使用不同颜色，也可能部分相同。

- `Rule`：
  - 第一层（确定填充顺序）：识别从内到外的所有矩形边框层级。最内层编号为1，向外依次递增。
  - 第二层（确定填充颜色）：每一层间隙的填充颜色不由本层边框决定，而由紧邻其外侧的那一层边框的颜色决定。最内层矩形内部区域的填充颜色由四个角落色块决定：左上角色块的颜色填充内部区域的左上象限，右上角色块填充右上象限，左下角色块填充左下象限，右下角色块填充右下象限。若内部区域的行数或列数为奇数，则中间行/列归属于左上象限。
  - 第三层（执行填充）：从最内层开始向外，依次将每层边框之间的1像素间隙填充为上述确定的颜色。边框像素本身不改变。最外层边框外侧不做任何填充。

- `Key insight`：填充颜色的来源存在"错位"——间隙颜色来自外侧边框而非内侧边框，最内部区域的颜色来自远处的角落色块而非任何边框；解题者需要发现这种非局部的颜色传递关系。
</new_puzzle>

<new_puzzle>
- `description`：用网格中的"钥匙"形状解锁对应的"锁"，解锁后锁的内部封闭区域按钥匙的齿数决定填充图案的重复次数。

- `Input structure`：
  - bg = black。
  - 网格中有若干对"锁"和"钥匙"。
  - "锁"：由某种颜色绘制的矩形封闭框（厚度1像素），框的某一条边（上、下、左或右）中央有一个向外凸出的1像素宽、2像素深的凹槽（即锁孔），凹槽处框的边缘断开。框内部为背景色。
  - "钥匙"：由另一种颜色绘制的细长形状，主体为一条1像素宽的直线段（钥匙柄），一端连接着若干个垂直于柄方向的1像素短突（齿），齿分布在柄的同一侧，齿之间间隔1像素。钥匙柄的另一端（无齿端）朝向某个方向。
  - 每把钥匙的柄的无齿端与某个锁的凹槽在同一行或同一列上对齐，且钥匙朝向锁孔方向。
  - 每把钥匙的齿数（1到4之间）各不相同。

- `Rule`：
  - 第一层（配对）：每把钥匙与其对齐的锁配对。配对依据是钥匙柄无齿端沿柄方向延伸能够到达锁的凹槽入口。
  - 第二层（解锁判定）：将钥匙沿柄方向平移直到无齿端插入凹槽。钥匙柄的宽度（1像素）恰好等于凹槽宽度（1像素），因此所有对齐的钥匙都能插入。插入后钥匙绘制在新的位置上（覆盖原位置为背景色）。
  - 第三层（填充）：解锁后，在锁的内部区域填充水平条纹图案。条纹使用钥匙的颜色，条纹数量等于该钥匙的齿数。条纹均匀分布在锁内部：将内部高度等分为 (2×齿数−1) 份，奇数份绘制钥匙色条纹，偶数份保持背景色。若锁内部空间的行数无法被均匀分配，则从顶部开始，每条条纹和间隔各占1行像素，多余的行保持背景色。

- `Key insight`：钥匙的朝向决定它开哪把锁，钥匙的齿数决定锁内条纹图案的密度——形状同时编码了空间配对信息和数值参数，两层信息需要分别解读并联合使用。
</new_puzzle>

<new_puzzle>
- `description`：根据彩色种子像素在网格分区中的位置，让种子在其所属分区内生长出形状由相邻分区的边界图案决定的结构。

- `Input structure`：
  - bg = black。
  - 网格被红色（red）的十字线（一条完整的水平线和一条完整的垂直线）分成四个矩形分区（左上、右上、左下、右下）。
  - 四个分区中，恰好有两个对角分区（如左上和右下，或右上和左下）各包含一个单独的彩色种子像素（非红、非黑的颜色），另外两个对角分区的边界处（紧邻红色十字线的那一行或一列）绘有由灰色（grey）像素组成的图案片段。
  - 灰色图案片段为一维排列（沿着紧邻十字线的一行或一列），可能有间断。

- `Rule`：
  - 第一层（识别种子与图案的配对关系）：每个种子像素与其水平方向相邻的分区中的灰色图案配对（左上的种子配对右上分区底边的图案，右下的种子配对左下分区顶边的图案；或类似的对称配对）。具体规则：种子所在分区的水平邻居分区中，靠近十字线的那一行/列的灰色图案即为该种子的"生长模板"。
  - 第二层（解读生长模板）：灰色模板是一维的像素序列（有灰色和背景色两种），将其解读为生长指令：灰色像素 = 向前伸展1格，背景色像素 = 向侧方偏移1格（偏移方向固定为：若种子在十字线左侧则向左偏，若在右侧则向右偏）。
  - 第三层（执行生长）：从种子像素开始，沿垂直方向（远离十字线的方向）逐步执行模板指令，用种子的颜色逐像素绘制生长路径。若路径碰到网格边界则停止。模板读完后若未到边界，则循环重复模板继续生长。

- `Key insight`：种子本身只提供颜色和起点，其生长形状完全由另一个分区的边界图案编码——解题者必须跨分区寻找配对关系，再将一维图案解码为二维路径指令，形成"跨区配对 → 图案解码 → 路径生成"的三层结构。
</new_puzzle>
