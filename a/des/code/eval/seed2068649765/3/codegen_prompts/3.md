- `Input structure`：
  - 网格被 Black 色线条分割成若干矩形区域（类似九宫格或不规则划分，Black 线条宽度为 1 像素）。
  - 网格的最上方一行区域（第一条分隔线上方）包含两个"候选模板"：每个模板是一个小型二值图案，由某种颜色绘制在 bg 上（如一个 Red 的十字形和一个 Blue 的 L 形）。这两个模板使用不同颜色。
  - 其余每个区域内部散落若干单独的彩色像素（"投票像素"），颜色只会是两个模板颜色之一（如只有 Red 和 Blue）。区域内其余位置为 bg。

- `Rule`：
  - 第一层推理——模板识别与颜色关联：识别顶部两个候选模板的形状和各自的颜色，建立"颜色 -> 模板形状"的映射。
  - 第二层推理——投票与选择：对每个非模板区域，统计其中两种颜色投票像素的数量。数量更多的颜色为该区域的"胜出颜色"（保证不会平票）。
  - 第三层推理——绘制输出：将胜出颜色对应的模板形状绘制在该区域内（模板左上角对齐到区域内部的左上角），使用胜出颜色填充模板像素。区域内原有的投票像素全部擦除为 bg。Black 分隔线和模板区域保持不变。

- `Key insight`：解题者必须先建立颜色到模板的映射关系，再通过像素计数的多数决确定每个区域选用哪个模板——投票像素既编码了选择信号，又在输出中被完全替换，形成"输入线索消失、输出模式涌现"的认知跳跃。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
