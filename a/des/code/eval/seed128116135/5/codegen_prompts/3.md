- `description`：通过比较每对相邻区域的"纹理密度"确定边界线的绘制颜色，再根据区域内标记点的分布生成向外辐射的射线。

- `Input structure`：
  - 背景为 black。网格被 grey 的单像素宽直线（水平或垂直）分割为若干矩形区域，类似棋盘格布局。
  - 每个矩形区域内部有一种"纹理"：由某种非 black、非 grey 颜色的像素稀疏分布而成（如随机散点、水平条纹、竖直条纹、棋盘格点等），不同区域的纹理颜色和密度（非 black 像素占区域面积的比例）不同。
  - 某些区域中央有一个单独的 red 像素标记点，与该区域的纹理颜色不同。

- `Rule`：
  - 第一层推理——边界着色：对于每条 grey 分隔线段，比较其两侧相邻区域的纹理密度（非 black 非 grey 像素数量占区域总像素数的比例）。将该分隔线段重新着色为密度较高一侧区域的纹理颜色。如果两侧密度相同，则保持 grey 不变。
  - 第二层推理——射线生成：对于每个包含 red 标记点的区域，从标记点向上、下、左、右四个方向发射射线。射线颜色为该区域的纹理颜色。射线延伸直到碰到与该区域纹理颜色相同的边界线段时停止（射线不画在该边界线上）；若碰到的边界线段颜色与纹理颜色不同（包括 grey），则射线穿过该边界继续延伸到下一个边界或网格边缘。
  - 射线像素覆盖在原有内容之上。原有纹理像素和标记点保留不变。

- `Key insight`：密度比较的结果决定了边界线颜色，而边界线颜色反过来又决定了射线是否被阻挡——形成了一个"先定边界属性、再用边界属性控制传播"的两层因果链。解题者必须先发现密度比较规则，才能理解射线的停止条件。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
