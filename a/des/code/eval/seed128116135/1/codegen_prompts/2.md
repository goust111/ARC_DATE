将网格中的多个"信号塔"沿各自天线方向广播色带，色带在交叉点处按叠加规则混色。

Input structure:
- 背景色为 black。
- 网格中散布若干个 3x3 的"信号塔"对象。每个信号塔由一个 grey 色的 3x3 实心方块构成，且在其四条边（上、下、左、右）中恰好有一条或两条边的中央像素被替换为某种非 grey、非 black 的颜色（称为"天线"）。天线颜色即为该方向广播的信号颜色。
- 天线所在边的方向即为信号的广播方向（例如上边中央为天线，则信号向上广播）。

Rule:
- 对每个信号塔的每个天线，从天线位置出发，沿天线朝外的方向逐格绘制宽 1 格的色带，颜色与天线颜色相同，一直延伸到网格边界为止。色带不覆盖任何信号塔本身（遇到其他信号塔的 grey 像素时跳过该格，色带继续在信号塔另一侧延伸）。
- 当两条不同颜色的色带交叉于同一像素时，该像素的颜色由以下固定混色规则决定：red + blue = magenta，red + yellow = orange，blue + yellow = green。若交叉的两色不属于上述三对之一（例如同色交叉），则保留先到者的颜色（按从左到右、从上到下的信号塔扫描顺序）。
- 三条及以上色带交叉时，依次按上述两两混色规则叠加（按信号塔扫描顺序）。

Key insight：第一层推理是识别天线方向并理解信号沿该方向无限广播；第二层推理是发现交叉点不是简单覆盖或保留，而是遵循一套特定的"颜色混合"映射规则（red+blue=magenta 等），解题者需要从样例中的交叉点颜色反推这套映射。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
