- `description`：根据彩色种子像素的颜色在对应颜色的框架内部生长出枝条，枝条方向由种子相对于原始框架中心的象限决定，长度由该方向上分配的种子数决定。

- `Input structure`：
  - 背景色 = 最常见颜色。网格中散布若干单色矩形框架（仅边框，内部为背景色），每个框架用不同颜色绘制（如 red、blue、green 等）。
  - 框架内部散布若干单像素"种子"，种子颜色与所在框架的边框颜色不同，但种子颜色一定是网格中某个其他框架的边框颜色。
  - 每个框架的中心可通过其边框的几何中点直观确定。

- `Rule`：
  - 第一层：将每颗种子按其颜色归属到对应颜色的框架——即种子颜色与目标框架边框颜色一致。这确定了每个框架要生长的枝条数量（= 被归属到该框架的种子总数）。
  - 第二层：在每个框架内部，从框架的几何中心点出发，向四个基本方向（上、下、左、右）生长枝条。枝条分配规则：种子位于其原始所在框架中心的哪个象限（左上→向上，右上→向右，左下→向左，右下→向下），就为目标框架在该方向分配一根枝条。
  - 每个方向上若分配了 N 根枝条，则从目标框架中心沿该方向画一条长度为 N 像素的线段，颜色使用目标框架的边框颜色。
  - 种子像素在输出中被移除；框架边框保留不变。

- `Key insight`：种子颜色决定目标框架（跨框架映射），种子在其原始框架中的象限位置编码了枝条在目标框架中的生长方向——解题者必须同时发现"颜色归属"和"象限→方向"两层隐含规则。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
