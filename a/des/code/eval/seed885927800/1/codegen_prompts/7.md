- `description`：根据"指令塔"的高度和顶端标记色，确定灯带的点亮长度和方向，将灯带局部染色。
- `Input structure`：
  - bg = black。网格中有若干"指令塔"：每座塔是一列连续的 grey 像素，从某行向上延伸，高度不等（2 到 7 格）。每座塔最顶端的一个像素被替换为一个彩色像素（red、blue、green 或 yellow 之一），作为方向标记。
  - 网格中还有若干水平的"灯带"：每条灯带是一行连续的 grey 像素（长度 ≥ 8），灯带的一个端点与某座塔的底部像素在同一行且水平相邻（紧挨着）。每条灯带只与一座塔相邻。
  - 网格右下角有一个颜色-方向图例：4 行 2 列，每行左侧是一个彩色像素（分别为 red、blue、green、yellow），右侧是一个用同色绘制的单像素指示方向——该像素位于左侧像素的左方或右方，表示该颜色对应的点亮方向（向左或向右）。
- `Rule`：
  - 第一层推理：解读右下角图例，建立顶端标记色到方向的映射（例如 red → 向右，blue → 向左等）。
  - 第二层推理：对每座指令塔，数出其高度 H（grey 像素数 + 顶端彩色像素共 H 格）。根据顶端颜色查图例确定点亮方向。
  - 找到与该塔底部同行且水平相邻的灯带。从灯带与塔相邻的端点出发，沿图例指示的方向（向左或向右远离塔的方向）将前 H 个 grey 像素点亮——将它们重新着色为塔顶端的颜色。若灯带剩余长度不足 H，则点亮到灯带末端为止。
  - 塔本身保持不变，图例保持不变，灯带中未被点亮的部分保持 grey。
- `Key insight`：塔的高度编码了"能量值"决定点亮多少格，而塔顶颜色经图例转译后编码了方向——解题者需要同时从两个独立维度提取信息并组合应用，任何一维的错误都会导致结果偏差。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
