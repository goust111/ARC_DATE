- `Input structure`：
  - 背景色 bg 为最常见颜色（如 black）。
  - 网格中有若干由同一种边框颜色（如 grey）围成的封闭矩形区域，每个区域内部散落着少量同色像素碎片（颜色各不相同，例如 red、blue、green 等）。
  - 网格的最上方或最左方有一个图例区域，图例区域由分隔线划分成若干小格子。每个小格子内包含两部分：左侧一列是一个纯色像素（表示颜色键），右侧是一个小型单色模板形状（如 L 形、T 形、十字形等），模板使用与颜色键相同的颜色绘制。

- `Rule`：
  - 第一步（图例解码）：在图例区域中，读取每个格子的颜色键和对应的模板形状，建立"颜色 → 模板形状"的映射关系。
  - 第二步（区域匹配）：对于网格中每个封闭矩形区域，识别其内部碎片像素的颜色 C。
  - 第三步（模板印刻）：根据颜色 C 在图例中查找对应的模板形状。计算区域内所有碎片像素的视觉中心位置（即碎片所占行范围的中间行、列范围的中间列），将模板形状的中心对齐到该位置，用颜色 C 绘制模板，同时擦除原有碎片。模板不超出封闭区域边界；若模板部分超出，则超出部分被裁剪。

- `Key insight`：碎片的颜色不是最终显示的内容，而是一个查表索引——解题者需要先在图例中建立颜色到形状的映射，再用碎片的位置信息确定模板的放置锚点。两层推理缺一不可：仅看碎片颜色无法得知输出形状，仅看图例无法得知放置位置。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
