- `description`：网格中的箭头指向目标对象，每个对象根据指向它的箭头总数进行相应次数的 90° 顺时针自旋转；箭头本身在输出中被擦除。

- `Input structure`：
  - 背景色为 black。
  - 网格中分布着若干彩色小型图案对象（每个对象是一个由单一非 black、非 maroon 颜色组成的 4-连通分量，形状不对称以便观察旋转，例如 L 形、阶梯形，占据约 3×3 至 5×5 的包围盒）。
  - 网格中另有若干 maroon 色的"箭头"标记。每个箭头由 5 个像素组成，构成一个明确指向上、下、左或右的箭头形状：以向右箭头为例，由 (r-1,c+1)、(r,c)、(r,c+1)、(r,c+2)、(r+1,c+1) 五个像素组成，即一条水平短线加右侧的三角尖。其他方向的箭头通过旋转该形状得到。
  - 每个箭头沿其指向方向上，最近的非 black 非 maroon 对象就是该箭头的目标对象。不同箭头可能指向同一个对象。

- `Rule`：
  - 对每个箭头，沿其指向方向扫描，找到射线命中的第一个对象作为目标。
  - 统计每个对象被指向的箭头数量 N。
  - 以该对象包围盒中心为旋转锚点，将对象顺时针旋转 N×90°（等效于 (N mod 4)×90°，但解题者无需计算取模，直接观察旋转结果即可）。
  - 旋转后对象仍以相同的包围盒中心位置放置。
  - 所有 maroon 箭头像素在输出中被擦除为 black。

- `Key insight`：箭头并非指示旋转方向，而是充当"计数投票"——解题者首先要识别箭头的指向并追踪其目标对象（第一层），然后发现旋转角度等于指向该对象的箭头总数乘以 90°（第二层），这一"数量→旋转角"的编码方式需要从样例中归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
