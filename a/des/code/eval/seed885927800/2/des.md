- `description`：根据封闭区域内"种子"像素的颜色找到边框上的同色缺口，从缺口向外生长一条藤蔓，藤蔓长度等于该封闭区域的内部面积。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干由 grey 像素围成的封闭矩形区域（边框宽度为 1 像素），每个矩形的边框上恰好有一个 1 像素的缺口（该缺口处 grey 被移除）。
  - 每个矩形内部恰好有一个彩色"种子"像素（颜色各不相同，可能是 red、blue、green、yellow 等）。
  - 缺口所在的位置被替换为与种子相同的颜色，作为出口标记。

- `Rule`：
  - 对每个封闭矩形，识别其内部种子像素的颜色 C 和矩形内部面积 A（即边框所围区域内不含边框本身的像素总数）。
  - 找到边框上颜色为 C 的缺口像素，确定缺口朝外的方向（上、下、左、右）。
  - 从缺口位置沿该方向向外延伸一条直线"藤蔓"，用颜色 C 逐像素绘制，总长度恰好为 A 个像素。
  - 若藤蔓遇到网格边界或已有的非 black 像素则沿顺时针方向转弯 90° 继续延伸，直到总长度达到 A。
  - 输出网格尺寸与输入相同。

- `Key insight`：封闭区域的面积编码了藤蔓的生长长度，而缺口的位置和颜色同时标识了生长起点与方向——解题者需要同时发现"面积→长度"的映射关系和"彩色缺口→出口方向"的对应规则，两层推理缺一不可。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片按形状匹配拼入带有相应形状孔洞的模板中，拼入后碎片颜色被替换为模板边框的颜色。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干由不同颜色边框围成的矩形"模板"（例如 red 边框、blue 边框），每个模板边框宽度 1 像素，内部大部分填充 grey，但模板内部有一个非矩形的"孔洞"——即一块连通的 black 区域，形状不规则（如 L 形、T 形、阶梯形等）。
  - 网格的其他位置散落着若干单色碎片（4-连通分量），每个碎片的形状恰好与某个模板中孔洞的形状一致（可能需要 90° 整数倍旋转，不允许翻转）。碎片的颜色与任何模板边框颜色均不同。

- `Rule`：
  - 对每个模板，提取其内部孔洞的形状（被 grey 包围的 black 连通区域）。
  - 在散落碎片中找到形状完全匹配的碎片（允许 0°、90°、180°、270° 旋转）。
  - 将碎片旋转至正确朝向后填入孔洞位置，但将碎片颜色替换为该模板边框的颜色。
  - 碎片原位置用 black 填充（擦除）。
  - 输出网格尺寸与输入相同。

- `Key insight`：解题者需要完成两层推理——第一层是通过形状匹配（含旋转）将碎片与孔洞配对，第二层是发现填入后颜色并非保留碎片原色而是继承模板边框颜色，这一颜色替换规则需要从多个样例对比中才能归纳。
</new_puzzle>

<new_puzzle>
- `description`：网格中的箭头指向目标对象，每个对象根据指向它的箭头总数进行相应次数的 90° 顺时针自旋转；箭头本身在输出中被擦除。

- `Input structure`：
  - 背景色为 black。
  - 网格中分布着若干彩色小型图案对象（每个对象是一个由单一非 black、非 maroon 颜色组成的 4-连通分量，形状不对称以便观察旋转，例如 L 形、阶梯形，占据约 3×3 至 5×5 的包围盒）。
  - 网格中另有若干 maroon 色的"箭头"标记。每个箭头由 5 个像素组成，构成一个明确指向上、下、左或右的箭头形状：以向右箭头为例，由 (r-1,c+1)、(r,c)、(r,c+1)、(r,c+2)、(r+1,c+1) 五个像素组成，即一条水平短线加右侧的三角尖。其他方向的箭头通过旋转该形状得到。
  - 每个箭头沿其指向方向上，最近的非 black 非 maroon 对象就是该箭头的目标对象。不同箭头可能指向同一个对象。

- `Rule`：
  - 对每个箭头，沿其指向方向扫描，找到射线命中的第一个对象作为目标。
  - 统计每个对象被指向的箭头数量 N。
  - 以该对象包围盒中心为旋转锚点，将对象顺时针旋转 N×90°（等效于 (N mod 4)×90°，但解题者无需计算取模，直接观察旋转结果即可）。
  - 旋转后对象仍以相同的包围盒中心位置放置。
  - 所有 maroon 箭头像素在输出中被擦除为 black。

- `Key insight`：箭头并非指示旋转方向，而是充当"计数投票"——解题者首先要识别箭头的指向并追踪其目标对象（第一层），然后发现旋转角度等于指向该对象的箭头总数乘以 90°（第二层），这一"数量→旋转角"的编码方式需要从样例中归纳。
</new_puzzle>

<new_puzzle>
- `description`：网格被分隔线划分为若干房间，墙壁上的同色"门"标记将房间配对，配对房间之间交换各自的内部图案，图案穿门时根据门所在墙壁方向进行镜像翻转。

- `Input structure`：
  - 背景色为 black。
  - azure 色的分隔线（水平和垂直，宽度 1 像素）将网格划分为若干矩形房间。
  - 每个房间内部包含一个由某种颜色绘制的小型不对称图案（4-连通分量，占据房间内部的一部分区域）。
  - 某些分隔线上有 1 像素的缺口，缺口处的 azure 像素被替换为一种其他颜色（如 red、green、yellow 等），这些彩色像素称为"门"。
  - 门总是成对出现：相同颜色的门恰好有且仅有两个，它们分别位于不同房间的墙壁上。每个房间至多有一扇门。

- `Rule`：
  - 找到所有颜色配对的门，每对同色门将两个房间 A 和 B 关联起来。
  - 将房间 A 的图案移动到房间 B 的对应位置，将房间 B 的图案移动到房间 A 的对应位置（交换）。
  - 图案在交换时必须进行镜像翻转：若门位于水平分隔线上（即门连接的两个房间上下相邻），则图案做上下翻转；若门位于垂直分隔线上（即门连接的两个房间左右相邻），则图案做左右翻转。
  - 传送后的图案以目标房间内部区域的中心为锚点居中放置。
  - 门的颜色像素和分隔线在输出中保持不变。

- `Key insight`：解题者需要三层推理——第一层是发现同色门标记将房间两两配对，第二层是发现配对房间之间的图案发生了交换而非复制，第三层是发现图案穿门时根据门所在墙壁的朝向进行了镜像翻转——仅观察一个样例难以区分是翻转还是旋转，需要多个样例综合才能确定规则。
</new_puzzle>

- `description`：根据画布边框角标颜色匹配印章图案，以画布内定位点为锚、角标所在角为起始方向，将印章平铺满画布内部。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干小型彩色图案作为"印章"（每个印章由单一颜色的像素组成，占据一个紧凑的矩形包围盒，形状各异，颜色互不相同，如 red、blue、green 等）。
  - 另有若干较大的 grey 边框矩形作为"画布"（边框宽度 1 像素，内部为 black）。
  - 每个画布的四个角像素中，恰好有一个被替换为某种非 grey、非 black 的颜色（与某个印章的颜色相同），称为"角标"。
  - 每个画布内部恰好有一个与角标同色的单像素点，称为"定位点"。

- `Rule`：
  - 通过角标颜色将画布与印章配对——角标颜色与印章颜色相同即为配对。
  - 角标所在的角决定印章的对齐角和铺贴方向：
    - 左上角标：将印章的左上角对齐到定位点，向右和向下重复平铺。
    - 右上角标：将印章的右上角对齐到定位点，向左和向下重复平铺。
    - 左下角标：将印章的左下角对齐到定位点，向右和向上重复平铺。
    - 右下角标：将印章的右下角对齐到定位点，向左和向上重复平铺。
  - 印章以不重叠的方式紧密平铺（像瓷砖一样），仅在画布内部 black 区域绘制，不覆盖 grey 边框，超出画布的部分截断。
  - 原印章位置在输出中保持不变。

- `Key insight`：解题者需要依次发现三层规则——第一层通过颜色匹配画布与印章，第二层发现画布内的单像素定位点是铺贴锚点（而非印章放置的中心），第三层发现角标的具体位置编码了印章对齐的角和扩展方向——三层信息共同决定最终铺贴结果。
</new_puzzle>

<new_puzzle>
- `description`：网格边缘的小型 2×2 开关方块通过内部像素排列模式控制同色路径的可见性——对角排列表示保留路径，同行排列表示擦除路径。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干条不同颜色的路径（每条路径是由单一颜色像素组成的宽度为 1 的连续折线，路径颜色互不相同，例如 red、blue、green、yellow 等）。
  - 网格的最外一圈边缘处分布着若干 2×2 的"开关"方块。每个开关由 4 个像素组成，其中 2 个像素为某条路径的颜色（称为"信号色"），另外 2 个像素为 grey。
  - 每种信号色在所有开关中只出现一次，且与某条路径颜色一一对应。

- `Rule`：
  - 对每个开关，识别其中的信号色 C 及其 2 个信号色像素在 2×2 方块中的位置。
  - 若信号色像素呈对角分布（左上+右下，或右上+左下），则开关状态为"开"：颜色 C 的路径在输出中保留。
  - 若信号色像素位于同一行（上方两格或下方两格），则开关状态为"关"：颜色 C 的路径在输出中被擦除为 black。
  - 开关方块本身在输出中保持不变。
  - 没有对应开关的路径（如果存在）在输出中保持原样。

- `Key insight`：解题者首先需要注意到边缘的 2×2 方块不是背景噪声而是功能性开关（第一层），然后需要从多个样例中归纳出开关内部像素的空间排列模式——对角分布意味着保留、同行分布意味着擦除——这种几何编码方式是解题的核心洞见（第二层）。
</new_puzzle>

<new_puzzle>
- `description`：在棋盘格背景上，根据每个彩色对象内部所包含的"空腔"数量，从对象边缘向外发射相应数量的十字形射线，射线颜色与对象相同。

- `Input structure`：
  - 背景为双色棋盘格（由 azure 和 black 交替排列）。
  - 棋盘上散布着若干单色对象（4-连通分量，颜色非 azure 非 black，如 red、green、yellow 等）。每个对象是一个较大的封闭或半封闭形状。
  - 部分对象内部包含"空腔"——即被对象像素完全包围的、由棋盘格背景色填充的连通区域（4-连通）。不同对象的空腔数量不同（0 到 4 个）。

- `Rule`：
  - 对每个对象，数出其内部空腔的数量 N。
  - 找到对象包围盒的四条边（上、右、下、左），按顺时针顺序取前 N 条边。
  - 从每条被选中的边的中点位置，沿该边的外法线方向（即远离对象的方向），向外发射一条射线，用对象的颜色逐像素绘制，直到碰到网格边界或另一个非棋盘格像素为止。
  - 空腔数为 0 的对象不发射任何射线。
  - 射线覆盖棋盘格像素时直接替换。

- `Key insight`：解题者需要先发现射线数量与对象内部空腔数之间的对应关系（第一层——"空腔计数→射线数量"），然后发现射线发射方向遵循从对象包围盒上边开始顺时针选取边的规则（第二层——"边的顺时针优先序→射线方向分配"），两层规则协同决定输出。
</new_puzzle>
