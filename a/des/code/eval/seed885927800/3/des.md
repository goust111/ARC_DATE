  - 网格中还散布着若干"钥匙"：每把钥匙是一个由某种非 grey、非 black 颜色构成的小型连通体（宽 1-2，高 3-5），其一端有凸出的"齿"（即不规则的像素突出部分）。

  - 钥匙原来的位置变为 black 背景。
  - 未匹配的钥匙保持不变。

- `Key insight`：解题需要两层推理——首先通过齿形与缺口的形状互补关系完成配对（非显然的空间匹配），然后理解插入后钥匙颜色会"感染"整个锁体内腔，而不仅仅填充缺口本身。

- `description`：在被墙壁分割的迷宫区域中，根据每个区域内种子像素的颜色，沿该区域的连通路径向相邻区域"蔓延"上色，蔓延深度由种子所在区域的面积决定。

- `Input structure`：
  - 背景为 black。
  - Maroon 色像素构成一格宽的墙壁网络，将网格划分为若干互不连通的区域。墙壁中存在若干"门"：即墙壁上有一个像素宽的缺口，连接相邻两个区域。
  - 部分区域内含有一个彩色种子像素（颜色为 red、blue、green、yellow 等，每个区域最多一个种子，颜色互不相同）。
  - 部分区域为空（无种子）。

- `Rule`：
  - 第一步（度量）：对每个含种子的区域，数出该区域中 black 空白像素的数量 N（不含种子自身和墙壁）。
  - 第二步（蔓延）：从种子像素开始，沿四连通方向扩散种子颜色。扩散可以穿过门进入相邻区域，但总共只能填充 N 个像素（即种子所在区域的空白面积决定了它能向外蔓延填充的总像素数）。扩散按照"先近后远"逐层填充（类似洪水填充的逐层扩展），直到填满 N 个像素或无路可走为止。
  - 种子自身保留，墙壁颜色不变。
  - 若两个种子的蔓延在同一区域相遇，先到达的像素保留其颜色（即先占先得）。

- `Key insight`：解题的核心在于发现蔓延距离不是固定的，而是由种子"母区域"的面积来决定——大区域的种子能蔓延更远，小区域的种子蔓延距离短。这一规律需要通过对比不同样例中各区域面积与蔓延范围的关系才能归纳出来。
</new_puzzle>

- `description`：将网格中散落的彩色线段碎片按颜色分组，每组碎片首尾相连拼成一条完整折线，然后根据每条折线的转弯次数，在指定的计分板框内绘制相应数量的点。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干彩色线段碎片：每个碎片是一条水平或垂直的直线段（长度 2-5 像素），颜色为 red、blue、green、yellow 等。同一颜色的碎片有 2-5 条。
  - 每条碎片的一个端点附近（间隔恰好 1 个 black 像素）有另一条同色碎片的端点，形成"断开但可对齐衔接"的关系——即两条碎片沿直线方向或垂直转弯方向相距 1 格。
  - 网格边缘或角落处有若干空心矩形框，框的边界颜色与某种碎片颜色相同，框内部为 black。每种碎片颜色对应一个框。

- `Rule`：
  - 第一步（拼接折线）：对每种颜色，将该色所有碎片首尾衔接成一条连续折线。衔接方式为：找到两条碎片中相距恰好 1 格的端点对，用该颜色像素填充中间的 1 格间隙，将两条碎片连起来。按此方式将同色所有碎片连成一条完整折线（每种颜色的碎片恰好能唯一地串成一条链）。
  - 第二步（计数转弯）：数出每条完整折线中方向发生改变的次数（即从水平变为垂直或从垂直变为水平的拐点数量）。
  - 第三步（绘制计分）：在对应颜色的空心矩形框内部，从左上角开始，按从左到右、从上到下的顺序，用该颜色绘制与转弯次数相等的单像素点，相邻点之间间隔 1 格。

- `Key insight`：解题需要三层推理——首先发现同色碎片之间存在间隔 1 格的衔接关系并将它们拼接起来（空间匹配），然后理解需要数折线的"转弯"而非长度或碎片数量（属性提取的非显然性），最后将计数结果映射到同色框内的点阵显示。
</new_puzzle>

- `description`：网格中有若干带缺口的彩色环形轨道和一个在轨道上运动的标记物；根据轨道的嵌套层级确定标记物的旋转方向，标记物沿轨道移动后从缺口跳入下一层轨道，最终输出标记物的停留位置。

- `Input structure`：
  - 背景为 black。
  - 网格中有 2-4 个同心的环形轨道（非圆形，而是矩形环，即空心矩形框），每个轨道由不同颜色的像素构成（如 red、blue、green、yellow），一格宽。轨道从外到内嵌套，彼此之间隔着 1-2 格 black 间隙。
  - 每个环形轨道上恰好有一个缺口（1 个像素的断开处），缺口位置各不相同。
  - 最外层轨道上有一个 orange 标记像素，位于轨道的某个位置上（覆盖了轨道原色）。

- `Rule`：
  - 层级规则：最外层轨道为第 1 层，向内依次为第 2、3、4 层。奇数层轨道上标记物按顺时针方向移动，偶数层轨道上按逆时针方向移动。
  - 移动规则：标记物从当前位置出发，沿当前层的方向在轨道上移动。当标记物到达本层缺口位置时，它从缺口跳出，沿径向（垂直于轨道方向）直线移动，进入下一层（更内层）轨道，落在下一层轨道上与缺口径向对齐的那个像素上。
  - 标记物进入新轨道后，继续按该层的方向移动，直到遇到该层的缺口，再跳入更内层。
  - 当标记物到达最内层轨道并绕完一圈（回到跳入点）后停止。
  - 输出：将标记物最终停留位置标记为 orange（覆盖轨道色），其他一切不变。标记物在外层轨道上的原始位置恢复为该层轨道的颜色。

- `Key insight`：解题的核心在于发现嵌套层级与旋转方向的交替关系（奇数层顺时针、偶数层逆时针），以及缺口不仅是"出口"还决定了跳入下一层的入口位置——需要沿径向投射找到对应点。这两层规律必须同时被归纳才能正确追踪标记物的完整路径。
</new_puzzle>

- `description`：网格中有若干颜色不同的"印章"图案和一块由多色像素组成的"画布"区域；根据画布上每个像素的颜色找到同色印章，将该印章图案以该像素为中心叠印到输出上，重叠处按后印覆盖规则处理，叠印顺序由印章的面积从小到大决定。

- `Input structure`：
  - 背景为 black。
  - 网格上半部分有 2-4 个小型"印章"图案（每个印章为 3×3 至 5×5 的连通形状），每个印章使用唯一的单一颜色（如 red、blue、green、yellow），形状各不相同。
  - 网格下半部分有一块矩形"画布"区域，由 grey 边框围成。画布内部的 black 背景上散布着若干单像素的彩色点，这些点的颜色恰好属于上方某个印章的颜色。同一颜色的点可能出现多个。

- `Rule`：
  - 第一步（关联）：画布内每个彩色点的颜色指向上方同色的印章图案。
  - 第二步（排序）：按印章面积从小到大排序。面积小的印章关联的所有点先处理，面积大的后处理。
  - 第三步（叠印）：按排序顺序依次处理每个印章。对于当前印章关联的所有彩色点（若同色多个点则按从左到右、从上到下顺序逐个处理），以该点在画布中的位置为中心，将印章图案叠印到画布上。叠印时，印章中非 black 的像素覆盖画布上对应位置的像素（无论该位置之前是什么颜色）；印章中 black 的位置不影响画布。超出画布边界的部分直接裁剪。
  - 输出为处理完毕后的画布区域（不含 grey 边框和上方印章），紧凑裁剪。

- `Key insight`：解题包含两层非显然推理：首先需要发现画布上的彩色点不是装饰，而是与上方同色印章的"放置坐标"——每个点指定了一次叠印操作的中心；然后需要归纳出叠印顺序由印章面积决定（小印章先印，大印章后印并覆盖），这决定了重叠区域的最终颜色，仅通过观察多个样例中重叠区域的覆盖结果才能发现这一排序规则。
</new_puzzle>

- `description`：网格中有若干由墙壁围成的房间，每个房间内有散落的彩色像素和一个箭头形标记；将箭头指向方向上的像素"推"到该方向的墙壁上堆积，然后根据堆积后每面墙上的像素总数，用对应数量的该墙颜色像素替换房间中心的标记。

- `Input structure`：
  - 背景为 black。
  - Azure 色像素构成一格宽的墙壁，将网格分隔为若干矩形房间（每个房间内部为 black，被 azure 墙壁完全包围）。
  - 每个房间内部散落着若干彩色单像素（颜色为 red、green、yellow 等，同一房间内可能有多种颜色）。
  - 每个房间的中心区域有一个由 maroon 像素构成的箭头标记（3 像素组成：一个像素为箭头头部，两个像素组成箭头尾部的"V"形分叉）。箭头指向四个基本方向之一（上、下、左、右），通过头部像素相对于尾部的位置来判断方向。例如：头部在上、两个尾部像素在头部下方左右各一个，则箭头指向上方。

- `Rule`：
  - 第一步（推像素）：对于房间内每一个彩色像素（非 maroon、非 azure、非 black），将其沿箭头指向的方向移动，直到碰到墙壁（azure）或已经堆积的像素为止。像素在该方向的墙壁前逐个堆叠。移动后原位置变为 black。
  - 第二步（计数与替换标记）：推完所有像素后，数出箭头指向方向那面墙壁上堆积的像素总数 K。将房间中心的 maroon 箭头标记（3 个像素）全部擦除（变为 black），然后在箭头原来的头部位置处，沿箭头的反方向绘制一条长度为 K 的直线，颜色为堆积像素中数量最多的那种颜色。若 K 超出房间范围则截断到墙壁处。

- `Key insight`：解题需要两层推理——第一层是理解箭头方向决定了像素的推动方向（需要识别 3 像素箭头标记的朝向），第二层是发现堆积后的像素计数会反向映射为标记位置的一条新线段，且线段颜色取决于堆积物中的主导颜色。箭头既是"推力方向"又是"计数目标墙"还是"绘制起点"的三重角色需要综合理解。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干颜色不同的"印章"图案和一组 grey 模板框；根据图案块的对称性类型选择对应的模板框，再将图案块按模板框内的布局指示进行对称变换后填入框中。

- `Input structure`：
  - 背景为 black。
  - 网格左半部分散布着若干小型彩色图案块（3×3 到 5×5 的连通体），每个图案块使用单一颜色（如 red、blue、green 等），形状各异且不具备完全对称性，但每个图案块恰好具备以下四种对称性之一的"接近"关系：接近水平轴对称、接近垂直轴对称、接近 180° 旋转对称、完全不对称。所谓"接近"是指图案块翻转或旋转后与原图仅差 1-2 个像素。
  - 网格右半部分有若干 grey 边框的空心矩形模板框，尺寸与图案块相同。每个模板框内部的四个角中，有 1-2 个角落处有一个 azure 小像素标记：
    - 左上 + 右上两角有标记 → 表示水平轴对称操作。
    - 左上 + 左下两角有标记 → 表示垂直轴对称操作。
    - 左上 + 右下两角有标记（对角）→ 表示 180° 旋转操作。
    - 仅左上一角有标记 → 表示保持原样（不对称）。

- `Rule`：
  - 第一步（判断对称类型）：对每个彩色图案块，分别尝试水平翻转、垂直翻转和 180° 旋转，找出哪种变换后与原图差异最小（差异像素最少，1-2 个）。差异最小的变换即为该图案块的"接近对称类型"。若所有变换差异都超过 2 个像素，则归类为"不对称"。
  - 第二步（匹配模板）：将每个图案块与角标记所指示的对称类型相同的模板框配对。同一对称类型的图案块和模板框数量一一对应。
  - 第三步（修补并填入）：将图案块执行其对应的对称变换（翻转或旋转），得到变换后的版本。将原图与变换后版本叠加——凡是两者不同的像素位置，采用变换后版本的值（即"修补"那 1-2 个像素使其真正对称）。将修补后的完美对称图案填入对应的模板框内部，替换掉 black 背景。移除 azure 角标记。
  - 原图案块的位置变为 black。

- `Key insight`：解题包含三层非显然推理：首先需要发现每个图案块"几乎但不完全"对称，并判断其最接近的对称类型（视觉差异比对）；然后发现模板框角落的 azure 标记编码了对称类型（标记位置的空间关系映射到对称操作）；最后理解输出不是简单复制图案块，而是将其"修补"成完美对称后再填入。
</new_puzzle>
