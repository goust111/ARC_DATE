- `Input structure`：
  - 背景色（black）。网格中有若干个小型彩色对象，每个对象是 3x3 的实心方块，颜色各不相同（使用 red、blue、green、yellow、orange、magenta、azure、maroon 等颜色）。
  - 部分对象之间有灰色（grey）"箭头"连接。每个箭头由 3 个灰色像素组成，排列为 L 形：其中 2 个像素构成箭杆（水平或垂直排列的相邻像素），第 3 个像素从箭杆的一端向垂直方向偏移 1 像素构成箭头尖（即 L 的短边）。
  - 箭杆的另一端（非弯折端）与"源"对象的边缘 4-连通相邻，箭头尖（L 的短边末端）与"目标"对象的边缘 4-连通相邻。也就是说，L 从源对象直走再拐弯指向目标对象。
  - 箭头形成有向无环图（实际为若干条不分叉的链）：每个对象最多有一个入箭头和一个出箭头。

- `Rule`：
  - 对每个有入箭头的对象，沿箭头反方向追溯，找到链的源头（没有入箭头的对象）。
  - 链上所有对象（包括源头自身）都被重绘为源头对象的原始颜色。
  - 所有灰色箭头像素在输出中被擦除（替换为背景色 black）。
  - 没有参与任何箭头链的孤立对象保持原色不变。
  - 输出网格尺寸与输入相同。

- `Key insight`：解题者需要先从 L 形灰色标记中识别出箭头及其方向性（L 的弯折方向编码了从源到目标的有向关系：直边连源、弯折端指目标），再沿链反向追溯到源头以确定最终颜色——箭头方向解读和链式溯源是两个依次递进的推理层。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
