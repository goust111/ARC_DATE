- `description`：根据边框内部小色块的颜色与位置，从网格外部找到对应颜色的拼图碎片，将其旋转至碎片上锚点朝向边框中心后，以色块位置为锚点放置碎片。

- `Input structure`：
  - 背景色为 Black。网格中央有一个由 Grey 像素构成的单像素宽矩形边框。
  - 边框内部散布若干单像素色块（颜色各不相同，如 Red、Blue、Green 等），每个色块位于边框内部的某个位置。
  - 边框外部散布与内部色块颜色一一对应的小型多像素连通碎片（4-连通），每个碎片中恰好有一个像素的颜色与碎片其余像素不同，该像素称为"锚点"。碎片主体颜色与边框内部某个色块颜色相同。

- `Rule`：
  - 输出仅保留边框及其内部区域（裁剪到边框的外边界）。
  - 对于边框内部每个单像素色块 C：
    1. 在边框外找到主体颜色为 C 的碎片。
    2. 计算色块 C 相对于边框几何中心的方位（上、下、左、右四个象限中最近的主方向）。
    3. 旋转碎片（0°/90°/180°/270°），使碎片的锚点朝向边框中心方向（即锚点在碎片包围盒中的位置指向中心方向：若色块在边框上半部，锚点应在碎片底侧，以此类推）。
    4. 将碎片平移，使锚点与色块 C 的位置重合。
  - 碎片仅覆盖背景像素，不覆盖边框和其他已放置的碎片。

- `Key insight`：内部色块不仅指定了匹配哪个碎片，还通过其相对于边框中心的方位隐式决定了碎片的旋转方向——解题者需要发现"色块方位 → 锚点朝向"这一非显然的映射规则。
</new_puzzle>

- `description`：将网格中散落的彩色对象按形状相似性分组，然后用每组中面积最大对象的颜色统一重绘该组所有对象，同时将每组对象平移聚拢到网格中按组数等分的水平条带内。

- `Input structure`：
  - 背景色为 Black。
  - 网格中散布若干彩色连通对象（4-连通），颜色多样（如 Red、Blue、Green、Yellow、Orange 等）。
  - 存在 2-4 组形状相同的对象（形状匹配允许旋转和翻转），每组包含 2-4 个对象。同组对象的颜色不一定相同，形状可能经过不同的旋转/翻转。
  - 每个对象的面积（像素数）相同（因为形状相同），但颜色不同。

- `Rule`：
  1. 识别所有对象，计算每个对象的规范形状（二值掩码，对旋转和翻转不变）。
  2. 按规范形状将对象分组。
  3. 在每组中，找到在原始网格中位置最靠上（行号最小）的对象，记录其颜色作为该组的"统一色"。若行号相同，取列号最小的。
  4. 将网格在垂直方向上等分为与组数相同的水平条带（从上到下）。组的排列顺序按各组"统一色"对象在原输入中的最左上角位置从上到下、从左到右排序。
  5. 在每个条带中，将该组所有对象用统一色重绘，保持对象间的相对水平顺序（按原始列位置从左到右排列），垂直居中放置在条带内，对象之间水平间隔 1 像素。

- `Key insight`：解题者需要先发现形状匹配分组规则（第一层推理），然后发现最靠上对象的颜色决定了统一色（第二层推理），最后发现条带排列顺序和内部排列规则（第三层推理）。三层规则需要逐步归纳。
</new_puzzle>

- `description`：在网格中，由边框围成的多个房间通过门洞连通；从指定起点出发，沿唯一可通行路径穿越房间，每进入一个新房间就用该房间墙壁颜色绘制从入口到出口的折线路径。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有若干矩形"房间"，每个房间由特定颜色的单像素宽边框围成（不同房间边框颜色不同，如 Red、Blue、Green、Yellow 等）。
  - 相邻房间共享一段边框墙壁，共享墙壁上恰好有一个像素缺口（"门洞"），门洞处为背景色。
  - 某个房间的内部有一个 Maroon 单像素标记（起点）。
  - 某个房间的内部有一个 Orange 单像素标记（终点）。
  - 房间内部除标记外均为背景色。从起点到终点存在唯一一条穿越门洞的路径（房间连通图为树形，无环）。

- `Rule`：
  1. 从起点所在房间开始，沿房间连通图的唯一路径走向终点。
  2. 在每个房间中，确定"入口门洞"和"出口门洞"（起点房间的入口为起点本身，终点房间的出口为终点本身）。
  3. 在每个房间内部，用该房间边框的颜色绘制一条从入口到出口的曼哈顿折线路径：先沿水平方向画到与出口同列的位置，再沿垂直方向画到出口。
  4. 路径仅绘制在房间内部的背景像素上，不覆盖边框。
  5. 起点和终点标记保留原色。

- `Key insight`：解题者需要首先识别房间连通拓扑（通过门洞判断哪些房间相邻），然后推断路径的唯一走向，最后发现路径颜色继承自所在房间的边框色——连通关系、路径方向和着色规则三者共同构成多层推理链。
</new_puzzle>

- `description`：网格被分为左右两个面板：左面板包含若干带有缺口的彩色环形（空心矩形），右面板包含对应数量的实心小矩形色块作为"填料"；根据填料尺寸匹配缺口长度，但填补颜色由环形内部隐藏的单像素标记决定。

- `Input structure`：
  - 背景色为 Black。网格中央有一条 Grey 竖线将网格分为左右两个面板。
  - 左面板：包含若干空心矩形环（即矩形边框，宽度为 1 像素，内部为背景色），每个环使用不同颜色（如 Red、Blue、Green 等），且每个环的某一条边上有一段连续缺口（缺口处为背景色）。每个环内部恰好有一个单像素标记，标记颜色与该环颜色不同。
  - 右面板：包含若干实心小矩形色块，颜色各不相同。每个色块为单像素宽的线段（水平或垂直），长度恰好等于某个环的缺口长度。右面板色块数量与左面板环的数量相同，且缺口长度各不相同以保证唯一匹配。

- `Rule`：
  1. 对于左面板每个环形，测量其缺口长度（缺口连续缺失的像素数）。
  2. 在右面板中找到长度等于该缺口长度的色块（一一对应，长度唯一匹配）。
  3. 确定填补颜色：不使用右面板色块自身的颜色，而是使用该环内部单像素标记的颜色。
  4. 用填补颜色在缺口位置绘制一段与缺口等长的线段，将环补全为完整矩形。线段方向与缺口所在的边一致。
  5. 输出仅保留左面板内容（去掉分隔线和右面板），且环内部的标记像素被移除（恢复为背景色）。

- `Key insight`：右面板色块的尺寸用于匹配缺口（第一层：尺寸匹配），但填补所用的颜色并非色块颜色而是环内部标记的颜色（第二层：颜色来源反直觉）。解题者容易误以为色块颜色就是填补色，需要通过仔细观察样例才能发现标记才是真正的颜色源。
</new_puzzle>

- `description`：网格中有一个大型多色图案（画布）和若干散落的单色小图章；将每个图章视为形状探测器，在画布上搜索与图章形状完全吻合且被掩码覆盖像素同色的子区域，然后将匹配区域重新着色为图章颜色。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有一个大型多色连通区域（"画布"），由多种颜色的像素组成，形成一个复杂图案。画布尺寸约 8x8 至 15x15。
  - 画布之外散布 2-4 个小型单色连通对象（"图章"），每个图章颜色不同（如 Red、Green、Yellow、Azure 等），形状也不同（如 L 形、T 形、直线等，占据 2x2 至 4x4 的包围盒）。

- `Rule`：
  1. 对每个图章，提取其形状掩码（相对于其包围盒的二值形状）。
  2. 在画布内部逐位置滑动扫描，找到所有位置使得画布在该位置的子区域中，图章掩码覆盖的所有像素均为同一种非背景颜色（即该子区域中被掩码选中的像素颜色一致，但可以是任意非背景颜色）。
  3. 将所有匹配位置处被掩码覆盖的像素重新着色为图章的颜色。
  4. 若多个图章在同一像素位置产生冲突，面积较大的图章优先（面积 = 掩码中非空像素数）。
  5. 画布中未被任何图章匹配覆盖的像素保持原色不变。

- `Key insight`：解题者需要理解图章不是直接叠印，而是作为"形状探测器"在画布上搜索同色匹配区域（第一层——理解匹配机制），然后发现匹配条件是"掩码下所有像素同色"而非"与图章同色"（第二层——匹配条件的非显然性），最后处理重叠时的面积优先级（第三层）。
</new_puzzle>

<new_puzzle>
- `description`：网格顶部有一行彩色"指令序列"，网格主体中有多个同形但不同色的箭头对象指向不同方向；按指令序列的颜色顺序依次激活对应箭头，每个箭头沿指向方向发射射线，射线碰到先前射线时顺时针转向90度继续延伸。

- `Input structure`：
  - 背景色为 Black。
  - 网格第一行（row 0）包含一个由若干彩色像素组成的水平序列（从左到右紧密排列），每个像素颜色不同。这是"指令序列"。
  - 网格其余区域散布若干箭头形对象。每个箭头由 3 个同色像素组成，占据 2x2 包围盒中的 3 个格子，缺失的那个角所在的对角方向即为箭头的指向方向。例如：右上角缺失表示箭头指向右上，但射线方向取水平/垂直中更接近的主方向——若缺失角在右上则射线向右发射；若缺失角在左上则射线向左发射；若缺失角在右下则射线向下发射；若缺失角在左下则射线向下发射。具体规则：缺失角在上方两角之一则射线向上，在下方两角之一则射线向下，在左方两角之一则射线向左，在右方两角之一则射线向右。更精确地：右上缺失→向上，左上缺失→向左，右下缺失→向右，左下缺失→向下。
  - 每种颜色在指令序列中最多出现一次，每种颜色对应网格中恰好一个箭头。

- `Rule`：
  1. 按指令序列从左到右的顺序依次处理每个颜色。
  2. 找到该颜色对应的箭头，确定其射线方向（根据缺失角位置确定：右上缺失→向上，左上缺失→向左，右下缺失→向右，左下缺失→向下）。
  3. 从箭头的缺失角位置出发，沿射线方向逐像素延伸，用箭头颜色填充背景像素。
  4. 当射线碰到一条先前绘制的射线像素时，射线顺时针转向 90 度后继续延伸。每条射线最多转向一次。
  5. 射线在到达网格边界时停止。
  6. 箭头对象本身保持不变。

- `Key insight`：解题者需要先破解箭头缺失角与射线方向的编码关系（第一层），然后发现指令序列决定了箭头的激活顺序从而影响射线间的碰撞关系（第二层——顺序依赖性），最后发现碰撞时的固定顺时针转向规则（第三层）。激活顺序的不同会导致完全不同的输出图案。
</new_puzzle>

<new_puzzle>
- `description`：网格中包含若干彩色"源"像素和一个由 Grey 线条构成的管道网络；每个源像素的颜色沿管道网络流动，在管道交叉口按特定规则选择分支，最终在管道末端（死端）沉积形成与流经距离相关的色块。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有由 Grey 像素构成的单像素宽线段网络，线段仅沿水平或垂直方向延伸，在交叉点处形成 T 形或十字形交叉。管道网络中存在若干"死端"（仅有一个方向连通的 Grey 像素端点）。
  - 某些死端位置上放置了一个彩色像素（非 Grey、非 Black），覆盖在 Grey 之上，这些是"源"。每个源颜色不同。
  - 管道网络保证每个非源死端从网络连通性上恰好可达一个源。

- `Rule`：
  1. 从每个源出发，颜色沿 Grey 管道像素传播。
  2. 在 T 形交叉口（三通），颜色不回头，而是选择直行方向继续（即保持进入交叉口时的方向）。若直行方向无管道（即来向与出向成 90 度），则选择右转方向（面向行进方向时的右侧）。
  3. 在十字形交叉口（四通），颜色始终直行。
  4. 颜色传播到达一个非源死端时停止。
  5. 在每个非源死端处，计算从源到该死端沿管道经过的 Grey 像素数量 N。在死端位置绘制一个边长为 min(N, 5) 的实心正方形色块（以死端为中心，颜色为源的颜色），色块覆盖背景像素但不覆盖管道。
  6. 管道本身（Grey 像素）在输出中保持 Grey 不变。

- `Key insight`：解题者需要发现管道交叉口的转向规则（直行优先、无法直行时右转——第一层推理），然后理解每个死端归属于哪个源（第二层——路径追踪），最后发现死端色块大小由路径长度决定（第三层——距离编码尺寸）。交叉口规则是最关键且最隐蔽的洞见。
</new_puzzle>
