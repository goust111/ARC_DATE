- `description`：网格中有若干带"窗口"的彩色建筑轮廓和一组游离的装饰图案，需要根据窗口数量将建筑与装饰图案配对，再将装饰图案铺设在建筑的屋顶上，铺设方向由建筑最高窗口所在的一侧决定。

- `Input structure`：
  - bg = black（黑色背景）。
  - 网格中有若干"建筑"：每栋建筑是一个用单一非bg颜色绘制的实心矩形，矩形顶部为"屋顶"（顶边）。建筑内部有若干"窗口"——即被挖去的 bg 像素区域，每个窗口为 1×1 的单像素孔洞。不同建筑的颜色不同，窗口数量也不同。
  - 网格中另有若干独立的"装饰图案"：每个装饰图案是一个由 maroon 像素构成的小型连通块，形状各不相同。每个装饰图案的正下方紧邻一行 yellow 像素，yellow 像素的数量等于某栋建筑的窗口数量。
  - 装饰图案的数量与建筑数量相同。

- `Rule`：
  - 第一步（配对）：数出每栋建筑内部的窗口（bg 孔洞）数量，数出每个装饰图案下方 yellow 像素的数量。将窗口数量与 yellow 数量相同的建筑和装饰图案配对。
  - 第二步（确定铺设方向）：对每栋建筑，找到其最高行（最靠近屋顶）的窗口。若该窗口位于建筑水平中线的左侧，则装饰图案从屋顶左端开始向右铺设；若位于右侧，则从右端开始向左铺设（镜像翻转后铺设）。若恰好在中线上，则居中铺设不翻转。
  - 第三步（铺设）：将装饰图案（必要时水平镜像翻转）放置在建筑屋顶正上方，对齐到指定一端。装饰图案的 maroon 像素覆盖 bg。
  - 输出中：装饰图案和 yellow 像素的原始位置清除为 bg；建筑保留；屋顶上方出现铺设的装饰图案。

- `Key insight`：第一层推理是通过数量匹配完成配对（窗口数 = yellow 像素数）；第二层推理是发现最高窗口的左右位置决定了铺设方向——这个规则不能从单个样例中看出，需要对比多个样例才能归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
