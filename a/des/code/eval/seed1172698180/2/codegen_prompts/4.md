- `Input structure`：
  - bg = 最常见颜色（Black）。
  - 网格上有若干条水平或垂直的单像素宽彩色直线段（路径），每条路径使用唯一颜色（如 Red、Blue、Green、Yellow 等）。
  - 路径之间存在交叉点：两条路径（一条水平、一条垂直）在某个像素位置重叠。每个交叉点处显示的是其中一条路径的颜色（表示该路径在此交叉点"从上方通过"），另一条路径在此处被遮挡。
  - 网格边缘（第 0 行）有一排小型 2×1 竖直色块作为"优先级标记"，从左到右排列。每个标记由上下两个不同颜色的像素组成。

- `Rule`：
  - 第一层推理——解读优先级关系：每个 2×1 优先级标记表示"上方像素的颜色优先级高于下方像素的颜色"。综合所有标记可建立颜色之间的完整优先级偏序。
  - 第二层推理——验证交叉点一致性：在每个交叉点处，优先级较高的路径颜色应显示在该像素上（从上方通过）。这用于确认优先级解读正确。
  - 第三层推理——擦除被完全遮挡的路径：检查每条路径的所有交叉点。如果一条路径在它参与的每一个交叉点处都被其他路径遮挡（即该路径在所有交叉点处都不是显示的颜色），则该路径的所有像素（包括非交叉点部分）全部擦除为背景色。仅在部分交叉点被遮挡的路径保持不变。
  - 优先级标记在输出中保留不变。

- `Key insight`：解题者必须先从边缘标记中推断出颜色间的优先级关系（而非仅观察交叉点的显示颜色），然后基于"在所有交叉点均被压制"这一全局条件判断哪些路径应被整条移除——这是一个从局部标记到全局判断的多层推理过程。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
