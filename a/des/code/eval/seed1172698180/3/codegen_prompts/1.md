- `Input structure`：
  - 背景色为black。网格中有若干用grey像素绘制的正方形空心框架（边长>=5），框架之间互不重叠。
  - 每个框架内部恰好有一个由red像素组成的L形碎片（3个像素组成的直角形状），L形的开口朝向四个基本方向之一（上、下、左、右）。
  - 框架外部散布着若干独立的小型彩色图案（模板），每个模板由单一非grey、非red、非black颜色绘制，形状各异且不对称。每个模板的外接矩形尺寸严格小于框架内部空间。
  - 每种模板颜色恰好出现一次。模板数量等于网格中不同L形朝向种类的数量。

- `Rule`：
  - 第一层：建立朝向-模板映射。观察所有框架，将L形碎片的四种可能朝向（上、下、左、右）按首次出现顺序排列；将外部模板按其在网格中从上到下、从左到右的顺序排列。第k种朝向对应第k个模板。
  - 第二层：确定旋转量。L形碎片的开口方向定义了一个"指向"；将模板的原始摆放视为"开口朝上"（即0度）。若碎片开口朝右则顺时针旋转90度，朝下则旋转180度，朝左则逆时针旋转90度。
  - 将旋转后的模板绘制到对应框架内部，居中放置（模板外接矩形的中心与框架内部空间的中心对齐）。L形碎片在输出中被移除（变为black）。框架本身和外部模板的原始位置保持不变。

- `Key insight`：需要先通过跨框架比较发现朝向与模板之间的配对关系（非显然的映射），再根据每个框架内L形的具体朝向对选中的模板施加正确的旋转——两步推理缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
