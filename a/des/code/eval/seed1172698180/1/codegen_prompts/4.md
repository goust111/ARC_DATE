- `Input structure`：
  - 网格整体为一个矩形。最外一圈为grey边框。
  - 左侧边框的内侧（第二列）有若干彩色像素散布在不同行上，作为"行刻度"；每个行刻度占一格，颜色各异或可重复。
  - 顶部边框的内侧（第二行）有若干彩色像素散布在不同列上，作为"列刻度"；每个列刻度占一格。
  - 内部画布（第三行第三列起）初始为black。
  - 行刻度和列刻度使用的颜色仅来自 {red, blue, yellow} 三原色。

- `Rule`：
  - 第一步（坐标读取）：记录每个行刻度所在的行号及其颜色，记录每个列刻度所在的列号及其颜色。
  - 第二步（交叉点定位）：对于每一对（行刻度, 列刻度），在内部画布上找到对应的交叉格（该行与该列的交点）。
  - 第三步（颜色混合）：交叉点的颜色由行刻度颜色与列刻度颜色共同决定：
    - 相同颜色 → 保持该颜色（red+red=red, blue+blue=blue, yellow+yellow=yellow）。
    - red + blue → magenta。
    - red + yellow → orange。
    - blue + yellow → green。
  - 仅在行刻度和列刻度都存在的交叉点处着色，其余画布像素保持black。边框和刻度本身不变。

- `Key insight`：表面上看像简单的坐标映射，但核心隐蔽性在于颜色混合规则——解题者必须从样例中归纳出行列颜色的配对产生第三种颜色的规律（类似颜料混色），这一规则无法仅从单个交叉点推断，需要观察多个不同颜色组合的交叉点才能确认。坐标读取是第一层推理，混色规则是第二层推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
