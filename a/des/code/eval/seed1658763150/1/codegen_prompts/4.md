按照颜色配对关系将散落的线段端点两两相连，连线路径需绕过障碍物，连线的绘制颜色由两端点各自所在象限决定。

Input structure:
- 背景为黑色，网格大小约 20x20 至 25x25。
- 网格中央有一个由 grey 像素构成的十字形分隔线，将网格分为四个象限。
- 每个象限的角落处各有一个单像素的颜色标签（分别为 blue、red、green、orange，分布在左上、右上、左下、右下象限），指示该象限的"象限色"。
- 网格中散布着若干成对的彩色端点像素（同色恰好出现两个），颜色包括 magenta、maroon、yellow、azure 等（与象限色不同）。
- 网格中还有若干由 grey 像素构成的小型矩形障碍物（与十字分隔线不相连）。

Rule:
- 将每对同色端点用一条单像素宽的正交折线（仅水平和竖直方向）连接起来。连线不能穿过障碍物或十字分隔线的 grey 像素，也不能与其他连线交叉。
- 连线的绘制颜色不是端点本身的颜色，而是由以下规则决定：找到两个端点分别所在的象限，取这两个象限的象限色；如果两端点在同一象限，连线颜色就是该象限色；如果在不同象限，连线颜色为两个象限色中在网格中出现次数较少的那个（即两个象限标签像素本身不算，只看已绘制的连线像素数量——第一条线默认取行号较小的端点所在象限色）。
- 连接完成后，移除所有端点像素（变为黑色），只保留连线。

Key insight: 第一层推理是发现同色端点需要配对连接并绕障碍；第二层推理是发现连线颜色并非端点色而是由象限标签决定的，需要理解象限归属与颜色选取规则。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
