- `Input structure`：背景为black。网格中央有若干层同心矩形框（每层框宽度为1像素），从外到内颜色各不相同。最内层不是框，而是一个填充了某种图案的实心矩形区域（由两种颜色的像素交替或不规则分布组成）。网格的四个角落各有一个2×2的色块，每个色块由两种颜色组成：上半部分（第一行的2个像素）是一种颜色，下半部分（第二行的2个像素）是另一种颜色。上半部分的颜色与某一层框的颜色相同，下半部分的颜色表示该层框所指定的操作类型（操作颜色只有red、blue、green三种，分别对应三种操作）。
- `Rule`：
  - 首先读取四个角落的"图例"色块，建立框颜色→操作的映射：red操作=将内容水平翻转；blue操作=将内容垂直翻转；green操作=将内容顺时针旋转90度。
  - 从最外层框开始，逐层向内处理。每剥离一层框时，根据该框颜色对应的操作，对框内部的全部内容（包括更内层的框和最终的图案）执行该变换。
  - 逐层剥离并变换直到所有框都被处理完毕。
  - 输出为最终变换后的最内层图案（仅输出实心矩形区域，不包含任何框）。
- `Key insight`：解题者需要发现两层独立的规则——第一层是角落色块构成颜色到操作的映射字典（这个映射本身需要从样例中归纳），第二层是变换的执行顺序是从外到内逐层累积的（每层变换作用于包含所有内层的整体，因此变换的累积效果取决于顺序）。仅看最终输出很难反推中间步骤，必须理解逐层剥离的管道机制。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
