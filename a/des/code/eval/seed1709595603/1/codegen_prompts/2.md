- `Input structure`：
  - bg = 最常见颜色（如 black）。
  - 网格被均匀的 grey 网格线（宽度 1 像素）划分为 R 行 x C 列的等大矩形格子（例如 4 行 x 5 列，每个格子内部为 W x H 像素）。
  - 每个格子内部包含一个由单色非 bg 像素绘制的小型图案（sprite），图案位于格子内部左上角对齐。
  - 每一行中，大多数格子（C-1 个）的图案完全相同（颜色和形状都相同），但恰好有一个格子的图案与该行其余格子不同（形状或颜色不同）。
  - 不同行的"异类格子"出现在不同的列位置。

- `Rule`：
  - 对每一行的 C 个格子，比较它们的内部图案，找到与其他 C-1 个格子不同的那一个"异类格子"，记录其列编号 j（从 0 开始计数）。
  - 构造输出：输出为 R 行 x 1 列的单列格子布局（保持原格子内部尺寸 W x H 和 grey 网格线）。
  - 第 i 行的输出格子内容为第 i 行异类格子的内部图案，但图案整体向右偏移 j 个像素（j 为异类格子的原始列编号）。偏移后超出格子右边界的部分被裁剪掉，左侧空出的区域为 bg。

- `Key insight`：第一层推理是逐行的"找不同"——识别多数派之外的异类；第二层推理是发现输出图案的水平偏移编码了异类在原始网格中的列位置，而非简单的原样提取。解题者需要对比多个样例才能注意到偏移与列号的对应关系。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
