<description>
根据围栏内部标记色块的朝向，选择对应的外部印章图案，将其旋印到围栏内部的空白区域。

Input structure:
- 背景为黑色（black）。网格中散布若干由同一颜色线条围成的矩形围栏（如蓝色、红色、绿色等），每个围栏内部除背景外恰好有一个由两个相邻像素组成的"方向标记"，其颜色与围栏颜色不同。方向标记的两像素排列方式指示朝向：水平排列时，左像素为标记色、右像素为围栏色则指向右，反之指向左；垂直排列同理表示上下方向。
- 在所有围栏的外部，散布着若干小型单色图案（印章），每个印章的颜色与某个围栏的方向标记颜色相同。每个印章颜色唯一对应一个围栏。

Rule:
- 对每个围栏，找到其内部方向标记的颜色，在围栏外部找到相同颜色的印章图案。
- 根据方向标记所指示的朝向，将印章图案旋转到该朝向（以印章原始朝向为"上"，旋转 0°/90°/180°/270° 使其朝向与标记一致）。
- 将旋转后的印章图案放置在围栏内部，位置紧靠方向标记所指方向的对面围栏墙壁（即标记指右则印章靠左墙，标记指上则印章靠下墙），水平或垂直方向居中对齐。
- 方向标记本身保留不变。

Key insight: 方向标记同时编码了两层信息——其颜色确定配对哪个外部印章，其朝向决定印章的旋转角度和放置位置；解题者需先建立颜色配对关系，再推断朝向编码规则。
</description>

<description>
在被分隔线划分的网格单元格中，根据"种子单元格"的生长模式向相邻单元格传播图案，传播方向由种子边缘的缺口位置决定。

Input structure:
- 背景为黑色（black）。网格被灰色（grey）线条划分为 N×M 个等大的矩形单元格。
- 大部分单元格内部为空（全黑）。少数单元格内含有彩色图案（非黑非灰），称为"种子单元格"。
- 每个种子单元格的灰色边框上有一处或多处缺口（缺口处灰色像素被替换为黑色），缺口位于边框的上、下、左、右某一侧中央位置。
- 不同种子单元格内的图案颜色各不相同。

Rule:
- 对每个种子单元格，识别其边框上所有缺口的方向。
- 从种子出发，沿每个缺口方向，将种子内部的图案复制到相邻单元格中。传播是递归的：被填充的单元格如果在传播方向上也有缺口（即该单元格与更远一个单元格之间的分隔线上也有缺口），则继续向同方向传播，直到遇到没有缺口的边框或网格边界。
- 传播只沿缺口方向直线进行，不转弯。
- 若两个种子的传播路径在某个单元格交汇，后到达的颜色覆盖先到达的（按种子距该单元格的跳数判断，跳数少的优先保留；跳数相同时，种子图案像素数多的优先）。

Key insight: 缺口不仅决定传播方向，还隐含了"通道"概念——只有相邻两个单元格共享边框上都有缺口时传播才能继续，解题者需要逐段检查通路而非简单地沿一个方向填满整行或整列。
</description>

<description>
将网格中散落的彩色路径片段按照颜色层级关系重新堆叠，生成一幅颜色正确分层的合成图。

Input structure:
- 背景为黑色（black）。网格中有若干条不同颜色的单像素宽路径（4-连通），各路径之间存在交叉。
- 在网格的最底行（或最右列），有一个由若干颜色方块组成的"图例条"，从左到右（或从上到下）排列了所有路径颜色，每种颜色占一个像素。
- 路径交叉处的像素当前只显示某一种颜色（即某条路径"压在"另一条上方）。

Rule:
- 图例条中颜色的排列顺序定义了层级：越靠右（或越靠下）的颜色层级越高，在交叉处应显示在最上层。
- 首先，为每条路径重建其完整轨迹：在交叉点处，被遮挡的路径应"穿过"交叉点继续延伸（通过交叉点两侧同色像素的共线性推断被遮挡段）。
- 然后，按照图例条定义的层级从低到高依次绘制所有路径：先画最低层级的完整路径，再画次低的，依次叠加，最终高层级路径在交叉处覆盖低层级路径。
- 输出网格去掉图例条，仅保留重新分层后的路径图。

Key insight: 解题者需要完成两步非平凡推理——第一步是通过交叉点两侧的颜色连续性重建每条路径的完整轨迹（被遮挡部分），第二步是从图例条中推断出正确的层级顺序并重新渲染交叉点颜色。
</description>

<description>
根据网格中"镜面"线段的位置和朝向，追踪从光源发出的光线经多次反射后的完整路径，并用光源颜色绘制该路径。

Input structure:
- 背景为黑色（black）。网格中有若干条由灰色（grey）像素组成的短线段（长度 2-4 像素），水平或垂直放置，充当"镜面"。
- 网格边缘上恰好有一个非黑非灰的彩色像素，作为"光源"，其位置在网格的某条边上。光源向网格内部发射一束沿行或列方向直行的光线（方向由光源在哪条边决定：上边缘则向下，左边缘则向右，依此类推）。
- 每面镜子的反射规则取决于其朝向：水平镜面将垂直光线反射为水平（向左还是向右取决于光线到达镜面的哪一端——光线命中镜面左半部分则向左反射，命中右半部分则向右反射）；垂直镜面对水平光线做类似处理（命中上半部分则向上反射，命中下半部分则向下反射）。

Rule:
- 从光源出发，沿初始方向逐像素前进，用光源颜色绘制路径。
- 当光线到达某面镜子的正前方一格时（即光线下一步会命中镜面像素），光线发生 90° 反射：判断光线命中镜面的位置是镜面的前半段还是后半段，据此决定反射方向。
- 反射后光线继续直行，可能再次遇到其他镜面并再次反射。
- 光线在到达网格边界时停止。镜面本身不被重新着色。
- 若光线经过已绘制的路径像素，直接覆盖（颜色相同，无变化）。

Key insight: 关键难点在于反射方向的判定规则——不是简单的"入射角等于反射角"，而是由光线命中镜面的哪一半决定转向哪边；解题者需要从多个样例中对比命中位置与反射方向的对应关系才能归纳出这一规则。
</description>

在包含多个"容器"的网格中，根据容器外壁上色环标记的位置确定旋转方向，根据标记数量的奇偶性确定是否追加镜像翻转，对容器内部的像素图案做相应变换。

Input structure:
- 背景为黑色（black）。网格中有若干个由单一颜色边框围成的正方形容器（边框颜色各不相同，如蓝色、红色、绿色等），每个容器内部包含一个不对称的多色像素图案。
- 每个容器的外壁某一侧上紧贴着若干个小色块（宽 1 像素、沿边框排列），这些小色块的颜色与容器边框颜色不同，称为"旋转标记"。旋转标记出现在容器的上、右、下、左四侧中的某一侧。
- 旋转标记所在的侧面编码旋转方向：上侧 = 不旋转（0°），右侧 = 顺时针 90°，下侧 = 180°，左侧 = 逆时针 90°。
- 旋转标记的像素数量编码额外的变换：若数量为奇数，旋转后还需将图案做水平翻转；若为偶数，仅旋转不翻转。

Rule:
- 对每个容器，找到其外壁上的旋转标记所在侧面，确定旋转角度。
- 数出旋转标记的像素数量，判断奇偶以决定是否追加镜像。
- 将容器内部图案按确定的旋转角度旋转，若需要镜像则对旋转结果做水平翻转。
- 容器边框和旋转标记本身保持不变，仅内部图案改变。
- 输出网格尺寸与输入相同，所有容器外部的内容不变。

Key insight: 解题者需要同时从旋转标记中提取两层独立信息——空间位置编码旋转角度，数量奇偶编码是否镜像——这两层信息叠加后才能确定最终的变换操作，仅靠观察一个样例中的位置或数量无法单独确定规则。
</description>

<description>
将网格中的多个形状按"嵌套深度"重新着色，嵌套关系通过形状之间的空间包含层级确定，颜色由网格边缘的色阶条指定。

Input structure:
- 背景为黑色（black）。网格中有多个不同大小的闭合形状（由同一种灰色 grey 像素绘制的轮廓线），形状之间存在嵌套关系——小形状完全位于大形状内部，可能有多层嵌套（如 A 包含 B，B 包含 C）。
- 网格的某一条边缘上有一列紧邻排列的不同颜色像素，形成"色阶条"，颜色数量至少等于最大嵌套深度加一。色阶条的第一个颜色（最靠近网格角落的）对应最外层，依次向内层递进。

Rule:
- 计算每个闭合形状的嵌套深度：不被任何其他形状包含的为深度 0，被一个形状包含的为深度 1，被两层包含的为深度 2，依此类推。
- 将色阶条中的第 k 个颜色分配给深度为 k 的形状。
- 用分配的颜色替换该形状轮廓线原来的灰色像素。形状内部（轮廓线围成的区域）保持黑色不变。
- 色阶条本身在输出中被清除（替换为背景色）。

Key insight: 核心挑战在于正确判断嵌套深度——解题者必须先通过空间包含关系建立层级树，再将色阶条中的颜色序列映射到对应层级；色阶条的长度本身也是一个线索，暗示了最大嵌套深度。
</description>

Input structure:
- 背景为黑色（black）。网格中有若干个由灰色（grey）像素构成的矩形"门框"，每个门框的一侧边缘上有一个不规则缺口（锁孔），缺口形状各不相同。
- 网格中另有若干个彩色小型图案（钥匙），每个钥匙的形状恰好与某个锁孔的缺口形状互补（即钥匙能精确填入缺口，可能需要旋转 0°/90°/180°/270°）。每把钥匙的颜色唯一。

Rule:
- 对每个门框，识别其锁孔（灰色边框上的缺口区域）的形状。

- 门框内部保持黑色不变。

Key insight: 解题需要两步独立推理——首先通过形状互补性建立钥匙与锁孔的配对（这需要心理旋转能力），然后意识到匹配后整个门框都会变成钥匙颜色而非仅填充缺口，这一"连带着色"规则需要从样例中归纳。
</description>

<description>
将网格中的彩色像素点沿各自所在的"轨道环"滑动，滑动步数由轨道环上特殊标记的位置隐式编码。

Input structure:
- 背景为黑色（black）。网格中有若干个由灰色（grey）像素组成的闭合环形轨道（环形路径宽度为 1 像素，4-连通，形成矩形封闭回路）。
- 每条轨道上分布着若干彩色像素（非黑非灰），它们占据轨道上的某些位置。
- 每条轨道上恰好有一个橙色（orange）像素作为"驱动标记"。轨道的其余非灰色像素为其他各种颜色。
- 驱动标记在轨道上的位置将轨道分为"长弧"和"短弧"两段（沿轨道环两个方向分别量到的距离），短弧的像素数即为滑动步数。

Rule:
- 对每条轨道，沿轨道环计算驱动标记两侧弧段的像素数（从驱动标记出发沿顺时针和逆时针分别到达自身的总像素数的两段），较短弧段的长度 S 即为滑动步数。
- 轨道上所有非灰色像素（包括驱动标记自身）沿轨道环顺时针方向滑动 S 步。
- "顺时针"的定义：对于轨道的最上方水平段，移动方向为向右；据此确定整条轨道的顺时针绕行方向。
- 滑动后，像素离开的位置恢复为灰色（轨道本体颜色）。
- 轨道的灰色骨架不变，仅彩色像素位置改变。

Key insight: 解题者首先需要识别出每条轨道是一个闭合环路并能沿环追踪像素位置，然后需要发现滑动步数的编码方式——不是直接给出数字，而是由驱动标记在环上的位置隐式编码（短弧长度），这要求解题者对环的两段弧分别计数并取较小值。
</description>
</new_puzzle>
