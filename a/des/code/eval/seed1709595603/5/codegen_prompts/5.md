在包含多个"容器"的网格中，根据容器外壁上色环标记的位置确定旋转方向，根据标记数量的奇偶性确定是否追加镜像翻转，对容器内部的像素图案做相应变换。

Input structure:
- 背景为黑色（black）。网格中有若干个由单一颜色边框围成的正方形容器（边框颜色各不相同，如蓝色、红色、绿色等），每个容器内部包含一个不对称的多色像素图案。
- 每个容器的外壁某一侧上紧贴着若干个小色块（宽 1 像素、沿边框排列），这些小色块的颜色与容器边框颜色不同，称为"旋转标记"。旋转标记出现在容器的上、右、下、左四侧中的某一侧。
- 旋转标记所在的侧面编码旋转方向：上侧 = 不旋转（0°），右侧 = 顺时针 90°，下侧 = 180°，左侧 = 逆时针 90°。
- 旋转标记的像素数量编码额外的变换：若数量为奇数，旋转后还需将图案做水平翻转；若为偶数，仅旋转不翻转。

Rule:
- 对每个容器，找到其外壁上的旋转标记所在侧面，确定旋转角度。
- 数出旋转标记的像素数量，判断奇偶以决定是否追加镜像。
- 将容器内部图案按确定的旋转角度旋转，若需要镜像则对旋转结果做水平翻转。
- 容器边框和旋转标记本身保持不变，仅内部图案改变。
- 输出网格尺寸与输入相同，所有容器外部的内容不变。

Key insight: 解题者需要同时从旋转标记中提取两层独立信息——空间位置编码旋转角度，数量奇偶编码是否镜像——这两层信息叠加后才能确定最终的变换操作，仅靠观察一个样例中的位置或数量无法单独确定规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
