- 每把钥匙的外轮廓色与某个锁的 Grey 边框上恰好一个像素被替换成的特殊颜色相匹配（即每个锁的 Grey 边框上有一个非 Grey 像素，其颜色对应一把钥匙的外轮廓色）。

Rule:
- 通过边框上特殊像素的颜色将钥匙与锁配对。
- 配对成功后，检查钥匙的内部填充色是否与锁内种子的颜色相同——若相同，则该锁被"解锁"。
- 对于解锁的锁：移除 Grey 边框（填充为背景色），然后以种子图案为起点，将种子颜色沿四方向向外扩散，每扩散一步距离换一次颜色——第一层用钥匙的外轮廓色，第二层用种子颜色，如此交替，直到碰到网格边界或其他非背景像素为止。

Key insight: 解题需要两层归纳——首先通过边框上的特殊颜色像素建立钥匙-锁配对关系，然后通过钥匙内部色与种子色的匹配判断是否解锁；解锁后的扩散规则又是第三层需要发现的模式。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
