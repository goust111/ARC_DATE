- `description`：在网格中根据"种子"像素的颜色查找对应的生长模板，然后从种子位置按模板形状向外逐层生长出同心图案，生长层数由种子周围的卫星点数量决定。

- `Input structure`：
  - 背景色 = black。网格被一条 grey 水平分隔线分为上下两个区域。
  - 上方区域（模板区）：包含若干小型图案模板，每个模板是一个以某种颜色 C 绘制的小型封闭环形（如 3x3 的方环、菱形环、十字环等），环的内部为 black。每种颜色对应唯一一个模板形状。
  - 下方区域（画布区）：包含若干孤立的"种子"像素，每个种子像素的颜色与上方某个模板的颜色相同。每个种子像素周围（8 邻域范围 3 格以内）散布着若干 yellow 像素作为"卫星点"。

- `Rule`：
  - 第一步——模板匹配：根据每个种子像素的颜色，在上方模板区找到颜色相同的模板形状。
  - 第二步——计数卫星：数出每个种子像素周围的 yellow 卫星点数量 N（卫星点数量很少，通常 1-4 个，解题者用肉眼即可数出）。
  - 第三步——同心生长：以种子像素为中心，将模板形状按比例 1、2、...、N 逐层放大绘制。比例 k 表示将模板中每个像素相对于模板中心的偏移量乘以 k。第 k 层使用种子颜色绘制。所有层叠加后，种子像素本身保持原色。
  - 卫星点（yellow）在输出中被移除（变为 black）。上方模板区保持不变。

- `Key insight`：解题需要三层独立推理：（1）通过颜色对应关系将种子与模板匹配；（2）发现卫星点的数量控制生长层数；（3）理解"同心放大"的几何规则——模板形状以种子为中心按整数倍缩放叠加。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
