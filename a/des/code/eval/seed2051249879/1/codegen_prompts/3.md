- `description`：在网格中识别"母图案"和若干"子标记"，根据子标记的排列顺序对母图案进行逐步裁剪，最终输出剩余部分。

- `Input structure`：
  - 背景色 = black。网格左侧有一个较大的多色矩形图案（"母图案"，由 2-4 种非背景色组成，尺寸约 6x6 至 10x10）。
  - 网格右侧有 2-4 个小型标记，每个标记是一个单色的 L 形（3 像素组成的直角形状，占据 2x2 区域中的三个格子，缺失一角）。
  - 这些 L 形标记从上到下排列，每个标记的颜色与母图案中使用的某种颜色一一对应。
  - 每个 L 形的缺角方向为四个方向之一（左上、右上、左下、右下）。

- `Rule`：
  - 第一层推理——操作顺序：L 形标记从上到下的排列顺序即为操作的执行顺序。
  - 第二层推理——裁剪方向：每个 L 形的缺角方向指示对母图案进行"象限保留"：缺角朝左上 → 保留母图案的左上四分之一区域（丢弃其余）；缺角朝右下 → 保留右下四分之一区域，以此类推。保留操作基于当前剩余图案的中心点进行对半切割。
  - 第三层推理——颜色验证：每步裁剪后，检查被保留区域中是否包含与当前 L 形标记同色的像素；若包含则裁剪有效，进入下一步；若不包含则跳过该步（母图案保持不变进入下一步）。
  - 输出为所有裁剪步骤执行完毕后的剩余图案（紧凑输出，去除多余背景行列）。

- `Key insight`：解题者需要同时发现三个非显然的规律：标记的纵向排列编码了操作顺序，L 形缺角编码了空间裁剪方向，而标记颜色与母图案颜色的匹配关系则控制着该步是否实际执行——这三层结构互相嵌套，单独看任何一层都无法完整还原规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
