- `Input structure`：
  - 背景色 = Black。
  - 网格中有若干由 Grey 像素构成的单像素宽管道路径，管道沿水平或垂直方向延伸，在交叉处形成十字（+形）或T形连接。
  - 管道的某些末端（死端，即只有一个 Grey 邻居的位置）标记为彩色像素（Red、Blue、Yellow 三种颜色之一），这些是信号源头。
  - 管道的另一些末端标记为 Magenta 像素，这些是信号终端。
  - 管道网络中没有环路，即从任意源头到任意终端的路径唯一。

- `Rule`：
  - 每个信号源头沿管道路径传播自己的颜色。信号沿 Grey 管道像素流动，将经过的 Grey 像素全部染为该信号颜色。
  - 当两条不同颜色的信号在交叉处相遇时，发生颜色混合：Red + Blue = Maroon，Red + Yellow = Orange，Blue + Yellow = Green。
  - 混合后的新颜色继续沿管道向终端传播。若三种颜色汇合则变为 Grey（回归管道本色，视觉上表示"全色"混合）。
  - 每个 Magenta 终端像素最终被替换为到达它的信号颜色（可能是原色或混合色）。
  - 如果某个终端没有任何信号能到达（不存在从源头到它的连通路径），则该终端保持 Magenta 不变。

- `Key insight`：解题者首先需要追踪每条管道路径的连通关系，确定哪些源头的信号能到达哪些终端；然后需要发现交叉处的颜色混合规则（这是一个需要从多个样例中归纳的隐含映射表）；最后将混合结果正确传播到终端。路径追踪是视觉直觉层，颜色混合规则是需要归纳的推理层。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
