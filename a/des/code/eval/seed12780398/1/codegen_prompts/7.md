- `Input structure`：
  - 背景色为 Black。
  - 网格上部分布着若干个"信号塔"：每个信号塔是一个用 Orange 绘制的 2×2 实心方块。
  - 网格下部分布着若干个"接收器"：每个接收器是一个 Grey 单像素，其正上方一格处有一个 Azure 像素作为"天线标记"。
  - 网格中间区域有若干水平放置的"滤镜条"：每个滤镜条是一段水平连续的同色像素（颜色为 Red、Blue 或 Green 三者之一），长度和行位置各异，不同滤镜条之间不重叠。

- `Rule`：
  - 第一步：从每个信号塔底边的左列像素向正下方画一条垂直虚拟射线，延伸至网格底部。
  - 第二步：检查每条射线穿过了哪些滤镜条，记录该射线携带的滤镜颜色集合（同色滤镜只计一次）。
  - 第三步：对每个接收器，找出所有经过其所在列的射线，将这些射线各自的滤镜颜色集合取并集，得到接收器的"接收颜色集"。
  - 第四步：根据接收颜色集确定接收器的最终颜色——若只有 Red 则变 Red；只有 Blue 则变 Blue；只有 Green 则变 Green；Red 与 Blue 共存则变 Magenta；Red 与 Green 共存则变 Yellow；Blue 与 Green 共存则变 Azure（保持不变）；三色共存则变为 Maroon；若无射线经过则保持 Grey。
  - 输出中信号塔和滤镜条保持不变，天线标记（Azure 像素）被移除。

- `Key insight`：解题者必须逐层推理三个非显然机制——首先发现信号塔发射的是不可见的垂直向下射线（而非可见线段），然后理解滤镜条对射线经过时进行"着色标记"的机制，最后归纳出接收器端的颜色混合映射规则。三层信息缺一不可。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
