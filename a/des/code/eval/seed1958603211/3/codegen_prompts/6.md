  - 每个箭头的 3 像素尾部中，中心像素为箭头本色，两侧像素可以是不同颜色——这两个侧翼颜色构成该箭头携带的"图案信息"。

- `Rule`：
  - 对每对同色箭头，选择其中头部方向朝向另一箭头的为"发射箭头"，另一个为"接收箭头"。
  - 从发射箭头的头部顶端像素出发，沿箭头指向方向画一条 1 像素宽的射线（颜色为箭头色）。
  - 当射线碰到 azure 镜面线段时，发生 90 度反射（水平镜面将垂直射线反射为水平，反之亦然），射线继续前进。

  - 射线路径保留在输出中；镜面保持不变。

- `Key insight`：解题者需要三层推理：(1) 理解 T 形像素结构编码了箭头方向和携带的图案信息；(2) 发现 azure 线段是镜面，射线遵循反射规则在箭头对之间传播；(3) 反射次数的奇偶性控制图案在接收端是否翻转——这是最隐蔽的一层，需要对比多个样例中反射次数与输出图案的对应关系才能归纳出来。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
