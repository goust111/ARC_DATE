  - 每条路径的一端（起点端）有一个同色的 2x2 方块标记，另一端（终点端）有一个同色的 1x1 像素紧邻一个 orange 像素（orange 像素作为"终点灯"）。
  - 部分路径在某些像素位置发生交叉（即两条不同颜色的路径共享同一个格子）。交叉格子当前显示为其中一种颜色（被覆盖的颜色不可见，但交叉位置可通过路径走向推断）。
  - 网格右侧有一个"优先级表"：一列纵向排列的彩色像素，从上到下表示颜色优先级从高到低。

- `Rule`：
  - 识别所有路径及其起点（2x2 方块）和终点（带 orange 灯的端点）。
  - 在路径交叉点处，查看优先级表：优先级高的颜色路径信号通过，优先级低的路径在该交叉点处信号被阻断（即该路径在交叉点断开，信号无法继续传播到终点）。
  - 从每条路径的起点出发沿路径追踪：如果路径在某个交叉点被阻断（因为该交叉点被更高优先级的路径占据），则信号无法到达终点。
  - 输出中：信号成功到达终点的路径保持原色不变，其终点旁的 orange 灯变为 green；信号被阻断的路径整体变为 grey，其终点旁的 orange 灯保持 orange。
  - 优先级表和 2x2 起点方块在输出中被清除为背景色。

- `Key insight`：解题者首先要理解右侧纵列不是装饰而是优先级排序表，然后推断出路径交叉点的通断规则——高优先级切断低优先级，最后沿每条路径追踪判断信号能否全程抵达终点。关键隐蔽性在于交叉点处"谁赢谁输"的规则需要从优先级表归纳得出。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
