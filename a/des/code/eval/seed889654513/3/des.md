- `Input structure`：
  - 背景为 black。
  - 网格中散布若干大小不一的空心矩形框（边框颜色各不相同，如 red、blue、green 等）。

- `Rule`：
  - 首先确定每个矩形框的嵌套层数：不被任何其他框包围的框为第 1 层，被恰好一个框包围的为第 2 层，依此类推。

  - 如果一个框内部还嵌套着更小的框，被嵌套框所占的区域不被外层框的图案覆盖——即内层框及其内容优先显示。
  - 图例区在输出中被清除为背景色。

- `Key insight`：解题者需要先识别矩形框之间的包含关系以确定嵌套层数，再将层数映射到图例区中的图案序号，最后用对应图案和框自身颜色填充——这是一个"空间包含分析 - 图例查表 - 图案平铺"的三层推理链。

- `Input structure`：
  - 背景为 azure。
  - 网格左半部分有一个较大的多色图案（"模板"），其中有若干处被挖去的矩形缺口，缺口区域显示为背景色 azure。每个缺口的尺寸各不相同。
  - 网格右半部分散布着若干个与缺口尺寸相同的彩色小矩形块（"碎片"），每个碎片的颜色图案各不相同。碎片数量与缺口数量相同。
  - 每个缺口的边缘（紧邻缺口的模板像素）形成一圈独特的颜色序列；每个碎片的外边缘（碎片最外一圈像素）也有独特的颜色序列。

- `Rule`：
  - 对于每个缺口，提取其四条边上紧邻的模板像素颜色序列（按上、右、下、左顺序读取）。
  - 对于每个碎片，提取其四条外边缘的像素颜色序列（同样按上、右、下、左顺序）。
  - 将碎片与缺口配对：配对条件是碎片的外边缘颜色序列与缺口周围模板像素的颜色序列逐像素相同（即碎片上边缘的颜色序列 = 缺口上方模板像素的颜色序列，其余三边同理）。
  - 将每个碎片填入其匹配的缺口位置。
  - 右半部分碎片原来的位置清除为背景色。

- `Key insight`：碎片与缺口的匹配不是靠颜色整体相似或尺寸，而是靠"边缘吻合"——碎片的外沿颜色必须与缺口周围的模板颜色逐像素对齐，这模拟了拼图的锯齿咬合逻辑，解题者需要对比边缘序列才能确定唯一配对。
</new_puzzle>

- `description`：根据箭头指示的方向和路径上收集的颜色标记，逐步更新箭头携带的颜色状态，最终在终点位置写入最后收集到的颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个由 grey 像素绘制的箭头形状。每个箭头由一个 3x1 的箭杆（三个连续的 grey 像素组成一条直线）和一个箭头尖端（在箭杆延长线末端的下一个像素，加上该像素两侧各一个像素，共 3 个像素组成一个"V"形箭尖）构成。箭头朝向上、下、左、右四个方向之一。
  - 沿着每个箭头所指方向的延长线上，在若干格距离处散布着单个彩色像素（如 red、blue、green 等）作为"颜色标记"。同一条延长线上可能有多个不同颜色的标记。
  - 每条延长线的尽头（遇到网格边界之前的最后一个空位置）放置一个 maroon 像素作为"终点标记"。

- `Rule`：
  - 每个箭头沿其朝向方向逐格扫描（概念上的前进，箭头本身不移动）。
  - 箭头初始颜色为 grey。每当沿途遇到一个颜色标记，箭头的"当前颜色"更新为该标记的颜色（如果连续遇到多个，依次更新，最终保留最后一个）。
  - 到达 maroon 终点标记时，将该终点标记的位置替换为箭头当前颜色的单个像素。
  - 同时，将箭头沿途经过的所有颜色标记从网格中清除为背景色。箭头自身（grey 像素）保留不变。maroon 终点标记被替换后不再显示。

- `Key insight`：解题者需要理解箭头是一个"扫描器"，沿指向方向依次读取颜色标记并覆盖自身颜色状态，最终将"最后读取到的颜色"写入终点位置。关键推理在于理解颜色是按顺序覆盖的，而非混合或累加——必须找到每条路径上离终点最近的那个颜色标记。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中每个封闭区域内的"种子"像素颜色，然后用该颜色按照区域形状生成同心收缩的交替填色等高线环纹。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个由 grey 像素围成的封闭区域。每个封闭区域的形状不规则但互不相交，区域内部为背景色 black。
  - 每个封闭区域内部恰好有一个单独的彩色像素（非 grey、非 black），称为"种子"。不同区域的种子颜色可能相同也可能不同。
  - 网格中还有一个独立的小型"示例区"（用 maroon 边框围起来），里面展示了一个简单的封闭形状及其内部已经填好的等高线环纹效果，作为规则的视觉提示。

- `Rule`：
  - 对于每个 grey 边界围成的封闭区域，从 grey 边界开始向内逐层收缩：
    - 第 1 层（紧贴 grey 边界内侧的所有 black 像素）填充为种子颜色。
    - 第 2 层（紧贴第 1 层内侧的所有剩余 black 像素）保持 black 不变。
    - 第 3 层填充为种子颜色。
    - 以此类推，奇数层填充种子颜色，偶数层保持 black，形成交替的同心环纹。
  - "层"的定义：第 k 层是所有与 grey 边界的最短正交步数（仅沿上下左右四方向）恰好为 k 的像素的集合。
  - 种子像素本身所在位置按照其所在层的奇偶规则决定填充或留空。
  - 示例区在输出中保持原样不变。

- `Key insight`：解题者需要先识别封闭区域和种子颜色的对应关系，再理解"从边界向内交替填色"的等高线规则。核心难点在于"层"是沿区域形状收缩的，不规则形状的内缩层会产生非直觉的环纹图案——解题者必须从示例区的简单形状中归纳出规则，再推广到复杂形状。
</new_puzzle>

- `description`：将多个重叠透明图层按照图层标号从下到上叠加合成，图层标号由各图层角落的彩色标记数量编码。

- `Input structure`：
  - 背景为 black。
  - 网格被等分为若干个大小相同的矩形子区域（如 2x2 或 3x2 的子区域排列），每个子区域之间用一列或一行 grey 分隔线隔开。
  - 每个子区域代表一个"图层"，内部绘有某种彩色图案（使用多种非 black、非 grey 颜色）。图案之间可能有大量 black（透明）区域。
  - 每个子区域的左上角有若干个连续的 maroon 小像素点（沿着顶边从左上角开始排列），数量为 1 到 N（N 为子区域总数）。不同子区域的 maroon 点数量互不相同。

- `Rule`：
  - 每个子区域左上角的 maroon 点数量代表该图层的叠加顺序编号：1 个点 = 最底层，2 个点 = 第二层，依此类推。
  - 输出是一个与单个子区域尺寸相同的网格（去掉分隔线）。
  - 按照编号从小到大（从底层到顶层）依次将各图层的图案叠加：每个图层中非 black 的像素会覆盖下方已有的内容，black 像素则透明（不覆盖下层）。
  - 叠加前先移除每个图层左上角的 maroon 标记像素（将其视为 black/透明）。

- `Key insight`：解题者面临两层推理：第一层是识别每个子区域角落 maroon 点的数量来确定图层叠加顺序（而非按子区域在网格中的空间位置排列）；第二层是理解透明合成规则——black 为透明、非 black 不透明、上层覆盖下层。子区域的空间排列顺序与叠加顺序不一致是关键的迷惑点。
</new_puzzle>

- `description`：识别网格中的"信号源"和"接收器"，通过连线网络传播信号，接收器根据收到信号的数量改变自身形状。

- `Input structure`：
  - 背景为 azure。
  - 网格中有若干个 3x3 的实心彩色方块，称为"信号源"，每个信号源颜色各不相同（如 red、green、yellow 等）。
  - 网格中还有若干个 3x3 的空心矩形框（仅一圈边框像素，内部为背景色），称为"接收器"，边框颜色为 grey。
  - 信号源和接收器之间通过单像素宽的 grey 直线段（水平或垂直）连接。一条线段从信号源的某一侧边中点出发，经过若干次直角转弯，到达某个接收器的某一侧边中点。一个接收器可能连接多个信号源，一个信号源也可能连接多个接收器。

- `Rule`：
  - 对每个接收器，沿着与其相连的 grey 线段回溯，找到所有与之相连的信号源。
  - 统计每个接收器连接的信号源数量 N。
  - 根据 N 值改变接收器的形状（此映射需从训练样例中归纳）：
    - N=1：接收器保持 3x3 空心框不变。
    - N=2：接收器变为 3x3 实心方块。
    - N=3：接收器变为 5x5 空心框（以原中心为中心向外扩展一圈）。
    - N=4：接收器变为 5x5 实心方块。
  - 接收器变换后的颜色：如果 N=1，使用唯一信号源的颜色；如果 N>1，使用连线像素数最少（即路径最短）的那个信号源的颜色。
  - 信号源本身在输出中保持不变。连接线段在输出中保持 grey 不变。

- `Key insight`：解题者需要三层推理：（1）沿 grey 线段追踪网络拓扑，确定每个接收器连接了哪些信号源；（2）根据连接数量确定接收器的目标形状（数量与尺寸/填充的映射需要从样例中归纳）；（3）根据线段长度确定接收器着色使用哪个信号源的颜色。
</new_puzzle>

- `description`：解读网格中散落的"骨牌指令"，按指令序列依次对一个初始色块执行旋转和平移操作，输出最终位置的色块。

- `Input structure`：
  - 背景为 black。
  - 网格左上角有一个小型彩色图案（约 3x3 至 4x4），称为"工件"，由多种颜色组成，形状不对称，便于观察旋转效果。
  - 网格中散布着若干个 1x2 或 2x1 的双色"骨牌"（每个骨牌由两个相邻像素组成，两个像素颜色不同）。
  - 网格右下角有一个 maroon 单像素，标记"目标锚点"。
  - 每个骨牌的两个像素的排列方向（水平或垂直）和颜色组合各不相同。

- `Rule`：
  - 骨牌按照其在网格中从上到下、从左到右的阅读顺序排列，构成一个指令序列。
  - 每个骨牌编码一条操作指令：
    - 骨牌的方向决定操作类型：水平骨牌 = 平移操作，垂直骨牌 = 旋转操作。
    - 对于水平骨牌（平移）：左侧像素的颜色指定平移方向（red=右, blue=左, green=上, yellow=下），右侧像素的颜色无关紧要但保证骨牌可识别。平移距离固定为 1 格。
    - 对于垂直骨牌（旋转）：上方像素如果是 orange 则顺时针旋转 90 度，如果是 magenta 则逆时针旋转 90 度。下方像素不影响操作。
  - 从工件初始位置开始，按指令序列依次执行所有操作。旋转以工件的中心为旋转中心。
  - 输出网格仅保留工件在最终位置和最终朝向的图案，其余全部为背景色。骨牌和 maroon 标记全部清除。

- `Key insight`：解题者必须先发现骨牌的朝向区分了两类不同操作（水平=平移，垂直=旋转），然后分别解码每类操作的参数含义（颜色编码方向）。核心难点在于需要从样例中同时归纳出"骨牌方向→操作类型"和"像素颜色→操作参数"两套独立的编码规则，并按正确顺序执行整个指令链。
</new_puzzle>
