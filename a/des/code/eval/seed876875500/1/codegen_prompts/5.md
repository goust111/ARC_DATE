<new_puzzle index="5">
- `description`：沿彩色边框的颜色分段顺序，对网格内部的同色嵌套环进行逐层"剥皮"操作，每层剥离厚度由边框对应色段的长度决定。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格最外一圈像素构成一个彩色边框，边框由若干段不同颜色的连续像素组成（从左上角顺时针读取，例如：5 个 red → 3 个 blue → 4 个 green → ...），每段颜色不同于相邻段。
  - 网格内部（边框以内）有一个大型的多层嵌套结构：最外层是颜色 A 的像素环，内层是颜色 B 的像素环，再内层是颜色 C 的像素环……形成洋葱状同心矩形环。每层环的厚度不一。环的颜色与边框中出现的颜色相同。

- `Rule`：
  - 从左上角开始，顺时针读取边框上的颜色段序列，得到有序的 (颜色, 段长度) 对列表，例如 [(red, 5), (blue, 3), (green, 4), ...]。
  - 对内部嵌套结构，按照边框颜色段的顺序依次处理每一层：
    - 找到当前嵌套结构最外层环的颜色，在边框颜色段序列中找到与之匹配的颜色段，读取该段的长度 L。
    - 将该层环从外侧剥离 L 个像素的厚度（即将最外侧 L 层像素设为 bg）。如果该环的实际厚度小于 L，则整层全部剥离。
    - 对剥离后暴露出的新最外层重复上述过程，直到所有环都被处理完毕。
  - 边框本身在输出中保持不变。

- `Key insight`：解题需要两层独立的归纳：（1）发现边框的颜色分段不仅标识了内部各环的颜色身份，还通过段长度编码了剥离厚度——颜色是"地址"，长度是"参数"；（2）剥离是逐层从外到内执行的，每层的剥离量由边框中对应颜色段的像素数决定，而非由环本身的几何属性决定。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
