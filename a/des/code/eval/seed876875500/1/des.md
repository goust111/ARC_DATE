- `description`：根据封闭区域内部"种子图案"的朝向，选择对应的外部模板精灵并填充到该区域中。

- `Input structure`：
  - 背景色 bg（最常见颜色）。
  - 若干条由同一颜色（如 green）绘制的闭合矩形边框，将网格划分为多个封闭区域。每个封闭区域内部恰好有一个由两个像素组成的小"种子"标记（使用另一种颜色，如 red），这两个像素相邻（4-连通），排列方向为水平或垂直，因此种子有四种可能朝向：向右（左→右）、向左（右→左）、向下（上→下）、向上（下→上）。
  - 网格边缘外侧（不在任何封闭区域内）分布着恰好四个模板精灵（template sprite），每个精灵是一个由某种独特颜色绘制的小型非对称图案（每个模板颜色不同，如 blue、yellow、magenta、orange）。四个模板分别位于网格的上方区域、下方区域、左侧区域、右侧区域，它们的位置编码了四个方向：上→向上、下→向下、左→向左、右→向右。

- `Rule`：
  - 对每个封闭区域，读取内部种子标记的朝向（向上/向下/向左/向右）。
  - 根据朝向，找到对应方位的模板精灵（例如种子朝右 → 选网格右侧的模板）。
  - 将该模板精灵复制并放置到封闭区域内部（居中对齐），使用模板自身的颜色绘制。种子标记被移除（覆盖为 bg）。
  - 闭合边框和未被选中的模板保持不变。

- `Key insight`：种子的两像素排列方向编码了一个指向，而模板精灵的空间位置（位于网格的哪一侧）编码了对应的方向——解题者必须同时识别出这两层映射关系，才能确定每个区域应填充哪个模板。
</new_puzzle>

- `description`：将散落的彩色碎片沿着同色"轨道线"滑动到轨道末端，碎片到达终点后根据轨道交汇处的颜色叠加规则改变自身颜色。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格中有若干条单像素宽的直线轨道（水平或垂直），每条轨道由一种颜色绘制（如 red、blue、green 等）。不同颜色的轨道可能在某些像素处交叉（交叉点同时属于两条轨道）。
  - 每条轨道的一端（起始端）附近有一个 2×2 的单色碎片（碎片颜色与所在轨道颜色相同），碎片的一条边紧贴轨道起始端。
  - 每条轨道的另一端（终止端）是轨道的自然结束位置（轨道最后一个像素）。

- `Rule`：
  - 每个碎片沿其所在轨道从起始端滑向终止端，碎片整体平移，直到碎片的前沿到达轨道终止端。
  - 碎片滑动后，检查碎片最终位置是否覆盖了其他颜色轨道的交叉点。如果碎片覆盖了一个交叉点，碎片整体变色为交叉轨道的颜色（即不是自身轨道的那个颜色）。如果碎片覆盖了多个不同颜色的交叉点，碎片变为这些交叉颜色中在网格中出现频次最少的那个颜色。
  - 如果碎片最终位置不覆盖任何交叉点，颜色保持不变。
  - 轨道本身在输出中保留。

- `Key insight`：第一层推理是识别碎片-轨道的颜色对应关系和滑动方向；第二层推理是理解终点位置的交叉点如何决定碎片的最终颜色——需要同时关注轨道的几何交叉和颜色替换规则。
</new_puzzle>

<new_puzzle>
- `description`：根据每个"房间"中墙壁缺口的位置和数量，从颜色图例中查找对应颜色，然后用该颜色按缺口方向向房间内部绘制等长的射线条纹。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格中有若干个由 grey 像素构成的矩形"房间"（空心矩形框），每个房间的四面墙上可能有一个或多个单像素宽的缺口（墙壁上缺少一个 grey 像素的位置）。房间内部全为 bg。
  - 网格的一个角落（如左上角）有一个颜色图例区域：图例是一个小型表格，由若干行组成，每行包含 N 个连续的同色像素（N = 1, 2, 3, ...），行按 N 从小到大排列。每行的颜色各不相同（如 N=1 为 red，N=2 为 blue，N=3 为 green 等）。

- `Rule`：
  - 对每个房间，数出其四面墙壁上缺口的总数 N（N 一般在 1~5 之间）。
  - 在颜色图例中找到长度为 N 的那一行，读取该行的颜色 C。
  - 对该房间的每个缺口，从缺口位置向房间内部（垂直于缺口所在墙壁的方向）绘制一条颜色为 C 的射线，射线长度等于 N 个像素，不超出房间内部边界。
  - 图例区域和房间墙壁在输出中保持不变。

- `Key insight`：解题需要两步非平凡推理：（1）缺口数量不是直接可见的属性标签，需要主动逐面清点并求和；（2）数量→颜色的映射必须通过图例的行长度来建立对应关系，而非简单的位置索引。射线的方向和长度同时受缺口位置与数量约束，形成几何与计数的耦合。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中每个多色精灵的内部"旋转指令"像素，按指令旋转精灵后，将所有精灵拼合到一个公共画布上进行像素叠加混色。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格中散布着若干个互不重叠的多色精灵（每个精灵由多种非 bg 颜色组成，占据一个紧致的矩形包围盒）。
  - 每个精灵的包围盒的四个角落位置中，恰好有一个角落像素的颜色与精灵内部其他像素的颜色都不同——这个独特颜色的角落像素就是"旋转指令"像素。指令像素所在的角落位置编码了旋转角度：左上角 = 不旋转（0°），右上角 = 顺时针 90°，右下角 = 顺时针 180°，左下角 = 顺时针 270°。
  - 所有精灵的包围盒尺寸相同（去掉旋转指令像素后的有效区域尺寸相同）。

- `Rule`：
  - 对每个精灵，找到其旋转指令像素（包围盒四角中颜色独特的那个），确定旋转角度。
  - 移除旋转指令像素（设为 bg），然后按指定角度旋转精灵剩余部分。
  - 将所有旋转后的精灵对齐叠放在同一个画布上（画布大小 = 精灵有效区域大小）。叠放规则：如果某个位置只有一个精灵有非 bg 像素，直接使用该颜色；如果多个精灵在同一位置都有非 bg 像素，则使用 maroon 标记该冲突位置。
  - 输出为叠放后的紧凑画布。

- `Key insight`：三层推理结构——（1）识别每个精灵中哪个角落像素是"指令"（需要发现它颜色独特这一规律）；（2）建立角落位置→旋转角度的映射（需要从样例中归纳四种对应关系）；（3）理解多精灵叠加时的冲突处理规则（冲突位置的特殊标记色需要从样例中发现）。
</new_puzzle>

<new_puzzle>
- `description`：沿彩色边框的颜色分段顺序，对网格内部的同色嵌套环进行逐层"剥皮"操作，每层剥离厚度由边框对应色段的长度决定。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格最外一圈像素构成一个彩色边框，边框由若干段不同颜色的连续像素组成（从左上角顺时针读取，例如：5 个 red → 3 个 blue → 4 个 green → ...），每段颜色不同于相邻段。
  - 网格内部（边框以内）有一个大型的多层嵌套结构：最外层是颜色 A 的像素环，内层是颜色 B 的像素环，再内层是颜色 C 的像素环……形成洋葱状同心矩形环。每层环的厚度不一。环的颜色与边框中出现的颜色相同。

- `Rule`：
  - 从左上角开始，顺时针读取边框上的颜色段序列，得到有序的 (颜色, 段长度) 对列表，例如 [(red, 5), (blue, 3), (green, 4), ...]。
  - 对内部嵌套结构，按照边框颜色段的顺序依次处理每一层：
    - 找到当前嵌套结构最外层环的颜色，在边框颜色段序列中找到与之匹配的颜色段，读取该段的长度 L。
    - 将该层环从外侧剥离 L 个像素的厚度（即将最外侧 L 层像素设为 bg）。如果该环的实际厚度小于 L，则整层全部剥离。
    - 对剥离后暴露出的新最外层重复上述过程，直到所有环都被处理完毕。
  - 边框本身在输出中保持不变。

- `Key insight`：解题需要两层独立的归纳：（1）发现边框的颜色分段不仅标识了内部各环的颜色身份，还通过段长度编码了剥离厚度——颜色是"地址"，长度是"参数"；（2）剥离是逐层从外到内执行的，每层的剥离量由边框中对应颜色段的像素数决定，而非由环本身的几何属性决定。
</new_puzzle>

- `description`：根据网格中"镜面"线段的位置和角度，将源图案反射到镜面另一侧，反射后的图案颜色由镜面自身的颜色决定。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格中有若干条由不同颜色绘制的直线段，每条线段为水平、垂直或 45° 对角线方向，长度至少 3 个像素，这些线段充当"镜面"。
  - 每面镜子的一侧（且仅一侧）有一个由 grey 像素构成的小型非对称图案（源图案）。源图案紧邻镜面（与镜面像素 4-连通或对角相邻）。镜面另一侧为空（bg）。

- `Rule`：
  - 对每面镜子，以镜面线段为对称轴，将其一侧的 grey 源图案做轴对称反射到另一侧。
  - 反射生成的图案不使用 grey，而是使用镜面本身的颜色来绘制。
  - 如果反射后的像素落在网格外，则忽略该像素。如果反射后的像素位置已有非 bg 内容（如另一面镜子或另一个源图案），反射像素不覆盖已有内容。
  - 原始的 grey 源图案在输出中保留不变。

- `Key insight`：解题者需要首先识别哪些线段是"镜面"（它们的一侧有 grey 图案、另一侧为空）；然后理解反射的几何操作（特别是对角线镜面的反射不同于水平/垂直镜面）；最后发现反射图案的颜色继承规则——不是继承源图案的颜色，而是使用镜面自身的颜色，这一规则需要从多个样例中对比才能归纳。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到由围墙包围的迷宫区域，根据迷宫内部路径像素的局部连通构型（直道、L 弯、T 岔、十字），使用角落图例定义的颜色映射为路径着色。

- `Input structure`：
  - 背景色 bg（如 black）。
  - 网格中有一个由 grey 像素构成的迷宫围墙，围墙内部形成单像素宽的连通路径（路径像素为 bg）。路径没有大于 1×1 的开阔区域，所有路径像素恰好形成一个 4-连通的网络。
  - 网格的某个角落有一个颜色图例，图例包含四个小图示，每个图示是一个 3×3 的格子，中心为某种颜色像素，周围用 grey 墙壁和 bg 空位展示了四种局部路径构型：
    - 直道（中心像素的上下两个邻居为 bg 或左右两个邻居为 bg，即两个对向邻居为通路）→ 中心像素颜色为 A
    - L 弯（中心像素的两个相邻正交方向的邻居为 bg，如上和右，即形成直角弯）→ 中心像素颜色为 B
    - T 岔（中心像素的三个邻居为 bg）→ 中心像素颜色为 C
    - 十字（中心像素的四个邻居都为 bg）→ 中心像素颜色为 D

- `Rule`：
  - 对迷宫中每个路径像素，检查其上下左右四个邻居中哪些是通路（bg 或网格外视为墙壁），统计通路邻居的数量和排布，判断该像素属于哪种局部构型：2 个对向通路 = 直道，2 个相邻正交通路 = L 弯，3 个通路 = T 岔，4 个通路 = 十字。
  - 端点像素（仅 1 个通路邻居）保持为 bg 不着色。
  - 从图例中查找该构型对应的颜色，将该路径像素着色为对应颜色。
  - 图例和围墙在输出中保持不变。

- `Key insight`：解题者需要先理解图例中 3×3 图示编码的是路径的局部拓扑分类（而非具体方向的形状模板——例如水平直道和垂直直道都属于"直道"类），然后将这种抽象分类规则应用到迷宫中每个路径像素——关键难点在于从图例中提取的是"连通模式类别"而不是"可旋转匹配的瓷砖"，解题者必须归纳出邻居通路数量与排布这一抽象维度。
</new_puzzle>
