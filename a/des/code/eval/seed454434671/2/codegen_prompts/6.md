将分散的彩色碎片按形状互补性配对拼合为完整矩形，再根据碎片所在网格半区的位置决定拼合矩形的放置区域。

Input structure:
- bg = black。网格被一条水平的 grey 分隔线（宽度 1 像素，贯穿网格全宽）分为上下两个半区。
- 上半区和下半区各散布着若干单色碎片（4-连通连通区域）。碎片颜色从 red、blue、green、yellow、orange 中选取。
- 每个碎片的形状是某个矩形的一部分。恰好有一个上半区碎片和一个下半区碎片能配对：它们颜色相同，最小外接矩形（bounding box）尺寸相同，且一个碎片在 bounding box 中占据的像素恰好是另一个碎片在同尺寸 bounding box 中未占据的像素（几何互补）。

Rule:
- 第一层（跨半区配对）：对于每种颜色，找到上半区和下半区中 bounding box 尺寸相同的同色碎片对，验证它们形状互补（拼合后恰好填满一个完整矩形）。
- 第二层（拼合放置）：将配对成功的两个碎片拼合为一个完整的实心矩形。该矩形放置在下半区中原来下半区碎片的 bounding box 位置，颜色为该碎片对的颜色。
- 上半区中已配对的碎片被擦除（变为 bg），下半区中原碎片被替换为拼合后的完整矩形。未配对的碎片原样保留。grey 分隔线保留。

Key insight: 碎片配对需要跨越分隔线在两个半区之间寻找几何互补关系，而不是在同一区域内匹配——分隔线既是视觉分界也是配对规则的隐含约束。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
