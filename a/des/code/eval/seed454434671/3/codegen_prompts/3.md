- `description`：根据网格中"管道"的拓扑连通关系，将阀门标记的颜色沿管道传播，在管道交汇处按混色规则生成新颜色。

- `Input structure`：
  - 背景色为 black。网格中有由 grey 像素绘制的单像素宽管道网络，管道沿水平和垂直方向延伸，在交叉点形成十字或 T 形连接。
  - 管道的某些末端（死端）紧邻一个彩色像素（非 black、非 grey），称为"阀门标记"。每个阀门标记颜色不同，可能出现的颜色包括 red、blue、yellow。
  - 管道网络中存在若干交汇节点（即管道像素同时有 3 个或 4 个正交方向的 grey 邻居）。

- `Rule`：
  - 第一步（颜色传播）：从每个阀门标记出发，沿其相邻的管道方向传播颜色，将管道上的 grey 像素替换为该阀门的颜色。传播沿管道持续进行，直到遇到交汇节点或管道末端。
  - 第二步（交汇混色）：当一个交汇节点从不同方向接收到两种颜色时，该节点及其后续管道段染为混合色：red + blue = magenta，red + yellow = orange，blue + yellow = green。若三种颜色同时到达，则染为 maroon。
  - 第三步（继续传播）：混合后的颜色继续沿未染色的管道传播，若再次遇到交汇并与另一颜色混合，则按同样的混色规则处理。
  - 阀门标记像素本身保留在输出中不变。

- `Key insight`：解题者首先需要从样例中归纳出"颜色沿管道传播"的机制，然后再发现交汇处的混色规则（这不是物理混色常识，而是需要从样例中对比推断的映射表）——传播方向判定和混色映射构成两层独立推理。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
