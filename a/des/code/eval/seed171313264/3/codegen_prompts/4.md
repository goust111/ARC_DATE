根据每条彩色路径穿过"染色门"的顺序，对路径上的线段逐段重新着色。

Input structure:
- 背景为 black。网格中有若干由 grey 像素构成的水平和垂直线段，它们首尾相连形成若干条不分叉的折线路径（每个 grey 像素最多与两个 grey 像素 4-连通相邻，路径端点只有一个邻居）。
- 在某些路径的一个端点处放置了一个非 black、非 grey 的彩色像素作为"起点标记"，表示路径的遍历起始端。不同路径的起点标记颜色相同或不同。
- 网格中还散布着若干"染色门"：每个染色门是一个孤立的非 black、非 grey 彩色像素，不与任何 grey 像素 4-连通相邻，但恰好与某条路径上的某个 grey 像素 4-连通相邻（即门像素与路径像素在同一行或同一列且相距 1 格）。染色门的颜色各异。

Rule:
- 对每条有起点标记的路径，从起点标记开始沿路径行走。
- 路径上的线段以拐点（方向改变的位置）为界分为若干"直线段"。
- 初始着色为起点标记的颜色。从起点出发，将当前直线段的所有 grey 像素改为当前颜色。
- 每当行走过程中经过一个与染色门相邻的 grey 像素时，当前颜色切换为该染色门的颜色。此后的直线段使用新颜色。
- 染色门像素本身保持不变。
- 没有起点标记的路径保持 grey 不变。

Key insight: 第一层归纳是发现路径由端点的彩色标记确定遍历方向，第二层是发现染色门不在路径上而是与路径相邻，其作用是在经过时切换后续线段的颜色。解题者需要理解"段"的划分（以拐点为界）和颜色切换的触发条件（经过门的邻接像素时切换，而非到达门时切换）。
</description>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
