- `description`：网格中的彩色"门"控制信号路径的走向：信号从源点出发沿直线传播，遇到门时根据门的颜色与朝向发生转弯或分裂，最终到达的终点格被标记。
- `Input structure`：黑色背景。网格中有若干红色（Red）单像素作为"源点"，每个源点的某一侧紧邻一个同色像素（共 2 像素），两像素的排列方向即为信号初始传播方向（例如两像素水平排列且源点在左，则信号向右传播）。网格中散布着若干"门"，每个门由 3 个同色像素组成 L 形（非红色），L 形的直角顶点为门的"枢纽"，两臂分别长 1 像素。不同颜色的门有不同行为。
- `Rule`：
  1. 信号从每个红色源点出发，沿初始方向逐格传播（不留痕迹，只关心终点）。
  2. 信号遇到门的枢纽像素时：
     - 绿色（Green）门：信号转向 90 度，转向方向为门的另一臂所指的方向（即信号从一臂方向进入枢纽，从另一臂方向射出）。
     - 黄色（Yellow）门：信号分裂为两束，一束继续直行，另一束转向 90 度（转向方向同绿色门规则）。
     - 蓝色（Blue）门：信号被吸收并停止，枢纽像素位置即为终点。
  3. 信号若未遇到任何门而到达网格边界，则边界处最后一个格为终点。
  4. 所有终点格被涂上橙色（Orange）。其余所有内容（源点、门、背景）保持不变。
- `Key insight`：解题者需先理解 L 形门的朝向决定了信号的入射和出射关系（并非简单的"碰墙反弹"），再区分三种颜色门的不同行为（转向、分裂、吸收），最后追踪可能因分裂而产生的多条路径。门的颜色编码行为类型、门的几何形状编码方向信息，两者必须同时解读。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
