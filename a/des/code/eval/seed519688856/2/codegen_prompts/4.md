  - 背景色为 Black。
  - 网格左侧有一个纵向排列的"图例区"，由 Grey 水平线分隔成若干条目（3 到 5 个）。每个条目包含两部分：左半是一个由彩色像素构成的小型边框图案（约 4×4，仅边框上的部分像素有色，内部为 Black），右半是一个几何变换示意——一个 Azure 小图标，表示特定变换类型。具体地：Azure 像素排成向右的水平箭头（3 像素长的水平线 + 右端上下各 1 像素）= 水平翻转；排成向下的垂直箭头 = 垂直翻转；排成顺时针弧形的 L 形（2 像素水平 + 右端向下 2 像素）= 顺时针旋转 90°；排成逆时针弧形的倒 L 形（2 像素水平 + 左端向下 2 像素）= 逆时针旋转 90°。
  - 网格右侧有若干矩形彩色区域（互不接触），每个区域被一圈单像素宽的彩色边框包围，边框内部有由其他颜色绘制的非对称图案内容。每个区域的边框颜色与图例区中某个条目的边框颜色相同，且边框上有色像素的相对位置模式与该条目的边框像素模式一致（即边框的哪些位置有像素、哪些位置缺失完全对应）。

- `Rule`：
  - 第一层推理——指纹匹配：对于每个右侧区域，提取其边框上有色像素的相对位置模式（记录边框四条边上哪些位置有像素、哪些位置为 Black 缺口），与图例区各条目的边框模式逐一比对，找到颜色和模式均匹配的条目。
  - 第二层推理——内容变换：根据匹配条目右半部分的 Azure 图标所指示的几何变换类型，对该区域边框内部的图案内容执行相应变换（水平翻转 / 垂直翻转 / 顺时针 90° / 逆时针 90°）。变换后的内容替换原内容，边框本身保持位置和形状不变。
  - 图例区在输出中保持不变。

- `Key insight`：边框不仅是区域的容器，其上像素的缺失位置排列模式本身就是一种"指纹编码"，用于在图例中检索该区域应执行的变换类型。解题者需要先发现边框模式与图例的对应关系，再理解图例中 Azure 图标所代表的具体几何操作。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
