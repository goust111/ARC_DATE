- `description`：识别画布上由虚线矩形框定义的"选区"，将选区内的图案按照选区边框上缺口的位置和数量进行平铺复制到选区外。

- `Input structure`：
  - 背景色为 Black。画布上有若干个小型彩色图案（每个图案由单一颜色的连通像素构成，3x3 到 5x5 大小不等）。
  - 每个图案被一个由 Grey 虚线构成的矩形框包围（虚线模式为：每隔 1 个像素画 1 个 Grey 像素，即 Grey-Black-Grey-Black 交替排列的边框）。虚线框与图案之间有 1 像素的间距。
  - 每个虚线矩形框的四条边上，有若干个位置的 Grey 像素被替换为 Red 像素，这些 Red 像素构成"缺口标记"。每条边上最多有 1 个 Red 像素。

- `Rule`：
  - 对于每个虚线框，检查四条边上是否存在 Red 缺口标记。
  - 对于有 Red 缺口的每条边，将框内的图案沿该边的法线方向（向外）复制一份。复制品的位置紧贴虚线框外侧，与原图案的间距等于虚线框的厚度（1 像素）加上 1 像素间距。
  - 若一条边上无 Red 标记，则该方向不复制。
  - 复制出的图案与原图案颜色相同。
  - 输出中移除所有虚线框和 Red 标记，仅保留原图案及其复制品。

- `Key insight`：虚线框的 Red 缺口是方向指令——每个缺口指示一个复制方向。解题者需要先识别虚线框结构（而非将其视为普通像素），再理解 Red 标记与复制方向的对应关系，最后确定复制品的精确放置位置。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
