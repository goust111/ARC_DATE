将网格中散落的彩色碎片按"拼接规则"组装成完整矩形，其中每块碎片的缺口方向指示了它在矩形中的位置。

Input structure:
- 背景色（bg）为 black。网格中散布着若干彩色碎片，每块碎片是一个近似矩形但有一条边带有凹槽缺口的形状（缺口为背景色侵入碎片的一个矩形凹陷）。
- 每块碎片使用同一种颜色，但不同碎片颜色不同。
- 网格右侧有一个由 grey 线条画出的空心目标矩形框架，尺寸恰好等于所有碎片无缝拼合后的大小。目标框架内部有若干 grey 的内部分割线，将框架分成与碎片数量相同的子区域。

Rule:
- 第一层推理——缺口配对：每块碎片恰好有一个凹槽缺口，而另一块碎片在对应位置恰好有一个凸起突出（即该碎片在那个方向上比矩形多出一小块）。凹槽与凸起的尺寸完全吻合，形成唯一的配对关系。解题者需要识别哪些碎片互为邻居。
- 第二层推理——空间排布：根据配对关系和碎片的缺口朝向（上/下/左/右），确定每块碎片在目标矩形中的相对位置。缺口朝右的碎片，其右侧邻居就是拥有匹配凸起的碎片。将所有碎片平移到目标框架中对应的子区域内，碎片颜色保留不变。
- 碎片之间的拼接处（凹凸交界）在输出中用碎片各自的颜色填充（凸起部分覆盖凹陷部分），grey 框架线保留。

Key insight:
碎片的形状不仅是装饰——凹凸缺口编码了邻接关系和方向信息。解题者必须先通过缺口形状配对找到邻居，再根据缺口方向推断空间布局，两步推理串联才能完成拼图。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
