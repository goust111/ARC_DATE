  - 网格中有若干个用 grey 像素绘制的空心矩形框架（大小各异，互不重叠，边框宽度 1 像素）。
  - 每个框架内部包含一个由单一非 grey 非 black 颜色组成的小型图案（占据框架内部面积的一小部分）。
  - 这些内部图案各自具有不同的对称性类型：有的关于水平中轴对称，有的关于垂直中轴对称，有的关于两条中轴都对称（即同时水平和垂直对称），有的完全不对称。
- `Rule`：
  - 第一步（对称性分类）：分析每个框架内部小图案的对称性：
    - 仅水平对称 → 类型 H
    - 仅垂直对称 → 类型 V
    - 双轴对称（水平+垂直）→ 类型 B
    - 无对称 → 类型 N
  - 第二步（框架着色）：根据对称性类型将 grey 框架重新着色：
    - 类型 H → 框架变为 red
    - 类型 V → 框架变为 blue
    - 类型 B → 框架变为 green
    - 类型 N → 框架变为 yellow
  - 第三步（图案扩展）：根据对称性类型，将内部小图案沿对称轴方向镜像复制直至填满框架内部：
    - 类型 H → 将图案沿水平轴上下镜像复制，向上和向下重复铺满内部。
    - 类型 V → 将图案沿垂直轴左右镜像复制，向左和向右重复铺满内部。
    - 类型 B → 将图案沿两轴同时镜像复制，向四个方向重复铺满内部。
    - 类型 N → 图案不扩展，保持原样。
    扩展时图案以原位置为中心，交替使用原图案和镜像图案进行平铺，超出框架内部边界处裁剪。
- `Key insight`：需要两层非平凡推理：第一层是从内部图案的几何特征中识别出"对称性类型"作为分类依据（而非颜色或大小），第二层是理解对称性类型同时决定了两件事——框架的颜色映射以及图案的扩展方向——这两个输出维度都由同一个隐含属性控制。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
