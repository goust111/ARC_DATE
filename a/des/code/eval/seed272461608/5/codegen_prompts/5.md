  - 某些框架的边框上附着有小标记：由 1-2 个 yellow 像素组成，紧贴在框架边框的外侧。标记的位置（在框架的上/下/左/右边以及沿边的偏移量）对每层框架各不相同。

  - 第一步（分层提取）：识别嵌套层次，从外到内依次提取每一层框架。记录每层框架的颜色、尺寸、以及附着标记相对于该层框架的位置。
  - 第二步（展开排列）：在输出网格中，将所有层的框架从左到右并排排列（层级从左到右为从外到内），框架之间间隔 2 列 black 背景，所有框架顶部对齐于第 0 行。每个框架保持其原始尺寸和颜色。

- `Key insight`：核心推理有三层——第一层需要正确解析嵌套层次关系（区分哪些框架包含哪些框架），第二层需要归纳"深度→填充颜色"的映射规则（这个映射只能通过对比多个样例中不同深度框架的填充颜色来发现），第三层需要注意标记的位置是相对于其所属框架而非全局坐标系定义的，展开后必须按相对位置正确还原。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
