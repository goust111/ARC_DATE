根据框架内部的彩色种子像素生长出与种子颜色匹配的图案模板，然后将生长结果按框架边框颜色指定的翻转方式写入框架内部。

Input structure:
- bg = Black。网格上散布着若干大小不同的空心矩形框架，每个框架的边框由某种非背景颜色绘制（如 Red、Blue、Green 等），框架内部填充背景色。
- 每个框架内部恰好有一个单像素的"种子"像素，颜色与边框颜色不同。
- 在网格的某个角落区域，有一组"图案模板"：每个模板是一个小的连通图案（3×3 至 5×5），由单一颜色绘制在背景上，且每种颜色的模板恰好出现一次。

Rule:
- 第一步（颜色匹配）：将每个框架内部的种子像素颜色与图案模板的颜色进行匹配，找到同色的模板。
- 第二步（翻转规则）：根据框架边框颜色确定翻转方式。网格边缘有一个颜色图例区域，每种边框颜色对应一个小箭头标记（由该颜色绘制的 3 像素 L 形）：L 形开口朝右表示不翻转；开口朝左表示水平翻转；开口朝上表示垂直翻转；开口朝下表示同时水平和垂直翻转。
- 第三步（放置）：将匹配到的模板按照翻转方式变换后，以种子像素为模板左上角的锚点，绘制到框架内部。模板像素覆盖背景色区域；若模板超出框架内部范围则截断。种子像素本身被模板覆盖。

Key insight: 解题需要同时发现两层独立的映射关系——种子颜色决定"画什么"，边框颜色通过箭头图例决定"怎么画"——两层映射互不相关，必须分别从样例中归纳。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
