- `Input structure`：
  - 背景色 bg 为黑色（Black）。
  - 网格中央有一个较大的灰色（Grey）矩形"模板"，模板内部有一个由 bg 组成的不规则镂空区域。
  - 模板外部散布着若干彩色碎片（各碎片颜色相同，均为某种非 bg、非灰色的颜色 C1），碎片形状各异、大小不一。
  - 所有碎片恰好可以无重叠、无缝隙地拼合填满模板的镂空区域（碎片可能需要平移，但不旋转不翻转）。
  - 网格的一侧（如最左列或最上行附近）有一个"图例面板"：面板中包含 3-5 个小型轮廓图形，每个轮廓图形旁边紧邻一个 1x1 的颜色标记像素。这些轮廓图形的形状各不相同。
- `Rule`：
  - 第一步（拼合）：将所有碎片平移到模板的镂空区域中，使碎片恰好填满整个镂空。填入后碎片保持颜色 C1。
  - 第二步（轮廓匹配）：拼合完成后，观察镂空区域的整体轮廓形状，在图例面板中找到与该轮廓形状相同的小型图形（图例中的图形是镂空轮廓的缩小版，尺寸等比缩放）。
  - 第三步（重新着色）：将模板中灰色区域全部替换为图例面板中匹配图形旁的颜色标记所指示的颜色。填入镂空的碎片保持颜色 C1 不变。图例面板从输出中删除（变为 bg）。
- `Key insight`：表面上看碎片拼合是主要任务，但实际上拼合只是中间步骤——真正的目的是通过拼合还原镂空区域的完整轮廓形状，再用这个形状去图例面板中查表获取模板的最终着色。解题者需要跨越"拼合"和"形状查表"两层独立的推理。

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
