- `description`：根据框架内部的彩色种子像素，选择匹配的外部碎片填入框架，并按种子像素的位置决定碎片的旋转方向。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个相同大小的正方形空心框架（边框颜色统一为 grey），框架内部为 black 背景，但每个框架内部的某一条边（上/下/左/右）的中点处有一个彩色种子像素。
  - 网格中还散布着若干个与框架内部尺寸相同的实心彩色小方块图案（碎片），每个碎片由一种非 grey、非 black 的颜色绘制，碎片内部有不对称的图案（例如 L 形、T 形等）。
  - 每个碎片的颜色与恰好一个框架内种子像素的颜色相同，形成一一对应。

- `Rule`：
  - 第一步：通过颜色匹配，将每个碎片与对应的框架配对——碎片颜色等于框架内种子像素的颜色。
  - 第二步：观察种子像素位于框架内部哪条边的中点：上边中点 → 碎片不旋转（0°）；右边中点 → 碎片顺时针旋转 90°；下边中点 → 碎片旋转 180°；左边中点 → 碎片顺时针旋转 270°。
  - 第三步：将旋转后的碎片填入对应框架的内部区域，覆盖种子像素。框架边框保持不变。
  - 碎片原来在网格中的位置变为 black 背景。

- `Key insight`：种子像素同时编码了两层信息——颜色决定"哪个碎片归我"，位置决定"碎片要转多少度"。解题者必须先完成颜色配对，再从种子在框架内的方位推断旋转量，两步推理缺一不可。
</new_puzzle>

- `description`：将网格中的彩色路径按照路径交叉点处的优先级规则重新分配颜色，使得高优先级路径在交叉处"压过"低优先级路径。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干条由不同颜色绘制的单像素宽路径（水平或垂直线段的组合），路径之间存在交叉点。
  - 网格左侧有一列纵向排列的彩色方块作为"优先级图例"，从上到下排列，顶部颜色优先级最高，底部最低。图例与路径之间有至少两列 black 间隔。
  - 每条路径的颜色都恰好出现在图例中。

- `Rule`：
  - 第一步：从左侧图例中读取颜色优先级排序（从上到下 = 从高到低）。
  - 第二步：找到所有路径交叉点（即同一像素被两条不同颜色的路径共用的位置；在输入中，交叉点显示为其中一条路径的颜色）。
  - 第三步：在每个交叉点处，将该像素设为优先级较高的路径颜色。同时，沿优先级较低的路径，从交叉点向两侧各延伸一个像素也改为高优先级颜色（表示高优先级路径在交叉处"覆盖"了低优先级路径的一小段）。
  - 非交叉区域的路径颜色保持不变。

- `Key insight`：图例不是简单的颜色标签，而是编码了一套优先级排序。解题者需要先破译"上高下低"的优先级含义，再将其应用于每个交叉点的颜色冲突解决，并注意覆盖范围向两侧各延伸一格的规则。

- `Input structure`：
  - 背景色为 orange。
  - 网格中有若干个由 grey 像素围成的封闭矩形区域（类似房间），每个区域内部背景为 orange。
  - 每个封闭区域内部有若干个 red 像素组成的箭头形状。箭头由 3 个像素构成：一个头部像素和两个尾部像素排成直线，头部像素在前进方向的最前端，两个尾部像素紧随其后排成一列。箭头指向上/下/左/右四个方向之一。一个区域内可能有 1 到 3 个箭头，且所有箭头指向同一方向。
  - 在网格中（封闭区域外部），沿每个可能的方向散布着若干小型彩色图章（3x3 或更小的非 orange、非 grey、非 red 的连通图案），每个图章颜色各不相同。

- `Rule`：
  - 第一步：对每个封闭区域，识别其内部箭头的方向和数量。
  - 第二步：从该区域的 grey 边界出发，沿箭头所指方向向外寻找最近的彩色图章。
  - 第三步：将找到的图章复制到封闭区域内部。若区域内有 N 个箭头，则沿箭头方向在区域内排列 N 个图章副本（相邻副本之间无间隔）。图章从靠近箭头指向方向的对面墙开始放置（即箭头指右，图章从区域左侧开始向右排列）。
  - 箭头像素被图章覆盖；区域外的原始图章保持不变。

- `Key insight`：箭头同时编码三层信息——方向决定"从哪里取图章"，数量决定"复制几份"，而放置起点则是方向的反向（从对面墙开始）。解题者需要先理解方向与取材的关系，再发现数量与重复的关系，最后注意放置的起始位置规则。

<new_puzzle>
- `description`：将散落的彩色碎片按形状互补性配对拼成完整矩形，再按矩形面积从小到大的顺序将它们堆叠排列到输出网格中。

- `Input structure`：
  - 背景色为 black。
  - 网格中散布着偶数个彩色碎片（4-connected 连通区域），每个碎片有独特的颜色。
  - 这些碎片可以两两配对：同一对中的两个碎片形状互补——即将它们（不旋转、不翻转）放入同一个最小外接矩形时，一个碎片占据的像素恰好是另一个碎片未占据的像素（两者合在一起填满整个矩形，无重叠无空隙）。
  - 不同对的矩形大小可能不同。

- `Rule`：
  - 第一步：识别所有碎片，计算每个碎片的最小外接矩形（bbox）。将 bbox 尺寸相同的碎片归为候选配对组。
  - 第二步：在每个候选组内，检验两个碎片在其 bbox 内的像素是否互补（一个为实、另一个为空的位置完全吻合）。确认互补的两个碎片形成一对。
  - 第三步：对所有配好的对，计算它们拼成的完整矩形面积，按面积从小到大排序。
  - 第四步：在输出网格中，从左上角开始，按排序顺序水平排列这些完整矩形。每个矩形内部两块碎片各保留自己的原始颜色。矩形之间留一列 black 间隔。

- `Key insight`：解题者首先需要发现"形状互补"这一配对规则——不是颜色匹配也不是形状相同，而是两个碎片像拼图一样恰好填满同一个矩形。然后需要发现输出的排列顺序取决于拼合后矩形的面积大小。两层推理彼此独立但都非显然。
</new_puzzle>

- `description`：通过对比"完好样本"和"破损样本"找出缺失部分的形状，然后在对应颜色的画布区域中绘制该缺失形状。

- `Input structure`：
  - 背景色为 black。
  - 网格被 blue 线（一行或一列贯穿整个网格的 blue 像素）分割成若干矩形区域。
  - 其中有若干对区域构成"样本对"：每对中一个区域包含一个完整的彩色图案（"完好样本"），另一个区域包含同一图案的残缺版本（"破损样本"，即从完好样本中移除了一块连通区域后的结果）。完好样本和破损样本使用相同的颜色，可以通过颜色匹配将它们配对。
  - 另外还有若干个区域是纯色填充的"画布"（仅包含单一颜色的背景填充，如 green、red 等），每个画布的颜色与恰好一对样本的颜色相同。

- `Rule`：
  - 第一步：通过颜色匹配将区域配对——每种非 black、非 blue 的图案颜色恰好出现在三个区域中：完好样本、破损样本和画布。
  - 第二步：将完好样本与破损样本对齐比较（两者 bbox 尺寸相同），找出完好样本中有而破损样本中没有的像素集合——即缺失部分的形状。
  - 第三步：将缺失部分的形状绘制在对应颜色的画布区域中央（水平和垂直都居中），使用 maroon 颜色绘制，画布原有的填充色保留在未被绘制的位置。

- `Key insight`：解题者需要完成三层非平凡推理：(1) 通过颜色将三种区域（完好、破损、画布）正确分组；(2) 通过"做差"发现缺失形状——这要求识别出哪个是完好版、哪个是破损版（破损版像素更少）；(3) 缺失形状不是用原色而是用统一的 maroon 色绘制在画布上，且要居中放置。
</new_puzzle>

<new_puzzle>
- `description`：根据网格中"钥匙"和"锁"的齿形匹配关系，将匹配的钥匙平移插入对应的锁中，并用钥匙颜色填充锁的内部空隙。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个"锁"：每个锁是一个 grey 矩形块，其中一条边上有若干个矩形缺口（凹槽），缺口朝外（朝向 black 背景），缺口内部为 black。不同锁的凹槽数量、宽度和间距各不相同。
  - 网格中还有若干个"钥匙"：每个钥匙是一个彩色（非 grey、非 black）的矩形条，其中一条边上有若干个矩形凸起（齿），凸起朝外。不同钥匙颜色不同。
  - 每把钥匙的齿形（凸起的数量、宽度和间距）与恰好一个锁的凹槽形状完全吻合。钥匙的齿朝向与锁的凹槽朝向相对（例如锁的凹槽朝右，则匹配的钥匙的齿朝左）。

- `Rule`：
  - 第一步：识别每个锁的凹槽轮廓和每把钥匙的齿形轮廓。
  - 第二步：将每把钥匙与凹槽形状匹配的锁配对（齿的数量、宽度、间距必须与凹槽完全吻合）。
  - 第三步：将钥匙沿其齿朝向的方向平移，直到钥匙的齿完全嵌入锁的凹槽中（齿填满凹槽，钥匙的矩形主体紧贴锁的有凹槽的那条边）。
  - 第四步：钥匙到达最终位置后，锁的凹槽被钥匙的齿填满（显示钥匙的颜色），钥匙的矩形主体也保留在新位置。钥匙原来的位置变为 black。

- `Key insight`：解题者需要先识别"凸起 vs 凹槽"的互补几何关系来完成配对（这不是颜色匹配，而是形状匹配），然后推断出钥匙的平移方向和距离（方向由齿的朝向决定，距离由锁和钥匙之间的间距决定）。两层推理分别涉及形状匹配和空间平移。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到每个彩色对象的"影子投射面"，根据对象的高度（像素行数）决定影子的长度，并检测影子是否被其他对象遮挡而截断。

- `Input structure`：
  - 背景色为 azure。
  - 网格底部有一行 grey 像素作为"地面"。
  - 地面上方有若干个彩色矩形对象（每个对象颜色不同，宽度不同，均"站"在地面上，即底边紧贴 grey 行的上方）。对象之间水平不重叠。
  - 所有对象的颜色各不相同，且都不是 azure、grey 或 yellow。

- `Rule`：
  - 假设光源在网格左上角。每个对象向右方投射影子。
  - 第一步：对每个对象，影子长度等于该对象的高度（行数）。影子是从对象右边缘向右延伸的水平条带，影子的垂直范围仅覆盖地面那一行（即影子画在 grey 地面行上）。
  - 第二步：影子颜色为 yellow。影子从对象右边缘的正下方（地面行）开始，向右延伸"高度"个像素。
  - 第三步：如果影子在延伸过程中遇到另一个对象的底边（即该对象也站在地面上，占据了地面行上方的像素，其底边对应的地面位置已被该对象"占据"），影子在该对象左边缘处截断——不会穿过其他对象。
  - 不改变对象本身的像素，仅在地面行上绘制 yellow 影子。

- `Key insight`：解题者首先需要发现影子长度与对象高度的对应关系（不是宽度，也不是面积），然后需要注意影子会被右侧邻近对象遮挡截断。高度→长度的映射和遮挡截断是两层独立的推理。
</new_puzzle>
