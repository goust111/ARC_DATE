- `description`：根据封闭区域内"指示箭头"的方向，将区域外对应方向上最近的彩色图章复制到封闭区域内部，并按箭头数量决定图章的重复次数。

- `Input structure`：
  - 背景色为 orange。
  - 网格中有若干个由 grey 像素围成的封闭矩形区域（类似房间），每个区域内部背景为 orange。
  - 每个封闭区域内部有若干个 red 像素组成的箭头形状。箭头由 3 个像素构成：一个头部像素和两个尾部像素排成直线，头部像素在前进方向的最前端，两个尾部像素紧随其后排成一列。箭头指向上/下/左/右四个方向之一。一个区域内可能有 1 到 3 个箭头，且所有箭头指向同一方向。
  - 在网格中（封闭区域外部），沿每个可能的方向散布着若干小型彩色图章（3x3 或更小的非 orange、非 grey、非 red 的连通图案），每个图章颜色各不相同。

- `Rule`：
  - 第一步：对每个封闭区域，识别其内部箭头的方向和数量。
  - 第二步：从该区域的 grey 边界出发，沿箭头所指方向向外寻找最近的彩色图章。
  - 第三步：将找到的图章复制到封闭区域内部。若区域内有 N 个箭头，则沿箭头方向在区域内排列 N 个图章副本（相邻副本之间无间隔）。图章从靠近箭头指向方向的对面墙开始放置（即箭头指右，图章从区域左侧开始向右排列）。
  - 箭头像素被图章覆盖；区域外的原始图章保持不变。

- `Key insight`：箭头同时编码三层信息——方向决定"从哪里取图章"，数量决定"复制几份"，而放置起点则是方向的反向（从对面墙开始）。解题者需要先理解方向与取材的关系，再发现数量与重复的关系，最后注意放置的起始位置规则。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
