<description>
根据种子图案中不同颜色区域的形状，在对应颜色的空框架内生成该形状的缩放副本。

Input structure:
- bg = black。网格左侧有一个由灰色(grey)边框围起的"种子区域"，内部包含若干不同颜色的连通区域（如 red、blue、green），每个区域形状各异（L形、T形、直线等），但面积较小（3-6像素）。
- 网格右侧散布着若干大小不等的空心矩形框架，每个框架的边框颜色与种子区域中某一颜色相同。框架内部全为 black。

Rule:
- 对于每个彩色框架，找到种子区域中与其边框颜色相同的连通区域，提取该区域的形状（相对于其自身 bounding box 的像素模式）。
- 将该形状等比缩放以恰好填满框架内部的可用空间（框架内部宽高即为缩放目标尺寸），缩放后的形状用该颜色绘制在框架内部。
- 缩放方式：种子形状 bounding box 的每个像素映射为框架内部空间中对应比例的矩形块（整数倍缩放，水平缩放因子 = 框架内部宽度 / 种子形状 bounding box 宽度，垂直同理）。
- 种子区域和框架本身保持不变，只在框架内部填充缩放后的图案。

Key insight: 需要先在种子区域中按颜色分离出各形状模板，再根据每个框架的内部尺寸与模板 bounding box 的比值进行整数倍缩放——颜色同时充当模板索引和绘制颜色，而框架大小决定缩放倍率。
</description>

识别网格中的"信号源"和"中继站"，让信号沿管道传播并在中继站处按规则变色，最终染色所有传播路径。

Input structure:
- bg = black。网格上有一条由 grey 像素构成的正交管道网络（单像素宽的水平/垂直线段，可在交叉点分叉）。
- 管道网络中有若干"信号源"：位于管道末端（死胡同）的彩色像素（非 grey、非 black），每个信号源颜色不同。
- 管道网络的某些交叉点上有"中继站"：一个 maroon 像素。中继站的四个正交邻居中恰好有两个方向连接着管道。
- 管道网络中还有若干"颜色门"：紧贴管道旁边（与管道像素 4-邻接但自身不在管道上）的彩色单像素，颜色与某个信号源相同。

Rule:
- 每个信号源向其连接的管道方向发出信号，信号沿 grey 管道传播，将经过的 grey 像素染为信号源的颜色。
- 信号到达中继站时：检查该中继站的两个管道方向，信号从入方向进入，从另一方向继续传播。同时，信号颜色变为该中继站旁边最近的"颜色门"的颜色（如果中继站旁无颜色门则保持原色）。
- 如果两个信号在同一段管道上相遇（从两端同时到达），该段管道的颜色由先到达的信号决定（距离该段起点更近的信号源优先）；若等距则保持 grey。
- 信号传播到管道末端或另一个信号源位置时停止。

Key insight: 三层推理结构——第一层识别管道拓扑和信号源位置，第二层理解中继站的"变色"机制（颜色门决定变色后的颜色），第三层处理多信号竞争时的优先级规则。管道网络的分叉使得信号覆盖范围和颜色变化需要逐段追踪。
</description>

- bg = black。网格中散布着若干由单一颜色构成的中空矩形"模具"（hollow rectangle），每个模具的一条边上有一个矩形缺口（边框中断形成的开口）。

- 将每个印章与尺寸匹配的模具缺口配对（印章 bounding box 尺寸 = 缺口尺寸，配对唯一）。
- 确定模具缺口在模具的哪一侧（上/下/左/右）。

- 印章原始位置清除为 bg。

Key insight: 两层非平凡推理——第一层通过尺寸匹配建立印章-模具配对关系，第二层通过 grey 标记点位置与缺口方向的对应关系确定旋转角度。标记点的"指向外侧"规则是隐蔽的核心机制，需要从多个样例中归纳出标记点始终朝向模具外侧这一模式。

<description>
根据网格中散落的彩色"路标"箭头所指方向，将对应颜色的像素群沿箭头方向依次堆叠压缩到网格边界，形成层叠的色带。

Input structure:
- bg = black。网格中有若干不同颜色的像素群（每种颜色的所有像素构成一个松散的分布，不一定连通）。
- 每种颜色在网格中恰好有一个 3x3 的"路标箭头"：箭头由该颜色的 5 个像素组成，在 3x3 bounding box 内排列成指向四个正交方向之一的箭头形状。具体画法：向右的箭头在 3x3 框中：第0行第1列为尖端像素，第1行第0列和第1行第1列为杆像素，第0行第0列和第2行第0列为翼像素——不对，更准确地说：向右箭头 = (1,2)为尖端，(1,1)为杆中段，(1,0)为杆尾部，(0,2)和(2,2)为翼——这也不对。明确定义如下：向右箭头在3x3框内的5个像素位置为：(0,1), (1,0), (1,1), (1,2), (2,1)——即十字形，不是箭头。重新定义：向右箭头 = 第1行全部3像素 (1,0)(1,1)(1,2) 构成水平杆 + (0,2)(2,2) 构成右侧两翼，共5像素。向上箭头 = 第1列全部3像素 (0,1)(1,1)(2,1) 构成垂直杆 + (0,0)(0,2) 构成顶部两翼，共5像素。向下箭头 = 第1列全部3像素 (0,1)(1,1)(2,1) 构成垂直杆 + (2,0)(2,2) 构成底部两翼，共5像素。向左箭头 = 第1行全部3像素 (1,0)(1,1)(1,2) 构成水平杆 + (0,0)(2,0) 构成左侧两翼，共5像素。翼所在的一侧即为箭头指向的方向。
- 除箭头外，该颜色的其余像素随机散布在网格中（每种颜色另有3-8个散布像素）。

Rule:
- 对于每种颜色，识别其唯一的3x3箭头（5像素连通区域且符合上述形状之一），提取箭头的朝向。
- 收集该颜色所有非箭头像素的坐标。
- 将这些像素沿箭头指向的方向"推"到网格边界：保持像素在垂直于推动方向的轴上的坐标不变，在推动方向上将同一行（或同一列）的所有该颜色像素紧密堆叠到对应的网格边缘。堆叠时保持像素之间的原始相对顺序。
- 箭头本身从输出中移除（变为 bg）。
- 不同颜色的堆叠互不干扰，各自独立执行。若不同颜色堆叠后发生重叠，则按该颜色箭头距其指向边界的距离排序，距离近的颜色在上层（覆盖其他颜色）。

Key insight: 路标箭头既是颜色标识又是方向指令——需要先识别每种颜色中哪个5像素区域是箭头（而非普通像素群），再通过翼的位置解码箭头方向，最后执行"重力堆叠"。箭头形状的识别和方向解码构成第一层推理，堆叠压缩规则构成第二层推理。
</description>

<description>
从网格中的多组"密码锁"读取指令序列，用指令控制一个游标在迷宫中移动，绘出游标的运动轨迹。

Input structure:
- bg = black。网格被一条 grey 水平分割线分为上下两部分。
- 上半部分是"迷宫区"：由 blue 像素构成的可通行路径（单像素宽的正交通道网络），路径上有一个 red 像素标记起点。通道的交叉口处可能有多个方向可选。
- 下半部分是"密码区"：包含若干水平排列的小型"密码锁"，每个密码锁是一个由 grey 边框围起的矩形小格子（内部高1像素、宽3-6像素），内部有一行彩色像素序列。每个密码锁的左侧紧贴一个方向指示符——一个由 green、yellow、orange 或 maroon 单像素构成的标记，分别代表上、右、下、左四个方向。

Rule:
- 游标从 red 起点出发。按密码锁从左到右的顺序依次读取指令。
- 每个密码锁提供一条移动指令：方向由左侧单像素色块决定（green=上, yellow=右, orange=下, maroon=左），步数等于密码锁内部彩色像素的数量。
- 游标沿指定方向在 blue 通道上移动指定步数。每一步移动一个像素。如果在移动过程中遇到通道分叉，游标始终优先选择当前指令方向继续前进；如果当前方向被墙壁阻挡但只有唯一的其他正交方向可走，则转向该方向继续计步。
- 游标经过的所有 blue 像素在输出中被染为当前密码锁内部像素中出现次数最多的颜色（主色）。
- 最终输出仅保留迷宫区：游标走过的路径被染色，未走过的 blue 通道保持 blue 不变。red 起点像素也被路径颜色覆盖。密码区和分割线从输出中移除。

Key insight: 三层结构——第一层从密码锁中解码方向（色块到方向的映射需从样例归纳）和步数（数内部像素个数），第二层理解游标在通道分叉处的行为规则（优先当前方向、否则唯一可行方向），第三层发现路径染色颜色来自密码锁内部的主色而非方向指示色。密码区作为外部指令集控制迷宫内的轨迹绘制，这种跨区域的信息传递是核心难点。
</description>

<description>
识别网格中每个封闭区域内的"投票像素"，用多数票颜色填充该区域的边界框架，同时将少数票颜色写入区域中心作为标记。

Input structure:
- bg = black。网格中有若干由 grey 像素构成的封闭矩形框架（单像素宽 grey 边框，内部为 bg），框架之间不重叠不接触。
- 每个框架内部散布着若干彩色像素（至少两种颜色），这些像素即为"投票像素"。每个框架内部恰好有两种非 bg 颜色。

Rule:
- 对于每个 grey 框架，统计其内部两种彩色像素各自的数量。
- 数量较多的颜色为"多数色"，数量较少的为"少数色"。如果两色数量相等，则在框架内部按从上到下、从左到右扫描顺序先出现的颜色为多数色。
- 将该框架的 grey 边框像素全部替换为多数色。
- 清除框架内部所有彩色像素（变为 bg），然后在框架内部的正中心位置放置一个少数色像素。若内部宽或高为偶数导致没有唯一中心像素，则取偏左上方的中心位置（即 row = 内部起始行 + (内部高度-1)/2 向下取整, col = 内部起始列 + (内部宽度-1)/2 向下取整）。
- 框架的矩形形状和大小保持不变。

Key insight: 两层推理——第一层需要发现框架内部的像素是"投票"，多数色决定边框颜色（框架颜色从统一的 grey 变成了各自不同的颜色，这一变化引导解题者去寻找颜色来源）；第二层需要发现少数色并没有消失，而是被浓缩为中心的单个标记点。"投票"机制的隐蔽性在于解题者需要从边框颜色的变化反推出计数规则。
</description>

<description>
将网格中的彩色对象视为"透镜"，从边缘光源发射光线，光线在交叉处进行颜色混合，生成新的混合色像素。

Input structure:
- bg = black。网格的四条边上各有若干"光源"像素，每个光源是位于网格最外圈的单个彩色像素（颜色仅限 red、blue 或 yellow 三种）。
- 位于上/下边缘的光源发射垂直光线（上边缘向下、下边缘向上），位于左/右边缘的光源发射水平光线（左边缘向右、右边缘向左）。
- 网格内部有若干由 grey 像素构成的小型实心矩形"挡板"（尺寸为 1x2 或 2x1），挡板会完全阻止光线穿过。

Rule:
- 每个光源向网格内部发射一条直线光线（单像素宽），光线颜色与光源相同。光线从光源位置的下一个像素开始延伸，直到遇到挡板或到达网格对面的边缘为止。
- 当两条不同颜色的光线（一条水平、一条垂直）交叉于同一像素时，该像素显示混合色：red + blue = magenta，red + yellow = orange，blue + yellow = green。
- 当三条不同颜色的光线交叉于同一像素时（red + blue + yellow），该像素显示 maroon。
- 同色光线交叉时保持原色不变。
- 挡板保持 grey 不变，光线被挡板阻挡后不继续延伸（挡板后方无光线）。
- 光源像素本身保留在输出中。

Key insight: 两层推理——第一层识别光源位置与射线方向的对应关系（哪条边缘决定哪个方向），第二层发现颜色混合规则（类似颜料三原色混色的直觉：red+blue=magenta, red+yellow=orange, blue+yellow=green, 三色混合=maroon）。挡板引入了遮挡关系，使得哪些交叉点实际会被光线覆盖需要逐条追踪，增加了空间推理的复杂度。
</description>

<description>
从一个"时间轴"带状区域中读取多帧快照的排列顺序，将散落在主区域中的对象按快照指示的位移逐帧移动并留下残影，输出累积叠加后的最终画面。

Input structure:
- bg = black。网格被一条垂直 grey 分割线分为左右两部分。
- 右侧是"时间轴区"：包含 K 个垂直排列的小矩形格子（由 grey 水平细线分隔），每个格子内部是一个微缩的网格快照，显示若干彩色小点的位置分布。每个格子内部尺寸相同（如 5x5）。这些格子从上到下代表第 1 帧到第 K 帧（K 通常为 3-5）。
- 左侧是"主区域"：包含若干彩色对象（每个对象是一个小型连通的彩色 sprite，2-6 像素大小），对象的颜色和数量与时间轴第 1 帧中的小点一一对应（每种颜色恰好一个对象和一个对应的点）。主区域的宽高是时间轴格子内部尺寸的整数倍（如3倍），每个时间轴格子中的一个像素对应主区域中一个等大的方块区域。

Rule:
- 时间轴第 1 帧中每个颜色点的位置，经过缩放映射后，对应主区域中该颜色对象当前所在的方块区域（对象的中心或左上角落入该区域内）。
- 从第 1 帧到第 K 帧，逐帧读取每个颜色点的位置变化。相邻帧之间，某颜色点的位置偏移量乘以缩放因子，即为主区域中该对象的平移量。
- 对象在每一帧经过的位置上留下自身的"残影"——即对象形状以对象颜色永久绘制在该位置，不会被后续帧清除。
- 最终输出是所有帧残影累积叠加后的主区域画面。如果不同对象的残影重叠，后续帧（帧号更大的）覆盖先前帧的颜色。
- 输出仅包含主区域（时间轴区和分割线被移除）。

Key insight: 三层结构——第一层建立时间轴微缩格子与主区域之间的空间缩放映射关系（需要计算缩放因子），第二层从时间轴连续帧中解码每个对象的逐帧位移向量，第三层理解"残影累积"叠加机制（每帧的对象位置都保留在最终输出中，后帧覆盖前帧）。时间轴将时序信息编码在垂直空间排列中，这种编码方式是核心隐蔽机制。
</description>
</new_puzzle>
