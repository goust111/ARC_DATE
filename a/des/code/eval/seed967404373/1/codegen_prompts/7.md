将网格中的彩色对象视为"透镜"，从边缘光源发射光线，光线在交叉处进行颜色混合，生成新的混合色像素。

Input structure:
- bg = black。网格的四条边上各有若干"光源"像素，每个光源是位于网格最外圈的单个彩色像素（颜色仅限 red、blue 或 yellow 三种）。
- 位于上/下边缘的光源发射垂直光线（上边缘向下、下边缘向上），位于左/右边缘的光源发射水平光线（左边缘向右、右边缘向左）。
- 网格内部有若干由 grey 像素构成的小型实心矩形"挡板"（尺寸为 1x2 或 2x1），挡板会完全阻止光线穿过。

Rule:
- 每个光源向网格内部发射一条直线光线（单像素宽），光线颜色与光源相同。光线从光源位置的下一个像素开始延伸，直到遇到挡板或到达网格对面的边缘为止。
- 当两条不同颜色的光线（一条水平、一条垂直）交叉于同一像素时，该像素显示混合色：red + blue = magenta，red + yellow = orange，blue + yellow = green。
- 当三条不同颜色的光线交叉于同一像素时（red + blue + yellow），该像素显示 maroon。
- 同色光线交叉时保持原色不变。
- 挡板保持 grey 不变，光线被挡板阻挡后不继续延伸（挡板后方无光线）。
- 光源像素本身保留在输出中。

Key insight: 两层推理——第一层识别光源位置与射线方向的对应关系（哪条边缘决定哪个方向），第二层发现颜色混合规则（类似颜料三原色混色的直觉：red+blue=magenta, red+yellow=orange, blue+yellow=green, 三色混合=maroon）。挡板引入了遮挡关系，使得哪些交叉点实际会被光线覆盖需要逐条追踪，增加了空间推理的复杂度。
</description>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
