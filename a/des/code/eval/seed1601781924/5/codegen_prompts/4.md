<new_puzzle index="4">
- `description`：网格中有若干对称图案和打破对称的"污点"像素；找出每个图案中的污点并将其移动到图案对称轴的镜像位置，同时污点的颜色根据其所在图案的对称类型（水平/垂直/中心对称）而改变。

- `Input structure`：
  - 背景色（bg）为黑色（black）。
  - 网格中有若干互相分离的彩色图案（connected components），每个图案由一种主色构成，形状"几乎"具有某种对称性（水平轴对称、垂直轴对称、或 180° 中心旋转对称），但恰好有一个像素位置偏离了完美对称——该位置有一个不同颜色的"污点"像素。
  - 每个图案的主体色各不相同。污点像素的颜色在输入中统一为 maroon。
  - 每个图案的对称轴/对称中心由其主体形状（忽略污点）的最小外接矩形中心确定。

- `Rule`：
  - 第一层推理：对每个图案，将 maroon 污点暂时替换为主色后，检查该图案满足哪种对称——优先检测水平轴对称，其次垂直轴对称，最后 180° 中心旋转对称。取第一个满足的对称类型。
  - 第二层推理：根据对称类型对污点位置做镜像/旋转，得到污点应当出现的正确位置。将污点从原位置移除（原位置填充为图案主色），在镜像位置放置污点。
  - 第三层推理：污点在输出中的颜色取决于对称类型：水平对称 → 污点变为 red；垂直对称 → 污点变为 blue；中心旋转对称 → 污点变为 green。
  - 图案主体其余部分不变。

- `Key insight`：解题者不仅需要识别"几乎对称"的模式和找到污点，还需要判断对称的类型——后者是隐蔽的，因为不同图案可能外观相似但对称类型不同，而对称类型直接决定了污点的最终颜色和位置。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
