<new_puzzle>
根据框架边缘的缺口位置与内部色块的颜色对应关系，将外部精灵投射到框架内部并按镜像轴翻转。

Input structure:
- bg = 最常见颜色。网格中有一个大型空心矩形框架，框架由 maroon 色绘制，框架的四条边上各有若干单格缺口（缺口处为 bg 色）。
- 框架内部散布着若干单色小方块（2x2），每个小方块颜色各不相同。
- 框架外部散布着若干单色精灵（形状不规则，3-6 格大小），每个精灵颜色各不相同，但与框架内部某个小方块颜色一一对应。
- 框架每条边上的缺口数量为 1 或 2 个。

Rule:
- 第一层推理：对于框架内部的每个 2x2 色块，找到它最近的框架边（上/下/左/右），该边上的缺口位置决定了投射的目标列或目标行。具体地：色块靠近上边则看上边缺口的列坐标，靠近左边则看左边缺口的行坐标，以此类推。
- 第二层推理：在框架外部找到与该色块同色的精灵，将精灵复制到框架内部，使精灵的中心对齐到（色块行/列，缺口列/行）的交叉点。如果该边有两个缺口，则精灵复制两份，分别对齐到两个交叉点。
- 第三层推理：精灵在放入框架时，需要沿"色块到最近边"的方向轴做镜像翻转。即若色块靠近上边，则精灵做上下翻转后放入；靠近左边则做左右翻转后放入。
- 框架内部原来的 2x2 色块被移除（变为 bg），精灵不得超出框架边界，超出部分裁剪。

Key insight: 色块到最近边的方向同时决定了两件事——在哪条边上读取缺口坐标，以及精灵放入时的翻转轴向。缺口充当坐标索引而非通道，色块充当颜色匹配键而非填充物。
</new_puzzle>

<new_puzzle>
根据管道网络的连通性将源色从入口传播到各出口，管道交叉处按叠加规则混色。

Input structure:
- bg = black。网格中有由 grey 色绘制的单格宽管道线段，管道只沿水平或垂直方向延伸，在某些格子处形成 L 形拐弯或十字交叉。
- 网格边缘处有若干"入口"标记：紧贴网格最外一行/列的管道端点旁放置一个彩色像素（red、blue、yellow 三色之一），表示该入口注入该颜色。
- 网格边缘处还有若干"出口"标记：紧贴网格最外一行/列的管道端点旁放置一个 green 像素，表示该处为出口。
- 管道网络内部还有若干"阀门"：用 orange 色的单格像素标记在管道上，阀门只允许一个方向通过——阀门所在格与其上下左右四邻中恰好有两个 grey 邻居，阀门允许从离入口更远的那个邻居方向流入，从离入口更近的那个邻居方向流出（即只允许"顺流"通过，不可逆流）。

Rule:
- 第一层推理：从每个入口的彩色像素出发，沿管道进行洪水扩散。扩散沿 grey 管道格子传播，遇到 bg 则停止，遇到阀门时检查方向是否为顺流方向（远→近），若逆流则该路径被阻断。
- 第二层推理：当两条不同颜色的路径在十字交叉格相遇时，该交叉格变为混合色：red + blue = magenta，red + yellow = orange，blue + yellow = green。若三色交汇则变为 maroon。
- 将所有管道格子（grey）替换为其最终传播到的颜色（若只有一色则为该色，若多色则为混合色，若无色到达则保持 grey）。入口彩色像素和出口 green 像素保持不变，阀门 orange 像素也替换为传播到的颜色。

Key insight: 阀门的方向性制造了非对称传播，解题者必须先推断每个阀门的允许方向（通过管道拓扑而非距离计算——沿管道追踪到入口的路径方向），然后才能确定哪些颜色能到达交叉点并进行混色。混色规则是固定的两两组合映射，不涉及算术运算。
</new_puzzle>

<new_puzzle>
将散落的拼图块按照边缘齿形互锁规则拼合成完整矩形，齿形朝向决定拼接位置。

Input structure:
- bg = azure。网格中散布着若干矩形色块（每块为单一非 bg 颜色，大小约 3x3 至 5x5），每块的某些边缘上带有单格凸起（"齿"）或单格凹陷（"槽"）。
- 凸起表现为：矩形主体某边向外多出一个同色像素。凹陷表现为：矩形主体某边向内缺少一个像素（该处为 bg 色）。
- 每块的四条边中，有些边是光滑的（无齿无槽），有些边有恰好一个齿或一个槽。
- 光滑边表示该方向是拼合后矩形的外边缘。有齿或有槽的边表示该方向需要与另一块拼接。

Rule:
- 第一层推理：判断每块的哪些边是外边缘（光滑边）、哪些边需要拼接（有齿或有槽的边）。从光滑边的分布推断每块在最终矩形中的位置类型——四角块有两条相邻光滑边，边缘块有一条光滑边，内部块无光滑边。
- 第二层推理：齿和槽的互锁配对——一块的齿必须嵌入相邻块同一位置的槽中。齿和槽在边上的偏移位置（距该边起点的格数）必须完全吻合。利用这一约束确定哪两块相邻以及它们的相对位置。
- 第三层推理：将所有块按推断出的相对位置拼合成一个紧密矩形。拼合时齿嵌入槽中（齿的像素覆盖到相邻块的槽位置上），最终输出为填满的矩形，无 bg 间隙。输出时每块保持原色。

Key insight: 光滑边→位置类型→大致布局，齿槽偏移量匹配→精确配对。解题者不能仅靠颜色或大小排列，必须同时利用边缘的光滑/齿/槽属性和齿的精确位置来唯一确定拼合方案。
</new_puzzle>

<new_puzzle>
用种子像素的颜色从调色板行中查找生长模板，然后从种子位置按模板形状向指定方向生长，生长层数由种子周围的卫星点数量决定。

Input structure:
- bg = black。网格底部有一个"调色板区"：由一条 grey 水平线分隔，线下方有若干行，每行左端是一个彩色像素（键色），右侧紧跟一个小型图案（3x3，用 maroon 色绘制），代表该键色对应的"生长模板"。不同键色对应不同的 3x3 模板形状。
- grey 线上方是"画布区"。画布区中散布若干"种子组"，每个种子组由以下部分构成：
  - 一个彩色种子像素（颜色与调色板某个键色相同）。
  - 种子像素的正上/正下/正左/正右四个方向之一上，距种子 2 格处有一个 green 箭头标记（由 3 个 green 像素组成的 L 形：一个像素在中心，另外两个像素向远离种子的方向展开形成箭头尖端），指示生长方向。
  - 种子像素周围（8-邻域内）有 0 到 4 个 grey 单像素"卫星点"。

Rule:
- 第一层推理（查表）：根据种子像素的颜色，在调色板区找到对应的 3x3 生长模板。
- 第二层推理（读方向与层数）：green 箭头标记指示生长方向（上/下/左/右）。种子 8-邻域内的 grey 卫星点数量 N 决定生长层数。
- 第三层推理（执行生长）：以种子像素为起点，沿箭头方向逐层铺设模板。第 1 层模板的近端边与种子像素相邻（种子占据模板中心列/行的前一格位置），第 2 层模板紧接第 1 层的远端，以此类推共 N 层。每层模板用种子的颜色绘制。
- 生长完成后，移除所有 green 箭头标记和 grey 卫星点。种子像素保留。调色板区保持不变。模板之间以及模板与其他对象重叠时，后绘制的模板覆盖先前内容。

Key insight: 解题需要三个独立的非显然推断——颜色→模板形状的查表映射、箭头→方向的空间解读、卫星数→重复次数的计数映射——三者缺一不可才能确定最终输出。模板本身的形状在调色板区可见但需要正确提取，生长方向和层数则完全由种子周围的标记决定。
</new_puzzle>

<new_puzzle>
根据封闭区域内信号塔的覆盖范围对区域分层染色，覆盖层数不同的格子着不同颜色，颜色顺序由区域边框色在色带中的位置决定。

Input structure:
- bg = black。网格中有若干由不同颜色绘制的封闭矩形边框（边框线宽 1 格），边框之间不重叠、不嵌套，边框内部为 bg。
- 每个边框内部有 1 到 3 个"信号塔"：用 red 单像素标记。
- 网格的最上方一行是一条"色带"：从左到右依次排列若干不同颜色的像素（不含 black 和 red），每种颜色占一格，颜色之间无间隔。色带中的颜色数量至少为 4。

Rule:
- 第一层推理（确定染色序列）：找到每个边框自身的颜色在色带中的位置索引 K（从左数第几个，从 1 开始）。该边框内部的染色将使用色带中从第 K 个位置开始的连续颜色序列——第 1 层用色带第 K 色，第 2 层用色带第 K+1 色，第 3 层用色带第 K+2 色，以此类推。
- 第二层推理（计算覆盖层数）：每个 red 信号塔以十字形（上下左右四个方向）向外扩展，直到碰到边框线或其他信号塔的覆盖区域为止。边框内部的每个 bg 格子被 0 到多个信号塔的十字覆盖范围所覆盖。统计每个格子被覆盖的信号塔数量（0、1、2 或 3）。
- 第三层推理（染色）：覆盖数为 0 的格子保持 bg 不变。覆盖数为 1 的格子染为该边框染色序列的第 1 色，覆盖数为 2 的染为第 2 色，覆盖数为 3 的染为第 3 色。
- 信号塔自身的 red 像素保留不变。边框线保留不变。色带保留不变。

Key insight: 解题者必须先发现边框颜色在色带中的位置索引决定了染色的"起始偏移"，再发现信号塔的十字覆盖叠加数决定了使用序列中的第几个颜色。两层映射（边框色→色带偏移，覆盖计数→序列内索引）独立且均需从样例中归纳，单看任何一层都无法解出完整答案。
</new_puzzle>

<new_puzzle>
将网格中的路径段按端点颜色配对连接，连接线穿过中转站时改变方向，中转站的形状决定转弯规则。

Input structure:
- bg = black。网格中有若干条短路径段（每条由 2-4 个连续 grey 格子组成，沿水平或垂直方向排列），每条路径段的两个端点中恰好有一个被染为彩色（非 black、非 grey），另一个端点保持 grey。
- 网格中还散布着若干"中转站"：由 maroon 色像素组成的小型形状。中转站有两种类型：
  - "直角站"：3 个 maroon 像素组成 L 形（占据一个角及其两个正交方向各延伸一格）。
  - "直通站"：2 个 maroon 像素组成水平或垂直的短线段。
- 彩色端点的颜色成对出现（每种彩色恰好出现两次），需要将同色的两个端点连接起来。

Rule:
- 第一层推理（配对）：找到所有彩色端点，将同色的两个端点配为一对。每对端点需要用一条连接线从一个端点的 grey 端出发，到达另一个端点的 grey 端。
- 第二层推理（路径规划与中转）：连接线沿 grey 端点所指的方向（即路径段的延伸方向）出发，以直线前进，直到碰到一个中转站。碰到直角站时，连接线转 90 度弯（沿 L 形的另一臂方向继续）；碰到直通站时，连接线保持原方向不变穿过。连接线继续前进直到碰到下一个中转站或到达目标端点。
- 第三层推理（绘制）：连接线用该对端点的彩色绘制，覆盖沿途的 bg 格子。中转站的 maroon 像素保持不变。原有的 grey 路径段保持不变。每条连接线恰好经过所需的中转站序列，路径唯一确定（不存在歧义）。

Key insight: 路径段的方向指定了出发角度，中转站的形状（L 形 vs 直线形）决定了转弯 vs 直行的行为。解题者必须先理解两种中转站形状对应的不同转向规则，然后才能正确追踪每条连接线的完整路径。颜色配对是第一层，方向读取是第二层，中转站形状→行为映射是第三层。
</new_puzzle>

<new_puzzle>
根据容器内色块的排列模式在容器外壁对应位置生成标记，排列模式的分类由隐含的对称性类型决定。

Input structure:
- bg = azure。网格中有若干个由 grey 色绘制的空心矩形容器（大小约 5x5 至 7x7），容器之间不重叠。
- 每个容器内部填有一个由单一非 bg、非 grey 颜色绘制的图案，图案占据容器内部的部分格子。
- 网格右下角有一个"图例区"：由一条 maroon 色 L 形边框围起，图例区内有 3 行，每行展示一种对称类型的示意图和对应的标记样式：
  - 第一行：一个小型左右对称图案，旁边跟一个 yellow 像素——表示左右对称类型对应 yellow 标记。
  - 第二行：一个小型上下对称图案，旁边跟一个 green 像素——表示上下对称类型对应 green 标记。
  - 第三行：一个小型无对称图案，旁边跟一个 red 像素——表示无对称类型对应 red 标记。
  （若图案同时具有左右和上下对称，则视为左右对称优先。）

Rule:
- 第一层推理（理解图例）：从图例区中归纳出"对称类型→标记颜色"的映射关系：左右对称→yellow，上下对称→green，无对称→red。
- 第二层推理（分类容器）：对每个容器内部的彩色图案，判断其对称性类型——是否具有左右镜像对称（以容器内部水平中线为轴）、上下镜像对称（以容器内部垂直中线为轴）、或两者皆无。若同时具有两种对称则归为左右对称。
- 第三层推理（生成标记）：根据分类结果，在容器的外壁上生成标记：
  - 左右对称→在容器的左边框和右边框的外侧中点各放一个 yellow 像素。
  - 上下对称→在容器的上边框和下边框的外侧中点各放一个 green 像素。
  - 无对称→在容器的四个角的外侧对角位置各放一个 red 像素。
- 容器和其内部图案保持不变。图例区保持不变。

Key insight: 解题者必须先从图例区的三个示意行中识别出对称类型与标记颜色的对应关系（图例本身不会直接写出"对称"二字，需要从示意图案的视觉特征归纳），然后对每个容器的内容进行对称性判断，最后还要发现标记的放置位置（边中点 vs 角）也取决于对称类型。三层推理环环相扣。
</new_puzzle>
