根据框架边缘的缺口位置与内部色块的颜色对应关系，将外部精灵投射到框架内部并按镜像轴翻转。

Input structure:
- bg = 最常见颜色。网格中有一个大型空心矩形框架，框架由 maroon 色绘制，框架的四条边上各有若干单格缺口（缺口处为 bg 色）。
- 框架内部散布着若干单色小方块（2x2），每个小方块颜色各不相同。
- 框架外部散布着若干单色精灵（形状不规则，3-6 格大小），每个精灵颜色各不相同，但与框架内部某个小方块颜色一一对应。
- 框架每条边上的缺口数量为 1 或 2 个。

Rule:
- 第一层推理：对于框架内部的每个 2x2 色块，找到它最近的框架边（上/下/左/右），该边上的缺口位置决定了投射的目标列或目标行。具体地：色块靠近上边则看上边缺口的列坐标，靠近左边则看左边缺口的行坐标，以此类推。
- 第二层推理：在框架外部找到与该色块同色的精灵，将精灵复制到框架内部，使精灵的中心对齐到（色块行/列，缺口列/行）的交叉点。如果该边有两个缺口，则精灵复制两份，分别对齐到两个交叉点。
- 第三层推理：精灵在放入框架时，需要沿"色块到最近边"的方向轴做镜像翻转。即若色块靠近上边，则精灵做上下翻转后放入；靠近左边则做左右翻转后放入。
- 框架内部原来的 2x2 色块被移除（变为 bg），精灵不得超出框架边界，超出部分裁剪。

Key insight: 色块到最近边的方向同时决定了两件事——在哪条边上读取缺口坐标，以及精灵放入时的翻转轴向。缺口充当坐标索引而非通道，色块充当颜色匹配键而非填充物。
</new_puzzle>

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。

4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
