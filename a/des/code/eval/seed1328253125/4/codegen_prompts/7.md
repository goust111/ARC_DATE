- `description`：将网格中的彩色"信号源"像素沿灰色线段网络传播颜色，在交汇节点处按三原色混合规则生成新颜色并继续级联传播。
- `Input structure`：
  - bg = 最常见颜色（如 black）。
  - 网格中有若干 grey 像素组成的线段网络（水平和垂直线段，宽 1 像素，互相在交叉点连接形成网络）。
  - 网络的某些末端（只有一个 grey 邻居的端点）被替换为彩色像素——这些是"信号源"，颜色为 red、blue 或 yellow（仅这三种原色）。
  - 网络中存在一些交叉节点（有 3 个或 4 个 grey 邻居的 grey 像素），这些是"交汇点"。
- `Rule`：
  - 每个信号源沿其连接的 grey 线段传播自身的颜色，将路径上的 grey 像素染为信号源的颜色。传播在遇到交汇点时停止（交汇点本身暂不被染色）。
  - 对于每个交汇点，收集从各条分支传来的所有信号源颜色（去重）。
  - 如果交汇点只收到一种颜色，它变为该颜色，并继续沿未传入的分支向外传播该颜色。
  - 如果交汇点收到恰好两种原色，它变为这两种原色的混合色：red + blue = magenta，red + yellow = orange，blue + yellow = green。混合色继续沿未传入的分支向外传播。
  - 如果交汇点收到三种原色，它变为 maroon，不再向外传播。
  - 传播过程逐层进行：先处理直接连接信号源的交汇点，再处理下一层交汇点，直到网络中所有可达的交汇点都被处理。
- `Key insight`：解题者需要先理解 grey 网络是颜色传播的通道结构，然后发现交汇点的颜色混合遵循直觉的"颜料三原色混合"规则（而非简单覆盖），最后理解混合色会继续作为新信号向下游传播——"网络拓扑→混色规则→级联传播"构成三层递进推理。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。

6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
