- `description`：利用边框上的箭头标记确定种子像素的生长方向和射线长度，射线交叉处变色。
- `Input structure`：
  - bg = 最常见颜色（如 black）。
  - 网格四周有 1 像素宽的 grey 边框。
  - 边框上的某些位置被替换为 red 像素，形成"方向标记"。顶部边框上的 red 像素表示"向下"，底部表示"向上"，左侧表示"向右"，右侧表示"向左"。
  - 网格内部（边框以内区域）散布着若干 blue 单像素点（种子像素）。每个种子像素恰好对应一个行方向边框标记和一个列方向边框标记：即该种子所在行的左或右边框有一个 red 标记，且该种子所在列的顶或底边框也有一个 red 标记。
- `Rule`：
  - 对于每个种子像素，找到其所在行对应的边框 red 标记（左侧或右侧边框），确定水平生长方向（左边框标记→向右生长，右边框标记→向左生长）。
  - 统计该种子所在行的边框上共有多少个 red 标记（通常为 1 个），该数量即为水平射线的长度（从种子出发，不含种子自身）。不，修正：射线从种子出发沿方向一直延伸到碰到边框为止。
  - 同理，找到其所在列对应的边框 red 标记（顶部或底部边框），确定垂直生长方向，射线沿垂直方向延伸到碰到边框为止。
  - 从种子位置出发，沿水平方向画出 blue 射线直到边框，沿垂直方向也画出 blue 射线直到边框。
  - 若两条不同种子产生的射线在某个像素交叉（同一位置被两条或更多射线覆盖），该像素变为 green。
  - 种子像素本身保持 blue。边框保持不变。
- `Key insight`：解题者需要先发现边框上的 red 标记与内部种子的行列对应关系决定了射线方向（而非长度），然后发现射线交叉点变色为 green——"边框标记→方向编码→射线→交叉变色"构成多层推理链条。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
