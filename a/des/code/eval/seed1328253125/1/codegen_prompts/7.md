网格中散布若干形状，通过忽略缩放比例的几何匹配将形状两两配对，然后在混色图例中查找配对双方颜色的混合结果，用混合色重绘较大形状并移除较小形状。

Input structure:
- Azure 背景。网格中有若干个彩色连通形状，每个形状由单一非背景色绘制。
- 这些形状可以两两配对：配对依据是两个形状在忽略缩放后具有完全相同的像素图案（即一个是另一个的 2 倍或 3 倍整数放大版本——放大是指每个像素变为 2x2 或 3x3 的方块）。
- 每对中两个形状颜色不同。不参与配对的形状不存在。
- 网格底部有一行"混色图例"：若干个 1x3 的小条，每个小条由三个像素组成——左像素颜色 A、右像素颜色 B、中间像素颜色 C，表示 A 和 B 混合后得到 C。图例覆盖了所有需要的颜色组合。

Rule:
- 第一步：通过形状匹配找到配对。将较大形状按其放大倍数缩小后与较小形状逐像素比较图案，图案一致则配对成功。
- 第二步：在混色图例中查找每对形状的两种颜色对应的混合色（图例中 A-B 和 B-A 视为相同组合，混合色唯一）。
- 第三步：移除每对中较小的那个形状（其位置变为 azure 背景）。
- 第四步：将较大形状的所有像素重新着色为查到的混合色。
- 混色图例行保持不变。

Key insight: 解题者面临双重挑战——首先必须发现形状配对不是基于颜色或位置邻近性，而是基于缩放后的几何形状一致性（需要心理旋转和缩放来比对）；然后需要理解混色图例的三像素编码方式来确定最终输出颜色。两层推理机制截然不同，一层是空间几何匹配，一层是符号化颜色查表。

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
