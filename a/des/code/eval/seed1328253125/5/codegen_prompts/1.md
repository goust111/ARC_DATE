- `description`：根据边框缺口方向确定内部图案的投影轴，再依据投影轴上各行/列的非背景像素数量，将对应行/列用图例区的颜色替换。
- `Input structure`：
  - 背景色（bg）为最常见颜色。
  - 网格中有若干大小相同的矩形边框（由同一种颜色绘制，如 Blue），每个边框的某一条边上有一个单格宽的缺口（缺口位置为背景色）。
  - 每个边框内部有一个由另一种颜色（如 Green）绘制的小型图案（形状各异，由若干非背景像素组成）。
  - 网格的一角有一个图例区：图例区由若干行组成，每行左侧是一个用 Maroon 绘制的 1 到 5 格宽的水平条（长度各不相同），右侧紧邻一个单格的颜色标记（如 Red、Yellow、Orange 等，各行颜色不同）。图例区的含义是：水平条的长度 N 对应右侧的颜色。
- `Rule`：
  - 对每个矩形边框，找到缺口所在的边。缺口决定投影轴方向：缺口在上边或下边 → 投影轴为垂直方向（按列统计）；缺口在左边或右边 → 投影轴为水平方向（按行统计）。
  - 沿投影轴方向，对边框内部图案的每一行（或每一列）统计非背景像素的数量 N。
  - 在图例区中查找长度为 N 的水平条，获取其对应的颜色 C。
  - 将该行（或该列）的所有非背景像素替换为颜色 C。
  - 边框本身和图例区保持不变。
- `Key insight`：缺口方向决定了统计维度（行 vs 列），像素计数通过图例映射为颜色——解题者必须先发现缺口与投影轴的对应关系，再发现计数-颜色映射表，两步推理缺一不可。
</new_puzzle>

## 实现要求

1. `main(grid)` 必须实现新题描述中的确定性转换规则，不能只识别 `generate_input()` 的固定模板。
2. `generate_input()` 必须随机生成多样样例，不能固定死。随机维度应覆盖：网格大小、对象数量、位置、颜色、方向、形状参数或关键分支。
3. 生成器必须保证输入满足 `main()` 的隐式假设：对象不重叠、不越界、特殊标记唯一或可区分、匹配关系无歧义、关键分支出现概率相同。
4. 禁止把 ARC 颜色 id 、亮度、拼写等当作人类不可见的数值语义参与排序、大小比较或隐藏映射。颜色变化必须有可见结构线索。注意颜色亮度、拼写等也是不可见信息，若描述中出现违规的颜色id或者亮度，可自行使用少量的固定颜色替代，但注意生成时要在三个以内输入输出网格中对所有变换100%覆盖度。
5. 输出样例要视觉清晰：避免对象粘连、覆盖关系混乱、同一像素多重语义、过密导致规则不可读。
6. 若规则有多个分支，生成器不能长期固定成一个分支；应让分支在随机样例中合理出现，即每个分支出现的概率平均，所谓的分支是在描述中提到的分支，即规则语义中的不同情况。
7. 代码风格参考 `ARC_code`：使用 `numpy`，必要时使用本地 helper，但目标文件应能被 `SourceFileLoader` 直接加载。
8. 可以在目标目录放公共 helper 文件，但若只实现一道题，优先保持目标文件自包含，减少额外依赖。
