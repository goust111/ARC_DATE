<description>
利用散落色块的形状作为"钥匙"解锁对应锁孔区域，并用钥匙内部的花纹填充锁孔所围成的封闭腔室。

Input structure:
- 背景为黑色。网格中有若干由灰色像素围成的封闭"锁体"区域，每个锁体的边界上恰好有一个缺口（"锁孔"），缺口形状为不规则的小凹槽（2-4像素宽）。
- 网格中散布着若干彩色小对象（"钥匙"），每把钥匙由两部分组成：外轮廓部分的形状恰好与某个锁孔的缺口形状互补（能精确嵌入），内部填有一种与外轮廓不同的纯色。
- 每个锁体内部（被灰色边界围住的区域）初始为背景色。

Rule:
- 对每把钥匙，找到其外轮廓形状与之互补匹配的唯一锁孔。
- 将钥匙嵌入锁孔位置，使灰色边界的缺口被补全（钥匙外轮廓变为灰色，与边界融为一体）。
- 用该钥匙内部的纯色填充整个锁体内腔（即灰色边界围成的全部背景像素都变为该颜色）。
- 钥匙原来所在的位置清除为背景色。

Key insight:
钥匙的外形不是装饰——它编码了目标锁孔的身份；而钥匙的内部颜色才是最终要施加到锁体腔室的填充色。解题者需要同时完成形状匹配（找到对应锁孔）和颜色传递（用内部色填充腔室）两层推理。
</description>

<description>
根据边框上的色带序列，将网格内部的散落碎片按颜色排入正确的行或列通道，碎片在通道内按面积从小到大堆叠排列。

Input structure:
- 背景为黑色。网格最外圈一行/一列构成边框，边框的每个像素被染成若干种颜色，形成连续色带段（例如左边框从上到下依次有红段、蓝段、绿段）。
- 网格内部散布着多个单色连通对象（碎片），每个碎片的颜色与边框上某段色带的颜色相同。
- 边框色带出现在左侧边框或上侧边框（每道题固定一侧），色带段的位置和长度定义了对应的行通道或列通道。

Rule:
- 根据边框色带确定每种颜色对应的通道：若色带在左边框，则该色带覆盖的那些行构成该颜色的水平通道；若色带在上边框，则覆盖的那些列构成垂直通道。
- 将所有同色碎片收集起来，按像素面积从小到大排序。
- 在对应通道内，从靠近边框的一端开始，依次紧密放置每个碎片（保持碎片原始形状不变，仅做平移），碎片之间留一列/一行的背景间隔。
- 碎片在通道的垂直/水平方向上居中放置（若通道宽度大于碎片宽度）。
- 原始碎片位置清除为背景色。

Key insight:
边框色带不仅指定颜色归属，还通过其位置和跨度隐式定义了每种颜色的空间通道范围；碎片的排列顺序则需要解题者比较面积来确定，形成"通道分配 + 面积排序"的双层推理结构。
</description>

<description>
将网格中每个彩色区域视为一面"旗帜"，根据旗帜内部被分割线划分出的子区域数量，从预置的颜色图例中查找对应颜色，用该颜色重新填充整面旗帜。

Input structure:
- 背景为黑色。网格中有若干矩形彩色区域（"旗帜"），每面旗帜内部用白色线条分割成若干个子区域（子区域数量从1到5不等）。
- 网格的某个角落（如左上角）有一个小型颜色图例区域，图例由灰色边框围成。图例内部从上到下排列着1到5个小方块行，每行的方块数量递增（第一行1个方块、第二行2个方块……），每行方块旁标注一个纯色像素作为颜色标签。

Rule:
- 对每面旗帜，数出其内部被白色分割线划分出的子区域数量 N。
- 在图例中找到方块数量为 N 的那一行，读取该行对应的颜色标签。
- 将整面旗帜（包括原来的白色分割线）全部重新填充为该颜色标签所指示的颜色。
- 图例区域本身保持不变。

Key insight:
白色分割线不是装饰而是计数线索——它们把旗帜切分为若干子区域，子区域的数量是查找图例的索引键。解题者需要先完成"分割计数"，再完成"图例查表"，两步推理缺一不可。
</description>

<description>
每个彩色对象沿其"尾巴"所指方向的反方向滑动，在路径上留下灰色拖尾痕迹，碰到其他对象时触发链式传递运动。

Input structure:
- 背景为黑色。网格中有若干单色连通对象，每个对象的主体是一个紧凑的小块（2x2 或 3x3），主体的某一侧延伸出一条单像素宽、长度为1-3像素的"尾巴"，尾巴与主体同色。
- 尾巴的方向指示运动的反方向（即对象将朝远离尾巴的方向滑动）。
- 对象之间初始不接触，且每个对象的滑动路径上最多遇到一个其他对象。

Rule:
- 确定每个对象的运动方向：从尾巴指向主体的方向即为运动方向。
- 对象沿运动方向滑动，直到主体的前缘接触另一个对象或到达网格边界。
- 对象停在最终位置，其原始位置到最终位置之间的路径上，用灰色填充单像素宽的拖尾轨迹。
- 若对象撞上另一个静止对象，被撞对象接收运动并沿相同方向开始滑动（链式传递），同样留下灰色拖尾。
- 尾巴在运动后消失（被背景色覆盖）。

Key insight:
尾巴是方向编码器而非运动轨迹——它的朝向与运动方向相反；碰撞产生的链式传递要求解题者追踪多个对象的连锁运动序列，形成"方向解码 + 碰撞传递链"的双层推理。
</description>

<description>
将散落的彩色碎片拼入中央模板的对应子区域中，当两个碎片竞争同一子区域时，根据它们在网格中的空间邻接关系决定最终填充色。

Input structure:
- 背景为黑色。网格中央有一个由灰色单像素线条勾勒出的矩形"模板区域"，模板内部被灰色线条划分为若干不规则子区域（类似拼图轮廓），每个子区域初始为背景色。
- 模板外部散布着若干彩色连通对象（碎片），每个碎片的形状恰好与模板内某个子区域的形状完全一致（允许平移匹配，不需旋转或翻转）。
- 某些子区域对应两个不同颜色的碎片（即有两块形状相同但颜色不同的碎片与同一个子区域匹配）。

Rule:
- 对每个碎片，通过形状匹配找到模板中与之形状完全一致的唯一子区域。
- 若某子区域只有一个碎片与之匹配，则用该碎片的颜色填充该子区域。
- 若某子区域有两个碎片与之匹配（两碎片颜色不同），则观察这两种颜色在网格其他位置是否有相邻接触：若在模板外某处这两种颜色的像素存在4-连通相邻，则该子区域填充为这两种颜色中在网格中像素数更少的那种颜色；若不相邻，则填充像素数更多的那种颜色。
- 碎片原始位置清除为背景色，灰色模板轮廓保持不变。

Key insight:
形状匹配只是第一层——它确定碎片归属；当两个碎片竞争同一子区域时，解题者需要观察这两种颜色在网格中的空间关系（是否4-连通相邻）来决定填充规则，这构成了第二层非显然的推理。
</description>

<description>
网格中的每个封闭房间根据其墙壁上"窗户"像素的朝向，从窗户向房间内部投射同色光线填充区域，内墙柱阻挡光线扩散。

Input structure:
- 背景为黑色。网格中有一个由蓝色像素构成的连通墙体结构，墙体将网格内部分割成若干封闭的矩形房间。
- 每个房间的墙壁上有1-2个"窗户"——即墙壁上被替换为其他颜色（红、绿、黄等）的单像素点。
- 每个窗户像素恰好位于房间边界的某一侧（上、下、左、右墙壁上），其位置指示光线进入方向。
- 部分房间内部有额外的蓝色单像素"内墙柱"。

Rule:
- 对每个房间的每个窗户，确定窗户所在的墙壁方位（上墙壁、下墙壁、左墙壁或右墙壁）。
- 从窗户位置向房间内部发射"光线"（即朝远离该墙壁的方向扩散）：光线以窗户所在行或列为起点，沿垂直于该墙壁的方向逐行/列向内推进，每行/列填满房间的整个宽度/高度，直到遇到内墙柱或对面墙壁为止。
- 光线填充的颜色与窗户像素的颜色相同。
- 若一个房间有两个窗户且光线覆盖区域重叠，重叠区域保留距离自身窗户更近的那束光线的颜色。
- 墙体和窗户像素本身保持不变。

Key insight:
窗户的位置编码了两层信息：它在哪面墙上决定了光线的传播方向，它的颜色决定了填充色。内墙柱作为光线阻挡器使每个房间的填充图案各不相同，解题者需要逐房间推演光线的实际覆盖范围。
</description>

<new_puzzle>
<description>
网格中散布的"种子"像素沿背景对角条纹所暗示的方向生长为藤蔓线段，生长长度由种子局部邻域中其他种子的数量决定。

Input structure:
- 网格的背景不是纯色，而是由两种深色（如 maroon 和 blue）交替形成的对角条纹纹理（条纹方向为左上到右下或右上到左下，每条纹宽1像素）。
- 背景条纹的走向在整个网格中一致，暗示一个全局的对角方向。
- 网格中散布若干亮色的单像素"种子"（如红、绿、黄、橙等），各种子之间互不相邻。

Rule:
- 读取背景对角条纹的走向，确定全局流场方向（左上→右下 或 右上→左下）。
- 每颗种子沿流场方向生长为一条同色的对角线段（"藤蔓"）。
- 藤蔓的生长长度（不含种子本身的额外像素数）等于该种子5x5邻域内其他种子像素的数量。若邻域内无其他种子像素，藤蔓长度为0（即只保留种子本身，不生长）。
- 藤蔓从种子出发沿流场方向逐像素延伸，覆盖背景纹理像素。若藤蔓遇到网格边界则提前停止。
- 种子本身保留在原位作为藤蔓起点。

Key insight:
背景纹理不是噪声而是方向编码——对角条纹的走向就是藤蔓生长的方向；而生长长度的线索藏在每颗种子的局部邻域中，解题者需要先从背景解读方向，再从邻域计数确定长度，构成"方向解码 + 邻域计数"的双层机制。
</description>
</new_puzzle>
