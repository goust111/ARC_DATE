- `Key insight`：解题者需要先理解底部图例编码了"颜色归属关系"（哪些颜色属于同一族谱），然后反向利用区域内散落的颜色碎片来查表匹配族谱，最终用族谱的祖先色来决定边框颜色。这需要两层推理：一是理解图例的编码含义，二是通过集合包含关系完成匹配。

- `description`：将网格中的彩色"种子"像素沿其所在通道生长为线段，生长方向由种子与通道壁的相对位置决定，生长长度由同通道内的其他种子数量决定。

- `Input structure`：背景为 Black。网格中有若干条由 Grey 像素构成的水平或垂直"通道"（宽度为3像素、长度不等的矩形条带）。每条通道内部散布着若干单像素的彩色"种子"（Red、Blue、Green、Yellow 等），种子总是位于通道的中轴线上。通道之间互不连通，且不与网格边缘相接。

- `Rule`：
  1. 对每条通道，数出其内部种子的总数 N。
  2. 对每个种子，判断它离通道的哪一端更近（对于水平通道是左端或右端，对于垂直通道是上端或下端）。种子沿远离较近端的方向生长（即朝向较远端的方向）。若种子恰好位于通道正中央，则朝通道延伸方向的正方向（水平通道向右，垂直通道向下）生长。
  3. 种子从自身位置开始，沿确定的方向在中轴线上生长 N 个像素（不含种子自身），使用种子自身的颜色。若生长遇到通道尽头则在尽头停止。
  4. 通道的 Grey 壁、背景、以及种子原始像素均保持不变。

- `Key insight`：生长方向需要通过种子在通道中的偏心位置来推断（靠近哪端就背离哪端生长），而生长长度则编码在同一通道内种子的总数中——这两条规则分别需要独立归纳，且"数量决定长度"这一关联并不显然。
</new_puzzle>

- `Input structure`：背景为 Azure。网格中散布着偶数个（通常为4或6个）大小相近的单色形状，每个形状使用不同的前景色（如 Red、Blue、Green、Yellow、Magenta、Orange）。每个形状的边缘带有明显的凹凸锯齿特征——某些边上有1像素的凸起（突出部分），某些边上有1像素的凹陷（缺口部分）。每个形状内部恰好有一个由背景色构成的矩形空洞（大小为1x1到2x2不等）。形状之间在网格上互不接触。

- `Rule`：
  1. 提取每个形状的边缘轮廓，记录其凹凸锯齿的序列模式（沿顺时针方向，凸起记为"凸"，凹陷记为"凹"，平直记为"平"）。
  2. 两个形状互为配对，当且仅当将其中一个形状旋转180度后，其锯齿序列与另一个形状的锯齿序列完全互补（即一个的凸对应另一个的凹，反之亦然）。

  4. 形状本身的颜色和位置不变，背景不变。

- `Key insight`：解题者首先需要发现形状边缘的凹凸锯齿构成了一种"钥匙-锁孔"配对机制（需要考虑180度旋转后的互补），然后理解空洞的填充色来自配对伙伴而非自身。第一层推理是发现配对规则，第二层是理解颜色传递方向。
</new_puzzle>

- `description`：根据网格中"信号塔"发射的彩色射线的交叉覆盖模式，推断每个空白区域应显示的混合色。

- `Input structure`：背景为 Black。网格的四条边缘上分布着若干单像素的彩色"信号塔"（颜色为 Red、Blue、Yellow 三种之一）。网格内部有若干由 Grey 像素构成的单像素宽矩形"墙壁"，墙壁将内部空间分割为若干矩形房间。每个房间内部全为背景色。信号塔只出现在网格的最外圈边缘行/列上。

- `Rule`：
  1. 每个信号塔沿其所在边缘的法线方向（边缘上的塔向内发射）发射一条射线。射线会被 Grey 墙壁阻挡——射线从信号塔出发，遇到第一面墙壁时停止。
  2. 对网格内每个背景色像素，收集所有能照射到该像素的信号塔颜色集合。
  3. 颜色混合规则：若只被一种颜色的射线覆盖，则该像素变为该颜色。若同时被 Red 和 Blue 覆盖，变为 Magenta。若同时被 Red 和 Yellow 覆盖，变为 Orange。若同时被 Blue 和 Yellow 覆盖，变为 Green。若同时被三种颜色覆盖，变为 Maroon。若未被任何射线覆盖，保持 Black。
  4. 信号塔像素、Grey 墙壁像素均保持不变。

- `Key insight`：解题者需要完成三层推理：第一层是理解信号塔从边缘向内发射射线且被墙壁阻挡的传播机制；第二层是理解每个像素可能被多条射线同时覆盖；第三层是发现颜色混合遵循类似"光的三原色"的固定映射表。墙壁的存在使得相邻房间可能呈现完全不同的混合色，增加了视觉上的迷惑性。
</new_puzzle>

- `description`：将散落的形状碎片按照"组装图纸"上标注的旋转角度旋转后，嵌入图纸中对应的空槽位。

- `Input structure`：背景为 Azure。网格左半部分是一个由 Grey 边框围成的大矩形"组装图纸"，图纸内部背景为 Azure，其中有若干个矩形空槽（由 Azure 背景构成）。每个空槽的某一个角上有一个单像素标记，标记颜色为 Red、Green、Yellow、Magenta 四种之一，分别代表 0度、90度顺时针、180度、270度顺时针旋转。网格右半部分散布着若干个彩色形状碎片（每个碎片使用独特的非标记色前景色，如 Blue、Orange、Maroon 等），碎片大小各异。

- `Rule`：
  1. 对每个组装图纸中的空槽，测量其矩形尺寸（宽 x 高）。
  2. 读取该空槽角上的颜色标记，确定旋转角度（Red=0度，Green=90度顺时针，Yellow=180度，Magenta=270度顺时针）。
  3. 在右侧碎片中，找到唯一一个碎片，使得将其按标记指定的角度旋转后，其边界框尺寸恰好等于空槽尺寸。
  4. 将该碎片旋转后放入空槽中，碎片颜色保持不变。标记像素被碎片覆盖（若碎片该角位置有像素）或保持标记色（若碎片该角位置为空）。
  5. 输出仅包含组装图纸区域（含 Grey 边框），右侧碎片区域被裁剪掉。

- `Key insight`：解题者需要先发现空槽角落的彩色标记不是装饰而是旋转指令的编码，然后理解匹配碎片时必须先将碎片旋转后再比较尺寸——这意味着一个看起来是"宽>高"的碎片可能对应一个"高>宽"的空槽（经90度旋转后匹配）。旋转编码的发现和旋转后匹配这两步推理缺一不可。
</new_puzzle>

- `description`：网格中的每条彩色路径记录了一个对象的运动轨迹，需要根据路径的转弯模式判断对象的"类型"，再用类型对应的颜色重绘路径的终点区域。

- `Input structure`：背景为 Black。网格中有若干条由不同颜色构成的单像素宽路径（如 Red、Blue、Green、Orange 路径），每条路径由连续的像素组成，从起点到终点依次相连（8-连通）。每条路径的起点都位于网格的最外圈边缘，终点位于网格内部。路径仅包含水平、垂直和精确45度对角线段，段与段之间形成明显的转弯。网格的一个角落有一个小型"类型图例"区域，由 Grey 边框围成，内部展示若干行，每行包含：一个转弯模式示意（用 Maroon 像素画出的2-3段折线，展示一种特定的转弯序列，如"左转-右转"或"右转-右转"），旁边紧跟一个 2x2 的颜色方块表示该类型对应的输出色。

- `Rule`：
  1. 对每条彩色路径，沿路径从起点到终点，记录每次转弯的方向（相对于当前前进方向的左转或右转）。
  2. 提取路径的前两次转弯组成的模式（如"左-右"、"右-右"、"左-左"等）。
  3. 在类型图例中匹配该转弯模式，找到对应的输出颜色。
  4. 将路径终点处的像素及其四方向相邻的背景像素（形成一个十字形，共5个像素）重绘为图例指定的输出颜色。
  5. 路径上除终点十字区域外的所有像素保持原色不变。图例区域保持不变。

- `Key insight`：解题者首先需要发现路径的颜色本身是干扰项，真正决定输出色的是路径的几何转弯模式；其次需要理解图例中 Maroon 折线编码的是转弯的相对方向（左转/右转）而非绝对方向；最后需要将这个匹配结果应用到终点的十字区域。路径颜色的多样性会误导解题者试图建立"输入色到输出色"的直接映射。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布的彩色像素对是"磁极"，同色磁极之间的连线穿过的所有Grey围栏需要被打开（擦除），而不同色磁极之间的连线穿过的围栏则需要加固（加粗）。

- `Input structure`：背景为 Azure。网格中有若干条由 Grey 像素构成的单像素宽水平或垂直线段，称为"围栏"，将网格分割为若干矩形区域。在这些矩形区域内部，散布着成对出现的彩色单像素点（如两个 Red 像素、两个 Blue 像素、两个 Green 像素等），每种颜色恰好出现两个像素。这些彩色像素点分布在不同的矩形区域中，即同色的两个像素之间至少隔着一条围栏。

- `Rule`：
  1. 对每对同色像素，画出连接两者中心的假想直线（水平或垂直，保证每对同色像素要么同行要么同列）。
  2. 该假想直线穿过的所有 Grey 围栏像素被擦除（变为背景色 Azure），即"打开"这些围栏。
  3. 对每对不同色但同行或同列的像素对，画出连接两者的假想直线。该直线穿过的所有 Grey 围栏像素被加固——将该围栏像素在垂直于围栏方向上两侧各扩展1像素（即单像素宽的围栏变为3像素宽），扩展部分也为 Grey。
  4. 若一段围栏同时被某对要求打开又被另一对要求加固，则加固优先（围栏保留并加粗）。
  5. 所有彩色像素点在输出中被移除（变为背景色）。

- `Key insight`：解题者需要发现两层规则：第一层是理解同色配对与异色配对分别触发相反的操作（擦除 vs 加固）；第二层是发现冲突时的优先级规则（加固覆盖擦除）。彩色像素的最终消失也是一个需要从样例中归纳的非显然细节。
</new_puzzle>
