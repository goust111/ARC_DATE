Thicken the sparse frame and stamp the external sparse sprites into it in positional order.

Input structure
The grid has a dominant background color, a regular lattice color, one large
sparse rectangular frame, and one or more external monochrome sprites whose
pixels also sit on a two-step lattice.

Rule
Use the largest sparse rectangular perimeter as the frame. Clear that frame
region and the external sprite pixels to background, draw a solid one-pixel
border in the frame color, solidify each sparse sprite into its contiguous
two-step mask, and place the sprites inside the frame with equal gaps.
Wide frames receive sprites left-to-right by source position; tall frames
receive them top-to-bottom by source position.

Key insight
The frame supplies ordered slots: the sprite-to-slot assignment is by visible
source order, not by numeric color or by matching individual cells.

<description>
Decode a stamp map: read templates, markers, and palette from a tiled grid, then render stamps.

Input structure:
- Grid divided into K tile columns (each N wide) separated by 1-col dashed separators.
- Top band (rows 0..N-1): K template masks, one per tile column.
- Middle band (rows N+1..2N): marker pixels whose color picks a template.
- Bottom band (rows 2N+2..): K palette swatches giving the output color per template.
- Separator rows at rows N and 2N+1 (dashed pattern of sep color).

Rule:
- Each marker's local position (lr, lc) within its tile column determines which N×N output block to stamp.
- The marker's color identifies which template to use; the palette recolors the template.

Key insight: Marker color encodes template index; local position within tile column encodes stamp block.
</description>

<reference_puzzle index="3" source="train" puzzle_id="e39e9282" lines="73-81">
<description>
Project maroon markers into adjacent grey or pink 3x3 squares, erasing grey squares afterward.

Input structure
The grid has a dominant background, solid 3x3 grey and/or pink squares, and maroon marker pixels or segments directly touching one side of exactly one square.
Rule
Grey squares are erased; their adjacent maroon markers stay in place and stamp the nearest edge cell inside the grey square. Pink squares stay pink; their adjacent maroon markers disappear and stamp the corresponding cell on the square's middle row or middle column.
Key insight
The side touched by a marker determines the projection: grey uses the near edge, while pink uses the centerline, preserving the marker's coordinate along that side.
</description>
</reference_puzzle>

<description>
Recolor the large mask crop column-by-column using the separate three-row palette strip.

Input structure:
- The background is the most common color.
- One large monochrome foreground object is the mask; its bbox is the output region and may contain background holes.

Rule:
- Crop to the mask object's bbox.
- For each output column, color mask pixels with the corresponding color from the repeated palette rows.
- Replace background holes inside the crop with the palette's uniform third-row color.

Key insight:
The grey object is only a stencil; its columns select colors from the legend, while its holes expose the legend's fill color.

<description>
Summarize the foreground line objects as ordered horizontal color stripes.

Input structure:
- A dominant background fills a rectangular grid.
- Each non-background color forms one contiguous one-cell-thick line segment.
- The line segments have distinct topmost rows, and there are at most five of
  them.

Rule:
- Sort the foreground colors by the topmost row occupied by their line
  segment.
- Create a 5x3 output filled with the background color.
- Place one solid 1x3 row for each foreground color, preserving that
  top-to-bottom order and padding any unused rows above with background.

Key insight: The exact line length and slope do not matter; only the
vertical order of the colored line segments is encoded in the output stack.

<description>
Drop the moving-color objects downward until they rest above a one-row cushion before the obstacle or bottom edge.

Input structure:
- The grid has exactly three colors: empty background, a stationary obstacle/floor color, and a moving object color.
- The obstacle color is the unique non-background role that touches the bottom edge.
- Moving pixels start outside the obstacle cells, outside the row directly above each obstacle pixel, and outside the bottom row.

Rule:
- Keep the background and obstacle pixels fixed.
- Treat obstacle pixels, cells directly above obstacle pixels, and the bottom row as blocked.
- Repeatedly move every 4-connected moving-color object one row down when its translated shape does not hit blocked cells or another moving object.

Key insight: The visible floor has an invisible one-row cushion above it, so the objects fall under gravity but stop with one empty row before the floor or the grid bottom.
</description>

<description>
Keep only the center color and redraw it as a diagonal ray to its indicated corner.

Rule:
- Fill the whole output with the background color.

<reference_puzzle index="12" source="train" puzzle_id="a1aa0c1e" lines="74-97">
<description>
Compress the stacked colored bars into a compact ordered table with the control pixel on the selected row.

Input structure
- A background grid contains several full-width colored bars from top to
  bottom; the last bar is the base/separator color.
- Each non-base bar may have an aligned three-column comb motif below it,
  alternating side-pair rows with solid rows.
- A singleton control pixel sits away from the colored motifs.

Rule
- Make one output row per non-base bar, preserving top-to-bottom order.
- In that row, paint the bar color once for each solid three-pixel row in
  its motif, then paint the base-bar color in the separator column.
- The singleton control pixel sits immediately above the base bar. Among
  motifs whose open side-pair parity is compatible with that bottom row,
  put the control pixel in the output row with the fewest solid rows; use
  horizontal distance to the motif center only to break count ties.

Key insight
- The vertical comb height is a count, while the control pixel is read by
  projecting it onto the center gap of compatible comb rows rather than by
  its vertical band alone.
</description>
</reference_puzzle>
