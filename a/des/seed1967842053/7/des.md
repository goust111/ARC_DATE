<new_puzzle>
根据框架内部色块的堆叠顺序，将散落的拼图碎片按遮挡层级重新组装进框架。

Input structure
- 背景色为主色。网格中有一个由单色边框围成的矩形框架，框架内部全部填充背景色。
- 框架外散落着若干大小不一的矩形色块（每个色块为单一颜色，且颜色各不相同）。
- 框架的一条边（上、下、左或右）上嵌有若干小的单像素标记点，每个标记点的颜色与某个散落色块的颜色一致，标记点沿该边从外到内（即从边框向框架中心方向）排列。

Rule
- 标记点在框架边上的排列顺序定义了色块的堆叠层级：最靠近边框外侧的标记点对应最底层色块，最靠近框架中心的标记点对应最顶层色块。
- 将每个散落色块平移到框架内部，使其中心与框架内部的中心对齐。
- 按照标记点定义的堆叠顺序从底到顶依次绘制色块：后绘制的色块覆盖先绘制的色块。
- 框架外的原始散落色块和标记点被擦除（变为背景色），框架边框保持不变。

Key insight
标记点不是位置提示而是深度提示：它们沿框架边的内外排列顺序编码了遮挡层级，解题者需要识别出这条从外到内的排序即为从底到顶的渲染顺序。
</new_puzzle>

<new_puzzle>
根据种子图案的对称性缺陷方向，选择性地将镜像副本拼接到缺陷侧。

Input structure
- 背景色网格上散布着若干小型多色图案（种子），每个种子占据不超过 5x5 的区域。
- 每个种子"几乎"具有某种对称性（水平镜像、垂直镜像或四折旋转），但恰好在一侧缺少 1-2 个像素，导致对称性不完整。
- 网格角落有一个 1x1 的颜色指示格，其颜色为 red、green 或 blue 之一，分别对应水平镜像、垂直镜像和旋转对称三种目标对称类型。

Rule
- 首先读取角落指示格的颜色，确定本题要求检查的对称类型。
- 对每个种子图案，检测其在目标对称类型下的缺陷方向（即对称翻转后，哪一侧有像素缺失）。
- 将种子图案沿缺陷方向的反方向做目标对称变换后，紧贴种子的缺陷侧拼接一份镜像/旋转副本。拼接后种子与副本共享接缝列/行。
- 若某个种子在目标对称类型下已经完美对称，则保持不变不做拼接。

Key insight
解题需要两层归纳：第一层是从角落指示格和样例的对比中推断颜色与对称类型的映射关系；第二层是对每个图案独立判断其对称缺陷方向，进而决定拼接朝向。单纯识别"不对称"不够——必须定位缺陷侧才能确定输出。
</new_puzzle>

<new_puzzle>
用连通管道网络中的阀门颜色对管道分段染色，阀门自身变为背景色。

Input structure
- 背景色网格上有一个由 grey 像素构成的单像素宽正交管道网络（类似迷宫走廊），管道上有若干 T 形或十字形交叉节点。
- 管道上散布着若干"阀门"：每个阀门是一个跨越管道的 1x1 彩色像素（非 grey、非背景色），将管道在该处切断为两段。阀门的颜色各不相同。
- 管道网络的某些末端（死胡同）带有一个与某阀门同色的 1x1 标记像素，位于管道末端外侧紧邻的背景格上。

Rule
- 每个阀门将管道局部切成两半；对于每个阀门，从该阀门位置出发沿管道向两侧做洪水填充（不穿越其他阀门），得到阀门两侧各自的管道连通段。
- 检查每段管道的所有死胡同末端：如果某段管道的某个末端外侧带有与该阀门同色的标记像素，则该段管道被染成该阀门的颜色。
- 阀门像素本身变为背景色（阀门被"打开"消失）。
- 末端标记像素保持不变。
- 如果某段管道不属于任何阀门的标记段，则保持 grey 不变。

Key insight
阀门同时承担两个角色——切割管道的分界点和染色的候选色源——但染色方向由末端标记决定，而非简单地"两侧都染"。解题者需要先理解阀门的切割功能，再通过末端标记匹配判断每段管道应该继承哪个阀门的颜色。
</new_puzzle>

<new_puzzle>
将网格中散落的箭头图案作为指令，按箭头距离目标的远近依次推动同色色块，色块滑动到碰撞为止。

Input structure
- 背景色网格上有若干单色填充的小矩形色块（每个色块为 2x2 或 3x3 的纯色方块）。
- 网格上还散布着若干"箭头"图案，每个箭头由 5 个同色像素构成：一个 3 像素的直线段作为箭杆，加上箭头尖端的两个斜向像素形成 V 形箭尖。例如，向右箭头的形状为：第 1、2、3 列各有一个中间行像素构成横向箭杆，第 3 列的上一行和下一行各有一个像素构成朝右的">"形尖端。向上、向下、向左的箭头以此类推，箭尖始终朝向移动方向。
- 每个箭头的颜色与恰好一个色块的颜色相同，表示该箭头控制该色块。

Rule
- 每个箭头指向四个基本方向之一（上、下、左、右），由箭尖的朝向决定。
- 将同色的箭头与色块配对。若同一色块有多个同色箭头，按箭头中心到色块中心的正交距离（沿箭头指向方向的行或列差值）从小到大排序依次执行。
- 执行一个箭头指令时，将对应色块沿箭头方向整体滑动，直到色块的前缘紧邻网格边界或紧邻另一个色块的边缘时停止。
- 所有箭头执行完毕后，擦除所有箭头图案（变为背景色），只留下移动后的色块。

Key insight
解题的第一层是识别箭头的绘制方式和朝向编码；第二层是发现同色多箭头时的执行顺序由距离决定——距离近的先执行会改变色块位置，从而影响后续箭头的滑动终点，顺序错误会导致完全不同的输出。
</new_puzzle>

<new_puzzle>
根据封闭区域内的"投票像素"多数色，对区域边界重新着色，然后清除区域内部所有投票像素。

Input structure
- 背景色网格上有若干由 grey 像素绘制的单像素宽封闭边框，每个边框围成一个矩形区域，各区域互不重叠也不嵌套。
- 每个矩形区域内部散布着若干彩色像素（非 grey、非背景色），这些像素称为"投票像素"，每个区域内的投票像素可能包含两种或三种不同颜色。
- 边框外的背景区域中可能散布少量干扰像素（颜色任意），这些不属于任何区域。

Rule
- 对每个 grey 边框围成的区域，统计其内部各色投票像素的数量。
- 将该区域的整个 grey 边框重新着色为投票像素中数量最多的颜色（即多数色）。若出现平局，选择在该区域内部位置最靠上（行号最小）的那种颜色；若行号也相同，选择最靠左（列号最小）的那种颜色。
- 清除该区域内部所有投票像素（变为背景色），边框外的干扰像素保持不变。

Key insight
解题者首先需要识别 grey 边框是"容器"而非固定装饰；然后发现内部散点不是要被保留的内容而是"选票"——其多数色决定了容器边框的新颜色，而选票本身在投票完成后被清除。边框外的干扰像素是用来验证解题者是否正确划定了"区域内部"范围的陷阱。
</new_puzzle>

<new_puzzle>
将钥匙形状旋转后插入同色矩形块的锁孔凹槽中，齿形与凹槽互补填充。

Input structure
- 背景色网格上有若干大型单色矩形块，每个矩形块的一条边上有一个向内凹陷的不规则凹槽（锁孔），凹槽深度为 2-3 像素，宽度为 2-4 像素，形状各异且不规则。凹槽内填充背景色。
- 网格上另有若干小型"钥匙"图案，每把钥匙由一个 1x1 或 1x2 的手柄段和一个与手柄同色的不规则齿形部分组成，手柄段与齿形部分四连通相连。钥匙的颜色与某个矩形块的颜色相同。
- 每把钥匙的齿形恰好能与其同色矩形块上的锁孔凹槽互补（即齿形填入凹槽后，凹槽被完全填满，无多余也无空缺）。但钥匙可能需要旋转 0 度、90 度、180 度或 270 度才能匹配。

Rule
- 将每把钥匙与同色矩形块配对。
- 对钥匙的齿形部分尝试四种旋转，找到能完全填充对应锁孔凹槽的唯一旋转角度。
- 将旋转后的钥匙齿形部分平移到锁孔凹槽的位置，用钥匙颜色填满凹槽（即矩形块恢复完整）。
- 钥匙的手柄段沿插入方向（从凹槽开口朝外）延伸绘制在矩形块外侧，长度保持原始手柄长度不变。
- 擦除钥匙原始位置的所有像素（变为背景色）。

Key insight
颜色匹配只完成了第一步配对；真正的推理核心是空间互补判断——需要对钥匙齿形做心理旋转后与锁孔凹槽进行形状互补匹配，这要求解题者同时处理旋转和互补填充两种空间变换。手柄段在输出中的位置和方向进一步约束了旋转的唯一解。
</new_puzzle>

<new_puzzle>
根据色带交叉点的图例信息恢复被覆盖的横色带，然后在交叉点绘制双色棋盘格。

Input structure
- 背景色网格中，某些完整的行被单一颜色填满（称为"横色带"），某些完整的列被单一颜色填满（称为"纵色带"）。横色带和纵色带的颜色各不相同。
- 横色带与纵色带在网格中产生交叉格。在输入中，交叉格显示的是纵色带的颜色（纵色带覆盖了横色带）。
- 网格最右侧有一列额外的"图例列"（宽度 1 列），图例列中每个格子的颜色标识该行是否为横色带以及其原始颜色：若该行是横色带则显示该横色带颜色，否则显示背景色。

Rule
- 利用图例列识别所有横色带及其颜色。
- 对于每个横色带与纵色带的交叉区域（交叉区域为 1x1 的单格），将该格替换为一个 2x2 的棋盘格图案：左上和右下格填横色带颜色，右上和左下格填纵色带颜色。由于交叉点本身只有 1x1，棋盘格向右下方扩展（即交叉点本身作为 2x2 的左上角），扩展部分覆盖原有内容。
- 删除图例列（输出网格宽度比输入少 1 列）。

Key insight
输入中交叉点只显示纵色带颜色是一个误导，图例列是恢复被覆盖的横色带信息的唯一途径。解题者需要先利用图例列推断隐藏的横色带，再在每个交叉点执行棋盘格混合——这两步都需要非平凡的归纳推理。
</new_puzzle>
