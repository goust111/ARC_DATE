- `description`：根据框架内部缺口的朝向选择对应边界色带，将该色带的图案铺入框架内部。

- `Input structure`：
  - 背景为 black。
  - 网格中散布若干大小不同的一像素厚空心矩形框架，每个框架用不同的颜色绘制（如 red、blue、green 等）。
  - 每个框架的四条边中恰好有一条边存在一个连续缺口（即该边上有若干连续像素被替换为 black）。
  - 在网格的四条边界（上、下、左、右）各有一条紧贴边界的彩色色带（宽度为 1 像素，长度等于网格对应维度）。每条色带由若干段不同颜色的连续像素构成，形成一个一维条纹图案。四条色带的颜色排列各不相同。

- `Rule`：
  - 对每个框架，找到其缺口所在的边（上、下、左、右）。
  - 缺口在上边 → 选择网格顶部边界色带；缺口在下边 → 选择网格底部边界色带；缺口在左边 → 选择网格左侧边界色带；缺口在右边 → 选择网格右侧边界色带。
  - 将选中的色带图案作为重复纹理铺满框架内部区域：如果色带是水平的（上/下边界），则将色带图案沿水平方向按列对齐，逐行重复填入框架内部每一行；如果色带是垂直的（左/右边界），则将色带图案沿垂直方向按行对齐，逐列重复填入框架内部每一列。色带的对齐方式为：色带的第一个像素对应框架内部区域的第一行或第一列。
  - 框架本身的边框像素保持不变，缺口处仍为 black。

- `Key insight`：
  缺口方向不是简单的"开口朝哪移动"，而是一个索引键——它从四条完全不同的边界色带中选出一条，再用该色带的颜色图案作为纹理填充框架内部。解题者需要先发现缺口方向与边界色带的对应关系，再发现内部填充是色带图案的重复平铺。
</new_puzzle>

<new_puzzle>
- `description`：将散布的彩色碎片按颜色归类到对应颜色的容器框中，碎片在容器内按面积从大到小自底部堆叠排列。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干一像素厚的空心矩形容器框，每个容器用不同颜色绘制（如 red、blue、green），容器内部初始为 black。
  - 网格中散布若干与容器颜色相同的小型 4-连通碎片（不规则形状），每个碎片是纯色的，碎片不与任何容器重叠或接触。
  - 每种容器颜色恰好对应若干个同色碎片。

- `Rule`：
  - 对每种颜色，找到该颜色的容器和所有同色碎片。
  - 将同色碎片按面积（像素数）从大到小排序。
  - 将碎片依次放入容器内部：第一个（最大的）碎片放在容器内部底部、水平居中（若无法精确居中则偏左一像素）；第二个碎片紧接着放在第一个碎片上方、同样水平居中；以此类推向上堆叠。每个碎片保持其原始形状不变，碎片之间无间隔。
  - 原来碎片所在的位置被清除为 black。
  - 容器框本身保持不变。

- `Key insight`：
  颜色同时承担两个角色——既是碎片的身份标签，也是容器的地址标签。解题者需要先识别颜色匹配关系（碎片归入同色容器），再发现容器内的堆叠规则是按面积从大到小、自底向上、水平居中排列。两层规则都需要从样例中归纳。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色区域根据其内部标记像素的颜色，执行该标记颜色所代表的特定几何变换，变换类型由网格角落的图例区编码。

- `Input structure`：
  - 背景为 grey。
  - 网格中有若干互不重叠的矩形纯色区域（矩形色块），每个区域使用不同的前景色（如 red、blue、green、orange 等）。
  - 每个矩形色块内部恰好包含一个单像素标记，标记的颜色与色块本身不同，且标记颜色只从以下三种中选取：yellow、magenta、azure。
  - 在网格的某个角落（如左上角）有一个 3 行的"图例区"，图例区包含三行，每行展示一种标记颜色及其对应的变换效果示意：
    - yellow 行：一个小矩形旁边有它的水平镜像 → 表示"水平翻转"。
    - magenta 行：一个小矩形旁边有它的顺时针 90 度旋转 → 表示"顺时针旋转 90 度"。
    - azure 行：一个小矩形旁边有它的垂直镜像 → 表示"垂直翻转"。

- `Rule`：
  - 首先读取图例区，建立标记颜色到几何变换的映射：yellow 对应水平翻转，magenta 对应顺时针旋转 90 度，azure 对应垂直翻转。
  - 对每个矩形色块，找到其内部标记像素的颜色，查找对应的变换。
  - 将该色块（包含标记像素）在其原位进行对应的几何变换。变换以色块自身的中心为锚点，变换后色块占据的区域可能改变（如旋转后宽高互换），新区域内的像素覆盖原内容。
  - 图例区在输出中被清除为 grey 背景色。
  - 标记像素在变换后保留在色块内对应的变换后位置。

- `Key insight`：
  这道题有三层推理：第一层是发现图例区编码了变换类型的映射表；第二层是识别每个色块内部标记像素的颜色是查表键；第三层是对每个色块执行对应的几何变换。图例区本身需要解题者通过观察其结构来"解码"，而不是直接给出文字说明。
</new_puzzle>

<new_puzzle>
- `description`：沿着每个箭头所指方向，将箭头尾部相连的彩色线段"推"出去，直到线段前端碰到同色锚点后停止，并在途经路径上留下间隔的灰色轨迹影子。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 maroon 像素绘制的箭头形状。每个箭头由一条 3 像素长的轴线和一个 V 形箭尖组成，箭尖朝向上、下、左、右四个方向之一。具体画法：轴线为沿箭头方向的 3 个连续像素；箭尖为轴线末端像素的两个对角邻居（形成一个指向轴线方向的 V 字）。
  - 每个箭头的尾端（轴线起始端）紧邻一条彩色线段（非 maroon、非 black），线段沿箭头方向的垂直方向延伸（即箭头朝上或朝下则线段水平，箭头朝左或朝右则线段垂直），长度为 2 到 5 像素。
  - 网格中散布若干单像素的彩色锚点，每个锚点颜色与某条线段颜色相同。每种颜色恰好有一条线段和一个锚点。锚点位于箭头轴线延长线上的某个位置。

- `Rule`：
  - 对每个箭头，确定其指向方向和尾部所连线段的颜色与形状。
  - 沿箭头指向方向，在箭头轴线的延长线上找到同色锚点。
  - 将线段整体沿箭头方向平移，直到线段的前沿（箭头方向侧）与锚点所在的行或列对齐。
  - 线段移动后，原始线段位置清除为 black，箭头本身也清除为 black。
  - 线段移动路径上（从起始位置到最终位置之间），每隔两个像素（沿移动方向）绘制一条与线段同形但颜色为 grey 的"轨迹影子"。
  - 锚点在输出中保留。

- `Key insight`：
  箭头同时编码了两个信息：移动方向和搜索锚点的轴线。解题者需要先理解箭头形状来确定方向，再沿轴线延长线找到颜色匹配的锚点确定移动距离，最后注意路径上间隔出现的灰色影子是运动轨迹的视觉记录。方向解读、颜色匹配、轨迹规律三层规则需要分别归纳。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中的"印章"模板与"画布"区域，根据画布边框上缺失色段的位置，将印章旋转到正确朝向后盖印到画布内部。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干小型矩形图案（3x3 至 5x5），每个图案由多种颜色组成且不具有四重旋转对称性——这些是"印章模板"。每个印章模板有一条边（上、下、左或右）的像素全部为 red，其余三条边的像素为其他颜色。
  - 网格中还有若干较大的一像素厚空心矩形"画布框"，每个画布框的边框颜色为 green，但恰好有一条边上存在一段连续的 red 像素（替换了部分 green 像素）。画布内部为 black。
  - 每个画布框的内部尺寸恰好等于某个印章模板的尺寸。每个印章与一个画布通过尺寸匹配配对（尺寸相同的印章和画布恰好各一个）。

- `Rule`：
  - 将每个印章模板与尺寸匹配的画布配对。
  - 观察画布框上 red 色段所在的边（上、下、左或右）。
  - 将印章模板旋转（0 度、90 度、180 度或 270 度），使得印章上全为 red 的那条边与画布上 red 色段所在的边方向一致（即都在上边、都在下边等）。
  - 将旋转后的印章图案绘制到画布内部区域，印章的 red 边像素也正常绘入。
  - 印章模板原来的位置清除为 black。
  - 画布框边框保持不变。

- `Key insight`：
  解题者需要同时发现三个非显然的规则：印章与画布通过内部尺寸匹配进行配对；印章上全 red 的边是方向标记；画布边框上的 red 段指示了印章应该旋转到的朝向。red 颜色在两个不同的对象上扮演"对齐锚"的角色，这种跨对象的语义共享是核心难点。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的管道网络按颜色分层拆解，每层管道独立"收缩"到其起点端，收缩后的残留长度由该管道穿过的交叉点数量决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条一像素宽的彩色直线段（水平或垂直），每条线段为纯色（如 red、blue、green、orange、yellow 等），线段之间会产生交叉——即不同颜色的线段在某些像素位置重叠。在交叉位置，显示的颜色为后绘制的线段颜色（即覆盖在上方的颜色）。
  - 每条线段的一端有一个 2x2 的同色方块作为"起点端"标记，另一端自然终止。
  - 不同颜色的线段数量不同（每种颜色 1 到 3 条线段）。

- `Rule`：
  - 对每条线段，从其非起点端沿线段方向向起点端扫描，统计该线段与其他颜色线段的交叉数量 K（即该线段经过的、被其他颜色线段穿越的位置数）。
  - 该线段收缩为：仅保留从起点端开始的 (K+1) 个像素长度，其余部分清除为 black。
  - 如果 K 等于 0（没有交叉），则该线段收缩为仅保留起点端的 1 个像素。
  - 2x2 起点方块始终保留。
  - 交叉点处若两条线段都保留了该位置的像素，则颜色显示规则与输入相同（后层覆盖前层）。

- `Key insight`：
  交叉点的数量是一个视觉可数的小量（通常 0 到 4 个），它决定了每条线段收缩后的残留长度。解题者需要先理解每条线段有方向性（起点端标记），再发现残留长度与交叉点数的对应关系。交叉点同时扮演"被计数的特征"和"空间重叠的视觉线索"双重角色。
</new_puzzle>

<new_puzzle>
- `description`：根据封闭区域的形状类别（矩形或 L 形）选择不同的填充策略，再依据区域内种子像素的位置决定填充图案的起始锚点。

- `Input structure`：
  - 背景为 grey。
  - 网格中有若干由 black 像素绘制的一像素厚封闭边界，这些边界围成若干互不重叠的封闭区域。每个封闭区域的形状要么是矩形，要么是 L 形（即两个矩形拼接而成的正交 L 形，拼接处无歧义）。
  - 每个封闭区域内部恰好有一个单像素"种子"，种子颜色为 red 或 blue。
  - 网格的右下角有一个小的"图案库"区域，用 black 边框隔开，内部展示两种填充图案：
    - 上方图案标注为 red 种子对应的图案：一个 2x2 的棋盘格（用 red 和 orange 交替）。
    - 下方图案标注为 blue 种子对应的图案：一个 2x2 的条纹（两列 blue、两列 azure 交替）。

- `Rule`：
  - 矩形区域：用该区域内种子颜色对应的图案（从图案库查询）平铺填充整个矩形内部。图案平铺的锚点（即图案的左上角位置）对齐到种子像素所在的位置，然后向四周重复铺开。种子像素本身被图案覆盖。
  - L 形区域：先将 L 形拆分为两个子矩形（沿 L 形的内凹角水平或垂直切割），较大的子矩形用种子颜色对应的图案填充（锚点同样对齐种子位置），较小的子矩形则用图案的颜色反转版本填充（即交换图案中的两种颜色）。若种子在较小子矩形中，则较大和较小子矩形的填充方式互换。
  - black 边界保持不变。图案库区域在输出中保持不变。

- `Key insight`：
  解题者需要分三层归纳：第一层是从图案库中解码种子颜色与填充图案的对应关系；第二层是发现形状类别（矩形与 L 形）决定了不同的填充策略；第三层是发现种子位置不仅选择图案，还决定了图案平铺的对齐锚点，以及 L 形中两个子区域的颜色反转规则。
</new_puzzle>
