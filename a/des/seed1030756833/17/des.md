- `description`：根据模板区域内已有碎片的颜色，在颜色图例中查找对应的填充图案，再将图案缩放后嵌入模板的空白腔体。

- `Input structure`：
  - 背景为 black。
  - 网格上方有一排颜色图例：每个图例由一个单色方块（2×2 或 3×3）紧邻右侧一个同尺寸的小图案组成，图案由该颜色和 black 组成的二值掩码构成。图例之间用至少一列 black 分隔。
  - 网格下方有一个较大的 grey 边框矩形（模板），模板内部被 grey 隔墙分成若干大小不等的矩形腔体。
  - 每个腔体中恰好有一个单像素的前景色标记点（非 black 非 grey），颜色与某个图例方块颜色一致。其余腔体像素为 black。

- `Rule`：
  - 对模板内的每个矩形腔体：
    1. 读取腔体中唯一标记点的颜色 C。
    2. 在上方图例中找到方块颜色为 C 的图例，提取其右侧的二值掩码图案。
    3. 将该图案按整数倍缩放（块缩放），使缩放后的图案恰好填满腔体的宽和高（腔体尺寸一定是图案尺寸的整数倍）。
    4. 将缩放后的图案绘入腔体：掩码前景像素用颜色 C 绘制，掩码背景像素保持 black。
  - 标记点本身被覆盖，不保留。模板边框和隔墙保持 grey 不变。

- `Key insight`：单像素标记点不是绘制内容——它是索引键，用于在图例中查找对应图案；腔体面积与图案面积的比值隐含了缩放倍数，解题者需同时推断"颜色→图案映射"和"腔体→缩放倍数"两层关系。
</new_puzzle>

<new_puzzle>
- `description`：将散布在网格中的彩色形状按照各自箭头指示的方向滑动，在碰到同色边框通道的死端时停止，然后用形状的轮廓颜色填充通道中被形状覆盖区域以外的剩余空间。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条单色边框通道（每条通道是由某种颜色的像素围成的长矩形管道，内部为 black，一端封闭、另一端开口）。每条通道的颜色各不相同。
  - 每条通道的开口端附近有一个小的 4-连通彩色形状（2×2 至 3×4 大小），形状颜色与某条通道颜色相同。
  - 每个形状内部恰好有一个单像素的箭头标记像素（用 red 表示），位于形状边缘的某一侧（上/下/左/右），指示滑动方向：red 像素在形状的哪一侧，形状就向该侧滑动。

- `Rule`：
  1. 识别每个彩色形状及其内部 red 标记像素的位置（形状上边缘→向上滑，形状下边缘→向下滑，形状左边缘→向左滑，形状右边缘→向右滑）。
  2. 将形状沿该方向滑动，进入与其同色的通道开口，一直滑到形状的前缘紧贴通道封闭端为止。
  3. 滑动后，形状像素（包括 red 标记）保留在新位置，颜色全部统一为通道颜色（red 标记被覆盖为通道颜色）。
  4. 通道内部除了被形状占据的像素外，其余 black 空间保持 black 不变。形状原始位置恢复为 black。

- `Key insight`：解题需要两层推理——第一层是从 red 标记在形状中的相对位置推断运动方向（而非从通道朝向推断），第二层是通过颜色匹配确定每个形状归属哪条通道。箭头标记位置编码方向的方式不直观，增加了机制的隐蔽性。
</new_puzzle>

<new_puzzle>
- `description`：在输入网格中找到被外框包围的若干独立区域，按区域内"种子行"的颜色顺序逐层向上堆叠交替色带，生成彩色条纹塔。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个不同大小的矩形 grey 边框（边框宽度为 1 像素），彼此不重叠。
  - 每个边框内部底部有 1 至 3 行连续的"种子行"，每行是一种纯色（非 black 非 grey），不同行颜色不同。种子行之上的内部空间全部为 black。
  - 边框的内部宽度均为奇数。

- `Rule`：
  1. 对每个 grey 边框区域，从底部读取种子行序列（从下到上记为颜色 C1, C2, C3…）。
  2. 从种子行顶端开始，向上交替循环绘制色带：依次用 C1, C2, C3, C1, C2, C3… 逐行填充，直到填满边框内部剩余空间。
  3. 同时，每画完一个完整循环（C1→C2→C3），色带的宽度从边框内部满宽开始，左右各缩进 1 像素（即宽度减少 2），形成阶梯状收窄的"塔"形。
  4. 当宽度缩减至 1 像素时，继续用循环颜色填充单像素列，直到触及边框顶部内壁。
  - 种子行本身保持不变。

- `Key insight`：解题者不仅要发现颜色循环的规律，还要注意到每完成一轮颜色循环后宽度递减——这个"循环周期"与"几何收窄"之间的绑定关系是核心难点。仅从单个样例可能会误以为是简单的逐行缩窄，需要多个样例（种子行数量不同）才能确认宽度缩减的触发条件是颜色循环完成而非固定行数。
</new_puzzle>

<new_puzzle>
- `description`：在棋盘状网格中，根据每个彩色碎片所在象限确定旋转角度，再根据碎片自身孔洞数量选择目标画布区域进行放置。

- `Input structure`：
  - 背景为 black。
  - 网格被一条水平 grey 线和一条垂直 grey 线分成四个象限（左上、右上、左下、右下）。
  - 每个象限中散布着 1 至 3 个小型彩色碎片（4-连通的前景对象，每个碎片为单一颜色，大小约 3×3 至 5×5）。部分碎片内部有 1 或 2 个 black 孔洞像素（被碎片完全包围的 black 像素）。
  - 网格右下角（右下象限之外、紧邻网格底部和右侧边缘）有一排小型 grey 边框方格，数量等于所有碎片总数。方格从左到右排列，每个方格内部大小足以容纳最大碎片的旋转后外接矩形。方格分成两行：上面一行放置有 0 个孔洞的碎片，下面一行放置有 1 个及以上孔洞的碎片。

- `Rule`：
  1. 象限决定旋转角度：左上象限的碎片不旋转（0°）、右上顺时针旋转 90°、右下旋转 180°、左下逆时针旋转 90°。
  2. 孔洞数量决定目标行：碎片内部 black 孔洞数为 0 的放入上行方格，孔洞数 ≥ 1 的放入下行方格。
  3. 在各行内，碎片按原始位置从左到右的顺序依次放入方格（先按象限左上→右上→左下→右下的阅读顺序，象限内再按碎片中心的列坐标从小到大排列）。
  4. 旋转后的碎片居中放入目标方格，保持原颜色。原象限中碎片的原始位置清除为 black。

- `Key insight`：解题包含三层需要独立归纳的规则——（1）象限位置编码旋转角度而非颜色或大小；（2）孔洞数量作为分类键决定目标行，而非碎片颜色；（3）放置顺序遵循阅读序。三层规则交织在同一视觉场景中，需要多个样例逐层剥离。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的单色线段碎片识别为"笔画"，按笔画方向和长度匹配到对应的彩色锚点对，然后用锚点颜色重新着色并连接锚点对。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干对彩色锚点：每对由两个相同颜色的单像素点组成（如两个 blue 点、两个 green 点等），不同颜色对之间颜色各不相同。每对锚点要么在同一行（水平对齐）、要么在同一列（垂直对齐）。
  - 网格中还散布着若干条 grey 线段碎片：每条线段是一条连续的水平或垂直的 grey 像素序列（长度 ≥ 2），各线段互不连通。
  - 每条 grey 线段的长度恰好等于某对同色锚点之间的间距（即锚点对之间空格数 + 1），且方向也相同（水平线段匹配水平锚点对，垂直线段匹配垂直锚点对）。每对锚点恰好匹配一条线段。

- `Rule`：
  1. 对每对同色锚点，计算它们之间的间距和方向（水平/垂直）。
  2. 在所有 grey 线段中找到方向相同且长度等于该间距的线段（匹配唯一）。
  3. 删除该 grey 线段的原始位置。
  4. 在两个锚点之间绘制一条连接线，颜色为锚点颜色，线段覆盖两锚点之间（含锚点本身）的所有像素。
  - 所有锚点对处理完毕后，网格中不应残留任何 grey 像素。

- `Key insight`：grey 线段本身的位置完全无关——它们只是"长度和方向"的编码载体。解题者容易被线段的空间位置误导，试图将线段平移到锚点处；实际上需要忽略线段位置，仅用其长度和方向与锚点对进行抽象匹配。这种"空间位置是噪声、几何属性才是信号"的模式是核心隐蔽点。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中嵌套方框的层级结构，根据每层方框内角落标记的颜色，对最内层的种子图案逐层施加不同的变换（翻转或旋转），从内向外展开输出。

- `Input structure`：
  - 背景为 black。
  - 网格中心有一个小的彩色种子图案（约 3×3 至 5×5，由多种颜色组成的非对称图案）。
  - 种子图案外面嵌套着 2 至 4 层同心矩形空心边框，每层边框颜色为 grey。相邻边框之间间隔至少 1 像素的 black 空间。
  - 每层边框的左上角内侧（边框内壁的左上角位置）有一个单像素彩色标记：
    - red 标记表示水平翻转。
    - blue 标记表示垂直翻转。
    - green 标记表示顺时针旋转 90°。
    - yellow 标记表示旋转 180°。

- `Rule`：
  1. 从最内层边框开始，读取其左上角标记颜色，对种子图案执行对应变换，得到第一次变换结果。
  2. 向外移动到下一层边框，读取该层标记颜色，对上一步结果再执行对应变换。
  3. 重复直到最外层边框的变换完成。
  4. 输出为最终变换后的种子图案（仅输出图案本身，裁剪到图案的紧凑边界框），不包含任何边框或标记。

- `Key insight`：解题者需要发现三件事：（1）角落标记的颜色不是装饰而是变换指令；（2）变换是从内到外逐层累积的，顺序不同结果不同（如先水平翻转再旋转 ≠ 先旋转再水平翻转）；（3）输出是纯净的变换后图案，所有框架结构都是指令编码而非输出内容。嵌套层数与变换复合的非交换性使得仅从一个样例难以区分各标记的含义。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到每个彩色区域的"影子投射方向"（由该区域附带的单像素方向标记决定），然后沿该方向在背景上绘制该区域的灰色投影，投影长度等于区域中同色连通像素的数量。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个不重叠的彩色 4-连通区域（每个区域为单一颜色，颜色互不相同，大小约 3 至 8 个像素）。
  - 每个彩色区域在其外侧恰好有一个紧邻的 maroon 单像素标记点，位于区域边界框外的上、下、左或右某一侧（maroon 点与区域有且仅有一个像素相邻）。

- `Rule`：
  1. 对每个彩色区域，找到其紧邻的 maroon 标记点。标记点相对于区域的方向即为投影方向（标记在区域上方→投影向上，标记在右方→投影向右，以此类推）。
  2. 数出该彩色区域的像素数量 N。
  3. 对区域中的每个像素，沿投影方向绘制长度为 N 的 grey 线段（不含起始像素本身，从该像素沿方向走 N 步）。
  4. 投影的 grey 像素不覆盖任何已有的彩色区域像素或 maroon 标记——若投影路径上遇到非 black 像素则该像素跳过不画（投影继续延伸，总步数仍为 N）。
  5. 原始彩色区域和 maroon 标记保持不变。

- `Key insight`：投影方向不是固定的也不是由形状朝向决定的，而是由外部 maroon 标记的相对位置编码；投影长度不是由区域的宽或高决定，而是由区域面积（像素数）决定。解题者需要分别发现方向编码机制和长度编码机制这两层独立规则。
</new_puzzle>
