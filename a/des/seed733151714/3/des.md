<description>
根据嵌套框架的层级深度，将散落的彩色碎片按深度对应的颜色重新着色，并沿框架开口方向向外逐层弹射排列。

Input structure:
- 背景为black。网格中有若干由不同颜色边框构成的嵌套矩形框架（框架之间不共享边），每个框架在某一侧有一个宽度为1格的开口（缺口）。
- 框架可嵌套多层（最多3-4层），最外层框架最大，最内层最小。
- 在最内层框架内部散落着若干小型单色碎片（连通分量，每个碎片占2-4格）。
- 网格边缘附近有一个竖直排列的颜色图例条：从上到下依次排列若干颜色方块，每个方块为1x1像素，颜色各不相同。图例条的第1个颜色对应嵌套深度1（最外层），第2个对应深度2，依此类推。

Rule:
- 首先确定每个嵌套框架组的层级结构：最外层为深度1，向内每嵌套一层深度加1。
- 将最内层框架中的每个碎片按照该碎片所在嵌套组的总深度（即层数），在颜色图例中查找对应颜色，将碎片重新着色为该颜色。
- 然后，找到每一层框架的开口方向（上/下/左/右）。从最内层开始，将碎片沿该层开口方向平移，穿过开口到达外一层框架内部；再沿外一层框架的开口方向继续平移穿出，依此逐层向外弹射。
- 碎片最终停在离最外层框架开口处向外延伸的第一个空位（紧邻已有内容或网格边界）。
- 碎片弹射时保持原始形状不变，碎片之间按原始在内层中的相对顺序（沿弹射方向的先后）依次排列，彼此紧邻不重叠。

Key insight: 颜色由嵌套总深度决定（需要逐层数框架层数后查图例），而弹射路径由每一层框架各自的开口方向逐层串联决定——两个独立的多层推理链共同作用。
</description>
</new_puzzle>

<description>
将网格中分散的彩色线段视为"编织指令"，在交叉网格上按线段颜色和朝向编织出棋盘状的交错图案。

Input structure:
- 背景为black。网格中央有一个由grey像素绘制的规则正交网格线（横线和竖线交叉形成格点），网格线宽度为1像素，间距均匀（如每隔3格一条线）。
- 在grey网格之外的区域散落着若干短线段（长度2-5像素的水平或竖直连通条），每条线段有独立颜色（如red、blue、green、orange等），且每种颜色恰好出现两条线段：一条水平、一条竖直。
- 水平线段的长度等于它将覆盖的横向网格交叉点数，竖直线段的长度等于纵向交叉点数。

Rule:
- 对每种颜色，找到其水平线段和竖直线段。水平线段的像素数 = 该颜色在网格上横向覆盖的列数 M，竖直线段的像素数 = 纵向覆盖的行数 N。
- 该颜色需要填充一个 M x N 的交叉点子区域。子区域在网格上的起始位置由该颜色水平线段左端对齐的网格列和竖直线段上端对齐的网格行决定（取最近的网格线交点）。
- 在该 M x N 子区域的每个交叉点处，按棋盘规则着色：行号+列号为偶数的交叉点涂该颜色，奇数的保持grey。
- 不同颜色的子区域可能重叠；后处理的颜色（按颜色线段离网格中心从近到远的顺序）覆盖先处理的。
- 所有颜色的原始线段在输出中被擦除（变为black）。

Key insight: 每种颜色的两条线段既编码了填充区域的尺寸（线段长度），又编码了位置（线段端点对齐网格线）——必须同时解码尺寸和位置两层信息，再叠加棋盘交错规则才能完成变换。
</description>

<description>
根据种子像素的颜色在颜色环上的相邻关系，决定区域生长方向，最终用生长区域覆盖目标形状。

Input structure:
- 背景为black。网格右下角有一个由5种颜色按固定顺序排成的环形图例：5个1x1像素排成十字形（上、右、下、左、中），中心像素的颜色为"起始色"，上/右/下/左四个像素各一种颜色，表示颜色环的方向映射（中心色的"上方向后继"是上方像素的颜色，"右方向后继"是右方像素的颜色，依此类推）。
- 网格中有若干互不接触的封闭区域（由grey边框围成的矩形，内部为black）。
- 每个封闭区域的边框某一侧外壁上贴着恰好一个1x1的彩色种子像素（颜色属于图例中的5种之一），种子像素紧邻边框外侧。

Rule:
- 对于每个封闭区域，找到其种子像素的颜色C和种子所贴的方向D（种子在区域的上/下/左/右哪一侧）。
- 在颜色环图例中，从中心色出发，查找颜色C处于环上的哪个方向位置，得到该颜色对应的"环方向"E。
- 实际生长方向 = 将种子的物理方向D旋转，使其对齐到环方向E。具体地：计算从E到D需要顺时针旋转几个90度（0/1/2/3次），然后将"向内"方向（即从种子朝向区域内部的方向）做相同次数的顺时针旋转，得到最终生长方向G。
- 从区域内部靠近种子一侧的边开始，沿方向G逐行/列地用颜色C填充区域内部像素，直到填满整个区域内部或碰到对面边框。
- 填充时每行/列的像素都着色为C。

Key insight: 种子颜色在环形图例中的位置决定了一个隐含的旋转偏移量，这个偏移量作用于种子的物理朝向才能得到真正的填充生长方向——需要先破解环形图例的方向映射，再将其与种子位置结合推理。
</description>

<description>
将网格中的彩色路径段按拓扑连接顺序拼成完整路径，再根据路径经过的门框颜色对路径分段重新着色。

Input structure:
- 背景为black。网格中散布着若干条不同颜色的短路径段（每段为宽1像素的折线或直线，长度3-8像素），路径段之间留有恰好1格的black间隙。
- 每条路径段的颜色各不相同（如red、blue、green、orange、maroon等）。
- 网格中还有若干由两个相同颜色像素构成的"门框"：两个像素分别位于某条间隙的两侧（间隙的上下或左右），形成一个宽1格的门洞。门框颜色与路径段颜色均不重复，门框使用的颜色集合独立于路径段颜色。
- 每个间隙处恰好有一个门框。
- 网格左上角有一个单独的1x1像素标记为yellow，表示路径的起始端。

Rule:
- 找到与yellow标记相邻的路径段作为起始段。沿着路径段→间隙→门框→下一段的顺序，将所有路径段串联成一条从起点到终点的完整路径。
- 串联顺序由物理邻接关系唯一确定：每条路径段的两个端点各自最多邻接一个间隙。
- 串联完成后，对路径进行重新着色：当路径穿过一个门框时，从该门框之后的路径段开始，颜色变为该门框的颜色，直到遇到下一个门框。起始段（第一个门框之前的部分）保持yellow。
- 输出时门框像素保留原色不变，间隙处填入该处新颜色（即门框后段的颜色），原始路径段的颜色全部替换为重着色后的颜色。
- yellow起始标记在输出中保留。

Key insight: 第一层推理是通过间隙和门框的物理邻接关系将碎片路径串联成唯一的线性序列；第二层推理是发现门框颜色并非装饰，而是定义了路径后续段的着色规则——两层推理缺一不可。
</description>

<description>
根据容器内部填充图案的对称性缺陷类型，从图例中选取对应的修补色，并将缺陷像素修补为该颜色。

Input structure:
- 背景为black。网格中有若干互不接触的矩形容器，每个容器由统一的grey边框包围。
- 每个容器内部填充着某种颜色（如red、blue、green等）的图案，这些图案"几乎"具有某种对称性（水平镜像、竖直镜像或180度旋转对称），但有1-3个像素位置存在缺陷——这些位置本应被填充却是black（缺失），或者本应是black却被多余填充了（多余）。
- 网格底部有一个横向排列的图例条，包含三对颜色方块（每对为上下两行、同一列）：上行是对称类型标记（用固定形状区分——单个像素代表水平镜像对称、两个水平相邻像素代表竖直镜像对称、四个像素组成2x2方块代表旋转对称），下行是对应的修补颜色。

Rule:
- 对每个容器，检测其内部图案最接近哪种对称性（水平镜像、竖直镜像、180度旋转对称）。判定方法：分别按三种对称方式检查，选择缺陷像素数最少的那种作为该容器的"目标对称性"。
- 确定目标对称性后，找出所有缺陷像素：对称位置应有填充色却为black的像素标记为"缺失"，对称位置应为black却有填充色的像素标记为"多余"。
- 在图例中查找该对称类型对应的修补颜色。
- 将所有"缺失"位置填入修补颜色（而非原始填充色）。将所有"多余"位置改为black。
- 容器边框和原始正确的填充色像素保持不变。

Key insight: 第一层推理需要识别每个容器图案"最接近"哪种对称性（需要对三种候选分别验证并比较缺陷数）；第二层推理需要理解图例中用形状编码对称类型的映射关系；第三层是将缺陷位置用修补色（而非原色）填补，这意味着修补痕迹在输出中是可见的，进一步确认了规则的正确性。
</description>

<description>
根据信号塔的高度和信号色，在地形上投射阴影状的信号覆盖区，被山体遮挡的区域不着色。

Input structure:
- 背景为azure（代表天空）。网格底部若干行由green像素构成高低起伏的"地形轮廓"：每列从底部向上连续填充green像素到不同高度，形成山丘和山谷。
- 地形顶部（green像素最顶端的那个像素之上）在某些列上竖立着"信号塔"：由某种非green、非azure颜色的像素从地形顶面向上延伸若干格（1-5格高）构成的竖直线段。每座信号塔颜色可能不同。
- 每座信号塔的正上方第一格（塔顶之上1格）有一个1x1的"信号色"像素，颜色与塔身不同——这就是该塔的发射颜色。

Rule:
- 每座信号塔从塔顶向左右两侧发射水平信号。信号覆盖范围：从塔顶所在行开始，向左和向右逐列扩展，将每列中从塔顶行到该列地形顶面之间的所有azure像素替换为该塔的信号色。
- 遮挡规则：信号水平传播时，如果遇到某一列的地形高度大于或等于塔顶高度，则信号被该列的山体遮挡，该列及该方向上更远的列都不再被覆盖。
- 如果两座塔的信号覆盖区重叠，则距离该像素更近的塔的信号色优先；若等距，则较高塔的信号色优先。
- 塔顶上方的信号色标记像素在输出中保留。塔身和地形保持原色不变。

Key insight: 第一层推理需要理解信号是水平传播并受地形遮挡（"视线"机制——只有当中间所有列的地形都低于塔顶时信号才能到达），第二层推理需要发现塔顶上方的独立像素才是真正的信号色、而塔身颜色只是塔的标识——两者的区分对正确着色至关重要。
</description>

<description>
在迷宫中根据钥匙颜色打开对应颜色的门，收集路径上的宝石并将宝石颜色填入终点房间的对应槽位。

Input structure:
- 背景为black。网格由maroon像素构成的墙壁分隔成若干互相连通的房间和走廊（宽度至少2格）。
- 起点房间：包含一个yellow像素标记（起点）。
- 终点房间：包含一排水平排列的grey像素槽位（1xN，N为宝石总数）。
- 走廊中某些位置有"门"：由两个相同颜色的像素上下（或左右）夹住走廊形成的1格宽关卡，门的颜色各不相同（如red、blue、green等）。
- 走廊中散落着"钥匙"：1x1的单色像素，颜色与某扇门的颜色相同。每把钥匙恰好匹配一扇门。
- 走廊中还散落着"宝石"：1x1的单色像素，颜色为门和钥匙都未使用的颜色（如orange、azure等）。

Rule:
- 从起点出发，沿走廊行走。遇到门时，必须已经经过（收集了）同色钥匙才能通过；否则该方向不通。
- 走廊的结构保证：从起点到终点只有一条合法路径（按正确的钥匙-门顺序通行）。
- 沿合法路径行走时，按经过的先后顺序收集路径上的宝石。
- 到达终点房间后，将收集到的宝石按收集顺序从左到右依次填入grey槽位：第1个收集的宝石颜色填入最左边的槽位，依此类推。
- 输出中：钥匙被收集后从原位擦除（变为black），宝石被收集后从原位擦除，门被打开后两个门像素变为black，槽位填入对应宝石颜色，其余保持不变。

Key insight: 第一层推理需要发现钥匙和门的颜色匹配关系（钥匙必须在同色门之前被遇到），由此推断出唯一合法路径；第二层推理需要沿该路径按顺序收集宝石并理解槽位的填充是按收集的时间顺序——路径选择和顺序填充是两个耦合的推理任务。
</description>
