- `Key insight`：解题者需要先从模板区归纳出"L 形朝向 → 颜色"的映射表，再对每个区域的种子图案进行朝向识别来查表染色——两步都需要非平凡的视觉匹配推理。

- `description`：沿彩色"导轨"传播信号，信号在交叉点处根据交叉导轨的颜色优先级决定转向。
- `Input structure`：背景为 Black。网格中有若干条由不同颜色像素组成的正交直线段（水平或垂直），颜色可能为 Red、Blue、Green、Yellow、Orange。这些线段会在某些位置正交交叉（交叉点处两条不同颜色的线段共享一个格子，该格子在输入中显示为其中一种颜色）。在某条线段的一个端点旁有一个 Magenta 像素作为"信号源"，信号源紧邻（4-邻接）线段端点。网格的一个角落有一个小的"优先级图例"：一行彩色像素从左到右排列，表示颜色优先级从高到低。
- `Rule`：
  1. 信号从 Magenta 信号源出发，沿着相邻线段的方向传播（将线段上的像素在输出中改为 Maroon）。
  2. 当信号沿一条颜色 A 的线段到达与颜色 B 的线段的交叉点时：查看优先级图例。如果 B 的优先级高于 A，信号转向进入 B 线段（沿 B 的方向继续）；如果 B 的优先级低于 A，信号忽略交叉继续沿 A 前进。
  3. 在交叉点转向时，信号沿 B 线段向远离已走过路径的方向前进（即选择 B 线段上尚未被标记的方向）。
  4. 信号到达线段末端且没有更多交叉点可走时停止。
  5. 未被信号经过的线段保持原色不变。
- `Key insight`：解题者需要先从角落图例归纳颜色优先级排序，再模拟信号传播时在每个交叉点应用"高优先级吸引转向"的规则——优先级的发现和交叉点处的条件转向构成两层独立推理。
</new_puzzle>

- `description`：根据"镜像缺陷"的位置和类型，从对称模板中选取修补方案并应用到目标对象上。
- `Input structure`：背景为 Black。网格上半部分有一个"模板库"：若干个小型图案排成一行，每个图案由某种颜色绘制（如 Blue、Green、Red 等），每个图案都是严格的上下对称图形（关于自身水平中轴对称）。网格下半部分散布着若干个与模板库中图案尺寸和形状相近的"目标对象"，每个目标对象使用 Grey 像素绘制，但其中恰好有 1-2 个像素被"破坏"——即被替换成了某个彩色像素（颜色与模板库中某个模板的颜色一致）。每个目标对象原本应该与模板库中的某一个模板形状相同。
- `Rule`：
  1. 对每个目标对象，找到其中被替换的彩色像素，该颜色指向模板库中对应颜色的模板。
  2. 将该模板的形状与目标对象当前的 Grey 像素进行对比，找到目标对象"缺失"的像素位置（模板有但目标对象没有 Grey 像素的位置）和"多余"的像素位置（目标对象有 Grey 但模板对应位置没有的位置）。

  4. 模板库保持不变。
- `Key insight`：彩色"破坏"像素既是破坏本身，又是指示应该使用哪个模板来修复的线索——解题者需要先识别这一双重角色（颜色编码匹配关系），再通过模板与破损对象的形状对比完成修复，两步推理缺一不可。

- `description`：将网格中的彩色"建筑"按其内部楼层结构进行垂直压缩或拉伸，压缩/拉伸的目标高度由外部"标尺"指定。
- `Input structure`：背景为 Black。网格中有若干个"建筑"——每个建筑是一个由 Grey 边框围成的竖直矩形，内部被水平的 Grey 隔线分成若干层（类似楼层），每层填充了某种颜色（Red、Blue、Green、Yellow 等），不同层颜色可能相同或不同。每个建筑的顶部正上方有一个由 Azure 像素画出的短竖线段（"标尺"），标尺的像素数量代表该建筑输出时应有的楼层数。网格底部有一行"颜色优先级条"：一行彩色像素从左到右排列，表示颜色优先级从高到低。
- `Rule`：
  1. 读取每个建筑顶部的 Azure 标尺长度 N，即目标楼层数。
  2. 如果建筑当前楼层数大于 N（需要压缩）：保留优先级最高的 N 个楼层（根据底部颜色优先级条判断每层颜色的优先级），从上到下排列这 N 层，移除其余层。若有两层颜色相同优先级并列，保留原始位置靠上的那层。
  3. 如果建筑当前楼层数小于 N（需要拉伸）：将最底层（优先级最低的那层）复制若干次填充到建筑底部，直到总楼层数达到 N。
  4. 如果楼层数恰好等于 N，不变。
  5. 输出中建筑的宽度不变，Grey 边框和隔线根据新的楼层数重新绘制，每层仍然是一个像素高。Azure 标尺在输出中被移除。
- `Key insight`：解题者需要三步推理——先从 Azure 标尺读取目标楼层数，再从底部颜色条归纳优先级排序，最后根据压缩或拉伸的不同情况应用不同的楼层选择/复制策略。标尺编码目标、颜色条编码规则、建筑结构编码数据，三者协同才能完成变换。
</new_puzzle>

- `description`：每个封闭房间内的彩色物体沿房间"出口"方向滑出，滑出后在相邻房间中触发连锁反应，将接触到的物体染成自身颜色。
- `Input structure`：背景为 Black。网格被 Grey 线条分隔成若干个矩形"房间"（类似网格迷宫，但所有隔墙宽度为 1 像素）。每面隔墙上最多有一个缺口（1 像素宽的 Black 间断），作为该墙的"出口"。部分房间内有一个由 2-4 个同色像素组成的小型彩色物体（颜色为 Red、Blue、Green、Yellow、Orange 之一），物体不接触房间墙壁。每个含物体的房间恰好有一面墙上有出口。
- `Rule`：
  1. 确定每个含物体房间的出口方向（出口在哪面墙上，物体就向该方向滑动）。
  2. 物体整体沿出口方向平移，穿过出口进入相邻房间，直到物体的前沿碰到对面的墙壁为止（物体紧贴墙壁停下）。
  3. 如果物体滑入的房间中已有另一个物体（不同颜色），则该房间中原有物体的颜色被替换为滑入物体的颜色（"染色效应"）。被染色的物体不再移动。
  4. 处理顺序：所有物体同时开始滑动；如果两个物体同时滑入同一房间，体积（像素数）较大的物体将较小的染成自己的颜色；体积相同则各自保持原色不变。
  5. 空房间（无物体）中不发生任何事件；物体滑出后原房间变为空（全 Black）。
- `Key insight`：解题者需要先通过墙壁缺口位置推断每个物体的运动方向（缺口即出口），再模拟物体穿越房间边界后的染色交互——方向推断和碰撞染色是两层独立的非平凡推理，且同时移动带来的冲突解决规则增加了额外的推理深度。
</new_puzzle>

<new_puzzle>
- `description`：用散落的彩色"钥匙"解锁对应颜色的"锁"，解锁后锁内隐藏的图案按钥匙的朝向旋转后显现。
- `Input structure`：背景为 Black。网格中有若干个"锁"——每个锁是一个由某种颜色（如 Red、Blue、Green 等）边框画成的 5×5 正方形，边框内部 3×3 区域全部填充为与边框相同的颜色（即看起来是一个实心方块）。网格中还散落着若干个"钥匙"——每个钥匙是一个由 3 个同色像素组成的 L 形小图案（两个像素水平相邻 + 一个像素从其中一端垂直延伸），钥匙颜色与某个锁的边框颜色相同。每个锁恰好对应一把钥匙（颜色配对）。同时，网格的某个边缘区域有一个"密码本"：一组 3×3 的小图案，每个图案使用 Grey 像素在 Black 背景上绘制了一个不对称的形状，密码本中每个图案旁边（右侧紧邻）有一个单像素的颜色标记，颜色与某个锁对应。
- `Rule`：
  1. 通过颜色匹配将每把钥匙与对应的锁配对。
  2. 通过颜色标记将密码本中的 Grey 图案与对应的锁配对。
  3. 判断钥匙的朝向：L 形的长边指向上/下/左/右中的某个方向。将朝上定义为 0°，朝右为 90°，朝下为 180°，朝左为 270°。
  4. 将该锁对应的密码本 3×3 图案按钥匙朝向角度顺时针旋转。
  5. 用旋转后的图案替换锁内部的 3×3 区域：Grey 像素位置保持 Grey，Black 像素位置变为 Black（即在锁的实心内部"刻出"图案）。锁的外层边框颜色不变。
  6. 钥匙在输出中被移除（变为 Black），密码本保持不变。
- `Key insight`：解题者需要完成三层推理：（1）颜色配对将钥匙、锁、密码本三者关联；（2）从 L 形钥匙的几何朝向推断旋转角度；（3）将旋转后的密码图案嵌入锁的内部。每一层都需要独立的归纳发现。
</new_puzzle>
