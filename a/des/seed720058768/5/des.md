<description>
根据框架缺口方向选择外部图案，再按框架内标记像素的颜色对图案进行逐层重绘后填入框架。

Input structure:
- 背景色（网格中最多的颜色）。网格上散布若干矩形单色框架（空心矩形边框），每个框架的边框恰好有一个单像素宽的缺口。
- 每个框架内部有 1–3 个不同颜色的孤立标记像素，分布在不同行上。
- 框架外部、远离所有框架的位置有若干小型多色图案（精灵），每个图案由恰好两种非背景色组成。其中一种颜色称为"主色"（像素数较多的那种），另一种称为"副色"。

Rule:
- 第一层：确定匹配关系。每个框架的缺口朝向（上/下/左/右）对应一个方向。沿缺口方向从框架出发，射线最先命中的外部图案即为该框架所选图案。
- 第二层：确定重绘方式。取框架内部标记像素，按从上到下的顺序排列。第一个标记像素的颜色替换图案的主色，第二个标记像素的颜色（如存在）替换图案的副色。若只有一个标记，则副色变为背景色（即擦除）。若有三个标记，第三个标记的颜色替换背景色区域中与图案紧邻（4-连通相邻）的那些背景像素。
- 第三层：将重绘后的图案紧贴缺口内侧放入框架中，图案的中心与缺口位置在缺口所在边的方向上对齐。若图案大于框架内部空间则裁剪至框架内。

Key insight: 缺口方向充当选择器来匹配外部图案，框架内标记像素的数量和颜色联合定义一个多级重绘规则——需要先发现方向选择机制，再归纳标记数量与重绘层次之间的对应关系。
</description>

<description>
将散落的彩色碎片按形状互补关系拼合成完整矩形，再根据拼合后内部形成的接缝线图案决定输出的排列顺序。

Input structure:
- 背景色为黑色。网格中散布若干彩色碎片，每个碎片是单色的不规则形状（4-连通区域）。
- 碎片总是成对出现：同一对碎片颜色不同，但形状恰好互补——即两块碎片无重叠地拼合后恰好填满一个无间隙的矩形区域。
- 每对碎片的矩形尺寸可能不同。拼合时其中一块可能需要旋转 0°/90°/180°/270° 才能与另一块互补。
- 网格边缘处有一行（或一列）由交替的两种颜色组成的色带，色带中的颜色对按顺序排列，指定了各对碎片在输出中的排列次序。

Rule:
- 识别所有碎片对：两个碎片能互补拼成矩形即为一对（尝试全部旋转）。
- 对每一对碎片执行拼合，生成填满的矩形。矩形中来自两块碎片的像素保留各自颜色。
- 两块碎片交界处形成一条接缝线。注意接缝线的走向（偏水平还是偏竖直）：若接缝线总体偏水平，则该矩形在输出中水平放置；若偏竖直，则竖直放置。
- 按照边缘色带给出的颜色对顺序，将拼好的矩形从左到右（若色带为水平行）或从上到下（若色带为竖直列）依次排列，矩形之间间隔一列或一行背景色。

Key insight: 需要先发现碎片的互补拼合关系（可能涉及旋转），再观察拼合后的接缝走向来确定放置方向，最后从边缘色带读取排列顺序——三层推理缺一不可。
</description>

<description>
用网格中的"种子像素"生长出形状，生长规则由同色参考区域的轮廓形状隐式编码。

Input structure:
- 背景色（网格最常见颜色）。网格被一条单像素宽的灰色分隔线分成左右两半（或上下两半）。
- 一侧（参考侧）包含若干不同颜色的实心小形状（参考形状），每个形状是完整的、无孔的 4-连通区域。
- 另一侧（生长侧）只包含若干孤立的单像素"种子"，每个种子的颜色与参考侧某个参考形状的颜色相同。同一颜色的种子可能有多个。

Rule:
- 第一层：对于每种颜色，在参考侧找到对应的参考形状。将该形状紧裁剪到其最小边界框，得到一个相对图案（相对于形状内某个特殊像素的偏移集合）。特殊像素的选取规则：取该形状中行号最小、行号相同则列号最小的像素作为锚点。
- 第二层：在生长侧，每个种子像素以自身位置为锚点，将对应颜色的相对图案"印章"盖上去。印章中的像素如果超出网格边界则忽略。
- 第三层：当多个印章覆盖同一个格子时，颜色冲突的解决规则为——种子像素距离该格子更近（按行差绝对值与列差绝对值中的较大值，即棋盘距离）的印章优先；若距离相同则后处理的颜色（按颜色在网格中首次出现的行优先、行相同则列优先的顺序排列，靠后者优先）覆盖先前的颜色。

Key insight: 参考形状不是直接被复制，而是被解读为"生长模板"——解题者需要先发现锚点的选取规则，再发现种子与模板的对应关系，最后理解冲突时的覆盖优先级。
</description>

<description>
根据封闭矩形框内"指针"像素的朝向，从框的对应边上采样颜色序列，然后用该序列作为条纹图案填充框内部。

Input structure:
- 背景色为黑色。网格中有若干由非黑色像素绘制的封闭矩形边框（边框宽度为 1 像素）。不同矩形的边框底色不同。
- 每个矩形边框的四条边上被涂上了不同片段的颜色——即边框并非纯单色，而是四条边各自由若干连续同色段组成（至少两种颜色交替出现在边框上）。角点像素同时属于两条边，其颜色以水平边为准。
- 每个矩形内部除背景色外，恰好有一个由两个像素组成的"指针"：两个像素 4-连通相邻，颜色相同且不同于背景色和边框上的任何颜色。指针的朝向由两个像素的相对位置决定——水平排列时指向从列号小的像素到列号大的像素的方向（即向右），竖直排列时指向从行号小的像素到行号大的像素的方向（即向下）。注意：向右表示采样右边，向下表示采样底边，以此类推需要通过样例归纳出指针朝向与边的完整映射。

Rule:
- 第一层：识别每个矩形框及其内部的指针，确定指针的朝向（上/下/左/右四种情况之一，实际由两像素的排列唯一确定方向：向右、向下各一种；若要表示向左或向上，则两像素顺序反转，即列号大的在前或行号大的在前——但更简洁的规则是：指针方向就是从第一个像素指向第二个像素的方向，其中"第一个"定义为行号较小者，行号相同则列号较小者）。
- 第二层：指针朝向指定了一条边框边。对应关系为：向上→顶边、向下→底边、向左→左边、向右→右边。读取该边上的颜色序列（顶边和底边从左到右读取，左边和右边从上到下读取），不包含角点像素。
- 第三层：用读取到的颜色序列作为重复条纹图案铺满矩形内部。若指针指向上或下（即采样水平边），则内部每一行的颜色按列依次循环使用该序列；若指针指向左或右（即采样竖直边），则内部每一列的颜色按行依次循环使用该序列。指针自身的像素也被条纹覆盖。

Key insight: 指针的朝向同时决定"从哪条边采样"和"沿哪个轴铺设条纹"——解题者需要先识别指针结构并归纳朝向规则，再建立朝向与边框边的对应关系，最后理解条纹的铺设方式是沿采样边的平行方向逐行或逐列重复。
</description>

<description>
在网格中找到被灰色路径连接的同色物体对，沿路径读取中转站的颜色指令，对发送端物体的形状执行累积变换后绘制到接收端位置。

Input structure:
- 背景色为黑色。网格中有若干彩色实心小物体（每个物体为单色 4-连通区域，面积至少 2 像素）。
- 恰好有若干对颜色相同的物体（每种非黑非灰颜色最多出现两个物体，出现两个即构成一对）。
- 每对同色物体之间由灰色像素组成的一条单像素宽路径连接（路径为 4-连通链，两端各自与一个同色物体的某个像素 4-连通相邻）。
- 路径上可能存在 0–3 个"中转站"——中转站是路径中被替换为非灰色的单个像素，颜色不同于背景和路径灰色。变换颜色含义固定为：Red = 水平翻转、Green = 竖直翻转、Blue = 顺时针旋转 90°、Yellow = 将形状中所有像素沿主对角线转置（即行列坐标互换）。

Rule:
- 第一层：识别同色物体对及其之间的灰色连接路径。在每对中，面积较小的物体为"发送端"，较大的为"接收端"。若面积相同，则边界框左上角行号较小的为发送端，行号也相同则列号较小的为发送端。
- 第二层：将发送端物体紧裁剪到其最小边界框，得到初始形状图案。沿路径从发送端一侧到接收端一侧的方向遍历，每遇到一个中转站，就按其颜色对应的变换操作作用于当前形状图案。多个中转站按路径上的先后顺序依次执行，变换结果累积。
- 第三层：将最终变换后的形状图案以接收端物体边界框的左上角为锚点绘制到输出中，颜色为该对物体的共同颜色。接收端原有像素被替换。发送端物体、灰色路径和所有中转站像素全部擦除为背景色。不成对的物体（若有）保持不变。

Key insight: 解题者需要先通过颜色配对找到物体对并区分收发方向，再沿路径按序读取中转站颜色来确定变换管道，最后理解变换的累积顺序——路径既是连接线索也是操作指令的有序序列。
</description>

<description>
根据网格中"窗户"矩形的内部分区结构，将外部配对的"货物"精灵切分后按螺旋顺序填入各分区。

Input structure:
- 背景色为黑色。网格中有若干橙色边框的矩形"窗户"（边框宽 1 像素，内部为黑色背景）。每个窗户内部可能被额外的橙色水平线和/或竖直线分割成若干等大的子区域（分隔线与边框同色，宽 1 像素），形成 R 行 × C 列的子区域网格。
- 每个窗户的某一条外边框上恰好有一个非橙色、非黑色的单像素"标签"，标签颜色在所有窗户中唯一。
- 网格中远离窗户的区域有若干矩形"货物"精灵（内部可含多种颜色的像素图案）。每个货物的左上角像素颜色与某个窗户标签颜色相同，以此表示配对关系。该左上角像素是角标，不属于货物图案本身。

Rule:
- 第一层：通过角标颜色与窗户标签颜色的匹配，将每个货物与对应的窗户配对。
- 第二层：读取窗户的分区结构——计算窗户内部被分成了 R 行 × C 列个子区域。每个子区域大小相同，设为 h 行 × w 列。
- 第三层：将配对货物（去除角标像素后的剩余矩形区域）切分为 R 行 × C 列个大小均为 h × w 的块。切分方式为从左到右、从上到下均匀划分（保证尺寸恰好整除）。
- 第四层：将切好的 R×C 个块按螺旋顺序填入窗户的子区域中。螺旋从窗户子区域网格的左上角开始，沿顺时针方向向内旋转（右→下→左→上→右→...）。货物块的读取顺序则是普通的逐行从左到右、从上到下。即：货物的第 1 块填入螺旋第 1 个子区域，第 2 块填入螺旋第 2 个子区域，依此类推。

Key insight: 窗户的分区结构同时决定了货物的切分粒度和子区域的数量，而子区域的填充采用螺旋遍历顺序而非普通的行列顺序——解题者必须同时归纳出切分规则和螺旋映射规则才能正确还原输出。
</description>

<description>
对网格中交叉的水平和竖直彩色条带，根据交叉点旁的标记像素决定叠压关系是否翻转，从而重绘交叉区域的可见颜色。

Input structure:
- 背景色为黑色。网格中有若干水平条带和若干竖直条带，每条条带宽度固定为 2 像素，各条带颜色不同（单色，且不为黑色、Azure 或 Maroon）。条带横跨网格，可能从一侧边界延伸到另一侧。
- 水平条带与竖直条带交叉时产生 2×2 的重叠区域。每个交叉区域中当前显示的是某一条条带的颜色（即该条带在视觉上位于上层）。
- 每个交叉区域的右下角外侧紧邻处（即交叉 2×2 区域右下角像素的右下方 1 格位置），有一个标记像素。标记颜色为 Azure 或 Maroon。

Rule:
- 第一层：识别所有水平和竖直条带，以及它们的交叉区域。对于每个交叉区域，根据当前显示的颜色判断哪条条带在上层。
- 第二层：读取每个交叉区域对应的标记像素颜色。若标记为 Azure，则该交叉区域的颜色保持不变（当前上层条带继续可见）；若标记为 Maroon，则将该交叉区域的 2×2 像素全部替换为另一条条带的颜色（即原本被遮挡的条带变为可见）。
- 第三层：输出中所有标记像素被擦除为背景色（黑色）。条带的非交叉部分保持不变。

Key insight: 交叉区域的颜色隐含了两条条带的前后层次关系，而标记像素的 Azure/Maroon 二元选择控制该层次是否翻转——解题者需要先理解条带交叉的遮挡概念，再发现标记颜色与翻转操作的对应关系。
</description>
</new_puzzle>
