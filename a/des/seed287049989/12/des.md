description：根据框架内部缺口的朝向，从外部选择对应方向的彩色箭头精灵，用箭头的颜色填充框架上与缺口同侧的整条边。

Input structure：
- 背景为最常见颜色。网格中央有一个单色矩形框架（空心矩形，边宽一像素）。
- 框架的每条边上恰好有一个一像素宽的缺口（即该边上有一个像素被擦除为背景色）。
- 框架外部散布着若干由不同颜色绘制的小型箭头精灵。每个箭头精灵由一个 3x3 的像素图案组成：箭头方向用一个三像素的直线段（箭杆）加末端的一个垂直于箭杆方向的三像素横线（箭头尖端）表示，整体呈"T"形，其中箭杆末端（非横线端）指示方向（上/下/左/右）。每个箭头精灵的颜色各不相同，且恰好有四个箭头，分别指向四个正方向之一。

Rule：
- 首先，确定框架四条边各自缺口的位置。顶边缺口对应"上"方向，底边缺口对应"下"方向，左边缺口对应"左"方向，右边缺口对应"右"方向。
- 然后，将每个缺口的方向与外部箭头精灵的朝向进行匹配：朝上的箭头匹配顶边缺口，朝下的箭头匹配底边缺口，以此类推。
- 最后，将框架中含有缺口的那条边的所有像素（包括缺口处）全部重新着色为匹配到的箭头精灵的颜色。框架的其余三条边保持原色不变。外部箭头精灵在输出中全部清除为背景色。
- 输出网格与输入同尺寸。

Key insight：箭头精灵的朝向不是指示移动方向，而是编码了它所对应的框架边——解题者需要先发现缺口的位置隐含了方向信息，再将方向与箭头匹配，最后用箭头颜色覆盖整条边。
</new_puzzle>

<new_puzzle>
description：将网格中每个彩色区域按其内部孔洞数量分组，同组区域合并为一个嵌套环形图案输出。

Input structure：
- 背景为黑色。网格中散布着若干由不同颜色绘制的闭合区域（4-连通单色连通分量），每个区域是一个不规则的实心形状，内部可能包含零个、一个或多个背景色孔洞（被该区域完全包围的黑色连通域）。
- 每个区域的颜色各不相同，区域之间互不接触。
- 孔洞数量的取值范围为 0、1 或 2，且每种孔洞数量至少有两个区域。

Rule：
- 第一步（分组）：统计每个彩色区域内部的孔洞数量（即被该区域完全包围的背景色 4-连通分量数目），将孔洞数量相同的区域归为一组。
- 第二步（组内排序）：在每组内，按区域的像素面积从大到小排序。
- 第三步（绘制嵌套方块）：为每组生成一个独立的正方形嵌套环图案。正方形边长 = 2 * 组内区域数 - 1。最大面积的区域颜色画最外圈环，次大面积的画次外圈环，最小面积的画中心像素。
- 输出网格将所有组的嵌套方块从左到右水平排列，组间留一列黑色间隔，总高度等于最大方块的边长，较小的方块垂直居中放置。

Key insight：解题者需要先识别出"孔洞数量"这一隐含属性作为分组依据（而非颜色、大小或位置），再在组内按面积排序绘制嵌套环——两步都需要非平凡的归纳推理。
</new_puzzle>

description：沿分隔线将网格分为图例侧和画布侧，根据图例中颜色条的层叠顺序，在画布侧的对应轮廓内按深度顺序填色。

Input structure：
- 背景为 Azure。网格被一条贯穿整个高度的单像素宽灰色竖线分为左右两半。
- 左侧（图例侧）：包含若干水平彩色条，每条宽度占满左半区域，颜色各不相同。这些彩色条从上到下排列，部分条之间可能有背景色间隔，部分条紧密相邻。某些条会在垂直方向上与其他条重叠（即同一行同时被两种颜色声明——此时上层颜色覆盖下层，只有上层可见）。重叠关系通过以下方式编码：每条彩色条的左端有一个一像素宽的 Maroon 标记，标记所在的行指示该条的起始行；右端有一个一像素宽的 Maroon 标记指示该条的结束行。当两条的行范围有交集时，出现在更低行（更靠下）的起始标记所属的条为上层。
- 右侧（画布侧）：包含若干由黑色单像素边框勾勒的闭合矩形轮廓，矩形内部为背景色。每个矩形的高度与左侧某条彩色条的高度（结束行 - 起始行 + 1）完全相同。矩形之间不重叠、不接触。

Rule：
- 首先，从图例侧还原每条彩色条的完整行范围（通过其起止 Maroon 标记确定）。
- 然后，确定层叠顺序：起始标记行号更大（更靠下）的条在更上层。
- 接着，将画布侧的每个矩形按高度匹配到图例侧的彩色条（高度唯一对应）。
- 最后，按照层叠顺序从底层到顶层，依次用对应颜色填充画布侧的矩形内部。如果多个矩形在画布侧有行范围重叠（矩形的行范围有交集），则上层颜色覆盖下层颜色——即画布侧重现了图例侧的层叠覆盖效果。
- 灰色分隔线、黑色边框和 Maroon 标记在输出中保持不变。

Key insight：图例侧的可见颜色条并不直接给出层叠信息——被遮盖的部分在图例中不可见，解题者必须通过 Maroon 起止标记推断每条的完整范围和覆盖优先级，再将这套深度规则映射到画布侧的矩形布局中。
</new_puzzle>

<new_puzzle>
description：每个彩色种子像素向其所在象限的外侧方向生长出 L 形臂，臂的长度由同象限内的灰色刻度尺决定。

Input structure：
- 背景为黑色。网格正中央有一条单像素宽的红色十字线（一条水平线和一条垂直线交叉于网格中心），将网格分成四个象限（左上、右上、左下、右下）。
- 每个象限内恰好有一个灰色的直线段（水平或垂直），充当"刻度尺"，其长度为 2 到 5 个像素。
- 每个象限内还有恰好一个非黑、非红、非灰的彩色单像素"种子"。四个种子颜色各不相同。

Rule：
- 对于每个象限，读取该象限内灰色刻度尺的像素长度 L。
- 从该象限的种子像素出发，向远离十字中心的两个方向（即朝向该象限的外侧角落方向）各延伸 L 个像素，形成一个 L 形臂。具体地说：左上象限的种子向左延伸 L 格、向上延伸 L 格；右上象限的种子向右延伸 L 格、向上延伸 L 格；左下象限的种子向左延伸 L 格、向下延伸 L 格；右下象限的种子向右延伸 L 格、向下延伸 L 格。L 形臂包括种子本身所在的角点。
- 延伸不能越过网格边界；若到达边界则截断。
- 红色十字线、灰色刻度尺在输出中保持不变。种子像素被 L 形臂覆盖（即种子处仍为该颜色）。

Key insight：解题者需要同时发现三个非显然关联：(1) 灰色线段是长度编码而非装饰；(2) 生长方向由象限位置决定而非由刻度尺方向决定；(3) 种子是 L 形的拐角而非端点。这三者共同决定了输出形状。
</new_puzzle>

description：网格中的每对同色标记之间的连线定义了一条隐形切割线，将被穿过的前景矩形切割后移除较小的碎片。

Input structure：
- 背景为 Azure。网格中有若干个由不同颜色绘制的大型实心矩形前景对象（每个矩形颜色唯一，矩形之间不重叠）。
- 网格边缘（最外圈一行或一列上）散布着若干成对的小标记像素。每对标记使用相同颜色（与所有矩形颜色均不同），且每种标记颜色恰好出现两次。两个同色标记一定位于网格的对边上（一个在顶边一个在底边，或一个在左边一个在右边）。
- 标记颜色的种类数不超过 3。

Rule：
- 对于每对同色标记，在两个标记之间画一条假想的直线（水平或垂直贯穿整个网格，因为它们在对边上且共享同一行或同一列）。
- 这条线将穿过零个或多个前景矩形。对于被穿过的每个矩形，沿该线将其切成两部分。
- 如果一个矩形被多条线切割，则产生多个碎片。
- 切割完成后，对于每个原始矩形，保留面积最大的碎片（像素数最多），移除所有较小的碎片（将其设为背景色）。如果切割产生的两个碎片面积相等，则保留靠近网格中心的那个（即碎片中心行列均值更接近网格中心行列均值的那个）。
- 标记像素在输出中被清除为背景色。切割线本身不可见，仅切割效果体现在矩形的缩减上。

Key insight：标记像素不是装饰也不是颜色编码——同色配对定义了一条隐形切割线。解题者需要先发现边缘标记的配对规则（同色且对边），再理解切割线对矩形的分割效果，最后推断出"保留大片、去除小片"的筛选逻辑。
</new_puzzle>

description：根据围栏内部空心区域的形状匹配外部钥匙精灵，用匹配所需的旋转角度旋转整个围栏，最终将旋转后的围栏按面积从大到小嵌套输出。

Input structure：
- 背景为黑色。网格中有若干个由不同颜色绘制的单像素厚矩形"围栏"（空心矩形框），围栏之间不重叠不接触。每个围栏内部的空心区域中包含一个由围栏色像素构成的小图案，使得剩余的背景色区域形成一个独特的连通形状（"锁孔"）。
- 网格边缘区域（远离所有围栏）散布着若干小型单色精灵（"钥匙"），每个钥匙的形状与某个围栏内部锁孔的形状完全匹配（可能需要旋转 0 度、90 度、180 度或 270 度之一才能对齐）。每个钥匙颜色各不相同，且每个钥匙恰好匹配一个围栏。
- 钥匙的数量等于围栏的数量。

Rule：
- 第一步（匹配）：将每个钥匙精灵的形状（作为二值掩模）与每个围栏的锁孔形状进行比对，找到唯一的形状匹配（允许 0 度、90 度、180 度、270 度旋转）。记录匹配所需的旋转角度。
- 第二步（旋转围栏）：将每个围栏（包括其内部图案）按照匹配钥匙时所用的旋转角度进行相同方向的旋转。例如，如果钥匙需要顺时针旋转 90 度才能匹配锁孔，则将围栏也顺时针旋转 90 度。
- 第三步（嵌套输出）：将所有旋转后的围栏按外框面积从大到小居中嵌套放置在输出网格中。最大的围栏放在最外层，依次嵌套。输出网格大小恰好容纳最大围栏。钥匙精灵在输出中被清除。

Key insight：钥匙精灵不仅是锁孔的形状编码，更隐含了旋转指令——匹配所需的旋转量同时定义了围栏本身应如何旋转。解题者需要先发现形状匹配关系，再发现旋转传递规则，最后发现嵌套排列的面积排序逻辑。
</new_puzzle>

description：在棋盘格图案中，根据散落标记像素的颜色查找角落模板块，用模板图案替换被标记的棋盘格块。

Input structure：
- 网格由两种颜色（Green 和 Yellow）组成规则的棋盘格图案，每个格子大小为 3x3 像素。整个网格是若干个 3x3 块的整数倍大小。
- 棋盘格中的某些 3x3 块的中心像素被替换为其他颜色的标记像素（非 Green 非 Yellow），这些标记颜色有 Red 和 Blue 两种。
- 网格四个角落的 3x3 块中，左上角块和右下角块包含"模板图案"：左上角块的 3x3 区域展示的是 Red 标记对应的替代图案（9 个像素构成一个特定的两色图案）；右下角块展示的是 Blue 标记对应的替代图案。这两个角落块的图案与正常棋盘格不同，可以被视觉识别出来。

Rule：
- 首先，从左上角 3x3 块读取 Red 的替代图案 P_red，从右下角 3x3 块读取 Blue 的替代图案 P_blue。
- 然后，扫描所有非角落的 3x3 块：如果某块的中心像素为 Red，则将该块的全部 9 个像素替换为 P_red；如果中心像素为 Blue，则替换为 P_blue。
- 替换时保持图案方向不变（不旋转）。
- 未被标记的非角落 3x3 块保持原有棋盘格颜色不变。
- 左上角和右下角的模板块本身保持不变。

Key insight：棋盘格的规则性让异常标记像素很容易被注意到，但解题者的关键挑战在于发现角落块不是普通棋盘格而是"图例"——它们定义了标记颜色到替代图案的映射。这需要同时归纳出标记的查找规则和模板的读取位置。
</new_puzzle>
