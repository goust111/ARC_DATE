<description>
通过"图例砖块的颜色与高度"建立一个排名查找表，再用查到的颜色为不同形状的孔洞着色：高度 k 的图例选出"孔洞数排名第 k"的对象，将其内部填上图例颜色。
</description>
Input structure:
- 背景为 Black。
- 网格顶部（紧贴第 0 行）有若干竖直的图例砖块（legend），每块是一列单色实心方块，颜色各不相同（如 Red、Green、Azure），高度 k 表示该砖块占据的格数（1 到 4）。各图例砖块沿顶行从左到右排列，彼此用一列 Black 隔开。
- 主区域（图例下方）散布着若干 Grey 实心闭合轮廓对象。每个对象是一个 Grey 的封闭环（厚度 1 像素的环形边框），其内部包住若干 Black 的"孔洞"（被 Grey 完全包围的 Black 连通块）。不同对象孔洞数量不同（如 1、2、3、4 个孔洞）。
- 图例砖块的数量与主区域 Grey 对象的数量相等，且各图例高度互不相同。

Rule:
- 先按"孔洞数量"对所有 Grey 对象排名：孔洞最多的对象排名为 1，次多为 2，依此类推（保证孔洞数互不相同，排名无歧义）。
- 对每个图例砖块 (颜色 K, 高度 k)：找到孔洞数排名第 k 的那个 Grey 对象，把该对象内部的所有 Black 孔洞像素全部重绘为颜色 K。Grey 环本身保持不变。
- 其余像素全部保持不变。

Key insight:
- 图例的高度不是几何尺寸，而是一个"排名索引"，必须先把对象按孔洞数排序，再用高度作为名次去查表选对象——双层映射（高度→名次→对象，颜色→填充），两步都需要主动归纳。
source: 取参考题 19（图例高度作为排名索引而非字面尺寸）与参考题 16/14（数孔洞作为对象的可见属性）的机制重组。变异点：把"按长度排名竖条"换成"按孔洞数排名闭合对象"，并把排名结果作为内部填色的对象选择器，而非直接重绘竖条，使排序键与变换目标解耦。
</new_puzzle>

<new_puzzle>
<description>
读取一串 3x3 字形指令决定每个箭头的转向序列，沿网格行进并在每步留下递进的颜色轨迹，直到撞墙停止。
</description>
Input structure:
- 背景为 Black。
- 网格左侧有一条整列高度的 Grey 竖直分隔线，把网格分成左右两部分。
- 分隔线左侧：自上而下排列若干 3x3 的彩色字形（glyph），每个字形画在 Black 背景上。字形只有两种形态：一种是"竖条"（中间一列三个像素填充，area=3），表示"左转"；另一种是"横条"（中间一行三个像素填充，area=3 但方向不同），表示"右转"。两种字形用不同朝向区分，颜色统一为 Azure。
- 分隔线右侧：恰好一个 Red 的起点像素，以及一个画在边界上的方向箭头（由 3 个像素组成的指向性箭头：箭头尖端单像素加其后两像素的短柄，明确指出起点初始前进方向）。

Rule:
- 移除 Grey 分隔线，把起点像素与箭头保留在右半区原位。
- 按从上到下的顺序读取左侧字形，得到一串转向指令（竖条=左转/逆时针 90°，横条=右转/顺时针 90°）。
- 箭头从 Red 起点出发，沿初始方向直行，每经过一个 Black 格就把它涂色：涂色按 Blue、Green、Yellow、Magenta 的固定循环依次推进（第 1 步 Blue，第 2 步 Green……第 5 步又回到 Blue）。
- 每当粒子撞到网格边界，就执行指令串中的下一个转向（第 1 次撞墙用第 1 个字形，第 2 次撞墙用第 2 个字形……）。
- 当转向指令用尽，或转向后立即又面对边界无法前进时，粒子停止。

Key insight:
- 字形序列是一份"转向脚本"，撞墙事件与脚本条目按次序一一对应；解题需把"字形形态→左右转"和"撞墙计数→取第几条指令"两层对齐，颜色循环则记录步数，三者缺一不可。
source: 取参考题 9（3x3 字形按顺序解码为指令）、参考题 18（沿路径行进、撞边界转向并按颜色循环上色）的机制重组。变异点：把参考题 18 固定的"奇偶交替左右转"替换为"由左侧字形脚本逐条决定转向"，使转向方向不再可预测，必须先解码字形脚本，再与撞墙事件序列对齐。
</new_puzzle>

<new_puzzle>
<description>
找出每一"格子行"中图案唯一的奇异格，把它的内部图案当作蓝图放大到整张格子网格上，在蓝图的激活位置铺满该奇异图案。
</description>
Input structure:
- 背景为 Black。网格被一种单色（Grey）的均匀分隔线划分成 N×N 个相等的方形格子。
- 绝大多数格子内部是同一个"多数图案"（majority），少数格子内部是一个不同的"奇异图案"（minority），二者都画在 Black 上，使用同一种前景色（如 Blue）。
- 每个格子内部图案占据格子内部固定的 m×m 像素区域；多数与少数图案的前景像素布局不同但 m 相同。

Rule:
- 第一步：从所有格子中找出唯一的那个奇异图案（在整张网格里出现次数最少的内部图案），记下它的 m×m 前景布局，作为"蓝图"。
- 第二步：把蓝图按格子尺度放大——蓝图中每个前景像素对应格子网格中的一个"激活格"，每个背景像素对应"非激活格"。蓝图的左上像素对齐到格子网格的左上格。
- 第三步：构造输出（保留 Grey 分隔线与格子尺寸）：所有"激活格"的内部填入奇异图案，所有"非激活格"的内部填入多数图案。
- 即把原本零散分布的奇异格重排成蓝图所指示的整体布局，缺的补齐、多的改回多数图案。

Key insight:
- 奇异格内部的小图案同时是"被复制的内容"和"复制到哪里去的位置蓝图"——同一份 m×m 图案在像素尺度是内容、在格子尺度是布局，自相似嵌套，需先识别奇异、再把它读成两种用途。
source: 取参考题 4（每行/整网中找唯一的奇异格）与参考题 10（奇异格内部作为格子尺度的分形蓝图）的机制重组。变异点：把参考题 10 中"奇异格已对齐到蓝图激活位"的前提去掉，改为奇异格随机散布、必须按蓝图重新排布，并叠加参考题 4 的奇异识别作为前置层，使识别与重布双层都需主动推理。
</new_puzzle>

<new_puzzle>
<description>
用"工具对象的某种颜色区域计数"匹配边框框架的孔洞数，再把工具旋转嵌入框架，按是否发生镜像决定是否交换工具两色。
</description>
Input structure:
- 背景为 Black。
- 若干贴边的彩色框架（frame）：每个框架是一个单色（Grey）的封闭矩形环，内部有一片 Black 的孔洞（cavity），孔洞形状不规则。框架贴着网格边界。
- 若干不贴边的"工具"对象（tool）：每个工具由恰好两种颜色（如 Red 与 Green）组成的连通块，其中一种颜色的像素恰好能拼成某个框架孔洞的形状。
- 框架数量与工具数量相等，且各框架孔洞的"格数"互不相同。

Rule:
- 对每个工具，数它两种颜色各自的像素数；对每个框架，数它孔洞的像素数。
- 匹配：把工具与某框架配对，使该框架孔洞像素数恰好等于工具中"某一种颜色"的像素数（保证唯一匹配）。被用来匹配的那种颜色称为"填充色"，另一种为"溢出色"。
- 把工具做旋转/翻转，使其填充色区域的形状与框架孔洞完全重合，嵌入框架内部填满孔洞；溢出色像素则落在框架外部紧贴框架。
- 若使工具嵌合所需的变换包含一次翻转（镜像），则在放置后交换该工具的两种颜色（填充色与溢出色对调）。
- 框架与未参与的背景保持不变。

Key insight:
- 配对键是"工具某一颜色的计数等于框架孔洞计数"，到底用哪种颜色作填充色由计数本身决定（不是预先指定），且镜像与否触发颜色交换——计数选色、几何嵌合、镜像换色三层都要主动判断。
source: 取参考题 5（孔洞/腔体尺寸决定工具-框架配对、镜像触发换色）与参考题 16（孔洞形状在旋转/翻转下的匹配）的机制重组。变异点：把参考题 5 中"工具某颜色区域数等于腔体"的判断升级为"由哪种颜色匹配上来反向决定填充色与溢出色的角色分配"，使颜色角色不再固定而是匹配结果的产物。
</new_puzzle>

<description>
把每个彩色记号沿其所在的双色平行栏走廊传送到走廊另一端，并在到达端把记号替换成它的"互补形态"。
</description>
Input structure:
- 背景为 Yellow。
- 若干成对的同色实心横栏（bar）：每对栏颜色相同、平行且相隔一行，中间夹出一条 Yellow 的"走廊"（corridor），走廊宽 1 行、沿水平方向贯穿到某一端的网格边界。不同走廊用不同的栏颜色（如 Blue 一对、Green 一对、Azure 一对）。
- 每条走廊靠近其封闭端的位置放着一个 3x3 的记号（token），形态只有两种：实心 3x3 方块，或 X 形（两条对角线共 5 像素）。记号颜色与走廊栏颜色无关，统一为 Maroon。

Rule:
- 每个记号沿其走廊从封闭端朝开口端（网格边界方向）传送：原位置的记号被清除（涂回 Yellow），在走廊另一端（贴着开口边界）重新画出。
- 传送过程中记号变为"互补形态"：实心方块 → 变为菱形（中心 + 四个正交邻居，共 5 像素）；X 形 → 变为实心方块。
- 颜色保持 Maroon，3x3 占位居中对齐于走廊行。
- 走廊栏与其它背景保持不变。

Key insight:
- 走廊由"同色平行栏"唯一定义合法路径（哪条栏配对决定记号往哪走），传送的同时形态按"实心→菱形、X→实心"的固定互补环替换，需同时读懂"配对栏决定路线"与"形态互补环"两层。
source: 取参考题 7（同色平行栏定义走廊、记号沿走廊行进）与参考题 3（记号沿连线传送并替换为互补形态）的机制重组。变异点：把参考题 3 的"导线网络"换成参考题 7 的"双色平行栏走廊"作为路由通道，并把互补环锁定为"实心↔X↔菱形"的子集，使路由判定与形态变换互相独立又必须同时成立。
</new_puzzle>

<new_puzzle>
<description>
学习一对"框中样例"展示的变换规则，把同一规则应用到测试框，但具体用哪条规则由测试框内部的颜色集合所匹配的训练对决定。
</description>
Input structure:
- 背景为 Black。网格中有若干单色的方形空心框（hollow border），每个框内部装着一个小图案样例。
- 框分成两组训练对加一个测试框：每个训练对由两个框组成（一个"源"框、一个"目标"框），二者内部图案的颜色集合相同，展示一种变换（例如：水平镜像、上下镜像、或前景背景互换）。不同训练对展示不同变换，且各自用不同的颜色集合。
- 测试框内部图案的颜色集合，与某一个训练对的颜色集合相同；该训练对就是测试框要套用的规则。测试框的"目标框"为空（全 Black），等待填充。

Rule:
- 第一步：把所有训练对按"内部颜色集合"配对识别出来，每对推断出源→目标的视觉变换规则。
- 第二步：看测试框内部图案的颜色集合，找出与之颜色集合相同的那个训练对，取该对所示的变换规则。
- 第三步：把该变换规则作用到测试框的源图案上，结果画进测试框配套的空目标框内部。
- 其余框与背景保持不变。

Key insight:
- 这是带"规则选择"的类比题：不仅要从每个训练对各自归纳一条规则，还要用"颜色集合相同"把测试框路由到正确的那条规则上——规则归纳与规则选择是两个独立的推理层，颜色集合是连接二者的唯一线索。
source: 取参考题 13（从训练对推断变换并套用到测试，用内部颜色集合配对）的机制，叠加参考题 15（颜色记号作为路由匹配键）的选择机制。变异点：参考题 13 只有一对训练，本题升级为"多对训练 + 颜色集合作为路由键选规则"，新增"在多条候选规则中选对"的推理层，使单纯学一条规则不再够用。
</new_puzzle>

<new_puzzle>
<description>
从一个短的彩色边界段沿垂直方向以固定节奏铺出条纹，其中"洪泛色条纹"会把所经整行/整列上的前景对象重绘，并按条纹推进的序号递增地染成不同颜色。
</description>
Input structure:
- 背景为 Black。网格内部散布若干 Grey 的前景对象（blob）。
- 某一条边界上有一段短的 Azure 边界段（segment），长度小于该边的全长。

Rule:
- 从 Azure 段出发，朝对侧边界推进，每 2 格画一条条纹（条纹之间的 1 格间隔强制为 Black）。
- 条纹颜色按推进序号循环：第 1 条 Azure、第 2 条 Azure、第 3 条为"洪泛条纹"，如此每 3 条出现一次洪泛条纹。
- Azure 条纹只在 Azure 段的跨度范围内绘制（不越出段宽）。
- 洪泛条纹则作用于它所在的整行（或整列，取决于推进方向）：把该行/列上所有非背景（Grey 对象）像素重绘。重绘颜色随洪泛条纹出现的次序递增：第 1 条洪泛用 Blue、第 2 条用 Green、第 3 条用 Yellow、第 4 条用 Magenta，依此循环。
- 同一行/列若同时被洪泛条纹覆盖，前景对象按对应洪泛序号的颜色重绘；未被洪泛条纹覆盖的对象保持 Grey。

Key insight:
- 洪泛条纹既是"节奏中的第 3 拍"，又携带一个随出现次序递增的颜色编号——解题者必须同时跟踪条纹的空间节奏（2 格步进、第 3 拍洪泛）与洪泛条纹的时间序号（第几次洪泛→染什么颜色），两层节奏交织。
source: 取参考题 20（从彩色边界段按 2 格节奏铺条纹、绿条纹洪泛重绘整行对象）的机制，叠加参考题 18/2 的"按序号递进着色"机制。变异点：把参考题 20 中"洪泛条纹统一染成单一绿色"升级为"每条洪泛条纹按其出现次序染不同递增色"，新增一层必须按洪泛发生顺序计数取色的推理。
</new_puzzle>
