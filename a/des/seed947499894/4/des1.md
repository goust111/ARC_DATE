description: 用图例统计出的对象数量为每条横向色条选定长度，再从分隔列向空白侧周期性延伸。

Input structure:
- 背景为 Black。
- 网格被一条几乎贯穿全高的纵向 Grey 分隔列分成左右两侧。
- 左侧（图例与计数区）：贴着左边界有一列"键像素"，每个键像素是一种不同颜色（例如 Red、Green、Azure）。在左侧区域内还散布着若干独立的小色块对象，每个对象是某个键颜色，彼此 4-连通分离。
- 右侧（延伸区）：紧贴分隔列右侧，每个含有键像素的行上各有一个该键颜色的横向短色条（长度可不同），色条右侧是大片 Black 空白。

Rule:
- 对每个键颜色 C：在左侧计数区里数出颜色为 C 的独立 4-连通对象个数，记为 N（约 2 到 6）。
- 在右侧，找到该键颜色所在那一行的横向短色条。无论该色条原本多长，都先把它截短或补齐为长度恰好等于 N（从紧贴分隔列的那一格开始向右计 N 格）。
- 然后以这个长度 N 为周期，从色条尾部继续向右：每隔 N 个 Black 格放置一个长度为 N 的同色条，直到到达右边界。即输出为"实心 N 段、空 N 段、实心 N 段……"的周期重复。
- 处理顺序按行从上到下；各行互不影响。左侧计数区与分隔列在输出中原样保留。

Key insight: 图例对象的"数量"先被转换成右侧色条的"长度"，再被同一个数当作"延伸周期"复用——同一个视觉计数在两个不同几何维度（长度与间隔）上被使用两次。
source: 取自参考题6（图例键像素＋数对象个数）的计数机制、参考题20（沿分隔列向空白侧按周期延伸色条）的延伸机制。变异点：参考题20中周期来自色条自身长度，这里周期改由"另一区域统计出的对象数"决定，且该数同时决定色条的初始长度，形成"计数→长度→周期"的二次复用，推理路径不同。
</new_puzzle>

<new_puzzle>
description: 沿一条 Grey 蛇形路径按经过顺序读取被路径触碰的色块颜色，将这些颜色按顺序填入一个空心方框的边缘。

Input structure:
- 背景为 Black。
- 一条 Grey 的 4-连通单笔画路径（蛇形，无分叉，恰有两个端点）蜿蜒穿过网格。
- 路径沿途紧贴着若干单色小方块（每个方块是一种不同颜色，且与 Grey 路径 4-相邻接触）。
- 网格一角有一个空心的 Grey 方框（hub），其边框为 Grey，内部为 Black，方框边长足以容纳所有沿途方块的颜色。

Rule:
- 找到 Grey 路径的两个端点（只有一个路径邻居的 Grey 格），从左上更靠前的那个端点开始，沿路径逐格走到另一端点。
- 在行走过程中，每当当前路径格 4-相邻接触到一个彩色方块，就按"首次接触的先后顺序"把该方块的颜色记入一个有序颜色序列（同一方块只记一次）。
- 在输出中：删除所有沿途彩色方块与原 Grey 路径（路径变回 Black），但保留空心 Grey 方框。
- 把有序颜色序列依次填入方框的边框格：从方框左上角开始，沿顺时针方向（先上边，再右边，再下边，再左边）逐格用序列颜色覆盖原 Grey 边框格，序列用完即停止，剩余边框格保持 Grey。

Key insight: 路径不直接变成输出形状，而是充当"读取顺序的指针"，把空间散布的颜色压成一个一维有序序列；随后这个序列又被重新铺到方框边框这个完全不同的几何容器上，读取顺序与书写顺序解耦。
source: 取自参考题15（沿单笔画蛇形路径按端点定序遍历）的定序遍历机制、参考题7（路径端点决定取色对象）的"路径作为指针"思想、参考题16（空心方框作为输出容器）的容器结构。变异点：参考题15直接输出一列颜色，这里把遍历得到的有序颜色改写到方框边框上，遍历方向与书写方向（顺时针绕框）是两套独立几何，形成"读序→写序"的双层映射。
</new_puzzle>

Input structure:
- 背景为 Black。
- 顶部有一排"图例样板精灵"：每个样板是一个带某种边框颜色的实心小块，块内部挖有若干 Black 孔洞，且块中心有一个单独的中心像素（中心像素颜色与边框颜色不同）。各样板的孔洞个数互不相同。
- 网格下方散布着若干"目标精灵"：每个目标精灵也是带边框的小块，内部挖有若干 Black 孔洞，但它们的中心像素当前是 Black（空缺）。不同目标精灵的孔洞个数可能相同也可能不同。

Rule:
- 对每个图例样板，数出其内部 Black 孔洞的个数（约 1 到 5），建立"孔洞数 → 中心颜色"的对应表（保证孔洞数在样板间唯一）。
- 对每个目标精灵，数出其内部 Black 孔洞个数 K，在对应表中查到孔洞数等于 K 的那个样板。
- 把该样板的中心颜色填入目标精灵当前 Black 的中心格。
- 图例样板在输出中原样保留；目标精灵除中心被填色外其余不变；网格尺寸不变。

Key insight: 孔洞个数不是用来直接做几何变换，而是充当一个查表索引——通过"孔洞数相等"把目标与图例样板配对，再借用样板的中心颜色完成间接上色，匹配键（孔洞数）与传递物（中心颜色）是两种完全无关的属性。
source: 取自参考题3a25b0d8编号13（数孔洞）的孔洞计数、参考题7（用某属性作为查表键间接传递中心颜色）的间接配色、参考题1（颜色匹配后做覆盖）的匹配-重绘流程。变异点：参考题13用孔洞做空间对齐填色，这里改用"孔洞计数"作纯粹的配对索引，传递的是与孔洞无关的中心颜色，推理由"几何对齐"变为"计数索引＋颜色搬运"，路径质变。

<new_puzzle>
description: 找出唯一一种其所有同色对象都是单像素的标记色，用这些标记像素所在行列连成的网格线交点处放置十字，并按交点数量给每条线染上对应的颜色。

Input structure:
- 背景为 Black。
- 网格中有若干水平和竖直的一格粗的彩色线段（每条线段一种颜色，可能有多种颜色的线段）。
- 另外散布着若干"标记像素"：标记色被定义为"该颜色的所有 4-连通分量都是单像素"的颜色（与参考题9的标记定义一致）。每个标记像素都恰好位于某条已存在线段的行或列的延长线视线上。

Rule:
- 第一步：识别出所有"标记色"（其全部分量均为单像素的颜色）。每个标记像素沿其所在的行或列存在一条与之共线的彩色线段——把该标记像素"吸附"到那条线段的颜色类别（即认为它属于那条线段所代表的那一行或那一列）。
- 第二步：由这些被标记像素确定一组"激活行"和"激活列"——凡有标记像素落在某条水平线段视线上的，该水平线段所在行成为激活行；落在竖直线段视线上的，对应列成为激活列。
- 第三步：在每个"激活行 × 激活列"的交点格，画一个由 5 个像素组成的加号十字（中心格＋上下左右各一格），十字颜色取该交点所在水平线段的颜色。
- 第四步：对每条水平线段，数它经过的十字个数 M，若 M≥1 则保留并加粗为原色；竖直线段同理保留。没有任何标记落在其上的线段保持原样。原标记像素在输出中删除（变回 Black）。

Key insight: 标记像素本身不携带几何信息，它们的作用是"投票"选出哪些行、哪些列被激活；真正的输出结构（十字阵列）出现在被激活行列的笛卡尔交点上——稀疏的点先被翻译成一组行列坐标集合，再由两个集合的乘积生成稠密的交点图案。
source: 取自参考题9（用"全分量皆单像素"定义标记色，并将标记沿行列视线吸附到线段）的标记识别与吸附机制、参考题6（用计数决定保留/绘制）的计数判定。变异点：参考题9把标记当作补线/控制射线的局部修复指令，这里改为让标记仅充当"行列激活投票"，输出是激活行列交点处的十字阵列，从"线网修复"质变为"行列集合求交生成点阵"。
</new_puzzle>

<new_puzzle>
description: 把若干彩色矩形精灵按各自面积从小到大排序，依次嵌套同心地重绘成一组由外到内的方框，颜色顺序由面积排名决定。

Input structure:
- 背景为 Black。
- 网格中散布着若干实心彩色矩形精灵，每个一种不同颜色，面积（像素数）互不相同。
- 另有一个单独的单像素"中心标记"（一种不出现在任何矩形中的颜色，例如 Magenta），它指示同心嵌套图案的几何中心。

Rule:
- 第一步：计算每个矩形精灵的面积（像素个数），按面积从大到小排序，得到一个有序颜色列表（面积最大的排第 1）。
- 第二步：删除所有原始矩形精灵，保留中心标记的位置作为嵌套图案中心。
- 第三步：以中心标记为几何中心，画一组同心的空心方环（每环一格粗）。从最内层到最外层，环的颜色按"面积从小到大"取用排序列表（即面积最小的颜色画最内圈，面积最大的颜色画最外圈）。相邻两环紧贴（半径每次加 1），共画出与矩形个数相等的环数。
- 第四步：中心标记格本身保留为它原来的标记颜色。网格尺寸不变；若最外环超出网格则被裁剪到边界。

Key insight: 矩形的具体形状被完全丢弃，只有"面积排名"这一个标量被保留下来，并被重新映射成同心环的"半径次序"——一个一维排名序列被翻译成二维的同心层结构，排序方向（小面积在内）是必须从样例归纳的隐藏约定。
source: 取自参考题18（取中位/排序作为隐藏序参考）的排序-序选取思想、参考题17（单像素标记锚定输出几何中心/方位）的标记锚定、参考题5（同心/块层级结构）的层级几何。变异点：参考题17用标记定锚后拼接原精灵，这里丢弃精灵形状、仅用面积排名映射成同心环半径次序，输出几何（同心环）与输入几何（散布矩形）完全无关，推理为"排序→半径层序"的重映射。
</new_puzzle>

<new_puzzle>
description: 比较两个相似带孔对象的孔洞图案，仅在两者孔洞位置不一致处用 Red 标出差异，并把差异格数写成图例条上的点。

Input structure:
- 背景为 Black。
- 网格左右（或上下）各有一个形状、尺寸、外框颜色都相同的实心彩色对象，每个对象内部挖有若干 Black 孔洞，但两个对象的孔洞分布不完全相同。
- 网格一侧有一个全 Black 的横向"计数图例条"，其最左端有一个 Grey 起始像素。

Rule:
- 第一步：把两个对象按其外框对齐叠放（它们形状全等，可直接逐格对应）。
- 第二步：逐格比较对应位置的孔洞：若某格在恰好一个对象里是孔洞、在另一个对象里是实心，则该格为"差异格"；两个都是孔洞或都是实心的格不算差异。
- 第三步：在输出中保留两个对象的实心外形，但把所有"差异格"在它们各自对象中的对应位置都涂成 Red（即每个对象上都标出差异点），其余孔洞恢复填成该对象的外框颜色（即非差异孔洞被补实）。
- 第四步：数出差异格的总数 D，从图例条的 Grey 起始像素起，向右每隔一格放一个 Red 点，共放 D 个点，标示差异数量。
- 网格尺寸不变。

Key insight: 解题核心是把两个全等对象做"异或式"逐格比对——只有孔洞状态不一致的位置才被激活，相同的位置（无论同为孔或同为实）都被抹平；随后差异数量又被复制到图例条上，形成"空间差异图＋差异计数"双输出。
source: 取自参考题13（两个相似对象的孔洞对应/对齐）的对象配对与孔洞对齐、参考题6（把计数写成图例条上的点）的计数可视化。变异点：参考题13是用源精灵填目标孔洞，这里改为对两个全等对象做"孔洞异或"求差并把差异同时以空间标记和图例计数两种形式输出，推理从"填补对齐"变为"对称差比对＋计数",路径不同。
</new_puzzle>
