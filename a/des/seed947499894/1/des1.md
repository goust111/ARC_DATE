<new_puzzle>
description: 根据每个对象的孔洞数量从图例中查得颜色，再把对象沿其唯一开口方向平移直到其孔洞被某个同色实心障碍堵住。

Input structure:
- 背景为 Black。
- 左侧有一列垂直图例：每一行由一个数字编码（用 1 到 4 个并排的 Grey 像素表示该行的"键"，键值等于 Grey 像素的个数）和紧邻其右的一个单色实心方块（颜色为 Red、Green、Yellow、Azure 之一）组成。键值越大不一定越靠下，图例顺序随机。
- 主区域中散布若干 Blue 的封闭轮廓对象（环形/框形），每个对象内部恰好包含 1 到 4 个被背景填充的孔洞（互不连通的 Black 空腔），且每个对象的外轮廓上恰有一处单像素缺口（开口），开口朝向上、下、左、右之一。
- 主区域边缘附近散布若干单色实心方块（障碍），颜色取自图例中出现过的颜色。

Rule:
- 对每个 Blue 对象，先数出其内部孔洞个数 n，在图例中找到键值等于 n 的那一行，读取该行的方块颜色 c，这是该对象的"目标颜色"。
- 该对象沿其开口所朝方向平移：每次移动一格，直到对象的外轮廓首次接触到一个颜色为 c 的实心障碍方块为止，然后停在接触位置（紧邻但不重叠）。若沿该方向不存在颜色为 c 的障碍，则对象移动到撞上网格边界为止。
- 移动后把对象整体重新着色为目标颜色 c（原 Blue 变为 c），孔洞保持为 Black。原位置清空为背景。
- 图例与障碍保持不变。

Key insight: 孔洞数量是查图例颜色的键，而这个颜色又决定了对象沿开口方向滑动时"认哪个障碍"作为停靠点——颜色既是终点选择器又是重绘色，两层信息共用同一个图例条目。
source: 参考题16/17（用图例做颜色查表）+ 参考题20（用孔洞/形状作为键）+ 参考题14/10（沿方向滑动到障碍停止）。变异点：把"孔洞数"从形状匹配键改造为"图例查色键"，再让查得的颜色反过来决定滑动终点（同色障碍才生效），使颜色同时承担查表输出、滑动选择器、重绘色三重角色，推理路径与任何单题都不同。
</new_puzzle>

<new_puzzle>
description: 把每条彩色横条按其长度排名映射到一组同样按长度排名的竖直槽位上，并在交点处生成对应颜色的十字标记。

Input structure:
- 背景为 Black。
- 网格上半部：若干条互不重叠的水平实心线段（横条），每条颜色不同、长度不同，各自从网格左边缘出发向右延伸，竖直位置互不相同。
- 网格下半部：一条贯穿全宽的 Grey 基准线，基准线上方竖立着若干条等高的竖直短柱（槽位），每根短柱颜色不同、x 位置互不相同，但全部高度相同（仅作为位置标记）。

Rule:
- 把所有横条按长度从短到长排名，得到序号 1,2,3,...。
- 把所有竖直短柱（槽位）按 x 位置从左到右排名，得到序号 1,2,3,...。
- 第 i 短的横条被分配给第 i 左的槽位：该横条整体水平平移，使其左端对齐到该槽位的 x 列，竖直位置保持不变；同时该横条被重新着色为该槽位的原颜色。
- 完成所有横条的重定位与重着色后，对每一对"已就位横条 + 它所对应的槽位"，在槽位的 x 列与横条所在行的交点处画一个 3 像素的十字（中心加上下左右四像素，若超出网格则截断），十字颜色与该横条新颜色相同。
- Grey 基准线与槽位短柱保持不变。

Key insight: 两套对象（横条、槽位）各自独立排名后按名次配对，配对同时决定了"水平位置""颜色"和"十字位置"三件事；解题者必须先发现是按长度↔位置的双排名配对，而非按颜色或就近匹配。
source: 参考题10（按高度排名重分配到固定槽位并继承槽位颜色）+ 参考题4（在交点处生成十字/射线标记）。变异点：把竖直柱排序改为"横条长度排名 ↔ 槽位位置排名"的跨维双排名配对，并叠加一层"在配对交点画十字"的几何派生步骤，使其成为排名配对+交点生成的两层结构。
</new_puzzle>

<new_puzzle>
description: 用网格的镜像对称补全被遮挡的色块图案，再统计每种颜色被遮挡的格数，按统计结果重排一条底部图例。

Input structure:
- 背景为 Black。
- 主区域是一块具有水平与竖直双轴镜像对称的彩色图案（由 2 到 4 种颜色的色块构成）。
- 图案中有一块实心的 Maroon 矩形遮挡物，盖住了图案的一部分（被盖住的原始颜色未知，需用对称恢复）。
- 网格底部有一行图例：每种在图案中出现的颜色各占一个单像素，初始按颜色在网格中"首次出现行列"的自然顺序从左到右排列。

Rule:
- 利用图案的水平/竖直镜像对称，逐格恢复 Maroon 遮挡区域下方的原始颜色（每个被遮格的真值等于它的镜像对应格的颜色）。
- 把恢复后的完整图案写入输出主区域（Maroon 完全消失）。
- 统计在恢复过程中每种颜色被遮挡（即原来藏在 Maroon 下）的格子数量。
- 底部图例重新排列：按"被遮挡格数从多到少"将各颜色像素从左到右重新摆放（被遮挡多的排左边）；若两色被遮格数相同，则维持它们原有的相对顺序。图例像素本身的颜色不变，只是顺序改变。

Key insight: 遮挡物既要靠对称"读出"它盖住了什么，又要"数出"每种颜色各被盖了多少格，这个隐藏统计量反过来决定底部图例的排序——必须先完成对称恢复才能获得用于排序的计数。
source: 参考题11（用镜像对称恢复被实心遮挡物盖住的图案）+ 参考题10（按某统计量排名重排一组标记）。变异点：把"恢复图案"的副产物（每色被遮格数）作为新的隐藏排序键去驱动一条独立图例的重排，形成"对称恢复→隐藏计数→图例重排"的三层结构。
</new_puzzle>

<new_puzzle>
description: 从一个起点像素出发沿可达通道泛洪，找出最先到达的彩色门，再用该门的颜色给所有同色门之间的连线染色。

Input structure:
- 背景为 Orange（地板）。
- Blue 像素构成墙壁，把网格分隔成若干互相连通或隔断的房间与走廊。
- 一个唯一的 Magenta 单像素位于某个房间内，作为起点。
- 走廊或墙缝处嵌着若干"门"：每扇门是一对相隔若干格、位于同一行或同一列、颜色相同的单像素（颜色取自 Red、Green、Yellow、Azure），同色的两个像素构成一扇门的两端，不同颜色代表不同门。门像素位于地板上，可被穿过。

Rule:
- 从 Magenta 起点对地板做四连通泛洪，墙壁（Blue）阻挡，门像素视为可通行的地板。
- 在泛洪过程中记录每扇门被首次"踏入"（其任一端点被泛洪触及）的先后；只有泛洪能到达的门才算"激活"，被墙完全围死、起点泛洪到不了的门保持不变。
- 对每一扇被激活的门，在其两个同色端点之间沿它们所在的同一行/列画一条直线段（用该门颜色填充两端之间的所有地板格），把门"连通"起来。
- 未被激活的门、墙壁、起点像素保持不变；其余地板保持 Orange。

Key insight: 门是否被画线取决于它能否从唯一起点经地板泛洪抵达（墙的连通性而非直线距离决定），解题者必须先做可达性判断这一隐蔽前置，才知道哪些同色对该被连线。
source: 参考题2/7（从唯一标记做地板泛洪，墙阻挡，只有可达的对象才参与变换）+ 参考题4（连接同色像素对画线）。变异点：把"连接所有同色对"改为"只连接泛洪可达的同色对"，可达性成为是否连线的隐藏门控，叠加在连线机制之上构成两层。
</new_puzzle>

<new_puzzle>
description: 按每个对象内部小标记的指向把对象旋转到正确朝向，再依据其包含的彩色种子数把它缩放后盖到画布上对应编号的锚点格。

Input structure:
- 背景为 Black。
- 网格被一条贯穿全列的 Grey 竖直分隔线分成左右两部分。
- 左侧是若干"零件面板"，自上而下排列，每个面板含一个不规则的单色（Azure）小精灵；精灵内部嵌有一个 3 像素的指向箭头（一个中心像素加两个像素构成指向上/下/左/右之一的方向，箭头为 Red），以及若干（1 到 4 个）散布的 Yellow 种子像素。
- 右侧画布上有一条从左到右编号 1,2,3,4 的锚点行：四个等距的单像素锚点，从左到右分别为第 1、2、3、4 号位（用 Grey 单像素标出位置）。

Rule:
- 对每个左侧面板的精灵：先根据其内部 Red 箭头的指向把整个精灵旋转，使箭头统一指向"上"（即把当前箭头方向旋到向上所需的旋转角，同时旋转整个精灵形状），旋转后移除箭头像素（恢复为 Azure）。
- 数出该精灵内 Yellow 种子的个数 k（1 到 4），把旋转后的精灵整体按 k 倍整数放大（每个像素扩成 k×k 块），放大后移除种子像素（恢复为 Azure）。
- 把放大并摆正后的精灵盖到右侧画布上：以第 k 号锚点为该精灵包围盒的左上角进行放置（即种子数 k 同时决定放大倍数和落点编号）。
- 若多个精灵的 k 相同会落到同一锚点，则后处理的精灵覆盖在上层（按面板自上而下的顺序处理，靠下的覆盖靠上的）。
- 分隔线、锚点（未被覆盖处）保持不变；左侧面板区在输出中清空为背景。

Key insight: 精灵内部的两类小标记承担完全不同的职责——箭头只管把形状旋正，种子数则一身二用地同时决定放大倍数与落点编号，解题者必须分离这两类标记并理解种子数的双重作用。
source: 参考题18（面板内小标记编码旋转与落点）+ 参考题8（用嵌入标记的尺寸/数量编码缩放比例）+ 参考题15（按内部锚区对齐放置缩放精灵）。变异点：让单一标记（种子数 k）同时编码"放大倍数"和"锚点编号"，箭头独立编码旋转，三类信息从同一精灵中分层解析，构成旋转→缩放→定位的三层管道。
</new_puzzle>

<new_puzzle>
description: 把每个被框对象与框外同形状精灵配对继承颜色，再让对象按其新颜色在图例中查到的方向各自移动一步并留下拖尾。

Input structure:
- 背景为 Black。
- 主区域内有若干 Grey 的单色小对象（多格连通块），形状各异、互不重叠。
- 框外（网格四角或边缘空白处）散布若干单色实心精灵，每个精灵的形状与主区域中某一个 Grey 对象的形状全等（允许旋转/翻转），精灵颜色取自 Red、Green、Blue、Yellow。
- 网格底部有一行方向图例：每个单元是"一个颜色像素 + 紧邻其右的一个 3 像素箭头"，箭头指向上/下/左/右之一，颜色取自精灵用到的四种颜色，每种颜色恰好出现一次。

Rule:
- 对每个 Grey 对象，找到框外与它形状全等（可旋转/翻转匹配）的精灵，把该对象重新着色为该精灵的颜色。
- 在底部图例中按该新颜色查到对应的箭头方向 d。
- 把该对象沿方向 d 平移一格（不考虑碰撞，仅移动一格），并在它原来占据的每个格子上留下一条该颜色的"拖尾"像素（即移动后对象占新位置为实色，原位置保留为同色的单层残影），形成长度为 1 的运动轨迹。
- 框外精灵保持不变；图例保持不变；其余背景为 Black。

Key insight: 形状匹配只负责给对象"上色"，而上到的颜色又通过图例第二次查表决定运动方向，颜色是连接"形状匹配"与"方向查表"两层推理的唯一纽带，单看任何一层都无法定出最终位置。
source: 参考题20/15（按形状全等匹配把对象与外部精灵配对并继承其颜色）+ 参考题16/17（颜色经图例查表）+ 参考题4（留下方向性轨迹）。变异点：把形状匹配的产出（颜色）串接为方向图例的查询键，使"形状→颜色→方向→位移"成为颜色贯穿始终的两层链式推理。
</new_puzzle>
