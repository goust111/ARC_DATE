- `description`：根据封闭区域内"种子"像素的颜色，在区域边框的图例映射表中查找对应的填充图案方向，然后用种子颜色沿该方向绘制平行条纹填满整个封闭区域。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有若干由 grey 像素围成的封闭矩形区域（一像素宽的边框）。
  - 每个封闭区域内部恰好有一个孤立的"种子"像素，颜色各不相同（如 red、blue、green 等）。
  - 网格的一条边缘处有一个图例区域：图例由若干小矩形格子组成，每个格子左半部分填一种颜色，右半部分绘有该颜色对应的条纹方向示意——水平条纹（同色像素排成一行）或垂直条纹（同色像素排成一列）。

- `Rule`：
  - 识别每个 grey 边框封闭区域内部的种子像素颜色 C。
  - 在边缘图例中查找颜色 C 对应的条纹方向（水平或垂直）。
  - 将该封闭区域内部所有背景像素用颜色 C 按照图例指定的方向绘制间隔条纹：若为水平方向，则从区域内部顶行开始，奇数行填充颜色 C、偶数行保持背景色；若为垂直方向，则从区域内部最左列开始，奇数列填充颜色 C、偶数列保持背景色。种子像素本身被条纹覆盖（视为区域内普通像素）。
  - Grey 边框和图例区域保持不变。

- `Key insight`：解题者需要先发现边缘图例是一张"颜色→条纹方向"的映射表，再将每个区域内种子的颜色与图例匹配以确定填充方式——仅靠种子颜色或仅靠区域形状都无法推断出正确的输出。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的同色碎片按颜色分组拼合成完整矩形，拼合后矩形的放置位置由同色"锚点"标记决定，锚点成为拼合矩形的指定角。

- `Input structure`：
  - 背景为主色（black）。
  - 每种前景色恰好出现两类对象：(1) 若干分散的小型 4-连通碎片，它们的像素总面积恰好能拼成一个整数边长的实心矩形；(2) 一个孤立的单像素"锚点"。
  - 不同颜色的碎片和锚点互不重叠、互不相邻。
  - 每种颜色的锚点位于其所有碎片的包围盒的某个角方向的外侧（左上、右上、左下、右下之一）。

- `Rule`：
  - 对每种前景色，统计该颜色所有碎片的总像素数 N，将 N 分解为最接近正方形的矩形尺寸（即选择使长宽之差最小的因子对 a×b，a≤b）。
  - 找到该颜色的锚点像素位置，判断锚点相对于碎片群包围盒中心的方位（左上、右上、左下、右下）。
  - 以锚点为对应角，绘制 a×b 的实心矩形（例如锚点在左上方位则锚点为矩形左上角）。
  - 清除该颜色原有的所有碎片像素。

- `Key insight`：解题者需要完成两步非平凡推理：第一步是发现碎片总面积决定矩形尺寸（需要数像素并找到最接近正方形的因子分解）；第二步是发现孤立锚点的方位角决定矩形的对齐角——两层信息缺一不可。
</new_puzzle>

- `description`：在网格中找到被"遮罩色"部分覆盖的隐藏形状，利用网格边缘的"形状字典"识别每个隐藏形状的完整轮廓，然后用该形状字典中对应的输出颜色替换遮罩区域，还原完整形状。

- `Input structure`：
  - 背景为主色（black）。
  - 网格主体区域包含若干前景色形状，其中一些形状被 grey 像素部分遮盖——grey 像素覆盖了形状的某些位置，使形状看起来不完整。
  - 网格的顶部或底部边缘有一排"形状字典"：每个字典条目是一个小矩形框，内部绘有一个完整的小型模板形状（用某种颜色绘制），旁边紧挨一个单像素的"输出色标"。
  - 主体区域中每个被遮盖的形状，其可见部分（非 grey 像素）与字典中某个模板形状的子集匹配，且颜色相同。

- `Rule`：
  - 在形状字典中读取每个模板形状及其对应的输出色标颜色。
  - 对主体区域中每个含有 grey 遮盖像素的前景形状，将其可见像素与字典模板逐一比对，找到唯一匹配的模板。
  - 根据匹配模板的完整轮廓，将该形状中被 grey 覆盖的位置还原为模板形状的像素，但还原的像素使用字典中对应的输出色标颜色（而非原始形状颜色）。
  - 形状的原始可见像素保持原色不变；字典区域在输出中移除（替换为背景色）。

- `Key insight`：解题需要三层推理——首先识别边缘字典的结构（模板+色标配对），然后通过部分可见像素与模板的形状匹配来确定被遮盖的完整形状，最后用色标颜色（而非原色）填回遮盖区域，这三步环环相扣。
</new_puzzle>

- `description`：每个前景对象沿其内部"箭头标记"所指方向平移，平移距离等于同色边框围栏内的空心孔洞数量。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有若干不同颜色的前景对象，每个对象由两部分组成：(1) 一个主体形状（任意 4-连通形状，面积 ≥ 3 像素）；(2) 主体形状内部嵌有一个由三个同色像素组成的 L 形"箭头标记"，箭头标记与主体同色，其 L 形的朝向指示一个基本方向（上、下、左、右——L 形的长边指向的方向即为移动方向）。
  - 网格中另有若干与前景对象同色的单像素宽矩形边框"围栏"（边框内部为背景色或包含背景色的孔洞）。每种颜色恰好有一个围栏与之对应。
  - 围栏内部可能有 0 到若干个由背景色构成的独立孔洞（4-连通背景色区域，被围栏边框完全包围）。

- `Rule`：
  - 对每种前景色，找到该颜色的主体对象和围栏。
  - 读取主体对象内部 L 形箭头标记的朝向，确定平移方向。
  - 数围栏内部的背景色孔洞数量 K。
  - 将主体对象（含箭头标记）沿箭头方向平移 K 个像素。原始位置清为背景色。
  - 围栏保持不变。

- `Key insight`：解题者需要同时破解两个独立编码：对象内部的 L 形标记编码了移动方向，而同色围栏中的孔洞数量编码了移动距离——方向和距离来自完全不同的视觉线索源，必须分别识别并关联到同一颜色才能得出正确变换。

- `Input structure`：

  - 网格中有若干 azure 色的单像素宽 45 度对角线段，充当"镜面"（每段长度 ≥ 2 像素，方向为左上-右下或左下-右上）。
  - 网格边缘上有若干不同颜色的孤立"信号源"像素（非 azure、非背景色），每个信号源位于网格的上、下、左、右某一条边上。

- `Rule`：
  - 每个信号源从其位置向网格内部发射一条垂直于所在边的直线射线（上边缘的向下，左边缘的向右，依此类推）。
  - 射线沿直线前进，遇到 azure 镜面时发生 90 度反射：遇到左上-右下方向（\）的镜面，水平射线变为垂直、垂直射线变为水平（类似光线反射）；遇到左下-右上方向（/）的镜面同理反射。
  - 射线持续前进直到命中一个 grey 目标格或到达网格边界（若到达边界则该射线无效果）。
  - 若射线命中 grey 目标格，将该目标格重新着色为射线信号源的颜色。
  - 镜面、信号源、以及未被命中的目标格保持不变。

- `Key insight`：解题者必须先理解 azure 对角线段是镜面而非障碍物，然后在心理上模拟每条射线的反射路径——关键难点在于发现射线不是被镜面阻挡而是被反射转向，这与直觉中"碰到东西就停下"的模式完全不同。

- `description`：在由隔板分割的多个子区域中，每个子区域内的彩色像素"投票"决定该区域的统一填充色，但投票规则由隔板颜色隐含编码：一种隔板色表示"多数色获胜"，另一种隔板色表示"少数色获胜"。

- `Input structure`：
  - 背景为主色（black）。
  - 网格被两种不同颜色的单像素宽直线隔板分割成若干矩形子区域。隔板颜色仅有两种（如 grey 和 maroon），每条隔板完整贯穿网格的一行或一列。
  - 每个子区域内部散布着若干彩色像素（非背景、非隔板色），每个区域内恰好有两种不同的前景色，数量可能不等。

- `Rule`：
  - 确定包围每个子区域的隔板颜色。若区域四边的隔板（或网格边界）中，隔板颜色以某一种为主（出现次数更多的隔板色），则以该主隔板色决定投票规则。
  - 若主隔板色为 grey：该区域采用"多数规则"——区域内像素数较多的前景色获胜，整个区域内部全部填充为该色。
  - 若主隔板色为 maroon：该区域采用"少数规则"——区域内像素数较少的前景色获胜，整个区域内部全部填充为该色。
  - 若两种前景色数量相等，则保留靠近区域左上角的那种颜色。
  - 隔板像素保持不变。

- `Key insight`：解题者首先需要发现区域内多色像素是一种"投票"，然后需要发现不同颜色的隔板编码了相反的投票规则（多数 vs 少数）——第二层发现是关键的隐蔽机制，仅观察单个区域无法区分两种规则，必须跨区域对比才能归纳出隔板颜色与投票逻辑的关联。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每对同色标记像素用直线连接，连线在交叉点处按照"先水平后垂直"的绘制优先级叠加颜色，交叉点最终显示垂直线段的颜色。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有若干种前景色，每种颜色恰好出现两个孤立像素作为"端点标记"。
  - 每对同色端点要么共享同一行、要么共享同一列、要么既不同行也不同列。
  - 端点之间不存在其他前景像素。

- `Rule`：
  - 对每对同色端点，用该颜色绘制连接它们的曼哈顿 L 形路径：先从一个端点水平画到与另一个端点同列的位置，再垂直画到另一个端点。若两端点同行则直接画水平线，同列则直接画垂直线。
  - 当多条路径经过同一像素时，该像素的颜色由最后绘制的垂直线段决定（垂直段覆盖水平段）。
  - 绘制顺序：各颜色之间的绘制不影响最终结果，因为覆盖规则始终是"垂直段优先于水平段"——任何像素若同时被某条路径的水平段和另一条路径的垂直段经过，显示垂直段的颜色。
  - 端点像素保持其原色不变。

- `Key insight`：解题者需要先发现每对同色点通过 L 形折线连接（而非直线），然后发现交叉点的颜色不是简单叠加或先后覆盖，而是由"垂直段始终优先于水平段"这一隐含规则决定——必须通过观察多个交叉点的颜色来归纳出这条方向性优先规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中的每个彩色对象根据其所在象限被施加不同的变换（旋转 0°/90°/180°/270°），象限与旋转角度的对应关系由网格中心的"罗盘"图案编码。

- `Input structure`：
  - 背景为主色（black）。
  - 网格尺寸为奇数×奇数，中心有一个 3×3 的"罗盘"图案：罗盘的中心像素为 grey，上下左右四个相邻像素各为不同颜色（从 red、blue、green、yellow 中选四种），四个对角像素为背景色。
  - 网格以中心行和中心列为界分成四个象限（不含中心行列本身）。
  - 每个象限内有恰好一个由某种非背景、非罗盘色的前景色构成的小型 4-连通对象（面积 ≤ 6 像素）。

- `Rule`：
  - 读取罗盘图案：中心像素上方的颜色对应"上"方向，右方对应"右"，下方对应"下"，左方对应"左"。
  - 建立象限到旋转角度的映射：罗盘上方颜色指示"不旋转"（0°），罗盘右方颜色指示"顺时针 90°"，罗盘下方颜色指示"180°"，罗盘左方颜色指示"逆时针 90°"（即顺时针 270°）。但这些颜色不直接对应象限——而是每个象限边界上（中心行或中心列上）与该象限相邻的两个罗盘臂颜色中，位于顺时针方向较后的那个颜色决定该象限的旋转。
  - 具体地：右上象限由罗盘"右"臂颜色决定旋转角度；右下象限由罗盘"下"臂颜色决定；左下象限由罗盘"左"臂颜色决定；左上象限由罗盘"上"臂颜色决定。
  - 对每个象限内的对象，以其自身中心为旋转中心，施加对应角度的旋转，结果留在原象限内。

- `Key insight`：解题者首先要识别中心 3×3 图案是一个方向编码罗盘，然后要建立罗盘臂颜色→旋转角度→象限的三重映射关系——关键难点在于罗盘臂与象限的对应规则本身需要从样例中归纳，不能仅靠空间直觉猜出。
</new_puzzle>
