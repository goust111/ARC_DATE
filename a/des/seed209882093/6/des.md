<new_puzzle>
- `description`：根据每个封闭区域内部"种子"像素的颜色，从区域的边框颜色图例中选取对应的填充色，将区域内的背景像素全部涂满。
- `Input structure`：
  - 背景为 Black。
  - 网格中存在若干由不同颜色绘制的一像素宽封闭矩形边框（例如 Red 边框、Blue 边框、Green 边框），每个边框内部是 Black 背景加上恰好一个单像素"种子"。
  - 网格的某一行或某一列是"图例行/列"：图例由交替出现的颜色对组成，每对由一个边框色像素紧邻一个填充色像素构成（例如 Red-Yellow 表示 Red 边框区域应填充 Yellow）。
  - 种子像素的颜色不一定与边框颜色或图例中的颜色相同——种子颜色另有用途（见规则）。
- `Rule`：
  - 第一步：识别图例行/列，解析出"边框颜色 → 填充颜色"的映射表。
  - 第二步：对每个封闭矩形边框，通过其边框颜色在映射表中查找对应的填充颜色。
  - 第三步：检查边框内部种子像素的颜色——如果种子颜色与边框颜色相同，则将边框内所有 Black 像素填充为映射表指定的填充颜色；如果种子颜色与边框颜色不同，则不填充该区域，保持 Black。
  - 图例行/列本身在输出中被清除为 Black。
- `Key insight`：图例提供了边框色到填充色的间接映射，但种子像素充当"开关"——只有种子颜色与自己所在边框颜色匹配时，该映射才被激活。解题者需要同时发现图例的配对规则和种子的门控作用，这两层逻辑缺一不可。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片按照它们在"模板格"中对应位置的行列坐标排序，重新拼接成一幅紧凑的马赛克图。
- `Input structure`：
  - 背景为 Black。
  - 网格左上角有一个小型 N×M 的"模板格"，由 Grey 网格线分隔成 N×M 个单元格，每个单元格恰好一像素，颜色各不相同（使用 Red、Blue、Green、Yellow、Orange、Magenta、Azure、Maroon 中的若干种）。
  - 网格其余区域散布着若干矩形碎片，每个碎片是一个小的彩色图案块（尺寸不一，但所有碎片尺寸相同）。每个碎片的左上角像素颜色恰好对应模板格中某个单元格的颜色（颜色唯一标识位置）。
  - 碎片之间互不重叠，但位置随机。
- `Rule`：
  - 第一步：读取模板格，建立"颜色 → (行, 列)位置"的映射。
  - 第二步：对每个碎片，通过其左上角像素颜色在模板格中查找对应的 (行, 列) 位置。
  - 第三步：按照模板格指定的行列位置，将所有碎片无间隙地拼接成一个大矩形图案。碎片之间不留间距，行列顺序与模板格中颜色位置严格对应。
  - 输出仅包含拼接好的大矩形，不包含模板格。
- `Key insight`：模板格不是装饰，而是一个位置编码图例——每个碎片左上角的颜色是它在最终拼图中的"地址"。解题者需要先发现碎片角落颜色与模板格的对应关系，再发现模板格定义了拼接布局。
</new_puzzle>

<new_puzzle>
- `description`：每个色块的形状定义了一个"印章"，该印章在同色标记点阵列的每个位置重复盖印，但印章的朝向由标记点相对于色块原始位置的象限决定。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干小型彩色连通图案（4-连通），每个图案使用唯一颜色（如 Red、Green、Blue 等），形状不对称（非正方形、非对称），包含 3-6 个像素。
  - 对于每种颜色，除了该图案本身之外，网格中还散布着若干同色的单像素标记点。
  - 标记点不与图案相邻，且标记点之间也互不相邻。
- `Rule`：
  - 第一步：对每种颜色，识别出连通图案（印章）和所有同色单像素标记点。
  - 第二步：计算印章的视觉中心（像素坐标的平均值取整）。
  - 第三步：对每个标记点，判断它相对于印章中心所在的象限：右下 → 原始朝向；右上 → 顺时针旋转 90°；左上 → 旋转 180°；左下 → 逆时针旋转 90°。（如果标记点与印章中心同行，视为右侧；同列视为下侧。）
  - 第四步：以标记点为锚点（对应印章中心位置），将按对应朝向旋转后的印章盖印到网格上。印章像素覆盖该位置的 Black 像素；不覆盖已有颜色的像素。
  - 原始印章图案和标记点在输出中保留。
- `Key insight`：单独看盖印操作并不难猜，但印章朝向的规则是隐蔽的——它不取决于标记点附近的局部信息，而取决于标记点与印章原始位置之间的全局空间关系（象限）。解题者需要先发现"印章在标记点处重复"的基本规则，再发现不同位置盖出的图案朝向不同，最后归纳出象限决定旋转角度的隐藏规律。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中由边框围成的多个"房间"，根据房间之间共享墙壁上的"门"（缺口）的数量，对房间内部进行分层染色。
- `Input structure`：
  - 背景为 Black。
  - 网格中有一个由 Grey 像素绘制的连通网格状结构，将画布分割成若干矩形"房间"。Grey 线条宽度为一像素。
  - 某些相邻房间之间的 Grey 墙壁上有一到多个单像素宽的缺口（"门"）——即墙壁上某处的 Grey 像素被替换为 Black，形成一个通道。
  - 网格的最外圈 Grey 边框上没有缺口（房间不通向外部）。
  - 每个房间内部完全为 Black。
- `Rule`：
  - 第一步：识别所有矩形房间以及每个房间四面墙壁上的门的总数。
  - 第二步：根据门的数量确定填充颜色，映射规则为：0 个门 → Red，1 个门 → Blue，2 个门 → Green，3 个门 → Yellow，4 个门或更多 → Orange。
  - 第三步：将每个房间内部的所有 Black 像素填充为对应颜色。Grey 墙壁和门保持不变。
- `Key insight`：表面上看每个房间的颜色似乎随意，但实际上颜色编码了房间的"连通度"——即门的数量。解题者需要先注意到墙壁上的微小缺口是有意义的，再发现门的数量与填充颜色之间存在固定映射。关键难点在于缺口只有一像素宽，容易被忽略，而且需要对每个房间的所有四面墙逐一检查。门的数量计数本身不难（通常 0-4 个），但"发现门的存在并将其数量与颜色关联"这一归纳过程是核心推理层。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象根据自身包含的孔洞数量，选择性地保留、删除或复制自身，复制规则由网格底部的"规则条"编码。
- `Input structure`：
  - 背景为 Black。
  - 网格中散布着若干互不接触的单色连通前景对象（4-连通），每个对象使用不同颜色（Red、Blue、Green、Yellow 等）。
  - 某些对象内部包含被完全包围的 Black 区域（"孔洞"），孔洞数量从 0 到 3 不等。每个孔洞是一个 4-连通的 Black 区域，完全被该对象的像素环绕。
  - 网格底部有一行"规则条"，与网格同宽，由 Maroon 和 Black 像素组成。规则条被等分为四段（宽度相等），从左到右分别对应孔洞数 0、1、2、3。每段内部的 Maroon 像素排列成 0 到 3 个不相邻的小竖条（每个竖条宽一像素、高与规则条等高），竖条的数量表示对应孔洞数的对象应在输出中出现的副本数。
- `Rule`：
  - 第一步：解析规则条——将其等分为四段，数出每段中 Maroon 竖条的数量，得到映射：0 个孔洞 → k₀ 个副本，1 个孔洞 → k₁ 个副本，2 个孔洞 → k₂ 个副本，3 个孔洞 → k₃ 个副本。副本数范围为 0-3。
  - 第二步：对每个前景对象，数出其内部孔洞的数量。
  - 第三步：根据映射确定该对象的副本数。如果副本数为 0，则删除该对象（变为 Black）；如果为 1，保持原位不变；如果为 2，则在对象正下方（与原件之间留一行 Black 间隔）放置一个相同的副本；如果为 3，则在正下方依次堆叠两个额外副本，每个副本之间留一行 Black 间隔。
  - 第四步：规则条本身在输出中被清除为 Black。
- `Key insight`：解题者面临两层归纳：第一层是发现规则条的编码方式（四段分区与竖条计数的含义），第二层是发现对象的孔洞数量决定了它的"命运"（保留、删除或复制）。仅观察对象的出现和消失不足以推断规则——必须同时解读规则条才能建立完整的映射关系。
</new_puzzle>
