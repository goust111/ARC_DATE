<new_puzzle>
description：根据封闭区域内种子像素的颜色与区域之间的共享边界关系，逐步向无种子区域传播颜色，完成整张网格的区域着色。

Input structure：
- 背景色为 black。网格中有一种前景色（如 grey）绘制的单像素宽直线段（水平或垂直），这些线段将网格分割成若干互不相连的矩形区域。
- 部分区域内恰好包含一个彩色种子像素（颜色各不相同，可能使用 red、blue、green、yellow、orange 等）。
- 其余区域内部全为 black，没有种子像素。
- 每个种子颜色在整张网格中只出现一次。

Rule：
- 第一步：识别所有被 grey 线段围成的矩形区域，以及每个区域内是否包含种子像素。
- 第二步：对于每个无种子区域，检查它与哪些已着色区域共享边界（即两个区域之间被同一段 grey 线段隔开，共享的边界长度等于该线段中两区域直接相邻的像素行数或列数）。
- 第三步：将无种子区域填充为与其共享边界最长的已着色邻居区域的种子颜色。若最长边界有平局，则选择种子像素距离该共享边界更近（像素步数更少）的那个颜色。
- 第四步：新着色的区域在下一轮中视为已着色区域，重复第二、三步，直到所有区域都被着色。
- 最终输出中，grey 线段保持不变，每个区域内所有 black 像素被替换为该区域确定的颜色。

Key insight：这不是简单的泛洪填充——传播顺序由共享边界长度决定，解题者必须先识别区域邻接关系及边界长度，再按优先级逐层传播颜色。平局时"种子到边界距离"的 tie-break 规则需要第二层推理才能发现。
</new_puzzle>

<new_puzzle>
description：将网格中散落的灰色形状按其内部孔洞数量分组，然后将同组形状排列到对应颜色图例所指示的目标行中，排列顺序由形状面积从小到大决定。

Input structure：
- 背景色为 black。网格分为左右两个区域，由一条垂直的 maroon 分隔线隔开。
- 左侧区域：散布着若干灰色（grey）形状，形状为 4-连通的不规则多边形，大小和孔洞数量各不相同。孔洞定义为完全被该形状像素包围的 black 连通区域。
- 右侧区域：在最左列有若干彩色方块（如 red、blue、green），每个方块占一个像素，纵向排列，它们之间间隔若干行。每个彩色方块右侧同一行上有一排与该方块孔洞数对应的小圆点（同色），圆点数量即为该颜色代表的孔洞数（例如 red 方块右侧有 0 个圆点表示 0 个孔洞，blue 方块右侧有 1 个圆点表示 1 个孔洞，green 方块右侧有 2 个圆点表示 2 个孔洞）。

Rule：
- 第一步：读取右侧颜色图例，建立"孔洞数 -> 颜色"的映射关系。
- 第二步：对左侧每个灰色形状，计算其孔洞数量（被形状完全围住的 black 区域个数）。
- 第三步：根据孔洞数将灰色形状分组，每组对应图例中的一种颜色。
- 第四步：输出网格中，右侧区域的每个颜色图例行变成一个目标行区域。将对应组的灰色形状按面积（像素数）从小到大，从左到右依次排列在该颜色行中，形状之间间隔 1 列。排列时形状顶部对齐该行顶部。
- 第五步：所有形状重新着色为对应图例颜色。左侧区域清空为 black。

Key insight：需要两步独立的非平凡推理——第一步是通过图例中圆点数量破译"孔洞数->颜色"的编码规则；第二步是发现同组形状按面积排序的规律。仅看单个样例容易遗漏排序规则。
</new_puzzle>

description：在被部分遮挡的棋盘格图案中，利用可见方格推断遮挡物下方的棋盘相位，然后根据遮挡物颜色在图例中的指示决定是还原棋盘还是用遮挡物颜色永久覆盖。

Input structure：
- 网格呈现一个由两种颜色（如 azure 和 yellow）交替组成的棋盘格图案，每个格子大小为 NxN（N 通过观察可得，通常为 2 或 3）。
- 棋盘上放置了若干矩形遮挡物，每个遮挡物是一个实心单色矩形（使用 red、green、blue 等颜色），完全覆盖了其下方的棋盘格子。
- 在网格的某个角落（如右下角），有一个小的颜色图例区域，背景为 black，其中列出了每种遮挡物颜色对应的操作标记——标记为该颜色像素组成的一行，像素数量为 1 表示"完全移除该遮挡物，还原下方棋盘"，像素数量为 2 表示"移除遮挡物，但将下方棋盘格子全部替换为该遮挡物的颜色"。

- 第一步：从可见的棋盘区域推断完整棋盘的相位（即哪些位置应该是 azure，哪些应该是 yellow），包括被遮挡区域下方的原始颜色。
- 第二步：读取角落图例，确定每种遮挡物颜色的处理方式——像素数为 1 表示还原，像素数为 2 表示永久覆盖。
- 第三步：对每个遮挡物，根据其颜色在图例中的指示执行操作——要么还原为下方棋盘色，要么用遮挡物颜色永久覆盖该区域。
- 输出网格尺寸与输入相同，图例区域保持不变。

Key insight：第一层推理需要从棋盘的可见部分推断遮挡区域下方的原始图案（相位恢复），第二层推理需要破译图例中的编码来决定每个遮挡物是"揭开"还是"印上"——两种操作产生截然不同的输出，且必须正确解读图例才能区分。
</new_puzzle>

description：根据框架内部的彩色锚点像素匹配外部精灵模板，将模板旋转到锚点所指示的朝向后印入框架，模板的旋转方向由锚点在其所在格子中的相对位置编码。

Input structure：
- 背景色为 black。网格中有一个较大的矩形框架，由 maroon 颜色的单像素边框绘制，内部填充为 black。
- 框架内部被隐含的等距网格线划分为若干大小相同的方格（网格线不可见，需通过锚点位置推断）。部分方格中恰好包含一个彩色像素（锚点），锚点的颜色有多种（如 red、blue、green 等），且锚点在方格内的位置不固定——可能在方格的上边中点、右边中点、下边中点或左边中点。
- 框架外部：每种锚点颜色对应一个小型精灵模板（由该颜色绘制的连通形状），模板具有明确的"上方"朝向（即模板整体形状不对称，可以区分上下左右）。每个模板内恰好有一个像素位于其边界框的上边中点位置，作为默认锚定点。

Rule：
- 第一步：识别框架内部的隐含方格划分（通过观察多个锚点的坐标，发现它们的行列间距呈等间隔分布，从而推断方格大小）。
- 第二步：确定每个锚点在其所属方格内的相对位置——位于方格的上边中点、右边中点、下边中点或左边中点。
- 第三步：锚点在方格内的位置编码了旋转角度——上边中点 = 0 度（不旋转），右边中点 = 顺时针 90 度，下边中点 = 180 度，左边中点 = 顺时针 270 度。
- 第四步：根据锚点颜色找到对应的外部精灵模板，将模板按锚点指示的角度旋转。
- 第五步：将旋转后的模板印入框架，使模板的锚定点（旋转后对应的位置）与框架内锚点像素对齐。模板像素覆盖框架内的 black 区域。
- 若多个模板有重叠，后处理的模板覆盖先前的（处理顺序为从左到右、从上到下扫描锚点）。

Key insight：解题者必须完成三层推理——首先发现框架内存在隐含的方格划分（通过多个锚点的间距推断），然后发现锚点在方格内的偏移位置编码了旋转角度（这一层最为隐蔽，需要对比多个样例才能归纳），最后将模板匹配、旋转并对齐印入。
</new_puzzle>

description：将散落在网格中的碎片拼入一个有缺口的矩形拼图中，每个碎片的目标位置由其颜色边框与拼图缺口边框的颜色匹配决定，碎片需要翻转或旋转以使其形状恰好填满对应缺口。

Input structure：
- 背景色为 black。网格中央有一个较大的矩形区域，内部填充为 grey，但其中有若干不规则形状的缺口（缺口区域为 black）。
- 每个缺口的边缘像素（即缺口旁边的 grey 像素）被替换为一种独特的颜色（如 red、blue、green 等），形成彩色边框，每个缺口的边框颜色不同。
- 在矩形区域外部，散布着若干小型碎片形状。每个碎片由两部分组成：内部填充为 grey，边框为某种颜色（与某个缺口的边框颜色相同）。碎片的形状与其对应缺口的形状全等，但可能经过了 90/180/270 度旋转或水平翻转。

Rule：
- 第一步：识别中央矩形中的所有缺口，提取每个缺口的形状轮廓及其彩色边框颜色。
- 第二步：对于每个外部碎片，通过边框颜色匹配找到其对应的缺口。
- 第三步：确定需要对碎片施加何种变换（旋转 0/90/180/270 度，可能附加水平翻转）才能使碎片的形状与缺口完全吻合。每个碎片恰好有一种变换可以匹配。
- 第四步：将变换后的碎片填入缺口。在输出中，缺口区域被 grey 填充，缺口的彩色边框恢复为 grey（即整个矩形变为完整的纯 grey 矩形）。外部碎片从网格中移除（变为 black）。

Key insight：颜色匹配是第一层推理（边框颜色将碎片与缺口配对），但真正的难点在第二层——必须判断每个碎片需要哪种几何变换才能嵌入缺口。由于碎片形状不规则，简单的视觉旋转判断并不容易，解题者需要仔细比对碎片与缺口的轮廓细节。
</new_puzzle>

<new_puzzle>
description：网格中多个同色连通区域各自包含一个方向标记像素，根据标记指示的方向将每个区域整体平移，平移距离等于该区域在垂直于平移方向上的跨度（宽或高），区域重叠时按面积大小决定遮挡关系。

Input structure：
- 背景色为 azure。网格中散布着若干彩色连通形状（4-连通），每个形状使用独特的颜色（如 red、green、blue、yellow 等）。
- 每个形状内部恰好有一个像素颜色为 maroon，该像素是方向标记。方向标记在形状边界框内的相对位置编码了平移方向：位于边界框顶边内侧 = 向上，底边内侧 = 向下，左边内侧 = 向左，右边内侧 = 向右。"内侧"指该标记像素紧贴边界框的对应边（即该像素所在行等于边界框的最小行则为顶边，等于最大行则为底边，所在列等于最小列则为左边，等于最大列则为右边）。

Rule：
- 第一步：识别每个彩色形状及其内部的 maroon 方向标记像素。
- 第二步：根据标记在形状边界框中的位置确定平移方向（顶边=上、底边=下、左边=左、右边=右）。
- 第三步：计算平移距离——等于该形状在垂直于平移方向上的跨度。即：若平移方向为上或下，则距离 = 形状边界框的宽度（列数）；若平移方向为左或右，则距离 = 形状边界框的高度（行数）。
- 第四步：将每个形状沿确定的方向平移确定的距离（maroon 标记像素在平移后恢复为该形状的颜色，即标记消失）。
- 第五步：若平移后多个形状占据同一像素，面积（像素数）较大的形状在上层（保留其颜色），较小的被遮挡。
- 超出网格边界的部分被裁剪。

Key insight：第一层推理需要发现 maroon 像素在边界框中的位置编码了方向（而不是直觉上以为的"朝 maroon 像素方向移动"），第二层推理需要发现平移距离与形状在正交方向上的跨度相关——这个"正交跨度决定距离"的规则需要跨多个样例比较才能归纳出来。
</new_puzzle>

<new_puzzle>
description：在网格中找到被噪声像素污染的多个矩形轮廓，修复轮廓并根据每个矩形的面积等级用图例颜色填充其内部。

Input structure：
- 背景色为 black。网格中有若干矩形轮廓，每个轮廓用同一颜色（grey）的单像素线段绘制，但部分线段像素被随机删除（产生缺口），同时有少量相同颜色的噪声像素散布在非轮廓位置。
- 网格某一边（如底部两行）有一条颜色图例带：从左到右排列若干彩色方块（如 red、blue、green、yellow），每个方块大小为 2x2，方块之间间隔 1 列，排列顺序代表面积从小到大的等级。

Rule：
- 第一步：在 grey 像素中区分矩形轮廓像素和噪声像素。判定方法：属于某个矩形边的像素，其同行或同列上应存在足够多的共线 grey 像素形成线段证据（即同一行或同一列上有多个 grey 像素近似构成一条直线段）。孤立的或不与任何矩形边共线的 grey 像素为噪声。
- 第二步：修复每个矩形——根据检测到的水平和垂直线段端点，补全缺失的轮廓像素，形成完整矩形边框。删除所有噪声像素。
- 第三步：计算每个修复后矩形的内部面积（即矩形内部的行数乘以列数，不含边框）。
- 第四步：将矩形按内部面积从小到大排序，第 k 小的矩形对应图例中从左到右第 k 个颜色。
- 第五步：用对应颜色填充每个矩形的内部区域。矩形边框保持 grey。图例带保持不变。

Key insight：第一层推理是从带噪声的像素中重建矩形轮廓（需要发现"共线证据"的判定准则），第二层推理是发现图例颜色的排列顺序对应面积的排序等级（而非直接对应某个固定面积值），需要跨样例对比才能确认排序规则。
</new_puzzle>
