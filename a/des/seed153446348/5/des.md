- `description`：根据框架内嵌套小方块的堆叠层级关系，将内层方块的颜色向外层框架传播，同时依据嵌套深度决定填充方式（实心或条纹）。

- `Input structure`：
  - 背景色为 black。
  - 网格上散布若干同心嵌套的矩形框架组。每组由 2~4 层矩形框架嵌套而成，每层框架用不同的非背景色绘制（1 像素宽边框）。
  - 最内层（最深层）不是框架，而是一个 1×1 或 2×2 的实心小方块，颜色与所有外层框架颜色不同。
  - 各嵌套组之间在网格上互不重叠，彼此间距至少 2 个像素。

- `Rule`：
  - 第一层推理——确定嵌套深度与内核颜色：对每个嵌套组，从外向内识别框架层数 D（不含最内层小方块），并记录最内层小方块的颜色 C。
  - 第二层推理——根据嵌套深度选择填充模式：若 D 为奇数（1 层或 3 层框架），则用颜色 C 将该组最外层框架的整个内部区域（含所有内层框架和小方块）全部实心填充；若 D 为偶数（2 层或 4 层框架），则用颜色 C 在最外层框架内部绘制水平条纹——从框架内部第一行开始，奇数行（第 1、3、5…行）填充颜色 C，偶数行保持 black。
  - 所有组的最外层框架边框本身保持原色不变。

- `Key insight`：解题者必须先识别嵌套层级结构并计数框架层数，然后发现奇偶层数对应两种截然不同的填充模式（实心 vs 条纹），而填充所用的颜色始终来自最深层的小方块——这形成了"结构解析→奇偶分类→颜色传播"的三层推理链。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色箭头形状按其指向方向归类，再根据同组箭头的数量决定输出区域中对应方向扇区的填充层数。

- `Input structure`：
  - 背景色为 black。
  - 网格上散布若干小型箭头形状（每个箭头占约 3×3 到 5×5 的区域）。箭头由一种非背景色绘制，形状为一个三角形尖端加一条短尾线，明确指向上、下、左、右四个方向之一。具体绘制方式：以"向右箭头"为例，在 3×3 区域中，中间行三格全填色，第一行第三格填色，第三行第三格填色，形成 `▷` 形状；其他方向依此旋转。
  - 每个箭头的颜色可以是 red、blue、green、yellow 中的任意一种。
  - 网格右下角有一个用 grey 绘制的小正方形标记（3×3 实心），作为输出锚点。

- `Rule`：
  - 第一层推理——按方向分组计数：识别所有箭头，按指向方向分为四组（上、下、左、右），统计每组箭头的数量 N。
  - 第二层推理——确定每组的代表色：每个方向组内，找出出现次数最多的颜色作为该方向的代表色（题目保证每组内恰好有一个众数颜色）。
  - 第三层推理——构建输出十字图案：以 grey 标记的位置为中心，向上、下、左、右四个方向各延伸 N 个像素（N 为该方向组的箭头总数），用该方向的代表色填充这些像素。四个方向的射线共同形成一个彩色十字。grey 中心标记本身保持不变。

- `Key insight`：箭头的朝向决定它属于哪个方向组，组内箭头数量决定射线长度，而组内的众数颜色决定射线颜色——解题者需要同时归纳方向分类、计数映射和颜色投票三个独立规则，且这三者缺一不可才能还原输出。
</new_puzzle>

<new_puzzle>
- `description`：在被彩色网格线分割的区域中，根据每个区域的边界接触颜色种类数选择性地镜像翻转区域内容。

- `Input structure`：
  - 背景色为 black。
  - 网格被若干条水平和垂直的单像素宽彩色线分割成矩形区域（类似窗格）。这些分割线使用 2~4 种不同颜色（如 red、blue、green、yellow），每条线整条为同一颜色。
  - 每个矩形区域内部包含一个由 grey 绘制的小型不对称图案（如 L 形、T 形、阶梯形等），占据区域内部的部分像素。

- `Rule`：
  - 第一层推理——识别边界颜色集合：对每个矩形区域，检查其四条边界（上、下、左、右）所接触的分割线颜色。位于网格边缘而没有分割线的边界不计入。收集该区域接触到的不同颜色种类数 K。
  - 第二层推理——根据 K 选择变换：
    - K = 1（所有接触的分割线同色）：区域内容不变。
    - K = 2（接触两种颜色的分割线）：将区域内容水平镜像翻转（左右翻转）。
    - K = 3（接触三种颜色的分割线）：将区域内容垂直镜像翻转（上下翻转）。
    - K = 4（接触四种颜色的分割线）：将区域内容旋转 180°。
  - 分割线本身保持不变，仅区域内部的 grey 图案被变换。

- `Key insight`：分割线不仅起到划分区域的作用，其颜色多样性还编码了每个区域的变换类型——解题者需要先发现"边界颜色种类数"这个隐蔽属性，再将其映射到四种不同的几何变换上，形成"结构分析→属性提取→变换选择"的推理链。
</new_puzzle>

- `description`：识别网格中由屏障围成的封闭走廊，根据走廊入口处的色标确定填充色，再根据走廊内部拐弯次数决定填充的起止范围。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干用 grey 绘制的 1 像素宽墙壁，这些墙壁围成若干条宽度恰好为 1 像素的弯曲走廊（走廊可以有直角拐弯，但宽度始终为 1）。每条走廊的两端各有一个开口通向网格边缘或连接到空旷区域。
  - 每条走廊的其中一个开口处（紧邻开口外侧 1 像素）放置一个彩色标记像素（颜色为 red、blue、green、yellow、orange 之一），标记该走廊。每条走廊只有一端有标记。
  - 走廊内部全部为 black（背景色）。

- `Rule`：
  - 第一层推理——走廊识别与标记配对：找到每个彩色标记像素，沿其相邻方向进入对应的走廊。走廊是 grey 墙壁之间宽度为 1 的连通黑色路径。
  - 第二层推理——计数拐弯次数：沿走廊从标记端的入口向另一端追踪，计算走廊路径的直角拐弯次数 T（走廊每改变一次 90° 方向算一次拐弯）。
  - 第三层推理——部分填充：从标记端入口开始，沿走廊用标记的颜色填充前 (T+1) 个像素。若走廊总长度小于 (T+1)，则整条走廊全部填满。走廊剩余部分保持 black。
  - 所有 grey 墙壁和彩色标记像素保持不变。

- `Key insight`：解题者需要先将彩色标记与对应走廊关联，然后沿走廊追踪路径发现拐弯次数这一隐含属性，最后意识到拐弯次数加一恰好等于填充长度——"走廊配对→拐弯计数→长度映射"构成三层递进推理，且拐弯次数作为填充量的编码方式是非显然的。
</new_puzzle>

- `description`：在棋盘式分区中，根据每个分区内"种子"像素与分区边界的相对位置，从种子向最近的边界方向生长出与种子同色的矩形色块，色块的大小由同一分区内另一个标记物的面积决定。

- `Input structure`：
  - 背景色为 black。
  - 网格被 maroon 色的单像素宽网格线均匀分割成若干大小相同的矩形分区（如每个分区 6×6 或 7×7 内部空间）。
  - 每个分区内部恰好包含两个对象：
    1. 一个单像素的"种子"，颜色为 red、blue、green 或 yellow 之一，位于分区内部的某个位置。
    2. 一个由 azure 色绘制的小型连通块（1~6 个像素），形状不规则，位于分区内部的另一个位置。

- `Rule`：
  - 第一层推理——确定生长方向：对每个分区，观察种子像素的位置。找到种子距离分区四条内边界（上、下、左、右）中最近的那条边界，该方向即为生长方向（若有并列则选择优先级：上 > 右 > 下 > 左）。
  - 第二层推理——确定生长尺寸：计数同一分区内 azure 连通块的像素数量 A。在生长方向上，从种子出发绘制一个宽 1 像素、长 A 像素的色条（使用种子的颜色），色条从种子位置向最近边界方向延伸。若色条长度超出分区边界则截断到边界。
  - 种子像素本身被色条覆盖（色条包含种子所在位置）。azure 连通块保持不变。maroon 网格线保持不变。

- `Key insight`：azure 块看似装饰，实则其面积编码了生长长度；种子的位置看似随机，实则其与边界的相对关系决定了生长方向——解题者需要同时发现"位置→方向"和"面积→长度"两条独立的编码规则，二者共同决定最终输出。
</new_puzzle>

<new_puzzle>
- `description`：在包含多个彩色环形框架的网格中，根据环形缺口的位置和环内独立色点的颜色，将色点沿缺口方向"弹射"出环，并在环外绘制与色点颜色对应的特定符号。

- `Input structure`：
  - 背景色为 black。
  - 网格上有若干用不同颜色绘制的矩形环形框架（宽 1 像素的矩形边框），每个环框的一条边上恰好有一个 1 像素宽的缺口（缺口位置在该边的中点处）。
  - 每个环框内部恰好有一个非背景、非框架色的独立色点（1×1 像素）。
  - 网格的一个角落（如左上角）有一个颜色图例区域：若干行，每行包含一个颜色像素和一个紧邻的 3×3 小图案（用同色绘制）。图例区域用 grey 边框围起来以区分。图例表示"该颜色对应该 3×3 图案"。

- `Rule`：
  - 第一层推理——缺口方向识别：对每个环形框架，找到其缺口所在的边及缺口位置，确定缺口朝向的方向（上、下、左、右）。
  - 第二层推理——颜色查图例：取环内色点的颜色，在左上角颜色图例中查找对应的 3×3 图案。
  - 第三层推理——弹射放置：从缺口位置出发，沿缺口朝外的方向移动 2 个像素（留出 1 像素间隔），在该位置以色点颜色绘制查到的 3×3 图案。环内的原始色点被擦除（变为 black）。环框本身和图例区域保持不变。

- `Key insight`：环的缺口方向决定弹射目标位置，环内色点的颜色通过图例间接编码了弹射物的形状——解题者必须同时发现"缺口→方向""颜色→图例形状"两个映射关系并组合使用，而非简单的单步变换。
</new_puzzle>

<new_puzzle>
- `description`：根据多个信号塔的覆盖范围叠加关系，对网格区域进行分层着色，覆盖层数越多的区域颜色越深（按预定颜色梯度序列）。

- `Input structure`：
  - 背景色为 black。
  - 网格上散布若干"信号塔"，每个信号塔是一个 1×1 的 red 像素。
  - 网格的最底行是一个颜色梯度图例：从左到右依次排列 1~N 个不同颜色的像素（如 yellow、orange、maroon、red……），表示覆盖层数 1 对应 yellow、覆盖层数 2 对应 orange、依此类推。图例像素之间无间隔，紧密排列从最底行最左端开始。

- `Rule`：
  - 第一层推理——识别信号塔与图例：找到所有 red 的信号塔像素及底行的颜色梯度图例。
  - 第二层推理——确定覆盖范围：每个信号塔以自身为中心，产生一个 5×5 的正方形覆盖区域（即上下左右各延伸 2 格的方形区域）。覆盖区域中超出网格边界的部分忽略。
  - 第三层推理——叠加计数与着色：对网格中每个非底行的像素，计算有多少个信号塔的覆盖区域包含该像素，得到覆盖计数 C。若 C = 0 则保持 black；若 C ≥ 1 则用图例中第 C 个颜色填充该像素（C 超出图例长度则使用图例最后一个颜色）。信号塔自身的像素也参与着色（被覆盖计数覆盖）。

- `Key insight`：解题者需要先识别底行图例的含义（覆盖层数→颜色映射），再发现每个信号塔的固定方形覆盖范围，最后理解重叠区域的计数叠加机制——图例不是装饰而是着色的查找表，多塔覆盖的叠加区域产生更深的颜色层级。
</new_puzzle>
