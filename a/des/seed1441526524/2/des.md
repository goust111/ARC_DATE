- `description`：根据网格中散落的"路径种子"像素，沿着它们隐含的可通行方向生长出完整路径，处理顺序由边缘标记列编码，顺序决定路径之间的遮挡关系。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中散布着若干单像素的彩色"种子点"，每个种子点颜色各不相同。
  - 网格左侧列有一列 grey 标记像素，标记像素的数量等于种子点的数量，标记像素从上到下排列，指示种子点的处理顺序（第一个标记对应距离该列最近的种子点，依此类推）。
  - 每个种子点的上下左右四个邻居中，恰好有两个方向是"空的"（即背景色且在网格范围内），这两个空方向定义了路径从该种子出发的两条臂。

- `Rule`：
  - 按 grey 标记列从上到下的顺序确定种子点的处理优先级：第一个标记对应的种子点最先生长路径，最后一个最后生长。
  - 对每个种子点，从它的两个空方向各自向外延伸直线段，直到碰到网格边界或已有的非背景像素为止（不覆盖已有像素）。延伸的像素颜色为该种子点自身的颜色。
  - 种子点按处理顺序逐个生长；后生长的路径会被先生长的路径所阻挡，因此路径长度取决于处理顺序。
  - 最终输出保留所有种子点及其生长出的路径段，grey 标记列保持不变。

- `Key insight`：
  - 种子点的两个"空方向"需要从其邻域推断（被网格边界或其他种子占据的方向不算空方向），这是第一层推理；grey 标记列编码了处理顺序，顺序决定了路径之间的遮挡关系，这是第二层推理。两层共同决定最终图案。
</new_puzzle>

- `Input structure`：

  - 网格中有若干对矩形区域，每对由一个"信封"和一个"印章"组成。

  - 每个信封和印章通过颜色配对：信封缺口处有一个与印章颜色相同的单像素标记点，紧贴在缺口外侧。

  - 将旋转后的印章图案填入信封内部：印章中的非背景像素写入信封内部对应位置，背景像素保持不变。

- `Key insight`：
  - 解题者需要先通过缺口处的彩色标记点建立信封-印章的配对关系（颜色匹配），这是第一层推理；然后根据缺口在边框的哪一条边上来确定旋转方向，这是第二层推理。旋转方向不是直接标注的，而是从缺口位置间接编码的。
</new_puzzle>

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有一个由多种颜色组成的矩形图案区域，占据网格的大部分。
  - 图案区域的边界之外，紧贴图案区域的某一侧，有一条或多条单像素宽的 red 水平线段或 red 垂直线段，每条线段跨越图案区域的整个宽度或高度。
  - red 线段之间互不相交，且都平行于同一个轴（全部水平或全部垂直）。

- `Rule`：
  - 每条 red 线段代表一条折叠线。折叠方向：将线段远离图案中心的那一侧翻折到靠近中心的那一侧。
  - 按照从外到内的顺序依次处理折叠线（最远离图案中心的 red 线段先折叠）。
  - 折叠时，翻折区域的像素叠加到目标区域上：若翻折像素为非背景色且目标位置为背景色，则写入翻折像素的颜色；若目标位置已有非背景色，则保留目标位置原有颜色不变（先占据者优先）。
  - 折叠后，red 线段本身及其外侧的多余行/列从网格中移除，输出网格尺寸相应缩小。

- `Key insight`：
  - 解题者需要理解 red 线段不是图案的一部分而是元指令，并且需要推断出折叠方向（朝向中心）和折叠顺序（从外向内）。折叠产生的像素叠加遵循"先到先得"原则——已有内容的位置不会被覆盖。这三层推理（线段功能、折叠方向与顺序、叠加优先级）共同决定了最终的合并图案。
</new_puzzle>

- `Input structure`：
  - 背景为主色（black）。
  - 网格中散布着若干个小型单色矩形块（2×2 或 3×3），每个块有不同颜色。

- `Rule`：
  - 根据每个非根块的 grey 标记方向，沿该方向搜索最近的块，建立父子关系，形成一棵以 red 块为根的树。
  - 从叶节点开始（没有任何块指向它的块为叶节点），按层级从叶到根的顺序处理。
  - 每个块沿 grey 标记指示的方向平移，直到它的边缘紧贴其父块的边缘（中间无间隙）。
  - 先移动叶节点到其父节点旁边，再移动这些已合并的子树整体到更上层的父节点旁边，依此逐层向根收缩。
  - grey 标记像素在输出中被清除。所有块保持原始颜色和尺寸，只改变位置。

- `Key insight`：
  - 第一层推理：识别 grey 像素的含义——它紧贴在块的哪一侧决定了该块的父方向。第二层推理：通过父方向链条重建出整棵树的层级结构，并理解收缩必须从叶到根逐层进行，因为子节点的最终位置取决于父节点是否已经完成移动。
</new_puzzle>

- `description`：网格被分隔线分为上下两个面板，两个面板分别保存了一幅完整图像的棋盘奇偶互补像素，输出将二者交错拼合还原。

- `Input structure`：
  - 背景为主色（black）。
  - 网格被一条 grey 水平分隔线分为上下两个面板，两个面板尺寸相同（宽 W、高 H）。
  - 上面板包含一些彩色像素，分布在棋盘格的"偶数格"位置（即行号+列号为偶数的位置），其余位置为背景色。
  - 下面板包含一些彩色像素，分布在棋盘格的"奇数格"位置（即行号+列号为奇数的位置），其余位置为背景色。
  - 两个面板中的非背景像素在空间上互补，没有重叠的位置。

- `Rule`：
  - 输出为一个 W×H 的网格（去掉分隔线）。

  - 最终输出是两个面板交错拼合后的完整图像。

- `Key insight`：
  - 解题者需要观察到两个面板中非背景像素的分布呈互补的棋盘格模式——上面板只在"偶数格"有内容，下面板只在"奇数格"有内容——从而推断出这是一幅图像的棋盘拆分。关键在于识别奇偶交错模式而非简单叠加，因为取值来源由位置的奇偶性决定。

- `Input structure`：

  - 网格中有若干个由 grey 像素围成的封闭矩形"围栏"。
  - 每个围栏内部恰好有一个小型彩色对象（3×3 以内的连通像素块，颜色非 grey 非背景色）。
  - 每个围栏的形状特征由缺角数量区分：0 个缺角（完整矩形）、1 个缺角（某个角被削去一个像素）、2 个对角缺角（对角线上的两个角各被削去一个像素）。
  - 每个围栏上边沿外侧有 0 到 3 个 maroon 像素标记。

- `Rule`：
  - 识别每个围栏的缺角数量以确定变换类型：0 个缺角 → 水平翻转；1 个缺角 → 顺时针旋转 90°；2 个对角缺角 → 旋转 180°。

  - 输出中保留所有 grey 围栏，清除 maroon 标记像素，显示变换并平移后的彩色对象在新位置。

- `Key insight`：
  - 第一层推理：发现围栏的"缺角"数量系统编码了变换类型（0/1/2 个缺角对应不同几何变换），而非随机残缺。第二层推理：发现围栏外侧的 maroon 标记数量控制额外的平移距离。两个独立编码通道分别控制变换类型和位移量，需要同时正确解读才能得到正确输出。

- `description`：grey 管道网络连接多个三原色源头，颜色沿管道传播并在交汇处按固定配色规则混合，输出显示每段管道的最终颜色。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有由 grey 像素绘制的单像素宽管道网络，管道沿水平和垂直方向延伸，在交叉点处以 T 形或十字形连接。

  - 管道内部所有连通的 grey 像素初始为 grey。

- `Rule`：
  - 每个彩色源头的颜色沿管道向所有可达方向扩散，将经过的 grey 管道像素染色。

  - 管道交汇处（T 形或十字形节点）允许颜色通过并继续向所有分支传播。
  - 输出网格中所有管道像素显示其最终颜色（源色或混合色），非管道区域保持不变。

- `Key insight`：
  - 第一层推理：识别 grey 像素构成的管道网络拓扑结构，区分源头端点（有彩色像素标记）和出口端点（无标记）。第二层推理：理解颜色沿管道全向传播并在交汇处按固定规则混合——需要追踪每条管道段可被哪些源头到达，由到达源色的组合决定最终颜色。

- `description`：每个彩色矩形空心框内左上角有一个小型"瓷砖"图案，框的内部尺寸与图案尺寸的整数比决定了图案在框内被平铺重复的行列数。

- `Input structure`：
  - 背景为主色（black）。
  - 网格中有若干个单色矩形空心框（每个框颜色不同，框线宽度为 1 像素）。
  - 每个框的内部左上角包含一个小型彩色图案（图案颜色与框颜色不同），占据一个固定的小矩形区域（如 2×2 或 3×3）。
  - 框的内部剩余空间为背景色。
  - 每个框的内部宽度是图案宽度的整数倍，内部高度是图案高度的整数倍。

- `Rule`：
  - 对每个框，计算内部宽度除以图案宽度得到列重复数 C，内部高度除以图案高度得到行重复数 R。
  - 将图案在框内部以 R 行 × C 列的方式平铺，完全填满整个框内部空间。
  - 输出中框边框保留，框内部显示完整的平铺图案。

- `Key insight`：
  - 解题者需要先识别框内左上角的小图案是"瓷砖单元"而非普通装饰，然后发现框的内部尺寸恰好是图案尺寸的整数倍，从而推断出平铺规则。关键洞见在于框的大小不是随意的——它精确编码了图案需要重复的次数。不同框有不同的尺寸比例，因此平铺的行列数各不相同，从样例中可以验证这个整数倍关系。
</new_puzzle>
