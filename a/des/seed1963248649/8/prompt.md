<description>
Let the largest center-pointing object grow outward while every other object loses its inward tip.

Input structure
- The grid has a single dominant background color and four 8-connected monochromatic foreground objects.
- The objects surround a central background gap and point toward it from cardinal directions.
- Exactly one object has the largest area.

Rule
- Find the central background gap by minimizing aggregate distance to the four objects.
- Recolor the nearest-to-center pixel of each non-largest object to background.
- Add a three-pixel cap in the largest object's color on the side away from the center, centered on the shared row or column.

Key insight
- The edit is a transfer of prominence around a common center: losers retract at their tips, and the unique largest object extends outward from the center.
</description>

<description>
Draw the missing diagonal connector segment between each pair of same-color rectangular objects.

Input structure:
- The grid has one dominant background color.
- Every foreground color appears as exactly two separated solid rectangular 4-connected objects.
- The two rectangles of each color are diagonally offset with facing corners on a 45-degree line.

Rule:
- Keep all existing rectangles unchanged.
- For each foreground color, connect the lower facing corner of the upper rectangle to the upper facing corner of the lower rectangle.
- Paint only the intervening background pixels on that diagonal, excluding the two endpoint pixels already in the rectangles.

Key insight:
- Same-color rectangles define the endpoints; the output completes the open diagonal between their nearest facing corners.
</description>

<reference_puzzle index="3" source="train" puzzle_id="99caaf76" lines="56-75">
<description>
Move each marked cross object away from its marker to the grid edge while rotating the colored cross 180 degrees.

Input structure:
- The background is the dominant color.
- Each 8-connected foreground object has nine pixels: a 4-pixel marker-color
  sprite attached to a 5-pixel non-marker colored cross.
- Each object bbox is either 3x6 or 6x3, so the marker sprite is on exactly
  one side of the cross.

Rule:
- Move the whole object straight away from its marker side until the object
  bbox touches the corresponding grid edge.
- Keep the marker sprite unchanged within the object.
- Rotate the 3x3 colored cross block by 180 degrees before placing it.

Key insight:
The marker sprite is a directional tail; the cross is the leading payload,
and only that payload turns around during the slide to the edge.
</description>
</reference_puzzle>

<reference_puzzle index="4" source="train" puzzle_id="2de01db2" lines="28-41">
<description>
Invert each row's native foreground color against the black background.

Input structure
- A black-background grid whose rows each have one native foreground color plus optional distractor colors.
- The native row color is the most frequent non-bg color in that row; if tied, its run starts leftmost among tied colors.

Rule
- For each row independently, turn pixels of the native row color into bg.
- Turn every other pixel in that row, including bg and distractor colors, into the native row color.

Key insight
- Distractor colors are not preserved objects; they mark cells that participate in the binary complement of the row's native color.
</description>
</reference_puzzle>

<reference_puzzle index="5" source="eval" puzzle_id="271d71e2" lines="9-22">
<description>
Move bordered containers toward same-colored destination markers, charging gray cells to orange.

Input structure:
- bg = 6 (magenta). Black-bordered (0) rectangles with gray (5) / orange (7) interiors.
- A head sprite (9) sits adjacent to one container edge; a matching destination sprite lies along the movement axis.

Rule:
- Each container translates toward its destination along the head-to-dest axis.
- Steps = min(head-to-dest distance, number of gray interior cells).
- Gray cells become orange from the head-facing side inward, one per step.

Key insight: Gray cell count caps movement — a container stops short if it runs out of gray cells to charge.
</description>
</reference_puzzle>

<reference_puzzle index="6" source="train" puzzle_id="17829a00" lines="21-36">
<description>
Move each colored object vertically until it touches the matching top or bottom border bar.

Input structure:
- The background is the dominant color.
- The top row is a full-width bar in one foreground color and the bottom row is a full-width bar in another.
- All other foreground pixels are 8-connected monochrome objects whose color matches one of those bars.

Rule:
- Top-bar-colored objects move upward so their bbox top is row 1.
- Bottom-bar-colored objects move downward so their bbox bottom is the row above the bottom bar.
- A downward-moving one-column segment whose landing overlaps its source becomes the continuous vertical segment swept between them.

Key insight:
The horizontal bars are destination anchors: color determines which border an object slides toward, while columns and object shape are otherwise preserved.
</description>
</reference_puzzle>

<description>
Extract the single plain rectangle and redraw it with the aligned rectangles' border-relative marker pattern.

Input structure:
- The boundary color is the background/separator.
- Foreground objects are dense rectangular regions; exactly one rectangle has only its base color.
- Other rectangles contain their base color plus marker pixels.

Rule:
- Crop the only plain rectangle; this crop is the output canvas.
- Use marked rectangles whose row span overlaps the plain rectangle's row span.
- Transfer their marker pixels by preserving each marker run's distance from the nearest rectangle edges.

Key insight:
- The marked rectangles are examples of an edge-relative pattern, so the missing plain rectangle receives the same pattern resized to its own dimensions.
</description>

<reference_puzzle index="8" source="eval" puzzle_id="cb2d8a2c" lines="13-26">
<description>
Extend a green path from one grid edge to the opposite, routing around red bars at a distance dictated by their blue pixel count.

Input structure:
- bg = azure (8). Red/blue bars (color 2/1) act as obstacles.
- A single green (3) pixel sits on a grid border — the path start.

Rule:
- Each bar's keep-out radius equals its number of blue pixels; the path must stay farther than that from every bar cell.
- The green pixel extends inward toward the opposite edge, turning at right angles to navigate around forbidden zones.
- After the path is drawn, all blue pixels become red.

Key insight: Blue pixels on a bar encode its danger radius — more blue means a wider no-go zone the path must respect.
</description>

<reference_puzzle index="9" source="train" puzzle_id="ac6f9922" lines="18-40">
<description>
Summarize the enclosed table slots by the single object color inside each slot, using the slot background color for empty slots.

Input structure
- The most common color forms the outer background and all enclosed slot
  backgrounds.
- The enclosed background components form a complete rectangular array of
  slots, ordered by their positions.
- Each slot contains either no other color or exactly one object color.

Rule
- Find all 4-connected components of the most common color that do not touch
  the input edge.
- Sort their bounding boxes into row and column order to define the output
  table.
- For each slot, output its unique non-background color if present; otherwise
  output the background color.

Key insight
- The large grid is an expanded table: the enclosed background components are
  the cells, and any colored object drawn inside a cell is that cell's summary
  value.
</description>
</reference_puzzle>

<description>
Dock movable tools into border-anchored frames by filling cavities.

Input structure:
- bg = most common color.
- Border-touching components cluster into anchor frames with interior bg cavities.
- Non-border 2-color components are movable tools.

Rule:
- Match each tool to a frame whose cavity size equals one of its color-region counts.
- Rotate/flip the tool so one color fills the cavity exactly; the other stays outside.
- If the docking orientation uses a reflection, swap the tool's two colors.

Key insight: Cavity size determines tool–frame pairing; reflection triggers color swap.
</description>

Extrapolate the moving sprite from a horizontal sequence of shared-border frames into the next standalone frame.

Input structure

Rule
- Build one output panel with the same height, frame color, fill color, and sprite.
- Continue the sprite's diagonal motion one more panel to the right.

- The panels are consecutive frames of motion; the output is the next frame after the sequence.

<reference_puzzle index="12" source="train" puzzle_id="14b8e18c" lines="40-57">
<description>
Mark every complete square object with red pixels just outside its corners.

Input structure:
- A uniform background contains one or more monochrome 4-connected foreground objects.
- The relevant objects are square frames or filled squares: their bbox is square
  and all cells on the bbox border have the object's color.
- Non-square bars and incomplete fragments may also appear and are ignored.

Rule:
- Keep the input unchanged.
- For each complete square object, paint red on the two outside background
  pixels orthogonally adjacent to each of the square's four corners.

Key insight: The transformation is not based on size or color; it selects
objects whose bounding box is a complete square border and labels only their
exposed outer corner-adjacent cells.
</description>

<reference_puzzle index="13" source="eval" puzzle_id="faa9f03d" lines="36-52">
<description>
Repair a one-cell-thick colored line network by replacing singleton markers, filling short orthogonal gaps, and redirecting yellow-marked arms to the edge.

Input structure:
- A rectangular grid with a dominant background.
- Line colors form one-cell-thick horizontal/vertical stroke fragments.
- Marker colors are exactly those whose 4-connected components are all singleton pixels.
- Red singleton markers are missing line cells; yellow singleton markers are directional controls next to a line endpoint.

Rule:
- Assign every marker to the nearest visible line color in row/column line-of-sight, preferring an endpoint supported along that same axis.
- For each line color, fill the gap between consecutive facing endpoints in a row or column.
- A yellow control erases the old straight arm on the far side of its endpoint and paints the same color from that endpoint through the control pixel to the grid edge.
- At crossings, yellow-control rays win; otherwise an original-vs-filled crossing uses the more fragmented pre-repair line color, while pure filled crossings use the lower color id.

Key insight: The singleton markers identify which sparse stroke fragments belong together; after they are colored, the intended lines are the axis-aligned gaps between facing endpoints, with yellow controls flipping one arm to the marked side.
</description>
</reference_puzzle>

<description>
Rebuild the foreground rectangles as a largest-to-smallest lower-left nesting.

Input structure
- A periodic wallpaper background is overlaid by foreground colors that each form a rectangular frame or solid rectangle.
- The largest foreground rectangle is the output frame; smaller foreground rectangles are the objects to nest inside it.

Rule
- Ignore the wallpaper and crop the result to the largest foreground rectangle's bbox size.
- Sort foreground rectangles by bbox area from largest to smallest.
- Reconstruct each frame or solid rectangle, placing every next smaller rectangle in the lower-left of the current rectangle's usable region.

- The scattered background colors are not objects; the meaningful order is the unique descending rectangle size chain, and each step nests into the previous rectangle's lower-left interior.

<description>
Shift each interior pixel whose color matches a frame side one cell toward that matching side.

Rule
Interior pixels with the top-side color move one row up, bottom-side color

The colored frame sides act as direction labels for matching interior pixels.

<description>
Detect thin '+' shapes in a single foreground color and recolor them to teal.

Input structure:

- One foreground color (e.g. yellow) forms various shapes on the bg, some of which are small '+' crosses.

Rule:
- A '+' center is any foreground pixel whose 4 orthogonal neighbors are also foreground.
- Recolor each such center and its 4 neighbors to teal (8).
- All other pixels remain unchanged.

Key insight: Only compact 5-cell crosses qualify — a pixel embedded in a larger filled region also satisfies the neighbor check, so the rule highlights every local '+' motif, not just isolated ones.

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 若涉及计算，只允许使用简单的计数、排序与数量比较；不允许使用复杂的数学公式或运算。
3. 问题必须能从少量示例中推断出来，但不代表题目一定简单。设计时需从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息或需要推算的隐藏属性。规则可以很难发现，难到反复对比所有样例仍需要深度思考才能归纳出来，但一旦发现后必须能用来解释所有样例且产出唯一确定的输出。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入/输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 “red”。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 五个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7.  题目难度应来自机制的隐蔽性而非步骤数。关键信息难以准确定位，需要反复对比尝试不同的角度才能发现真正的规则。


生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述20道参考题相同或者是类似，不可只是替换了颜色、方向、对象类型、维度等表层要素。判断标准：新题的核心推理路径（解题者从样例中归纳规则的认知过程）应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5个样例中发现规律。
