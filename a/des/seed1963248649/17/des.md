# 第一步：分析与思考

## 参考题中的基础操作梳理

参考题涉及的核心操作类型包括：
- **空间移动与路径约束**：物体沿通道滑动、受尺寸限制（#1），按标记对齐滑动（#13）
- **形状/模式替换与展开**：小标记扩展为大图案（#15），每像素替换为模板块（#17），递归自相似展开（#18）
- **排序与重新排列**：按面积排序生成嵌套环（#4），按频率排序列填充（#5）
- **颜色间接索引**：颜色作为查找键进行跨对象信息传递（#3），颜色配对确定粘贴位置（#6、#7）
- **对称性修复/检测**：逐色层检测并强制镜像对称（#19）
- **区域分割与合成**：洪泛填充分区域选择不同源（#9），交换两面板图案（#20）
- **标记生命周期/状态机**：标记经历"生长→完成→传送"的两步循环（#11）
- **解码/编码**：小图案作为密码编码大结构（#8），端点标记锚定整个符号重建（#2）

## 非显而易见的串联方式与信息编码思考

1. **拓扑关系作为隐式指令**：物体的连通性、包围关系、邻接图本身可以编码操作序列——不是物体"是什么"决定输出，而是物体之间"怎么连"决定输出。
2. **缺失即信息**：网格中"不存在"某个期望元素本身就是一个信号——空洞的形状、断开的线段、缺失的颜色都可以作为操作触发器。
3. **几何属性的二义性**：同一个形状在不同语境下可以表示完全不同的含义——比如一个十字形既可以是"加号运算符"也可以是"方向指示器"，上下文决定解读。
4. **空间位置本身作为数值**：物体到边界的距离、到某个锚点的偏移量可以被隐式地用作计数器或索引。
5. **操作的条件分支**：不同区域的物体可能遵循不同的变换规则，而区分条件隐藏在某个全局特征中。

## 新颖构思方向

我追求的是真正全新的认知路径——解题者需要发现的规律本身是前所未见的，而不是旧机制的表面变体。以下新题的设计重点在于：让关键规则隐蔽但视觉上可验证，认知发现过程独特，且一旦发现规则即可确定性地解出。

<new_puzzle>
- `description`：根据每个封闭区域内部的"视线可达边界颜色集合"，用该集合中出现次数最少的颜色填充该区域。

- `Input structure`：
  - 背景为 black。
  - 网格中存在由 grey 像素构成的不规则墙壁，将网格划分为若干封闭区域（4-连通 black 区域）。
  - 墙壁的部分像素被替换为其他颜色（如 red、blue、green、yellow），这些彩色像素位于墙壁结构中，仍作为墙壁的一部分（即不可通行）。
  - 每个封闭区域的边界墙壁上可能包含多种颜色的墙壁像素。

- `Rule`：
  - 对每个封闭的 black 区域，统计其4-邻接边界上所有非 grey 的彩色墙壁像素（不含 grey 本身）。
  - 在这些颜色中，找到出现次数最少的颜色（若有唯一最少的），将该封闭区域内所有 black 像素填充为该颜色。
  - 若某区域边界上没有彩色墙壁像素（全部为 grey），则该区域保持 black 不变。
  - 若最少出现次数存在并列，则选择这些并列颜色中在网格上按从上到下、从左到右扫描时最先出现的那个颜色。
  - 墙壁像素本身保持不变。

- `Key insight`：解题者需要意识到决定区域填充色的不是"区域内部有什么"，而是"包围该区域的墙壁上嵌入了哪些颜色标签"——并且是最稀有的那个颜色胜出。这需要将注意力从区域内部转向边界墙壁上的微小色差。
</new_puzzle>

<new_puzzle>
- `description`：将散布在网格中的彩色线段解读为"指针"，每根指针指向的目标位置接收该指针颜色的一个像素印记，形成一幅由指针间接绘制的隐形图案。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干水平或垂直的短线段（长度为2到4个像素），每根线段为单一非 black 颜色。
  - 每根线段严格位于一行或一列上，且长度大于1，因此具有明确的方向（水平或垂直）。
  - 网格中还存在若干单独的 grey 像素，分散在各处，作为"靶点标记"。

- `Rule`：
  - 每根彩色线段被视为一个指针：它从自身的起点出发，沿线段延伸的方向（从线段的第一个像素到最后一个像素的方向，按行列顺序——水平线段从左到右，垂直线段从上到下）向前延伸。
  - 沿该方向从线段末端继续前进，遇到的第一个 grey 像素就是该指针的目标。
  - 在输出中：将目标 grey 像素替换为该指针的颜色。
  - 若一个 grey 像素被多根指针指向，保留所有指针中线段长度最长的那个颜色；若长度相同，保留行号较小的指针颜色。
  - 指针线段本身在输出中被擦除（变为 black）。
  - 未被任何指针指向的 grey 像素保持 grey 不变。

- `Key insight`：线段不是输出图案本身——它们是"投射器"，其方向和延长线决定了颜色的着陆点。解题者需要把每根线段理解为一支有方向的笔，沿其延长线追踪到最近的灰色靶点，才能还原出最终图案。
</new_puzzle>

<new_puzzle>
- `description`：网格中的每个彩色"种子"根据其所在象限的不同，执行不同的生长规则，最终生成四种不同方向的分形枝条图案。

- `Input structure`：
  - 网格尺寸为偶数×偶数（如 20×20），背景为 black。
  - 网格被一条水平中线和一条垂直中线隐式划分为四个象限（中线本身不可见，不画出）。中线位置为 rows/2 和 cols/2。
  - 每个象限中恰好有一个单像素的彩色"种子"，四个种子颜色各不相同（例如 red、blue、green、yellow）。

- `Rule`：
  - 每个种子根据其所在象限生长出一条 L 形枝条：
    - 左上象限：种子向上生长 d 格，然后向左生长 d 格（d = 种子到最近象限边界的曼哈顿距离中较小的那个值，即 min(种子行号, 种子列号)，其中行号和列号是相对于象限左上角的偏移）。
    - 右上象限：种子向上生长 d 格，然后向右生长 d 格。
    - 左下象限：种子向下生长 d 格，然后向左生长 d 格。
    - 右下象限：种子向下生长 d 格，然后向右生长 d 格。
  - d 的具体计算：种子在其所在象限内的局部坐标为 (lr, lc)（相对于该象限左上角的行、列偏移，从0开始），d = min(lr, lc)。
  - 生长路径上的所有像素都染为种子的颜色。种子本身也保留。
  - 若生长路径超出网格边界，则在边界处截断。

- `Key insight`：四个种子看似独立，但它们的生长方向由各自所在的象限隐式决定——解题者需要发现不可见的象限分界线，并理解"象限身份"如何映射到"生长方向"。位置不仅决定了在哪里生长，还决定了往哪个方向生长。
</new_puzzle>

<new_puzzle>
- `description`：网格中的多条彩色"传送带"各自携带其上的货物像素平移一定步数，步数由传送带末端的编码标记决定；货物滑出传送带后消失。

- `Input structure`：
  - 背景为 black。
  - 网格中存在若干水平的单色条带，每条条带占据一整行的连续区间，长度至少为5。每条条带颜色为 grey。
  - 每条 grey 条带的最右端有 1 到 3 个像素被替换为 maroon 色——这些 maroon 像素的数量就是该条带的"步数"。
  - 在每条 grey 条带上方（不在条带内部），有若干彩色像素（非 black、非 grey、非 maroon），这些像素位于条带上方紧邻的一行中，且列坐标落在条带的水平范围内。这些像素被视为"货物"。

- `Rule`：
  - 对于每条条带，读取其最右端 maroon 像素的数量 n（1、2 或 3）。
  - 将该条带上方一行中所有属于该条带列范围内的彩色货物像素向右平移 n 格。
  - 平移后若货物像素的列坐标仍在条带的水平范围内（包括 maroon 部分），则在新位置绘制该颜色像素。
  - 平移后若货物像素的列坐标超出条带的右端，则该货物消失（不绘制）。
  - 货物原来的位置变为 black。
  - 条带本身（grey 和 maroon 像素）保持不变。
  - 不同条带之间互相独立，不会干扰。

- `Key insight`：grey 条带看起来只是结构性的背景条纹，但实际上它们是有方向的"传送带"。关键在于发现条带末端 maroon 像素的数量编码了移动步数——这个信息隐藏在条带的边缘，不容易一眼看到。解题者需要同时理解"条带定义了货物的归属"和"maroon 数量定义了移动距离"两层关系。
</new_puzzle>

<new_puzzle>
- `description`：根据彩色框架的"开口方向"将框架内部的图案旋转对应角度后输出，框架本身不出现在输出中。

- `Input structure`：
  - 背景为 black。
  - 网格中有一个或多个互不重叠的矩形框架。每个框架由单一颜色绘制（如 red、blue、green 等），框架是一个矩形环，但恰好有一条边是缺失的（即框架有三条完整的边和一条完全缺失的边）。
  - 框架内部（被框架围起来的区域，包括开口边所在的那一行/列内侧像素）包含由其他颜色构成的一个小图案（4-连通的彩色像素组）。小图案不接触框架像素。
  - 每个框架的开口可以在上、下、左、右四个方向之一。

- `Rule`：
  - 对于每个框架，确定其开口方向（缺失边所在的方向）。
  - 根据开口方向确定旋转角度：开口朝上 → 不旋转（0°）；开口朝右 → 顺时针旋转90°；开口朝下 → 旋转180°；开口朝左 → 顺时针旋转270°（即逆时针90°）。
  - 提取框架内部的图案（不含框架本身），按上述角度旋转。
  - 输出网格仅包含所有旋转后的图案，按其原始框架中心位置放置（若有多个框架则都保留），背景为 black。输出网格大小与输入相同。
  - 框架像素在输出中被移除（变为 black）。

- `Key insight`：框架不只是装饰性边框——它的不完整性（哪条边缺失）才是核心信息。解题者需要发现"开口方向"与"旋转角度"之间的映射关系。框架的颜色是干扰项，真正重要的是它的几何缺陷。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每个彩色区块按其"邻居数量"进行层级着色——邻居越多的区块颜色越深，实现一种基于拓扑度数的热力图。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个互不重叠的单色矩形区块（每个区块为一个纯色实心矩形），颜色各异。
  - 两个区块若在4-邻接意义下（不是对角线）至少共享一个相邻像素对（即区块A的某像素与区块B的某像素4-邻接），则互为"邻居"。
  - 网格中还有一个颜色图例区域：位于网格最底部一行，由左到右依次排列着若干颜色色块（每个1×1像素），依次为 blue、green、yellow、orange、red，之间无间隔。该图例行的其余部分为 black。

- `Rule`：
  - 对每个矩形区块，计算它的邻居数量 k（即与它4-邻接的其他区块的个数）。
  - 根据 k 的值，用图例中第 k 个颜色（从1开始计数）重新着色该区块：k=1 用图例第1色（blue），k=2 用第2色（green），k=3 用第3色（yellow），k=4 用第4色（orange），k=5或更多用第5色（red）。
  - k=0 的孤立区块保持原色不变。
  - 图例行本身在输出中保持不变。
  - 区块的形状和位置不变，只改变颜色。

- `Key insight`：每个区块的最终颜色不取决于它"自己是什么颜色"或"有多大"，而取决于它"和多少个其他区块物理相邻"。解题者需要从空间邻接的拓扑角度看待区块之间的关系，并发现底部图例行是一个度数→颜色的映射表。
</new_puzzle>

<new_puzzle>
- `description`：网格中分散的同色像素对之间拉出连线，但连线的颜色不是像素对自身的颜色，而是由两个像素之间围起的矩形区域内已有的第三种颜色决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干成对出现的同色像素（每种非 black 颜色恰好出现两次），这些像素对分散在网格各处。
  - 每对同色像素定义一个矩形区域（以两像素为对角）。在该矩形区域内部（不含对角像素本身），恰好存在一个第三种颜色的单个像素（不是 black，也不是该像素对的颜色）。

- `Rule`：
  - 对每对同色像素，找到以它们为对角的矩形区域。
  - 在该矩形区域内部找到那个唯一的非 black、非该对颜色的像素，记其颜色为 C。
  - 用颜色 C 在两个同色像素之间画一条 L 形路径：先水平到达与目标像素同列的位置，再垂直连到目标像素（即先水平后垂直的折线路径）。
  - 路径覆盖的所有像素（包括起点和终点像素）都变为颜色 C。
  - 矩形内部用于指定颜色的那个第三色像素在输出中被移除（变为 black）。
  - 各对之间互相独立，路径可能交叉，后处理的对覆盖先处理的（按颜色对的行优先扫描顺序：按该对中行号较小的像素的行号排序，行号相同则按列号排序）。

- `Key insight`：同色像素对告诉你"连谁和谁"，但连线用什么颜色画却藏在两点之间的矩形区域里——一个容易被忽视的孤立像素充当了"颜色指令"。解题者必须将空间中三个层级的信息关联起来：配对关系（同色）、路径形状（L形折线）、以及绘制颜色（夹在中间的第三者）。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色图案被一条隐含的"折叠线"分为两半，输出是将其中一半沿折叠线翻折叠到另一半上、像素逐位取色彩"混合"后的结果。

- `Input structure`：
  - 背景为 black。
  - 网格中有一个连续的彩色图案区域（由多种非 black 颜色构成），形状不规则。
  - 该图案关于某一条水平线或垂直线具有近似的几何对称性，但两侧的颜色可能不同。
  - 在网格边缘上有一个单独的 azure 像素标记，位于某一行或某一列的边缘。若 azure 标记在左边缘或右边缘，则折叠线是经过该行的水平线；若在上边缘或下边缘，则折叠线是经过该列的垂直线。折叠线经过 azure 标记所在的那一行或列的中点位置。

- `Rule`：
  - 确定折叠线方向和位置（根据 azure 标记）。
  - 折叠线本身那一行/列保持不变。
  - 将折叠线一侧的图案翻转叠到另一侧之上：
    - 若某位置只有一侧有非 black 像素，则取该颜色。
    - 若两侧翻折后同一位置都有非 black 像素，则取"保留侧"的颜色。保留侧规则：折叠线上方/左侧为保留侧。
  - 输出网格的尺寸为折叠线到保留侧边界的距离（加上折叠线本身），即输出只保留折叠后的那一半网格（含折叠线行/列）。
  - azure 标记在输出中被移除。

- `Key insight`：解题者必须先发现图案存在近似对称性、找到隐含的折叠轴（由边缘 azure 标记暗示），再理解"折叠"是将图案的一半翻转叠合到另一半上，而不是简单的镜像或裁剪。输出尺寸的变化是重要线索。
</new_puzzle>
