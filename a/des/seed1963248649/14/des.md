# 第一步：分析与思考

## 参考题中的基础操作归纳

从 20 道参考题中，可以提取以下几类核心操作：

1. **连通性分析与区域分类**：基于 4-连通或 8-连通的像素分组，再依据内部拓扑结构（对角链、分叉、环）对区域进行分类（如题1的对角链识别）。
2. **模式匹配与原型交换**：识别缩放后的精灵图并将其与原型匹配，然后执行替换（题2、题6）。
3. **空间压缩与展开**：将分散的像素压实到一行/一列（题3、题5），或将压缩的参考图例展开到更大区域（题13）。
4. **物理模拟（重力/流体）**：模拟重力下落，包含滑动、阻挡、缓冲等规则（题4、题10）。
5. **对称性推断与修复**：从残存像素推断对称轴并填补缺失（题7、题17）。
6. **路径/射线行为由图例编码**：射线遇到障碍物时的转向规则由网格中的独立图例编码（题8）。
7. **循环排列与颜色旋转**：沿环状连接顺序旋转属性（题9）。
8. **最近邻/沃罗诺伊分区**：按与标记行/列的距离划分区域，等距时产生分隔（题11）。
9. **层叠顺序恢复**：从遮挡关系逆推图层顺序（题18）。
10. **属性驱动的排序与重排**：按面积或其他可数属性排序后重新放置（题19）。
11. **行列乘积子网格提取**：找到行列完全覆盖的二色矩形子图（题20）。
12. **唯一种子传播/洪泛填充**：从边界标记出发，沿线条找到封闭区域并填充（题15）。

## 非显而易见的串联方式思考

- **拓扑分类的输出作为映射索引**：先通过连通性分析为对象分类（如计算孔洞数、凸出数），再将分类结果作为索引查询颜色表或决定变换方式。这把"形状识别"和"查表映射"两个独立操作串联起来，解题者必须先发现"数什么"才能找到映射。
- **飞行路径上的环境交互改变匹配条件**：物体沿某方向移动时，路径上的环境元素修改物体的属性（如颜色），从而改变其最终的匹配目标。这将"运动模拟"与"动态属性变化"和"颜色匹配"三层操作叠加。
- **多维坐标交叉读取**：物体在网格中的位置同时映射到行标尺和列标尺，两个标尺的读数交叉决定输出属性。这种二维索引机制在现有题目中罕见。
- **几何互补性作为拼接信号**：边缘轮廓的凹凸互补关系（而非颜色或位置）编码了拼接信息。
- **近似对称 + 折叠 = 重叠标记**：一个区域几乎但不完全对称，折叠操作暴露了不对称部分，重叠区域标记为特殊颜色。这将"对称性检测"和"空间折叠"串联，产生的 maroon 标记是两者作用的复合结果。
- **交叉计数编码查表索引**：路径与其他路径交叉的次数成为一个隐含变量，用于索引一个预设的颜色查找表。信息通过"空间交互的次数"编码，而非颜色或位置。
- **围栏颜色组合 → 数值运算 → 二元判定**：封闭区域的属性由包围它的所有边界颜色共同决定，需要将颜色映射为数值再做运算。这是一种从"邻接关系集合"到"标量属性"的多步推导。

- `Key insight`：解题者首先需要发现每个区域并非完全对称，而是有一条"近似"对称轴。变换的核心是将较大一半折叠到较小一半上——maroon 标记出现在折叠后两层重叠的位置。关键难点在于识别出 maroon 代表"折叠重叠"，从而反推出整个折叠机制。这与简单的对称性修复（填补缺失）或镜像反射不同：这里是将一侧"压到"另一侧上，并用特殊颜色标记冲突。

- `description`：每条彩色路径的终点颜色由该路径与其他路径交叉的次数在起点编码条中索引决定。
- `Input structure`：背景为 black。网格中有若干条不同颜色的路径，每条路径是一系列 4-连通的同色像素组成的线段（可以有转弯但不分叉，即除了两个端点外每个像素恰好有 2 个同色 4-连通邻居）。不同路径可以在空间上交叉（即不同颜色的路径像素可以 4-连通相邻；交叉点处各路径保持各自颜色，路径不共享像素）。每条路径的一端（"起点端"）紧邻一个"编码条"：编码条由 2 到 5 个不同颜色的像素竖向排列（从上到下），紧贴在路径起点像素的左侧一列（即编码条像素位于起点像素左侧，按行从上到下排列）。编码条中的颜色与该路径自身的颜色不同，也彼此不同。路径的另一端（"终点端"）不紧邻任何编码条。
- `Rule`：(1) 对每条路径，识别其起点（紧邻编码条的那端）和终点（另一端）。(2) 沿路径从起点到终点遍历每个像素，统计"交叉事件"的次数：当路径上某个像素的 4-连通邻居中存在属于其他路径的像素时，该像素计为一个交叉点。连续相邻的交叉点（即路径上连续的多个像素都与同一条其他路径相邻）只算一次交叉事件。(3) 以交叉事件总数 N 作为索引（从 0 开始：0 次交叉 → 编码条第 1 格，1 次 → 第 2 格，依此类推），在该路径的编码条中查找对应颜色。若 N >= 编码条长度，则取 N mod 编码条长度。(4) 将路径终点像素的颜色改为查找到的颜色。(5) 路径其余像素和编码条保持不变。
- `Key insight`：路径终点的颜色既不由路径自身颜色决定，也不由终点的空间位置决定，而是由一个隐含的拓扑变量——路径与其他路径交叉的次数——编码的。编码条充当查找表，将交叉计数映射为颜色。解题者需要先注意到终点颜色的变化与路径的空间交互模式有关，再发现"计数交叉事件"这一具体机制，最后将计数结果与起点处的编码条对应起来。
</new_puzzle>

- `Input structure`：背景为 black。网格中有若干"色块"：每个色块是一个正方形空心边框（1 像素宽），使用 red、blue、green、yellow 或 orange 等颜色绘制，边长在 4 到 12 像素之间。色块内部（边框围成的区域）背景为 black，部分色块的内部包含由另一种颜色像素组成的简单图案（如直线、十字、对角线、小方块等），另一部分色块的内部完全为 black。色块之间通过 grey 的 1 像素宽直线段（水平或竖直）两两配对连接：每条 grey 线段的两端分别 4-连通接触一个色块的外边框。每个色块恰好连接一条 grey 线段（即色块两两配对，无落单）。在每对配对色块中，恰好一个色块内部有图案（"发送方"），另一个内部为纯 black（"接收方"）。
- `Rule`：(1) 找到每对通过 grey 线段连接的色块。(2) 在每对中，识别发送方（内部有非 black 像素的色块）和接收方（内部全为 black 的色块）。(3) 提取发送方内部图案：取发送方边框内部区域（不包括边框本身），找到所有非 black 像素组成的图案。(4) 计算接收方内部区域的尺寸 (Wr x Hr) 与发送方内部区域的尺寸 (Ws x Hs)。由于两者都是正方形，缩放因子 S = (接收方内边长) / (发送方内边长)，S 为正整数。(5) 将发送方图案进行 S 倍最近邻放大：图案中每个像素扩展为 S x S 的同色像素块。(6) 将放大后的图案绘制到接收方的内部区域中（左上角对齐）。(7) 发送方保持不变（边框和内部图案都不变）。(8) grey 连接线在输出中被移除（替换为 black 背景）。(9) 所有色块边框保持不变。

- `description`：每个小精灵图的最终颜色由其所在位置对应的行标尺颜色和列标尺颜色共同决定。
- `Input structure`：背景为 black。网格的第 0 行（最顶行）为"列标尺"，第 0 列（最左列）为"行标尺"。列标尺和行标尺由若干连续同色段组成，段与段之间用 grey 单像素分隔。标尺使用的颜色从 red、blue、green、yellow、orange 中选取（不使用 grey 和 black）。第 0 行第 0 列的像素（角落）为 grey。网格内部（从第 1 行第 1 列开始的区域）散布着若干小型 4-连通精灵图，每个精灵图使用单一颜色（与标尺中出现的颜色相同），不同精灵图可以使用不同颜色，形状各异但每个精灵图占据不超过 3x3 的边界框。精灵图之间互不接触。
- `Rule`：(1) 对每个精灵图，计算其边界框的中心坐标 (r_center, c_center)（若边界框宽或高为偶数，取靠左上的中心）。(2) 查列标尺：在第 0 行中找到 c_center 所在的颜色段（跳过 grey 分隔像素），记该颜色为 C_col。(3) 查行标尺：在第 0 列中找到 r_center 所在的颜色段（跳过 grey 分隔像素），记该颜色为 C_row。(4) 比较精灵图原色 C_orig 与 C_col、C_row 的关系：(a) 若 C_col == C_row（行列标尺颜色相同），精灵图保持原色不变；(b) 若 C_col != C_row 且 C_orig == C_col，精灵图重着色为 C_row；(c) 若 C_col != C_row 且 C_orig == C_row，精灵图重着色为 C_col；(d) 若 C_col != C_row 且 C_orig 既不等于 C_col 也不等于 C_row，精灵图重着色为 C_col。(5) 精灵图的形状和位置不变。标尺保持不变。
- `Key insight`：精灵图的颜色变化不由其自身形状或大小决定，而由其位置在二维坐标系（行标尺 x 列标尺）中的读数决定。解题者需要发现网格边缘的标尺构成了一个隐含的坐标系统，精灵图的位置是输入变量，两条标尺的颜色读数交叉决定了输出颜色。这种"位置 → 双标尺读数 → 颜色变换"的间接推理链条是解题的核心挑战。
