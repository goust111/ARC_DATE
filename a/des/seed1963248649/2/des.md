# 第一步：分析与思考

## 参考题中的基础操作归纳

从20道参考题中可以提取出以下基础操作类别：

1. **遮挡与修复**（#1, #19）：灰色/其他颜色像素遮挡底层图案，需通过上下文推断恢复。
2. **逐行/逐列选择与提取**（#2）：在晶格结构中寻找"异类"并提取。
3. **标记传播/染色**（#3）：标记像素将颜色信息传递给邻近的中性区域。
4. **几何变换——收缩/膨胀**（#4）：轮廓按规则扩大或缩小。
5. **路径追踪/走廊导航**（#5）：沿着走廊前进，遇到阻碍转弯。
6. **框架填充与排序**（#6）：将外部精灵按位置顺序填入框架槽位。
7. **局部裁剪/擦除**（#7）：按对象自身坐标系删除局部列。
8. **颜色替换链/图例**（#8, #18）：通过图例或拓扑属性进行颜色映射。
9. **对称延伸/填充间隙**（#9）：两个对齐对象向彼此延伸填充间隙。
10. **反射/镜像**（#10）：利用标记像素作为反射轴。
11. **方向编码与滑动**（#11）：边界图例编码方向，内部对象沿该方向滑动堆叠。
12. **弹射/推送至边界**（#12）：接触标记的对象沿远离方向推至网格边缘。
13. **分割-交换-位移**（#13）：对象被切分、颜色交换、对角拼接。
14. **切割与角落分配**（#14）：沿控制射线切割，碎片滑向对应角落。
15. **包含树/层次结构**（#15, #20）：识别嵌套关系，按层次重建。
16. **匹配与对接**（#16）：通过计数属性匹配对象，旋转对齐后对接。
17. **孔洞填充/模板转移**（#17）：从源对象提取子图案填充目标对象的空洞。

## 非显而易见的串联方式思考

- **拓扑属性作为索引键**：一个对象的孔洞数量不仅可以映射颜色（#18），还可以决定该对象参与哪种变换操作——例如孔洞数为偶数的对象执行旋转，奇数的执行镜像。
- **路径追踪的终点成为另一操作的触发器**：路径走廊（#5）到达某位置后，该位置的对象被激活执行另一种变换。
- **几何属性编码非几何信息**：对象的面积、周长比、凸度等可以编码排序顺序、选择条件等，而非仅仅是视觉特征。
- **空间关系的间接传递**：A对象的属性决定B对象的变换方式，但A和B之间没有直接接触，而是通过共享某种隐含的"地址"（如所在行号、颜色匹配、对齐关系）间接关联。
- **负空间作为信息载体**：背景区域的形状本身编码了变换规则（如背景形成的通道形状决定前景的移动方向）。
- **对象的边界形状决定填充内容**：边框的局部凹凸特征指示内部应填充什么颜色或图案。
- **计数结果的空间化**：将某种属性的计数结果转化为空间维度（如生成对应长度的线段或对应大小的方块）。

<new_puzzle>
- `description`：根据每个封闭区域边界上的缺口方向，从缺口处向区域内部射入一条与缺口方向一致的彩色射线，射线长度等于该区域内已有彩色像素的数量。

- `Input structure`：
  - 背景为 black。
  - 网格中散布若干由 grey 像素构成的封闭矩形边框（单像素宽），每个边框的某一条边上恰好有一个单像素宽的缺口（即该边上有一个像素缺失）。
  - 每个封闭区域内部散布若干 blue 像素（数量1到5不等，位置随机但不与边框重叠）。
  - 缺口所在的边框像素被替换为 black（即与背景融合），因此缺口位置需要通过边框的不完整性来发现。

- `Rule`：
  - 对每个 grey 矩形边框，找到其唯一缺口的位置和朝向（缺口在上边则方向向下，缺口在下边则方向向上，缺口在左边则方向向右，缺口在右边则方向向左）。
  - 统计该边框内部 blue 像素的数量 N。
  - 从缺口位置沿缺口指向内部的方向，绘制一条长度为 N 个像素的 red 线段（从缺口位置的下一个内部像素开始，沿方向延伸 N 格，不超出边框内部范围）。
  - 保留原有的所有 grey 边框像素、blue 像素不变。

- `Key insight`：缺口是视觉上的"入口"，其方向决定射线方向；内部散布的 blue 像素数量看似无关联，实际上编码了射线的长度——解题者需要同时发现缺口方向规则和计数规则两个独立线索并将它们组合。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每个彩色对象沿其"重心偏移方向"的反方向平移，平移距离等于该对象重心到其几何中心的曼哈顿距离（取整），最终对象不超出网格边界则停在计算位置，否则贴边停靠。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干单色 4-连通前景对象，每个对象使用不同颜色（可选颜色包括 red、green、blue、yellow、magenta）。
  - 每个对象的形状不规则（非矩形），使得其像素质心（所有像素行列坐标的算术平均值）与其包围盒几何中心不重合。
  - 对象之间不接触，且初始位置距离网格边缘有足够空间。

- `Rule`：
  - 对每个前景对象，计算其像素质心 C = (所有像素行坐标平均值, 所有像素列坐标平均值)，以及其包围盒几何中心 G = (包围盒行中点, 包围盒列中点)。
  - 计算偏移向量 V = C - G（行分量和列分量分别取 round 到最近整数）。
  - 将对象整体平移 -V（即向偏移的反方向移动），移动距离为各分量的绝对值。
  - 若平移后对象的任一像素超出网格边界，则将对象在该方向上回退至恰好不超出边界的位置。
  - 若平移后与其他已平移对象重叠，按对象面积从大到小的优先级处理：面积大的对象优先占据位置，面积小的对象在其平移路径上停在不重叠的最远位置。

- `Key insight`：解题的关键不在于识别对象或它们的颜色，而在于发现每个不规则对象的"不对称性"（质心偏离几何中心）才是决定移动方向和距离的隐藏属性。直觉上人们会寻找外部标记或颜色编码，但真正的控制信号藏在对象自身的形状中。
</new_puzzle>

<new_puzzle>
- `description`：在网格中，每个"信号源"对象通过与之同行或同列的"导线"将自身颜色传播到导线末端的"灯泡"对象上，但信号必须经过"滤波器"对象时会被改变为滤波器的颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有三类对象：
    - **信号源**：2×2 的实心彩色方块（颜色可为 red、blue、green 之一），位于网格的左侧或上侧区域。
    - **灯泡**：单个 grey 像素，位于网格的右侧或下侧区域。
    - **导线**：由 yellow 像素组成的直线段（水平或垂直），连接信号源和灯泡。导线的一端与信号源的某一边相邻（4-连通），另一端与灯泡相邻（4-连通）。
  - 某些导线上存在一个 **滤波器**：导线路径中间有一个像素不是 yellow 而是其他前景色（如 orange 或 magenta），该像素即为滤波器。
  - 每根导线恰好连接一个信号源和一个灯泡。导线之间不交叉。

- `Rule`：
  - 对每根导线，追踪其从信号源端到灯泡端的路径。
  - 如果导线上没有滤波器，将灯泡像素的颜色改为信号源的颜色。
  - 如果导线上存在滤波器，将灯泡像素的颜色改为滤波器的颜色（信号被滤波器"覆盖"）。
  - 信号源、导线、滤波器本身保持不变，只有灯泡的颜色发生变化。

- `Key insight`：解题者首先需要识别三类不同对象（通过尺寸和颜色区分：2×2 方块是信号源、单像素 grey 是灯泡、yellow 线段是导线），然后发现导线中间偶尔出现的非 yellow 像素不是噪声而是功能性的"滤波器"，它会截断信号源的颜色传播并替换为自己的颜色。关键难点在于注意到滤波器的存在并理解其对信号传播的影响。
</new_puzzle>

<new_puzzle>
- `description`：网格中分布着若干个形状相同但旋转角度不同的小图案；将每个图案旋转至标准朝向后，根据其在网格中的相对位置（属于哪个象限）为其着色。

- `Input structure`：
  - 背景为 black。
  - 网格正中央有一个由 grey 像素构成的十字标记（单像素宽，横竖各贯穿整个网格），将网格分为四个象限。
  - 四个象限中各散布若干个小图案（sprite），每个图案由 azure 像素组成，形状相同但可能经过 0°、90°、180°、270° 旋转。该基础形状是一个不对称的 L 形：在 3×3 的包围盒内，左上角 2×2 区域填充加上右下角单像素，共 5 个像素。
  - 每个图案完全位于某一个象限内，不与十字标记重叠。

- `Rule`：
  - 首先识别每个 azure 图案当前的旋转状态（0°、90°、180°、270°），将其旋转回标准朝向（0° 状态，即 L 形的长边在左上）。旋转操作以图案包围盒中心为旋转中心，就地完成。
  - 然后根据图案所在的象限进行着色：
    - 左上象限 → red
    - 右上象限 → blue
    - 左下象限 → green
    - 右下象限 → yellow
  - grey 十字标记保持不变。

- `Key insight`：这道题的表层现象是"不同象限的图案颜色不同"，解题者很容易注意到颜色按象限分配。但真正的难点在于发现每个图案还需要被旋转回标准朝向——因为在小样本中，旋转的差异和颜色的差异同时出现，解题者需要分离这两个独立的变换规则（旋转归一化 + 象限着色），而不是把它们混为一个更复杂的单一规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干对"锁"和"钥匙"，每把钥匙的凸出轮廓恰好与某把锁的凹陷轮廓互补；将每把钥匙移动并嵌入其匹配的锁中，形成完整的矩形。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干彩色对象，分为两类：
    - **锁**：近似矩形的对象，但某一条边上有一个矩形凹槽（缺失若干像素）。每把锁使用不同颜色（如 red、blue、green 等）。锁的凹槽深度和宽度各不相同。
    - **钥匙**：每把钥匙由两部分组成——一个矩形"柄部"（使用 grey 颜色）和一个从柄部某边伸出的矩形"齿部"（使用与某把锁相同的颜色）。齿部的尺寸恰好与某把锁的凹槽尺寸完全相同。
  - 锁与钥匙之间有间距，不直接相邻。钥匙的齿部颜色与其对应锁的颜色相同，这是匹配的唯一依据。

- `Rule`：
  - 通过颜色匹配找到每把钥匙对应的锁（钥匙齿部颜色 = 锁的颜色）。
  - 将钥匙的齿部从钥匙上分离（擦除灰色柄部，只保留齿部）。
  - 将齿部平移到对应锁的凹槽位置，恰好填满凹槽，使锁变为完整矩形。
  - 平移方向由凹槽的朝向决定：齿部沿垂直于凹槽开口面的方向移入。
  - 最终输出中，所有锁变为完整矩形，所有钥匙的灰色柄部被擦除。

- `Key insight`：解题者需要发现"互补形状匹配"的机制——钥匙的彩色齿部恰好能填满同色锁的凹槽。颜色既是匹配信号也是最终填充色。难点在于识别出钥匙是由两种颜色（灰色柄 + 彩色齿）组合而成的复合对象，并理解只有齿部参与变换而柄部被丢弃。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布着若干彩色像素点，它们实际上是"星座"的节点；将属于同一星座的节点用该星座颜色的线段连接起来，连接顺序由节点间的距离从近到远依次串联（最近邻链）。

- `Input structure`：
  - 背景为 black。
  - 网格中散布若干前景像素，使用 2-4 种不同颜色（例如 red、blue、green、yellow）。
  - 同一颜色的像素构成一个"星座"，每个星座包含 3-6 个像素点。
  - 不同颜色的像素点之间有足够间距，避免连线交叉歧义。
  - 所有像素点为单个像素。

- `Rule`：
  - 对每种颜色的像素点集合独立处理。
  - 在同色像素点中，选择最左上角的点（先按行最小，行相同则按列最小）作为起点。
  - 从起点开始，连接到距离当前点最近的尚未连接的同色点（距离使用曼哈顿距离；若距离相同则选行坐标较小的，仍相同则选列坐标较小的）。
  - 连线方式：先水平移动到目标点所在列，再垂直移动到目标点所在行（即 L 形折线），沿途所有经过的 black 像素被染为该星座的颜色。
  - 重复此过程直到所有同色点被串联。
  - 若连线路径经过已有的其他颜色像素或连线，则该像素保持先绘制的颜色不变（先画的优先）。绘制顺序按颜色的首字母排序（blue → green → red → yellow）。

- `Key insight`：散布的彩色像素点看起来毫无关联，解题者需要发现同色点之间存在"最近邻串联"的隐含连接规则，且连接路径遵循固定的 L 形折线模式（先水平后垂直）。难点在于从少量样例中同时推断出三个要素：按颜色分组、最近邻遍历顺序、L 形连线路径。
</new_puzzle>

<new_puzzle>
- `description`：网格中有一个由彩色像素构成的"种子图案"和若干灰色的"土壤区域"；种子图案的每一行定义了一个生长规则，将该规则应用到每个土壤区域上，使土壤从底部逐行向上"生长"出与种子行对应的颜色条纹。

- `Input structure`：
  - 背景为 black。
  - 网格左侧有一个竖直排列的"种子图案"：一个 1 列 × H 行的彩色列（每行一个像素，颜色各异或有重复），使用 red、blue、green、yellow、orange 等颜色。该种子列的左边或右边有一条 maroon 竖线作为边框标记，帮助识别种子区域。
  - 网格其余区域散布若干 grey 的实心矩形"土壤区域"（宽度 ≥ 2，高度 ≥ 种子图案高度 H）。每个土壤矩形互不重叠。

- `Rule`：
  - 读取种子图案从上到下的颜色序列 [C1, C2, ..., CH]。
  - 对每个 grey 矩形土壤区域，从其底部第一行开始向上逐行染色：底部第一行染为 C1（种子最上方颜色），第二行染为 C2，依此类推，直到第 H 行染为 CH。
  - 若土壤区域高度大于 H，则第 H 行以上的 grey 像素保持 grey 不变。
  - 染色覆盖整行（土壤矩形的完整宽度）。
  - 种子图案本身和 maroon 边框保持不变。

- `Key insight`：种子图案的读取顺序是从上到下（C1 在顶），但应用到土壤时是从底部向上生长（C1 在底部）——这个"翻转映射"是最容易被忽视的细节。解题者可能直觉地认为种子顶部对应土壤顶部，但实际上种子顶部对应土壤底部，就像植物从种子向上生长一样。需要仔细对比样例才能发现这个方向反转。
</new_puzzle>
