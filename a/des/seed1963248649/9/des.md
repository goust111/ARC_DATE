# 第一步：分析与思考

## 参考题中的基础操作梳理

从20道参考题中提炼出以下核心操作族：

1. **位移与滑动**：像素/对象按某种规则移动（颜色编码方向、滑向边界、滑向锚点）。
2. **射线与传播**：从源点沿方向发射射线，遇障碍物反射/停止（对角反射、十字投射）。
3. **折叠与旋转**：绕标记点折叠杆件、绕中心旋转90度。
4. **镜像与对称补全**：以十字线为轴镜像复制标记。
5. **压缩与抽象**：噪声区域提取主色、格格降采样、丢弃干扰项。
6. **填充与区域操作**：洪泛填充可达区域、填充矩形、涂满行列。
7. **拼接与对齐**：分面板提取精灵、交错拼合、碎片互补成矩形。
8. **包含与删除**：包围盒嵌套判定后删除内部对象。
9. **方向编码**：形状缺口、三角朝向、骨牌水平/垂直 → 编码行为指令。
10. **分步消耗**：精灵逐步移动并消耗标记像素。

## 非显而易见的串联方式思考

- **信息多义编码**：同一个视觉特征同时承载两种语义——例如一个形状的颜色编码"做什么"，而它的朝向编码"对谁做"。参考题多是一对一映射，若一个属性同时指定操作类型和操作参数，解题者需要拆分出双重语义。

- **隐式分组后差异驱动**：对象们看似独立，但实际上通过某种隐含等价关系（如相同面积、相同凸包形状、相同连通度）分组，而输出取决于组内的"异常成员"或组间的差异。

- **拓扑性质作为条件**：颜色和形状都是表面特征，而"有没有洞""是否简单连通""欧拉数是多少"这类拓扑性质是人眼可见但不直觉的属性，可以作为分支条件。

- **相对空间关系生成绝对参数**：两个对象之间的相对距离或方向并非直接指示操作，而是编码了操作的幅度或角度——需要量化空间关系才能解码规则。

- **因果链条**：一个操作的结果改变了另一个操作的条件——比如先清除某些像素后，连通性发生变化，进而影响哪些区域被填充。

- **网格自身的全局几何**：网格尺寸、长宽比、对称性本身作为规则的一部分，而不仅仅是容器。

- **负空间的语义**：空白区域的形状本身携带信息——对象围成的空洞、边界间的缝隙形状可能才是真正的操作对象。

- **序关系与优先级的隐式编码**：对象的处理顺序不由位置或颜色显式标注，而是由某种结构属性（如面积、周长、离某参考点的距离）隐式排序，不同的排序产生不同的结果。

  - 对每个封闭矩形框，检查其内部 red 标记分别紧贴了哪些内壁方向（上、下、左、右四个方向的子集）。

  - 没有被 red 标记触碰的边保持原位不动。
  - 拉伸完成后，移除所有 red 标记像素（变为 black）。
  - 多个矩形框按距网格中心的曼哈顿距离从近到远依次处理（先处理的框拉伸完毕后作为后续框的障碍）。

- `Key insight`：红色标记像素贴靠内壁的位置不是装饰——它们是"方向开关"，选择性地激活矩形的某些边进行膨胀。解题者需要精确定位红点贴的是哪面墙，而非仅仅注意红点的存在。

<new_puzzle>
- `description`：网格中每个前景对象向正下方投射 grey 影子，影子长度等于该对象最高像素所在的行号——位置越低的对象影子越长。

- `Input structure`：
  - 背景为 black，网格行数不超过 20。
  - 网格中散布若干小型 4-连通单色对象（每个对象的颜色互不相同，使用 red、green、blue、yellow、magenta 等），每个对象占 2~4 个像素。
  - 各对象占据的列范围互不重叠（即不同对象不共享任何列），每个对象最底部像素的下方到网格底部有足够的 black 空间。

- `Rule`：
  - 保留所有原始对象不变。
  - 对每个对象，找到它最高像素所在的行号 r（从 0 开始计数，第0行为最顶行）。影子长度 L = r。
  - 对该对象占据的每一列 c，找到该列中属于该对象的最低像素所在行 b。从第 b+1 行开始，向下连续绘制 L 个 grey 像素在列 c 上。如果向下超出网格底部则截断。
  - 如果影子路径上遇到其他非 black 像素，该列影子在该处截断（不覆盖已有像素）。

- `Key insight`：影子长度不取决于对象的大小、形状或颜色，而取决于对象在网格中的垂直位置。这模拟了一种反直觉的"光照"模型——离顶部越远的物体影子越长。解题者需要从样例中推断出"行号=影子长度"这一精确数值关系。
</new_puzzle>

<new_puzzle>
- `description`：网格被 grey 分隔线分为若干格子，每个格子内的一个小黑点位置编码了指向相邻格子的方向指针；沿指针链追踪到环，将环上格子的底色回传给链上所有格子。

- `Input structure`：
  - 网格被 grey 像素构成的横竖线分割为一个规则的 M×N 格子阵列（例如 3×3 或 4×4），每个格子为正方形，内部大小为 3×3 像素。
  - 每个格子内部被某种颜色完全填充（非 grey、非 black），作为该格子的"底色"，不同格子的底色可能相同或不同。
  - 每个格子内部恰好有一个 black 像素作为"指针"。该 black 像素位于格子内部 3×3 区域的上边中点（第0行第1列）、下边中点（第2行第1列）、左边中点（第1行第0列）或右边中点（第1行第2列）之一，分别表示指向上方、下方、左方、右方的相邻格子。
  - 边缘格子的指针永远不指向网格外部（即最上行格子不会有向上指针，以此类推）。

- `Rule`：
  - 从每个格子出发，沿指针方向跳到相邻格子，再从相邻格子的指针继续跳，依此追踪。因为格子数有限且每个格子恰好一个出边，链路最终必定进入一个环。
  - 识别所有环：环上的格子底色保持不变。
  - 对于不在环上的格子（即汇入环的"尾巴"链上的格子），将其底色替换为该链所汇入的环上第一个被到达的格子的底色。
  - 输出中所有格子内的 black 指针像素恢复为该格子的最终底色（即指针消失）。
  - grey 分隔线保持不变。

- `Key insight`：每个格子内几乎看不到的小黑点是解题的关键——它编码了方向信息，将所有格子组织成有向图。解题者需要：(1) 发现黑点的方位含义；(2) 逐个追踪链路找到环；(3) 理解"颜色从环回流到链尾"的传播机制。难点在于黑点非常不起眼，容易被忽略。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干同色像素对通过"配对颜色"关联，一条 grey 分隔线充当过滤器——只有跨越分隔线的配对才被 L 形路径连接，同侧配对保持沉默。

- `Input structure`：
  - 背景为 black。
  - 网格中有一条完整的 grey 线横贯整个网格（占满某一整行或整一列），将网格分成两个半区。
  - 网格中散布若干彩色单像素，每种非 grey、非 black 颜色恰好出现两个像素（形成若干配对），颜色可能包括 red、blue、green、yellow、magenta、orange 等。
  - 每对同色像素可能都在分隔线同侧，也可能分居两侧。

- `Rule`：
  - 保留 grey 分隔线不变。
  - 对每对同色像素：
    - 如果两个像素在分隔线的**同一侧**，保留像素原样，不做操作。
    - 如果两个像素在分隔线的**不同侧**，用该颜色绘制一条 L 形路径连接它们：先从其中一个像素水平移动到与另一个像素同列的位置，再垂直移动到另一个像素。路径宽度1像素，路径上所有经过的 black 或 grey 像素都被该颜色覆盖。
  - 两个端点像素本身保留。
  - 多对路径如果交叉，交叉点颜色由后绘制的路径决定。处理顺序：按颜色对中两像素间曼哈顿距离从小到大依次处理（距离短的先画）。

- `Key insight`：分隔线是一个"激活过滤器"而非障碍物——它判定哪些颜色对需要连接（跨线的配对被激活，同侧的保持沉默）。解题者容易将 grey 线视为墙壁或镜面，但它实际上是条件判定器。辨认出这一角色需要反复比对哪些颜色对被连接、哪些没有。
</new_puzzle>

<new_puzzle>
- `description`：根据每个矩形色块与其邻居色块的数量关系，将色块重新着色——颜色完全由空间邻接拓扑决定，输入颜色是无关的干扰项。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个互不重叠的实心矩形色块（每个色块由某种非 black 颜色填充），色块之间至少隔一格 black。
  - 色块的颜色在输入中可能各不相同，也可能有重复。
  - 定义"相邻"：两个色块在水平方向或垂直方向上投影有重叠（即它们的行范围或列范围有交集），且在投影重叠方向的垂直方向上间距恰好为1格 black 像素。简单说，两个色块如果"几乎挨着"（仅隔1格且在对应轴上有重叠投影），就算相邻。

- `Rule`：
  - 对每个色块，统计其相邻色块的数量 N。
  - 按以下映射重新着色（形状和位置不变）：
    - N=0 → red
    - N=1 → blue
    - N=2 → green
    - N=3 → yellow
    - N≥4 → magenta
  - 背景 black 像素不变。

- `Key insight`：输出颜色与输入颜色完全无关——输入颜色的多样性是精心设置的干扰项。真正决定输出的是色块之间的空间邻接拓扑。解题者必须忽略颜色信息、转而分析"哪些色块互为邻居"，并且需要准确理解"相邻"的几何定义（投影重叠+间距为1），才能推断出颜色映射规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干不同大小的对象，大对象会"吞噬"距离自己最近的更小对象，吞噬后概念面积增大，可能在后续轮次中吞噬原本比它大的对象——一个多轮淘汰过程。

- `Input structure`：
  - 背景为 black。
  - 网格中有 5~8 个单色 4-连通对象，每个对象颜色互不相同（使用 red、blue、green、yellow、orange、magenta、azure、maroon 等），面积（像素数）也互不相同。
  - 对象之间不接触，有 black 间隔。

- `Rule`：
  - 进行多轮同步吞噬判定：
    - 每轮开始时，对每个存活对象，找到距离它最近的（两对象间最近像素对的曼哈顿距离）面积严格小于它的存活对象。如果存在，标记该小对象为"被吞噬"。
    - 如果某个小对象同时被多个大对象标记为目标，则由距离最近的那个大对象吞噬它（距离相同则由面积更大者吞噬）。
    - 本轮被吞噬的对象全部移除（像素变 black）。每个吞噬者的"概念面积"增加其吞噬的所有对象的面积之和（但吞噬者的形状和位置不变）。
  - 进入下一轮，使用更新后的概念面积重复上述过程。
  - 重复直到某轮没有发生任何吞噬。
  - 输出保留所有幸存对象的原始形状、位置和颜色，被吞噬对象的位置为 black。

- `Key insight`：这是一个"大鱼吃小鱼"的动态博弈。核心难点在于吞噬后面积的概念增长会改变后续轮次的大小关系——一个中等对象可能通过吞噬小对象而"升级"，在下一轮反过来威胁原本更大的对象。解题者需要模拟这个逐轮演化过程才能确定最终幸存者集合。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色对象的凸包与实际形状之间的"缺失区域"决定了该对象的变换方式——有缺口的对象被旋转，完美凸形的对象被平移。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干互不接触的单色 4-连通对象（颜色各不相同），每个对象的包围盒不超过 5×5。
  - 每个对象要么是"凸形"的（其像素完全填满自身的最小轴对齐凸包——即包围盒内所有行连续、所有列连续，没有凹陷），要么是"凹形"的（包围盒内存在属于凸包但不属于对象的 black 空洞像素，即存在凹陷缺口）。
  - 每个凹形对象的凹陷缺口恰好出现在包围盒的某一个角落区域（左上、右上、左下、右下之一）。

- `Rule`：
  - 对凸形对象（无缺口）：将其整体向网格最近的边缘方向平移，直到对象的包围盒贴紧网格边缘。若距两个边缘等距，选择向右或向下的方向（优先右，其次下）。原位置清除为 black。
  - 对凹形对象（有缺口）：确定缺口所在的角落方位。以对象包围盒中心为旋转中心，将对象旋转使缺口移动到对角位置（左上缺口→旋转180度使缺口到右下；右上→旋转180度到左下；等等）。旋转后的对象放置在原包围盒位置。
  - 所有变换互不干扰（先全部计算目标位置，再同时更新画布；如果平移后发生重叠则停在碰撞前的位置）。

- `Key insight`：对象的变换类型和参数不由颜色或大小决定，而由形状的"凸性"这一拓扑几何性质决定。凸形和凹形对象适用完全不同的规则（平移 vs 旋转），且凹形对象的旋转方向由缺口位置编码。解题者需要识别凸/凹分类这一非显而易见的判据。
</new_puzzle>
