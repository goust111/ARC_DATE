<reference_puzzle index="1" source="train" puzzle_id="9968a131" lines="10-27">
<description>
Shift alternating two-color row bars so each row aligns to the topmost bar's color columns.

Input structure:
- The dominant background surrounds horizontal two-pixel bars.
- Every foreground row has exactly one adjacent bar using the same two colors.
- The topmost bar gives the reference left/right column for each color.

Rule:
- Keep bars whose left color is already in its reference column.
- For a reversed bar, shift the whole two-pixel bar horizontally until its
  left color lands in that color's reference column.
- Background cells vacated by shifted bars become background.

Key insight:
- The rows are not recolored; each two-color bar is translated so equal
  colors line up with the topmost reference bar.
</description>
</reference_puzzle>

<reference_puzzle index="2" source="eval" puzzle_id="7491f3cf" lines="9-24">
<description>
Composite two pattern tiles into a fourth panel using flood-fill from an indicator pixel.

Input structure:
- Four 5×5 panels in one row, border-separated.
- Panel 0: cue pixels = wall boundary (8-connected, edge-to-edge, through center)
           + one 8-isolated indicator pixel.
- Panels 1–2: source patterns. Panel 3: blank (to fill).

Rule:
- Flood-fill (4-conn) from indicator, blocked by wall → inside region.
- Inside → non-bg from panel 1; outside → non-bg from panel 2.
- Wall → panel 1 if non-bg; panel 2 fallback when wall is 4-connected.

Key insight: The cue panel's isolated indicator and wall partition the tile into inside/outside masks that select between the two source panels.
</description>
</reference_puzzle>

<reference_puzzle index="3" source="eval" puzzle_id="64efde09" lines="68-83">
<description>
Copy colored control-ray ports from one rectangular sprite orientation to every matching transformed sprite.

Input structure:
- bg is the most common color.
- Several dense 2-by-N or N-by-2 rectangular sprites are dihedral transforms of one template.
- Isolated single-pixel control markers sit on rays projected outward from the dominant long edge of some sprites.

Rule:
- For each sprite, the active edge is the long side whose cells have the strongest same-color majority.
- A control marker seen first along an outward ray from an active-edge cell assigns its color to that template cell.
- On every transformed sprite, draw that assigned color outward from the corresponding active-edge cell through bg cells until blocked or out of bounds.

Key insight:
- The marker positions are not absolute; they label cells of a shared rectangular template, then the labels follow each sprite's rotation/reflection.
</description>
</reference_puzzle>

<reference_puzzle index="4" source="train" puzzle_id="494ef9d7" lines="16-30">
<description>
Slide each blue/teal or yellow/orange row pair together while preserving its left-to-right order.

Input structure
- The grid has a black background.
- Each nonempty row contains exactly two distinct foreground pixels.
- Blue/teal and yellow/orange row pairs are the moving pairs; other color pairs are distractors.

Rule
- For each moving pair, keep the left pixel fixed and move the right pixel left until it touches the left pixel.
- Clear the moved pixel's original location, and leave non-moving rows unchanged.

Key insight
- Only same-hue-family pixel pairs attract horizontally; separated unrelated colors do not compact.
</description>
</reference_puzzle>

<reference_puzzle index="5" source="train" puzzle_id="b5bb5719" lines="17-32">
<description>
Fill the background under a top-row red/grey span with a shrinking diagonal pattern that alternates red and grey.

Input structure:
- The grid has an orange background.
- All foreground pixels are red or grey and lie on the top row.
- The first and last top-row foreground pixels define an odd-width span.

Rule:
- Copy the input grid.
- For row r below the top, fill columns span_left + r through span_right - r.
- Each filled cell takes the top-row color r columns up-left, flipped red<->grey once per row step.

Key insight:
- The output is the top-row span propagated down-right along diagonals, while the allowable region shrinks inward from both ends each row.
</description>
</reference_puzzle>

<reference_puzzle index="6" source="train" puzzle_id="ff2825db" lines="18-36">
<description>
Select the majority interior marker color, then redraw the framed board as that color's frame plus its bounding-box outline.

Input structure:
- The top row is a copied palette made from adjacent equal color pairs.
- Below it is a one-cell-thick rectangular frame around a black interior.
- Non-black, non-frame interior pixels are marker colors; one marker color has
  the unique highest count.

Rule:
- Keep the palette row unchanged.
- Pick the uniquely most frequent interior marker color.
- Clear the lower board to black, recolor its outer frame with the picked color,
  and draw the picked color's interior bounding-box border.

Key insight:
- The noisy marker cloud is not preserved as pixels; only the majority marker
  color and its spatial extent define the output.
</description>
</reference_puzzle>

<reference_puzzle index="7" source="train" puzzle_id="98c475bf" lines="62-76">
<description>
Erase the complete interior glyph and expand each endpoint marker pair into its color's full glyph.

Input structure
- The grid is 20x20 with background inside two same-color full-height vertical frame bars.
- Inside the frame there is one complete color glyph and one or more other colors appearing only as two endpoint markers in the same row.
- Marker endpoints are always in the first and last interior columns.

Rule
- Keep the vertical frame unchanged.
- Erase any complete interior glyph.
- For each endpoint marker pair, use that marker color's learned glyph template and anchor its horizontal bar on the marker row.

Key insight
- Color identifies which glyph shape to draw; the two endpoint pixels are not copied objects, they are anchors for reconstructing that color's full symbol.
</description>
</reference_puzzle>

<reference_puzzle index="8" source="train" puzzle_id="4e7e0eb9" lines="31-49">
<description>
Transform each 9x9 panel by mirroring across its center guide line or filling all four block slots from its lone exemplar.

Input structure
The grid is made of 9x9 panels separated by one-cell-wide grid lines. Each
panel has four monochrome 3x3 slots at the quadrant positions, with either a
full non-background center row, a full non-background center column, or no
guide line.

Rule
A panel with a full center column is reflected left-to-right, and a panel
with a full center row is reflected top-to-bottom. A panel with no guide line
has exactly one slot color that appears once and one slot color that appears
three times; recolor all four slots to the once-occurring slot color.

Key insight
The center guide line encodes the mirror axis, while panels without a guide
line are completed by copying the structurally unique slot color.
</description>
</reference_puzzle>

<reference_puzzle index="9" source="eval" puzzle_id="2ba387bc" lines="6-21">
<description>
Sort scattered 4×4 squares into two columns by type: frames left, solids right.

Input structure:
- bg = most common color. Multiple 4×4 objects on bg.
- Frames: colored 1px border, bg-filled 2×2 interior.
- Solids: entirely filled with one non-bg color.

Rule:
- Classify each 4×4 object as frame or solid by its interior.
- Sort each group top-to-bottom by input row.
- Stack frames in left column (cols 0–3), solids in right (cols 4–7).
- Output is 8 wide; height = 4 × max(#frames, #solids), bg-padded.

Key insight: Frame vs solid is determined solely by whether the 2×2 interior matches bg.
</description>
</reference_puzzle>

<reference_puzzle index="10" source="eval" puzzle_id="aa4ec2a5" lines="52-66">
<description>
Add red outlines around objects, and mark enclosed holes inside hollow objects.

Input structure:
- A mostly uniform background contains one or more 4-connected foreground objects.
- Some objects may enclose 4-connected background holes inside their bbox.

Rule:
- For every foreground component, draw a one-cell 8-neighborhood outline in red (2).
- If a component has enclosed background holes, recolor the component to teal (8).
- Fill those enclosed holes with magenta (6) before drawing the outline.

Key insight: Holes are treated as part of the object for outlining, while only objects
that actually enclose holes get the teal/magenta interior recoloring.
</description>

Complete the scene by adding the point-reflected copy of the colored object across the central marker.

<reference_puzzle index="12" source="eval" puzzle_id="142ca369" lines="6-19">
<description>
Trace diagonal rays from triangular arrows, reflecting off colored wall pixels.

Input structure:
- bg grid with monochrome 3-pixel L-shaped "arrows" (2x2 bbox missing one corner) and scattered colored wall pixels.

Rule:
- Each arrow fires a ray diagonally away from its missing corner, painting bg cells in its color.
- A head-on wall hit reverses both axes; a side-touch wall hit flips the touched axis only.
- On any bounce the ray adopts the wall's color and recolors the contact cell.
- Ray stops when it exits the grid or reaches another arrow.

Key insight: Two distinct reflection types (corner vs side-touch) plus color inheritance at each bounce drive the path geometry.
</description>
</reference_puzzle>

<reference_puzzle index="13" source="train" puzzle_id="f8cc533f" lines="10-25">
<description>
Complete every colored sprite by applying the union of all aligned partial sprite masks.

Input structure:
- The dominant color is the background.
- Each non-background color appears as a separated partial copy of one common sprite mask.
- The copies share a top-left-aligned sprite window; some copies may be missing lower or right edge pixels.

Rule:
- Crop each same-color mask to its bounding box.
- Pad the crops to the maximum observed height and width, aligned at the top-left, and OR them into one complete template.
- Fill that template at every sprite location using the sprite's own color.

Key insight:
- No single input sprite is complete, but their missing cells are complementary, so the aligned union reveals the full mask.
</description>
</reference_puzzle>

Count same-color patterns per frame and represent the tally as dots inside.

Input structure:
- bg = most common color.
- Hollow rectangular frames in various colors.
- Small monochrome pattern sprites scattered outside frames.

Rule:
- Remove all small patterns from the grid.
- For each frame of color C, count how many patterns share color C.
- Draw that many dots along the frame's center row, spaced by 2, starting from the right.

<description>
Paint straight rays from colored side markers into the hollow diamond frame until an interior foreground pixel blocks each ray.

Input structure
- The background contains one complete one-pixel-thick diamond frame.
- Colored marker pixels outside the diamond sit on the top, bottom, left, or right side of the frame's bounding box.
- Any non-background, non-frame pixels inside the diamond are blockers that remain unchanged.

Rule
- Each outside marker emits inward perpendicular to its side of the diamond bounding box.
- Along that row or column, paint only background pixels strictly inside the diamond with the marker color.
- Stop a ray when it reaches an existing interior foreground pixel; keep the frame and all original colored pixels unchanged.

Key insight
- The diamond frame defines a strict interior, while the side markers are column or row emitters whose color fills the visible interior interval until blocked.
</description>

- The grid is a uniform background field with exactly one foreground pixel.

Rule
- Find the grid corner with the smallest Manhattan distance to the foreground pixel.
- Recolor every pixel in the inclusive axis-aligned rectangle bounded by that

  nearest corner of the whole canvas.

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 若涉及计算，只允许使用简单的计数、排序与数量比较；不允许使用复杂的数学公式或运算。
3. 问题必须能从少量示例中推断出来，但不代表题目一定简单。设计时需从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息或需要推算的隐藏属性。规则可以很难发现，难到反复对比所有样例仍需要深度思考才能归纳出来，但一旦发现后必须能用来解释所有样例且产出唯一确定的输出。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入/输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 “red”。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 五个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7.  题目难度应来自机制的隐蔽性而非步骤数。关键信息难以准确定位，需要反复对比尝试不同的角度才能发现真正的规则。


生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述20道参考题相同或者是类似，不可只是替换了颜色、方向、对象类型、维度等表层要素。判断标准：新题的核心推理路径（解题者从样例中归纳规则的认知过程）应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5个样例中发现规律。
