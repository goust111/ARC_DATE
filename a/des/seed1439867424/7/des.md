# 第一步：分析与思考

## 参考题中的基础操作分类

纵观20道参考题，可以提炼出以下基础操作族：

1. **空间映射与变形**：缩放（#1拉伸精灵到框架内部）、剪切（#10行偏移形成对角线）、镜像/反射（#5红色标记轴反射）、平移（#19对角移动）。
2. **模板匹配与印章**：识别模板后复制粘贴到指定位置（#6瓦片复制、#12锚点印章、#16标记交叉点印章、#4部分匹配补全）。
3. **框架与区域交互**：框架内部操作（#1、#3、#16）、分隔线划分瓦片（#6、#15、#20）。
4. **编码与解码**：颜色图例映射（#3）、查询表查找（#17）、角落L编码三角形参数（#11）、少数单元格内部图案编码全局分布（#20分形自相似）。
5. **路径与连通性**：路径搜索与障碍物回避（#8安全路线）、重力下落（#18）、切割与滑动（#14）。
6. **冗余与修复**：多副本投票恢复受损图案（#15）。
7. **组装与拼合**：散件拼成框架（#2）、计数转化为条形（#7）。
8. **条件分支**：根据标记几何形态选择不同操作（#5线段vs单点、#9灰色vs粉色方块）。

## 非显而易见的串联方式

- **图案自身编码其变换参数**：不仅仅是"图案→复制"，而是图案的某个几何属性（如连通分量数、凸包形状、对称性类型）决定了对它执行什么操作或如何参数化操作。
- **空间位置编码语义角色**：一个对象在网格中的绝对位置或相对于其他对象的拓扑关系（包围、邻接、穿越）决定它是"指令"还是"数据"。
- **视觉遮挡作为信息通道**：两个图层重叠时，被遮挡的部分恰好携带关键信息——需要"透视"还原。
- **负空间承载规则**：不是前景像素定义变换，而是背景区域的形状/连通性/面积比才是真正的线索。
- **时间序列折叠到空间**：网格的不同行/列代表同一过程的不同时间步，输出是该过程的终态或某个统计量。
- **自指与递归**：输出的一部分可以作为输入再次执行同一规则，形成不动点或收敛状态。

## 创新方向的思考

参考题大多遵循"识别对象→确定规则→应用变换"的线性流程。真正新颖的题目可以探索：
- 规则本身隐藏在输入的某个"元层"中，需要先解码规则再应用
- 对象之间的**关系网络**（而非单个对象的属性）决定输出
- 需要构建中间表示（如图、序列）才能推导出输出
- 视觉上的"噪声"实际上是编码信息的载体
- 输出的结构与输入完全不同类型（如输入是散点、输出是路径图）

<new_puzzle>
- `description`：根据每个彩色区域的"视觉重心"方向，将区域内所有像素沿重心偏移方向平推至边界，形成压缩后的色带。
- `Input structure`：
  - 背景为 black。
  - 网格中散布若干个不同颜色的4-连通区域（每种颜色只出现一个区域），每个区域形状不规则但连通，面积在4到15像素之间。
  - 每个区域的质心（所有像素坐标的算术平均）相对于其外接矩形中心存在一个明确的偏移方向（上、下、左或右之一，取偏移量绝对值最大的轴方向）。
- `Rule`：
  - 对每个彩色区域，计算其所有像素行坐标的平均值和列坐标的平均值，得到质心 (cr, cc)。
  - 计算其外接矩形的中心 (mr, mc)。
  - 比较 cr-mr 和 cc-mc 的绝对值：若行方向偏移更大，则方向为上（cr<mr）或下（cr>mr）；若列方向偏移更大，则方向为左（cc<mc）或右（cc>mc）。
  - 将该区域的所有像素沿该方向平移，直到区域整体碰到网格边缘（即区域在该方向上最前沿的像素到达网格边界的第0行/最后行/第0列/最后列）。
  - 平移后的像素保持原色，原位置变为 black。若多个区域平移后发生重叠，则后处理的区域覆盖先处理的（处理顺序为区域面积从小到大）。
- `Key insight`：每个区域的运动方向不是由任何外部标记指定的，而是由区域自身形状的不对称性（质心相对于外接矩形中心的偏移）隐式编码的——形状"偏向哪边重"，就向那边滑动。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中散落的彩色线段，将每条线段解释为"扫描线"，用该线段的颜色填充其扫过的矩形带区域。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干条彩色线段（每条线段是严格水平或严格垂直的连续同色像素串，长度≥2），颜色各不相同。
  - 每条线段的一个端点处有一个 grey 像素紧邻（4-连通方向），该 grey 像素位于线段的延长线方向之外（即垂直于线段方向的某一侧）。grey 像素指示扫描方向。
  - 在线段的延长线方向上（线段指向的两端之一），存在一个同色的单独像素（孤立点），该孤立点与线段端点在同一行或同一列上，两者之间全为 black，孤立点标识扫描终止位置。
- `Rule`：
  - 对每条彩色线段：
    - grey 像素相对于线段的位置（上/下/左/右）确定扫描的垂直方向。
    - 同色孤立点与线段最近端点之间的距离确定扫描的宽度（即线段需要沿扫描方向移动多少步）。
    - 从线段当前位置开始，沿 grey 指示的方向逐行/逐列复制线段，共复制"宽度"次，形成一个实心矩形带，颜色为线段颜色。
  - 原始线段保留在矩形带内，grey 像素和孤立点从输出中移除（变为 black）。
- `Key insight`：每条线段配有两个辅助标记——grey 像素指定法线方向，同色孤立点指定扫描距离——线段本身是"刷子"，灰点是"推的方向"，孤立点是"推到哪里停"。三者协作定义一个填充矩形，但它们在视觉上分散，需要分别识别并关联。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多个同色"种子"像素同时生长为以种子为中心的同心菱形环，环的层数由该种子所在封闭区域的面积决定；不同种子的生长区域相遇时互相阻挡。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 grey 像素绘制的封闭围栏（每个围栏是一个一像素宽的4-连通闭合环，围成一个封闭的矩形或近似矩形区域）。
  - 每个封闭区域内部恰好有一个彩色种子像素（颜色为 red、blue、green、yellow 等，各种子颜色可相同也可不同）。
  - 围栏之外的区域全为 black，不含任何种子。
- `Rule`：
  - 移除所有 grey 围栏像素（变为 black），释放整个网格为自由空间。
  - 对每个种子，计算其原先所在封闭区域的内部面积（围栏内 black 像素数 + 1个种子像素 = 总内部像素数）。
  - 每个种子同时开始"生长"：以种子坐标为中心，按曼哈顿距离逐层向外扩展同心菱形环，第 k 层（k=1,2,...）为所有曼哈顿距离恰好等于 k 的像素。总共生长的层数 = 该种子原始封闭区域的内部面积（含种子自身）。
  - 生长过程中，若某层的某个像素已被其他种子的早期层占据，则该像素不被覆盖（先到先得）。若两个种子在同一层同时到达同一像素，则该像素保持 black（互相抵消）。
  - 种子本身保留其原色，生长出的所有像素也使用该种子的颜色。
- `Key insight`：围栏在输出中完全消失，但它编码了关键参数——每个种子的生长半径。解题者需要意识到围栏面积不是装饰而是"能量储备"，面积越大的种子扩展得越远。竞争性生长的先到先得和同时抵消机制使得最终图案不可简单叠加，需要逐层推演。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片拼成一个完整矩形拼图，拼合顺序和位置由碎片边缘的颜色编码锯齿接口决定。
- `Input structure`：
  - 背景为 black。
  - 网格中散布若干个彩色矩形块（每块为单一前景色填充的实心矩形，各块颜色不同，尺寸不一但高度或宽度中至少有一个维度相同）。
  - 每个矩形块的某些边缘像素被替换为 maroon 像素，形成"接口凸起"：在该边缘向外延伸一个像素的位置有一个与该矩形块同色的像素（形成凸起），而边缘上对应位置的原像素变为 maroon。
  - 同时，某些边缘像素被替换为 maroon 并且该位置没有向外凸起，形成"接口凹槽"。
  - 两个矩形块可以拼合当且仅当：一个块的凸起恰好嵌入另一个块的凹槽——即凸起的位置和凹槽的位置在拼合后完全互补匹配。
- `Rule`：
  - 找到所有矩形块及其边缘接口（凸起和凹槽的位置模式）。
  - 通过匹配凸起-凹槽对，确定块之间的邻接关系和相对位置。
  - 将所有块平移拼合成一个无缝的大矩形。拼合后，凸起像素填入凹槽位置，maroon 标记消失，恢复为各块的原色。
  - 输出为拼合后的完整矩形（输出网格尺寸恰好等于拼合后矩形的尺寸）。
- `Key insight`：maroon 标记的边缘像素不是装饰，而是类似拼图锯齿的接口编码。凸起和凹槽的空间排列模式是唯一的匹配钥匙——每对相邻块的接口模式互补，这决定了全局拼合方案。解题者需要将"颜色替换"理解为"形状锁扣"。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每个彩色对象解释为一个"投影指令"，根据对象的朝向在背景墙面上投射该对象的正交投影阴影。
- `Input structure`：
  - 背景为 black。
  - 网格的四条边缘各有一条不同颜色的单像素宽边框线（上 = azure，下 = orange，左 = green，右 = magenta），这四条线代表四面"墙壁"。
  - 网格内部散布若干个彩色对象（4-连通，颜色为 red、blue、yellow 等，不与墙壁颜色重复）。
  - 每个对象内部恰好有一个像素被替换为 grey，这个 grey 像素的位置相对于对象的外接矩形中心指示投影方向：grey 在对象上半部→向上投影到 azure 墙；grey 在下半部→向下投影到 orange 墙；grey 在左半部→向左投影到 green 墙；grey 在右半部→向右投影到 magenta 墙（以 grey 相对于外接矩形中心的最大偏移轴判断）。
- `Rule`：
  - 对每个彩色对象，根据其内部 grey 像素确定投影方向（上/下/左/右）。
  - 沿投影方向，对该对象做正交投影：将对象沿投影方向"压扁"到对应墙壁上。
    - 向上/向下投影：投影结果是一条水平线段，长度等于对象在水平方向的跨度（即对象占据的列范围），绘制在对应墙壁行上，颜色为该对象的颜色。
    - 向左/向右投影：投影结果是一条垂直线段，长度等于对象在垂直方向的跨度（即对象占据的行范围），绘制在对应墙壁列上，颜色为该对象的颜色。
  - 原始对象和 grey 标记从输出中移除（变为 black）。四面墙壁保留，墙壁上叠加各对象的投影线段。若同一墙壁位置收到多个投影，保留最后一个（按对象面积从小到大处理）。
- `Key insight`：每个对象内嵌的 grey 像素同时编码了两条信息——投影方向和投影目标墙壁。解题者首先要识别出四面彩色墙壁的角色，然后理解 grey 点不是噪声而是"聚光灯方向"，最后将三维投影概念映射到二维网格操作上。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到隐藏的"传送门"配对，将每个传送门入口一侧的图案通过传送门传输并旋转后出现在配对出口的另一侧。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干条彩色线段（水平或垂直，长度≥3，颜色各异），每种颜色恰好出现两条相同长度的线段——它们构成一对"传送门"。
  - 每条传送门线段的一侧（沿线段法线方向）有一个由 grey 像素构成的小图案（4-连通，面积2到8像素），另一侧为空（全 black）。
  - 两条配对线段（同色同长度）各自有图案的一侧可能朝不同方向。
- `Rule`：
  - 配对同色同长度的两条线段为一组传送门 (A, B)。
  - 对于传送门 A：取其有图案一侧的 grey 图案，将该图案相对于线段 A 的局部坐标进行变换——旋转使其适应线段 B 的朝向（若 A 水平而 B 垂直则旋转90度，若两者平行则不旋转），然后将变换后的图案放置在线段 B 的无图案一侧对应位置。
  - 对传送门 B 执行对称操作：将 B 侧的图案变换后放到 A 的空白侧。
  - 传输后的图案颜色从 grey 变为该传送门对的颜色。
  - 原始 grey 图案保留不变（仍为 grey），传送门线段本身也保留。
- `Key insight`：同色同长度的线段是"传送门配对"的视觉线索。每个传送门将一侧的图案"传送"到配对传送门的另一侧，传送过程中可能涉及旋转（因为两个传送门朝向可能不同）。解题者需要先发现配对规则，再理解图案的"穿越"和旋转变换逻辑。
</new_puzzle>

- `description`：将网格视为一个状态机的展开图：每行是一个时间步，特定颜色的像素根据其邻居状态按隐含的局部规则演化，输出为演化若干步后的终态行。
- `Input structure`：
  - 背景为 black。
  - 网格从上到下分为若干行组（每组之间由一行 grey 分隔线隔开）。
  - 第一组只有一行，包含由 red 和 black 像素构成的初始状态。
  - 后续每组也只有一行，是前一组按某个局部规则演化一步后的结果。
  - 最后一组之后有一行 azure 分隔线，接着是一行全 black 的待填区域（与其他行等宽）。
- `Rule`：
  - 从已给出的连续状态行中推断一维元胞自动机规则：每个像素的下一状态由其自身及左右两个邻居（共3个像素）在当前步的状态决定。总共有 2^3 = 8 种输入组合，每种对应输出 red 或 black。
  - 根据已给出的所有状态转换行验证并确定唯一的规则编号。
  - 将最后一个给出的状态行按该规则再演化一步，填入 azure 分隔线下方的待填区域。
  - 输出网格与输入网格完全相同，仅待填区域从全 black 变为演化结果。
- `Key insight`：给出的多行状态并非独立的多个对象，而是同一过程的时间展开。解题者需要将"空间排列的多行"重新解读为"时间序列"，然后从相邻行的逐像素对应关系中归纳出局部演化规则，最终预测下一步。关键难点在于识别"行=时间步"这一非空间的语义映射。
</new_puzzle>

<new_puzzle>
- `description`：根据网格中彩色路径的交叉模式推断"上下穿越"关系，在每个交叉点处用正确的颜色覆盖表示哪条路径在上方。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干条彩色路径（每条路径是一像素宽的4-连通连续线段序列，允许直角转弯，每条路径使用不同的颜色如 red、blue、green、yellow 等）。
  - 路径之间存在交叉点：两条不同颜色的路径经过同一个像素。在输入中，每个交叉点的像素被标记为 grey（因为两条路径重叠，无法同时显示两种颜色）。
  - 每条路径的两个端点（路径的起止位置，即只有一个4-连通邻居的像素）中，恰好有一个端点旁边（8-连通邻域中）有一个 maroon 像素作为"优先标记"。
- `Rule`：
  - 追踪每条彩色路径，将 grey 交叉点视为属于所有经过该点的路径。
  - 对每条路径，确定其"优先端"——即有 maroon 标记的那个端点。
  - 在每个 grey 交叉点处，比较经过该交叉点的两条路径：对每条路径，计算从其优先端沿路径到达该交叉点的步数（曼哈顿路径距离）。步数较少的路径"在上方"。
  - 将该交叉点的 grey 像素替换为"在上方"那条路径的颜色。
  - 移除所有 maroon 标记像素（变为 black）。其余像素不变。
- `Key insight`：grey 交叉点的最终颜色不是随机选择的，而是由一种"优先级距离"决定的——离优先端更近的路径"先到"交叉点，因此在上方。maroon 标记表面上看是端点装饰，实际上定义了每条路径的距离计算起点，从而在所有交叉点建立了一致的上下层叠关系。解题者必须同时发现三个机制：路径追踪、优先端识别、距离比较。
</new_puzzle>
