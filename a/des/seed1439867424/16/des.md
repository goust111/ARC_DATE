# 第一步：分析与思考

## 参考题中的基础操作归纳

从20道参考题中可以提取出以下核心操作类别：

1. **空间位移与方向**：对象沿某方向移动（题1按面积下移、题11移到边缘、题12按缺口方向滑动、题14拼合矩形）。位移量、方向由对象自身属性决定。
2. **拓扑/图结构推理**：将网格中的空间元素解读为图论中的节点和边（题3最短路径、题18环形连接器确定旋转顺序）。
3. **模式复制与模板操作**：用一个区域的图案去覆盖/填充另一个区域（题2克罗内克积、题4图例展开、题7精灵码互换、题8归一化印章、题16角落图案复制）。
4. **属性分离与重组**：对象的不同属性（颜色、高度、形状、大小）被独立操纵或交换（题13颜色右移高度左移、题10按面积重新排列为方块）。
5. **遮挡与层序重建**：从可见碎片推断层叠顺序（题5环形精灵遮挡排序）。
6. **形状识别与分类**：根据几何特征（完整正方形、有缺口、孔洞数量）对对象分类并差异化处理（题6标记正方形角、题12按缺口分类、题20按孔洞数匹配）。
7. **距离场/辐射填充**：以某点为中心按距离规则填充（题17曼哈顿距离环）。
8. **编码/解码**：网格中的视觉元素编码了非视觉信息（题15梳状结构编码计数、题19对角象限编码方向）。

## 非显而易见的串联方式思考

- **属性交叉继承**：一个对象的颜色来自另一个对象，而其形状来自第三个对象，位置由第四个对象决定。这种多源属性组装在参考题中较少见。
- **空间关系作为运算指令**：对象之间的相对位置不仅是布局信息，还可以编码具体的变换操作（如：左边代表旋转，上方代表翻转）。
- **输出网格尺寸由输入内容决定**：输入中某个隐含的数值属性（如对象个数、某种标记的分布）决定了输出网格的维度。
- **路径追踪 + 信息收集**：沿某条路径移动的过程中，路径上遇到的元素决定了最终输出的某些属性。
- **负空间推理**：关键信息隐藏在对象之间的空白区域，而非对象本身。需要观察"不存在的东西"来推断规则。
- **自指结构**：网格中的某个元素描述了对其他元素应施加的变换——变换指令和被变换对象共存于同一网格。
- **全局统计量驱动局部行为**：某个局部对象的变换参数不来自它自身，而来自对全网格的某种统计（如同色对象个数、某种颜色的总面积等）。
- **拓扑邻域属性决定内容**：一个区域内部应绘制的内容不取决于它自身的颜色或形状，而取决于它和周围邻居之间的拓扑关系。

- `description`：根据每个封闭框架周围标记颜色中"缺失"的那种颜色，来填充该框架内部。

- `Input structure`：
  - 背景为 black。
  - 网格中存在若干由 grey 像素构成的封闭矩形框架（单像素宽的空心矩形），框架之间不重叠、不接触。
  - 每个框架的外侧紧邻处（即框架外边缘正交相邻的像素位置）分布着若干彩色单像素标记，颜色取自 {red, blue, green, yellow} 中的若干种。
  - 框架内部全部为 black（空白）。
  - 整个网格中恰好使用了 {red, blue, green, yellow} 这四种非黑非灰颜色作为标记色。每个框架外侧的标记恰好涵盖了这四种颜色中的三种，"缺少"其中一种。

- `Rule`：
  - 首先，识别网格中出现的所有非 black、非 grey 的颜色，得到"全局颜色集合"（即 {red, blue, green, yellow}）。
  - 对于每个 grey 矩形框架，收集其外侧正交相邻位置上所有彩色标记的颜色种类集合。
  - 用全局颜色集合减去该框架外侧已有的颜色种类，得到恰好一种"缺失颜色"。
  - 用该缺失颜色填充该框架的整个内部区域（将内部的 black 像素替换为该颜色）。
  - 框架本身（grey 像素）、外侧标记和背景保持不变。

- `Key insight`：解题的关键不在于观察框架内部有什么，而在于观察框架外部标记中"缺少了什么"。需要先建立全局颜色集合，再对每个框架做集合差运算，通过"缺席"的颜色来确定填充色。信息编码在"不存在"之中，这是一种负空间推理。
</new_puzzle>

<new_puzzle>
- `description`：每个对象沿其内部箭头所指方向移动，移动距离等于网格中同色对象的总个数。

- `Input structure`：
  - 背景为 azure。
  - 网格中散布着若干个小型 3×3 对象，每个对象用单一非背景颜色绘制成"T 形箭头"图案，指示一个方向（上、下、左、右之一）。
  - 箭头的绘制方式：在 3×3 区域中，中心行（或中心列）的三个格子全部填充对象颜色作为"箭杆"，箭头所指方向那一端的垂直（或水平）两侧各再填充一个像素作为"箭头尖端"，共 5 个有色像素。具体地：
    - 向右箭头：(0,2), (1,0), (1,1), (1,2), (2,2) 填色。
    - 向左箭头：(0,0), (1,0), (1,1), (1,2), (2,0) 填色。
    - 向上箭头：(0,0), (0,1), (0,2), (1,1), (2,1) 填色。（注意不是标准上箭头形状，这里(0,0)(0,2)是箭头尖端两翼）
    - 向下箭头：(0,1), (1,1), (2,0), (2,1), (2,2) 填色。
  - 每个对象有一种颜色（可选 red、blue、green、yellow、maroon），同一颜色可能出现多个对象。
  - 对象之间在初始状态下不重叠，移动后也不会重叠或超出网格边界。

- `Rule`：
  - 对于每种非背景颜色 C，统计网格中颜色为 C 的对象总数，记为 N_C。
  - 每个对象根据其 3×3 箭头图案确定移动方向。
  - 每个对象沿该方向移动 N_C 个像素（N_C 为该对象所属颜色的对象总数）。
  - 将对象绘制在新位置，原位置恢复为 azure 背景。

- `Key insight`：箭头图案提供方向信息，但移动距离并非由对象自身的大小或位置决定，而是由"网格中与我同色的对象一共有几个"这一全局统计量决定。解题者需要同时理解两个独立信息源：局部的方向编码（箭头形状）和全局的颜色计数（同色对象数目）。
</new_puzzle>

<new_puzzle>
- `description`：根据网格底部的颜色优先级条，重新裁定彩色路径在交叉点处的层叠归属。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条单像素宽的彩色路径，每条路径使用一种独特颜色（如 red、blue、green、yellow、orange），每种颜色只出现一条路径。
  - 每条路径是一条 4-连通的连续像素链，从网格的某一条边延伸到另一条边。
  - 部分路径产生交叉：交叉点处恰好有两条路径想要共享同一像素位置。在输入中，交叉点的颜色被任意设为两条交叉路径中某一条的颜色（不反映真正的优先级）。
  - 网格最底行是一条"优先级条"：该行中，从左到右依次排列着所有路径颜色的单个像素，颜色之间用 grey 像素分隔。左侧代表最高优先级，右侧代表最低优先级。

- `Rule`：
  - 从底部优先级条中读取颜色排列顺序：最左边的颜色优先级最高，最右边最低。
  - 识别所有路径交叉点。交叉点的判定方法：一个像素 P 是交叉点，当且仅当 P 被染为颜色 A，但 P 的四邻域中有两个不相邻的像素被染为颜色 B（B ≠ A 且 B ≠ black），说明颜色 B 的路径也经过 P 点。
  - 对于每个交叉点，比较交叉的两种颜色的优先级，将该像素设置为优先级较高的颜色。
  - 移除底部优先级条（最底行全部设为 black）。
  - 所有非交叉点像素保持不变。

- `Key insight`：输入中交叉点的现有颜色可能是误导性的。真正决定交叉点归属的优先级关系编码在底部那一行看似无关的颜色排列中。解题者需要发现这条色条是"优先级图例"，其左右顺序编码了路径层叠的高低关系。
</new_puzzle>

<new_puzzle>
- `description`：将被分隔线划分的彩色区块内部雕刻出该区块"非空邻居数"对应的点阵数字。

- `Input structure`：
  - 背景为 black。
  - 网格被 grey 单像素宽的水平线和垂直线划分为规则的矩形区块网格（如 4×4 或 5×5 的区块阵列），每个区块大小相同（至少 7×7 像素，以容纳数字图案）。
  - 部分区块内部被填充为某种单一非黑非灰颜色（如 red、blue、green、yellow、orange），称为"有色区块"。
  - 其余区块内部为 black，称为"空白区块"。
  - grey 分隔线本身不属于任何区块。

- `Rule`：
  - 对于每个有色区块，统计其上下左右四个正交方向上直接相邻的有色区块数量（0 到 4），记为 N。
  - 在该区块内部的正中央位置，用 black 像素绘制数字 N 的 3×5 点阵图案（宽 3 像素、高 5 像素）。3×5 点阵数字的具体定义如下（1 表示 black 雕刻像素，0 表示保持区块颜色）：
    - 数字 0：行1=[1,1,1], 行2=[1,0,1], 行3=[1,0,1], 行4=[1,0,1], 行5=[1,1,1]
    - 数字 1：行1=[0,1,0], 行2=[1,1,0], 行3=[0,1,0], 行4=[0,1,0], 行5=[1,1,1]
    - 数字 2：行1=[1,1,1], 行2=[0,0,1], 行3=[1,1,1], 行4=[1,0,0], 行5=[1,1,1]
    - 数字 3：行1=[1,1,1], 行2=[0,0,1], 行3=[1,1,1], 行4=[0,0,1], 行5=[1,1,1]
    - 数字 4：行1=[1,0,1], 行2=[1,0,1], 行3=[1,1,1], 行4=[0,0,1], 行5=[0,0,1]
  - 空白区块保持不变（仍为 black）。
  - grey 分隔线保持不变。
  - 区块填充颜色保持不变，仅在中央叠加黑色数字。

- `Key insight`：每个区块中显示的数字不取决于它自身的颜色或在网格中的绝对位置，而是取决于"有多少个相邻区块是非空的"这一拓扑邻域属性。解题者需要忽略颜色差异（颜色只是装饰），转而关注区块之间的空间邻接关系，发现每个数字恰好等于该区块上下左右四个方向上有色邻居的计数。
</new_puzzle>

- `description`：根据每个对象的"影子投射方向"（由颜色冷暖分类决定），将对象压缩为一维线段投影到网格边缘的对应轴上。

- `Input structure`：
  - 背景为 black。
  - 网格的最左列为 grey 像素（垂直投影轴），最顶行为 grey 像素（水平投影轴），左上角像素为 grey。
  - 网格内部（排除 grey 轴之外的区域）散布着若干个单色填充的矩形对象，颜色互不相同，且不与 grey 边缘重叠。
  - 对象的颜色分为两类：
    - "暖色"组：red、orange、yellow、maroon。
    - "冷色"组：blue、green、azure。
  - 所有对象之间不重叠。

- `Rule`：
  - 对于每个"暖色"矩形对象，向左投影：确定该对象占据的行范围 [r1, r2]，将最左列 grey 轴上第 r1 行到第 r2 行的像素替换为该对象的颜色。
  - 对于每个"冷色"矩形对象，向上投影：确定该对象占据的列范围 [c1, c2]，将最顶行 grey 轴上第 c1 列到第 c2 列的像素替换为该对象的颜色。
  - 投影完成后，所有原始矩形对象从网格内部移除（恢复为 black）。
  - 若两个同类对象的投影范围在轴上有重叠，重叠区域的像素取面积较大的对象的颜色。
  - 非轴的 grey 像素和 black 背景保持不变。

- `Key insight`：颜色的"冷暖"分类决定了投影的目标轴——暖色投影到左侧垂直轴（保留行跨度信息），冷色投影到顶部水平轴（保留列跨度信息）。这是一条隐含的分类规则，需要从多个样例中归纳：解题者必须注意到 red/orange/yellow/maroon 总是向左投影，而 blue/green/azure 总是向上投影，从而发现颜色语义属性（冷暖）与投影方向之间的对应关系。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色对象被"吸引"向网格中与它面积最接近的另一个对象移动，直到两者边界相邻。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干个不规则形状的单色 4-连通对象，每个对象使用不同的颜色（可选 red、blue、green、yellow、orange、maroon、magenta），颜色各不相同。
  - 对象的面积（像素数）各不相同。
  - 对象之间间距足够大，不相邻也不重叠。
  - 对象总数为偶数。

- `Rule`：
  - 计算每个对象的面积（像素总数）。
  - 将所有对象按面积从小到大排序，然后两两配对：面积最小的与面积第二小的配对，面积第三小的与面积第四小的配对，依此类推。即排序后第 1 和第 2 配对、第 3 和第 4 配对……
  - 对于每一对对象，计算两者边界框中心之间的方向，然后将两者沿该方向（各自朝对方方向）平移，直到两个对象的像素在正交方向上刚好相邻（即一个对象的某个像素与另一个对象的某个像素四邻域相接，但不重叠）。
  - 具体移动方式：先确定两个对象中心连线的主方向（水平或垂直，取 |Δcol| 与 |Δrow| 中较大者对应的方向）。两个对象均沿该主方向朝对方移动相同的步数，直到恰好相邻。如果沿主方向无法相邻（存在垂直偏移），则较小面积的对象还需沿副方向调整，使两者可以相邻。
  - 对象形状不变，颜色不变，仅位置改变。背景保持 black。

- `Key insight`：配对规则隐藏在面积排序中——不是最近的对象相互吸引，也不是同色配对，而是面积最接近的两个对象会配成一对并相互靠拢。解题者需要跳出"空间邻近"或"颜色相似"的直觉，转而计算面积并发现排序配对这一非直觉规则。
</new_puzzle>

<new_puzzle>
- `description`：将每个封闭房间中的彩色碎片重组为该房间形状的缩小版轮廓线。

- `Input structure`：
  - 背景为 black。
  - 网格中由 grey 像素构成若干封闭的"房间"——每个房间是一个由 grey 像素围成的不规则但轴对齐的多边形区域（即房间的边界由水平和垂直的 grey 线段组成，形成凹凸不规则的封闭区域）。
  - 每个房间内部散布着若干同色的单像素碎片，每个房间使用不同的颜色（如 red、blue、green、yellow 等）。碎片的位置随机，没有规律。
  - 每个房间内部碎片的总数恰好等于该房间缩小版轮廓线的像素数。具体地，将房间的形状（含边界的 grey 区域）按比例缩小为原来的 1/2（行数和列数各减半，向下取整），然后只保留缩小版形状的外轮廓（边框像素），该轮廓的像素数即等于该房间内的碎片总数。

- `Rule`：
  - 对每个房间，提取其 grey 边界定义的完整形状（包括边界本身）。
  - 将该形状缩小为 1/2 尺寸（每 2×2 像素块映射为 1 个像素，若该块中有 grey 则结果为 grey，否则为 black——类似最近邻下采样）。
  - 从缩小后的形状中提取外轮廓（仅保留与 black 相邻的 grey 像素）。
  - 将该缩小轮廓用房间内碎片的颜色绘制，居中放置在原房间内部（原碎片被移除）。
  - grey 边界墙壁保持不变。背景保持 black。

- `Key insight`：碎片的数量是验证线索而非随机噪音——它精确等于房间缩小版轮廓的像素数。解题者需要发现每个房间内部实际上要绘制的是"房间自身形状的微缩轮廓"，而碎片的颜色提供了绘制颜色、碎片的数量则暗示了缩小比例。房间形状的自指性（内部绘制自身的缩小版）是核心难点。
</new_puzzle>
