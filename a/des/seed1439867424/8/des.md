# 第一步：分析与思考

## 参考题中的基础操作归纳

纵览20道参考题，可提取出以下基础操作类别：

1. **空间变换**：平移（#1 精灵沿方向平铺）、镜像反射（#2 跨分隔线镜像）、旋转（#15 精灵旋转对齐）。
2. **匹配与配对**：颜色键值匹配（#1 中心色→目标矩形）、尺寸匹配（#13 精灵→空腔）、拓扑匹配（#20 孔洞数→颜色图例）。
3. **路径与运动**：迷宫路径生成（#5 穿过门的路径）、粒子沿走廊运动（#11 遇墙转向）、轨迹跟踪（#19 沿 trail 移动源像素）。
4. **区域操作**：填充（#13 精灵嵌入空腔）、清除/擦除（#8 包含关系删除）、重涂色（#4 方向分类后重涂、#20 按孔洞数重涂）。
5. **结构识别**：分隔线/边框检测（#2, #6, #9）、连通分量分类（#10 大小筛选、#17 同色分量连接）、缺陷/噪声清理（#3 清除孤立斑点）。
6. **信息编码**：位置编码目的地（#1 中心像素是键不是颜色）、位置编码模板（#14 角落位置→模板形状）、模式编码（#9 条纹周期→全局延伸）、形状交换（#18 面板间交换 motif mask）。

## 操作之间非显而易见的串联方式

- **拓扑属性驱动空间操作**：一个对象的拓扑特征（如孔洞数、连通分量数、周长与面积比）可以编码一个数值，这个数值不是直接用于重涂色，而是决定空间变换的参数（如平移距离、旋转角度、缩放系数）。
- **路径生成的结果成为结构识别的输入**：想象一条路径画出后，路径本身将网格分割成多个区域，这些区域的属性再驱动后续操作。
- **局部缺陷编码全局指令**：微小的不规则性（如一个像素的偏移、一条边缺失的像素）不是噪声而是指令——指示变换的方向、距离或类型。
- **对称性差异作为信息载体**：一个几乎对称的形状中的非对称部分，恰恰是需要被提取和利用的信号。
- **负空间（背景形状）作为主要操作对象**：被前景包围的背景区域本身构成有意义的形状，操作应针对这些"看不见的"形状进行。
- **时间/顺序编码在空间中**：空间上的排列顺序（从左到右、从内到外）暗示一个变换的多步执行过程，每一步的输出是下一步的输入。

## 信息的非直觉编码方式

- 颜色不代表身份而代表操作指令（红色=删除，蓝色=复制等）。
- 对象的朝向（哪一面有缺口）编码目标方向。
- 两个对象之间的相对位置关系（左上-右下 vs 左下-右上）编码二元选择。
- 形状的凸包与实际形状之间的差异区域携带信息。

<new_puzzle>
- `description`：根据每个彩色形状的凸包缺失区域的形状，在该缺失区域内填入从网格边缘图例中查找到的匹配颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干单色非凸形状（即形状的凸包严格大于形状本身），每个形状使用不同的前景色（如 blue、red、green 等）。
  - 网格的最底行或最右列排列着若干小的单色矩形色块作为图例，每个图例色块的颜色各不相同且与主网格中的形状颜色都不同。每个图例色块的形状（忽略平移）与恰好一个主形状的"凸包缺失区域"（凸包减去原形状）形状相同。

- `Rule`：
  - 对每个主网格中的彩色非凸形状，计算其凸包（最小凸多边形在网格上的像素化近似：即包含该形状的最小凸区域的所有整数坐标点）。
  - 将凸包像素集合减去原始形状像素集合，得到"凸包缺失区域"。
  - 在图例中找到形状（忽略平移）与该缺失区域完全匹配的图例色块。
  - 将缺失区域中的像素填充为该图例色块的颜色。
  - 图例本身在输出中被擦除（变为 black）。

- `Key insight`：解题者需要识别出每个形状的"凹陷"部分恰好构成一个有意义的形状，而这个形状与边缘图例中的某个色块一一对应。信息不在形状本身，而在形状"缺少的部分"。
</new_puzzle>

<new_puzzle>
- `description`：将每个封闭区域内部的小标记像素视为"投影源"，沿标记所在位置相对于区域中心的方向，将整个封闭区域的轮廓投影为影子。

- `Input structure`：
  - 背景为 grey。
  - 网格中有若干用同一种颜色（如 blue）绘制的封闭环形轮廓（即一像素宽的闭合边界），每个轮廓内部全部为 grey 背景，内部恰好有一个 red 像素作为"光源标记"。
  - 各轮廓之间不重叠且有充足间距。

- `Rule`：
  - 对每个封闭轮廓，确定其几何中心（bounding box 中心取整）。
  - 从 red 标记像素指向几何中心的方向，取反方向作为"投影方向"（即光从标记处照射，影子投向相反方向）。投影方向取最近的四个基本方向（上、下、左、右）之一。
  - 从轮廓的每个边界像素出发，沿投影方向逐格绘制 maroon 像素，直到碰到网格边界或另一个已有的非背景像素。
  - 原轮廓和 red 标记保持不变。

- `Key insight`：red 标记在轮廓内部的偏心位置决定了"光源在哪侧"，从而决定影子的投射方向。解题者必须理解标记不是装饰，而是通过其相对于中心的偏移来编码方向信息。
</new_puzzle>

<new_puzzle>
- `description`：每个前景形状是一个"印章"，其旋转角度由该形状所在象限决定，将印章旋转后盖印到网格中心的目标画布上。

- `Input structure`：
  - 背景为 black，网格大小为偶数×偶数（如 20×20）。
  - 网格正中心有一个用 grey 色绘制的正方形目标画布（如 8×8），内部全为 grey。
  - 在中心画布外的四个象限（左上、右上、左下、右下）中，各有恰好一个单色小形状（各色不同，如 blue、red、green、yellow），每个形状的 bounding box 不超过画布尺寸的一半。

- `Rule`：
  - 将网格以中心画布的中心点分成四个象限。
  - 左上象限的形状不旋转（0°）；右上象限的形状顺时针旋转 90°；右下象限的形状顺时针旋转 180°；左下象限的形状顺时针旋转 270°。
  - 旋转后的每个形状被放置到中心画布上对应的象限区域内：左上形状放在画布左上角、右上形状放在画布右上角、右下形状放在画布右下角、左下形状放在画布左下角。形状的 bounding box 角与画布对应角对齐。
  - 在画布上，形状像素覆盖 grey 像素；若多个形状重叠，后放置的（按左上→右上→右下→左下顺序）覆盖先放置的。
  - 画布外的原始形状在输出中被擦除。

- `Key insight`：每个形状的旋转量不是由形状本身的属性决定，而是由它在网格中所处的象限位置决定。象限位置既编码了旋转角度，又编码了在画布上的目标位置。解题者需要注意到四个形状各自旋转了不同角度后恰好拼合在中心画布的四个角落。
</new_puzzle>

<new_puzzle>
- `description`：检测每行/列中的颜色渐变序列方向，在序列末端追加下一个颜色以延续渐变。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干独立的水平行段或垂直列段，每段由连续的彩色像素构成（长度 3 到 6 个像素不等），段与段之间被 black 背景分隔。
  - 每一段内的像素颜色构成一个从固定颜色顺序表（Azure → Blue → Maroon → Red → Orange → Yellow → Green，共 7 色循环）中截取的连续子序列，方向可以是正序也可以是逆序。
  - 每一段的一端紧邻网格边界或另一非 black 像素，另一端紧邻至少两格 black 空间。

- `Rule`：
  - 对每个连续彩色段，判断其颜色序列在上述颜色顺序表中的方向（正序或逆序）。
  - 在该段有充足 black 空间的那一端（即远离边界或密集区的一端），追加一个像素，颜色为顺序表中紧接着该段末尾颜色的下一个颜色（顺序表循环）。
  - 若一段两端都有充足空间（均至少两格 black），则在颜色序列递增方向的末端追加。

- `Key insight`：解题者需要先发现存在一个隐含的颜色顺序表，再判断每段的方向，最后在正确的一端延续序列。信息编码在颜色排列的有序性中，而非颜色本身的含义。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每对同色像素之间的曼哈顿路径绘制出来，路径颜色由两点间距离决定，使用距离-颜色映射关系（从距离最短的一对中读取）。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干成对出现的彩色像素点：每种前景色恰好出现两次，形成一"对"。至少有 3-5 对不同颜色的像素。
  - 其中恰好有一对像素之间已经用第三种颜色绘制了一条完整的 L 形曼哈顿最短路径（先水平再垂直），这对像素和路径一起构成"示例"。

- `Rule`：
  - 找到已有路径连接的那对像素，记录：该对像素之间的曼哈顿距离 D_example，以及路径所用颜色 C_path。
  - 对所有其他未连接的像素对，计算每对的曼哈顿距离 D_i。
  - 为每对未连接像素绘制 L 形曼哈顿最短路径（先沿水平方向移动到目标列，再沿垂直方向移动到目标行）。
  - 路径颜色规则：若 D_i == D_example，路径颜色为 C_path；若 D_i < D_example，路径颜色为 green；若 D_i > D_example，路径颜色为 red。
  - 原始像素点保持原色不变，路径仅覆盖 black 像素。

- `Key insight`：已绘制的示例路径不仅示范了路径的画法（L 形、先水平后垂直），还隐式地建立了一个"距离基准"。解题者必须意识到路径颜色不取决于端点颜色，而取决于该对端点距离与示例距离的大小关系。
</new_puzzle>

<new_puzzle>
- `description`：根据形状边界上的缺口位置，将每个形状内部填充的颜色"倒出"——沿缺口方向流出并填满外部空间直到碰壁。

- `Input structure`：
  - 背景为 black，网格边缘视为墙壁。
  - 网格中有若干用 grey 像素绘制的一像素宽的矩形边框（类似容器），每个边框内部填充了一种独特的非 grey、非 black 颜色（如 blue、red、orange 等）。
  - 每个矩形边框的某一条边上恰好有一个一像素宽的缺口（该位置的 grey 被替换为 black），缺口朝向四个基本方向之一。
  - 各容器之间有足够间距，彼此不接触。

- `Rule`：
  - 对每个容器，识别其边框上缺口的位置和朝向方向。
  - 从缺口处开始，沿缺口朝向的方向（向外），用该容器内部的填充颜色逐行/列地进行 flood fill，填充所有 black 像素，直到碰到网格边界、grey 边框像素或已有的非 black 颜色像素。填充宽度与缺口等宽（1 像素），即形成一条从缺口延伸出去的彩色射线。
  - 容器内部的填充颜色被清空为 black（"倒空"），grey 边框保持不变。
  - 若一个容器的射线路径上遇到另一个容器的外壁（grey），射线停在壁前一格。

- `Key insight`：解题者需要将灰色边框理解为"容器"、内部颜色理解为"液体"、缺口理解为"出口"。变换的本质是颜色从内部转移到外部射线上，缺口方向决定了射线方向。视觉上看就像容器被倾倒，内容物从缺口流出。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色"时钟指针"指向某个方向，根据指针旁边小色块标注的"时间增量"，将指针旋转相应角度。

- `Input structure`：
  - 背景为 black，网格约 15×15 到 25×25。
  - 网格中有若干独立的"时钟"结构，每个时钟由以下部分组成：
    - 一个 azure 像素作为中心轴点。
    - 从轴点出发沿八个方向之一（上、下、左、右、四个对角）延伸的一条 2-3 像素长的单色线段作为"指针"，指针颜色为 yellow。
    - 紧邻时钟结构旁边（不与指针或轴点相邻，但在轴点 bounding box 外扩 1 格范围内）有 1 到 3 个 red 小像素点。
  - 各时钟之间有足够间距不互相干扰。

- `Rule`：
  - 对每个时钟，读取其当前指针方向（八方向之一，可映射为 0°、45°、90°…315°）。
  - 数出该时钟旁边的 red 小像素点数量 N（1、2 或 3）。
  - 将指针顺时针旋转 N×45°。即若当前指针指向上方（0°），旁边有 2 个 red 点，则旋转到 90°（指向右方）。
  - 在输出中，擦除旧指针，绘制新方向的指针（同长度、同颜色 yellow、从同一 azure 轴点出发）。
  - red 像素点在输出中被擦除。

- `Key insight`：red 点的数量不是装饰——它们编码了旋转的步数。解题者需要发现指针方向发生了变化，且变化量恰好等于旁边 red 点数乘以 45°。这道题的难点在于，解题者需要先识别出"时钟指针"这个抽象概念，然后发现旋转量与邻近标记数量的关系。
</new_puzzle>

<new_puzzle>
- `description`：将散布在网格中的彩色碎片按颜色分组，每组碎片在保持相对位置不变的前提下平移到以该组"锚点像素"为基准的位置，最终所有同色碎片拼合成完整形状。

- `Input structure`：
  - 背景为 black，网格约 20×20 到 28×28。
  - 网格中有多种前景颜色（如 blue、red、green 等），每种颜色出现若干个分散的小像素块（1-4 个像素大小的碎片），同一颜色的碎片总共 3 到 6 块。
  - 每种颜色中恰好有一个碎片与一个 maroon 像素直接 4-连通相邻，该碎片称为"锚碎片"，maroon 像素称为"锚点"。其余同色碎片无 maroon 邻居。
  - 不同颜色的锚点之间距离足够远。

- `Rule`：
  - 对每种前景颜色，找到其锚碎片和对应的锚点（maroon 像素）。
  - 计算所有同色碎片（包括锚碎片）各自相对于锚碎片的偏移向量（以锚碎片 bounding box 左上角为参考点）。
  - 将所有同色碎片平移，使锚碎片的 bounding box 左上角移动到锚点所在位置。所有其他同色碎片保持与锚碎片相同的相对偏移。
  - 平移后的所有同色碎片像素绘制为该颜色；原位置处的碎片像素和 maroon 锚点都被清除为 black。
  - 若平移后不同颜色的碎片发生重叠，后处理的颜色（按颜色编号从小到大的顺序）覆盖先处理的。

- `Key insight`：maroon 锚点不仅标记了"哪个碎片是基准"，还标记了"整组碎片应聚合到哪个位置"。解题者需要发现碎片是被打散的拼图，锚点既指定了拼合的原点，也指定了基准碎片的身份。
</new_puzzle>
