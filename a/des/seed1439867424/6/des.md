# 第一步：分析与思考

## 参考题中的基础操作梳理

纵观 20 道参考题，可以提炼出以下基础操作类别：

1. **空间变换**：平移（slide/dock）、反射（mirror）、旋转（clockwise rotation）、缩放（expand/compress）
2. **颜色映射**：重新着色（recolor）、颜色交换（swap）、基于频率/数量的颜色筛选
3. **路径与连通性**：路径追踪（snake tracing）、射线投射（ray casting）、走廊导航（corridor sliding）
4. **模式匹配与对应**：模板印章（stamp）、符号索引替换、标记与目标配对
5. **拓扑/结构识别**：U 形容器检测、十字形缺口检测、网络枢纽与分支识别、L 形方向编码

## 操作之间的非显而易见串联方式

- **结构特征作为隐式编码**：一个对象的形状不是它"自身"的信息，而是编码了对另一个对象应执行何种操作的指令。例如参考题7中 L 的朝向决定了输出角落的选择——形状即指令。
- **数量/频率作为选择器**：颜色出现次数不是"统计量"，而是区分"操作对象"与"保留对象"的判据（题5的重复色、题18的频率排名）。
- **空间位置编码因果关系**：对象在网格中的位置不仅是"在哪里"，还可以编码"做什么"（题6的列位置决定落入哪个容器）或"按什么顺序"（题11的左右顺序定义循环调色板）。
- **一个变换的副产品是另一个变换的输入**：例如射线投射创建的路径可以成为颜色传播的通道；压缩操作的结果可以成为索引网格。
- **双重身份对象**：同一个对象既是"内容"也是"元数据"——例如模板既定义形状也定义间距（题19），标记像素既属于精灵也指向目标（题16）。

## 信息的非直觉编码方式

- 对象的**缺失部分**（空洞、缺口的位置和形状）携带比实体部分更关键的信息。
- **相对关系**（对象之间的间距、对齐偏移、包含关系）而非绝对属性驱动变换。
- **边界条件**（是否触及网格边缘、是否被包围）作为隐式布尔条件控制不同的变换分支。
- 颜色不代表"身份"而代表"角色"——相同颜色在不同位置可能有完全不同的语义（框架色 vs 填充色 vs 标记色）。

## 新的因果关系与信息传递路径

- **负空间编码**：变换的关键参数不由存在的像素承载，而由"空缺"的模式承载——缺口数量、空洞形状、缺失的对称轴。
- **几何属性作为分类标签**：对象的拓扑/几何属性（对称性类型、连通度、凸性）可以作为隐式分类标准，决定该对象被路由到何处。
- **并行扩散与竞争**：多个源同时向网格中传播信息，碰撞或交汇处的处理方式（混合、优先级、取消）构成隐藏规则。
- **排序键的非直觉选择**：对象被排序的依据不是最显眼的属性（颜色、大小、位置），而是某个需要计算或推断的派生属性。

<new_puzzle>
- `description`：根据每个封闭区域边界上"缺口"（grey 线段中断处）的数量，用对应层数的颜色环从外向内填充该区域。
- `Input structure`：背景为 black。网格中有若干条 grey 线段（水平或垂直，宽度为1像素），这些线段相互交叉或连接，将网格分割成若干个封闭的矩形区域。每个封闭区域的边界上可能存在"出口"——即 grey 线段中断形成的单像素宽缺口（缺口长度恰好为1像素）。每个区域内部初始全为 black 背景。网格边缘也视为封闭边界的一部分（即紧贴网格边缘的区域，该侧无需 grey 线段也算封闭）。
- `Rule`：
  - 对每个封闭矩形区域，计算其边界上有多少个出口（缺口数量 N）。
  - 根据出口数量 N 选择填充层数和颜色。颜色序列固定为（从最外层到最内层）：green、red、blue、yellow。规则如下：
    - N=0 → 区域保持 black 不变。
    - N=1 → 用 yellow 填充整个区域内部（1层）。
    - N=2 → 外环 blue、内部 yellow（2层）。
    - N=3 → 外环 red、中环 blue、最内部 yellow（3层）。
    - N=4 → 外环 green、次外环 red、次内环 blue、最内部 yellow（4层）。
    - N>=5 的情况不出现。
  - "环"的定义：外环是区域内部紧贴边界的一圈像素，中环是去掉外环后紧贴新边界的一圈像素，依此类推。若区域太小无法容纳所有环层，则剩余空间全部使用最内层颜色 yellow。
  - grey 分割线保持不变。
- `Key insight`：解题者需要发现关键信息不是区域的大小或位置，而是每个区域边界上"缺口"的数量——这个拓扑特征决定了填充层数和配色方案。缺口容易被视为"线段没画完"而忽略，但它才是驱动变换的核心变量。出口数量为0的区域不填充，这进一步强化了"缺口=信号"的逻辑。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散布的彩色孤立像素按颜色分组，每组像素定义一个矩形包围盒，按像素数量从多到少的顺序依次绘制填充矩形（先画的被后画的覆盖）。
- `Input structure`：背景为 black。网格中散布着若干种颜色的孤立像素（每个彩色像素的4-邻域内没有同色像素），每种颜色至少出现 3 个像素且不超过 6 个。不同颜色的像素数量互不相同。所用颜色可以是 red、blue、green、yellow、orange 等（不含 black）。
- `Rule`：
  - 对每种颜色 C，找到该颜色所有像素构成的最小轴对齐矩形包围盒（最小行、最大行、最小列、最大列围成的矩形）。
  - 按每种颜色的像素数量从多到少排序。
  - 按该排序顺序依次将每种颜色的包围盒矩形区域全部填充为该颜色。后画的覆盖先画的。
  - 最终效果：像素数量最少的颜色最后绘制，其矩形总是完整可见；数量最多的颜色最先绘制，可能被大量覆盖。
  - 原始的孤立像素如果位于某个后绘制的包围盒内，会被覆盖。
- `Key insight`：解题者需要将"散布的孤立点"重新理解为每种颜色矩形包围盒的"定义点"，而非独立的对象。更关键的是发现绘制顺序由点的数量决定：数量多的颜色先画（被遮挡更多），数量少的后画（更完整可见）——这与直觉中"多数=重要=前景"的假设相反。需要通过观察重叠区域的颜色归属来反推绘制顺序。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色方块沿与其同行/同列的箭头所指方向移动，移动距离等于箭头身体的长度，碰撞时距箭头更近的方块优先占位。
- `Input structure`：背景为 black。网格中包含以下元素：
  - 若干个 2x2 的单色实心方块（颜色各不相同，可以是 red、blue、green、yellow 等）。
  - 若干个由 maroon 像素构成的箭头。每个箭头的构造方式：一条水平或垂直的直线段作为"箭身"（长度 >= 2 像素），箭身的一端有一个垂直于箭身方向的单像素突出作为"箭头尖"（构成 T 形或 L 形末端）。箭头指向的方向为从无尖端向有尖端的方向。例如：一条从左到右的水平箭身，若右端上方或下方有一个突出像素，则箭头指向右。
  - 每个 2x2 方块恰好与一个箭头共享同一行（对于水平箭头，方块的某一行与箭身在同一行）或同一列（对于垂直箭头），且一个方块只对应一个箭头，一个箭头只对应一个方块。
- `Rule`：
  - 对每个 2x2 方块，找到与它共行或共列的唯一箭头。
  - 方块沿箭头指向的方向移动，移动的格数等于箭身的像素长度（不含箭头尖的那个突出像素）。
  - 若两个方块移动后会重叠，按照方块与其对应箭头之间的距离（方块最近边到箭身最近端的曼哈顿距离）从近到远的顺序依次放置：距离近的方块先放，后续方块若与已放置方块冲突则停在冲突前的最近位置。
  - 箭头在输出中被擦除（变为 black），方块的原始位置也被清除。
- `Key insight`：箭头不仅编码方向，其"身体长度"还编码了移动距离——解题者需要将箭头从一个简单的方向标志重新理解为同时携带方向和量级的复合指令。此外，碰撞优先级由方块与箭头的距离决定（近者优先），这是需要从多个示例对比中才能发现的隐藏规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色"种子"从边框入口注入灰色管道网络，两种颜色在管道中以等速扩散并在等距点生成混合色。
- `Input structure`：背景为 black。网格包含以下元素：
  - 一个由 grey 像素构成的管道网络：宽度为 1 像素的正交连通路径（仅水平和垂直方向），可以有分叉但不形成环路（即为树形结构）。管道的若干末端（叶子节点）位于网格边缘。
  - 恰好两个边框入口：在网格边缘上，恰好有两个管道末端各自紧邻一个彩色标记像素。两个标记分别是 red 和 blue（位于网格最外圈，与管道末端4-连通相邻）。
  - 管道中可能有其他不与边框标记相邻的叶子末端。
- `Rule`：
  - red 标记和 blue 标记分别从各自相邻的管道末端"注入"颜色。
  - 颜色沿管道以"等速"传播：可以理解为同时从两个注入口出发，每步各前进一个像素。
  - 对管道中每个 grey 像素，计算它沿管道路径到 red 入口的距离 Dr 和到 blue 入口的距离 Db（距离 = 沿管道经过的像素步数）：
    - 若 Dr < Db，该像素着色为 red。
    - 若 Db < Dr，该像素着色为 blue。
    - 若 Dr = Db，该像素着色为 magenta。
  - 若某个 grey 像素沿管道无法到达某个入口（位于树的不同分支末端，但由于是树形结构，每个像素到每个入口都有唯一路径），则按正常路径距离计算。
  - 若某段管道与两个入口都不连通（孤立管道段），保持 grey。
  - 边框上的彩色标记像素保持不变。
- `Key insight`：解题者需要发现颜色的传播遵循"沿管道的路径距离"而非"直线距离"——因此在弯曲的管道中，直线上看起来更近的入口可能因为管道绕路而实际更远。等距交汇处产生 magenta 混合色是规则的标志性线索，帮助解题者确认"等速扩散"模型。核心认知路径是将静态的着色结果反推为动态的双源扩散过程。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象根据自身的对称性类型被路由到网格中对应的象限位置。
- `Input structure`：背景为 black。网格大小为偶数x偶数（例如 20x20）。网格中央有一条水平和一条垂直的 azure 分隔线（各1像素宽），将网格均分为四个象限：左上、右上、左下、右下。所有前景对象都位于一个象限（称为"源象限"），其余三个象限为空（仅 black 背景）。源象限中有恰好 4 个互不重叠的小型单色对象（每个对象的包围盒不超过 4x4，各自颜色不同，颜色可以是 red、green、yellow、orange 等），每个对象恰好属于以下四种对称性类型之一：
  - 仅水平对称：以对象包围盒中心的垂直轴为镜面左右翻转后与自身重合，但以水平轴上下翻转后不重合。
  - 仅垂直对称：以水平轴上下翻转后与自身重合，但以垂直轴左右翻转后不重合。
  - 双轴对称：左右翻转和上下翻转后均与自身重合。
  - 无对称：左右翻转和上下翻转后均不与自身重合。
- `Rule`：
  - 四种对称性类型与四个象限的对应关系固定为：
    - 双轴对称 → 左上象限
    - 仅水平对称（左右对称）→ 右上象限
    - 仅垂直对称（上下对称）→ 左下象限
    - 无对称 → 右下象限
  - 将每个对象从源象限中擦除（恢复为 black），然后放置到其对称性类型对应的目标象限中。
  - 放置位置：对象的包围盒中心与目标象限的中心对齐。若象限宽高为偶数导致无法完美居中，则偏左偏上。
  - azure 分隔线保持不变。对象搬移时不旋转、不改变颜色。
- `Key insight`：解题者需要辨认每个小对象的对称性类别——这要求对每个对象进行心理上的镜像翻转测试，而非关注其颜色、大小或位置。对称性作为一种几何属性"标签"来分配目标象限，这是一种非直觉的分类准则。关键难点在于：解题者首先需要排除颜色、面积等更显眼的属性假设，发现"对称性"才是真正的分类依据，然后还要通过对比多个样例推断出四种对称性与四个象限之间的具体映射关系。
</new_puzzle>

- `description`：网格中排列着若干"简易时钟"图案，根据每个时钟的指针方向读取时间值，然后按时间值从小到大重新排列所有时钟到固定槽位中。
- `Input structure`：背景为 black。网格被 grey 线条（1像素宽）划分为均匀的矩形槽位，排列为 R 行 C 列（例如 2x3 共6个槽位），每个槽位内部大小相同（例如 7x7）。每个槽位内有一个"简易时钟"图案：一个 5x5 的 blue 菱形轮廓（由位于相对坐标 (0,2)、(1,1)、(1,3)、(2,0)、(2,4)、(3,1)、(3,3)、(4,2) 处的8个 blue 像素构成），菱形中心位于相对坐标 (2,2)。从中心向上、下、左、右四个方向中恰好一个方向延伸出一条由 red 像素构成的线段（长度为2像素，即中心相邻的1格和再外1格共2个像素），作为"指针"。指针末端恰好落在菱形边框的像素位置上，该位置由 red 覆盖原本的 blue。
- `Rule`：
  - 读取每个槽位中时钟的指针方向，将其映射为时间值：上→0，右→3，下→6，左→9。
  - 将所有时钟按时间值从小到大排序。时间值相同的时钟，保持它们在输入中从左到右、从上到下的扫描顺序（即先扫描第一行从左到右，再扫描第二行从左到右，依此类推）。
  - 按排序结果，将时钟图案依次填入槽位：填充顺序为从左到右、从上到下（先填第一行从左到右，再填第二行）。
  - 每个时钟图案原样搬移（指针方向不变、颜色不变）。
  - grey 分隔线保持不变。
- `Key insight`：解题者需要发现菱形图案中的 red 指针方向不是随机装饰，而是编码了一个离散的数值。核心认知路径是：先注意到所有时钟的唯一区别在于指针朝向（上/下/左/右），再通过对比输入输出发现时钟被重新排列了，最后推断出排列依据是指针方向对应的时间值大小。难点不在于排序操作本身，而在于"方向→时间值→排序键"这条编码链的发现。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色像素向四个正交方向发射光线，光线遇到其他彩色像素时停止；背景像素被着色为覆盖它的光线中来源最远的那种颜色。
- `Input structure`：背景为 black。网格中稀疏分布着若干个单独的彩色像素（每两个彩色像素之间的曼哈顿距离 >= 3），每个彩色像素的颜色互不相同（可以是 red、blue、green、yellow、orange 等）。彩色像素总数在 3 到 6 之间。
- `Rule`：
  - 每个彩色像素向上、下、左、右四个方向发射光线。光线沿直线逐像素前进，标记沿途的 black 像素为该颜色的"候选"。
  - 光线遇到另一个彩色像素时立即停止（不覆盖该像素，也不穿过）。光线到达网格边界时也停止。
  - 对于每个 black 背景像素，可能被零条、一条或多条光线覆盖：
    - 未被任何光线覆盖 → 保持 black。
    - 仅被一条光线覆盖 → 着色为该光线来源像素的颜色。
    - 被多条光线覆盖 → 着色为来源像素与该位置曼哈顿距离**最大**的那条光线的颜色。若最大距离有平局，选择来源像素行号更小的；行号也相同则选列号更小的。
  - 原始彩色像素本身保持不变。
- `Key insight`：直觉上，人们倾向于认为"最近的光源"应该决定颜色（类似最近邻），但这道题的规则恰恰相反——在多条光线交叉时，距离最远的光源获胜。解题者需要仔细观察光线交叉区域的着色结果，发现它们总是取自更远的来源，从而打破"就近原则"的思维定式。这种反直觉的优先级规则使得交叉区域的颜色归属成为解题的核心线索。
</new_puzzle>
