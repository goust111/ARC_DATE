## 第一步：分析与思考

### 参考题中涉及的基础操作归纳

1. **计数驱动尺寸/布局**：像素数量决定输出维度（参考1）
2. **颜色匹配/筛选**：通过颜色一致性选择特定对象（参考2）
3. **形状变换与传播**：沿线路网络传递并变换形状（参考3）
4. **拓扑排序/图推理**：从遮挡关系推断顺序（参考4）
5. **行列压缩/打包**：跨面板提取有效行并重新排列（参考5）
6. **对称性修复/去噪**：逐色层恢复镜像对称（参考6）
7. **形状补全**：从部分可见推断完整形状并重着色（参考7）
8. **对角线传播**：沿对角方向复制并变换颜色序列（参考8）
9. **种子洪填充**：从边界标记出发填充封闭区域（参考9）
10. **查找替换表/颜色映射**：按有序图例进行链式替换（参考10）
11. **拼图对接**：工具旋转/翻转后嵌入框架空腔（参考11）
12. **路径连接**：同色组件间绕障碍连线（参考12）
13. **周期性图案扩展**：从锚点和控制条推断重复边框（参考13）
14. **螺旋生长**：从端点按优先转向规则生长路径（参考14）
15. **多模式反射**：根据标记几何形状选择反射类型（参考15）
16. **环上颜色旋转**：3x3环的角与边中心反向旋转（参考16）
17. **标记→空腔映射**：格子角隙标记控制相邻空腔填色（参考17）
18. **标记对齐叠加**：按共享标记对齐后分层粘贴（参考18）
19. **接触边标记重着色**：按接触面标记色统一对象颜色（参考19）
20. **十字轴四象限反射**：沿全行/全列十字镜像补全图案（参考20）

### 非显而易见的串联思路

- **负空间作为信息载体**：对象内部的背景像素排列，而非前景本身，携带关键信息。前景是"容器"，背景空洞是"内容"。
- **几何特征隐式编码操作指令**：对象的凹凸、开口方向、长宽比等几何属性本身就是变换参数——不需要显式标记。
- **跨区域因果绑定**：一个区域内的微小特征（如孔洞数、指针方向）决定另一个远处区域的变换方式，但两者之间没有视觉上的直接连接线索。
- **排序键的非直觉性**：排列顺序不由面积或颜色直接决定，而由需要计算才能获得的派生属性（如内接矩形、周长/面积比）驱动。
- **图底反转**：前景变背景、背景变前景，关注点从"画了什么"变成"没画什么"。
- **组合式语义拆分**：一个紧凑的视觉组合体被拆解为多个独立语义角色（方向、距离、载荷），每部分独立解读后组合执行。

- `description`：每个前景对象根据其形状凹口的朝向，沿凹口的反方向滑动到网格边缘。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个单色前景对象，每个对象是一个 4-连通区域，形状为带有恰好一个矩形凹口的块状结构（类似字母 C、U 或其 90 度旋转体）。
  - 具体地说，每个对象的 bounding box 为 W x H，对象占据了 bounding box 内的大部分像素，但在 bounding box 的恰好一条边上有一个连续的矩形缺口（缺口深度至少 1 像素，宽度至少 1 像素），缺口内部为 black 背景。
  - 各对象颜色互不相同，对象之间互不接触，且初始时不接触网格边缘。

- `Rule`：
  - 对每个对象，确定其凹口朝向的方向：检查 bounding box 四条边，找到有连续背景缺口的那条边，缺口开口所朝的方向即为凹口朝向（上/下/左/右）。
  - 对象沿凹口朝向的反方向平移（即"背朝缺口"方向移动），逐像素滑动，直到对象的前进方向边缘碰到网格边界为止。
  - 处理顺序：按对象到其目标边缘的初始距离从小到大处理；若某对象滑动路径上遇到已就位的其他对象，则在该对象旁停下（相隔 0 像素，即紧贴）。
  - 原始位置清除为 black，对象形状和颜色不变。

- `Key insight`：没有任何显式箭头或颜色编码来标示移动方向——方向信息完全隐含在对象自身的凹陷几何结构中。缺口朝左意味着对象向右移动，缺口朝上意味着向下移动。解题者需要把对形状"开口"的观察转化为运动方向的推断。
</new_puzzle>

- `description`：在每个对象的 bounding box 中执行图底反转——前景变为背景、背景变为前景——并用邻近色标指定新前景颜色。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个不规则形状的单色前景对象（4-连通区域），每个对象不是完整的矩形，因此其 bounding box 内必然存在一些 black 背景像素。
  - 每个对象的 bounding box 外部、与 bounding box 的某条边相邻（间隔 1 像素），有一个单像素的"色标"，颜色与该对象不同且与背景不同。每个对象恰好有一个色标，各色标颜色可以相同也可以不同。

- `Rule`：
  - 对每个前景对象，取其 bounding box 区域。
  - 在该 bounding box 内，将原来属于该对象的前景像素全部置为 black（背景）。
  - 将原来为 black 背景的像素（即对象的"负形"）全部填充为该对象的邻近色标颜色。
  - 色标像素本身从网格中移除（置为 black）。
  - 不同对象的 bounding box 互不重叠。网格其余部分不变。

- `Key insight`：这是一个"图底反转"问题——输出的形状不是输入中看到的前景，而是前景在其 bounding box 中留下的空白。色标提供新颜色。解题者必须将注意力从"画了什么"转移到"没画什么"上，同时识别出色标与对象的一一对应关系。
</new_puzzle>

- `description`：网格被分为时钟区和图案区，时钟区中指针的朝向编码一个旋转角度，该角度应用于同行图案区中的图案。

- `Input structure`：
  - 背景色为 black。
  - 网格由单像素宽的 grey 线分割为若干等大的矩形单元格（例如每个单元格 7x7 像素）。单元格排列成若干行若干列。
  - 每行单元格中，最左侧的一个是"时钟单元格"，其余是"图案单元格"。
  - 时钟单元格的内容：一个 3x3 的 grey 正方形环（8 个 grey 边框像素围绕 1 个 black 中心），加上从中心位置向四个正方向（上/下/左/右）之一延伸 1 像素的一个彩色指针像素。指针的颜色在各行之间可以不同但不影响规则。指针朝上 = 不旋转，朝右 = 顺时针 90 度，朝下 = 180 度，朝左 = 逆时针 90 度（即顺时针 270 度）。
  - 图案单元格的内容：一个由非 grey 非 black 像素组成的小型图案（不超过 5x5），图案可以是非对称的。图案在单元格内居中放置。

- `Rule`：
  - 对每一行单元格，读取该行时钟单元格中指针的朝向，确定旋转角度 R。
  - 将该行所有图案单元格中的图案绕其各自的中心旋转 R 度。旋转以像素网格对齐的方式执行（仅 0/90/180/270 度）。
  - 时钟单元格在输出中保持原样不变。
  - grey 分隔线和 black 背景保持不变。

- `Key insight`：时钟并非装饰，而是一个紧凑的旋转指令——3x3 环是"表盘"，单像素是"指针"。解题者需要先识别时钟结构，再将指针方向映射到旋转角度，最后发现同行图案全部受该时钟控制。难点在于从视觉上辨认出"指针方向"到"旋转操作"的对应关系。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色对象被其自身轮廓上凸角与凹角的数量差驱动：差值为正则放大，差值为负则缩小，差值为零则不变。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干互不接触的单色前景对象，每个对象是一个 4-连通区域，形状各异（可以是矩形、L 形、T 形、十字形等），各对象颜色不同。
  - 每个对象至少有 3x3 的 bounding box。
  - 网格右下角有一个 1x2 的标记：左侧像素颜色表示"放大色"，右侧像素颜色表示"缩小色"。

- `Rule`：
  - 对每个对象，沿其轮廓（8-连通边界）遍历，统计凸角和凹角的数量。凸角定义为：某个前景边界像素，其 8 邻域中恰好有 2 个属于该对象的邻居且这 2 个邻居相互相邻（即形成 90 度外角）。凹角定义为：某个背景像素与该对象的边界相邻，且该背景像素的 8 邻域中有至少 3 个属于该对象的像素形成 90 度内角。
  - 计算差值 D = 凸角数 - 凹角数。
  - 若 D > 0：将对象的每个像素向外扩展 1 像素（形态学膨胀 D 次，使用 4-连通结构元素），扩展的像素用"放大色"着色，原对象颜色不变。
  - 若 D < 0：将对象从外向内收缩 |D| 次（形态学腐蚀，4-连通），被移除的像素置为 black。若收缩后对象消失则整个对象消失。
  - 若 D = 0：对象不变。
  - 右下角标记保持不变。

- `Key insight`：变换方向（放大/缩小）和变换幅度同时编码在对象自身的几何复杂度中——凸角多于凹角意味着形状"凸出"较多（如矩形有 4 凸 0 凹），凹角多于凸角意味着形状"凹入"较多（如十字形凹角多于凸角）。解题者需要从样例中发现"角的类型计数"驱动了缩放操作。
</new_puzzle>

<new_puzzle>
- `description`：将散落在网格中的彩色碎片按颜色分组后，每组碎片在一个公共锚点处拼合成完整的矩形，拼合顺序由碎片到锚点的距离决定堆叠层次。

- `Input structure`：
  - 背景色为 black。
  - 网格中央有一个小型的 grey 十字标记（单像素宽的十字，臂长 1-2 像素），作为"锚点"。
  - 网格各处散布着若干彩色碎片，每个碎片是一个 4-连通单色区域。同一颜色可能出现 2 到 4 个碎片。
  - 每种颜色的所有碎片如果被平移到正确位置后，恰好可以无重叠、无间隙地拼合成一个完整的实心矩形。
  - 不同颜色拼合后的矩形尺寸可以不同。

- `Rule`：
  - 对每种颜色，找出其所有碎片。计算这些碎片拼合成完整矩形时每个碎片相对于矩形左上角的偏移量（这可以通过碎片的形状互补性唯一确定）。
  - 将拼合后的矩形放置在锚点位置，矩形的中心与 grey 十字中心对齐。
  - 若多种颜色的矩形重叠，按颜色组中"离锚点最远的碎片"的 Manhattan 距离排序：距离最远的颜色在最底层，距离最近的在最顶层（即最近的覆盖最远的）。
  - 移除所有碎片的原始位置（置为 black）。grey 锚点被矩形覆盖后不再可见。

- `Key insight`：碎片看似随机散落，实际上同色碎片是一个矩形的拆分件，需要"拼图式"地组装回去。锚点提供了放置位置，而堆叠顺序由散落距离隐式决定——离得越近优先级越高，这需要解题者同时理解空间拼合和距离排序两层逻辑。
</new_puzzle>

<new_puzzle>
- `description`：在一个包含多个同心框架的网格中，每层框架的颜色由该层框架所围区域中被涂色的角落数目决定，角落数目作为索引从色表中取色重绘框架。

- `Input structure`：
  - 背景色为 black。
  - 网格中心有若干层同心的单像素宽正方形框架（3 到 5 层），初始时所有框架均为 grey。从外到内编号为第 1 层、第 2 层等。
  - 每层框架的四个角位置（左上、右上、左下、右下），某些角被涂上了非 grey 非 black 的彩色像素（覆盖了原本的 grey）。每层被涂色的角数目为 0 到 4 之间的整数。被涂色的角的具体颜色无关紧要，只有数目有意义。
  - 网格底部有一行色表：从左到右排列 5 个不同颜色的像素，分别对应索引 0、1、2、3、4。

- `Rule`：
  - 对每层框架，计算该层四个角中有多少个被涂上了非 grey 颜色，得到数目 N（0 <= N <= 4）。
  - 从底部色表中取第 N 个位置（从 0 开始计数）的颜色 C。
  - 将该层框架的所有像素（包括被涂色的角）重新着色为 C。
  - 色表本身保持不变。black 背景保持不变。

- `Key insight`：彩色角像素看起来像是局部的装饰或损坏，实际上它们是该层的"计票标记"——角的着色数目才是真正的信息。解题者必须忽略角的具体颜色，只关注"有几个角被涂了色"，再将这个数目映射到色表中。这是一种"数量而非身份"的编码方式。
</new_puzzle>
