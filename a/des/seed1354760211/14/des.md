## 第一步：分析与思考

### 参考题目中涉及的基础操作分类

**空间变换类：**
- 缩放/拉伸映射（#1：小精灵拉伸到框架内部）
- 归一化/标准化尺寸（#5：将图案归一化为5x5图标）
- 平移/滑动（#9：在bracket间移动物体，#19：黑色形状右滑至分隔符）
- 旋转/循环重着色（#13：颜色沿分隔器顺时针旋转一步）

**计数与统计类：**
- 计数转表示（#3：数量变为点的个数，#15：计数决定矩形尺寸）
- 压缩/编码（#6：竖梳高度编码数量）

**匹配与查找类：**
- 间接颜色查找（#2：通过颜色键查找源精灵）
- 条件匹配决定行为（#17：颜色匹配决定移动方向）

**区域/连通性类：**
- 连通区域分析（#7：墙体分隔的二部图交替着色）
- 洪水填充/可达性（#14：从角标记泛洪确定可达区域）
- 封闭区域检测（#19：滑动后封闭孔洞发射射线）

**模式/周期类：**
- 周期推断与修复（#8：推断周期背景，#12：推断最小重复瓦片）
- 自相似/递归结构（#4：每个像素展开为整体网格的掩码）

**传播/扩展类：**
- 条件生长/迭代（#11：交替颜色三角形向下生长）
- 最近种子分配（#20：每行取最近源bar颜色）
- 方向性扩展（#16：标记向实边扩展，#18：矩形向彼此延伸填充间隙）

**分类/排序类：**
- 按属性分类（#10：框架vs实心分两列排列）

### 非显而易见的串联方式思考

1. **拓扑属性决定颜色映射**：连通区域的孔洞数量可以用来索引一个颜色表，而不是直接着色——孔洞数不是被填充的对象而是查表的键。

2. **对称性缺陷作为信息载体**：一个几乎对称的图案中，不对称的部分编码了变换的参数（方向、距离等），解题者必须先识别"期望的对称性"才能定位缺陷。

3. **物体的负空间承载信息**：两个物体之间的空隙形状才是核心信号，而非物体本身。结合#19的孔洞射线思想，负空间可以是操作触发器。

4. **阴影/投影作为隐含操作**：一个物体的"投影"（沿某方向的列/行覆盖）与另一个物体的实体区域的交集定义输出区域——两个独立物体之间通过投影建立关联。

5. **颜色频率编码排序键**：某种颜色在输入中出现的次数不用于计数显示，而是用于决定对象的排列顺序或优先级。

6. **连通路径的长度作为选择器**：从种子到各目标的最短路径距离决定哪个目标被激活，路径长度成为隐式优先级。

7. **形状的旋转不变量作为匹配键**：两个看似不同的形状可能互为旋转关系，必须识别旋转等价性才能完成配对。

<new_puzzle>
- `description`：将每个封闭区域内的彩色种子像素"投影"到区域边界上，投影方向由种子在区域内的相对位置（偏左/偏右/偏上/偏下）决定，在边界上标记投影落点。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由蓝色（blue）像素绘制的一像素宽封闭矩形框（各框互不重叠、互不接触）。每个矩形框内部为黑色背景。
  - 每个矩形框内部恰好有一个非黑非蓝的彩色单像素（种子），颜色各异（如红色 red、绿色 green、黄色 yellow 等）。
  - 种子不在矩形框内部的正中心，而是偏向某一侧。

- `Rule`：
  - 对于每个矩形框，计算其内部区域的中心坐标（内部行范围和列范围的中点）。
  - 将种子的位置与中心比较，确定种子偏向哪个方向：若种子的列 < 中心列，则偏左；若种子的列 > 中心列，则偏右；若种子的行 < 中心行，则偏上；若种子的行 > 中心行，则偏下。若同时偏两个方向，取偏移量绝对值更大的那个维度作为主偏移方向。
  - 从种子位置沿主偏移方向的反方向（即远离种子偏向的方向）画一条直线，直到碰到矩形框的对侧蓝色边界。将该边界像素的颜色替换为种子的颜色。
  - 种子像素本身从内部移除（变为黑色）。
  - 蓝色框体的其余部分不变。

- `Key insight`：种子偏离中心的方向决定了投影的朝向——但投影是向反方向射出而非顺着偏移方向。解题者需要注意到种子总是"远离"自己偏移方向被投射。核心认知路径是：偏移量是信号，反方向是操作方向。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中每个图案缺失的对称部分，仅补全缺失区域，且补全所用颜色由该图案最接近的对称轴类型决定。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由灰色（grey）像素构成的互不相连的4连通图案。每个图案是某个具有完美对称性（水平对称、垂直对称或180度旋转对称）的形状被随机删去一部分像素后的残缺版本。
  - 每个图案的残缺率较低（保留70%以上的原始像素），使得原始的对称类型仍然可以被人眼识别。
  - 网格的最下方一行有一个颜色图例：从左到右依次排列三个不同颜色的单像素，分别标记为位置 1、2、3（如红色 red、绿色 green、蓝色 blue）。这三种颜色分别对应三种对称类型：位置 1 对应水平对称（关于水平中轴翻转），位置 2 对应垂直对称（关于垂直中轴翻转），位置 3 对应180度旋转对称。

- `Rule`：
  - 对于每个灰色图案：
    1. 计算其最小包围矩形。
    2. 在包围矩形内，分别尝试三种对称操作（水平翻转、垂直翻转、180度旋转），对于每种操作，检查现有灰色像素与其对称映像的一致性得分（现有像素的对称位置也是灰色像素的比例）。
    3. 选择一致性得分最高的对称类型（保证在所有样例中最高得分唯一且明显高于次高）。
    4. 根据该对称类型，将所有缺失的对称像素补全——补全像素的颜色使用图例中对应位置的颜色（而非灰色）。
  - 原始灰色像素保持灰色不变。图例保持不变。

- `Key insight`：灰色像素既是图案的主体，又隐含了对称类型信息。解题者需要对每个图案逆向推断出它"想要成为"哪种对称形状，然后用颜色编码标注其对称类型的同时完成修补。补全颜色不同于原色这一设计迫使解题者识别出颜色图例与对称类型的映射关系。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色"印章"叠放在一起，根据重叠区域的颜色混合结果反推各印章的原始形状，输出去除重叠后的独立印章排列。

- `Input structure`：
  - 背景为黑色（black）。
  - 输入网格中可见若干颜色区域，包括"纯色"区域和"混合色"区域。
  - 实际上，网格由恰好两个矩形印章叠放而成。每个印章是一个轴对齐的实心矩形，分别为红色（red）和蓝色（blue）。两个印章有部分重叠。
  - 重叠区域显示为 magenta（红+蓝的视觉混合色）。非重叠的红色印章部分显示红色，非重叠的蓝色印章部分显示蓝色。

- `Rule`：
  - 识别三种颜色区域：纯红色区域、纯蓝色区域、magenta 区域。
  - 还原红色印章的完整矩形：纯红色区域 + magenta 区域的并集的最小包围矩形。
  - 还原蓝色印章的完整矩形：纯蓝色区域 + magenta 区域的并集的最小包围矩形。
  - 输出网格的宽度 = 红色印章宽度 + 1（间隔列）+ 蓝色印章宽度，高度 = 两个印章高度的较大值。
  - 在输出网格中，左侧放置完整的红色实心矩形（顶部对齐），右侧隔一列黑色间隔后放置完整的蓝色实心矩形（顶部对齐）。
  - 无 magenta 出现在输出中。

- `Key insight`：magenta 不是独立颜色，而是两个印章重叠的证据。解题者必须理解"颜色混合=物理重叠"这一隐含逻辑，通过混合色反推出被遮挡的完整形状，然后将两个印章"拆开"并列展示。核心困难在于识别 magenta 是红+蓝的组合产物而非第三个独立对象。
</new_puzzle>

<new_puzzle>
- `description`：每个彩色区域是一个"视野锥"的发射源，从区域的尖端沿扇形扩散照亮背景，被墙壁阻挡后留下阴影。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由灰色（grey）像素构成的一像素宽墙壁段（水平或垂直线段），墙壁段之间不连通。
  - 网格中有若干彩色"光源"像素（每个光源为单个非黑非灰像素，如红色 red、绿色 green 等），每个光源紧贴网格的某一条边（上/下/左/右边缘），且不与任何墙壁相邻。
  - 光源所在的边缘位置决定其照射方向：上边缘光源向下照射，下边缘光源向上照射，左边缘光源向右照射，右边缘光源向左照射。

- `Rule`：
  - 每个光源从其所在位置沿照射方向发射光线。光线以逐行（或逐列，取决于方向）的方式扩散：第一步照亮正前方1格，第二步照亮正前方及左右各1格（共3格），第三步照亮更宽的5格范围，以此类推——每前进一步，照亮范围向两侧各扩展1格（形成45度扇形）。
  - 照亮的格子从黑色变为该光源的颜色。
  - 如果光线遇到灰色墙壁像素，该光线路径被阻挡：墙壁像素本身不变色，墙壁正后方（沿光线传播方向）的区域形成阴影，不被照亮。阴影区域的宽度等于墙壁段的长度，向远处延伸直到网格边缘。
  - 当两个光源的照亮区域重叠时，先处理行/列编号更小的光源（即靠近左上角的优先），后处理的光源颜色覆盖先处理的。
  - 墙壁像素和光源像素保持不变。

- `Key insight`：光源位于边缘，其照射方向由所在边隐式决定——解题者需要注意到"位于上边缘=向下照"这一空间逻辑。墙壁不仅阻挡光线还在其身后投射持续的"阴影柱"，这意味着一小段墙壁可以保护其后方一大片区域不被染色。
</new_puzzle>

- `description`：网格中散落的数字形图案（由像素拼成的1-9数字字形）指示对应数量的相邻空行或空列应被染成该数字的颜色。

- `Input structure`：

  - 网格较大（如 25x25 或 30x30）。

  - 所有数字字形排列在网格的最左侧区域（占据前3列或前几列），从上到下依次排列，数字之间有1行黑色间隔。

- `Rule`：
  - 从主区域的最左列（紧挨数字字形区域右侧）开始，从左到右依次分配列。
  - 按照数字字形从上到下的排列顺序，依次处理每个数字：
    - 读取该数字字形表示的数值 n。
    - 将接下来的 n 列全部染成该数字的颜色（每列从第一行到最后一行全部填充）。
  - 所有数字处理完毕后，剩余的列保持黑色。
  - 数字字形本身保持不变。

- `Key insight`：像素拼成的数字字形同时编码了两个信息：颜色（决定染什么色）和数值（决定染多少列）。解题者需要先"读出"每个像素图案所代表的阿拉伯数字，这需要视觉模式识别能力。核心认知挑战在于意识到这些像素图案不是抽象形状而是可读的数字符号。
</new_puzzle>

- `description`：检测每个封闭矩形框内部图案的连通分量数，然后在框的外部四周均匀放置等量的标记点。

- `Input structure`：
  - 背景为黑色（black）。

  - 框本身和内部图案保持不变。

- `Key insight`：框内绿色图案的视觉复杂度不重要，唯一重要的是其连通分量的数量。解题者需要在不同样例间比较：内部图案的形状千变万化，但外部标记点的数量只跟"有几块"相关，而非"每块多大"或"什么形状"。连通分量计数是一个拓扑属性而非几何属性。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干对颜色相同的像素，每对之间的曼哈顿路径上的背景像素被染成第三种颜色，但路径必须先水平再垂直（L形拐弯），拐弯点的颜色不同于路径其他部分。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中散布着若干彩色单像素。每种非黑颜色恰好出现两次，形成若干"配对"（如两个红色像素、两个蓝色像素等）。
  - 各配对的两个像素既不在同一行也不在同一列（即形成的路径必然有拐弯）。
  - 不同配对之间的路径不会交叉（题目设计保证）。

- `Rule`：
  - 对于每对同色像素（颜色为 C），从其中行号较小（靠上）的像素出发，先沿水平方向移动到与另一个像素同列的位置，再沿垂直方向到达另一个像素。即路径为"先水平后垂直"的 L 形。
  - 路径经过的所有背景像素（不包括两个端点本身）染成灰色（grey）。
  - L 形路径的拐弯点（水平段与垂直段交汇的那个像素）染成橙色（orange），而非灰色。
  - 两个端点像素（颜色 C）保持不变。

- `Key insight`：同色像素配对是连接关系的编码。路径的走法不是任意的——必须是"先水平后垂直"而非"先垂直后水平"，这个约定只能从样例中观察推断。拐弯点用不同颜色标记这一细节进一步增加了规则的隐蔽性：解题者可能先注意到灰色路径，但需要额外注意到拐弯点总是橙色的。
</new_puzzle>
