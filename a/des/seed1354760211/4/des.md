# 第一步：分析与思考

## 参考题目中的基础操作提炼

通过分析 20 道参考题目，我提炼出以下基础操作类别：

1. **空间移动/滑动**：对象沿某方向滑动（ref1 的 docking、ref3 的按面积上移、ref5 的粒子沿走廊移动）
2. **计数与编码**：将数量信息映射到网格中（ref16 的计数打点、ref2 的精灵计数转移）
3. **排序与重排**：按某属性排序后重新分配（ref17 的按高度排序柱形图）
4. **模式提取/压缩**：从冗余结构中提取核心信息（ref12 的奇异格提取、ref20 的行列压缩、ref10 的表格摘要）
5. **路径追踪/射线**：沿方向传播并遇障碍改变行为（ref5 的走廊粒子、ref8 的对角射线、ref14 的反射射线）
6. **模板与着色组合**：用一个来源提供形状、另一个来源提供颜色（ref6 的模板+色板、ref15 的种子着色网络）
7. **几何变换映射**：旋转/镜像后保持对应关系（ref19 的控制标记跟随旋转、ref11 的符号压缩+重力方向）
8. **序列/路径上的颜色操作**：沿路径做颜色层面的变换（ref13 的颜色反转）
9. **连接/桥接**：在对象间建立可见连接（ref18 的桥接方块、ref9 的填充间距）

## 非显而易见的串联方式思考

- **面积编码方向**：一个区域的像素数可以决定另一个对象的移动方向（如面积 mod 4 映射到四个方向），这将计数和空间移动以非直觉方式连接。
- **拓扑作为选择器**：对象的孔洞数量（genus）可以作为选择哪种变换规则的隐性索引。
- **颜色频率编码排列**：某种颜色在网格中出现的次数决定了另一组对象的排列顺序。
- **邻域对称性决定变换类型**：一个对象周围邻居的对称类型（水平对称 vs 旋转对称 vs 无对称）决定对该对象施加哪种操作。
- **形状边界的凹凸编码信息**：形状轮廓上凸出/凹入的位置可以编码一个二进制序列，用于驱动其他变换。
- **间距作为缩放因子**：两个标记物之间的距离决定输出对象的缩放比例。
- **遮挡层序恢复**：多个半透明叠加的形状需要通过颜色混合规则推断原始分层顺序。

<description>
根据每个封闭区域内部的孔洞数量，从调色板行中选取对应颜色填充该区域。

Input structure:
- 背景色（black）占据大部分网格。网格上半部分散布着若干用同一种前景色（如 blue）绘制的封闭形状，每个形状由一像素宽的闭合轮廓构成。有的形状内部被完全填充（0 个孔洞），有的形状内部包含 1 个、2 个或更多个由背景色构成的独立连通孔洞区域。
- 网格底部有一行水平排列的单像素色块，颜色各不相同且依次排列（例如从左到右为 red、green、yellow、magenta……），这一行即为"调色板行"，色块之间以背景色间隔。调色板行中第 1 个色块对应 0 个孔洞，第 2 个色块对应 1 个孔洞，依次类推。

Rule:
- 首先识别网格上半部分所有用前景色绘制的封闭形状（4-连通轮廓线）。
- 对每个封闭形状，计算其内部（轮廓线围成的区域中）有多少个独立的背景色 4-连通分量——即孔洞数量 h。注意：整个轮廓线外的大面积背景不算孔洞。
- 读取调色板行，从左到右将色块编号为 0, 1, 2, …。
- 将每个封闭形状的轮廓线颜色替换为调色板中第 h 号色块的颜色。形状内部仍为背景色，孔洞保持不变。
- 调色板行本身在输出中被移除（用背景色替换）。

Key insight:
形状的拓扑特征——孔洞数量——是颜色选择的隐性索引，解题者需要意识到不同形状之间的视觉差异在于内部孔洞数量，而非形状大小或位置，并将其映射到底部调色板的序号。
</description>

<new_puzzle>
<description>
将每个彩色对象沿其质心到最近同色单像素标记的方向平移，平移距离等于对象与标记之间的曼哈顿距离。

Input structure:
- 背景色为 grey。网格中分布着若干不同颜色的小型多像素对象（每种颜色恰好有一个对象，形状各异，均为 4-连通），以及若干散落的单像素标记点。
- 每个单像素标记点的颜色恰好与某个多像素对象的颜色相同——即每个对象都有一个同色的单像素"锚点"。锚点与其对应对象之间存在明确的行或列对齐关系：锚点要么在对象质心的正上方、正下方、正左方或正右方（严格在四个基本方向之一上）。

Rule:
- 对每个多像素对象，找到与其颜色相同的单像素锚点。
- 计算对象质心（像素坐标均值取整）到锚点的曼哈顿距离 d 和方向 dir（上/下/左/右）。
- 将对象沿 dir 方向平移 d 个像素，保持形状和颜色不变。平移后对象的原位置恢复为背景色。
- 锚点在输出中消失（用背景色替换）。
- 对象平移后不会超出网格边界，也不会与其他对象重叠（题目保证此条件）。

Key insight:
解题者需要发现每个对象都有一个同色的单像素"导航标记"，而关键的非直觉之处在于平移距离不是"移动到锚点位置"，而是"以锚点距离为步数继续沿同方向移动"——对象飞越锚点而非停在锚点处。
</description>

<description>
在网格中根据每个矩形边框四条边上缺口的位置，在边框内部对应的行或列上绘制贯穿线段。

Input structure:
- 背景色为 black。网格中散布着若干不同颜色的矩形空心边框（每个边框由单像素宽的完整矩形轮廓线构成），边框之间不重叠不接触。
- 某些边框的轮廓线上存在一个或多个"缺口"——即轮廓线上有单像素被替换为背景色的位置。每个缺口的位置是明确的（在顶边、底边、左边或右边上）。
- 在网格某个角落有一个小型 2x2 的色块作为"填充色指示器"，其颜色不同于任何边框颜色。

Rule:
- 对每个矩形边框，逐一检查其四条边上的缺口。
- 对于顶边或底边上位于列 c 的缺口，在边框内部沿列 c 从顶边内侧到底边内侧绘制一条竖直线段，颜色使用填充色指示器的颜色。
- 对于左边或右边上位于行 r 的缺口，在边框内部沿行 r 从左边内侧到右边内侧绘制一条水平线段，颜色同样使用填充色指示器的颜色。
- 若水平线段和竖直线段交叉，交叉点颜色为填充色（直接覆盖即可，因为颜色相同）。
- 边框轮廓线本身（包括缺口）保持不变。填充色指示器在输出中保留。

Key insight:
解题者需要发现边框轮廓上看似"破损"的缺口不是需要修复的瑕疵，而是一种编码信号——每个缺口的位置投射一条内部填充线。核心推理在于将缺口的一维位置（边上的哪个像素）映射到内部二维空间的行或列贯穿线。
</description>

<new_puzzle>
<description>
识别网格中每对颜色相同的 L 形标记，用它们的朝向差异决定旋转角度，然后将两个标记之间矩形区域内的图案按该角度旋转。

Input structure:
- 背景色为 black。网格中有若干互不重叠的矩形区域，每个区域内部包含一个用 grey 像素绘制的小型图案（非对称形状，便于辨认旋转）。
- 每个矩形区域的两个对角处各有一个 L 形标记（由 3 个像素组成的直角形状），两个标记颜色相同且与 grey 不同。不同矩形区域的 L 形标记颜色不同。
- L 形标记有 4 种朝向：开口朝右下（标准）、开口朝左下（顺时针 90°）、开口朝左上（180°）、开口朝右上（逆时针 90°）。每对标记中，一个位于左上角附近，另一个位于右下角附近。

Rule:
- 将左上角 L 形标记的朝向定义为"源朝向"，右下角 L 形标记的朝向定义为"目标朝向"。
- 计算从源朝向到目标朝向的顺时针旋转角度（0°、90°、180°、270°）。
- 将该矩形区域内部的 grey 图案围绕区域中心顺时针旋转相应角度。
- L 形标记本身在输出中被移除（替换为背景色）。
- 若旋转角度为 0°，则图案保持不变。

Key insight:
L 形标记不仅仅是区域定位的边角装饰，它们的朝向差异编码了一个旋转指令。解题者需要对比每对 L 形标记的朝向来推断旋转量，而非简单地将标记视为位置锚点。
</description>

<description>
将网格中每个多色条纹对象按条纹颜色的出现顺序拆分成单色层，然后在垂直方向上将各层展开排列。

Input structure:
- 背景色为 azure。网格左半部分包含若干水平排列的多色条纹矩形对象，每个对象由多行组成，每行为单一颜色，不同行颜色不同，形成自上而下的颜色条纹序列（例如一个对象可能从上到下为 red-green-red-yellow，每行宽度相同）。
- 网格右半部分为空白（全为背景色），预留了足够的空间。
- 每个对象底部紧邻一行由 maroon 像素构成的单像素高度标记线，宽度与对象相同，标示该对象的位置。

Rule:
- 对每个多色条纹对象，识别其从上到下的颜色序列中每种颜色首次出现的顺序。例如 red-green-red-yellow 的首次出现顺序为 red(1st)、green(2nd)、yellow(3rd)。
- 将对象拆分为若干单色层：每种颜色对应一层，该层保留该颜色的所有行的位置，其余行替换为背景色。
- 在网格右半部分，将各单色层按首次出现顺序从左到右水平排列，层与层之间间隔一列背景色。每一层的垂直高度和宽度与原对象相同。
- 原对象从左半部分移除（替换为背景色），maroon 标记线保留在原位。

Key insight:
解题者需要发现输出不是简单地复制或移动条纹对象，而是按颜色将其"分层展开"——相当于将一个多色叠加的物体拆解为透明胶片式的单色分层视图。颜色首次出现的顺序决定了分层排列的空间位置，这是推断规则的关键。
</description>

<description>
在网格中找到所有成对的同色像素，将每对之间的最短正交路径用该颜色绘制；路径交叉时，交叉点变为两种路径颜色之外的第三种"冲突色"。

Input structure:
- 背景色为 black。网格边缘附近散布着若干单像素标记点，每种非背景颜色恰好出现两次（即标记点成对出现）。颜色包括 red、blue、green、yellow 等，共 3-5 对。
- 网格中央区域可能有少量 grey 像素作为不可通行的障碍墙。
- 网格右下角有一个单独的 orange 像素，这是"冲突色指示器"。

Rule:
- 对每对同色标记点，找到它们之间的曼哈顿最短正交路径（仅走水平和垂直方向，不穿过障碍墙）。当存在多条等长路径时，选择先水平后垂直的 L 形路径（即先走水平段直到与目标同列，再走垂直段）。
- 用该对标记点的颜色在路径上的所有背景像素处绘制线段（标记点本身保留）。
- 若两条不同颜色的路径经过同一个像素，则该像素的颜色变为冲突色指示器所示的颜色（orange）。
- 障碍墙和冲突色指示器在输出中保留不变。

Key insight:
解题者首先要发现同色像素的配对关系和路径绘制规则，但更深层的洞见是路径交叉产生第三种颜色——这一冲突检测机制是最不直觉的部分，需要通过对比多个样例中交叉点的颜色才能发现。L 形路径的确定性选择规则（先水平后垂直）也需要仔细观察样例中的拐弯方向来归纳。
</description>

<description>
根据每个形状在网格中的相对垂直位置，从上到下赋予递增的"权重"，然后将所有形状按权重值向下拉伸对应行数。

Input structure:
- 背景色为 yellow。网格中散布着若干大小不一的单色矩形（颜色各异，如 red、blue、green、magenta 等），矩形之间不重叠，不接触。每个矩形是实心填充的。
- 网格足够高，底部有充足的空白空间。

Rule:
- 将所有矩形按其顶边行号从小到大排序（即从上到下），排名从 1 开始。
- 对排名为 k 的矩形，将其在垂直方向上向下拉伸 k 行。具体地：保持矩形的顶边位置和宽度不变，将其高度增加 k（即底边向下扩展 k 个像素）。
- 若拉伸后矩形超出网格底边，则截断到网格边界。
- 拉伸后若矩形与其他矩形发生重叠，后拉伸的矩形（排名更大的）覆盖先存在的像素。

Key insight:
解题者必须发现矩形的变形量不是由其自身属性（大小、颜色）决定，而是由其在所有矩形中的相对垂直排名决定——位置越靠下的矩形被拉伸得越多。这种"排名决定变换参数"的机制需要通过对比不同样例中各矩形的拉伸量与其位置排序的对应关系来发现。
</description>

<new_puzzle>
<description>
将网格中的多段折线按其转弯方向序列解码为二进制信息，并在指定位置用填充/留空来表示解码结果。

Input structure:
- 背景色为 black。网格上半部分有若干条不同颜色的单像素宽折线（4-连通路径），每条折线从网格左侧边缘开始，向右延伸，途中发生若干次 90° 转弯（向上或向下），最终到达网格右侧边缘。每条折线颜色不同。
- 网格下半部分有一个用 grey 像素绘制的空白表格框架：表格有 N 行 M 列的小方格（每个方格内部为 3x3 的背景色区域，由 grey 边框分隔），其中 N 等于折线数量，M 等于每条折线的转弯次数（所有折线转弯次数相同）。

Rule:
- 对每条折线，从左到右沿路径行走，记录每次转弯的方向：向上转弯记为 1，向下转弯记为 0。
- 这样每条折线产生一个长度为 M 的二进制序列。
- 在表格中，第 i 行对应第 i 条折线（按折线颜色从上到下的起始位置排序），第 j 列对应第 j 次转弯。
- 若编码值为 1，在对应方格内部填充该折线的颜色；若为 0，方格内部保持背景色。
- 折线本身在输出中保留不变。表格框架保留。

Key insight:
折线的几何形状不仅仅是装饰——每个转弯方向是一个信息比特。解题者需要发现折线的空间轨迹编码了二进制信息，而下方表格是该信息的可视化解码矩阵。关键在于识别"向上=1、向下=0"的编码约定，这需要仔细对比折线的弯折方向与表格中的填充模式。
</description>
</new_puzzle>
