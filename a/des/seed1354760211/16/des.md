## 第一步：基础操作分析与非显而易见的串联思考

### 参考题中涉及的基础操作梳理

1. **空间移动/滑动**：精灵沿特定方向移动（题1、15、19）
2. **形状匹配与对接**：通过颜色/形状匹配将对象放入对应位置（题2、3、4、7）
3. **物理模拟**：水流、重力等物理过程模拟（题5）
4. **排序/统计**：按频率、位置等属性排序或统计（题6、20）
5. **几何变换**：旋转、翻转、缩放（题3、11、17）
6. **层级/遮挡关系推断**：从可见碎片推断层叠顺序（题13）
7. **包含关系判断**：边界框包含检测（题14）
8. **路径/连通性分析**：膨胀、交集、连通分量（题9、10）
9. **信息编码/解码**：用像素位置或颜色差异编码方向、数量等信息（题16、19）
10. **压缩/聚拢**：将散落的像素向锚点收拢（题12）
11. **链式依赖**：一个对象的属性决定下一个对象的选取（题1、17）
12. **过滤与合成**：从多个面板中选择子集并合成（题18）

### 非显而易见的串联方式思考

- **遮挡关系作为排序键**：层叠顺序本身可以编码一种优先级，用来决定后续变换的执行顺序——但不是简单的"上层先处理"，而是被遮挡的程度决定变换的参数。
- **连通性拓扑作为颜色赋予依据**：对象的连通路径结构（是否为环、是否有分支、端点数量）可以直接映射到离散颜色选择。
- **形状作为操作指令选择器**：不同形状不是被放到某个位置，而是代表不同的变换操作（如"L 形意味着旋转 90 度"，"T 形意味着镜像"）。
- **像素计数编码空间偏移量**：一个封闭区域内部的前景像素数直接决定另一个对象需要平移的格数。
- **边界接触方式编码填充图案**：对象接触网格边界的哪一侧（以及接触长度）决定了该对象内部应该以什么模式着色。
- **对象间距离编码颜色**：两个同色对象之间的曼哈顿距离或切比雪夫距离对应到调色板中的某个颜色。
- **局部对称性缺陷作为信息载体**：一个近似对称的图案中，打破对称的那几个像素本身编码了关键信息（方向、数量等）。

<new_puzzle>
<description>
利用封闭区域内部"种子"像素的偏心位置，选择性地对矩形边框最近的边着色。

Input structure:
- 背景为 black。网格中有若干由 grey 像素构成的封闭矩形边框（边框宽度恰好为1像素，内部为 black 区域）。各矩形互不接触，尺寸各异（内部至少 3x3）。
- 每个矩形内部恰好有一个非 black、非 grey 的单像素"种子"，种子颜色在不同矩形中各不相同（可为 red、blue、green、yellow 等）。
- 矩形内部除种子外均为 black。

Rule:
- 对每个矩形框，计算种子像素到内部四条边（上、下、左、右内壁，即边框内侧紧邻的那一行/列）的距离（以像素格数计，即种子行/列坐标与内壁行/列坐标之差的绝对值）。
- 找出距离最短的一条或多条边（若有并列则全部选中）。
- 将距离最短的边对应的那一段 grey 边框像素全部重新着色为种子的颜色。具体地，若最近边为"上"，则将矩形上边框整条水平线段的所有 grey 像素改为种子色；其余类推。
- 未被选中的边保持 grey，种子像素保持原色不变。

Key insight: 种子像素在矩形内的偏心位置编码了哪些边需要被着色——离种子最近的边"吸收"种子的颜色。解题者需要发现距离-着色的对应关系，而非颜色匹配或形状匹配。
</description>
</new_puzzle>

<new_puzzle>
<description>
每个前景对象像"印章"一样在其4-连通邻域的 black 空间中留下缩小一圈的同色印记，印记的层数由对象内部嵌入的计数标记决定。

Input structure:
- 背景为 black。网格中有若干个不同颜色的实心4-连通前景对象，形状不规则但凸性较好（无细长突出），大小在 4x4 到 8x8 之间。
- 每个对象内部恰好嵌有若干个 maroon 单像素标记（1 到 3 个），这些标记像素位于对象内部（被同色像素完全包围）。

Rule:
- 对每个前景对象，计算其内部 maroon 标记的数量 N。
- 对该对象执行 N 次"腐蚀-印记"操作：
  - 第 1 次：将对象的当前形状向外平移——沿每个边界像素的朝外方向各扩展1像素——但只在 black 空间中印下原形状（不覆盖其他已有对象）。然后对原对象做一次形态学4-连通腐蚀（剥去最外一层像素），得到缩小后的形状。
  - 第 2 次及后续：在第一次印记的外圈再向外扩展1像素，印下当前（再次腐蚀后的）更小形状；以此类推。
- 实际上更简洁地说：将原对象保留不变。在对象周围的 black 区域，从紧邻对象外侧开始，依次画出腐蚀 1 次、腐蚀 2 次、...、腐蚀 N 次后的对象轮廓（仅轮廓像素），颜色与对象相同。每一层轮廓与上一层之间间隔 1 像素。
- 所有 maroon 标记在输出中保持不变。

Key insight: maroon 标记的数量控制了"回声"轮廓的层数；解题者必须同时理解腐蚀作为形状缩小操作、以及计数标记作为迭代次数的编码，这两层信息缺一不可。
</description>
</new_puzzle>

<new_puzzle>
<description>
在网格中，不同颜色的发射器像素各自向四个正交方向发射光线，输出仅保留两条不同色光线交叉处的像素并标记为特定颜色。

Input structure:
- 背景为 black。网格尺寸不超过 20x20。
- 网格中散布着若干个不同颜色的单像素"发射器"（颜色可为 red、blue、green、yellow、magenta 等，每种颜色恰好一个发射器）。
- 任意两个发射器既不在同一行也不在同一列（保证不同色光线才可能交叉）。

Rule:
- 每个发射器从其位置向上、下、左、右四个方向各发射一条光线，光线沿行/列逐格延伸，颜色与发射器相同。
- 光线在碰到网格边界时停止。光线在碰到另一个发射器像素时也停止（不覆盖该发射器）。
- 在输出中，所有发射器像素保持其原始位置和颜色不变。
- 对于其余位置：如果该像素同时被恰好一条水平光线和一条垂直光线覆盖，且这两条光线颜色不同，则该像素在输出中着色为 orange。
- 所有其他位置（仅被一条光线覆盖、被同色两条光线覆盖、或未被覆盖）保持 black。

Key insight: 输出仅在异色光线交叉处显示 orange，光线路径本身完全不可见——解题者需要从散布的 orange 像素反推"正交投射+异色交叉"的机制，而非简单的连线或填充。
</description>
</new_puzzle>

<new_puzzle>
<description>
根据同色对象对的空间排列方向（水平主导还是垂直主导），对每个对象执行不同轴向的镜像翻转。

Input structure:
- 背景为 black。网格中有若干种前景颜色，每种颜色恰好出现两个分离的4-连通对象。
- 每个对象是一个不对称的小图案（边界框在 2x2 到 5x5 之间），使得镜像翻转后的结果与原图案视觉上明显不同。
- 同色的两个对象形状、朝向完全相同（像素图案一致，未经旋转或翻转）。
- 不同颜色的对象之间互不接触，且边界框不重叠。

Rule:
- 对每种前景颜色，取其两个对象边界框中心的坐标差：delta_col = 列差绝对值，delta_row = 行差绝对值。
- 若 delta_col > delta_row（两对象水平间距更大，即"水平排列"），则对该颜色的两个对象各自在原位执行左右镜像翻转（以各自边界框的垂直中心轴为对称轴）。
- 若 delta_row >= delta_col（两对象垂直间距更大或相等，即"垂直排列"），则对该颜色的两个对象各自在原位执行上下镜像翻转（以各自边界框的水平中心轴为对称轴）。
- 翻转在原位进行：翻转后的图案覆写在原来边界框的位置上，输出网格尺寸不变。

Key insight: 变换类型（左右镜像 vs 上下镜像）不是由颜色、形状或绝对位置决定的，而是由同色对象对之间的相对空间排列方向决定。解题者需要发现"对象对的几何关系"这一隐含条件。
</description>
</new_puzzle>

<new_puzzle>
<description>
将网格中近似对称的图案中打破对称的"瑕疵"像素提取出来，用这些瑕疵的相对位置在小输出网格中编码一个方向指令，据此旋转整个图案。

Input structure:
- 背景为 black。网格中央有一个由单一前景色（如 blue）构成的中等大小图案（约 7x7 到 12x12），该图案关于某一条对称轴（水平、垂直、或45度对角线之一）近似对称。
- "近似对称"的含义：图案如果关于该轴做镜像，绝大部分像素重合，但有少数（1-3个）像素不重合——这些不重合的像素被称为"瑕疵像素"。瑕疵像素使用与图案不同的另一种前景色（如 red）标出。
- 图案中恰好存在一条对称轴使得瑕疵数最少（即"最佳对称轴"）。

Rule:
- 找到图案的最佳对称轴（使瑕疵像素数量最少的那条轴）。
- 确定所有瑕疵像素（关于该轴镜像后不重合的 red 像素）。
- 计算瑕疵像素群的质心相对于图案中心的方向：若质心在图案中心的右侧，旋转方向为顺时针90度；若在左侧，为逆时针90度；若在上方，为180度旋转；若在下方，不旋转（0度）。方向判定以水平和垂直分量中绝对值较大者为主方向。
- 将整个图案（包括 blue 和 red 像素）按该旋转角度绕图案边界框中心旋转，输出旋转后的结果。背景保持 black。

Key insight: 瑕疵像素不是噪声——它们的位置编码了旋转指令。解题者需要先发现图案的近似对称性，再识别出打破对称的像素承载着变换信息。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格被分为若干"房间"，每个房间的墙壁颜色决定了该房间内部散落像素应该执行的聚合方式（靠左墙、靠下墙、或向中心收缩）。

Input structure:
- 背景为 black。网格被若干条1像素宽的彩色直线段分割成不规则的矩形"房间"（线段颜色有三种可能：red、green、blue，分别代表三种聚合指令）。
- 分割线段水平或垂直放置，完全跨越网格或在交叉点处与其他线段相接，形成封闭的矩形区域。
- 每个房间内部散布着若干 yellow 单像素，位置随机。
- 每个房间恰好被一种颜色的墙壁完全包围（即构成该房间四面墙的线段全部为同一种颜色）。

Rule:
- 识别每个封闭矩形房间及其墙壁颜色。
- 根据墙壁颜色执行不同的聚合操作：
  - red 墙壁：房间内所有 yellow 像素向左滑动，紧贴左墙堆叠（保持各自原始行不变，列坐标变为左墙内侧起依次排列，若同一行有多个 yellow 则紧密排列）。
  - green 墙壁：房间内所有 yellow 像素向下滑动，紧贴下墙堆叠（保持各自原始列不变，行坐标变为下墙内侧起依次向上排列）。
  - blue 墙壁：房间内所有 yellow 像素同时向房间中心收缩——每个 yellow 像素沿指向房间中心点的方向移动，直到与另一个 yellow 像素相邻或到达中心位置，最终所有 yellow 像素形成紧密连通的一团位于房间中央。
- 墙壁线段和背景保持不变。

Key insight: 墙壁颜色是操作指令——解题者需要通过对比不同房间内像素的移动模式，反推颜色-操作的映射关系。关键难点在于三种聚合规则视觉表现差异微妙，需要仔细对比多个房间才能区分。
</description>
</new_puzzle>

<new_puzzle>
<description>
网格中的每条折线路径被"拉直"为单方向直线段，拉直方向由路径端点处的标记像素位置编码，直线段长度等于原路径的像素总数。

Input structure:
- 背景为 black。网格中有若干条不同颜色的1像素宽折线路径，每条路径由一种独特颜色的像素组成（如 red、blue、green 等）。
- 每条路径是4-连通的像素链，没有分支——即链中每个像素最多与链中的两个像素4-连通相邻（端点像素只有一个链内邻居）。
- 每条路径恰好有两个端点。其中一个端点的某个4-连通邻居位置放置了一个 maroon 单像素标记（该位置不在路径上，也不在其他对象上）。另一个端点没有标记。
- 不同路径之间互不4-连通接触，maroon 标记之间也互不接触。

Rule:
- 对每条路径，找到与 maroon 标记4-连通相邻的那个端点作为"起点"。
- 计算路径的总像素数 L（从起点沿链遍历到另一端点所经过的像素数，包括两个端点）。
- maroon 标记相对于起点的方向（上、下、左、右四种之一）定义了"展开方向"。
- 在输出中，从起点位置出发，沿展开方向绘制一条长度恰好为 L 的连续直线段（包括起点自身），使用路径原本的颜色。
- 清除原路径中除起点外的所有像素（设为 black），清除所有 maroon 标记（设为 black）。
- 若直线段延伸时超出网格边界，则在边界处截断（只画到边界为止）。

Key insight: 折线路径的空间走向是无关的干扰信息——输出只关心路径长度和展开方向。解题者需要理解"路径遍历得到长度"和"标记方位编码方向"两个独立机制的结合。
</description>

<new_puzzle>
<description>
网格中有若干个形状相同但大小不同的同心图案，根据每个图案的面积（像素数）在输出中按面积从小到大的顺序垂直堆叠，并用面积差值决定图案之间的间距。

Input structure:
- 背景为 azure。网格中有 3 到 5 个由不同前景色构成的实心十字形（"+"形）对象，每个十字的臂宽为1像素，但臂长各不相同，因此大小不同。
- 每个十字使用独特的颜色（如 red、green、blue、yellow、magenta）。
- 十字对象在网格中随机分布，互不重叠、互不接触。

Rule:
- 计算每个十字形对象的像素总数（面积）。
- 在输出中，创建一个新的网格（背景为 azure），将所有十字形按面积从小到大的顺序从上到下垂直排列。
- 每个十字在输出中水平居中放置。
- 相邻两个十字之间的垂直间距（两者边界框之间的空行数）等于它们面积的差值。
- 输出网格的宽度等于最大十字的边界框宽度，高度恰好容纳所有十字及其间距。

Key insight: 排列顺序由面积决定，间距也由面积差值编码——解题者需要发现两个数值关系：排序和间距都来源于同一个属性（像素计数），这使得规律不容易通过单一维度的观察发现。
</description>
</new_puzzle>
