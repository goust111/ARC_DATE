## 第一步：分析与思考

### 参考题中涉及的基础操作梳理

1. **空间变换类**：反转/翻转（#1 中心对称反转）、旋转（#8 90°CCW旋转）、平移（#5 水平对齐移动、#13 水平平移对齐）、膨胀/收缩（#18 方块尺寸循环、#19 小L标记扩展为角落L）
2. **分割与重组类**：区域分割（#7 沿裂缝线分离、#12 flood-fill分区）、块重排（#2 整块重排序）、拼接/堆叠（#8 排序后堆叠、#4 链式拼装到凹槽）
3. **匹配与映射类**：颜色匹配（#6 颜色配对模版与方块）、形状匹配（#3 耦合器计数匹配、#4 形状填入凹槽）、类比推理（#10 A:B = C:?）
4. **标记/信号解码类**：方向标记（#3 朝向标记、#14 控制像素确定射线方向）、位置标记（#11 缺失角落确定三角形、#19 L朝向确定角落）、计数编码（#3 耦合器数量）
5. **模板/遮罩操作类**：刻模（#6 用模版挖空）、填充（#12 分区选择两个源面板）、掩膜交换（#20 交换motif mask并重着色）
6. **递归/自相似类**：分形展开（#17 种子掩膜递归替换）
7. **扫描排序与着色类**：序列着色（#15 扫描序重新着色循环）

### 非显而易见的串联方式思考

- **形状编码指令**：一个对象的几何属性（面积、周长、凸包缺口方向）可以编码另一个对象应受的操作类型，而非简单的颜色匹配。例如，一个对象的"洞"的形状决定另一个对象的裁剪方式。
- **拓扑关系作为隐藏通道**：两个对象之间的相对位置关系（包围、相切、嵌套深度）可以编码一个全局排列规则，而非仅用于局部操作。
- **缺失信息的推断**：像 #11 中缺失角落决定三角形一样，网格中"不存在"的东西可以作为核心信息源——缺失的颜色、缺失的对称性、中断的规律等。
- **跨对象属性传播**：一个对象的某种属性（如朝向）传播给相邻对象，形成链式反应，而非独立处理每个对象。
- **双重身份**：同一组像素既是某个变换的操作对象，又是另一个变换的参数编码。

<description>
根据每个封闭区域内部"缺口方向"来决定该区域应向哪个方向平移，最终所有区域各自移动一格。

Input structure:
- 背景为 black。
- 网格中有若干个由同一颜色（如 blue）绘制的矩形闭合边框（空心矩形），彼此不重叠不相邻。
- 每个矩形边框的四条边中，恰好有一条边上存在一个单像素宽的缺口（即该位置的边框像素被替换为 black），缺口位于该边的中点位置。

Rule:
- 对每个矩形边框，确定缺口所在的边：上边→矩形整体向上平移1格；下边→向下平移1格；左边→向左平移1格；右边→向右平移1格。
- 平移后，缺口保持不变（仍在原来那条边的中点位置）。
- 若平移后矩形会超出网格边界，则该矩形保持不动。
- 原位置的边框像素被清除为 black。

Key insight:
- 缺口不是破损，而是方向指令——它编码了该矩形应移动的方向。解题者需要发现缺口位置与平移方向之间的对应关系，而非试图"修补"缺口。
</description>
</new_puzzle>

<description>
将散落的彩色线段按"交叉点颜色"分组，每组线段拼合成一个完整的十字形，输出所有十字形紧凑排列的网格。

Input structure:
- 背景为 black。
- 网格中散布着若干条水平或垂直的单像素宽彩色线段（长度 3-7 像素不等），每条线段由单一颜色绘成。
- 某些线段的一个端点处有一个不同颜色的单像素标记点（标记点颜色不同于线段颜色，但同组线段共享相同的标记点颜色）。
- 没有标记点的线段不参与变换，直接从输出中移除。

Rule:
- 将所有带标记点的线段按标记点颜色分组。
- 每组恰好包含一条水平线段和一条垂直线段。
- 将同组的两条线段组合成十字形：以标记点颜色绘制交叉中心像素，水平线段的非标记端构成十字的左右臂，垂直线段的非标记端构成上下臂。十字臂的长度由对应线段长度决定（从中心向外延伸 = 线段长度 - 1 个像素）。
- 所有十字形按标记点颜色在可用颜色列表中的顺序，从左到右水平排列在输出网格中，相邻十字形之间间隔 1 列 black。
- 输出网格的高度为最大十字形高度，宽度为所有十字形宽度之和加上间隔。

Key insight:
- 标记点颜色是分组密钥而非装饰——颜色相同的标记点标识应当拼合的线段对。解题者必须忽略线段本身的空间位置，转而关注端点上微小标记点的颜色匹配关系。
</description>

<description>
网格中每个彩色区块的"影子"方向由区块自身的非对称缺角决定，将影子投射到背景上。

Input structure:
- 背景为 grey。
- 网格中有若干个大小不等的实心矩形色块（每个色块使用不同颜色，如 red、blue、green 等），彼此间有足够间距。
- 每个矩形色块在其四个角中恰好有一个角被挖去了一个 1×1 的像素（变为 grey 背景色），其余三个角完好。

Rule:
- 确定每个色块被挖去角的位置：左上角缺→影子投射方向为右下；右上角缺→影子向左下；左下角缺→影子向右上；右下角缺→影子向左上。
- 影子是该色块的完整矩形形状（含缺角）在投射方向上偏移 1 格后的副本，颜色使用 black。
- 先绘制所有影子，再绘制原色块（原色块覆盖在影子之上）。
- 若影子超出网格边界则裁剪。

Key insight:
- 缺角是方向编码器——缺失的角标识了"光源"所在的方向（光从缺角方向照来），影子投射到对侧。解题者需要建立"缺角位置"与"影子偏移方向"之间的对角映射关系。
</description>

<new_puzzle>
<description>
每个连通前景对象根据其内部包含的"种子像素"的数量，被复制成对应数量的缩小副本并环绕原位置排列。

Input structure:
- 背景为 black。
- 网格中有若干个由同一前景色（如 orange）构成的 4-连通实心对象，形状各异（矩形、L形等），彼此不相邻。
- 每个前景对象内部嵌有 1 到 4 个 red 像素（种子像素），这些 red 像素替换了对象中相应位置的 orange 像素。

Rule:
- 统计每个对象内部 red 种子像素的数量 N。
- 将原对象从网格上清除（变为 black）。
- 在原对象的 bounding box 中心位置，放置 N 个该对象的缩小副本（缩小到原对象 bounding box 尺寸的一半，向下取整，最小为 1×1）。
- N 个副本按以下位置排列：N=1 时放在中心；N=2 时分别放在中心左侧和右侧各偏移 1 格；N=3 时三角排列（上方一个、下方左右各一个）；N=4 时放在原 bounding box 的四个角。
- 副本颜色使用原对象的前景色（orange），不含 red 种子。

Key insight:
- red 种子像素不是装饰或噪声，而是一个计数器，编码了该对象应被分裂成多少个副本。解题者需要同时发现两件事：种子数量决定副本数、副本的排列模式随数量变化。
</description>
</new_puzzle>

<new_puzzle>
<description>
输入网格中的两种前景图案互为"锁"与"钥匙"，将钥匙旋转至与锁的开口朝向匹配后插入锁中，输出合并结果。

Input structure:
- 背景为 black。
- 网格中恰好有两个独立的前景对象，各用不同颜色绘制（如 blue 画"锁"，red 画"钥匙"）。
- "锁"是一个带有矩形凹槽（开口朝向四个方向之一）的较大实心形状——凹槽是锁的 bounding box 边缘上一段连续的缺口。
- "钥匙"是一个较小的凸出形状，其突出部分的宽度和深度恰好与锁凹槽的宽度和深度相等。钥匙的突出方向可能与锁凹槽开口方向不匹配。

Rule:
- 确定锁凹槽的开口方向（上/下/左/右）。
- 确定钥匙突出部分当前的朝向。
- 将钥匙绕其中心旋转 0°/90°/180°/270°，使钥匙的突出方向恰好与锁凹槽的开口方向相对（即钥匙突出部分指向锁凹槽内部）。
- 将旋转后的钥匙平移，使其突出部分恰好嵌入锁的凹槽，钥匙主体紧贴锁的外边缘。
- 输出网格仅包含合并后的形状：锁保持 blue，嵌入的钥匙部分重叠区域显示为 maroon（混合色），钥匙的非嵌入部分保持 red。

Key insight:
- 凹槽的朝向是隐含的旋转指令——解题者必须先识别哪个形状有"凹"（锁）哪个有"凸"（钥匙），然后发现钥匙需要旋转到凸凹互补方向后才能对接。重叠区域的颜色变化确认了插入动作。
</description>
</new_puzzle>

<description>
网格被若干条彩色分隔线划分为区域，每个区域内的散点图案需要沿该区域的分隔线颜色所编码的轴进行镜像翻转。

Input structure:
- 背景为 black。
- 网格中有若干条贯穿整个网格的水平或垂直单像素宽直线，每条线使用不同颜色（如 red、blue、green）。这些线将网格划分为矩形区域。
- 每个矩形区域内有若干散布的 yellow 前景像素构成不规则图案。

Rule:
- 每条分隔线作为其两侧相邻区域的镜像轴。
- 对于被多条分隔线包围的区域，使用以下优先级确定翻转方式：
  - 若区域的上边界或下边界是 red 线 → 将该区域内的 yellow 图案沿水平中轴上下镜像翻转。
  - 若区域的左边界或右边界是 blue 线 → 将该区域内的 yellow 图案沿垂直中轴左右镜像翻转。
  - 若同时存在 red 和 blue 边界 → 先执行水平翻转，再执行垂直翻转（等效于 180° 旋转）。
  - 若边界是 green 线或其他颜色 → 该区域图案不变。
- 分隔线本身保持不动。

Key insight:
- 分隔线的颜色不仅仅是视觉分隔器，更是变换指令——每种颜色编码了一种特定的镜像操作。解题者需要逐区域对比输入输出，发现不同区域的图案经历了不同方向的翻转，然后追溯到边界线颜色的编码含义。
</description>
</new_puzzle>

<description>
将网格中分散的同色像素对通过 L 形折线连接，连线颜色由像素对之间的曼哈顿距离奇偶性决定。

Input structure:
- 背景为 black。
- 网格中散布着若干彩色像素，每种非黑颜色恰好出现两次，形成若干"像素对"。
- 同色像素对之间没有其他同色像素阻挡。
- 像素对的分布保证连线不会重叠（每对的连线路径上不会经过其他对的像素或连线）。

Rule:
- 对每对同色像素，画一条 L 形折线连接它们（先水平再垂直，即先沿行移动到目标列，再沿列移动到目标行）。
- 连线颜色规则：计算两像素之间的曼哈顿距离 D。
  - 若 D 为奇数，连线颜色使用 azure。
  - 若 D 为偶数，连线颜色使用 maroon。
- 原始像素对保留其原有颜色不变（仅在端点之间的路径上绘制连线颜色）。
- 连线像素覆盖背景但不覆盖其他已有前景像素。

Key insight:
- 颜色配对确定了哪些点应当连接（同色即一对），但连线的颜色并非由端点颜色决定，而是由两端之间的距离奇偶性决定。解题者需要先发现同色配对规则，再发现连线颜色与距离之间的隐藏关系。
</description>
</new_puzzle>
