- Continue the sprite's diagonal motion one more panel to the right.

- The panels are consecutive frames of motion; the output is the next frame after the sequence.

<reference_puzzle index="2" source="train" puzzle_id="11dc524f" lines="25-40">
<description>
Slide the non-square sprite to the square anchor and replace the anchor with the sprite's mirror image.

Input structure:
- The background is the most common color.
- There is one 8-connected non-background sprite that is not a solid 2x2 square.
- There is one solid 2x2 square anchor in another non-background color.

Rule:
- Move the sprite straight toward the anchor along their unique cardinal separation until it touches the anchor's near edge.
- Reflect the moved sprite across that near edge and draw the reflected copy in the anchor color.
- Clear the original locations; the output keeps only the moved sprite and reflected anchor-color copy.

Key insight:
- The 2x2 square marks the mirror line: its side facing the sprite becomes the contact edge for a two-color reflected pair.
</description>

<reference_puzzle index="3" source="train" puzzle_id="3d6c6e23" lines="10-27">
<description>
Move each vertical stream of pixels into a bottom-aligned centered pile.

Input structure
- A mostly background grid contains one or more vertical source columns of
  foreground pixels.
- Each source column has n^2 foreground pixels, and the top-to-bottom color
  sequence splits into monochrome groups of lengths 1, 3, 5, ...

Rule
- Clear the canvas to background.
- For each source column, read the foreground colors from top to bottom and
  rebuild them at the bottom below the same column as odd-width centered
  rows of lengths 1, 3, 5, ...

Key insight
- The scattered vertical pixels are falling grains; a square number of
  grains decomposes into the odd row widths of a centered pyramid.
</description>

<reference_puzzle index="4" source="train" puzzle_id="abbfd121" lines="56-74">
<description>
Recover the repeating background pattern hidden under the largest solid rectangle.

Input structure:
- The grid is covered by a small row/column periodic pattern.
- Several non-pattern colors form solid rectangular foreground objects that
  overwrite the pattern.
- The requested output region is the largest of those solid rectangles.

Rule:
- Find every 4-connected monochromatic object whose bounding box is a filled
  rectangle with both dimensions greater than one.
- Treat those rectangles as masks, infer the smallest repeating tile that is
  consistent with all remaining visible pixels, and repaint the largest
  rectangle's coordinates with that tile.

Key insight: The rectangle colors are occluders; the visible pixels outside
them are enough to reconstruct the original periodic background underneath.
</description>
</reference_puzzle>

<description>
Decode the colored 3x3 contour motif into a 16x16 periodic lattice with the motif stamped in maroon at the center.

Input structure:
- The grid is 6x6 with orange background and one non-orange color.
- The non-orange pixels have a tight 3x3 bbox containing one contour glyph.
- The glyph is one of the task's period-3 contour forms: plus, H, X, or four corners.

Rule:
- Decode the 3x3 glyph into the period-3 orange phase tile.
- Fill a black 16x16 canvas by repeating that orange phase tile.
- Tile the original 3x3 glyph 2x2 and recolor its true pixels to maroon in the centered 6x6 region.

Key insight:
- The colored object is not copied at its input location; it is a small contour code whose phase tells where orange appears in the repeated lattice.
</description>
</reference_puzzle>

Rule

<description>
Render the filled-square object counts as compact nested stacks ordered by count rank.

Input structure
A large noisy grid has a dominant background, scattered non-square noise, and
filled monochrome square objects. Each square side length has exactly one
object color, and side lengths form consecutive sizes.

Rule
Ignore non-square components. If the lowest square in the scene is of the
smallest side length, treat that one smallest square as a distractor and do
not count it. For count rank k from left to right, create one block from all
square sizes with at least k remaining objects; draw larger squares first and
smaller squares over their upper-left corner, then append one background
separator column.

Key insight
The output is a count histogram of square side lengths, but each histogram
slot is rendered as nested upper-left square masks using the side colors.
</description>
</reference_puzzle>

Swap paired marker pixels across the largest foreground-color barrier, placing them just outside the barrier segment.

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式。
   - **禁止使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算 / 余数、拓扑距离（BFS / 最短路 / 跳数）、高精度方向区分（>4 方向，如时钟 12 方向）、精确几何质心坐标、凸角 / 凹角计数。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号进行排序；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 排序或优先级规则必须基于网格中可见的属性（如位置、面积、数量），不得依赖颜色名称的字母顺序或颜色编号等先验知识。
7. 每个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
8. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
9. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
10. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。
   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**禁止用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
11. 层数可以是两层、三层或更多——不必拘泥于两层。若题目的机制天然适合更深的嵌套，鼓励向三层及以上尝试；但层数本身不是目的，每一层都必须有独立的归纳价值。

生成后对生成的题执行以下五项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述参考题相同或类似，不可只是替换颜色、方向、对象类型等表层要素。判断标准：新题的核心推理路径应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。禁止使用上述禁用的数学知识和人类不可用的信息（颜色id排序等）。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。
5. 层级有效性与内部一致性
  逐题检查以下两点，发现问题需要重写该题：
  - **层级是否会坍缩**：每一层是否都对最终输出有独立贡献？是否存在某一层无论怎么变化都不影响下一层结果的情况？（例如规则号称"先用 A 选出 B，再用 B 控制 C"，但 A 的所有可能取值都导出同一个 B，第一层实际无效，整道题坍缩为单层。）
  - **层级是否"感知透明"**：某一层的结果是否无需从样例中归纳、仅靠直觉就能看出？（例如"数嵌套层数""找面积最大的色块""看缺口在哪一侧"等——这些是直接读取而非推理，不算独立的归纳层。真正的层应该是：如果只看单个样例，无法确定该层的规则，必须对比多个样例才能发现。）
  - **规则是否自相矛盾**：题目内部是否存在隐性冲突或未覆盖的退化情况？（例如两条优先级条件在某些输入下会冲突，或某个对象没有标记、某个区域无内部像素时规则失效。）

若任意一题未通过上述五项审查中的任何一项，丢弃该题并重新生成一道替代题，替代题同样需要通过全部五项审查后才可保留。
