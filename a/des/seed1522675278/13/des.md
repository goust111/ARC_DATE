<new_puzzle>
把每个前景对象按其内部孔洞数量归入对应的颜色图例行，然后将对象缩放并排列到该行中。

Input structure：
- 背景为黑色。
- 网格左侧有一列纵向排列的颜色图例条目，每个条目是一个小色块（如红、蓝、绿），色块旁边紧跟着若干个用灰色小方块表示的计数标记（1个、2个或3个灰色方块）。
- 网格其余区域散布着若干个不同颜色的4连通前景对象，这些对象内部可能包含0到3个背景色孔洞（被对象像素完全包围的背景色连通区域）。

Rule：
- 统计每个前景对象内部的孔洞数量。
- 在颜色图例中，找到灰色计数标记数量与该孔洞数量相等的图例行。
- 将该对象重新着色为对应图例行的颜色。
- 输出网格仅保留图例列；在每个图例行的右侧，按照对象在原网格中从左到右的顺序，将归入该行的所有对象紧凑排列（对象之间间隔1列背景色），对象保持原始形状不缩放。
- 若某图例行无对象归入，则该行右侧保持空白。

Key insight：
- 孔洞数量是分类的隐含键，而非对象自身的颜色；图例中的灰色方块数量编码了分类阈值，解题者必须先发现"孔洞数→灰色标记数"的对应关系，再完成颜色替换与空间重排。
</new_puzzle>

<new_puzzle>
沿着每个箭头指示的方向，将箭头尾部区域的图案"印章式"复制到箭头头部前方的空白区域。

Input structure：
- 背景为黑色。
- 网格中有若干个由单一颜色绘制的箭头形状。每个箭头由一条直线段（至少3像素长，水平或垂直）加上末端的三角形箭头头组成：三角形箭头头由3个像素构成——直线末端像素的前方1格为尖端，尖端两侧各1格为翼。
- 每个箭头的尾部方向（与箭头指向相反的方向）存在一个由其他颜色组成的矩形图案块，该图案块的一条边紧贴箭头直线段的起始端。

Rule：
- 对每个箭头，识别其指向的基数方向（上、下、左、右）。
- 找到箭头尾部紧贴的矩形图案块。
- 将该图案块沿箭头指向方向平移，使图案块的对应边紧贴箭头头部尖端前方1格处。
- 在新位置绘制图案块的副本，保持原始颜色和形状。
- 移除箭头本身（箭头像素变为背景色），但保留原始位置的图案块不变。

Key insight：
- 箭头不是要移动的对象，而是"传送指令"；解题者需要先识别箭头方向来确定传送目标位置，再理解尾部图案是被复制的内容——箭头同时编码了方向和距离（箭头长度决定了图案出现的位置）。
</new_puzzle>

<new_puzzle>
根据框架颜色选择内部填充模式：框架缺口侧的相邻外部色块决定填充颜色，框架完整边的数量决定填充方向（水平条纹或垂直条纹或棋盘格）。

Input structure：
- 背景为黑色。
- 网格中有若干个由同一颜色像素构成的矩形框架（空心矩形），每个框架的四条边中可能有一条或多条边存在1像素宽的缺口（该边中间某处缺少一个像素）。
- 每个框架外部、紧贴缺口位置处，有一个单像素的彩色标记（颜色各不相同）。
- 框架内部为背景色（空的）。

Rule：
- 对每个框架，统计其四条边中完整（无缺口）的边数 N。
- 找到缺口旁的外部彩色标记，该标记的颜色即为填充颜色 C。若有多个缺口，取最上方或最左方缺口的标记色。
- 根据 N 的值决定填充图案：
  - N = 3（仅一个缺口）：用颜色 C 对框架内部做水平条纹填充（奇数行填色，偶数行留背景，行号相对于框架内部顶行从1开始计数）。
  - N = 2（两个缺口）：用颜色 C 对框架内部做垂直条纹填充（奇数列填色，偶数列留背景，列号相对于框架内部左列从1开始计数）。
  - N = 1（三个缺口）：用颜色 C 对框架内部做棋盘格填充（行号+列号为偶数时填色，为奇数时留背景）。
- 框架边框本身保持不变。

Key insight：
- 解题者需要分两层推理：第一层是发现缺口旁的外部标记决定填充颜色；第二层是发现完整边的数量编码了填充模式的类型——这两个信息来源完全不同（空间邻接 vs 结构计数），不容易一次看出。
</new_puzzle>

<new_puzzle>
将散落的单色碎片拼回到网格中央的灰色剪影区域内，每个碎片的放置位置由剪影内部的同色锚点像素确定。

Input structure：
- 背景为黑色。
- 网格中央有一个由灰色像素组成的大型不规则剪影区域（4连通）。
- 剪影内部散布着若干个不同颜色的单个锚点像素（每种非灰色、非背景颜色恰好在剪影内出现一次）。
- 剪影外部散布着与锚点颜色一一对应的小型单色碎片对象（4连通，每个碎片恰好包含一个与其同色的特殊标记像素，该像素在碎片中被替换为灰色）。

Rule：
- 对每个碎片，找到其中唯一的灰色像素——这是碎片的锚定点。
- 在剪影内部找到与该碎片颜色相同的锚点像素。
- 将碎片平移，使碎片中的灰色锚定点与剪影内部的同色锚点像素位置重合。
- 将碎片（包括其灰色锚定点）覆盖写入输出网格。碎片的非灰色像素覆盖剪影的灰色像素；碎片的灰色锚定点保持灰色。
- 所有碎片放置完毕后，剪影中未被碎片覆盖的灰色像素保持灰色不变。
- 输出网格大小与输入相同，剪影外部保持黑色背景。

Key insight：
- 碎片中的灰色像素不是碎片形状的一部分，而是对齐锚——解题者必须先发现碎片内部"异色像素"的作用是定位键，再将其与剪影内部的同色锚点匹配，这是两步非显然的归纳过程。
</new_puzzle>

<new_puzzle>
根据每个封闭区域的边界颜色组合，从网格边缘的色带图例中查找对应的填充颜色，然后填充该区域。

Input structure：
- 背景为黑色。
- 网格中由多种颜色的线段交叉形成若干个封闭区域（线段宽度为1像素，线段颜色可以是红、蓝、绿、黄等）。
- 网格最底部一行是色带图例：由若干组色块组成，每组包含2-3个相邻像素的颜色组合（如红+蓝相邻），紧接着隔1格背景色后是一个单独的"结果色"像素。各组之间用2格背景色分隔。

Rule：
- 找到网格中所有被线段完全围成的封闭背景色区域（4连通背景色连通分量，不与网格边界相连的）。
- 对每个封闭区域，收集其边界上所有线段像素的颜色集合（去重后排序）。
- 在底部色带图例中，找到颜色组合与该边界颜色集合完全匹配的图例组。
- 用该图例组的结果色填充该封闭区域。
- 线段本身保持不变，图例行保持不变。

Key insight：
- 封闭区域的填充颜色不由任何单一边界线决定，而由围成它的所有边界线的颜色组合共同决定——解题者必须先发现"多色边界→组合查表"的映射机制，再在图例中找到对应的输出颜色，这需要同时理解空间结构（哪些线围成了区域）和符号映射（颜色组合对应什么填充色）。
</new_puzzle>

<new_puzzle>
将网格中的每个对象沿其"尾巴"方向滑动，直到尾巴尖端接触到同色边框线段，然后将对象与边框线段之间的间隙用 azure 色填充轨迹。

Input structure：
- 背景为黑色。
- 网格的四条边上各有一段或多段单色线段（不一定覆盖整条边），这些边框线段颜色各异。
- 网格内部有若干个前景对象，每个对象由一个主体块（紧凑的矩形或近矩形区域）加上一条从主体某侧伸出的单像素宽"尾巴"组成（尾巴沿基数方向延伸2-4个像素）。
- 每个对象的主体颜色与网格四边上某一段边框线段的颜色相同。

Rule：
- 对每个对象，识别其尾巴伸出的方向（尾巴从主体延伸出去的基数方向）。
- 找到网格四边上与该对象同色的边框线段。
- 将整个对象（主体+尾巴）沿尾巴方向平移，直到尾巴的尖端像素与同色边框线段相邻（紧贴边框线段，中间无间隔）。
- 对象移动后，在原始位置和新位置之间、沿移动路径上，用 azure 色填充对象主体扫过的矩形轨迹区域（不含对象最终位置本身）。
- 若多个对象的轨迹重叠，后移动的对象（按原始位置从上到下、从左到右的顺序）的轨迹覆盖先前的。

Key insight：
- 解题者需要三层推理：第一层是识别对象的"尾巴"结构来确定移动方向（尾巴指向目标而非远离目标）；第二层是通过颜色匹配找到目标边框线段确定终点；第三层是理解轨迹填充规则。尾巴既编码了方向又暗示了目标，这种双重编码增加了机制的隐蔽性。
</new_puzzle>

<new_puzzle>
根据连接线将分散的半图案配对，然后将每对半图案沿连接线方向对折合并，重叠区域取两个半图案的非背景色像素的并集。

Input structure：
- 背景为黑色。
- 网格中有若干对小型彩色图案（每个图案为一个4连通前景对象）。
- 每对图案之间由一条单像素宽的灰色直线连接（水平或垂直），灰色线的两端分别紧贴配对图案的边缘。
- 每对图案的形状大小相同（bbox 尺寸一致），但内部像素分布不同——它们像是同一个完整图案被拆成了互补的两半（两者的非背景像素在 bbox 内不重叠）。

Rule：
- 通过灰色连接线识别配对关系。
- 对每一对，确定连接线的方向（水平或垂直）。
- 将两个图案沿连接线方向折叠合并：保持其中一个图案（离网格中心更近的那个）位置不变，将另一个图案平移到与之完全重叠。
- 在重叠位置，将两个图案的非背景像素合并（取并集），生成完整的合并图案。
- 移除灰色连接线和被平移的图案的原始位置（恢复为背景色）。
- 输出网格大小不变。

Key insight：
- 灰色线不是装饰而是配对标识和折叠轴线的方向提示；两个半图案互补的性质需要解题者先观察到它们的像素不重叠，然后推断出"合并"而非"替换"的操作——配对发现和合并逻辑是两个独立的推理层。
</new_puzzle>
