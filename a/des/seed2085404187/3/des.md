- `description`：根据边框形状匹配内外区域，将外部图案通过边框缺口"投射"进对应的封闭区域，投射方向由缺口朝向决定。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个由 grey 线条围成的封闭矩形区域（"房间"），每个房间内部填充 black，且每个房间的边框上恰好有一个 1 像素宽的缺口。
  - 每个房间外部、紧邻缺口处有一个小型彩色图案（sprite），颜色各不相同（如 red、blue、green 等），图案尺寸不超过房间内部尺寸。
  - 另外，网格中有若干个与房间分离的、用同样颜色绘制的独立色块（"钥匙"），每个钥匙是一个 1×1 或 2×1 的小块，颜色与某个外部图案颜色相同。

- `Rule`：
  - 第一层推理：每个钥匙的颜色指向一个外部图案，同时钥匙自身位于某个房间内部。这建立了"哪个图案进入哪个房间"的映射关系——图案进入包含同色钥匙的房间，而非进入紧邻该图案的房间。
  - 第二层推理：确定映射后，将图案通过目标房间的缺口"推入"房间内部。缺口在房间上边框则图案从上方向下贴入，缺口在左边框则从左向右贴入，以此类推。图案的边缘与缺口所在边框内侧对齐，沿缺口方向平移至紧贴对面内壁。
  - 移除所有钥匙像素和原始外部图案像素。房间边框和背景保持不变。

- `Key insight`：图案并非进入最近的房间，而是通过颜色钥匙间接匹配目标房间；缺口方向则决定图案在房间内的放置朝向和位置。两层映射（颜色匹配 + 空间投射）需要分别归纳。
</new_puzzle>

<new_puzzle>
- `description`：将散落的彩色碎片按形状互补原则拼合成完整矩形，再根据拼合后矩形的面积大小关系确定输出排列顺序。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干彩色连通块（4-连通），每个连通块有自己的颜色（如 red、blue、green、yellow、magenta 等），形状不规则。
  - 这些连通块可以两两配对：同一对中的两个块颜色不同，但形状互补——将其中一个块平移（不旋转、不翻转）后与另一个块恰好拼合成一个无间隙的实心矩形。
  - 每个连通块恰好属于一对，不存在落单的块。

- `Rule`：
  - 第一层推理（配对）：找出哪些块可以互补拼成矩形。方法是：对每个块计算其最小外接矩形（bounding box），两个块能配对当且仅当它们的 bounding box 尺寸相同，且一个块的像素恰好填充另一个块在同尺寸 bounding box 中留下的空位。
  - 第二层推理（排序与输出）：将配对后的矩形按面积从小到大排列。输出网格中，每个拼合矩形从左到右依次排列（矩形之间间隔 1 列 black），矩形内部用两个原始块的颜色填充——保留各自原来的颜色，拼合在一起。

- `Key insight`：需要先通过"形状互补"这一非显然的几何关系找到正确配对，再通过面积排序决定输出布局。配对过程不是靠颜色或距离，而是靠形状的负空间匹配。
</new_puzzle>

<new_puzzle>
- `description`：在被墙壁分割的网格中，根据每个区域内"种子像素"的颜色层级关系，逐层向外扩展填充，高层级颜色覆盖低层级颜色。

- `Input structure`：
  - 背景为 black。
  - Azure 色的线条将网格分割成若干不规则的封闭区域。
  - 每个区域内散布着少量（1-4 个）不同颜色的单像素种子点（颜色可为 red、green、yellow、magenta、orange 等）。
  - 同一区域内不会出现两个相同颜色的种子。

- `Rule`：
  - 第一层推理（确定颜色层级）：观察所有训练样例，会发现颜色之间存在固定的优先级顺序（例如 red > green > yellow > orange > magenta），该顺序在所有样例中保持一致，需要从样例的输出中归纳出来。
  - 第二层推理（同步扩展与覆盖）：在每个区域内，所有种子同时开始向四方向（上下左右）逐步扩展，每步扩展 1 像素，填充为种子自身颜色。扩展不越过 azure 墙壁。当两个种子的扩展区域发生碰撞时，优先级高的颜色覆盖优先级低的颜色。最终每个区域内所有 black 像素都被填满。
  - Azure 墙壁保持不变。

- `Key insight`：表面上看是简单的 Voronoi 式填充（离谁近填谁的色），但当两个种子到某像素等距时，颜色优先级才决定归属。解题者必须从多个样例中归纳出隐含的全局颜色优先级顺序，这是第一层非平凡推理；同步扩展的空间填充逻辑是第二层。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中的"指令箭头"和"货物块"，箭头指示货物的移动方向，货物沿途会在经过的路径上"印刷"出自身颜色的痕迹，但痕迹的图案取决于货物的形状。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个彩色连通块作为"货物"（如 red 矩形、blue L 形等），每个货物颜色唯一。
  - 每个货物旁边（4-邻接方向上）有一个用 grey 像素绘制的箭头形状（由 3 个像素组成：一个箭杆像素和两个构成箭头尖端的像素，箭头尖端朝向移动方向）。箭头与货物之间恰好相邻 1 像素。
  - 网格边缘或其他货物可以作为阻挡物。

- `Rule`：
  - 第一层推理（解读箭头方向）：每个 grey 箭头由 3 像素组成——箭杆 1 像素在远离货物的一侧，箭头尖端 2 像素在靠近移动方向的一侧，形成">"、"<"、"∧"、"∨"的形态。箭头指向即为货物移动方向。
  - 第二层推理（移动与印刷）：货物沿箭头方向移动，直到碰到网格边缘或另一个货物（不重叠）停下。货物移动后，其起始位置到终止位置之间经过的所有格子（不含终止位置处货物自身占据的格子）用该货物颜色的"投影"填充——投影方式为：将货物形状沿移动方向逐行/逐列复制，形成拖尾效果。
  - 第三层推理（移动顺序）：当多个货物存在时，箭头箭杆长度（箭头总像素数不变，但箭杆到货物的间距可以是 1 或 2 格）决定移动优先级——间距为 1 的先移动，间距为 2 的后移动。先移动的货物停下后成为后续货物的阻挡物。
  - 移除所有 grey 箭头像素。

- `Key insight`：三层递进推理——先解读箭头方向，再理解形状拖尾的印刷机制，最后发现移动顺序由箭头与货物的间距隐式编码。间距信息容易被忽略，因为箭头形状看起来相似。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色环形边框内部隐藏着一个"模板"图案，需要提取模板并将其旋转后印刷到同色的目标区域上，旋转角度由环形边框的缺口位置编码。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个彩色矩形环形边框（如 red 环、blue 环、green 环），每个环宽 1 像素，内部尺寸为 3×3 或 4×4。
  - 每个环的边框上恰好有一个 1 像素缺口（缺口位于上、下、左、右四条边之一的中点位置）。
  - 每个环内部有一个用 maroon 像素绘制的小图案（不对称形状，以便旋转后可区分方向）。
  - 网格中另有若干个与环同色的小型实心矩形目标区域（尺寸与环内部相同），内部为 black，目标区域没有边框。

- `Rule`：
  - 第一层推理（模板提取与颜色匹配）：每个环内部的 maroon 图案是"模板"。通过环的边框颜色与目标区域的颜色匹配，确定每个模板应印刷到哪个目标区域。
  - 第二层推理（旋转角度解码）：环形边框的缺口位置编码旋转角度：缺口在上表示不旋转（0°），缺口在右表示顺时针 90°，缺口在下表示 180°，缺口在左表示逆时针 90°（即顺时针 270°）。将模板按此角度旋转。
  - 输出时，将旋转后的模板用环的边框颜色（而非 maroon）绘制到对应目标区域内。环形边框及其内部的原始模板从输出中移除（替换为 black）。目标区域无边框，仅显示旋转后的彩色图案。

- `Key insight`：缺口位置不仅仅是边框的装饰或入口标记，而是一个旋转指令的隐式编码。解题者需要先发现颜色匹配关系，再归纳出缺口方位与旋转角度的对应规则，最后注意到输出时颜色从 maroon 变为边框色。
</new_puzzle>

<new_puzzle>
- `description`：根据封闭区域内标记像素的相对位置关系，选择对应的几何变换（水平翻转、垂直翻转、转置）应用到区域内的彩色图案上。

- `Input structure`：
  - 背景为 black。
  - Green 色线条将网格划分为若干矩形区域。
  - 每个区域内部有一个用某种颜色绘制的不对称小图案（占据部分格子），以及恰好两个 yellow 标记像素。
  - 两个 yellow 标记像素位于图案的 bounding box 之外，但仍在该区域内。

- `Rule`：
  - 第一层推理（解码变换类型）：两个 yellow 标记像素的相对位置编码了要执行的几何变换：
    - 两个标记在同一行（水平排列）→ 对图案执行水平翻转（左右镜像）。
    - 两个标记在同一列（垂直排列）→ 对图案执行垂直翻转（上下镜像）。
    - 两个标记既不同行也不同列（对角排列）→ 对图案执行转置（沿主对角线翻转，即行列互换）。
  - 第二层推理（变换的锚点）：变换以图案的 bounding box 中心为锚点，在该区域内原地执行。变换后如果图案超出区域范围则裁剪（但设计上保证不会超出）。
  - 移除两个 yellow 标记像素（变为 black）。Green 分隔线保持不变。

- `Key insight`：yellow 标记的空间排列方式（水平、垂直、对角）本身就是变换指令的编码——这不是"标记在哪里"而是"标记之间的关系是什么"。解题者需要忽略标记的绝对位置，关注它们的相对几何关系。
</new_puzzle>

- `description`：在网格中找到被"遮罩块"部分覆盖的底层图案，利用相同图案在其他位置的未遮挡副本来还原被遮盖的部分，输出仅包含还原后的遮罩区域。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个彩色图案（每个图案由单一非 black 颜色绘制，形状各异，如 T 形、L 形等），每种图案至少出现两个副本，且副本之间形状完全相同（可能经过平移但未旋转或翻转）。
  - 有一个 grey 实心矩形"遮罩块"覆盖在网格上，部分遮盖了一个或多个图案的某些像素。被遮盖的像素在输入中显示为 grey。
  - 未被遮盖的图案副本完整可见。

- `Rule`：
  - 第一层推理（识别被遮盖的图案）：找到 grey 遮罩块的位置。检查遮罩块边缘处哪些彩色像素被截断（即某个彩色连通块的一部分与遮罩块相邻，说明该图案被部分遮盖）。
  - 第二层推理（通过副本还原）：对于每个被遮盖的图案，在网格其他位置找到同色且形状匹配的完整副本。将副本的形状对齐到被遮盖图案的可见部分，从而推断出被 grey 覆盖的那些像素原本应该是什么颜色。
  - 输出为仅包含 grey 遮罩块区域的子网格（裁剪到遮罩块的 bounding box），其中 grey 像素被还原为正确的底层颜色，未被任何图案占据的 grey 像素还原为 black。

- `Key insight`：解题者需要理解 grey 块是一层"遮挡"而非实体对象，然后利用远处的完整副本作为"参考答案"来重建被隐藏的信息。这要求同时进行模式匹配（找到对应副本）和空间推理（对齐并填补缺失部分）。
</new_puzzle>
