# 第一步：分析与思考

## 参考题中的基础操作梳理

从20道参考题中提炼出核心操作类型：

- **空间移动/压缩**：将对象沿特定方向滑动、压缩、弹射（#4 标记推进、#8 物体滑向边界栏、#15 杯中内容沿尾部弹出、#17 棋盘格压缩）
- **镜像/对称**：跨轴线反射像素（#9 沿轴镜像最少色）
- **模板匹配与填充**：用模板扩展、合成或转移图案（#3 洪水填充选择面板、#10 种子像素确定模板并放大填充、#12 从标记矩形提取边缘相对图案）
- **计数编码**：像素数量编码某种信息（#2 物体像素数决定线长、#18 行内前景计数决定条长）
- **标记/控制像素**：单个特殊像素充当指令（#16 粉色像素指定3x3区域位置、#7 红色像素标记目标中心）
- **分类与分组**：按颜色/属性将对象分组后分别处理（#14 角标记色分组精灵、#5 按原型归类后互换）
- **拓扑/连通性**：洪水填充、路径可达性判断（#7 墙壁阻隔可达性、#3 洪水填充分区域）
- **降维/抽象压缩**：将大网格压缩为小网格的摘要（#19 四象限压缩为3x3色图）

## 非显而易见的串联方式与信息编码思考

1. **几何形状本身就是指令**：一个对象的轮廓形状可以编码操作类型（比如缺口方向 → 移动方向；不规则凸起 → 生长点），而不仅仅是"哪个颜色"或"多少像素"。

2. **空间拓扑关系作为隐式配对**：两个不相邻的对象通过共享某个几何属性（如同处一条对角线、bbox面积相等、周长相同）而配对，这种配对决定后续操作。参考题中配对往往通过颜色显式标识，但更隐蔽的方式是通过空间/几何性质隐式配对。

3. **缺失即信息**：网格中"不存在"的东西可以是关键线索——比如一组规律排列中唯一缺失的位置就是输出需要填补的位置，或者一个对称图形中缺失的部分暗示了变换方向。

4. **层级嵌套**：外层结构决定宏观操作类型，内层细节决定微观参数——比如一个大框的形状决定变换类型，而框内小标记的位置决定变换参数。参考题多是单层操作，但若引入两层解读则难度和新颖度大幅提升。

5. **负空间操作**：对前景做操作实际需要观察背景的形状，或者反过来——变换的目标并非前景对象本身而是前景对象围出的背景空洞。

6. **跨对象的属性传递**：A对象的某个属性（面积、朝向、内部标记位置）被"传递"给B对象，影响B的变换方式。这种跨对象的信息流在参考题中较少出现，是一个有创造力的方向。

7. **结构自指**：网格中某部分的结构描述了如何处理另一部分——类似"自包含的说明书"，规则不是外部给定的而是嵌入在输入网格本身之中。

  - 网格中有若干个 azure 的 1x1 像素作为"靶心"，初始颜色均为 azure。

  - 网格中有若干条由 grey 像素组成的水平或垂直线段，称为"篱笆"。每条篱笆是连续的一行或一列 grey 像素，长度至少为3。篱笆之间可能在端点相接形成T形或L形的围栏。
  - 篱笆将网格划分成若干个矩形区域（每个区域由篱笆线段和/或网格边缘围成）。
  - 每个矩形区域内部恰好包含一个或多个种子像素。
- `Rule`：
  - 首先识别由篱笆和网格边缘围成的每个封闭矩形区域。
  - 统计每个区域内的种子数量。
  - 若区域内只有一个种子，则用该种子的颜色填满整个区域内部（篱笆像素保持 grey）。
  - 若区域内有多个种子，则找出其中面积最大的种子...不，种子都是单像素没有面积差异。改为：若区域内有多个种子，则用出现在该区域中最靠近区域中心的那个种子的颜色来填满整个区域。若有多个种子与中心等距，则取这些种子中颜色值排序（按 red < orange < yellow < green < blue < magenta 的顺序）最前的那个。
  - 填充后，所有种子像素被填充色覆盖（消失在填充中）。篱笆保持 grey。
- `Key insight`：解题者最初可能以为每个种子"生长"填满自己的区域（类似 Voronoi），但实际上篱笆严格定义了区域边界，且决定填充颜色的关键是"哪个种子最靠近区域中心"。这意味着一个种子可能位于某区域的角落而被另一个更靠近中心的种子"抢占"了该区域的颜色权。解题者需要先识别篱笆围成的区域，再比较区域内各种子到中心的距离。
</new_puzzle>

  - 蛇头颜色编码旋转角度：red = 顺时针90度，blue = 顺时针180度，green = 逆时针90度（即顺时针270度）。

  - 对每条蛇，以蛇头像素的位置为旋转中心。

  - 旋转后若蛇的某些像素落在网格外则截断（不绘制那些超出边界的像素）。
  - 旋转后若蛇的像素与另一条蛇重叠，则后者不受影响（先画的保留，重叠位置取先旋转完成的蛇的颜色——但题目保证在正确旋转下不会发生重叠）。
- `Key insight`：解题者面对的挑战是多层的：首先要识别出每条蛇由"身体+异色头"构成，然后要发现蛇头的颜色不是随机的而是一个旋转指令，最后要理解旋转的锚点是蛇头而非蛇的中心或尾部。一旦发现"异色端点 = 旋转枢纽 + 旋转角度编码"，规则就完全确定了。

- `Input structure`：
  - 背景为 black。
  - 网格中有一条完整的水平或垂直的 grey 线条，宽度为1像素，从网格一端延伸到另一端，称为"墨带"。
  - 墨带的一侧（上方或左方）分布着若干个彩色前景对象，称为"印章"。每个印章是一个由单一颜色组成的4-连通区域，形状不规则，面积在2~10像素之间。不同印章颜色不同。
  - 墨带的另一侧（下方或右方）为空白（全 black）。
  - 印章只出现在墨带的一侧，且不与墨带接触（至少间隔1行/列的 black 背景）。
- `Rule`：
  - 将每个印章向墨带方向做正交投影（若墨带水平则向下投影，若墨带垂直则向右投影）。
  - 投影是指：对印章中的每个像素，在墨带上找到同列（水平墨带）或同行（垂直墨带）的位置。该墨带位置被标记为该印章的颜色。
  - 若多个印章的投影覆盖墨带上的同一个位置，则该位置的颜色由距离墨带最远的印章决定——即"后方优先"规则（离墨带远的印章被视为"在上层"，其投影遮挡近处印章的投影）。
  - 墨带上未被任何投影覆盖的像素保持 grey。
  - 印章本身和印章那一侧的区域在输出中保持不变。
- `Key insight`：直觉上可能以为近处的印章会遮挡远处的投影（近处优先），但实际规则恰好相反——离墨带更远的印章在投影中优先级更高。解题者需要从样例中发现这一"反直觉"的深度排序规则。此外，解题者还需要理解"投影"的概念：印章形状被压扁到1维的墨带上，只有占据的列/行信息被保留。
</new_puzzle>

<new_puzzle>
- `description`：网格中的每个彩色区域是一块"拼图碎片"，相邻碎片之间有锯齿形的边界；输出时每块碎片按它缺失的锯齿凸起数量向外扩展相应的像素数。
- `Input structure`：
  - 背景为 black。
  - 整个网格被若干个相邻的彩色区域无缝铺满（没有 black 背景，除了网格最外圈的1像素边框为 black）。每个区域是一种独特的颜色。
  - 相邻区域之间的边界呈锯齿形：在公共边界线上，一侧区域的像素"凸出"嵌入另一侧区域1个像素深度。每对相邻区域之间的凸出方向交替出现（类似拼图的凸起和凹陷），但每个凸起/凹陷只有1像素宽、1像素深。
  - 每个区域在其各条边界上的凸出总数（该区域向外凸出嵌入邻居的像素数）和凹陷总数（邻居向内凸入该区域的像素数）可以不同。
- `Rule`：
  - 输出网格与输入大小相同。
  - 对每个区域，计算其所有边界上"凹陷"的总数 N（即邻居的像素嵌入到自己领地的次数）。
  - 该区域在输出中保持原色不变，但其所有凹陷处被自己的颜色填平——即把邻居凸入自己的那些像素重新改为自己的颜色。
  - 同时，该区域自己的所有"凸出"像素（嵌入邻居的那些像素）被回收为邻居的颜色——即自己凸入邻居的像素归还给邻居。
  - 最终效果：所有锯齿边界被抹平，每对相邻区域之间变为一条平直的边界线。
- `Key insight`：解题者需要首先识别出相邻区域之间的"锯齿"结构，然后理解变换的目标是"消除锯齿使边界平直化"。关键洞见是，每个像素的归属要重新判定：如果一个像素是某区域"凸出"嵌入邻居的，那么它应该归还给邻居；如果是邻居"凸入"自己的，那么它应该被自己收回。判断方法是：在公共边界上，凸出的像素是那些如果被移除后不会破坏自身区域连通性、但会使边界变得更平直的像素。更具体地：沿每条水平或垂直的区域边界线，将边界上的"凸出"定义为边界线上偏离主线方向1像素的突出部分。
- `Rule`（简化重述）：
  - 识别每对相邻区域的公共边界。
  - 公共边界是一条大致水平或垂直的线段；边界上存在"锯齿"——某些像素从直线位置偏移了1像素。
  - 对每个锯齿凸起/凹陷：将凸起的像素归还给被凸入的区域（即把这些像素的颜色改为邻居区域的颜色）。
  - 等价地：将每段公共边界拉直为水平或垂直的直线，两侧的像素归属按直线划分。
- `Key insight`（修正）：核心洞见更精练地说是：输入中相邻区域的边界是锯齿形的，输出中所有边界变为直线。解题者需要发现"拉直锯齿边界"这一变换目标，而不是被各区域的颜色或面积分散注意力。
</new_puzzle>

- `description`：网格中每个对象旁边有一个由箭头形状标记指出的"目标位置"轮廓；将对象移动到目标轮廓内，并按轮廓形状裁剪对象。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干个彩色前景对象（每个是单色的4-连通区域，面积在4~15像素之间）。
  - 每个前景对象附近有一个对应的 grey "目标轮廓"——轮廓是由 grey 像素围成的封闭框，框内为 black，框的形状（内部空腔形状）与前景对象的形状可能不同（通常更小或形状有差异）。
  - 每个前景对象与其目标轮廓之间有一个由 azure 像素组成的"箭头"标记，箭头是一条1像素宽的直线（水平或垂直，长度2~4像素），末端有一个垂直于方向的1像素"箭头尖"，整体形成一个简单的箭头形状，从对象指向轮廓。
  - 每个前景对象恰好对应一个轮廓和一个箭头，箭头连接两者。
- `Rule`：
  - 对每对（对象，轮廓）：
  - 清除原始对象的所有像素（变为 black）。
  - 清除箭头的所有像素（变为 black）。
  - 将轮廓内部的空腔用前景对象的颜色填满。即目标轮廓的 grey 边框保持不变，但内部 black 区域变为对象颜色。
  - 无论原始对象与轮廓内腔的形状/大小是否匹配，都一律填满整个轮廓内腔——对象被"压入"轮廓模具中，溢出部分被裁掉，不足部分被填满。
- `Key insight`：解题者最初可能试图将对象的形状"搬运"到轮廓内，但实际上对象的形状完全不重要——只有对象的颜色被使用。变换的本质是：对象提供颜色，轮廓提供形状，箭头提供配对关系。三种元素各司其职。一旦理解了"颜色来源 + 形状模具 + 箭头配对"这三者的角色分工，规则就完全清晰了。

<new_puzzle>
- `description`：网格中有若干个同色的"时钟"对象，每个时钟处于不同的"阶段"状态；输出中所有时钟统一推进到下一阶段。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干个相同大小（5x5）的正方形区域，彼此不重叠不相邻。
  - 每个 5x5 区域由 blue 像素构成一个"L形"图案——即5x5区域中只有部分像素为 blue，其余为 black 背景。
  - 所有区域中的 L形图案是同一个基本形状经过 0度、90度、180度、270度 旋转后的变体。但并非所有旋转角度都出现——输入中每个区域的旋转角度是四种之一。
  - 具体形状：基本 L形 由一个 3x1 的垂直条和底部向右延伸的 2x1 水平条组成（总共5个像素），占据 5x5 区域左下角。旋转90度后占据左上角，180度后占据右上角，270度后占据右下角。
- `Rule`：
  - 将每个 5x5 区域中的 L形图案顺时针旋转90度。
  - 即：原来处于 0度（左下角）的变为 90度（左上角），90度（左上角）的变为 180度（右上角），180度（右上角）的变为 270度（右下角），270度（右下角）的变为 0度（左下角）。
  - 每个 L形图案各自在其 5x5 区域内独立旋转，不影响其他区域。
  - 5x5 区域的位置不变，只有内部的 L形图案转动。
- `Key insight`：解题者看到的网格中有多个"类似但朝向不同"的 L形。关键洞见是：这些 L形不是随机朝向的独立对象，而是同一个"时钟"处于不同"时刻"的快照。所有时钟统一执行"下一步"操作——顺时针转动90度。解题者需要从多个样例中发现"每个L都转了90度"这一简洁规律，而非试图寻找更复杂的位置/颜色依赖规则。难点在于辨认出不同朝向的 L 形是同一基本图案的旋转，以及旋转方向始终是顺时针。

- `description`：网格中散布着成对的同色像素点，每对之间需要画出一条不与其他连线交叉的最短曼哈顿路径，路径颜色与端点相同。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干对彩色像素点。每种非背景颜色恰好出现两次，形成一对端点。颜色可能包括 red、blue、green、yellow、orange 等。
  - 所有像素点分布在网格中，互不相邻。
  - 网格中可能有若干个 grey 像素作为"障碍物"，路径不能经过障碍物。
- `Rule`：
  - 对每对同色端点，画出一条连接它们的路径。路径由水平和垂直线段组成（只走格子的上下左右），宽度为1像素，颜色与端点相同。
  - 路径不能经过 grey 障碍物像素。
  - 不同颜色的路径不能共享任何像素（不能交叉或重叠）。
  - 在满足"不交叉、不经过障碍物"的约束下，每条路径取曼哈顿最短路径。若最短路径不唯一，取先尽量沿水平方向走、再沿垂直方向走的那条（水平优先规则）。
  - 端点像素保持原色不变。
- `Key insight`：表面上像一个简单的"连点"问题，但核心难点在于"不交叉"约束使得各路径之间相互依赖——某条路径的走法可能迫使另一条路径绕道。解题者需要从样例中发现不仅仅是"连同色点"，还需要注意路径之间的空间互斥。水平优先的消歧规则需要从多个样例中通过对比推断出来。
