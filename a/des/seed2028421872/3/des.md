# 第一步：分析与思考

## 参考题中涉及的基础操作梳理

从20道参考题中提炼出的基础操作族群：

1. **空间变换类**：旋转（#5 绕中心旋转条形）、平移（#4 精灵移动到锚点）、拉伸映射（#20 精灵拉伸填入框架）、滑动（#18 方块沿通道滑行）
2. **传播/射线类**：沿方向发射射线（#1 彩色标记射线）、对角线反射（#10 蓝色射线遇红镜反射）、洪水填充与辐射（#12 从开口向外辐射填充）
3. **计数/统计类**：计数对象转换为视觉编码（#2 图例中打点）、长度映射颜色代码（#19 条形长度对应颜色编码）
4. **模式识别与复制类**：重复图案铺满（#11 底部图案向上重复）、模板替换（#9 用模板替换匹配像素）、块级编解码（#6 精灵块与纯色块互换）
5. **结构解析类**：解析表格提取摘要（#13 封闭槽提取颜色摘要）、管道网络模拟（#15 令牌下落通过管道）、压缩图例展开（#8 左面板压缩展开到右面板）
6. **噪声处理类**：去除对角线噪声修复直线（#16）、重建墙壁忽略噪声（#7）
7. **条件/属性驱动类**：颜色类型决定投影方式（#14 灰色vs粉色方块不同投影规则）、边带位移（#17 标记颜色决定边、trail颜色决定行）

## 非显而易见的串联方式思考

- **编码-解码链条的隐蔽性**：信息可以被编码在看似装饰性的结构中。例如颜色本身不是信息——颜色的空间分布模式才是。一个对象的轮廓形状可以编码另一个对象的生成规则。
- **因果反转**：通常我们认为"输入的结构决定输出的内容"，但也可以反过来——"输出的约束反向决定输入中哪些元素是有意义的"——即先理解输出的结构框架，再回头在输入中寻找填充数据源。
- **拓扑信息作为隐藏通道**：两个对象是否被第三个对象分隔、某个区域是否与边界相连、某个路径是否存在——这些拓扑关系肉眼可见但不容易第一时间注意到，可以作为规则的核心判据。
- **对象的"缺席"作为信息**：网格中某种规律性结构缺少的那一块，恰好是需要生成的输出。关键不是看"有什么"，而是看"少了什么"。
- **形状作为指令集**：一个小图案不是被复制或缩放的对象，而是一组操作指令——每个像素的相对位置编码一个动作或参数。
- **遮挡关系推理**：当两个对象重叠时，被遮挡的对象仍然存在但不可见，需要通过上下文推断其完整形态，这种"看不见但确定存在"的信息可以驱动变换。
- **间距模式编码**：对象之间的空白距离不是无意义的留白，而可以编码数值参数，例如两个标记之间的间距决定了某种操作的重复次数。

- `description`：根据每个封闭区域内壁颜色的"多数投票"结果，将整个区域统一填充为胜出颜色，同时将边框重绘为落选颜色。

  - 背景为 Black。
  - 网格中有若干由 Grey 像素构成的封闭矩形边框（边框宽度为1像素），边框之间互不重叠、互不接触。
  - 每个边框的内部区域（不含边框本身）散布着若干彩色像素（可能包含 Red、Blue、Green、Yellow 等颜色），其余内部像素为 Black（背景色）。
  - 每个封闭区域内恰好只出现两种非背景颜色，且两种颜色的像素数量不相等。

- `Rule`：
  - 对每个 Grey 边框围成的内部区域，统计其中两种非背景颜色的像素数量。
  - 将该区域内部所有像素（包括原本为 Black 的位置）统一填充为数量较多的那种颜色（"多数胜出"）。
  - 将该区域的 Grey 边框重绘为数量较少的那种颜色（"少数上框"）。

<new_puzzle>
- `description`：在网格中找到每个形状的"对称性缺陷"——即打破该形状对称性的那个像素——提取缺陷的类型信息，汇总为一个小型编码表格。

- `Input structure`：
  - 背景为 Black。
  - 网格中散布着若干互不接触的单色形状（4-连通），每个形状使用不同颜色（如 Red、Blue、Green、Orange 等）。
  - 每个形状"几乎"关于自身边界框的某条中轴线（水平或垂直）对称，但恰好有一个像素破坏了这种对称——要么是多出的一个像素（该位置有像素但其镜像位置没有），要么是缺失的一个像素（该位置没有像素但其镜像位置有）。
  - 每个形状只有一条轴接近对称（差一个像素），另一条轴偏差较大，因此近似对称轴的选择是唯一确定的。

- `Rule`：
  - 对每个形状，找到其边界框的水平中轴和垂直中轴，检测哪条轴"几乎"构成对称（仅有一处差异）。
  - 定位那个破坏对称性的像素位置。如果是"多余"像素（一侧有、镜像侧没有），则缺陷类型为"多余"。如果是"缺失"像素（一侧没有、镜像侧有），则缺陷类型为"缺失"。
  - 输出一个小网格：行数等于形状数量，列数为2。每行第一列填该形状的颜色，第二列填 Magenta 表示缺陷是"多余"类型，填 Azure 表示缺陷是"缺失"类型。
  - 行的排列顺序按形状在原网格中从上到下、从左到右排序（以每个形状边界框左上角坐标为准，先比较行号再比较列号）。

- `Key insight`：解题者通常会关注形状的整体外观或颜色，但真正的信息隐藏在形状的"不完美"之处。需要对每个形状执行对称性检测，找到唯一的缺陷像素，再判断缺陷类型。核心认知路径是"从整体到局部瑕疵的审视"。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色"路标"箭头指示方向，从起点出发沿路标指引依次行走，收集路径上的颜色序列，用该序列填充终点处的空白容器。

- `Input structure`：
  - 背景为 Black。
  - 网格中有一个 Maroon 像素标记起点，一个由 Grey 像素构成的小矩形空心框作为终点容器（内部全为 Black）。
  - 起点与终点之间散布若干"路标"——每个路标是一个 3x3 区域内的箭头图案，由某种颜色绘制。箭头绘制方式：中心像素(1,1)始终存在；向右箭头额外填充(0,2),(1,2),(2,2)三个像素；向下箭头额外填充(2,0),(2,1),(2,2)；向左箭头额外填充(0,0),(1,0),(2,0)；向上箭头额外填充(0,0),(0,1),(0,2)。（坐标以3x3区域左上角为原点，(行,列)格式。）
  - 每个路标颜色各不相同，从 Red、Blue、Green、Yellow、Orange 中选取。
  - 所有路标的3x3区域互不重叠，且不与起点或终点框重叠。

- `Rule`：
  - 从 Maroon 起点出发，寻找四个正交方向上最近的路标（以起点到路标中心像素的曼哈顿距离为准）。起点四个方向中恰好只有一个方向能找到路标，以此确定初始前进方向。
  - 到达第一个路标后，读取其箭头指向的方向，沿该方向继续寻找下一个最近的路标。重复此过程直到沿当前方向找不到更多路标为止。
  - 按经过顺序记录每个路标的颜色，形成一个颜色序列。
  - 将颜色序列逐像素填入终点容器内部区域：从容器内部左上角开始，逐行从左到右、从上到下填充。序列长度恰好等于容器内部面积。
  - 原有的路标和起点在输出中保持不变，只有容器内部被填充。

- `Key insight`：路标的箭头方向不是装饰而是路径规划指令。解题者需要模拟一个"行走过程"——先确定起始方向，再逐步跟随箭头指引。收集到的颜色序列是路径的副产品，最终被"倒入"容器中。核心难点在于发现箭头编码了方向信息以及行走的链式逻辑。
</new_puzzle>

<new_puzzle>
- `description`：网格中有若干嵌套的矩形环，环的嵌套深度决定了最内层种子对象的缩放倍率，输出将所有种子对象按缩放后的尺寸水平排列。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干由不同颜色绘制的闭合矩形环（1像素宽的矩形边框），这些环可能彼此嵌套（一个环完全包含在另一个环内部），但不会交叉或部分重叠。
  - 在最内层（不包含其他环）的某些环内部，各有一个小的单色形状（4-连通，占据2到4个像素），颜色与所有环的颜色都不同。这些小形状称为"种子对象"。
  - 嵌套层数计算：种子对象被几个环包围则层级为几。例如只被一个环直接包围、该环外没有其他环则层级为1；被一个环包围且该环又被外层环包围则层级为2。层级范围为1到4。

- `Rule`：
  - 对每个种子对象，计算包围它的矩形环层数 N。
  - 将种子对象进行 N 倍像素块缩放：原始形状中每个像素扩展为 N x N 的同色像素块。
  - 输出网格中，所有缩放后的种子对象按照它们在原网格中的水平位置从左到右排列成一行，相邻对象之间间隔1列 Black。
  - 输出网格的高度等于所有缩放后对象中最高的那个，所有对象底部对齐。较矮的对象上方用 Black 填充。
  - 所有矩形环在输出中消失。

- `Key insight`：环的颜色和具体尺寸是干扰项——关键信息是嵌套层数。解题者需要数清每个种子对象被几层"壳"包裹，嵌套深度直接等于缩放因子。这要求解题者从视觉上剥离层层环结构来计数，而不是关注颜色或形状细节。
</new_puzzle>

<new_puzzle>
- `description`：网格中的线段在交叉点处发生颜色"混合"——交叉点周围生成由两条线段颜色组成的棋盘格标记，揭示被遮挡的重叠信息。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干条单像素宽的水平线段和垂直线段。每条线段是一种纯色（从 Red、Blue、Green、Yellow、Orange、Azure 中选取）。
  - 不同线段的颜色可以相同也可以不同。线段之间可能交叉（一条水平线段与一条垂直线段在同一像素位置重叠）。
  - 交叉点处的像素在输入中仅显示水平线段或垂直线段的颜色（不确定显示哪条）。
  - 每条线段长度至少为5像素。同方向的线段之间不共线（不在同一行或同一列）。

- `Rule`：
  - 识别所有交叉点：判断某个像素是否同时属于一条水平线段和一条垂直线段。判断方法为检查该像素所在行是否有一段连续的同色水平像素序列（长度>=3）经过它，同时所在列是否有一段连续的同色垂直像素序列（长度>=3）经过它。
  - 对每个交叉点，确定水平线段颜色 H 和垂直线段颜色 V（其中一个是交叉点处显示的颜色，另一个通过该点所在列的上下连续像素推断）。
  - 在交叉点的四个对角邻居位置（左上、右上、左下、右下）放置标记像素：左上和右下位置填 H 色，右上和左下位置填 V 色。如果某个对角位置已被线段像素占据则不覆盖，跳过该位置。
  - 所有原有线段像素（包括交叉点像素）保持不变。

- `Key insight`：输入中线段交叉处看起来只是普通的线段像素，解题者必须识别出某些位置实际上是两条不同方向线段的重叠。然后通过分析行和列的连续性来还原被遮挡线段的颜色。对角方向出现的小标记是"交叉证据"——它们的棋盘格颜色模式编码了水平线和垂直线各自的身份。
</new_puzzle>

- `description`：网格被分割线划分为若干房间，每个房间角落的标记像素编码了旋转指令，房间内的形状按指令旋转后放回房间中央。

- `Input structure`：
  - 背景为 Black。
  - Azure 颜色的直线将网格分割为若干矩形房间。分割线为1像素宽的完整直线（从网格一边到另一边或到另一条分割线），可以是水平或垂直的。
  - 每个房间的内部区域（不含 Azure 边界线）中恰好包含两个元素：

    2. 一个由其他颜色（Red、Green、Yellow、Orange 中的某一种）组成的单色4-连通形状，形状占据2到6个像素。

- `Rule`：
  - 对每个房间，读取 Magenta 像素所在的角落位置，确定旋转角度。
  - 将房间内的彩色形状绕其自身边界框中心旋转相应角度。旋转以90度为单位，像素坐标取整映射。
  - 旋转后的形状放回房间中，使形状边界框中心与房间内部区域中心对齐（如果尺寸为偶数导致无法精确居中，则偏向左上方）。
  - Magenta 标记像素在输出中被擦除为 Black。
  - Azure 分割线在输出中保持不变。

- `Key insight`：房间角落的 Magenta 单像素看似微不足道，实际上它是旋转操作的指令编码器。解题者需要注意到每个房间的形状在输出中发生了不同角度的旋转，然后将旋转角度与 Magenta 像素的角落位置对应起来。关键认知跳跃是"位置编码操作"——一个像素的空间位置不表示数据，而表示对数据的操作。
</new_puzzle>

<new_puzzle>
- `description`：网格中有一条由多色片段拼接而成的闭合环路，将环路沿特定起点展开，按各片段的长度生成柱状图输出。

- `Input structure`：
  - 背景为 Black。
  - 网格中有一条由彩色像素构成的闭合环路，环路宽度为1像素，由4-连通路径形成一个闭合回路（每个环路像素恰好有2个4-连通的环路邻居）。
  - 环路由若干段连续同色的区间拼接而成，相邻区间颜色不同。使用的颜色从 Red、Blue、Green、Yellow、Orange、Maroon 中选取。
  - 环路上恰好有一个 Grey 像素作为"起点标记"，它位于两个不同颜色区间的交界处（即它的两个环路邻居颜色不同）。

- `Rule`：
  - 从 Grey 起点出发，沿环路顺时针方向遍历。顺时针方向的确定：站在 Grey 像素上，面朝两个邻居中的一个前进，如果环路围成的区域在右手侧则该方向为顺时针方向。实践中，可通过计算环路围成区域的有符号面积来判断：选择使遍历方向为顺时针的那个邻居作为起始前进方向。
  - 遍历过程中（Grey 像素本身不计入任何区间），依次记录每段连续同色区间的颜色和像素数量（长度）。
  - 输出一个柱状图网格：每段区间对应一列，列宽为1像素，列高等于该区间的长度，列颜色为该区间的颜色。各列从左到右排列，顺序对应环路的顺时针遍历顺序。
  - 所有列底部对齐（底行为同一行），输出网格高度等于最长区间的长度，背景为 Black。

- `Key insight`：环路的空间形状是干扰信息——真正重要的是环路上颜色区间的排列顺序和各自的长度。解题者需要理解这是一个"展开"操作：将二维闭合路径线性化后提取统计特征。Grey 像素定义展开起点，顺时针方向定义遍历顺序，两者共同决定了输出柱状图的列排列。
</new_puzzle>

<new_puzzle>
- `description`：网格中散布着若干成对的相同形状物体（颜色不同），在每对之间绘制一条颜色交替的曼哈顿路径来连接它们。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干小型单色形状（4-连通，每个占3到5个像素），每种形状恰好出现两次，但两次出现的颜色不同。例如一个L形分别为 Red 和 Blue，一个T形分别为 Green 和 Yellow。
  - 形状的两次出现具有完全相同的像素相对排列（不含旋转或翻转），即将两个实例的边界框对齐后，各像素的相对位置完全一致。
  - 所有形状实例的边界框互不重叠且互不接触（至少间隔1像素）。
  - 不同形状对之间的形状排列不同（即每种形状是唯一可识别的）。

- `Rule`：
  - 将形状相同的两个实例配对。匹配标准是像素的相对排列完全一致（与颜色无关）。
  - 对每一对，定义"第一个"为边界框左上角行号较小的那个（行号相同时取列号较小的），另一个为"第二个"。
  - 从第一个形状的边界框中心像素出发，到第二个形状的边界框中心像素，绘制一条L型曼哈顿路径：先水平移动到目标列，再垂直移动到目标行。
  - 路径上的像素从起点开始交替使用第一个形状的颜色和第二个形状的颜色（第1个路径像素用第一个形状颜色，第2个用第二个形状颜色，第3个用第一个，以此类推）。
