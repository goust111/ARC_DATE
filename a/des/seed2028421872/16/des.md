# 第一步：分析与思考

## 参考题基础操作分类

**空间变换类**：
- 平移/推动（#11 沿方向推至边界）、折叠（#4 杆在铰链处折叠）、膨胀/收缩（#5 最大对象外扩、其余收缩）、对角线射线投射（#6 从端点发射对角线射线）
- 扩展/缩放（#2 像素→方块、#14 稀疏点阵→粗线条、#19 顶行向下扩展为楔形）

**填充/上色类**：
- 曼哈顿距离场填充（#15 同心距离环）、对称性修复填充（#10 双轴对称缺失像素恢复）
- 条件区域填充（#1 根据朝向涂框边颜色、#3 标记对角线之间的菱形填充、#20 两路径膨胀交集上色）
- 形状匹配后填充缺口（#18 标记形状匹配缺口→填色）

**信息编码/映射类**：
- 颜色→形状索引（#2 颜色查表选模板、#17 占位颜色选精灵+图例重映射）
- 缩略图/迷你地图（#12 小图是大图的缩放索引）
- 数量传递（#7 灰条像素计数→橙矩形内行/列条纹数）
- 等价关系表（#16 形状等价表，旋转/反射判定）

**位置/方向推断类**：
- 方向由相对位置决定（#8 红→青的水平方向决定出口侧、#11 与标记接触的基方向决定推动方向）
- 轴/中心隐式推断（#10 从非零像素推断对称轴、#15 标记像素即中心）

## 非显而易见的串联方式

1. **数量→几何**：一个对象的像素数不仅仅是"计数"，还可以编码几何参数——如半径、步数、旋转角度。参考题 #7 把像素计数转化为条纹行数，但更隐蔽的做法是让计数决定路径弯折次数或填充的深度。

2. **拓扑→颜色**：对象间的连通性或邻接关系可以决定着色方案。例如，两个对象是否通过某条"桥"相连来决定它们是否同色——这在参考题中未见。

3. **形状的负空间作为指令**：参考题 #18 用缺口形状匹配标记形状，但可以进一步——对象的内部空洞形状本身可以编码变换指令（如空洞形状像箭头则指示移动方向）。

4. **边界接触模式作为选择器**：对象与网格边缘的接触模式（哪些边碰到、碰到几个像素）可以作为隐含的分类键，决定后续变换。

5. **颜色频率序作为排列密钥**：将网格中各颜色的出现频率排序，得到一个排列，再用这个排列重排某些对象的位置或颜色——信息隐藏在全局统计中。

6. **路径追踪→区域归属**：从特定标记点出发沿前景路径行走，路径分叉时根据某种局部规则选择方向，最终到达的位置决定输出中的映射关系。

- `description`：根据每个封闭区域内部标记像素的数量，从预设的颜色序列中选取对应颜色填充该区域。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干由 Grey 像素构成的一像素宽的闭合边框，每个边框围出一个矩形封闭区域（边框之间不重叠、不嵌套）。

- `Key insight`：标记像素的作用不是标示位置，而是通过数量索引来查阅独立存放的颜色图例；解题者需要先发现"计数→查表"这一间接映射机制。

- `description`：每个前景对象根据自身与网格四条边的最短距离值，被平移到距离最小的那条边上并紧贴该边。
- `Input structure`：
  - 背景为 Azure。
  - 网格中散布着若干单色 4-连通前景对象（每个对象颜色各异，如 Red、Green、Blue、Yellow 等），对象形状不规则但较小（3-6像素）。

  - 对象之间互不重叠，且平移后也不会互相重叠。
- `Rule`：
  - 对每个前景对象，计算其所有像素到网格四条边（上边 = 最小行号、下边 = 最大行号与网格底之差、左边 = 最小列号、右边 = 最大列号与网格右之差）的最短距离。

  - 将对象沿垂直于该边的方向平移，直到对象的外缘像素紧贴该边（行号或列号为 0 或最大值）。
  - 对象在平行于该边的方向上不改变位置。
  - 清除对象在原始位置上的像素（恢复为背景色）。
- `Key insight`：对象移动的方向不是由任何标记或箭头指示的，而是由对象自身在网格中的空间位置隐式决定的——离哪条边最近就"吸附"到哪条边。解题者需要注意到每个对象的位移方向与它距各边的相对远近之间的对应关系。

<new_puzzle>
- `description`：将网格中的多条折线路径按折点处的转向方向分为两组，分别重新着色。
- `Input structure`：
  - 背景为 Black。

  - 网格角落有两个颜色色块：一个 Red 单像素标记在左上角，一个 Blue 单像素标记在右上角。
- `Rule`：
  - 对每条折线路径，确定行进方向：从 Maroon 标记的起点出发，沿第一段走到折点，再沿第二段走到终点。
  - 在折点处判断转向方向：如果从第一段到第二段是"左转"（相对于行进方向），则该路径属于左转组；如果是"右转"，则属于右转组。
  - 将左转组的所有路径像素重新着色为 Red；将右转组的所有路径像素重新着色为 Blue。
  - Maroon 标记保持不变。Red 和 Blue 角落标记保持不变。
- `Key insight`：关键在于发现路径分类的依据是折点处的转向方向（左转 vs 右转），而非路径的形状、长度或位置。解题者需要先识别出 Maroon 标记确定了行进方向，然后用"相对转向"（而非绝对方向）来分类。角落的 Red/Blue 色块暗示了两种分类结果的对应颜色。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到每对相同颜色的标记点，将它们之间的最短曼哈顿路径画出来，路径颜色由两点之间包围的前景对象的颜色决定。
- `Input structure`：
  - 背景为 Black。
  - 网格中散布着若干成对出现的彩色标记像素。每种非背景颜色恰好出现两个像素（如两个 Red、两个 Blue、两个 Green 等），形成若干"配对"。
  - 每对标记之间的轴对齐包围盒（bounding box）内部恰好包含一个由某种独特颜色（与标记色不同）构成的小型单色 4-连通对象（2-4像素大小）。
  - 不同配对之间的包围盒互不重叠。
- `Rule`：
  - 对每对相同颜色的标记点 A 和 B，找到它们之间的包围盒。
  - 识别该包围盒内唯一的前景对象，记其颜色为 C。
  - 从 A 到 B 绘制一条 L 形曼哈顿最短路径（先水平后垂直），路径颜色使用颜色 C。
  - 路径绘制时覆盖背景像素，但不覆盖已有的前景对象像素或标记像素。
  - 包围盒内的小型对象在输出中保留不变。
  - 标记像素在输出中保留不变。
- `Key insight`：路径的颜色不是由端点的标记颜色决定的，而是由两个端点之间"夹着"的那个对象的颜色决定的。解题者需要发现"被包围的对象充当颜色标签"这一间接关联。同色配对找连接路线是显而易见的，但路径颜色的来源是真正的谜题。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象在其"锚点"关于网格中心做点对称映射后，于对角象限生成一个180度旋转且颜色角色互换的副本。
- `Input structure`：
  - 背景为 Black。
  - 网格正中央有一个由 Grey 单像素绘制的十字线（一条水平线贯穿整行、一条垂直线贯穿整列），将网格分为四个象限（左上、右上、左下、右下）。网格尺寸为奇数×奇数，确保中心像素唯一。
  - 每个象限中恰好有一个小型前景对象（4-连通，3-6像素），颜色各不相同（如 Red、Blue、Green、Yellow）。每个对象完全位于一个象限内，不跨越十字线。
  - 每个对象的像素中有一个"特殊像素"颜色为 Orange（其余像素为该对象的主色），标记该对象的"锚点"。
- `Rule`：
  - 对每个对象，找到其 Orange 锚点的位置。
  - 将该锚点关于十字线的交叉点（网格中心）做点对称映射，得到目标锚点位置。该目标位置必然落在对角象限内。
  - 以目标锚点为基准，将原对象的形状做180度旋转后放置在对角象限中。
  - 新副本中，原来的主色像素变为 Orange，原来的 Orange 锚点变为主色。即颜色角色互换。
  - 原始对象保持不变。Grey 十字线保持不变。
- `Key insight`：变换不是简单的对称复制——解题者需要发现三个层次的规则：(1) Orange 锚点决定映射基准点而非对象中心；(2) 副本出现在关于网格中心的对角象限（180度旋转对称）；(3) 副本中颜色角色互换（主色↔Orange）。单独看任何一个样例都可能有多种假设，需要对比多个样例才能确认这三个同时生效的约束。
</new_puzzle>

<new_puzzle>
- `description`：根据每个矩形内部被横竖分割线切出的子区域数量的奇偶性，决定该矩形边框的颜色和绘制样式。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干个由 Blue 像素绘制的一像素宽的矩形边框（不嵌套、不重叠、不接触），大小各异。
  - 每个矩形内部可能有若干条 Red 的一像素宽直线，这些直线从矩形的一条内壁延伸到对面内壁（水平线从左内壁到右内壁，垂直线从上内壁到下内壁），将矩形内部分割为若干个子区域。
  - 有些矩形内部没有分割线（子区域数为 1），有些有一条或多条。
- `Rule`：
  - 对每个矩形，计算其内部被 Red 分割线切出的子区域数量 n。
  - 如果 n 为奇数，则矩形边框保持 Blue 不变。
  - 如果 n 为偶数，则矩形边框的所有像素重新着色为 Green，同时边框上的像素按位置交替保留和删除——从每条边的起始角像素开始保留 Green，下一个像素删除（变为 Black），如此交替。四个角像素始终保留为 Green。
  - Red 分割线在输出中保持不变。
- `Key insight`：边框样式的变化取决于内部子区域数量的奇偶性，而非分割线的数量或位置。解题者容易误以为规则与分割线数量或方向有关，但实际上需要正确地数出被切出的区域数（一条线切出2个区域，两条平行线切出3个区域，一横一竖交叉切出4个区域……），然后判断奇偶。
</new_puzzle>

<new_puzzle>
- `description`：网格中的多个箭头各自指向一个目标对象，目标对象被重新着色为箭头的颜色；箭头自身则被擦除。
- `Input structure`：
  - 背景为 Black。
  - 网格中有若干个小型 4-连通前景对象（形状不规则，3-5像素），每个对象由 Grey 像素构成。
  - 网格中还有若干个由不同颜色绘制的箭头（Red、Blue、Green、Yellow 等），每种颜色恰好一个箭头。每个箭头由一条3像素长的直线段（水平或垂直）和一个三角形箭尖组成。具体绘制方式：直线段3像素沿一个基方向排列；在直线段的一端，垂直于直线段方向的两侧各延伸1像素形成箭尖（共5像素构成完整箭头）。箭尖所在的一端即为箭头指向方向的反方向（尾部），直线段的另一端为箭头尖端指向的方向。
  - 每个箭头的尖端沿指向方向延伸，在该方向上最先遇到的 Grey 对象即为其目标对象。箭头与目标之间可能隔有若干个背景像素的空隙。
  - 每个 Grey 对象恰好被一个箭头指向（一一对应）。
- `Rule`：
  - 对每个箭头，确定其指向方向和颜色。
  - 沿箭头指向方向做射线扫描，找到射线上第一个 Grey 对象。
  - 将该 Grey 对象的所有像素重新着色为箭头的颜色。
  - 将箭头自身的所有像素擦除为背景色 Black。
- `Key insight`：箭头既编码了颜色信息，又通过方向指向编码了"哪个对象接收该颜色"的映射关系。解题者需要同时解读箭头的两个语义维度：方向指向选定目标，颜色传递给目标。箭头在完成信息传递后自身消失。
</new_puzzle>
