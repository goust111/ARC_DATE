# 第一步：分析与思考

## 参考题基础操作梳理

参考题中涉及的核心操作可大致分为以下类别：

**空间变换类**：平移（题15、17的sprite滑动）、缩放/尺寸循环（题4的方块尺寸循环）、旋转/翻转不变量（题2的形状规范化）、对角投射（题9的L三连骨牌对角复制）、螺旋生长（题20的十字臂螺旋路径）。

**分割与填充类**：区域分割与连通域操作（题5的背景隔间填充）、边界/轮廓处理（题12的周长段重复、题6的地形剖面标记）。

**层级与排序类**：遮挡关系排序（题18的环形精灵层叠重建）、形状频率排序（题2按共享形状分上下）、面积降序嵌套（题13矩形逐级嵌套）。

**信息编码与传递类**：颜色配对/匹配（题15、17的标记色与锚点色配对）、方向编码（题8图例中心→指示点编码滑动方向）、时间序列外推（题10序列面板预测）。

**路径与射线类**：对角射线与反射（题19箭头发射射线反弹）、龟图学运动规则（题20右转优先螺旋）。

## 非显而易见的串联方式

1. **拓扑关系作为隐式排序键**：遮挡顺序（题18）本质上是从可视碎片推断不可见的分层关系。如果将这种"从局部缺失推断全局顺序"的思路扩展——对象之间的"谁挡住谁"不再通过颜色覆盖表现，而是通过某种拓扑连接（如哪条路径穿过哪个区域）来隐式编码优先级。

2. **边界信息的双重角色**：题5中前景像素既是"画"也是"墙"，题12中前景段既是"图案"也是"度量标尺"。这启发我们思考：同一个视觉元素可以同时充当操作对象和操作参数。例如一个对象的形状既定义了它"是什么"，也定义了它对其他对象的作用方式。

3. **编码的间接性**：题8中方向不是直接标注的，而是通过两个点的相对位置隐式编码。可以进一步推广——如果规则参数不是直接给出，而是需要从某种"元对象"中解读？例如网格中的某个小图案不是待变换的对象，而是一条"指令"，告诉你如何处理其他对象。

4. **缺失信息的语义**：题9中L三连骨牌的缺角决定了复制方向——"不存在什么"比"存在什么"更重要。这种负空间逻辑可以延伸为：对象的"洞"或"缺口"本身携带关键信息。

5. **全局约束的局部表达**：题12将周长展开为一维循环序列后操作，这种"降维→操作→升维"模式值得探索。类似地，二维网格中的某种全局属性（如对称性类型、连通度）可以在降维后变得清晰。

6. **输出结构与输入结构的质变**：题11将空间分布的方块转化为直方图式的嵌套堆叠——输出不是输入的简单修改，而是对输入信息的一种全新"可视化"。这种"信息重编码"的思路可以产生许多新颖的谜题。

<new_puzzle>
- `description`：根据每个封闭房间内墙壁颜色的"多数投票"结果，将房间内部的空白区域填充为获胜颜色。

- `Input structure`：
  - 背景为 Black。
  - Grey 像素构成正交连通的薄墙网络（每段墙宽度为1像素），将网格划分为若干矩形封闭房间。
  - 部分墙段被替换为非 Grey 的前景色（如 Red、Blue、Green 等），每段彩色墙恰好替换一整条连续的 Grey 墙段。一个房间可能被多段不同颜色的墙段包围。

- `Rule`：
  - 对每个封闭房间，统计其四面墙壁中各彩色墙段的总长度（以像素计）。
  - 将该房间内部所有 Black 像素填充为总长度最大的那种颜色。若有平局，选择在该房间的墙段中最先出现（按从上到下、从左到右扫描顺序）的颜色。
  - Grey 墙段和彩色墙段本身保持不变。

- `Key insight`：解题者需要意识到，墙壁的颜色不是装饰——它们是一种"选票"，每段彩色墙用自己的长度为所围房间投票，房间内部的填充色由这些围墙的长度竞争决定。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散布的彩色像素点视为"星座"，用它们之间的曼哈顿距离关系确定连线方向，在最近邻对之间画出正交折线路径。

- `Input structure`：
  - 背景为 Black。
  - 网格中散布着若干孤立的彩色像素点（每个像素四邻域均为背景），颜色可能包括 Red、Blue、Green、Yellow 等，每种颜色恰好出现两个像素。

- `Rule`：
  - 对每种颜色，找到该颜色的两个像素点 A 和 B。
  - 从 A 到 B 画一条正交折线：先沿行方向（水平）移动到与 B 同列，再沿列方向（垂直）移动到 B 的位置。若 A 在 B 的左上方，则先向右再向下；若 A 在 B 的右上方，则先向左再向下；以此类推——水平段在前，垂直段在后。
  - 折线路径上的所有像素（包括拐角处）用 Grey 填充，但起点 A 和终点 B 保持原色。
  - 若两条不同颜色的折线路径交叉，交叉点处的像素用 Magenta 标记。

- `Key insight`：核心在于发现每种颜色恰好成对出现，并且连线规则是"先水平后垂直"的固定折线策略，而非最短直线。交叉点的特殊标色是验证规则正确性的关键线索——解题者通过交叉点颜色可以反推折线的行进规则。
</new_puzzle>

<new_puzzle>
- `description`：网格中每个彩色区域是一面"镜子"，背景中的每条水平扫描线遇到镜子时，会根据镜子颜色决定的偏转规则改变行进方向，最终在路径上留下轨迹。

- `Input structure`：
  - 背景为 Black，网格尺寸不超过 25×25。
  - 网格中有若干小型实心矩形色块（每个矩形为单一前景色，宽度和高度均≥2），这些色块不相互接触且不触及网格边界。
  - 颜色仅使用三种前景色（例如 Red、Blue、Green），每种颜色可出现一个或多个矩形。
  - 网格最左列的某些单元格中有 Yellow 像素作为"发射器"标记。

- `Rule`：
  - 从每个 Yellow 发射器出发，向右发射一条水平射线（沿行前进）。
  - 射线前进过程中在经过的 Black 格子上留下 Yellow 轨迹。
  - 当射线的下一个格子是某个彩色矩形的边缘时：
    - Red 矩形：射线向下偏转90°（变为向下前进），绕过矩形下边缘，然后继续保持向右方向前进。具体地：射线向下移动到矩形底边下方一格，然后向右移动到矩形右边缘右方一格，再继续向右前进。
    - Blue 矩形：射线向上偏转，类似地绕过矩形上边缘后继续向右。射线向上移动到矩形顶边上方一格，然后向右移动到矩形右边缘右方一格，再继续向右前进。
    - Green 矩形：射线被吸收，轨迹终止于矩形左边缘前一格。
  - 射线遇到网格右边界也终止。
  - 射线绕行过程中若再遇到另一个矩形，递归应用同样的规则。

- `Key insight`：表面上看这是简单的射线追踪，但核心洞见在于颜色不是标识，而是"偏转指令"——Red 代表"向下绕行"，Blue 代表"向上绕行"，Green 代表"终止"。解题者需要从多个样例中归纳出颜色→行为的映射关系，而非仅仅观察路径形状。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到每个"指针对象"所指向的目标区域，然后将目标区域内的图案旋转，旋转角度由指针对象自身的朝向决定。

- `Input structure`：
  - 背景为 Black，网格尺寸不超过 30×30。
  - 网格中有若干小型非对称图案（"目标图案"），每个由单一前景色绘制，占据一个紧凑的矩形包围盒（不超过5×5），图案不是旋转对称的。
  - 每个目标图案附近有一个同色的"指针对象"。指针对象是一个3像素的直线段（水平或垂直），其中一端额外连接一个像素形成一个直角拐，使整体呈 L 形（占据2×2包围盒中的3个像素，类似题9中的L三连骨牌）。
  - 指针对象与其目标图案颜色相同，且每种前景颜色恰好有一个指针和一个目标图案。

- `Rule`：
  - 指针 L 形的朝向通过其缺失角确定。缺失角在右上 = 指向右上 = 顺时针旋转 90°；缺失角在右下 = 指向右下 = 顺时针旋转 180°；缺失角在左下 = 指向左下 = 顺时针旋转 270°；缺失角在左上 = 指向左上 = 不旋转（0°）。
  - 将每个目标图案在其包围盒中心处按指针指定的角度顺时针旋转。
  - 指针对象本身从网格中删除（替换为背景色）。
  - 旋转后的图案放置在目标图案原来的包围盒位置（中心对齐）。

- `Key insight`：L 形指针的缺失角不仅标识了方向，还编码了精确的旋转角度。解题者需要发现颜色配对关系（指针与目标同色），然后理解 L 形的四种朝向分别对应四个旋转角度，最后在目标图案上应用对应旋转。关键挑战在于识别出 L 形小对象是"指令"而非普通图案。
</new_puzzle>

<new_puzzle>
- `description`：网格被若干水平色带分隔成行区域，每个行区域内的对象需要按照该色带的颜色所编码的规则进行变换——颜色决定了镜像轴的方向。

- `Input structure`：
  - 背景为 Black，网格尺寸不超过 25×30。
  - 网格中有若干条完整的水平色带（跨越整个网格宽度，高度为1像素），颜色为 Red、Blue 或 Green。色带将网格分成若干水平条状区域。
  - 每个条状区域内有一个或多个由 Grey 像素绘制的小型非对称连通图案（4连通），每个图案不超过 5×5。

- `Rule`：
  - 查看每个条状区域**下方**紧邻的色带颜色（最底部区域下方无色带，则视为与其上方色带颜色相同）：
    - Red：将该区域内的每个 Grey 图案做**水平镜像**（左右翻转），保持图案中心位置不变。
    - Blue：将该区域内的每个 Grey 图案做**垂直镜像**（上下翻转），保持图案中心位置不变。
    - Green：将该区域内的每个 Grey 图案做**中心旋转180°**，保持图案中心位置不变。
  - 色带本身保持不变。

- `Key insight`：色带的作用不是简单分隔符——它们的颜色是变换指令。解题者首先会注意到色带将网格分区，但需要进一步发现：决定每个区域内图案如何变换的，是该区域下方那条色带的颜色（而非上方）。这种"向下看"的方向性是解题的关键难点，需要通过对比不同区域中图案的变换方式与相邻色带颜色之间的对应关系才能发现。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多个同构图案按照它们各自"缺失像素"的位置进行拼合，生成一个完整的合成图案。

- `Input structure`：
  - 背景为 Black，网格尺寸不超过 25×25。
  - 网格中有 N 个（N ≥ 2）由同一颜色（如 Blue）绘制的连通图案，它们空间上互不接触。
  - 这些图案几乎相同——它们都是同一个"完整模板"的副本，但每个副本恰好缺少模板中不同位置的一个像素。
  - 每个副本旁边有一个不同颜色的单独标记像素（如 Red、Green、Yellow 等），位于副本包围盒外部、与副本最近的一个格子处。

- `Rule`：
  - 识别所有 Blue 图案，对齐它们的包围盒，通过叠加（取并集）还原出完整的模板图案。
  - 每个副本中缺失的那个像素位置，在完整模板中对应一个格子。在输出中，将模板绘制在网格中央，每个缺失位置用对应副本旁边的标记像素颜色填充，其余模板像素保持 Blue。
  - 输出网格大小等于完整模板的包围盒大小。

- `Key insight`：每个副本看似相同，但仔细比对会发现各少了一个不同位置的像素。解题者需要通过叠加所有副本来重建完整形状，然后意识到每个副本旁的彩色标记是在为其缺失像素"命名"——最终输出是一个完整模板，其中每个曾经缺失的位置被标上了对应的颜色。
</new_puzzle>

<new_puzzle>
- `description`：在网格中根据每个封闭区域的"出口数量"来决定其填充颜色，出口数量由区域边界上的缺口数决定。

- `Input structure`：
  - 背景为 Black，网格尺寸不超过 20×20。
  - Azure 像素构成若干近似封闭的矩形边框（边框宽度1像素）。每个边框的边上有零个或多个单像素宽的缺口（即边框线断开一个像素的位置）。
  - 边框之间不重叠、不接触。

- `Rule`：
  - 统计每个 Azure 边框上的缺口数量 k。
  - 根据 k 的值填充边框内部的 Black 区域：
    - k = 0（完全封闭）：填充 Red。
    - k = 1：填充 Green。
    - k = 2：填充 Yellow。
    - k = 3：填充 Magenta。
    - k ≥ 4：填充 Orange。
  - Azure 边框像素本身不变。

- `Key insight`：边框看上去都很相似，但关键在于数清每个边框上细微的单像素缺口数量。缺口数量映射到一张颜色表，决定了内部填充色。解题者需要先发现"缺口"这个概念的重要性，然后通过对比多个样例中的缺口数量与填充颜色建立映射关系。难点在于缺口仅有一个像素大小，非常容易被忽略。
</new_puzzle>
