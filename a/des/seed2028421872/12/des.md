# 第一步：分析与思考

## 参考题中涉及的基础操作类型

从 20 道参考题中可以提炼出以下基础操作族：

1. **传播与射线**：从种子/标记出发沿某方向发射射线或扩散图案（题1的条纹传播、题2的对角线光束、题13的滑动轨迹）。
2. **查表/图例映射**：网格中嵌入一个小型图例区域，充当颜色→颜色或颜色→形状的映射字典（题3的调色板、题6的符号字典、题10的图例过滤器、题17的边缘图例）。
3. **统计/计数驱动**：对象的某种数值属性（面积、像素计数）决定输出的几何尺寸或排列顺序（题8的计数矩形、题12的面积排序嵌套环）。
4. **空间对齐/拼接**：识别对象之间的空间关系，然后连接或合并它们（题5的桥接、题11的对角连接线、题19的矩形叠加合并）。
5. **分格/晶格操作**：网格被分割成均匀的子单元，操作在单元级别进行（题4的晶格行筛选、题16的分形自相似）。
6. **几何变换**：平移、剪切、旋转、缩放等经典空间变换（题13的滑动、题15的剪切、题9的平移拼框）。
7. **序列/周期控制**：某种控制序列决定操作的顺序或参数（题5的控制行、题14的环形颜色旋转、题20的梳齿计数）。

## 非显而易见的串联方式

- **统计量作为空间编码**：一个对象的像素计数不用来决定大小，而是编码一个坐标（如计数=5意味着"第5行"），从而把计数操作转化为空间定位操作。
- **拓扑属性作为隐式分类器**：不按颜色或面积，而是按对象的拓扑特征（有几个洞、是否为简单连通、边界的凹凸性）来分类对象并施加不同变换。
- **方向信息隐藏在形状不对称性中**：一个非对称对象的朝向本身编码了变换的方向参数，而非由外部标记指定。
- **网格边界作为镜面**：射线在网格边界反射，路径的反弹次数或最终落点决定输出。
- **对象间的相对位置编码操作类型**：两个对象的相对方位（上下左右、对角）不仅决定连接方向，更决定对它们施加哪种不同的变换。
- **负空间携带信息**：对象之间的背景间隙形状本身就是需要被"读取"的信号，而非对象本身。

- `description`：根据每个封闭区域的边界凹陷数量，选择对应颜色填充该区域。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干由 grey 像素绘制的不规则封闭轮廓（一像素宽的连通闭合边界）。每个封闭轮廓的外形各不相同。
  - 某些轮廓的边界是光滑的凸多边形轮廓（无凹陷），某些边界有 1 个凹陷缺口，某些有 2 个，某些有 3 个。"凹陷"定义为：沿轮廓外侧行走时，轮廓边界向内凹进形成的单像素深度的凹槽（即轮廓的外接矩形内、紧邻轮廓外侧的背景像素形成的 1×1 凹口）。
  - 网格底部有一行颜色样本条：从左到右依次为 red、blue、green、yellow 四个单像素色块，分别对应凹陷数 0、1、2、3。

- `Rule`：
  - 统计每个封闭轮廓的凹陷数目（0、1、2 或 3）。
  - 根据底部颜色样本条的映射关系（第 1 个颜色 → 0 个凹陷，第 2 个 → 1 个，以此类推），用对应颜色填充该封闭轮廓的内部区域。
  - grey 边界本身保持不变，底部的颜色样本条在输出中保留。

- `Key insight`：解题者需要注意的不是封闭区域的大小或位置，而是其边界形状的凹凸特征——凹陷的数量才是决定填充颜色的关键。颜色样本条的顺序隐含了"第几个 = 几个凹陷"的计数映射。
</new_puzzle>

<new_puzzle>
- `description`：将每个前景对象沿其自身最长轴方向投影到网格边界，投影线的颜色由对象面积的奇偶性决定。

- `Input structure`：
  - 背景色为 black。
  - 网格中散布着若干单色的 4-连通前景对象，每个对象使用不同的颜色（如 red、blue、green 等）。
  - 每个对象都是不规则的小型连通区域（3-8 像素），形状各异且不对称。

- `Rule`：
  - 对每个前景对象，计算其"最长轴方向"：比较对象的紧包围矩形的宽和高。若宽 > 高，最长轴为水平方向；若高 > 宽，最长轴为垂直方向；若宽 = 高，取对象质心到各像素的主方向（水平像素跨度 ≥ 垂直像素跨度则水平，否则垂直）。
  - 从对象的质心位置（取整到最近像素），沿最长轴方向向两侧延伸直线，直到碰到网格边界。这条直线穿过对象本身及两侧的背景。
  - 在该直线上，仅绘制对象以外的背景部分。绘制颜色的规则：若对象的像素面积为奇数，使用 orange；若为偶数，使用 azure。
  - 对象本身的像素保持原色不变。

- `Key insight`：解题者需要同时关注两个独立线索——对象形状的空间延展方向决定了投影方向，而面积的奇偶性决定了投影颜色。这两个属性分别从不同维度提取信息，需要分别识别后再组合。
</new_puzzle>

<new_puzzle>
- `description`：利用前景对象之间背景间隙的宽度，作为索引来决定对相邻对象对施加的颜色重映射。

- `Input structure`：
  - 背景色为 black。
  - 网格中有一行（水平排列）的若干彩色矩形块，每个矩形高度相同（例如 3 像素高），宽度各异，颜色各异。矩形块之间有宽度不等的 black 间隙（间隙宽度为 1、2 或 3 像素）。
  - 网格底部有一个 3 行 × 2 列的颜色对照表：第 1 行左列为 red、右列为 green；第 2 行左列为 blue、右列为 yellow；第 3 行左列为 magenta、右列为 orange。该对照表表示"间隙宽度 k → 左列第 k 行的颜色映射为右列第 k 行的颜色"。

- `Rule`：
  - 从左到右扫描相邻矩形块之间的间隙。
  - 对每个间隙，测量其宽度 k（1、2 或 3）。
  - 查阅底部对照表第 k 行：若间隙右侧的矩形恰好是左列颜色，则将其重映射为右列颜色。
  - 间隙左侧矩形不受该间隙影响（但可能受其左侧间隙的影响）。
  - 若矩形颜色不在对照表左列中出现，则保持不变。
  - 对照表自身在输出中保留不变。

- `Key insight`：间隙（负空间）不是无意义的分隔，而是携带了操作指令的编码。解题者需要意识到每个间隙的宽度是一个"选择器"，决定了对其右邻矩形应用哪条颜色替换规则。信息同时存在于对象中和对象之间的空白中。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象按照自身与网格中心的方位角，旋转对应角度后原地重绘。

- `Input structure`：
  - 背景色为 black，网格为正方形（边长为奇数，如 15×15 或 17×17）。
  - 网格中散布着若干小型单色前景对象（每个对象占 3-6 像素），颜色各不相同。
  - 每个对象都有一个明确的不对称形状（如 L 形、T 形、Z 形等），使得旋转后的结果可以与原始形状区分。
  - 所有对象距离网格中心的距离大致相等，分布在中心周围的不同方位。

- `Rule`：
  - 确定网格的中心像素。
  - 对每个前景对象，计算其质心相对于网格中心的方位：若质心在中心的正上方区域（从正上方顺时针 0°-90°），则将对象顺时针旋转 0°（不变）；若在右侧区域（90°-180°），旋转 90°；若在下方区域（180°-270°），旋转 180°；若在左侧区域（270°-360°），旋转 270°。
  - 方位角的判定以对象质心到网格中心的向量为准。四个象限的划分：右上（x≥0, y<0）→ 0°，右下（x≥0, y≥0）→ 90°，左下（x<0, y≥0）→ 180°，左上（x<0, y<0）→ 270°。这里 x 为列偏移（右为正），y 为行偏移（下为正）。
  - 旋转以对象自身质心为中心进行，旋转后对象仍在原位置附近（质心不变，形状绕质心旋转）。

- `Key insight`：对象本身的形状和颜色不变（仅被旋转），关键在于发现旋转角度不是固定的，而是由对象在网格中的空间位置（相对于中心的方位象限）隐式决定的。解题者需要将对象的全局位置与局部变换关联起来。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到被"路径"连通的对象对，将路径拐弯次数编码为目标对象内部的标记点数量。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干小型填充矩形（3×3 或 4×4），每个矩形使用不同的颜色（如 red、blue、green、yellow 等），矩形内部全部填充为该颜色。
  - 矩形之间由 grey 单像素宽的路径连接。每条路径由水平和垂直线段组成，仅做直角拐弯。每个矩形恰好连接一条路径（即矩形是路径的端点）。路径的两端各连接一个矩形，路径从矩形的某一边中点出发。

- `Rule`：
  - 对每条 grey 路径，计算其拐弯次数（直角转弯的数量）。例如一条纯水平或纯垂直路径拐弯次数为 0；一条 L 形路径拐弯 1 次；一条 Z 形路径拐弯 2 次。
  - 在路径连接的两个矩形中，选择颜色编号较大的那个矩形（颜色排序：red < blue < green < yellow < grey < magenta < orange < azure < maroon），在其内部中心区域放置 maroon 色标记点，标记点数量等于路径的拐弯次数。
  - 标记点的排列方式：1 个点放在矩形正中心；2 个点水平排列在中心行；3 个点排成倒 L 形（中心 + 右 + 下）；0 个拐弯则不放置任何标记点。
  - 路径本身和较小颜色编号的矩形保持不变。

- `Key insight`：路径（连接线）不仅是装饰性的连接，其几何形态（拐弯次数）本身编码了数值信息。解题者需要将路径的拓扑复杂度"测量"出来，并将结果写入特定的目标对象内部。同时，目标对象的选择依赖于颜色的隐含排序。
</new_puzzle>

<new_puzzle>
- `description`：将网格中每个对象替换为其"影子"——对象沿光源方向偏移后的轮廓，影子长度由对象到光源的距离决定。

- `Input structure`：
  - 背景色为 black，网格大小约 20×20 至 25×25。
  - 网格的某个角落（如左上角）有一个 yellow 单像素，代表"光源"。
  - 网格中散布着若干单色填充矩形前景对象（大小约 2×2 至 4×3），颜色各不相同，均不为 yellow。

- `Rule`：
  - 光源位于角落，定义光的传播方向为从光源指向网格对角（如光源在左上角，则光向右下方传播）。
  - 每个前景对象产生一个"影子"：影子是对象沿光的传播方向平移后的副本。平移距离等于对象质心与光源之间的切比雪夫距离除以 3（向下取整），最小为 1。
  - 影子的颜色为 grey，绘制在对象的光传播方向侧。
  - 若影子区域与原对象重叠，重叠部分保留原对象颜色（对象在影子之上）。
  - 若影子区域超出网格边界，超出部分裁剪丢弃。
  - 原始对象保持不变（颜色、位置不变）。光源像素在输出中保留。

- `Key insight`：解题者需要发现角落的 yellow 像素不是普通对象而是"光源"，从而理解所有 grey 图形是原对象的方向性投影。影子长度与距离成正比这一点需要通过比较不同对象的影子来推断——距离光源越远的对象影子越长。
</new_puzzle>

<new_puzzle>
- `description`：每个前景形状内部的"空洞"形状决定了该对象在输出中被复制到哪个目标区域。

- `Input structure`：
  - 背景色为 black。
  - 网格上半部分包含若干大型单色框架对象（类似空心矩形或空心不规则形状），每个框架内部有一个由背景色构成的封闭空洞。不同框架的空洞形状各不相同——有些空洞是正方形，有些是竖长矩形，有些是横长矩形，有些是 L 形。
  - 网格下半部分有一排与空洞形状一一对应的小型目标轮廓，由 grey 线条绘制。每个 grey 轮廓的内部形状恰好匹配某一个框架的空洞形状（大小相同）。每个 grey 轮廓内部当前为 black。

- `Rule`：
  - 对上半部分每个框架对象，提取其内部空洞的形状（以像素坐标的相对布局表示）。
  - 在下半部分的 grey 轮廓中，找到内部形状与该空洞完全匹配的那个轮廓。
  - 用该框架对象的颜色填充匹配的 grey 轮廓内部。
  - 上半部分的框架对象在输出中保持不变。grey 轮廓线条保持不变。

- `Key insight`：关键信息不在对象本身的外形中，而在对象"缺失"的部分——空洞的形状。解题者需要关注负空间，将每个框架的内部空洞形状与下方的目标轮廓进行形状匹配。这是一种"反向模板匹配"——用空缺而非实体来建立对应关系。
</new_puzzle>
