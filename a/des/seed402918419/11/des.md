- `description`：根据每个前景对象内部孔洞的形状，在网格边缘的色带图例中找到匹配的模板，然后用该图例色带的颜色对对象进行重新着色。
- `Input structure`：
  - 背景为 Black。
  - 网格左侧或上侧有一列/一行色带图例，每个图例条目包含一个小型镂空模板（由 Grey 像素围成的孔洞形状）和紧邻其旁的一个纯色色块（Red、Blue、Green、Yellow 等）。

- `Rule`：
  - 提取每个前景对象内部孔洞的形状（紧贴边界框），对其进行归一化（允许旋转和翻转）。
  - 将归一化后的孔洞形状与左侧/上侧图例中的每个镂空模板进行匹配（同样归一化后比较）。

  - 图例区域在输出中保持不变。
- `Key insight`：对象的身份不是由其外轮廓决定的，而是由其内部孔洞的几何形状决定的；孔洞形状是查找颜色图例的索引键。
</new_puzzle>

- `description`：在网格中找到由分隔线划分的多个面板，每个面板内有一个"种子图案"和若干"生长方向标记"像素，将种子图案沿标记所指方向进行镜像平铺扩展，直到填满面板。
- `Input structure`：
  - 背景为 Black。
  - Maroon 色的单像素宽分隔线将网格划分为若干等大的矩形面板。
  - 每个面板的某个角落区域包含一个由多种颜色构成的小型矩形"种子图案"（如 3×3 或 4×4）。
  - 种子图案所在角落之外的面板边缘上，有若干 Azure 单像素标记点，分布在与种子相邻的两条边上。Azure 标记点的数量指示沿该方向需要镜像翻转复制种子图案的次数。
- `Rule`：
  - 确定种子图案所在的角落位置（左上、右上、左下、右下）。
  - 统计与种子相邻的水平边上 Azure 标记点的数量 H，以及垂直边上 Azure 标记点的数量 V。
  - 从种子所在角落出发，沿水平方向交替镜像翻转复制种子图案 H 次，沿垂直方向交替镜像翻转复制 V 次，形成一个 (V+1)×(H+1) 的种子阵列，每相邻副本都是前一个副本的镜像。
  - 用该阵列填充面板（覆盖原来的 Azure 标记和背景），分隔线保持不变。
- `Key insight`：种子图案所在的角落决定了扩展的起点和方向，而边缘标记点的数量编码了每个方向的重复次数；交替镜像翻转产生无缝平铺效果。

  - 每对同色像素之间的直线路径上可能有 Grey 障碍像素和空背景像素。

  - 对每种颜色，找到该颜色的两个像素，它们一定处于同一行或同一列。

- `description`：识别网格中每个封闭区域被哪些颜色的边框线段包围，然后用这些边框颜色的"混合"结果填充该区域——边框颜色数量为奇数时填充出现最多次的颜色，偶数时填充边框中最稀有的颜色。
- `Input structure`：
  - 背景为 Black。
  - 网格中有多段单像素宽的彩色线段（Red、Blue、Green、Yellow 等），它们水平或垂直排列，端点相互连接形成若干封闭多边形区域。
  - 每段线段是纯色的，但围成同一区域的不同边可以是不同颜色。
  - 某些区域可能嵌套在其他区域内部。
- `Rule`：
  - 找出所有由彩色线段围成的 4-连通封闭区域（区域内部均为 Black 背景像素）。
  - 对每个封闭区域，统计其边界由哪些颜色的线段组成。计算参与围成该区域的每种颜色的线段像素数。

  - 如果围成该区域的不同颜色种类数为偶数，则用像素数最少的边框颜色填充该区域。

- `Key insight`：解题者需要先识别哪些线段共同构成一个封闭区域的边界（空间拓扑推理），再根据边界颜色种类数的奇偶性决定填充策略——这两个判断步骤都需要非显然的归纳。
</new_puzzle>

- `Rule`：
  - 对每个矩形框，提取其缺口的形状（即缺口处背景像素相对于缺口起始位置的坐标集合）。

- `Key insight`：碎片与缺口之间的对应关系通过形状匹配（含旋转）来确定，而填充后的颜色由目标矩形框决定，不由碎片自身决定——解题者需要同时完成形状配对和颜色继承两步推理。

- `description`：在一个包含多个同心矩形框的网格中，每层框的颜色编码了一个"传播指令"——从最内层向外逐层读取指令，将核心图案按指令序列依次变换后输出。
- `Input structure`：

  - 网格中心有一个小型多色图案（核心精灵，如 3×3）。
  - 核心精灵外围是若干层同心单像素宽矩形框，从内到外依次编号为第1层、第2层……
  - 每层框使用以下四种颜色之一：Red 表示"水平翻转"，Blue 表示"垂直翻转"，Green 表示"顺时针旋转90°"，Yellow 表示"逆时针旋转90°"。
- `Rule`：
  - 从最内层框开始，向外逐层读取每层框的颜色，构成一个变换指令序列。
  - 对核心精灵依次执行该指令序列中的每个变换操作。
  - 输出仅包含最终变换后的核心精灵（紧贴边界框输出，无多余背景）。
- `Key insight`：同心框不是装饰边界，而是一个从内向外排列的指令队列；解题者必须先发现颜色到变换操作的映射关系，再按正确的层序（由内向外）依次应用，才能得到正确输出。
</new_puzzle>

  - 每个小对象在网格中的相对位置（相对于大型图案的边界框）暗示了它在大型图案中的对应位置：小对象中心相对于网格中心的方向和大致距离，指示了它在大型图案中应匹配的子区域。

<new_puzzle>
- `description`：网格中的前景对象按照它们之间的"视线连通性"分组——能通过无障碍水平或垂直直线互相"看见"的对象归为同一组，然后每组对象统一重新着色为组内面积最大对象的原始颜色。
- `Input structure`：
  - 背景为 Black。
  - 网格中散布若干个不同颜色的 4-连通前景对象（每个对象为单色，颜色各异或部分相同）。
  - 对象之间可能存在无障碍的水平或垂直"视线"——即从一个对象的某个像素出发，沿水平或垂直方向在不经过任何其他前景像素的情况下可以到达另一个对象的某个像素。
- `Rule`：
  - 两个对象之间如果存在至少一条无障碍的水平或垂直直线（直线上除两端的对象像素外全部为背景），则它们"视线连通"。
  - 将所有视线连通的对象进行传递闭包分组（若 A 看见 B，B 看见 C，则 A、B、C 同组）。
  - 在每个组中，找到像素数量最多的对象，将组内所有对象的颜色统一替换为该最大对象的原始颜色。
  - 若组内有多个对象面积相同且最大，选择在网格中位置最靠上（行号最小）的那个对象的颜色。
  - 对象的形状和位置不变，仅改变颜色。
- `Key insight`：解题者需要先发现分组依据不是空间邻接或颜色相同，而是"视线连通性"这一非显然的关系；然后再归纳出组内统一着色的规则取决于面积最大者——两步推理缺一不可。
</new_puzzle>
