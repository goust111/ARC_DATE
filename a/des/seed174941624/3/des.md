- `description`：根据每个封闭区域内部散落标记像素的颜色，从隐藏的颜色-形状图例中查找对应模板，将该模板居中绘制到封闭区域内部。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干用 grey 像素绘制的封闭矩形框（框线宽度为 1 像素，矩形大小各异但内部空间均不小于 5x5）。
  - 每个封闭矩形框内部散落着 1-3 个同色的前景标记像素（颜色来自 red、blue、green、yellow 中的一种），这些标记像素的位置无规律。
  - 网格的一个角落区域有一个"图例区"：图例区由若干小的 3x3 色块紧密排列而成，每个 3x3 色块的外圈 8 像素为某种颜色（与矩形框内标记颜色对应），中心 1 像素为 black；在每个 3x3 色块的正下方紧邻放置一个 3x3 的形状模板（用 maroon 像素在 black 背景上绘制，表达 L 形、T 形、十字形等不同图案）。

- `Rule`：
  - 第一步（图例解码）：在图例区中，将每个 3x3 色块的颜色与其正下方 3x3 模板配对，建立"颜色 -> 形状模板"的映射。
  - 第二步（颜色匹配）：检查每个 grey 矩形框内部散落标记像素的颜色，通过图例映射找到对应的形状模板。
  - 第三步（模板放置）：清除矩形框内部的标记像素，将查到的 3x3 形状模板用该标记颜色居中绘制在矩形框内部（居中取框内部空间的行列中点，模板左上角对齐到中点偏移 (-1,-1) 的位置）。
  - 图例区本身在输出中被完全擦除为 black。grey 矩形框保持不变。

- `Key insight`：
  - 解题者需要先识别角落的图例区并解码颜色-形状映射关系，然后才能确定每个矩形框应绘制什么形状。标记像素的位置和数量是干扰项，只有颜色才有意义。两步推理缺一不可：图例解码是非显然的，模板放置规则也需要从多个样例中归纳居中对齐方式。
</new_puzzle>

- `description`：将网格中每个彩色对象沿其内部箭头指示的方向投射，投射距离由该对象的孔洞数量决定，投射副本使用与孔洞数量对应的新颜色。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干互不接触的 4-连通前景对象，每个对象由单一颜色（red、blue、green 等）填充。
  - 每个对象内部包含一个由 3 像素组成的箭头标记（用 yellow 像素绘制）：箭头由一个"头部像素"和两个"尾部像素"组成，尾部两像素水平或垂直相邻，头部像素位于尾部中点的上/下/左/右方向延伸一格处（形成一个指向上/下/左/右的 V 字形或楔形）。箭头指向从尾部中点到头部的方向。
  - 每个对象可能包含 0、1 或 2 个"孔洞"（孔洞定义为对象内部被 black 背景色完全包围的 4-连通区域，每个孔洞大小为 1 像素）。

- `Rule`：
  - 对每个对象，先确定其内部箭头的朝向（上/下/左/右四个方向之一）。
  - 统计该对象的孔洞数量 N（0、1 或 2）。
  - 沿箭头方向将该对象整体平移 (N+1) 格，生成一个副本。
  - 副本的颜色由孔洞数量决定：0 个孔洞 -> orange，1 个孔洞 -> magenta，2 个孔洞 -> azure。
  - 副本中不绘制箭头标记（即副本中原箭头位置用副本颜色填充）。
  - 原始对象（含箭头标记）保持不变。副本超出网格边界的部分被裁剪。

- `Key insight`：
  - 第一层推理：识别每个对象内部的 3 像素箭头标记并判断其朝向，这决定了投射方向。第二层推理：发现孔洞数量同时控制了两件事——投射距离和副本颜色，解题者需要从多个样例中分别归纳这两个映射关系。箭头方向和孔洞数量是两个独立的视觉特征，分别编码不同参数。
</new_puzzle>

- `description`：将散落的彩色种子像素沿网格中预设的灰色轨道路径生长，生长长度由种子所在轨道分支的编号决定，分支编号通过轨道交叉点的连接顺序确定。

- `Input structure`：
  - 背景为 black，网格大小约 18x18 至 25x25。
  - 网格中有一组由 grey 像素绘制的轨道路径，轨道为单像素宽的水平或垂直直线段，若干线段在交叉点处相连形成树状结构（无环路）。
  - 轨道有一个明显的"根端"：根端所在的一条直线段的末端有一个 maroon 像素标记。
  - 从根端出发，轨道在每个交叉点处分叉为 2-3 条分支。每条最终的末端分支（叶分支）上恰好放置了一个彩色种子像素（颜色各不相同，来自 red、blue、green、yellow、orange 等）。种子像素位于该叶分支的末端（远离交叉点的一端）。

- `Rule`：
  - 从 maroon 根端标记出发，沿轨道按深度优先、优先向上再向左的顺序遍历所有叶分支，为叶分支按遍历顺序编号为 1, 2, 3, ...
  - 对每个叶分支上的种子像素，从种子位置开始，沿该分支的轨道方向（朝交叉点方向）生长，将轨道上的 grey 像素替换为种子的颜色，生长的像素数量等于该分支的编号。
  - 生长不超过该叶分支到最近交叉点的长度；若编号大于分支长度，则填满整个分支后停止。
  - 未被生长覆盖的 grey 轨道像素保持 grey 不变。maroon 根标记保持不变。

- `Key insight`：
  - 解题者需要先从轨道的拓扑结构中找到根端标记，然后理解分支的遍历顺序规则（深度优先、上优先左优先），从而确定每个叶分支的编号。编号直接决定生长长度。核心难点在于发现遍历顺序这一隐含规则——它不是由种子颜色或位置直接给出的，而需要从轨道结构和根端位置推断。
</new_puzzle>

- `Input structure`：
  - 背景为 black，网格尺寸约 20x20 至 28x28。
  - 网格内部有若干由不同颜色绘制的小图案（每个图案由 3-6 个同色像素组成的 4-连通形状）。
  - 网格的四条边框上分布着成对的彩色锚点像素：每种锚点颜色恰好出现两次，一次在水平边框（顶边或底边）上，一次在垂直边框（左边或右边）上。锚点颜色从 red、blue、green、yellow 中选取，共 2-3 对。
  - 每对锚点的水平坐标和垂直坐标定义一个矩形裁剪窗口的一个角（锚点的行列交叉处）；窗口的对角由该锚点颜色的另一个锚点的行列交叉处确定。

- `Rule`：
  - 对每种锚点颜色，找到其两个锚点像素，一个在水平边上提供行坐标，另一个在垂直边上提供列坐标。两个锚点分别确定裁剪窗口的两个对角：水平边上锚点的列坐标与垂直边上锚点的行坐标交叉得到一个角点，垂直边上锚点的列坐标与水平边上锚点的行坐标交叉得到另一个角点。
  - 提取窗口内所有非 black 像素的图案，保持相对位置不变。
  - 输出网格由提取的窗口从上到下垂直堆叠组成，堆叠顺序按锚点颜色在顶边/底边上从左到右出现的顺序排列。
  - 每个提取窗口之间用一行 grey 像素分隔。窗口宽度统一为所有窗口中最大的宽度（较窄的窗口用 black 填充右侧）。

- `Key insight`：
  - 第一层推理：理解边框上成对锚点如何通过行列交叉定义矩形窗口——这不是直观的包围框，而是需要解题者发现"水平边锚点给列、垂直边锚点给行"的编码方式。第二层推理：发现输出的堆叠顺序由锚点在水平边上的位置决定，而非颜色本身或窗口内容。两层规则都需要从样例中归纳。
</new_puzzle>

<new_puzzle>
- `description`：识别网格中被分隔线划分的子区域，根据每个子区域内"种子对"的相对方位确定旋转角度，将种子对之间的图案旋转后重新绘制。

- `Input structure`：
  - 背景为 black，网格大小约 20x20 至 26x26。
  - 网格被 grey 的单像素宽直线（水平线和垂直线各若干条）分割为若干矩形子区域。
  - 每个子区域内恰好包含两个不同颜色的单像素标记（称为"种子对"），以及一个由第三种颜色绘制的小型连通图案（3-5 像素的 4-连通形状）。
  - 每个子区域中，两个种子像素之一（称为"锚种子"）紧邻图案（4-连通相邻），另一个种子像素（称为"方位种子"）不与图案相邻。

- `Rule`：
  - 在每个子区域内，找到与图案 4-连通相邻的锚种子。
  - 判断方位种子相对于锚种子的方位：正上方 -> 不旋转（0 度），正右方 -> 顺时针旋转 90 度，正下方 -> 旋转 180 度，正左方 -> 顺时针旋转 270 度。（方位种子与锚种子一定在同一行或同一列上。）
  - 以锚种子的位置为旋转中心，将图案按上述角度旋转。
  - 旋转后的图案绘制在子区域内，颜色不变。擦除原图案位置（未被旋转后图案覆盖的原位置恢复为 black）。两个种子像素保持不变。
  - grey 分隔线保持不变。

- `Key insight`：
  - 第一层推理：在每个子区域中，解题者需要分辨哪个种子是"锚"（与图案相邻）、哪个是"方位"（不相邻），这需要检查邻接关系。第二层推理：发现方位种子相对于锚种子的方位编码了旋转角度——上/右/下/左分别对应 0/90/180/270 度。两步推理紧密耦合：错误地识别锚种子会导致方位判断完全错误。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到被"门"打断的封闭围墙，根据围墙外部指示条的长度和方向决定从门口向内填充的条纹数量和方向。

- `Input structure`：
  - 背景为 black，网格大小约 18x18 至 25x25。
  - 网格中有若干用 blue 像素绘制的封闭矩形围墙（墙壁宽 1 像素），每个围墙的某一侧边上恰好有一个"门"——即该侧边上连续缺失 1-2 个 blue 像素形成的缺口。
  - 每个围墙的外部、与门所在侧相邻的位置，有一根由 red 像素组成的指示条（单像素宽的直线段），指示条平行于门所在围墙边且紧贴围墙外壁（与围墙外壁有 1 像素间隔）。指示条长度为 1-4 像素。

- `Rule`：
  - 对每个围墙，找到其门的位置和门所在的边（上/下/左/右）。
  - 找到该围墙外的 red 指示条，记录其长度 L。
  - 从门口向围墙内部方向填充条纹：
    - 若门在上边或下边：从门口位置开始，向内绘制 L 条完整的水平 green 条纹（每条条纹横跨围墙内部整个宽度，从门口向内逐行绘制）。
    - 若门在左边或右边：从门口位置开始，向内绘制 L 条完整的垂直 green 条纹（每条条纹纵跨围墙内部整个高度，从门口向内逐列绘制）。
  - 围墙像素和指示条像素保持不变。条纹不覆盖围墙像素。

- `Key insight`：
  - 解题者需要整合三条独立线索：门的位置决定填充起始边和条纹方向，外部指示条的长度决定条纹数量。关键的隐蔽性在于指示条与门的关联不是通过位置对齐而是通过"属于同一围墙的外部"来建立的，解题者必须先将指示条归属到正确的围墙，再读取其长度信息。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多个同色对象按其内部"标签像素"的颜色分组，然后在每组内按对象面积从小到大排序，将排序后的对象形状依次填入网格底部预设的"槽位框"中。

- `Input structure`：
  - 背景为 black，网格大小约 22x22 至 28x28。
  - 网格上半部分散布着若干由 grey 像素绘制的 4-连通对象（形状各不相同，面积在 3-8 像素之间）。每个 grey 对象的内部或紧邻位置恰好有一个彩色单像素"标签"（颜色从 red、blue、green 中选取）。
  - 网格下半部分有一排由 yellow 像素绘制的空心矩形"槽位框"（每个槽位框内部为 black），槽位框从左到右排列，每个槽位框大小相同（内部空间足以容纳最大的对象）。
  - 槽位框的左上角各有一个彩色单像素标记，颜色与上方标签颜色对应（每种颜色出现的槽位框数量等于拥有该颜色标签的对象数量）。同色槽位框相邻排列。

- `Rule`：
  - 第一步（分组）：根据标签颜色将上方的 grey 对象分组——所有标签为 red 的对象为一组，blue 的为一组，green 的为一组。
  - 第二步（排序）：在每组内，按对象面积（像素数量）从小到大排序。
  - 第三步（填充）：将每组中排序后的对象依次填入对应颜色的槽位框中（最小面积的对象填入该颜色最左边的槽位框，依次向右）。对象绘制在槽位框内部的左上角，使用标签颜色（而非 grey）绘制。
  - 上方的原始 grey 对象和标签像素被擦除。槽位框的 yellow 边框和角标记保持不变。

- `Key insight`：
  - 三层推理结构：第一层需要发现标签像素与对象的从属关系以及标签颜色的分组作用；第二层需要归纳出组内按面积排序的规则（而非按位置或形状）；第三层需要理解槽位框角标记的颜色如何与分组对应，以及填入时的重新着色和对齐规则。每一层都不是一眼可见的，需要跨样例比较才能确认。
</new_puzzle>
