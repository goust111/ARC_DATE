<description>
Drop the singleton marker into the matching red U-shaped container, or make a bottom-row puddle if no closed container is hit.

Input structure
- The grid has a dominant background, one singleton marker pixel on the top row,
  and one other foreground color forming vertical bars and bottom segments.
- A closed container is a U shape: two vertical side bars with a continuous
  bottom segment between them and an empty rectangular interior above the bottom.

Rule
- Remove the top marker from its original cell.
- If exactly one closed U-shaped container has the marker column within its
  horizontal footprint, fill that container's empty interior with the marker color.
- If no closed container is under the marker column, fill the whole bottom row
  with the marker color.

Key insight
- The marker does not identify a color by value; it identifies a vertical drop
  column, and only a structurally closed U shape can catch and contain the fill.

<description>
Reconstruct the repeated tile from its separated copies and mark the missing pixels in the damaged copy blue.

Input structure:
- The input is a lattice of equal-size blocks separated by one-cell solid rows
  and columns of the same separator color.
- All blocks are copies of one motif except exactly one block, where some
  motif pixels have been overwritten by the motif background color.
- Blue is absent from the input and is reserved as the output marker color.

Rule:
- Recover the motif by taking the unique majority color at each local block
  coordinate across all block copies.
- Find the single block that differs from this consensus motif.
- Return the consensus motif, recoloring the differing local coordinates blue.

Key insight:
- The repeated copies provide redundancy: the damaged positions are exactly
  the coordinates where the lone nonconforming copy has background instead of
  the consensus motif color.
</description>

<description>
Stamp source sprites into a destination frame via color-matched singleton markers.

Input structure:
- Two bordered rectangles: source (multi-cell sprites) and destination (singleton markers).
- Each sprite has an anchor pixel — its least-frequent color. Markers share these colors.

- Match each destination marker to the source sprite with the same anchor color.

<reference_puzzle index="4" source="train" puzzle_id="c920a713" lines="87-102">
<description>
Untangle overlapping colored rectangular frames into concentric square frames ordered by their visible crossings.

Input structure
- The background contains several one-cell-thick axis-aligned rectangular frames, one color per frame.
- Frames overlap, and the visible color at an overlap records a directed crossing from the hidden frame to the visible frame.
- Each foreground color still has visible pixels on the perimeter of its full rectangular bounding box.

Rule
- Infer each color's full rectangular frame from the bounding box of its visible pixels.
- Add a directed edge A -> B when B is visible at a crossing of A and B's frame perimeters.
- Find the unique path that visits every frame color once, then render those colors as one-pixel-thick concentric square frames from outside to inside.

Key insight
- The output is not a crop of the input; the crossing graph gives a single frame order, and that order is redrawn as nested rings.
</description>

<description>
Merge same-sized filled rectangular objects by overlaying their internal marker pixels.

Input structure:
- A dominant background surrounds two or more separated 4-connected foreground objects.
- Every object is a filled rectangle of the same size.
- Each rectangle has the same majority base color plus one or more non-base marker pixels.

Rule:
- Create one output rectangle with the shared object size, filled with the shared base color.
- For each input rectangle, copy every non-base marker pixel to the same relative location
  in the output.
- Marker overlays must either land on base color or agree in color with an existing marker.

Key insight:
The separated rectangles are layers of the same template; their colored marker pixels
combine by local coordinates while the repeated base fill is just the output canvas.

<reference_puzzle index="8" source="train" puzzle_id="bd283c4a" lines="7-23">
<description>
Pack all pixels into color-frequency runs along bottom-up columns.

Input structure
The input is a rectangular grid whose colors are all foreground material;
only the number of pixels of each color matters. In the observed task
instances, every present color has a distinct pixel count.

Rule
Count the pixels of each color and order the colors from most frequent to
least frequent. Rewrite a same-size grid by placing each color's full count
as one contiguous run while scanning columns from left to right and, within
each column, from bottom to top.

Key insight
The output preserves the multiset of colors but discards all original
positions, turning the grid into a frequency-sorted column packing.
</description>
</reference_puzzle>

<description>

Rule:
- For every marked northwest corner gap, clear that marker to black.

<description>
Decode a block-grid image by swapping each sprite-coded cell with a solid cell and each blank cell with the sprite.

Input structure
The grid is partitioned by black separator rows and columns into equal-size
square blocks. Each block is either a copy of one two-color sprite or a
uniform blank block of the sprite's minority color; grey pixels are erased
cells that act as wildcards.

Rule
Infer the repeated sprite from fully visible mixed-color blocks. Replace a
block matching that sprite, ignoring grey erasures, with a solid block of
the sprite's majority color. Replace a uniform blank block with the sprite.
Separator rows and columns, including grey erasures on them, become black.

Key insight
The small sprite is a block-level code for one macro-cell state, and the
uniform minority-color block is the other state; the output renders the
opposite code in each macro-cell while cleaning erased pixels.
</description>
</reference_puzzle>

<description>
Fire projectiles from 3-pixel triangle sprites; mark collisions with maroon or blue.

Input structure:
- bg = most common color. Non-bg 3-pixel sprites shaped as axis-aligned L's or diagonal V's.

Rule:

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 关于"计算"的边界：
   - **允许使用**（这些都是人类能心算的视觉量）：数像素 / 孔洞 / 对象 / 邻居（≤10 量级）、比大小、按某个可见属性排序、奇偶判断、取最大 / 最小、用一个计数值作为另一个等量几何量（如 N 个像素 → 长度 N 的射线、面积 N → 边长 N）、判断接触 / 相邻 / 包含、粗略中心位置（簇的视觉中点）、"距离"作为"几步"而不是公式等人类能够直观感受计算的内容。
   - **禁止使用**（这些是算法量而非视觉量，会迫使解题者依赖公式而非视觉直觉）：曼哈顿 / 欧氏 / Chebyshev 距离作为精确查表键、凸包面积、二进制位编码 / 位运算、模运算（取模） / 余数、拓扑距离（BFS / 最短路 / 跳数）、精确几何质心坐标、凸角 / 凹角计数等复杂且不易被看出来的计算都是禁止使用的。
3. 问题必须能从少量示例中推断出来（通常为 3 对训练样例 + 1 个测试样例）。设计时从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息（例如颜色id和颜色亮度是禁止使用的）或需要推算的隐藏属性。规则背后的逻辑本身可以有一定挑战性，但解题所需的所有线索必须能从网格中直接获取。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入 / 输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 "red"。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7. 题目难度应来自机制的隐蔽性而非步骤数。用参考题作为难度标尺——如果你生成的题一个样例就能猜到规则，说明机制太透明，需要加深隐蔽性。
8. 优先从参考题的机制出发进行重组或推演，而非从物理隐喻出发。物理隐喻容易导致大量题目归结为一种模式，例如"沿方向移动到阻挡处停止"。
9. 题目的难度优先来自规则的**结构层数**，而不是单一步骤的复杂度。关于"结构层数"的判定标准：**只有解题者需要主动推理才能完成的步骤才算一层**。肉眼一扫即可获得的信息（如"找到缺口在哪一侧"、"数出像素个数"、"识别哪个对象最大"）不构成独立的推理层——它们只是变换的前置输入，不增加认知难度。真正的多层结构是指每一层都需要解题者发现一个非显然的规律。以两层结构为例：
   - ✗ 伪两层："找到缺口方向"→"把东西推到对面" — 第一步肉眼可见，实际只有一层推理。
   - ✓ 真两层："通过孔洞数量匹配颜色图例"→"用匹配到的颜色重绘对象" — 两步都需要非平凡的归纳。

   如果你发现自己写出的题只是"对每个对象，根据它的某个属性做某变换"的单步规则，请引入一个需要主动推理的前置步骤。**用堆叠 tie-break 规则或复杂数学公式来"加难度"是劣解；用多一层需要归纳的结构嵌套来"加难度"才是好解**。
10. 在符合ARC题目和提示词要求的基础上，鼓励尝试创新规则为多层结构的题目，不局限于两层，可以创新三层或四层结构的题目，但不可为了多结构层数违背要求。

生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述参考题相同或类似，不可只是替换颜色、方向、对象类型等表层要素。判断标准：新题的核心推理路径应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5 个样例中发现规律。没有使用上述注意事项第二条禁止使用的复杂计算。
