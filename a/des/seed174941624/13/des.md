根据封闭区域内部的"种子"颜色对，用图例查找表中的对应结果颜色重新着色区域边框。

Input structure:
- 背景为 black。网格中有若干由 grey 色像素绘制的封闭矩形区域，矩形之间互不重叠、互不接触。
- 每个封闭矩形内部恰好包含两个不同颜色的单像素"种子点"，种子点颜色来自 red、blue、green、yellow、orange、magenta 中的某两种。
- 网格右上角有一个小型"图例矩阵"：一张 N 行 3 列的表格（N 为所有出现的种子颜色对的数量），每行三个格子，左格和中格分别填一种种子颜色，右格填一种"结果颜色"，表示当某个区域内同时包含左格颜色和中格颜色的种子时，该区域的边框应被重绘为右格所示的结果颜色。图例行的种子颜色对无序——即图例中 (red, blue) 同样匹配区域内的 (blue, red)。

Rule:
- 对每个封闭矩形区域，识别其内部两个种子点的颜色对。
- 在图例矩阵中查找与该颜色对匹配的行，读取对应的结果颜色。
- 将该矩形的整条 grey 边框替换为结果颜色，内部种子点保持不变，背景不变。
- 图例矩阵本身在输出中被擦除为背景色。

Key insight:
需要先识别出右上角的图例是一张"颜色对 -> 结果颜色"的查找表，再对每个区域执行颜色对匹配和边框重绘——图例的解读与区域的匹配构成两层独立的推理。
</new_puzzle>

Input structure:
- 背景为 black。网格中央有一个较大的 grey 色矩形模板，模板内部有若干不规则的背景色空洞（即模板中被挖去的区域）。

- 清除模板外部的所有碎片（替换为背景色）。
- 模板的 grey 部分和标记颜色边框保持不变。

Key insight:
碎片与空洞之间有两层对应关系需要分别推理：第一层是通过形状匹配（含旋转）找到哪个碎片填入哪个空洞；第二层是填入时颜色不跟随碎片，而是由空洞边框的标记颜色决定——解题者必须发现"颜色来源于空洞标记"这一非直观规则。

Input structure:
- 背景为 black。网格被一条水平的 grey 分隔线和一条垂直的 grey 分隔线（均贯穿全网格）划分为四个矩形区域（左上、右上、左下、右下）。

- 每个区域内散布着若干彩色的小对象（每个对象为单一颜色的 4-连通区域，颜色不是 black、grey 或 maroon），对象不跨越分隔线。

- 将该区域内每个彩色对象沿重力方向整体平移，直到对象的某个像素紧邻区域边界（分隔线或网格边缘）或紧邻另一个已停止的对象为止，对象形状保持不变。

- 条形标记自身在输出中被擦除为背景色。
- 分隔线保持不变。

Key insight:
解题的第一层推理是发现四个区域各有独立的重力方向，第二层是识别角落小条形标记的位置和朝向编码了重力方向——条形标记靠近哪个边就代表物体被吸向那个边。两层推理缺一不可：仅观察对象运动可能看出方向，但标记的编码方式需要归纳才能应用于测试。
</new_puzzle>

根据每个封闭房间内彩色像素的数量奇偶性，选择性地填充或清空房间，填充时同时将房间边框染为房间内像素的颜色。

Input structure:
- 背景为 black。网格中由 grey 色线条构成若干封闭矩形房间（类似网格状布局，但房间大小不一），房间之间共享墙壁，所有墙壁宽度为 1 像素。
- 每个房间内部可能为空（全部背景色），也可能包含若干同色的非背景、非 grey 像素（散布在房间内部的任意位置），每个含像素的房间只使用一种颜色。

Rule:
- 对每个房间，数其内部彩色像素的个数。
- 若像素个数为奇数：将整个房间内部（包括原来的背景像素）全部填充为该房间的彩色像素颜色，并将围成该房间的 grey 边框也替换为该颜色。

Key insight:
解题者需要发现两个非显然规律：(1) 房间的命运取决于内部像素数量的奇偶性——奇数扩张、偶数清空；(2) 扩张时不仅填充内部，还会"感染"边框颜色。由于房间大小不一且像素散布位置随机，仅靠视觉面积判断容易误判，必须精确数像素个数。
</new_puzzle>

将输入网格中的多个互相遮挡的彩色矩形分离还原，然后按面积从小到大依次水平排列输出。

Input structure:
- 背景为 black。网格中有若干不同颜色的矩形色块，它们在网格上部分重叠，形成类似"窗口叠放"的效果。每个矩形为实心单色，当两个矩形重叠时，"上层"矩形的像素覆盖"下层"矩形的像素。
- 所有矩形颜色互不相同，矩形数量为 2 到 5 个。
- 被遮挡的矩形可能只露出 L 形、U 形或分散的边缘条，但其完整轮廓可以从可见部分推断出来（每个矩形的四条边中至少有两条完整可见的边，从而可以确定完整宽高）。

Rule:
- 首先还原每个矩形的完整尺寸：对于每种颜色，找到该颜色所有可见像素的最小外接矩形，即为该矩形的原始大小。
- 计算每个矩形的面积（宽 x 高）。
- 输出一个新网格：将所有还原后的完整矩形按面积从小到大从左到右水平排列，相邻矩形之间间隔 1 列背景色。输出网格的高度等于最大矩形的高度，每个矩形顶部对齐。

Key insight:
第一层推理是发现输入中的颜色区域实际上是互相遮挡的完整矩形，需要从部分可见的轮廓推断每个矩形的原始尺寸；第二层是发现输出按面积排序并水平排列——排序依据不是颜色或位置，而是还原后的面积。遮挡关系的识别和面积排序的发现构成两层独立的归纳任务。
</new_puzzle>

- 迷宫的某个死胡同末端有一个彩色像素作为"起点标记"，起点标记的颜色不是 black 或 grey。起点标记所在通道的朝向即为初始行进方向（从死胡同向开放方向前进）。

- 从起点出发，沿初始方向前进。每走一步将路径像素绘制为起点标记的颜色。

- 路径不回头（不走来时的方向，除非是唯一选择）。
- 图例区本身在输出中保持不变。

Key insight:
解题者需要完成三层推理：(1) 识别角落的图例区是一张查找表；(2) 理解 L 形符号的朝向编码了左转/右转规则；(3) 将查找到的转向规则应用于迷宫路径绘制。图例的存在使得不同样例中相同颜色可能有不同转向规则，迫使解题者必须先读图例再画路径。

<new_puzzle>
将网格中的彩色"信号源"沿其发射方向传播，信号穿过"透镜条"时颜色发生由边缘映射表决定的替换。

Input structure:
- 背景为 black。网格中有若干单像素的"信号源"，每个信号源由一种颜色（如 red、blue、green 等）绘制，且紧邻信号源的上下左右四个方向中恰好有一个方向存在一个 maroon 单像素"方向指示器"，指示器与信号源相邻。
- 网格中还有若干条贯穿整行或整列的"透镜条"，每条透镜条由某种颜色（非 black、非 maroon）的连续像素绘制，宽度为 1 像素。透镜条颜色可能与某些信号源颜色相同，也可能不同。
- 网格边缘有一个 2 行 N 列的小型"颜色映射表"：第一行是若干不同颜色的像素（输入色），第二行是对应位置的另一种颜色（输出色），表示信号穿过该颜色透镜时的颜色变换关系。每种透镜颜色在映射表第一行中出现一次。

Rule:
- 对每个信号源，发射方向为信号源指向远离 maroon 指示器的方向（即指示器在信号源左侧，则信号向右发射）。
- 从信号源出发，沿发射方向逐像素绘制信号线（颜色与当前信号颜色相同），直到碰到网格边缘。
- 当信号线穿过一条透镜条时：查找颜色映射表，找到透镜条颜色所在列，读取第二行的输出色；从透镜条之后开始，信号线的颜色变为该输出色。若之后再穿过另一条透镜条，再次查表变色。
- maroon 指示器在输出中被擦除为背景色。信号线覆盖透镜条像素时，透镜条像素被信号线当前颜色覆盖。

Key insight:
三层推理：(1) 从 maroon 指示器的位置推断信号发射方向（反向逻辑）；(2) 识别边缘的映射表将透镜颜色映射为变换后的颜色；(3) 信号线在穿过不同透镜时会发生多次颜色变换，最终颜色取决于透镜的穿越顺序。方向推断、映射表解读和多次变色三者缺一不可。
</new_puzzle>

<new_puzzle>
在分格棋盘中，每个格子的最终颜色由其所在行的"行模板"和所在列的"列模板"的颜色经优先级图例裁决后共同决定。

Input structure:
- 网格被 grey 色线条均匀分割为 R 行 C 列的格子阵列（每个格子内部为 3x3 的方块）。
- 最左列的格子作为"行模板"：每个格子内部填充了一种颜色（非 black、非 grey），不同行的颜色可能相同或不同。
- 最上行的格子作为"列模板"：每个格子内部填充了一种颜色，不同列的颜色可能相同或不同。
- 左上角的格子（行模板与列模板的交叉处）为空（背景色）。
- 网格右下角区域有一个由 maroon 边框围起的小型"优先级图例"：图例内部将出现的所有颜色纵向排列为单像素列，从上到下表示优先级从高到低。
- 阵列中其余格子（非模板行/列）的内容在输入中为空（背景色），需要在输出中填充。

Rule:
- 对于阵列中第 i 行第 j 列的非模板格子，读取第 i 行行模板的颜色 A 和第 j 列列模板的颜色 B。
- 若 A 等于 B，则该格子填充颜色 A。
- 若 A 不等于 B，则查看优先级图例，优先级更高（在图例中位置更靠上）的颜色胜出，格子填充胜出的颜色。
- 模板行/列本身在输出中保持不变。优先级图例在输出中保持不变。

Key insight:
第一层推理是发现行模板和列模板的交叉决定了每个格子的颜色（类似乘法表结构）；第二层是当行列颜色冲突时，需要发现角落的优先级图例提供了裁决规则——图例中的纵向排列顺序编码了颜色优先级。仅从输出的颜色分布无法直接反推规则，必须同时参考模板和图例。
</new_puzzle>
