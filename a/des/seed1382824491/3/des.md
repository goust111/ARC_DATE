- `description`：根据封闭区域内部"种子"色块的形状推断生长方向，再依据区域边框上缺口的位置选择输出颜色，将生长结果涂入区域。

- `Input structure`：
  - 背景色为 Black。网格中散布若干由单一颜色（如 Blue、Red、Green 等，各区域边框颜色不同）绘制的封闭矩形边框。
  - 每个矩形边框的某一条边上恰好有一个 1 像素宽的缺口（缺口处为背景色）。
  - 每个矩形内部包含一个由 Grey 像素构成的小型连通色块（"种子"），种子的形状为 L 形、T 形或直线段中的一种。
  - 网格的最右列或最底行有一个小型颜色图例区：图例由若干 2 像素高的色条组成，每条色条左列为形状示意（L 形 = Maroon、T 形 = Orange、直线段 = Yellow），右列为对应的输出填充色。

- `Rule`：
  - 第一层推理——确定生长方向：观察每个矩形边框缺口所在的边（上/下/左/右），缺口的反方向即为种子的"生长方向"。例如缺口在上边，则生长方向为向下。
  - 第二层推理——通过种子形状查图例获取填充颜色：识别种子的形状类别（L 形、T 形、直线段），在颜色图例中找到该形状类别对应的输出填充色。
  - 执行变换：从种子的每个像素出发，沿生长方向逐像素延伸，填充对应的输出颜色，直到碰到边框的对侧内壁为止。种子本身的 Grey 像素也被替换为该输出颜色。缺口保持不变（仍为背景色）。其余部分（边框、背景）不改动。

- `Key insight`：缺口位置决定方向，但填充颜色并非由边框颜色或缺口位置决定，而是由种子的几何形状在图例中查表获得——解题者必须先识别形状分类，再交叉引用图例，才能确定最终颜色。
</new_puzzle>

- `description`：将网格中散落的彩色碎片按"磁铁"标记的极性配对，然后沿磁铁连线方向将配对碎片滑动合并为一个对称图案。

- `Input structure`：
  - 背景色为 Azure。网格中散布若干小型彩色连通碎片（每个碎片 3-6 像素，颜色各不相同）。
  - 每个碎片内部恰好包含一个 Red 像素（"北极"标记）或一个 Maroon 像素（"南极"标记），其余像素为该碎片自身颜色。
  - 碎片总数为偶数，且恰好一半含 Red 标记、一半含 Maroon 标记。
  - 含 Red 标记的碎片与含 Maroon 标记的碎片之间存在唯一配对关系：配对的两个碎片去掉标记像素后形状完全相同（互为全等，不含旋转或翻转）。

- `Rule`：
  - 第一层推理——形状匹配配对：去掉每个碎片中的标记像素（Red 或 Maroon），比较剩余形状。形状全等的一对碎片（一个含 Red、一个含 Maroon）构成配对。
  - 第二层推理——确定合并轴线与滑动：对于每一对配对碎片，找到两个标记像素的连线方向（水平或垂直，保证只出现这两种情况）。两个碎片沿该方向相向滑动，直到它们的标记像素相邻（间距 1 像素）为止。
  - 合并后，两个标记像素合并为一个 Yellow 像素，放置在两个标记原位置的中点处。碎片其余像素保持各自颜色不变。原始位置的碎片被擦除（恢复为背景色）。

- `Key insight`：解题者必须先通过去除标记后的形状全等性完成跨色配对，然后才能确定滑动方向——标记颜色区分极性、形状全等确定配对、标记连线确定运动轴，三个信息缺一不可。
</new_puzzle>

- `description`：在被彩色墙壁分隔的房间网络中，根据门洞上方悬挂的钥匙色块解锁通道，并用路径颜色标记从起点到终点的唯一可达路线。

- `Input structure`：
  - 背景色为 Black（代表可通行地板）。网格被若干单像素厚的彩色墙壁（Blue、Green、Red、Orange 等不同颜色）分割成多个矩形房间。
  - 墙壁上偶尔有 1 像素宽的缺口（"门洞"）。每个门洞的墙壁侧（紧邻门洞的墙壁像素中）恰好有一个与该墙壁颜色不同的像素嵌入其中，称为"锁"像素。
  - 网格中有一个 Yellow 像素标记起点，一个 Maroon 像素标记终点。
  - 若干房间的地板上各放置一个小型 Grey 边框的 2x2 方块，方块内部填充某种颜色——该内部颜色即为"钥匙颜色"。

- `Rule`：
  - 第一层推理——钥匙与锁的颜色匹配：每个门洞的"锁"像素颜色必须与某个钥匙方块的内部颜色一致，门洞才算"可通行"。没有对应钥匙的门洞视为封死（不可通过）。
  - 第二层推理——寻找唯一路径：从起点出发，仅通过可通行的门洞在房间之间移动，找到到达终点的唯一路径（题目保证解唯一）。
  - 执行变换：输出网格中，沿该路径经过的所有地板像素被涂为 Yellow，所经过的门洞像素也涂为 Yellow。起点和终点保持原色不变。钥匙方块被擦除（恢复为地板色 Black）。墙壁保持不变。

- `Key insight`：不是所有门洞都可通行——解题者必须先建立"钥匙内部颜色 → 锁颜色"的对应关系来判断哪些门洞开启，然后才能在简化后的房间拓扑中找到唯一通路。视觉上钥匙方块和锁像素分散在不同房间中，需要跨区域匹配。
</new_puzzle>

- `description`：根据网格边缘的"折叠指令条"将矩形画布分层折叠，输出折叠后各层颜色的叠加结果。

- `Input structure`：
  - 背景色为 Black。网格中央有一个矩形彩色画布区域（尺寸为偶数行 × 偶数列），画布内散布若干不同颜色的像素图案。
  - 画布的上方有一行"水平折叠指令条"：该行的每个像素要么是背景色，要么是 Red。Red 像素所在的列标记了垂直折叠线的位置。
  - 画布的左侧有一列"垂直折叠指令条"：该列的每个像素要么是背景色，要么是 Blue。Blue 像素所在的行标记了水平折叠线的位置。
  - 指令条中 Red 像素最多 1 个，Blue 像素最多 1 个（即最多一次水平折叠 + 一次垂直折叠）。

- `Rule`：
  - 第一层推理——解读折叠指令：如果上方指令条中有 Red 像素在第 c 列，则画布沿第 c 列垂直对折（右半部分翻到左半部分上方）。如果左侧指令条中有 Blue 像素在第 r 行，则画布沿第 r 行水平对折（下半部分翻到上半部分上方）。两个折叠的执行顺序为：先垂直折叠、后水平折叠。
  - 第二层推理——颜色叠加规则：折叠后多层像素重叠时，遵循以下规则：若某位置所有层都是背景色，则输出背景色；若只有一层有非背景色，输出该颜色；若多层都有非背景色，则输出在画布上行号更小（更靠上）的那一层的颜色（即上层优先）。
  - 输出网格仅包含折叠后的画布（尺寸缩小），不包含指令条。

- `Key insight`：解题者需要从边缘的指令条读出折叠线位置和折叠顺序，然后在脑中完成空间翻转——难点在于理解"翻折后哪些像素对齐到同一位置"以及"折叠顺序影响最终哪一层在上方"。指令条的存在使得折叠线不是靠对称性猜测，而是被显式编码的。
</new_puzzle>

<new_puzzle>
- `description`：用网格角落的"旋转罗盘"确定每个彩色环的旋转方向，然后将环上的标记像素旋转到新位置。

- `Input structure`：
  - 背景色为 Black。网格中央区域包含若干同心的单像素厚矩形环（每个环为不同颜色，如 Blue、Green、Red、Orange 等），环与环之间间隔 1 像素的背景色。
  - 每个环上恰好有 1-3 个 Yellow 像素（"标记"），它们替换了该环上原本颜色的像素。
  - 网格的四个角落之一放置一个"旋转罗盘"：罗盘是一个 3x3 的小方块，中心为 Grey，四个正交方向（上/下/左/右）各有一个像素。罗盘中恰好有一个方向的像素为 Maroon，其余三个方向为 Grey。Maroon 在中心上方或左方表示顺时针旋转，在中心下方或右方表示逆时针旋转。

- `Rule`：
  - 第一层推理——从罗盘读取旋转方向：找到角落的 3x3 罗盘，根据 Maroon 像素相对于中心的位置确定全局旋转方向（上/左 = 顺时针，下/右 = 逆时针）。
  - 第二层推理——确定每个环的旋转步数：每个环的旋转步数等于该环上 Yellow 标记像素的数量。1 个标记 = 旋转 1 步，2 个标记 = 旋转 2 步，3 个标记 = 旋转 3 步。这里"1 步"指环上所有像素（包括标记）沿环的周长方向移动 1 个像素位置。
  - 执行变换：将每个环上的所有像素（该环颜色的像素和 Yellow 标记像素）沿环的轮廓按指定方向旋转指定步数。环的矩形轮廓上的像素顺序为：从左上角开始，沿上边向右、沿右边向下、沿下边向左、沿左边向上，形成一个顺序序列；旋转即在该序列上做循环移位。
  - 输出网格中，罗盘区域被擦除（恢复为背景色），同心环区域显示旋转后的结果。

- `Key insight`：旋转方向由罗盘全局指定，但每个环的旋转量由该环自身的标记数量各自决定——解题者需要分别识别这两个独立信息源，并理解"沿矩形环轮廓循环移位"这一空间操作。标记既是"被旋转的对象"又是"编码旋转量的信号"，这种双重角色增加了推理的隐蔽性。
</new_puzzle>

<new_puzzle>
- `description`：在网格中识别由边框颜色编码的"容器"层级关系，根据嵌套深度对容器内部执行不同的填充变换。

- `Input structure`：
  - 背景色为 Black。网格中包含若干嵌套的单像素厚矩形边框。每个边框使用不同颜色（如 Blue、Red、Green、Orange 等）。
  - 边框可以嵌套：一个边框完全位于另一个边框的内部。嵌套深度从 0 开始计数（最外层边框深度为 0，被一层边框包围的边框深度为 1，以此类推）。
  - 最内层的边框（不再包含其他边框的边框）内部有一个小型彩色图案（由 1-4 个像素组成的连通色块，颜色为 Yellow）。
  - 网格底部有一个单行图例条：从左到右排列若干颜色像素，第 1 个像素的颜色对应深度 0 的填充色，第 2 个对应深度 1 的填充色，依此类推。图例像素之间以背景色间隔。

- `Rule`：
  - 第一层推理——建立嵌套层级：识别所有矩形边框，根据包含关系确定每个边框的嵌套深度（最外层 = 0，往内逐层加 1）。
  - 第二层推理——查图例确定填充色：根据每个边框的嵌套深度，在底部图例条中查找对应位置的颜色。
  - 第三层推理——按深度奇偶决定填充方式：偶数深度（0, 2, 4...）的边框，将其内部（不含更内层边框占据区域的）空白背景像素全部填充为图例对应颜色。奇数深度（1, 3, 5...）的边框，仅将其内部空白区域的四个角落各填充一个像素为图例对应颜色。
  - 最内层边框中的 Yellow 图案保持不变。边框本身保持原色不变。

- `Key insight`：解题者需要三步推理：先通过空间包含关系建立嵌套树，再用深度值查表获取颜色，最后发现奇偶深度对应不同的填充模式（全填 vs 仅角落）。嵌套层级、颜色查表、奇偶分支三层机制交织，使得仅观察一个样例难以完全归纳规则。
</new_puzzle>
