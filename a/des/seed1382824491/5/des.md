<new_puzzle>
description: 根据嵌套框架的边框颜色序列在颜色环上查找对应的填充色，再用框架内部的镂空形状作为模板印到同色精灵上。

Input structure:
- 背景色（bg）为黑色（Black）。网格中散布着若干"嵌套框架"和若干"精灵"。
- 每个嵌套框架由 2-3 层同心矩形边框组成，每层边框颜色不同；框架最内层为背景色的空腔，空腔中有一个由背景色构成的镂空图案（即空腔并非完全空白，而是被边框色部分填充后留下的形状）。
- 精灵是远离框架的小型单色连通区域，每个精灵的颜色各不相同。
- 颜色环定义为：Red → Orange → Yellow → Green → Azure → Blue → Magenta → Maroon → Red（循环）。

Rule:
- 第一层推理——颜色映射：对每个嵌套框架，从最外层到最内层读取边框颜色序列，在颜色环上从外层颜色出发，按序列长度步数前进，到达的颜色即为该框架的"目标色"。例如外层 Red、中层 Orange、内层 Yellow，共 3 层，从 Red 出发走 3 步到达 Green，Green 即为目标色。
- 第二层推理——模板匹配：目标色对应网格中同色的那个精灵。提取框架最内层空腔中的镂空形状（以空腔左上角为原点的相对坐标集合）。
- 变换：将镂空形状以 Grey 色叠印到对应精灵的左上角对齐位置上（仅覆盖精灵范围内的像素）。框架本身保留不变，精灵被叠印后输出。

Key insight: 边框层数不仅是视觉装饰，它同时编码了在颜色环上的步进距离，从而间接指定目标精灵；而框架内部的镂空形状才是要转移的信息载荷。
</new_puzzle>

<new_puzzle>
description: 利用散落的彩色路标像素确定传送路径，将路径起点处的图案沿路径逐站复制并按站点颜色重新着色。

Input structure:
- 背景色（bg）为黑色（Black）。网格中有一个多色"源图案"（一个紧凑的非背景连通区域，包含 2-3 种颜色）。
- 网格边缘和内部散布着若干孤立的彩色像素，称为"路标"。路标颜色各不相同，且每种颜色恰好出现两个像素。
- 源图案中有一个特殊的单像素"出发标记"，其颜色与某个路标颜色相同。

Rule:
- 第一层推理——构建传送链：找到出发标记的颜色，定位与之同色的路标对（两个像素）。出发标记本身是链的起点。同色路标对中，离出发标记较近的那个（行优先比较：先比较行号差的绝对值，再比较列号差的绝对值）是第一站的"入口"，另一个是第一站的"出口"。出口像素有且仅有一个 4-邻接的其他颜色路标像素——该颜色确定下一对路标，重复此过程直到某个出口没有相邻路标（链终止）。
- 第二层推理——图案复制与着色：沿传送链的每一站，将源图案以出发标记为锚点对齐到该站入口像素位置，复制整个图案。复制时，源图案中所有非出发标记颜色的像素保持原色，而出发标记颜色的像素改为当前站对应的路标颜色。
- 源图案在原位保留不变。新复制的图案覆盖在背景上（若超出网格边界则裁剪）。路标像素被图案覆盖或保留均可（图案优先）。

Key insight: 颜色相同的路标对构成"传送门"的两端，而出口旁边紧邻的不同色路标像素是通往下一个传送门的线索——解题者必须先发现这条隐式链路，再理解图案的着色替换规则。
</new_puzzle>

<new_puzzle>
description: 根据围栏内部缺口的方位确定旋转角度，再将围栏外的种子图案旋转后植入围栏内部，同时按面积排序配对围栏与种子。

Input structure:
- 背景色（bg）为黑色（Black）。网格中有若干"围栏"和若干"种子图案"。
- 每个围栏是一个单色矩形环（中空矩形边框，宽度为 1 像素），每个围栏颜色各不相同。每个围栏的边框上恰好有一个 1 像素的缺口（即边框上某个像素为背景色替代）。
- 种子图案是小型单色连通区域，位于所有围栏之外。每个种子图案的颜色各不相同，且种子的外接矩形严格小于围栏内部空腔。
- 围栏数量与种子数量相同。

Rule:
- 第一层推理——旋转角度：检查每个围栏缺口所在的方位：缺口在上边→不旋转（0°）；缺口在右边→顺时针旋转 90°；缺口在下边→旋转 180°；缺口在左边→逆时针旋转 90°（即顺时针 270°）。
- 第二层推理——匹配：每个种子图案与围栏的配对方式为：将所有围栏按内部空腔面积从小到大排序，将所有种子按像素数量从小到大排序，一一对应配对。
- 变换：将配对的种子图案按对应围栏的旋转角度旋转，然后放置在围栏内部空腔的中心位置（上下左右居中，若无法精确居中则偏左偏上）。种子图案的颜色改为围栏的颜色。围栏本身保持不变（包括缺口）。

Key insight: 缺口方位编码了旋转指令而非"入口方向"，而围栏与种子的配对需要通过面积/像素数的排序对齐来发现，两层规则都需要从样例中独立归纳。
</new_puzzle>

<new_puzzle>
description: 将网格中由分隔线划分的多个房间视为节点，根据房间内种子像素的颜色沿门洞同步传播颜色波，冲突房间标记为特殊色。

Input structure:
- 背景色（bg）为黑色（Black）。网格被 Grey 色的水平线和垂直线分割成若干矩形"房间"（类似表格）。
- 分隔线宽度为 1 像素。部分分隔线上有 1 像素宽的缺口（即分隔线上某个像素为背景色），这些缺口称为"门洞"，连接相邻两个房间。
- 若干房间内包含一个孤立的彩色非背景、非灰色像素，称为"种子"。不同种子颜色可以相同或不同。
- 其余房间内部为纯背景色。

Rule:
- 第一层推理——重建连通关系：解题者需要识别门洞的位置，从而确定哪些房间彼此相邻可达。没有门洞相连的相邻房间之间不可传播。
- 第二层推理——同步传播与冲突：所有种子同时开始传播。每个种子的颜色通过门洞扩散到相邻的空房间。传播是逐层的：第 1 轮，种子所在房间标记为该种子颜色；第 2 轮，通过门洞与已标记房间相邻的空房间被标记为传来的颜色；以此类推。若一个空房间在同一轮被两种不同颜色同时到达（即它通过门洞与两个不同颜色的已标记房间相邻），则该房间标记为 Maroon（冲突色）。已被标记的房间（包括冲突色房间）不再改变，且冲突色房间也会向外继续传播 Maroon 色。
- 输出着色：每个房间最终用其被标记的颜色填充内部所有背景像素（种子像素保留原色）。Grey 分隔线保持不变。门洞保持为背景色。未被任何颜色到达的房间保持为背景色。

Key insight: 解题者必须首先从门洞的位置中重建房间之间的连通图结构，然后模拟多源同步扩散——关键难点在于识别冲突条件（同一轮到达意味着经过相同数量的门洞）并理解冲突产生特殊颜色，而非简单的"先到先得"。
</new_puzzle>

<new_puzzle>
description: 将散布的箭头形标记解码为方向指令，按邻接关系形成指令链依次移动活动精灵，每次停靠处留下以箭头颜色着色的足迹。

Input structure:
- 背景色（bg）为黑色（Black）。网格中有一个多像素的彩色"活动精灵"（紧凑的 4-连通区域，单一颜色，称为"活动色"）。
- 网格中散布着若干"箭头标记"。每个箭头标记由 5 个同色像素组成：3 个像素排成一条水平或垂直直线构成箭杆，箭杆的一端额外延伸 1 个像素构成箭尾（共 4 像素成直线），箭杆另一端（箭头端）的垂直方向两侧各有 1 个像素不存在，但箭头端像素本身存在——因此箭头方向即为从箭尾指向箭杆前端的方向。整体呈 "→" 简化形态（朝上、下、左、右四方向之一）。每个箭头共 4 个像素（一条长度为 4 的直线段）。
- 每个箭头标记的颜色各不相同，且不与活动色相同。
- 网格中还有一个 Maroon 色单像素"起始标记"，位于活动精灵某个像素的 4-邻接位置。

Rule:
- 第一层推理——确定指令链：起始标记的 4-邻接像素中有且仅有一个箭头标记的像素。该箭头是第一条指令。活动精灵按该箭头方向平移，直到精灵的前沿碰到箭头的最前端像素所在行或列（即精灵沿移动方向滑动，停在使精灵最前沿与箭头前端像素对齐的位置）。到达新位置后，精灵任意像素的 4-邻接中会有且仅有一个尚未使用的箭头标记的像素——这是下一条指令。重复直到无下一个箭头。
- 第二层推理——足迹着色：精灵每次从一个位置移动到下一个位置时，在原位置留下与精灵形状完全相同的"足迹"，足迹颜色为触发本次移动的箭头标记的颜色。活动精灵在最终停靠位置保持活动色。
- 所有箭头标记和起始标记在输出中被擦除（替换为背景色）。

Key insight: 解题者需要三层归纳——首先识别箭头的绘制方式来确定朝向，然后发现基于精灵当前位置邻接关系的链式指令排序（而非箭头在网格中的空间位置排序），最后理解足迹颜色来自驱动该次移动的箭头颜色。箭头同时充当方向指令和足迹调色板。
</new_puzzle>
