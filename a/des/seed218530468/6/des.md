- `description`：根据封闭区域内部的标记像素颜色，从颜色图例条中查找对应的填充图案方向，再沿该方向用条纹填充该区域。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干由灰色（grey）像素围成的封闭区域（每个区域是一个单像素宽的闭合矩形环），每个区域内部恰好包含一个单独的标记像素，颜色各不相同（如 red、blue、green 等）。
  - 网格的最下方一行是颜色图例条：由若干组"颜色像素 + 方向指示线段"组成，各组之间间隔至少一个黑色像素。每组包含一个彩色像素和紧邻其右侧的一个由同色像素构成的短线段（恰好 2 像素长）。短线段相对于彩色像素的朝向表示条纹方向：向右延伸两格表示水平条纹，向上延伸两格表示垂直条纹，向右上延伸两格表示 45° 右上对角条纹，向右下延伸两格表示 45° 右下对角条纹。
  - 每个封闭区域的标记像素颜色必定在图例条中出现恰好一次。

- `Rule`：
  - 对每个封闭灰色区域，读取其内部标记像素的颜色 C。
  - 在图例条中找到颜色 C 对应的方向指示线段，确定条纹方向 D。
  - 用颜色 C 沿方向 D 在区域内部画等间距条纹：从区域内部左上角像素开始，沿 D 方向每隔一个像素画一个像素（即画一行/列/对角线后跳一行/列/对角线），条纹仅覆盖区域内部的黑色背景像素。
  - 灰色边界像素不变；标记像素若在条纹位置上则被条纹覆盖（颜色相同），若不在则保持原色。
  - 图例条保持不变。

- `Key insight`：
  - 解题需要两层推理：第一层是识别图例条中短线段朝向编码了条纹方向（而非仅仅是颜色标签），第二层是将区域内标记颜色与图例匹配后在正确方向上填充条纹。仅看区域和标记无法推断方向，必须借助图例解码。
</new_puzzle>

- `description`：将网格中散落的同色碎片对沿对称轴折叠合并，并在两片不重合的像素位置标记差异色。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中包含若干对彩色小型不规则碎片。每种非背景颜色（如 red、blue、green 等）恰好出现两个 4-连通分量，即一对碎片。
  - 每对同色碎片分布在对称轴的两侧：若两个碎片上下排列，则对称轴为水平线；若左右排列，则对称轴为垂直线。对称轴始终是两个碎片各自质心连线的正中央所在的行或列（视觉上即两个碎片中间的行或列）。
  - 两个碎片的形状高度相似但不完全相同——各自多出或缺少 1-2 个像素。
  - 网格中有一个 maroon 单像素标记位于网格边缘，不属于任何碎片对。

- `Rule`：
  - 对每对同色碎片：
    1. 确定对称轴（两碎片之间的中间行或列）。
    2. 将两个碎片分别沿对称轴翻折，使它们重合在对称轴位置上。
    3. 两个碎片翻折后都有像素的格子 → 保持该碎片颜色。
    4. 仅一个碎片翻折后有像素的格子（即差异部分）→ 标记为 maroon 色。
  - 折叠后的图案放置在对称轴上，原碎片位置清除为背景色。
  - 边缘的 maroon 标记像素在输出中被清除为背景色。

- `Key insight`：
  - 解题者需要三层推理：（1）发现同色分量的配对关系；（2）发现每对碎片存在近似镜像对称关系并定位对称轴；（3）理解输出中 maroon 像素标记的是"折叠后不重合的差异部分"而非某种独立的标记。
</new_puzzle>

- `description`：根据围栏内部标记点的数量选择对应序号的印章模板，将模板图案印在围栏正下方。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格上半部分包含若干个由蓝色（blue）像素围成的封闭矩形围栏（单像素宽矩形环，内部为黑色）。每个围栏内部散落着若干个绿色（green）单像素标记点（数量从 1 到 N 不等，N 不超过模板数量）。

  - 围栏数量不超过模板数量。

- `Rule`：
  - 对每个蓝色围栏：
    1. 数出围栏内部绿色标记点的数量 K（K >= 1）。

  - 原始围栏、内部绿色标记、模板区和灰色分隔线均保持不变。

- `Key insight`：
  - 第一层推理是发现围栏内部绿色点的数量具有索引意义，而不仅仅是装饰；第二层是发现下方模板区是一个有序图案库，数量索引用于在库中选择特定模板。模板选择机制通过计数映射而非颜色映射实现，更为隐蔽。

- `description`：信号从起点沿灰色通道传播，在每个交叉路口由闸门标记的相对位置决定转弯方向，最终经过的路径被染上信号色。

- `Input structure`：
  - 背景为黑色（black）。
  - 灰色（grey）像素构成若干条单像素宽的水平和垂直通道，通道相互交叉形成网格状通道系统。通道的末端均为死胡同（不连接到网格边缘）。
  - 在某个死胡同端点处有一个彩色像素（颜色为 red、blue 或 green 之一），称为信号源——这是通道系统中唯一的非灰色、非背景像素（除闸门外）。
  - 在若干交叉路口处，紧邻交叉点的四个对角位置（左上、右上、左下、右下）之一放有一个 magenta 单像素作为"闸门"标记。每个有闸门的交叉路口恰好有一个闸门标记。并非所有交叉路口都有闸门。

- `Rule`：
  - 信号从信号源出发，沿灰色通道向唯一可行方向传播。
  - 在无闸门的交叉路口，信号直行（保持原方向）。
  - 在有闸门的交叉路口，根据闸门相对于信号前进方向的位置决定行为：
    - 闸门在前进方向的右前方对角 → 信号右转 90°。
    - 闸门在前进方向的左前方对角 → 信号左转 90°。
    - 闸门在前进方向的右后方或左后方对角 → 信号直行。
  - 信号到达死胡同端点时停止。
  - 输出中，信号实际经过的所有灰色像素替换为信号源的颜色，未经过的灰色像素保持灰色。
  - 信号源像素、magenta 闸门像素和黑色背景均保持不变。

- `Key insight`：
  - 核心难点在于闸门的方向判定是相对于信号传播方向的，而非基于全局坐标——同一个闸门对从不同方向到达的信号会产生不同的转弯指令。解题者需要从多个样例中跟踪信号路径，才能发现这种方向相对性。
</new_puzzle>

- `description`：识别窗框缺口的方向作为图案发射方向，根据窗框内黄色标记点数量决定图案向外复制的次数。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干个由 azure 像素构成的矩形"窗框"。每个窗框是单像素宽的矩形环，且在某一条边（上、下、左或右）上有一个连续缺口。缺口的宽度等于窗框内部在该边方向上的完整跨度（即缺口把那条边完全移除）。
  - 每个窗框内部包含一个由某种颜色（如 red、green、blue 等，各窗框不同）构成的小型图案，占据内部的部分像素。
  - 每个窗框内部还散落着若干个 yellow 单像素标记点（位于内部图案之外的黑色空白像素上），数量在 1 到 4 之间。
  - 不同窗框之间有足够间距。

- `Rule`：
  - 对每个窗框：
    1. 确定缺口所在的边——该边方向即为图案的"发射方向"（缺口在上边则向上发射，缺口在右边则向右发射，依此类推）。
    2. 数出窗框内部 yellow 标记点的数量 N。
    3. 将窗框内部的彩色图案（不含 yellow 标记和 azure 边框）沿发射方向平移复制 N 次。第 k 次复制（k = 1, 2, ..., N）的偏移量为 k 乘以窗框在发射方向上的外部尺寸（包含边框的总宽度或总高度）。
  - 原窗框及其全部内容保持不变。
  - 复制出的图案若部分超出网格边界则截断丢弃超出部分。

- `Key insight`：
  - 解题包含三层非显然推理：（1）缺口方向编码了发射方向——需要发现"缺口 = 出口"的隐喻而非仅仅是形状缺陷；（2）yellow 标记数量编码了复制次数——需要从多个样例中归纳出数量与复制的对应关系；（3）复制间距由窗框自身外部尺寸决定——不是固定间距也不是图案自身尺寸，需要从样例中测量推断。

- `description`：通过边框颜色配对源区域与目标区域，将源区域图案旋转后填入目标区域，旋转角度由连接两区域的折线路径上的拐弯次数决定。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中有若干对矩形区域，每对由相同颜色的单像素宽边框围成（如一对 red 边框、一对 blue 边框等，每种边框颜色恰好出现两个矩形）。每对中的两个矩形大小相同（内部尺寸一致）。
  - 每对中，一个矩形内部包含由 grey 像素构成的非对称图案（源区域），另一个矩形内部为纯黑色背景（目标区域）。
  - 每对矩形之间由一条与边框同色的单像素宽折线路径相连。路径从源矩形边框某个像素出发，仅沿水平或垂直方向延伸，经若干次直角拐弯后到达目标矩形边框某个像素。路径不与任何其他路径或矩形交叉。

- `Rule`：
  - 对每对同色矩形：
    1. 识别哪个是源（内有 grey 图案）、哪个是目标（内部为空）。
    2. 沿连接路径从源到目标行走，数出路径中直角拐弯的次数 T。
    3. 将源区域内部的 grey 图案顺时针旋转 (T mod 4) × 90°（T mod 4 = 0 则不旋转，= 1 则顺时针 90°，= 2 则 180°，= 3 则顺时针 270°）。
    4. 将旋转后的图案以 grey 色填入目标区域内部。
  - 所有边框、路径和源区域图案在输出中保持不变。

- `Key insight`：
  - 第一层推理通过边框颜色实现源-目标配对。第二层核心洞见是连接路径的拐弯次数编码了旋转角度——解题者需要跟踪每条路径、数出拐弯数、并发现拐弯数对 4 取余对应旋转量这一隐藏规律。路径形状看似仅起连接作用，实则携带关键变换参数。
</new_puzzle>

- `description`：在网格中根据种子像素的颜色确定生长规则类型，再根据同色边界墙的形状约束生长范围，最终在墙内区域生成特定的填充图案。

- `Input structure`：
  - 背景为黑色（black）。
  - 网格中包含若干个互不接触的"生长单元"，每个单元由以下部分组成：
    - 一个由某颜色（如 red、blue、green 之一）像素构成的不规则封闭边界墙（单像素宽，4-连通闭合曲线，围成一块区域）。
    - 边界墙内部恰好有一个与墙同色的单像素"种子"。
  - 网格某一角落（如左上角）有一个 3×2 的颜色图例区域，包含三行，每行两个像素：左列分别为 red、blue、green，右列分别为三种不同的 grey/orange/yellow 等颜色，表示对应关系。

- `Rule`：
  - 图例左列颜色对应右列颜色，建立映射：red→X, blue→Y, green→Z（X、Y、Z 为图例右列的具体颜色）。
  - 对每个生长单元：
    1. 确定边界墙和种子的颜色 C，在图例中查找 C 映射的填充颜色 F。
    2. 从种子位置出发，用颜色 F 做 4-连通洪水填充，填充区域不越过边界墙。
    3. 但填充并非覆盖所有内部像素——而是按棋盘格模式填充：以种子位置为基准，仅填充与种子位置"行+列奇偶性相同"的格子（即种子行+列为偶数，则填所有行+列为偶数的内部格子）。
  - 边界墙和种子像素保持原色不变。
  - 图例区域保持不变。

- `Key insight`：
  - 第一层推理是理解角落图例建立了墙颜色到填充颜色的映射。第二层是发现填充并非完全填满，而是按棋盘格间隔填充——种子位置确定了棋盘格的相位。两层规则叠加使得仅从一两个样例难以分离出各自的作用。
</new_puzzle>
