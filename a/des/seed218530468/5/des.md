将网格中散落的彩色碎片按形状匹配填入对应框架的缺口中，填入时需根据框架边框颜色对碎片进行旋转。

Input structure：
- 背景为主色调。网格中分布着若干由单一非背景色绘制的矩形框架（一像素宽边框，内部为背景色），每个框架的边框上恰好有一个缺口（连续缺失 2-4 个边框像素）。
- 网格中还散落着若干彩色碎片（每个碎片是一个 4-连通的小形状，颜色与所有框架边框颜色均不同）。
- 每个碎片的形状恰好与某一个框架缺口的形状吻合（像素数相同、可通过 0/90/180/270 度旋转后完美嵌入缺口）。
- 框架使用四种不同颜色：red、blue、green、yellow，分别对应旋转 0 度、90 度、180 度、270 度。

Rule：
- 对每个框架，找到与其缺口形状匹配的碎片。
- 根据框架边框颜色确定旋转角度（red=0 度、blue=90 度顺时针、green=180 度、yellow=270 度顺时针），将碎片旋转后放入缺口位置。
- 碎片放入后保持碎片自身的原始颜色。
- 原碎片位置擦除为背景色。

Key insight：框架的边框颜色不仅用于视觉区分，还隐含编码了碎片填入前需要执行的旋转角度；解题者需要先发现颜色-旋转的映射关系，再通过形状匹配找到碎片与缺口的对应。
</new_puzzle>

<new_puzzle>
根据种子像素的颜色在封闭区域内生长出与该区域边界形状相似的缩小版轮廓。

Input structure：
- 背景为主色调。网格中有若干由同一颜色（如 grey）绘制的封闭轮廓（一像素宽，形成闭合多边形，内部为背景色）。
- 每个封闭轮廓内部恰好有一个非背景、非轮廓色的单像素"种子"。
- 种子有两种可能的颜色：red 或 blue。

Rule：
- 对每个封闭轮廓，计算其内部区域（不含轮廓线本身）。
- 如果种子颜色为 red：在轮廓内部绘制一圈向内收缩一像素的同形轮廓（即原轮廓每个像素向内移动一格后的位置），用 red 绘制。
- 如果种子颜色为 blue：在轮廓内部绘制向内收缩两像素的同形轮廓，用 blue 绘制。
- 收缩轮廓仅保留与原轮廓拓扑一致的像素（若收缩后某段消失则不绘制）。
- 种子像素本身在输出中擦除为背景色。原始 grey 轮廓保持不变。

Key insight：种子的颜色决定了收缩的层数（red=1层、blue=2层），解题者需要先归纳出颜色与收缩深度的对应关系，再理解"收缩轮廓"是将边界整体向内侵蚀指定步数后的结果。
</new_puzzle>

将网格中的彩色条带按照隐含的编织规则交错叠放，根据条带的宽度决定上下遮挡顺序。

Input structure：
- 背景为主色调。网格中有若干水平条带和若干垂直条带，每条条带是一像素或两像素宽的直线段，各有不同颜色。
- 水平条带和垂直条带会在网格上产生交叉区域。
- 在输入中，所有交叉点处的像素统一显示为背景色（即交叉处被"挖空"了）。

Rule：
- 将所有条带视为编织中的经纬线。
- 在每个交叉点处，比较水平条带与垂直条带的宽度（像素数）：较宽的条带覆盖在上方（即该交叉区域填充较宽条带的颜色）。
- 若两条带宽度相同，则水平条带在上（填充水平条带颜色）。
- 输出时所有交叉区域不再为空，而是填入了由上述规则决定的颜色。非交叉区域保持不变。

Key insight：输入中交叉处的空白是有意留出的待决区域；解题者需要发现条带宽度决定叠放优先级这一隐含规则，而非简单地按颜色或位置填充。
</new_puzzle>

在网格中找到所有箭头形状，沿箭头指向方向发射射线，射线末端根据箭头尾部长度复制目标图案。

Input structure：
- 背景为主色调。网格中分布着若干"箭头"对象和若干"图案块"对象。
- 每个箭头由两部分组成：一个三角形箭头尖（3 像素组成的直角三角形，开口朝四个正方向之一）和一条从箭头尖底边反向延伸的单像素宽尾巴（长度 1-4 像素）。箭头整体使用同一颜色。
- 图案块是 3x3 的彩色方块（可以包含多种颜色），散布在网格中。
- 每个箭头沿其指向方向上恰好存在一个图案块（箭头尖与图案块之间可能有任意距离的背景像素）。

Rule：
- 对每个箭头，确定其指向方向和尾巴长度 L。
- 从箭头尖端沿指向方向前进，找到第一个图案块。
- 在该图案块的正后方（沿箭头指向方向继续前进，紧贴图案块的远端），按箭头指向方向连续复制该图案块 L 次（L 等于箭头尾巴的像素数量）。
- 箭头本身在输出中擦除为背景色。图案块原件保留。

Key insight：箭头的尾巴长度编码了复制次数，箭头的朝向决定了操作方向；解题者需要先识别箭头结构并区分箭头尖和尾巴，再发现尾巴长度与复制次数的对应关系。
</new_puzzle>

将散布在网格中的彩色像素对按照连线方向归类，然后用各类别对应的图例颜色重绘连线。

Input structure：
- 背景为主色调。网格左侧有一列"方向图例"：图例区占据最左边两列，每个图例条目由两个相邻的同色像素组成，条目之间至少隔一行背景。水平相邻的两像素表示"水平方向"，垂直相邻的两像素表示"垂直方向"，对角相邻的两像素表示"对角方向"。不同条目的颜色各不相同。
- 网格右侧主区域中散布着若干成对的同色像素点。每对像素点之间可以用一条沿水平、垂直或 45 度对角的直线段连接（两点恰好在同一行、同一列、或同一条 45 度对角线上）。
- 每对像素点的连线方向（水平/垂直/对角）恰好对应图例中某一条目的方向类型。

Rule：
- 读取左侧图例，建立"方向类型→图例颜色"的映射：水平相邻的两像素表示水平方向，垂直相邻的表示垂直方向，对角相邻的表示对角方向。
- 对主区域中每对同色像素点，判断它们之间的连线方向（水平、垂直或对角）。
- 用该方向在图例中对应的颜色，绘制连接这两个像素点的直线段（包含两端点，中间所有格子填入图例颜色）。
- 原像素对本身也被重绘为图例颜色。左侧图例区保持不变。

Key insight：左侧图例不是简单的颜色标签，而是通过两个像素的空间排列方式编码了"方向"信息；解题者需先破译图例的方向编码，再将其应用到主区域的像素对连线上。
</new_puzzle>

<new_puzzle>
网格中的封闭房间通过门洞相连，根据房间内标记像素的数量是否相等决定门洞的开关状态。

Input structure：
- 背景为主色调。网格由 grey 颜色的墙壁线条分隔成若干封闭"房间"（矩形区域）。
- 相邻房间之间的墙壁上有恰好两像素宽的缺口作为"门洞"，门洞处当前为背景色（即门是打开的）。
- 每个房间内部可能有零个或若干个 maroon 色标记像素（散布在房间内任意位置）。

Rule：
- 对每个门洞，确定它连接的两个房间。
- 统计两个房间各自的 maroon 标记像素数量。
- 若两个房间的标记数量相同（包括都为零），则关闭门洞：将门洞的两个像素填充为 grey（与墙壁同色）。
- 若两个房间的标记数量不同，则门洞保持打开：保留为背景色。
- 所有 maroon 标记像素在输出中擦除为背景色。墙壁和房间结构其余部分不变。

Key insight：标记像素的数量不是直接用于数值计算，而是作为房间的"身份标签"——数量相同意味着两个房间"等价"，门就关闭；解题者需要发现"相同计数→关门、不同计数→开门"这一反直觉的规则，而标记的消失暗示它们只是线索而非输出的一部分。
</new_puzzle>

<new_puzzle>
在网格中识别由边框颜色编码的容器嵌套层级，将最内层容器的内容物逐层向外迁移，每穿越一层边框内容物颜色就变为该层边框色。

Input structure：
- 背景为主色调。网格中有若干嵌套的矩形"容器"，每个容器是一像素宽的彩色矩形边框。
- 容器可以嵌套：一个容器完全位于另一个容器内部。最多三层嵌套。同一嵌套组中各层边框颜色互不相同。
- 最内层容器的内部有若干散布的彩色像素作为"内容物"，内容物颜色与所有容器边框颜色均不同。
- 每个嵌套组中，外层容器内部（但在内层容器外部的区域）为背景色。

Rule：
- 识别所有嵌套组。对于每个嵌套组，找到最内层容器及其内容物像素。
- 将内容物像素从最内层容器中移除（擦除为背景），然后在次外层容器的内部空白区域（内层容器外、次外层容器内）以相同的相对位置模式放置这些像素，但颜色更改为次外层容器的边框颜色。相对位置以所在区域的左上角为锚点。
- 如果存在第三层（最外层），则将次外层区域中刚放置的像素再次向外迁移到最外层区域，颜色更改为最外层容器的边框颜色。
- 所有容器边框保持不变。

Key insight：容器的嵌套层级决定了内容物的迁移路径，每次穿越一层容器边界时内容物就"染上"该层边框的颜色；解题者需要先识别嵌套结构，再发现颜色随层级变化的规律，最后理解位置映射的锚点机制。
</new_puzzle>
