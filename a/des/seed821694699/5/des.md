<description>
根据框架内部的分隔墙颜色，从外部同色精灵库中选取对应精灵，按墙的朝向将精灵旋转后填入墙两侧的空腔。

Input structure:
- bg = 最常见颜色。网格中央有一个由 Grey 像素构成的矩形框架，框架内部被若干条彩色直线墙（水平或垂直，各墙颜色不同）分隔成多个矩形空腔。每条彩色墙将框架内部局部地一分为二。
- 框架外部散布着若干小型彩色精灵（connected component），每个精灵的颜色与框架内某条分隔墙的颜色相同。每种墙颜色恰好对应外部两个同色精灵。

Rule:
- 对框架内每条彩色分隔墙，在外部找到与之同色的两个精灵。
- 判断该墙的朝向：若墙是水平线段，则墙将局部区域分为上下两个空腔；若墙是垂直线段，则分为左右两个空腔。
- 两个同色精灵中，面积较大的填入墙的第一侧空腔（水平墙的上方或垂直墙的左方），面积较小的填入第二侧空腔（水平墙的下方或垂直墙的右方）。
- 填入时，精灵需要旋转以使其最长轴与墙平行。具体地：若墙为水平方向，精灵旋转至其 bounding box 宽度 ≥ 高度；若墙为垂直方向，旋转至高度 ≥ 宽度。旋转只使用 0° 或 90° 顺时针。
- 精灵放置位置：紧贴墙的对应侧，水平居中（或垂直居中）于该空腔内。
- 输出为整个框架的 bounding box 区域，包含框架、墙和填入的精灵，外部精灵被移除。

Key insight: 分隔墙的颜色是索引键，其朝向同时决定了精灵的旋转方式和填入侧；面积大小决定了哪个精灵进哪一侧——这构成两层独立的匹配推理。
</description>

<description>
将网格中散落的彩色"种子"像素沿其所在的彩色通道（corridor）生长为与通道同宽的色带，色带长度等于该通道内同色种子的数量。

Input structure:
- bg = Black。网格上有若干条由 Grey 像素构成的直线通道（水平或垂直），每条通道宽度为 1-3 个像素，长度不等。
- 每条通道内散布着若干单像素的彩色种子（非 Grey、非 Black），同一通道内可能有多种颜色的种子。
- 通道的一端有一个 Azure 像素标记，表示生长方向的起点端。

Rule:
- 对每条通道，找出其中所有种子，按颜色分组。
- 对每种颜色，计算该颜色在此通道内的种子数量 N。
- 从 Azure 标记端开始，沿通道方向依次绘制色带。色带的排列顺序按该颜色第一个种子距 Azure 标记的距离从近到远排序。
- 每条色带的长度为 N 个像素（沿通道方向），宽度等于通道宽度，颜色为对应的种子颜色。相邻色带紧密衔接，无间隔。
- 原有种子像素和 Azure 标记在输出中被色带覆盖或保留为通道灰色（未被色带覆盖的通道部分保持 Grey）。

Key insight: 种子的数量编码了色带的长度，种子的空间分布顺序编码了色带的排列次序——解题者必须先发现"计数→长度"的映射，再发现"首个种子位置→排列序"的规则，形成两层推理。
</description>

<description>
在网格中找到多个带缺口的彩色环形边框，根据缺口朝向将环内图案沿缺口方向"倒出"并平铺到环外，同时环内被清空。

Input structure:
- bg = Black。网格中有若干个由不同颜色构成的矩形空心边框（1 像素厚），每个边框恰好在一条边上有一个连续缺口（缺口宽度 ≥ 2 像素）。
- 每个边框内部包含一个由多种颜色组成的小图案（connected region），图案不接触边框。
- 边框外部、缺口延伸方向上是空的 bg 区域。

Rule:
- 对每个边框，确定缺口所在的边（上、下、左、右）。
- 将边框内部的图案视为一个整体，沿缺口方向平移"倒出"：图案从原位出发，沿缺口方向移动，直到图案的整体 bounding box 完全位于边框外部。具体移动距离 = 图案在移动方向上的尺寸 + 图案到缺口边的距离 + 1。
- 图案倒出后，边框内部全部变为 bg。边框本身保持不变（缺口仍然存在）。
- 若图案倒出后的区域与其他边框重叠，则图案像素覆盖边框像素。

Key insight: 缺口方向决定了图案的移动轴向，但移动距离必须由图案与缺口边的相对位置推算——解题者需要先识别缺口位置（第一层），再推断"完全倒出"的精确偏移量（第二层）。
</description>

<description>
将网格中的彩色路径段按照路口处的"信号灯"颜色进行接续拼接，信号灯的颜色指示下一段路径应取哪个颜色的段来衔接。

Input structure:
- bg = Black。网格中有若干条由不同颜色绘制的 1 像素宽的水平或垂直路径段（例如 Red 段、Blue 段、Green 段等），每段为一条直线。
- 路径段的端点处，相邻像素（4-邻域中不在该段上的像素）可能有一个"信号灯"像素：一个与任何路径段颜色都不同的单独颜色像素（Maroon 或 Orange）。
- 网格角落有一个 2x2 的图例区：两行，每行为一个信号灯颜色像素 + 一个路径颜色像素，表示"看到此信号灯颜色 → 下一段应为此路径颜色"。
- 有一条路径段的某个端点标记有 Yellow 像素，表示链的起点。

Rule:
- 从 Yellow 标记的起点路径段开始，沿该段到达其另一端点。
- 在端点处找到信号灯像素，查图例得到下一段路径的颜色 C。
- 在当前端点的 4-邻域（排除已走过的段）中找到颜色为 C 的路径段的端点，将这两个端点之间的 bg 像素填充为 Grey，形成连接桥。
- 沿颜色 C 的路径段继续行进到其另一端点，重复上述过程。
- 当端点处无信号灯或无可连接的路径段时，链终止。
- 输出中，所有被链连接的路径段保持原色，连接桥为 Grey，图例区域清除为 bg，未被链接的路径段也清除为 bg。

Key insight: 图例建立了"信号灯→路径颜色"的间接映射，解题者必须先破译图例的编码方式（第一层），再利用信号灯在路口处进行路径选择和接续（第二层），最后判断哪些段被保留、哪些被移除（第三层）。
</description>

<description>
在网格中，每个彩色区域根据其相邻区域的数量生成对应层数的同心收缩边框，边框颜色取自相邻区域的颜色，层序由相邻区域的面积从大到小决定。

Input structure:
- bg = Black。网格被若干条 Grey 分隔线划分为多个不规则但互不重叠的矩形区域。
- 每个矩形区域内部填充有单一颜色（非 Black、非 Grey），不同区域可以是不同颜色，也可能有相同颜色。
- 两个区域"相邻"定义为它们之间仅隔一条 Grey 分隔线（即分隔线两侧各属一个区域）。

Rule:
- 对每个区域 R，找出所有与 R 相邻的区域，记为邻居列表。
- 将邻居按面积从大到小排序（面积相同则按颜色在 Red、Blue、Green、Yellow、Magenta、Orange、Azure、Maroon 中的顺序排列）。
- 在区域 R 的内部，从外向内逐层绘制 1 像素厚的矩形边框环：第 1 层（最外层）使用面积最大的邻居的颜色，第 2 层使用面积第二大的邻居的颜色，依此类推。
- 绘制的层数等于邻居的数量。若区域太小无法容纳所有层，则只绘制能容纳的层数（从外到内优先）。
- 最内层剩余的像素保持区域的原始填充色。
- Grey 分隔线在输出中保持不变。

Key insight: 解题者需要三步推理——首先识别区域的邻接关系图（第一层），然后发现邻居面积决定边框颜色的排列顺序（第二层），最后理解同心收缩的几何生成方式（第三层）。面积排序是非显然的，因为需要目测比较不同区域的大小。
</description>

<new_puzzle>
<description>
网格中的多个小型模板图案各自缺少若干像素，通过与网格边缘的彩色刻度尺交叉定位来确定缺失像素的颜色，然后补全每个模板。

Input structure:
- bg = Black。网格的顶部边缘有一行彩色"列刻度"像素，底部边缘也有一行；左侧边缘有一列彩色"行刻度"像素，右侧也有一列。这些刻度像素颜色各异，标记了对应的行或列。
- 网格内部散布着若干个 3x3 或 4x4 的小型图案。每个图案大部分像素已填充颜色，但有 1-3 个像素位置为 bg（即缺失）。
- 所有图案是同一个"原型模板"的副本，但被放置在网格的不同位置，且各自缺失了不同的像素。

Rule:
- 对每个图案中每个缺失（bg）像素，找到该像素所在的全局行和全局列。
- 查看该行对应的行刻度颜色（左侧或右侧边缘的刻度像素——两侧标注相同行时颜色一致）以及该列对应的列刻度颜色（顶部或底部边缘的刻度像素）。
- 若行刻度颜色与列刻度颜色相同，则该缺失像素填入此颜色。
- 若行刻度颜色与列刻度颜色不同，则该缺失像素填入的颜色为：在该图案中已存在的像素里，与行刻度或列刻度颜色相同的那个颜色。若两个都存在于图案中，则取行刻度颜色。
- 补全所有图案后，刻度尺保持不变。

Key insight: 解题者需要先发现边缘刻度尺的索引机制（第一层），再发现行列刻度交叉决定颜色的规则（第二层），最后处理行列颜色冲突时需要参考图案自身已有颜色来消歧（第三层）。刻度尺的存在并不明显——它们看起来只是边缘装饰。
</description>

<new_puzzle>
<description>
将散布在网格中的彩色箭头按照"箭头链"的方式依次连接：每个箭头指向下一个箭头的位置，链中前一个箭头的颜色决定后一个箭头射出的光线颜色，光线沿指向方向延伸直到碰到障碍或边界。

Input structure:
- bg = 最常见颜色（Azure）。网格中散布着若干个由 3x3 像素组成的箭头符号，每个箭头由一种颜色绘制。箭头的绘制方式：中心像素 + 指向方向的 1 个像素 + 垂直于指向方向的 2 个像素构成箭尾（形成 T 字形，T 的竖笔指向方向即为箭头方向）。每个箭头指向四个基本方向之一（上、下、左、右）。
- 网格中还有若干 Grey 的 1x1 障碍像素。
- 恰好有一个箭头的尾部（T 字横笔的中心外侧一格）处有一个 Yellow 标记像素，表示链的起始箭头。

Rule:
- 从 Yellow 标记的起始箭头开始。
- 从当前箭头的尖端沿其指向方向寻找，找到的第一个箭头（按指向方向的直线扫描，箭头的任意像素在扫描线上即算命中）就是链中的下一个箭头。
- 在当前箭头的尖端到下一个箭头之间的 bg 像素上绘制光线，光线颜色 = 当前箭头的颜色。
- 移动到下一个箭头，重复上述过程。
- 当箭头指向方向上没有其他箭头（扫描到边界或只遇到障碍）时，光线从尖端延伸到边界或障碍处停止，链终止。
- 输出中所有箭头保持原样，新增光线，Grey 障碍保持不变，Yellow 标记保持不变。

Key insight: 解题者首先要识别箭头的形状编码（T 字形）和朝向（第一层），然后发现箭头之间通过指向方向形成链式连接关系（第二层），最后发现光线颜色取自发射箭头而非目标箭头的颜色（第三层）。链的顺序完全由空间指向关系决定，而非颜色匹配。
</description>
</new_puzzle>
