- `description`：根据彩色锚点之间的连线方向，选择对应的模板图章，将其旋转至连线方向后印在连线中点处，模板颜色由锚点颜色的配对决定。

- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中散布着若干成对的小型彩色像素点（锚点），每对锚点颜色相同，且每种非黑非灰颜色恰好出现两个锚点。
  - 网格的一个角落区域（例如左下角）放置着若干灰色（Grey）小型图章模板（3×3 或 5×5 的形状），这些模板彼此用黑色间隔隔开，按从左到右的顺序排列。
  - 每个模板内部中心有一个单像素的颜色标记，标记颜色各不相同。

- `Rule`：
  - 第一层：确定锚点配对与连线方向。将同色锚点两两配对。计算每对锚点之间的主方向：若水平距离 ≥ 垂直距离，方向为水平（左右）；否则方向为垂直（上下）。若水平距离等于垂直距离，方向为从左上到右下的对角线。
  - 第二层：匹配模板。灰色模板按照从左到右的排列顺序，依次对应锚点对按其中心行坐标从小到大的排序。即第一个模板对应中心行最小的锚点对，第二个模板对应中心行次小的锚点对，以此类推。
  - 第三层：旋转与放置。根据锚点对的连线方向旋转模板：水平方向保持原样（0°），垂直方向旋转 90°，对角线方向旋转 45°（仅限正交情况下实际只有 0° 和 90° 两种旋转）。将旋转后的模板以两个锚点的中点为中心印到网格上，模板中灰色像素重绘为该锚点对的颜色。
  - 移除角落区域的所有原始模板。保留锚点。

- `Key insight`：模板与锚点对的匹配不是通过颜色，而是通过空间排序——模板的排列顺序对应锚点对按行坐标的排序。解题者需要先发现这一隐含的顺序映射关系，再根据方向旋转模板并放置到正确位置。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的彩色碎片按形状互补性拼合成完整矩形，然后根据拼合后每块碎片所在的象限，用象限对应的边框颜色重绘碎片内部。

- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中有若干彩色碎片（每块碎片为单一非黑颜色，形状不规则但各碎片面积相同）。
  - 网格的某一行存在一条完整的红色（Red）水平分隔线，某一列存在一条完整的蓝色（Blue）垂直分隔线，两条线将网格划分为四个象限。
  - 每个象限的交界角落处（紧邻分隔线的四个角格）各有一个单像素的不同颜色标记（例如：左上角为绿色 Green，右上角为黄色 Yellow，左下角为橙色 Orange，右下角为紫色 Magenta）。

- `Rule`：
  - 第一层：识别互补碎片对。每两块碎片恰好能拼成一个无间隙、无重叠的矩形。判断方法：将一块碎片在其最小外接矩形中取反（碎片占据的位置变为空，空位变为占据），得到的形状与另一块碎片完全吻合（可能需要平移但不旋转不翻转）。
  - 第二层：确定拼合位置。每对互补碎片拼合后形成的矩形放置在两块碎片各自外接矩形中心的中点位置（取整）。
  - 第三层：重绘颜色。拼合后，查看每块碎片在矩形中的重心落在四个象限中的哪一个（以红蓝分隔线为界），将该碎片的所有像素重绘为对应象限角落标记的颜色。
  - 移除分隔线和角落标记。输出仅包含重绘后的拼合矩形，背景为黑色。

- `Key insight`：碎片的配对关系由形状互补性决定——一块碎片的外接矩形"空缺"恰好是另一块碎片的形状。解题者需要先识别这种负空间匹配，再利用象限划分来确定最终颜色。
</new_puzzle>

<new_puzzle>
- `description`：在被彩色围墙围起的房间中，根据房间内"窗户"（墙上缺口）的朝向组合来选择填充图案，图案取自网格边缘的图案库。

- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中有若干由灰色（Grey）像素围成的封闭矩形"房间"，每个房间的四面墙壁上可能有一个或多个单像素宽的缺口（"窗户"），缺口处为黑色。
  - 每个房间的内部（灰色围墙以内）全部为黑色，面积为 3×3 到 6×6 不等。
  - 网格的最下方一行以下，紧贴底部边缘排列着若干小型彩色图案样本（每个图案用不同的非黑非灰颜色绘制，图案之间用黑色列间隔）。每个图案样本正上方有一组由 Azure 色小点组成的方向指示符，指示符分布在图案上方的上、下、左、右四个位置中的若干个，表示该图案对应哪些窗户朝向。

- `Rule`：
  - 第一层：识别每个房间的窗户朝向集合。扫描每个房间的四面灰色墙壁，记录缺口所在的方向（上、下、左、右）。例如一个房间在上墙和左墙各有一个缺口，则其朝向集合为 {上, 左}。
  - 第二层：匹配图案。将每个房间的窗户朝向集合与底部图案库中每个图案的方向指示符进行匹配——朝向集合完全相同的图案即为该房间应填充的图案。
  - 第三层：缩放填充。将匹配到的图案等比缩放到房间内部的尺寸（房间内部即灰色墙壁以内的矩形区域），然后填入房间内部。缩放方式为最近邻缩放（每个输出像素取对应源像素的颜色）。
  - 灰色墙壁和窗户缺口保持不变。

- `Key insight`：房间的"身份"不由颜色或位置决定，而由墙壁上缺口的方向组合编码。解题者必须先发现窗户朝向是查找键，再将其与图案库中的方向指示符匹配，最后将图案缩放填入房间。
</new_puzzle>

- `description`：沿着彩色路径追踪箭头指向，在每个路径交叉口根据交叉口中心颜色选择转向方向，最终在路径终点放置起点处携带的标记色块。

- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中有若干条由不同颜色绘制的单像素宽直线路径（水平或垂直），路径之间存在交叉点。每个交叉点的中心像素为特定颜色（与交叉的两条路径颜色都不同）。
  - 每条路径的一端有一个 2×2 的彩色方块（"货物"），方块颜色与路径颜色不同。路径的另一端为一个单像素的 Maroon 色终止标记。
  - 在网格某个角落有一个颜色图例区：若干行，每行包含一个交叉点颜色的色块和紧邻其右侧的一个箭头符号（由 3 个同色像素组成的 L 形，指向上、下、左或右之一）。

- `Rule`：
  - 第一层：确定路径起点。每条路径的起点是带有 2×2 货物方块的那一端。
  - 第二层：沿路径追踪并在交叉口转向。从起点沿路径前进。到达交叉口时，读取交叉口中心像素的颜色，在图例区查找该颜色对应的箭头方向，按该方向转向继续前进（转向后沿新路径行走）。若路径上有多个交叉口，则每次都查表转向。
  - 第三层：放置货物。当追踪到达 Maroon 终止标记时，将起点处的 2×2 货物方块搬移到终止标记所在位置（以终止标记为左上角放置）。移除原始起点处的货物方块。
  - 所有路径、交叉口和图例区保持不变。

- `Key insight`：解题者需要理解路径追踪是一个多步导航过程——交叉口颜色不是装饰而是转向指令的编码。图例区将颜色翻译为方向，形成"颜色→方向"的间接寻址机制。整个过程需要先建立查找表，再逐步模拟路径行走。

<new_puzzle>
- `description`：根据种子像素的颜色确定生长规则，让种子在约束区域内按规则扩展填充，不同种子的生长区域相遇时，由边界仲裁色块决定哪一方覆盖另一方。

- `Input structure`：
  - 背景为黑色（Black）。
  - 网格中有若干灰色（Grey）像素组成的不规则封闭区域（连通的灰色区域，内部全为灰色）。
  - 每个灰色区域内部散布着一到两个单像素的彩色"种子"（非黑非灰颜色），种子颜色在同一区域内各不相同。
  - 在两个相邻灰色区域的公共边界上（灰色区域之间共享的灰色像素段），有一个单像素的彩色"仲裁标记"，其颜色与某个种子颜色相同。

- `Rule`：
  - 第一层：种子生长方向由颜色决定。网格的四个角落各有一个单像素颜色标记，分别对应上、下、左、右四个生长方向：左上角标记→向右生长，右上角标记→向下生长，右下角标记→向左生长，左下角标记→向上生长。每个种子查找与自己颜色相同的角落标记，从而确定自己的生长方向。
  - 第二层：执行生长。每个种子沿其生长方向逐像素扩展，将经过的灰色像素重绘为种子颜色，直到遇到黑色边界（区域边缘）或遇到已被其他种子颜色占据的像素为止。生长仅沿单一方向进行（不扩散到侧向），形成一条与生长方向平行的彩色条带，条带宽度为 1 像素。
  - 第三层：跨区域仲裁。当同一区域内有两个种子，或两个相邻区域的种子生长到公共边界时，仲裁标记决定优先权——仲裁标记颜色对应的种子可以继续穿过边界进入相邻区域继续生长，另一个种子在边界处停止。仲裁标记本身被优先种子的颜色覆盖。
  - 角落的方向标记在输出中保留不变。

- `Key insight`：种子的生长方向不是由其位置或周围结构决定的，而是通过颜色与角落标记的匹配来间接编码。解题者需要先破解"角落颜色 = 方向"的映射，再理解生长机制，最后发现仲裁标记的裁决作用——这三层推理缺一不可。
</new_puzzle>
