<description>
根据边框精灵的缺口方向在色彩映射表中查找对应颜色，再用该颜色填充精灵内部与缺口方向垂直的条纹图案。

Input structure:
- 黑色背景。网格边缘有一个小型映射表，由若干 1x2 的色块对组成，排列成一列：每对中左侧色块为方向编码色（red、blue、green、yellow 分别代表上、右、下、左四个方向），右侧色块为填充色。
- 网格内散布若干 5x5 的中空矩形边框精灵，每个边框精灵由同一种非黑色绘制，且恰好在某一条边的中央位置有一个 1 像素宽的缺口（即该边中间一个像素为黑色背景）。
- 每个精灵的边框颜色各不相同，但缺口方向只有上、右、下、左四种。

Rule:
- 第一步：识别每个边框精灵的缺口方向（上/右/下/左）。
- 第二步：将缺口方向映射为方向编码色（上=red，右=blue，下=green，左=yellow），在映射表中查找该方向编码色对应的填充色。
- 第三步：用查到的填充色在精灵的 3x3 内部区域绘制与缺口方向垂直的条纹。具体而言：若缺口在上或下（垂直方向），则绘制水平条纹（填充内部第 1 行和第 3 行）；若缺口在左或右（水平方向），则绘制垂直条纹（填充内部第 1 列和第 3 列）。内部未填充的像素保持黑色。
- 边框本身及缺口保持不变。

Key insight: 解题者需要先发现缺口方向与映射表中方向编码色的对应关系（这一层并非肉眼直接可见，需要通过多个样例归纳），再利用映射表查到填充色，最后理解条纹方向与缺口方向的垂直关系——三层推理环环相扣。
</description>

<description>
将网格中的彩色路径段按颜色归组，找到每组路径的两个端点，然后在端点之间沿路径的延伸方向生长出与路径段总像素数等长的新射线。

Input structure:
- 灰色（grey）背景。网格中有若干条由不同颜色绘制的路径段，每条路径段为连续的水平或垂直直线，长度为 2 到 5 个像素。
- 同一颜色的路径段恰好有 2 条，它们不相连，分散在网格的不同位置。
- 网格中还散布有若干单独的 maroon 像素作为障碍物。

Rule:
- 第一步：将同颜色的两条路径段配对。
- 第二步：对于每对路径段，分别确定每条段的"朝向"——即该段作为直线的延伸方向（水平段有左和右两个延伸方向，垂直段有上和下两个延伸方向）。选取两条段中"面朝对方"的那个端点作为生长起点，生长方向为从段身指向该端点的方向。具体地说：取两条段各自离对方更近的那一端，从该端沿着段本身延伸的方向（即远离段身、朝向对方的方向）生长射线。
- 第三步：从生长起点沿生长方向逐格绘制该颜色的像素，射线长度等于该颜色路径段的总像素数（两条段的像素数之和）。射线在遇到网格边界或 maroon 障碍物时提前停止。
- 原有的路径段保持不变，射线从端点的下一格开始绘制。

Key insight: 解题者需要同时归纳两个非显然规则——射线的生长方向由同色路径段之间的空间关系决定（面朝对方的端点），而射线长度由同色像素的总数决定——两者缺一不可才能完全确定输出。
</description>

<description>
网格被十字线分为四个象限，每个象限有独立背景色；含形状的象限与含锚点的象限按背景色配对，将形状重着色为来源象限背景色后盖印到锚点位置。

Input structure:
- 黑色背景。网格被 orange 色的十字线（一条水平线和一条垂直线贯穿整个网格）分割为四个象限。
- 每个象限有自己的背景色（从 azure、green、magenta、yellow 中选取，四个象限各不相同，但恰好有两对背景色相同的象限）。
- 恰好有两个象限各含一个由非背景、非 orange 颜色绘制的小型形状（3x3 到 5x5 大小的任意连通形状）。
- 另外两个象限各有一个单像素的 maroon 锚点标记，其余区域为该象限的纯背景色。
- 含形状的象限和含锚点的象限通过背景色配对：背景色相同的两个象限为一对。

Rule:
- 第一步：识别四个象限各自的背景色，将背景色相同的象限配对。每对中一个含形状，一个含锚点。
- 第二步：从含形状的象限提取形状的相对像素坐标（以形状左上角为原点）。
- 第三步：将形状重新着色为其所在象限的背景色。
- 第四步：在配对象限中，以 maroon 锚点为左上角，将重着色后的形状绘制出来。绘制后移除 maroon 锚点像素（锚点位置被形状像素覆盖）。
- orange 十字线保持不变。

Key insight: 解题者需要先发现象限配对机制是基于背景色匹配（而非位置对称性），再理解形状被重着色为来源象限的背景色（而非保留原色或使用目标象限的背景色），这两层规则都需要从样例中归纳发现。
</description>

<description>
网格中的闭合矩形环内部含有若干种子像素，种子数量决定环向内收缩的层数，收缩层与原始环交替着色形成同心环带。

Input structure:
- 黑色背景。网格中有若干个由不同颜色绘制的闭合矩形环形轮廓（中空矩形边框），每个环由单一颜色绘制，环的大小从 7x7 到 13x13 不等。
- 每个环的内部（黑色区域）散布有 1 到 3 个 red 像素作为"种子像素"。
- 环与环之间不重叠、不相邻。

Rule:
- 第一步：对每个环，数出其内部 red 种子像素的数量 N。
- 第二步：从该环的轮廓开始，向内收缩 N 层。每一层收缩生成一个比上一层每边各缩 1 像素（整体小 2）的同心矩形环。若收缩到内部剩余空间宽或高不足 3 时停止（即无法再画出新的环）。
- 第三步：为收缩产生的各层着色——原始最外层环保持原色，第 1 层收缩环使用 grey 色，第 2 层收缩环使用原色，第 3 层使用 grey，依此交替。
- 第四步：移除所有 red 种子像素（种子位置变为黑色，除非被新生成的收缩环覆盖）。

Key insight: 种子像素的数量不是简单的填充指令，而是控制收缩的层数——解题者需要先发现"数种子"与"收缩层数"之间的对应关系，再发现交替着色的模式，两层规则都需要跨样例比对才能归纳。
</description>

<description>
网格角落的图例展示标准 L 形经各种几何变换后的结果，解题者须从图例反推每种颜色编码的变换类型，再对网格中箭头所指向的灰色形状执行对应变换。

Input structure:
- Azure 背景。网格中有若干个由 grey 绘制的小型非对称连通形状（3x3 到 5x5），彼此不相邻。
- 每个 grey 形状的某一侧（上、下、左或右）隔一格的位置有一个由 3 个同色像素组成的箭头标记。箭头由一个"尖端"像素和两个"尾翼"像素组成：尾翼在垂直于指向方向的轴上分列尖端两侧，且比尖端后退一格（即尖端比尾翼更靠近目标形状）。箭头指向方向为从尾翼朝向尖端的方向，该方向同时指向相邻的 grey 形状。
- 箭头颜色从以下四种中选取：red、blue、green、yellow。
- 网格左上角有一个黑色背景的 4x8 图例区域。图例共 4 行，每行展示：左侧一个颜色像素（red/blue/green/yellow 之一），右侧紧跟一个 3x3 区域显示标准 L 形（原始 L 形为：第一行左两格填充、第二行仅左一格填充）经过该颜色对应变换后的结果。四种变换为顺时针旋转 90 度、逆时针旋转 90 度、水平翻转、旋转 180 度（但颜色与变换的对应关系每道题可能不同，需从图例归纳）。

Rule:
- 第一步：读取角落图例，观察标准 L 形在每种颜色对应下变成了什么形状，反推出每种颜色代表的几何变换类型。
- 第二步：对每个箭头，确定它指向的 grey 形状。
- 第三步：提取该 grey 形状的像素图案，以形状包围盒的中心为旋转/翻转中心，执行箭头颜色对应的变换。
- 第四步：将变换后的形状放回原位置（包围盒中心不变），仍用 grey 绘制。移除箭头标记（箭头位置变为 azure 背景）。图例区域保持不变。

Key insight: 解题者必须先从角落图例中反向推断每种颜色编码的是哪种几何变换（通过观察标准 L 形如何变化），然后才能对每个 grey 形状执行正确操作——图例解读本身就是一层需要主动推理的非平凡步骤，与后续的变换执行构成真正的两层推理。
</description>

<description>
网格被灰色墙壁分割为若干房间，房间之间通过墙上的彩色"门"像素相连；将物体沿唯一门路径从起始房间传送到目标房间，物体最终颜色由最后经过的门决定。

Input structure:
- 黑色背景。由 grey 线条绘制的墙壁将网格分割为 4 到 6 个矩形房间。
- 每面墙上可能有"门"：门是墙壁上一个被替换为彩色像素的位置（占 1 个像素），相邻房间共享墙壁上的同色门像素表示它们通过该颜色的门相连。
- 恰好有一个房间包含一个 maroon 的 2x2 实心方块作为"物体"。
- 恰好有一个不同的房间的地板上有一个单独的 maroon 像素作为"目标点"。
- 路径唯一性保证：起始房间只有一扇门（出门），目标房间只有一扇门（入门），每个中间房间恰好有两扇颜色不同的门（一进一出），形成从起点到终点的唯一链式通道。

Rule:
- 第一步：从物体所在房间出发，通过该房间唯一的门进入相邻房间，再通过该房间的另一扇门继续前进，依次穿过各中间房间，直到到达目标点所在的房间。
- 第二步：记录物体从起始房间到目标房间依次经过的门的颜色序列。
- 第三步：从物体所在房间移除 2x2 方块（位置变为黑色）。在目标点位置以 maroon 像素为左上角绘制 2x2 方块，方块颜色为路径上最后经过的那扇门的颜色。
- 第四步：将路径上经过的每扇门像素颜色改为 maroon，标记为"已使用"。

Key insight: 解题者需要先理解门的连通机制（墙上的彩色像素代表门，同色门连接相邻房间），再发现路径唯一性的结构约束（每个房间的门数量严格控制形成唯一链路），最后归纳出物体最终颜色取决于最后一扇门的颜色——三层规则层层递进，每层都需要主动推理。
</description>

<description>
网格中散布若干形状，通过忽略缩放比例的几何匹配将形状两两配对，然后在混色图例中查找配对双方颜色的混合结果，用混合色重绘较大形状并移除较小形状。

Input structure:
- Azure 背景。网格中有若干个彩色连通形状，每个形状由单一非背景色绘制。
- 这些形状可以两两配对：配对依据是两个形状在忽略缩放后具有完全相同的像素图案（即一个是另一个的 2 倍或 3 倍整数放大版本——放大是指每个像素变为 2x2 或 3x3 的方块）。
- 每对中两个形状颜色不同。不参与配对的形状不存在。
- 网格底部有一行"混色图例"：若干个 1x3 的小条，每个小条由三个像素组成——左像素颜色 A、右像素颜色 B、中间像素颜色 C，表示 A 和 B 混合后得到 C。图例覆盖了所有需要的颜色组合。

Rule:
- 第一步：通过形状匹配找到配对。将较大形状按其放大倍数缩小后与较小形状逐像素比较图案，图案一致则配对成功。
- 第二步：在混色图例中查找每对形状的两种颜色对应的混合色（图例中 A-B 和 B-A 视为相同组合，混合色唯一）。
- 第三步：移除每对中较小的那个形状（其位置变为 azure 背景）。
- 第四步：将较大形状的所有像素重新着色为查到的混合色。
- 混色图例行保持不变。

Key insight: 解题者面临双重挑战——首先必须发现形状配对不是基于颜色或位置邻近性，而是基于缩放后的几何形状一致性（需要心理旋转和缩放来比对）；然后需要理解混色图例的三像素编码方式来确定最终输出颜色。两层推理机制截然不同，一层是空间几何匹配，一层是符号化颜色查表。
</description>
</new_puzzle>
