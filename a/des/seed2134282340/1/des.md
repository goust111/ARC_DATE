- `Input structure`：
  - 背景色（black）。
  - 网格顶部有一条水平的颜色图例条：图例条被 grey 分隔为若干格，每格内有一个由某种颜色绘制的小形状（如 L 形、T 形、十字形等，占据 3×3 区域内的若干像素），该颜色即为该形状的键。
  - 网格下方散布着若干由 grey 像素围成的封闭矩形区域，每个区域的边框恰好有一个 1 像素宽的缺口（缺口位于上、下、左或右边之一）。
  - 每个封闭区域内部恰好有一个单独的彩色"种子"像素，其颜色与图例条中某格的颜色一致。

- `Rule`：
  - 第一层推理——形状查找：对每个封闭区域，取其内部种子像素的颜色 C，在图例条中找到颜色为 C 的那一格，提取其中的 3×3 形状模板。
  - 第二层推理——方向确定与生长：确定该区域边框缺口所在的方向 D（上/下/左/右）。以种子像素为起点，沿方向 D 逐步平移形状模板，每次平移 1 格，将模板覆盖的位置都绘制为颜色 C，直到模板的任何一个像素超出封闭区域的内部范围或到达缺口边缘时停止（最后一次完整落入区域内的位置保留）。
  - 生长的形状从缺口处"溢出"：最终一次平移允许部分像素穿过缺口绘制到区域外部（仅穿过缺口的那些像素绘制在外部，不穿过墙壁的像素不绘制）。
  - 图例条在输出中移除。

- `Key insight`：种子颜色不仅决定填充色，还通过图例查表决定生长的形状；缺口位置决定生长方向——两层信息必须同时推断才能得出正确输出。

  - 碎片绘制在模具内部，覆盖背景色像素。标记点本身被碎片覆盖或保留（若碎片未覆盖到标记点位置，标记点保持不变）。
  - 散落在模具外部的原始碎片从网格上移除（设为背景色）。

- `Key insight`：颜色同时编码了"属于哪个模具"和"放入模具的什么位置"，解题者需要先识别颜色归属关系，再发现排序配对的规律。

- `Input structure`：
  - 背景色（black）。
  - 网格分为左右两个区域，由一条垂直的 maroon 分隔线隔开。
  - 左侧区域包含一个由 grey 网格线划分出的 N×N 棋盘（如 4×4），每个棋盘格为 3×3 像素。部分棋盘格内绘有小图案（由单一非背景色像素组成的简单形状：单点、水平线段、垂直线段、或 2×2 方块），其余为空（背景色）。
  - 棋盘外侧恰好有一个由 red 像素组成的箭头形标记，位于棋盘的某一边（上、下、左或右），箭头指向棋盘内部。箭头所在的边确定扫描起始边，箭头方向确定扫描推进方向。
  - 右侧区域为空白画布（全为背景色），尺寸足够大。

- `Rule`：
  - 第一层推理——确定读取顺序：根据箭头位置和方向确定棋盘的扫描方式。箭头在左侧指向右 → 从左到右逐列扫描，每列从上到下；箭头在上方指向下 → 从上到下逐行扫描，每行从左到右；以此类推。
  - 第二层推理——解码指令：每个非空棋盘格内的图案编码一条绘图指令：单点 = 画笔落下（开始在画布上留下轨迹）；水平线段（2 或 3 像素宽）= 向右移动该像素数步；垂直线段（2 或 3 像素高）= 向下移动该像素数步；2×2 方块 = 画笔抬起（停止留下轨迹）。空棋盘格跳过不执行。
  - 第三层推理——执行绘图：在右侧画布上，从左上角开始，按指令序列依次执行。画笔落下后移动时，沿路径像素涂为图案的颜色；画笔抬起后移动不留轨迹。最终右侧画布显示绘制结果。
  - 分隔线和棋盘在输出中保留不变，仅右侧画布被绘制。

- `Key insight`：箭头决定了棋盘格的读取顺序（这改变了指令序列），棋盘格内图案的几何形状编码了不同的绘图操作——三层推理缺一不可。

- `Input structure`：
  - 背景色（black）。
  - 网格中散布着若干 2×2 的彩色方块，称为"信号塔"，每个塔有唯一颜色（如 red、blue、green 等）。
  - 某些塔之间由单像素宽的水平或垂直 grey 直线连接（线段端点紧邻塔的边缘像素）。每条 grey 连线的正中间有一个彩色像素，称为"频率标记"，其颜色为 orange、azure 或 yellow 之一。
  - 频率标记的颜色编码传播模式：orange = 从两端同时向中间扩散；azure = 仅从较大颜色编号的塔向较小的扩散（颜色大小按塔在网格中从左到右、从上到下首次出现的顺序）；yellow = 从两端交替扩散（左/上端先走一格，右/下端再走一格，交替进行）。

- `Rule`：
  - 第一层推理——识别传播模式：找到每条连线中间的频率标记颜色，确定该连线使用哪种扩散规则。
  - 第二层推理——执行扩散：沿着 grey 连线像素，将塔的颜色向外扩散，覆盖 grey 像素。
    - orange 模式：两端的塔同时各自从靠近自己的一端开始，逐像素向中间涂上自己的颜色，在正中间（频率标记位置）相遇，频率标记像素变为两端塔颜色中在网格中出现位置更靠上的那个颜色。
    - azure 模式：仅一端的塔颜色覆盖整条连线（含频率标记），另一端不扩散。
    - yellow 模式：两端交替扩散，最终连线上形成两色交替条纹，频率标记像素被先到达的一端覆盖。
  - 信号塔本身保持不变。频率标记位置被扩散颜色覆盖。

- `Key insight`：连线中间的单像素频率标记不仅是装饰，它编码了该连线上两个塔之间完全不同的颜色扩散行为——解题者需要归纳出三种标记颜色对应三种截然不同的填充模式。

- `Input structure`：
  - 背景色（black）。
  - 网格中心有一个小型彩色图案（核心图案），由若干非背景色像素组成，占据约 3×3 至 5×5 的区域。
  - 核心图案外围有若干层同心矩形框架，每层框架由单像素宽的 grey 线条组成，相邻框架之间间隔 1 像素的背景色。
  - 每层框架的四个角落中，恰好有一个角落的 grey 像素被替换为一个彩色像素（非 grey、非背景色），其余三个角落保持 grey。该彩色角落的**颜色**和**位置**共同编码一种变换操作。

- `Rule`：
  - 第一层推理——解码变换指令：每层框架的彩色角落编码如下：
    - 颜色为 red：旋转操作。角落在左上 = 旋转 90° 顺时针，右上 = 旋转 180°，右下 = 旋转 90° 逆时针，左下 = 不旋转（即 0°）。
    - 颜色为 blue：翻转操作。角落在左上或右上 = 水平翻转（左右镜像），角落在左下或右下 = 垂直翻转（上下镜像）。
    - 颜色为 green：颜色替换操作。将核心图案中出现次数最少的颜色替换为 green，角落位置不影响此操作。
  - 第二层推理——确定执行顺序并叠加：从最外层框架到最内层框架的顺序依次读取变换指令，形成一个操作序列。将核心图案按该序列依次执行每一步变换。
  - 输出仅包含最终变换后的核心图案（紧凑裁剪，去掉所有框架和多余背景）。

- `Key insight`：框架不是装饰而是指令栈——角落标记的颜色决定变换类型，角落的位置决定变换参数，框架的嵌套层级决定执行顺序。解题者必须同时归纳颜色-操作映射和位置-参数映射两套规则，并正确识别由外到内的执行顺序。

- `Input structure`：
  - 背景色（black）。
  - 网格中有若干对由相同颜色边框围成的小矩形区域，每对颜色相同的两个矩形构成一对"传送门"（例如两个 red 边框矩形为一对，两个 blue 边框矩形为另一对）。每对传送门中，一个内部含有彩色图案（入口），另一个内部为空（出口）。
  - 每个传送门矩形的边框上有一个特殊标记：边框某一边的正中间像素被替换为 yellow 像素。入口和出口的 yellow 标记可能位于不同的边（上、下、左或右）。

- `Rule`：
  - 第一层推理——配对与方向识别：按边框颜色将传送门配对。对每对传送门，找到入口（有图案的）和出口（空的），并记录各自 yellow 标记所在的边。
  - 第二层推理——计算旋转量：入口的 yellow 标记所在边视为"原始朝向"，出口的 yellow 标记所在边视为"目标朝向"。从原始朝向顺时针旋转到目标朝向所需的 90° 步数即为图案的旋转量（例如入口标记在上、出口标记在右 = 顺时针旋转 90°；入口标记在左、出口标记在右 = 旋转 180°）。
  - 将入口内的图案按计算出的旋转量旋转后，绘制到出口矩形内部对应位置。入口的原始图案保持不变。

- `Key insight`：同色边框建立传送门配对关系，而 yellow 标记的相对位置差异编码了图案传送时的旋转角度——解题者需要发现标记位置差 = 旋转量这一隐含规则。

- `description`：在网格中根据"河流"走向将两岸的同色像素配对连线，连线的绘制方式由河流中的"桥墩"标记决定。

- `Input structure`：
  - 背景色（black）。
  - 网格中有一条由 azure 像素组成的连续曲线横贯网格，宽度为 1 像素，将网格分为两个区域（"两岸"）。这条曲线称为"河流"，仅做水平和垂直转弯（无对角线）。
  - 两岸各散布着若干彩色单像素点，同一颜色在两岸各恰好出现一次，形成配对。
  - 河流上有若干像素被替换为 maroon 色，称为"桥墩"。每个桥墩像素的位置恰好是某对同色像素之间最短直角路径穿越河流的交叉点。

- `Rule`：
  - 第一层推理——配对识别：将两岸的同色像素配对。
  - 第二层推理——路径确定：对每对同色像素，从一侧像素出发，沿水平或垂直方向画直线到达对应的 maroon 桥墩，穿过桥墩后继续沿直线到达另一侧像素。路径由两段或三段直角线段组成（类似 L 形或 Z 形），拐点仅出现在桥墩处或必要的转弯处。连线使用该对像素的颜色绘制，覆盖路径上的背景色像素。
  - 连线穿过河流时，桥墩（maroon）像素被连线颜色覆盖。河流的其余 azure 像素保持不变。两岸的原始彩色点保留。

- `Key insight`：河流的走向和桥墩的位置共同约束了每对像素的唯一连线路径——桥墩不仅标记穿越点，还隐式决定了连线的拐弯方式。解题者需要先通过颜色配对，再通过桥墩位置推断唯一合法路径。
</new_puzzle>
