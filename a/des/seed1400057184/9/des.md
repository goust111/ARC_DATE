# 第一步：分析与思考

## 参考题中涉及的基础操作归纳

通读20道参考题，可以提取出以下基础操作类型：

1. **属性分类与重着色**：根据对象的几何属性（对称性、面积、形状）将其分类并映射到不同颜色（参考1、12）。
2. **模板匹配与印刻/雕刻**：将一种形状作为模板叠加到另一种结构上，进行"印上"或"挖去"操作（参考2、9）。
3. **空间位移与对齐**：按照标记点或参照物移动对象到指定位置（参考3、18、16）。
4. **排序与重分配**：按某种度量（高度、面积等）对对象排序，然后重新分配到固定槽位（参考4）。
5. **拓扑/图论推理**：从遮挡关系、连通性等推断排列顺序或传播路径（参考5、14）。
6. **几何变换**：旋转、镜像、平移等刚体变换，由标记编码变换参数（参考6、8）。
7. **物理模拟**：重力下落、碰撞停止等物理直觉（参考7、12、13）。
8. **查找表与映射**：网格中嵌入一个"图例"或"字典"，用于查表替换（参考10、17）。
9. **补全与修复**：从不完整信息中恢复完整结构（参考9、11、20）。
10. **路径追踪与终点定位**：沿路径移动到特定终止条件（参考16、19）。
11. **拼图组装**：将散落的碎片拼成完整矩形（参考15）。

## 非显而易见的串联方式

- **属性提取驱动后续变换的参数**：一个对象的某种几何属性（如凸包面积、周长、孔洞数量）不直接用于重着色，而是编码为另一个操作的位移量、旋转角度或重复次数。这在参考题中几乎没有出现——参考题中属性只用于分类着色，而非作为变换的数值参数。
- **对象间的空间关系作为隐式图结构**：对象之间的相对位置（如"A在B的右上方"）定义了一个有向图，该图的拓扑排序决定了输出中对象的某种排列。参考5用遮挡做了类似的事，但可以用更抽象的空间关系。
- **颜色作为"密码"编码操作指令**：参考题中颜色通常用于标识或匹配，但颜色本身可以编码"要执行的操作类型"——比如红色表示水平翻转、蓝色表示旋转90度。
- **自指结构——网格的一部分描述了对另一部分的操作**：参考10的图例是一个例子，但可以更深入——网格中某个区域的形状本身就是变换指令的编码。
- **信息的跨区域传递**：一个区域的某种属性影响远处另一个区域的变换方式，需要在两个不相邻的区域之间建立因果关系。

## 寻找新的因果关系和信息传递路径

- 对象的**连通分量数量**可以编码一个数值，该数值决定另一个对象的平移距离。
- 对象的**朝向**（如L形的开口方向）可以编码路径选择指令。
- 多个小标记的**计数**可以决定大对象的截取/裁剪行数。
- 对象的**边界接触模式**（哪些边接触网格边界）可以编码其在输出中的放置位置。
- **颜色频率排名**可以决定对象的叠放层次（而非颜色本身）。

- `description`：根据每个封闭区域内部被"窥视孔"小标记指向的外部颜色，来填充该封闭区域。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有若干用 Grey 像素绘制的一像素宽的封闭矩形框（Grey 框互不重叠，互不接触）。
  - 每个 Grey 框的内部完全为 Black 背景。
  - 每个 Grey 框的边上恰好有一个像素被替换为 Red（称为"窥视孔"）。这个 Red 像素是框边的一部分，位于框的上、下、左或右边。
  - 在每个 Grey 框的外部，沿着窥视孔 Red 像素所面向的方向（即从框内部看，Red 像素所在边的法线外侧方向），在该方向上的网格空间中存在恰好一个单独的彩色像素（颜色为 Blue、Green、Yellow、Magenta、Orange、Azure 或 Maroon 之一），该彩色像素与窥视孔之间只隔着 Black 背景（同一行或同一列上，无其他障碍）。

- `Rule`：
  - 对于每个 Grey 封闭矩形框，找到其边上的 Red 窥视孔像素。
  - 确定窥视孔面向框外部的方向（如窥视孔在框的上边，则面向上方）。
  - 沿该方向向外扫描，找到第一个非 Black 非 Grey 的彩色像素，记录其颜色。
  - 将该 Grey 框内部所有 Black 像素填充为该颜色。
  - Grey 框本身保持不变，Red 窥视孔保持不变，外部的彩色像素也保持不变。

- `Key insight`：每个框的填充颜色不是由框自身的任何属性决定的，而是由框边上唯一的 Red "窥视孔"的朝向决定的——它像一个窗口，"看向"外部某个方向，捕获那个方向上的颜色信息。解题者需要先发现每个框上有一个 Red 像素，然后理解这个 Red 像素的位置编码了一个方向，最后沿该方向找到颜色源。
</new_puzzle>

<new_puzzle>
- `description`：将每个彩色 L 形标记的开口方向解读为箭头指令，沿该方向推动同色矩形块直到碰到网格边界或另一个块。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有若干个小的 L 形标记（每个由3个像素组成：占据2x2区域中的3个格子，空缺的那个角定义了L的"开口方向"）。每个 L 形标记有一个独特的颜色（如 Red、Blue、Green 等）。
  - 对于每个 L 形标记，网格中存在恰好一个同色的实心矩形块（面积至少为 4 像素，即至少 2x2）。
  - L 形标记和其对应的矩形块不相邻、不重叠。
  - 初始状态下所有矩形块之间也不重叠。

- `Rule`：
  - 通过颜色匹配将每个 L 形标记与其对应的矩形块配对。
  - 确定每个 L 形标记的开口方向：L 形占据 2x2 区域中的 3 个格子，缺失的那个角所在的方向就是开口方向（缺失角在右上→开口朝右上，但简化为四方向：若缺失角在右上则开口朝右，若缺失角在左上则开口朝上，若缺失角在左下则开口朝左，若缺失角在右下则开口朝下）。更精确地说：缺失角在 (top-left) 位置，开口方向为上；缺失角在 (top-right)，开口方向为右；缺失角在 (bottom-left)，开口方向为左；缺失角在 (bottom-right)，开口方向为下。
  - 将每个矩形块沿其配对 L 形标记所指示的方向滑动，直到矩形块的前沿碰到网格边界或碰到另一个已停止的矩形块（类似冰面滑行）。
  - 处理顺序：沿运动方向最前方的块优先处理（即朝右移动的块中，最右边的先移动；朝下的块中，最下面的先移动；以此类推）。
  - L 形标记本身在输出中保持不变。

- `Key insight`：解题的核心在于识别出 L 形标记不是装饰物，而是编码了运动指令。L 的缺口方向与推动方向之间的映射关系需要从多个样例中归纳：哪个缺口位置对应哪个移动方向。一旦破解了这个编码，还需要注意块的移动存在碰撞优先级。
</new_puzzle>

<new_puzzle>
- `description`：将散布的同色像素点解读为一个多边形的顶点，用该颜色填充多边形的轴对齐最小包围矩形，但在矩形内部沿顶点对角线连线"切割"出三角形空洞。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有若干组彩色像素，每组使用一种独特的颜色（如 Red、Blue、Green 等）。
  - 每组恰好包含4个同色像素点，这4个点构成一个轴对齐矩形的四个角中的恰好3个角——即缺少一个角。
  - 不同组的像素不会在空间上重叠或相互干扰（各组的包围矩形互不重叠）。

- `Rule`：
  - 对于每组3个同色像素点，找到它们的轴对齐最小包围矩形（即如果4个角都存在时的完整矩形）。
  - 确定缺失的第4个角的位置。
  - 用该组颜色填充整个包围矩形区域。
  - 然后，以缺失角为直角顶点，以与缺失角相邻的两个矩形角为另外两个顶点，形成一个直角三角形区域。将该直角三角形区域内部（不含边上的像素）的像素恢复为 Black 背景色。
  - 更精确地说：缺失角为 C，与 C 共享矩形边的两个角为 A 和 B，对角的角为 D。三角形 ACB 的内部（严格在 A-C 边、C-B 边和 A-B 对角线所围区域内，不含边界像素）被清除为 Black。其中 A-B 对角线使用 Bresenham 直线算法从 A 到 B 绘制，对角线本身的像素保留为该组颜色，只有对角线与矩形缺失角一侧之间的严格内部像素被清除。

- `Key insight`：解题者最初看到3个散布的同色点，需要意识到它们是一个矩形的3个角。缺失的角不是要被补全的——恰恰相反，缺失角的位置指示了要从完整矩形中"切掉"的三角形区域。3个点的空间排列同时编码了矩形的范围和切割的方向。
</new_puzzle>

<new_puzzle>
- `description`：网格被分隔线划分为若干面板，每个面板内有一个彩色图案；根据面板边界上共享分隔线段的颜色标记，将相邻面板的图案进行逐像素混合（叠加）。

- `Input structure`：
  - 背景色为 Black。
  - 网格被 Grey 直线（一像素宽，贯穿整个网格的水平线和垂直线）分割成若干个矩形面板（类似网格布局，如 2x2 或 2x3 的面板阵列）。
  - 每个面板内部包含一个由某种非 Black、非 Grey 颜色绘制的小图案（sprite），图案的其余部分为 Black 背景。所有面板内的图案占据相同大小的区域（比如都是 5x5），位于面板的中心。
  - 在某些 Grey 分隔线段上，恰好有一个像素被替换为 Maroon 色。这个 Maroon 像素标记了一对相邻面板之间的"混合指令"。

- `Rule`：
  - 输出网格的尺寸等于单个面板内部的尺寸（即裁掉所有 Grey 分隔线后的一个面板大小）。
  - 找到所有被 Maroon 标记的分隔线段，每个 Maroon 标记连接两个相邻面板。
  - 从任意一个面板开始（选择左上角的面板），沿着 Maroon 标记形成的连接路径（恰好形成一条不分叉的链，依次经过所有面板恰好一次），确定面板的叠加顺序。
  - 按照路径顺序，将各面板的图案依次叠加到输出网格上：后绘制的面板中的非 Black 像素覆盖先绘制的像素（即后面的图案具有更高的 z-order）。
  - 最终输出是所有面板图案按该顺序叠加后的合成图像。

- `Key insight`：分隔线上不起眼的 Maroon 标记像素是解题的关键——它们不是装饰，而是定义了面板之间的遍历路径。解题者需要先注意到分隔线上的异色像素，然后意识到这些标记形成了一条哈密顿路径，决定了图案的叠加顺序（从而决定遮挡关系）。面板图案本身可能互相重叠的部分在不同叠加顺序下会产生不同结果，这要求解题者精确追踪路径。
</new_puzzle>

- `description`：将网格中每个彩色连通区域"投影"到由同色边界标记所指示的网格边缘，投影方向由标记位于网格四条边中的哪一条来决定。

- `Input structure`：
  - 背景色为 Black。
  - 网格中散布着若干个由不同颜色构成的 4-连通前景区域（形状不规则，每个区域是某种单一颜色，如 Red、Blue、Green 等）。
  - 在网格的四条边（最外一圈像素行/列）上，存在一些单像素的彩色标记。每种前景颜色在网格边缘上恰好出现一个同色标记像素。该标记像素位于网格的上边、下边、左边或右边之一。
  - 网格边缘除了这些标记像素外，其余均为 Black。

- `Rule`：
  - 对于每个彩色前景区域，找到网格边缘上同色的标记像素，确定该标记位于哪条边：
    - 标记在上边 → 投影方向为向上。
    - 标记在下边 → 投影方向为向下。
    - 标记在左边 → 投影方向为向左。
    - 标记在右边 → 投影方向为向右。
  - 将该前景区域沿投影方向"压扁"到网格边缘：取该区域在垂直于投影方向上的跨度（即如果向上投影，取该区域覆盖的所有列），在标记所在的边缘行/列中，将这些列/行对应的像素涂为该区域的颜色。
  - 原始的前景区域从网格内部移除（变为 Black）。
  - 更精确地说：若投影方向为向上，则在网格第 0 行（最上行）中，将前景区域所覆盖的每一列都涂上该颜色。若投影方向为向左，则在网格第 0 列（最左列）中，将前景区域所覆盖的每一行都涂上该颜色。向下和向右类推。
  - 如果多个区域投影到同一边缘的同一像素位置，则后处理的颜色覆盖先处理的（处理顺序为：先处理面积较小的区域，后处理面积较大的区域）。

- `Key insight`：解题者首先需要注意到网格边缘有零星的彩色单像素，然后将它们与内部的同色区域关联起来。关键洞见是边缘标记不仅标识了"哪个区域"，还通过其所在的边编码了投影方向。前景区域的复杂形状被"压扁"成一维的边缘投影，类似于从某个方向照射光线后在边缘留下的影子。
</new_puzzle>

<new_puzzle>
- `description`：在一个包含多个同色"种子"像素对的网格中，每对种子之间生长出一条沿曼哈顿最短路径的彩色管道，管道的颜色由两颗种子之间的曼哈顿距离决定。

- `Input structure`：
  - 背景色为 Black。
  - 网格中有若干个 Grey 像素作为"种子"。Grey 种子的总数为偶数（如 4、6、8 个）。
  - 网格的一个角落（如右下角）有一个小的颜色图例区域（用 Azure 单像素框围起来的 N x 2 或 2 x N 小矩形），其中每行包含两个像素：左侧是一个用 Grey 写的数字形状的简化表示（实际上是1到N个 Grey 像素排成一排，像素数量代表数值），右侧是一个彩色像素表示该数值对应的管道颜色。例如：1个 Grey 像素对应 Red，2个 Grey 像素对应 Blue，3个 Grey 像素对应 Green。
  - 每对种子的曼哈顿距离各不相同，且每个距离值在图例中恰好有对应颜色。

- `Rule`：
  - 种子配对规则：将所有 Grey 种子按照"最近优先"原则配对——找到曼哈顿距离最近的两个未配对种子，将它们配对；重复直到所有种子都配对。
  - 对于每对配对的种子 (A, B)，计算它们的曼哈顿距离 D。
  - 在图例中查找 D 对应的颜色 C。
  - 从 A 到 B 绘制一条曼哈顿路径（先水平后垂直），将路径上的所有像素（包括 A 和 B 自身）涂为颜色 C。
  - 图例区域保持不变。

- `Key insight`：解题者面对的是看似随机散布的 Grey 点和一个不明用途的图例。核心发现在于：(1) Grey 点需要配对，配对规则是贪心最近配对；(2) 图例中 Grey 像素的数量编码了距离值而非序号；(3) 配对后的距离值决定了连线颜色。这需要同时破解配对机制和图例的编码方式。
</new_puzzle>

<new_puzzle>
- `description`：网格中的彩色像素群按"生命游戏"风格的邻域规则进行一步状态转换，但转换规则不是固定的，而是由网格角落的一个小"规则表"编码。

- `Input structure`：
  - 背景色为 Black。
  - 网格的主体区域包含由 Red 像素组成的图案（类似元胞自动机的"活细胞"），其余为 Black（"死细胞"）。
  - 网格的左上角有一个用 Grey 边框隔开的 3x3（或 4x4）小区域，作为"规则表"。规则表的结构如下：
    - 共 9 个格子排成 3x3（对应一个中心细胞的 8 邻域中活细胞数为 0-8 的九种情况，按从左到右、从上到下排列分别对应 0, 1, 2, ..., 8 个活邻居）。
    - 每个格子为 Green 或 Blue：Green 表示在该邻居数下细胞在下一步为"活"（变为/保持 Red），Blue 表示为"死"（变为/保持 Black）。
  - 规则表仅占据角落很小的区域（如左上角 5x5 像素，含边框），与主网格的 Red 图案区域不重叠。

- `Rule`：
  - 读取左上角的规则表：按从左到右、从上到下的顺序，得到邻居数 0 到 8 各自对应的下一步状态（Green=活, Blue=死）。
  - 对主区域中的每一个格子（包括当前为 Red 和 Black 的格子），计算其 8-邻域中 Red 像素的数量 N。
  - 在规则表中查找 N 对应的条目：若为 Green，则该格子在输出中变为 Red；若为 Blue，则变为 Black。
  - 左上角的规则表区域（含 Grey 边框）在输出中保持不变。
  - 此变换只执行一步（不迭代）。

- `Key insight`：乍看这像是一个简单的细胞自动机演化题，但解题者需要发现角落里不起眼的小色块并非装饰——它是一个可变的规则查找表。不同样例中规则表的配色可能不同（即不同的生存/死亡规则），解题者必须先破译规则表的编码方式（格子位置→邻居数，颜色→生死），然后将其应用到主网格上。关键难点在于规则表的存在和解读方式本身就是需要归纳的隐藏信息。
</new_puzzle>
