<description>
Recover each partially hidden 6x6 ring sprite and stack complete copies from top layer to bottom layer.

Input structure:
- The dominant color is the background.
- Several non-background colors are visible fragments of the same 12-pixel
  outline ring in a 6x6 box; small off-template marker pixels are noise.
- Ring fragments overlap, so upper rings replace some expected pixels of
  lower rings, and a ring may also be clipped by the input boundary.

Rule:
- Identify every substantial color whose pixels all lie on one translated
  copy of the ring template.
- For each missing in-bounds template pixel, the color currently occupying
  that pixel is above the hidden ring.
- Topologically sort these occlusion relations from top to bottom, then draw
  one complete 6x6 ring for each color in that order on a background canvas.

Key insight:
- The output is not a crop of the scene; it is the layer stack of complete
  ring sprites reconstructed from their visible fragments.
</description>

<reference_puzzle index="2" source="eval" puzzle_id="6ffbe589" lines="83-98">
<description>
Crop a board cluster and rotate its color layers based on outside cue sprites.

Input structure:
- bg = most common color.
- A main multi-color board cluster (largest foreground region).
- Small monochrome cue sprites outside the board for the colors that rotate.

Rule:
- Tight-crop around the board cluster.
- For each color layer inside the crop, find its same-color cue outside.
- Rotate that layer clockwise by (cue pixel count mod 4) × 90°.
- No outside cue → no rotation.

Key insight: Cue sprite size mod 4 encodes rotation amount for its matching color layer.
</description>
</reference_puzzle>

<reference_puzzle index="3" source="train" puzzle_id="689c358e" lines="72-88">
<description>
Mark each arrow-like sprite's pointed frame endpoint with its color and the opposite endpoint black.

Input structure:
- The grid has a one-pixel solid rectangular frame around a dominant interior background.
- Inside the frame are monochrome six-pixel sprites shaped as asymmetric T arrows.
- Each sprite has a length-4 bar and a length-3 crossbar one cell closer to the pointed end.

Rule:
- For each sprite, follow its bar axis from the shorter end to the frame.
- Paint that frame endpoint with the sprite color.
- Paint the opposite endpoint on the same row or column black.
- Leave the interior background, sprites, and all other frame pixels unchanged.

Key insight:
- The direction is encoded by the crossbar's off-center position: the nearer end is the pointing end.
</description>

<description>
Count same-color patterns per frame and represent the tally as dots inside.

Input structure:
- bg = most common color.
- Hollow rectangular frames in various colors.
- Small monochrome pattern sprites scattered outside frames.

Rule:
- Remove all small patterns from the grid.
- For each frame of color C, count how many patterns share color C.
- Draw that many dots along the frame's center row, spaced by 2, starting from the right.

Key insight: Frames act as tally displays — scattered same-color patterns are "absorbed" and their count is shown as interior dots.
</description>

<reference_puzzle index="5" source="eval" puzzle_id="195c6913" lines="37-52">
<description>
Simulate particles along a path with alternating turn direction at collisions.

Input structure:
- Top-left: 2x2 monochrome blocks define a repeating color cycle (left-to-right).
- Isolated single pixels of a cycle color: start markers adjacent to the path.
- A 2x2 monochrome block of a distinct color: end marker.

Rule:
- Each start marker launches a particle moving straight, painting cycle colors in order.
- On hitting a boundary, paint that cell with the end color and turn 90°.
- Turn direction alternates: odd collisions → left (CCW), even → right (CW).
- If the scheduled turn is blocked, the particle stops.

Key insight: The alternating left/right turn rule is the core mechanism; without it the path would be trivial.
</description>
</reference_puzzle>

<reference_puzzle index="6" source="eval" puzzle_id="b9e38dc0" lines="7-18">
<description>
Fill the region enclosed by a wall sprite and radiate color outward through its opening.

Input structure:
- bg = most common color. Wall = most frequent non-bg color, forming a partial enclosure (e.g. U-shape).
- A fill-color pixel sits inside the enclosed area. Other non-bg pixels may act as obstacles.
Rule:
- Flood-fill the enclosed area with the fill color, radiating outward through the wall's open end.
- Obstacles cast "shadows" along the radiate direction, blocking fill behind them.

Key insight: The wall endpoints define the opening direction; fill radiates outward through it, and obstacles block propagation along that same axis.
</description>
</reference_puzzle>

<reference_puzzle index="7" source="train" puzzle_id="c6141b15" lines="84-95">
<description>
Swap a connector segment with repeated marker sprites by connecting the marker anchors and stamping the sprite at the segment endpoints.

Input structure
The grid has one background color and exactly two foreground colors. One foreground color forms a single straight 8-connected segment. The other foreground color forms two or more identical centered sprites.

Rule
Build a background canvas of the same size. Draw straight connector-color segments between every pair of original sprite anchors. Then stamp the marker sprite, using its centered anchor, onto the two endpoints of the original connector segment.

Key insight
The original segment endpoints are the destinations for the repeated sprite, while the original sprite centers become the vertices of the new connector-color complete graph.
</description>
</reference_puzzle>

<reference_puzzle index="8" source="eval" puzzle_id="4c7dc4dd" lines="7-21">
<description>
Learn a transformation rule from a training pair of framed sprites, then apply it to a test sprite.

Input structure:
- Grid contains several colored square frames (hollow borders of a single color).
- Each frame's interior holds a small pattern sprite; one frame's interior is blank (all black).
- Two frames form a training pair (their interiors share the same color palette); one remaining frame is the test case.

Rule:
- Identify the training pair by matching interior color sets; the other non-blank frame is the test input.
- Infer the rule mapping source→destination (e.g. reflection, color inversion, gap filling, endpoint extraction, or checkerboard complement).
- Apply that same rule to the test sprite; output the transformed interior.

Key insight: The puzzle is an analogy — "A is to B as C is to ?" — where you must discover the visual rule from one example pair and generalize it.
</description>
</reference_puzzle>

<reference_puzzle index="9" source="eval" puzzle_id="5545f144" lines="191-207">
<description>
Move a triangular sprite across the grid, consuming aligned marker pixels.

Input structure:
- Frames concatenated horizontally with solid divider columns; bg is most common color.
- Each frame: a triangular arrow-shaped sprite and scattered single-pixel markers, all one color.

Rule:
- Start from the rightmost frame.
- At each step, exactly one cardinal direction from the head has reachable
  markers (on a half-line: same row or column); the sprite advances to the
  nearest one.
- On reaching a marker, consume it; sprite re-faces that direction.
- Repeat until no markers remain; output the final sprite position on a clean bg.

Key insight: The triangle's tip encodes facing direction, which sets marker-consumption priority.
</description>
</reference_puzzle>

<reference_puzzle index="10" source="eval" puzzle_id="9aaea919" lines="38-51">
<description>
Transfer sprites from red-marked lanes to green-marked lanes, recoloring and stacking.

Input structure:
- bg = most common color. Red (2) and green (3) thin bars define vertical lanes.
- Each lane contains repeated identical monochrome sprites in an evenly spaced vertical grid.

Rule:
- Each red lane's sprites turn grey (5); their count transfers to the nearest green lane.
- New sprites fill empty lattice slots bottom-up, using the source shape recolored to the destination lane's sprite color.
- All marker bars are removed.

Key insight: Sprite count is conserved across lanes — red sprites become grey, and equally many new sprites stack into the green lane's regular grid.
</description>
</reference_puzzle>

<reference_puzzle index="11" source="eval" puzzle_id="7b3084d4" lines="253-266">
<description>
Assemble colored rectangular sprites into a single tiled rectangle, anchored by a marker pixel.

Input structure:
- bg = most common color. Several solid-colored rectangular sprites scattered on the grid.
- One sprite has a unique single-pixel marker (different color) at one corner — this is the anchor.

Rule:
- Identify the anchor sprite (contains the marker pixel) and the remaining pieces.
- Rotate the anchor so the marker pixel lands at position (0,0) of the output.
- Pack all remaining pieces (allowing 90° rotations) to tile a complete rectangle with no gaps.

Key insight: The lone marker pixel picks the anchor and fixes the output orientation — it must sit at the top-left corner.
</description>
</reference_puzzle>

<description>
Turn black dents in two colored regions into marked opposite-color patches.

Input structure:
- Black background with two large foreground colors.
- The large regions contain small black dents and a few one-cell color specks
  or protrusions along region boundaries.

Rule:
- Locally clean the two foreground regions: isolated specks become black, and
  one-cell protrusions surrounded by the other region take that region's color.
- Each original black dent whose cleaned 3x3 neighborhood is mostly one
  foreground color becomes the center of a 3x3 patch in the opposite color.
- The dent center itself is recolored teal (8).

Key insight: The teal pixels mark the original black defects; the surrounding
3x3 patch uses the other foreground color, after first removing boundary noise.

<reference_puzzle index="13" source="eval" puzzle_id="9385bd28" lines="71-87">
<description>
Fill rectangles between diagonal marker pairs using a color legend.

Input structure:
- bg grid with a vertical legend at the bottom-left: each row is a (marker_color, fill_color) pair.
- Scattered L-shaped corner markers of each marker color define opposite corners of axis-aligned rectangles.
- Some markers are solid 2×2 blocks instead of corner pairs.

Rule:
- Read legend bottom-to-top; for each entry find all pixels of that marker color.
- Determine which two bbox corners carry L-shaped anchors — the *other* diagonal defines the fill region.
- Fill the diamond (all shortest-path cells between those two corners) with the legend's fill color.
- Solid 2×2 marker blocks are simply recolored to the fill color.
- Later legend entries are protected from earlier fills.

Key insight: The L-shaped anchors sit on the marker diagonal; the fill goes on the opposite diagonal of the bounding box.
</description>
</reference_puzzle>

Extract the lattice subregion bounded by the four background-colored corner holes.

Rule:

- The crop is marked by the missing lattice intersections, not by the marker

<reference_puzzle index="15" source="train" puzzle_id="17829a00" lines="21-36">
<description>
Move each colored object vertically until it touches the matching top or bottom border bar.

Input structure:
- The background is the dominant color.
- The top row is a full-width bar in one foreground color and the bottom row is a full-width bar in another.
- All other foreground pixels are 8-connected monochrome objects whose color matches one of those bars.

Rule:
- Top-bar-colored objects move upward so their bbox top is row 1.
- Bottom-bar-colored objects move downward so their bbox bottom is the row above the bottom bar.
- A downward-moving one-column segment whose landing overlaps its source becomes the continuous vertical segment swept between them.

Key insight:
The horizontal bars are destination anchors: color determines which border an object slides toward, while columns and object shape are otherwise preserved.
</description>
</reference_puzzle>

<reference_puzzle index="16" source="train" puzzle_id="320afe60" lines="41-56">
<description>
Slide each foreground object horizontally to the edge indicated by whether its shape has an open notch.

Input structure:
- Yellow is the background and there is one blue foreground color.
- The foreground is split into separated 4-connected objects.
- Each object keeps its row span and shape in the output.

Rule:
- If an object's bbox border contains a background gap flanked by object pixels along that same border, slide it to the right edge and recolor it green.
- Otherwise slide the object to the left edge and recolor it red.
- Start from a blank background canvas; no moved objects overlap.

Key insight:
- The target side is encoded by the object's shape, not by its original position: open notches go right, while closed or solid shapes go left.
</description>
</reference_puzzle>

<reference_puzzle index="17" source="train" puzzle_id="305b1341" lines="22-37">
<description>
Expand each sparse color object into a filled rectangular region using its legend-paired fill color.

Input structure
A background-color grid has a two-column legend in columns 0 and 1, starting at row 0: each row gives
a source color in the left column and that source color's fill color in the right column.  Outside the
legend, the foreground pixels are sparse dot objects whose colors are exactly the legend source colors.

Rule
Clear the legend.  For each source color, take the bbox of all of its non-legend dots, expand that bbox
by one pixel in every direction, and fill background cells inside the expanded rectangle with the paired
legend fill color while preserving every original non-legend dot.

Key insight
The legend order is also the layer order: earlier legend rows are in front, so fill rectangles are painted
from the last legend row back to the first and higher-priority fills overwrite lower-priority fills.
</description>
</reference_puzzle>

<description>
Move each marked cross object away from its marker to the grid edge while rotating the colored cross 180 degrees.

Input structure:
- The background is the dominant color.
- Each 8-connected foreground object has nine pixels: a 4-pixel marker-color
  sprite attached to a 5-pixel non-marker colored cross.
- Each object bbox is either 3x6 or 6x3, so the marker sprite is on exactly
  one side of the cross.

Rule:
- Move the whole object straight away from its marker side until the object
  bbox touches the corresponding grid edge.
- Keep the marker sprite unchanged within the object.
- Rotate the 3x3 colored cross block by 180 degrees before placing it.

Key insight:
The marker sprite is a directional tail; the cross is the leading payload,
and only that payload turns around during the slide to the edge.

<description>
Mark every complete square object with red pixels just outside its corners.

Input structure:
- A uniform background contains one or more monochrome 4-connected foreground objects.
- The relevant objects are square frames or filled squares: their bbox is square
  and all cells on the bbox border have the object's color.
- Non-square bars and incomplete fragments may also appear and are ignored.

Rule:
- Keep the input unchanged.
- For each complete square object, paint red on the two outside background
  pixels orthogonally adjacent to each of the square's four corners.

Key insight: The transformation is not based on size or color; it selects
objects whose bounding box is a complete square border and labels only their
exposed outer corner-adjacent cells.
</description>

<reference_puzzle index="20" source="train" puzzle_id="80214e03" lines="48-64">
<description>
Extract the color of each noisy block in a row/column lattice and mirror the coarse grid horizontally.

Input structure:
- A background surrounds a rectangular lattice of monochrome foreground blocks.
- Consecutive rows in a lattice band share the same set of visible foreground colors.
- Consecutive columns in a lattice band share the same set of visible foreground colors.
- Each row-band/column-band intersection has one foreground color, with possible background holes.

Rule:
- Group non-empty rows and columns into consecutive bands by their foreground color sets.
- Replace each lattice cell by the single foreground color inside that row/column-band intersection.
- Return the resulting coarse color grid with the column order reversed.

Key insight:
- Whole-row and whole-column color sets reveal the hidden lattice even when neighboring cells share a color or contain holes.
</description>
</reference_puzzle>

注意事项：
1. 任务不应依赖大量先验知识或复杂计算，而应依赖对模式、结构与空间关系的直觉推理。
2. 若涉及计算，只允许使用简单的计数、排序与数量比较；不允许使用复杂的数学公式或运算。
3. 问题必须能从少量示例中推断出来，但不代表题目一定简单。设计时需从人类解题者的视觉角度思考：规则涉及的所有关键要素（对象、关系、属性）必须在网格上肉眼可见，不应依赖人眼无法直接观察到的隐含信息或需要推算的隐藏属性。规则可以很难发现，难到反复对比所有样例仍需要深度思考才能归纳出来，但一旦发现后必须能用来解释所有样例且产出唯一确定的输出。
4. 生成的问题描述旨在促进后续用于创建题目网格的代码生成。因此，对输入/输出网格的描述以及规则总结必须极其详细；语言风格应易于理解；对于特定对象（如箭头），必须在描述中明确其绘制方式。
5. 描述谜题时避免使用 0 或 1 这类颜色编号；应使用颜色名称，例如 “red”。可用颜色如下：Black、Blue、Red、Green、Yellow、Grey、Magenta、Orange、Azure、Maroon。
6. 五个新题的核心推理机制应明显不同——即从观察样例到归纳规则的认知路径不同，而不仅仅是场景、对象或颜色不同。
7.  题目难度应来自机制的隐蔽性而非步骤数。关键信息难以准确定位，需要反复对比尝试不同的角度才能发现真正的规则。


生成后对生成的题执行以下四项审查（审查内容不需要保存到文件）：
1. 原创性
  新题不可与上述20道参考题相同或者是类似，不可只是替换了颜色、方向、对象类型、维度等表层要素。判断标准：新题的核心推理路径（解题者从样例中归纳规则的认知过程）应与任何一道参考题不同。
2. 确定性
  规则完全确定，同一输入只能产生唯一输出，每一步操作都有明确定义。
3. 可实现性
  所有必要细节都已给出——对象如何生成、如何识别、如何变换、边界情况如何处理，读完描述后可以直接写代码。
4. ARC 合规性
  网格尺寸合理（≤30×30），使用颜色不超过 10 种，规则复杂度适中，人类能从 3-5个样例中发现规律。
