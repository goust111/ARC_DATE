# 第一步：分析与思考

## 参考题中的基础操作梳理

通览20道参考题，可以提炼出以下基础操作类型：

1. **空间移动/滑动**：像素或对象沿某方向平移（题4、9、16、17、19）
2. **形状匹配与填充**：通过形状对应关系填充或替换区域（题8、18、20）
3. **标记/线索驱动的选择**：某些特殊像素或边缘元素作为"指令"控制变换行为（题3、11、14、16）
4. **对称性操作**：检测或强制对称（题13）
5. **拓扑/连通性分析**：识别连通分量、边界、轮廓（题1、15、19）
6. **编码/解码**：将计数、排名、位置等信息编码到几何结构中（题10、14）
7. **对接/拼合**：将两个部件按锚点对齐组装（题5、6、12）
8. **颜色交换/重映射**：按规则改变颜色（题6、7）

## 非显而易见的串联与信息编码方式

- **拓扑属性作为隐式索引**：一个对象的"孔洞数"、"凸凹性"、"分支数"等拓扑特征可以编码为一个数字，用于在另一个结构中查找或排序。这与直接的颜色/大小匹配不同——需要解题者意识到拓扑特征本身是一种信息载体。

- **负空间的语义**：我们通常关注前景对象，但"背景被前景围成的形状"本身也可以携带信息——比如两个对象之间的间隙形状可以编码操作类型或目标位置。

- **连通路径作为信息通道**：网格中的连通路径不仅是空间结构，还可以定义"信息传播方向"——颜色或图案沿路径传播时，路径的分支结构、长度或颜色序列都可以调制输出。

- **相对位置编码操作类型**：对象之间的空间关系（相对方位、距离的奇偶性、排列顺序）可以充当"操作码"，决定执行哪种变换，而非总是执行同一种操作。

- **多尺度观察**：信息可以同时存在于像素级和对象级——比如单个对象的微观纹理（内部像素排列）编码一个属性，而对象在网格中的宏观位置编码另一个属性，两者共同决定变换结果。

- **跨区域射线交互**：一个区域中的元素可以通过直线视线与远处区域中的元素建立因果关系，类似光线投射。这种长距离、非接触的信息传递方式不容易被发现。

- **序列/时间维度隐藏在空间中**：若干在空间中散乱排列的图案实际上是某个演变过程的不同阶段，解题者需要从"空间分布"切换到"时间序列"的思维模式。

## 创新方向

以下谜题的设计追求全新的认知路径——解题者需要发现此前未见的"从输入到输出的因果关系类型"。重点放在：规则隐蔽但一旦发现就完全确定；难度来自机制的隐蔽性而非步骤的复杂性。

<new_puzzle>
- `description`：根据每个封闭区域内部被短隔板切割成的子区域数量，用对应数量的不同颜色分别填充各子区域。

- `Input structure`：
  - 背景为 black。
  - 前景由 grey 线条（单像素宽）构成，形成若干独立的封闭区域（类似不规则多边形）。
  - 部分 grey 线条从封闭区域的边界向内延伸若干像素后终止，形成不完全贯穿的"短隔板"。这些短隔板与边界同色(grey)。
  - 短隔板虽然没有将区域从一侧贯通到另一侧，但在 4-连通意义下，它们确实将封闭区域内部的 black 空间分隔成了多个不相连的连通分量。

- `Rule`：
  - 对每个由 grey 线条围成的封闭区域，提取其内部所有 black 像素，做 4-连通分量分析，得到子区域数量 N。
  - 按预定颜色序列（Red, Blue, Green, Yellow, Orange, Magenta, Azure, Maroon），取前 N 种颜色。
  - 将该封闭区域内的 N 个连通分量分别着色：按像素数量从大到小排序，最大的分量着 Red，次大的着 Blue，依此类推。若面积相同，按连通分量最上方像素的行号升序排列，行号也相同则按列号升序排列。
  - grey 线条保持不变，封闭区域外部的 black 背景保持不变。

- `Key insight`：解题者需要意识到那些从边界向内伸出的短线段不是无意义的装饰或噪声——虽然它们没有完全贯穿区域，但在 4-连通拓扑下确实产生了有效分割。真正需要发现的因果链是："短隔板数量 → 子区域数量 → 使用颜色数量"以及"子区域面积排序 → 颜色分配顺序"。核心难度在于从视觉上看，区域似乎仍是一个整体，需要"4-连通分割"这一非直觉视角才能理解输出。
</new_puzzle>

<new_puzzle>
- `description`：将每个彩色对象沿其内部标记像素指示的方向"压扁投影"到对应的网格边界墙壁上。

- `Input structure`：
  - 背景为 black，网格的四条边界视为"墙壁"。
  - 网格中分布着若干单色的 4-连通前景对象（每个对象使用唯一颜色，颜色各不相同），尺寸不超过 7×7。
  - 每个对象内部恰好有一个像素被替换为 maroon（方向标记）。该 maroon 像素是对象的一部分，但颜色与对象其余像素不同。

- `Rule`：
  - 对每个前景对象，计算对象所有像素（含 maroon）的质心（所有像素行坐标的平均值四舍五入为质心行，列坐标的平均值四舍五入为质心列）。
  - maroon 像素相对于质心的位置决定投影方向：maroon 行号 < 质心行号 → 向上投影；maroon 行号 > 质心行号 → 向下投影；行号相同且 maroon 列号 < 质心列号 → 向左投影；行号相同且 maroon 列号 > 质心列号 → 向右投影。若行列偏移均非零，取绝对偏移量较大的轴方向；若绝对偏移量相等则取竖直方向（上或下）。
  - 沿投影方向，将对象"压扁"为一维截面：对于垂直于投影方向的每个坐标，如果对象在该坐标上有至少一个像素，则截面在该位置记录一个像素。
  - 在对应的墙壁上（网格边缘行/列）绘制该截面：用对象的颜色（非 maroon）画出单像素宽度的投影线。向上投影则画在第 0 行，向下投影画在最后一行，向左投影画在第 0 列，向右投影画在最后一列。
  - 原对象（含 maroon 像素）从网格中擦除为 black。
  - 若多个投影重叠在墙壁同一位置，保留原对象距该墙壁距离最近的那个颜色（距离 = 对象最近边缘到墙壁的像素数）。

- `Key insight`：解题者需要连续发现三层信息：(1) maroon 像素不是独立对象或噪声，而是嵌入在每个对象内部的方向标记；(2) 标记相对于对象质心的偏移编码了投影方向（上/下/左/右）；(3)"投影"不是平移，而是沿指定方向将对象压缩成一维轮廓后绘制在对应的网格边界上。核心认知路径：识别标记 → 推断方向 → 理解压缩投影机制。
</new_puzzle>

<new_puzzle>
- `description`：网格中散落的同尺寸小图案是某个图形逐步演变的"帧序列"，需根据相邻帧间仅差一个像素的规律找出正确的时间顺序，然后水平拼接输出。

- `Input structure`：
  - 背景为 black。
  - 网格中散布着 K 个大小相同的矩形小图案（sprite），每个 sprite 的边界框尺寸完全相同（例如均为 4×4 或 5×3）。
  - 每个 sprite 内部由若干彩色像素（可以包含多种非 black 颜色）构成图案，其余位置为 black。所有 sprite 使用相同的颜色集合。
  - 这些 sprite 是同一个小图形在逐步变化过程中的不同阶段快照。任意两个相邻阶段之间恰好有一个像素的差异（新增一个像素、删除一个像素、或一个像素改变颜色，均只计为1个差异）。
  - sprite 在输入网格中的空间排列位置是随机的，与时间顺序完全无关。sprite 之间不重叠，且被至少1像素宽的 black 间隙分隔。

- `Rule`：
  - 识别并提取所有 sprite：找到所有与最小非纯黑矩形尺寸相同的区域，或找到所有彩色像素簇的外接矩形。
  - 计算每对 sprite 之间的逐像素差异数（在相同的矩形位置逐一比较，不同的像素总数即为汉明距离）。
  - 构建帧序列：找到唯一一条遍历所有 sprite 的路径，使相邻帧的汉明距离恰好为 1。起点选择非 black 像素数量最少的 sprite（若相同则取非 black 像素重心行号最小的，再按列号最小的）。
  - 将排好序的 sprite 按时间顺序从左到右水平无间隔拼接，形成输出网格。输出高度 = sprite 高度，输出宽度 = K × sprite 宽度。

- `Key insight`：解题者面对的挑战是一组在空间上随意散落的小图案，需要转换思维维度——从"空间分布"切换到"内容相似度"。关键发现是：这些图案之间存在"单像素差异"的链式递进关系，形成一条唯一的演变路径。空间位置是完全无关的干扰信息，真正的排序依据是图案内容的最小编辑距离链。
</new_puzzle>

- `description`：每个前景对象在其自身位置保持不变，同时在网格中所有形状匹配其"形态学骨架"的 grey 标记处复制盖印一份。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干不同颜色的小型前景对象（每个对象使用单一非 black、非 grey 的颜色，4-连通，尺寸不超过 5×5 像素）。
  - 背景中另外散布着一些 grey 的小型标记图案（每个标记也是 4-连通的，尺寸不超过 3×3 像素）。
  - 每个 grey 标记的形状恰好是某个前景对象的"形态学骨架"。骨架的计算方法：反复执行腐蚀操作（每一轮移除所有 4-邻居中属于对象的邻居数 ≤ 1 的边界像素，但保留若移除则会使对象断开连通性的像素），直至不再变化。如果对象完全消失（例如2像素的线段），骨架为对象质心处的单个像素。骨架形状只考虑相对位置（平移不变），但不允许旋转或翻转。

- `Rule`：
  - 对每个前景对象，计算其骨架形状（像素的相对位置集合）。
  - 在网格中搜索所有 grey 标记，找到与该骨架形状完全匹配（平移对齐即可）的 grey 标记。
  - 在每个匹配的 grey 标记位置进行盖印：将骨架像素与 grey 标记像素对齐，然后以此对齐关系绘制完整的前景对象。绘制时用对象的颜色覆盖 black 像素和 grey 像素，但不覆盖已有的其他非 black、非 grey 彩色像素。
  - 前景对象在原始位置保持不变。
  - 未被任何骨架匹配的 grey 标记保持不变。

- `Key insight`：解题者需要发现 grey 标记与前景对象之间存在"形态学骨架"这一深层几何映射关系。表面上看，grey 标记比前景对象小得多且形状完全不同，看不出明显联系。但骨架是一个确定性的几何操作的结果——它保留了对象的拓扑核心。解题的认知跳跃在于：认出每个 grey 标记是某个对象"瘦身"后的核心骨架，然后反向"膨胀"还原出完整对象。
</new_puzzle>

<new_puzzle>
- `description`：网格被分隔线分为"查询区"和"色表区"，查询区中每个彩色像素向色表区发射四方向射线，距离最近的命中结果决定该像素的输出颜色。

- `Input structure`：
  - 网格被一条完整的 grey 直线（水平或垂直，贯穿整个网格宽或高）分隔为两个矩形区域。
  - 一个区域为"查询区"：包含若干稀疏散布的彩色像素（非 black、非 grey），其余为 black 背景。
  - 另一个区域为"色表区"：包含若干由彩色像素构成的短线段或小色块，其余为 black 背景。色表区中的彩色像素数量多于查询区。
  - 判定哪个是查询区的规则：非 black 非 grey 像素更稀疏（数量更少）的一侧为查询区。

- `Rule`：
  - 对查询区中的每个彩色像素 P：
    - 从 P 的位置向上、下、左、右四个方向分别发射射线（射线沿该方向逐像素前进，可穿过 grey 分隔线进入色表区）。
    - 每条射线前进直到碰到色表区中的第一个非 black 像素或到达网格边界。如果碰到非 black 像素，记录该像素的颜色及其与 P 的曼哈顿距离；如果到达边界未碰到，则该方向无响应。
    - 在所有有响应的方向中，选择距离 P 最近的响应。如果有多个方向距离相同，优先级为：垂直于分隔线的方向 > 平行于分隔线的方向；若仍相同，上优先于下，左优先于右。
    - P 的输出颜色即为所选响应的颜色。
  - 输出网格仅包含查询区部分（不含分隔线和色表区）：查询区中的彩色像素被替换为其通过射线查找到的输出颜色，black 背景不变。

- `Key insight`：色表区并非输出的一部分——它充当一个空间编码的"颜色查找表"。解题者需要发现：(1) grey 分隔线区分了功能完全不同的两个区域；(2) 查询区像素的颜色变化不取决于自身的原始颜色，而是通过"射线碰撞"机制从色表区远程获取的；(3) 四个方向中距离最近的命中结果胜出。核心难点在于理解这种跨区域的"光线投射查找"信息传递机制——查询区的每个像素就像一个探照灯，向四面搜索色表区中最近的颜色提示。
</new_puzzle>

- `description`：每个矩形对象内部两种颜色的数量比例决定了对象的命运——比例悬殊的保留并填实，比例接近的擦除并用少数色绘制外轮廓。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干互不重叠的矩形区域（轴对齐，尺寸各异但均不超过 10×10），彼此被至少1像素的 black 间隙分隔。
  - 每个矩形内部恰好由两种非 black 颜色的像素构成不规则混合图案（像素级交错），且其中一种颜色的像素数严格多于另一种。不同矩形内使用的两种颜色可以不同。

- `Rule`：
  - 对每个矩形区域，统计内部两种颜色各自的像素数，确定多数颜色 M（像素更多）和少数颜色 m（像素更少）。
  - 若 count(M) > 2 × count(m)（多数颜色是少数颜色的两倍以上），该矩形"保留"：将矩形内部所有像素统一替换为 M 的颜色，形成纯色实心矩形。
  - 若 count(M) ≤ 2 × count(m)（多数优势不够大），该矩形"擦除"：将矩形内部所有像素清除为 black，然后用 m 的颜色绘制该矩形的 1 像素宽外框轮廓。外框轮廓定义为：矩形边界框向外扩展1像素后形成的环形框线。若外框部分超出网格边界则截断（只画网格内的部分）。外框仅绘制在 black 像素上，不覆盖其他矩形的像素。
  - 网格中其余 black 背景保持不变。

- `Key insight`：解题者需要发现两种截然不同的输出模式（有些矩形变为实心色块，有些矩形消失并被外框取代）并找出区分条件。关键难点在于阈值"两倍"关系不是显而易见的——需要从多个训练样例中仔细统计每个矩形内两种颜色的像素比例，对比其保留/擦除结果，才能归纳出 "2倍" 这一分界线。此外，"擦除时用少数色画外框而非多数色"也是反直觉的，需要仔细观察输出中新出现的颜色来源。
</new_puzzle>

<new_puzzle>
- `description`：网格中彩色像素构成一棵树，从根到每个叶子的路径上颜色的变化次数决定了叶子处应绘制的参考图案的旋转角度。

- `Input structure`：
  - 背景为 black。
  - 网格中有一棵由彩色像素构成的树形连通结构（4-连通、无环的连通图），像素可以使用多种不同的非 black 颜色。
  - 树的"根"定义为：与网格某条边界相邻（4-邻居中有网格外部）的度数为 1 的端点像素。若有多个满足条件的端点，取行号最小的，行号相同取列号最小的。
  - 树的"叶子"定义为：除根以外的所有度数为 1 的像素（即只有一个 4-连通的树内邻居）。
  - 网格中另有一个小型参考图案（reference sprite），由单一颜色 azure 构成，尺寸不超过 5×5，与树不连通。参考图案是非对称的（旋转90°后与原图不同）。参考图案位于网格中不与树相邻的空闲位置。

- `Rule`：
  - 对每个叶子，追溯从根到该叶子的唯一路径，记录路径上依次经过的所有像素颜色序列（含根和叶子本身的颜色）。
  - 统计该颜色序列中"颜色变化"的次数 T：即相邻两个像素颜色不同的次数。例如序列 [Red, Red, Blue, Blue, Green] 有 2 次颜色变化。
  - 旋转角度 R = (T mod 4) × 90°，方向为顺时针。即 T mod 4 = 0 → 0°，1 → 90°，2 → 180°，3 → 270°。
  - 在每个叶子的位置（以叶子像素为参考图案的中心），绘制参考图案旋转 R 度后的副本。绘制时使用叶子自身的颜色替代 azure。若图案部分超出网格边界则截断，绘制不覆盖树上已有的像素。
  - 树结构本身保持不变，原始参考图案也保持不变。

- `Key insight`：解题者需要逐步发现多层嵌套的信息编码：(1) 网格中有树结构和一个独立的参考图案两个组件；(2) 叶子处出现了参考图案的旋转变体；(3) 旋转角度不是由叶子自身颜色或位置决定的，而是由从根到叶子整条路径上的信息决定的；(4) 具体地，是路径上"颜色变化次数"（而非颜色种类、路径长度等）编码了旋转角度。核心难度在于"颜色变化次数 → 旋转"这一关系非常隐蔽——需要反复对比不同叶子的旋转结果与其路径特征才能归纳出来。
</new_puzzle>
