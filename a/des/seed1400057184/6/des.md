# 第一步：分析与思考

## 参考题中涉及的基础操作梳理

参考题涵盖了以下基础操作类型：
- **空间扩展/压缩**：点阵展开为粗线条（#1）、彩条压缩为紧凑表（#3）
- **算术编码**：柱状图高度表示加减法（#2）、条长度编码数量（#10）
- **模板匹配与印章**：精灵图印章着色（#4）、模板补全（#6）、控制像素展开为字形（#7）
- **射线与传播**：十字射线投影（#9）、水流瀑布分叉（#14）、条纹图案传播（#5）
- **连通性与区域分析**：对角链判定（#8）、二分区域交替着色（#16）
- **空间变换**：条旋转90度（#18）、滑动方块穿越通道（#19）、块重排序拼接（#15）
- **形状分类与重着色**：形状归一化后赋色（#12）、奇偶判定标记中心（#20）
- **局部方向性**：边界标记决定方向（#17）、层叠偏移（#11）
- **最近种子分区**：条作为种子进行一维最近邻分区（#13）

## 非显而易见的串联方式与创新思路

1. **拓扑属性作为隐含指令**：一个对象的孔洞数、端点数、分支数等拓扑特征不仅可以用于分类，还可以编码一个操作的参数——比如孔洞数决定重复次数，分支数决定旋转角度。

2. **对象间的空间关系编码操作类型**：两个对象的相对位置（上下左右、包含、相切）本身可以构成一种"指令语言"——不同的相对关系指示不同的变换操作。

3. **网格的负空间**：前景对象定义正空间，但背景中被前景"框住"或"夹住"的空间同样携带信息。负空间的形状可以作为输出的模板。

4. **路径依赖的变换**：对象的变换不仅取决于其自身属性，还取决于从某个起点沿某条路径到达它的过程中经过了什么——路径上的颜色序列、转弯次数等构成上下文。

5. **对称性缺陷作为信号**：一个近乎对称的图案中，打破对称的那些像素恰恰编码了关键信息——缺陷位置指示操作目标、缺陷颜色指示操作类型。

6. **层叠读取顺序**：多个对象在视觉上有重叠时，重叠关系（谁在上谁在下）可以编码顺序信息，而这种顺序又决定了输出中元素的排列。

- `description`：根据每个封闭区域内部被困住的"碎屑"像素数量，用对应层数的颜色向内填充该区域。
- `Input structure`：
  - 背景为 black。
  - 前景包含若干由 grey 像素构成的闭合环形边界（环宽为1像素，形状不规则但保证4-连通闭合，且各环互不接触）。

  - 闭合环外部（背景区域）没有碎屑。
- `Rule`：
  - 识别所有 grey 闭合环及其包围的内部区域。
  - 计数每个环内部 red 碎屑像素的数量 N。
  - 清除环内部所有碎屑（变为 black）。
  - 从环的内侧边界向内收缩 N 层（每层1像素厚），将这 N 层像素都着色为 green。具体方法：第1层为所有与 grey 边界4-连通相邻的内部 black 像素，第2层为所有与第1层4-连通相邻的更内部 black 像素，以此类推。如果环的内部空间不足 N 层，则尽可能填充直到内部完全填满。
  - grey 环边界本身保持不变。
- `Key insight`：碎屑数量不是装饰——它精确控制了环内部 green 填充的厚度。解题者需要发现"数碎屑 -> 决定向内扩展的层数"这一因果关系，而不是被碎屑的位置分布所误导。

- `description`：网格中散布的小形状对象根据自身轮廓的凹凸性决定颜色变化：凸形对象变为一种颜色，凹形对象被"补全"为凸包并变为另一种颜色。
- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干由 blue 像素构成的4-连通独立对象，每个对象占3到15个像素不等。
  - 每个对象的形状各异：有些是凸形（即对象占据的像素恰好等于其最小外接凸多边形覆盖的所有网格单元——如实心矩形、实心直角三角形等紧凑形状），有些是凹形（即对象像素是其凸包的真子集——如L形、U形、C形等带缺口的形状）。
  - 判定凸性的方法：将对象所有像素坐标的凸包求出（即包含所有像素中心点的最小凸多边形），然后取该凸多边形覆盖的所有网格单元；若对象像素集合与凸包像素集合完全相同，则该对象为凸形，否则为凹形。
- `Rule`：
  - 对每个 blue 对象计算其凸包覆盖的像素集合。
  - 如果对象本身已经是凸的（像素集合等于凸包集合），则将该对象所有像素颜色改为 green，形状不变。
  - 如果对象是凹的（像素集合是凸包集合的真子集），则将该对象擦除，替换为完整凸包形状的所有像素，着色为 red。
  - 背景保持 black 不变。
- `Key insight`：解题者需要注意到输出中颜色（green vs red）和形状变化（保留 vs 补全）与对象的凹凸性一一对应。凸对象只改色不改形，凹对象既改色又补全为凸包。核心认知挑战在于从视觉上区分凸与凹，而非依赖大小、位置或朝向。
</new_puzzle>

  - 从每个箭头的尖端像素出发，沿箭头指向方向做射线检测（扫描该方向上的每个像素），找到射线命中的第一个 grey 对象（即遇到的第一个 grey 像素所属的4-连通对象）。
  - 将该 grey 对象的所有像素重着色为该箭头的颜色。
  - 如果同一个 grey 对象被多个不同颜色箭头指向，则取距离该对象最近的箭头的颜色（距离定义为箭头尖端到对象最近像素的曼哈顿距离）。距离仍相同时以行号较小的箭头优先，行号也相同时以列号较小的箭头优先。
  - 删除所有箭头像素（变为 black）。
  - 未被任何箭头指向的 grey 对象保持 grey 不变。
- `Key insight`：解题者需要先在视觉上识别出箭头的几何形状及其朝向，再理解"箭头指向 = 射线投影 = 选中目标"这一机制，最后发现目标的新颜色取自指向它的箭头。难点在于箭头形状的辨认以及理解颜色传递方向。

- `Input structure`：

  - 网格中有一个由 azure 像素构成的大型连通矩形区域（边长至少6），这是"画布"。
  - 画布内部有若干条单像素宽的直线段（水平或竖直），每条线段颜色为 maroon，长度至少为3且完全位于画布内部，横跨画布的整个宽度（水平线段）或整个高度（竖直线段），将画布切分为两部分。
  - 输入中恰好有1到3条 maroon 线段，线段之间互相平行或垂直但不相交。
- `Rule`：
  - 按照折叠线从短到长的顺序依次处理（长度相同时按从上到下、从左到右排序）。
  - 对每条折叠线：该线段将当前画布分成两部分，确定像素数较少的那一部分（若相等则取上方或左方的部分）。
  - 将较小部分沿折叠线做镜像翻转，映射到较大部分的对应位置。
  - 翻转映射后，如果映射目标位置原本是 azure 且被映射过来的也是 azure，则该像素变为 green（表示双层叠加）。如果映射目标位置原本是 black（画布外或已清除区域），则映射过来的像素着色为 azure。已经是 green 的位置保持 green。
  - 折叠后较小侧的所有原始画布像素清除为 black。
  - maroon 折叠线本身在输出中清除为 black。
- `Key insight`：maroon 线段不是装饰或分隔符——它们是折叠指令。解题者需要发现"沿线翻折、较小侧叠向较大侧、重叠区域变 green"这一空间操作。折叠顺序由线段长度决定，多次折叠的累积效果增加了推理难度。
</new_puzzle>

<new_puzzle>
- `description`：根据每个矩形色块的"邻域多样性"（其边界接触的不同邻居颜色种类数）对色块排序，输出为按此排序重新排列的紧凑柱状图。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干不同颜色的实心矩形色块（每个色块使用唯一颜色，可能用到 red、blue、green、yellow、orange、magenta 等），色块之间不重叠，但部分色块的边缘可能4-连通相邻。
  - 每个色块的面积（宽x高的像素总数）各不相同——没有两个色块面积相同。色块数量为3到6个。
- `Rule`：
  - 对每个色块，计算其"邻域多样性"D：统计该色块所有边缘像素的4-连通邻居中，有多少种不同的非 black 且非自身颜色的颜色出现。例如一个 red 色块的边缘接触了 blue 和 green 两种邻居，则 D=2；若不接触任何其他色块，则 D=0。
  - 按邻域多样性 D 从小到大排序；D 相同时按色块面积从小到大排序。
  - 输出一个紧凑网格：排序后的每个色块变为一个1列宽的竖直条，高度等于该色块的原始面积，使用该色块的原始颜色。竖直条按排序顺序从左到右排列，相邻条之间无间隔，所有条底部对齐。
  - 输出网格的高度等于所有色块中最大面积值，宽度等于色块数量。不足最大高度的条上方填充 black。
- `Key insight`：色块在输入中的空间布局决定了它们的"社交度"（接触多少种不同邻居），而这一隐含属性控制了输出中柱的排列顺序。解题者需要将注意力从色块本身的形状和颜色转移到色块之间的空间接触关系上——这是一种从个体属性到关系属性的认知跳跃。
</new_puzzle>

- `description`：网格中的单像素宽路径是"传送带"，路径一端的 yellow 标记指定物品滑动方向，物品沿路径向 yellow 端紧密堆叠。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干条由 grey 像素构成的单像素宽路径。每条路径是一条4-连通的像素链，可以弯曲转折但不分叉——即路径内部每个 grey 像素恰好有2个 grey 的4-连通邻居，路径两个端点各只有1个 grey 邻居。不同路径之间互不相连。
  - 每条路径的两个端点中恰好有一个被标记为 yellow（该像素颜色为 yellow 而非 grey），另一个端点为 grey。yellow 端点与路径中其相邻的 grey 像素保持4-连通。
  - 路径上散布着若干"物品"像素：路径中某些 grey 像素被替换为其他颜色（如 red、blue、green、orange 等，非 black 非 grey 非 yellow），每个物品占1个像素。
- `Rule`：
  - 对每条路径，找到其 yellow 标记端点。
  - 所有物品沿路径向 yellow 端点方向滑动，保持它们在路径上的相对顺序不变。
  - 滑动结果：距离 yellow 端点最近的物品（沿路径计算距离，即路径上经过的像素数）移动到紧邻 yellow 端点的第一个路径位置，第二近的物品紧跟在第一个物品之后（沿路径方向），以此类推，所有物品在 yellow 端点附近紧密排列。
  - 物品原来所在的路径位置恢复为 grey。物品到达的新位置从 grey 变为该物品的颜色。
  - yellow 端点自身保持 yellow 不变。没有物品经过的路径位置保持 grey。
- `Key insight`：yellow 标记不仅标识了路径端点，还指定了物品的"吸引方向"——物品被拉向黄色端点并紧密堆叠。解题者需要识别路径拓扑和端点标记，推断出方向性滑动规则。关键的认知跳跃在于理解 yellow 端点是"磁铁"/"目的地"，而非"发射点"。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象内部是否隐藏一个特殊颜色的"种子"像素，决定了该对象是向外膨胀还是向内收缩一层。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 blue 像素构成的独立4-连通对象，形状各异（不规则多边形），每个对象至少包含9个像素，且包围盒至少为 3x3。各对象之间互不4-连通相邻，且对象之间至少间隔2个像素。
  - 部分对象内部包含恰好1个 red 像素（"种子"）。种子的定义条件：该 red 像素的上下左右4个邻居全部为同一对象的 blue 像素（即种子完全被蓝色包围，不在对象边缘）。
  - 其余对象内部没有 red 像素——所有像素均为 blue。
- `Rule`：
  - 分别标记每个对象为"有种子"或"无种子"。
  - 对有种子的对象（膨胀）：找到该对象所有外边界像素（与 black 相邻的 blue 像素），将这些边界像素的所有4-连通 black 邻居变为 blue，实现向外膨胀1层。种子 red 像素本身变为 blue。
  - 对无种子的对象（收缩）：找到该对象所有外边界像素（与 black 相邻的 blue 像素），将这些边界像素变为 black，实现向内收缩1层。如果收缩后对象不再连通或完全消失，仍然执行。
  - 所有对象的膨胀/收缩同时计算：先基于输入状态确定每个对象的所有边界变化，然后一次性应用。膨胀对象之间如果扩展区域重叠，重叠位置仍为 blue。
- `Key insight`：隐藏在对象深处的单个 red 像素是"生命种子"——有种子则生长，无种子则萎缩。这一机制的隐蔽性在于：种子像素被蓝色完全包围，视觉上很容易被忽略，解题者必须仔细审视每个对象的内部来发现分类依据。
</new_puzzle>

<new_puzzle>
- `description`：网格中每个彩色像素同时沿其所在行和列"广播"自身颜色，形成十字投影；不同投影交叉时按固定优先级保留一种颜色。
- `Input structure`：
  - 背景为 black。
  - 网格尺寸至少为10x10。
  - 网格中散布2到5个单独的彩色像素点，每个像素使用不同颜色（从 red、blue、green、yellow、magenta、orange 中选取），各点之间不4-连通相邻，且没有任意两个点位于同一行或同一列。
- `Rule`：
  - 对每个彩色像素点 P（位于第 r 行第 c 列，颜色为 X）：
    - 将第 r 行的所有 black 像素着色为 X。
    - 将第 c 列的所有 black 像素着色为 X。
  - 所有投影同时计算。当某个位置被两个或以上不同颜色的投影覆盖时（即该位置位于某个点的行投影和另一个点的列投影的交叉处），按以下固定优先级保留优先级最高的颜色（优先级从高到低）：red > orange > yellow > green > blue > magenta。
  - 原始彩色像素点保持其原色不变。
- `Key insight`：每个像素是一个"广播站"，同时在行方向和列方向发射自己的颜色形成十字形覆盖。真正的挑战不在于理解十字投影，而在于发现交叉冲突点的颜色取决于一个固定的优先级序列。解题者需要从多个交叉点的实际颜色中反推出这一隐含的颜色优先级排序。
</new_puzzle>
