# 第一步：分析与思考

## 参考题中的基础操作归类

通过对20道参考题的梳理，可以提炼出以下基础操作族群：

1. **空间投射与光线追踪**：像素沿特定方向发射射线，直到碰到障碍物或边界（参考3的射线消除、参考9的对角射线遮挡、参考15的重力下落）。
2. **模式重建与周期推断**：从可见部分推断被遮挡的周期性底层纹理，或从局部外推全局重复模式（参考5的向上铺设motif、参考8的周期背景恢复、参考19的轮廓编码解码成周期格点）。
3. **属性匹配与配对**：通过计数、颜色、尺寸等属性将独立对象配对（参考10通过孔洞数匹配、参考2通过连接器颜色对接、参考12小地图到主区域的映射）。
4. **条件分类与差异着色**：根据某种拓扑或几何属性对同类对象进行分组并赋予不同颜色（参考13按对角方向分类、参考18按面积排序嵌套）。
5. **标记驱动的变换**：网格中的特殊标记像素编码了操作方向、目标或参数（参考16的teal标记指定压缩方向、参考17的图例箭头编码滑动方向、参考20的红色控制像素选择象限）。
6. **形状模板与印章操作**：将一个对象作为模板印到另一个位置或用其定义遮罩（参考11的精灵覆盖标记、参考14的自掩模膨胀）。

## 非显而易见的串联方式思考

- **拓扑编码空间指令**：一个封闭区域的拓扑特征（如连通孔洞数、凹凸数量）可以不仅用于匹配配对，还可以编码变换的具体参数——例如旋转角度、平移距离等。这把"识别属性"和"解码指令"融合在一起。
- **负空间作为信息载体**：通常我们关注前景对象，但背景被前景切割后形成的连通区域本身可能蕴含信息——它们的形状、数量或相对位置决定了变换规则。
- **对象间的相对位置关系作为隐式图结构**：多个对象之间的相对空间关系（如左右顺序、包含关系、最近邻距离）可以定义一个隐式图，而变换规则作用在这个图结构上而非直接作用在单个对象上。
- **变换的自指性**：某个对象的几何形状本身就描述了对它自身应执行的变换——比如一个L形状暗示需要进行L形的路径填充，或一个箭头状形状指示自身的移动方向。
- **多层信息叠加**：网格中同时存在"内容层"和"控制层"，外观上混合在一起，需要先分离出哪些像素属于控制信息、哪些属于待变换内容，然后用控制信息来变换内容。

<new_puzzle>
- `description`：根据每个封闭区域内部背景连通块的数量，用对应数量的同心收缩环来填充该区域。
- `Input structure`：
  - 背景色为 black。
  - 网格中有若干用 grey 像素绘制的封闭边框，每个边框形成一个矩形围栏（边框宽度为1像素）。
  - 每个围栏内部散布着若干不相连的 blue 小块（每个小块是1到3像素的4-连通团），其余内部像素为 black 背景。
  - 不同围栏内部的 blue 小块数量不同（范围1-4）。
- `Rule`：
  - 对每个 grey 围栏，计算其内部 blue 小块的数量 N。
  - 清除围栏内部所有 blue 小块。
  - 从围栏内壁开始，向内绘制 N 层同心矩形环，每层环宽度为1像素。
  - 第1层（最外层，紧贴围栏内壁）用 red 填充，第2层用 green，第3层用 yellow，第4层用 magenta（按此固定顺序循环）。
  - 如果围栏内部空间不足以容纳 N 层环，则尽可能绘制，最内层允许退化为实心矩形。
  - 围栏外部及 grey 边框本身保持不变。
- `Key insight`：blue 小块本身的位置和形状无关紧要——它们只是计数令牌；解题者需要意识到需要数内部离散块的个数，然后把这个数字翻译成同心环的层数。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象的轮廓形状隐式编码了一个旋转角度，将对象按该角度旋转后放回其质心位置。
- `Input structure`：
  - 背景色为 azure。
  - 网格中散布着若干 4-连通的单色前景对象（每个对象使用不同颜色，可选 red、green、yellow、magenta 等）。
  - 每个对象都是一个近似矩形的形状，但恰好有一个角被切掉（即矩形的四个角中，恰好有一个角的像素缺失，形成一个缺角矩形）。
  - 缺角位置不同的对象出现在网格的不同位置。
- `Rule`：
  - 识别每个前景对象的缺角位置：左上角缺失 = 不旋转（0°）；右上角缺失 = 顺时针旋转90°；右下角缺失 = 旋转180°；左下角缺失 = 顺时针旋转270°。
  - 将每个对象的完整矩形形式（补全缺角后的矩形）按上述角度绕对象的包围盒中心进行旋转。
  - 旋转后的对象放置在原包围盒中心位置（若旋转后尺寸改变，则以中心对齐）。
  - 旋转后的对象仍然保留原来的缺角（即旋转的是缺角矩形本身，不是补全后再旋转）。
  - 背景保持不变，对象之间不重叠。
- `Key insight`：缺角的位置不是瑕疵，而是旋转指令——解题者需要先发现所有对象都是缺角矩形，再注意到缺角位置与输出中的旋转状态之间的对应关系。关键难点在于从视觉上辨认出"缺角位置"这一属性是驱动变换的信号。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的多条折线路径按照颜色深浅排序后进行垂直分层堆叠，深色在下、浅色在上，重叠时上层覆盖下层。
- `Input structure`：
  - 背景色为 black。
  - 网格中有3到5条折线路径，每条路径由不同颜色绘制（从 blue、red、green、yellow、magenta 中选用）。
  - 每条路径是1像素宽的4-连通折线，从网格左边缘延伸到右边缘（即每条路径在每一列恰好占据一个像素）。
  - 这些路径在输入中互不重叠，各自占据不同的行位置。
- `Rule`：
  - 按照固定的颜色亮度顺序对路径排序：yellow（最亮）> green > azure > blue > red > magenta > maroon（最暗）。实际只看输入中出现的颜色子集。
  - 将所有路径在垂直方向上压缩到网格底部——最暗的颜色路径放在最下方，次暗的在其上方，依次叠加，最亮的在最上方。
  - 具体操作：逐列处理，在每一列中，将各路径像素按亮度排序后从底部开始依次向上堆叠（最暗的在最低行，最亮的在最高行），相邻像素之间无间隔。
  - 网格的其余部分填充为 black 背景。
- `Key insight`：每条折线在每列只有一个像素，所以逐列堆叠不会产生冲突。解题者需要识别出颜色与垂直位置之间存在固定的亮度排序对应关系，而不是基于路径原本的高低位置或路径编号。难点在于"亮度"这一隐含排序标准需要从对比多个样例中归纳出来。
</new_puzzle>

<new_puzzle>
- `description`：每个前景色块充当"印章"，将自身形状沿与最近网格边缘垂直的方向反复印到边缘，形成逐渐褪色的重复轨迹。
- `Input structure`：
  - 背景色为 black。
  - 网格尺寸不超过 25x25。
  - 网格中有1到3个 4-连通的单色前景对象，每个对象使用不同颜色（如 red、blue、green）。
  - 每个对象是一个小型形状（包围盒不超过 4x4），且不位于网格边缘。
  - 每个对象到四条网格边缘的距离各不相同，存在唯一的最近边缘。
- `Rule`：
  - 对每个前景对象，确定距离其包围盒最近的网格边缘（上/下/左/右取最小距离，距离定义为包围盒边缘到网格边缘的像素行/列数）。
  - 从对象当前位置开始，沿垂直于该最近边缘的方向（即朝向该边缘的方向），以对象包围盒高度（或宽度，取决于方向）为步长，重复印出对象的形状副本，直到到达或超出网格边缘。
  - 原始对象保留原色。第一个副本使用 grey，之后所有副本都使用 grey。
  - 如果副本超出网格边界，则只绘制仍在网格内的部分像素。
  - 多个对象的印章轨迹互不干扰——若轨迹重叠，后处理的对象覆盖先处理的（按对象颜色的字母顺序处理：blue < green < red）。
- `Key insight`：每个对象"知道"自己离哪个边最近，然后朝那个方向"走"过去，留下灰色脚印。解题者需要先发现印章方向的决定因素是"最近边缘"而非对象朝向或形状特征，然后理解重复步长等于对象自身的包围盒尺寸。
</new_puzzle>

<new_puzzle>
- `description`：网格中分散的彩色像素对构成"虫洞"传送门——将穿越两个同色像素之间的连线路径上的所有墙壁像素删除。
- `Input structure`：
  - 背景色为 black。
  - 网格中有一组 maroon 像素构成一个不规则的迷宫墙壁（4-连通的单一墙壁结构，将网格分成多个腔室）。
  - 在墙壁结构中散布着若干成对的彩色像素标记（如一对 red、一对 blue、一对 green，每种颜色恰好出现两次）。这些彩色像素替换了墙壁像素的位置（即它们嵌在墙壁中）。
  - 彩色标记对数量为2到4对。
- `Rule`：
  - 对每对同色标记像素，找到它们在墙壁结构上的最短路径（仅沿 maroon 墙壁像素进行4-连通移动，彩色标记像素也视为可通行节点）。
  - 将该最短路径上所有 maroon 墙壁像素删除（变为 black 背景），但保留两端的彩色标记像素。
  - 对所有颜色对依次执行此操作。如果某对路径经过已被之前操作删除的像素，则跳过这些已删除像素（它们已经是背景），继续寻找仍存在的墙壁像素上的最短路径。
  - 最终所有彩色标记像素也变为 black 背景。
- `Key insight`：彩色像素对不是装饰物，而是"虫洞"指令——同色对之间沿墙壁的最短路径定义了需要拆除的墙段。解题者需要识别出颜色配对关系，然后理解"沿墙壁结构的最短路径"这一空间概念。难点在于路径不是直线，而是沿着弯曲的墙壁拓扑结构行走。
</new_puzzle>

<new_puzzle>
- `description`：识别每个封闭房间中的"指针"图案，指针的朝向决定该房间墙壁上哪一侧被打开（删除该侧墙壁线段）。
- `Input structure`：
  - 背景色为 black。
  - 网格中有若干用 orange 绘制的矩形封闭房间（每个房间是完整的矩形边框，边框宽1像素，房间之间不共享墙壁，互不相邻）。
  - 每个房间内部有一个由 yellow 像素组成的小型"指针"图案。指针是一个 3 像素的直线段（水平或垂直），其中一端额外延伸出一个垂直方向的1像素凸起，使整体呈 L 形。L 形的长臂指向某个方向（上、下、左或右），该方向即指针朝向。
  - 每个房间的指针朝向可能不同。
- `Rule`：
  - 对每个房间，确定其内部 yellow 指针的朝向方向（上/下/左/右）。
  - 删除该房间在指针朝向那一侧的整段墙壁（将该侧的所有 orange 墙壁像素变为 black），但保留与相邻墙壁共享的角落像素（即矩形的四个角像素始终保留）。
  - 删除房间内部的 yellow 指针像素（变为 black）。
  - 其他墙壁和其他房间不受影响。
- `Key insight`：每个房间里的 L 形指针是一个方向编码器——它告诉你该房间的哪面墙要被"打开"。解题者首先需要在每个房间里识别出小型 L 形图案，然后判断其朝向，最后将朝向映射到墙壁拆除操作。难点在于 L 形很小（仅4像素），容易被忽略或误读方向。
</new_puzzle>

<new_puzzle>
- `description`：根据前景对象之间的"影子投射"关系重新着色——被其他对象的正下方投影覆盖的对象变为阴影色。
- `Input structure`：
  - 背景色为 azure。
  - 网格中有若干互不重叠的 4-连通单色矩形对象，每个对象使用不同颜色（如 red、green、yellow、magenta、blue 等）。
  - 这些矩形分布在网格的不同位置和不同行高度上。
  - 没有两个矩形在同一行上重叠，但它们的列范围可能有交集。
- `Rule`：
  - 对每个矩形对象，将其所有像素向下垂直投影到网格底部，形成该对象的"影子列范围"。
  - 如果某个矩形 B 的任意像素恰好落在另一个位于更高行的矩形 A 的影子列范围内，且 B 位于 A 的下方（B 的顶部行号 > A 的底部行号），则 B 被 A "遮蔽"。
  - 所有被遮蔽的矩形重新着色为 grey（无论被几个对象遮蔽）。
  - 未被任何其他对象遮蔽的矩形保持原色不变。
  - 判断遮蔽时只看列范围是否有交集，不要求完全覆盖——只要有至少一列重叠就算遮蔽。
- `Key insight`：解题者需要想象一束从上方照射下来的平行光，每个矩形在其正下方投射阴影。位于阴影区域内的其他矩形变灰。关键在于"遮蔽"是基于列范围的重叠和行的上下关系，而非对象之间的直接接触或距离。
</new_puzzle>
