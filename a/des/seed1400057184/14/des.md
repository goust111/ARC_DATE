# 第一步：分析与思考

## 参考题中涉及的基础操作归纳

纵览20道参考题，可以提炼出以下基础操作类别：

1. **空间投影与路径生成**：沿行/列/对角线投射射线、生成路径（#1蓝色折角路径、#9红色射线网络、#7粒子沿走廊运动）。
2. **颜色替换与重涂**：根据某种标记/上下文将区域颜色替换（#2侧标记重涂、#3行内前景色反转、#16 T形标记重涂区域）。
3. **几何变换**：旋转、平移、镜像、剪切（#11点对称复制、#19移动+剪切变形、#17旋转精灵拼接、#16可选旋转）。
4. **形状检测与分类**：识别特定形态（#10十字形检测、#6凸起/缺口配对、#18形状匹配填补）。
5. **排序与摘要**：将空间信息压缩为有序序列（#8按垂直位置排序颜色条、#12重建帧堆叠顺序）。
6. **嵌套/分层结构**：两级模式叠加（#13 Kronecker积式模板展开、#20四象限控制模式）。
7. **计数与度量**：像素计数决定输出维度（#20上象限计数定输出尺寸）、距离度量（#5 Chebyshev距离调色板）。
8. **拓扑操作**：连通分量分析、膨胀交集（#15两路径膨胀交集取中间通道）、孔洞填充（#2填充被对象包围的孔）。

## 操作之间非显而易见的串联方式

- **形状 → 编码信息**：一个对象的轮廓形状本身可以编码出一段"指令"——例如某条边界的凹凸序列可以被读取为二进制串，用来决定另一个区域的变换方式。
- **拓扑属性 → 选择条件**：一个连通分量的拓扑属性（如有几个孔、是否简单连通）可以作为筛选条件，决定哪些对象参与变换、哪些被忽略。
- **相对位置 → 操作参数**：两个标记之间的空间关系（距离、角度、相对象限）可以编码出变换的具体参数（移动方向、缩放倍数、旋转角度）。
- **颜色频率 → 结构生成**：某种颜色在输入中的出现频率或分布特征，可以反过来决定输出网格的结构布局。
- **边界接触模式 → 信息传递**：当两个对象共享边界时，共享的像素数量或共享边的方向可以定义信息如何从一个对象"传递"到另一个对象。
- **负空间作为信号**：背景中被多个前景对象共同围合但不属于任何对象的空白区域，其形状或面积可以成为决定变换方式的关键信号。

## 信息编码的非直觉方式

- 对象的朝向（如L形的开口方向）编码旋转指令。
- 前景对象之间的间距序列编码颜色选择顺序。
- 一个对象内部的孔洞数量编码该对象应被复制的次数。
- 网格边缘上的标记像素的排列模式编码出一种"密码"来变换中心区域。

<new_puzzle>
- `description`：根据每个封闭区域内部孔洞的数量，用对应数量的同心收缩层填充该区域。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个由同一前景色（如 green）绘制的封闭轮廓，每个轮廓是一个一像素宽的闭合环形。
  - 部分轮廓内部包含一个或多个由同一轮廓色绘制的独立小方块（1x1 像素），这些小方块是"孔洞标记"。
  - 每个轮廓的内部区域（被轮廓围住的 black 区域）面积足够大，保证能容纳所需层数的收缩。

- `Rule`：
  - 对每个封闭轮廓，计算其内部孔洞标记的数量 n。
  - 删除所有孔洞标记像素（恢复为 black）。
  - 从轮廓内壁开始，向内逐层收缩填充：第 1 层紧贴轮廓内壁，用 red 填充一圈一像素宽的环；第 2 层紧贴第 1 层内壁，用 blue 填充；第 3 层用 yellow；颜色按固定序列 red → blue → yellow → magenta → orange 循环。
  - 总共填充 n 层，剩余内部保持 black。
  - 轮廓本身颜色不变。

- `Key insight`：
  - 内部的孤立小像素不是装饰或噪声，它们是计数标记，决定了填充的同心层数。解题者需要注意到：不同轮廓内部小像素数量不同，而输出中同心层的数量恰好与之对应，颜色则遵循固定的循环序列。
</new_puzzle>

<new_puzzle>
- `description`：将网格中散落的彩色线段视为"指针"，每根指针指向一个目标区域，然后将指针自身的颜色涂满该目标区域。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个由 grey 绘制的矩形实心区域（宽高均 ≥ 3），各不重叠。
  - 网格中还散布着若干条彩色线段（非 grey、非 black），每条线段是严格的水平或垂直直线，长度 ≥ 2 像素，颜色各不相同。
  - 每条线段恰好有一个端点与某个 grey 矩形的外边界相邻（4-连通），另一个端点悬空（不与任何 grey 矩形相邻）。
  - 线段不与任何其他线段接触或交叉。

- `Rule`：
  - 对每条彩色线段，确定它与哪个 grey 矩形相邻。相邻端点所在的方位（矩形的上/下/左/右边）确定"被指向的方向"。
  - 但指针指向的含义是：从线段的悬空端点出发，沿线段方向（即朝矩形方向）延伸，穿过该矩形后，继续在矩形另一侧寻找第一个遇到的另一个 grey 矩形——这就是"目标矩形"。
  - 将目标矩形内部（不含边框一圈像素）全部填充为该线段的颜色。如果矩形宽或高仅为 3，则内部恰好是一列或一行。
  - 删除所有彩色线段（恢复为 black）。
  - 未被任何线段指向的 grey 矩形保持不变。

- `Key insight`：
  - 线段并非指向它直接接触的矩形，而是"穿过"接触矩形，指向同一射线方向上的下一个矩形。解题者容易误认为线段为相邻矩形着色，但仔细对比输入输出会发现被着色的总是射线方向上更远处的那个矩形。
</new_puzzle>

<new_puzzle>
- `description`：识别每个前景对象的轮廓转角数量，按转角数量从少到多将所有对象重新排列到输出网格的固定槽位中。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个（3-6个）由不同颜色绘制的实心多连通块对象（polyomino 形状），每个对象是单色的一像素宽连通区域，颜色互不相同。
  - 对象之间不接触，均为 4-连通。
  - 每个对象的形状不同，具有不同数量的"轮廓凸转角"（即沿着对象外轮廓顺时针行走时向右转90度的次数）。

- `Rule`：
  - 对每个对象计算其外轮廓的凸转角数量。凸转角定义为：对象像素的一个角点处，该角点被恰好一个对象像素覆盖（即在该角点周围的2x2区域中，恰好1个属于该对象）。
  - 按凸转角数量从少到多排序所有对象。
  - 输出网格高度等于所有对象的最大高度加2，宽度等于所有对象宽度之和加上（对象数-1）个间距列（间距1列 grey 分隔线）。
  - 从左到右，按排序结果依次放置每个对象（保持原形状和颜色），顶部对齐，对象之间用一列 grey 分隔。

- `Key insight`：
  - 排序的依据不是面积、颜色或位置，而是每个多连通块轮廓的几何复杂度（凸转角数量）。解题者需要注意到输出中对象的排列顺序与形状的"锯齿程度"相关。简单紧凑的形状（如矩形，仅4个凸角）排在前面，边缘越曲折的形状排在越后面。
</new_puzzle>

<new_puzzle>
- `description`：将网格中的每个彩色"种子"像素按其颜色对应的生长规则扩展为特定朝向的箭头形状。

- `Input structure`：
  - 背景色为 black。
  - 网格中散布若干孤立的彩色像素（"种子"），每个种子仅占一个像素，颜色取自 {red, blue, green, yellow} 四种。
  - 网格边缘（最外一圈）无种子，保证生长空间。
  - 种子之间距离足够远（曼哈顿距离 ≥ 7），生长后不会重叠。

- `Rule`：
  - 每种颜色对应一个固定的生长方向：red → 向右，blue → 向上，green → 向左，yellow → 向下。
  - 从每个种子出发，沿对应方向生长一个五像素长的箭头形状。箭头的具体绘制方式：
    - 箭杆：从种子位置出发，沿生长方向延伸 3 个像素（含种子共 4 个像素构成水平或垂直直线）。
    - 箭头尖：在箭杆末端的下一个像素处放置 1 个像素作为箭尖，同时在箭尖位置的两个垂直于箭杆方向的相邻像素各放置 1 个像素，构成三像素宽的箭头。
  - 即箭头总形状为：一条4像素长的杆 + 末端一个3像素宽的横排（或竖排），整体呈 "→" 形。
  - 所有像素均使用种子的颜色。
  - 种子本身是箭杆的起点，保留在输出中。

- `Key insight`：
  - 颜色并不只是视觉区分——它编码了生长方向。解题者需要从多个样例中发现每种颜色的种子总是朝同一个方向生长出箭头，而不同颜色方向不同。关键在于建立颜色-方向的映射关系。
</new_puzzle>

<new_puzzle>
- `description`：根据前景对象与网格四条边的接触模式，选择性地对对象执行沿接触边的镜像翻转。

- `Input structure`：
  - 背景色为 black。
  - 网格中有若干个（2-4个）不规则形状的单色前景对象，颜色各不相同。
  - 每个对象恰好接触网格的一条或两条边（即对象中至少有一个像素位于网格的第0行、最后一行、第0列或最后一列）。
  - 对象之间不接触、不重叠。

- `Rule`：
  - 若对象仅接触一条边（上/下/左/右），则以该边为镜像轴，将对象翻转到对面。原位置清除为 black，新位置绘制该对象的镜像。如果对象接触上边，则沿水平轴上下翻转后放到下边对应位置（使翻转后的对象接触下边）；接触左边则沿垂直轴翻转到右边，依此类推。翻转后对象在平行于镜像轴方向上的位置保持不变。
  - 若对象同时接触两条相邻边（如上边和左边），则对象保持原位不动，但颜色改为 maroon。
  - 若对象同时接触两条对边（如上边和下边），这种情况不会在输入中出现。

- `Key insight`：
  - 变换类型（翻转或变色）取决于对象与网格边界的接触模式，而非对象的颜色或形状。解题者需要注意到：被翻转到对面的对象原来只接触一条边，而留在原位变色的对象接触了两条相邻边。边界接触是一种隐含的空间属性，不容易第一时间注意到。
</new_puzzle>

<new_puzzle>
- `description`：将输入网格中由分隔线划分的多个小面板视为"帧序列"，输出仅保留在帧间发生变化的像素，静止像素清除为背景色。

- `Input structure`：
  - 背景色为 black。
  - 网格被若干条等间距的 grey 竖直分隔线分割为 3-5 个等宽的小面板（帧），每个面板宽度相同、高度等于网格高度减去可能存在的边框。
  - 每个面板内含有由若干颜色绘制的相同或相似图案，但部分像素在不同面板间发生了位置或颜色变化。

- `Rule`：
  - 输出网格的尺寸等于单个面板的尺寸（去掉分隔线）。
  - 对于面板中的每个像素位置 (r, c)，检查该位置在所有面板中的颜色是否完全一致。
  - 如果某位置的颜色在所有面板中完全一致（包括背景色），则输出中该位置为 black。
  - 如果某位置的颜色在至少两个面板间不同，则输出中该位置取最后一个面板（最右面板）中该位置的颜色。
  - grey 分隔线不参与比较，不出现在输出中。

- `Key insight`：
  - 多个面板并非独立的图案或可选项，而是同一场景的时间序列"快照"。输出提取的是"运动差异"——只有在帧间变化过的像素才保留，静止背景被消除。解题者需要将空间上并排的面板理解为时间上连续的帧，然后做逐像素差异检测。
</new_puzzle>

<new_puzzle>
- `description`：每个前景对象"投下阴影"——根据网格中唯一光源标记的位置，在对象的特定一侧绘制与对象同形但偏移一格的深色阴影。

- `Input structure`：
  - 背景色为 black（注意：这里 black 作为背景但阴影使用 grey）。
  - 网格中有一个 yellow 像素作为"光源标记"，位于网格的某个角落（四角之一）。
  - 网格中有若干个（2-4个）彩色实心对象（颜色各异，非 yellow、非 grey、非 black），互不接触。
  - 对象离网格边缘和其他对象足够远，确保阴影不会越界或重叠。

- `Rule`：
  - 确定光源所在角落（左上、右上、左下、右下）。
  - 阴影方向为远离光源的方向：光源在左上则阴影偏移为 (向下1, 向右1)；光源在右上则偏移为 (向下1, 向左1)；光源在左下则偏移为 (向上1, 向右1)；光源在右下则偏移为 (向上1, 向左1)。
  - 对每个彩色对象，将其所有像素按上述偏移量平移一格，在平移后的位置绘制 grey 像素，但仅在该位置原本为 black（背景）时才绘制。即阴影不会覆盖任何已有前景像素。
  - 原始对象保持不变，光源标记 yellow 像素也保持不变。
  - 阴影绘制顺序不影响结果，因为对象间距足够大。

- `Key insight`：
  - 角落里孤独的 yellow 像素不是装饰或干扰，而是全局光源，决定了所有阴影的投射方向。解题者需要建立"光源位置→阴影偏移方向"的映射。关键发现点是：所有对象的阴影总是偏向同一个方向，而这个方向恰好与角落 yellow 像素的位置呈对角线关系。
</new_puzzle>

<new_puzzle>
- `description`：将网格中两个同色对象之间的最短路径用该颜色"铺路"连通，路径绕开所有障碍物。

- `Input structure`：
  - 背景色为 black。
  - 网格中有 2-3 对彩色对象，每对由两个相同颜色的小型实心矩形（2x2 或 3x3）组成，不同对的颜色不同。
  - 网格中还散布若干 grey 实心矩形作为障碍物，挡在某些对象对之间。
  - 同色对象对之间保证存在至少一条不经过任何障碍物或其他颜色对象的4-连通路径。

- `Rule`：
  - 对每一对同色对象，找到连接它们的最短曼哈顿路径（4-连通，仅经过 black 像素），路径宽度为一像素。
  - 若存在多条等长最短路径，优先选择先尽量水平移动、再垂直移动的路径（即先消耗水平距离）。路径的起点为第一个对象（行列坐标字典序较小者）距离第二个对象最近的边缘像素，终点为第二个对象最近的边缘像素。
  - 将路径上的所有 black 像素替换为该对的颜色。
  - 障碍物和原始对象保持不变。
  - 不同颜色的路径互不交叉（输入保证这一点）。

- `Key insight`：
  - 解题者需要发现每对同色对象通过路径被连通。grey 矩形的作用不是标记或指示，而是迫使路径绕行的障碍。关键认知是将这视为一个"配对连线"问题——颜色相同的两个对象需要被连接，路径必须是沿网格线绕障碍的最短路线。
</new_puzzle>
