- `description`：根据框架内部的缺口形状匹配外部碎片，将碎片填入框架后，用碎片原始颜色对框架本体进行分段着色。
- `Input structure`：
  - 背景为 black。
  - 网格中有一个由单一颜色（如 blue）绘制的大矩形框架（空心矩形边框，宽度为 1 像素）。框架的边框上有若干处缺口（连续缺失的像素段）。
  - 框架外部散落着若干小的彩色碎片（每个碎片是一个 4-连通的单色形状，颜色各不相同，如 red、green、orange 等）。每个碎片的形状恰好能精确填入框架上某一处缺口（形状与缺口完全吻合）。
  - 碎片数量等于缺口数量，且碎片与缺口之间存在一一对应的形状匹配关系。
- `Rule`：
  - 第一步：识别框架边框上的所有缺口，以及外部所有碎片。将每个碎片平移（不旋转）到与其形状匹配的缺口位置，填补缺口。
  - 第二步：统计所有成功填入的碎片的颜色集合。按碎片在框架上的出现顺序（从框架左上角沿顺时针方向遍历边框），依次读出每个碎片的颜色，得到一个颜色序列。
  - 第三步：将框架本体（原本为 blue 的边框像素）按照该颜色序列进行分段着色——框架边框按顺时针方向均等分为 N 段（N = 碎片数量），每段用对应颜色重新着色。碎片填入的像素保持各自颜色不变。
- `Key insight`：碎片不仅是用来修补框架的拼图，其颜色还编码了框架本体的重新着色方案。解题者需要先通过形状匹配完成拼图，再利用匹配结果的顺序信息对框架进行分段染色——两层推理缺一不可。
</new_puzzle>

- `description`：将网格中的箭头形标记作为"投影指令"，从箭头指向的方向提取源图案的切片，并将切片印到箭头对侧的空白区域。
- `Input structure`：
  - 背景为 black。网格被一条 grey 的水平或垂直分隔线分成两个区域。
  - 一个区域（源区域）包含一个多色图案（由多种非背景色构成的连通形状）。
  - 另一个区域（目标区域）为空白（全 black），但在靠近分隔线的一侧放置了若干箭头标记。
  - 箭头标记由 red 像素绘制，每个箭头占据 3x3 的区域：箭头由一个指向分隔线方向的三角形构成（例如，若分隔线在箭头上方，则箭头朝上，形状为底行 3 像素 + 中间行中间 1 像素，即倒 V 形）。箭头的水平或垂直位置标记了要提取的列或行。
- `Rule`：
  - 确定分隔线方向（水平或垂直）。若水平分隔，箭头指向上或下；若垂直分隔，箭头指向左或右。
  - 对每个箭头，找到其指向方向上的源区域对应列（水平分隔时）或对应行（垂直分隔时）。箭头的中心列/行即为要提取的列/行索引。
  - 从源图案中提取该列或行的所有非背景像素，形成一个一维切片。
  - 将该切片从箭头位置开始，沿箭头的反方向（远离分隔线的方向）依次绘制到目标区域中。
  - 所有箭头标记在输出中被移除。
- `Key insight`：箭头的位置决定从源图案的哪个截面提取信息，箭头的朝向决定提取方向，而输出绘制方向是箭头朝向的反向。解题者需要同时理解箭头的"选择"功能（定位截面）和"投影"功能（确定绘制方向），这两个功能编码在同一个标记中。
</new_puzzle>

<new_puzzle>
- `description`：在网格中找到由相同颜色围成的封闭区域，根据封闭区域内部"种子"像素的数量决定填充行为和边界变色规则。
- `Input structure`：
  - 背景为 black。
  - 网格中有若干由单一颜色绘制的封闭环形边界（每个边界是一个由 4-连通像素组成的闭合环，宽度为 1 像素）。不同的边界可以使用不同颜色（如 blue、green、maroon 等）。边界之间互不接触。
  - 每个封闭边界的内部（被边界完全包围的背景像素区域）包含零个或多个"种子"像素。种子像素是单独的彩色像素点（颜色各异，如 red、yellow、orange 等），不与边界颜色相同。
  - 部分封闭区域内部没有种子像素（空腔）。
- `Rule`：
  - 第一步（填充）：对每个封闭区域，若内部恰好有 1 个种子像素，则将该区域内的所有 black 背景像素填充为种子的颜色。若内部有 0 个或多于 1 个种子像素，则内部保持不变（black 不填充）。
  - 第二步（边界变色）：对每个封闭边界，统计其内部种子像素的数量 K。若 K = 0，边界颜色不变。若 K = 1，边界颜色变为与种子相同的颜色。若 K >= 2，边界颜色变为 grey。
  - 种子像素本身在输出中保留原色。
- `Key insight`：解题者需要发现两个独立但关联的规则——内部填充仅在单种子时激活，而边界变色依赖种子计数的三档分类。单一种子既触发填充又决定边界色，这种"一石二鸟"的耦合关系是关键洞见。多种子区域的边界统一变 grey 这一规则需要通过观察多个样例才能归纳。
</new_puzzle>

- `Input structure`：
  - 背景为 black。
  - 网格中有若干由 azure 填充的矩形区域（实心 azure 色块），这些区域彼此不重叠，散布在网格中，其间以 black 背景分隔。
  - 在 azure 区域之上以及 black 背景之上，散落着成对的彩色锚点像素。每种非背景、非 azure 颜色恰好出现两个像素，形成一对。同色锚点对之间存在严格的水平或垂直对齐关系（同行或同列）。
  - 每个锚点要么位于 azure 区域之上（即该像素位置的底色为 azure），要么位于 black 背景之上。
- `Rule`：
  - 对每对同色锚点，沿它们对齐的方向（水平或垂直）绘制连线，连接两点之间的所有像素。
  - 连线样式取决于两个锚点各自所在区域的底色组合：
    - 若两个锚点都在 azure 上：绘制该锚点颜色的实线（每个像素都着色）。
    - 若两个锚点都在 black 上：绘制该锚点颜色的虚线（每隔 1 个像素着色，即着色、跳过、着色、跳过……从靠近网格原点的锚点开始着色）。
    - 若一个在 azure 上、一个在 black 上：绘制 yellow 实线。
  - 连线覆盖路径上的所有像素（包括 azure 和 black 背景），但两端的锚点像素保持原色不变。
  - azure 区域中未被连线覆盖的像素保持 azure 不变。
- `Key insight`：解题者首先要发现锚点按颜色配对并通过对齐方向连接（第一层推理），然后要发现连线的样式和颜色并非由锚点自身颜色决定，而是由两个锚点底部区域的"azure 与 black"组合决定（第二层推理）。azure 区域表面上只是装饰性色块，实际上编码了连线规则的分支条件。
</new_puzzle>

<new_puzzle>
- `description`：网格中包含若干"模板行"和"指令列"，模板行定义了图案的形状词汇表，指令列通过其标记像素选择模板行子集，并同时决定输出中各行的排列和着色。
- `Input structure`：
  - 背景为 black。
  - 网格的左侧部分包含若干"模板行"：每行由单一颜色（如 blue）在 black 背景上绘制的像素图案组成。所有模板行使用相同的颜色，它们各自的图案不同（不同行上有不同位置的像素被点亮）。模板行之间可以有空行（全 black 行）分隔。
  - 网格的右侧部分是一个或多个"指令列"：每个指令列是一条垂直的列，其中在某些行位置放置了彩色标记像素（颜色各异，如 red、green、orange 等），其余位置为 black。
  - 指令列中标记像素所在的行位置与左侧模板行一一对应（标记在第 i 个非空模板行的同一行上）。
  - 不同指令列使用不同颜色的标记像素，且各指令列之间用至少一列 black 分隔。
- `Rule`：
  - 第一步（选择）：对每个指令列，找出其标记像素所在的行，确定被选中的模板行集合。
  - 第二步（排列）：将被选中的模板行按照标记像素从上到下的出现顺序排列。
  - 第三步（着色与组装）：将选中的模板行图案用该指令列标记像素的颜色重新着色（替换原来的 blue），然后将这些重新着色的行紧凑地堆叠（去除空行），形成该指令列对应的输出块。
  - 第四步（输出）：所有指令列的输出块按指令列从左到右的顺序水平拼接（块间插入 1 列 black 分隔），形成最终输出网格。输出网格的高度等于所有输出块中最大高度，较短的块底部用 black 填充。
- `Key insight`：解题者需要发现三层嵌套结构——模板行提供形状词汇表，指令列通过标记位置"点菜"式选择子集，标记颜色同时编码输出着色方案。这三个角色（形状源、选择器、颜色映射）被紧凑编码在一个二维网格中，需要逐层剥离才能理解完整规则。指令列的水平排列顺序决定输出块的拼接顺序是最后一个需要归纳的细节。
</new_puzzle>

- `description`：网格中的每个彩色对象根据其自身形状中的"对称性缺陷"方向进行平移，平移距离等于该对象包含的像素数量，最终所有对象在新位置重新绘制。
- `Input structure`：
  - 背景为 black。
  - 网格中散布着若干独立的彩色对象（每个对象是 4-连通的单色形状，颜色各不相同）。
  - 每个对象的形状近似对称（接近左右对称或上下对称），但恰好有一个方向上存在"对称性缺陷"——即该对象在某个方向上多出 1 个像素，使其不完全对称。例如，一个本应左右对称的 T 形在右侧多了一个像素凸起。
  - 对象之间互不接触，且有足够空间进行平移。
- `Rule`：
  - 对每个对象，找到其最接近的对称轴方向（水平轴或垂直轴）。通过将对象沿候选轴翻转并与原形状比较，不匹配像素更少的轴即为"最接近的对称轴"。
  - 确定对称性缺陷的位置——即相对于该对称轴，多余像素所偏向的方向（上/下/左/右）。具体来说，将对象沿该轴翻转后，不匹配的像素落在哪一侧，该侧即为缺陷方向。
  - 将该对象沿缺陷方向平移，平移距离等于该对象包含的像素总数。
  - 原位置的像素被清除为 black。若平移后的位置超出网格边界，则该对象被裁剪（只绘制网格内的部分）。
  - 对象之间不会发生碰撞（题目保证平移后不重叠）。
- `Key insight`：解题者需要对每个对象进行两层推理：第一层是识别该对象"几乎对称"的轴以及打破对称的那个缺陷方向（这决定了移动方向），第二层是发现平移距离等于对象自身的像素数（这是一个从自身属性到几何量的非平凡映射）。对称性分析和计数分别提供方向和距离，两者缺一不可。
</new_puzzle>

- `description`：网格中有一个大的参考图案和若干小的"窗口框"，每个窗口框内显示参考图案的一个局部片段但其中一种颜色被替换了，需要找出被替换的颜色并恢复，同时将窗口框的边框颜色改为被替换的那种原始颜色。
- `Input structure`：
  - 背景为 black。
  - 网格左半部分有一个较大的多色参考图案（由多种颜色组成的矩形区域，如包含 blue、red、green、yellow 等像素）。
  - 网格右半部分散布着若干小矩形"窗口框"。每个窗口框由 1 像素宽的 grey 边框围成，内部显示一个图案片段。
  - 每个窗口框内部的图案是参考图案某个对应位置区域的副本，但恰好有一种颜色被替换成了另一种颜色（替换色为参考图案中未出现过的颜色，如 maroon 或 orange）。窗口框内部的其他颜色与参考图案完全一致。
  - 窗口框的大小可能不同，但每个窗口框的内部尺寸恰好匹配参考图案中某个子区域的尺寸。
- `Rule`：
  - 对每个窗口框，在参考图案中找到与之匹配的子区域（通过比对未被替换的像素位置和颜色来定位）。
  - 比较窗口框内部图案与参考图案对应区域，找出被替换的原始颜色 C 和替换色 R。
  - 将窗口框内部的所有 R 色像素恢复为 C 色（即还原为参考图案的原貌）。
  - 将该窗口框的 grey 边框改为 C 色（被替换掉的那种原始颜色）。
  - 参考图案本身保持不变。
- `Key insight`：解题者需要先进行空间匹配（将窗口内容与参考图案对齐定位），再进行差异检测（找出哪种颜色被篡改），最后发现边框变色规则（边框色 = 被篡改的原始色，而非替换色）。三层推理中，最隐蔽的是边框变色取的是"原始色"而非"替换色"——这需要通过多个样例对比才能归纳出来。
</new_puzzle>
