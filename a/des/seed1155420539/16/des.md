<new_puzzle>
description：根据封闭区域内部"锚点颜色对"的朝向，选择匹配的外部精灵并以锚点指定的旋转方式填入区域。

Input structure：
- 背景为黑色。网格中有若干由灰色像素围成的封闭矩形区域，每个区域内部恰好有两个相邻的彩色像素（锚点对），两像素颜色不同。
- 网格外围（不在任何灰色区域内部）散布着若干单色小精灵（4-连通的彩色像素块），每个精灵的颜色各不相同。

Rule：
- 对每个封闭区域，读取其内部锚点对中两个像素的颜色 A 和 B。
- 颜色 A 用于在外部精灵中查找颜色匹配的精灵；颜色 B 编码旋转量：Red = 0度、Green = 90度顺时针、Yellow = 180度、Blue = 270度顺时针。
- 将匹配精灵按 B 指定的角度旋转后，居中放入该封闭区域内部（覆盖锚点对），精灵颜色保持为 A。
- 若精灵旋转后无法完全容纳在区域内部，则不放置，区域保持原样。

Key insight：锚点对承担双重角色——一个像素的颜色选择精灵，另一个像素的颜色编码旋转角度；解题者必须先拆解这一"颜色即指令"的双通道机制，再执行空间变换。
</new_puzzle>

<new_puzzle>
description：将网格中散落的彩色碎片按形状互补原则两两配对，然后用配对伙伴的颜色重新着色每个碎片。

Input structure：
- 背景为Azure。网格中有偶数个单色4-连通碎片对象，每个碎片占据不超过6个像素，碎片颜色各不相同。
- 碎片可以视为在一个隐含的矩形包围盒内的像素图案，包围盒内未被碎片占据的部分构成该碎片的"互补形状"。

Rule：
- 对每个碎片，计算其最小包围盒，并提取包围盒内碎片未覆盖的像素图案（即互补形状）。
- 在所有碎片中寻找另一个碎片，其实际形状（允许旋转0/90/180/270度）与当前碎片的互补形状完全匹配。这两个碎片构成一对。
- 配对完成后，将每个碎片重新着色为其配对伙伴的原始颜色。碎片位置和形状不变。

Key insight：匹配的依据不是碎片自身形状的相似性，而是"一个碎片的负空间恰好是另一个碎片的正空间"——解题者需要同时观察形状与其周围的空白才能发现配对规则。
</new_puzzle>

<new_puzzle>
description：在分层网格中，上层面板定义颜色映射规则，下层面板中的对象按规则逐层传递颜色后输出最终状态。

Input structure：
- 网格被一条水平的Maroon分隔线分为上下两部分。
- 上半部分包含若干"颜色箭头"：每个箭头由一个3像素长的水平或垂直线段构成，线段一端有一个1像素的垂直于线段的翼（形成 T 型但不对称，翼在哪端就表示箭头指向哪端），整个箭头用颜色 X 绘制，箭头尖端的像素被涂成颜色 Y。这表示映射规则"X → Y"。
- 下半部分背景为黑色，包含若干彩色的4-连通矩形块。

Rule：
- 从上半部分提取所有颜色映射规则，构建一个颜色替换链（例如 Red→Blue, Blue→Green 意味着 Red 最终变成 Green）。
- 对下半部分的每个矩形块，沿替换链追踪其颜色直到链终止（即该颜色不再是任何规则的输入端），得到最终颜色。
- 用最终颜色重绘该矩形块。上半部分保持不变。

Key insight：上层箭头不是简单的一对一替换表——它们可以串联成链。解题者必须先从不对称箭头形状中解读方向和映射关系，再沿链条追踪到终点，两步推理缺一不可。
</new_puzzle>

<new_puzzle>
description：根据网格边缘的"刻度尺"对内部每个彩色条带进行截断或延伸，使条带长度与刻度尺上对应颜色的标记位置一致。

Input structure：
- 背景为黑色。网格最左列是一把"纵向刻度尺"：从底部第1行到顶部，某些行的最左列被涂上不同颜色的单像素标记，每种颜色最多出现一次。
- 网格内部（从第2列开始）有若干水平彩色条带，每条宽1像素，从第2列开始向右延伸若干格，颜色各不相同。每条条带的垂直位置（行号）不一定与刻度尺上同色标记的行号相同。

Rule：
- 对每条彩色条带，在刻度尺（第0列）中找到同色标记所在的行号 r。
- 该行号 r（从底部起算，底行 = 1）即为该条带的目标长度。
- 调整条带长度：若当前长度大于目标长度，从右端截断；若小于目标长度，向右延伸至目标长度。
- 条带的行位置（垂直位置）不变，刻度尺本身不变。

Key insight：刻度尺标记的行号不是指条带应该移动到哪一行，而是编码了条带应该具有的长度——解题者需要将"空间位置"重新解读为"数值量"。
</new_puzzle>

<new_puzzle>
description：识别网格中由边框颜色编码的嵌套层级关系，按层级深度的奇偶对每层内容执行不同的几何变换。

Input structure：
- 背景为黑色。网格中有若干彩色矩形边框（仅1像素宽的空心矩形），边框之间存在嵌套关系（一个边框完全在另一个边框内部）。
- 最内层的边框内部包含一个单色的4-连通小精灵（非矩形形状）。
- 每层边框的颜色各不相同。

Rule：
- 确定每个边框的嵌套深度（最外层深度为1，向内递增）。
- 深度为奇数的边框层：将其边框内（但在下一层边框外）的所有空白区域填充为该边框的颜色。
- 深度为偶数的边框层：将该层边框自身及其全部内容旋转180度（上下翻转 + 左右翻转）。
- 最内层精灵按其所在深度执行对应操作（奇数深度则用所在边框颜色填充精灵周围空白，偶数深度则旋转精灵180度）。
- 操作从最外层向最内层逐层执行。

Key insight：边框颜色表面上只是区分层级的标签，实际上隐含了奇偶层级的判断——解题者必须先识别嵌套结构、确定深度，才能决定每层应用哪种变换，这是一个"结构解析 → 规则分派"的双层推理。
</new_puzzle>

<new_puzzle>
description：网格中的彩色种子像素向四周生长出十字形枝条，枝条长度由同色种子的全局数量决定，枝条碰撞时按角落标记的优先级截断。

Input structure：
- 背景为Grey。网格中散布着若干单像素的彩色种子点，可能有多个种子共享同一颜色。
- 网格四个角落各有一个单像素颜色标记，从左上角顺时针依次排列，表示颜色优先级从高到低。

Rule：
- 统计每种颜色的种子数量 N。
- 每颗种子向上、下、左、右四个方向各生长 N 格长的枝条（用该种子的颜色绘制），遇到网格边界则停止。
- 当两个不同颜色的枝条试图占据同一格时，按角落标记定义的优先级决定：优先级高的颜色保留，低的被截断到碰撞点前一格。
- 同色枝条相遇时自然合并。

Key insight：枝条长度不是由种子本身的某种空间属性决定的，而是由"全局同色种子的计数"决定——这迫使解题者先完成全局统计，再执行局部生长；而碰撞优先级的线索隐藏在角落标记中，需要额外一步归纳。
</new_puzzle>

<new_puzzle>
description：将网格中散落的线段碎片识别为被打散的矩形边框碎片，重建完整矩形并用碎片的多数颜色决定重建边框的最终颜色。

Input structure：
- 背景为黑色。网格中有若干水平或垂直的单色线段（长度 >= 2像素），每条线段是某个原始空心矩形边框的一段边。
- 同一个矩形的碎片可能颜色不完全一致（例如4条边中有3条Red、1条Blue）。
- 碎片之间的空间排列保留了原始矩形的几何关系：属于同一矩形的水平碎片共享相同的列跨度起止，垂直碎片共享相同的行跨度起止。

Rule：
- 将所有共享行或列端点坐标的线段归为同一组（即它们来自同一个矩形）。具体地：若一条水平线段的左端列号和右端列号分别与某条垂直线段的列号匹配，且垂直线段的行跨度覆盖水平线段的行号，则它们属于同一矩形。
- 对每组碎片，重建完整的空心矩形边框（补全缺失的边段）。
- 重建边框的颜色取该组碎片中出现次数最多的颜色（多数投票）。
- 移除原始碎片，绘制重建后的完整矩形边框。

Key insight：解题的第一层挑战是将散落的线段正确归组为矩形——需要发现端点坐标的对齐关系；第二层挑战是发现边框颜色不取决于任何单一碎片，而是该组碎片的多数颜色投票结果。
</new_puzzle>
