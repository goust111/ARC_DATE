description：根据每个封闭区域内部散落标记像素的颜色，从网格边缘的色带图例中查找对应的填充图案，将该图案平铺填入封闭区域。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干由同一种墙壁颜色（如 Blue）围成的封闭矩形区域，每个区域内部面积不同。
- 每个封闭区域内部散落着少量（1-3 个）同色标记像素，标记颜色在不同区域间各不相同。
- 网格的最右侧若干列是色带图例区：图例由若干小矩形块纵向排列组成，每个小矩形块高 2 行、宽 2 列，左列为标记颜色（纯色），右列为该标记对应的两行填充图案（由两种颜色交替排列构成）。

Rule：
- 识别所有由墙壁颜色围成的封闭矩形区域。
- 读取每个封闭区域内散落标记像素的颜色。
- 在色带图例中找到与该标记颜色匹配的条目，提取其右列的 2 行填充图案。
- 将该 2 行图案作为 tile，在封闭区域内部按行列周期性平铺（从区域左上角开始对齐），覆盖区域内所有背景像素（标记像素也被覆盖）。
- 墙壁、图例区域和区域外背景保持不变。

Key insight：
- 解题需要两层非显然的推理：第一层是发现散落标记像素的颜色是索引键，第二层是发现图例右列编码的是平铺图案而非单一填充色，且平铺需要从区域左上角对齐相位。
</new_puzzle>

description：将输入网格中多个不规则前景对象按照各自的"开口朝向"分组，然后将同组对象合并为一个紧凑排列的复合体输出。

Input structure：
- 背景为主色（如 Black）。
- 网格中有 4-6 个不规则的单色前景对象（每个对象颜色各不相同），每个对象形状类似一个"C"形或"U"形——即一个矩形缺了一条边，形成一个明显的开口。
- 开口方向为上、下、左、右四种之一。
- 开口的大小（缺口宽度）在同一朝向的对象间可能不同。

Rule：
- 判断每个对象的开口朝向：对象的紧凑包围盒中，某一条边上完全没有前景像素的那条边即为开口方向。
- 将开口朝向相同的对象归为一组。
- 对每组内的对象：按照对象在输入中从左到右、从上到下的出现顺序，将它们的紧凑包围盒水平紧邻排列（开口朝左或朝右的组）或垂直紧邻排列（开口朝上或朝下的组），对象间无间距。
- 输出网格大小恰好容纳所有组的复合体；不同组的复合体之间留 1 行或 1 列背景色间隔，按组的开口方向排列（朝上的组在最上方，朝下的组在最下方，朝左的组在最左方，朝右的组在最右方）。

Key insight：
- 第一层推理需要发现"开口朝向"是分组依据（而非颜色或大小），第二层需要发现同组对象的排列轴由开口方向决定——水平开口的组垂直排列对象，垂直开口的组水平排列对象，这与直觉相反。
</new_puzzle>

description：在由分隔线划分的子区域中，找到每个区域的"种子图案"，根据区域内隐藏的对称轴类型展开种子图案以填满该区域。

- 网格被一种分隔颜色（如 Grey）的完整行和完整列划分为若干大小相等的矩形子区域。
- 每个子区域的背景为主色（如 Black）。
- 每个子区域中恰好有一个象限（左上、右上、左下或右下四分之一区域）包含一个由非背景像素组成的彩色图案（种子），其余三个象限为空（纯背景）。
- 在每个子区域的正中心位置有一个单独的标记像素，颜色为 Red、Green、Yellow 或 Blue 之一。

Rule：
- 对于每个子区域，首先定位种子图案所在的象限和中心标记像素的颜色。
- 标记颜色编码对称展开方式：Red 表示关于水平中轴做镜像（种子复制到上下对称位置），Green 表示关于垂直中轴做镜像（种子复制到左右对称位置），Yellow 表示同时关于水平和垂直中轴做双轴镜像（填满四个象限），Blue 表示关于主对角线做转置镜像。

Key insight：
- 第一层需要发现中心标记像素不是装饰而是控制信号；第二层需要归纳出四种颜色分别对应四种不同的对称操作类型；第三层需要正确处理种子在不同象限起始时镜像的坐标映射。

description：根据每个对象内部孔洞的数量，在网格边缘的颜色图例中查找对应颜色，然后用该颜色重新绘制对象的外轮廓。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干由同一种前景色（如 Blue）绘制的 4-连通封闭环形对象，每个对象内部包含 0-4 个不同大小的背景色孔洞（被前景像素完全包围的连通背景区域）。
- 网格最上方一行是颜色图例：从左到右排列着 5 个不同颜色的像素，分别标注在列位置 0、1、2、3、4 处，其余位置为背景色。图例中的列位置编号对应孔洞数量。

Rule：
- 计算每个封闭环形对象内部的孔洞数量 N（N 为 0 到 4 之间的整数）。
- 在图例行中，取列位置 N 处的颜色作为该对象的新颜色。
- 将该对象所有前景像素重新着色为查到的新颜色。
- 孔洞保持为背景色不变，图例行在输出中移除（整行变为背景色）。

Key insight：
- 第一层需要发现图例行不是普通装饰而是颜色查找表，且其索引键是位置编号；第二层需要发现每个对象被重新着色的颜色取决于其内部孔洞的数量，而孔洞数量就是图例中的列索引——将一个拓扑属性（孔洞计数）映射为一个视觉属性（颜色）。
</new_puzzle>

description：将网格中分散的碎片根据边缘锯齿的互补咬合关系配对，然后将每对碎片沿咬合边拼合，输出所有拼合后的完整矩形。

Input structure：
- 背景为主色（如 Black）。
- 网格中有偶数个（4-6 个）单色前景碎片对象，每个碎片颜色各不相同。
- 每个碎片大致呈矩形，但恰好有一条边是锯齿形的（由若干 1 像素深的凹凸交替构成），其余三条边是平直的。
- 碎片成对存在：同一对中两个碎片的锯齿边形状互补——一个的凸起恰好对应另一个的凹陷，拼合后形成完整的矩形。
- 同一对碎片的平直部分高度或宽度相同。

Rule：
- 对每个碎片，找到其锯齿边（非平直的那条边）及其朝向（上/下/左/右）。
- 锯齿朝向相反且锯齿轮廓互补的两个碎片配为一对。互补的判定：将一个碎片的锯齿边逐像素与另一个碎片的锯齿边对齐，凸凹完全互锁。
- 将每对碎片沿锯齿边拼合为一个完整矩形，拼合后的矩形中两个碎片各自保留原色。
- 输出网格尺寸恰好容纳所有拼合后的矩形，矩形之间留 1 行或 1 列背景色间隔，按照拼合矩形面积从大到小、从左到右排列。

Key insight：
- 第一层需要识别出每个碎片的锯齿边及其方向；第二层需要发现配对依据是锯齿轮廓的互补咬合关系（而非颜色、大小或空间邻近性）；第三层需要在输出中按面积排序重新布局，而非保持原始位置。
</new_puzzle>

<new_puzzle>
description：在网格中找到由路径连通的"源"与"槽"对象，将源对象的形状沿路径传送到槽内，传送过程中形状按路径拐弯次数旋转。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干"源对象"：小型非矩形的彩色前景图案（3x3 至 4x4），每个源对象颜色唯一。
- 网格中有与源对象数量相同的"槽对象"：由 Maroon 颜色绘制的空心矩形框，内部为背景色，每个槽的内部面积足以容纳某个源对象。
- 每个源对象通过一条由 Grey 像素组成的宽度为 1 的路径连接到恰好一个槽对象。路径从源对象的某一边缘出发，可能包含若干直角拐弯，最终到达槽对象的某一边缘。
- 不同的源-槽路径互不交叉。

Rule：
- 沿每条 Grey 路径，将源对象与其对应的槽配对。
- 计算路径中直角拐弯的次数 N。
- 将源对象的形状顺时针旋转 N×90 度。
- 将旋转后的形状绘制在对应槽的内部（居中放置），保留源对象的原始颜色。
- 输出中移除所有 Grey 路径像素（恢复为背景色），源对象原始位置也清除为背景色，Maroon 槽框保留。

Key insight：
- 第一层需要通过路径追踪发现源与槽的配对关系；第二层需要发现路径的几何形状（拐弯次数）编码了旋转角度——路径不仅是连接线，其拓扑结构本身携带变换信息；拐弯次数是小量（0-3），可以通过肉眼数出。
</new_puzzle>

<new_puzzle>
description：识别网格中散布的"箭头"指示物，每个箭头指向的方向和距离决定了将其相邻对象复制到目标位置，但复制时需按箭头颜色对应的规则进行变换。

Input structure：
- 背景为主色（如 Black）。
- 网格中有若干小型单色前景对象（形状各异，3x3 至 5x5 大小）。
- 每个对象的某一侧紧邻一个"箭头"标记。箭头由 3 个像素组成：一个中心像素和两个对角像素，形成一个指向上、下、左或右的尖角。例如朝右的箭头形如：第一行右侧一个像素、第二行中心一个像素、第三行右侧一个像素（呈 ">" 形）。
- 箭头颜色为 Red、Green 或 Yellow 之一。
- 箭头尖端方向即为复制方向；箭头与其相邻对象之间的间距（以像素计，1-4）即为复制的平移距离倍数。

Rule：
- 对每个对象，找到其相邻箭头，确定复制方向和平移距离 D（箭头尖端到对象最近边的间距）。
- 将对象沿箭头方向平移 D 个像素的距离，在目标位置绘制副本。
- 副本的变换由箭头颜色决定：Red 表示原样复制，Green 表示沿复制方向的垂直轴做镜像翻转，Yellow 表示颜色替换为箭头另一侧若存在的第二个对象的颜色（若不存在则保持原色）。
- 原始对象和箭头在输出中保留不变。

Key insight：
- 第一层需要从像素模式中识别出箭头的形状和朝向；第二层需要发现箭头与对象的间距编码了平移量；第三层需要归纳出箭头颜色控制的是复制时的变换类型，三种颜色对应三种不同操作。
</new_puzzle>
