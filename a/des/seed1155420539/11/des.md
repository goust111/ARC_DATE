- `Input structure`：
  - 背景为 black。
  - 网格中散布若干大小相同的正方形框架（由 grey 像素绘制的一像素宽空心矩形）。
  - 每个框架内部恰好有一个单像素彩色锚点（颜色各不相同），锚点位于框架内部的某个象限（左上、右上、左下、右下）。
  - 网格边缘区域（不与任何框架重叠）散布着若干小型彩色精灵（3x3 或 4x4 的多像素图案）。每个精灵有一个主体颜色和一个单像素的标识色；标识色与某个框架内锚点颜色相同，且标识色位于精灵的左上角像素。
  - 每个精灵在自然状态下呈现一个不对称的形状（即旋转 90 度后形状不同）。

- `Rule`：
  - 将每个框架内的锚点颜色与拥有相同标识色的外部精灵配对。
  - 判断锚点在框架内部的象限位置：左上象限对应 0 度（不旋转），右上象限对应顺时针 90 度旋转，右下象限对应 180 度旋转，左下象限对应逆时针 90 度旋转。
  - 将精灵按对应角度旋转后，以锚点位置为精灵左上角，粘贴到框架内部。精灵像素覆盖框架内部的 black 背景，但不覆盖 grey 框架边框。
  - 外部精灵在输出中被擦除（变为 black）。

- `Key insight`：锚点同时承担两个角色——其颜色是模板查找键，其在框架内的象限位置编码了旋转角度。解题者必须先发现颜色配对关系，再发现象限-旋转的对应规则。

- `Key insight`：解题者需要先识别出图例区的"形状-颜色"映射关系，再对工作区每个瓦片进行形状匹配查表。难点在于图例中的形状可能经过不同位置放置，需要平移归一化后才能比较，且图例的编码方式（右下角单像素表示颜色）需要从样例中归纳发现。

- `description`：将网格中散落的同色路径碎片按颜色拼接成完整路径，再沿每条路径的行进方向在路径两侧交替绘制等距的"栅栏柱"。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干条不同颜色的路径碎片。每条路径由同一颜色的多段一像素宽的水平或垂直线段组成（每段长度至少 2 像素），同一路径的所有碎片端点两两之间恰好有一对可以通过直角折线（先水平再垂直，或先垂直再水平）连接且路径不重叠。
  - 每条路径的其中一个端点像素被替换为 yellow，标记为起点。
  - 网格中另有若干 red 的单像素散布在路径附近（不接触任何路径），作为干扰物。

- `Rule`：
  - 第一步——拼接路径：对每种颜色，找到所有碎片的自由端点（仅有一个同色邻居的像素），将可以通过一次直角弯折相连且不穿越其他已有像素的端点对连接起来，连线颜色与路径相同。连接后每条路径成为一条从 yellow 起点出发的连续折线。
  - 第二步——绘制栅栏柱：从 yellow 起点沿路径前进，每隔 3 个像素（即在路径的第 4、第 7、第 10 个像素处，以此类推），在路径的垂直方向上交替向两侧延伸一个 green 像素。第一个栅栏柱向路径行进方向的左侧延伸，第二个向右侧，依此交替。若延伸位置已有非 black 像素则跳过该柱但交替顺序不跳过。
  - red 干扰像素在输出中保留不变。

- `Key insight`：第一层推理是发现碎片按颜色分组后需要通过直角折线拼接成完整路径；第二层推理是发现栅栏柱的放置规则——等间距、左右交替、垂直于局部路径方向。两层规则都需要从样例中独立归纳。
</new_puzzle>

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个一像素宽的空心矩形边框，每个边框使用不同的颜色绘制（如 red、blue、green、orange、magenta 等）。
  - 这些矩形存在嵌套包含关系：某些矩形完全位于另一个矩形内部，形成树状层级结构（不存在部分重叠，要么完全包含要么完全分离）。
  - 网格右下角有一个小型颜色图例：一列纵向排列的彩色像素，从上到下依次代表深度 0、深度 1、深度 2 等的填充颜色。图例像素之间无间隔，紧贴网格右下角边缘。

- `Rule`：
  - 识别所有矩形边框，并根据几何包含关系构建嵌套树：最外层矩形深度为 0，被它直接包含（不经过其他矩形中介）的矩形深度为 1，以此类推。
  - 读取右下角的颜色图例，将自上而下第 k 个像素的颜色映射为深度 k 的填充色（k 从 0 开始）。
  - 对每个矩形，将其内部区域（不包括边框本身）中属于 black 背景的像素填充为该矩形深度对应的图例颜色。填充顺序为从最外层到最内层，因此内层矩形的填充会覆盖外层的填充。
  - 所有矩形边框颜色保持不变。图例像素保持不变。

- `Key insight`：解题者需要先发现矩形间的嵌套包含关系并确定每个矩形的深度层级，然后发现右下角图例是深度到填充颜色的查找表。两步推理缺一不可：仅靠边框颜色无法确定填充色，仅靠图例也无法知道该给哪个区域填色。
</new_puzzle>

- `description`：识别网格中由"门"连通的多个封闭房间，根据每个房间内标记像素的颜色对房间进行配对，然后沿连通两个配对房间的最短门序列路径绘制通道。

- `Input structure`：
  - 背景为 black。
  - 网格中有多个由 grey 墙壁围成的封闭矩形房间（墙壁一像素宽）。相邻房间共享墙壁。
  - 某些共享墙壁上有恰好一个像素的缺口（即该位置为 black 而非 grey），这些缺口构成房间之间的"门"。通过门可以从一个房间走到相邻房间。
  - 每个房间内部要么为空（全 black），要么包含恰好一个彩色标记像素（非 black、非 grey）。标记颜色成对出现：网格中恰好有偶数个带标记的房间，且每种标记颜色恰好出现两次。

- `Rule`：
  - 将标记颜色相同的两个房间配对。
  - 对每一对配对房间，找到连通它们的房间序列——即从一个房间出发，每次通过一扇门进入相邻房间，最终到达配对房间，且经过的房间数最少。由于房间排布的规则性，这条路径是唯一的。
  - 沿这条路径，将途经的所有门缺口像素涂为该对的标记颜色，同时将路径上所有中间房间（不含起止房间）的内部背景像素全部涂为该对标记颜色的"淡化色"。淡化色规则：在可用颜色列表 [red, blue, green, yellow, orange, magenta, azure, maroon] 中，淡化色为标记色在该列表中的下一个颜色（末尾循环回首位）。
  - 起止房间内部的标记像素保留不变，起止房间的背景不填充。无标记的房间若不在任何路径上则不改变。

- `Key insight`：第一层推理是发现房间之间通过墙壁缺口（门）连通的拓扑结构，并将标记按颜色配对；第二层推理是发现通道绘制规则——门被涂为标记色，中间房间被涂为标记色的"下一色"。淡化色的映射规则需要观察多个样例中不同标记颜色的对应关系才能归纳出来。
</new_puzzle>

- `description`：将网格中每个彩色对象作为"印章"，按照对象自身 azure 标记指示的朝向在其前方盖印出逐层缩小的副本序列。

- `Input structure`：
  - 背景为 black。
  - 网格中有若干个由同一颜色构成的 4-连通实心凸形对象（如矩形、直角三角形等简单轴对称形状）。每个对象的尺寸不同。
  - 每个对象恰好有一个像素被替换为 azure，该 azure 像素位于对象的某一条边的中点位置，充当方向指示器：azure 像素所在的边即为对象的"前方"朝向。

- `Rule`：
  - 对每个对象，确定 azure 像素所在边的朝外法线方向（上、下、左或右），即为该对象的印章方向。
  - 从对象出发，沿印章方向逐步放置缩小副本。第一个副本为原对象去掉最外一圈像素后的形状（即将对象的边界向内收缩一像素），第二个副本为在第一个副本基础上再收缩一圈，以此类推，直到收缩后形状为空为止。
  - 每个副本紧贴前一个形状放置：副本的靠近原对象一侧的边与前一个形状的远离原对象一侧的边相距恰好一个像素的间隔。
  - 每个副本在垂直于印章方向的维度上与原对象居中对齐。
  - 副本颜色与原对象主体颜色相同。原对象保持不变（包括 azure 像素）。若副本位置超出网格边界则截断不绘制。

- `Key insight`：第一层推理是发现 azure 像素标记了对象的朝向（位于哪条边的中点决定了法线方向）；第二层推理是发现副本序列的生成规则——逐步剥去外层轮廓进行缩小，并沿指定方向等距排列且居中对齐。对象的形状决定了缩小后每一步的具体图案，解题者需要理解"去掉最外一圈"这一几何操作。
</new_puzzle>

- `description`：将散落在网格中的彩色碎片按照隐含的拼图边缘互锁规则拼合到中央灰色底板上，拼合顺序由碎片面积从大到小决定。

- `Input structure`：
  - 背景为 black。
  - 网格中央有一个由 grey 像素填充的矩形底板区域。底板边缘有若干单像素的凸起（从底板向外突出一格的 grey 像素）和凹槽（底板边缘缺少一格的 black 空位）。
  - 网格其余区域散布着若干彩色碎片（每个碎片为一种非 black、非 grey 的颜色，形成 4-连通区域）。每个碎片的形状为矩形减去若干边缘像素后再加上若干突出像素，形成互锁边缘。
  - 每个碎片的某些边缘有凸起（额外突出的像素）和凹槽（缺失的像素），这些凸起和凹槽恰好与底板上（或已拼合碎片上）的凹槽和凸起一一对应。

- `Rule`：
  - 按碎片面积从大到小排序处理每个碎片。
  - 对每个碎片，在底板的四条边上寻找一个位置，使碎片的互锁边缘（凸起对凹槽、凹槽对凸起）与底板当前状态完全吻合。碎片可能需要旋转 0、90、180 或 270 度中的某一个角度才能匹配。
  - 将碎片平移到匹配位置，碎片像素覆盖底板上对应的 grey 像素，同时碎片的凸起填入底板的凹槽。
  - 拼合后，底板的轮廓形状更新（碎片成为底板的一部分，可能产生新的凹凸供后续碎片对接）。

- `Key insight`：第一层推理是发现碎片与底板之间的凸凹互锁关系（类似拼图的锯齿边）；第二层推理是发现拼合顺序由面积从大到小决定；第三层推理是发现碎片可能需要旋转才能与底板吻合。三层规则共同决定唯一输出。
</new_puzzle>
