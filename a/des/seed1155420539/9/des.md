用网格边缘的彩色刻度尺确定每个内部色块的裁剪窗口，再按刻度尺颜色顺序拼接裁剪结果。

Input structure：
- 背景为Black。
- 网格的上边缘和左边缘各有一排彩色刻度像素，每个刻度像素占一格，颜色各不相同。上边缘的刻度像素标记列坐标，左边缘的刻度像素标记行坐标。
- 网格内部（不含边缘刻度行/列）散布着若干单色矩形色块，每个色块的颜色恰好与某个上边缘刻度像素和某个左边缘刻度像素的颜色相同。
- 每个色块严格位于其对应的行刻度和列刻度所指示的行列交叉区域内，但色块尺寸小于该区域，周围填充背景色。

Rule：
- 对每个内部色块，找到与其颜色相同的上边缘刻度像素的列位置和左边缘刻度像素的行位置，确认该色块位于两者交叉的区域。
- 将色块裁剪为其最小包围矩形。
- 按照左边缘刻度像素从上到下的顺序排列行，按照上边缘刻度像素从左到右的顺序排列列，将所有裁剪后的色块拼接成一个紧凑的输出网格。行与行之间、列与列之间不留间隔，空缺位置用背景色填充。

Key insight：
- 边缘刻度尺同时充当了色块的寻址索引和输出排列的顺序指令；解题者必须先发现边缘颜色与内部色块颜色的对应关系，再意识到刻度顺序决定了拼接顺序。
</new_puzzle>

<new_puzzle>
根据框架内部标记像素的相对位置，选择对应方向的箭头模板，并用框架颜色绘制箭头替换框架。

Input structure：
- 背景为Azure。
- 网格中散布着若干大小相同的正方形空心框架（边框宽1像素），每个框架颜色各不相同。
- 每个框架的内部恰好有一个单像素标记，标记颜色为Grey，标记位于框架内部的上、下、左、右四个边缘中点位置之一（不在角落）。
- 网格的一个角落区域（与框架不重叠）放置着四个用Maroon绘制的箭头模板，分别指向上、下、左、右。每个箭头模板为5×3或3×5的像素图案：一个三角形箭头加一条单像素宽的短尾巴。四个箭头模板排列在2×2的小区域中，之间用背景色分隔。

Rule：
- 找到角落的四个箭头模板，识别每个模板指向的方向（上、下、左、右）。
- 对每个框架，检查其内部Grey标记像素的位置：标记靠近框架内部的上边→指向上，靠近下边→指向下，靠近左边→指向左，靠近右边→指向右。
- 将框架（包括边框和内部）替换为对应方向的箭头模板，箭头居中放置在框架原来的位置，箭头颜色改为该框架的边框颜色。
- 移除角落区域的模板（用背景色填充）。

Key insight：
- 第一层推理：Grey标记在框架内部的偏移方向编码了"选哪个箭头"；第二层推理：角落的Maroon模板是形状字典，需要按方向匹配后再用框架自身颜色重绘。
</new_puzzle>

<new_puzzle>
将分散的同色像素对视为"弹性绳"的两端，沿绳方向在两端之间填充该颜色，但遇到障碍色带时绳子绕行到带的另一侧继续延伸。

Input structure：
- 背景为Black。
- 网格中有若干条完整的水平或垂直Grey色带（宽1像素，贯穿网格全宽或全高），将网格分割成若干矩形区域。
- 在这些区域中，散布着成对的同色单像素点（每种非背景、非Grey颜色恰好出现两个像素）。同一对像素可能在同一区域，也可能被一条或多条Grey色带隔开。

Rule：
- 对每对同色像素，确定它们之间的连线方向（两点组成的最短轴对齐路径：先水平再垂直，或先垂直再水平——选择穿越Grey色带次数较少的路径）。
- 沿该路径，在两个端点之间的所有背景像素上填充该颜色。
- 当路径遇到Grey色带时，不在色带上绘制，而是跳过色带的1像素宽度，在色带另一侧继续绘制。Grey色带本身保持不变。
- 如果两条路径穿越Grey色带次数相同，选择先沿水平方向移动的路径。

Key insight：
- 解题者首先要识别出同色像素的配对关系，然后发现Grey色带是不可穿越的障碍（连线在色带处中断但在另一侧继续），最后需要归纳出路径选择的优先规则（最少穿越次数）。
</new_puzzle>

<new_puzzle>
用小色块的堆叠层数对大区域进行等高线式的逐层收缩填色。

Input structure：
- 背景为Black。
- 网格左半部分包含一个大的不规则单色闭合区域（颜色A，如Blue），区域内部为背景色。
- 网格右半部分包含若干小色块，每个小色块是一个由不同颜色像素垂直堆叠的小柱（宽1像素，高度1~5像素不等）。每个小柱中的颜色从下到上各不相同，且不包含颜色A和背景色。

Rule：
- 数出右半部分小柱的数量N。
- 对左半部分的闭合区域，从外边界开始，向内逐层收缩（类似剥洋葱，每层收缩1像素）。第一层（最外圈）保持颜色A不变。
- 从第二层开始，依次用右半部分各小柱从下到上的第一个颜色、第二个颜色……进行填色。具体地：所有小柱底部的颜色用于第二层，所有小柱底部第二格的颜色用于第三层，以此类推。如果多个小柱在同一层提供不同颜色，使用出现次数最多的那个颜色。
- 收缩层数超过小柱最大高度后，剩余内层全部填充背景色。

Key insight：
- 第一层推理：右侧小柱不是独立对象，而是一个"调色板堆栈"，从下往上读取提供了逐层填色的颜色序列；第二层推理：左侧大区域的等高线式收缩将这些颜色逐层映射到空间结构上，形成嵌套环形带。
</new_puzzle>

<new_puzzle>
识别网格中被遮挡的完整形状，通过遮挡顺序的逆序将所有形状分离并从前到后排列到输出中。

Input structure：
- 背景为Black。
- 网格中有若干个不同颜色的矩形色块，它们相互重叠（部分遮挡），如同一叠纸张从上往下堆叠。被上层矩形遮挡的部分不可见。
- 每个矩形的颜色各不相同，至少有一部分可见。
- 网格底部有一行单像素高的Grey分隔条。

Rule：
- 推断每个矩形的完整尺寸：对每个可见颜色，找到该颜色所有可见像素的包围矩形，这就是该矩形的实际完整尺寸（因为矩形是轴对齐的，被遮挡的部分不影响包围矩形的行列范围）。
- 确定遮挡顺序（即图层从前到后的顺序）：如果颜色A的像素在颜色B的包围矩形范围内出现，说明A在B的上层。
- 输出中，移除Grey分隔条，将所有矩形按从最上层到最底层的顺序从左到右水平排列，每个矩形之间留1列背景色间隔。每个矩形用其完整尺寸绘制（恢复被遮挡部分）。

Key insight：
- 第一层推理：利用轴对齐矩形的性质，仅凭可见像素的行列极值即可还原完整形状；第二层推理：遮挡关系蕴含在"一个颜色出现在另一个颜色的包围矩形内部"这一视觉线索中，由此确定前后图层排序；第三层推理：输出的排列顺序是图层深度顺序而非空间位置顺序。
</new_puzzle>

<new_puzzle>
将网格中的彩色种子像素按颜色分组，每组生长为以种子为中心的十字形，十字臂长度等于该颜色组内种子的数量，臂之间相互裁剪按颜色优先级决定归属。

Input structure：
- 背景为Black。
- 网格中散布着若干单像素的彩色种子点，共使用2~4种非背景颜色，每种颜色出现1~4次。
- 网格的右下角有一个小的颜色优先级图例：2~4个颜色像素从上到下垂直排列，排在上方的颜色优先级更高。

Rule：
- 对每种颜色，数出该颜色的种子像素数量，记为该颜色的"生长半径"R。
- 从每个种子像素出发，向上、下、左、右四个方向各延伸R个像素，形成一个十字形（包含种子本身）。超出网格边界的部分裁剪掉。
- 当两个不同颜色的十字形在某个像素位置重叠时，查看右下角的优先级图例，优先级高的颜色占据该像素。
- 优先级图例本身在输出中被移除（用背景色填充）。

Key insight：
- 第一层推理：每种颜色的种子数量不仅仅是分组信息，同时编码了十字臂的生长长度——数量越多，扩展越远；第二层推理：重叠冲突的解决方式不是按空间远近，而是由角落里一个容易被忽略的小图例决定的颜色优先级来裁定。
</new_puzzle>

<new_puzzle>
将网格中的多条折线按交叉点处的颜色混合规则重新着色，交叉点颜色由参与交叉的两条折线颜色在色环上的中间色决定。

Input structure：
- 背景为Black。
- 网格中有若干条单像素宽的折线（每条折线由水平和垂直线段交替连接而成），每条折线一种颜色，使用的颜色来自以下有序色环：Red → Orange → Yellow → Green → Azure → Blue → Magenta → Red（循环）。
- 折线之间可能在某些像素位置交叉。交叉点处两条折线共享同一个像素格。
- 网格边缘有一圈1像素宽的Grey边框。

Rule：
- 找到所有交叉点（即同时属于两条折线路径的像素）。
- 对每个交叉点，确定经过该点的两条折线的颜色，在色环上找到两者之间较短弧的中间色（如Red和Yellow之间的中间色为Orange；Green和Blue之间的中间色为Azure）。
- 将交叉点像素涂为该中间色。
- 非交叉点的折线像素保持原色不变。Grey边框保持不变。

Key insight：
- 第一层推理：需要追踪每条折线的完整路径以识别交叉点，而非简单地寻找某种颜色的像素；第二层推理：交叉点的颜色不是两条线中任何一条的颜色，而是通过一个隐含的色环关系计算出的中间色——解题者必须从多个交叉点的颜色样例中归纳出色环顺序及中间色规则。
</new_puzzle>
