<description>
根据每个封闭区域内部"种子像素"的颜色，从对应颜色的图例条中读取填充图案，将该图案平铺填满整个封闭区域。

Input structure:
- 背景为黑色。网格中有若干用灰色像素围成的封闭区域（形状各异，均为矩形，内部面积不超过 6×6）。
- 每个封闭区域内部恰好有一个非黑色、非灰色的单像素"种子像素"，颜色各不相同。
- 网格的最底部若干行是"图例区"：每种种子颜色对应一行，行首有一个该颜色的标记像素，紧随其后是一个用多种颜色绘制的 1×N 短条纹图案（N 为 2 到 5 之间），条纹图案之间用黑色间隔与下一行图例分隔。

Rule:
- 对每个封闭灰色区域，找到其内部的种子像素颜色。
- 在图例区中找到该颜色对应的条纹图案。
- 从封闭区域的左上角开始，将该条纹图案在水平方向上重复平铺、在垂直方向上逐行复制，填满整个封闭区域的内部（覆盖种子像素，但不覆盖灰色边框）。超出区域边界的部分裁掉。
- 图例区在输出中被移除（输出网格高度缩小）。

Key insight:
- 解题需要两层推理：第一层是发现种子像素与图例行的颜色匹配关系；第二层是理解图例中的短条纹是一个水平重复单元，需要被平铺而非直接粘贴。
</description>

<description>
将每个前景对象沿其形状不对称"尾巴"的反方向平移，平移距离等于尾巴的像素长度。

Input structure:
- 背景为黑色。网格中有若干单色的 4-连通前景对象，每个对象形状紧凑（包围盒不超过 4×4），各自颜色互不相同。
- 每个对象的形状都有且仅有一个"尾巴"：即从对象主体延伸出的一条单像素宽的直线段（水平或垂直方向），尾巴末端像素在该对象内仅有一个 4-连通邻居。尾巴的方向定义为从对象主体中心指向尾巴末端的基本方向（上/下/左/右）。
- 尾巴长度为 1 到 3 个像素不等。

Rule:
- 对每个对象，确定其尾巴方向（上/下/左/右）。
- 计算该对象的尾巴长度：沿尾巴方向，从主体边界出发，尾巴部分连续像素的数量。
- 将整个对象沿尾巴方向的**反方向**平移，平移步数等于尾巴长度。
- 原位置清为黑色，新位置绘制该对象。各对象在输入中保证平移后不会超出网格边界也不会与其他对象重叠。

Key insight:
- 尾巴方向和平移方向相反——对象向远离尾巴的方向移动；平移距离编码在对象自身的局部形状中（尾巴的像素长度），不是全局属性。解题者需要同时识别形状的方向性不对称特征并从中提取数值，两个推理步骤缺一不可。
</description>

在由分隔线划分的子区域网格中，根据每个子区域四条边上的彩色标记数量，在区域内部的四个角落分别生成尺寸由对应两条边的标记数决定的实心矩形块。

Input structure:
- 背景为黑色。一条 Azure 色的完整横线和一条 Azure 色的完整竖线将网格分成四个矩形子区域（2×2 布局）。
- 每个子区域的四条边（紧贴分隔线或网格边缘的那一行/列）上散布着若干单像素的彩色标记，每个子区域内所有标记同色，但不同子区域的标记颜色不同。
- 子区域内部（不含边缘行/列）初始全为黑色。

Rule:
- 对每个子区域，分别统计其上边、下边、左边、右边上的标记数量，记为 T、B、L、R。
- 在该子区域内部的四个角落各放置一个同色（与标记同色）实心矩形块：左上角矩形高 T、宽 L；右上角矩形高 T、宽 R；左下角矩形高 B、宽 L；右下角矩形高 B、宽 R。每个矩形紧贴对应的角落。
- 若某条边上标记数为 0，则与该边相关的角落矩形对应维度为 0（不绘制）。
- 四个角落矩形可能重叠，重叠部分仍为同色。Azure 分隔线保持不变。

Key insight:
- 解题需要三层推理：第一层识别分隔线将网格分成子区域；第二层发现每条边上的标记数独立控制一个维度的填充量；第三层理解四条边的标记数通过"行维度×列维度"的交叉组合方式决定四个角落矩形的尺寸，而非简单地把标记总数个像素随意摆放。
</description>

<description>
将网格中散落的同色直线段碎片平移到多层同心矩形框架中，精确填补每层框架的唯一缺口。

Input structure:
- 背景为黑色。网格右侧有一个由多层同心矩形框构成的"框架"结构（通常 2 到 4 层），每层框用不同颜色绘制（例如从外到内为 Red、Green、Blue），每层框是一个单像素宽的完整矩形环，但恰好缺少一段连续的边段（缺口），缺口位置各层不同（可能在上边、下边、左边或右边）。
- 网格左侧散落着若干彩色直线段碎片（水平或垂直的单像素宽连续条），每个碎片的颜色与框架某一层相同。
- 每种颜色在碎片中和框架缺口中各出现恰好一次，且碎片的长度和方向（水平或垂直）与对应层缺口完全吻合。

Rule:
- 对每个碎片，根据颜色找到框架中同色的那一层。
- 确定该层缺口的位置和方向。
- 将碎片平移（不旋转）到缺口位置，使其恰好填补该层的缺失边段，令该层成为完整的矩形环。
- 碎片原位置清为黑色。框架和背景其余部分保持不变。

Key insight:
- 颜色匹配只是第一层推理（将碎片与框架层配对）；第二层需要理解每层框架的拓扑结构——识别每层矩形环的唯一缺口位置和朝向——才能确定碎片的精确目标坐标。碎片不是填入框架内部空间，而是修补矩形环边框上的断口。
</description>

<description>
根据每个 C 形对象的开口方向将其分类，然后将同类对象重新排列到输出网格的对应象限中。

Input structure:
- 背景为黑色。网格中有若干同色（例如全部为 Green）的前景对象，每个对象都是一个 3×3 的"C 形"图案：即 3×3 实心方块去掉某一边中间位置的一个像素后剩下的 8 像素形状。去掉的那个像素所在的边即为该对象的"开口方向"（上/下/左/右四种可能）。
- 所有对象彼此不重叠、不相邻，对象数量为 4 到 8 个，分布在网格各处。

Rule:
- 输出网格的尺寸与输入相同，用两条穿过网格中心的黑色十字线（一条水平、一条垂直，各占一个像素）将输出分为四个等大象限。
- 开口朝上的对象放入左上象限；开口朝右的对象放入右上象限；开口朝左的对象放入左下象限；开口朝下的对象放入右下象限。
- 在每个象限内，对象从该象限的左上角开始，按行优先顺序紧密排列，相邻对象之间留一个像素的黑色间隔。
- 若某个方向没有对象，该象限全为黑色。

Key insight:
- 第一层推理要发现所有对象虽然颜色相同、大小相同，但形状上存在一个微妙的单像素差异（开口位置），这个差异是分类的唯一依据。第二层推理要从多个样例中归纳出开口方向与象限位置之间的固定映射关系（例如开口朝上→左上），这一对应法则不是显而易见的，需要跨样例比较才能确认。
</description>

<description>
将每个灰色 L 形"指针"对象沿其缺角方向做射线扫描，找到第一个目标色块并用该色块的颜色重绘指针自身。

Input structure:
- 背景为黑色。网格中有两类对象：
  - "指针对象"：灰色的 L 形三像素图案，即 2×2 方块去掉一个角后剩余的三个像素。被去掉的角所在的方向即为该指针的"指向方向"（右下角缺失则指向右下，以此类推，共四个对角方向）。
  - "目标对象"：各种非灰色、非黑色颜色的 2×2 实心方块，散布在网格中。
- 每个指针对象沿其指向方向的对角线延伸，必定会在该对角线上遇到恰好一个目标对象的某个像素（中间可能隔着若干黑色像素）。

Rule:
- 对每个灰色指针对象，确定其缺角方向（左上/右上/左下/右下）。
- 从缺角位置出发，沿该对角方向逐步扫描（每步行列各加减 1），找到第一个非黑色像素所属的目标方块。
- 读取该目标方块的颜色。
- 将该指针对象的三个灰色像素全部重绘为目标方块的颜色，保持指针形状和位置不变。
- 所有目标方块本身保持不变。

Key insight:
- 第一层推理需要识别灰色 L 形的缺角方向即为"指向"方向——这是对角线方向而非正交方向，且由缺失像素的位置编码而非现有像素的排列编码。第二层推理需要理解灰色对象是"读取器"：它从远处的目标方块获取颜色并自我变色，而目标方块是信息源保持不变。
</description>

<description>
在包含多条水平传送带的网格中，根据传送带两端的端点颜色筛选并分拣带上的货物像素。

Input structure:
- 背景为黑色。网格中有若干条水平的灰色条带（高度为 1 像素，长度各异），每条条带代表一条"传送带"，不同传送带之间有至少两行黑色间隔。
- 每条传送带的最左端像素和最右端像素分别被替换为一个非灰色的彩色"端点标记"（例如左端为 Red，右端为 Blue），这两个端点颜色互不相同。
- 传送带上方紧邻的那一行中，在传送带水平范围内散布着若干单像素的彩色"货物"，每个货物可能是各种颜色。

Rule:
- 对每条传送带，读取其左端点颜色 L 和右端点颜色 R。
- 传送带上方的货物中，颜色为 L 或 R 的货物被保留；颜色既非 L 也非 R 的货物被清除为黑色。
- 保留的货物进一步分拣：颜色为 L 的货物向左平移，在传送带范围内紧靠左端点正上方依次向右排列（保持在上方那一行，互相紧邻无间隔）；颜色为 R 的货物向右平移，在传送带范围内紧靠右端点正上方依次向左排列。
- 传送带本身（包括端点标记）保持不变。

Key insight:
- 第一层推理需要发现端点标记不仅标示传送带的边界，还定义了该传送带"允许通过"的颜色集合，充当筛选器的角色。第二层推理需要发现被保留的货物不是原地不动，而是按其颜色被"吸引"到对应颜色端点的那一侧紧密聚集，实现了按颜色的双向分拣。
</description>
</new_puzzle>
