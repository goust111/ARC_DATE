Build nested square frames from a stack of horizontal color stripes.

Input structure:
- Full-width horizontal stripes of distinct non-bg colors, stacked vertically.
- Each stripe has uniform color and variable height (1-4 rows).

Rule:
- Read stripes bottom to top.
- Bottom stripe becomes the center solid square with side length = stripe height.
- Each subsequent stripe wraps the current shape with a square frame of thickness = stripe height, in that stripe's color.

Key insight: Stripe height doubles as both frame thickness and (for the innermost) center-square side length; output dimensions are fully determined by the stripe heights.

<description>
Decode the colored slot map inside the marked motif and rebuild the motif lattice with those colors.

Input structure:
- A blank background surrounds a rectangular lattice of identical motifs.
- The motif rows and columns are separated by one background line.

Rule:

- Read the marked motif's odd internal slots as the color map for the R by C output motifs.
- Slots that still contain the repeated motif color map to that repeated motif color.
- Rebuild the compact lattice on a canvas filled with the repeated motif color,
  painting each motif mask with its decoded color.

Key insight:
- The holes and filled odd slots inside one motif are a miniature legend for recoloring the entire repeated motif lattice.

<description>
Move the repeated boundary color's rectangles one block inward while leaving singleton boundary rectangles in place.

Input structure:
- The background is the most common color.
- Foreground objects are solid monochrome rectangles touching a grid corner.
- Exactly one foreground color appears as multiple separate 4-connected objects; other colors appear once.

Rule:
- Clear the multiple objects of the repeated color from their original positions.
- For each cleared rectangle, translate it away from the row and column border it touches by exactly its height and width.
- Keep singleton-color objects unchanged; overlapping translated rectangles of the same color merge.

Key insight:
- Multiplicity selects the moving color, and each boundary rectangle's touched edges determine its inward diagonal translation.

<reference_puzzle index="5" source="eval" puzzle_id="800d221b" lines="7-22">
<description>
Recolor a path-network by adjacent seed regions.

Input structure:
- bg = most common color.
- Path color P forms a thin orthogonal network with a solid square hub (NxN).
- Seed colors appear in colored regions (non-bg, non-P) adjacent to path branches.

Rule:
- Infer P as the non-bg color whose largest component is most network-like.
- Find the largest solid k×k all-P square (the hub); exclude it from recoloring.
- Recolor each path branch to the seed-region color it touches most.
- Recolor the hub center pixel to the seed whose branches touch the hub most.

Key insight: The hub stays uncolored; branches inherit color from adjacent seed regions by adjacency count.
</description>

<description>

Rule:

Reorder and stack rectangles by proximity to two colored edge lines.

<reference_puzzle index="8" source="train" puzzle_id="b1986d4b" lines="19-37">
<description>
Render the filled-square object counts as compact nested stacks ordered by count rank.

Input structure
A large noisy grid has a dominant background, scattered non-square noise, and
filled monochrome square objects. Each square side length has exactly one
object color, and side lengths form consecutive sizes.

Rule
Ignore non-square components. If the lowest square in the scene is of the
smallest side length, treat that one smallest square as a distractor and do
not count it. For count rank k from left to right, create one block from all
square sizes with at least k remaining objects; draw larger squares first and
smaller squares over their upper-left corner, then append one background
separator column.

Key insight
The output is a count histogram of square side lengths, but each histogram
slot is rendered as nested upper-left square masks using the side colors.
</description>

<description>
Slide yellow pixels inside walled regions in the direction dictated by border-legend arrows.

Input structure:

Rule:

<description>
Crop out the grid half containing the two aligned marker pixels, then erase the markers to background.

Input structure
- The grid has a dominant background color and one non-background marker color
  that appears as exactly two cells.
- The marker cells are aligned either in one row or one column and both lie
  in the same half along that direction.
- Other non-background pixels are content inside one or both halves.

Rule
- If the markers share a row, keep the left or right half whose columns
  contain them.
- If the markers share a column, keep the top or bottom half whose rows
  contain them.
- In the kept half, recolor the marker pixels to the background color.

Key insight
- The two marker pixels are not part of the picture; their alignment and
  half-position identify which half of the doubled canvas is the answer.
</description>

<description>
Connect same-colored foreground components with one-cell-wide orthogonal paths around teal wall segments.

Input structure
- The dominant color is the background.
- Teal cells are fixed wall segments and are never source connectors.
- Other foreground colors appear as one or more 4-connected components; colors with a single component stay unchanged.

Rule
- For each non-background, non-teal color, read its 4-connected components in row-major order.
- Connect each consecutive pair by the shortest clear L-shaped path between the two components.
- Clear paths may pass only through background or the same color, and they preserve the previous travel axis when both bends are possible.

Key insight
- The output is not a global recolor: each color traces a routed chain through its own components while teal cells and other colors act as blockers.

Advance the marker from one half of a vertical bar to the same half of the next longer bar.

Rule

<description>
Align parallel colored line segments so they all share the same start and end positions as a reference line.

Input structure:
- bg = most common color.
- Several parallel line segments (diagonal, horizontal, or vertical), each a different color, running in the same direction but starting/ending at different positions.

Rule:
- Detect the dominant direction shared by all segments.
- Pick the median segment (by perpendicular offset) as the reference.
- Shift every segment along the shared direction so its start aligns with the reference's start, then trim or extend it to match the reference's length.
- Grid size stays the same; isolated single pixels are untouched.

Key insight: The reference is the median line, not the longest; all segments are snapped to its extent regardless of their original length.
</description>

<description>
Untangle overlapping colored rectangular frames into concentric square frames ordered by their visible crossings.

Input structure
- The background contains several one-cell-thick axis-aligned rectangular frames, one color per frame.
- Frames overlap, and the visible color at an overlap records a directed crossing from the hidden frame to the visible frame.
- Each foreground color still has visible pixels on the perimeter of its full rectangular bounding box.

Rule
- Infer each color's full rectangular frame from the bounding box of its visible pixels.
- Add a directed edge A -> B when B is visible at a crossing of A and B's frame perimeters.
- Find the unique path that visits every frame color once, then render those colors as one-pixel-thick concentric square frames from outside to inside.

Key insight
- The output is not a crop of the input; the crossing graph gives a single frame order, and that order is redrawn as nested rings.

<description>
Recover each partially hidden 6x6 ring sprite and stack complete copies from top layer to bottom layer.

- The dominant color is the background.

- The output is not a crop of the scene; it is the layer stack of complete
  ring sprites reconstructed from their visible fragments.
