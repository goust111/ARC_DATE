description：根据框架内部孔洞的形状在外部精灵库中匹配对应精灵，再依据精灵自身的面积大小决定孔洞的填充顺序与叠加优先级。

Input structure：
- 背景为黑色。网格中有一个大型灰色(grey)矩形框架，框架内部包含若干不规则形状的孔洞（黑色区域）。
- 框架外部散布着若干小型单色精灵（连通分量），每个精灵由不同的非黑非灰颜色构成（如红色、蓝色、绿色、黄色等）。
- 部分孔洞在空间上互相重叠（即共享若干像素位置）。

Rule：
- 第一步：将每个外部精灵的形状（忽略颜色）与框架内的孔洞形状进行匹配（允许旋转 0°/90°/180°/270°，不允许翻转）。每个精灵恰好匹配一个孔洞。
- 第二步：确定填充优先级——观察所有精灵在网格外部占据的面积（像素数），面积越大的精灵优先级越高。
- 第三步：按优先级从低到高依次将匹配到的精灵颜色填入对应孔洞。后填入的颜色会覆盖先填入的颜色，因此在重叠区域中，面积更大（优先级更高）的精灵颜色最终显示在顶层。
- 输出仅包含框架的边界框区域，框架本身保持灰色不变。

Key insight：匹配孔洞与精灵需要空间形状推理（第一层），而确定重叠区域的最终颜色则需要发现"精灵面积决定叠加优先级"的隐含规则（第二层）——面积大的精灵后绘制，因此在重叠处胜出。
</new_puzzle>

description：沿灰色路径网络传播信号，在每个交叉节点处根据可选分支数量选择转向策略，最终将终点像素染成信号源的颜色。

Input structure：
- 背景为黑色。网格中有由灰色(grey)像素构成的单像素宽路径网络，路径沿水平和垂直方向延伸，在某些位置形成十字或丁字交叉。
- 网络中散布着若干彩色"信号源"像素（红色、蓝色、绿色等），每个信号源位于某条路径的一个端点上（路径的末端，仅有一个灰色邻居方向）。
- 网络中还有若干橙色(orange)像素，每个也位于路径的端点上，这些是"终点"。

Rule：
- 每个信号源沿其唯一的灰色邻居方向发射信号，信号沿灰色路径传播。
- 当信号到达一个交叉节点（有三个或四个灰色正交邻居的位置）时，需要决定转向：统计该节点上除了信号来源方向之外还有多少条可通行的灰色路径分支。若只有一条分支（丁字路口且来自直通方向），信号直接进入该分支；若有两条分支（丁字路口且来自侧面），信号选择右转方向的分支；若有三条分支（十字路口），信号选择左转方向的分支。
- 信号持续传播，直到到达一个端点像素（橙色终点或网格边缘）。
- 将信号最终到达的橙色终点像素重新染成该信号源的颜色。路径本身保持灰色不变。若信号到达网格边缘而非橙色终点，则不产生任何变化。

Key insight：第一层推理需要识别路径网络的拓扑结构和端点角色（信号源vs终点）；第二层推理需要发现交叉节点处的转向规则取决于可选分支的数量——这不是简单的"一直向前"或"一直右转"，而是根据路口类型动态切换转向策略。
</new_puzzle>

description：将散落的彩色碎片按颜色分组拼入各自颜色对应的模板轮廓中，碎片在模板内的放置位置由碎片上的黄色锚点标记与模板上的对应锚点对齐决定。

Input structure：
- 背景为黑色。网格被一条垂直的洋红色(magenta)分割线分为左右两半。
- 左半部分包含若干用不同颜色绘制的空心轮廓（仅边框，内部为黑色），每个轮廓是一个不规则但连通的封闭形状。每个轮廓的边框上恰好有一个像素被替换为黄色(yellow)，作为轮廓的锚点。
- 右半部分散布着若干小型实心碎片（连通分量），每个碎片的主体颜色与左侧某个轮廓的边框颜色相同。每个碎片内部恰好有一个像素为黄色，作为碎片的锚点。
- 同一颜色可能有多个碎片，但它们合在一起恰好能无重叠无间隙地铺满对应轮廓的内部区域。

Rule：
- 第一步：按颜色将右侧碎片与左侧轮廓配对。

- 第三步：将含锚点的碎片平移，使碎片的黄色像素与轮廓的黄色像素正交相邻（碎片锚点放在轮廓锚点向内侧偏移一格的位置）。该碎片就位后，剩余碎片必须恰好填满轮廓内部剩余的空间（剩余碎片仅可平移，不可旋转或翻转）。
- 第四步：输出为左半部分的网格，轮廓边框保持不变，轮廓内部被对应颜色的碎片填满（碎片使用其主体颜色绘制，包括锚点位置也改回主体颜色）。

Key insight：颜色匹配碎片与轮廓是第一层；发现黄色锚点作为定位基准是第二层——锚点碎片先固定位置，约束了其余碎片的唯一放法，使得看似复杂的拼图问题变为确定性操作。
</new_puzzle>

Input structure：
- 背景为黑色。网格顶部有一行色带图例：色带由若干颜色块组成，每个颜色块宽1列。色块之间用黑色列间隔开。每个色块的高度为2行或3行：高2行表示"水平方向"，高3行表示"垂直方向"。色带整体占据网格的前3行。

- 每个封闭区域内部恰好有一个非黑非灰的彩色像素，作为"种子"。种子的颜色一定在色带图例中出现。

Rule：
- 第一步：读取色带图例，建立颜色到方向的映射（高2行对应水平，高3行对应垂直）。
- 第二步：对每个封闭区域，找到其内部的种子像素及其颜色。

- 第四步：条纹仅填充在封闭区域内部（不覆盖灰色边界线），种子像素本身被条纹覆盖（即种子位置也变为条纹的一部分）。
- 输出包含完整网格（含色带图例），色带和灰色边界保持不变。

Key insight：第一层推理需要发现色带中色块高度编码了填充方向（而非面积或其他属性）——这一编码方式并不直观；第二层推理需要理解条纹的间距规律和起始位置（从种子行/列出发，间隔一行/列），将方向信息转化为具体的空间填充操作。

<new_puzzle>
description：在网格中找到由围墙包围的房间，根据房间门洞的朝向和数量从外部标记库中选取对应的符号印章，将其旋转后印入房间中心。

Input structure：
- 背景为黑色。网格中有若干由蓝色(blue)像素构成的矩形"围墙"，每个围墙是一个完整的矩形环，但每面墙上有1到3个单像素宽的缺口（"门洞"）。每个门洞恰好位于墙的某一条边（上、下、左、右）的中央位置。
- 网格的最右侧两列有一列纵向排列的"标记库"，由绿色(green)水平分隔线分成若干小格。每个小格内有一个由红色(red)像素绘制的小型符号（如单点、短横线、L形等），每个符号的像素数量各不相同（分别为1、2、3个像素）。标记库中的符号从上到下排列，像素数量递增（最上方的符号1个像素，往下依次2个、3个像素）。
- 每个符号还具有一个朝向特征：符号整体的形状存在一个"开口方向"或"指向方向"——单点无朝向；短横线的长轴方向为其朝向；L形的开口对角方向为其朝向。

Rule：
- 第一步：对每个房间，数出其门洞的总数 N（N 为 1、2 或 3）。
- 第二步：在标记库中选择像素数量等于 N 的那个符号。
- 第三步：确定房间的"主门方向"——若只有一个门洞，主门方向就是该门洞所在的边；若有多个门洞，取最靠上的边上的门洞方向，若上边没有门洞则依次检查左边、右边、下边。
- 第四步：旋转符号（0°/90°/180°/270°），使符号的朝向面朝房间的主门方向。对于单像素符号（N=1），无需旋转。
- 第五步：将旋转后的符号放置在房间内部区域的中心位置（内部区域的行中位数和列中位数交叉处）。符号使用红色绘制。
- 输出网格中围墙、门洞和标记库保持不变，仅在每个房间内部新增了对应的红色符号。

Key insight：第一层推理需要发现门洞数量与标记库符号的像素数量之间的对应关系（这是选择"印哪个章"的依据）；第二层推理需要发现主门方向的优先级规则并将其与符号的旋转对齐（这决定了"章怎么盖"）——两层规则共同作用才能完全确定输出。

<new_puzzle>
description：在棋盘格背景上，根据每个彩色对象轮廓上的凸凹特征确定其移动方向和配对关系，使凸出部分嵌入相邻对象的凹陷部分，完成榫卯式对称拼合。

Input structure：
- 背景为双色棋盘格（黑色与灰色交替）。网格中散布着若干彩色对象，每个对象是一个近似矩形的连通分量，但其某一条边上有一个单像素的凸出（多出一个像素），而对边上有一个单像素的凹陷（少一个像素形成的缺口）。
- 每个对象使用不同的非黑非灰颜色（如红色、蓝色、绿色等）。
- 对象总是成对出现，每对对象的凸出和凹陷在空间上可以互相匹配——即一个对象的凸出方向恰好朝向另一个对象的凹陷方向，且它们位于同一行或同一列上。

Rule：
- 第一步：对每个对象，识别其凸出所在的边（上、下、左、右）和凹陷所在的边。凸出方向即为该对象的"推动方向"。
- 第二步：找到配对——在凸出方向上搜索同一行或列上最近的另一个对象，该对象在面对方向上恰好有一个凹陷。
- 第三步：将两个配对对象沿凸出方向相向平移，直到凸出像素恰好嵌入凹陷像素的位置（即两个对象之间无间隙，凸出填满凹陷）。两个对象各自保持原有颜色不变。
- 第四步：拼合后的位置由两者的中点决定——双方各移动相同的距离（若总间距为奇数像素，则凸出方对象多移一格）。
- 输出中棋盘格背景保持不变，对象移到新位置后覆盖背景像素。

Key insight：第一层推理需要发现每个对象轮廓上凸出与凹陷的位置编码了移动方向和配对信息；第二层推理需要发现对象并非单向移动到对方位置，而是双方对称地相向靠拢并在中点处拼合——棋盘格背景帮助解题者验证移动距离的对称性。
</new_puzzle>

<new_puzzle>
description：通过颜色传导链在嵌套的同心矩形环之间传递颜色，每一层环的最终颜色由内层环角落标记的颜色查阅最外层边标记的方位来决定取色来源。

Input structure：
- 背景为黑色。网格中心有若干层同心矩形环（从内到外嵌套，共3至5层），每层环为单像素宽，初始均为灰色(grey)。
- 最内层环的内部区域填充有一个实心的彩色矩形（如红色），作为"核心色"。
- 从内数第二层起，每层环的四个角落像素中恰好有一个角被替换为某种非灰非黑的颜色，称为"角标记"。不同层的角标记颜色各不相同。
- 最外层环的四条边上，每条边的正中间像素被替换为某种非灰非黑的颜色，称为"边标记"。四个边标记的颜色各不相同，且恰好与各内层环的角标记颜色一一对应。

Rule：
- 第一步：最内层环（直接包围核心色的那一层）整层被重新染为核心色。
- 第二步：对于从内数第 k 层环（k 大于等于 2），找到其内层（第 k-1 层）环上的角标记颜色 C_inner。
- 第三步：在最外层环的四个边标记中，找到颜色等于 C_inner 的那个边标记，记录其所在边的方向（上、下、左或右）。
- 第四步：根据方向决定第 k 层环的颜色——上边：取第 k 层自身角标记的颜色；下边：取核心色；左边：取第 k-1 层环的最终颜色（即已经确定的染色结果）；右边：取第 k+1 层环的角标记颜色（若第 k 层已是最外层的内侧一层，则保持灰色）。
- 第五步：最外层环始终保持灰色，仅保留其边标记的原始颜色不变。内层环被染色后，角标记像素也随之被覆盖为该层的最终颜色。
- 输出为完整网格，背景和核心色不变，每层同心环被染为相应的确定颜色。

Key insight：第一层推理需要发现环的颜色不是由自身属性独立决定，而是通过内层角标记与外层边标记之间的颜色匹配形成传导链；第二层推理需要发现边标记所在的方位编码了一套选色规则（上/下/左/右各对应不同的取色来源），两层结合形成从内到外的级联染色逻辑。
</new_puzzle>
