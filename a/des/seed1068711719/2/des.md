- `description`：根据封闭区域内部种子颜色选取对应的边框染色方案，再将区域内部按种子位置生成对称图案。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干由 Grey 像素围成的封闭矩形区域（Grey 边框厚度为 1 像素）。
  - 每个封闭区域内部恰好有一个彩色种子像素（颜色为 Red、Blue、Green、Yellow 等之一），其余内部像素为 Black。
  - 网格边缘另有一组"图例条"：每条由一个颜色像素紧邻一个 2×2 的小图案组成（图案仅用该颜色和 Black 两色），图例条之间用 Black 行分隔。

- `Rule`：
  - 第一层推理——颜色匹配：将每个封闭区域内部的种子颜色与图例条中的颜色进行匹配，找到该颜色对应的 2×2 图案。
  - 第二层推理——图案铺设：以种子像素在区域内部的位置为中心，将匹配到的 2×2 图案沿四个象限做镜像对称铺贴，填满整个区域内部。铺贴时，图案在左上象限按原样放置，右上象限水平镜像，左下象限垂直镜像，右下象限双轴镜像。超出区域内部边界的部分裁剪。
  - Grey 边框和图例条保持不变。

- `Key insight`：
  - 种子颜色不是简单的填充色，而是在图例中查找对应微型图案的索引键；找到图案后还需要根据种子在区域中的位置进行四象限对称展开，两步推理缺一不可。
</new_puzzle>

- `description`：将散落的彩色碎片按形状互补关系配对拼合，再按拼合后面积从小到大垂直排列输出。

- `Input structure`：
  - 背景为 Black。
  - 网格中散布着偶数个单色 4-连通前景对象（碎片），每个碎片的颜色各不相同。
  - 碎片两两互补：同一配对的两块碎片可以无重叠、无间隙地拼成一个完整矩形（不需要旋转或翻转，仅需平移）。
  - 互补碎片的识别方式：将每块碎片放入其最小外接矩形，碎片占据的像素与 Black 空缺像素恰好互补；同一配对的两块碎片外接矩形尺寸相同，且一块碎片的形状恰好填满另一块碎片外接矩形中的空缺。

- `Rule`：
  - 第一步——配对：对所有碎片按最小外接矩形尺寸分组（尺寸相同的归为一组），同组内的两块碎片，其中一块的填充像素位置恰好是另一块在同尺寸矩形中的空缺位置，由此确定配对关系。
  - 第二步——拼合：将配对的两块碎片叠合到同一个外接矩形内，形成一个完整的双色矩形（两种碎片颜色各占其原本的像素位置）。
  - 第三步——排序输出：将所有拼合后的矩形按面积从小到大从上往下排列（相邻矩形之间空一行 Black），左对齐。输出网格宽度为最大矩形的宽度，高度为所有矩形高度之和加上间隔行数。

- `Key insight`：
  - 碎片的"互补"关系是核心洞见——不是按颜色或位置配对，而是按形状的正负空间配对；配对后还需按面积排序才能确定输出布局，构成两层非显然推理。
</new_puzzle>

- `description`：每个彩色对象沿其内部通道颜色指定的路径方向滑动，通道交汇处决定最终停靠位置。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干单色矩形"滑块"对象（颜色各异，如 Red、Blue、Green 等），每个滑块尺寸为 2×2 或 3×3。
  - 每个滑块内部正中央有一个不同颜色的单像素"方向标记"。
  - 网格中还有若干条单像素宽的彩色"轨道线"，轨道线从网格边缘延伸，颜色与某些方向标记颜色相同。
  - 轨道线只出现在水平或垂直方向上，且同一颜色的轨道线恰好有两条（一条水平、一条垂直），它们交叉形成一个交叉点。

- `Rule`：
  - 第一层推理——轨道匹配：将每个滑块内部方向标记的颜色与网格中同色轨道线配对。
  - 第二层推理——定位停靠：每个滑块移动到其匹配颜色的两条轨道线交叉点处，使滑块中心对准交叉点。
  - 移动后，滑块覆盖住交叉点及其周围的轨道线像素。滑块保留原色，方向标记像素也保留。轨道线未被滑块覆盖的部分保持不变。

- `Key insight`：
  - 方向标记不是指示移动方向的箭头，而是一个颜色索引，用于在网格中找到同色轨道线对；轨道线的交叉点才是真正的目的地坐标，解题者需要先建立"标记色→轨道对→交叉点"的推理链。

- `description`：根据框架内缺口的位置和数量，从相邻色块中选取对应行/列切片填入框架内部。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干个由同一颜色（如 Grey）绘制的矩形空心框架（边框宽度 1 像素），每个框架的某一条边上有 1 至 3 个单像素缺口（缺口处边框像素被替换为 Black）。
  - 每个框架的缺口所在边的外侧紧邻一个实心彩色矩形色块（色块与框架之间无间距，色块紧贴缺口所在边）。色块的长边与框架的该边等长，短边宽度不等（2 到 5 像素）。
  - 框架内部初始全为 Black。

- `Rule`：
  - 第一层推理——缺口定位与切片提取：对每个框架，找到其边框上的所有缺口位置。每个缺口在相邻色块中对应一行或一列（取决于缺口所在边是水平边还是垂直边）：若缺口在水平边（上边或下边），则缺口的列坐标对应色块中的一列；若缺口在垂直边（左边或右边），则缺口的行坐标对应色块中的一行。提取这些行或列作为"切片"。
  - 第二层推理——切片投射填充：将每条提取的切片从缺口位置向框架内部方向垂直投射，沿投射方向逐像素填入框架内部，直到碰到框架对面的边框为止。多条切片在框架内部交叉处，后投射的切片覆盖先投射的（按缺口从左到右、从上到下的顺序）。
  - 框架边框、色块和其余 Black 区域保持不变。

- `Key insight`：
  - 缺口不仅决定了"从哪里进入"，还同时确定了"从色块中取哪一条数据"——缺口位置同时编码了入口和数据索引两重信息；切片投射进框架后形成的交叉覆盖模式需要解题者理解投射顺序。
</new_puzzle>

- `description`：在网格中识别由屏障分割的若干区域，根据每个区域内散点的连线方向推断该区域的"旋转指令"，然后将区域内的主体图案按指令旋转。

- `Input structure`：
  - 背景为 Black。
  - 网格被 Maroon 色的完整行和完整列分割成若干矩形子区域（Maroon 线形成十字网格状分隔）。
  - 每个子区域内包含两类元素：
    - 一个由某种颜色（如 Blue、Green、Red 等）绘制的小型不规则图案（主体图案），占据区域内部的若干像素。
    - 恰好两个 Yellow 像素（散点标记），它们不与主体图案相邻。这两个 Yellow 像素构成一条隐含的有向线段：起点为更靠近区域左上角的那个（按行优先排序在前的），终点为另一个。

- `Rule`：
  - 第一层推理——方向解码：对每个子区域，根据两个 Yellow 标记的相对位置确定旋转指令：
    - 起点在终点正左方 → 不旋转（0°）。
    - 起点在终点正上方 → 顺时针旋转 90°。
    - 起点在终点正右方 → 旋转 180°。
    - 起点在终点正下方 → 逆时针旋转 90°。
    两个标记必定处于同行或同列（纯水平或纯垂直关系）。
  - 第二层推理——图案旋转：将该子区域内的主体图案以其自身最小外接矩形的中心为旋转中心，按解码出的角度旋转。旋转后的图案放回子区域原位（居中放置）。
  - Yellow 标记在输出中被擦除为 Black。Maroon 分隔线保持不变。

- `Key insight`：
  - Yellow 标记对不是装饰，而是一个方向编码器——两个点的相对空间关系映射为旋转角度；解题者必须先破解这套编码规则，再将其应用于同区域内的图案变换，形成"解码指令→执行变换"的双层推理。
</new_puzzle>

- `description`：将网格中每个封闭管道的入口颜色沿管道路径传播，在管道分叉处按分支长度分配不同的颜色混合结果。

- `Input structure`：
  - 背景为 Black。
  - 网格中有若干条由 Grey 像素构成的单像素宽管道路径（4-连通），管道可以有直角弯折但不会形成环路。
  - 每条管道是一棵树形结构：有一个根端点和若干叶端点（端点即只有一个 Grey 邻居的 Grey 像素）。
  - 根端点紧邻（4-连通）一个彩色像素（如 Red、Blue、Green 等），该彩色像素即为该管道的"源色"。叶端点不紧邻任何彩色像素。
  - 管道路径中恰好有若干个分叉点（拥有 3 个 Grey 邻居的 Grey 像素）。

- `Rule`：
  - 第一层推理——管道识别与源色确定：找出所有 Grey 连通分量（管道），对每条管道找到其紧邻彩色像素的端点作为根，该彩色像素的颜色为源色。
  - 第二层推理——路径染色：从根端点开始，沿管道路径向所有叶端点方向传播。每个管道像素被染成源色。但在每个分叉点处，执行如下规则：从分叉点到各分支叶端点的路径长度（像素数）不同——最长分支保持源色，最短分支将源色替换为 Orange，若有中间长度的分支则替换为 Yellow。
  - 第三层推理——分叉点本身的颜色取其最长分支的颜色（即源色）。分叉点到根方向的路径段始终保持源色。
  - 原始的彩色源像素保持不变。

- `Key insight`：
  - 管道不是简单地被源色填充——分叉点处的分支长度比较决定了各段的最终颜色。解题者需要先识别树形拓扑结构，再理解"长度→颜色分配"规则，最后追踪每段路径的归属，形成三层递进推理。
</new_puzzle>

<new_puzzle>
- `description`：从输入网格的局部对称破缺中推断被遮挡区域的原始颜色，并将遮挡物替换为正确的颜色来恢复全局对称。

- `Input structure`：
  - 网格背景为 Black，其上有一个大型多色图案。
  - 该图案本应具有 4 重旋转对称性（90° 旋转不变），但图案中有若干个矩形区域被 Azure 色完全覆盖（遮挡块），破坏了对称性。
  - 遮挡块的数量为 1 到 3 个，每个遮挡块是纯 Azure 色的实心矩形。
  - 图案的旋转中心在网格的几何中心。

- `Rule`：
  - 第一层推理——对称性识别：观察图案中未被遮挡的部分，确认图案具有 90° 旋转对称性（即绕中心旋转 90°、180°、270° 后与自身重合）。
  - 第二层推理——遮挡区域定位：找出所有 Azure 实心矩形区域，这些是被遮挡的位置。
  - 第三层推理——对称恢复：对于每个 Azure 像素，利用 90° 旋转对称性，在其旋转对应的 3 个位置中找到未被遮挡的那个位置的颜色，将该颜色复制到当前 Azure 像素处。若旋转对应的多个位置都未被遮挡，取其中任一个（由对称性保证结果一致）。
  - 输出网格与输入网格尺寸相同，Azure 像素全部被替换，其余像素不变。

- `Key insight`：
  - 关键在于识别出图案具有的是 4 重旋转对称而非简单的镜像对称——这决定了可以从旋转 90° 对应位置（而非仅镜像位置）恢复被遮挡内容。遮挡块的放置保证每个被遮挡像素至少有一个旋转对应位置是可见的。
</new_puzzle>
